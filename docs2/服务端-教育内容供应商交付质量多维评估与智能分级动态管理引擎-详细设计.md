# 服务端-教育内容供应商交付质量多维评估与智能分级动态管理引擎-详细设计

## 1. 概述

### 1.1 功能定位

本模块是 PrimeTop 教育平台**内容供应链管理**的核心质量保障引擎，负责对入驻内容供应商（出版社、教辅机构、题库厂商、个人教研团队等）的交付质量进行**多维度量化评估**，基于评估结果实施**动态分级管理**，并驱动内容采购决策、任务分配偏好和供应商淘汰机制。

与已有模块的关系：

| 已有模块 | 关系说明 |
| --- | --- |
| `教育内容供应商接入与外部资源标准化导入引擎` | 前置模块：负责供应商入驻审核和内容导入流程，本模块在入驻后开始运行 |
| `教育内容供应商版权费自动核算与结算对账引擎` | 并行模块：结算关注"钱"，本模块关注"质量" |
| `教育内容审核工作流与多级审核管线` | 数据来源：审核结果作为质量评估的关键输入 |
| `教育内容用户评价体系与口碑驱动的质量迭代引擎` | 数据来源：用户评价作为质量评估的输入维度之一 |
| `教育内容质量自动评估与低质内容智能检测引擎` | 数据来源：内容自动质检结果作为供应商质量评估依据 |

### 1.2 设计目标

1. **量化评估**：将供应商交付质量从主观感受转化为可量化、可比较的多维评分体系。
2. **动态分级**：基于评分实现供应商自动分级（铂金/金/银/铜/观察/黑名单），驱动业务策略。
3. **风险预警**：提前识别质量下滑趋势，在问题扩大前发出预警并触发干预措施。
4. **决策支持**：为内容采购分配、供应商续约/淘汰提供数据支撑。
5. **持续改进**：通过反馈闭环帮助供应商了解自身短板，驱动交付质量持续提升。

### 1.3 适用范围

- 供应商类型：教材出版社、教辅出版社、第三方题库供应商、教研内容工作室、个人内容创作者、AI 内容生成管线（将 AI 生成管线也视为一种"供应商"进行质量管理）。
- 内容类型：题目、解析、知识点讲解、教案/学案、试卷、音视频资源、互动课件。
- 评估周期：实时事件驱动 + 日维度增量更新 + 周维度综合评估 + 月度评级调整。

## 2. 核心概念与领域模型

### 2.1 领域模型概览

```
Supplier（供应商）
  ├── SupplierProfile（供应商档案）
  ├── SupplierDeliveryBatch（交付批次）
  │     └── SupplierDeliveryItem（交付条目：单条内容）
  ├── SupplierQualityScore（质量评分快照）
  ├── SupplierTierRecord（分级记录）
  ├── SupplierSLAConfig（SLA配置）
  ├── SupplierRiskAlert（风险预警）
  └── SupplierImprovementPlan（改进计划）
```

### 2.2 核心概念定义

| 概念 | 定义 |
| --- | --- |
| **交付批次 (Delivery Batch)** | 供应商一次提交的一组内容集合，如"2026年7月人教版八年级数学第3章题库" |
| **质量维度 (Quality Dimension)** | 评估交付质量的独立维度，每个维度有0-100的标准化得分 |
| **综合质量指数 (CQI)** | Composite Quality Index，多维加权综合得分，0-100分 |
| **供应商等级 (Tier)** | 基于CQI和历史表现动态计算的等级标识 |
| **SLA** | Service Level Agreement，供应商入驻时签订的交付质量承诺 |
| **风险信号 (Risk Signal)** | 从多数据源探测到的质量异常信号 |

### 2.3 质量评估维度体系

| 维度ID | 维度名称 | 权重 | 数据来源 | 说明 |
| --- | --- | --- | --- | --- |
| D1 | 内容准确性 | 25% | 自动事实校验 + 专家审核 | 知识点是否正确、答案是否准确 |
| D2 | 课标对齐度 | 15% | 知识点标注引擎 + 课标数据库 | 内容是否对齐当前课标要求 |
| D3 | 内容完整度 | 15% | 结构化校验 + 模板匹配 | 必填字段是否齐全、解析步骤是否完整 |
| D4 | 审核通过率 | 15% | 审核工作流 | 一审通过率、终审通过率 |
| D5 | 用户满意度 | 10% | 用户评价 + 反馈系统 | 学生/教师评分、负面反馈率 |
| D6 | 交付时效性 | 10% | 交付记录 vs 承诺时间 | 按时交付率、平均交付延迟 |
| D7 | 格式规范度 | 5% | 自动格式校验 | LaTeX、Markdown、图片规格等 |
| D8 | 内容原创度 | 5% | 查重引擎 | 与已有内容的重复率 |

> **权重可配置**：不同内容类型（题目 vs 视频）可使用不同权重方案，由运营后台配置。

## 3. 数据结构设计

### 3.1 核心表设计

#### 3.1.1 supplier（供应商主表）

```sql
CREATE TABLE supplier (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    supplier_code   VARCHAR(32) NOT NULL UNIQUE COMMENT '供应商编码，如 SUP-2026-001',
    supplier_name   VARCHAR(128) NOT NULL COMMENT '供应商名称',
    supplier_type   TINYINT NOT NULL COMMENT '类型：1=出版社 2=教辅机构 3=题库厂商 4=教研工作室 5=个人 6=AI管线',
    status          TINYINT NOT NULL DEFAULT 1 COMMENT '状态：0=停用 1=正常 2=观察 3=冻结 4=黑名单',
    contact_name    VARCHAR(64) COMMENT '联系人',
    contact_phone   VARCHAR(20) COMMENT '联系电话',
    contact_email   VARCHAR(128) COMMENT '联系邮箱',
    contract_start  DATE COMMENT '合同开始日期',
    contract_end    DATE COMMENT '合同结束日期',
    content_types   JSON COMMENT '擅长内容类型 ["question","explanation","video","courseware"]',
    subjects        JSON COMMENT '擅长学科 ["math","physics","chinese"]',
    grade_ranges    JSON COMMENT '擅长学段 ["primary","junior","senior"]',
    current_tier    VARCHAR(16) NOT NULL DEFAULT 'OBSERVE' COMMENT '当前等级：PLATINUM/GOLD/SILVER/BRONZE/OBSERVE/BLACKLIST',
    current_cqi     DECIMAL(5,2) DEFAULT 0 COMMENT '当前综合质量指数',
    tier_updated_at DATETIME COMMENT '等级最后更新时间',
    total_deliveries INT DEFAULT 0 COMMENT '累计交付批次数',
    total_items     INT DEFAULT 0 COMMENT '累计交付内容条数',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_type_status (supplier_type, status),
    INDEX idx_tier (current_tier),
    INDEX idx_cqi (current_cqi)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='供应商主表';
```

#### 3.1.2 supplier_delivery_batch（交付批次表）

```sql
CREATE TABLE supplier_delivery_batch (
    id                BIGINT PRIMARY KEY AUTO_INCREMENT,
    batch_no          VARCHAR(32) NOT NULL UNIQUE COMMENT '批次编号',
    supplier_id       BIGINT NOT NULL COMMENT '供应商ID',
    content_type      VARCHAR(32) NOT NULL COMMENT '内容类型：question/explanation/courseware/... ',
    subject           VARCHAR(16) NOT NULL COMMENT '学科',
    grade_range       VARCHAR(16) NOT NULL COMMENT '学段',
    textbook_version  VARCHAR(32) COMMENT '教材版本',
    chapter_codes     JSON COMMENT '关联章节编码列表',
    total_items       INT NOT NULL DEFAULT 0 COMMENT '本批次条目总数',
    passed_items      INT NOT NULL DEFAULT 0 COMMENT '审核通过条目数',
    rejected_items    INT NOT NULL DEFAULT 0 COMMENT '审核驳回条目数',
    pending_items     INT NOT NULL DEFAULT 0 COMMENT '待审核条目数',
    pass_rate         DECIMAL(5,2) DEFAULT 0 COMMENT '一审通过率',
    promised_date     DATE NOT NULL COMMENT '承诺交付日期',
    actual_date       DATE COMMENT '实际交付日期',
    delay_days        INT DEFAULT 0 COMMENT '延迟天数（负数=提前）',
    batch_status      TINYINT NOT NULL DEFAULT 0 COMMENT '0=待审核 1=审核中 2=已完成 3=已驳回 4=已撤回',
    batch_cqi         DECIMAL(5,2) COMMENT '批次综合质量得分',
    metadata          JSON COMMENT '附加元数据',
    created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_supplier (supplier_id, created_at),
    INDEX idx_status (batch_status),
    INDEX idx_promised (promised_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='供应商交付批次表';
```

#### 3.1.3 supplier_quality_dimension_score（质量维度评分表）

```sql
CREATE TABLE supplier_quality_dimension_score (
    id                BIGINT PRIMARY KEY AUTO_INCREMENT,
    supplier_id       BIGINT NOT NULL,
    evaluation_period VARCHAR(16) NOT NULL COMMENT '评估周期：YYYY-Wxx / YYYY-MMxx / YYYY-Qx',
    period_type       TINYINT NOT NULL COMMENT '1=日 2=周 3=月 4=季度',
    dimension_code    VARCHAR(16) NOT NULL COMMENT '维度ID：D1-D8',
    raw_score         DECIMAL(5,2) NOT NULL COMMENT '原始得分 0-100',
    weighted_score    DECIMAL(5,2) NOT NULL COMMENT '加权后得分',
    sample_count      INT NOT NULL DEFAULT 0 COMMENT '样本数',
    data_sources      JSON COMMENT '数据来源明细',
    details           JSON COMMENT '评分细节，如各子项得分',
    created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_supplier_period_dim (supplier_id, evaluation_period, dimension_code),
    INDEX idx_period (evaluation_period),
    INDEX idx_supplier (supplier_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='供应商质量维度评分表';
```

#### 3.1.4 supplier_tier_record（供应商分级变更记录）

```sql
CREATE TABLE supplier_tier_record (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    supplier_id     BIGINT NOT NULL,
    evaluation_date DATE NOT NULL COMMENT '评估日期',
    from_tier       VARCHAR(16) NOT NULL COMMENT '变更前等级',
    to_tier         VARCHAR(16) NOT NULL COMMENT '变更后等级',
    from_cqi        DECIMAL(5,2) COMMENT '变更前CQI',
    to_cqi          DECIMAL(5,2) COMMENT '变更后CQI',
    change_reason   VARCHAR(32) NOT NULL COMMENT 'UPGRADE/DOWNGRADE/MAINTAIN/PENALTY/BLACKLIST',
    trigger_rule    VARCHAR(128) COMMENT '触发的分级规则编码',
    evidence        JSON COMMENT '评级依据快照',
    reviewer        VARCHAR(64) COMMENT '审核人（自动则为SYSTEM）',
    review_note     TEXT COMMENT '备注',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_supplier (supplier_id, evaluation_date),
    INDEX idx_change_reason (change_reason)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='供应商分级变更记录';
```

#### 3.1.5 supplier_sla_config（供应商SLA配置表）

## 5. 质量评估算法

### 5.1 CQI（综合质量指数）计算公式

CQI 采用**滑动窗口加权平均**模型，兼顾近期表现与历史基线：

```
CQI_current = α × CQI_this_period + (1 - α) × CQI_previous
```

其中 `α` 为平滑系数（默认 0.3），可通过配置调整：

- 新供应商（交付 < 5 个周期）：`α = 0.5`（更快反映近期表现）
- 成熟供应商（交付 ≥ 5 个周期）：`α = 0.3`（更稳定）
- 观察期供应商：`α = 0.7`（高灵敏度，快速发现问题）

### 5.2 各维度评分计算规则

#### D1 - 内容准确性 (25%)

```python
def calc_accuracy_score(batch_items: list, fact_check_results: list) -> float:
    """
    内容准确性得分计算
    数据来源：
      - 自动事实校验引擎输出
      - 专家审核标注
      - 答案验算管线结果
    """
    total = len(batch_items)
    if total == 0:
        return 0.0

    error_weights = {
        "WRONG_ANSWER": 10.0,       # 答案错误，扣分最重
        "WRONG_FORMULA": 5.0,       # 公式错误
        "WRONG_UNIT": 2.0,          # 单位错误
        "TYPO": 0.5,                # 错别字
        "FORMAT_ISSUE": 0.3,        # 格式问题
    }

    total_penalty = 0.0
    for result in fact_check_results:
        for error in result.errors:
            total_penalty += error_weights.get(error.type, 1.0)

    # 基础分100，扣分后不低于0
    raw_score = max(0.0, 100.0 - (total_penalty / total) * 100)
    return round(raw_score, 2)
```

#### D4 - 审核通过率 (15%)

```python
def calc_pass_rate_score(batches: list) -> float:
    """
    审核通过率得分
    综合一审通过率和终审通过率
    """
    if not batches:
        return 0.0

    total_items = sum(b.total_items for b in batches)
    first_pass = sum(b.passed_items for b in batches)
    final_pass = sum(b.passed_items + b.rejected_items * 0.3 for b in batches)  # 驳回后修改重审按0.3折算

    first_pass_rate = first_pass / total_items if total_items > 0 else 0
    final_pass_rate = min(1.0, final_pass / total_items) if total_items > 0 else 0

    # 一审通过率权重60%，终审通过率权重40%
    score = (first_pass_rate * 0.6 + final_pass_rate * 0.4) * 100
    return round(score, 2)
```

#### D6 - 交付时效性 (10%)

```python
def calc_timeliness_score(batches: list) -> float:
    """
    交付时效性得分
    基于按时交付率和平均延迟天数
    """
    if not batches:
        return 0.0

    on_time_count = sum(1 for b in batches if b.delay_days <= 0)
    on_time_rate = on_time_count / len(batches)

    avg_delay = sum(max(0, b.delay_days) for b in batches) / len(batches)

    # 基础分 = 按时率 * 100
    # 每天平均延迟扣2分
    score = on_time_rate * 100 - avg_delay * 2.0
    return round(max(0.0, min(100.0, score)), 2)
```

### 5.3 CQI 综合计算

```python
def compute_cqi(
    dimension_scores: dict[str, float],
    weight_config: dict[str, float],
    previous_cqi: float,
    alpha: float = 0.3
) -> float:
    """
    计算当期CQI
    
    Args:
        dimension_scores: {"D1": 97.2, "D2": 95.0, ...}
        weight_config: {"D1": 0.25, "D2": 0.15, ...}
        previous_cqi: 上期CQI
        alpha: 平滑系数
    """
    # 步骤1：加权求和得当期原始CQI
    current_raw = sum(
        dimension_scores[dim] * weight_config[dim]
        for dim in dimension_scores
        if dim in weight_config
    )

    # 步骤2：与历史CQI做指数平滑
    if previous_cqi > 0:
        cqi = alpha * current_raw + (1 - alpha) * previous_cqi
    else:
        cqi = current_raw  # 首次评估直接使用原始分

    return round(cqi, 2)
```

## 6. 供应商分级策略

### 6.1 分级体系

| 等级 | CQI 范围 | 最小交付批次 | 业务含义 | 对应策略 |
| --- | --- | --- | --- | --- |
| PLATINUM (铂金) | ≥ 92 | ≥ 20 | 行业标杆，免检优先 | 自动审核通道、优先分配任务、奖励金 |
| GOLD (金) | 85-91.9 | ≥ 10 | 优质可靠 | 抽检比例30%、优先任务分配 |
| SILVER (银) | 75-84.9 | ≥ 5 | 合格稳定 | 全量审核、正常任务分配 |
| BRONZE (铜) | 65-74.9 | ≥ 3 | 基本可用但需改进 | 全量审核+加强抽检、限制新任务分配 |
| OBSERVE (观察) | < 65 或新入驻 | - | 质量不稳定或新供应商 | 逐条审核、不分配新任务、进入改进流程 |
| BLACKLIST (黑名单) | - | - | 严重违规或屡教不改 | 冻结账号、终止合作、启动交接 |

### 6.2 自动分级决策引擎

```python
class SupplierTierEngine:
    """供应商自动分级决策引擎"""

    # 分级阈值配置
    TIER_THRESHOLDS = {
        "PLATINUM": {"min_cqi": 92, "min_batches": 20, "min_sla_rate": 1.0},
        "GOLD":     {"min_cqi": 85, "min_batches": 10, "min_sla_rate": 0.95},
        "SILVER":   {"min_cqi": 75, "min_batches": 5,  "min_sla_rate": 0.90},
        "BRONZE":   {"min_cqi": 65, "min_batches": 3,  "min_sla_rate": 0.80},
    }

    # 一票降级规则（触发即降级）
    PENALTY_RULES = [
        {
            "code": "CRITICAL_SAFETY_VIOLATION",
            "condition": lambda ctx: ctx.safety_violation_count > 0,
            "action": "BLACKLIST",
            "reason": "出现内容安全事故（涉政/涉黄/涉暴）"
        },
        {
            "code": "CATASTROPHIC_ACCURACY",
            "condition": lambda ctx: ctx.accuracy_score < 80.0,
            "action": "DOWNGRADE_TO_OBSERVE",
            "reason": "内容准确率低于80%，存在严重质量问题"
        },
        {
            "code": "CQI_DECLINE_15_PLUS",
            "condition": lambda ctx: ctx.cqi_decline >= 15.0,
            "action": "DOWNGRADE_ONE_TIER",
            "reason": "CQI连续下滑超过15分"
        },
        {
            "code": "SLA_BREACH_CONSECUTIVE_3",
            "condition": lambda ctx: ctx.consecutive_sla_breach >= 3,
            "action": "DOWNGRADE_ONE_TIER",
            "reason": "连续3个周期违反SLA"
        },
    ]

    def evaluate_tier(self, supplier_id: int, period: str) -> TierDecision:
        """
        执行分级评估
        返回分级决策结果
        """
        ctx = self._build_context(supplier_id, period)

        # 1. 检查一票降级规则
        for rule in self.PENALTY_RULES:
            if rule["condition"](ctx):
                return TierDecision(
                    from_tier=ctx.current_tier,
                    to_tier=self._apply_penalty_action(ctx.current_tier, rule["action"]),
                    reason=rule["reason"],
                    rule_code=rule["code"],
                    evidence=ctx.to_snapshot()
                )

        # 2. 基于CQI的常规分级
        target_tier = self._calc_target_tier(ctx)

        # 3. 分级变更冷却期检查（防止频繁升降）
        if self._in_cooldown(supplier_id, ctx.current_tier, target_tier):
            return TierDecision.maintain(ctx.current_tier, "分级冷却期内，维持当前等级")

        # 4. 连续稳定期检查（升级需要连续N期达标）
        if self._is_upgrade(ctx.current_tier, target_tier):
            if not self._check_consecutive_qualify(supplier_id, target_tier, periods=2):
                return TierDecision.maintain(
                    ctx.current_tier,
                    f"CQI达标但需连续2期确认升级至{target_tier}"
                )

        return TierDecision(
            from_tier=ctx.current_tier,
            to_tier=target_tier,
            reason=f"CQI={ctx.current_cqi}, SLA达标率={ctx.sla_compliance_rate}",
            rule_code="CQI_BASED",
            evidence=ctx.to_snapshot()
        )

    def _calc_target_tier(self, ctx) -> str:
        """基于CQI和交付量计算目标等级"""
        for tier, threshold in sorted(
            self.TIER_THRESHOLDS.items(),
            key=lambda x: -x[1]["min_cqi"]  # 从高到低匹配
        ):
            if (ctx.current_cqi >= threshold["min_cqi"]
                and ctx.total_batches >= threshold["min_batches"]
                and ctx.sla_compliance_rate >= threshold["min_sla_rate"]):
                return tier
        return "OBSERVE"
```

## 11. 错误处理与异常场景

### 11.1 错误码定义

| 错误码 | HTTP | 说明 | 处理建议 |
| --- | --- | --- | --- |
| `SUPPLIER_NOT_FOUND` | 404 | 供应商不存在 | 检查供应商ID |
| `SUPPLIER_FROZEN` | 403 | 供应商已冻结 | 联系运营确认 |
| `BATCH_NOT_FOUND` | 404 | 批次不存在 | 检查批次编号 |
| `INSUFFICIENT_DATA` | 422 | 数据不足以计算评分 | 至少需要1个交付批次 |
| `TIER_COOLDOWN` | 409 | 分级冷却期内 | 等待冷却期结束后重试 |
| `SLA_CONFIG_CONFLICT` | 409 | SLA配置冲突 | 同内容类型只能有一份有效SLA |
| `EVALUATION_IN_PROGRESS` | 409 | 评估任务正在执行 | 等待当前评估完成 |

### 11.2 异常场景处理

#### 场景1：供应商无交付数据

```python
if total_items == 0:
    # 维持OBSERVE等级，CQI保持0
    return TierDecision.maintain(
        Tier.OBSERVE,
```

#### 场景2：数据源服务不可用

```python
async def safe_get_dimension_score(dim: str, supplier_id: int) -> Optional[float]:
    """安全获取维度分数，数据源不可用时返回None"""
    try:
        return await fetch_dimension_score(dim, supplier_id, timeout=5)
    except (ServiceUnavailable, TimeoutError) as e:
        logger.warning(f"维度{dim}数据源不可用: {e}")
        # 使用上一周期分数作为兜底
        return await get_last_period_score(dim, supplier_id)
```

#### 场景3：并发评估冲突

使用分布式锁确保同一供应商同一周期不重复评估：

```python
@distributed_lock(key="supplier_eval:{supplier_id}:{period}", timeout=300)
async def evaluate_supplier(supplier_id: int, period: str):
    """供应商质量评估（带分布式锁）"""
    # 检查是否已评估
    existing = await get_quality_score(supplier_id, period)
    if existing and existing.status == "COMPLETED":
        return existing  # 幂等返回
    # ... 执行评估
```

#### 场景4：批量评估任务失败重试

```python
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=retry_if_exception_type((DatabaseError, TimeoutError))
)
async def batch_evaluate(supplier_ids: list[int], period: str):
    """批量评估供应商质量"""
    for supplier_id in supplier_ids:
        try:
            await evaluate_supplier(supplier_id, period)
        except Exception as e:
            logger.error(f"供应商{supplier_id}评估失败: {e}")
            await record_evaluation_failure(supplier_id, period, str(e))
            # 继续评估下一个，不中断批量任务
```

## 12. 性能优化

### 12.1 缓存策略

| 缓存Key | TTL | 说明 |
| --- | --- | --- |
| `supplier:cqi:{supplier_id}` | 1小时 | 供应商当前CQI缓存 |
| `supplier:dimensions:{supplier_id}:{period}` | 24小时 | 周期维度评分缓存 |
| `supplier:tier:{supplier_id}` | 1小时 | 当前等级缓存 |
| `supplier:ranking:{tier}:{subject}` | 5分钟 | 分级排行缓存 |
| `supplier:alerts:active` | 30秒 | 活跃预警列表缓存 |

### 12.2 数据库优化

```sql
-- 供应商质量评分高频查询索引
CREATE INDEX idx_quality_supplier_period 
ON supplier_quality_dimension_score(supplier_id, evaluation_period)
INCLUDE (dimension_code, raw_score, weighted_score);

-- 分级变更记录时间线查询
CREATE INDEX idx_tier_timeline 
ON supplier_tier_record(supplier_id, evaluation_date DESC);

-- 预警查询索引
CREATE INDEX idx_alert_active 
ON supplier_risk_alert(status, alert_level, created_at DESC)
WHERE status = 0;
```

### 12.3 批量评估并行化

```python
import asyncio

async def parallel_batch_evaluate(supplier_ids: list[int], period: str):
    """并行评估多个供应商，控制并发度"""
    semaphore = asyncio.Semaphore(5)  # 最多5个并发

    async def evaluate_one(sid: int):
        async with semaphore:
            await evaluate_supplier(sid, period)

    await asyncio.gather(*[evaluate_one(sid) for sid in supplier_ids])
```
