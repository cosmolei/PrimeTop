## 1. 概述

### 1.1 背景与目标

PrimeTop 采用 Freemium + 会员订阅商业模式。免费用户与付费会员之间存在显著的转化漏斗损耗。本引擎旨在：

1. **预测用户生命周期价值（LTV）**：基于历史行为、学习参与度、消费特征等维度，预测用户在未来 30/90/365 天的净收入贡献。
2. **评分会员升级意向**：对免费用户和即将到期的付费用户进行升级意向打分（0-100），输出高/中/低意向分群。
3. **驱动精细化运营**：为推送营销、弹窗策略、优惠券发放、专属客服等提供数据决策依据，实现"在正确的时间向正确的用户推送正确的套餐"。

### 1.2 核心业务价值

| 价值点 | 说明 |
|--------|------|
| 提升付费转化率 | 识别高意向未付费用户，精准触达 |
| 降低用户流失成本 | 识别低 LTV 用户，提前干预或降低服务成本 |
| 优化营销 ROI | 按 LTV 分层分配营销预算，避免无效补贴 |
| 动态定价支持 | 为弹性折扣、限时优惠提供用户级定价依据 |
| 产品迭代度量 | 通过 LTV 趋势变化衡量产品改进的长期效果 |

### 1.3 设计原则

- **数据驱动**：所有评分基于可量化指标，避免人为规则偏差。
- **可解释性**：评分结果附带 Top 影响因子，运营人员可理解"为什么这个用户分高"。
- **实时性 + 批处理结合**：核心评分每日批量计算，关键事件触发实时增量更新。
- **隐私合规**：未成年人数据脱敏处理，不使用敏感个人信息作为特征。

## 5. LTV 预测模型

### 5.1 模型选型

| 方案 | 模型 | 适用性 | 决策 |
|------|------|--------|------|
| 线性回归 | Ridge/Lasso | 可解释性强，但欠拟合 | ❌ 非线性特征多 |
| **梯度提升树** | **XGBoost / LightGBM** | **非线性表达好，特征重要性天然可输出** | **✅ MVP 首选** |
| 深度学习 | MLP / DeepFM | 表达力强，但调参复杂，数据量不足时不稳定 | ⏸ V2 等数据积累后 |
| 生存分析 | Kaplan-Meier + Cox | 适合流失时间预测，不适合金额预测 | ❌ 用途不匹配 |

**决策结果**：MVP 阶段使用 **LightGBM 回归模型** 预测 LTV。

### 5.2 标签定义

```python
def build_ltv_label(user_id: int, anchor_date: date, horizon_days: int) -> float:
    """
    构建LTV标签：用户在 [anchor_date, anchor_date + horizon_days] 期间
    产生的净收入（总付费 - 总退款），单位：元
    """
    payments = payment_repo.find_in_range(
        user_id=user_id,
        start=anchor_date,
        end=anchor_date + timedelta(days=horizon_days)
    )
    total_revenue = sum(p.amount for p in payments if p.status == 'SUCCESS')
    total_refund = sum(p.refund_amount for p in payments if p.has_refund)
    return round(total_revenue - total_refund, 2)
```

### 5.3 训练流程

```python
class LTVModelTrainer:
    """LTV预测模型训练器"""
    
    def __init__(self):
        self.model = None
        self.feature_columns = LTV_FEATURE_COLUMNS  # 约30个特征列
        self.horizons = [30, 90, 365]               # 三个时间窗口分别训练
    
    def prepare_training_data(
        self, 
        start_date: date, 
        end_date: date
    ) -> tuple[pd.DataFrame, dict[int, pd.Series]]:
        """
        准备训练数据：
        - 特征X：anchor_date 当天的用户特征快照
        - 标签Y：anchor_date 之后 N 天的净收入
        - 只选择注册天数 >= 7 的用户（保证有足够行为数据）
        """
        all_samples = []
        all_labels = {h: [] for h in self.horizons}
        
        current = start_date
        while current <= end_date:
            # 获取当天所有活跃用户的特征向量
            features_df = feature_store.load_features(current, min_register_days=7)
            
            for horizon in self.horizons:
                # 获取标签：未来 horizon 天的净收入
                labels = []
                for _, row in features_df.iterrows():
                    label = build_ltv_label(row['user_id'], current, horizon)
                    labels.append(label)
                all_labels[horizon].extend(labels)
            
            all_samples.append(features_df)
            current += timedelta(days=1)
        
        X = pd.concat(all_samples, ignore_index=True)
        y_dict = {h: pd.Series(all_labels[h]) for h in self.horizons}
        
        return X, y_dict
    
    def train(self, training_start: date, training_end: date) -> dict:
        """训练三个时间窗口的 LTV 预测模型"""
        X, y_dict = self.prepare_training_data(training_start, training_end)
        
        results = {}
        for horizon in self.horizons:
            y = y_dict[horizon]
            
            # 时间序列感知的 train/test split（用最后 20% 时间做验证）
            split_idx = int(len(X) * 0.8)
            X_train, X_val = X.iloc[:split_idx], X.iloc[split_idx:]
            y_train, y_val = y.iloc[:split_idx], y.iloc[split_idx:]
            
            model = lgb.LGBMRegressor(
                n_estimators=500,
                max_depth=6,
                learning_rate=0.05,
                num_leaves=31,
                min_child_samples=50,
                subsample=0.8,
                colsample_bytree=0.8,
                reg_alpha=0.1,
                reg_lambda=0.1,
                random_state=42,
                objective='regression',  # L2 损失
                metric='rmse'
            )
            
            model.fit(
                X_train[self.feature_columns], y_train,
                eval_set=[(X_val[self.feature_columns], y_val)],
                callbacks=[
                    lgb.early_stopping(stopping_rounds=50),
                    lgb.log_evaluation(period=50)
                ]
            )
            
            # 记录特征重要性
            importance = dict(zip(
                self.feature_columns,
                model.feature_importances_.tolist()
            ))
            
            # 验证集评估
            y_pred = model.predict(X_val[self.feature_columns])
            metrics = {
                'rmse': float(np.sqrt(mean_squared_error(y_val, y_pred))),
                'mae': float(mean_absolute_error(y_val, y_pred)),
                'r2': float(r2_score(y_val, y_pred)),
            }
            
            results[horizon] = {
                'model': model,
                'metrics': metrics,
                'feature_importance': importance,
            }
            
            logger.info(
                f"LTV model (horizon={horizon}d) - "
                f"RMSE={metrics['rmse']:.2f}, "
                f"MAE={metrics['mae']:.2f}, "
                f"R²={metrics['r2']:.4f}"
            )
        
        return results
```

## 6. 升级意向评分模型

### 6.1 模型选型

采用 **两阶段方案**：

1. **阶段一（分类器）**：LightGBM 二分类，预测用户在未来 14 天内发起付费/升级的概率。
2. **阶段二（评分映射）**：将概率值映射到 0-100 意向评分，并结合规则微调。

### 6.2 标签定义

```python
def build_upgrade_label(user_id: int, anchor_date: date, window_days: int = 14) -> int:
    """
    升级意向标签：
    - 1: 用户在 (anchor_date, anchor_date + window_days] 内发起了付费或升级
    - 0: 未发起付费
    注意：取消后重新订阅也算升级
    """
    has_payment = payment_repo.exists_payment_in_range(
        user_id=user_id,
        start=anchor_date + timedelta(days=1),
        end=anchor_date + timedelta(days=window_days),
        statuses=['SUCCESS', 'PENDING']
    )
    return 1 if has_payment else 0
```

### 6.3 评分映射

```python
class UpgradeIntentScorer:
    """升级意向评分器"""
    
    # 分维度子模型权重
    DIMENSION_WEIGHTS = {
        'engagement_score':    0.30,  # 学习参与度最重要
        'monetization_score':  0.25,  # 消费倾向
        'feature_usage_score': 0.20,  # 功能使用深度
        'timing_score':        0.15,  # 时机匹配
        'social_score':        0.10,  # 社交影响
    }
    
    def compute_dimension_scores(self, fv: dict) -> dict[str, int]:
        """计算各维度子评分（0-100）"""
        
        # 参与度子评分
        engagement = min(100, int(
            25 * min(fv['fv_active_days_7d'] / 7.0, 1.0) +
            25 * min(fv['fv_streak_days'] / 30.0, 1.0) +
            25 * min(fv['fv_study_plan_completion_7d'], 1.0) +
            25 * min(fv['fv_subject_count_active_7d'] / 4.0, 1.0)
        ))
        
        # 消费倾向子评分
        if fv['fv_has_paid_ever']:
            # 曾付费用户：侧重续费/升级信号
            mon = min(100, int(
                40 * (1 - min(fv['fv_days_since_last_payment'] / 90.0, 1.0)) +  # 越近付费分越高
                30 * min(fv['fv_payment_count'] / 5.0, 1.0) +
                30 * min(fv['fv_total_payment_amount'] / 50000, 1.0)  # 500元为满分基准
            ))
        else:
            # 未付费用户：侧重消费倾向信号
            mon = min(100, int(
                40 * (1 if fv['fv_has_used_coupon'] else 0) +
                30 * min(fv['fv_coupon_used_count_30d'] / 3.0, 1.0) +
                30 * min(fv['fv_ai_ask_count_7d'] / 30.0, 1.0)  # 高频使用暗示付费潜力
            ))
        
        # 功能使用深度子评分
        feature_usage = min(100, int(
            30 * min(fv['fv_ai_ask_count_7d'] / 20.0, 1.0) +
            25 * min(fv['fv_photo_search_count_7d'] / 10.0, 1.0) +
            20 * min(fv['fv_mistake_add_count_7d'] / 10.0, 1.0) +
            15 * min(fv['fv_exercise_count_7d'] / 15.0, 1.0) +
            10 * min(fv['fv_chapter_progress_avg'], 1.0)
        ))
        
        # 时机匹配子评分
        timing = 0
        if fv['fv_is_trial_period']:
            timing += 40  # 试用期是最佳转化窗口
        if 0 < fv['fv_days_to_membership_expiry'] <= 7:
            timing += 50  # 即将到期，续费决策窗口
        elif 0 < fv['fv_days_to_membership_expiry'] <= 30:
            timing += 30
        # 开学季/考试季加成
        if fv['fv_seasonal_index'] in (1, 2):  # 开学季=1, 考试季=2
            timing += 20
        timing = min(100, timing)
        
        # 社交影响子评分
        social = 0
        if fv['fv_has_parent_bound']:
            social += 40  # 家长绑定增加付费可能性
        if fv['fv_has_invited_users']:
            social += 30  # 邀请行为表明高认同感
        if fv['fv_class_member']:
            social += 30  # 班级成员，可能跟随班级订阅
        social = min(100, social)
        
        return {
            'engagement_score':    engagement,
            'monetization_score':  mon,
            'feature_usage_score': feature_usage,
            'timing_score':        timing,
            'social_score':        social,
        }
    
    def compute_final_score(self, dimensions: dict[str, int], 
                             model_probability: float | None = None) -> tuple[int, str]:
        """
        计算最终升级意向评分。
        
        融合策略：
        - 规则维度评分占 60%
        - 模型概率评分占 40%（如果有模型可用）
        """
        rule_score = sum(
            dimensions[dim] * weight
            for dim, weight in self.DIMENSION_WEIGHTS.items()
        )
        
        if model_probability is not None:
            model_score = model_probability * 100
            final_score = int(0.6 * rule_score + 0.4 * model_score)
        else:
            final_score = int(rule_score)
        
        final_score = max(0, min(100, final_score))
        
        # 分层
        if final_score >= 70:
            tier = 'HIGH'
        elif final_score >= 40:
            tier = 'MEDIUM'
        elif final_score >= 15:
            tier = 'LOW'
        else:
            tier = 'DORMANT'
        
        return final_score, tier
```

### 6.4 推荐动作映射

```python
ACTION_STRATEGY = {
    # (tier, has_paid_ever, context) → recommended_action
    'HIGH_FREE':       'UPGRADE_PUSH',  # 高意向免费用户 → 推送升级
    'HIGH_EXPIRING':   'RETARGET',      # 高意向即将到期 → 续费触达
    'MEDIUM_FREE':     'DISCOUNT',      # 中意向免费用户 → 发放优惠券
    'MEDIUM_EXPIRING': 'NUDGE',         # 中意向即将到期 → 轻触达
    'LOW_FREE':        'OBSERVE',       # 低意向免费用户 → 观察，不过度打扰
    'LOW_EXPIRING':    'HOLD',          # 低意向即将到期 → 不主动续费推送
    'DORMANT_ANY':     'OBSERVE',       # 休眠用户 → 仅观察
}

def get_recommended_action(tier: str, fv: dict) -> str:
    has_paid = fv.get('fv_has_paid_ever', False)
    days_to_expiry = fv.get('fv_days_to_membership_expiry', -1)
    
    if tier == 'DORMANT':
        return 'OBSERVE'
    
    if tier == 'HIGH':
        if has_paid and 0 < days_to_expiry <= 14:
            return 'RETARGET'
        elif not has_paid:
            return 'UPGRADE_PUSH'
    
    if tier == 'MEDIUM':
        if not has_paid:
            return 'DISCOUNT'
        elif has_paid and 0 < days_to_expiry <= 14:
            return 'NUDGE'
    
    if tier == 'LOW':
        if not has_paid:
            return 'OBSERVE'
        elif has_paid and 0 < days_to_expiry <= 14:
            return 'HOLD'
    
    return 'OBSERVE'
```

## 7. 批处理与调度

### 7.1 每日批量计算流程

```
每日 02:00 AM 触发（Cron: 0 2 * * *）
    │
    ├── Step 1: 特征向量构建 (02:00 - 02:20)
    │   └── 从各数据源拉取昨日数据，构建用户特征向量快照
    │       覆盖范围：过去30天有活跃记录的所有用户
    │
    ├── Step 2: LTV 预测 (02:20 - 02:35)
    │   └── 加载最新 LTV 模型，批量预测三个时间窗口
    │       写入 user_ltv_prediction 表 + Redis 缓存
    │
    ├── Step 3: 升级意向评分 (02:35 - 02:50)
    │   └── 计算各维度子评分 + 模型概率融合 → 最终评分
    │       写入 user_upgrade_intent_score 表 + Redis 缓存
    │       写入 upgrade_intent:daily:{date} ZSET
    │
    ├── Step 4: 运营动作分发 (02:50 - 03:00)
    │   └── 根据 recommended_action 生成运营任务
    │       发送 Kafka 事件给营销/弹窗/推送服务
    │
    └── Step 5: 指标上报 (03:00)
        └── 统计当日评分分布、模型覆盖率，上报监控
```

### 7.2 实时增量更新（事件驱动）

对于关键行为事件，触发评分增量更新（不重跑模型，仅调整规则维度评分）：

```python
# 事件监听器
class UpgradeIntentEventHandler:
    
    @kafka_listener(topic='payment-events')
    def on_payment_event(self, event: dict):
        """用户完成付费后立即更新评分"""
        user_id = event['userId']
        if event['eventType'] == 'PAYMENT_SUCCESS':
            # 标记为已转化，更新意向分
            self._refresh_user_score(user_id, trigger='EVENT')
            # 发送转化归因事件
            event_bus.publish('upgrade_intent.converted', {
                'user_id': user_id,
                'previous_tier': self._get_previous_tier(user_id),
                'conversion_source': event.get('source', 'UNKNOWN'),
                'amount': event['amount'],
            })
    
    @kafka_listener(topic='user-behavior')
    def on_behavior_event(self, event: dict):
        """关键行为变化时增量更新"""
        user_id = event['userId']
        event_type = event['eventType']
        
        # 仅对以下高影响力事件触发增量更新
        TRIGGER_EVENTS = {
            'AI_ASK_EXCEEDED_QUOTA',      # AI问答次数耗尽（强付费信号）
            'PHOTO_SEARCH_QUOTA_EXCEEDED', # 拍题次数耗尽
            'MEMBERSHIP_EXPIRING_SOON',    # 会员即将到期（7天内）
            'TRIAL_PERIOD_ENDING',         # 试用期即将结束
            'COUPON_RECEIVED',             # 用户领取优惠券
        }
        
        if event_type in TRIGGER_EVENTS:
            self._refresh_user_score(user_id, trigger='EVENT')
    
    def _refresh_user_score(self, user_id: int, trigger: str):
        """重新拉取最新特征 → 重算评分 → 更新存储"""
        fv = feature_store.get_latest(user_id)
        if not fv:
            return
        
        dimensions = self.scorer.compute_dimension_scores(fv)
        score, tier = self.scorer.compute_final_score(dimensions)
        action = get_recommended_action(tier, fv)
        
        self._upsert_score(user_id, score, tier, dimensions, action, trigger)
```

## 11. 错误处理与降级策略

### 11.1 错误处理矩阵

| 场景 | 处理策略 | 降级方案 |
|------|----------|----------|
| 特征数据源不可用（如 ClickHouse 宕机） | 使用上一次成功的特征快照 | 标记 `feature_stale=true`，降级为规则评分 |
| 模型加载失败 | 跳过模型评分，仅使用规则评分 | 评分基于100%规则维度（model_probability=None） |
| Redis 写入失败 | 仅写数据库，异步补偿写 Redis | 下次查询走 DB，增加延迟但不丢数据 |
| Kafka 消费积压 | 丢弃超过2小时的 behavior 事件触发 | 仅保留 payment 等高优先级事件触发 |
| 单用户特征查询超时 | 跳过该用户，记录到异常日志 | 当日评分覆盖数降低，不影响整体 |
| 模型预测值异常（如LTV为负数） | 裁剪到 [0, MAX_LTV] 范围 | MAX_LTV = 100000（1000元/天上限） |

### 11.2 模型回滚机制

```python
class ModelRegistry:
    """模型版本管理，支持一键回滚"""
    
    def get_active_model(self, model_name: str) -> ModelArtifact:
        """获取当前生效模型"""
        return self.registry.get_active(model_name)
    
    def rollback(self, model_name: str, target_version: str | None = None):
        """
        回滚模型到指定版本。
        如未指定版本，回滚到上一个稳定版本。
        """
        if target_version:
            self.registry.activate(model_name, target_version)
        else:
            previous = self.registry.get_previous_stable(model_name)
            if previous:
                self.registry.activate(model_name, previous.version)
            else:
                logger.warning(f"No previous model to rollback to for {model_name}")
        
        # 发布回滚事件
        event_bus.publish('model.rolled_back', {
            'model_name': model_name,
            'rolled_to': target_version or previous.version,
            'timestamp': datetime.utcnow().isoformat()
        })
```

### 11.3 数据质量监控

```python
class DataQualityMonitor:
    """每日计算前的数据质量检查"""
    
    def check(self, run_date: date) -> DataQualityReport:
        report = DataQualityReport(date=run_date)
        
        # 检查1: 用户覆盖率
        active_users = user_repo.count_active_users(run_date, days=30)
        feature_users = feature_store.count_snapshot(run_date)
        coverage = feature_users / max(active_users, 1)
        report.add('feature_coverage', coverage, 
                    threshold=0.90, severity='WARNING')
        
        # 检查2: 特征空值率
        for col in CRITICAL_FEATURE_COLUMNS:
            null_rate = feature_store.null_rate(run_date, col)
            if null_rate > 0.05:  # 关键特征空值率超过5%
                report.add(f'null_rate_{col}', null_rate,
                          threshold=0.05, severity='CRITICAL')
        
        # 检查3: 特征分布偏移
        for col in NUMERIC_FEATURE_COLUMNS:
            drift_score = feature_store.calculate_psi(run_date, col)
            if drift_score > 0.2:  # PSI > 0.2 表示显著偏移
                report.add(f'drift_{col}', drift_score,
                          threshold=0.2, severity='WARNING')
        
        # 检查4: 标签延迟（支付数据是否到位）
        payment_delay = payment_repo.max_data_delay(run_date)
        if payment_delay > timedelta(hours=2):
            report.add('payment_data_delay', payment_delay.total_seconds(),
                      threshold=7200, severity='WARNING')
        
        return report
```

### 12.2 批处理优化

```python
# 使用并行化加速批量评分
from concurrent.futures import ThreadPoolExecutor

def batch_score_users(user_ids: list[int], run_date: date) -> int:
    """并行批量评分"""
    BATCH_SIZE = 500
    
    def score_batch(batch: list[int]) -> list[ScoreResult]:
        fvs = feature_store.batch_get(batch, run_date)
        results = []
        for uid, fv in zip(batch, fvs):
            if fv is None:
                continue
            dims = scorer.compute_dimension_scores(fv)
            score, tier = scorer.compute_final_score(dims)
            action = get_recommended_action(tier, fv)
            results.append(ScoreResult(uid, score, tier, dims, action))
        return results
    
    all_results = []
    with ThreadPoolExecutor(max_workers=8) as pool:
        futures = []
        for i in range(0, len(user_ids), BATCH_SIZE):
            batch = user_ids[i:i+BATCH_SIZE]
            futures.append(pool.submit(score_batch, batch))
        
        for future in futures:
            all_results.extend(future.result())
    
    # 批量写入
    score_repo.batch_upsert(all_results)
    
    return len(all_results)
```

## 14. 安全与合规

| 维度 | 措施 |
|------|------|
| 数据访问 | API 鉴权 + 权限校验，仅运营/管理后台可查看用户级评分 |
| 未成年人数据 | 评分不使用姓名、身份证号等敏感信息，仅基于行为特征 |
| 模型公平性 | 每月检查模型输出在学段、性别（如有）、地区间的公平性指标 |
| 审计日志 | 所有手动重算、模型部署、阈值变更记录审计日志 |
| 数据保留 | 特征向量保留 180 天，评分结果保留 365 天，超期归档 |
| 输出限制 | 单次批量查询上限 500 条，防止全量数据导出 |
