# 服务端 - 用户生命周期营销自动化与智能触达策略编排引擎 详细设计

## 1. 模块概述

### 1.1 模块定位

用户生命周期营销自动化与智能触达策略编排引擎（以下简称"营销自动化引擎"，内部代号 **Pulse**）是 PrimeTop 运营增长体系的**统一触达编排中枢**。它站在推送、弹窗、短信、站内信等具体投递通道之上，负责回答四个核心问题：

1. **对谁触达** —— 基于用户生命周期阶段、行为特征、标签画像进行受众圈选
2. **何时触达** —— 基于时间触发（每日定时）、事件触发（用户完成某动作）、阶段触发（进入新生命周期阶段）三类时机
3. **触达什么** —— 编排多步骤旅程内容，每步包含渠道、素材、文案、实验变体
4. **触达效果如何** —— 全链路归因追踪，从触达到转化的完整漏斗

**与已有模块的边界划分：**

| 已有模块 | 已有职责 | 本模块增量 |
|---------|---------|-----------|
| 用户活跃度统计与留存分析引擎 | 度量 DAU/WAU/MAU、留存率、生命周期阶段标记 | **消费**生命周期阶段标签，作为旅程触发条件 |
| 用户流失预警与智能挽留策略引擎 | 预测流失风险、生成挽留策略建议 | **接收**高风险用户后纳入挽留旅程进行多步触达 |
| 运营弹窗规则引擎 | APP 内弹窗的规则匹配、频次控制、效果统计 | **调用**弹窗作为一个投放渠道，旅程中的某一步可以是弹窗 |
| 多厂商推送通道适配层 | Android/iOS 推送通道适配与投递 | **调用**推送作为一个投放渠道 |
| 统一短信验证码服务 | 短信发送网关 | **调用**短信作为一个投放渠道（营销类） |
| 用户标签与智能分群引擎 | 用户标签管理和分群圈选 | **消费**分群结果作为旅程受众 |
| AB测试与实验平台 | 通用的 A/B 实验框架 | **集成**实验平台做文案/渠道/时机的实验 |
| 通知中心与站内消息系统 | 站内信存储和展示 | **调用**站内信作为一个投放渠道 |

### 1.2 核心能力总览

| 能力 | 说明 |
|------|------|
| 旅程编排引擎 | 可视化/JSON 配置多步骤用户旅程，支持串行、并行、条件分支 |
| 触发器管理 | 时间触发、事件触发、阶段触发三类触发器，支持复合条件 |
| 受众管理 | 静态分群导入 + 动态实时圈选 + 旅程内动态入组/退组 |
| 多渠道调度 | 推送、弹窗、站内信、短信四渠道统一调度，支持渠道优先级与降级 |
| 频次控制 | 全局/旅程/渠道三级别频次上限，防止用户被过度打扰 |
| 智能时机 | 基于用户历史活跃时段，选择最佳触达时间窗口 |
| 实验集成 | 旅程中任意步骤支持 A/B 测试分组，不同变体走不同内容路径 |
| 效果归因 | 从触达→点击→行为→转化全漏斗追踪，支持首触/末触/线性归因 |
| 旅程仪表盘 | 运营人员可视化查看旅程运行状态、步骤转化、整体 ROI |

### 1.4 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 旅程定义存储 | MySQL + Redis | 旅程元数据存 MySQL，运行时状态存 Redis |

| 效果统计 | ClickHouse | 大规模事件写入 + 实时聚合查询 |
| 配置管理 | 数据库 + 本地缓存 | 旅程定义热加载 |

## 2. 核心数据模型

### 2.1 旅程定义 (journey_def)

```sql
CREATE TABLE `journey_def` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT COMMENT '旅程ID',
    `name`            VARCHAR(100) NOT NULL COMMENT '旅程名称',
    `code`            VARCHAR(50)  NOT NULL COMMENT '旅程编码（唯一）',
    `description`     TEXT         NULL     COMMENT '旅程描述',
    `trigger_type`    VARCHAR(20)  NOT NULL COMMENT '触发类型: TIME / EVENT / STAGE / MANUAL',
    `trigger_config`  JSON         NOT NULL COMMENT '触发条件配置（见 2.2）',
    `audience_type`   VARCHAR(20)  NOT NULL COMMENT '受众类型: STATIC / DYNAMIC / ALL',
    `audience_config` JSON         NULL     COMMENT '受众圈选配置（见 2.3）',
    `status`          VARCHAR(20)  NOT NULL DEFAULT 'DRAFT' COMMENT '状态: DRAFT / RUNNING / PAUSED / ARCHIVED',
    `priority`        INT          NOT NULL DEFAULT 50 COMMENT '旅程优先级（用于频控竞争，值大优先）',
    `freq_config`     JSON         NOT NULL COMMENT '频控配置（见 2.7）',
    `conversion_goal` VARCHAR(100) NULL     COMMENT '转化目标事件（如 pay_success, ai_ask_first）',
    `start_time`      DATETIME     NULL     COMMENT '生效开始时间',
    `end_time`        DATETIME     NULL     COMMENT '生效结束时间',
    `version`         INT          NOT NULL DEFAULT 1 COMMENT '版本号（乐观锁）',
    `created_by`      BIGINT       NOT NULL COMMENT '创建人',
    `updated_by`      BIGINT       NOT NULL COMMENT '更新人',
    `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`),
    KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='旅程定义';
```

### 2.2 触发器配置 (trigger_config)

触发器配置以 JSON 存储在 `journey_def.trigger_config` 中，按类型不同结构不同。

#### 2.2.1 时间触发 (TIME)

每日/每周/每月定时触达指定受众。

```json
{
  "type": "TIME",
  "cron": "0 9 * * 1-5",
  "timezone": "Asia/Shanghai",
  "oncePerUser": false,
  "maxEntries": 1
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| cron | String | 标准 cron 表达式，控制触发时机 |
| timezone | String | 用户时区，默认 Asia/Shanghai |
| oncePerUser | Boolean | 是否每用户仅触发一次 |
| maxEntries | Integer | 同一用户最大并行旅程实例数（默认 1） |

#### 2.2.2 事件触发 (EVENT)

当用户完成（或未完成）特定行为时触发。

```json
{
  "type": "EVENT",
  "eventConditions": [
    {
      "event": "ai_ask_first",
      "operator": "EQUALS",
      "value": null,
      "window": null
    }
  ],
  "logic": "AND",
  "delayMinutes": 30,
  "oncePerUser": true
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| eventConditions | Array | 事件条件列表，支持多事件 |
| event | String | 事件标识（见事件字典） |
| operator | String | EQUALS / NOT_OCCURRED / COUNT_GTE / COUNT_LTE |
| value | Any | 事件属性值（如 event=answer_correct, value.subject="math"） |
| window | Object | 时间窗口限制 `{ "value": 7, "unit": "DAYS" }` |
| logic | String | 多条件逻辑：AND / OR |
| delayMinutes | Integer | 事件发生后延迟N分钟再触发旅程 |
| oncePerUser | Boolean | 是否每用户仅触发一次 |

**支持的触发事件清单：**

| 事件标识 | 说明 | 常见旅程场景 |
|---------|------|-------------|
| `user_register` | 用户注册成功 | 新手引导旅程 |
| `ai_ask_first` | 首次发起 AI 问答 | 首次体验转化旅程 |
| `photo_search_first` | 首次拍照搜题 | 拍题功能引导 |
| `mistake_add_first` | 首次加入错题 | 错题功能引导 |
| `study_session_end` | 学习会话结束 | 学习反馈与鼓励 |
| `answer_wrong_streak` | 连续答错 ≥ N 题 | 学挫情绪安抚 |
| `membership_expire_t7` | 会员到期前7天 | 续费提醒旅程 |
| `membership_expire_t3` | 会员到期前3天 | 紧急续费提醒 |
| `membership_expired` | 会员已过期 | 权益降级挽留 |
| `free_quota_exhausted` | 免费额度用尽 | 付费转化旅程 |
| `study_plan_created` | 学习计划已创建 | 计划执行督促 |
| `exam_created` | 考试日程已录入 | 考前复习提醒 |
| `login_after_gap` | 长时间未登录后回归 | 回归欢迎旅程 |
| `parent_bound` | 家长已绑定 | 家长协同引导 |
| `textbook_changed` | 教材版本切换 | 新教材内容引导 |

#### 2.2.3 阶段触发 (STAGE)

当用户生命周期阶段发生转换时触发。

```json
{
  "type": "STAGE",
  "fromStage": "ACTIVE",
  "toStage": "DECLINING",
  "delayMinutes": 0,
  "oncePerUser": false
}
```

生命周期阶段枚举：

| 阶段 | 说明 | 判定依据 |
|------|------|---------|
| `NEW` | 新用户 | 注册 ≤ 7 天 |
| `ACTIVE` | 活跃用户 | 近 7 天 ≥ 3 次有效会话 |
| `DECLINING` | 衰退用户 | 近 14 天活跃度环比下降 > 50% |
| `DORMANT` | 沉默用户 | 近 30 天无有效会话 |
| `CHURNED` | 流失用户 | 近 60 天无登录 |
| `REACTIVATED` | 回流用户 | 流失后重新登录 |

### 2.3 受众配置 (audience_config)

```json
{
  "type": "DYNAMIC",
  "rules": {
    "logic": "AND",
    "conditions": [
      {
        "field": "user.grade",
        "operator": "IN",
        "value": ["G7", "G8", "G9"]
      },
      {
        "field": "user.stage",
        "operator": "EQUALS",
        "value": "ACTIVE"
      },
      {
        "field": "user.isMember",
        "operator": "EQUALS",
        "value": false
      },
      {
        "field": "user.tags",
        "operator": "CONTAINS_ANY",
        "value": ["science_weak", "math_strong"]
      }
    ]
  },
  "refreshInterval": "HOURLY",
  "estimatedSize": 0
}
```

| 操作符 | 说明 | 适用字段类型 |
|--------|------|-------------|
| EQUALS | 等于 | String, Number, Boolean |
| NOT_EQUALS | 不等于 | String, Number, Boolean |
| IN | 在列表中 | String, Number |
| NOT_IN | 不在列表中 | String, Number |
| CONTAINS_ANY | 包含任一标签 | Array (tags) |
| CONTAINS_ALL | 包含全部标签 | Array (tags) |
| GTE / LTE / GT / LT | 数值比较 | Number |
| BETWEEN | 范围 | Number |

### 2.4 旅程步骤 (journey_step)

```sql
CREATE TABLE `journey_step` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT,
    `journey_id`      BIGINT       NOT NULL COMMENT '所属旅程ID',
    `step_code`       VARCHAR(50)  NOT NULL COMMENT '步骤编码',
    `step_type`       VARCHAR(20)  NOT NULL COMMENT '步骤类型: ACTION / WAIT / CONDITION / END',
    `next_step_code`  VARCHAR(50)  NULL     COMMENT '下一步编码（CONDITION类型有多个分支）',
    `config`          JSON         NOT NULL COMMENT '步骤配置（见下文）',
    `sort_order`      INT          NOT NULL COMMENT '步骤序号',
    `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_journey_step` (`journey_id`, `step_code`),
    KEY `idx_journey` (`journey_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='旅程步骤定义';
```

#### 步骤类型说明

**ACTION** —— 执行一次触达动作：

```json
{
  "channel": "PUSH",
  "fallbackChannel": "IN_APP",
  "content": {
    "pushTitle": "今天的数学练习已就绪",
    "pushBody": "3道精选题目等你挑战，预计15分钟",
    "deepLink": "primetop://practice/daily?subject=math",
    "imageUrl": null
  },
  "experimentId": null,
  "variants": null
}
```

**WAIT** —— 等待时间或等待事件：

```json
{
  "waitType": "DURATION",
  "duration": 1440,
  "durationUnit": "MINUTES"
}
```

或等待用户事件：

```json
{
  "waitType": "EVENT",
  "event": "study_session_end",
  "timeoutMinutes": 2880,
  "timeoutBranch": "step_remind_again"
}
```

**CONDITION** —— 条件分支判断：

```json
{
  "branches": [
    {
      "condition": {
        "field": "user.studyStreakDays",
        "operator": "GTE",
        "value": 7
      },
      "nextStepCode": "step_encourage_streak"
    },
    {
      "condition": {
        "field": "user.studyStreakDays",
        "operator": "LT",
        "value": 3
      },
      "nextStepCode": "step_motivate_restart"
    }
  ],
  "defaultBranch": "step_continue_normal"
}
```

**END** —— 旅程结束节点：

```json
{
  "endReason": "COMPLETED",
  "markConversion": true
}
```

### 2.7 频次控制配置 (freq_config)

```json
{
  "globalDailyCap": 3,
  "journeyDailyCap": 1,
  "channelCap": {
    "PUSH": 2,
    "POPUP": 1,
    "SMS": 1,
    "IN_APP": 5
  },
  "cooldownMinutes": {
    "PUSH": 240,
    "SMS": 1440
  },
  "quietHours": {
    "start": "22:00",
    "end": "08:00"
  },
  "respectOptOut": true
}
```

| 字段 | 说明 |
|------|------|
| globalDailyCap | 单用户每日所有营销触达上限 |
| journeyDailyCap | 单用户每日同一旅程触达上限 |
| channelCap | 单用户每日每个渠道触达上限 |

**核心代码 — 触发器消费器：**

```java
@Component
@Slf4j
public class TriggerConsumer {

    @Autowired private TriggerMatcher triggerMatcher;
    @Autowired private AudienceChecker audienceChecker;
    @Autowired private JourneyInstanceService instanceService;
    @Autowired private FrequencyGuard frequencyGuard;

    /**
     * 消费用户行为事件，匹配事件触发器
     */
    @KafkaListener(topics = "user-action-events", groupId = "pulse-trigger")
    public void onUserAction(UserActionEvent event) {
        // 1. 查找所有当前 RUNNING 且触发类型为 EVENT 的旅程
        List<JourneyDef> activeJourneys = journeyCache.getActiveEventJourneys();

        for (JourneyDef journey : activeJourneys) {
            try {
                // 2. 匹配触发条件
                TriggerMatchResult matchResult = triggerMatcher.match(journey, event);
                if (!matchResult.isMatched()) {
                    continue;
                }

                // 3. 延迟检查（部分触发器配置了 delayMinutes）
                if (journey.getTriggerConfig().getDelayMinutes() > 0) {
                    delayQueueService.scheduleEnrollment(
                        journey.getId(), event.getUserId(),
                        journey.getTriggerConfig().getDelayMinutes()
                    );
                    continue;
                }

                // 4. 执行入组
                doEnroll(journey, event.getUserId());

            } catch (Exception e) {
                log.error("Trigger matching failed. journeyId={}, event={}",
                    journey.getId(), event, e);
            }
        }
    }

    private void doEnroll(JourneyDef journey, Long userId) {
        // 受众校验
        if (!audienceChecker.matches(journey.getAudienceConfig(), userId)) {
            log.debug("User {} not in audience for journey {}", userId, journey.getId());
            return;
        }

        // 并行实例数限制
        int activeCount = instanceService.countActive(journey.getId(), userId);
        if (activeCount >= journey.getTriggerConfig().getMaxEntries()) {
            log.debug("User {} already has {} active instances for journey {}",
                userId, activeCount, journey.getId());
            return;
        }

        // 频控预检
        FrequencyCheckResult freqResult = frequencyGuard.checkGlobalCap(userId);
        if (!freqResult.isAllowed()) {
            log.debug("User {} blocked by frequency cap: {}", userId, freqResult.getReason());
            return;
        }

        // 退订检查
        if (!optOutService.canReceive(userId, journey.getCategory())) {
            log.debug("User {} opted out for category {}", userId, journey.getCategory());
            return;
        }

        // 创建实例，进入首步
        instanceService.createAndStart(journey, userId);
    }
}
```
