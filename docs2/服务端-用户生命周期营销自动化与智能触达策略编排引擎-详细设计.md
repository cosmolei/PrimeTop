# 服务端 - 用户生命周期营销自动化与智能触达策略编排引擎 详细设计

## 1. 模块概述

### 1.1 模块定位

用户生命周期营销自动化与智能触达策略编排引擎（以下简称"营销自动化引擎"，内部代号 **Pulse**）是 PrimeTop 运营增长体系的**统一触达编排中枢**。它站在推送、弹窗、短信、站内信等具体投递通道之上，负责回答四个核心问题：

1. **对谁触达** —— 基于用户生命周期阶段、行为特征、标签画像进行受众圈选
2. **何时触达** —— 基于时间触发（每日定时）、事件触发（用户完成某动作）、阶段触发（进入新生命周期阶段）三类时机
3. **触达什么** —— 编排多步骤旅程内容，每步包含渠道、素材、文案、实验变体
4. **触达效果如何** —— 全链路归因追踪，从触达到转化的完整漏斗

**与已有模块的边界划分：**

| 已有模块 | 已有职责 | 本模块增量 |
|---------|---------|-----------|
| 用户活跃度统计与留存分析引擎 | 度量 DAU/WAU/MAU、留存率、生命周期阶段标记 | **消费**生命周期阶段标签，作为旅程触发条件 |
| 用户流失预警与智能挽留策略引擎 | 预测流失风险、生成挽留策略建议 | **接收**高风险用户后纳入挽留旅程进行多步触达 |
| 运营弹窗规则引擎 | APP 内弹窗的规则匹配、频次控制、效果统计 | **调用**弹窗作为一个投放渠道，旅程中的某一步可以是弹窗 |
| 多厂商推送通道适配层 | Android/iOS 推送通道适配与投递 | **调用**推送作为一个投放渠道 |
| 统一短信验证码服务 | 短信发送网关 | **调用**短信作为一个投放渠道（营销类） |
| 用户标签与智能分群引擎 | 用户标签管理和分群圈选 | **消费**分群结果作为旅程受众 |
| AB测试与实验平台 | 通用的 A/B 实验框架 | **集成**实验平台做文案/渠道/时机的实验 |
| 通知中心与站内消息系统 | 站内信存储和展示 | **调用**站内信作为一个投放渠道 |

### 1.2 核心能力总览

| 能力 | 说明 |
|------|------|
| 旅程编排引擎 | 可视化/JSON 配置多步骤用户旅程，支持串行、并行、条件分支 |
| 触发器管理 | 时间触发、事件触发、阶段触发三类触发器，支持复合条件 |
| 受众管理 | 静态分群导入 + 动态实时圈选 + 旅程内动态入组/退组 |
| 多渠道调度 | 推送、弹窗、站内信、短信四渠道统一调度，支持渠道优先级与降级 |
| 频次控制 | 全局/旅程/渠道三级别频次上限，防止用户被过度打扰 |
| 智能时机 | 基于用户历史活跃时段，选择最佳触达时间窗口 |
| 实验集成 | 旅程中任意步骤支持 A/B 测试分组，不同变体走不同内容路径 |
| 效果归因 | 从触达→点击→行为→转化全漏斗追踪，支持首触/末触/线性归因 |
| 旅程仪表盘 | 运营人员可视化查看旅程运行状态、步骤转化、整体 ROI |

### 1.4 技术选型

| 组件 | 选型 | 说明 |

| 旅程定义存储 | MySQL + Redis | 旅程元数据存 MySQL，运行时状态存 Redis |

| 配置管理 | 数据库 + 本地缓存 | 旅程定义热加载 |

## 2. 核心数据模型

### 2.1 旅程定义 (journey_def)

```sql
CREATE TABLE `journey_def` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT COMMENT '旅程ID',
    `name`            VARCHAR(100) NOT NULL COMMENT '旅程名称',
    `code`            VARCHAR(50)  NOT NULL COMMENT '旅程编码（唯一）',
    `description`     TEXT         NULL     COMMENT '旅程描述',
    `trigger_type`    VARCHAR(20)  NOT NULL COMMENT '触发类型: TIME / EVENT / STAGE / MANUAL',
    `trigger_config`  JSON         NOT NULL COMMENT '触发条件配置（见 2.2）',
    `audience_type`   VARCHAR(20)  NOT NULL COMMENT '受众类型: STATIC / DYNAMIC / ALL',
    `audience_config` JSON         NULL     COMMENT '受众圈选配置（见 2.3）',
    `status`          VARCHAR(20)  NOT NULL DEFAULT 'DRAFT' COMMENT '状态: DRAFT / RUNNING / PAUSED / ARCHIVED',
    `priority`        INT          NOT NULL DEFAULT 50 COMMENT '旅程优先级（用于频控竞争，值大优先）',
    `freq_config`     JSON         NOT NULL COMMENT '频控配置（见 2.7）',
    `conversion_goal` VARCHAR(100) NULL     COMMENT '转化目标事件（如 pay_success, ai_ask_first）',
    `start_time`      DATETIME     NULL     COMMENT '生效开始时间',
    `end_time`        DATETIME     NULL     COMMENT '生效结束时间',
    `version`         INT          NOT NULL DEFAULT 1 COMMENT '版本号（乐观锁）',
    `created_by`      BIGINT       NOT NULL COMMENT '创建人',
    `updated_by`      BIGINT       NOT NULL COMMENT '更新人',
    `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`),
    KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='旅程定义';
```

### 2.2 触发器配置 (trigger_config)

触发器配置以 JSON 存储在 `journey_def.trigger_config` 中，按类型不同结构不同。

#### 2.2.1 时间触发 (TIME)

每日/每周/每月定时触达指定受众。

```json
{
  "type": "TIME",
  "cron": "0 9 * * 1-5",
  "timezone": "Asia/Shanghai",
  "oncePerUser": false,
  "maxEntries": 1
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| cron | String | 标准 cron 表达式，控制触发时机 |
| timezone | String | 用户时区，默认 Asia/Shanghai |
| oncePerUser | Boolean | 是否每用户仅触发一次 |
| maxEntries | Integer | 同一用户最大并行旅程实例数（默认 1） |

#### 2.2.2 事件触发 (EVENT)

当用户完成（或未完成）特定行为时触发。

```json
{
  "type": "EVENT",
  "eventConditions": [
    {
      "event": "ai_ask_first",
      "operator": "EQUALS",
      "value": null,
      "window": null
    }
  ],
  "logic": "AND",
  "delayMinutes": 30,
  "oncePerUser": true
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| eventConditions | Array | 事件条件列表，支持多事件 |
| event | String | 事件标识（见事件字典） |
| operator | String | EQUALS / NOT_OCCURRED / COUNT_GTE / COUNT_LTE |
| value | Any | 事件属性值（如 event=answer_correct, value.subject="math"） |
| window | Object | 时间窗口限制 `{ "value": 7, "unit": "DAYS" }` |
| logic | String | 多条件逻辑：AND / OR |
| delayMinutes | Integer | 事件发生后延迟N分钟再触发旅程 |
| oncePerUser | Boolean | 是否每用户仅触发一次 |

**支持的触发事件清单：**

| 事件标识 | 说明 | 常见旅程场景 |
|---------|------|-------------|
| `user_register` | 用户注册成功 | 新手引导旅程 |
| `ai_ask_first` | 首次发起 AI 问答 | 首次体验转化旅程 |
| `photo_search_first` | 首次拍照搜题 | 拍题功能引导 |
| `mistake_add_first` | 首次加入错题 | 错题功能引导 |
| `study_session_end` | 学习会话结束 | 学习反馈与鼓励 |
| `answer_wrong_streak` | 连续答错 ≥ N 题 | 学挫情绪安抚 |
| `membership_expire_t7` | 会员到期前7天 | 续费提醒旅程 |
| `membership_expire_t3` | 会员到期前3天 | 紧急续费提醒 |
| `membership_expired` | 会员已过期 | 权益降级挽留 |
| `free_quota_exhausted` | 免费额度用尽 | 付费转化旅程 |
| `study_plan_created` | 学习计划已创建 | 计划执行督促 |
| `exam_created` | 考试日程已录入 | 考前复习提醒 |
| `login_after_gap` | 长时间未登录后回归 | 回归欢迎旅程 |
| `parent_bound` | 家长已绑定 | 家长协同引导 |
| `textbook_changed` | 教材版本切换 | 新教材内容引导 |

#### 2.2.3 阶段触发 (STAGE)

当用户生命周期阶段发生转换时触发。

```json
{
  "type": "STAGE",
  "fromStage": "ACTIVE",
  "toStage": "DECLINING",
  "delayMinutes": 0,
  "oncePerUser": false
}
```

生命周期阶段枚举：

| 阶段 | 说明 | 判定依据 |
|------|------|---------|
| `NEW` | 新用户 | 注册 ≤ 7 天 |
| `ACTIVE` | 活跃用户 | 近 7 天 ≥ 3 次有效会话 |
| `DECLINING` | 衰退用户 | 近 14 天活跃度环比下降 > 50% |
| `DORMANT` | 沉默用户 | 近 30 天无有效会话 |
| `CHURNED` | 流失用户 | 近 60 天无登录 |
| `REACTIVATED` | 回流用户 | 流失后重新登录 |

### 2.3 受众配置 (audience_config)

```json
{
  "type": "DYNAMIC",
  "rules": {
    "logic": "AND",
    "conditions": [
      {
        "field": "user.grade",
        "operator": "IN",
        "value": ["G7", "G8", "G9"]
      },
      {
        "field": "user.stage",
        "operator": "EQUALS",
        "value": "ACTIVE"
      },
      {
        "field": "user.isMember",
        "operator": "EQUALS",
        "value": false
      },
      {
        "field": "user.tags",
        "operator": "CONTAINS_ANY",
        "value": ["science_weak", "math_strong"]
      }
    ]
  },
  "refreshInterval": "HOURLY",
  "estimatedSize": 0
}
```

| 操作符 | 说明 | 适用字段类型 |
|--------|------|-------------|
| EQUALS | 等于 | String, Number, Boolean |
| NOT_EQUALS | 不等于 | String, Number, Boolean |
| IN | 在列表中 | String, Number |
| NOT_IN | 不在列表中 | String, Number |
| CONTAINS_ANY | 包含任一标签 | Array (tags) |
| CONTAINS_ALL | 包含全部标签 | Array (tags) |
| GTE / LTE / GT / LT | 数值比较 | Number |
| BETWEEN | 范围 | Number |

### 2.4 旅程步骤 (journey_step)

```sql
CREATE TABLE `journey_step` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT,
    `journey_id`      BIGINT       NOT NULL COMMENT '所属旅程ID',
    `step_code`       VARCHAR(50)  NOT NULL COMMENT '步骤编码',
    `step_type`       VARCHAR(20)  NOT NULL COMMENT '步骤类型: ACTION / WAIT / CONDITION / END',
    `next_step_code`  VARCHAR(50)  NULL     COMMENT '下一步编码（CONDITION类型有多个分支）',
    `config`          JSON         NOT NULL COMMENT '步骤配置（见下文）',
    `sort_order`      INT          NOT NULL COMMENT '步骤序号',
    `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_journey_step` (`journey_id`, `step_code`),
    KEY `idx_journey` (`journey_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='旅程步骤定义';
```

#### 步骤类型说明

**ACTION** —— 执行一次触达动作：

```json
{
  "channel": "PUSH",
  "fallbackChannel": "IN_APP",
  "content": {
    "pushTitle": "今天的数学练习已就绪",
    "pushBody": "3道精选题目等你挑战，预计15分钟",
    "deepLink": "primetop://practice/daily?subject=math",
    "imageUrl": null
  },
  "experimentId": null,
  "variants": null
}
```

**WAIT** —— 等待时间或等待事件：

```json
{
  "waitType": "DURATION",
  "duration": 1440,
  "durationUnit": "MINUTES"
}
```

或等待用户事件：

```json
{
  "waitType": "EVENT",
  "event": "study_session_end",
  "timeoutMinutes": 2880,
  "timeoutBranch": "step_remind_again"
}
```

**CONDITION** —— 条件分支判断：

```json
{
  "branches": [
    {
      "condition": {
        "field": "user.studyStreakDays",
        "operator": "GTE",
        "value": 7
      },
      "nextStepCode": "step_encourage_streak"
    },
    {
      "condition": {
        "field": "user.studyStreakDays",
        "operator": "LT",
        "value": 3
      },
      "nextStepCode": "step_motivate_restart"
    }
  ],
  "defaultBranch": "step_continue_normal"
}
```

**END** —— 旅程结束节点：

```json
{
  "endReason": "COMPLETED",
  "markConversion": true
}
```

### 2.7 频次控制配置 (freq_config)

```json
{
  "globalDailyCap": 3,
  "journeyDailyCap": 1,
  "channelCap": {
    "PUSH": 2,
    "POPUP": 1,
    "SMS": 1,
    "IN_APP": 5
  },
  "cooldownMinutes": {
    "PUSH": 240,
    "SMS": 1440
  },
  "quietHours": {
    "start": "22:00",
    "end": "08:00"
  },
  "respectOptOut": true
}
```

| 字段 | 说明 |
|------|------|
| globalDailyCap | 单用户每日所有营销触达上限 |

**核心代码 — 触发器消费器：**

```java
@Component
@Slf4j
public class TriggerConsumer {

    @Autowired private TriggerMatcher triggerMatcher;
    @Autowired private AudienceChecker audienceChecker;
    @Autowired private JourneyInstanceService instanceService;
    @Autowired private FrequencyGuard frequencyGuard;

    /**
     * 消费用户行为事件，匹配事件触发器
     */
    @KafkaListener(topics = "user-action-events", groupId = "pulse-trigger")
    public void onUserAction(UserActionEvent event) {
        // 1. 查找所有当前 RUNNING 且触发类型为 EVENT 的旅程
        List<JourneyDef> activeJourneys = journeyCache.getActiveEventJourneys();

        for (JourneyDef journey : activeJourneys) {
            try {
                // 2. 匹配触发条件
                TriggerMatchResult matchResult = triggerMatcher.match(journey, event);
                if (!matchResult.isMatched()) {
                    continue;
                }

                // 3. 延迟检查（部分触发器配置了 delayMinutes）
                if (journey.getTriggerConfig().getDelayMinutes() > 0) {
                    delayQueueService.scheduleEnrollment(
                        journey.getId(), event.getUserId(),
                        journey.getTriggerConfig().getDelayMinutes()
                    );
                    continue;
                }

                // 4. 执行入组
                doEnroll(journey, event.getUserId());

            } catch (Exception e) {
                log.error("Trigger matching failed. journeyId={}, event={}",
                    journey.getId(), event, e);
            }
        }
    }

    private void doEnroll(JourneyDef journey, Long userId) {
        // 受众校验
        if (!audienceChecker.matches(journey.getAudienceConfig(), userId)) {
            log.debug("User {} not in audience for journey {}", userId, journey.getId());
            return;
        }

        // 并行实例数限制
        int activeCount = instanceService.countActive(journey.getId(), userId);
        if (activeCount >= journey.getTriggerConfig().getMaxEntries()) {
            log.debug("User {} already has {} active instances for journey {}",
                userId, activeCount, journey.getId());
            return;
        }

        // 频控预检
        FrequencyCheckResult freqResult = frequencyGuard.checkGlobalCap(userId);
        if (!freqResult.isAllowed()) {
            log.debug("User {} blocked by frequency cap: {}", userId, freqResult.getReason());
            return;
        }

        // 退订检查
        if (!optOutService.canReceive(userId, journey.getCategory())) {
            log.debug("User {} opted out for category {}", userId, journey.getCategory());
            return;
        }

        // 创建实例，进入首步
        instanceService.createAndStart(journey, userId);
    }
}
```

**步骤调度器核心代码：**

```java
@Component
@Slf4j
public class StepScheduler {

    private static final String DUE_ZSET = "pulse:step:due";
    private static final long SCAN_INTERVAL_MS = 30_000;
    private static final int BATCH_SIZE = 500;

    @Autowired private StringRedisTemplate redis;
    @Autowired private StepExecutor stepExecutor;
    @Autowired private JourneyInstanceService instanceService;

    /**
     * 每 30s 扫描一次到期步骤。Lua 原子领取：ZRANGEBYSCORE + ZREM，
     * 防止多节点部署时同一任务被重复执行（守卫 G3）。
     */
    @Scheduled(fixedDelay = SCAN_INTERVAL_MS)
    public void scanDueSteps() {
        long now = System.currentTimeMillis();
        // Lua: 取出 score<=now 的 BATCH_SIZE 个成员并删除，返回成员列表
        List<String> dueItems = redis.execute(DUE_CLAIM_LUA,
            Arrays.asList(DUE_ZSET),
            String.valueOf(now), String.valueOf(BATCH_SIZE));

        if (dueItems == null || dueItems.isEmpty()) return;

        for (String item : dueItems) {
            // item 格式: {instanceId}:{stepCode}
            String[] parts = item.split(":");
            Long instanceId = Long.valueOf(parts[0]);
            try {
                JourneyInstance inst = instanceService.getForUpdate(instanceId);
                // 实例可能已被归档/退出（守卫 G8），跳过并记录
                if (inst == null || !"RUNNING".equals(inst.getStatus())) {
                    log.info("Skip due step for non-running instance {}", instanceId);
                    continue;
                }
                stepExecutor.execute(inst, parts[1]);
            } catch (Exception e) {
                log.error("Step execution failed. instance={}, step={}", instanceId, parts[1], e);
                // 失败补偿：见 §11 E2，重入 ZSet 延迟重试（≤3 次）
                retryQueue.requeue(instanceId, parts[1], e);
            }
        }
    }
}
```

**StepExecutor 执行骨架（ACTION 分支）：**

```java
@Component
public class StepExecutor {

    @Autowired private FrequencyGuard frequencyGuard;      // 旅程级频控（全局级委托治理引擎）
    @Autowired private TimingClient timingClient;          // 智能时机（委托 58500 时机引擎）
    @Autowired private DeliveryGateway deliveryGateway;    // 渠道委托（治理引擎统一入口）
    @Autowired private OptOutChecker optOutChecker;        // 退订二次校验（守卫 G6）
    @Autowired private MinorGuard minorGuard;              // 未成年人营销 fail-closed（守卫 G7）
    @Autowired private StepLogService stepLogService;
    @Autowired private JourneyInstanceService instanceService;

    public void execute(JourneyInstance inst, String stepCode) {
        JourneyStep step = stepDefService.get(inst.getJourneyId(), stepCode);

        switch (step.getStepType()) {
            case "ACTION" -> executeAction(inst, step);
            case "WAIT"   -> executeWait(inst, step);
            case "CONDITION" -> executeCondition(inst, step);
            case "END"    -> instanceService.complete(inst, step.getConfig());
        }
    }

    private void executeAction(JourneyInstance inst, JourneyStep step) {
        Long userId = inst.getUserId();
        ActionConfig cfg = step.parseActionConfig();

        // 1. 旅程级频控（journeyDailyCap/oncePerUser，全局级权威在治理引擎）
        if (!frequencyGuard.checkJourneyCap(inst.getJourneyId(), userId)) {
            stepLogService.skip(inst, step, "FREQ_LIMIT");
            advance(inst, null);  // 跳过本步，继续推进
            return;
        }

        // 2. 未成年人营销 fail-closed（守卫 G7，先于一切渠道委托）
        if (minorGuard.isMarketingBlocked(userId, journey.getCategory())) {
            stepLogService.skip(inst, step, "MINOR_BLOCKED");
            instanceService.exit(inst, "MINOR_BLOCKED");  // 营销旅程对未成年整程退出
            return;
        }

        // 3. 退订二次校验（治理引擎投递前亦有校验，双保险 G6）
        if (!optOutChecker.canReceive(userId, journey.getCategory(), cfg.getChannel())) {
            stepLogService.skip(inst, step, "OPT_OUT");
            advance(inst, null);
            return;
        }

        // 4. 智能时机（委托 58500，本地缓存 10min，超时取配置默认窗口）
        LocalDateTime bestTime = timingClient.decide(userId, cfg.getSceneId())
            .orElse(cfg.getDefaultSendTime());

        // 5. 渠道委托投递（统一治理入口，含全局频控/合并/免打扰二次裁决）
        DeliveryResult result = deliveryGateway.deliver(userId, cfg, bestTime, inst, step);

        // 6. 记录与推进（决策性抑制 SUPPRESS 不是错误，照常推进，见契约 R1）
        stepLogService.record(inst, step, result);
        advance(inst, step.getNextStepCode());
    }
}
```

### 3.4 智能时机与频控委托流程

Pulse 不重复实现全局频控与最佳时机算法，两个权威均委托既有引擎，本引擎只保留**旅程编排语义级**的频控（journeyDailyCap、oncePerUser、maxEntries）：

```

        │  (Idempotency-Key=pulse:{instanceId}:{stepCode})  │
        │                                    │
        ├─ 智能最佳时机 ─────────────────────▶ 58500 时机引擎 gRPC Decide
        │  (本地缓存 10min, 超时取默认窗口)      │
        │                                    │
        ├─ POPUP 渠道素材 ───────────────────▶ 运营弹窗引擎 campaign API
        │  (其余渠道全部走治理引擎统一入口)      │
        │                                    │
        ├─ 短信 ─────────────────────────────▶ 统一短信网关(营销模板审核+双同意)
        │                                    │
```

**延迟预算（ACTION 步骤执行全链路 P99 ≤ 800ms）：**

**归因模型：**

### 5.2 条件评估器（CONDITION 步骤）

```java
@Component
public class ConditionEvaluator {

    @Autowired private UserFeatureClient featureClient;  // 画像服务只读

    public String evaluate(ConditionConfig cfg, Long userId) {
        Map<String, Object> features = featureClient.get(userId,
            cfg.extractFields());  // 批量拉取，单次 ≤20 字段

        for (ConditionBranch branch : cfg.getBranches()) {
            if (evalCondition(branch.getCondition(), features)) {
                return branch.getNextStepCode();
            }
        }
        return cfg.getDefaultBranch();  // defaultBranch 必填（发布时校验）
    }

    private boolean evalCondition(Condition c, Map<String, Object> f) {
        Object actual = f.get(c.getField());
        return switch (c.getOperator()) {
            case "EQUALS"     -> Objects.equals(actual, c.getValue());
            case "NOT_EQUALS" -> !Objects.equals(actual, c.getValue());
            case "IN"         -> ((List<?>) c.getValue()).contains(actual);
            case "GTE"        -> ((Number) actual).doubleValue() >= ((Number) c.getValue()).doubleValue();
            case "LT"         -> ((Number) actual).doubleValue() <  ((Number) c.getValue()).doubleValue();
            default -> throw new BizException(52806, "未知操作符: " + c.getOperator());
        };
    }
}
```

```java
@Component
public class DeliveryGateway {

    @Autowired private NotifyGovernClient governClient;   // 52500 统一治理入口
    @Autowired private PopupEngineClient popupClient;     // 弹窗引擎（POPUP 渠道）
    @Autowired private SmsGatewayClient smsClient;        // 短信网关（含营销审核）

    public DeliveryResult deliver(Long userId, ActionConfig cfg,
                                  LocalDateTime sendAt,
                                  JourneyInstance inst, JourneyStep step) {
        String requestId = "pulse:" + inst.getId() + ":" + step.getStepCode();

        switch (cfg.getChannel()) {
            case "PUSH", "IN_APP" -> {
                // 全量走治理引擎：全局频控/合并/免打扰/最佳时机二次裁决
                GovernResponse resp = governClient.send(GovernRequest.builder()
                    .requestId(requestId)
                    .userId(userId)
                    .source(journeyCategoryToSource(journey.getCategory()))
                    .title(cfg.getPushTitle()).body(cfg.getPushBody())
                    .channels(List.of(cfg.getChannel()))
                    .deepLink(cfg.getDeepLink())
                    .businessRef(new BusinessRef("journey_step", requestId))
                    .expireAt(sendAt.plusHours(24))
                    .sceneId(cfg.getSceneId())
                    .build());
                // SUPPRESS/MERGE_DELAYED 为正常决策（52823 语义），不得重试
                return DeliveryResult.fromGovern(resp);
            }
            case "POPUP" -> {
                // 委托弹窗引擎创建活动，受众为当前用户快照
                return popupClient.dispatchJourneyPopup(userId, cfg, requestId);
            }
            case "SMS" -> {
                // 营销短信：模板须审核通过 + 用户双同意（网关侧硬校验）
                return smsClient.sendMarketing(userId, cfg.getSmsTemplateId(), cfg.getParams(), requestId);
            }
            default -> throw new BizException(52807, "未知渠道: " + cfg.getChannel());
        }
    }

    /** fallbackChannel：治理网关返回 CHANNEL_UNAVAILABLE 时一次性降级渠道重试 */
    private DeliveryResult tryFallback(Long userId, ActionConfig cfg, DeliveryResult r) {
        if (r.isChannelUnavailable() && cfg.getFallbackChannel() != null) {
            ActionConfig fb = cfg.withChannel(cfg.getFallbackChannel());
            return deliver(userId, fb, LocalDateTime.now(), null, null); // requestId 后缀 :fb 区分
        }
        return r;
    }
}
```

```java
@Component
public class TimingClient {

    private static final String CACHE_KEY = "pulse:timing:{userId}";
    private static final long CACHE_TTL = 600;  // 10min

    @Autowired private BestTimeGrpcClient bestTimeClient;   // 58500 时机引擎
    @Autowired private StringRedisTemplate redis;

    public Optional<LocalDateTime> decide(Long userId, String sceneId) {
        String cached = redis.opsForValue().get(CACHE_KEY.replace("{userId}", userId.toString()));
        if (cached != null) return Optional.of(LocalDateTime.parse(cached));
        try {
```

```java
@Component
public class LastTouchAttributor {

    @Autowired private StepLogRepository stepLogRepository;
    @Autowired private JourneyInstanceRepository instanceRepository;

    @Transactional
    public void onConversion(Long userId, String goal, Map<String, Object> event) {
        // 1. 找该用户 48h 窗口内最近一次 CLICKED 的 step_log
        StepLog lastClick = stepLogRepository.findLastClickedWithin(
            userId, Duration.ofHours(48));
        if (lastClick == null) return;   // 窗口外点击，不归因

        // 2. CAS 回填转化（防并发双计）
        int updated = instanceRepository.markConverted(
            lastClick.getInstanceId(), Instant.now());
        if (updated == 0) return;        // 已转化，幂等吞没

        // 3. step_log 推进 CONVERTED + 发布事件（同事务 Outbox）
        stepLogRepository.markConverted(lastClick.getId());
        outbox.publish(new ConversionAttributedEvent(
            lastClick.getJourneyId(), lastClick.getStepCode(), userId, goal,
            event.get("orderId")));
    }
}
```

### 7.1 旅程定义状态机

## 11. 降级矩阵

| 编号 | 故障场景 | 降级策略 | 红线 |
|------|---------|---------|------|
| D1 | MySQL 主库故障 | 旅程定义读 Redis 缓存（5min 旧数据），实例推进暂停（入组拒绝，返回 52800 上游重试） | 不丢已领取的 ZSet 任务（Redis 独立可用） |
| D2 | Redis 故障 | 暂停新入组与步骤调度（fail-stop），DB 权威不受影响；恢复后经实例表扫描重建 ZSet（兑底任务） | 不双发：重建前校验 step_log 防重 |
| D3 | 58500 时机引擎故障 | 取配置默认发送窗口（TimingClient 超时降级） | 仅影响时机质量，不阻塞触达 |
| D4 | 治理引擎（52500）超时 | 单次重试 + 指数退避 ≤3 次；持续失败该步置 FAILED，旅程不阻塞推进 | **绝不绕过治理引擎直发渠道（频控/未成年保护不可绕过）** |
| D5 | 画像服务故障 | CONDITION 评估失败→走 defaultBranch；受众 DYNAMIC 校验失败→拒绝入组（fail-closed 营销，fail-open 学习提醒） | 营销 fail-closed |
| D6 | 弹窗引擎故障 | POPUP 渠道降级 fallbackChannel（默认 IN_APP） | — |
| D7 | CH 故障 | 归因与看板延迟，MySQL step_log 为短期兑底（7 天） | 不丢回执（先入 MySQL） |
| D8 | Kafka 故障 | Outbox 积压，恢复后补投；触发器事件消费落后>10min 告警 | 不丢事件（埋点平台重放） |
| D9 | 通知偏好中心故障 | 退订投影本地缓存 24h 有效期内继续有效；过期后营销 fail-closed | 未成年人保护不降级 |
| D10 | AB 平台故障 | 实验分流失效→走默认变体（对照组） | 实验组用户不得误入对照内容 |

**总红线：** 任何降级不得绕过全局频控治理与未成年人营销 fail-closed；营销类旅程对一切依赖故障默认 fail-closed，学习提醒类至多延迟、不得放大打扰。

## 12. 监控与容量

| 指标 | 口径 | 告警阈值 |
|------|------|---------|
| M1 入组速率 | 每分钟新实例数（分旅程） | 突增 >5×基线 10min → P2 |
| M2 步骤执行成功率 | 1 - FAILED/总执行 | <98% 15min → P2；<95% → P1 |
| M3 治理引擎决策延迟 | deliver 调用 P99 | >500ms 10min → P2 |
| M4 决策性抑制率 | SUPPRESS+MERGE/总决策 | >40% 连续 1h → 提示运营检查频控配置 |
| M5 退订率 | 退订用户/触达用户（日） | >2% 单日 → P2（话术/频次问题） |
| M6 实例积压 | ZSet due 队列长度 | >10 万 → P2；>50 万 → P1 |
| M7 转化率（分旅程） | attributed conversion/入组 | 较 7 天基线跌 >50% → 提示 |
| M8 Outbox 积压 | PENDING 事件数 | >5 万 → P2 |
| M9 未成年人拦截数 | MINOR_BLOCKED 退出（日） | 突增说明营销配置错误 → P2 |
| M10 对账差异 | Outbox↔Kafka / step_log↔CH | >0.5% → P2 |

| 项 | 估算 |
|----|------|
| 行为事件触发匹配 | 日 2000 万事件 × 倒排索引后平均每事件命中 0.3 旅程 → 600 万次匹配评估 |

| ClickHouse | 漏斗宽表日增 150 万行 ≈ 300MB/日 |
