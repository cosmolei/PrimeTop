# 用户账号体系 - 详细设计文档

## 1. 模块概述

用户账号体系是 PrimeTop 的基础设施，涵盖用户注册登录、学生档案管理、家长绑定与权限控制、会员状态管理。所有业务模块（AI辅导、拍题、错题等）均依赖此模块完成身份识别和权限校验。

### 1.1 功能范围

| 功能 | 优先级 | MVP |
|------|--------|-----|
| 手机号+验证码注册/登录 | P0 | ✅ |
| 第三方登录（微信/Apple） | P0 | ✅ |
| 年级学段选择与切换 | P0 | ✅ |
| 教材版本设置 | P0 | ✅ |
| 家长绑定学生账号 | P1 | ❌ |
| 家长控制（时长/内容） | P1 | ❌ |
| Token 鉴权与刷新 | P0 | ✅ |
| 个人中心基本管理 | P0 | ✅ |

## 3. API 接口设计

### 3.1 基础约定

- **Base URL**: `/api/v1`
- **认证方式**: Bearer Token (JWT)，放在 `Authorization` 头
- **请求格式**: JSON
- **统一响应结构**:

```json
{
    "code": 0,
    "message": "success",
    "data": { ... },
    "timestamp": 1716000000000
}
```

**错误码规范**:

| 错误码 | 含义 | HTTP状态码 |
|--------|------|-----------|
| 0 | 成功 | 200 |
| 10001 | 参数错误 | 400 |
| 10002 | 验证码错误/过期 | 400 |
| 10003 | 手机号已注册 | 409 |
| 10004 | 用户不存在 | 404 |
| 10005 | 密码错误 | 401 |
| 10006 | 账号已禁用 | 403 |
| 10007 | Token 过期 | 401 |
| 10008 | Token 无效 | 401 |
| 10009 | 第三方登录失败 | 400 |
| 10010 | 操作频率过高 | 429 |
| 20001 | 会员已过期 | 403 |
| 20002 | 额度已用完 | 403 |
| 50001 | 服务内部错误 | 500 |

### 3.2 验证码发送

```
POST /api/v1/auth/sms/send
```

**Request:**
```json
{
    "phone": "13800138000",
    "purpose": "register"  // register | login | bind_phone | reset_password
}
```

**Response:**
```json
{
    "code": 0,
    "message": "success",
    "data": {
        "expires_in": 300,
        "interval": 60
    }
}
```

**业务规则:**
- 同一手机号 60 秒内限发 1 次
- 同一 IP 每小时限发 10 次
- 验证码 5 分钟有效
- 使用阿里云/腾讯云短信服务
- 验证码为 6 位数字

## 4. Token 与鉴权设计

### 4.1 JWT 结构

```json
// Access Token Payload（有效期 24 小时）
{
    "sub": "100001",           // user_id
    "type": "student",         // user_type
    "jti": "uuid-random",      // token 唯一ID，用于黑名单
    "iat": 1716000000,
    "exp": 1716086400
}

// Refresh Token Payload（有效期 30 天）
{
    "sub": "100001",
    "type": "refresh",
    "jti": "uuid-random",
    "iat": 1716000000,
    "exp": 1718592000
}
```

### 4.2 鉴权流程

```
客户端请求 → API网关 → 提取 Bearer Token → JWT验签
    ↓ Token有效
检查黑名单(Redis: token_blacklist:{jti})
    ↓ 不在黑名单
解析 user_id, user_type → 注入请求上下文 → 转发到业务服务
```

### 4.3 额度检查中间件

AI 和 OCR 接口需检查会员额度：

```python
async def check_quota(user_id: int, quota_type: str) -> bool:
    """
    quota_type: 'ai' | 'ocr'
    使用 Redis 计数器实现每日额度
    """
    key = f"quota:{quota_type}:{user_id}:{date.today()}"
    count = await redis.incr(key)
    if count == 1:
        await redis.expire(key, 86400)  # 首次设置过期时间
    
    # 查询用户额度上限
    limit = await get_user_quota_limit(user_id, quota_type)
    if limit == -1:  # 无限额度
        return True
    return count <= limit
```

## 6. 关键代码示例

### 6.1 验证码服务（Python/伪代码）

```python
import random
from datetime import datetime, timedelta

class SmsService:
    def __init__(self, redis_client, sms_client):
        self.redis = redis_client
        self.sms = sms_client

    async def send_code(self, phone: str, purpose: str) -> dict:
        # 1. 频率检查
        interval_key = f"sms:interval:{phone}"
        if await self.redis.exists(interval_key):
            raise BizError(10010, "发送过于频繁，请60秒后重试")
        
        # 2. IP频率检查
        ip_count_key = f"sms:ip:{self._get_client_ip()}"
        ip_count = await self.redis.incr(ip_count_key)
        if ip_count == 1:
            await self.redis.expire(ip_count_key, 3600)
        if ip_count > 10:
            raise BizError(10010, "操作过于频繁，请稍后再试")
        
        # 3. 生成验证码
        code = f"{random.randint(0, 999999):06d}"
        
        # 4. 存储验证码
        code_key = f"sms:code:{phone}:{purpose}"
        await self.redis.setex(code_key, 300, code)  # 5分钟有效
        
        # 5. 设置间隔锁
        await self.redis.setex(interval_key, 60, "1")
        
        # 6. 发送短信
        await self.sms.send(phone, f"您的验证码是{code}，5分钟内有效。")
        
        return {"expires_in": 300, "interval": 60}

    async def verify_code(self, phone: str, purpose: str, code: str) -> bool:
        code_key = f"sms:code:{phone}:{purpose}"
        stored = await self.redis.get(code_key)
        if not stored or stored != code:
            return False
        # 验证成功后删除，防止重复使用
        await self.redis.delete(code_key)
        return True
```

### 6.2 JWT 工具类

```python
import jwt
from datetime import datetime, timedelta, timezone

class TokenService:
    def __init__(self, secret: str, redis_client):
        self.secret = secret
        self.redis = redis_client

    def generate_tokens(self, user_id: int, user_type: str) -> dict:
        now = datetime.now(timezone.utc)
        
        # Access Token: 24小时
        access_jti = str(uuid.uuid4())
        access_payload = {
            "sub": str(user_id),
            "type": user_type,
            "jti": access_jti,
            "iat": now,
            "exp": now + timedelta(hours=24),
        }
        access_token = jwt.encode(access_payload, self.secret, algorithm="HS256")
        
        # Refresh Token: 30天
        refresh_jti = str(uuid.uuid4())
        refresh_payload = {
            "sub": str(user_id),
            "type": "refresh",
            "jti": refresh_jti,
            "iat": now,
            "exp": now + timedelta(days=30),
        }
        refresh_token = jwt.encode(refresh_payload, self.secret, algorithm="HS256")
        
        return {
            "access_token": access_token,
            "refresh_token": refresh_token,
            "token_type": "Bearer",
            "expires_in": 86400,
        }

    async def blacklist_token(self, jti: str, exp: int):
        """将token加入黑名单"""
        ttl = max(exp - int(datetime.now(timezone.utc).timestamp()), 0)
        if ttl > 0:
            await self.redis.setex(f"token_blacklist:{jti}", ttl, "1")

    async def is_blacklisted(self, jti: str) -> bool:
        return await self.redis.exists(f"token_blacklist:{jti}")
```

### 6.4 鉴权中间件

```python
from fastapi import Request, HTTPException
from starlette.middleware.base import BaseHTTPMiddleware

class AuthMiddleware(BaseHTTPMiddleware):
    # 不需要鉴权的路径
    WHITE_LIST = {
        "/api/v1/auth/sms/send",
        "/api/v1/auth/register/phone",
        "/api/v1/auth/login/phone",
        "/api/v1/auth/login/wechat",
        "/api/v1/auth/login/apple",
        "/api/v1/auth/token/refresh",
    }

    async def dispatch(self, request: Request, call_next):
        path = request.url.path
        
        # 白名单放行
        if path in self.WHITE_LIST:
            return await call_next(request)
        
        # 提取Token
        auth_header = request.headers.get("Authorization", "")
        if not auth_header.startswith("Bearer "):
            raise HTTPException(401, detail={"code": 10008, "message": "未登录"})
        
        token = auth_header[7:]
        try:
            payload = jwt.decode(token, SECRET, algorithms=["HS256"])
        except jwt.ExpiredSignatureError:
            raise HTTPException(401, detail={"code": 10007, "message": "登录已过期"})
        except jwt.InvalidTokenError:
            raise HTTPException(401, detail={"code": 10008, "message": "Token无效"})
        
        # 检查黑名单
        if await token_svc.is_blacklisted(payload["jti"]):
            raise HTTPException(401, detail={"code": 10008, "message": "Token已失效"})
        
        # 注入用户信息到请求上下文
        request.state.user_id = int(payload["sub"])
        request.state.user_type = payload.get("type", "student")
        
        return await call_next(request)
```

## 7. 错误处理

### 7.1 客户端处理策略

| 场景 | 错误码 | 客户端行为 |
|------|--------|-----------|
| Token 过期 | 10007 | 自动用 refresh_token 刷新，成功后重试原请求；刷新也失败则跳登录页 |
| Token 无效/被踢 | 10008 | 清除本地 token，跳转登录页 |
| 账号被禁用 | 10006 | 提示"账号已被限制，请联系客服" |
| 验证码错误 | 10002 | 提示用户重新输入，不自动重发 |
| 发送频率限制 | 10010 | 显示倒计时 |
| 网络异常 | - | 自动重试1次，失败后提示网络异常 |

### 7.2 Token 刷新机制（客户端）

```
请求返回 10007 (Token过期)
    ↓
检查本地是否有 refresh_token
    ↓ 有
POST /auth/token/refresh
    ↓ 成功
更新本地 token，重试原请求
    ↓ 失败（refresh_token 也过期）
清除本地 token，跳转登录页
```

**并发请求处理**: 多个请求同时遇到 token 过期时，只发一次 refresh 请求，其他请求排队等待结果。

## 8. 安全设计

### 8.1 密码与敏感数据

- 手机号存储时使用 AES-256 加密，展示时脱敏（`138****8000`）
- 验证码在 Redis 中存储，不持久化到数据库
- 第三方 token 加密后存储
- JWT secret 定期轮换（通过配置中心热更新）

### 8.2 防刷策略

| 接口 | 限制策略 |
|------|---------|
| 发送验证码 | 同手机号 60s/次，同 IP 10次/小时 |
| 注册 | 同 IP 5次/小时 |
| 登录失败 | 同账号连续失败 5 次后锁定 30 分钟 |
| Token 刷新 | 同 refresh_token 只能用一次 |

### 8.3 未成年人保护

- 注册时需确认用户年龄段（家长协助或学生自选）
- 14 岁以下用户需家长绑定后使用完整功能
- 所有接口响应经内容安全过滤
