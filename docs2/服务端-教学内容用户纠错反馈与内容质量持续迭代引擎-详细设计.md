# 服务端-教学内容用户纠错反馈与内容质量持续迭代引擎-详细设计

## 1. 模块概述

### 1.1 功能定位

本模块负责管理**已发布教学内容**的用户反馈全生命周期：从学生/教师/家长发现问题并提交纠错报告，到运营审核、内容修正、版本发布、用户回通知，再到基于反馈数据的内容质量评分与迭代优先级排序。

与现有模块的边界划分：

| 现有模块 | 职责 | 与本模块关系 |
|----------|------|-------------|
| 教育内容审核工作流与多级审核管线 | 内容**发布前**的多级审核 | 本模块处理**发布后**的问题反馈 |
| 教育内容质量自动评估与低质内容智能检测引擎 | 基于规则的**自动化**质量检测 | 本模块基于**用户真实反馈**驱动质量改进 |
| AI回答质量监控与用户纠错反馈 | 针对 **AI 实时生成**内容的纠错 | 本模块针对**已存储的结构化教学内容**（题目、解析、知识点讲解、微课等） |
| 题库质量监控与题目生命周期管理 | 题目层面的质量管理 | 本模块覆盖所有教学内容类型，并引入用户反馈闭环 |

### 1.2 核心价值

1. **质量闭环**：打通"用户发现 → 反馈 → 修正 → 通知"的完整闭环，提升用户信任
2. **数据驱动迭代**：基于反馈频次、严重度、影响面等数据自动排序内容优化优先级
3. **降本增效**：将用户从"被动消费者"转变为"质量共建者"，降低人工巡检成本
4. **合规保障**：满足教育内容出版物的纠错追溯合规要求

### 1.3 涉及的内容类型

| 类型编码 | 说明 | 典型问题 |
|----------|------|----------|
| `QUESTION` | 题库中的题目 | 题干错误、答案错误、解析错误、选项重复 |
| `EXPLANATION` | 知识点讲解/图文内容 | 知识点表述错误、公式错误、过时内容 |
| `VIDEO` | 微课/视频内容 | 音画不同步、字幕错误、内容与标题不符 |
| `EXERCISE` | 互动练习 | 交互逻辑错误、判定条件错误、素材缺失 |
| `EXAM_PAPER` | 试卷/模考卷 | 题目重复、分值错误、时间设置异常 |
| `KNOWLEDGE_MAP` | 知识图谱节点 | 关联关系错误、前置依赖标注错误 |

## 3. 核心业务流程

### 3.1 反馈状态机

```
                            ┌──────────────────────────────────┐
                            │                                  │
  ┌─────────┐    ┌─────────▼─────────┐    ┌──────────────┐   │
  │ PENDING │───►│  TRIAGING         │───►│ IN_PROGRESS  │   │
  │ (待处理) │    │  (分流中)          │    │ (修正中)     │   │
  └─────────┘    └───────┬───────────┘    └──────┬───────┘   │
       │                  │                       │           │
       │          ┌───────▼───────┐       ┌───────▼───────┐   │
       │          │ DUPLICATE     │       │ IN_REVIEW     │   │
       │          │ (重复-合并)    │       │ (审核中)      │   │
       │          └───────────────┘       └───────┬───────┘   │
       │                                          │           │
       │          ┌───────────────┐       ┌───────▼───────┐   │
       │          │ INVALID       │       │ RESOLVED      │   │
       │          │ (无效)        │       │ (已解决)      │   │
       │          └───────────────┘       └───────┬───────┘   │
       │                                          │           │
       │          ┌───────────────┐       ┌───────▼───────┘   │
       └─────────►│ WONT_FIX      │       │ NOTIFIED          │
                    │ (不修复)      │       │ (已通知用户)      │
                    └───────────────┘       └───────────────────┘
```

**状态流转规则：**

| 当前状态 | 允许的下一状态 | 触发条件 | 操作角色 |
|----------|---------------|----------|----------|
| `PENDING` | `TRIAGING` | 运营人员认领或系统自动分配 | OPERATOR / SYSTEM |
| `PENDING` | `INVALID` | 经核实为无效反馈（如误报） | OPERATOR |
| `PENDING` | `DUPLICATE` | 与已有反馈重复 | OPERATOR / SYSTEM(自动) |
| `TRIAGING` | `IN_PROGRESS` | 分配给教研/内容团队修正 | OPERATOR |
| `TRIAGING` | `WONT_FIX` | 经评估暂不修复（合理设计） | OPERATOR |
| `TRIAGING` | `INVALID` | 深入核实后判定无效 | OPERATOR |
| `IN_PROGRESS` | `IN_REVIEW` | 内容修正完成，提交审核 | CONTENT_EDITOR |
| `IN_REVIEW` | `RESOLVED` | 审核通过，修正内容上线 | REVIEWER |
| `IN_REVIEW` | `IN_PROGRESS` | 审核驳回，需重新修正 | REVIEWER |
| `RESOLVED` | `NOTIFIED` | 系统自动通知反馈人 | SYSTEM |
| `NOTIFIED` | (终态) | — | — |
| `RESOLVED` | `IN_PROGRESS` | 上线后发现问题需返工 | OPERATOR |

### 3.4 自动去重与聚类规则

当新反馈提交时，系统自动检查是否与已有反馈重复：

```python
def check_duplicate(new_feedback: ContentFeedback) -> Optional[int]:
    """
    检查新反馈是否与已有反馈重复。
    返回重复的目标 feedback_id，不重复返回 None。
    """
    # 规则1: 同一内容 + 同一分类 + 状态为 PENDING/TRIAGING
    exact_match = db.query(ContentFeedback).filter(
        ContentFeedback.content_type == new_feedback.content_type,
        ContentFeedback.content_id == new_feedback.content_id,
        ContentFeedback.category == new_feedback.category,
        ContentFeedback.status.in_(['PENDING', 'TRIAGING']),
    ).first()
    if exact_match:
        # 标题相似度 > 80% → 判定为重复
        if text_similarity(new_feedback.title, exact_match.title) > 0.8:
            return exact_match.id

    # 规则2: 同一锚点位置 + 同一内容 + 24小时内
    if new_feedback.anchor_section:
        anchor_match = db.query(ContentFeedback).filter(
            ContentFeedback.content_type == new_feedback.content_type,
            ContentFeedback.content_id == new_feedback.content_id,
            ContentFeedback.anchor_section == new_feedback.anchor_section,
            ContentFeedback.created_at > datetime.utcnow() - timedelta(hours=24),
            ContentFeedback.status.in_(['PENDING', 'TRIAGING', 'IN_PROGRESS']),
        ).first()
        if anchor_match:
            return anchor_match.id

    # 规则3: 语义相似度（对 description 做向量化检索）
    if new_feedback.description and len(new_feedback.description) > 20:
        similar = vector_search(
            text=new_feedback.description,
            filter={"content_id": new_feedback.content_id, "status": ["PENDING", "TRIAGING"]},
            top_k=3,
            threshold=0.92
        )
        if similar:
            return similar[0].id

    return None
```

```python
    "HIGH_TRAFFIC": {
        "top_10_percent": "boost_1",  # 访问量前10%的内容：提升1级
    },
}

SEVERITY_ORDER = ['LOW', 'MEDIUM', 'HIGH', 'CRITICAL']

def auto_escalate_severity(feedback: ContentFeedback) -> str:
    current_idx = SEVERITY_ORDER.index(feedback.severity)
    boost = 0

    # 确认人数
    confirm_count = count_confirms(feedback.id)
    for (lo, hi), action in SEVERITY_ESCALATION_RULES["CONFIRM_COUNT"].items():
        if lo <= confirm_count <= hi and action:
            boost = max(boost, int(action.split('_')[1]))

    # 考试临近（仅对考试相关内容）
    if is_exam_related(feedback.content_type, feedback.content_id):
        days_to_exam = get_days_to_nearest_exam(feedback.reporter_id)
        if days_to_exam and days_to_exam <= 3:
            boost = max(boost, 2)
        elif days_to_exam and days_to_exam <= 7:
            boost = max(boost, 1)

    # 高频内容
    traffic_rank = get_content_traffic_rank(feedback.content_type, feedback.content_id)
    if traffic_rank and traffic_rank <= 0.1:  # top 10%
        boost = max(boost, 1)

    new_idx = min(current_idx + boost, len(SEVERITY_ORDER) - 1)
    return SEVERITY_ORDER[new_idx]
```

## 5. 内容质量评分算法

### 5.1 综合质量评分模型

```python
def calculate_quality_score(content_type: str, content_id: int) -> QualityScore:
    """
    综合计算内容质量评分。
    数据来源：用户评分 + 反馈数据 + 使用数据。
    """
    # 1. 获取评分数据
    ratings = get_ratings(content_type, content_id)
    rating_scores = {
        'accuracy': avg([r.accuracy for r in ratings if r.accuracy]),
        'clarity': avg([r.clarity for r in ratings if r.clarity]),
        'difficulty': avg([r.difficulty for r in ratings if r.difficulty]),
    }

    # 2. 获取反馈数据
    feedbacks = get_feedbacks(content_type, content_id)
    feedback_stats = {
        'total': len(feedbacks),
        'critical': len([f for f in feedbacks if f.severity == 'CRITICAL']),
        'resolved': len([f for f in feedbacks if f.status == 'NOTIFIED']),
        'invalid': len([f for f in feedbacks if f.resolution == 'INVALID']),
    }

    # 3. 使用数据
    usage_stats = get_usage_stats(content_type, content_id)
    # usage_stats: {views, completions, avg_time_spent, bounce_rate}

    # 4. 计算各维度得分
    n_ratings = len(ratings)
    confidence_factor = min(n_ratings / 30.0, 1.0)  # 30个评分达到置信

    # 准确性得分 = 用户评分 - 反馈惩罚
    accuracy_base = rating_scores['accuracy'] or 5.0  # 无评分默认满分
    feedback_penalty = min(feedback_stats['critical'] * 0.5, 2.0)
    accuracy_final = max(0, accuracy_base - feedback_penalty)

    # 清晰度得分
    clarity_final = rating_scores['clarity'] or 4.0

    # 难度合理性（偏离值越低越合理）
    if rating_scores['difficulty']:
        # 计算难度评分与预期难度的偏差
        expected = get_expected_difficulty(content_type, content_id)
        actual = rating_scores['difficulty']
        difficulty_deviation = abs(actual - expected)
        clarity_final -= difficulty_deviation * 0.3

    # 5. 综合得分
    weights = CONTENT_TYPE_WEIGHTS.get(content_type, DEFAULT_WEIGHTS)
    overall = (
        accuracy_final * weights['accuracy'] +
        clarity_final * weights['clarity'] +
        (5.0 - feedback_stats['critical'] * 0.3) * weights['stability']
    ) * confidence_factor + (1 - confidence_factor) * 4.0  # 无数据时倾向中性

    overall = max(0, min(5, overall))

    # 6. 质量 grade
    grade = score_to_grade(overall, feedback_stats['critical'])

    return QualityScore(
        accuracy_score=accuracy_final,
        clarity_score=clarity_final,
        difficulty_score=rating_scores['difficulty'],
        overall_score=overall,
        quality_grade=grade,
        total_ratings=n_ratings,
        total_feedback=feedback_stats['total'],
        critical_feedback=feedback_stats['critical'],
        resolved_feedback=feedback_stats['resolved'],
    )

CONTENT_TYPE_WEIGHTS = {
    'QUESTION':     {'accuracy': 0.6, 'clarity': 0.2, 'stability': 0.2},
    'EXPLANATION':  {'accuracy': 0.5, 'clarity': 0.35, 'stability': 0.15},
    'VIDEO':        {'accuracy': 0.3, 'clarity': 0.5, 'stability': 0.2},
    'EXERCISE':     {'accuracy': 0.5, 'clarity': 0.3, 'stability': 0.2},
    'EXAM_PAPER':   {'accuracy': 0.7, 'clarity': 0.1, 'stability': 0.2},
}

def score_to_grade(score: float, critical_count: int) -> str:
    if critical_count >= 3 and score < 3.5:
        return 'D'
    if score >= 4.5:
        return 'S'
    if score >= 4.0:
        return 'A'
    if score >= 3.0:
        return 'B'
    if score >= 2.0:
        return 'C'
    return 'D'
```

### 5.2 内容优化优先级排序

```python
def calculate_priority_score(content_type: str, content_id: int) -> float:
    """
    计算内容优化的优先级分数（0-100）。
    分数越高，越应优先处理。
    """
    score = get_quality_score(content_type, content_id)
    feedbacks = get_active_feedbacks(content_type, content_id)  # 未关闭的反馈
    usage = get_usage_stats(content_type, content_id)

    # 维度1: 反馈严重度加权（40%）
    severity_weight = sum(
        {'CRITICAL': 10, 'HIGH': 5, 'MEDIUM': 2, 'LOW': 1}[f.severity]
        for f in feedbacks
    )
    severity_score = min(severity_weight / 50.0, 1.0) * 40

    # 维度2: 影响面（30%）— 基于访问量
    impact_score = min(usage['views'] / 1000.0, 1.0) * 30

    # 维度3: 质量分数倒数（20%）— 分数越低优先级越高
    quality_inverse = (1 - score.overall_score / 5.0) * 20

    # 维度4: 时效性（10%）— 反馈积压天数
    oldest_feedback_age = max(
        (datetime.utcnow() - f.created_at).days for f in feedbacks
    ) if feedbacks else 0
    recency_score = min(oldest_feedback_age / 14.0, 1.0) * 10

    # 考试临近加权
    if is_exam_related_content(content_type, content_id):
        exam_boost = 1.2
    else:
        exam_boost = 1.0

    return round(
        (severity_score + impact_score + quality_inverse + recency_score) * exam_boost,
        2
    )
```

```python
class FeedbackService:

    # 提交频率限制：同一用户对同一内容，5分钟内仅允许1条
    SUBMIT_COOLDOWN_SECONDS = 300
    # 每日提交上限
    DAILY_LIMIT = 30

    def __init__(self, db: Session, notification_svc: NotificationService):
        self.db = db
        self.notification = notification_svc

    def submit_feedback(
        self,
        user_id: int,
        user_role: str,
        user_grade: Optional[int],
        req: FeedbackCreateRequest,
    ) -> ContentFeedback:
        """提交内容反馈"""

        # 1. 频率限制
        self._check_rate_limit(user_id, req.content_type, req.content_id)

        # 2. 每日限额
        self._check_daily_limit(user_id)

        # 3. 获取内容快照（用于后续修正时的上下文对比）
        content_snapshot = self._get_content_snapshot(

        )
        if not content_snapshot:
            raise BusinessError(404, "REFERENCED_CONTENT_NOT_FOUND",
                                "引用的内容不存在")

        # 4. 自动查重
        duplicate_of = self._check_duplicate(
            req.content_type, req.content_id,
            req.category, req.title, req.description,
            req.anchor_section,
        )

        # 5. 获取内容当前版本
        content_version = self._get_content_version(
            req.content_type, req.content_id
        )

        # 6. 入库
        feedback = ContentFeedback(
            feedback_no=generate_feedback_no(),
            content_type=req.content_type,
            content_id=req.content_id,
            content_snapshot=content_snapshot,
            content_version=content_version,
            reporter_id=user_id,
            reporter_role=user_role,
            reporter_grade=user_grade,
            category=req.category,
            severity=req.severity,
            title=req.title,
            description=req.description,
            anchor_section=req.anchor_section,
            anchor_offset=req.anchor_offset,
            attachments=req.attachments,
            status="DUPLICATE" if duplicate_of else "PENDING",
            duplicate_of=duplicate_of,
        )
        self.db.add(feedback)
        self.db.flush()  # 获取 id

        # 7. 如果重复，给原反馈添加确认，不单独建单
        if duplicate_of:
            original = self.db.query(ContentFeedback).get(duplicate_of)
            self._add_confirm_vote(
                feedback_id=duplicate_of,
                user_id=user_id,
                comment=f"自动合并：{req.title}",
            )
            self.db.delete(feedback)  # 删除重复项
            self.db.commit()
            return original

        # 8. 触发自动处理
        self._trigger_auto_triage(feedback)

        self.db.commit()

        # 9. 通知内容负责人
        self._notify_content_owner(feedback)

        return feedback

    def _check_rate_limit(
        self, user_id: int, content_type: str, content_id: int

            ContentFeedback.reporter_id == user_id,
            ContentFeedback.content_type == content_type,
            ContentFeedback.content_id == content_id,

                seconds=self.SUBMIT_COOLDOWN_SECONDS

                429, "FEEDBACK_RATE_LIMIT",

            )

    def _check_daily_limit(self, user_id: int):
        """每日提交限额"""
        today_count = self.db.query(ContentFeedback).filter(
            ContentFeedback.reporter_id == user_id,
            ContentFeedback.created_at >= datetime.now(timezone.utc).replace(
                hour=0, minute=0, second=0, microsecond=0
            ),
        ).count()
        if today_count >= self.DAILY_LIMIT:
            raise BusinessError(
                429, "FEEDBACK_DAILY_LIMIT",
                f"每日最多提交{self.DAILY_LIMIT}条反馈"
            )

    def _check_duplicate(
        self, content_type, content_id, category, title,
        description, anchor_section
    ) -> Optional[int]:
        """自动查重，返回重复目标ID或None"""
        # 规则1: 同内容 + 同分类 + 活跃状态
        candidates = self.db.query(ContentFeedback).filter(
            ContentFeedback.content_type == content_type,
            ContentFeedback.content_id == content_id,
            ContentFeedback.category == category,
            ContentFeedback.status.in_(
                ["PENDING", "TRIAGING", "IN_PROGRESS"]
            ),
        ).all()

        for c in candidates:
            if text_similarity(title, c.title) > 0.8:
                return c.id

        # 规则2: 同锚点
        if anchor_section:
            for c in candidates:
                if c.anchor_section == anchor_section:
                    return c.id

        return None

    def _get_content_snapshot(
        self, content_type: str, content_id: int
    ) -> dict:
        """获取内容快照"""
        snapshot_service = ContentSnapshotService(self.db)
        return snapshot_service.capture(content_type, content_id)

    def _trigger_auto_triage(self, feedback: ContentFeedback):
        """新反馈自动预处理"""
        # 1. 统计同内容的历史反馈
        history_count = self.db.query(ContentFeedback).filter(
            ContentFeedback.content_type == feedback.content_type,
            ContentFeedback.content_id == feedback.content_id,
            ContentFeedback.id != feedback.id,
        ).count()

        # 2. 如果该内容已有3+条反馈 → 自动升级为 TRIAGING 并通知
        if history_count >= 3:
            feedback.status = "TRIAGING"
            feedback.assigned_team = self._route_to_team(feedback.content_type)

        # 3. CRITICAL 级别 → 自动标记 TRIAGING
        if feedback.severity == "CRITICAL":
            feedback.status = "TRIAGING"
            feedback.assigned_team = self._route_to_team(feedback.content_type)

    def _route_to_team(self, content_type: str) -> str:
        """根据内容类型路由到处理团队"""
        routing = {
            "QUESTION": "QUESTION_BANK_TEAM",
            "EXPLANATION": "CONTENT_EDITOR_TEAM",
            "VIDEO": "MEDIA_TEAM",
            "EXERCISE": "INTERACTIVE_TEAM",
            "EXAM_PAPER": "EXAM_TEAM",
            "KNOWLEDGE_MAP": "KNOWLEDGE_TEAM",
        }
        return routing.get(content_type, "CONTENT_EDITOR_TEAM")

    def _notify_content_owner(self, feedback: ContentFeedback):
        """通知内容负责人"""
        self.notification.send(
            template="NEW_CONTENT_FEEDBACK",
            recipients=self._get_content_owners(feedback.content_type,
                                                feedback.content_id),
            data={
                "feedback_no": feedback.feedback_no,
                "title": feedback.title,
                "severity": feedback.severity,
                "content_type": feedback.content_type,
                "content_id": feedback.content_id,
            },
            priority="HIGH" if feedback.severity in ("CRITICAL", "HIGH") else "NORMAL",
        )
```

```python
class FeedbackResolutionService:

    def __init__(self, db: Session, notification_svc: NotificationService):
        self.db = db
        self.notification = notification_svc

    def resolve_feedback(
        self,
        feedback_id: int,
        operator_id: int,
        resolution: str,
        resolution_note: str,
        fix_log_id: Optional[int] = None,
    ) -> ContentFeedback:
        """解决反馈并触发后续流程"""

        feedback = self.db.query(ContentFeedback).get(feedback_id)
        if not feedback:
            raise BusinessError(404, "FEEDBACK_NOT_FOUND", "反馈不存在")

        if feedback.status not in ("IN_REVIEW", "IN_PROGRESS"):
            raise BusinessError(
                400, "INVALID_STATUS_TRANSITION",
                f"当前状态 {feedback.status} 不允许标记为已解决"
            )

        # 1. 更新反馈状态
        feedback.status = "RESOLVED"
        feedback.resolution = resolution
        feedback.resolution_note = resolution_note
        feedback.resolved_at = datetime.now(timezone.utc)

        # 2. 如果有修正记录，关联版本号
        if fix_log_id:
            fix_log = self.db.query(ContentFixLog).get(fix_log_id)
            feedback.fixed_version = fix_log.to_version

        # 3. 更新内容质量评分
        self._update_quality_score(feedback)

        # 4. 触发用户通知（异步）
        self._schedule_user_notifications(feedback)

        self.db.commit()
        return feedback

    def _update_quality_score(self, feedback: ContentFeedback):
        """反馈解决后更新内容质量评分"""
        score = self.db.query(ContentQualityScore).filter(
            ContentQualityScore.content_type == feedback.content_type,
            ContentQualityScore.content_id == feedback.content_id,
        ).first()

        if not score:
            score = ContentQualityScore(
                content_type=feedback.content_type,
                content_id=feedback.content_id,
            )
            self.db.add(score)

        score.total_feedback += 1
        if feedback.severity == "CRITICAL":
            score.critical_feedback += 1
        score.resolved_feedback += 1

        # 重新计算评分
        scoring_engine = QualityScoringEngine(self.db)
        new_score = scoring_engine.recalculate(
            feedback.content_type, feedback.content_id
        )
        score.accuracy_score = new_score.accuracy_score
        score.clarity_score = new_score.clarity_score
        score.overall_score = new_score.overall_score
        score.quality_grade = new_score.quality_grade
        score.last_scored_at = datetime.now(timezone.utc)
        score.updated_at = datetime.now(timezone.utc)

    def _schedule_user_notifications(self, feedback: ContentFeedback):
        """异步通知反馈人和确认用户"""
        # 获取所有需要通知的用户：反馈人 + 确认用户
        user_ids = {feedback.reporter_id}

        confirms = self.db.query(ContentFeedbackVote).filter(
            ContentFeedbackVote.feedback_id == feedback.id,
            ContentFeedbackVote.vote_type == "CONFIRM",
        ).all()
        user_ids.update(c.user_id for c in confirms)

        # 异步推送通知
        notification_data = {
            "feedback_no": feedback.feedback_no,
            "title": feedback.title,
            "resolution": feedback.resolution,
            "resolution_note": feedback.resolution_note,
            "content_type": feedback.content_type,
            "content_id": feedback.content_id,
        }

        self.notification.send_batch(
            template="FEEDBACK_RESOLVED",
            recipients=list(user_ids),
            data=notification_data,
            channel="APP_PUSH",  # App推送
            priority="NORMAL",
        )

        # 更新状态为 NOTIFIED（延迟几秒，确保通知发出）
        feedback.status = "NOTIFIED"
```

```python
from apscheduler.triggers.cron import CronTrigger

scheduler = AsyncIOScheduler()


@scheduler.scheduled_job(
    CronTrigger(hour=2, minute=0)  # 每天凌晨2点执行

async def daily_quality_score_refresh():
    """
    每日质量评分刷新任务。
    1. 扫描过去24小时有新反馈/评分的内容
    2. 重新计算质量评分
    3. 对质量降级的内容发出预警
    """
    db = get_db_session()
    try:
        # 1. 找出需要重算的内容
        affected_contents = db.execute("""
            SELECT DISTINCT content_type, content_id
            FROM (
                SELECT content_type, content_id
                FROM content_feedback
                WHERE updated_at > NOW() - INTERVAL '24 hours'

                UNION

                SELECT content_type, content_id
                FROM content_rating
                WHERE created_at > NOW() - INTERVAL '24 hours'
            ) t
        """).fetchall()

        scoring_engine = QualityScoringEngine(db)
        degraded_contents = []

        for row in affected_contents:
            content_type, content_id = row

            # 获取旧评分
            old = db.query(ContentQualityScore).filter_by(
                content_type=content_type, content_id=content_id
            ).first()

            # 重算
            new_score = scoring_engine.recalculate(content_type, content_id)

            # 检测降级
            if old and old.quality_grade != new_score.quality_grade:
                grade_order = ['S', 'A', 'B', 'C', 'D']
                old_idx = grade_order.index(old.quality_grade)
                new_idx = grade_order.index(new_score.quality_grade)
                if new_idx > old_idx:  # 降级了
                    degraded_contents.append({
                        "content_type": content_type,
                        "content_id": content_id,
                        "old_grade": old.quality_grade,
                        "new_grade": new_score.quality_grade,
                        "score": new_score.overall_score,
                    })

            # 持久化
            db.merge(new_score)

        db.commit()

        # 2. 对降级到C/D的内容发出预警
        critical_degradation = [
            c for c in degraded_contents if c["new_grade"] in ("C", "D")
        ]
        if critical_degradation:
            await send_quality_alert(critical_degradation)

        logger.info(
            "daily_quality_score_refresh done: %d contents re-scored, "
            "%d degraded, %d critical",
            len(affected_contents),
            len(degraded_contents),
            len(critical_degradation),
        )

    finally:
        db.close()
```

## 9. 错误处理与边界条件

### 9.1 错误码体系

| 错误码 | HTTP | 说明 | 处理建议 |
|--------|------|------|----------|
| `FEEDBACK_NOT_FOUND` | 404 | 反馈不存在 | 检查 feedbackId |
| `FEEDBACK_RATE_LIMIT` | 429 | 提交频率超限 | 等待冷却期 |
| `FEEDBACK_DAILY_LIMIT` | 429 | 每日提交超限 | 次日重试 |
| `INVALID_STATUS_TRANSITION` | 400 | 状态流转不合法 | 检查当前状态 |
| `REFERENCED_CONTENT_NOT_FOUND` | 404 | 引用的内容不存在 | 检查 content_id |
| `PERMISSION_DENIED` | 403 | 无权操作 | 检查角色权限 |
| `FEEDBACK_ALREADY_VOTED` | 409 | 已投过票 | 前端忽略 |
| `FEEDBACK_LOCKED` | 409 | 反馈已关闭，不可操作 | 检查状态 |
| `CONTENT_SNAPSHOT_FAILED` | 500 | 内容快照失败 | 重试或人工介入 |
| `QUALITY_CALC_FAILED` | 500 | 评分计算异常 | 降级返回缓存值 |

### 9.2 边界条件处理

| 场景 | 处理策略 |
|------|----------|
| 内容被删除但仍有活跃反馈 | 反馈自动标记为 `WONT_FIX`，备注"内容已下线"，通知反馈人 |
| 同一反馈被大量用户确认（>50） | 触发 P0 告警，立即通知内容总监 |
| 修正后的内容引发新反馈 | 关联原始 fix_log，标记为"回归问题"，严重度自动+1级 |
| 内容版本回滚 | 自动关闭该版本后的所有 fix_log 关联的反馈，通知相关用户 |
| 用户注销账号 | 反馈保留（reporter_id 置为 NULL，显示为"已注销用户"） |
| 离线提交反馈 | 客户端本地缓存，网络恢复后批量提交，服务端去重 |
| 审核人离职 | 自动转派给同团队其他成员，通知管理员 |
| 大批量内容质量降级（>10%） | 触发系统级告警，可能存在内容标准变更问题 |

### 9.3 幂等性保障

```python
# 反馈操作幂等键
# 格式: feedback:{feedback_id}:{operation}:{version}
# 同一操作重复执行时，通过 Redis 幂等键防止重复处理

IDEMPOTENCY_KEY_TTL = 300  # 5分钟

async def resolve_feedback_idempotent(
    feedback_id: int, operator_id: int, resolution: str
):
    key = f"feedback:{feedback_id}:resolve:{operator_id}"
    acquired = await redis.set(key, "1", nx=True, ex=IDEMPOTENCY_KEY_TTL)
    if not acquired:
        raise BusinessError(409, "DUPLICATE_OPERATION", "请勿重复操作")
    try:
        return await resolve_feedback(feedback_id, operator_id, resolution)
    except Exception:
        await redis.delete(key)  # 失败时释放锁
        raise
```
