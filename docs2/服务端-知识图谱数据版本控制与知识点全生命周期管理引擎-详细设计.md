# 知识图谱数据版本控制与知识点全生命周期管理引擎 详细设计

## 1. 概述

### 1.1 模块定位

知识图谱是 PrimeTop 教育平台的底层数据骨架——题目标注、教材章节映射、学习路径规划、学情诊断、AI 辅导上下文注入等核心业务全部依赖知识点体系的正确性与稳定性。本引擎负责管理知识点的**实体生命周期状态**与知识图谱的**数据版本控制**，确保知识图谱在任何时点都处于一致、可追溯、可回滚的状态。

### 1.2 核心职责

| 职责 | 说明 |
| --- | --- |
| 知识点生命周期状态机 | 管理 KnowledgePoint 实体从草稿到归档的完整状态流转 |
| 图谱快照版本管理 | 对知识图谱进行定期/触发式快照，支持任意历史版本回溯查询 |
| 变更审计与影响分析 | 记录每一次知识点/边的变更，自动计算变更对下游资源的影响范围 |
| 向后兼容与引用迁移 | 知识点废弃/合并/拆分时，自动处理题目、课程、学生数据中的旧引用 |
| 时序查询支持 | 支持按时间点/版本号查询图谱拓扑，满足历史数据分析与合规审计需求 |

### 1.3 依赖关系

```
                    ┌──────────────────────────┐
                    │   本引擎 (KG Versioning)  │
                    └──────────┬───────────────┘
         ┌─────────────┬──────┴───────┬──────────────┐
         ▼             ▼              ▼              ▼
  ┌──────────────┐ ┌──────────┐ ┌──────────┐ ┌───────────────┐
  │ 知识点体系    │ │ 题目服务 │ │ 内容服务 │ │ 学情分析服务  │
  │ 与教材映射    │ │          │ │           │               │
  └──────────────┘ └──────────┘ └──────────┘ └───────────────┘
         │                                             │
         ▼                                             ▼
  ┌──────────────┐                          ┌───────────────────┐
  │ 图数据库      │                          │ 学生掌握度数据     │
  │ (Neo4j/Janus)│                          │ (MySQL/ClickHouse) │
  └──────────────┘                          └───────────────────┘
```

**上游依赖：**
- 知识点体系与教材映射引擎：提供知识点基础数据
- 管理后台：提供人工操作入口（创建、审核、发布、废弃知识点）

**下游影响：**
- 题目服务：题目关联的知识点 ID 变更需要同步
- 内容服务：教材章节关联的知识点变更需要同步
- 学情分析服务：学生掌握度数据中的知识点引用需要迁移
- AI 辅导服务：RAG 检索使用的知识点图谱需要保持一致
- 学习路径推荐：路径规划依赖的图谱拓扑需要匹配当前版本

### 1.4 设计原则

1. **不可变历史**：已发布的图谱版本不可被修改，只能产生新版本
2. **兼容优先**：知识点废弃时必须提供替代项或迁移路径
3. **影响可控**：任何变更必须经过影响分析，高风险变更需人工审批
4. **最终一致**：下游服务通过事件通知 + 异步迁移达到最终一致

### 2.1 核心实体定义

#### 2.1.1 KnowledgePoint（知识点实体）

```typescript
interface KnowledgePoint {
  // === 基础信息 ===
  id: string;                    // 全局唯一 ID，格式：kp_{ulid}
  code: string;                  // 知识点编码，如 "MATH.6.RF.01" (数学6年级分数01)
  name: string;                  // 知识点名称，如 "分数的基本性质"
  aliases: string[];             // 别名列表，如 ["等值分数", "分数相等"]
  description: string;           // 详细描述
  subject: SubjectCode;          // 学科：CHINESE|MATH|ENGLISH|PHYSICS|...
  stage: StageCode;              // 学段：KINDERGARTEN|PRIMARY|JUNIOR|SENIOR
  gradeBand: GradeBand[];        // 适用年级段：["G5","G6"]

  // === 分类与标签 ===
  category: KnowledgeCategory;   // 类别：CONCEPT|SKILL|METHOD|APPLICATION
  cognitiveLevel: CognitiveLevel;// 认知层级：REMEMBER|UNDERSTAND|APPLY|ANALYZE|EVALUATE|CREATE
  difficulty: number;            // 基础难度系数 1-5
  tags: string[];                // 业务标签：["中考高频","易错点"]

  // === 关键词与检索 ===
  keywords: string[];            // 检索关键词，用于RAG匹配
  examples: string[];            // 典型例子描述

  // === 生命周期 ===
  status: KnowledgePointStatus;  // 状态：DRAFT|IN_REVIEW|PUBLISHED|DEPRECATED|ARCHIVED
  supersedesId?: string;         // 替代的旧知识点ID（新知识点指向被废弃的旧知识点）
  supersededById?: string;       // 被哪个新知识点替代（旧知识点指向新知识点）
  mergeTargetId?: string;        // 合并到的目标知识点ID
  splitFromId?: string;          // 从哪个知识点拆分而来

  // === 版本控制 ===
  currentVersion: number;        // 当前数据版本号，从1开始递增
  graphVersionId: string;        // 所属图谱版本ID

  // === 元数据 ===
  createdAt: string;             // 创建时间 ISO 8601
  updatedAt: string;             // 最后修改时间
  publishedAt?: string;          // 发布时间
  deprecatedAt?: string;         // 废弃时间
  archivedAt?: string;           // 归档时间

  // === 审计 ===
  createdBy: string;             // 创建人（管理后台用户ID）
  updatedBy: string;             // 最后修改人
  reviewedBy?: string;           // 审核人
}
```

#### 2.1.2 知识点状态枚举

```typescript
/**
 * 知识点生命周期状态
 *
 * 状态流转图：
 *
 *  ┌──────┐  提交审核   ┌───────────┐  审核通过  ┌───────────┐  废弃操作  ┌────────────┐  定期清理 ┌──────────┐
 *  │ DRAFT │ ─────────► │ IN_REVIEW  │ ────────► │ PUBLISHED │ ────────► │ DEPRECATED │ ────────► │ ARCHIVED │
 *  └──────┘            └───────────┘           └───────────┘           └────────────┘          └──────────┘
 *      │                     │                      │ ▲                     │
 *      │     审核驳回         │                      │ │    发布新版本        │ 回退（仅在
 *      │     (退回修改)       │                      │ │    (版本号+1)        │ 窗口期内）
 *      ▼                     ▼                      │ │                     ▼
 *  ┌──────┐            ┌───────────┐                │ │              ┌────────────┐
 *  │ DRAFT │            │ IN_REVIEW │◄───────────────┘ │              │ superseded │
 *  └──────┘            └─┬─────────┘  驳回后修改重新提交│              │   状态      │
 *                          │                        │              └────────────┘
 *                      审核拒绝                       │
 *                          │               ┌──────────┴─────┐
 *                          ▼               │  并行版本：     │
 *                    ┌──────────┐          │  PUBLISHED_V2  │ 替代旧版本
 *                    │ REJECTED │          │  与 PUBLISHED  │
 *                    └──────────┘          │  并存过渡期     │
 *                                          └────────────────┘
 */
type KnowledgePointStatus =
  | 'DRAFT'        // 草稿：刚创建，仅创建人可见，可自由编辑
  | 'IN_REVIEW'    // 审核中：已提交审核，等待教研团队审批
  | 'PUBLISHED'    // 已发布：对所有服务可见，参与图谱查询
  | 'DEPRECATED'   // 已废弃：不再推荐使用，但保留引用兼容
  | 'ARCHIVED'     // 已归档：只读历史记录，不再参与任何业务查询
  | 'REJECTED';    // 已拒绝：审核未通过，退回创建人修改
```

#### 2.1.3 KnowledgeEdge（知识点关系边）

```typescript
interface KnowledgeEdge {
  id: string;                      // 边ID：ke_{ulid}
  sourceKpId: string;              // 源知识点ID
  targetKpId: string;              // 目标知识点ID
  edgeType: KnowledgeEdgeType;     // 关系类型
  weight: number;                  // 关系强度 0.0-1.0
  metadata: Record<string, any>;   // 扩展元数据
  status: EdgeStatus;              // ACTIVE|INACTIVE
  graphVersionId: string;          // 所属图谱版本
  createdAt: string;
  updatedAt: string;
}

/**
 * 知识点关系类型
 */
type KnowledgeEdgeType =
  | 'PREREQUISITE'         // 前置知识：学习target前需先掌握source
  | 'RELATED_TO'           // 相关联：两个知识点有交叉内容
  | 'PART_OF'             // 包含关系：source是target的子知识点
  | 'DERIVED_FROM'         // 衍生关系：source从target发展而来
  | 'SIMILAR_TO'           // 相似知识点：易混淆概念
  | 'LEADS_TO'             // 进阶关系：掌握source后可学习target
  | 'CROSS_SUBJECT'        // 跨学科关联
  | 'SAME_AS';             // 同义知识点（合并时使用）
```

#### 2.1.4 GraphVersion（图谱快照版本）

```typescript
interface GraphVersion {
  id: string;                      // 版本ID：gv_{ulid}
  versionNumber: number;           // 语义化版本号，如 2026.06.1
  subject: SubjectCode | 'ALL';    // 学科范围
  snapshotType: SnapshotType;      // SCHEDULED|EVENT_TRIGGERED|MANUAL
  description: string;             // 版本说明
  status: GraphVersionStatus;      // DRAFT|FROZEN|ACTIVE|SUPERSEDED

  // === 快照统计 ===
  knowledgePointCount: number;     // 知识点总数
  edgeCount: number;               // 关系边总数
  changeSummary: ChangeSummary;    // 相对上一版本的变更摘要

  // === 关联 ===
  previousVersionId?: string;      // 上一版本ID
  nextVersionId?: string;          // 下一版本ID

  // === 时间 ===
  frozenAt?: string;               // 冻结时间
  activatedAt?: string;            // 生效时间
  supersededAt?: string;           // 被替代时间

  createdBy: string;
  createdAt: string;
}

interface ChangeSummary {
  addedKpCount: number;            // 新增知识点数
  modifiedKpCount: number;         // 修改知识点数
  deletedKpCount: number;          // 删除知识点数
  addedEdgeCount: number;          // 新增边数
  removedEdgeCount: number;        // 移除边数
  affectedSubjects: SubjectCode[]; // 受影响学科
  affectedDownstream: number;      // 受影响下游资源数（题目、课程等）
  riskLevel: RiskLevel;            // 风险等级
}

type RiskLevel = 'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL';
```

#### 2.1.5 ChangeRecord（变更记录）

```typescript
interface ChangeRecord {
  id: string;                      // cr_{ulid}
  graphVersionId: string;          // 所属图谱版本
  entityType: 'KNOWLEDGE_POINT' | 'KNOWLEDGE_EDGE';
  entityId: string;                // 知识点或边的ID
  changeType: ChangeType;          // CREATE|UPDATE|DELETE|MERGE|SPLIT|DEPRECATE
  beforeSnapshot?: string;         // 变更前数据快照 (JSON)
  afterSnapshot?: string;          // 变更后数据快照 (JSON)
  diff: DiffEntry[];               // 字段级差异
  impactAnalysis: ImpactAnalysis;  // 影响分析结果
  approvedBy?: string;             // 审批人（高风险变更需要）
  appliedAt: string;               // 变更应用时间
  appliedBy: string;               // 变更操作人
  reason: string;                  // 变更原因
}

interface DiffEntry {
  field: string;                   // 变更字段
  oldValue?: any;                  // 旧值
  newValue?: any;                  // 新值
  changeType: 'SET' | 'UPDATE' | 'UNSET' | 'ARRAY_ADD' | 'ARRAY_REMOVE';
}

  // 影响范围
  affectedQuestions: number;       // 受影响题目数

  affectedLearningPaths: number;   // 受影响学习路径数
  affectedAiPrompts: number;       // 受影响AI Prompt模板数

  // 风险评估
  riskLevel: RiskLevel;
  riskReasons: string[];           // 风险原因说明
  requiresApproval: boolean;       // 是否需要人工审批
  estimatedMigrationTime?: number; // 预估迁移耗时（秒）
}

FOR (n:KnowledgePoint) REQUIRE n.id IS UNIQUE;

FOR (n:KnowledgePoint) REQUIRE n.code IS UNIQUE;

// 知识点节点属性
// (:KnowledgePoint {
//   id, code, name, subject, stage, gradeBand,
//   category, cognitiveLevel, difficulty, tags,
//   status, currentVersion, graphVersionId
// })

// 关系类型（全部携带 graphVersionId = 该边自哪个图谱版本起生效）
// [:PREREQUISITE  {weight, graphVersionId}]                  前置知识：学习 target 前需先掌握 source
// [:RELATED_TO    {weight, graphVersionId}]                  相关联：内容交叉
// [:PART_OF       {weight, graphVersionId, textbookScope}]   包含：source 是 target 的子知识点；
//                                                            textbookScope 为空表示全版本通用，
//                                                            非空（如 ["人教版"]）表示仅特定教材版本编排
// [:DERIVED_FROM  {weight, graphVersionId}]                  衍生：source 从 target 发展而来
// [:SIMILAR_TO    {weight, graphVersionId}]                  易混淆概念
// [:LEADS_TO      {weight, graphVersionId}]                  进阶：掌握 source 后建议学习 target
// [:CROSS_SUBJECT {weight, graphVersionId}]                  跨学科关联
// [:SAME_AS       {mergedAt, graphVersionId}]                同义合并迁移期专用（见 §3.5）

// 节点属性补充：currentVersion = 实体数据版本（对应 kp_version_history.version_number），
// graphVersionId = 该节点首次进入图谱的版本，二者含义不同，禁止混用。

// 辅助索引
CREATE INDEX kp_subject_stage_idx IF NOT EXISTS
FOR (n:KnowledgePoint) ON (n.subject, n.stage);

CREATE INDEX kp_status_idx IF NOT EXISTS
FOR (n:KnowledgePoint) ON (n.status);

CREATE INDEX kp_graph_version_idx IF NOT EXISTS
FOR (n:KnowledgePoint) ON (n.graphVersionId);

CREATE INDEX kp_name_text_idx IF NOT EXISTS
FOR (n:KnowledgePoint) ON (n.name);   -- 供管理后台图内按名定位（全文检索仍走 ES）

// ============================================================
// 时序建模原则（重要设计决策）
// ============================================================
// Neo4j 只保存"当前活跃图谱"（ACTIVE 版本的投影），不做"每版本复制全图"：
// 全学段约 8 万节点 / 40 万边，若每周一版、每版全量复制，一年后图库膨胀 50 倍，
// 且跨版本遍历查询语义混乱。历史版本的可回溯性由三层机制保证：
//   1. 每个版本 FROZEN 时导出全量清单（节点/边 JSONL）到 OSS —— 历史权威副本；
//   2. 相邻版本差异直接查 MySQL kp_change_record（无需读 OSS）；
//   3. 任意历史版本拓扑查询 = 拉取 OSS 清单内存建图（见 §3.8，深度与节点数受限）。
// SAME_AS 边是唯一允许"过期存在"的关系：合并迁移期保留，迁移完成后随归档清理。

// ============================================================
// MySQL → Neo4j 投影映射规则（投影 Worker 消费，见 §3.7）
// ============================================================
// kp_knowledge_point 同名字段      → (:KnowledgePoint) 同名属性
// kp_knowledge_point.aliases       → 不投影（仅供 MySQL/ES 检索）
// kp_knowledge_point.description   → 不投影（正文走内容服务，图查询只关心结构）
// kp_edge.edge_type                → 关系类型（枚举直映射）
// kp_edge.weight / metadata        → 关系属性（metadata 仅投影白名单键：textbookScope）
// kp_edge.status = INACTIVE        → 投影为 DELETE 关系（物理删除边）
```

## 3. 核心流程设计

### 3.1 知识点生命周期状态机守卫表

§2.1.2 的状态图落地为以下守卫规则。所有状态迁移必须经 `LifecycleStateMachine.transit()` 统一入口，非法迁移直接拒绝（错误码 54103，响应携带守卫编号）。

| --- | --- | --- | --- | --- | --- |

| G2 | IN_REVIEW→PUBLISHED | 学科负责人 | 审核人 ≠ 提交人（四眼原则）；影响分析已挂接；高风险需 kp_change_approval=APPROVED | 写 kp_version_history、kp_change_record(PUBLISH)、published_at、首次发布时分配 graphVersionId | KnowledgePointPublished |
| G3 | IN_REVIEW→REJECTED | 学科负责人 | 必须填写 review_comment | — | — |
| G4 | IN_REVIEW→DRAFT | 提交人本人 | 仅提交人可撤回 | — | — |
| G5 | REJECTED→DRAFT | 提交人本人 | 编辑保存即自动回 DRAFT（修改后重走 G1） | — | — |
| G6 | PUBLISHED→DEPRECATED | 平台管理员 | 必须指定 successor（SUPERSEDE 新 KP 或 MERGE 目标），除非 impactAnalysis.affectedTotal=0 且填写理由；HIGH/CRITICAL 需审批 | 写 deprecated_at、supersedes/supersededBy 链、kp_reference_registry 全量标 PENDING | KnowledgePointDeprecated |

| G8 | DEPRECATED→ARCHIVED | 系统（定时）/平台管理员 | deprecated 满 90 天 且 registry 中 PENDING=0 且 FAILED=0；或人工强制（双人） | 写 archived_at；Neo4j 删除节点与 SAME_AS 边；清单层保留历史 | KnowledgePointArchived |

| G12 | SPLIT 组合 | 平台管理员 | source 为 PUBLISHED；targets 为新建 DRAFT（split_from_id=source）；逐个走 G1-G2 发布；全部发布后才可触发 source→DEPRECATED(mode=SPLIT) | 建 split_from_id 链 | KnowledgePointSplit |

### 3.2 图谱快照版本：冻结与激活

版本号规则：`{yyyy}.{MM}.{seq}`，seq 每学科每自然月自增；`ALL` 范围版本仅用于全库导出，不参与常规激活轮换。

触发条件：

| 类型 | 条件 |
| --- | --- |
| SCHEDULED | 每周一 02:00（Asia/Shanghai），仅当上周存在变更 |
| EVENT_TRIGGERED | 未冻结变更累积 ≥50 条，或出现 CRITICAL 风险变更并落地 1h 后 |
| MANUAL | 管理员手动触发（需填写说明，双人二次确认） |

```text
冻结（Freeze）时序：

Admin/Scheduler        FreezeService             MySQL(一致性快照)         OSS              Redis
     │ POST /versions/freeze  │                        │                    │                 │
     ├──────────────────────►│ SET freeze:lock(SPX)    │                    │                 │
     │                       ├──────────────────────────────────────────────┼────────────────►│
     │                       │ BEGIN(CONSISTENT SNAPSHOT)                    │                 │
     │                       │  count kp / edge (status过滤)                 │                 │
     │                       │  流式导出 JSONL ──────────────────────────────►│ multipart put   │
     │                       │  sha256 / 行数回填 kp_version_manifest          │                 │
     │                       │  diff 上一版本清单头 → ChangeSummary            │                 │
     │                       │  INSERT kp_graph_version(FROZEN)               │                 │
     │                       │ COMMIT                                        │                 │
     │                       │ DEL freeze:lock                               │                 │
     │◄── 201 {versionId, status: FROZEN} ──│                                 │                 │

激活（Activate）：
     │ POST /versions/{id}/activate                                      │                 │
     ├──────────────────────►│ CAS 旧 ACTIVE→SUPERSEDED（superseded_at=now）   │                 │
     │                       │ CAS 本版本 FROZEN→ACTIVE（activated_at=now）     │                 │
     │                       │ 链接 previous/next_version_id                  │                 │
     │                       │ Outbox: GraphVersionActivated                  │                 │
     │                       │ SET kg:version:current:{subject} ──────────────┼────────────────►│
     │                       │ (可选) 触发 Neo4j 全量投影重建（结构变更>500 时） │                 │
```

关键实现规则：

1. **冻结用一致性快照而非停写**：`BEGIN TRANSACTION WITH CONSISTANT SNAPSHOT`（RR 隔离）内完成计数与导出读；期间业务写入不阻塞。快照点之后提交的变更自然归入下一个版本（by design，非降级场景）。
2. **清单对账**：manifest.row_count 必须 = 快照内计数，sha256 必须与 OSS 回传 ETag 对齐；任一不一致 → 冻结失败回滚、版本删除、告警（D3）。
3. **激活 CAS 双改**：`UPDATE ... SET status='SUPERSEDED' WHERE id=? AND status='ACTIVE'` 与 `... SET status='ACTIVE' WHERE id=? AND status='FROZEN'`，任一影响行数=0 即整体回滚并返回 54113/54112。
4. **Redis 指针最后切**：事件已落 Outbox 后才切换指针，保证消费者收到事件时指针已可读（消费者重试兼容乱序）。
5. **同一学科同时只有一个 ACTIVE**：uk_version_number + 激活 CAS 共同保证。

### 3.3 变更影响分析引擎

任何 G2/G6/G9/G11/G12 守卫放行前调用；结果写入 kp_change_record.impact_analysis，作为审批路由依据。

```python
class ImpactAnalysisService:
    """变更影响分析：引用登记 + 图遍历 + 下游询问 三路汇总"""

    REF_QUERIES = {
        "affectedQuestions":   "SELECT COUNT(*) FROM kp_reference_registry WHERE kp_id=%s AND ref_type='QUESTION'",
        "affectedCourses":     "... ref_type='COURSE'",
        "affectedChapters":    "... ref_type='CHAPTER'",
        "affectedStudentRecords": "... ref_type='STUDENT_MASTERY'",
    }

    def compute(self, change: ChangeRecord) -> ImpactAnalysis:
        impact = ImpactAnalysis(riskReasons=[])

        # 1) 引用登记表直查（题目/课程/章节/学生记录）
        for field, sql in self.REF_QUERIES.items():
            setattr(impact, field, self.mysql.scalar(sql, change.entityId))

        # 2) 图遍历：结构变更（PART_OF 父节点、PREREQUISITE 上游）波及的子图
        if change.changeType in ("UPDATE", "DELETE", "MERGE", "SPLIT", "DEPRECATE") \
                and change.structural_fields_touched():
            downstream = self.neo4j.run("""
                MATCH (k:KnowledgePoint {id: $kpId})<-[:PART_OF*1..2]-(child)
                RETURN count(child) AS children
            """, kpId=change.entityId).single()["children"]
            impact.riskReasons.append(f"structural_change_cascades_{downstream}_children")

        # 3) 下游询问：学习路径使用量（gRPC，路径引擎）
        impact.affectedLearningPaths = self.path_client.get_path_usage_by_kp(change.entityId)

        # 4) AI Prompt 模板引用（关键词/编码检索，限 100 条防全表扫）
        impact.affectedAiPrompts = self.prompt_registry.search_by_kp(change.entityId, limit=100)

        # 5) 风险评分矩阵（顺序判定，取最高级）
        impact.riskLevel = self._score(change, impact)
        impact.requiresApproval = (
            impact.riskLevel in ("HIGH", "CRITICAL")
            or change.changeType in ("MERGE", "SPLIT", "DEPRECATE")
        )
        return impact

    def _score(self, change, impact) -> RiskLevel:
        if change.changeType == "BULK_IMPORT" and change.bulk_rows > 200:
            return "CRITICAL"                       # 批量导入超阈值直接最高级
        if change.changeType == "DEPRECATE" and impact.affectedStudentRecords > 0:
            return "CRITICAL"                       # 学生数据涉及迁移
        if impact.affectedStudentRecords > 100_000 \
                or impact.affectedQuestions > 5_000:
            return "CRITICAL"
        if impact.affectedStudentRecords > 10_000 \
                or impact.affectedQuestions > 1_000 \
                or change.touches_structural_fields():   # stage/subject/gradeBand/关系边
            return "HIGH"
        if impact.affectedQuestions + impact.affectedCourses > 0 \
                or change.changeType in ("MERGE", "SPLIT"):
            return "MEDIUM"
        return "LOW"
```

> 影响分析结果随变更缓存于 kp_change_record；批量导入按批生成聚合分析（逐条仅计数，不逐条落分析 JSON）。

### 3.4 废弃（Deprecate）全流程

#### 3.4.1 主流程

```text
管理员发起 deprecate(mode=SUPERSEDE|MERGE|NONE, successorKpId, reason)
   │
   ▼
① 影响分析（§3.3）→ requiresApproval=true 则创建 kp_change_approval(PENDING)
   │    └─ 审批驳回 → 终止，知识点保持 PUBLISHED（approval.status=REJECTED 留痕）
   ▼
② 单事务执行（G6 守卫）：
   │  - kp_knowledge_point: status→DEPRECATED, deprecated_at, superseded_by_id
   │  - successor.supersedes_id 反向回填
   │  - kp_version_history 快照
   │  - kp_reference_registry: 该 kp 全部引用标 migration_status=PENDING
   │  - kp_change_record + impact_analysis
   │  - kg_outbox_event: KnowledgePointDeprecated
   ▼
③ 引用迁移 Worker（异步，按 ref_type 分批，batch=100）：
   │  QUESTION         → 题目服务 gRPC RebindQuestionKp(questionId, fromKp, toKp) 幂等键(questionId,fromKp,toKp)
   │  COURSE/CHAPTER   → 内容服务 gRPC RebindChapterKp 同幂等模式
   │  STUDENT_MASTERY  → 见 3.4.3 掌握度迁移（ClickHouse 双写窗口）
   │  LEARNING_PATH    → 不主动迁移：路径引擎消费 Deprecated 事件自行重算（GRAPH_VERSION_MISMATCH 场景）
   │  AI_PROMPT        → Prompt 配置工作台收到事件，人工更新提示词（不自动改）
   │  成功→MIGRATED；失败→指数退避重试 5 次（Redis 记 retry 计数）→ FAILED 进人工队列
   ▼
④ 迁移完成校验：registry 中该 kp 的 PENDING=0 且 FAILED=0 → kg:migration:{kpId} 标 DONE
   │  → 事件 ReferenceMigrationCompleted
   ▼
⑤ 90 天后自动归档（G8）：删除 Neo4j 节点/边、清 SAME_AS、ARCHIVED 只读
```

#### 3.4.2 迁移 Worker 核心代码

```python
class ReferenceMigrationWorker:
    BATCH = 100

    def run(self, kp_id: str):
        while True:
            rows = self.mysql.query("""
                SELECT id, ref_type, ref_id FROM kp_reference_registry
                WHERE kp_id=%s AND migration_status='PENDING'
                ORDER BY id LIMIT %s FOR UPDATE SKIP LOCKED
            """, kp_id, self.BATCH)
            if not rows:
                return self._finalize(kp_id)
            for r in rows:
                try:
                    self.dispatchers[r.ref_type].rebind(   # 各下游 gRPC，均幂等
                        ref_id=r.ref_id, from_kp=kp_id, to_kp=self.successor_of(kp_id))
                    self.mark(r.id, "MIGRATED")
                except DownstreamUnavailable:
                    self.retry_later(r)          # 指数退避：30s/2m/8m/30m/2h，共 5 次
                except InvalidReference:
                    self.mark(r.id, "SKIPPED")  # 引用方已删除等场景，跳过并审计

    def _finalize(self, kp_id):
        pending = self.mysql.scalar(
            "SELECT COUNT(*) FROM kp_reference_registry "
            "WHERE kp_id=%s AND migration_status IN ('PENDING','FAILED')", kp_id)
        if pending == 0:
            self.outbox.emit("ReferenceMigrationCompleted",
                             aggregate_id=kp_id, payload={"kpId": kp_id})
        else:  # 存在 FAILED → 人工队列 + 告警（D5）
            self.alert.stuck_migration(kp_id, pending)
```

#### 3.4.3 学生掌握度迁移（STUDENT_MASTERY 专项）

学生掌握度数据量大（ClickHouse）且不可阻塞，采用**双写窗口 + 异步回填**：

1. Deprecated 生效时：在 `mastery_kp_alias` 表写入映射 `(fromKp → toKp, effectiveAt)`；
2. 读路径（学情分析查询）：查询时 JOIN alias 表，旧 KP 掌握度按映射折算展示（读时兼容）；
3. 写路径：新答题记录按别名表直接落到新 KP（写时归一）；
4. 回填 Job：每日将 fromKp 历史序列按学生聚合写入 toKp 校准记录（`source='MIGRATION:{fromKp}'`），不修改原始序列（不可变历史原则）；
5. 回填完成后 alias 表标记 `backfilled=1`，读兼容层保留 180 天后下线。

#### 3.4.4 无 successor 废弃

仅当 `impactAnalysis.affectedTotal = 0`（无任何登记引用）且填写充分理由时允许 mode=NONE；否则返回 54106。防"孤儿废弃"导致下游悬空引用。

#### 3.4.5 前置关系成环检测（G1/G9 边变更共用）

```cypher
// 新增/修改 PREREQUISITE 或 PART_OF 边 (source → target) 前：
// 若 target 已可达 source，则成环，拒绝（54126）
MATCH path = (target:KnowledgePoint {id: $targetId})
             -[:PREREQUISITE|PART_OF*1..15]->
             (source:KnowledgePoint {id: $sourceId})
RETURN count(path) > 0 AS has_cycle;
```

> 深度上限 15：知识点链长度 P99 < 15，超过即视为异常结构，单独告警（防止超大环检测 DoS）。

#### 3.4.6 部分失败的补偿

| 失败点 | 补偿 |
| --- | --- |
| 事务②后事件投递延迟 | Outbox 重试，下游按事件幂等（§5） |
| 迁移某批失败 | SKIP LOCKED 保证不阻塞其它批次；退避重试；5 次后 FAILED + 人工队列 |
| 迁移卡死 > 24h | 告警 kg_migration_stuck；管理端可整批重置 PENDING 重跑（幂等安全） |
| 掌握度回填 Job 失败 | 从 checkpoint 续跑；alias 读兼容层不因此下线 |

#### 3.4.7 回退窗口（G7）

废弃后 30 天内可回退：生成反向 ChangeRecord（状态 DEPRECATED→PUBLISHED、清除 successor 链）；**引用迁移不自动回滚**——已迁移引用由迁移 Worker 按反向幂等键再迁回（与正向同一套机制）；掌握度别名表追加反向映射（不删除历史映射，形成链式解析 A→B→A'，解析时取末端）。回退后 successor 若因此成为零引用知识点，仅提示管理员，不自动废弃。

### 3.5 合并（Merge）流程

```text
merge(source=A, target=B)：
① 守卫：A、B 均 PUBLISHED（54117/54118）；无进行中 merge（Redis 锁 kg:merge:{A}/{B}）
② 影响分析（对 A、B 并集计算）→ 审批（G11 必审）
③ 事务：建 SAME_AS 边(A-[:SAME_AS]->B)；A.merge_target_id=B；A→DEPRECATED(mode=MERGE)
   B.aliases += [A.name, *A.aliases]（去重）；B.keywords 并集合并
   Outbox: KnowledgePointsMerged{sourceKpId:A, targetKpId:B}
④ 引用迁移：A 的全部 QUESTION/COURSE/CHAPTER 引用 → B
   一题同时挂 A、B 时：迁移后 tags 去重（题目服务按 (questionId, kpId) 幂等天然去重）
⑤ 掌握度合并（按学生，180 天窗口加权）：
   merged(student, B) = (n_A × m_A + n_B × m_B) / (n_A + n_B)
   n = 窗口内答题次数；写入 B 的校准记录 source='MERGE:{A}'；A 序列只读归档
   （样本量加权防"少量高掌握覆盖大量低掌握"；n_A+n_B=0 的学生不产生记录）
⑥ 迁移完成 → SAME_AS 边保留至 A 归档（供历史查询解释"为何 A 的题目出现在 B"）
```

**竞态防护：** ①阶段对 A、B 各加合并锁（SET NX EX 300）；若 A 已 DEPRECATED → 54103（守卫 G11）；若 B 在锁等待期间被另一 merge 消费 → 第二个 merge 在①校验失败拒绝。事务内二次校验状态（乐观读 + UPDATE ... WHERE status='PUBLISHED' 影响行数=0 即回滚）。

### 3.6 拆分（Split）流程

```text
split(source=A, targets=[A1, A2])：
① 守卫：A 为 PUBLISHED；targets 编码全局唯一（54120）；≥1 个（54119）
② 创建 A1/A2 为 DRAFT（split_from_id=A），逐个走 G1→G2 发布
③ 全部 targets 发布后：A→DEPRECATED(mode=SPLIT)，Outbox: KnowledgePointSplit
④ 引用迁移——拆分不能全自动，走"推荐+人工决策"队列：
   - 题目知识点标注引擎对每道 A 引用题目计算与 A1/A2 的相似分
   - 管理后台决策队列：单选迁移 / 多挂（一题挂 A1+A2）/ 待定
   - 待定项 > 30 天未决策：自动挂全部新 KP（保守策略）+ 审计标记 AUTO_ATTACHED
⑤ 学生掌握度：不自动拆分（无法从 A 的聚合值推断 A1/A2 分布）。
   A 掌握度序列随 A 归档只读保留；A1/A2 冷启动；学情报告层渲染"A 拆分为 A1/A2"
   连续性说明（报告服务消费 KnowledgePointSplit 事件）；路径引擎将 A1/A2 纳入后续练习
⑥ 归档守卫：A 的引用全部决策完成（含 AUTO_ATTACHED）才允许 G8
```

### 3.7 MySQL→Neo4j 投影同步管线

```python
class GraphProjectionWorker:
    """Outbox → Neo4j 增量投影；幂等 + 乱序防护 + 断点续传"""

    def poll(self):
        cursor = int(self.redis.get("kg:sync:cursor") or 0)
        events = self.mysql.query("""
            SELECT id, event_id, aggregate_id, event_type, payload
            FROM kg_outbox_event WHERE id > %s ORDER BY id LIMIT 200
        """, cursor)
        for ev in events:
            last = self.redis.get(f"kg:node:lastevent:{ev.aggregate_id}")
            if last and self.ulid_cmp(last, ev.event_id) >= 0:
                continue                      # 乱序/重复投递，跳过（事件 ULID 单调）
            self.apply(ev)                    # MERGE 节点/关系 或 DETACH DELETE
            self.redis.set(f"kg:node:lastevent:{ev.aggregate_id}", ev.event_id)
            self.redis.set("kg:sync:cursor", ev.id)

    def apply(self, ev):
        if ev.event_type in ("KnowledgePointArchived",):
            self.neo4j.run("MATCH (n:KnowledgePoint {id:$id}) DETACH DELETE n", id=ev.aggregate_id)
        else:
            self.neo4j.run("""
                MERGE (n:KnowledgePoint {id: $kp.id})
                SET n += $kp.props, n.status = $kp.status
            """, kp=ev.projection())          # 边变更同理：MERGE 关系 + SET 属性
```

**全量重建（蓝绿切换）：** 当结构变更 >500 或投影疑似漂移时，激活流程可选触发：

1. 从当前 ACTIVE 清单流式构建带影子标签的子图 `:KgShadow:{n}`；
2. 校验 `count(:KgShadow:{n})` = manifest.row_count，不符 → 丢弃重建（D2）；
3. 原子切换：事务内 `REMOVE n:KgShadow:{n} SET n:KnowledgePoint` 批处理 + 删除旧图中不在清单的节点；
4. 期间读流量仍走旧图（最终一致，切换后秒级收敛）。

**毒丸事件：** apply 连续失败 3 次（语法/约束冲突类异常，非连接类）→ 写入死信表 kg_projection_dead（事件快照 + 异常栈），Worker 跳过继续，管理端提供单条重放与丢弃按钮；死信积压 >0 即告警。

### 3.8 时序查询（Time-Travel）

```python
class TimeTravelService:
    """三类时序查询入口"""

    def resolve_version(self, at: datetime, subject: str) -> str:
        """时间点 → 版本：取 activated_at <= at 的最新 ACTIVE/SUPERSEDED 版本"""
        return self.mysql.scalar("""
            SELECT id FROM kp_graph_version
            WHERE subject=%s AND status IN ('ACTIVE','SUPERSEDED')
              AND activated_at <= %s ORDER BY activated_at DESC LIMIT 1
        """, subject, at)

    def topology(self, version_id: str, kp_id: str, depth: int = 2) -> SubGraph:
        """历史拓扑：OSS 清单 → 内存建图 → BFS 限界"""
        manifest = self.load_manifest(version_id)          # Redis 缓存 1h（gzip）
        self.verify_sha256(manifest)                       # 校验失败 → D8 降级
        return manifest.bfs(kp_id, min(depth, 3), max_nodes=500)

    def diff(self, v1: str, v2: str) -> list[DiffEntry]:
        """相邻/跨越版本差异：直接查 kp_change_record（不读 OSS）"""
        return self.mysql.query("""
            SELECT entity_type, entity_id, change_type, diff
            FROM kp_change_record
            WHERE graph_version_id IN (%s, %s)
        """, v1, v2)
```

**限界与约束：** BFS 深度 ≤3、返回节点 ≤500（超出截断并标记 truncated=true）；时间点早于最早可用清单（归档未解冻）返回 54128 并提示解冻等待；子图结果缓存键 `kg:tt:subgraph:{versionId}:{kpId}:{depth}`（1h）。

**典型消费方：** 合规审计（"某时间点某学科图谱中 X 的前置链"）、教研复盘（版本 diff）、数据团队回溯建模（清单离线下载）。

### 3.9 版本回滚（Rollback）

**原则：回滚 = 生成新版本，绝不指针回拨**（不可变历史原则，见 §1.4）。

```text
rollback(targetVersionId=V)：
① 守卫：V 的 manifest 存在且已验证（54111/54116/D8）
② 计算逆向变更：对 (V, current] 窗口内每条 ChangeRecord 生成逆记录
   （CREATE↔DELETE、UPDATE 字段互换、MERGE/SPLIT/DEPRECATE 标记为 IRREVERSIBLE）
③ 若窗口含 IRREVERSIBLE 变更 → 54123，需 force=true + 双人审批（回滚仅还原图谱结构，
   已执行的引用迁移/掌握度合并不自动还原，管理员需单独评估，响应中明示清单）
④ 生成 DRAFT 新版本（实体状态取自 V 清单）→ 走标准 freeze→activate（§3.2）
⑤ Outbox: GraphVersionActivated(reason=ROLLBACK_FROM:{current}→{V})
```

> 回滚窗口不限时长（历史清单在即可回滚），但跨 IRREVERSIBLE 变更的成本随窗口增长，管理端展示逆向变更条数预估耗时。

## 7. 降级矩阵

| 编号 | 故障 | 策略 | 用户影响 |
| --- | --- | --- | --- |
| D1 | Neo4j 不可用 | 图查询降级 MySQL 邻接 CTE（递归深度≤3）；更深查询返回 503 + 建议稍后重试；判题/标注不受影响（ValidateKpRefs 走 Redis+MySQL） | 仅深度图遍历受限 |
| D2 | 投影延迟 >5min | 版本冻结/激活照常（以 MySQL 为准）；图查询自动走 MySQL CTE；告警 kg_projection_lag | 图查询 P99 上升，功能可用 |
| D3 | OSS 清单写失败/校验失败 | 冻结失败回退 DRAFT，自动重试 3 次；版本不产生；告警 | 无脏版本；周快照顺延 |
| D4 | Kafka 不可用 | Outbox 积压（表内保留 7 天）；恢复后按 id 顺序回放；管理后台展示"事件延迟"横幅 | 下游感知延迟，主链路不受阻 |
| D5 | 下游迁移 API 失败 | 指数退避 5 次 → FAILED 人工队列；不阻塞其它 KP 迁移 | 迁移进度延后，可重试 |
| D6 | 掌握度双写/回填失败 | alias 读兼容层继续生效（读时折算）；回填 Job checkpoint 续跑；对账任务日终核对差集 | 学情展示无感，回填延后 |
| D7 | 冻结与变更并发 | 快照后提交的变更归入下一版本（by design）；变更无阻塞、无丢失 | 无 |
| D8 | 回滚目标清单已转 ARCHIVE 存储或缺失 | 拒绝回滚/时序查询（54128），提示解冻等待（OSS 解冻≤5min）或禁止回滚；重建路径＝从更早 STANDARD 清单+变更记录重放 | 历史查询延后 |
| D9 | 审批服务不可用 | 高风险变更排队待审（approval PENDING）；FAST_TRACK 轻量变更不受影响 | 高风险变更延迟落地 |
| D10 | 批量导入部分块失败 | 已提交块保留；失败块独立重试；整体可作废（反向批量 DEPRECATE）；进度 API 透明 | 导入可断点续作 |

## 8. 监控告警与容量

### 8.1 指标与告警

| 指标 | 采集 | 告警阈值 |
| --- | --- | --- |
| kg_projection_lag_seconds | Outbox max(unpublished) 年龄 | >300s 告警；>900s 自动切 MySQL 降级（D2） |
| kg_freeze_failures | 计数 | 24h 内 ≥2 次 P2 |
| kg_migration_pending_total | registry PENDING 总数 | >500 P3；单 KP pending age >24h P2（kg_migration_stuck） |
| kg_version_activate_duration | 激活耗时 | >30s P3（CAS 竞争或锁泄漏） |
| kg_outbox_age | 未投递事件年龄 | >600s P2（D4） |
| kg_time_travel_latency_p99 | 时序查询 | >2s P3（清单缓存未命中风暴） |
| kg_dead_letter_count | 投影死信 | >0 P2 |
| kg_rollback_count_7d | 回滚次数 | ≥2 次 P3（数据质量预警信号） |
| kg_kp_status_gauge | 按状态分布 | DEPRECATED 总量 >5%×PUBLISHED 提示治理 |

```sql
-- 迁移积压与卡死（每 10min）
SELECT kp_id, COUNT(*) AS pending,
       MIN(created_at) AS oldest
FROM kp_reference_registry
WHERE migration_status IN ('PENDING','FAILED')
GROUP BY kp_id HAVING oldest < NOW() - INTERVAL 24 HOUR;

-- Outbox 积压年龄（每 1min）
SELECT TIMESTAMPDIFF(SECOND, MIN(occurred_at), NOW()) AS lag
FROM kg_outbox_event WHERE published_at IS NULL;
```

## 11. 验收场景

1. 新建知识点→提交→审批通过→发布：状态链 DRAFT→IN_REVIEW→PUBLISHED，kp_version_history v1，事件 KnowledgePointPublished，ValidateKpRefs 返回 valid；
2. 审核驳回→编辑（自动回 DRAFT）→重新提交通过；驳回无 comment 请求被拒；
3. PUBLISHED 轻量编辑（tags）走 FAST_TRACK 单人审批，currentVersion+1，事件 Updated；
4. 创建重复 code 知识点→54102，响应携带冲突 ID；
5. 新增 PREREQUISITE 边构成环→54126，环路径脱敏展示；
6. 周快照：冻结→清单行数与快照计数一致→激活→Redis 指针切换→GraphVersionActivated 事件→路径引擎收到重算；
7. 冻结进行中并发发布一个 KP：冻结成功且该变更不在本版清单（进入下一版），无报错（D7）；
8. 高风险 deprecate：→审批 PENDING→通过后落地→引用迁移至 PENDING=0→事件链齐全→90 天后自动归档；
9. 有引用但 mode=NONE 且无理由→54106；successor 为后代节点→54107；
10. 废弃 20 天后回退（G7）：状态回 PUBLISHED，引用反向幂等迁移，alias 链式解析正确；废弃 40 天后回退→54122；
11. merge：SAME_AS 边建立、aliases 合并去重、题目引用迁移幂等（重放不重复）、掌握度加权合并值与手算一致、样本为 0 学生无记录；
12. merge 目标为 DEPRECATED→54117；并发双 merge 竞态仅一个成功；
13. split：新 KP 逐个发布→决策队列推荐分正确→待定 30 天自动全挂（AUTO_ATTACHED 审计）→归档守卫拦截未决策完成项；
14. time-travel：按时间点解析版本→拉清单建图→BFS 深度 3 截断标记 truncated；相邻版本 diff 与 kp_change_record 一致；
15. 回滚：生成新版本号而非指针回拨；窗口含 MERGE 时拒绝（54123），force+双人审批后结构还原但引用不自动回滚，响应明示；
16. Neo4j 宕机：深度≤3 查询走 MySQL CTE 正确返回，深度 4 返回 503；ValidateKpRefs 正常（D1）；
17. 批量导入 dryRun：行级错误含行号与错误码；正式导入块级断点续作；作废产生反向批量 DEPRECATE；
18. 投影毒丸事件：连续失败 3 次进死信、Worker 不阻塞、管理端重放成功后 cursor 推进。
