# 学生作业全生命周期管理与智能催交提醒调度引擎详细设计

## 1. 设计目标

针对学生作业场景，建立从作业创建、发布、领取、完成、批改到归档的全生命周期管理闭环，并基于截止时间、学生行为模式与历史催交效果，构建智能催交提醒调度策略，提升作业按时完成率，降低人工催交成本，形成可观测、可配置、可进阶的作业数据资产。

## 2. 范围与边界

- 本设计面向学生作业场景，适用于个人任务与班级作业。
- 不涉及考试、测验的评分归因与复杂判卷逻辑（另见"服务端-主观题智能评分与自适应反馈生成引擎"）。
- 不涉及教师端批量阅卷、分屏对比与批改工具链（另见"服务端-智能作业批改与教师阅卷辅助引擎"）。
- 本设计集中于作业流转状态、定时调度、催交策略、通知渠道与数据归档。

## 3. 关键术语

| 术语 | 说明 |
|---|---|
| 作业（Assignment） | 由教师或系统创建、需要学生完成的任务（个人或班级） |
| 作业实例（AssignmentInstance） | 学生抽领作业后的执行实例，含个人进度与状态 |
| 截止时间（DueAt） | 作业要求的最晚提交时间 |
| 自动提醒策略（ReminderStrategy） | 基于时间、行为、频次与渠道的催交提醒规则 |
| 催交动作（NudgeAction） | 系统触发的单次提醒动作（站内信、推送、短信等） |
| 归档窗口（ArchiveWindow） | 作业完成后保留的归档保留期 |
| 迟交容差（GracePeriod） | 允许超时的相对时间窗口，不计入迟交 |

## 4. 系统概览

```
教师/系统 → 作业创建服务 → 作业调度器 → 作业实例（学生）
               ↓                           ↓
          作业发布与分发               完成/提交/批改
               ↓                           ↓
          提醒策略引擎 ← 行为观测与状态机 → 归档服务
```

## 6. 状态机与流转

### 6.1 作业（Assignment）状态

| 状态 | 说明 | 触发条件 |
|---|---|---|
| draft | 草稿，未发布 | 创建初始 |
| published | 已发布 | 首次发布 |
| closed | 已关闭，不可再提交 | 达到截止+批改完成 |
| archived | 已归档，仅供查阅 | 归档窗口到期 |
| deleted | 已删除（软删除） | 教师或管理员删除 |

### 6.2 作业实例（AssignmentInstance）状态

| 状态 | 说明 | 触发条件 |
|---|---|---|
| pending | 待领取（班级作业） | 作业发布后实例创建，学生未进入 |
| claimed | 已领取 | 学生首次打开作业 |
| started | 已开始作答 | 学生首次提交草稿或答题 |
| submitted | 已提交 | 学生点击提交 |
| reviewed | 已批改 | 教师完成批改 |
| closed | 已关闭（不可再修改） | 系统批量关闭或作业归档 |

### 7.2 调度触发逻辑

1. 任务周期：每 5 分钟扫描一次待触发提醒（基于 `reminder_events.scheduled_at`）。
2. 事件生成：
   - 作业发布时，根据 `remind_strategy` 一次性生成未来 `reminder_events`（schedule 规则）。
   - 行为类规则在运行时动态创建事件（例如：领取后检查 idle 规则）。
3. 去重与跳过：
   - 若实例已提交，跳过所有催交（除非教师重开作业）。
   - 若实例已批改，跳过后续非紧急提醒。
   - 若学生在策略触发时间前手动领取/开始，仍按策略执行（行为类规则另起）。
4. 频次上限：单学生在同一作业上同策略最多触发一次（除手动触发）。

### 7.3 提醒下发流程

```
调度器扫描 → 批量读取待发送事件 → 渠道适配（推送/短信/站内信） → 发送 → 更新事件状态（sent/failed）
```

## 9. 关键代码示例（伪代码）

### 9.1 作业发布与实例分发

```typescript
async function publishAssignment(assignmentId: bigint) {
  const assignment = await repo.findAssignment(assignmentId);
  if (assignment.publish_strategy === 'immediate') {
    await repo.updateStatus(assignmentId, 'published');
    await createInstancesForTargets(assignment);
    await scheduleReminderEvents(assignment);
    if (assignment.notify_on_publish) {
      await notifyStudents(assignment, 'assignment_published');
    }
  } else if (assignment.publish_strategy === 'scheduled') {
    await enqueueDelayedPublish(assignment.id, assignment.scheduled_publish_at);
  }
}

async function createInstancesForTargets(assignment: Assignment) {
  const targets = assignment.type === 'class'
    ? await repo.getStudentsByClassIds(assignment.target_class_ids)
    : await repo.getStudentsByIds(assignment.target_student_ids);

  const instances = targets.map(student => ({
    assignment_id: assignment.id,
    student_id: student.id,
    class_id: student.class_id,
    tenant_id: assignment.tenant_id,
    status: 'pending'
  }));

  await repo.bulkCreateInstances(instances);
}
```

### 9.2 提醒事件生成

```typescript
async function scheduleReminderEvents(assignment: Assignment) {
  const strategy = assignment.remind_strategy_id
    ? await repo.findStrategy(assignment.remind_strategy_id)
    : await repo.findDefaultStrategy(assignment.tenant_id);

  if (!strategy || !strategy.enabled) return;

  const instances = await repo.findInstances(assignment.id, ['pending', 'claimed', 'started']);
  const events: ReminderEvent[] = [];

  for (const instance of instances) {
    for (const rule of strategy.rules) {
      if (rule.type !== 'schedule') continue;

      const scheduledAt = calculateScheduleTime(rule.trigger, assignment.due_at);
      if (!scheduledAt) continue;

      events.push({
        tenant_id: assignment.tenant_id,
        assignment_id: assignment.id,
        instance_id: instance.id,
        student_id: instance.student_id,
        trigger_type: 'schedule',
        strategy_rule: rule.id,
        channel: rule.channel,
        title: renderTitle(rule.template, assignment),
        content: renderContent(rule.template, assignment),
        template_id: rule.template,
        payload: { assignment_id: assignment.id, type: 'assignment' },
        scheduled_at: scheduledAt,
        status: 'pending'
      });
    }
  }

  await repo.bulkCreateReminderEvents(events);
}

function calculateScheduleTime(trigger: ScheduleTrigger, dueAt: Date): Date | null {
  if (trigger.mode === 'before_due' && trigger.hours) {
    return new Date(dueAt.getTime() - trigger.hours * 3600 * 1000);
  }
  if (trigger.mode === 'after_due' && trigger.minutes) {
    return new Date(dueAt.getTime() + trigger.minutes * 60 * 1000);
  }
  return null;
}
```

### 9.3 提醒调度器（Cron Job）

```typescript
export async function scheduleReminderDispatcher() {
  const now = new Date();
  const pending = await repo.findPendingReminderEvents(now);

  for (const event of pending) {
    try {
      const instance = await repo.findInstance(event.instance_id);
      if (shouldSkip(event, instance)) {
        await repo.markEventSkipped(event.id);
        continue;
      }

      await dispatchToChannel(event.channel, event);
      await repo.markEventSent(event.id, now);
    } catch (e) {
      await repo.markEventFailed(event.id, String(e));
    }
  }
}

function shouldSkip(event: ReminderEvent, instance: AssignmentInstance): boolean {
  // 已提交
  if (instance.status === 'submitted' || instance.status === 'reviewed') {
    return true;
  }
  // 策略配置的跳过规则
  const rule = event.strategy_rule; // 可进一步查策略元数据
  if (rule?.skip_if_submitted && instance.status === 'submitted') {
    return true;
  }
  if (rule?.skip_if_reviewed && instance.status === 'reviewed') {
    return true;
  }
  return false;
}
```

### 9.4 提交校验与迟交判别

```typescript
async function submitAssignment(instanceId: bigint, payload: SubmitPayload) {
  const instance = await repo.findInstance(instanceId);
  const assignment = await repo.findAssignment(instance.assignment_id);

  if (instance.status === 'submitted') {
    throw new Error('作业已提交，不可重复提交');
  }

  const now = new Date();
  const dueWithGrace = new Date(assignment.due_at.getTime() + assignment.grace_period_minutes * 60 * 1000);
  const isLate = now > dueWithGrace;
  const lateMinutes = isLate ? Math.floor((now.getTime() - assignment.due_at.getTime()) / 60000) : 0;

  await repo.updateInstance(instanceId, {
    status: 'submitted',
    submitted_at: now,
    is_late: isLate,
    late_minutes: lateMinutes,
    attachments: payload.attachments,
    draft_snapshot: payload.extra_data,
    extra_data: { ...instance.extra_data, ...payload.extra_data }
  });

  if (assignment.auto_review) {
    await enqueueAutoReview(instanceId);
  }
}
```

async function onAssignmentClaimed(instanceId: bigint) {
  const strategy = await getStrategyForInstance(instanceId);
  if (!strategy) return;

  const idleRule = strategy.rules.find(r => r.type === 'behavior' && r.trigger?.mode === 'idle_after_claim');
  if (!idleRule) return;

  const hours = idleRule.trigger.hours ?? 24;
  const scheduledAt = new Date(Date.now() + hours * 3600 * 1000);

  await repo.createReminderEvent({
    tenant_id: instance.tenant_id,
    assignment_id: instance.assignment_id,
    instance_id: instanceId,
    student_id: instance.student_id,
    trigger_type: 'behavior',
    strategy_rule: idleRule.id,
    channel: idleRule.channel,
    title: renderTitle(idleRule.template, assignment),
    content: renderContent(idleRule.template, assignment),
    template_id: idleRule.template,
    payload: { assignment_id: instance.assignment_id, type: 'assignment' },
    scheduled_at: scheduledAt,
    status: 'pending'
  });
}

## 10. 错误处理与异常场景

| 场景 | 处理策略 |
|---|---|
| 作业发布时目标班级不存在 | 记录警告日志，跳过该班级；不阻塞整体发布 |
| 定时发布时间早于当前时间 | 立即执行发布并记录补偿日志 |
| 提醒发送失败（推送渠道） | 记录错误，标记 `failed`；支持重试机制（最多3次） |
| 学生已删除但仍有未提交实例 | 保留实例记录，但不再发送提醒；并在归档时标记 |
| 迟交容差配置为负数 | 启动时校验配置，拒绝非法配置，使用默认0 |
| 策略规则包含重复触发时间 | 以第一次生成事件为准，后续去重（使用唯一索引覆盖） |
| 作业配置了短信提醒但租户无短信额度 | 降级为 push + in_app，并记录告警 |
| 教师删除已发布作业 | 软删除；保留历史实例数据供学情追溯 |
| 批量关闭时部分实例正在批改中 | 关闭状态对已批改实例立即生效；对批改中的实例等待批改完成或强制关闭（可配置） |

## 11. 性能与扩展性

- **分批处理**: 实例分发与提醒事件生成采用分批插入，避免单次事务过大。
- **索引覆盖**: `reminder_events.scheduled_at + status` 联合索引支持快速扫描待发送事件。
- **分布式锁**: 同一作业的提醒事件生成与调度器扫描需要加租户级锁，避免并发生成重复事件。
- **消息队列**: 提醒下发可由调度器写入消息队列（Kafka/RabbitMQ），消费者按渠道异步发送。
- **限流熔断**: 对同一学生的提醒发送频次做全局限流，避免刷屏。

## 12. 安全与合规

- **权限校验**: 学生只能操作自己实例；教师仅能操作所属班级作业；管理员可操作全租户作业。
- **敏感数据脱敏**: 短信内容不暴露学生个人信息；推送标题脱敏处理。
- **审计日志**: 教师发布/删除/关闭作业、手动催交、修改策略等操作需记录审计。
- **防滥用**: 同一学生在同一作业上的手动提醒需间隔至少 10 分钟。

## 13. 监控与告警

- **作业发布成功率**: 监控发布流程失败，及时告警。
- **提醒发送成功率**: 按渠道统计 `sent/failed`，失败率超阈值告警。
- **实例状态分布**: 监控 pending/claimed/started 比例，识别异常卡顿。
- **调度器延迟**: 监控事件 `scheduled_at` 与实际发送时间差。

## 14. 归档与清理

- **归档窗口**: 作业关闭后保留 X 天（可配置），到期自动归档。
- **归档策略**: 归档后实例与事件数据移至冷存储，仅保留查询索引；附件保留对象存储生命周期策略。
- **清理日志**: 归档过程中生成清理报告，供审计。

## 15. 后续演进方向

- **智能催交**: 基于历史迟交率与活跃时段，自适应调整提醒时间。
- **多策略组合**: 支持按班级/年级/学科应用不同催交策略。
- **家长抄送**: 低年级作业提醒同时推送给家长端。
- **学习绩效归因**: 归因迟交与成绩相关性，为作业难度与时间分配提供数据支持。
