# 题库生命周期管理与版本迭代机制-详细设计

## 1. 文档说明
本文档针对 PrimeTop 项目题库内容（题目、解析、知识点关联）的全生命周期管理机制进行详细设计，涵盖数据结构定义、API 接口设计、关键代码示例、状态流转与错误处理，便于开发人员直接实现与维护。

## 2. 需求背景与目标
- 支持题目从创建、审核、发布、上架、下架到归档的完整生命周期。
- 支持题目多版本管理与可追溯变更，保证教学数据一致性。
- 支持教材版本与考纲变更影响评估，同步触发题目关联内容的版本更新与归档方案。
- 支持题目质量评分、标签、难易度动态标定与纠错反馈闭环。
- 提供运维层面的批量导入/导出、灰度发布与回滚、数据清洗与去重能力。

## 4. API 接口设计

### 4.1 题目创建与提交审核
- 接口路径：POST /api/v1/questions
- 请求：
  - type, content, subject_id, grade_level, textbook_version_id, chapter_id, knowledge_points, tags, source
- 响应：
  - 成功返回 question_id、version_no、status=draft
- 状态流转：draft → pending_review（触发审核工作流）

### 4.2 题目审核通过/驳回
- 接口路径：POST /api/v1/questions/{id}/review
- 请求：{result: "pass|reject", comment: ""}
- 响应：更新 status、更新 lifecycle_state、记录审核表
- 规则：仅审核权限可操作；驳回返回原因，可重新编辑并提交。

### 4.3 题目发布（上架）
- 接口路径：POST /api/v1/questions/{id}/publish
- 响应：status=published、published_at=now、is_latest=true
- 规则：仅从 approved 可发布；发布后进入可用池，触发关联搜索索引更新。

### 4.4 题目下架
- 接口路径：POST /api/v1/questions/{id}/offline
- 响应：status=offline
- 规则：下架后学习端不可见，但历史答题记录可查；提供理由与归档任务。

### 4.5 题目归档
- 接口路径：POST /api/v1/questions/{id}/archive
- 响应：status=archived
- 规则：仅对 offline 或长期无使用记录题目执行；归档后移至归档存储，但不删除。

### 4.6 题目版本回滚
- 接口路径：POST /api/v1/questions/{id}/rollback?target_version_no={target_version_no}
- 响应：创建新版本号，复制目标版本字段，记录变更类型为 rollback
- 规则：仅管理员可回滚；生成 question_history 记录。

### 4.7 题目版本历史查询
- 接口路径：GET /api/v1/questions/{id}/versions
- 响应：版本列表（含 version_no、change_type、change_summary、changed_fields、changed_author_id、created_at）

### 4.8 题目纠错提交
- 接口路径：POST /api/v1/questions/{id}/feedback
- 请求：{type, description, attachments}
- 响应：创建 feedback 记录，status=pending

### 4.9 题目反馈处理
- 接口路径：POST /api/v1/questions/{id}/feedback/{feedback_id}/resolve
- 请求：{status: "resolved|ignored", resolution: ""}
- 响应：更新状态与处理人，记录 resolved_at；影响题目 quality_score

### 4.10 题目质量评分计算与刷新
- 接口路径：POST /api/v1/questions/{id}/quality-score/refresh
- 规则：聚合 feedback 数量与严重度、correct_rate、usage_count 更新 quality_score（算法见 6.4）

### 4.11 批量导入题目
- 接口路径：POST /api/v1/questions/import
- 请求：multipart/form-data（文件）+ meta JSON（版本归属、教材版本等）
- 响应：任务ID与异步导入进度状态；失败逐行记录错误日志

### 4.12 教材版本影响范围查询
- 接口路径：GET /api/v1/textbooks/{textbook_version_id}/impact
- 规则：返回关联章节、知识点、题目数量，提示是否需要版本迁移或内容修复

## 5. 状态流转图（概念级）
- draft → pending_review → approved → published
- approved → published → offline → archived
- rejected → draft（可重新编辑）
- 任何阶段 → archived（归档）
- published → rollback → 新版本号（复制目标版本字段）

## 6. 关键代码示例（伪代码）

### 6.1 创建题目与初始化生命周期
```sql
INSERT INTO question (
  title, content, type, subject_id, grade_level, textbook_version_id,
  chapter_id, knowledge_points, difficulty_score, official_answer,
  explanation, tags, source, author_id, status, version_no, is_latest,
  quality_score, usage_count, correct_rate, created_at
) VALUES (
  :title, :content, :type, :subject_id, :grade_level, :textbook_version_id,
  :chapter_id, :knowledge_points, :difficulty_score, :official_answer,
  :explanation, :tags, :source, :author_id, 'draft', 1, TRUE,
  0.0, 0, 0.0, NOW()
);
```

### 6.2 提交审核（事务）
```sql
BEGIN;
UPDATE question SET status = 'pending_review', lifecycle_state = JSON_SET(lifecycle_state, '$.previous', status, '$.current', 'pending_review') WHERE id = :id;
INSERT INTO question_review (question_id, reviewer_id, result, comment, reviewed_at) VALUES (:id, :reviewer_id, 'pending', NULL, NOW());
COMMIT;
```

### 6.3 审核通过并发布（事务）
```sql
BEGIN;
UPDATE question SET status = 'approved', lifecycle_state = JSON_SET(lifecycle_state, '$.current', 'approved') WHERE id = :id;
UPDATE question_review SET result = 'pass', comment = :comment, reviewed_at = NOW() WHERE id = :review_id;
UPDATE question SET status = 'published', published_at = NOW() WHERE id = :id;
COMMIT;
```

### 6.4 版本回滚（伪代码）
```sql
-- 1. 查询目标版本快照
SELECT * FROM question_history WHERE question_id = :id AND version_no = :target_version_no;
-- 2. 新建版本号
UPDATE question SET version_no = version_no + 1 WHERE id = :id;
-- 3. 覆盖字段并记录变更
UPDATE question SET
  content = :target_content,
  explanation = :target_explanation,
  official_answer = :target_official_answer,
  is_latest = TRUE,
  updated_at = NOW()
WHERE id = :id;
-- 4. 写入 question_history（change_type = 'rollback'）
INSERT INTO question_history (question_id, version_no, change_type, change_summary, changed_fields, change_author_id, created_at)
VALUES (:id, :new_version_no, 'rollback', 'Rollback to version :target_version_no', :changed_fields_json, :author_id, NOW());
```

### 6.5 反馈处理与质量分更新（伪代码）
```python
def resolve_feedback(question_id, feedback_id, status, resolution, resolved_by):
    # 记录处理结果
    update_feedback_status(feedback_id, status, resolution, resolved_by)

    # 聚合反馈数据
    feedbacks = fetch_feedbacks(question_id)
    critical_count = sum(1 for f in feedbacks if f.type in ['wrong_answer', 'inaccurate'] and f.status == 'resolved')

    # 计算质量分（示例算法）
    base_score = 100.0
    penalty = critical_count * 5.0
    usage_factor = min(1.0, question.usage_count / 1000.0)  # 使用越多可信度越高
    correct_factor = question.correct_rate / 100.0 if question.correct_rate else 0.5

    quality_score = (base_score - penalty) * 0.4 + (correct_factor * 100.0) * 0.4 + (usage_factor * 100.0) * 0.2
    quality_score = max(0.0, min(100.0, quality_score))

    update_question_quality_score(question_id, quality_score)
```

## 7. 错误处理与边界情况
- 权限不足：返回 403，明确所需权限类型
- 状态不合法（如从 draft 直接 offline）：返回 400 并提示合法转换路径
- 版本号冲突：使用悲观锁或乐观锁（version_no + CAS）防止并发覆盖
- 知识点映射不存在：回滚事务，返回 400 并提示知识库缺失点
- 纠错反馈与题目无关（question_id 检验）：返回 404
- 导入文件解析失败：记录错误行号与字段，返回 207（部分成功）与错误列表
- 撤销/回滚越权：仅管理员或创建者可执行，否则 403
- 归档后不可再次变更：除读取操作外，所有写接口返回 400 错误
- 教材版本不存在：返回 404，并提供可用的版本列表

## 8. 性能与扩展性
- 对 status、published_at、version_no、quality_score 建立复合索引，加速列表查询与质量排序。
- 题目变更采用异步消息（例如 Kafka/RabbitMQ）驱动搜索索引、缓存失效与通知。
- 大规模导入采用批处理与任务队列，每批大小建议 1000 行，并发不超过 3。
- 历史表按 created_at 分区，归档查询走分区裁剪。
- 提供 JSON 字段部分索引，例如 knowledge_points 内字段若频繁查询可建立 GIN 索引。

## 9. 安全与合规
- 内容审核接口需记录审核人ID与时间，支持审计。
- 用户反馈内容需经过敏感词过滤，避免泄露与恶意信息。
- 人工回滚操作需二次确认，并记录操作日志（question_history 与审计表）。
- 答案与解析字段在生产环境加密存储（应用层加密）或存储于独立密钥管理的安全表中。
- 敏感变更需触发 webhook 或消息通知运营/内容团队复核。

## 10. 监控与告警
- 监控题库发布/下架频次，异常升高触发告警。
- 监控纠错反馈积压，超过阈值通知内容团队处理。
- 监控题库导入失败率，批次成功率 < 95% 告警。
- 监控题目质量分分布，低于 60 的占比异常需人工复查。

## 11. 依赖与调用关系
- 上游：教材版本服务（chapter/knowledge 同步）、内容审核服务（content moderation）、权限服务（RBAC）。
- 下游：搜索服务（ES索引更新）、缓存服务（失效题目缓存）、通知服务（发布/下架通知）、学习服务（习题问答需使用 published 状态题目）。

## 12. 附录
- 变更类型枚举：create, update, downgrade, rollback, delete_soft, archive, restore
- 反馈类型枚举：wrong_answer, typo, inaccurate, hard_to_understand, other
- 题型枚举（type）：single_choice, multiple_choice, fill_blank, short_answer, essay, multi_step, true_false, matching
- 题目状态枚举（status）：draft, pending_review, approved, published, offline, archived

以上设计确保题库从创建到归档的完整生命周期可追溯、可管理、可审计，并与教材版本和考纲变更联动，支撑系统整体的可维护性与数据一致性。
