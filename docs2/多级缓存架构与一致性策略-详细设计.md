# 多级缓存架构与一致性策略 - 详细设计

## 1. 模块概述

### 1.1 定位与目标

PrimeTop 作为面向全学段的 AI 辅助学习 APP，缓存是贯穿客户端、网关、应用层、数据层的核心基础设施。现有各模块文档（客户端本地持久层、API 网关、AI 输出缓存、数据架构等）分别从各自角度描述了缓存策略，但缺少一份统一的全局缓存架构参考，导致：

1. **缓存 Key 命名冲突**：各模块独立设计 Key，可能出现跨模块覆盖
2. **TTL 策略不统一**：同类数据在不同层使用不同过期策略，造成不一致
3. **失效机制分散**：数据更新后的缓存失效方式各异，难以保证全局一致性
4. **容量规划缺失**：没有统一的缓存容量估算和淘汰策略

本文档定义 PrimeTop 的多级缓存架构，为所有模块提供统一的缓存设计规范、Key 命名约定、TTL 策略、失效机制和容量规划。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **分层解耦** | 明确 L1~L5 五级缓存边界，每级职责清晰 |
| **统一规范** | 全局 Key 命名、TTL 分档、序列化格式统一 |
| **一致性保障** | 定义数据变更后的失效链路，明确最终一致性时间窗口 |
| **容量可控** | 每级缓存有明确的容量上限和淘汰策略 |
| **可观测** | 缓存命中率、内存占用、淘汰次数等指标可监控 |
| **防御性** | 防缓存穿透、防雪崩、防击穿的通用方案 |

### 1.3 与其他文档的关系

| 文档 | 交叉点 | 本文档侧重点 |

### 2.2 各级缓存详解

#### 2.2.1 L1 - Flutter 内存缓存

**适用数据：**
- 当前页面渲染所需的 DTO 对象
- AI 对话的 SSE 流式片段（会话内）
- 列表首页数据（首页工作台、错题列表、章节目录）
- 用户身份信息与权限数据

**不适用数据：**
- 大文件（图片、音频、视频） → 由 L2 或 CDN 管理
- 敏感凭证（Token 明文） → 仅存于安全存储
- 需要持久化的用户操作 → 直接写 L2 或服务端

**实现方式：**

```dart
/// L1 内存缓存管理器
class MemoryCacheManager {
  static final _instance = MemoryCacheManager._();
  factory MemoryCacheManager() => _instance;
  MemoryCacheManager._();

  /// 缓存存储：Key → CacheEntry
  final Map<String, _CacheEntry> _cache = {};

  /// 容量上限（条目数）
  static const int maxEntries = 500;

  /// 总内存上限（字节）
  static const int maxMemoryBytes = 100 * 1024 * 1024; // 100 MB

  /// 当前已用内存估算
  int _usedBytes = 0;

  /// 读写锁
  final _lock = Lock();

  /// 写入缓存
  Future<void> set<T>(
    String key,
    T value, {
    Duration? ttl,
    int? estimatedBytes,
  }) async {
    await _lock.synchronized(() {
      // 淘汰检查
      _evictIfNeeded(estimatedBytes ?? _estimateSize(value));

      final entry = _CacheEntry(
        value: value,
        expireAt: ttl != null
            ? DateTime.now().add(ttl)
            : DateTime.now().add(const Duration(minutes: 30)),
        bytes: estimatedBytes ?? _estimateSize(value),
        createdAt: DateTime.now(),
      );

      // 已存在则先释放旧值大小
      if (_cache.containsKey(key)) {
        _usedBytes -= _cache[key]!.bytes;
      }

      _cache[key] = entry;
      _usedBytes += entry.bytes;
    });
  }

  /// 读取缓存
  Future<T?> get<T>(String key) async {
    return await _lock.synchronized(() {
      final entry = _cache[key];
      if (entry == null) return null;
      if (DateTime.now().isAfter(entry.expireAt)) {
        _removeEntry(key);
        return null;
      }
      // LRU 更新：移到末尾（通过重新插入）
      entry.accessedAt = DateTime.now();
      return entry.value as T;
    });
  }

  /// 批量读取
  Future<Map<String, T>> getMulti<T>(Iterable<String> keys) async {
    final result = <String, T>{};
    await _lock.synchronized(() {
      for (final key in keys) {
        final entry = _cache[key];
        if (entry != null && !DateTime.now().isAfter(entry.expireAt)) {
          result[key] = entry.value as T;
        }
      }
    });
    return result;
  }

  /// 删除缓存
  Future<void> delete(String key) async {
    await _lock.synchronized(() {
      _removeEntry(key);
    });
  }

  /// 按前缀批量删除
  Future<void> deleteByPrefix(String prefix) async {
    await _lock.synchronized(() {
      final keysToRemove = _cache.keys
          .where((k) => k.startsWith(prefix))
          .toList();
      for (final key in keysToRemove) {
        _removeEntry(key);
      }
    });
  }

  /// 清空所有缓存
  Future<void> clear() async {
    await _lock.synchronized(() {
      _cache.clear();
      _usedBytes = 0;
    });
  }

  /// LRU 淘汰
  void _evictIfNeeded(int incomingBytes) {
    if (_cache.length >= maxEntries ||
        _usedBytes + incomingBytes > maxMemoryBytes) {
      // 按访问时间排序，淘汰最旧的
      final sortedKeys = _cache.keys.toList()
        ..sort((a, b) =>
            _cache[a]!.accessedAt.compareTo(_cache[b]!.accessedAt));

      final targetCount = (_cache.length * 0.3).ceil(); // 淘汰 30%
      for (int i = 0;
          i < targetCount &&
              (_cache.length >= maxEntries ||
                  _usedBytes + incomingBytes > maxMemoryBytes);
          i++) {
        _removeEntry(sortedKeys[i]);
      }
    }
  }

  void _removeEntry(String key) {
    final entry = _cache.remove(key);
    if (entry != null) {
      _usedBytes -= entry.bytes;
    }
  }

  int _estimateSize(dynamic value) {
    // 粗略估算：JSON 序列化后字节数
    try {
      return jsonEncode(value).length * 2; // UTF-16 近似
    } catch (_) {
      return 1024; // 默认 1KB
    }
  }
}

class _CacheEntry {
  final dynamic value;
  final DateTime expireAt;
  final int bytes;
  final DateTime createdAt;
  DateTime accessedAt;

  _CacheEntry({
    required this.value,
    required this.expireAt,
    required this.bytes,
    required this.createdAt,
  }) : accessedAt = createdAt;
}
```

**与 Riverpod 状态管理的边界：**

| 层级 | 职责 | 生命周期 |
|------|------|---------|
| Riverpod StateProvider | 单页面的 UI 响应式状态 | 页面可见期间 |
| Riverpod CacheProvider | 跨页面的数据缓存（autoDispose=false） | 应用存活期间 |
| MemoryCacheManager | 非响应式的通用缓存（图片URL、配置项等） | 应用存活期间 |

```dart
/// Riverpod 与 MemoryCache 的集成模式
@riverpod
Future<HomeDashboard> homeDashboard(Ref ref) async {
  const cacheKey = 'home:dashboard:${currentUserId()}';

  // 先查内存缓存
  final cached = await MemoryCacheManager().get<HomeDashboard>(cacheKey);
  if (cached != null) return cached;

  // 缓存未命中，请求服务端
  final result = await ref.watch(apiServiceProvider).getHomeDashboard();

  // 写入缓存，TTL 5分钟
  await MemoryCacheManager().set(cacheKey, result, ttl: Duration(minutes: 5));

  return result;
}
```

#### 2.2.2 L2 - 客户端本地持久层

**适用数据：**
- 用户基本信息（姓名、年级、教材版本、头像 URL）
- 教材章节目录树（结构化 JSON）
- 错题列表与错题详情
- 学习记录（离线可查）
- 配置快照（功能开关、远程配置）
- 资源索引（已下载的教材资源包清单）
- AI 对话历史摘要

**存储引擎选择：**

| 数据类型 | 引擎 | 原因 |
|---------|------|------|
| 结构化业务数据 | SQLite (sqflite/drift) | 支持复杂查询、事务、索引 |
| Key-Value 配置 | Hive Box | 高性能、支持加密 Box、类型安全 |
| 二进制资源 | 文件系统 + 索引数据库 | 大文件不适合数据库存储 |

**Hive 缓存 Key 规范：**

```dart
/// Hive Box 命名与 Key 规范
class HiveCacheKeys {
  /// Box 名称
  static const String boxConfig = 'cache_config';       // 配置缓存
  static const String boxUser = 'cache_user';           // 用户数据缓存
  static const String boxTextbook = 'cache_textbook';   // 教材目录缓存
  static const String boxQuestions = 'cache_questions'; // 题目缓存
  static const String boxMistakes = 'cache_mistakes';   // 错题缓存
  static const String boxLearning = 'cache_learning';   // 学习记录缓存
  static const String boxMessages = 'cache_messages';   // 消息缓存

  /// Key 命名规范：{模块}:{实体}:{标识}
  /// 示例：
  static String userProfile(String userId) => 'user:profile:$userId';
  static String textbookTree(String versionId, String gradeId) =>
      'textbook:tree:$versionId:$gradeId';
  static String chapterDetail(String chapterId) =>
      'textbook:chapter:$chapterId';
  static String questionDetail(String questionId) =>
      'question:detail:$questionId';
  static String mistakeList(String userId, int page) =>
      'mistake:list:$userId:$page';
  static String featureFlags() => 'config:feature_flags';
  static String remoteConfig() => 'config:remote_config';
  static String learningProgress(String userId, String subjectId) =>
      'learning:progress:$userId:$subjectId';
}

/// Hive 缓存条目封装
class HiveCacheEntry {
  @HiveField(0)
  String data; // JSON 字符串

  @HiveField(1)
  int cachedAt; // 缓存时间戳（毫秒）

  @HiveField(2)
  int ttlMs; // TTL（毫秒）

  @HiveField(3)
  String eTag; // 服务端 ETag，用于条件请求

  @HiveField(4)
  String version; // 数据版本号

  bool get isExpired =>
      DateTime.now().millisecondsSinceEpoch > cachedAt + ttlMs;

  HiveCacheEntry({
    required this.data,
    required this.cachedAt,
    required this.ttlMs,
    this.eTag = '',
    this.version = '',
  });
}
```

**SQLite 缓存表设计：**

```sql
-- 通用缓存表（用于结构化数据的离线缓存）
CREATE TABLE cache_entries (
    cache_key   VARCHAR(255) NOT NULL PRIMARY KEY,
    cache_group VARCHAR(64)  NOT NULL,           -- 分组：user/textbook/question/...
    data        TEXT         NOT NULL,            -- JSON 数据
    etag        VARCHAR(128) DEFAULT '',          -- 服务端 ETag
    version     VARCHAR(64)  DEFAULT '',          -- 数据版本
    cached_at   BIGINT       NOT NULL,            -- 缓存时间戳（毫秒）
    ttl_ms      BIGINT       NOT NULL,            -- TTL（毫秒）
    size_bytes  INTEGER      DEFAULT 0,           -- 数据大小估算
    access_count INTEGER     DEFAULT 0,           -- 访问次数（LFU 参考）
    last_access BIGINT       DEFAULT 0            -- 最后访问时间
);

-- 索引
CREATE INDEX idx_cache_group ON cache_entries(cache_group);
CREATE INDEX idx_cache_expired ON cache_entries(cached_at + ttl_ms);

-- 容量管理：按分组设置容量上限
CREATE TABLE cache_group_config (
    cache_group   VARCHAR(64) NOT NULL PRIMARY KEY,
    max_size_mb   INTEGER     NOT NULL DEFAULT 50,
    default_ttl_ms BIGINT     NOT NULL DEFAULT 86400000, -- 24h
    eviction_policy VARCHAR(16) NOT NULL DEFAULT 'lru'   -- lru / lfu / fifo
);
```

#### 2.2.3 L3 - API 网关层缓存

**适用接口：**
- 教材版本列表、学科列表 → 极少变更
- 年级章节目录 → 学期内不变
- 功能开关与远程配置 → 分钟级更新
- 公开题目详情页（SEO 场景）→ 按版本缓存
- 静态资源（JS/CSS/图片/字体） → CDN 长期缓存

**不适用接口：**
- AI 对话请求 → 个性化强、实时性要求高
- 用户学习记录写入 → 必须穿透到服务端
- 支付相关接口 → 绝对不能缓存

**Nginx 缓存配置：**

```nginx
# 缓存区域定义
proxy_cache_path /var/cache/nginx/primetop
    levels=1:2
    keys_zone=primetop_cache:100m
    max_size=10g
    inactive=1h
    use_temp_path=off;

server {
    listen 443 ssl http2;
    server_name api.primetop.com;

    # 公共只读接口缓存规则
    location ~ ^/api/v1/(textbook/versions|subjects|grades) {
        proxy_cache primetop_cache;
        proxy_cache_key "$scheme$host$request_uri";
        proxy_cache_valid 200 1h;           # 成功响应缓存 1 小时
        proxy_cache_valid 404 30s;          # 404 缓存 30 秒
        proxy_cache_use_stale error timeout updating;
        proxy_cache_lock on;                # 防击穿：只放一个请求穿透
        add_header X-Cache-Status $upstream_cache_status;
        proxy_pass http://backend;
    }

    # 教材章节目录缓存
    location ~ ^/api/v1/textbook/.+/chapters {
        proxy_cache primetop_cache;
        proxy_cache_key "$scheme$host$request_uri";
        proxy_cache_valid 200 4h;
        proxy_cache_use_stale error timeout updating;
        proxy_cache_lock on;
        proxy_cache_bypass $http_pragma $http_authorization; # 登录态变化时跳过
        add_header X-Cache-Status $upstream_cache_status;
        proxy_pass http://backend;
    }

    # 远程配置缓存（短 TTL）
    location ~ ^/api/v1/config/ {
        proxy_cache primetop_cache;
        proxy_cache_key "$scheme$host$request_uri";
        proxy_cache_valid 200 5m;
        proxy_cache_use_stale error timeout updating;
        proxy_cache_lock on;
        add_header X-Cache-Status $upstream_cache_status;
        proxy_pass http://backend;
    }

    # AI 接口：不缓存（由应用层 AI 输出缓存引擎管理）
    location ~ ^/api/v1/(ai|chat|tutoring)/ {
        proxy_cache off;
        proxy_pass http://backend;
    }

    # 用户数据写入：不缓存
    location ~ ^/api/v1/(learning-records|mistakes|orders)/ {
        if ($request_method != GET) {
            proxy_cache off;
        }
        proxy_pass http://backend;
    }
}
```

**Redis 数据分区策略：**

采用逻辑分区（DB 编号），非物理分片，按业务域隔离：

| Redis DB | 用途 | Key 前缀 | 预估 Key 数 | 内存占用 |
|----------|------|---------|------------|---------|
| DB 0 | 用户会话与认证 | `auth:` `session:` `token:` | 50万 | 2 GB |
| DB 1 | 学习数据热缓存 | `learn:` `progress:` `streak:` | 200万 | 8 GB |
| DB 2 | 题目与知识库缓存 | `q:` `kp:` `ch:` | 500万 | 16 GB |
| DB 3 | AI 输出缓存 | `ai:` `llm:` | 100万 | 8 GB |
| DB 4 | 配置与功能开关 | `cfg:` `feat:` `ab:` | 1万 | 0.5 GB |
| DB 5 | 限流与计数器 | `rate:` `quota:` `cnt:` | 100万 | 2 GB |
| DB 6 | 分布式锁 | `lock:` | 1万 | 0.01 GB |
| DB 7 | 临时数据（排行榜等） | `rank:` `zset:` | 50万 | 4 GB |

#### 2.2.5 L5 - 数据库层缓存

由数据库引擎自身管理，应用层通过以下方式间接控制：

| 策略 | MySQL | PostgreSQL |
|------|-------|-----------|
| Buffer Pool / Shared Buffers | `innodb_buffer_pool_size` = 物理内存的 60-70% | `shared_buffers` = 物理内存的 25% |
| 查询缓存 | MySQL 8.0 已移除，不使用 | pg_catalog 查询计划缓存 |
| 索引优化 | 覆盖索引减少回表 | 部分索引减少维护开销 |
| 分区表 | 按时间分区，热数据在最近分区 | 同左 |

## 3. Redis Key 设计规范

### 3.1 命名规范

```
格式：{业务域}:{实体}:{操作/维度}:{标识}
层级：用冒号 ":" 分隔，最多 5 级
长度：Key 总长不超过 128 字节
字符：仅使用小写字母、数字、冒号、下划线、短横线
```

### 3.3 Key 过期策略分档

| TTL 分档 | 时长 | 适用场景 | 示例 |
|---------|------|---------|------|
| 极短 | 10s~60s | 分布式锁、验证码、秒级计数器 | `auth:captcha`, `lock:*` |
| 短 | 1m~10m | 限流计数器、功能开关、实时配置 | `rate:*`, `cfg:feat` |
| 中短 | 30m~1h | 用户会话、AI 上下文、热点数据 | `auth:token`, `ai:ctx`, `learn:session` |
| 中 | 4h~8h | 教材目录、知识点树、章节列表 | `ch:tree`, `kp:tree`, `q:list` |
| 中长 | 12h~24h | 题目详情、用户画像、学习进度 | `q:detail`, `user:profile`, `learn:progress` |
| 长 | 7d~30d | 排行榜、历史报告、推送 Token | `rank:*`, `learn:weekly`, `push:token` |
| 超长 | 90d~365d | CDN 资源索引、归档数据 | `ai:resp`(部分场景) |

### 3.4 序列化格式

| 数据类型 | 序列化方式 | 说明 |
|---------|-----------|------|
| 简单字符串 | 直接存储 | Token、计数器、状态标记 |
| 结构化对象 | JSON (紧凑模式) | 用户信息、题目详情、配置项 |
| 列表/集合 | JSON Array 或 Redis 原生 List/Set | 小列表用 JSON，大列表用 Redis List |
| 排行榜 | Redis ZSet | 直接使用原生有序集合 |
| 计数器 | Redis String (INCR) | 原子自增，不序列化 |
| 哈希表 | Redis Hash | 多字段对象（用户 Profile 字段多时可按需读取） |
