> 模块版本：v1.0 | 最后更新：2026-05-19
> 原始需求来源：`docs/design/启硕-PrimeTop-全学段AI辅助学习软件项目设计文档.md` §13.1, §13.2, §13.3, §13.4

## 1. 模块概述

### 1.1 定位

日志与监控告警体系是 PrimeTop 的生产可观测性基础设施，为开发、运维、运营团队提供统一的日志采集、指标监控、链路追踪和告警能力。本体系确保所有服务上线即可观测，故障可快速定位，性能可量化分析。

### 1.2 核心价值

1. **统一日志标准**：全服务采用结构化日志，统一格式、统一采集、统一检索
2. **全链路追踪**：一次用户请求从网关→业务→AI→数据库的完整调用链可视化
3. **实时告警**：关键业务指标异常秒级发现，多渠道通知（钉钉/飞书/短信/电话）
4. **成本可视化**：AI 模型调用成本、延迟、成功率实时监控
5. **合规审计**：操作审计日志保留满足数据安全和未成年人保护合规要求

### 1.3 系统边界

| 范围内 | 范围外 |
|--------|--------|
| 日志采集、存储、检索、归档 | 业务埋点规范定义（由数据埋点系统负责） |
| 基础设施指标（CPU/内存/磁盘/网络） | 用户行为分析（由学情分析模块负责） |
| 业务指标采集与看板 | AI 输出质量评估算法（由用户反馈与AI质量评估负责） |
| 全链路追踪（Trace） | A/B 测试框架（由灰度发布系统负责） |
| 告警规则引擎与通知 | 安全攻击检测与防御（由安全与内容合规系统负责） |
| 运维仪表盘 | |

### 1.4 核心用户

| 用户 | 使用场景 |
|------|----------|
| 后端开发 | 排查线上问题、查看调用链路、分析错误日志 |
| 运维工程师 | 基础设施监控、容量规划、故障响应 |
| AI 工程师 | 模型调用延迟/成本/质量监控 |
| 产品/运营 | 业务指标看板、AI 调用量趋势、会员转化漏斗 |
| 安全审计 | 操作审计日志查询、合规检查 |

### 2.2 技术选型

| 组件 | 选型 | 版本要求 | 说明 |
|------|------|----------|------|
| 日志采集 | Filebeat 8.x | ≥ 8.8 | 轻量级日志采集器，支持多行合并、JSON 解析 |
| 日志备选采集 | FluentBit 3.x | ≥ 3.0 | 资源占用更低，适合容器化环境 |
| 日志存储 | Elasticsearch 8.x | ≥ 8.8 | 日志存储、检索、聚合分析 |
| 日志检索 | Kibana 8.x | ≥ 8.8 | 日志可视化检索、仪表盘 |
| 指标采集 | Prometheus 2.x | ≥ 2.48 | 时序指标存储、PromQL 查询 |
| 指标导出 | Node Exporter / JMX Exporter | 最新 | 系统/ JVM 指标导出 |
| 链路追踪 | OpenTelemetry + Jaeger | OTel ≥ 1.30 | 统一 Trace/Span 采集，Jaeger 存储+展示 |
| 可视化 | Grafana 10.x | ≥ 10.2 | 统一仪表盘，支持 Prometheus/ES/Jaeger 数据源 |
| 告警 | Alertmanager 0.27+ | ≥ 0.27 | 告警路由、分组、抑制、静默 |
| 告警增强 | Grafana Alerting | 内置 | 补充业务指标告警 |

### 2.3 设计原则

1. **零侵入**：采集端以 sidecar/agent 方式运行，不侵入业务代码（除 OTel SDK 打点）
2. **结构化日志**：全部输出 JSON 格式日志，禁止非结构化文本
3. **采样策略**：Trace 默认采样率 10%，错误请求 100% 采样，可按场景动态调整
4. **分级存储**：热数据 7 天（SSD），温数据 30 天（HDD），冷数据 90 天（对象存储），审计日志 1 年
5. **统一关联**：日志/指标/Trace 通过 `trace_id` 贯穿关联

## 3. 日志体系设计

### 3.1 日志分类

| 日志类型 | 产出方 | 保留策略 | 说明 |
|----------|--------|----------|------|
| 业务日志 | 各业务模块 | 热数据7天 + 温数据30天 | 请求处理、业务异常 |
| 访问日志 | API Gateway | 热数据7天 + 温数据30天 | 每次 HTTP 请求记录 |
| AI 调用日志 | AI Service | 热数据7天 + 温数据30天 | 模型调用详情、Token 用量 |
| 审计日志 | 权限相关操作 | 冷数据1年 | 管理后台操作、敏感数据访问 |
| 系统日志 | OS/运行时 | 热数据3天 + 温数据14天 | GC、OOM、连接池异常 |
| 慢查询日志 | 数据库 | 热数据7天 + 温数据30天 | 超过阈值的 SQL 查询 |

### 3.2 统一日志格式

所有业务服务必须输出以下 JSON 结构日志（非业务日志如 GC、系统日志除外）：

```json
{
  "timestamp": "2026-05-19T13:41:00.123+08:00",
  "level": "INFO",
  "service": "ai-service",
  "instance": "ai-svc-pod-7b8f9",
  "trace_id": "abc123def456",
  "span_id": "span789",
  "request_id": "req-uuid-001",
  "user_id": "U100001",
  "tenant_id": null,
  "module": "model_dispatch",
  "action": "invoke_model",
  "message": "Model invocation completed",
  "error_code": null,
  "error_message": null,
  "duration_ms": 2340,
  "tags": {
    "model_provider": "deepseek",
    "model_name": "deepseek-chat-v3",
    "scene": "homework_help",
    "input_tokens": 1250,
    "output_tokens": 860,
    "status": "success"
  }
}
```

### 3.3 日志字段规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `timestamp` | string | ✅ | ISO 8601 格式，精确到毫秒，带时区 |
| `level` | string | ✅ | DEBUG / INFO / WARN / ERROR / FATAL |
| `service` | string | ✅ | 服务/模块名，对应 §2.1 的服务清单 |
| `instance` | string | ✅ | 实例标识（Pod名/主机名） |
| `trace_id` | string | 条件必填 | 存在链路追踪时必填，否则为空字符串 |
| `span_id` | string | 条件必填 | 当前 Span ID |
| `request_id` | string | ✅ | 请求唯一标识，由网关生成，全链路透传 |
| `user_id` | string | 条件必填 | 已登录用户必填 |
| `module` | string | ✅ | 模块内子功能标识 |
| `action` | string | ✅ | 具体操作名 |
| `message` | string | ✅ | 人类可读的日志描述 |
| `error_code` | string | 条件必填 | level≥WARN 时必填，业务错误码 |
| `error_message` | string | 条件必填 | level≥WARN 时必填 |
| `duration_ms` | number | 条件必填 | 有耗时操作时必填 |
| `tags` | object | 推荐 | 扩展字段，键值对，用于业务上下文 |

### 3.4 日志级别使用规范

| 级别 | 使用场景 | 示例 |
|------|----------|------|
| DEBUG | 开发调试信息，生产环境默认关闭 | 方法入参、中间变量 |
| INFO | 正常业务流程关键节点 | 请求开始/结束、用户操作、定时任务执行 |
| WARN | 可恢复的异常，不影响主流程 | 重试成功、降级触发、缓存未命中 |
| ERROR | 影响当前请求的异常，需要关注 | 外部服务超时、数据库异常、AI 模型返回错误 |
| FATAL | 进程级不可恢复错误 | 数据库连接池耗尽、OOM、配置缺失无法启动 |

### 3.5 日志采集 Pipeline

```
业务进程 (stdout/stderr)
     │
     ▼
容器运行时日志 (/var/log/containers/*.log)
     │
     ▼
Filebeat DaemonSet
     ├── 多行合并 (Java Exception stacktrace)
     ├── JSON 解析 (decode_json_fields)
     ├── 字段 enrichment (kubernetes metadata)
     └── 过滤 (drop DEBUG level in production)
     │
     ▼
Elasticsearch (按 service+日期 分索引)
     │
     ▼
Kibana (检索、仪表盘)
```

### 3.6 Elasticsearch 索引策略

```
索引命名规则：primetop-{log_type}-{yyyy.MM.dd}

示例：
- primetop-business-2026.05.19
- primetop-access-2026.05.19
- primetop-ai-call-2026.05.19
- primetop-audit-2026.05.19

ILM（Index Lifecycle Management）策略：
- hot phase:  0-7天，滚动索引，每50GB或1天 rollover
- warm phase: 7-30天，force merge，shrink 到 1 shard，标记 read_only
- cold phase: 30-90天，迁移到冷节点（ searchable snapshot 可选）
- delete phase: 90天后删除（审计日志除外，1年后删除）
```

**MDC 注入（Filter/Interceptor）:**
```java
@Component
public class TraceFilter implements Filter {

    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest httpReq = (HttpServletRequest) req;
        
        // 从网关透传的 header 中提取
        String traceId = httpReq.getHeader("X-Trace-Id");
        String requestId = httpReq.getHeader("X-Request-Id");
        String userId = httpReq.getHeader("X-User-Id");

        if (traceId == null) traceId = UUID.randomUUID().toString();
        if (requestId == null) requestId = UUID.randomUUID().toString();

        MDC.put("trace_id", traceId);
        MDC.put("span_id", UUID.randomUUID().toString().substring(0, 16));
        MDC.put("request_id", requestId);
        MDC.put("user_id", userId != null ? userId : "");

        try {
            chain.doFilter(req, res);
        } finally {
            MDC.clear();
        }
    }
}
```

**业务日志工具类:**
```java
@Slf4j
public class BizLogger {

    /**
     * 记录 AI 模型调用日志
     */
    public static void logModelCall(String provider, String model, String scene,
                                     int inputTokens, int outputTokens,
                                     long durationMs, String status,
                                     String errorCode, String errorMessage) {
        Map<String, Object> tags = Map.of(
            "model_provider", provider,
            "model_name", model,
            "scene", scene,
            "input_tokens", inputTokens,
            "output_tokens", outputTokens,
            "status", status
        );

        StructuredArguments[] kvTags = tags.entrySet().stream()
            .map(e -> kv(e.getKey(), e.getValue()))
            .toArray(StructuredArguments[]::new);

        if ("success".equals(status)) {
            log.info("Model invocation completed", kvTags);
        } else {
            log.error("Model invocation failed: {}", errorMessage,
                kv("error_code", errorCode), kv("error_message", errorMessage));
        }
    }

    /**
     * 记录业务操作日志
     */
    public static void logAction(String module, String action, long durationMs,
                                  Object... keyValues) {
        StructuredArguments[] args = new StructuredArguments[keyValues.length / 2];
        for (int i = 0; i < keyValues.length; i += 2) {
            args[i / 2] = kv((String) keyValues[i], keyValues[i + 1]);
        }
        log.info("Action completed: {}.{}", module, action, args);
    }
}
```

#### 自定义指标埋点

```java
@Component
public class AIMetrics {

    private final Counter modelCallCounter;
    private final Histogram modelCallDuration;
    private final Counter tokenCounter;

    public AIMetrics(MeterRegistry registry) {
        this.modelCallCounter = Counter.builder("primetop.ai.model.call")
            .description("AI model call count")
            .tag("service", "ai-service")
            .register(registry);

        this.modelCallDuration = Histogram.builder("primetop.ai.model.call.duration")
            .description("AI model call latency")
            .tag("service", "ai-service")
            .publishPercentileHistogram()
            .register(registry);

        this.tokenCounter = Counter.builder("primetop.ai.model.tokens")
            .description("AI model token usage")
            .tag("service", "ai-service")
            .register(registry);
    }

    public void recordModelCall(String provider, String model, String scene,
                                 String status, long durationMs,
                                 int inputTokens, int outputTokens) {
        modelCallCounter.increment();
        modelCallDuration.record(Duration.ofMillis(durationMs));
        tokenCounter.increment(inputTokens + outputTokens);
    }
}
```

## 5. 全链路追踪

### 5.1 追踪架构

```
客户端 APP
  │
  │ HTTP (自动注入 traceparent header)
  ▼
API Gateway (OpenTelemetry Instrumentation)
  │ 生成 root span: HTTP GET /api/v1/ai/chat
  │ context propagation: inject traceparent header
  ▼
PrimeTop Server
  │ span: AIController.chat()
  │   span: PromptEngine.render()
  │   span: ModelDispatcher.dispatch()
  │     span: RAGService.retrieve() ──► Milvus (DB client span)
  │     span: ProviderClient.call() ──► DeepSeek API (HTTP client span)
  │   span: SafetyFilter.check()
  │   span: UsageRecorder.record()
  │   span: MySQL insert (DB client span)
  ▼
响应返回
```

### 5.2 Trace 上下文传播

跨服务/跨组件通过 W3C `traceparent` Header 传播：

```
traceparent: 00-abc123def45678901234567890123456-1234567890123456-01
             │  │                       │                │         │
             │  trace-id (32 hex)       │                │      sampled
          version                   span-id (16 hex)    flags
```

### 5.3 关键 Span 定义

| Span 名称 | 类型 | 必填属性 | 说明 |
|------------|------|----------|------|
| `HTTP {method} {path}` | Server | http.method, http.status_code, http.url | HTTP 请求入口 |
| `ai.chat` | Internal | ai.scene, ai.model, ai.prompt_tokens | AI 对话处理 |
| `ai.model.invoke` | Client | ai.provider, ai.model, ai.status, ai.duration_ms | 模型 API 调用 |
| `ai.rag.retrieve` | Internal | rag.query, rag.top_k, rag.hit_count | RAG 检索 |
| `db.query` | Client | db.system, db.statement, db.operation | 数据库查询 |
| `cache.{get\|set}` | Client | cache.key, cache.hit, cache.ttl | 缓存操作 |
| `mq.publish` | Producer | mq.topic, mq.partition | 消息发送 |
| `ocr.recognize` | Client | ocr.provider, ocr.status, ocr.page_count | OCR 识别 |

### 5.5 代码集成

```java
// OpenTelemetry SDK 自动配置（application.yml）
management:
  tracing:
    sampling:
      probability: 0.1  # 默认 10% 采样率
  otlp:
    tracing:
      endpoint: http://otel-collector:4317/v1/traces

// 手动创建 Span（用于关键业务逻辑）
@Inject Tracer tracer;

public AIResponse chat(AIRequest request) {
    Span span = tracer.spanBuilder("ai.chat")
        .setAttribute("ai.scene", request.getScene())
        .setAttribute("user.grade", request.getGrade())
        .startSpan();
    
    try (Scope scope = span.makeCurrent()) {
        // RAG 检索
        Span ragSpan = tracer.spanBuilder("ai.rag.retrieve")
            .setAttribute("rag.query", request.getQuery())
            .startSpan();
        List<Document> docs = ragService.retrieve(request.getQuery(), 5);
        ragSpan.setAttribute("rag.hit_count", docs.size());
        ragSpan.end();

        // 模型调用
        Span modelSpan = tracer.spanBuilder("ai.model.invoke")
            .setAttribute("ai.provider", selectedProvider)
            .setAttribute("ai.model", selectedModel)
            .startSpan();
        AIResponse response = modelClient.invoke(prompt);
        modelSpan.setAttribute("ai.status", "success");
        modelSpan.setAttribute("ai.input_tokens", response.getInputTokens());
        modelSpan.end();
        
        return response;
    } catch (Exception e) {
        span.recordException(e);
        span.setStatus(StatusCode.ERROR, e.getMessage());
        throw e;
    } finally {
        span.end();
    }
}
```

## 6. 告警体系

### 6.1 告警分级

| 级别 | 标识 | 含义 | 响应时间 | 通知方式 |
|------|------|------|----------|----------|
| P0 | 🔴 Critical | 服务不可用，影响大量用户 | 立即（<5分钟） | 电话 + 飞书/钉钉 + 短信 |
| P1 | 🟠 High | 核心功能降级，影响部分用户 | <15分钟 | 飞书/钉钉 + 短信 |
| P2 | 🟡 Medium | 非核心功能异常或性能下降 | <1小时 | 飞书/钉钉 |
| P3 | 🔵 Low | 需关注的潜在问题 | 当日处理 | 飞书/钉钉（仅工作时间） |

## 8. 审计日志

### 8.1 审计日志范围

审计日志独立于业务日志，用于记录所有敏感操作，满足合规和可追溯要求。

| 操作类型 | 记录内容 | 示例 |
|----------|----------|------|
| 管理后台登录 | 操作人、IP、时间、结果 | 管理员 192.168.1.1 登录成功 |
| 用户数据查看 | 操作人、目标用户、字段 | 客服查看用户 U100001 手机号 |
| 内容管理操作 | 操作人、操作类型、对象 | 运营编辑上传教材章节 |
| 权限变更 | 操作人、目标、变更内容 | 超管给运营授予内容审核权限 |
| 会员权益变更 | 操作人、目标用户、变更 | 手动延长会员到期时间 |
| AI Prompt 修改 | 操作人、场景、变更前后值 | 修改「初中数学解题」Prompt |
| 数据导出 | 操作人、范围、记录数 | 导出本月注册用户列表 |
| 敏感配置修改 | 操作人、配置项、变更 | 修改模型供应商 API Key |

### 8.2 审计日志数据结构

```sql
CREATE TABLE audit_logs (
```

### 10.2 日志脱敏规则

```java
@Component
public class LogMaskingConverter implements LayoutWrappingConverter {

    // 手机号脱敏: 138****1234
    private static final Pattern PHONE = Pattern.compile("(1[3-9]\\d)\\d{4}(\\d{4})");
    // 身份证脱敏: 110***********1234
    private static final Pattern ID_CARD = Pattern.compile("(\\d{3})\\d{11}(\\d{4})");
    // 邮箱脱敏: t****@example.com
    private static final Pattern EMAIL = Pattern.compile("(\\w)\\w*(@\\S+)");

    @Override
    public String convert(ILoggingEvent event) {
        String msg = super.convert(event);
        msg = PHONE.matcher(msg).replaceAll("$1****$2");
        msg = ID_CARD.matcher(msg).replaceAll("$1***********$2");
        msg = EMAIL.matcher(msg).replaceAll("$1****$2");
        return msg;
    }
}
```
