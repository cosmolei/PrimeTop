# 客户端性能监控与用户体验度量系统 - 详细设计

## 1. 概述

### 1.1 模块定位

客户端性能监控与用户体验度量系统是 PrimeTop 的客户端可观测性基础设施，负责采集、上报、聚合和展示客户端运行时性能指标与用户体验数据。区别于服务端的「日志与监控告警体系」（关注 API 延迟、服务健康），本系统聚焦于客户端侧的性能瓶颈、崩溃、ANR、卡顿、首屏加载、交互延迟等用户可感知的质量问题。

### 1.2 设计目标

| 目标 | 指标 |
|------|------|
| 崩溃率 < 0.1% | 每日崩溃用户 / 日活 < 0.1% |
| ANR率 < 0.3% | Android 严格模式 ANR |
| 首屏加载 < 2s | P90 冷启动到首页可交互 |
| AI首Token < 3s | P90 从发送到首个Token渲染 |
| 帧率 > 55fps | 关键交互页面的P90帧率 |
| 内存稳定 | 单次会话内存增长 < 50MB |

### 1.3 与已有模块的关系

| 已有模块 | 关系 |
|----------|------|
| 日志与监控告警体系 | 服务端监控，本系统是客户端侧的补充 |
| 数据埋点与关键指标系统 | 业务埋点，本系统是技术性能埋点 |
| 错误处理与服务降级策略 | 错误处理后上报到本系统 |
| 客户端版本管理与升级策略 | 版本升级后对比性能基线 |
| 灰度发布与特性开关系统 | 灰度期间监控新版本性能指标 |

```dart
class PerfEvent {
  /// 事件唯一ID (UUID v7)
  final String eventId;
  
  /// 事件类型
  final PerfEventType type;
  
  /// 事件名称 (如 "cold_start", "page_render", "ai_first_token")
  final String name;
  
  /// 事件发生时间 (ms 精度)
  final int timestamp;
  
  /// 持续时间 (ms), 0 表示瞬时事件
  final int duration;
  
  /// 附加标签
  final Map<String, String> tags;
  
  /// 附加数值指标
  final Map<String, double> metrics;
  
  /// 设备快照 (采样, 非每次都带)
  final DeviceSnapshot? deviceSnapshot;
  
  /// 应用状态快照
  final AppStateSnapshot appState;
  
  /// 会话ID
  final String sessionId;
  
  /// 用户ID (可选, 未登录时为空)
  final String? userId;
}

/// 事件类型枚举
enum PerfEventType {

  frameRate,
```

```dart
    return StartupReport(
      totalDuration: _milestoneTimes['home_interactive'] ?? 0,
      milestones: Map.from(_milestoneTimes),
      startupType: _determineStartupType(),
    );
  }
}
```

#### 3.2.3 帧率与卡顿采集

```dart
class FrameRateCollector {
  Timer? _sampleTimer;
  final List<FrameTiming> _frameTimings = [];
  
  static const _jankThresholdMs = 16.67 * 2; // 2帧掉帧 = 卡顿
  static const _sampleInterval = Duration(seconds: 1);
  static const _reportInterval = Duration(seconds: 30);

  void start() {
    // 使用 Flutter 的 FrameTiming 回调
    WidgetsBinding.instance.addTimingsCallback(_onFrameTimings);
    _sampleTimer = Timer.periodic(_reportInterval, (_) => _report());
  }

  void _onFrameTimings(List<FrameTiming> timings) {
    _frameTimings.addAll(timings);
    
    for (final timing in timings) {
      final frameDuration = timing.totalSpan.inMilliseconds;
      if (frameDuration > _jankThresholdMs) {
        // 检测到卡顿帧
        MonitorManager.instance.track(PerfEvent(
          eventId: Uuid().v7(),
          type: PerfEventType.frameRate,
          name: 'jank_detected',
          timestamp: DateTime.now().millisecondsSinceEpoch,
          duration: frameDuration,
          tags: {
            'build_ms': timing.buildDuration.inMilliseconds.toString(),
            'raster_ms': timing.rasterDuration.inMilliseconds.toString(),
          },
          metrics: {
            'frame_ms': frameDuration.toDouble(),
            'dropped_frames': (frameDuration / 16.67).floorToDouble(),
          },
          appState: AppStateSnapshot.current(),
          sessionId: SessionManager.currentSessionId,
        ));
      }
    }
  }

  void _report() {
    if (_frameTimings.isEmpty) return;
    
    final avgFps = _calculateAvgFps();
    final p90Fps = _calculatePercentileFps(0.9);
    final jankCount = _frameTimings.where(
      (t) => t.totalSpan.inMilliseconds > _jankThresholdMs
    ).length;
    
    MonitorManager.instance.track(PerfEvent(
      eventId: Uuid().v7(),
      type: PerfEventType.frameRate,
      name: 'fps_sample',
      timestamp: DateTime.now().millisecondsSinceEpoch,
      duration: 0,
      tags: {},
      metrics: {
        'avg_fps': avgFps,
        'p90_fps': p90Fps,
        'jank_count': jankCount.toDouble(),
        'total_frames': _frameTimings.length.toDouble(),
      },
      appState: AppStateSnapshot.current(),
      sessionId: SessionManager.currentSessionId,
    ));
    
    _frameTimings.clear();
  }

  double _calculateAvgFps() {
    if (_frameTimings.isEmpty) return 0;
    final avgMs = _frameTimings.map(
      (t) => t.totalSpan.inMilliseconds
    ).reduce((a, b) => a + b) / _frameTimings.length;
    return avgMs > 0 ? 1000 / avgMs : 0;
  }

  void stop() {
    WidgetsBinding.instance.removeTimingsCallback(_onFrameTimings);
    _sampleTimer?.cancel();
  }
}
```

```dart
class CrashCollector {
  static CrashCollector? _instance;
  static CrashCollector get instance => _instance ??= CrashCollector._();
  CrashCollector._();

  void init() {
    // 1. Dart 异常捕获
    FlutterError.onError = _onFlutterError;
    
    // 2. 异步未捕获异常
    PlatformDispatcher.instance.onError = _onPlatformError;
    
    // 3. Isolate 异常 (后台 Isolate)
    Isolate.current.addErrorListener(
      RawReceivePort((dynamic error) {
        _reportCrash(
          type: 'isolate_error',
          error: error.toString(),
          stackTrace: null,
        );
      }).sendPort,
    );

    // 4. 原生崩溃 (通过 MethodChannel 桥接)
    _setupNativeCrashHandler();
  }

  void _onFlutterError(FlutterErrorDetails details) {
    // 过滤掉已知的非致命异常
    if (_isNonFatal(details)) return;
    
    _reportCrash(
      type: 'dart_exception',
      error: details.exceptionAsString(),
      stackTrace: details.stack?.toString(),
      context: details.context?.toString(),
      library: details.library,
    );
  }

  bool _onPlatformError(Object error, StackTrace stack) {
    _reportCrash(
      type: 'platform_error',
      error: error.toString(),
      stackTrace: stack.toString(),
    );
    return true; // 已处理
  }

  void _reportCrash({
    required String type,
    required String error,
    String? stackTrace,
    String? context,
    String? library,
  }) {
    final event = CrashEvent(
      eventId: Uuid().v7(),
      crashType: type,
      errorMessage: error.length > 4000 ? error.substring(0, 4000) : error,
      stackTrace: stackTrace != null 
        ? (stackTrace.length > 8000 ? stackTrace.substring(0, 8000) : stackTrace)
        : null,
      context: context,
      library: library,
      deviceSnapshot: DeviceSnapshot.current(),
      appState: AppStateSnapshot.current(),
      sessionId: SessionManager.currentSessionId,
      userId: AuthManager.currentUserId,
      timestamp: DateTime.now().millisecondsSinceEpoch,
      // 附带最近 10 条操作日志用于复现
      recentActions: UserActionLogger.getRecentActions(limit: 10),
    );
    
    // 崩溃事件立即写入本地持久化
    _persistCrashEvent(event);
    
    // 尝试立即上报
    MonitorManager.instance.trackCrash(event);
  }

  void _persistCrashEvent(CrashEvent event) {
    final dir = Directory(
      path.join(AppPaths.cacheDir, 'crash_reports')
    );
    if (!dir.existsSync()) dir.createSync(recursive: true);
    
    final file = File(
      path.join(dir.path, '${event.eventId}.json')
    );
    file.writeAsStringSync(jsonEncode(event.toJson()));
  }

  bool _isNonFatal(FlutterErrorDetails details) {
    // 过滤: 图片加载失败、布局溢出等非致命异常
    final nonFatalPatterns = [
      'Unable to load asset',
      'A RenderFlex overflowed',
      'Looking up a deactivated widget',
    ];
    return nonFatalPatterns.any(
      (p) => details.exceptionAsString().contains(p)
    );
  }
}
```

```kotlin
// NativeCrashHandler.kt
class NativeCrashHandler : Thread.UncaughtExceptionHandler {
    private val defaultHandler = Thread.getDefaultUncaughtExceptionHandler()
    
    override fun uncaughtException(thread: Thread, throwable: Throwable) {
        val crashReport = buildCrashReport(throwable)
        saveCrashReport(crashReport)
        
        // 传递给默认处理器让系统处理
        defaultHandler?.uncaughtException(thread, throwable)
    }
    
    private fun buildCrashReport(throwable: Throwable): String {
        val sw = StringWriter()
        throwable.printStackTrace(PrintWriter(sw))
        return JSONObject().apply {
            put("crash_type", "native_crash")
            put("thread_name", thread.name)
            put("error_message", throwable.message ?: "Unknown")
            put("stack_trace", sw.toString().take(8000))
            put("timestamp", System.currentTimeMillis())
            put("device_info", DeviceInfoCollector.collect().toJson())
        }.toString()
    }
    
    private fun saveCrashReport(report: String) {
        val dir = File(context.cacheDir, "native_crash_reports")
        dir.mkdirs()
        File(dir, "${System.currentTimeMillis()}.json")
            .writeText(report)
    }
}
```

```dart
class MemoryCollector {
  Timer? _monitorTimer;
  
  static const _warningThresholdMB = 300;  // 内存警告阈值
  static const _criticalThresholdMB = 500; // 临界阈值
  static const _sampleInterval = Duration(seconds: 30);

  void start() {
    _monitorTimer = Timer.periodic(_sampleInterval, (_) => _sample());
  }

  void _sample() {
    final info = ProcessInfo.currentRss; // bytes
    
    MonitorManager.instance.track(PerfEvent(
      eventId: Uuid().v7(),
      type: PerfEventType.memory,
      name: 'memory_sample',
      timestamp: DateTime.now().millisecondsSinceEpoch,
      duration: 0,
      tags: {},
      metrics: {
        'rss_mb': info / (1024 * 1024),
        'heap_mb': _getHeapSize() / (1024 * 1024),
      },
      appState: AppStateSnapshot.current(),
      sessionId: SessionManager.currentSessionId,
    ));

    // 内存预警
    final rssMB = info / (1024 * 1024);
    if (rssMB > _criticalThresholdMB) {
      MonitorManager.instance.track(PerfEvent(
        eventId: Uuid().v7(),
        type: PerfEventType.memory,
        name: 'memory_critical',
        timestamp: DateTime.now().millisecondsSinceEpoch,
        duration: 0,
        tags: {'level': 'critical'},
        metrics: {'rss_mb': rssMB},
        appState: AppStateSnapshot.current(),
        sessionId: SessionManager.currentSessionId,
      ));
      // 触发主动内存回收
      _triggerMemoryCleanup();
    }
  }

  void _triggerMemoryCleanup() {
    // 清理图片缓存
    PaintingBinding.instance.imageCache.clear();
    PaintingBinding.instance.imageCache.clearLiveImages();
    // 通知各模块释放缓存
    EventBus.instance.fire(MemoryPressureEvent());
  }
}
```

## 4. 本地缓冲与上报策略

### 4.1 EventBuffer 设计

```dart
class EventBuffer {
  /// SQLite 本地存储, 保证崩溃不丢失
  final Database _db;
  
  /// 内存缓冲区 (减少磁盘IO)
  final List<PerfEvent> _memoryBuffer = [];
  
  /// 内存缓冲区上限
  static const _memoryBufferCapacity = 50;
  
  /// 本地存储上限
  static const _maxStoredEvents = 5000;
  
  /// 单次上报上限
  static const _batchSize = 100;

  Future<void> add(PerfEvent event) async {
    // 崩溃事件立即持久化
    if (event.type == PerfEventType.crash) {
      await _persistEvents([event]);
      return;
    }
    
    _memoryBuffer.add(event);
    
    if (_memoryBuffer.length >= _memoryBufferCapacity) {
      await _flushToDisk();
    }
  }

  Future<void> _flushToDisk() async {
    if (_memoryBuffer.isEmpty) return;
    await _persistEvents(List.from(_memoryBuffer));
    _memoryBuffer.clear();
  }

  Future<void> _persistEvents(List<PerfEvent> events) async {
    await _db.transaction((txn) async {
      for (final event in events) {
        await txn.insert(
          'perf_events',
          _eventToRow(event),
          conflictAlgorithm: ConflictAlgorithm.replace,
        );
      }
    });
    
    // 超限清理: 保留最新的 _maxStoredEvents 条
    await _db.rawDelete(
      'DELETE FROM perf_events WHERE id NOT IN '
      '(SELECT id FROM perf_events ORDER BY timestamp DESC LIMIT ?)',
      [_maxStoredEvents],
    );
  }

  /// 获取待上报事件
  Future<List<PerfEvent>> getPendingEvents({int limit = _batchSize}) async {
    final rows = await _db.query(
      'perf_events',
      orderBy: 'timestamp ASC',
      limit: limit,
    );
    return rows.map(_rowToEvent).toList();
  }

  /// 删除已上报事件
  Future<void> removeEvents(List<String> eventIds) async {
    await _db.delete(
      'perf_events',
      where: 'event_id IN (${List.filled(eventIds.length, '?').join(',')})',
      whereArgs: eventIds,
    );
  }
}
```

### 4.2 上传调度器 (UploadScheduler)

```dart
class UploadScheduler {
  final EventBuffer _buffer;
  final PerfApiClient _apiClient;
  Timer? _periodicTimer;
  
  // 上报策略配置
  static const _uploadInterval = Duration(seconds: 30);
  static const _maxBatchSize = 100;
  static const _maxRetries = 3;
  static const _retryBaseDelay = Duration(seconds: 5);

  void start() {
    // 定时上报
    _periodicTimer = Timer.periodic(_uploadInterval, (_) => _upload());
    
    // 应用回到前台时立即上报
    AppLifecycle.instance.onResume.listen((_) => _upload());
    
    // 崩溃恢复后立即上报
    _reportPendingNativeCrashes();
  }

  Future<void> _upload() async {
    final events = await _buffer.getPendingEvents(limit: _maxBatchSize);
    if (events.isEmpty) return;

    // 按类型分组聚合 (减少数据量)
    final aggregated = _aggregateEvents(events);
    
    // 压缩上报
    final payload = gzip.encode(utf8.encode(jsonEncode({
      'events': aggregated.map((e) => e.toJson()).toList(),
      'device_fingerprint': DeviceFingerprint.current,
      'app_version': AppInfo.version,
      'sdk_version': '1.0.0',
    })));

    try {
      await _apiClient.uploadPerfData(payload);
      // 上报成功, 删除本地记录
      await _buffer.removeEvents(events.map((e) => e.eventId).toList());
    } catch (e) {
      // 失败重试 (下次定时器触发时自动重试)
      _incrementRetryCount(events);
    }
  }

  /// 事件聚合: 同一秒内相同类型的指标取均值/最大值
  List<PerfEvent> _aggregateEvents(List<PerfEvent> events) {
    final Map<String, List<PerfEvent>> groups = {};
    
    for (final event in events) {
      // 按秒级时间+类型+名称分组
      final key = '${event.timestamp ~/ 1000}_${event.type}_${event.name}';
      groups.putIfAbsent(key, () => []).add(event);
    }

    return groups.entries.map((entry) => _mergeGroup(entry.value)).toList();
  }

  /// 组内合并: 峰值类指标取 max, 其余取 avg + max 双指标
  PerfEvent _mergeGroup(List<PerfEvent> group) {
    final first = group.first;
    if (group.length == 1) return first;

    final mergedMetrics = <String, double>{};
    final metricKeys = group.expand((e) => e.metrics.keys).toSet();
    for (final key in metricKeys) {
      final values = group
          .map((e) => e.metrics[key])
          .whereType<double>()
          .toList();
      if (values.isEmpty) continue;
      if (key.endsWith('_max') || key.contains('peak') || key == 'jank_count') {
        mergedMetrics[key] = values.reduce((a, b) => a > b ? a : b);
      } else {
        final sum = values.reduce((a, b) => a + b);
        mergedMetrics['${key}_avg'] = sum / values.length;
        mergedMetrics['${key}_max'] = values.reduce((a, b) => a > b ? a : b);
      }
    }

    return PerfEvent(
      eventId: Uuid().v7(),
      type: first.type,
      name: first.name,
      timestamp: first.timestamp,
      duration: group.map((e) => e.duration).reduce((a, b) => a + b),
      tags: {...first.tags, 'aggregated_count': group.length.toString()},
      metrics: mergedMetrics,
      appState: first.appState,
      sessionId: first.sessionId,
    );
  }

  /// 重试计数: 超限丢弃并落日志, 防止本地积压拖垮存储
  void _incrementRetryCount(List<PerfEvent> events) {
    for (final event in events) {
      final count = (_retryCounts[event.eventId] ?? 0) + 1;
      if (count >= _maxRetries) {
        _retryCounts.remove(event.eventId);
        // G4: 放弃上报, 删除本地记录
        _buffer.removeEvents([event.eventId]);
        Log.w('PFM_UPLOAD_GIVE_UP', 'event=${event.name} retried=$_maxRetries');
      } else {
        _retryCounts[event.eventId] = count;
      }
    }
  }

  /// 启动时补报上次未发出的原生崩溃报告 (上次进程可能已崩溃)
  Future<void> _reportPendingNativeCrashes() async {
    final dir = Directory(
      path.join(AppPaths.cacheDir, 'native_crash_reports')
    );
    if (!dir.existsSync()) return;

    for (final file in dir.listSync().whereType<File>()) {
      try {
        final content = await file.readAsString();
        await _apiClient.uploadCrashData(
          gzip.encode(utf8.encode(content)),
        );
        await file.delete();
      } catch (e) {
        // 保留文件, 等待下次启动重试
        Log.w('PFM_NATIVE_CRASH_RETRY', file.uri.pathSegments.last);
      }
    }
  }

  void stop() {
    _periodicTimer?.cancel();
    // 退出前尽力完成一次上报 (不 await, 避免阻塞退出流程)
    _upload();
  }
}
```

## 5. 服务端接收与存储设计

### 5.1 Ingest Gateway

客户端上报入口，复用 API 网关鉴权（设备令牌 / 用户令牌二选一，未登录设备走设备令牌）。

```text
POST /v1/perf/ingest
Headers:
  Authorization: Bearer <device_token | user_token>
  Content-Type: application/octet-stream        # gzip 后的 JSON
  X-Client-Version: 1.4.2
  X-Sdk-Version: 1.0.0
Body (解压后):
{
  "events": [ PerfEvent, ... ],                  // ≤ 100 条/批
  "device_fingerprint": "a1b2c3...",             // 未登录幂等/去重维度
  "app_version": "1.4.2",
  "sdk_version": "1.0.0"
}
Response 200:
{
  "code": 0,
  "data": { "accepted": 98, "duplicated": 2, "rejected": 0 }
}
```

**处理管线：**

1. 鉴权：设备令牌校验（未登录场景）或用户令牌校验；失败返回 `46001`。
2. 解压与大小校验：单批解压后 > 2MB 拒绝整批，返回 `46003`。
3. 单条 Schema 校验：缺 `event_id`/`type`/`name`/`timestamp` 的条目计入 `rejected`，不拖垮整批。
4. 幂等去重：`event_id` 写入 Redis `SETNX perf:dedup:{event_id} 1 EX 86400`，已存在计 `duplicated`。
5. 崩溃类事件（`type=crash`）同步写入 `crash_reports` 表（P1 优先级，供告警秒级触发），其余写入 Kafka `perf-events`。

### 5.2 Kafka Topic 规划

| Topic | Key | 分区 | 保留 | 说明 |
|-------|-----|------|------|------|
| perf-events | device_fingerprint | 12 | 7 天 | 常规性能事件流 |
| perf-crash | user_id ?? device_fingerprint | 6 | 30 天 | 崩溃事件，独立 topic 保序消费 |

### 5.3 Flink 实时聚合

```text
perf-events → 清洗(滤除 rejected/未来时间戳) →
  ├─ 1 分钟滚动窗口: 按 (app_version, os_version, page) 聚合
  │     avg/p90/p99 时长类指标 → perf_metrics_1m
  ├─ 1 小时滚动窗口: 按 (app_version, device_model) 聚合
  │     → perf_metrics_1h (长期基线对比)
  └─ 崩溃流: crash 事件 1 分钟内同 stack_hash 计数 ≥ 50
        → 立即触发 PagerDuty (不等 Dashboard 轮询)
```

## 6. 核心流程与状态机

### 6.1 事件生命周期状态机

```text
                ┌────────────┐
                │  CAPTURED  │  (采集器产生)
                └─────┬──────┘
                      │ 崩溃事件立即持久化 (G1)
                      ▼
                ┌────────────┐   内存缓冲满 50 条
                │  BUFFERED  │──────────────────┐
                └─────┬──────┘                  ▼
                      │ flush              ┌────────────┐
                      ▼                    │ PERSISTED  │
                ┌────────────┐             └─────┬──────┘
                │ PERSISTED  │◄───────────────────┘
                └─────┬──────┘   SQLite 落盘
                      │ UploadScheduler 取批
                      ▼
                ┌────────────┐
                │ UPLOADING  │──网关 2xx──▶ ┌───────────┐──删除本地──▶ ┌──────────┐
                └─────┬──────┘              │ ACCEPTED  │              │ UPLOADED │
                      │ 失败                 └───────────┘              └──────────┘
                      ▼
              retry_count < 3
                ┌────────────┐   是
                │   FAILED   │────▶ 等待下轮重试 ──▶ UPLOADING
                └─────┬──────┘
                      │ 否 (G4)
                      ▼
                ┌────────────┐
                │  DROPPED   │──删除本地记录 + 落 warning 日志
                └────────────┘
```

**守卫规则：**

| 编号 | 规则 | 说明 |
|------|------|------|
| G1 | 崩溃/ANR 事件立即持久化 | 进程可能随后死亡，不允许驻留内存缓冲 |
| G2 | 本地存储超 5000 条丢弃最旧 | 保证磁盘占用有界，DropOldest 策略 |
| G3 | 聚合不跨 session | 同秒同类型但 session 不同的事件禁止合并，避免会话维度指标失真 |
| G4 | 单事件重试上限 3 次 | 超限放弃上报，防积压恶性循环 |
| G5 | 未登录可上报 | 以 device_fingerprint 作为去重与聚合维度，user_id 留空 |
| G6 | 聚合不合并 crash 事件 | 崩溃事件逐条保留，禁止均值化丢失现场 |
| G7 | 时间戳异常事件丢弃 | 未来时间戳（> 当前+5min）或早于 7 天前的事件直接 rejected |
| G8 | 上传中 App 退出不阻断 | `stop()` 中上传不 await，进程自然退出，下轮启动补报 |

| 事件类型 | 采样率 | 说明 |

## 9. 幂等与并发

| 场景 | 机制 |
|------|------|
| 客户端重发 | event_id（UUID v7）全局唯一；服务端 Redis SETNX 24h 去重 |
| 网关重复投递 | Kafka 消费侧按 event_id 幂等写（ReplacingMergeTree 天然去重） |
| 批次部分失败 | 已入库条目不重发：响应携带 accepted/duplicated/rejected，客户端按 event_id 全量删除已受理批（失败重试由客户端整批重发，服务端去重兜底） |
| 本地写并发 | 单写 Isolate + 内存缓冲主线程独占，无锁设计 |
| 崩溃文件重复上报 | 上报成功后才 delete 文件，失败保留 |

## 10. 错误码

本节使用 46000-46049 段（46500 归「消息与推送服务」，本文不占用；全库扫描确认 46001-46020 空闲）。

| 错误码 | 符号 | 场景 | 客户端处理 |
|--------|------|------|-----------|

| 46012 | PFM_SQLITE_CORRUPTED | 本地库损坏 | 删库重建，内存缓冲兜底 |

## 11. 降级策略

| 编号 | 触发条件 | 降级行为 | 恢复条件 |
|------|----------|----------|----------|
| D1 | Ingest Gateway 5xx 持续 3 分钟 | 客户端照常落盘，上报暂停 | 网关恢复 + 客户端心跳成功 |
| D2 | Kafka 不可用 | Gateway 落本地磁盘队列（+2h TTL），恢复后回放 | Kafka 恢复 |
| D3 | Flink Job 失败 | 跳过聚合，原始数据仍可查；Redis 实时值停更（显示 stale 标记） | Job 重启 checkpoint 恢复 |
| D4 | 单设备日预算超限 | 降采样：仅崩溃 + AI 链路 | 次日 0 点 |
| D5 | 低端机（RAM<4GB） | 关闭帧率采样与 device_snapshot，保留崩溃/AI 链路 | 不可恢复（按设备分级固定） |
| D6 | 弱网（RTT>2000ms） | 上报间隔拉长至 5 分钟，事件只落盘 | RTT 恢复正常两轮 |
| D7 | 某采集器连续崩溃 2 次 | 自动 disable 该采集器，其余采集器不受影响（采集器互相隔离） | 下个版本修复后恢复 |
| D8 | 崩溃告警风暴（同 stack_hash 10 分钟内 >200 条） | 聚合为一条「爆发中」告警 + 熔断该 stack_hash 1 小时 | 1 小时后自动解除 |

| AI 首 Token P90 | perf_metrics_1m | > 3s 持续 15 分钟 P2 |
| Ingest 5xx 率 | Gateway 自身 | > 1% 持续 5 分钟 P2 |

## 13. 合规与隐私

1. **未成年人数据最小化：** user_id 可选上报；ClickHouse 仅存 `user_id_hash`（SHA-256 + 盐），原始 user_id 不落分析库。
2. **崩溃日志脱敏：** 入库前对 `error_message`/`recent_actions` 执行正则脱敏（手机号、身份证、疑似 token 串），命中即遮蔽为 `***`。
3. **家长可控：** 家长端「隐私设置」可关闭性能采集（设备维度开关，关闭后仅保留崩溃采集——崩溃数据是稳定性必需，协议中明示）。
4. **保留期限：** 原始事件 90 天 TTL，聚合指标 1 年，崩溃报告 1 年（过期自动删除）。
5. **数据出境：** 全链路境内存储；境外 SDK（如 Firebase Crashlytics）一律不接入，崩溃采集为自研链路。
6. **recent_actions 边界：** 仅记录界面路由与操作类型，不记录输入内容、不记录截屏。

## 14. 契约约定

| 编号 | 契约 |
|------|------|
| R1 | `event_id` 为 UUID v7，客户端生成，全局唯一；服务端不得改写 |
| R2 | 服务端去重窗口 24h，窗口外重传视为新事件 |
| R3 | `tags`/`metrics` 的 key 采用 snake_case，与埋点平台命名规范一致 |
| R4 | 指标权威归属：客户端只采集上报，聚合口径一律以 Flink/ClickHouse 为准，客户端不做跨会话统计 |
| R5 | 崩溃率口径 = 当日崩溃去重设备数 / 当日活跃去重设备数，分母以埋点平台日活为准 |
| R6 | 内部查询接口仅允许运维网段 + 服务账号访问，不暴露公网 |
| R7 | 与「客户端异常监控与崩溃上报系统」的边界：Dart/原生崩溃归本文链路，业务异常（接口失败 toast）归异常监控系统，二者以 `type` 区分不重复上报 |
| R8 | 灰度期间 Dashboard 必须支持按 `app_version` 拆分对比（与「灰度发布与特性开关系统」契约） |
| R9 | 版本升级后 24h 内旧版本指标仍按原版本号归组，禁止合并 |
| R10 | 性能采集不得影响主线程：所有采集逻辑执行耗时 > 2ms 必须下沉 Isolate（接入 CI 静态检查） |

## 15. 验收场景

| 编号 | 场景 | 预期 |
|------|------|------|
| AC01 | 冷启动并等待 1 分钟 | 本地 perf_events 表出现 startup 里程碑 + fps_sample 事件 |
| AC02 | 触发一次 Dart 异常 | crash 事件立即落盘，进程存活时 30s 内上报成功 |
| AC03 | 触发原生崩溃后重启 App | 启动时补报 native_crash_reports 中文件并删除 |
| AC04 | 断网使用 10 分钟后恢复网络 | 事件无丢失按序上报，服务端 accepted 数 = 客户端发送数 |
| AC05 | 服务端返回 46002 | 客户端指数退避，事件持续落盘，恢复后补报 |
| AC06 | 本地写入 6000 条 | 库存保持 ≤5000，最旧被丢弃并计 46011 |
| AC07 | 同 event_id 重发 | 服务端计 duplicated，不重复入库 |
| AC08 | 上报内容含手机号样例 | 服务端脱敏后入库，明文不可见 |
| AC09 | 模拟采集器内部抛异常 | 该采集器自动 disable，其他采集器正常，产生 46015 事件 |
| AC10 | 低端机（4GB RAM）启动 | 帧率采样与 device_snapshot 关闭，崩溃/AI 链路正常 |
| AC11 | 单设备单日产生 2500 条事件 | 触发日预算降采样，次日恢复 |
| AC12 | Dashboard 查询崩溃率 | 数值与 Redis 实时值一致，ClickHouse 延迟 ≤ 1 分钟 |
| AC13 | 同 stack 崩溃 60 次/分钟 | 触发 PagerDuty 告警；10 分钟内 200 次触发 D8 熔断 |
| AC14 | 家长关闭性能采集 | 除 crash 外停止采集，开关状态服务端可查 |
