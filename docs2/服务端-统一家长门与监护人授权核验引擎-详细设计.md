# 统一家长门与监护人授权核验引擎 - 详细设计

> 文档版本：v1.0
> 更新日期：2026-08-15
> 上游设计：`docs/design/启硕-PrimeTop-全学段AI辅助学习软件项目设计文档.md` §8.7 安全与合规架构（未成年人保护、家长控制）、§9 界面交互设计原则（家长可控）、§11.4 商业化注意事项（未成年人产品应避免过度诱导消费）

## 1. 模块概述

### 1.1 功能定位

本引擎是平台**家长控制类操作的统一身份核验与授权网关**（Parent Gate），负责：

1. **门控策略管理**：集中定义"哪些业务操作、在什么用户画像/风险条件下、需要哪一级监护人核验"，策略后台可配置、可灰度。
2. **验证会话编排**：为一次业务操作发起验证会话，支持多种核验方式（本地 PIN、短信验证码、家长端 App 远程确认、实名强核验）及其自动降级链。
3. **授权凭证签发与校验**：验证通过后签发**用途绑定、短时效、可撤销、高风险场景一次性**的授权凭证（Grant Token），业务方在执行动作前通过 SDK/注解校验凭证。
4. **防爆破与风控联动**：PIN 猜测锁定、短信频控、异常尝试告警，尝试记录接入统一风控决策中心。
5. **合规审计**：所有门控触发、验证成败、凭证签发/使用/撤销全程留痕，满足《未成年人保护法》与苹果 Kids Category（家长门）审计要求。

### 1.2 设计背景与问题

家长门是儿童教育产品的**合规硬需求**，但当前平台处于"20+ 处引用、0 处服务端专门设计"的断裂状态：

| 引用方 | 引用内容 | 现状问题 |
| --- | --- | --- |
| 客户端-全局防误触与儿童安全交互保护机制 §4.3 | 客户端定义了"家长验证网关"交互（扫码/PIN/指纹/推送确认） | **只有交互层定义，无服务端核验协议**；指纹/扫码的信任根、凭证格式、有效期均未定义 |
| 家长中心-详细设计 §3.3/§4.3 | `parent_verify_log` 表、PIN 设置与验证、30 分钟 token | 仅覆盖"进入家长中心"单一场景；**支付、抽奖、兑换、教材切换等场景无法复用**；防爆破规则未定义 |
| 客户端-会员中心与订阅购买交互设计 | 支付前家长验证（22 处提及） | 验证方式、失败降级、防孩子代验无统一规范 |
| 服务端-运营抽奖营销引擎 | 抽奖参与需家长授权 | 引用了"家长身份"校验但无实现归属 |
| 客户端-积分商城与奖品兑换 | 实物兑换家长确认（7 处） | 收货地址保护与家长确认链路无凭证传递设计 |
| 客户端-学段年级切换与教材版本更新引导（13 处）、端到端-学段年级升迁与教材版本切换链路（12 处） | 升级/换教材需家长授权 | 各自描述流程，无统一验证 API |
| 服务端-未成年人支付风控与误充值自动识别退款引擎 | 家长授权作为风控信号 | 无上游凭证来源 |
| 服务端-未成年人数据隐私合规自动化与数据主体权利请求处理引擎 | 监护人确认（数据导出/注销/隐私请求） | 确认动作无核验强度分级 |
| 服务端-学习同伴圈层匹配与协作学习编排引擎 | 开通社交功能需家长授权 | 同上 |
| 护眼模式、AI 学习伙伴设置、学情分享可见度、亲子共学模式 | 修改设置需家长验证/确认 | 同上 |
| 防沉迷与未成年人保护机制 | 修改防沉迷设置需家长验证 | 同上 |

典型断裂场景：8 岁学生在抽奖页点击"参与"→ 客户端弹家长验证 → **服务端无 API 可调**；孩子偷看家长 PIN 后连续尝试 → **无锁定策略**；家长远程确认后 → **无标准凭证**传递给抽奖引擎证明"已授权"；审计要求提供"该笔支付经过家长核验"的证据 → **无统一留痕**。本引擎即补齐这条链路。

### 1.3 与现有系统的关系（边界划分）

| 职责 | 归属 | 说明 |
| --- | --- | --- |
| 家长门触发时的客户端交互 UI | 客户端-全局防误触与儿童安全交互保护机制 | 防误触分级矩阵（L0-L3/R1-R4）决定**何时弹**；本引擎决定**如何验、验完给什么** |
| 监护人**绑定关系**维护 | 用户服务（ParentBinding）/ 用户实名认证与未成年人身份核验服务 | 本引擎只消费绑定关系，不维护 |
| 家长 PIN 的**设置/修改/重置管理** | **本引擎**（从家长中心收敛迁移，见 §7.6） | 家长中心原 `parent_verify_log` 废弃，历史数据归档 |
| 实名认证（身份证 OCR + 三要素） | 用户实名认证与未成年人身份核验服务 | V4 强核验复用其能力，本引擎只做结果引用 |
| 短信验证码下发通道 | 统一短信验证码服务与多渠道通知发送网关 | 本引擎只做模板申请与频控参数 |
| 家长端推送触达 | 多厂商推送通道适配层 + 用户消息中心 | 远程确认通知经消息服务投递 |
| 门控策略配置 UI | 管理后台（建议挂载至"权限角色与系统安全配置工作台"） | 本引擎提供管理 API |
| 异常尝试的风险画像更新 | 统一风控决策中心与用户安全画像引擎 | 消费本引擎事件 |
| 操作留痕归档 | 审计日志与操作追溯系统 | 消费本引擎审计事件 |

### 1.4 设计目标

1. `POST /parent-gate/sessions` 发起 API P99 < 200ms（不含家长确认等待）；凭证校验（本地 JWT 验签）P99 < 5ms。
2. 家长端远程确认（V3）从发起到确认 P50 < 60s、P95 < 5min；超时默认 10 分钟。
3. 单一业务动作凭证**不可跨场景复用**（purpose 绑定），高风险动作凭证**一次性消费**，重放拦截率 100%。
4. PIN 爆破防护：单会话 5 次失败锁定该会话；单家长凭证 24h 内 10 次失败锁定 24h 并告警。
5. 门控策略变更**分钟级生效**（本地缓存 60s + 配置中心推送失效）。
6. 全链路审计留痕，支持按 `student_id + action` 检索 180 天内完整证据链。

## 2. 门控场景与核验等级体系

### 2.1 核验等级（Verify Level）

| 等级 | 名称 | 核验方式 | 信任根 | 适用 |
| --- | --- | --- | --- | --- |
| V1 | 本地 PIN | 家长在设备安全区设置的 4-6 位 PIN（服务端存加盐哈希） | 共享秘密（弱） | 低风险设置类操作、已绑定且家长不在线时的兜底 |
| V2 | 短信验证码 | 向**绑定家长的手机号**下发 6 位验证码 | 手机持有（中） | 中风险；要求家长手机不在孩子手中 |
| V3 | 家长端远程确认 | 推送至家长端 App / 家长微信服务号，家长查看**操作摘要**后点确认/拒绝 | 家长账号持有 + 知情（强） | **平台默认推荐等级**；金额/内容摘要直达家长，防孩子代验 |
| V4 | 实名强核验 | 家长身份证四要素 + 人脸活体（复用实名服务） | 法定身份（最强） | 大额/不可逆操作：账户注销、数据导出、单笔 ≥1000 元支付 |

> 设计原则：**V3 优先于 V2/V1**。V1/V2 无法证明"知情"（孩子可能偷看 PIN、持有家长手机），V3 的操作摘要让家长看到"孩子要在积分商城兑换 3D 打印机并填写收货地址"这类完整上下文，是儿童产品家长门的事实标准（对应苹果 Kids Category 对外链/购买的家长门要求）。

### 2.2 门控动作注册表（Gate Action Registry）

业务方向本引擎注册 `action`，策略表决定等级。MVP 首批注册动作与既有文档引用对齐：

| action | 场景 | 默认等级 | 引用文档 |
| --- | --- | --- | --- |
| `payment.subscribe` | 会员订阅/增值服务购买 | V3（单笔 ≥1000 元升 V4） | 客户端-会员中心与订阅购买、端到端-会员订阅与增值服务购买 |
| `payment.lottery` | 抽奖参与（消耗付费机会） | V3 | 服务端-运营抽奖营销引擎 |
| `redeem.physical` | 积分商城实物兑换 + 收货地址填写 | V3 | 客户端-积分商城与奖品兑换、服务端-实物奖品履约交付 |
| `profile.upgrade_grade` | 学段/年级升迁确认 | V3 | 服务端-用户年级升迁与学段转换、客户端-学段年级切换引导 |
| `profile.switch_textbook` | 教材版本切换 | V2 | 端到端-学段年级升迁与教材版本切换链路 |
| `control.misdediction.update` | 修改防沉迷/时长/内容范围管控 | V2 | 家长中心、防沉迷与未成年人保护机制 |
| `privacy.subject_request` | 数据导出、账户注销、隐私请求发起 | V4 | 服务端-未成年人数据隐私合规自动化 |
| `social.peer.enable` | 开通学习同伴圈/协作社交 | V3 | 服务端-学习同伴圈层匹配 |
| `report.share_scope.update` | 学情报告对外分享可见度修改 | V2 | 客户端-学情分析页面 |
| `companion.setting.update` | AI 学习伙伴角色/对话风格重大变更 | V1 | 服务端-学生AI学习伙伴角色个性化 |
| `eyecare.rule.update` | 护眼规则关闭/放宽 | V1 | 护眼模式与视觉健康管理系统 |
| `account.unbind_parent` | 解除家长绑定 | V3 | 用户服务 |

等级可被**风险因子**动态上调（见 §6.2）：近 7 天 PIN 失败 ≥3 次 → 至少 V2；风控画像高风险 → 至少 V3；设备为新登录设备 → 上调一级。

### 2.3 凭证时效与消费策略

| 策略 | 值 | 说明 |
| --- | --- | --- |
| `grant_ttl`（默认） | 300s | 验证通过到业务执行的最大间隔 |
| `grant_ttl`（`privacy.subject_request` 等 V4 动作） | 1800s | 实名流程长，放宽 |
| `single_use`（一次性消费） | 默认 true | `payment.*`、`redeem.*`、`privacy.*` 强制 true |
| `multi_use_window`（可多次使用时） | ≤ 600s 且 ≤ 3 次 | 仅 `*.update` 类低风险设置允许，如连续改多项护眼设置 |
| `confirm_window`（家长确认等待） | 600s | V3 远程确认超时 |

## 3. 数据结构设计

### 3.1 门控策略表 `pg_gate_policy`

```sql
CREATE TABLE `pg_gate_policy` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `action`          VARCHAR(64)  NOT NULL COMMENT '门控动作编码，如 payment.subscribe',
  `action_name`     VARCHAR(128) NOT NULL COMMENT '动作展示名，用于家长确认摘要',
  `default_level`   TINYINT      NOT NULL COMMENT '默认核验等级 1-4',
  `risk_boosters`   JSON         NULL COMMENT '等级上调规则数组 [{factor,addLevels}]',
  `grant_ttl_sec`   INT          NOT NULL DEFAULT 300 COMMENT '凭证有效期秒',
  `single_use`      TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '是否一次性消费 0/1',
  `max_use_count`   INT          NOT NULL DEFAULT 1 COMMENT '可重复使用时最大次数',
  `confirm_window_sec` INT       NOT NULL DEFAULT 600 COMMENT 'V3 家长确认等待窗口秒',
  `enabled`         TINYINT(1)   NOT NULL DEFAULT 1,
  `version`         INT          NOT NULL DEFAULT 1 COMMENT '策略版本，审计引用',
  `remark`          VARCHAR(255) NULL,
  `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_action` (`action`),
  KEY `idx_enabled` (`enabled`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='家长门-门控策略表';
```

### 3.2 家长凭证表 `pg_parent_credential`

收敛家长 PIN（自家长中心迁移），并扩展双因素因子：

```sql
CREATE TABLE `pg_parent_credential` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `parent_user_id`  BIGINT UNSIGNED NOT NULL COMMENT '家长账号 user_id',
  `student_user_id` BIGINT UNSIGNED NOT NULL COMMENT '针对哪个孩子的凭证（同一家长对不同孩子可独立设 PIN）',
  `pin_hash`        VARCHAR(255)  NULL COMMENT 'PIN 加盐哈希(Argon2id)，未设置则 NULL',
  `pin_salt`        VARCHAR(64)   NULL,
  `pin_set_at`      DATETIME      NULL,
  `fail_count_24h`  INT           NOT NULL DEFAULT 0 COMMENT '24h 滚动失败次数',
  `locked_until`    DATETIME      NULL COMMENT '锁定截止时间',
  `bio_enrolled`    TINYINT(1)    NOT NULL DEFAULT 0 COMMENT '是否已录入设备生物识别（仅本地生效，服务端只记状态位）',
  `status`          VARCHAR(16)   NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/DISABLED',
  `created_at`      DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`      DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_parent_student` (`parent_user_id`, `student_user_id`),
  KEY `idx_locked` (`locked_until`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='家长门-家长核验凭证表';
```

> 说明：`bio_enrolled` 仅表示"某台受控设备已开启生物识别快捷验证"。生物识别（指纹/FaceID）**不作为服务端信任根**：设备指纹（device_id）+ 家长账号登录态满足时，生物识别可作为 V1 的等价快捷方式（本地 API 返回的一次性票据需服务端二次校验，见 §6.5）。

### 3.3 验证会话表 `pg_verify_session`

```sql
CREATE TABLE `pg_verify_session` (
  `id`                 CHAR(32)     NOT NULL COMMENT '会话ID（雪花或UUID去横线）',

  `updated_at`         DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
```


### 3.5 授权凭证表 `pg_grant`

```sql
CREATE TABLE `pg_grant` (
  `id`            CHAR(32)     NOT NULL COMMENT '凭证ID（JWT jti）',
  `session_id`    CHAR(32)     NOT NULL,
  `action`        VARCHAR(64)  NOT NULL,
  `student_user_id` BIGINT UNSIGNED NOT NULL,
  `parent_user_id`  BIGINT UNSIGNED NOT NULL,
  `verify_level`  TINYINT      NOT NULL COMMENT '达成等级',
  `verify_method` VARCHAR(24)  NOT NULL,
  `single_use`    TINYINT(1)   NOT NULL DEFAULT 1,
  `use_count`     INT          NOT NULL DEFAULT 0,
  `state`         VARCHAR(16)  NOT NULL DEFAULT 'ISSUED' COMMENT 'ISSUED/CONSUMED/EXPIRED/REVOKED',
  `expires_at`    DATETIME     NOT NULL,
  `consumed_at`   DATETIME     NULL COMMENT '业务方核销时间',
  `consumed_by`   VARCHAR(64)  NULL COMMENT '核销服务名（如 lottery-engine）',
  `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_session` (`session_id`),
  KEY `idx_student_action` (`student_user_id`, `action`, `created_at`),
  KEY `idx_expires` (`expires_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='家长门-授权凭证表';
```

> JWT 内只放 `jti/action/studentUid/parentUid/lvl/exp`，家长手机号等敏感信息不入 token；服务端以 DB 行为准做撤销与消费（JWT 快速验签 + DB 状态复核双层校验）。

### 3.6 审计事件表 `pg_audit_log`

```sql
CREATE TABLE `pg_audit_log` (
  `id`           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `event_type`   VARCHAR(48) NOT NULL COMMENT 'GATE_TRIGGERED/VERIFY_SUCCESS/VERIFY_FAIL/GRANT_ISSUED/GRANT_CONSUMED/GRANT_REVOKED/LOCKED/POLICY_CHANGED',
  `student_user_id` BIGINT UNSIGNED NULL,
```

```java
public enum VerifyMethod { PIN, SMS, REMOTE_CONFIRM, REALNAME, BIO_TICKET }

}

public enum GrantState { ISSUED, CONSUMED, EXPIRED, REVOKED }
```

## 4. 核心状态机

### 4.1 验证会话状态机

```text
PENDING ──chooseMethod(PIN)──────────► VERIFYING_PIN(内存态) ──fail<5──┐
   │                                     │success                      │
   │                                     ▼                             │
   │ chooseMethod(SMS) ──► SMS_SENT ──code ok──► VERIFIED(签发凭证)     │fail≥5
   │                          │code wrong/expired──► 回 SMS_SENT ──────┤
   │ chooseMethod(REMOTE)                                     ▼        │
   │      ──► REMOTE_WAITING ──parent confirm──► VERIFIED          FAILED(终态)
   │                │parent reject──► FAILED(被拒)                  ▲
   │                │confirm_window 超时──► EXPIRED                 │
   └── any ── user cancel ──► CANCELLED                       SMS 累计错 5 次同左
```

状态迁移约束：

1. 所有迁移 CAS 更新：`UPDATE ... SET state=#{to} WHERE id=#{id} AND state=#{from}`，影响行数为 0 即并发冲突，读最新态重试或报 `110303`。
2. 仅 `PENDING/SMS_SENT/REMOTE_WAITING` 可发起**方式降级切换**（如家长端 3 分钟未响应，客户端引导切短信），切换计入 attempt 记录 `method_switch`。
3. `VERIFIED` 幂等：重复收到确认回调时，若已存在 grant 直接返回原 grant（不重复签发）。
4. 终态后同一 `biz_no` 重新发起视为**新会话**，旧会话不复活。

### 4.2 凭证状态机

```text
ISSUED ──consume(single_use)──► CONSUMED（终态）
ISSUED ──use(n<max)──────────► ISSUED（计数+1，达 max 即 CONSUMED）
ISSUED ──ttl 到期──► EXPIRED（终态，定时任务批量）
ISSUED ──revoke(家长撤回/风控/管理端)──► REVOKED（终态）
```

撤销场景：家长确认后反悔（家长端"最近授权"列表可撤回未消费凭证）、风控判定会话异常、管理端处置。撤销通过删除 Redis 标记 + 更新 DB 状态实现；已消费凭证不可撤销（业务侧走退款/逆向流程）。

## 6. 核心流程详细设计

### 6.1 发起会话流程

```text
客户端业务页 ──► POST /sessions
   │
   ├─ 1. 加载策略（本地缓存 60s）→ 不存在/禁用 → 110501（业务方未接入门控则放行并打 UNREGISTERED_ACTION 埋点）
   ├─ 2. 查 ParentBinding：无有效家长 → 返回 110301 + bindHint（客户端跳绑定引导，复用《端到端-家长绑定与管控设置》流程）
   ├─ 3. 风险上调：读风控画像 + Redis 失败计数 → 计算 requiredLevel = max(策略默认+boosters, 上调结果, 4 上限)
   ├─ 4. 多家长择一：默认最近 30 天最活跃家长；summary 中注明家长昵称
   ├─ 5. allowedMethods 裁剪：
   │      PIN 不存在 → 剔除 V1；SMS 手机号无效 → 剔除 V2；家长 7 天未活跃 → V3 降级提示
   │      若 requiredLevel=3 但只剩 V1/V2 → 返回 allowedMethods 并附 weakFallback=true（客户端提示"建议完成家长端确认"）
   ├─ 6. 写 pg_verify_session(PENDING) + 审计 GATE_TRIGGERED
   └─ 7. 返回 sessionId + 降级链；preferredMethod=REMOTE_CONFIRM 时直接推送家长端（消息服务），state→REMOTE_WAITING
```

### 6.2 风险因子与等级上调

| 因子 | 来源 | 规则 |
| --- | --- | --- |
| `pin_fail_recent` | Redis `pg:pin:fail:*` | 7 天内 ≥3 次 → 至少 V2 |
| `risk_profile_high` | 风控画像接口 | 高风险 → 至少 V3 |
| `new_device` | 设备指纹服务 | 学生新设备发起 → 上调 1 级 |
| `amount_ge_1000` | summary.amount | 单笔 ≥1000 元 → V4 |
| `action_irreversible` | 策略标记 | 强制 V4（注销/数据导出） |

### 6.3 V3 家长端远程确认流程

```text
学生端                          服务端                                家长端
  │ POST /sessions(REMOTE) ──►  创建会话
  │                             │ 推送+站内信（消息中心，标题含孩子名+动作名，正文含摘要）
  │                             │ state=REMOTE_WAITING ──────────► 收到通知
  │ GET /sessions (2s轮询) ──►  返回 REMOTE_WAITING                  │ 点开确认卡片（展示完整 summary）
  │                             │◄──── POST /parent-decision(APPROVE，家长设备) ─┤
  │                             │ 校验：家长身份✓ 绑定✓ 设备≠学生设备✓ 状态机 CAS✓
  │                             │ 签发 grant（JWT+DB），state=VERIFIED
  │ ◄── {state:VERIFIED, token} │ 发 GATE_VERIFIED 事件
```

降级与超时：`confirm_window`（默认 600s）内未响应 → `EXPIRED`；客户端可在 120s 后主动引导切换 V2。家长点拒绝 → `FAILED(REJECTED_BY_PARENT)`，24h 内同 action 重复发起 ≥3 次触发 `GATE_LOCKED` 告警并要求家长端处理（防孩子骚扰式重试）。

### 6.4 PIN 验证与防爆破（Redis Lua）

```lua
-- KEYS[1]=pg:pin:fail:{credentialId}  ARGV[1]=86400, ARGV[2]=maxDaily=10
-- 返回 {0=通过, 1=已达日限, 2=已锁定}
local fails = tonumber(redis.call('GET', KEYS[1]) or '0')
if fails >= tonumber(ARGV[2]) then return 1 end
local locked = redis.call('GET', KEYS[1]..':lockedUntil')
if locked and tonumber(locked) > tonumber(ARGV[3]) then return 2 end
return 0
```

验证失败：`INCR` + `EXPIRE`，会话内 ≥5 次失败置会话 `FAILED`；凭证 24h 累计 ≥10 次写 `locked_until=now+24h`，发布 `GATE_LOCKED`，家长端推送"PIN 疑似被尝试破解，建议重置"。锁定期间 V1 不可用，其他方式不受影响（不能锁死全部通道）。

### 6.5 设备生物识别快捷通道（BIO_TICKET）

针对"家长与孩子共用一台设备、家长就在身边"的高频低风险场景：

1. 家长在受控设备（家长账号登录过且 `bio_enrolled=1`）唤起系统生物识别。
2. 客户端本地校验通过后，用**设备内预注册的服务端公钥**对 `(ticketId, action, ts, nonce)` 签名请求 `bio-tickets/exchange`。
3. 服务端验证签名、nonce 一次性、设备与凭证绑定关系，直接签发等级 **V1 等价** grant（`verify_method=BIO_TICKET`）。
4. 票据 120s 一次性；V4 动作与风险上调场景**禁用**该通道。

### 6.6 防代验（同设备远程确认）

`parent-decision` 请求的 `device_id` 与会话发起设备相同（且非家长常用设备）时：不直接通过，改判"弱确认"，`required_level≥3` 的动作要求补 V2 短信二次确认；连续 3 次弱确认触发风控事件 `PG_SAME_DEVICE_CONFIRM`。

### 6.7 未绑定家长兜底

低学段（幼儿/小学低年级）注册强制引导绑定（见用户注册链路文档）；存量未绑定用户触发门控时返回 `110301`，客户端展示绑定引导页（二维码/邀请码），完成绑定后自动继续原业务动作（携带 `resumeContext`）。

## 7. 与业务系统集成设计

### 7.1 SDK 注解接入（推荐方式）

```java
@ParentGate(action = "payment.lottery", consume = true)
@PostMapping("/api/v1/lottery/draw")
public Result<DrawVO> draw(@RequestBody DrawReq req, @RequestHeader("X-PG-Grant") String grantToken) { ... }
```

### 7.2 集成点与调用时序约定

| 业务 | 调用时机 | consume | 备注 |
| --- | --- | --- | --- |
| 支付/订阅 | 创建订单**前** | true | grant_id 落订单扩展字段，退款风控引用 |
| 抽奖 | 参与接口前 | true | 复用风控事件做授权信号 |
| 实物兑换 | 提单前（含地址授权提示） | true | 地址保护要求写入 summary.riskNote |
| 学段升迁 | 确认弹窗点确认后调升级接口前 | false(窗口内) | 升迁确认页与文档 §13 一致 |
| 教材切换 | 同上 | false | — |
| 管控设置修改 | 保存前 | false(600s/3次) | 连续改多项不需重复验证 |
| 数据导出/注销 | 发起请求前 | true | V4，凭证 30 分钟 |
| 社交开通 | 开通前 | true | 家长可随时在家长端撤回授权并触发 GRANT_REVOKED 联动关闭 |

### 7.3 网关层联动（未接入 SDK 的存量接口）

BFF 网关维护 action → route 的映射（配置中心下发），对未携带有效凭证的请求直接拦截返回 `110302`，响应头带 `X-PG-Required-Level`，客户端据此弹家长门组件——保证**存量接口不改代码也能被门控**。

### 7.4 客户端家长门组件对接

《客户端-全局防误触与儿童安全交互保护机制》§4.3 的"家长验证网关"按下述协议对接：

- 触发：防误触分级矩阵命中 → 业务调用 `PGGateWidget.open(action, bizNo, summary)`。
- 组件内部完成：发起会话 → 方式选择 UI（按 `allowedMethods`）→ PIN 输入 / 短信填写 / 远程确认等待页（含"已发送给妈妈，等待确认"状态）→ 拿到 grantToken 回调业务。
- 失败/超时统一按 §10 错误码映射文案，不暴露内部细节。

### 7.5 与统一风控决策中心的信号约定

本引擎发布的事件经 MQ 进入风控事件总线（`RiskEvent`）：`type=PG_VERIFY_FAIL(权重+2)/PG_LOCKED(+8)/PG_SAME_DEVICE_CONFIRM(+4)/PG_VERIFIED(-1)`，纳入安全画像。家长门自身也消费画像结果用于 §6.2 上调。

### 7.6 家长中心 PIN 迁移兼容

1. 上线双写：家长中心写 PIN 时改调本引擎 API；旧表 `parent_center.parent_verify_log` 停写。
2. 存量数据迁移：`parent_center` 的 PIN 哈希字段按算法差异决定——旧实现若为弱哈希（MD5/无盐）则**不迁移、强制重置**（首次使用触发 V2 短信重置流程）；若为带盐 bcrypt 可平移到 `pg_parent_credential`。
3. 家长中心"进入家长中心"自身改为门控动作 `center.enter`（V1/V2），复用统一会话与审计。

## 8. 关键代码示例

### 8.1 会话创建（含风险上调与方法裁剪）

```java
@Service
@RequiredArgsConstructor
public class GateSessionService {

    private final GatePolicyCache policyCache;
    private final ParentBindingClient bindingClient;
    private final RiskProfileClient riskClient;
    private final PgVerifySessionMapper sessionMapper;
    private final ParentPushService pushService;
    private final PgAuditPublisher audit;

    @Transactional
    public CreateSessionVO create(long studentUid, String deviceId, CreateSessionReq req) {
        GatePolicy p = policyCache.get(req.getAction())
                .orElseThrow(() -> new BizException(110501, "动作未注册门控策略"));
        Long parentUid = bindingClient.latestActiveParent(studentUid)
                .orElseThrow(() -> new BizException(110301, "请先完成家长绑定"));

        int level = p.getDefaultLevel();
        level = Math.max(level, boostByRisk(studentUid, req));          // §6.2
        level = Math.min(level, 4);

        List<VerifyMethod> chain = trimChain(level, parentUid, studentUid);

        PgVerifySession s = PgVerifySession.builder()
                .id(IdGen.next("pgs")).action(p.getAction())
                .policyVersion(p.getVersion()).requiredLevel(level)
                .studentUserId(studentUid).parentUserId(parentUid)
                .device(deviceId).bizNo(req.getBizNo())
                .summaryJson(Jsons.write(req.getSummary()))
                .state(SessionState.PENDING)
                .expiresAt(LocalDateTime.now().plusSeconds(p.getConfirmWindowSec()))
                .build();
        sessionMapper.insert(s);
        audit.publish("GATE_TRIGGERED", s, null);

        if (req.preferRemote() && chain.contains(VerifyMethod.REMOTE_CONFIRM)) {
            s.setState(SessionState.REMOTE_WAITING);
            sessionMapper.casState(s.getId(), SessionState.PENDING, SessionState.REMOTE_WAITING);
            pushService.pushConfirm(parentUid, studentUid, s);          // 消息中心+厂商推送
        }
        return CreateSessionVO.of(s, chain);
    }
}
```

### 8.2 家长端确认（状态机 CAS + 幂等签发）

```java
@Transactional
public DecisionVO parentDecision(long parentUid, String sessionId, String deviceId, boolean approve) {
    PgVerifySession s = sessionMapper.selectById(sessionId);
    assertParentBound(parentUid, s);                                    // 绑定校验

    if (!approve) {
        sessionMapper.casState(sessionId, SessionState.REMOTE_WAITING, SessionState.FAILED);
        attemptRecorder.record(s, VerifyMethod.REMOTE_CONFIRM, "FAIL", "REJECTED_BY_PARENT", parentUid);
        return DecisionVO.failed("REJECTED_BY_PARENT");
    }
    // 防代验：同设备确认视为弱确认（§6.6）
    if (deviceId.equals(s.getDeviceId())) {
        return DecisionVO.weakConfirm(s);                               // 客户端引导补 V2
    }
    int rows = sessionMapper.casState(sessionId, SessionState.REMOTE_WAITING, SessionState.VERIFIED);
    if (rows == 0) {                                                    // 并发/重复回调
        return DecisionVO.ofExisting(grantMapper.selectBySessionId(sessionId));  // 幂等
    }
    PgGrant g = grantIssuer.issue(s, VerifyMethod.REMOTE_CONFIRM);      // JWT + DB
    attemptRecorder.record(s, VerifyMethod.REMOTE_CONFIRM, "SUCCESS", null, parentUid);
    mq.publish("parent-gate-event", GateVerified.of(s, g));
    return DecisionVO.verified(g);
}
```

### 8.3 凭证签发与原子核销

```java
public class GrantIssuer {

    public PgGrant issue(PgVerifySession s, VerifyMethod m) {
        String jti = IdGen.next("pgt");
        long ttl = policyCache.get(s.getAction()).map(GatePolicy::getGrantTtlSec).orElse(300L);
        String token = Jwts.builder()
                .id(jti)
                .claim("act", s.getAction())
                .claim("suid", s.getStudentUserId())
                .claim("puid", s.getParentUserId())
                .claim("lvl", s.getRequiredLevel())
                .claim("mth", m.name())
                .setExpiration(Date.from(Instant.now().plusSeconds(ttl)))
                .signWith(serverPrivateKey, SignatureAlgorithm.ES256)    // 非对称，网关可公钥验签
                .compact();

        PgGrant g = PgGrant.builder().id(jti).sessionId(s.getId())
                .action(s.getAction()).studentUserId(s.getStudentUserId())
                .parentUserId(s.getParentUserId()).verifyLevel(s.getRequiredLevel())
                .verifyMethod(m.name()).singleUse(policy.singleUse(s.getAction()))
                .state(GrantState.ISSUED)
                .expiresAt(LocalDateTime.now().plusSeconds(ttl)).build();
        grantMapper.insert(g);
        return g.withToken(token);
    }
}

/** 一次性核销：Redis SETNX 抢占 + DB CAS 兜底 */
public boolean consume(String jti, String action, long studentUid, String consumer) {
    Boolean first = redis.opsForValue().setIfAbsent("pg:grant:used:" + jti, consumer, ttlOf(jti));
    if (Boolean.FALSE.equals(first)) return false;
    int n = grantMapper.casConsume(jti, action, studentUid, consumer, LocalDateTime.now());
    if (n == 0) return false;   // 已撤销/过期/参数不符
    mq.publish("parent-gate-event", GrantConsumed.of(jti, action, consumer));
    return true;
}
```

### 8.4 PIN 防爆破校验

```java
public PinResult verifyPin(PgVerifySession s, String pin) {
    PgParentCredential c = credentialMapper.find(s.getParentUserId(), s.getStudentUserId());
    if (c.getLockedUntil() != null && c.getLockedUntil().isAfter(now()))
        return PinResult.locked(c.getLockedUntil());

    Long fails = redis.opsForValue().increment("pg:pin:fail:" + c.getId());
    redis.expire("pg:pin:fail:" + c.getId(), Duration.ofDays(1));
    if (fails != null && fails > 10) {                                   // 日限锁定
        credentialMapper.lock(c.getId(), now().plusHours(24));
        mq.publish("parent-gate-event", GateLocked.of(c));
        return PinResult.locked(now().plusHours(24));
    }
    if (!argon2.verify(c.getPinHash(), pin)) {
        int sessionFails = s.getFailCount() + 1;
        sessionMapper.updateFailCount(s.getId(), sessionFails);
        if (sessionFails >= 5) sessionMapper.casStateAnyTo(s.getId(), SessionState.FAILED);
        return PinResult.wrong(5 - sessionFails);
    }
    redis.delete("pg:pin:fail:" + c.getId());                            // 成功清零
    return PinResult.ok();
}
```

### 8.5 AOP 注解切面

```java
@Aspect @Component
@RequiredArgsConstructor
public class ParentGateAspect extends BaseAspect {

    private final GrantVerifier verifier;

    @Around("@annotation(parentGate)")
    public Object around(ProceedingJoinPoint pjp, ParentGate parentGate) throws Throwable {
        String token = currentHeader("X-PG-Grant");
        if (token == null) throw new BizException(110402, "缺少家长授权凭证");

        long studentUid = currentStudentUid();                          // 网关注入
        VerifyVO v = verifier.verify(token, parentGate.action(), studentUid);
        if (!v.isValid()) throw BizException.ofGrantReason(v.getReason()); // 110403-110406 映射
        if (parentGate.consume() && !verifier.consume(token, parentGate.action(), studentUid, appName()))
            throw new BizException(110405, "凭证已被使用");

        Object result = pjp.proceed();
        return result;
    }
}
```

## 10. 错误处理与错误码

沿用《服务端统一业务异常码与错误分类体系》六位编码，归属**家长服务（服务码 11）**，新增 1103xx-1106xx：

| 错误码 | 含义 | HTTP | 严重度 | 客户端处理 |
| --- | --- | --- | --- | --- |
| 110301 | 未绑定家长 | 403 | LOW | 弹绑定引导页（可恢复，绑完自动续跑原动作） |
| 110302 | 缺少/未通过门控凭证（网关拦截） | 401 | MEDIUM | 响应头读等级 → 拉起家长门组件 |
| 110303 | 会话状态冲突（并发） | 409 | LOW | 刷新会话态重试 1 次 |
| 110304 | 会话不存在或已终态 | 404 | LOW | 重新发起验证 |
| 110401 | 凭证校验失败（通用） | 401 | MEDIUM | 重新走验证流程 |
| 110402 | 业务请求缺凭证头 | 400 | LOW | 客户端检查接入 |
| 110403 | 凭证已过期 | 401 | LOW | 提示"授权已超时"，重新验证 |
| 110404 | 凭证已被撤销 | 401 | MEDIUM | 提示"家长已撤回授权" |
| 110405 | 一次性凭证重复使用 | 409 | MEDIUM | 判定重放，重新验证 + 埋点 |
| 110406 | 凭证与动作/学生不匹配 | 403 | HIGH | 拦截并上报风控（疑似凭证挪用） |
| 110501 | 动作未注册策略 | 404 | LOW | 放行 + UNREGISTERED_ACTION 埋点（灰度期） |
| 110502 | 策略配置非法 | 500 | HIGH | 告警，回退上一版本策略 |
| 110601 | PIN 已锁定 | 423 | MEDIUM | 展示解锁倒计时 + "短信重置"入口 |
| 110602 | 触发频控 | 429 | LOW | 倒计时提示 |
| 110603 | 短信验证码错误/过期 | 400 | LOW | 内联提示，剩余次数 |
| 110604 | 同设备弱确认需二次核验 | 401 | LOW | 引导补短信验证 |

## 12. 测试要点

1. **策略矩阵**：12 个首批 action × 4 等级 × 风险上调组合的穷举用例（等级计算快照测试）。
2. **状态机并发**：家长端确认与客户端超时取消并发、确认回调重复投递幂等、CAS 冲突路径。
3. **防爆破**：PIN 连续 5 次会话失败、24h 10 次日限、锁定后 V2 通道仍可用、锁定到期自动恢复。
4. **凭证安全**：一次性凭证并发消费（两请求同时核销仅一个成功）、跨 action/跨学生挪用返回 110406、过期/撤销后消费被拒、JWT 篡改签名失败。
5. **防代验**：同设备远程确认走弱确认、连续 3 次触发风控事件。
6. **兜底链路**：未绑定家长 110301 → 绑定 → resumeContext 恢复原动作；家长未装 App（推送不可达）120s 后引导短信通道。
7. **迁移**：家长中心旧 PIN 弱哈希强制重置、bcrypt 平移后旧入口不可再用。
8. **性能**：发起接口 500 QPS 压测（策略缓存命中路径）、凭证验签 10ms 内。
9. **合规审计**：全事件可按 student+action 检索串联；审计不可删除（仅归档）。
10. **儿童猜 PIN 可用性**：邀请 10 组家庭做可用性回归——孩子无法在无提示下通过 V1；家长 3 步内完成 V3 确认。

## 14. 开放问题

1. 家长使用**微信服务号**作为远程确认渠道的占比需调研——若成为主渠道，需在微信生态集成文档中补服务号模板消息的家长门卡片规范。
2. 多家长（父母双方）对同一动作给出**相反决定**时的仲裁策略：当前"先到先得 + 后到者可撤回未消费凭证"，是否需要双人共签（大额支付）待产品决策。
3. B 端学校托管场景下"家长"角色被"班主任/管理员"替代时的门控主体映射，待 B 端方案定稿后扩展 `principal_type` 字段。
4. 离线场景（无网）下低风险 V1 是否允许端侧预置凭证离线核销，涉及防回放设计，暂不做。
