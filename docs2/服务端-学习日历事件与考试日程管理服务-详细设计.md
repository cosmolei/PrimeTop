> 版本: v1.0 | 创建日期: 2026-06-05 | 状态: 初稿

## 1. 模块概述

### 1.1 功能定位

学习日历事件与考试日程管理服务是 PrimeTop **时间维度的数据中心**，负责用户个人日历事件与考试日程的全生命周期管理，同时作为其他模块产生的时间相关数据的聚合网关。

**核心职责：**

| 能力 | 说明 |
|------|------|
| 考试日程 CRUD | 用户手动创建/编辑/删除考试日程，支持设置学科、类型、重要度、提醒策略 |
| 日历事件管理 | 支持自定义学习提醒、校历事件订阅、学习计划事件自动生成 |
| 事件聚合查询 | 将分散在多模块中的时间线数据聚合为统一的日历视图 |
| 冲突检测 | 考试日程与学习计划的时间冲突检测和智能建议 |
| 提醒调度 | 考试/事件的提前提醒规则管理，驱动消息推送 |
| 家长共享 | 家长查看孩子考试日程和日历事件，支持家庭维度聚合 |
| 统计分析 | 按月/学期的考试频率、学科分布、学习密度等统计 |

**不在本服务范围内：**

| 事项 | 归属模块 |
|------|----------|
| 校历学期数据管理 | `学期与学年管理服务` |
| 学习计划生成 | `服务端-学习目标分解与个性化里程碑动态规划服务` |
| 推送消息发送 | `消息与推送服务` |
| 学习时长采集 | `学习时长统计与有效性判定引擎` |
| 打卡记录管理 | `学习习惯养成与打卡系统` |

### 1.3 术语定义

| 术语 | 含义 |
|------|------|
| CalendarEvent | 日历事件，泛指所有展示在日历上的条目 |
| ExamSchedule | 考试日程，CalendarEvent 的子类型，专指考试相关 |
| CalDay | 日历日聚合数据，包含当日所有事件的摘要和统计 |
| EventSource | 事件来源：`personal`（用户创建）、`plan`（计划生成）、`school`（校历）、`class`（教师布置）、`system`（系统生成） |
| ReminderRule | 提醒规则，定义在事件发生前多久触发提醒 |

## 2. 数据结构

### 2.1 考试日程表 `user_exam_schedules`

```sql
CREATE TABLE user_exam_schedules (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL,
    title           VARCHAR(100) NOT NULL COMMENT '考试名称，如"期中数学考试"',
    subject_code    VARCHAR(10) DEFAULT NULL COMMENT '学科编码，NULL表示综合',
    exam_date       DATE NOT NULL COMMENT '考试日期',
    exam_type       VARCHAR(20) NOT NULL COMMENT '考试类型枚举',
    scope           VARCHAR(20) NOT NULL DEFAULT 'personal' COMMENT '来源: personal/class/school/system',
    source_id       BIGINT DEFAULT NULL COMMENT '来源实体ID（班级作业ID/校历事件ID等）',
    importance      TINYINT NOT NULL DEFAULT 3 COMMENT '重要度 1-5，5最重要',
    remind_days     JSON DEFAULT NULL COMMENT '提前提醒天数，如[7,3,1]',
    notes           VARCHAR(500) DEFAULT NULL COMMENT '用户备注',
    status          VARCHAR(20) NOT NULL DEFAULT 'active' COMMENT 'active/completed/cancelled',
    completed_at    DATETIME DEFAULT NULL COMMENT '标记完成时间',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_user_date (user_id, exam_date),
    INDEX idx_user_status_date (user_id, status, exam_date),
    INDEX idx_user_type (user_id, exam_type, exam_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户考试日程';
```

### 2.2 日历事件表 `user_calendar_events`

```sql
CREATE TABLE user_calendar_events (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL,
    event_type      VARCHAR(30) NOT NULL COMMENT '事件类型枚举',
    title           VARCHAR(100) NOT NULL COMMENT '事件标题',
    description     VARCHAR(500) DEFAULT NULL COMMENT '事件描述',
    event_date      DATE NOT NULL COMMENT '事件日期',
    start_time      TIME DEFAULT NULL COMMENT '开始时间，NULL表示全天',
    end_time        TIME DEFAULT NULL COMMENT '结束时间',
    all_day         TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否全天事件',
    source_type     VARCHAR(20) NOT NULL DEFAULT 'personal' COMMENT '来源类型',
    source_id       BIGINT DEFAULT NULL COMMENT '来源实体ID',
    metadata        JSON DEFAULT NULL COMMENT '扩展元数据，按事件类型不同而不同',
    remind_minutes  JSON DEFAULT NULL COMMENT '提前提醒分钟数列表，如[1440,60]',
    color_tag       VARCHAR(10) DEFAULT NULL COMMENT '颜色标签（用户自定义）',
    status          VARCHAR(20) NOT NULL DEFAULT 'active' COMMENT 'active/completed/cancelled',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_user_date (user_id, event_date),
    INDEX idx_user_type_date (user_id, event_type, event_date),
    INDEX idx_source (source_type, source_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户日历事件';
```

### 2.3 事件类型枚举

```python
class CalendarEventType(str, Enum):
    """日历事件类型"""
    EXAM = 'exam'                    # 考试日程

    STUDY_PLAN_TASK = 'study_plan_task'            # 学习计划任务
    SCHOOL_EVENT = 'school_event'    # 校历事件（开学/放假/考试周）
    CUSTOM_REMINDER = 'custom_reminder'  # 自定义提醒
    CAMP_ACTIVITY = 'camp_activity'  # 寒暑假营地日程
    MOCK_EXAM = 'mock_exam'         # 模拟考（系统生成）
    HOMEWORK_DEADLINE = 'homework_deadline'  # 作业截止日


class ExamType(str, Enum):
    """考试类型"""
    DAILY_QUIZ = 'daily_quiz'        # 日常小测验
    UNIT_TEST = 'unit_test'          # 单元测试
    MIDTERM = 'midterm'              # 期中考试
    FINAL = 'final'                  # 期末考试
    MONTHLY = 'monthly'              # 月考
    MOCK = 'mock'                    # 模拟考试
    ZHONGKAO = 'zhongkao'            # 中考
    GAOKAO = 'gaokao'                # 高考
    ENTRANCE = 'entrance'            # 入学考试
    OTHER = 'other'                  # 其他


class EventSource(str, Enum):
    """事件来源"""
    PERSONAL = 'personal'   # 用户手动创建
    PLAN = 'plan'           # 学习计划自动生成
    SCHOOL = 'school'       # 校历同步
    CLASS = 'class'         # 教师/班级布置

    MOCK_EXAM = 'mock_exam' # 考试模拟模块生成
```

```python
# ─── 日聚合摘要缓存 ───
# Key:   calendar:day:{user_id}:{yyyy-MM-dd}
# Type:  Hash
# TTL:   7 天
# Fields:
#   study_duration_sec  - 有效学习时长(秒)

#   checkin_done        - 是否打卡 (0/1)
#   exam_count          - 考试数量
#   event_ids           - 事件ID列表 (JSON array)
#   plan_task_total     - 计划任务总数
#   plan_task_done      - 已完成计划任务数

CALENDAR_DAY_KEY = "calendar:day:{user_id}:{date}"

# ─── 月度概览缓存 ───
# Key:   calendar:month:{user_id}:{yyyy-MM}
# Type:  Hash
# TTL:   30 天
# Fields:
#   total_study_sec     - 月总学习时长
#   total_questions     - 月总答题数
#   total_checkin_days  - 打卡天数
#   exam_count          - 考试次数
#   active_days         - 活跃天数

CALENDAR_MONTH_KEY = "calendar:month:{user_id}:{month}"

# ─── 即将到来的考试缓存 ───
# Key:   calendar:upcoming_exams:{user_id}
# Type:  Sorted Set (score=exam_date的timestamp)
# TTL:   24 小时
# Member: JSON序列化的考试摘要

CALENDAR_UPCOMING_KEY = "calendar:upcoming_exams:{user_id}"
```

## 3. API 接口设计

### 3.1 考试日程 API

#### 3.1.1 创建考试日程

```
POST /api/v1/calendar/exams
```

**请求体：** `CreateExamScheduleRequest`

```json
{
  "title": "期中数学考试",
  "subjectCode": "MATH",
  "examDate": "2026-07-15",
  "examType": "midterm",
  "importance": 4,
  "remindDays": [7, 3, 1],
  "notes": "第三章到第六章"
}
```

**响应：** `ExamScheduleDTO` (201)

**业务规则：**
1. `examDate` 不得早于当天（已过期考试不允许创建，除非 scope=system）
2. 单用户同一天同类型同学科的考试最多 3 条（防误操作）
3. `remindDays` 中的值须为正整数且 ≤ 30
4. 自动创建对应的 `calendar_events` 记录（`event_type=exam`）
5. 根据 `remindDays` 自动调度提醒任务（写入 `scheduled_reminders` 表）

**错误码：**

| HTTP | code | 说明 |
|------|------|------|
| 400 | EXAM_DATE_PAST | 考试日期不能早于今天 |
| 400 | EXAM_DUPLICATE | 同一天已存在相同考试 |
| 400 | REMIND_DAYS_INVALID | 提醒天数格式不合法 |
| 400 | IMPORTANCE_OUT_OF_RANGE | 重要度须在 1-5 之间 |

#### 3.1.2 更新考试日程

```
PUT /api/v1/calendar/exams/{examId}
```

**请求体：** `UpdateExamScheduleRequest`

**响应：** `ExamScheduleDTO` (200)

**业务规则：**
1. `scope=personal` 的日程用户可自由修改
2. `scope=class/school` 的日程仅允许修改 `remindDays`、`notes`、`importance`，不允许改 `title`、`examDate`
3. 修改 `examDate` 或 `remindDays` 时，需重新调度提醒任务
4. `status` 变更为 `completed` 或 `cancelled` 时，取消未触发的提醒

#### 3.1.3 删除考试日程

```
DELETE /api/v1/calendar/exams/{examId}
```

**响应：** 204 No Content

**业务规则：**
1. `scope=personal` 可直接删除
2. `scope=class/school` 不允许删除，只能 `status→cancelled`
3. 删除时同步删除关联的 `calendar_events` 记录
4. 取消所有未触发的提醒任务

#### 3.1.4 查询考试日程列表

```
GET /api/v1/calendar/exams?startDate={}&endDate={}&examType={}&status={}&page={}&size={}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| startDate | date | 是 | 查询起始日期 |
| endDate | date | 是 | 查询结束日期（跨度 ≤ 365 天） |
| examType | string | 否 | 考试类型过滤 |
| subjectCode | string | 否 | 学科过滤 |
| status | string | 否 | 默认 active |
| page | int | 否 | 默认 1 |
| size | int | 否 | 默认 20, max 100 |

**响应：**

```json
{
  "items": [ExamScheduleDTO],
  "total": 15,
  "page": 1,
  "size": 20
}
```

#### 3.1.5 获取即将到来的考试

```
GET /api/v1/calendar/exams/upcoming?days={30}
```

**响应：** `list[UpcomingExamDTO]`

**缓存策略：** 优先从 Redis `calendar:upcoming_exams:{user_id}` 读取，miss 时从 DB 查询并回填。

#### 3.1.6 标记考试完成

```
POST /api/v1/calendar/exams/{examId}/complete
```

**请求体：**

```json
{
  "score": 92,
  "fullScore": 100,
  "feeling": "satisfied"
}
```

**业务规则：**
1. 仅 `status=active` 的考试可标记完成
2. 完成后触发学习效果分析事件（可关联后续的考点复盘）
3. 更新缓存

### 3.2 日历事件 API

#### 3.2.1 创建日历事件

```
POST /api/v1/calendar/events
```

**请求体：** `CreateCalendarEventRequest`

**业务规则：**
1. `startTime` 和 `endTime` 格式为 `HH:mm`，`endTime > startTime`
2. 同一天同一时间段冲突检测（警告但不阻止）

#### 3.2.2 更新/删除日历事件

```
PUT /api/v1/calendar/events/{eventId}
DELETE /api/v1/calendar/events/{eventId}
```

**规则与考试日程类似**：`source_type=personal` 可自由操作，其他来源受限修改。

#### 3.2.3 查询日历事件

```
GET /api/v1/calendar/events?startDate={}&endDate={}&eventType={}&page={}&size={}
```

### 3.3 日历聚合视图 API

#### 3.3.1 获取月度日历视图

```
GET /api/v1/calendar/monthly?month={2026-07}
```

**响应：** `CalendarMonthOverviewDTO`

**数据来源聚合：**

| 数据项 | 来源模块 | 获取方式 |
|--------|----------|----------|
| 每日学习时长 | 学习时长统计引擎 | Redis `calendar:day:*` 预聚合 |
| 答题数据 | 练习与测评系统 | Redis 预聚合 |
| 打卡状态 | 打卡系统 | Redis 预聚合 |
| 考试日程 | 本服务 `user_exam_schedules` | DB + Redis 缓存 |
| 日历事件 | 本服务 `user_calendar_events` | DB + Redis 缓存 |
| 计划任务完成度 | 学习规划服务 | 事件驱动更新缓存 |

**性能要求：** 月度视图接口 RT ≤ 200ms（依赖缓存命中）。

#### 3.3.2 获取单日详情

```
GET /api/v1/calendar/daily?date={2026-07-15}
```

**响应：** `CalendarDayDTO`

**包含：**
- 当日所有日历事件和考试日程
- 学习时长、答题数、正确率
- 打卡状态
- 计划任务明细和完成情况

#### 3.3.3 获取日历热力图数据

```
GET /api/v1/calendar/heatmap?startDate={}&endDate={}
```

**响应：**

```json
{
  "dates": {
    "2026-07-01": { "level": 3, "studyMinutes": 45 },
    "2026-07-02": { "level": 0, "studyMinutes": 0 },
    "2026-07-03": { "level": 5, "studyMinutes": 120 }
  }
}
```

`level` 热力等级（0-5），基于学习时长映射：
- 0: 0 分钟
- 1: 1-15 分钟
- 2: 16-30 分钟
- 3: 31-60 分钟
- 4: 61-90 分钟
- 5: >90 分钟

#### 3.3.4 家长查看孩子日历

```
GET /api/v1/calendar/family/{childUserId}/monthly?month={2026-07}
GET /api/v1/calendar/family/{childUserId}/exams/upcoming?days={30}
```

**权限校验：**
1. 请求者必须是目标孩子的已绑定家长（`parent_bindings` 表校验）
2. 返回数据脱敏：不展示 `notes` 字段中的敏感内容
3. 速率限制：每家长每孩子 ≤ 60 次/分钟

### 3.4 冲突检测 API

## 4. 核心业务流程

### 4.1 考试日程创建流程

```
┌─────────┐    POST /exams     ┌───────────────────┐
│  客户端   │ ───────────────▶ │ CalendarController │
└─────────┘                   └────────┬──────────┘
                                      │ 1. 参数校验
                                      ▼
                              ┌───────────────────┐
                              │  ExamScheduleService │
                              └────────┬──────────┘
                                      │ 2. 日期校验 (examDate >= today)
                                      │ 3. 重复检测
                                      ▼
                              ┌───────────────────┐
                              │    事务开始         │
                              │  a. INSERT exam    │
                              │  b. INSERT event   │
                              │  c. INSERT reminders│
                              └────────┬──────────┘
                                      │ 4. 事务提交
                                      ▼
                              ┌───────────────────┐
```

```python
class ExamScheduleService:
    def __init__(self, db: Database, cache: RedisCache, event_bus: EventBus):
        self.db = db
        self.cache = cache
        self.event_bus = event_bus

    async def create_exam(self, user_id: int, req: CreateExamScheduleRequest) -> ExamScheduleDTO:
        # 1. 校验日期
        exam_date = date.fromisoformat(req.examDate)
        if exam_date < date.today():
            raise BizError("EXAM_DATE_PAST", "考试日期不能早于今天")

        # 2. 重复检测
        existing = await self.db.fetch_val(
            """SELECT COUNT(*) FROM user_exam_schedules
               WHERE user_id = :uid AND exam_date = :date
               AND subject_code <=> :subj AND exam_type = :type AND status = 'active'""",
            {"uid": user_id, "date": exam_date, "subj": req.subjectCode, "type": req.examType}
        )
        if existing >= 3:
            raise BizError("EXAM_DUPLICATE", "同一天同类型考试已达上限")

        # 3. 事务写入
        async with self.db.transaction() as tx:
            exam_id = await tx.execute(
                """INSERT INTO user_exam_schedules
                   (user_id, title, subject_code, exam_date, exam_type,
                    scope, importance, remind_days, notes)
                   VALUES (:uid, :title, :subj, :date, :type,
                    'personal', :imp, :remind, :notes)""",
                {"uid": user_id, "title": req.title, "subj": req.subjectCode,
                 "date": exam_date, "type": req.examType,
                 "imp": req.importance, "remind": json.dumps(req.remindDays or []),
                 "notes": req.notes}
            )

            # 3b. 创建关联日历事件
            await tx.execute(
                """INSERT INTO user_calendar_events
                   (user_id, event_type, title, event_date, all_day,
                    source_type, source_id, metadata)
                   VALUES (:uid, 'exam', :title, :date, 1,
                    'personal', :exam_id, :meta)""",
                {"uid": user_id, "title": req.title, "date": exam_date,
                 "exam_id": exam_id, "meta": json.dumps({"exam_type": req.examType})}
            )

            # 3c. 创建提醒调度记录
            if req.remindDays:
                for days in req.remindDays:
                    remind_at = datetime.combine(exam_date, time(8, 0)) - timedelta(days=days)
                    if remind_at > datetime.now():
                        await tx.execute(
                            """INSERT INTO scheduled_reminders
                               (user_id, event_type, event_id, remind_at, status)
                               VALUES (:uid, 'exam', :eid, :rat, 'pending')""",
                            {"uid": user_id, "eid": exam_id, "rat": remind_at}
                        )

        # 4. 异步更新缓存
        await self._refresh_cache(user_id, exam_date)

        # 5. 发布事件
        await self.event_bus.publish("exam.created", {
            "user_id": user_id, "exam_id": exam_id,
            "exam_date": req.examDate, "subject_code": req.subjectCode,
            "importance": req.importance
        })

        return await self._get_exam_dto(exam_id)
```

### 4.2 日历月视图聚合流程

```
客户端请求 GET /calendar/monthly?month=2026-07
        │
        ▼
┌─ Cache Layer ─────────────────────────────────┐
│  尝试读取 calendar:month:{uid}:2026-07          │
│  ├─ HIT → 直接返回（跳过DB查询）                  │
│  └─ MISS → 继续                                 │
└────────────────────────────────────────────────┘
        │
        ▼
┌─ 并行聚合 ────────────────────────────────────┐
│                                                 │
│  ┌─ Redis 批量 MGET ───────────────────────┐   │
│  │ calendar:day:{uid}:2026-07-01 ~ 31      │   │
│  │ → 学习时长/答题数/打卡/活跃数据           │   │
│  └─────────────────────────────────────────┘   │
│           │                                     │
│  ┌─ DB 查询 ───────────────────────────────┐   │
│  │ user_exam_schedules WHERE month=07      │   │
│  │ user_calendar_events WHERE month=07     │   │
│  └─────────────────────────────────────────┘   │
│           │                                     │
│  ┌─ 学习计划服务 RPC ──────────────────────┐   │
│  │ GET /plans/monthly-tasks?month=2026-07   │   │
│  └─────────────────────────────────────────┘   │
│                                                 │
└──────────────┬──────────────────────────────────┘
               │ 合并 & 组装
               ▼
┌─ 组装 CalendarMonthOverviewDTO ──┐
│  1. 合并 Redis 日聚合数据          │
│  2. 按日期关联考试和事件            │
│  3. 计算月度汇总统计               │
│  4. 回填 Redis 月度缓存 (TTL=1h)  │
│  5. 返回                          │
└───────────────────────────────────┘
```

**性能优化关键点：**

1. **Redis Pipeline**：31 个 `calendar:day:*` key 通过 Pipeline 批量获取，避免 31 次网络往返
2. **DB 单查询**：考试和事件各一条 SQL 查出全月数据，在内存中按日期分组
3. **计划数据降级**：学习计划服务不可用时，返回已有数据，`planTaskTotal/planTaskDone` 字段置为 null
4. **缓存回填**：首次查询后写入月度缓存，后续请求直接走缓存

```python
class CalendarAggregationService:
    async def get_monthly_view(self, user_id: int, month: str) -> CalendarMonthOverviewDTO:
        # 1. 尝试缓存
        cached = await self.cache.hgetall(f"calendar:month:{user_id}:{month}")
        if cached:
            return CalendarMonthOverviewDTO.from_cache(cached)

        year, mon = map(int, month.split('-'))
        start_date = date(year, mon, 1)
        end_date = date(year, mon, calendar.monthrange(year, mon)[1])

        # 2. Redis Pipeline 批量获取日聚合
        day_keys = [f"calendar:day:{user_id}:{start_date + timedelta(days=d)}"
                    for d in range((end_date - start_date).days + 1)]
        day_data = await self.cache.pipeline_mget(day_keys)

        # 3. DB 查询考试和事件
        exams = await self.db.fetch_all(
            """SELECT * FROM user_exam_schedules
               WHERE user_id = :uid AND exam_date BETWEEN :sd AND :ed AND status = 'active'""",
            {"uid": user_id, "sd": start_date, "ed": end_date}
        )
        events = await self.db.fetch_all(
            """SELECT * FROM user_calendar_events
               WHERE user_id = :uid AND event_date BETWEEN :sd AND :ed AND status = 'active'""",
            {"uid": user_id, "sd": start_date, "ed": end_date}
        )

        # 4. 学习计划数据（容错）
        plan_data = {}
        try:
            plan_data = await self.plan_service.get_monthly_tasks(user_id, month)
        except ServiceUnavailable:
            pass  # 降级返回

        # 5. 组装
        result = self._assemble_month_view(
            user_id, start_date, end_date,
            day_data, exams, events, plan_data
        )

        # 6. 缓存回填
        await self.cache.hmset(
            f"calendar:month:{user_id}:{month}",
            result.to_cache_dict(),
            ttl=3600  # 1小时
        )

        return result
```

```python
class ExamReminderJob(CronJob):
    """每分钟扫描待发送的考试提醒"""

    async def execute(self):
        now = datetime.now()
        reminders = await self.db.fetch_all(
            """SELECT r.*, e.title, e.subject_code, e.exam_date, e.exam_type,
                      e.importance, u.device_token, u.settings
               FROM scheduled_reminders r
               JOIN user_exam_schedules e ON r.event_id = e.id
               JOIN users u ON r.user_id = u.id
               WHERE r.status = 'pending'
                 AND r.remind_at <= :now
                 AND e.status = 'active'
               ORDER BY r.remind_at ASC
               LIMIT 500""",
            {"now": now}
        )

        for reminder in reminders:
            try:
                # 计算距离天数
                days_until = (reminder.exam_date - now.date()).days
                template = REMIND_TEMPLATES.get(days_until, REMIND_TEMPLATES[0])

                subject_name = SUBJECT_NAMES.get(reminder.subject_code, "")
                content = template.format(subject=subject_name, title=reminder.title)

                # 调用推送服务
                await self.push_service.send(
                    user_id=reminder.user_id,
                    push_type="exam_reminder",
                    title="考试提醒",
                    content=content,
                    deep_link=f"primetop://exam/preparation/{reminder.event_id}",
                    device_token=reminder.device_token
                )

                # 更新状态
                await self.db.execute(
                    "UPDATE scheduled_reminders SET status = 'sent', sent_at = :now WHERE id = :id",
                    {"now": now, "id": reminder.id}
                )
            except Exception as e:
                await self.db.execute(
                    """UPDATE scheduled_reminders
                       SET status = 'failed', retry_count = retry_count + 1,
                           last_error = :err, next_retry_at = :nra
                       WHERE id = :id""",
                    {"err": str(e), "nra": now + timedelta(minutes=5), "id": reminder.id}
                )
```

### 8.2 缓存失效策略

| 触发事件 | 失效范围 | 失效方式 |
|----------|----------|----------|
| 创建/更新/删除考试日程 | `calendar:day:{uid}:{date}` + `calendar:month:{uid}:{month}` + `calendar:upcoming_exams:{uid}` | DEL + 延迟双删 |

```python
async def _invalidate_cache(self, user_id: int, event_date: date):
    """延迟双删：先删 → 等 500ms → 再删"""
    day_key = f"calendar:day:{user_id}:{event_date.isoformat()}"
    month_key = f"calendar:month:{user_id}:{event_date.strftime('%Y-%m')}"

    await self.cache.delete(day_key, month_key)
    await asyncio.sleep(0.5)
    await self.cache.delete(day_key, month_key)

    # 即将到来的考试缓存也需失效
    await self.cache.delete(f"calendar:upcoming_exams:{user_id}")
```

## 10. 错误处理

### 10.1 业务异常码

| 错误码 | HTTP | 说明 | 处理建议 |
|--------|------|------|----------|
| `EXAM_DATE_PAST` | 400 | 考试日期不能早于今天 | 前端提示用户修正日期 |
| `EXAM_DUPLICATE` | 400 | 同一天同类型考试已达上限 | 前端展示已有考试列表 |
| `EXAM_NOT_FOUND` | 404 | 考试日程不存在 | 引导用户刷新 |
| `EXAM_SCOPE_FORBIDDEN` | 403 | 无权修改该来源的考试日程 | 提示仅可修改提醒设置 |
| `EVENT_DATE_RANGE_EXCEED` | 400 | 查询日期跨度超过限制 | 限制前端日期选择器 |
| `REMIND_DAYS_INVALID` | 400 | 提醒天数格式不合法 | 前端校验 |
| `IMPORTANCE_OUT_OF_RANGE` | 400 | 重要度须在 1-5 | 前端下拉限制 |
| `PARENT_NOT_BOUND` | 403 | 家长未绑定该学生 | 引导绑定流程 |
| `PLAN_SERVICE_UNAVAILABLE` | 200 | 计划服务不可用（降级） | 返回部分数据 |
| `CACHE_BUILD_FAILED` | 200 | 缓存构建失败（降级） | 直接返回 DB 数据 |

### 10.2 降级策略

```
请求进入
    │
    ├── 缓存层异常 → 降级到 DB 直接查询
    │   └── DB 也异常 → 返回 503 + 客户端使用本地缓存
    │
    ├── 学习计划服务不可用 → plan 相关字段返回 null
    │   └── 客户端隐藏计划任务区域
    │
    ├── 学习时长服务不可用 → study_duration_sec = null
    │   └── 客户端展示"暂无数据"
    │
    └── 推送服务不可用 → 提醒状态标记为 failed
        └── 等待推送服务恢复后重试
```

### 10.3 数据一致性保障

| 场景 | 风险 | 保障措施 |
|------|------|----------|
| 考试日程与日历事件不一致 | 事务部分成功 | 同事务写入，失败全部回滚 |
| 缓存与 DB 不一致 | 并发写入 | 延迟双删 + 定时刷新 |
| 提醒重复发送 | 任务重复调度 | `scheduled_reminders` 行级锁 + 幂等键 |
| 家长看到过期数据 | 缓存未及时更新 | 家长请求强制刷新当天缓存 |

## 12. 数据库索引补充

```sql
-- 考试日程表补充索引
ALTER TABLE user_exam_schedules
    ADD INDEX idx_user_exam_type_date (user_id, exam_type, exam_date),
    ADD INDEX idx_scope_source (scope, source_id),
    ADD INDEX idx_importance_date (user_id, importance DESC, exam_date);

-- 日历事件表补充索引
ALTER TABLE user_calendar_events
    ADD INDEX idx_user_event_date (user_id, event_date, event_type),
    ADD INDEX idx_source_lookup (source_type, source_id, user_id);

-- 提醒调度表
CREATE TABLE scheduled_reminders (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL,
    event_type      VARCHAR(30) NOT NULL COMMENT '触发源类型: exam/event',
    event_id        BIGINT NOT NULL COMMENT '关联的事件ID',
    remind_at       DATETIME NOT NULL COMMENT '预定提醒时间',
    status          VARCHAR(20) NOT NULL DEFAULT 'pending' COMMENT 'pending/sending/sent/failed/cancelled',
    retry_count     TINYINT NOT NULL DEFAULT 0 COMMENT '重试次数',
    max_retries     TINYINT NOT NULL DEFAULT 3,
    last_error      VARCHAR(500) DEFAULT NULL,
    next_retry_at   DATETIME DEFAULT NULL,
    sent_at         DATETIME DEFAULT NULL,
    idempotency_key VARCHAR(64) NOT NULL COMMENT '幂等键: {event_type}:{event_id}:{remind_at_hash}',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE INDEX uk_idempotency (idempotency_key),
    INDEX idx_pending_time (status, remind_at),
    INDEX idx_user_event (user_id, event_type, event_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='提醒调度记录';
```
