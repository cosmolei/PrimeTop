# 服务端-统一短链服务与深链接跳转编排引擎 - 详细设计

## 1. 模块概述

### 1.1 背景与目标

PrimeTop 产品中存在大量"分享"场景：学习报告分享、邀请好友、运营活动推广、课程内容分享、推送通知跳转等。这些场景均需要一个统一的短链服务来：

1. **生成短链**：将冗长的业务 URL（含查询参数）转化为简短易传播的短码 URL
2. **跳转编排**：根据访问设备（iOS / Android / Web / 微信）、用户登录状态、App 安装状态，智能编排跳转目标
3. **深链接解析**：将短码还原为 App 内 Deep Link / Universal Link / App Link 路径，实现"点击直达指定页面"
4. **归因追踪**：记录短链的访问、跳转、App 唤起、安装转化等全链路数据，为运营分析和裂变效果评估提供依据

### 1.2 功能范围

| 功能 | 说明 |
|------|------|
| 短链生成 | 根据业务方传入的目标 URL + 扩展参数，生成唯一短码并返回短链 URL |
| 短链解析 | 根据短码查询原始目标 URL 及业务上下文 |
| 跳转编排 | 根据设备类型、平台、登录态、安装态执行差异化跳转策略 |
| Universal Link / App Link 支持 | 为 iOS / Android 生成对应的域名 apple-app-site-association / assetlinks.json 配置 |
| Deferred Deep Link（延迟深链接） | 用户未安装 App 时，先引导至应用商店安装，安装后首次打开恢复目标页面 |
| 归因与统计 | 记录 PV / UV / 设备分布 / 跳转成功率 / App 唤起率 / 安装转化率 |
| 短链生命周期管理 | 支持过期时间、访问次数限制、启用/停用、批量失效 |
| 自定义短码 | 支持业务方指定自定义短码（如运营活动固定口令） |
| 防滥用与风控 | 短链访问频率限制、异常访问检测、恶意短码封禁 |

**上游依赖（被调用）：**
- 分享邀请服务：调用短链生成接口创建分享链接
- 运营弹窗/活动服务：调用短链生成接口创建活动推广链接

- 客户端路由系统：客户端通过短链域名解析获取 Deep Link 路径
- 数据分析平台：消费短链访问事件进行归因分析
- CDN / Nginx：处理短链域名的 HTTP 302 跳转

### 2.4 Redis 数据结构

```
# 短码 → 短链数据（热点缓存，TTL 7天，与数据库一致）
short_link:code:{short_code} → HASH {
    short_link_id, original_url, deeplink_path, fallback_url,
    biz_type, status, expire_at, max_clicks, click_count
}

# 自增序列号（用于生成短码，防碰撞）
short_link:seq → INCR (daily reset, format: {yyyyMMdd}{6位序列})

# 短码占用检查（自定义短码防重）
short_link:custom:{custom_code} → SETNX (TTL 与短链一致)

# 访问频率限制（防滥用）
short_link:ratelimit:{short_code}:{ip_hash} → INCR (TTL 60s, max 30)

# UV 去重（HyperLogLog，按天）
short_link:uv:{short_code}:{yyyyMMdd} → PFADD

# Deferred Deep Link 会话（缓存层，加速查询）
deferred_dl:{session_token} → HASH { target_deeplink, extra_data, status } (TTL 24h)
```

## 3. 短码生成算法

### 3.1 算法选择：自增序列 + Base62 编码 + 校验位

采用"发号器自增 ID + Base62 转码"方案，保证短码有序、唯一、短小、不可预测。

```
最终短码格式：[类型前缀] + [Base62(序列号)] + [校验位]

示例：
  自增序列 = 123456789
  Base62(123456789) = "dNT7"
  类型前缀 = "" (无前缀，分享类)
  校验位 = "K" (由序列号 + 秘钥 CRC32 取模 62)
  最终短码 = "dNT7K" (5位)
```

### 3.2 Base62 字符表

```java
private static final String BASE62 = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz";

public static String encodeBase62(long num) {
    if (num == 0) return "0";
    StringBuilder sb = new StringBuilder();
    while (num > 0) {
        sb.insert(0, BASE62.charAt((int) (num % 62)));
        num /= 62;
    }
    return sb.toString();
}
```

### 3.3 校验位算法

```java
/**
 * 计算校验位，防止短码被遍举和篡改
 * 算法：CRC32(序列号 + 秘钥) % 62
 */
public static char calculateChecksum(long seq, String salt) {
    long crc = CRC32.hash(seq + salt);
    return BASE62.charAt((int) (crc % 62));
}

/**
 * 组装完整短码
 */
public static String buildShortCode(long seq) {
    String base = encodeBase62(seq);
    char checksum = calculateChecksum(seq, SHORT_LINK_SALT);
    // 补齐到至少 5 位
    while (base.length() < 4) {
        base = "0" + base;
    }
    return base + checksum;
}
```

### 3.4 发号器实现（Redis + 数据库双保险）

```java
/**
 * 分布式发号器
 * 采用 Redis INCR 为主 + 数据库自增序列为兜底
 * 每日重置，序列号格式: {yyMMdd}{6位自增}，最多每日约 1 亿个
 */
@Component
public class ShortCodeIdGenerator {

    @Resource
    private StringRedisTemplate redisTemplate;

    @Resource
    private ShortLinkMapper shortLinkMapper;

    private static final String SEQ_KEY_PREFIX = "short_link:seq:";

    /**
     * 获取下一个序列号
     */
    public long nextSeq() {
        String today = LocalDate.now().format(DateTimeFormatter.ofPattern("yyMMdd"));
        String key = SEQ_KEY_PREFIX + today;
        try {
            Long seq = redisTemplate.opsForValue().increment(key);
            if (seq != null && seq > 0) {
                // 设置次日过期
                redisTemplate.expire(key, Duration.ofDays(2));
                // 将日期编码进序列号：yyMMdd * 10_000_000 + seq
                long datePart = Long.parseLong(today) * 10_000_000L;
                return datePart + seq;
            }
        } catch (Exception e) {
            log.warn("Redis 发号器异常，降级到数据库", e);
        }
        // 兜底：数据库自增序列
        return shortLinkMapper.selectNextSeq();
    }
}
```

### 3.5 短码格式总结

| 场景 | 短码长度 | 示例 | 说明 |
|------|----------|------|------|
| 常规短链 | 5-6 位 | `dNT7K` | 自增序列 Base62 + 校验位 |
| 自定义短链 | 4-16 位 | `summer2026` | 运营活动指定，需唯一性校验 |
| 临时短链 | 6 位 | `x9Km2Q` | 过期时间 ≤ 24h 的临时链接 |

### 4.3 解析短链（服务端 302 跳转）

```
GET https://s.pturl.cn/{shortCode}
```

**这是面向终端用户的 HTTP 端点**，不携带 Authorization。服务器根据短码查询原始信息，根据设备信息执行跳转。

**响应流程（见第 5 节详细设计）：**

| 场景 | HTTP 响应 | 说明 |
|------|-----------|------|
| 正常跳转（App 已安装） | `302 Location: {deeplink_scheme}://{deeplink_path}` | 通过 Universal Link / App Link 唤起 App |
| App 未安装（iOS） | `302 Location: https://apps.apple.com/app/id{APP_ID}` | 引导安装，同时记录 deferred deep link |
| App 未安装（Android） | `302 Location: https://play.google.com/store/apps/details?id={PKG}` | 引导安装 |
| App 未安装（降级 H5） | `302 Location: {fallback_url}` | 走 H5 页面展示 |
| 短链已过期 | `200 text/html: 过期提示页面` | 展示"链接已过期" |
| 短链已封禁 | `200 text/html: 违规提示页面` | 展示"链接不可用" |
| 短码不存在 | `404 text/html: 404页面` | 展示"链接不存在" |
| 微信内打开 | `302 Location: {fallback_url or H5 页面}` | 微信拦截了 Universal Link，需走 H5 引导 |

### 5.2 设备识别逻辑

```java
@Component
public class DeviceDetector {

    public enum DeviceType {
        IOS, ANDROID, WEB, WECHAT_IOS, WECHAT_ANDROID, WECHAT_OTHER
    }

    /**
     * 根据 User-Agent 识别设备类型
     */
    public DeviceType detect(String userAgent) {
        if (userAgent == null || userAgent.isEmpty()) {
            return DeviceType.WEB;
        }
        String ua = userAgent.toLowerCase();

        // 微信内嵌浏览器
        boolean isWechat = ua.contains("micromessenger");
        boolean isIOS = ua.contains("iphone") || ua.contains("ipad") || ua.contains("ipod");
        boolean isAndroid = ua.contains("android");

        if (isWechat && isIOS) return DeviceType.WECHAT_IOS;
        if (isWechat && isAndroid) return DeviceType.WECHAT_ANDROID;
        if (isWechat) return DeviceType.WECHAT_OTHER;
        if (isIOS) return DeviceType.IOS;
        if (isAndroid) return DeviceType.ANDROID;
        return DeviceType.WEB;
    }
}
```

### 5.3 跳转策略编排器

```java
@Service
public class RedirectOrchestrator {

    @Resource
    private DeviceDetector deviceDetector;

    @Resource
    private DeferredDeepLinkService deferredService;

    @Resource
    private AccessLogService accessLogService;

    @Resource
    private ShortLinkCacheService cacheService;

    /**
     * 核心跳转编排方法
     * @return ResponseEntity 包含 302 跳转或 200 页面
     */
    public ResponseEntity<?> resolve(String shortCode, HttpServletRequest request) {
        // 1. 查询短链
        ShortLinkDTO link = cacheService.getByCode(shortCode);
        if (link == null) {
            return renderNotFound();
        }

        // 2. 校验状态
        if (link.getStatus() == STATUS_BANNED) return renderBannedPage();
        if (link.getStatus() == STATUS_DISABLED) return renderDisabledPage();
        if (isExpired(link)) return renderExpiredPage();
        if (isClickLimitExceeded(link)) return renderLimitExceededPage();

        // 3. 设备识别
        String ua = request.getHeader("User-Agent");
        DeviceType device = deviceDetector.detect(ua);
        String ipHash = IpUtils.hash(IpUtils.getClientIp(request));

        // 4. 记录访问日志（异步）
        String accessId = UUID.randomUUID().toString();
        accessLogService.asyncLogAccess(shortCode, link.getId(), ipHash, ua, device, request);

        // 5. 更新统计（异步）
        cacheService.asyncIncrementPV(shortCode, ipHash);

        // 6. 根据设备执行跳转策略
        return routeByDevice(device, link, request);
    }

    private ResponseEntity<?> routeByDevice(DeviceType device, ShortLinkDTO link,
                                             HttpServletRequest request) {
        switch (device) {
            case IOS:
                return routeIOS(link, request);
            case ANDROID:
                return routeAndroid(link, request);
            case WECHAT_IOS:
            case WECHAT_ANDROID:
            case WECHAT_OTHER:
                return routeWeChat(link, device, request);
            case WEB:
            default:
                return routeWeb(link);
        }
    }

    /**
     * iOS 跳转策略：
     * 1. Universal Link 可用时，返回 Universal Link 格式 URL
     * 2. 同时记录 Deferred Deep Link（备选方案）
     * 3. 若 UA 中无 Universal Link 标记，尝试 scheme + fallback
     */
    private ResponseEntity<?> routeIOS(ShortLinkDTO link, HttpServletRequest request) {
        String universalLink = buildUniversalLink(link.getDeeplinkPath());

        // 创建 deferred session（24h有效）
        deferredService.createSession(link, request);

        // 尝试通过 Universal Link 打开 App
        // 若 Universal Link 失效，通过 JS 自动 fallback 到 App Store
        return ResponseEntity.status(302)
            .location(URI.create(universalLink))
            .build();
    }

    /**
     * Android 跳转策略：
     * 1. 优先使用 App Link (https://www.primetop.com/{deeplink})
     * 2. Fallback: Intent URI 或应用商店
     */
    private ResponseEntity<?> routeAndroid(ShortLinkDTO link, HttpServletRequest request) {
        String appLink = buildAppLink(link.getDeeplinkPath());

        // 创建 deferred session
        deferredService.createSession(link, request);

        // 使用 Intent URI 尝试唤起，失败后跳转 fallback
        String intentUri = String.format(
            "intent://%s#Intent;scheme=primetop;package=%s;S.browser_fallback_url=%s;end",
            link.getDeeplinkPath(),
            APP_PACKAGE_NAME,
            urlEncode(link.getFallbackUrl() != null ? link.getFallbackUrl() : PLAY_STORE_URL)
        );

        return ResponseEntity.status(302)
            .location(URI.create(intentUri))
            .build();
    }

    /**
     * 微信内打开策略：
     * 微信屏蔽了 Universal Link 和外部 App 唤起
     * 需要展示 H5 中间引导页，提示用户"点击右上角 → 在浏览器中打开"
     */
    private ResponseEntity<?> routeWeChat(ShortLinkDTO link, DeviceType device,
                                          HttpServletRequest request) {
        // 构建 H5 引导页 URL
        String guidePageUrl = String.format(
            "https://s.pturl.cn/guide?code=%s&path=%s",
            link.getShortCode(),
            urlEncode(link.getDeeplinkPath())
        );

        return ResponseEntity.status(302)
            .location(URI.create(guidePageUrl))
            .build();
    }

    /**
     * Web / PC 端策略：
     * 直接走 fallback_url，若无则展示 H5 预览页
     */
    private ResponseEntity<?> routeWeb(ShortLinkDTO link) {
        String target = link.getFallbackUrl() != null
            ? link.getFallbackUrl()
            : "https://www.primetop.com/share/" + link.getShortCode();
        return ResponseEntity.status(302)
            .location(URI.create(target))
            .build();
    }
}
```

## 6. Deferred Deep Link（延迟深链接）完整设计

### 6.1 场景说明

用户在微信中看到好友分享的学习报告短链 → 点击打开 H5 → 被引导到应用商店 → 下载安装 PrimeTop → **首次打开 App 时自动恢复到学习报告详情页**。

### 6.2 数据流

```
[1] 用户点击短链（微信/浏览器）
         │
         ▼
[2] 短链服务检测到 App 未安装
         │
         ▼
[3] 创建 deferred_deeplink_session
    ├── session_token (UUID)
    ├── ip_hash (访问者 IP 哈希)
    ├── user_agent 快照
    └── target_deeplink（目标页面路径）
         │
         ▼
[4] 跳转应用商店
         │
         ▼
[5] 用户安装并打开 App
         │
         ▼
[6] 客户端 SDK 调用 /api/v1/short-links/deferred/resolve
    携带: sessionToken (若有) 或 deviceId + ipHash
         │
         ▼
[7] 服务端匹配 deferred session
    ├── 精确匹配: sessionToken 直接命中
    └── 模糊匹配: ip_hash + device_type + 时间窗口(24h内)
         │
         ▼
[8] 返回 target_deeplink → 客户端执行页面跳转
         │
         ▼
[9] 标记 session 为 consumed
```

### 6.3 客户端集成代码示例（Flutter）

```dart
class DeferredDeepLinkService {
  static const _endpoint = '/api/v1/short-links/deferred/resolve';

  /// App 首次启动时调用
  Future<DeferredDeepLink?> checkDeferredDeepLink() async {
    final prefs = await SharedPreferences.getInstance();

    // 仅在安装后首次启动时检查
    final isFirstLaunch = prefs.getBool('first_launch_checked') == null;
    if (!isFirstLaunch) return null;

    prefs.setBool('first_launch_checked', true);

    // 尝试从剪贴板获取 sessionToken（H5 页面可能已写入）
    final clipboardData = await Clipboard.getData('text/plain');
    final sessionToken = _extractSessionToken(clipboardData?.text ?? '');

    final deviceId = await DeviceFingerprint.getDeviceId();
    final platform = Platform.isIOS ? 'ios' : 'android';

    try {
      final response = await ApiClient.post(_endpoint, body: {
        'sessionToken': sessionToken,
        'deviceId': deviceId,
        'platform': platform,
      });

      final data = response['data'];
      if (data != null && data['matched'] == true) {
        return DeferredDeepLink(
          deeplinkPath: data['deeplinkPath'],
          extraData: data['extraData'],
          shortCode: data['shortCode'],
          sourceUserId: data['sourceUserId'],
        );
      }
    } catch (e) {
      // Silent fail: deferred deep link 是增强体验，不应阻塞启动
      debugPrint('Deferred deep link check failed: $e');
    }

    return null;
  }

  /// App 被 Universal Link / App Link 唤起时调用
  void handleUniversalLink(Uri uri) {
    final path = uri.path;
    final queryParams = uri.queryParameters;

    // 解析路径并导航到对应页面
    AppRouter.navigateByPath(path, queryParams);
  }
}
```

### 6.4 模糊匹配规则

当用户安装后打开 App 但没有 sessionToken 时，使用模糊匹配：

```java
/**
 * Deferred Deep Link 模糊匹配
 * 规则: ip_hash + device_type 匹配，且在 24h 内创建的最近一条 session
 */
public DeferredDeepLinkDTO fuzzyMatch(String ipHash, String deviceType) {
    List<DeferredDeeplinkSession> candidates = sessionMapper.selectByFuzzyMatch(
        ipHash, deviceType,
        LocalDateTime.now().minusHours(24)
    );

    if (candidates.isEmpty()) {
        return null;
    }

    // 取最近的一条
    DeferredDeeplinkSession session = candidates.get(0);

    // 标记为已消费
    sessionMapper.markConsumed(session.getId(), deviceType);

    return DeferredDeepLinkDTO.builder()
        .deeplinkPath(session.getTargetDeeplink())
        .extraData(session.getExtraData())
        .shortCode(session.getShortCode())
        .build();
}
```

> **注意**：模糊匹配存在误差（如用户卸载重装、IP 变化等），不可作为唯一方案。仅在 sessionToken 缺失时作为补充手段。

## 7. 防滥用与风控设计

### 7.1 访问频率限制

```java
/**
 * 基于 Redis 滑动窗口的短链访问频率限制
 */
@Component
public class ShortLinkRateLimiter {

    @Resource
    private StringRedisTemplate redisTemplate;

    // 同一 IP 对同一短链: 30次/分钟
    private static final int IP_CODE_LIMIT = 30;
    private static final int IP_CODE_WINDOW = 60; // 秒

    // 同一 IP 全局: 200次/分钟
    private static final int IP_GLOBAL_LIMIT = 200;
    private static final int IP_GLOBAL_WINDOW = 60;

    /**
     * 检查频率限制
     * @return true=允许, false=拒绝
     */
    public RateLimitResult check(String shortCode, String ipHash) {
        // 短链级限制
        String codeKey = String.format("rl:code:%s:%s", shortCode, ipHash);
        int codeCount = redisTemplate.opsForValue().increment(codeKey).intValue();
        if (codeCount == 1) redisTemplate.expire(codeKey, Duration.ofSeconds(IP_CODE_WINDOW));
        if (codeCount > IP_CODE_LIMIT) {
            return RateLimitResult.blocked("该链接访问过于频繁，请稍后再试");
        }

        // 全局限制
        String globalKey = String.format("rl:global:%s", ipHash);
        int globalCount = redisTemplate.opsForValue().increment(globalKey).intValue();
        if (globalCount == 1) redisTemplate.expire(globalKey, Duration.ofSeconds(IP_GLOBAL_WINDOW));
        if (globalCount > IP_GLOBAL_LIMIT) {
            return RateLimitResult.blocked("访问频率过高，请稍后再试");
        }

        return RateLimitResult.allowed();
    }
}
```

### 7.2 异常访问检测

| 异常模式 | 检测条件 | 处置 |
|----------|----------|------|
| 短码遍历攻击 | 同一 IP 在 5 分钟内访问超过 50 个不同短码 | 临时封禁 IP 30 分钟，记录安全日志 |
| 爬虫行为 | UV/PV 比率异常（PV > 1000 且 UV < 5） | 触发人工审核短链 |
| DDoS 疑似 | 单短链 QPS > 100 | 自动降级为 H5 预览页，跳过 302 |
| 恶意举报 | 短链被多名用户举报 | 自动停用短链，触发内容审核 |

### 7.3 短链内容安全

短链目标 URL 在创建时进行安全检查：

```java
/**
 * 短链创建时的安全校验
 */
public class ShortLinkSecurityValidator {

    private static final Set<String> BLOCKED_DOMAINS = Set.of(
        "malicious-site.com", "phishing.example.net"
    );

    /**
     * 校验目标 URL 安全性
     */
    public ValidationResult validate(String originalUrl, String deeplinkPath) {
        // 1. 仅允许白名单 scheme
        if (!isAllowedScheme(originalUrl)) {
            return ValidationResult.reject("不允许的 URL 协议");
        }

        // 2. 仅允许 primetop:// 或 https://www.primetop.com 域名
        if (!isAllowedDomain(originalUrl)) {
            return ValidationResult.reject("目标域名不在允许范围");
        }

        // 3. 检查 deeplink 路径是否合法
        if (!isValidDeeplinkPath(deeplinkPath)) {
            return ValidationResult.reject("Deep Link 路径格式不合法");
        }

        // 4. 检查黑名单域名
        String host = extractHost(originalUrl);
        if (BLOCKED_DOMAINS.contains(host)) {
            return ValidationResult.reject("目标域名已被封禁");
        }

        return ValidationResult.pass();
    }
}
```

## 8. 缓存与一致性策略

### 8.1 缓存架构

```
请求 → CDN 缓存 (302 响应) → Nginx → 应用层 → Redis → MySQL
                                       ↓
                                 本地缓存 (Caffeine, 5s)
```

| 层级 | 缓存对象 | TTL | 失效策略 |
|------|----------|-----|----------|
| CDN | 302 跳转响应 | 60s | 短链停用时主动 PURGE |
| 应用本地 | ShortLinkDTO | 5s | TTL 过期 |
| Redis | ShortLinkDTO | 7天 | 主动失效（停用/过期时） |
| MySQL | 持久数据 | - | 源数据 |

### 8.2 缓存失效

```java
/**
```

### 8.3 统计数据一致性

PV / UV 统计采用"Redis 累积 + 定时同步 MySQL"方案：

```
实时统计: Redis HINCRBY + PFCOUNT
          ↓ (每 5 分钟批量同步)
准实时表: MySQL short_link 表的 pv_count / uv_count 字段
          ↓ (每天凌晨)
历史归档: short_link_access_log 月表 → 归档存储
```

## 9. 统计与归因分析

### 9.1 归因模型

```
分享者(userA) → 生成短链(shortCode=S, source_user_id=userA)
    │
    ▼
点击者(userB, ip=IP_X) → 访问短链S
    │
    ├── 已安装App → 唤起 → 回传 → 归因: userA 邀请 userB
    │
    └── 未安装 → deferred session(ip=IP_X) → 安装App
                    │
                    └── 首次打开 → 模糊匹配(ip=IP_X) → 归因: userA 拉新成功
```

### 9.2 归因事件定义

| 事件名 | 触发时机 | 关键参数 |
|--------|----------|----------|
| `short_link.click` | 短链被点击 | shortCode, bizType, channel, sourceUserId |
| `short_link.app_open` | App 被成功唤起 | shortCode, userId, deviceId |
| `short_link.install` | 首次安装后打开 App 并匹配到 deferred session | shortCode, userId, sourceUserId |
| `short_link.fallback` | 走 H5 fallback 页 | shortCode, deviceType, fallbackUrl |
| `short_link.expire` | 短链已过期被访问 | shortCode, accessedAt |

### 9.3 归因数据消费

```java
/**
 * 发送归因事件到消息队列
 */
@Component
public class AttributionEventPublisher {

    @Resource
    private RocketMQTemplate mqTemplate;

    public void publishClickEvent(ShortLinkDTO link, String ipHash,
                                   DeviceType device, String channel) {
        AttributionEvent event = AttributionEvent.builder()
            .eventType("short_link.click")
            .shortCode(link.getShortCode())
            .bizType(link.getBizType())
            .bizId(link.getBizId())
            .sourceUserId(link.getSourceUserId())
            .campaignId(link.getCampaignId())
            .channel(channel)
            .deviceType(device.name())
            .ipHash(ipHash)
            .utmSource(link.getUtmSource())
            .utmMedium(link.getUtmMedium())
            .utmCampaign(link.getUtmCampaign())
            .timestamp(Instant.now().toEpochMilli())
            .build();

        mqTemplate.asyncSend("short-link-attribution-topic", event, ...);
    }
}
```

## 14. 边界条件与注意事项

1. **短码碰撞**：发号器自增方案天然防碰撞。自定义短码需用 Redis SETNX 保证原子性占用。

2. **大量短链创建**：运营活动可能一次性生成数千条短链（如批量生成带个人标识的邀请码）。批量接口单次上限 500 条，超出需分批调用。

3. **URL 长度限制**：`original_url` 最长 2048 字符。超长 URL 应提示调用方精简参数。

4. **HTTPS 强制**：所有短链域名必须启用 HTTPS。iOS Universal Link 和 Android App Link 均要求 HTTPS。

5. **Deferred Deep Link 时间窗口**：从点击到安装后打开的有效匹配窗口为 24 小时。超过窗口无法归因。

6. **微信环境特殊性**：微信对 Universal Link 有严格限制，必须通过"右上角浏览器打开"引导。微信内分享需配合微信开放平台 JS-SDK 或小程序中转。

7. **CDN 缓存影响**：短链停用后需主动 PURGE CDN 缓存。对于已缓存的 302 响应，最多有 60 秒延迟才全局生效。

8. **跨域跳转**：短链域名 `s.pturl.cn` 和 Universal Link 域名 `www.primetop.com` 需在 apple-app-site-association 中分别配置。

9. **短链迁移**：如未来短链系统迁移域名，旧域名需保留 301 永久重定向至少 6 个月，确保历史分享链接不失效。

10. **隐私合规**：访问日志中的 IP 需脱敏（存储 ip_hash 而非明文 IP）。UV 去重使用 HyperLogLog，不存储可识别个人身份的信息。
