# 服务端-学习进度快照与历史趋势对比查询引擎-详细设计

## 1. 模块概述

### 1.1 功能定位

学习进度快照引擎负责对学生学习状态进行周期性快照采集和持久化存储，支持任意时间点的进度回溯、多时段趋势对比、进度异常检测与数据修复。该引擎是学情报告、家长周报/月报、年级升迁数据迁移、学习趋势分析等上层功能的基础数据设施。

### 1.2 核心能力

| 能力 | 说明 |
| --- | --- |
| 周期快照 | 按日/周/月自动采集学生知识掌握度、章节进度、练习正确率等核心指标 |
| 手动快照 | 关键节点（学期结束、考试前后、年级升迁前）触发手动快照 |
| 历史查询 | 查询任意历史日期的学习状态快照 |
| 趋势对比 | 对比两个时间段的学习进度变化趋势 |
| 进度回滚 | 年级升迁或数据异常时回滚到指定快照版本 |
| 快照导出 | 导出指定时间范围的快照数据用于家长报告或数据分析 |

### 1.3 与其他模块的关系

```
学习记录与进度追踪服务 ──(事件驱动)──→ 学习进度快照引擎
                                              │
                                              ├──→ 学情分析模块（趋势数据源）
                                              ├──→ 学习报告生成服务（报告数据源）
                                              ├──→ 家长中心（周报/月报数据源）
                                              ├──→ 用户年级升迁服务（迁移前快照）
                                              └──→ 数据归档与生命周期管理（冷热分离）
```

## 2. 数据结构设计

### 2.1 快照主表 `learning_snapshot`

```sql
CREATE TABLE learning_snapshot (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '快照ID',
    snapshot_id     VARCHAR(36)     NOT NULL COMMENT '快照唯一标识(UUID)',
    user_id         BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    snapshot_type   TINYINT         NOT NULL COMMENT '快照类型: 1=日快照 2=周快照 3=月快照 4=手动快照 5=关键节点快照',
    snapshot_scope  TINYINT         NOT NULL COMMENT '快照范围: 1=全学科 2=单学科 3=单章节',
    scope_ref_id    BIGINT UNSIGNED DEFAULT NULL COMMENT '范围关联ID(学科ID或章节ID)',
    snapshot_date   DATE            NOT NULL COMMENT '快照所属日期',
    snapshot_time   DATETIME(3)     NOT NULL COMMENT '快照实际采集时间',
    period_start    DATE            DEFAULT NULL COMMENT '统计周期起始(周/月快照用)',
    period_end      DATE            DEFAULT NULL COMMENT '统计周期结束(周/月快照用)',
    trigger_source  VARCHAR(64)     DEFAULT 'system' COMMENT '触发来源: system/schedule/manual/grade_migration/exam',
    version         INT             NOT NULL DEFAULT 1 COMMENT '快照数据版本(用于Schema演进)',
    status          TINYINT         NOT NULL DEFAULT 1 COMMENT '状态: 0=采集中 1=已完成 2=已归档 3=已作废',
    checksum        VARCHAR(64)     DEFAULT NULL COMMENT '数据校验和(SHA-256)',
    created_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_snapshot_id (snapshot_id),
    INDEX idx_user_date (user_id, snapshot_date),
    INDEX idx_user_type_date (user_id, snapshot_type, snapshot_date),
    INDEX idx_status_time (status, snapshot_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='学习进度快照主表';
```

### 2.2 快照汇总数据表 `learning_snapshot_summary`

存储快照采集时刻的核心汇总指标，用于快速查询和趋势对比。

```sql
CREATE TABLE learning_snapshot_summary (
    id                      BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    snapshot_id             VARCHAR(36)     NOT NULL COMMENT '关联快照ID',
    user_id                 BIGINT UNSIGNED NOT NULL COMMENT '冗余用户ID(加速查询)',
    -- 学习时长指标
    total_study_minutes     INT UNSIGNED    DEFAULT 0 COMMENT '累计学习时长(分钟)',
    period_study_minutes    INT UNSIGNED    DEFAULT 0 COMMENT '本周期学习时长(分钟)',
    daily_avg_minutes       DECIMAL(6,1)    DEFAULT 0 COMMENT '日均学习时长',
    -- 练习指标
    total_questions         INT UNSIGNED    DEFAULT 0 COMMENT '累计答题数',
    period_questions        INT UNSIGNED    DEFAULT 0 COMMENT '本周期答题数',
    total_correct_rate      DECIMAL(5,4)    DEFAULT 0 COMMENT '总正确率(0~1)',
    period_correct_rate     DECIMAL(5,4)    DEFAULT 0 COMMENT '本周期正确率',
    -- 知识掌握度
    total_knowledge_points  INT UNSIGNED    DEFAULT 0 COMMENT '已学习知识点总数',
    mastered_points         INT UNSIGNED    DEFAULT 0 COMMENT '已掌握知识点数',
    mastery_rate            DECIMAL(5,4)    DEFAULT 0 COMMENT '总体掌握率',
    weak_point_count        INT UNSIGNED    DEFAULT 0 COMMENT '薄弱知识点数',
    -- 章节进度
    total_chapters          INT UNSIGNED    DEFAULT 0 COMMENT '总章节数',
    completed_chapters      INT UNSIGNED    DEFAULT 0 COMMENT '已完成章节数',
    chapter_progress        DECIMAL(5,4)    DEFAULT 0 COMMENT '章节完成率',
    -- 错题指标
    total_mistakes          INT UNSIGNED    DEFAULT 0 COMMENT '累计错题数',
    period_mistakes         INT UNSIGNED    DEFAULT 0 COMMENT '本周期新增错题',
    reviewed_mistakes       INT UNSIGNED    DEFAULT 0 COMMENT '已复习错题数',
    mistake_review_rate     DECIMAL(5,4)    DEFAULT 0 COMMENT '错题复习率',
    -- 活跃与连续
    active_days             INT UNSIGNED    DEFAULT 0 COMMENT '累计活跃天数',
    streak_days             INT UNSIGNED    DEFAULT 0 COMMENT '当前连续学习天数',
    max_streak_days         INT UNSIGNED    DEFAULT 0 COMMENT '最长连续学习天数',
    -- 学习计划
    plan_completion_rate    DECIMAL(5,4)    DEFAULT 0 COMMENT '学习计划完成率',
    -- 能力维度(JSON)
    ability_dimensions      JSON            DEFAULT NULL COMMENT '能力维度评分 {reasoning: 0.72, reading: 0.85, ...}',
    created_at              DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_snapshot_id (snapshot_id),
    INDEX idx_user_snapshot (user_id, snapshot_id),
    INDEX idx_user_date (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='快照汇总数据表';
```

### 2.3 学科维度快照表 `learning_snapshot_subject`

按学科拆分的学习进度快照，支持单学科趋势分析。

```sql
CREATE TABLE learning_snapshot_subject (
    id                      BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,

    subject_id              BIGINT UNSIGNED NOT NULL COMMENT '学科ID',
    subject_name            VARCHAR(32)     NOT NULL COMMENT '学科名称(冗余)',

    knowledge_mastery       DECIMAL(5,4)    DEFAULT 0 COMMENT '学科知识掌握率',
    chapter_progress        DECIMAL(5,4)    DEFAULT 0 COMMENT '学科章节完成率',
    mistake_count           INT UNSIGNED    DEFAULT 0 COMMENT '学科错题数',
    weak_points             JSON            DEFAULT NULL COMMENT '薄弱知识点列表 [{"id":1,"name":"二元一次方程","mastery":0.3}]',
```

```sql
    UNIQUE KEY uk_comparison_id (comparison_id),
    INDEX idx_user (user_id),
    INDEX idx_snapshots (base_snapshot_id, compare_snapshot_id)

```



**请求体：**
```json

  "snapshotScope": 1,
  "scopeRefId": null,
  "triggerSource": "manual",
  "remark": "期末考试前手动备份"
}
```

```json
{
```

### 3.5 进度回滚

```
POST /api/v1/learning-snapshots/{snapshotId}/rollback
```

**请求体：**
```json
{
  "rollbackScope": "FULL",
  "reason": "年级升迁数据异常，回滚至升迁前状态",
  "createPreRollbackSnapshot": true
}
```

**说明：**
- `createPreRollbackSnapshot=true` 时，系统先对当前状态做一次快照，再执行回滚，保证可逆。
- 回滚操作需管理员权限或系统自动触发，普通用户无权调用。
- 回滚是异步操作，通过事件驱动逐步更新下游数据。

### 3.6 获取最新学习进度

```
GET /api/v1/learning-snapshots/latest?scope=FULL
```

**响应：** 返回最新完成的快照详情，客户端用于展示当前学习进度概览。

## 4. 核心流程设计

### 4.1 周期快照自动采集流程

```
                    ┌─────────────────────────────────────────────────┐
                    │           定时任务触发 (每日 23:50)                │
                    └────────────────────┬────────────────────────────┘
                                         │
                                         ▼
                    ┌─────────────────────────────────────────────────┐
                    │ 1. 查询当日有学习活动的活跃用户列表                  │
                    │    (从学习行为事件流/Redis布隆过滤器获取)           │
                    └────────────────────┬────────────────────────────┘
                                         │
                                         ▼
                    ┌─────────────────────────────────────────────────┐
                    │ 2. 批量创建日快照记录 (status=COLLECTING)          │
                    │    批量INSERT + 发送MQ消息                        │
                    └────────────────────┬────────────────────────────┘
                                         │
                                         ▼
              ┌──────────────────────────────────────────────────────────┐
              │              MQ消费者: 单用户快照采集Worker                 │
              │                                                          │
              │  Step 1: 聚合当日学习时长                                    │
              │    → 调用 学习时长统计服务 获取累计/当日时长                   │
              │                                                          │
              │  Step 2: 聚合答题数据                                      │
              │    → 调用 练习测评服务 获取答题数/正确率                      │
              │                                                          │
              │  Step 3: 聚合知识掌握度                                     │
              │    → 调用 知识掌握度服务 获取各知识点掌握等级                  │
              │                                                          │
              │  Step 4: 聚合章节进度                                      │
              │    → 调用 同步课堂服务 获取章节完成情况                       │
              │                                                          │
              │  Step 5: 聚合错题数据                                      │
              │    → 调用 错题服务 获取错题数/复习率                         │
              │                                                          │
              │  Step 6: 计算能力维度评分                                   │
              │    → 调用 学情分析服务 获取五维能力评分                      │
              │                                                          │
              │  Step 7: 计算活跃/连续天数                                  │
              │    → 查 Redis 学习打卡记录                                  │
              │                                                          │
              │  Step 8: 组装汇总数据 + 写入 learning_snapshot_summary     │
              │                                                          │
              │  Step 9: 按学科拆分 + 写入 learning_snapshot_subject       │
              │                                                          │
              │  Step 10: 写入知识掌握度明细 learning_snapshot_knowledge    │
              │          (数据量大时分批写入，每批500条)                      │
              │                                                          │
              │  Step 11: 计算checksum + 更新快照状态为 COMPLETED           │
              └──────────────────────────┬───────────────────────────────┘
                                         │
                                         ▼
                    ┌─────────────────────────────────────────────────┐
                    │ 3. 发送快照完成事件                                │
                    │    → 触发下游: 学习报告/家长通知/数据仓库同步         │
                    └─────────────────────────────────────────────────┘
```

### 4.2 周/月快照聚合流程

```
每周一 01:00 / 每月1日 02:00 定时触发

Step 1: 查询上一周期内的所有日快照
Step 2: 对日快照汇总数据进行聚合计算
        - period_study_minutes = SUM(daily.study_minutes)
        - period_questions = SUM(daily.questions)
        - period_correct_rate = 加权平均(按答题数量加权)
        - mastery_rate = 最新日快照的 mastery_rate
Step 3: 创建周/月快照记录
Step 4: 写入周/月快照汇总数据
Step 5: 写入学科维度数据(聚合各日快照的学科数据)
Step 6: 知识掌握度明细直接取最新日快照数据
Step 7: 更新状态为 COMPLETED
```

### 4.4 趋势对比计算流程

```
Step 1: 根据对比类型确定基准快照和对比快照
        - 指定 snapshotId → 直接获取
        - 指定日期范围 → 查找最近的快照

Step 2: 分别读取两个快照的 summary 数据

Step 3: 计算各指标的 delta 值
        delta = compare_value - base_value
        deltaPercent = delta / base_value (base_value ≠ 0 时)

Step 4: 学科维度对比
        按学科匹配两个快照的学科数据，计算各学科 delta

Step 5: 识别进步项和退步项
        - 进步: 正向指标 delta > 阈值 (如正确率提升 > 3%)
        - 退步: 正向指标 delta < -阈值 或 反向指标 delta > 阈值

Step 6: 调用学习建议服务生成个性化建议
        基于对比结果和用户画像生成 2-3 条建议

Step 7: 写入 comparison 记录 + 缓存 (TTL = 24h)

Step 8: 返回对比结果
```

```java
@Service
@Slf4j
public class LearningSnapshotCollector {

    @Autowired
    private StudyTimeService studyTimeService;
    @Autowired
    private PracticeService practiceService;
    @Autowired
    private KnowledgeMasteryService knowledgeMasteryService;
    @Autowired
    private SyncClassService syncClassService;
    @Autowired
    private MistakeService mistakeService;
    @Autowired
    private LearningAnalyticsService learningAnalyticsService;
    @Autowired
    private StreakService streakService;
    @Autowired
    private LearningSnapshotRepository snapshotRepository;
    @Autowired
    private LearningSnapshotSummaryRepository summaryRepository;
    @Autowired
    private LearningSnapshotSubjectRepository subjectRepository;
    @Autowired
    private LearningSnapshotKnowledgeRepository knowledgeRepository;
    @Autowired
    private ApplicationEventPublisher eventPublisher;

    /**
     * 采集单个用户的日快照
     */
    @Transactional
    public SnapshotCollectResult collectDailySnapshot(Long userId, LocalDate snapshotDate) {
        log.info("开始采集用户日快照: userId={}, date={}", userId, snapshotDate);
        long startTime = System.currentTimeMillis();

        // Step 1: 创建快照主记录
        String snapshotId = generateSnapshotId();
        LearningSnapshot snapshot = new LearningSnapshot();
        snapshot.setSnapshotId(snapshotId);
        snapshot.setUserId(userId);
        snapshot.setSnapshotType(SnapshotType.DAILY.getCode());
        snapshot.setSnapshotScope(1); // 全学科
        snapshot.setSnapshotDate(snapshotDate);
        snapshot.setSnapshotTime(LocalDateTime.now());
        snapshot.setTriggerSource("system");
        snapshot.setStatus(SnapshotStatus.COLLECTING.getCode());
        snapshotRepository.insert(snapshot);

        try {
            // Step 2: 并行聚合各项数据
            CompletableFuture<StudyTimeResult> studyTimeFuture = 
                CompletableFuture.supplyAsync(() -> studyTimeService.getUserStudyTime(userId, snapshotDate));
            CompletableFuture<PracticeResult> practiceFuture = 
                CompletableFuture.supplyAsync(() -> practiceService.getUserPracticeStats(userId, snapshotDate));
            CompletableFuture<KnowledgeMasteryResult> masteryFuture = 
                CompletableFuture.supplyAsync(() -> knowledgeMasteryService.getUserMasteryStats(userId));
            CompletableFuture<ChapterProgressResult> chapterFuture = 
                CompletableFuture.supplyAsync(() -> syncClassService.getUserChapterProgress(userId));
            CompletableFuture<MistakeResult> mistakeFuture = 
                CompletableFuture.supplyAsync(() -> mistakeService.getUserMistakeStats(userId, snapshotDate));
            CompletableFuture<AbilityDimensionResult> abilityFuture = 
                CompletableFuture.supplyAsync(() -> learningAnalyticsService.getAbilityDimensions(userId));
            CompletableFuture<StreakResult> streakFuture = 
                CompletableFuture.supplyAsync(() -> streakService.getUserStreak(userId));

            // 等待所有聚合完成（超时30秒）
            CompletableFuture.allOf(studyTimeFuture, practiceFuture, masteryFuture, 
                chapterFuture, mistakeFuture, abilityFuture, streakFuture)
                .get(30, TimeUnit.SECONDS);

            // Step 3: 组装汇总数据
            StudyTimeResult studyTime = studyTimeFuture.get();
            PracticeResult practice = practiceFuture.get();
            KnowledgeMasteryResult mastery = masteryFuture.get();
            ChapterProgressResult chapter = chapterFuture.get();
            MistakeResult mistake = mistakeFuture.get();
            AbilityDimensionResult ability = abilityFuture.get();
            StreakResult streak = streakFuture.get();

            LearningSnapshotSummary summary = buildSummary(snapshotId, userId,
                studyTime, practice, mastery, chapter, mistake, ability, streak);
            summaryRepository.insert(summary);

            // Step 4: 按学科拆分
            List<LearningSnapshotSubject> subjectSnapshots = 
                buildSubjectSnapshots(snapshotId, userId, practice, mastery, chapter, mistake);
            subjectRepository.batchInsert(subjectSnapshots);

            // Step 5: 知识掌握度明细
            List<LearningSnapshotKnowledge> knowledgeSnapshots = 
                buildKnowledgeSnapshots(snapshotId, userId, mastery);
            knowledgeRepository.batchInsert(knowledgeSnapshots, 500); // 分批500条

            // Step 6: 计算checksum + 更新状态
            String checksum = computeChecksum(summary, subjectSnapshots);
            snapshot.setStatus(SnapshotStatus.COMPLETED.getCode());
            snapshot.setChecksum(checksum);
            snapshotRepository.updateById(snapshot);

            long cost = System.currentTimeMillis() - startTime;
            log.info("快照采集完成: snapshotId={}, userId={}, cost={}ms", snapshotId, userId, cost);

            // Step 7: 发布完成事件
            eventPublisher.publishEvent(new SnapshotCompletedEvent(snapshotId, userId, snapshotDate));

            return SnapshotCollectResult.success(snapshotId);
        } catch (Exception e) {
            log.error("快照采集失败: userId={}, error={}", userId, e.getMessage(), e);
            snapshot.setStatus(SnapshotStatus.INVALID.getCode());
            snapshotRepository.updateById(snapshot);
            return SnapshotCollectResult.fail(e.getMessage());
        }
    }

    private String generateSnapshotId() {
        return "snap-" + UUID.randomUUID().toString();
    }

    private String computeChecksum(LearningSnapshotSummary summary, 
                                    List<LearningSnapshotSubject> subjects) {
        String raw = String.format("%s|%d|%d|%.4f|%.4f|%d",
            summary.getSnapshotId(),
            summary.getPeriodStudyMinutes(),
            summary.getPeriodQuestions(),
            summary.getPeriodCorrectRate(),
            summary.getMasteryRate(),
            summary.getStreakDays());
        return DigestUtils.sha256Hex(raw);
    }
}
```

### 5.2 趋势对比服务

```java
@Service
@Slf4j
public class SnapshotComparisonService {

    private static final BigDecimal IMPROVEMENT_THRESHOLD = new BigDecimal("0.03");
    private static final BigDecimal DECLINE_THRESHOLD = new BigDecimal("-0.03");

    @Autowired
    private LearningSnapshotSummaryRepository summaryRepository;
    @Autowired
    private LearningSnapshotSubjectRepository subjectRepository;
    @Autowired
    private LearningSuggestionService suggestionService;
    @Autowired
    private LearningSnapshotComparisonRepository comparisonRepository;
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    /**
     * 对比两个快照的学习进度变化
     */
    public ComparisonResult compareSnapshots(Long userId, String baseSnapshotId, 
                                              String compareSnapshotId, ComparisonType type) {
        // 查缓存
        String cacheKey = String.format("snapshot:comparison:%s:%s", baseSnapshotId, compareSnapshotId);
        ComparisonResult cached = (ComparisonResult) redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return cached;
        }

        // 获取两个快照的汇总数据
        LearningSnapshotSummary base = summaryRepository.selectBySnapshotId(baseSnapshotId);
        LearningSnapshotSummary compare = summaryRepository.selectBySnapshotId(compareSnapshotId);

        if (base == null || compare == null) {
            throw new BusinessException(ErrorCode.SNAPSHOT_NOT_FOUND, "快照不存在");
        }
        if (!base.getUserId().equals(userId) || !compare.getUserId().equals(userId)) {
            throw new BusinessException(ErrorCode.PERMISSION_DENIED, "无权访问该快照");
        }

        // 计算核心指标变化
        Map<String, DeltaValue> deltaSummary = new LinkedHashMap<>();
        deltaSummary.put("studyMinutes", computeDelta(
            base.getPeriodStudyMinutes(), compare.getPeriodStudyMinutes()));
        deltaSummary.put("correctRate", computeDelta(
            base.getPeriodCorrectRate(), compare.getPeriodCorrectRate()));
        deltaSummary.put("masteryRate", computeDelta(
            base.getMasteryRate(), compare.getMasteryRate()));
        deltaSummary.put("weakPointCount", computeDelta(
            base.getWeakPointCount(), compare.getWeakPointCount()));
        deltaSummary.put("streakDays", computeDelta(
            base.getStreakDays(), compare.getStreakDays()));

        // 学科维度对比
        List<SubjectDelta> subjectDeltas = compareSubjectDeltas(
            userId, baseSnapshotId, compareSnapshotId);

        // 识别进步项和退步项
        List<ComparisonPoint> improvements = identifyImprovements(deltaSummary, subjectDeltas);
        List<ComparisonPoint> declines = identifyDeclines(deltaSummary, subjectDeltas);

        // 生成学习建议
        List<String> suggestions = suggestionService.generateProgressSuggestions(
            userId, deltaSummary, subjectDeltas, improvements, declines);

        // 构建结果
        ComparisonResult result = ComparisonResult.builder()
            .comparisonId("cmp-" + UUID.randomUUID().toString())
            .userId(userId)
            .baseSnapshotId(baseSnapshotId)
            .compareSnapshotId(compareSnapshotId)
            .comparisonType(type)
            .deltaSummary(deltaSummary)
            .subjectDeltas(subjectDeltas)
            .improvementPoints(improvements)
            .declinePoints(declines)
            .suggestions(suggestions)
            .build();

        // 持久化 + 缓存
        comparisonRepository.insert(buildComparisonRecord(result));
        redisTemplate.opsForValue().set(cacheKey, result, 24, TimeUnit.HOURS);

        return result;
    }

    private DeltaValue computeDelta(Number baseVal, Number compareVal) {
        double base = baseVal.doubleValue();
        double compare = compareVal.doubleValue();
        double delta = compare - base;
        double deltaPercent = base != 0 ? delta / Math.abs(base) : 0;
        return new DeltaValue(base, compare, delta, deltaPercent);
    }

    private List<ComparisonPoint> identifyImprovements(Map<String, DeltaValue> deltas,
                                                        List<SubjectDelta> subjectDeltas) {
        List<ComparisonPoint> points = new ArrayList<>();
        
        // 正向指标提升 → 进步
        if (deltas.get("correctRate").getDeltaPercent() > IMPROVEMENT_THRESHOLD.doubleValue()) {
            points.add(new ComparisonPoint("correctRate", "答题正确率显著提升", null));
        }
        if (deltas.get("masteryRate").getDeltaPercent() > IMPROVEMENT_THRESHOLD.doubleValue()) {
            points.add(new ComparisonPoint("masteryRate", "知识掌握度明显进步", null));
        }
        // 反向指标下降 → 进步
        if (deltas.get("weakPointCount").getDelta() < -DECLINE_THRESHOLD.doubleValue()) {
            points.add(new ComparisonPoint("weakPointCount", "薄弱知识点减少", null));
        }

        // 学科维度进步
        for (SubjectDelta sd : subjectDeltas) {
            if (sd.getMasteryDelta() > IMPROVEMENT_THRESHOLD.doubleValue()) {
                points.add(new ComparisonPoint("masteryRate", 
                    sd.getSubjectName() + "知识掌握度提升", sd.getSubjectId()));
            }
        }
        return points;
    }
}
```

## 7. 错误处理

### 7.1 异常场景与处理策略

| 异常场景 | 处理策略 | 错误码 |
| --- | --- | --- |
| 快照采集时下游服务超时 | 30秒总超时，标记为INVALID，等待下次采集或手动重试 | SNAPSHOT_COLLECT_TIMEOUT |
| 快照采集时数据不一致 | 以最新成功快照为准，当前快照标记INVALID | SNAPSHOT_DATA_INCONSISTENT |
| 回滚过程中部分服务失败 | 记录回滚进度，支持断点续滚 | SNAPSHOT_ROLLBACK_PARTIAL |
| 快照checksum校验失败 | 标记INVALID，发送告警，等待人工介入 | SNAPSHOT_CHECKSUM_MISMATCH |
| 重复快照（同日同类型） | 幂等处理：已存在则跳过，未完成则重试 | SNAPSHOT_DUPLICATE_SKIPPED |
| 并发创建同类型快照 | 数据库唯一约束 + 分布式锁保护 | SNAPSHOT_CONCURRENT_CONFLICT |
| 对比查询快照不存在 | 返回明确错误信息，提示可选快照列表 | SNAPSHOT_NOT_FOUND |
| 归档过程中写入冷存储失败 | 保留原数据，重试归档，不删除热数据 | SNAPSHOT_ARCHIVE_FAILED |

### 7.3 重试与降级策略

```java
@Service
public class SnapshotRetryPolicy {

    /**
     * 快照采集重试策略
     * - 第1次重试: 延迟5分钟
     * - 第2次重试: 延迟15分钟  
     * - 第3次重试: 延迟30分钟
     * - 超过3次: 标记INVALID，发送告警
     */
    public RetryPolicy getCollectRetryPolicy() {
        return RetryPolicy.builder()
            .maxAttempts(3)
            .backoffStrategy(BackoffStrategy.EXPONENTIAL)
            .initialDelay(Duration.ofMinutes(5))
            .maxDelay(Duration.ofMinutes(30))
            .retryOn(Exception.class)
            .build();
    }

    /**
     * 快照对比降级策略
     * - 优先使用完整快照数据对比
     * - 如某个维度数据缺失，使用可用的维度进行部分对比
     * - 如两个快照都不完整，返回错误
     */
    public ComparisonResult degradeCompare(LearningSnapshotSummary base,
                                            LearningSnapshotSummary compare) {
        // 只对比可用的维度
        Map<String, DeltaValue> partialDeltas = new LinkedHashMap<>();
        if (base.getPeriodStudyMinutes() != null && compare.getPeriodStudyMinutes() != null) {
            partialDeltas.put("studyMinutes", computeDelta(base, compare));
        }
        // ... 其他维度类似
        return ComparisonResult.partial(partialDeltas);
    }
}
```

## 8. 性能优化与容量规划

### 8.1 分表策略

- `learning_snapshot` / `learning_snapshot_summary`: 按 `user_id % 16` 分16张表
- `learning_snapshot_subject`: 按 `user_id % 16` 分16张表
- `learning_snapshot_knowledge`: 按 `user_id % 32` 分32张表（数据量最大）

### 8.2 性能目标

| 操作 | 目标延迟 | 说明 |
| --- | --- | --- |
| 单用户日快照采集 | < 5s | 并行聚合各维度数据 |
| 快照列表查询 | < 200ms | 索引覆盖查询 |
| 快照详情查询 | < 300ms | 主键查询 |
| 趋势对比计算 | < 1s | 两个快照数据对比 + 建议 |
| 批量快照采集 (1万用户) | < 30min | MQ并发消费，Worker并发度20 |

### 8.3 存储估算

- 单用户日快照（含明细）: ~50KB
- 月度新增存储 (100万DAU): ~50GB/月
- 年度存储 (含归档压缩): ~300GB/年
- 建议归档策略: 90天后迁移到ClickHouse，1年后迁移到对象存储

## 9. 监控与告警

| 监控指标 | 告警阈值 | 处理方式 |
| --- | --- | --- |
| 快照采集成功率 | < 99% | 检查下游服务状态 |

| 回滚操作执行 | 任何回滚 | 通知管理员确认 |
