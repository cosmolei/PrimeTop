# 学生学习风险评估与早期预警系统 - 详细设计

## 1. 模块概述

### 1.1 功能定位

基于学生历史学习行为、答题数据、活跃度趋势等多维特征，构建学生学习风险预测模型，对可能出现的学习退步、长期低活跃、知识点断层等风险进行早期识别，自动触发预警并生成干预建议，推送给家长和教师，实现"早发现、早干预"的学习保障闭环。

### 1.2 核心价值

1. **预测性**：不等成绩下滑才反应，提前 1-2 周识别风险信号
2. **可解释性**：每个风险预警附带具体原因和证据链，家长/教师能理解
3. **可操作性**：不只是报警，同时给出干预建议（如推荐复习某个知识点）
4. **隐私安全**：风险数据仅家长和绑定教师可见，学生端不直接展示风险标签

### 1.3 与现有模块的关系

| 关联模块 | 交互方式 |
|----------|----------|
| 学情分析 | 消费学情数据作为风险特征输入 |
| 学习记录与进度追踪 | 消费学习时长、完成率等行为数据 |
| 知识点体系与教材映射引擎 | 消费知识点掌握度数据 |
| 错题整理 | 消费错题数量、错因分布数据 |
| 家长中心 | 向家长推送预警通知和干预建议 |
| 教师端与班级管理 | 向教师推送班级风险概览和学生预警 |
| 学习提醒与智能通知调度系统 | 通过通知系统分发预警 |
| 练习与测评系统 | 消费答题正确率、用时等测评数据 |
| 用户标签与智能分群引擎 | 写入风险标签，供运营分群使用 |

## 2. 风险模型设计

### 2.1 风险维度定义

系统从 5 个维度评估学生学习风险：

```python
class RiskDimension(str, Enum):
    ENGAGEMENT = "engagement"       # 活跃度风险：使用频率下降、学习时长锐减
    MASTERY = "mastery"             # 掌握度风险：知识点掌握度持续走低
    MISTAKE = "mistake"             # 错误率风险：答题正确率下降、同类错题增多
```

### 2.4 风险评分模型

采用**加权评分 + 规则叠加**的混合模型，兼顾可解释性和预测准确性。

#### 2.4.1 维度评分函数

每个维度独立计算 0-100 的风险分：

```python
def compute_engagement_risk(features: EngagementFeatures) -> RiskScore:
    """活跃度风险评分"""
    score = 0.0
    
    # (1) 活跃天数衰减（权重 30%）
    if features.active_days_last_7d <= 1:
        score += 30
    elif features.active_days_last_7d <= 3:
        score += 15
    elif features.active_days_last_7d <= 5:
        score += 5
    
    # (2) 活跃度周环比下降（权重 25%）
    if features.active_days_week_over_week < -0.5:
        score += 25
    elif features.active_days_week_over_week < -0.3:
        score += 15
    elif features.active_days_week_over_week < -0.1:
        score += 5
    
    # (3) 学习时长趋势下降（权重 25%）
    if features.daily_time_trend_14d < -5:
        score += 25
    elif features.daily_time_trend_14d < -2:
        score += 15
    elif features.daily_time_trend_14d < 0:
        score += 5
    
    # (4) 连续中断天数（权重 20%）
    if features.max_gap_days_30d >= 7:
        score += 20
    elif features.max_gap_days_30d >= 5:
        score += 12
    elif features.max_gap_days_30d >= 3:
        score += 5
    
    return RiskScore(
        dimension=RiskDimension.ENGAGEMENT,
        score=min(score, 100),
        confidence=_compute_confidence(features),
        contributors=_get_top_contributors(features)
    )
```

其他维度的评分函数结构类似，每个维度定义独立的评分规则和阈值。

#### 2.4.2 综合风险评分

```python
# 分龄权重矩阵（不同学段关注点不同）
DIMENSION_WEIGHTS = {
    "primary": {  # 小学：更关注活跃度和连续性
        RiskDimension.ENGAGEMENT: 0.25,
        RiskDimension.MASTERY: 0.20,
        RiskDimension.MISTAKE: 0.15,
        RiskDimension.PROGRESS: 0.15,
        RiskDimension.CONSISTENCY: 0.25,
    },
    "junior": {  # 初中：更关注掌握度和错误率
        RiskDimension.ENGAGEMENT: 0.20,
        RiskDimension.MASTERY: 0.25,
        RiskDimension.MISTAKE: 0.25,
        RiskDimension.PROGRESS: 0.15,
        RiskDimension.CONSISTENCY: 0.15,
    },
    "senior": {  # 高中：更关注掌握度和进度
        RiskDimension.ENGAGEMENT: 0.15,
        RiskDimension.MASTERY: 0.30,
        RiskDimension.MISTAKE: 0.20,
        RiskDimension.PROGRESS: 0.25,
        RiskDimension.CONSISTENCY: 0.10,
    },
}

def compute_composite_risk(
    dimension_scores: dict[RiskDimension, RiskScore],
    stage: str
) -> CompositeRiskAssessment:
    """计算综合风险评分"""
    weights = DIMENSION_WEIGHTS.get(stage, DIMENSION_WEIGHTS["junior"])
    
    composite_score = sum(
        dimension_scores[dim].score * weights[dim]
        for dim in RiskDimension
    )
    
    # 规则叠加：关键风险因子额外加分
    bonus = 0.0
    # 多维度同时高风险：叠加效应
    high_risk_dims = sum(
        1 for s in dimension_scores.values() if s.score >= 60
    )
    if high_risk_dims >= 3:
        bonus += 15
    elif high_risk_dims >= 2:
        bonus += 8
    
    final_score = min(composite_score + bonus, 100)
    
    return CompositeRiskAssessment(
        overall_score=final_score,
        risk_level=_score_to_level(final_score),
        dimension_scores=dimension_scores,
        primary_risk_dimension=max(
            dimension_scores, key=lambda d: dimension_scores[d].score
        ),
        bonus_applied=bonus,
        bonus_reason=f"{high_risk_dims}个维度高风险叠加" if bonus > 0 else None,
    )
```

### 3.2 数据模型（Python）

```python
from datetime import date, datetime
from decimal import Decimal
from typing import Optional
from pydantic import BaseModel, Field
from enum import Enum


class RiskDimension(str, Enum):
    ENGAGEMENT = "engagement"
    MASTERY = "mastery"
    MISTAKE = "mistake"
    PROGRESS = "progress"
    CONSISTENCY = "consistency"


class RiskLevel(str, Enum):
    NORMAL = "normal"
    LOW_RISK = "low_risk"
    MEDIUM_RISK = "medium_risk"
    HIGH_RISK = "high_risk"


class AlertType(str, Enum):
    SCORE_THRESHOLD = "score_threshold"       # 风险分超过阈值
    LEVEL_CHANGE_UP = "level_change_up"       # 风险等级上升
    PROLONGED_RISK = "prolonged_risk"         # 持续处于风险状态
    SUDDEN_DROP = "sudden_drop"               # 指标骤降
    INACTIVITY = "inactivity"                 # 长时间不活跃
    MASTERY_COLLAPSE = "mastery_collapse"     # 掌握度崩塌


class InterventionType(str, Enum):
    REVIEW_PLAN = "review_plan"               # 推荐复习计划
    WEAK_KP_DRILL = "weak_kp_drill"           # 薄弱知识点专项练习
    STUDY_SCHEDULE = "study_schedule"          # 调整学习时间表
    PARENT_ENCOURAGE = "parent_encourage"      # 家长鼓励沟通
    TEACHER_CHECKIN = "teacher_checkin"        # 教师关怀跟进
    CONTENT_ADJUST = "content_adjust"          # 降低难度/调整内容


class RiskScore(BaseModel):
    """单维度风险评分"""
    dimension: RiskDimension
    score: Decimal = Field(ge=0, le=100)
    confidence: Decimal = Field(ge=0, le=1)
    contributors: list[str] = Field(default_factory=list)  # 主要贡献因子


class EvidenceItem(BaseModel):
    """预警证据项"""
    metric_name: str          # 指标名称
    current_value: float      # 当前值
    previous_value: float     # 之前值
    change_rate: float        # 变化率
    threshold: float          # 阈值
    severity: str             # 严重程度: mild/moderate/severe


class InterventionSuggestion(BaseModel):
    """干预建议"""
    type: InterventionType
    priority: int = Field(ge=1, le=10)
    title: str
    description: str
    action_url: Optional[str] = None
    target_kp_ids: list[int] = Field(default_factory=list)
    target_chapter_id: Optional[int] = None
    estimated_effort: str     # 预估投入: "10分钟"/"30分钟"/"1小时"/"每日15分钟×7天"


class RiskAlert(BaseModel):
    """风险预警"""
    id: Optional[int] = None
    student_id: int
    alert_type: AlertType
    risk_level: RiskLevel
    trigger_score: Decimal
    primary_dimension: RiskDimension
    title: str
    summary: Optional[str] = None
    evidence: list[EvidenceItem]
    interventions: list[InterventionSuggestion] = Field(default_factory=list)
    status: str = "pending"
    created_at: Optional[datetime] = None


class CompositeRiskAssessment(BaseModel):
    """综合风险评估"""
    student_id: int
    assessment_date: date
    overall_score: Decimal = Field(ge=0, le=100)
    risk_level: RiskLevel
    dimension_scores: dict[RiskDimension, RiskScore]
    primary_risk_dimension: RiskDimension
    trend_direction: Optional[str] = None      # improving/stable/worsening
    score_delta_7d: Optional[Decimal] = None
    confidence: Decimal = Field(ge=0, le=1)
    bonus_applied: Decimal = Decimal("0")
    bonus_reason: Optional[str] = None
```

## 5. 核心流程设计

### 5.1 日终评估批处理管线

```text
04:15 调度触发（延迟任务引擎，避开 04:00 学情/掌握度聚合批次）
  │
  ├─ ① 批次初始化：risk_assess_batch 当日 uk(date) 抢占；已存在且 RUNNING→检查心跳，
  │     心跳 >10min 视为僵死，CAS 接管续跑（游标断点）
  ├─ ② 学生分片：按 student_id % 16 分 16 片，串行+并行混合（每片内 500 学生/批）
  ├─ ③ 特征聚合：gRPC 拉取五维特征 → 写 risk_feature_snapshots（uk 幂等 upsert）
  │     单源失败 → 该维度特征置 NULL + data_sufficiency 降级（D1/D2）
  ├─ ④ 评分计算：五维评分函数 → 综合分 → 等级映射
  │     数据不足判定：近 14 天活跃天数 <3 → insufficient，跳过预警仅存快照（G9）
  ├─ ⑤ 快照落库：student_risk_snapshots uk(student_id, assessment_date)
  │     ON CONFLICT 覆盖（手动重算同日覆盖时 model_version 递增、computed_at 更新）
  ├─ ⑥ 预警判定：六类触发条件（§5.2），生成/升级/恢复
  ├─ ⑦ Outbox 同事务写入 risk_outbox
  └─ ⑧ 批次收尾：COMPLETED / PARTIAL_FAILED（失败片重试 2 次后登记，次日补偿）

超时预算：06:30 未完成触发 P1 告警（M1）；未评估学生当日沿用昨日快照，
trend 字段标记 stale（客户端展示「数据截至 X 日」）。
```

**置信度计算**（补全 §2.4.1 引用）：`_compute_confidence = 0.4×样本量因子 + 0.3×特征完整度 + 0.3×历史一致度`；样本量因子按近 14 天答题数/活跃天数分档（<20 题 0.3、20-100 题 0.7、>100 题 1.0）。contributors 取该维度得分贡献 Top3 因子的规则描述文案。

### 5.2 预警触发条件与去重

| 触发类型 | 条件 | 目标对象 |
|---------|------|---------|
| score_threshold | 综合分 ≥50（medium）且昨日 <50 | 家长+教师 |
| level_change_up | 等级上跨一档及以上（low→medium、→high、normal→low 不触发） | 家长+教师 |
| prolonged_risk | 连续 ≥7 天处于 low_risk 及以上且未产生过同维度预警 | 家长 |
| sudden_drop | 单维度 3 天内得分跳升 ≥20，或正确率 7 天降幅 ≥15pp、掌握度 7 天降幅 ≥10pp | 家长+教师 |
| inactivity | days_since_last_study ≥7 且此前 30 天活跃 ≥10 天 | 仅家长（教师端只入班级概览） |
| mastery_collapse | mastery_delta_7d ≤ -10 或 below_threshold_ratio ≥0.4 | 家长+教师 |

**去重与冷却（三层）：**

1. **DB 唯一键**：`uk_student_date_type_dim(student_id, alert_date, alert_type, primary_dimension)`，同一评估日同型同维度仅一条（幂等基线）。
2. **活跃预警互斥**：生成前检查该学生是否存在同 `alert_type + primary_dimension` 的 `pending/acknowledged/acting` 预警，存在则只更新 `trigger_score`（追加到 evidence，不新建）。
3. **冷却窗口**：同型同维度预警解决/过期后 7 天内不重新生成（Redis `risk:cooldown:{student}:{type}:{dim}` SETNX 7d，TTL 与 DB 扫描双保险，D7）。

**例外**：`high_risk` 等级不受冷却限制（升级为更高等级的预警允许穿透冷却，作为原预警的 escalation 关联，`escalated_from_id` 关联原预警）。

### 5.3 通知分发

1. 预警生成后由 Outbox 消费者调用统一通知网关（多渠道通知发送网关），渠道决策、频控合并、免打扰静默期全部委托通知侧（本系统不自带发送通道）。
2. 优先级映射：medium→`HIGH`、high→`URGENT`；inactivity 降为 `NORMAL`（避免唤醒式打扰）。营销内容禁止夹带（C6）。
3. 双接收人差异化模板：家长版含干预建议入口；教师版仅班级上下文摘要（教师收多个学生预警时由通知侧多源合并引擎聚合为一条日报类消息，防疲劳）。
4. 话术红线：标题/摘要过成长型话术校验（禁用「差生」「落后」「危险」等标签词，词库与内容安全规则引擎共享）；AI 摘要失败降级为模板拼接（D5）。

### 5.4 干预建议生成与委托执行

```text
预警生成 ─→ 干预矩阵匹配（维度×等级×学段）─→ 建议列表（1-4 条，按优先级排序）
  │
  ├─ weak_kp_drill → 委托《学生薄弱点识别与靶向训练推荐服务》
  │     GET /api/v1/weakness/recommendations?student_id=&subject_code=&scene=RISK_INTERVENTION
  │     生成练习计划实体，action_url 指向计划详情；完成事件驱动干预自动 complete
  ├─ review_plan → 委托《学习计划模板库/每日任务生成服务》创建轻量复习计划，
  │     任务经《多源学习任务统一调度与优先级仲裁引擎》投递（source_type=SYSTEM_RECOMMEND，
  │     遵守双减校日 21:00 后不投递与防沉迷分龄硬上限，本系统不直接投递任务）
  ├─ study_schedule / content_adjust → 写入建议文案，由家长在学习规划页参考执行（纯建议，无自动执行）
  ├─ parent_encourage / teacher_checkin → 纯文案建议 + 沟通指南链接（复用家长辅导建议引擎素材）
  └─ 端内学生轻干预（如温和的复习提醒卡片）→ 不由本系统直接触达，注册为
        统一学习干预编排引擎上游信号源（source=RISK），由其统一频控与时机决策
```

**矩阵要点**：medium 级 1-2 条建议；high 级 2-4 条且必含 `teacher_checkin`；幼儿/小学低龄段禁用 `study_schedule`（作息调整建议发给家长而非学生）。

### 5.5 干预效果回评（T+14）

```text
干预 completed / 预警 resolved ─→ 登记 T+14 回评任务（延迟任务引擎）
  │
  ├─ 取 T0（干预完成日）与 T0+14 两次快照的 overall_score 与主维度分
  ├─ effectiveness_score = clamp( (T0分 - T14分) / max(T0分,1) × 0.6
  │                             + 主维度改善比例 × 0.4, -1, 1 )
  ├─ skipped/未接受 → 记 0 分并标记 no_action 对照组样本
  └─ 结果写 risk_interventions.effectiveness_score + 回评明细表（供模型阈值调优）
```

回评不向家长推送分数对比（防「效果承诺」误导），仅内部用于建议质量排序与阈值校准。

### 5.6 过期自动关闭

- 活跃预警 30 天未解决 → `expired`（resolution_note 自动写「超时未处理，随风险快照滚动重评」）。
- 干预建议 30 天未接受 → `expired`；接受后 30 天未完成 → `expired`。
- 过期扫描任务每 60min 增量执行（updated_at 游标），与 §5.1 批处理错峰。

### 5.7 恢复与正向反馈

快照回到 `normal` 且存在该维度活跃预警时：自动 resolve 关联预警（resolution_note=「风险指标恢复正常」），发布 `risk.level.recovered` 事件，通知侧向家长发送一次正向反馈（成长型文案：「近两周坚持复习，数学掌握度已回升」）。恢复通知同维度 30 天仅一次（防反复打扰）。

## 6. 状态机设计

### 6.1 预警状态机

```text
                 ┌──────────────────────────────┐
                 │          pending             │
                 └──────┬──────────────┬───────┘
          家长/教师确认 │              │ 直接解决（含误报判定）
                 ┌──────▼──────┐       └──────► resolved
                 │ acknowledged │
                 └──────┬──────┘
        开始执行干预/接受建议 │
                 ┌──────▼──────┐
                 │   acting    │──────────────► resolved
                 └─────────────┘

任意非终态 ──(30天起时)──► expired（仅过期任务/管理员）
终态：resolved / expired（不可再流转）
```

**守卫表：**

| 守卫 | 规则 |
|------|------|
| G1 | acknowledge/acting/resolve 仅限绑定家长、绑定教师；学生本人 403（不区分存在性） |
| G2 | resolve 必须携带 resolution_note 与 outcome |
| G3 | acting 可重复进入（幂等），不回退到 acknowledged |
| G4 | resolved/expired 终态，任何流转请求返回 57204 |
| G5 | acknowledge 使用 CAS（`WHERE status='pending'`），双确认并发时后到者收 200+already_acknowledged_by |
| G6 | expired 仅由过期扫描任务或管理员双人审批触发 |
| G7 | 同学生同 alert_type+primary_dimension 仅允许一条活跃预警（uk+活跃互斥） |
| G8 | high_risk 升级预警穿透冷却，须携带 escalated_from_id 关联原预警 |
| G9 | data_sufficiency=insufficient 的快照不触发任何预警 |
| G10 | 心理危机 active 期间：预警照常生成，但推送暂缓挂起（crisis 冲突见 C5/契约 9） |
| G11 | 恢复自动 resolve 仅允许由日终批处理/手动重算触发，携带 resolution_note=自动 |
| G12 | 手动重算覆盖同日快照时 model_version 必须 > 原值（乐观版本号） |

### 6.2 干预建议状态机

```text
suggested ──accept──► accepted ──complete──► completed
   │  │                  │
   │  └──────skip────────┤
   └───────(30d)────────► expired
accepted ──(30d)──► expired
终态：completed / skipped / expired
```

| 守卫 | 规则 |
|------|------|
| G13 | 仅 suggested 可 accept；重复 accept 幂等返回 |
| G14 | 仅 accepted 可 complete；completion_evidence 可空但委托类建议优先事件驱动 |
| G15 | skip 必须携带 reason；other 必填说明（57207） |
| G16 | 接受委托类干预（weak_kp_drill/review_plan）自动将预警推进 acting（幂等） |
| G17 | 终态干预不可流转；同一预警下全部建议终态且无 accepted → 预警可被效果回评采样 |

### 6.3 评估批次状态机

`RUNNING → COMPLETED / PARTIAL_FAILED`（失败片登记次日补偿；无回退态）。心跳僵死接管见 §5.1-①。

## 7. 幂等与并发控制（八场景）

| # | 场景 | 机制 |
|---|------|------|
| 1 | 日终批次重复调度 | risk_assess_batch uk(date) + 分布式锁 10s 心跳续期 |
| 2 | 同日同型预警并发生成（重算与批处理交叠） | uk_student_date_type_dim + ON CONFLICT DO NOTHING |
| 3 | 冷却期内重复触发（事件重放） | Redis SETNX 7d + 活跃预警 DB 扫描双保险 |
| 4 | acknowledge 双确认并发 | CAS `WHERE status='pending'`，后到者幂等返回 |
| 5 | 通知重复发送 | 通知侧以 (alert_id, 通道) 幂等，本系统传 alert_id 作为业务键 |
| 6 | 干预 accept 重复点击 | CAS + 委托下游携带 Idempotency-Key=intervention_id |
| 7 | Outbox 事件重复投递 | 消费方按 (event_id, consumer) 幂等跳过 |
| 8 | 手动重算与日终批处理并发覆盖快照 | model_version 乐观锁（G12），低版本写入被拒并重读合并 |

## 10. 降级矩阵

| # | 故障 | 降级策略 |
|---|------|---------|
| D1 | 掌握度引擎不可达 | MASTERY 维度置 NULL + data_sufficiency=limited，快照继续；连续 3 日不可达则该维度不参与综合分，权重按剩余维度归一 |

## 14. 验收场景（18 条）

1. 日终批次正常跑：50 万学生快照全部落库，uk 无冲突，06:30 前完成。
2. 批次僵死接管：kill 进程后重启，游标断点续跑，无重复快照。
3. 掌握度源不可达：当日快照 data_sufficiency=limited，无 MASTERY 预警，次日恢复自动回正常。
4. 综合分 49→52：触发 score_threshold 预警，家长+教师双通道通知送达。
5. 同日同型重复触发（事件重放）：uk 幂等，仅一条预警。
6. 冷却期内同型再触发：7 天内不新建，原预警 evidence 追加新证据。
7. medium→high 升级：穿透冷却，escalated_from_id 关联，原预警自动 acting。
8. 家长与教师并发确认同一预警：后者收 200+already_acknowledged_by。
9. 学生本人调任意风险接口：统一 403（57202），响应体不泄露资源存在性。
10. 跨班教师访问班级概览：404。义务教育班级列表仅 band 聚合无排名。
11. 家长摘要：仅 L3 字段，无答题原文/AI 对话细节。
12. accept weak_kp_drill：靶向训练服务收到委托（幂等键=intervention_id），预警自动 acting，action_url 激活。
13. 委托下游不可达时 accept：建议可接受，补偿重试后 action_url 激活，无用户侧报错。
14. 干预完成 T+14：回评任务产出 effectiveness_score，不向家长推送分数对比。
15. 快照回 normal：关联预警自动 resolve，家长收一次正向反馈，30 天内同维度不重复。
16. 心理危机 active 期间生成预警：预警入库但 push_suspended=1，无通知；危机 resolved 后补推。
17. 活跃预警 30 天未处理：过期任务自动 expired，resolution_note 自动填写。
18. AI 摘要失败：模板拼接摘要生成，预警不阻塞，词库校验拦截标签化文案。
