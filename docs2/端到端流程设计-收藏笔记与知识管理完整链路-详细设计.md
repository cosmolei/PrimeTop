# 端到端流程设计 - 收藏笔记与知识管理完整链路

> 版本：v1.0 | 日期：2026-06-03 | 模块归属：端到端流程
> 依赖：收藏与笔记系统（服务端）、客户端-收藏与笔记管理页面架构、客户端本地持久层、客户端路由与深链接系统、离线缓存与数据同步

## 1. 概述

### 1.1 文档目的

本文档描述 PrimeTop「收藏 + 笔记」功能从用户触发到数据持久化的完整端到端链路，覆盖 **6 大学习场景**中的收藏/笔记入口交互、客户端本地写入、服务端同步、离线冲突处理和跨场景跳转等全流程。

现有《收藏与笔记系统-详细设计》定义了服务端数据模型与 API，现有《客户端-收藏与笔记管理页面架构》定义了页面组件与 UI 交互。本文档聚焦**跨模块的端到端串联**——开发人员读完本文档后，应能清晰理解：

1. 在 AI 对话、题目浏览、知识点学习、教材章节、考点梳理、作文素材等场景中，收藏/笔记按钮如何埋入、如何调用、如何回写状态。
2. 离线操作如何落盘、联网后如何与服务器同步、冲突如何解决。
3. 从收藏/笔记列表点击某项后，如何跳回原始学习场景并恢复上下文。
4. 会员配额校验在哪个环节拦截、免费用户超限后如何引导升级。

### 2.2 各场景收藏入口规范

#### 2.2.1 AI 对话页收藏

**触发位置：** AI 消息气泡右上角收藏图标（星星按钮）

**收藏粒度：** 单条 AI 回答消息（含上下文引用的问题）

**数据结构：**
```typescript
// 客户端侧收藏请求
interface CollectionRequest {
  targetType: 'ai_message';       // 固定值
  targetId: string;                // 消息 ID (client_message_id)
  folderId?: string;               // 目标文件夹 ID，不传则入默认文件夹
  tags?: string[];                 // 用户选择的标签
  context: {
    conversationId: string;        // 对话会话 ID
    questionText: string;          // 用户提问文本（快照）
    answerText: string;            // AI 回答文本（快照）
    subjectCode?: string;          // 学科上下文
    gradeCode?: string;            // 年级上下文
    knowledgePointIds?: string[];  // 关联知识点
    modelUsed?: string;            // 使用的模型标识
  };
}
```

**UI 交互时序：**
1. 用户点击星星按钮 → 按钮变为实心星（乐观更新，立即视觉反馈）
2. 若用户已设置默认文件夹 → 直接入默认文件夹，无弹窗
3. 若未设置默认文件夹 → 底部弹出轻量 Sheet（选文件夹 + 选标签），0.5s 无操作自动确认入"全部收藏"
4. 收藏成功后，Toast 提示"已收藏"，提供"查看"快捷入口
5. 收藏失败（网络异常），星星闪烁后恢复空心，Toast 提示"收藏失败，已加入待同步队列"

**关键代码示例（Flutter）：**
```dart
class AiMessageCollectionAction extends ConsumerWidget {
  final String conversationId;
  final ChatMessage message;

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final isCollected = ref.watch(
      collectionStatusProvider(message.id),
    );

    return IconButton(
      icon: Icon(
        isCollected ? Icons.star_rounded : Icons.star_outline_rounded,
        color: isCollected ? AppColors.starYellow : AppColors.textTertiary,
        size: 20,
      ),
      onPressed: () => _toggleCollection(context, ref, isCollected),
    );
  }

  Future<void> _toggleCollection(
    BuildContext context,
    WidgetRef ref,
    bool isCollected,
  ) async {
    final service = ref.read(collectionLocalServiceProvider);

    if (isCollected) {
      // 取消收藏
      await service.removeByTarget('ai_message', message.id);
    } else {
      // 执行收藏
      await service.addCollection(CollectionLocalModel(
        targetType: 'ai_message',
        targetId: message.id,
        folderId: ref.read(defaultFolderProvider),
        context: AiMessageContext(
          conversationId: conversationId,
          questionText: message.previousUserMessage?.text ?? '',
          answerText: message.text,
          subjectCode: ref.read(currentSubjectProvider),
          gradeCode: ref.read(currentGradeProvider),
        ),
      ));
    }

    // 乐观更新：立即刷新 UI 状态
    ref.invalidate(collectionStatusProvider(message.id));
  }
}
```

**触发位置：** 题目详情页底部操作栏中的收藏按钮

**数据结构：**
```typescript
interface QuestionCollectionContext {
  targetType: 'question';
  targetId: string;               // 题目 ID
  context: {
    questionId: string;           // 题目 ID（冗余，方便检索）
    questionText: string;         // 题干快照

    subjectCode: string;          // 学科

    hasAnalysis: boolean;         // 是否含解析
```

**特殊处理：**

### 2.3 服务端 API 设计

#### POST /api/v1/collections — 添加收藏

**请求体：**
```json
{
  "targetType": "ai_message",
  "targetId": "msg_abc123",
  "folderId": "folder_xyz",
  "tags": ["函数", "易错"],
  "context": {
    "conversationId": "conv_001",
    "questionText": "二次函数顶点怎么求？",
    "answerText": "二次函数 y=ax²+bx+c...",
    "subjectCode": "MATH",
    "gradeCode": "G9"
  }
}
```

**响应体（201 Created）：**
```json
{
  "id": "col_20260603001",
  "targetType": "ai_message",
  "targetId": "msg_abc123",
  "folderId": "folder_xyz",
  "tags": ["函数", "易错"],
  "createdAt": "2026-06-03T12:00:00+08:00",
  "snapshot": {
    "title": "二次函数顶点怎么求？",
    "summary": "二次函数 y=ax²+bx+c 的顶点坐标为...",
    "subjectCode": "MATH"
  }
}
```

**错误码：**

| 错误码 | HTTP 状态 | 含义 | 客户端处理 |
|--------|----------|------|-----------|
| QUOTA_EXCEEDED | 403 | 免费用户收藏数已达上限 | 弹窗引导升级会员 |
| DUPLICATE_COLLECTION | 409 | 已收藏相同内容 | 忽略，返回已有记录 |
| INVALID_TARGET | 400 | 目标类型或 ID 不合法 | 提示用户重新操作 |
| TARGET_NOT_FOUND | 404 | 目标内容不存在 | 提示内容已被删除 |

#### DELETE /api/v1/collections/{collectionId} — 取消收藏

**响应体（200 OK）：**
```json
{
  "deleted": true,
  "collectionId": "col_20260603001"
}
```

### 2.4 配额校验流程

```
用户触发收藏
    │
    ▼
读取本地配额缓存（lastQuotaCheck < 5min 有效）
    │
    ├── 缓存有效 & 未超限 → 直接执行收藏
    │
    ├── 缓存有效 & 已超限 → 弹窗引导升级
    │
    └── 缓存过期/无缓存
        │
        ▼
    GET /api/v1/collections/quota
        │
        ├── { used: 45, limit: 50, plan: 'free' } → 更新本地缓存
        │   └── used < limit → 执行收藏
        │   └── used >= limit → 弹窗引导升级
        │
        └── { used: 30, limit: -1, plan: 'premium' } → 无限制
            └── 直接执行收藏
```

**配额限额表：**

| 用户等级 | 收藏上限 | 笔记上限 | 单条笔记最大字数 | 附件大小 |
|---------|---------|---------|---------------|---------|
| 免费用户 | 50 条 | 20 条 | 500 字 | 无附件 |
| 月度会员 | 500 条 | 200 条 | 5000 字 | 单个 5MB |
| 年度会员 | 无限制 | 无限制 | 20000 字 | 单个 20MB |

### 3.3 笔记自动保存与版本管理

```
编辑器内容变更
    │
    ▼
防抖计时器 (30s)
    │
    ▼
生成内容快照 (contentSnapshot)
    │
    ▼
比较与上一版本差异
    │
    ├── 无差异 → 跳过
    │
    └── 有差异
        │
        ▼
    本地保存新版本
    │
    ├── versionNumber++
    ├── 保留最近 20 个版本
    ├── 超出部分自动清理
    │
    ▼
标记 sync_status = 'pending'
    │
    ▼
同步调度器上传
```

**版本数据结构：**
```sql
-- note_versions 表（客户端本地）
CREATE TABLE note_versions (
    id              TEXT PRIMARY KEY,    -- UUID
    note_id         TEXT NOT NULL,
    version_number  INTEGER NOT NULL,
    content         TEXT NOT NULL,       -- JSON 格式富文本
    content_hash    TEXT NOT NULL,       -- SHA256 快速比较
    created_at      INTEGER NOT NULL,   -- Unix timestamp ms
    sync_status     TEXT DEFAULT 'pending',
    FOREIGN KEY (note_id) REFERENCES notes(id)
);
```

### 5.2 自动保存策略

```dart
class AutoSaveController {
  Timer? _debounceTimer;
  final Duration _interval = const Duration(seconds: 30);

  void onContentChanged() {
    _debounceTimer?.cancel();
    _debounceTimer = Timer(_interval, () => _save());
  }

  Future<void> _save() async {
    final content = editorController.getJSONContent();
    final hash = sha256.convert(utf8.encode(jsonEncode(content)));

    // 与上次保存内容比较
    if (hash == _lastSavedHash) return;

    await _localService.saveNoteVersion(
      noteId: noteId,
      content: content,
      contentHash: hash.toString(),
    );

    _lastSavedHash = hash;
  }
}
```

## 6. F5: 离线操作与同步冲突解决

### 6.1 离线操作队列

客户端所有收藏/笔记操作先写入本地 SQLite，通过 `pending_operations` 表记录待同步操作：

```sql
CREATE TABLE pending_operations (
    id              TEXT PRIMARY KEY,      -- UUID
    operation_type  TEXT NOT NULL,          -- 'collection_add' | 'collection_remove' | 'note_create' | 'note_update' | 'note_delete' | 'folder_create' | 'folder_update'
    entity_type     TEXT NOT NULL,          -- 'collection' | 'note' | 'folder'
    entity_id       TEXT NOT NULL,          -- 本地 ID
    server_id       TEXT NULL,              -- 服务端 ID（首次同步后填充）
    payload         TEXT NOT NULL,          -- JSON 序列化的请求体
    created_at      INTEGER NOT NULL,      -- 操作时间戳 ms
    retry_count     INTEGER DEFAULT 0,
    max_retries     INTEGER DEFAULT 5,
    status          TEXT DEFAULT 'pending', -- 'pending' | 'syncing' | 'failed' | 'completed'
    error_code      TEXT NULL
);
```

### 6.2 同步调度器

```
网络状态变更（离线 → 在线）
    │
    ▼
启动同步调度器
    │
    ▼
查询 pending_operations WHERE status IN ('pending', 'failed')
    │  ORDER BY created_at ASC
    │  LIMIT 50
    ▼
按 entity_type 分组，同类型批量处理
    │
    ▼
对每条操作:
    │
    ├── operation_type = 'collection_add'
    │   → POST /api/v1/collections (idempotency key = local_id)
    │   → 成功: 更新 server_id, status='completed'
    │   → 409 DUPLICATE: status='completed'（幂等处理）
    │   → 403 QUOTA_EXCEEDED: status='failed', 提示用户
    │   → 网络错误: retry_count++, status='pending'
    │
    ├── operation_type = 'note_update'
    │   → PUT /api/v1/notes/{serverId}
    │   → 成功: status='completed'
    │   → 409 VERSION_CONFLICT: 触发冲突解决流程
    │   → 网络错误: retry_count++
    │
    └── ...其他操作类型
```

### 6.3 冲突解决策略

**收藏冲突：** 几乎不会发生，因为收藏是幂等操作（基于 target_type + target_id 去重）。

**笔记冲突（核心场景）：**

```
同步时收到 409 VERSION_CONFLICT
    │
    ▼
┌───────────────────────────────────┐
│ 冲突检测                          │
│ local.version = 3                │
│ server.version = 5               │
│ → 本地落后2个版本                 │
└──────────────┬────────────────────┘
               │
               ▼
┌───────────────────────────────────┐
│ 自动合并尝试                      │
│ 对比 local.content 和 server.content│
│ 生成 diff                         │
└──────────────┬────────────────────┘
               │
        ┌──────┴──────┐
        │             │
   可自动合并     无法自动合并
        │             │
        ▼             ▼
  合并后提交    弹窗提示用户选择
  PUT + v6       ├─ 保留本地版本（强制覆盖）
                  ├─ 保留服务端版本（丢弃本地）
                  └─ 手动合并（并排对比编辑）
```

**自动合并判定规则：**
- 若本地和服务端修改的是不同 block（富文本 JSON 的不同段落），则自动合并
- 若修改的是同一 block，则无法自动合并，需要用户决策

### 6.4 幂等性保障

所有同步请求携带 `X-Idempotency-Key` 请求头，值为本地操作 ID（UUID）。服务端基于此 key 去重，确保网络重试不会产生重复收藏或笔记。

## 12. 异常场景处理

| 场景 | 表现 | 处理策略 |
|------|------|--------|
| 收藏时服务端不可用 | 请求超时/5xx | 乐观更新 UI + 标记 pending，待同步 |
| 同步时重复收藏 | 服务端返回 409 | 幂等处理，更新 server_id，不弹错误 |
| 笔记同步冲突 | 版本号不一致 | 自动合并或弹窗让用户选择 |
| 原始内容被删除 | 跳转目标 404 | 展示快照模式，提示原始内容不可用 |
| 配额服务不可用 | quota 接口超时 | 使用本地缓存的配额信息（允许超限 10% 容差） |
| 存储空间不足 | 本地 SQLite 写入失败 | 提示用户清理空间，保留操作在内存队列 |
| 大量待同步操作积压 | pending_operations > 200 | 分批同步，每批 50 条，间隔 2s |

## 14. 安全与隐私

1. **数据隔离**：收藏/笔记接口强制校验 `user_id`，任何查询/操作都基于当前登录用户，防止越权访问
2. **内容安全**：笔记内容经过敏感词过滤（复用内容安全审核模块），违规内容拦截并提示
3. **家长查看**：家长端只能查看孩子的收藏/笔记**统计信息**（数量、学科分布），不能查看具体内容（隐私保护），除非孩子主动授权
4. **数据导出**：用户可导出全部收藏和笔记数据（账户注销流程的一部分）
5. **缓存清理**：本地收藏/笔记数据在用户主动退出登录时清除，下次登录重新拉取
