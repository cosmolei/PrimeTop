# 端到端流程设计 - 会员退订与权益降级完整链路

## 1. 概述

### 1.1 文档目的

本文档详细设计「会员退订、续费中断、权益到期降级」的完整端到端链路，覆盖从用户发起退订/取消自动续费、到期提醒、权益降级、数据保留到挽留策略的全流程。使开发人员可直接依据本文档进行编码实现。

### 1.2 范围

| 场景 | 说明 |
|------|------|
| 用户主动取消自动续费 | 在应用内或应用商店取消订阅 |
| 订阅到期未续费 | 余额不足、支付失败等被动中断 |
| 退款导致订阅失效 | 用户申请退款成功后权益回收 |
| 降级到免费用户 | 权益到期后回到免费额度 |
| 挽留与召回 | 退订/到期后的优惠引导与再激活 |
| 多端同步 | iOS/Android/Web 订阅状态一致性 |

### 1.3 与已有文档的关系

- **上游文档**：`端到端流程设计-会员订阅与增值服务购买完整链路-详细设计.md`（购买/订阅侧）
- **关联文档**：`服务端-退款与订单售后处理服务-详细设计.md`、`支付与会员订阅-详细设计.md`
- **本文档聚焦**：从「订阅已生效」到「取消/到期/降级/挽留」的反向链路

## 3. 核心数据结构

### 3.1 订阅状态枚举

```sql
-- 订阅状态 (subscription_status)
CREATE TYPE subscription_status AS ENUM (
    'trial',          -- 试用期
    'active',         -- 活跃订阅中
    'pending_cancel', -- 已取消自动续费，当前周期未到期
    'past_due',       -- 支付失败，宽限期
    'paused',         -- 暂停（部分平台支持）
    'expired',        -- 已到期/已降级
    'refunded'        -- 已退款
);

-- 降级原因枚举
CREATE TYPE cancel_reason AS ENUM (
    'too_expensive',       -- 价格过高
    'not_enough_usage',    -- 使用频率低
    'child_not_interested', -- 孩子不感兴趣
    'found_alternative',   -- 找到替代品
    'technical_issues',    -- 技术问题
    'privacy_concern',     -- 隐私顾虑
    'refund',              -- 退款导致
    'payment_failed',      -- 支付失败
    'store_cancel',        -- 商店侧取消
    'other'                -- 其他
);
```

```sql
CREATE INDEX idx_sle_event_type ON subscription_lifecycle_events(event_type);
```

## 4. API 接口设计

### 4.1 用户发起取消订阅

```
POST /api/v1/subscriptions/{subscriptionId}/cancel
```

**请求体：**
```json
{
  "reason": "too_expensive",
  "reasonText": "月费太高了，暂时不需要",
  "source": "app"
}
```

**响应体（200）：**
```json
{
  "subscriptionId": 12345,
  "status": "pending_cancel",
  "currentPeriodEnd": "2026-07-05T23:59:59.000Z",
  "message": "已取消自动续费，您的会员权益将持续到 2026年7月5日",
  "retentionOffer": {
    "offerId": "cancel_save_30pct",
    "offerType": "discount",
    "offerValue": 30,
    "description": "继续使用可享 7 折优惠",
    "validUntil": "2026-06-14T23:59:59.000Z"
  }
}
```

**处理逻辑：**
1. 校验 subscriptionId 归属当前用户且状态为 `active`
2. 检查是否通过 Apple/Google 订阅，若是则引导去商店操作
3. 写入 `subscription_lifecycle_events`（event_type = `cancel_initiated`）
4. 匹配挽留策略，如有则返回 `retentionOffer`
5. 状态不变，等待用户确认或挽留

**错误码：**

| 错误码 | HTTP Status | 说明 |
|--------|-------------|------|
| SUBSCRIPTION_NOT_FOUND | 404 | 订阅不存在或不属于该用户 |
| SUBSCRIPTION_NOT_ACTIVE | 409 | 订阅已非活跃状态，无法取消 |
| STORE_MANAGED | 400 | 需要在应用商店内管理订阅 |

```json
    "appAppleId": 123456,
```

**Google Play Real-time Developer Notification 示例：**
```json
{
  "version": "1.0",
  "packageName": "com.primetop.app",
  "eventTimeMillis": "1749302400000",
  "subscriptionNotification": {
    "version": "1.0",
    "notificationType": 12,
    "purchaseToken": "purchase_token_xyz",
```

Google notificationType 映射：
- `12` (SUBSCRIPTION_REVOKED) → 退款/撤销
- `10` (SUBSCRIPTION_PAUSED) → 暂停

**处理逻辑：**
1. 验证 Webhook 签名（Apple: JWT 签名校验; Google: OAuth2 token 验证）
2. 幂等处理：以 `originalTransactionId` + `notificationType` 为幂等键
3. 更新 `user_subscriptions` 状态
4. 写入 `subscription_lifecycle_events`
5. 触发后续流程（提醒/降级/挽留）

## 5. 核心业务流程

### 5.1 用户主动取消自动续费流程

```text
[用户点击「取消订阅」]
       │
       ▼
[检查订阅来源] ──┬── [Apple订阅] → 引导去「设置 > 订阅」操作
                ├── [Google订阅] → 引导去「Play商店 > 订阅」操作
                └── [自有支付] → 应用内直接取消
                              │
                              ▼
                    [POST /cancel API]
                              │
                              ▼
                    [查询挽留策略]
                    ┌─ 有匹配策略 → 返回挽留优惠
                    │         │
                    │    [用户选择]
                    │    ├─ 接受优惠 → POST /retention/accept → 恢复 active
                    │    └─ 拒绝优惠 → POST /cancel/confirm → pending_cancel
                    │
                    └─ 无匹配策略 → 直接标记 pending_cancel
                              │
                              ▼
                    [记录 lifecycle event]
                              │
                              ▼
                    [调度到期提醒任务]
                    （T-7、T-3、T-1天各一次）
```

### 5.2 支付失败被动中断流程

```text
[扣费失败回调]
       │
       ▼
[更新 subscription status → past_due]
       │
       ▼
[启动宽限期（默认 3 天）]
       │
       ├── Day 0: 推送「支付失败，请更新支付方式」
       ├── Day 1: 推送「宽限期剩余 2 天」
       ├── Day 2: 推送「最后机会，请尽快处理」
       │
       ▼
[宽限期内是否支付成功？]
       │
    ┌──┴──┐
    │ 是  │ → 恢复 active
    └──┬──┘
       │ 否
       ▼
[到期 → 执行降级流程 5.4]
```

### 5.3 退款导致订阅失效流程

```text
[退款成功事件]
       │
       ▼
[检查退款类型]
├── 全额退款 → status = refunded → 立即降级
└── 部分退款 → 保持 active，调整下次扣费金额
       │
       ▼
[立即执行降级流程（跳过宽限期）]
       │
       ▼
[写入 lifecycle event: refund_processed]
       │
       ▼
[标记用户进入退款黑名单观察期（30天内不可再次订阅优惠价）]
```

### 5.4 权益降级执行流程

```text
[到期时间到达 / 降级触发]
       │
       ▼
[开启数据库事务]
       │
       ├── 1. 更新 user_subscriptions.status = expired
       ├── 2. 更新 users.membership_tier = free
       ├── 3. 写入 lifecycle event: downgraded
       │
       ├── 4. 重置免费额度计数器
       │     UPDATE user_quota_counters
       │     SET daily_ai_questions = 0,
       │         daily_photo_search = 0
       │     WHERE user_id = ?
       │
       ├── 5. 保留错题本数据（不删除，仅变为只读超限提醒）
       │     -- 错题本保留策略：最近50条可操作，更早的标记为归档
       │     UPDATE mistake_records
       │     SET is_archived = TRUE
       │     WHERE user_id = ?
       │       AND is_archived = FALSE
       │       AND id NOT IN (
       │         SELECT id FROM mistake_records
       │         WHERE user_id = ?
       │         ORDER BY updated_at DESC
       │         LIMIT 50
       │       );
       │
       ├── 6. 保留学习记录（全量保留，免费用户也可查看）
       │
       ├── 7. 降级同步课堂内容可见性
       │     -- 付费章节标记为不可见
       │     UPDATE user_content_access
       │     SET accessible = FALSE
       │     WHERE user_id = ?
       │       AND content_tier = 'premium';
       │
       ├── 8. 降级AI辅导对话能力
       │     -- 更新用户AI会话配置
       │     UPDATE user_ai_config
       │     SET max_context_turns = 5,  -- 免费用户5轮
       │         model_tier = 'basic'
       │     WHERE user_id = ?;
       │
       └── 9. 提交事务
              │
              ▼
        [触发降级后事件]
        ├── 推送「您的会员已到期」
        ├── 调度降级后触达计划（D+1, D+3, D+7...）
        ├── 更新用户标签（标记为 churned）
        └── 更新推荐系统特征（取消付费权重）
```

## 6. 定时任务设计

### 6.1 到期提醒定时任务

```python
# 每日 09:00 执行（用户本地时区上午）
# 扫描即将到期的 pending_cancel 订阅

class SubscriptionExpiryReminderJob:
    """
    扫描 7/3/1 天内到期的 pending_cancel 订阅，
    发送提醒通知
    """
    SCHEDULE = "0 1 * * *"  # UTC 01:00 = 北京时间 09:00

    REMINDER_DAYS = [7, 3, 1]

    async def execute(self, db: AsyncSession):
        now = utcnow()

        for days_before in self.REMINDER_DAYS:
            target_date = now + timedelta(days=days_before)

            subscriptions = await db.execute(
                select(UserSubscription).where(
                    UserSubscription.status == 'pending_cancel',
                    UserSubscription.expire_at.between(
                        target_date - timedelta(hours=12),
                        target_date + timedelta(hours=12)
                    ),
                    # 避免重复发送
                    ~SubscriptionLifecycleEvent.query.filter_by(
                        event_type=f'expiry_reminder_d{days_before}'
                    ).filter(
                        SubscriptionLifecycleEvent.created_at > now - timedelta(hours=24)
                    ).exists()
                )
            )

            for sub in subscriptions.scalars():
                await self._send_reminder(sub, days_before)
                await self._log_event(sub, f'expiry_reminder_d{days_before}')

    async def _send_reminder(self, sub: UserSubscription, days: int):
        user = await get_user(sub.user_id)
        message = self._build_message(user, sub, days)

        # 多渠道发送
        await push_service.send(user.id, message)
        if days <= 1:
            # 最后1天加发短信
            await sms_service.send(user.phone, message.sms_text)
```

### 6.2 降级执行定时任务

```python
# 每 10 分钟执行一次，扫描已到期的订阅并执行降级

class SubscriptionDowngradeJob:
    SCHEDULE = "*/10 * * * *"

    async def execute(self, db: AsyncSession):
        now = utcnow()

        # 查找已到期的 pending_cancel / past_due 订阅
        expired_subs = await db.execute(
            select(UserSubscription).where(
                UserSubscription.status.in_(['pending_cancel', 'past_due']),
                UserSubscription.expire_at <= now,
                UserSubscription.downgrade_at.is_(None)  # 尚未降级
            ).limit(500)  # 批量处理
        )

        for sub in expired_subs.scalars():
            async with db.begin():
                await self._downgrade(db, sub)

    async def _downgrade(self, db: AsyncSession, sub: UserSubscription):
        """执行单个用户的降级，参考 5.4 流程"""
        try:
            # 1. 更新状态
            sub.status = 'expired'
            sub.downgrade_at = utcnow()

            # 2. 更新用户会员等级
            user = await db.get(User, sub.user_id)
            user.membership_tier = 'free'

            # 3. 重置额度
            await self._reset_quotas(db, sub.user_id)

            # 4. 归档超限错题
            await self._archive_excess_mistakes(db, sub.user_id, limit=50)

            # 5. 降级内容访问
            await self._downgrade_content_access(db, sub.user_id)

            # 6. 降级AI配置
            await self._downgrade_ai_config(db, sub.user_id)

            # 7. 记录事件
            event = SubscriptionLifecycleEvent(
                user_id=sub.user_id,
                subscription_id=sub.id,
                event_type='downgraded',
                event_source='cron'
            )
            db.add(event)

            await db.commit()

            # 8. 异步触发通知和运营
            await self._post_downgrade_notifications(sub.user_id)
            await self._schedule_retention_campaigns(sub.user_id)

        except Exception as e:
            await db.rollback()
            logger.error(f"降级失败 user_id={sub.user_id}: {e}")
            # 发送告警
            await alert_service.send("subscription_downgrade_failed", {
                "user_id": sub.user_id,
                "error": str(e)
            })
```

### 7.1 挽留策略匹配逻辑

```python
class RetentionEngine:
    """
    根据用户取消原因、历史订阅时长、使用频率等
    匹配最优挽留策略
    """

    async def match_strategy(
        self,
        user_id: int,
        reason: CancelReason,
        subscription: UserSubscription
    ) -> Optional[RetentionStrategy]:
        # 1. 查询活跃策略
        strategies = await self._get_active_strategies(reason)
        if not strategies:
            return None

        # 2. 检查用户是否已使用过该策略
        usage_count = await self._get_offer_usage_count(user_id)
        available = [s for s in strategies
                     if usage_count.get(s.id, 0) < s.max_offer_times]
        if not available:
            return None

        # 3. 根据用户画像选择最优策略
        user_profile = await self._get_user_retention_profile(user_id)

        # 高价值用户（订阅>6个月）→ 更大优惠
        if user_profile.total_subscription_days > 180:
            return max(available, key=lambda s: s.offer_value)

        # 新用户（订阅<1个月）→ 延长试用期
        if user_profile.total_subscription_days < 30:
            free_days = [s for s in available if s.offer_type == 'free_days']
            if free_days:
                return free_days[0]

        # 默认返回优先级最高的
        return max(available, key=lambda s: s.priority)

    async def _get_user_retention_profile(self, user_id: int) -> dict:
        """获取用户挽留画像"""
        return {
            "user_id": user_id,
            "total_subscription_days": await self._calc_sub_days(user_id),
            "avg_daily_usage_minutes": await self._calc_avg_usage(user_id, days=30),
            "ai_questions_last_7d": await self._count_recent_ai_usage(user_id, days=7),
            "has_children": await self._check_has_children(user_id),
            "previous_cancellations": await self._count_prev_cancellations(user_id),
        }
```

```python
class AppleWebhookVerifier:
    """Apple App Store Server Notification V2 签名验证"""

    async def verify(self, signed_payload: str) -> dict:
        """
        1. 解码 JWT header 获取 kid
        2. 从 Apple 根证书链下载对应公钥
        3. 验证 JWT 签名
        4. 验证 bundleId 匹配
        5. 解码 payload
        """
        import jwt

        # 获取 Apple 公钥
        apple_keys = await self._fetch_apple_public_keys()

        try:
            decoded = jwt.decode(
                signed_payload,
                key=apple_keys,
                algorithms=['ES256'],
                audience='com.primetop.app',
                options={'verify_exp': True}
            )
            return decoded
        except jwt.InvalidTokenError as e:
            raise WebhookVerificationError(f"Apple webhook 签名验证失败: {e}")


class GoogleWebhookVerifier:
    """Google Play Real-time Developer Notification 验证"""

    async def verify(self, message: dict) -> dict:
        """

        2. 使用 Google OAuth2 验证 purchaseToken
        3. 调用 Google Play Developer API 确认状态
```

```python
class ChurnUserScorer:
    """流失用户评分与召回优先级"""

    async def calculate_churn_score(self, user_id: int) -> float:
        """
        计算流失风险评分 (0-100)
        分数越高 = 越可能永久流失 = 需要更强力的召回策略
        """
        profile = await self._get_profile(user_id)

        score = 0.0

        # 1. 订阅时长因素：短订阅用户更容易流失
        if profile.sub_days < 30:
            score += 30
        elif profile.sub_days < 90:
            score += 15
        else:
            score += 5

        # 2. 使用频率因素：低频用户更容易流失
        if profile.avg_daily_minutes < 5:
            score += 25
        elif profile.avg_daily_minutes < 15:
            score += 15
        else:
            score += 5

        # 3. 历史取消次数
        score += min(profile.prev_cancellations * 10, 20)

        # 4. 错题/学习数据量：数据越多越不舍得离开
        if profile.total_mistakes > 100:
            score -= 10
        if profile.total_learning_hours > 50:
            score -= 15

        # 5. 有无家长绑定
        if profile.has_parent_bound:
            score -= 10  # 家长绑定 = 更可能续费

        return max(0, min(100, score))

    async def get_recall_priority(self, user_id: int) -> str:
        score = await self.calculate_churn_score(user_id)
        if score >= 70:
            return 'high'       # 需要人工客服介入
        elif score >= 40:
            return 'medium'     # 自动触达 + 大额优惠
        else:
            return 'low'        # 常规触达
```

### 11.1 异常场景与处理策略

| 异常场景 | 处理策略 |

| 退款后用户又重新订阅 | 清除退款黑名单标记 |
| 降级后免费额度已用完 | 超限提示引导续费，不阻断核心功能 |

- 不可在应用内提供「跳过平台」的支付通道诱导
