# 服务端-全链路流量染色与多环境泳道隔离路由体系-详细设计

## 1. 概述

### 1.1 功能定位

PrimeTop 教育平台采用微服务架构，随着业务复杂度增长和团队规模扩大，面临以下工程挑战：

- **多分支并行开发**：多个 feature 分支需要同时验证，传统"一套 staging 环境所有人共用"模式成为瓶颈
- **全链路压测安全**：压测流量必须与生产流量严格隔离，防止压测数据污染真实用户数据
- **金丝雀/灰度发布精度不足**：现有灰度方案基于用户 ID 取模，无法实现"特定测试人员走特定代码分支"的精确路由
- **联调成本高**：前端联调需要绑定特定后端分支，环境配置和切换耗时

**全链路流量染色与泳道隔离路由体系**（Traffic Coloring & Swim Lane Isolation）通过在请求入口注入染色标记，并在整个服务调用链路中传播和路由该标记，实现：

1. 按需创建逻辑隔离的"泳道"（Swim Lane），无需部署完整独立环境
2. 压测流量自动标识并隔离，保障生产数据安全
3. 灰度发布支持基于请求特征的精确流量路由
4. 开发人员可指定 feature 分支的流量路由，支持多分支并行联调

### 1.2 设计目标

| 目标 | 说明 |
| --- | --- |
| **零侵入** | 业务代码无需感知染色逻辑，通过框架中间件/API网关自动完成 |
| **全链路传播** | 染色标记在 HTTP → RPC → MQ → 异步任务 → 定时任务全链路自动透传 |
| **动态配置** | 泳道路由规则通过配置中心动态下发，无需重启服务 |
| **基线兼容** | 无染色标记的请求走"基线泳道"（Baseline Lane），即生产稳定版本 |
| **监控可观测** | 染色流量与基线流量在监控大盘中可分别查看 |
| **成本可控** | 泳道按需创建，仅部署变更中的服务实例，未变更服务复用基线实例 |

### 1.3 适用范围

- PrimeTop 全部后端微服务（Spring Boot / Spring Cloud 体系）
- API 网关层（Spring Cloud Gateway / APISIX）
- 消息队列（RocketMQ / Kafka）
- 定时任务与异步任务调度
- 全链路压测流量标识

## 2. 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| **流量染色（Traffic Coloring）** | 在请求入口为请求打上标签（如 `lane=feature-xxx`），标识该请求的目的泳道 |
| **泳道（Swim Lane）** | 一组服务实例的逻辑集合，处理特定染色标记的请求。泳道中的服务可以是该泳道专属的，也可以复用基线 |
| **基线泳道（Baseline Lane）** | 生产环境的稳定服务集合，处理所有无染色标记的正常请求 |
| **基线降级（Baseline Fallback）** | 当泳道中某服务无对应实例时，自动降级路由到基线实例 |
| **流量影子（Traffic Shadowing）** | 将生产流量复制一份发送到测试泳道，不影响真实响应 |
| **染色上下文（Color Context）** | 封装染色标记的上下文对象，在整个调用链中传播 |

### 3.2 染色标记传播链路

```text
客户端请求
  │
  ├─ HTTP Header: X-Lane-Id: feature-question-recommend-v2
  │
  ▼
API Gateway (染色入口)
  │
  ├─ 解析/生成染色标记 → 写入 RequestContext
  │
  ▼
Service A (业务服务)
  │
  ├─ 从 RequestContext 读取染色标记
  ├─ 服务发现时带染色标记 → 路由到同泳道实例
  ├─ RPC 调用 → HTTP Header 自动透传染色标记
  │
  ▼
Service B
  │
  ├─ 异步发送 MQ 消息 → 消息 Property 写入染色标记
  │
  ▼
MQ Consumer
  │
  ├─ 消费时从消息 Property 读取染色标记 → 写入消费线程 RequestContext
  │
  ▼
Service C
  │
  ├─ 定时任务触发 → 从任务元数据读取染色标记
  │
  ▼
Service D
```

### 3.3 与现有系统的关系

| 现有系统 | 关系 |
| --- | --- |
| API网关 | 网关层是染色的**主要入口**，负责对外部请求进行染色标记识别和注入 |
| 服务注册发现 (Nacos) | 扩展服务注册元数据，注册实例时携带所属泳道信息 |
| 配置中心 (Nacos Config) | 泳道路由规则、染色规则的动态配置存储 |
| 分布式链路追踪 | 染色标记写入 Trace Span Tag，与链路追踪集成实现按泳道筛选 |
| 全链路压测平台 | 压测流量通过染色标记自动隔离，无需独立压测环境 |
| 灰度发布系统 | 灰度规则可基于染色标记路由，实现更精确的灰度控制 |

## 4. 数据结构定义

### 4.1 染色上下文 (ColorContext)

```java
/**
 * 流量染色上下文
 * 在整个请求链路中传播的染色信息载体
 */
public class ColorContext {
    
    /** 泳道标识 (如 "feature-question-recommend-v2") */
    private String laneId;
    
    /** 流量来源类型 */
    private TrafficType trafficType;
    
    /** 染色标签集合 (支持多维度标记) */
    private Map<String, String> tags;
    
    /** 染色时间戳 (毫秒) */
    private long colorTimestamp;
    
    /** 染色来源 (网关/压测平台/手动指定) */
    private ColorSource source;
    
    /** 请求追踪ID (与链路追踪集成) */
    private String traceId;
    
    // Getters & Setters
}
```

### 4.2 流量类型枚举

```java
/**
 * 流量类型
 */
public enum TrafficType {
    
    /** 正常用户流量 */
    NORMAL("normal"),
    
    /** 压测流量 */
    STRESS_TEST("stress-test"),
    
    /** 灰度流量 */
    CANARY("canary"),
    
    /** 内部测试流量 */
    INTERNAL_TEST("internal-test"),
    
    /** 流量影子 (镜像流量) */
    SHADOW("shadow");
    
    private final String code;
    
    TrafficType(String code) {
        this.code = code;
    }
    
    public String getCode() {
        return code;
    }
}
```

### 4.4 泳道服务条目 (LaneServiceEntry)

```java
/**
 * 泳道中的服务条目
 */
public class LaneServiceEntry {
```

### 4.5 染色路由规则 (LaneRouteRule)

```java
/**
 * 泳道路由规则
 * 定义哪些请求应该被路由到该泳道
 */
public class LaneRouteRule {
    
    /** 规则ID */
    private String ruleId;
    
    /** 关联泳道ID */
    private String laneId;
    
    /** 规则类型 */
    private RuleType type;
    
    /** 规则表达式 (根据类型不同含义不同) */
    private String expression;
    
    /** 规则优先级 (数值越小优先级越高) */
    private int priority;
    
    /** 是否启用 */
    private boolean enabled;
    
    /** 规则描述 */
    private String description;
}

/**
 * 规则类型
 */
public enum RuleType {
    /** 按请求头匹配 */
    HEADER,
    /** 按用户ID列表匹配 */
    USER_ID_LIST,
    /** 按用户ID取模匹配 */
    USER_ID_MODULO,
    /** 按URL路径匹配 */
    URL_PATH,
    /** 按域名匹配 */
    DOMAIN,
    /** 按设备ID匹配 */
    DEVICE_ID,
    /** 按时间窗口匹配 (定时染色) */
    TIME_WINDOW,
    /** 按压测标记匹配 */
    STRESS_TEST_FLAG
}
```

### 6.1 网关层染色拦截器 (GatewayColorFilter)

```java
/**
 * API 网关层流量染色拦截器
 * 
 * 负责在请求进入网关时进行染色标记的识别、生成和注入。
 * 拦截器优先级最高，确保后续所有过滤器都能读取到染色上下文。
 */
@Component
@Order(Ordered.HIGHEST_PRECEDENCE + 10)
public class GatewayColorFilter implements GlobalFilter {
    
    private static final String HEADER_LANE_ID = "X-Lane-Id";
    private static final String HEADER_TRAFFIC_TYPE = "X-Traffic-Type";
    private static final String HEADER_TEST_FLAG = "X-Test-Flag";
    private static final String HEADER_TEST_RUN_ID = "X-Test-Run-Id";
    private static final String COOKIE_LANE_ID = "lane_id";
    private static final String PARAM_LANE_ID = "__lane_id";
    
    @Autowired
    private LaneRouteRuleEngine ruleEngine;
    
    @Autowired
    private SwimLaneRegistry laneRegistry;
    
    @Autowired
    private ColorAuditLogger auditLogger;
    
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        ServerHttpRequest request = exchange.getRequest();
        
        // Step 1: 检查请求中已有的染色标记
        ColorContext existingColor = extractExistingColor(request);
        
        ColorContext finalColor;
        
        if (existingColor != null) {
            // Step 2a: 验证已有染色标记
            finalColor = validateAndAdopt(existingColor);
        } else {
            // Step 2b: 规则引擎匹配
            finalColor = matchByRules(request);
        }
        
        // Step 3: 如果没有匹配到任何泳道，标记为基线流量
        if (finalColor == null) {
            finalColor = ColorContext.baseline();
        }
        
        // Step 4: 注入染色信息到请求头 (向下游传播)
        ServerHttpRequest mutatedRequest = injectColorHeaders(request, finalColor);
        exchange = exchange.mutate().request(mutatedRequest).build();
        
        // Step 5: 写入审计日志
        auditLogger.logAsync(finalColor, request);
        
        // Step 6: 记录指标
        MetricsRecorder.recordLaneTraffic(finalColor.getLaneId(), finalColor.getTrafficType());
        
        // Step 7: 写入 MDC (网关日志关联)
        MDC.put("laneId", finalColor.getLaneId());
        MDC.put("trafficType", finalColor.getTrafficType().getCode());
        
        return chain.filter(exchange)
                .doFinally(signalType -> MDC.clear());
    }
    
    /**
     * 从请求中提取已有的染色标记
     */
    private ColorContext extractExistingColor(ServerHttpRequest request) {
        // 优先级: Header > Cookie > URL Parameter
        
        String laneId = null;
        
        // 1. 检查 X-Lane-Id Header
        laneId = request.getHeaders().getFirst(HEADER_LANE_ID);
        
        // 2. 检查压测标记 (自动染色)
        if (laneId == null) {
            String testFlag = request.getHeaders().getFirst(HEADER_TEST_FLAG);
            if ("perf-test".equals(testFlag)) {
                String testRunId = request.getHeaders().getFirst(HEADER_TEST_RUN_ID);
                ColorContext ctx = new ColorContext();
                ctx.setLaneId("stress-test");
                ctx.setTrafficType(TrafficType.STRESS_TEST);
                ctx.setSource(ColorSource.GATEWAY_AUTO);
                ctx.getTags().put("test_run_id", testRunId);
                ctx.setColorTimestamp(System.currentTimeMillis());
                return ctx;
            }
        }
        
        // 3. 检查 Cookie
        if (laneId == null) {
            laneId = extractFromCookie(request, COOKIE_LANE_ID);
        }
        
        // 4. 检查 URL 参数
        if (laneId == null) {
            laneId = request.getQueryParams().getFirst(PARAM_LANE_ID);
        }
        
        if (laneId != null) {
            String trafficTypeStr = request.getHeaders().getFirst(HEADER_TRAFFIC_TYPE);
            ColorContext ctx = new ColorContext();
            ctx.setLaneId(laneId);
            ctx.setTrafficType(trafficTypeStr != null 
                    ? TrafficType.fromCode(trafficTypeStr) 
                    : TrafficType.NORMAL);
            ctx.setSource(ColorSource.HEADER);
            ctx.setColorTimestamp(System.currentTimeMillis());
            return ctx;
        }
        
        return null;
    }
    
    /**
     * 验证已有染色标记的合法性
     */
    private ColorContext validateAndAdopt(ColorContext color) {
        // 压测流量不做泳道验证 (固定走 stress-test 泳道)
        if (color.getTrafficType() == TrafficType.STRESS_TEST) {
            return color;
        }
        
        // 验证泳道是否存在且激活
        SwimLane lane = laneRegistry.getLane(color.getLaneId());
        if (lane == null || lane.getStatus() != LaneStatus.ACTIVE) {
            // 泳道不存在或未激活，降级为基线流量
            return ColorContext.baseline();
        }
        
        // 检查是否过期
        if (lane.getExpireAt() != null && lane.getExpireAt().isBefore(LocalDateTime.now())) {
            // 泳道已过期，降级为基线流量
            laneRegistry.markLaneForDeletion(color.getLaneId());
            return ColorContext.baseline();
        }
        
        return color;
    }
    
    /**
     * 通过规则引擎匹配染色
     */
    private ColorContext matchByRules(ServerHttpRequest request) {
        return ruleEngine.match(request);
    }
    
    /**
     * 将染色信息注入到请求头中 (向下游传播)
     */
    private ServerHttpRequest injectColorHeaders(ServerHttpRequest request, ColorContext color) {
        return request.mutate()
                .header(HEADER_LANE_ID, color.getLaneId())
                .header(HEADER_TRAFFIC_TYPE, color.getTrafficType().getCode())
                .header("X-Color-Trace-Id", color.getTraceId() != null 
                        ? color.getTraceId() 
                        : UUID.randomUUID().toString())
                .build();
    }
}
```

### 6.2 路由规则引擎 (LaneRouteRuleEngine)

```java
/**
 * 泳道路由规则引擎
 * 
 * 根据配置的路由规则对请求进行匹配，决定请求应路由到哪个泳道。
 * 规则从配置中心动态加载，支持热更新。
 */
@Component
public class LaneRouteRuleEngine {
    
    @Autowired
    private LaneRouteRuleRepository ruleRepository;
    
    @Autowired
    private SwimLaneRegistry laneRegistry;
    
    /** 规则缓存 (按优先级排序) */
    private final AtomicReference<List<CompiledRule>> ruleCache = new AtomicReference<>(Collections.emptyList());
    
    /** 用户上下文服务 (获取当前用户ID) */
    @Autowired
    private UserContextService userContextService;
    
    /**
     * 监听配置变更，刷新规则缓存
     */
    @NacosConfigListener(dataId = "lane-route-rules", timeout = 5000)
    public void onRulesChanged(String config) {
        refreshRules();
    }
    
    /**
     * 刷新规则缓存
     */
    @PostConstruct
    public synchronized void refreshRules() {
        List<LaneRouteRule> rules = ruleRepository.findEnabledRulesOrderByPriority();
        
        List<CompiledRule> compiled = rules.stream()
                .map(this::compile)
                .filter(Objects::nonNull)
                .collect(Collectors.toList());
        
        ruleCache.set(compiled);
    }
    
    /**
     * 对请求执行规则匹配
     */
    public ColorContext match(ServerHttpRequest request) {
        List<CompiledRule> rules = ruleCache.get();
        
        for (CompiledRule rule : rules) {
            if (rule.matches(request)) {
                // 验证泳道状态
                SwimLane lane = laneRegistry.getLane(rule.getLaneId());
                if (lane != null && lane.getStatus() == LaneStatus.ACTIVE) {
                    ColorContext ctx = new ColorContext();
                    ctx.setLaneId(rule.getLaneId());
                    ctx.setTrafficType(determineTrafficType(lane));
                    ctx.setSource(ColorSource.RULE_ENGINE);
                    ctx.setMatchedRuleId(rule.getRuleId());
                    ctx.setColorTimestamp(System.currentTimeMillis());
                    return ctx;
                }
            }
        }
        
        return null; // 未匹配任何规则
    }
    
    /**
     * 编译单条规则
     */
    private CompiledRule compile(LaneRouteRule rule) {
        try {
            switch (rule.getType()) {
                case HEADER:
                    return new HeaderMatchRule(rule);
                case USER_ID_LIST:
                    return new UserIdListMatchRule(rule, userContextService);
                case USER_ID_MODULO:
                    return new UserIdModuloMatchRule(rule, userContextService);
                case URL_PATH:
                    return new UrlPathMatchRule(rule);
                case DOMAIN:
                    return new DomainMatchRule(rule);
                case DEVICE_ID:
                    return new DeviceIdMatchRule(rule);
                case TIME_WINDOW:
                    return new TimeWindowMatchRule(rule);
                case STRESS_TEST_FLAG:
                    return new StressTestFlagMatchRule(rule);
                default:
                    return null;
            }
        } catch (Exception e) {
            log.error("Failed to compile lane route rule: {}", rule.getRuleId(), e);
            return null;
        }
    }
    
    private TrafficType determineTrafficType(SwimLane lane) {
        switch (lane.getType()) {
            case CANARY: return TrafficType.CANARY;
            case STRESS_TEST: return TrafficType.STRESS_TEST;
            default: return TrafficType.NORMAL;
        }
    }
}
```

#### 规则匹配器示例: 用户ID列表规则

```java
/**
 * 按用户ID列表匹配的泳道路由规则
 * 
 * 表达式格式: {"userIds": [1001, 1002, 1003]}
 * 用于指定特定测试人员的流量路由到特定泳道
 */
public class UserIdListMatchRule implements CompiledRule {
    
    private final String ruleId;
    private final String laneId;
    private final Set<Long> userIds;
    private final UserContextService userContextService;
    
    public UserIdListMatchRule(LaneRouteRule rule, UserContextService userContextService) {
        this.ruleId = rule.getRuleId();
        this.laneId = rule.getLaneId();
        this.userContextService = userContextService;
        
        // 解析表达式
        JsonObject json = JsonParser.parseString(rule.getExpression()).getAsJsonObject();
        this.userIds = json.getAsJsonArray("userIds").asList().stream()
                .map(e -> e.getAsLong())
                .collect(Collectors.toSet());
    }
    
    @Override
    public boolean matches(ServerHttpRequest request) {
        // 尝试从 Token 中提取用户ID
        Long userId = userContextService.tryExtractUserId(request);
        if (userId == null) {
            return false;
        }
        return userIds.contains(userId);
    }
    
    @Override
    public String getRuleId() { return ruleId; }
    
    @Override
    public String getLaneId() { return laneId; }
}
```

#### 6.3.2 服务发现泳道路由

```java
/**
 * 基于泳道的服务实例过滤器
 * 
 * 在 LoadBalancer 选择服务实例时，根据当前请求的 ColorContext
 * 过滤出对应泳道的实例。如果泳道中没有可用实例，降级到基线。
 */
@Component
public class LaneAwareServiceInstanceFilter implements ServiceInstanceListSupplier {
    
    private final ServiceInstanceListSupplier delegate;
    
    @Autowired
    private SwimLaneRegistry laneRegistry;
    
    @Override
    public Flux<List<ServiceInstance>> get() {
        return delegate.get().map(instances -> filterByLane(instances));
    }
    
    private List<ServiceInstance> filterByLane(List<ServiceInstance> instances) {
        ColorContext context = ColorContextHolder.get();
        
        if (context == null || context.isBaseline()) {
            // 基线流量: 只返回基线实例
            return instances.stream()
                    .filter(inst -> isBaselineInstance(inst))
                    .collect(Collectors.toList());
        }
        
        // 染色流量: 优先返回泳道实例
        String targetLaneId = context.getLaneId();
        List<ServiceInstance> laneInstances = instances.stream()
                .filter(inst -> targetLaneId.equals(getLaneId(inst)))
                .collect(Collectors.toList());
        
        if (!laneInstances.isEmpty()) {
            return laneInstances;
        }
        
        // 泳道无实例，降级到基线
        LaneMetricsRecorder.recordFallback(context.getLaneId(), getServiceId(instances));
        return instances.stream()
                .filter(inst -> isBaselineInstance(inst))
                .collect(Collectors.toList());
    }
    
    /**
     * 从服务实例元数据获取泳道ID
     */
    private String getLaneId(ServiceInstance instance) {
        Map<String, String> metadata = instance.getMetadata();
        return metadata != null ? metadata.getOrDefault("lane-id", "baseline") : "baseline";
    }
    
    private boolean isBaselineInstance(ServiceInstance instance) {
        return "baseline".equals(getLaneId(instance));
    }
}
```

#### 6.3.3 ThreadLocal 持有者

```java
/**
 * 染色上下文 ThreadLocal 持有者
 * 
 * 使用 TransmittableThreadLocal 支持线程池场景下的上下文传播。
 */
public final class ColorContextHolder {
    
    private static final ThreadLocal<ColorContext> CONTEXT_HOLDER = 
            new TransmittableThreadLocal<>();
    
    private ColorContextHolder() {}
    
    /**
     * 设置当前线程的染色上下文
     */
    public static void set(ColorContext context) {
        if (context != null) {
            CONTEXT_HOLDER.set(context);
            
            // 同步写入 MDC (日志关联)
            MDC.put("laneId", context.getLaneId());
            MDC.put("trafficType", context.getTrafficType().getCode());
        } else {
            clear();
        }
    }
    
    /**
     * 获取当前线程的染色上下文
     */
    public static ColorContext get() {
        return CONTEXT_HOLDER.get();
    }
    
    /**
     * 清除当前线程的染色上下文
     */
    public static void clear() {
        CONTEXT_HOLDER.remove();
        MDC.remove("laneId");
        MDC.remove("trafficType");
    }
    
    /**
     * 在代码块中设置染色上下文，执行完毕后自动清理
     */
    public static <T> T with(ColorContext context, Supplier<T> supplier) {
        ColorContext previous = get();
        try {
            set(context);
            return supplier.get();
        } finally {
            set(previous);
        }
    }
}
```

#### 6.4.2 RocketMQ Consumer 端

```java
/**
 * RocketMQ 消息染色恢复器 (Consumer 端)
 * 
 * 在消费 MQ 消息时，从消息的 UserProperty 中恢复 ColorContext，
 * 写入消费线程的 ThreadLocal，使后续调用链保持染色传播。
 */
@Component
public class ColorContextRocketMQConsumerListener implements MessageListenerConcurrently {
    
    @Override
    public ConsumeConcurrentlyStatus consumeMessage(
            List<MessageExt> messages, ConsumeConcurrentlyContext context) {
        
        for (MessageExt message : messages) {
            ColorContext colorContext = extractColorFromMessage(message);
            
            try {
                ColorContextHolder.set(colorContext);
                
                // 委托给实际的业务消费者处理
                ConsumeConcurrentlyStatus status = doConsume(message, context);
                
                return status;
            } finally {
                ColorContextHolder.clear();
            }
        }
        
        return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
    }
    
    private ColorContext extractColorFromMessage(MessageExt message) {
        String laneId = message.getUserProperty(PROP_LANE_ID);
        
        if (laneId == null || "baseline".equals(laneId)) {
            return ColorContext.baseline();
        }
        
        ColorContext ctx = new ColorContext();
        ctx.setLaneId(laneId);
        
        String trafficTypeStr = message.getUserProperty(PROP_TRAFFIC_TYPE);
        if (trafficTypeStr != null) {
            ctx.setTrafficType(TrafficType.fromCode(trafficTypeStr));
        }
        
        ctx.setTraceId(message.getUserProperty(PROP_COLOR_TRACE_ID));
        
        String tagsJson = message.getUserProperty(PROP_COLOR_TAGS);
        if (tagsJson != null) {
            try {
                Map<String, String> tags = new ObjectMapper().readValue(tagsJson, Map.class);
                ctx.setTags(tags);
            } catch (Exception ignored) {
            }
        }
        
        ctx.setSource(ColorSource.MQ_PROPAGATION);
        return ctx;
    }
}
```

### 6.5 压测流量数据隔离组件

#### 6.5.1 数据库写入拦截器

```java
/**
 * 压测流量数据库隔离拦截器
 * 
 * 在 MyBatis 执行 INSERT/UPDATE 时，如果是压测流量，
 * 自动追加压测标记字段，确保压测数据可识别、可清理。
 */
@Intercepts({
    @Signature(type = Executor.class, method = "update", 
               args = {MappedStatement.class, Object.class})
})
public class StressTestDataInterceptor implements Interceptor {
    
    private static final String TEST_FLAG_FIELD = "is_test_data";
    private static final String TEST_RUN_ID_FIELD = "test_run_id";
    
    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        ColorContext context = ColorContextHolder.get();
        
        if (context != null && context.getTrafficType() == TrafficType.STRESS_TEST) {
            MappedStatement ms = (MappedStatement) invocation.getArgs()[0];
            Object parameter = invocation.getArgs()[1];
            
            // 获取 SqlCommandType
            SqlCommandType commandType = ms.getSqlCommandType();
            
            if (commandType == SqlCommandType.INSERT || commandType == SqlCommandType.UPDATE) {
                // 通过反射设置压测标记字段
                setTestFlag(parameter, context);
            }
        }
        
        return invocation.proceed();
    }
    
    private void setTestFlag(Object parameter, ColorContext context) {
        try {
            // 处理 MyBatis 参数对象
            Object target = parameter;
            if (parameter instanceof MapperMethod.ParamMap) {
                MapperMethod.ParamMap<?> paramMap = (MapperMethod.ParamMap<?>) parameter;
                // 尝试获取实体参数
                for (Object value : paramMap.values()) {
                    if (value != null && !value.getClass().isPrimitive() 
                            && !value.getClass().getName().startsWith("java.")) {
                        target = value;
                        break;
                    }
                }
            }
            
            if (target != null) {
                setFieldValue(target, TEST_FLAG_FIELD, 1);
                setFieldValue(target, TEST_RUN_ID_FIELD, 
                        context.getTags().get("test_run_id"));
            }
        } catch (Exception e) {
            // 设置失败时记录日志但不阻断流程
            log.warn("Failed to set stress test flag on entity: {}", e.getMessage());
        }
    }
    
    private void setFieldValue(Object target, String fieldName, Object value) 
            throws NoSuchFieldException, IllegalAccessException {
        Field field = target.getClass().getDeclaredField(fieldName);
        field.setAccessible(true);
        field.set(target, value);
    }
}
```

## 8. 流量影子 (Traffic Shadowing)

### 8.1 设计目的

将生产环境基线流量异步复制一份到目标泳道，不影响真实用户响应。用于：
- 新版本验证：在不影响用户的情况下验证新代码的正确性
- 性能对比：对比新旧版本的性能指标
- A/B 预验证：在正式灰度前提前发现问题

### 8.2 影子流量架构

```text
客户端请求 (基线)
     │
     ▼
API Gateway
     │
     ├─ 正常处理 → 路由到基线实例 → 返回响应给客户端
     │
     └─ 异步复制 (Shadow Asynchronizer):
          │
          ├─ 深拷贝请求对象
          ├─ 修改染色标记: laneId → shadow-target-lane
          ├─ 设置 trafficType = SHADOW
          ├─ 异步发送到影子泳道
          │
          ├─ 影子响应 → 对比引擎 → 结果差异分析
          │
          └─ 丢弃影子响应 (不影响客户端)
```

### 8.3 影子流量实现

```java
/**
 * 流量影子异步处理器
 */
@Component
public class TrafficShadowProcessor {
    
    @Autowired
    private RestTemplate shadowRestTemplate;
    
    @Autowired
    private ShadowResultComparator resultComparator;
    
    @Async("shadowExecutor")
    public void shadowRequest(ShadowRequestContext context) {
        try {
            // 构建影子请求
            HttpHeaders headers = new HttpHeaders();
            headers.add("X-Lane-Id", context.getTargetLaneId());
            headers.add("X-Traffic-Type", TrafficType.SHADOW.getCode());
            headers.add("X-Shadow-Origin-Trace", context.getOriginalTraceId());
            
            HttpEntity<byte[]> entity = new HttpEntity<>(context.getRequestBody(), headers);
            
            // 发送影子请求
            ResponseEntity<byte[]> response = shadowRestTemplate.exchange(
                    context.getTargetUrl(),
                    context.getHttpMethod(),
                    entity,
                    byte[].class
            );
            
            // 对比结果 (可选, 仅对幂等接口)
            if (context.isComparable()) {
                resultComparator.compare(
                        context.getOriginalTraceId(),
                        context.getOriginalResponse(),
                        response.getBody()
                );
            }
            
            // 记录影子流量指标
            ShadowMetrics.record(
                    context.getTargetLaneId(),
                    response.getStatusCode().value(),
                    System.currentTimeMillis() - context.getStartMillis()
            );
            
        } catch (Exception e) {
            // 影子流量异常不影响主流程
            log.warn("Shadow request failed for trace {}: {}", 
                    context.getOriginalTraceId(), e.getMessage());
            ShadowMetrics.recordError(context.getTargetLaneId(), e);
        }
    }
}
```

## 11. 异常处理与容错

### 11.1 异常场景与处理策略

| 异常场景 | 处理策略 | 降级方案 |
| --- | --- | --- |
| 泳道实例全部不可用 | 自动降级到基线实例 | 记录降级日志 + 指标 |
| Nacos 规则加载失败 | 使用本地缓存的规则（最近一次成功） | 5分钟后重试 |
| 染色上下文传播失败 | 当前调用走基线 | 记录告警，不阻断业务 |
| 泳道配置中心不可达 | 使用本地兜底配置 | 所有请求走基线 |
| MQ 消息缺少染色标记 | 消费时标记为基线流量 | 正常消费 |
| 泳道数据库连接失败 | 泳道服务实例自动重启 | 如果持续失败，标记泳道为 DEGRADED |

### 11.2 熔断保护

当泳道持续异常时，自动熔断该泳道，将流量切回基线：

```java
/**
 * 泳道熔断器
 */
@Component
public class LaneCircuitBreaker {
    
    private final Map<String, CircuitBreaker> laneBreakers = new ConcurrentHashMap<>();
    
    @Autowired
    private SwimLaneRegistry laneRegistry;
    
    /**
     * 判断泳道是否被熔断
     */
    public boolean isCircuitOpen(String laneId) {
        CircuitBreaker breaker = laneBreakers.computeIfAbsent(laneId, this::createBreaker);
        return !breaker.tryAcquire();
    }
    
    /**
     * 记录泳道请求结果
     */
    public void recordResult(String laneId, boolean success, long latencyMs) {
        CircuitBreaker breaker = laneBreakers.get(laneId);
        if (breaker != null) {
            breaker.record(success, latencyMs);
        }
    }
    
    private CircuitBreaker createBreaker(String laneId) {
        return CircuitBreaker.builder()
                .failureRateThreshold(0.5)          // 错误率 > 50%
                .slowCallRateThreshold(0.8)          // 慢调用比例 > 80%
                .slowCallDurationThreshold(Duration.ofSeconds(5))
                .minimumNumberOfCalls(20)             // 最少 20 次调用才统计
                .waitDurationInOpenState(Duration.ofSeconds(30))
                .onOpen(() -> {
                    log.warn("Lane {} circuit breaker OPENED, traffic will fallback to baseline", laneId);
                    MetricsRecorder.recordLaneCircuitOpen(laneId);
                })
                .onClose(() -> {
                    log.info("Lane {} circuit breaker CLOSED, traffic resumes", laneId);
                })
                .build();
    }
}
```

### 12.1 泳道管理权限

| 操作 | 所需权限 |

| 查看泳道列表 | `LANE:READ` (开发人员) |
| 查看泳道指标 | `LANE:METRICS:READ` (开发人员) |
| 手动指定染色 | `LANE:COLOR:MANUAL` (仅测试人员) |

### 12.2 安全约束

1. **泳道隔离强制校验**：压测流量（trafficType=STRESS_TEST）禁止路由到基线实例
2. **敏感接口禁止影子流量**：支付接口、退款接口不参与流量影子
3. **染色标记防伪造**：外部请求携带的 `X-Lane-Id` 需验证泳道存在且请求来源可信（内网IP或特定Token）
4. **泳道过期自动回收**：防止资源泄漏，默认最大 72 小时
5. **泳道数量限制**：同时活跃的泳道不超过 20 个，防止资源过度消耗
6. **压测数据物理隔离**：压测流量写入的数据必须带 `is_test_data=1` 标记，定期清理
7. **审计日志**：所有泳道创建/销毁/规则变更操作记录审计日志
8. **外部请求染色校验**：网关层对外部来源的 `X-Lane-Id` 请求头进行白名单校验，防止恶意路由

### 14.2 状态定义

| 状态 | 说明 | 接受流量 | 可操作 |
| --- | --- | --- | --- |
| CREATING | 泳道创建中，CI/CD 部署进行中 | 否 | 不可修改规则 |
| ACTIVE | 泳道就绪，正常接受染色流量 | 是 | 可修改规则、延长过期 |
| DRAINING | 排空中，不再接受新请求，等待处理中的请求完成 | 否（新请求降级基线） | 不可修改 |
| DEGRADED | 泳道实例部分不可用，部分流量降级到基线 | 是（部分） | 可修复后恢复 ACTIVE |
| DELETED | 泳道已销毁，资源已回收 | 否 | 不可操作 |

```java
/**
 * 泳道实例缓存
 * 监听 Nacos 变更，按 lane-id 分组缓存
 */
@Component
public class LaneInstanceCache {
    
    private final ConcurrentHashMap<String, LaneInstanceBucket> cache = new ConcurrentHashMap<>();
    
    /**
     * 获取指定泳道的服务实例
     */
    public List<ServiceInstance> getInstances(String serviceName, String laneId) {
        LaneInstanceBucket bucket = cache.get(serviceName);
        if (bucket == null) {
            return Collections.emptyList();
        }
        return bucket.getByLane(laneId);
    }
    
    /**
     * Nacos 实例变更回调
     */
    @NacosNamingListener(serviceName = "${spring.application.name}")
    public void onInstancesChanged(List<ServiceInstance> instances) {
        Map<String, List<ServiceInstance>> byLane = instances.stream()
                .collect(Collectors.groupingBy(
                        inst -> inst.getMetadata().getOrDefault("lane-id", "baseline")));
        
        cache.put(serviceName, new LaneInstanceBucket(byLane));
    }
}
```

### 21.3 FAQ

**Q1: 泳道和独立环境（Staging）有什么区别？**

A: 独立环境需要部署全套服务，成本高、维护复杂。泳道只需部署变更中的 1~3 个服务，其余服务复用基线实例，大幅降低资源开销和运维复杂度。

**Q2: 压测流量染色和独立压测环境相比有什么优势？**

A: 染色方案在生产环境直接压测（数据物理隔离），能发现更多真实环境问题。但部分高安全要求场景仍建议使用独立压测环境。两种方案互补使用。

**Q3: 流量染色会增加多少延迟？**

A: 全链路染色的额外开销 < 3ms（P99），主要来自 HTTP Header 解析和 ThreadLocal 操作。对用户体验无感知影响。

**Q4: 泳道中的数据库是否需要独立？**

A: 不需要。泳道中的服务共享基线数据库，通过 `is_test_data` 字段和 `test_run_id` 区分压测数据。业务数据层面，泳道流量产生的真实用户数据也写入主库，无需额外隔离。

**Q5: 如果 Nacos 宕机，染色路由是否还能工作？**
