# 向量数据库基础设施与嵌入向量全生命周期管理服务 详细设计

## 1. 概述

### 1.1 模块定位

向量数据库是 PrimeTop AI 辅助学习平台的核心基础设施层，为 RAG 检索增强生成、知识图谱关联查询、题目相似度计算、个性化推荐、语义去重等多个上层业务提供底层的向量存储与相似性检索能力。

本模块负责管理从嵌入模型调用、向量数据写入、索引构建、相似性检索到向量数据过期归档的完整生命周期，是连接 AI 能力层（嵌入模型）和业务服务层（RAG、推荐、搜索）之间的桥梁。

### 1.2 核心职责

| 职责 | 说明 |
| --- | --- |
| 嵌入向量生产 | 统一调度嵌入模型，将文本/图片转为高维向量 |
| 向量存储管理 | 按业务域组织 Collection，管理向量数据的增删改查 |
| 索引构建与优化 | 构建和维护 ANN 索引，保证检索延迟与召回率 |
| 相似性检索服务 | 提供统一的向量检索 API，支持过滤、混合检索 |
| 向量生命周期 | 管理向量数据的版本、过期、归档和批量重建 |
| 多模型适配 | 支持多种嵌入模型共存，平滑切换与灰度迁移 |
| 容量与性能监控 | 监控存储容量、查询延迟、召回率等核心指标 |

## 2. 技术选型

### 2.1 向量数据库选型：Milvus 2.x

| 候选方案 | 维度 | 适用场景 | 结论 |
| --- | --- | --- | --- |
| **Milvus 2.x** | 十亿级向量、云原生、丰富的索引类型、成熟的混合检索 | 大规模生产环境 | ✅ **选定** |
| pgvector | 千万级、与 PostgreSQL 一体化、运维简单 | 中小规模、原型阶段 | 备选（MVP 阶段可用） |
| Qdrant | 百万至千万级、Rust 高性能、过滤效率好 | 中等规模、高过滤场景 | 观察 |
| Weaviate | 百万级、内置嵌入模块、GraphQL API | 快速原型、一体化方案 | 不选（嵌入模型需自控） |
| FAISS | 库而非服务、需自行封装、无分布式 | 单机研究、嵌入式场景 | 不选 |

**选型理由：**
1. PrimeTop 知识库预估向量规模：题目 500 万+、知识点 50 万+、教材内容 200 万+、AI 对话摘要 1000 万+，总计 2000 万级，后续持续增长。
2. Milvus 支持十亿级向量扩展，存算分离架构利于独立扩缩容。
3. 丰富的索引类型（HNSW、IVF_FLAT、IVF_SQ8、DISKANN）适应不同场景。
4. 原生支持标量字段过滤，满足"按学科+年级+教材版本"预过滤的需求。
5. 活跃社区与完善文档，国内教育行业已有生产案例。

### 2.2 嵌入模型选型

| 模型 | 维度 | 语言 | 最大Token | 部署方式 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| **BGE-M3** | 1024 | 多语言 | 8192 | 本地 GPU / API | 通用文本嵌入（主模型） |
| **OpenAI text-embedding-3-small** | 1536 | 多语言 | 8191 | API | 英文内容、国际化备用 |
| **M3E-large** | 1024 | 中文优 | 512 | 本地 GPU | 短文本、题目题干 |
| **BGE-VL** | 1024 | 多模态 | - | 本地 GPU | 图片题目、图文混合 |

**主模型策略：**
- **BGE-M3** 作为通用文本嵌入主模型，覆盖中文为主的教育内容
- 短文本场景（题目标题、知识点名称）使用 **M3E-large** 以降低延迟
- 图片理解场景使用 **BGE-VL** 多模态嵌入
- 所有嵌入向量统一归一化后存储，支持余弦相似度计算

### 2.3 MVP 阶段简化方案

MVP 阶段向量规模约 200 万以内，可采用 **pgvector** 作为简化方案：

```sql
-- pgvector MVP 方案
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE embedding_store (
    id BIGSERIAL PRIMARY KEY,
    collection VARCHAR(64) NOT NULL,
    content_id BIGINT NOT NULL,
    content_type VARCHAR(32) NOT NULL,
    embedding vector(1024) NOT NULL,
    metadata JSONB DEFAULT '{}',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- HNSW 索引
CREATE INDEX idx_embedding_store_vec 
ON embedding_store 
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- 过滤索引
CREATE INDEX idx_embedding_store_collection 
ON embedding_store (collection, content_type);
```

后续随数据量增长平滑迁移至 Milvus，迁移策略见 §8。

## 3. 数据模型

### 3.1 Milvus Collection 设计

按业务域划分 Collection，每个 Collection 承载一类内容的向量数据。

#### 3.1.1 Collection 总览

| Collection 名称 | 业务域 | 内容类型 | 预估规模 | 向量维度 | 嵌入模型 |
| --- | --- | --- | --- | --- | --- |

| `knowledge_point_vectors` | 知识点 | 知识点描述/定义 | 50万 | 1024 | BGE-M3 |
| `textbook_content_vectors` | 教材内容 | 课文/讲解/例题 | 200万 | 1024 | BGE-M3 |

### 3.2 索引设计

#### 3.2.1 向量索引选型

| 索引类型 | 适用场景 | 召回率 | 内存占用 | 构建速度 | 选型决策 |
| --- | --- | --- | --- | --- | --- |
| **HNSW** | < 1000万，低延迟 | 高（99%+） | 高 | 中 | ✅ 默认选择 |
| **IVF_FLAT** | 1000万-1亿，中等延迟 | 中高（95%+） | 中 | 快 | 大数据量备选 |
| **DISKANN** | > 1亿，可接受较高延迟 | 高 | 低（磁盘） | 慢 | 超大规模备选 |
| **FLAT** | < 10万，暴力搜索 | 100% | 低 | 即时 | 测试/小数据 |

**MVP 默认配置 — HNSW：**

```python
index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",          # 余弦相似度（向量已归一化）
    "params": {
        "M": 16,                      # 每层最大连接数，影响召回率与内存
        "efConstruction": 256,        # 构建时搜索宽度，影响索引质量
    }
}
```

**查询参数调优：**

```python
search_params = {
    "metric_type": "COSINE",
    "params": {
        "ef": 128,   # 查询时搜索宽度，越大召回越高、延迟越大
    }
}
```

| ef 值 | 召回率@10 | 平均延迟(P99) | 适用场景 |
| --- | --- | --- | --- |
| 64 | 92% | 8ms | 实时推荐、快速预筛 |
| 128 | 97% | 15ms | **默认值** — 平衡精度与速度 |
| 256 | 99% | 30ms | 精确匹配、去重场景 |
| 512 | 99.5%+ | 60ms | 离线分析、全量比对 |

### 3.3 元数据管理

向量的业务元数据（非向量字段）需要与业务数据库保持一致性。采用 **双写 + 异步校验** 策略：

```sql
-- PostgreSQL 中的向量元数据注册表
CREATE TABLE vector_metadata_registry (
    id BIGSERIAL PRIMARY KEY,
    pk VARCHAR(128) NOT NULL UNIQUE,           -- Milvus 主键
    collection_name VARCHAR(64) NOT NULL,       -- 所属 Collection
    content_id BIGINT NOT NULL,                 -- 业务内容ID
    content_type VARCHAR(32) NOT NULL,          -- 内容类型
    content_hash VARCHAR(64) NOT NULL,          -- 内容 Hash（用于变更检测）
    embedding_model VARCHAR(64) NOT NULL,       -- 嵌入模型名
    model_version VARCHAR(32) NOT NULL,         -- 模型版本
    vector_status VARCHAR(16) DEFAULT 'ACTIVE', -- ACTIVE / PENDING_UPDATE / DELETED
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    
    UNIQUE (collection_name, content_id)
);

CREATE INDEX idx_vm_registry_content ON vector_metadata_registry (content_type, content_id);
CREATE INDEX idx_vm_registry_status ON vector_metadata_registry (vector_status);
CREATE INDEX idx_vm_registry_hash ON vector_metadata_registry (content_hash);
CREATE INDEX idx_vm_registry_model ON vector_metadata_registry (embedding_model, model_version);
```

```python
class TextPreprocessor:
    """嵌入前文本预处理"""
    
    @staticmethod
    def preprocess(text: str, content_type: str) -> str:
        # 1. 清理多余空白
        text = re.sub(r'\s+', ' ', text).strip()
        
        # 2. 根据内容类型拼接上下文
        if content_type == 'question':
            # 题目：拼接题干+选项+知识点标签
            return TextPreprocessor._enrich_question(text)
        elif content_type == 'knowledge_point':
            # 知识点：拼接定义+所属章节+学科
            return TextPreProcessor._enrich_kp(text)
        elif content_type == 'textbook_content':
            # 教材内容：拼接章节路径+正文
            return TextPreprocessor._enrich_textbook(text)
        
        return text
    
    @staticmethod
    def _enrich_question(text: str) -> str:
        """题目文本增强：拼接元数据上下文"""
        # 示例：将学科、学段、章节信息拼接到题目前方
        # "【初中数学-二次函数】已知抛物线y=ax²+bx+c..."
        # 这样嵌入向量能隐式编码学科和章节信息
        pass
    
    @staticmethod
    def truncate(text: str, model: str) -> str:
        """按模型最大 token 数截断文本"""
        max_tokens = EMBEDDING_MODELS[model]['max_tokens']
        tokens = tokenizer.encode(text)
        if len(tokens) > max_tokens:
            logger.warning(f"Text truncated from {len(tokens)} to {max_tokens} tokens")
            tokens = tokens[:max_tokens]
        return tokenizer.decode(tokens)
```

### 5.2 嵌入模型调度层

```python
from abc import ABC, abstractmethod
from typing import List, Optional
import hashlib
import time

class EmbeddingProvider(ABC):
    """嵌入模型提供者抽象接口"""
    
    @abstractmethod
    def embed(self, texts: List[str]) -> List[List[float]]:
        pass
    
    @abstractmethod
    def dim(self) -> int:
        pass
    
    @abstractmethod
    def max_tokens(self) -> int:
        pass


class BGEM3Provider(EmbeddingProvider):
    """BGE-M3 本地部署 / API 调用"""
    
    def __init__(self, endpoint: str, api_key: Optional[str] = None):
        self.endpoint = endpoint
        self.api_key = api_key
        self._dim = 1024
        self._max_tokens = 8192
    
    def embed(self, texts: List[str]) -> List[List[float]]:
        resp = self._call_api(texts)
        # 归一化向量（L2 normalization）
        return [self._normalize(vec) for vec in resp['embeddings']]
    
    def dim(self) -> int:
        return self._dim
    
    def max_tokens(self) -> int:
        return self._max_tokens
    
    @staticmethod
    def _normalize(vec: List[float]) -> List[float]:
        import numpy as np
        arr = np.array(vec, dtype=np.float32)
        norm = np.linalg.norm(arr)
        if norm > 0:
            arr = arr / norm
        return arr.tolist()


class OpenAIEmbeddingProvider(EmbeddingProvider):
    """OpenAI text-embedding-3-small/large"""
    
    def __init__(self, model: str = "text-embedding-3-small"):
        self.model = model
        self._dim = 1536 if "small" in model else 3072
    
    def embed(self, texts: List[str]) -> List[List[float]]:
        import openai
        resp = openai.embeddings.create(
            model=self.model,
            input=texts,
            encoding_format="float"
        )
        return [self._normalize(d.embedding) for d in resp.data]
    
    def dim(self) -> int:
        return self._dim
    
    def max_tokens(self) -> int:
        return 8191


class EmbeddingRouter:
    """
    嵌入模型路由器 — 根据内容类型、负载情况路由到合适的嵌入模型
    """
    
    def __init__(self):
        self.providers: dict[str, EmbeddingProvider] = {}
        self.default_model: str = "bge-m3"
        self.fallback_model: str = "openai-text-embedding-3-small"
        
        # 内容类型 → 首选模型映射
        self.model_routing: dict[str, str] = {
            "question": "bge-m3",           # 题目用 BGE-M3
            "knowledge_point": "bge-m3",    # 知识点用 BGE-M3
            "textbook_content": "bge-m3",   # 教材内容用 BGE-M3
            "short_text": "m3e-large",      # 短文本用 M3E
            "image": "bge-vl",              # 图片用 BGE-VL
            "conversation": "bge-m3",       # 对话摘要用 BGE-M3
        }
    
    def embed(
        self,
        texts: List[str],
        content_type: str = "question",
        model: Optional[str] = None,
        batch_size: int = 32
    ) -> tuple[List[List[float]], str]:
        """
        统一嵌入接口
        返回: (向量列表, 使用的模型名)
        """
        model_name = model or self.model_routing.get(content_type, self.default_model)
        provider = self.providers.get(model_name)
        
        if not provider:
            # 降级到备用模型
            model_name = self.fallback_model
            provider = self.providers[model_name]
            logger.warning(f"Model {model_name} unavailable, fallback to {self.fallback_model}")
        
        all_embeddings = []
        for i in range(0, len(texts), batch_size):
            batch = texts[i:i + batch_size]
            try:
                embeddings = provider.embed(batch)
                all_embeddings.extend(embeddings)
            except RateLimitError:
                # 限流降级
                fallback = self.providers[self.fallback_model]
                embeddings = fallback.embed(batch)
                all_embeddings.extend(embeddings)
                model_name = self.fallback_model
        
        return all_embeddings, model_name
```

### 5.3 向量写入服务

```python
class VectorWriteService:
    """向量写入服务"""
    
    def __init__(self, milvus_client, embedding_router: EmbeddingRouter, 
                 metadata_repo, event_publisher):
        self.milvus = milvus_client
        self.embedder = embedding_router
        self.metadata_repo = metadata_repo
        self.events = event_publisher
    
    async def insert_batch(
        self,
        collection: str,
        items: List[dict],
        auto_embed: bool = True
    ) -> dict:
        """
        批量写入向量
        1. 文本预处理
        2. 调用嵌入模型生成向量
        3. 写入 Milvus
        4. 注册元数据到 PostgreSQL
        5. 发布事件通知
        """
        start = time.time()
        
        # Step 1: 文本预处理
        texts = []
        for item in items:
            text = TextPreprocessor.preprocess(item['text'], item['content_type'])
            text = TextPreprocessor.truncate(text, self.embedder.default_model)
            texts.append(text)
            item['content_hash'] = self._compute_hash(text)
        
        # Step 2: 嵌入向量生成
        if auto_embed:
            embeddings, model_used = self.embedder.embed(
                texts=texts,
                content_type=items[0].get('content_type', 'question')
            )
        else:
            embeddings = [item.pop('query_vector') for item in items]
            model_used = "manual"
        
        # Step 3: 组装 Milvus 数据
        insert_data = []
        for item, embedding in zip(items, embeddings):
            record = {
                "pk": item['pk'],
                "embedding": embedding,
                "content_id": item['content_id'],
                "content_type": item['content_type'],
                "embedding_model": model_used,
                "model_version": EMBEDDING_MODELS.get(model_used, {}).get('version', 'unknown'),
                "content_hash": item['content_hash'],
                "status": 0,  # 正常
                "created_at": int(time.time()),
                "updated_at": int(time.time()),
            }
            # 合并业务元数据
            record.update(item.get('metadata', {}))
            insert_data.append(record)
        
        # Step 4: 写入 Milvus
        result = self.milvus.insert(collection_name=collection, data=insert_data)
        
        # Step 5: 注册元数据
        for record in insert_data:
            self.metadata_repo.upsert({
                "pk": record['pk'],
                "collection_name": collection,
                "content_id": record['content_id'],
                "content_type": record['content_type'],
                "content_hash": record['content_hash'],
                "embedding_model": model_used,
                "model_version": record['model_version'],
                "vector_status": "ACTIVE",
            })
        
        # Step 6: 发布事件
        self.events.publish("vector.inserted", {
            "collection": collection,
            "count": len(items),
            "model": model_used,
        })
        
        took_ms = int((time.time() - start) * 1000)
        return {
            "inserted": result.insert_count,
            "failed": 0,
            "errors": [],
            "took_ms": took_ms,
            "embedding_model": model_used,
        }
    
    async def update(self, collection: str, pk: str, text: str, metadata: dict) -> dict:
        """
        更新向量（先删后插策略）
        """
        new_hash = self._compute_hash(text)
        existing = self.metadata_repo.get_by_pk(pk)
        
        if existing and existing['content_hash'] == new_hash:
            # 内容未变化，仅更新元数据
            self.milvus.update(collection, pk, metadata)
            return {"updated": 1, "re_embedded": False}
        
        # 内容变化，重新嵌入
        embeddings, model_used = self.embedder.embed([text])
        self.milvus.upsert(collection, [{
            "pk": pk,
            "embedding": embeddings[0],
            "content_hash": new_hash,
            "embedding_model": model_used,
            "updated_at": int(time.time()),
            **metadata,
        }])
        
        self.metadata_repo.update(pk, {
            "content_hash": new_hash,
            "embedding_model": model_used,
            "vector_status": "ACTIVE",
        })
        
        return {"updated": 1, "re_embedded": True}
    
    async def delete(self, collection: str, pk: str, hard_delete: bool = False) -> dict:
        """
        删除向量
        hard_delete=False: 逻辑删除（标记 status=2）
        hard_delete=True: 物理删除
        """
        if hard_delete:
            self.milvus.delete(collection, f'pk == "{pk}"')
            self.metadata_repo.update(pk, {"vector_status": "DELETED"})
        else:
            self.milvus.update(collection, pk, {"status": 2})
            self.metadata_repo.update(pk, {"vector_status": "DELETED"})
        
        return {"deleted": 1}
    
    @staticmethod
    def _compute_hash(text: str) -> str:
        return hashlib.sha256(text.encode('utf-8')).hexdigest()[:32]
```

```python
                "content_type": event['content_type'],
                "text": event['content_text'],
                "metadata": event.get('metadata', {}),
            }]

        await self.writer.update(
            collection=collection,
            pk=pk,
            text=event['content_text'],
```

```python
class VectorConsistencyJob:
    """
    定时任务：校验业务数据与向量数据的一致性，修复不一致项
    
    调度：每天凌晨 02:00 执行
    """
    
    BATCH_SIZE = 500
    
    async def run(self):
        # 1. 扫描 PostgreSQL 中的内容数据
        # 2. 对比 content_hash，找出内容已变化但向量未更新的记录
        # 3. 对比向量状态，找出业务已删除但向量仍存在的记录
        # 4. 触发补偿更新/删除
        
        # 检查"内容已变更但向量未更新"
        stale_items = await self.metadata_repo.find_stale_vectors(limit=self.BATCH_SIZE)
        
        for item in stale_items:
            logger.info(f"Re-embedding stale vector: {item['pk']}")
            await self.writer.update(
                collection=item['collection_name'],
                pk=item['pk'],
                text=item['text'],
                metadata=item['metadata']
            )
        
        # 检查"已删除内容但向量仍存在"
        orphan_vectors = await self.metadata_repo.find_orphan_vectors(limit=self.BATCH_SIZE)
        
        for item in orphan_vectors:
            logger.info(f"Deleting orphan vector: {item['pk']}")
            await self.writer.delete(
                collection=item['collection_name'],
                pk=item['pk'],
                hard_delete=True
            )
        
        logger.info(f"Consistency job done: fixed {len(stale_items)} stale, "
                     f"removed {len(orphan_vectors)} orphan")
```

### 6.4 嵌入模型版本迁移

当嵌入模型升级时（如 BGE-M3 v1 → v2），需要全量重建向量索引。

```python
class ModelMigrationService:
    """
    嵌入模型版本迁移服务
    
    策略：Shadow Collection 双写双读 → 数据校验 → 切换流量 → 清理旧 Collection
    """
    
    async def migrate(
        self,
        collection: str,
        old_model: str,
        new_model: str,
        batch_size: int = 500,
        dry_run: bool = False
    ) -> dict:
        """
        全量模型迁移流程
        
        Step 1: 创建 Shadow Collection（如 question_vectors_v2）
        Step 2: 双写：新数据同时写入旧 Collection 和 Shadow Collection
        Step 3: 批量回填：将旧 Collection 的数据用新模型重新嵌入写入 Shadow
        Step 4: 数据校验：对比行数、抽样检查相似性排序差异
        Step 5: 流量切换：读取流量灰度切换到 Shadow Collection
        Step 6: 清理：下线旧 Collection
        """
        shadow_collection = f"{collection}_v2"
        
        # Step 1: 创建 Shadow Collection（相同Schema，不同嵌入模型字段）
        await self._create_shadow_collection(shadow_collection, collection, new_model)
        
        # Step 2: 开启双写
        self._enable_dual_write(collection, shadow_collection)
        
        # Step 3: 批量回填
        stats = await self._backfill(collection, shadow_collection, new_model, batch_size, dry_run)
        
        # Step 4: 校验
        if not dry_run:
            await self._verify(collection, shadow_collection)
        
        return {
            "shadow_collection": shadow_collection,
            "old_model": old_model,
            "new_model": new_model,
            "backfilled": stats['total'],
            "duration_seconds": stats['duration'],
            "dry_run": dry_run,
        }
    
    async def _backfill(self, source, target, new_model, batch_size, dry_run):
        """
        批量读取源 Collection 数据，用新模型重新嵌入，写入目标 Collection
        """
        total = 0
        start = time.time()
        
        # 使用 Milvus QueryIterator 分批读取
        iterator = self.milvus.query_iterator(
            collection_name=source,
            batch_size=batch_size,
            output_fields=["pk", "content_id", "content_type"],
            filter='status == 0'  # 只迁移正常状态的数据
        )
        
        batch = []
        while True:
            rows = iterator.next()
            if not rows:
                break
            
            # 从业务数据库获取原始文本
            texts = await self.content_service.get_texts([r['content_id'] for r in rows])
            
            # 用新模型嵌入
            embeddings, model_used = self.embedder.embed(
                texts, model=new_model
            )
            
            for row, text, embedding in zip(rows, texts, embeddings):
                batch.append({
                    "pk": row['pk'],
                    "embedding": embedding,
                    "embedding_model": model_used,
                    **{k: v for k, v in row.items() if k != 'embedding'}
                })
            
            if len(batch) >= batch_size:
                if not dry_run:
                    self.milvus.insert(target, batch)
                total += len(batch)
                logger.info(f"Backfilled {total} vectors...")
                batch = []
        
        # 写入剩余
        if batch and not dry_run:
            self.milvus.insert(target, batch)
            total += len(batch)
        
        return {"total": total, "duration": int(time.time() - start)}
    
    async def _verify(self, old_collection, new_collection):
        """
        校验新旧 Collection 数据一致性
        """
        old_count = self.milvus.num_entities(old_collection)
        new_count = self.milvus.num_entities(new_collection)
        
        if abs(old_count - new_count) / old_count > 0.01:
            raise VectorMigrationError(
                f"Row count mismatch: old={old_count}, new={new_count}, "
                f"diff_ratio={abs(old_count - new_count) / old_count:.4f}"
            )
        
        # 抽样 100 条做相似性排序对比
        test_queries = ["一元二次方程", "光合作用", "辛亥革命", "英语现在完成时"]
        for q in test_queries:
            old_results = self.milvus.search(old_collection, q, top_k=10)
            new_results = self.milvus.search(new_collection, q, top_k=10)
            overlap = len(set(r['pk'] for r in old_results) & set(r['pk'] for r in new_results))
            logger.info(f"Query '{q}': top-10 overlap = {overlap}/10")
            if overlap < 6:
                logger.warning(f"Low overlap for query '{q}', manual review needed")
        
        logger.info(f"Verification passed: old_count={old_count}, new_count={new_count}")
```

```python
class HybridSearchEngine:
    """混合检索引擎：向量 + BM25 + 知识图谱"""
    
    async def search(
        self,
        collection: str,
        query: str,
        top_k: int = 10,
        vector_weight: float = 0.7,
        bm25_weight: float = 0.3,
        filter: dict = None,
        rerank: bool = True,

        """
        # Step 1: 并行召回
        vector_task = self._vector_search(collection, query, top_k * 5, filter)
        bm25_task = self._bm25_search(collection, query, top_k * 5, filter)
        
        vector_results, bm25_results = await asyncio.gather(
            vector_task, bm25_task, return_exceptions=True
        )
        
        # Step 2: 分数融合 — Reciprocal Rank Fusion (RRF)
        fused = self._rrf_fuse(
            vector_results if not isinstance(vector_results, Exception) else [],
            bm25_results if not isinstance(bm25_results, Exception) else [],
            vector_weight,
            bm25_weight
        )
        
        # Step 3: 重排序（可选）
        if rerank and len(fused) > top_k:
            fused = await self._rerank(query, fused, top_k)
        
        return fused[:top_k]
    
    def _rrf_fuse(
        self,
        vector_results: List[dict],
        bm25_results: List[dict],
        vector_weight: float,
        bm25_weight: float,
        k: int = 60  # RRF 平滑参数
    ) -> List[dict]:
        """
        Reciprocal Rank Fusion 融合算法
        score = Σ weight_i / (k + rank_i)
        """
        scores: dict[str, float] = {}
        metadata: dict[str, dict] = {}
        
        for rank, item in enumerate(vector_results):
            pk = item['pk']
            scores[pk] = scores.get(pk, 0) + vector_weight / (k + rank + 1)
            metadata[pk] = item
        
        for rank, item in enumerate(bm25_results):
            pk = item['pk']
            scores[pk] = scores.get(pk, 0) + bm25_weight / (k + rank + 1)
            if pk not in metadata:
                metadata[pk] = item
        
        # 排序
        sorted_pks = sorted(scores.keys(), key=lambda x: scores[x], reverse=True)
        return [
            {**metadata[pk], "fused_score": scores[pk]}
            for pk in sorted_pks
        ]
    
    async def _rerank(
        self,
        query: str,
        candidates: List[dict],
        top_k: int
    ) -> List[dict]:
        """
        使用 BGE-Reranker-V2 进行交叉编码器精排
        """
        pairs = [[query, c.get('text', '')] for c in candidates]
        scores = await self.reranker.predict_batch(pairs)
        
        for candidate, score in zip(candidates, scores):
            candidate['rerank_score'] = score
        
        candidates.sort(key=lambda x: x['rerank_score'], reverse=True)
        return candidates[:top_k]
```

### 9.1 查询结果缓存

```python
class VectorSearchCache:
    """
    向量检索结果缓存
    
    场景：热门问题的相似题检索结果可缓存复用
    
    缓存层级：
    L1: 本地 LRU 缓存（单实例，超快）
    L2: Redis 分布式缓存（跨实例共享）
    """
    
    def __init__(self, redis_client, local_size: int = 10000, ttl: int = 3600):
        self.redis = redis_client
        self.ttl = ttl
        self._local_cache = {}  # 简化版 LRU
    
    async def get(self, cache_key: str) -> Optional[List[dict]]:
        """L1 → L2 → Miss"""
        # L1
        if cache_key in self._local_cache:
            return self._local_cache[cache_key]
        
        # L2
        data = await self.redis.get(f"vec_search:{cache_key}")
        if data:
            results = json.loads(data)
            self._local_cache[cache_key] = results
            return results
        
        return None
    
    async def set(self, cache_key: str, results: List[dict]):
        """写入缓存"""
        self._local_cache[cache_key] = results
        await self.redis.setex(
            f"vec_search:{cache_key}",
            self.ttl,
            json.dumps(results, ensure_ascii=False)
        )
    
    def make_key(self, collection: str, query: str, filter: dict, top_k: int) -> str:
        """生成缓存键"""
        raw = f"{collection}|{query}|{json.dumps(filter, sort_keys=True)}|{top_k}"
        return hashlib.md5(raw.encode()).hexdigest()
```

## 11. 错误处理与降级策略

### 11.1 错误处理矩阵

| 故障场景 | 影响范围 | 处理策略 | 用户感知 |
| --- | --- | --- | --- |
| Milvus 节点宕机 | 向量检索不可用 | 自动故障转移到健康节点 | 部分搜索结果降级 |
| Milvus 全集群不可用 | 所有向量检索失败 | 降级为 BM25 全文检索 | 搜索质量略降 |
| 嵌入模型 API 超时 | 新向量写入失败 | 写入 Kafka 重试队列，稍后补偿 | 新内容搜索延迟 |
| 嵌入模型返回错误 | 嵌入生成失败 | 切换备用嵌入模型 | 无感知 |
| MinIO 存储满 | 向量写入失败 | 告警 + 自动扩容 + 拒绝写入 | 新内容暂时无法搜索 |
| etcd 集群异常 | 元数据不一致 | 告警 + 人工介入 | 可能搜索异常 |
| Redis 缓存不可用 | 缓存穿透到 Milvus | 限流 + 降级 | 延迟略增 |

### 11.2 降级链路实现

```python
class VectorSearchService:
    """
    向量检索服务 — 包含完整降级链路
    """
    
    async def search(self, query: str, filter: dict, top_k: int = 10) -> List[dict]:
        """
        检索链路（逐级降级）：
        1. 缓存命中 → 直接返回
        2. 向量检索 → 正常返回
        3. BM25 检索 → 降级返回（语义检索不可用）
        4. 热门数据 → 兜底返回（搜索完全不可用）
        """
        # Level 1: 缓存
        cache_key = self.cache.make_key("default", query, filter, top_k)
        cached = await self.cache.get(cache_key)
        if cached:
            return cached
        
        try:
            # Level 2: 向量检索（正常链路）
            results = await self._vector_search(query, filter, top_k)
            await self.cache.set(cache_key, results)
            return results
            
        except MilvusUnavailableError:
            logger.warning("Milvus unavailable, falling back to BM25")
            # Level 3: BM25 降级
            try:
                results = await self._bm25_fallback(query, filter, top_k)
                results[0]['_degraded'] = True  # 标记降级
                return results
            except Exception:
                logger.error("BM25 also failed, using hot data fallback")
                # Level 4: 热门数据兜底
                return await self._hot_data_fallback(filter, top_k)
        
        except Exception as e:
            logger.error(f"Vector search failed: {e}", exc_info=True)
            # 兜底：返回热门/推荐内容
            return await self._hot_data_fallback(filter, top_k)
    
    async def _bm25_fallback(self, query: str, filter: dict, top_k: int) -> List[dict]:
        """BM25 全文检索降级"""
        return await self.elasticsearch.search(
            index="questions",
            query={
                "bool": {
                    "must": [{"match": {"content": query}}],
                    "filter": self._build_es_filter(filter)
                }
            },
            size=top_k
        )
    
    async def _hot_data_fallback(self, filter: dict, top_k: int) -> List[dict]:
        """热门数据兜底"""
        return await self.content_service.get_popular_contents(
            subject=filter.get('subject'),
            stage=filter.get('stage'),
            limit=top_k
        )
```

### 11.3 重试与补偿

```python
class VectorWriteRetryHandler:
    """
    向量写入失败重试处理器
    
    策略：
    - 即时重试：3次，指数退避（1s, 2s, 4s）
    - 持久化重试：写入 Kafka dead-letter topic，定时补偿
    """
    
    MAX_IMMEDIATE_RETRY = 3
    BACKOFF_BASE = 1  # 秒
    
    async def write_with_retry(self, collection: str, items: List[dict]):
        for attempt in range(self.MAX_IMMEDIATE_RETRY):
            try:
                return await self.writer.insert_batch(collection, items)
            except (MilvusUnavailableError, EmbeddingTimeoutError) as e:
                if attempt == self.MAX_IMMEDIATE_RETRY - 1:
                    # 写入 dead-letter queue
                    await self.kafka_produce(
                        topic='vector-write-dlq',
                        value={
                            'collection': collection,
                            'items': items,
                            'error': str(e),
                            'timestamp': int(time.time()),
                            'retry_count': attempt + 1,
                        }
                    )
                    logger.error(f"Vector write failed after {attempt + 1} retries, "
                                 f"sent to DLQ: {e}")
                    raise
                
                wait = self.BACKOFF_BASE * (2 ** attempt)
                logger.warning(f"Vector write attempt {attempt + 1} failed, "
                               f"retrying in {wait}s: {e}")
                await asyncio.sleep(wait)
```

## 14. pgvector → Milvus 迁移策略

### 14.1 迁移触发条件

| 条件 | 阈值 | 说明 |
| --- | --- | --- |
| 向量总量 | > 200万 | pgvector 性能开始下降 |
| 检索 P99 延迟 | > 100ms | HNSW 索引在大量数据下性能衰减 |
| 并发查询 QPS | > 100 | PostgreSQL 连接数瓶颈 |
| Collection 数量 | > 5 | 多表 JOIN 维护成本高 |

### 14.2 双写迁移方案

```python
class PgVectorToMilvusMigrator:
    """
    pgvector → Milvus 平滑迁移
    
    Phase 1: 双写（同时写入 pgvector 和 Milvus）
    Phase 2: 历史数据批量迁移
    Phase 3: 读取流量灰度切换
    Phase 4: 停止 pgvector 写入
    Phase 5: 下线 pgvector
    """
    
    async def enable_dual_write(self):
        """开启双写模式"""
        config.set('vector.dual_write.enabled', True)
        config.set('vector.dual_write.primary', 'milvus')  # 主写
        config.set('vector.dual_write.secondary', 'pgvector')  # 辅写
        logger.info('Dual write enabled: primary=milvus, secondary=pgvector')
    
    async def batch_migrate(self, batch_size: int = 1000):
        """批量迁移历史数据"""
        offset = 0
        while True:
            # 从 pgvector 批量读取
            rows = await self.pg.query(f'''
                SELECT pk, content_id, content_type, embedding, metadata,
                       embedding_model, model_version
                FROM embedding_store
                WHERE status = 0
                ORDER BY id
                LIMIT %s OFFSET %s
            ''', batch_size, offset)
            
            if not rows:
                break
            
            # 写入 Milvus
            milvus_data = [self._convert_row(row) for row in rows]
            self.milvus.insert('question_vectors', milvus_data)
            
            offset += batch_size
            if offset % 10000 == 0:
                logger.info(f'Migrated {offset} vectors...')
        
        logger.info(f'Migration complete: {offset} total vectors migrated')
    
    async def gradual_read_shift(self):
        """读取流量灰度切换"""
        for percentage in [10, 30, 50, 80, 100]:
            config.set('vector.read.milvus_percentage', percentage)
            logger.info(f'Read traffic shifted: {percentage}% → Milvus')
            # 等待 30 分钟观察指标
            await asyncio.sleep(1800)
            
            metrics = self._check_read_metrics()
            if metrics['error_rate'] > 0.01:
                logger.error(f'Error rate too high at {percentage}%, rolling back')
                config.set('vector.read.milvus_percentage', 0)
                return False
        
        return True
```

```python
#!/usr/bin/env python3
"""Milvus Collection 批量初始化脚本"""

from pymilvus import utility, connections, Collection, FieldSchema, DataType, CollectionSchema

COLLECTIONS_CONFIG = [
    {
        'name': 'question_vectors',
        'description': '题目向量索引库',
        'dim': 1024,
        'extra_fields': [
            ('question_id', DataType.INT64),
            ('subject', DataType.VARCHAR, 32),
            ('stage', DataType.VARCHAR, 16),
            ('grade', DataType.INT8),
            ('question_type', DataType.VARCHAR, 32),
            ('difficulty', DataType.INT8),
            ('textbook_version', DataType.VARCHAR, 32),
            ('chapter_id', DataType.VARCHAR, 64),
        ],
    },
    # ... 其他 Collection 配置
]

INDEX_CONFIG = {
    'index_type': 'HNSW',
    'metric_type': 'COSINE',
    'params': {'M': 16, 'efConstruction': 256},
}

def init_all_collections():
    connections.connect(alias='default', host='localhost', port='19530')
    
    for config in COLLECTIONS_CONFIG:
        name = config['name']
        
        if utility.has_collection(name):
            print(f'Collection {name} already exists, skipping')
            continue
        
        fields = [
            FieldSchema(name='pk', dtype=DataType.VARCHAR, max_length=128, is_primary=True),
            FieldSchema(name='embedding', dtype=DataType.FLOAT_VECTOR, dim=config['dim']),
            FieldSchema(name='content_id', dtype=DataType.INT64),
            FieldSchema(name='content_type', dtype=DataType.VARCHAR, max_length=32),
            FieldSchema(name='embedding_model', dtype=DataType.VARCHAR, max_length=64),
            FieldSchema(name='model_version', dtype=DataType.VARCHAR, max_length=32),
            FieldSchema(name='content_hash', dtype=DataType.VARCHAR, max_length=64),
            FieldSchema(name='status', dtype=DataType.INT8),
            FieldSchema(name='created_at', dtype=DataType.INT64),
            FieldSchema(name='updated_at', dtype=DataType.INT64),
        ]
        
        # 添加额外字段
        for field_def in config.get('extra_fields', []):
            if len(field_def) == 3:
                fname, ftype, fmax = field_def
                fields.append(FieldSchema(name=fname, dtype=ftype, max_length=fmax))
            else:
                fname, ftype = field_def
                fields.append(FieldSchema(name=fname, dtype=ftype))
        
        schema = CollectionSchema(fields=fields, description=config['description'])
        collection = Collection(name=name, schema=schema)
        
        # 创建索引
        collection.create_index(
            field_name='embedding',
            index_params=INDEX_CONFIG
        )
        
        # 加载到内存
        collection.load()
        print(f'Created and loaded collection: {name}')

if __name__ == '__main__':
    init_all_collections()
    print('All collections initialized.')
```

### 15.3 术语表

| 术语 | 说明 |
| --- | --- |
| Collection | Milvus 中的向量集合，类似于数据库中的表 |
| Schema | Collection 的字段定义，包括向量字段和标量字段 |
| Partition | Collection 内的数据分区，用于物理隔离不同数据 |
| Segment | 数据存储的最小单元，数据写入后按 Segment 组织 |
| ANN | Approximate Nearest Neighbor，近似最近邻搜索 |
| HNSW | Hierarchical Navigable Small World，分层可导航小世界图索引 |
| IVF | Inverted File Index，倒排文件索引 |
| RRF | Reciprocal Rank Fusion，倒数排名融合 |
| Embedding | 将文本/图片等映射为高维向量的过程 |
| Reranker | 对初步检索结果进行精排的交叉编码器模型 |
| efConstruction | HNSW 构建时搜索宽度，影响索引质量 |
| ef (Search) | HNSW 查询时搜索宽度，影响召回率和延迟 |
| Partition Key | 用于数据分片的标量字段 |
| Scalar Index | 标量字段索引，加速过滤操作 |
