# 端到端流程设计：会员订阅与增值服务购买完整链路

> 版本：1.0 | 最后更新：2026-06-02

## 1. 概述

### 1.1 文档范围

本文档详细描述 PrimeTop 用户从**免费用户 → 会员订阅 → 增值服务购买 → 权益消费 → 续费/降级/退款**的完整端到端链路，覆盖客户端交互、服务端处理、支付网关对接、额度管控、权益联动和异步后置处理的全部环节。

### 1.2 核心价值

会员订阅与增值服务是 PrimeTop 的核心商业化引擎，本链路需要满足：

1. **购买体验流畅**：从发现到完成支付 ≤ 4 步操作
2. **权益即时生效**：支付成功后 ≤ 2s 内权益可感知
3. **合规安全**：未成年人消费保护、支付风控、退款合规
4. **数据一致**：支付状态、权益状态、额度状态三方强一致
5. **降级可控**：支付失败、回调超时、服务异常时有明确兜底

### 1.3 端到端阶段总览

```
P1 发现与选择 → P2 订单创建 → P3 支付执行 → P4 权益激活 → P5 增值购买 → P6 续费/降级/退款
```

| 阶段 | 核心职责 | 关键模块 |
|------|----------|----------|
| P1 发现与选择 | 引导用户了解权益、选择套餐 | 客户端会员中心、运营弹窗 |
| P2 订单创建 | 生成订单、锁定价格、预检资格 | 订单服务、配额服务 |
| P3 支付执行 | 调起支付SDK、处理回调 | 支付网关、第三方支付 |
| P4 权益激活 | 更新会员状态、同步额度、下发权益 | 会员服务、额度服务 |
| P5 增值购买 | 购买次数包/时长包等增值商品 | 增值商品服务、资产服务 |
| P6 续费/降级/退款 | 到期续费、等级变更、退款处理 | 会员服务、订单服务、退款引擎 |

### 2.3 Redis 数据结构

```
# 用户会员缓存 (写入后同步到Redis)
user:membership:{user_id}         → Hash {tier, status, expires_at, auto_renew}  TTL=会员到期时间

# 用户额度 (原子操作)
user:quota:{user_id}:{quota_type} → String (剩余次数)  TTL=会员到期时间

# 订单幂等键
order:idempotent:{user_id}:{product_id}:{hash}  → String "order_no"  TTL=5min

# 支付回调处理锁
pay:callback:lock:{transaction_id} → String "1"  TTL=30s

# 价格缓存
config:tier:prices                 → Hash {tier_code → price_json}  TTL=10min
```

### 4.2 未成年人消费保护

```python
class MinorProtectionService:
    """未成年人消费保护服务"""
    
    # 消费限额配置 (单笔/月累计)
    CONSUMPTION_LIMITS = {
        "under_8": {"single_cents": 0, "monthly_cents": 0},       # 8岁以下禁止消费
        "age_8_16": {"single_cents": 5000, "monthly_cents": 20000}, # 8-16岁单笔≤50元/月≤200元
        "age_16_18": {"single_cents": 10000, "monthly_cents": 50000}, # 16-18岁放宽
    }
    
    async def check_purchase_eligibility(
        self, user_id: int, amount_cents: int
    ) -> MinorCheckResult:
        """
        检查未成年人消费资格
        
        规则：
        1. 用户年龄 < 8 岁 → 拒绝，提示家长代购
        2. 用户年龄 8-16 岁 → 单笔/月累计限额
        3. 所有未成年人 → 消费前需家长授权(首次)/已授权
        4. 会员类商品 → 相对宽松(教育属性)
        5. 增值商品 → 严格限额
        """
        user = await self.user_repo.get(user_id)
        
        if not user.is_minor:
            return MinorCheckResult(passed=True)
        
        age = user.age
        if age < 8:
            return MinorCheckResult(
                passed=False,
                reason="age_restriction",
                message="根据相关规定，8岁以下用户不支持自主消费，请家长代为操作",
                redirect="parent_purchase_guide"
            )
        
        limits = self._get_limits(age)
        if amount_cents > limits["single_cents"]:
            return MinorCheckResult(
                passed=False,
                reason="single_limit_exceeded",
                message=f"单笔消费不可超过 {limits['single_cents'] // 100} 元",
            )
        
        # 检查月累计
        month_total = await self.order_repo.get_month_total(user_id)
        if month_total + amount_cents > limits["monthly_cents"]:
            return MinorCheckResult(
                passed=False,
                reason="monthly_limit_exceeded",
                message="本月消费已达上限",
            )
        
        # 检查家长授权
        parent_auth = await self.parent_auth_repo.get_active_auth(user_id)
        if not parent_auth:
            return MinorCheckResult(
                passed=False,
                reason="parent_auth_required",
                message="需要家长授权才能完成消费",
                redirect="parent_auth",
                auth_token=generate_auth_token(user_id)
            )
        
        return MinorCheckResult(passed=True, minor_verified=True)
```

```python
    订单创建核心流程
    """

            upgrade_info = calculate_upgrade_price(membership, product)
            request.discount_price_cents = upgrade_info.price_cents

        request.user_id, product.price_cents
    )

        raise BizError(ErrorCode.MINOR_PROTECTION, minor_check.message)
    
    # 4. 风控预检
    risk_result = await risk_service.pre_check(
        user_id=request.user_id,
        amount=product.price_cents,
        device_id=request.device_id,
        client_ip=request.client_ip,
    )
    
    # 5. 幂等检查 (5分钟内同一用户+同一商品)
    idempotent_key = f"order:idempotent:{request.user_id}:{request.product_id}:{hash_parts}"
    existing = await redis.get(idempotent_key)
    if existing:
        return await get_existing_order(existing)

    final_price = product.price_cents
    if request.coupon_id:
        coupon = await coupon_service.apply_coupon(
            request.coupon_id, request.user_id, product
        )
        final_price = max(0, final_price - coupon.discount_cents)
    
    if request.use_trial and await trial_service.is_eligible(request.user_id):
        final_price = 0  # 试用免费
    
    # 7. 创建订单
    order = MembershipOrder(
        order_no=generate_order_no(),
        user_id=request.user_id,
        order_type=request.order_type,
        product_id=product.id,
        product_name=product.name,
        product_snapshot=product.to_snapshot(),
        original_price_cents=product.original_price_cents,
        discount_price_cents=final_price,

        coupon_id=request.coupon_id,
        payment_channel=request.payment_channel,
        payment_status="pending",
        target_tier=product.tier_code,
        duration_days=product.duration_days,
        risk_check_passed=risk_result.passed,
        risk_check_detail=risk_result.to_dict(),
        minor_verified=minor_check.minor_verified,
        device_id=request.device_id,
        client_ip=request.client_ip,
    )
    await order_repo.create(order)
    
    # 8. 设置幂等键
    await redis.setex(idempotent_key, 300, order.order_no)
    
    # 9. 计算权益生效时间
    effective_start, effective_end = calculate_effective_period(
        membership, product, request.order_type
    )
    order.effective_start = effective_start
    order.effective_end = effective_end
    await order_repo.update_effective_period(order)
    
    # 10. 零元单直接完成（试用/全额券）

            order_no=order.order_no,
            payment_status="paid",
            require_pay=False,
            pay_params=None,

            effective_end=order.effective_end,
        )

        channel=request.payment_channel,
        order_no=order.order_no,
        amount_cents=final_price,
        subject=f"启硕PrimeTop-{product.name}",
        client_ip=request.client_ip,
        device_id=request.device_id,

    )

        order_no=order.order_no,
        payment_status="pending",
        require_pay=True,

        effective_start=order.effective_start,
```

### 5.1 支付渠道统一抽象

### 5.3 支付回调处理（服务端核心）

```python
async def handle_payment_callback(channel: str, callback_data: dict) -> CallbackAck:
    """
    支付回调统一入口。所有渠道回调先验签、再幂等、再推进状态。
    """
    # 1. 验签（渠道适配器实现：微信平台证书SHA256-RSA / 支付宝RSA2 / Apple JWS）
    verified = await payment_gateway.verify_signature(channel, callback_data)
    if not verified:
        alarm.emit("pay_callback_sign_fail", channel=channel)
        raise BizError(080203)  # 支付回调验签失败

    tx = payment_gateway.parse_transaction(channel, callback_data)
    # tx: {transaction_id, order_no, amount_cents, status, paid_at}

    # 2. 回调幂等锁（Redis 30s）+ DB transaction_id 唯一索引 双保险
    lock_key = f"pay:callback:lock:{tx.transaction_id}"
    if not await redis.set(lock_key, "1", nx=True, ex=30):
        return CallbackAck.success()  # 重复回调直接应答成功

    order = await order_repo.get_by_order_no(tx.order_no)
    if not order:
        return CallbackAck.fail("order_not_found")  # 记录死信队列人工排查

    # 3. 状态机守卫：仅 pending 可推进为 paid（CAS）
    if order.payment_status == "paid":
        return CallbackAck.success()  # 已处理，幂等应答
    if order.payment_status in ("closed", "failed"):
        # 关单竞态：先查渠道确认真实支付时间
        if tx.paid_at and tx.paid_at < order.closed_at:
            await reopen_and_pay(order, tx)  # 关单在支付之后发生 → 恢复订单并推进
            return CallbackAck.success()
        alarm.emit("pay_after_close", order_no=order.order_no)
        return CallbackAck.success()  # 先应答渠道，转人工核对退款

    # 4. 金额强校验
    if tx.amount_cents != order.discount_price_cents:
        alarm.emit("pay_amount_mismatch",
                   expect=order.discount_price_cents, actual=tx.amount_cents)
        raise BizError(080105)  # 金额不匹配，高危：拒绝推进并告警人工

    # 5. 单事务推进：订单状态 + 支付流水 + Outbox 事件
    async with db.transaction():
        rows = await order_repo.cas_to_paid(
            order_no=order.order_no,
            from_status="pending",
            transaction_id=tx.transaction_id,
            payment_time=tx.paid_at,
            payment_raw_data=callback_data,
        )
        if rows == 0:
            return CallbackAck.success()  # 并发回调，另一条已成功
        await outbox.emit("membership.paid", {
            "order_no": order.order_no,
            "user_id": order.user_id,
            "target_tier": order.target_tier,
            "order_type": order.order_type,
            "duration_days": order.duration_days,
        })
    return CallbackAck.success()
```

**关键规则：**

1. 回调**先落库后应答**：验签通过→更新订单→写 Outbox→应答渠道；任何异常应答失败让渠道重试（微信重试 1/4/10/30/60min…，支付宝 25h 内 8 次）；
2. 激活不在回调线程内同步执行——回调只负责把订单推进到 `paid` 并发事件，权益激活由 `MembershipActivator` 消费 `membership.paid` 异步完成（目标 P99 ≤ 2s），避免回调超时；
3. `payment_raw_data` 全量留存原始报文（排障+对账+合规审计），含敏感字段脱敏后入库。

### 5.4 Apple IAP 凭证校验（服务端）

```python
async def verify_apple_iap(order: MembershipOrder, transaction_jws: str) -> AppleTx:
    """
    StoreKit 2 服务端校验：
    1. 解 JWS header 取 x5c 证书链 → 验证链至 Apple Root CA（含 OCSP 吊销检查）
    2. 解 payload 取 transactionId / productId / purchaseDate / revocationDate
    3. 调 App Store Server API /inAppTransactions/{id} 二次确认（防伪造）
    """
    payload = apple_jws.verify(transaction_jws)  # 验证失败 → 080204
    if payload.productId != order.product_id:
        raise BizError(080105, "IAP商品与订单不一致")
    if payload.revocationDate:  # 已被退款/家庭共享撤销
        return AppleTx(status="revoked", original=order, payload=payload)
    return AppleTx(status="purchased", payload=payload)
```

**App Store Server Notifications V2 联动：**

| 通知类型 | 处理动作 |
|---------|---------|
| TRANSACTION / SUBSCRIBED | 等价支付回调，走 §5.3 主流程 |
| DID_RENEW | 自动续费成功，走 §8.2 续费时间线 |
| DID_FAIL_TO_RENEW | 续费扣款失败，进入宽限期（grace period） |
| EXPIRED | 订阅过期，执行降级（§8.1） |
| REFUND / REVOKE | 退款/撤销，走 §8.4 权益回收 |
| GRACE_PERIOD_EXPIRED | 宽限期结束仍未恢复扣款 → 降级 |

Apple 退款通知到达时**无需用户申请直接执行回收**：按已使用天数折算保留/回收（见 §8.4），并写 `refund_records(refund_reason="Apple退款")`。

## 6. P4：权益激活阶段

### 6.1 激活主流程（消费 membership.paid 事件）

```java
@Transactional
public void onMembershipPaid(MembershipPaidEvent evt) {
    // 0. 激活幂等：以 order_no 为幂等键（activate_records 表唯一索引）
    if (activateRepo.existsByOrderNo(evt.getOrderNo())) return;

    MembershipOrder order = orderRepo.lockByOrderNo(evt.getOrderNo()); // SELECT ... FOR UPDATE
    if (!"paid".equals(order.getPaymentStatus())) {
        throw new BizException(080102); // 已支付才允许激活
    }

    // 1. 计算生效周期（§6.2 规则）
    EffectivePeriod period = effectivePeriodCalculator.calculate(order);
    order.setEffectiveStart(period.getStart());
    order.setEffectiveEnd(period.getEnd());
    orderRepo.save(order);

    // 2. 会员主表 upsert（同事务）
    UserMembership m = membershipRepo.lockByUserId(order.getUserId());
    if (m == null) {
        m = UserMembership.newFree(order.getUserId());
    }
    m.setPreviousTier(m.getCurrentTier());
    m.setCurrentTier(order.getTargetTier());
    m.setStatus(order.isTrial() ? TRIAL : ACTIVE);
    m.setStartedAt(period.getStart());
    m.setExpiresAt(period.getEnd());
    if (order.getOrderType() == SUBSCRIPTION_RENEW) {
        m.setConsecutiveMonths(m.getConsecutiveMonths() + period.getMonths());
    }
    m.setTotalPaidCents(m.getTotalPaidCents() + order.getDiscountPriceCents());
    m.setTotalOrders(m.getTotalOrders() + 1);
    membershipRepo.save(m);

    // 3. 增值商品 → 资产发放（P5）；会员商品 → 跳过
    if (order.getOrderType() == ADDON_PURCHASE) {
        assetService.grantFromOrder(order);  // 写 user_assets，见 §7.2
    }

    // 4. 额度同步（§6.3）
    quotaSyncService.rebuildUserQuotas(order.getUserId(), m);

    // 5. 激活流水 + Outbox 事件（同事务提交）
    activateRepo.insert(ActivateRecord.of(order, m));
    outbox.emit("membership.activated", MembershipActivatedEvent.of(order, m, period));
}
```

**激活失败重试**：Outbox 消费失败按 1m/5m/15m/1h 重试 5 次；仍失败进入死信 + 告警人工介入（订单已 `paid` 但会员未激活属于**资损/客诉高危**，监控项见 §12）。恢复手段：管理后台"订单重放激活"按钮（复用本幂等方法）。

### 6.2 生效周期计算规则

| 场景 | 生效起点 | 失效终点 | 示例 |
|------|---------|---------|------|
| 新购（当前 free/过期） | 支付成功当日 00:00 | start + duration_days | 6-02 购年卡 → 2026-06-02 ~ 2027-06-01 23:59:59 |
| 试用开通 | 立即 | now + trial_days | 7 天试用 |
| 到期前续费（active） | 原 expires_at 顺延 | 原到期 + duration_days | 剩 30 天续年卡 → 总时长 395 天 |
| 到期后 30 天内回归续费 | 支付当日 | start + duration_days | 断档不清零 consecutive_months 的宽限窗口 |
| 升级（monthly→annual） | 当日（立即切换权益） | 折算：剩余价值/新套餐日均 抵扣新时长 | 见下方折算公式 |
| exam_prep 专项 | 购买当日 | 对齐考试日（中考 6-17 / 高考 6-9 次日） | 考后自动 expired |
| 增值资产（addon） | 支付当日 | start + validity_days | 与会员独立，见 §7 |

**升级折算公式：**

```text
剩余价值 = 原套餐剩余天数 × (原套餐实付/原套餐总天数)
升级应付 = 新套餐价 − 剩余价值（下限 1 分钱，不允许零元升级走 IAP）
新时长   = duration_days(新) + floor(剩余价值 / 新套餐日均)
```

### 6.3 额度同步与缓存重建

```python
async def rebuild_user_quotas(user_id: int, membership: UserMembership):
    """
    会员变更后重建额度。规则：
    1) tier 每日额度：每日 00:05 由定时任务重置（按当日 tier 配置）
    2) addon 资产额度：独立计数，跨日不清零，按资产过期时间失效
    3) Redis 为唯一读路径；重建 = 删缓存 + 立即回填，避免旧值残留
    """
    pipe = redis.pipeline()
    pipe.delete(f"user:membership:{user_id}")           # 先失效
    pipe.hset(f"user:membership:{user_id}", mapping={   # 再回填（防旧 TTL 残留）
        "tier": membership.current_tier,
        "status": membership.status,
        "expires_at": membership.expires_at.isoformat(),
        "auto_renew": int(membership.auto_renew),
    })
    pipe.expireat(f"user:membership:{user_id}", membership.expires_at)

    # addon 资产汇总（active 资产 remaining 求和，按 quota_type）
    for qt, remaining in await asset_repo.sum_active_remaining(user_id):
        pipe.set(f"user:quota:{user_id}:{qt}:addon", remaining)
    await pipe.execute()
```

**额度扣减顺序（消费时）**：先扣 `addon` 资产（有过期时间，先到期先用；同类型多资产按 expires_at 升序），再扣 tier 每日额度——保证用户付费买的次数不被"免费日额度"稀释浪费。扣减 Lua 原子脚本与负余额保护由《服务端-用户额度管控与功能门控引擎-详细设计.md》《服务端-积分获取规则计算与虚拟资产交易结算服务-详细设计.md》统一定义，本链路只负责发放与失效。

## 8. P6：续费、降级与退款

### 8.1 到期与降级时间线

```
                T-7天        T-3天      T-0 09:00      宽限期72h        T+7天
                 │            │            │               │              │
  会员(annual) ──┼─ 推送提醒 ──┼─ 短信提醒 ──┼─ 自动续费扣款 ──┼─ 保权益重试扣款 ──┼─ 降级 free
                 │            │            │               │              │
  状态         active ────────┴────── expiring_soon ── grace(可选) ──── expired
```

| 时点 | 动作 | 责任模块 |
|------|------|---------|
| T-7 / T-3 | 续费提醒（推送/短信，含关闭自动续费入口） | 《服务端-订阅续费预警与自动续费失败补偿调度引擎-详细设计.md》 |
| T-0 09:00 | 自动续费委托代扣（微信/支付宝签约、IAP自动续订由渠道自行扣款后通知） | 同上 |
| 扣款失败 | D0 21:00 / D+1 / D+3 / D+5 四轮重试（换渠道优先级降级） | 同上 |
| 宽限期 | 保留权益、标记 grace，客户端顶部横幅"扣款失败，请更新支付方式" | 客户端会员中心 |
| T+7 仍失败 | 执行降级：tier→free、额度回到免费档、addon 资产**保留**（已付费资产不受会员降级影响） | 本文档 §6.3 rebuild |
| 降级完成 | Outbox 发 `membership.downgraded`（通知/埋点/挽留券发放） | 通知服务 + 运营 |

**用户主动取消自动续费**：仅关闭代扣，权益保留至到期；`cancelled_at/cancel_reason` 记录，到期走同一降级时间线（跳过扣款环节）。取消路径必须在支付成功页、会员中心、每条续费提醒三处可达（合规）。

### 8.2 自动续费成功链路

```
渠道扣款成功(委托代扣回执 / DID_RENEW通知 / Play扣款)
  → 复用 §5.3 回调主流程（新订单 order_type=subscription_renew，系统预创建）
  → §6.1 激活（expires_at 顺延，consecutive_months+1）
  → 推送"续费成功"（附账单与发票入口）
```

### 8.3 升级 / 降级规则

| 操作 | 价格 | 生效 | 权益处理 |
|------|------|------|---------|
| 升级 | 剩余价值折算抵扣（§6.2 公式） | 立即 | 立即按新 tier 重建额度（当日已用次数保留） |
| 降级（到期后自然降） | — | 到期时 | free 档额度次日生效 |
| 月→年切换购买 | 按升级单处理 | 立即 | previous_tier 记录，便于回溯 |

### 8.4 退款与权益回收

入口：App 内申请（48h 内自助通道）/ 客服工单 / Apple 退款 / 渠道争议（chargeback）。执行细节由《服务端-退款与订单售后处理服务-详细设计.md》定义，本链路约定 E2E 回收矩阵：

**按剩余价值比例回收（默认策略）：**

```text
可退金额 = 实付 × max(0, 剩余天数 / 总天数) − 已消费增值部分×1.0
权益回收：
  ├─ 会员：expires_at 提前至退款生效日；若剩余天数 ≤ 3 天 → 直接降级 free（避免碎片化宽限）
  ├─ addon 资产：未使用部分作废（refunded）；已使用部分不追回
  └─ 额度：当日已发放日额度不回收（体验优先），次日 free 档
未成年人误充值：走《服务端-未成年人支付风控与误充值自动识别退款引擎-详细设计.md》快速通道（免审核全额退，72h 内到账）
```

**退款状态机：** `pending → approved → processing → completed`；`rejected` 终态；`processing` 超过渠道 SLA（微信1天/支付宝1天/IAP 48h）自动告警人工跟进。退款完成 → Outbox `refund.completed` → 通知、账单红冲、会员状态推进（`refunded` 或回到 `active`+新 expires_at）。

## 9. 全链路状态机

### 9.1 订单状态机（membership_orders.payment_status + closed 补充态）

```
                 ┌──────────────────────────────────────┐
                 │                                      │
  pending ──支付成功──> paid ──退款完成──> refunded       │
     │  │                │                              │
     │  └─渠道明确失败──> failed（可重新下单）             │
     │                                                   │
     └─15min超时/用户取消──> closed ──关单后收到迟到回调───┘（§5.3 竞态恢复）
                              paid ──部分退款──> partial_refunded
```

| 转换 | 触发 | 守卫条件 | 副作用 |
|------|------|---------|--------|
| pending→paid | 回调/查单确认 | 金额一致 + 验签通过 + CAS | Outbox `membership.paid` |
| pending→closed | 超时关单任务/用户取消 | 先查单确认未支付 | 释放优惠券；`order.timeout_closed` |
| pending→failed | 渠道明确失败回调 | — | 客户端引导重试（新订单） |
| paid→refunded | 退款 completed | 退款单核销完成 | 权益回收（§8.4）；`refund.completed` |
| paid→partial_refunded | 部分退款 | 折算后权益调整 | 会员到期日调整 |
| closed→paid | 迟到回调竞态 | 支付时间早于关单时间 | 告警 `pay_after_close` + 恢复激活 |

### 9.2 会员状态机（user_memberships.status）

| 当前态 | 事件 | 目标态 | 说明 |
|--------|------|--------|------|
| (free) | 新购支付成功 | active/trial | 写主表 |
| active | 距到期 ≤7 天（派生态） | expiring_soon | 只读展示态，权益不变 |
| expiring_soon | 续费成功 | active | expires_at 顺延 |
| expiring_soon | 到期未续费 | expired | 降级 rebuild 额度 |
| active/expiring_soon | 用户取消自动续费 | cancelled | 权益保留至到期，再转 expired |
| active | 风控冻结 | suspended | 全端权益暂停（争议/盗号） |
| suspended | 风控解除 | active | 补偿冻结天数 |
| 任意 | 全额退款 | refunded | 立即降级 |
| grace（宽限） | 扣款成功 | active | expires_at 顺延 |
| grace | T+7 仍失败 | expired | 降级 + `membership.downgraded` |

> 派生态 `expiring_soon` 不落库，由读时计算（`expires_at - now ≤ 7d`），避免状态抖动；表内 `status` 只存主态。

**关键埋点事件：** `pay_page_view`、`pay_start`(order_no/product/channel)、`pay_result`(status/耗时)、`membership_activated_view`、`auto_renew_alert_view`、`refund_apply_submit`。

**审计日志**：订单创建/回调/关单/激活/退款/后台重放，全量入审计日志系统（《服务端-审计日志与操作追溯系统-详细设计.md》），留存 ≥ 3 年（支付合规）。

## 13. 合规红线清单

1. 未成年人：8 岁以下禁消费；8-16 岁限额+家长授权（统一家长门 Grant Token）；家长端必须能查看孩子全部订单并可发起退款。
2. 自动续费：开通前显著提示（价格/周期/取消方式）；扣款前提醒（T-3）；取消入口三处可达；不得默认勾选隐蔽条款。
3. iOS：数字商品强制 IAP；不得引导外部支付（含客服话术管控）；IAP 价格与配置价差异处理见 §5.1。
4. 宣传合规：折扣划线价需有真实成交记录依据（价格法）；"最划算/最受欢迎"标签需 A/B 数据支撑留存审批记录。
5. 发票：支付成功即提供电子发票申请入口（7×24，mailto 由发票服务异步开具）。
6. 数据留存：支付报文脱敏留存；未成年人支付信息不用于画像营销。
