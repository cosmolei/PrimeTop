## 1. 模块概述

### 1.1 功能定位

运营活动与成长激励体系是 PrimeTop 的用户粘性引擎。通过**成长等级、徽章收集、学习打卡、阶段挑战、虚拟奖励**等机制，将学习行为游戏化，提升学生的持续学习动力和产品留存率。同时为运营团队提供灵活的活动配置能力，支撑寒暑假营、考试冲刺、节日活动等运营场景。

### 1.2 核心目标

| 目标 | 衡量指标 |
|------|----------|
| 提升日活留存 | 激励体系上线后 7 日留存率提升 ≥ 5% |
| 增加学习时长 | 人均日学习时长提升 ≥ 10% |
| 培养学习习惯 | 连续打卡 ≥ 7 天的用户占比 ≥ 30% |
| 运营活动转化 | 活动参与率 ≥ 20%，活动带来的新注册 ≥ 15% |

### 1.3 目标用户

| 用户类型 | 年龄段 | 激励偏好 |
|----------|--------|----------|
| 幼儿用户 | 3-6 | 图形化奖励、卡通动画、声音反馈 |
| 小学生 | 6-12 | 徽章收集、等级提升、排行榜竞争 |
| 初中生 | 12-15 | 成就感、目标达成、同伴比较 |
| 高中生 | 15-18 | 实用价值、效率导向、学习数据可见 |
| 家长 | 25-45 | 孩子进步可见、成长报告、亲子互动 |

### 3.3 徽章触发规则定义（`trigger_rule` JSON Schema）

```jsonc
// trigger_rule 字段的 JSON 结构
{
    "type": "event_count | stat_threshold | composite | time_limited",
    // event_count: 累计事件次数达到阈值
    // stat_threshold: 某项统计指标达到阈值
    // composite: 组合条件（多个子条件 AND）
    // time_limited: 限时完成某目标

    // 当 type=event_count
    "event": "ai_qa_complete | photo_solve_complete | chapter_complete | mistake_review | checkin | writing_submit | recite_pass | ...",
    "count": 50,

    // 当 type=stat_threshold
    "stat": "total_xp | streak_days | subjects_covered | mistakes_corrected | ...",
    "threshold": 1000,

    // 当 type=composite
    "conditions": [
        { "type": "event_count", "event": "checkin", "count": 7 },
        { "type": "stat_threshold", "stat": "streak_days", "threshold": 7 }
    ],

    // 当 type=time_limited
    "target_event": "chapter_complete",
    "target_count": 10,
    "within_days": 7,

    // 通用
    "subject_scope": ["math", "chinese"],  // null=全部学科
    "stage_scope": ["primary", "middle"]    // null=全部学段
}
```

## 4. 经验值(XP)与等级系统

### 4.1 经验值获取规则

| 行为 | XP 奖励 | 每日上限 | 说明 |
|------|---------|----------|------|
| AI 问答（完整交互） | +5 XP | 100 XP | 用户收到回答后停留 ≥ 10s 算有效 |
| 拍照搜题（查看解析） | +8 XP | 80 XP | 查看完整解析算有效 |
| 同步课堂学习（完成一节） | +15 XP | 120 XP | 学习时长 ≥ 5min 且完成章节测试 |
| 错题订正 | +10 XP | 80 XP | 订正后再次答对算有效 |
| 错题复习（完成一组） | +12 XP | 96 XP | 每组 ≥ 5 道题 |

```python
def check_level_up(user_id: int, stage_group: str) -> Optional[LevelUpResult]:
    """检查并执行升级"""
    user_level = db.get_user_level(user_id, stage_group)
    level_defs = db.get_level_defs(stage_group)  # 按 min_xp DESC 排序

    new_level = user_level.level
    for ld in level_defs:
        if user_level.total_xp >= ld.min_xp:
            new_level = ld.level
            break

    if new_level <= user_level.level:
        return None  # 未升级

    # 执行升级
    old_level = user_level.level
    user_level.level = new_level
    user_level.xp = user_level.total_xp - level_defs[new_level - 1].min_xp
    db.save(user_level)

    # 发放升级奖励
    rewards = level_defs[new_level - 1].rewards_json
    if rewards.get('coins'):
        wallet_service.earn(user_id, 'coins', rewards['coins'], 'level_up', str(new_level))
    if rewards.get('badge_id'):
        badge_service.unlock(user_id, rewards['badge_id'])

    # 发布升级事件
    event_bus.publish('user.level_up', {
        'user_id': user_id,
        'old_level': old_level,
        'new_level': new_level,
        'stage_group': stage_group,
        'rewards': rewards,
    })

    return LevelUpResult(old_level=old_level, new_level=new_level, rewards=rewards)
```

### 5.2 徽章触发检查引擎

徽章解锁采用异步事件驱动，业务模块发布事件后由徽章引擎检查所有匹配规则：

```python
class BadgeEngine:
    """徽章触发检查引擎"""

    def on_event(self, event_name: str, user_id: int, payload: dict):
        """处理业务事件，检查是否有徽章解锁"""
        # 获取所有匹配该事件的活跃徽章规则
        candidates = self.badge_repo.find_active_by_event(event_name)

        for badge_def in candidates:
            # 检查学段/学科范围
            if not self._scope_match(badge_def, payload):
                continue

            # 检查是否已解锁
            if self.user_badge_repo.exists(user_id, badge_def.id):
                continue

            # 根据触发规则类型评估
            rule = badge_def.trigger_rule
            unlocked = self._evaluate_rule(user_id, rule, payload)

            if unlocked:
                self._unlock_badge(user_id, badge_def)

    def _evaluate_rule(self, user_id: int, rule: dict, payload: dict) -> bool:
        rule_type = rule['type']

        if rule_type == 'event_count':
            count = self.event_counter.get_count(
                user_id, rule['event'],
                subject_scope=rule.get('subject_scope')
            )
            return count >= rule['count']

        elif rule_type == 'stat_threshold':
            value = self.stat_service.get_stat(
                user_id, rule['stat']
            )
            return value >= rule['threshold']

        elif rule_type == 'composite':
            return all(
                self._evaluate_rule(user_id, cond, payload)
                for cond in rule['conditions']
            )

        elif rule_type == 'time_limited':
            count = self.event_counter.get_count_since(
                user_id, rule['target_event'],
                days=rule['within_days']
            )
            return count >= rule['target_count']

        return False

    def _unlock_badge(self, user_id: int, badge_def: BadgeDef):
        """解锁徽章并发放奖励"""
        self.user_badge_repo.create(user_id, badge_def.id)

        if badge_def.reward_coins > 0:
            self.wallet_service.earn(
                user_id, 'coins', badge_def.reward_coins,
                'badge_unlock', str(badge_def.id)
            )
        if badge_def.reward_xp > 0:
            self.xp_service.earn(
                user_id, badge_def.reward_xp,
                'badge_bonus', str(badge_def.id)
            )

        # 推送解锁通知
        self.notification_service.send(user_id, 'badge_unlock', {
            'badge_name': badge_def.name,
            'badge_icon': badge_def.icon_url,
            'rarity': badge_def.rarity,
        })

        event_bus.publish('badge.unlocked', {
            'user_id': user_id,
            'badge_id': badge_def.id,
            'badge_code': badge_def.code,
        })
```

```python
def calculate_streak(user_id: int) -> int:
    """计算连续打卡天数"""
    today = date.today()

    # 获取最近30天的打卡记录
    records = db.query(
        "SELECT checkin_date FROM checkin_record "
        "WHERE user_id = %s AND checkin_type = 'daily' "
        "AND checkin_date >= %s ORDER BY checkin_date DESC",
        [user_id, today - timedelta(days=30)]
    )

    if not records:
        return 0

    # 检查今天是否已打卡
    streak = 0
    expected_date = today

    # 如果今天还没打卡，从昨天开始算
    if records[0]['checkin_date'] != today:
        expected_date = today - timedelta(days=1)

    for record in records:
        if record['checkin_date'] == expected_date:
            streak += 1
            expected_date -= timedelta(days=1)
        else:
            break

    return streak
```

```python
def makeup_checkin(user_id: int, target_date: date) -> MakeupResult:
    """补卡"""
    # 1. 检查月份补卡次数
    month_makeups = db.count_monthly_makeups(user_id, target_date)
    if month_makeups >= 3:
        raise BusinessError('MONTHLY_MAKEUP_LIMIT', '本月补卡次数已达上限')

    # 2. 检查目标日期合理性
    if target_date >= date.today():
        raise BusinessError('INVALID_DATE', '只能补过去日期')
    if target_date < date.today() - timedelta(days=30):
        raise BusinessError('TOO_OLD', '只能补30天内的打卡')

    # 3. 检查是否已打卡
    if db.checkin_exists(user_id, target_date, 'daily'):
        raise BusinessError('ALREADY_CHECKED', '该日期已打卡')

    # 4. 扣除金币
    self.wallet_service.spend(user_id, 'coins', 20, 'makeup_checkin', str(target_date))

    # 5. 写入补卡记录
    db.insert_checkin_record(
        user_id=user_id,
        checkin_date=target_date,
        checkin_type='daily',
        source_type='makeup',
        streak_days=0,  # 补卡不计入连续天数计算，但会重新计算streak
    )

    # 6. 重新计算连续天数
    new_streak = self.calculate_streak(user_id)
    db.update_latest_streak(user_id, new_streak)

    return MakeupResult(success=True, new_streak=new_streak)
```

```python
def redeem_item(user_id: int, item_id: int) -> RedeemResult:
    """兑换商品（乐观锁 + 事务）"""
    with db.transaction():
        # 1. 查商品（加行锁）
        item = db.query_one(
            "SELECT * FROM reward_item WHERE id = %s AND status = 'active' FOR UPDATE",
            [item_id]
        )
        if not item:
            raise BusinessError('ITEM_NOT_FOUND', '商品不存在或已下架')

        # 2. 检查库存
        if item.stock is not None and item.sold_count >= item.stock:
            raise BusinessError('OUT_OF_STOCK', '库存不足')

        # 3. 检查学段
        if item.stage_scope and user_stage not in item.stage_scope:
            raise BusinessError('STAGE_MISMATCH', '该商品不适用于当前学段')

        # 4. 扣除金币（钱包行锁）
        wallet = db.query_one(
            "SELECT * FROM user_wallet WHERE user_id = %s AND currency_type = 'coins' FOR UPDATE",
            [user_id]
        )
        if wallet.balance < item.price_coins:
            raise BusinessError('INSUFFICIENT_BALANCE', '金币不足')

        wallet.balance -= item.price_coins
        wallet.total_spent += item.price_coins
        db.save(wallet)

        # 5. 扣库存
        db.execute(
            "UPDATE reward_item SET sold_count = sold_count + 1 WHERE id = %s",
            [item_id]
        )

        # 6. 写兑换记录
        db.insert_redeem_record(user_id, item_id, item.price_coins)

        # 7. 发放商品内容到用户资产
        asset_service.grant(user_id, item.type, item.content_json)

    return RedeemResult(success=True, item_name=item.name)
```

### 8.2 排行榜生成策略

采用 **Redis ZSet + MySQL 持久化** 双层架构：

```
实时更新层 (Redis ZSet):
  key: leaderboard:{board_type}:{period_key}:{scope}
  member: user_id
  score: 分数值

持久化层 (MySQL leaderboard_snapshot):
  定时任务每小时快照一次
  排行榜页面优先读 Redis，回退读 MySQL
```

```python
def update_leaderboard(board_type: str, period_key: str, user_id: int, score: float):
    """更新排行榜分数"""
    redis_key = f"leaderboard:{board_type}:{period_key}:global"
    redis.zadd(redis_key, {str(user_id): score})
    # 设置过期时间（排行榜保留90天）
    redis.expire(redis_key, 90 * 86400)

def get_leaderboard(board_type: str, period_key: str, scope: str = 'global',
                    page: int = 1, page_size: int = 50) -> List[RankItem]:
    """获取排行榜"""
    redis_key = f"leaderboard:{board_type}:{period_key}:{scope}"

    start = (page - 1) * page_size
    # ZREVRANGE 按分数降序
    raw = redis.zrevrange(redis_key, start, start + page_size - 1, withscores=True)

    if not raw:
        # 回退到 MySQL
        return db.query_leaderboard_snapshot(board_type, period_key, scope, page, page_size)

    # 批量查用户信息
    user_ids = [int(uid) for uid, _ in raw]
    users = user_service.batch_get(user_ids)

    results = []
    for idx, (uid, score) in enumerate(raw):
        user = users.get(int(uid))
        results.append(RankItem(
            rank=start + idx + 1,
            user_id=int(uid),
            nickname=user.nickname if user else '用户',
            avatar_url=user.avatar_url if user else None,
            score=score,
        ))

    return results
```

### 8.3 隐私保护策略

- 用户可在设置中关闭排行榜展示（`profile.show_on_leaderboard = false`）

## 9. 运营活动引擎

### 9.1 活动生命周期状态机

```
  draft → active → paused → active（可恢复）
                ↘ ended → settled
```

| 状态 | 说明 | 可转换到 |
|------|------|----------|
| `draft` | 草稿，未开始 | active |
| `active` | 进行中 | paused, ended |
| `paused` | 暂停（紧急关停） | active, ended |
| `ended` | 已结束（到达 end_time 或手动结束） | settled |
| `settled` | 已结算（奖励发放完毕） | — |

### 9.2 活动参与状态机

```
joined → in_progress → completed → rewarded
                      ↘ failed
```

### 9.3 活动定时任务

```python
# Celery 定时任务注册表

@app.task
def activity_start_check():
    """每分钟检查：将到期的 draft 活动自动变为 active"""
    activities = Activity.query(
        status='draft',
        start_time__lte=now()
    )
    for act in activities:
        act.status = 'active'
        # 推送活动开始通知给目标用户群
        notification_service.broadcast_activity_start(act)

@app.task
def activity_end_check():
    """每分钟检查：将到期的 active 活动自动变为 ended"""
    activities = Activity.query(
        status__in=['active', 'paused'],
        end_time__lte=now()
    )
    for act in activities:
        act.status = 'ended'

@app.task
def activity_settle():
    """每小时检查：结算已结束的活动，发放奖励"""
    activities = Activity.query(status='ended')
    for act in activities:
        settle_activity(act)

def settle_activity(activity: Activity):
    """结算单个活动"""
    if activity.type == 'rank_race':
        rules = activity.rules_json
        participants = ActivityParticipation.query(
            activity_id=activity.id
        ).order_by(score.desc())

        for reward in rules.get('top_n_reward', []):
            rank = reward['rank']
            if rank <= len(participants):
                p = participants[rank - 1]
                # 发放奖励
                if reward.get('coins'):
                    wallet_service.earn(p.user_id, 'coins', reward['coins'],
                                       'activity_reward', str(activity.id))
                if reward.get('badge_id'):
                    badge_service.unlock(p.user_id, reward['badge_id'])
                p.status = 'rewarded'
                p.reward_claimed = True

        # 未获奖参与者标记完成
        ActivityParticipation.query(
            activity_id=activity.id,
            status__in=['joined', 'in_progress']
        ).update(status='completed')

    activity.status = 'settled'
```

### 9.4 闯关型活动进度追踪

```python
class TopicSprintHandler:
    """专题闯关型活动进度处理器"""

    def on_chapter_complete(self, user_id: int, activity_id: int,
                           chapter_id: int, score: float):
        participation = db.get_participation(activity_id, user_id)
        if not participation:
            return

        rules = db.get_activity(activity_id).rules_json
        stages = rules['stages']
        progress = participation.progress_json or {'completed_stages': [], 'scores': {}}

        # 找到当前阶段
        current_stage_idx = len(progress['completed_stages'])
        if current_stage_idx >= len(stages):
            return  # 已全部通关

        stage = stages[current_stage_idx]
        if chapter_id in stage['chapter_ids'] and score >= stage.get('required_score', 0):
            progress['scores'][str(current_stage_idx + 1)] = score
            if all(ch in progress['scores'] for ch in stage['chapter_ids']):
                progress['completed_stages'].append(current_stage_idx + 1)

        participation.progress_json = progress

        # 检查是否全部通关
        if len(progress['completed_stages']) == len(stages):
            participation.status = 'completed'
            event_bus.publish('activity.completed', {
                'activity_id': activity_id,
                'user_id': user_id,
            })

        db.save(participation)
```

| 等级定义 | Redis | `growth:level_def:{stage}` | 24h | 后台修改时主动失效 |
| 徽章定义 | Redis | `growth:badge_def` | 24h | 后台修改时主动失效 |
| 用户徽章列表 | Redis | `growth:user_badges:{user_id}` | 30min | 解锁后主动失效 |
| 打卡日历 | Redis | `growth:checkin_cal:{user_id}:{month}` | 5min | 打卡后主动失效 |
| 连续天数 | Redis | `growth:streak:{user_id}` | 24h | 打卡/补卡后更新 |
| 钱包余额 | Redis | `growth:wallet:{user_id}:{currency}` | 10min | 交易后写穿透 |
| 排行榜 | Redis ZSet | `leaderboard:{type}:{period}:{scope}` | — | 实时更新，定时快照 |
| 活动详情 | Redis | `growth:activity:{id}` | 10min | 后台修改时失效 |
| XP 每日上限 | Redis | `growth:xp_daily:{user_id}:{source}:{date}` | 到当日 23:59 | 累加计数 |

## 15. 错误处理

### 15.1 错误码定义

| 错误码 | HTTP 状态码 | 说明 |
|--------|-------------|------|
| `ALREADY_CHECKED` | 409 | 今日已打卡 |
| `MONTHLY_MAKEUP_LIMIT` | 429 | 本月补卡次数已达上限 |
| `INSUFFICIENT_BALANCE` | 400 | 金币/星星不足 |
| `ITEM_NOT_FOUND` | 404 | 商品不存在或已下架 |
| `OUT_OF_STOCK` | 410 | 商品库存不足 |
| `STAGE_MISMATCH` | 400 | 商品不适用当前学段 |
| `BADGE_ALREADY_UNLOCKED` | 409 | 徽章已解锁 |
| `LEVEL_NOT_FOUND` | 404 | 等级定义不存在 |
| `ACTIVITY_NOT_ACTIVE` | 400 | 活动未在进行中 |
| `ACTIVITY_FULL` | 429 | 活动参与人数已满 |
| `ACTIVITY_ALREADY_JOINED` | 409 | 已参与该活动 |
| `REWARD_ALREADY_CLAIMED` | 409 | 奖励已领取 |
| `LEADERBOARD_DISABLED` | 403 | 用户已关闭排行榜展示 |

### 15.2 降级策略

| 故障场景 | 降级方案 |
|----------|----------|
| Redis 不可用 | 排行榜回退 MySQL 查询；XP/金币直接写 DB（降级警告） |
| 消息队列积压 | XP/徽章处理延迟容忍，用户侧先展示"奖励计算中"状态 |
| 活动结算失败 | 自动重试 3 次，仍失败则告警人工介入 |
| 钱包并发冲突 | 乐观锁重试 3 次，仍冲突返回"请稍后再试" |

## 17. 容量估算

### 17.1 数据量级（10 万 DAU 估算）

| 表 | 日增量 | 月增量 | 年增量 |
|----|--------|--------|--------|
| `xp_transaction` | ~50 万 | ~1500 万 | ~1.8 亿 |
| `checkin_record` | ~10 万 | ~300 万 | ~3600 万 |
| `point_transaction` | ~20 万 | ~600 万 | ~7200 万 |
| `user_badge` | ~2 万 | ~60 万 | ~720 万 |
| `activity_participation` | 波动大 | ~50 万 | ~600 万 |
| `leaderboard_snapshot` | ~5000 | ~15 万 | ~180 万 |
| `redeem_record` | ~5000 | ~15 万 | ~180 万 |

### 17.2 存储优化建议

- `xp_transaction`、`point_transaction`：按月分表或归档到 ClickHouse
- `leaderboard_snapshot`：保留近 90 天，历史数据归档
- `checkin_record`：按用户 + 月份组合查询为主，索引优化足够
- Redis 排行榜 ZSet：单 key 约 10 万 member，内存约 5MB/类型
