## 1. 概述

### 1.1 文档范围

本文档详细设计 PrimeTop 的**考前冲刺学习包（Exam Sprint Pack，简称 ESP）**，是增值服务与商品系统（VAS）下 `CONTENT_PACK` 子类的考试场景商品形态。学生可一次性购买针对某一考试（期中/期末/中考/高考/会考等）的冲刺学习包，解锁后按结构化日程进行知识点串讲、真题演练、模拟考试与能力复盘。

本模块只负责：

- 冲刺包的商品元数据、内容编排与日程规划。
- 用户购买/领取后的解锁、访问授权与有效期管理。
- 按日程生成的学习任务、练习会话、模拟考试与答题记录。
- 冲刺能力报告、薄弱点诊断与后续复习推荐。
- 与支付系统、用户资产、错题本、学情分析、学习规划的联动。

不负责：

- 题目内容生产与审核（由题目服务、内容审核管线负责）。
- 通用支付渠道处理（由支付与会员订阅系统负责，本模块调用其订单接口）。
- 通用会员订阅权益（由会员系统负责）。
- 寒暑假专题营的社群/打卡/排行榜玩法（由寒暑假专题与备考冲刺专区负责）。

### 1.2 术语定义

| 术语 | 英文 | 说明 |
|------|------|------|
| 冲刺包 | ExamSprintPack | 面向单次考试的可售卖学习集合，含日程、内容块、题目、模拟卷 |
| 内容块 | ContentBlock | 冲刺包内的最小学习单元，如知识点串讲、真题练习、模拟考试 |
| 日程 | StudySchedule | 按天编排的内容块序列，支持固定日期解锁或顺序解锁 |
| 用户包 | UserExamSprintPack | 用户购买/领取后产生的实例，记录有效期、解锁状态、学习进度 |
| 练习会话 | SprintPracticeSession | 用户在某内容块上的一次练习/考试，支持断点续答 |
| 冲刺报告 | SprintReport | 整个冲刺包或阶段性生成的考试能力诊断报告 |
| 模拟考试 | SprintMockExam | 内容块类型之一，限时、整卷、模拟真实考试流程 |

## 2. 数据结构设计

### 2.1 冲刺包主表 `exam_sprint_pack`

```sql
CREATE TABLE exam_sprint_pack (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT,
    pack_code           VARCHAR(64)  NOT NULL UNIQUE COMMENT '冲刺包编码，如 EXAM_SPRINT_GAO_KAO_MATH_2026',
    name                VARCHAR(128) NOT NULL COMMENT '包名称，如 "2026 高考数学冲刺包"',
    subtitle            VARCHAR(256) COMMENT '副标题',
    description         TEXT COMMENT '商品详情（富文本/Markdown）',
    cover_image         VARCHAR(512) COMMENT '封面图 URL',
    detail_images       JSON COMMENT '详情图 URL 列表',

    -- 考试定位
    exam_type           VARCHAR(32)  NOT NULL COMMENT '考试类型：MIDTERM/FINAL/ZHONG_KAO/GAO_KAO/HUI_KAO/MOCK',
    subject_code        VARCHAR(20)  NOT NULL COMMENT '学科编码',
    stage               TINYINT      NOT NULL COMMENT '学段：1幼儿 2小学 3初中 4高中',
    target_grades       JSON         NOT NULL COMMENT '适用年级列表，如 [10,11,12]',
    region_codes        JSON         COMMENT '适用地区编码，如 ["NATIONAL","BEING"]',

    -- 内容规格
    total_blocks        INT          NOT NULL DEFAULT 0 COMMENT '内容块总数',
    total_questions     INT          NOT NULL DEFAULT 0 COMMENT '题目总数',
    estimated_minutes   INT          COMMENT '预计完成总时长（分钟）',
    schedule_days       INT          NOT NULL DEFAULT 0 COMMENT '建议学习天数',
    difficulty_band     VARCHAR(16)  COMMENT '难度带：EASY/MEDIUM/HARD/MIXED',

    -- 日程解锁策略
    unlock_strategy     VARCHAR(32)  NOT NULL DEFAULT 'DATE' COMMENT 'DATE-按日期 / SEQUENTIAL-顺序 / FREE-立即全开',
    start_date_type     VARCHAR(32)  NOT NULL DEFAULT 'PURCHASE' COMMENT 'PURCHASE-购买后 / FIXED-固定日期 / EXAM_DATE-考前N天',
    start_date_offset   INT          DEFAULT 0 COMMENT 'EXAM_DATE 时考前 N 天开始',
    fixed_start_date    DATE         COMMENT '固定开始日期',
    fixed_end_date      DATE         COMMENT '固定结束日期',

    -- 定价与售卖
    original_price_cents INT         NOT NULL COMMENT '原价（分）',
    current_price_cents  INT         NOT NULL COMMENT '现价（分）',
    currency            VARCHAR(8)   DEFAULT 'CNY',
    validity_type       VARCHAR(16)  NOT NULL DEFAULT 'DAYS_AFTER_BUY' COMMENT 'PERMANENT/UNTIL_DATE/DAYS_AFTER_BUY',
    validity_days       INT          NOT NULL DEFAULT 30 COMMENT '购买后 N 天有效',
    fixed_end_at        DATETIME     COMMENT 'UNTIL_DATE 类型的统一截止日期',

    -- 销售控制
    status              TINYINT      NOT NULL DEFAULT 0 COMMENT '0草稿 1上架 2下架 3售罄 4归档',
    on_sale_at          DATETIME     COMMENT '上架时间',
    off_sale_at         DATETIME     COMMENT '下架时间',
    purchase_limit      INT          DEFAULT NULL COMMENT '每用户限购，NULL 不限',
    sort_order          INT          DEFAULT 0,

    -- 版本与权限
    content_version     INT          NOT NULL DEFAULT 1 COMMENT '内容版本，用于更新后增量同步',
    min_app_version     VARCHAR(32)  COMMENT '最低客户端版本',

    created_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by          BIGINT       COMMENT '创建人',

    INDEX idx_exam_subject_stage (exam_type, subject_code, stage),
    INDEX idx_status_sort (status, sort_order),
    INDEX idx_target_grades ((CAST(target_grades AS UNSIGNED ARRAY))),
    INDEX idx_on_sale (on_sale_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='考前冲刺学习包主表';
```

### 2.2 冲刺包内容块表 `esp_content_block`

```sql
CREATE TABLE esp_content_block (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT,
    pack_id             BIGINT       NOT NULL COMMENT '关联 exam_sprint_pack.id',
    block_code          VARCHAR(64)  NOT NULL COMMENT '块编码，包内唯一',
    block_type          VARCHAR(32)  NOT NULL COMMENT '类型：KNOWLEDGE_REVIEW/PRACTICE/MOCK_EXAM/REVIEW_DAY/TIP',
    title               VARCHAR(128) NOT NULL COMMENT '块标题',
    description         TEXT         COMMENT '块描述',

    -- 日程编排
    day_number          INT          NOT NULL COMMENT '第几天，从 1 开始',
    order_in_day        INT          NOT NULL DEFAULT 1 COMMENT '当天顺序',
    unlock_day_offset   INT          NOT NULL DEFAULT 0 COMMENT '相对于开始日第 N 天解锁',

    -- 内容引用
    knowledge_ids       JSON         COMMENT '覆盖知识点ID列表',
    question_ids        JSON         COMMENT '关联题目ID列表',
    mock_exam_paper_id  BIGINT       COMMENT '模拟考试卷ID',
    recommended_content JSON         COMMENT '推荐学习内容ID列表（视频/文章/AI讲解）',

    -- 完成条件
    completion_type     VARCHAR(32)  NOT NULL DEFAULT 'VIEW' COMMENT 'VIEW/DURATION/QUESTION_COUNT/ACCURACY/SUBMIT',
    completion_config   JSON         COMMENT '完成条件配置，如 {"min_questions":10,"min_accuracy":0.6}',
    estimated_minutes   INT          COMMENT '预计用时（分钟）',

    -- 元数据
    tags                JSON         COMMENT '标签',
    content_version     INT          NOT NULL DEFAULT 1,
    status              TINYINT      NOT NULL DEFAULT 1 COMMENT '0禁用 1启用',
    created_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE INDEX uk_pack_block (pack_id, block_code),
    INDEX idx_pack_day (pack_id, day_number, order_in_day),
    INDEX idx_block_type (block_type),

    FOREIGN KEY (pack_id) REFERENCES exam_sprint_pack(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='冲刺包内容块表';
```

### 2.7 Redis 键设计

| 键名 | 类型 | 说明 | TTL |
|------|------|------|-----|
| `esp:pack:{pack_id}` | Hash | 冲刺包元数据缓存 | 10 min |

| `esp:count:report_gen:{user_pack_id}` | String | 报告生成限流计数 | 1 min |

### 4.1 日程解锁判定器

```python
class ScheduleUnlockEvaluator:
    def __init__(self, user_pack: UserExamSprintPack, blocks: list[EspContentBlock]):
        self.user_pack = user_pack
        self.blocks = blocks

    def evaluate(self, now: datetime = None) -> list[UnlockDecision]:
        now = now or datetime.now(timezone.utc)
        strategy = self.user_pack.pack.unlock_strategy
        decisions = []

        base_date = self.user_pack.start_date or now.date()
        elapsed_days = (now.date() - base_date).days + 1

        for block in self.blocks:
            decision = UnlockDecision(block_id=block.id, unlock=False)

            if strategy == UnlockStrategy.FREE:
                decision.unlock = True
            elif strategy == UnlockStrategy.SEQUENTIAL:
                # 第一天默认解锁；后续需前一天全部完成
                if block.day_number == 1:
                    decision.unlock = True
                else:
                    prev_blocks = [b for b in self.blocks if b.day_number == block.day_number - 1]
                    decision.unlock = all(self._is_completed(b.id) for b in prev_blocks)
            elif strategy == UnlockStrategy.DATE:
                # 按日期解锁：达到当天即可
                decision.unlock = elapsed_days >= block.day_number

            if decision.unlock:
                decision.unlock_time = datetime.combine(
                    base_date + timedelta(days=block.day_number - 1),
                    time.min,
                    tzinfo=now.tzinfo
                )
            decisions.append(decision)

        return decisions

    def _is_completed(self, block_id: int) -> bool:
        # 从 Redis/DB 读取完成状态
        return get_schedule_status(self.user_pack.id, block_id) == ScheduleStatus.COMPLETED
```

### 4.2 内容块完成条件评估器

```python
class CompletionEvaluator:
    CRITERIA_EVALUATORS = {
        'VIEW': lambda session, config: True,
        'DURATION': lambda session, config: session.study_seconds >= config.get('min_seconds', 0),
        'QUESTION_COUNT': lambda session, config: session.answered_count >= config.get('min_questions', 0),
        'ACCURACY': lambda session, config: (session.accuracy or 0) >= config.get('min_accuracy', 0),
        'SUBMIT': lambda session, config: session.status in (SessionStatus.SUBMITTED, SessionStatus.COMPLETED),
    }

    def evaluate(self, block: EspContentBlock, session: EspPracticeSession) -> bool:
        evaluator = self.CRITERIA_EVALUATORS.get(block.completion_type)
        if not evaluator:
            return False
        return evaluator(session, block.completion_config or {})
```

### 4.4 提交处理核心流程（伪代码）

```python
@transactional
def submit_session(user_id, user_pack_id, block_id, request: SubmitRequest):
    # 1. 幂等锁
    lock_key = f"esp:lock:submit:{request.session_id}"
    if not redis.set(lock_key, "1", nx=True, ex=30):
        raise BizError(59211, "提交处理中，请勿重复提交")

    # 2. 加载并校验
    session = session_repo.get(request.session_id)
    if session.user_id != user_id or session.block_id != block_id:
        raise BizError(59207, "会话归属校验失败")
    if session.status != SessionStatus.ONGOING:
        raise BizError(59208, "会话已结束")

    user_pack = user_pack_repo.get_for_update(user_pack_id)
    block = block_repo.get(block_id)

    # 3. 判题
    results = judge_service.batch_judge(block.question_ids, request.answers)
    session.correct_count = sum(1 for r in results if r.is_correct)
    session.answered_count = len(request.answers)
    session.accuracy = int(session.correct_count / session.total_questions * 10000)
    session.status = SessionStatus.SUBMITTED
    session.submitted_at = now()
    session_repo.update(session)

    # 4. 更新日程完成状态
    completed = completion_evaluator.evaluate(block, session)
    if completed:
        schedule_repo.mark_completed(user_pack_id, block_id, session.id)

    # 5. 更新用户包进度
    user_pack.answered_questions += session.answered_count
    user_pack.correct_questions += session.correct_count
    user_pack.completed_blocks = schedule_repo.count_completed(user_pack_id)
    user_pack.total_study_minutes += session.duration_minutes
    if user_pack.completed_blocks >= user_pack.total_blocks:
        user_pack.status = UserPackStatus.FINISHED
    user_pack_repo.update(user_pack)

    # 6. 同步错题（异步 Outbox）
    for r in results:
        if not r.is_correct:
            outbox_repo.publish(
                topic='esp.mistake.created',
                payload={
                    'user_id': user_id,
                    'question_id': r.question_id,
                    'source': 'EXAM_SPRINT',
                    'user_pack_id': user_pack_id,
                    'block_id': block_id
                }
            )

    # 7. 触发报告生成检查
    report_scheduler.check_and_trigger(user_pack_id)

    return session
```

                购买/领取
                   │
                   ▼
┌─────────┐   激活/开始   ┌─────────┐   完成全部内容块   ┌──────────┐

     │                        │

└─────────┘              └─────────┘

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| LOCKED | 已购买但未激活 | 查看预览、激活 |

| PAUSED | 暂停（保留进度，不计时） | 恢复学习（V1.5） |
| FINISHED | 已完成全部内容块 | 查看报告、复习错题 |

### 6.2 降级策略

| 场景 | 降级行为 | 红线 |
|------|---------|------|
| Redis 缓存不可用 | 直查 DB，响应延迟增加 | 不拒绝核心读请求 |

## 9. 合规要点

1. **未成年人付费**：购买前必须校验家长门/监护人授权，15 周岁以下需家长确认（委托用户额度管控与功能门控引擎）。
2. **内容适龄**：冲刺包内容需按学段、年级过滤，不得向低年级展示超纲内容。
3. **虚假宣传**：商品详情不得承诺「保分」「提分 X 分」等效果性承诺。
4. **退款规则**：未激活且未超过 7 天无理由期的支持退款；已激活/已过期的按剩余价值折算（委托订单售后处理服务）。
5. **数据隐私**：学习包进度、报告不向第三方透露，家长端按绑定权限可见。
6. **AIGC 标识**：AI 生成的报告解读、推荐话术需在界面标注「AI 生成」。

| AC-09 | 提交后错题自动收录 | 错题服务收到 `esp.mistake.created` 事件 |
| AC-10 | 阶段性报告生成 | 完成第 7 天后自动生成 PHASE 报告 |
| AC-11 | 结包报告生成 | 完成全部内容块后生成 FINAL 报告 |
| AC-12 | 重复激活幂等 | 同一 `client_request_id` 返回相同结果，不重复创建日程 |
| AC-13 | 过期后不可学习 | 状态变为 EXPIRED，练习接口返回 59203 |
| AC-14 | 内容版本更新 | 已购用户包按原版本内容完成，新购买用户获得新版本 |
| AC-15 | 退款后权益回收 | 用户包状态回滚为 LOCKED 或标记 REFUNDED |
| AC-16 | 弱网环境下提交 | 答案本地保存，恢复网络后幂等提交不重复计分 |
| AC-17 | 多端同步 | 同一用户在不同设备看到一致的进度和日程 |
| AC-18 | 学情分析联动 | 报告中的薄弱知识点同步至学情分析模块 |
