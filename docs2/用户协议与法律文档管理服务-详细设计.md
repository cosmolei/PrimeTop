# 用户协议与法律文档管理服务 - 详细设计

> **版本**: v1.0 | **日期**: 2026-05-25 | **状态**: 初稿
> **关联文档**: 数据安全与隐私合规体系、用户账号体系、家长中心、权限管理与角色访问控制、客户端架构与前端框架、防沉迷与未成年人保护机制

---

## 1. 模块概述

### 1.1 功能定位

用户协议与法律文档管理服务负责管理 PrimeTop 产品中所有面向用户的法律文档（隐私政策、用户协议、儿童个人信息保护规则等），包括文档的版本管理、发布上线、用户同意记录追踪、强制更新机制和合规审计。本模块是产品合规运营的**基础设施层**，确保所有用户（特别是未成年人）在使用产品前完成必要的法律授权。

### 1.2 为什么需要这个模块

1. **法律合规要求**：《个人信息保护法》《儿童个人信息网络保护规定》《App违法违规收集使用个人信息行为认定方法》等法规要求 APP 在收集个人信息前获得用户（或监护人）同意
2. **未成年人保护**：14 周岁以下用户的个人信息处理需获得监护人同意，需要独立的同意管理机制
3. **版本更新管理**：隐私政策或用户协议更新时，需要告知用户并获取新版本同意
4. **审计追溯**：监管检查时需要提供完整的用户同意记录

### 1.3 文档类型清单

| 文档类型 | 枚举值 | 适用对象 | 是否必须同意 | 更新频率 |
|----------|--------|----------|-------------|----------|
| 用户服务协议 | `terms_of_service` | 全部用户 | 是 | 低（年均 1-2 次） |
| 隐私政策 | `privacy_policy` | 全部用户 | 是 | 中（季均 1-2 次） |
| 儿童个人信息保护规则 | `children_privacy` | <14 岁用户及其监护人 | 是 | 中 |
| 家长授权协议 | `parental_consent` | 监护人（绑定 <14 岁账号时） | 是 | 低 |
| 会员服务协议 | `membership_agreement` | 付费会员 | 是 | 低 |
| 第三方信息共享清单 | `third_party_sharing` | 全部用户 | 是（随隐私政策） | 中 |
| Cookie/SDK 声明 | `cookie_sdk_notice` | 全部用户 | 是（首次启动） | 低 |

### 1.4 目标指标

| 指标 | 目标值 |
|------|--------|
| 同意记录写入延迟 | ≤ 50ms |
| 文档加载延迟（CDN） | ≤ 200ms |
| 协议弹窗渲染时间 | ≤ 300ms |
| 合规审计报告生成 | ≤ 10s |
| 同意记录数据保留 | 账号存续期 + 注销后 3 年 |

```python
    """文档变更类型"""
    MINOR = "minor"           # 小改动（措辞调整、错别字）→ 不强制重新同意

class ConsentAction(str, Enum):
    """同意动作"""
    ACCEPTED = "accepted"
    REJECTED = "rejected"
    WITHDRAWN = "withdrawn"

    """同意方式"""
    DIALOG_CLICK = "dialog_click"             # 弹窗点击同意
    SIGNUP_FLOW = "signup_flow"               # 注册流程中同意
    SETTINGS_PAGE = "settings_page"           # 设置页手动同意
    GUARDIAN_DELEGATE = "guardian_delegate"   # 监护人代为同意
    API_CONFIRM = "api_confirm"               # API 调用确认

    """同意场景"""

    LOGIN = "login"                 # 登录（有新协议时）
```

```python
@dataclass
class LegalDocument:

    def requires_consent(self) -> bool:
```

### 3.3 用户同意状态模型

```python
@dataclass
class UserConsentState:
    """用户的法律文档同意状态"""
    user_id: int
    is_minor: bool                             # 是否 <14 岁
    has_guardian: bool                         # 是否有监护人绑定
    documents: Dict[LegalDocType, DocConsentStatus]

    @property
    def is_fully_compliant(self) -> bool:
        """是否所有必要文档都已同意"""
        required = self._get_required_docs()
        return all(
            self.documents.get(dt, DocConsentStatus()).is_accepted
            for dt in required
        )

    @property
    def blocking_docs(self) -> List[LegalDocType]:
        """需要立即同意的文档（阻断使用）"""
        return [
            dt for dt, status in self.documents.items()
            if status.needs_accept and status.is_blocking
        ]

    def _get_required_docs(self) -> List[LegalDocType]:
        """根据用户类型确定必须同意的文档"""
        required = [
            LegalDocType.TERMS_OF_SERVICE,
            LegalDocType.PRIVACY_POLICY,
        ]
        if self.is_minor:
            required.extend([
                LegalDocType.CHILDREN_PRIVACY,
            ])
        return required


@dataclass
class DocConsentStatus:
    """单个文档的同意状态"""
    doc_type: LegalDocType
    current_version: Optional[str]             # 当前生效版本
    accepted_version: Optional[str]            # 用户已同意版本
    is_accepted: bool                          # 是否已同意
    needs_accept: bool                         # 是否需要同意（版本更新等）
    is_blocking: bool                          # 是否阻断使用
    deadline: Optional[datetime]               # 同意截止时间
    pending_id: Optional[int]                  # pending_consent 记录 ID
```

## 4. 核心流程设计

### 4.1 注册流程中的同意收集

```
用户点击"注册"
    │
    ▼
[1] 检查注册必要文档列表
    ├── 用户服务协议 (terms_of_service)
    ├── 隐私政策 (privacy_policy)
    └── (若 <=14 岁) 儿童个人信息保护规则 (children_privacy)
    │
    ▼
[2] 获取各文档当前生效版本
    │
    ▼
[3] 渲染注册页 → 底部勾选框 "已阅读并同意《用户协议》《隐私政策》"
    │                                    (<=14岁额外勾选《儿童信息保护规则》)
    ▼
[4] 用户勾选 → 提交注册
    │
    ▼
[5] 后端批量写入 user_consent 记录
    ├── consent_method = signup_flow
    ├── scene = signup
    └── (<=14岁) 同时创建 pending_consent → 家长授权流程
    │
    ▼
[6] (<=14岁) 引导进入家长绑定流程
    ├── 家长扫码或输入手机号
    ├── 家长同意 parental_consent
    └── 写入 guardian_consent 记录
    │
    ▼
[7] 注册完成，进入 APP
```

### 4.2 APP 启动时的同意检查

```python
class ConsentCheckService:
    """APP 启动时的同意检查服务"""

    def __init__(
        self,
        doc_repo: LegalDocumentRepository,
        consent_repo: UserConsentRepository,
        pending_repo: PendingConsentRepository,
        audit_logger: ConsentAuditLogger,
    ):
        self._doc_repo = doc_repo
        self._consent_repo = consent_repo
        self._pending_repo = pending_repo
        self._audit = audit_logger

    async def check_on_launch(
        self,
        user_id: int,
        is_minor: bool,
        has_guardian: bool,
    ) -> ConsentCheckResult:
        """
        APP 启动时检查用户同意状态。
        
        Returns:
            ConsentCheckResult: 包含待同意文档列表和是否阻断使用
        """
        # Step 1: 确定用户需要同意的文档类型
        required_types = self._get_required_doc_types(is_minor, has_guardian)

        # Step 2: 获取各文档当前生效版本
        current_docs = await self._doc_repo.get_published_versions(required_types)

        # Step 3: 获取用户已有同意记录
        accepted_versions = await self._consent_repo.get_accepted_versions(
            user_id=user_id,
            doc_types=required_types,
        )

        # Step 4: 对比版本，确定需要更新的文档
        pending_items: List[PendingConsentItem] = []

        for doc_type, doc in current_docs.items():
            accepted_ver = accepted_versions.get(doc_type)

            if accepted_ver is None:
                # 从未同意 → 必须同意（阻断）
                pending_items.append(PendingConsentItem(
                    doc_type=doc_type,
                    doc_version=doc.version,
                    doc_id=doc.id,
                    priority=1,
                    block_access=True,
                    deadline=None,
                    reason="never_accepted",
                ))

            elif self._version_lt(accepted_ver, doc.version):
                # 版本低于当前版本
                if doc.is_major_change and doc.force_accept_before:
                    # 重大变更 → 阻断使用
                    pending_items.append(PendingConsentItem(
                        doc_type=doc_type,
                        doc_version=doc.version,
                        doc_id=doc.id,
                        priority=1,
                        block_access=True,
                        deadline=doc.force_accept_before,
                        reason="major_update",
                    ))
                elif doc.is_major_change:
                    # 重大变更但无强制截止日 → 高优先级提醒
                    pending_items.append(PendingConsentItem(
                        doc_type=doc_type,
                        doc_version=doc.version,
                        doc_id=doc.id,
                        priority=2,
                        block_access=False,
                        deadline=doc.effective_date + timedelta(days=30),
                        reason="major_update",
                    ))
                else:
                    # minor 改动 → 不强制，记录即可
                    await self._consent_repo.auto_accept_minor(
                        user_id=user_id,
                        doc_type=doc_type,
                        doc_version=doc.version,
                        doc_id=doc.id,
                    )

        # Step 5: 未成年人监护人同意检查
        if is_minor and not has_guardian:
            pending_items.append(PendingConsentItem(
                doc_type=LegalDocType.PARENTAL_CONSENT,
                doc_version="n/a",
                doc_id=0,
                priority=1,
                block_access=True,
                deadline=None,
                reason="no_guardian",
            ))

        # Step 6: 写入待同意队列
        for item in pending_items:
            await self._pending_repo.upsert(
                user_id=user_id,
                item=item,
            )

        # Step 7: 返回检查结果
        has_blocking = any(item.block_access for item in pending_items)

        result = ConsentCheckResult(
            user_id=user_id,
            is_compliant=not has_blocking,
            pending_items=pending_items,
            has_blocking=has_blocking,
        )

        # Step 8: 审计日志
        await self._audit.log(
            action="consent_check_on_launch",
            actor_id=user_id,
            actor_type="user",
            target_user_id=user_id,
            detail={
                "pending_count": len(pending_items),
                "has_blocking": has_blocking,
                "pending_types": [item.doc_type for item in pending_items],
            },
        )

        return result

    def _get_required_doc_types(
        self, is_minor: bool, has_guardian: bool
    ) -> List[LegalDocType]:
        """确定用户必须同意的文档类型"""
        types = [
            LegalDocType.TERMS_OF_SERVICE,
            LegalDocType.PRIVACY_POLICY,
        ]
        if is_minor:
            types.append(LegalDocType.CHILDREN_PRIVACY)
        return types

    @staticmethod
    def _version_lt(v1: str, v2: str) -> bool:
        """比较语义版本号 v1 < v2"""
        parts1 = [int(p) for p in v1.split('.')]
        parts2 = [int(p) for p in v2.split('.')]
        return parts1 < parts2


@dataclass
class ConsentCheckResult:
    """同意检查结果"""
    user_id: int
    is_compliant: bool                        # 是否合规（无阻断项）
    pending_items: List[PendingConsentItem]    # 待同意列表
    has_blocking: bool                        # 是否有阻断项


@dataclass
class PendingConsentItem:
    """待同意项"""
    doc_type: LegalDocType
    doc_version: str
    doc_id: int
    priority: int                             # 1=最高(阻断), 5=最低
    block_access: bool
    deadline: Optional[datetime]
    reason: str                               # never_accepted/major_update/no_guardian
```

```python
        consent_method: ConsentMethod,
        scene: ConsentScene,
        client_info: ClientInfo,
    ) -> ConsentAcceptResult:
        """
        用户同意某个文档版本。
        
        流程：
        1. 校验文档版本是否存在且有效
        2. 创建同意快照（截屏/记录页面状态）
        3. 写入 user_consent 记录
        4. 更新 pending_consent 状态
        5. 写入审计日志
        6. 返回同意结果
        """
        # Step 1: 校验文档版本
        doc = await self._doc_repo.get_by_type_version(doc_type, doc_version)
        if not doc or doc.status != 'published':
            raise InvalidDocumentVersionError(
                f"文档 {doc_type} 版本 {doc_version} 不存在或未发布"
            )

        # Step 2: 创建同意快照
        snapshot_url = await self._snapshot.capture(
            user_id=user_id,
            doc_type=doc_type,
            doc_version=doc_version,
            client_info=client_info,
        )

        # Step 3: 写入同意记录
        consent_id = await self._consent_repo.create(
            user_id=user_id,
            doc_type=doc_type,
            doc_version=doc_version,
            doc_id=doc.id,
            consent_action=ConsentAction.ACCEPTED,
            consent_method=consent_method,
            scene=scene,
            client_platform=client_info.platform,
            client_version=client_info.app_version,
            device_id=client_info.device_id,
            ip_address=client_info.ip_address,
            user_agent=client_info.user_agent,
            snapshot_url=snapshot_url,
        )

        # Step 4: 更新待同意队列
        await self._pending_repo.mark_accepted(
            user_id=user_id,
            doc_type=doc_type,
            doc_version=doc_version,
        )

        # Step 5: 审计日志
        await self._audit.log(
            action="consent_accepted",
            actor_id=user_id,
            actor_type="user",
            target_user_id=user_id,
            doc_type=doc_type,
            doc_version=doc_version,
            detail={
                "consent_id": consent_id,
                "method": consent_method,
                "scene": scene,
                "has_snapshot": bool(snapshot_url),
            },
            ip_address=client_info.ip_address,
        )

        return ConsentAcceptResult(
            consent_id=consent_id,
            doc_type=doc_type,
            doc_version=doc_version,
            accepted_at=datetime.utcnow(),
        )

    async def reject(
        self,
        user_id: int,
        doc_type: LegalDocType,
        doc_version: str,
        scene: ConsentScene,
        client_info: ClientInfo,
    ) -> None:
        """用户拒绝同意（记录拒绝行为）"""
        # 对于必要文档，拒绝 = 无法使用 APP
        # 此处仅记录，由前端处理退出逻辑

        doc = await self._doc_repo.get_by_type_version(doc_type, doc_version)

        await self._consent_repo.create(
            user_id=user_id,
            doc_type=doc_type,
            doc_version=doc_version,
            doc_id=doc.id
,
            consent_action=ConsentAction.REJECTED,
            consent_method=ConsentMethod.DIALOG_CLICK,
            scene=scene,
            client_platform=client_info.platform,
            client_version=client_info.app_version,
            device_id=client_info.device_id,
            ip_address=client_info.ip_address,
            user_agent=client_info.user_agent,
            snapshot_url=None,
        )

        await self._audit.log(
            action="consent_rejected",
            actor_id=user_id,
            actor_type="user",
            target_user_id=user_id,
            doc_type=doc_type,
            doc_version=doc_version,
            detail={"scene": scene},
            ip_address=client_info.ip_address,
        )

    async def withdraw(
        self,
        user_id: int,
        doc_type: LegalDocType,
        client_info: ClientInfo,
    ) -> None:
        """
        用户撤回同意。
        
        规则：
        1. 用户服务协议/隐私政策为必要文档，撤回 = 触发账号注销引导，而非简单标记
        2. 可选文档（如营销授权）允许直接撤回
        3. 撤回必须记录审计日志并通知监护人（未成年用户）
        """
        # 校验是否允许撤回
        if doc_type in (LegalDocType.TERMS_OF_SERVICE, LegalDocType.PRIVACY_POLICY):
            raise ConsentNotWithdrawableError(
                "必要协议不可直接撤回，请使用账号注销流程"
            )

        latest = await self._consent_repo.get_latest(user_id, doc_type)
        if not latest or latest.consent_action != ConsentAction.ACCEPTED:
            raise ConsentStateConflictError("当前无可撤回的同意记录")

        await self._consent_repo.create(
            user_id=user_id,
            doc_type=doc_type,
            doc_version=latest.doc_version,
            doc_id=latest.doc_id,
            consent_action=ConsentAction.WITHDRAWN,
            consent_method=ConsentMethod.SETTINGS_PAGE,
            scene=ConsentScene.FEATURE_ACCESS,
            client_platform=client_info.platform,
            client_version=client_info.app_version,
            device_id=client_info.device_id,
            ip_address=client_info.ip_address,
            user_agent=client_info.user_agent,
            snapshot_url=None,
        )

        await self._audit.log(
            action="consent_withdrawn",
            actor_id=user_id,
            actor_type="user",
            target_user_id=user_id,
            doc_type=doc_type,
            doc_version=latest.doc_version,
            detail=None,
            ip_address=client_info.ip_address,
        )


class InvalidDocumentVersionError(Exception):
    """文档版本不存在或未发布"""
    pass


class ConsentNotWithdrawableError(Exception):
    """必要协议不允许直接撤回"""
    pass


class ConsentStateConflictError(Exception):
    """同意状态冲突（重复提交/无可撤回记录）"""
    pass


@dataclass
class ConsentAcceptResult:
    """同意提交结果"""
    consent_id: int
    doc_type: LegalDocType
    doc_version: str
    accepted_at: datetime


@dataclass
class ClientInfo:
    """客户端信息（随同意请求上送）"""
    platform: str                          # ios/android/web/miniapp
    app_version: str                       # 如 "2.3.1"
    device_id: Optional[str] = None
    ip_address: Optional[str] = None
    user_agent: Optional[str] = None
```

### 4.4 监护人授权流程（≤14 岁）

```
孩子账号注册（≤14 岁）
    │
    ▼
[1] 孩子勾选《儿童个人信息保护规则》（自己无法律行为能力）
    ├── 写入 user_consent(child, children_privacy, guardian_delegate)
    └── 创建 pending_consent(guardian_consent, block_access=1)
    │
    ▼
[2] 引导家长绑定
    ├── 方式 A：家长端 APP 扫码（二维码含 child_binding_token，TTL 10min）
    ├── 方式 B：家长手机号 + 短信验证码验证
    └── 方式 C：人工客服审核（兜底）
    │
    ▼
[3] 家长阅读并同意《家长授权协议》
    ├── 展示家长授权协议当前版本
    ├── 家长勾选同意
    └── 录入监护人身份信息（姓名/证件号/与儿童关系）
    │
    ▼
[4] 监护人身份核验
    ├── sms：短信验证码核验手机号
    ├── face：人脸核验（对接实名认证服务）
    └── manual：人工审核（T+1）
    │
    ▼
[5] 写入 guardian_consent 记录
    ├── guardian_id_hash = SHA256(证件号 + 盐)
    ├── verification_status = verified
    └── consent_record_id 关联家长的 user_consent 记录
    │
    ▼
[6] 解除阻断
    ├── pending_consent(guardian_consent) → accepted
    ├── user_consent(child, parental_consent, guardian_delegate)
    └── 通知孩子账号"家长已完成授权"
    │
    ▼
[7] 审计日志 + 事件扇出（guardian.bound）
```

监护人核验状态机：

| 状态 | 说明 | 进入条件 | 退出条件 |
|------|------|----------|----------|
| `pending` | 待核验 | 创建绑定申请 | 核验通过/失败/超时 |
| `verified` | 已核验 | 短信/人脸核验通过 | 监护人主动解绑 |
| `rejected` | 核验失败 | 核验未通过 | 可重新发起（≤3 次/日） |
| `expired` | 申请过期 | 二维码/令牌超 10min 未使用 | 重新生成 |

### 4.5 文档发布生命周期（管理后台）

```
法务/运营起草新版本（draft）
    │
    ▼
[1] 内容合规评审 → 记录评审人/评审意见
    │
    ▼
[2] 法务终审 → status: draft → approved（预留字段，当前用 detail JSON 记录）
    │
    ▼
[3] 设置生效参数
    ├── effective_date（生效日期）
    ├── change_type（minor/major/correction）
    └── force_accept_before（仅 major：强制同意截止日）
    │
    ▼
[4] 发布（published）
    ├── 内容上传 CDN + 计算 content_hash
    ├── 同类型旧版本 → archived
    └── Outbox 事件 legaldoc.published
    │
    ▼
[5] major 变更触发批量重同意
    ├── 扫描受影响用户（applicable_users 过滤）
    ├── 批量写入 pending_consent（分批 1000/批，避免长事务）
    └── 客户端下次启动/登录时弹出重同意弹窗
    │
    ▼
[6] 到期处理
    ├── 到达 force_accept_before 仍未同意 → 服务端下发阻断标记
    └── 宽限策略见 §11 降级矩阵
```

## 6. 状态机与守卫规则

### 6.1 文档版本状态机

```
draft ──publish──> published ──supersede──> archived
  │                    │
  └──discard──> (删除)  └──unpublish──> draft（仅未生效前允许）
```

### 6.2 待同意队列状态机

```
pending ──accept──> accepted
   │                     │
   │                     └──（major 再发新版）──> pending(新版本)
   ├──deadline 超期──> expired（非阻断项）
   └──bypass（运营豁免）──> bypassed（必须双人审批）
```

### 6.3 守卫规则表

| 编号 | 规则 | 说明 |
|------|------|------|
| G1 | 发布唯一性 | 同 doc_type 同时只允许一个 published 版本（DB 部分唯一索引保障：`status` 为 published 时唯一，MySQL 可用生成列实现） |
| G2 | 生效时间不可回溯 | `effective_date` 必须 > now() - 5min（容忍时钟偏移），禁止发布"已生效"的历史版本 |
| G3 | 同意版本一致性 | `user_consent.doc_version` 必须是当时 published 的版本；过期版本接受同意时返回 51505 |
| G4 | major 必配截止日 | `change_type=major` 且 applicable_users=all 时，`force_accept_before` 必填 |
| G5 | 未成年人双重同意 | <14 岁用户：children_privacy 由监护人代同意后，才允许进入主流程（fail-closed） |
| G6 | 监护人唯一性 | 同一 child 同一 guardian_user_id 仅一条 verified 记录（uk 保障） |
| G7 | 撤回限制 | 必要文档不可撤回，只能注销（服务端 51508 拒绝） |
| G8 | 阻断项不可绕过 | `block_access=1` 的 pending 项未 accepted 前，业务网关对受保护功能返回 51503 |
| G9 | 快照必存 | 弹窗场景同意必须生成 snapshot（快照生成失败时整体失败重试，不允许无快照写库） |
| G10 | 审计不可改 | consent_audit_log 只允许 INSERT，禁用 UPDATE/DELETE（DB 账号级权限） |
| G11 | minor 自动接受 | minor/correction 变更不弹窗，自动写 accepted 记录（仍需落 user_consent） |
| G12 | 批量重同意限流 | major 发布后的扫描任务限速 1000 用户/秒，避免打满 DB |

## 7. 幂等与并发处理

| 场景 | 方案 |
|------|------|
| 同意重复提交 | Idempotency-Key + `(user_id, doc_type, doc_version)` 唯一约束；重复请求返回原记录 |
| 弹窗与设置页同时同意 | DB 唯一约束兜底，第二个请求收到 51504 冲突，客户端按"已同意"处理 |
| major 扫描与主动同意竞态 | `pending_consent` upsert 采用 `INSERT ... ON DUPLICATE KEY UPDATE`，以先 accepted 者为准 |
| 监护人重复绑定 | `uk_child_guardian` 冲突时返回已有 binding_id，引导继续未完成流程 |
| 发布并发 | 发布接口加分布式锁（key=`legal:publish:{doc_type}`），防止两个 major 同时发布 |
| 注销与同意并发 | 账号注销流程获取用户级锁，注销后拒绝一切同意写入（51510） |

## 8. 事件与对账

### 8.1 Outbox 事件

| 事件 | 触发 | 消费方 |
|------|------|--------|
| `legaldoc.published` | 文档发布 | 消息中心（全员公告）、客户端推送（major） |
| `legaldoc.archived` | 版本归档 | 缓存刷新 |
| `consent.accepted` | 用户同意 | 用户服务（合规标记）、风控、数据分析 |
| `consent.rejected` | 用户拒绝 | 风控、运营 |
| `consent.withdrawn` | 撤回 | 风控、消息中心 |
| `guardian.bound` | 监护人核验通过 | 家长中心、家庭账户服务 |

### 8.2 对账任务（每日 04:50）

1. `user_consent` 中 accepted 记录 vs 对应版本在生效期内存在（孤儿记录告警）
2. `pending_consent.status=accepted` ⇔ 存在同版本 `user_consent` accepted 记录（双向核对）
3. 未成年人用户必有 verified 监护人（无监护人且非 pending 的未成年账号 → P1 告警）

## 10. 降级策略

| 场景 | 降级方案 |
|------|----------|
| 快照服务不可用 | 同意流程整体失败（G9 不可降级），客户端提示稍后重试；不得绕过快照写库 |
| CDN 文档加载失败 | 客户端展示内置兜底文案页 + "加载失败重试"，阻断项维持阻断 |
| 同意服务整体不可用 | 网关 fail-open 仅对老用户（已有全部必要文档同意记录）放行只读功能；新用户/新协议场景 fail-closed |
| major 扫描积压 | 允许 24h 内逐步完成，期间靠登录/启动检查补齐（不依赖扫描完成） |
| 审计日志写入失败 | 阻塞操作（G10），该次同意回滚并提示重试 |

## 11. 监控指标

| 指标 | 告警阈值 |
|------|----------|
| 同意提交成功率 | <99.9% 持续 5min → P2 |
| 阻断性弹窗展示-同意转化率 | major 版本 7 日 <40% → 运营告警 |
| 快照生成耗时 P99 | >2s → P3 |
| `force_accept_before` 到期未同意用户数 | >1000 → P2（法务同步） |
| 未成年人无监护人告警数 | >0 → P1 |
| Outbox 事件积压 | >10k → P2 |

## 12. 合规要点

1. C1：14 周岁以下必须取得监护人同意（《儿童个人信息网络保护规定》第 9 条），G5 为 fail-closed 强制项。
2. C2：同意记录（含快照）留存至账号注销后 3 年（《个人信息保护法》审计要求）。
3. C3：监护人证件号仅存哈希；姓名脱敏存储（保留首尾字符）。
4. C4：第三方共享清单随隐私政策版本更新，SDK 变更必须走 major 流程。
5. C5：拒绝同意不得诱导再次弹出——同一版本最多弹 3 次，其后仅在设置页入口展示。
6. C6：撤回同意后，依赖该授权的加工行为（如个性化推荐）必须在 72h 内停止。
