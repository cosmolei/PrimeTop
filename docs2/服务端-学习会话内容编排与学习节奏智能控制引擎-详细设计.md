## 1. 概述

### 1.1 设计目标

本引擎负责在**单次学习会话**（一次连续的学习活动，通常 15~60 分钟）内，实时决定：

- **呈现什么内容**：新知识点讲解、练习题、错题复习、旧知识巩固的选材
- **以什么顺序呈现**：内容的前后依赖、难度梯度、认知切换成本
- **以什么节奏推进**：加速 / 减速 / 插入休息 / 切换学科
- **何时结束或延长**：基于学习目标完成度、学生疲劳信号、时间预算

引擎每 30~90 秒进行一次决策窗口评估，动态调整会话内容队列，使学生在有限时间内获得最高效的学习体验。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **学习科学驱动** | 依据间隔重复、交错练习（Interleaving）、认知负荷理论编排内容 |
| **实时响应** | 基于当前会话内的答题结果、耗时、行为信号动态调整 |
| **目标导向** | 每次会话有明确学习目标，编排服务于目标达成 |
| **防过度挑战** | 当连续错误超过阈值时自动降级，防止挫败感积累 |
| **防无效重复** | 当学生已掌握时快速推进，避免时间浪费 |
| **可解释性** | 每次编排决策附带理由标签，供前端展示和教师查看 |

### 1.3 与现有模块的边界

| 现有模块 | 职责 | 与本引擎的关系 |
|---------|------|---------------|
| 学习会话编排与上下文管理引擎 | 会话生命周期（创建/暂停/恢复/结束）、上下文存储 | 本引擎消费会话上下文，输出内容队列，由会话引擎执行 |
| 间隔重复算法与遗忘曲线复习调度引擎 | 计算遗忘曲线、安排复习日期和复习内容候选 | 本引擎从复习候选池中选取内容，决定在当前会话中是否安排 |
| 题目智能推荐与个性化练习编排服务 | 基于能力画像推荐适合的题目 | 本引擎调用其获取题目候选集，但决定取用顺序和节奏 |
| 学生认知负荷监测与学习内容难度动态调节引擎 | 监测实时认知负荷、调整单个内容难度 | 本引擎订阅其负荷信号作为节奏控制输入 |
| 学习规划与每日任务 | 生成日/周学习计划 | 本引擎接收当日任务作为会话目标，但负责任务内的内容编排 |
| 学习状态实时感知与会话质量动态评估引擎 | 感知学生状态（专注/走神/疲劳）| 本引擎消费状态信号进行节奏调整 |

## 2. 系统定位与边界

### 2.1 系统边界

```
┌─────────────────────────────────────────────────────────────────┐
│                    学习会话内容编排引擎                            │
│                                                                 │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
│  │ 目标解析  │→│ 内容选材  │→│ 节奏决策  │→│ 队列输出  │        │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘        │
│       ↑              ↑              ↑              │            │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐         │            │
│  │ 策略配置  │  │ 候选池    │  │ 信号采集  │         │            │
│  └──────────┘  └──────────┘  └──────────┘         │            │
│                                                   ↓            │
│                                            内容队列 + 节奏指令    │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 输入与输出

**输入：**

| 输入项 | 来源 | 说明 |
|--------|------|------|
| 会话学习目标 | 学习规划服务 | 本会话要完成的学习任务（如"复习二次函数+练习5道错题"）|
| 学生画像 | 用户学习画像服务 | 年级、能力维度、学习风格偏好、历史表现 |
| 内容候选池 | 题库/知识库/错题本 | 可选的题目、讲解、视频等素材 |
| 实时答题反馈 | 练习测评服务 | 每道题的对错、耗时、求助行为 |
| 认知负荷信号 | 认知负荷监测引擎 | 当前负荷指数（0-1连续值）|
| 学习状态信号 | 学习状态感知引擎 | 专注度、疲劳度、情绪倾向 |
| 会话时间预算 | 客户端传入 | 预计可用学习时间 |
| 历史会话模式 | 学习记录服务 | 该学生历史会话的节奏偏好和效果 |

**输出：**

| 输出项 | 消费方 | 说明 |
|--------|--------|------|
| 内容队列（ContentQueue）| 客户端练习/学习页面 | 有序的下一个内容项列表（预取3~5项）|
| 节奏指令（PaceDirective）| 客户端会话控制器 | 是否插入休息、是否切换学科、速度建议 |
| 编排理由（Explanation）| 客户端UI / 教师端 | 决策原因的可解释标签 |
| 会话报告数据 | 学情分析服务 | 会话级效果数据（覆盖度、挑战度、效率）|

## 3. 核心概念定义

### 3.1 内容项（ContentItem）

```typescript
interface ContentItem {
  contentId: string;              // 内容唯一标识
  contentType: ContentType;       // 内容类型
  knowledgePointIds: string[];    // 关联知识点
  difficulty: number;             // 难度 1-10（10最难）
  estimatedDurationSec: number;   // 预估耗时（秒）
  subject: Subject;               // 学科
  source: ContentSource;          // 来源
  metadata: Record<string, any>;  // 扩展元数据
}

enum ContentType {
  NEW_CONCEPT = 'new_concept',        // 新概念讲解
  EXAMPLE_PROBLEM = 'example_problem',// 例题精讲
  PRACTICE = 'practice',              // 练习题
  REVIEW = 'review',                  // 复习题
  ERROR_CORRECTION = 'error_correction', // 错题订正
  VIDEO_LESSON = 'video_lesson',      // 视频微课
  READING = 'reading',                // 阅读材料
  QUIZ = 'quiz',                      // 小测验
  BREAK = 'break',                    // 休息
  SUMMARY = 'summary',                // 知识总结
}

enum ContentSource {
  TEXTBOOK = 'textbook',      // 同步教材
  QUESTION_BANK = 'question_bank', // 题库
  ERROR_BOOK = 'error_book',  // 错题本
  AI_GENERATED = 'ai_generated', // AI生成
  CURATED = 'curated',        // 精选内容
}
```

### 3.2 编排策略（OrchestrationStrategy）

```typescript
interface OrchestrationStrategy {
  strategyId: string;
  strategyType: StrategyType;
  // 内容混合比例
  mixRatios: {
    newContent: number;     // 0-1，新内容占比
    review: number;         // 复习占比
    practice: number;       // 练习占比
    errorCorrection: number;// 错题占比
  };
  // 难度曲线
  difficultyCurve: DifficultyCurve;
  // 交错策略
  interleavingEnabled: boolean;
  interleavingInterval: number; // 每隔几个内容项切换主题
  // 节奏参数
  targetPace: 'relaxed' | 'standard' | 'intensive';
  maxConsecutiveErrors: number;   // 连续错误上限（触发降级）
  maxConsecutiveCorrects: number; // 连续正确上限（触发升级）
  restInterval: number;           // 每隔多少分钟建议休息
  sessionTimeBudgetMin: number;   // 时间预算（分钟）
}

enum StrategyType {
  EXAM_PREP = 'exam_prep',         // 考前冲刺
  DAILY_PRACTICE = 'daily_practice',// 日常练习
  ERROR_REVIEW = 'error_review',   // 错题复习
  NEW_LEARNING = 'new_learning',   // 新课学习
  MIXED_REVIEW = 'mixed_review',   // 混合复习
  WEAKNESS_TARGETED = 'weakness_targeted', // 薄弱点定向突破
}
```

### 4.2 组件职责

| 组件 | 职责 |
|------|------|
| **SessionOrchestrator** | 主控编排器，协调各子组件，管理编排周期 |
| **GoalResolver** | 解析会话学习目标，生成内容需求清单 |
| **StrategyResolver** | 根据目标+学生画像+历史模式，选择编排策略 |
| **ContentSelector** | 从候选池中按策略选材，排序生成内容队列 |
| **CandidatePool** | 聚合来自题库、知识库、错题本、复习引擎的内容候选 |
| **PaceController** | 基于实时信号评估节奏，生成节奏指令 |
| **SignalAggregator** | 聚合多源信号（答题、认知负荷、状态）为统一输入 |
| **ExplanationGenerator** | 为编排决策生成可解释理由标签 |

### 4.3 编排周期（Orchestration Cycle）

引擎以周期方式运行，每个周期完成一次完整的"感知→决策→输出"流程：

```
时间轴：  T0 ──── T1 ──── T2 ──── T3 ──── T4 ──── T5 ────
         │       │        │        │        │        │
事件：   会话    决策     答题     决策     答题     决策
         开始    #1      完成     #2      完成     #3
```

每个决策窗口（通常在学生完成一个内容项后触发，或定时 60 秒触发）：

1. **信号采集**（< 50ms）：获取最近的答题结果、耗时、认知负荷、学习状态
2. **节奏评估**（< 100ms）：评估当前节奏是否需要调整
3. **内容选材**（< 200ms）：从候选池选取下 3~5 个内容项
4. **队列更新**（< 50ms）：推送给客户端
5. **理由生成**（< 50ms）：附加决策理由

单次决策总耗时 < 500ms，用户无感知。

## 5. 数据模型设计

### 5.1 PostgreSQL 表结构

#### 5.1.1 `session_orchestration` — 会话编排记录

```sql
CREATE TABLE session_orchestration (
    id              BIGSERIAL PRIMARY KEY,
    session_id      VARCHAR(64)  NOT NULL,
    user_id         BIGINT       NOT NULL,
    strategy_type   VARCHAR(32)  NOT NULL,
    strategy_config JSONB        NOT NULL,
    goal_summary    TEXT,
    time_budget_min INT          NOT NULL,
    status          VARCHAR(16)  NOT NULL DEFAULT 'active',
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    ended_at        TIMESTAMPTZ
);

CREATE INDEX idx_session_orch_user   ON session_orchestration(user_id, created_at DESC);
CREATE INDEX idx_session_orch_status ON session_orchestration(status) WHERE status = 'active';

COMMENT ON TABLE session_orchestration IS '学习会话编排主记录';
```

```sql
CREATE TABLE session_orchestration_event (

CREATE INDEX idx_orch_event_session ON session_orchestration_event(session_id, event_seq);
```

### 6.1 策略选择算法

根据会话目标和学生画像，选择最优编排策略。

```python
def resolve_strategy(
    goal: SessionGoal,
    student_profile: StudentProfile,
    pace_profile: StudentPaceProfile,
    context: SessionContext
) -> OrchestrationStrategy:
    """
    策略选择入口。基于规则优先 + ML辅助。
    """
    # Step 1: 规则匹配 — 根据目标类型确定候选策略
    candidate_types = match_goal_to_strategies(goal)
    
    # Step 2: 按学生画像过滤
    candidate_types = filter_by_profile(candidate_types, student_profile)
    
    # Step 3: 加载策略模板
    templates = load_strategy_templates(candidate_types)
    
    # Step 4: 个性化参数调整
    strategy = personalize_strategy(
        template=select_best_template(templates, context),
        pace_profile=pace_profile,
        student_profile=student_profile,
        context=context
    )
    
    return strategy


def match_goal_to_strategies(goal: SessionGoal) -> list[str]:
    """规则映射：目标类型 → 候选策略"""
    mapping = {
        'exam_preparation': ['exam_prep', 'weakness_targeted', 'daily_practice'],
        'daily_homework': ['daily_practice', 'new_learning'],
        'error_review': ['error_review', 'weakness_targeted'],
        'new_chapter': ['new_learning'],
        'mixed_review': ['mixed_review', 'daily_practice'],
        'weakness_improvement': ['weakness_targeted', 'error_review'],
    }
    return mapping.get(goal.type, ['daily_practice'])


def personalize_strategy(
    template: StrategyTemplate,
    pace_profile: StudentPaceProfile,
    student_profile: StudentProfile,
    context: SessionContext
) -> OrchestrationStrategy:
    """基于学生画像个性化策略参数"""
    params = dict(template.default_params)
    
    # 根据节奏偏好调整
    if pace_profile.preferred_pace == 'relaxed':
        params['restInterval'] = min(params['restInterval'], 15)
        params['maxConsecutiveErrors'] = max(params['maxConsecutiveErrors'] - 1, 1)
    elif pace_profile.preferred_pace == 'intensive':
        params['restInterval'] = max(params['restInterval'], 30)
        params['maxConsecutiveCorrects'] = max(params['maxConsecutiveCorrects'] + 1, 3)
    
    # 根据时间预算调整内容混合
    time_budget = context.time_budget_min
    if time_budget < 15:
        # 短时会话：减少新内容，增加练习
        mix = adjust_mix_ratios(template.mix_ratios, new_content=-0.1, practice=+0.1)
    elif time_budget > 45:
        # 长时会话：增加新内容和复习
        mix = adjust_mix_ratios(template.mix_ratios, new_content=+0.1, review=+0.05)
    else:
        mix = template.mix_ratios
    
    # 根据学段调整难度曲线
    stage = student_profile.stage  # 'primary' | 'junior' | 'senior'
    curve = template.difficulty_curve
    if stage == 'primary':
        curve['peakDifficulty'] = min(curve['peakDifficulty'], 6)
    elif stage == 'senior':
        curve['startDifficulty'] = max(curve['startDifficulty'], 3)
    
    return OrchestrationStrategy(
        strategy_type=template.strategy_type,
        mix_ratios=mix,
        difficulty_curve=curve,
        **params
    )
```

### 6.2 内容选择算法

```python
def select_content(
    strategy: OrchestrationStrategy,
    candidate_pool: CandidatePool,
    signals: SessionSignals,
    session_state: SessionState,
    count: int = 5
) -> list[ContentItem]:
    """
    从候选池中选择内容并排序。
    核心思路：多目标加权评分 + 约束过滤 + 多样性保障。
    """
    candidates = candidate_pool.get_candidates(
        subjects=session_state.target_subjects,
        knowledge_points=session_state.target_kps,
        min_difficulty=max(1, session_state.current_difficulty - 2),
        max_difficulty=min(10, session_state.current_difficulty + 2),
        limit=100
    )
    
    scored = []
    for item in candidates:
        score = compute_content_score(item, strategy, signals, session_state)
        scored.append((item, score))
    
    scored.sort(key=lambda x: x[1], reverse=True)
    
    # 多样性保障：避免连续3个同知识点/同题型
    selected = apply_diversity_constraint(scored, count, session_state)
    
    # 确保内容类型混合比例符合策略
    selected = enforce_mix_ratios(selected, strategy.mix_ratios, count)
    
    # 插入休息项（如果需要）
    selected = maybe_insert_break(selected, strategy, signals, session_state)
    
    return selected


def compute_content_score(
    item: ContentItem,
    strategy: OrchestrationStrategy,
    signals: SessionSignals,
    state: SessionState
) -> float:
    """
    多维度加权评分（0-100）
    """
    weights = {
        'relevance': 0.25,      # 与当前学习目标的关联度
        'difficulty_fit': 0.20,  # 难度匹配度
        'spaced_repetition': 0.15, # 间隔重复紧迫度
        'novelty': 0.10,        # 新鲜度（是否近期做过）
        'weakness_alignment': 0.15, # 薄弱点对齐度
        'type_balance': 0.10,   # 内容类型平衡（缺少的类型加分）
        'subject_balance': 0.05, # 学科平衡
    }
    
    score = 0.0
    
    # 1. 关联度：目标知识点命中得分
    target_kps = set(state.target_kps)
    item_kps = set(item.knowledge_point_ids)
    overlap = len(target_kps & item_kps) / max(len(target_kps), 1)
    score += weights['relevance'] * overlap * 100
    
    # 2. 难度匹配：当前能力±1为最优
    target_difficulty = compute_target_difficulty(strategy, state, signals)
    diff_penalty = abs(item.difficulty - target_difficulty)
    difficulty_fit = max(0, 100 - diff_penalty * 25)
    score += weights['difficulty_fit'] * difficulty_fit
    
    # 3. 间隔重复紧迫度：越紧迫越高分
    if item.content_type in ['review', 'error_correction']:
        sr_score = compute_spaced_repetition_urgency(item, state.user_id)
    else:
        sr_score = 50  # 非复习内容给中等分
    score += weights['spaced_repetition'] * sr_score
    
    # 4. 新鲜度：近期做过的降分
    if item.content_id in state.recent_content_ids:
        novelty = 0  # 刚做过的不再推荐
    elif was_seen_today(item.content_id, state.user_id):
        novelty = 20
    else:
        novelty = 100
    score += weights['novelty'] * novelty
    
    # 5. 薄弱点对齐
    weakness_score = compute_weakness_alignment(item, state.weak_kps)
    score += weights['weakness_alignment'] * weakness_score
    
    # 6. 内容类型平衡
    type_count = state.content_type_counts
    total = sum(type_count.values()) or 1
    item_type_ratio = type_count.get(item.content_type, 0) / total
    type_balance = (1 - item_type_ratio) * 100
    score += weights['type_balance'] * type_balance
    
    # 7. 学科平衡
    subject_count = state.subject_counts
    total_s = sum(subject_count.values()) or 1
    item_subject_ratio = subject_count.get(item.subject, 0) / total_s
    subject_balance = (1 - item_subject_ratio) * 100
    score += weights['subject_balance'] * subject_balance
    
    return score


def compute_target_difficulty(
    strategy: OrchestrationStrategy,
    state: SessionState,
    signals: SessionSignals
) -> float:
    """
    动态计算当前最优难度。
    基于策略难度曲线 + 实时信号调整。
    """
    curve = strategy.difficulty_curve
    progress = state.items_completed / max(state.target_items, 10)
    
    # 基础难度：按策略曲线
    base = compute_curve_value(curve, progress)
    
    # 实时调整
    adjustment = 0
    if signals.consecutive_errors >= strategy.max_consecutive_errors:
        adjustment -= 2  # 连续错误：降难度
    elif signals.consecutive_corrects >= strategy.max_consecutive_corrects:
        adjustment += 1  # 连续正确：升难度
    
    if signals.cognitive_load > 0.8:
        adjustment -= 1  # 高认知负荷：降难度
    elif signals.cognitive_load < 0.3 and signals.accuracy > 0.8:
        adjustment += 1  # 低负荷高正确率：升难度
    
    # 学生节奏画像约束
    optimal = state.pace_profile.optimal_difficulty
    if optimal and abs(base + adjustment - optimal) > 3:
        # 拉回最优区间
        adjustment = int(optimal - base)
    
    return max(1, min(10, base + adjustment))
```

### 6.3 节奏控制算法

```python
def evaluate_pace(
    strategy: OrchestrationStrategy,
    signals: SessionSignals,
    state: SessionState
) -> PaceDirective:
    """
    节奏评估核心逻辑。
    输入实时信号，输出节奏指令。
    """
    rules = [
        # (条件, (PaceAction, PaceReasonCode), 优先级)
        # === 紧急干预规则（优先级 100+） ===
        (
            signals.consecutive_errors >= strategy.max_consecutive_errors + 2,
            (PaceAction.SLOW_DOWN, PaceReasonCode.CONSECUTIVE_ERRORS),
            110
        ),
        (
            signals.cognitive_load > 0.9 and signals.engagement < 0.2,
            (PaceAction.INSERT_BREAK, PaceReasonCode.HIGH_COGNITIVE_LOAD),
            105
        ),
        (
            signals.fatigue_level == 'high' and state.time_elapsed_min > 15,
            (PaceAction.INSERT_BREAK, PaceReasonCode.FATIGUE_DETECTED),
            103
        ),
        
        # === 加速规则（优先级 80-99） ===
        (
            signals.consecutive_corrects >= strategy.max_consecutive_corrects
            and signals.avg_response_fast,
            (PaceAction.SPEED_UP, PaceReasonCode.CONSECUTIVE_CORRECTS),
            90
        ),
        (
            signals.accuracy > 0.9 and signals.cognitive_load < 0.4
            and state.goal_completion_rate > 0.5,
            (PaceAction.SPEED_UP, PaceReasonCode.HIGH_ACCURACY),
            85
        ),
        
        # === 减速规则（优先级 70-89） ===
        (
            signals.accuracy < 0.4 and not signals.consecutive_errors >= strategy.max_consecutive_errors,
            (PaceAction.SLOW_DOWN, PaceReasonCode.LOW_ACCURACY),
            80
        ),
        (
            signals.avg_response_sec > signals.expected_response_sec * 2,
            (PaceAction.SLOW_DOWN, PaceReasonCode.SLOW_RESPONSE),
            75
        ),
        (
            signals.engagement < 0.3,
            (PaceAction.ENCOURAGE, PaceReasonCode.LOW_ENGAGEMENT),
            70
        ),
        
        # === 时间管理规则（优先级 60-69） ===
        (
            state.time_remaining_min < 5 and state.goal_completion_rate < 0.7,
            (PaceAction.END_SESSION, PaceReasonCode.GOAL_AT_RISK),
            65
        ),
        (
            state.goal_completion_rate >= 0.95,
            (PaceAction.END_SESSION, PaceReasonCode.GOAL_NEARLY_COMPLETE),
            63
        ),
        (
            state.time_elapsed_min >= strategy.rest_interval
            and not state.had_rest_recently,
            (PaceAction.INSERT_BREAK, PaceReasonCode.FATIGUE_DETECTED),
            60
        ),
        
        # === 学科切换规则（优先级 50-59） ===
        (
            state.consecutive_same_subject >= strategy.subject_switch_tolerance,
            (PaceAction.SWITCH_SUBJECT, PaceReasonCode.SESSION_QUALITY_LOW),
            55
        ),
    ]
    
    # 按优先级排序，取第一个匹配的规则
    rules.sort(key=lambda r: r[2], reverse=True)
    for condition, (action, reason_code), _ in rules:
        if condition:
            return PaceDirective(
                action=action,
                reason=generate_reason_text(reason_code, signals, state),
                reason_code=reason_code,
                data=build_pace_data(action, signals, state)
            )
    
    # 默认：继续当前节奏
    return PaceDirective(
        action=PaceAction.CONTINUE,
        reason='当前学习节奏良好，继续保持',
        reason_code=PaceReasonCode.SESSION_QUALITY_HIGH
    )
```

### 6.4 多样性保障算法

```python
def apply_diversity_constraint(
    scored_items: list[tuple[ContentItem, float]],
    count: int,
    state: SessionState
) -> list[ContentItem]:
    """
    贪心+回溯：确保不连续出现3个同知识点或同题型。
    """
    selected = []
    used_kp_streak = {}  # knowledge_point_id -> 连续计数
    used_type_streak = {} # content_type -> 连续计数
    
    remaining = list(scored_items)
    
    while len(selected) < count and remaining:
        chosen = None
        for i, (item, score) in enumerate(remaining):
            # 检查知识点连续约束
            kp_violation = any(
                used_kp_streak.get(kp, 0) >= 2
                for kp in item.knowledge_point_ids
            )
            # 检查题型连续约束
            type_violation = used_type_streak.get(item.content_type, 0) >= 2
            
            if not kp_violation and not type_violation:
                chosen = (i, item)
                break
        
        if chosen is None:
            # 所有候选都违反约束，取最高分
            chosen = (0, remaining[0][0])
        
        i, item = chosen
        remaining.pop(i)
        selected.append(item)
        
        # 更新连续计数
        for kp in item.knowledge_point_ids:
            used_kp_streak[kp] = used_kp_streak.get(kp, 0) + 1
        # 非当前item的kp计数归零
        for kp in list(used_kp_streak.keys()):
            if kp not in item.knowledge_point_ids:
                used_kp_streak[kp] = 0
        
        used_type_streak[item.content_type] = used_type_streak.get(item.content_type, 0) + 1
        for ct in list(used_type_streak.keys()):
            if ct != item.content_type:
                used_type_streak[ct] = 0
    
    return selected
```

### 6.5 难度曲线模型

```python
def compute_curve_value(curve: dict, progress: float) -> int:
    """
    根据进度（0-1）和曲线类型计算目标难度。
    """
    curve_type = curve['type']
    start = curve['startDifficulty']
    peak = curve['peakDifficulty']
    
    if curve_type == 'gradual_rise':
        # 渐升型：前60%逐步上升到峰值，后40%维持在峰值
        position = curve.get('position', 0.6)
        if progress <= position:
            ratio = progress / position
            return round(start + (peak - start) * ratio)
        else:
            return peak
    
    elif curve_type == 'high_plateau':
        # 高原型：快速上升到峰值，大部分时间维持在高位
        position = curve.get('position', 0.3)
        if progress <= position:
            ratio = progress / position
            return round(start + (peak - start) * ratio)
        else:
            return peak
    
    elif curve_type == 'step':
        # 阶梯型：分段上升
        position = curve.get('position', 0.4)
        if progress < position:
            return start
        elif progress < position + 0.3:
            return round(start + (peak - start) * 0.5)
        else:
            return peak
    
    elif curve_type == 'adaptive':
        # 自适应型：完全由实时信号决定
        # 此处返回中值，由 compute_target_difficulty 的调整逻辑处理
        return round((start + peak) / 2)
    
    else:
        return round((start + peak) / 2)
```

## 9. 节奏控制策略

### 9.1 交错练习（Interleaving）策略

交错练习是学习科学中证据最强的策略之一——不同主题/题型交替出现，比集中练习（Blocking）更能促进长期保持。

```python
def compute_interleaving_plan(
    target_subjects: list[str],
    target_kps: list[str],
    session_length: int,
    switch_interval: int = 3
) -> list[dict]:
    """
    生成交错练习计划。
    
    switch_interval=3 表示每3个内容项切换一次主题。
    例如：数学A → 数学A → 数学A → 物理B → 物理B → 物理B → 数学A → ...
    """
    plan = []
    blocks = session_length // switch_interval
    remainder = session_length % switch_interval
    
    # 轮转主题
    subjects = cycle(target_subjects)
    kp_groups = group_kps_by_subject(target_kps)
    
    for block_idx in range(blocks):
        current_subject = next(subjects)
        kps = kp_groups.get(current_subject, [])
        for i in range(switch_interval):
            plan.append({
                'subject': current_subject,
                'kpGroup': kps,
                'position': block_idx * switch_interval + i + 1,
                'blockIndex': block_idx
            })
    
    # 处理余数
    if remainder:
        current_subject = next(subjects)
        for i in range(remainder):
            plan.append({
                'subject': current_subject,
                'kpGroup': kp_groups.get(current_subject, []),
                'position': blocks * switch_interval + i + 1,
                'blockIndex': blocks
            })
    
    return plan
```

**交错与集中练习的自动切换：**

| 条件 | 策略 |
|------|------|
| 会话开始前 5 个内容项 | 集中练习（Blocking），建立基线 |
| 正常学习阶段 | 交错练习（Interleaving），间隔 3~4 项 |
| 错误恢复阶段 | 集中练习，同知识点连练至正确率恢复 |
| 考前冲刺 | 密集交错（间隔 2 项），模拟考试混合题型 |

### 9.2 休息策略

```python
def should_insert_break(
    strategy: OrchestrationStrategy,
    signals: SessionSignals,
    state: SessionState
) -> tuple[bool, int]:
    """
    判断是否需要休息，返回（是否休息, 休息秒数）。
    """
    # 规则1：定时休息
    elapsed_since_rest = state.time_elapsed_min - state.last_rest_min
    if elapsed_since_rest >= strategy.rest_interval:
        return True, 60  # 1分钟短休息
    
    # 规则2：高认知负荷
    if signals.cognitive_load > 0.85 and state.items_completed >= 5:
        return True, 90  # 1.5分钟休息
    
    # 规则3：疲劳信号
    if signals.fatigue_level == 'high' and state.time_elapsed_min >= 15:
        return True, 120  # 2分钟休息
    
    # 规则4：连续错误后的情绪休息
    if signals.consecutive_errors >= 3:
        return True, 45  # 45秒短休息（深呼吸/鼓励）
    
    return False, 0
```

**休息内容设计：**

| 休息类型 | 时长 | 内容 |
|---------|------|------|
| 眼睛休息 | 30~60s | 护眼提示动画 + 远眺建议 |
| 认知休息 | 60~90s | 简单趣味知识/脑筋急转弯 |
| 情绪恢复 | 45~60s | 鼓励语 + 成长心态信息 |
| 体力活动 | 60~120s | 站起来活动建议 + 简单拉伸动画 |

### 9.3 鼓励互动策略

```python
def should_encourage(
    signals: SessionSignals,
    state: SessionState
) -> tuple[bool, str]:
    """
    判断是否需要鼓励互动。
    """
    # 高投入 + 高正确率：庆祝性鼓励
    if signals.accuracy > 0.8 and signals.engagement > 0.7:
        if state.items_completed % 5 == 0:
            return True, 'celebration'
    
    # 低投入：动机性鼓励
    if signals.engagement < 0.3:
        return True, 'motivation'
    
    # 错误后：成长心态鼓励
    if signals.consecutive_errors >= 2:
        return True, 'growth_mindset'
    
    # 长时间会话：耐力鼓励
    if state.time_elapsed_min > 30 and state.items_completed % 10 == 0:
        return True, 'endurance'
    
    return False, ''
```

## 11. 关键代码示例

### 11.1 服务端编排核心实现（Java/Spring Boot）

```java
@Service
@Slf4j
public class SessionOrchestrator {

    @Autowired private StrategyResolver strategyResolver;
    @Autowired private ContentSelector contentSelector;
    @Autowired private PaceController paceController;
    @Autowired private SignalAggregator signalAggregator;
    @Autowired private ExplanationGenerator explanationGenerator;
    @Autowired private SessionStateRepository stateRepo;
    @Autowired private OrchestrationEventLogger eventLogger;
    @Autowired private RedissonClient redisson;

    /**
     * 创建会话编排
     */
    public OrchestrationSession createSession(CreateSessionRequest req) {
        // 1. 解析策略
        OrchestrationStrategy strategy = strategyResolver.resolve(
            req.getGoalType(), req.getUserId(), req.getTimeBudgetMin()
        );

        // 2. 初始化会话状态
        SessionState state = SessionState.builder()
            .sessionId(req.getSessionId())
            .userId(req.getUserId())
            .strategy(strategy)
            .status(SessionStatus.LEARNING)
            .itemsCompleted(0)
            .consecutiveCorrects(0)
            .consecutiveErrors(0)
            .currentDifficulty(strategy.getDifficultyCurve().getStartDifficulty())
            .timeElapsedSec(0)
            .timeBudgetSec(req.getTimeBudgetMin() * 60)
            .recentContentIds(new LinkedHashSet<>(50))
            .build();
        stateRepo.save(state);

        // 3. 选取初始内容队列
        List<ContentItem> initialQueue = contentSelector.select(
            strategy, state, CandidatePool.empty(), 5
        );

        // 4. 生成初始节奏指令
        PaceDirective initialPace = PaceDirective.continue_(
            "会话开始，保持标准节奏"
        );

        // 5. 持久化
        OrchestrationSession session = OrchestrationSession.builder()
            .id(IdGenerator.next())
            .sessionId(req.getSessionId())
            .userId(req.getUserId())
            .strategyType(strategy.getType())
            .strategyConfig(JsonUtils.toJson(strategy))
            .timeBudgetMin(req.getTimeBudgetMin())
            .status("active")
            .build();
        sessionMapper.insert(session);

        eventLogger.log(req.getSessionId(), OrchestrationEvent.Type.SESSION_START, null, initialQueue);

        return OrchestrationSession.builder()
            .session(session)
            .strategy(strategy)
            .initialQueue(initialQueue)
            .paceDirective(initialPace)
            .build();
    }

    /**
     * 处理内容完成，返回下一批内容
     */
    @Transactional
    public NextResponse handleItemCompletion(
        String sessionId, ItemCompletion completion, ClientSignals clientSignals
    ) {
        // 1. 获取分布式锁（防并发）
        RLock lock = redisson.getLock("session:orch:" + sessionId + ":lock");
        boolean locked = lock.tryLock(3, TimeUnit.SECONDS);
        if (!locked) {
            // 降级：返回空队列，让客户端稍后重试
            return NextResponse.retry(1000);
        }

        try {
            // 2. 更新会话状态
            SessionState state = stateRepo.findBySessionId(sessionId);
            updateStateAfterCompletion(state, completion);

            // 3. 聚合信号
            SessionSignals signals = signalAggregator.aggregate(
                state, completion, clientSignals
            );

            // 4. 节奏评估
            PaceDirective pace = paceController.evaluate(
                state.getStrategy(), signals, state
            );

            // 5. 应用节奏指令
            applyPaceDirective(state, pace);

            // 6. 选取下一批内容
            CandidatePool candidates = fetchCandidates(state);
            List<ContentItem> queue = contentSelector.select(
                state.getStrategy(), state, candidates, 5
            );

            // 7. 生成可解释理由
            String explanation = explanationGenerator.generate(pace, signals, state);

            // 8. 持久化事件
            eventLogger.log(sessionId, OrchestrationEvent.Type.ITEM_COMPLETED,
                completion, queue, pace, signals, explanation);

            // 9. 更新状态
            stateRepo.save(state);

            return NextResponse.builder()
                .paceDirective(pace)
                .contentQueue(queue)
                .sessionProgress(buildProgress(state))
                .encouragement(maybeEncourage(signals, state))
                .build();

        } finally {
            lock.unlock();
        }
    }

    private void updateStateAfterCompletion(SessionState state, ItemCompletion completion) {
        state.setItemsCompleted(state.getItemsCompleted() + 1);
        state.getRecentContentIds().add(completion.getContentId());

        // 更新连续正确/错误计数
        if (completion.getResult().isCorrect()) {
            state.setConsecutiveCorrects(state.getConsecutiveCorrects() + 1);
            state.setConsecutiveErrors(0);
        } else {
            state.setConsecutiveErrors(state.getConsecutiveErrors() + 1);
            state.setConsecutiveCorrects(0);
        }

        // 累计时间
        state.setTimeElapsedSec(state.getTimeElapsedSec() + completion.getResult().getDurationSec());

        // 更新难度
        int newDifficulty = Math.max(1, Math.min(10,
            state.getCurrentDifficulty()
            + (completion.getResult().isCorrect() ? 0 : -1)
            + (state.getConsecutiveCorrects() >= 3 ? 1 : 0)
        ));
        state.setCurrentDifficulty(newDifficulty);
    }

    private void applyPaceDirective(SessionState state, PaceDirective pace) {
        switch (pace.getAction()) {
            case SLOW_DOWN:
                state.setCurrentDifficulty(
                    Math.max(1, state.getCurrentDifficulty() - 1)
                );
                state.setHintPolicy("proactive");
                break;
            case SPEED_UP:
                state.setCurrentDifficulty(
                    Math.min(10, state.getCurrentDifficulty() + 1)
                );
                state.setHintPolicy("minimal");
                break;
            case INSERT_BREAK:
                state.setLastRestMin(state.getTimeElapsedSec() / 60);
                state.setRestCount(state.getRestCount() + 1);
                break;
            case END_SESSION:
                state.setStatus(SessionStatus.COMPLETED);
                break;
            default:
                // CONTINUE / ENCOURAGE: 无状态变更
        }
    }
}
```

```java
@Service
public class CandidatePoolAggregator {

    @Autowired private QuestionServiceClient questionClient;
    @Autowired private ErrorBookServiceClient errorBookClient;
    @Autowired private SpacedRepetitionClient srClient;
    @Autowired private KnowledgeContentClient knowledgeClient;

    @Async("orchestrationExecutor")
    public CompletableFuture<CandidatePool> aggregateAsync(
        SessionState state, OrchestrationStrategy strategy
    ) {
        int targetCount = 50; // 每类取50个候选

        // 并行获取各来源候选
        CompletableFuture<List<ContentItem>> questions = CompletableFuture.supplyAsync(() ->
            questionClient.search(QuestionSearchRequest.builder()
                .subject(state.getCurrentSubject())
                .knowledgePointIds(state.getTargetKps())
                .difficultyRange(
                    Math.max(1, state.getCurrentDifficulty() - 2),
                    Math.min(10, state.getCurrentDifficulty() + 2)
                )
                .excludeIds(state.getRecentContentIds())
                .limit(targetCount)
                .build()
            ).stream().map(this::toContentItem).toList()
        );

        CompletableFuture<List<ContentItem>> errorItems = CompletableFuture.supplyAsync(() ->
            errorBookClient.getDueItems(state.getUserId(), state.getCurrentSubject(), targetCount)
                .stream().map(this::toContentItem).toList()
        );

        CompletableFuture<List<ContentItem>> reviewItems = CompletableFuture.supplyAsync(() ->
            srClient.getDueReviews(state.getUserId(), state.getCurrentSubject(), targetCount)
                .stream().map(this::toContentItem).toList()
        );

        CompletableFuture<List<ContentItem>> knowledgeItems = CompletableFuture.supplyAsync(() ->
            knowledgeClient.getByKnowledgePoints(state.getTargetKps(), targetCount)
                .stream().map(this::toContentItem).toList()
        );

        // 合并
        return CompletableFuture.allOf(questions, errorItems, reviewItems, knowledgeItems)
            .thenApply(v -> CandidatePool.builder()
                .questions(questions.join())
                .errorItems(errorItems.join())
                .reviewItems(reviewItems.join())
                .knowledgeItems(knowledgeItems.join())
                .build()
            );
    }
}
```

```dart
      sessionId: _session.sessionId,

        contentType: completed.contentType,
        result: result,
      ),
      clientSignals: clientSignals,
    );

    for (final item in response.contentQueue) {
      if (!_queue.any((e) => e.contentId == item.contentId)) {
        _queue.add(item);
      }
    }
```

## 12. 错误处理与降级策略

### 12.1 错误分类与处理

| 错误场景 | 影响 | 处理策略 | 降级方案 |
|---------|------|---------|---------|
| 候选池获取失败（题库/错题本不可用）| 无法选取新内容 | 重试3次，间隔 200ms | 使用缓存队列或提前结束会话 |
| 认知负荷信号缺失 | 节奏决策缺少输入 | 使用历史均值替代 | 降级为定时节奏控制 |
| Redis 不可用 | 无法读写会话状态 | 尝试本地缓存 | 降级为无状态编排（每次重新计算）|
| 并发锁获取失败 | 决策冲突 | 等待 500ms 重试1次 | 返回当前队列（不更新）|
| 策略模板未找到 | 无法编排 | 使用默认 `daily_practice` 策略 | — |
| 学生画像缺失 | 个性化不足 | 使用学段默认画像 | — |

### 12.2 降级编排流程

当关键依赖不可用时，按以下顺序降级：

```
Level 0: 全功能编排（所有信号可用）
    ↓ 认知负荷/学习状态信号缺失
Level 1: 基于答题信号的简化编排（正确率+耗时）
    ↓ 候选池部分不可用
Level 2: 受限编排（仅使用可用来源的内容）
    ↓ 题库完全不可用
Level 3: 错题/复习专用模式（仅使用错题本和间隔重复）
    ↓ 所有外部依赖不可用
Level 4: 基础模式（客户端本地缓存内容 + 固定节奏）
```

```java
public ResponseEntity<NextResponse> handleEmptyPool(
    CandidatePoolEmptyException e, String sessionId
) {
    log.warn("Candidate pool empty for session={}, reason={}", sessionId, e.getMessage());
    
    // 降级：从通用题库获取基础题目

    );

        return ok(NextResponse.builder()
            .paceDirective(PaceDirective.endSession("暂无可用学习内容，请稍后重试"))
            .contentQueue(Collections.emptyList())
            .build());
    }
    
    return ok(NextResponse.builder()
        .paceDirective(PaceDirective.continue_("使用基础题库继续练习"))
        .contentQueue(fallback)
        .degraded(true)
        .build());
}
```

## 14. 性能与容量规划

### 14.1 性能目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 编排决策 P50 延迟 | < 300ms | 中位数用户感知 |
| 编排决策 P95 延迟 | < 800ms | 95% 用户感知 |
| 编排决策 P99 延迟 | < 1500ms | 极端情况 |
| 并发会话编排 | 5000 ops | 同时活跃编排会话 |
| 候选池获取 | < 500ms (并行) | 4个来源并行获取 |
| 会话状态读写 | < 20ms | Redis Hash 操作 |

### 14.2 容量估算

```
假设：
- 日活用户 100万
- 同时在线 10万
- 同时学习会话 2万（20% 在线用户正在学习）
- 平均会话时长 30 分钟
- 平均编排决策频率：每 2 分钟 1 次

并发编排 QPS = 20000 / 120 ≈ 170 QPS
峰值编排 QPS = 170 * 3 = 510 QPS（晚高峰倍数）

单实例处理能力：约 200 QPS（CPU密集型决策）
建议实例数：3 个（含冗余）

内存需求：
- 每个活跃会话状态 ~2KB（Redis Hash）
- 每个队列缓存 ~5KB（List of JSON）
- 2万并发会话 * 7KB = 140MB Redis
- 预留 2x = 300MB Redis 专用
```

### 14.3 数据库存储估算

```
每次编排事件约 2KB（trigger_data + decision_data）
每个会话约 15~30 次决策
每日会话数约 50万

日新增数据 = 500000 * 20 * 2KB ≈ 20GB
月新增数据 ≈ 600GB

建议：
- session_orchestration_event 表按月分区
- 超 3 个月的数据归档到对象存储（Parquet 格式）
- session_orchestration_summary 保留 2 年
```
