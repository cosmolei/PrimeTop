# 服务端-用户学习激励中心与行为奖励统一规则引擎 详细设计

> 模块代号：`incentive-hub`
> 所属域：用户增长与留存域
> 关联模块：积分系统、成就系统、打卡系统、运营活动系统、消息通知系统

---

## 1. 模块概述

### 1.1 设计目标

构建一个**统一的、可配置的行为激励规则引擎**，作为全站 Gamification 的中枢神经。该引擎监听用户学习行为事件（答题正确、每日登录、完成任务、连续打卡等），实时评估激励规则，自动触发奖励动作（发放积分、解锁徽章、播放庆祝动画、推送通知等）。

### 1.2 为什么需要这个引擎

当前系统已有多个独立的激励子系统：

| 现有模块 | 职责 | 局限 |
|----------|------|------|
| 积分获取规则计算与虚拟资产交易结算服务 | 积分发放与消费 | 仅管积分数值，不关心触发时机 |
| 学习打卡记录与成就解锁计算引擎 | 打卡记录与成就解锁 | 仅管打卡和勋章，不处理其他行为奖励 |
| 运营活动与成长激励体系 | 运营层面激励策略 | 偏运营配置，不处理实时事件流 |

**缺失的部分**：没有一个统一的规则引擎来：
- 监听**所有**用户行为事件
- 按**可配置规则**判断是否命中激励条件
- 统一调度奖励发放（积分、勋章、动画、弹窗、通知）
- 处理规则优先级、互斥、冷却
- 支持运营人员动态配置规则，无需发版

### 1.3 核心能力

1. **事件订阅**：通过消息队列订阅用户行为事件流
2. **规则评估**：基于 CEL/JSON 表达式引擎实时匹配规则
3. **奖励编排**：支持多种奖励类型的组合发放与优先级控制
4. **防刷冷却**：同一规则对同一用户的触发频率控制
5. **规则管理 API**：运营后台 CRUD 管理激励规则
6. **效果追踪**：规则命中日志与 A/B 实验对接

### 2.2 模块职责边界

| 职责 | 说明 |
|------|------|
| **本引擎负责** | 事件监听、规则匹配、奖励编排与分发、冷却控制、规则配置管理 |
| **本引擎不负责** | 积分余额管理（积分服务负责）、勋章存储（成就服务负责）、推送通道管理（通知服务负责） |

### 2.3 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 消息队列 | Kafka | 高吞吐、有序消费、事件回溯 |
| 规则表达式引擎 | CEL (Common Expression Language) | Google 开源，Go/Java 友好，沙箱安全 |
| 缓存 | Redis 7.x (Lua脚本) | 原子操作保障冷却与计数 |
| 规则存储 | PostgreSQL | 事务一致性、JSONB 支持灵活配置 |
| 规则版本管理 | PostgreSQL schema_migrations | 版本快照 + 审计 |
| 任务调度 | 延迟队列 (Redis ZSET) | 延迟奖励、定时触发 |

## 3. 数据结构设计

### 3.1 PostgreSQL 表结构

#### 3.1.1 激励规则定义表 `incentive_rules`

```sql
CREATE TABLE incentive_rules (
    id              BIGSERIAL PRIMARY KEY,
    rule_code       VARCHAR(64) NOT NULL UNIQUE,       -- 规则唯一编码：DAILY_LOGIN_BONUS
    rule_name       VARCHAR(128) NOT NULL,              -- 规则名称：每日登录奖励
    rule_group      VARCHAR(64) NOT NULL DEFAULT 'DEFAULT', -- 规则分组：DEFAULT / EXAM_PREP / SUMMER_CAMP
    description     TEXT,
    status          VARCHAR(16) NOT NULL DEFAULT 'DRAFT', -- DRAFT / ACTIVE / PAUSED / ARCHIVED
    
    -- 触发条件
    trigger_event   VARCHAR(64) NOT NULL,               -- 触发事件类型（见 3.2 事件类型枚举）
    condition_expr  TEXT NOT NULL,                       -- CEL 条件表达式
    
    -- 奖励定义（JSON 数组，支持多奖励）
    rewards         JSONB NOT NULL DEFAULT '[]'::jsonb,
    
    -- 限制条件
    cooldown_seconds BIGINT NOT NULL DEFAULT 0,          -- 冷却时间（秒），0=无限制
    max_triggers_per_user INT NOT NULL DEFAULT 0,        -- 每用户最大触发次数，0=无限
    max_triggers_per_day  INT NOT NULL DEFAULT 0,        -- 每用户每日最大触发次数，0=无限
    priority        INT NOT NULL DEFAULT 100,            -- 优先级（越小越高）
    mutex_group     VARCHAR(64),                         -- 互斥组：同组只触发优先级最高的一条
    
    -- 生效范围
    target_user_segment VARCHAR(64),                     -- 目标用户分群：ALL / FREE / VIP / NEW_USER
    target_grade_range  VARCHAR(32),                     -- 目标年级范围：1-6;7-9;10-12;ALL
    start_at        TIMESTAMPTZ,                         -- 生效开始时间
    end_at          TIMESTAMPTZ,                         -- 生效结束时间
    
    -- A/B 实验
    experiment_id   VARCHAR(64),                         -- 关联实验 ID
    experiment_variant VARCHAR(32),                      -- 实验变体：CONTROL / TREATMENT_A
    
    -- 元数据
    version         INT NOT NULL DEFAULT 1,
    created_by      BIGINT NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_rules_status_event ON incentive_rules(status, trigger_event) 
    WHERE status = 'ACTIVE';
CREATE INDEX idx_rules_group ON incentive_rules(rule_group, status);
CREATE INDEX idx_rules_mutex ON incentive_rules(mutex_group, priority) 
    WHERE status = 'ACTIVE';
```

#### 3.1.2 规则触发日志表 `incentive_rule_logs`

```sql
CREATE TABLE incentive_rule_logs (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL,
    rule_id         BIGINT NOT NULL,
    rule_code       VARCHAR(64) NOT NULL,
    rule_version    INT NOT NULL,
    
    trigger_event_id   VARCHAR(128) NOT NULL,            -- 原始事件 ID（幂等去重）
    trigger_event_type VARCHAR(64) NOT NULL,
    trigger_payload JSONB,                                -- 触发时的完整事件载荷
    
    rewards_executed JSONB NOT NULL DEFAULT '[]'::jsonb,  -- 实际执行的奖励列表
    execution_status VARCHAR(16) NOT NULL DEFAULT 'SUCCESS', -- SUCCESS / PARTIAL / FAILED / SKIPPED
    error_message   TEXT,
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_logs_user_time ON incentive_rule_logs(user_id, created_at DESC);
CREATE INDEX idx_logs_rule_time ON incentive_rule_logs(rule_id, created_at DESC);
CREATE UNIQUE INDEX idx_logs_event_unique ON incentive_rule_logs(trigger_event_id, rule_id);
```

#### 3.1.3 用户激励状态表 `user_incentive_states`

```sql
CREATE TABLE user_incentive_states (
    user_id         BIGINT PRIMARY KEY,
    
    total_trigger_count INT NOT NULL DEFAULT 0,          -- 累计触发总次数
    daily_trigger_count INT NOT NULL DEFAULT 0,          -- 今日触发次数
    daily_reset_date     DATE NOT NULL DEFAULT CURRENT_DATE,
    
    last_trigger_at  TIMESTAMPTZ,                        -- 最近一次触发时间
    last_rule_code   VARCHAR(64),                         -- 最近触发的规则
    
    streak_days      INT NOT NULL DEFAULT 0,             -- 连续激励天数
    streak_last_date DATE,                                -- 最近激励日期
    
    -- 各类型累计统计（用于成就/里程碑判断）
    total_points_earned    BIGINT NOT NULL DEFAULT 0,
    total_badges_earned    INT NOT NULL DEFAULT 0,
    total_celebrations_shown INT NOT NULL DEFAULT 0,
    
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

#### 3.1.4 用户-规则触发计数表 `user_rule_counters`

```sql
CREATE TABLE user_rule_counters (
    user_id         BIGINT NOT NULL,
    rule_id         BIGINT NOT NULL,
    trigger_count   INT NOT NULL DEFAULT 0,
    last_trigger_at TIMESTAMPTZ,
    last_event_id   VARCHAR(128),                        -- 最近事件 ID（幂等）
    
    PRIMARY KEY (user_id, rule_id)
);
```

```json

  "ruleCode": "DAILY_LOGIN_POINTS",
```
