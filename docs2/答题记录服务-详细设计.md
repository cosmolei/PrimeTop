# 答题记录服务 详细设计

## 1. 概述

### 1.1 模块定位
答题记录服务（AnswerRecord Service）是 PrimeTop 平台的核心数据服务，负责统一管理用户作答行为的全生命周期数据。它是连接前端答题交互、题目服务、评分服务、学情分析服务和错题服务的枢纽。

### 1.2 核心职责
- **记录管理**：创建、更新、查询、归档用户答题记录。
- **数据关联**：建立答题记录与用户、题目、学习会话、知识点之间的映射关系。
- **状态流转**：管理答题记录从创建到归档的状态变迁，确保数据一致性。
- **事件触发**：在答题状态变更时，触发下游服务（如知识点掌握度更新、错题生成、学情分析）。
- **性能保障**：针对高频读写场景进行性能优化，支持大并发下的数据吞吐。

### 1.3 依赖关系
- **上游依赖**：
  - 用户服务：获取用户基本信息、年级、学段。
  - 题目服务：获取题目详情、标准答案、评分规则。
  - 学习会话服务：关联学习会话ID，追踪学习上下文。
  - 评分服务：调用评分逻辑，获取判断结果、分数、解析。
- **下游依赖**：
  - 错题服务：在答题错误时触发错题记录创建。
  - 知识点掌握度服务：基于答题结果更新知识点掌握度。
  - 学情分析服务：消费答题数据，生成分析报告。
  - 消息服务：发送答题完成提醒、成就解锁通知。

### 2.3 存储策略
- **热数据**：最近6个月的答题记录存储在主库，支持高频查询和更新。
- **温数据**：6个月至2年的答题记录可迁移至只读从库或归档库，查询速度稍慢但存储成本更低。
- **冷数据**：超过2年的答题记录可导出至对象存储（如OSS/S3）进行冷备，仅保留聚合统计数据。
- **归档策略**：采用定时任务或事件触发的方式进行数据迁移，迁移前需确保下游服务（如学情分析）已完成相关数据消费。

### 2.4 缓存策略
- **缓存目标**：缓存用户近期的答题记录，减少数据库查询压力，加速学情报告、错题列表等页面的加载。
- **缓存介质**：Redis。
- **缓存键设计**：
  - 单条记录：`answer_record:{recordId}`
  - 用户最近N条记录列表（分页）：`user_answer_records:{userId}:{page}:{pageSize}:{filterHash}`
  - 用户统计（今日/本周/本月答题数）：`user_answer_stats:{userId}:{period}`
- **缓存过期策略**：
  - 单条记录：TTL = 1小时
  - 列表缓存：TTL = 30分钟
  - 统计缓存：TTL = 5分钟
- **缓存更新策略**：
  - 写穿透：答题记录创建或更新时，同步更新缓存。
  - 缓存失效：答题记录删除或状态变更时，主动使相关缓存失效。

## 4. 业务逻辑

### 4.1 核心流程：创建答题记录并评分

1. **接收请求**：接口层接收用户提交的答题请求，校验必填参数和用户权限。
2. **创建记录**：服务层生成答题记录ID，设置初始状态为`DRAFT`，将基础信息写入数据库。
3. **触发评分**：服务层调用评分服务（同步或异步），传入用户答案、题目ID和题目元数据。
4. **更新记录**：收到评分结果后，更新答题记录的`isCorrect`、`score`、`feedback`、`knowledgePoints`等字段，并将状态更新为`COMPLETED`，同时记录`gradedAt`时间。
5. **触发下游**：
    - 若`isCorrect`为`false`，调用错题服务，创建或更新错题记录。
    - 调用知识点掌握度服务，传入答题结果和知识点列表，更新掌握度。
    - 发送答题完成事件到消息队列（如Kafka），供学情分析等服务消费。
6. **返回响应**：将更新后的答题记录返回给调用方。

### 4.2 状态机

答题记录的状态流转如下：

```
[DRAFT] --(提交评分)--> [GRADING] --(评分完成)--> [COMPLETED] --(归档任务)--> [ARCHIVED]
    ^                                                     |
    |                                                     |
    -----------------------------(失败/取消)--------------|
```

- **DRAFT (草稿)**：初始状态，已保存基础信息，尚未进入评分流程。
- **GRADING (评分中)**：已发送评分请求，等待评分结果返回。
- **COMPLETED (已完成)**：评分完成，结果已回填。
- **ARCHIVED (已归档)**：数据已迁移至归档存储，不可再修改。

**状态变更约束：**
- 从`DRAFT`只能变更为`GRADING`或`ARCHIVED`（如超时未评分）。
- 从`GRADING`只能变更为`COMPLETED`（成功）或`DRAFT`（失败重试）。
- 从`COMPLETED`只能变更为`ARCHIVED`。
- `ARCHIVED`为最终状态，不可变更。

### 4.3 关键算法

#### 4.3.1 答案相似度计算（用于主观题部分匹配）
```python
def calculate_similarity(user_answer, standard_answer):
    """
    使用预训练的文本嵌入模型（如Sentence-BERT）计算用户答案与标准答案的语义相似度。
    相似度分数范围[0, 1]。
    """
    user_embedding = embedding_model.encode(user_answer)
    standard_embedding = embedding_model.encode(standard_answer)
    similarity = cosine_similarity(user_embedding, standard_embedding)
    return similarity
```

#### 4.3.2 评分规则匹配
- 根据题目类型（单选、多选、填空、主观题等）匹配对应的评分规则处理器。
- 对于客观题，进行精确匹配或模糊匹配。
- 对于主观题，结合相似度算法和关键词匹配进行评分。

## 5. 代码示例

### 5.1 核心类定义（伪代码）

```typescript
// 答题记录实体类
class AnswerRecord {
    id: string;
    userId: string;
    questionId: string;
    sessionId: string | null;
    answerContent: Record<string, any>;
    isCorrect: boolean | null;
    score: number | null;
    feedback: string | null;
    knowledgePoints: string[];
    durationSeconds: number;
    submittedAt: Date;
    gradedAt: Date | null;
    status: RecordStatus;
    source: RecordSource;
    createdAt: Date;
    updatedAt: Date;
}

enum RecordStatus {
    DRAFT = 'DRAFT',
    GRADING = 'GRADING',
    COMPLETED = 'COMPLETED',
    ARCHIVED = 'ARCHIVED'
}

enum RecordSource {
    PRACTICE = 'PRACTICE',
    EXAM = 'EXAM',
    HOMEWORK = 'HOMEWORK',
    QUIZ = 'QUIZ'
}

// 答题记录服务类
class AnswerRecordService {
    private db: Database;
    private cache: CacheClient;
    private gradingService: GradingService;
    private messageQueue: MessageQueue;

    /**
     * 创建答题记录并触发评分
     */
    async createAndGrade(request: CreateAnswerRequest): Promise<AnswerRecord> {
        // 1. 校验
        this.validateRequest(request);

        // 2. 创建DRAFT记录
        const record = new AnswerRecord({
            id: generateId(),
            userId: request.userId,
            questionId: request.questionId,
            sessionId: request.sessionId || null,
            answerContent: request.answerContent,
            status: RecordStatus.DRAFT,
            source: request.source,
            durationSeconds: request.durationSeconds,
            submittedAt: new Date(),
            createdAt: new Date(),
            updatedAt: new Date()
        });
        await this.db.insert('answer_records', record);
        this.updateCache(record);

        // 3. 异步触发评分
        try {
            this.triggerGrading(record.id);
            record.status = RecordStatus.GRADING;
            await this.db.update('answer_records', record.id, { status: RecordStatus.GRADING });
        } catch (error) {
            // 记录日志，稍后补偿
            logger.error(`Failed to trigger grading for record ${record.id}`, error);
        }

        return record;
    }

    /**
     * 触发评分（内部方法，可能异步执行）
     */
    private async triggerGrading(recordId: string): Promise<void> {
        const record = await this.getAnswerRecordById(recordId);
        if (!record) throw new Error('Record not found');

        // 调用评分服务
        const gradingResult = await this.gradingService.grade({
            questionId: record.questionId,
            userAnswer: record.answerContent
        });

        // 更新记录
        const updateData: Partial<AnswerRecord> = {
            isCorrect: gradingResult.isCorrect,
            score: gradingResult.score,
            feedback: gradingResult.feedback,
            knowledgePoints: gradingResult.knowledgePoints,
            gradedAt: new Date(),
            status: RecordStatus.COMPLETED
        };

        await this.db.update('answer_records', recordId, updateData);
        this.invalidateCache(recordId);

        // 触发下游事件
        this.emitAnswerCompletedEvent({
            recordId: recordId,
            userId: record.userId,
            isCorrect: gradingResult.isCorrect,
            knowledgePoints: gradingResult.knowledgePoints
        });
    }

    /**
     * 根据ID获取答题记录
     */
    async getAnswerRecordById(recordId: string): Promise<AnswerRecord | null> {
        // 1. 查缓存
        const cached = await this.cache.get(`answer_record:${recordId}`);
        if (cached) return cached;

        // 2. 查数据库
        const record = await this.db.findOne('answer_records', { id: recordId });
        if (record) {
            // 写缓存
            await this.cache.set(`answer_record:${recordId}`, record, 3600);
        }

        return record;
    }

    /**
     * 获取用户答题记录列表
     */
    async getUserAnswerRecords(userId: string, options: QueryOptions): Promise<PaginatedResult<AnswerRecord>> {
        // 构建查询条件
        const where: any = { userId };
        if (options.status) where.status = options.status;
        if (options.source) where.source = options.source;
        if (options.startTime && options.endTime) {
            where.submittedAt = { between: [options.startTime, options.endTime] };
        }

        // 分页查询
        const [items, total] = await Promise.all([
            this.db.findMany('answer_records', where, {
                limit: options.pageSize,
                offset: (options.page - 1) * options.pageSize,
                orderBy: { submittedAt: 'DESC' }
            }),
            this.db.count('answer_records', where)
        ]);

        return { items, total, page: options.page, pageSize: options.pageSize };
    }

    // 其他辅助方法...
}
```

## 6. 错误处理

### 6.1 异常类型
- **AnswerRecordNotFoundException**: 答题记录不存在。
- **InvalidAnswerContentException**: 答案内容格式错误或不符合题目要求。
- **DuplicateSubmissionException**: 重复提交（同一用户在同一会话下对同一题目）。
- **GradingServiceUnavailableException**: 评分服务不可用。
- **RecordStatusTransitionException**: 状态流转非法。

### 6.2 重试策略
- **评分失败重试**：采用指数退避策略，初始延迟1秒，最大重试3次，重试间隔依次为1s, 2s, 4s。
- **消息发送失败重试**：使用消息队列内置的重试机制，重试次数为5次，最终失败后转入死信队列进行人工干预。

### 6.3 降级方案
- **评分服务降级**：当评分服务不可用时，答题记录状态保持为`GRADING`，并在`extra`字段中记录错误信息。系统应提供管理员手动触发重评或标记为失败的功能。
- **缓存降级**：当Redis不可用时，直接查询数据库，并在日志中记录降级事件。

## 7. 性能优化

### 7.1 缓存策略
- **多级缓存**：在服务实例内部使用本地缓存（如Caffeine）作为一级缓存，Redis作为二级缓存。
- **缓存预热**：对于热门题目或用户，可在低峰期提前加载其答题记录到缓存。
- **缓存雪崩防护**：为缓存键设置随机的过期时间偏移量，避免大量key同时失效。

### 7.2 并发控制
- **乐观锁**：在更新答题记录时，使用版本号或`updated_at`字段进行乐观锁控制，防止并发更新导致数据覆盖。
- **分布式锁**：对于关键操作（如批量归档），使用Redis分布式锁确保同一时间只有一个任务在执行。

### 7.3 资源限制
- **限流**：对创建答题记录接口进行限流，例如每用户每分钟最多提交50次，防止恶意刷题或接口滥用。
- **熔断**：当评分服务连续失败率达到阈值（如50%）时，触发熔断器，暂时停止调用评分服务，快速失败，避免级联雪崩。

## 8. 安全考虑

### 8.1 权限控制
- **用户数据隔离**：用户只能查询和修改自己的答题记录。后台管理员拥有所有数据的查询权限，但需严格审计。
- **API鉴权**：所有接口需进行JWT或OAuth2.0等标准的身份鉴权。

### 8.2 数据验证
- **输入清洗**：对`answerContent`等用户输入进行格式校验和清洗，防止SQL注入、XSS等攻击。
- **长度限制**：对文本类答案设置最大长度限制，防止恶意构造大字符串消耗资源。

### 8.3 审计日志
- 记录所有对答题记录的增删改查操作，包括操作者ID、操作时间、操作类型、受影响记录ID等，存入审计日志表或专门的日志系统。
- 管理员的批量查询或删除操作必须记录详细的查询条件和操作原因。

## 9. 测试策略

### 9.1 单元测试
- 测试核心业务逻辑：创建记录、状态流转、评分结果回填。
- 测试异常处理：模拟各种异常场景（记录不存在、参数错误、服务不可用）。
- 测试缓存逻辑：验证缓存读写、失效、穿透场景。

### 9.2 集成测试
- 测试完整的答题流程：从提交答案到评分完成、触发错题、更新掌握度。
- 测试数据库事务：确保在多步操作中发生异常时数据能回滚。
- 测试消息队列集成：验证下游事件能否正确发送和消费。

### 9.3 性能测试
- **压测目标**：创建接口TPS达到1000，查询接口TPS达到5000。
- **场景设计**：模拟1000个并发用户同时提交答案。
- **监控指标**：关注接口响应时间（P99 < 500ms）、数据库慢查询数量、缓存命中率（目标 > 80%）。

### 9.4 兼容性测试
- 验证不同题型（选择、填空、主观题）的答案结构和存储格式兼容性。
- 验证不同来源（练习、考试、作业）的业务逻辑兼容性。
