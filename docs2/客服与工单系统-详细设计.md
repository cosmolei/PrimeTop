# 客服与工单系统 - 详细设计

## 1. 模块概述

### 1.1 定位

客服与工单系统是 PrimeTop 的用户服务支撑平台，负责管理用户咨询、问题反馈、投诉建议的完整生命周期，从问题接入手入到最终解决闭环。系统面向三个角色：

- **学生/家长用户**：提交工单、查看进度、自助FAQ、满意度评价
- **客服人员**：接单、处理、回复、转派、关闭工单
- **运营主管**：监控SLA、分配策略、质量抽检、数据分析

### 1.2 与现有系统的关系

| 关联系统 | 交互方式 | 说明 |
|----------|----------|------|
| 用户反馈与AI质量评估 | 工单创建 | AI纠错反馈可一键升级为工单 |
| 用户账号体系 | 身份查询 | 查询用户信息、会员状态、设备信息 |
| 消息与推送服务 | 通知推送 | 工单状态变更通知用户 |
| 支付与会员订阅 | 订单查询 | 投诉类工单关联支付订单 |
| 学习记录与进度追踪 | 数据查询 | 学情问题工单可查看学习行为 |
| 内容与运营后台 | 管理入口 | 运营后台集成客服工作台 |

### 1.3 设计目标

1. **全渠道接入**：APP内、邮件、后台等多入口统一汇聚
2. **智能分发**：根据工单类型、优先级自动分配给对应客服组
3. **SLA保障**：响应时效、解决时效可视化监控
4. **自助优先**：FAQ + 智能推荐减少人工工单量
5. **闭环可追溯**：工单全生命周期可查、可统计、可复盘

### 2.3 优先级规则

| 优先级 | 触发条件 | SLA响应 | SLA解决 |
|--------|----------|---------|---------|
| **urgent** | 未成年人安全/内容涉黄/支付大额异常/媒体曝光 | 15分钟 | 2小时 |
| **high** | 退款投诉/会员无法使用/APP无法启动/批量用户影响 | 30分钟 | 8小时 |
| **normal** | 一般功能咨询/题目错误/内容建议 | 2小时 | 24小时 |
| **low** | UI优化建议/功能请求/一般性咨询 | 4小时 | 48小时 |

优先级自动判定逻辑：

```python
class PriorityEngine:
    """工单优先级自动判定引擎"""

    KEYWORD_MAP = {
        "urgent": [
            "涉黄", "色情", "暴力", "诈骗", "隐私泄露",
            "未成年人安全", "自杀", "自残", "大额扣费",
        ],
        "high": [
            "退款", "扣费异常", "无法登录", "闪退", "崩溃",
            "会员失效", "数据丢失", "投诉",
        ],
    }

    # 分类默认优先级
    CATEGORY_DEFAULT = {
        ("payment", "退款申请"): "high",
        ("payment", "发票问题"): "normal",
        ("ai_feature", "内容安全"): "urgent",
        ("technical", "APP 崩溃"): "high",
    }

    @classmethod
    def determine(cls, ticket_data: dict) -> str:
        """
        综合判定工单优先级
        1. 关键词检测 → 可能升级到 urgent/high
        2. 分类默认优先级
        3. 用户角色 (家长投诉默认+1级)
        4. 会员状态 (付费用户默认+1级)
        """
        base = "normal"

        # Step 1: 关键词检测
        text = f"{ticket_data['title']} {ticket_data['description']}"
        for level, keywords in cls.KEYWORD_MAP.items():
            if any(kw in text for kw in keywords):
                base = level
                break

        # Step 2: 分类默认值(仅当关键词未匹配更高优先级时)
        if base == "normal":
            cat_key = (ticket_data["category_l1"], ticket_data["category_l2"])
            base = cls.CATEGORY_DEFAULT.get(cat_key, "normal")

        # Step 3: 角色加权
        if ticket_data.get("user_role") == "parent" and base in ("normal", "low"):
            base = cls._upgrade(base)

        # Step 4: 付费用户加权
        if ticket_data.get("is_paid_user") and base == "low":
            base = "normal"

        return base

    @staticmethod
    def _upgrade(level: str) -> str:
        return {"low": "normal", "normal": "high", "high": "urgent"}.get(level, level)
```

### 3.3 SLA 计算引擎

```python
from dataclasses import dataclass
from datetime import datetime, timedelta
from typing import Optional


@dataclass
class SLAPolicy:
    """SLA策略配置"""
    response_hours: int      # 首次响应时效(小时)
    resolution_hours: int    # 解决时效(小时)
    business_hours_only: bool = True  # 是否仅计算工作时间


# 优先级 → SLA策略映射
SLA_POLICIES: dict[str, SLAPolicy] = {
    "urgent": SLAPolicy(response_hours=0.25, resolution_hours=2),
    "high":   SLAPolicy(response_hours=0.5,  resolution_hours=8),
    "normal": SLAPolicy(response_hours=2,    resolution_hours=24),
    "low":    SLAPolicy(response_hours=4,    resolution_hours=48),
}

# 工作时间定义 (09:00-21:00, 周一至周日)
BUSINESS_START = 9
BUSINESS_END = 21


def calculate_sla_deadlines(
    priority: str,
    created_at: datetime,
    business_hours_only: bool = True,
) -> dict[str, Optional[datetime]]:
    """
    计算SLA截止时间
    考虑工作时间窗口: 非工作时间创建的工单从下一个工作时段开始计算
    """
    policy = SLA_POLICIES.get(priority, SLA_POLICIES["normal"])

    if business_hours_only:
        response_due = _add_business_hours(created_at, policy.response_hours)
        resolution_due = _add_business_hours(created_at, policy.resolution_hours)
    else:
        response_due = created_at + timedelta(hours=policy.response_hours)
        resolution_due = created_at + timedelta(hours=policy.resolution_hours)

    return {
        "sla_response_due_at": response_due,
        "sla_resolution_due_at": resolution_due,
    }


def _add_business_hours(start: datetime, hours: float) -> datetime:
    """在工作时间窗口内累加小时数"""
    current = start
    remaining_minutes = hours * 60

    while remaining_minutes > 0:
        # 今天工作时间窗口
        biz_start = current.replace(hour=BUSINESS_START, minute=0, second=0, microsecond=0)
        biz_end = current.replace(hour=BUSINESS_END, minute=0, second=0, microsecond=0)

        if current < biz_start:
            # 还没到工作时间，跳到工作开始
            current = biz_start
            continue

        if current >= biz_end:
            # 已过工作时间，跳到明天工作开始
            current = (current + timedelta(days=1)).replace(
                hour=BUSINESS_START, minute=0, second=0, microsecond=0
            )
            continue

        # 当前在工作时间内
        available_minutes = (biz_end - current).total_seconds() / 60
        used_minutes = min(remaining_minutes, available_minutes)

        current += timedelta(minutes=used_minutes)
        remaining_minutes -= used_minutes

    return current


def get_sla_status(ticket: dict) -> dict:
    """获取工单当前SLA状态"""
    now = datetime.utcnow()
    result = {"response": "ok", "resolution": "ok"}

    # 响应SLA
    if ticket.get("first_responded_at"):
        result["response"] = "met"
    elif ticket.get("sla_response_due_at"):
        if now > ticket["sla_response_due_at"]:
            result["response"] = "breached"
        elif now > ticket["sla_response_due_at"] - timedelta(minutes=15):
            result["response"] = "warning"  # 15分钟内即将超时

    # 解决SLA
    if ticket.get("resolved_at"):
        result["resolution"] = "met"
    elif ticket.get("sla_resolution_due_at"):
        if now > ticket["sla_resolution_due_at"]:
            result["resolution"] = "breached"
        elif now > ticket["sla_resolution_due_at"] - timedelta(hours=1):
            result["resolution"] = "warning"  # 1小时内即将超时

    return result
```

## 5. 自动分配引擎

### 5.1 分配策略

```python
class AssignmentEngine:
    """工单自动分配引擎"""

    @classmethod
    def assign(cls, ticket: dict) -> Optional[dict]:
        """
        自动分配工单给客服
        返回分配结果: {"agent_id": 123, "group_id": 1, "strategy": "round_robin"}
        无可用客服时返回 None
        """
        # 1. 查找负责该分类的客服组
        groups = cls._find_groups(ticket["category_l1"])
        if not groups:
            return None

        group = groups[0]
        strategy = group["assignment_strategy"]

        # 2. 查找该组在线且可用的客服
        agents = cls._get_available_agents(group["id"])
        if not agents:
            # 无可用客服 → 工单保持 pending，发布告警
            return None

        # 3. 按策略选择
        if strategy == "round_robin":
            agent = cls._round_robin_select(group["id"], agents)
        elif strategy == "least_load":
            agent = cls._least_load_select(agents)
        else:  # manual
            return None  # 手动分配策略不自动分配

        return {
            "agent_id": agent["id"],
            "group_id": group["id"],
            "strategy": strategy,
        }

    @classmethod
    def _round_robin_select(cls, group_id: int, agents: list) -> dict:
        """轮询分配"""
        key = f"ticket_rr_cursor:{group_id}"
        cursor = cache.get(key, -1)
        cursor = (cursor + 1) % len(agents)
        cache.set(key, cursor, timeout=86400)
        return agents[cursor]

    @classmethod
    def _least_load_select(cls, agents: list) -> dict:
        """最少负载优先"""
        return min(agents, key=lambda a: a["current_load"])

    @classmethod
    def _find_groups(cls, category_l1: str) -> list:
        """查找负责该分类的客服组"""
        # 从缓存中获取客服组配置
        return AgentGroupRepository.find_by_category(category_l1)

    @classmethod
    def _get_available_agents(cls, group_id: int) -> list:
        """获取组内在线可用客服"""
        return AgentRepository.find_available(
            group_id=group_id,
            is_online=True,
            status="available",
        )
```

```python
def search_faq(query: str, category_l1: str = None, limit: int = 5) -> list:
    """
    FAQ 搜索：FULLTEXT + 关键词匹配混合策略
    """
    # 1. MySQL FULLTEXT 检索
    sql = """
        SELECT id, question, answer,
               MATCH(question, answer) AGAINST(:query IN NATURAL LANGUAGE MODE) AS score
        FROM faq_articles
        WHERE is_visible = 1
          AND (:category IS NULL OR category_id IN (
              SELECT id FROM faq_categories WHERE name = :category
          ))
        HAVING score > 0.5
        ORDER BY score DESC
        LIMIT :limit
    """

    # 2. 关键词精确匹配补充（FULLTEXT 可能遗漏短词）
    keyword_matches = search_by_keywords(query, category_l1)

    # 3. 合并去重，关键词匹配的结果适当加权
    results = merge_and_rank(fulltext_results, keyword_matches)

    # 4. 记录搜索日志（用于后续优化 FAQ 内容）
    log_faq_search(query, results)

    return results[:limit]
```

```python
def check_duplicate(user_id: int, title: str, category_l1: str) -> Optional[dict]:
    """
    检测用户是否有相似内容的未关闭工单
    避免用户重复提交同一问题
    """
    active_statuses = ["pending", "assigned", "in_progress", "waiting_user"]

    # 1. 精确匹配: 同一用户+同分类+相似标题+未关闭
    similar = db.query("""
        SELECT id, ticket_no, title, status, created_at
        FROM support_tickets
        WHERE user_id = :user_id
          AND category_l1 = :category
          AND status IN :active_statuses
          AND created_at > DATE_SUB(NOW(), INTERVAL 7 DAY)
        ORDER BY created_at DESC
        LIMIT 5
    """, user_id=user_id, category=category_l1, active_statuses=active_statuses)

    if not similar:
        return None

    # 2. 标题相似度计算 (编辑距离)
    for ticket in similar:
        similarity = compute_similarity(title, ticket["title"])
        if similarity > 0.8:
            return ticket  # 疑似重复

    return None
```

客户端处理：检测到重复时弹出提示"您有一个类似问题正在处理中，是否查看已有工单？"，用户确认后才继续创建。

### 12.2 数据安全

1. **工单内容加密**：标题和描述字段存储时使用 AES-256 加密（密钥由 KMS 管理）
2. **附件安全**：上传附件需经过内容安全扫描（复用现有安全审核服务）
3. **PII 脱敏**：客服工作台展示用户信息时，手机号中间四位脱敏
4. **审计日志**：所有客服操作（查看、回复、转派）记录到 `ticket_status_logs`
5. **访问限制**：用户仅能访问自己创建的工单，客服仅能访问本组工单
6. **附件清理**：工单关闭 90 天后附件自动删除，保留元数据

- 13 岁以下用户的工单自动附加"未成年人"标签
- 涉及未成年人的工单优先级自动提升一级
- 客服回复内容需经过内容安全过滤
- 家长可代孩子查看和回复工单（通过家长绑定关系验证）
