# 管理后台-推荐策略调控与内容运营管理工作台-详细设计

## 1. 概述

### 1.1 功能定位

推荐策略调控与内容运营管理工作台（以下简称"推荐运营工作台"）是 PrimeTop 管理后台的核心模块之一，为运营人员、内容编辑和产品经理提供可视化界面，用于管理和调控平台推荐系统的策略参数、内容曝光规则、推荐效果监控和人工干预操作。

该工作台是连接业务运营与技术推荐引擎之间的桥梁——将底层 30+ 推荐引擎（冷启动策略、多样性保障、疲劳防护、场景化推荐等）的能力转化为运营人员可操作的配置面板，使非技术人员也能精准调控推荐策略。

### 1.2 设计目标

| 目标 | 说明 |
| --- | --- |
| 策略可视化 | 将推荐算法参数以表单/滑块形式呈现，运营人员无需理解代码 |
| 实时调控 | 策略变更后秒级生效，支持灰度推送和一键回滚 |
| 内容管控 | 运营手动置顶/下架/加权特定内容，干预自动推荐结果 |
| 效果可测 | 内置 AB 实验框架，策略变更前后效果一目了然 |
| 安全可控 | 全操作审计日志，关键策略变更需主管审批 |

### 1.3 使用角色

| 角色 | 权限范围 |
| --- | --- |
| 推荐运营专员 | 调整策略参数、管理内容曝光、创建 AB 实验 |
| 内容运营编辑 | 管理内容标签、置顶/加权内容、配置专题 |
| 产品经理 | 查看效果数据、审批策略变更、管理实验 |
| 技术管理员 | 管理推荐模型版本、配置算法参数、系统运维 |

### 1.4 关联系统

| 系统 | 关系 |
| --- | --- |
| 推荐内容多样性保障引擎 | 工作台下发多样性参数 |
| 推荐内容疲劳防护引擎 | 工作台配置疲劳阈值 |
| 个性化推荐解释生成引擎 | 工作台管理解释模板 |
| 内容推荐冷启动引擎 | 工作台配置新用户策略 |
| 首页内容卡片推荐服务 | 工作台管理卡片类型和排序 |
| 学习内容热度评估引擎 | 工作台查看热度趋势 |
| AB测试与实验平台 | 工作台内嵌实验创建和效果分析 |
| 内容推荐效果监控引擎 | 工作台消费监控数据并展示 |

## 2. 数据结构定义

### 2.1 推荐策略配置表 `rec_strategy_config`

```sql
CREATE TABLE rec_strategy_config (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    strategy_key    VARCHAR(128) NOT NULL COMMENT '策略唯一标识，如 homepage_feed, exam_review, error_review',
    strategy_name   VARCHAR(128) NOT NULL COMMENT '策略中文名',
    scene_code      VARCHAR(64)  NOT NULL COMMENT '场景编码：HOME/AI_DIALOG/SYNC_CLASS/ERROR_REVIEW/EXAM_PREP',
    target_user_segment VARCHAR(64) DEFAULT 'all' COMMENT '目标用户分群：all/new_user/vip/free/grade_xxx',
    config_json     JSON         NOT NULL COMMENT '策略参数JSON，见2.2节',
    status          TINYINT      NOT NULL DEFAULT 0 COMMENT '0=草稿 1=待审批 2=已生效 3=已暂停 4=已废弃',
    version         INT          NOT NULL DEFAULT 1 COMMENT '版本号，每次修改+1',
    effective_from  DATETIME     NULL COMMENT '生效开始时间',
    effective_to    DATETIME     NULL COMMENT '生效结束时间',
    grayscale_ratio INT          DEFAULT 100 COMMENT '灰度比例(0-100)，100=全量生效',
    grayscale_rules JSON         NULL COMMENT '灰度规则：按地区/学段/年级等维度',
    created_by      BIGINT       NOT NULL COMMENT '创建人ID',
    updated_by      BIGINT       NOT NULL COMMENT '最后修改人ID',
    created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_scene (scene_code, status),
    INDEX idx_strategy (strategy_key, version),
    INDEX idx_status (status, effective_from, effective_to)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='推荐策略配置表';
```

### 2.3 内容曝光管控表 `content_exposure_control`

```sql
CREATE TABLE content_exposure_control (
    id               BIGINT PRIMARY KEY AUTO_INCREMENT,
    content_id       BIGINT       NOT NULL COMMENT '内容ID',
    content_type     VARCHAR(32)  NOT NULL COMMENT '内容类型：video/article/exercise/card/course',
    control_type     VARCHAR(32)  NOT NULL COMMENT '管控类型：PIN/BOOST/SUPPRESS/BLACKLIST/FEATURE',
    scope            VARCHAR(32)  DEFAULT 'global' COMMENT '生效范围：global/scene_specific/user_segment',
    scene_code       VARCHAR(64)  NULL COMMENT '场景编码（scope=scene_specific时必填）',
    user_segment     VARCHAR(64)  NULL COMMENT '用户分群（scope=user_segment时必填）',
    priority         INT          DEFAULT 100 COMMENT '优先级（数字越大越优先）',
    weight_multiplier DECIMAL(5,2) DEFAULT 1.00 COMMENT '权重乘数',
    effective_from   DATETIME     NOT NULL COMMENT '生效开始时间',
    effective_to     DATETIME     NULL COMMENT '生效结束时间（NULL=长期有效）',
    reason           VARCHAR(512) NULL COMMENT '管控原因说明',
    status           TINYINT      NOT NULL DEFAULT 1 COMMENT '0=已撤销 1=生效中 2=已过期',
    created_by       BIGINT       NOT NULL,
    created_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    expired_at       DATETIME     NULL COMMENT '撤销时间',
    INDEX idx_content (content_id, content_type, status),
    INDEX idx_scene (scene_code, status, effective_from, effective_to),
    INDEX idx_control (control_type, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='内容曝光管控表';
```

## 3. API 接口设计

### 3.1 推荐策略管理

#### 3.1.1 获取策略列表

```
GET /admin/api/v1/rec/strategies
```

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| scene_code | String | 否 | 场景编码筛选 |
| status | Integer | 否 | 状态筛选 |
| page | Integer | 是 | 页码，从1开始 |
| page_size | Integer | 是 | 每页数量，最大50 |

**响应示例**

```json

```

```
PATCH /admin/api/v1/rec/strategies/{strategy_id}/grayscale
```

**请求体**

```json
{
  "action": "increase",
  "target_ratio": 50,
  "auto_full_release_hours": 24
}
```

| action | 说明 |
| --- | --- |
| increase | 提高灰度比例到 target_ratio |
| full_release | 直接全量发布 |
| rollback | 回滚到上一版本 |
| pause | 暂停策略 |

### 3.5 审批管理

#### 3.5.1 提交审批

```
POST /admin/api/v1/rec/approvals
```

系统根据变更内容自动判定风险等级：

| 风险等级 | 判定条件 | 审批链 |
| --- | --- | --- |
| low | 灰度比例<10%，非核心场景 | 直属主管 → 自动通过 |
| medium | 灰度比例10%-50%，核心场景参数微调 | 直属主管 → 产品经理 |
| high | 灰度比例>50%，核心算法权重变更 | 直属主管 → 产品经理 → 技术负责人 |
| critical | 全量发布，多样性/疲劳参数关闭 | 直属主管 → 产品经理 → 技术负责人 → CTO |

#### 3.5.2 审批操作

```
POST /admin/api/v1/rec/approvals/{approval_id}/decide
```

**请求体**

```json
{
  "decision": "approve",
  "comment": "参数调整合理，同意发布"
```

```java
/**
 * 推荐策略配置校验器
 * 在策略保存前校验参数合法性和业务约束
 */
@Component
public class StrategyConfigValidator {

    /**
     * 校验策略配置JSON
     */
    public ValidationResult validate(StrategyConfigDTO config) {
        ValidationResult result = new ValidationResult();
        JSONObject cfg = config.getConfigJson();

        // 1. 排序因子权重之和必须为1.0
        validateRankingWeights(cfg, result);

        // 2. 多样性参数边界校验
        validateDiversityParams(cfg, result);

        // 3. 疲劳参数合理性校验
        validateFatigueParams(cfg, result);

        // 4. 内容池非空校验
        validateContentPool(cfg, result);

        // 5. 业务规则内容存在性校验
        validateBusinessRules(cfg, result);

        return result;
    }

    private void validateRankingWeights(JSONObject cfg, ValidationResult result) {
        JSONObject ranking = cfg.getJSONObject("ranking");
        if (ranking == null) {
            result.addError("ranking", "排序配置不能为空");
            return;
        }

        JSONArray factors = ranking.getJSONArray("factors");
        if (factors == null || factors.isEmpty()) {
            result.addError("ranking.factors", "排序因子不能为空");
            return;
        }

        double totalWeight = 0;
        for (int i = 0; i < factors.size(); i++) {
            JSONObject factor = factors.getJSONObject(i);
            double weight = factor.getDoubleValue("weight");
            if (weight < 0 || weight > 1) {
                result.addError("ranking.factors[" + i + "].weight",
                    "排序因子权重必须在0-1之间");
            }
            totalWeight += weight;
        }

        // 权重之和允许±0.01误差
        if (Math.abs(totalWeight - 1.0) > 0.01) {
            result.addError("ranking.factors",
                String.format("排序因子权重之和必须为1.0，当前为%.4f", totalWeight));
        }
    }

    private void validateDiversityParams(JSONObject cfg, ValidationResult result) {
        JSONObject diversity = cfg.getJSONObject("diversity");
        if (diversity == null || !diversity.getBooleanValue("enabled")) {
            return;
        }

        int maxSameSubject = diversity.getIntValue("max_same_subject");
        if (maxSameSubject < 1 || maxSameSubject > 10) {
            result.addError("diversity.max_same_subject",
                "同一学科最大连续出现次数必须在1-10之间");
        }

        double explorationRatio = diversity.getDoubleValue("exploration_ratio");
        if (explorationRatio < 0 || explorationRatio > 0.5) {
            result.addError("diversity.exploration_ratio",
                "探索比例建议在0-0.5之间，过大会影响推荐精准度");
        }
    }

    private void validateFatigueParams(JSONObject cfg, ValidationResult result) {
        JSONObject fatigue = cfg.getJSONObject("fatigue");
        if (fatigue == null) return;

        int maxExposure = fatigue.getIntValue("max_exposure_per_day");
        if (maxExposure < 10 || maxExposure > 200) {
            result.addError("fatigue.max_exposure_per_day",
                "每日最大曝光次数建议在10-200之间");
        }

        int cooldown = fatigue.getIntValue("cooldown_minutes");
        if (cooldown < 5 || cooldown > 1440) {
            result.addError("fatigue.cooldown_minutes",
                "冷却时间建议在5-1440分钟之间");
        }
    }

    private void validateContentPool(JSONObject cfg, ValidationResult result) {
        JSONObject pool = cfg.getJSONObject("content_pool");
        if (pool == null) {
            result.addError("content_pool", "内容池配置不能为空");
            return;
        }

        JSONArray types = pool.getJSONArray("content_types");
        if (types == null || types.isEmpty()) {
            result.addError("content_pool.content_types", "内容类型不能为空");
        }

        double minQuality = pool.getDoubleValue("min_quality_score");
        if (minQuality < 0 || minQuality > 1) {
            result.addError("content_pool.min_quality_score",
                "最低质量分必须在0-1之间");
        }
    }

    private void validateBusinessRules(JSONObject cfg, ValidationResult result) {
        JSONObject rules = cfg.getJSONObject("business_rules");
        if (rules == null) return;

        // 置顶内容上限校验
        JSONArray pinned = rules.getJSONArray("pinned_content_ids");
        if (pinned != null && pinned.size() > 10) {
            result.addError("business_rules.pinned_content_ids",
                "置顶内容数量不能超过10个");
        }

        // 加权乘数范围校验
        double boostMultiplier = rules.getDoubleValue("boost_multiplier");
        if (boostMultiplier < 0.1 || boostMultiplier > 5.0) {
            result.addError("business_rules.boost_multiplier",
                "加权乘数必须在0.1-5.0之间");
        }
    }
}
```

```java
/**
 * 策略变更风险等级自动判定器
 */
@Component
public class StrategyRiskAssessor {

    private static final List<String> CORE_SCENES = List.of(
        "HOME", "AI_DIALOG", "SYNC_CLASS"
    );

    private static final List<String> HIGH_RISK_KEYS = List.of(
        "ranking.factors", "diversity.enabled", "fatigue.max_exposure_per_day"
    );

    /**
     * 评估策略变更风险等级
     */
    public RiskAssessment assess(StrategyConfig oldConfig, StrategyConfig newConfig) {
        RiskAssessment assessment = new RiskAssessment();
        assessment.setRiskLevel("low");

        // 1. 灰度比例判定
        int ratio = newConfig.getGrayscaleRatio();
        if (ratio >= 100) {
            assessment.upgradeTo("critical");
        } else if (ratio > 50) {
            assessment.upgradeTo("high");
        } else if (ratio > 10) {
            assessment.upgradeTo("medium");
        }

        // 2. 核心场景判定
        if (CORE_SCENES.contains(newConfig.getSceneCode())) {
            assessment.upgradeTo("medium");
        }

        // 3. 高风险参数变更判定
        JSONObject oldJson = oldConfig != null ? oldConfig.getConfigJson() : new JSONObject();
        JSONObject newJson = newConfig.getConfigJson();
        for (String highRiskKey : HIGH_RISK_KEYS) {
            Object oldValue = JSONPath.read(oldJson, "$." + highRiskKey);
            Object newValue = JSONPath.read(newJson, "$." + highRiskKey);
            if (!Objects.equals(oldValue, newValue)) {
                assessment.upgradeTo("high");
                assessment.addRiskFactor(String.format(
                    "高风险参数变更：%s 从 %s 变为 %s",
                    highRiskKey, oldValue, newValue));
            }
        }

        // 4. 多样性/疲劳关闭判定
        Boolean diversityEnabled = (Boolean) JSONPath.read(newJson, "$.diversity.enabled");
        if (Boolean.FALSE.equals(diversityEnabled)) {
            assessment.upgradeTo("critical");
            assessment.addRiskFactor("关闭了推荐多样性保障，可能导致信息茧房");
        }

        Boolean fatigueEnabled = newJson.getJSONObject("fatigue") != null;
        if (oldConfig != null && fatigueEnabled == false) {
            assessment.upgradeTo("critical");
            assessment.addRiskFactor("关闭了推荐疲劳防护，可能导致用户打扰");
        }

        return assessment;
    }
}
```

```java
/**

@RestController
@RequestMapping("/admin/api/v1/rec/strategies")
public class StrategyGrayscaleController {

    @Autowired
    private StrategyConfigService strategyService;
    @Autowired
    private RecommendationEngineClient engineClient;
    @Autowired
    private OperationLogService logService;

    /**
     * 提高灰度比例
     */
    @PutMapping("/{strategyId}/grayscale/increase")
    @AuditLog(operationType = "GRAYSCALE_INCREASE")
    public ApiResponse increaseGrayscale(
            @PathVariable Long strategyId,
            @RequestParam int targetRatio,
            @RequestParam(required = false, defaultValue = "false") boolean skipObservation) {

        StrategyConfig strategy = strategyService.getById(strategyId);
        validateStrategyState(strategy, "GRAYSCALE", "ACTIVE");

        if (targetRatio <= strategy.getGrayscaleRatio()) {
            throw new BusinessException("目标比例必须大于当前比例(" +
                strategy.getGrayscaleRatio() + "%)");
        }

        // 非跳过观察模式下，每次最多提升30%
        int maxStep = skipObservation ? 100 : 30;
        if (targetRatio - strategy.getGrayscaleRatio() > maxStep) {
            throw new BusinessException(String.format(
                "灰度比例每次最多提升%d%%，当前%d%%，目标%d%%",
                maxStep, strategy.getGrayscaleRatio(), targetRatio));
        }

        // 全量发布前校验是否有进行中的实验冲突
        if (targetRatio == 100) {
            List<RecExperiment> activeExps = experimentService
                .findActiveByStrategy(strategyId);
            if (!activeExps.isEmpty()) {
                throw new BusinessException(String.format(
                    "策略存在%d个进行中的AB实验，请先结束实验后再全量发布",
                    activeExps.size()));
            }
        }

        // 更新灰度比例
        int oldRatio = strategy.getGrayscaleRatio();
        strategy.setGrayscaleRatio(targetRatio);
        if (targetRatio == 100) {
            strategy.setStatus(StrategyStatus.ACTIVE.getCode());
        }
        strategyService.update(strategy);

        // 推送至推荐引擎
        engineClient.updateStrategy(strategy);

        // 记录审计日志
        logService.log(StrategyGrayscaleController.class.getSimpleName(),
            "increaseGrayscale", strategyId,
            String.format("灰度比例从%d%%调整为%d%%", oldRatio, targetRatio));

        return ApiResponse.success(StrategyGrayscaleVO.from(strategy));
    }

    /**
     * 回滚策略
     */
    @PostMapping("/{strategyId}/rollback")
    @AuditLog(operationType = "STRATEGY_ROLLBACK")
    public ApiResponse rollback(@PathVariable Long strategyId,
                                @RequestParam(required = false) String reason) {
        StrategyConfig current = strategyService.getById(strategyId);

        // 获取上一个生效版本
        StrategyConfig previous = strategyService.getPreviousVersion(
            current.getStrategyKey(), current.getVersion());

        if (previous == null) {
            throw new BusinessException("无历史版本可回滚");
        }

        // 当前版本标记为已回滚
        current.setStatus(StrategyStatus.ROLLED_BACK.getCode());
        strategyService.update(current);

        // 恢复上一版本为生效状态
        previous.setStatus(StrategyStatus.ACTIVE.getCode());
        previous.setGrayscaleRatio(100);
        strategyService.update(previous);

        // 推送回滚至引擎
        engineClient.updateStrategy(previous);

        // 告警通知
        alertService.sendStrategyRollbackAlert(current, previous, reason);

        return ApiResponse.success(Map.of(
            "rolled_back_version", current.getVersion(),
            "restored_version", previous.getVersion(),
            "restored_strategy_id", previous.getId()
        ));
    }
}
```

```java
            dto.getControlType(),
            dto.getSceneCode(),

            dto.getEffectiveTo()
        );

                    dto.getContentId(), dto.getControlType(),
                    conflicts.get(0).getId()));
        }

        // 4. 创建管控记录
        ContentExposureControl control = new ContentExposureControl();
        BeanUtils.copyProperties(dto, control);
        control.setStatus((byte) 1);

        // 5. PIN类型校验数量上限
        if ("PIN".equals(dto.getControlType())) {
            int pinCount = controlMapper.countActiveByScene(
                dto.getControlType(), dto.getSceneCode());
            if (pinCount >= 10) {
                throw new BusinessException(
                    String.format("场景%s的置顶内容已达上限(10个)", dto.getSceneCode()));
            }
            control.setPriority(Math.max(dto.getPriority(), 900));
        }

        controlMapper.insert(control);

        // 6. 实时推送至推荐引擎
        engineClient.updateContentControl(Map.of(
            "action", "ADD",
            "content_id", control.getContentId(),
            "control_type", control.getControlType(),
            "scene_code", control.getSceneCode(),
            "priority", control.getPriority(),
            "weight_multiplier", control.getWeightMultiplier()
        ));

    }
```

### 5.5 AB实验效果统计算法

```java
/**
 * AB实验效果统计算法
 */
@Service
public class ExperimentStatService {

    /**
     * 计算实验两组指标和显著性
     */
    public ExperimentResult calculateResult(Long experimentId) {
        RecExperiment experiment = experimentMapper.selectById(experimentId);

        // 获取实验周期内的指标数据
        LocalDate startDate = experiment.getStartedAt().toLocalDate();
        LocalDate endDate = experiment.getEndedAt() != null
            ? experiment.getEndedAt().toLocalDate()
            : LocalDate.now();

        // 分别查询A/B两组的指标
        Map<String, MetricStats> groupAStats = queryGroupMetrics(
            experiment.getStrategyAId(), startDate, endDate);
        Map<String, MetricStats> groupBStats = queryGroupMetrics(
            experiment.getStrategyBId(), startDate, endDate);

        // 计算核心指标显著性
        String primaryMetric = experiment.getPrimaryMetric();
        SignificanceResult primarySig = calculateSignificance(
            groupAStats.get(primaryMetric),
            groupBStats.get(primaryMetric)
        );

        // 计算辅助指标显著性
        Map<String, SignificanceResult> secondarySigs = new HashMap<>();
        if (experiment.getSecondaryMetrics() != null) {
            for (String metric : experiment.getSecondaryMetrics()) {
                SignificanceResult sig = calculateSignificance(
                    groupAStats.get(metric),
                    groupBStats.get(metric)
                );
                secondarySigs.put(metric, sig);
            }
        }

        // 生成推荐建议
        String recommendation = generateRecommendation(
            primarySig, secondarySigs, experiment);

        return ExperimentResult.builder()
            .experimentId(experimentId)
            .groupA(toMetricMap(groupAStats))
            .groupB(toMetricMap(groupBStats))
            .significance(Map.of(
                "primary", primarySig,
                "secondary", secondarySigs
            ))
            .recommendation(recommendation)
            .build();
    }

    /**
     * 双样本Z检验计算显著性
     */
    private SignificanceResult calculateSignificance(
            MetricStats groupA, MetricStats groupB) {
        double meanA = groupA.getMean();
        double meanB = groupB.getMean();
        double varA = groupA.getVariance();
        double varB = groupB.getVariance();
        long nA = groupA.getSampleSize();
        long nB = groupB.getSampleSize();

        // Z分数
        double pooledSE = Math.sqrt(varA / nA + varB / nB);
        double zScore = pooledSE == 0 ? 0 : (meanB - meanA) / pooledSE;

        // 双侧p值
        double pValue = 2 * (1 - normalCDF(Math.abs(zScore)));

        // 提升幅度
        double lift = meanA == 0 ? 0 : (meanB - meanA) / meanA;

        boolean significant = pValue < 0.05 && nA >= 1000 && nB >= 1000;

        return SignificanceResult.builder()
            .meanA(meanA)
            .meanB(meanB)
            .lift(lift)
            .zScore(zScore)
            .pValue(pValue)
            .significant(significant)
            .sampleSizeA(nA)
            .sampleSizeB(nB)
            .build();
    }

    /**
     * 自动生成实验结论建议
     */
    private String generateRecommendation(
            SignificanceResult primary,
            Map<String, SignificanceResult> secondary,
            RecExperiment experiment) {

        StringBuilder sb = new StringBuilder();

        if (!primary.isSignificant()) {
            sb.append("核心指标").append(experiment.getPrimaryMetric())
              .append("未达到统计显著性(p=")
              .append(String.format("%.3f", primary.getPValue()))
              .append(")，建议延长实验周期或增加样本量。");
            return sb.toString();
        }

        double lift = primary.getLift();
        if (lift > 0) {
            sb.append(String.format(
                "实验组在核心指标%s上显著提升(+%.1f%%, p=%.3f)",
                experiment.getPrimaryMetric(),
                lift * 100, primary.getPValue()));
        } else {
            sb.append(String.format(
                "实验组在核心指标%s上显著下降(%.1f%%, p=%.3f)",
                experiment.getPrimaryMetric(),
                lift * 100, primary.getPValue()));
        }

        // 检查辅助指标是否有恶化
        List<String> regressions = secondary.entrySet().stream()
            .filter(e -> e.getValue().isSignificant() && e.getValue().getLift() < 0)
            .map(e -> String.format("%s(%.1f%%)", e.getKey(),
                e.getValue().getLift() * 100))
            .collect(Collectors.toList());

        if (!regressions.isEmpty() && lift > 0) {
            sb.append("。但辅助指标出现显著下降：")
              .append(String.join("、", regressions))
              .append("，建议谨慎评估。");
        } else if (lift > 0) {
            sb.append("。辅助指标无显著恶化，建议全量发布。");
        } else {
            sb.append("。建议停止实验，保留对照组策略。");
        }

        return sb.toString();
    }

    private double normalCDF(double z) {
        return 0.5 * (1 + erf(z / Math.sqrt(2)));
    }

    private double erf(double x) {
        // Abramowitz and Stegun 近似
        double t = 1.0 / (1.0 + 0.3275911 * Math.abs(x));
        double y = 1.0 - (((((1.061405429 * t - 1.453152027) * t)
            + 1.421413741) * t - 0.284496736) * t + 0.254829592) * t
            * Math.exp(-x * x);
        return x >= 0 ? y : -y;
    }
}
```

## 8. 错误处理与异常场景

### 8.1 错误码定义

| 错误码 | HTTP状态 | 说明 | 处理方式 |
| --- | --- | --- | --- |
| REC_STRATEGY_001 | 400 | 排序因子权重之和不为1 | 前端实时校验并提示 |
| REC_STRATEGY_002 | 400 | 多样性参数超出合理范围 | 表单校验拦截 |
| REC_STRATEGY_003 | 409 | 策略key已存在 | 提示用户更名 |
| REC_STRATEGY_004 | 409 | 存在冲突的内容管控记录 | 弹窗确认是否覆盖 |
| REC_STRATEGY_005 | 422 | 策略非灰度状态，无法调整比例 | 提示当前状态 |
| REC_STRATEGY_006 | 422 | 置顶内容已达上限(10个) | 提示先撤销旧置顶 |
| REC_STRATEGY_007 | 422 | 全量发布前存在进行中的AB实验 | 提示先结束实验 |
| REC_APPROVAL_001 | 403 | 无审批权限 | 提示联系有权限人员 |
| REC_APPROVAL_002 | 422 | 审批已过期或已处理 | 刷新页面 |
| REC_ENGINE_001 | 503 | 推荐引擎不可用 | 重试 + 告警 |
| REC_ENGINE_002 | 504 | 引擎ACK超时 | 显示部分生效 + 告警 |

### 8.2 异常场景处理

| 场景 | 处理策略 |
| --- | --- |
| 策略JSON格式错误 | 前端JSON Schema实时校验 + 后端二次校验，拒绝保存 |
| 引擎节点部分不可用 | 策略变更标记为"部分生效"，前端展示节点状态，触发P2告警 |
| 审批人离职/转岗 | 审批超时(48h)后自动流转到备选审批人 |
| 灰度指标突然恶化 | 系统自动触发告警，推送至企业微信/钉钉，但不自动回滚（需人工判断） |
| 同一策略被多人同时编辑 | 乐观锁控制，后保存者收到冲突提示，需拉取最新版本后重新编辑 |
| 内容被管控但已从内容池下架 | 管控记录自动标记为"内容已下线"状态，不影响推荐流程 |
| AB实验两组策略相同 | 创建时校验，提示"对照组和实验组策略相同，无法创建实验" |

### 8.3 降级策略

```text
当推荐运营工作台自身出现故障时：

1. 工作台不可用 → 推荐引擎使用最近一次成功下发的策略快照继续运行
2. 数据库不可用 → 切换到只读副本，禁止写操作，前端展示降级提示
3. 消息队列不可用 → 策略变更延迟下发，标记为"待同步"，恢复后批量推送
4. 监控数据不可用 → 看板展示"数据采集中"占位，不影响策略运行

核心原则：工作台故障不影响线上推荐服务的正常运行。
```

## 9. 性能优化

### 9.1 数据查询优化

| 场景 | 优化策略 |
| --- | --- |
| 策略列表查询 | scene_code + status 联合索引，分页限制 |
| 审计日志查询 | 按月分表，operator_id + created_at 索引，超3个月数据归档到ClickHouse |
| 效果监控看板 | 指标数据预计算写入 Redis，看板查询直接读取聚合结果 |
| 内容搜索选择器 | Elasticsearch全文检索，支持拼音、简繁体搜索 |

### 9.2 缓存设计

```text
缓存层次：
  L1 - 本地缓存（Caffeine，TTL 60s）
       └─ 策略列表、场景枚举、用户角色

  L2 - Redis分布式缓存（TTL 5min）
       └─ 策略详情、内容管控列表、实验状态

  L3 - MySQL持久化
       └─ 全量数据

写入策略：Write-Through
  工作台写入 → MySQL → 更新Redis → 推送引擎 → 更新本地缓存
  读取策略：L1 → L2 → L3
```

### 9.3 并发控制

- 策略编辑：乐观锁（version字段），冲突时提示用户
- 内容管控创建：分布式锁 `lock:content_control:{contentId}`，防止重复创建
- 实验启动：分布式锁 `lock:experiment:scene:{sceneCode}`，防止同场景实验冲突
