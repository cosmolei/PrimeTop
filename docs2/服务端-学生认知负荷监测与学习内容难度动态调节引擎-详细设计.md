## 1. 模块概述

### 1.1 功能定位

本引擎负责在**单次学习会话内**（一次连续学习行为，通常 15-60 分钟），实时监测学生的认知负荷状态，并动态调节后续推送内容的难度梯度，使学习内容始终处于学生的**最近发展区（Zone of Proximal Development, ZPD）**内。

### 1.2 与现有模块的边界

| 模块 | 关注层面 | 与本引擎区别 |
|------|----------|-------------|
| 知识追踪模型引擎 | 跨会话能力评估 | 本引擎关注**会话内**实时状态，而非长期能力画像 |
| 自适应学习与推荐引擎 | 内容选择与推荐 | 本引擎不决定"学什么"，而是调节"多难" |
| 学习风格识别服务 | 呈现方式适配 | 本引擎不改变呈现方式，只调节内容难度参数 |
| 学习倦怠预警引擎 | 宏观疲劳/倦怠 | 本引擎关注**微观**认知过载，时间粒度为分钟级 |
| 专注力分析引擎 | 高效时段识别 | 本引擎关注当前会话的负荷变化，而非历史时段规律 |

### 1.3 核心价值

1. **降低挫败感**: 当学生连续答错或响应时间异常延长时，自动降低下一题难度，避免"习得性无助"
2. **防止无聊**: 当学生连续快速答对时，自动提升难度，保持心流（Flow）状态
3. **保护认知资源**: 检测到认知过载时，主动建议休息或切换学习模式
4. **提升学习效率**: 在 ZPD 内学习的内容留存率比随机难度高 40-60%（参考教育心理学研究）

## 4. 核心算法设计

### 4.1 认知负荷指数（CLI）计算

CLI 是一个 0-100 的综合指标，值越高代表认知负荷越大。

#### 4.1.1 瞬时 CLI 计算（每题完成后）

```python
def calculate_instant_cli(
    response_time_ms: int,
    expected_time_ms: int,
    is_correct: bool,
    hint_count: int,
    revision_count: int,
    hesitation_pauses: int,
    app_background_count: int,
    difficulty: float,
    theta: float,
    profile: CognitiveProfile
) -> float:
    """
    计算单题完成后的瞬时认知负荷指数。
    
    返回值: 0-100 的 CLI 分数
    """
    
    # 1. 时间比率分量 (0-100)
    time_ratio = response_time_ms / max(expected_time_ms, 1)
    # time_ratio > 1.5 开始增加负荷，> 3.0 为高负荷
    time_component = clamp(
        50 + (time_ratio - 1.0) * 40,
        min_val=10, max_val=100
    )
    
    # 2. 正确性分量 (0-100)
    # 连续答错会累积负荷
    if is_correct:
        correctness_component = 20  # 答对：低负荷
    else:
        correctness_component = 75  # 答错：高负荷
    
    # 3. 提示使用分量
    hint_component = min(hint_count * 15, 60)  # 每次提示+15，上限60
    
    # 4. 犹豫/修改分量
    hesitation_component = min(
        hesitation_pauses * 8 + revision_count * 10,
        max_val=50
    )
    
    # 5. 注意力分散分量 (切后台)
    distraction_component = min(app_background_count * 20, 60)
    
    # 6. 难度-能力差距分量
    # 题目远超当前能力时，负荷急剧增加
    diff_gap = difficulty - theta  # IRT参数空间
    difficulty_component = clamp(
        50 + diff_gap * 60,
        min_val=10, max_val=100
    )
    
    # 7. 加权融合 (使用用户个性化敏感度)
    cli = (
        time_component * profile.sensitivity_to_time * 0.7 +
        correctness_component * profile.sensitivity_to_error * 0.8 +
        hint_component * profile.sensitivity_to_hints +
        hesitation_component * 0.3 +
        distraction_component * 0.4 +
        difficulty_component * 0.5
    ) / (
        profile.sensitivity_to_time * 0.7 +
        profile.sensitivity_to_error * 0.8 +
        profile.sensitivity_to_hints +
        0.3 + 0.4 + 0.5
    )
    
    return round(clamp(cli, min_val=0, max_val=100), 2)


def classify_load_level(cli: float) -> str:
    """将 CLI 映射到负荷等级"""
    if cli < 25:
        return "LOW"        # 认知负荷过低 → 可能无聊
    elif cli < 55:
        return "OPTIMAL"    # 最佳负荷区间 → 心流
    elif cli < 75:
        return "HIGH"       # 高负荷 → 需要关注
    else:
        return "OVERLOAD"   # 过载 → 需要干预
```

#### 4.1.2 会话级 EMA 平滑

```python
def update_session_cli(
    prev_session_cli: float,
    instant_cli: float,
    alpha: float = 0.35   # EMA 平滑因子，越接近1越敏感
) -> float:
    """
    使用指数移动平均更新会话级 CLI。
    alpha 越大，最新答题行为的权重越高。
    """
    return round(prev_session_cli * (1 - alpha) + instant_cli * alpha, 2)
```

#### 4.1.3 负荷趋势斜率

```python
from collections import deque

class CLITrendCalculator:
    """基于最近 N 题的 CLI 序列计算趋势斜率"""
    
    def __init__(self, window_size: int = 5):
        self.window_size = window_size
        self.cli_history: deque[float] = deque(maxlen=window_size)
    
    def push(self, cli: float) -> None:
        self.cli_history.append(cli)
    
    def slope(self) -> float:
        """简单线性回归斜率"""
        n = len(self.cli_history)
        if n < 2:
            return 0.0
        x_mean = (n - 1) / 2
        y_mean = sum(self.cli_history) / n
        numerator = sum(
            (i - x_mean) * (y - y_mean)
            for i, y in enumerate(self.cli_history)
        )
        denominator = sum((i - x_mean) ** 2 for i in range(n))
        return numerator / denominator if denominator != 0 else 0.0
    
    def trend_label(self) -> str:
        s = self.slope()
        if s > 1.5:
            return "RISING"
        elif s < -1.5:
            return "FALLING"
        else:
            return "STABLE"
```

### 4.2 ZPD 难度计算

基于维果茨基的最近发展区理论，结合 IRT（项目反应理论）参数。

#### 4.2.1 ZPD 边界计算

```python
def calculate_zpd_bounds(
    theta: float,               # 学生当前能力估计 (-3 to 3, IRT scale)
    optimal_gap: float = 0.5,   # 最优难度差 (来自用户档案)
    cli: float = 50.0,          # 当前认知负荷指数
    load_adjustment: bool = True
) -> tuple[float, float]:
    """
    计算当前条件下的 ZPD 边界。
    
    返回 (lower_bound, upper_bound) 在 IRT 难度 scale 上。
    """
    # 基础 ZPD：能力 ± 最优差距
    base_lower = theta - optimal_gap * 0.8
    base_upper = theta + optimal_gap
    
    if not load_adjustment:
        return round(base_lower, 3), round(base_upper, 3)
    
    # 根据认知负荷动态收窄/扩展 ZPD
    if cli > 70:
        # 高负荷：收窄ZPD，降低上界
        shrink = (cli - 70) / 100  # 0 - 0.3
        lower = base_lower - shrink * 0.2  # 略微降低下界
        upper = base_upper - shrink * 0.5  # 明显降低上界
    elif cli < 30:
        # 低负荷：扩展ZPD，提高上界
        expand = (30 - cli) / 100  # 0 - 0.3
        lower = base_lower + expand * 0.1  # 略微提高下界
        upper = base_upper + expand * 0.3  # 明显提高上界
    else:
        # 最佳负荷区间：保持基础ZPD
        lower = base_lower
        upper = base_upper
    
    return round(lower, 3), round(upper, 3)


def calculate_target_difficulty(
    theta: float,
    cli: float,
    zpd_lower: float,
    zpd_upper: float,
    consecutive_correct: int,
    consecutive_wrong: int,
    slope: float              # CLI趋势斜率
) -> float:
    """
    计算下一题的目标难度。
    """
    # 基础目标：ZPD 中点偏上（略具挑战性）
    base_target = (zpd_lower + zpd_upper) / 2 + (zpd_upper - zpd_lower) * 0.25
    
    # 动态偏移
    offset = 0.0
    
    # 连续答对 → 适度提升
    if consecutive_correct >= 2:
        offset += min(consecutive_correct * 0.08, 0.25)
    
    # 连续答错 → 明显降低
    if consecutive_wrong >= 2:
        offset -= min(consecutive_wrong * 0.12, 0.40)
    
    # CLI 上升趋势 → 降低难度
    if slope > 1.5:
        offset -= min(slope * 0.05, 0.20)
    
    # CLI 下降趋势且负荷低 → 提升难度
    if slope < -1.0 and cli < 40:
        offset += min(abs(slope) * 0.03, 0.15)
    
    target = base_target + offset
    
    # 确保在 ZPD 范围内
    target = max(zpd_lower, min(zpd_upper, target))
    
    return round(target, 3)
```

#### 4.3.1 决策规则引擎

```python

from typing import Optional

class AdjustmentAction(Enum):
    UP = "UP"              # 提升难度
    DOWN = "DOWN"          # 降低难度
    HOLD = "HOLD"          # 保持当前难度
    BREAK = "BREAK"        # 建议休息
    SWITCH_MODE = "SWITCH_MODE"  # 切换学习模式 (如从练习切到复习)


@dataclass
class AdjustmentDecision:
    action: AdjustmentAction
    target_difficulty: Optional[float]
    delta: float
    confidence: float
    reason: str
    evidence: dict


def make_adjustment_decision(
    session_state: CognitiveSessionState,
    cli_trend: CLITrendCalculator,
    profile: CognitiveProfile,
    events: list[AnswerBehaviorEvent]
) -> AdjustmentDecision:
    """
    主决策入口。综合多维信号生成难度调节决策。
    """
    cli = session_state.cognitive_load_index
    slope = cli_trend.slope()
    consecutive_correct = session_state.consecutive_correct
    consecutive_wrong = session_state.consecutive_wrong
    session_minutes = (datetime.now() - session_state.session_start_time).total_seconds() / 60
    
    triggers = []
    confidence = 0.5
    
    # ========== 规则 1: 连续错误降难 (最高优先级) ==========
    if consecutive_wrong >= profile.frustration_threshold:
        triggers.append({
            "type": "CONSECUTIVE_WRONG",
            "value": consecutive_wrong,
            "threshold": profile.frustration_threshold,
            "weight": 0.45
        })
        confidence = min(confidence + 0.3, 0.95)
    
    # ========== 规则 2: 响应时间异常 ==========
    recent_events = events[-3:] if len(events) >= 3 else events
    slow_count = sum(1 for e in recent_events if e.time_ratio > 2.0)
    if slow_count >= 2:
        triggers.append({
            "type": "RESPONSE_TIME_RATIO",
            "value": sum(e.time_ratio for e in recent_events) / len(recent_events),
            "threshold": 2.0,
            "weight": 0.25
        })
        confidence = min(confidence + 0.15, 0.95)
    
    # ========== 规则 3: 提示使用过多 ==========
    recent_hints = sum(e.hint_count for e in recent_events)
    if recent_hints >= 2:
        triggers.append({
            "type": "HINT_USAGE",
            "value": recent_hints,
            "threshold": 1,
            "weight": 0.15
        })
        confidence = min(confidence + 0.10, 0.95)
    
    # ========== 规则 4: 犹豫暂停增多 ==========
    recent_hesitation = sum(e.hesitation_pauses for e in recent_events)
    if recent_hesitation >= 3:
        triggers.append({
            "type": "HESITATION",
            "value": recent_hesitation,
            "threshold": 2,
            "weight": 0.15
        })
    
    # ========== 规则 5: 连续正确提难 ==========
    if consecutive_correct >= 3 and cli < 40:
        triggers.append({
            "type": "CONSECUTIVE_CORRECT",
            "value": consecutive_correct,
            "threshold": 3,
            "weight": 0.50
        })
        confidence = min(confidence + 0.25, 0.95)
    
    # ========== 规则 6: 认知过载保护 ==========
    if cli >= 80 or (cli >= 70 and slope > 2.0):
        # 触发休息建议
        triggers.append({
            "type": "OVERLOAD",
            "value": cli,
            "threshold": 80,
            "weight": 0.80
        })
        confidence = min(confidence + 0.35, 0.98)
    
    # ========== 规则 7: 会话时长保护 ==========
    if session_minutes >= profile.max_session_minutes:
        triggers.append({
            "type": "SESSION_DURATION",
            "value": session_minutes,
            "threshold": profile.max_session_minutes,
            "weight": 0.60
        })
        confidence = min(confidence + 0.30, 0.95)
    elif session_minutes >= profile.max_session_minutes * 0.8:
        # 接近建议时间，开始降低难度
        triggers.append({
            "type": "SESSION_FATIGUE",
            "value": session_minutes,
            "threshold": profile.max_session_minutes * 0.8,
            "weight": 0.20
        })
    
    # ========== 生成决策 ==========
    evidence = {
        "triggers": triggers,
        "current_abilities": {
            "theta": session_state.current_ability,
            "confidence": confidence,
            "trend": "DECLINING" if slope > 1.0 else ("RISING" if slope < -1.0 else "STABLE")
        },
        "load_indicators": {
            "cli": cli,
            "load_level": session_state.load_level,
            "trend_5q": cli_trend.trend_label(),
            "slope": round(slope, 2)
        },
        "context": {
            "session_minutes": round(session_minutes, 1),
            "consecutive_correct": consecutive_correct,
            "consecutive_wrong": consecutive_wrong
        }
    }
    
    # 决策逻辑
    has_overload = any(t["type"] in ("OVERLOAD", "SESSION_DURATION") for t in triggers)
    has_negative = any(t["type"] in ("CONSECUTIVE_WRONG", "RESPONSE_TIME_RATIO", "HINT_USAGE", "HESITATION", "SESSION_FATIGUE") for t in triggers)
    has_positive = any(t["type"] == "CONSECUTIVE_CORRECT" for t in triggers)
    
    zpd_lower, zpd_upper = calculate_zpd_bounds(
        session_state.current_ability,
        profile.optimal_difficulty_gap,
        cli
    )
    
    if has_overload:
        return AdjustmentDecision(
            action=AdjustmentAction.BREAK,
            target_difficulty=None,
            delta=0.0,
            confidence=confidence,
            reason="认知负荷过载或会话时间超限，建议休息",
            evidence=evidence
        )
    elif has_negative:
        target = calculate_target_difficulty(
            session_state.current_ability, cli,
            zpd_lower, zpd_upper,
            consecutive_correct, consecutive_wrong, slope
        )
        delta = target - session_state.target_difficulty
        if delta < -0.05:
            return AdjustmentDecision(
                action=AdjustmentAction.DOWN,
                target_difficulty=target,
                delta=delta,
                confidence=confidence,
                reason="检测到认知负荷升高信号，降低难度",
                evidence=evidence
            )
    elif has_positive:
        target = calculate_target_difficulty(
            session_state.current_ability, cli,
            zpd_lower, zpd_upper,
            consecutive_correct, consecutive_wrong, slope
        )
        delta = target - session_state.target_difficulty
        if delta > 0.05:
            return AdjustmentDecision(
                action=AdjustmentAction.UP,
                target_difficulty=target,
                delta=delta,
                confidence=confidence,
                reason="学生表现优异且负荷较低，提升挑战",
                evidence=evidence
            )
    
    # 默认保持
    return AdjustmentDecision(
        action=AdjustmentAction.HOLD,
        target_difficulty=session_state.target_difficulty,
        delta=0.0,
        confidence=confidence,
        reason="负荷处于合理区间，维持当前难度",
        evidence=evidence
    )
```

## 6. 状态流转设计

### 6.1 会话级负荷状态机

| 状态 | 进入条件 | 退出条件 | 引擎动作 |
|------|---------|---------|----------|
| **LOW** (负荷过低/无聊) | CLI < 25 | CLI 回升至 30+ | 提升难度 |
| **OPTIMAL** (最佳) | 25 ≤ CLI < 55 | CLI 超出范围 | 维持或微调 |
| **FLOW** (心流) | 30 ≤ CLI < 50 且连续正确≥2 | 连续错误或 CLI>55 | 维持当前策略 |
| **HIGH** (偏高) | 55 ≤ CLI < 75 | CLI 下降至 55 以下 | 降低难度 |
| **OVERLOAD** (过载) | CLI ≥ 75 | 休息完成 | 降低难度+建议休息 |
| **FRUSTRATED** (挫败) | CLI ≥ 75 且连续错误≥3 | 答对一题 | 大幅降难+强制提示 |
| **BREAK** (休息中) | 触发休息建议且用户接受 | 休息计时结束 | 恢复学习，降低初始难度 |
| **RECOVERING** (恢复) | 休息结束 | 完成 2 题 | 逐步回到正常难度 |

### 6.2 难度调节状态流转

| 当前动作 | 触发条件 | 下一步动作 | 说明 |
|---------|---------|-----------|------|
| HOLD | 连续正确≥3 + CLI<40 | → UP | 提升挑战 |
| UP | 下一题答对 | → HOLD | 确认提升有效 |
| UP | 下一题答错 | → DOWN | 回退 |
| HOLD | 连续错误≥2 | → DOWN | 降低难度 |
| DOWN | 下一题答对 | → HOLD | 确认降难有效 |
| DOWN | 下一题仍错 | → DOWN | 继续降低+提供提示 |
| 任意 | CLI≥80 | → BREAK | 强制休息 |
| BREAK | 休息完成 | → HOLD | 以更低难度恢复 |

## 7. 关键流程设计

### 7.1 答题后实时调节流程

```
客户端提交答案
  │
  ▼
Step 1: 记录答题行为事件 → answer_behavior_event
  │
  ▼
Step 2: 计算瞬时 CLI（时间/正确性/提示/犹豫/难度差距 加权）
  │
  ▼
Step 3: 更新会话级 EMA-CLI + 计算趋势斜率
  │
  ▼
Step 4: 更新能力估计 θ（调用知识追踪模型增量更新）
  │
  ▼
Step 5: 难度调节决策（规则引擎 → UP/DOWN/HOLD/BREAK）
  │
  ├─ UP → 检索更高难度题目
  ├─ DOWN → 检索更低难度题目
  ├─ HOLD → 检索同等难度题目
  └─ BREAK → 推送休息建议卡片
  │
  ▼
Step 6: 写入调节决策日志（evidence + decision）
  │
  ▼
Step 7: 返回下一题 + 调节信息给客户端
```

### 7.2 冷启动处理流程

新用户首次使用时，没有历史认知负荷数据。冷启动策略：

```
新会话（无 cognitive_profile）
  │
  ▼
使用默认参数初始化档案（按学段差异化）
  │
  ▼
前 5 题使用固定难度序列进行探查
  题1-2: 中等难度 (b ≈ θ_initial)
  题3-4: 略高难度 (b ≈ θ + 0.3)
  题5: 恢复中等难度
  → 收集行为数据，建立初始 CLI 基线
  │
  ▼
第 6 题起启用动态调节
```

冷启动默认参数按学段差异化：

| 学段 | max_session_minutes | frustration_threshold | optimal_gap |
|------|---------------------|----------------------|-------------|
| 幼儿 | 15 | 2 | 0.3 |
| 小学 | 30 | 3 | 0.4 |
| 初中 | 40 | 3 | 0.5 |
| 高中 | 50 | 4 | 0.6 |

### 7.3 休息恢复流程

```
触发 BREAK 决策
  │
  ▼
推送休息建议卡片到客户端
  │
  ├─ 用户接受 → 启动休息计时 → 推送护眼/伸展引导 → 休息完成
  │                                         │
  │                                         ▼
  │                             恢复后降低一档难度 (target - 0.2)
  │
  └─ 用户拒绝 → 降低难度但不停止 → 更新 profile: 更敏感的降难阈值
```

## 8. 心流状态识别

### 8.1 心流状态分类

基于 Csikszentmihalyi 的心流理论，结合 CLI 和能力-难度差将学生状态分类：

| 状态 | 条件 | 表现特征 | 引擎响应 |
|------|------|---------|----------|
| **无聊 (BORED)** | CLI < 25 且 diff_gap < -0.3 | 快速答题，低交互率 | 提升难度 |
| **心流 (FLOW)** | 30 < CLI < 55 且 \|diff_gap\| < 0.3 | 专注答题，稳定节奏 | 维持当前难度 |
| **焦虑 (ANXIETY)** | 55 < CLI < 75 且 diff_gap > 0.3 | 响应变慢，犹豫增多 | 降低难度 |
| **挫败 (FRUSTRATED)** | CLI > 75 且 diff_gap > 0.5 | 连续错误，切后台频繁 | 强制降难或休息 |

## 9. 用户认知档案自学习

每次会话结束后，使用该会话数据反向更新用户认知档案参数。

```python
async def update_cognitive_profile_after_session(
    user_id: int,
    subject_code: str,
    session_events: list[AnswerBehaviorEvent],
    session_state: CognitiveSessionState
) -> None:
    profile = await get_cognitive_profile(user_id, subject_code)
    if not profile:
        return
    total_q = len(session_events)
    if total_q < 3:
        return
    
    # 1. 更新基线 CLI（加权移动平均）
    session_avg_cli = sum(e.instant_cli for e in session_events) / total_q
    profile.baseline_cli = round(profile.baseline_cli * 0.7 + session_avg_cli * 0.3, 2)
    
    # 2. 更新疲劳率
    if total_q >= 5:
        half = total_q // 2
        first_avg = sum(e.instant_cli for e in session_events[:half]) / half
        second_avg = sum(e.instant_cli for e in session_events[half:]) / (total_q - half)
        minutes = (session_state.last_activity_time - session_state.session_start_time).total_seconds() / 60
        if minutes > 0:
            observed_rate = max(0, (second_avg - first_avg) / minutes)
            profile.fatigue_rate = round(profile.fatigue_rate * 0.8 + observed_rate * 0.2, 3)
    
    # 3. 更新最优难度差
    best_events = sorted(session_events, key=lambda e: (1 if e.is_correct else 0, -e.time_ratio), reverse=True)[:3]
    if best_events:
        gaps = [e.difficulty - session_state.current_ability for e in best_events]
        observed_gap = sum(gaps) / len(gaps)
        profile.optimal_difficulty_gap = round(profile.optimal_difficulty_gap * 0.75 + observed_gap * 0.25, 3)
    
    # 4. 更新会话统计
    profile.total_sessions += 1
    profile.avg_session_cli = round(
        (profile.avg_session_cli or 0) * 0.9 + session_avg_cli * 0.1, 2
    )
    
    await save_cognitive_profile(profile)
```

## 10. 客户端配合要求

### 10.1 需要采集的行为信号

| 信号 | 采集方式 | 上报时机 |
|------|---------|----------|
| `response_time_ms` | 从题目展示到点击提交 | 每题提交 |
| `hint_count` | 提示按钮点击计数 | 每题提交 |
| `revision_count` | 答案修改计数 | 每题提交 |
| `hesitation_pauses` | 超过 3 秒无操作次数 | 每题提交 |
| `app_background_count` | APP onPause/onResume 事件 | 每题提交 |
| `screen_interaction_rate` | 每分钟触摸/点击事件数 | 心跳上报(30s) |
| `idle_seconds` | 连续无操作秒数 | 心跳上报(30s) |

### 10.2 客户端响应

客户端收到 `adjustment.action` 后的 UI 行为：

| Action | 客户端行为 |
|--------|-----------|
| `UP` | 正常展示下一题（更高难度），不做特殊提示 |
| `DOWN` | 正常展示下一题（更低难度），可显示鼓励语 "来道简单的缓缓~" |
| `HOLD` | 正常展示下一题（同等难度） |
| `BREAK` | 展示休息卡片（含建议时长+小活动），用户可接受或拒绝 |
| `SWITCH_MODE` | 弹窗建议切换学习模式（如从新知识学习切到复习模式） |

### 10.3 休息卡片 UI 规范

休息卡片展示规则：
- 全屏半透明遮罩 + 居中卡片
- 展示当前 CLI 数值（可视化仪表盘）
- 展示建议休息时长（倒计时样式）
- 可选择护眼操 / 伸展运动 / 自由休息
- 「稍后再说」按钮（记录拒绝，不影响学习）

## 11. 错误处理与边界条件

### 11.1 异常场景处理

| 场景 | 处理策略 |
|------|----------|
| 客户端心跳超时（>2分钟无心跳） | 标记会话为 ABNORMAL_END，不更新档案 |
| response_time_ms 异常大（>300秒） | 截断至预期时间的 5 倍上限，标记为 OUTLIER |
| 行为数据缺失（字段为 null/0） | 使用该用户历史均值填充，标记 FILLED |
| 并发答题上报（同一会话多个请求） | 使用分布式锁保护会话状态更新 |
| 会话恢复（断网后重连） | 客户端补传离线期间的答题数据，服务端按顺序重新计算 |
| 知识追踪模型不可用 | 降级为使用上次 θ 值，不影响难度调节流程 |

### 11.2 安全边界

| 边界 | 限制 |
|------|------|
| 单次调节最大幅度 | |delta| ≤ 0.40（防止难度跳变） |
| 连续调节次数限制 | 同一方向最多连续 3 次（防止难度漂移到极端） |
| 最低难度下限 | target_difficulty ≥ -3.0（IRT scale） |
| 最高难度上限 | target_difficulty ≤ 3.0（IRT scale） |
| 单会话最长时长 | 60 分钟（强制结束并发送报告） |
| 休息建议频率 | 每 15 分钟最多 1 次（避免打扰） |

### 11.3 业务异常码

| 错误码 | HTTP | 说明 |
|--------|------|------|
| 48001 | 400 | 会话不存在或已结束 |
| 48002 | 400 | 非法会话状态（如已结束的会话收到上报） |
| 48003 | 429 | 调节频率超限（同一会话调节过于频繁） |
| 48004 | 500 | 知识追踪模型调用失败（已降级处理） |
| 48005 | 400 | 参数校验失败（如 response_time_ms < 0） |

## 12. 性能与扩展性设计

### 12.1 性能指标要求

| 操作 | P99 延迟目标 |
|------|------------|
| 答题上报 → 返回下一题 | ≤ 200ms（含题目检索） |
| CLI 计算 | ≤ 10ms |
| 难度调节决策 | ≤ 20ms |
| 会话心跳处理 | ≤ 50ms |
| 档案更新（异步） | ≤ 2s（不阻塞主流程） |

### 12.2 缓存策略

| 数据 | 缓存位置 | TTL | 说明 |
|------|---------|-----|------|
| 会话认知状态 | Redis (session_cli:{session_id}) | 2h | 实时读写 |
| CLI 历史(近5题) | Redis (cli_hist:{session_id}) | 2h | 环形缓冲 |
| 用户认知档案 | Redis (cog_profile:{user_id}:{subject}) | 24h | 读多写少 |
| 题目难度索引 | Redis (q_diff_idx:{kp_id}:{difficulty_range}) | 1h | 按知识点+难度分区 |

### 12.3 水平扩展方案

- **无状态设计**: 认知状态全部存储在 Redis，服务实例可自由伸缩
- **会话亲和**: 通过一致性哈希将同一 session 的请求路由到同一实例组，减少缓存穿透
- **降级策略**: Redis 不可用时，降级为仅使用规则引擎（跳过历史 CLI 趋势），确保核心功能可用

## 15. 开发实现要点

### 15.1 实现优先级

| 阶段 | 范围 | 周期 |
|------|------|------|
| **Phase 1 (MVP)** | 基础 CLI 计算 + 连续对错规则 + HOLD/UP/DOWN 三种动作 | 2 周 |
| **Phase 2** | 完整多维 CLI + ZPD 计算 + 心流识别 + BREAK 动作 | 2 周 |
| **Phase 3** | 用户档案自学习 + 冷启动优化 + 监控告警 | 1 周 |

### 15.2 单元测试要点

- CLI 计算函数边界值测试（全对、全错、超时等极端场景）
- ZPD 边界计算精度测试
- 决策规则引擎逻辑覆盖（每条规则至少 2 个用例：触发/不触发）
- 冷启动参数初始化测试
- 参数自适应更新测试

### 15.3 集成测试场景

| 场景 | 预期行为 |
|------|----------|
| 模拟学生连续答错 5 题 | 第 3 题后触发 DOWN，难度持续降低 |
| 模拟学生连续答对 5 题 | 第 3 题后触发 UP，难度逐步提升 |
| 模拟学习 45 分钟 | 在 max_session_minutes 时触发 BREAK |
| 模拟频繁切后台 | CLI 上升，触发 DOWN |
| 模拟断网重连 | 离线数据补传后 CLI 正确计算 |
| 模拟新用户首次使用 | 前 5 题使用固定序列，第 6 题开始动态调节 |
