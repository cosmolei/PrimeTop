## 1. 模块概述

### 1.1 功能定位

本引擎是 PrimeTop AI 能力层的"知识推理大脑"，核心目标是将**静态的教育知识图谱**转化为**动态的推理能力**，增强 AI 辅导问答的准确性和教学深度。

传统 RAG（检索增强生成）仅基于向量相似度检索相关文本片段，缺乏对知识点之间逻辑关系（前置依赖、并列延伸、因果推导）的理解。本引擎在 RAG 基础上叠加知识图谱推理层，实现：

1. **图谱引导检索（KG-RAG）**：利用知识图谱的关系结构指导检索，而非仅依赖向量距离。
2. **多跳推理**：当学生问题涉及多个关联知识点时，沿图谱路径进行链式推理。
3. **前置知识检测**：回答前自动检测学生是否具备该问题所需的前置知识。
4. **个性化解释路径**：根据学生的知识掌握图谱，生成定制化的讲解路径。
5. **图谱验证回答**：用知识图谱中的确定性关系校验 AI 生成内容的逻辑一致性。

### 1.2 与其他模块的边界

| 能力 | 本引擎 | RAG与知识库系统 | 知识图谱构建引擎 | AI对话引擎 |
| --- | --- | --- | --- | --- |
| 向量检索 | ❌ 调用 | ✅ 负责 | ❌ | ❌ |
| 图谱构建与维护 | ❌ | ❌ | ✅ 负责 | ❌ |
| 图谱查询与推理 | ✅ 负责 | ❌ | ❌（只构建） | ❌ |
| 对话状态管理 | ❌ | ❌ | ❌ | ✅ 负责 |
| Prompt 模板组装 | ❌（提供推理结果） | ❌ | ❌ | ❌（由 AI-Prompt 模块负责） |
| 知识点标注 | ❌ | ❌ | ❌ | ❌（由题目知识点标注引擎负责） |

### 1.3 核心业务价值

| 场景 | 无本引擎 | 有本引擎 |
| --- | --- | --- |
| 学生问"为什么二次函数开口向上" | RAG 检索到相关文本，AI 基于文本回答 | 检测到需理解"判别式""系数符号"，沿图谱路径从"函数定义→系数→图像特征"推理回答 |
| 学生问"杠杆原理和滑轮有什么关系" | 向量检索可能只返回杠杆或滑轮的内容 | 图谱识别两者都属于"简单机械"子图，从"简单机械→杠杆/滑轮→力的传递"多跳关联 |
| 初中生问"导数是什么" | 可能直接给出导数定义（超出认知） | 图谱检测"导数"的前置为"极限→连续性→变化率"，提示学生需先学变化率 |
| AI 回答出现"光合作用产生氧气需要二氧化碳和水" | 无校验 | 图谱关系验证：光合作用-[原料]→CO₂+H₂O，[产物]→O₂+葡萄糖，确认正确 |

### 2.2 处理流程

```
学生问题
    │
    ▼
[1] 实体识别与链接 ──→ 从问题中抽取知识点实体、学科概念
    │                   映射到知识图谱中的标准节点
    ▼
[2] 前置知识检测 ────→ 查询图谱中该知识点的 prerequisite 链
    │                   交叉比对学生的学习画像（掌握度）
    │                   ┌─ 全部掌握 → 正常回答
    │                   ├─ 部分缺失 → 回答中补充前置说明
    │                   └─ 关键缺失 → 提示先学前置知识
    ▼
[3] 图谱引导检索 ────→ 沿图谱关系扩展检索范围
    │                   一跳邻居（直接关联）+ 二跳邻居（间接关联）
    │                   融合向量检索结果，形成增强知识上下文
    ▼
[4] 多跳推理 ────────→ 对于复杂问题，沿图谱路径进行链式推理
    │                   生成中间推理步骤
    │                   标注每步引用的知识点
    ▼
[5] 解释路径生成 ────→ 基于学生认知水平，生成个性化讲解路径
    │                   选择最佳切入点和讲解顺序
    ▼
[6] 事实校验 ────────→ AI 生成回答后，用图谱确定性关系校验
    │                   检测逻辑矛盾和事实错误
    ▼
增强后的上下文 + 推理结果 + 校验报告
    │
    ▼
  返回给 AI 对话引擎 / Prompt 编排系统
```

## 3. 数据结构定义

### 3.1 知识图谱节点模型

本引擎消费知识图谱构建引擎产出的图谱，以下为引擎核心关注的节点和关系结构。

#### 3.1.1 知识点节点 (KnowledgePoint)

```java
@Data
@Node("KnowledgePoint")
public class KnowledgePointNode {

    @Id
    private String kpId;                    // 知识点唯一ID: kp_{subject}_{grade}_{seq}
    
    @Property("name")
    private String name;                    // 知识点名称: "一元二次方程"
    
    @Property("subject")
    private String subject;                 // 学科: MATH, PHYSICS, ...
    
    @Property("grade_level")
    private Integer gradeLevel;             // 年级编码: 7=初一, 10=高一, ...
    
    @Property("stage")
    private String stage;                   // 学段: PRIMARY, JUNIOR, SENIOR
    
    @Property("bloom_level")
    private String bloomLevel;              // 布鲁姆层级: REMEMBER, UNDERSTAND, APPLY, ANALYZE, EVALUATE, CREATE
    
    @Property("difficulty")
    private Double difficulty;              // 难度系数 0.0-1.0
    
    @Property("textbook_chapter")
    private String textbookChapter;         // 关联教材章节ID
    
    @Property("description")
    private String description;             // 知识点简述
    
    @Property("keywords")
    private List<String> keywords;          // 关键词列表，用于实体链接
    
    @Property("aliases")
    private List<String> aliases;           // 别名: "quadratic equation", "二次方程"
    
    @Property("mastery_threshold")
    private Double masteryThreshold;        // 掌握度阈值: 0.7 表示 70% 正确率视为掌握
}
```

#### 3.1.2 知识点关系类型

```java
/**
 * 知识图谱核心关系类型枚举
 */
public enum KnowledgeRelationType {
    
    PREREQUISITE_OF,        // A 是 B 的前置知识: A →[PREREQUISITE_OF]→ B
                            // 学"二次方程"前需先学"一元一次方程"
    
    DEPENDS_ON,             // A 依赖于 B: A →[DEPENDS_ON]→ B
                            // "求导" 依赖于 "极限"的概念
    
    PART_OF,                // A 是 B 的组成部分: A →[PART_OF]→ B
                            // "因式分解" 是 "代数运算" 的一部分
    
    INSTANCE_OF,            // A 是 B 的具体实例: A →[INSTANCE_OF]→ B
                            // "勾股定理" 是 "直角三角形性质" 的实例
    
    RELATED_TO,             // A 与 B 相关: A →[RELATED_TO]→ B
                            // 带权重，表示关联强度
    
    DERIVED_FROM,           // A 由 B 推导而来: A →[DERIVED_FROM]→ B
                            // "动能定理" 由 "牛顿第二定律" 推导
    
    CONTRASTS_WITH,         // A 与 B 对比: A →[CONTRASTS_WITH]→ B
                            // "串联电路" 与 "并联电路" 对比
    
    APPLIED_IN,             // A 应用于 B: A →[APPLIED_IN]→ B
                            // "三角函数" 应用于 "波的传播"
    
    SAME_AS;                // A 等价于 B（跨教材版本映射）
}
```

#### 3.1.3 关系节点定义（Cypher Schema）

```cypher
// 前置知识关系（带权重）
CREATE (a:KnowledgePoint)-[r:PREREQUISITE_OF {
    weight: 0.8,           // 前置强度 0-1，1 表示绝对前置
    required: true,        // 是否为硬性前置
    description: "需要先掌握因式分解才能理解求根公式"
}]->(b:KnowledgePoint);

// 关联关系（带类型和权重）
CREATE (a:KnowledgePoint)-[r:RELATED_TO {
    weight: 0.6,           // 关联强度
    relation_desc: "都是描述物体运动的基本方法",
    category: "METHOD_COMPARISON"  // 关联分类
}]->(b:KnowledgePoint);
```

## 5. 核心算法设计

### 5.1 实体链接算法 (Entity Linking)

将学生自然语言问题中的知识点映射到知识图谱标准节点。

```
输入: "为什么二次函数y=x²的图像开口向上"
输出: [(kp_math_9_003, "二次函数", 0.95), (kp_math_9_002, "图像开口", 0.82)]

处理步骤:
1. 文本预处理 → 分词、词性标注、学科术语识别
2. 字典匹配 → 用知识点 keywords + aliases 做精确/模糊匹配
3. 语义匹配 → 对未命中的片段，用嵌入向量与知识点描述向量做相似度计算
4. 消歧 → 同一文本匹配到多个知识点时，用上下文（学科、年级、已有知识点）消歧
5. 输出 → 带置信度和位置的识别结果列表
```

**关键实现：**

```java
/**
 * 实体链接器
 * 将自然语言文本中的知识点映射到知识图谱节点
 */
@Service
@Slf4j
public class EntityLinker {

    @Autowired
    private KnowledgePointRepository kpRepository;
    
    @Autowired
    private EmbeddingService embeddingService;
    
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    
    /** 知识点字典缓存key前缀 */
    private static final String KP_DICT_CACHE_KEY = "kgqa:kp:dict:";
    
    /**
     * 执行实体链接
     * @param text 学生问题文本
     * @param subject 学科上下文
     * @param grade 年级上下文
     * @return 识别的知识点列表
     */
    public List<IdentifiedKnowledgePoint> link(String text, String subject, Integer grade) {
        
        // 1. 文本预处理
        List<Token> tokens = preprocess(text);
        
        // 2. 多策略匹配
        List<IdentifiedKnowledgePoint> results = new ArrayList<>();
        
        // 2a. 精确匹配（关键词/别名完全命中）
        results.addAll(exactMatch(tokens, subject, grade));
        
        // 2b. 模糊匹配（编辑距离 ≤ 2 的近似匹配）
        results.addAll(fuzzyMatch(tokens, subject, grade));
        
        // 2c. 语义匹配（对未命中片段用向量相似度）
        List<Token> unmatched = filterMatched(tokens, results);
        results.addAll(semanticMatch(unmatched, subject, grade));
        
        // 3. 去重 & 消歧
        results = disambiguate(results, subject, grade);
        
        // 4. 按置信度排序
        results.sort((a, b) -> Double.compare(b.getConfidence(), a.getConfidence()));
        
        return results;
    }
    
    /**
     * 精确匹配：用知识点关键词和别名字典做Aho-Corasick多模式匹配
     */
    private List<IdentifiedKnowledgePoint> exactMatch(List<Token> tokens, 
                                                       String subject, Integer grade) {
        // 从Redis加载学科+年级范围内的知识点字典
        Map<String, String> dict = loadKpDict(subject, grade);
        
        // Aho-Corasick自动机实现多模式高效匹配
        AhoCorasick automaton = buildAutomaton(dict);
        
        List<IdentifiedKnowledgePoint> matches = new ArrayList<>();
        for (Token token : tokens) {
            List<Match> acMatches = automaton.search(token.getText());
            for (Match m : acMatches) {
                String kpId = dict.get(m.getPattern());
                matches.add(IdentifiedKnowledgePoint.builder()
                    .kpId(kpId)
                    .matchedText(m.getMatchedText())
                    .matchType(MatchType.EXACT)
                    .confidence(1.0)
                    .startPos(token.getStart() + m.getStart())
                    .endPos(token.getStart() + m.getEnd())
                    .build());
            }
        }
        return matches;
    }
    
    /**
     * 语义匹配：对未命中片段计算向量相似度
     */
    private List<IdentifiedKnowledgePoint> semanticMatch(List<Token> unmatched, 
                                                          String subject, Integer grade) {
        List<IdentifiedKnowledgePoint> results = new ArrayList<>();
        
        for (Token token : unmatched) {
            // 跳过太短的文本
            if (token.getText().length() < 2) continue;
            
            // 计算文本嵌入向量
            float[] textVector = embeddingService.embed(token.getText());
            
            // 在学科范围内搜索最近邻知识点
            List<KpVectorMatch> candidates = kpRepository.searchByVector(
                textVector, subject, grade, 5, 0.65  // topK=5, minScore=0.65
            );
            
            for (KpVectorMatch c : candidates) {
                results.add(IdentifiedKnowledgePoint.builder()
                    .kpId(c.getKpId())
                    .name(c.getKpName())
                    .matchedText(token.getText())
                    .matchType(MatchType.SEMANTIC)
                    .confidence(c.getScore())
                    .startPos(token.getStart())
                    .endPos(token.getStart() + token.getText().length())
                    .build());
            }
        }
        return results;
    }
    
    /**
     * 消歧：当同一文本匹配到多个知识点时，用上下文选择最佳匹配
     */
    private List<IdentifiedKnowledgePoint> disambiguate(
            List<IdentifiedKnowledgePoint> candidates, String subject, Integer grade) {
        
        // 按匹配文本分组
        Map<String, List<IdentifiedKnowledgePoint>> grouped = candidates.stream()
            .collect(Collectors.groupingBy(IdentifiedKnowledgePoint::getMatchedText));
        
        List<IdentifiedKnowledgePoint> resolved = new ArrayList<>();
        for (var entry : grouped.entrySet()) {
            List<IdentifiedKnowledgePoint> group = entry.getValue();
            if (group.size() == 1) {
                resolved.add(group.get(0));
            } else {
                // 多候选消歧：优先选同学科、同年级、置信度最高的
                IdentifiedKnowledgePoint best = group.stream()
                    .min(Comparator.comparing(IdentifiedKnowledgePoint::getMatchType)
                        .thenComparing(kp -> -kp.getConfidence()))
                    .orElse(group.get(0));
                resolved.add(best);
            }
        }
        return resolved;
    }
    
    // 缓存知识点字典（1小时过期）
    private Map<String, String> loadKpDict(String subject, Integer grade) {
        String cacheKey = KP_DICT_CACHE_KEY + subject + ":" + grade;
        String cached = redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return JsonUtils.parseMap(cached);
        }
        // 从DB加载
        Map<String, String> dict = kpRepository.loadKeywordsAndAliases(subject, grade);
        redisTemplate.opsForValue().set(cacheKey, JsonUtils.toJson(dict), 
            Duration.ofHours(1));
        return dict;
    }
}
```

### 5.2 前置知识检测算法

```
输入: 目标知识点 kpId, 学生掌握度快照 masterySnapshot, 最大检测深度 maxDepth
输出: 前置就绪状态 + 缺失知识点列表

算法:
1. 从 kpId 出发，沿 PREREQUISITE_OF 和 DEPENDS_ON 关系做反向 BFS
2. 对每个前置节点:
   a. 查询学生在 masterySnapshot 中的掌握度
   b. 判断是否达到 masteryThreshold
   c. 标记为 mastered / not_mastered
3. 判定整体就绪状态:
   - 所有 required=true 的直接前置已掌握 → READY
   - 部分 required=true 的直接前置未掌握 → NOT_READY
   - 仅 required=false 或间接前置未掌握 → PARTIAL
4. 生成补救建议
```

**Cypher 查询：**

```cypher
// 前置知识链检测（BFS 3跳）
MATCH path = (target:KnowledgePoint {kpId: $kpId})<-[:PREREQUISITE_OF*1..3]-(prereq:KnowledgePoint)
WITH prereq, relationships(path) AS rels, length(path) AS hopDistance
// 取最短路径
WITH prereq, min(hopDistance) AS minHop, 
     [r IN relationships(path) | r.required] AS requiredFlags
UNWIND requiredFlags AS reqFlag
RETURN prereq.kpId AS kpId,
       prereq.name AS kpName,
       minHop AS hopDistance,
       collect(DISTINCT reqFlag)[0] AS isRequired
ORDER BY minHop ASC;
```

### 5.3 图谱引导检索 (KG-RAG)

传统的 RAG 只使用向量相似度检索。KG-RAG 在此基础上，沿知识图谱关系扩展检索范围，提供更有结构的知识上下文。

```
输入: 识别的知识点列表 identifiedKps, 最大跳数 maxHops
输出: 增强的知识上下文列表

算法:
1. 对每个 identifiedKp:
   a. 0跳（自身）：获取知识点描述和相关教学内容
   b. 1跳：获取直接关联的知识点（PREREQUISITE_OF, RELATED_TO, PART_OF等）
   c. 2跳：获取间接关联的知识点
2. 对每跳的邻居，按关系类型和权重打分:
   score = baseScore * relationWeight * decayFactor^hopDistance
   关系权重: PREREQUISITE_OF(0.9) > DEPENDS_ON(0.85) > DERIVED_FROM(0.8) 
           > PART_OF(0.7) > RELATED_TO(0.6) > CONTRASTS_WITH(0.5)
3. 将图谱扩展的知识点ID列表传递给RAG系统
4. RAG系统根据扩展后的知识点ID做精确内容检索
5. 合并去重，按相关性排序输出
```

**Cypher 查询：**

```cypher
// 图谱引导的知识点扩展查询（2跳）
MATCH (center:KnowledgePoint)-[r1*1..2]-(neighbor:KnowledgePoint)
WHERE center.kpId IN $kpIds
  AND neighbor.subject = $subject
WITH neighbor, 
     relationships(r1) AS rels,
     [n IN nodes(r1) WHERE n.kpId <> neighbor.kpId] AS pathNodes,
     length(r1) AS hops
// 计算路径分数
WITH neighbor, hops,
     reduce(score = 1.0, r IN rels | 
         score * 
         CASE type(r)
             WHEN 'PREREQUISITE_OF' THEN 0.9
             WHEN 'DEPENDS_ON' THEN 0.85
             WHEN 'DERIVED_FROM' THEN 0.8
             WHEN 'PART_OF' THEN 0.7
             WHEN 'RELATED_TO' THEN coalesce(r.weight, 0.6)
             WHEN 'CONTRASTS_WITH' THEN 0.5
             ELSE 0.5
         END * 0.7  -- 衰减因子
     ) AS pathScore
// 取每个邻居的最高分路径
WITH neighbor, max(pathScore) AS bestScore, min(hops) AS minHops
RETURN neighbor.kpId AS kpId,
       neighbor.name AS name,
       neighbor.description AS description,
       minHops AS hopDistance,
       bestScore AS relevanceScore
ORDER BY bestScore DESC
LIMIT 20;
```

### 5.4 多跳推理路径生成

当问题涉及多个知识点的因果推理时，沿图谱路径生成推理步骤。

```
输入: 起始知识点 fromKp, 目标知识点 toKp, 最大跳数 maxHops
输出: 推理路径（包含有序步骤）

算法:
1. 在图谱中查找 fromKp 到 toKp 的所有路径（DFS，深度 ≤ maxHops）
2. 对每条路径打分:
   pathScore = Σ(relationWeight_i * confidence_i) / hopCount
3. 选择 top-K 路径（默认 K=3）
4. 对每条路径，生成中间推理步骤:
   a. 提取每条边的 relation description
   b. 生成 reasoning hint（给AI的推理提示）
5. 返回推理路径列表
```

**关键实现：**

```java
/**
 * 多跳推理引擎
 */
@Service
@Slf4j
public class MultiHopReasoningEngine {

    @Autowired
    private Neo4jTemplate neo4jTemplate;

    private static final int DEFAULT_MAX_HOPS = 3;
    private static final int DEFAULT_TOP_K = 3;

    /**
     * 查找两个知识点之间的推理路径
     */
    public List<ReasoningPath> findReasoningPaths(String fromKpId, String toKpId,
                                                   int maxHops, int topK) {
        
        String cypher = """
            MATCH path = (from:KnowledgePoint {kpId: $fromKpId})
                  -[r*1..%d]-
                  (to:KnowledgePoint {kpId: $toKpId})
            WHERE ALL(n IN nodes(path) WHERE n.subject = $subject)
            WITH path, relationships(path) AS rels, nodes(path) AS ns
            RETURN 
                [n IN ns | n.kpId] AS kpIds,
                [n IN ns | n.name] AS kpNames,
                [r IN rels | type(r)] AS relTypes,
                [r IN rels | coalesce(r.description, '')] AS relDescs,
                [r IN rels | coalesce(r.weight, 0.7)] AS relWeights,
                length(path) AS hopCount
            ORDER BY hopCount ASC
            LIMIT $topK
            """.formatted(maxHops);

        Map<String, Object> params = Map.of(
            "fromKpId", fromKpId,
            "toKpId", toKpId,
            "topK", topK
        );

        List<Map<String, Object>> rows = neo4jTemplate.query(cypher, params);

        return rows.stream().map(row -> buildReasoningPath(row, fromKpId, toKpId))
            .sorted(Comparator.comparingDouble(ReasoningPath::getConfidence).reversed())
            .collect(Collectors.toList());
    }

    private ReasoningPath buildReasoningPath(Map<String, Object> row, 
                                              String fromKpId, String toKpId) {
        List<String> kpIds = (List<String>) row.get("kpIds");
        List<String> kpNames = (List<String>) row.get("kpNames");
        List<String> relTypes = (List<String>) row.get("relTypes");
        List<String> relDescs = (List<String>) row.get("relDescs");
        List<Double> relWeights = (List<Double>) row.get("relWeights");

        List<ReasoningStep> steps = new ArrayList<>();
        double totalScore = 0;
        
        for (int i = 0; i < kpIds.size(); i++) {
            ReasoningStep.ReasoningStepBuilder stepBuilder = ReasoningPath.builder()
                .step(i)
                .kpId(kpIds.get(i))
                .kpName(kpNames.get(i));
            
            if (i < relTypes.size()) {
                stepBuilder
                    .relationToNext(KnowledgeRelationType.valueOf(relTypes.get(i)))
                    .relationDescription(relDescs.get(i))
                    .reasoningHint(generateHint(relTypes.get(i), relDescs.get(i), 
                        kpNames.get(i), 
                        i + 1 < kpNames.size() ? kpNames.get(i + 1) : ""));
                totalScore += relWeights.get(i);
            }
            steps.add(stepBuilder.build());
        }

        int hopCount = kpIds.size() - 1;
        double confidence = hopCount > 0 ? totalScore / hopCount : 0;

        return ReasoningPath.builder()
            .pathId(UUID.randomUUID().toString())
            .fromKpId(fromKpId)
            .toKpId(toKpId)
            .steps(steps)
            .confidence(confidence)
            .pathType(inferPathType(relTypes))
            .build();
    }

    private String generateHint(String relType, String relDesc, 
                                 String currentName, String nextName) {
        if (StringUtils.isNotBlank(relDesc)) {
            return relDesc;
        }
        return switch (relType) {
            case "PREREQUISITE_OF" -> 
                "利用已掌握的'" + currentName + "'知识来理解'" + nextName + "'";
            case "DERIVED_FROM" -> 
                "'" + nextName + "'由'" + currentName + "'推导而来";
            case "RELATED_TO" -> 
                "'" + currentName + "'与'" + nextName + "'存在关联";
            case "CONTRASTS_WITH" -> 
                "对比'" + currentName + "'和'" + nextName + "'的异同";
            default -> 
                "从'" + currentName + "'过渡到'" + nextName + "'";
        };
    }
}
```

### 5.5 个性化解释路径生成

根据学生的知识掌握度快照，选择最佳讲解策略和讲解顺序。

```java
/**
 * 解释路径生成器
 * 根据学生画像和知识图谱，生成个性化讲解路径
 */
@Service
@Slf4j
public class ExplanationPathGenerator {

    @Autowired
    private PrerequisiteChecker prerequisiteChecker;
    
    @Autowired
    private KnowledgeGraphQueryService graphQueryService;

    /**
     * 生成个性化解释路径
     */
    public ExplanationPath generate(String targetKpId, 
                                     Map<String, Double> masterySnapshot,
                                     String studentStage,
                                     List<String> contextKpIds) {
        
        // 1. 获取前置知识检测结果
        PrerequisiteCheckResult prereqResult = prerequisiteChecker.check(
            targetKpId, masterySnapshot, 3);
        
        // 2. 确定讲解策略
        ExplanationStrategy strategy = decideStrategy(prereqResult, contextKpIds);
        
        // 3. 确定讲解步骤
        List<ExplanationStep> steps;
        Boolean needsRemediation = false;
        String remediationContext = null;
        
        switch (strategy) {
            case DIRECT:
                // 学生已掌握所有前置，直接讲解目标知识点
                steps = List.of(buildStep(1, targetKpId, "直接讲解核心概念"));
                break;
                
            case BOTTOM_UP:
                // 从已掌握的基础逐步构建到目标
                steps = buildBottomUpPath(targetKpId, prereqResult, masterySnapshot);
                needsRemediation = true;
                remediationContext = buildRemediationContext(prereqResult);
                break;
                
            case ANALOGY_FIRST:
                // 用类比引入新概念
                String analogyKpId = findBestAnalogy(targetKpId, masterySnapshot);
                steps = buildAnalogyPath(analogyKpId, targetKpId);
                break;
                
            case COMPARISON:
                // 通过对比已有知识来讲解
                String compareKpId = findBestComparison(targetKpId, masterySnapshot);
                steps = buildComparisonPath(compareKpId, targetKpId);
                break;
                
            case PROBLEM_FIRST:
                // 先提出问题再解释
                steps = buildProblemFirstPath(targetKpId);
                break;
                
            default: // TOP_DOWN
                steps = buildTopDownPath(targetKpId, prereqResult);
        }
        
        // 4. 确定最佳切入点
        String entryKpId = strategy == ExplanationStrategy.DIRECT ? 
            targetKpId : steps.get(0).getKpId();
        
        return ExplanationPath.builder()
            .entryKpId(entryKpId)
            .steps(steps)
            .strategy(strategy)
            .needsRemediation(needsRemediation)
            .remediationContext(remediationContext)
            .build();
    }
    
    /**
     * 策略决策
     */
    private ExplanationStrategy decideStrategy(PrerequisiteCheckResult prereq,
                                                List<String> contextKpIds) {
        if (prereq.getReadiness() == ReadinessLevel.READY) {
            // 前置全部就绪
            if (contextKpIds != null && !contextKpIds.isEmpty()) {
                // 如果有上下文，优先用对比策略
                return ExplanationStrategy.COMPARISON;
            }
            return ExplanationStrategy.DIRECT;
        }
        
        if (prereq.getReadiness() == ReadinessLevel.NOT_READY) {
            // 关键前置缺失，需要从基础讲起
            return ExplanationStrategy.BOTTOM_UP;
        }
        
        // PARTIAL: 尝试找类比
        return ExplanationStrategy.ANALOGY_FIRST;
    }
    
    /**
     * 构建自底向上的讲解路径
     */
    private List<ExplanationStep> buildBottomUpPath(String targetKpId,
            PrerequisiteCheckResult prereq, Map<String, Double> masterySnapshot) {
        
        List<ExplanationStep> steps = new ArrayList<>();
        int order = 1;
        
        // 按跳数排序，先讲解最基础（最远）的前置
        List<PrerequisiteStatus> sortedPrereqs = prereq.getPrerequisites().stream()
            .filter(p -> !p.getMastered())
            .sorted(Comparator.comparingInt(PrerequisiteStatus::getHopDistance).reversed())
            .toList();
        
        for (PrerequisiteStatus prereqKp : sortedPrereqs) {
            steps.add(ExplanationStep.builder()
                .order(order++)
                .kpId(prereqKp.getKpId())
                .kpName(prereqKp.getKpName())
                .teachingHint("补充前置知识：" + prereqKp.getKpName())
                .exampleSuggestion(generateExample(prereqKp.getKpId()))
                .estimatedComplexity(estimateComplexity(prereqKp.getKpId(), masterySnapshot))
                .build());
        }
        
        // 最后讲解目标知识点
        steps.add(ExplanationStep.builder()
            .order(order)
            .kpId(targetKpId)
            .kpName(graphQueryService.getKpName(targetKpId))
            .teachingHint("现在学习目标知识点")
            .exampleSuggestion(generateExample(targetKpId))
            .estimatedComplexity(4)
            .build());
        
        return steps;
    }
}
```

### 5.6 事实校验算法

AI 生成回答后，用知识图谱中的确定性关系校验回答的事实正确性。

```java
/**
 * 事实校验器
 * 使用知识图谱的确定性关系验证AI回答
 */
@Service
@Slf4j
public class FactValidator {

    @Autowired
    private Neo4jTemplate neo4jTemplate;
    
    @Autowired
    private EmbeddingService embeddingService;

    /**
     * 校验AI回答
     */
    public FactValidationResult validate(FactValidationRequest request) {
        
        // 1. 从知识图谱提取相关事实三元组
        List<KnowledgeTriplet> facts = extractFacts(request.getKpIds());
        
        // 2. 对每个事实三元组，检查回答中是否正确反映
        List<RuleValidationResult> ruleResults = new ArrayList<>();
        for (KnowledgeTriplet fact : facts) {
            RuleValidationResult result = validateAgainstAnswer(fact, request.getAnswer());
            ruleResults.add(result);
        }
        
        // 3. 综合判定
        boolean allPassed = ruleResults.stream().allMatch(RuleValidationResult::isPassed);
        double confidence = ruleResults.stream()
            .mapToDouble(RuleValidationResult::getScore)
            .average().orElse(0.5);
        
        return FactValidationResult.builder()
            .overallResult(allPassed ? "PASS" : "FAIL")
            .ruleResults(ruleResults)
            .confidence(confidence)
            .build();
    }
    
    /**
     * 从知识图谱提取事实三元组
     */
    private List<KnowledgeTriplet> extractFacts(List<String> kpIds) {
        String cypher = """
            MATCH (s:KnowledgePoint)-[r]->(o:KnowledgePoint)
            WHERE s.kpId IN $kpIds OR o.kpId IN $kpIds
            RETURN s.kpId AS subjectId, s.name AS subjectName,
                   type(r) AS relation,
                   o.kpId AS objectId, o.name AS objectName,
                   coalesce(r.description, '') AS description,
                   coalesce(r.weight, 0.7) AS weight
            """;
        
        return neo4jTemplate.query(cypher, Map.of("kpIds", kpIds))
            .stream()
            .map(row -> KnowledgeTriplet.builder()
                .subjectId((String) row.get("subjectId"))
                .subjectName((String) row.get("subjectName"))
                .relation((String) row.get("relation"))
                .objectId((String) row.get("objectId"))
                .objectName((String) row.get("objectName"))
                .description((String) row.get("description"))
                .weight((Double) row.get("weight"))
                .build())
            .collect(Collectors.toList());
    }
    
    /**
     * 校验单个事实三元组在回答中是否正确
     */
    private RuleValidationResult validateAgainstAnswer(KnowledgeTriplet fact, 
                                                        String answer) {
        // 使用语义匹配检测回答中是否包含正确的三元组关系
        
        // 1. 构建校验模式串
        String expectedPattern = fact.getSubjectName() + 
            RelationVerbMapper.getVerb(fact.getRelation()) + 
            fact.getObjectName();
        
        // 2. 语义匹配
        float[] patternVec = embeddingService.embed(expectedPattern);
        float[] answerVec = embeddingService.embed(answer);
        double similarity = CosineSimilarity.compute(patternVec, answerVec);
        
        // 3. 实体存在性检查
        boolean subjectFound = answer.contains(fact.getSubjectName()) || 
            checkAliasMatch(answer, fact.getSubjectName());
        boolean objectFound = answer.contains(fact.getObjectName()) || 
            checkAliasMatch(answer, fact.getObjectName());
        
        // 4. 方向校验（防止因果倒置）
        String reversedPattern = fact.getObjectName() + 
            RelationVerbMapper.getVerb(fact.getRelation()) + 
            fact.getSubjectName();
        float[] reversedVec = embeddingService.embed(reversedPattern);
        double reversedSimilarity = CosineSimilarity.compute(reversedVec, answerVec);
        
        boolean directionCorrect = similarity >= reversedSimilarity;
        
        boolean passed = subjectFound && objectFound && directionCorrect;
        
        return RuleValidationResult.builder()
            .passed(passed)
            .score(passed ? similarity : 1 - similarity)
            .message(buildValidationMessage(fact, subjectFound, objectFound, 
                directionCorrect, similarity))
            .build();
    }
}
```

### 6.2 主编排流程

```java
/**
 * KGQA 引擎主编排器
 */
@Service
@Slf4j
public class KgqaOrchestrator {

    @Autowired private EntityLinker entityLinker;
    @Autowired private PrerequisiteChecker prerequisiteChecker;
    @Autowired private KgRagRetriever kgRagRetriever;
    @Autowired private MultiHopReasoningEngine reasoningEngine;
    @Autowired private ExplanationPathGenerator explanationPathGenerator;
    @Autowired private FactValidator factValidator;
    @Autowired private EnhancedContextBuilder contextBuilder;

    /** 总超时预算 */
    private static final long TOTAL_TIMEOUT_MS = 200;

    /**
     * 增强入口（被 AI 对话引擎调用）
     */
    public EnhanceResponse enhance(EnhanceRequest request) {
        long startTime = System.currentTimeMillis();
        String requestId = IdGenerator.next("req_kgqa");
        
        try {
            // 1. 实体链接
            List<IdentifiedKnowledgePoint> identifiedKps = 
                executeWithTimeout(
                    () -> entityLinker.link(
                        request.getUserQuestion(), 
                        request.getSubject(), 
                        request.getGrade()),
                    50, 
                    List.of(), 
                    "entity_linking"
                );
            
            // 2. 前置知识检测
            PrerequisiteCheckResult prereqResult = 
                identifiedKps.isEmpty() ? PrerequisiteCheckResult.ready() :
                executeWithTimeout(
                    () -> prerequisiteChecker.check(
                        identifiedKps.get(0).getKpId(),
                        request.getMasterySnapshot(),
                        3),
                    30,
                    PrerequisiteCheckResult.ready(),
                    "prerequisite_check"
                );
            
            // 3. 图谱引导检索
            List<GraphKnowledgeContext> graphContexts = 
                identifiedKps.isEmpty() ? List.of() :
                executeWithTimeout(
                    () -> kgRagRetriever.retrieve(
                        identifiedKps.stream()
                            .map(IdentifiedKnowledgePoint::getKpId)
                            .toList(),
                        request.getSubject(),
                        request.getMaxHops()),
                    30,
                    List.of(),
                    "graph_expand"
                );
            
            // 4. 多跳推理（仅当识别到多个知识点时）
            List<ReasoningPath> reasoningPaths = List.of();
            if (identifiedKps.size() >= 2) {
                reasoningPaths = executeWithTimeout(
                    () -> reasoningEngine.findReasoningPaths(
                        identifiedKps.get(0).getKpId(),
                        identifiedKps.get(1).getKpId(),
                        request.getMaxHops(), 3),
                    25,
                    List.of(),
                    "reasoning"
                );
            }
            
            // 5. 解释路径生成
            ExplanationPath explanationPath = 
                identifiedKps.isEmpty() ? null :
                executeWithTimeout(
                    () -> explanationPathGenerator.generate(
                        identifiedKps.get(0).getKpId(),
                        request.getMasterySnapshot(),
                        request.getStage().name(),
                        request.getContextKpIds()),
                    20,
                    null,
                    "explanation_path"
                );
            
            // 6. 事实校验规则生成
            List<FactValidationRule> validationRules = 
                identifiedKps.isEmpty() ? List.of() :
                executeWithTimeout(
                    () -> factValidator.generateRules(
                        identifiedKps.stream()
                            .map(IdentifiedKnowledgePoint::getKpId)
                            .toList()),
                    15,
                    List.of(),
                    "validation_prep"
                );
            
            long elapsed = System.currentTimeMillis() - startTime;
            
            return EnhanceResponse.builder()
                .requestId(requestId)
                .identifiedKps(identifiedKps)
                .prerequisiteCheck(prereqResult)
                .graphContexts(graphContexts)
                .reasoningPaths(reasoningPaths)
                .explanationPath(explanationPath)
                .validationRules(validationRules)
                .processingTimeMs(elapsed)
                .status(EngineStatus.SUCCESS)
                .build();
            
        } catch (Exception e) {
            log.error("KGQA enhance failed, requestId={}", requestId, e);
            return EnhanceResponse.builder()
                .requestId(requestId)
                .status(EngineStatus.FAILED)
                .processingTimeMs(System.currentTimeMillis() - startTime)
                .build();
        }
    }
    
    /**
     * 带超时和降级执行的包装器
     */
    private <T> T executeWithTimeout(Supplier<T> supplier, 
                                      long timeoutMs,
                                      T fallback,
                                      String stepName) {
        try {
            CompletableFuture<T> future = CompletableFuture.supplyAsync(supplier);
            return future.get(timeoutMs, TimeUnit.MILLISECONDS);
        } catch (TimeoutException e) {
            log.warn("KGQA step '{}' timed out after {}ms, using fallback", 
                stepName, timeoutMs);
            return fallback;
        } catch (Exception e) {
            log.warn("KGQA step '{}' failed, using fallback: {}", 
                stepName, e.getMessage());
            return fallback;
        }
    }
}
```

```java
/**
 * KGQA 多级缓存
 */
@Component
@Slf4j
public class KgqaCacheManager {
    
    /** L1: 本地缓存 */
    private final Cache<String, Object> l1Cache = Caffeine.newBuilder()
        .maximumSize(10_000)
        .expireAfterWrite(Duration.ofMinutes(5))
        .recordStats()
        .build();
    
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    
    /**
     * 多级缓存读取
     */
    @SuppressWarnings("unchecked")
    public <T> T get(String key, Class<T> type, Supplier<T> loader) {
        // L1
        T cached = (T) l1Cache.getIfPresent(key);
        if (cached != null) return cached;
        
        // L2
        String json = redisTemplate.opsForValue().get(key);
        if (json != null) {
            T value = JsonUtils.parse(json, type);
            l1Cache.put(key, value);
            return value;
        }
        
        // Load
        T value = loader.get();
        if (value != null) {
            l1Cache.put(key, value);
            redisTemplate.opsForValue().set(key, JsonUtils.toJson(value), 
                Duration.ofMinutes(30));
        }
        return value;
    }
}
```

## 9. 错误处理与降级策略

### 9.1 错误分级

| 错误级别 | 触发条件 | 处理方式 | 用户影响 |
| --- | --- | --- | --- |
| WARN | 单个子步骤超时 | 降级跳过该步骤，返回已有结果 | 无感知，AI 回答质量略降 |
| ERROR | 图谱数据库不可达 | 返回空增强结果，RAG 正常工作 | 无感知，等同于无 KG 增强 |
| FATAL | 所有步骤失败 | 返回 FAILED 状态，AI 正常生成回答 | 无感知，等同于不调用本引擎 |

### 9.2 降级策略

```
降级决策树:

  图谱DB(Neo4j) 是否可用?
    ├── 否 → 跳过所有图谱功能，仅返回实体识别结果（基于字典）
    └── 是 → 执行完整流程
              
  嵌入向量服务 是否可用?
    ├── 否 → 跳过语义匹配和事实校验
    └── 是 → 执行完整流程

  Redis 是否可用?
    ├── 否 → 直连 DB 查询（性能降低，功能正常）
    └── 是 → 正常多级缓存
```

### 10.2 扩容策略

- **KGQA 服务节点**: 无状态，支持水平扩容，根据 QPS 自动伸缩
- **Neo4j**: 读多写少，通过增加只读副本提升查询吞吐
- **Redis**: 通过 Cluster 模式扩展容量和吞吐
- **嵌入向量**: 预计算并缓存知识点向量，运行时仅对学生问题做实时计算

## 11. 与 AI 对话引擎的集成

### 11.1 集成时序图

```
学生提问 → AI对话引擎
                  │
                  ├─[1] 调用 KGQA enhance()
                  │
                  │    KGQA引擎:
                  │      a) 实体链接
                  │      b) 前置检测
                  │      c) 图谱扩展检索
                  │      d) 推理路径生成
                  │      e) 解释路径生成
                  │      f) 校验规则生成
                  │
                  ├─[2] 将增强结果 + RAG检索结果组装到Prompt
                  │
                  │    Prompt结构:
                  │      [系统角色 + 教学策略]
                  │      [图谱增强上下文(知识关系)]
                  │      [RAG检索到的教材内容]
                  │      [前置知识提示]
                  │      [推理路径建议]
                  │      [学生问题]
                  │
                  ├─[3] 调用大模型生成回答
                  │
                  ├─[4] 用校验规则对回答做事后校验
                  │
                  │    如果校验失败:
                  │      a) 标记低置信度
                  │      b) 触发多模型复核
                  │      c) 或在回答后追加提示
                  │
                  └─[5] 返回最终回答给学生
```

### 11.2 Prompt 增强示例

```text
[图谱增强上下文]
本问题涉及知识点: 二次函数图像与系数关系
前置知识状态: 学生未学习'二次函数定义'(需补充)
关联知识: 
  - 二次函数的定义(前置): 形如y=ax²+bx+c(a≠0)
  - 抛物线的顶点与对称轴(相关)

[推理路径建议]
建议按以下逻辑讲解:
  1. 先明确二次函数的一般式 y=ax²+bx+c
  2. 分析a的正负对函数值变化的影响
  3. 得出结论: a>0开口向上, a<0开口向下

[事实校验约束]
回答中必须正确反映以下关系:
  - a>0 → 开口向上
  - a<0 → 开口向下

[学生问题]
为什么二次函数y=x²的图像开口向上？
```

```java
class KgqaIntegrationTest {

            .userQuestion("为什么二次函数y=x²的图像开口向上？")
```
