## 1. 模块概述

### 1.1 功能定位

PrimeTop 平台存在大量异步耗时操作：拍题解析、作文批改、学情报告生成、数据导出、资源包下载、批量导入、AI 内容生成等。当前各业务模块各自实现任务状态查询接口，导致：

1. **客户端集成碎片化**：拍题走 `/api/v1/photo-solve/task/:id`，作文走 `/api/v1/essay/task/:id`，导出走 `/api/v1/export/task/:id`，客户端需要为每种任务类型编写不同的轮询逻辑。
2. **进度推送缺失**：大多数模块仅支持 HTTP 轮询，缺少 SSE/WebSocket 实时推送，用户在等待时无法获得流畅的进度反馈。
3. **任务列表分散**：用户无法在一个地方查看"我所有正在进行的任务"。
4. **取消能力不一致**：部分模块支持取消，部分不支持，用户体验不统一。

**统一异步任务进度中心（Unified Task Progress Center，简称 UTPC）** 是面向客户端的**统一任务进度入口**，屏蔽后端各业务模块差异，为客户端提供：

| 能力 | 说明 |
|------|------|
| 统一任务注册 | 各业务模块在创建异步任务时，向 UTPC 注册任务元信息 |
| 统一进度查询 | 客户端通过单一 API `GET /api/v1/tasks/{taskId}` 查询任意任务进度 |
| 统一实时推送 | 通过 SSE/WebSocket 推送任务进度变更，客户端无需轮询 |
| 统一任务取消 | 客户端通过单一 API 取消任务，UTPC 路由到对应业务模块 |
| 统一任务列表 | 查询当前用户的所有进行中/已完成任务 |

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 零侵入接入 | 业务模块通过 SDK 一行代码注册任务，不改原有执行逻辑 |
| 实时性 | 任务状态变更后 ≤ 2 秒内推送到客户端 |
| 一致性 | 同一任务在所有端的进度展示一致 |
| 可扩展 | 新增异步任务类型时，业务模块自行注册，UTPC 无需修改代码 |
| 高可用 | UTPC 故障不影响任务执行，仅影响进度展示（降级为轮询） |

### 1.3 适用范围

本服务管理**用户可感知的异步任务**，即用户发起的、需要等待结果的操作。不包括系统内部的异步处理（如数据同步、缓存刷新等）。

| 典型任务类型 | 来源模块 | 预计耗时 |
|-------------|---------|---------|
| 拍题解析 | 拍照搜题 | 3-15 秒 |
| 作文批改 | 作文辅导 | 10-60 秒 |
| AI 内容生成 | 教育内容生成 | 30-300 秒 |
| 学情报告生成 | 学习报告 | 10-60 秒 |
| 数据导出 | 数据导出中心 | 10-120 秒 |
| 错题 PDF 导出 | 错题打印 | 5-30 秒 |
| 资源包下载 | 资源包管理 | 10-300 秒 |
| 批量导入 | 通用导入服务 | 30-600 秒 |
| 试卷扫描识别 | 试卷扫描 | 10-60 秒 |
| 手写批改 | 手写批改引擎 | 5-30 秒 |

### 2.2 核心设计原则

1. **注册制，非侵入**：业务模块通过 `TaskRegistry.register()` 注册任务，UTPC 不执行任务，只追踪进度。
2. **事件驱动更新**：业务模块通过发布标准事件更新进度，UTPC 监听事件并维护状态。
3. **降级友好**：SSE/WebSocket 不可用时，客户端自动降级为 HTTP 轮询。
4. ** TTL 自动清理**：任务记录有生命周期，完成后保留一定时间供查询，超期自动归档。

### 3.3 Redis 缓存结构

```

# SSE 订阅通道
utpc:sse:{userId} → Pub/Sub channel

# 任务类型注册表
utpc:types → Hash {taskType → JSON({name, icon, defaultEstimatedSeconds, cancellable, resultDisplay})}
```

## 4. API 接口设计

```
GET /api/v1/tasks/{taskId}
```

**权限**: 任务发起人本人或其绑定的家长

**响应**: 任务详情（见 3.5）

**说明**: 客户端轮询或 SSE 断开时的兜底查询。正常流程下应通过 SSE 接收推送。

### 4.4 取消任务

```
POST /api/v1/tasks/{taskId}/cancel
```

**请求体**:

```json
{
    "reason": "user_manual"
}
```

**响应**:

```json
{
    "code": 0,
    "data": {
        "taskId": "utpc_a1b2c3d4e5f6",
        "status": "cancelled",
        "cancelledAt": "2026-08-09T10:30:10.000+08:00"
    }
}
```

**说明**: UTPC 先将任务标记为 `cancelled`，然后调用业务模块注册的取消回调。如果业务模块取消失败，UTPC 回滚状态。取消是**尽力而为**的——任务可能已经完成。

**错误码**:

| 错误码 | HTTP | 说明 |
|--------|------|------|
| TASK_001 | 404 | 任务不存在 |
| TASK_002 | 403 | 无权操作（非任务发起人） |
| TASK_003 | 409 | 任务已终态（succeeded/failed/cancelled），不可取消 |
| TASK_004 | 409 | 该任务类型不支持取消（`cancellable=false`） |
| TASK_005 | 500 | 业务模块取消失败 |

### 4.5 订阅任务进度推送（SSE）

```
GET /api/v1/tasks/stream
Accept: text/event-stream
```

**说明**: 建立 SSE 长连接，接收当前用户所有任务的进度推送。客户端只需维护一个 SSE 连接，无需为每个任务单独订阅。

**推送事件格式**:

```
event: progress
data: {"taskId":"utpc_a1b2c3d4e5f6","status":"running","progress":45,"progressMessage":"AI正在分析解题步骤...","timestamp":"2026-08-09T10:30:05.000+08:00"}

event: progress
data: {"taskId":"utpc_a1b2c3d4e5f6","status":"running","progress":80,"progressMessage":"正在生成解析...","timestamp":"2026-08-09T10:30:10.000+08:00"}

event: completed
data: {"taskId":"utpc_a1b2c3d4e5f6","status":"succeeded","progress":100,"progressMessage":"解析完成","result":{"type":"json","data":{...}},"completedAt":"2026-08-09T10:30:14.000+08:00","timestamp":"2026-08-09T10:30:14.000+08:00"}

event: failed
data: {"taskId":"utpc_a1b2c3d4e5f6","status":"failed","progress":60,"errorCode":"AI_TIMEOUT","errorMessage":"AI服务响应超时，请重试","timestamp":"2026-08-09T10:30:20.000+08:00"}

event: created
data: {"taskId":"utpc_a7b8c9d0","taskType":"essay_grade","taskTypeName":"作文批改","status":"pending","progress":0,"timestamp":"2026-08-09T10:31:00.000+08:00"}
```

**事件类型**:

| 事件 | 触发时机 | 客户端动作 |
|------|---------|-----------|
| `created` | 新任务注册 | 显示任务浮窗 |
| `progress` | 进度更新 | 更新进度条 |
| `completed` | 任务成功完成 | 展示完成态 + 结果入口 |
| `failed` | 任务失败 | 展示失败态 + 重试按钮 |

```python
class TaskEventConsumer:
    """监听任务事件，更新UTPC状态，推送到客户端"""
    
    def handle_progress_event(self, event: TaskProgressEvent):
        """处理进度更新事件"""
        # 1. 更新 Redis 缓存
        redis.hset(f"utpc:task:{event.task_id}", mapping={
            "progress": event.progress,
            "progressMessage": event.message,
            "status": event.status
        })
        
        # 2. 异步写入 MySQL（批量延迟写入，减少DB压力）
        self.progress_buffer.append(event)
        
        # 3. 通过 SSE 推送到客户端
        redis.publish(f"utpc:sse:{event.user_id}", json.dumps({
            "event": "progress",
            "data": {
                "taskId": event.task_id,
                "status": event.status,
                "progress": event.progress,
                "progressMessage": event.message,
                "timestamp": event.timestamp.isoformat()
            }
        }))
    
    def handle_completed_event(self, event: TaskCompletedEvent):
        """处理任务完成事件"""
        # 1. 更新 Redis
        redis.hset(f"utpc:task:{event.task_id}", mapping={
            "status": event.status,
            "progress": 100 if event.status == "succeeded" else redis.hget(...),
            "resultType": event.result_type,
            "resultData": json.dumps(event.result_data),
            "completedAt": event.timestamp.isoformat()
        })
        
        # 2. 更新 MySQL
        update_task_in_db(event)
        
        # 3. 从活跃任务列表移除
        redis.srem(f"utpc:user:{event.user_id}:active", event.task_id)
        
        # 4. SSE 推送
        event_type = "completed" if event.status == "succeeded" else "failed"
        redis.publish(f"utpc:sse:{event.user_id}", json.dumps({
            "event": event_type,
            "data": {...}
        }))
        
        # 5. 如果任务完成后有结果文件URL，设置过期清理任务
        if event.result_url:
            schedule_url_cleanup(event.task_id, event.result_expire_at)
```

### 5.4 SSE 连接管理与降级策略

```dart
// 客户端 TaskProgressManager (Flutter)

class TaskProgressManager {
  /// 启动任务进度监听
  /// 优先使用 SSE，失败降级为轮询
  Stream<TaskEvent> subscribe() async* {
    try {
      // 尝试 SSE
      yield* _connectSSE();
    } catch (e) {
      // 降级为轮询
      yield* _polling();
    }
  }
  
  Stream<TaskEvent> _connectSSE() async* {
    final client = http.Client();
    final request = http.Request('GET', Uri.parse('$baseUrl/api/v1/tasks/stream'));
    request.headers['Accept'] = 'text/event-stream';
    request.headers['Authorization'] = 'Bearer $token';
    
    final response = await client.send(request);
    if (response.statusCode != 200) {
      throw Exception('SSE connection failed');
    }
    
    _sseConnected = true;
    
    await for (final chunk in response.stream.transform(utf8.decoder).transform(_sseParser)) {
      final event = TaskEvent.fromJson(chunk);
      if (event.type == 'heartbeat') continue;
      yield event;
    }
    
    // SSE 断开，自动降级为轮询
    _sseConnected = false;
    yield* _polling();
  }
  
  /// 轮询降级：每2秒查询一次活跃任务
  Stream<TaskEvent> _polling() async* {
    while (true) {
      try {
        final active = await api.get('/tasks/active');
        for (final task in active.items) {
          yield TaskEvent.fromTask(task);
        }
      } catch (e) {
        // 网络错误时降低频率
      }
      await Future.delayed(Duration(seconds: _sseConnected ? 0 : 2));
    }
  }
}
```

## 6. 业务模块接入规范

### 6.1 接入步骤

业务模块接入 UTPC 需要完成以下步骤：

1. **注册任务类型**（首次接入时）：在 UTPC 管理后台注册任务类型，声明 `cancellable`、`estimatedSeconds` 等。
2. **创建任务时调用注册 API**：创建 Celery 任务时，同步调用 `POST /api/internal/tasks` 注册到 UTPC。
3. **执行过程中更新进度**：在 Celery 任务的关键步骤发布 `TaskProgressEvent`。
4. **完成时上报结果**：任务完成时发布 `TaskCompletedEvent`。
5. **（可选）注册取消回调**：如果任务支持取消，提供取消回调 URL。

## 8. SSE 推送引擎设计

### 8.1 连接管理

```java
@Service
public class SSEConnectionManager {
    
    private final ConcurrentHashMap<Long, SseEmitter> userEmitters = new ConcurrentHashMap<>();
    private final RedisMessageListenerContainer redisListenerContainer;
    
    private static final long SSE_TIMEOUT = 5 * 60 * 1000L; // 5分钟超时
    
    /**
     * 为用户创建 SSE 连接
     */
    public SseEmitter createConnection(Long userId) {
        SseEmitter emitter = new SseEmitter(SSE_TIMEOUT);
        
        userEmitters.put(userId, emitter);
        
        emitter.onCompletion(() -> userEmitters.remove(userId, emitter));
        emitter.onTimeout(() -> {
            userEmitters.remove(userId, emitter);
            emitter.complete();
        });
        emitter.onError(e -> userEmitters.remove(userId, emitter));
        
        // 订阅 Redis Pub/Sub
        subscribeToUserChannel(userId);
        
        // 发送初始事件（当前活跃任务快照）
        sendInitialSnapshot(userId, emitter);
        
        // 启动心跳
        startHeartbeat(userId, emitter);
        
        return emitter;
    }
    
    /**
     * 从 Redis Pub/Sub 接收消息并推送到 SSE
     */
    private void onRedisMessage(Long userId, String message) {
        SseEmitter emitter = userEmitters.get(userId);
        if (emitter == null) return;
        
        try {
            JSONObject msg = new JSONObject(message);
            String eventType = msg.getString("event");
            String data = msg.getJSONObject("data").toString();
            
            emitter.send(SseEmitter.event()
                .name(eventType)
                .data(data)
                .id(String.valueOf(System.currentTimeMillis()))
            );
        } catch (Exception e) {
            log.warn("SSE推送失败, userId={}", userId, e);
            userEmitters.remove(userId, emitter);
        }
    }
    
    /**
     * 心跳定时任务
     */
    @Scheduled(fixedRate = 15000)
    public void sendHeartbeat() {
        userEmitters.forEach((userId, emitter) -> {
            try {
                emitter.send(SseEmitter.event()
                    .name("heartbeat")
                    .data("ping")
                );
            } catch (Exception e) {
```

### 8.2 推送可靠性保障

由于 SSE 是"至少一次"推送（可能因网络断连而丢失消息），需要以下保障：

1. **断线重连 + 状态同步**：客户端重连后，先调用 `GET /tasks/active` 获取最新状态快照，再继续接收 SSE。
2. **序号检测**：每个事件携带 `timestamp`，客户端若发现 timestamp 回退或跳跃，触发一次全量同步。
3. **终态保证**：任务进入终态（succeeded/failed/cancelled）时，除了 SSE 推送，还额外通过 **APP 推送通知** 确保用户感知。

```dart
// 客户端 SSE 重连与状态同步
class SSEReconnectHandler {
  DateTime? _lastEventTime;
  
  void onReconnect() async {
    // 1. 获取活跃任务快照
    final active = await api.get('/tasks/active');
    
    // 2. 对比本地状态，补齐缺失更新
    for (final task in active.items) {
      final localTask = _localTasks[task.taskId];
      if (localTask == null || localTask.status != task.status) {
        // 本地状态与服务端不一致，以服务端为准
        _emitEvent(TaskSyncEvent(task));
      }
    }
    
    // 3. 继续接收 SSE
    _resumeSSE();
  }
}
```

## 9. 进度预估算法

### 9.1 基于历史数据的预估

对于未上报中间进度的任务，UTPC 提供基于历史数据的**虚拟进度**：

```python
class ProgressEstimator:
    """基于历史数据估算任务进度"""
    
    async def estimate_progress(self, task: UnifiedTask) -> int:
        """返回估算进度 0-100"""
        if task.progress > 0:
            # 已有真实进度，不覆盖
            return task.progress
        
        if not task.started_at:
            return 0
        
        elapsed = (datetime.now() - task.started_at).total_seconds()
        
        # 从 Redis 获取该任务类型的历史平均耗时
        avg_key = f"utpc:avg_duration:{task.task_type}"
        avg_duration = await redis.get(avg_key)
        
        if avg_duration:
            estimated = int((elapsed / float(avg_duration)) * 100)
            return min(99, max(0, estimated))  # 不超过99%（未确认完成）
        else:
            # 无历史数据，使用默认预估
            if task.estimated_seconds:
                ratio = elapsed / task.estimated_seconds
                if ratio < 0.3:
                    return int(ratio * 33)
                elif ratio < 0.7:
                    return 33 + int((ratio - 0.3) * 33 / 0.4)
                else:
                    return 66 + min(33, int((ratio - 0.7) * 33 / 0.3))
            return 50  # 默认50%
    
    async def update_average_duration(self, task_type: str, actual_seconds: float):
        """任务完成后更新历史平均耗时"""
        key = f"utpc:avg_duration:{task_type}"
        # 使用滑动平均
        old_avg = await redis.get(key)
        if old_avg:
            new_avg = float(old_avg) * 0.8 + actual_seconds * 0.2
        else:
            new_avg = actual_seconds
        await redis.set(key, str(new_avg))
```

```dart
class SmoothProgress {
  double _displayed = 0;
  double _target = 0;
  Timer? _timer;
  
  void update(int targetProgress) {
    _target = targetProgress.toDouble();
    _startAnimationIfNeeded();
  }

    _timer?.cancel();
    _timer = Timer.periodic(Duration(milliseconds: 50), (timer) {
      final diff = _target - _displayed;
      if (diff.abs() < 0.5) {
        _displayed = _target;
        timer.cancel();

        _displayed += step;
      }
      notifyListeners();
    });
  }

}
```

## 11. 性能优化

### 11.1 写入优化

| 场景 | 策略 |

```python
class ProgressWriter:
    """延迟批量写入 MySQL"""
    
    _buffer: list[ProgressLog] = []
    _flush_lock = asyncio.Lock()
    
    async def buffer(self, log_entry: ProgressLog):
        """缓冲写入"""
        _buffer.append(log_entry)
        if len(_buffer) >= 100:
            await self._flush()
    
    @Scheduled(fixed_delay=5000)  # 每5秒flush
    async def _flush(self):
        async with self._flush_lock:
            if not _buffer:
                return
            batch = _buffer[:]
            _buffer.clear()
            
            # 批量插入
            values = [(log.task_id, log.progress, log.message, log.status, log.created_at) 
                      for log in batch]
            await db.executemany("""
                INSERT INTO unified_task_progress_log 
                (task_id, progress, message, status, created_at) 
                VALUES (%s, %s, %s, %s, %s)
            """, values)
```
