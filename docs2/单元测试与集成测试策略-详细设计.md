# 单元测试与集成测试策略-详细设计

## 1. 概述

### 1.1 目标

为 PrimeTop 全学段 AI 辅助学习软件建立完整的测试体系，确保代码质量、系统稳定性和业务正确性。本设计涵盖了单元测试、集成测试、端到端测试的完整策略，包括测试框架选择、测试覆盖率要求、Mock 策略、测试数据管理、CI/CD 集成等。

### 1.2 适用范围

- 服务端：Node.js/TypeScript 业务服务
- 客户端：Flutter 移动应用
- AI 能力层：Prompt 测试、RAG 测试
- 数据层：数据库访问、缓存测试

### 1.3 测试金字塔

```
        /\
       /E2E\        端到端测试 (5-10%)
      /------\
     /集成测试\      集成测试 (15-20%)
    /----------\
   /  单元测试  \    单元测试 (70-80%)
  /______________\
```

- **单元测试**：测试最小可测试单元（函数、类、组件），独立运行，快速反馈
- **集成测试**：测试模块间交互、API 接口、数据库访问等
- **端到端测试**：测试完整用户流程，模拟真实用户操作

## 2. 服务端单元测试策略

### 2.1 测试框架选择

#### 2.1.1 测试运行器

| 框架 | 选择 | 理由 |
|------|------|------|
| Jest | ✅ 推荐使用 | 零配置、内置断言、Mock、覆盖率报告、快照测试 |
| Mocha | ❌ 不推荐 | 需要额外配置断言库、Mock 库 |
| Vitest | 🟐 可选 | Vite 生态，性能更优，但生态成熟度不如 Jest |

**配置示例**：`jest.config.js`

```javascript
module.exports = {
  preset: 'ts-jest',
  testEnvironment: 'node',
  roots: ['<rootDir>/src'],
  testMatch: ['**/__tests__/**/*.ts', '**/?(*.)+(spec|test).ts'],
  collectCoverageFrom: [
    'src/**/*.ts',
    '!src/**/*.d.ts',
    '!src/types/**',
    '!src/migrations/**',
    '!src/config/**',
  ],
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 80,
      lines: 80,
      statements: 80,
    },
  },
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/src/$1',
  },
  setupFilesAfterEnv: ['<rootDir>/tests/setup.ts'],
};
```

import { PrismaClient } from '@prisma/client';

export class TestDatabase {
  private prisma: PrismaClient;

  constructor() {
    this.prisma = new PrismaClient({
      datasources: {
        db: {
          url: process.env.TEST_DATABASE_URL || 'postgresql://localhost:5432/primetop_test',
        },
      },
    });
  }

  async cleanup() {
    // 清理所有表数据，保留 schema
    const tables = await this.prisma.$queryRaw<TableInfo[]>`
      SELECT tablename FROM pg_tables WHERE schemaname = 'public'
    `;

    for (const table of tables) {
      await this.prisma.$executeRawUnsafe(`TRUNCATE TABLE "${table.tablename}" CASCADE`);
    }
  }

  async disconnect() {
    await this.prisma.$disconnect();
  }

  getClient() {
    return this.prisma;
  }
}

interface TableInfo {
  tablename: string;
}

#### 3.1.2 测试场景覆盖

每个 API 端点应覆盖以下场景：

1. **正常场景**
   - 正确参数返回预期结果
   - 列表查询的分页、排序、过滤

2. **错误场景**
   - 参数验证失败（400）
   - 未授权访问（401）
   - 权限不足（403）
   - 资源不存在（404）
   - 服务器错误（500）

3. **边界条件**
   - 空列表
   - 单个元素
   - 大数据量（分页）
   - 特殊字符

```typescript
// tests/integration/user-repository.integration.ts
import { UserRepository } from '../../src/repositories/userRepository';
import { TestDatabase } from '../helpers/testDatabase';

describe('UserRepository Integration Tests', () => {
  let userRepository: UserRepository;
  let testDb: TestDatabase;

  beforeEach(async () => {
    testDb = new TestDatabase();
    await testDb.cleanup();
    userRepository = new UserRepository(testDb.getClient());
  });

  afterEach(async () => {
    await testDb.cleanup();
  });

  describe('create', () => {
    it('should create user in database', async () => {
      const userData = {
        id: 'test-1',
        name: 'Test User',
        grade: '5',
      };

      const user = await userRepository.create(userData);

      expect(user).toMatchObject(userData);

      // 验证数据已写入数据库
      const found = await testDb.getClient().user.findUnique({
        where: { id: userData.id },
      });
      expect(found).toMatchObject(userData);
    });
  });

  describe('transaction', () => {
    it('should rollback on error', async () => {
      try {
        await testDb.getClient().$transaction(async (tx) => {
          await tx.user.create({
            data: { id: 'test-1', name: 'User 1', grade: '5' },
          });
          await tx.user.create({
            data: { id: 'test-1', name: 'User 2', grade: '6' }, // 重复 ID
          });
        });
      } catch (error) {
        // 预期会抛出错误
      }

      // 验证事务已回滚，没有数据被写入
      const count = await testDb.getClient().user.count();
      expect(count).toBe(0);
    });
  });
});
```

### 13.3 常见问题

**Q: 测试运行太慢怎么办？**
A: 1. 减少集成测试数量；2. 使用 Jest 的 `--maxWorkers` 限制并发；3. 优化数据库查询；4. 考虑测试并行化。

**Q: 如何测试异步代码？**
A: 使用 `async/await` 或 Promise 链，Jest 会自动等待 Promise 完成。不要忘记 `await`。

**Q: Mock 不生效怎么办？**
A: 1. 检查 Mock 是否在测试执行前设置；2. 确认 Mock 路径正确；3. 使用 `jest.mock` 在文件顶部声明。

**Q: 测试覆盖率不准确怎么办？**
A: 1. 排除不需要测试的文件（类型定义、配置文件）；2. 检查 coverageThreshold 配置；3. 查看覆盖率报告详情。
