# 服务端-纸质答题卡拍照识别与客观题自动阅卷评分引擎-详细设计

## 1. 概述

### 1.1 功能定位

本模块为 PrimeTop 提供**纸质答题卡数字化判分**能力。学生或教师在考试结束后，通过 APP 拍照上传纸质答题卡，系统自动完成：

1. 答题卡模板识别与匹配（定位点检测 + 二维码锚点）
2. 图像预处理（透视矫正、去阴影、二值化）
3. 填涂区块识别（客观题选项填涂检测）
4. 学号/考号填涂识别（教师批量场景的学生身份绑定）
5. 与标准答案自动比对判分（含多选、漏选、缺考等策略）
6. 成绩单生成与错题自动归档
7. 低置信度结果转人工复核

与相邻模块的边界：

| 维度 | 本模块（答题卡阅卷） | 试卷扫描归档引擎（已有） | 智能作业批改引擎（已有） | 多题型统一判题引擎（已有） |
|------|---------------------|------------------------|------------------------|--------------------------|
| 输入 | **未批改**纸质答题卡照片 | **已批改**纸质试卷照片 | 教师发布的线上/拍照作业 | App 内在线作答答案 |
| 判分主体 | **本系统自动判分** | 老师已判，仅提取分数与错题 | AI 批改主观题为主 | 在线答题实时判题 |
| 核心技术 | 填涂识别（CV）+ 模板匹配 | 版面分析 + OCR + 批改痕迹识别 | LLM 评阅 | 规则/相似度判题 |
| 输出 | 成绩 + 答题明细 + 错题归档 | 错题归档 + 试卷报告 | 批改结果 + 评语 | 判题结果 |
| 典型场景 | 考完试当天学生自查对答案；教师收卡后批量阅客观题 | 试卷发下来后整理归档 | 日常作业批改 | 在线练习 |

> 关键区别：`试卷扫描归档` 处理的是"老师已经改完、有红笔分数"的试卷；本模块处理的是"还没人改"的答题卡，由系统给出分数。两者在错题归档环节汇合。

### 1.2 适用场景

| 场景 | 触发者 | 流程形态 | 说明 |
|------|--------|---------|------|
| S1 学生自查 | 学生本人 | 单张拍照 → 自动判分 → 成绩+错题 | 考完试当天，标准答案由平台提供或教师提前发布 |
| S2 教师批量阅卷 | 教师 | 批量拍照/扫描 → 学号识别 → 班级成绩单 | 客观题全自动化，主观题留白给教师在批改工作台处理 |
| S3 对答案轻量模式 | 学生本人 | 无答题卡时在 App 内逐题输入自己的答案 → 判分 | 无卡降级路径，不涉及 CV |

### 1.3 学段与学科范围

- **学段**：小学三年级以上至高中（低学段客观题量少，优先级低）
- **学科**：全学科。英语（听力/单选/完形）、文综理综选择题密集学科收益最大
- **题型**：单选题、多选题（含漏选给分策略）、判断题（映射为两选项单选）
- **不适用**：主观题作答区（作文、解答题）——识别为"留空"并引导至教师批改或试卷扫描归档模块

### 1.4 核心价值

1. **考试当天闭环**：考完即对答案，错题趁热进入错题本，不必等老师批改下发
2. **教师减负**：一个 50 人班级的客观题阅卷从 ~40 分钟压缩到 ~5 分钟
3. **线下考试数据资产化**：为学情分析、学校考试成绩管理服务补全"考试级"结构化数据

## 3. 答题卡模板体系设计

### 3.1 设计思路

答题卡判分的前提是"知道每个填涂格在页面上的理论坐标"。坐标必须与分辨率无关，因此采用**归一化坐标系（0~1）**：以卡面左上角定位点为原点、右下角定位点为 (1,1) 的仿射参照系。识别时通过 4 个定位点将拍摄图像透视变换回标准平面，即可用模板坐标直接定位每个格子。

平台维护两级模板：

1. **平台标准卡（P 系）**：PrimeTop 出品的通用答题卡，教师可直接打印使用，模板内置；
2. **自定义卡（C 系）**：教师/学校使用自己的答题卡时，通过"模板制作工具"（拍照 → 自动检测格阵 → 人工校正 → 关联题目）生成，需审核后生效。

### 3.4 模板匹配策略

拍摄图像如何确定用哪个模板：

```
1. 解码卡面二维码 → 直接得到 templateCode（置信路径，覆盖平台标准卡）
2. QR 解码失败：
   a. 定位点几何检测 → 得到格阵布局指纹（列数/题数/选项数/格距比）
   b. 在模板库中检索布局指纹最接近的自定义卡（教师上传时已生成指纹）
   c. 相似度 ≥ 0.97 → 自动匹配；< 0.97 → 转人工选择模板（给出 Top3 候选）
3. 用户在创建任务时可显式指定 templateId（优先级最高）
```

## 5. CV 识别管线详细设计

### 5.1 管线阶段与耗时预算（单页 A4，中端手机拍摄）

| 阶段 | 内容 | 预算 (P95) |
|------|------|-----------|
| P0 图像质检 | 分辨率/模糊度/亮度/倾斜角粗判 | 300ms（客户端本地已预检，服务端复核） |
| P1 预处理 | 灰度化、光照归一化、自适应二值化 | 400ms |
| P2 定位与矫正 | 定位点检测、透视变换 | 600ms |
| P3 模板匹配 | QR 解码 / 布局指纹检索 | 300ms |
| P4 格子提取与填涂判定 | 全部 option cell 逐格分析 | 1200ms |
| P5 学号识别 | 数字格阵填涂 → 考号串 | 300ms |
| P6 置信度汇总 | 单格/单题/整卡三级置信度 | 100ms |
| 合计 | | ≤ 3.5s（不含排队）+ 判分 50ms |

### 5.2 图像质检标准（P0）

| 检查项 | 阈值 | 不达标处理 |
|--------|------|-----------|
| 短边分辨率 | ≥ 1000px | 拒绝，`IMG_TOO_SMALL` |
| 拉普拉斯方差（模糊度） | ≥ 100 | 拒绝，`IMG_TOO_BLURRY` |
| 平均亮度 | 60~220 | 拒绝，`IMG_BAD_LIGHT` |
| 过曝面积占比 | ≤ 15%（光斑会吞掉填涂） | 拒绝，`IMG_GLARE` |
| 倾斜角 | ≤ 30°（可矫正范围） | 拒绝，`IMG_TOO_SKEW` |

客户端在拍摄时实时执行同规则预检并引导重拍（接口契约见 §8.6），服务端复核兜底。

### 5.3 定位点检测与透视矫正（P2）

```python
# cv_worker/geometry.py
import cv2
import numpy as np

def detect_anchors_and_warp(binary: np.ndarray, gray: np.ndarray):
    """检测四角实心黑方块定位点，透视矫正到标准平面。
    返回: warped(二值图), H(变换矩阵), anchor_pts(原图四点)
    """
    contours, _ = cv2.findContours(binary, cv2.RETR_EXTERNAL,
                                   cv2.CHAIN_APPROX_SIMPLE)
    h, w = gray.shape
    candidates = []
    for cnt in contours:
        x, y, cw, ch = cv2.boundingRect(cnt)
        area = cw * ch
        fill = cv2.contourArea(cnt) / max(area, 1)
        # 黑方块: 面积适中 + 矩形度高 + 长宽比接近1
        if not (0.0015 * w * h < area < 0.02 * w * h):
            continue
        if fill < 0.85 or not (0.7 < cw / max(ch, 1) < 1.4):
            continue
        candidates.append((x, y, x + cw, y + ch))

    # 按象限归类取最角落者
    quadrants = {q: None for q in range(4)}
    for (x0, y0, x1, y1) in candidates:
        cx, cy = (x0 + x1) / 2, (y0 + y1) / 2
        q = (2 if cx > w / 2 else 0) + (1 if cy > h / 2 else 0)
        key = (cx if q < 2 else w - cx) + (cy if q % 2 == 0 else h - cy)
        # 距角点距离最近者胜出
        dist = min(cx, w - cx) + min(cy, h - cy)
        if quadrants[q] is None or dist < quadrants[q][0]:
            quadrants[q] = (dist, (x0, y0, x1, y1))

    if any(v is None for v in quadrants.values()):
        raise AnchorNotFoundError("anchors missing in quadrant(s)")

    pts_src = np.float32([quadrants[i][1] for i in
                          [0, 1, 2, 3]])  # TL, BL, TR, BR
    SIDE = 2000  # 标准平面边长，模板归一化坐标 * SIDE = 像素坐标
    pts_dst = np.float32([[0, 0], [0, SIDE], [SIDE, 0], [SIDE, SIDE]])
    H, _ = cv2.findHomography(pts_src, pts_dst, cv2.RANSAC, 5.0)
    warped = cv2.warpPerspective(binary, H, (SIDE, SIDE))
    return warped, H, pts_src
```

工程要点：

1. `SIDE=2000` 是全链路统一的**标准平面分辨率**，模板坐标 × SIDE 即像素坐标，杜绝二次换算误差；
2. 象限归类 + 取距角最近者，可抵御卡面上其他黑色图形（题号黑块、条码）的干扰；
3. 若 4 点只找到 3 点，用第四点几何预测（矩形约束）补齐并降低置信度，进入复核而非直接失败。

### 5.4 填涂判定算法（P4）

核心思想：对模板定位出的每个 option cell，计算**墨迹面积占比（fill ratio）**，结合双阈值滞回与邻格相对比较判定"涂/未涂"。

```python
# cv_worker/fill_detect.py
import numpy as np

FILL_HIGH = 0.55   # ≥ 视为确定涂黑
FILL_LOW  = 0.38   # ≤ 视为确定未涂；中间为可疑带

def judge_cell(warped: np.ndarray, cell_rect: tuple, side: int = 2000):
    """cell_rect: (x0, y0, w, h) 归一化; 返回 (fill_ratio, ink_std)"""
    x0 = int(cell_rect[0] * side); y0 = int(cell_rect[1] * side)
    w  = int(cell_rect[2] * side); h  = int(cell_rect[3] * side)
    # 内缩 15%，规避格线与相邻格渗墨
    pad_x, pad_y = int(w * 0.15), int(h * 0.15)
    roi = warped[y0 + pad_y: y0 + y0*0 + h - pad_y,
                 x0 + pad_x: x0 + w - pad_x]
    if roi.size == 0:
        raise CellROIsEmpty(cell_rect)
    fill = float((roi < 128).mean())          # 二值图中黑像素占比
    ink_std = float(roi.std())                # 墨迹分布均匀度
    return fill, ink_std


def classify_question(cells: list[dict]) -> dict:
    """cells: [{option:'A', fill:0.72, std:...}, ...] → 该题判定结果"""
    fills = np.array([c["fill"] for c in cells])
    marked, suspicious = [], []
    for c in cells:
        if c["fill"] >= FILL_HIGH:
            marked.append(c["option"])
        elif c["fill"] > FILL_LOW:
            suspicious.append(c["option"])     # 可疑带，待滞回判定
    # 滞回规则: 可疑格与同题最高 fill 差 < 0.12 且 > 其余格 0.15 → 认为涂
    for opt in suspicious:
        c = next(x for x in cells if x["option"] == opt)
        if fills.max() - c["fill"] < 0.12:
            marked.append(opt)
    # 多涂检测: 单选题 marked > 1 → 冲突
    return {
        "marked": sorted(marked),
        "conflict": len(marked) > 1,           # 由判分层结合题型决定是否真冲突
        "allBlank": len(marked) == 0 and len(suspicious) == 0,
        "suspiciousOptions": suspicious,
    }
```

关键工程细节：

| 问题 | 对策 |
|------|------|
| 2B 与 HB 铅笔浓度差异 | fill 阈值经标注集分学段校准；可疑带宽 (0.38~0.55) 覆盖浅涂 |
| 橡皮擦不干净（灰影） | 擦除残迹通常 fill ∈ 0.15~0.35 且 `ink_std` 高（斑驳），低于 FILL_LOW 不判涂；落在可疑带则标可疑 |
| 打钩/画圈代替填涂 | 形状特征：填涂墨迹连通域外接矩形占格比 > 0.7 判涂；打钩 < 0.4，标可疑引导自校对 |
| 相邻格渗墨/格线残留 | ROI 内缩 15% |
| 折痕/污渍落在格内 | 与邻格 fill 分布对比：孤立异常格若 `ink_std` 极低（均匀大片黑）且边缘锐利度低，标可疑 |

### 5.5 学号填涂识别（P5）

按 `studentIdRegion` 定义逐位识别 0-9 格，每位取 fill 最高者；若某位最高与次高差距 < 0.1（并涂两位）或全部 < FILL_LOW（漏涂某位），整个学号标记不可靠 → 教师场景进"身份待指派"，学生自查场景弹窗手输考号。

### 5.6 置信度体系（P6）

三级置信度，任一环节低置信即进入对应复核路径：

| 级别 | 定义 | 低置信阈值 | 低置信动作 |
|------|------|-----------|-----------|
| Cell 级 | 单格 fill 落入可疑带 | 0.38~0.55 | App 内高亮该格让学生确认 |
| Question 级 | 单题存在可疑格或多涂 | 可疑格 ≥ 1 | 题目级卡片式确认 |
| Sheet 级 | 全卡可疑题占比 / 定位补点 / 模板匹配度 < 0.97 | 可疑题 > 8% 或匹配度低 | 整卡进复核工作台（教师场景）/ 全卡自校对页（学生场景） |

置信度计算：

```java
// grading-core: SheetConfidence.java
public double sheetConfidence(RecognitionResult r) {
    double cellScore = 1.0 - (double) r.getSuspiciousCellCount()
                            / Math.max(r.getTotalCellCount(), 1);
    double anchorScore = r.isAnchorPredicted() ? 0.85 : 1.0; // 定位点被补齐
    double templateScore = r.getTemplateMatchScore();         // 0~1
    return 0.5 * cellScore + 0.2 * anchorScore + 0.3 * templateScore;
}
```

## 6. 判分引擎设计

### 6.1 给分策略

| 题型/情形 | 策略 | 规则编码 |
|-----------|------|---------|
| 单选-涂对 | 得满分 | `SINGLE_CORRECT` |
| 单选-涂错 | 0 分 | `SINGLE_WRONG` |
| 单选-未涂 | 0 分，标记 `BLANK` | `SINGLE_BLANK` |
| 单选-检测到多涂 | 默认 0 分 + 复核提示（可能识别误差） | `SINGLE_MULTI_MARK` |
| 多选-全对 | 得满分 | `MULTI_CORRECT` |
| 多选-漏选无错选 | 按 partialPolicy：`MISS_ONE_HALF`(漏一个得一半)/`HALF_PER_MISS`(每漏一个减半)/`NO_PARTIAL`(0分) | `MULTI_PARTIAL` |
| 多选-有错选 | 0 分 | `MULTI_WRONG` |
| 答案为 null（争议题） | 跳过，不计入总分与统计 | `SKIPPED_DISPUTED` |
| 缺考标记 | 全卡 0 分 + `ABSENT` 状态，不产生错题 | `ABSENT` |

策略以 `partialPolicy` 挂在 answerKey 条目上，默认 `NO_PARTIAL`，教师发布答案时可改。

### 6.2 判分核心代码

```java
// grading-core/GradingEngine.java
public class GradingEngine {

    public GradeResult grade(RecognitionResult recog, ExamAnswerKey key) {
        GradeResult result = new GradeResult(recog.getTaskId());
        for (AnswerEntry entry : key.getEntries()) {
            QuestionMark mark = recog.getQuestionMark(entry.getQuestionNo())
                    .orElse(QuestionMark.unanswered(entry.getQuestionNo()));

            QuestionOutcome outcome = judgeOne(mark, entry);
            result.add(outcome);
        }
        result.finalize(
            /* totalScore 按未跳过题聚合 */,
            /* objectiveFullScore 争议题剔除 */);
        return result;
    }

    private QuestionOutcome judgeOne(QuestionMark mark, AnswerEntry entry) {
        if (entry.getAnswer() == null) {                    // 争议题
            return QuestionOutcome.skipped(mark, entry, "SKIPPED_DISPUTED");
        }
        Set<String> marked = mark.getMarked();
        if (marked.isEmpty()) {
            return QuestionOutcome.scored(mark, entry, 0, false,
                    mark.isSuspicious() ? Flag.BLANK_SUSPICIOUS : Flag.BLANK);
        }
        if (entry.isSingle()) {
            boolean correct = marked.size() == 1
                    && marked.contains(entry.getSingleAnswer());
            if (marked.size() > 1) {                        // 多涂：先复核
                return QuestionOutcome.needReview(mark, entry,
                        "SINGLE_MULTI_MARK");
            }
            return QuestionOutcome.scored(mark, entry,
                    correct ? entry.getScore() : 0, correct, Flag.NONE);
        }
        // 多选
        Set<String> answer = entry.getMultiAnswer();
        Set<String> wrong = Sets.difference(marked, answer);
        Set<String> missed = Sets.difference(answer, marked);
        if (!wrong.isEmpty()) {
            return QuestionOutcome.scored(mark, entry, 0, false, Flag.NONE);
        }
        if (missed.isEmpty()) {
            return QuestionOutcome.scored(mark, entry, entry.getScore(),
                    true, Flag.NONE);
        }
        double score = partialScore(entry, missed.size());
        return QuestionOutcome.scored(mark, entry, score, false,
                Flag.MULTI_PARTIAL);
    }

    private double partialScore(AnswerEntry e, int missCount) {
        switch (e.getPartialPolicy()) {
            case MISS_ONE_HALF:  return missCount == 1 ? e.getScore() / 2.0 : 0;
            case HALF_PER_MISS:  return e.getScore() * Math.pow(0.5, missCount);
            case NO_PARTIAL:
            default:             return 0;
        }
    }
}
```

```
                    └─────┬───────┘                ▼
              管线完成     │              ┌────────────────┐
              高置信       │              │     FAILED     │──终态(可重新
                           ▼              │ (failCode必填) │  上传→attempt+1)
                   ┌──────────────┐      └────────────────┘
                   │   GRADED     │
                   │ (判分完成)    │
                   └─────┬────────┘
              存在复核项  │ 无复核项
             (学生自校对/ │
              教师复核台) ▼
                   ┌──────────────┐
                   │REVIEW_REQUIRED│
                   └─────┬────────┘
                  确认/修正提交│
                         ▼
                   ┌──────────────┐   发布GRADE_COMPLETED事件
                   │  CONFIRMED   │──▶ 错题归档/学情更新
                   └──────────────┘
```

状态迁移表：

| from | event | to | 动作 |
|------|-------|----|------|
| UPLOADED | worker_lease | PROCESSING | 更新 Redis 状态，锁 120s |
| PROCESSING | pipeline_ok(high_conf) | GRADED | 写 recognition + grade |
| PROCESSING | pipeline_ok(low_conf) | REVIEW_REQUIRED | 生成 review_items |
| PROCESSING | quality_fail / anchor_fail / timeout | FAILED | failCode 写入，告警 |
| PROCESSING | worker 超时未回报 | (重试) | 最多 2 次，之后 FAILED |
| GRADED | auto_confirm (学生自查场景默认可延迟自动确认, 24h) | CONFIRMED | 发布事件 |
| REVIEW_REQUIRED | user_confirm | CONFIRMED | 修正重判后发布事件 |
| REVIEW_REQUIRED | 超时 72h 未处理 | CONFIRMED(机器值) | 打 `AUTO_CONFIRMED` 标记 |
| FAILED | reupload | UPLOADED(新attempt) | 幂等键校验 |

> 教师批量场景 `CONFIRMED` 由 `batch publish` 触发，单卡不单独确认。

### 9.2 批量任务状态

`RUNNING(进行中) → READY(全部子任务完成,待复核/发布) → PUBLISHED(已发布)`；任一子任务 FAILED 不阻塞批量完成，汇总中单独列示。

## 11. 错误处理与降级策略

### 11.1 错误码表

| code | HTTP | 阶段 | 用户提示 | 处理 |
|------|------|------|---------|------|
| IMG_TOO_SMALL | 422 | 质检 | "照片太小，请靠近重拍" | 引导重拍 |
| IMG_TOO_BLURRY | 422 | 质检 | "照片模糊，请对焦后重拍" | 引导重拍 |
| IMG_GLARE | 422 | 质检 | "反光太强，换个角度拍摄" | 引导重拍 |
| IMG_TOO_SKEW | 422 | 质检 | "请正对答题卡拍摄" | 引导重拍 |
| ANCHOR_NOT_FOUND | 422 | 定位 | "未识别到答题卡定位点，请完整拍入四角" | 引导重拍 |
| TEMPLATE_NOT_MATCHED | 422 | 模板 | "未匹配到答题卡模板" | 引导选模板/创建模板 |
| EXAM_ANSWER_KEY_NOT_FOUND | 404 | 接入 | "该考试暂无标准答案" | 引导等待/切换考试 |
| SHEET_TASK_DUPLICATED | 409 | 接入 | "该答题卡已在上传处理中" | 返回原任务 |
| STUDENT_NO_INVALID | 200(复核) | 学号 | "考号识别有误" | 手输修正 |
| CV_PIPELINE_TIMEOUT | 500 | 管线 | "识别超时，已自动重试" | 重试2次→FAILED |
| CONTENT_SECURITY_REJECTED | 422 | 合规 | "图片未通过安全审核" | 终态,记录审计 |
| RATE_LIMITED | 429 | 接入 | "操作太频繁" | 客户端退避 |

### 11.2 降级路径

| 故障 | 降级行为 |
|------|---------|
| QR 解码服务不可用 | 直接走布局指纹匹配；指纹也失败→人工选模板 |
| CV Worker 队列积压 > 5min | 学生自查场景弹出"稍后通知"，完成后推送；批量场景教师端显示排队进度 |
| 单卡重试 2 次仍失败 | FAILED + 附失败原因；学生可转 S3 对答案模式兜底 |
| 识别准确率周报 < 99.0% | 自动收紧 FILL_HIGH 至 0.58，扩大复核带（宁可多复核不可错判） |
| 判分服务 DB 抖动 | 结果先落 Redis，任务状态置 GRADED_PENDING_FLUSH，恢复后回写 |

## 12. 性能与容量设计

### 12.1 目标

| 指标 | 目标值 |
|------|--------|
| 单页端到端（上传→出分，学生自查） | P50 ≤ 6s，P95 ≤ 12s |
| 教师批量 50 张全流程 | ≤ 4min（并行 Worker 16） |
| 客观题判分准确率（确认后修正前） | ≥ 99.5%（以人工复核修正为真值） |
| 自动确认无修正率 | ≥ 92% |
| 复核率（进入 REVIEW_REQUIRED 占比） | ≤ 8% |
| CV Worker 单页 CPU 耗时 | ≤ 3.5s @ 2C |

### 12.2 容量估算（参考）

- 高峰假设：10 万 DAU × 6% 当日使用答题卡 × 1.2 张 = 7,200 张/日；晚高峰 19:00-21:00 占 55% → ~66 张/分钟。
- 单 Worker 2C 处理 3.5s/页 → 34 页/分钟/Worker；3 Worker 常驻 + HPA（队列深度 > 100 持续 1min 扩容，上限 12）即可覆盖，批量场景教师多在白天使用，错峰良好。
- 存储：每张原图 ~2.5MB + 矫正图 ~1.2MB + 裁片 ~0.3MB，7,200 张/日 ≈ 29GB/日；原图 90 天后转低频存储（复用存储生命周期管理引擎）。

| 埋点/指标 | 类型 | 用途 |
|-----------|------|------|

## 14. 安全与合规设计

1. **未成年人图像**：所有上传图像过内容安全审核（复用平台统一审核管线），审核通过才进入 CV 管线；原图访问走带签名的临时 URL，默认 30 天后删除原图（仅保留结构化结果）。
2. **数据最小化**：成绩数据仅学生本人、绑定家长、任课教师、班级学校授权角色可见；对外接口按 `examId + studentUid` 双重鉴权。
3. **成绩防篡改**：`detail_json` 计算摘要哈希与 `confirmed_by/confirmed_at` 一并存储；教师发布后的批量成绩只读，修正须走"成绩复核流"并留痕。
4. **审计**：模板审核、成绩发布、复核修正均写平台审计日志（操作者/前后值/时间）。
5. **答案保密**：`exam_answer_key` 在考试结束时间前对学生侧接口不可见（服务端双重校验考试结束时间 + 教师发布标记）。
