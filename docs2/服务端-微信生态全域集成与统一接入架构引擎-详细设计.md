# 服务端-微信生态全域集成与统一接入架构引擎 详细设计

## 1. 概述

### 1.1 模块定位

微信生态全域集成平台（WeChat Ecosystem Integration Platform，简称 WIP）是 PrimeTop 服务端与微信开放生态之间的**统一接入层与能力编排中枢**。

在 PrimeTop 的产品矩阵中，微信生态承担着多重角色：
- **身份层**：微信授权登录（APP / 小程序 / 公众号），UnionID 跨端身份打通
- **支付层**：微信支付（APP / JSAPI / H5 / 小程序），覆盖会员订阅与增值服务购买
- **消息层**：公众号模板消息、小程序订阅消息，作为多渠道通知体系的重要一环
- **社交层**：学习报告分享、邀请裂变、学习挑战排行分享至微信好友/朋友圈
- **入口层**：微信小程序作为轻量级产品入口，降低新用户体验门槛
- **协同层**：企业微信为教师/学校端提供班级群消息推送与家校沟通能力

当前各业务模块（支付、登录、分享、推送等）各自独立对接微信 API，存在 **Token 管理混乱、重复接入、配额浪费、合规风险分散** 等问题。WIP 的核心目标是将这些分散的对接收拢为统一的集成平台。

### 1.2 核心职责

| 职责 | 说明 |
| --- | --- |
| 统一 Token 管理 | 集中管理 access_token、jsapi_ticket、component_verify_ticket，全局唯一、自动刷新、高可用 |
| 身份联邦 | 微信 OpenID / UnionID 体系与 PrimeTop 账号体系的双向映射 |
| 支付通道适配 | 对接微信支付全场景 API，封装统一的下单、查单、退款、回调处理 |
| 消息投递适配 | 将公众号模板消息和小程序订阅消息封装为统一通知渠道 |
| 社交分享适配 | 生成微信分享卡片、小程序码、带参数二维码 |
| 开放平台对接 | 第三方平台代小程序/公众号实现快速授权接入 |
| 企业微信集成 | 家校沟通消息推送、教师班级群通知 |
| 合规管控 | 微信平台规范合规检查、内容审核前置过滤 |

## 2. 数据模型

### 2.1 微信应用配置表 `wx_app_config`

管理 PrimeTop 在微信开放生态中的各类应用（公众号、小程序、开放平台应用）配置。

```sql
CREATE TABLE `wx_app_config` (
    `id`                    BIGINT UNSIGNED    NOT NULL AUTO_INCREMENT,
    `app_type`              TINYINT UNSIGNED   NOT NULL COMMENT '应用类型: 1=开放平台应用, 2=公众号, 3=小程序, 4=企业微信应用',
    `app_id`                VARCHAR(64)        NOT NULL COMMENT '微信 AppID',
    `app_secret`            VARCHAR(256)       NOT NULL COMMENT '微信 AppSecret（AES加密存储）',
    `app_name`              VARCHAR(100)       NOT NULL COMMENT '应用名称',
    `status`                TINYINT UNSIGNED   NOT NULL DEFAULT 1 COMMENT '状态: 0=禁用, 1=启用',
    `config_json`           JSON               DEFAULT NULL COMMENT '扩展配置（原始ID、服务器配置URL、IP白名单等）',
    `created_at`            DATETIME           NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`            DATETIME           NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_app_id` (`app_id`),
    KEY `idx_app_type_status` (`app_type`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='微信应用配置表';
```

### 2.2 微信 Token 管理表 `wx_access_token`

集中管理所有微信应用的 access_token 和 jsapi_ticket，确保全局唯一。

```sql
CREATE TABLE `wx_access_token` (
    `id`                    BIGINT UNSIGNED    NOT NULL AUTO_INCREMENT,
    `app_id`                VARCHAR(64)        NOT NULL COMMENT '微信 AppID',
    `token_type`            VARCHAR(20)        NOT NULL COMMENT 'token类型: access_token/jsapi_ticket/api_ticket/wx_card_ticket',
    `token_value`           VARCHAR(512)       NOT NULL COMMENT 'Token值',
    `expires_in`            INT UNSIGNED       NOT NULL COMMENT '有效期（秒）',
    `expires_at`            DATETIME           NOT NULL COMMENT '过期时间',
    `fetched_at`            DATETIME           NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '获取时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_app_token_type` (`app_id`, `token_type`),
    KEY `idx_expires_at` (`expires_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='微信Token管理表';
```

### 2.7 缓存策略

| 缓存键 | 类型 | TTL | 说明 |
| --- | --- | --- | --- |
| `wx:token:{appId}:access_token` | Redis String | 7000s | access_token（微信有效期7200s，提前200s刷新） |
| `wx:token:{appId}:jsapi_ticket` | Redis String | 7000s | jsapi_ticket |
| `wx:token:{appId}:api_ticket` | Redis String | 7000s | api_ticket（卡券接口） |
| `wx:lock:{appId}:token_refresh` | Redis Lock | 30s | Token 刷新分布式锁，防并发刷新 |
| `wx:user:{unionId}` | Redis Hash | 24h | 微信用户信息缓存 |
| `wx:pay:notify:{outTradeNo}` | Redis String | 24h | 支付回调幂等键 |
| `wx:msgid:{msgId}` | Redis String | 48h | 消息防重投递 |

### 3.2 微信授权登录

**POST** `/api/v1/wechat/auth/login`

支持三种场景的微信授权登录，通过 `login_scene` 字段区分。

**请求参数：**

```json
{
    "login_scene": "APP",
    "code": "wx_oauth_code_xxx",
    "encrypted_data": "encrypted_user_info_data",
    "iv": "initialization_vector",
    "invite_code": "INVITE_ABC123"
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| login_scene | string | 是 | 登录场景: `APP` / `MINIPROGRAM` / `H5` |
| code | string | 是 | 微信授权 code |
| encrypted_data | string | 否 | 小程序场景下加密的用户数据 |
| iv | string | 否 | 小程序场景下加密向量 |
| invite_code | string | 否 | 邀请码（裂变场景） |

**响应（成功）：**

```json
{
    "code": 0,
    "msg": "success",
    "data": {
        "access_token": "pt_access_token_xxx",
        "refresh_token": "pt_refresh_token_xxx",
        "expires_in": 7200,
        "user_id": 100001234,
        "is_new_user": true,
        "need_complete_profile": true
    }
}
```

**响应（需要绑定手机号）：**

```json
{
    "code": 0,
    "msg": "success",
    "data": {
        "temp_token": "wx_bind_temp_token_xxx",
        "expires_in": 600,
        "need_phone": true,
        "wx_user_info": {
            "nickname": "微信昵称",
            "avatar_url": "https://thirdwx.qlogo.cn/..."
        }
    }
}
```

> **说明**：根据《未成年人保护法》和微信平台规范，新用户通过微信首次登录时，需要补充手机号验证以确认身份。`temp_token` 有效期 10 分钟，用于后续绑定手机号接口。

### 3.4 微信支付回调

**POST** `/api/v1/wechat/pay/notify`

微信支付异步通知回调端点。此接口由微信支付服务器调用。

**处理流程：**
1. 接收原始 XML / JSON 报文
2. 验证签名（使用微信支付平台证书）
3. 解密回调数据（AEAD_AES_256_GCM）
4. 幂等校验（基于 `out_trade_no` + Redis）
5. 更新订单状态
6. 触发后续业务流程（会员开通、额度发放等）
7. 返回成功应答

**响应格式：**

```json
{
    "code": "SUCCESS",
    "message": "成功"
}
```

**非成功响应（触发微信重试）：**

```json
{
    "code": "FAIL",
    "message": "签名验证失败"
}
```

### 3.7 错误码定义

| 错误码 | HTTP | 说明 | 处理建议 |
| --- | --- | --- | --- |
| 070101 | 401 | 微信授权 code 无效或已过期 | 引导用户重新授权 |
| 070102 | 401 | 微信 access_token 获取失败 | 检查 AppID/Secret 配置 |
| 070103 | 409 | 该微信号已绑定其他账号 | 引导用户解绑后重试 |
| 070104 | 400 | 缺少必要参数（openid/encrypted_data等） | 检查请求参数 |
| 070201 | 400 | 微信支付下单失败 | 检查订单参数、金额 |
| 070202 | 409 | 微信支付预付单已存在 | 直接返回已有 prepay_id |
| 070203 | 402 | 微信支付签名验证失败 | 检查 API 密钥配置 |
| 070204 | 500 | 微信支付回调处理异常 | 记录日志，等待微信重试 |
| 070301 | 400 | 模板消息模板
