## 1. 概述

### 1.1 功能定位

内容生产运营与质量管控工作台是平台运营团队的内容生产指挥中枢，覆盖五大职能：

1. **生产任务编排**：缺口转化建单、手动/批量建单、分派调整、进度跟踪、逾期预警。
2. **质量管控**：AI 预检（事实准确性/知识点对齐/适龄化/内容安全/格式/查重六阶段）+ 人工检查清单审核（通过/退回/条件通过），多轮审核与质量评分。
3. **缺口分析**：按章节 × 内容类型聚合需求缺口，需求分计算与批量转化为生产任务。
4. **产能管理**：团队/供应商产能日历、负载均衡建议、利用率监控。
5. **发布管控**：审核通过后发布、下线、归档，发布后事件回流推荐系统与知识点体系。

**执行边界（契约 R1）**：生产任务的调度执行（自动分派、排产、负载算法）权威归《服务端-教育内容生产任务编排与产能智能调度引擎》；本工作台为运营管理域权威，管理质量态状态机（§6.1）、审核结论（content_quality_reviews）、发布/下线与缺口分析结果。任务创建选择自动分派时由 BFF 委托引擎执行，执行态变化经引擎事件回流本工作台读模型。

### 1.2 设计目标

| 目标 | 说明 | 衡量标准 |
| --- | --- | --- |
| 单工作台闭环 | 运营人员在一个工作台完成"发现缺口→建单→跟踪→审核→发布→效果回流" | 全流程无需切换系统 |
| 质量前置拦截 | AI 预检在人工审核前自动执行，内容安全一票否决 | 低质内容进入人工审核占比下降 |
| 边界清晰 | 调度执行归引擎、质量审核归本工作台、安全终审归内容安全审核工作台 | 契约 §18 无歧义 |
| 全程可审计 | 建单/流转/审核/发布/规则修改全部留痕 | 审计日志覆盖率 100% |

### 1.3 与其他系统的关系

| 系统 | 关系 | 边界裁决 |
| --- | --- | --- |
| 服务端-教育内容生产任务编排与产能智能调度引擎 | 生产执行与排产调度 | 调度算法/执行态权威归引擎（R1） |
| 管理后台-内容安全审核工作台 | 安全审核联动 | 安全终审权威归对方，AI 预检仅为前置拦截（R2） |
| 管理后台-题库内容管理与生产运维工作台 | 题目类任务协同 | 题目主数据权威归题库工作台（R6） |
| 管理后台-内容供应商管理与合作伙伴运营工作台 | 供应商产能/交付 | 供应商数据权威归对方，本工作台只读引用（R7） |
| 管理后台-推荐策略调控与内容运营管理工作台 | 发布回流 | content-published-topic 消费方（R3） |
| 服务端-题库知识点覆盖度智能诊断与内容生产需求预测引擎 | 缺口需求信号 | demand_score 权重归对方，本工作台消费结果（R5） |

## 3. 数据模型

### 3.1 content_production_tasks（生产任务主表）

```sql
CREATE TABLE content_production_tasks (
    id                BIGINT PRIMARY KEY,
    task_no           VARCHAR(32)  NOT NULL UNIQUE COMMENT '任务编号 CPT-YYYY-XXXXXX',
    title             VARCHAR(256) NOT NULL COMMENT '任务标题',

    -- 任务来源
    source_type       VARCHAR(32)  NOT NULL COMMENT 'GAP_ANALYSIS/MANUAL/TEXTBOOK_UPDATE/TIMELINESS_ALERT',
    source_ref_id     BIGINT COMMENT '来源引用ID（缺口分析记录ID等）',

    -- 任务内容
    content_type      VARCHAR(32)  NOT NULL COMMENT '见附录14.1 ContentType',
    subject_code      VARCHAR(16)  NOT NULL COMMENT '学科编码',
    grade_range       VARCHAR(8)   NOT NULL COMMENT '学段年级，如 P3/J2/S1',
    chapter_id        BIGINT COMMENT '教材章节ID',
    chapter_name      VARCHAR(128) COMMENT '冗余章节名，展示用',
    knowledge_point   VARCHAR(128) COMMENT '知识点名称',

    -- 执行信息
    priority          TINYINT      NOT NULL DEFAULT 3 COMMENT '1紧急 2高 3中 4低',
    assignee_id       BIGINT COMMENT '负责人用户ID（内部编辑）',
    supplier_id       BIGINT COMMENT '供应商ID（外部交付）',
    auto_assigned     BOOLEAN      NOT NULL DEFAULT FALSE COMMENT '是否引擎自动分派',
    progress_pct      SMALLINT     NOT NULL DEFAULT 0 COMMENT '进度 0-100',

    -- 时间
    planned_start     DATETIME,
    planned_end       DATETIME     NOT NULL COMMENT '截止日期',
    actual_start      DATETIME,
    actual_end        DATETIME,

    -- 质量与产出
    status            VARCHAR(24)  NOT NULL DEFAULT 'PENDING' COMMENT '见§6.1状态机',
    quality_score     DECIMAL(5,2) COMMENT '最近一轮审核总分',
    review_rounds     TINYINT      NOT NULL DEFAULT 0 COMMENT '已审核轮次',
    output_content_id BIGINT COMMENT '产出的内容ID',

    -- 乐观并发
    version           INT          NOT NULL DEFAULT 0 COMMENT '乐观锁版本',

    created_by        BIGINT NOT NULL,
    created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_status_priority (status, priority),
    INDEX idx_deadline (planned_end),
    INDEX idx_subject_stage (subject_code, grade_range),
    INDEX idx_assignee (assignee_id, status)
) COMMENT='内容生产任务表（运营管理域）';
```

> 注：§10.1 的覆盖索引 `idx_task_list_cover` 使用 PostgreSQL `INCLUDE` 语法，若落 MySQL 需改写为冗余列联合索引（契约 R8）。

### 3.2 content_quality_reviews（质量审核记录表）

```sql
CREATE TABLE content_quality_reviews (
    id                BIGINT PRIMARY KEY,
    task_id           BIGINT NOT NULL COMMENT '生产任务ID',
    round             TINYINT NOT NULL COMMENT '审核轮次，从1开始',

    reviewer_id       BIGINT NOT NULL COMMENT '审核人',
    reviewer_name     VARCHAR(64) NOT NULL COMMENT '冗余快照',
    checklist_id      BIGINT NOT NULL COMMENT '使用的检查清单',
    checklist_version INT NOT NULL COMMENT '清单版本快照',

    -- 逐项检查结果：[{"item_id":"Q1","passed":true,"score":24,"comment":""}]
    items_json        JSON NOT NULL,
    -- AI预检结果（§7.2管线输出）：{"overall_score":85.5,"stages":{...},"issues":[...]}
    ai_pre_check      JSON,

    verdict           VARCHAR(16) NOT NULL COMMENT 'APPROVED/REJECTED/CONDITIONAL',
    total_score       DECIMAL(5,2) NOT NULL COMMENT '加权总分 0-100',
    issues            JSON COMMENT '问题列表',
    suggestions       JSON COMMENT '修改建议列表',

    created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY uk_task_round (task_id, round),
    INDEX idx_reviewer (reviewer_id, created_at)
) COMMENT='质量审核记录表';
```

`uk_task_round` 同时是审核结论幂等约束：同一任务同一轮次仅可写入一次（守卫 G3）。

### 3.3 content_quality_checklists（质量检查清单模板表）

```sql
CREATE TABLE content_quality_checklists (
    id            BIGINT PRIMARY KEY,
    name          VARCHAR(128) NOT NULL,
    content_type  VARCHAR(32)  NOT NULL COMMENT '适用内容类型，ALL 表示通用',
    subject_code  VARCHAR(16)  NOT NULL DEFAULT 'ALL',
    grade_range   VARCHAR(8)   NOT NULL DEFAULT 'ALL',
    items         JSONB        NOT NULL COMMENT '检查项数组，结构见§14.2种子数据',
    passing_score DECIMAL(5,2) NOT NULL COMMENT '通过阈值',
    version       INT          NOT NULL DEFAULT 1,
    status        VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/DISABLED',
    updated_by    BIGINT NOT NULL,
    updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) COMMENT='质量检查清单模板表';
```

清单匹配优先级：`content_type+subject_code` 精确 > `content_type+ALL` > 通用模板。审核时快照 `checklist_version` 与 `items_json`，清单后续修改不回溯历史审核记录。

### 3.4 content_gap_analysis（内容缺口分析表）

```sql
CREATE TABLE content_gap_analysis (
    id                     BIGINT PRIMARY KEY,
    analysis_batch         VARCHAR(32)  NOT NULL COMMENT '分析批次号 GA-YYYYMMDD-NN',
    subject_code           VARCHAR(16)  NOT NULL,
    grade_range            VARCHAR(8)   NOT NULL,
    chapter_id             BIGINT,
    chapter_name           VARCHAR(128) NOT NULL,
    knowledge_point        VARCHAR(128) NOT NULL COMMENT '知识点名称',
    content_type           VARCHAR(32)  NOT NULL,

    demand_level           VARCHAR(16)  NOT NULL COMMENT 'CRITICAL/HIGH/MEDIUM/LOW',
    demand_score           DECIMAL(8,2) NOT NULL COMMENT '需求分',
    current_count          INT          NOT NULL DEFAULT 0,
    target_count           INT          NOT NULL DEFAULT 4,
    gap_count              INT          NOT NULL,
    suggested_priority     TINYINT NOT NULL COMMENT '建议优先级 1-4',
    estimated_effort_minutes INT COMMENT '预估工时',

    task_id                BIGINT COMMENT '已转化的生产任务ID（幂等标记）',
    analysis_date          DATE NOT NULL,
    created_at             DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY uk_batch_dim (analysis_batch, subject_code, chapter_id, knowledge_point, content_type),
    INDEX idx_demand (subject_code, grade_range, demand_level, gap_count)
) COMMENT='内容缺口分析表';
```

缺口由定时任务每周一 02:00 生成（§13.1 `gap_analysis.schedule_cron`），需求分权重归服务端需求预测引擎（R5）。

### 4.3 创建任务（单个/批量）

```
POST /api/admin/content-prod/tasks
POST /api/admin/content-prod/tasks/batch
```

**单个创建请求体：**

```json
{
  "title": "浮力-阿基米德原理应用 讲解",
  "content_type": "EXPLANATION",
  "subject_code": "PHY",
  "grade_range": "J2",
  "chapter_id": 88012,
  "knowledge_point": "阿基米德原理的应用",
  "priority": 2,
  "planned_end": "2026-08-20T00:00:00Z",
  "assignee_id": 2001,
  "auto_assign": false,
  "ai_assist_enabled": true,
  "source_type": "MANUAL",
  "source_ref_id": null
}
```

**规则：**

- `auto_assign=true` 时 `assignee_id` 可为空，由 BFF 委托引擎分派（契约 R1）；分派失败任务落 `PENDING` 并告警，不阻断创建。
- 批量创建上限 100 条，超出返回 `CONTENT_PROD_006`。
- `planned_end` 不得早于创建时间，否则 `CONTENT_PROD_001`。

**响应：**

```json
{
  "code": 0,
  "data": {
    "task_id": 10301,
    "task_no": "CPT-2026-001301",
    "status": "PENDING",
    "version": 0
  }
}
```

任务编号规则：`CPT-年份-6位序列`，序列由分布式序号服务批量预取（§10.3），编号冲突返回 `CONTENT_PROD_004`。

### 4.5 状态流转

```
POST /api/admin/content-prod/tasks/{id}/transition
```

**请求体：**

```json
{
  "action": "SUBMIT_REVIEW",
  "reason": "初稿完成，提交审核",
  "version": 3
}
```

**规则：**

- `action` 合法性由 §6.1 状态机 + §6.3 角色权限双重校验；非法返回 `CONTENT_PROD_003`，越权返回 `CONTENT_PROD_002`。
- `version` 乐观锁校验，并发流转仅一方成功，另一方返回 `CONTENT_PROD_003`（守卫 G2）。
- 终态任务（ARCHIVED/CANCELLED）拒绝一切流转。

**响应：**

```json
{
  "code": 0,
  "data": {"id": 10301, "status": "IN_REVIEW", "version": 4}
}
```

### 4.6 审核提交与审核结论

```
POST /api/admin/content-prod/tasks/{id}/review
GET  /api/admin/content-prod/tasks/{id}/reviews
```

**审核结论请求体：**

```json
{
  "verdict": "CONDITIONAL",
  "checklist_id": 12,
  "items": [
    {"item_id": "Q1", "passed": true, "score": 24, "comment": ""},
    {"item_id": "Q5", "passed": false, "score": 4, "comment": "例题过于抽象，建议增加生活化例子"}
  ],
  "issues": ["例题抽象，低龄学生理解困难"],
  "suggestions": ["补充船舶载重的生活场景例子"]
}
```

**规则：**

- 仅 `IN_REVIEW` 状态可提交审核结论，否则 `CONTENT_PROD_003`。
- 轮次上限 `max_review_rounds=5`（§13.1），超限任务强制升级运营经理人工裁决。
- `verdict=APPROVED` 且 `total_score ≥ passing_score` → 任务转 `APPROVED`；`REJECTED/CONDITIONAL` → 转 `REVISION_REQUIRED`；总分未达阈值即使 verdict=APPROVED 也按 CONDITIONAL 处理并返回 `CONTENT_PROD_005` 语义提示。
- AI 预检 `content_safety` 未通过的任务禁止得出通过结论（守卫 G4，fail-closed）。
- 必填检查项未填写完整返回 `CONTENT_PROD_005`。

### 6.3 状态机代码实现

```typescript
// 任务状态机定义
const TASK_STATE_MACHINE = {
  PENDING: {
    transitions: {
      START: 'IN_PROGRESS',
      CANCEL: 'CANCELLED',
    }
  },
  IN_PROGRESS: {
    transitions: {
      SUBMIT_REVIEW: 'IN_REVIEW',
      REVERT: 'PENDING',
    }
  },
  IN_REVIEW: {
    transitions: {
      APPROVE: 'APPROVED',
      REJECT: 'REVISION_REQUIRED',
      CONDITIONAL_PASS: 'REVISION_REQUIRED',
    }
  },
  REVISION_REQUIRED: {
    transitions: {
      START_REVISION: 'IN_PROGRESS',
      RESUBMIT: 'IN_REVIEW',
    }
  },
  APPROVED: {
    transitions: {
      PUBLISH: 'PUBLISHED',
      ARCHIVE: 'ARCHIVED',
    }
  },
  PUBLISHED: {
    transitions: {
      UNPUBLISH: 'REVISION_REQUIRED',
      ARCHIVE: 'ARCHIVED',
    }
  },
  ARCHIVED: {
    transitions: {} // 终态
  },
  CANCELLED: {
    transitions: {} // 终态
  }
};

// 状态流转校验
function validateTransition(
  currentStatus: string,
  action: string,
  userRole: string
): { valid: boolean; newStatus?: string; error?: string } {
  const state = TASK_STATE_MACHINE[currentStatus];
  if (!state) {
    return { valid: false, error: `未知状态: ${currentStatus}` };
  }

  const newStatus = state.transitions[action];
  if (!newStatus) {
    return { valid: false, error: `当前状态 ${currentStatus} 不支持操作 ${action}` };
  }

  // 角色权限校验
  const rolePermissions: Record<string, string[]> = {
    'CONTENT_OPS_MANAGER': ['CANCEL', 'PUBLISH', 'ARCHIVE'],
    'CONTENT_PROD_ADMIN': ['START', 'REVERT', 'CANCEL'],
    'QUALITY_LEAD': ['APPROVE', 'REJECT', 'CONDITIONAL_PASS', 'UNPUBLISH'],
    'SUBJECT_EDITOR': ['START', 'SUBMIT_REVIEW', 'START_REVISION', 'RESUBMIT'],
  };

  if (!rolePermissions[userRole]?.includes(action)) {
    return { valid: false, error: `角色 ${userRole} 无权执行操作 ${action}` };
  }

  return { valid: true, newStatus };
}
```

### 6.4 守卫规则总表（G1-G10）

全文散见的状态机与数据一致性守卫收拢如下，开发与测试以本表为验收口径：

| 编号 | 规则 | 类型 | 失败表现 | 落点 |
| --- | --- | --- | --- | --- |
| G1 | 任务状态变更必须经 §6.3 状态机唯一入口校验，禁止任何旁路 UPDATE 直改 status | fail-closed | 旁路写入被拒绝并告警 | Repository 层强制走 `transition()` |
| G2 | 状态流转使用 `version` 乐观锁 CAS，并发流转仅一方成功，失败方返回 `CONTENT_PROD_003` | fail-closed | 409 冲突 | §4.5、§6.3 |
| G3 | 审核结论幂等：`uk_task_round (task_id, round)` 唯一约束，同任务同轮次仅可写入一次，重复提交返回首条记录（结果回放） | fail-closed | 唯一键冲突转幂等回放 | §3.2 |
| G4 | AI 预检 `content_safety` 未通过的任务禁止得出「通过」结论，质量主管手工通过按钮置灰 | fail-closed | 服务端拒绝 + 前端置灰 | §4.6、§7.2 |
| G5 | 缺口转化为生产任务幂等：`task_id IS NULL` 才允许转化，转化与回填同一事务，重复点击/重试不产生重复任务 | fail-closed | 第二次 CAS 影响行数为 0 时返回已生成任务 | §4.9 |
| G6 | 检查清单修改不回溯历史：审核记录快照 `checklist_version` 与 `items_json`，模板后续变更不影响已产生结论 | 不可变约束 | 历史审核详情展示快照 | §3.3 |
| G7 | `PUBLISHED` 状态内容禁止物理删除，只能走 `UNPUBLISH`→下线或 `ARCHIVE`；删除接口对已发布任务返回 `CONTENT_PROD_008` | fail-closed | 409 拒绝 | §9.1 |
| G8 | `quality_score`、`review_rounds` 与审核记录同事务回写，禁止双写分叉；任务主表不独立更新质量字段 | 一致性 | 同事务提交 | §4.6 |
| G9 | 自动分派失败（引擎委托超时/无可用产能）时任务落回 `PENDING` 并产生告警，禁止停留在中间态或静默挂起 | fail-visible | `AUTO_ASSIGN_FAILED` 告警 | §4.3 |
| G10 | 全部写操作审计事件不丢：本地事务提交后先落 Outbox 再异步投递，消费失败重试 ≥3 次后转死信并 P1 告警 | fail-visible | 审计积压 >0 即告警 | §11.1、§4.0 |

> G1/G2/G4/G7 为 fail-closed 红线，任何降级方案不得绕过；G9/G10 为可见性红线，宁可告警不可用，不可静默吞没。

### 7.2 AI辅助审核流程

```python
# AI 预检管线 - 在提交人工审核前自动执行

class ContentAIPreCheckPipeline:
    """内容AI预检管线"""
    
    CHECK_STAGES = [
        "factual_accuracy",    # 事实准确性检查
        "knowledge_alignment", # 知识点对齐检查
        "age_appropriateness", # 适龄化检查
        "content_safety",      # 内容安全检查
        "format_validation",   # 格式规范检查
        "plagiarism_check",    # 查重检查
    ]
    
    async def run(self, task_id: int, content: str, metadata: dict) -> dict:
        """
        执行AI预检
        返回: {
            "overall_score": 85.5,
            "passed": True,
            "stages": {...},
            "issues": [...],
            "suggestions": [...]
        }
        """
        results = {}
        issues = []
        
        for stage in self.CHECK_STAGES:
            checker = self.get_checker(stage)
            result = await checker.check(content, metadata)
            results[stage] = result
            
            if not result.passed:
                issues.extend(result.issues)
        
        overall_score = self._calculate_score(results)
        
        return {
            "overall_score": overall_score,
            "passed": overall_score >= self.threshold,
            "stages": results,
            "issues": issues,
            "ai_pre_check": results,  # 存入 content_quality_reviews.ai_pre_check
        }
    
    def _calculate_score(self, results: dict) -> float:
        """各阶段加权评分"""
        weights = {
            "factual_accuracy": 30,
            "knowledge_alignment": 20,
            "age_appropriateness": 15,
            "content_safety": 20,  # 必须通过，否则直接0分
            "format_validation": 10,
            "plagiarism_check": 5,
        }
        
        # 内容安全一票否决
        if not results["content_safety"].passed:
            return 0.0
        
        score = sum(
            weights[stage] * results[stage].score / 100
            for stage in self.CHECK_STAGES
        )
        return round(score, 2)
```

```typescript
      const { from: fromCol, to: toCol, item } = evt;
      const taskId = item.dataset.taskId;
      const action = deriveAction(fromCol, toCol);
      
      if (!action) {
        await ElNotification.warning('不支持的状态变更');
        await reloadBoard(); // 回滚
        return;
      }

      // 校验权限
      const validation = validateTransition(
        fromCol,
        action,
        currentUser.role
      );

      if (!validation.valid) {
        await ElNotification.error(validation.error);
        await reloadBoard();
        return;
      }

      // 调用API
      try {
        await api.transitionTask(taskId, { action });
        await ElNotification.success(`任务已移至「${STATUS_LABELS[toCol]}」`);
      } catch (err) {
        await ElNotification.error('状态变更失败，请重试');
        await reloadBoard();
      }
    };

    const deriveAction = (from: string, to: string): string | null => {
      const map: Record<string, string> = {
        'PENDING→IN_PROGRESS': 'START',
        'IN_PROGRESS→IN_REVIEW': 'SUBMIT_REVIEW',
        'REVISION_REQUIRED→IN_PROGRESS': 'START_REVISION',
        'APPROVED→PUBLISHED': 'PUBLISH',
      };
      return map[`${from}→${to}`] ?? null;
    };

    return { columns, onDragEnd };
  },
});
```

| 审核结论（§4.6） | `X-Idempotency-Key` + `uk_task_round` | 30min + 永久唯一 | 同轮次重复写入回放首条记录（G3） |

| 清单模板更新 | `version` 乐观锁 | — | 冲突返回 409，前端合并后重试 |

### 16.2 幂等执行器（参考实现）

```java
// 通用幂等执行器：SETNX 抢占 + 结果快照回放
@Component
public class IdempotentExecutor {

    @Autowired private StringRedisTemplate redis;

    public <T> T execute(String idemKey, Duration ttl, Supplier<T> action) {
        String lockKey = "idem:content-prod:" + idemKey;
        String resultKey = lockKey + ":result";

        // 1. 已存在结果 → 直接回放（窗口内）
        String cached = redis.opsForValue().get(resultKey);
        if (cached != null) {
            metrics.counter("content_prod_idempotent_replay_total", "api", currentApi()).increment();
            return deserialize(cached);
        }

        // 2. SETNX 抢占执行权（防并发同键击穿）
        Boolean acquired = redis.opsForValue()
            .setIfAbsent(lockKey, nodeId, ttl);
        if (!Boolean.TRUE.equals(acquired)) {
            // 3. 抢占失败：短暂自旋等待首执方落结果（最多 3s）
            return awaitResult(resultKey, Duration.ofSeconds(3));
        }

        try {
            T result = action.get();
            redis.opsForValue().set(resultKey, serialize(result), ttl);
            return result;
        } finally {
            redis.delete(lockKey);
        }
    }
}
```

> 结果快照仅 replay 语义使用，不含敏感正文；审核类快照只存 `review_id` 与结论摘要。
