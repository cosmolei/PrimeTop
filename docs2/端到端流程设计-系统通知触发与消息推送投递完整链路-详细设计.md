## 1. 文档概述

### 1.1 设计目的

本文档描述 PrimeTop 系统中**一条通知从业务事件产生到用户完成交互的完整端到端链路**。现有文档分别覆盖了通知中心存储、推送服务投递、智能调度引擎和客户端展示四个独立模块，但缺少跨模块的全链路串接视图。本文档将四者串联，明确每一步的数据流转、接口调用、异常处理和性能要求，使开发人员能完整理解通知系统的运作机制。

**定时任务入口**

```java
/**
 * 每日学习计划提醒定时任务
 * 按用户设置的提醒时间分桶执行
 */
@Component
@Slf4j
public class DailyStudyReminderJob {

    @Autowired
    private ReminderTargetMapper reminderTargetMapper;
    @Autowired
    private ReminderProcessor reminderProcessor;
    @Autowired
    private ReminderExecutor reminderExecutor;

    /**
     * 每小时整点执行，处理提醒时间在当前小时的用户
     * 例：07:00 执行，查询 reminder_hour=7 的所有用户
     */
    @Scheduled(cron = "0 5 * * * ?") // 每小时第5分钟执行，给系统缓冲时间
    public void execute() {
        int currentHour = LocalTime.now().getHour();
        log.info("开始处理 {}:00 时段的学习计划提醒", currentHour);

        int offset = 0;
        int batchSize = 500;
        List<ReminderTarget> targets;

        do {
            targets = reminderTargetMapper.selectByReminderHour(
                ReminderType.STUDY_PLAN_REMINDER, currentHour, offset, batchSize
            );
            if (targets.isEmpty()) break;

            // 异步提交，不阻塞主线程
            for (ReminderTarget target : targets) {
                reminderExecutor.submit(() -> {
                    try {
                        reminderProcessor.process(target);
                    } catch (Exception e) {
                        log.error("处理提醒失败: userId={}", target.getUserId(), e);
                    }
                });
            }
            offset += batchSize;
        } while (targets.size() == batchSize);

        log.info("{}:00 时段提醒任务提交完成", currentHour);
    }
}
```

**单个提醒处理（含全部检查逻辑）**

```java
@Service
@Slf4j)
public class ReminderProcessor {

    @Autowired private FrequencyChecker frequencyChecker;
    @Autowired private DeduplicationService deduplicationService;
    @Autowired private DoNotDisturbChecker dndChecker;
    @Autowired private TemplateRenderer templateRenderer;
    @Autowired private NotificationPipelineService notificationPipeline;

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void process(ReminderTarget target) {
        Long userId = target.getUserId();
        String templateCode = target.getTemplateCode();

        // ① 频率管控：检查日发送上限
        if (frequencyChecker.isExceeded(userId, templateCode,
                FrequencyWindow.DAILY, target.getMaxDailyCount())) {
            log.debug("用户{}日频率已达上限", userId);
            return;
        }

        // ② 聚合去重：同类型1小时内不重复
        if (deduplicationService.isDuplicate(userId, templateCode,
                Duration.ofHours(1))) {
            log.debug("用户{}近期已发送同类提醒", userId);
            return;
        }

        // ③ 免打扰检查
        DndCheckResult dndResult = dndChecker.check(userId);
        if (dndResult.isInQuietPeriod()) {
            // 延迟到免打扰结束后发送
            scheduleDelayed(target, dndResult.getNextAvailableTime());
            return;
        }

        // ④ 渲染模板
        Map<String, Object> vars = buildVariables(target);
        NotificationContent content = templateRenderer.render(templateCode, vars);

        // ⑤ 创建并投递通知（统一管道）
        notificationPipeline.createAndDeliver(
            userId,
            target.getNotificationType(),
            target.getCategory(),
            content,
            DeliveryPriority.NORMAL
        );

        log.info("学习计划提醒已发送: userId={}", userId);
    }

    private Map<String, Object> buildVariables(ReminderTarget target) {
        // 从学习计划服务获取今日任务信息
        TodayTaskSummary summary = studyPlanService
            .getTodayTaskSummary(target.getUserId());

        return Map.of(
            "nickname", target.getNickname(),
            "task_count", summary.getTaskCount(),
            "est_minutes", summary.getEstMinutes(),
            "subjects", summary.getSubjectNames(),
            "first_task_title", summary.getFirstTaskTitle()
        );
    }
}
```

**统一通知管道（创建 + 投递一体化）**

```java
@Service
public class NotificationPipelineService {

    @Autowired private NotificationMapper notificationMapper;
    @Autowired private NotificationCounterService counterService;
    @Autowired private DeliveryRouter deliveryRouter;
    @Autowired private DeliveryLogService deliveryLogService;

    /**
     * 统一通知管道：创建通知 → 更新计数 → 路由投递 → 记录日志
     */
    public Notification createAndDeliver(
            Long userId,
            NotificationType type,
            NotificationCategory category,
            NotificationContent content,
            DeliveryPriority priority) {

        // 1. 持久化通知记录
        Notification notification = new Notification();
        notification.setUserId(userId);
        notification.setType(type);
        notification.setCategory(category);
        notification.setTitle(content.getTitle());
        notification.setBody(content.getBody());
        notification.setRichBody(content.getRichBody());
        notification.setImageUrl(content.getImageUrl());
        notification.setDeepLink(content.getDeepLink());
        notification.setGroupKey(content.getGroupKey());
        notification.setMetadata(content.getMetadataJson());
        notification.setIsRead(false);
        notification.setExpireAt(calculateExpireTime(type));
        notification.setCreatedAt(Instant.now());
        notificationMapper.insert(notification);

        // 2. 更新未读计数（Redis 原子操作）
        counterService.incrementUnreadCount(userId, category);

        // 3. 路由投递
        DeliveryContext ctx = deliveryRouter.routeAndDeliver(notification, priority);

        // 4. 记录投递日志
        deliveryLogService.log(ctx);

        return notification;
    }

    private Instant calculateExpireTime(NotificationType type) {
        // 不同类型通知过期时间不同
        return switch (type.getCategory()) {
            case LEARNING -> Instant.now().plus(7, ChronoUnit.DAYS);
            case SOCIAL -> Instant.now().plus(14, ChronoUnit.DAYS);
            case SYSTEM -> Instant.now().plus(30, ChronoUnit.DAYS);
            case MARKETING -> Instant.now().plus(3, ChronoUnit.DAYS);
        };
    }
}
```

#### 3.1.3 推送渠道路由

```java
@Service
public class DeliveryRouter {

    @Autowired private WebSocketSessionManager wsSessionManager;
    @Autowired private PushService pushService;
    @Autowired private SmsService smsService;
    @Autowired private UserPreferenceService preferenceService;
    @Autowired private PushTokenService pushTokenService;

    /**
     * 推送渠道路由策略
     * 在线用户：WebSocket + Push双通道
     * 离线用户：Push → 短信(高优先级) → 仅端内
     */
    public DeliveryContext routeAndDeliver(Notification notification,
            DeliveryPriority priority) {
        Long userId = notification.getUserId();
        DeliveryContext ctx = new DeliveryContext(notification, priority);

        boolean isOnline = wsSessionManager.isOnline(userId);

        if (isOnline) {
            // 在线：WebSocket 实时推送
            wsPushService.pushNotification(userId, notification);
            ctx.addChannel(DeliveryChannel.WEBSOCKET, Instant.now());

            // 同时发 Push（确保后台也能看到）
            if (shouldSendPush(userId, notification.getType())) {
                sendPush(userId, notification, ctx);
            }
        } else {
            // 离线：按优先级选择渠道
            UserMessagePreference pref = preferenceService.getPreference(userId);

            if (pref.isPushEnabled() && pushTokenService.hasValidToken(userId)) {
                sendPush(userId, notification, ctx);
            } else if (pref.isSmsEnabled() && priority == DeliveryPriority.URGENT) {
                // 仅紧急通知走短信
                smsService.send(userId, notification.getBody());
                ctx.addChannel(DeliveryChannel.SMS, Instant.now());
            }
            // 其他情况：仅端内消息，用户上线后拉取
        }

        return ctx;
    }

    private boolean shouldSendPush(Long userId, NotificationType type) {
        UserMessagePreference pref = preferenceService.getPreference(userId);
        return pref.isPushEnabledForType(type);
    }

    private void sendPush(Long userId, Notification notification,
            DeliveryContext ctx) {
        PushPayload payload = PushPayload.builder()
            .notificationId(notification.getId())
            .type(notification.getType())
            .deepLink(notification.getDeepLink())
            .build();

        pushService.send(userId,
            notification.getTitle(),
            notification.getBody(),
            payload);
        ctx.addChannel(DeliveryChannel.PUSH, Instant.now());
    }
}
```

```dart
class PushClickHandler {
  final NotificationStore _store;
  final DeepLinkRouter _router;
  final AnalyticsService _analytics;

  Future<void> handlePushTap(Map<String, dynamic> payload) async {
    final notificationId = payload['notification_id'] as String?;
    final deepLink = payload['deep_link'] as String?;

    if (notificationId != null) {
      await _store.markAsRead(notificationId);
      _analytics.logEvent('notification_opened', params: {
        'notification_id': notificationId,
        'source': 'push',
      });
    }

    if (deepLink != null) {
      await _router.navigate(deepLink);
    } else {
      _router.navigate('/notifications');
    }
  }
}
```

#### 3.2.1 事件发布与监听

```java
/**

@Getter
public class AchievementUnlockedEvent extends DomainEvent {
```

### 3.3 场景三：错题复习到期提醒（事件 + 定时双触发型）

错题复习提醒是学习闭环的发动机（P0）。与场景一不同，它有**两个触发源**，必须做双入口幂等收敛。

#### 3.3.1 双触发源设计

| 触发源 | 时机 | 说明 |
|--------|------|------|
| 定时（Cron） | 每日用户个性化活跃时段（默认 18:00，由「学生个性化推送时间智能决策与通知触达时机优化引擎」产出 `best_push_hour`） | 扫描 `review_schedule` 中当日到期的复习项，聚合为一条 |
| 事件（Event） | `mistake.corrected` 错题订正完成 | 即时发「订正完成，已加入 X 日后复习计划」确认通知（可被用户偏好关闭） |

```
错题订正完成                    每日到期扫描
(mistake.corrected)             (review_schedule.due_date = today)
      │                                │
      ▼                                ▼
┌──────────────┐            ┌──────────────────────┐
│ 即时确认通知  │            │ 聚合查询到期复习项     │
│ (订正完成)    │            │ 按用户+学科分组       │
└──────────────┘            └──────────┬───────────┘
                                        │ 到期数 > 0
                                        ▼
                            ┌──────────────────────┐
                            │ 幂等闸门（当日已发?）   │
                            │ SETNX review:{uid}:{d}│
                            └──────────┬───────────┘
                                       │ 未发
                                       ▼
                            ┌──────────────────────┐
                            │ 渲染聚合模板           │
                            │ "今日有N道错题待复习"  │
                            │ group_key=review:{uid}:{date} │
                            └──────────┬───────────┘
                                       ▼
                            NotificationPipeline.createAndDeliver
```

#### 3.3.2 服务端核心代码

**到期扫描任务（主入口）**

```java
/**
 * 错题复习到期提醒任务
 * 分桶执行：按用户个性化推送时段分桶，替代统一 18:00 群发
 */
@Component
@Slf4j
public class MistakeReviewReminderJob {

    @Autowired private ReviewScheduleMapper reviewScheduleMapper;
    @Autowired private UserPushTimeService pushTimeService; // 个性化推送时段
    @Autowired private ReminderExecutor executor;
    @Autowired private MistakeReviewReminderProcessor processor;

    /**
     * 每小时第 10 分钟执行，处理 best_push_hour = 当前小时的活跃用户。
     * 未建立个性化时段的用户落在默认桶 18 点。
     */
    @Scheduled(cron = "0 10 * * * ?")
    public void scanDueReviews() {
        int hour = LocalTime.now().getHour();
        int offset = 0;
        final int BATCH = 500;
        List<Long> userIds;

        do {
            userIds = pushTimeService.selectUserIdsByPushHour(hour, offset, BATCH);
            for (Long userId : userIds) {
                executor.submit(() -> {
                    try {
                        processor.process(userId, LocalDate.now());
                    } catch (Exception e) {
                        log.error("错题复习提醒处理失败 userId={}", userId, e);
                    }
                });
            }
            offset += BATCH;
        } while (userIds.size() == BATCH);
    }
}

@Service
@Slf4j
public class MistakeReviewReminderProcessor {

    @Autowired private ReviewScheduleMapper reviewScheduleMapper;
    @Autowired private StringRedisTemplate redis;
    @Autowired private TemplateRenderer templateRenderer;
    @Autowired private NotificationPipelineService pipeline;
    @Autowired private UserPreferenceService preferenceService;

    /** 时效窗口：到期提醒在到期日 21:00 前有效，之后不再补发（次日扫描会再覆盖） */
    private static final LocalTime EFFECTIVE_UNTIL = LocalTime.of(21, 0);

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void process(Long userId, LocalDate dueDate) {
        // ① 偏好开关
        if (!preferenceService.isNotificationEnabled(
                userId, NotificationType.MISTAKE_REVIEW_DUE)) return;

        // ② 幂等闸门：同一用户当日仅一条到期提醒（与事件触发源共享此键）
        String idemKey = "notify:review_reminder:%d:%s"
                .formatted(userId, dueDate.toString());
        Boolean first = redis.opsForValue()
                .setIfAbsent(idemKey, "1", Duration.ofHours(30));
        if (Boolean.FALSE.equals(first)) return; // 已发（无论哪个入口先到）

        // ③ 聚合到期项：当日到期 + 已过期未复习（最多展示 30 条，防止文案爆长）
        List<DueReviewItem> items = reviewScheduleMapper
                .selectDueItems(userId, dueDate, /*overdueLimit*/30);
        if (items.isEmpty()) {
            redis.delete(idemKey); // 无到期项，释放幂等键
            return;
        }

        // ④ 时效性检查：超时则不推（宁可次日再提醒，避免夜间打扰）
        if (LocalTime.now().isAfter(EFFECTIVE_UNTIL)) return;

        // ⑤ 渲染聚合模板
        Map<String, Object> vars = Map.of(
            "nickname", preferenceService.getNickname(userId),
            "count", items.size(),
            "subjects", groupSubjectSummary(items),   // "数学×3、物理×2"
            "oldest_days", items.stream()
                    .mapToInt(DueReviewItem::getOverdueDays).max().orElse(0)
        );
        NotificationContent content = templateRenderer
                .render("mistake_review_due", vars);
        content.setGroupKey("review_" + userId + "_" + dueDate);

        pipeline.createAndDeliver(
            userId, NotificationType.MISTAKE_REVIEW_DUE,
            NotificationCategory.LEARNING, content, DeliveryPriority.HIGH);
    }
}
```

```java
@Component
```

```java
public class WeeklyReportNotificationJob {
```

### 3.5 场景五：会员到期与续费提醒（定时触发型）

#### 3.5.1 提醒矩阵

| 时点 | 自动续费=ON | 自动续费=OFF |
|------|-------------|--------------|
| T-7（到期前7天） | 预告一次（合规要求展示续费价格与扣费时间） | 首次提醒 + 续费入口 |
| T-3 | 不发（避免打扰） | 强调提醒（附优惠时走 MARKETING 频控） |
| T-0（到期日） | 扣费结果通知（成功=收据 / 失败=重试预告） | 最后提醒 |
| T+3（宽限期） | 扣费失败第 2/3 次重试结果（引用订阅续费预警与自动续费失败补偿调度引擎） | 权益冻结预告 |
| T+7 | —— | 降级通知（权益变化说明，见会员退订与权益降级链路） |

#### 3.5.2 核心代码

```java
@Component
public class MembershipExpiryReminderJob {

    /** 每日 10:00 扫描未来 8 天内到期的会员 */
    @Scheduled(cron = "0 0 10 * * ?")
    public void scanExpiringMemberships() {
        List<ExpiringMembership> list =
                membershipMapper.selectExpiringWithin(Duration.ofDays(8));
        for (ExpiringMembership m : list) {
            long daysLeft = ChronoUnit.DAYS.between(
                    LocalDate.now(), m.getExpireDate());
            ExpiryReminderPoint point = ExpiryReminderPoint.of(daysLeft);
            if (point == null) continue; // 非提醒时点

            // 幂等：同一会员同一提醒时点只发一次
            String idem = "notify:membership_expiry:%d:%s"
                    .formatted(m.getMembershipId(), point.name());
            if (Boolean.FALSE.equals(redis.opsForValue()
                    .setIfAbsent(idem, "1", Duration.ofDays(9)))) continue;

            // 未成年人红线：付款类通知仅作事实提醒，禁止促销话术（见 §11）
            boolean isMinor = m.getUserAge() < 16;
            String template = resolveTemplate(point, m.isAutoRenew(), isMinor);

            Map<String, Object> vars = Map.of(
                "nickname", m.getNickname(),
                "expire_date", m.getExpireDate().toString(),
                "days_left", daysLeft,
                "plan_name", m.getPlanName(),
                "price", m.getRenewalPrice(), // 自动续费预告必须含价格
                "next_charge_date", m.getExpireDate().toString()
            );
            NotificationContent content = templateRenderer.render(template, vars);
            content.setDeepLink("/membership?source=notification_expiry_"
                    + point.name().toLowerCase());

            // 分类：含促销内容 → MARKETING（受频控）；纯事实 → SYSTEM
            NotificationCategory category = (point == ExpiryReminderPoint.T_3
                    && !isMinor && m.hasRenewalDiscount())
                    ? NotificationCategory.MARKETING
                    : NotificationCategory.SYSTEM;

            pipeline.createAndDeliver(m.getUserId(),
                    NotificationType.MEMBERSHIP_EXPIRING,
                    category, content, DeliveryPriority.NORMAL);
        }
    }

    private String resolveTemplate(ExpiryReminderPoint point,
            boolean autoRenew, boolean isMinor) {
        if (autoRenew) {
            return switch (point) {
                case T_7 -> "membership_autorenew_preview"; // 含价格+扣费日
                case T_0 -> "membership_autorenew_charged";  // 由扣费结果事件触发替换
                case GRACE -> "membership_autorenew_retry_failed";
                default -> null;
            };
        }
        return switch (point) {
            case T_7 -> "membership_expiry_first";
            case T_3 -> isMinor ? "membership_expiry_minor"
                               : "membership_expiry_urge"; // 未成年人用中性文案
            case T_0 -> "membership_expiry_last";
            case GRACE -> "membership_grace_freeze_warning";
            case T_PLUS_7 -> "membership_downgrade_notice";
            default -> null;
        };
    }
}
```

> 自动续费 ON 用户的 T-0 扣费结果通知不由此 Job 产生，而由支付回调事件 `membership.renewal_result` 触发，保证金额与状态准确；本 Job 只负责 T-7 预告与 T+3 宽限提醒。

```java
        Long homeworkId = event.getHomeworkId();
        List<Long> studentIds = classMemberMapper
                .selectActiveStudentIds(event.getClassId());

        // 幂等：同一作业只扇出一次（事件可能因 MQ 重投被重复消费）
        String fanoutKey = "notify:hw_fanout:" + homeworkId;
        if (Boolean.FALSE.equals(redis.opsForValue()
                .setIfAbsent(fanoutKey, "1", Duration.ofDays(2)))) return;

        // 延迟一个撤回窗口再投递；窗口内撤回事件会删除此任务
        batchService.createBatch(BatchFanoutTask.builder()
                .taskType(TaskType.HOMEWORK_ASSIGNED)
                .homeworkId(homeworkId)
                .recipients(studentIds)
                .executeAt(Instant.now().plus(RECALL_WINDOW))
                .rateLimitPerSecond(100)
                .build());
    }
}

/**
 * 批量扇出执行器：从 notification_batch 表捞任务，限速逐用户走统一管道。
 * 45 人班级按 100/s 限速 <1s 完成；万人年级联考场景也不会打爆厂商通道。
 */
@Service
public class BatchFanoutExecutor {

    @Scheduled(fixedDelay = 5000)
    public void drain() {
        List<BatchFanoutTask> tasks = batchMapper
                .selectExecutable(Instant.now(), /*max*/20);
        for (BatchFanoutTask task : tasks) {
            batchMapper.casStatus(task.getId(), PENDING, RUNNING); // 防多实例抢占
            fanout(task);
        }
    }

    private void fanout(BatchFanoutTask task) {
        RateLimiter limiter = RateLimiter.create(task.getRateLimitPerSecond());
        for (Long studentId : task.getRecipients()) {
            limiter.acquire();
            // 单用户失败不阻断批次；失败记录进 delivery_log 由补偿任务重试
            Try.of(() -> deliverToStudent(task, studentId))
               .onFailure(e -> log.warn("扇出失败 hw={} student={}",
                       task.getHomeworkId(), studentId, e));
        }
        batchMapper.casStatus(task.getId(), RUNNING, COMPLETED);
    }
}
```

> **转班补发**：教师布置后 24h 内新转入班级的学生，由班级成员变更事件 `class.member.joined` 触发补发检查（幂等键 `hw:{homeworkId}:{studentId}` 保证不重复）。作业截止后不再补发。

### 3.7 场景七：系统公告与运营活动群发（运营手动触发型）

#### 3.7.1 公告发布状态机

```
DRAFT ──提交──▶ REVIEWING ──审核通过──▶ APPROVED ──定时──▶ SCHEDULED
  ▲                ││                        │                 │
  │  驳回           ││ 内容安全审核            │                 │ 到点
  └────────────────┘└─(命中敏感词→人工复审)    │                 ▼
                                              │        PUBLISHING（分批灰度）
                                              ▼                 │
                                         撤回（仅 PUBLISHED 前）   ▼
                                              │            PUBLISHED
                                              ▼                │
                                           REVOKED ◀──紧急下架──┘
```

| 状态 | 守卫 | 说明 |
|------|------|------|
| DRAFT→REVIEWING | 运营提交 | 必填标题/正文/受众圈选/类目 |
| REVIEWING→APPROVED | 内容安全审核通过 | 机审+人审两级，运营活动必须人审 |
| APPROVED→SCHEDULED | 定时时间设置 | 最早 = 当前时间 + 30min |
| SCHEDULED→PUBLISHING | 到点触发 | 生成 notification_batch |
| PUBLISHING→PUBLISHED | 全部批次完成 | 灰度期间可暂停 |
| PUBLISHED→REVOKED | 管理员紧急下架 | 端内通知标记 deleted；**推送栏消息无法撤回**，需评估是否补发澄清公告 |

#### 3.7.2 分批灰度群发

```java
@Service
public class AnnouncementPublishService {

    /**
     * 灰度放量：1% → 10% → 50% → 100%，每档观察 30 分钟。
     * 观察指标：通知退出率、设置页关闭推送率、投诉/反馈量。
     * 任一指标超阈 → 自动暂停放量并告警运营群。
     */
    private static final int[] RAMP_STEPS = {1, 10, 50, 100};
    private static final Duration STEP_OBSERVE = Duration.ofMinutes(30);

    public void publishNextRamp(Long announcementId) {
        Announcement ann = announcementMapper.selectById(announcementId);
        int nextPercent = resolveNextPercent(ann);

        // 圈选受众（引用用户标签与智能分群引擎）
        List<Long> audience = audienceService.selectBySegment(
                ann.getSegmentRule(), nextPercent, /*excludePublished*/true);

        // 类目分流：系统公告(SYSTEM)不受营销频控；运营活动(MARKETING)受限
        // 未成年人(<16岁)对 MARKETING 类目整体屏蔽（§11 合规红线）
        if (ann.getCategory() == NotificationCategory.MARKETING) {
            audience = audience.stream()
                    .filter(id -> !userService.isMinorUnder16(id))
                    .collect(Collectors.toList());
        }

        batchService.createBatch(BatchFanoutTask.builder()
                .taskType(TaskType.ANNOUNCEMENT)
                .announcementId(announcementId)
                .recipients(audience)
                .rateLimitPerSecond(200)      // 平滑速率：百万级 2 小时投完
                .onComplete(t -> metrics.evaluateRamp(announcementId))
                .build());
    }
}
```

### 3.8 场景八：薄弱知识点预警（事件触发型，P2）

**防焦虑设计是本场景的第一约束**：学生端文案禁止使用「差 / 落后 / 不及格」等定性词，统一使用成长型话术（「还有提升空间」「即将突破」）。

```
练习判题结果流（answer.judged）
      │
      ▼
知识点正确率滑动窗口更新（最近N次）
      │
      ├── 触发条件：同一知识点连续 3 次练习正确率 < 60%
      │
      ▼
预警防抖层（10 分钟聚合缓冲）
      │  · 同一用户多个知识点同时预警 → 合并为一条
      │  · 同一知识点 7 天内只预警 1 次（Redis SETNX kp_alert:{uid}:{kpid}:7d）
      ▼
双收件人分流
      ├──▶ 家长（主）：完整诊断版（知识点名+建议动作），深链 /parent/weak-points
      └──▶ 学生（弱化版）：仅当家长未关闭「学生可见预警」；文案=鼓励型
```

```java
@Component
public class WeakPointAlertListener {

    private static final Duration AGGREGATE_WINDOW = Duration.ofMinutes(10);

    @Async("notificationEventExecutor")
    @EventListener
    public void onAnswerJudged(AnswerJudgedEvent event) {
        // ① 滑动窗口正确率更新（Redis ZSET 存最近20次判定，TTL 30天）
        masteryWindowService.record(event.getUserId(),
                event.getKnowledgePointId(), event.isCorrect());

        // ② 触发判定：连续3次练习窗口正确率<60%
        if (!masteryWindowService.isWeakPattern(
                event.getUserId(), event.getKnowledgePointId())) return;

        // ③ 7天防重
        String key = "notify:kp_alert:%d:%d".formatted(
                event.getUserId(), event.getKnowledgePointId());
        if (Boolean.FALSE.equals(redis.opsForValue()
                .setIfAbsent(key, "1", Duration.ofDays(7)))) return;

        // ④ 进入聚合缓冲（延迟10分钟，等待同批知识点合并）
        aggregationBuffer.offer(event.getUserId(),
                event.getKnowledgePointId(), AGGREGATE_WINDOW);
    }

    /** 聚合缓冲到期冲刷：合并同用户多知识点为一条通知 */
    @Scheduled(fixedDelay = 60_000)
    public void flushAggregationBuffer() {
        aggregationBuffer.drainExpired().forEach((userId, kpIds) -> {
            List<KnowledgePointBrief> kps = kpService.getBriefs(kpIds);

            // 家长版（完整诊断）
            deliverParentVersion(userId, kps);
            // 学生版（弱化，可选）
            if (familyPrivacyService.isStudentAlertVisible(userId)) {
                deliverStudentVersion(userId, kps); // 成长型话术
            }
        });
    }
}
```

### 4.2 通道路由核心代码

```java
@Service
public class VendorChannelSelector {

    /**
     * 厂商通道选择：按设备品牌与 token 注册表路由。
     * token 注册见《服务端-多厂商推送通道适配层》——客户端启动时上报
     * (deviceId, brand, vendorToken[])，服务端维护 user → 多设备 → 多 token。
     */
    public VendorChannel resolve(PushToken token) {
        return switch (token.getBrand()) {
            case HUAWEI, HONOR -> VendorChannel.HMS;      // 华为 Push Kit
            case XIAOMI -> VendorChannel.MIPUSH;
            case OPPO -> VendorChannel.OPPUSH;
            case VIVO -> VendorChannel.VPUSH;
            default -> isOverseas(token) ? VendorChannel.FCM
                                        : VendorChannel.SELF_BUILT; // 自建长连接
        };
    }

    /**
     * 消息形态选择：
     * - 通知栏消息（厂商服务器渲染，不依赖 App 存活）→ 离线/后台必选
     * - 透传消息（App 接收后自渲染，可带大 payload）→ 仅自建通道/FCM 存活时
     */
    public PushMessageShape selectShape(VendorChannel channel,
            boolean appAlive, Notification n) {
        if (channel == VendorChannel.SELF_BUILT && appAlive) {
            return PushMessageShape.TRANSPARENT; // 透传：端上自绘横幅+自定义跳转
        }
        // 华为透传有严格频控（每日少量），通知栏消息不受限 → 离线一律通知栏
        return PushMessageShape.NOTIFICATION_BAR;
    }
}
```

## 5. 通知与投递状态机

### 5.1 通知实体状态机

```
                ┌───────── EXPIRED（到期清理，按类目保留期）
                │
ACTIVE ──read──▶ READ
  │  │
  │  └──user delete──▶ DELETED
  └──admin revoke──▶ REVOKED（公告下架/误发撤回，端内隐藏）
```

| 迁移 | 触发者 | 守卫 | 副作用 |
|------|--------|------|--------|
| ACTIVE→READ | 用户 | 存在未读记录 | 未读计数-1；多端广播 notification_read |
| ACTIVE→EXPIRED | 定时清理 | now > expire_at | 不改变已读状态；不推送 |
| ACTIVE→DELETED | 用户 | —— | 未读则计数-1；软删除 |
| ACTIVE→REVOKED | 管理员 | 仅公告/运营类 | 端内列表过滤；已推送的推送栏消息无法撤回 |
| REVOKED→ACTIVE | 管理员 | 误撤回恢复 | 重新进列表，不重推 |

### 5.2 投递记录状态机（delivery_log）

```
         ┌─(偏好关闭/频控超限/无token)──▶ SKIPPED（终态，不算失败）
         │
PENDING ─┼─(免打扰延迟)──▶ DEFERRED ──到点──▶ PENDING(重入)
         │
         └─发送──▶ SENT ──厂商回执──▶ ACKED
                      │
                      ├─可重试失败──▶ RETRYING(≤3次, 5s/30s/120s) ──▶ SENT
                      │
                      └─不可重试(token无效/模板缺失)──▶ FAILED（终态）
                                               重试耗尽──▶ GAVE_UP（进补偿对账）
```

**幂等键汇总表**（全链路防重核心）

| 场景 | 幂等键 | TTL |
|------|--------|-----|
| 学习计划每日提醒 | `notify:plan_reminder:{uid}:{yyyyMMdd}` | 30h |
| 错题到期提醒（双入口收敛） | `notify:review_reminder:{uid}:{dueDate}` | 30h |
| 成就聚合通知 | `group_key = achievement_{uid}_{date}`（DB 更新式聚合） | —— |
| 作业扇出 | `notify:hw_fanout:{homeworkId}` + `hw:{homeworkId}:{studentId}` | 2d |
| 会员到期各时点 | `notify:membership_expiry:{membershipId}:{T_x}` | 9d |
| 薄弱知识点预警 | `notify:kp_alert:{uid}:{kpid}` | 7d |
| 周报投递任务 | `delayed_task.id`（DB 主键） | —— |
| 公告批次 | `batch_id` + 受众已发集 `ann:{annId}:sent`（bitmap） | 7d |

## 7. 免打扰延迟投递机制

场景一中 `scheduleDelayed(target, nextAvailableTime)` 的落地实现：

```java
@Service
public class DeferredDeliveryService {

    private static final String ZSET_KEY = "notify:deferred";

    /** 延迟投递入队（score = 下一个可投时刻） */
    public void defer(Long userId, ReminderTarget target, Instant nextSlot) {
        redis.opsForZSet().add(ZSET_KEY,
                DeferredTaskPayload.of(userId, target),
                nextSlot.getEpochSecond());
    }

    /** 每分钟扫描到期任务，交回 ReminderProcessor（复用全部检查） */
    @Scheduled(fixedDelay = 60_000)
    public void pump() {
        var due = redis.opsForZSet().rangeByScoreWithScores(
                ZSET_KEY, 0, Instant.now().getEpochSecond(), 0, 200);
        for (var item : due) {
            redis.opsForZSet().remove(ZSET_KEY, item.getValue());
            reminderExecutor.submit(() ->
                    reminderProcessor.process(item.getValue().toTarget()));
        }
    }
}
```

**时效性分级策略**（延迟后是否仍值得投递）：

| 通知类型 | 免打扰到期后 | 依据 |
|----------|--------------|------|
| 学习计划提醒 / 错题到期提醒 | 投递（若当日未超 21:00 有效窗） | 待办次日仍有效 |
| 周报 / 报告类 | 投递 | 无时效衰减 |
| 成就解锁 | 不补推，仅端内 | 即时反馈错过即贬值，补推反而打扰 |
| 作业布置 / 截止提醒 | 投递（截止前） | 强待办 |
| 营销活动 | 不补推 | 过时营销 = 打扰 |
| URGENT 安全类（异地登录等） | 不受免打扰限制，直接投递 | 安全优先于免打扰 |

## 8. 异常补偿与对账

### 8.1 异常补偿矩阵

| # | 异常 | 检测点 | 补偿动作 |
|---|------|--------|----------|
| 1 | 通知创建后 WS 推送失败 | WS 服务 | 不重试（端内有记录），客户端心跳恢复后拉取增量 |
| 2 | Push 发送超时 | DeliveryRouter | 5s/30s/120s 三次退避重试 → GAVE_UP |
| 3 | 厂商通道 5xx | 适配层 | 指数退避 + 切换备用厂商通道（华为↔自建） |
| 4 | 厂商 token 失效回执 | 回调 | 标记 invalid；客户端启动重注册；期间端内 only |
| 5 | 模板缺失/禁用 | TemplateRenderer | 跳过 + P2 告警（模板配置错误必须人工介入） |
| 6 | 通知 DB 写成功但计数 INCR 失败 | Pipeline | 计数以 hourly 校准任务重建（见 §8.2） |
| 7 | 事件监听事务失败 | Listener | @REQUIRES_NEW + MQ 重投；幂等键保证不重复 |
| 8 | 免打扰延迟任务丢失（Redis 驱逐） | 对账任务 | 扫描 DEFERRED 超时未投递 → 重新入队或放弃 |
| 9 | 批量扇出中途实例崩溃 | BatchFanout | CAS 状态 + 已发 bitmap 断点续发 |
| 10 | 公告灰度中指标异常 | RampEvaluator | 自动暂停放量 + 运营告警 |
| 11 | 重复事件消费 | 全部 Listener | 幂等键表（§5.2）拦截 |
| 12 | 定时任务重复执行（多实例） | Job | Redis SETNX 任务锁 + 分批 offset 记录 |
| 13 | SMS 兜底发送失败 | SmsService | 仅 URGENT 类，记 failed + 人工工单 |
| 14 | 客户端通知列表与服务端不一致 | 客户端 | cursor 全量校准接口（信任服务端） |

### 8.2 每日对账任务

```java
/**
 * 三方对账：notifications(DB) × delivery_log × 厂商回执。
 * 每日 03:00 跑前一日数据，差异自动修复或生成 P2 工单。
 */
@Component
public class NotificationReconciliationJob {

    @Scheduled(cron = "0 0 3 * * ?")
    public void reconcile() {
        LocalDate day = LocalDate.now().minusDays(1);

        // ① 通知数 vs 投递日志数（SKIPPED 除外）
        reconcileCounts(day);

        // ② SENT 但 24h 无 ACKED 且厂商支持回执 → 人工抽样核查
        List<Long> suspicious = deliveryMapper.selectSentWithoutAck(day);
        if (suspicious.size() > threshold) {
            alertService.warn("推送到达率异常", Map.of("count", suspicious.size()));
        }

        // ③ 未读计数校准：Redis vs DB COUNT(is_read=0)
        counterService.rebuildFromDb(day);

        // ④ 延迟队列孤儿：DEFERRED 超过 48h 的投递任务 → 清理并计数告警
        deferredService.cleanOrphans(Duration.ofHours(48));
    }
}
```

### 8.3 管道错误码段（52200–52299）

| 错误码 | 场景 | 处理 |
|--------|------|------|
| 52201 | 通知类型未注册路由映射 | 客户端降级跳转 /notifications |
| 52202 | 模板渲染变量缺失 | 服务端跳过发送 + 告警 |
| 52203 | 幂等键冲突（重复投递被拦截） | 静默，属预期行为 |
| 52204 | 免打扰延迟队列写入失败 | 降级为放弃投递（非 URGENT） |
| 52205 | 批量扇出部分失败 | 断点续发，详见 delivery_log |
| 52206 | 公告已下架仍请求投递 | 终止批次 |
| 52210 | WS 推送失败 | 等待客户端增量拉取，不重试 |
| 52211 | 厂商通道全失败 | 降级端内 only + 告警 |
| 52212 | SMS 兜底失败 | 人工工单（仅 URGENT） |

> 投递层基础错误码（`MSG_*` 字符串码：模板缺失/频控超限/Token 无效等）沿用《消息与推送服务-详细设计》§9.1 定义，522xx 段只补充 E2E 管道编排层错误。

### 9.2 核心漏斗与 SQL

```sql
-- 前一日分类型漏斗：创建→投递→曝光→打开→转化
SELECT
  n.type,
  COUNT(*)                                            AS created,
  COUNT(d.id)                                         AS delivered,
  COUNT(d.id) FILTER (WHERE d.status = 'ACKED')       AS acked,
  COUNT(e.id) FILTER (WHERE e.name = 'notify_banner_shown') AS shown,
  COUNT(e.id) FILTER (WHERE e.name = 'notify_opened')       AS opened,
  COUNT(e.id) FILTER (WHERE e.name = 'notify_actioned')     AS actioned
FROM notifications n
LEFT JOIN delivery_logs d ON d.notification_id = n.id
LEFT JOIN events e ON e.notification_id = n.id
WHERE n.created_at >= CURRENT_DATE - 1
  AND n.created_at < CURRENT_DATE
GROUP BY n.type;
```

### 9.3 监控告警阈值

| 指标 | 基线 | 告警 |
|------|------|------|
| 事件型链路耗时（事件产生→端上横幅） | P99 < 5s | P99 > 10s 持续 5min → P2 |
| 定时型批处理完成度（时段桶内完成比例） | 100% | < 95% → P2；< 80% → P1 |
| Push 投递失败率（含重试后） | < 0.5% | > 2% → P1 |
| 厂商到达率（ACKED/SENT，支持回执的厂商） | > 85% | < 70% → P1（疑似 token 大面积失效） |
| 通知打开率（待办类） | > 12% | 连续 3 天 < 5% → 产品复盘（通知疲劳） |
| 退订率（notify_unsubscribed/created） | < 0.3% | > 1% → P2（立即检查频控配置） |

## 11. 合规红线

1. **夜间禁推**：22:00–08:00 不投递任何非 URGENT 通知（安全类豁免：异地登录、账号风险）。定时任务时段桶配置已内置该约束。
2. **未成年人营销屏蔽**：<16 岁用户对 MARKETING 类目整体不可达（公告群发侧过滤 + 投递侧二次校验双保险）。
3. **付款类通知话术**：未成年人账号的会员到期提醒只含事实（到期日/权益变化），禁止促销与紧迫感话术。
4. **自动续费预告**：自动续费 ON 用户的 T-7 通知必须包含续费价格与下次扣费日期（应用商店合规要求）。
5. **先审后发**：运营活动/公告必须机审+人审通过后才能进入 SCHEDULED；紧急下架无法撤回已投递的推送栏消息，需评估补发澄清。
6. **退订入口**：所有 MARKETING 通知的端内详情页必须提供「关闭此类通知」一键入口（notify_unsubscribed 埋点）。
7. **家长代管**：家长中心可代为关闭孩子账号的任一通知类目，子账号设置页需展示「由家长管理」状态。
8. **学生文案红线**：面向学生的诊断/预警类通知禁止负面定性词，统一成长型话术（见 §3.8）。
9. **数据最小化**：推送 payload 不含答案、成绩明文等敏感学习数据，仅含计数与深链；敏感内容进端内登录态页面。
