# 古诗文专项学习系统 - 详细设计

## 1. 模块概述

### 1.1 功能定位

面向小学高年级至高中学生，提供古诗词鉴赏、文言文阅读理解、名句默写检测、诗词创作启蒙等一站式古诗文学习服务。系统依托 AI 大模型进行分级讲解、逐句翻译、意象分析和默写批改，结合教材课标同步进度和考试高频篇目，形成"学-背-练-测-用"完整闭环。

### 1.2 目标用户与需求矩阵

| 学段 | 年级 | 核心需求 | 考试关联 |
|------|------|----------|----------|
| 小学高年级 | 4-6年级 | 古诗词背诵、诗意理解、名句默写 | 小升初素养考查 |
| 初中 | 7-9年级 | 课内古诗精讲、文言文阅读、鉴赏答题技巧 | 中考语文占分20-25% |
| 高中 | 10-12年级 | 文言文实词虚词、古诗词鉴赏、比较阅读、名句名篇 | 高考语文占分15-20% |

### 1.3 设计原则

1. **教材同步**：按教材版本、年级、单元组织篇目，覆盖人教版、苏教版、北师大版等主流教材
2. **分级讲解**：小学用通俗语言，初中增加鉴赏术语，高中引入学术化表达
3. **默写驱动**：以"背得准、写得对"为核心目标，强化易错字辨析
4. **意象串联**：通过常见意象（月、柳、雁、梅等）构建跨篇目知识网络
5. **考试导向**：紧贴中考/高考题型，提供鉴赏题答题模板和训练

## 3. 数据结构设计

### 3.1 篇目主表

```sql
CREATE TABLE poem (
    id                BIGINT PRIMARY KEY AUTO_INCREMENT,
    title             VARCHAR(128) NOT NULL COMMENT '篇名',
    author_id         BIGINT COMMENT '作者ID，关联poem_author表',
    dynasty           VARCHAR(16) NOT NULL COMMENT '朝代：唐/宋/元/明/清/先秦/汉/魏晋/南北朝/现代',
    poem_type         VARCHAR(16) NOT NULL COMMENT 'poem/ci/qu/fu/prose',
    content_original  TEXT NOT NULL COMMENT '原文（繁体或简体原文）',
    content_simplified TEXT NOT NULL COMMENT '简体中文原文',
    content_lines     JSON NOT NULL COMMENT '分行数据，结构见3.2',
    translation       TEXT COMMENT '全文白话译文',
    annotation        JSON COMMENT '注释列表，结构见3.3',
    appreciation      TEXT COMMENT '赏析正文（富文本）',
    background        TEXT COMMENT '写作背景',
    themes            JSON COMMENT '["思乡","爱国","田园"]',
    imagery_tags      JSON COMMENT '意象标签 ["moon","willow","plum"]',
    technique_tags    JSON COMMENT '表达技巧 ["比喻","借景抒情","对仗"]',
    emotion_tags      JSON COMMENT '情感标签 ["悲凉","豪迈","婉约"]',
    difficulty        TINYINT DEFAULT 3 COMMENT '难度等级1-5',
    stage_tags        JSON COMMENT '适用学段 ["primary_high","junior","senior"]',
    source_tags       JSON COMMENT '来源标签 ["textbook","exam_high_freq","classic"]',
    exam_frequency    TINYINT DEFAULT 0 COMMENT '考试出现频率0-5',
    recite_requirement VARCHAR(16) DEFAULT 'none' COMMENT 'none/recommended/required 全篇必背/推荐背诵',
    word_count        INT COMMENT '正文字数',
    status            TINYINT DEFAULT 1,
    version           INT DEFAULT 1,
    created_at        DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_author (author_id),
    INDEX idx_dynasty (dynasty),
    INDEX idx_type (poem_type),
    INDEX idx_difficulty (difficulty),
    FULLTEXT idx_title_content (title, content_simplified)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='古诗文篇目';
```

## 5. AI 讲解生成与缓存策略

### 5.1 讲解类型与生成时机

| targetType | 内容 | 生成时机 | 预估占比 |
| --- | --- | --- | --- |
| line | 逐句讲解（字面义/手法/情感） | 篇目详情首次请求该行时 | 60% |
| word | 文言字词讲解 | 首次点击标注词时 | 15% |
| appreciation | 全篇鉴赏引导 | 篇目详情页「鉴赏」Tab 首次展开 | 10% |
| pattern | 表达技巧分析 | 鉴赏训练首次触发 | 10% |
| creation_guide | 仿写/创作启蒙 | 用户主动点击「我也写一句」 | 5% |

### 5.2 Prompt 编排与学段适配

- 模板变量：`{poemContent}`、`{targetRef}`、`{annotation}`、`{stageProfile}`、`{quoteConstraint}`。
- `stageProfile` 三档：primary_high（短句、生活化、多举例）、junior（术语适度、手法+情感分层）、senior（术语完整、命题视角、比较鉴赏）。
- `quoteConstraint`：强制要求讲解中引用的原句必须逐字来自 `content_original`，并要求模型输出 JSON 结构（`contentMd` + `quotes[]`），供 5.3 校验。
- Prompt 模板纳入统一 Prompt 版本管理（见《服务端-Prompt版本管理与效果回归评估引擎》），`prompt_version` 变更即触发 5.5 的缓存刷新评估。

### 5.3 生成管线与校验

```
请求 → 缓存查询(5.4) → 未命中 → 组装Prompt → LLM生成(JSON)
     → 引用校验(quotes 逐字比对 content_original) → 安全过滤
     → 通过 → 写入 poem_explain_cache(quote_verified=1)
     → 引用不匹配 → 重试一次(附纠错指令) → 仍失败 → 降级：只返回结构化静态数据，标记 quote_verified=0 不入缓存
```

- 安全过滤复用大模型流式输出安全过滤中间件；`safety_status=replaced/blocked` 的内容不入缓存。
- 生成失败重试走统一 AI 多模型容灾链路，不本模块自建。

### 5.4 缓存策略

1. **命中路径（读）：** `uk_cache(poem_id, target_type, target_ref, stage_tag, prompt_version)` 主键查询，Redis 前置缓存 `poem:explain:{poemId}:{targetType}:{targetRef}:{stageTag}:{promptVersion}`，TTL 24h，DB 兜底。目标命中率 ≥ 95%（教材同步篇目）。
2. **预热：** 新学期教材章节解锁时，对 `isRequiredRecite=true` 篇目的全部 line 讲解按学生学段批量预生成（夜间批量任务，限速调用）；考试高频篇目（`exam_frequency>=4`）全量预热。
3. **非会员差异：** 非会员 line 讲解缓存只读不生成增量（引导升级），创作启蒙 creation_guide 仅会员可触发。
4. **指标：** 命中率、生成 P95、单篇目讲解成本（Token 计量归集到 AI 模型调用成本服务）。

### 5.5 缓存失效与刷新

| 触发源 | 动作 |
| --- | --- |
| 篇目内容修订（原文/注释变更） | 该 poem_id 全部缓存 `status=0`，按需重新生成 |
| prompt_version 升级 | 新版本并行生成，旧版本保留 7 天供灰度回退，随后下线 |
| 纠错反馈达阈值（4.6.2） | 该条目 `status=0`，进入人工复核，复核通过前返回静态数据 |
| 安全抽查不通过 | 该条目 `safety_status=blocked`，立即失效并上报内容安全 |

## 6. 复习调度算法与状态流转

### 6.1 篇目学习状态机

```
not_started ──(首次学习行为)──> learning
learning ──(explain_coverage >= 0.8 且完成任一模式检测)──> reciting
reciting ──(full 模式得分 >= 80)──> mastered
mastered ──(到期复习得分 < 80)──> decaying
mastered ──(到期复习得分 >= 80)──> mastered（仅更新 SM-2 参数）
decaying ──(full 模式得分 >= 80)──> mastered
decaying ──(full 模式得分 < 80)──> decaying（lapse_count+1，间隔重置）
```

- `learning → reciting` 的 `explain_coverage = 已讲解行数 / 必背行数`，由讲解阅读行为（4.6.1 的 `line` 请求）累积。
- 状态变更写入事件流（`poem_progress.changed`），供学情分析与复习提醒消费。

### 6.2 综合掌握度计算（mastery 字段）

```
mastery = 0.45 × dictationScoreN
        + 0.25 × explainCoverage
        + 0.30 × memoryStabilityN

dictationScoreN = min(full模式历史最高分 / 100, 1)   // 无记录则为 0
memoryStabilityN = min(stability / 21, 1)            // 21 天稳定期视为满分
lapse 惩罚：mastery = mastery × (1 − 0.1 × min(lapse_count, 3))
```

取值 0–1，随每次复习结果事务内重算，供学情分析（薄弱点识别）与推荐（复习优先级）消费。

### 6.3 SM-2 参数更新算法

quality 映射：full 默写得分 ≥95 → easy(4)；≥80 → good(3)；≥60 → hard(2)；<60 → again(0)；manual 自评直接取 again/hard/good/easy。

```java
public ReviewOutcome applySm2(Progress p, int quality) {
    if (quality < 3) {                       // again/hard：判为遗忘
        p.repetition = 0;
        p.intervalDays = (quality == 0) ? 0 : 1;   // again 当天重现，hard 次日
        p.easeFactor = Math.max(1.3, p.easeFactor - 0.20);
        p.lapseCount += 1;
    } else {
        p.repetition += 1;
        if (p.repetition == 1)      p.intervalDays = 1;
        else if (p.repetition == 2) p.intervalDays = 6;
        else p.intervalDays = (int) Math.round(p.intervalDays * p.easeFactor);
        p.easeFactor = clamp(p.easeFactor + delta(quality), 1.3, 2.8);
        // delta: good=0, easy=+0.10（本实现将 again/hard 的系数下调并入遗忘分支）
    }
    p.stability = max(p.stability, p.intervalDays); // 稳定性只增，遗忘分支不改
    p.nextReviewAt = now().plusDays(p.intervalDays)
                          .plusJitterHours(0, 12);  // 防同批篇目同时到期
    return outcome(p);
}
```

- `intervalDays=0` 表示当日需重现，进 4.4.2 队列顶部。
- 状态流转（6.1）在 SM-2 更新同一事务内执行，避免状态与参数不一致。

### 6.4 易错字训练状态机与数据流

```
默写/填空提交(4.2.2) --错误字--> upsert weak_word_drill(status=new/训练中)
new/training/reactivated --选对--> consecutive_correct+1 --达到3--> conquered
conquered --后续任意检测再错--> reactivated（wrong_count 续加，consecutive_correct 清零）
next_drill_at 间隔：错后 +1天 → 连对1次 +3天 → 连对2次 +7天（conquered 后出队）
```

- upsert 冲突键 `uk_user_char`；同一字多处错误合并为一条（保留首次出错的行号/字位）。
- `conquered` 的字不进入日常队列，仅保留作学情统计与「曾经易错」标记。

## 7. 错误处理

| 错误码 | 场景 | 处理策略 |
| --- | --- | --- |
| POEM_NOT_FOUND | 篇目不存在/下架 | 404，客户端展示空态并引导返回列表 |
| DICTATION_ANSWER_MALFORMED | 行号越界、答案含非中文字符 | 400，提示重新输入；不产生记录 |
| DICTATION_LINE_COUNT_MISMATCH | 提交行数与 requiredLines 不符 | 400（缺行按 missing 批改的宽松模式需显式传 `allowPartial=true`） |
| EXPLAIN_GENERATE_FAILED | LLM 两次重试仍失败 | 返回静态结构化数据 + 降级提示，任务不重试风暴（熔断走统一 AI 管线） |
| EXPLAIN_UNDER_REVIEW | 缓存失效且待复核 | 返回静态数据，隐藏 AI 讲解入口 |
| MEMBER_LIMIT_REACHED | 非会员触发会员专属讲解 | 统一额度管控错误码，客户端弹权益引导（不打断学习主流程） |
| REVIEW_CONFLICT | 并发重复提交复习结果 | 以先到者为准，后到幂等返回首次结果（请求携带 recordId 去重） |

通用约定：所有接口错误响应遵循《服务端统一业务异常码与错误分类体系》，本表仅列模块特有码段。

## 9. 性能要求

| 接口 | 目标 | 说明 |
| --- | --- | --- |
| 篇目详情/列表 | P95 < 300ms | 静态内容 CDN + Redis 缓存 |
| 默写批改提交（4.2.2） | P95 < 500ms | 字级比对为纯本地计算，仅落库与事件外发异步 |
| 到期复习队列（4.4.2） | P95 < 200ms | `(user_id, next_review_at)` 索引直查 |
| AI 讲解命中（4.6.1） | P95 < 300ms | Redis 命中路径 |
| AI 讲解未命中 | 首 token < 3s | 走统一大模型推理管线，异步任务化 |
| 弱网 | 默写作答支持离线 | 本地暂存答案，恢复后按行号幂等补交 |
