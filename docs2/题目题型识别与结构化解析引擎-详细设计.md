## 1. 模块概述

### 1.1 功能定位

题目题型识别与结构化解析引擎是拍照搜题、AI辅导、题库管理等多个上游模块的**核心中间件**。它将原始题目文本（OCR 输出或手动输入）转化为结构化的题目对象，自动识别题型、提取关键组成部分（题干、选项、公式、图形引用、条件、问题），并映射到对应的解题策略模板。

**一句话定位：** 把一段"毛坯题目文本"变成"机器可理解、AI可解题的结构化题目对象"。

### 1.2 在系统中的位置

```
┌─────────────┐     原始文本/图片     ┌──────────────────────────┐     结构化题目      ┌──────────────────┐
│  图片OCR管线  │ ─────────────────→  │                          │ ────────────────→  │  AI解题引擎       │
│  用户手动输入  │                     │  题目题型识别与结构化解析  │                    │  题库服务         │
│  题库批量导入  │                     │  引擎（本模块）            │                    │  同类题推荐       │
│  AI对话提取   │                     │                          │                    │  错题归因         │
└─────────────┘                      └──────────────────────────┘                    └──────────────────┘
```

### 1.3 核心能力

| 能力 | 说明 | 优先级 |
|------|------|--------|
| 题型自动分类 | 识别选择题、填空题、解答题、证明题等 15+ 种题型 | P0 |
| 题干提取 | 分离题干、选项、条件、问题 | P0 |
| 公式检测与 LaTeX 转换 | 识别行内/行间公式，转换为 LaTeX | P0 |
| 图形/表格引用检测 | 标记题目中引用的图形、表格、电路图等 | P1 |
| 多题分割 | 一张图片中识别多道题并逐一分割 | P0 |
| 学科自动识别 | 根据题目内容判断所属学科 | P1 |
| 解题策略路由 | 根据题型+学科映射到对应 Prompt 模板 | P0 |
| 置信度评估 | 输出每个字段的识别置信度 | P1 |

### 1.4 目标指标

| 指标 | 目标值 |
|------|--------|
| 题型分类准确率 | ≥ 95% |
| 题干提取完整率 | ≥ 92% |
| 公式识别准确率 | ≥ 90%（印刷体）/ ≥ 80%（手写体） |
| 单题解析耗时 | ≤ 500ms（不含 LLM 调用）/ ≤ 3s（含 LLM 调用） |
| 多题分割准确率 | ≥ 90% |

### 2.2 题型分类规则

题型分类采用**规则引擎 + LLM 辅助**的混合策略：

```
                    输入原始题目文本
                          │
                    ┌─────▼──────┐
                    │  规则预分类  │  ← 正则匹配 + 关键词检测
                    └─────┬──────┘
                          │
               ┌──────────┼──────────┐
               │          │          │
         置信度 ≥ 0.85  0.5~0.85   < 0.5
               │          │          │
          ┌────▼───┐ ┌───▼────┐ ┌──▼──────┐
          │ 直接采用 │ │LLM辅助  │ │LLM主导  │
          │ 分类结果 │ │分类确认 │ │全量解析 │
          └────────┘ └───┬────┘ └──┬──────┘
                         │         │
                    ┌────▼─────────▼────┐
                    │   分类结果输出      │
                    │   + 置信度分数     │
                    └───────────────────┘
```

**规则引擎关键词表（示例）：**

```typescript
interface TypeRule {
  type: QuestionType;
  patterns: RegExp[];
  negativePatterns?: RegExp[];  // 排除模式
  priority: number;              // 优先级，数字越小越优先
}

const TYPE_RULES: TypeRule[] = [
  {
    type: QuestionType.MULTI_CHOICE,
    patterns: [/下列.*正确的是/g, /下列.*正确的[有有几]/g, /可能[是的].*?选项/g],
    negativePatterns: [/只有一个.*正确/g],
    priority: 1,
  },
  {
    type: QuestionType.SINGLE_CHOICE,
    patterns: [/^[A-D][.．、)\s]/m, /选[出择].*?选项/g, /正确答案是/g],
    priority: 2,
  },
  {
    type: QuestionType.TRUE_FALSE,

    priority: 3,
  },
  {
```

## 3. 结构化解析数据模型

### 3.1 核心数据结构

#### 结构化题目（StructuredQuestion）

```typescript
/**
 * 结构化题目 —— 本引擎的核心输出
 *
 * 设计原则：
 * 1. 所有字段可选，解析引擎尽力填充
 * 2. 每个字段带置信度，下游按需使用
 * 3. 保留原始文本，便于回溯和人工修正
 */
interface StructuredQuestion {
  /** 唯一标识（由引擎生成，格式：sq_{timestamp}_{hash8}） */
  id: string;

  // ──── 元信息 ────
  /** 原始文本（OCR 输出或手动输入的完整题目文本） */
  rawText: string;
  /** 来源 */
  source: 'ocr' | 'manual_input' | 'import' | 'ai_extract';
  /** OCR 图片 URL（如有） */
  sourceImageUrl?: string;
  /** 解析引擎版本 */
  parserVersion: string;
  /** 解析时间戳 */
  parsedAt: number;

  // ──── 题型分类 ────
  typeClassification: TypeClassificationResult;

  // ──── 学科信息 ────
  /** 检测到的学科 */
  detectedSubject?: SubjectCode;
  /** 学科置信度 */
  subjectConfidence?: number;

  // ──── 题目组成部分 ────
  /** 题干（不含选项、不含子题标记） */
  stem: StemSection;
  /** 选项（选择题/判断题） */
  options?: OptionSection;
  /** 填空位（填空题） */
  blanks?: BlankSection[];
  /** 条件（已知条件列表） */
  conditions?: ConditionSection;
  /** 提问部分（"求..." / "问..." / "证明..."） */
  questions: QuestionSection[];
  /** 图形/表格引用 */
  mediaRefs?: MediaRef[];

  // ──── 公式信息 ────
  /** 检测到的所有公式 */
  formulas: FormulaBlock[];

  // ──── 子题（复合题时） ────
  subQuestions?: StructuredQuestion[];

  // ──── 解析元数据 ────
  /** 解析置信度（整体，0~1） */
  overallConfidence: number;
  /** 解析过程中是否使用了 LLM */
  usedLLM: boolean;
  /** 解析耗时 ms */
  parseTimeMs: number;
  /** 人工修正记录 */
  manualCorrections?: ManualCorrection[];
}

type SubjectCode = 'math' | 'physics' | 'chemistry' | 'biology'
                 | 'chinese' | 'english' | 'history' | 'geography' | 'politics';
```

#### 条件（ConditionSection）

```typescript
interface ConditionSection {
  /** 已知条件列表 */
  items: ConditionItem[];
  /** 置信度 */

}

interface ConditionItem {
  /** 条件文本 */
  text: string;
  /** 条件文本（带公式） */
  formattedText: string;
  /** 条件类型 */
  type: 'given' | 'constraint' | 'assumption' | 'definition';
  /**
   * 条件类型说明：
   * - given: 已知条件（"已知AB=5"）
   * - constraint: 约束条件（"且x>0"）
   * - assumption: 假设（"假设函数f(x)可导"）
   * - definition: 定义/设定（"设集合A={1,2,3}"）
   */
  formulaIndices: number[];
  /** 可提取的变量赋值（用于数值计算） */
  extractedValues?: ExtractedValue[];
}

interface ExtractedValue {
  variable: string;   // 变量名，如 "AB", "x"
  value: string;      // 值，如 "5", "3.14"
  unit?: string;      // 单位，如 "m", "kg"
  confidence: number;
}
```

```sql
CREATE TABLE parsed_questions (
    id                  VARCHAR(64) PRIMARY KEY COMMENT 'sq_{timestamp}_{hash8}',
    raw_text            TEXT NOT NULL COMMENT '原始题目文本',

    question_type       VARCHAR(32) NOT NULL COMMENT '题型枚举值',
    type_confidence     DECIMAL(3,2) NOT NULL COMMENT '题型置信度',
    type_source         VARCHAR(16) NOT NULL COMMENT 'rule/llm_assisted/llm_primary',
    is_composite        TINYINT DEFAULT 0,
    sub_question_count  INT DEFAULT 0,
    structured_data     JSON NOT NULL COMMENT '完整 StructuredQuestion JSON',
    overall_confidence  DECIMAL(3,2) NOT NULL COMMENT '整体解析置信度',
    used_llm            TINYINT DEFAULT 0,
    parse_time_ms       INT COMMENT '解析耗时',
    parser_version      VARCHAR(16) NOT NULL,
    has_manual_correction TINYINT DEFAULT 0,
    created_at          DATETIME DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_type (question_type),

    INDEX idx_confidence (overall_confidence),
    INDEX idx_source (source),
    INDEX idx_created (created_at)
```

### 4.2 入口模式与预处理（Stage 1）

#### 4.2.1 三种入口模式

| 入口模式 | 触发来源 | Stage 2 多题分割 | Stage 4 公式来源 | 时效要求 | 扣额 |
|---------|---------|----------------|----------------|---------|------|
| `ENTRY_OCR` | OCR 管线异步任务 / 编排服务 `parse_batch` | 跳过（OCR §3.5 已分割，仅做文本级边界二次校验） | 回收 `{{formula:n}}` 占位符与 OCR 公式 LaTeX | 同步 ≤600ms | 不扣（OCR 任务已计） |
| `ENTRY_TEXT` | 客户端手动输入 / AI 对话 `ai_extract` | 执行 | 文本启发式检测 + 公式服务（可选） | 同步 ≤600ms | 手动输入免费，AI 提取计 AI 侧 |
| `ENTRY_IMPORT` | 题库批量导入（题库生产管线） | 执行 | 文本启发式 + 可选公式 OCR（异步无强预算） | 异步批任务，单题 ≤5s | 导入工单成本中心归集 |

> **OCR 粗分类强先验注入**：`ENTRY_OCR` 模式下，OCR 管线输出的 8 类粗分类（`SINGLE_CHOICE/MULTI_CHOICE/FILL_BLANK/TRUE_FALSE/SHORT_ANSWER/COMPUTE/PROOF/COMPOSITE`）映射到本引擎细类候选集（见 §4.4.2 映射表），Stage 3 规则引擎**仅在该候选集内仲裁**，禁止把 OCR 高置信粗分类改判到集合外（守卫 G3）；仅在规则置信度 < 0.5 且 LLM 确认时才允许越集改判，并在 warnings 中记录 `coarseTypeOverridden`。

#### 4.2.2 文本清洗规则表

| 规则 | 输入示例 → 输出示例 | 说明 |
|------|---------------------|------|
| R1 全半角统一 | `ＡＢＣ１２３` → `ABC123`；`（１）` → `(1)` | 全角字母/数字/括号转半角，句读保留全角 |
| R2 OCR 形近字映射 | `l→1`（数字上下文）、`O→0`（数字上下文）、`rn→m` | 仅在"前后均为数字/运算符"的局部上下文内替换，避免误伤英文 |
| R3 水印/噪声行剔除 | 行匹配 `^\s*(来源[:：].*|某某教育.*|第\s*\d+\s*页.*|\d{1,4}\s*[/-]\s*\d{1,2}\s*[/-]\s*\d{1,4})\s*$` | 整行删除，记入 `noiseLines` 供回查 |
| R4 题号前缀剥离 | `5．计算…` → `计算…`（题号存 `questionNo`） | 剥离模式与 OCR §3.5 五类题号模式库同源 |
| R5 不可见字符清理 | 零宽字符 `\u200b\u200c\u200d`、BOM、软换行 | 直接删除 |
| R6 空白折叠 | 连续空格/Tab → 单空格；保留单换行结构 | 换行是段落结构信号，不可折叠 |

```python
class TextPreprocessor:
    """Stage 1 预处理器：幂等、纯 CPU、单题 ≤20ms"""

    # 数字上下文形近字映射（R2）：仅当左右邻字符均为 [0-9+\-*/=^().,%] 或行首尾时替换
    _NUM_CTX_CHAR_RE = re.compile(r'(?:(?<=^[0-9+\-*/=^().,%\s])|(?<=[0-9+\-*/=^().,%]))[lOo](?=[0-9+\-*/=^().,%\s]|$)')
    _WATERMARK_RE = re.compile(
        r'^\s*(?:来源[:：].*|.*教育.*|第\s*\d+\s*页.*|\d{4}\s*[-/年]\s*\d{1,2}\s*[-/月]\s*\d{1,2})\s*$'
    )

    def clean(self, raw: str, source: str) -> CleanResult:
        text = self._normalize_width(raw)                    # R1
        if source == 'ocr':
            text = self._fix_ocr_chars(text)                 # R2（仅 OCR 来源）
        lines, noise = [], []
        for ln in text.split('\n'):                          # R3/R5/R6
            s = self._strip_invisible(ln).strip()
            if self._WATERMARK_RE.match(s):
                noise.append(s); continue
            lines.append(s)
        cleaned, question_no = self._strip_question_no('\n'.join(lines))   # R4
        return CleanResult(cleanedText=cleaned, questionNo=question_no, noiseLines=noise)
```

### 4.3 多题分割（Stage 2，仅 ENTRY_TEXT / ENTRY_IMPORT）

与《图片处理与OCR识别管线》§3.5 的分工：**图像入口的分割由 OCR 管线负责**（正则+视觉双通道，含 bbox 裁剪），本引擎不重复执行；本引擎的文本级分割服务于纯文本入口，规则与 OCR §3.5 五类题号模式库**同源复用**（单一规则文件 `split_patterns.yaml` 双端引用，避免规则漂移）。

文本级分割的补充规则（OCR 视觉通道不可用时的兜底）：

| 规则 | 说明 |
|------|------|
| S1 新题起始判定 | 行首匹配题号模式 `^\s*(\d{1,3})[.、．)）]\s*\S` 且上一题已有实质内容（≥10 字符） |
| S2 选项跨题截断保护 | 若切分点落在选项 A-D 区间内（上一段已有 ≥2 个选项且当前段以选项字母开头），不在此切分，向后找非选项行 |
| S3 子题不升格 | `(1)(2)` / `①②` 编号层级不切分为新题，作为 COMPOSITE 子题处理（见 §4.9） |
| S4 篇幅突变 | 相邻块长度比 > 8:1 且长块含 2 个以上题号模式时触发二次切分复核 |
| S5 上限保护 | 单次最多切 10 题，超出部分合并入末题并标 `splitTruncated`（与 OCR 管线 10 题上限一致） |

```python
def split_questions(cleaned: str) -> list[QuestionBlock]:
    """文本级多题分割。返回块列表，每块含 startOffset/endOffset/text/questionNo。"""
    blocks = _split_by_numbered_lines(cleaned)          # S1，模式库同源 OCR §3.5
    blocks = _merge_option_spillover(blocks)            # S2
    blocks = _refine_length_anomaly(blocks)             # S4
    if len(blocks) > 10:                                # S5
        blocks = blocks[:9] + [merge(blocks[9:], truncated=True)]
    return blocks
```

### 4.4 题型分类实现（Stage 3）

#### 4.4.1 规则评分器

对 §2.2 的 `TYPE_RULES` 逐条打分后合成置信度，而非首中即返回：

```python
def classify_by_rules(text: str, coarse: CoarseType | None) -> RuleScore:
    """规则评分器。
    score(type) = Σ(hit_i × weight_i) − Σ(neg_hit_j × 0.5) 后做 min-max 归一；
    confidence = top1_score / (top1 + top2 + ε)，并按证据条数打折：
      证据 1 条 ×0.75，2 条 ×0.9，≥3 条 ×1.0（防单规则误判高置信）。
    """
    candidates = COARSE_TO_FINE.get(coarse, ALL_TYPES) if coarse else ALL_TYPES   # G3 候选集约束
    scores = {}
    for rule in TYPE_RULES:
        if rule.type not in candidates:
            continue
        hits = sum(1 for p in rule.patterns if p.search(text))
        negs = sum(1 for p in (rule.negativePatterns or []) if p.search(text))
        if hits:
            scores[rule.type] = scores.get(rule.type, 0) + hits * (1.0 / rule.priority)
        if negs:
            scores[rule.type] = scores.get(rule.type, 0) - negs * 0.5
    ranked = sorted(((t, max(s, 0)) for t, s in scores.items()), key=lambda x: -x[1])
    if not ranked or ranked[0][1] <= 0:
        return RuleScore UNKNOWN_CONF=0.35                       # 无证据 → 待 LLM 主导
    top1, top2 = ranked[0][1], (ranked[1][1] if len(ranked) > 1 else 0)
    conf = top1 / (top1 + top2 + 1e-6)
    conf *= {1: 0.75, 2: 0.9}.get(evidence_count(top1), 1.0)
    return RuleScore(primary=ranked[0][0], confidence=min(conf, 0.98), candidates=ranked[:3])
```

**置信度分流**（对齐 §2.2 流程图）：

| 规则置信度 | 路径 | 行为 |
|-----------|------|------|
| ≥ 0.85 | 直接采用 | `source='rule'`，不调 LLM |
| 0.50 ~ 0.85 | LLM 辅助确认 | 同步返回规则结果（`source='rule'`），异步 LLM 复核，分歧>阈值时 PATCH 修订（§4.12） |
| < 0.50 | LLM 主导 | 同步返回 UNKNOWN+规则候选（`source='rule'`，低置信标记），ASYNC_DEEP 完成后 PATCH 修订 |

### 4.5 公式检测与 LaTeX 转换（Stage 4）

#### 4.5.1 三条公式来源

| 来源 | 适用入口 | 处理 |
|------|---------|------|
| F1 OCR 占位符回收 | `ENTRY_OCR` | 解析 `stemText` 中的 `{{formula:n}}`，按 n 取 OCR `formulas[n].latex` 直接生成 FormulaBlock（confidence、engine 透传），**不重复调公式识别** |
| F2 文本启发式检测 | `ENTRY_TEXT` / `ENTRY_IMPORT` | 下表规则检测公式片段，调《学科公式LaTeX统一解析与多端渲染管线引擎》文本转换服务 |
| F3 手写图片引用 | 任一 | `{{figure:n}}` 的 figureType ∈ {FORMULA_IMG} 时标记为公式图，仅建 MediaRef 不猜 LaTeX（低置信猜错代价高），由 AI 解题侧多模态处理 |

#### 4.5.2 文本启发式公式检测规则（F2）

| 规则 | 模式 | 公式类型 |
|------|------|---------|
| T1 行间独立公式 | 整行为 `^[=+\-±×÷^√∑∫\dxyf(x)…]+$` 且含 ≥2 个运算符 | equation/expression |
| T2 行内上标下标 | `x²`/`aⁿ`/`H₂O`（Unicode 上下标字符） | expression/chemical |
| T3 分数线替代 | `a/b` 且 a、b 为数字或单字母 ×≥1 次 | expression |
| T4 函数记号 | `f(x)`/`y=`/`sin/cos/tan/log/ln` 开头片段 | function_def |
| T5 不等式链 | `>`/`<`/`≥`/`≤`/`≠` 连接两个 T1-T4 片段 | inequality |
| T6 化学方程式 | `[A-Z][a-z]?(\d*[±]?)+…(→|=)[^=]+=?$` 且元素符号全部合法（元素周期表校验） | chemical |

#### 4.5.3 LaTeX 合法性校验与自动修复

```python
def validate_and_fix_latex(latex: str) -> tuple[str, bool]:
    """返回 (修复后 latex, latexValid)。修复规则按序尝试，全部失败则标 latexValid=False。"""
    fixes = [
        (r'\\left\s*$', r''),                     # R1 悬挂 \left
        (r'\{([^{}]*)\}([_^])\{([^{}]*)\}', r'{\1}\2{\3}'),  # R2 幂/下标花括号规范化
        (r'([a-zA-Z0-9])\^([a-zA-Z0-9])\b', r'\1^\2'),       # R3 单字符幂补花括号（防歧义）
        (r'\\frac\{([^{}]+)\}', r'\\frac{\1}{1}'),           # R4 \frac 缺分母补 {1} 并 warnings 标记
    ]
    fixed = latex
    for pat, rep in fixes:
        fixed = re.sub(pat, rep, fixed)
    balanced = all(fixed.count(o) == fixed.count(c) for o, c in (('{', '}'), ('\\left', '\\right')))
    ok = balanced and katex_try_parse(fixed, timeout_ms=30)   # 嵌入式 KaTeX 试解析
    return fixed, ok
```

> `latexValid=False` 的公式照常输出（AI 解题仍可用原文），但客户端渲染降级为代码块展示，且不参与相似度 SimHash 特征（防错误 LaTeX 污染去重）。

### 4.6 组成部分提取（Stage 5）

#### 4.6.1 题干/选项切分

```python
OPTION_LINE_RE = re.compile(
    r'^(?P<label>[A-Da-d①-④Ⅰ-Ⅳ甲乙丙丁])\s*[.、．)）:]\s*(?P<text>\S.*)$'
)

def split_stem_options(lines: list[str]) -> tuple[str, list[OptionItem]]:
    """从后向前扫描选项行：收集连续选项（允许中间空行/公式行），
    其余部分为题干。跨行选项合并：选项行后紧跟的非选项非空行，
    若不以题号/新选项开头则并入该选项文本（对齐 OCR §3.5 选项跨题截断修复）。"""
    options, i = [], len(lines)
    while i > 0:
        i -= 1
        m = OPTION_LINE_RE.match(lines[i])
        if m or (options and lines[i].strip() and not is_new_question_start(lines[i])):
            if m:
                options.append(OptionItem(label=norm_label(m['label']), text=m['text']))
            else:
                options[-1].text = lines[i].strip() + options[-1].text   # 跨行选项前接合并
        elif options:
            break                                                        # 题干边界
    options.reverse()
    stem = '\n'.join(lines[: i + 1]).strip()
    return stem, options
```

选项格式判定：`A_B_C_D` / `①_②_③_④` / `甲_乙_丙_丁`（按 label 集合自动识别写入 `OptionSection.format`）；`hasSpecialOption` 匹配 `以上都(对|正确|不|错)|都不(对|正确)|无法确定`。

### 4.7 学科识别（Stage 6）

三路证据合成：

```python
def detect_subject(sq_ctx) -> tuple[SubjectCode | None, float]:
    # E1 特征词典：学科 → (词, 权重) 词典，AC 自动机一次扫描全部命中，加权求和
    #    例：math: 抛物线(3)/定理(1)/方程(2)；chemistry: 溶液(3)/摩尔(3)/离子(2)；
    #        chinese: 之乎者也(2)/下列加点字(3)；english: 完形填空(4)/阅读理解(3)
    e1 = ac_dict_scan(sq_ctx.text)                       # {subject: score}
    # E2 字符分布：希腊字母ΣΔθ→math/physics；汉字密度>0.8 且无公式→文科；
    #    英文词占比>0.6 且句长>12 词→english；化学元素大写连写→chemistry
    e2 = char_distribution(text)
    # E3 题型先验 P(subject|type)：由 QUESTION_TYPE_SUBJECT_MAP 导出的均匀先验
    e3 = type_prior(sq_ctx.questionType)
    # 合成：logits = w1·softmax(e1) + w2·softmax(e2) + w3·log(e3+ε)，w=(0.55,0.25,0.20)
    # 合法性过滤：题型-学科非法组合直接置 -inf（如 CLOZE 只能 english）
    # 上游强约束：编排服务已传 subject（用户选择/教材上下文）时，直接采用并置 subjectConfidence=0.99，本阶段仅校验题型合法性并告警
    return argmax_normalize(logits)
```

### 4.8 置信度汇总与输出组装（Stage 7）

**overallConfidence 加权公式**（无该字段时其权重归一化到题干/题型）：

| 分量 | 权重 | 来源 |
|------|------|------|
| 题型分类 confidence | 0.30 | Stage 3 |
| 题干提取 confidence | 0.25 | Stage 5（选项/条件切分边界清晰度） |
| 公式最小 confidence | 0.20 | Stage 4（无公式时归零并重归一） |
| 学科 confidence | 0.10 | Stage 6 |
| OCR ocrConfidence | 0.15 | 上游（仅 ENTRY_OCR；文本入口重归一） |

**partial 输出策略**：任一 Stage 抛异常不中断整体——捕获后该字段置空、`warnings` 追加 `stage{N}_degraded:{error_code}`，其余字段照常输出；仅当 Stage 1/3 双双失败才返回 `PARSE_FAIL`（对齐编排 P3 降级：原始 OCR 文本直接送 AI）。

### 4.9 复合题递归处理

```python
def parse_composite(block: str, depth: int = 0) -> StructuredQuestion:
    """COMPOSITE 递归拆解。深度上限 2（材料→大题→小问），超限拍平为 QuestionSection 列表。"""
    material, subs = split_material_and_subquestions(block)   # 公共材料段（阅读材料/题干背景）
    if not subs:
        return parse_single(block)                            # 伪复合 → 单题
    sq = parse_single(material, is_material=True)
    sq.typeClassification.primaryType = QuestionType.COMPOSITE
    sq.subQuestions = []
    for sub_text in subs:\n        child = parse_composite(sub_text, depth + 1) if depth < 2 and looks_composite(sub_text) \
                else parse_single(material_context + sub_text)   # 子题携带材料上下文重解析
        sq.subQuestions.append(child)
    sq.typeClassification.subQuestionCount = len(sq.subQuestions)
    return sq
```

子题 `overallConfidence` 独立计算；父题取子题最小值 × 0.9。子题题型写入候选与统计，**判题/解题路由以子题为单位**，父题仅做组织。

### 4.12 LLM 深度分析异步链路（ASYNC_DEEP）

```python
async def deep_refine_async(parse_id: str, sync_result: StructuredQuestion, budget_ms=3000):
    """低置信题的异步补全。成本门控：每日 LLM 深度分析配额（默认 20000 次/日），
    超额后仅对 confidence < 0.3 的题放行，其余维持规则结果（D5 降级）。"""
    if not llm_quota_allow(sync_result.overallConfidence):
        return                                                  # D5：预算耗尽
    refined = await llm_classify_and_extract(                  # §4.4.3 协议 + 组件提取补全
        sync_result, prompt='parse_deep_refine_v2', timeout_ms=budget_ms - 200)
    merged = merge_with_guard(sync_result, refined)            # 只允许覆盖低置信字段（<0.6），
                                                                # 高置信规则结果不可被 LLM 覆写（G6）
    merged.usedLLM = True
    merged.typeClassification.source = 'llm_primary' if sync_result.typeClassification.confidence < 0.5 \
                                       else 'llm_assisted'
    persist(merged)                                            # 更新 parsed_questions（乐观锁 version）
    cache_put(merged)                                          # L1 重写
    outbox_publish('parse.deep.completed', {                   # Outbox 事件，编排服务消费后 PATCH 前端
        'parseId': parse_id,                                   # SSE 流（若该题 AI 解答仍在生成，
        'overallConfidence': merged.overallConfidence,         # 深度结构化结果注入解题 Prompt 的下一轮）
        'changedFields': diff_fields(sync_result, merged),
    })
```

### 6.3 解析记录质量状态机

```

AUTO/LLM_REFINED ──(人工修正)──→ MANUAL
MANUAL/LLM_REFINED ──(版本退役/parser 大版本升级)──→ RETIRED

```

| 守卫 | 起始态 | 事件 | 目标态 | 规则 |
|------|--------|------|--------|------|
| G1 | – | 同步解析完成 | AUTO | 任一 Stage partial 仍为 AUTO，不阻塞 |
| G2 | AUTO | LLM merge 后 confidence 提升 ≥0.05 | LLM_REFINED | 提升不足维持 AUTO（省缓存重写） |
| G3 | * | OCR 粗分类候选集约束 | * | 规则阶段禁止越集改判；LLM 越集需 confidence ≥0.85 且记 `coarseTypeOverridden` |
| G4 | * | 题型-学科非法组合 | * | 拒绝写入，回退 generic_solver 路由 + warning |
| G5 | LLM_REFINED/MANUAL | 再次 ASYNC_DEEP | 不变 | 人工修正与高置信 LLM 结果不可被后续 LLM 覆写 |
| G6 | AUTO | LLM 覆写规则字段 | 仅 confidence<0.6 字段 | 高置信规则结果保护 |
| G7 | MANUAL | parser 升级重解析 | 不变 | 人工结果永不被自动任务覆写，仅新 parseId 重建 |
| G8 | RETIRED | 任何 | 不变 | 终态；缓存命中 RETIRED 视为 miss |

### 6.4 批量任务状态机

`PENDING → PROCESSING → (COMPLETED | FAILED(partial_results) | CANCELLED)`；守卫：PROCESSING 中每题独立 try/catch，单题失败不终止批（失败清单回传）；取消仅允许 PENDING/PROCESSING 前 10% 进度内。

## 8. 性能、容量与配置

### 8.1 延迟预算（编排 12s 总预算中本引擎份额）

| 路径 | P50 | P99 | 预算 | 说明 |
|------|-----|-----|------|------|
| L1 缓存命中 | 5ms | 15ms | 50ms | Redis GET + 反序列化 |
| 规则全流程（单题） | 80ms | 300ms | 600ms | AC 自动机一次扫描 + 正则批处理 |
| parse_batch（每题） | 80ms | 300ms | 600ms | OCR N 题：多题内并行 4 worker |
| ASYNC_DEEP | 800ms | 2.5s | 3000ms | 含 LLM 网络往返，异步不阻塞搜题 |

### 8.2 容量估算（DAU 50 万口径）

| 项 | 估算 |
|----|------|
| 日解析量 | 拍照搜题 8 万 + 导入 2 万 + AI 提取 1 万 ≈ 11 万次/日（缓存命中 30% 后回源 ~7.7 万） |
| 峰值 QPS | 晚 20:00-21:00，~15 QPS 解析（规则路径 CPU 单核 3 题/s，4 实例 × 2 worker 裕量 3 倍+） |
| LLM 调用 | 低置信比例 ~15% ≈ 1.2 万次/日（配额 2 万，D5 门控） |
| parsed_questions 增量 | 11 万行/日；保留 180 天后由《存储资源统一生命周期管理》清理（RETIRED 90 天清理） |
| Redis L1 | 单条均值 2.5KB × 日活 7.7 万 × 7d ≈ 13.5GB（含副本），key 过期自动回收 |

### 8.3 吞吐保护

编排侧用户级限流之外，本服务自身：单实例信号量（同步解析并发 32）；批量队列削峰（并发 8）；LLM 全局并发 16（超发排队超时即 D4）。

### 8.4 规则热更新

`split_patterns.yaml` / `TYPE_RULES` / 学科特征词典 / 单位白名单均支持管理端 reload：新词典构建完成后**原子换指针**（双缓冲），进行中的解析继续用旧词典直到自然结束；词典版本号写入 `parser_version`（如 `v2.3.1+r42`）便于回归定位。

## 12. 验收场景

1. 手动输入单选（含 4 选项跨行）：题型 SINGLE_CHOICE，options 4 项无串行，<600ms。
2. OCR 入口：占位符 `{{formula:0}}` 回收为 FormulaBlock，latex 与 OCR 透传一致，不触发二次公式识别。
3. OCR 粗分类 COMPUTE + 规则判 math_geometry（越集）：置信度 <0.5 走 LLM 确认后方改判，warnings 含 `coarseTypeOverridden`。
4. 填空题：3 个空位，blanks 序号 1-3，前后文窗口正确，括号型空不与选项 (A) 混淆。
5. 复合题：材料 + 3 小问递归，subQuestions=3，父题 confidence=子题最小×0.9，子题各自带 solverRoute。
6. 化学方程式配平题：T6 检测 + 元素校验通过，FormulaBlock.type=chemical。
7. 化学式误检防护：`XxY2` 不合法元素 → 归 expression 而非 chemical。
8. 证明题：questions[0].type=prove，expectedAnswerType=proof_steps，路由 math_proof_v3。
9. 低置信（<0.5）短答：同步返回 UNKNOWN+候选，ASYNC_DEEP 3s 内 PATCH，source=llm_primary。
10. LLM 输出枚举外值：V1 拒绝，维持规则结果，llm_logs.outcome=REJECTED。
11. 同题重复解析：L1 命中，fromCache=true，latency <15ms，id/parsedAt 重生成。
12. 人工修正题型：quality_state=MANUAL，缓存失效重写，`parse.manual.corrected` 事件可被消费方幂等接收。
13. 人工修正后 ASYNC_DEEP 到达：G5/G11 乐观锁，LLM 放弃合并（54460），人工结果保持。
14. 公式服务宕机：D6，公式 rawText 内联，latexValid=false，主流程不受阻。
15. 同步预算耗尽：partial=true + budget_exhausted warning，编排不报错照常组装。
16. 批量导入 248 题：3 题失败（空文本），批状态 COMPLETED，failureExamples 含行号与原因。
17. 水印行/页脚行：noiseLines 捕获，不进入题干。
18. 题型-学科非法组合（english:cotze 以外学科命中特征词）：G4 拒绝，回退 generic 路由 + warning。
