# 通知中心与站内消息系统 - 详细设计

> 版本：v1.0 | 日期：2026-05-23 | 模块归属：用户服务域

## 1. 模块概述

### 1.1 定位与边界

通知中心是 PrimeTop 应用内统一的消息收件箱，负责管理所有站内通知的生成、存储、聚合、展示和生命周期管理。

**本模块 vs 消息与推送服务的边界：**

| 维度 | 通知中心（本模块） | 消息与推送服务 |
|------|---------------------|----------------|
| 核心职责 | 站内通知存储、聚合、展示、偏好管理 | APNs/FCM 推送、短信、邮件投递 |
| 消息载体 | App 内通知列表 | 设备推送栏 / 短信 / 邮箱 |
| 持久化 | 需要（长期存储） | 不需要（投递即结束） |
| 实时性 | 准实时（WebSocket/SSE 推送增量） | 实时（第三方推送通道） |
| 交互 | 点击跳转、标记已读、删除、批量操作 | 点击唤起 App |

**协作关系：** 业务事件 → 通知中心（生成站内通知）→ 消息与推送服务（触发外部推送）。两者通过事件总线解耦。

### 1.2 设计目标

1. **统一入口**：所有站内通知汇聚到一个收件箱，按类别分 Tab 展示
2. **实时可达**：用户在线时，新通知在 2 秒内到达客户端
3. **分类清晰**：学习、系统、互动、营销四大类别，支持用户自定义偏好
4. **高性能**：单用户通知列表 P99 响应 < 200ms，未读计数查询 < 50ms
5. **可控生命周期**：通知自动过期归档，热数据保持精简

### 1.3 目标用户

| 用户角色 | 使用场景 |
|----------|----------|
| 学生 | 查看学习提醒、错题复习通知、成就解锁、系统公告 |
| 家长 | 查看孩子学情周报、时长预警、会员到期提醒 |
| 教师 | 查看班级动态、学生提问、系统通知 |
| 运营/管理员 | 发送系统公告、活动通知、定向消息 |

## 3. 数据模型

### 3.1 核心表结构

#### notification（通知主表）

```sql
CREATE TABLE notification (
    id              BIGINT UNSIGNED    NOT NULL AUTO_INCREMENT COMMENT '通知ID，雪花算法生成',
    user_id         BIGINT UNSIGNED    NOT NULL COMMENT '接收用户ID',
    category        TINYINT UNSIGNED   NOT NULL COMMENT '通知大类: 1=LEARNING 2=SOCIAL 3=SYSTEM 4=MARKETING',
    type            VARCHAR(64)        NOT NULL COMMENT '通知子类型，见 NotificationType 枚举',
    title           VARCHAR(128)       NOT NULL COMMENT '通知标题',
    body            VARCHAR(512)       NOT NULL COMMENT '通知正文摘要',
    content         TEXT               NULL     COMMENT '通知富文本详情（可选，点击展开查看）',
    icon_url        VARCHAR(512)       NULL     COMMENT '通知图标URL',
    image_url       VARCHAR(512)       NULL     COMMENT '通知配图URL（可选）',
    
    -- 关联与跳转
    link_type       TINYINT UNSIGNED   NULL     COMMENT '跳转类型: 0=无跳转 1=内页 2=外链 3=弹窗',
    link_target     VARCHAR(256)       NULL     COMMENT '跳转目标：内页路由路径 / 外链URL / 弹窗标识',
    link_params     JSON               NULL     COMMENT '跳转参数，JSON格式',
    source_id       VARCHAR(128)       NULL     COMMENT '来源业务对象ID（如错题ID、报告ID）',
    source_type     VARCHAR(64)        NULL     COMMENT '来源业务类型（如 mistake, report, order）',
    
    -- 聚合支持
    group_key       VARCHAR(128)       NULL     COMMENT '聚合键，相同 key 的通知可合并展示',
    group_count     INT UNSIGNED       DEFAULT 1 COMMENT '聚合数量',
    
    -- 状态
    is_read         TINYINT UNSIGNED   DEFAULT 0 COMMENT '已读标记: 0=未读 1=已读',
    is_pinned       TINYINT UNSIGNED   DEFAULT 0 COMMENT '置顶标记: 0=普通 1=置顶',
    is_deleted      TINYINT UNSIGNED   DEFAULT 0 COMMENT '删除标记: 0=正常 1=已删除',
    read_at         DATETIME(3)        NULL     COMMENT '已读时间',
    
    -- 生命周期
    priority        TINYINT UNSIGNED   DEFAULT 5 COMMENT '优先级: 1=最高 5=普通 9=最低',
    expire_at       DATETIME(3)        NULL     COMMENT '过期时间，过期后不再展示',
    published_at    DATETIME(3)        NOT NULL COMMENT '发布时间（用于排序展示）',
    
    -- 审计字段
    created_at      DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3)        NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    
    PRIMARY KEY (id),
    INDEX idx_user_category_time (user_id, category, is_deleted, published_at DESC),
    INDEX idx_user_unread (user_id, is_read, is_deleted, published_at DESC),
    INDEX idx_user_type (user_id, type, is_deleted),
    INDEX idx_group_key (user_id, group_key, is_deleted, published_at DESC),
    INDEX idx_expire (expire_at, is_deleted)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='站内通知主表';
```

### 3.2 Redis 数据结构

#### 未读计数器

```
# 各大类未读数
Key:   notify:unread:{user_id}
Type:  HASH
Fields:
  total     → 总未读数
  learning  → 学习类未读数
  social    → 互动类未读数
  system    → 系统类未读数
  marketing → 营销类未读数

TTL:  7天（与MySQL同步兜底）
```

#### 实时推送通道（WebSocket）

```
# 用户在线状态
Key:   notify:online:{user_id}
Type:  STRING
Value: WebSocket连接节点ID
TTL:   5分钟（心跳续期）

# 待推送队列（用户离线时暂存）
Key:   notify:pending:{user_id}
Type:  LIST
Value: JSON序列化的通知摘要
TTL:   24小时
```

#### 聚合计数器（相同 group_key 实时累加）

```
Key:   notify:group:{user_id}:{group_key}
Type:  STRING (整数)
Value: 聚合数量
TTL:   24小时（过期后聚合窗口重置）
```

### 4.1 客户端 API

#### 4.1.1 获取通知列表

```
GET /api/v1/notifications
```

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| category | string | 否 | 筛选大类：LEARNING / SOCIAL / SYSTEM / MARKETING。不传则返回全部 |
| cursor | string | 否 | 分页游标（上一页最后一条的 published_at + id 编码） |
| limit | int | 否 | 每页条数，默认 20，最大 50 |
| unread_only | bool | 否 | 是否只看未读，默认 false |

**响应：**

```json
{

  "data": {
    "items": [
      {
        "id": "7210345678901234567",
        "category": "LEARNING",
        "type": "mistake_review_due",
        "title": "错题复习提醒",
        "body": "你有 3 道数学错题到了复习时间，快来巩固一下吧！",

        "link_params": { "knowledge_point_ids": ["kp_101", "kp_205"] },
```

**游标设计说明：**
游标为 Base64 编码的 `published_at|id` 组合。按 `published_at DESC, id DESC` 排序，游标分页避免 OFFSET 性能问题。

```typescript
// 游标编解码
function encodeCursor(publishedAt: string, id: string): string {
  return Buffer.from(`${publishedAt}|${id}`).toString('base64url');
}

function decodeCursor(cursor: string): { publishedAt: string; id: string } {
  const [publishedAt, id] = Buffer.from(cursor, 'base64url').toString().split('|');
  return { publishedAt, id };
}
```

### 4.2 服务端内部 API

#### 4.2.1 发送单条通知

```
POST /internal/v1/notifications/send
```

供其他微服务调用的内部接口，通过服务间鉴权（内网 Token）。

**请求体：**

```json
{
  "user_id": 12345678,
  "type": "mistake_review_due",
  "template_params": {
    "subject_name": "数学",
    "count": 3,
    "knowledge_points": ["二次函数", "一元二次方程"]
  },
  "source_id": "mr_batch_20260523_001",
  "source_type": "mistake_review_batch",
  "group_key": "mistake_review:12345678:2026-05-23",
  "link_override": {
    "type": 1,
    "target": "/mistake/review?batch=mr_batch_20260523_001"
  },
  "scheduled_at": null
}
```

**处理流程：**
1. 查找 `notification_template` 中 `type` 对应的模板
2. 用 `template_params` 渲染标题、正文、详情
3. 检查用户偏好，决定是否生成 + 是否触发推送
4. 检查聚合键：若 Redis 中已有同 group_key 的未读通知，执行聚合逻辑
5. 写入 MySQL
6. 更新 Redis 未读计数

```go
func (s *NotificationService) handleAggregation(ctx context.Context, n *Notification) (aggregated bool, err error) {
    if n.GroupKey == "" {
        return false, nil
    }
    
    // 尝试增加聚合计数
    key := fmt.Sprintf("notify:group:%d:%s", n.UserID, n.GroupKey)
    count, err := s.redis.Incr(ctx, key).Result()
    if err != nil {
        return false, err
    }
    s.redis.Expire(ctx, key, 24*time.Hour)
    
    if count == 1 {
        // 首条，正常插入新记录
        return false, nil
    }
    
    // 已有同组通知，执行聚合更新
    err = s.db.Model(&Notification{}).
        Where("user_id = ? AND group_key = ? AND is_read = 0 AND is_deleted = 0", n.UserID, n.GroupKey).
        Updates(map[string]interface{}{
            "group_count":  gorm.Expr("group_count + 1"),
            "body":         s.buildAggregatedBody(n.Type, int(count)),
            "published_at": time.Now(),
        }).Error
    
    return true, err
}
```

```go
func (s *NotificationService) pushRealtime(ctx context.Context, userID int64, msg *WSNotificationMessage) {
    key := fmt.Sprintf("notify:online:%d", userID)
    nodeID, err := s.redis.Get(ctx, key).Result()
    if err == redis.Nil {

        s.enqueuePending(userID, msg)

    }
```

```typescript
class NotificationSyncManager {
  private ws: WebSocket | null = null;
  private lastSyncTime: string = '';
  
  // 1. WebSocket 实时推送（在线时）
  onWSMessage(msg: WSNotificationMessage) {
    switch (msg.type) {
      case 'notification_new':
        // 新通知：插入本地列表头部
        this.insertLocal(msg.payload.notification!);
        this.updateBadge(msg.payload.unread_count!);
        this.playSound(); // 可选提示音
        break;
      case 'count_update':
        this.updateBadge(msg.payload.unread_count!);
        break;
      case 'notification_read':
        this.markLocalRead(msg.payload.read_ids!);
        break;
    }
  }
  
  // 2. 冷启动全量同步
  async coldStartSync() {
    // 拉取未读计数
    const counts = await api.getUnreadCount();
    this.updateBadge(counts);
    
    // 拉取最近通知（本地缓存为空时）
    if (!this.hasLocalCache()) {
      await this.fetchFirstPage();
    } else {
      // 增量同步：本地最新通知之后的
      await this.incrementalSync();
    }
  }
  
  // 3. 增量同步（拉取本地最新时间之后的通知）
  async incrementalSync() {
    const latest = this.getLocalLatest();
    const resp = await api.getNotifications({
      cursor: encodeCursor(latest.published_at, latest.id),
      limit: 50
    });
    this.mergeLocal(resp.items);
  }
  
  // 4. 断线重连
  async reconnect() {
    if (this.ws) {
      this.ws.close();
    }
    await this.connectWS();
    // 重连后做一次增量同步防止丢失
    await this.incrementalSync();
  }
}
```

```go
type TemplateRenderer struct {

}

func (r *TemplateRenderer) Render(tmplStr string, params map[string]interface{}) (string, error) {
    tmpl, err := template.New("").Parse(tmplStr)
    if err != nil {
        return "", fmt.Errorf("parse template: %w", err)
    }

    body, err := s.renderer.Render(tmpl.BodyTemplate, params)

        if err != nil {
            return nil, fmt.Errorf("render content: %w", err)
        }
        content = &c
    }
    
    return &RenderedNotification{
        Title:   title,
        Body:    body,
        Content: content,
    }, nil
```

```go
func (s *NotificationService) CleanExpiredNotifications(ctx context.Context) error {
    now := time.Now()
    
    // 批量软删除过期通知（每次处理 5000 条）
    for {
        result := s.db.Where(
            "expire_at IS NOT NULL AND expire_at < ? AND is_deleted = 0",
            now,
        ).Limit(5000).Delete(&Notification{})
        
        if result.RowsAffected == 0 {
            break
        }

        // 限流
        time.Sleep(100 * time.Millisecond)
    }

    cutoff := now.AddDate(0, 0, -180)

        cutoff,
```

```go
// 每天凌晨 4:00 执行
// 修复 Redis 未读计数与 MySQL 不一致的问题
func (s *NotificationService) RepairUnreadCounts(ctx context.Context) error {
    // 分页扫描活跃用户（最近30天有登录）
    offset := 0
    batchSize := 500
    
    for {
        users := s.getActiveUsers(offset, batchSize)
        if len(users) == 0 {
            break
        }
        
        for _, uid := range users {
            // MySQL 真实计数
            realCounts := s.countUnreadFromDB(uid)
            
            // Redis 当前计数
            redisCounts := s.countUnreadFromRedis(uid)
            
            // 不一致则修复
            if !countsEqual(realCounts, redisCounts) {
                s.resetRedisCounts(uid, realCounts)
                log.Printf("Repaired unread counts for user %d: %+v", uid, realCounts)
            }
        }
        
        offset += batchSize
        time.Sleep(50 * time.Millisecond)
    }
    
    return nil
}
```

## 9. 性能设计

### 9.1 关键性能指标

| 指标 | 目标值 | 测量点 |
|------|--------|--------|
| 通知列表查询 P99 | < 200ms | API 网关侧 |
| 未读计数查询 P99 | < 50ms | API 网关侧 |
| 单条通知写入 | < 50ms | 服务端内部 |
| 批量通知吞吐 | > 5000条/秒 | 批量发送任务 |
| WebSocket 消息延迟 | < 2秒 | 端到端 |
| Redis 未读计数精度 | 99.9% | 与 MySQL 对比 |

### 9.2 优化策略

**列表查询优化：**
- 游标分页避免 OFFSET（`WHERE (published_at, id) < (cursor_time, cursor_id)`）
- 覆盖索引 `idx_user_category_time` 避免回表
- 第一页数据 Redis 缓存 30 秒

**未读计数优化：**
- 读操作：Redis HASH 直接 HGETALL，无则回源 MySQL
- 写操作：Redis HINCRBY 原子递增
- 一致性兜底：每日凌晨修复任务

**批量写入优化：**
- 批量 INSERT 使用 `INSERT INTO ... VALUES (...), (...), ...` 多值语句
- 每批 500 条，批间 Sleep 100ms 限流
- Redis 计数使用 Pipeline 批量更新

**WebSocket 优化：**
- 单节点支撑 10 万连接
- 多节点通过 Redis Pub/Sub 跨节点路由
- 消息体精简（只推摘要，详情点击时加载）

### 9.3 分库分表策略（中期）

当单表通知量超过 5000 万行时，按 `user_id % 16` 分表：

```
notification_00 ~ notification_15
```

分表规则在数据访问层透明处理，业务代码无感知。路由函数：

```go
func notificationTable(userID int64) string {
    return fmt.Sprintf("notification_%02d", userID%16)
}
```

## 10. 错误处理

### 10.1 错误码定义

| 错误码 | HTTP 状态 | 说明 | 客户端处理 |
|--------|----------|------|-----------|
| NOTIFY_001 | 400 | 无效的通知类型 | 提示参数错误 |
| NOTIFY_002 | 400 | 模板渲染失败 | 记录日志，返回通用文案 |
| NOTIFY_003 | 404 | 通知不存在 | 刷新列表 |
| NOTIFY_004 | 429 | 批量操作超过限制（100条） | 提示分批操作 |
| NOTIFY_005 | 500 | Redis 计数更新失败 | 降级：不影响主流程，日志告警 |
| NOTIFY_006 | 500 | WebSocket 推送失败 | 降级：客户端轮询兜底 |
| NOTIFY_007 | 403 | 无权操作他人通知 | 忽略 |
| NOTIFY_008 | 409 | 聚合冲突（并发更新） | 重试一次 |

### 10.2 降级策略

```
                    优先级
Redis 不可用 ────────► 直接查 MySQL（降级响应时间）
WebSocket 断连 ──────► 客户端轮询模式（每 30 秒拉取一次）
MySQL 写入失败 ──────► 写入本地消息队列，异步重试
模板渲染失败 ─────────► 使用默认硬编码模板兜底
批量任务超时 ─────────► 记录断点，下次从断点恢复
```

### 10.3 幂等保障

```go
// 通知发送幂等：相同 source_id + source_type + user_id 不重复发送
func (s *NotificationService) SendNotification(ctx context.Context, req *SendRequest) (*SendResponse, error) {
    // 幂等检查
    if req.SourceID != "" {
        exists, err := s.db.Model(&Notification{}).
            Where("user_id = ? AND source_id = ? AND source_type = ? AND is_deleted = 0",
                req.UserID, req.SourceID, req.SourceType).
            Exists()
        if err != nil {
            return nil, err
        }
        if exists {
            return &SendResponse{Duplicated: true}, nil
        }
    }
    
    // ... 正常发送流程
}
```

```go
// 批量操作校验：所有 notification_id 必须属于当前用户
func (s *NotificationService) MarkRead(ctx context.Context, userID int64, ids []string) (int64, error) {
    result := s.db.Model(&Notification{}).
        Where("id IN ? AND user_id = ? AND is_read = 0", ids, userID).  // 绑定 user_id
        Updates(map[string]interface{}{"is_read": 1, "read_at": time.Now()})
    return result.RowsAffected, result.Error
}
```

### 11.2 内容安全

- 模板内容在写入时经过内容安全审核

- 通知中不承载敏感信息（如不展示完整手机号、密码等）
