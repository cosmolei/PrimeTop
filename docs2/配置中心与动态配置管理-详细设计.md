# 配置中心与动态配置管理 - 详细设计

## 1. 概述

### 1.1 背景

PrimeTop 作为面向全学段的 AI 辅助学习应用，需要大量运行时可调整的配置项：AI 模型路由策略、功能开关（Feature Flags）、灰度发布规则、限流阈值、业务参数（如免费用户每日 AI 调用次数）等。硬编码这些参数会导致每次变更都需要发版，无法快速响应运营需求和紧急事件（如模型供应商宕机时的降级切换）。

配置中心是整个系统的"遥控面板"，为多个上层模块提供统一的配置管理能力：

| 依赖模块 | 使用场景 |
| --- | --- |
| 灰度发布与特性开关 | 按用户分群控制功能可见性 |
| AB测试与实验平台 | 实验分组配置与流量分配 |
| 多模型调度与成本治理 | 模型路由规则、降级策略、成本阈值 |
| 错误处理与服务降级 | 降级开关、熔断阈值、重试策略 |
| 消息与推送服务 | 推送开关、静默时段、渠道权重 |
| 防沉迷与未成年人保护 | 时长阈值、年龄分段规则 |
| 支付与会员订阅 | 权益配置、促销活动开关 |
| 运营活动与成长激励 | 活动规则、奖励配置、有效期 |

### 1.2 设计目标

1. **实时性**：配置变更后秒级生效，无需重启服务或发版
2. **高可用**：配置中心不可用时，客户端/服务端可使用本地缓存继续运行
3. **一致性**：同一次变更在多实例间保持一致的生效时间
4. **可追溯**：所有配置变更记录完整的审计日志（谁、何时、改了什么）
5. **多端支持**：服务端 + 客户端（APP）均能消费配置
6. **安全性**：敏感配置加密存储，按角色控制读写权限

### 1.3 非目标

- 不做通用 PaaS 级配置中心，仅服务于 PrimeTop 业务
- 不替代 CI/CD 流水线中的构建时配置（如数据库连接串等环境变量）
- 不处理静态资源版本管理（由 CDN 体系负责）

| --- | --- |

## 3. 配置模型设计

### 3.1 配置项结构 (ConfigItem)

```typescript
interface ConfigItem {
  /** 配置唯一标识，全局唯一，格式: namespace.key */
  key: string;
  
  /** 所属命名空间，如 "ai", "feature", "rate-limit" */
  namespace: string;
  
  /** 配置值，支持多种类型 */
  value: ConfigValue;
  
  /** 值类型，用于反序列化和校验 */
  valueType: 'STRING' | 'NUMBER' | 'BOOLEAN' | 'JSON' | 'YAML';
  
  /** 配置描述 */
  description: string;
  
  /** 默认值（当运行时获取失败时的兜底） */
  defaultValue: ConfigValue;
  
  /** 配置标签，用于过滤和分组 */
  tags: string[];
  
  /** 是否启用 */
  enabled: boolean;
  
  /** 是否需要审批才能发布 */
  requireApproval: boolean;
  
  /** 当前生效版本号 */
  version: number;
  
  /** 创建时间 */
  createdAt: string;
  
  /** 最后修改时间 */
  updatedAt: string;
  
  /** 最后修改人 */
  updatedBy: string;
}
```

### 3.2 条件配置 (ConditionalConfig)

支持按条件分发的配置（灰度、AB测试、分群等）：

```typescript
interface ConditionalConfig {
  /** 基础配置 key */
  baseKey: string;
  
  /** 规则列表，按优先级从高到低匹配，首个命中即返回 */
  rules: ConditionalRule[];
  
  /** 全都不匹配时的兜底值 */
  fallbackValue: ConfigValue;
  
  /** 规则版本号 */
  version: number;
}

interface ConditionalRule {
  /** 规则名称 */
  name: string;
  
  /** 规则优先级，数字越小优先级越高 */
  priority: number;
  
  /** 匹配条件（全部满足才命中） */
  conditions: Condition[];
  
  /** 命中时返回的配置值 */
  value: ConfigValue;
  
  /** 是否启用此规则 */
  enabled: boolean;
}

interface Condition {
  /** 匹配维度 */
  dimension: 'user_id' | 'user_group' | 'grade' | 'platform' 
           | 'app_version' | 'region' | 'device_id' | 'percentage';
  
  /** 匹配操作符 */
  operator: 'EQ' | 'NE' | 'IN' | 'NOT_IN' | 'GT' | 'LT' | 'GTE' | 'LTE'
          | 'CONTAINS' | 'STARTS_WITH' | 'REGEX' | 'PERCENTAGE';
  
  /** 匹配值 */
  values: string[];
}
```

### 3.3 命名空间规划

| 命名空间 | 说明 | 示例 key |
| --- | --- | --- |
| `feature` | 功能开关 | `feature.essay_coaching.enabled` |
| `ai` | AI 模型与调度 | `ai.model_routing.math.high_school` |
| `rate-limit` | 限流配置 | `rate-limit.ai_daily_call.free` |
| `content` | 内容安全与审核 | `content.filter.sensitivity_level` |
| `business` | 业务参数 | `business.membership.trial_days` |
| `push` | 推送配置 | `push.quiet_hours.start` |
| `experiment` | AB 实验配置 | `experiment.onboarding_flow.variant` |
| `infra` | 基础设施 | `infra.cache.ttl.learning_record` |
| `client` | 客户端行为控制 | `client.force_update.min_version` |
| `safety` | 安全与合规 | `safety.anti_addiction.max_daily_minutes.primary` |

## 4. 数据库设计

### 4.1 配置主表 (config_item)

```sql
CREATE TABLE config_item (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `key`           VARCHAR(255) NOT NULL COMMENT '配置唯一标识 namespace.key',
    namespace       VARCHAR(64) NOT NULL COMMENT '命名空间',
    value_type      VARCHAR(16) NOT NULL DEFAULT 'STRING' COMMENT '值类型',
    config_value    MEDIUMTEXT NOT NULL COMMENT '配置值（JSON 序列化后存储）',
    default_value   MEDIUMTEXT COMMENT '默认兜底值',
    description     VARCHAR(512) DEFAULT '' COMMENT '配置描述',
    tags            JSON COMMENT '标签数组',
    enabled         TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否启用',
    require_approval TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否需要审批',
    version         INT UNSIGNED NOT NULL DEFAULT 1 COMMENT '当前生效版本',
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    updated_by      VARCHAR(64) NOT NULL DEFAULT 'system',
    
    UNIQUE KEY uk_key (`key`),
    INDEX idx_namespace (namespace),
    INDEX idx_enabled (enabled),
    INDEX idx_updated_at (updated_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='配置项主表';
```

### 4.2 条件配置表 (config_rule)

```sql
CREATE TABLE config_rule (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    base_key        VARCHAR(255) NOT NULL COMMENT '关联的配置 key',
    rule_name       VARCHAR(128) NOT NULL COMMENT '规则名称',
    priority        INT NOT NULL DEFAULT 100 COMMENT '优先级，数字越小越高',
    conditions      JSON NOT NULL COMMENT '匹配条件数组',
    rule_value      MEDIUMTEXT NOT NULL COMMENT '命中时返回的值',
    enabled         TINYINT(1) NOT NULL DEFAULT 1,
    version         INT UNSIGNED NOT NULL DEFAULT 1,
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    updated_by      VARCHAR(64) NOT NULL DEFAULT 'system',
    
    INDEX idx_base_key (base_key),
    INDEX idx_base_key_priority (base_key, priority)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='条件配置规则表';
```

### 4.3 配置变更历史表 (config_changelog)

```sql
CREATE TABLE config_changelog (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    config_key      VARCHAR(255) NOT NULL,
    from_version    INT UNSIGNED NOT NULL,
    to_version      INT UNSIGNED NOT NULL,
    old_value       MEDIUMTEXT COMMENT '变更前值快照',
    new_value       MEDIUMTEXT COMMENT '变更后值快照',
    change_type     VARCHAR(16) NOT NULL COMMENT 'CREATE/UPDATE/DELETE/ROLLBACK/ENABLE/DISABLE',
    operator        VARCHAR(64) NOT NULL,
    reason          VARCHAR(512) DEFAULT '',
    approval_status VARCHAR(16) NOT NULL DEFAULT 'PENDING',
    approver        VARCHAR(64) DEFAULT NULL,
    approved_at     DATETIME(3) DEFAULT NULL,
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    
    INDEX idx_config_key (config_key),
    INDEX idx_created_at (created_at),
    INDEX idx_operator (operator)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='配置变更历史';
```

### 4.4 客户端配置快照表 (config_client_snapshot)

```sql
CREATE TABLE config_client_snapshot (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    snapshot_version BIGINT UNSIGNED NOT NULL COMMENT '快照版本号（全局递增）',
    platform        VARCHAR(16) NOT NULL COMMENT 'android/ios/web',
    app_version     VARCHAR(32) NOT NULL COMMENT '目标 APP 版本',
    config_content  MEDIUMTEXT NOT NULL COMMENT '全量配置 JSON',
    content_hash    CHAR(64) NOT NULL COMMENT 'SHA-256 哈希',
    compressed_size INT UNSIGNED COMMENT '压缩后字节数',
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    
    UNIQUE KEY uk_platform_version (platform, app_version),
    INDEX idx_snapshot_version (snapshot_version)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='客户端配置快照';
```

### 4.5 Redis 缓存结构

```
# 配置项缓存（热数据）
config:item:{key}          -> Hash { value, version, type, enabled, updatedAt }
TTL: 24h（被动失效 + 主动删除）

# 命名空间索引
config:ns:{namespace}      -> Set { key1, key2, ... }
TTL: 无（主动维护）

# 条件规则缓存
config:rules:{baseKey}     -> String (JSON 序列化的规则数组)
TTL: 24h

# 全局配置版本号（用于客户端增量更新）
config:global_version      -> String (单调递增数字)

# 客户端配置 hash（用于判断是否需要更新）
config:client_hash:{platform}:{appVersion} -> String (SHA-256)

# 变更通知 Pub/Sub 频道
config:notify:{namespace}  -> Pub/Sub channel
```

## 5. API 接口设计

### 5.1 配置读取 API（业务服务调用）

#### GET /api/v1/config/{key}

获取指定配置项的当前值。

**请求：**

```http
GET /api/v1/config/ai.model_routing.math.high_school
Authorization: Bearer <service-token>
```

**查询参数：**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `resolve` | boolean | 否 | 是否解析条件规则（默认 true） |
| `context` | string | 否 | 解析上下文 JSON（用于条件匹配），Base64 编码 |
| `version` | int | 否 | 指定版本号（不传则返回最新） |

**响应：**

```json
{
  "code": 0,
  "data": {
    "key": "ai.model_routing.math.high_school",
    "value": {
      "primary": "deepseek-v3",
      "fallback": "gpt-4o-mini",
      "timeout": 30000
    },
    "valueType": "JSON",
    "version": 15,
    "enabled": true,
    "updatedAt": "2026-05-19T10:30:00Z"
  }
}
```

#### GET /api/v1/config/namespace/{namespace}

批量获取某命名空间下的所有配置。

**响应：**

```json
{
  "code": 0,
  "data": {
    "namespace": "feature",
    "version": 42,
    "items": [
      {
        "key": "feature.essay_coaching.enabled",
        "value": true,
        "version": 10
      },
      {
        "key": "feature.oral_practice.enabled",
        "value": false,
        "version": 8
      }
    ]
  }
}
```

#### POST /api/v1/config/resolve

解析条件配置（批量）。

**请求：**

```json
{
  "keys": [
    "feature.essay_coaching.enabled",
    "ai.model_routing.math.high_school"
  ],
  "context": {
    "user_id": "u_12345",
    "grade": "高一",
    "platform": "android",
    "app_version": "1.2.0",

  }
}
```

**响应：**

```json
{
  "code": 0,
  "data": {
    "results": [
      {
        "key": "feature.essay_coaching.enabled",
        "value": true,
        "matchedRule": "grade_high_school",
        "version": 10
      },
      {
        "key": "ai.model_routing.math.high_school",

          "primary": "deepseek-v3",

```

## 6. Server SDK 设计

### 6.1 配置读取接口（Java/Kotlin 示例）

```kotlin
/**
 * 配置中心客户端 SDK
 */
interface ConfigClient {
    
    /**
     * 获取配置值，带本地缓存
     * @param key 配置 key
     * @return 配置值，获取失败返回 null
     */
    fun getString(key: String): String?
    
    fun getInt(key: String): Int?
    fun getLong(key: String): Long?
    fun getBoolean(key: String): Boolean?
    fun <T> getJson(key: String, clazz: Class<T>): T?
    
    /**
     * 获取配置值，带默认值兜底
     */
    fun getString(key: String, defaultValue: String): String
    fun getInt(key: String, defaultValue: Int): Int
    fun getBoolean(key: String, defaultValue: Boolean): Boolean
    fun <T> getJson(key: String, clazz: Class<T>, defaultValue: T): T
    
    /**
     * 解析条件配置（传入用户上下文）
     */
    fun <T> resolve(key: String, clazz: Class<T>, context: ConfigContext): T?
    
    /**
     * 注册配置变更监听器
     */
    fun addListener(key: String, listener: ConfigChangeListener)
    
    /**
     * 批量获取命名空间下所有配置
     */
    fun getNamespace(namespace: String): Map<String, ConfigValue>
}

data class ConfigContext(
    val userId: String? = null,
    val grade: String? = null,
    val platform: String? = null,
    val appVersion: String? = null,
    val region: String? = null,
    val deviceId: String? = null,
    val userGroups: Set<String> = emptySet()
)

interface ConfigChangeListener {
    fun onChanged(key: String, oldValue: Any?, newValue: Any?)
}
```

### 6.2 SDK 内部缓存与更新策略

```
┌──────────────────────────────────────────────┐
│               Server SDK 内部流程             │
│                                              │
│  应用启动                                     │
│    │                                         │
│    ▼                                         │
│  全量拉取配置 → 写入内存 ConcurrentHashMap     │
│    │             + 本地文件备份               │
│    ▼                                         │
│  订阅 Redis Pub/Sub                          │
│    │                                         │
│    ├── 收到变更通知                            │
│    │     │                                   │
│    │     ▼                                   │
│    │   拉取变更的 key 最新值                    │
│    │     │                                   │
│    │     ▼                                   │
│    │   更新内存缓存 + 触发 Listener            │
│    │                                         │
│    └── 定时心跳（每 60s）                      │
│          │                                   │
│          ▼                                   │
│        检查 global_version                    │
│        若落后则增量拉取补齐                     │
│                                              │
│  读取配置时：                                   │
│    内存缓存 → 本地文件 → 默认值                 │
└──────────────────────────────────────────────┘
```

## 7. Client SDK 设计（APP 端）

### 7.1 设计约束

客户端无法维持长连接（省电、网络不稳定），采用**定时拉取 + 启动拉取 + 关键节点拉取**策略。

### 7.2 Dart (Flutter) SDK 接口

```dart
/// 配置中心客户端
class PrimeTopConfig {
  static PrimeTopConfig? _instance;
  static PrimeTopConfig get instance => _instance!;
  
  final SharedPreferences _prefs;
  final Dio _http;
  
  /// 本地缓存的最大有效时长
  static const _maxCacheAge = Duration(hours: 24);
  
  /// 获取配置值
  String? getString(String key) => _cache[key]?.asString();
  int? getInt(String key) => _cache[key]?.asInt();
  bool? getBool(String key) => _cache[key]?.asBool();
  T? getJson<T>(String key, T Function(Map<String, dynamic>) fromJson) {
    final raw = _cache[key]?.asMap();
    if (raw == null) return null;
    return fromJson(raw);
  }
  
  /// 带默认值的获取
  String getString(String key, String defaultValue) =>
      getString(key) ?? defaultValue;
  bool getBool(String key, bool defaultValue) =>
      getBool(key) ?? defaultValue;
  
  /// 监听配置变化
  void addListener(String key, void Function(dynamic) listener) {
    _listeners.putIfAbsent(key, () => []).add(listener);
  }
  
  /// 拉取最新配置
  Future<void> refresh() async {
    try {
      final currentHash = _prefs.getString('config_hash');
      final resp = await _http.get('/api/v1/client/config', queryParameters: {
        'platform': Platform.isAndroid ? 'android' : 'ios',
        'app_version': await _getAppVersion(),
        'current_hash': currentHash,
      });
      
      final data = resp.data['data'];
      if (data['has_update'] == true) {
        _updateCache(data['content'], data['hash']);
      }
    } catch (e) {
      // 拉取失败，继续使用本地缓存
      _log.warning('Config refresh failed: $e');
    }
  }
  
  void _updateCache(Map<String, dynamic> content, String hash) {
    final old = Map<String, dynamic>.from(_cache);
    _cache.clear();
    _cache.addAll(content);
    _prefs.setString('config_hash', hash);
    _prefs.setString('config_cache', jsonEncode(content));
    _prefs.setInt('config_cache_time', DateTime.now().millisecondsSinceEpoch);
    
    // 触发变更监听
    for (final entry in _listeners.entries) {
      if (old[entry.key] != _cache[entry.key]) {
        for (final listener in entry.value) {
          listener(_cache[entry.key]);
        }
      }
    }
  }
}
```

### 7.3 拉取时机

| 时机 | 策略 | 超时 |
| --- | --- | --- |
| APP 冷启动 | 同步拉取（阻塞首页渲染最多 500ms） | 500ms |
| APP 从后台回到前台 | 如果距上次拉取 > 5 分钟则拉取 | 2s |
| 定时器 | 每 30 分钟后台拉取一次 | 5s |
| 关键操作前 | 调用 `refresh()` 后执行业务 | 3s |
| 推送触发 | 收到 `config_update` 推送后立即拉取 | 3s |

### 7.4 本地持久化策略

```
SharedPreferences:
  config_hash     → String     (当前配置 hash)
  config_cache    → String     (全量配置 JSON)
  config_cache_time → int      (缓存写入时间戳)

启动时读取顺序:
  1. 内存缓存（如果在运行中）
  2. SharedPreferences
  3. 代码内置默认值

缓存过期策略:
  - 本地缓存超过 24h 仍可使用，但打印警告日志
  - 服务端返回的 expires_at 用于判断是否需要强制刷新
```

## 8. 条件规则引擎

### 8.1 规则匹配流程

```
输入: configKey + ConfigContext
         │
         ▼
    读取条件规则列表（Redis 缓存 → DB 回源）
         │
         ▼
    按 priority 升序排序
         │
         ▼
    ┌─── 遍历规则 ───┐
    │                │
    │  检查 enabled?  │──否──→ 跳过
    │                │
    │  遍历 conditions│
    │    │           │
    │    ▼           │
    │  匹配 dimension│
    │  + operator    │
    │  + values      │
    │    │           │
    │    ▼           │
    │  全部条件满足？  │──否──→ 跳过此规则
    │                │
    │    命中！       │──→ 返回 rule_value
    │                │
    └────────────────┘
         │
         ▼
    无规则命中 → 返回基础配置值（fallbackValue）
```

### 8.2 PERCENTAGE 操作符实现

按百分比分流需要保证**稳定性**（同一用户多次请求结果一致）和**均匀性**。

```kotlin
/**
 * 基于用户 ID 的百分比分桶
 * 将 userId 哈希到 0-99 的整数，判断是否 < percentage
 */
fun matchPercentage(userId: String, percentage: Int): Boolean {
    require(percentage in 0..100)
    
    // 使用 MurmurHash3 保证分布均匀且确定性
    val hash = userId.murmurHash3_32()
    val bucket = Math.floorMod(hash, 100)
    return bucket < percentage
}
```

### 8.3 规则匹配性能优化

| 优化点 | 方案 |
| --- | --- |
| 规则缓存 | 规则列表缓存到 Redis，变更时主动失效 |
| 短路求值 | 按优先级排序，首个命中即返回 |
| 条件索引 | 对高频 dimension（grade, platform）建立内存索引 |
| 批量解析 | 单次请求解析多个 key 时，共享同一个 ConfigContext |

## 9. 变更通知机制

### 9.1 服务端通知链路

```
管理后台修改配置
    │
    ▼
Config Service 写入 MySQL + 更新 Redis 缓存
    │
    ├── 更新 config:item:{key} 缓存
    ├── 递增 config:global_version
    │
    ├── 发布 Redis Pub/Sub
    │     频道: config:notify:{namespace}
    │     消息: { "key": "...", "version": 16, "timestamp": "..." }
    │
    └── 通过推送服务通知客户端
          推送类型: silent_push
          payload: { "type": "config_update", "version": 42 }
```

### 9.2 服务端 SDK 订阅

```kotlin
// 每个 Server SDK 实例启动时订阅 Pub/Sub
fun subscribe() {
    jedis.subscribe(object : JedisPubSub() {
        override fun onMessage(channel: String, message: String) {
            val notification = json.decodeFromString<ConfigNotification>(message)
            
            // 1. 从 Redis 拉取最新值
            val newValue = fetchConfig(notification.key)
            
            // 2. 更新内存缓存
            localCache.put(notification.key, newValue)
            
            // 3. 触发监听器
            listeners[notification.key]?.forEach { listener ->
                listener.onChanged(notification.key, null, newValue)
            }
        }
    }, "config:notify:*")
}
```

### 9.3 客户端通知

客户端通过**静默推送 + 拉取**模式获取更新：

1. 服务端配置变更后发送 APNs/FCM 静默推送
2. APP 收到静默推送后调用 `PrimeTopConfig.instance.refresh()`
3. 若 APP 不在前台，下次启动/回到前台时自动拉取

## 10. 安全设计

### 10.1 敏感配置加密

对数据库中的敏感配置值（如 API Key、Secret）进行 AES-256-GCM 加密存储：

```kotlin
/**
 * 敏感配置加密/解密
 */
object ConfigEncryption {
    private val keyStore = KeyStore.getInstance("JCEKS")
    
    fun encrypt(plaintext: String, keyAlias: String): String {
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.ENCRYPT_MODE, getSecretKey(keyAlias))
        val encrypted = cipher.doFinal(plaintext.toByteArray(Charsets.UTF_8))
        // 格式: base64(iv + ciphertext + tag)
        return Base64.getEncoder().encodeToString(encrypted)
    }
    
    fun decrypt(ciphertext: String, keyAlias: String): String {
        val encrypted = Base64.getDecoder().decode(ciphertext)
        val cipher = Cipher.getInstance("AES/GCM/NoPadding")
        cipher.init(Cipher.DECRYPT_MODE, getSecretKey(keyAlias), 
                    GCMParameterSpec(128, encrypted.copyOfRange(0, 12)))
        val decrypted = cipher.doFinal(encrypted)
        return String(decrypted, Charsets.UTF_8)
    }
}
```

### 10.2 配置项安全分级

| 级别 | 说明 | 存储方式 | 审批要求 | 示例 |
| --- | --- | --- | --- | --- |
| PUBLIC | 面向客户端的公开配置 | 明文 | 无需审批 | 功能开关、UI 参数 |
| INTERNAL | 服务端内部参数 | 明文 | 单人审批 | 限流阈值、缓存 TTL |
| SENSITIVE | 含密钥/Token | AES 加密 | 双人审批 | API Key、数据库密码 |
| CRITICAL | 影响全局的核心配置 | AES 加密 + 审批流 | 双人审批 + 等待期 | 支付开关、维护模式 |

### 11.1 审批流程状态机

```
     ┌─────────────────────────────────────────┐
```

| --- | --- | --- | --- |
| PUBLIC | 可选 | 1 人 | 立即 |

3. 变更立即生效，但 24 小时内必须补审批
4. 超过 24 小时未补审批则自动回滚

## 12. 容错与降级

### 12.1 Server SDK 降级策略

```
读取配置的降级链:
  1. 内存缓存 → 命中则返回
  2. 本地文件备份 → 命中则返回（打印 WARN 日志）
  3. 代码默认值 → 返回（打印 ERROR 日志）
```

### 12.2 Client SDK 降级策略

```
读取配置的降级链:
  1. 内存缓存 → 命中则返回
  2. SharedPreferences 本地持久化 → 命中则返回
  3. 代码内置默认值 → 返回
```

### 12.3 Config Service 故障应对

| 故障场景 | 影响 | 应对 |
| --- | --- | --- |
| MySQL 不可用 | 无法修改配置 | 读取走 Redis 缓存 + 本地备份 |
| Redis 不可用 | 无法推送变更通知 | SDK 定时轮询兜底（每 60s） |
| Config Service 全挂 | 无法读写 | SDK 完全依赖本地缓存和默认值 |
| 网络分区 | 部分实例配置不一致 | 最终一致，最多 60s 延迟 |

### 12.4 熔断保护

Config Service 调用配置中心时增加熔断器：

```kotlin
val circuitBreaker = CircuitBreaker.ofDefaults("configService")
    .config { config ->
        config.failureRateThreshold(50.0f)
            .waitDurationInOpenState(Duration.ofSeconds(30))
            .permittedNumberOfCallsInHalfOpenState(3)
            .slidingWindowSize(10)
    }

// 当配置中心连续失败超过阈值时，自动熔断，使用本地缓存
```
