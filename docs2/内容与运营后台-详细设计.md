# 内容与运营后台 - 详细设计文档

## 1. 模块概述

### 1.1 定位

内容与运营后台是 PrimeTop 的管理中枢，面向平台运营人员、内容编辑和管理员，提供教材管理、知识库维护、题库管理、AI Prompt 配置、模型管理、内容审核、数据看板、权限管理等功能。所有面向学生的内容与 AI 输出质量均依赖此后台的配置和管理。

### 1.2 目标用户

| 角色 | 职责 |
|------|------|
| 超级管理员 | 全部权限，系统配置、角色管理 |
| 运营管理员 | 运营活动、数据看板、会员管理 |
| 内容编辑 | 教材、知识点、题库、考点内容维护 |
| 审核专员 | AI 输出审核、用户上传内容审核 |
| AI 工程师 | Prompt 模板、模型配置、RAG 策略调优 |

### 1.3 优先级

| 功能 | 优先级 | 版本 |
|------|--------|------|
| 用户与权限管理 | P0 | MVP |
| 教材版本管理 | P0 | MVP |
| 章节/知识点管理 | P0 | MVP |
| Prompt 模板配置 | P0 | MVP |
| 模型供应商配置 | P0 | MVP |
| 题库管理 | P1 | V1.0 |
| 内容审核 | P1 | V1.0 |
| 数据看板 | P1 | V1.0 |
| 运营活动管理 | P2 | V1.5 |
| AI 质量评估 | P2 | V1.5 |

### 3.2 RBAC 权限模型

```
权限编码规则: {模块}:{资源}:{操作}

模块划分:
- user      → 用户管理
- content   → 内容管理(教材/知识点/考点)
- question  → 题库管理
- ai        → AI 配置(Prompt/模型)
- audit     → 审核管理
- ops       → 运营管理(活动/会员)
- dashboard → 数据看板
- system    → 系统设置(角色/权限/日志)

示例:
- content:textbook:create    → 创建教材版本
- content:textbook:read      → 查看教材
- content:textbook:update    → 编辑教材
- content:textbook:delete    → 删除教材
- content:chapter:update     → 编辑章节
- question:question:create   → 创建题目
- ai:prompt:update           → 修改 Prompt 模板
- ai:model:update            → 修改模型配置
```


### 3.4 认证流程

```
管理员登录:
1. POST /api/admin/auth/login { username, password }
2. 验证密码 (bcrypt compare)
3. 检查账号状态 (enabled/disabled)
4. 生成 JWT Token (payload: { userId, roles[] })
5. 记录登录日志 (IP、UA、时间)
6. 返回 { token, expiresIn, userInfo }

请求鉴权:
1. 前端请求头携带 Authorization: Bearer <token>
2. Gateway 校验 JWT 签名和过期时间
3. 从 token 提取 userId + roles
4. 查询角色对应的权限列表 (Redis 缓存)
5. 与请求的 API 路径进行权限匹配
6. 通过 → 转发; 拒绝 → 403
```

## 4. 教材与章节管理

### 4.1 数据模型

```sql
-- 教材版本表
CREATE TABLE textbook (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    name            VARCHAR(128) NOT NULL COMMENT '如: 人教版数学',
    publisher       VARCHAR(64) COMMENT '出版社',
    subject_code    VARCHAR(32) NOT NULL COMMENT '学科编码: MATH/CHINESE/ENGLISH/PHYSICS...',
    stage           VARCHAR(16) NOT NULL COMMENT 'PRIMARY/JUNIOR/SENIOR',
    grade_start     INT NOT NULL COMMENT '起始年级 1-12',
    grade_end       INT NOT NULL COMMENT '结束年级',
    semester_type   VARCHAR(16) COMMENT 'UPPER/LOWER/FULL',
    version_code    VARCHAR(64) NOT NULL UNIQUE COMMENT '如: PEP-MATH-PRIMARY',
    status          TINYINT NOT NULL DEFAULT 0 COMMENT '0=草稿 1=已发布 2=已下线',
    cover_url       VARCHAR(512),
    description     TEXT,
    published_at    DATETIME,
    created_by      BIGINT,
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_subject_stage (subject_code, stage),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 章节目录表（树形结构）
CREATE TABLE chapter (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    textbook_id     BIGINT NOT NULL,
    parent_id       BIGINT DEFAULT 0 COMMENT '0=顶级章节',
    level           TINYINT NOT NULL COMMENT '1=册 2=单元 3=课 4=知识点',
    sort_order      INT NOT NULL DEFAULT 0,
    name            VARCHAR(256) NOT NULL,
    code            VARCHAR(128) COMMENT '章节编码',
    description     TEXT,
    status          TINYINT NOT NULL DEFAULT 0 COMMENT '0=草稿 1=已发布',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (textbook_id) REFERENCES textbook(id),
    INDEX idx_textbook_parent (textbook_id, parent_id, sort_order),
    INDEX idx_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 章节资源关联表
CREATE TABLE chapter_resource (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    chapter_id      BIGINT NOT NULL,
    resource_type   VARCHAR(32) NOT NULL COMMENT 'VIDEO/DOC/AUDIO/IMAGE/PDF',
    title           VARCHAR(256),
    url             VARCHAR(1024) NOT NULL,
    file_size       BIGINT COMMENT '字节',
    format          VARCHAR(16) COMMENT 'mp4/pdf/mp3/png...',
    duration_sec    INT COMMENT '音视频时长',
    sort_order      INT NOT NULL DEFAULT 0,
    status          TINYINT NOT NULL DEFAULT 1,
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (chapter_id) REFERENCES chapter(id),
    INDEX idx_chapter_type (chapter_id, resource_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.2 章节树形结构设计

```
教材版本: 人教版小学数学 (textbook_id=1)
│
├── 一年级上册 (level=1, parent_id=0, sort=1)
│   ├── 第一单元 准备课 (level=2, parent_id=101, sort=1)
│   │   ├── 1.1 数一数 (level=3, parent_id=201, sort=1)
│   │   ├── 1.2 比多少 (level=3, parent_id=201, sort=2)
│   │   └── ...
│   ├── 第二单元 位置 (level=2, parent_id=101, sort=2)
│   └── ...
├── 一年级下册 (level=1, parent_id=0, sort=2)
└── ...

约定:
- level 最多4层: 册 → 单元 → 课 → 知识点
- sort_order 同级排序，从小到大
- code 用于外部系统对接，如 "PEP-MATH-P1A-U1-L1"
```


### 4.4 教材导入流程

```json
// Excel 导入模板格式 (每行一个章节)
{
  "columns": ["册别", "单元", "课", "知识点", "章节编码"],
  "example": [
    ["一年级上册", "第一单元 准备课", "数一数", "", "PEP-MATH-P1A-U1-L1"],
    ["一年级上册", "第一单元 准备课", "比多少", "", "PEP-MATH-P1A-U1-L2"]
  ]
}
```

```
导入流程:
1. 内容编辑上传 Excel/JSON 文件
2. 后台解析 → 校验格式和必填字段
3. 构建 parent_id 关系 → 生成树形结构
4. 写入 chapter 表 (status=草稿)
5. 返回导入结果: 成功数/跳过数/错误列表
6. 编辑确认后批量发布
```

### 5.2 知识点树与关联关系

```

├── 图形与几何 (level=1)

关联关系:
- knowledge_chapter_mapping: 知识点 ↔ 章节多对多
```

**版本管理流程：**

```
1. 编辑入口: 基于当前 ACTIVE 版本复制出新版本 (version = max(version)+1, 状态 DRAFT)
2. DRAFT 可反复编辑、试运行; 试运行走独立沙箱模型, 不写线上指标, 试运行结果保留 24h
3. 提交审核 → REVIEWING (复核人需持 ai:prompt:audit, 且复核人 ≠ 编辑人)
4. 审核通过 → APPROVED; 驳回 → REJECTED (附驳回理由, 可修改后重新提交, 生成 version+1)
5. 激活 activate (单人执行 + 双人复核生效):
   事务内: 旧 ACTIVE 版本 → ARCHIVED; 新版本 → ACTIVE;
   同事务写 admin_audit_log; 提交后删除 Redis 缓存 admin:prompt:active:{scene_code}
6. 回滚: 从版本历史选择任一 APPROVED/ARCHIVED 版本重新 activate, 等价于版本指针切换,
   不删除任何历史版本; 回滚同样需要双人复核并记审计
```

**变量校验规则：**

```
占位符语法: {{variable_name}}
1. 模板中出现的每个 {{var}} 必须在 variables JSON 数组中声明
2. variables 中 required=true 的变量必须在 user_prompt_tpl 中出现
3. 变量名命名: ^[a-z][a-zA-Z0-9_]{0,31}$
4. 保存时做「占位符 ↔ 声明」双向比对, 不一致 → 拒绝保存(40004)
5. variables 结构: [{"name":"grade","type":"string","required":true,
                   "description":"学生年级","example":"初二"}]
6. 试运行时注入 example 值; 渲染后总长度超过 max_tokens*4 字符 → 提示裁剪
```

**Prompt 版本状态机：**

```
DRAFT ──submit──▶ REVIEWING ──approve──▶ APPROVED ──activate──▶ ACTIVE ──(被替换)──▶ ARCHIVED
  ▲                   │reject                                   │
  └───────────────────▼                                         │
REJECTED ──修改重提(新version)                                   │
                                ARCHIVED ──rollback(重新activate)─┘
```

| 守卫 | 规则 |
|------|------|
| G1 | 仅 DRAFT / REJECTED 状态可编辑内容 |
| G2 | 仅 APPROVED 状态可执行 activate |
| G3 | 同一 scene_code 全表仅允许一个 ACTIVE 版本（uk_scene_version + 激活事务保证） |
| G4 | 编辑人 ≠ 审核人 ≠ 激活复核人（三方分离，super_admin 可豁免审核但记高危审计） |
| G5 | ARCHIVED 版本只读，仅可作为回滚目标引用 |
| G6 | 激活/回滚操作幂等：重复请求同一版本激活返回当前状态不报错 |

### 8.3 审核流程

```
内容产生(业务方)
→ 机审前置(统一安全服务, 500ms 超时降级为「进人审」fail-secure)
→ 分流:
   ├─ LOW 且未命中 → 直接放行, 记 machine_result
   ├─ MEDIUM/HIGH → 创建 review_task(PENDING), 按 biz_type 路由到对应技能组队列
   └─ CRITICAL → 直接拦截不下发, 同步创建 CRITICAL 任务并即时告警值班群
→ 人审:
   1. 审核员认领(CAS 抢占 assignee, 15min 无操作自动释放回池)
   2. 查看快照+机审明细, 提交结论(APPROME=通过 / REJECT=驳回+理由)
   3. 驳回内容允许修改后重提 → round_no+1 生成新任务, 原任务保留不覆盖
→ SLA 超时升级: HIGH 2h / MEDIUM 8h / LOW 24h 未处理 → 推送组长看板并标红
→ 结果回写: review.completed 事件(Outbox) → 业务方按结论放行/下线/通知作者
```

```
PUT    /api/admin/reviews/{id}/decision       # 提交结论 {action, remark} (乐观锁)
POST   /api/admin/reviews/{id}/release        # 主动释放回池
GET    /api/admin/reviews/{id}                # 详情(快照+机审明细+操作记录)
GET    /api/admin/reviews/stats               # 工作量/时效/驳回率统计

# 权限点: audit:review:read / audit:review:update / audit:review:supervise(组长释放/改派)
```

### 8.5 审核任务状态机与守卫

```
PENDING ──claim──▶ IN_REVIEW ──approve──▶ APPROVED(终态)
   ▲                  │reject                ▲
   │release/超时释放    ▼                      │ 重提(round+1 创建新任务)
   └────────────── REJECTED(终态) ─────────────┘
```

| 守卫 | 规则 |
|------|------|
| G1 | 认领 CAS：UPDATE ... SET assignee=me, status=1 WHERE id=? AND status=0，他人已认领 → 409 |
| G2 | 驳回必须填写 ≥5 字理由 |
| G3 | 审核人不可审核自己创建/提交的内容（按 biz 方创建人比对） |
| G4 | CRITICAL 机审直接拦截，不入常规队列，走应急响应流程 |
| G5 | 快照只读；驳回重提生成新任务（round+1），不修改历史任务 |
| G6 | 结论提交幂等：乐观锁 version 冲突 → 409 提示刷新 |
| G7 | 认领 15min 无操作自动释放；释放/超时释放均写 review_action_log |

### 9.2 数据链路与数据模型

```
客户端埋点(SDK) ─┐
业务库 Binlog ────┼─▶ CDC(Kafka) → Flink 清洗(dwd) → 聚合(dws) → daily_stats(T+1 物化)
model_call_log ──┘                                        ↘ 当日实时指标 → Redis 计数(HLL/INCR)
```

```sql
-- 每日指标物化表
CREATE TABLE daily_stats (
    id            BIGINT PRIMARY KEY AUTO_INCREMENT,
    stat_date     DATE NOT NULL,
    metric_code   VARCHAR(64) NOT NULL COMMENT 'dau/new_users/retention_d1/ai_cost... 对齐指标字典',
    dimension     JSON COMMENT '维度 {"stage":"JUNIOR","subject":"MATH","channel":"hw"}',
    dimension_hash CHAR(16) NOT NULL COMMENT 'dimension 规范化 JSON 的 MD5 前 16 位',
    metric_value  DECIMAL(20,4) NOT NULL,
    updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_date_metric_dim (stat_date, metric_code, dimension_hash),
    INDEX idx_metric_date (metric_code, stat_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

* 聚合任务幂等：重跑按 `uk_date_metric_dim` ON DUPLICATE KEY UPDATE 覆盖写。
* 当日实时指标（DAU/调用量/成本）走 Redis 计数，日终由聚合任务收敛入 daily_stats 并清零重置。

## 11. 缓存设计

| Redis Key | 内容 | TTL | 失效策略 |
|-----------|------|-----|----------|
| admin:perm:{userId} | 用户权限编码集 | 300s | 权限变更时主动删除 |
| admin:prompt:active:{scene_code} | 激活版 Prompt 全量 | 60s | 激活/回滚时主动删除 |
| admin:route:{scene_code} | 场景模型路由 | 60s | 路由变更时主动删除 |
| admin:provider:{provider_code} | 供应商配置(含解密后密钥, 仅服务端内存可达) | 300s | 变更审批生效后删除 |
| admin:dash:rt:{metric}:{date} | 当日实时指标计数 | 次日 00:10 | 日终收敛后自然过期 |
| admin:review:pool:{biz_type} | 待审队列计数(展示) | 60s | 任务状态变更时增量更新 |

* 原则：DB 为权威，缓存仅作展示与高频读加速；所有主动删除失败依赖 TTL 兜底，最大不一致窗口 = TTL。

## 12. 错误码与降级策略

**通用错误（HTTP 语义 + 业务码前缀 ADMIN）：**

| 业务码 | HTTP | 场景 | 处理建议 |
|--------|------|------|----------|
| ADMIN_001 | 403 | 无权限(权限编码不匹配) | 联系管理员分配 |
| ADMIN_002 | 400 | 参数校验失败(详情见 message) | 修正表单 |
| ADMIN_003 | 409 | 乐观锁冲突(数据已被他人修改) | 刷新后重试 |
| ADMIN_004 | 409 | 资源被锁定/认领 | 刷新队列 |
| ADMIN_005 | 423 | 双人审批未完成, 变更未生效 | 等待审批人确认 |
| ADMIN_006 | 40004 | Prompt 占位符与变量声明不一致 | 按提示修正模板 |
| ADMIN_007 | 40006 | 降级链成环 | 修正 backup_chain |
| ADMIN_008 | 40007 | 供应商仍被路由引用, 禁用被拒 | 先调整路由 |
| ADMIN_009 | 503 | 依赖服务(安全服务/数仓)不可用 | 按降级矩阵执行 |

> 各细分工作台的专属错误码段（5xxxx）以对应工作台文档为权威，本表不重复定义。

**降级矩阵：**

| 编号 | 故障 | 降级动作 |
|------|------|----------|
| D1 | 权限缓存 Redis 故障 | 回源 DB 查询 + 网关限流(50 QPS), 权限校验不降级放行(fail-secure) |
| D2 | Prompt 缓存故障 | DB 直读 + 本地 Caffeine 30s 二级缓存 |
| D3 | 机审安全服务超时/故障 | 内容不直接放行, 全量转人审队列(fail-secure 红线) |
| D4 | 数仓聚合延迟(T+1 未产出) | 看板展示最近可用日期并标注「数据延迟」, 不展示空数据误导 |
| D5 | 实时指标 Redis 故障 | 隐藏当日实时卡, 仅展示 T+1 物化值 |
| D6 | 供应商连通性测试失败 | 不阻塞保存, 标记 health=DOWN 供路由决策参考 |
| D7 | 审计日志写入失败 | 业务事务回滚(审计优先红线), 告警 P1 |
| D8 | 报表导出中心不可用 | 前端提示稍后再试, 不降级为同步导出(防网关超时) |

## 13. 安全与合规

```
1. 网络边界: 独立域名 admin.primetop.cn + IP 白名单(办公网/VPN); 全站 HTTPS
2. 账号安全: 密码 bcrypt(cost≥10); super_admin 与 ai:provider:approve 角色强制 TOTP 二次验证
3. 会话管理: JWT 2h + Refresh Token 7d; 异地/新设备登录告警; 禁用账号 Token 即时吊销(黑名单)
4. 敏感数据:
   - 手机号默认脱敏展示; 查看明文需 user:phone:reveal 权限且强制写审计(明文 60s 自动恢复脱敏)
   - API Key 加密落库, 前端永不回显明文
5. 审计日志: append-only(应用层无 UPDATE/DELETE 入口), 保留 ≥3 年; 高危操作
   (权限变更/密钥变更/Prompt 激活/批量上下线)实时推送安全群
6. 数据最小化: 内容编辑默认仅可见业务数据, 学生个体数据(画像/答题明细)不在本后台暴露,
   学情分析走专用驾驶舱并受数据合规工作台管控
7. 未成年人保护: 涉未成年人内容审核从严(risk_level 抬升一档); 审核快照含未成年人信息时
   访问权限收敛到 audit:review:update 持有者
```
