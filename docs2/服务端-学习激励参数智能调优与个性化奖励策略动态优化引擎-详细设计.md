# 学习激励参数智能调优与个性化奖励策略动态优化引擎 - 详细设计

## 1. 概述

### 1.1 功能定位

本引擎是 PrimeTop 教育平台激励体系的"大脑"，负责对已有的激励规则引擎（成就解锁、积分发放、打卡奖励、激励时刻编排等）进行**参数层面的智能调优**和**学生个体层面的个性化适配**。

与已有的「用户学习激励中心与行为奖励统一规则引擎」的关系：
- **规则引擎**：定义激励规则（做什么动作给多少分），是静态配置的执行层
- **本引擎**：基于数据驱动，动态优化规则中的参数值，并针对每个学生生成个性化激励策略

### 1.2 核心目标

| 目标 | 描述 |
| --- | --- |
| 参数自优化 | 通过 A/B 实验与多臂老虎机（MAB）自动寻找最优激励参数 |
| 个性化适配 | 根据学生激励响应画像，为不同学生匹配不同的奖励策略 |
| 行为经济学应用 | 引入损失厌恶、可变奖励、目标梯度效应等行为经济学模型提升激励效果 |
| 实时反馈调整 | 基于学生近期激励响应信号（活跃度、完成率、停留时长）实时微调策略 |
| 防激励疲劳 | 监测奖励阈值递增导致的"通货膨胀"和"激励疲劳"，自动执行策略刷新 |

### 1.3 适用范围

- 覆盖学段：小学、初中、高中（幼儿阶段因认知限制仅使用固定策略）
- 激励场景：每日学习任务、连续打卡、错题订正、练习测评、知识突破、社交分享
- 奖励类型：积分、勋章、学习称号、虚拟形象道具、会员体验卡、推荐优先级提升

### 1.4 系统边界

## 3. 核心算法设计

### 3.1 学生激励响应画像构建

#### 3.1.1 动机类型分类模型

基于学生历史行为数据，将学生分为五种动机类型：

```python
from enum import Enum
from typing import Dict, List
import numpy as np

class MotivationType(str, Enum):
    ACHIEVEMENT = "achievement"       # 成就导向：追求高分、勋章、排名
    SOCIAL = "social"                 # 社交导向：分享、互动、协作
    EXPLORATION = "exploration"       # 探索导向：新内容、新题型、知识拓展
    MASTERY = "mastery"               # 精通导向：深度理解、反复练习、攻克难点
    BALANCED = "balanced"             # 均衡型：无明显偏好


class StudentMotivationClassifier:
    """学生动机类型分类器"""

    # 各动机类型的特征权重
    FEATURE_WEIGHTS = {
        MotivationType.ACHIEVEMENT: {
            "rank_check_freq": 0.25,
            "score_share_freq": 0.20,
            "badge_pursuit_ratio": 0.25,
            "challenge_accept_rate": 0.15,
            "high_score_retry_rate": 0.15,
        },
        MotivationType.SOCIAL: {
            "share_action_freq": 0.30,
            "study_room_join_freq": 0.20,
            "peer_help_freq": 0.25,
            "comment_post_freq": 0.25,
        },
        MotivationType.EXPLORATION: {
            "new_chapter_open_rate": 0.25,
            "cross_subject_browse_freq": 0.25,
            "extra_content_click_rate": 0.25,
            "ai_curiosity_question_rate": 0.25,
        },
        MotivationType.MASTERY: {
            "retry_until_correct_rate": 0.30,
            "deep_explanation_view_rate": 0.25,
            "same_topic_repeat_practice": 0.25,
            "error_analysis_read_rate": 0.20,
        },
    }

    def classify(
        self,
        student_id: int,
        behavior_features: Dict[str, float],
        min_confidence: float = 0.35,
    ) -> MotivationType:
        """
        对学生进行动机类型分类。

        Args:
            student_id: 学生ID
            behavior_features: 行为特征字典，各特征值归一化到[0,1]
            min_confidence: 最低置信度阈值，低于此值归类为balanced

        Returns:
            动机类型枚举值
        """
        scores: Dict[MotivationType, float] = {}

        for m_type, weights in self.FEATURE_WEIGHTS.items():
            score = sum(
                weights.get(feature, 0) * behavior_features.get(feature, 0.0)
                for feature in weights
            )
            scores[m_type] = score

        # 归一化
        total = sum(scores.values())
        if total > 0:
            scores = {k: v / total for k, v in scores.items()}

        # 选择最高分类型
        best_type = max(scores, key=scores.get)
        best_score = scores[best_type]

        # 如果最高分低于阈值，或多个类型接近，归类为均衡型
        sorted_scores = sorted(scores.values(), reverse=True)
        if best_score < min_confidence:
            return MotivationType.BALANCED

        if len(sorted_scores) >= 2 and (sorted_scores[0] - sorted_scores[1]) < 0.10:
            return MotivationType.BALANCED

        return best_type
```

#### 3.1.2 奖励敏感度建模

```python
class RewardSensitivityModel:
    """
    基于历史激励响应数据，建模学生对各类奖励的敏感度。

    敏感度定义：学生收到某类奖励后，在接下来24h内活跃度提升的比例。
    """

    def compute_sensitivity(
        self,
        student_id: int,
        response_events: List[dict],
        reward_types: List[str],
        smoothing_alpha: float = 0.3,
    ) -> Dict[str, float]:
        """
        使用指数加权移动平均（EWMA）计算各类奖励的敏感度。

        Args:
            response_events: 历史响应事件列表
            reward_types: 待计算的奖励类型列表
            smoothing_alpha: 平滑系数，越大越偏向近期数据

        Returns:
            {reward_type: sensitivity_score} 字典，值域[0,1]
        """
        sensitivities: Dict[str, float] = {}

        for r_type in reward_types:
            type_events = [
                e for e in response_events
                if e["reward_type"] == r_type
            ]

            if not type_events:
                # 无数据时使用先验均值
                sensitivities[r_type] = 0.5
                continue

            # 按时间排序（旧→新）
            type_events.sort(key=lambda e: e["event_time"])

            # EWMA 计算
            ewma = 0.5  # 初始先验
            for event in type_events:
                response_score = event.get("response_score", 0.5)
                ewma = smoothing_alpha * response_score + (1 - smoothing_alpha) * ewma

            sensitivities[r_type] = round(ewma, 4)

        return sensitivities
```

### 3.2 多臂老虎机（MAB）参数优化

#### 3.2.1 Thompson Sampling 实现

```python
import numpy as np
from typing import List, Dict
import json

class ThompsonSamplingOptimizer:
    """
    基于Thompson Sampling的多臂老虎机参数优化器。

    用于在多个候选参数值之间进行探索-利用平衡（explore-exploit trade-off）。
    每个候选参数值是一个"臂"(arm)，每次分配学生到某个臂，
    收集响应数据后更新该臂的后验分布。
    """

    def select_arm(
        self,
        experiment_id: str,
        arms: List[Dict],
    ) -> str:
        """
        使用Thompson Sampling选择当前最优臂。

        Args:
            experiment_id: 实验ID
            arms: 实验臂列表，每个臂包含:
                - arm_id: 臂ID
                - value: 参数值
                - alpha: Beta分布参数α（默认1）
                - beta: Beta分布参数β（默认1）

        Returns:
            被选中的arm_id
        """
        best_arm_id = None
        best_sample = -1.0

        for arm in arms:
            alpha = max(arm.get("alpha", 1.0), 0.01)
            beta = max(arm.get("beta", 1.0), 0.01)

            # 从Beta(α, β)分布中采样
            sample = np.random.beta(alpha, beta)

            if sample > best_sample:
                best_sample = sample
                best_arm_id = arm["arm_id"]

        return best_arm_id

    def update_arm(
        self,
        experiment_id: str,
        arm_id: str,
        response_score: float,
        success_threshold: float = 0.5,
    ) -> Dict[str, float]:
        """
        根据学生响应更新臂的后验分布参数。

        Args:
            experiment_id: 实验ID
            arm_id: 臂ID
            response_score: 响应评分[0,1]
            success_threshold: 成功阈值

        Returns:
            更新后的 {alpha, beta} 字典
        """
        if response_score >= success_threshold:
            new_alpha = None  # 从Redis读取当前值+1
            new_beta = None   # 保持不变
            # 实际实现中从Redis更新：
            # HINCRBY incentive:mab:{exp_id}:arm:{arm_id} alpha 1
        else:
            new_alpha = None  # 保持不变
            new_beta = None   # +1
            # HINCRBY incentive:mab:{exp_id}:arm:{arm_id} beta 1

        return {"alpha": new_alpha, "beta": new_beta}

    def get_winning_arm(
        self,
        arms: List[Dict],
        min_samples: int = 200,
        min_confidence: float = 0.95,
    ) -> Dict | None:
        """
        判断是否有明确胜出的臂。

        使用Beta分布的置信区间判断。

        Args:
            arms: 所有臂的当前状态
            min_samples: 最小样本量要求
            min_confidence: 最小置信度要求

        Returns:
            胜出臂信息或None
        """
        total_samples = sum(a["alpha"] + a["beta"] - 2 for a in arms)
        if total_samples < min_samples:
            return None

        # 计算每个臂的期望和95%置信区间下界
        arm_stats = []
        for arm in arms:
            alpha, beta = arm["alpha"], arm["beta"]
            mean = alpha / (alpha + beta)
            # Beta分布的95%置信区间下界（近似）
            ci_lower = self._beta_ppf(alpha, beta, 1 - min_confidence)
            arm_stats.append({
                "arm_id": arm["arm_id"],
                "value": arm["value"],
                "mean": mean,
                "ci_lower": ci_lower,
                "samples": alpha + beta - 2,
            })

        # 找到期望最高的臂
        best = max(arm_stats, key=lambda x: x["mean"])

        # 检查是否显著优于其他所有臂
        for other in arm_stats:
            if other["arm_id"] == best["arm_id"]:
                continue
            if best["ci_lower"] < other["mean"]:
                # 最佳臂的置信下界仍低于其他臂的期望，不够显著
                return None

        return best

    def _beta_ppf(self, alpha: float, beta: float, q: float) -> float:
        """Beta分布分位数函数（近似实现，生产环境用scipy.stats.beta.ppf）"""
        from scipy.stats import beta as beta_dist
        return beta_dist.ppf(q, alpha, beta)
```

#### 3.2.2 参数调优调度器

```python
from datetime import datetime, timedelta
from typing import Optional

class ParamOptimizationScheduler:
    """
    参数调优实验调度器。
    管理实验的生命周期：创建→运行→判定胜者→应用结果。
    """

    # 实验配置
    MIN_SAMPLES_PER_ARM = 200       # 每个臂最少样本量
    MAX_EXPERIMENT_DAYS = 14        # 单次实验最长天数
    MIN_DAILY_RESPONSES = 50        # 每日最少响应数才继续实验
    CONFIDENCE_THRESHOLD = 0.95     # 置信度阈值

    # 参数调优范围模板（基于业务规则的安全边界）
    PARAM_BOUNDS = {
        "task_complete_base_points": {"min": 5, "max": 50, "step": 5},
        "streak_bonus_multiplier":   {"min": 1.0, "max": 3.0, "step": 0.5},
        "badge_rarity_threshold":    {"min": 0.05, "max": 0.30, "step": 0.05},
        "quiz_pass_bonus_points":    {"min": 10, "max": 80, "step": 10},
        "mistake_correct_points":    {"min": 5, "max": 30, "step": 5},
        "share_reward_points":       {"min": 5, "max": 40, "step": 5},
        "daily_cap_points":          {"min": 100, "max": 500, "step": 50},
    }

    def create_experiment(
        self,
        param_key: str,
        candidate_values: Optional[List] = None,
    ) -> Dict:
        """
        为指定参数创建新的调优实验。

        Args:
            param_key: 参数键
            candidate_values: 候选值列表（如未提供，根据PARAM_BOUNDS自动生成）

        Returns:
            实验配置字典
        """
        if param_key not in self.PARAM_BOUNDS:
            raise ValueError(f"参数 {param_key} 不在可调优范围内")

        bounds = self.PARAM_BOUNDS[param_key]

        if candidate_values is None:
            # 自动生成候选值（等间距采样3-5个）
            step = bounds["step"]
            values = []
            v = bounds["min"]
            while v <= bounds["max"] and len(values) < 5:
                values.append(round(v, 4))
                v += step
            candidate_values = values

        # 确保候选值在安全范围内
        candidate_values = [
            v for v in candidate_values
            if bounds["min"] <= v <= bounds["max"]
        ]

        if len(candidate_values) < 2:
            raise ValueError(f"参数 {param_key} 的有效候选值不足2个")

        # 构造实验臂
        arms = [
            {
                "arm_id": f"arm_{chr(97 + i)}",  # arm_a, arm_b, arm_c...
                "value": val,
                "prior_alpha": 1.0,   # Beta(1,1) = 均匀分布先验
                "prior_beta": 1.0,
            }
            for i, val in enumerate(candidate_values)
        ]

        experiment = {
            "experiment_id": f"exp_{datetime.utcnow().strftime('%Y%m%d%H%M%S')}_{param_key}",
            "param_key": param_key,
            "arms": arms,
            "assignment_rule": "thompson",
            "status": "running",
            "start_at": datetime.utcnow(),
            "end_at": datetime.utcnow() + timedelta(days=self.MAX_EXPERIMENT_DAYS),
        }

        return experiment

    def check_and_conclude(self, experiment: Dict) -> Optional[Dict]:
        """
        检查实验是否可以结束并得出结论。

        Returns:
            结论字典或None（实验继续）
        """
        optimizer = ThompsonSamplingOptimizer()

        # 检查是否超时
        if datetime.utcnow() > experiment["end_at"]:
            return {
                "reason": "timeout",
                "winning_arm": optimizer.get_winning_arm(experiment["arms"]),
            }

        # 检查样本量
        total_samples = sum(
            arm["alpha"] + arm["beta"] - 2 for arm in experiment["arms"]
        )
        if total_samples < self.MIN_SAMPLES_PER_ARM * len(experiment["arms"]):
            return None

        # 检查是否有胜出臂
        winner = optimizer.get_winning_arm(
            experiment["arms"],
            min_samples=self.MIN_SAMPLES_PER_ARM,
            min_confidence=self.CONFIDENCE_THRESHOLD,
        )

        if winner:
            return {
                "reason": "confidence_reached",
                "winning_arm": winner,
            }

        return None
```

### 3.3 个性化策略匹配引擎

#### 3.3.1 策略匹配算法

```python
from typing import List, Dict, Tuple
import math

class StrategyMatcher:
    """
    根据学生画像匹配最优激励策略。

    匹配过程：
    1. 基于动机类型筛选候选策略集
    2. 基于奖励敏感度对候选策略打分
    3. 基于疲劳度进行调节
    4. 输出最终策略推荐
    """

    # 动机类型 → 推荐行为经济学模型
    MOTIVATION_MODEL_MAP = {
        "achievement": ["goal_gradient", "variable_reward"],
        "social":      ["variable_reward", "sunk_cost"],
        "exploration": ["variable_reward"],
        "mastery":     ["goal_gradient", "loss_aversion"],
        "balanced":    ["variable_reward", "goal_gradient"],
    }

    def match(
        self,
        profile: Dict,
        strategies: List[Dict],
        fatigue_score: float,
    ) -> Tuple[str, float]:
        """
        为学生匹配最优策略。

        Args:
            profile: 学生激励画像
            strategies: 可用策略列表
            fatigue_score: 当前疲劳度[0,1]

        Returns:
            (strategy_id, match_score) 元组
        """
        motivation = profile.get("motivation_type", "balanced")
        sensitivities = profile.get("reward_sensitivity", {})
        preferred_models = self.MOTIVATION_MODEL_MAP.get(motivation, ["variable_reward"])

        scored: List[Tuple[str, float]] = []

        for strategy in strategies:
            if not strategy.get("is_active"):
                continue

            score = self._score_strategy(
                strategy, sensitivities, preferred_models, fatigue_score
            )
            scored.append((strategy["strategy_id"], score))

        if not scored:
            return ("default_balanced_v1", 0.5)

        scored.sort(key=lambda x: x[1], reverse=True)
        return scored[0]

    def _score_strategy(
        self,
        strategy: Dict,
        sensitivities: Dict[str, float],
        preferred_models: List[str],
        fatigue_score: float,
    ) -> float:
        """计算策略匹配评分"""
        score = 0.0

        # 因子1: 行为经济学模型匹配（权重 0.35）
        model = strategy.get("behavior_economics_model", "variable_reward")
        model_score = 1.0 if model in preferred_models else 0.4
        score += 0.35 * model_score

        # 因子2: 奖励类型敏感度匹配（权重 0.35）
        param_overrides = strategy.get("param_overrides", {})
        # 分析策略主要影响哪些奖励类型
        reward_types_affected = self._infer_reward_types(param_overrides)
        sensitivity_scores = [
            sensitivities.get(rt, 0.5) for rt in reward_types_affected
        ]
        avg_sensitivity = (
            sum(sensitivity_scores) / len(sensitivity_scores)
            if sensitivity_scores else 0.5
        )
        score += 0.35 * avg_sensitivity

        # 因子3: 疲劳度调节（权重 0.30）
        # 高疲劳度时，偏向保守策略（更低的奖励幅度、更稀疏的触发）
        if fatigue_score > 0.7:
            # 寻找策略是否降低了奖励频率
            has_fatigue_relief = any(
                k.endswith("_threshold") and v > 0.2
                for k, v in param_overrides.items()
            )
            fatigue_score_val = 0.8 if has_fatigue_relief else 0.2
        elif fatigue_score < 0.3:
            fatigue_score_val = 0.9  # 低疲劳，任何策略都可以
        else:
            fatigue_score_val = 0.5
        score += 0.30 * fatigue_score_val

        return round(score, 4)

    def _infer_reward_types(self, param_overrides: Dict) -> List[str]:
        """从参数覆盖推断策略主要影响的奖励类型"""
        types = set()
        for key in param_overrides:
            if "points" in key or "bonus" in key:
                types.add("points")
            elif "badge" in key:
                types.add("badge")
            elif "streak" in key:
                types.add("streak")
            elif "share" in key or "social" in key:
                types.add("social")
            elif "unlock" in key:
                types.add("unlock")
        return list(types) if types else ["points"]
```

### 3.4 激励疲劳监测与恢复

```python
from datetime import datetime, timedelta

class FatigueMonitor:
    """
    激励疲劳度监测与恢复引擎。

    疲劳度信号：
    1. 奖励忽略率升高（收到奖励后无后续活跃行为）
    2. 奖励敏感度持续下降（EWMA趋势）
    3. 日活跃时长下降但奖励频率不变
    4. 连续低响应评分事件增多
    """

    FATIGUE_THRESHOLDS = {
        "warning": 0.6,     # 预警阈值
        "intervention": 0.75,  # 干预阈值
        "critical": 0.85,   # 严重阈值
    }

    def compute_fatigue_score(
        self,
        student_id: int,
        recent_events: List[dict],
        daily_metrics: Dict,
    ) -> float:
        """
        计算学生当前的激励疲劳度评分。

        Args:
            recent_events: 最近7天的激励响应事件
            daily_metrics: 最近7天的日维度指标

        Returns:
            疲劳度评分[0,1]，越高越疲劳
        """
        if not recent_events:
            return 0.0

        # 信号1: 最近7天奖励忽略率
        total_rewards = len(recent_events)
        ignored = sum(1 for e in recent_events if e.get("response_score", 0) < 0.2)
        ignore_rate = ignored / total_rewards if total_rewards > 0 else 0

        # 信号2: 响应评分下降趋势
        recent_half = recent_events[len(recent_events)//2:]
        early_half = recent_events[:len(recent_events)//2]
        recent_avg = sum(e.get("response_score", 0.5) for e in recent_half) / max(len(recent_half), 1)
        early_avg = sum(e.get("response_score", 0.5) for e in early_half) / max(len(early_half), 1)
        trend_decline = max(0, early_avg - recent_avg)

        # 信号3: 奖励频率vs活跃度的剪刀差
        reward_freq = total_rewards / 7.0  # 日均奖励次数
        avg_active_minutes = daily_metrics.get("avg_daily_active_minutes", 60)
        # 如果奖励频率高但活跃时长低，说明激励效果在减弱
        frequency_activity_gap = max(0, (reward_freq / 10) - (avg_active_minutes / 120))

        # 加权合成
        fatigue = (
            0.40 * ignore_rate +
            0.35 * trend_decline * 2 +  # 放大趋势信号
            0.25 * min(frequency_activity_gap, 1.0)
        )

        return round(min(max(fatigue, 0.0), 1.0), 4)

    def get_recovery_action(self, fatigue_score: float) -> Dict:
        """
        根据疲劳度等级返回恢复策略建议。

        Returns:
            恢复动作字典
        """
        if fatigue_score < self.FATIGUE_THRESHOLDS["warning"]:
            return {
                "level": "normal",
                "action": "maintain",
                "adjustments": {},
            }

        if fatigue_score < self.FATIGUE_THRESHOLDS["intervention"]:
            return {
                "level": "warning",
                "action": "reduce_frequency",
                "adjustments": {
                    "reward_trigger_threshold_boost": 0.15,  # 提高触发门槛15%
                    "badge_grant_cooldown_hours": 48,        # 勋章冷却期翻倍
                    "variable_reward_ratio": 0.5,            # 增加可变奖励比例
                },
            }

        if fatigue_score < self.FATIGUE_THRESHOLDS["critical"]:
            return {
                "level": "intervention",
                "action": "strategy_reset",
                "adjustments": {
                    "reward_trigger_threshold_boost": 0.30,
                    "badge_grant_cooldown_hours": 72,
                    "suppress_low_value_rewards": True,
                    "introduce_novel_reward_type": True,  # 引入新的奖励类型
                    "variable_reward_ratio": 0.7,
                },
            }

        return {
            "level": "critical",
            "action": "full_reset",
            "adjustments": {
                "pause_rewards_hours": 24,               # 暂停奖励24小时
                "strategy_force_reassign": True,          # 强制重新分配策略
                "notify_product_team": True,              # 通知产品团队
                "suppress_all_push_except_urgent": True,
            },
        }
```

## 5. 关键业务流程

### 5.1 激励参数读取流程（同步，高频率）

这是每次奖励发放时都会调用的核心路径，要求 **P99 < 20ms**。

```
学生完成任务
    │
    ▼
奖励规则引擎准备发放奖励
    │
    ▼
读取学生激励参数 ────────────────────────────────────┐
    │                                                │
    ├─ 1. 查Redis缓存 incentive:strategy:{student_id} │
    │     命中 → 返回参数（<1ms）                     │
    │                                                │
    ├─ 2. 未命中 → 查MySQL student_incentive_profile  │
    │     命中 → 回填Redis → 返回参数（<5ms）         │
    │                                                │
    └─ 3. 未命中（新用户/冷启动）→                    │
          读取全局默认参数 → 返回（<3ms）              │
          异步触发画像初始化                           │
    │                                                │
    ▼ ◄──────────────────────────────────────────────┘
奖励规则引擎根据参数计算具体奖励金额
    │
    ▼
发放奖励 → 异步上报激励响应事件
```

### 5.2 画像刷新流程（异步，每日批量）

```
每日凌晨 02:00 定时任务触发
    │
    ▼
读取需要刷新的学生列表
    │ (按 last_updated 排序，优先刷新超过7天未更新的)
    ▼
批量读取最近7天行为数据 + 响应事件
    │
    ▼
┌─────────────────────────────────────┐
│ Step 1: 动机类型分类                 │
│ 输入: 行为特征向量                    │
```

## 6. 行为经济学模型应用

### 6.1 可变奖励（Variable Reward）

**原理**：固定的奖励会快速失去吸引力，而不确定性的奖励（如抽奖箱）能持续激发多巴胺分泌。

**实现方式**：

```python
import random

class VariableRewardEngine:
    """可变奖励引擎"""

    def compute_reward(
        self,
        base_points: int,
        variable_ratio: float = 0.3,
        multiplier_range: tuple = (0.5, 2.0),
    ) -> dict:
        """
        计算可变奖励。

        Args:
            base_points: 基础积分
            variable_ratio: 可变比例（0=完全固定, 1=完全随机）
            multiplier_range: 倍数范围

        Returns:
            {"points": int, "is_bonus": bool, "multiplier": float, "display_mode": str}
        """
        fixed_part = base_points * (1 - variable_ratio)
        variable_part = base_points * variable_ratio

        multiplier = random.uniform(*multiplier_range)
        variable_amount = int(variable_part * multiplier)

        total_points = int(fixed_part + variable_amount)
        is_bonus = multiplier > 1.3

        # 展示策略
        if is_bonus:
            display_mode = "jackpot"  # 中奖式展示
        elif multiplier < 0.7:
            display_mode = "consolation"  # 鼓励式展示
        else:
            display_mode = "normal"

        return {
            "points": total_points,
            "is_bonus": is_bonus,
            "multiplier": round(multiplier, 2),
            "display_mode": display_mode,
        }
```

### 6.2 目标梯度效应（Goal Gradient Effect）

**原理**：越接近目标，学生的动力越强。通过可视化进度和加速奖励来利用这一心理。

```python
class GoalGradientEngine:
    """目标梯度效应引擎"""

    def compute_progress_bonus(
        self,
        current_progress: float,   # 当前进度 [0, 1]
        base_reward: int,
    ) -> dict:
        """
        根据目标梯度计算进度加成。

        越接近100%完成，额外加成越大。
        """
        if current_progress < 0.5:
            # 前半程：基础奖励，不加成
            bonus = 0
            motivation_msg = "继续加油！完成更多任务可获得额外奖励"
        elif current_progress < 0.8:
            # 中后段：小幅加成
            bonus = int(base_reward * 0.2)
            motivation_msg = "已过半程！再加把劲"
        elif current_progress < 0.95:
            # 冲刺段：中幅加成
            bonus = int(base_reward * 0.5)
            motivation_msg = "即将完成！每一步都在加分"
        else:
            # 最后冲刺：大幅加成
            bonus = int(base_reward * 1.0)
            motivation_msg = "最后一步！冲刺到底！"

        return {
            "base_reward": base_reward,
            "progress_bonus": bonus,
            "total_reward": base_reward + bonus,
            "current_progress": round(current_progress, 4),
            "motivation_message": motivation_msg,
        }
```

### 6.3 损失厌恶（Loss Aversion）

**原理**：失去已有的东西比获得新的东西更让人痛苦。利用连续打卡的"失去风险"来增强黏性。

```python
class LossAversionEngine:
    """损失厌恶引擎"""

    def compute_streak_warning(
        self,
        student_id: int,
        current_streak: int,
        last_active_date: str,
        daily_cap_hours: int = 20,
    ) -> dict:
        """
        计算连续打卡损失风险提醒。

        当学生有较长连续记录但当天尚未学习时，
        发送"即将失去"提醒。
        """
        # 只有连续天数 >= 3 才触发损失厌恶
        if current_streak < 3:
            return {"should_remind": False}

        # 计算潜在损失
        potential_loss = self._calculate_streak_value(current_streak)

        return {
            "should_remind": True,
            "current_streak": current_streak,
            "potential_loss_points": potential_loss,
            "potential_loss_badges": self._get_endangered_badges(current_streak),
            "urgency_level": self._get_urgency(current_streak),
            "message_template": self._craft_loss_message(
                current_streak, potential_loss
            ),
        }

    def _calculate_streak_value(self, streak_days: int) -> int:
        """计算连续打卡的累积价值（积分等价物）"""
        # 等差数列求和：每天5基础分 + 连续天数×2加成
        total = 0
        for day in range(1, streak_days + 1):
            total += 5 + day * 2
        return total

    def _craft_loss_message(self, streak: int, loss_points: int) -> str:
        if streak >= 30:
            return f"你已经连续学习{streak}天了！今天不学习将失去{loss_points}积分和「月度全勤」勋章"
        elif streak >= 14:
            return f"连续{streak}天的努力！今天继续保持，不要让记录中断"
        elif streak >= 7:
            return f"坚持了一周了！今天完成学习即可保持{streak}天连续记录"
        else:
            return f"已连续学习{streak}天，继续保持吧！"
```

```python
class IncentiveDegradationHandler:
    """激励引擎降级处理器"""

    def get_params_with_degradation(self, student_id: int) -> dict:
        """
        多级降级获取参数：
        Level 0: 正常 - Redis缓存命中
        Level 1: Redis未命中 → MySQL查询
        Level 2: MySQL异常 → 全局默认参数
        Level 3: 全局配置也异常 → 硬编码兜底参数
        """
        try:
            # Level 0: Redis
            cached = self.redis_client.hgetall(f"incentive:strategy:{student_id}")
            if cached:
                return json.loads(cached["param_overrides"])

            # Level 1: MySQL
            profile = self.db.query(
                "SELECT * FROM student_incentive_profile WHERE student_id = %s",
                [student_id]
            )
            if profile:
                strategy = self.db.query(
                    "SELECT * FROM incentive_strategy_template WHERE strategy_id = %s",
                    [profile["current_strategy_id"]]
                )
                if strategy:
                    self._backfill_redis(student_id, strategy)
                    return strategy["param_overrides"]

        except Exception as e:
            logger.warning(f"激励参数获取降级: student_id={student_id}, error={e}")

        try:
            # Level 2: 全局默认
            return self.global_config.get("incentive.default_params", {})
        except Exception:
            # Level 3: 硬编码兜底
            return {
                "task_complete_base_points": 20,
                "streak_bonus_multiplier": 1.0,
                "badge_rarity_threshold": 0.10,
                "quiz_pass_bonus_points": 30,
                "mistake_correct_points": 10,
```

```python
import asyncio
from typing import List

class BatchProfileRefresher:
    """批量画像刷新器"""

    BATCH_SIZE = 500       # 每批学生数
    MAX_CONCURRENCY = 10   # 最大并发数

    async def refresh_batch(self, student_ids: List[int]):
        """
        分批并发刷新学生画像。
        每天凌晨处理约10万活跃学生，目标在30分钟内完成。
        """
        # 分批
        batches = [
            student_ids[i:i + self.BATCH_SIZE]
            for i in range(0, len(student_ids), self.BATCH_SIZE)
        ]

        semaphore = asyncio.Semaphore(self.MAX_CONCURRENCY)

        async def process_batch(batch: List[int]):
            async with semaphore:
                # 批量查询行为数据（一次查询所有学生的7天数据）
                behavior_data = await self.batch_query_behavior(batch)
                response_events = await self.batch_query_responses(batch)

                tasks = []
                for student_id in batch:
                    tasks.append(
                        self.refresh_single(
                            student_id,
                            behavior_data.get(student_id, {}),
                            response_events.get(student_id, [])
                        )
                    )

                await asyncio.gather(*tasks, return_exceptions=True)

        await asyncio.gather(*[process_batch(b) for b in batches])
```

### 9.3 Redis Pipeline 优化

```python
class IncentiveRedisPipeline:
    """使用Redis Pipeline批量操作"""

    def batch_update_strategy_cache(self, updates: List[dict]):
        """
        批量更新学生策略缓存。
        使用Pipeline减少网络往返。
        """
        pipe = self.redis.pipeline()
        for update in updates:
            key = f"incentive:strategy:{update['student_id']}"

                "assigned_at": str(int(time.time())),
                "expires_at": str(int(time.time()) + 86400),
            })
            pipe.expire(key, 86400)
        pipe.execute()
```

## 11. 安全与合规

### 11.1 数据安全

- 学生画像数据属于个人敏感信息，传输使用 TLS 1.2+
- 画像数据存储在独立数据库实例，与业务数据隔离
- Redis 缓存不存储明文学生ID，使用 HMAC 签名后的ID作为Key
- 响应事件表按月分区，保留6个月后归档到冷存储

### 11.2 参数安全边界

```python
class ParamSafetyGuard:
    """参数安全守卫，防止异常参数导致成本失控"""

    ABSOLUTE_BOUNDS = {
        "daily_cap_points": (50, 500),       # 每日积分上限绝对边界
        "task_complete_base_points": (1, 50), # 单次任务基础积分
        "streak_bonus_multiplier": (1.0, 3.0),
    }

    DAILY_COST_BUDGET = 500_000  # 每日积分发放总预算

    def validate_param(self, param_key: str, value: float) -> bool:
        """验证参数是否在安全边界内"""
        if param_key in self.ABSOLUTE_BOUNDS:
            low, high = self.ABSOLUTE_BOUNDS[param_key]
            if not (low <= value <= high):
                logger.error(
                    f"参数安全违规: {param_key}={value}, 允许范围[{low},{high}]"
                )
                return False
        return True

    def check_daily_budget(self, current_spending: int) -> dict:
        """检查当日积分发放预算"""
        utilization = current_spending / self.DAILY_COST_BUDGET
        if utilization > 0.9:
            return {
                "action": "throttle",
                "reduce_factor": 0.5,  # 所有积分减半
                "notify": True,
            }
        elif utilization > 0.8:
            return {
                "action": "caution",
                "reduce_factor": 0.8,
                "notify": False,
            }
        return {"action": "normal", "reduce_factor": 1.0}
```

### 11.3 未成年人保护

- 策略匹配不使用任何涉及"消费"、"付费"的激励手段针对未成年人
- 疲劳度严重时优先保护学生（暂停激励而非加码）
- 可变奖励的"中奖"体验不模拟赌博机制（不使用老虎机式动画）
- 所有激励文案需通过内容安全过滤

### 14.2 术语表

| 术语 | 说明 |
| --- | --- |
| MAB | Multi-Armed Bandit，多臂老虎机，一种探索-利用平衡算法 |
| Thompson Sampling | 汤普森采样，MAB的经典算法之一 |
| Beta分布 | 概率分布，用于建模伯努利试验的成功率 |
| EWMA | 指数加权移动平均，对近期数据赋予更高权重 |
| 激励响应评分 | 学生收到奖励后24h内活跃行为变化的综合评分[0,1] |
| 激励疲劳 | 学生对奖励刺激逐渐脱敏，响应评分持续下降的现象 |
| 冷启动 | 新用户无历史数据时的策略初始化过程 |
| 可变奖励 | 奖励金额随机变化，而非固定值的奖励机制 |
| 目标梯度效应 | 越接近目标时动机越强的心理现象 |
| 损失厌恶 | 相比获得等量收益，人们对损失更为敏感的心理倾向 |
