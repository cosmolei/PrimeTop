# 服务端-学习内容隐喻式讲解生成与类比联想记忆辅助引擎-详细设计

## 1. 概述

### 1.1 功能定位

本引擎是 PrimeTop AI 辅导能力层的特色增强模块，负责在知识点讲解、题目解析、AI 对话等场景中，**自动生成适龄化、个性化、学科准确的隐喻（Metaphor）和类比（Analogy）**，帮助学生将抽象概念转化为具象理解。

教育研究表明，恰当的类比能显著降低认知负荷、提升知识内化效率、增强长期记忆。传统 AI 辅导在讲解抽象概念时往往依赖"教材式"的平铺直叙，缺乏生动的联想辅助，导致学生"看了解析但没真正理解"。

### 1.2 设计目标

| 目标 | 描述 |
| --- | --- |
| 自动生成 | 在 AI 辅导讲解中自动判断何时需要类比，并生成恰当的类比内容 |
| 适龄适配 | 隐喻的复杂度、参照物、语言风格须匹配学生学段和认知水平 |
| 个性匹配 | 优先使用学生感兴趣的领域（如游戏、运动、动漫）作为类比参照域 |
| 学科准确 | 类比不能出现科学性错误，须经受学科知识库校验 |
| 效果追踪 | 记录类比使用效果（学生反馈、后续答题正确率），持续优化类比库 |
| 低延迟 | 类比生成作为 AI 回复的增强层，不应显著增加响应延迟 |

### 1.3 适用范围

- **学段**：小学至高中全学段（幼儿阶段以图文为主，隐喻需求较低）
- **学科**：数学、物理、化学、生物、英语语法、信息技术等概念密集型学科为主；语文、历史等也可使用情境类比
- **触发场景**：AI 智能辅导对话、拍照搜题解析、同步课堂知识点讲解、错题复习讲解

### 1.4 与现有模块的关系

| 模块 | 关系 |
| --- | --- |
| AI 智能辅导对话 | 本引擎为对话回复提供类比增强，是后处理管线的增强环节 |
| AI 回答后处理与智能优化管线 | 本引擎的类比注入逻辑嵌入后处理管线 |
| RAG 检索增强生成 | 类比素材库作为 RAG 知识库的补充数据源 |
| Prompt 编排与场景模板系统 | 类比生成的 Prompt 模板纳入场景模板管理 |
| 学生学习风格识别 | 提供学生兴趣偏好数据，驱动类比参照域选择 |
| 教育内容知识切片与微课分段 | 微课内容可调用本引擎生成类比讲解段落 |

## 2. 核心概念与术语

### 2.1 关键术语

| 术语 | 定义 |
| --- | --- |
| **隐喻（Metaphor）** | 将概念 A 直接当作概念 B 来描述，如"细胞是微型工厂" |
| **类比（Analogy）** | 显式比较两个事物的相似结构关系，如"电流像水流，电压像水压" |
| **参照域（Source Domain）** | 类比中用作参照的、学生已熟悉的领域，如"水流通路""跷跷板" |
| **目标域（Target Domain）** | 需要解释的新概念领域，如"电路""力矩" |
| **映射（Mapping）** | 参照域与目标域之间的结构对应关系 |
| **类比断裂点（Breakdown Point）** | 类比不再成立的边界，需明确告知学生避免过度推演 |
| **类比库（Analogy Library）** | 结构化存储已验证的优质类比，按学科/知识点/学段索引 |
| **个性化参照域（Personalized Source Domain）** | 根据学生兴趣画像选择的参照域，如对游戏玩家用"升级打怪"类比 |

### 2.2 类比质量六维模型

```
 ┌──────────────────────────────────────────────────┐
 │              类比质量评估六维模型                  │
 ├──────────┬───────────────────────────────────────┤
 │ 结构相似性 │ 参照域与目标域的内在结构对应程度       │
 │ 认知适龄性 │ 参照域是否在该学段学生的经验范围内     │
 │ 表达简洁性 │ 类比描述是否简明扼要，不冗余           │
 │ 科学准确性 │ 类比是否存在误导性或科学性错误         │
 │ 记忆锚定力 │ 类比是否具有鲜明特征便于回忆           │
 │ 兴趣契合度 │ 参照域是否匹配学生个人兴趣偏好         │
 └──────────┴───────────────────────────────────────┘
```

### 3.2 核心子系统职责

| 子系统 | 职责 | 技术方案 |
| --- | --- | --- |
| 类比触发判定引擎 | 判断当前讲解是否需要类比增强 | 规则引擎 + 概念难度模型 |
| 类比素材检索引擎 | 从类比库中检索已有优质类比 | 向量检索（pgvector / Milvus） |

| 效果追踪与反馈 | 记录类比使用效果，持续优化 | 事件流 + 离线分析 |

## 4. 数据结构定义

### 4.1 类比素材库主表 `analogy_library`

```sql
CREATE TABLE analogy_library (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    analogy_code    VARCHAR(64) NOT NULL UNIQUE COMMENT '类比唯一编码',

    -- 目标域信息（被解释的概念）
    subject_code    VARCHAR(16) NOT NULL COMMENT '学科编码 MATH/PHYSICS/CHEM...',
    knowledge_point_id BIGINT NOT NULL COMMENT '关联知识点ID',
    concept_name    VARCHAR(128) NOT NULL COMMENT '目标概念名称',
    concept_summary TEXT COMMENT '概念简要描述',

    -- 参照域信息（用来做类比的事物）
    source_domain   VARCHAR(128) NOT NULL COMMENT '参照域名称',
    source_category VARCHAR(32) NOT NULL COMMENT '参照域类别 LIFE/GAME/SPORT/NATURE/TECH...',

    -- 类比内容
    analogy_title   VARCHAR(256) NOT NULL COMMENT '类比标题',
    analogy_content TEXT NOT NULL COMMENT '类比详细内容（Markdown）',
    mapping_points  JSON NOT NULL COMMENT '结构映射点列表',
    breakdown_point TEXT COMMENT '类比失效边界说明',

    -- 适用范围
    min_grade       SMALLINT NOT NULL COMMENT '最低适用年级',
    max_grade       SMALLINT NOT NULL COMMENT '最高适用年级',
    stage_tags      JSON COMMENT '学段标签 ["PRIMARY","JUNIOR","SENIOR"]',

    -- 质量评分
    avg_rating      DECIMAL(3,2) DEFAULT 0 COMMENT '平均评分 0-5',
    usage_count     INT DEFAULT 0 COMMENT '使用次数',
    positive_feedback_rate DECIMAL(3,2) DEFAULT 0 COMMENT '正面反馈率',
    effectiveness_score DECIMAL(3,2) DEFAULT 0 COMMENT '效果得分',

    -- 状态
    status          VARCHAR(16) DEFAULT 'DRAFT' COMMENT 'DRAFT/PUBLISHED/DEPRECATED',
    source_type     VARCHAR(16) DEFAULT 'AI_GENERATED' COMMENT 'AI_GENERATED/EXPERT_CURATED/STUDENT_CONTRIBUTED',

    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by      VARCHAR(64),

    INDEX idx_kp (knowledge_point_id),
    INDEX idx_subject_stage (subject_code, min_grade, max_grade),
    INDEX idx_source_category (source_category),
    INDEX idx_status_rating (status, avg_rating DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='类比素材库';
```

## 6. 核心算法与流程

### 6.1 类比触发判定流程

```text
输入：student_id, knowledge_point_id, concept_name, student_mastery, scene
  │
  ▼
┌─────────────────────────────────────┐
│ Step 1: 查询概念难度模型              │
│ 获取 abstraction_score,             │
│       counter_intuitive,            │
│       recommend_analogy             │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│ Step 2: 触发规则评估                  │
│                                     │
│ 规则A（强触发）：                     │
│   recommend_analogy=true             │
│   AND student_mastery < 0.4          │
│   → 触发，priority=HIGH              │
│                                     │
│ 规则B（常规触发）：                   │
│   abstraction_score >= 0.6           │
│   AND student_mastery < 0.6          │
│   → 触发，priority=NORMAL            │
│                                     │
│ 规则C（违反直觉触发）：               │
│   counter_intuitive=true             │
│   AND student_mastery < 0.5          │
│   → 触发，priority=HIGH              │
│                                     │
│ 规则D（学生主动请求）：               │
│   scene=AI_DIALOG                    │
│   AND 对话中出现"不懂""不明白"       │
│       "太抽象""换种方式"             │
│   → 触发，priority=HIGH              │
│                                     │
│ 规则E（冷却检查）：                   │
│   同一知识点最近 N 分钟内             │
│   未展示过类比                        │
│   → 否则跳过                         │
└──────────────┬──────────────────────┘
               │
               ▼
          输出：是否触发 + 优先级 + 触发原因
```

### 6.2 类比生成编排流程

```python
# 核心编排伪代码

async def generate_analogy(request: AnalogyRequest) -> AnalogyResponse:
    """
    类比生成主流程：先检索库，命中则直接返回；未命中则调用 LLM 生成。
    """
    # Step 1: 类比库检索
    library_hit = await search_analogy_library(
        knowledge_point_id=request.knowledge_point_id,
        student_grade=request.student_grade,
        subject_code=request.subject_code,
        top_k=3
    )

    if library_hit and not request.force_generate:
        # Step 2a: 库命中 - 个性化排序后返回最优
        ranked = await personalize_rank(
            analogies=library_hit,
            student_id=request.student_id
        )
        best = ranked[0]
        
        # 异步更新使用计数
        await update_usage_count_async(best.id)
        
        return AnalogyResponse(
            analogies=[best],
            generation_method="LIBRARY_HIT",
            latency_ms=elapsed
        )

    # Step 2b: 库未命中 - LLM 生成
    # 2b-1: 选择个性化参照域
    source_domain = await select_source_domain(
        student_id=request.student_id,
        subject_code=request.subject_code,
        concept_name=request.concept_name,
        exclude=request.exclude_domains
    )

    # 2b-2: 组装 Prompt
    prompt = build_analogy_prompt(
        concept_name=request.concept_name,
        concept_explanation=request.concept_explanation,
        student_grade=request.student_grade,
        source_domain=source_domain,
        textbook_version=request.textbook_version
    )

    # 2b-3: 调用 LLM（流式）
    raw_analogy = await llm_generate(
        prompt=prompt,
        model=select_model(request.student_grade),
        temperature=0.7,
        max_tokens=600,
        stream=request.options.stream
    )

    # Step 3: 质量校验
    quality_result = await validate_analogy(
        analogy=raw_analogy,
        concept_name=request.concept_name,
        subject_code=request.subject_code,
        knowledge_point_id=request.knowledge_point_id,
        student_grade=request.student_grade
    )

    if not quality_result.passed:
        # 校验失败 - 尝试一次重试
        raw_analogy = await llm_generate(prompt_with_feedback, ...)
        quality_result = await validate_analogy(...)

    # Step 4: 结构化解析
    analogy = parse_analogy_structure(raw_analogy)

    # Step 5: 记录使用日志
    usage_id = await log_usage(
        student_id=request.student_id,
        analogy=analogy,
        scene=request.scene
    )

    # Step 6: 异步入库候选（满足条件时）
    if quality_result.score >= 3.5:
        await save_to_library_candidate(analogy)

    return AnalogyResponse(
        analogies=[analogy],
        generation_method="LLM_GENERATED",
        latency_ms=elapsed
    )
```

### 6.3 个性化参照域选择算法

```python
def select_source_domain(
    student_id: int,
    subject_code: str,
    concept_name: str,
    exclude: list[str] = None
) -> str:
    """
    综合学生兴趣偏好、学科适配性和历史反馈选择最佳参照域。
    """
    exclude = exclude or []
    
    # 1. 获取学生偏好排序
    preferences = get_student_preferences(student_id)
    # 返回: [{"category": "GAME", "score": 0.85}, {"category": "SPORT", "score": 0.72}, ...]
    
    # 2. 获取该概念/学科的推荐参照域列表
    recommended = get_recommended_domains(subject_code, concept_name)
    # 返回: [{"domain": "水流通路", "category": "LIFE", "base_score": 0.9}, ...]
    
    # 3. 综合打分
    scored = []
    for rec in recommended:
        if rec["domain"] in exclude:
            continue
        
        pref_score = get_pref_score(preferences, rec["category"])
        # 学生未接触过的类别给默认分 0.3
        
        # 综合分 = 参照域基础分 * 0.5 + 学生偏好分 * 0.3 + 新颖性加分 * 0.2
        novelty_bonus = 0.1 if pref_score < 0.2 else 0.0  # 尝试新领域
        final_score = rec["base_score"] * 0.5 + pref_score * 0.3 + novelty_bonus * 0.2
        
        scored.append({
            "domain": rec["domain"],
            "category": rec["category"],
            "score": final_score
        })
    
    # 4. 按分数排序，加入随机性避免固定输出
    scored.sort(key=lambda x: x["score"], reverse=True)
    
    # Top 3 中按概率选择（softmax 温度）
    top_candidates = scored[:3]
    return weighted_random_select(top_candidates)
```

### 6.4 质量校验算法

```python
async def validate_analogy(
    analogy: dict,
    concept_name: str,
    subject_code: str,
    knowledge_point_id: int,
    student_grade: int
) -> QualityResult:
    """
    多层校验确保类比质量。
    """
    checks = []
    
    # Check 1: 结构完整性 - 必须有映射点和断裂点
    if not analogy.get("mapping_points") or len(analogy["mapping_points"]) < 2:
        checks.append(("STRUCTURE", False, "映射点不足"))
    else:
        checks.append(("STRUCTURE", True, f"{len(analogy['mapping_points'])}个映射点"))
    
    # Check 2: 长度控制 - 小学生类比不超过 200 字
    content_len = len(analogy.get("content", ""))
    max_len = 150 if student_grade <= 6 else (250 if student_grade <= 9 else 350)
    if content_len > max_len:
        checks.append(("LENGTH", False, f"超长: {content_len}>{max_len}"))
    else:
        checks.append(("LENGTH", True, f"{content_len}字"))
    
    # Check 3: 学科知识校验 - 调用学科知识图谱做事实检查
    fact_check = await verify_against_knowledge_base(
        analogy_content=analogy["content"],
        knowledge_point_id=knowledge_point_id,
        subject_code=subject_code
    )
    checks.append(("ACCURACY", fact_check.passed, fact_check.reason))
    
    # Check 4: 适龄性检查 - 参照域是否在学生经验范围内
    age_check = check_age_appropriateness(
        source_domain=analogy["source_domain"],
        student_grade=student_grade
    )
    checks.append(("AGE_APPROPRIATE", age_check.passed, age_check.reason))
    
    # Check 5: LLM 自评 - 让模型评估自己的类比质量
    self_eval = await llm_self_evaluate(analogy, concept_name)
    checks.append(("SELF_EVAL", self_eval.score >= 3, f"自评{self_eval.score}/5"))
    
    # 综合评分
    weights = {"STRUCTURE": 1.0, "LENGTH": 0.5, "ACCURACY": 1.5, 
               "AGE_APPROPRIATE": 1.0, "SELF_EVAL": 0.8}
    total_weight = sum(weights.values())
    score = sum(w * (1.0 if passed else 0.0) 
                for name, passed, _ in checks 
                for w in [weights.get(name, 0)])
    final_score = (score / total_weight) * 5.0
    
    all_critical_passed = all(
        passed for name, passed, _ in checks 
        if name in ("STRUCTURE", "ACCURACY", "AGE_APPROPRIATE")
    )
    
    return QualityResult(
        passed=all_critical_passed,
        score=round(final_score, 2),
        checks=checks
    )
```

## 9. 错误处理与降级策略

### 9.1 错误码定义

| 错误码 | 含义 | 处理策略 |
| --- | --- | --- |
| ANALOGY_001 | LLM 生成超时 | 降级为库检索或返回无比比讲解 |
| ANALOGY_002 | 质量校验连续失败 | 跳过类比增强，记录异常日志 |
| ANALOGY_003 | 向量检索服务不可用 | 降级为关键词检索 |
| ANALOGY_004 | 概念难度模型缺失 | 使用默认抽象度阈值 0.6 |
| ANALOGY_005 | 学生画像数据不足 | 使用全局默认偏好排序 |
| ANALOGY_006 | 参照域选择失败 | 使用学科默认参照域 |
| ANALOGY_007 | 类比库写入失败 | 忽略，不影响主流程 |

### 9.2 降级链路

```text
正常链路：库检索 → 个性化排序 → 返回
    ↓ (失败)
降级1：LLM生成 → 质量校验 → 返回
    ↓ (失败)
降级2：LLM生成（无个性化参照域）→ 质量校验 → 返回
    ↓ (失败)
降级3：返回无类比的纯文字讲解（完全跳过本引擎）
```

**核心原则：类比增强是锦上添花，绝不能阻断主学习流程。**

## 12. 性能优化

### 12.1 性能指标要求

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 库检索响应时间 | < 50ms (P99) | 向量检索 + 排序 |
| LLM 生成响应时间 | < 3s (P95) | 包含质量校验 |
| 端到端延迟（库命中） | < 100ms (P99) | 含网络开销 |
| 端到端延迟（LLM生成） | < 4s (P95) | 含质量校验 |
| 吞吐量 | 500 QPS | 高峰期并发 |

### 12.2 优化措施

1. **预生成**：对高频知识点（Top 500）的类比提前生成并入库
2. **批量向量检索**：多个类比候选一次性检索
3. **流式输出**：LLM 生成采用流式，让前端边接收边渲染
4. **异步入库**：候选类比入库、偏好更新等异步执行
5. **分级调用**：低年级优先使用库检索（库命中率高），高年级允许更多 LLM 实时生成

- 学生偏好数据仅用于类比优化，不对外暴露
- 使用日志中的学生 ID 须脱敏后才可用于分析
- 符合《未成年人保护法》和《个人信息保护法》要求
