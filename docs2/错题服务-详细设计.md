# 错题服务 - 详细设计

## 1. 概述

### 1.1 模块定位

错题服务（Mistake Service）是 PrimeTop 平台的核心业务服务之一，负责错题记录的全生命周期管理：从错题产生、结构化收录、错因标注、订正跟踪、复习调度到掌握归档。该服务向上为客户端错题本、学情分析、学习规划、家长报告等模块提供统一 API；向下对接答题记录服务、题目服务、AI 服务、复习调度引擎、掌握度服务与消息服务。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 错题收录 | 接收来自拍题、练习、考试、AI 辅导、手动录入等渠道的错题来源事件，生成标准化错题记录 |
| 错因管理 | 维护错因标签体系，支持系统自动标注、用户补充标注、AI 错因分析 |
| 订正跟踪 | 记录学生每次订正作答，判定订正是否通过，维护订正状态机 |
| 复习调度 | 与复习调度引擎协作，生成基于遗忘曲线的复习计划，并消费复习执行结果 |
| 掌握度评估 | 根据订正与复习表现，计算并更新错题掌握度，触发归档或顽固错题干预 |
| 错题查询 | 提供多维度错题检索、筛选、统计与报告生成能力 |

### 1.3 服务边界

```
┌─────────────────────────────────────────────────────────────────┐
│                         错题服务 (Mistake Service)                 │
│  ┌───────────┐ ┌───────────┐ ┌───────────┐ ┌───────────┐       │
│  │ 错题收录   │ │ 错因管理   │ │ 订正跟踪   │ │ 复习调度   │       │
│  └───────────┘ └───────────┘ └───────────┘ └───────────┘       │
│  ┌───────────┐ ┌───────────┐ ┌───────────┐                     │
│  │ 掌握度评估 │ │ 错题查询   │ │ 报告统计   │                     │
│  └───────────┘ └───────────┘ └───────────┘                     │
└─────────────────────────────────────────────────────────────────┘
          ↑↓                ↑↓                ↑↓
    答题记录服务      题目服务 / 知识点服务      AI 服务
    练习测评服务      复习调度引擎              掌握度服务
    拍照搜题服务      消息服务                  学情分析服务
```

### 1.4 依赖关系

- **上游依赖**：用户服务、答题记录服务、练习测评服务、拍照搜题服务、AI 辅导服务、考试模拟服务
- **下游依赖**：题目服务、知识点服务、错因分析引擎、复习调度引擎、掌握度服务、学情分析服务、消息服务、搜索服务

## 4. 业务逻辑与状态机

### 4.1 错题状态机

```
                    ┌─────────────┐
                    │   ACTIVE    │  ← 刚收录/未开始订正
                    └──────┬──────┘
                           │ 提交订正
                           ▼
                    ┌─────────────┐
                    │  CORRECTING │  ← 订正中
                    └──────┬──────┘
                           │ 订正通过
                           ▼
                    ┌─────────────┐
                    │  REVIEWING  │  ← 进入复习周期
                    └──────┬──────┘
         ┌───────────────┼───────────────┐
         │ 复习失败/     │ 复习通过      │ 手动归档
         │ 多次订正不过   │ 达到掌握阈值   │
         ▼               ▼               ▼
   ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
   │   ACTIVE    │ │  MASTERED   │ │  ARCHIVED   │
   │  (重新激活)  │ │  (已掌握)    │ │  (已归档)    │
   └─────────────┘ └─────────────┘ └─────────────┘
```

状态说明：

| 状态 | 说明 | 可转移 |
|------|------|--------|
| ACTIVE | 活跃状态，待订正或已重新激活 | CORRECTING, ARCHIVED |
| CORRECTING | 已产生订正记录，等待订正结果 | REVIEWING, ACTIVE |
| REVIEWING | 订正通过，进入复习周期 | MASTERED, ACTIVE, ARCHIVED |
| MASTERED | 已掌握，不再出现在待复习列表 | ARCHIVED |
| ARCHIVED | 已归档，可查询但不参与主动复习 | ACTIVE（可手动恢复） |

### 4.2 核心流程

#### 4.2.1 错题收录流程

```
1. 接收来源事件 / 调用内部接口
2. 幂等校验：根据 sourceType + sourceId + questionId 去重
3. 数据标准化：补齐学科、年级、知识点、题目快照
4. 重复题目检测：同一用户同一 questionId 是否已存在
   ├─ 存在：合并答案/更新元数据，返回已有记录
   └─ 不存在：创建新错题记录
5. 生成首次复习计划（可选，依赖配置）
6. 发送事件：MistakeCreated
7. 更新缓存与统计计数
```

#### 4.2.2 订正流程

```
1. 接收订正请求
2. 加载错题与题目信息
3. 调用评分服务（或本地判题）判定答案
4. 创建 correction_records
5. 更新 mistake_records 状态
   ├─ 正确：status → REVIEWING，生成复习计划
   └─ 错误：status → ACTIVE（保持），记录错误次数
6. 发送事件：CorrectionSubmitted
7. 触发掌握度/学情更新
```

#### 4.2.3 复习流程

```
1. 接收复习结果
2. 校验 schedule_id 与错题匹配
3. 更新 review_schedules 结果
4. 根据复习结果调整状态
   ├─ 通过：review_count++，若达到掌握阈值 → MASTERED → ARCHIVED
   └─ 失败：重置/缩短复习间隔，status → ACTIVE
5. 更新 next_review_at
6. 发送事件：ReviewCompleted
```

## 5. 代码示例

### 5.1 核心领域模型（Java）

```java
@Data
public class MistakeRecord {
    private String id;
    private String userId;
    private String studentProfileId;
    private MistakeSourceType sourceType;
    private String sourceId;
    private String answerRecordId;
    private String questionId;
    private QuestionContent questionContent;
    private String subjectCode;
    private String gradeCode;
    private String textbookId;
    private List<String> chapterIds;
    private List<String> knowledgePointIds;
    private AnswerContent userAnswer;
    private AnswerContent correctAnswer;
    private AnalysisContent analysis;
    private List<String> errorTags;
    private String errorReason;
    private MasteryLevel masteryLevel;
    private Integer difficulty;
    private MistakeStatus status;
    private Integer reviewCount;
    private LocalDateTime nextReviewAt;
    private LocalDateTime lastReviewedAt;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
    private LocalDateTime archivedAt;
    private Map<String, Object> metadata;

    public boolean canSubmitCorrection() {
        return status == MistakeStatus.ACTIVE || status == MistakeStatus.REVIEWING;
    }

    public void transitTo(MistakeStatus newStatus) {
        if (!this.status.canTransitionTo(newStatus)) {
            throw new IllegalStateException(
                "Invalid status transition: " + this.status + " -> " + newStatus);
        }
        this.status = newStatus;
        this.updatedAt = LocalDateTime.now();
        if (newStatus == MistakeStatus.ARCHIVED) {
            this.archivedAt = LocalDateTime.now();
        }
    }
}

public enum MistakeStatus {
    ACTIVE, CORRECTING, REVIEWING, MASTERED, ARCHIVED;

    public boolean canTransitionTo(MistakeStatus target) {
        return switch (this) {
            case ACTIVE -> target == CORRECTING || target == ARCHIVED;
            case CORRECTING -> target == REVIEWING || target == ACTIVE;
            case REVIEWING -> target == MASTERED || target == ACTIVE || target == ARCHIVED;
            case MASTERED -> target == ARCHIVED;
            case ARCHIVED -> target == ACTIVE;
        };
    }
}

public enum MasteryLevel {
    NONE, PARTIAL, MASTERED
}

public enum MistakeSourceType {
    PHOTO, PRACTICE, EXAM, AI_DIALOG, MANUAL
}
```

### 5.2 错题收录服务

```java
@Service
@RequiredArgsConstructor
public class MistakeCollectionService {

    private final MistakeRepository mistakeRepository;
    private final CorrectionRecordRepository correctionRepository;
    private final ReviewScheduleService reviewScheduleService;
    private final ApplicationEventPublisher eventPublisher;
    private final IdGenerator idGenerator;

    @Transactional
    public MistakeRecord createMistake(CreateMistakeCommand cmd) {
        // 幂等：同一来源同一题目只创建一次
        Optional<MistakeRecord> existing = mistakeRepository
            .findByUserIdAndSourceTypeAndSourceIdAndQuestionId(
                cmd.getUserId(), cmd.getSourceType(), cmd.getSourceId(), cmd.getQuestionId());

        if (existing.isPresent()) {
            return mergeMistake(existing.get(), cmd);
        }

        // 重复题目检测：同一用户同一 questionId
        if (cmd.getQuestionId() != null) {
            Optional<MistakeRecord> duplicate = mistakeRepository
                .findByUserIdAndQuestionIdAndStatusNot(
                    cmd.getUserId(), cmd.getQuestionId(), MistakeStatus.ARCHIVED);
            if (duplicate.isPresent()) {
                return mergeMistake(duplicate.get(), cmd);
            }
        }

        MistakeRecord record = MistakeRecord.builder()
            .id(idGenerator.next("ms"))
            .userId(cmd.getUserId())
            .studentProfileId(cmd.getStudentProfileId())
            .sourceType(cmd.getSourceType())
            .sourceId(cmd.getSourceId())
            .answerRecordId(cmd.getAnswerRecordId())
            .questionId(cmd.getQuestionId())
            .questionContent(cmd.getQuestionContent())
            .subjectCode(cmd.getSubjectCode())
            .gradeCode(cmd.getGradeCode())
            .textbookId(cmd.getTextbookId())
            .chapterIds(cmd.getChapterIds())
            .knowledgePointIds(cmd.getKnowledgePointIds())
            .userAnswer(cmd.getUserAnswer())
            .correctAnswer(cmd.getCorrectAnswer())
            .analysis(cmd.getAnalysis())
            .errorTags(cmd.getErrorTags())
            .difficulty(cmd.getDifficulty())
            .status(MistakeStatus.ACTIVE)
            .masteryLevel(MasteryLevel.NONE)
            .reviewCount(0)
            .metadata(cmd.getMetadata())
            .createdAt(LocalDateTime.now())
            .updatedAt(LocalDateTime.now())
            .build();

        mistakeRepository.save(record);

        eventPublisher.publishEvent(new MistakeCreatedEvent(record));
        return record;
    }

    private MistakeRecord mergeMistake(MistakeRecord existing, CreateMistakeCommand cmd) {
        // 保留第一次的错误答案，追加新的错误标签
        if (cmd.getErrorTags() != null) {
            List<String> merged = new ArrayList<>(existing.getErrorTags());
            for (String tag : cmd.getErrorTags()) {
                if (!merged.contains(tag)) merged.add(tag);
            }
            existing.setErrorTags(merged);
        }
        if (cmd.getUserAnswer() != null && existing.getUserAnswer() == null) {
            existing.setUserAnswer(cmd.getUserAnswer());
        }
        existing.setUpdatedAt(LocalDateTime.now());
        mistakeRepository.save(existing);
        return existing;
    }
}
```

### 5.3 订正服务

```java
@Service
@RequiredArgsConstructor
public class CorrectionService {

    private final MistakeRepository mistakeRepository;
    private final CorrectionRecordRepository correctionRepository;
    private final GradingService gradingService;
    private final ReviewScheduleService reviewScheduleService;
    private final IdGenerator idGenerator;

    @Transactional
    public CorrectionResult submitCorrection(String mistakeId, CorrectionCommand cmd) {
        MistakeRecord mistake = mistakeRepository.findById(mistakeId)
            .orElseThrow(() -> new MistakeNotFoundException(mistakeId));

        if (!mistake.canSubmitCorrection()) {
            throw new InvalidMistakeStatusException(
                "Cannot submit correction in status: " + mistake.getStatus());
        }

        int attemptNumber = correctionRepository.countByMistakeId(mistakeId) + 1;

        GradingResult gradingResult = gradingService.grade(
            mistake.getQuestionContent(),
            mistake.getCorrectAnswer(),
            cmd.getAnswerContent()
        );

        CorrectionRecord record = CorrectionRecord.builder()
            .id(idGenerator.next("cr"))
            .mistakeId(mistakeId)
            .userId(mistake.getUserId())
            .attemptNumber(attemptNumber)
            .answerContent(cmd.getAnswerContent())
            .isCorrect(gradingResult.isCorrect())
            .score(gradingResult.getScore())
            .feedback(gradingResult.getFeedback())
            .durationSeconds(cmd.getDurationSeconds())
            .submittedAt(LocalDateTime.now())
            .build();

        correctionRepository.save(record);

        if (gradingResult.isCorrect()) {
            mistake.transitTo(MistakeStatus.REVIEWING);
            reviewScheduleService.generateSchedule(mistake);
        } else {
            // 保持 ACTIVE，但记录失败次数
            mistake.setUpdatedAt(LocalDateTime.now());
        }

        mistakeRepository.save(mistake);

        return CorrectionResult.builder()
            .correctionId(record.getId())
            .attemptNumber(attemptNumber)
            .isCorrect(gradingResult.isCorrect())
            .score(gradingResult.getScore())
            .feedback(gradingResult.getFeedback())
            .mistakeStatus(mistake.getStatus())
            .nextReviewAt(mistake.getNextReviewAt())
            .build();
    }
}
```

```java
@Service
@RequiredArgsConstructor
public class ReviewCompletionService {

    private final MistakeRepository mistakeRepository;
    private final ReviewScheduleRepository reviewScheduleRepository;

    @Transactional
    public ReviewResult submitReview(String mistakeId, ReviewCommand cmd) {
        MistakeRecord mistake = mistakeRepository.findById(mistakeId)
            .orElseThrow(() -> new MistakeNotFoundException(mistakeId));

        ReviewSchedule schedule = reviewScheduleRepository
            .findById(cmd.getScheduleId())
            .orElseThrow(() -> new ReviewScheduleNotFoundException(cmd.getScheduleId()));

        schedule.setResult(cmd.getResult());
        schedule.setCompletedAt(LocalDateTime.now());
        reviewScheduleRepository.save(schedule);

        mistake.setReviewCount(mistake.getReviewCount() + 1);
        mistake.setLastReviewedAt(LocalDateTime.now());

        if (cmd.getResult() == ReviewResultType.PASSED) {
            List<ReviewSchedule> completed = reviewScheduleRepository
                .findByMistakeIdAndResult(mistakeId, ReviewResultType.PASSED);
            if (completed.size() >= 3) { // 掌握阈值可配置
                mistake.setMasteryLevel(MasteryLevel.MASTERED);
                mistake.transitTo(MistakeStatus.MASTERED);
                mistake.setNextReviewAt(null);
            } else {
                mistake.setMasteryLevel(MasteryLevel.PARTIAL);
                ReviewSchedule next = reviewScheduleService.planNext(mistake, completed.size() + 1);
                mistake.setNextReviewAt(next.getPlannedAt());
            }
        } else {
            // 复习失败，重新进入订正/复习循环
            mistake.transitTo(MistakeStatus.ACTIVE);
            mistake.setNextReviewAt(null);
        }

        mistakeRepository.save(mistake);

        return ReviewResult.builder()
            .mistakeStatus(mistake.getStatus())
            .masteryLevel(mistake.getMasteryLevel())
            .reviewCount(mistake.getReviewCount())
            .archived(mistake.getStatus() == MistakeStatus.MASTERED)
            .build();
    }
}
```

```java
@RestControllerAdvice
public class MistakeExceptionHandler {

    @ExceptionHandler(MistakeNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(MistakeNotFoundException e) {

            .body(ErrorResponse.of(40001, "MISTAKE_NOT_FOUND", e.getMessage()));

        return ResponseEntity.status(502)
```

### 6.3 重试策略

| 场景 | 策略 | 说明 |
|------|------|------|
| 评分服务超时 | 指数退避重试 3 次 | 失败后标记为 GRADING_FAILED，用户可手动刷新 |
| 复习计划生成失败 | 同步回滚 + 异步补偿 | 错题状态保持 ACTIVE，定时任务补偿 |
| 消息发送失败 | 异步重试 5 次 | 不影响主流程 |
| 缓存更新失败 | 删除缓存 | 下次查询回源数据库 |

## 7. 性能优化

### 7.1 查询优化

- 错题列表按用户 + 学科 + 状态建立复合索引，避免全表扫描。
- 高频查询（如首页今日待复习数量）使用 Redis 缓存，定时异步刷新。
- 错题详情使用 Hash 缓存，更新时删除缓存。
- 复杂统计查询（如高频错点）使用预计算表或 OLAP，避免实时聚合。

### 7.2 写入优化

- 错题收录、订正、复习等写操作采用数据库主键写入，避免复杂事务。
- 对外事件发送使用异步消息队列，降低接口延迟。
- 批量归档使用 `UPDATE ... WHERE id IN (...)`，避免逐条更新。

### 7.3 分页与限流

- 列表接口最大 pageSize 限制为 100，防止深分页。
- 内部来源事件接口进行限流：单个用户每分钟最多 60 次。
- 订正提交接口进行限流：单个错题每分钟最多 10 次。

## 8. 安全考虑

### 8.1 权限控制

- 所有错题 API 必须携带用户身份令牌，并校验 `userId` 与资源归属关系。
- 家长端查询孩子错题需通过家长绑定关系鉴权。
- 教师端查询班级错题需通过班级权限校验。
- 内部接口 `internal` 仅限服务间调用，通过 mTLS 或内部 Token 鉴权。

### 8.2 数据隔离

- 错题数据按用户 ID 物理隔离（分库分表时按 user_id 分片）。
- 学生档案变更不影响历史错题归属。

### 8.3 数据验证

- 学科、年级、教材版本等字段使用枚举校验，防止脏数据。
- 题目内容快照最大 64KB，防止超大 JSON 写入。
- 错因标签必须是系统预定义标签或用户自定义标签（长度限制 32 字符）。

### 8.4 审计日志

- 错题创建、删除、归档、状态变更等关键操作记录审计日志。
- 审计日志保留 180 天，包含操作人、时间、变更前后状态。

## 10. 部署与运维

### 10.1 服务拆分

MVP 阶段错题服务可作为单体服务中的模块存在；当每日错题写入超过 100 万条或查询 QPS 超过 5000 时，建议独立部署。

### 10.2 关键监控指标

| 指标 | 告警阈值 | 说明 |
|------|----------|------|
| 错题收录接口 P99 | > 500ms | 核心写入链路 |
| 订正提交接口 P99 | > 800ms | 依赖评分服务 |
| 今日待复习查询 P99 | > 200ms | 首页核心接口 |
| 错题服务错误率 | > 1% | 整体可用性 |
| 复习计划延迟 | > 5min | 计划生成任务 |

### 10.3 数据库分片策略

当单表数据量超过 5000 万行时，按 `user_id` 取模分 64 张表，通过分表路由组件统一访问。
