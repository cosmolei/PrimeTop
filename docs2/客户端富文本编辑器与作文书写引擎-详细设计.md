# 客户端富文本编辑器与作文书写引擎 - 详细设计

> 版本：v1.0 | 创建：2026-05-26 | 状态：初稿

## 1. 概述

### 1.1 设计目标

为启硕 PrimeTop 客户端提供统一的富文本编辑能力，主要服务于作文书写、长文本笔记、主观题作答等场景。编辑器需要：

- 跨平台一致体验（Flutter）
- 支持中文排版特性和学科专用输入
- 与 AI 辅导模块深度集成（实时批改建议、润色提示）
- 适配全学段不同的编辑复杂度需求
- 自动保存与断点恢复，防止内容丢失

### 1.2 适用场景

| 场景 | 入口 | 编辑复杂度 | 目标学段 |
|------|------|-----------|---------|
| 作文书写 | 作文辅导 → 开始写作 | 高（完整富文本） | 小学至高中 |
| 片段练习 | 作文辅导 → 片段训练 | 中（简式富文本） | 小学至高中 |
| 笔记编辑 | 错题本/收藏 → 添加笔记 | 低（纯文本+高亮） | 全学段 |
| 主观题作答 | 练习系统 → 简答/论述 | 中（学科公式支持） | 初中至高中 |
| AI 对话长文输入 | AI 辅导 → 展开输入 | 低（纯文本） | 全学段 |

### 1.3 与已有模块的关系

- **富文本与学科内容渲染引擎**：本模块负责「编辑」，渲染引擎负责「展示」，两者共享相同的 AST 数据模型和样式定义
- **数学公式与学科符号输入系统**：编辑器调用该模块的公式输入面板和符号键盘
- **作文辅导**：上层业务模块，调用本编辑器作为书写界面
- **客户端本地持久层**：编辑器的草稿数据通过持久层保存
- **AI对话引擎**：编辑器内嵌 AI 批改/润色建议气泡
- **客户端手势交互与动画系统**：编辑器内的选区操作、工具栏动画等

### 4.2 撤销/重做栈设计

```dart
class HistoryManager {
  final List<DocumentSnapshot> _undoStack = [];
  final List<DocumentSnapshot> _redoStack = [];
  static const int _maxHistorySize = 50;

  /// 记录当前状态（在每次有意义的编辑操作前调用）
  void pushSnapshot(DocumentSnapshot snapshot) {
    _undoStack.add(snapshot);
    _redoStack.clear(); // 新操作清空重做栈
    if (_undoStack.length > _maxHistorySize) {
      _undoStack.removeAt(0);
    }
  }

  DocumentSnapshot? undo() {
    if (_undoStack.isEmpty) return null;
    final current = _undoStack.removeLast();
    _redoStack.add(current);
    return current;
  }

  DocumentSnapshot? redo() {
    if (_redoStack.isEmpty) return null;
    final snapshot = _redoStack.removeLast();
    _undoStack.add(snapshot);
    return snapshot;
  }
}

/// 文档快照：轻量化存储，仅保存变化的增量
class DocumentSnapshot {
  final String id;
  final DateTime timestamp;
  final Map<String, dynamic> documentState;  // 序列化的文档 AST
  final SelectionState selection;             // 光标/选区位置
}
```

```dart
/// 编辑器选区
class EditorSelection {
  /// 选区起始位置（文档内全局偏移）
  final int startOffset;
  
  /// 选区结束位置
  final int endOffset;
  
  /// 选区是否折叠（光标模式）
  bool get isCollapsed => startOffset == endOffset;
  
  /// 选中文本长度
  int get length => endOffset - startOffset;

  /// 选中的节点路径（用于格式操作定位）
  List<NodePath> get selectedPaths;

/// 节点路径：从根到目标节点的路径
class NodePath {
  final List<int> indices;  // 例如 [0, 2, 1] 表示 document.children[0].children[2].children[1]
}
```

## 8. 草稿自动保存与恢复

### 8.1 保存策略

```dart
class DraftAutoSaveService {
  final LocalStorageProvider _storage;
  Timer? _debounceTimer;
  
  static const Duration _debounceDelay = Duration(seconds: 3);
  static const Duration _forceSaveInterval = Duration(seconds: 30);
  DateTime? _lastSaveTime;

  /// 文档内容变化时调用
  void onContentChanged(DocumentModel document) {
    _debounceTimer?.cancel();
    _debounceTimer = Timer(_debounceDelay, () => _saveDraft(document));
    
    // 强制保存：每 30 秒至少保存一次
    final now = DateTime.now();
    if (_lastSaveTime == null || 
        now.difference(_lastSaveTime!) > _forceSaveInterval) {
      _saveDraft(document);
    }
  }

  Future<void> _saveDraft(DocumentModel document) async {
    final draft = DraftData(
      id: document.id,
      content: document.toJson(),
      plainText: document.plainText,
      wordCount: document.wordCount,
      savedAt: DateTime.now(),
      appVersion: await PackageInfo.version,
    );
    await _storage.saveDraft(draft);
    _lastSaveTime = DateTime.now();
  }
}
```

```
    └── 有草稿 & 有服务端版本 → 对比时间戳
         │
         ├── 草稿更新 → 提示"发现未保存的草稿，是否恢复？"

```

## 9. 中文输入法适配

### 9.1 合成事件处理

Flutter 的 `TextEditingController` 对中文输入法的处理需要额外关注合成（composing）阶段：

```dart
class CJKInputHandler {
  final EditorController _controller;
  
  /// 处理输入法合成文本
  /// composing 区域是输入法尚未确认的拼音/笔画文本
  void handleComposingText(String composingText, 
                           int composingStart, 
                           int composingEnd) {
    // 不在合成阶段插入节点，仅在 composing 区域显示预览
    _controller.setComposingRegion(composingStart, composingEnd);
  }

  /// 输入法确认文本
  void handleCommittedText(String committedText) {
    _controller.insertText(committedText);
    _controller.clearComposingRegion();
  }

  /// 处理输入法候选词选择
  void handleCandidateSelected(String text) {
    _controller.insertText(text);
  }
}
```

### 9.2 特殊处理项

| 问题 | 解决方案 |
|------|---------|
| 拼音输入法合成中光标跳动 | 锁定光标位置直到 committed |
| 中文标点自动转换 | 监听输入，在句号/逗号等位置自动转换为中文标点 |
| 首行缩进空格 | 新段落自动插入两个全角空格（可配置） |
| 段首空格不参与选区 | 将缩进空格标记为不可选择 |
| 长文本输入卡顿 | 使用虚拟化渲染，仅渲染可视区域的段落 |

## 14. 错误处理

### 14.1 编辑器错误码

| 错误码 | 含义 | 处理策略 |
|--------|------|----------|
| `EDITOR_DRAFT_LOAD_FAILED` | 草稿加载失败 | 回退到空白文档，上报日志 |
| `EDITOR_DRAFT_SAVE_FAILED` | 草稿保存失败 | 重试 3 次，失败后 Toast 提示用户 |
| `EDITOR_IMAGE_INSERT_FAILED` | 图片插入失败 | Toast 提示，不阻塞编辑 |
| `EDITOR_FORMULA_PARSE_ERROR` | 公式解析失败 | 显示原始 LaTeX 文本，标注错误 |
| `EDITOR_AI_REVIEW_TIMEOUT` | AI 批改超时 | 不影响编辑，静默重试一次 |
| `EDITOR_AI_REVIEW_ERROR` | AI 批改服务异常 | 隐藏 AI 批注功能，仅用本地检查 |
| `EDITOR_NODE_CORRUPTED` | 文档节点数据损坏 | 尝试从上一个快照恢复 |
| `EDITOR_MEMORY_PRESSURE` | 内存压力 | 清理撤销栈，触发 GC |

### 14.2 容灾策略

```
编辑器异常退出（crash / OOM / 被系统杀死）
    │
    ▼
下次启动时检查
    │
    ├── drafts 表中是否有 sync_status='pending' 的草稿？
    │   └── 是 → 弹出恢复对话框
    │
    ├── 是否有 crash 日志记录？
    │   └── 是 → 检查最后自动保存时间，尝试恢复
    │
    └── 恢复成功 → 标记原草稿为 'recovered'
        恢复失败 → 显示道歉信息，提供空白文档
```

## 16. 与渲染引擎的数据共享

### 16.1 共享 AST 模型

编辑器产出的文档 AST 与「富文本与学科内容渲染引擎」共享同一套节点定义。编辑完成后，文档 JSON 直接传递给渲染引擎进行预览和展示，无需格式转换。

```dart
/// 共享包：editor_renderer_shared
class SharedDocumentAST {
  /// 版本号，用于前后向兼容
  static const int schemaVersion = 1;
  
  /// 验证文档结构完整性
  static bool validate(Map<String, dynamic> docJson) { ... }
  
  /// 迁移旧版本文档
  static Map<String, dynamic> migrate(Map<String, dynamic> docJson, int fromVersion) { ... }
}
```

### 16.2 版本兼容策略

- 文档 JSON 包含 `schemaVersion` 字段
- 编辑器和渲染引擎均支持当前版本和前一个版本
- 打开旧版本文档时自动迁移，迁移后以新版本保存
- 不兼容的版本降级为纯文本展示
