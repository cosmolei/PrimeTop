## 1. 文档概述

### 1.1 文档目的

详细设计 PrimeTop 客户端"应用内评分引导"（In-App Rating Prompt）功能的完整实现方案，包括触发策略、平台原生评分能力桥接、频控与冷却、服务端配置下发、合规约束与数据度量，使开发人员可直接据此完成 Android / iOS 双端的评分引导模块编码。

### 1.2 功能范围

| 功能 | 说明 |
|------|------|
| 资格判定 | 基于安装时长、活跃会话、正向事件、冷却期等规则判定用户是否满足弹出条件 |
| 系统评分弹窗 | iOS 调起 StoreKit 应用内评分；Google Play 渠道调起 In-App Review |
| 商店页降级 | 不支持系统弹窗的环境（国内安卓商店、Web、小程序）降级为跳转商店详情页或静默关闭 |
| 频控冷却 | 单用户冷却期、全局年上限、按版本重置等频控策略 |
| 远程配置 | 评分引导开关、文案、触发点、冷却参数全部服务端可配置，支持灰度 |
| 展示埋点 | 曝光/点击/跳转/关闭全事件埋点，支撑漏斗分析 |
| 负反馈保护 | 用户关闭/连续忽略后自动延长冷却，避免打扰 |

### 1.3 不在本模块范围内

- 应用商店 ASO 优化、买量投放归因（见 服务端-效果投放点击归因与买量ROI分析引擎）
- 应用内更新弹窗（见 客户端版本管理与升级策略）
- 用户调研问卷 / NPS 度量（见 用户调研问卷与NPS满意度度量平台）——评分引导与 NPS 弹窗互斥，共用互斥仲裁（§9.3）
- 激励视频、任何与评分挂钩的奖励发放（**合规红线，禁止**）

### 1.4 依赖关系

| 依赖文档 | 关联点 |
|---------|--------|
| 配置中心与动态配置管理 | 评分引导远程配置（开关/参数/文案/灰度）下发与热更新 |

| 客户端版本管理与升级策略 | 商店详情页跳转 URL 随版本与渠道变化 |
| 客户端-多渠道打包与国内应用商店上架交付体系 | 渠道识别（store_channel 决定降级路径） |
| 客户端应用启动流程与初始化管线 | 安装时间、首次启动时间等基础事实获取 |

| 灰度发布与特性开关系统 | 评分引导特性的灰度放量与紧急关停 |

### 1.5 设计原则

1. **绝不打扰学习过程**：学习会话中、答题中、考试模拟中一律不弹；只在自然停顿点（会话结束、报告查看完成）评估资格。
2. **未成年人保护**：未成年人账号（<18 岁，依实名/家长设置判定）默认不展示评分引导，配置可显式开启但需运营审批。
3. **合规中性**：文案不得诱导好评、不得承诺奖励、不得"差评留在反馈、好评去商店"式分流（违反 Apple Guideline 5.6.1 与 Google Play 评价政策）。
4. **服务端权威**：是否弹出、何时弹出、冷却参数全部服务端可配，客户端只做执行与缓存，支持秒级关停。
5. **优雅降级**：任何一步失败（无网络、原生 API 不可用、商店未安装）都必须静默收敛，绝不出现卡死弹窗或崩溃。

## 2. 功能需求与场景定义

### 2.1 用户故事

- US-1：作为平台运营，我希望在用户体验正向时刻（如完成一周学习计划）后引导其到应用商店评分，以提升商店评分与口碑。
- US-2：作为学生用户，我不希望在上课、做题、考试模拟时被弹窗打断；如果弹出，我可以一键关闭且短期内不再看到。
- US-3：作为家长/合规方，我不希望未成年人被引导至公开商店环境进行评分操作。
- US-4：作为开发，我需要一个统一的资格判定 + 原生桥接模块，双端行为一致、失败静默。

### 2.2 触发点定义

| 触发点编码 | 时机 | 默认启用 | 说明 |
|-----------|------|---------|------|
| `SESSION_END` | 学习会话自然结束（退出学习页回到首页） | ✅ | 主触发点，最不打扰 |
| `REPORT_VIEWED` | 学完情周报/学习报告后停留 ≥5 秒 | ✅ | 正向情绪点 |
| `PLAN_COMPLETED` | 完成一个周期（周/月）学习计划 | ✅ | 成就时刻，延迟到下一次会话首页展示 |
| `ACHIEVEMENT_UNLOCKED` | 解锁重大成就（稀有度 epic/legendary） | ❌ | 默认关闭，避免与学习激励弹窗冲突 |
| `APP_START` | 冷启动完成且首页加载后 | ❌ | 仅兜底，默认关闭 |

**通用约束**：触发点只负责"产生评估机会"，真正是否弹窗由资格引擎（§5）统一裁决；同一 App 生命周期内每次冷启动评估机会 ≤3 次。

### 2.3 不打扰规则（硬规则，客户端本地强制）

以下任一条件成立时，**直接短路，不评估、不上报**：

1. 当前处于学习会话中（`LearningSession.status == active`）。
2. 当前处于答题/测评/考试模拟页（路由命中 `/quiz/*`、`/exam/*`、`/homework/doing`）。
3. 当前正在播放音视频（播放器状态 playing）。
4. 当前存在更高优先级模态（来电、家长验证弹窗、支付弹窗）。
5. 青少年/幼儿模式运行中（`appMode == child`）。
6. 距上次任何模态弹窗 <60 秒（防连弹）。
7. 前台时长本次会话 <30 秒（避免刚启动就弹）。
8. 设备为未成年账号且配置未显式允许（见 §2.4）。

### 2.4 未成年人策略

| 账号类型 | 判定依据 | 默认行为 |
|---------|---------|---------|
| 实名 <18 岁学生账号 | 实名认证结果 / 家长登记生日 | 不展示评分引导 |
| 未实名但学段为小学及以下 | StudentProfile.phase ∈ {preschool, primary} | 不展示评分引导 |
| 家长账号（家长端视角操作） | 当前活跃角色为 parent | 允许（但家长端本身非独立 App 时不触发） |
| 教师/成年账号 | role == teacher / adult 实名 | 允许 |

服务端配置项 `allow_minor` 默认 `false`，置 `true` 需走运营审批流并留审计日志（未成年人向商店引导属敏感操作）。

## 3. 数据结构定义

### 3.1 服务端配置表

```sql
-- 评分引导配置表（运营在管理后台维护，配置中心下发）
CREATE TABLE rating_prompt_config (
    id              BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    config_code     VARCHAR(64)  NOT NULL COMMENT '配置编码，如 rating_prompt.default',
    platform        VARCHAR(16)  NOT NULL DEFAULT 'all' COMMENT 'all/android/ios',
    channel         VARCHAR(32)  NOT NULL DEFAULT 'all' COMMENT 'all/google_play/app_store/huawei/xiaomi/...',
    app_min_version VARCHAR(16)  NOT NULL DEFAULT '0.0.0' COMMENT '生效最低版本',
    app_max_version VARCHAR(16)  NULL COMMENT '生效最高版本（空=不限）',

    -- 开关与灰度
    enabled         TINYINT      NOT NULL DEFAULT 1,
    gray_percent    INT          NOT NULL DEFAULT 100 COMMENT '灰度百分比 0-100',

    -- 资格参数（详见 §5.2）
    min_install_days        INT NOT NULL DEFAULT 7    COMMENT '安装天数下限',
    min_sessions            INT NOT NULL DEFAULT 5    COMMENT '累计会话数下限',
    min_positive_events     INT NOT NULL DEFAULT 3    COMMENT '正向事件累计下限',
    prompt_interval_days    INT NOT NULL DEFAULT 90   COMMENT '两次弹窗冷却天数',
    max_prompts_per_year    INT NOT NULL DEFAULT 3    COMMENT '自然年内最多弹出次数',
    dismiss_cooldown_days   INT NOT NULL DEFAULT 30   COMMENT '用户点"暂不评分"后的冷却天数',
    force_close_cooldown_days INT NOT NULL DEFAULT 90 COMMENT '用户关闭/忽略后的冷却天数',
    suppress_after_consecutive_dismiss INT NOT NULL DEFAULT 3 COMMENT '连续忽略N次后转长期抑制(180天)',

    -- 未成年与文案
    allow_minor     TINYINT      NOT NULL DEFAULT 0,
    title           VARCHAR(128) NOT NULL DEFAULT '喜欢 PrimeTop 吗？',
    body            VARCHAR(256) NOT NULL DEFAULT '您的评分能帮助我们做得更好',
    button_rate     VARCHAR(32)  NOT NULL DEFAULT '去评分',
    button_later    VARCHAR(32)  NOT NULL DEFAULT '暂不评分',

    -- 治理
    updated_by      VARCHAR(64)  NOT NULL,
    updated_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_config_scope (config_code, platform, channel)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='评分引导配置';
```

### 3.2 服务端用户状态表

```sql
-- 单用户评分引导状态（SSOT，服务端权威）
CREATE TABLE user_rating_state (
    user_id                 BIGINT UNSIGNED NOT NULL,
    prompt_count_year       INT          NOT NULL DEFAULT 0 COMMENT '自然年内弹出次数',
    year_bucket             SMALLINT     NOT NULL COMMENT '计数所属自然年，如 2026',
    consecutive_dismiss     INT          NOT NULL DEFAULT 0 COMMENT '连续忽略/关闭次数',
    last_prompt_at          DATETIME     NULL COMMENT '上次弹出时间',
    last_dismiss_at         DATETIME     NULL COMMENT '上次忽略/关闭时间',
    next_eligible_at        DATETIME     NULL COMMENT '下次可评估时间（冷却截止时间）',
    ever_clicked_rate       TINYINT      NOT NULL DEFAULT 0 COMMENT '曾点击"去评分"（不表示已提交评分，商店不回传）',
    long_suppressed_until   DATETIME     NULL COMMENT '长期抑制截止时间',
    created_at              DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at              DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id),
    KEY idx_next_eligible (next_eligible_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户评分引导状态';

-- 弹出记录流水（审计 + 漏斗分析源）
CREATE TABLE rating_prompt_log (
    id             BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    user_id        BIGINT UNSIGNED NOT NULL,
    prompt_id      VARCHAR(40)  NOT NULL COMMENT '本次弹出唯一ID（雪花）',
    trigger_point  VARCHAR(32)  NOT NULL COMMENT '触发点编码',
    config_code    VARCHAR(64)  NOT NULL,
    prompt_type    VARCHAR(16)  NOT NULL COMMENT 'system_review/store_page/none',
    action         VARCHAR(16)  NOT NULL COMMENT 'shown/clicked_rate/clicked_later/closed/degraded_fail',
    client_version VARCHAR(16)  NOT NULL,
    channel        VARCHAR(32)  NOT NULL,
    created_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_prompt_action (prompt_id, action),
    KEY idx_user_created (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='评分引导弹出流水';
```

**设计要点**

- `user_rating_state` 行惰性创建：首次需要判定资格时 upsert 创建，避免为全量用户预建。
- `year_bucket` 换年重置：`prompt_count_year` 仅在 `year_bucket == 当前年` 时有效，跨年读取时按 0 计并在下次写入时重置（读时派生，避免定时任务）。
- 服务端**不感知**用户是否真正提交了评分：Apple/Google 均不回传评分行为，`ever_clicked_rate` 仅表示点击了"去评分"按钮（见 §7.4 设计裁决）。

### 3.3 Redis 缓存设计

```
-- 资格判定热数据（读多写少，TTL 兜底防穿透）
rating:state:{userId}            HASH  TTL=24h
  fields: next_eligible_at, prompt_count_year, year_bucket,
          consecutive_dismiss, long_suppressed_until, last_prompt_at
-- 配置缓存（配置变更主动失效）
rating:config:{platform}:{channel}  STRING(JSON)  TTL=1h
-- 全局应急关停闸（配置中心同步，独立于业务表）
feature:rating_prompt:kill_switch   STRING(0/1)
```

> 缓存为读加速副本，**写操作一律落 MySQL 后删缓存**；缓存 miss 回源 DB。与《多级缓存架构与一致性策略》的 Cache-Aside 规范一致。

## 5. 触发策略引擎详细设计

### 5.1 资格判定顺序（固定流水线，任何一步失败即终止）

```
Step 1  kill_switch 检查（本地缓存的配置中心闸）
Step 2  配置存在性 + enabled + 灰度命中（userId % 100 < grayPercent，使用稳定哈希）
Step 3  平台/渠道/版本匹配（platform、channel、app_min/max_version）
Step 4  未成年人策略（§2.4）
Step 5  安装时长 ≥ min_install_days
Step 6  累计会话数 ≥ min_sessions
Step 7  正向事件数 ≥ min_positive_events
Step 8  年度次数 prompt_count_year < max_prompts_per_year（跨年自动归零）
Step 9  时间冷却：now ≥ next_eligible_at
Step 10 长期抑制：long_suppressed_until 为空或 now ≥ 该时间
```

### 5.2 配置参数语义表

| 参数 | 默认 | 调参指引 |
|------|------|---------|
| `min_install_days` | 7 | 新用户先体验完整学习闭环，太早弹易引起反感 |
| `min_sessions` | 5 | 与次日/7日留存节奏匹配，避免注册即弹 |
| `min_positive_events` | 3 | 正向事件定义：完成学习计划、查看学情报告、连续打卡 ≥3 天等（事件清单服务端可配） |
| `prompt_interval_days` | 90 | 与 Apple 系统级年 3 次限制取更严格者；调整后不得突破 120 天/年系统约束 |
| `max_prompts_per_year` | 3 | **不得上调**：Apple StoreKit 一年内最多请求 3 次评分 |
| `dismiss_cooldown_days` | 30 | "暂不评分"的温和冷却 |
| `force_close_cooldown_days` | 90 | 明确关闭（非按钮路径）视为强负反馈 |
| `suppress_after_consecutive_dismiss` | 3 | 连续 3 次关闭进入 180 天长期抑制 |

### 5.3 客户端资格引擎代码（Dart）

```dart
/// lib/features/rating/domain/rating_eligibility_engine.dart

enum EligibilityVerdict {
  eligible,
  blockedByKillSwitch,
  blockedByDisabled,
  blockedByGray,
  blockedByMinorPolicy,
  blockedByInstallAge,
  blockedBySessionCount,
  blockedByPositiveEvents,
  blockedByYearCap,
  blockedByCooldown,
  blockedByLongSuppress,
}

class EligibilityInput {
  final RatingConfig config;
  final RatingUserState? serverState;      // 服务端权威状态（缓存）
  final LocalRatingSnapshot localState;    // 本地兜底
  final DateTime installedAt;
  final int totalSessions;
  final int positiveEventCount;
  final bool isMinor;
  final String userId;
  final DateTime now;
  const EligibilityInput({/* ... */});
}

class RatingEligibilityEngine {
  /// 稳定灰度：同一 userId 恒定落在同一分桶，避免灰度期间抖动
  bool _hitGray(String userId, int grayPercent) {
    final h = xxhash64(utf8.encode('rating:$userId')) % 100;
    return h < grayPercent;
  }

  EligibilityVerdict evaluate(EligibilityInput in) {
    if (in.config.enabled == false) return EligibilityVerdict.blockedByDisabled;
    if (!_hitGray(in.userId, in.config.grayPercent)) {
      return EligibilityVerdict.blockedByGray;
    }
    if (in.isMinor && !in.config.allowMinor) {
      return EligibilityVerdict.blockedByMinorPolicy;
    }
    if (in.now.difference(in.installedAt).inDays < in.config.minInstallDays) {
      return EligibilityVerdict.blockedByInstallAge;
    }
    if (in.totalSessions < in.config.minSessions) {
      return EligibilityVerdict.blockedBySessionCount;
    }
    if (in.positiveEventCount < in.config.minPositiveEvents) {
      return EligibilityVerdict.blockedByPositiveEvents;
    }

    // 服务端状态优先；不可达时用本地快照按最保守策略裁决
    final st = in.serverState ?? in.localState.toUserState();
    final curYear = in.now.year;
    final yearCount = (st.yearBucket == curYear) ? st.promptCountYear : 0;
    if (yearCount >= in.config.maxPromptsPerYear) {
      return EligibilityVerdict.blockedByYearCap;
    }
    final nextAt = st.nextEligibleAt;
    if (nextAt != null && in.now.isBefore(nextAt)) {
      return EligibilityVerdict.blockedByCooldown;
    }
    final suppressed = st.longSuppressedUntil;
    if (suppressed != null && in.now.isBefore(suppressed)) {
      return EligibilityVerdict.blockedByLongSuppress;
    }
    return EligibilityVerdict.eligible;
  }
}
```

### 5.4 触发点观察器（以 SESSION_END 为例）

```dart
/// lib/features/rating/presentation/trigger_observers.dart

class SessionEndObserver {
  StreamSubscription? _sub;

  void start() {
    // 监听学习会话状态流：active -> finished 的边沿触发一次评估机会
    _sub = ref.watch(learningSessionProvider.notifier).stream
        .distinct()
        .where((s) => s.status == SessionStatus.finished)
        .listen((_) => _onTrigger('SESSION_END'));
  }

  Future<void> _onTrigger(String triggerPoint) async {
    // 硬规则短路（§2.3）在前，成本最低
    if (await HardRules.shouldShortCircuit(ref)) return;
    final verdict = await ref.read(ratingEligibilityProvider.future);
    if (verdict != EligibilityVerdict.eligible) return;

    final granted = await ref.read(modalSchedulerProvider).requestSlot(
          priority: ModalPriority.low,          // 评分弹窗永远低优先级
          owner: ModalOwner.ratingPrompt,
        );
    if (!granted) return;

    unawaited(ref.read(ratingControllerProvider).prompt(triggerPoint));
  }
}
```

### 6.1 MethodChannel 契约

```text
通道名:   com.primetop.app/store_rating
方法集:

  入参: {}
  返回: { "result": "system_review_shown" | "degraded_to_store_page" | "unavailable" }

        降级结果如实返回, Flutter 层据 result 记埋点。

  入参: {}
  返回: { "result": "opened" | "no_store_app" | "failed" }
  语义: 直接跳转应用商店详情页（无系统评分能力渠道的主路径）。
```

### 6.2 Android 实现（Kotlin，Google Play 渠道）

```kotlin
// android/app/src/main/kotlin/com/primetop/app/StoreRatingPlugin.kt

class StoreRatingPlugin : MethodChannel.MethodCallHandler {
    private lateinit var reviewManager: ReviewManager
    private lateinit var activity: Activity

    override fun onMethodCall(call: MethodCall, result: MethodChannel.Result) {
        when (call.method) {
            "requestStoreReview" -> handleRequestReview(result)
            "openStoreListing" -> openStoreListing(result)
            else -> result.notImplemented()
        }
    }

    private fun handleRequestReview(result: MethodChannel.Result) {
        // 仅 Google Play 渠道包内启用 Play In-App Review；
        // 国内商店渠道 BuildConfig.STORE_CHANNEL != "google_play" 时直接降级
        if (BuildConfig.STORE_CHANNEL != "google_play") {
            return openStoreListing(result)   // 降级路径统一返回 opened
        }
        val request = reviewManager.requestReviewFlow()
        request.addOnCompleteListener { task ->
            if (task.isSuccessful) {
                val reviewInfo = task.result
                reviewManager.launchReviewFlow(activity, reviewInfo)
                    .addOnCompleteListener {
                        // Google Play 不回传用户是否评分，仅表示流程结束
                        result.success(mapOf("result" to "system_review_shown"))
                    }
            } else {
                // 配额耗尽 / 设备不支持 / 版本过低 → 降级商店页
                openStoreListing(result)
            }
        }
    }

    private fun openStoreListing(result: MethodChannel.Result) {
        val uri = Uri.parse(
            "market://details?id=${activity.packageName}"
        )
        val intent = Intent(Intent.ACTION_VIEW, uri).apply {
            addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
        }
        runCatching {
            activity.startActivity(intent)
            result.success(mapOf("result" to "opened"))
        }.onFailure {
            // 无商店 App（模拟器/海外无 GMS）→ 尝试 https 兜底
            val webIntent = Intent(Intent.ACTION_VIEW,
                Uri.parse("https://play.google.com/store/apps/details?id=${activity.packageName}"))
            runCatching {
                activity.startActivity(webIntent)
                result.success(mapOf("result" to "opened"))
            }.onFailure {
                result.success(mapOf("result" to "no_store_app"))
            }
        }
    }
}
```

```swift
@available(iOS 14.0, *)
func handleRequestReview(result: @escaping FlutterResult) {

func openStoreListing(result: @escaping FlutterResult) {
    let appId = Bundle.main.object(forInfoDictionaryKey: "APP_STORE_ID") as? String ?? ""
    let urlString = "https://apps.apple.com/cn/app/id\(appId)?action=write-review"
    guard let url = URL(string: urlString),
          UIApplication.shared.canOpenURL(url) else {
        result(["result": "no_store_app"])
        return
    }
    UIApplication.shared.open(url) { ok in
        result(["result": ok ? "opened" : "failed"])
    }
}
```

### 6.4 渠道能力矩阵与降级路径

| 渠道 | 系统评分能力 | 主路径 | 降级路径 |
|------|------------|--------|---------|
| Google Play | ✅ In-App Review | `requestStoreReview` | `market://` → https 兜底 |
| App Store | ✅ StoreKit requestReview | `requestStoreReview` | App Store 详情页（带 `?action=write-review`） |

**业务规则**

- 未登录设备返回 `eligible=false, verdict=blockedByDisabled`（本功能仅对登录用户开放，埋点可用设备维度兜底统计）。

### 7.2 弹出与行为上报

```
POST /api/v1/app/rating/prompts
Authorization: Bearer {access_token}
Idempotency-Key: {promptId}
```

**请求体（shown 事件，弹窗展示时上报）：**

```json
{
  "prompt_id": "rp_7263548290174638",
  "trigger_point": "SESSION_END",
  "config_code": "rating_prompt.default",
  "config_version": 17,
  "prompt_type": "system_review",
  "action": "shown",
  "client_version": "2.3.1",
  "channel": "google_play",
  "client_request_id": "crid_9f27ab01"
}
```

**action 枚举与语义：**

| action | 触发时机 | 服务端副作用 |
|--------|---------|-------------|
| `shown` | 弹窗渲染完成 | `prompt_count_year+1`、`last_prompt_at=now`、`consecutive_dismiss` 不变；写 `rating_prompt_log` |
| `clicked_rate` | 用户点"去评分" | `ever_clicked_rate=1`；冷却置 `dismiss_cooldown_days`；`consecutive_dismiss=0`；写流水 |
| `clicked_later` | 用户点"暂不评分" | 冷却置 `dismiss_cooldown_days`；`consecutive_dismiss=0`；写流水 |
| `closed` | 弹窗被 X/返回键关闭（无明确选择） | 冷却置 `force_close_cooldown_days`；`consecutive_dismiss+1`，达到阈值置 `long_suppressed_until=now+180天`；写流水 |
| `degraded_fail` | 原生桥接最终失败（含无商店） | 仅写流水（诊断用），**不更新冷却**（用户未做任何选择） |

**幂等与事务规则**

1. 同一 `prompt_id` 下同一 `action` 幂等：`uk_prompt_action` 冲突即返回 200 去重。
2. `shown` 的状态更新使用 `UPDATE ... WHERE user_id=? AND (last_prompt_at IS NULL OR last_prompt_at < ?)` CAS 防并发重复计数（弱网重试场景）。
3. 跨 action 乱序（clicked 先于 shown 到达）：流水照收，状态以 `shown` 为准更新计数；`clicked_*` 更新冷却时不回退 `last_prompt_at`。
4. 客户端 Outbox 重传：`Idempotency-Key = promptId`，30 分钟窗口，与《接口幂等性与防重提交机制》规范一致。

### 7.3 正向事件计数同步

```
POST /api/v1/app/rating/positive-events
{ "event_type": "plan_completed", "occurred_at": "2026-11-10T08:00:00+08:00", "client_request_id": "crid_x" }
```

- 服务端累计用户正向事件数（近 90 天滑动窗口，Redis `ZSET` 存时间戳，`ZREMRANGEBYSCORE` 滑窗 + `ZCARD` 计数）。
- 判定资格时读窗口计数，与 `min_positive_events` 比较。
- 事件类型白名单：`plan_completed` / `report_viewed` / `streak_3d` / `mistake_mastered` / `homework_full_score`，其余类型入库但不计数（防刷）。

### 7.4 设计裁决：不追踪"是否已评分"

| 候选方案 | 结论 | 理由 |
|---------|------|------|
| 假定点击"去评分"即完成评分 | ❌ 不采用 | 用户可能跳转后未操作，数据失真 |
| 解析商店页面回调 / 抓包识别 | ❌ 禁止 | 违反商店政策与平台条款，有封号风险 |
| 年度计数达到上限后默认已评分 | ❌ 不采用 | 与关闭行为无法区分 |
| **仅在用户点击时置 `ever_clicked_rate`，不推断提交** | ✅ 采用 | 诚实可解释；商店真实评分数据以商店后台 Console 为准，运营侧周会对账 |

## 9. 错误处理与降级矩阵

### 9.1 错误码（63xxx 段，经全库扫描确认空闲）

| 错误码 | 场景 | 客户端处理 |
|--------|------|-----------|
| 63001 | 配置不存在或 `enabled=false` | 按 `blockedByDisabled` 丢弃，缓存 1h |
| 63002 | 灰度未命中 | 丢弃，不缓存（灰度随时放量） |
| 63003 | 未成年账号未授权展示 | 丢弃，缓存 24h |
| 63010 | 参数校验失败（config 非法值，如 cooldown<0） | 客户端回退内置保守默认值并上报诊断 |
| 63020 | 资格接口 5xx/超时 | 使用本地快照按最保守策略裁决（本地冷却有效则允许一次/否则拒绝），shown 走 Outbox |
| 63030 | 上报接口失败 | Outbox 重试（指数退避，最多 5 次/24h） |

> 通用网络/认证错误码复用基础段（40103 未登录、50200 网关超时等），不重复定义。

### 9.2 降级矩阵

| # | 故障点 | 降级行为 | 用户感知 |
|---|--------|---------|---------|
| D1 | 拉取配置网络失败 | 使用本地缓存配置；无缓存则本轮不弹 | 无 |
| D2 | 服务端资格接口整体不可用 | 本地预筛通过也**不弹**（资格必须服务端确认，宁可漏弹） | 无 |
| D3 | shown 上报失败 | Outbox 补报，弹窗照常 | 无 |
| D4 | Google Play Review 配额耗尽/不支持 | 自动降级商店页跳转 | 无 |
| D5 | 设备无商店 App | https 详情页兜底；仍失败静默关闭，记 `degraded_fail` | 无 |
| D6 | 原生桥接通道未注册（旧版本插件缺失） | 直接尝试 `openStoreListing`；失败静默 | 无 |
| D7 | 配置中心 kill_switch 开启 | 全量静默，客户端 5 分钟内感知 | 无 |
| D8 | Hive 本地存储损坏 | 清空 rating box，按无状态处理（服务端为准） | 无 |
| D9 | iOS <14（无 scene API） | `openStoreListing` 路径 | 无 |

### 9.3 与 NPS 弹窗 / 运营弹窗的互斥仲裁

- 三者统一经 `ModalScheduler` 排队：运营弹窗（高）> NPS 问卷（中）> 评分引导（低）。
- 任意一种弹出后，其余两种当日静默（`shared_modal_daily_gate`，Hive 记录日期）。
- NPS 与评分引导共享 `min_interval_days` 语义：一次 NPS 响应后 30 天内不再弹评分引导（反之亦然），仲裁逻辑放服务端资格接口一并返回 `suppressed_by=nps`。

```sql
-- 曝光→点击→跳转漏斗（按周）
SELECT
  DATE_FORMAT(created_at, '%Y-%u') AS week,
  COUNT(*) FILTER (WHERE action = 'shown')            AS shows,
  COUNT(*) FILTER (WHERE action = 'clicked_rate')     AS rate_clicks,
  COUNT(*) FILTER (WHERE action = 'clicked_later')    AS later_clicks,
  COUNT(*) FILTER (WHERE action = 'closed')           AS closes
FROM rating_prompt_log
GROUP BY week;
```

### 10.3 告警阈值

| 指标 | 阈值 | 级别 |
|------|------|------|
| 弹窗曝光 → `closed` 比例 | >40% 持续 3 天 | P2（文案/时机需复盘） |
| `degraded_fail` 占比 | >15% | P3（商店跳转链路异常） |
| 资格接口 P99 | >800ms | P3 |
| shown 上报 Outbox 积压 | >1000 条/小时 | P3 |
| 年弹出均值 | 超过 3 次/用户 | P1（可能违反 Apple 政策，紧急排查配置） |

### 10.4 真实评分口径

商店真实评分、评价数量、评分分布以各商店开发者后台为准（App Store Connect / Google Play Console / 华为 AGC 等），由运营每周人工汇总录入运营看板，不进入实时数据链路。

## 11. 合规红线（C 系列）

| 编号 | 红线 | 依据 |
|------|------|------|
| C1 | 不得以任何形式奖励、诱导用户评分（积分/优惠券/虚拟道具均禁止） | Apple Guideline 3.10.1 / Google Play 评价政策 |
| C2 | 文案不得要求"五星""好评"，不得预设评分方向 | Apple Guideline 5.6.1 |
| C3 | 不得用"差评请走内部反馈"方式拦截差评流向商店 | Google Play 政策 |
| C4 | 未成年人账号默认不展示；`allow_minor=true` 需双人审批 + 审计日志 | 《未成年人保护法》第 74 条 / 平台未成年人条款 |
| C5 | 展示时机避开教学过程（呼应 G1/G2），防止被认定为干扰教学类投诉 | 教育类 App 备案规范 |
| C6 | 评分引导数据不与学习画像融合建模，不用于个性化推荐输入 | 数据最小化原则（见 数据安全与隐私合规体系） |
| C7 | 埋点不得采集弹窗截图、页面内容等超范围信息 | PIPL 最小必要 |
