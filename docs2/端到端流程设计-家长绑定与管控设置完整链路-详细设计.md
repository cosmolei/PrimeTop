## 1. 流程概述

### 1.1 目标

将家长从「首次打开 APP」到「完成孩子绑定 + 管控策略配置 + 接收第一份学情报告」的完整链路进行端到端设计，使开发人员能够清晰理解每一步的客户端调用序列、服务端处理逻辑、数据流转和异常恢复策略。

### 1.2 用户故事

| # | 角色 | 用户故事 | 验收标准 |
|---|------|----------|----------|
| US-1 | 家长 | 作为家长，我想绑定孩子的学习账号，以便查看和管理孩子的学习情况 | 绑定邀请发出后，孩子在学生端确认即可完成绑定 |
| US-2 | 家长 | 作为家长，我想设置每天的使用时长限制，防止孩子过度使用 | 设置后实时生效，学生端到时自动提醒并锁定 |
| US-3 | 家长 | 作为家长，我想设置允许使用的时间段（如 18:00-21:00） | 非允许时段学生端无法进入学习功能 |
| US-4 | 家长 | 作为家长，我想绑定多个孩子并快速切换查看 | 一个家长可绑定最多 5 个孩子，切换即时生效 |
| US-5 | 家长 | 作为家长，我想接收孩子的周报/月报推送 | 报告按时推送至家长端消息中心 |
| US-6 | 学生 | 作为学生，我想确认家长的绑定请求，防止被陌生人绑定 | 收到绑定通知后可接受或拒绝 |
| US-7 | 家长 | 作为家长，我想对内容范围做限制（如禁用某些功能） | 配置实时下发，学生端立即遵守 |

## 2. 阶段一：家长注册与角色选择

### 2.1 前置条件

- APP 已安装并启动
- 网络可用

### 2.2 客户端调用序列

```
[APP 启动]
    │
    ▼
GET /api/v1/auth/check-token          ← 自动检查本地 Token
    │
    ├─ 有效 → 直接进入家长中心首页
    │
    └─ 无效/过期
        │
        ▼
    [展示登录页：手机号+验证码 / 第三方OAuth]
        │
        ▼
POST /api/v1/auth/send-code            ← 发送短信验证码
        │
        ▼
POST /api/v1/auth/login                ← 验证码登录
        │                              ← 返回: { access_token, refresh_token, user_id, is_new_user }
        ▼
    [is_new_user == true?]
        │
        ├─ 是 → 进入角色选择页
        │         │
        │         ▼
        │    POST /api/v1/users/{userId}/profile
        │    Body: { role: "parent", nickname: "..." }
        │         │
        │         ▼
        │    POST /api/v1/family/create   ← 自动创建家庭组
        │         │
        │         ▼
        │    返回 family_code
        │
        └─ 否 → 检查已有家庭组
                │
                ▼
           GET /api/v1/family/my
                │
                ├─ 有家庭组 → 进入家长中心
                └─ 无家庭组 → 引导创建
```

```sql

-- 2. 创建家庭组
INSERT INTO family (family_code, parent_user_id, family_name, status)
VALUES ('F3K8M2', 10086, '张小明家', 1);

-- 3. 家长自动成为家庭成员（角色=家长）
INSERT INTO family_member (family_id, user_id, role, status, joined_at)

```

### 2.5 异常处理

| 异常场景 | 客户端行为 | 服务端行为 |
|----------|-----------|-----------|
| 网络中断 | 本地缓存引导状态，恢复网络后重试 | 幂等设计，重复请求不重复创建 |
| 短信验证码发送失败 | 展示错误提示，提供「重新发送」按钮（60s 冷却） | 记录发送日志，限流 1条/60s/手机号 |
| Token 过期（注册流程中） | 自动 refresh_token 换新 | Refresh token 有效期 7 天 |
| 创建家庭组冲突 | 跳转到已有家庭组 | 返回 409 + 已有家庭组信息 |

## 3. 阶段二：生成与发送绑定邀请

### 3.1 绑定方式对比

| 方式 | 流程 | 安全等级 | 适用场景 |
|------|------|---------|---------|
| 邀请码 | 家长获得6位码 → 口头/文字告知孩子 → 孩子输入 | 中 | 最常用，简单快捷 |
| 二维码 | 家长展示QR → 孩子扫码 | 高 | 面对面场景 |
| 短信邀请 | 家长输入孩子手机号 → 系统发送邀请链接 | 中 | 孩子已有手机 |
| 学生抽码 | 学生端生成绑定码 → 家长输入 | 高 | 学生主动发起 |

### 3.2 邀请码方式 — 调用序列

```
家长端:
POST /api/v1/family/{familyId}/invitation
Body: { "method": "code" }

Response 200:
{
    "code": 0,
    "data": {
        "invitation_id": "inv_20001",
        "bind_code": "B7X9K4",         // 6位绑定码
        "expires_at": "2026-06-10T10:00:00.000Z",
        "qr_code_url": "https://primetop.app/bind?code=B7X9K4"
    }
}

[家长展示邀请码或二维码给孩子]
```

### 3.3 短信邀请方式 — 调用序列

```
家长端:
POST /api/v1/family/{familyId}/invitation
Body: {
    "method": "sms",
    "student_phone": "+8613800138000",
    "student_nickname": "小明"       // 可选，家长给孩子的称呼
}

Response 200:
{
    "code": 0,
    "data": {
        "invitation_id": "inv_20002",
        "bind_code": "B7X9K5",
        "sms_sent": true,
        "expires_at": "2026-06-10T10:00:00.000Z"
    }
}

Response 429 (短信限流):
{
    "code": 42901,
    "message": "邀请短信发送过于频繁，请5分钟后再试"
}
```

### 3.4 邀请数据模型

```sql
CREATE TABLE family_invitation (
    id              BIGSERIAL PRIMARY KEY,
    invitation_id   VARCHAR(32) NOT NULL UNIQUE,        -- 邀请唯一标识 inv_XXXXX
    family_id       BIGINT NOT NULL REFERENCES family(id),
    bind_code       VARCHAR(6) NOT NULL,                -- 6位绑定码
    method          VARCHAR(10) NOT NULL DEFAULT 'code', -- code | sms | qrcode
    inviter_user_id BIGINT NOT NULL,                    -- 发起邀请的家长ID
    invitee_phone   VARCHAR(20),                        -- 被邀请人手机号（SMS方式）
    invitee_nickname VARCHAR(50),                       -- 家长给孩子的昵称
    status          VARCHAR(20) NOT NULL DEFAULT 'pending', -- pending | confirmed | expired | cancelled
    expires_at      TIMESTAMPTZ NOT NULL,
    confirmed_by    BIGINT,                             -- 确认绑定的学生用户ID
    confirmed_at    TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_invitation_bind_code ON family_invitation(bind_code);
CREATE INDEX idx_invitation_family ON family_invitation(family_id, status);
```

### 3.5 异常处理

| 异常场景 | 处理策略 |
|----------|---------|
| 邀请码过期（7天） | 提示家长重新生成，旧码自动失效 |
| 邀请码被多人使用 | 仅第一个确认的学生生效，后续提示"该邀请已被使用" |
| 学生输入错误码 | 提示"邀请码无效，请确认后重试"，连续5次错误锁定15分钟 |
| 短信发送失败 | 提示家长稍后重试或换用邀请码方式 |
| 孩子已有家庭组 | 提示"该学生已绑定其他家庭，需先解绑" |

### 4.2 服务端绑定处理逻辑

```java
@Transactional
public BindingResult confirmBinding(String invitationId, Long studentUserId) {
    // 1. 查询邀请记录
    FamilyInvitation invitation = invitationRepository
        .findByInvitationId(invitationId)
        .orElseThrow(() -> new BizException(40402, "邀请不存在"));

    // 2. 校验邀请状态
    if (invitation.getStatus() != InvitationStatus.PENDING) {
        throw new BizException(40003, "邀请已失效或已被使用");
    }

    // 3. 校验过期时间
    if (invitation.getExpiresAt().isBefore(Instant.now())) {
        invitation.setStatus(InvitationStatus.EXPIRED);
        invitationRepository.save(invitation);
        throw new BizException(40004, "邀请已过期，请联系家长重新发送");
    }

    // 4. 检查学生是否已绑定其他家庭
    Optional<FamilyMember> existingBinding = familyMemberRepository
        .findActiveByUserId(studentUserId);
    if (existingBinding.isPresent()) {
        throw new BizException(40902, "您已绑定其他家庭，请先解绑后再操作");
    }

    // 5. 检查家庭组孩子数量上限
    long childCount = familyMemberRepository
        .countActiveChildren(invitation.getFamilyId());
    if (childCount >= 5) {
        throw new BizException(40005, "该家庭已达到孩子数量上限");
    }

    // 6. 创建家庭成员关系
    FamilyMember member = FamilyMember.builder()
        .familyId(invitation.getFamilyId())
        .userId(studentUserId)
        .nickname(invitation.getInviteeNickname() != null 
            ? invitation.getInviteeNickname() : "孩子" + (childCount + 1))
        .role("child")
        .status(MemberStatus.ACTIVE)
        .bindMethod(invitation.getMethod())
        .joinedAt(Instant.now())
        .build();
    familyMemberRepository.save(member);

    // 7. 更新邀请状态
    invitation.setStatus(InvitationStatus.CONFIRMED);
    invitation.setConfirmedBy(studentUserId);
    invitation.setConfirmedAt(Instant.now());
    invitationRepository.save(invitation);

    // 8. 创建默认管控配置
    ParentControlConfig defaultConfig = ParentControlConfig.builder()
        .bindingId(member.getId())
        .studentId(studentUserId)
        .dailyTimeLimitMin(null)         // 默认不限制
        .allowedTimeSlotsJson("[]")      // 默认不限制
        .enabledModulesJson("[]")        // 空数组表示全部开放
        .nightRestMode(true)             // 默认开启夜间休息 (22:00-06:00)
        .nightRestStart("22:00")
        .nightRestEnd("06:00")
        .build();
    controlConfigRepository.save(defaultConfig);

    // 9. 发送通知给家长
    notificationService.send(ParentBindSuccessNotification.builder()
        .targetUserId(invitation.getInviterUserId())
        .studentUserId(studentUserId)
        .familyId(invitation.getFamilyId())
        .build());

    // 10. 发布绑定成功事件（触发下游处理）
    eventPublisher.publish(new StudentBoundEvent(
        invitation.getFamilyId(), studentUserId, member.getId()));

    return BindingResult.builder()
        .bindingId(member.getId())
        .familyId(invitation.getFamilyId())
        .familyName(familyRepository.findById(invitation.getFamilyId())
            .map(Family::getFamilyName).orElse(""))
        .build();
}
```

### 4.3 绑定成功后的下游事件处理

```java
@EventListener
public void onStudentBound(StudentBoundEvent event) {
    Long familyId = event.getFamilyId();
    Long studentId = event.getStudentId();

    // 1. 初始化学生学习画像（冷启动）
    learningProfileService.initializeColdStartProfile(studentId);

    // 2. 为家长生成首次绑定消息卡片
    parentNotificationService.sendWelcomeGuide(event.getBindingId());

    // 3. 如果家庭有家庭套餐，为新绑定的孩子分配权益
    familyPlanService.allocateQuota(familyId, studentId);

    // 4. 记录审计日志
    auditLogService.log(AuditAction.PARENT_BIND_CHILD, Map.of(
        "family_id", familyId,
        "student_id", studentId,
        "binding_id", event.getBindingId()
    ));
}
```

## 5. 阶段四：家长管控策略配置

### 5.1 管控配置总览

管控策略分为以下维度：

| 维度 | 配置项 | 默认值 | 生效方式 |
|------|--------|--------|---------|
| 时长控制 | 每日使用时长上限 (分钟) | 不限制 | 实时下发 |
| 时段控制 | 允许使用的时间段 | 全天 (除夜间休息) | 实时下发 |
| 夜间休息 | 休息时段 (如 22:00-06:00) | 开启, 22:00-06:00 | 实时下发 |
| 功能模块 | 可用/禁用模块列表 | 全部开放 | 实时下发 |
| AI 调用 | 每日AI问答次数上限 | 不限制(会员权益内) | 实时下发 |
| 拍题次数 | 每日拍题次数上限 | 不限制(会员权益内) | 实时下发 |
| 内容范围 | 可学习的学科白名单 | 全部学科 | 实时下发 |

### 5.3 管控策略实时下发机制

管控配置变更后需要实时同步到学生端。下发路径：

```
家长端                          服务端                         学生端
  │                              │                              │
  │  PUT /control/{studentId}    │                              │
  │─────────────────────────────▶│                              │
  │                              │                              │
  │                              │  ① 写入 parent_control_config│
  │                              │  ② 发布 ControlUpdated 事件  │
  │                              │  ③ 推送 WebSocket 消息        │
  │                              │─────────────────────────────▶│
  │                              │                              │
  │  Response 200                │                    ④ 学生端收到  │
  │◀─────────────────────────────│                    control_updated │
  │                              │                       │      │
  │                              │                       ▼      │
  │                              │              [更新本地管控缓存] │
  │                              │              [重启计时器]       │
```

### 5.4 管控执行引擎（学生端）

```dart
/// 学生端管控执行引擎
class ParentalControlEngine {
  final ControlConfigRepository _configRepo;
  final UsageTimerService _timerService;
  final TimeSlotChecker _timeSlotChecker;

  /// 检查当前是否允许使用
  /// 返回 null 表示允许，返回字符串表示拒绝原因
  String? checkAccess() {
    final config = _configRepo.current;

    // 1. 检查时段限制
    if (!_timeSlotChecker.isNowAllowed(config.allowedTimeSlots)) {
      return '当前不在允许使用的时间段内';
    }

    // 2. 检查夜间休息模式
    if (config.nightRestMode && _timeSlotChecker.isInRestPeriod(
        config.nightRestStart, config.nightRestEnd)) {
      return '现在是休息时间，明天继续学习吧';
    }

    // 3. 检查每日时长限制
    if (config.dailyTimeLimitMin != null) {
      final usedMin = _timerService.getTodayUsageMinutes();
      if (usedMin >= config.dailyTimeLimitMin!) {
        return '今日学习时长已达到家长设定的上限 (${config.dailyTimeLimitMin}分钟)';
      }
    }

    return null; // 允许使用
  }

  /// 获取剩余可用分钟数（null 表示不限制）
  int? getRemainingMinutes() {
    final config = _configRepo.current;
    if (config.dailyTimeLimitMin == null) return null;
    final used = _timerService.getTodayUsageMinutes();
    return max(0, config.dailyTimeLimitMin! - used);
  }

  /// 时长即将用尽提醒策略
  /// 返回需要弹出的提醒级别
  TimeWarningLevel checkTimeWarning() {
    final remaining = getRemainingMinutes();
    if (remaining == null) return TimeWarningLevel.none;
    if (remaining <= 5) return TimeWarningLevel.critical;   // ≤5分钟：弹窗强提醒
    if (remaining <= 15) return TimeWarningLevel.warning;   // ≤15分钟：Toast提醒
    if (remaining <= 30) return TimeWarningLevel.info;      // ≤30分钟：状态栏提示
    return TimeWarningLevel.none;
  }
}

enum TimeWarningLevel {
  none,       // 不提醒
  info,       // 状态栏提示
  warning,    // Toast 提醒
  critical,   // 弹窗强提醒 + 倒计时
}
```

## 10. 关键边界条件与异常场景

### 10.1 并发与竞态

| 场景 | 风险 | 处理方案 |
|------|------|---------|
| 同一邀请码被两个学生同时确认 | 数据不一致 | 数据库乐观锁 + UNIQUE 约束，先到先得 |
| 家长修改管控配置同时学生端拉取 | 学生拿到旧配置 | WebSocket 推送优先，HTTP 拉取兜底，30s 内最终一致 |
| 学生解绑同时家长发送管控更新 | 更新写入孤儿记录 | 解绑时级联清理管控配置，更新时校验绑定状态 |
| 多设备同时登录学生端 | 时长统计不准 | 心跳以最后活跃设备为准，单设备心跳间隔 60s |

### 10.2 极端场景

| 场景 | 处理方案 |
|------|---------|
| 学生账号被封禁后家长尝试绑定 | 返回 "该账号不可用" ，不泄露封禁原因 |
| 家长解绑后重新绑定同一学生 | 允许，但历史管控配置不保留，使用默认值 |
| 家庭套餐到期后管控是否失效 | 管控功能不依赖会员状态，始终可用 |
| 学生端长时间离线（>7天） | 管控配置本地持久化，启动时强制拉取最新 |
| 家长忘记密码无法登录 | 通过手机验证码重置，不影响已绑定关系 |
| 未成年人冒充家长注册 | 首次进入家长中心需额外身份验证（短信验证码确认） |
