# 服务端-教育内容生产任务编排与产能智能调度引擎-详细设计

## 1. 概述

### 1.1 功能定位

教育内容生产任务编排与产能智能调度引擎是 PrimeTop 平台内容生产线的核心调度中枢。在"生产需求预测 → 任务编排 → 创作者分配 → 生产执行 → 质量审核 → 发布上线"的内容全生命周期中，本引擎专注于**任务编排与创作者资源调度**环节，解决以下核心问题：

1. **谁来做**：根据创作者的能力画像、历史产能、当前负载，将内容生产任务最优分配给合适的创作者。
2. **什么时候做**：基于学期日历、考试节点、内容上线截止日期，智能排定任务优先级和生产时序。
3. **产能是否足够**：预测未来内容生产需求与创作者产能的匹配度，提前发现产能缺口。
4. **哪里有瓶颈**：实时监控生产流水线各环节吞吐量，自动检测并预警瓶颈节点。

### 1.2 与现有系统的关系

| 现有系统 | 关系 |
| --- | --- |
| 题库知识点覆盖度智能诊断与内容生产需求预测引擎 | **上游**：产出"需要生产什么内容"的需求清单，本引擎接收需求并编排生产 |
| 教育内容协同创作与审校发布生产线引擎 | **下游**：本引擎分配任务后，由生产线引擎管理具体的创作→审校→发布工作流 |
| 教育内容审核工作流与多级审核管线 | **协作**：审核环节的吞吐量影响整体产能调度 |
| 教育内容供应商管理与合作伙伴运营工作台 | **数据来源**：提供创作者（内部编辑 + 外部供应商）的能力与绩效数据 |
| 管理后台-题库内容管理与生产运维工作台 | **展示层**：运维人员通过此工作台查看调度结果和产能看板 |

### 1.3 设计目标

| 目标 | 指标 |
| --- | --- |
| 任务分配合理率 | ≥ 90%（创作者能力与任务难度匹配） |
| 产能预测准确率 | ≥ 85%（月度产能预测偏差） |
| 瓶颈检测提前量 | ≥ 3 天（在瓶颈造成延期前预警） |
| 任务按时完成率 | ≥ 95%（在 deadline 前完成） |
| 创作者负载均衡度 | CV（变异系数）≤ 0.3 |

## 2. 核心概念与领域模型

### 2.1 领域概念

```
ProductionTask（生产任务）
  ├── 来源：需求预测引擎自动生成 / 运营人员手动创建
  ├── 类型：题目编写、解析编写、知识点讲解、视频脚本、课件制作等
  ├── 难度等级：L1（简单）~ L5（高难）
  ├── 优先级：P0（紧急）~ P3（常规）
  ├── 预估工时：基于历史数据估算
  └── 截止日期：基于上线计划和学期日历推算

Creator（创作者）
  ├── 类型：内部编辑（IN_HOUSE）、外部供应商（SUPPLIER）、AI辅助（AI_ASSISTED）
  ├── 能力画像：学科 × 学段 × 内容类型 × 难度等级 → 熟练度评分
  ├── 产能画像：日产能（任务数/工时）、质量评分、按时率
  └── 当前负载：已分配任务数、已占用工时、可用时间窗口

SchedulePlan（排产计划）
  ├── 周期：周排产 / 月排产
  ├── 约束：创作者可用时间、任务依赖关系、审核环节吞吐量
  ├── 目标：最大化按时完成率 + 最小化超时风险 + 负载均衡
  └── 输出：TaskAssignment 列表（任务-创作者-时间段映射）

CapacityForecast（产能预测）
  ├── 预测维度：按学科、按内容类型、按创作者团队
  ├── 预测周期：未来 4 周 / 8 周 / 12 周
  ├── 输入：历史产能数据 + 待生产需求清单 + 创作者可用性
  └── 输出：产能缺口预警 / 产能过剩建议
```

### 2.2 核心状态机

#### 2.2.1 生产任务状态机

```
                    ┌──────────┐
                    │ PENDING  │ 待分配
                    └────┬─────┘
                         │ 分配创作者
                    ┌────▼─────┐
                    │ ASSIGNED │ 已分配
                    └────┬─────┘
                         │ 创作者接单
                    ┌────▼──────┐
                    │ IN_PROGRESS│ 生产中
                    └────┬──────┘
                         │ 提交初稿
                    ┌────▼──────┐
                    │  REVIEW   │ 审核中
                    └────┬──────┘
                    ┌────┴────┐
                    │         │
              ┌─────▼──┐  ┌──▼──────┐
              │PASS    │  │REJECT   │
              │        │  │         │
              │        │  │ REWORK  │→ 返回 IN_PROGRESS
              │        │  └─────────┘
              │
         ┌────▼────┐
         │PUBLISHED│ 已发布
         └─────────┘

异常分支：
  PENDING   → CANCELLED（需求变更取消）
  ASSIGNED  → RETURNED（创作者退回）
  ASSIGNED  → REASSIGNED（超时未接单，重新分配）
  IN_PROGRESS → BLOCKED（阻塞等待依赖）
  REVIEW    → ESCALATED（升级审核）
```

#### 2.2.2 排产计划状态机

```
DRAFT → COMPUTING → READY → LOCKED → ARCHIVED
  │                                   ▲
  │___________（重新计算）______________│
```

## 4. 核心算法设计

### 4.1 任务-创作者匹配评分算法

```python
def calculate_match_score(task: dict, creator: dict, current_date: datetime) -> float:
    """
    计算任务与创作者的匹配度评分 (0.0 ~ 1.0)
    
    评分维度:
      1. 能力匹配 (40%): 创作者是否有能力完成此任务
      2. 负载可用性 (25%): 创作者当前是否有足够时间
      3. 历史绩效 (20%): 创作者在此类任务上的历史表现
      4. 紧急度适配 (15%): 创作者是否适合处理紧急任务
    """
    # --- 1. 能力匹配评分 ---
    capability_score = _calc_capability_score(task, creator)
    if capability_score == 0.0:
        return 0.0  # 能力不匹配，直接排除
    
    # --- 2. 负载可用性评分 ---
    availability_score = _calc_availability_score(task, creator, current_date)
    if availability_score == 0.0:
        return 0.0  # 无可用时间，直接排除
    
    # --- 3. 历史绩效评分 ---
    performance_score = _calc_performance_score(task, creator)
    
    # --- 4. 紧急度适配评分 ---
    urgency_score = _calc_urgency_score(task, creator)
    
    # 加权汇总
    total_score = (
        capability_score * 0.40 +
        availability_score * 0.25 +
        performance_score * 0.20 +
        urgency_score * 0.15
    )
    
    return round(total_score, 4)


def _calc_capability_score(task: dict, creator: dict) -> float:
    """计算能力匹配度"""
    caps = creator.get('capability_matrix', {}).get('capabilities', [])
    
    for cap in caps:
        if cap['subject'] != task['subject_code']:
            continue
        if task['grade_stage'] not in cap.get('stages', []):
            continue
        
        for ct_cap in cap.get('contentTypeCapabilities', []):
            if ct_cap['contentType'] != task['content_type']:
                continue
            
            # 难度检查
            if task['difficulty'] > ct_cap['maxDifficulty']:
                return 0.0  # 难度超出能力范围
            
            # 熟练度 × 难度系数
            difficulty_factor = 1.0 - (task['difficulty'] - ct_cap['maxDifficulty']) * 0.1
            difficulty_factor = max(0.5, difficulty_factor)
            
            return ct_cap['proficiency'] * difficulty_factor
    
    return 0.0  # 无匹配能力


def _calc_availability_score(task: dict, creator: dict, current_date: datetime) -> float:
    """计算负载可用性评分"""
    available_hours = creator.get('available_hours_per_day', 8.0)
    current_workload = creator.get('current_workload_hours', 0)
    estimated_hours = task.get('estimated_hours', 2.0)
    
    # 计算剩余可用时间
    remaining_daily_hours = available_hours - current_workload
    
    if remaining_daily_hours <= 0:
        return 0.0
    
    # 计算到 deadline 的可用总时间
    days_to_deadline = max(1, (task['deadline'] - current_date).days)
    work_days = creator.get('work_days', [1,2,3,4,5])
    
    # 估算可用工作日数
    available_work_days = _count_work_days(current_date, task['deadline'], work_days)
    total_available_hours = available_work_days * remaining_daily_hours
    
    if total_available_hours < estimated_hours:
        return 0.0  # 时间不够
    
    # 富裕度评分：可用时间/需要时间 比率
    ratio = total_available_hours / estimated_hours
    return min(1.0, ratio / 2.0)  # 比率≥2时满分


def _calc_performance_score(task: dict, creator: dict) -> float:
    """计算历史绩效评分"""
    quality = creator.get('avg_quality_score', 0.8)
    on_time = creator.get('on_time_rate', 0.85)
    
    # 在特定任务类型上的历史完成量
    total_completed = _get_historical_completion_count(
        creator['id'], task['subject_code'], 
        task['content_type'], task['difficulty']
    )
    
    # 经验加分（完成量越多越熟练）
    experience_bonus = min(0.15, total_completed * 0.005)
    
    base_score = quality * 0.6 + on_time * 0.4
    return min(1.0, base_score + experience_bonus)


def _calc_urgency_score(task: dict, creator: dict) -> float:
    """计算紧急度适配评分"""
    priority = task.get('priority', 2)
    
    if priority == 0:  # P0 紧急任务
        # 优先分配给高质量、高效率的创作者
        quality = creator.get('avg_quality_score', 0.8)
        avg_hours = creator.get('avg_completion_hours', 2.0)
        efficiency = max(0.5, 1.0 - (avg_hours - 1.0) * 0.1)
        return quality * efficiency
    elif priority == 1:
        return 0.75
    else:
        # 常规任务更适合分配给需要积累经验的创作者
        return 0.60
```

### 4.2 批量任务调度算法（贪心 + 负载均衡）

```python
class ProductionScheduler:
    """
    生产任务批量调度器
    
    策略：贪心 + 负载均衡
    1. 按优先级和 deadline 排序任务
    2. 对每个任务，计算所有候选创作者的匹配评分
    3. 选择最佳匹配，同时考虑负载均衡惩罚因子
    """
    
    BALANCE_PENALTY = 0.15  # 负载不均衡惩罚因子
    MAX_ITERATIONS = 3       # 最大迭代次数
    
    def schedule(self, tasks: list, creators: list, 
                 plan_period: tuple) -> list:
        """
        执行排产调度
        
        Args:
            tasks: 待分配任务列表
            creators: 可用创作者列表
            plan_period: (start_date, end_date)
        
        Returns:
            list[dict]: 分配方案列表
        """
        assignments = []
        
        # Step 1: 任务排序 - 优先级高的先分配
        sorted_tasks = self._sort_tasks(tasks)
        
        # Step 2: 初始化创作者负载追踪
        creator_loads = {
            c['id']: {
                'task_count': c.get('current_task_count', 0),
                'workload_hours': c.get('current_workload_hours', 0),
                'daily_capacity': c.get('avg_daily_capacity', 10)
            }
            for c in creators
        }
        
        # Step 3: 计算团队平均负载（用于均衡判断）
        avg_load = self._calc_average_load(creator_loads)
        
        # Step 4: 贪心分配
        unassigned = []
        for task in sorted_tasks:
            candidates = self._find_candidates(task, creators, creator_loads)
            
            if not candidates:
                unassigned.append(task)
                continue
            
            # 计算每个候选的综合得分（匹配分 - 负载惩罚）
            scored_candidates = []
            for creator_id, match_score in candidates:
                load = creator_loads[creator_id]
                load_ratio = load['workload_hours'] / max(1, load['daily_capacity'] * 5)  # 周产能比
                
                # 负载过重的创作者降低优先级
                balance_penalty = 0.0
                if load_ratio > avg_load * 1.5:
                    balance_penalty = self.BALANCE_PENALTY * (load_ratio - avg_load)
                
                final_score = match_score - balance_penalty
                scored_candidates.append((creator_id, final_score, match_score))
            
            # 选择最高分
            scored_candidates.sort(key=lambda x: x[1], reverse=True)
            best_creator_id, _, best_match_score = scored_candidates[0]
            
            assignments.append({
                'task_id': task['id'],
                'creator_id': best_creator_id,
                'match_score': best_match_score,
                'expected_start_at': self._calc_expected_start(task, creator_loads[best_creator_id]),
                'expected_complete_at': self._calc_expected_complete(task, creator_loads[best_creator_id]),
                'assignment_type': 'AUTO',
                'assignment_reason': f'匹配度={best_match_score:.2f}, 综合评分={scored_candidates[0][1]:.2f}'
            })
            
            # 更新负载
            est_hours = task.get('estimated_hours', 2.0)
            creator_loads[best_creator_id]['task_count'] += 1
            creator_loads[best_creator_id]['workload_hours'] += est_hours
        
        # Step 5: 对未分配任务进行二次尝试（放宽约束）
        if unassigned:
            retry_assignments = self._retry_unassigned(unassigned, creators, creator_loads)
            assignments.extend(retry_assignments)
            still_unassigned = [t for t in unassigned 
                              if t['id'] not in {a['task_id'] for a in retry_assignments}]
        else:
            still_unassigned = []
        
        # Step 6: 生成预警
        alerts = self._generate_alerts(still_unassigned, creator_loads, avg_load)
        
        return {
            'assignments': assignments,
            'unassigned': still_unassigned,
            'alerts': alerts,
            'stats': self._calc_stats(assignments, len(tasks), creator_loads)
        }
    
    def _sort_tasks(self, tasks: list) -> list:
        """任务排序：优先级 → deadline → 难度"""
        return sorted(tasks, key=lambda t: (
            t.get('priority', 2),     # P0=0 排最前
            t['deadline'],             # 截止时间早的排前面
            -t.get('difficulty', 3)    # 高难度的优先分配（可选拘认少）
        ))
    
    def _find_candidates(self, task: dict, creators: list, 
                         creator_loads: dict) -> list:
        """找到所有匹配的候选创作者"""
        candidates = []
        current_date = datetime.now()
        
        for creator in creators:
            if creator['status'] != 'ACTIVE':
                continue
            
            load = creator_loads[creator['id']]
            # 跳过负载已达上限的创作者
            if load['workload_hours'] >= load['daily_capacity'] * 5:  # 周上限
                continue
            
            score = calculate_match_score(task, creator, current_date)
            if score >= 0.3:  # 最低匹配阈值
                candidates.append((creator['id'], score))
        
        return candidates
    
    def _calc_average_load(self, creator_loads: dict) -> float:
        """计算团队平均负载率"""
        if not creator_loads:
            return 0.0
        
        total_ratio = 0.0
        for load in creator_loads.values():
            cap = load['daily_capacity'] * 5
            ratio = load['workload_hours'] / max(1, cap)
            total_ratio += ratio
        
        return total_ratio / len(creator_loads)
```

```python
class CapacityForecaster:
    """
    产能预测器
    
    基于历史产能数据 + 未来需求清单，预测产能缺口
    """
    
    FORECAST_MODELS = {
        'SIMPLE': '简单移动平均',
        'WEIGHTED': '加权移动平均',
        'TREND': '趋势外推',
        'SEASONAL': '季节性调整'
    }
    
    def forecast(self, horizon_weeks: int, dimension: dict) -> dict:
        """
        生成产能预测
        
        Args:
            horizon_weeks: 预测周期（4/8/12周）
            dimension: 预测维度过滤条件
        
        Returns:
            预测结果（含供需对比和缺口分析）
        """
        # Step 1: 获取历史产能数据（最近12周）
        historical = self._fetch_historical_capacity(12, dimension)
        
        # Step 2: 获取未来需求清单
        demand_forecast = self._fetch_demand_forecast(horizon_weeks, dimension)
        
        # Step 3: 预测未来产能
        supply_forecast = self._predict_supply(historical, horizon_weeks)
        
        # Step 4: 逐周对比
        weekly_gaps = []
        for week_idx in range(horizon_weeks):
            demand = demand_forecast[week_idx]
            supply = supply_forecast[week_idx]
            
            gap_tasks = demand['tasks'] - supply['tasks']
            gap_hours = demand['hours'] - supply['hours']
            
            weekly_gaps.append({
                'week': week_idx + 1,
                'demand_tasks': demand['tasks'],
                'supply_tasks': supply['tasks'],
                'gap_tasks': gap_tasks,
                'gap_hours': gap_hours,
                'severity': self._classify_gap_severity(gap_tasks, supply['tasks'])
            })
        
        # Step 5: 生成建议
        recommendations = self._generate_recommendations(weekly_gaps, dimension)
        
        return {
            'horizon_weeks': horizon_weeks,
            'weekly_gaps': weekly_gaps,
            'summary': self._summarize(weekly_gaps),
            'recommendations': recommendations
        }
    
    def _predict_supply(self, historical: list, horizon: int) -> list:
        """预测未来产能"""
        predictions = []
        
        for week_idx in range(horizon):
            # 加权移动平均（近期数据权重更高）
            weights = [0.35, 0.25, 0.15, 0.10, 0.05, 0.03, 0.02, 0.02, 0.01, 0.01, 0.005, 0.005]
            
            total_tasks = 0
            total_hours = 0
            for i, hist in enumerate(historical):
                weight = weights[i] if i < len(weights) else 0
                total_tasks += hist['completed_tasks'] * weight
                total_hours += hist['completed_hours'] * weight
            
            # 季节性调整（考试季产能通常更高）
            seasonal_factor = self._get_seasonal_factor(week_idx)
            
            predictions.append({
                'tasks': int(total_tasks * seasonal_factor),
                'hours': round(total_hours * seasonal_factor, 1)
            })
        
        return predictions
    
    def _get_seasonal_factor(self, week_offset: int) -> float:
        """获取季节性调整因子"""
        future_date = datetime.now() + timedelta(weeks=week_offset)
        month = future_date.month
        
        # 开学季（2-3月、8-9月）产能需求更高
        if month in [2, 3, 8, 9]:
            return 1.15
        # 期末考试季（6月、12月）产能需求更高
        elif month in [6, 12]:
            return 1.20
        # 寒暑假（1月、7月）产能需求较低
        elif month in [1, 7]:
            return 0.85
        else:
            return 1.0
    
    def _classify_gap_severity(self, gap_tasks: int, supply_tasks: int) -> str:
        """分类缺口严重程度"""
        if supply_tasks == 0:
            return 'CRITICAL'
        
        gap_ratio = gap_tasks / supply_tasks
        
        if gap_ratio <= 0:
            return 'NONE'
        elif gap_ratio <= 0.10:
            return 'LOW'
        elif gap_ratio <= 0.25:
            return 'MEDIUM'
        elif gap_ratio <= 0.50:
            return 'HIGH'
        else:
            return 'CRITICAL'
    
    def _generate_recommendations(self, weekly_gaps: list, dimension: dict) -> list:
        """生成产能调整建议"""
        recommendations = []
        
        critical_weeks = [g for g in weekly_gaps if g['severity'] in ['HIGH', 'CRITICAL']]
        
        if critical_weeks:
            total_gap_hours = sum(g['gap_hours'] for g in critical_weeks)
            
            # 建议1：增加外部供应商
            supplier_hours = total_gap_hours * 0.6  # 外包60%缺口
            recommendations.append({
                'type': 'OUTSOURCE',
                'priority': 'HIGH',
                'description': f'未来{len(critical_weeks)}周存在产能缺口，建议外包约{supplier_hours:.0f}工时',
                'estimated_cost': self._estimate_outsource_cost(supplier_hours, dimension),
                'action': 'CREATE_SUPPLIER_ORDER'
            })
            
            # 建议2：启用AI辅助
            ai_tasks = sum(g['gap_tasks'] for g in critical_weeks)
            recommendations.append({
                'type': 'AI_ASSIST',
                'priority': 'MEDIUM',
                'description': f'建议启用AI辅助生产，预计可覆盖{int(ai_tasks * 0.4)}个任务',
                'action': 'ENABLE_AI_DRAFT_GENERATION'
            })
            
            # 建议3：调整上线时间
            recommendations.append({
                'type': 'RESCHEDULE',
                'priority': 'LOW',
                'description': '建议与产品团队沟通，评估是否可调整部分内容的上线时间',
                'action': 'REVIEW_PUBLISH_SCHEDULE'
            })
        
        # 产能过剩建议
        surplus_weeks = [g for g in weekly_gaps if g['gap_tasks'] < -5]
        if surplus_weeks:
            recommendations.append({
                'type': 'SURPLUS',
                'priority': 'LOW',
                'description': f'未来{len(surplus_weeks)}周可能出现产能过剩，建议安排创作者休假或进行内容储备',
                'action': 'PLAN_CONTENT_RESERVE'
            })
        
        return recommendations
```

## 6. 瓶颈检测引擎设计

### 6.1 流水线吞吐量监控

```python
class BottleneckDetector:
    """
    生产流水线瓶颈检测器
    
    监控各环节吞吐量，基于历史基线检测异常
    """
    
    STAGE_WAIT_THRESHOLD = {
        'ASSIGNED': 4 * 3600,      # 接单等待阈值 4小时
        'IN_PROGRESS': 30 * 3600,   # 生产等待阈值 30小时
        'REVIEW': 36 * 3600,        # 审核等待阈值 36小时
        'REWORK': 24 * 3600,        # 返工等待阈值 24小时
    }
    
    DEVIATION_THRESHOLD = 1.5  # 超过历史均值1.5倍判定为瓶颈
    
    def detect(self, period_start: datetime, period_end: datetime) -> dict:
        """检测指定周期内的流水线瓶颈"""
        
        stages = ['ASSIGNED', 'IN_PROGRESS', 'REVIEW', 'REWORK', 'PUBLISHED']
        stage_metrics = []
        bottlenecks = []
        
        for stage in stages:
            # 当前周期指标
            current = self._fetch_stage_metrics(stage, period_start, period_end)
            
            # 历史基线（最近4周同期均值）
            historical = self._fetch_historical_baseline(stage, weeks=4)
            
            # 计算偏差
            wait_deviation = current.avg_wait_seconds / max(1, historical.avg_wait_seconds)
            throughput_deviation = (
                1 - current.throughput / max(1, historical.avg_throughput)
            ) if historical.avg_throughput > 0 else 0
            
            is_bottleneck = (
                wait_deviation >= self.DEVIATION_THRESHOLD or
                throughput_deviation >= 0.3
            )
            
            metric = {
                'stage': stage,
                'throughput': current.throughput,
                'avgWaitHours': round(current.avg_wait_seconds / 3600, 1),
                'historicalAvgWaitHours': round(historical.avg_wait_seconds / 3600, 1),
                'waitDeviation': round(wait_deviation, 2),
                'throughputDeviation': round(throughput_deviation, 2),
                'status': 'BOTTLENECK' if is_bottleneck else 'NORMAL',
                'queueSize': current.queue_size
            }
            
            stage_metrics.append(metric)
            
            if is_bottleneck:
                bottlenecks.append({
                    'stage': stage,
                    'metric': metric,
                    'cause': self._analyze_cause(stage, current, historical),
                    'recommendation': self._recommend_fix(stage, current)
                })
        
        return {
            'period': f"{period_start.date()} ~ {period_end.date()}",
            'pipelineStages': stage_metrics,
            'bottlenecks': bottlenecks,
            'overallHealth': self._assess_health(stage_metrics)
        }
    
    def _analyze_cause(self, stage: str, current: dict, historical: dict) -> str:
        """分析瓶颈原因"""
        if stage == 'ASSIGNED':
            if current['queue_size'] > historical['avg_queue'] * 2:
                return f"待分配任务积压({current['queue_size']}件)，可能原因：活跃创作者不足或任务难度分布失衡"
        
        if stage == 'IN_PROGRESS':
            if current['avg_wait_seconds'] > historical['avg_wait_seconds'] * 1.5:
                return f"生产环节耗时过长(平均{current['avg_wait_seconds']/3600:.1f}h)，可能原因：任务难度过高或创作者负载过重"
        
        if stage == 'REVIEW':
            if current['queue_size'] > 30:
                return f"审核任务积压({current['queue_size']}件)，审核人员不足或审核标准过于严格"
        
        return "异常波动，建议人工排查"
    
    def _recommend_fix(self, stage: str, current: dict) -> dict:
        """推荐修复方案"""
        recommendations = {
            'ASSIGNED': [
                {'action': 'EXPAND_CREATOR_POOL', 'desc': '扩充创作者池，引入更多供应商'},
                {'action': 'ADJUST_DIFFICULTY', 'desc': '将高难度任务拆分为多个低难度子任务'},
                {'action': 'ENABLE_AI_ASSIST', 'desc': '为高难度任务启用AI辅助初稿'}
            ],
            'IN_PROGRESS': [
                {'action': 'REDUCE_WORKLOAD', 'desc': '减少单创作者并行任务数，提高专注度'},
                {'action': 'PROVIDE_REFERENCE', 'desc': '为创作者提供更多参考资料和模板'},
                {'action': 'ENABLE_AI_ASSIST', 'desc': '启用AI辅助生成初稿'}
            ],
            'REVIEW': [
                {'action': 'ADD_REVIEWERS', 'desc': '增加审核人员数量'},
                {'action': 'AI_PRE_REVIEW', 'desc': '启用AI预审核，减少人工审核工作量'},
                {'action': 'STAGED_REVIEW', 'desc': '实施分级审核，低风险内容快速通道'}
            ]
        }
        
        return recommendations.get(stage, [
            {'action': 'MANUAL_REVIEW', 'desc': '建议人工排查具体原因'}
        ])
```

## 9. 错误处理与异常场景

### 9.1 错误码定义

| 错误码 | HTTP状态码 | 说明 | 处理建议 |
| --- | --- | --- | --- |
| 40001 | 400 | 任务参数无效 | 检查请求参数 |
| 40002 | 400 | 任务难度超出创作者能力范围 | 降低难度或扩展创作者池 |
| 40003 | 409 | 任务已被分配 | 刷新任务状态 |
| 40004 | 409 | 排产计划已锁定，不可修改 | 先解锁再修改 |
| 40005 | 400 | 无可用创作者 | 扩展创作者池或启用AI辅助 |
| 40006 | 404 | 创作者不存在或已停用 | 检查创作者状态 |
| 40007 | 400 | 产能预测参数无效 | 检查预测周期和维度 |
| 40008 | 422 | 任务存在循环依赖 | 检查 depends_on_task_ids |
| 40009 | 409 | 创作者当前负载已达上限 | 等待或分配给其他创作者 |
| 40010 | 500 | 排产计算异常 | 重试或检查算法参数 |

### 9.2 异常场景处理

#### 场景1：创作者临时请假

```
触发条件：创作者状态变更为 PAUSED
处理流程：
1. 系统检测到创作者状态变更
2. 查询该创作者所有 ASSIGNED/IN_PROGRESS 状态的任务
3. ASSIGNED 状态 → 自动退回 PENDING 池，标记为 REASSIGN
4. IN_PROGRESS 状态 → 通知组长人工处理（评估是否可转移或延期）
5. 重新触发增量排产，将退回的任务分配给其他创作者
6. 通知受影响的任务相关方
```

#### 场景2：紧急任务插队

```
触发条件：运营人员创建 priority=0 的紧急任务
处理流程：
1. 紧急任务直接进入排产队列
2. 系统评估当前所有活跃创作者的负载
3. 优先选择：当前负载 < 50% 且能力匹配度 ≥ 0.7 的创作者
4. 如果无合适创作者 → 通知组长手动指定
5. 如果需要调整其他任务的 deadline → 生成影响评估报告
```

#### 场景3：排产计算超时

```
触发条件：排产计算超过 5 分钟未完成
处理流程：
1. 标记排产计划状态为 COMPUTING_TIMEOUT
2. 自动切换到简化算法（减少迭代次数）
3. 如果简化算法仍超时 → 返回部分分配结果 + 未分配任务清单
4. 通知运营人员人工介入
```

#### 场景4：大面积审核拒绝

```
触发条件：某周期内 REVIEW 阶段拒绝率 > 30%
处理流程：
1. 触发质量告警
2. 分析拒绝原因分布（格式问题/内容错误/知识点错误）
3. 如果集中在某个创作者 → 标记该创作者为"质量观察"
4. 如果集中在某个学科/内容类型 → 生成质量问题分析报告
5. 建议组织创作者培训或更新创作规范
```

### 10.3 并发控制

```java
@Service
public class ScheduleService {
    
    private final RedissonClient redisson;
    
    /**
     * 排产计划锁定，防止并发排产
     */
    public ScheduleResult executeSchedule(ScheduleRequest request) {
        String lockKey = "schedule:lock:" + request.getPeriodStart() + ":" + request.getPeriodEnd();
        RLock lock = redisson.getLock(lockKey);
        
        try {
            // 尝试获取锁，等待10秒，自动释放300秒
            boolean acquired = lock.tryLock(10, 300, TimeUnit.SECONDS);
            if (!acquired) {
                throw new BusinessException(40010, "排产计算繁忙，请稍后重试");
            }
            
            return doSchedule(request);
            
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException(40010, "排产计算被中断");
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
    
    /**
     * 任务分配的乐观锁
     */
    @Transactional
    public void assignTask(Long taskId, Long creatorId) {
        // 乐观锁：CAS更新任务状态
        int updated = taskMapper.updateStatusWithVersion(
            taskId, "PENDING", "ASSIGNED", Instant.now().getEpochSecond()
        );
        
        if (updated == 0) {
            throw new BusinessException(40003, "任务已被其他操作分配");
        }
        
        // 创建分配记录
        TaskAssignment assignment = new TaskAssignment();
        assignment.setTaskId(taskId);
        assignment.setCreatorId(creatorId);
        assignmentMapper.insert(assignment);
        
        // 更新创作者负载
        creatorProfileMapper.incrementWorkload(creatorId, 
            taskMapper.getEstimatedHours(taskId));
    }
}
```
