> 版本：v1.0　　创建日期：2026-05-30　　负责人：后端架构组

---

## 1. 概述

### 1.1 背景

学习时长是 PrimeTop 中被最广泛引用的核心指标之一：

| 消费方 | 用途 |
|--------|------|
| 学情分析 | 日/周/月学习时长统计、趋势图 |
| 家长中心 | 每日使用时长监控、超时提醒、时长限额管控 |
| 学习规划 | 每日任务完成判定（"学习 30 分钟"类型任务） |
| 打卡/成就系统 | 连续学习天数、累计时长里程碑、学习勋章 |
| AI 辅导 | 判定用户是否长时间无交互，触发关怀提示 |
| 运营后台 | 全站学习时长报表、分学段时长对比 |
| 防沉迷 | 累计使用时长达到阈值后强制休息 |

然而"APP 在前台 ≠ 正在学习"。如果只按 APP 前台时间统计，用户可能：
- 把 APP 挂后台后切回来（前台但不活跃）
- 长时间停留在某个页面不做任何操作（挂机刷时长）
- 利用自动化脚本模拟心跳（作弊）

本引擎的目标是：**以合理的精度和成本，区分"有效学习时间"和"无效挂机时间"，为上层业务提供可信的时长数据。**

### 1.2 设计目标

1. **准确性**：有效学习时长误差控制在 ±5% 以内。
2. **实时性**：统计延迟不超过 30 秒即可用于实时展示（当日累计）。
3. **防刷**：识别并过滤常见挂机/作弊行为。
4. **低功耗**：客户端心跳间隔不低于 30 秒，不过度消耗电量和流量。
5. **可审计**：所有原始事件可追溯，支持回放和纠偏。
6. **模块化**：独立服务，通过事件总线与其他模块解耦。

### 1.3 术语定义

| 术语 | 含义 |
|------|------|
| Learning Session（学习会话） | 用户从打开 APP 到关闭（或切到后台超时）的一次连续使用周期 |
| Heartbeat（心跳） | 客户端周期性上报的存活信号，携带当前页面和交互状态 |
| Active Event（活跃事件） | 用户主动操作产生的行为事件（点击、滑动、输入、语音等） |
| Valid Duration（有效时长） | 经引擎判定为真实学习行为的时间段累加 |
| Raw Duration（原始时长） | APP 前台驻留的绝对时间 |
| Idle Threshold（空闲阈值） | 超过此时间无活跃事件则判定为空闲（默认 120 秒） |
| Heartbeat Gap（心跳间隙） | 两次心跳之间的时间间隔（默认 30 秒） |

## 4. 会话状态机

### 4.1 状态定义

```
                         ┌───────────────┐
          APP启动/切回前台  │               │  用户退出/切后台超时
           ┌──────────────▶│   ACTIVE      │──────────┐
           │              │   (活跃)      │          │
           │              └───────┬───────┘          │
           │                      │                  │
           │           空闲超时     │      收到心跳     │  ▼
           │           (120s无事件) │   (重新激活)     │ ┌──────────────┐
           │                      ▼                  └─▶│   ENDED      │
           │              ┌───────────────┐            │   (已结束)    │
           │              │   IDLE        │            └──────────────┘
           │              │   (空闲)      │                 ▲
           │              └───────┬───────┘                 │
           │                      │                         │
           │           空闲超时(600s)│   用户退出/切后台超时     │
           │           或会话超时    └─────────────────────────┘
           │                                             │
           └─────────────────────────────────────────────┘
                    (APP重新启动，创建新会话)
```

### 4.2 状态转换规则

| 当前状态 | 触发事件 | 目标状态 | 处理逻辑 |
|---------|---------|---------|---------|
| — | APP启动/切回前台 | ACTIVE | 创建新会话，记录 started_at |
| ACTIVE | 收到心跳（有活跃事件） | ACTIVE | 更新 last_heartbeat，累加有效时长 |
| ACTIVE | 收到心跳（无活跃事件且超120s） | IDLE | 标记空闲开始时间 |
| ACTIVE | 会话超时（15分钟无心跳） | ENDED | 以 end_reason=4 结束会话 |
| ACTIVE | 用户退出/APP切后台 | ENDED | 以 end_reason=1 结束会话 |
| IDLE | 收到心跳（有活跃事件） | ACTIVE | 恢复活跃，空闲期间不计入有效时长 |
| IDLE | 空闲超过 10 分钟 | ENDED | 以 end_reason=2 结束会话 |
| ENDED | — | — | 终态，不再处理心跳 |

### 4.3 会话超时参数

| 参数 | 值 | 说明 |
|------|---|------|
| HEARTBEAT_INTERVAL | 30 s | 客户端心跳发送间隔 |
| HEARTBEAT_TIMEOUT | 90 s | 3 个心跳周期未收到视为超时 |
| IDLE_THRESHOLD | 120 s | 2 分钟无活跃事件视为空闲 |
| IDLE_MAX_DURATION | 600 s | 空闲 10 分钟自动结束会话 |
| SESSION_MAX_DURATION | 14400 s | 单次会话最长 4 小时（防沉迷硬上限） |

## 6. 核心算法

### 6.1 有效时长计算算法

每次收到心跳时执行：

```python
def on_heartbeat(session, hb_event):
    """
    session: 当前会话状态 (从 Redis 读取)
    hb_event: 本次心跳事件
    """
    now = server_now()
    interval = now - session.last_heartbeat  # 距上次心跳的时间差(秒)
    
    # ---- 基础校验 ----
    if interval < 5:
        # 心跳过于密集，忽略（防刷）
        return
    
    if interval > HEARTBEAT_TIMEOUT:
        # 心跳丢失过久，结束旧会话，创建新会话
        end_session(session, reason="heartbeat_timeout")
        return create_new_session(hb_event)
    
    # ---- 有效时长计算 ----
    is_active = (
        hb_event.active_events > 0
        or hb_event.scroll_offset is not None
        or hb_event.screen_on == False  # 屏幕关闭不计有效时长
    )
    
    if session.status == "ACTIVE":
        if is_active:
            # 全额计入有效时长
            valid_increment = min(interval, HEARTBEAT_INTERVAL + 10)  # 上限40s
            session.valid_duration_s += valid_increment
            session.raw_duration_s += valid_increment
        else:
            # 无活跃事件 → 检查是否进入空闲
            idle_time = now - session.last_active_event_time
            if idle_time > IDLE_THRESHOLD:
                session.status = "IDLE"
                session.idle_started_at = now
            else:
                # 空闲时间不足阈值，仍计入有效时长（宽容期）
                session.valid_duration_s += min(interval, HEARTBEAT_INTERVAL + 10)
                session.raw_duration_s += min(interval, HEARTBEAT_INTERVAL + 10)
    
    elif session.status == "IDLE":
        if is_active:
            # 从空闲恢复活跃
            session.status = "ACTIVE"
            session.last_active_event_time = now
            # 恢复后的第一个心跳才开始计有效时长
            session.raw_duration_s += interval  # 原始时长照算
        else:
            # 仍在空闲
            session.idle_duration_s += interval
            session.raw_duration_s += interval
            
            # 空闲超过上限 → 结束会话
            if now - session.idle_started_at > IDLE_MAX_DURATION:
                end_session(session, reason="idle_timeout")
                return
    
    # ---- 更新上下文 ----
    session.last_heartbeat = now
    if is_active:
        session.last_active_event_time = now
        # 更新主要场景（停留最久的场景）
        update_primary_scene(session, hb_event)
    
    # ---- 写入 ----
    save_session_to_redis(session)
    save_heartbeat_event(hb_event)
    update_daily_cache(session.user_id, today(), valid_increment_or_zero)
```

### 6.2 每日时长聚合

**实时聚合（当日）：**
- 每次心跳处理时，同步更新 Redis 中 `ld:daily:{userId}:{date}` 的 validDuration
- 客户端查询当日时长时直接读 Redis，延迟 < 10ms

**终算（T+1）：**
- 次日凌晨 02:00 由定时任务触发
- 从 `learning_sessions` 表读取前一天所有已结束会话，重新计算精确时长
- 更新 `learning_duration_daily` 表，标记 `is_finalized = 1`
- 终算结果与实时缓存不一致时，以终算为准，并发出校准事件

```python
def daily_finalize(target_date):
    """T+1 终算任务"""
    users = get_active_users_on_date(target_date)
    
    for user_id in users:
        sessions = get_sessions(user_id, target_date)
        
        # 过滤无效会话
        valid_sessions = [s for s in sessions if s.is_valid and s.cheat_score < 50]
        
        raw_total = sum(s.raw_duration_s for s in sessions)
        valid_total = sum(s.valid_duration_s for s in valid_sessions)
        
        scene_breakdown = aggregate_by_scene(valid_sessions)
        subject_breakdown = aggregate_by_subject(valid_sessions)
        
        upsert_daily_summary(
            user_id=user_id,
            date=target_date,
            raw_duration_s=raw_total,
            valid_duration_s=valid_total,
            session_count=len(sessions),
            scene_breakdown=scene_breakdown,
            subject_breakdown=subject_breakdown,
            is_finalized=True
        )
        
        # 发布终算完成事件
        emit_event("learning.duration.finalized", {
            "userId": user_id,
            "date": target_date,
            "validDuration": valid_total
        })
```

### 7.1 规则列表

| 规则编码 | 规则名称 | 检测逻辑 | 置信度 | 动作 |
|---------|---------|---------|--------|------|
| `HB_FREQ_ANOMALY` | 心跳频率异常 | 同一小时内心跳数 > 正常值的 3 倍（>180次/小时） | 70 | 标记 flag |
| `HB_TIME_SKEW` | 客户端时间偏差 | clientTs 与 serverTs 偏差 > 30s，且多次出现 | 60 | 标记 flag |
| `ZERO_ACTIVITY` | 零活跃事件会话 | 整个会话所有心跳的 activeEvents 均为 0 | 85 | 标记 warn |
| `SCENE_FREEZE` | 场景冻结 | 场景持续不变且无滚动偏移变化，超过 30 分钟 | 75 | 标记 warn |
| `MULTI_DEVICE` | 多设备同时会话 | 同一用户在 2+ 设备上有活跃会话 | 90 | 保留最新设备，标记 flag |
| `OVERNIGHT_MARATHON` | 深夜马拉松 | 凌晨 0:00-5:00 单次会话 > 2 小时 | 60 | 标记 flag（可能家长未管控） |
| `RAPID_SCENE_SWITCH` | 快速场景切换 | 10 分钟内切换场景 > 20 次 | 50 | 标记 flag |
| `PERFECT_PATTERN` | 完美心跳模式 | 心跳间隔标准差 < 1s（机器发送特征） | 95 | 会话标记为无效 |

### 7.2 作弊评分

每条规则命中后累加作弊分数：

```python
def calculate_cheat_score(session):
    score = 0
    records = get_anti_cheat_records(session.id)
    
    for record in records:
        weight = RULE_WEIGHTS[record.rule_code]  # 每条规则有不同权重

```

**阈值判定：**

| cheat_score | 判定 | 动作 |
|-------------|------|------|
| 0 - 30 | 正常 | 正常计入有效时长 |
| 31 - 60 | 可疑 | 计入有效时长但标记，不参与排行榜 |
| 61 - 100 | 作弊 | 会话标记为无效（is_valid=0），不计入有效时长 |

```dart
/// 学习时长管理器 — 全局单例
class LearningDurationManager {
  static final LearningDurationManager _instance = LearningDurationManager._();
  static LearningDurationManager get instance => _instance;
  
  final HeartbeatSender _heartbeatSender;
  final ActivityTracker _activityTracker;
  final SessionManager _sessionManager;

  Timer? _heartbeatTimer;
  String _currentScene = 'unknown';
  String _currentSubject = '';

  DateTime? _lastActionTime;
  
  LearningDurationManager._()
    : _heartbeatSender = HeartbeatSender(),
      _activityTracker = ActivityTracker(),
      _sessionManager = SessionManager();
  
  /// APP 启动时调用
  Future<void> onAppStart() async {
    // 1. 创建/恢复会话
    final session = await _sessionManager.createOrResume();
    _currentSessionId = session.sessionId;
    
    // 2. 启动活跃事件监听
    _activityTracker.startListening(_onUserActivity);
    
    // 3. 启动心跳定时器
    _heartbeatTimer = Timer.periodic(
      Duration(seconds: 30),
      (_) => _sendHeartbeat(),
    );
    
    // 4. 注册 APP 生命周期回调
    WidgetsBinding.instance.addObserver(this);
  }
  
  /// 用户操作回调
  void _onUserActivity(ActivityEvent event) {
    _activeEventsSinceLastHb++;
    _lastActionTime = DateTime.now();
  }
  
  /// 发送心跳
  Future<void> _sendHeartbeat() async {
    if (_currentSessionId == null) return;
    
    final heartbeat = HeartbeatRequest(
      sessionId: _currentSessionId!,
      clientTs: DateTime.now(),
      scene: _currentScene,
      subject: _currentSubject,
      activeEvents: _activeEventsSinceLastHb,
      lastActionTs: _lastActionTime,
      scrollOffset: _activityTracker.currentScrollOffset,
      screenOn: await ScreenDetector.isScreenOn,
      batteryLevel: await BatteryProvider.level,
      networkType: await NetworkProvider.type,
    );
    
    // 重置计数器
    _activeEventsSinceLastHb = 0;
    
    try {
      final response = await _heartbeatSender.send(heartbeat);
      
      // 处理服务端返回的状态
      if (response.status == 'ended') {
        // 服务端已终止会话，需要重新创建
        await _handleSessionEnded(response);
      }
    } catch (e) {
      // 心跳失败不阻塞，记录日志
      debugPrint('Heartbeat failed: $e');
      // 弱网时缓存到本地，下次心跳时附带
      _cacheOfflineHeartbeat(heartbeat);
    }
  }
  
  /// 场景切换（由各业务模块调用）
  void onSceneChanged(String scene, {String subject = ''}) {
    _currentScene = scene;
    _currentSubject = subject;
  }
  
  /// APP 切到后台
  @override
  void didChangeAppLifecycleState(AppLifecycleState state) {
    if (state == AppLifecycleState.paused) {
      _heartbeatTimer?.cancel();
      _sendEndSession(reason: 1); // 立即结束会话
    } else if (state == AppLifecycleState.resumed) {
      onAppStart(); // 重新创建会话
    }
  }
}
```

```dart
    _emit(ActivityEvent(type: 'tap', detail: elementId));
  }
  
  /// 由全局 TextInputHandler 自动调用
  void recordInput() {
    _emit(ActivityEvent(type: 'input', detail: ''));

  int get currentScrollOffset => _scrollOffset;
  DateTime? get lastActivityTime => _lastActivityTime;
  
  void _emit(ActivityEvent event) {
    _lastActivityTime = DateTime.now();
    for (final listener in _listeners) {
      listener(event);
    }
  }
}
```

## 9. 服务端核心代码示例

### 9.1 心跳处理 Service（Java/Spring Boot 风格）

```java
@Service
@Slf4j
public class LearningDurationService {
    
    @Autowired
    private SessionRedisRepository sessionRedis;
    
    @Autowired
    private HeartbeatEventRepository heartbeatRepo;
    
    @Autowired
    private DailyDurationCache dailyCache;
    
    @Autowired
    private AntiCheatEngine antiCheatEngine;
    
    @Autowired
    private ApplicationEventPublisher eventPublisher;
    
    private static final int HB_INTERVAL_S = 30;
    private static final int HB_TIMEOUT_S = 90;
    private static final int IDLE_THRESHOLD_S = 120;
    private static final int IDLE_MAX_S = 600;
    
    /**
     * 处理心跳上报
     */
    @Transactional
    public HeartbeatResponse handleHeartbeat(Long userId, HeartbeatRequest req) {
        // 1. 从 Redis 获取当前会话
        SessionState session = sessionRedis.getSession(userId);
        
        if (session == null || !session.getSessionId().equals(req.getSessionId())) {
            return HeartbeatResponse.error(40001, "会话无效或已过期");
        }
        
        if (session.getStatus() == SessionStatus.ENDED) {
            return HeartbeatResponse.error(40003, "会话已结束");
        }
        
        // 2. 时间校验
        long clientServerSkew = Math.abs(
            Duration.between(req.getClientTs(), Instant.now()).getSeconds()
        );
        if (clientServerSkew > 30) {
            // 记录时间偏差（可能作弊信号）
            antiCheatEngine.recordTimeSkew(userId, session.getSessionId(), clientServerSkew);
        }
        
        // 3. 计算时间差
        Instant now = Instant.now();
        long intervalSeconds = Duration.between(session.getLastHeartbeat(), now).getSeconds();
        
        // 3a. 心跳丢失过久
        if (intervalSeconds > HB_TIMEOUT_S) {
            endSession(session, EndReason.HEARTBEAT_LOST);
            return HeartbeatResponse.error(40003, "心跳超时，会话已结束");
        }
        
        // 4. 计算有效时长增量
        boolean isActive = req.getActiveEvents() > 0 
            || req.getScrollOffset() != null
            || !req.isScreenOn() == false;  // 屏幕关闭 = 不活跃
        
        long validIncrement = 0;
        
        if (session.getStatus() == SessionStatus.ACTIVE) {
            if (isActive) {
                validIncrement = Math.min(intervalSeconds, HB_INTERVAL_S + 10);
                session.addValidDuration(validIncrement);
                session.updateLastActiveEvent(now);
            } else {
                long idleTime = Duration.between(session.getLastActiveEventTime(), now).getSeconds();
                if (idleTime > IDLE_THRESHOLD_S) {
                    session.setStatus(SessionStatus.IDLE);
                    session.setIdleStartedAt(now);
                } else {
                    // 宽容期内仍计有效时长
                    validIncrement = Math.min(intervalSeconds, HB_INTERVAL_S + 10);
                    session.addValidDuration(validIncrement);
                }
            }
            session.addRawDuration(Math.min(intervalSeconds, HB_INTERVAL_S + 10));
            
        } else if (session.getStatus() == SessionStatus.IDLE) {
            session.addRawDuration(Math.min(intervalSeconds, HB_INTERVAL_S + 10));
            session.addIdleDuration(Math.min(intervalSeconds, HB_INTERVAL_S + 10));
            
            if (isActive) {
                session.setStatus(SessionStatus.ACTIVE);
                session.updateLastActiveEvent(now);
            } else if (Duration.between(session.getIdleStartedAt(), now).getSeconds() > IDLE_MAX_S) {
                endSession(session, EndReason.IDLE_TIMEOUT);
                return HeartbeatResponse.ended(session.getSessionId());
            }
        }
        
        // 5. 更新会话状态
        session.setLastHeartbeat(now);
        session.updateScene(req.getScene(), req.getSubject());
        
        // 6. 作弊检测
        antiCheatEngine.check(userId, session, req);
        
        // 7. 持久化
        sessionRedis.saveSession(session);
        heartbeatRepo.saveAsync(toEntity(req, session));  // 异步写入心跳事件
        
        // 8. 更新当日缓存
        if (validIncrement > 0) {
            dailyCache.incrementValidDuration(userId, LocalDate.now(), validIncrement);
        }
        dailyCache.incrementRawDuration(userId, LocalDate.now(), 
            Math.min(intervalSeconds, HB_INTERVAL_S + 10));
        
        // 9. 检查防沉迷
        long todayValid = dailyCache.getValidDuration(userId, LocalDate.now());
        int dailyLimit = getUserDailyLimit(userId); // 从用户配置读取
        
        return HeartbeatResponse.success(
            session.getSessionId(),
            session.getStatus(),
            todayValid,
            dailyLimit,
            Math.max(0, dailyLimit - todayValid)
        );
    }
    
    /**
     * 结束会话
     */
    public void endSession(SessionState session, EndReason reason) {
        session.setStatus(SessionStatus.ENDED);
        session.setEndedAt(Instant.now());
        session.setEndReason(reason);
        
        // 计算最终作弊评分
        int cheatScore = antiCheatEngine.calculateCheatScore(session.getSessionId());
        session.setCheatScore(cheatScore);
        session.setIsValid(cheatScore <= 60);
        
        // 持久化到 MySQL
        sessionRepo.updateSession(session);
        
        // 清除 Redis
        sessionRedis.deleteSession(session.getUserId());
        
        // 发布事件
        eventPublisher.publishEvent(new SessionEndedEvent(
            session.getUserId(),
            session.getSessionId(),
            session.getValidDurationSeconds(),
            session.getRawDurationSeconds(),
            cheatScore,
            session.getIsValid()
        ));
    }
}
```

### 9.2 作弊检测引擎

```java
@Component
public class AntiCheatEngine {
    
    @Autowired
    private AntiCheatRuleRepository ruleRepo;
    
    @Autowired
    private RedisTemplate<String, String> redis;
    
    private static final Map<String, Double> RULE_WEIGHTS = Map.of(
        "HB_FREQ_ANOMALY", 15.0,
        "HB_TIME_SKEW", 10.0,
        "ZERO_ACTIVITY", 25.0,
        "SCENE_FREEZE", 20.0,
        "MULTI_DEVICE", 30.0,
        "OVERNIGHT_MARATHON", 10.0,
        "RAPID_SCENE_SWITCH", 8.0,
        "PERFECT_PATTERN", 30.0
    );
    
    /**
     * 逐条规则检测
     */
    public void check(Long userId, SessionState session, HeartbeatRequest hb) {
        // 心跳频率异常
        String freqKey = "ld:hb:count:" + userId + ":" + LocalDateTime.now().getHour();
        Long hbCount = redis.opsForValue().increment(freqKey);
        redis.expire(freqKey, Duration.ofHours(2));
        if (hbCount != null && hbCount > 180) {
            record(userId, session.getSessionId(), "HB_FREQ_ANOMALY", 70, 
                Map.of("hbCount", hbCount));
        }
        
        // 零活跃事件
        if (hb.getActiveEvents() == 0 && session.getValidDurationSeconds() > 0) {
            long consecutiveZeroHb = session.incrementAndGetZeroHbCount();
            if (consecutiveZeroHb >= 4) {  // 连续4次心跳无事件 (2分钟)
                record(userId, session.getSessionId(), "ZERO_ACTIVITY", 85,
                    Map.of("consecutiveZeroHb", consecutiveZeroHb));
            }
        }
        
        // 场景冻结
        if (hb.getScene().equals(session.getLastScene()) 
            && hb.getScrollOffset() != null 
            && hb.getScrollOffset().equals(session.getLastScrollOffset())) {
            long frozenMinutes = session.incrementAndGetSceneFrozenMinutes();
            if (frozenMinutes >= 30) {
                record(userId, session.getSessionId(), "SCENE_FREEZE", 75,
                    Map.of("frozenMinutes", frozenMinutes, "scene", hb.getScene()));
            }
        }
        
        // 深夜马拉松
        int hour = LocalDateTime.now().getHour();
        if (hour >= 0 && hour < 5 && session.getRawDurationSeconds() > 7200) {
            record(userId, session.getSessionId(), "OVERNIGHT_MARATHON", 60,
                Map.of("duration", session.getRawDurationSeconds(), "hour", hour));
        }
        
        // 完美心跳模式 — 检查最近10次心跳间隔的标准差
        List<Long> recentIntervals = session.getRecentHbIntervals(10);
        if (recentIntervals.size() >= 10) {
            double stdDev = calculateStdDev(recentIntervals);
            if (stdDev < 1.0) {
                record(userId, session.getSessionId(), "PERFECT_PATTERN", 95,
                    Map.of("stdDev", stdDev));
            }
        }
    }
    
    private void record(Long userId, Long sessionId, String ruleCode, 
                       int confidence, Map<String, Object> detail) {
        AntiCheatRecord record = new AntiCheatRecord();
        record.setUserId(userId);
        record.setSessionId(sessionId);
        record.setRuleCode(ruleCode);
        record.setRuleName(ruleCode); // 实际中从规则表读取
        record.setConfidence(confidence);
        record.setDetail(JsonUtils.toJson(detail));
        record.setActionTaken(confidence >= 90 ? "discard" : 
                             confidence >= 70 ? "warn" : "flag");
        ruleRepo.save(record);
    }
    
    public int calculateCheatScore(Long sessionId) {
        List<AntiCheatRecord> records = ruleRepo.findBySessionId(sessionId);
        double score = 0;
        for (AntiCheatRecord r : records) {
            score += RULE_WEIGHTS.getOrDefault(r.getRuleCode(), 10.0) 
                   * (r.getConfidence() / 100.0);
        }
        return (int) Math.min(100, Math.round(score));
    }
}
```

## 11. 定时任务

| 任务 | Cron 表达式 | 说明 |
|------|------------|------|
| 会话超时扫描 | `0 */2 * * * *` | 每 2 分钟扫描 Redis 中超时会话并关闭 |
| 当日聚合预计算 | `0 */5 * * * *` | 每 5 分钟将 Redis 累计值同步到 MySQL |
| T+1 终算 | `0 0 2 * * *` | 每日凌晨 2 点终算前一天数据 |
| 作弊记录清理 | `0 0 4 * * *` | 清理 90 天前的作弊检测记录 |
| 心跳事件归档 | `0 0 3 * * *` | 将 30 天前的心跳事件迁入 ClickHouse |
| 月度汇总 | `0 30 2 1 * *` | 每月 1 日生成上月汇总 |

### 11.1 超时扫描任务

```java
@Scheduled(fixedRate = 120_000) // 每 2 分钟
public void scanTimeoutSessions() {
    // 扫描 Redis 中 lastHeartbeat 超过 90 秒的会话
    List<SessionState> timedOut = sessionRedis.scanTimedOutSessions(90);
    
    for (SessionState session : timedOut) {
        try {
            endSession(session, EndReason.HEARTBEAT_LOST);
            log.info("Session timed out: userId={}, sessionId={}", 
                session.getUserId(), session.getSessionId());
        } catch (Exception e) {
            log.error("Failed to end timed out session: {}", session.getSessionId(), e);
        }
    }
}
```

## 12. 性能与容量规划

### 12.1 读写量估算

| 指标 | 估算值 | 说明 |
|------|--------|------|
| DAU | 100,000 | MVP 阶段 |
| 同时在线 | 30,000 | DAU × 30% |
| 每秒心跳 QPS | 1,000 | 30,000 / 30s |
| 每日心跳事件数 | 86,400,000 | 30,000 × 30s × 8h × 3600/30 |
| 每日会话数 | ~150,000 | 人均 1.5 次 |
| 单次心跳处理耗时 | < 5 ms | Redis 读写 + 内存计算 |

### 12.2 存储估算

| 数据 | 单条大小 | 日增量 | 月增量 |
|------|---------|--------|--------|
| 心跳事件 | ~300 B | ~26 GB | ~780 GB |
| 会话记录 | ~500 B | ~75 MB | ~2.3 GB |
| 每日汇总 | ~1 KB | ~100 MB | ~3 GB |
| 作弊记录 | ~400 B | ~10 MB | ~300 MB |

**建议：**
- 心跳事件表按月分区，3 个月后归档到 ClickHouse
- Redis 内存预估：30,000 活跃会话 × 1 KB ≈ 30 MB，加上每日缓存约 50 MB
- MySQL 会话和汇总表保留 2 年在线，更早的归档

### 12.3 优化手段

1. **心跳批量写入**：收集 100 条或每 2 秒批量 INSERT，减少 DB 压力
2. **Redis Pipeline**：会话状态更新和每日缓存更新用 Pipeline 一次完成
3. **事件降采样**：下游消费心跳事件时，可配置采样率（如只处理每 5 个）
4. **本地缓存**：当日累计时长客户端侧也缓存一份，减少查询请求

## 13. 错误处理

### 13.1 客户端错误处理

| 场景 | 处理策略 |
|------|---------|
| 心跳发送失败（网络错误） | 缓存到本地 SQLite，下次心跳时附带最近 3 条离线心跳 |
| 服务端返回会话已结束 | 自动创建新会话，无需用户感知 |
| 服务端返回限流(429) | 延长下次心跳间隔到 60 秒 |
| 客户端时间与服务端偏差过大 | 拉取服务端时间校准本地时钟 |
| APP 非正常退出（崩溃/杀进程） | 下次启动时检测未结束的会话，调用结束接口 |

### 13.2 服务端错误处理

| 场景 | 处理策略 |
|------|---------|
| Redis 不可用 | 降级为纯 MySQL 写入，心跳频率自动降低到 60 秒 |
| MySQL 写入超时 | 心跳事件先写入本地队列（内存/磁盘），异步补录 |
| 会话状态不一致 | 以 MySQL 中的 ended_at 为准，Redis 数据定期校准 |
| 定时任务失败 | 重试 3 次，间隔 5/10/30 分钟，失败后告警 |

### 13.3 数据一致性保障

```
Redis (实时) → MySQL (持久化) → ClickHouse (归档分析)
     │                │
     └── 定期校准 ────┘
```

1. **写入链路**：心跳先写 Redis，异步批量写 MySQL
2. **校准链路**：T+1 终算时以 MySQL 为准校准 Redis 和 Daily 表
3. **容灾链路**：Redis 宕机时降级为 MySQL 直写，牺牲性能保证数据不丢

## 14. 测试要点

### 14.1 单元测试

| 测试场景 | 预期结果 |
|---------|---------|
| 正常心跳序列（30s 间隔，每次有活跃事件） | 有效时长 = 原始时长 |
| 中间有一次心跳无活跃事件（60s 内） | 宽容期内仍计有效时长 |
| 连续 5 次心跳无活跃事件 | 进入 IDLE 状态 |
| IDLE 后有活跃事件恢复 | 恢复 ACTIVE，空闲期间不计有效时长 |
| 心跳间隔 > 90s | 会话自动结束 |
| 多设备同时上报 | 保留最新设备，标记作弊 |
| 心跳间隔标准差 < 1s | 标记 PERFECT_PATTERN 规则 |

### 14.2 集成测试

| 测试场景 | 验证点 |
|---------|--------|
| 完整学习周期：启动 → 学习 30 分钟 → 退出 | 当日有效时长 ≈ 1800s (±10%) |
| 弱网环境：50% 心跳丢失 | 有效时长约为实际的一半（丢失部分不计） |
| 离线场景：断网 10 分钟后恢复 | 离线心跳补发，有效时长校准 |
| 作弊模拟：固定间隔心跳 + 零事件 | 会话被标记为作弊，有效时长不计 |
| 防沉迷触发：累计达到限额 | 收到 limit_reached 事件 |

### 14.3 压力测试

- 模拟 30,000 并发用户同时发送心跳
- 目标：P99 延迟 < 50ms，错误率 < 0.1%
- 持续压测 1 小时，验证无内存泄漏和连接池耗尽
