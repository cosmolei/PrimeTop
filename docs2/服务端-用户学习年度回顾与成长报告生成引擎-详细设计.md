# 服务端 - 用户学习年度回顾与成长报告生成引擎

> 细化日期：2026-06-09  
> 关联模块：学习报告生成与交付服务、学生成就与学习里程碑追踪引擎、学习习惯养成与打卡系统、分享与社交裂变系统

## 1. 模块概述

### 1.1 功能定位

用户学习年度回顾与成长报告生成引擎（Annual Learning Review Engine，简称 ALR）是 PrimeTop 在每年年末（12 月中下旬）为全体用户自动生成的个性化年度学习总结。其产品形态参考 Spotify Wrapped、支付宝年度账单、微信年度报告等爆款社交传播产品，以数据驱动的方式呈现用户全年的学习轨迹、成就里程碑和成长故事，并鼓励用户通过社交媒体分享传播，实现品牌曝光和新用户获客。

ALR 与常规学习报告（日报/周报/月报）的核心区别：

| 维度 | 常规学习报告 | 年度回顾报告 |
|------|-------------|-------------|
| 时间跨度 | 日/周/月 | 全年（1月1日-12月31日） |
| 数据深度 | 详细答题记录 | 聚合统计 + 趋势对比 |
| 情感色彩 | 客观、理性 | 温暖、激励、有趣 |
| 社交属性 | 较弱（家长分享为主） | 极强（朋友圈/社群传播） |
| 呈现形式 | 表格、图表为主 | 沉浸式全屏卡片、动画、数据故事 |
| AI 参与 | 生成摘要文本 | 生成个性化评语、学习故事、年度关键词 |
| 商业目标 | 学情反馈 | 用户活跃唤醒 + 社交裂变 + 会员转化 |

### 1.2 核心目标

| 目标 | 指标 |
|------|------|
| 社交传播 | 年度回顾分享率 ≥ 15%（DAU 基数） |
| 用户唤醒 | 沉默用户（30天未登录）通过年度回顾回流率 ≥ 8% |
| 品牌曝光 | 社交媒体曝光量（分享卡片被查看次数）≥ 分享数 × 50 |
| 会员转化 | 年度回顾页面会员转化率 ≥ 常规渠道 2 倍 |
| 用户满意度 | 年度回顾好评率 ≥ 90%（端内反馈） |

### 1.3 适用用户范围

| 用户类型 | 年度回顾内容 | 分享能力 |
|----------|-------------|---------|
| 学生（全年活跃） | 完整年度学习数据 + 成就 + 成长故事 | 全平台分享 |
| 学生（部分活跃） | 活跃时段学习数据 + 温暖激励 | 全平台分享 |
| 学生（新用户<30天） | 入门阶段数据 + 新起点寄语 | 全平台分享 |
| 家长 | 孩子学习年度数据 + 家庭共学回顾 | 家长圈分享 |
| 教师 | 班级年度教学数据 + 学生成长汇总 | 教师圈分享 |

## 2. 数据模型

### 2.1 年度回顾主表

```sql
CREATE TABLE annual_review (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL,                        -- 用户 ID
    review_year     SMALLINT NOT NULL,                      -- 年份，如 2026
    status          VARCHAR(20) NOT NULL DEFAULT 'pending', -- 状态：pending/aggregating/generating/ready/published/expired
    
    -- 数据聚合快照（JSONB，存储原始计算结果）
    data_snapshot   JSONB,
    
    -- 内容生成结果（JSONB，存储卡片序列）
    card_sequence   JSONB,
    
    -- 分享信息
    share_image_url VARCHAR(512),                           -- 分享主图 URL
    share_deep_link VARCHAR(512),                           -- 分享深链接
    share_count     INT NOT NULL DEFAULT 0,                 -- 被分享次数
    view_count      INT NOT NULL DEFAULT 0,                 -- 被查看次数
    
    -- 时间戳
    aggregated_at   TIMESTAMPTZ,                            -- 数据聚合完成时间
    generated_at    TIMESTAMPTZ,                            -- 内容生成完成时间
    published_at    TIMESTAMPTZ,                            -- 对用户发布时间
    first_viewed_at TIMESTAMPTZ,                            -- 用户首次查看时间
    expires_at      TIMESTAMPTZ,                            -- 过期时间（次年 3月1日）
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    CONSTRAINT uk_user_year UNIQUE (user_id, review_year)
);

CREATE INDEX idx_annual_review_status ON annual_review (status, review_year);
CREATE INDEX idx_annual_review_published ON annual_review (published_at) WHERE status = 'published';
```

**聚合 SQL 核心逻辑示例：**

```sql
-- 基础学习统计
SELECT
    l.user_id,
    SUM(l.study_duration_seconds) / 60 AS total_study_minutes,
    COUNT(DISTINCT DATE(l.created_at)) AS total_study_days,
    COUNT(a.id) AS total_questions_answered,
    AVG(CASE WHEN a.is_correct THEN 1.0 ELSE 0.0 END) AS total_correct_rate
FROM learning_sessions l
LEFT JOIN answer_records a ON a.user_id = l.user_id
    AND a.created_at >= '2026-01-01'
    AND a.created_at < '2027-01-01'
WHERE l.created_at >= '2026-01-01'
    AND l.created_at < '2027-01-01'
    AND l.user_id = ANY(:user_ids)
GROUP BY l.user_id;
```

```sql
-- 月度学习时长分布
SELECT
    user_id,
    EXTRACT(MONTH FROM created_at) AS month,
    SUM(study_duration_seconds) / 60 AS monthly_minutes
FROM learning_sessions
WHERE created_at >= '2026-01-01'
    AND created_at < '2027-01-01'
    AND user_id = ANY(:user_ids)
GROUP BY user_id, EXTRACT(MONTH FROM created_at)
ORDER BY user_id, month;
```

#### 3.6.4 发布状态变更

发布操作由 `Admin Publish Job` 触发，按批次将 `annual_review` 从 `ready` 推进到 `published`：

```
Admin Publish Job
        │
        ▼
  ┌─────────────┐
  │ 读取 ready  │
  │ 按 user_id  │
  │ 分片(batch) │
  └──────┬──────┘
         │
         ▼
  ┌─────────────┐
  │ CAS update  │
  │ status ready│
  │ → published │
  │ + published_at│
  └──────┬──────┘
         │
         ▼
  ┌─────────────┐
  │ 写 Domain   │
  │ Event Outbox│
  │ ALRPublished│
  └──────┬──────┘
         │
         ▼
  ┌─────────────┐
  │ 清除缓存    │
  │ 预热 CDN    │
  └─────────────┘
```

**批次参数：**

- 批次大小：500 用户/次
- 并发：8 worker
- 写入限速：≤ 3,000 row/s（避免 DB 主库尖刺）
- 失败重试：3 次，每次间隔 30s

#### 3.6.5 回滚方案

| 回滚级别 | 触发条件 | 动作 | 影响范围 | RTO |
|----------|----------|------|----------|-----|
| L1 单用户 | 客诉/数据错误 | 将该用户状态重置为 `ready`，重新生成 | 单用户 | 5 min |
| L2 批次 | 某批次生成异常/图片错误 | 回滚该批次至 `ready`，停止对应 worker | 批次内用户 | 15 min |
| L3 全量 | 崩溃率 >1% 或 P0 合规事故 | 全量状态重置为 `ready`，关闭入口，停止 Push | 全部 | 30 min |

**回滚 SQL（L3）：**

```sql
BEGIN;
UPDATE annual_review
   SET status = 'ready',
       published_at = NULL,
       updated_at = NOW()
 WHERE review_year = 2026
   AND status = 'published'
   AND published_at > NOW() - INTERVAL '7 days';
-- 同步清理 CDN 预渲染图缓存版本号
UPDATE annual_review_template
   SET active_version = active_version - 1
 WHERE review_year = 2026;
COMMIT;
```

### 4.4 幂等与分页约定

**幂等：**

| 操作 | 幂等键来源 | 存储 | 有效期 |
|------|------------|------|--------|
| POST /events | 请求头 `Idempotency-Key` | Redis `alr:idempotency:{key}` | 24h |
| 管理端 publish/rollback | `Idempotency-Key` + adminId + scope | Redis `alr:admin:idempotency:{key}` | 7d |
| 批处理 aggregate/generate | `batch_id` | 任务表唯一键 | 永久 |

**分页：**

- 统一页码从 1 开始；
- `pageSize` 默认 20，最大 100，超限返回 `56930`；
- 返回 `pagination.total` 为估算值（当 `>10000` 时显示 `"10000+"` 或精确值取决于 DB 执行计划）。

### 5.1 聚合查询（年度学习统计）

```sql
WITH user_year AS (
    SELECT UNNEST(:user_ids) AS user_id
)
SELECT
    u.user_id,
    COALESCE(s.total_study_minutes, 0) AS total_study_minutes,
    COALESCE(s.total_study_days, 0) AS total_study_days,
    COALESCE(a.total_questions_answered, 0) AS total_questions_answered,
    ROUND(COALESCE(a.total_correct_rate, 0), 4) AS total_correct_rate
FROM user_year u
LEFT JOIN (
    SELECT
        user_id,
        SUM(study_duration_seconds) / 60 AS total_study_minutes,
        COUNT(DISTINCT DATE(created_at)) AS total_study_days
    FROM learning_sessions
    WHERE created_at >= :year_start
      AND created_at < :year_end
      AND user_id = ANY(:user_ids)
    GROUP BY user_id
) s ON s.user_id = u.user_id
LEFT JOIN (
    SELECT
        user_id,
        COUNT(*) AS total_questions_answered,
        AVG(CASE WHEN is_correct THEN 1.0 ELSE 0.0 END) AS total_correct_rate
    FROM answer_records
    WHERE created_at >= :year_start
      AND created_at < :year_end
      AND user_id = ANY(:user_ids)
    GROUP BY user_id
) a ON a.user_id = u.user_id;
```

**月度时长分布：**

```sql
SELECT
    user_id,
    EXTRACT(MONTH FROM created_at)::INT AS month,
    SUM(study_duration_seconds) / 60 AS monthly_minutes
FROM learning_sessions
WHERE created_at >= :year_start
  AND created_at < :year_end
  AND user_id = ANY(:user_ids)
GROUP BY user_id, EXTRACT(MONTH FROM created_at)
ORDER BY user_id, month;
```

## 6. 状态机

### 6.1 年度回顾状态定义

| 状态 | 含义 | 允许的外部可见行为 |
|------|------|--------------------|
| pending | 待处理，尚未开始聚合 | 不可见 |
| aggregating | 数据聚合中 | 不可见 |
| generating | 内容/卡片/AI 评语生成中 | 不可见 |
| ready | 内容已生成，待发布 | 管理端可见，白名单可预览 |
| published | 已发布，用户可见 | 全部入口可见、可分享 |
| expired | 超过次年 3 月 1 日，已归档 | 仅支持查看静态快照（只读） |

| G11 | ready → expired | 当 expires_at 到达且未发布 | 56918 |
| G12 | published → published | 幂等重入：同 scope 重复发布不报错、不重复触发事件 | — |

## 7. 幂等性与并发规则

### 7.1 并发控制原则

| 场景 | 锁粒度 | 实现 | 超时 |
|------|--------|------|------|
| 单用户聚合 | user_id + year | Redis 分布式锁 `alr:lock:agg:{user_id}:{year}` | 10 min |
| 单用户生成 | user_id + year | Redis 分布式锁 `alr:lock:gen:{user_id}:{year}` | 20 min |
| 单用户渲染 | user_id + year | Redis 分布式锁 `alr:lock:render:{user_id}:{year}` | 5 min |
| 批量发布 | year + shard | DB 乐观锁（status CAS）+ 批处理任务去重 | — |

### 7.2 幂等规则

1. **批量任务幂等**：`batch_id` 全局唯一，任务表 `annual_review_batch_task(batch_id, job_type, year)` 唯一键约束；重复触发返回已处理结果。
2. **写事件幂等**：客户端上报 `VIEW/SHARE` 等事件必须带 `Idempotency-Key`，服务端 Redis 去重 24h。
3. **管理端发布幂等**：`Idempotency-Key` + adminId + scope 组合，7 天内重复请求返回首次结果。
4. **AI 生成幂等**：对同一 `(user_id, year, prompt_version)` 的生成结果缓存 72h，重复调用直接复用 `card_sequence`。
5. **分享图渲染幂等**：图片 URL 按 `annual/{year}/share/u_{user_id}.png` 固定命名；已存在则跳过渲染，仅刷新 CDN 缓存版本。

### 7.3 重试与补偿

| 阶段 | 失败处理 | 重试次数 | 退避 |
|------|----------|----------|------|
| 聚合 SQL | 单用户失败记录 `annual_review_error_log` | 3 | 30s/2min/5min |
| AI 评语 | 模板兜底文案；夜间任务重试 | 3 | 1min/5min/15min |
| 分享图渲染 | 失败进入死信队列，人工复核 | 5 | 指数退避，最大 30min |
| 发布 CAS | 按行重试，行级失败计入日志 | 3 | 固定 5s |

## 8. 事件 Outbox（alr.domain.events）

### 8.1 Outbox 表结构

```sql
CREATE TABLE alr_domain_event_outbox (
    id              BIGSERIAL PRIMARY KEY,
    event_id        VARCHAR(64) NOT NULL UNIQUE,           -- UUID
    event_type      VARCHAR(64) NOT NULL,                 -- 事件类型
    aggregate_type  VARCHAR(32) NOT NULL DEFAULT 'annual_review',
    aggregate_id    BIGINT NOT NULL,                      -- annual_review.id
    payload         JSONB NOT NULL,                       -- 事件载荷
    headers         JSONB DEFAULT '{}',                   -- 扩展头
    status          VARCHAR(20) NOT NULL DEFAULT 'pending', -- pending/sent/failed
    retry_count     INT NOT NULL DEFAULT 0,
    next_retry_at   TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    sent_at         TIMESTAMPTZ,

    INDEX idx_outbox_status_time (status, next_retry_at),
    INDEX idx_outbox_aggregate (aggregate_type, aggregate_id)
);
```

### 8.2 事件定义

| 事件类型 | 触发时机 | 消费者 | payload 关键字段 |
|----------|----------|--------|------------------|
| `AnnualReviewAggregated` | 单用户聚合完成 | 内容生成调度器、画像服务 | user_id, year, snapshot_version |
| `AnnualReviewGenerated` | 单用户内容生成完成 | 渲染任务队列、消息服务 | user_id, year, card_count, image_url |
| `AnnualReviewPublished` | 单用户发布完成 | 消息推送服务、分享服务、首页配置 | user_id, year, published_scope |
| `AnnualReviewViewed` | 用户首次查看 | 用户激励服务、会员转化服务 | user_id, year, source, is_first |
| `AnnualReviewShared` | 用户完成分享 | 分享裂变服务、用户增长服务 | user_id, year, channel, share_code |
| `AnnualReviewExpired` | 年度报告过期 | 归档服务、对象存储生命周期 | user_id, year |
| `AnnualReviewRollback` | 管理端回滚 | 消息服务、CDN 刷新 | user_id, year, scope, reason |

### 8.3 消费矩阵

| 下游服务 | 订阅事件 | 处理语义 | 幂等键 | 失败策略 |
|----------|----------|----------|--------|----------|
| 消息推送服务 | AnnualReviewPublished, AnnualReviewViewed | 发送 Push / 刷新未读 | event_id | 死信队列，24h 人工介入 |
| 分享服务 | AnnualReviewShared | 生成短链、统计归因 | event_id | 指数退避 5 次 |
| 用户画像服务 | AnnualReviewAggregated | 更新年度画像标签 | user_id+year+event_type | 覆盖写，天然幂等 |
| 会员转化服务 | AnnualReviewViewed | 在报告页投放会员权益 | user_id+year | 去重表 7 天 |
| 归档服务 | AnnualReviewExpired | 转冷存储、删索引 | user_id+year | 定时补偿 |

### 8.4 上游依赖事件

| 上游事件 | 来源 | ALR 用途 | 处理规则 |
|----------|------|----------|----------|

## 9. 错误码（56900-56999）

|--------|------|------|------------|
| 56900 | 500 | 内部未分类错误 | 稍后重试 |
| 56901 | 202 | 年度报告尚未生成（状态非 published/ready） | 展示「报告生成中」占位页 |
| 56902 | 404 | 年度报告不存在（未达生成条件） | 引导用户学习/或展示空状态 |
| 56903 | 403 | 无权限查看他人报告（非本人/家长/教师） | 拦截，返回首页 |
| 56904 | 410 | 年度报告已过期 | 展示过期提示，仅允许查看静态快照 |
| 56905 | 429 | 请求过于频繁（查看/分享） | 冷却提示 |
| 56906 | 422 | 年份参数非法 | 修正参数 |
| 56907 | 422 | 分享渠道非法 | 修正参数 |
| 56908 | 500 | AI 评语生成失败（已走兜底文案） | 正常展示，不弹错误 |
| 56909 | 500 | 分享图渲染失败（降级为默认图） | 正常分享，使用默认模板图 |
| 56910 | 422 | 聚合结果校验失败（data_snapshot 缺字段） | 内部错误，自动重试 |
| 56911 | 422 | 生成结果校验失败（卡片/图片缺失） | 内部错误，自动重试 |

| 56916 | 409 | 过期报告不可重新发布 | 管理端提示 |

## 10. 降级矩阵 D1-D10

| 编号 | 降级场景 | 触发条件 | 降级行为 | 用户侧表现 |
|------|----------|----------|----------|------------|
| D1 | 生成队列拥塞 | 待生成积压 >10 万 | 跳过 AI 评语，使用模板兜底 | 报告文案为通用模板，不影响查看 |
| D2 | 分享图渲染服务不可用 | 渲染失败率 >5% | 使用默认模板图 + 用户头像占位 | 分享图仍可生成，样式统一 |
| D3 | AI 服务超时 | AI 评语 P99 >3s | 超时后截断，使用模板文案 | 用户无感知，仅文案通用 |
| D4 | 数据库主库压力大 | 主库 CPU >80% | 聚合/发布任务降速 50% | 生成/发布时间延后 |
| D5 | CDN 边缘节点异常 | 图片下载失败率 >2% | 切换备用 CDN 域名 | 图片加载恢复 |
| D6 | Push 通道拥堵 | 推送队列积压 >50 万 | 延迟 Push、错峰发送 | Push 到达延后 |
| D7 | 客户端低端设备 | 内存 <2GB 或 CPU 低端 | 关闭动画、降低卡片分辨率 | 保证流畅，牺牲动效 |
| D8 | 站外分享服务异常 | 微信/QQ SDK 失败 | 降级为链接复制 + 本地保存海报 | 用户可继续分享 |
| D9 | 学习数据缺失 | 全年无学习记录 | 生成「新起点寄语」简化版 | 新用户也能查看 |
| D10 | 全链路 P0 事故 | 崩溃率 >1% 或合规风险 | 关闭全部入口，停止 Push | 年度报告入口隐藏 |

| M6 | 分享率 | 客户端 | ≥15% | <8% P2 |

### 11.2 DAU 500k 容量估算

假设 DAU=50 万，目标用户覆盖率 80%，全年活跃用户数约 40 万。

| 资源 | 估算公式 | 数值 |
|------|----------|------|
| 聚合峰值 QPS | 40 万用户 / (14 天 × 4h) ≈ 2 users/s | 低，批处理为主 |
| 生成峰值 QPS | 40 万 / (5 天 × 8h) ≈ 3 users/s | 低，AI 调用集中 |
| AI 调用总量 | 40 万 × 1（评语）+ 少量标题 | 约 40 万次 |
| 分享图存储 | 40 万 × 350KB / 80% 生成率 | 约 175 GB |
| CDN 峰值带宽 | 40 万同时查看 × 2MB / 10s ≈ 80 Gbps（理论尖峰） | 实际按 95% 错峰 ≈ 8 Gbps |
| 数据库写入峰值 | 发布日 40 万 / (2h) ≈ 56 row/s | 远低于 DB 容量 |
| Redis 峰值 | 锁 + 缓存 + 幂等 | 约 2 GB |
| 推送峰值 | 40 万 / 30min ≈ 222 msg/s | 需厂商通道预热 |

**部署建议：**

- 聚合服务：4 台 8C16G，按 user_id 分片；
- 生成服务：8 台 8C16G，每台 20 worker；
- 渲染服务：10 台 4C8G + Playwright 池（每节点 5 浏览器实例）；
- 对象存储：标准存储 30 天，之后转低频；
- CDN：全国 + 教育网节点预热，图片缓存 7 天。
