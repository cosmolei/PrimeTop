# 服务端 - 学生解题过程分步评分与过程性评价服务

> 模块负责人：待定 | 版本：1.0 | 日期：2026-06-03

---

## 1. 模块概述

### 1.1 定位

学生解题过程分步评分与过程性评价服务（Stepwise Solution Evaluation Service, SSES）是 PrimeTop 面向初中、高中学生理科学习场景的核心 P1 服务。与"理科解题步骤推导服务"负责 **AI 生成标准解题过程** 不同，本服务负责 **评估学生自己书写/输入的解题过程**——逐步判断每一步的正确性、定位错误步骤、计算部分得分、生成分步反馈。

本服务的核心价值在于：**不仅判断对错，更要告诉学生在哪一步错了、为什么错了、怎么改**。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 解题步骤分割 | 将学生提交的解题过程（文本/手写识别文本）分割为独立逻辑步骤 |
| 步骤级正确性判定 | 逐步判定每一步是否正确，标注错误类型 |
| 错误步骤精确定位 | 定位第一个错误步骤，分析错误根因 |
| 部分得分计算 | 基于步骤完成度和正确度计算过程得分（非全对/全错） |
| 步骤级反馈生成 | 为每个步骤生成针对性反馈（正确肯定 / 错误纠正 / 优化建议） |
| 解题方法质量评估 | 评估学生所选方法是否最优、是否存在更简洁解法 |
| 过程性掌握度更新 | 基于过程评估结果更新知识点掌握度（区别于只看答案对错） |
| 规范性评分 | 评分维度覆盖：逻辑完整性、计算准确性、表达规范性、方法选择 |

### 1.3 适用场景

| 场景 | 触发方式 | 说明 |
|------|---------|------|
| 练习自由作答 | 学生在练习中输入解题过程后提交 | 主动评分 |
| 错题订正 | 学生对错题重新写出解题过程 | 订正效果评估 |
| 作业批改 | 上传作业图片，OCR 提取后评分 | 批量评分 |
| 拍题追问 | 学生对 AI 解答追问"我这样解为什么不对" | 按需评估 |
| 考试模拟 | 模拟考试中大题自由作答 | 按步骤给分 |

### 1.4 与其他模块的关系

| 关联模块 | 关系 | 交互方式 |
|---------|------|---------|
| 理科解题步骤推导与模型匹配解析服务 | 上游：获取标准解题过程作为参照 | RPC 同步调用 |
| 练习答题实时批改与知识点掌握度增量更新服务 | 互补：本服务提供过程级评分，批改服务消费评分结果 | 事件发布 |
| 答案管控与渐进式提示引擎 | 上游：在提示阶段可参考本服务的步骤评估 | RPC 同步调用 |
| AI教育辅导策略引擎 | 下游：基于步骤评估结果选择辅导策略 | 事件发布 |
| 拍照图像采集与预处理引擎 | 上游：手写解题过程的 OCR 文本输入 | 消息消费 |
| 错题整理模块 | 下游：消费错误步骤定位信息丰富错因标签 | 事件发布 |
| AI-Prompt编排与场景模板系统 | 本服务消费 Prompt 模板组装评估请求 | RPC 同步调用 |
| 多模型调度与成本治理 | 本服务消费模型路由，选择评估模型 | RPC 同步调用 |
| 知识点体系与教材映射引擎 | 本服务输出步骤级知识点映射 | RPC 同步调用 |

### 1.5 适用学科与题型

| 学科 | 适用题型 | 不适用 |
|------|---------|--------|
| 数学 | 解答题、证明题、计算题、应用题 | 选择题、填空题 |
| 物理 | 计算题、实验分析题、推导证明题 | 选择题 |
| 化学 | 方程式书写、计算题、实验推断题 | 选择题 |
| 生物 | 遗传推断题、实验设计题 | 选择题 |
| 英语/语文 | 不适用 | — |

> 英语作文的步骤评估由「作文批改评分引擎」负责，不在本服务范围内。

### 2.3 数据库表设计

#### 2.3.1 解题过程评估记录表（step_evaluation_record）

```sql
CREATE TABLE step_evaluation_record (
    id                  BIGSERIAL PRIMARY KEY,
    request_id          VARCHAR(64) NOT NULL UNIQUE,           -- 评估请求ID
    student_id          BIGINT NOT NULL,                       -- 学生ID
    question_id         BIGINT NOT NULL,                       -- 题目ID
    session_id          VARCHAR(64),                           -- 学习会话ID
    scene               VARCHAR(32) NOT NULL,                  -- 场景：practice_free_answer / mistake_correction / homework / exam_simulation
    
    -- 学生提交内容
    input_type          VARCHAR(16) NOT NULL,                  -- text / handwriting_ocr
    raw_content         TEXT NOT NULL,                          -- 原始解题过程文本
    step_count          INT NOT NULL,                           -- 步骤数
    
    -- 总体评分
    total_score         DECIMAL(5,2) NOT NULL,                  -- 总得分
    full_score          DECIMAL(5,2) NOT NULL,                  -- 满分
    correctness_level   VARCHAR(48) NOT NULL,                   -- 正确性级别
    
    -- 方法评估
    method_selected     VARCHAR(64),                            -- 学生使用的方法
    method_is_optimal   BOOLEAN,                                -- 方法是否最优
    efficiency_rating   VARCHAR(16),                            -- 效率评级：EXCELLENT / GOOD / FAIR / POOR
    
    -- 过程指标
    logic_completeness  DECIMAL(3,2),                           -- 逻辑完整性 0~1
    calculation_accuracy DECIMAL(3,2),                          -- 计算准确性 0~1
    expression_normative DECIMAL(3,2),                          -- 表达规范性 0~1
    method_selection    DECIMAL(3,2),                           -- 方法选择合理性 0~1
    
    -- AI 评估元数据
    ai_model_used       VARCHAR(64),                            -- 使用的AI模型
    ai_tokens_consumed  INT,                                    -- token消耗
    evaluation_latency_ms INT,                                  -- 评估耗时(ms)
    
    -- 审计
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_ser_student ON step_evaluation_record(student_id, created_at DESC);
CREATE INDEX idx_ser_question ON step_evaluation_record(question_id, created_at DESC);
CREATE INDEX idx_ser_session ON step_evaluation_record(session_id);
CREATE INDEX idx_ser_scene ON step_evaluation_record(scene, created_at DESC);
```

#### 2.3.2 步骤评估明细表（step_evaluation_detail）

```sql
CREATE TABLE step_evaluation_detail (
    id                  BIGSERIAL PRIMARY KEY,
    record_id           BIGINT NOT NULL REFERENCES step_evaluation_record(id),
    step_index          INT NOT NULL,                            -- 步骤序号（从1开始）
    content             TEXT NOT NULL,                           -- 步骤内容
    is_correct          BOOLEAN NOT NULL,                        -- 是否正确
    correctness_type    VARCHAR(48) NOT NULL,                    -- 正确性类型
    score               DECIMAL(5,2) NOT NULL,                   -- 本步得分
    max_score           DECIMAL(5,2) NOT NULL,                   -- 本步满分
    score_penalty       DECIMAL(5,2) DEFAULT 0,                  -- 扣分
    
    -- 错误详情（仅错误步骤有值）
    error_type          VARCHAR(48),                             -- 错误类型
    error_description   TEXT,                                    -- 错误描述
    correction_hint     TEXT,                                    -- 修正提示
    
    -- AI 生成
    feedback            TEXT,                                    -- 步骤反馈文本
    knowledge_points    JSONB,                                   -- 关联知识点ID列表
    
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    UNIQUE(record_id, step_index)
);

CREATE INDEX idx_sed_record ON step_evaluation_detail(record_id, step_index);
```

#### 2.3.3 步骤级知识点掌握度更新日志（step_kp_mastery_log）

```sql
CREATE TABLE step_kp_mastery_log (
```

### 3.2 查询评估历史

**GET** `/api/v1/step-evaluation/records`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| studentId | long | 是 | 学生ID |
| questionId | long | 否 | 题目ID（查特定题目的评估记录） |
| scene | string | 否 | 场景过滤 |
| startDate | string | 否 | 起始日期 (ISO 8601) |
| endDate | string | 否 | 结束日期 (ISO 8601) |
| page | int | 否 | 页码（默认1） |
| pageSize | int | 否 | 每页数量（默认20，最大100） |

### 3.3 获取单次评估详情

**GET** `/api/v1/step-evaluation/records/{requestId}`

返回完整的评估记录，包含所有步骤明细和知识点掌握度更新日志。

### 3.4 获取题目评分模板

**GET** `/api/v1/step-evaluation/rubrics/{questionId}`

根据题目信息自动匹配评分模板并返回，用于客户端展示评分标准。

### 4.2 步骤分割与标准化（StepSplitter）

学生提交的 `rawContent` 可能是整段文本（未预分割）或 OCR 识别结果。分割规则 S1-S6：

| 规则 | 触发条件 | 动作 |
|------|---------|------|
| S1 预分割优先 | 请求已携带 steps 且每步 content 非空 | 跳过自动分割，仅做标准化 |
| S2 显式编号 | 行首匹配 `^[①-⑩]|^(\d+)[.、)]|^第[一二三四五六七八九十]+步` | 按编号切分 |
| S3 逻辑连接词 | 行首匹配 `^(因为\|由于\|又∵\|所以\|因此\|故\|则\|可得\|即\|综上)` | 在连接词前切分新步骤 |
| S4 因果换行 | 单行含 `∵...∴...` 或 `因为...所以...` 且长度>40 字 | 按因果分句切分为两个步骤 |
| S5 OCR 噪声清洗 | 连续 2 个以上空格/识别置信度<0.6 的字符块 | 归一化空白、标记 suspectSpan 交 LLM 评估时注意 |
| S6 保护合并 | 切分后单步<4 字（如「所以」「即」） | 与下一步合并，避免碎步 |

约束与守卫：

- 步骤数上限 30 步，超出返回 56312（避免超长输入撑爆评估预算）；
- 总长度上限 5000 字，超出返回 56313；
- 分割仅按形式规则，**不做语义判断**（语义判断在评估阶段），防止规则层误吞步骤；
- 标准化输出统一为 `{stepIndex, content, source}`，source ∈ `student_input / auto_split / ocr_recognized`。

### 4.3 步骤对齐算法（StepAligner）

目标：将学生步骤序列与标准步骤序列建立映射，为逐步评估提供参照锚点。对齐按置信度逐层升级，任何一层达到阈值即停止：

| 层级 | 方法 | 置信度阈值 | 成本 | 耗时预算 |
|------|------|-----------|------|---------|
| A1 归一化精确匹配 | 去空白/全半角归一/符号替换后 SimHash 相等 | 1.0 | 近零 | <1ms |
| A2 结构相似度 | 公式骨架抽取（操作符+操作数类型序列）+ 编辑距离 | ≥0.90 | 低 | <10ms |
| A3 语义向量 | 步骤文本 embedding 余弦相似度（复用向量库 1024 维通道） | ≥0.85 | 中 | ≤100ms |
| A4 LLM 对齐 | 一次性提交全步骤序列，由 LLM 输出对齐映射 JSON | ≥0.75 | 高 | ≤1200ms |

对齐结果 `alignmentMap` 元素结构：

```json
{
  "studentStepIndex": 4,
  "matchedStandardStepIndex": 3,
  "matchType": "SEMANTIC_VECTOR",
  "confidence": 0.88,
  "note": "学生使用 SAS 表述，标准步骤 3 为 AAS 判定，结论同构但判定依据不同"
}
```

裁决规则：

- 学生步骤多于标准步骤：多余步骤按 IRRELEVANT / MISSING_CONDITION / 新方法分支三种情况交 LLM 判定，不允许静默丢弃（守卫 G4）；
- 学生步骤少于标准步骤：缺失步骤计入 logicCompleteness 扣分项 `missingSteps`；
- 整体对齐置信度（全部映射的加权均值）<0.75 → 本次评估标记 `degraded=true`，步骤评估改为整体式（不分步），并在响应中明示客户端「过程结构识别置信度较低，建议检查输入完整性」。

### 4.4 步骤级评估策略（分层评估器矩阵）

| 层级 | 评估器 | 判定内容 | 输出 | 失败语义 |
|------|--------|---------|------|---------|
| L0 | 数值重算器 | 纯数值算式（四则/乘方/开方）重算比对 | 计算对错 | 无法解析→跳过交 L2，不判错 |
| L0 | 单位量纲校验器 | 物理量单位换算与量纲一致性 | 单位错误 | 无法判定→跳过交 L2 |
| L1 | 结构校验器 | 因果关系链闭合性、步骤引用（如「由①得」）有效性 | 结构缺陷清单 | 仅产生扣分依据，不单独判步错 |
| L2 | LLM 主评估器 | 逐步正确性、错误类型、错误归因、修正提示 | 完整 StepEvaluation | 超时/异常→降级整体评估（§11-D2） |

L2 LLM 评估协议（单次调用合并「评估+反馈生成」，避免二次调用浪费）：

- 输入：题目题干、标准解题步骤（含每步依据）、学生步骤序列、alignmentMap、题目元数据（学科/年级/知识点）、评分模板；
- 输出协议 V1-V5 校验：JSON Schema 校验（步骤数一致、每步含 isCorrect/correctnessType/score/feedback 字段），Schema 校验失败自动重试 1 次（temperature=0），仍失败→56317 降级整体评估；
- 评分校准：LLM 输出的步骤分需经 `ScoreNormalizer` 归一（每步分∈[0,maxScore]，总和∈[0,fullScore]），越界裁剪并记录 `score_adjusted=true`；
- 安全：学生输入先经敏感词引擎 scene=STEP_EVAL（复用教育场景敏感词过滤，≤50ms），命中高危→56311 拒绝；学生原文不出域（与供应商协议含不训练条款对齐）。

### 4.5 错误传播与首错定位

首个错误步骤 `firstErrorIndex` 之后的学生步骤按如下规则重新归类（覆盖 LLM 原始输出，属服务端权威修正）：

| 条件 | 归类 | 得分折算 |
|------|------|---------|
| 步骤内容与标准后续步骤同构，且推理本身正确 | CORRECT_LOGICALLY_DERIVED_FROM_WRONG_PREMISE | 该步满分 × 0.5 |
| 步骤依赖错误结论且推理亦错误 | 维持 LLM 判定（WRONG_*） | 按 LLM 评分 |
| 步骤引入全新独立论证分支且正确 | FULLY_CORRECT（不受首错影响） | 满分 |

> 首错定位是错题归因与错因标签的关键输入：首错步骤的 errorType 作为该错题的主错因（错题服务消费，见 §9）。

### 4.6 得分合成算法（ScoreAggregator）

```
步骤得分：stepScore_i ∈ [0, maxScore_i]，maxScore_i 由评分模板按标准步骤权重分摊

过程四维指标：
  calculationAccuracy = Σ(计算类步骤得分) / Σ(计算类步骤满分)；无计算步骤→继承历史均值（无历史=1.0 不计维度）
  logicCompleteness   = 1 - 0.6×(首错位置占比) - 0.4×(missingSteps / 标准步骤数)
  expressionNormative = 1 - 0.25×(符号误用数) - 0.25×(单位缺失数) - 0.5×(因果词缺失主步数/主步数)
  methodSelection     = LLM 方法评估映射：OPTIMAL=1.0 / GOOD=0.8 / FAIR=0.6 / POOR=0.3

总分校验：totalScore = clamp(Σ stepScore_i, [0, fullScore])，与 LLM 直接给出的总分偏差>1 分时以步骤和为准并记录 score_adjusted
```

维度分仅用于过程性评价展示与统计（§3.5），**不回写答题成绩**——练习/作业的最终成绩以判题引擎或教师批改为准（契约 R2）。

### 4.7 反馈生成约束

- 话术红线：错误反馈采用「指出位置→说明原因→给出方向」三段式，**禁止直接给出完整替代解题过程**（防代写，与答案管控引擎分级策略一致：订正场景学生已看过解析方可给完整修正）；
- 成长型话术：禁止「太笨了/这么简单都不会」类贬损词，使用白名单鼓励句式（复用激励引擎话术词库）；
- 适龄：幼儿/小学低年级学段本服务不启用（守卫 G1），反馈句式长度按学段模板约束（小学≤60 字/步，高中≤150 字/步）；
- 反馈中引用学生原文≤50 字，超出截断为「你写的第X步」指代（隐私最小化）。

### 4.8 掌握度更新边界（SSOT 裁决）

- 本服务只产出**步骤级掌握度信号**（step_kp_mastery_log 落库 + `step.evaluation.completed` 事件携带 knowledgeUpdates），**不直接写统一掌握度画像**——知识点级 SSOT 归《多渠道学习数据融合与统一知识掌握度计算引擎》（契约 R5）；
- 信号权重：过程性信号 channel=step_evaluation，融合引擎按其信号量表加权（建议低于实测答题信号、高于 AI 对话评估信号）；
- 同一题目多次评估：以最新一次有效评估为准，历史信号不回收（时间衰减由融合引擎处理）。

### 4.9 与判题引擎的权威边界

| 维度 | 判题引擎（53800 段） | 本服务（56300 段） |
|------|---------------------|-------------------|
| 适用题型 | 全题型（选择/填空/计算/主观） | 仅过程型大题（解答/证明/计算/实验分析） |
| 判定对象 | 最终答案 | 解题过程逐步 |
| 成绩权威 | 练习/作业/考试最终得分 | 过程性评价与反馈，不影响最终成绩 |
| 触发方式 | 答题提交 | 学生显式提交过程/错题订正/教师要求 |

选择题、填空题请求本服务→56303 直接拒绝（客户端不应路由至此）。

## 5. 关键代码示例

### 5.1 评估编排器（EvaluationOrchestrator）

```java
@Service
@RequiredArgsConstructor
public class EvaluationOrchestrator {

    private final StepSplitter stepSplitter;
    private final ReferenceSolutionClient referenceClient;   // 理科解题服务 REST 客户端
    private final StepAligner stepAligner;
    private final LayeredEvaluator layeredEvaluator;
    private final ScoreAggregator scoreAggregator;
    private final FeedbackComposer feedbackComposer;
    private final SsesRepository ssesRepository;
    private final OutboxPublisher outboxPublisher;
    private final IdempotencyGuard idempotencyGuard;

    @Transactional
    public StepEvaluationResult evaluate(StepEvaluationRequest req) {
        // G2 幂等闸门：clientRequestId + 内容哈希
        IdempotencyGuard.GuardResult guard = idempotencyGuard.tryAcquire(
                req.getRequestId(), req.getStudentId(), canonicalHash(req.getStudentSolution()));
        if (guard.isReplay()) {
            return guard.replayedResult();                    // 200 语义码 56307
        }
        // G3 并发互斥：同学生同题目 30s 内仅允许一个在途评估
        idempotencyGuard.assertNoInflight(req.getStudentId(), req.getQuestionId());

        // ② 分割标准化（S1-S6）
        List<StudentStep> steps = stepSplitter.split(req.getStudentSolution());

        // ③ 参照解题过程
        ReferenceSolution ref = referenceClient.fetch(req.getQuestionId())
                .orElseGet(() -> referenceClient.llmFallback(req));   // D2 降级：LLM 自生成并标 degraded

        // ④ 对齐
        AlignmentResult alignment = stepAligner.align(steps, ref.getStandardSteps());

        // ⑤⑥ 分层评估 + 错误传播
        List<StepEvaluation> evaluations = layeredEvaluator.evaluate(req, steps, ref, alignment);
        ErrorPropagation.reclassify(evaluations, alignment);   // 首错传播折算，服务端权威

        // ⑦ 得分合成
        OverallResult overall = scoreAggregator.aggregate(evaluations, ref.getRubric());

        // ⑧ 反馈生成（合并于 L2 输出，此处做话术校验）
        feedbackComposer.validateAndPolish(evaluations, overall, req.getContext().getGrade());

        // ⑨ 同事务持久化 + Outbox
        StepEvaluationRecord record = ssesRepository.saveAll(req, steps, evaluations, overall);
        outboxPublisher.publish(StepEvaluationCompletedEvent.of(record));   // sses_outbox 同事务
        idempotencyGuard.markCompleted(req.getRequestId(), record.getId());
        return record.toResult();
    }
}
```

### 5.2 步骤对齐器（StepAligner，A1-A3 快速层）

```java
@Component
public class StepAligner {

    private final EmbeddingClient embeddingClient;   // 复用向量基础设施 1024 维

    public AlignmentResult align(List<StudentStep> student, List<StandardStep> standard) {
        AlignmentResult result = new AlignmentResult();
        boolean[] usedStd = new boolean[standard.size()];
        for (StudentStep s : student) {
            // A1 归一化精确匹配
            int exact = findExact(s, standard, usedStd);
            if (exact >= 0) { result.map(s.getIndex(), exact + 1, MatchType.EXACT, 1.0); usedStd[exact] = true; continue; }
            // A2 结构相似度（公式骨架编辑距离）
            int structural = bestByStructure(s, standard, usedStd);
            if (structural.score >= 0.90) { result.map(s.getIndex(), structural.idx + 1, MatchType.STRUCTURAL, structural.score); usedStd[structural.idx] = true; continue; }
            // A3 语义向量
            int semantic = bestByEmbedding(s, standard, usedStd);
            if (semantic.score >= 0.85) { result.map(s.getIndex(), semantic.idx + 1, MatchType.SEMANTIC_VECTOR, semantic.score); usedStd[semantic.idx] = true; continue; }
            result.unmapped(s.getIndex());   // 交 A4 LLM 层或标记多余步骤，禁止静默丢弃（G4）
        }
        return result;
    }
}
```

### 5.3 得分聚合器（ScoreAggregator）

```java
@Component
public class ScoreAggregator {

    public OverallResult aggregate(List<StepEvaluation> evals, ScoringRubric rubric) {
        BigDecimal total = evals.stream()
                .map(e -> e.getScore().min(e.getMaxScore()).max(BigDecimal.ZERO))
                .reduce(BigDecimal.ZERO, BigDecimal::add)
                .min(rubric.getTotalScore());                       // 越界裁剪 G8
        ProcessMetrics metrics = ProcessMetrics.builder()
                .calculationAccuracy(calcRatio(evals, Dimension.CALCULATION))
                .logicCompleteness(logicCompleteness(evals))       // 首错位置 + missingSteps
                .expressionNormative(normativeScore(evals))
                .methodSelection(methodScore(evals))
                .build();
        return OverallResult.builder()
                .totalScore(total).fullScore(rubric.getTotalScore())
                .correctnessLevel(CorrectnessLevel.from(total, rubric.getTotalScore()))
                .processMetrics(metrics)
                .scoreAdjusted(evals.stream().anyMatch(StepEvaluation::isAdjusted))
                .build();
    }
}
```

## 7. 状态机与守卫

### 7.1 评估请求状态机（内存态 + 落库镜像）

```
RECEIVED → STEP_SPLIT → REFERENCE_FETCHED → ALIGNED → EVALUATING → SCORING
    │           │              │                 │            │
    │           │              │                 │            ▼
    │           │              │                 │      FEEDBACK_GENERATING → COMPLETED(终态)
    ▼           ▼              ▼                 ▼            ▼
  FAILED(终态) FAILED        FAILED           FAILED      FAILED
```

- FAILED 为终态，失败结果同样落库（`correctness_level=NOT_EVALUABLE`）并发布事件（`status=FAILED, degraded=true`），客户端据此展示「本次评估未完成，请稍后重试」；
- 状态迁移仅在编排器主流程推进，禁止分支流程反向迁移（守卫 G6）；
- 状态镜像与评估记录同事务落 `step_evaluation_record.status` 列（v1.1 增补，见 §7.3）。

### 7.2 守卫总表

| 编号 | 守卫 | 违反后果 |
|------|------|---------|
| G1 | 学段守卫：幼儿/小学一~二年级不启用本服务（无过程性大题要求） | 56315 |
| G2 | 幂等：clientRequestId + 内容哈希唯一；同键不同内容→拒绝并 P2 告警 | 409 + 56308 |

## 8. 幂等与并发

| 场景 | 裁决 |
|------|------|
| 同 requestId 同内容重试 | 命中幂等表→返回首次结果（56307 语义，HTTP 200） |
| 同 requestId 不同内容 | 协议违规→409 + 56308，P2 告警（数据完整性异常） |
| 不同 requestId 同题同内容（双击） | 内容哈希相同且 10min 内存在完成记录→视为幂等重放返回原结果 |
| 在途评估并发提交 | Redis SET NX EX 30 互斥；在途期间重试→409 + 56308，客户端指数退避（1s/2s/4s）后查结果 |
| 取消评估 | 不提供取消：评估已消耗 LLM 成本，结果落库供查询 |
| 学生多端同时提交 | 学生级互斥（G3）天然串行化；后到达请求按「在途」处理 |
| Outbox 重复投递 | eventId 唯一键插入幂等 + 消费方 processed_events(eventId) 去重 |
| Relay 5 轮重试失败 | 进 DLQ + P2 告警；日终对账 Job 扫描 COMPLETED 记录缺事件→补发 |

## 11. 降级矩阵

| 编号 | 故障点 | 降级策略 | 用户体验 |
|------|--------|---------|---------|
