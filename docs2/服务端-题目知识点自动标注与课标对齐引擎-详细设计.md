# 服务端-题目知识点自动标注与课标对齐引擎 - 详细设计

## 1. 概述

### 1.1 功能定位

当新题目进入系统（通过 OCR 识别、AI 生成、教师手动录入等渠道），本引擎负责：
1. **自动识别**题目涉及的知识点（1~N 个）
2. **映射课标**：将知识点关联到国家课程标准的具体条目
3. **确定年级/章节对齐**：定位题目属于哪个教材版本、哪个年级、哪个章节
4. **校验难度适配性**：评估题目难度是否与所在课标位置的预期难度匹配
5. **输出置信度**：为每个标注结果提供置信度分数，低置信度的走人工审核

### 1.2 核心价值

| 场景 | 无本引擎 | 有本引擎 |
|------|---------|---------|
| 题库规模化入库 | 人工逐题标注，效率低、标准不一 | 自动标注 + 人工抽检，10x 效率提升 |
| AI 生成题目 | 生成后缺少知识点标签，难以入库复用 | 生成即标注，可直接进入推荐池 |
| 拍照搜题 | 搜到题但无法关联知识点，无法精准推荐 | 自动关联知识点，支持后续精准推荐 |
| 课标覆盖率统计 | 题库覆盖率无法统计 | 可实时统计每个课标条目的题目覆盖情况 |

### 1.3 设计原则

- **准确率优先**：宁可走人工审核，也不允许错误标注污染题库
- **可解释性**：每个标注结果附带依据和置信度，可追溯
- **课标驱动**：以国家课程标准为根，教材版本为映射层
- **持续学习**：从人工审核结果中反馈学习，持续提升自动标注准确率

## 2. 系统架构

### 2.1 整体架构

```
题目入库事件
    │
    ▼
┌─────────────────────────────────────┐
│        题目预处理 & 特征提取          │
│  (文本清洗 / 公式识别 / 图表描述)      │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│        知识点识别模块                 │
│  (LLM 标注 + 规则匹配 + 向量检索)     │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│        课标对齐模块                   │
│  (知识点 → 课标条目 → 教材章节)       │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│        难度适配校验模块               │
│  (题目难度 vs 课标位置期望难度)       │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│        结果聚合 & 置信度评估          │
│  (多路结果融合 / 置信度计算)          │
└─────────────┬───────────────────────┘
              │
         ┌────┴────┐
         │         │
    置信度 ≥ 阈值  置信度 < 阈值
         │         │
         ▼         ▼
   自动确认入库   人工审核队列
```

### 2.2 模块职责

| 模块 | 职责 | 核心技术 |
|------|------|---------|
| 题目预处理 | 清洗题目文本，提取结构化特征 | 正则、LaTeX 解析、多模态模型 |
| 知识点识别 | 识别题目涉及的知识点 | LLM + 规则引擎 + 向量检索 |
| 课标对齐 | 将知识点映射到课标条目和教材章节 | 课标知识图谱 + 教材映射表 |
| 难度适配校验 | 校验题目难度与课标位置的一致性 | 难度评估模型 + 统计检验 |
| 结果聚合 | 融合多路结果，输出最终标注 | 投票/加权融合、置信度计算 |

## 5. 核心流程详细设计

### 5.1 知识点识别流程

知识点识别采用 **三路并行 + 共识投票** 策略：

```
              题目文本
                 │
     ┌───────────┼───────────┐
     │           │           │
     ▼           ▼           ▼
  LLM 标注    规则匹配    向量检索
     │           │           │
     └───────────┼───────────┘
                 │
                 ▼
          结果融合 & 投票
                 │
                 ▼
          知识点列表（含置信度）
```

#### 5.1.1 LLM 标注路径

**Prompt 模板**：

```python
KP_ANNOTATION_PROMPT = """
你是一个教育领域专家，请分析以下题目，识别其涉及的知识点。

## 学科：{subject}
## 年级范围：{grade_hint}

## 题目内容：
{question_content}

## 可选知识点列表（从中选择最相关的）：
{candidate_kps}

## 输出要求：
请以 JSON 格式输出，包含以下字段：
- "knowledge_points": 知识点数组，每个包含：
  - "kp_name": 知识点名称（必须从候选列表中选择）
  - "is_primary": 是否为主要知识点（仅一个为 true）
  - "relevance": 相关度评分 0~1
  - "reasoning": 判断依据（一句话）

注意：
1. 最多标注 {max_kps} 个知识点
2. 只选择与题目核心考查内容直接相关的知识点
3. 如果题目涉及多个知识点的综合应用，都应标注
4. 相关度评分要严格，非核心知识点应低于 0.7
"""
```

**调用策略**：
- 使用 GPT-4o 或同等级模型（准确率优先）
- temperature=0.1（追求稳定性）
- 提供 candidate_kps 缩小选择范围（通过向量检索 Top-20 候选）

#### 5.1.2 规则匹配路径

基于预定义规则进行知识点匹配：

```python
class RuleBasedMatcher:
    """规则匹配器"""

    def __init__(self, rules_repo: KnowledgePointRuleRepository):
        self.rules = rules_repo.load_all()

    def match(self, question: Question) -> list[KPMatch]:
        matches = []

        for rule in self.rules:
            if self._evaluate_rule(rule, question):
                matches.append(KPMatch(
                    kp_id=rule.kp_id,
                    kp_name=rule.kp_name,
                    confidence=rule.confidence,
                    match_type=rule.rule_type
                ))

        return matches

    def _evaluate_rule(self, rule: KPRule, question: Question) -> bool:
        """规则评估"""
        if rule.rule_type == "KEYWORD":
            # 关键词匹配：题干中出现特定关键词
            return any(kw in question.content for kw in rule.keywords)

        elif rule.rule_type == "FORMULA":
            # 公式模式匹配：识别特定公式的出现
            return self._match_formula_pattern(rule.pattern, question.content)

        elif rule.rule_type == "QUESTION_TYPE":
            # 题型规则：如"证明题"+"三角形" → 全等三角形判定
            return (question.question_type in rule.question_types
                    and any(kw in question.content for kw in rule.context_keywords))

        return False
```

#### 5.1.3 向量检索路径

```python
class VectorKPMatcher:
    """向量检索知识点匹配"""

    def __init__(self, vector_store: VectorStore, embedding_model: EmbeddingModel):
        self.vector_store = vector_store
        self.embedding_model = embedding_model

    async def match(self, question: Question, top_k: int = 20) -> list[KPMatch]:
        # 1. 对题目文本进行向量化
        query_embedding = await self.embedding_model.embed(question.content)

        # 2. 在知识点向量库中检索最相似的
        results = await self.vector_store.search(
            collection="knowledge_points",
            query_vector=query_embedding,
            top_k=top_k,
            filter={
                "subject": question.subject_code,  # 限定同学科
            }
        )

        # 3. 转换为匹配结果
        matches = []
        for result in results:
            if result.score >= 0.6:  # 相似度阈值
                matches.append(KPMatch(
                    kp_id=result.metadata["kp_id"],
                    kp_name=result.metadata["kp_name"],
                    confidence=min(result.score, 0.95),
                    match_type="VECTOR"
                ))

        return matches
```

#### 5.1.4 结果融合算法

```python
class ConsensusFusion:
    """多路结果共识融合"""

    def fuse(self, llm_results: list[KPMatch],
             rule_results: list[KPMatch],
             vector_results: list[KPMatch]) -> list[KPAnnotation]:
        """
        融合策略：
        1. 三路都命中的 → 高置信度（CONSENSUS）
        2. 两路命中的 → 中置信度
        3. 仅单路命中的 → 低置信度，需人工确认
        """

        # 以 kp_id 为 key 聚合各路结果
        kp_scores: dict[str, KPFusionEntry] = {}

        for source, results in [("LLM", llm_results),
                                 ("RULE", rule_results),
                                 ("VECTOR", vector_results)]:
            for match in results:
                if match.kp_id not in kp_scores:
                    kp_scores[match.kp_id] = KPFusionEntry(
                        kp_id=match.kp_id,
                        kp_name=match.kp_name,
                        sources=[]
                    )
                kp_scores[match.kp_id].sources.append(
                    SourceScore(source=source, confidence=match.confidence)
                )

        # 计算融合置信度
        annotations = []
        for entry in kp_scores.values():
            source_count = len(entry.sources)
            avg_confidence = sum(s.confidence for s in entry.sources) / source_count

            # 融合置信度 = 基础置信度 × 来源加成
            if source_count >= 3:
                fusion_confidence = min(avg_confidence * 1.1, 1.0)  # 三路共识加成
                annotation_source = "CONSENSUS"
            elif source_count == 2:
                fusion_confidence = avg_confidence * 0.95
                annotation_source = "DUAL"
            else:
                fusion_confidence = avg_confidence * 0.85
                annotation_source = entry.sources[0].source

            annotations.append(KPAnnotation(
                kp_id=entry.kp_id,
                kp_name=entry.kp_name,
                confidence=round(fusion_confidence, 4),
                annotation_source=annotation_source,
                is_primary=False  # 后续决定
            ))

        # 排序并标记主要知识点
        annotations.sort(key=lambda a: a.confidence, reverse=True)
        if annotations:
            annotations[0].is_primary = True

        return annotations
```

class CurriculumAligner:
    """课标对齐器"""

    def __init__(self, kp_curriculum_repo: KPCurriculumMappingRepository,
                 textbook_mapping_repo: TextbookMappingRepository):
        self.kp_cs_repo = kp_curriculum_repo
        self.tb_repo = textbook_mapping_repo

    async def align(self, kp_annotations: list[KPAnnotation],
                    subject_code: str,
                    grade_hint: str = None) -> AlignmentResult:
        curriculum_alignments = []
        chapter_alignments = []

        for kp in kp_annotations:
            # Step 1: 知识点 → 课标条目
            cs_mappings = await self.kp_cs_repo.get_curriculum_standards(
                kp_id=kp.kp_id
            )

            for cs in cs_mappings:
                curriculum_alignments.append(CurriculumAlignment(
                    curriculum_standard_id=cs.cs_id,
                    standard_code=cs.standard_code,
                    standard_desc=cs.description,
                    alignment_type="PRIMARY" if kp.is_primary else "SECONDARY",
                    confidence=kp.confidence * cs.mapping_confidence
                ))

                # Step 2: 课标条目 → 各教材版本章节
                textbook_chapters = await self.tb_repo.get_chapters_by_curriculum(
                    cs_id=cs.cs_id,
                    subject_code=subject_code,
                    grade_code=grade_hint
                )

                for tc in textbook_chapters:
                    chapter_alignments.append(ChapterAlignment(
                        textbook_id=tc.textbook_id,
                        textbook_name=tc.textbook_name,
                        grade_code=tc.grade_code,
                        semester=tc.semester,
                        chapter_id=tc.chapter_id,
                        chapter_name=tc.chapter_name,
                        section_id=tc.section_id,
                        section_name=tc.section_name,
                        confidence=kp.confidence * tc.mapping_confidence
                    ))

        return AlignmentResult(
            curriculum_alignments=self._deduplicate(curriculum_alignments),
            chapter_alignments=self._deduplicate(chapter_alignments)
        )

### 5.3 难度适配校验

```python
class DifficultyConsistencyChecker:
    """难度一致性校验"""

    async def check(self, difficulty: DifficultyEstimate,
                    chapter_alignments: list[ChapterAlignment]) -> DifficultyEstimate:
        if not chapter_alignments:
            difficulty.is_consistent = True  # 无章节信息时不做校验
            return difficulty

        # 取最高置信度的章节对齐
        primary_chapter = max(chapter_alignments, key=lambda c: c.confidence)

        # 查询该章节在课标中的期望难度范围
        expected_range = await self._get_expected_difficulty_range(
            primary_chapter.textbook_id,
            primary_chapter.chapter_id
        )
        difficulty.expected_range = f"{expected_range.low:.1f}~{expected_range.high:.1f}"

        # 判断是否在合理范围内
        # 允许一定弹性：题目难度可以略高于章节期望（提升题）
        tolerance = 0.15
        is_consistent = (
            expected_range.low - tolerance
            <= difficulty.estimated_difficulty
            <= expected_range.high + tolerance
        )
        difficulty.is_consistent = is_consistent

        return difficulty

    async def _get_expected_difficulty_range(self, textbook_id: str,
                                              chapter_id: str) -> DifficultyRange:
        """
        查询章节的期望难度范围。
        该数据来源于：
        1. 教研组预设的章节难度参数
        2. 历史题目难度的统计分布
        """
        # 先查教研预设
        preset = await self.range_repo.get_preset(textbook_id, chapter_id)
        if preset:
            return preset

        # 回退到历史统计
        stats = await self.range_repo.get_statistics(textbook_id, chapter_id)
        if stats.count >= 10:  # 样本量足够
            return DifficultyRange(
                low=stats.p25,   # 25th percentile
                high=stats.p75    # 75th percentile
            )

        # 兜底：基于年级返回默认范围
        return DifficultyRange(low=0.2, high=0.6)
```

class AnnotationTaskConsumer:
    """标注任务消费者"""

    async def handle(self, event: AnnotationTaskCreatedEvent):
        try:
            # 1. 更新状态为 PROCESSING
            await self.task_repo.update_status(event.task_id, "PROCESSING")

            # 2. 加载题目数据
            question = await self.question_repo.get(event.question_id)
            request = await self.build_request(question, event)

            # 3. 执行标注流水线
            result = await self.pipeline.execute(request)

            # 4. 持久化结果
            await self.result_repo.save(result)

            # 5. 更新任务状态
            await self.task_repo.update_status(
                event.task_id, result.status,
                confidence=result.confidence,
                processing_ms=result.processing_ms
            )

            # 6. 发布完成事件
            await self.event_bus.publish(AnnotationTaskCompletedEvent(
                task_id=event.task_id,
                question_id=event.question_id,
                status=result.status,
                confidence=result.confidence,
                primary_kp_id=result.knowledge_points[0].kp_id if result.knowledge_points else None,
                processing_ms=result.processing_ms
            ))

        except Exception as e:
            await self.task_repo.update_status(event.task_id, "FAILED",
                                                error_message=str(e))
            # 失败重试：最多 3 次
            await self.retry_or_dead_letter(event, e)

## 8. 错误处理

### 8.1 错误分类

| 错误类型 | 错误码 | 处理策略 |
|---------|--------|---------|
| 题目内容为空 | ANN_EMPTY_CONTENT | 直接失败，不重试 |
| 学科未识别且无法推断 | ANN_SUBJECT_UNKNOWN | 走 LLM 推断，仍失败则进入人工队列 |
| LLM 调用超时 | ANN_LLM_TIMEOUT | 重试 1 次，失败降级为仅规则+向量 |
| LLM 返回格式异常 | ANN_LLM_PARSE_ERROR | 重试 1 次（调整 prompt），失败走规则+向量 |
| 向量库不可用 | ANN_VECTOR_UNAVAILABLE | 降级为 LLM+规则，不影响标注 |
| 规则库加载失败 | ANN_RULE_LOAD_ERROR | 降级为 LLM+向量 |
| 所有路径均失败 | ANN_ALL_PATHS_FAILED | 进入人工队列，标记为 FAILED |
| 并发限流 | ANN_RATE_LIMITED | 排队等待，指数退避重试 |

## 9. 性能设计

### 9.1 性能指标

| 指标 | 目标值 |
|------|--------|
| 单题标注延迟（同步） | ≤ 3s |
| 单题标注延迟（异步） | ≤ 5s（从入队到结果就绪） |
| 批量标注吞吐量 | ≥ 100 题/min |
| 知识点识别准确率（Top-3） | ≥ 90% |
| 课标对齐准确率 | ≥ 85% |
| 自动确认率（无需人工） | ≥ 70% |

### 9.2 优化策略

1. **向量缓存**：相同/相似题目的向量结果缓存，避免重复 Embedding 调用
2. **LLM 批量调用**：多题合并为一个 LLM 请求，减少调用次数
3. **规则预编译**：规则加载时编译为正则表达式，运行时 O(1) 匹配
4. **课标映射预加载**：高频学科的课标映射关系常驻内存
5. **异步并行**：三路识别完全并行，取最慢一路的耗时为总耗时
