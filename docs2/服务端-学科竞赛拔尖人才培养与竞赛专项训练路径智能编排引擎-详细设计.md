# 服务端 - 学科竞赛拔尖人才培养与竞赛专项训练路径智能编排引擎 详细设计

## 1. 概述

### 1.1 模块定位

学科竞赛拔尖人才培养引擎是 PrimeTop 平台面向学有余力、有学科特长或竞赛需求的优秀学生提供的专项训练与培养路径管理服务。区别于同步课堂和常规考点梳理，本模块聚焦于**超纲拓展、竞赛真题、奥赛级思维训练和拔尖人才早期发现**，覆盖数学、物理、化学、生物、信息学五大学科竞赛及英语/语文能力竞赛。

本模块是"因材施教"理念在拔尖维度的落地：常规学习路径追求"补短板、保下限"，竞赛培养路径追求"扬长板、冲上限"，两者共用底层能力（知识追踪、题库、学情画像），但在**选题难度、知识边界、训练强度、评估口径**上采用完全独立的策略体系。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 竞赛人才识别 | 基于日常学习数据、能力画像和测评结果，智能识别有竞赛潜力的学生 |
| 训练路径编排 | 根据竞赛类别、学生水平、备赛时间窗，生成个性化竞赛备考路径 |
| 竞赛内容管理 | 管理竞赛知识点体系、真题库、模拟题库和专项训练模块 |
| 训练过程追踪 | 追踪竞赛训练进度、能力成长和薄弱环节 |
| 竞赛模拟评估 | 提供全真模拟测试环境与成绩预测 |
| 教练匹配推荐 | 为有需要的学生匹配优质竞赛辅导资源（线上课程/推荐教练） |

### 1.3 依赖关系

```
┌─────────────────────────────────────────────────────────────────┐
│                  竞赛训练路径智能编排引擎                          │
├─────────────┬──────────────┬──────────────┬────────────────────┤
│  知识图谱服务 │  题目服务     │  学情分析    │  AI辅导服务         │
│  (竞赛知识树) │  (竞赛题库)   │  (能力画像)   │  (高难度推理)       │
├─────────────┼──────────────┼──────────────┼────────────────────┤
│  用户服务     │  学习规划服务 │  推荐服务     │  知识追踪引擎       │
│  (学生档案)   │  (备赛计划)   │  (课程推荐)   │  (能力动态评估)     │
└─────────────┴──────────────┴──────────────┴────────────────────┘
```

依赖服务的具体调用方式：

| 依赖服务 | 调用内容 | 降级策略 |
|----------|----------|----------|
| 知识追踪引擎 | 读取课内知识点掌握度，用于课标重叠部分跳级 | 不可用时按"全部从基础学"处理 |
| 题目服务 | 竞赛题检索、组卷、解析获取 | 不可用时训练任务降级为知识学习任务 |
| 学情分析 | 能力画像五维分数、学习时长基线 | 不可用时潜力评估只走专项测评 |
| AI 辅导服务 | 高难题分步讲解、证明题过程评分 | 不可用时证明题批改转人工复核队列 |
| 多源学习任务统一调度 | 训练任务需要与课内作业统一仲裁优先级 | 不可用时竞赛任务独立排期，但高峰期避让逻辑失效 |
| 防沉迷/疲劳引擎 | 训练时长需叠加疲劳度检测（竞赛训练强度高） | 不可用时按本地固定阈值限流 |

### 1.4 适用学段

| 学段 | 竞赛类型 | 说明 |
|------|----------|------|
| 小学4-6年级 | 华罗庚金杯、希望杯、走美杯等 | 数学启蒙竞赛，兴趣导向 |
| 初中7-9年级 | 全国初中数学/物理/化学联赛 | 竞赛入门，能力分化 |
| 高中10-12年级 | 全国高中数学/物理/化学/生物联赛、CSP-J/S、NOI | 核心竞赛阶段，强基/保送路径 |

### 1.5 与相关模块的边界

| 模块 | 边界说明 |
|------|----------|
| 考点梳理/备考冲刺 | 面向课标内考试（中考/高考），本模块面向超纲竞赛；`competition_question_ext.difficulty_score > 7` 的题目不进入常规考点训练池 |
| 理科解题引擎 | 本模块复用其分步推导能力，但解题模型库额外包含竞赛专属模型（如反演变换、生成函数） |
| 智能组卷引擎 | 竞赛模拟组卷由本模块内置组卷器完成（约束模型差异大），组卷完成后调用题目服务取题 |
| 学习规划服务 | 常规学习计划由规划服务管理；竞赛训练计划独立存储（`competition_training_plan`），但每日任务统一汇聚到任务调度中心展示 |

#### 2.1.1 竞赛信息表 `competition_info`


```sql

        {
            "title": "完成代数基础模块",
            "target_date": "2025-09-15",
            "criteria": {"accuracy": 0.75, "coverage": 0.90}
        }
    ]',
    daily_task_template JSON COMMENT '每日任务模板配置',
    difficulty_config JSON COMMENT '难度配置 {
        "min": 5,
        "max": 9,
        "target_avg": 7.2,
        "adaptive": true
    }',
    status ENUM('draft','active','completed','abandoned') DEFAULT 'draft',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user (user_id),
    INDEX idx_subject (subject),
    INDEX idx_dates (start_date, end_date),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='竞赛训练计划表';
```

> 说明：一张训练计划对应一个**阶段（phase）**而非整个备赛周期。整个备赛周期由多条首尾相接的计划串联，阶段晋级由里程碑校验驱动（见 6.1 状态流转）。这样设计的目的是让"动态调整"只影响当前阶段计划，历史阶段数据保留用于复盘。

## 4. 核心业务逻辑

### 4.1 竞赛潜力评估算法

评估输入分两类信号：

**（1）日常数据信号（daily_signal，被动采集）**

| 信号特征 | 来源 | 说明 |
|----------|------|------|
| 课内 Top10% 正确率 | 答题记录服务 | 目标学科课内题目正确率在同龄同学段中的分位 |
| 高难题突围率 | 答题记录服务 | difficulty ≥ 6 的课内拓展题正确率 |
| 解题速度分位 | 答题行为数据 | 单位难度用时在同年级的分位（越快越高） |
| 一题多解行为 | 答题过程行为 | 主观题中呈现多种解法路径的频率 |
| 自主拓展学习占比 | 学习行为事件 | 主动浏览超纲内容、追问"有没有更一般的情况"的比例 |
| 坚持性指标 | 学习会话数据 | 高难度题上的持续尝试时长（放弃率） |

**（2）专项测评信号（quick / full，主动触发）**

按学科从竞赛知识树 `entry` 层级抽取测评题组（quick：8 题 25 分钟；full：20 题 90 分钟），题目覆盖不同能力维度（逻辑推理、抽象思维、问题解决、计算速度、空间直觉），采用自适应出题：答对升难、答错降难，最终以作答题目的难度覆盖与正确率联合估计能力分。

**综合评分模型：**

```
overall = w1 × daily_signal_score + w2 × test_score
默认 w1=0.35, w2=0.65（无日常数据时 w2=1.0）
维度分 = 各维度题目加权得分（权重随目标竞赛类型调整，
        如数论方向竞赛上调 logic_reasoning 权重）
```

等级判定阈值（可配置）：

| overall | talent_level | 含义 |
|---------|--------------|------|
| ≥ 0.85 | elite | 顶级潜力，建议冲击国赛级目标 |
| 0.70 ~ 0.85 | advanced | 省赛获奖潜力 |
| 0.55 ~ 0.70 | developing | 可培养，联赛入门目标 |
| < 0.55 | potential | 兴趣培养为主，不建议高强度训练 |

推荐竞赛匹配分 `match_score = 0.5 × overall + 0.3 × dimension_match + 0.2 × time_window_fit`，其中 `dimension_match` 是学生维度向量与竞赛历史获奖者维度分布的余弦相似度，`time_window_fit` 评估距报名截止/考试日的时间是否充裕。

### 4.2 训练路径编排算法

编排分四步：**定目标 → 排知识 → 划阶段 → 装任务**。

**Step 1 定目标**：根据目标竞赛的 `competition_level` 与学生的 `talent_level` 确定目标层级与建议总时长：

| 学生等级 | 目标竞赛层级 | 建议总时长（小时） |
|----------|--------------|--------------------|
| developing | entry → regional | 120 ~ 180 |
| advanced | regional → national | 200 ~ 300 |
| elite | national → olympiad | 300 ~ 450 |

**Step 2 排知识（知识点学习序列）**：

1. 从竞赛知识树取出 `[学生当前层级, 目标层级]` 区间内的知识点集合 `N`。
2. 剪枝：`curriculum_overlap` 中映射的课标知识点若学生掌握度 ≥ 0.85，则标记为 `skip_review`（不安排学习任务，仅在测评中复验）。
3. 拓扑排序：以 `prerequisites` 为边做拓扑排序；环检测失败时按编辑运营配置的 `manual_order` 强制破环并告警。
4. 同层排序：拓扑同层内按 `(is_key_node DESC, focus_areas 命中 DESC, difficulty ASC)` 排序，保证主干先行、优势方向优先。

**Step 3 划阶段**：按知识点难度分布与备赛时间窗切分四阶段，每阶段占比随总时长缩放（不足 8 周时合并 foundation 与 intensive）：

| 阶段 | 知识范围 | 难度带 | 里程碑口径 |
|------|----------|--------|-----------|
| foundation | entry 层 + 少量 regional | [4,6] | 综合测评正确率 ≥ 70%，覆盖率 ≥ 90% |
| intensive | regional 层为主 | [6,8] | 专项测试正确率 ≥ 65%，覆盖率 ≥ 85% |
| sprint | national 层 + 真题 | [7,10] | 近 3 年真题正确率 ≥ 60% |
| simulation | 全真模拟 | [8,10] | 2 套全真模拟达到目标奖项等级 |

**Step 4 装任务（周计划 → 日任务）**：

每周可用时长 `weekly_hours`（用户申报，与防沉迷引擎联动上限校验）。周内任务装配规则：

```
每周结构 = 60% 知识学习+配套练习 + 25% 综合练习/真题 + 15% 复盘分析
单日上限 = min(120min, weekly_hours / 训练天数 × 1.5)
每周至少 1 个 rest/analysis 任务（防burnout硬约束）
```

单日任务序列模板：`knowledge_learn(45min) → practice(60min)` 或 `practice(90min) → analysis(30min)`；练习题由题目服务按 `(node_ids, 难度带, 目标平均难度 target_avg, 排除近期做过)` 检索，题量 = 目标用时 / 单题预估用时（`estimated_time_min`），向上取整。

### 4.3 自适应难度调节

每次任务提交后，对下一任务的目标难度做微调：

```
new_target = old_target + α × (weighted_score - 0.65) + β × (difficulty_perception - target)
约束：new_target ∈ [difficulty_config.min, difficulty_config.max]
默认 α=1.0, β=0.3（感知偏差权重较低，避免主观压难度）
```

连续 3 次 `weighted_score < 0.4`：触发**降档保护**——插入前置知识点复习任务，难度下调 2 档，并写入 `risk_flags += "struggling"`；连续 2 周 `risk_flags` 含 `struggling` 时，建议降级目标竞赛层级（推送确认，不自动降级）。

### 4.4 里程碑校验与阶段流转

阶段结束（计划到期或任务全部完成）触发复盘：

1. 汇总本阶段全部任务的 `weighted_score` 均值 → `accuracy`。
2. 已学知识点数 / 计划知识点数 → `coverage`。
3. 对照 `milestones.criteria` 逐项判定：
   - 全部通过 → `milestone_pass`，编排并创建下一阶段计划，写 `competition_stage_transition`。
   - 通过率 ≥ 60% 且关键指标差距 < 0.1 → `milestone_fail_repeat`：未通过知识点保留，生成**为期 1~2 周的补弱计划**（phase 不变，重开一张计划）。
   - 通过率 < 60% → 推送人工介入建议（教练沟通/降低目标），计划挂起为 `draft`。
4. 竞赛结束（`competition_info.status → completed`）：全部关联计划转 `completed`，档案进入 `rest`，2 周后触发赛后复盘与下赛季建议。

### 4.5 风险检测（burnout / plateau / time_conflict）

| 风险 | 检测规则 | 处置 |
|------|----------|------|
| burnout | 连续 7 天训练且日均 > 90min，或 self_rating 连续 5 次 ≤ 2 | 强制插入 rest 任务；连续触发则压缩 weekly_hours 20% 并通知家长端 |
| plateau | 同一知识点 3 次专项练习 weighted_score 波动 < 0.05 且 < 0.65 | 切换讲解策略（换题型/换方法标签）；仍无突破则标记为"瓶颈节点"，进入 AI 深度诊断 |
| time_conflict | 课内作业完成率 < 70% 或课内成绩下滑信号 | 竞赛任务降权避让（通过多源任务调度仲裁），连续 2 周未缓解则建议暂停（paused） |

### 4.6 竞赛模拟组卷与排名预估

**组卷约束求解**（贪心 + 回溯，题目规模 ≤ 20，无需复杂求解器）：

```
目标：总分 = 竞赛真实卷面结构（按 competition_info 关联的卷面模板）
约束：
  C1 每题难度 ∈ 目标层级难度带 ±1
  C2 知识点覆盖 ≥ scope_node_ids 的 80%，单知识点题数 ≤ 30%
  C3 近 30 天做过的题排除（exclude_recent）
  C4 解题方法标签多样性：同一 solution_method 最多 2 题
  C5 经典名题（classic_tag）至少 1 题且放在压轴
求解：按 seq 位置贪心选满足全部硬约束的候选；无解时按 C2→C4→C1 顺序放松软约束回溯重试
```

**排名预估**：将卷面得分率映射到历史同卷难度的成绩分布（按 `subject+level` 维护的历史获奖者得分分布表，管理后台维护），输出奖项等级与置信度；样本 < 30 人时 `rank_confidence` 封顶 0.5 并提示"预估仅供参考"。

```java
@Service
public class CompetitionTrainingPlanner {

    /**
     * 编排全周期蓝图并落库第一阶段计划
     */
    @Transactional(rollbackFor = Exception.class)
    public PlanGenerateResult generatePlan(PlanGenerateRequest req) {
        // 1. 定目标
        CompetitionInfo comp = competitionRepo.requireById(req.getTargetCompetitionId());
        TalentProfile profile = talentRepo.requireByUserId(req.getUserId());
        int targetHours = suggestTotalHours(profile.getTalentLevel(), comp);
        if (Duration.between(req.getStartDate(), req.getEndDate()).toDays() < 14) {
            throw new BizException(CompErrorCode.PLAN_WINDOW_TOO_SHORT);
        }

        // 2. 排知识
        List<KnowledgeNode> sequence = orderKnowledgeNodes(req.getSubject(),
                profile.getTalentLevel(), comp.getLevel(), req.getFocusAreas());

        // 3. 划阶段
        List<PhaseBlueprint> phases = splitPhases(sequence, req, targetHours);

        // 4. 落库：仅创建第一阶段计划 + 首周任务
        TrainingPlan firstPlan = buildPlanEntity(req, phases.get(0));
        trainingPlanRepo.insert(firstPlan);
        taskAssembler.assembleWeekTasks(firstPlan, weekRange(req.getStartDate(), 1));

        profile.setCurrentTrainingStage(Stage.FOUNDATION);
        profile.setTrainingPlanId(firstPlan.getId());
        talentRepo.update(profile);
        cacheEvictor.evictUserProfile(req.getUserId());

        return PlanGenerateResult.of(firstPlan, phases);
    }

    /** 知识点学习序列：剪枝 → 拓扑排序 → 同层排序 */
    private List<KnowledgeNode> orderKnowledgeNodes(String subject, TalentLevel level,
                                                    String targetLevel, List<String> focusAreas) {
        List<KnowledgeNode> nodes = knowledgeTreeRepo
                .findBySubjectAndLevelRange(subject, level.lowerBound(), targetLevel);
        // 剪枝：课标重叠且掌握度>=0.85 的节点只标记复验、不进学习序列
        Map<Long, Double> masteryMap = knowledgeTraceClient.batchGetCurriculumMastery(
                nodes.stream().flatMap(n -> n.getCurriculumOverlap().stream()).toList());
        Set<Long> skipReview = nodes.stream()
                .filter(n -> n.getCurriculumOverlap().stream()
                        .allMatch(cid -> masteryMap.getOrDefault(cid, 0.0) >= 0.85))
                .map(KnowledgeNode::getId).collect(toSet());
        List<KnowledgeNode> toSchedule = nodes.stream()
                .filter(n -> !skipReview.contains(n.getId())).toList();

        List<KnowledgeNode> ordered = topoSort(toSchedule); // 环检测失败时按 manualOrder 破环
        ordered.sort(withinTierComparator(focusAreas));     // 同层内：key_node > focus命中 > 难度升序
        return ordered;
    }
}
```

### 5.2 自适应难度调节

```java
@Component
public class AdaptiveDifficultyAdjuster {

    private static final double ALPHA = 1.0;   // 成绩信号权重
    private static final double BETA = 0.3;    // 感知信号权重
    private static final double TARGET_SCORE = 0.65;

    public int nextDifficulty(TaskSubmitContext ctx) {
        DifficultyConfig cfg = ctx.getPlan().getDifficultyConfig();
        double adjusted = ctx.getLastDifficulty()
                + ALPHA * (ctx.getWeightedScore() - TARGET_SCORE)
                + BETA * (ctx.getDifficultyPerception() - ctx.getLastDifficulty());
        int clamped = (int) Math.round(
                Math.max(cfg.getMin(), Math.min(cfg.getMax(), adjusted)));
        // 降档保护：连续3次低分，强制下调2档并插入复习任务
        if (ctx.getConsecutiveLowScoreCount() >= 3) {
            clamped = Math.max(cfg.getMin(), clamped - 2);
            ctx.markNeedReviewTask();
        }
        return clamped;
    }
}
```

```java
        List<CompetitionQuestion> pool = questionRepo.searchCandidates(
                req.getSubject(), req.getTargetLevelBand(), req.getExcludedQuestionIds());

        Map<Long, List<CompetitionQuestion>> byNode = groupByNode(pool);
        Map<String, Integer> methodCount = new HashMap<>();

        List<CompetitionQuestion> selected = new ArrayList<>();
        for (Slot slot : template.getSlots()) {           // 卷面槽位：序号/分值/难度带
            CompetitionQuestion best = null;
            for (CompetitionQuestion cand : candidatesFor(slot, byNode)) {
                if (violatesCoverage(cand, byNode, req)) continue;      // C2
                if (methodCount.getOrDefault(cand.topMethod(), 0) >= 2) continue; // C4
                if (slot.isFinale() && !cand.isClassic()) continue;     // C5 压轴经典题
                best = betterFit(best, cand, slot);
                if (isPerfectFit(best, slot)) break;
            }
            if (best == null) { // 硬约束无解 → 放松C2回溯重试，仍无解则降级报错
                return retryWithRelaxedCoverage(req, template, pool);
            }
            selected.add(best);
            methodCount.merge(best.topMethod(), 1, Integer::sum);
        }
        return ComposedPaper.of(selected, template);
    }
}
```

```java
@Service
public class MilestoneChecker {

    @Transactional(rollbackFor = Exception.class)
    public ReviewResult reviewPlan(Long planId, Long userId) {
        TrainingPlan plan = trainingPlanRepo.lockById(planId); // SELECT ... FOR UPDATE
        checkOwnership(plan, userId);

        Milestone ms = plan.getMilestone();
        List<CriteriaResult> details = new ArrayList<>();
        double accuracy = taskRepo.avgWeightedScore(planId);
        double coverage = taskRepo.coverageRate(planId);
        details.add(check("accuracy", accuracy, ms.getAccuracyTarget()));
        details.add(check("coverage", coverage, ms.getCoverageTarget()));

        long passedCount = details.stream().filter(CriteriaResult::isPassed).count();
        StageTransition transition;
        if (passedCount == details.size()) {                    // 全部通过 → 晋级
            TrainingPlan next = planner.generateNextStage(plan);
            transition = StageTransition.pass(plan, next);
        } else if (passedCount >= 1 && nearMiss(details)) {     // 接近达标 → 补弱重修
            TrainingPlan remedy = planner.generateRemedyPlan(plan, failedNodes(details));
            transition = StageTransition.repeat(plan, remedy);
        } else {                                                // 差距过大 → 挂起待人工
            plan.setStatus(PlanStatus.DRAFT);
            notificationClient.pushCoachIntervention(userId, planId);
            transition = StageTransition.suspended(plan);
        }
        transitionRepo.insert(transition);
        return ReviewResult.of(plan, details, transition);
    }
}
```

## 6. 状态流转

### 6.1 训练计划状态机

```
                 ┌──────────────────────────────────────────┐
                 │                                          │
   generate      ▼          review(pass)        review(repeat)
 ┌──────┐    ┌───────┐    ┌──────────┐  ┌──────────────┐    │
 │draft │───▶│active │───▶│completing│─▶│remedy_active │────┘(再次复盘)
 └──────┘    └───┬───┘    └────┬─────┘  └──────────────┘
    │            │             │
    │ abandon    │ abandon     │ review(pass)+竞赛未结束
    │            │             ▼
    │            │        ┌──────────┐  生成下一阶段计划
    │            ▼        │completed │─────▶(新计划 draft→active)
    └────────▶└──────┘◀──┘  竞赛结束/用户退出
```

| 迁移 | 触发 | 动作 |
|------|------|------|
| draft→active | 用户确认计划 | 创建首周任务、推送提醒、写审计日志 |
| active→completing | 任务全部完成或到期 | 触发里程碑复盘 |
| completing→completed | review 通过且无下一阶段 | 档案 `current_training_stage` 更新 |
| completing→remedy_active | review 未过但接近达标 | 生成补弱计划并激活 |
| active→completed（abandon） | 用户退出/竞赛结束 | 结算统计、档案回写、保留数据 |
| active→draft | 风险挂起（time_conflict 严重） | 通知家长端与教练 |

### 6.2 训练任务状态机

```
pending → in_progress → completed
   │           │            │
   │skip       │expire      │(证明题置信度低)
   ▼           ▼            ▼
skipped     expired(=failed) review_pending → completed(复核修正)
```

- `pending → skipped`：仅允许 D-1 顺延 1 次，连续 skip 2 次的任务触发计划重排建议。
- `in_progress → failed`：模拟考超时未提交、或任务开始后 48h 未提交。
- `review_pending`：AI 评分低置信转人工，复核后回写 `partial_score` 与 `accuracy_rate`。

### 6.3 模拟考试状态机

```
not_started → in_progress → submitted → graded → reviewed
                   │                        │
                   │超时自动提交             │用户查看报告
                   └──────▶ submitted       ▼
                                     (超时题0分)  reviewed(错题入库/报告已读)
```

关键规则：`in_progress` 由服务端 `deadline_at` 定时器兜底（延迟任务调度引擎注册到期事件），客户端断网重连后若已过 deadline，本地未提交作答只作草稿留存不计分。

### 6.4 培养档案阶段流转

```
assessment ⇄ foundation ⇄ intensive ⇄ sprint ⇄ simulation → rest → (下赛季)assessment
     ▲           │            │           │          │
     └───────────┴────────────┴───────────┴──────────┘
                任意阶段可 paused（风险/用户主动），恢复后回当前阶段
```

`talent_level` 独立于训练阶段，由定时任务（每赛季 1 次 + 大型模拟后即时）依据最新评估记录与模拟成绩重算，变更写审计日志并推送用户。

| 故障 | 降级行为 |
|------|----------|
| AI 辅导服务不可用 | 证明题批改全部转人工复核队列；客观题训练不受影响 |
| 知识追踪引擎不可用 | 掌握度更新写入本地补偿表，恢复后重放（事件带 `occurred_at`） |

- 生成计划 / 开始模拟 / 提交类接口要求 `Idempotency-Key`，Redis `SETNX` + 24h 过期去重。
- 任务提交接口带 `task_version`（乐观锁），重复提交返回上次结果。
- 定时重算等级任务使用分布式锁（`comp:lock:recalc:{userId}`），防止并发覆盖。

## 11. 安全与合规

1. **未成年人保护**：竞赛训练强度高，防沉迷联动为硬约束——每日训练时长计入总使用时长上限；burnout 风险强制休息；22:00 后不推送训练提醒。
2. **防焦虑设计**：排名预估默认仅自己可见，家长端不展示具体名次预测；转化文案禁用"再不学就来不及""别人家孩子已进国集"类话术（文案审核清单由合规运营维护）。
3. **数据合规**：潜力评估属未成年人画像，遵循最小必要原则；评估原始作答仅用于模型改进时需走匿名化管线（对接数据匿名化引擎）；用户可注销竞赛档案（随账户注销流程删除）。
4. **内容版权**：真题入库必须携带授权来源标识，对接内容版权管理引擎做到期下线；无授权真题禁止进入组卷池（导入管线强校验）。
5. **公平性**：潜力评估模型纳入 AI 公平性审计范围，监控城乡/性别/学段分组间的等级分布漂移，偏差超阈值触发模型复审。

## 12. 测试要点

### 12.1 单元测试

- 拓扑排序与破环逻辑（构造含环知识树用例）。
- 自适应难度调节的边界收敛（连续低分/满分场景，验证 clamp 与降档）。
- 里程碑判定三种分支（pass/repeat/suspend）的判定边界。
- 组卷约束求解：覆盖/多样性/压轴经典题约束的违反检测。

### 12.2 集成测试

- 计划生成全链路（知识树→排序→阶段切分→任务装配→落库→缓存失效）。
- 证明题 AI 评分失败→人工复核→分数回写闭环。
- 模拟考超时自动提交（延迟任务调度引擎联动）。
- 与任务调度中心的优先级仲裁（课内作业高峰避让）。

### 12.3 端到端场景

- 典型用户旅程：评估 → foundation 计划 → 训练提交 → 复盘晋级 → 模拟考 → 报告 → sprint 计划调整。
- 风险旅程：连续高强度触发 burnout → 强制休息 → 家长通知。
- 降级旅程：AI 服务宕机 30min 期间的训练提交与恢复后数据重放。

### 12.4 数据与回归

- 评估模型回归：固定学生特征集跑分对比（等级漂移 > 5% 需评审）。
- 排名预估校准：用上一赛季真实获奖数据回测映射表准确率。

## 14. 灰度与发布
