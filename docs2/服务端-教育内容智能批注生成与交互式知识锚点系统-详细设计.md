# 教育内容智能批注生成与交互式知识锚点系统 - 详细设计

## 1. 模块概述

### 1.1 功能定位

本系统负责将平台中的静态教育内容（教材章节讲解、题目解析、知识卡片、作文范文等）转化为**可交互的智能学习材料**，通过自动识别内容中的关键术语、知识点、公式和概念，生成结构化批注与知识锚点，使学生可以在阅读过程中随时获取深度解释、关联知识、前置依赖提示和即时练习。

### 1.2 核心价值

| 维度 | 价值描述 |
|------|----------|
| 学习体验 | 学生阅读讲解内容时，遇到不懂的术语可直接点击查看解释，无需跳出当前页面 |
| 知识关联 | 通过锚点将不同内容模块关联，形成网状知识结构，支持发散学习 |
| 个性化 | 根据学生学段、能力水平动态调整批注密度和解释深度 |
| 内容复用 | 同一知识锚点可被多个内容引用，修改一处即处处生效 |
| 数据采集 | 记录学生对批注的点击、展开、停留行为，为学习兴趣建模提供信号 |

### 1.3 与现有系统的关系

| 现有系统 | 关系说明 |
|----------|----------|
| 知识点体系与教材映射引擎 | 提供知识点树结构，批注锚点挂载到知识点节点 |
| 知识图谱构建与可视化交互引擎 | 锚点之间的关联关系来源于知识图谱边 |
| 教育内容审核工作流 | 批注内容同样需要经过审核管线 |
| 分龄UI适配与交互设计规范 | 批注弹窗样式按学段适配 |
| AI回答适龄化处理与学段表达适配引擎 | 批注解释文本的适龄化处理 |
| 富文本与学科内容渲染引擎 | 客户端渲染批注标记和弹窗 |
| RAG与知识库系统 | 批注生成时检索知识库获取权威解释 |

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| 批注 (Annotation) | 挂载在内容片段上的增强信息单元，包含类型、内容、元数据 |
| 锚点 (Anchor) | 批注在内容中的定位标记，由 XPath + 偏移量或 DOM 选择器确定 |
| 锚标 (Anchor Tag) | 锚点关联的知识点 ID，用于跨内容关联 |
| 批注类型 | term_definition / formula_explain / prerequisite / cross_reference / quick_check / difficulty_marker / warning |
| 批注密度 | 单位内容长度内的批注数量，受学段和用户偏好控制 |

### 2.2 服务拆分

| 子服务 | 职责 | 部署方式 |
|--------|------|----------|
| annotation-query-service | 面向客户端的批注查询接口，支持个性化过滤 | 随主应用部署 |
| annotation-generation-service | 离线/异步批注生成管线，调用 NER + AI + 知识库 | 独立 Worker |
| annotation-management-service | 批注的后台管理 CRUD、审核流程接入 | 随管理后台部署 |
| annotation-event-consumer | 消费批注交互事件（点击/展开），写入行为日志 | 独立 Consumer |

## 3. 数据结构设计

### 3.1 PostgreSQL 表结构

#### 3.1.1 批注主表 `content_annotations`

```sql
CREATE TABLE content_annotations (
    id              BIGSERIAL PRIMARY KEY,
    content_id      BIGINT       NOT NULL,              -- 关联内容ID (lessons/questions/explanations等)
    content_type    VARCHAR(32)  NOT NULL,              -- 内容类型: lesson / question_explanation / knowledge_card / essay_sample
    anchor_type     VARCHAR(16)  NOT NULL,              -- 锚点类型: xpath / css_selector / char_range
    anchor_path     TEXT         NOT NULL,              -- 锚点路径, 如 "/html/body/div[2]/p[3]"
    anchor_start    INT          NOT NULL DEFAULT 0,    -- 起始字符偏移 (char_range类型时使用)
    anchor_end      INT          NOT NULL DEFAULT 0,    -- 结束字符偏移
    anchor_text     TEXT         NOT NULL,              -- 被批注的原文片段 (冗余, 便于调试和搜索)
    annotation_type VARCHAR(32)  NOT NULL,              -- 批注类型: term_definition / formula_explain / prerequisite / cross_reference / quick_check / difficulty_marker / warning
    knowledge_point_id BIGINT    NULL,                  -- 关联知识点ID (锚标)
    
    -- 批注内容
    title           VARCHAR(128) NULL,                  -- 批注标题 (如术语名)
    summary         VARCHAR(512) NOT NULL,              -- 简要说明 (弹窗预览)
    body            TEXT         NULL,                  -- 详细内容 (展开后显示, 支持 Markdown)
    body_format     VARCHAR(16)  NOT NULL DEFAULT 'markdown', -- 内容格式: markdown / html / latex
    media_urls      JSONB        NULL,                  -- 关联媒体 (图片/音频/动画)
    
    -- 个性化控制
    min_grade_level VARCHAR(16)  NOT NULL DEFAULT 'G1', -- 最低适用年级
    max_grade_level VARCHAR(16)  NOT NULL DEFAULT 'G12',-- 最高适用年级
    difficulty_hint VARCHAR(16)  NULL,                  -- 难度标记: easy / medium / hard
    
    -- 来源与审核
    source          VARCHAR(16)  NOT NULL DEFAULT 'auto', -- 来源: auto (AI生成) / manual (人工编辑) / imported (导入)
    status          VARCHAR(16)  NOT NULL DEFAULT 'pending', -- 状态: pending / approved / rejected / revision / archived
    confidence      DECIMAL(3,2) NOT NULL DEFAULT 0.50, -- AI 生成置信度 0.00~1.00
    
    -- 版本与时间
    version         INT          NOT NULL DEFAULT 1,
    created_by      BIGINT       NULL,                  -- 创建者 (系统/user_id)
    reviewed_by     BIGINT       NULL,                  -- 审核人
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    reviewed_at     TIMESTAMPTZ  NULL,
    
    CONSTRAINT ck_anchor_type CHECK (anchor_type IN ('xpath', 'css_selector', 'char_range')),
    CONSTRAINT ck_annotation_type CHECK (annotation_type IN (
        'term_definition', 'formula_explain', 'prerequisite',
        'cross_reference', 'quick_check', 'difficulty_marker', 'warning'
    )),
    CONSTRAINT ck_status CHECK (status IN ('pending', 'approved', 'rejected', 'revision', 'archived')),
    CONSTRAINT ck_source CHECK (source IN ('auto', 'manual', 'imported'))
);

-- 核心查询索引: 按内容ID获取该内容的全部已审批注
CREATE INDEX idx_annotations_content ON content_annotations (content_id, content_type, status)
    WHERE status = 'approved';

-- 按知识点查找关联批注 (跨内容关联)
CREATE INDEX idx_annotations_kp ON content_annotations (knowledge_point_id)
    WHERE knowledge_point_id IS NOT NULL AND status = 'approved';

-- 按类型筛选
CREATE INDEX idx_annotations_type ON content_annotations (annotation_type, status);

-- 审核待处理队列
CREATE INDEX idx_annotations_review ON content_annotations (status, created_at)
    WHERE status IN ('pending', 'revision');
```

#### 3.1.3 批注个性化规则表 `annotation_personalization_rules`

```sql
CREATE TABLE annotation_personalization_rules (
    id              BIGSERIAL PRIMARY KEY,
    rule_name       VARCHAR(128) NOT NULL,
    priority        INT          NOT NULL DEFAULT 100,  -- 数值越小优先级越高
    
    -- 匹配条件
    grade_levels    JSONB        NOT NULL,              -- 适用年级 ["G1","G2",...] 或 ["*"]
    subject_codes   JSONB        NOT NULL,              -- 适用学科 ["math","physics",...] 或 ["*"]

    -- 控制策略
    max_density     DECIMAL(5,2) NOT NULL DEFAULT 10.00,-- 最大批注密度 (每千字批注数上限)
    display_mode    VARCHAR(16)  NOT NULL DEFAULT 'tap', -- 展示模式: tap(点击展开) / inline(内联显示) / hover(悬停)
    explanation_depth VARCHAR(16) NOT NULL DEFAULT 'standard', -- 解释深度: brief / standard / detailed
    
    is_active       BOOLEAN      NOT NULL DEFAULT TRUE,
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_ann_rules_match ON annotation_personalization_rules (is_active, priority);
```

### 3.2 Redis 缓存设计

```
# 批注查询缓存 (按内容ID聚合)
ann:content:{content_id} → JSON Array
  TTL: 1小时
  内容: 该内容的全部已审批注 (精简格式)

# 个性化批注缓存 (按用户+内容)
ann:user:{user_id}:content:{content_id} → JSON Array
  TTL: 30分钟
  内容: 经个性化规则过滤后的批注列表

# 批注热度统计 (ZSet)
ann:hot:content:{content_id} → ZSet (annotation_id → tap_count)
  TTL: 24小时
  用途: 热门批注优先展示

# 术语词典缓存
ann:glossary:{subject_code} → Hash (term → definition_summary)
  TTL: 6小时

# 用户批注密度偏好
ann:pref:{user_id} → Hash
  fields: density_factor (float), default_display_mode (string)
  TTL: 7天
```

### 5.1 管线概览

```java
/**
 * 将富文本内容解析为可标注的文本块序列

public record ContentBlock(
    String blockId,           // 块ID, 如 "block_1"
    String xpath,             // DOM XPath 路径
    String text,              // 纯文本内容
    int charStart,            // 在全文中的起始位置
    int charEnd,              // 在全文中的结束位置
    BlockType type            // PARAGRAPH / FORMULA / CODE / HEADING / LIST_ITEM
) {}

public List<ContentBlock> parseContent(String htmlContent, ContentType contentType) {
    // 1. 使用 Jsoup 解析 HTML
    Document doc = Jsoup.parse(htmlContent);
    
    // 2. 遍历叶子文本节点, 构建块序列
    List<ContentBlock> blocks = new ArrayList<>();
    int globalOffset = 0;
    
    for (Element element : doc.select("p, h1, h2, h3, h4, li, td, div.formula")) {
        String text = element.text().trim();
        if (text.isEmpty()) continue;
        
        String xpath = buildXPath(element);
        BlockType type = inferBlockType(element);
        
        blocks.add(new ContentBlock(
            "block_" + blocks.size(),
            xpath,
            text,
            globalOffset,
            globalOffset + text.length(),
            type
        ));
        globalOffset += text.length() + 1; // +1 for separator
    }
    return blocks;
}
```

```java
public class EntityRecognitionPipeline {
    
    /**
     * 策略1: 术语词典匹配 (高精度, 召回率中等)
     */
    public List<EntityMatch> dictionaryMatch(List<ContentBlock> blocks, 
                                              String subjectCode,
                                              String gradeLevel) {
        // 加载学科+年级范围内的术语词典
        List<GlossaryTerm> glossary = glossaryCache.get(subjectCode);
        
        List<EntityMatch> matches = new ArrayList<>();
        for (ContentBlock block : blocks) {
            for (GlossaryTerm term : glossary) {
                // 主名称匹配
                findOccurrences(block.text(), term.term(), term)
                    .forEach(matches::add);
                // 别名匹配
                for (String alias : term.aliases()) {
                    findOccurrences(block.text(), alias, term)
                        .forEach(matches::add);
                }
            }
        }
        
        // 去重叠: 保留最长匹配
        return resolveOverlaps(matches);
    }
    
    /**
     * 策略2: NER 模型识别 (召回率高, 精度依赖模型)
     * 使用教育领域微调的 NER 模型识别:
     * - 数学术语: 定理名、函数名、几何概念
     * - 物理概念: 定律名、物理量、单位
     * - 化学术语: 元素名、反应类型、化学键
     * - 英语语法: 时态名、句型名
     */
    public List<EntityMatch> modelRecognize(List<ContentBlock> blocks,
                                             String subjectCode) {
        // 调用教育NER服务
        // POST http://ner-service/v1/recognize
        // Request: { text, subject, model_version }
        // Response: { entities: [{ text, type, start, end, confidence }] }
        return nerClient.recognize(blocks, subjectCode);
    }
    
    /**
     * 策略3: 公式与符号检测 (正则 + LaTeX 解析)
     */
    public List<EntityMatch> detectFormulas(List<ContentBlock> blocks) {
        List<EntityMatch> formulas = new ArrayList<>();
        Pattern latexPattern = Pattern.compile("\\$\\$(.+?)\\$\\$|\\\\\\[(.+?)\\\\\\]");
        
        for (ContentBlock block : blocks) {
            Matcher m = latexPattern.matcher(block.text());
            while (m.find()) {
                formulas.add(new EntityMatch(
                    m.group(),
                    EntityType.FORMULA,
                    block.xpath(),
                    m.start(),
                    m.end(),
                    0.95  // 正则匹配置信度
                ));
            }
        }
        return formulas;
    }
    
    /**
     * 合并三种策略的结果
     */
    public List<EntityMatch> mergeResults(List<EntityMatch> dictMatches,
                                           List<EntityMatch> modelMatches,
                                           List<EntityMatch> formulaMatches) {
        // 1. 合并所有匹配
        List<EntityMatch> all = new ArrayList<>();
        all.addAll(dictMatches);
        all.addAll(modelMatches);
        all.addAll(formulaMatches);
        
        // 2. 解决重叠冲突 (优先级: 词典 > 公式 > NER模型)
        return resolveOverlaps(all, MatchPriority.DICTIONARY);
    }
}
```

```java
public class KnowledgePointMatcher {
    
    /**
     * 将识别到的实体匹配到知识点树
     */
    public List<AnnotationCandidate> matchToKnowledgePoints(
            List<EntityMatch> entities, 
            String subjectCode,
            String gradeLevel) {
        
        List<AnnotationCandidate> candidates = new ArrayList<>();
        
        for (EntityMatch entity : entities) {
            // 1. 先查术语词典是否已直接关联知识点
            if (entity.glossaryTerm() != null && entity.glossaryTerm().knowledgePointId() != null) {
                candidates.add(new AnnotationCandidate(
                    entity, 
                    entity.glossaryTerm().knowledgePointId(),
                    MatchMethod.DIRECT,
                    0.95
                ));
                continue;
            }
            
            // 2. 模糊匹配知识点名称
            List<KnowledgePoint> kps = knowledgePointService.searchByName(
                entity.text(), subjectCode, gradeLevel, 5
            );
            
            if (!kps.isEmpty()) {
                KnowledgePoint best = kps.get(0);
                double similarity = calculateSimilarity(entity.text(), best.name());
                if (similarity >= 0.75) {
                    candidates.add(new AnnotationCandidate(
                        entity,
                        best.id(),
                        MatchMethod.FUZZY,
                        similarity
                    ));
                    continue;
                }
            }
            
            // 3. AI 辅助匹配 (当直接和模糊匹配都失败时)
            KnowledgePoint aiMatch = aiMatchKnowledgePoint(entity, subjectCode);
            if (aiMatch != null) {
                candidates.add(new AnnotationCandidate(
                    entity,
                    aiMatch.id(),
                    MatchMethod.AI_INFERENCE,
                    0.70  // AI匹配置信度下限
                ));
            }
        }
        
        return candidates;
    }
}
```

```java
public class AnnotationPostProcessor {
    
    /**
     * 对AI生成的批注内容进行后处理
     */
    public ContentAnnotation process(AnnotationCandidate candidate,
                                      GeneratedContent content,
                                      String gradeLevel) {
        // 1. 适龄化过滤: 调用适龄化引擎
        AgeAdaptationResult adaptation = ageAdaptationService.adapt(
            content.body(),
            gradeLevel,
            AdaptationLevel.STANDARD
        );
        
        // 2. 安全过滤: 检查是否有不当内容
        SafetyCheckResult safety = safetyFilter.check(content.body());
        if (!safety.isSafe()) {
            log.warn("批注内容安全过滤未通过: annotation_text={}, issues={}",
                candidate.anchorText(), safety.issues());
            return null;  // 丢弃该批注
        }
        
        // 3. 事实性校验 (对于术语定义类)
        if (candidate.type() == AnnotationType.TERM_DEFINITION) {
            FactCheckResult factCheck = factChecker.verify(
                content.summary(),
                candidate.knowledgePointId()
            );
            if (!factCheck.isVerified()) {
                // 降低置信度, 仍入库但标记需要人工审核
                content.setConfidence(content.confidence() * 0.5);
            }
        }
        
        // 4. 密度控制: 检查同一内容块内的批注数量
        int existingCount = countExistingAnnotations(
            candidate.contentId(), 
            candidate.xpath()
        );
        double density = calculateDensity(existingCount + 1, 
            getBlockTextLength(candidate.contentId(), candidate.xpath()));
        
        double maxDensity = getMaxDensity(gradeLevel, candidate.subjectCode());
        if (density > maxDensity) {
            // 密度超标, 仅保留置信度最高的批注
            if (candidate.confidence() < 0.70) {
                log.info("批注密度超标, 丢弃低置信度批注: {}", candidate.anchorText());
                return null;
            }
        }
        
        // 5. 构建最终实体
        return ContentAnnotation.builder()
            .contentId(candidate.contentId())
            .contentType(candidate.contentType())
            .anchorType(AnchorType.CHAR_RANGE)
            .anchorPath(candidate.xpath())
            .anchorStart(candidate.start())
            .anchorEnd(candidate.end())
            .anchorText(candidate.anchorText())
            .annotationType(candidate.type())
            .knowledgePointId(candidate.knowledgePointId())
            .title(content.title())
            .summary(adaptation.summary())
            .body(adaptation.body())
            .bodyFormat("markdown")
            .minGradeLevel(determineMinGrade(gradeLevel, candidate))
            .maxGradeLevel("G12")
            .source(SourceType.AUTO)
            .status(content.confidence() >= 0.80 ? 
                AnnotationStatus.PENDING :     // 高置信度仍需审核
                AnnotationStatus.REVISION)      // 低置信度需要修订
            .confidence(content.confidence())
            .build();
    }
}
```

```java
public class AnnotationPersistenceService {
    
    @Transactional
    public BatchResult batchInsert(List<ContentAnnotation> annotations) {
        // 1. 去重检查: 同一内容同一锚点位置不重复
        List<ContentAnnotation> unique = deduplicate(annotations);
        
        // 2. 批量写入
        List<ContentAnnotation> saved = annotationRepository.batchInsert(unique);
        
        // 3. 发送审核任务
        for (ContentAnnotation ann : saved) {
            // 高置信度的 term_definition 和 cross_reference 可自动通过
            if (shouldAutoApprove(ann)) {
                ann.approve(SYSTEM_USER_ID, "自动审核通过");
                annotationRepository.update(ann);
            } else {
                // 推入审核队列
                reviewQueueClient.enqueue(new ReviewTask(
                    ann.getId(),
                    ReviewTaskType.ANNOTATION,
                    ann.getConfidence(),
                    ann.getAnnotationType(),
                    ReviewPriority.fromConfidence(ann.getConfidence())
                ));
            }
        }
        
        // 4. 清除内容批注缓存
        for (Long contentId : annotations.stream().map(ContentAnnotation::getContentId).distinct().toList()) {
            cacheService.evict("ann:content:" + contentId);
        }
        
        return BatchResult.success(saved.size(), unique.size() - saved.size());
    }
    
    private boolean shouldAutoApprove(ContentAnnotation ann) {
        // 词典直接匹配的术语定义, 置信度>0.90, 可自动通过
        if (ann.getAnnotationType() == AnnotationType.TERM_DEFINITION 
            && ann.getConfidence() >= 0.90
            && ann.getSource() == SourceType.AUTO) {
            return true;
        }
        // 交叉关联 (来自知识图谱结构化数据), 可自动通过
        if (ann.getAnnotationType() == AnnotationType.CROSS_REFERENCE
            && ann.getConfidence() >= 0.80) {
            return true;
        }
        return false;
    }
}
```

## 7. 个性化策略

### 7.1 密度控制算法

```java
public class AnnotationDensityController {
    
    /**
     * 根据用户画像和个性化规则, 过滤和排序批注
     */
    public List<AnnotationDTO> personalize(List<ContentAnnotation> annotations,
                                            UserProfile profile,
                                            String subjectCode,
                                            int contentTextLength) {
        // 1. 获取适用的个性化规则
        AnnotationPersonalizationRule rule = ruleService.findBestMatch(
            profile.gradeLevel(), subjectCode, annotations.get(0).getAnnotationType()
        );
        
        // 2. 按年级过滤
        List<ContentAnnotation> gradeFiltered = annotations.stream()
            .filter(a -> isGradeApplicable(a, profile.gradeLevel()))
            .toList();
        
        // 3. 计算当前密度
        double currentDensity = (double) gradeFiltered.size() / (contentTextLength / 1000.0);
        
        // 4. 如果未超密度上限, 全部返回
        if (currentDensity <= rule.getMaxDensity()) {
            return convertToDTO(gradeFiltered, rule.getDisplayMode());
        }
        
        // 5. 超限: 按优先级截断
        int maxCount = (int)(rule.getMaxDensity() * contentTextLength / 1000.0);
        
        return gradeFiltered.stream()
            .sorted(Comparator.comparing(this::annotationPriority).reversed())
            .limit(maxCount)
            .map(a -> convertToDTO(a, rule.getDisplayMode()))
            .toList();
    }
    
    /**
     * 批注优先级 (用于密度截断时排序)
     */
    private double annotationPriority(ContentAnnotation a) {
        double base = a.getConfidence();
        
        // 类型加权: 术语定义 > 公式解释 > 前置依赖 > 交叉关联 > 快速检测 > 其他
        double typeWeight = switch (a.getAnnotationType()) {
            case TERM_DEFINITION -> 1.0;
            case FORMULA_EXPLAIN -> 0.9;
            case PREREQUISITE -> 0.8;
            case CROSS_REFERENCE -> 0.6;
            case QUICK_CHECK -> 0.5;
            case DIFFICULTY_MARKER -> 0.4;
            case WARNING -> 0.7;
        };
        
        // 热度加权: 被其他学生频繁点击的批注优先级更高
        double hotnessWeight = getHotnessFactor(a.getId());
        
        return base * typeWeight * 0.6 + hotnessWeight * 0.4;
    }
    
    private double getHotnessFactor(Long annotationId) {
        // 从 Redis ZSet 读取该批注的 tap_count
        Double score = redis.zscore("ann:hot:content:*", annotationId.toString());
        if (score == null) return 0.5;  // 新批注默认中等热度
        // 归一化到 0~1
        return Math.min(1.0, score / 100.0);
    }
}
```

### 8.3 批注失效检测

当被批注的内容发生变更时，需要检测锚点是否仍然有效：

```java
public class AnchorValidationService {
    
    /**
     * 内容更新后校验锚点有效性
     */
    public List<AnchorValidationResult> validateAnchors(Long contentId, 
                                                         String newHtmlContent) {
        List<ContentAnnotation> annotations = 
            annotationRepository.findByContentId(contentId, AnnotationStatus.APPROVED);
        
        List<AnchorValidationResult> results = new ArrayList<>();
        
        for (ContentAnnotation ann : annotations) {
            AnchorValidationResult result = validateSingle(ann, newHtmlContent);
            results.add(result);
            
            if (!result.isValid()) {
                // 标记为需要重新定位
                ann.setStatus(AnnotationStatus.REVISION);
                annotationRepository.update(ann);
                
                // 触发重新生成
                eventPublisher.publish(new AnchorInvalidatedEvent(
                    contentId, ann.getId(), InvalidationReason.CONTENT_CHANGED
                ));
            }
        }
        
        return results;
    }
    
    private AnchorValidationResult validateSingle(ContentAnnotation ann, 
                                                    String newHtml) {
        // 1. 检查 XPath 是否仍然存在
        Document doc = Jsoup.parse(newHtml);
        Elements elements = Xsoup.compile(ann.getAnchorPath()).evaluate(doc).getElements();
        if (elements.isEmpty()) {
            return AnchorValidationResult.invalid("XPath not found: structure changed");
        }
        
        // 2. 检查原文片段是否仍然匹配
        String elementText = elements.first().text();
        String expectedText = ann.getAnchorText();
        
        if (!elementText.contains(expectedText)) {
            return AnchorValidationResult.invalid(
                "Anchor text not found: content changed. Expected: '%s'".formatted(expectedText)
            );
        }
        
        // 3. 检查 char_range 是否仍然准确
        if (ann.getAnchorType() == AnchorType.CHAR_RANGE) {
            int start = elementText.indexOf(expectedText);
            if (start != ann.getAnchorStart()) {
                // 偏移量变化, 更新锚点位置
                return AnchorValidationResult.needsUpdate(start, 
                    start + expectedText.length());
            }
        }
        
        return AnchorValidationResult.valid();
    }
}
```

```java
// 生成失败的重试策略
public class AnnotationGenerationRetryHandler {
    
    public void handleFailures() {
        List<GenerationFailure> failures = failureRepository.getPendingFailures();
        
        for (GenerationFailure failure : failures) {
            if (failure.retryCount() >= 3) {
                // 超过最大重试次数, 放弃
                failure.markAsAbandoned("Max retries exceeded");
                continue;
            }
            
            // 指数退避
            long delaySeconds = (long) Math.pow(2, failure.retryCount()) * 60;
            if (failure.lastAttempt().plusSeconds(delaySeconds).isAfter(Instant.now())) {
                continue;  // 未到重试时间
            }
            
            // 按失败原因决定重试策略
            switch (failure.reason()) {
                case AI_TIMEOUT -> retryWithLighterModel(failure);
                case NER_UNAVAILABLE -> retryWithoutNER(failure);
                case PARSE_ERROR -> retryWithSimplifiedParser(failure);
                default -> retryFullPipeline(failure);
            }
        }
    }
}
```

```java
    public InterestSignal extract(Long userId, TimeWindow window) {
        List<AnnotationInteractionLog> logs = 
            logRepository.findByUserIdAndTimeRange(userId, window);
        
        // 1. 统计各知识点被点击频率

            subjectInterests.merge(kp.subjectCode(), 
                entry.getValue().doubleValue(), Double::sum);

        if (total > 0) {
            subjectInterests.replaceAll((k, v) -> v / total);
        }
        
        return new InterestSignal(
            userId,
            subjectInterests,
            kpTapCounts,           // 知识点级兴趣
            window,
            logs.size()
        );
    }
```

## 15. 边界条件与注意事项

1. **批注不是必须项**: 批注系统是内容增强层，其故障不应影响基础内容浏览。客户端必须实现降级策略，当批注接口不可用时静默降级为无批注模式。

2. **避免批注泛滥**: 单篇内容批注密度必须严格控制。过多的批注会干扰阅读节奏，特别是低年级学生。宁可少而精，不可多而杂。

3. **quick_check 的克制使用**: 不是每段内容都需要检测题。建议每篇内容最多 2-3 个 quick_check，且分布在关键知识点处。

4. **锚点稳定性**: 内容编辑更新时，字符偏移可能变化。系统使用 `anchor_text` 作为冗余校验，当原文与锚点记录不一致时触发重新校验。

5. **公式和特殊符号**: 数学的 LaTeX 公式、化学方程式等需要特殊处理，不能简单按纯文本匹配。公式类批注需要解析 LaTeX 结构。

6. **多教材版本**: 同一概念在不同教材版本中可能有不同表述（如"二次函数"vs"抛物线函数"），术语词典需要支持别名。

7. **审核效率**: AI 自动生成的批注量大，需要设计高效的审核界面（批量审核、快捷键操作、差异对比）来提升人工审核效率。

8. **缓存一致性**: 批注状态变更（审核通过、下线）时必须主动清除缓存。使用 Redis Pub/Sub 或消息队列通知各节点清除本地缓存。

9. **离线模式**: 离线场景下无法获取批注，客户端应缓存已查看过的批注数据，在离线模式下仍可展示（但不支持 quick_check 交互）。

10. **数据隔离**: 批注交互日志只记录用户ID和批注ID，不记录批注原文内容，避免在日志中泄露平台内容资产。
