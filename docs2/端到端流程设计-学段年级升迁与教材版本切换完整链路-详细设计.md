# 端到端流程设计 - 学段年级升迁与教材版本切换完整链路

> **版本**: v1.0 | **日期**: 2026-06-04 | **状态**: 初稿
> **优先级**: P0（首次建档年级选择）+ P1（学期升迁引导）
> **依赖**: 服务端-用户年级升迁与学段转换服务、学期与学年管理服务、客户端-学段年级切换与教材版本更新引导页面架构与交互设计、用户账号体系、教材内容数字化与结构化生产管线

---

## 1. 概述

### 1.1 什么是学段年级升迁

学段年级升迁是指学生在学期/学年交替时，年级发生变化（如五年级→六年级）或学段发生跨段（如小学→初中、初中→高中）的场景。这一过程涉及：

- 用户档案更新（年级、学段标签）
- 教材版本重新映射
- 学科列表增删（如初中新增物理、化学）
- 学习数据归档与迁移
- 学习计划重置
- 知识掌握度延续性评估
- UI 分龄适配策略切换
- 家长通知与确认

### 1.2 触发场景

| 场景 | 触发方式 | 频率 | 优先级 |
|------|---------|------|--------|
| 自然年级升迁（9月开学） | 服务端定时任务自动检测 | 每年1次 | P0 |
| 首次注册建档 | 客户端引导流程 | 一次性 | P0 |
| 用户手动申请升迁 | 客户端设置页手动触发 | 极少 | P2 |
| 家长代为操作 | 家长端发起 | 少量 | P1 |
| 跳级/留级特殊情况 | 管理后台人工处理 | 极少 | P3 |
| 教材版本变更（中途换教材） | 客户端设置页手动触发 | 偶尔 | P2 |

## 3. 数据结构定义

### 3.1 用户年级学段状态

```typescript
interface UserProfile {
  userId: string;
  nickname: string;
  avatar: string;
  birthday: string;                    // YYYY-MM-DD

  // 学段年级
  stage: SchoolStage;                  // 当前学段
  grade: number;                       // 当前年级 (1-12)
  gradeLabel: string;                  // 年级显示名 "三年级"

  // 教材配置
  textbookEditions: TextbookEdition[]; // 各学科教材版本

  // 学期信息
  currentSemester: SemesterInfo;

  // 升迁状态
  transitionStatus: TransitionStatus;
  transitionHistory: TransitionRecord[];
}

enum SchoolStage {
  PRESCHOOL = 'PRESCHOOL',   // 幼儿启蒙
  PRIMARY   = 'PRIMARY',     // 小学 (1-6年级)
  JUNIOR    = 'JUNIOR',      // 初中 (7-9年级)
  SENIOR    = 'SENIOR',      // 高中 (10-12年级)
}

enum TransitionStatus {
  IDLE                 = 'IDLE',
  PENDING_CONFIRM      = 'PENDING_CONFIRM',
  PENDING_PARENT_AUTH  = 'PENDING_PARENT_AUTH',
  IN_PROGRESS          = 'IN_PROGRESS',
  COMPLETED            = 'COMPLETED',
  FAILED               = 'FAILED',
  ROLLED_BACK          = 'ROLLED_BACK',
}
```

### 3.2 升迁任务

```typescript
interface TransitionTask {
  taskId: string;
  userId: string;

  type: TransitionType;
  triggerSource: 'AUTO' | 'MANUAL' | 'PARENT' | 'ADMIN';

  fromStage: SchoolStage;
  fromGrade: number;
  toStage: SchoolStage;
  toGrade: number;

  textbookChanges: TextbookChange[];
  subjectChanges: SubjectChange[];

  status: TransitionStatus;
  currentStep: number;
  totalSteps: number;
  steps: TransitionStep[];

  detectedAt: string;
  confirmedAt: string | null;
  parentAuthAt: string | null;
  startedAt: string | null;
  completedAt: string | null;
  expireAt: string;                    // 14天内需完成

  rollbackSnapshot: UserSnapshot | null;
}

enum TransitionType {
  GRADE_UP         = 'GRADE_UP',           // 同学段升年级
  STAGE_CROSS      = 'STAGE_CROSS',        // 跨学段（小学->初中等）
  TEXTBOOK_CHANGE   = 'TEXTBOOK_CHANGE',   // 仅换教材
  GRADE_DOWN       = 'GRADE_DOWN',         // 降级（特殊情况）
}

interface TextbookChange {
  subject: string;
  oldEditionId: string | null;
  oldEditionName: string | null;
  newEditionId: string;
  newEditionName: string;
  confirmed: boolean;
}

interface SubjectChange {
  subject: string;
  action: 'ADD' | 'REMOVE' | 'KEEP';
  reason: string;
}

interface TransitionStep {
  stepNo: number;
  name: string;
  status: 'PENDING' | 'RUNNING' | 'DONE' | 'FAILED' | 'SKIPPED';
  startedAt: string | null;
  completedAt: string | null;
  error: string | null;
  detail: Record<string, any>;
}

interface UserSnapshot {
  snapshotId: string;
  userId: string;
  profile: UserProfile;
  masteryData: Record<string, number>;  // 知识点掌握度
  planIds: string[];
  snapshotAt: string;
}
```

### 3.3 数据库表设计

```sql
-- 升迁任务表
CREATE TABLE transition_tasks (
    task_id         VARCHAR(36) PRIMARY KEY,
    user_id         VARCHAR(36) NOT NULL,
    type            ENUM('GRADE_UP','STAGE_CROSS','TEXTBOOK_CHANGE','GRADE_DOWN'),
    trigger_source  ENUM('AUTO','MANUAL','PARENT','ADMIN'),
    from_stage      ENUM('PRESCHOOL','PRIMARY','JUNIOR','SENIOR'),
    from_grade      TINYINT,
    to_stage        ENUM('PRESCHOOL','PRIMARY','JUNIOR','SENIOR'),
    to_grade        TINYINT,
    status          ENUM('PENDING_CONFIRM','PENDING_PARENT_AUTH',
                         'IN_PROGRESS','COMPLETED','FAILED','ROLLED_BACK'),
    current_step    TINYINT DEFAULT 0,
    total_steps     TINYINT,
    detected_at     DATETIME NOT NULL,
    confirmed_at    DATETIME,
    parent_auth_at  DATETIME,
    started_at      DATETIME,
    completed_at    DATETIME,
    expire_at       DATETIME NOT NULL,
    rollback_snapshot_id VARCHAR(36),
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_status (user_id, status),
    INDEX idx_expire (expire_at, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 教材变更明细
CREATE TABLE transition_textbook_changes (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    task_id         VARCHAR(36) NOT NULL,
    subject_code    VARCHAR(20) NOT NULL,
    old_edition_id  VARCHAR(36),
    new_edition_id  VARCHAR(36) NOT NULL,
    confirmed       BOOLEAN DEFAULT FALSE,
    FOREIGN KEY (task_id) REFERENCES transition_tasks(task_id),
    INDEX idx_task (task_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 学科变更明细
CREATE TABLE transition_subject_changes (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    task_id         VARCHAR(36) NOT NULL,
    subject_code    VARCHAR(20) NOT NULL,
    action          ENUM('ADD','REMOVE','KEEP'),
    reason          VARCHAR(200),
    FOREIGN KEY (task_id) REFERENCES transition_tasks(task_id),
    INDEX idx_task (task_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 迁移步骤记录
CREATE TABLE transition_steps (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    task_id         VARCHAR(36) NOT NULL,
    step_no         TINYINT NOT NULL,
    name            VARCHAR(50) NOT NULL,
    status          ENUM('PENDING','RUNNING','DONE','FAILED','SKIPPED') DEFAULT 'PENDING',
    started_at      DATETIME,
    completed_at    DATETIME,
    error           TEXT,
    detail          JSON,
    FOREIGN KEY (task_id) REFERENCES transition_tasks(task_id),
    UNIQUE KEY uk_task_step (task_id, step_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 用户快照（回滚用）
CREATE TABLE user_snapshots (
    snapshot_id     VARCHAR(36) PRIMARY KEY,
    user_id         VARCHAR(36) NOT NULL,
    profile_data    JSON NOT NULL,
    mastery_data    JSON,
    plan_ids        JSON,
    snapshot_at     DATETIME NOT NULL,
    task_id         VARCHAR(36),
    INDEX idx_user (user_id),
    INDEX idx_task (task_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 5. 端到端流程详解

### 5.1 阶段一：检测触发

#### 5.1.1 服务端自动检测

```
服务端定时任务（每日 06:00 执行）
  |
  +-- 查询学期管理服务：当前是否处于"升迁窗口期"
  |   （新学期开学前7天 ~ 开学后14天）
  |
  +-- 查询所有活跃用户的当前年级与学期信息
  |
  +-- 对比：用户当前年级 < 新学期应处于的年级?
  |   |
  |   +-- YES -> 检查是否已有进行中的升迁任务
  |   |   |
  |   |   +-- 无任务 -> 创建 PENDING_CONFIRM 任务
  |   |   |   +-- 确定目标年级、学段
  |   |   |   +-- 生成学科变更列表
  |   |   |   +-- 生成推荐教材版本
  |   |   |   +-- 设置过期时间（开学后14天）
  |   |   |
  |   |   +-- 已有任务 -> 跳过
  |   |
  |   +-- NO -> 跳过
  |
  +-- 发送推送通知
      +-- 学生端："新学期开始啦！点击确认你的新年级"
      +-- 家长端："孩子的年级需要更新，请协助确认"
```

#### 5.1.2 客户端启动检测

```dart
class TransitionCheckMiddleware {
  Future<void> onAppStart() async {
    final response = await api.get('/transition/status');
    if (response.data['hasPendingTransition']) {
      _showTransitionGuide(response.data['task']);
    }
  }
}
```

### 5.2 阶段二：通知与引导

#### 5.2.1 通知策略

| 通知渠道 | 触发时机 | 内容 | 频率限制 |
|---------|---------|------|---------|
| App内弹窗 | 启动时检测到待确认任务 | "新学期开始，确认你的新年级" | 每次启动最多1次 |
| 推送通知 | 任务创建后 | "点击确认年级信息" | 3天内最多2次 |
| 家长端推送 | 任务创建后 | "请协助确认孩子年级" | 3天内最多2次 |
| 过期提醒 | 过期前3天 | "请尽快完成确认" | 最多1次 |

#### 5.4.1 服务端迁移编排

```java
@Service
public class TransitionExecutionService {

    private static final int TOTAL_STEPS = 7;

    @Autowired
    private UserSnapshotService snapshotService;
    @Autowired
    private LearningDataArchiveService archiveService;
    @Autowired
    private UserProfileService profileService;
    @Autowired
    private ContentMappingService contentMappingService;
    @Autowired
    private MasteryMigrationService masteryService;
    @Autowired
    private StudyPlanService planService;
    @Autowired
    private SemesterInitService semesterInitService;
    @Autowired
    private TransitionTaskRepository taskRepository;
    @Autowired
    private ApplicationEventPublisher eventPublisher;

    /**
     * 执行升迁迁移（异步编排）
     */
    @Async("transitionExecutor")
    public void executeTransition(String taskId) {
        TransitionTask task = taskRepository.findById(taskId)
            .orElseThrow(() -> new BusinessException(ErrorCode.TASK_NOT_FOUND));

        try {
            task.setStatus(TransitionStatus.IN_PROGRESS);
            task.setStartedAt(LocalDateTime.now());
            taskRepository.save(task);

            // Step 1: 创建用户快照
            executeStep(task, 1, "创建用户快照", () -> {
                UserSnapshot snapshot = snapshotService.createSnapshot(task.getUserId());
                task.setRollbackSnapshot(snapshot);
            });

            // Step 2: 归档旧学期数据
            executeStep(task, 2, "归档旧学期数据", () -> {
                archiveService.archiveCurrentSemesterData(task.getUserId());
            });

            // Step 3: 更新用户档案
            executeStep(task, 3, "更新用户档案", () -> {
                profileService.updateGradeAndStage(
                    task.getUserId(),
                    task.getToStage(),
                    task.getToGrade()
                );
            });

            // Step 4: 映射新教材版本
            executeStep(task, 4, "映射新教材版本", () -> {
                contentMappingService.applyTextbookChanges(
                    task.getUserId(),
                    task.getTextbookChanges()
                );
            });

            // Step 5: 迁移知识掌握度
            executeStep(task, 5, "迁移知识掌握度", () -> {
                masteryService.migrateMasteryData(
                    task.getUserId(),
                    task.getFromStage(),
                    task.getToStage()
                );
            });

            // Step 6: 重置学习计划
            executeStep(task, 6, "重置学习计划", () -> {
                planService.resetPlansForNewSemester(task.getUserId());
            });

            // Step 7: 初始化新学期
            executeStep(task, 7, "初始化新学期", () -> {
                semesterInitService.initializeNewSemester(
                    task.getUserId(),
                    task.getToStage(),
                    task.getToGrade()
                );
            });

            // 全部完成
            task.setStatus(TransitionStatus.COMPLETED);
            task.setCompletedAt(LocalDateTime.now());
            taskRepository.save(task);

            // 发布完成事件
            eventPublisher.publishEvent(
                new TransitionCompletedEvent(taskId, task.getUserId())
            );

        } catch (Exception e) {
            // 迁移失败，标记状态
            task.setStatus(TransitionStatus.FAILED);
            taskRepository.save(task);

            log.error("迁移执行失败, taskId={}", taskId, e);
            // 通知客户端失败
            eventPublisher.publishEvent(
                new TransitionFailedEvent(taskId, e.getMessage())
            );
        }
    }

    private void executeStep(TransitionTask task, int stepNo,
                              String stepName, Runnable action) {
        TransitionStep step = new TransitionStep();
        step.setTaskId(task.getTaskId());
        step.setStepNo(stepNo);
        step.setName(stepName);
        step.setStatus(StepStatus.RUNNING);
        step.setStartedAt(LocalDateTime.now());

        try {
            action.run();
            step.setStatus(StepStatus.DONE);
            step.setCompletedAt(LocalDateTime.now());
        } catch (Exception e) {
            step.setStatus(StepStatus.FAILED);
            step.setError(e.getMessage());
            throw e; // 向上抛出，中断后续步骤
        } finally {
            task.setCurrentStep(stepNo);
            taskRepository.save(task);
            stepRepository.save(step);
        }
    }
}
```

#### 5.4.2 知识掌握度迁移策略

跨学段时，知识点体系可能完全不同。迁移策略如下：

```java
@Service
public class MasteryMigrationService {

    /**
     * 策略矩阵：
     * 1. 同学段升年级 -> 直接延续，基础知识点保留掌握度
     * 2. 小学->初中    -> 基础学科(语数英)掌握度按70%折算延续
     *                     新学科(理化生)初始化为"未评估"
     * 3. 初中->高中    -> 基础学科掌握度按60%折算延续
     *                     高中专属知识点初始化为"未评估"
     */
    public void migrateMasteryData(String userId, SchoolStage from, SchoolStage to) {
        if (from == to) {
            // 同学段：保持掌握度不变
            return;
        }

        double retentionRate = getRetentionRate(from, to);

        // 获取可延续的学科
        List<String> continuedSubjects = getContinuedSubjects(from, to);

        for (String subject : continuedSubjects) {
            Map<String, Double> currentMastery =
                masteryRepository.getSubjectMastery(userId, subject);

            // 跨学段知识点映射（如小学数学->初中数学的知识点对应关系）
            Map<String, String> knowledgeMapping =
                knowledgeMappingService.getCrossStageMapping(subject, from, to);

            for (var entry : currentMastery.entrySet()) {
                String oldKnowledgeId = entry.getKey();
                double oldMastery = entry.getValue();

                if (knowledgeMapping.containsKey(oldKnowledgeId)) {
                    String newKnowledgeId = knowledgeMapping.get(oldKnowledgeId);
                    double newMastery = oldMastery * retentionRate;
                    masteryRepository.upsertMastery(
                        userId, newKnowledgeId,
                        Math.max(0.1, newMastery) // 最低0.1，避免完全不记得
                    );
                }
            }
        }

        // 新增学科初始化
        List<String> newSubjects = getNewSubjects(from, to);
        for (String subject : newSubjects) {
            masteryRepository.initializeSubjectMastery(userId, subject);
        }
    }

    private double getRetentionRate(SchoolStage from, SchoolStage to) {
        if (from == SchoolStage.PRIMARY && to == SchoolStage.JUNIOR) return 0.70;
        if (from == SchoolStage.JUNIOR && to == SchoolStage.SENIOR) return 0.60;
        return 0.80; // 默认
    }
}
```

## 7. 异常处理与边界情况

### 7.1 常见异常场景

| 异常场景 | 表现 | 处理策略 |
|---------|------|---------|
| 迁移过程中网络中断 | 步骤状态为RUNNING超时 | 步骤级别重试，最多3次 |
| 目标教材版本不存在 | 映射教材步骤失败 | 降级为默认版本，记录告警 |
| 快照创建失败 | 无法回滚 | 中止迁移，通知人工介入 |
| 家长授权超时(48h) | 任务卡在PENDING_PARENT_AUTH | 客户端允许重新请求授权 |
| 用户在迁移中打开App | 数据不一致 | 客户端检测IN_PROGRESS状态，展示迁移中页面 |
| 并发升迁请求 | 同一用户多个任务 | 加分布式锁，只允许一个活跃任务 |
| 跨学段知识点无映射 | 掌握度无法迁移 | 标记为"未评估"，不强行折算 |

### 7.2 并发控制

@Service
public class TransitionLockService {

    @Autowired
    private RedissonClient redisson;

    /**
     * 分布式锁：同一用户同一时间只允许一个升迁任务
     */
    public boolean tryAcquireLock(String userId) {
        RLock lock = redisson.getLock("transition:" + userId);
        return lock.tryLock(0, 10, TimeUnit.MINUTES);
    }

    public void releaseLock(String userId) {
        RLock lock = redisson.getLock("transition:" + userId);
        if (lock.isHeldByCurrentThread()) {
            lock.unlock();
        }
    }
}

### 7.3 边界情况处理

#### 7.3.1 用户跳级

`
场景：小学4年级直接跳到初中1年级
处理：
1. 允许手动触发，targetGrade=7, targetStage=JUNIOR
2. 学科按初中配置全量新增
3. 知识掌握度：小学5-6年级知识点标记为"未学习"
4. 学习计划：生成补漏计划（建议先补齐跳过的年级知识点）
`

#### 7.3.2 中途换教材（非升迁场景）

`
场景：学期中途学校更换教材版本
处理：
1. 创建 TEXTBOOK_CHANGE 类型任务（非年级变更）
2. 仅执行教材映射步骤（Step 4），跳过其他步骤
3. 学习计划中的章节进度重新对齐新教材
4. 错题本中的题目保留，关联的知识点映射更新
`

#### 7.3.3 多孩子家庭

`
场景：家长管理多个孩子，每个孩子可能在不同年级
处理：
1. 每个孩子独立的升迁任务
2. 家长端聚合展示所有待处理的升迁请求
3. 家长逐一授权（避免批量操作误操作）
`

#### 7.3.4 降级（留级）

`
场景：学生需要回到上一个年级
处理：
1. 仅管理后台可操作（学生/家长无法自行降级）
2. 创建 GRADE_DOWN 类型任务
3. 当前学期学习数据保留（归档），不做删除
4. 回退到旧年级的学习计划和数据
5. 知识掌握度保持不变（已学的不会遗忘）
`

| 家长授权验证 | 小学及以下学段升迁需家长PIN/生物识别授权 |
| 操作审计日志 | 所有升迁操作记录审计日志 |
| 数据快照与回滚 | 迁移前创建完整快照，支持24h内回滚 |
| 分布式锁 | 防止并发升迁导致数据不一致 |
| 接口鉴权 | 所有API需验证用户身份和操作权限 |
| 数据脱敏 | 快照数据中的敏感信息脱敏存储 |

### 9.2 合规要求

- 学段变更需经家长知情同意（《未成年人保护法》）
- 升迁过程中的用户数据迁移需符合《个人信息保护法》
- 保留完整的变更历史记录，支持监管审计
