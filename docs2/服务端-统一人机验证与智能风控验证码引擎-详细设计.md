# 服务端-统一人机验证与智能风控验证码引擎 详细设计

## 1. 概述

### 1.1 模块定位

统一人机验证与智能风控验证码引擎（Unified CAPTCHA & Risk-based Verification Engine，简称 URVE）是 PrimeTop 平台的基础安全设施，负责在关键业务节点（注册、登录、AI 调用、拍题、支付、领券等）进行自动化流量识别与人机验证拦截。作为"最后一道防线"，URVE 在账号安全引擎、API 限流、支付风控等系统之上提供细粒度的实时人机判别能力，有效防御脚本刷量、暴力破解、恶意抢券、自动化 AI 滥用等黑灰产攻击。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 风险评估 | 基于设备指纹、行为特征、IP 信誉、频率统计等多维度数据，实时计算请求风险分数（0~100） |
| 验证触发 | 根据风险分数与业务场景规则，动态决定是否需要人机验证及验证强度 |
| 验证服务 | 提供多种验证方式：滑块拼图、点选文字、行为验证、无感验证、短信/邮件验证码升级 |
| 第三方适配 | 对接国内主流验证码服务商（腾讯验证码、极验 GeeTest、网易易盾、阿里云验证），支持灵活切换与容灾 |
| 验证令牌 | 验证通过后颁发短时效 VerificationToken，业务系统凭令牌放行请求 |
| 审计分析 | 记录全量验证日志，提供验证通过率、拦截率、攻击趋势等分析看板 |

#### 2.1.1 verification_scene（验证场景配置表）

```sql
CREATE TABLE verification_scene (
    id                  INT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    scene_code          VARCHAR(64)  NOT NULL COMMENT '场景编码',
    scene_name          VARCHAR(128) NOT NULL COMMENT '场景名称',
    scene_category      VARCHAR(32)  NOT NULL COMMENT '场景大类: AUTH(认证) / RESOURCE(资源调用) / TRANSACTION(交易) / MARKETING(营销)',
    description         VARCHAR(512) NULL     COMMENT '场景描述',
    risk_threshold_pass TINYINT      NOT NULL DEFAULT 20  COMMENT '直接放行阈值(0-100)，低于此分数直接通过',
    risk_threshold_verify TINYINT    NOT NULL DEFAULT 60  COMMENT '触发验证阈值(0-100)，达到此分数触发人机验证',
    risk_threshold_block TINYINT     NOT NULL DEFAULT 90  COMMENT '直接拦截阈值(0-100)，超过此分数直接拒绝',

    enabled             TINYINT      NOT NULL DEFAULT 1 COMMENT '是否启用: 0=关闭, 1=开启',
    cooldown_seconds    INT          NOT NULL DEFAULT 300 COMMENT '验证通过后冷却时间(秒)，冷却期内同场景免验证',
    max_fail_attempts   INT          NOT NULL DEFAULT 5 COMMENT '最大验证失败次数，超出后临时封禁',
    fail_ban_minutes    INT          NOT NULL DEFAULT 30 COMMENT '验证失败超限后封禁时长(分钟)',
    created_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_scene_code (scene_code),
    KEY idx_category (scene_category),
    KEY idx_enabled (enabled)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='验证场景配置表';
```

### 2.3 核心实体定义

```java
/** 验证场景类型 */
public enum SceneCategory {
    AUTH,          // 认证类: 注册、登录、密码重置
    RESOURCE,      // 资源调用类: AI问答、拍题OCR、语音服务
    TRANSACTION,   // 交易类: 支付下单、退款、积分兑换
    MARKETING      // 营销类: 领券、抽奖、反馈提交
}

/** 验证方式 */
public enum VerifyType {
    NONE,          // 免验证(风险极低)
    INVISIBLE,     // 无感验证(前端收集行为数据，后端判断)
    SLIDER,        // 滑块拼图
    CLICK,         // 点选文字/图标
    BEHAVIOR,      // 行为验证(手势轨迹)
    SMS_UPGRADE    // 升级为短信验证码(高风险)
}

/** 验证状态 */
public enum VerifyStatus {
    PENDING,       // 等待验证
    SUCCESS,       // 验证通过
    FAILED,        // 验证失败
    BLOCKED,       // 已拦截(风险极高或失败超限)
    TIMEOUT        // 验证超时
}

/** 风险评估请求 */
@Data
@Builder
public class RiskAssessRequest {
    private String sceneCode;           // 场景编码
    private Long userId;                // 用户ID(可选)
    private String deviceId;            // 设备指纹ID
    private String clientIp;            // 客户端IP
    private String userAgent;           // User-Agent
    private Map<String, Object> deviceInfo;  // 设备信息(型号、系统等)
    private List<Float> behaviorTrace;  // 行为轨迹数据(可选,前端采集)
    private String businessId;          // 业务ID(如订单号,可选)
}

/** 风险评估结果 */
@Data
@Builder
public class RiskAssessResult {
    private int riskScore;              // 综合风险评分 0-100
    private RiskLevel riskLevel;        // 风险等级
    private VerifyType recommendVerifyType;  // 建议验证方式
    private boolean shouldVerify;       // 是否需要验证
    private boolean shouldBlock;        // 是否直接拦截
    private boolean inCooldown;         // 是否在验证冷却期内
    private String reason;              // 决策原因
    private Map<String, Integer> dimensionScores;  // 各维度评分明细
}

public enum RiskLevel {
    LOW(0, 29),       // 低风险
    MEDIUM(30, 59),   // 中风险
    HIGH(60, 84),     // 高风险
    CRITICAL(85, 100); // 极高风险
    
    public final int min;
    public final int max;
    RiskLevel(int min, int max) { this.min = min; this.max = max; }
}
```

## 3. API 接口设计

### 3.1 接口总览

| # | 接口 | 方法 | 路径 | 说明 |

### 3.2 接口详细定义

#### 3.2.1 风险评估接口

业务方在执行关键操作前调用此接口，获取"是否需要验证"的决策。

```
POST /api/v1/verification/risk-assess
Authorization: Bearer {service_token}
Content-Type: application/json
```

**请求体：**
```json
{
  "sceneCode": "AI_CHAT",
  "userId": 10086,
  "deviceId": "fp_a1b2c3d4e5f6",
  "clientIp": "114.114.114.114",
  "userAgent": "Mozilla/5.0 (Linux; Android 14; ...) PrimeTop/1.0.0",
  "deviceInfo": {
    "platform": "android",
    "model": "MI 14",
    "osVersion": "14",
    "appVersion": "1.0.0",
    "screenWidth": 1080,
    "screenHeight": 2400
  },
  "behaviorTrace": [0.12, 0.35, 0.68, 0.92, 1.03],
  "businessId": "session_abc123"
}
```

**响应体：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "riskScore": 72,
    "riskLevel": "HIGH",
    "shouldVerify": true,
    "shouldBlock": false,
    "inCooldown": false,
    "recommendVerifyType": "INVISIBLE",
    "reason": "IP_RISK_HIGH+FREQ_EXCEED",
    "dimensionScores": {
      "ipRisk": 65,
      "deviceRisk": 30,
      "frequencyRisk": 85,
      "accountRisk": 20,
      "behaviorRisk": 50
    },
    "assessId": "assess_xyz789",
    "expireAt": "2026-07-17T00:15:00Z"
  }
}
```

**决策逻辑：**

| 风险评分 | 决策 | 说明 |
|----------|------|------|
| 0 ~ threshold_pass | 直接放行，无需验证 | 低风险用户，直接颁发令牌 |
| threshold_pass ~ threshold_verify | 触发人机验证 | 根据推荐验证方式进行 |
| threshold_verify ~ threshold_block | 触发强验证 | 使用滑块/点选等强验证方式 |
| > threshold_block | 直接拦截 | 极高风险，直接拒绝并记录 |

#### 3.2.2 创建验证接口

客户端收到"需要验证"的决策后，调用此接口获取验证参数。
