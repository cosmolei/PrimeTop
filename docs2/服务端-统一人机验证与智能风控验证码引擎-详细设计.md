# 服务端-统一人机验证与智能风控验证码引擎 详细设计

## 1. 概述

### 1.1 模块定位

统一人机验证与智能风控验证码引擎（Unified CAPTCHA & Risk-based Verification Engine，简称 URVE）是 PrimeTop 平台的基础安全设施，负责在关键业务节点（注册、登录、AI 调用、拍题、支付、领券等）进行自动化流量识别与人机验证拦截。作为"最后一道防线"，URVE 在账号安全引擎、API 限流、支付风控等系统之上提供细粒度的实时人机判别能力，有效防御脚本刷量、暴力破解、恶意抢券、自动化 AI 滥用等黑灰产攻击。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 风险评估 | 基于设备指纹、行为特征、IP 信誉、频率统计等多维度数据，实时计算请求风险分数（0~100） |
| 验证触发 | 根据风险分数与业务场景规则，动态决定是否需要人机验证及验证强度 |
| 验证服务 | 提供多种验证方式：滑块拼图、点选文字、行为验证、无感验证、短信/邮件验证码升级 |
| 第三方适配 | 对接国内主流验证码服务商（腾讯验证码、极验 GeeTest、网易易盾、阿里云验证），支持灵活切换与容灾 |
| 验证令牌 | 验证通过后颁发短时效 VerificationToken，业务系统凭令牌放行请求 |
| 审计分析 | 记录全量验证日志，提供验证通过率、拦截率、攻击趋势等分析看板 |

```sql
    updated_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_scene_code (scene_code),
    KEY idx_category (scene_category),
```

### 2.2 Redis 缓存结构

```
# 场景配置缓存 (Hash)
CACHE:scene_config:{sceneCode}
  → JSON序列化的场景配置对象
  TTL: 300s

# 设备/IP频率统计 (Sorted Set, 按时间窗口)
CACHE:freq:{sceneCode}:{deviceId|ip}:{minute}  
  → score=timestamp, member=requestId
  TTL: 600s

# 用户验证冷却标记 (String)
CACHE:verify_cooldown:{userId|deviceId}:{sceneCode}
  → "verified" 
  TTL: {cooldown_seconds}

# 验证会话 (Hash) - 客户端发起验证后的临时会话
CACHE:verify_session:{recordId}
  → { scene_code, device_id, risk_score, verify_type, provider, captcha_params, status: "PENDING" }
  TTL: 180s

# IP实时风险评分缓存 (String)
CACHE:ip_risk:{ipAddr}
  → "42"
  TTL: 60s

# 服务商健康状态缓存 (Hash)
CACHE:provider_health:{providerCode}
  → { status, qps, latency, success_rate, last_check }
  TTL: 30s

# 封禁列表 (String)
CACHE:ban:{deviceId|ip}:{sceneCode}
  → "ban_reason"
  TTL: {ban_minutes * 60}

# 令牌黑名单 (用于主动撤销)
CACHE:token_revoked:{tokenId}
  → "revoked"
  TTL: {剩余过期时间}
```

### 2.3 核心实体定义

```java
/** 验证场景类型 */
public enum SceneCategory {
    AUTH,          // 认证类: 注册、登录、密码重置
    RESOURCE,      // 资源调用类: AI问答、拍题OCR、语音服务
    TRANSACTION,   // 交易类: 支付下单、退款、积分兑换
    MARKETING      // 营销类: 领券、抽奖、反馈提交
}

/** 验证方式 */
public enum VerifyType {
    NONE,          // 免验证(风险极低)
    INVISIBLE,     // 无感验证(前端收集行为数据，后端判断)
    SLIDER,        // 滑块拼图
    CLICK,         // 点选文字/图标
    BEHAVIOR,      // 行为验证(手势轨迹)
    SMS_UPGRADE    // 升级为短信验证码(高风险)
}

/** 验证状态 */
public enum VerifyStatus {
    PENDING,       // 等待验证
    SUCCESS,       // 验证通过
    FAILED,        // 验证失败
    BLOCKED,       // 已拦截(风险极高或失败超限)
    TIMEOUT        // 验证超时
}

/** 风险评估请求 */
@Data
@Builder
public class RiskAssessRequest {
    private String sceneCode;           // 场景编码
    private Long userId;                // 用户ID(可选)
    private String deviceId;            // 设备指纹ID
    private String clientIp;            // 客户端IP
    private String userAgent;           // User-Agent
    private Map<String, Object> deviceInfo;  // 设备信息(型号、系统等)
    private List<Float> behaviorTrace;  // 行为轨迹数据(可选,前端采集)
    private String businessId;          // 业务ID(如订单号,可选)
}

/** 风险评估结果 */
@Data
@Builder
public class RiskAssessResult {
    private int riskScore;              // 综合风险评分 0-100
    private RiskLevel riskLevel;        // 风险等级
    private VerifyType recommendVerifyType;  // 建议验证方式
    private boolean shouldVerify;       // 是否需要验证
    private boolean shouldBlock;        // 是否直接拦截
    private boolean inCooldown;         // 是否在验证冷却期内
    private String reason;              // 决策原因
    private Map<String, Integer> dimensionScores;  // 各维度评分明细
}

public enum RiskLevel {
    LOW(0, 29),       // 低风险
    MEDIUM(30, 59),   // 中风险
    HIGH(60, 84),     // 高风险
    CRITICAL(85, 100); // 极高风险
    
    public final int min;
    public final int max;
    RiskLevel(int min, int max) { this.min = min; this.max = max; }
}
```

> 写入策略：异步批量写入（内存队列聚合，500 条或 2 秒刷库）；评估 QPS 峰值 1500 时不阻塞主链路。降库失败仅丢弃并计数告警，不影响决策（Redis 决策缓存 10 分钟内可重放）。

```sql
ALTER TABLE verification_scene
    ADD COLUMN token_ttl_seconds INT NOT NULL DEFAULT 120 COMMENT '令牌有效期(秒)' AFTER cooldown_seconds,
    ADD COLUMN sms_upgrade_enabled TINYINT NOT NULL DEFAULT 1 COMMENT '是否允许短信升级验证' AFTER token_ttl_seconds;

    ADD COLUMN assess_id VARCHAR(64) NULL COMMENT '关联评估ID' AFTER risk_score,
    ADD COLUMN upgraded_from VARCHAR(32) NULL COMMENT '无感验证升级前的方式(INVISIBLE->SLIDER)' AFTER verify_type,

-- 令牌表：消费方可观测

    ADD KEY idx_scene_expire (scene_code, expire_at);
```

#### 2.4.4 增补 Redis 键

```

CACHE:assess:{assessId}
  → { scene_code, risk_score, decision, recommend_type, dims, degraded_dims }
  TTL: 600s（与 expire_at 一致）

# 评估结果回放（幂等重放窗口内重复 token 签发复用） (String)

CACHE:token_ro:{tokenValueHash}
  → JSON { tokenId, scene, uid, did, risk, exp }

# 双人审批待决队列 (ZSET)
CACHE:approval_pending:scene_config
  → score=提交时间, member=变更单ID
  TTL: 7d（超时自动过期作废）
```

- `recordId` 一次性：记录状态离开 PENDING 后再次提交，按状态返回 55804（终态拒绝）或 55807（超时）；

#### 3.2.9 服务间内部接口（gRPC）

业务服务内联调用（如 AI 网关转发前同步评估）对延迟敏感，提供 gRPC 接口；REST 与 gRPC 共享同一决策引擎，语义完全一致。

```protobuf
syntax = "proto3";
package urve.v1;

service UrveService {
  // 风险评估：返回是否需要验证及推荐验证方式
  rpc RiskAssess (RiskAssessRequest) returns (RiskAssessReply);
  // 令牌校验：与 REST token-check 语义一致（含消费语义）
  rpc CheckToken (TokenCheckRequest) returns (TokenCheckReply);
  // 信任回传：业务方发现违规后反向上报（如令牌关联请求事后判恶意）
  rpc ReportAbuse (ReportAbuseRequest) returns (ReportAbuseReply);
}

message RiskAssessRequest {
  string scene_code = 1;
  int64 user_id = 2;
  string device_id = 3;
  string client_ip = 4;
  string user_agent = 5;
  map<string, string> device_info = 6;
  string business_id = 7;
}

message RiskAssessReply {
  int32 risk_score = 1;
  string risk_level = 2;              // LOW/MEDIUM/HIGH/CRITICAL
  bool should_verify = 3;
  bool should_block = 4;
  bool in_cooldown = 5;
  string recommend_verify_type = 6;
  string assess_id = 7;
  int64 expire_at_epoch = 8;          // 评估结果有效期（10 分钟）
  map<string, int32> dimension_scores = 9;
}

message TokenCheckRequest {
  string token_value = 1;
  string scene_code = 2;
  int64 user_id = 3;
  string device_id = 4;
  bool consume = 5;
  string consumer_service = 6;
}

message TokenCheckReply {
  bool valid = 1;
  int32 err_code = 2;                 // 无效时返回 55810~55815 对应码
  int32 risk_score = 3;
  string token_id = 4;
}

message ReportAbuseRequest {
  string token_id = 1;                // 关联令牌
  string scene_code = 2;
  string abuse_type = 3;              // SCRIPT / SCRAPE / FAKE_ORDER / SPAM
  string evidence = 4;                // 证据摘要（≤512 字符）
}

message ReportAbuseReply {
  bool accepted = 1;
}
```

**延迟预算：** `RiskAssess` P99 ≤ 30ms（纯 Redis + 本地规则，外部依赖全部带 50ms 超时与降级，见 §4.1）；`CheckToken` P99 ≤ 10ms（Redis 快路径 + HMAC 本地验签）。

**鉴权：** 服务间 mTLS + service_token 双重校验，未注册的服务调用直接拒绝（55820），防止引擎被恶意刷探测。`ReportAbuse` 回传将作为设备/IP 信誉负向证据（权重见 §4.1 表）。

## 4. 核心流程与关键代码

### 4.1 风险评估引擎（RiskAssessEngine）

五维并行评估，加权合成；任一维度进入 CRITICAL 区间时触发抬升规则（防加权平均掩设单点极高风险）。

**维度定义与权重：**

| 维度 | 权重 | 数据源 | 降级中性分 |
|------|------|--------|------------|
| ipRisk | 25% | `ip_reputation` 表 + `CACHE:ip_risk` + 网段黑名单 | 40 |
| deviceRisk | 25% | 设备指纹引擎 gRPC `risk_score`（root/模拟器/多账号） | 40 |
| frequencyRisk | 20% | Redis ZSET 分钟/小时窗（ip + device + user 三键） | 50（无法统计时） |
| accountRisk | 15% | 登录风控引擎账号风险分（新注册/无实名/历史封禁） | 40 |
| behaviorRisk | 15% | 前端轨迹熵/直线度（无轨迹时） | 50（视为未知） |

**合成公式：**

```
weighted = Σ(dim_i × weight_i)
if 任一 dim_i >= 85:            // 单点极高风险抬升
    final = max(weighted, dim_i + 15)   // 封顶100
else:
    final = weighted
```

**关键代码：**

```java
@Service
public class RiskAssessEngine {

    private static final long EXTERNAL_TIMEOUT_MS = 50;  // 外部依赖统一超时预算

    // 各维度并行评估，CompletableFuture + 独立线程池（对齐线程池治理规范，urm-assess 池）
    public RiskAssessResult assess(RiskAssessRequest req) {
        SceneConfig scene = sceneConfigService.get(req.getSceneCode());

        var fIp    = CompletableFuture.supplyAsync(() -> assessIp(req), assessPool);
        var fDev   = CompletableFuture.supplyAsync(() -> assessDevice(req), assessPool);
        var fFreq  = CompletableFuture.supplyAsync(() -> assessFrequency(req), assessPool);
        var fAcct  = CompletableFuture.supplyAsync(() -> assessAccount(req), assessPool);
        var fBehav = CompletableFuture.supplyAsync(() -> assessBehavior(req), assessPool);

        try {
            CompletableFuture.allOf(fIp, fDev, fFreq, fAcct, fBehav)
                    .get(EXTERNAL_TIMEOUT_MS * 3, TimeUnit.MILLISECONDS);
        } catch (Exception e) {
            // 未完成的维度用中性分克底（getNow 已在各自内部超时降级，此处兑底防整体拖尾）
        }

        int ip = fIp.getNow(40), dev = fDev.getNow(40), freq = fFreq.getNow(50),
            acct = fAcct.getNow(40), behav = fBehav.getNow(50);

        int weighted = (int) Math.round(ip * .25 + dev * .25 + freq * .20 + acct * .15 + behav * .15);
        int maxDim = Math.max(Math.max(ip, dev), Math.max(Math.max(freq, acct), behav));
        int finalScore = (maxDim >= 85) ? Math.min(100, Math.max(weighted, maxDim + 15)) : weighted;

        return buildResult(scene, finalScore, Map.of(
                "ipRisk", ip, "deviceRisk", dev, "frequencyRisk", freq,
                "accountRisk", acct, "behaviorRisk", behav), collectDegradedDims());
    }

    /** IP 维度：黑名单直接 100，其余按信誉分 + 类型加权 */
    private int assessIp(RiskAssessRequest req) {
        try {
            IpReputation rep = ipRepo.findWithCache(req.getClientIp());   // 60s缓存
            if (rep == null) return 40;                                    // 未知IP中性
            int s = rep.getRiskScore();
            if (rep.isBlacklisted()) return 100;
            if ("DATACENTER".equals(rep.getIpType())) s = Math.max(s, 55);
            if ("PROXY".equals(rep.getIpType()) || "TOR".equals(rep.getIpType())) s = Math.max(s, 70);
            s += Math.min(15, rep.getBlockedCount() * 3);                   // 历史被拦截加分
            s += Math.min(10, rep.getVerifyFailCnt() * 2);                  // 历史验证失败加分
            return Math.min(100, s);
        } catch (Exception e) { degraded("ip"); return 40; }
    }

    /** 设备维度：委托设备指纹引擎，50ms超时降级 */
    private int assessDevice(RiskAssessRequest req) {
        if (isBlank(req.getDeviceId())) return 60;                          // 无指纹=高危特征
        try {
            return deviceFingerprintClient.queryRiskScore(req.getDeviceId())
                       .get(EXTERNAL_TIMEOUT_MS, TimeUnit.MILLISECONDS);
        } catch (Exception e) { degraded("device"); return 40; }
    }

    /** 频率维度：同IP+同设备双窗口（ZSET），1分钟/1小时 */
    private int assessFrequency(RiskAssessRequest req) {
        try {
            long minuteIp  = freqCounter.count("ip", req.getClientIp(), 60);
            long minuteDev = freqCounter.count("dev", req.getDeviceId(), 60);
            long hourIp    = freqCounter.count("ip", req.getClientIp(), 3600);
            int s = 0;
            if (minuteIp  >= 30) s = Math.max(s, 85); else if (minuteIp  >= 15) s = Math.max(s, 60);
            if (minuteDev >= 30) s = Math.max(s, 85); else if (minuteDev >= 15) s = Math.max(s, 60);
            if (hourIp   >= 200) s = Math.max(s, 75); else if (hourIp  >= 100) s = Math.max(s, 50);
            return Math.min(100, s);
        } catch (Exception e) { degraded("frequency"); return 50; }
    }

    /** 账号维度：委托登录风控引擎；匿名场景（未登录）固定 45（不可信不可疑） */
    private int assessAccount(RiskAssessRequest req) {
        if (req.getUserId() == null) return 45;
        try {
            return accountRiskClient.queryScore(req.getUserId())
                       .get(EXTERNAL_TIMEOUT_MS, TimeUnit.MILLISECONDS);
        } catch (Exception e) { degraded("account"); return 40; }
    }

    /** 行为维度：轨迹熵+直线度；无轨迹中性50 */
    private int assessBehavior(RiskAssessRequest req) {
        List<Float> trace = req.getBehaviorTrace();
        if (trace == null || trace.size() < 5) return 50;
        double entropy = BehaviorFeatureUtil.approximateEntropy(trace);
        double straightness = BehaviorFeatureUtil.straightness(trace);
        if (entropy < 0.3 || straightness > 0.98) return 90;  // 机器轨迹：低熵/超直
        if (entropy < 0.6) return 65;
        return 15;                                           // 自然人类轨迹
    }
}
```

**评估结果缓存：** 评估完成写 `CACHE:assess:{assessId}`（TTL 600s）与异步落 `verification_assess`（批量）。同一 `(scene, deviceId, ip)` 在 3 秒内的重复评估直接返回上次结果（评估去抖，防同一请求重试打爆）。

### 4.2 策略决策引擎（DecisionEngine）

决策顺序：**场景开关 → 封禁检查 → 冷却检查 → 阈值三段 → 强度升级 → 降级标记合成**。

**决策表（核心顺序即优先级）：**

| # | 前置条件 | 决策 | 说明 |
|---|----------|------|------|
| 1 | scene.enabled = false | PASS（SCENE_DISABLED） | 场景停用，评估短路 |
| 2 | 主体在封禁名单 `CACHE:ban:{subject}:{scene}` | BLOCK | 失败超限临时封禁中 |
| 3 | IP 黑名单命中 | BLOCK | ipRisk=100 已抬升，此处双重兑底 |
| 4 | 冷却标记存在 `CACHE:verify_cooldown` | PASS（inCooldown=true） | 冷却期内免验（附带剩余时间） |
| 5 | riskScore ≤ threshold_pass | PASS + 直接签发低风险令牌 | 令牌 riskScore 冗余记录 |
| 6 | riskScore > threshold_block | BLOCK | 记录 BLOCKED，写 Outbox 事件 |
| 7 | threshold_verify ≤ score ≤ threshold_block | VERIFY（强度见升级矩阵） | 主路径 |
| 8 | threshold_pass < score < threshold_verify | VERIFY（默认方式，轻度） | 或直接PASS——按场景阈值语义，此处为触发默认验证 |

**验证强度升级矩阵（分数区间 × 场景大类 → 验证方式）：**

| 分数区间 | AUTH | RESOURCE | TRANSACTION | MARKETING |
|----------|------|----------|-------------|-----------|
| pass < s < verify | NONE（直接签发） | NONE | SLIDER | SLIDER |
| verify ≤ s < verify+15 | SLIDER | INVISIBLE | SLIDER | CLICK |
| verify+15 ≤ s < block | CLICK | SLIDER | CLICK | CLICK |
| s ≥ block 且 sms_upgrade_enabled 且已绑定手机且非未成年人 | SMS_UPGRADE | —（RESOURCE 不升级，直接 BLOCK 降级为 SLIDER+人工观察） | SMS_UPGRADE | SMS_UPGRADE |

> SMS_UPGRADE 仅在 TRANSACTION/AUTH/MARKETING 且风险极高时触发；未成年人账号（is_child）禁止 SMS_UPGRADE（短信打扰合规，见 §10），降级 CLICK + 账号维度负向记录。

**关键代码：**

```java
@Service
public class DecisionEngine {

    public Decision decide(SceneConfig cfg, RiskAssessResult risk, SubjectContext ctx) {
        // 1. 场景停用
        if (!cfg.isEnabled()) return Decision.pass("SCENE_DISABLED", risk);
        // 2. 封禁中
        if (banService.isBanned(ctx, cfg.getSceneCode()))
            return Decision.block("BANNED_FAIL_EXCEEDED", risk);
        // 3. IP黑名单（评估已抬升，此处兑底拦截）
        if (risk.getDimensionScores().get("ipRisk") >= 100)
            return Decision.block("IP_BLACKLISTED", risk);
        // 4. 冷却期
        OptionalLong cooldownRemain = cooldownService.remaining(ctx, cfg.getSceneCode());
        if (cooldownRemain.isPresent())
            return Decision.pass("IN_COOLDOWN", risk, cooldownRemain.getAsLong());
        // 5. 阈值三段
        int s = risk.getRiskScore();
        if (s <= cfg.getRiskThresholdPass())
            return Decision.passWithToken("LOW_RISK", risk);      // 直接签发
        if (s > cfg.getRiskThresholdBlock())
            return Decision.block("RISK_EXCEED_BLOCK", risk);
        // 6. 强度升级
        VerifyType type = upgradeMatrix.resolve(cfg.getSceneCategory(), s, cfg, ctx);
        if (type == VerifyType.SMS_UPGRADE && !ctx.canSmsUpgrade())   // 未成年人/无手机号
            type = VerifyType.CLICK;
        return Decision.verify(type, risk);
    }
}
```

**BLOCK 的副作用：** 写 `verification_record(status=BLOCKED)` + Outbox `VERIFICATION_BLOCKED` 事件（风控画像消费）；同主体 5 分钟内重复 BLOCK 升级为 30 分钟临时封禁（防止持续探测）。BLOCK 响应对客户端不暴露具体维度分（防攻击者探测规则）。

### 4.3 验证调度引擎（ProviderRouter）

多服务商路由：正常态按健康集合加权分流（主离+灰度观察新服务商），异常态按优先级熔断切换。

**选择算法：**

```
1. 取 enabled=true 且 health != UNAVAILABLE 的服务商集合 S
2. 若 S 为空 → 返回 INTERNAL（自研滑块，永不下线，见 §4.4）
3. 若 |S| >= 2 且主服务商 health == HEALTHY 且未超过 qps_limit：
     按权重加权随机（如主90% / 备10%灰度），避免全量压单家
   否则取 S 中 priority 最小者
4. 超过 qps_limit 的服务商从 S 中剔除
```

**健康探测：** 每 30 秒对启用中服务商发探测请求（轻量 captcha 会话创建+立即作废）：成功率 <90% 降为 DEGRADED（降权重为 0，仅容灾保留），连续 3 次探测失败置 UNAVAILABLE 并告警；恢复探测成功 2 次回升 DEGRADED，成功率 ≥98% 回 HEALTHY。

**关键代码：**

```java
@Service
public class ProviderRouter {

    public VerifyProvider route(String sceneCode) {
        List<ProviderConfig> healthy = providerRepo.findEnabled().stream()
                .filter(p -> p.getHealth() != HealthStatus.UNAVAILABLE)
                .filter(p -> p.getCurrentQps() < p.getQpsLimit())
                .sorted(Comparator.comparingInt(ProviderConfig::getPriority))
                .toList();
        if (healthy.isEmpty()) return internalSliderProvider;      // 永久兑底

        ProviderConfig primary = healthy.get(0);
        if (healthy.size() >= 2 && primary.getHealth() == HealthStatus.HEALTHY) {
            return weightedPick(healthy);                           // 主服务商为主，灰度分流
        }
        return providerRegistry.get(primary.getProviderCode());
    }

    /** 二次校验失败/超时的即时切换：写入熔断标记，30s内不再路由到该商 */
    public void markCircuitOpen(String providerCode) {
        redis.setex("CACHE:provider_circuit:" + providerCode, 30, "open");
        healthMonitor.recordFailure(providerCode);
    }
}
```

### 4.4 内置滑块验证器（INTERNAL，永久兑底）

第三方全部不可用时的自研兑底，平时也可作为灰度分流目标。**安全设计核心：缺口位置只存服务端。**

**题目生成（预生成图库）：**

- 背景图库 500 张（动物/风景/学习场景，适龄），CDN 分发；
- 每次会话随机：背景图 + 缺口 x ∈ [40, 260] + y 固定带±8px 抖动 + 拼图形状（4 选 1）；
- 服务端会话（`CACHE:verify_session:{recordId}`）保存：`answerX、tolerance=6、createdAt`；
- 下发给客户端：`bgImageUrl、sliderImageUrl、sliderLength`——**不含 answerX**。

**校验算法（位置容差 + 轨迹特征双门槛）：**

```java
public boolean verify(String recordId, SliderAnswer ans) {
    VerifySession s = sessionRepo.get(recordId);        // Redis
    if (s == null || s.expired()) return retryOrFail(55807);

    // 门槛一：位置容差（双次容差策略：第1次失败容差不变，第2次起容差放宽到±8防误伤）
    int tol = s.getAttempt() >= 2 ? 8 : 6;
    boolean posOk = Math.abs(ans.sliderOffset - s.getAnswerX()) <= tol;

    // 门槛二：轨迹特征 5 项（任一顶线即判脚本，位置对也拒）
    Trace t = Trace.of(ans.getSliderTrace());
    boolean botLike =
        t.totalDurationMs() < 400                                   // 过快
     || t.totalDurationMs() > 8000                                  // 过慢（挂机重放）
     || t.speedVariance() < 0.02                                    // 匀速直线（电机特征）
     || t.yJitterCount() == 0 && t.sampleCount() > 8                // 零垂直抖动
     || t.pauseCount(150) > 3;                                      // 超过3次≥150ms停顿（分段注入）

    return posOk && !botLike;
}
```

> 轨迹特征阈值通过离线标注（众包真实用户样本 + 脚本生成样本）校准，季度复审；误伤率指标监控见 §9。位置正确但轨迹异常时**不提示具体原因**，统一返回“验证失败”（防规则探测）。

### 4.5 第三方适配层（VerifyProvider SPI）

统一抽象，四家适配器 + 内置实现；新增供应商只需实现 SPI 并注册。

```java
public interface VerifyProvider {
    String code();                                    // TENCENT/GEETEST/NETEASE/ALIYUN/INTERNAL
    CaptchaSession createSession(SceneConfig cfg, VerifySessionCtx ctx);   // 创建挑战（下发参数）
    boolean verifyResult(String recordId, Map<String, Object> clientPayload); // 二次校验
}
```

**四家适配要点（二次校验均为服务端调用，不信任客户端结果）：**

| 服务商 | 创建挑战 | 二次校验 | 超时/失败处理 |
|--------|----------|----------|----------------|
| 腾讯防水墙 | 前端 ticket + randstr | 服务端 `DescribeCaptchaResult`（appid + AppSecretKey + ticket） | 1.5s 超时 → failover 下一家或 INTERNAL |
| 极验 GeeTest v4 | 前端 lot_number / captcha_output / pass_token | 服务端 `validate` 接口（captcha_id + captcha_key） | 同上；验证成功后需主动作废会话 |
| 网易易盾 v2 | 前端 validate 字串 | 服务端 verify 二次校验（secretId + secretKey 签名） | 同上 |
| 阿里云验证码 | 前端 CaptchaVerifyParam | 服务端 VerifyIntelligentCaptcha（AccessKey 签名） | 同上 |

**统一规则：**

- 二次校验超时预算 1.5s，失败即 failover（记 `verify_provider` 实际使用方）；failover 后重新创建挑战而非沿用旧 payload（旧 payload 属于失败服务商会话）；
- `app_secret` 信封加密存储（对齐《服务端密钥管理与敏感配置安全策略》），运行时解密缓存 5 分钟；
- 供应商返回“验证通过”但会话已过期（如客户端重试旧 payload）按 55807 处理，不重复扣减尝试次数（幂等窗口内）；
- 每家适配器独立熔断标记（§4.3 markCircuitOpen），互不影响。

### 4.6 令牌服务（TokenService）

**令牌结构：** `vtd.{header}.{tokenId}.{hmacSig}`——header 为 base64url 的 `{"alg":"HS256","kid":"k2026a"}`；签名内容 = `tokenId + "\n" + scene + "\n" + uid + "\n" + did + "\n" + iat + "\n" + exp`。

- HMAC 密钥从密钥管理服务获取，双版本并行（kid 区分），每 90 天轮换，旧 kid 仅验签不签发（宽限 24h）；
- `tokenValue` 仅存哈希（SHA-256）入 `token_value` 列（库泄露不致令牌重放）；接口返回原始值给客户端；

**签发（同事务写 DB + 冷却标记，令牌生效）：**

```java
@Transactional
public IssuedToken issue(VerifyRecord rec, SceneConfig cfg) {
    String tokenId = "vt_" + IdGenerator.next();
    long now = Instant.now();
    long exp = now.plusSeconds(cfg.getTokenTtlSeconds());
    String raw = TokenCodec.encode(tokenId, rec, now, exp, hmacKey());

    tokenRepo.insert(TokenRow.of(tokenId, sha256(raw), rec, exp));   // status=1
    cooldownService.mark(rec.getSubjectKey(), cfg.getSceneCode(),
                         cfg.getCooldownSeconds());                    // 验证冷却
    return new IssuedToken(tokenId, raw, exp);
}
```

**校验五步（含消费，Redis 快路径）：**

```java
public TokenCheckReply checkAndConsume(String raw, String scene, Long uid, String did,
                                        boolean consume, String consumer) {
    // ① 本地验签（不落网络）；② 解析字段
    TokenClaims c = TokenCodec.decodeAndVerify(raw, hmacKeys());       // 失败→55810
    if (c.isExpired()) return invalid(55812);                          // ② 过期
    if (redis.exists("CACHE:token_revoked:" + c.tokenId)) return invalid(55813);  // ③ 撤销
    if (!c.scene.equals(scene)) return invalid(55814);                 // ④ 场景不匹配
    if (!c.subjectMatches(uid, did)) return invalid(55815);            // 主体转移

    // ⑤ 消费：DB CAS（0或1行）；consume=false 走只读快路径（30s缓存）
    if (consume) {
        int rows = jdbc.update("""
            UPDATE verification_token SET status=0, used_at=NOW(), used_by_service=?
            WHERE token_id=? AND status=1""", consumer, c.tokenId);
        if (rows == 0) return invalid(55811);                          // 已被并发消费
    }
    return valid(c);
}
```

> 高频低风险令牌（riskScore ≤ pass 阈值直接签发）与验证通过令牌同结构、同消费语义，业务方无需区分。

## 5. 状态机设计

### 5.1 验证记录状态机（verify_status）

```
               ┌──────────────────┐
               │      PENDING     │  创建验证 / 校验未过且未超限（attempt_count累加，仍为PENDING）
               └───┬────┬────┬────┘
     校验通过      │    │    │   超时未提交(180s会话过期)
                   ▼    │    ▼
           ┌─────────┐ │ ┌──────────┐
           │ SUCCESS │ │ │  TIMEOUT │
           └─────────┘ │ └──────────┘
    失败次数达max_fail_attempts │
                   ▼    │
           ┌─────────┐ ┌──┴──────────┐
           │ BLOCKED │ │   FAILED    │  判定失败且不再重试（终态：如无感评分极低且不升级）
           └─────────┘ └────────────┘
   另：创建时风险评估即拦截 → 直接写入 BLOCKED（无 PENDING 阶段）
```

### 5.2 令牌状态机（status 列）

```
签发→ 1(有效) ──消费──▶ 0(已使用)
         ├──自然到期──▶ 2(已过期)   （惰性标记：校验时发现过期才写，扫描任务批量补齐）
         └──撤销────▶ 3(已撤销)
```

### 5.3 服务商健康状态机（health_status）

```
HEALTHY ──探测成功率<90%/二次校验失败率>8%──▶ DEGRADED ──连续3次探测失败──▶ UNAVAILABLE
UNAVAILABLE ──探测成功2次──▶ DEGRADED ──成功率≥98%持续10min──▶ HEALTHY
DEGRADED 状态权重置0，仅 priority 兑底保留；熔断标记独立（30s）叠加生效
```

## 6. 事件与 Outbox

### 6.1 事件定义（Topic：verification.domain.events）

| 事件类型 | 触发时机 | 关键字段 | 主要消费方 |
|----------|----------|----------|------------|
| VERIFICATION_PASSED | 记录转 SUCCESS（含无感/滑块/短信） | recordId, sceneCode, userId, deviceId, ip, verifyType, durationMs | 统一风控画像（正向信誉）、埋点平台 |
| VERIFICATION_BLOCKED | 评估拦截或失败超限封禁 | recordId, sceneCode, subject, reason, riskScore | 统一风控画像（负向）、登录风控、告警 |
| FAIL_EXCEEDED_BANNED | 失败超限触发临时封禁 | subject, sceneCode, banUntil | 告警、风控画像 |
| ABUSE_REPORTED | 业务方 ReportAbuse 回传 | tokenId, abuseType, evidence | 风控画像、设备指纹引擎（信誉回流） |
| IP_BLACKLISTED / IP_REMOVED | IP 名单变更 | ip, reason, operator | 反爬虫引擎（同步缓存）、风控画像 |
| SCENE_CONFIG_CHANGED | 配置发布生效 | sceneCode, diff | 埋点平台（前后对比实验标记） |
| PROVIDER_HEALTH_CHANGED | 健康状态流转 | providerCode, from, to | 告警、成本引擎（分流变化） |

**幂等：** 消费方以 `(event_id, consumer)` 去重；Outbox Relay 每秒扫描 PENDING 行发布（顺序保证同一 aggregate 内单调），失败退避 2^n 重试 8 次后置 DEAD + P2 告警；日终对账任务比对 Outbox 与已发布确认数。

### 6.2 与风控画像的信誉回流闭环

```
验证通过 ──▶ 信誉正向 +2（设备/IP，日累计上限 +6）
验证拦截 ──▶ 信誉负向 +15
失败封禁 ──▶ 信誉负向 +30，并同步设备指纹引擎 risk_events
业务事后判恶意(ReportAbuse) ──▶ 负向 +40，触发画像重算（异步）
```

## 8. 降级矩阵与容灾策略

**总原则（fail-secure）：** 验证体系宁可多挑战、不可静默放行；但冷却/低风险路径的体验保护优先于重复强挑战。

| # | 故障场景 | 降级策略 | 用户感知 |
|---|----------|----------|----------|
| D1 | 第三方验证码全部不可用 | 路由 INTERNAL 自研滑块（永久兑底） | 换样式，无功能损失 |
| D2 | 单家第三方二次校验超时/失败 | 30s 熔断 + failover 下一家；挑战重建 | 无感（自动重发挑战） |
| D3 | Redis 集群不可用 | 频率统计降级 DB 滑动窗口（分钟级精度）；冷却标记降级 DB 查询最近 SUCCESS；verify_session 落 DB 临时表 | 评估延迟上升，决策不放宽 |
| D4 | 设备指纹引擎超时 | dim_device=中性40，升级默认验证方式一档（INVISIBLE→SLIDER） | 可能多见滑块 |
| D5 | 登录风控引擎超时 | dim_account=中性40 | 无感 |
| D6 | 密钥管理服务不可用 | 本地缓存旧密钥续用（宽限24h，超时告警 P1） | 无感 |
| D7 | MySQL 不可用 | 已签发令牌走 Redis 只读快路径放行校验（只读不消费，消费延后补记）；新验证会话暂停并返回 55824（不静默放行新挑战） | 新验证提示稍后重试 |
| D8 | 短信网关不可用 | SMS_UPGRADE 降级 CLICK，记录 degraded_dims | 多见点选验证 |
| D9 | 评估 QPS 超自身限流阈值 | 未命中去抖缓存的请求直接返回默认 INVISIBLE 挑战（保守挑战而非放行） | 无感（可能多一次无感验证） |
| D10 | 滑块图库 CDN 不可用 | 服务端动态生成 SVG 参数图（无图库依赖，画质降级） | 图片变简洁样式 |

**与业务方的降级契约：** URVE 整体不可用时，业务方按各自场景的兑底策略执行（如登录风控文档的 CHALLENGE 分支强制短信验证码、领券默认拒绝）——本引擎宕机不等于放行，已在各消费方文档约定。

## 9. 监控、告警与容量规划

### 9.1 核心指标

| # | 指标 | 口径 | 告警阈值 |
|---|------|------|----------|
| 1 | assess_qps / assess_p99_ms | gRPC+REST 合并 | P99 > 30ms 持续 5min（P2） |
| 2 | verify_trigger_rate | 验证触发次数 / 评估次数 | 单场景周环比 +50%（误伤或攻击，人工判读） |
| 3 | verify_pass_rate | 一次通过 / 全部尝试（按场景） | < 70% 持续 1h（误伤告警 P1）；> 99.5%（脚本绕过嫌疑 P2） |
| 4 | first_attempt_pass_rate | 首次提交即过率 | < 85% 触发滑块参数复审 |
| 5 | provider_success_rate / latency | 二次校验成功率和延迟（分服务商） | < 90% 或 P99 > 1.5s（自动熔断 + 告警） |
| 6 | token_check_p99_ms | 含 CAS 消费 | > 10ms 持续 5min（P2） |
| 7 | blocked_count_5min | BLOCK 总量滑动窗口 | 环比 5 倍突增（攻击告警 P1，联动反爬虫） |
| 8 | fail_banned_count | 失败封禁数（日） | 突增触发黑产打击预案 |
| 9 | invisible_upgrade_rate | 无感验证升级 SLIDER 比例 | > 40% 说明行为模型阈值漂移，需重新校准 |
| 10 | cooldown_hit_rate | 冷却命中 / 评估总量 | < 50%（正常用户被反复挑战，体验劣化 P2） |

### 9.2 容量估算（DAU 50 万）

- **评估调用：** 登录+注册+AI+拍题+支付+领券等，日均 ≈ 600 万次，晚高峰 QPS ≈ 1500，评估 P99 ≤ 30ms；单评估 Redis 读 ≤ 8 次、外部 gRPC ≤ 2 次（均 50ms 超时）；
- **验证触发：** 触发率 8% → 日 ≈ 48 万次（含无感）；可见挑战（滑块/点选）占其中 ≈ 25%；第三方调用日 ≈ 12 万次，成本可控（单次约 ¥0.003，月 ≈ ¥1.1万）；
- **存储：** verification_assess 日增 600 万行（含重复去抖后 ≈ 480 万），按月分区，在线 90 天 + 归档 ClickHouse 180 天；verification_record 日增 ≈ 48 万行；令牌表日增 55 万行，过期行由扫描任务 7 天后物理清理；
- **Redis：** 频率 ZSET + 会话 + 冷却 + 令牌黑名单峰值内存 ≈ 2.5GB（含 30% 冗余）；
- **部署：** 独立部署单元 4 副本起（CPU 密集度低，IO 等待型），支持水平扩展；HMAC 验签本地无状态。
