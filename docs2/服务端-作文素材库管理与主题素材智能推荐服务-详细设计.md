## 1. 概述

### 1.1 文档目的

定义 PrimeTop 作文素材库的数据结构、内容生产管线、分类标签体系、检索引擎和智能推荐算法，使开发人员能够据此实现完整的素材管理与推荐服务。

### 1.2 范围

| 范围内 | 范围外 |
| --- | --- |
| 素材数据模型与存储设计 | 作文批改评分引擎（见《服务端-作文批改评分引擎与写作能力评估服务》） |
| 素材分类标签体系 | 作文辅导页面交互（见《客户端-作文辅导页面架构与批改交互设计》） |
| 素材内容生产与审核流程 | 富文本编辑器（见《客户端-富文本编辑器与作文书写引擎》） |
| 全文检索与语义检索 | AI Prompt 编排系统（见《AI-Prompt编排与场景模板系统》） |
| 主题匹配推荐算法 | 向量数据库基础设施 |
| 学段适龄化过滤 | 搜索服务通用基础设施 |
| 个性化推荐（基于写作历史） | 通用推荐引擎框架 |
| 素材使用效果追踪 | 支付与会员权益校验 |
| 管理后台素材管理 API | 内容安全审核通用服务 |

### 1.3 术语定义

| 术语 | 含义 |
| --- | --- |
| Material | 素材，作文素材库中的单条内容单元 |
| MaterialType | 素材类型：quote（名言警句）、story（事例典故）、expression（表达句式）、vocabulary（好词好句）、opening（开头模板）、ending（结尾模板）、transition（过渡衔接） |
| Theme | 主题标签，素材关联的写作主题，如"坚持""成长""亲情""环保" |
| SceneTag | 场景标签，素材适用的写作场景，如"议论文论据""记叙文开头""描写抒情" |
| MaterialCollection | 素材合集，按主题或用途组织的素材集合 |
| WritingProfile | 写作能力画像，用于个性化推荐的数据基础 |

### 1.4 设计原则

1. **分类精细**：素材按类型、主题、场景、学段、文体等多维度标签化，支持精准匹配。
2. **适龄过滤**：高中素材不应出现在小学生推荐中，确保内容认知水平匹配。
3. **主题驱动**：以作文题目主题为核心匹配维度，优先推荐与主题强相关的素材。
4. **个性化补充**：基于用户历史写作数据和薄弱维度，补充个性化推荐。
5. **质量可控**：所有入库素材需经过审核，AI 生成素材需人工复核。
6. **扩展友好**：素材类型和标签体系可动态扩展，不依赖硬编码枚举。

## 3. 数据模型

### 3.1 素材主表 `essay_materials`

```sql
CREATE TABLE essay_materials (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '素材ID',
    -- 内容
    material_type   VARCHAR(20) NOT NULL COMMENT '素材类型: quote/story/expression/vocabulary/opening/ending/transition',
    title           VARCHAR(200) NOT NULL COMMENT '素材标题（用于展示和检索）',
    content         TEXT NOT NULL COMMENT '素材正文',
    source          VARCHAR(200) COMMENT '出处/作者（名言类必填，如 "苏轼《赤壁赋》"）',
    source_type     VARCHAR(20) COMMENT '来源类型: classic（古籍经典）/ modern（近现代）/ foreign（外国）/ ai_generated（AI生成）/ user_extracted（用户沉淀）',
    
    -- 分类标签
    themes          JSON NOT NULL COMMENT '主题标签 ["坚持","奋斗","成长"]',
    scene_tags      JSON COMMENT '场景标签 ["议论文论据","开头引入","结尾升华"]',
    genres          JSON COMMENT '适用文体 ["narrative","argumentative","expository"]',
    
    -- 学段适配
    min_stage       VARCHAR(10) NOT NULL DEFAULT 'primary' COMMENT '最低适用学段: kindergarten/primary/junior/senior',
    max_stage       VARCHAR(10) NOT NULL DEFAULT 'senior' COMMENT '最高适用学段',
    min_grade       INT COMMENT '最低适用年级（1-12，为空表示不限制）',
    max_grade       INT COMMENT '最高适用年级',
    difficulty_level TINYINT NOT NULL DEFAULT 1 COMMENT '理解难度: 1=简单 2=中等 3=较深',
    
    -- 统计
    usage_count     INT NOT NULL DEFAULT 0 COMMENT '被引用次数',
    like_count      INT NOT NULL DEFAULT 0 COMMENT '收藏次数',
    avg_score       DECIMAL(3,2) COMMENT '平均评分（用户反馈 1-5）',
    
    -- 状态
    status          TINYINT NOT NULL DEFAULT 0 COMMENT '状态: 0=草稿 1=待审核 2=已上架 3=已下架 4=审核拒绝',
    audit_remark    VARCHAR(500) COMMENT '审核备注',
    audited_by      BIGINT COMMENT '审核人ID',
    audited_at      DATETIME COMMENT '审核时间',
    
    -- 元数据
    source_id       VARCHAR(100) COMMENT '外部来源ID（导入时标记去重）',
    vector_status   TINYINT NOT NULL DEFAULT 0 COMMENT '向量化状态: 0=未处理 1=处理中 2=已完成 3=失败',
    vector_task_id  VARCHAR(100) COMMENT '向量化任务ID',
    
    created_by      BIGINT COMMENT '创建人ID（后台管理员/系统）',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_type_status (material_type, status),
    INDEX idx_stage (min_stage, max_stage),
    INDEX idx_usage (usage_count DESC),
    INDEX idx_created (created_at DESC),
    INDEX idx_source_id (source_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='作文素材库';
```

## 4. 素材标签体系设计

### 4.1 主题标签分类

素材主题按六大类别组织，支持两级层级：

| 一级分类 | 说明 | 二级示例 |
| --- | --- | --- |
| personal（个人品质） | 个人成长、品质修养 | 坚持、勇敢、诚信、勤奋、创新、乐观、自律、责任 |
| social（社会关系） | 人际、家国、社会 | 亲情、友情、师生、团结、合作、爱国、奉献、感恩 |
| nature（自然） | 自然环境、科技 | 环保、四季、山水、星辰、探索、科技、生态 |
| culture（文化） | 文化传承、艺术 | 读书、传统、历史、艺术、语言、文明、礼仪 |
| philosophy（哲理） | 思辨、哲理、人生 | 时间、选择、变化、得失、平凡、自由、幸福、价值 |
| life（生活） | 日常生活、体验 | 成长、梦想、青春、旅行、美食、运动、校园 |

### 4.2 场景标签

| 场景标签 | 说明 | 适用素材类型 |
| --- | --- | --- |
| `argue_evidence` | 议论文论据 | story, quote |
| `narrative_opening` | 记叙文开头 | opening |
| `narrative_ending` | 记叙文结尾 | ending |
| `descriptive_detail` | 描写细节 | expression, vocabulary |
| `transition_connect` | 过渡衔接 | transition |
| `emotional_expression` | 情感抒发 | expression, quote |
| `argument_opening` | 议论文开头 | opening |
| `argument_ending` | 议论文结尾 | ending |
| `rhetoric_device` | 修辞手法 | expression |
| `contrast_reference` | 对比引用 | story, quote |

### 4.3 学段-难度映射

```
kindergarten (幼儿)  → difficulty_level = 1
primary_low (小学低)  → difficulty_level = 1-2
primary_high (小学高) → difficulty_level = 1-2
junior (初中)         → difficulty_level = 1-3
senior (高中)         → difficulty_level = 1-3
```

具体映射规则：
- 小学低年级（1-3年级）：只推荐 difficulty_level=1 的素材，语言通俗简短
- 小学高年级（4-6年级）：推荐 difficulty_level=1-2，引入中等长度素材
- 初中（7-9年级）：推荐 difficulty_level=1-3，鼓励引用经典名句
- 高中（10-12年级）：全量可用，侧重思辨性和深度素材

## 6. 核心算法：素材推荐引擎

### 6.1 推荐流程总览

```
作文题目 + 用户上下文
        │
        ▼
  ┌─────────────────┐
  │ 1. 主题解析     │  提取题目核心主题词
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 2. 候选召回     │  多路召回：主题匹配 + 语义召回 + 热门兜底
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 3. 适龄过滤     │  根据学段、年级、难度过滤不适宜素材
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 4. 精排打分     │  综合相关性、质量分、个性化偏好排序
  └────────┬────────┘
           │

  │ 5. 多样性打散   │  类型打散 + 主题打散，避免推荐同质化
  └────────┬────────┘

  └────────┬────────┘
```

### 6.2 主题解析算法

对作文题目进行结构化分析，提取核心主题：

```java
public class ThemeAnalyzer {
    
    /**
     * 分析作文题目，提取主题词和匹配信息
     */
    public ThemeAnalysisResult analyze(String essayTitle, String genre, List<String> keywords) {
        ThemeAnalysisResult result = new ThemeAnalysisResult();
        
        // 1. 关键词直接匹配主题词表
        List<ThemeMatch> directMatches = matchThemesByKeywords(
            mergeKeywords(essayTitle, keywords)
        );
        
        // 2. 语义相似度匹配（通过向量库）
        List<ThemeMatch> semanticMatches = matchThemesBySemantic(essayTitle);
        
        // 3. 合并去重，按匹配分数排序
        List<ThemeMatch> merged = mergeAndDeduplicate(directMatches, semanticMatches);

        // 4. 取 Top-3 主题为主主题，其余为关联主题
        List<ThemeMatch> topThemes = merged.stream()
            .limit(3)
            .collect(Collectors.toList());

        if (!topThemes.isEmpty()) {
            result.setPrimaryTheme(topThemes.get(0).getTheme());
            result.setThemeId(topThemes.get(0).getThemeId());
            result.setRelatedThemes(
                topThemes.subList(1, topThemes.size()).stream()
                    .map(ThemeMatch::getTheme)
                    .collect(Collectors.toList())
            );
            result.setConfidence(topThemes.get(0).getScore());
        }

        // 5. 低置信度兜底：最高匹配分低于 0.5 时，按文体注入默认主题，防止召回为空
        if (result.getConfidence() < 0.5) {
            result.setFallbackThemes(getDefaultThemesByGenre(genre));
            result.setConfidence(0.5); // 兜底主题置信度统一记 0.5，日志打 fallback=true 便于监控兜底率
        }

        return result;
    }

    /**
     * 关键词与主题词表（含同义词）匹配：精确词 1.0，同义词 0.9
     */
    private List<ThemeMatch> matchThemesByKeywords(List<String> keywords) {
        List<EssayMaterialTheme> allThemes = themeCache.getAllActive(); // 本地缓存 10min，Redis 宕见 §12-D5
        Map<String, EssayMaterialTheme> synonymIndex = buildSynonymIndex(allThemes);

        return keywords.stream()
            .map(kw -> {
                EssayMaterialTheme theme = synonymIndex.get(kw);
                if (theme == null) return null;
                boolean exact = theme.getThemeName().equals(kw);
                double score = exact ? 1.0 : 0.9;
                return new ThemeMatch(theme.getId(), theme.getThemeName(), score, "keyword");
            })
            .filter(Objects::nonNull)
            .collect(Collectors.toList());
    }

    /**
     * 题目语义向量与主题描述向量求余弦相似度，阈值 0.75 才采纳
     */
    private List<ThemeMatch> matchThemesBySemantic(String essayTitle) {
        return vectorSearchService.matchThemes(essayTitle, /*minScore*/0.75, /*limit*/5);
    }

    /**
     * 双通道合并：keyword 与 semantic 命中同一主题时按 1-(1-a)(1-b) 融合并标记 dual
     */
    private List<ThemeMatch> mergeAndDeduplicate(List<ThemeMatch> direct, List<ThemeMatch> semantic) {
        Map<String, ThemeMatch> merged = new LinkedHashMap<>();
        for (ThemeMatch m : direct) {
            merged.put(m.getTheme(), m);
        }
        for (ThemeMatch m : semantic) {
            merged.merge(m.getTheme(), m, (a, b) -> new ThemeMatch(
                a.getThemeId(),
                a.getTheme(),
                1 - (1 - a.getScore()) * (1 - b.getScore()),
                "dual"
            ));
        }
        return merged.values().stream()
            .sorted(Comparator.comparingDouble(ThemeMatch::getScore).reversed())
            .collect(Collectors.toList());
    }

    /**
     * 文体默认主题兜底（fail-soft，仅用于召回，不作为最终主题分析结果展示）
     */
    private List<String> getDefaultThemesByGenre(String genre) {
        switch (genre == null ? "narrative" : genre) {
            case "argumentative": return List.of("思辨", "社会", "价值");
            case "expository":    return List.of("知识", "探索", "方法");
            default:              return List.of("成长", "生活", "情感");
        }
    }
}
```

**主题解析延迟预算**：整体 ≤150ms（关键词匹配本地缓存 ≤10ms + 向量语义 ≤100ms + 融合 ≤5ms），超时则仅使用关键词通道结果并标记 `semanticSkipped=true`。

### 6.3 多路召回引擎

召回采用四路并行（CompletableFuture），每路上限与去重策略如下：

| 路 | 来源 | 召回数上限 | 说明 |
| --- | --- | --- | --- |
| R1 主题路 | `essay_material_theme_rel` 按 primaryTheme + relatedThemes join | 60 | 主主题素材 relevance_score 加权 |
| R2 关键词路 | Elasticsearch（title/content/source，ik 分词） | 40 | 作文题目分词后检索，不含主题词时启用 |
| R3 语义路 | pgvector 余弦相似度（素材 embedding） | 40 | 阈值 0.72，向量库宕机整体关闭（§12-D2） |
| R4 热门兜底路 | `usage_count` 全库 Top | 20 | 仅当 R1-R3 去重后不足 limit 时补足，且必须再次过适龄过滤 |

```java
@Service
public class MaterialRecallService {

    private static final Map<String, Integer> RECALL_LIMITS = Map.of(
        "R1_THEME", 60, "R2_KEYWORD", 40, "R3_SEMANTIC", 40, "R4_HOT", 20
    );

    public List<RecalledMaterial> recall(ThemeAnalysisResult theme, RecommendRequest req) {
        // 四路并行，单路异常不拖垮整体（ exceptionally 返回空列表 + 告警 ）
        CompletableFuture<List<RecalledMaterial>> r1 = CompletableFuture.supplyAsync(
            () -> recallByTheme(theme), recallExecutor).exceptionally(ex -> { log.warn("R1 fail", ex); return List.of(); });
        CompletableFuture<List<RecalledMaterial>> r2 = CompletableFuture.supplyAsync(
            () -> recallByKeyword(req), recallExecutor).exceptionally(ex -> { log.warn("R2 fail", ex); return List.of(); });
        CompletableFuture<List<RecalledMaterial>> r3 = vectorEnabled()
            ? CompletableFuture.supplyAsync(() -> recallBySemantic(req), recallExecutor)
                .exceptionally(ex -> { log.warn("R3 fail", ex); return List.of(); })
            : CompletableFuture.completedFuture(List.of());

        List<RecalledMaterial> merged = Stream.of(r1.join(), r2.join(), r3.join())
            .flatMap(List::stream)
            .filter(m -> req.getExcludeIds() == null || !req.getExcludeIds().contains(m.getId()))
            .collect(Collectors.toMap(RecalledMaterial::getId, Function.identity(),
                // 同素材多路命中：召回分按 max 取，来源合并（用于效果归因）
                (a, b) -> a.mergeSource(b)))
            .values().stream()
            .sorted(Comparator.comparingDouble(RecalledMaterial::getRecallScore).reversed())
            .collect(Collectors.toList());

        // R4 热门兜底：仅在去重后不足 2×limit 时触发，且兜底素材强制重新走适龄过滤
        if (merged.size() < req.getLimit() * 2) {
            Set<Long> existing = merged.stream().map(RecalledMaterial::getId).collect(Collectors.toSet());
            materialRepository.findHotFallback(RECALL_LIMITS.get("R4_HOT"), existing).stream()
                .map(m -> new RecalledMaterial(m, 0.50, "R4_HOT"))
                .forEach(merged::add);
        }
        return merged;
    }

    private List<RecalledMaterial> recallByTheme(ThemeAnalysisResult theme) {
        List<Integer> themeIds = new ArrayList<>();
        themeIds.add(theme.getThemeId());
        // 父主题展开一层：亲情类题目可同时召回"爱"父主题下的素材
        themeIds.addAll(themeRepository.findParentThemeIds(theme.getThemeId()));
        return materialRepository.findByThemeIds(themeIds, RECALL_LIMITS.get("R1_THEME")).stream()
            .map(m -> new RecalledMaterial(m, Math.min(1.0, 0.6 + 0.4 * m.getRelevanceScore()), "R1_THEME"))
            .collect(Collectors.toList());
    }
}
```

### 6.4 适龄过滤

适龄过滤是**不可降级的 fail-closed 红线**（守卫 G7），任何一路召回结果必须经过过滤器：

| 规则 | 判定 | 不满足时 |
| --- | --- | --- |
| F1 学段区间 | `min_stage ≤ user.stage ≤ max_stage`（学段序 kindergarten<primary<junior<senior） | 过滤 |
| F2 年级区间 | 若 min_grade/max_grade 非空，user.grade 须在区间内 | 过滤 |
| F3 难度上限 | 小学低年级（grade≤3）仅 difficulty_level=1；小学高年级 ≤2 | 过滤 |
| F4 内容安全 | status=2（已上架）且审核通过 | 过滤 |
| F5 未知学段 | user.stage 缺失或非法 | **默认按最低学段 kindergarten 处理**（fail-closed） |

```java
@Component
public class AgeAppropriateFilter {

    private static final Map<String, Integer> STAGE_ORDER = Map.of(
        "kindergarten", 1, "primary", 2, "junior", 3, "senior", 4
    );

    public boolean isAppropriate(EssayMaterial m, RecommendRequest req) {
        int userStage = STAGE_ORDER.getOrDefault(req.getStage(), STAGE_ORDER.get("kindergarten")); // F5
        if (STAGE_ORDER.get(m.getMinStage()) > userStage
            || STAGE_ORDER.get(m.getMaxStage()) < userStage) {
            return false; // F1
        }
        if (m.getMinGrade() != null && req.getGrade() < m.getMinGrade()) return false;   // F2
        if (m.getMaxGrade() != null && req.getGrade() > m.getMaxGrade()) return false;   // F2
        if (req.getGrade() != null && req.getGrade() <= 3 && m.getDifficultyLevel() > 1) return false; // F3
        return m.getStatus() == 2; // F4
    }
}
```

### 6.5 精排打分

召回并过滤后的候选集（一般 80~140 条）进入精排，最终得分公式：

```
finalScore = 0.45 × relevance      -- 主题相关度（召回分归一化）
           + 0.20 × quality         -- 素材质量分（公式见下）
           + 0.20 × personalization -- 个性化偏好分（写作画像）
           + 0.15 × freshness       -- 新鲜度（新上架素材提权，30 天后衰减为 0）

quality = 0.4 × min(1, usageCount/5000)          -- 使用热度，5000 次封顶
        + 0.3 × min(1, likeCount/500)
        + 0.3 × (avgScore / 5.0)                    -- 用户评分，无评分记 0.5

personalization = Σ 维度权重 × 画像匹配度
  -- 画像来自《用户学习画像与能力维度模型》：若用户薄弱维度为"论据运用"，
     则 story/quote 类素材 +0.1；若用户常写 narrative，narrative 适配素材 +0.1
  -- 画像服务不可用时权重置 0（§12-D4），不得阻断推荐主链路

freshness = max(0, 1 - daysSincePublished / 30) × 0.15
```

```java
@Component
public class MaterialRanker {

    public List<ScoredMaterial> rank(List<RecalledMaterial> candidates,
                                     RecommendRequest req,
                                     WritingProfile profile) {
        return candidates.stream()
            .filter(c -> ageFilter.isAppropriate(c.getMaterial(), req)) // G7：fail-closed，见 §6.4
            .map(c -> new ScoredMaterial(
                c.getMaterial(),
                0.45 * normalize(c.getRecallScore())
              + 0.20 * qualityScore(c.getMaterial())
              + 0.20 * personalizationScore(c.getMaterial(), profile)
              + 0.15 * freshnessScore(c.getMaterial()),
                c.getSource()
            ))
            .sorted(Comparator.comparingDouble(ScoredMaterial::getFinalScore).reversed())
            .limit(50) // 精排截断 50，交多样性打散
            .collect(Collectors.toList());
    }

    private double personalizationScore(EssayMaterial m, WritingProfile p) {
        if (p == null) return 0.0; // D4 降级语义：无画像不加不减
        double score = 0.0;
        if (p.getWeakDimensions().contains("evidence_use")
            && (m.getMaterialType().equals("story") || m.getMaterialType().equals("quote"))) {
            score += 0.10; // 论据运用薄弱 → 补强论据类素材
        }
        if (p.getPreferredGenres().contains(reqGenre) && m.getGenres() != null
            && m.getGenres().contains(reqGenre)) {
            score += 0.10;
        }
        return Math.min(score, 0.20);
    }
}
```

### 6.6 多样性打散

为避免推荐结果同质化（例如 10 条全是名言），打散采用**类型配额 + MMR 重排序**两阶段：

| 素材类型 | 单次推荐配额（limit=10 时） |
| --- | --- |
| quote（名言） | ≤3 |
| story（事例） | ≤2 |
| expression / vocabulary | ≤2 |
| opening / ending | 各 ≤1 |
| transition | ≤1 |

```java
@Component
public class DiversityReranker {

    private static final double MMR_LAMBDA = 0.7; // 相关度 vs 多样性的权衡

    public List<ScoredMaterial> rerank(List<ScoredMaterial> ranked, int limit, String primaryTheme) {
        Map<String, Integer> typeQuota = buildTypeQuota(limit);
        List<ScoredMaterial> selected = new ArrayList<>();
        List<ScoredMaterial> pool = new ArrayList<>(ranked);
        Set<String> coveredThemes = new HashSet<>();

        while (selected.size() < limit && !pool.isEmpty()) {
            ScoredMaterial best = null;
            double bestMmr = -1;
            for (ScoredMaterial m : pool) {
                // 类型配额硬约束
                if (typeQuota.getOrDefault(m.getType(), 0) <= 0) continue;
                double mmr = MMR_LAMBDA * m.getFinalScore()
                           - (1 - MMR_LAMBDA) * maxThemeSimilarity(m, coveredThemes);
                if (mmr > bestMmr) { bestMmr = mmr; best = m; }
            }
            if (best == null) break;
            selected.add(best);
            pool.remove(best);
            typeQuota.merge(best.getType(), -1, Integer::sum);
            coveredThemes.addAll(best.getThemes());
        }
        return selected;
    }

    private double maxThemeSimilarity(ScoredMaterial m, Set<String> coveredThemes) {
        // 主题重合度：与新选中素材主题集合的 Jaccard 相似度取最大
        if (coveredThemes.isEmpty()) return 0;
        return m.getThemes().stream()
            .mapToDouble(t -> coveredThemes.contains(t) ? 1.0 : 0.0)
            .max().orElse(0);
    }
}
```

### 6.8 推荐编排主流程

```java
@Service
public class MaterialRecommendOrchestrator {

    @Resource private ThemeAnalyzer themeAnalyzer;
    @Resource private MaterialRecallService recallService;
    @Resource private MaterialRanker ranker;
    @Resource private DiversityReranker diversityReranker;
    @Resource private UsageTipGenerator usageTipGenerator;
    @Resource private ProfileGateway profileGateway;      // 委托用户画像服务（契约 R3）
    @Resource private UsageTracker usageTracker;

    /**
     * 核心推荐入口：整体延迟预算 800ms（P99）
     */
    public RecommendResponse recommend(RecommendRequest req) {
        long start = System.currentTimeMillis();

        // 1. 主题解析（≤150ms）
        ThemeAnalysisResult theme = themeAnalyzer.analyze(
            req.getEssayTitle(), req.getGenre(), req.getKeywords());

        // 2. 多路召回（≤200ms，四路并行）
        List<RecalledMaterial> candidates = recallService.recall(theme, req);

        // 3. 获取写作画像（≤50ms，失败降级 null，不阻断）
        WritingProfile profile = profileGateway.getWritingProfile(req.getUserId());

        // 4. 精排（≤50ms）
        List<ScoredMaterial> ranked = ranker.rank(candidates, req, profile);

        // 5. 多样性打散
        List<ScoredMaterial> finalList = diversityReranker.rerank(ranked, req.getLimit(), theme.getPrimaryTheme());

        // 6. 使用建议（仅 Top-N，异步并发生成）
        List<RecommendItem> items = attachWithTips(finalList, req);

        // 7. 使用打点（异步，view 类型）
        usageTracker.trackAsync(req, items, "topic_match");

        log.info("recommend done, cost={}ms, theme={}, candidates={}, result={}",
            System.currentTimeMillis() - start, theme.getPrimaryTheme(), candidates.size(), items.size());
        return RecommendResponse.of(theme, items);
    }
}
```

## 7. 素材内容生产管线

### 7.1 三种生产方式

| 方式 | 入口 | 流程 | 质量要求 |
| --- | --- | --- | --- |
| 后台录入 | 管理后台表单/批量导入 | 创建→待审核→审核→上架 | source_type=classic/modern/foreign 须核验出处 |
| AI 批量生成 | `POST /api/admin/essay-materials/generate` | 按主题批量生成→**人工逐条复核**→上架 | source_type=ai_generated，未复核禁止上架（G8） |
| 用户沉淀回流 | 订阅作文批改引擎好词好句提取事件 | 提取→聚合→进入待审核池 | source_type=user_extracted，涉及原文著作权，默认不上架，仅作个人素材 |

### 7.2 AI 生成 Prompt 约束

AI 生成素材的 Prompt 必须包含以下约束（与《AI-Prompt编排与场景模板系统》素材场景模板对齐，契约 R6）：

1. 每条素材须标注出处；无法确认出处的名言宁可不生成，也不得编造出处（**出处真实性红线 C2**）。
2. 同一主题一次生成 ≥5 条候选，供人工择优。
3. 输出 JSON 数组，字段与 `essay_materials` 表结构一一对应，themes 必须从主题词表选取，禁止自造主题词。
4. 生成内容自动经过内容安全审核（委托统一审核服务），审核不通过的候选直接丢弃并记录。

## 8. 素材状态机与守卫

### 8.1 素材生命周期状态机

```
                 ┌──────────┐   提交审核    ┌──────────┐
   创建/导入 ──→ │ DRAFT 0  │ ──────────→ │PENDING 1 │
                 └────┬─────┘             └────┬─────┘
                      │ 保存草稿               │ 审核通过
                      ↓                        ↓
                 （留在草稿）             ┌──────────┐     下架      ┌──────────┐
                                        │PUBLISHED 2│ ←─────────→ │OFFLINE 3 │
                                        └────┬─────┘   重新上架    └──────────┘
                                             │ 审核拒绝
                                             ↓
                                        ┌──────────┐   修改后重新提交   ┌──────────┐
                                        │REJECTED 4│ ──────────────→ │PENDING 1 │
                                        └──────────┘                  └──────────┘
```

### 8.2 转移表

| 当前状态 | 动作 | 目标状态 | 守卫 |
| --- | --- | --- | --- |
| DRAFT | submitAudit | PENDING | G1 必填字段完整（title/content/material_type/themes） |
| PENDING | approve | PUBLISHED | G8：source_type=ai_generated 必须有 audited_by 人工复核记录 |
| PENDING | reject | REJECTED | 必填 audit_remark |
| PUBLISHED | offline | OFFLINE | G3 必填下线原因，写审计日志 |
| OFFLINE | republish | PUBLISHED | 需重新走内容抽检（G4 向量化状态检查） |
| REJECTED | resubmit | PENDING | 内容须有变更（比对 updated_at/content hash） |
| 任意 | 物理删除 | — | G2 仅 DRAFT/REJECTED 且 usage_count=0 可删除 |

### 8.3 守卫表

| 守卫 | 规则 | 违反后果 |
| --- | --- | --- |
| G1 | 提交审核前必填校验（含 themes 非空且主题词存在于词表） | 400，拒绝提交 |
| G2 | PUBLISHED/OFFLINE 素材禁止物理删除 | 409；只能下架 |
| G3 | 下架/拒绝必须填写原因并写 admin_audit_log | 400 |
| G4 | vector_status=3（失败）的素材上架后 24h 内须重试向量化，连续 3 次失败告警 | 监控 M7 |
| G5 | usage_count/like_count 只许原子自增（Redis Lua 或 SQL `SET count=count+1`），禁止读改写 | 并发丢更新 |
| G6 | 素材-主题关联的 relevance_score 人工标注值优先于算法值，人工修改记录 change_log | 可追溯 |
| G7 | 适龄过滤 fail-closed（§6.4 F5），任何降级方案不得跳过 | 合规红线 |
| G8 | AI 生成素材未经人工复核不得上架 | 阻断 + 告警 |

## 9. 幂等性与并发

| 场景 | 幂等键 | 重复请求行为 |
| --- | --- | --- |
| 收藏素材 | `uk_user_material(user_id, material_id)` | 重复收藏返回 200 已收藏（ESSAY_MAT_105 语义，见 §11） |
| 取消收藏 | 同上唯一键 | 未收藏时返回 200 无副作用（幂等删除） |
| 使用打点 quote/collect | `uk(user_id, material_id, task_id, usage_type)` | 同任务同素材同类型重复上报去重；view 类型不去重 |
| 后台批量导入 | `source_id` 唯一（同来源重复导入执行 upsert） | 返回导入/更新/跳过计数 |
| AI 批量生成 | 请求头 `Idempotency-Key`，24h 内重复返回同一批次结果 | 防重复扣费 |
| 审核操作 | `(material_id, from_status)` CAS：`UPDATE ... SET status=? WHERE id=? AND status=?`，影响行数=0 返回 409 | 防并发双审 |

**并发说明**：推荐接口只读无并发写问题；收藏与使用打点为高频写，全部走唯一键/原子自增，不在应用层做"先查再插"。

## 10. 事件 Outbox

素材服务通过 Outbox 模式（同事务写业务表与 outbox 表，Relay 异步投递）发布以下事件：

| 事件 | 触发时机 | 关键载荷 | 消费方 |
| --- | --- | --- | --- |
| `material.published` | 素材上架 | materialId, materialType, themes, stageRange | ES 索引同步、向量任务调度 |
| `material.offlined` | 素材下架 | materialId, reason | ES 索引删除、推荐缓存清理 |
| `material.updated` | 素材内容/标签变更 | materialId, changedFields | ES/向量增量更新 |
| `material.usage.quoted` | 素材被引用入文 | materialId, userId, taskId | 统计聚合（usage_count 异步校准）、效果分析 |
| `material.theme.recount` | 主题关联变更 | themeId | 主题词表 material_count 重算 |

消费方幂等：以 `(event_id, consumer)` 为键记录消费水位；`material.published` 与 `material.updated` 对 ES 消费者可安全重放（幂等索引）。

## 11. 错误码

沿用作文域符号化错误码体系（与《服务端-作文范文智能推荐与结构拆解分析引擎》《服务端-作文审题分析与提纲生成引擎》一致，不新占数字段，契约 R1）。

| 错误码 | HTTP 状态 | 说明 | 客户端处理 |
| --- | --- | --- | --- |
| ESSAY_MAT_001 | 400 | essayTitle 为空或超长（>200 字） | 提示检查题目 |
| ESSAY_MAT_002 | 400 | 学段/年级参数缺失或非法 | 提示完善个人信息 |
| ESSAY_MAT_003 | 404 | 素材不存在 | 刷新列表 |
| ESSAY_MAT_004 | 403 | 素材已下架（命中缓存脏数据） | 刷新并隐藏该条 |
| ESSAY_MAT_005 | 403 | 素材不在当前学段适用范围 | 前端不应展示，防御性报错 |
| ESSAY_MAT_101 | 429 | 推荐接口限流（默认 20 QPS/用户） | 退避重试 |
| ESSAY_MAT_102 | 429 | 搜索接口限流 | 退避重试 |
| ESSAY_MAT_103 | 429 | AI 生成素材任务超限（管理端） | 排队或次日再试 |
| ESSAY_MAT_104 | 500 | 推荐引擎内部错误 | 降级返回热门素材（D1） |
| ESSAY_MAT_105 | 200 | 已收藏（幂等语义） | 静默成功 |
| ESSAY_MAT_106 | 409 | 审核状态冲突（CAS 失败） | 刷新列表重试 |
| ESSAY_MAT_107 | 400 | 主题词不存在（管理端标注） | 提示从词表选择 |
| ESSAY_MAT_108 | 422 | 导入文件解析失败 | 返回行级错误明细 |
| ESSAY_MAT_109 | 500 | 出处核验服务不可用 | 暂停该批导入，不默认可用 |

## 12. 降级策略

| 编号 | 故障场景 | 降级方案 | 恢复 |
| --- | --- | --- | --- |
| D1 | 推荐引擎整体异常 | 降级返回按学段过滤的热门素材 Top-N（走 MySQL 直查，限 10 QPS） | 自动探测恢复 |
| D2 | 向量库（pgvector）宕机 | 关闭 R3 语义召回路，R1/R2 权重等比放大；主题解析语义匹配同步关闭 | 探活恢复，累计 30min 未恢复 P2 告警 |
| D3 | AI 使用建议生成超时 | 模板兜底（§6.7），接口不报错 | 自动 |
| D4 | 用户画像服务不可用 | personalization 权重置 0，推荐退化为纯内容质量排序 | 自动 |
| D5 | Redis 宕机 | 主题词表读 MySQL + Caffeine 本地缓存 10min；usageTip 缓存失效直调 AI | 自动 |
| D6 | ES 宕机 | 关键词路回源 MySQL `LIKE` 检索（仅 title 列，限 20 QPS，搜索精度下降提示） | 自动 |
| D7 | Outbox Relay 堆积 | 消费方以 5min 全量 diff 兜底同步 ES，防索引长期漂移 | 对账任务 |
| D8 | 出处核验服务不可用 | AI 生成候选全部暂存待审核池，禁止直接上架 | 人工处理 |

**降级红线**：适龄过滤（G7）与素材上架审核（G8）无任何降级路径；素材服务整体不可用时，作文辅导模块应隐藏素材推荐入口，不得展示兜底为空的推荐区。

## 14. 合规要点

| 编号 | 要点 |
| --- | --- |
| C1 | 素材内容须适合未成年人：不含暴力、色情、歧视、价值观扭曲内容，上架前经内容安全审核。 |
| C2 | 名言/典故出处真实性为红线：AI 生成素材必须人工核验出处，无法核验的素材不得上架；错误引用列入质检扣分项。 |
| C3 | 使用建议（usageTip）只做"用法引导"，禁止输出可直接抄入作文的成段文字，落实"辅助不代写"产品原则。 |
| C4 | AI 生成内容按监管要求带 AIGC 标识（素材详情与 usageTip 均标注，契约 R5）。 |
| C5 | 用户沉淀素材（user_extracted）默认仅本人可见可用，不进入公共推荐池；聚合统计须去标识化。 |
| C6 | 素材使用记录含未成年人行为数据，保留 180 天后脱敏归档，禁止用于画像营销定向（复用《数据安全与隐私合规体系》）。 |

## 15. 契约对齐

| 编号 | 契约 |
| --- | --- |
| R1 | 错误码体系沿用作文域符号化编码（ESSAY_MAT_xxx），不新占数字错误码段。 |
| R2 | 主题词表（essay_material_themes）为作文域共享资产，与《服务端-作文审题分析与提纲生成引擎》的立意方向主题对齐，新增主题词需双向同步。 |
| R3 | 写作画像数据委托《用户学习画像与能力维度模型》服务提供，本服务不自建画像存储，失败按 D4 降级。 |
| R4 | 推荐响应字段（matchReason/usageTip）由《客户端-作文辅导页面架构与批改交互设计》消费，字段增删需同步客户端。 |
| R5 | AI 生成内容（AI 素材、AI usageTip）的 AIGC 标识协议与《AIGC内容标识与生成内容溯源水印系统》对齐。 |
| R6 | AI 生成 Prompt 使用《AI-Prompt编排与场景模板系统》素材场景模板，禁止服务内硬编码 Prompt。 |
| R7 | 好词好句回流入口订阅《服务端-作文批改评分引擎与写作能力评估服务》的批改完成事件，本服务不直接调用批改引擎。 |
| R8 | usage_count 以本服务打点为准（同步自增 + 事件异步校准），其他模块不得直接修改素材表计数列。 |
