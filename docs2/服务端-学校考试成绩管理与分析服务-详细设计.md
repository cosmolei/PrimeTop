# 学校考试成绩管理与分析服务（服务端）详细设计

> 所属领域：教师端 / B 端合作 / 学情分析
> 文档版本：v1.0（2026-08-14）
> 上游设计：`docs\design\启硕-PrimeTop-全学段AI辅助学习软件项目设计文档.md` §4.2（教师：班级数据）、§6.7（学情分析）、§10.5（V2.0 教师端与班级管理）、§11.3（B 端班级学情分析工具）

## 1. 概述

### 1.1 模块定位

PrimeTop 平台当前的学情数据主要来源于平台内的练习答题、AI 辅导对话、错题订正等行为数据。但对于中国 K12 场景，**校内真实考试成绩**（单元测验、期中期末、月考、模考）是教师、家长最关注的权威结果性数据，也是 B 端班级学情分析工具的核心输入。

现有体系中：

- `服务端-学校教务系统标准数据对接与学籍信息同步集成适配器引擎` 解决了外部教务系统（SIS）成绩数据的**传输与同步**问题（`ExternalExamScore` 实体），但不负责成绩的业务管理；
- `服务端-教育测量学统计指标自动计算与试卷质量检验引擎`、`服务端-考后试卷深度分析与个性化讲评报告生成服务` 面向**平台内自组考试**（有逐题作答数据），不支持"只有总分、无作答明细"的校内考试；
- `服务端-学情分析`、`服务端-多渠道学习数据融合与统一知识掌握度计算引擎` 需要外部成绩作为融合证据源，但缺少统一的证据供给方。

**本服务定位为校内考试成绩的统一领域服务**：负责成绩的录入/批量导入/SIS 同步接入、数据校验、发布管控、排名与统计计算、成绩单生成、个人趋势追踪、复核申诉处理，以及面向学生/家长/教师/年级主任的**差异化可见性控制**，并向学情分析、家长报告、通知推送等下游发布领域事件。

### 1.2 核心职责

1. **考试档案管理**：创建/维护校内考试档案（考试类型、科目、满分/及格/优秀线、参考班级、考试日期、学期归属）。
2. **成绩多源接入**：统一支持三种成绩来源——教师手动录入、Excel 模板批量导入、教务系统（SIS）同步，三种来源走同一条校验与确认管线。
3. **成绩校验与确认**：学生匹配（学号/姓名+班级）、分数范围校验、异常状态（缺考/作弊/免考）标记、错误行报告、二次确认后落库。
4. **发布管控**：成绩"录入 → 复核 → 发布 → 可撤回重录"全生命周期状态机；发布时**冻结排名快照与统计快照**，保证历史可回溯。
5. **排名与统计分析**：班级/年级排名（同分并列 1-2-2-4 规则）、百分位、平均分/中位数/标准差/及格率/优秀率、分数段分布、加权总分。
6. **个人成绩趋势**：跨考试的学科成绩轨迹、班级/年级相对位次变化、弱势学科预警信号输出。
7. **复核申诉**：学生/家长提交成绩复核申请，教师/教务处理，通过后自动触发受影响排名重算与通知。
8. **多角色可见性控制**：按角色（学生/家长/任课教师/班主任/年级主任/校管理员）与平台合规策略（如小学低年级排名保护）控制字段级可见性。
9. **联动与事件发布**：成绩发布后触发家长推送、学情分析融合、错题归档提醒（考后错题）、学习报告引用。

**明确不在本服务范围内**：逐题作答数据管理（属练习测评域）、试卷命题与质量分析（属教育测量学引擎）、SIS 对接协议适配（属教务对接引擎）、消息触达执行（属通知服务）、PDF 渲染（属统一文件生成中心）。

### 1.3 与相关模块边界

| 相关模块 | 边界说明 |
| --- | --- |
| 学校教务系统对接引擎 | 其将 SIS 成绩标准化后调用本服务接入 API 落库；本服务不直接访问 SIS |
| 教育测量学统计指标引擎 | 其处理"有作答明细"的平台考试；本服务处理"仅总分"的校内考试；两者统计结果统一进入数据仓库 |
| 考后试卷深度分析服务 | 平台模考场景使用；若校内考试试卷同步进平台，其分析结果可通过 `exam_ref` 关联本服务档案 |
| 多渠道学习数据融合引擎 | 消费本服务 `ScorePublished` 事件，将校内成绩作为外部证据参与掌握度融合（低权重、结果性） |
| 学情分析 / 学习报告 | 读取本服务趋势与统计快照，生成"校内成绩 vs 平台练习"对照视图 |
| 统一异步任务进度中心 | Excel 解析校验、成绩单批量导出为异步任务，进度回调走该中心 |
| 统一文件生成中心 | 成绩单 PDF / 导入错误报告 Excel 的渲染由其完成 |
| 通知服务 / 多源通知合并引擎 | 成绩发布、复核结果通知由本服务发事件，触达策略与频控由通知域决定 |
| 用户权限 / 数据权限框架 | 本服务只声明所需数据范围（本班/本年级任课），鉴权由统一框架执行 |

### 1.3.1 依赖关系

```text
学校考试成绩管理与分析服务
    ├─ 依赖：用户服务（角色、师生关系、班级归属）
    ├─ 依赖：学校与组织服务（学校、年级、班级、学期档案）
    ├─ 依赖：学科基础数据服务（学科编码、满分规范）
    ├─ 依赖：统一异步任务进度中心（导入/导出任务）
    ├─ 依赖：消息队列（事件发布：ScorePublished 等）
    ├─ 依赖：对象存储（导入文件、错误报告、导出成绩单）
    └─ 被依赖：学情分析、家长报告、错题服务、通知服务、数据仓库
```

### 2.2 服务边界与内部分层

采用模块化单体中的独立 domain package（与现有服务端代码分层规范一致）：

```text
score-center/
  ├─ controller/    # HTTP 接入，参数校验，鉴权声明
  ├─ service/       # 用例编排（上述领域服务）
  ├─ domain/        # 实体、值对象、状态机、领域事件定义
  ├─ repository/    # MySQL/Redis/CH/DAO
  └─ consumer/      # SIS 同步成绩确认消费、导出任务回调
```

### 2.3 核心数据流

```text
[来源1 手动录入] ─┐
[来源2 Excel导入] ─┼─► 统一接入管线：解析 → 学生匹配 → 校验 → 待确认 →
[来源3 SIS同步]  ─┘     错误报告(可选) → 教师确认提交 ─┐
                                                       ▼
                              考试状态: SCORE_ENTERING → (SCORE_REVIEW) → PUBLISHED
                                                       │ 发布事务
                       ┌───────────────┬───────────────┼───────────────┐
                       ▼               ▼               ▼               ▼
                 rank_snapshot   subject_score_stat  MQ事件        ClickHouse
                 (排名冻结)       (统计快照)        ScorePublished  趋势明细写入
                                                       │
                              ┌────────────┬───────────┼───────────┬─────────┐
                              ▼            ▼           ▼           ▼         ▼
                           家长推送    学情分析融合  错题归档提醒  学习报告  数据仓库
```

## 3. 数据模型

### 3.1 核心实体关系

```text
SchoolExam 1 ── n SchoolExamSubject（每科一条：满分/及格线/权重）
SchoolExam 1 ── n StudentExamScore（学生 × 科目 粒度）
SchoolExamSubject 1 ── n ScoreImportBatch（多次导入尝试）
ScoreImportBatch 1 ── n ScoreImportRow（逐行校验结果）
SchoolExam 1 ── n RankSnapshotRow（发布时冻结：班级/年级排名）
SchoolExamSubject 1 ── n SubjectScoreStat（按班级统计快照）
StudentExamScore 1 ── n ScoreAppeal（复核申请）
SchoolExam 1 ── n ScoreStatusLog（状态流转审计）
```

### 3.2 MySQL 表设计

> 所有表含通用字段：`id BIGINT UNSIGNED PK(雪花ID)`、`created_at`、`updated_at`、`deleted_at(软删)`，下表省略。字符集 utf8mb4。

#### 3.2.1 school_exam（校内考试档案）

```sql
CREATE TABLE school_exam (
  id                BIGINT UNSIGNED PRIMARY KEY,
  school_id         BIGINT UNSIGNED NOT NULL,
  term_id           BIGINT UNSIGNED NOT NULL COMMENT '学期ID',
  grade_id          BIGINT UNSIGNED NOT NULL COMMENT '年级ID',
  name              VARCHAR(64)  NOT NULL COMMENT '如：2026学年第一学期期中考试',
  exam_type         TINYINT NOT NULL COMMENT '1单元测验 2月考 3期中 4期末 5模考 6随堂测 9其他',
  exam_date         DATE NOT NULL,
  class_ids         JSON NOT NULL COMMENT '参考班级ID数组',
  status            TINYINT NOT NULL DEFAULT 1 COMMENT '1草稿 2录入中 3复核中 4已发布 5已撤回 6已归档',
  ranking_policy    JSON NOT NULL COMMENT '排名策略：{"showRank":true,"minGradeToShowRank":4,"scope":"GRADE"}',
  creator_id        BIGINT UNSIGNED NOT NULL,
  publish_time      DATETIME NULL,
  version           INT NOT NULL DEFAULT 1 COMMENT '发布版本，撤回重发递增',
  KEY idx_school_term (school_id, term_id, exam_date),
  KEY idx_grade_date (grade_id, exam_date),
  KEY idx_status (status)
) COMMENT='校内考试档案';
```

`ranking_policy` 说明（发布与可见性控制共用）：

```json
{
  "showRank": true,              // 是否计算并展示名次
  "minGradeToShowRank": 4,       // 4年级以下不展示具体名次（合规默认）
  "scope": "GRADE",              // CLASS=仅班级排名 / GRADE=班级+年级排名
  "weightTotalEnabled": true,    // 是否计算加权总分
  "percentileMode": "PERCENTILE" // 低龄替代展示：百分位区间
}
```

#### 3.2.2 school_exam_subject（考试科目）

```sql
CREATE TABLE school_exam_subject (
  id             BIGINT UNSIGNED PRIMARY KEY,
  exam_id        BIGINT UNSIGNED NOT NULL,
  subject_code   VARCHAR(16) NOT NULL COMMENT '学科编码，引用学科基础数据',
  full_score     DECIMAL(5,1) NOT NULL,
  pass_score     DECIMAL(5,1) NOT NULL,
  excellent_score DECIMAL(5,1) NOT NULL,
  weight         DECIMAL(5,2) NOT NULL DEFAULT 1.00 COMMENT '加权总分权重',
  enter_teacher_id BIGINT UNSIGNED NULL COMMENT '负责录入门课教师',
  entering_status TINYINT NOT NULL DEFAULT 1 COMMENT '1未开始 2录入中 3已完成',
  UNIQUE KEY uk_exam_subject (exam_id, subject_code)
) COMMENT='考试科目配置';
```

#### 3.2.3 student_exam_score（学生成绩，核心表）

```sql
CREATE TABLE student_exam_score (
  id             BIGINT UNSIGNED PRIMARY KEY,
  exam_id        BIGINT UNSIGNED NOT NULL,
  exam_version   INT NOT NULL DEFAULT 0 COMMENT '写入时的发布版本',
  subject_code   VARCHAR(16) NOT NULL,
  student_id     BIGINT UNSIGNED NOT NULL,
  class_id       BIGINT UNSIGNED NOT NULL COMMENT '考试时所在班级（快照，防后续转班污染）',
  score_status   TINYINT NOT NULL DEFAULT 1 COMMENT '1正常 2缺考 3作弊记零 4免考 5待定',
  raw_score      DECIMAL(5,1) NULL COMMENT 'score_status=1 时必填',
  score_level    TINYINT NULL COMMENT '1优秀 2良好 3合格 4不合格（按科目录入时即时计算）',
  rank_in_class  INT NULL,
  rank_in_grade  INT NULL,
  percentile     DECIMAL(5,2) NULL COMMENT '年级百分位',
  enter_source   TINYINT NOT NULL COMMENT '1手动 2Excel导入 3SIS同步',
  enter_batch_id BIGINT UNSIGNED NULL,
  remark         VARCHAR(255) NULL,
  version        INT NOT NULL DEFAULT 1 COMMENT '乐观锁',
  UNIQUE KEY uk_exam_student_subject (exam_id, student_id, subject_code),
  KEY idx_exam_subject (exam_id, subject_code, score_status),
  KEY idx_student_date (student_id)
) COMMENT='学生校内考试成绩';
```

> `rank_in_class / rank_in_grade / percentile` 仅在**发布事务**中由 `RankSnapshotRow` 回填，未发布成绩该三列为 NULL，防止"边录边看排名"导致的不一致。

### 3.3 Redis 设计

| Key | 类型 | TTL | 用途 |
| --- | --- | --- | --- |
| `score:exam:{examId}` | String(JSON) | 10min | 考试档案读缓存，发布/撤回时主动失效 |
| `score:stats:{examId}:{ver}:{subject}:{classId}` | String(JSON) | 1h | 统计快照读缓存 |
| `score:import:lock:{examId}:{subject}` | String | 120s | 同科目导入互斥锁（防并发导入覆盖） |
| `score:publish:lock:{examId}` | String | 30s | 发布事务互斥锁 |
| `score:trend:hot:{studentId}` | Hash | 30min | 高频个人趋势页缓存 |

```sql
    score         Float32,
    full_score    Float32,
    score_rate    Float32 COMMENT '得分率',
    class_rank    UInt32,
    grade_rank    UInt32,
    percentile    Float32,
    class_avg     Float32,
    grade_avg     Float32,
    exam_version  UInt32,
    published_at  DateTime
)
ENGINE = ReplacingMergeTree(published_at)
PARTITION BY toYYYYMM(exam_date)
ORDER BY (student_id, subject_code, exam_date);
```

个人趋势查询走该表（`FINAL`/`argMax` 取最新版本），MySQL 快照表仅服务当次考试详情。

```typescript
// score-center/service/import-pipeline.ts
export class ScoreImportPipeline {

  async run(batchId: bigint): Promise<void> {
    const batch = await this.batchRepo.mustGet(batchId);
    // 互斥：同考试同科目仅允许一个进行中的导入批次
    const lockKey = `score:import:lock:${batch.examId}:${batch.subjectCode}`;
    if (!(await this.redis.set(lockKey, String(batchId), 'EX', 120, 'NX'))) {
      throw new BizError('SCORE-4092', '该科目存在进行中的导入任务');
    }
    try {
      await this.batchRepo.updateStatus(batchId, 'PARSING');
      const rows = await this.excelParser.parse(batch.fileUrl, SCORE_TEMPLATE); // 模板列: 学号/姓名/班级/分数/状态
      await this.batchRepo.initRows(batchId, rows);

      await this.batchRepo.updateStatus(batchId, 'VALIDATING');
      const roster = await this.rosterRepo.loadClassRoster(batch.examId); // Map<no,Student> + Map<name+class,Student[]>
      for (const r of rows) {
        const v = this.validateRow(r, roster, batch.subject);
        await this.batchRepo.saveRowResult(batchId, r.rowNo, v);
      }
      await this.batchRepo.summarize(batchId); // 统计 valid/invalid/warning → WAIT_CONFIRM
      await this.taskCenter.complete(batch.taskTrackingKey, { batchId });
    } catch (e) {
      await this.batchRepo.updateStatus(batchId, 'FAILED', e.message);
      await this.taskCenter.fail(batch.taskTrackingKey, e);
      throw e;
    } finally {
      await this.redis.del(lockKey);
    }
  }

  private validateRow(r: ParsedRow, roster: Roster, subject: ExamSubject): RowResult {
    // 1) 学生匹配：学号精确 > 学号+班级 > 姓名+班级唯一；多解/无解 → 错误
    const m = roster.match(r.studentNo, r.studentName, r.className);
    if (!m.ok) return RowResult.error('SCORE_STUDENT_NOT_FOUND', m.message);
    if (m.ambiguous) return RowResult.error('SCORE_STUDENT_AMBIGUOUS', '多个候选学生，请人工指定');

    // 2) 状态与分数
    if (r.absent) return RowResult.ok(m.student, { scoreStatus: 2 });
    const score = Number(r.scoreText);
    if (!Number.isFinite(score)) return RowResult.error('SCORE_BAD_NUMBER', '分数格式非法');
    if (score < 0 || score > subject.fullScore)
      return RowResult.error('SCORE_OUT_OF_RANGE', `分数${score}超出满分${subject.fullScore}`);
    if ((subject.fullScore * 10) % 10 === 0 && (score * 10) % 10 !== 0)
      return RowResult.warn('精度超过1位小数，将四舍五入');

    return RowResult.ok(m.student, { scoreStatus: 1, rawScore: round1(score) },
                        m.matchedType === 3 ? '姓名+班级匹配，请核对' : undefined);
  }
}
```

### 5.2 排名与统计计算

```typescript
// score-center/service/rank-compute.ts
export class RankComputeService {

  /** 同分并列采用竞赛排名（1,2,2,4）；缺考/作弊不参与排名但保留位次记录 */
  computeRanks(scoreRows: ScoreRow[]): RankRow[] {
    const ranked = scoreRows
      .filter(s => s.scoreStatus === 1)               // 正常作答者参与排名
      .sort((a, b) => b.rawScore! - a.rawScore!);
    const out: RankRow[] = [];
    let prevScore = Number.NaN, prevRank = 0;
    ranked.forEach((s, idx) => {
      const rank = (s.rawScore === prevScore) ? prevRank : idx + 1;  // 1-2-2-4
      out.push({ studentId: s.studentId, classId: s.classId,
                 score: s.rawScore!, rankNo: rank,
                 percentile: pct(s.rawScore!, ranked) });
      prevScore = s.rawScore!; prevRank = rank;
    });
    return out;
  }

  /** 百分位：低于该分数的人数占比（同分计半），四舍五入1位小数 */
  private pct(score: number, all: ScoreRow[]): number {
    const below = all.filter(s => s.rawScore! < score).length;
    const equal = all.filter(s => s.rawScore! === score).length;
    return round1(((below + equal / 2) / all.length) * 100);
  }

  /** 加权总分排名：subject_code = 'TOTAL'，缺一科即无总分（可配置 bestEffort） */
  weightedTotal(scores: StudentSubjectScoreMap, subjects: ExamSubject[]): number | null {
    let total = 0, got = 0;
    for (const sub of subjects) {
      const s = scores.get(sub.subjectCode);
      if (!s || s.scoreStatus !== 1) return null;    // 严格模式：缺考不计总分
      total += s.rawScore! * sub.weight; got++;
    }
    return got === subjects.length ? round2(total) : null;
  }

  /** 班级统计：一次遍历 + 分数段直方图 */
  computeStat(scores: number[], subject: ExamSubject, absent: number): SubjectStat {
    const sorted = [...scores].sort((a, b) => a - b);
    const avg = mean(scores), sd = stdev(scores);
    return {
      candidateCount: scores.length, absentCount: absent,
      avgScore: round2(avg), medianScore: median(sorted),
      maxScore: Math.max(...scores), minScore: Math.min(...scores), stdev: round3(sd),
      passRate: ratio(scores.filter(s => s >= subject.passScore).length, scores.length),
      excellentRate: ratio(scores.filter(s => s >= subject.excellentScore).length, scores.length),
      distribution: histogram(scores, subject) // [10分/档，满分档自适应]
    };
  }
}
```

### 5.3 发布事务（快照冻结 + 事件）

```typescript
// score-center/service/score-publish.ts
export class ScorePublishService {

  @Transactional()
  async publish(examId: bigint, opts: PublishOptions) {
    const exam = await this.examRepo.lockById(examId);           // SELECT ... FOR UPDATE
    this.stateMachine.assert(exam, 'PUBLISH');                   // 仅 SCORE_ENTERING/SCORE_REVIEW 可发布
    const subjects = await this.subjectRepo.byExam(examId);

    // 1) 完整性：每科 entering_status=3 且覆盖 roster（force 可放行并在 dryRun 报告标注）
    const coverage = await this.coverageRepo.check(examId);
    if (!coverage.complete && !opts.force) throw new BizError('SCORE-4093', coverage.report);

    // 2) 计算并冻结：班级排名 → 年级排名 → 加权总分排名 → 统计快照
    const version = exam.version;                                 // 撤回重发时已在 revoke 中 version+1
    const ctx = await this.rankService.computeAll(exam, subjects);
    await this.rankSnapRepo.bulkInsert(examId, version, ctx.rankRows);
    await this.statRepo.bulkInsert(examId, version, ctx.stats);

    // 3) 回填 student_exam_score 排名字段 + 状态推进（同事务）
    await this.scoreRepo.backfillRanks(examId, ctx.rankIndex);
    await this.examRepo.publish(examId, version);                 // status=PUBLISHED, publish_time=now
    await this.statusLog.insert(examId, exam.status, 'PUBLISHED', opts.operatorId);

    // 4) ClickHouse 趋势明细（失败仅告警，不回滚主事务）
    await this.chSink.appendAsync(examId, version, ctx);

    // 5) 领域事件（事务提交后由 Outbox 投递）
    await this.outbox.append({
      type: 'ScorePublished',
      payload: { examId, schoolId: exam.schoolId, gradeId: exam.gradeId,
                 examVersion: version, subjectCodes: subjects.map(s => s.subjectCode),
                 studentIds: ctx.studentIds, notifyPolicy: opts.notifyPolicy },
      occurredAt: new Date()
    });
    return { examId, examVersion: version };
  }
}
```

> Outbox + MQ 投递遵循《服务端-分布式事务补偿与最终一致性保障策略》；发布接口以 `examId+version` 幂等，重复调用返回既有结果。

```typescript
// score-center/service/visibility.ts
export class VisibilityService {
  /** 输出某角色对指定学生成绩的可见字段集；BFF 与查询层共用 */
  resolve(viewer: Viewer, studentId: bigint, policy: RankingPolicy): FieldSet {
    const self = viewer.userId === studentId;
    if (viewer.role === 'STUDENT') return self
      ? this.studentView(policy) : DENY;
    if (viewer.role === 'PARENT') {
      return this.bindingRepo.isBound(viewer.userId, studentId)
        ? this.studentView(policy) : DENY;
    }
    if (viewer.role === 'TEACHER') {
      // 任课教师：可见本班本学科全部学生（教学必需）；非本班 → 拒绝
      return this.scopeRepo.teachesClassSubject(viewer.userId, this.ctx)
        ? TEACHER_FULL : DENY;
    }
    if (viewer.role === 'HEAD_TEACHER') { /* 班主任：本班全科目 FULL */ }
    if (viewer.role === 'GRADE_DIRECTOR') { /* 本年级：FULL，无个体明细外泄到报表导出需审批 */ }
    return DENY;
  }

  private studentView(p: RankingPolicy): FieldSet {
    const f: FieldSet = { score: true, level: true, classAvg: true, gradeAvg: true, percentile: true };
    // 合规默认：低于 minGradeToShowRank 的年级不返回具体名次，仅百分位区间
    if (p.showRank && this.ctx.gradeNo >= p.minGradeToShowRank) f.rank = true;
    else f.percentileBand = true;   // 如 "超过全网85%的同学" → 前15%区间
    return f;
  }
}
```

## 6. 状态流转

### 6.1 考试成绩状态机（school_exam.status）

```text
DRAFT(1) ──open-entering──► SCORE_ENTERING(2) ──publish──► PUBLISHED(4)
   ▲                            │    ▲                        │
   │                            │    └── submit-review ──► SCORE_REVIEW(3)
   │                            │                              │ publish
   │                            ▼                              ▼
   └──────────────────── REVOKED(5) ◄────────────────── revoke(4)
                                │  reason 必填
                                └── re-enter → SCORE_ENTERING(2)（version+1）
PUBLISHED ──archive(学期结束+90天)──► ARCHIVED(6)   [终态，仅可查询]
```

| 迁移 | 守卫条件 | 副作用 |
| --- | --- | --- |
| DRAFT→ENTERING | 至少1个科目配置 | 写状态日志 |
| ENTERING→REVIEW | 可选人工复核环节 | 冻结录入（导入/录入API拒绝） |
| ENTERING/REVIEW→PUBLISHED | 覆盖完整或 force；无未关闭申诉阻塞（可配置） | 发布事务 §5.3 |
| PUBLISHED→REVOKED | reason 必填；版本保留 | 全端查询置灰文案；事件 ScoreRevoked |
| REVOKED→ENTERING | version+1 | 旧版本快照隔离可查 |

非法迁移统一返回 `SCORE-4090`（状态冲突），并记录告警日志。

### 6.2 导入批次状态机（score_import_batch.status）

```text
UPLOADED(1) → PARSING(2) → VALIDATING(3) → WAIT_CONFIRM(4) → COMMITTING(5) → COMMITTED(6)
                  │              │                │
                  └──── FAILED(7)（解析/系统异常，可重新上传）
                                 └── 用户主动取消 → CANCELLED(8)
规则：仅 WAIT_CONFIRM 可 commit；FAILED/CANCELLED 批次不写成绩；同科目进行中批次互斥（锁）。
```

### 6.3 复核申诉状态机（score_appeal.status）

```text
SUBMITTED(1) → REVIEWING(2) → APPROVED(3) ─(分数变更，重算+通知)→ CLOSED(5)
                   └────────► REJECTED(4) ────────────────────────► CLOSED(5)
SLA：REVIEWING 起 3 个工作日内处理，超时进入提醒队列（通知域频控）。
```

## 7. 事件与联动

### 7.1 领域事件（MQ topic：`score.center.event`，CelesDB/RocketMQ Tag 区分）

| 事件 | 触发时机 | 主要消费者 |
| --- | --- | --- |
| ScorePublished | 发布事务提交后（Outbox） | 通知服务（学生/家长推送）、学情分析融合、错题服务（考后错题归档提醒）、学习报告、数据仓库 |
| ScoreRevoked | 撤回 | 通知服务、学情分析（撤销融合证据） |
| ScoreAppealResolved | 复核通过且分数变更 | 通知服务、数据仓库（修正流） |
| ScoreImportCommitted | 导入确认 | 教师端进度提醒 |
| ScorecardExportReady | 导出任务完成 | 通知中心（文件投递） |

事件信封示例：

```json
{
  "eventId": "evt-20260814-0001",
  "type": "ScorePublished",
  "occurredAt": "2026-08-14T10:30:00+08:00",
  "payload": {
    "examId": 660001, "schoolId": 9001, "gradeId": 7, "examVersion": 1,
    "subjectCodes": ["MATH","CHNS","ENG","TOTAL"], "studentCount": 142,
    "studentIds": ["[分页游标引用，>500人时走附件URL]"],
    "notifyPolicy": { "pushStudent": true, "pushParent": true }
  }
}
```

> 学生 ID 超过 500 人时 payload 内改用对象存储附件 URL（含签名，24h 有效），避免大消息。

### 7.2 与学情分析的融合约定

- 校内成绩作为**结果性证据**进入《多渠道学习数据融合》引擎，默认权重低于平台内即时作答数据，且按 `score_rate` 与平台同知识点掌握度偏差 >0.3 时触发"平台练习表现 vs 校内考试"差异预警（供家长报告引用）。

## 8. 隐私、合规与安全

1. **最小化展示**：默认策略下，小学 1-3 年级不返回具体名次（仅等级 + 百分位区间）；学校可收紧不可放宽（`ranking_policy` 写入时服务端强制 clamp）。
2. **排名焦虑防护**：通知文案不包含名次数字（"成绩已发布，点击查看"），名次仅在 App 内查看；连续两次年级排名下滑 ≥30% 时，家长推送附学习建议而非单纯排名播报（联动学习干预编排）。
3. **导出管控**：批量名单导出一律走审批流（管理后台）+ 审计日志；导出文件带水印（复用客户端数字水印体系的服务端签章字段 `exportAuditId`）。
4. **审计**：所有状态迁移、导出、复核处理写 `score_status_log` / 审计日志服务，保留 ≥2 年。
5. **未成年人数据**：成绩属个人教育信息，遵循《未成年人数据隐私合规》引擎的数据主体权利流程（导出/删除请求中成绩按"导出可满足、删除走账户注销级联"处理）。
6. **接口安全**：导入文件类型/大小白名单（xlsx ≤10MB）、行数上限 2000、上传频率限制（教师 10 次/小时）；防越权依赖统一数据权限框架 + 本服务二次校验双重防线。

## 9. 错误处理

### 9.1 错误码表

| 错误码 | HTTP | 场景 | 处理建议 |
| --- | --- | --- | --- |
| SCORE-4001 | 400 | 考试档案参数缺失/非法 | 修正后重试 |
| SCORE-4002 | 400 | 满分/及格线/优秀线关系非法（及格≥满分等） | 修正科目配置 |
| SCORE-2031 | 422 | 手动录入部分条目被拒 | 按 data.rejected 明细修正 |
| SCORE-4011 | 401 | 未登录/令牌失效 | 重新登录 |
| SCORE-4031 | 403 | 数据范围外（非本班/非本年级） | 不重试，前端隐藏入口 |
| SCORE-4041 | 404 | 考试/批次/成绩不存在 | 检查 ID |
| SCORE-4090 | 409 | 状态机非法迁移 | 刷新详情页状态 |
| SCORE-4091 | 409 | 重复提交复核申请 | 展示已有申诉单 |
| SCORE-4092 | 409 | 同科目导入批次冲突 | 等待当前批次结束 |
| SCORE-4093 | 409 | 发布覆盖不完整 | 查看报告，补录或 force |
| SCORE-5001 | 500 | 发布事务失败（已回滚） | 可安全重试（幂等） |
| SCORE-5002 | 500 | ClickHouse 写入失败 | 仅告警，自动补偿任务重写 |
| SCORE-5010 | 503 | 依赖（学生名单/学科服务）不可用 | 稍后重试，前端展示降级提示 |

### 9.2 幂等与重试

- 导入：`idempotencyKey` 唯一索引兜底；重复上传返回既有 batchId。
- 发布：`examId+version` 幂等；MQ 消费方按 `eventId` 去重（通知域已有去重表）。
- 复核重算：`recomputeSubject` 以 score 行乐观锁 `version` 防并发双写。
- ClickHouse 写入失败进入补偿队列，指数退避重试 5 次后转人工。

### 9.3 降级策略

- 学生名单服务不可用：导入暂停（批次 FAILED，可重试），手动录入降级为"仅学籍号精确匹配"。
- 通知服务不可达：发布不阻塞（Outbox 重投），家长最迟在 24h 内收到。
- Redis 故障：读缓存穿透至 MySQL（有限流保护），发布锁降级为 MySQL `GET_LOCK`。

## 10. 性能与容量

| 指标 | 目标 |
| --- | --- |
| Excel 导入（1000 行）解析+校验 | < 20s（异步，P95） |
| 发布计算（单年级 10 班 × 500 人 × 9 科） | < 15s（事务外预计算，事务内仅写） |
| 成绩单详情查询 | P95 < 200ms（缓存命中 < 30ms） |
| 个人趋势查询（10 次考试） | P95 < 300ms（ClickHouse） |
| 单校学期考试档案量 | ~200 场；全国规模按 school_id 分库（64 库起步，与其余业务域分库策略一致） |

写入热点：发布事务批量 `INSERT ... VALUES` 分片 500 行/批；`student_exam_score` 唯一键 upsert 冲突走 `ON DUPLICATE KEY UPDATE raw_score=VALUES(...)`。

## 11. 监控与告警

- 业务指标：导入成功率、发布 P95 耗时、复核 SLA 达标率、发布→家长触达转化。
- 技术指标：Outbox 积压、CH 写入失败数、锁等待次数、4031 占比（越权尝试信号 → 风控）。
- 告警规则：Outbox 积压 > 1000 或 5 分钟无消费；发布失败率 > 1%；CH 补偿队列 > 50；单教师导出 > 5 次/日（异常导出行为）。
