# 端到端流程设计 - 寒暑假专题学习营完整链路

> 文档版本：v1.0 | 创建日期：2026-06-08
> 依赖模块：寒暑假专题与备考冲刺专区-详细设计.md（数据模型与核心定义引用自该文档）

---

## 1. 流程概览

本端到端流程描述学生从**发现营地 → 报名 → 每日学习 → 打卡激励 → 结营总结**的完整用户旅程，以及家长端与运营后台的配套交互。

```
[发现营地] → [查看详情] → [报名/购买] → [入营前诊断测试]
     ↓                                          ↓
[首页卡片展示]                            [生成基础能力画像]
                                               ↓
                                    ┌──── 每日学习循环 ────┐
                                    │ 1. 接收任务提醒       │
                                    │ 2. 进入当日学习任务    │
                                    │ 3. 完成知识点/练习/测验│
                                    │ 4. 查看当日报告       │
                                    │ 5. 打卡分享           │
                                    └──────────┬───────────┘
                                               ↓
                              [全部天数完成 / 营期结束]
                                               ↓
                                    [结营测试 + 学习报告]
                                               ↓
                              [颁发证书/徽章 + 积分奖励]
```

---

## 2. 角色

| 角色 | 说明 |
|------|------|
| 学生 | 参加营地学习的主角 |
| 家长 | 查看孩子营地进度、接收周报 |
| 运营人员 | 创建营地、配置内容、查看数据 |
| 系统 | 自动执行任务解锁、提醒推送、进度计算 |

## 3. 阶段一：营地发现与浏览

### 3.1 用户场景

暑假来临，学生在首页看到推荐的学习营，或通过推送通知、分享链接进入。

### 3.2 客户端流程

```
首页工作台
  │
  ├─ 运营弹窗："暑期学习营开始报名啦！" → 点击 → 营地列表页
  │

  │
  └─ 学习模块入口 → "专题营地" Tab → 营地列表页
```

## 5. 阶段三：每日学习循环（核心循环）

### 5.1 每日触发：任务提醒推送

**触发时间：** 每日设定学习时间前 15 分钟（用户可在营地设置中自定义提醒时间，默认 09:00）

**推送逻辑（服务端定时任务）：**

```
定时任务：camp_daily_reminder
Cron: */15 * * * *   （每15分钟检查一次）
逻辑：
1. 查询所有 status = IN_PROGRESS 的营地
2. 对每个营地，查询 status = IN_PROGRESS 的 enrollment
3. 对每个 enrollment：
   a. 计算当前应完成的天数 = (today - study_start) / 1day
   b. 若 current_day < 应完成天数 → 发送"补学"提醒
   c. 若 current_day == 应完成天数 且 今日任务未完成 → 发送"今日任务"提醒
   d. 获取用户设置的提醒时间，匹配当前时间窗口
4. 批量调用消息推送服务
```

**推送模板：**

```json
{
  "template_id": "camp_daily_reminder",
```

**自适应难度调整（服务端逻辑）：**

```python
def adapt_question_difficulty(session: PracticeSession) -> int:
    """根据已答题正确率动态调整下一题难度"""
    if len(session.answers) < 2:
        return session.base_difficulty

    recent_accuracy = calculate_recent_accuracy(session.answers, window=3)

    if recent_accuracy >= 0.85:
        # 连续答对 → 提升难度
        return min(session.current_difficulty + 1, 5)
    elif recent_accuracy <= 0.4:
        # 连续答错 → 降低难度
        return max(session.current_difficulty - 1, 1)
    else:
        return session.current_difficulty
```

### 5.6 当日完成 → 打卡与激励

**打卡触发（服务端）：**

```python
async def on_day_completed(enrollment: CampEnrollment, day_number: int):
    """当日全部任务完成后的级联处理"""
    tasks = []

    # 1. 更新连续打卡天数
    streak = calculate_streak(enrollment)
    enrollment.current_day = day_number
    enrollment.completed_days.append(day_number)

    # 2. 积分奖励（基础 + 连续打卡加成）
    base_points = 20
    streak_bonus = min(streak * 5, 50)  # 上限50
    total_points = base_points + streak_bonus
    tasks.append(award_points(enrollment.user_id, total_points, source="camp_daily"))

    # 3. 打卡事件写入事件流
    tasks.append(emit_event("camp.daily_checkin", {
        "user_id": enrollment.user_id,
        "camp_id": enrollment.camp_id,
        "day_number": day_number,
        "streak_days": streak,
    }))

    # 4. 更新排行榜分数
    day_score = calculate_day_score(enrollment, day_number)
    tasks.append(update_leaderboard(
        f"camp:{enrollment.camp_id}:ranking",
        enrollment.user_id,
        score_increment=day_score
    ))

    # 5. 家长推送
    if day_number % 7 == 0:  # 每周推送
        tasks.append(send_parent_weekly_report(enrollment))

    await asyncio.gather(*tasks)
```

**得分计算公式：**

```python
def calculate_day_score(enrollment: CampEnrollment, day_number: int) -> float:
    """计算当日学习得分"""
    task_records = get_day_task_records(enrollment.id, day_number)

    # 基础分 = 任务完成度 × 60
    completion_rate = len([r for r in task_records if r.status == "completed"]) / len(task_records)
    base_score = completion_rate * 60

    # 正确率加分 = 平均正确率 × 30
    accuracy_scores = [r.accuracy for r in task_records if r.accuracy is not None]
    accuracy_bonus = (sum(accuracy_scores) / len(accuracy_scores) * 30) if accuracy_scores else 0

    # 速度加分 = 当日完成时间越早分越高（前20%满分10分）
    day_start = get_day_start_time(enrollment.camp_id, day_number)
    completion_time = max(r.completed_at for r in task_records)
    hours_elapsed = (completion_time - day_start).total_seconds() / 3600
    speed_bonus = max(0, 10 - hours_elapsed) if hours_elapsed < 10 else 0

    return round(base_score + accuracy_bonus + speed_bonus, 1)
```

```python
    # 1. 学习时长汇总
    total_minutes = sum(r.time_spent_seconds for r in all_records) / 60

    accuracy_records = [r.accuracy for r in all_records if r.accuracy is not None]
```

## 9. 异常与降级处理

### 9.1 常见异常场景

| 场景 | 表现 | 处理策略 |
|------|------|----------|
| 营地进行中用户降级/取消会员 | 会员专属营地无法继续 | 允许已完成天数保留，未开始天数锁定，提示续费 |
| 付费营地支付超时 | 订单状态不明确 | 定时对账，超时30分钟自动关闭订单 |
| AI服务不可用 | 知识点讲解无法生成 | 展示缓存的历史讲解，降级为纯文本题目 |
| 用户设备时间被篡改 | 每日任务解锁异常 | 以服务端时间为准，客户端时钟不参与判断 |
| 营地过期后用户未完成 | 任务不可继续 | 允许查看已学内容，标记"未完赛"，不颁发证书 |
| 大量用户同时入营 | 服务端压力 | 排行榜更新异步化，报名接口做限流（100 QPS/营） |

### 9.2 关键降级策略

```python
class CampDegradationPolicy:
    """营地服务降级策略"""

    @staticmethod
    async def handle_ai_unavailable(task: CampTask):
        """AI服务不可用时的降级"""
        if task.task_type == CampTaskType.KNOWLEDGE_REVIEW:
            # 降级为展示预缓存的标准教材讲解
            return await get_cached_lesson(task.config.knowledge_point_ids)
        elif task.task_type == CampTaskType.PRACTICE:
            # 练习题不受AI影响，正常出题
            return await get_practice_questions(task.config)
        elif task.task_type == CampTaskType.QUIZ:
            # 测验正常进行，但延迟批改主观题
            return await get_quiz_questions(task.config, delay_subjective=True)

    @staticmethod
    async def handle_redis_unavailable():
        """Redis不可用时的排行榜降级"""
        # 1. 排行榜展示缓存快照
        # 2. 积分先写入DB，Redis恢复后同步
        # 3. 不影响核心学习流程
        pass
```

## 12. 性能与并发考虑

| 关注点 | 方案 |
|--------|------|
| 营地开课日高峰 | 营地首页数据预缓存，定时任务提前生成每日任务 |
| 排行榜实时更新 | Redis Sorted Set + 5分钟批量同步DB |
| 打卡并发写入 | 积分操作异步化，先写缓存后异步入库 |
| 结营报告生成 | 异步生成，前端轮询或WebSocket推送 |
| 电子证书生成 | PDF渲染走异步任务队列，完成后推送下载链接 |
| 营地列表查询 | 分页 + Redis缓存热门营地列表（TTL 5分钟） |

## 13. 数据一致性保障

| 操作 | 一致性要求 | 保障策略 |

| 排行榜排名 | 最终一致 | Sorted Set实时，DB定期快照 |
| 结营证书 | 最终一致 | 生成后异步通知 |
