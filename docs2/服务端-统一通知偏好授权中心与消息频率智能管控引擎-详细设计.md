# 服务端-统一通知偏好授权中心与消息频率智能管控引擎-详细设计

## 1. 概述

### 1.1 功能定位

统一通知偏好授权中心（Notification Preference & Authorization Center，简称 NPAC）是 PrimeTop 平台消息通知体系中的**授权网关**，位于通知生成方（业务系统）与通知发送方（推送通道/短信网关/站内消息）之间。

**核心职责：**
- 管理用户对不同类型通知的订阅与退订偏好
- 在通知发出前进行授权校验（该用户是否允许接收该类通知？）
- 执行多维度频率管控（每日上限、冷却间隔、聚合窗口）
- 管理安静时段（Do Not Disturb）与免打扰规则
- 提供合规审计能力（用户同意记录、退订追溯）

**在通知架构中的位置：**

```
┌─────────────┐     ┌───────────────────┐     ┌──────────────────┐
│ 业务系统     │────▶│ 通知偏好授权中心   │────▶│ 多渠道发送网关    │
│ (学习提醒/   │     │ (NPAC)            │     │ (Push/SMS/      │
│  运营活动/   │     │                   │     │  站内/Email)     │
│  系统公告等) │     │ ✓ 偏好校验        │     │                  │
└─────────────┘     │ ✓ 频率管控        │     └──────────────────┘
                     │ ✓ 安静时段        │
                     │ ✓ 优先级仲裁      │
                     │ ✓ 合规审计        │
                     └───────────────────┘
```

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 精准触达 | 只发送用户愿意接收的通知，减少打扰 |
| 频率可控 | 防止通知轰炸，保障用户体验 |
| 合规遵从 | 满足《个人信息保护法》《未成年人保护法》对消息推送的合规要求 |
| 高性能 | 单次授权校验延迟 < 5ms（P99） |
| 可扩展 | 支持新通知类型、新渠道的快速接入 |
| 可观测 | 全链路审计，每次拦截/放行可追溯 |

### 1.3 适用范围

- 学生端推送通知（学习提醒、任务到期、错题复习等）
- 家长端推送通知（学情报告、孩子使用情况等）
- 运营类通知（活动推广、优惠信息、新功能上线等）
- 系统类通知（维护公告、安全提醒、账号通知等）
- 教师/管理员端通知（作业提交提醒、审批待办等）

## 2. 通知分类体系

### 2.1 通知分类模型

采用 **三级分类** 体系：大类 → 中类 → 具体场景。

| 大类 (category_l1) | 中类 (category_l2) | 场景 (scene_code) | 默认状态 | 可退订 |
|---|---|---|---|---|
| **learning** (学习类) | reminder | daily_study_reminder (每日学习提醒) | ✅ 开启 | ✅ |
| | reminder | task_due_reminder (任务到期提醒) | ✅ 开启 | ✅ |
| | reminder | mistake_review_reminder (错题复习提醒) | ✅ 开启 | ✅ |
| | progress | mastery_improvement (掌握度提升) | ✅ 开启 | ✅ |
| | progress | weak_point_warning (薄弱点预警) | ✅ 开启 | ✅ |
| | report | weekly_report (周报生成) | ✅ 开启 | ✅ |
| | report | monthly_report (月报生成) | ✅ 开启 | ✅ |
| **social** (社交类) | interaction | class_message (班级消息) | ✅ 开启 | ✅ |
| | interaction | teacher_feedback (教师反馈) | ✅ 开启 | ✅ |
| | interaction | peer_interaction (同伴互动) | ✅ 开启 | ✅ |
| **operation** (运营类) | promotion | discount_activity (优惠活动) | ❌ 关闭 | ✅ |
| | promotion | new_feature (新功能推荐) | ❌ 关闭 | ✅ |
| | promotion | membership_benefit (会员权益提醒) | ❌ 关闭 | ✅ |
| | event | holiday_event (节日活动) | ❌ 关闭 | ✅ |
| **system** (系统类) | account | security_alert (安全提醒) | ✅ 强制开启 | ❌ |
| | account | login_reminder (登录提醒) | ✅ 强制开启 | ❌ |
| | platform | maintenance_notice (维护公告) | ✅ 强制开启 | ❌ |
| | platform | policy_update (政策更新) | ✅ 强制开启 | ❌ |
| **parent** (家长类) | report | child_weekly_report (孩子周报) | ✅ 开启 | ✅ |
| | report | child_usage_alert (孩子使用异常) | ✅ 强制开启 | ❌ |
| | report | child_safety_warning (安全预警) | ✅ 强制开启 | ❌ |

### 2.2 通知优先级

```
P0_CRITICAL  — 不可退订、不可静音（安全警报、未成年人保护预警）
P1_HIGH      — 默认开启、可退订、安静时段静音 unless 紧急
P2_NORMAL    — 默认开启、可退订、安静时段静音
P3_LOW       — 默认关闭、可退订、安静时段静音、可聚合
```

### 2.3 渠道策略矩阵

每个通知场景与渠道有默认适配关系：

| 场景类型 | Push推送 | SMS短信 | 站内消息 | Email |
|---|---|---|---|---|
| 学习提醒 | ✅ 主渠道 | ⚠️ 仅付费用户 | ✅ | ❌ |
| 任务到期 | ✅ 主渠道 | ❌ | ✅ | ❌ |
| 学情报告 | ✅ | ❌ | ✅ 主渠道 | ⚠️ 可选 |
| 运营活动 | ✅ | ❌ | ✅ | ❌ |
| 安全警报 | ✅ 强制 | ✅ 强制 | ✅ | ⚠️ |
| 家长报告 | ✅ | ❌ | ✅ | ⚠️ 可选 |

## 3. 数据结构定义

### 3.1 核心表设计

#### 3.1.1 `notify_preference` — 用户通知偏好表

```sql
CREATE TABLE notify_preference (
    id              BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    user_id         BIGINT       NOT NULL COMMENT '用户ID',
    scene_code      VARCHAR(64)  NOT NULL COMMENT '通知场景编码',
    category_l1     VARCHAR(32)  NOT NULL COMMENT '一级分类',
    category_l2     VARCHAR(32)  NOT NULL COMMENT '二级分类',
    
    -- 渠道偏好
    push_enabled    TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '推送是否开启',
    sms_enabled     TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '短信是否开启',
    inapp_enabled   TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '站内消息是否开启',
    email_enabled   TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '邮件是否开启',
    
    -- 频率偏好
    max_per_day     INT          NULL     COMMENT '每日最大接收数(null=使用默认)',
    cooldown_min    INT          NULL     COMMENT '同类通知最小间隔(分钟)',
    
    -- 安静时段
    dnd_enabled     TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '是否启用自定义安静时段',
    dnd_start       TIME         NULL     COMMENT '安静时段开始时间',
    dnd_end         TIME         NULL     COMMENT '安静时段结束时间',
    
    -- 元数据
    is_system_forced TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '系统强制(不可退订)',
    source          VARCHAR(16)  NOT NULL DEFAULT 'default' COMMENT '偏好来源: default/user/inferred',
    
    created_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_scene (user_id, scene_code),
    KEY idx_user_category (user_id, category_l1),
    KEY idx_scene (scene_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户通知偏好表';
```

### 3.2 Redis 数据结构

#### 3.2.1 用户偏好缓存

```
Key:    npac:pref:{userId}
Type:   Hash
Fields: {scene_code} -> {push:1,sms:0,inapp:1,email:0,dnd:1,dnd_s:22:00,dnd_e:07:00,max_day:20,cd_min:10}
TTL:    24h（被动刷新）
```

#### 3.2.2 频率计数器

```
# 小时计数器
Key:    npac:freq:h:{userId}:{scene_code}:{yyyyMMddHH}
Type:   String (INCR)
TTL:    2h

# 日计数器
Key:    npac:freq:d:{userId}:{category_l1}:{yyyyMMdd}
Type:   String (INCR)
TTL:    48h

# 周计数器
Key:    npac:freq:w:{userId}:{yyyyMMdd_week}
Type:   String (INCR)
TTL:    8d

# 最近发送时间（冷却间隔）
Key:    npac:freq:last:{userId}:{scene_code}
Type:   String (timestamp)
TTL:    24h
```

#### 3.2.3 安静时段缓存

```
# 用户安静时段
Key:    npac:dnd:{userId}
Type:   Hash
Fields: enabled -> 1
        start -> "22:00"
        end -> "07:00"
TTL:    24h

# 全局安静时段
Key:    npac:dnd:global:{userSegment}
Type:   Hash
Fields: start -> "21:00"
        end -> "07:00"
        floor -> "P2_NORMAL"
TTL:    1h
```

#### 3.2.4 布隆过滤器 — 日内已发送去重

```
Key:    npac:sent:bf:{userId}:{yyyyMMdd}
Type:   BloomFilter (capacity=1000, errorRate=0.001)
TTL:    36h
```

## 4. API 接口设计

### 4.1 通知授权校验接口（核心）

**POST** `/api/v1/npac/authorize`

通知发送前调用，校验是否允许发送。

**请求：**
```json
{
    "trace_id": "trace_20260814_001",
    "user_id": 10000168,
    "scene_code": "daily_study_reminder",
    "category_l1": "learning",
    "category_l2": "reminder",
    "priority": "P2_NORMAL",
    "intended_channels": ["push", "inapp"],
    "notification_id": "notif_20260814_00001",
    "scheduled_time": "2026-08-14T19:00:00+08:00",
    "metadata": {
        "content_summary": "今天的数学作业还有2道题未完成",
        "deep_link": "/study/plan/today"
    }
}
```

**响应（放行）：**
```json
{
    "code": 0,
    "data": {
        "decision": "PASS",
        "actual_channels": ["push", "inapp"],
        "send_time": "2026-08-14T19:00:00+08:00",
        "dispatch_id": "disp_20260814_00001",
        "rules_evaluated": [
            {"rule": "preference_check", "result": "PASS"},
            {"rule": "frequency_check", "result": "PASS", "remaining_today": 4},
            {"rule": "dnd_check", "result": "PASS"},
            {"rule": "cooldown_check", "result": "PASS"}
        ]
    }
}
```

**响应（拦截）：**
```json
{
    "code": 0,
    "data": {
        "decision": "BLOCK",
        "block_reason": "USER_UNSUBSCRIBED",
        "actual_channels": [],
        "send_time": null,
        "dispatch_id": "disp_20260814_00002",
        "rules_evaluated": [
            {"rule": "preference_check", "result": "BLOCK", "reason": "USER_UNSUBSCRIBED"}
        ]
    }
}
```

**响应（延迟）：**
```json
{
    "code": 0,
    "data": {
        "decision": "DELAY",
        "delay_until": "2026-08-15T07:00:00+08:00",
        "delay_reason": "DND_ACTIVE",
        "actual_channels": ["push", "inapp"],
        "dispatch_id": "disp_20260814_00003"
    }
}
```

**响应（聚合）：**
```json
{
    "code": 0,
    "data": {
        "decision": "DIGEST",
        "digest_type": "daily",
        "digest_send_time": "2026-08-15T08:00:00+08:00",
        "dispatch_id": "disp_20260814_00004",
        "queued_item_count": 3
    }
}
```

### 4.2 批量授权校验接口

**POST** `/api/v1/npac/authorize/batch`

用于群发通知前的批量校验（如运营活动）。

```json
{
    "trace_id": "trace_20260814_002",
    "scene_code": "discount_activity",
    "category_l1": "operation",
    "priority": "P3_LOW",
    "intended_channels": ["push"],
    "user_ids": [10000168, 10000169, 10000170],
    "scheduled_time": "2026-08-14T10:00:00+08:00"
}
```

**响应：**
```json
{
    "code": 0,
    "data": {
        "total": 3,
        "pass_count": 2,
        "block_count": 1,
        "results": [
            {"user_id": 10000168, "decision": "PASS"},
            {"user_id": 10000169, "decision": "PASS"},
            {"user_id": 10000170, "decision": "BLOCK", "reason": "USER_UNSUBSCRIBED"}
        ]
    }
}
```

## 5. 核心业务逻辑

### 5.1 授权校验决策流程

授权校验是 NPAC 的核心逻辑，采用 **责任链模式** 串联多个校验节点：

```
通知请求进入
       │
       ▼
┌──────────────────┐     REJECT
│ 1. 基础校验      │──────────▶ 记录日志 → 返回BLOCK
│ (用户存在性/     │
│  场景有效性)     │
└────────┬─────────┘
         │ PASS
         ▼
┌──────────────────┐     REJECT
│ 2. 偏好校验      │──────────▶ 记录日志 → 返回BLOCK
│ (用户是否订阅    │
│  该场景)         │
└────────┬─────────┘
         │ PASS
         ▼
┌──────────────────┐     REJECT
│ 3. 强制校验      │──────────▶ 记录日志 → 返回BLOCK
│ (系统强制场景    │
│  跳过用户偏好)   │
└────────┬─────────┘
         │ PASS(is_system_forced跳到6)
         ▼
┌──────────────────┐     REJECT
│ 4. 频率校验      │──────────▶ 记录日志 → 返回BLOCK/DIGEST
│ (小时/日/周上限  │
│  冷却间隔)       │
└────────┬─────────┘
         │ PASS
         ▼
┌──────────────────┐     REJECT
│ 5. 安静时段校验  │──────────▶ 记录日志 → 返回DELAY
│ (DND时段/       │
│  优先级穿透)     │
└────────┬─────────┘
         │ PASS
         ▼
┌──────────────────┐
│ 6. 聚合策略校验  │──── 如果命中聚合规则 → 返回DIGEST
│ (是否需要聚合    │
│  而非立即发送)   │
└────────┬─────────┘
         │ PASS
         ▼
┌──────────────────┐
│ 7. 渠道选择      │──── 最终渠道决策
│ (偏好渠道∩可用   │
│  渠道∩默认策略)  │
└────────┬─────────┘
         │
         ▼
   返回 PASS + 渠道列表
```

### 5.2 决策核心代码示例

```java
/**
 * 通知授权校验责任链
 */
@Component
public class AuthorizationPipeline {

    private final List<AuthorizationHandler> handlers;

    public AuthorizationPipeline(
            BasicValidationHandler basicHandler,
            PreferenceCheckHandler preferenceHandler,
            FrequencyCheckHandler frequencyHandler,
            DndCheckHandler dndHandler,
            DigestCheckHandler digestHandler,
            ChannelSelectionHandler channelHandler
    ) {
        this.handlers = List.of(
                basicHandler,
                preferenceHandler,
                frequencyHandler,
                dndHandler,
                digestHandler,
                channelHandler
        );
    }

    /**
     * 执行授权校验
     */
    public AuthorizationResult authorize(NotificationRequest request) {
        AuthorizationContext ctx = AuthorizationContext.from(request);
        
        for (AuthorizationHandler handler : handlers) {
            AuthorizationDecision decision = handler.handle(ctx);
            
            // 记录每个节点的决策
            ctx.recordRuleEvaluation(handler.getName(), decision);
            
            if (decision.isTerminal()) {
                // BLOCK / DELAY / DIGEST 是终态
                ctx.finalize(decision);
                return ctx.buildResult();
            }
            // PASS 继续下一个节点
        }
        
        // 全部通过
        ctx.finalize(AuthorizationDecision.pass(ctx.getResolvedChannels()));
        return ctx.buildResult();
    }
}
```

```java
/**
 * 偏好校验处理器
 */
@Component
@Order(20)
public class PreferenceCheckHandler implements AuthorizationHandler {

    private final NotifyPreferenceCacheService preferenceCache;
    private final NotifyGlobalConfig config;

    @Override
    public String getName() {
        return "preference_check";
    }

    @Override
    public AuthorizationDecision handle(AuthorizationContext ctx) {
        NotificationRequest req = ctx.getRequest();
        
        // 系统强制场景跳过偏好校验
        if (req.isSystemForced()) {
            return AuthorizationDecision.pass();
        }
        
        // 获取用户偏好（带缓存）
        NotifyPreference pref = preferenceCache.getPreference(
                req.getUserId(), req.getSceneCode());
        
        if (pref == null) {
            // 无偏好记录 → 使用默认配置
            SceneDefaultConfig defaultConfig = config.getSceneDefault(req.getSceneCode());
            if (defaultConfig != null && !defaultConfig.isDefaultEnabled()) {
                return AuthorizationDecision.block("SCENE_DEFAULT_DISABLED");
            }
            return AuthorizationDecision.pass();
        }
        
        // 检查各渠道开关
        List<String> allowedChannels = new ArrayList<>();
        for (String channel : req.getIntendedChannels()) {
            if (isChannelEnabled(pref, channel)) {
                allowedChannels.add(channel);
            }
        }
        
        if (allowedChannels.isEmpty()) {
            // 所有渠道都被关闭
            return AuthorizationDecision.block("USER_UNSUBSCRIBED");
        }
        
        ctx.setResolvedChannels(allowedChannels);
        return AuthorizationDecision.pass();
    }
    
    private boolean isChannelEnabled(NotifyPreference pref, String channel) {
        return switch (channel) {
            case "push"  -> pref.isPushEnabled();
            case "sms"   -> pref.isSmsEnabled();
            case "inapp" -> pref.isInappEnabled();
            case "email" -> pref.isEmailEnabled();
            default -> false;
        };
    }
}
```

```java
/**
 * 频率校验处理器

@Component
@Order(30)
public class FrequencyCheckHandler implements AuthorizationHandler {

    private final RedisTemplate<String, String> redis;
    private final NotifyFrequencyRuleService ruleService;

    @Override
    public String getName() {
        return "frequency_check";
    }

    @Override
    public AuthorizationDecision handle(AuthorizationContext ctx) {
        NotificationRequest req = ctx.getRequest();
        long userId = req.getUserId();
        String scene = req.getSceneCode();
        String catL1 = req.getCategoryL1();
        
        // 系统强制场景的 P0_CRITICAL 不做频率限制
        if (req.getPriority() == NotificationPriority.P0_CRITICAL) {
            return AuthorizationDecision.pass();
        }
        
        // 获取适用的频率规则（用户偏好 > 分群规则 > 全局默认）
        FrequencyRule rule = ruleService.resolveRule(userId, scene, catL1);
        if (rule == null) {
            return AuthorizationDecision.pass();
        }
        
        // 检查冷却间隔
        String lastSendKey = "npac:freq:last:" + userId + ":" + scene;
        String lastSendVal = redis.opsForValue().get(lastSendKey);
        if (lastSendVal != null) {
            long lastSendEpoch = Long.parseLong(lastSendVal);
            long minutesSinceLast = (System.currentTimeMillis() - lastSendEpoch) / 60_000;
            if (minutesSinceLast < rule.getMinIntervalMin()) {
                long waitMin = rule.getMinIntervalMin() - minutesSinceLast;
                
                // 如果配置了聚合策略，转为摘要
                if (rule.getAggregationStrategy() != null) {
                    return AuthorizationDecision.digest(rule.getAggregationStrategy());
                }
                return AuthorizationDecision.block("COOLDOWN_ACTIVE")
                        .withMeta("retry_after_minutes", waitMin);
            }
        }
        
        // 检查日上限
        String dayKey = "npac:freq:d:" + userId + ":" + catL1 + ":" 
                        + LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE);
        String dayCountStr = redis.opsForValue().get(dayKey);
        int dayCount = dayCountStr != null ? Integer.parseInt(dayCountStr) : 0;
        
        if (dayCount >= rule.getMaxPerDay()) {
            return AuthorizationDecision.block("DAILY_LIMIT_EXCEEDED")
                    .withMeta("limit", rule.getMaxPerDay())
                    .withMeta("current", dayCount);
        }
        
        // 检查小时上限
        String hourKey = "npac:freq:h:" + userId + ":" + scene + ":" 
                         + LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMddHH"));
        String hourCountStr = redis.opsForValue().get(hourKey);
        int hourCount = hourCountStr != null ? Integer.parseInt(hourCountStr) : 0;
        
        if (hourCount >= rule.getMaxPerHour()) {
            return AuthorizationDecision.block("HOURLY_LIMIT_EXCEEDED")
                    .withMeta("limit", rule.getMaxPerHour());
        }
        
        // 记录剩余配额
        ctx.setMeta("remaining_today", rule.getMaxPerDay() - dayCount);
        
        return AuthorizationDecision.pass();
    }
}
```

```java
/**
 * 安静时段校验处理器
 */
@Component
@Order(40)
public class DndCheckHandler implements AuthorizationHandler {

    private final NotifyDndCacheService dndCache;

    @Override
    public String getName() {
        return "dnd_check";
    }

    @Override
    public AuthorizationDecision handle(AuthorizationContext ctx) {
        NotificationRequest req = ctx.getRequest();
        
        // P0_CRITICAL 穿透安静时段
        if (req.getPriority() == NotificationPriority.P0_CRITICAL) {
            return AuthorizationDecision.pass();
        }
        
        // 获取用户个性化安静时段，无则使用全局默认
        DndConfig dnd = dndCache.getUserDnd(req.getUserId());
        if (dnd == null || !dnd.isEnabled()) {
            // 查全局
            String segment = req.getUserSegment();
            dnd = dndCache.getGlobalDnd(segment);
            if (dnd == null || !dnd.isEnabled()) {
                return AuthorizationDecision.pass();
            }
        }
        
        // 判断当前时间是否在安静时段内
        ZoneId userZone = ZoneId.of(req.getUserTimezone());
        LocalTime now = LocalTime.now(userZone);
        
        boolean inDnd = isTimeInRange(now, dnd.getStart(), dnd.getEnd());
        
        if (!inDnd) {
            return AuthorizationDecision.pass();
        }
        
        // 在安静时段内，检查优先级穿透
        NotificationPriority floor = dnd.getPriorityFloor();
        if (req.getPriority().ordinal() <= floor.ordinal()) {
            // 优先级 >= floor，允许穿透
            return AuthorizationDecision.pass();
        }
        
        // 不允许穿透 → 延迟到安静时段结束后发送
        LocalTime dndEnd = dnd.getEnd();
        LocalDateTime delayUntil = LocalDateTime.of(
                LocalDate.now(userZone), dndEnd).plusDays(
                        dnd.getEnd().isAfter(dnd.getStart()) ? 0 : 1)
                .atZone(userZone).toInstant().atZone(ZoneOffset.UTC)
                .toLocalDateTime();
        
        return AuthorizationDecision.delay(delayUntil, "DND_ACTIVE")
                .withMeta("dnd_window", dnd.getStart() + "-" + dnd.getEnd());
    }
    
    /**
     * 判断时间是否在区间内（支持跨午夜）
     * 例：22:00-07:00 表示晚10点到早7点
     */
    private boolean isTimeInRange(LocalTime now, LocalTime start, LocalTime end) {
        if (start.isBefore(end)) {
            // 不跨午夜：08:00-12:00
            return !now.isBefore(start) && now.isBefore(end);
        } else if (start.isAfter(end)) {
            // 跨午夜：22:00-07:00
            return !now.isBefore(start) || now.isBefore(end);
        } else {
            // start == end，视为全天
            return true;
        }
    }
}
```

```lua
-- NPAC 频率计数更新 + 冷却检查（原子操作）
-- KEYS[1] = hour_count_key
-- KEYS[2] = day_count_key  
-- KEYS[3] = last_send_key
-- ARGV[1] = max_per_hour
-- ARGV[2] = max_per_day
-- ARGV[3] = cooldown_seconds
-- ARGV[4] = current_timestamp_seconds
-- ARGV[5] = hour_ttl_seconds
-- ARGV[6] = day_ttl_seconds

local hourCount = tonumber(redis.call('GET', KEYS[1]) or '0')
local dayCount = tonumber(redis.call('GET', KEYS[2]) or '0')
local maxPerHour = tonumber(ARGV[1])
local maxPerDay = tonumber(ARGV[2])
local cooldownSec = tonumber(ARGV[3])
local now = tonumber(ARGV[4])

-- 检查上限
if hourCount >= maxPerHour then
    return {0, 'HOURLY_LIMIT', hourCount, dayCount}
end
if dayCount >= maxPerDay then
    return {0, 'DAILY_LIMIT', hourCount, dayCount}
end

-- 检查冷却
local lastSend = redis.call('GET', KEYS[3])
if lastSend then
    local elapsed = now - tonumber(lastSend)
    if elapsed < cooldownSec then
        return {0, 'COOLDOWN', hourCount, dayCount, cooldownSec - elapsed}
    end
end

-- 通过所有检查，原子递增
redis.call('INCR', KEYS[1])
redis.call('EXPIRE', KEYS[1], ARGV[5])
redis.call('INCR', KEYS[2])
redis.call('EXPIRE', KEYS[2], ARGV[6])
redis.call('SET', KEYS[3], now, 'EX', ARGV[6])

return {1, 'PASS', hourCount + 1, dayCount + 1}
```

## 6. 聚合与摘要策略

### 6.1 聚合策略类型

| 策略 | 行为 | 适用场景 |
|------|------|----------|
| `MERGE` | 多条通知合并为一条展示（保留全部条目） | 班级消息、同伴互动 |
| `DIGEST` | 多条通知汇总为摘要（提取关键信息） | 运营活动、错题提醒 |
| `HOLD` | 暂存通知，在指定时间批量发出 | 低优先级运营通知 |

### 6.2 摘要聚合流程

```
通知请求 → 授权校验 PASS → 命中聚合规则 → 写入 notify_digest_queue
                                                        │
                                                        ▼
                                         定时任务扫描（每5分钟）
                                                        │
                                                        ▼
                                         到达 scheduled_send_at?
                                                        │ YES
                                                        ▼
                                         聚合 pending_items → 生成摘要
                                                        │
                                                        ▼
                                         调用模板引擎渲染摘要内容
                                                        │
                                                        ▼
                                         通过发送网关投递摘要消息
```

### 6.3 摘要生成代码示例

```java
/**
 * 通知摘要生成器
 */
@Component
public class NotificationDigestBuilder {

    private final NotifyTemplateEngine templateEngine;
    private final NotifyDigestQueueMapper digestMapper;

    /**
     * 处理到期的摘要队列
     */
    @Scheduled(fixedDelay = 300_000) // 每5分钟
    public void processDigestQueue() {
        List<NotifyDigestQueue> readyItems = digestMapper.selectReadyItems(
                LocalDateTime.now(), 100);
        
        for (NotifyDigestQueue item : readyItems) {
            try {
                // 标记为处理中
                digestMapper.updateStatus(item.getId(), "processing");
                
                // 聚合同一用户所有待发摘要
                List<NotifyDigestQueue> userDigests = digestMapper
                        .selectPendingByUser(item.getUserId(), item.getDigestType());
                
                // 生成摘要内容
                DigestContent content = buildDigest(item.getUserId(), userDigests);
                
                // 调模板引擎渲染
                RenderedMessage message = templateEngine.renderDigest(content);
                
                // 发送摘要通知
                sendService.send(item.getUserId(), message);
                
                // 批量标记已发送
                List<Long> ids = userDigests.stream()
                        .map(NotifyDigestQueue::getId).toList();
                digestMapper.batchUpdateStatus(ids, "sent");
                
            } catch (Exception e) {
                log.error("摘要生成失败 userId={} digestId={}", 
                        item.getUserId(), item.getId(), e);
                digestMapper.updateStatus(item.getId(), "pending");
            }
        }
    }
    
    /**
     * 构建摘要内容
     */
    private DigestContent buildDigest(Long userId, List<NotifyDigestQueue> items) {
        DigestContent content = new DigestContent();
        content.setUserId(userId);
        
        // 按场景分组统计
        Map<String, List<DigestItem>> grouped = items.stream()
                .collect(Collectors.groupingBy(NotifyDigestQueue::getSceneCode));
        
        List<DigestSection> sections = new ArrayList<>();
        for (var entry : grouped.entrySet()) {
            DigestSection section = new DigestSection();
            section.setSceneCode(entry.getKey());
            section.setCount(entry.getValue().size());
            
            // 提取每条通知的关键信息
            List<DigestItem> digestItems = entry.getValue().stream()
                    .flatMap(dq -> parsePendingItems(dq.getPendingItems()).stream())
                    .toList();
            section.setItems(digestItems);
            
            sections.add(section);
        }
        
        content.setSections(sections);
        content.setTotalCount(sections.stream().mapToInt(DigestSection::getCount).sum());
        return content;
    }
}
```

### 7.3 DND 延迟消息处理

被 DND 拦截的消息有两种处理方式：

| 优先级 | 处理方式 | 说明 |
|---|---|---|
| P0_CRITICAL | 立即穿透 | 安全预警、未成年人保护 |
| P1_HIGH | 延迟到 DND 结束 | 存入延迟队列，DND 结束后发送 |
| P2_NORMAL | 延迟或丢弃 | 如果有聚合规则则聚合，否则延迟 |
| P3_LOW | 丢弃 | 低优先级通知不延迟发送 |

延迟消息使用延迟队列实现：

```java
/**
 * DND 延迟消息处理器
 */
@Component
public class DndDelayProcessor {

    private final RedisTemplate<String, String> redis;
    private final NotifyDispatchService dispatchService;

    private static final String DELAY_QUEUE_KEY = "npac:dnd:delay:queue";

    /**
     * 将消息加入延迟队列
     */
    public void scheduleDelay(NotificationRequest req, Instant delayUntil) {
        DelayedNotification delayed = new DelayedNotification(
                req.getNotificationId(),
                req.getUserId(),
                req.getSceneCode(),
                req.getIntendedChannels(),
                req.getMetadata()
        );
        
        // 使用 Redis ZSet 按到期时间排序
        redis.opsForZSet().add(
                DELAY_QUEUE_KEY,
                JsonUtils.toJson(delayed),
                delayUntil.getEpochSecond()
        );
    }

    /**
     * 定时扫描到期消息
     */
    @Scheduled(fixedDelay = 60_000) // 每分钟扫描
    public void processDelayedNotifications() {
        long now = Instant.now().getEpochSecond();
        
        // 获取所有到期的延迟消息
        Set<ZSetOperations.TypedTuple<String>> expired = redis.opsForZSet()
                .rangeByScoreWithScores(DELAY_QUEUE_KEY, 0, now);
        
        if (expired == null || expired.isEmpty()) return;
        
        for (var tuple : expired) {
            DelayedNotification delayed = JsonUtils.fromJson(
                    tuple.getValue(), DelayedNotification.class);
            
            // 重新走发送流程（这次跳过 DND 检查，因为已经过了 DND 时段）
            dispatchService.dispatchDelayed(delayed);
            
            // 从延迟队列移除
            redis.opsForZSet().remove(DELAY_QUEUE_KEY, tuple.getValue());
        }
    }
}
```

## 8. 用户偏好智能推断

### 8.1 推断策略

当用户没有手动设置偏好时，系统根据行为模式自动推断：

| 行为信号 | 推断逻辑 | 示例 |
|---|---|---|
| 通知点击率 < 5% | 该类通知可能不受欢迎 | 连续7天推送点击率<5% → 建议关闭 |
| 通知频繁清除 | 用户在通知中心批量删除 | 3天内连续批量清除同类通知 → 建议关闭 |
| 通知打开后停留 < 2s | 误触或快速关闭 | 打开即关 → 降低优先级 |
| 长期不点击学习提醒 | 学习提醒效果不佳 | 30天无点击 → 建议改为每日摘要模式 |
| 高频点击学情报告 | 对报告感兴趣 | 保持或建议增加频率 |

### 8.2 偏好推断代码示例

```java
/**
 * 通知偏好智能推断引擎
 */
@Component
public class PreferenceInferenceEngine {

    private final NotifyInteractionStatsMapper statsMapper;
    private final NotifyPreferenceMapper preferenceMapper;

    /**
     * 定期推断用户偏好建议（每天凌晨执行）
     */
    @Scheduled(cron = "0 0 2 * * ?")
    public void inferPreferences() {
        // 获取最近7天有交互数据的用户
        List<Long> activeUsers = statsMapper.selectActiveUsersInDays(7, 1000);
        
        for (Long userId : activeUsers) {
            List<PreferenceSuggestion> suggestions = new ArrayList<>();
            
            // 检查各类通知的交互指标
            Map<String, SceneInteractionStats> statsMap = 
                    statsMapper.getInteractionStatsByScene(userId, 7);
            
            for (var entry : statsMap.entrySet()) {
                String sceneCode = entry.getKey();
                SceneInteractionStats stats = entry.getValue();
                
                // 低点击率推断
                if (stats.getDeliveryCount() >= 10 
                        && stats.getClickRate() < 0.05) {
                    suggestions.add(new PreferenceSuggestion(
                            sceneCode,
                            "LOW_CLICK_RATE",
                            "您最近7天收到" + stats.getDeliveryCount() 
                                    + "条该类通知，点击率仅" 
                                    + String.format("%.1f%%", stats.getClickRate() * 100)
                                    + "，是否关闭？",
                            SuggestionAction.DISABLE_PUSH
                    ));
                }
                
                // 频繁清除推断
                if (stats.getDismissCount() >= 5 
                        && stats.getDismissRatio() > 0.7) {
                    suggestions.add(new PreferenceSuggestion(
                            sceneCode,
                            "FREQUENT_DISMISS",
                            "您经常清除该类通知，是否关闭推送？",
                            SuggestionAction.DISABLE_PUSH
                    ));
                }
                
                // 建议改为摘要模式
                if (stats.getDeliveryCount() >= 15 
                        && stats.getClickRate() > 0.05 
                        && stats.getClickRate() < 0.2) {
                    suggestions.add(new PreferenceSuggestion(
                            sceneCode,
                            "SUGGEST_DIGEST",
                            "该类通知较多，是否改为每日摘要？",
                            SuggestionAction.ENABLE_DIGEST
                    ));
                }
            }
            
            if (!suggestions.isEmpty()) {
                // 写入偏好建议（客户端在设置页展示）
                preferenceMapper.batchInsertSuggestions(userId, suggestions);
            }
        }
    }
}
```

### 10.2 缓存策略

```
用户偏好缓存更新策略：

1. 用户修改偏好 → 同步更新 DB + 失效 Redis 缓存 → 下次读取重建
2. 管理后台修改默认配置 → 发送 MQ 消息 → 批量失效相关用户缓存
3. 定时全量刷新 → 每天凌晨3点全量预热活跃用户缓存
4. 缓存穿透保护 → 空结果缓存60秒 + 布隆过滤器
```

NPAC 是无状态服务，可水平扩展：
- 所有计数器和状态存储在 Redis 中
- 用户偏好缓存在 Redis 中共享
- DB 通过读写分离承担读压力

### 11.2 降级策略

```java
/**
 * NPAC 降级策略
 */
@Component
public class NpacFallbackHandler {

    /**
     * 当 NPAC 服务不可用时的降级逻辑
     * 由通知发送网关调用
     */
    public AuthorizationResult fallbackAuthorize(NotificationRequest req) {
        // 规则1: 系统强制类通知 → 放行
        if (req.isSystemForced()) {
            return AuthorizationResult.pass(req.getIntendedChannels());
        }
        
        // 规则2: 运营类通知 → 默认拦截（宁可漏发不可乱发）
        if ("operation".equals(req.getCategoryL1())) {
            return AuthorizationResult.block("FALLBACK_BLOCK_OPERATION");
        }
        
        // 规则3: 学习类通知 → 放行（核心业务不中断）
        if ("learning".equals(req.getCategoryL1())) {
            return AuthorizationResult.pass(List.of("push", "inapp"));
        }
        
        // 规则4: 其他 → 仅站内消息
        return AuthorizationResult.pass(List.of("inapp"));
    }
}
```

### 13.3 接入示例（调用方）

```java
/**
 * 业务系统调用 NPAC 示例
 */
@Service
public class StudyReminderService {

    private final NpacClient npacClient;
    private final NotifySendGateway sendGateway;

    public void sendDailyReminder(Long userId, String content) {
        // 1. 构造通知请求
        NotificationRequest request = NotificationRequest.builder()
                .traceId(TraceIdGenerator.next())
                .userId(userId)
                .sceneCode("daily_study_reminder")
                .categoryL1("learning")
                .categoryL2("reminder")
                .priority(NotificationPriority.P2_NORMAL)
                .intendedChannels(List.of("push", "inapp"))
                .notificationId(IdGenerator.nextId())
                .scheduledTime(LocalDateTime.now())
                .metadata(Map.of(
                        "content_summary", content,
                        "deep_link", "/study/plan/today"
                ))
                .build();

        // 2. 调用 NPAC 授权校验
        AuthorizationResult result = npacClient.authorize(request);

        // 3. 根据决策执行
        switch (result.getDecision()) {
            case PASS -> {
                // 放行 → 调用发送网关
                sendGateway.send(request, result.getActualChannels());
            }
            case BLOCK -> {
                // 拦截 → 记录日志，不发送
                log.info("通知被拦截 userId={} reason={} scene={}",
                        userId, result.getBlockReason(), request.getSceneCode());
            }
            case DELAY -> {
                // 延迟 → NPAC 内部处理延迟队列，调用方无需操作
                log.info("通知延迟发送 userId={} delayUntil={}",
                        userId, result.getDelayUntil());
            }
            case DIGEST -> {
                // 聚合 → NPAC 内部处理摘要队列，调用方无需操作
                log.info("通知进入摘要队列 userId={} digestType={}",
                        userId, result.getDigestType());
            }
        }
    }
}
```
