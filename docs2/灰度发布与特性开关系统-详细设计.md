# 灰度发布与特性开关系统 - 详细设计

## 1. 概述

### 1.1 背景

启硕 PrimeTop 面向幼儿至高中全学段用户，功能模块众多，AI 能力依赖外部模型供应商，任何一次全量发布都存在较大风险。需要一套灰度发布与特性开关（Feature Flag）系统，实现：

- 按用户群体（学段、年级、地区、会员状态等）逐步放量
- 出问题时秒级关闭线上功能，无需发版回滚
- A/B 测试不同 AI Prompt、UI 方案的效果
- 跨平台（Android / iOS / Web / 小程序）统一开关控制

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 安全性 | 灰度期间问题功能可秒级关停，不影响主流程 |
| 精细度 | 支持按学段、年级、地区、用户标签、百分比等多维度灰度 |
| 低延迟 | 客户端获取开关状态耗时 < 100ms，支持本地缓存 |
| 低侵入 | 业务代码通过 SDK 调用，无需关心灰度逻辑 |
| 可观测 | 灰度过程有完整日志和指标，支持效果对比分析 |

### 1.3 适用范围

- **服务端**：Java/Kotlin Spring Boot 微服务
- **客户端**：Flutter (Android + iOS)，后续 Web / 小程序
- **管理后台**：React 前端 + 后台 API

## 2. 核心概念

### 2.1 术语定义

| 术语 | 英文 | 说明 |
|------|------|------|
| 特性开关 | Feature Flag / Feature Toggle | 一个布尔或枚举类型的控制变量，决定某功能是否启用 |
| 灰度规则 | Rollout Rule | 定义哪些用户、在什么条件下能看到新功能 |
| 灰度策略 | Rollout Strategy | 放量的方式（百分比、白名单、分群等） |
| 灰度实验 | Experiment / A/B Test | 带效果度量指标的灰度，用于对比不同方案 |
| 开关环境 | Environment | 开发、测试、预发、生产等环境隔离 |
| 命中 | Evaluation | 用户满足灰度规则，获得新功能体验 |

### 2.2 开关类型

```
┌─────────────────────────────────────────────┐
│              Feature Flag Types              │
├──────────────┬──────────────────────────────┤
│ Boolean      │ 简单开/关，适用于功能上线/下线 │
│ Percentage   │ 按百分比放量（0-100%）         │
│ Targeting    │ 按用户属性/标签定向投放         │
│ Variant      │ 多变体（A/B/C...），用于实验    │
│ Scheduled    │ 定时开关（如活动功能定时上线）   │
└──────────────┴──────────────────────────────┘
```

### 3.2 数据流

```
1. 管理员在后台创建/修改开关和灰度规则
2. Flag Service 持久化到 MySQL，推送变更通知（SSE/WebSocket）
3. 客户端启动时拉取全量开关状态，缓存到本地
4. 业务代码调用 SDK 检查开关：SDK 先查本地缓存，过期则同步拉取
5. SDK 将命中事件上报到 Event Tracker，用于效果分析
```

## 5. 评估引擎设计

### 5.1 评估流程

```
输入: flag_key, user_context (user_id, grade, stage, ...)
输出: serve_value (命中的值)

┌─────────────────────────────────────────┐
│ 1. 查找 flag (by key + environment)     │
│    - 不存在 → 返回 defaultValue         │
│    - status=0 → 返回 defaultValue       │
├─────────────────────────────────────────┤
│ 2. 按 priority 降序加载所有 rollout_rule │
├─────────────────────────────────────────┤
│ 3. 逐条评估规则:                         │
│    for rule in rules (desc priority):   │
│      if rule.enabled == false: skip     │
│      if matchConditions(rule, context): │
│        return applyStrategy(rule, ctx)  │
├─────────────────────────────────────────┤
│ 4. 没有规则命中 → 返回 defaultValue     │
└─────────────────────────────────────────┘
```

### 5.2 条件匹配

```java
public class ConditionEvaluator {

    /**
     * 评估单个条件
     */
    public static boolean evaluate(Condition condition, UserContext ctx) {
        String field = condition.getField();
        String op = condition.getOp();
        
        // 从用户上下文获取属性值
        String actualValue = ctx.getAttribute(field);
        if (actualValue == null) return false;
        
        return switch (op) {
            case "eq"  -> actualValue.equals(condition.getValue());
            case "in"  -> condition.getValues().contains(actualValue);
            case "gte" -> compareVersion(actualValue, condition.getValue()) >= 0;
            case "lte" -> compareVersion(actualValue, condition.getValue()) <= 0;
            default    -> false;
        };
    }
    
    /**
     * 评估条件列表（AND 关系）
     */
    public static boolean evaluateAll(List<Condition> conditions, UserContext ctx) {
        return conditions.stream().allMatch(c -> evaluate(c, ctx));
    }
}
```

### 5.3 百分比分桶（一致性哈希）

为保证同一用户多次请求结果一致，采用确定性分桶：

```java
public class PercentageBucket {

    /**
     * 计算用户在某个 flag 下的百分位桶（1-100）
     * 使用 flag_key + user_id 的哈希保证：
     * 1. 同一用户同一开关结果一致
     * 2. 不同开关的用户分布不同（避免所有开关命中同一批用户）
     */
    public static int getBucket(String flagKey, long userId) {
        String input = flagKey + ":" + userId;
        int hash = Math.abs(input.hashCode());
        return (hash % 100) + 1; // 1-100
    }
    
    /**
     * 判断是否在百分比范围内
     * percentage=10 表示桶 1-10 命中
     */
    public static boolean isInRange(String flagKey, long userId, int percentage) {
        int bucket = getBucket(flagKey, userId);
        return bucket <= percentage;
    }
}
```

### 5.4 UserContext 数据结构

```java
public class UserContext {
    private Long userId;
    private String deviceId;
    private String stage;         // 幼儿/小学/初中/高中
    private String grade;         // 具体年级
    private String memberType;    // free/monthly/annual
    private String province;      // 省份
    private String appVersion;    // APP 版本
    private String platform;      // android/ios/web/miniapp
    private Set<String> customTags; // 自定义标签（后台可配置）
    
    /**
     * 根据字段名获取属性值
     */
    public String getAttribute(String field) {
        return switch (field) {
            case "user_id"      -> userId != null ? userId.toString() : null;
            case "device_id"    -> deviceId;
            case "grade"        -> grade;
            case "stage"        -> stage;
            case "member_type"  -> memberType;
            case "province"     -> province;
            case "app_version"  -> appVersion;
            case "platform"     -> platform;
            case "custom_tag"   -> customTags != null ? String.join(",", customTags) : null;
            default             -> null;
        };
    }
}
```

### 7.2 核心方法

```dart
class PrimeTopFeatureFlag {
  /// 检查布尔开关
  bool isEnabled(String flagKey, {bool defaultValue = false}) {
    final flag = _cache.get(flagKey);
    if (flag == null) return defaultValue;
    _reportExposure(flagKey, flag);
    return flag.value?.toLowerCase() == 'true';
  }
  
  /// 获取开关值（通用）
  String getString(String flagKey, {String defaultValue = ''}) {
    final flag = _cache.get(flagKey);
    if (flag == null) return defaultValue;
    _reportExposure(flagKey, flag);
    return flag.value ?? defaultValue;
  }
  
  /// 获取变体（用于 A/B 实验）
  String getVariant(String flagKey, {String defaultVariant = 'control'}) {
    final flag = _cache.get(flagKey);
    if (flag == null) return defaultVariant;
    _reportExposure(flagKey, flag);
    return flag.variant ?? defaultVariant;
  }
  
  /// 获取开关值的 JSON 对象
  dynamic getJSON(String flagKey, {dynamic defaultValue}) {
    final flag = _cache.get(flagKey);
    if (flag == null) return defaultValue;
    _reportExposure(flagKey, flag);
    try {
      return jsonDecode(flag.value ?? '{}');
    } catch (_) {
      return defaultValue;
    }
  }
}
```

### 7.4 缓存与更新策略

```dart
class FeatureFlagCache {
  final Box<dynamic> _box; // Hive 本地存储
  String? _currentVersion;
  
  // 缓存策略：
  // 1. 启动时从本地 Hive 读取（秒开，零网络依赖）
  // 2. 异步拉取服务端全量，对比 version 增量更新
  // 3. 定时轮询（默认5分钟）
  // 4. 收到 SSE 推送时立即更新
  
  Future<void> initialize() async {
    // 第一步：从本地缓存加载
    _loadFromLocal();
    
    // 第二步：异步拉取最新（不阻塞UI）
    _fetchFromServer().then((_) {
      // 第三步：启动定时轮询
      _startPolling();
    });
  }
  
  FlagValue? get(String flagKey) {
    return _box.get('flag:$flagKey');
  }
  
  Future<void> _fetchFromServer() async {
    final response = await _apiClient.fetchFlags(
      cacheVersion: _currentVersion,
    );
    
    if (response.version == _currentVersion) return; // 无变更
    
    // 批量更新本地缓存
    for (final entry in response.flags.entries) {
      await _box.put('flag:${entry.key}', entry.value);
    }
    _currentVersion = response.version;
    await _box.put('flag_version', response.version);
  }
}
```

## 8. 灰度发布典型流程

### 8.1 标准灰度流程

```
阶段1: 内部测试
├── 创建 Boolean 开关，default=false
├── 添加白名单规则：user_id in [内部测试人员ID列表]
├── serve_value = true
└── 内部验证通过

阶段2: 小范围灰度
├── 修改规则为 Percentage 策略
├── 先 1% 放量
├── 监控核心指标：错误率、AI回答质量、用户反馈
├── 无问题 → 5% → 10% → 20% → 50%
└── 每个阶段停留至少 24 小时

阶段3: 全量
├── 设置 serve_value = true，percentage = 100
├── 观察全量稳定性
├── 确认稳定后标记为"待清理"
└── 下一版本移除开关代码
```

### 8.2 紧急关停流程

```
发现线上问题（如AI幻觉严重）
  │
  ▼
管理员在后台点击"紧急关停"
  │  (或调用 POST /api/v1/admin/flags/{id}/toggle {"status":0})
  ▼
Flag Service 更新数据库
  │
  ▼
推送 SSE 变更通知到在线客户端
  │
  ▼
客户端 SDK 收到通知，更新本地缓存
  │  (未在线的客户端下次启动时拉取最新状态)
  ▼
业务代码 flag.isEnabled() 返回 false
  │
  ▼
功能关闭，回退到 defaultValue 对应的旧逻辑
  │
  ▼
总耗时：< 5秒（在线客户端）/ 下次启动（离线客户端）
```

### 8.3 PrimeTop 典型灰度场景

| 场景 | flag_key | 灰度策略 | 示例规则 |

## 9. A/B 实验支持

### 9.1 实验创建流程

```
1. 创建 Variant 类型开关
2. 定义变体：control（对照组）、treatment_a、treatment_b ...
3. 设置变体权重：如 50/50 或 80/10/10
4. 绑定效果指标（通过数据埋点关联）：
   - ai_answer_satisfaction（AI回答满意度）
   - question_solve_rate（解题完成率）
   - essay_score_avg（作文评分均值）
5. 启动实验，收集数据
6. 在管理后台查看实验报表，决策是否全量
```

### 9.2 变体分配

```java
public class VariantAssigner {
    
    /**
     * 基于一致性哈希为用户分配变体
     * bucket = hash(flag_key + user_id) % 1000
     * 然后按权重区间分配
     */
    public static String assign(String flagKey, long userId, Map<String, Integer> weights) {
        String input = flagKey + ":" + userId;
        int hash = Math.abs(input.hashCode()) % 1000;
        
        int totalWeight = weights.values().stream().mapToInt(Integer::intValue).sum();
        int accumulated = 0;
        
        for (Map.Entry<String, Integer> entry : weights.entrySet()) {
            accumulated += (entry.getValue() * 1000 / totalWeight);
            if (hash < accumulated) {
                return entry.getKey();
            }
        }
        
        // 兜底：返回第一个变体
        return weights.keySet().iterator().next();
    }
}
```

## 11. 性能与可靠性

### 11.1 性能目标

| 指标 | 目标 | 实现方式 |
|------|------|----------|
| 全量拉取延迟 | < 100ms (P99) | Redis 缓存 + CDN |
| 单开关评估 | < 5ms (P99) | 本地缓存优先 |
| 紧急关停生效 | < 5s (在线客户端) | SSE 推送 |
| 缓存命中率 | > 95% | 客户端本地 Hive 缓存 |
| 日评估量 | 1000万+/天 | 无状态评估，水平扩展 |

### 11.2 服务端缓存策略

```
请求 → 本地进程缓存 (Caffeine, TTL=30s)
         │ miss
         ▼
       Redis 缓存 (TTL=5min)
         │ miss
         ▼
       MySQL 查询 → 写入 Redis → 写入本地缓存
```

### 11.3 降级策略

```
正常: 客户端 → Feature Flag Service → MySQL
                    │
降级1: Feature Flag Service 不可用
  → 客户端使用本地 Hive 缓存（最长 TTL=24h）
  → 所有开关返回 defaultValue

降级2: MySQL 不可用
  → Feature Flag Service 使用 Redis 缓存继续服务
  → 后台管理界面只读

降级3: 全部不可用
  → 客户端 SDK 返回 defaultValue
  → 业务代码按兜底逻辑运行
```

### 11.4 弱网与离线处理

```dart
// SDK 离线策略
class FeatureFlagCache {
  static const maxCacheAge = Duration(hours: 24);
  
  FlagValue? get(String flagKey) {
    final cached = _box.get('flag:$flagKey');
    if (cached == null) return null;
    
    // 缓存超过24小时视为过期，但仍返回（降级服务）
    final age = DateTime.now().difference(cached.timestamp);
    if (age > maxCacheAge) {
      // 标记为过期，触发异步刷新
      _triggerBackgroundRefresh();
      // 仍返回旧值（不阻塞用户）
    }
    
    return cached;
  }
}
```

## 14. 开关生命周期管理

### 14.1 开关状态流转

```
  创建(DRAFT) ──→ 启用(ACTIVE) ──→ 全量(FULL_ROLLOUT) ──→ 待清理(STALE) ──→ 删除(DELETED)
                    │                                       ▲
                    └──→ 紧急关停(DISABLED) ──→ 重新启用 ──┘
```

### 14.2 清理规范

临时开关（`is_permanent=false`）在以下条件下应被清理：

1. 已全量发布且稳定运行超过 2 周
2. 业务代码中的 `flag.isEnabled()` 调用已移除
3. 清理步骤：
   - 后台标记为 STALE，设置清理提醒
   - 在代码中搜索 flag_key，确认无引用
   - 从数据库删除开关和规则
   - 在 CHANGELOG 中记录
