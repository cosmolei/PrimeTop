# 服务端 - 会员权益使用统计与功能价值感知量化分析引擎 - 详细设计

> **模块定位**：商业智能层 / 会员运营分析  
> **优先级**：P1  
> **依赖模块**：会员订阅服务、用户额度管控与功能门控引擎、学习行为埋点平台、用户活跃度统计、支付订单服务  
> **文档版本**：1.0  
> **最后更新**：2026-08-06

---

## 1. 概述

### 1.1 背景与目标

PrimeTop 采用 Freemium + 会员订阅商业模式，会员可享受 AI 问答、拍照搜题、同步课堂、作文批改、学情分析等多项增值权益。然而当前系统缺乏对**会员权益实际使用情况**的深度量化能力，产品与运营团队面临以下问题：

1. **权益盲区**：不知道哪些会员功能被高频使用、哪些形同虚设。
2. **续费归因模糊**：用户续费到底是因为 AI 对话好用，还是因为拍题次数够多？缺乏数据支撑。
3. **定价缺乏依据**：会员套餐定价和权益打包缺乏用量数据支撑，难以科学调整。
4. **流失预警滞后**：会员停止使用某项核心权益后，往往在到期后才被识别为流失，错失挽留窗口。
5. **新功能效果难评估**：上线新的会员功能后，难以快速评估其对会员满意度和续费的影响。

本引擎旨在构建一套完整的**会员权益使用追踪、价值感知量化、续费归因分析**体系，为产品迭代、定价策略、精细化运营提供数据决策支撑。

### 1.2 核心业务价值

| 价值点 | 说明 |
|--------|------|
| 权益优化 | 识别高使用率与低使用率权益，指导权益打包调整 |
| 续费预测增强 | 将权益使用频度纳入续费影响因子，提升续费预测准确率 |
| 流失早期预警 | 当会员核心权益使用频次骤降时，提前触发挽留策略 |
| 价值感知报告 | 向会员展示"本月已为你节省 XX 元、批改作文 XX 篇"，增强续费动力 |
| 定价科学化 | 基于权益使用数据，支撑按功能定价或模块化订阅方案 |
| A/B 测试度量 | 为会员功能 A/B 测试提供权益级效果度量指标 |

### 1.3 设计原则

- **事件驱动**：基于用户行为埋点实时采集权益使用事件，非侵入式接入。
- **多维归因**：续费归因不依赖单一指标，采用多因子贡献度模型。
- **可解释**：价值感知评分附带 Top 影响因子，运营和产品可理解。
- **低延迟**：权益使用看板查询 P99 < 500ms；价值感知报告生成 < 3s。
- **隐私合规**：未成年人数据脱敏聚合，不产出个人信息级报告。

### 1.4 与现有模块边界

| 现有模块 | 职责 | 本模块差异 |
|----------|------|-----------|
| 会员订阅服务 | 交易履约、权益发放、额度扣减 | 本模块**不处理交易**，只分析权益使用效果 |
| 用户额度管控与功能门控 | 额度校验、功能开关控制 | 本模块**不做运行时拦截**，只消费额度变更事件 |
| LTV 预测与升级意向评分 | 预测用户长期价值与升级概率 | 本模块提供**权益级粒度**数据，作为 LTV 模型的输入特征 |
| 用户活跃度统计与留存分析 | 整体活跃度和留存分析 | 本模块聚焦**会员功能维度**，非整体应用维度 |
| 用户流失预警 | 基于活跃度预测流失 | 本模块提供**权益使用退化**信号，增强流失预警精度 |

| benefit_code | 名称 | 描述 | 计量方式 | 模块来源 |
|--------------|------|------|----------|----------|
| `ai_chat` | AI 智能问答 | 多轮 AI 对话辅导 | 按次（消息轮次） | AI 服务 |

| `photo_search` | 拍照搜题 | OCR 拍题识别+解析 | 按次 | 拍题服务 |
| `photo_multi_question` | 多题同拍 | 单次拍摄多题识别 | 按次 | 拍题服务 |
| `sync_classroom` | 同步课堂完整内容 | 章节预习/复习/练习 | 按章节访问 | 学习服务 |
| `essay_correction` | 作文批改 | AI 作文评分与反馈 | 按次（每篇） | 作文服务 |
| `essay_deep_analysis` | 作文深度分析 | 修辞、结构、素材多维分析 | 按次 | 作文服务 |

| `learning_report` | 学情分析报告 | 详细学情与能力画像 | 按次（每月报告数） | 分析服务 |

### 3.3 价值感知量化模型（Value Perception Model, VPM）

VPM 是本引擎的核心创新，用于回答："这位会员对自己花的钱感到值不值？"

模型输出一个 **Value Perception Score (VPS)**，取值范围 0-100，并附带 Top 影响因子。

### 4.2 权益使用明细表 `benefit_usage_log`（ClickHouse）

```sql
-- ClickHouse 建表：权益使用明细事件，支持高写入吞吐和快速聚合查询
CREATE TABLE benefit_usage_log
(
    event_id          String        COMMENT '事件唯一ID',
    user_id           UInt64        COMMENT '用户ID',
    session_id        String        COMMENT '学习会话ID',
    benefit_code      LowCardinality(String) COMMENT '权益编码',
    event_type        LowCardinality(String) COMMENT '事件类型: usage/refund/grant',
    usage_count       UInt32        COMMENT '本次使用次数(通常为1)',
    quota_before      Int32         COMMENT '使用前剩余额度',
    quota_after       Int32         COMMENT '使用后剩余额度',
    membership_tier   LowCardinality(String) COMMENT '当时会员等级',
    subject           LowCardinality(String) COMMENT '学科上下文',
    grade             LowCardinality(String) COMMENT '年级上下文',
    chapter_id        String        COMMENT '章节ID',
    extra_context     String        COMMENT '附加上下文JSON',
    platform          LowCardinality(String) COMMENT '平台: android/ios/web',
    app_version       String        COMMENT 'APP版本号',
    event_date        Date          COMMENT '事件日期(分区键)',
    event_datetime    DateTime64(3) COMMENT '事件精确时间',
    ingestion_time    DateTime64(3) DEFAULT now64(3) COMMENT '入库时间'
)
ENGINE = MergeTree()
PARTITION BY toYYYYMM(event_date)
ORDER BY (event_date, user_id, benefit_code, event_datetime)
TTL event_date + INTERVAL 730 DAY
SETTINGS index_granularity = 8192;
```

### 4.3 每日益益使用聚合表 `benefit_daily_aggregate`（ClickHouse 物化视图 + Redis 缓存）

```sql
-- ClickHouse 物化视图：按用户×权益×天 自动聚合
CREATE MATERIALIZED VIEW benefit_daily_aggregate_mv
TO benefit_daily_aggregate
AS
SELECT
    user_id,
    benefit_code,
    event_date                                                    AS usage_date,
    sum(usage_count)                                              AS daily_usage_count,
    count()                                                       AS daily_event_count,
    min(event_datetime)                                           AS first_usage_time,
    max(event_datetime)                                           AS last_usage_time,
    any(membership_tier)                                          AS membership_tier,
    any(subject)                                                  AS primary_subject,
    if(sum(usage_count) > 0, 1, 0)                                AS is_used_today
FROM benefit_usage_log
WHERE event_type = 'usage'
GROUP BY user_id, benefit_code, event_date;

-- 目标表
CREATE TABLE benefit_daily_aggregate
(
    user_id           UInt64,
    benefit_code      LowCardinality(String),
    usage_date        Date,
    daily_usage_count UInt32,
    daily_event_count UInt32,
    first_usage_time  DateTime64(3),
    last_usage_time   DateTime64(3),
    membership_tier   LowCardinality(String),
    primary_subject   LowCardinality(String),
    is_used_today     UInt8
)
ENGINE = SummingMergeTree()
PARTITION BY toYYYYMM(usage_date)
ORDER BY (user_id, benefit_code, usage_date);
```

## 5. 权益使用事件采集管线

### 5.1 事件采集架构

权益使用事件通过**事件驱动架构**非侵入式采集，不修改现有业务代码逻辑：

```text
                    ┌─────────────────────────┐
                    │   权益校验/额度扣减      │
                    │   (功能门控引擎)         │
                    └────────┬────────────────┘
                             │ 原有流程不变
                             ▼
                    ┌─────────────────────────┐
                    │   AOP 切面 / 事件拦截器   │
                    │   BenefitUsageInterceptor │
                    └────────┬────────────────┘
                             │ 发送 Kafka 消息
                             ▼
                    ┌─────────────────────────┐
                    │   benefit-usage-events   │
                    │   (Kafka Topic)          │
                    └────────┬────────────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
     ┌──────────────┐ ┌───────────┐ ┌──────────────┐
     │ ClickHouse   │ │ Redis     │ │ Flink        │
     │ 批量写入     │ │ 实时缓存  │ │ 流处理       │
```

```java
@Component
@SLF4J
public class BenefitUsageAspect {

    private BenefitEventProducer eventProducer;

    @Autowired
    private MembershipQueryService membershipQueryService;

    public Object trackBenefitUsage(ProceedingJoinPoint pjp, 
                                     BenefitRequired benefitRequired) throws Throwable {
        String benefitCode = benefitRequired.value();
        Long userId = UserContext.getCurrentUserId();

                .userId(userId)
                .benefitCode(benefitCode)

                .timestamp(LocalDateTime.now())
                .clientInfo(ClientInfo.fromContext());

            // 执行原方法
            result = pjp.proceed();
            
            // 成功使用
            int quotaAfter = membershipQueryService.getRemainingQuota(userId, benefitCode);
            eventBuilder
                .eventType("usage")
                .usageCount(quotaBefore - quotaAfter)
                .quotaAfter(quotaAfter)
                .success(true);
            
            // 从方法参数中提取学习上下文
            enrichLearningContext(pjp.getArgs(), eventBuilder);
            
        } catch (BenefitExhaustedException e) {

            eventBuilder
                .eventType("quota_exhausted")
                .usageCount(0)
                .quotaAfter(0)
                .success(false);
            throw e;
        } catch (Exception e) {
            eventBuilder.eventType("usage_error").success(false);
            throw e;
        } finally {
            // 异步发送事件，不影响主流程
            eventProducer.sendAsync(eventBuilder.build());
        }
        
        return result;
    }

     * 从方法参数中提取学科、年级、章节等学习上下文

                builder.subject(req.getSubject())
                      .grade(req.getGrade())
                      .chapterId(req.getChapterId())
                      .textbookVersion(req.getTextbookVersion());

            }
        }
    }
```

## 6. 价值感知量化模型（VPM）

### 6.1 模型概述

VPM 综合五个维度计算会员的 Value Perception Score (VPS)：

```
VPS = w1 × F_usage_frequency      (使用频度分)
    + w2 × F_benefit_diversity    (权益多样性分)
    + w3 × F_cost_ratio           (成本回收率分)
    + w4 × F_usage_trend          (使用趋势分)
    + w5 × F_engagement_depth     (参与深度分)

默认权重: w1=0.30, w2=0.15, w3=0.25, w4=0.15, w5=0.15
```

### 6.2 维度详解

#### F_usage_frequency（使用频度分，0-100）

衡量会员在当前周期内各项权益的使用频度是否达到"值得"的阈值。

```python
def calc_usage_frequency_score(user_id, cycle_start, cycle_end, benefit_catalog):
    """
    计算使用频度分
    
    逻辑：
    1. 对每项权益，计算周期内使用次数
    2. 与该权益的"合理使用基线"对比
    3. 加权汇总（核心权益权重高）
    """
    scores = []
    weights = []
    
    for benefit in benefit_catalog:
        usage_count = query_cycle_usage(user_id, benefit.code, cycle_start, cycle_end)
        baseline = benefit.expected_monthly_usage  # 基线值，如 ai_chat=100次/月
        
        # 归一化: 达到基线=60分, 超过基线线性增长至100, 低于基线线性下降
        if baseline > 0:
            ratio = usage_count / baseline
            score = min(100, ratio * 60 + (ratio - 1) * 40 if ratio >= 1 
                       else ratio * 60)
        else:
            # bool型权益: 使用过=70分, 没用过=0分
            score = 70.0 if usage_count > 0 else 0.0
        
        # 权重: 核心权益*1.5, pro*1.0, exclusive*0.5
        weight = benefit.category_weight
        scores.append(score * weight)
        weights.append(weight)
    
    return sum(scores) / sum(weights) if weights else 0
```

#### F_benefit_diversity（权益多样性分，0-100）

衡量会员使用了多少种不同的权益功能。只用1-2个功能的会员，价值感知通常脆弱。

```python
def calc_diversity_score(user_id, cycle_start, cycle_end, total_benefit_count):
    """
    使用了全部权益的N% → 100分
    使用了一半 → 60分
    只用了1个 → 20分
    """
    used_count = count_distinct_benefits_used(user_id, cycle_start, cycle_end)
    
    if total_benefit_count == 0:
        return 0
    
    coverage = used_count / total_benefit_count
    
    # 使用覆盖率映射: 100%→100, 50%→60, 25%→35, 10%→15, 0%→0
    # 使用分段映射，覆盖非线性感知
    if coverage >= 0.8:
        return 90 + (coverage - 0.8) * 50  # 90-100
    elif coverage >= 0.5:
        return 60 + (coverage - 0.5) * 100  # 60-90
    elif coverage >= 0.25:
        return 35 + (coverage - 0.25) * 100  # 35-60
    elif coverage > 0:
        return coverage * 140  # 0-35
    else:
        return 0
```

#### F_cost_ratio（成本回收率分，0-100）

衡量会员通过使用权益"回本"的程度。

```python
def calc_cost_ratio_score(user_id, cycle_start, cycle_end, membership_fee):
    """
    计算已使用权益的等效货币价值与会员费的比率
    
    例如: 会员费98元/月
          AI问答用了200次 × 0.5元/次 = 100元
          作文批改3篇 × 15元/次 = 45元
          拍题50次 × 0.3元/次 = 15元
          总价值 = 160元
          回收率 = 160/98 = 163% → 满分100
    """
    total_estimated_value = 0
    
    for benefit in get_user_used_benefits(user_id, cycle_start, cycle_end):
        usage_count = get_cycle_usage(user_id, benefit.code, cycle_start, cycle_end)
        unit_price = benefit.standalone_price or 0
        total_estimated_value += usage_count * unit_price
    
    if membership_fee <= 0:
        return 100  # 免费用户或特殊账号
    
    ratio = total_estimated_value / membership_fee
    
    # 回收率映射: 200%+→100, 100%→80, 50%→50, 25%→25, 0%→0
    if ratio >= 2.0:
        return 100
    elif ratio >= 1.0:
        return 80 + (ratio - 1.0) * 20
    elif ratio >= 0.5:
        return 50 + (ratio - 0.5) * 60
    else:
        return ratio * 100
```

#### F_usage_trend（使用趋势分，0-100）

衡量权益使用频度是在上升还是下降。

```python
def calc_trend_score(user_id, reference_date):
    """
    对比最近14天与前14天的权益使用频度变化
    """
    recent_14 = count_usage_in_range(user_id, reference_date.minus_days(14), reference_date)
    previous_14 = count_usage_in_range(user_id, reference_date.minus_days(28), 
                                        reference_date.minus_days(14))
    
    if previous_14 == 0 and recent_14 == 0:
        return 30  # 双零: 长期未使用, 低分但不为零
    elif previous_14 == 0:
        return 80  # 从零到有: 强趋势
    else:
        change_ratio = (recent_14 - previous_14) / previous_14
        if change_ratio >= 0.2:
            return min(100, 70 + change_ratio * 50)  # 上升: 70-100
        elif change_ratio >= -0.1:
            return 60  # 稳定: 55-70
        elif change_ratio >= -0.3:
            return 40  # 小幅下降: 30-50
        else:
            return max(10, 40 + change_ratio * 30)  # 大幅下降: 10-30
```

#### F_engagement_depth（参与深度分，0-100）

衡量使用权益时是"浅尝辄止"还是"深度使用"。

```python
def calc_engagement_depth_score(user_id, cycle_start, cycle_end):
    """
    参与深度指标:
    - AI对话: 平均每轮对话消息数(>8=深度, <3=浅层)
    - 拍题: 看完解析的比例(>80%=深度)
    - 作文: 使用了深度分析功能的比例
    - 同步课堂: 完成章节练习的比例
    """
    depth_signals = []
    
    # AI 对话深度
    avg_msg_per_conv = get_avg_messages_per_conversation(user_id, cycle_start, cycle_end)
    ai_depth = min(100, avg_msg_per_conv / 10 * 100) if avg_msg_per_conv else 0
    depth_signals.append(("ai_chat", ai_depth, 0.3))
    
    # 拍题解析阅读深度
    photo_total = get_photo_search_count(user_id, cycle_start, cycle_end)
    photo_read_full = get_photo_full_analysis_read_count(user_id, cycle_start, cycle_end)
    photo_depth = (photo_read_full / photo_total * 100) if photo_total > 0 else 0
    depth_signals.append(("photo_search", photo_depth, 0.2))
    
    # 错题复习深度
    mistake_total = get_mistake_count(user_id, cycle_start, cycle_end)
    mistake_reviewed = get_mistake_reviewed_count(user_id, cycle_start, cycle_end)
    review_depth = (mistake_reviewed / mistake_total * 100) if mistake_total > 0 else 50
    depth_signals.append(("mistake_review", review_depth, 0.25))
    
    # 学习计划完成深度
    plan_total = get_plan_task_count(user_id, cycle_start, cycle_end)
    plan_completed = get_plan_completed_count(user_id, cycle_start, cycle_end)
    plan_depth = (plan_completed / plan_total * 100) if plan_total > 0 else 0
    depth_signals.append(("study_plan", plan_depth, 0.25))
    
    total_weight = sum(w for _, _, w in depth_signals)
    weighted_sum = sum(score * w for _, score, w in depth_signals if score is not None)
    
    return weighted_sum / total_weight if total_weight > 0 else 0
```

### 6.3 VPS 计算与分级

```python
class VPMEngine:
    """
    Value Perception Model 主引擎
    每日为所有活跃会员计算 VPS
    """
    
    WEIGHTS = {
        'frequency': 0.30,
        'diversity': 0.15,
        'cost_ratio': 0.25,
        'trend': 0.15,
        'depth': 0.15
    }
    
    def compute_vps(self, user_id: int, reference_date: date) -> VPSCoreResult:
        membership = get_active_membership(user_id, reference_date)
        if not membership:
            return VPSCoreResult(user_id=user_id, score=0, level='none')
        
        cycle_start = membership.cycle_start
        cycle_end = membership.cycle_end
        fee = membership.fee_paid
        benefits = get_applicable_benefits(membership.tier)
        
        # 计算五个维度
        f_freq = calc_usage_frequency_score(user_id, cycle_start, cycle_end, benefits)
        f_div = calc_diversity_score(user_id, cycle_start, cycle_end, len(benefits))
        f_cost = calc_cost_ratio_score(user_id, cycle_start, cycle_end, fee)
        f_trend = calc_trend_score(user_id, reference_date)
        f_depth = calc_engagement_depth_score(user_id, cycle_start, cycle_end)
        
        # 加权汇总
        vps = (self.WEIGHTS['frequency'] * f_freq +
               self.WEIGHTS['diversity'] * f_div +
               self.WEIGHTS['cost_ratio'] * f_cost +
               self.WEIGHTS['trend'] * f_trend +
               self.WEIGHTS['depth'] * f_depth)
        
        vps = round(vps, 2)
        
        # 分级
        level = self._score_to_level(vps)
        
        # Top贡献权益
        top_benefits = self._get_top_contribution_benefits(user_id, cycle_start, cycle_end, fee)
        weak_benefits = self._get_unused_benefits(user_id, cycle_start, cycle_end, benefits)
        
        # 续费意向推断
        renewal_intent = self._infer_renewal_intent(vps, level, f_trend)
        
        # 风险标记
        risk_flags = self._detect_risk_flags(user_id, f_freq, f_trend, f_div)
        
        return VPSCoreResult(
            user_id=user_id,
            score_date=reference_date,
            vps_score=vps,
            vps_level=level,
            top_benefits=top_benefits,
            weak_benefits=weak_benefits,
            usage_diversity=f_div / 100,
            trend_30d='rising' if f_trend > 70 else ('declining' if f_trend < 40 else 'stable'),
            renewal_intent=renewal_intent,
            risk_flags=risk_flags
        )
    
    def _score_to_level(self, score):
        if score >= 80: return 'very_high'
        elif score >= 65: return 'high'
        elif score >= 45: return 'medium'
        elif score >= 25: return 'low'
        else: return 'very_low'
    
    def _infer_renewal_intent(self, vps, level, trend_score):
        """
        基于VPS和趋势推断续费意向
        """
        if level in ('very_high', 'high') and trend_score >= 50:
            return 'likely'
        elif level == 'medium':
            return 'neutral'
        elif level in ('very_low', 'low') and trend_score < 40:
            return 'unlikely'
        else:
            return 'neutral'
    
    def _detect_risk_flags(self, user_id, freq_score, trend_score, div_score):
        flags = []
        
        # 核心权益7天未使用
        last_ai_usage = get_last_usage_date(user_id, 'ai_chat')
        last_photo_usage = get_last_usage_date(user_id, 'photo_search')
        if last_ai_usage and (date.today() - last_ai_usage).days > 7:
            flags.append('核心权益AI问答7天未使用')
        if last_photo_usage and (date.today() - last_photo_usage).days > 7:
            flags.append('核心权益拍照搜题7天未使用')
        
        # 趋势骤降
        if trend_score < 30:
            flags.append('权益使用频次两周内显著下降')
        
        # 多样性极低
        if div_score < 20:
            flags.append('权益使用过于单一, 仅使用少量功能')
        
        return flags
```

## 7. 续费归因分析模型

### 7.1 模型设计

当会员发生续费/流失事件时，系统回溯分析哪些权益的使用模式最显著地影响了决策：

```python
class RenewalAttributionEngine:
    """
    续费归因分析引擎
    
    方法论: Shapley Value 启发的权益贡献度分配
    1. 收集续费用户和未续费用户的权益使用特征
    2. 训练二分类模型预测续费概率
    3. 对每位用户计算各权益特征的 SHAP 值作为贡献度
    """
    
    def __init__(self):
        self.model = None  # 延迟加载
        self.model_version = 'v1.0'
        self.feature_codes = []  # 权益编码列表(特征列)
    
    def attribute_renewal(self, user_id: int, trigger_event: str) -> RenewalAttributionResult:
        """
        对单用户执行续费归因分析
        
        trigger_event: 'renewal' | 'churn_warning' | 'upgrade'
        """
        membership = get_membership(user_id)
        cycle_start = membership.cycle_start
        cycle_end = membership.cycle_end
        
        # 构建特征向量
        features = self._build_feature_vector(user_id, cycle_start, cycle_end)
        
        # 模型预测 + SHAP 值
        if self.model is None:
            self._load_model()
        
        prediction = self.model.predict_proba(features.reshape(1, -1))[0, 1]
        shap_values = self.model.explainer.shap_values(features.reshape(1, -1))
        
        # 贡献度排序
        contributions = []
        for i, code in enumerate(self.feature_codes):
            shap_val = float(shap_values[0][i])
            # SHAP 值转百分比贡献度
            contributions.append({
                'code': code,
                'shap_value': round(shap_val, 4),
                'feature_value': float(features[i]),
                'contribution_pct': 0  # 稍后计算
            })
        
        # 归一化为百分比
        total_positive = sum(max(0, c['shap_value']) for c in contributions)
        for c in contributions:
            if total_positive > 0:
                c['contribution_pct'] = round(
                    max(0, c['shap_value']) / total_positive * 100, 1
                )
        
        # 排序，取Top驱动因子
        contributions.sort(key=lambda x: x['contribution_pct'], reverse=True)
        top_driver = contributions[0]['code'] if contributions else None
        second_driver = contributions[1]['code'] if len(contributions) > 1 else None
        
        return RenewalAttributionResult(
            user_id=user_id,
            attribution_date=date.today(),
            trigger_event=trigger_event,
            membership_tier=membership.tier,
            cycle_start=cycle_start,
            cycle_end=cycle_end,
            benefit_contributions=contributions[:10],  # Top10
            top_driver=top_driver,
            second_driver=second_driver,
            confidence=self._calc_confidence(prediction, contributions),
            model_version=self.model_version
        )
    
    def _build_feature_vector(self, user_id, cycle_start, cycle_end):
        """
        构建权益使用特征向量
        每个权益对应3个特征: 总次数/活跃天数/最近7天频次比
        """
        features = []
        for code in self.feature_codes:
            total = get_cycle_usage(user_id, code, cycle_start, cycle_end)
            active_days = get_active_days(user_id, code, cycle_start, cycle_end)
            
            recent_7 = get_usage_in_range(user_id, code, 
                                          cycle_end - timedelta(days=7), cycle_end)
            cycle_days = max(1, (cycle_end - cycle_start).days)
            recent_ratio = recent_7 / max(1, total) if total > 0 else 0
            
            features.extend([total, active_days, recent_ratio])
        
        return np.array(features)
    
    def _calc_confidence(self, prediction, contributions):
        """
        置信度: 模型预测概率与Top贡献因子的集中度
        """
        top_concentration = contributions[0]['contribution_pct'] / 100 if contributions else 0
        return round(min(1.0, prediction * 0.5 + top_concentration * 0.5), 3)
```

## 8. 权益使用退化检测引擎

### 8.1 流式退化检测逻辑

```python
class UsageDeclineDetector(AggregateFunction):
    """
    Flink 滑动窗口退化检测器
    
    在14天滑动窗口内检测权益使用退化:
    - 连续7天未使用某核心权益 → 强退化信号
    - 使用频次较前7天下降>50% → 中度退化信号
    - 使用深度下降（如AI对话轮次变短）→ 轻度退化信号
    """
    
    def create_accumulator(self):
        return UsageWindow(
            daily_counts=[0] * 14,  # 14天每日计数
            first_half_total=0,     # 前7天总计
            second_half_total=0,    # 后7天总计
            last_usage_day=None,
            window_end=None
        )
    
    def add(self, event, accumulator):
        day_index = (event.event_date - accumulator.window_start).days
        if 0 <= day_index < 14:
            accumulator.daily_counts[day_index] += event.usage_count
            accumulator.last_usage_day = event.event_date
        
        return accumulator
    
    def get_result(self, accumulator):
        first_half = sum(accumulator.daily_counts[:7])
        second_half = sum(accumulator.daily_counts[7:])
        
        decline_score = 0.0
        
        # 完全停滞
        if second_half == 0 and first_half > 0:
            decline_score = 1.0  # 强信号
        # 显著下降
        elif first_half > 0:
            ratio = second_half / first_half
            if ratio < 0.5:
                decline_score = 1.0 - ratio  # 0.5-1.0
        
        return DeclineSignal(
            user_id=accumulator.user_id,
            benefit_code=accumulator.benefit_code,
            decline_score=decline_score,
            first_half_count=first_half,
            second_half_count=second_half,
            detected_at=datetime.now()
        )
```

### 8.2 退化信号处置策略

```python
class DeclineSignalHandler:
    """
    权益退化信号处置策略
    
    根据退化程度和会员等级选择不同干预方式:
    """
    
    def handle(self, signal: DeclineSignal):
        user = get_user(signal.user_id)
        tier = user.membership_tier
        
        if signal.decline_score >= 0.8:
            # 强退化: 核心权益几乎停止使用
            action = self._handle_severe_decline(signal, user, tier)
        elif signal.decline_score >= 0.5:
            # 中度退化: 使用频次显著下降
            action = self._handle_moderate_decline(signal, user, tier)
        else:
            # 轻度: 记录但不主动干预
            action = self._log_only(signal)
        
        # 推送到权益退化预警通道
        publish_decline_alert(signal, action)
    
    def _handle_severe_decline(self, signal, user, tier):
        """
        强退化处置: 
        - 年度会员: 推送"发现你可能错过的好功能"引导
        - 月度会员: 推送使用技巧 + 优惠券
        - 即将到期(30天内): 升级为高优流失预警
        """
        days_to_expire = (user.membership_end - date.today()).days
        
        if days_to_expire <= 30:
            # 即将到期 + 停止使用 = 高流失风险
            return AlertAction(
                priority='critical',
                type='churn_escalation',
                target_teams=['retention', 'customer_success'],
                recommended_actions=[
                    'send_personalized_re_engagement',
                    'offer_extension_discount',
                    'assign_dedicated_cs'
                ]
            )
        else:
            return AlertAction(
                priority='high',
                type='feature_re_engagement',
                recommended_actions=[
                    f'send_benefit_rediscovery_card:{signal.benefit_code}',
                    'adjust_homepage_recommendation_weight'
                ]
            )
```

### 10.2 调度代码示例

```java
/**
 * 权益追踪定时任务调度
 */
@Component
@SLF4J
public class BenefitTrackingScheduler {

    @Autowired
    private VPMEngine vpmEngine;

    @Autowired
    private RenewalAttributionEngine attributionEngine;

    @Autowired
    private BenefitCycleSummaryService cycleSummaryService;

    @Autowired
    private DeclineDetectionService declineService;

    /**
     * 每日VPS评分计算
     * 03:00 执行，分批处理所有活跃会员
     */
    @Scheduled(cron = "0 0 3 * * ?", zone = "Asia/Shanghai")
    public void dailyVpsCompute() {
        LocalDate today = LocalDate.now();
        log.info("[VPS] 开始每日评分计算, date={}", today);
        
        long startTime = System.currentTimeMillis();
        
        // 分页处理，每批500用户
        long maxUserId = userService.getMaxActiveMemberUserId();
        int batchSize = 500;
        int successCount = 0;
        int errorCount = 0;
        
        for (long offset = 0; offset <= maxUserId; offset += batchSize) {
            try {
                List<Long> userIds = userService.getActiveMemberUserIds(offset, batchSize);
                
                // 并行计算
                List<VPSCoreResult> results = userIds.parallelStream()
                    .map(uid -> {
                        try {
                            return vpmEngine.compute_vps(uid, today);
                        } catch (Exception e) {
                            log.error("[VPS] 计算失败, userId={}", uid, e);
                            return null;
                        }
                    })
                    .filter(Objects::nonNull)
                    .collect(Collectors.toList());
                
                // 批量写入
                vpsRepository.batchUpsert(results);
                successCount += results.size();
                errorCount += userIds.size() - results.size();
                
            } catch (Exception e) {
                log.error("[VPS] 批处理失败, offset={}", offset, e);
                errorCount += batchSize;
            }
        }
        
        long elapsed = System.currentTimeMillis() - startTime;
        log.info("[VPS] 每日评分完成, success={}, error={}, elapsed={}ms", 
                 successCount, errorCount, elapsed);
        
        // 发送监控指标
        Metrics.gauge("vps.compute.success_count", successCount);
        Metrics.gauge("vps.compute.error_count", errorCount);
        Metrics.timer("vps.compute.duration").record(elapsed, TimeUnit.MILLISECONDS);
    }

    /**
     * 每日退化检测批量补充
     * 04:00 执行
     */
    @Scheduled(cron = "0 0 4 * * ?", zone = "Asia/Shanghai")
    public void dailyDeclineDetection() {
        LocalDate today = LocalDate.now();
        log.info("[Decline] 开始批量退化检测, date={}", today);
        
        declineService.batchDetectDecline(today);
    }

    /**
     * 每日续费归因分析
     * 05:00 执行
     */
    @Scheduled(cron = "0 0 5 * * ?", zone = "Asia/Shanghai")
    public void dailyRenewalAttribution() {
        LocalDate yesterday = LocalDate.now().minusDays(1);
        log.info("[Attribution] 开始续费归因分析, date={}", yesterday);
        
        // 获取前日发生的续费和流失事件
        List<MembershipEvent> events = membershipEventService
            .getEventsByDate(yesterday, "renewal", "churn_warning");
        
        for (MembershipEvent event : events) {
            try {
                var result = attributionEngine.attribute_renewal(
                    event.getUserId(), event.getEventType()
                );
                attributionRepository.save(result);
            } catch (Exception e) {
                log.error("[Attribution] 归因分析失败, userId={}, event={}", 
                          event.getUserId(), event.getEventType(), e);
            }
        }
    }
}
```

### 12.1 事件采集容错

### 12.2 VPS 计算容错

```java
/**
 * VPS 计算降级策略
 */
public class VPMEngineWithFallback {

    public VPSCoreResult computeWithFallback(Long userId, LocalDate date) {
        try {
            // 正常计算
            return vpmEngine.compute_vps(userId, date);
        } catch (Exception e) {
            log.warn("[VPS] 完整计算失败, 降级到简化版, userId={}", userId, e);
            return computeSimplifiedVps(userId, date);
        }
    }

    /**
     * 简化版VPS: 只用使用频次单一维度估算
     * 作为完整模型不可用时的降级方案
     */
    private VPSCoreResult computeSimplifiedVps(Long userId, LocalDate date) {
        Membership membership = getMembership(userId);
        if (membership == null) return VPSCoreResult.empty(userId);
        
        // 快速查询: 本周期总使用次数
        int totalUsage = benefitAggregateService
            .getQuickTotalUsage(userId, membership.cycle_start, membership.cycle_end);
        
        // 简化映射: 0次=0分, 50次=40分, 200次=70分, 500+次=90分
        double simpleScore;
        if (totalUsage == 0) simpleScore = 0;
        else if (totalUsage < 50) simpleScore = 20 + totalUsage * 0.4;
        else if (totalUsage < 200) simpleScore = 40 + (totalUsage - 50) * 0.2;
        else if (totalUsage < 500) simpleScore = 70 + (totalUsage - 200) * 0.067;
        else simpleScore = 90;
        
        return VPSCoreResult.builder()
            .userId(userId)
            .scoreDate(date)
            .vpsScore(Math.min(100, simpleScore))
            .vpsLevel(scoreToLevel(simpleScore))
            .topBenefits(Collections.emptyList())
            .riskFlags(Collections.emptyList())
            .metadata(Map.of("fallback", true, "method", "simplified"))
            .build();
    }
}
```

### 12.3 归因模型降级

| 场景 | 降级策略 |
|------|----------|

| SHAP 计算超时 | 降级为特征重要度排序（预计算的全局重要度） |

### 13.3 Redis 热数据缓存

```java
/**
 * 权益使用热数据缓存策略
 */
@Component
public class BenefitTrackingCache {

    @Autowired
    private RedisTemplate<String, String> redis;

    // 缓存Key设计
    private static final String KEY_USER_VPS = "bvt:vps:{userId}";           // TTL: 24h
    private static final String KEY_USER_CYCLE = "bvt:cycle:{userId}";        // TTL: 1h
    private static final String KEY_BENEFIT_DAILY = "bvt:daily:{userId}:{date}:{code}"; // TTL: 7d
    private static final String KEY_DASHBOARD_SUMMARY = "bvt:dash:{date}";   // TTL: 1h
    
    /**
     * 获取用户VPS（先查缓存）
     */
    public VPSCoreResult getVps(Long userId) {
        String key = KEY_USER_VPS.replace("{userId}", String.valueOf(userId));
        String cached = redis.opsForValue().get(key);
        if (cached != null) {
            return JsonUtils.fromJson(cached, VPSCoreResult.class);
        }
        return null; // 缓存未命中，需查数据库
    }
    
    /**
     * 更新用户VPS缓存
     */
    public void cacheVps(Long userId, VPSCoreResult result) {
        String key = KEY_USER_VPS.replace("{userId}", String.valueOf(userId));
        redis.opsForValue().set(key, JsonUtils.toJson(result), 
                                 Duration.ofHours(24));
    }
    
    /**
     * 原子递增当日权益使用计数
     */
    public Long incrementDailyUsage(Long userId, String benefitCode) {
        String key = KEY_BENEFIT_DAILY
            .replace("{userId}", String.valueOf(userId))
            .replace("{date}", LocalDate.now().toString())
            .replace("{code}", benefitCode);
        return redis.opsForValue().increment(key);
    }
}
```

### 15.2 未成年人数据保护

```java
/**
 * 未成年人权益数据脱敏处理
 * 在所有对外API输出时自动执行
 */
@Aspect
@Component
public class MinorDataProtectionAspect {

    @Around("execution(* com.primetop.benefit.controller.*.*(..))")
    public Object applyMinorProtection(ProceedingJoinPoint pjp) throws Throwable {
        Object result = pjp.proceed();
        
        Long currentUserId = UserContext.getCurrentUserId();
        if (userService.isMinor(currentUserId)) {
            // 未成年人: 在运营看板中不展示个人级数据
            // 仅保留聚合级别的统计数据
            if (result instanceof DashboardResponse resp) {
                resp.maskIndividualData();
            }
        }
        
        return result;
    }
}
```
