# 管理后台-数据合规与隐私保护管理工作台-详细设计

## 1. 概述

### 1.1 功能定位

数据合规与隐私保护管理工作台是 PrimeTop 管理后台的核心合规模块，面向合规运营人员、法务团队和数据保护官（DPO），提供个人信息保护全生命周期管理能力。

作为面向 K12 全学段未成年用户的教育产品，PrimeTop 需严格遵守《中华人民共和国个人信息保护法》（PIPL）、《未成年人保护法》、《数据安全法》及教育部、网信办相关部门规章。本工作台将分散在各后端引擎中的合规能力进行统一管理入口聚合，提供可视化的合规态势感知与操作工作流。

### 1.2 目标用户

| 角色 | 职责 | 权限范围 |
|------|------|----------|
| 数据保护官 (DPO) | 合规策略制定、隐私影响评估、监管对接 | 全部模块读写 |
| 合规运营专员 | 日常数据主体权利请求处理、协议管理 | 权利请求、协议管理读写 |
| 法务人员 | 隐私政策审核、数据处理合同管理 | 政策管理、合同管理只读 + 审批 |
| 安全工程师 | 数据分类分级、脱敏规则配置、 breach 响应 | 安全配置读写 |
| 平台管理员 | 角色权限分配、审计日志查看 | 全部模块读写 + 权限管理 |

### 1.3 设计目标

1. **统一入口**：聚合所有数据合规管理功能，避免跨系统操作
2. **流程闭环**：数据主体权利请求从接收到办结全流程线上化
3. **审计可追溯**：所有合规操作留存不可篡改审计日志
4. **实时感知**：合规态势仪表盘实时呈现关键指标
5. **未成年人优先**：针对未成年用户数据提供增强保护视图和特殊处理流程

### 1.4 与现有系统的关系

| 关联系统 | 依赖关系 |
|----------|----------|
| 服务端-未成年人数据隐私合规自动化与数据主体权利请求处理引擎 | 本工作台的前端管理层，引擎负责自动化处理流水线 |
| 服务端-用户协议同意状态管理与合规审计追踪引擎 | 协议同意数据来源 |
| 数据安全与隐私合规体系-详细设计 | 底层安全架构基础 |
| 服务端-数据脱敏规则引擎与敏感信息动态遮蔽服务 | 脱敏规则配置下发 |
| 服务端-审计日志与操作追溯系统 | 操作日志存储后端 |
| 服务端-数据归档与生命周期管理策略 | 数据保留策略执行层 |

## 3. 数据结构定义

### 3.1 核心表设计

#### 3.1.1 数据主体权利请求表 `compliance_dsar`

```sql
CREATE TABLE compliance_dsar (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '请求ID',
    request_no VARCHAR(32) NOT NULL UNIQUE COMMENT '请求编号，格式：DSAR-YYYYMMDD-XXXXX',
    user_id BIGINT NOT NULL COMMENT '发起用户ID',
    user_type TINYINT NOT NULL DEFAULT 0 COMMENT '用户类型：0-学生本人 1-家长代理 2-监护人代理',
    request_type TINYINT NOT NULL COMMENT '请求类型：1-访问权 2-更正权 3-删除权 4-可携带权 5-拒绝自动化决策权',
    
    -- 请求内容
    request_reason TEXT COMMENT '请求原因说明',
    request_detail JSON COMMENT '请求详情（更正内容、删除范围等）',
    target_scope VARCHAR(256) COMMENT '数据范围：all/account/learning/payment/ai_chat 等',
    
    -- 状态流转
    status TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0-待受理 1-审核中 2-处理中 3-已完成 4-已拒绝 5-已撤回 6-超期关闭',
    priority TINYINT NOT NULL DEFAULT 1 COMMENT '优先级：0-普通 1-紧急 2-特急',
    
    -- 时效控制
    received_at DATETIME NOT NULL COMMENT '收到请求时间',
    deadline_at DATETIME NOT NULL COMMENT '法定办结截止时间（收到后15个工作日）',
    completed_at DATETIME COMMENT '实际完成时间',
    
    -- 处理信息
    assigned_to BIGINT COMMENT '指派处理人ID',
    processing_notes TEXT COMMENT '处理备注',
    rejection_reason TEXT COMMENT '拒绝原因',
    rejection_legal_basis VARCHAR(256) COMMENT '拒绝的法律依据条款',
    export_file_url VARCHAR(512) COMMENT '数据导出文件URL（可携带权/访问权）',
    export_file_expires_at DATETIME COMMENT '导出文件过期时间',
    
    -- 未成年人特殊字段
    is_minor_case TINYINT NOT NULL DEFAULT 0 COMMENT '是否涉及未成年人：0-否 1-是',
    guardian_verified TINYINT DEFAULT NULL COMMENT '监护人身份已验证：0-否 1-是',
    guardian_relation VARCHAR(32) COMMENT '监护人关系',
    
    -- 审计
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_user_id (user_id),
    INDEX idx_status (status),
    INDEX idx_deadline (deadline_at),
    INDEX idx_minor (is_minor_case),
    INDEX idx_type_status (request_type, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='数据主体权利请求表';
```

#### 3.1.2 隐私政策版本表 `compliance_privacy_policy`

```sql
CREATE TABLE compliance_privacy_policy (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    version_no VARCHAR(16) NOT NULL UNIQUE COMMENT '版本号，如 v2.1.0',
    title VARCHAR(128) NOT NULL COMMENT '政策标题',
    
    -- 政策内容
    content_md TEXT NOT NULL COMMENT '政策正文（Markdown格式）',
    content_html TEXT COMMENT '渲染后HTML（缓存）',
    summary TEXT COMMENT '变更摘要',
    change_diff TEXT COMMENT '与上一版本的差异说明',
    
    -- 关键条款提取（用于同意管理）
    key_clauses JSON COMMENT '关键条款列表，用于精细化同意管理',
    -- 示例：[{"clause_id":"analytics","title":"学习数据分析","required":true},{"clause_id":"recommendation","title":"个性化推荐","required":false}]
    
    -- 适用范围
    applicable_user_types JSON COMMENT '适用用户类型：student/parent/teacher',
    applicable_minors TINYINT NOT NULL DEFAULT 1 COMMENT '是否适用于未成年用户',
    
    -- 状态
    status TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0-草稿 1-审核中 2-已发布 3-已下线 4-已撤回',
    
    -- 审批流程
    drafted_by BIGINT COMMENT '起草人ID',
    reviewed_by BIGINT COMMENT '审核人ID',
    approved_by BIGINT COMMENT '审批人ID',
    published_at DATETIME COMMENT '发布时间',
    effective_at DATETIME NOT NULL COMMENT '生效时间',
    retired_at DATETIME COMMENT '下线时间',
    
    -- 未成年人特殊保护
    minor_version_id BIGINT COMMENT '对应儿童版隐私政策版本ID',

    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_status (status),
    INDEX idx_effective (effective_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='隐私政策版本表';

### 5.1 数据主体权利请求状态机

```
                    ┌──────────────┐
          创建 ───▶ │  待受理 (0)   │
                    └──────┬───────┘
                           │ 受理
                           ▼
                    ┌──────────────┐
                    │  审核中 (1)   │ ◄──── 用户补充信息
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │ 审核通过    │ 审核拒绝    │ 需补充
              ▼            ▼            ▼
       ┌────────────┐ ┌────────────┐ ┌────────────┐
       │ 处理中 (2)  │ │ 已拒绝 (4) │ │ 待受理 (0) │
       └──────┬─────┘ └────────────┘ └────────────┘
              │
              │ 处理完成
              ▼
       ┌──────────────┐
       │  已完成 (3)   │
       └──────────────┘

       超期未处理：
       任何状态 ──▶ 超期关闭 (6)
       
       用户撤回：
       待受理/审核中 ──▶ 已撤回 (5)
```

**SLA 要求：**
| 请求类型 | 法定时限 | 内部SLA |
|----------|----------|---------|
| 数据访问权 | 15个工作日 | 10个工作日 |
| 数据更正权 | 15个工作日 | 7个工作日 |
| 数据删除权 | 15个工作日 | 10个工作日 |
| 数据可携带权 | 15个工作日 | 10个工作日 |
| 未成年人相关 | 15个工作日 | **5个工作日**（加急）|

### 5.2 隐私政策发布流程

```
 起草 (0) ──▶ 审核中 (1) ──▶ 待审批 ──▶ 已发布 (2) ──▶ 已下线 (3)
                  │               │
                  └── 退回修改 ────┘
                  
 已发布 + requiresReConsent=true:
   → 触发用户重新同意流程
   → 30天宽限期（hard_block模式）
   → 宽限期内未同意 → 冻结部分功能
```

```
 已报告 (0) ──▶ 调查中 (1) ──▶ 已控制 (2) ──▶ 已解决 (3) ──▶ 已关闭 (4)
     │                               │
     └── 严重事件 ──▶ 立即启动应急响应小组
                      → 72小时内评估是否需监管报告
                      → 若需要 → 生成监管报告 → 提交

## 6. 关键业务逻辑

### 6.1 数据删除权请求执行流程

```python
class DataSubjectRightsProcessor:
    """数据主体权利请求处理器"""
    
    DELETE_SCATTERED_DATA_TIMEOUT = 300  # 散落数据清理超时（秒）
    
    # 各服务的数据清理策略
    DELETION_PIPELINES = {
        "user-service": {
            "tables": ["users", "student_profiles", "parent_bindings"],
            "strategy": "anonymize",  # 匿名化而非物理删除（保留统计价值）
            "fields": {
                "real_name": "ANONYMIZED",
                "phone": None,  # 物理清除
                "email": None,
                "avatar_url": None,
                "id_card_no": None,
            }
        },
        "learning-service": {
            "tables": ["learning_sessions", "answer_records", "learning_plans"],
            "strategy": "hard_delete",
            "cascade": True,  # 级联删除关联数据
        },
        "mistake-service": {
            "tables": ["mistake_records"],
            "strategy": "hard_delete",
        },
        "ai-service": {
            "tables": ["ai_conversations", "ai_messages"],
            "strategy": "hard_delete",
            "vector_db_cleanup": True,  # 同时清理向量库中的对话嵌入
        },
        "payment-service": {
            "tables": ["orders", "membership"],
            "strategy": "retain_anonymized",  # 保留匿名化交易记录（法务要求）
            "retention_reason": "税收和财务审计要求，保留5年",
            "anonymize_fields": ["payer_name", "payer_phone", "payer_email"],
        },
        "content-service": {
            "tables": ["user_notes", "user_favorites"],
            "strategy": "hard_delete",
        },
    }
    
    async def execute_deletion(self, dsar_id: int, user_id: int, 
                                target_scope: str = "all") -> DeletionResult:
        """执行数据删除请求"""
        
        results = []
        errors = []
        
        # 1. 预检查：是否有法律保留义务
        legal_holds = await self.check_legal_holds(user_id)
        if legal_holds:
            return DeletionResult(
                success=False,
                reason="存在法律保留义务的数据",
                details=legal_holds
            )
        
        # 2. 检查是否为未成年人请求，验证监护人身份
        user_info = await self.user_service.get_user(user_id)
        if user_info.age < 14:
            guardian_verified = await self.verify_guardian(dsar_id, user_id)
            if not guardian_verified:
                return DeletionResult(
                    success=False,
                    reason="未成年人删除请求需监护人身份验证"
                )
        
        # 3. 按服务逐个执行删除
        for service_name, pipeline in self.DELETION_PIPELINES.items():
            if target_scope != "all" and service_name not in self._get_scope_services(target_scope):
                continue
            
            try:
                result = await self._execute_service_deletion(
                    service_name, user_id, pipeline
                )
                results.append(result)
            except Exception as e:
                errors.append({
                    "service": service_name,
                    "error": str(e),
                    "retry_recommended": True
                })
        
        # 4. 清理缓存
        await self.cache_invalidator.invalidate_user_cache(user_id)
        
        # 5. 清理搜索引擎索引
        await self.search_index_cleaner.remove_user_documents(user_id)
        
        # 6. 清理CDN上的用户资源
        await self.cdn_cleaner.cleanup_user_resources(user_id)
        
        # 7. 生成删除证明文件
        certificate = await self.generate_deletion_certificate(
            dsar_id, user_id, results, errors
        )
        
        # 8. 记录审计日志
        await self.audit_logger.log(
            action="DSAR_DELETION_EXECUTED",
            operator="SYSTEM",
            target_user=user_id,
            dsar_id=dsar_id,
            results=results,
            errors=errors,
            certificate_id=certificate.id
        )
        
        return DeletionResult(
            success=len(errors) == 0,
            results=results,
            errors=errors,
            certificate_url=certificate.url
        )
    
    async def _execute_service_deletion(self, service_name: str, 
                                         user_id: int, 
                                         pipeline: dict) -> dict:
        """执行单个服务的数据删除"""
        
        strategy = pipeline["strategy"]
        
        if strategy == "hard_delete":
            # 物理删除
            for table in pipeline["tables"]:
                rows = await self.db.execute(
                    f"DELETE FROM {table} WHERE user_id = ?",
                    user_id
                )
                self.logger.info(f"[{service_name}] Deleted {rows} rows from {table}")
                
        elif strategy == "anonymize":
            # 匿名化处理
            for table in pipeline["tables"]:
                set_clauses = []
                params = []
                for field, replacement in pipeline["fields"].items():
                    if replacement is None:
                        set_clauses.append(f"{field} = NULL")
                    else:
                        set_clauses.append(f"{field} = ?")
                        params.append(replacement)
                
                params.append(user_id)
                await self.db.execute(
                    f"UPDATE {table} SET {', '.join(set_clauses)} WHERE user_id = ?",
                    *params
                )
        
        elif strategy == "retain_anonymized":
            # 保留但匿名化关键字段
            for table in pipeline["tables"]:
                for field in pipeline["anonymize_fields"]:
                    await self.db.execute(
                        f"UPDATE {table} SET {field} = 'REDACTED' "
                        f"WHERE user_id = ? AND {field} IS NOT NULL",
                        user_id
                    )
        
        # 向量库清理
        if pipeline.get("vector_db_cleanup"):
            await self.vector_db.delete_by_filter(
                collection="conversation_embeddings",
                filter_expr=f"user_id == {user_id}"
            )
        
        return {
            "service": service_name,
            "strategy": strategy,
            "tables": pipeline["tables"],
            "status": "success"
        }
```

        """

            - grace_period_days: 宽限期天数

            policy.applicable_user_types,
            policy.applicable_minors
        )
        
        # 分批处理，避免一次性大批量推送
        batch_size = 5000
        total_batches = (len(affected_users) + batch_size - 1) // batch_size
        
        for batch_idx in range(total_batches):
            batch = affected_users[batch_idx * batch_size : (batch_idx + 1) * batch_size]
            
            tasks = []
            for user_id in batch:
                user = await self.user_service.get_user(user_id)
                
                # 未成年人特殊处理

                        self._notify_guardian_for_consent(user, policy, config)
                    )
                else:
                    tasks.append(
                        self._notify_user_for_consent(user, policy, config)
                    )
            
            await asyncio.gather(*tasks, return_exceptions=True)
            
            # 批次间间隔，避免推送洪峰
            await asyncio.sleep(2)
        
        # 2. 设置宽限期过期检查的延迟任务
        grace_period_end = datetime.utcnow() + timedelta(days=config.grace_period_days)
        await self.delayed_task_scheduler.schedule(
            task_type="policy_grace_period_expired",

                "policy_id": policy_id,

class DeletionCompensationManager:
    """数据删除失败的补偿管理器"""
    
    async def handle_deletion_failure(self, dsar_id: int, failure: DeletionFailure):
        """处理删除失败"""
        
        dsar = await self.dsar_service.get(dsar_id)
        
        if failure.error_type == "service_unavailable":
            # 服务不可用 - 延迟重试
            await self.retry_scheduler.schedule(
                task_id=f"deletion_retry_{dsar_id}",
                delay_seconds=300,  # 5分钟后重试
                action="retry_deletion",
                payload={
                    "dsar_id": dsar_id,
                    "failed_service": failure.service_name
                }
            )
            await self.notify_operator(
                dsar_id, 
                f"服务 {failure.service_name} 暂时不可用，已安排5分钟后自动重试"
            )
        
        elif failure.error_type == "foreign_key_constraint":
            # 外键约束 - 需要人工介入
            await self.dsar_service.update_status(
                dsar_id, 
                status="PROCESSING_BLOCKED",
                notes=f"外键约束失败: {failure.detail}. 需人工介入处理关联数据。"
            )

                f"数据删除请求 {dsar.request_no} 遇到外键约束阻塞",
                f"服务: {failure.service_name}\n"
                f"错误: {failure.detail}\n"
                f"需人工确认数据关联关系后继续处理"
            )
        
        elif failure.error_type == "timeout":
            # 超时 - 分批重试
            await self.retry_with_smaller_batch(dsar_id, failure.service_name)

### 11.2 同意撤回联动

```python
async def handle_consent_withdrawal(event: ConsentWithdrawnEvent):
    """处理用户撤回同意"""
    
    user_id = event.user_id
    clause_id = event.clause_id
    
    # 根据撤回的条款类型，执行不同的功能限制
    WITHDRAWAL_ACTIONS = {
        "analytics": [
            "stop_behavior_analytics",
            "disable_learning_analytics_dashboard",
        ],
        "recommendation": [
            "switch_to_default_content",
            "clear_personalization_profile",
        ],
        "ai_training": [
            "flag_data_excluded_from_training",
        ],
        "core_service": [
            # 核心服务同意撤回 = 无法继续使用产品
            "notify_user_service_disruption",
            "offer_account_deletion",
        ],
    }
    
    actions = WITHDRAWAL_ACTIONS.get(clause_id, [])
    for action in actions:
        await self.action_executor.execute(action, user_id=user_id)
    
    # 如果是未成年人，通知监护人
    user = await self.user_service.get_user(user_id)
    if user.is_minor:
        await self.notify_guardian(
            user.guardian_user_id,
            template="minor_consent_withdrawn_notification",
            context={"clause": clause_id, "student_name": user.nickname}
        )
```
