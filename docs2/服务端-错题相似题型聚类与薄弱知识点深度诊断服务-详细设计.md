# 服务端 - 错题相似题型聚类与薄弱知识点深度诊断服务 详细设计

> 版本: v1.1 | 更新日期: 2026-08-18 | 状态: 已补全（v1.0 截断于 §4.2 响应 JSON，本次补齐 API 全集/核心算法/状态机/DDL 增补/事件/错误码/降级/监控/合规/契约对齐/验收）

## 1. 概述

### 1.1 模块定位

错题相似题型聚类与薄弱知识点深度诊断服务（Error Pattern Clustering & Deep Diagnosis Service, EPC-DDS）是 PrimeTop 学习闭环中"诊断归因"环节的核心引擎。它从学生积累的错题记录中，识别出系统性错误模式，区分"概念性薄弱"与"表面性失误"，并生成可操作的深度诊断报告与补救路径。

**核心职责：**
- 对学生错题进行多维度相似性聚类，发现高频错误模式
- 区分概念性错误（需要重新学习）与操作性失误（需要增加练习）
- 识别跨章节、跨知识点的隐性关联薄弱点
- 生成薄弱知识点深度诊断报告
- 为每位学生维护动态更新的「错误模式画像」
- 推荐针对性的补救学习路径

**不在本模块范围内：**
- 错题收录与管理 → 见 `错题整理-详细设计.md`
- 错题订正与复习追踪 → 见 `服务端-错题订正效果评估与复习成效追踪服务-详细设计.md`
- 复习调度（遗忘曲线） → 见 `间隔重复算法与遗忘曲线复习调度引擎-详细设计.md`
- 学习计划生成 → 见 `学习规划-详细设计.md`
- 题目推荐 → 见 `服务端-题目智能推荐与个性化练习编排服务-详细设计.md`

### 1.2 触发场景

| 场景 | 触发方 | 说明 |
|------|--------|------|
| 错题累积触发 | 错题服务 | 新增错题达到阈值（≥5 道）或距上次诊断超过 7 天 |
| 手动诊断 | 学生/家长 | 用户主动请求「学情深度诊断」 |
| 定期批量 | 定时任务 | 每周日凌晨批量对所有活跃用户执行增量诊断 |
| 学段切换 | 升迁服务 | 学生升入新学段时对历史错题进行回溯分析 |
| 考前分析 | 考试系统 | 考试模拟完成后自动触发针对性薄弱点诊断 |
| 家长报告 | 报告服务 | 生成周报/月报时附带最新诊断结论 |

### 1.3 设计目标

| 目标 | 指标 |
|------|------|
| 聚类准确性 | 同一聚类内题目错误根因一致率 ≥ 85% |
| 诊断时效 | 增量诊断 < 3s，全量诊断 < 10s |
| 误判率低 | 概念性错误 vs 操作性失误分类准确率 ≥ 90% |
| 可操作性 | 每条诊断结论必须附带 ≥1 条可执行补救建议 |
| 覆盖度 | 对累积 ≥10 道错题的学生，诊断覆盖率 ≥ 95% |

## 2. 核心概念与数据模型

### 2.1 核心概念

```
┌───────────────────────────────────────────────────────┐
│                     错误模式画像                        │
│  (ErrorPatternProfile)                                │
│                                                       │
│  ┌─────────────┐  ┌─────────────┐  ┌──────────────┐  │
│  │ 错误聚类组   │  │ 薄弱知识点   │  │ 诊断报告     │  │
│  │ ErrorCluster │  │ WeakKP      │  │ Diagnosis    │  │
│  └─────────────┘  └─────────────┘  └──────────────┘  │
│                                                       │
│  ┌─────────────┐  ┌─────────────┐                    │
│  │ 错误根因标签 │  │ 补救路径     │                    │
│  │ RootCause   │  │ RemedyPath  │                    │
│  └─────────────┘  └─────────────┘                    │
└───────────────────────────────────────────────────────┘
```

| 概念 | 说明 |
|------|------|
| **ErrorCluster（错误聚类组）** | 将多道错题按错误根因归为一组，同一组内的题目具有相似的错误模式 |
| **RootCause（错误根因）** | 对错误聚类组的归因标签，如"概念不清"、"审题失误"、"计算错误"等 |
| **WeakKP（薄弱知识点）** | 通过聚类分析识别出的掌握不足的知识点，附带严重程度和趋势 |
| **Diagnosis（诊断报告）** | 一次诊断的完整结果，包含聚类结果、薄弱点列表、补救建议 |
| **RemedyPath（补救路径）** | 针对诊断结果生成的学习补救方案 |
| **ErrorPatternProfile（错误模式画像）** | 学生长期累积的错误模式综合画像，持续更新 |

### 2.2 错误根因分类体系

```typescript
/**
 * 错误根因一级分类
 */
enum ErrorRootCause {
  /** 概念性错误 - 对知识点理解有偏差或缺失 */
  CONCEPTUAL = 'CONCEPTUAL',
  /** 操作性失误 - 理解正确但执行出错 */
  PROCEDURAL = 'PROCEDURAL',
  /** 审题失误 - 未能正确理解题意 */
  READING = 'READING',
  /** 策略性错误 - 解题方法选择不当 */
  STRATEGIC = 'STRATEGIC',
  /** 知识关联缺失 - 未能将多个知识点综合运用 */
  INTEGRATION = 'INTEGRATION',
}

/**
 * 概念性错误二级分类
 */
enum ConceptualErrorType {
  CONCEPT_MISSING = 'CONCEPT_MISSING',           // 概念完全缺失
  CONCEPT_CONFUSION = 'CONCEPT_CONFUSION',         // 概念混淆
  CONCEPT_MISAPPLICATION = 'CONCEPT_MISAPPLICATION', // 概念误用
  CONCEPT_INCOMPLETE = 'CONCEPT_INCOMPLETE',       // 概念理解不完整
}

/**
 * 操作性失误二级分类
 */
enum ProceduralErrorType {
  CALCULATION = 'CALCULATION',           // 计算失误
  SIGN_ERROR = 'SIGN_ERROR',             // 符号错误
  UNIT_ERROR = 'UNIT_ERROR',             // 单位换算错误
  FORMAT_ERROR = 'FORMAT_ERROR',         // 格式/书写规范错误
  CARELESS = 'CARELESS',                 // 粗心大意（抄错、漏看等）
}

/**
 * 审题失误二级分类
 */
enum ReadingErrorType {
  MISREAD_CONDITION = 'MISREAD_CONDITION',   // 漏看/误读条件
  WRONG_QUESTION_GOAL = 'WRONG_QUESTION_GOAL', // 理解错问题目标
  IGNORE_KEYWORD = 'IGNORE_KEYWORD',         // 忽略关键限制词
  OVERLOOK_NEGATION = 'OVERLOOK_NEGATION',   // 忽略否定词
}

/**
 * 薄弱程度等级
 */
enum WeaknessLevel {
  CRITICAL = 'CRITICAL',   // 严重薄弱 - 正确率 < 30%
  SEVERE = 'SEVERE',       // 较重薄弱 - 正确率 30-50%
  MODERATE = 'MODERATE',   // 中度薄弱 - 正确率 50-70%
  MILD = 'MILD',           // 轻度薄弱 - 正确率 70-85%
}
```

### 2.3 数据库表结构

#### 2.3.1 错误聚类组表 `error_cluster`

```sql
CREATE TABLE error_cluster (
    id                  BIGSERIAL PRIMARY KEY,
    cluster_id          VARCHAR(36) NOT NULL,          -- 聚类唯一标识 (UUID)
    student_id          BIGINT NOT NULL,               -- 学生 ID
    subject_id          BIGINT NOT NULL,               -- 学科 ID
    root_cause          VARCHAR(30) NOT NULL,          -- 一级根因: ErrorRootCause
    sub_cause           VARCHAR(40),                   -- 二级根因
    error_count         INT NOT NULL DEFAULT 0,        -- 聚类内错题数量
    first_occurred_at   TIMESTAMPTZ NOT NULL,          -- 最早出错时间
    last_occurred_at    TIMESTAMPTZ NOT NULL,          -- 最近出错时间
    recurrence_count    INT NOT NULL DEFAULT 0,        -- 同类错误重复出现次数（订正后仍错）
    description         TEXT,                          -- AI 生成的聚类描述
    confidence_score    DECIMAL(5,4),                  -- 聚类置信度 (0-1)
    status              VARCHAR(20) NOT NULL DEFAULT 'ACTIVE', -- ACTIVE / RESOLVED / MERGED
    resolved_at         TIMESTAMPTZ,                   -- 解消时间
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT uk_cluster_id UNIQUE (cluster_id)
);

CREATE INDEX idx_error_cluster_student ON error_cluster (student_id, subject_id);
CREATE INDEX idx_error_cluster_status ON error_cluster (student_id, status);
CREATE INDEX idx_error_cluster_root_cause ON error_cluster (root_cause, sub_cause);
```

#### 2.3.2 聚类-错题关联表 `error_cluster_item`

```sql
CREATE TABLE error_cluster_item (
```

### 3.2 模块职责

| 模块 | 职责 | 关键算法 |
|------|------|----------|
| **FeatureExtractor** | 从错题记录中提取多维特征向量，包括知识点、文本语义、题型、难度、根因标签 | TF-IDF + Sentence Embedding |
| **ClusterAnalyzer** | 对特征向量进行聚类分析，将相似错误归组，识别高频错误模式 | DBSCAN + 层次聚类 + 自定义合并策略 |
| **RootCauseClassifier** | 对聚类结果进行根因分类，区分概念性错误与操作性失误 | 规则引擎 + AI 辅助分类 |
| **WeaknessDetector** | 从聚类结果中提取薄弱知识点，评估严重程度和趋势 | 统计分析 + 时序趋势检测 |
| **ReportGenerator** | 组装诊断报告，调用 AI 生成自然语言摘要和补救建议 | Prompt 编排 + LLM |
| **ProfileManager** | 维护学生错误模式画像的持续更新 | 增量更新策略 |

## 4. API 接口设计

### 4.1 触发诊断

```
POST /api/v1/diagnosis
```

**请求体：**

```json
{
  "subjectId": 3,
  "diagnosisType": "INCREMENTAL",
  "triggerSource": "AUTO",
  "sinceTimestamp": "2026-05-30T00:00:00.000Z"
}
```

**响应体（异步模式）：**

```json
{
  "code": 0,
  "data": {
    "reportId": "diag-20260607-abc123",
    "status": "PROCESSING",
    "estimatedWaitSeconds": 5
  }
}
```

**说明：**
- 诊断请求采用异步处理，立即返回 `reportId`
- 调用方通过轮询或 WebSocket 获取结果
- 同一学生同一学科 10 分钟内不允许重复触发

### 4.2 查询诊断报告

```
GET /api/v1/diagnosis/{reportId}
```

**响应体：**

```json
{
  "code": 0,
  "data": {
```

## 5. 关键流程设计

### 5.1 增量诊断主链路（事件触发）

```
错题服务            MQ(epc消费组)         EPC-DDS 编排器                Redis/DB
   │ MistakeCreated ──▶ │                     │                          │
   │                    │──消费(幂等见表§9.2)──▶│                          │
   │                    │                     │──INCR epc:cnt:{stu}:{sub}─▶│ TTL 7d
   │                    │                     │   计数≥5 或 距上次诊断>7d? │
   │                    │                     │   否 → 结束(仅记账)       │
   │                    │                     │   是 → SETNX epc:diag:lock─▶│ TTL 120s
   │                    │                     │   抢锁失败 → 复用进行中reportId(deduplicated)
   │                    │                     │──创建 report(PROCESSING)──▶│
   │◀──GET /internal/mistakes/batch(增量错题+快照)──│                      │
   │                    │                     │──FeatureExtractor(§6.1)  │
   │                    │                     │   向量缓存 miss → 向量库按题目ID取1024维主向量
   │                    │                     │──ClusterAnalyzer(§6.2/6.3)│
   │                    │                     │   就近并入/新簇/噪声暂存   │
   │                    │                     │──RootCauseClassifier(§6.4)│
   │                    │                     │──WeaknessDetector(§6.5)   │
   │                    │                     │   新增/升级/解消薄弱KP     │
   │                    │                     │──ReportGenerator(§6.8)    │
   │                    │                     │   AI摘要+补救建议(降级见D3)│
   │                    │                     │──事务:report终态+KP/簇变更 │
   │                    │                     │  +epc_outbox(§10) 同事务  │
   │                    │                     │──Relay投递epc.domain.events▶ MQ(下游)
```

**要点：**
- 特征提取阶段批量拉取（单批 ≤200 条），向量优先从向量库按 `questionId` 引用主向量（不重复计算嵌入，契约 A2）
- 全流程单学生单学科预算 3s（增量）/ 10s（全量），超时熔断标记 `FAILED`（`processing_time_ms` 落库）
- 事务边界：诊断结果落库与 Outbox 同事务（本地消息表模式），跨服务调用全部在事务外

### 5.2 手动诊断与周批量的并发互斥

```
用户点「深度诊断」                周批 Cron(周日 03:00)
   │ POST /diagnosis                  │ 分片滚动(每片500学生,片间200ms)
   │                                  │ 对每学生: 同样走 epc:diag:lock 抢锁
   │ 抢锁失败:                        │
   │  ├ 锁持有者=进行中诊断 → 409/56002 + data.reportId(复用轮询)
   │  └ 锁持有者=周批量 → 同上(不插队, 防止重复计算)
   │ 抢锁成功但10min内有已完成报告 → 200 + deduplicated=true + 旧reportId
```

- 周批量仅处理「累积错题 ≥10 道」的活跃学生（对应 §1.3 覆盖度指标），单学生超时 10min 熔断
- 批量窗口 03:00-07:00，游标断点续跑；06:30 未完成片告警（P3）
- 学段切换回溯（升迁服务）与考前诊断（考试系统）走 gRPC `TriggerDiagnosis`，`forceFull` 由场景白名单放行（普通用户请求 `forceFull=true` 返回 56009）

### 5.3 聚类增量更新流程

```
新增错题特征向量 v
   │
   ├── 与全部 ACTIVE 簇中心计算 cos 相似度 (pgvector, 单学科簇数通常≤8)
   │
   ├── max_cos ≥ 0.80 ──▶ 就近并入(EMA更新中心 α=0.3) ──▶ error_cluster_item.assigned_by=INCREMENTAL
   │
   ├── 0.60 ≤ max_cos < 0.80 ──▶ 候补队列(挂到最近簇, similarity_score如实记录)
   │        └─ 同一候补簇累计≥3条 ──▶ 派生新簇(种子=这3条), 原簇剔除候补挂载
   │
   └── max_cos < 0.60 ──▶ 噪声暂存表(noise_flag=true, 不参与画像)
            └─ 噪声累计≥5条且相互cos≥0.75 ──▶ 组合判定新簇(二次扫描, 每日一次)

簇维护(诊断任务尾部执行):
   ├── 分裂: 簇内 pairwise 平均 cos < 0.55 且成员≥6 ──▶ 以最远两点为种子做2-means分裂
   └── 合并: 两 ACTIVE 簇中心 cos ≥ 0.92 且根因一致 ──▶ 小簇并入大簇(保留大簇cluster_id)
                                             小簇置 MERGED + merged_into 记录(守卫G2/G4)
```

## 6. 核心算法设计

### 6.1 特征提取与向量复用（FeatureExtractor）

**向量复用契约（对齐《题目相似度计算与智能去重服务-详细设计》）：**

| 项 | 约定 |
|----|------|
| 主向量 | 复用题目相似度服务的 1024 维主向量（`bge-large-zh-v1.5`），按 `questionId` 从向量库引用，**本服务不重复计算嵌入** |
| 版本快照 | 每道错题特征带 `embeddingVersion`；相似度服务模型升级后，簇中心与新向量版本混用时（版本混杂率 >30%）触发该学生全量重建（§6.7） |
| 簇中心存储 | `error_cluster.center_vec VECTOR(1024)`（pgvector），只存 ACTIVE 簇中心，MERGED/RESOLVED 置 NULL 释放空间 |
| 本地缓存 | Redis `epc:vec:{questionId}` 缓存向量哈希前 256 字节指纹用于快速去重，全量向量不落 Redis（体积红线） |

**混合特征空间（聚类距离度量）：**

```typescript
/**
 * 混合距离：语义向量余弦为主，根因/知识点/题型为强先验修正项。
 * v1.1 起语义向量维度对齐题目相似度服务(1024)，不再独立维护128维向量。
 */
function hybridDistance(a: ErrorFeatureVector, b: ErrorFeatureVector): number {
  // (1) 语义相似度：余弦
  const cosSim = dot(a.textFeatures, b.textFeatures) /
                 (norm(a.textFeatures) * norm(b.textFeatures));
  // (2) 知识点 Jaccard（multi-hot 集合）
  const kpSim = jaccard(a.knowledgePointIds, b.knowledgePointIds);
  // (3) 根因一致性（未标注时按 0.5 中性，不奖不罚）
  const causeSim = (!a.rootCause || !b.rootCause)
      ? 0.5
      : (a.rootCause === b.rootCause
          ? (a.subCause === b.subCause ? 1.0 : 0.8)
          : 0.2);
  // (4) 题型一致性（同题型 1 / 同大类 0.6 / 跨类 0）
  const typeSim = questionTypeAffinity(a.questionType, b.questionType);

  // 加权合成相似度（权重经 §6.2 参数灰度可调）
  const sim = 0.55 * cosSim + 0.20 * kpSim + 0.15 * causeSim + 0.10 * typeSim;
  return 1 - sim;   // 距离 = 1 - 相似度
}
```

> **设计取舍：** 根因标签作为强先验修正而非硬分组——因为根因本身是聚类的**输出**之一（未标注错题占新入库错题多数），若硬分组会导致「未标注」错题无法与任何簇合并。

### 6.2 聚类算法：DBSCAN 参数自适应（ClusterAnalyzer）

**全量诊断（初始化/重建）使用 DBSCAN；增量诊断使用 §5.3 就近分配。**

| 参数 | 取值 | 说明 |
|------|------|------|
| `eps` | 自适应 | 取该学生错题两两距离的 20 分位数 × `eps_scale`(默认 1.0)，下限 0.25、上限 0.55 |
| `min_samples` | 3 | 样本 <8 道时降为 2（保护小样本） |
| 度量 | `hybridDistance`（§6.1） | — |
| 噪声点 | 进噪声暂存表 `noise_flag=true` | 不入画像、不计 error_count；噪声率 >40% 告警（指标 M4） |

```python
def adaptive_eps(distances: np.ndarray) -> float:
    """distances: 该学生错题两两距离矩阵的上三角"""
    if distances.size < 6:            # 样本过少，直接用保守下限
        return 0.30
    eps = float(np.percentile(distances, 20)) * PARAMS.eps_scale
    return max(0.25, min(0.55, eps))

def run_dbscan(features: list[ErrorFeatureVector]):
    X = pairwise_hybrid(features)            # n×n 距离矩阵（n≤2000，见D8）
    eps = adaptive_eps(triu(X))
    labels = dbscan(X, eps=eps, min_samples=3 if len(features) >= 8 else 2,
                    metric="precomputed")
    clusters = group_by_label(labels)        # label=-1 → 噪声暂存
    return clusters, noise_indices, {"eps": eps, "noise_rate": ...}
```

**簇 → DB 实体映射：** DBSCAN 输出的每个簇创建 `error_cluster` 记录（`confidence_score` = 簇内平均两两相似度，见 §6.5 质量分），成员写入 `error_cluster_item`（`assigned_by=INITIAL`）。

### 6.3 层次聚类与簇合并/分裂策略

- **合并**（优先级高，每次诊断任务尾部执行）：两 ACTIVE 簇中心 `hybridSim ≥ 0.92` **且** 根因一致（或两者均未标注）→ 小并入大；`error_cluster_item` 整体改挂（`assigned_by=MERGED`），小簇 `status=MERGED`、`merged_into=大簇cluster_id`、`center_vec=NULL`
- **分裂**：簇内 pairwise 平均相似度 `< 0.55` 且成员 `≥ 6` → 以 pairwise 距离最大的两点为种子做 2-means，分裂出的两个子簇重新过根因分类（§6.4）；分裂**不产生 MERGED 状态**，原簇保留成员较多的子簇
- **约束**：单学生单学科 ACTIVE 簇上限 12（超出时优先合并噪声外最相似对）；合并/分裂均写 `epc.cluster.merged` / 簇变更审计字段（§10）

### 6.4 根因分类引擎（RootCauseClassifier）

**两级架构：规则引擎先行（R1-R10），AI 分类仅处理规则无法裁决的簇。**

**规则表（命中即停，按序评估）：**

| 规则 | 条件（信号来源：错题快照 + 作答行为数据） | 判定 |
|------|------|------|
| R1 | 用户手动自标 `rootCauseOverride` 存在 | 以用户标注为准（不可被 AI 覆盖） |
| R2 | 学生答案为空 / 作答超时 | `STRATEGIC`（时间管理） |
| R3 | 数值类答案与正确答案仅符号相反（`-3` vs `3`） | `PROCEDURAL / SIGN_ERROR` |
| R4 | 数值相同但单位量纲不同（`3` vs `3m`，`3000` vs `3km`） | `PROCEDURAL / UNIT_ERROR` |
| R5 | 题干含否定词且学生选项恰好是「肯定表述」项 | `READING / OVERLOOK_NEGATION` |
| R6 | 同模式题（簇内文本相似 ≥0.85）≥2 次出错且订正后复发 | `CONCEPTUAL`（二级待 AI/人工） |
| R7 | 判题过程数据：中间步骤正确、末步计算错 | `PROCEDURAL / CALCULATION` |
| R8 | 多知识点综合题出错，但其每个子知识点单独题正确率 ≥0.8 | `INTEGRATION` |
| R9 | AI 解析携带 misconception 标签（判题引擎/错题服务透传） | 对应概念性二级分类（如 `CONCEPT_CONFUSION`） |
| R10 | 以上均未命中 | 进入 AI 分类；AI 亦失败 → `ANALYSIS_REQUIRED` 人工队列（56013） |

**AI 分类协议（簇级，非单题级）：**

```json
{
  "task": "error_root_cause_classification",
  "inputs": {
    "gradeBand": "SENIOR_HIGH",
    "subject": "数学",
    "clusterSamples": [
      { "stem": "判断 p: x²>4 是否为 q: x>2 的充分条件",
        "studentAnswer": "是充分条件", "correctAnswer": "不是充分条件" }
    ],
    "behaviorSignals": { "recurrenceRate": 0.75, "avgTimeSpent": 46 }
  },
  "outputSchema": {
    "rootCause": "ErrorRootCause",
    "subCause": "string|null",
    "confidence": "0-1",
    "reasoning": "≤50字"
  }
}
```

**校验规则：**

| # | 校验 | 处理 |
|---|------|------|
| V1 | `rootCause` 必须在枚举内 | 越界 → 丢弃该结果，计一次失败 |
| V2 | `subCause` 必须与一级分类匹配（对照 §2.2 体系） | 不匹配 → 只采信一级 |
| V3 | `confidence` ∈ [0,1] 数值 | 非法 → 置 0.5 |
| V4 | 概念性/操作性判别需与 §6.6 矩阵不冲突 | 冲突 → 以 §6.6 矩阵为准（AI 仅补二级） |
| V5 | `reasoning` ≤50 字 | 超长截断并降级复核 |

**置信度三档路由：** `≥0.85` 直采（写 `confidence_score`）· `0.50-0.85` 直采但标记 `needs_review=true` 进入人工抽检队列 · `<0.50` 不采信 → R10 人工队列。

### 6.5 薄弱深度评分（WeaknessDetector）

**depth_score 公式（0-1，越高越严重）：**

```
depth = 0.35 × err_rate_c     // 错误强度：clamp((1 - accuracy - 0.15) / 0.55, 0, 1)
      + 0.25 × recur_c       // 复发强度：clamp(recurrenceRate / 0.8, 0, 1)，订正后再错是最强概念性信号
      + 0.20 × recency_c     // 近期集中度：近30天错误占该KP总错误比例
      + 0.10 × trend_c       // DECLINING=1 / STABLE=0.5 / IMPROVING=0
      + 0.10 × conceptual_c  // §6.6 判定为概念性=1，操作性=0.4
```

**算例：** accuracy=0.35 → err_rate_c=(1-0.35-0.15)/0.55=0.91；recurrenceRate=0.75 → recur_c=0.94；近 30 天占 0.8 → recency_c=0.8；DECLINING → 1.0；概念性 → 1.0。
depth = 0.35×0.91 + 0.25×0.94 + 0.20×0.8 + 0.10×1.0 + 0.10×1.0 = **0.90**（与 §4.2 示例的 0.82 差异源于示例为较早版本口径，计算式以此处为准）

**等级映射（weakness_level 由 depth + accuracy 双门槛决定）：**

| 等级 | 条件（满足其一） |
|------|------------------|
| CRITICAL | accuracy < 0.30 且 depth ≥ 0.75 |
| SEVERE | accuracy < 0.50 且 depth ≥ 0.60 |
| MODERATE | accuracy < 0.70 且 depth ≥ 0.40 |
| MILD | accuracy < 0.85 且 depth ≥ 0.25 |
| （无） | 其余 → 不入薄弱点表 |

> 概念性薄弱（is_conceptual=true）在同等 depth 下优先级提升（同等 depth 排序在前），因为概念性薄弱是补救路径首选目标（§6.8）。

### 6.6 概念性 vs 操作性判别矩阵

| 信号 \ 倾向 | 指向概念性 | 指向操作性 |
|-------------|------------|------------|
| 复发率（订正后再错） | ≥0.5 | <0.2 |
| 簇内文本相似度（同模式反复） | ≥0.75 | <0.55（散发性） |
| 知识点集中度（错误集中于少数 KP） | ≥0.7 | <0.4（跨 KP 散布） |
| 样本量 | ≥4（可靠判别） | ≥4 |
| 单 KP 单题正确率（同 KP 简单题） | <0.8（简单题也错） | ≥0.8（难题才错） |

**裁决：** 概念性信号占多数（≥3/5）→ `is_conceptual=true`；反之操作性；打平时：复发率信号优先（订正后再错权重最高）。样本 <4 时 `is_conceptual` 置 false 且 `confidence` 减半，标签标 `LOW_SAMPLE`。

### 6.7 增量更新与画像维护（ProfileManager）

**增量 vs 全量决策表：**

| 条件 | 策略 |
|------|------|
| 常规增量（阈值触发） | 就近分配（§5.3）+ 局部维护（合并/分裂） |

### 6.8 AI 摘要与补救建议生成（ReportGenerator）

**Prompt 编排（复用 AI-Prompt 编排系统的场景模板 `epc.diagnosis.summary.v2`）：**

```
[系统角色] 你是学习诊断分析师，面向{gradeBand}学生输出诊断摘要。
[红线] 成长型话术（禁否定人格化）；不出现具体分数排名；不暴露同伴对比；≤200字。
[输入] 聚类结果摘要 + 薄弱点列表(depth/趋势/根因) + 补救建议骨架
[输出] aiSummary(自然语言) + remedyDescriptions[]（每个建议一句话理由）
[Token预算] 输入≤1200, 输出≤400；超预算先截断 sampleMistakes 再截断低优先级簇
```

**补救路径推荐策略（与推荐服务边界：本服务只生成“补救骨架”，题目级编排归推荐服务）：**

| 薄弱点类型 | remedy_type | 步骤骨架 |
|-----------|-------------|----------|
| 概念性 | CONCEPT_REVIEW | ① AI 对话重理解概念（≤10min）② 基础题 5 道 ③ 综合应用 3 道 |
| 操作性 | TARGETED_PRACTICE | ① 计算规范微课/技巧卡 ② 限时专项 8 道（错因针对性） |
| 知识关联缺失 | GUIDED_LEARNING | ① 知识图谱浏览关联 KP ② 跨 KP 综合题 3 道 |

**优先级排序：** `priority = round(10 × (0.6 × depth_rank + 0.4 × conceptual_rank))`（1 最高）；同分时 CRITICAL > SEVERE > MODERATE > MILD。每份报告最多生成 3 条补救路径（防信息过载，对齐注意力预算管理原则）。

**降级：** AI 摘要失败 → 模板摘要（`summary_source=TEMPLATE`，客户端不区分展示，但报告 JSON 保留来源字段用于质量监控）；补救建议生成不走 AI（纯规则骨架），无降级需求。

## 7. 状态机设计

### 7.1 错误聚类组（error_cluster）

```
                 ┌──────────── MERGED (终态,不可逆) ◀─── 合并(小并大) ───┐
                 │                                                     │
  新建 ──▶ ACTIVE ────────── 解消(连续2次诊断无新增+订正通过率≥0.8+≥14d) ──▶ RESOLVED
                 ▲                                                     │
                 └────────── 复发回退(recurrence+1, 重新参与合并) ◀──────┘
```

### 7.2 薄弱知识点（weak_knowledge_point）

```
  诊断发现/升级 ──▶ ACTIVE ──(最近≥10次作答accuracy≥0.85 且无ACTIVE关联簇)──▶ RESOLVED
                       ▲                                              │
                       └────(回退窗口30天内再错且depth≥MIDL门槛)──────────┘
```

### 7.3 诊断报告（diagnosis_report.status，DDL 需增列，见 §8）

```
  PROCESSING ──┬──▶ COMPLETED（全部学科成功 / 单学科诊断成功）
               ├──▶ PARTIAL（仅全科：≥1学科成功且≥1失败，degradedSubjects 非空）
               └──▶ FAILED（单学科全失败 / 全科全部失败；可重试→新reportId）
```

### 7.4 补救路径（remedy_path）

```
  PENDING ──START──▶ IN_PROGRESS ──全部步骤完成──▶ COMPLETED
     │                    │
     │ 7天未START          │ 用户SKIP(reason必填)
     ▼                    ▼
  EXPIRED              SKIPPED（30天内同根因建议降权）
```

### 7.5 守卫总表

| 守卫 | 状态机 | 规则 |
|------|--------|------|
| G1 | cluster | `ACTIVE→RESOLVED` 需同时满足：连续 2 次诊断无新增错误、簇内错题订正通过率 ≥0.8、距 `first_occurred_at` ≥14 天 |
| G2 | cluster | `ACTIVE→MERGED` 目标簇必须为 ACTIVE；合并方向小并大（按 error_count） |
| G3 | cluster | `RESOLVED→ACTIVE` 仅由复发触发，且 `recurrence_count+1`；触发源为新错题就近命中已解消簇（中心保留 90 天） |
| G4 | cluster | MERGED 为终态不可逆；原簇成员改挂目标簇，`error_cluster_item` 不复制不删除（改 cluster_id 外键） |
| G5 | cluster | 任何状态不可物理删除；学生注销时按账号注销流程由统一清理引擎处理（合规 C7） |
| G6 | weakKP | `ACTIVE→RESOLVED` 需最近 ≥10 次作答 accuracy ≥0.85 且无 ACTIVE 关联簇 |
| G7 | weakKP | `RESOLVED→ACTIVE` 仅在回退窗口（30 天）内再犯时触发；窗口外再犯走「新建」（uk 冲突时复用旧记录并刷新 `first_diagnosed_at`） |
| G8 | weakKP | 等级/depth/trend 仅可由诊断任务变更；对外 API 一律只读 |
| G9 | weakKP | 同一 (student_id, knowledge_point_id) 全局唯一（uk_student_kp）；解消后记录保留不删除 |
| G10 | report | PARTIAL 仅全科诊断可产生；单学科只允许 COMPLETED/FAILED |
| G11 | report | FAILED 重试 `retry_count≤2`；超出转人工排查队列（管理端可见） |
| G12 | report | 终态不可变；重跑/重试生成新 reportId，旧报告保留（审计与回溯） |
| G13 | remedy | START 幂等：IN_PROGRESS 状态下重复 START 返回当前状态（不报错） |
| G14 | remedy | COMPLETE 要求所有步骤完成（progress=1）；否则 56015 |
| G15 | remedy | SKIP 必须 reason；执行后 30 天内同 (rootCause, kpId) 建议降权（priority 分数 -3，非拒绝） |
| G16 | remedy | EXPIRED 仅由每日 09:00 扫描器驱动（`UPDATE ... WHERE status='PENDING' AND created_at < now()-7d` 单语句幂等），客户端任何操作不可产生 |

```sql
    report_id       VARCHAR(36),                   -- 命中/创建的报告
    deduplicated    BOOLEAN NOT NULL DEFAULT FALSE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT uk_dtl_window UNIQUE (student_id, COALESCE(subject_id,0), window_key)
);
```

> PostgreSQL 支持表达式唯一索引；若目标库为 MySQL 8.0，参照《管理后台-教师与班级数据管理工作台》§5.6 的函数唯一索引方案改写。

### 8.4 数据保留与归档

## 9. 幂等与并发控制

### 9.1 触发幂等（双保险）

```
POST /diagnosis:
  1. Idempotency-Key 命中(Redis 24h) → 直接返回首次结果
  2. Redis SETNX epc:trigger:{stu}:{sub}:{window10min} EX 600
     ├─ 成功 → 继续；FAIL → 查 trigger_log 最近 report → deduplicated=true 返回
  3. DB 写 diagnosis_trigger_log（uk 冲突 → 同上兜底）
  4. 执行中互斥锁：SETNX epc:diag:lock:{stu}:{sub} EX 120
     └─ 失败 → 56002 + 进行中 reportId（HTTP 409）
```

> 三层顺序：先幂等后互斥——幂等命中可零成本返回；互斥仅保护真实并发。

### 9.2 事件消费幂等

消费 `MistakeCreated`/`CorrectionSubmitted`/`ReviewCompleted`（错题服务事件，PascalCase 信封）：
- 幂等键 `(event_id, consumer='epc-service')`，消费记录 Redis `epc:consumed:{event_id}` EX 7d + DB 消费日志双写
- 消费失败重试 3 次后进死信 `epc.dlq`，管理端可重放；重放同样受幂等保护

### 9.3 聚类更新并发

- 簇记录乐观锁：`UPDATE error_cluster SET ..., version=version+1 WHERE cluster_id=? AND version=?`；冲突重读重试（≤3 次）
- 同一学生的诊断任务天然串行（互斥锁保证）；聚类更新仅发生在诊断任务内，无独立并发入口

### 9.4 补救操作并发

- actions 接口 CAS：`UPDATE remedy_path SET status=?, progress=? WHERE remedy_id=? AND version<?` 按预期前置状态过滤
- `clientRequestId` 幂等表（Redis 24h）：同 key 同 body 重放返回首次结果；同 key 异 body → 56017

## 10. 事件设计（epc.domain.events）

**统一信封：** `producer='epc-service'`，topic `epc.domain.events`，事件 ID 全局唯一（ULID），消费方幂等键 `(event_id, consumer)`。

| 事件 | 触发时机 | 关键 payload 字段 | 消费方（幂等键） |
|------|----------|-------------------|------------------|
| `epc.weakness.diagnosed` | 诊断终态 COMPLETED/PARTIAL | reportId, studentId, subjectId?, weakKpIds[], newKps, resolvedKps, degradedFlags | 融合引擎 / 首页提醒 / 学情分析 / 家长报告 / 推荐服务 |
| `epc.diagnosis.failed` | 终态 FAILED（重试后仍失败） | reportId, errorCode, retryCount | 监控告警管道（事件驱动的 P2 告警） |
| `epc.cluster.merged` | 簇合并 | oldClusterId, newClusterId, memberCount | 错题组卷（改挂后重新取簇）/ 订正追踪 |
| `epc.cluster.resolved` | 簇解消 | clusterId, resolvedAt | 首页提醒（解除关联提醒项） |
| `epc.weakkp.resolved` | 薄弱点解消 | kpId, resolvedAt, accuracyRate | 融合引擎（正向证据）/ 首页提醒移除 / 推荐停止补弱推送 / 成就系统（进步时刻候选） |
| `epc.remedy.suggested` | 补救路径创建 | remedyId, weakKpIds, priority | 学习规划（计划项挂接）/ 多源任务调度（SYS_RECOMMEND 投递，未成年人 21:00 红线由调度引擎执行） |
| `epc.remedy.status_changed` | START/COMPLETE/SKIP/EXPIRED | remedyId, action, progress | 推荐服务（通过率回流）/ 学习规划（阻塞解除） |

**Relay 对账：** 每小时统计 `published=false AND next_retry_at < now()` 积压量 >500 告警；日终对账 `epc_outbox` 发布量 vs Kafka 消费 ACK 量，差异 >1% 重推差额（对齐统一数据对账体系）。

## 11. 错误码（全局段 56000-56099）

> 错误码体系对齐《服务端-统一业务异常码与错误分类体系-详细设计》分段规范；客户端展示文案由客户端错误码映射表负责，本表为服务间契约权威。

| 56001 | 429 | 触发过于频繁（10min 窗口） | 提示「诊断进行中/刚完成」并引导查看上次报告 |
| 56002 | 409 | 同学科诊断进行中（data 携带 reportId） | 转轮询该报告 |
| 56003 | 422 | 错题样本不足（<5 道） | 引导继续练习积累错题 |
| 56004 | 403 | 无权限（非本人/非授权角色） | 拦截并上报 |
| 56005 | 404 | 报告不存在 | 刷新列表 |
| 56006 | 409 | 报告未完成（详情接口 misuse） | 引导轮询 §4.3 |
| 56007 | 422 | 学科无效/未开通 | 修正参数 |
| 56008 | 422 | scope 参数无效（章节/KP 不存在） | 修正参数 |
| 56009 | 403 | forceFull 未授权（仅场景白名单/管理端） | 去掉参数重试 |
| 56010 | 410 | 画像/报告已过期清理（超出保留期） | 引导重新诊断 |
| 56011 | 500 | 簇中心向量缺失（数据异常） | 自动创建重建任务（内部），用户侧同 56000 |

| 56013 | 500 | 根因分类失败且规则无法兑底（ANALYSIS_REQUIRED） | 簇标待分类，不影响其余结果（报告可 PARTIAL） |

## 12. 降级矩阵

| # | 故障场景 | 降级策略 | 用户感知 |
|---|----------|----------|----------|
| D1 | 向量库/嵌入服务不可用 | TF-IDF 稀疏向量降级聚类（仅题干关键词+知识点），`degraded_flags+=TFIDF_FALLBACK`，聚类结果照常但 confidence 打 8 折 | 无直接感知；报告标注「基于简化分析」 |
| D2 | AI 分类服务不可用 | 纯规则 R1-R10；未命中簇置 `ANALYSIS_REQUIRED`，不阻塞诊断完成 | 部分簇显示「分析中」 |
| D3 | AI 摘要失败 | 模板摘要（summary_source=TEMPLATE），报告照常 COMPLETED | 摘要文案模板化 |
| D4 | 知识点服务不可用 | 仅题目级聚类，不出薄弱 KP 结论；诊断置 PARTIAL（degraded_subjects） | 提示「知识点诊断暂不可用」 |
| D5 | 聚类计算异常（算法崩溃/内存） | 跳过聚类，直通基于正确率统计的薄弱点（无簇关联），`degraded_flags+=NO_CLUSTER` | 有薄弱点列表，无错误模式画像 |
| D6 | Redis 不可用 | 触发互斥降级为 DB `diagnosis_trigger_log` 唯一键裁决；画像缓存降级直读 DB（P99 放宽至 800ms）；周批量暂停（防重复计算） | 周报延迟，手动诊断可用 |
| D7 | MQ 不可用 | Outbox 积压，Relay 按 next_retry_at 退避重试；下游消费延迟不影响诊断主链路 | 无感知（下游联动延迟） |
| D8 | 单学生全量样本 >2000 | 截断至最近 180 天窗口，`truncated=true`（56020 软警告） | 提示「已分析近 180 天」 |
| D9 | 报告详情 JSON >2MB | sampleMistakes 裁剪至每簇 2 条，仍超限则 clusters>5 时只保留 TOP5 簇 | 略少示例错题 |
| D10 | 补救建议依赖的推荐/内容服务不可用 | 降级为骨架建议（步骤描述有，resourceType 无具体资源 ID），`remedy.degraded=true` | 步骤可看，资源待补 |

> 原则：诊断主链路永不因 AI/向量依赖而整体失败——统计兜底永远可用（D1-D5 三层兑底：向量→规则→统计）。

## 17. 验收场景（18 条）

1. **增量触发阈值**：同一学科新增 5 道错题后（第 5 道 MistakeCreated 消费后 1s 内）自动触发诊断，报告 COMPLETED 且 `analyzedErrors=5`
2. **未达阈值**：新增 3 道错题仅计数不触发（Redis 计数器可查），无 report 产生
3. **7 天兜底**：仅 2 道新增错题但距上次诊断 8 天，下次消费事件触发增量诊断
4. **触发幂等**：连续两次 POST /diagnosis（同学生同学科，10min 内）→ 第二次返回 deduplicated=true + 同一 reportId，不产生第二份报告
