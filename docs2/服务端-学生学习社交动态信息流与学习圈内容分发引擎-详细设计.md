# 服务端-学生学习社交动态信息流与学习圈内容分发引擎-详细设计

## 1. 模块概述

### 1.1 功能定位

学生学习社交动态信息流与学习圈内容分发引擎（以下简称"学习动态引擎"）是 PrimeTop 社交学习体系的服务端核心模块，负责管理学生学习动态的**生产、聚合、分发、互动与隐私管控**。

本模块解决的核心问题：
- 学生在完成学习任务、获得成就、突破记录时产生动态内容，需要高效推送到其所在学习圈（班级圈、同伴圈、全校圈）的信息流中。
- 不同学段用户隐私要求不同（未成年人不能暴露真实姓名、联系方式），需精细化权限控制。
- 信息流需要根据关系亲密度、内容质量、时效性进行个性化排序。
- 高并发场景下需平衡写扩散与读扩散策略，保证 Feed 流的实时性与系统吞吐量。

### 1.2 与已有模块的边界

| 已有模块 | 本模块差异 |
|---------|-----------|
| 协作学习与学习同伴圈互动（客户端） | 客户端负责 UI 展示与交互；本模块负责服务端 Feed 生产、排序、分发 |
| 服务端-学习同伴圈层匹配与协作学习编排引擎 | 该模块负责同伴**匹配算法**；本模块负责匹配后的**动态内容分发** |
| 服务端-学习挑战赛与排行榜竞技系统 | 该模块产出竞技数据；本模块将其转化为社交动态卡片 |
| 服务端-学习打卡记录与成就解锁计算引擎 | 该模块计算打卡/成就；本模块将其作为动态来源消费 |
| 分享与社交裂变系统 | 该模块处理外部平台分享（微信/QQ）；本模块处理 App 内社交信息流 |

### 1.3 设计目标

| 指标 | 目标 |
|------|------|
| Feed 刷新延迟（首屏） | P95 ≤ 200ms |
| 动态发布到可见延迟 | P95 ≤ 3s |
| 日均动态生产量 | 500 万条（100 万 DAU × 日均 5 条） |
| 信息流查询 QPS 峰值 | 10,000 |
| 动态互动（点赞/评论）写入 TPS 峰值 | 8,000 |

## 2. 核心概念定义

| 概念 | 说明 |
|------|------|
| **学习动态 (Feed Post)** | 一条结构化的社交内容单元，来源于学习行为（完成打卡、获得徽章、考试进步等）或用户主动发布 |
| **学习圈 (Learning Circle)** | 动态分发的范围单元，包括：班级圈、同伴圈、全校圈、自定义小组 |
| **信息流 (Feed Stream)** | 某个用户视角下按时间或算法排序的动态列表 |
| **动态卡片 (Feed Card)** | 动态在前端的展现形态，包含内容主体 + 互动区 + 来源标识 |
| **动态来源 (Feed Source)** | 触发动态产生的业务事件类型，如打卡、成就、挑战赛等 |
| **可见范围 (Visibility Scope)** | 单条动态的可见性配置，支持公开/仅好友/仅自己/指定圈子 |

### 4.1 Feed 流缓存

```
TTL: 2 小时

# 用户是否已点赞 (Set: 存储已点赞的 post_id)

TTL: 10 分钟
```

### 4.2 排序分值计算

```java
/**
 * 排序分值计算 —— 时间衰减 + 互动加权模型
 * <p>
 * score = (baseScore + interactionWeight) * timeDecayFactor
 * <p>
 * baseScore: 动态来源基础分 (打卡=1, 成就=5, 挑战赛=8, 考试进步=10)
 * interactionWeight: 点赞×2 + 评论×3 + 分享×5
 * timeDecayFactor: 1 / (1 + α × hoursElapsed)  α=0.05 (半衰期约14小时)
 */
public class FeedRankScoreCalculator {

    private static final double ALPHA = 0.05;
    private static final Map<Integer, Double> BASE_SCORES = Map.of(
        0, 1.0,   // MANUAL_POST
        1, 2.0,   // CHECKIN
        2, 5.0,   // ACHIEVEMENT
        3, 8.0,   // CHALLENGE_WIN
        4, 10.0,  // EXAM_IMPROVE
        5, 1.5,   // MISTAKE_REVIEW
        6, 7.0,   // STUDY_GOAL
        7, 3.0,   // NOTE_SHARE
        8, 6.0,   // RANK_CHANGE
        9, 4.0    // STREAK_RECORD
    );

    public static double calculate(FeedPost post, Instant now) {
        double baseScore = BASE_SCORES.getOrDefault(post.getSourceType(), 1.0);
        double interactionWeight = post.getLikeCount() * 2.0
                                 + post.getCommentCount() * 3.0
                                 + post.getShareCount() * 5.0;

        long hoursElapsed = Duration.between(post.getPublishedAt(), now).toHours();
        double timeDecayFactor = 1.0 / (1.0 + ALPHA * hoursElapsed);

        return (baseScore + interactionWeight) * timeDecayFactor;
    }
}
```

## 5. Feed 分发策略：混合读写扩散

### 5.1 策略概述

采用**混合模式 (Hybrid Fan-out)**，根据圈子规模和用户活跃度选择不同扩散路径：

| 场景 | 策略 | 原因 |
|------|------|------|
| 班级圈 (≤100人) | **写扩散** | 成员少，直接写入每个成员的 timeline |
| 同伴圈 (≤50人) | **写扩散** | 同上 |
| 全校圈 (可能数千人) | **读扩散** | 写扩散开销过大，查询时实时拉取 |
| 自定义小组 (≤200人) | **写扩散** | 中等规模可控 |
| 热门动态 | **推拉结合** | 先写入活跃用户 timeline，非活跃用户读时拉取 |

### 5.2 活跃度判定

```java
/**
 * 用户活跃度分层
 * - ACTIVE: 7天内有登录 → 始终写扩散
 * - SEMI_ACTIVE: 7-30天有登录 → 仅热门动态写扩散
 * - INACTIVE: 30天以上未登录 → 不写扩散，登录时补偿拉取
 */
public enum UserActivityTier {
    ACTIVE,      // DAU/WAU
    SEMI_ACTIVE, // 7-30d
    INACTIVE     // >30d
}
```

### 5.3 写扩散核心流程

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│  动态发布事件 │────▶│  Fan-out Job  │────▶│  batch insert   │
│  (MQ消息)    │     │  (消费者)      │     │  feed_timeline  │
└─────────────┘     └──────┬───────┘     └─────────────────┘
                           │
                    ┌──────▼───────┐
                    │ 查询圈子成员   │
                    │ (Redis缓存)   │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────────┐
        │ ACTIVE   │ │SEMI_ACTIVE│ │  INACTIVE   │
        │ 直接写入  │ │仅热门写入 │ │  跳过       │
        │timeline  │ │timeline  │ │ (登录补偿)   │
        └──────────┘ └──────────┘ └──────────────┘
```

### 5.4 写扩散任务实现

```java
@Service
public class FeedFanoutService {

    @Autowired private FeedCircleMemberMapper circleMemberMapper;
    @Autowired private FeedTimelineMapper timelineMapper;
    @Autowired private RedisTemplate<String, String> redisTemplate;
    @Autowired private UserActivityService userActivityService;

    private static final int BATCH_SIZE = 200;

    /**
     * 处理写扩散任务（由 MQ 消费者调用）
     */
    @Transactional
    public void processFanout(FeedPost post) {
        // 1. 查询圈子成员
        List<Long> memberIds = getCircleMembers(post.getCircleType(), post.getCircleId());
        if (memberIds.isEmpty()) {
            return;
        }

        // 2. 过滤可见性 (排除被拉黑、隐私设置不可见的成员)
        memberIds = filterByVisibility(memberIds, post);

        // 3. 计算排序分值
        double rankScore = FeedRankScoreCalculator.calculate(post, Instant.now());

        // 4. 按活跃度分层处理
        Map<UserActivityTier, List<Long>> tiered = userActivityService.batchClassify(memberIds);

        // 4a. 活跃用户：直接写入 timeline
        List<Long> activeIds = tiered.get(UserActivityTier.ACTIVE);
        batchInsertTimeline(activeIds, post, rankScore);

        // 4b. 半活跃用户：仅热门动态写入
        if (post.getIsHot() || rankScore > HOT_THRESHOLD) {
            List<Long> semiActiveIds = tiered.get(UserActivityTier.SEMI_ACTIVE);
            batchInsertTimeline(semiActiveIds, post, rankScore);
        }

        // 4c. 非活跃用户：跳过，登录时补偿拉取

        // 5. 更新 outbox 状态
        feedOutboxMapper.updateFanoutStatus(post.getPostId(),
            FanoutStatus.COMPLETED, memberIds.size(), Instant.now());
    }

    /**
     * 批量写入 timeline（分批，每批 BATCH_SIZE 条）
     */
    private void batchInsertTimeline(List<Long> userIds, FeedPost post, double rankScore) {
        Lists.partition(userIds, BATCH_SIZE).forEach(batch -> {
            List<FeedTimeline> records = batch.stream()
                .map(uid -> FeedTimeline.builder()
                    .userId(uid)
                    .postId(post.getPostId())
                    .publisherId(post.getUserId())
                    .circleType(post.getCircleType())
                    .circleId(post.getCircleId())
                    .sourceType(post.getSourceType())
                    .rankScore(rankScore)
                    .readStatus(0) // 未读
                    .createdAt(Instant.now())
                    .build())
                .collect(Collectors.toList());
            timelineMapper.batchInsert(records);

            // 更新 Redis 缓存
            batch.forEach(uid -> {
                redisTemplate.opsForZSet().add(
                    "feed:timeline:" + uid,
                    post.getPostId(),
                    rankScore
                );
                redisTemplate.opsForValue().increment("feed:unread:" + uid);
            });
        });
    }
}
```

### 5.5 读补偿流程（非活跃用户登录时）

```java
@Service
public class FeedCatchUpService {

    /**
     * 用户登录时检查是否需要补偿拉取错过的动态
     */
    public void catchUpOnLogin(Long userId) {
        Instant lastLogin = userActivityService.getLastLoginTime(userId);
        if (lastLogin == null) return;

        long daysSinceLogin = Duration.between(lastLogin, Instant.now()).toDays();
        if (daysSinceLogin < 7) return; // 活跃用户无需补偿

        // 拉取用户所在圈子在离线期间的热门动态 (最多 50 条)
        List<Long> circleIds = circleMemberMapper.findActiveCircleIds(userId);

        for (CircleMembership cm : circleIds) {
            List<FeedPost> missedHotPosts = feedPostMapper.selectHotPostsByCircle(
                cm.getCircleType(), cm.getCircleId(),
                lastLogin, Instant.now(),
                /* limit */ 20
            );

            // 写入 timeline
            for (FeedPost post : missedHotPosts) {
                double score = FeedRankScoreCalculator.calculate(post, Instant.now());
                timelineMapper.insertOrSkip(FeedTimeline.builder()
                    .userId(userId)
                    .postId(post.getPostId())
                    .publisherId(post.getUserId())
                    .rankScore(score)
                    .readStatus(0)
                    .build());
            }
        }

        // 清理 30 天前的 timeline 记录
        timelineMapper.deleteOldRecords(userId, Instant.now().minus(30, ChronoUnit.DAYS));
    }
}
```

## 7. 隐私与未成年人保护

### 7.1 匿名化展示策略

根据《未成年人保护法》和《儿童个人信息网络保护规定》，对不同学段用户采用不同脱敏策略：

| 学段 | 昵称策略 | 头像策略 | 学段标签 | 真实姓名 |
|------|---------|---------|---------|---------|
| 幼儿 | 昵称仅显示首字+★ | 使用系统默认卡通头像 | 显示"幼儿园" | 禁止 |
| 小学(1-3年级) | 昵称仅显示首字+★ | 使用系统默认卡通头像 | 显示年级 | 禁止 |
| 小学(4-6年级) | 昵称显示，禁止含真实姓名 | 可使用自定义头像 | 显示年级 | 禁止 |
| 初中 | 昵称正常显示 | 可使用自定义头像 | 显示年级+学科 | 禁止 |
| 高中 | 昵称正常显示 | 可使用自定义头像 | 显示年级+学科 | 用户可选 |

```java
@Component
public class FeedPrivacyMasker {

    /**
     * 根据发布者学段对用户信息进行脱敏
     */
    public FeedPublisherDTO maskPublisher(UserBasicInfo user) {
        FeedPublisherDTO dto = new FeedPublisherDTO();
        dto.setUserId(user.getId());

        StageType stage = user.getStageType();
        switch (stage) {
            case PRESCHOOL:
            case PRIMARY_LOW:  // 1-3年级
                dto.setNickname(maskName(user.getNickname()));
                dto.setAvatar(SystemAvatar.randomKidAvatar());
                dto.setGradeLabel(stage.getShortLabel());
                dto.setIsAnonymous(true);
                break;
            case PRIMARY_HIGH:  // 4-6年级
                dto.setNickname(sanitizeName(user.getNickname()));
                dto.setAvatar(user.getAvatar());
                dto.setGradeLabel(stage.getShortLabel());
                dto.setIsAnonymous(false);
                break;
            default:
                dto.setNickname(user.getNickname());
                dto.setAvatar(user.getAvatar());
                dto.setGradeLabel(user.getGradeLabel());
                dto.setIsAnonymous(false);
        }
        return dto;
    }

    private String maskName(String name) {
        if (name == null || name.isEmpty()) return "同学";
        return name.charAt(0) + "★";
    }

    /**
     * 过滤昵称中可能包含的真实姓名信息
     */
    private String sanitizeName(String nickname) {
        // 移除手机号模式
        nickname = nickname.replaceAll("1[3-9]\\d{9}", "***");
        // 移除明显真实姓名模式 (张三 → 张*)
        nickname = nickname.replaceAll("[\\u4e00-\\u9fa5]{2,4}(?=$|同学|学生)", match -> {
            String g = match.group();
            return g.charAt(0) + "*".repeat(g.length() - 1);
        });
        return nickname;
    }
}
```

### 7.2 可见性控制

```java
@Service
public class FeedVisibilityService {

    /**
     * 检查用户是否可以查看某条动态
     */
    public boolean canView(Long viewerId, FeedPost post) {
        // 已删除/违规的动态仅管理员可见
        if (post.getStatus() != 1) {
            return securityService.isAdmin(viewerId);
        }

        // 发布者本人始终可见
        if (post.getUserId().equals(viewerId)) {
            return true;
        }

        // 检查可见性范围
        switch (post.getVisibility()) {
            case 0: // 公开（同圈子可见）
                return isInCircle(viewerId, post.getCircleType(), post.getCircleId());
            case 1: // 仅好友
                return friendService.isFriend(viewerId, post.getUserId())
                    && isInCircle(viewerId, post.getCircleType(), post.getCircleId());
            case 2: // 仅自己
                return false; // 已在上面处理
            case 3: // 指定圈子
                return isInDesignatedCircles(viewerId, post.getPostId());
            default:
                return false;
        }
    }

    private boolean isInCircle(Long userId, int circleType, String circleId) {
        // 先查缓存
        String key = String.format("feed:members:%d:%s", circleType, circleId);
        if (Boolean.TRUE.equals(redisTemplate.opsForSet().isMember(key, userId.toString()))) {
            return true;
        }
        // 回查数据库
        return circleMemberMapper.existsActive(userId, circleType, circleId);
    }
}
```

## 8. 热门动态发现机制

### 8.1 热度计算定时任务

```java
/**
 * 每 15 分钟执行一次，计算各圈子热门动态
 */
@Component
public class HotFeedDetector {

    @Scheduled(fixedRate = 15 * 60 * 1000)
    public void detectAndMarkHotFeeds() {
        Instant since = Instant.now().minus(2, ChronoUnit.HOURS);

        // 批量查询近期互动率高的动态
        List<FeedPost> candidates = feedPostMapper.selectHighInteractionPosts(since, 500);

        for (FeedPost post : candidates) {
            double hotScore = calculateHotScore(post);

            if (hotScore > HOT_THRESHOLD) {
                // 标记为热门
                feedPostMapper.markAsHot(post.getPostId(), hotScore);

                // 投递到全校圈（提升曝光）
                if (post.getCircleType() != CircleType.SCHOOL_CIRCLE.getCode()) {
                    eventPublisher.publishEvent(new PromoteToSchoolCircleEvent(post));
                }

                // 对半活跃用户补充推送
                List<Long> semiActiveIds = userActivityService
                    .getSemiActiveUsers(post.getCircleType(), post.getCircleId());
                feedFanoutService.fanoutToUsers(post, semiActiveIds);
            }
        }
    }

    /**
     * 热度分 = 互动密度 × 时间衰减 × 来源加权
     */
    private double calculateHotScore(FeedPost post) {
        long hoursAge = Duration.between(post.getPublishedAt(), Instant.now()).toHours();
        if (hoursAge == 0) hoursAge = 1;

        double interactionDensity = (post.getLikeCount() * 2.0
                                   + post.getCommentCount() * 3.0
                                   + post.getShareCount() * 5.0) / hoursAge;

        double sourceWeight = FeedSourceType.valueOf(post.getSourceType()).getHotWeight();

        return interactionDensity * sourceWeight / (1 + 0.1 * hoursAge);
    }
}
```

```java
@RestControllerAdvice
public class FeedFallbackHandler {

    /**
     * Timeline 查询降级：
     * 1. Redis 缓存命中 → 返回缓存（即使数据稍旧）
     * 2. Redis 未命中 → 查数据库，跳过排序直接按时间倒序
     * 3. 数据库异常 → 返回空列表 + 降级标记
     */
    public FeedListDTO getTimelineWithFallback(Long userId, String cursor, int limit) {
        try {
            // 正常流程
            return feedQueryService.getTimeline(userId, cursor, limit);
        } catch (RedisConnectionFailureException e) {
            log.warn("Redis unavailable, fallback to DB for user={}", userId);
            try {
                // 降级：直接查 DB，按时间排序，不走缓存
                return feedQueryService.getTimelineFromDB(userId, cursor, limit, "latest");
            } catch (DataAccessException dbEx) {
                log.error("DB also failed for user={}", userId, dbEx);
                return FeedListDTO.degradedEmpty();
            }
        }
    }
}
```

```java
@Service
public class FeedPublishIdempotentService {

    private static final String IDEMPOTENT_KEY = "feed:publish:idem:";
    private static final Duration TTL = Duration.ofMinutes(5);

    public String acquireIdempotentKey(Long userId, String contentHash) {
        String key = IDEMPOTENT_KEY + userId + ":" + contentHash;
        String requestId = UUID.randomUUID().toString();

        Boolean acquired = redisTemplate.opsForValue()
            .setIfAbsent(key, requestId, TTL);

        if (Boolean.FALSE.equals(acquired)) {
            // 已有相同请求在处理中，返回之前的 requestId
            return redisTemplate.opsForValue().get(key);
        }
        return requestId;
    }
}
```

```java
@Component
public class FeedContentModerator {

    @Autowired private DFAFilter dfaFilter;  // 敏感词过滤器
    @Autowired private ContentSafetyClient aiSafetyClient;

    /**
     * 发布前内容审核
     * @return 审核通过返回 true，否则 false
     */
    public ModerationResult moderate(FeedPost post) {
        // 1. 敏感词检测
        String fullText = extractText(post);
        List<String> hits = dfaFilter.match(fullText);
        if (!hits.isEmpty()) {
            return ModerationResult.blocked("包含敏感内容: " + hits.get(0));
        }

        // 2. 图片安全检测 (异步标记，不阻塞发布)
        if (post.getContentType() == 1 || post.getContentType() == 2) {
            CompletableFuture.runAsync(() -> {
                for (String imgUrl : extractImageUrls(post)) {
                    SafetyCheckResult result = aiSafetyClient.checkImage(imgUrl);
                    if (result.isUnsafe()) {
                        feedPostMapper.updateStatus(post.getPostId(), Status.REPORTED);
                        eventPublisher.publishEvent(new UnsafeContentEvent(post, result));
                    }
                }
            });
        }

        return ModerationResult.passed();
    }
}
```

### 13.2 缓存预热

```java
/**
 * 用户打开 Feed 页面时的缓存预热
 */
@Service
public class FeedCacheWarmer {

    @Async("feedCacheExecutor")
    public void warmUp(Long userId) {
        String timelineKey = "feed:timeline:" + userId;

        // 如果缓存不存在，从 DB 加载
        if (!redisTemplate.hasKey(timelineKey)) {
            List<FeedTimeline> records = timelineMapper.selectLatestByUser(userId, 100);
            if (!records.isEmpty()) {
                Set<ZSetOperations.TypedTuple<String>> tuples = records.stream()
                    .map(r -> ZSetOperations.TypedTuple.of(
                        r.getPostId(), r.getRankScore()))
                    .collect(Collectors.toSet());
                redisTemplate.opsForZSet().add(timelineKey, tuples);
                redisTemplate.expire(timelineKey, Duration.ofMinutes(30));
            }
        }

        // 预热未读计数
        Long unread = timelineMapper.countUnread(userId);
        redisTemplate.opsForValue().set("feed:unread:" + userId, unread.toString(),
            Duration.ofDays(7));
    }
}
```

### 13.3 查询优化 — 推荐排序混合读取

```java
@Service
public class FeedRecommendationService {

    /**
     * 混合读取策略：
     * 1. 从 timeline 表读取写扩散的动态 (排序分过滤)
     * 2. 从 circle_posts 表实时拉取全校圈动态 (读扩散)
     * 3. 合并 + 去重 + 重新排序
     */
    public FeedListDTO getHybridTimeline(Long userId, FeedCursor cursor, int limit) {
        // 并行查询
        CompletableFuture<List<FeedTimeline>> inboxFuture = CompletableFuture.supplyAsync(
            () -> timelineMapper.selectByUser(userId, cursor, limit + 10)
        );

        CompletableFuture<List<FeedPost>> circleFuture = CompletableFuture.supplyAsync(
            () -> {
                List<Long> schoolCircleIds = circleMemberMapper
                    .findCircleIdsByType(userId, CircleType.SCHOOL_CIRCLE);
                if (schoolCircleIds.isEmpty()) return Collections.emptyList();
                return feedPostMapper.selectByCircleIds(schoolCircleIds, cursor, limit);
            }
        );

        // 合并结果
        List<FeedTimeline> inbox = inboxFuture.join();
        List<FeedPost> circlePosts = circleFuture.join();

        // 转换为统一格式并去重
        Map<String, FeedItemDTO> merged = new LinkedHashMap<>();
        for (FeedTimeline tl : inbox) {
            merged.put(tl.getPostId(), convert(tl));
        }
        for (FeedPost cp : circlePosts) {
            if (!merged.containsKey(cp.getPostId())) {
                double score = FeedRankScoreCalculator.calculate(cp, Instant.now());
                merged.put(cp.getPostId(), convert(cp, score));
            }
        }

        // 排序并截断
        List<FeedItemDTO> result = merged.values().stream()
            .sorted(Comparator.comparingDouble(FeedItemDTO::getRankScore).reversed())
            .limit(limit)
            .collect(Collectors.toList());

        // 生成游标
        FeedItemDTO last = result.isEmpty() ? null : result.get(result.size() - 1);
        String nextCursor = last != null ? encodeCursor(last) : null;

        return FeedListDTO.builder()
            .list(result)
            .nextCursor(nextCursor)
            .hasMore(result.size() == limit)
            .build();
    }
}
```

## 16. 数据清理与生命周期

| 数据 | 保留策略 | 清理方式 |
|------|---------|---------|
| `feed_posts` 正常动态 | 永久保留（或用户删除后 90 天物理删除） | 定时任务清理已删除数据 |
| `feed_timeline` 记录 | 90 天 | 归档到 `feed_timeline_archive`，1 年后物理删除 |
| `feed_interactions` | 与动态生命周期一致 | 动态删除时级联清理 |
| Redis Feed 缓存 | 30 分钟 TTL | 自动过期 |
| Redis 点赞记录 | 7 天 TTL | 自动过期 + 容量淘汰 |

```sql
-- 定时清理任务 (每天凌晨 3 点执行)
-- 1. 归档超期 timeline 记录
INSERT INTO feed_timeline_archive
SELECT * FROM feed_timeline
WHERE created_at < NOW() - INTERVAL '90 days'
ON CONFLICT DO NOTHING;

DELETE FROM feed_timeline
WHERE created_at < NOW() - INTERVAL '90 days';

-- 2. 物理删除已软删除超过 90 天的动态
DELETE FROM feed_posts
WHERE status = 0 AND updated_at < NOW() - INTERVAL '90 days';

-- 3. 清理孤立的互动记录
DELETE FROM feed_interactions
WHERE post_id NOT IN (SELECT post_id FROM feed_posts)
  AND created_at < NOW() - INTERVAL '30 days';
```

### 17.3 关键 SQL 汇总

```sql
-- 1. 获取用户信息流（推荐排序，游标分页）
SELECT t.post_id, t.rank_score, t.created_at, p.*
FROM feed_timeline t
INNER JOIN feed_posts p ON t.post_id = p.post_id
WHERE t.user_id = #{userId}
  AND p.status = 1
  AND (#{cursor.score} IS NULL
       OR (t.rank_score < #{cursor.score}
           OR (t.rank_score = #{cursor.score} AND t.id < #{cursor.id})))
ORDER BY t.rank_score DESC, t.id DESC
LIMIT #{limit};

-- 2. 获取圈子动态（读扩散场景）
SELECT * FROM feed_posts
WHERE circle_type = #{circleType}
  AND circle_id = #{circleId}
  AND status = 1
  AND published_at < #{cursor.time}
ORDER BY published_at DESC
LIMIT #{limit};

-- 3. 用户各圈子未读总数
SELECT circle_type, COUNT(*) AS unread
FROM feed_timeline
WHERE user_id = #{userId} AND read_status = 0
GROUP BY circle_type;

-- 4. 批量写入 timeline
INSERT INTO feed_timeline (user_id, post_id, publisher_id, circle_type,
    circle_id, source_type, rank_score, read_status, created_at)
VALUES
    (#{userId}, #{postId}, #{publisherId}, #{circleType},
     #{circleId}, #{sourceType}, #{rankScore}, 0, NOW()),
    ...;

-- 5. 热门动态检测（近 2 小时高互动）
SELECT post_id, source_type, circle_type, circle_id,
       like_count, comment_count, share_count, published_at
FROM feed_posts
WHERE status = 1
  AND published_at > NOW() - INTERVAL '2 hours'
  AND (like_count + comment_count * 2 + share_count * 3) >= 10
ORDER BY (like_count + comment_count * 2 + share_count * 3) DESC
LIMIT 500;
```
