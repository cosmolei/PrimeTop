# 用户设备管理与多端登录策略 - 详细设计

> 版本：1.0 | 更新日期：2026-05-22

## 1. 模块概述

### 1.1 定位

用户设备管理模块是 PrimeTop 认证鉴权体系的核心子系统，负责设备注册与识别、多端登录策略、Token 生命周期管理、远程会话管控和跨设备学习续接。该模块向上支撑 API 网关的认证中间件，向下关联推送服务、学习记录同步和会员权益校验。

### 1.2 与其他模块的关系

```
                    API 网关 (认证中间件)
                          │
                    ┌─────▼──────┐
                    │ 设备管理服务 │◄── 权限管理 (角色/家长管控)
                    └──┬──┬──┬───┘
                       │  │  │
          ┌────────────┘  │  └────────────┐
          │               │               │
    用户账号体系       推送服务        离线缓存与同步
   (注册/登录)     (设备Token)     (跨端续学触发)
```

### 1.3 设计目标

| 目标 | 说明 |
|------|------|
| 设备唯一标识 | 准确识别用户设备，支撑多端管理 |
| 按等级限制并发 | 不同会员等级允许不同数量的同时在线设备 |
| 安全风控联动 | 异常设备登录触发二次验证或冻结 |
| 无缝续学 | 用户在任一设备可继续上次未完成的学习会话 |
| 远程管控 | 支持主动踢人、全量下线（改密码、注销时） |

## 2. 核心概念

### 2.1 设备指纹 (Device Fingerprint)

设备指纹用于在无稳定硬件 ID 的场景下唯一标识一台设备。采用多维度合成策略：

| 维度 | 来源 | 权重 |
|------|------|------|
| 平台类型 | `Platform.operatingSystem` | 固定 |
| 设备型号 | `device_info_plugin` 读取 model | 高 |
| 系统版本 | `device_info_plugin` 读取 osVersion | 中 |
| 设备唯一ID | Android: `Settings.Secure.ANDROID_ID` / iOS: `identifierForVendor` | 高 |
| 屏幕分辨率 | `MediaQuery` | 低 |
| APP版本 | `packageInfo.version` | 低 |
| 时区/语言 | `Localizations` | 低 |

**合成算法**：将上述维度按固定顺序拼接，经 SHA-256 生成设备指纹哈希。

```
fingerprint_source = "{platform}|{model}|{osVersion}|{deviceId}|{screenWidth}x{screenHeight}|{appVersion}|{timezone}"
device_fingerprint = SHA256(fingerprint_source)
```

> **注意**：设备指纹仅用于辅助识别，不作为唯一判定依据。同一用户同一物理设备可能产生不同指纹（系统升级、APP 更新），因此以 `deviceId` 为主键、指纹为辅。

### 2.2 设备会话 (Device Session)

设备会话是用户在某一台设备上的登录实例。一个用户可以同时拥有多个活跃设备会话。

### 2.3 设备信任等级

| 信任等级 | 标识 | 说明 |
|----------|------|------|
| 新设备 | `new` | 首次登录，未经过验证 |
| 已验证 | `verified` | 已通过短信/邮箱验证码确认 |
| 信任设备 | `trusted` | 连续登录超过 30 天且无异常行为 |
| 异常设备 | `suspicious` | 触发风控规则（异地、频繁切换等） |

### 3.1 设备注册表 `user_device`

存储每次登录产生的 Token 对与状态：

```sql
CREATE TABLE device_session (
    id                BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id           BIGINT       NOT NULL,

    revoked_at        DATETIME     COMMENT '吊销时间',

    login_location    VARCHAR(128),

    user_agent        VARCHAR(512),

    created_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_expires (expires_at),

```

### 3.3 Redis 缓存结构

```
# 用户在线设备集合（实时维护）
Key:   user:online_devices:{user_id}
Type:  SET
Value: device_id1, device_id2, ...
TTL:   无（登出时主动移除）

# 设备会话快速校验
Key:   device_session:{session_id}
Type:  HASH
Fields: user_id, device_id, status, expires_at, trust_level
TTL:   与 session expires_at 对齐

# 设备 Token 黑名单（用于即时吊销）
Key:   token_blacklist:{jti}
Type:  STRING
Value: revoke_reason
TTL:   剩余有效时间

# 设备限流：同一设备登录频率
Key:   ratelimit:device_login:{device_id}
Type:  STRING (counter)
TTL:   1小时

# 用户在线心跳
Key:   heartbeat:{user_id}:{device_id}
Type:  STRING
Value: timestamp
TTL:   5分钟（需客户端定时续期）
```

## 4. 多端登录策略

### 4.1 按会员等级的设备限制

| 会员等级 | 最大同时在线设备数 | 最大注册设备数 | 说明 |
|----------|-------------------|---------------|------|
| 免费用户 | 1 | 3 | 仅允许一台设备在线 |
| 月度会员 | 2 | 5 | 手机+平板同时使用 |
| 年度会员 | 3 | 10 | 手机+平板+电脑 |
| 专项会员 | 2 | 5 | 同月度会员 |
| 家庭套餐 | 5 | 20 | 覆盖多个家庭成员设备 |

### 4.2 设备冲突处理策略

当新设备登录导致超出限制时的处理流程：

```
用户在新设备发起登录请求
        │
        ▼
  查询当前在线设备数
        │
   ┌────┴────┐
   │未超限    │超限
   ▼         ▼
  直接     查询策略配置
  登录        │
        ┌─────┼──────┐
        │踢最老│让用户 │拒绝
        │设备  │选择  │登录
        ▼     ▼      ▼
     自动踢   返回   返回
     出最久   在线   错误
     未活跃   设备   提示
     的设备   列表
```

**默认策略（可后台配置）**：`kick_oldest` —— 自动踢出最后活跃时间最早的设备。

#### 4.2.1 踢出设备详细流程

```python
async def handle_concurrent_login(user_id: int, new_device_id: str) -> None:
    """
    处理并发登录冲突
    """
    # 1. 获取用户会员等级和设备限制
    membership = await get_user_membership(user_id)
    max_devices = get_max_online_devices(membership.tier)

    # 2. 查询当前在线设备
    online_devices = await get_online_devices(user_id)

    if len(online_devices) < max_devices:
        # 未超限，直接登录
        return

    # 3. 超限，按策略处理
    strategy = await get_concurrent_strategy(membership.tier)

    if strategy == "kick_oldest":
        # 找出最久未活跃的设备
        oldest = min(online_devices, key=lambda d: d.last_active_at)

        # 不能踢自己（同设备重新登录）
        if oldest.device_id == new_device_id:
            # 更新会话即可
            await refresh_device_session(oldest.session_id)
            return

        # 踢出
        await kick_device(
            user_id=user_id,
            device_id=oldest.device_id,
            reason="concurrent_limit"
        )

        # 推送通知被踢设备
        await send_kick_notification(
            push_token=oldest.push_token,
            push_provider=oldest.push_provider,
            reason="您的账号已在其他设备登录"
        )

    elif strategy == "user_choice":
        # 返回在线设备列表，让用户选择踢谁
        # 由前端展示选择界面，用户选择后再调用 /auth/kick-and-login
        raise ConcurrentLoginError(
            online_devices=[
                DeviceInfo(d) for d in online_devices
            ],
            action_required="select_device_to_kick"
        )

    elif strategy == "reject":
        raise DeviceLimitExceededError(
            max_devices=max_devices,
            current_devices=len(online_devices)
        )
```

### 4.3 同平台替换策略

同一用户在同一平台（如两台 Android 手机）上的处理：

| 场景 | 策略 |
|------|------|
| 同一物理设备重新登录 | 复用已有设备记录，刷新 Token，不清除学习缓存 |
| 同平台不同设备登录 | 视为不同设备，受并发限制约束 |
| 同设备不同 APP 版本 | 以新版本信息更新设备记录，会话延续 |

## 5. Token 生命周期管理

### 5.1 Token 体系

| Token 类型 | 有效期 | 存储 | 用途 |
|-----------|--------|------|------|
| Access Token | 30 分钟 | 内存（客户端） | API 请求鉴权 |
| Refresh Token | 30 天 | 安全存储（Keychain/Keystore） | 刷新 Access Token |
| Device Token | 与设备绑定 | 安全存储 | 设备身份标识（非 Push Token） |

### 5.2 Token 刷新流程

```
客户端                              服务端
  │                                   │
  │  ① API 请求 (带 Access Token)     │
  │──────────────────────────────────►│
  │                                   │ 校验 Token
  │  ② 返回数据 / 401                 │
  │◄──────────────────────────────────│
  │                                   │
  │  ③ 检测到 401 + error=token_expired
  │     用 Refresh Token 刷新         │
  │──────────────────────────────────►│
  │                                   │ 校验 Refresh Token
  │                                   │ 检查 session 是否被吊销
  │                                   │ 检查设备是否仍在线
  │  ④ 返回新 Token 对                │
  │◄──────────────────────────────────│
  │                                   │
  │  ⑤ 旧 Refresh Token 吊销          │
  │     (单次使用，防重放)              │
  │                                   │
  │  ⑥ 用新 Token 重放原始请求         │
  │──────────────────────────────────►│
```

### 5.3 Token 刷新 API

```
POST /api/v1/auth/refresh
Content-Type: application/json

Request:
{
    "refresh_token": "eyJ...",
    "device_id": "abc123",
    "device_fingerprint": "sha256hash..."
}

Response 200 (成功):
{
    "code": 0,
    "data": {
        "access_token": "eyJ...(新)",
        "refresh_token": "eyJ...(新)",
        "expires_in": 1800,
        "session_id": "uuid-session-id"
    }
}

Response 401 (Refresh Token 无效或已吊销):
{
    "code": 40101,
    "message": "Refresh token has been revoked",
    "data": {
        "reason": "kicked" | "password_changed" | "account_frozen" | "expired",
        "require_relogin": true
    }
}
```

### 5.4 关键安全规则

1. **Refresh Token 单次使用**：每次刷新后旧 Token 立即加入黑名单（Redis `token_blacklist:{jti}`）
2. **刷新频率限制**：同一设备每分钟最多刷新 3 次
3. **吊销传播延迟**：Token 黑名单写入 Redis 后，网关需在 5 秒内生效
4. **密码修改全量吊销**：用户修改密码时，该用户所有活跃 `device_session` 状态置为 `revoked`
5. **账号冻结全量吊销**：同上，`revoke_reason = account_frozen`

## 7. 心跳与在线状态管理

### 7.1 客户端心跳机制

客户端每隔 **2 分钟**发送一次轻量心跳请求：

```
POST /api/v1/device/heartbeat
Authorization: Bearer {access_token}

Request:
{
    "device_id": "xxx",
    "client_timestamp": 1716364800
}

Response 200:
{
    "code": 0,
    "data": {
        "server_time": 1716364801,
        "force_logout": false
    }
}
```

### 7.2 心跳处理逻辑

```python
async def handle_heartbeat(user_id: int, device_id: str) -> HeartbeatResult:
    """
    处理客户端心跳
    """
    session_key = f"device_session:{user_id}:{device_id}"

    # 1. 检查会话是否被吊销
    session = await redis.hgetall(session_key)
    if not session or session["status"] != "active":
        return HeartbeatResult(force_logout=True, reason="session_revoked")

    # 2. 检查 Token 黑名单
    jti = session.get("refresh_token_jti")
    if jti and await redis.exists(f"token_blacklist:{jti}"):
        return HeartbeatResult(force_logout=True, reason="token_revoked")

    # 3. 更新心跳时间
    now = datetime.utcnow()
    await redis.hset(session_key, "last_heartbeat_at", now.isoformat())

    # 4. 续期在线设备心跳 key
    await redis.setex(
        f"heartbeat:{user_id}:{device_id}",
        300,  # 5分钟 TTL
        str(int(now.timestamp()))
    )

    # 5. 更新数据库中的 last_active_at（异步，不阻塞响应）
    await db.execute(
        update(user_device)
        .where(user_device.c.user_id == user_id)
        .where(user_device.c.device_id == device_id)
        .values(last_active_at=now, is_online=1)
    )

    # 6. 检查 APP 版本是否需要强制更新
    force_update = await check_force_update(session.get("app_version"))

    return HeartbeatResult(
        force_logout=False,
        force_update=force_update,
        server_time=now
    )
```

### 7.3 离线判定

服务端通过心跳超时判定设备离线：

- **心跳 key 过期**（5 分钟无心跳）→ 标记设备 `is_online = 0`
- **离线检测定时任务**：每 10 分钟扫描一次 `user:online_devices:{user_id}`，移除已过期的 `heartbeat:{user_id}:{device_id}` 对应的设备 ID
- **会话自然过期**：`device_session` 的 `expires_at` 到期后，定时任务批量清理

### 8.2 踢出执行逻辑

```python
async def kick_device(user_id: int, device_id: str, reason: str) -> None:
    """
    踢出指定设备
    """
    now = datetime.utcnow()

    # 1. 查询目标设备的活跃会话
    sessions = await db.fetch_all(
        select([device_session])
        .where(device_session.c.user_id == user_id)
        .where(device_session.c.device_id == device_id)
        .where(device_session.c.status == "active")
    )

    # 2. 吊销所有活跃会话
    for session in sessions:
        # 加入 Token 黑名单
        await redis.setex(
            f"token_blacklist:{session.refresh_token_jti}",
            ttl_seconds(session.expires_at),
            reason
        )

        # 更新会话状态
        await db.execute(
            update(device_session)
            .where(device_session.c.id == session.id)
            .values(status="revoked", revoked_at=now, revoke_reason=reason)
        )

        # 清除 Redis 缓存
        await redis.delete(f"device_session:{session.session_id}")

    # 3. 更新设备状态
    await db.execute(
        update(user_device)
        .where(user_device.c.user_id == user_id)
        .where(user_device.c.device_id == device_id)
        .values(is_online=0, last_invalidated_at=now)
    )

    # 4. 从在线设备集合移除
    await redis.srem(f"user:online_devices:{user_id}", device_id)
    await redis.delete(f"heartbeat:{user_id}:{device_id}")

    # 5. 推送通知被踢设备（如果 push token 可用）
    device = await get_device(user_id, device_id)
    if device and device.push_token:
        await push_service.send(
            provider=device.push_provider,
            token=device.push_token,
            title="账号安全提醒",
            body="您的账号已在其他设备登录，如非本人操作请及时修改密码",
            data={
                "action": "force_logout",
                "reason": reason,
                "timestamp": now.isoformat()
            }
        )
```

### 8.3 全量下线场景

| 触发场景 | 处理方式 |
|----------|----------|
| 修改密码 | 踢出所有设备，当前设备自动使用新 Token |
| 账号冻结 | 踹出所有设备，不保留任何会话 |
| 账号注销 | 所有会话立即吊销，7天冷静期后清除数据 |
| 管理员封禁 | 同冻结 |
| 长期未登录（>90天） | 过期会话批量清理，设备信任等级重置 |

```python
async def revoke_all_sessions(user_id: int, reason: str, except_device_id: str = None) -> int:
    """
    吊销用户所有设备会话
    返回吊销的会话数量
    """
    sessions = await db.fetch_all(
        select([device_session])
        .where(device_session.c.user_id == user_id)
        .where(device_session.c.status == "active")
    )

    revoked_count = 0
    for session in sessions:
        if except_device_id and session.device_id == except_device_id:
            continue

        await kick_device(user_id, session.device_id, reason)
        revoked_count += 1

    # 清空在线设备集合
    if except_device_id:
        await redis.delete(f"user:online_devices:{user_id}")
        await redis.sadd(f"user:online_devices:{user_id}", except_device_id)
    else:
        await redis.delete(f"user:online_devices:{user_id}")

    return revoked_count
```

## 10. Push Token 管理

### 10.1 Push Token 注册/更新流程

Push Token（FCM/APNs/HMS）由客户端获取后上报，与设备绑定。需处理以下场景：

| 场景 | 处理 |
|------|------|
| 首次获取 Push Token | 登录时在 device_info 中上报 |
| Token 刷新 | 客户端检测到 Token 变化，调用更新接口 |
| APP 重装 | 新 Token 与旧设备记录关联（通过 device_id 匹配） |
| 用户关闭通知权限 | 保留 Token 但标记 `notifications_enabled = false` |
| 用户卸载 | Token 无效后由推送服务回调标记 |

## 11. 异常设备检测与风控

### 11.1 风控规则

| 规则ID | 规则描述 | 阈值 | 动作 |
|--------|----------|------|------|
| `R001` | 同一设备不同账号频繁切换 | 1小时内 ≥ 5 次 | 设备标记 `suspicious`，需二次验证 |
| `R002` | 同一账号短时间内多设备登录 | 10分钟内 ≥ 3 台新设备 | 触发短信告警，需验证 |
| `R003` | 登录 IP 与常用 IP 地理差异大 | 跨省/跨国 | 新设备标记 `new`，需短信验证 |
| `R004` | 设备指纹与已注册设备不匹配 | 同 device_id 指纹变化 > 2 次 | 降低信任等级 |
| `R005` | 频繁 Token 刷新 | 1分钟内 ≥ 10 次 | 限制刷新频率，记录告警 |

### 11.2 风控检查集成

```python
async def check_login_risk(user_id: int, device_info: DeviceInfo, login_ip: str) -> RiskCheckResult:
    """
    登录风控检查
    """
    risks = []

    # R001: 设备频繁切换账号
    device_switch_count = await redis.get(f"ratelimit:device_switch:{device_info.device_id}")
    if device_switch_count and int(device_switch_count) >= 5:
        risks.append(RiskItem(rule="R001", level="high"))

    # R002: 账号频繁新设备登录
    recent_new_devices = await redis.get(f"ratelimit:new_device_login:{user_id}")
    if recent_new_devices and int(recent_new_devices) >= 3:
        risks.append(RiskItem(rule="R002", level="high"))

    # R003: 异地登录
    known_locations = await get_user_known_locations(user_id)
    login_location = await resolve_ip_location(login_ip)
    if known_locations and not is_nearby(login_location, known_locations, threshold_km=200):
        risks.append(RiskItem(rule="R003", level="medium"))

    if any(r.level == "high" for r in risks):
        return RiskCheckResult(
            action="require_verification",
            verification_method="sms",
            risks=risks
        )
    elif risks:
        return RiskCheckResult(
            action="allow_with_alert",
            risks=risks
        )

    return RiskCheckResult(action="allow")
```

```dart
import 'package:flutter_secure_storage/flutter_secure_storage.dart';

class TokenStorage {
    static const _accessTokenKey = 'access_token';
    static const _refreshTokenKey = 'refresh_token';
    static const _deviceIdKey = 'device_id';
    static const _sessionIdKey = 'session_id';

    final _storage = const FlutterSecureStorage();

    Future<void> saveTokens({
        required String accessToken,
        required String refreshToken,
        required String sessionId,
    }) async {
        await Future.wait([
            _storage.write(key: _accessTokenKey, value: accessToken),
            _storage.write(key: _refreshTokenKey, value: refreshToken),
            _storage.write(key: _sessionIdKey, value: sessionId),
        ]);
    }

    Future<String?> get refreshToken => _storage.read(key: _refreshTokenKey);

    Future<void> clearAll() async {
        await _storage.deleteAll();
    }
}
```

### 13.2 心跳服务

```dart
class HeartbeatService {
    Timer? _timer;
    static const _interval = Duration(minutes: 2);

    void start() {
        _timer?.cancel();
        _timer = Timer.periodic(_interval, (_) => _sendHeartbeat());
    }

    void stop() {
        _timer?.cancel();
        _timer = null;
    }

    Future<void> _sendHeartbeat() async {
        try {
            final result = await api.post('/device/heartbeat', body: {
                'device_id': await getDeviceId(),
                'client_timestamp': DateTime.now().millisecondsSinceEpoch ~/ 1000,
            });

            if (result.data['force_logout'] == true) {
                await _handleForceLogout(result.data['reason']);
            }
        } on UnauthorizedException {
            // Access Token 过期，尝试刷新
            final refreshed = await refreshTokenIfNeeded();
            if (!refreshed) {
                await _handleForceLogout('token_expired');
            }
        }
    }

    Future<void> _handleForceLogout(String reason) async {
        stop();
        await tokenStorage.clearAll();
        // 跳转到登录页，并显示提示
        navigator.pushNamedAndRemoveUntil('/login', (route) => false,
            arguments: {'kick_reason': reason});
    }
}
```

### 13.3 设备信息采集

```dart
import 'package:device_info_plus/device_info_plus.dart';
import 'package:crypto/crypto.dart';
import 'dart:convert';

class DeviceInfoCollector {
    static final _deviceInfo = DeviceInfoPlugin();

    static Future<Map<String, dynamic>> collect() async {
        String deviceId;
        String model;
        String osVersion;
        String platform;

        if (Platform.isAndroid) {
            final info = await _deviceInfo.androidInfo;
            deviceId = info.id; // Settings.Secure.ANDROID_ID
            model = info.model;
            osVersion = info.version.release;
            platform = 'android';
        } else {
            final info = await _deviceInfo.iosInfo;
            deviceId = info.identifierForVendor ?? '';
            model = info.utsname.machine;
            osVersion = info.systemVersion;
            platform = 'ios';
        }

        final fingerprint = _generateFingerprint(
            platform: platform,
            model: model,
            osVersion: osVersion,
            deviceId: deviceId,
        );

        return {
            'device_id': deviceId,
            'device_model': model,
            'platform': platform,
            'os_version': osVersion,
            'app_version': await _getAppVersion(),
            'device_fingerprint': fingerprint,
        };
    }

    static String _generateFingerprint({
        required String platform,
        required String model,
        required String osVersion,
        required String deviceId,
    }) {
        final source = '$platform|$model|$osVersion|$deviceId';
        return sha256.convert(utf8.encode(source)).toString();
    }
}
```
