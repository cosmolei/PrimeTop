## 2. 整体流程架构

### 2.1 全链路概览

```
来源渠道: ①手动录入 ②批量导入(Excel/CSV) ③AI智能生成 ④OCR试卷扫描
                                │
                                ▼
                    ┌──────────────────────┐
                    │  统一题目暂存区 DRAFT  │
                    └──────────┬───────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
       ┌────────────┐  ┌────────────┐  ┌─────────────────┐
       │ 结构化解析  │  │ 查重去重   │  │ 知识点自动标注   │
       └─────┬──────┘  └─────┬──────┘  └────────┬────────┘
             └───────────────┼──────────────────┘
                             ▼
                    ┌────────────────────┐
                    │ 自动质量评分(规则+AI) │
                    └─────────┬──────────┘
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
              score ≥ 80           score < 80
                    │                   │
                    ▼                   ▼
            ┌──────────────┐   ┌───────────────┐
            │ 自动通过      │   │ 人工审核队列    │
            │ APPROVED     │   │ PENDING_REVIEW │
            └──────┬───────┘   └───────┬───────┘
                   │            ┌──────┴──────┐
                   │            ▼             ▼
                   │        审核通过       审核驳回
                   │        APPROVED      REJECTED
                   │            │             │
                   └────────────┘             ▼
                        │               退回修改→DRAFT
                        ▼
               ┌─────────────────┐
               │ 灰度发布→全量上线 │  PUBLISHED
               └─────────────────┘
```

### 2.2 题目状态机

```
DRAFT → STRUCTURING → DEDUP_CHECK → TAGGING → QUALITY_SCORING
  │(删)     │(失败)       │(疑似重复)    │(失败)      │
  ▼         ▼             ▼             ▼            ▼
DELETED  PARSE_FAILED  DUPLICATE    TAG_FAILED   PENDING_REVIEW
                       _SUSPECT                       │
                                              ┌───────┤
                                              ▼       ▼
                                          APPROVED  REJECTED→(退回DRAFT)
                                              │
                                              ▼
                                          PUBLISHED → ARCHIVED
```

### 2.3 状态定义

| 状态 | 说明 | 可流转到 |
|------|------|----------|
| `DRAFT` | 草稿/暂存 | `STRUCTURING`, `DELETED` |
| `STRUCTURING` | 结构化解析中 | `DEDUP_CHECK`, `PARSE_FAILED` |
| `PARSE_FAILED` | 解析失败 | `DRAFT`（修正重试） |
| `DEDUP_CHECK` | 查重检测中 | `TAGGING`, `DUPLICATE_SUSPECT` |
| `DUPLICATE_SUSPECT` | 疑似重复 | `DRAFT`（废弃）, `TAGGING`（确认不重复） |
| `TAGGING` | 自动标注中 | `QUALITY_SCORING`, `TAG_FAILED` |
| `TAG_FAILED` | 标注失败 | `DRAFT`（重试）, `QUALITY_SCORING`（跳过） |
| `QUALITY_SCORING` | 质量评分中 | `APPROVED`, `PENDING_REVIEW` |
| `PENDING_REVIEW` | 待人工审核 | `APPROVED`, `REJECTED` |
| `APPROVED` | 审核通过 | `PUBLISHED`, `PENDING_REVIEW`（撤回） |
| `REJECTED` | 审核驳回 | `DRAFT`（修改重提） |
| `PUBLISHED` | 已发布 | `ARCHIVED` |
| `ARCHIVED` | 已归档 | `DRAFT`（重新启用） |
| `DELETED` | 已删除 | 终态 |

### 5.3 步骤一：结构化解析校验

| 校验项 | 规则 | 失败处理 |
|--------|------|----------|
| 题干非空 | stem 不能为空 | PARSE_FAILED |
| 题型匹配 | 选择题须有选项 | PARSE_FAILED |
| 答案非空 | answer 不能为空 | PARSE_FAILED |
| 选项数量 | 2-6个 | 警告 |
| LaTeX语法 | 公式格式校验 | 警告，不阻断 |
| 长度限制 | 题干≤2000，解析≤5000 | 截断警告 |

```java
@Service
public class QuestionStructuringService {

    private final QuestionStructureValidator validator;
    private final QuestionRepository questionRepo;
    private final PipelineEventPublisher eventPub;

    public StructuringResult structure(String questionId) {
        Question q = questionRepo.findById(questionId)
            .orElseThrow(() -> new QuestionNotFoundException(questionId));

        ValidationResult vr = validator.validateFields(q);
        if (!vr.isValid()) {
            q.setStatus(QuestionStatus.PARSE_FAILED);
            q.setParseError(vr.getFirstError());
            questionRepo.save(q);
            eventPub.publishStepFailed(questionId, PipelineStep.STRUCTURING, vr.getFirstError());
            return StructuringResult.fail(questionId, vr.getFirstError());
        }

        // 规范化
        q.setStem(normalizeText(q.getStem()));
        q.setStatus(QuestionStatus.DEDUP_CHECK);
        questionRepo.save(q);
        eventPub.publishStepCompleted(questionId, PipelineStep.STRUCTURING);
        return StructuringResult.success(questionId);
    }
}
```

### 5.4 步骤二：查重去重

| 相似度 | 判定 | 处理 |
|--------|------|------|
| ≥ 0.95 | 高度重复 | 自动废弃 |
| 0.85-0.95 | 疑似重复 | `DUPLICATE_SUSPECT`，人工判定 |
| < 0.85 | 不重复 | 正常流转 |

```java
@Service
public class QuestionDedupService {

    @Value("${question.dedup.auto-discard:0.95}")
    private double autoDiscardThreshold;
    
    @Value("${question.dedup.threshold:0.85}")
    private double dedupThreshold;

    public DedupResult checkDuplicate(String questionId) {
        Question q = questionRepo.findById(questionId)
            .orElseThrow(() -> new QuestionNotFoundException(questionId));

        List<SimilarQuestion> similar = similarityClient
            .findSimilar(q.getStem(), q.getSubjectId(), q.getGradeRange(), 20);

        if (similar.isEmpty()) {
            q.setStatus(QuestionStatus.TAGGING);
            questionRepo.save(q);
            return DedupResult.unique(questionId);
        }

        double topScore = similar.get(0).getSimilarity();
        if (topScore >= autoDiscardThreshold) {
            q.setStatus(QuestionStatus.DUPLICATE_SUSPECT);
            q.setParseError("高度重复题目: " + similar.get(0).getQuestionId());
            questionRepo.save(q);
            return DedupResult.duplicate(questionId, similar);
        }
        if (topScore >= dedupThreshold) {
            q.setStatus(QuestionStatus.DUPLICATE_SUSPECT);
            questionRepo.save(q);
            return DedupResult.suspect(questionId, similar);
        }

        q.setStatus(QuestionStatus.TAGGING);
        questionRepo.save(q);
        return DedupResult.similar(questionId, similar);
    }
}
```

### 5.5 步骤三：知识点自动标注

调用知识点标注引擎，自动关联课标知识点。标注失败时根据配置决定是否阻断。

```java
@Service
public class QuestionTaggingStep {

    private final KnowledgeTaggingClient taggingClient;
    private final QuestionRepository questionRepo;

    public TaggingResult tag(String questionId) {
        Question q = questionRepo.findById(questionId)
            .orElseThrow(() -> new QuestionNotFoundException(questionId));

        try {
            TaggingResponse resp = taggingClient.tag(
                q.getStem(), q.getSubjectId(), q.getGradeRange(), q.getTextbookId());

            if (resp.getTaggedPoints().isEmpty()) {
                // 标注失败但允许跳过
                q.setStatus(QuestionStatus.TAG_FAILED);
                questionRepo.save(q);
                return TaggingResult.failed(questionId, "无法自动标注知识点");
            }

            q.setKnowledgePointIds(
                resp.getTaggedPoints().stream()
                    .map(TaggedPoint::getPointId).collect(Collectors.toList()));
            q.setChapterId(resp.getSuggestedChapterId());
            q.setDifficulty(resp.getSuggestedDifficulty());
            q.setStatus(QuestionStatus.QUALITY_SCORING);
            questionRepo.save(q);
            return TaggingResult.success(questionId, resp.getTaggedPoints());

        } catch (Exception e) {
            log.error("知识点标注异常 questionId={}", questionId, e);
            q.setStatus(QuestionStatus.TAG_FAILED);
            questionRepo.save(q);
            return TaggingResult.failed(questionId, e.getMessage());
        }
    }
}
```

### 5.6 步骤四：质量评分

采用规则引擎 + AI 辅助的双重评分机制。

#### 5.6.1 评分维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 内容完整性 | 25% | 题干、答案、解析是否完整 |
| 知识点对齐 | 20% | 知识点标注与课标一致性 |
| 难度合理性 | 15% | 难度标注与实际内容匹配度 |
| 表述规范性 | 15% | 语言规范、无错别字、公式正确 |
| 原创性 | 15% | 与已有题目的差异化程度 |
| 适龄性 | 10% | 表达方式适合目标学段 |

#### 5.6.2 规则引擎评分

```java
@Component
public class RuleBasedScorer {

    public ScoreResult score(Question q) {
        int total = 0;

        // 内容完整性 (25分)
        int completeness = 0;
        if (StringUtils.isNotBlank(q.getStem())) completeness += 8;
        if (StringUtils.isNotBlank(q.getAnswer())) completeness += 8;
        if (StringUtils.isNotBlank(q.getAnswerExplanation())) completeness += 5;
        if (q.getOptions() != null && !q.getOptions().isEmpty()) completeness += 4;
        total += completeness;

        // 知识点对齐 (20分)
        int alignment = 0;
        if (q.getKnowledgePointIds() != null && !q.getKnowledgePointIds().isEmpty()) {
            alignment += 10;
        }
        if (q.getChapterId() != null) {
            alignment += 10;
        }
        total += alignment;

        // 表述规范 (15分)
        int language = 15;
        if (containsGarbledText(q.getStem())) language -= 5;
        if (hasInvalidLatex(q.getStemRichText())) language -= 5;
        total += Math.max(0, language);

        // 原创性由去重步骤提供
        total += 10; // 默认，去重结果中会修正

        // 适龄性由AI辅助判定
        total += 7; // 默认

        return new ScoreResult(total, Map.of(
            "completeness", completeness,
            "alignment", alignment,
            "language", Math.max(0, language)
        ));
    }
}
```

### 5.7 自动审核判定

```java
@Service
public class AutoApproveService {

    @Value("${question.pipeline.auto-approve-threshold:80}")
    private int autoApproveThreshold;

    public AutoApproveResult judge(String questionId, int qualityScore) {
        if (qualityScore >= autoApproveThreshold) {
            // 自动通过
            questionRepo.updateStatus(questionId, QuestionStatus.APPROVED);
            return AutoApproveResult.approved(questionId, qualityScore);
        } else {
            // 进入人工审核
            questionRepo.updateStatus(questionId, QuestionStatus.PENDING_REVIEW);
            // 分配审核人
            String reviewer = reviewerAssignStrategy.assign(questionId);
            notificationService.notifyReviewer(reviewer, questionId);
            return AutoApproveResult.pendingReview(questionId, qualityScore, reviewer);
        }
    }
}
```

```java
@Scheduled(fixedDelay = 3600000) // 每小时检查
public void checkReviewTimeout() {
    LocalDateTime threshold = LocalDateTime.now()
        .minusHours(pipelineConfig.getReviewTimeoutHours());
    
    List<Question> timedOut = questionRepo.findByStatusAndReviewAssignedBefore(
        QuestionStatus.PENDING_REVIEW, threshold);
    
    for (Question q : timedOut) {
        // 1. 发送催审通知
        notificationService.sendUrgentReviewNotice(q.getReviewedBy(), q.getId());
        
        // 2. 超时24小时以上自动升级

            reviewEscalationService.escalate(q.getId());
        }
    }
}
```

### 6.3 审核人分配策略

```java
@Component
public class ReviewerAssignStrategy {

    private final ReviewerLoadTracker loadTracker;

    /**
     * 按学科匹配 + 负载均衡分配审核人
     */
    public String assign(String questionId) {
        Question q = questionRepo.findById(questionId).orElseThrow();
        
        // 获取有该学科审核权限的审核人
        List<Reviewer> candidates = reviewerRepo
            .findActiveBySubject(q.getSubjectId());
        
        if (candidates.isEmpty()) {
            candidates = reviewerRepo.findActiveGeneral();
        }
        
        // 按当前待审核数量升序排列，选择最空闲的
        return candidates.stream()
            .min(Comparator.comparingInt(
                r -> loadTracker.getPendingCount(r.getId())))
            .map(Reviewer::getId)
            .orElseThrow(() -> new NoReviewerAvailableException());
    }
}
```

```java
public void monitorGrayPublish() {
    List<Question> grayQuestions = questionRepo
        .findByPublishScopeIn(List.of("GRAY_10", "GRAY_50"));
    
    for (Question q : grayQuestions) {
        GrayMetrics metrics = metricsCollector.collect(q.getId());

    }
```

### 8.1 批量管线执行

```java
@Service
public class BatchPipelineService {

    private final QuestionPipelineOrchestrator orchestrator;
    private final TaskExecutor taskExecutor;

    public BatchPipelineResult executeBatch(List<String> questionIds, 
                                             PipelineConfig config) {
        String batchId = "pb_" + IdGenerator.next();
        
        // 分批执行，每批 batchSize 个并行
        List<List<String>> partitions = Lists.partition(questionIds, 
            config.getBatchSize());
        
        List<CompletableFuture<Void>> futures = partitions.stream()
            .map(batch -> CompletableFuture.runAsync(() -> {
                for (String qId : batch) {
                    try {
                        orchestrator.submitToPipeline(qId, config);
                    } catch (Exception e) {
                        log.error("管线提交失败: questionId={}", qId, e);
                    }
                }
            }, taskExecutor))
            .collect(Collectors.toList());

        CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
        
        return new BatchPipelineResult(batchId, questionIds.size());
    }
}
```

## 9. 错误处理与异常场景

### 9.1 异常码定义

| 错误码 | HTTP状态 | 说明 |
|--------|----------|------|
| `QUESTION_NOT_FOUND` | 404 | 题目不存在 |
| `INVALID_STATE_TRANSITION` | 409 | 非法状态流转 |
| `PARSE_FAILED` | 422 | 结构化解析失败 |
| `DUPLICATE_DETECTED` | 409 | 检测到重复题目 |
| `IMPORT_FILE_INVALID` | 400 | 导入文件格式错误 |
| `IMPORT_ROW_ERROR` | 422 | 导入行数据校验失败 |
| `REVIEW_TIMEOUT` | 408 | 审核超时 |
| `NO_REVIEWER_AVAILABLE` | 503 | 无可用审核人 |
| `AI_GENERATION_FAILED` | 502 | AI生成失败 |
| `OCR_RECOGNITION_FAILED` | 502 | OCR识别失败 |
| `PUBLISH_SCOPE_INVALID` | 400 | 无效发布范围 |
| `GRAY_MONITOR_ALERT` | 200 | 灰度监控告警（非错误） |

### 9.2 重试策略

| 步骤 | 可重试 | 重试策略 |
|------|--------|----------|
| 结构化解析 | 否 | 需人工修正后重新提交 |
| 查重去重 | 是 | 指数退避，最多3次 |
| 知识点标注 | 是 | 指数退避，最多3次，失败后可跳过 |
| 质量评分 | 是 | 指数退避，最多3次 |
| AI生成 | 是 | 指数退避，最多3次 |
| OCR识别 | 是 | 指数退避，最多2次 |

### 9.3 降级策略

- **知识点标注服务不可用**：标记 `TAG_FAILED`，允许跳过进入质量评分，人工补充标注
- **AI评分服务不可用**：仅使用规则评分，降低自动通过阈值到 70
- **相似度服务不可用**：跳过查重步骤，在发布时增加人工审核权重
- **OCR服务不可用**：返回错误，提示用户稍后重试

## 11. 关键注意事项

1. **并发控制**：同一题目同一时间只允许一个管线任务运行，通过 Redis 分布式锁 `pipeline:{questionId}` 保证
2. **幂等性**：所有管线步骤必须幂等，重复执行不产生副作用
3. **审计追踪**：题目状态变更、审核操作均需记录到 `question_review_log`
4. **缓存一致性**：题目发布/下架后需主动刷新推荐缓存和搜索索引
5. **文件清理**：导入任务完成 30 天后自动清理上传的临时文件
6. **批量限流**：单次批量导入上限 5000 条，AI 生成上限 100 条，防止资源过载
