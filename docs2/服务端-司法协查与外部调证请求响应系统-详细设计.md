# 服务端-司法协查与外部调证请求响应系统 详细设计

> 补缺说明：外部法定主体（公安/国安/检察院/法院/市场监管/网信/教育主管等）依法调取用户数据、要求冻结涉案资产、协助账号处置、以及监管现场检查配合，是未成年人教育平台的高确定性合规义务。经全库核查，该链路**此前零设计**且存在多处悬空引用：
> - 《服务端-数据脱敏规则引擎与敏感信息动态遮蔽服务》§代码注释："仅在授权上下文（如公安协查、用户本人验证）下可解密"——**"公安协查"授权解密通道无任何协议定义**；
> - 《服务端-未成年人支付风控与误充值自动识别退款引擎》escalation_type 枚举含 `12315/12345/COURT/APP_STORE/MEDIA`——升级后的**法务应诉与行政调档流程无落地**；
> - 《服务端-用户违规处罚执行与账号状态管控服务》覆盖平台自主处罚，**法院令/监管令驱动的账号封禁与解封**无执行入口；
> - 《服务端-未成年人数据隐私合规自动化与数据主体权利请求处理引擎》仅覆盖**用户本人发起**的 DSR，第三方法定调取与其对称的"数据披露"侧完全缺失；
> - 《服务端-教育行业监管合规与政策适配引擎》经全文检索，对"执法/检查/调取/协查"**零字覆盖**。
>
> 本系统（内部代号 **LERMS**，Legal External Request Management System）补齐该执行层：统一受理 → 公文核验 → 最小范围决策 → 分级审批 → 授权取数打包 → 加密交付回执 → 司法冻结/划扣 → 账号处置协助 → 用户通知（含豁免）→ 透明度报告，全程留痕、四眼分权。

## 1. 模块概述

### 1.1 功能定位

| 维度 | 说明 |
| --- | --- |
| 系统职责 | 承接所有**平台外部法定主体**对平台数据的调取、冻结、处置协助与检查配合请求，将其转化为可审计、可限权、可追责的内部工作流 |
| 用户 | 平台法务经办（Legal Ops）、法务负责人、DPO（数据保护官）/安全负责人、CEO 授权人、财务（冻结资产侧）、外部请求方（线下交互，无系统账号） |
| 形态 | 管理后台独立菜单域（`legal` 域），独立权限点族 + 独立审计通道；**无 App 端接口**（用户侧仅被动接收通知） |
| 服务定位 | 独立微服务 `lerms-service`，读写各自数据库 schema，通过适配器访问各业务域数据 |

### 1.2 法务依据摘要（以法务部出具的《外部调证操作细则》为准绳，本系统仅做流程落地）

| 依据 | 要点 | 系统落地 |
| --- | --- | --- |
| 《网络安全法》第 28 条 | 公安机关、国家安全机关因维护国家安全和社会治安秩序需要可依法调取 | `requestor_type=PSB/NSB` 快速通道类型校验 |
| 《个人信息保护法》第 13 条第 1 款第 3 项 | 履行法定义务处理个人信息无需取得个人同意 | 披露目录决策的合法性前提字段 `legal_basis_cited` 必填 |
| 《个人信息保护法》第 63/64 条 | 履行个人信息保护职责部门的监督检查、约谈权 | `doc_type=inspection_notice` 检查支持流程（§6.11） |
| 《刑事诉讼法》调取证据制度 | 调取证据通知书等法定文书形式 | 文书类型目录与核验要素表（§6.2） |
| 《民事诉讼法》及各地法院律师调查令规程 | 法院调查令/律师持令调查 | `requestor_type=COURT` + 持令人核验 |
| 《未成年人保护法》《未成年人网络保护条例》 | 涉未成年人案件配合义务与未成年人信息特别保护并存 | 未成年人数据加签审批（§6.4）+ 交付脱敏强化 |
| 《互联网信息服务管理办法》等 | 配合主管部门监督检查的义务 | 检查资料包装配（§6.11） |

> ⚠️ 红线：本系统**不提供"万能查询"**。任何取数必须挂在某个 `legal_request` 下、经披露目录决策与审批、产出 `data_package` 并留痕；直连生产库的取数接口对本服务运维账号默认封禁（§12）。

### 1.3 与已有模块边界

| 模块 | 边界 |
| --- | --- |
| 未成年人数据隐私合规与数据主体权利请求处理引擎（DSR） | DSR 处理**用户本人/监护人发起**的查阅/更正/删除/导出；本系统处理**第三方法定主体发起**的调取/冻结/处置。两者共用"跨服务数据清除/导出适配器"的注册表思想，但适配器实现独立（本系统导出走"脱敏+审批后明文"路径，不走用户自助路径） |
| 数据脱敏规则引擎 | 本系统消费其脱敏能力完成"范围外字段自动遮蔽"；并向其注册 **ADT（Authorized Decrypt Token，授权解密令牌）**——即该文档注释中"公安协查授权上下文"的正式协议（§6.5.3） |
| 用户违规处罚执行与账号状态管控服务 | 平台自主处罚 vs 法定文书驱动处置。本系统通过其 `penalty_command` 幂等指令通道下发 ban/unban，指令来源标记 `source=LEGAL_ORDER`，台账双向可溯 |
| 积分获取规则计算与虚拟资产交易结算服务 / 会员服务 | 冻结/解冻/划扣的资产执行方；本系统持有指令状态机，结算服务提供幂等执行接口 |
| 未成年人支付风控与误充值自动识别退款引擎 | 该引擎 escalation_type=`COURT` 的诉讼应诉、`12315/12345` 行政投诉调档升级后，转入本系统 `doc_type=litigation_support` 受理 |
| 在线人工客服与工单系统 | 客服/工单收到疑似执法来函（罕见）时只做"转法务"动作（工单字段 `legal_escalated=true`），不自行取数 |
| 审计日志与操作追溯系统 | 本系统所有读写动作产生 `audit_source=LERMS` 审计事件，并要求其提供哈希链校验（防内部抵赖） |
| 教育行业监管合规与政策适配引擎 | 该引擎维护资质台账与政策清单；本系统 §6.11 检查支持流程消费其台账数据装配资料包 |
| 消息与推送服务 | 用户通知（§6.10）经统一通知中心下发，尊重通知偏好与频控，但法定通知走 `channel_priority=LEGAL` 强投递 |

### 1.4 设计目标

1. **期限合规**：来函要求答复期限前置展示、超期预警（72h/24h/超期三级）；常规请求收件→交付 P50 ≤ 72 小时（工作日）。
2. **最小必要**：字段级披露目录，默认给"部分同意+裁剪清单"，全量披露必须 L3。
3. **四眼分权**：受理/核验（Legal Ops）→ 审批（法务负责人/DPO/L3）→ 构建（系统+Ops）→ 出库复核（另一人）→ 交付（Ops），任何一人不得兼任同一单中"经办"与"审批/复核"。
4. **可证明性**：请求原件、核验记录、审批意见、取数快照、包清单哈希、回执扫描件全链归档，保存 ≥ 10 年（或法务要求的更长期限）。
5. **防伪造**：公文要素核验 + 官方渠道回拨（不用来函电话）双闸；疑似伪造转安全处置并留证。
6. **紧急通道**：涉儿童安全/生命危急的公安紧急查找，15 分钟内完成授权披露，事后 24 小时内补验。

### 2.2 四眼冲突规则（系统强制）

- 同一 `legal_request`：`assigned_legal_ops` ≠ 任一 `legal_approval.approver_id` ≠ `data_package.reviewed_by`。
- 构建人 `built_by` ≠ `reviewed_by`（§6.6）。
- 冻结双人：`legal.freeze.execute` 操作员 + 一名法务负责人会签（`co_signer_id` 必填）。
- 违反以上约束的写入返回 53608。

## 3. 请求类型与请求方模型

### 3.1 文书/请求类型（doc_type）

| 枚举 | 含义 | 典型文书 | 是否取数 | 是否动资产 | 是否动账号 |
| --- | --- | --- | --- | --- | --- |
| `evidence_obtain` | 调取证据 | 调取证据通知书 | ✅ | — | — |
| `investigation_order` | 法院调查令 | 律师调查令（附法院签发页） | ✅ | — | — |
| `assist_letter` | 协查函 | 各类协查函件 | ✅（通常窄范围） | — | — |
| `freeze_order` | 冻结/止付协助 | 冻结通知书/协助冻结财产通知书 | 可附调证 | ✅ | — |
| `unfreeze_order` | 解冻 | 解除冻结通知书 | — | ✅ | — |
| `deduct_order` | 划扣/执行 | 生效裁判文书+执行裁定 | 可附调证 | ✅ | — |
| `account_action_order` | 账号处置协助 | 责令封禁/解封通知 | — | — | ✅ |
| `inspection_notice` | 现场检查/约谈通知 | 监督检查通知书 | 资料包 | — | — |
| `litigation_support` | 应诉/行政投诉调档 | 平台作为被告/被投诉方（内部发起） | ✅ | — | — |

### 3.2 请求方类型（requestor_type）

`PSB`（公安）/`NSB`（国安）/`PROCURATORATE`（检察院）/`COURT`（法院，含律师持令）/`MARKET_REGULATOR`（市场监管）/`CAC`（网信）/`EDU_BUREAU`（教育主管）/`OTHER_GOV`（其他有权机关，逐单法务认定）。
非法定主体（律所直接来函、商业函件、私人诉求）→ **不受理**，转客服工单，登记 `not_accepted_ledger`（仅记录，不建单）。

### 3.3 优先级与紧急类型

| priority | 触发 | SLA |
| --- | --- | --- |
| `normal` | 默认 | 收件→交付 P50 ≤ 72h（工作日），不晚于来函答复期限前 24h |
| `high` | 文书标注"加急"或答复期 ≤ 5 自然日 | 收件→交付 ≤ 24h |
| `emergency` | `emergency_reason ∈ {child_safety, life_threatening}` 且 requestor_type=PSB/NSB | **15 分钟**内紧急披露（§6.7） |

## 4. 数据模型设计

### 4.1 ER 总览

```text
legal_request 1─N legal_request_target      （调取对象，可多个）
legal_request 1─N legal_request_document    （来函扫描件与证件件）
legal_request 1─1 legal_verification        （核验结论，可多版本→存 event）
legal_request 1─N legal_approval            （L1/L2/L3 审批记录）
legal_request 1─N data_package              （可多次构建/作废重建）
data_package 1─N data_package_item          （按域适配器取数明细）
data_package 1─1 delivery_record            （交付与回执）
legal_request 1─N user_notification         （用户通知/豁免登记）
legal_request 1─N asset_freeze_order        （冻结/解冻/划扣指令）
legal_request 1─N account_action_record     （账号处置协助记录）
legal_request 1─N legal_request_event       （append-only 事件流）
data_disclosure_catalog                     （字段级披露目录，配置表）
transparency_report_snapshot                （透明度报告快照）
```

### 4.2 数据库 DDL（PostgreSQL）

```sql
-- ============================================================
-- LERMS schema：lerms.*
-- 主键规范：带业务前缀的 ULID（lreq_/ltgt_/ldoc_/lver_/lapr_/lpkg_/lpi_/ldlv_/lunf_/lfo_/laar_/lev_）
-- ============================================================

CREATE TABLE lerms.legal_request (
    id                  VARCHAR(40) PRIMARY KEY,              -- lreq_01J...
    case_no             VARCHAR(120) NOT NULL,                -- 来函文号（幂等键）
    doc_type            VARCHAR(32)  NOT NULL,                -- §3.1 枚举
    requestor_type      VARCHAR(32)  NOT NULL,                -- §3.2 枚举
    requestor_name      VARCHAR(200) NOT NULL,                -- 机关全称
    requestor_dept      VARCHAR(200),                         -- 办案单位/庭室
    officer_name        VARCHAR(64)  NOT NULL,                -- 办案人/持令人
    officer_cert_no_enc BYTEA,                                -- 证件号（AES-GCM 加密存储）
    contact_phone_enc   BYTEA,                                -- 来函联系方式（加密，仅核验用）
    legal_basis_cited   TEXT         NOT NULL,                -- 文书引用的法律依据（原文）
    scope_summary       JSONB        NOT NULL,                -- 原始范围描述（时间窗/对象/字段，人工结构化）
    answer_deadline     DATE,                                 -- 文书要求答复期限
    priority            VARCHAR(16)  NOT NULL DEFAULT 'normal',
    emergency_reason    VARCHAR(32),                          -- child_safety/life_threatening/NULL
    received_channel    VARCHAR(32)  NOT NULL,                -- mail/email/online_portal/onsite
    status              VARCHAR(32)  NOT NULL,                -- §5.1 主状态机
    current_step        VARCHAR(48),                          -- 人机分工当前步骤提示
    assigned_legal_ops  VARCHAR(64)  NOT NULL,                -- 经办人 adminId
    reject_reason       TEXT,
    supplement_reason   TEXT,
    closed_at           TIMESTAMPTZ,
    version             INT          NOT NULL DEFAULT 0,      -- 乐观锁
    created_at          TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ  NOT NULL DEFAULT now(),
    CONSTRAINT uq_legal_case_no UNIQUE (case_no),
    CONSTRAINT ck_priority CHECK (priority IN ('normal','high','emergency'))
);
CREATE INDEX idx_lreq_status_dl ON lerms.legal_request(status, answer_deadline);

CREATE TABLE lerms.legal_request_target (
    id             VARCHAR(40) PRIMARY KEY,
    request_id     VARCHAR(40) NOT NULL REFERENCES lerms.legal_request(id),
    target_kind    VARCHAR(24) NOT NULL,   -- user/phone/device/order/asset/content
    target_value_enc BYTEA      NOT NULL,  -- 目标值（手机号/设备号/订单号原文，加密）
    resolved_ref   VARCHAR(64),            -- 解析后的内部主键（user_id 等），多义时为空
    resolve_status VARCHAR(16) NOT NULL DEFAULT 'pending',  -- pending/resolved/ambiguous/not_found
    ambiguity_note JSONB,                  -- 多候选列表 [{userId,nickname,grade,lastActiveAt}]
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE lerms.legal_request_document (
    id                VARCHAR(40) PRIMARY KEY,
    request_id        VARCHAR(40) NOT NULL REFERENCES lerms.legal_request(id),
    doc_kind          VARCHAR(24) NOT NULL,  -- main_letter/officer_cert/seal_page/ruling/attachment
    file_key          VARCHAR(200) NOT NULL, -- 对象存储 key（legal-request/ 私有桶，禁外链）
    sha256            CHAR(64)     NOT NULL,
    virus_scan_status VARCHAR(16)  NOT NULL DEFAULT 'pending', -- pending/clean/infected
    uploaded_by       VARCHAR(64)  NOT NULL,
    created_at        TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE lerms.legal_verification (
    id                VARCHAR(40) PRIMARY KEY,
    request_id        VARCHAR(40) NOT NULL REFERENCES lerms.legal_request(id),
    verifier_id       VARCHAR(64) NOT NULL,
    item_results      JSONB NOT NULL,  -- 要素核验明细（§6.2.1 结构）
    callback_attempt  JSONB,           -- 官方回拨记录（§6.2.2 结构）
    risk_score        NUMERIC(5,2) NOT NULL,
    result            VARCHAR(24) NOT NULL, -- passed/manual_review/failed_suspected_forgery
    failed_items      JSONB,
    verified_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE lerms.legal_approval (
    id              VARCHAR(40) PRIMARY KEY,
    request_id      VARCHAR(40) NOT NULL REFERENCES lerms.legal_request(id),
    level           SMALLINT NOT NULL,      -- 1/2/3
    approver_id     VARCHAR(64) NOT NULL,
    decision        VARCHAR(16) NOT NULL,   -- approve/partial/reject/supplement
    partial_fields  JSONB,                  -- partial 时：被裁剪字段路径列表+理由
    involves_minor  BOOLEAN NOT NULL DEFAULT false, -- 目标含未成年人 → 强制 L2
    opinion         TEXT,
    decided_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 字段级披露目录（配置表，运营于管理后台维护，含版本）
CREATE TABLE lerms.data_disclosure_catalog (
    id              BIGSERIAL PRIMARY KEY,
    domain          VARCHAR(32) NOT NULL,   -- user/order/learning/ai_conversation/points/device_log/content
    field_path      VARCHAR(128) NOT NULL,  -- 如 user.real_name / ai_conversation.content / points.balance
    sensitivity     VARCHAR(8)  NOT NULL,   -- L1/L2/L3/L4（§6.3.2 定义）
    disclosure_rule JSONB NOT NULL,         -- 决策矩阵：[{requestorType,docType,requiredLevel,mask?}]
    is_active       BOOLEAN NOT NULL DEFAULT true,
    version         INT NOT NULL,
    effective_from  TIMESTAMPTZ NOT NULL,
    UNIQUE (domain, field_path, version)
);

CREATE TABLE lerms.data_package (
    id               VARCHAR(40) PRIMARY KEY,
    request_id       VARCHAR(40) NOT NULL REFERENCES lerms.legal_request(id),
    build_no         SMALLINT NOT NULL,
    status           VARCHAR(16) NOT NULL,   -- building/built/reviewed/delivered/invalidated
    manifest_sha256  CHAR(64),               -- 清单文件哈希（交付核验）
    item_count       INT,
    total_size_bytes BIGINT,
    package_file_key VARCHAR(200),           -- 加密包对象存储 key
    encryption_fp    CHAR(64),               -- 接收方公钥指纹 / 一次性密钥封装指纹
    built_by         VARCHAR(64) NOT NULL,
    reviewed_by      VARCHAR(64),
    review_diff      JSONB,                  -- 与上一 build 的差异（重建场景）
    built_at         TIMESTAMPTZ,
    reviewed_at      TIMESTAMPTZ,
    UNIQUE (request_id, build_no)
);

CREATE TABLE lerms.data_package_item (
    id                VARCHAR(40) PRIMARY KEY,
    package_id        VARCHAR(40) NOT NULL REFERENCES lerms.data_package(id),
    target_ref        VARCHAR(64) NOT NULL,   -- user_id / order_id ...
    domain            VARCHAR(32) NOT NULL,
    source_adapter    VARCHAR(48) NOT NULL,   -- §6.5.2 适配器编码
    query_snapshot    JSONB NOT NULL,         -- 取数查询快照（含时间窗），复现依据
```

## 5. 状态机设计

### 5.1 主状态机（legal_request.status）

```text
                    ┌──────────(紧急通道旁路，§6.7)──────────┐
                    ▼                                        │
RECEIVED → VERIFYING → SUPPLEMENTING ──(补正后重验)──→ VERIFYING
              │  │                                        │
              │  ├──(核验不通过/疑似伪造)──→ REJECTED      │
              │  └──(核验通过)──→ L1_REVIEWING             │
              │                      │                     │
              │                      ├─(补充材料)─→ SUPPLEMENTING
              │                      ├─(驳回)───→ REJECTED │
              │                      ├─(需L2)──→ L2_REVIEWING
              │                      │             ├─(需L3)→ L3_REVIEWING
              │                      │             └─(通过)─┐│
              │                      ├─(直接通过)──→ APPROVED
              │                      └─(部分同意,partial)→ APPROVED（携带裁剪清单）
              ▼
          EXTRACTING → OUTPUT_REVIEW → DELIVERING → DELIVERED → CLOSED
              │             │(差异不通过)→ invalidated → EXTRACTING(重建)
              └─(取数失败可重试3次)→ APPROVED
任意活跃态 ──(请求方书面撤回)──→ WITHDRAWN
REJECTED/WITHDRAWN/CLOSED 为终态；CLOSED 需：已交付 或 无取数义务，且回执齐备、通知决策完成
```

### 5.2 迁移守卫表

| 迁移 | 前置条件（全部满足） | 执行者 |
| --- | --- | --- |
| RECEIVED→VERIFYING | 主文书件上传且病毒扫描 clean；officer_name/case_no/legal_basis_cited 齐备 | Ops |
| VERIFYING→SUPPLEMENTING | 核验项存在 `missing` 且非伪造特征 | Ops |
| VERIFYING→REJECTED | 核验不通过（无管辖/文书形式重大瑕疵）+ reject_reason 必填 | 法务负责人 |
| VERIFYING→L1_REVIEWING | verification.result=passed **或** manual_review 已附人工复核意见；`callback_attempt.conclusion=confirmed`（紧急通道除外，§6.7 事后补） | 系统 |
| L1_REVIEWING→L2_REVIEWING | decision=approve/partial 且（涉及 L3 字段 或 involves_minor=true 或 doc_type∈{freeze_order,deduct_order}） | 系统 |
| L2_REVIEWING→L3_REVIEWING | 存在 L4 字段申请 或 全量披露（未裁剪任何请求字段） | 系统 |
| *→APPROVED | 最高级审批 decision∈{approve,partial}；四眼校验通过；partial_fields 已回写 scope | 系统 |
| APPROVED→EXTRACTING | 全部 target resolve_status∈{resolved,not_found}（ambiguous 必须先人工裁决） | Ops |
| EXTRACTING→OUTPUT_REVIEW | package.status=built 且 manifest_sha256 非空 | 系统 |
| OUTPUT_REVIEW→DELIVERING | reviewed_by≠built_by 且 review 通过 | 复核人 |
| DELIVERING→DELIVERED | delivery.delivered_at 非空 + receipt_evidence_key 或 tracking_no | Ops |
| DELIVERED→CLOSED | receipt_status∈{received,overdue→已登记说明} 且 user_notification 决策完成 | Ops |
| 活跃态→WITHDRAWN | 撤回函上传 + 法务负责人确认 | 法务负责人 |

> 所有迁移写 `legal_request_event`；非法迁移返回 53602。冻结单（asset_freeze_order）为**独立子状态机**，不随主单 CLOSED 而自动终态（冻结可持续至解冻文书到达）。

### 5.3 冻结指令子状态机

```text
pending_exec ──(执行成功)──→ active ──(unfreeze_order)──→ released
     │                        │──(deduct_order+L3)──→ deducted
     └─(执行失败:53612)──→ rejected │
                              └──(freeze_expire_at 到期且未续冻)──→ expired_guard
                                   （expired_guard：自动解冻+告警+法务复盘事件，防超期冻结）
```

## 6. 核心流程设计

### 6.1 受理登记

1. Ops 收件（线下函件扫描上传 / 法务邮箱自动转工单 / 线上协查平台下载），创建 `legal_request`。
2. 幂等：`case_no` 唯一约束；重复来函（同文号补寄）挂附件并返回已有单号（53619 幂等提示）。
3. 结构化 `scope_summary`：时间窗（默认最早 90 天，超范围需 L2 说明）、对象清单、请求字段清单（从文书誊录，宁可多录不可漏录——审批时裁剪）。
4. 非"有权机关"来件（律所直函等）：不建单，登记 `not_accepted_ledger` 并回复指引（走 DSR 或诉讼调查令通道）。

### 6.2 公文核验

#### 6.2.1 要素核验（系统辅助 + 人工确认）

| 核验项 | 权重 | 系统可判部分 |
| --- | --- | --- |
| 文号格式合规（发文字号规则按机关类型） | 15 | 正则库 + 历史文号查重 |
| 公章/签发页存在且清晰 | 20 | 附件 OCR 检测印章区域存在性 |
| 办案人证件信息完整（2 人或按当地规则） | 15 | 字段非空 |
| 法律依据引用明确且与请求类型匹配 | 15 | doc_type × legal_basis 关键词矩阵 |
| 管辖权/关联性（涉案与平台用户存在可指向对象） | 20 | target 可解析性预检 |
| 答复期限合理（≥3 个工作日；emergency 除外） | 10 | 日期计算 |
| 来函渠道可信（官方函件渠道/机要/EMS 公对公） | 5 | 渠道登记 |

评分 ≥ 85 → 建议 `passed`；60–85 → `manual_review`；< 60 或命中伪造特征（文号重复使用、印章图样与历史件哈希碰撞异常、话术模板与已知诈骗函件相似）→ `failed_suspected_forgery`。

#### 6.2.2 官方回拨核验（强制闸门）

- **回拨号码来源**：请求方机关**对外公开的官方电话**（内置机关黄页目录 + 每季度运营核对），**禁止使用来函所留电话**。
- 记录 `callback_attempt`：`{officialDirectorySource, dialedNumber, answeredBy, confirmedCaseNo(是/否/拒答), conclusion, calledAt}`。
- 常规单：`conclusion=confirmed` 前不得进入审批（守卫表）；emergency 旁路（§6.7）。
- 三次未接通 → 转机要/发函求证，SLA 挂起并计入期限预警。

#### 6.2.3 疑似伪造处置

`failed_suspected_forgery` → 单据锁定，事件 `LEGAL_SUSPECTED_FORGERY` 推安全团队；原件与附件转私有证据桶；**不向"请求方"透露系统判断**；同步风控画像机关黑名单库（供后续受理预警）；涉嫌违法的由法务决定是否报案。

### 6.3 范围解析与披露目录决策

#### 6.3.1 目标解析（target resolution）

- 输入：手机号/身份证号（脱敏存储）/设备号/订单号/用户昵称+学段等。
- 解析服务调用用户域只读接口（`user.resolve.byPhone` 等，均带 ADT 审计）。
- 多候选（`ambiguous`）→ 生成候选清单（昵称、年级、注册时间、最近活跃）供**请求方书面确认**或按文书上下文人工裁决；禁止"全都要"式解析。

#### 6.3.2 敏感度分级（Field Sensitivity）

| 级别 | 定义 | 示例字段 |
| --- | --- | --- |
| L1 | 一般注册与状态信息 | user.id、nickname、grade、created_at、account_status |
| L2 | 身份与交易信息 | real_name、cert_no、phone、address、orders、points.balance、consume records |
| L3 | 学习行为与通信内容 | ai_conversation.content、mistake_records、learning_sessions、家长绑定关系 |
| L4 | 默认禁止披露 | 生物识别特征（声纹向量）、明文密码散列盐、第三方授权 token、其他用户数据（除非同案调取） |

#### 6.3.3 披露目录决策（DisclosureDecisionEngine）

对 scope 内每个字段查 `data_disclosure_catalog.disclosure_rule`：

```text
rule = { requestorType: [...], docType: [...], requiredLevel: 1|2|3, mask: "none|partial|full" }
匹配优先级：精确匹配 > 通配；无匹配规则 → 按 L4 处理（宁拒不滥）
```

决策结果四类：
- `ALLOW`：requiredLevel ≤ 当前已获审批级 → 入包；
- `NEEDS_L2/L3`：提升审批级；
- `ALLOW_WITH_MASK`：入包但按脱敏规则遮蔽（如证件号仅披露前 3 后 4）；
- `DENY`：不在任何规则内或 L4 → 记入 `partial_fields`，回复请求方"该字段不属于可依法调取范围"并说明依据。

> 时间窗约束：行为类数据（L3）默认披露窗口 ≤ 案件相关区间，最宽 180 天，超出需 L2 书面理由。

### 6.4 审批流

```text
L1（法务负责人）：形式合规 + 范围合理性初判；可 partial（裁剪字段）
L2（DPO/安全负责人）：涉 L3 字段、未成年人数据、时间窗>180d、freeze/deduct 单
L3（CEO 授权人）：L4 字段例外、全量披露、划扣执行
```

- 审批任务经管理后台工作台 + 企业 IM 卡片提醒；`answer_deadline - 72h` 未完成 L1 → 升级通知法务负责人；`-24h` → 升级 DPO + CTO；超期 → 事件 `LEGAL_RECEIPT_OVERDUE` 同类告警通道，计入法务 SLA 看板。
- 未成年人目标（grade 段 < 高中毕业年龄上限判定或实名年龄 < 18）：强制 L2 且 `involves_minor=true`，DPO 需评估"对该未成年人的保护影响"并写入 opinion。

### 6.5 取数与打包（DataPackageBuilder）

#### 6.5.1 构建流程

```text
APPROVED 单 → 生成 build_no → 逐 target × domain 调适配器取数
→ 字段过滤（scope ∩ catalog 允许集）→ 范围外字段强制脱敏
→ 生成 query_snapshot + extraction_log（含执行人/时间/SQL指纹）
→ 汇总 manifest（每条记录 SHA-256）→ 加密打包 → 状态 built
```

#### 6.5.2 数据源适配器

| adapter | 数据域 | 数据通道 | 说明 |
| --- | --- | --- | --- |
| `user-profile-adapter` | user | 用户服务只读 API | 身份与档案 |
| `order-adapter` | order | 支付域只读副本 | 订单与流水 |
| `learning-adapter` | learning/ai_conversation | 学习库只读 API + ClickHouse | 行为与对话（时间窗过滤在服务端执行） |
| `points-adapter` | points | 结算服务对账接口 | 余额与流水 |
| `content-adapter` | content | 内容服务 | 用户 UGC（学习圈帖文等） |
| `device-log-adapter` | device_log | 风控库 | 登录设备与 IP（IP 属 L2，需 mask 规则） |

> 适配器全部走**只读副本/只读账号**；生产主库账号对本服务不可见（§12）。

#### 6.5.3 ADT 授权解密令牌（对接《数据脱敏规则引擎》）

脱敏引擎中所有密文字段的解密入口统一收敛为 `AuthorizedDecryptContext`。本系统签发 ADT：

```json
{
  "adt_id": "adt_01J...",
  "package_id": "lpkg_01J...",
  "request_id": "lreq_01J...",
  "field_scope": ["user.real_name", "user.phone"],
  "target_refs": ["u_10086"],
  "expires_at": "2026-08-20T12:00:00Z",
  "issuer": "lerms-service",
  "signature": "Ed25519(...)"
}
```

- ADT 一次性、绑定 package_item、短时效（构建期 + 24h）；脱敏引擎验签并记录 `decrypt_audit`，与 `decrypt_tokens` 双向可对账。
- 该协议即《数据脱敏规则引擎》"公安协查授权上下文"注释的正式实现；DSR 自助导出走独立的 `dsr_context`，两者互不通用。

#### 6.5.4 打包加密

- 一次性对称密钥 AES-256-GCM 加密包体；密钥以请求方提供的**公钥**（法院/公安在线平台常见）封装，无公钥则线下口交换（双人分持半口令，登记 `encryption_fp`）。
- 包内结构：`/manifest.json`（清单+每文件 SHA-256）+ `/data/*.json|csv` + `/README.txt`（字段口径说明，含"部分字段依法未予提供"的 partial 清单）。

### 6.6 出库复核与交付

1. **复核**（reviewed_by ≠ built_by）：逐 item 核对 ①仅含审批允许字段 ②脱敏生效 ③时间窗正确 ④无其他用户数据串包。任一不通过 → 包 `invalidated`，回 EXTRACTING 重建，差异写 `review_diff`。
2. **交付方式**：`onsite_handover`（当面+签收单扫描）/ `courier_secret`（机要/EMS 公对公）/ `online_portal`（政法机关在线调证平台，附包哈希）/ `secure_email`（S/MIME，仅限已建信任的机关）。
3. **回执**：`receipt_due_date = delivered_at + 7d`；超期未回收执 → 定时任务置 `receipt_status=overdue` 并每日提醒经办；回执扫描件与包哈希一并归档。
4. 用户通知决策（§6.10）须在交付前完成（豁免或发送），守卫迁移 DELIVERED。

### 6.7 紧急通道（emergency）

适用：`requestor_type ∈ {PSB, NSB}` + `emergency_reason ∈ {child_safety, life_threatening}`（如未成年人失踪紧急查找、危及生命案件）。

```text
T+0min   Ops 标记 emergency → 旁路：跳过回拨/审批（仅要素形式核验 + 电话录音双通道）
T+2min   按"紧急白名单目录"（仅 L1/L2 字段：身份、设备、最近定位类登录 IP、联系方式）构建小包
T+5min   DPO/法务负责人 通讯工具即时会签（双击确认，留录音/截图证据）
T≤15min  交付（在线平台/电子送达）→ 事件 LEGAL_EMERGENCY_TRIGGERED
T+24h    事后补验：回拨确认 + 补全核验与审批记录（POST_VERIFIED）
         补验失败（POST_FAILED）→ 事件 P1 告警，法务 24h 内书面报告请求方机关并启动内部复盘
```

- 紧急白名单硬编码于披露目录（`rule.emergencyOnly=true`），L3/L4 字段**永不**走紧急通道。
- 每次紧急通道使用强制复盘会（≤3 个工作日），复盘结论写 `legal_request_event`。

### 6.8 司法冻结 / 解冻 / 划扣

| 动作 | 前置 | 执行 |
| --- | --- | --- |
| 冻结 `freeze_order` | L2 审批 + 财务会签 | 调结算服务 `freezeAssets(userId, kind, amount, idempotencyKey=freezeId)`：积分账户余额→司法冻结子账户；会员未消费权益→标记 HOLD；`pending_refund` 类挂起 |
| 部分冻结 | 余额 < 请求额 | 冻结实际余额，status=partial，差额在复函中说明 |
| 解冻 `unfreeze_order` | 原冻结单匹配（53613 防错单） | 逆向释放；若用户账号已注销→按退款服务路径原路退回并留痕 |
| 划扣 `deduct_order` | **生效裁判文书**（非协助执行通知）+ L3 | 从司法冻结子账户划扣至监管/法院指定账户（对接支付对账服务走专用出金通道）；无冻结余额时转"待执行负债"台账，从后续充值/退款优先抵扣 |
| 到期保护 | freeze_expire_at（默认 +90d，可按文书续冻） | 到期未续冻 → `expired_guard` 自动解冻 + P2 告警（防止超期冻结侵害用户权益） |

冲突处理：冻结期间用户主动消费 → 结算服务按冻结子账户优先扣减规则拒绝/降额，错误码由结算域返回；本系统只维护指令状态机并对账（每日冻结台账 vs 结算服务余额快照，差异 → 53612 类告警工单）。

### 6.9 账号处置协助

- `account_action_order`（责令封禁/解封、内容下架）：经 L1 审批后向《用户违规处罚执行与账号状态管控服务》下发 `penalty_command`，`source=LEGAL_ORDER`，`external_ref=request_id`，复用其幂等执行、Token 吊销、设备黑名单联动与台账。
- 解封令：同样走 command（`action=unban`），处罚服务校验无其他并行处罚时才执行，冲突时回执"存在其他独立处罚"由法务复函说明。
- 执行结果回写 `account_action_record.result`，闭环进主单 CLOSED 条件。

### 6.10 用户通知与豁免

- 原则：数据披露后应通知目标用户（站内信 + 家长可见，经统一通知中心 `channel_priority=LEGAL`）。
- 豁免登记（`waiver_ground` 必填）：法律明确禁止 / 有碍侦查办案（需请求方文书中注明保密要求或法务负责人认定）/ 涉及其他第三人重大利益。
- 通知文案模板法务预审（含"你的部分信息因法定事由被依法提供，详情可依法行使权利"），不透露侦查细节。
- 家长可见性：目标为未成年人时，通知同时触达监护人（复用家长绑定关系），但冻结/涉案类以法务意见为准。

### 6.11 现场检查与约谈支持（inspection_notice）

- 资料包自动装配（只读、盖章版）：资质与备案台账（消费《教育行业监管合规与政策适配引擎》）、未成年人保护机制说明、数据处理活动记录（消费 DSR 服务同意台账）、内容审核制度与拦截数据、安全评估报告索引。
- 装配产物为 `doc_type=inspection_notice` 专用只读包，**不包含任何个体用户数据**（个体数据仍须单独调证文书）。
- 陪同登记：参加人、时间、提出材料清单、承诺时限 → 转 TODO 跟踪至闭环。

### 8.1 公文核验评分器（Kotlin）

```kotlin
// lerms-verification/src/main/kotlin/VerificationScorer.kt
data class VerifyItem(val key: String, val passed: Boolean, val missing: Boolean = false)
data class ScoreResult(val score: BigDecimal, val outcome: Outcome) {
    enum class Outcome { AUTO_PASS, MANUAL_REVIEW, SUSPECTED_FORGERY }
}

class VerificationScorer(
    private val caseNoRegistry: CaseNoRegistry,        // 文号查重
    private val sealOcr: SealRegionDetector,           // 印章区域 OCR
    private val fraudSignatures: FraudSignatureStore   // 已知伪造特征库
) {
    fun score(req: LegalRequest, docs: List<LegalRequestDocument>): ScoreResult {
        val items = mutableListOf<VerifyItem>()
        items += item("case_no_format", CaseNoPattern.of(req.requestorType).matches(req.caseNo))
        items += item("case_no_unique", !caseNoRegistry.exists(req.caseNo, exclude = req.id))
        items += item("seal_present", docs.any { sealOcr.hasSeal(it.fileKey) })
        items += item("officer_complete", req.officers.size >= 2)
        items += item("legal_basis_match",
            BasisMatrix.of(req.docType).matchesAny(req.legalBasisCited))
        items += item("deadline_reasonable",
            req.priority == EMERGENCY || req.answerDeadline >= todayPlusWorkDays(3))
        // 命中伪造特征直接降级，不参与加权
        if (fraudSignatures.matchAny(req, docs)) return ScoreResult(ZERO, SUSPECTED_FORGERY)
        val s = WEIGHTS.entries.filter { (k, _) -> items.first { it.key == k }.passed }
            .map { it.value }.sum().toBigDecimal()
        return when {
            s >= 85 -> ScoreResult(s, AUTO_PASS)
            s >= 60 -> ScoreResult(s, MANUAL_REVIEW)
            else    -> ScoreResult(s, MANUAL_REVIEW)  // <60 且无伪造特征：转人工+补充材料评估
        }
    }
}
```

### 8.2 披露决策引擎（Java）

```java
// lerms-core/src/main/java/DisclosureDecisionEngine.java
public class DisclosureDecisionEngine {

    private final DisclosureCatalogRepo catalogRepo;   // data_disclosure_catalog 缓存

    public Decision decide(ScopeField field, LegalRequest req, int approvedLevel) {
        CatalogEntry rule = catalogRepo.findActive(field.domain(), field.path())
            .orElse(CatalogEntry.denyByDefault(field));          // 无规则 = 按 L4 拒绝

        Optional<RuleMatch> m = rule.match(req.getRequestorType(), req.getDocType());
        if (m.isEmpty()) return Decision.deny(field, "无适用披露规则，按默认禁止处理");

        RuleMatch rm = m.get();
        if (rm.requiredLevel() > approvedLevel)
            return Decision.needsHigherApproval(field, rm.requiredLevel());

        if (rule.sensitivity() == Sensitivity.L4)
            return Decision.deny(field, "L4 字段默认禁止披露，如属必要须逐字段 L3 例外审批");

        return switch (rm.mask()) {
            case NONE   -> Decision.allow(field, MaskPolicy.none());
            case PARTIAL -> Decision.allow(field, MaskPolicy.partial(field.path())); // 如证件号前3后4
            case FULL   -> Decision.allow(field, MaskPolicy.full());                 // 仅存在性证明
        };
    }
}
```

### 8.3 数据包构建器（Java，核心节选）

```java
// lerms-core/src/main/java/DataPackageBuilder.java
@Service
public class DataPackageBuilder {

    private final Map<String, SourceAdapter> adapters;      // §6.5.2
    private final MaskingService masking;                    // 数据脱敏引擎客户端
    private final AdtSigner adtSigner;                       // §6.5.3

    @Transactional
    public DataPackage build(LegalRequest req, ApprovedScope scope) {
        DataPackage pkg = repo.create(req.id(), nextBuildNo(req));

        for (TargetRef t : scope.resolvedTargets()) {
            for (DomainScope ds : scope.domainsFor(t)) {
                SourceAdapter adapter = adapters.get(ds.adapter());
                // 1) 只读副本取数 + 时间窗服务端过滤
                SourceRows rows = adapter.fetch(t, ds.timeWindow(), ds.fieldPaths());

                // 2) 字段过滤：scope ∩ 目录允许集；范围外字段强制遮蔽（防适配器多取）
                FieldFilterResult ffr = FieldFilter.apply(rows, ds.fieldPaths());
                masking.maskBatch(ffr.outOfScopeRows(), MaskPolicy.full());

                // 3) ADT：对密文字段（cert_no/phone 等加密列）申请授权解密
                List<String> adts = ffr.encryptedFields().stream()
                    .map(f -> adtSigner.issue(pkg.id(), t, f, ttl = Duration.ofHours(24)))
                    .toList();

                // 4) 明细落库：查询快照 + 遮蔽清单 + 取数日志
                pkg.addItem(ItemSnapshot.of(t, ds, ffr, adts, adapter.auditLogRef()));
            }
        }
        // 5) manifest（每记录 SHA-256）→ AES-256-GCM 加密 → 对象存储
        PackageArtifact art = ArtifactPacker.packAndEncrypt(pkg);
        pkg.markBuilt(art.manifestSha256(), art.sizeBytes(), art.fileKey(), art.keyFp());
        events.out(LEGAL_PACKAGE_BUILT, pkg);
        return pkg;
    }
}
```

```java
// lerms-core/src/main/java/AssetFreezeSaga.java
public class AssetFreezeSaga {

    public FreezeResult execute(FreezeOrder fo, LegalRequest req) {
        // 幂等：freezeId 即 idempotencyKey
        if (settlement.isExecuted(fo.id())) return FreezeResult.replayed(fo.id());

        try {
            SettlementTx tx = settlement.freezeAssets(
                SettlementFreezeCmd.builder()
                    .freezeId(fo.id()).userId(fo.targetUserId())
                    .assetKind(fo.assetKind()).amount(fo.amount())
                    .expireAt(defaultExpire(fo, Duration.ofDays(90)))
                    .build());
            audit.write(LEGAL_ASSET_FROZEN, fo, tx);
            return FreezeResult.active(tx);
        } catch (InsufficientBalanceException e) {          // 部分冻结
            SettlementTx tx = e.partialTx();
            fo.markPartial(tx.frozenAmount());
            return FreezeResult.partial(tx);
        } catch (SettlementUnavailableException e) {
            fo.markRetryPending();                          // 退避重试×3 → 53612 告警工单
            throw new LermsException(53612, "结算服务不可用，冻结进入重试", e);
        }
    }
}
```

```kotlin

class EmergencyPathOrchestrator(
    private val scorer: VerificationScorer,
    private val imSign: InstantCoSignClient,      // DPO+法务负责人 即时会签
    private val builder: DataPackageBuilder,

    fun run(req: LegalRequest): EmergencyOutcome {

        val scope = ApprovedScope.emergencyWhitelist(req)

        delivery.deliverOnlinePortal(pkg, receiptRequired = false)

        scheduler.schedule(Duration.ofHours(24)) { postVerification(req.id) }
```

## 12. 安全与防滥用红线

1. **无万能查询**：所有取数必须挂 `legal_request` + 审批 + package；`lerms-service` 运维账号无业务库直连权限，适配器专用只读账号定期轮转（90 天）。
2. **请求即审计**：核验/审批/构建/复核/交付/冻结全链 `legal_request_event` + 独立审计哈希链；审计员只读角色可独立核查。
3. **来函原件防篡改**：上传即 SHA-256 固化，任何修改产生新版本记录；原件桶禁删（生命周期 10 年+）。
4. **最小知悉面**：管理后台 legal 域默认隐藏手机号/证件号明文（掩码展示），明文仅构建期经 ADT 解密进包，不在前端回显。
5. **伪造防线**：官方黄页回拨（禁用来函号码）+ 文号查重 + 伪造特征库；伪造黑名单进风控画像。
6. **未成年人特别保护**：involves_minor 强制 L2；交付包对未成年人证件信息默认增强脱敏（前 1 后 2），除非文书明确要求全文。
7. **紧急通道刚性边界**：白名单目录硬编码（仅 L1/L2 字段）、PSB/NSB 限定、双签与录音、24h 补验，四者缺一即拒绝进入紧急通道。
8. **对外沟通纪律**：系统所有复函模板由法务维护；Ops 不得自行起草实质回复（复函生成器仅做占位填充）。

## 15. 配置项与灰度
