# 服务端-教育平台资源使用量监控与成本优化决策引擎 详细设计

## 1. 模块概述

### 1.1 功能定位

本引擎是 PrimeTop 平台基础设施层的核心成本治理组件，负责对全平台计算资源、存储资源、网络带宽、AI 模型调用量、第三方服务调用量等多维度资源进行实时采集、聚合、分析，并以成本视角输出监控大盘、异常预警和优化决策建议，帮助技术团队和运营团队在保障用户体验的前提下持续降低单用户服务成本。

### 1.2 与已有模块的边界

| 已有模块 | 职责范围 | 本引擎差异 |
|---|---|---|
| 成本管理与优化系统-详细设计 | 全局成本管理策略、预算编制流程、成本意识文化 | 本引擎是**技术实现层**，负责实时数据采集、指标计算、自动决策执行 |
| 服务端-AI模型调用Token计量与成本归集核算服务 | AI 模型 Token 级别的计量和归集 | 本引擎覆盖**全量资源类型**（CPU/内存/存储/带宽/第三方API），AI Token 仅是其中一个维度 |
| 服务端-统一计费账单中心与实时用量核扣引擎 | 面向用户的计费、扣费、账单生成 | 本引擎面向**平台内部**，关注成本而非收入 |
| 服务端-存储资源统一生命周期管理与过期数据自动清理引擎 | 存储侧的数据生命周期管理 | 本引擎监控存储**费用**并输出存储优化建议，不直接执行清理 |

### 1.3 设计目标

1. **实时可见**：5 秒级资源用量指标采集，1 分钟级成本大盘刷新。
2. **精准归因**：将平台总成本按用户、功能模块、学科、模型供应商等维度精准分摊。
3. **智能决策**：基于历史趋势和实时负载，自动输出优化建议并支持一键执行。
4. **预算守护**：支持多级预算阈值，超限时自动触发降级策略或通知。
5. **可扩展**：新增资源类型或计费维度时无需改代码，配置化接入。

## 3. 数据模型设计

### 3.1 资源指标原始数据 (resource_metric_raw)

存储从各数据源采集的原始指标，按时间分区。

```sql
CREATE TABLE resource_metric_raw (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    metric_time     DATETIME(3) NOT NULL COMMENT '指标采集时间(毫秒精度)',
    metric_type     VARCHAR(64) NOT NULL COMMENT '指标类型: CPU/MEMORY/DISK/NETWORK/AI_TOKEN/THIRD_PARTY/CUSTOM',
    metric_name     VARCHAR(128) NOT NULL COMMENT '指标名称: 如 ai_token_input, cpu_usage_percent',
    metric_value    DECIMAL(20,6) NOT NULL COMMENT '指标原始值',
    metric_unit     VARCHAR(32) NOT NULL COMMENT '计量单位: percent/bytes/tokens/count/cny_usd',
    source_system   VARCHAR(64) NOT NULL COMMENT '来源系统: k8s/ai_gateway/stripe/aliyun_oss...',
    source_entity   VARCHAR(128) NOT NULL COMMENT '来源实体: pod名/模型名/服务名/bucket名',
    
    -- 多维度标签(JSON)
    dim_tags        JSON NOT NULL COMMENT '维度标签: {"user_id":"...","module":"ai_tutor","subject":"math","model":"gpt-4o","region":"cn-east-1"}',
    
    ingestion_time  DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
    
    INDEX idx_time_type (metric_time, metric_type),
    INDEX idx_source (source_system, source_entity),
    INDEX idx_time_name (metric_time, metric_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
PARTITION BY RANGE (TO_DAYS(metric_time)) (
    PARTITION p_20260801 VALUES LESS THAN (TO_DAYS('2026-09-01')),
    PARTITION p_20260901 VALUES LESS THAN (TO_DAYS('2026-10-01')),
    -- 后续按月自动新增分区
    PARTITION p_max VALUES LESS THAN MAXVALUE
);
```

### 3.2 聚合成本数据 (cost_aggregation)

按多维度聚合后的成本数据，供大盘展示和趋势分析。

```sql
CREATE TABLE cost_aggregation (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    stat_period     VARCHAR(16) NOT NULL COMMENT '统计周期: MINUTE/HOUR/DAY/WEEK/MONTH',
    period_start    DATETIME NOT NULL COMMENT '周期开始时间',
    period_end      DATETIME NOT NULL COMMENT '周期结束时间',
    
    -- 维度列
    dim_module      VARCHAR(64) DEFAULT 'ALL' COMMENT '功能模块维度: ai_tutor/photo_search/sync_class/essay/mistake/...',
    dim_subject     VARCHAR(32) DEFAULT 'ALL' COMMENT '学科维度: math/chinese/english/physics/...',
    dim_model       VARCHAR(64) DEFAULT 'ALL' COMMENT 'AI模型维度: gpt-4o/claude-3.5/deepseek/...',
    dim_user_tier   VARCHAR(32) DEFAULT 'ALL' COMMENT '用户等级维度: free/monthly/yearly/family/...',
    dim_region      VARCHAR(32) DEFAULT 'ALL' COMMENT '区域维度: cn-east/cn-south/cn-north/...',
    
    -- 资源类型成本
    cost_ai_token       DECIMAL(14,4) DEFAULT 0 COMMENT 'AI Token 成本(CNY)',
    cost_compute        DECIMAL(14,4) DEFAULT 0 COMMENT '计算资源成本(CPU+内存)',
    cost_storage        DECIMAL(14,4) DEFAULT 0 COMMENT '存储成本',
    cost_network        DECIMAL(14,4) DEFAULT 0 COMMENT '网络带宽成本',
    cost_third_party    DECIMAL(14,4) DEFAULT 0 COMMENT '第三方服务成本',
    cost_total          DECIMAL(14,4) DEFAULT 0 COMMENT '总成本(CNY)',
    
    -- 业务指标(用于计算单次成本)
    biz_request_count   BIGINT DEFAULT 0 COMMENT '请求次数',
    biz_active_users    INT DEFAULT 0 COMMENT '活跃用户数(DAU维度)',
    biz_learn_minutes   INT DEFAULT 0 COMMENT '学习总分钟数',
    
    -- 衍生指标
    cost_per_request    DECIMAL(10,6) GENERATED ALWAYS AS (
        CASE WHEN biz_request_count > 0 
        THEN cost_total / biz_request_count ELSE 0 END
    ) STORED COMMENT '单次请求成本',
    cost_per_dau        DECIMAL(10,6) GENERATED ALWAYS AS (
        CASE WHEN biz_active_users > 0 
        THEN cost_total / biz_active_users ELSE 0 END
    ) STORED COMMENT '单DAU成本',
    cost_per_learn_hour DECIMAL(10,6) GENERATED ALWAYS AS (
        CASE WHEN biz_learn_minutes > 0 
        THEN cost_total / (biz_learn_minutes / 60.0) ELSE 0 END
    ) STORED COMMENT '单学习小时成本',
    
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_period_dim (stat_period, period_start, dim_module, dim_subject, dim_model, dim_user_tier, dim_region),
    INDEX idx_period (stat_period, period_start),
    INDEX idx_module_period (dim_module, stat_period, period_start)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.3 成本规则配置 (cost_rule)

可配置的成本计算规则，支持灵活的单价和分摊策略。

```sql
CREATE TABLE cost_rule (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    rule_code       VARCHAR(64) NOT NULL UNIQUE COMMENT '规则编码',
    rule_name       VARCHAR(128) NOT NULL COMMENT '规则名称',
    resource_type   VARCHAR(32) NOT NULL COMMENT '资源类型: AI_TOKEN/COMPUTE/STORAGE/NETWORK/THIRD_PARTY',
    
    -- 定价模型
    pricing_model   VARCHAR(32) NOT NULL COMMENT '定价模式: FLAT_RATE/TIERED/PER_UNIT/HOURLY',
    unit_price      DECIMAL(14,6) NOT NULL COMMENT '单价(CNY)',
    unit_metric     VARCHAR(64) NOT NULL COMMENT '计量指标: token_count/gb_hours/gb_transferred/cpu_core_hour',
    
    -- 分时定价(可选)
    off_peak_discount   DECIMAL(4,2) DEFAULT 0 COMMENT '低谷时段折扣(0-1)',
    off_peak_hours      VARCHAR(128) COMMENT '低谷时段: "22:00-08:00"',
    
    -- 分摊规则
    allocation_strategy VARCHAR(32) NOT NULL DEFAULT 'PROPORTIONAL' COMMENT '分摊策略: PROPORTIONAL/EVENLY/WEIGHTED/CUSTOM',
    allocation_tags  JSON COMMENT '分摊权重配置: {"ai_tutor":0.4,"photo_search":0.2,...}',
    
    -- 生效周期
    effective_from  DATETIME NOT NULL,
    effective_to    DATETIME,
    status          VARCHAR(16) DEFAULT 'ACTIVE' COMMENT 'ACTIVE/INACTIVE/ARCHIVED',
    
    created_by      VARCHAR(64),
    updated_by      VARCHAR(64),
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_type_status (resource_type, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.4 预算配置 (budget_config)

```sql
CREATE TABLE budget_config (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    budget_code     VARCHAR(64) NOT NULL UNIQUE COMMENT '预算编码',
    budget_name     VARCHAR(128) NOT NULL COMMENT '预算名称',
    budget_scope    VARCHAR(32) NOT NULL COMMENT '范围: PLATFORM/MODULE/MODEL/USER_TIER',
    scope_value     VARCHAR(64) NOT NULL COMMENT '范围值: ALL/ai_tutor/gpt-4o/free...',
    
    budget_period   VARCHAR(16) NOT NULL COMMENT '周期: DAILY/WEEKLY/MONTHLY',
    budget_amount   DECIMAL(14,4) NOT NULL COMMENT '预算金额(CNY)',
    currency        VARCHAR(8) DEFAULT 'CNY',
    
    -- 多级阈值(百分比)
    threshold_warn      DECIMAL(5,2) DEFAULT 70.00 COMMENT '预警阈值(%)',
    threshold_critical  DECIMAL(5,2) DEFAULT 90.00 COMMENT '严重阈值(%)',
    threshold_emergency DECIMAL(5,2) DEFAULT 100.00 COMMENT '紧急阈值(%)',
    
    -- 阈值触发动作
    action_warn        VARCHAR(64) DEFAULT 'NOTIFY' COMMENT '预警动作: NOTIFY/LOG',
    action_critical    VARCHAR(64) DEFAULT 'NOTIFY_THROTTLE' COMMENT '严重动作: NOTIFY_THROTTLE/AUTO_DOWNGRADE',
    action_emergency   VARCHAR(64) DEFAULT 'FORCE_DEGRADE' COMMENT '紧急动作: FORCE_DEGRADE/BLOCK',
    
    -- 降级目标配置
    degrade_target     JSON COMMENT '降级目标配置: {"model":"deepseek-v3","quality":"standard"}',
    
    status          VARCHAR(16) DEFAULT 'ACTIVE',
    effective_from  DATETIME NOT NULL,
    effective_to    DATETIME,
    
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_scope (budget_scope, scope_value, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 5.2 多维度成本聚合引擎

**核心思路**: 采用预计算 + 实时补充的混合模式。

```
预计算 (离线):
  - 每天 02:00 执行 T-1 全量聚合
  - 遍历 resource_metric_raw 的 T-1 数据
  - 按 dim_tags 中的维度字段 GROUP BY
  - 写入 cost_aggregation 表 (stat_period=DAY)

实时计算 (流式):
  - Flink 消费 Kafka 实时数据
  - 1分钟滚动窗口聚合
  - 写入 InfluxDB (realtime_cost_measurement)
  - 大盘查询时合并预计算 + 实时数据

查询合并:
  - 若查询范围包含今天: 
    DAY级数据 = 预计算(历史天) + 实时聚合(今天)
  - 否则直接查 cost_aggregation
```

**关键代码 — 聚合引擎:**

```java
@Service
public class CostAggregationEngine {
    
    private final CostAggregationRepository aggRepo;
    private final InfluxDBClient influxClient;
    private final CostRuleEngine ruleEngine;
    
    /**
     * 按指定维度组合聚合成本
     */
    public AggregationResult aggregate(
            Instant start, Instant end, 
            List<String> groupByDims,
            Map<String, String> filters) {
        
        // 1. 查询预计算数据
        List<CostAggregation> preAggregated = aggRepo.findByPeriodRangeAndFilters(
            start, end, groupByDims, filters
        );
        
        // 2. 如果范围包含今天，补充实时数据
        Instant todayStart = Instant.now().truncatedTo(ChronoUnit.DAYS);
        if (end.isAfter(todayStart)) {
            List<RealtimeCost> realtime = influxClient.query(
                buildRealtimeQuery(todayStart, end, groupByDims, filters)
            );
            preAggregated = mergeAggregations(preAggregated, realtime);
        }
        
        // 3. 应用成本规则(汇率换算、分摊调整等)
        preAggregated = preAggregated.stream()
            .map(row -> ruleEngine.applyRules(row))
            .toList();
        
        // 4. 计算衍生指标
        return computeDerivedMetrics(preAggregated, groupByDims);
    }
    
    /**
     * 实时成本监控(每分钟执行)
     */
    @Scheduled(fixedDelay = 60_000)
    public void realtimeCostMonitor() {
        // 获取所有活跃预算
        List<BudgetConfig> activeBudgets = budgetRepo.findActive();
        Instant now = Instant.now();
        Instant periodStart = getPeriodStart(now);
        
        for (BudgetConfig budget : activeBudgets) {
            // 查询当前周期已消费金额
            BigDecimal currentSpend = calculateSpend(
                periodStart, now, 
                budget.getBudgetScope(), 
                budget.getScopeValue()
            );
            
            BigDecimal usagePct = currentSpend
                .divide(budget.getBudgetAmount(), 4, RoundingMode.HALF_UP)
                .multiply(BigDecimal.valueOf(100));
            
            // 检查阈值
            BudgetAlertLevel level = checkThreshold(budget, usagePct);
            if (level != null) {
                handleBudgetAlert(budget, level, currentSpend, usagePct);
            }
        }
    }
    
    private BudgetAlertLevel checkThreshold(BudgetConfig budget, BigDecimal usagePct) {
        if (usagePct.compareTo(BigDecimal.valueOf(budget.getThresholdEmergency())) >= 0) {
            return BudgetAlertLevel.EMERGENCY;
        } else if (usagePct.compareTo(BigDecimal.valueOf(budget.getThresholdCritical())) >= 0) {
            return BudgetAlertLevel.CRITICAL;
        } else if (usagePct.compareTo(BigDecimal.valueOf(budget.getThresholdWarn())) >= 0) {
            return BudgetAlertLevel.WARN;
        }
        return null;
    }
    
    private void handleBudgetAlert(
            BudgetConfig budget, BudgetAlertLevel level,
            BigDecimal spend, BigDecimal pct) {
        
        // 记录告警事件
        CostAlertEvent event = CostAlertEvent.builder()
            .alertCode(generateAlertCode())
            .budgetId(budget.getId())
            .alertLevel(level.name())
            .scope(budget.getBudgetScope())
            .scopeValue(budget.getScopeValue())
            .currentSpend(spend)
            .budgetAmount(budget.getBudgetAmount())
            .usagePct(pct)
            .actionsTaken(new ArrayList<>())
            .status("OPEN")
            .build();
        
        List<String> actions = new ArrayList<>();
        
        switch (level) {
            case WARN:
                if (budget.getActionWarn().contains("NOTIFY")) {
                    notifyService.sendBudgetAlert(budget, level, spend, pct);
                    actions.add("notify_sent");
                }
                break;
                
            case CRITICAL:
                notifyService.sendBudgetAlert(budget, level, spend, pct);
                actions.add("notify_sent");
                
                if (budget.getActionCritical().contains("THROTTLE")) {
                    // 对免费用户限流
                    throttleService.applyThrottle(
                        budget.getScopeValue(),
                        ThrottleTarget.FREE_TIER,
                        ThrottleAction.REDUCE_RATE_LIMIT
                    );
                    actions.add("throttle_free_tier");
                }
                break;
                
            case EMERGENCY:
                notifyService.sendBudgetAlert(budget, level, spend, pct);
                actions.add("notify_sent");
                
                if (budget.getActionEmergency().contains("DEGRADE")) {
                    // 自动降级模型
                    DegradeTarget target = budget.getDegradeTarget();
                    modelRouter.applyEmergencySubstitution(
                        target.getModelSubstitution()
                    );
                    actions.add("model_degraded:" + target);
                }
                break;
        }
        
        event.setActionsTaken(actions);
        alertRepo.save(event);
    }
}
```

### 5.4 单位成本实时计算

```
单位成本 = 总成本 / 业务量

实时单位成本计算:
  costPerRequest = sum(cost_total) / sum(request_count)  -- 在当前时间窗口内
  
  costPerDAU     = sum(cost_total) / count(distinct user_id)  -- 当日累计

  costPerLearnHour = sum(cost_total) / (sum(learn_minutes) / 60)

异常检测:
  - 使用过去14天同时段的均值 ± 2σ 作为正常区间
  - 超出区间时标记为异常
  - 异常持续 >15min 时触发告警
```

**关键代码 — 异常检测:**

```java
@Service
public class CostAnomalyDetector {
    
    private final TimeSeriesRepository tsRepo;
    
    @Scheduled(fixedDelay = 60_000)
    public void detectAnomalies() {
        // 检测维度: 每个模块 × 每个资源类型
        List<MetricDefinition> metrics = getMonitoringMetrics();
        
        for (MetricDefinition metric : metrics) {
            // 获取过去14天同时段的历史数据
            double[] history = tsRepo.getHistoricalValues(
                metric, 
                Instant.now().minus(14, ChronoUnit.DAYS),
                Instant.now(),
                60 // 1分钟粒度
            );
            
            // 计算基线
            double mean = Arrays.stream(history).average().orElse(0);
            double stdDev = Math.sqrt(
                Arrays.stream(history)
                    .map(v -> Math.pow(v - mean, 2))
                    .average().orElse(0)
            );
            
            // 当前值
            double current = tsRepo.getLatestValue(metric);
            
            // 判断异常
            if (stdDev > 0 && Math.abs(current - mean) > 2 * stdDev) {
                double zScore = (current - mean) / stdDev;
                AnomalyLevel level = Math.abs(zScore) > 3 
                    ? AnomalyLevel.SEVERE : AnomalyLevel.WARNING;
                
                publishAnomalyEvent(AnomalyEvent.builder()
                    .metricDef(metric)
                    .currentValue(current)
                    .baselineValue(mean)
                    .stdDeviation(stdDev)
                    .zScore(zScore)
                    .level(level)
                    .detectedAt(Instant.now())
                    .build());
            }
        }
    }
}
```

## 8. 错误处理与容错

### 8.1 数据采集失败

| 场景 | 处理策略 |
|---|---|
| Prometheus scrape 超时 | 重试3次，失败后跳过本周期，告警 |
| Kafka 消费积压 | 自动扩容消费者，积压>10万条时丢弃低优先级指标 |
| AI Call Log 查询超时 | 分页查询，单页5000条，超时后缩小时间窗口 |
| InfluxDB 写入失败 | 降级写入 MySQL 临时表，后台补偿迁移 |

### 8.2 聚合计算异常

```java
@Service
public class FaultTolerantAggregator {
    
    /**
     * 容错聚合: 优先使用精确数据，降级使用近似数据
     */
    public AggregationResult safeAggregate(AggregateRequest req) {
        try {
            // 尝试精确聚合
            return preciseAggregate(req);
        } catch (DataIncompleteException e) {
            log.warn("精确聚合并数据不完整，降级为近似聚合: {}", e.getMessage());
            
            // 降级: 使用已有数据 + 插值估算缺失部分
            AggregationResult partial = partialAggregate(req);
            AggregationResult estimated = estimateMissing(partial, req);
            estimated.setQuality("PARTIAL_ESTIMATED");
            return estimated;
            
        } catch (Exception e) {
            log.error("聚合失败，返回空结果", e);
            return AggregationResult.empty(req, "AGGREGATION_FAILED");
        }
    }
    
    /**
     * 估算缺失数据(线性插值)
     */
    private AggregationResult estimateMissing(
            AggregationResult partial, AggregateRequest req) {
        // 如果缺失时段<30分钟，使用前一时段均值填充
        // 如果缺失时段>30分钟，使用过去7天同时段均值填充
        // 在结果中标注 estimated=true
        return partial;
    }
}
```

### 8.3 降级动作执行失败

```
降级执行失败处理链:
  1. 重试 (最多3次, 指数退避)
  2. 重试失败 → 尝试备选降级策略
     - 模型替换失败 → 回退至降低请求频率
     - 限流执行失败 → 通知运维人工介入
  3. 所有策略失败 → 紧急飞书通知 + 电话告警
```

## 9. 性能考量

### 9.1 数据量预估

| 指标源 | 预估量级 | 采集频率 |
|---|---|---|
| 基础设施(Pod级) | ~500 pods × 10指标 = 5000/min | 15秒 |
| AI模型调用 | ~2000次/min × 5字段 = 10000/min | 每次调用 |
| 第三方API | ~500次/min | 每次调用 |
| 业务事件 | ~50000/min | 每次事件 |
| **合计** | ~65000 条/min ≈ 9300万条/天 | - |

### 9.2 存储策略

| 数据类型 | 热存储 | 温存储 | 冷存储 |
|---|---|---|---|
| 原始指标(raw) | MySQL 7天 | 归档至 S3 30天 | 30天后删除 |
| 分钟级聚合 | InfluxDB 90天 | 90天后降采样为小时级 | - |
| 小时级聚合 | InfluxDB 1年 | 1年后降采样为日级 | - |
| 日级聚合 | MySQL 永久 | - | - |

### 9.3 查询优化

1. **大盘首屏查询 < 500ms**: 使用 Redis 缓存预计算结果，TTL 1分钟。
2. **下钻查询 < 1s**: InfluxDB 按时间分区 + 物化视图。
3. **实时指标推送**: WebSocket 长连接，服务端 5 秒推送一次。

```java
@FeignClient(name = "model-router-service")
public interface ModelRouterClient {
    
    @PostMapping("/api/v1/model-router/substitutions")
    SubstitutionResult applySubstitution(@RequestBody SubstitutionCommand command);
}

// 降级指令
SubstitutionCommand command = SubstitutionCommand.builder()
    .triggerReason("BUDGET_EMERGENCY")
    .budgetCode(budget.getBudgetCode())
    .scope("ai_tutor")
    .substitutionMap(Map.of(
        "gpt-4o", "deepseek-v3",        // 高端模型 → 经济模型
        "claude-3.5-sonnet", "deepseek-v3"
    ))
    // 保留高端模型给付费用户
    .whitelist(UserTier.YEARLY)
    .estimatedCostReductionPct(45.0)
    .autoRevertAt(nextPeriodStart())    // 下月自动恢复
    .build();

SubstitutionResult result = modelRouterClient.applySubstitution(command);
```
