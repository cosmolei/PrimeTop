# 服务端-个性化推荐解释生成与推荐决策可解释性引擎-详细设计

> **文档版本：** v1.0  
> **最后更新：** 2026-06-15  
> **所属模块：** 学习推荐体系 / 可解释AI  
> **依赖模块：** 首页内容卡片推荐服务、题目智能推荐服务、自适应学习引擎、知识追踪模型引擎、学情分析服务

---

## 1. 模块概述

### 1.1 背景与动机

PrimeTop 已有多条推荐链路（首页卡片推荐、题目推荐、学习路径推荐、作文素材推荐等），这些引擎解决了 **"推荐什么"** 的问题，但缺少对 **"为什么推荐"** 的系统性解答。

在教育场景中，推荐可解释性具有特殊价值：

| 维度 | 价值 |
|------|------|
| **家长信任** | 家长需要理解推荐依据，才能信任并支持孩子的学习路径 |
| **学生投入度** | 研究表明，当学生理解学习任务的必要性时，投入度提升 30%+ |
| **教师参考** | 教师参考推荐结果时需要知道依据，才能与教学计划对齐 |
| **推荐 debugging** | 运营和内容团队需要理解推荐逻辑以发现和修正偏差 |
| **合规要求** | 《互联网信息服务算法推荐管理规定》要求提供算法推荐说明 |
| **教育透明** | 教育产品应以"启发理解"为核心，黑盒推荐与教育理念冲突 |

### 1.2 模块定位

本模块是一个**横切型服务**，不产生推荐结果本身，而是接入各推荐引擎的输出，为每条推荐生成**人类可读的、多维度可解释的理由**。

```
┌─────────────────────────────────────────────────────────┐
│                   各推荐引擎 (上游)                       │
│  首页卡片推荐 │ 题目推荐 │ 学习路径推荐 │ 素材推荐 │ ...  │
└──────────┬──────────────────────────────────────────────┘
           │ 推荐结果 + 上下文
           ▼
┌─────────────────────────────────────────────────────────┐
│              推荐解释生成引擎 (本模块)                     │
│                                                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐             │
│  │ 规则解释器│  │ AI解释器  │  │ 统计解释器│             │
│  └─────┬────┘  └─────┬────┘  └─────┬────┘             │
│        └─────────────┼─────────────┘                    │
│                      ▼                                  │
│              解释合成与排序器                             │
│                      │                                  │
│                      ▼                                  │
│              解释模板渲染器                               │
└──────────────────────┬──────────────────────────────────┘
                       │ 结构化解释 + 自然语言解释
                       ▼
               各客户端 / 家长端 / 教师端
```

### 1.3 设计目标

1. **低延迟**：解释生成增加延迟 ≤ 50ms（P99），不阻塞推荐主流程
2. **可组合**：规则 + AI + 统计三种解释器可灵活编排
3. **分龄适配**：同一条推荐，对小学生、家长、教师生成不同表达
4. **可追溯**：每条解释关联到底层推荐因子和数据快照
5. **可配置**：解释模板、AI Prompt、展示策略均通过配置中心管理
6. **渐进增强**：推荐解释为可选增强，上游引擎不依赖本模块

### 2.2 核心组件

| 组件 | 职责 | 实现方式 |
|------|------|---------|
| ExplainRequestOrchestrator | 接收推荐结果，编排解释生成流程 | 异步+同步混合 |
| RuleExplainer | 基于预定义规则生成解释 | 规则引擎(Drools/自研) |
| AIExplainer | 调用大模型生成自然语言解释 | Prompt模板 + 轻量模型 |
| StatsExplainer | 基于统计数据生成量化解释 | 实时查询 + 预计算 |
| ExplanationCompositor | 合并多个解释器的输出，去重排序 | 加权打分 |
| AgeAdaptiveRenderer | 按受众（学生/家长/教师）适配表达 | 模板引擎 |
| ExplanationCache | 缓存解释结果避免重复生成 | Redis |
| ExplainQueryAPI | 对外查询接口 | RESTful |

### 2.3 与上游推荐引擎的集成模式

采用 **"旁路生成"** 模式，不侵入推荐主链路：

```java
// 推荐引擎正常返回结果，同时发送事件
@RestController
public class RecommendationController {

    @PostMapping("/api/v1/recommend/cards")
    public RecommendResponse recommend(@RequestBody RecommendRequest req) {
        RecommendResult result = recommendService.recommend(req);

        // 异步发送推荐事件，触发解释生成（非阻塞）
        eventPublisher.publishAsync(new RecommendationEvent(
            req.getUserId(),
            req.getScene(),
            result.getItems(),
            result.getSnapshot() // 推荐因子快照
        ));

        return RecommendResponse.success(result);
    }
}
```

推荐事件通过 Kafka 异步消费，生成解释后写入缓存。客户端查询推荐时携带 `with_explanation=true` 参数，服务端从缓存读取解释一并返回；若缓存未就绪则返回推荐结果不含解释（降级），不阻塞推荐本身。

## 3. 数据模型设计

### 3.1 PostgreSQL 表结构

#### 3.1.1 推荐解释记录表 `recommend_explanations`

```sql
CREATE TABLE recommend_explanations (
    id              BIGSERIAL PRIMARY KEY,
    explanation_id  VARCHAR(64) NOT NULL UNIQUE,      -- 解释唯一ID (雪花ID)
    user_id         BIGINT NOT NULL,                   -- 用户ID
    scene           VARCHAR(32) NOT NULL,              -- 推荐场景 see enum
    recommend_item_id VARCHAR(128) NOT NULL,           -- 被推荐项ID (题目ID/卡片ID/路径节点ID)
    item_type       VARCHAR(32) NOT NULL,              -- 推荐项类型
    recommend_event_id VARCHAR(64) NOT NULL,           -- 关联推荐事件ID
    explain_version  VARCHAR(16) NOT NULL DEFAULT 'v1',-- 解释版本
    explain_sources VARCHAR(32)[] NOT NULL,            -- 解释来源 [RULE, AI, STATS]
    structured_explain JSONB NOT NULL,                 -- 结构化解释 (见3.2)
    natural_language TEXT,                              -- 自然语言解释 (渲染后)
    confidence_score DECIMAL(5,4),                     -- 解释置信度 0.0-1.0
    -- 冗余字段，方便查询
    grade           SMALLINT,                          -- 用户年级
    subject         VARCHAR(16),                       -- 学科
    -- 元数据
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at      TIMESTAMPTZ,                       -- 过期时间
    tenant_id       VARCHAR(32) NOT NULL DEFAULT 'default',

    -- 索引
    CONSTRAINT idx_explain_unique UNIQUE (explanation_id)
);

-- 查询索引
CREATE INDEX idx_explain_user_scene ON recommend_explanations (user_id, scene, created_at DESC);
CREATE INDEX idx_explain_item ON recommend_explanations (recommend_item_id, item_type);
CREATE INDEX idx_explain_event ON recommend_explanations (recommend_event_id);
CREATE INDEX idx_explain_expires ON recommend_explanations (expires_at) WHERE expires_at IS NOT NULL;
-- 分区策略: 按月分区 created_at
```

## 5. 核心流程设计

### 5.1 解释生成主流程

```
推荐引擎输出结果
       │
       ▼
┌──────────────────┐
│ 1.接收推荐事件     │
│ (Kafka Consumer)  │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 2.加载推荐因子     │◀──── 推荐因子快照表
│ 快照              │
└────────┬─────────┘
         │
         ▼
┌──────────────────────────────────────────┐
│ 3.并行执行三个解释器 (CompletableFuture)   │
│                                          │
```

### 5.2 规则解释器详解

规则解释器基于预定义的业务规则，将推荐因子映射为结构化解释。延迟预算 ≤ 10ms。

#### 核心规则定义

```java
/**
 * 规则解释器 - 将推荐因子映射为可读解释
 */
@Component
public class RuleExplainer implements Explainer {

    private final List<RuleDefinition> rules;

    /**
     * 规则定义示例
     */
    private void initRules() {
        // 规则1: 薄弱点补强
        rules.add(RuleDefinition.builder()
            .name("weakness_remediation")
            .condition(ctx -> {
                var factors = ctx.getFactors();
                return factors.getKnowledgeMastery() < 0.5
                    && factors.getWeakPointBoost() > 0.7
                    && ctx.getRecentAccuracy("current_kp") < 0.5;
            })
            .explanation(ctx -> Explanation.builder()
                .type(ExplanationType.WEAKNESS_REMEDIATION)
                .title("薄弱知识点补强")
                .detail(String.format(
                    "你在「%s」的最近%d次练习中正确率为%.0f%%",
                    ctx.getKnowledgePointName(),
                    ctx.getRecentAttemptCount(),
                    ctx.getRecentAccuracy("current_kp") * 100
                ))
                .dataRefs(List.of(DataRef.knowledgePoint(
                    ctx.getKnowledgePointId(),
                    ctx.getKnowledgePointName(),
                    ctx.getRecentAccuracy("current_kp")
                )))
                .confidence(Math.min(0.95, 0.5 + ctx.getFactors().getWeakPointBoost() * 0.5))
                .build())
            .priority(10)
            .build());

        // 规则2: 前置知识已就绪
        rules.add(RuleDefinition.builder()
            .name("prerequisite_ready")
            .condition(ctx -> {
                var factors = ctx.getFactors();
                return factors.isPrerequisiteReady()
                    && factors.getKnowledgeMastery() < 0.3;
            })
            .explanation(ctx -> Explanation.builder()
                .type(ExplanationType.PREREQUISITE_READY)
                .title("前置知识已掌握")
                .detail(String.format(
                    "你已熟练掌握「%s」，可以开始学习「%s」",
                    ctx.getPrerequisiteName(),
                    ctx.getKnowledgePointName()
                ))
                .confidence(0.85)
                .build())
            .priority(20)
            .build());

        // 规则3: 考试关联度
        rules.add(RuleDefinition.builder()
            .name("exam_relevance")
            .condition(ctx -> {
                var factors = ctx.getFactors();
                return factors.getExamRelevance() > 0.6;
            })
            .explanation(ctx -> {
                double frequency = ctx.getExamFrequency(ctx.getKnowledgePointId());
                return Explanation.builder()
                    .type(ExplanationType.EXAM_RELEVANCE)
                    .title(ctx.isSeniorGrade() ? "高考高频考点" :
                           ctx.isMiddleGrade() ? "中考高频考点" : "重点考试内容")
                    .detail(String.format(
                        "该知识点在近%d年%s中出现率为%.0f%%",
                        ctx.getExamYearRange(),
                        ctx.getExamName(),
                        frequency * 100
                    ))
                    .dataRefs(List.of(DataRef.examStat(
                        frequency,
                        ctx.getExamSource(),
                        ctx.getExamQuestionCount()
                    )))
                    .confidence(frequency)
                    .build();
            })
            .priority(30)
            .build());

        // 规则4: 复习到期 (间隔重复)
        rules.add(RuleDefinition.builder()
            .name("review_due")
            .condition(ctx -> {
                var factors = ctx.getFactors();
                return "REVIEW".equals(factors.getRecommendationType())
                    && factors.getDaysSinceLastReview() >= factors.getReviewInterval();
            })
            .explanation(ctx -> Explanation.builder()
                .type(ExplanationType.REVIEW_DUE)
                .title("复习时间到")
                .detail(String.format(
                    "距离上次复习「%s」已过去%d天，遗忘曲线显示现在复习效果最佳",
                    ctx.getKnowledgePointName(),
                    ctx.getDaysSinceLastReview()
                ))
                .confidence(0.80)
                .build())
            .priority(15)
            .build());

        // 规则5: 难度适宜
        rules.add(RuleDefinition.builder()
            .name("difficulty_appropriate")
            .condition(ctx -> {
                var factors = ctx.getFactors();
                double optimal = 0.6 + ctx.getStudentLevel() * 0.2; // 最近发展区
                return Math.abs(factors.getDifficultyMatch() - optimal) < 0.15;
            })
            .explanation(ctx -> Explanation.builder()
                .type(ExplanationType.DIFFICULTY_APPROPRIATE)
                .title("难度刚刚好")
                .detail(String.format(
                    "这道题的难度(%s)适合你当前的水平，挑战性和成就感平衡得很好",
                    ctx.getDifficultyLabel()
                ))
                .confidence(0.70)
                .build())
            .priority(40)
            .build());

        // 规则6: 学习计划对齐
        rules.add(RuleDefinition.builder()
            .name("study_plan_aligned")
            .condition(ctx -> ctx.getFactors().getStudyPlanAlignment() > 0.7)
            .explanation(ctx -> Explanation.builder()
                .type(ExplanationType.STUDY_PLAN_ALIGNED)
                .title("今日学习计划")
                .detail(String.format(
                    "这是你今天计划中「%s」部分的练习，完成它今天的任务就完成%d%%了",
                    ctx.getPlanSectionName(),
                    ctx.getPlanCompletionPercentAfter()
                ))
                .confidence(0.75)
                .build())
            .priority(25)
            .build());

        // 规则7: 同伴参照
        rules.add(RuleDefinition.builder()
            .name("peer_benchmark")
            .condition(ctx -> {
                var factors = ctx.getFactors();
                return factors.getPeerPerformanceAvg() != null
                    && ctx.getRecentAccuracy("current_kp") != null
                    && factors.getPeerPerformanceAvg() > ctx.getRecentAccuracy("current_kp") + 0.15;
            })
            .explanation(ctx -> Explanation.builder()
                .type(ExplanationType.PEER_BENCHMARK)
                .title("同学们都在练")
                .detail(String.format(
                    "同年级同学在「%s」的平均正确率是%.0f%%，你还有提升空间",
                    ctx.getKnowledgePointName(),
                    ctx.getFactors().getPeerPerformanceAvg() * 100
                ))
                .confidence(0.60)
                .build())
            .priority(50)
            .build());
    }

    @Override
    public CompletableFuture<List<Explanation>> explain(ExplainContext ctx) {
        // 同步执行，规则匹配 < 5ms
        return CompletableFuture.supplyAsync(() -> {
            List<Explanation> results = new ArrayList<>();
            for (RuleDefinition rule : rules) {
                if (rule.getCondition().test(ctx)) {
                    results.add(rule.getExplanation().apply(ctx));
                    if (results.size() >= 5) break; // 最多5条
                }
            }
            return results;
        }, ruleExecutor); // 专用线程池
    }
}
```

### 5.3 统计解释器详解

统计解释器从数据仓库和实时聚合层获取量化数据，生成数据驱动的解释。延迟预算 ≤ 20ms。

```java
@Component
public class StatsExplainer implements Explainer {

    private final LearningStatsCache statsCache;     // Redis 预计算缓存
    private final ExamStatsService examStatsService; // 考试统计

    @Override
    public CompletableFuture<List<Explanation>> explain(ExplainContext ctx) {
        return CompletableFuture.supplyAsync(() -> {
            List<Explanation> results = new ArrayList<>();

            // 1. 学习趋势解释
            LearningTrend trend = statsCache.getTrend(
                ctx.getUserId(), ctx.getKnowledgePointId()
            );
            if (trend != null && trend.isDeclining()) {
                results.add(Explanation.builder()
                    .type(ExplanationType.WEAKNESS_REMEDIATION)
                    .title("最近正确率下降")
                    .detail(String.format(
                        "你对「%s」的掌握从两周前的%.0f%%降到了%.0f%%，需要巩固一下",
                        ctx.getKnowledgePointName(),
                        trend.getPreviousAccuracy() * 100,
                        trend.getCurrentAccuracy() * 100
                    ))
                    .confidence(0.85)
                    .source(ExplanationSource.STATS)
                    .build());
            }

            // 2. 学习连续性解释
            StreakData streak = statsCache.getStreak(ctx.getUserId());
            if (streak.isActive() && streak.getDays() >= 3) {
                results.add(Explanation.builder()
                    .type(ExplanationType.SEQUENCE_CONTINUATION)
                    .title("保持学习节奏")
                    .detail(String.format(
                        "你已经连续%d天坚持学习，继续保持！",
                        streak.getDays()
                    ))
                    .confidence(0.65)
                    .source(ExplanationSource.STATS)
                    .build());
            }

            // 3. 时间投入 vs 同伴
            TimeInvestment investment = statsCache.getTimeInvestment(
                ctx.getUserId(), ctx.getSubject()
            );
            if (investment.isBelowMedian()) {
                results.add(Explanation.builder()
                    .type(ExplanationType.KNOWLEDGE_REINFORCEMENT)
                    .title("多投入一些时间")
                    .detail(String.format(
                        "本周你在%s上花了%.1f小时，比同学们的平均%.1f小时少一些",
                        ctx.getSubjectName(),
                        investment.getHours(),
                        investment.getPeerMedianHours()
                    ))
                    .confidence(0.55)
                    .source(ExplanationSource.STATS)
                    .build());
            }

            return results;
        }, statsExecutor);
    }
}
```

### 5.4 AI 解释器详解

AI 解释器使用轻量级大模型（如 GLM-4-Flash / Qwen-Turbo）生成自然语言解释。延迟预算 ≤ 40ms。

```java
@Component
public class AIExplainer implements Explainer {

    private final ModelAdapter modelAdapter;     // 多模型适配层
    private final PromptTemplateManager templateManager;

    // 只在规则和统计解释不足时触发
    @Override
    public CompletableFuture<List<Explanation>> explain(ExplainContext ctx) {
        // 如果规则+统计已产出>=2条高质量解释，跳过AI
        if (ctx.getExistingExplanations().size() >= 2
            && ctx.getExistingExplanations().stream()
                .anyMatch(e -> e.getConfidence() > 0.85)) {
            return CompletableFuture.completedFuture(List.of());
        }

        return CompletableFuture.supplyAsync(() -> {
            // 构建 Prompt
            ExplainPrompt prompt = buildPrompt(ctx);
            String aiResponse = modelAdapter.call(
                ModelRequest.builder()
                    .model("glm-4-flash") // 轻量模型，低延迟
                    .messages(prompt.getMessages())
                    .temperature(0.3)     // 低温度保证稳定性
                    .maxTokens(200)       // 短文本
                    .timeout(Duration.ofMillis(35))
                    .build()
            );

            return parseAIResponse(aiResponse, ctx);
        }, aiExecutor);
    }

    private ExplainPrompt buildPrompt(ExplainContext ctx) {
        PromptTemplate template = templateManager.getTemplate(
            ctx.getScene().name(),
            ctx.getAudience().name()
        );

        Map<String, Object> vars = Map.of(
            "studentGrade", ctx.getGradeLabel(),
            "subject", ctx.getSubjectName(),
            "knowledgePoint", ctx.getKnowledgePointName(),
            "recentAccuracy", ctx.getRecentAccuracy("current_kp"),
            "attemptCount", ctx.getRecentAttemptCount(),
            "difficulty", ctx.getDifficultyLabel(),
            "examRelevance", ctx.getFactors().getExamRelevance(),
            "studyTime", ctx.getTodayStudyMinutes(),
            "planCompletion", ctx.getPlanCompletionPercent(),
            "peerAccuracy", ctx.getFactors().getPeerPerformanceAvg(),
            "interestScore", ctx.getFactors().getInterestAlignment()
        );

        return template.render(vars);
    }
}
```

### 5.5 解释合成与排序

```java
@Component
public class ExplanationCompositor {

    /**
     * 合并多个解释来源，去重排序，选取最优解释集
     */
    public CompositeExplanation composite(
        List<Explanation> ruleExplanations,
        List<Explanation> statsExplanations,
        List<Explanation> aiExplanations,
        ExplainContext ctx
    ) {
        // 1. 合并所有解释
        List<ScoredExplanation> all = new ArrayList<>();

        ruleExplanations.forEach(e ->
            all.add(score(e, 1.0)));  // 规则解释权重1.0
        statsExplanations.forEach(e ->
            all.add(score(e, 0.9)));  // 统计解释权重0.9
        aiExplanations.forEach(e ->
            all.add(score(e, 0.7)));  // AI解释权重0.7（可能幻觉）

        // 2. 按类型去重（同一类型只保留置信度最高的）
        Map<ExplanationType, ScoredExplanation> deduped = new LinkedHashMap<>();
        for (ScoredExplanation se : all) {
            deduped.merge(se.getExplanation().getType(), se,
                (a, b) -> a.getFinalScore() >= b.getFinalScore() ? a : b);
        }

        // 3. 按综合分数排序
        List<ScoredExplanation> sorted = deduped.values().stream()
            .sorted(Comparator.comparingDouble(ScoredExplanation::getFinalScore).reversed())
            .toList();

        // 4. 构造复合解释
        CompositeExplanation result = new CompositeExplanation();
        if (!sorted.isEmpty()) {
            result.setPrimaryReason(sorted.get(0).getExplanation());

            List<Explanation> secondary = sorted.subList(1, Math.min(sorted.size(), 4))
                .stream()
                .map(ScoredExplanation::getExplanation)
                .toList();
            result.setSecondaryReasons(secondary);

            // 综合置信度
            result.setOverallConfidence(
                sorted.stream()
                    .mapToDouble(ScoredExplanation::getFinalScore)
                    .average().orElse(0.5)
            );
        }

        return result;
    }

    private ScoredExplanation score(Explanation e, double sourceWeight) {
        double score = e.getConfidence() * sourceWeight;
        return new ScoredExplanation(e, score);
    }
}
```

## 7. 缓存策略

### 7.1 多级缓存架构

```
请求 → L1 (本地 Caffeine, 60s) → L2 (Redis 集群, 30min) → DB (PostgreSQL)
```

| 缓存层 | 容量 | TTL | 命中率目标 | 用途 |
|--------|------|-----|-----------|------|
| L1 Caffeine | 10,000 条 | 60s | >70% | 应对突发流量（同一推荐被多端查询） |
| L2 Redis | 无限 | 30min | >90% | 主缓存层 |
| PostgreSQL | 无限 | 永久 | - | 持久化存储 |

### 7.2 缓存 Key 设计

```
# 解释结果缓存
explain:result:{userId}:{scene}:{itemId}:{audience}    → JSON
TTL: 30min

# 统计数据缓存（Stats解释器使用）
explain:stats:trend:{userId}:{knowledgePointId}        → JSON
explain:stats:streak:{userId}                          → JSON
explain:stats:time:{userId}:{subject}                  → JSON
TTL: 5min

# 模板缓存（本地）
explain:template:{scene}:{type}:{audience}:{grade}     → Object
TTL: 60s (本地), 10min (Redis)
```

### 11.2 Prometheus 指标定义

```java
@Component
public class ExplanationMetrics {

    private final MeterRegistry registry;

    // 解释生成延迟
    private final Timer generationTimer;
    // 解释覆盖率
    private final Counter generationCounter;
    private final Counter failureCounter;
    // 各解释器延迟
    private final Timer ruleTimer;
    private final Timer statsTimer;
    private final Timer aiTimer;

    public ExplanationMetrics(MeterRegistry registry) {
        this.registry = registry;
        this.generationTimer = Timer.builder("explain.generation.duration")
            .publishPercentiles(0.5, 0.95, 0.99)
            .register(registry);
        this.generationCounter = Counter.builder("explain.generation.total")
            .register(registry);
        this.failureCounter = Counter.builder("explain.generation.failure")
            .register(registry);
        this.ruleTimer = Timer.builder("explain.rule.duration")
            .register(registry);
        this.statsTimer = Timer.builder("explain.stats.duration")
            .register(registry);
        this.aiTimer = Timer.builder("explain.ai.duration")
            .register(registry);
    }

    public void recordGeneration(String scene, String status, Duration duration) {
        generationTimer.record(duration);
        generationCounter.increment();
        if (!"ACTIVE".equals(status)) {
            failureCounter.increment();
        }
        Counter.builder("explain.generation.by_scene")
            .tag("scene", scene)
            .tag("status", status)
            .register(registry)
            .increment();
    }
}
```

## 12. 安全与隐私

### 12.1 数据安全

| 安全要求 | 实现方式 |
|---------|---------|
| 推荐因子含用户学情数据，属于个人敏感信息 | 解释API需用户鉴权；解释记录表按 tenant_id 隔离 |
| AI 解释器发送给大模型的数据 | 仅传递脱敏统计值（正确率、天数），不传个人身份信息 |
| 解释反馈含用户自由文本 | 入库前经过敏感词过滤（复用 安全与内容合规系统） |
| 家长端查看孩子解释 | 需验证家长绑定关系（复用 ParentBinding 校验） |

### 12.2 合规要求

根据《互联网信息服务算法推荐管理规定》第十七条：

> 算法推荐服务提供者向用户提供算法服务的，应当以显著方式告知用户其提供算法推荐服务的情况，并以适当方式公示算法推荐服务的基本原理、目的意图和主要运行机制等。

本模块作为推荐算法透明性的核心实现，需确保：
1. 每条推荐均可提供解释（coverage ≥ 95%）
2. 解释内容对用户可访问
3. 用户可以对解释进行反馈
4. 解释逻辑可审计（完整日志保留）
