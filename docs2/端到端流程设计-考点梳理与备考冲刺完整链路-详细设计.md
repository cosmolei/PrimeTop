# 端到端流程设计：考点梳理与备考冲刺完整链路

## 1. 文档概述

### 1.1 文档目的

本文档描述"考点梳理 → 诊断测评 → 针对性复习 → 专题训练 → 模拟考试 → 冲刺规划"这一完整端到端链路的详细设计，覆盖用户从进入备考模式到完成考前冲刺的全过程。旨在让开发人员理解各模块在备考场景下如何协同工作，并可直接据此编码。

### 1.2 范围与边界

| 范围 | 说明 |
|------|------|
| 入口场景 | 主动进入考点梳理、系统推荐备考、考试日程触发 |
| 学段覆盖 | 初中（中考）、高中（高考）为主要场景，小学高年级（期末）辅助场景 |
| 学科覆盖 | 全学科，数学/物理/化学/英语/语文为核心 |
| 不含 | 寒暑假专题营（独立链路）、日常同步学习、作文辅导单独链路 |

### 1.3 关联模块

| 模块 | 关联点 |
|------|--------|
| 考点梳理 | 考点清单、高频考点、知识图谱、易错提醒 |
| 考试模拟与真题练习 | 试卷生成、限时答题、评分、复盘 |
| 学情分析 | 薄弱点识别、能力画像、掌握度数据 |
| 学习规划 | 目标设定、计划生成、任务追踪 |
| 错题整理 | 错题收录、复习计划、订正评估 |
| 练习与测评系统 | 章节练习、专题训练、自适应难度 |
| 知识点体系与教材映射引擎 | 知识点树、前置关系、课标对齐 |
| 自适应学习与个性化推荐引擎 | 选题推荐、路径规划 |
| 答案管控与渐进式提示引擎 | 答案分级展示 |
| 用户额度管控与功能门控引擎 | 备考功能额度 |

## 2. 端到端流程总览

### 2.1 主流程全景图

```
用户进入备考模式
      │
      ▼
[P1] 备考场景初始化
  ├─ 识别考试类型（期中/期末/中考/高考）
  ├─ 确定考试范围（学科、章节、知识点）
  ├─ 加载用户当前学情快照
  └─ 生成备考概览（倒计时、待覆盖考点数、薄弱点数）
      │
      ▼
[P2] 考点诊断测评
  ├─ 考点覆盖度检测（已掌握/未掌握/薄弱）
  ├─ 生成诊断试卷（覆盖全部考点）
  ├─ 用户完成诊断测评
  └─ 输出诊断报告（薄弱考点TOP-N、能力差距、优先级排序）
      │
      ▼
[P3] 冲刺计划生成
  ├─ 根据诊断结果+考试倒计时计算每日任务量
  ├─ 生成知识点复习序列（按优先级+前置依赖排序）
  ├─ 分配每日任务（复习+练习+错题重练）
  └─ 计划确认/调整
      │
      ▼
[P4] 针对性复习与专题训练（循环执行）
  ├─ 考点知识复习（讲解+例题+笔记）
  ├─ 专题训练（按考点组题）
  ├─ 错题强化（关联错题重练+订正）
  ├─ 知识点掌握度实时更新
  └─ 自适应调整（强化薄弱点，跳过已掌握）
      │
      ▼
[P5] 模拟考试与效果验证
  ├─ 生成模拟试卷（按真实考试规格）
  ├─ 限时答题（模拟考试环境）
  ├─ 自动批改+AI解析
  ├─ 生成模考报告（对比诊断、进步分析）
  └─ 更新考点掌握度 & 调整冲刺计划
      │
      ▼
[P6] 考前冲刺与临考准备
  ├─ 高频考点速查回顾
  ├─ 易错点终极提醒
  ├─ 错题本最后一轮复习
  ├─ 考试技巧/答题策略推送
  └─ 信心指数评估与心理建议
```

### 2.2 阶段与时间线

```
考试倒计时 T
├── T > 30天: 常规备考阶段 (P1→P2→P3→P4循环)
├── 14 < T ≤ 30天: 强化冲刺阶段 (P4加速+P5模考)
├── 7 < T ≤ 14天: 模考验证阶段 (P5密集+P4定点补强)
├── 3 < T ≤ 7天: 临考准备阶段 (P6为主)
└── T ≤ 3天: 考前调整阶段 (速查回顾+心理准备)
```

#### 3.1.5 优先级评分算法

```python
def calculate_kp_priority(kp: KnowledgePoint, snapshot: PrepContextSnapshot, exam_scope: ExamScope) -> float:
    """
    考点优先级评分 (0~1, 越高越优先)
    综合考虑: 掌握度、考试权重、错题频率、前置依赖
    """
    # 1. 掌握度得分 (越低越优先)
    mastery_score = 1.0 - snapshot.knowledge_point_mastery.get(kp.id, 0.5)

    # 2. 考试权重得分 (高频考点优先)
    weight_score = kp.exam_frequency_weight  # 0~1, 基于历史真题分析

    # 3. 错题频率得分 (错题多的优先)
    mistake_count = snapshot.mistake_count_by_kp.get(kp.id, 0)
    mistake_score = min(mistake_count / 10.0, 1.0)

    # 4. 前置依赖得分 (被依赖的知识点优先复习)
    dependency_score = min(len(kp.dependent_kp_ids) / 5.0, 1.0)

    # 加权计算
    priority = (
        mastery_score * 0.35 +
        weight_score * 0.30 +
        mistake_score * 0.20 +
        dependency_score * 0.15
    )
    return priority
```

#### 3.2.1 诊断策略

根据备考初始化结果，系统决定是否需要诊断测评：

```python
def should_run_diagnostic(snapshot: PrepContextSnapshot) -> tuple[bool, str]:
    """
    判断是否需要诊断测评
    """
    total_kps = len(snapshot.knowledge_point_mastery)
    unknown_ratio = sum(1 for v in snapshot.knowledge_point_mastery.values() if v < 0) / total_kps if total_kps else 1.0

    if unknown_ratio > 0.3:
        return True, "超过30%考点无掌握度数据，建议进行诊断测评"
    elif snapshot.current_mastery_overall < 0.4:
        return True, "整体掌握度低于40%，建议进行诊断测评"
    elif not snapshot.recent_exam_scores:
        return True, "缺少近期考试记录，建议进行诊断测评"
    else:
        return False, "学情数据充足，可直接生成冲刺计划"
```

#### 3.3.2 计划生成算法

```python
class SprintPlanGenerator:
    """冲刺计划生成器"""

    def generate(self, config: SprintPlanConfig, snapshot: PrepContextSnapshot, diagnostic: DiagnosticReport) -> SprintPlan:
        # 1. 计算有效学习天数
        effective_days = config.available_days - config.rest_day_per_week * (config.available_days // 7)
        if config.include_mock_exams:
            effective_days -= self._count_mock_days(config)

        # 2. 排序知识点复习序列（拓扑排序 + 优先级）
        review_sequence = self._topological_sort_by_priority(
            config.target_kps,
            priority_fn=lambda kp: self._kp_priority(kp, snapshot, diagnostic)
        )

        # 3. 分配每日任务
        daily_plans = []
        kp_idx = 0
        for day_num in range(1, config.available_days + 1):
            if self._is_rest_day(day_num, config):
                daily_plans.append(self._rest_day_plan(day_num))
                continue

            if self._is_mock_day(day_num, config):
                daily_plans.append(self._mock_exam_plan(day_num, config))
                continue

            daily_plan = self._generate_daily_plan(
                day_num=day_num,
                config=config,
                review_sequence=review_sequence,
                kp_idx=kp_idx,
                snapshot=snapshot
            )
            kp_idx = daily_plan.next_kp_index
            daily_plans.append(daily_plan)

        # 4. 构建完整计划
        return SprintPlan(
            prep_session_id=config.prep_session_id,
            total_days=config.available_days,
            daily_plans=daily_plans,
            estimated_kps_to_cover=len(review_sequence),
            milestone_days=self._calculate_milestones(daily_plans)
        )

    def _topological_sort_by_priority(self, kp_ids: list[str], priority_fn) -> list[str]:
        """
        基于知识点前置依赖的拓扑排序 + 优先级加权
        保证前置知识点先复习，同级中高优先级的先排
        """
        # 构建DAG
        graph = self._build_dependency_graph(kp_ids)

        # Kahn's algorithm with priority queue
        in_degree = {kp: len(graph[kp].prerequisites) for kp in kp_ids}
        heap = []
        for kp in kp_ids:
            if in_degree[kp] == 0:
                heapq.heappush(heap, (-priority_fn(kp), kp))  # 负号使高优先级先出

        result = []
        while heap:
            _, kp = heapq.heappop(heap)
            result.append(kp)
            for dependent in graph[kp].dependents:
                in_degree[dependent] -= 1
                if in_degree[dependent] == 0:
                    heapq.heappush(heap, (-priority_fn(dependent), dependent))

        return result
```

#### 3.3.5 计划调整机制

```
PUT /api/v1/exam-prep/{prep_session_id}/plan/{plan_id}/adjust
```

触发调整的条件：
1. **进度偏差**：连续2天未完成80%以上任务 → 降低任务量
2. **掌握度更新**：某知识点提前达标 → 跳过，将时间分配给薄弱点
3. **新错题涌现**：出现新的高频错题知识点 → 插入复习队列
4. **模考反馈**：模考发现新薄弱点 → 紧急插入
5. **用户主动调整**：用户手动修改每日学习时间或学科优先级

```python
class PlanAdjustmentEngine:
    def evaluate_and_adjust(self, plan: SprintPlan, current_day: int, latest_data: dict) -> SprintPlanAdjustment:
        adjustments = []

        # 1. 进度检查
        completion_rate = self._calculate_completion_rate(plan, current_day)
        if completion_rate < 0.6:
            adjustments.append(self._reduce_task_volume(plan, reduction=0.2))

        # 2. 掌握度检查
        newly_mastered = self._find_newly_mastered_kps(plan, latest_data)
        if newly_mastered:
            adjustments.append(self._skip_mastered_kps(plan, newly_mastered))
            adjustments.append(self._redistribute_time(plan, newly_mastered, to_weak=True))

        # 3. 新薄弱点
        new_weak = self._find_new_weak_kps(latest_data)
        if new_weak:
            adjustments.append(self._insert_emergency_review(plan, new_weak, priority="high"))

        return SprintPlanAdjustment(
            plan_id=plan.plan_id,
            adjustment_reasons=[a.reason for a in adjustments],
            updated_daily_plans=self._apply_adjustments(plan, adjustments),
            effective_from_day=current_day + 1
        )
```

#### 3.4.3 错题强化循环

```python
class MistakeRevisitScheduler:
    """备考场景下的错题重练调度器"""

    def schedule_for_exam_prep(self, prep_session_id: str, plan: SprintPlan, day: int) -> list[MistakeRevisitTask]:
        # 1. 筛选本次备考范围内的错题
        exam_scope_kps = plan.kp_review_sequence
        relevant_mistakes = self.mistake_repo.find_by_kps(
            user_id=self._get_user_id(prep_session_id),
            kp_ids=exam_scope_kps,
            status=["unresolved", "partially_resolved"],
            min_occurrences=1
        )

        # 2. 按考点优先级排序
        sorted_mistakes = sorted(relevant_mistakes, key=lambda m: (
            -m.kp_priority_score,   # 考点优先级高的错题先练
            m.last_review_date       # 最久没复习的先练
        ))

        # 3. 每日配额
        daily_quota = plan.daily_plans[day - 1].target_mistake_revisit
        selected = sorted_mistakes[:daily_quota]

        # 4. 生成重练任务
        tasks = []
        for mistake in selected:
            # 获取原题 + 1道同类题
            original_q = mistake.question
            similar_q = self.question_service.find_similar(
                question_id=original_q.id,
                same_kps=True,
                count=1
            )
            tasks.append(MistakeRevisitTask(
                original_question=original_q,
                similar_question=similar_q[0] if similar_q else None,
                mistake_record=mistake,
                knowledge_point_ids=mistake.knowledge_point_ids
            ))

        return tasks
```

```python
class ExamPrepMasteryUpdater:
    """备考场景下的掌握度更新器"""

    def update_from_practice(self, user_id: str, practice_result: PracticeResult, prep_session_id: str):
        for kp_id in practice_result.knowledge_point_ids:
            old_mastery = self.mastery_repo.get(user_id, kp_id)
            accuracy = practice_result.get_accuracy_for_kp(kp_id)

            # 备考场景下采用更敏感的更新策略
            # 标准场景: alpha = 0.3
            # 备考场景: alpha = 0.5（更快响应）
            alpha = 0.5
            new_mastery = old_mastery + alpha * (accuracy - old_mastery)

            self.mastery_repo.update(user_id, kp_id, new_mastery)

            # 发布掌握度变更事件
            self.event_bus.publish(KPMasteryUpdatedEvent(
                user_id=user_id,
                kp_id=kp_id,
                old_mastery=old_mastery,
                new_mastery=new_mastery,
                source="exam_prep_practice",
                prep_session_id=prep_session_id
            ))

            # 检查是否达到备考达标线
            target_mastery = self._get_target_mastery(kp_id, prep_session_id)
            if new_mastery >= target_mastery and old_mastery < target_mastery:
                self.event_bus.publish(KPPreppedEvent(
                    user_id=user_id,
                    kp_id=kp_id,
                    mastery=new_mastery,
                    prep_session_id=prep_session_id
                ))
```

```python
class ConfidenceIndexCalculator:
    """考前信心指数计算"""

    def calculate(self, prep_session_id: str) -> ConfidenceIndex:
        # 1. 知识点掌握度聚合
        kp_mastery_avg = self._avg_kp_mastery(prep_session_id)

        # 2. 近期练习正确率
        recent_accuracy = self._recent_practice_accuracy(prep_session_id, days=7)

        # 3. 模考进步趋势
        mock_trend = self._mock_score_trend(prep_session_id)

        # 4. 错题解决率
        mistake_resolution = self._mistake_resolution_rate(prep_session_id)

        # 综合信心指数 (0~100)
        confidence = (
            kp_mastery_avg * 35 +
            recent_accuracy * 30 +
            mock_trend * 20 +
            mistake_resolution * 15
        )

        return ConfidenceIndex(
            score=confidence,
            level=self._confidence_level(confidence),
            advice=self._generate_advice(confidence, kp_mastery_avg, recent_accuracy)
        )

    def _confidence_level(self, score: float) -> str:
        if score >= 80:
            return "excellent"  # 准备充分
        elif score >= 60:
            return "good"       # 准备较好
        elif score >= 40:
            return "moderate"   # 还需努力
        else:
            return "needs_work" # 需要加强
```

```sql
    review_order        INT,                    -- 复习顺序

    review_count        INT NOT NULL DEFAULT 0,
    practice_count      INT NOT NULL DEFAULT 0,
    mistake_revisit_count INT NOT NULL DEFAULT 0,

    status              VARCHAR(20) NOT NULL DEFAULT 'pending',
    -- pending → reviewing → practiced → mastered → skipped

    first_reviewed_at   DATETIME,
    last_reviewed_at    DATETIME,
    mastered_at         DATETIME,

    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_session_kp (prep_session_id, knowledge_point_id),
    INDEX idx_user_status (user_id, status),
    INDEX idx_priority (prep_session_id, priority_score DESC),
    FOREIGN KEY (prep_session_id) REFERENCES exam_prep_session(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 8. 错误处理

### 8.1 错误码定义

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| `EXAM_PREP_001` | 备考会话不存在 | 返回列表或创建新会话 |
| `EXAM_PREP_002` | 已有活跃备考会话 | 提示先完成或放弃当前会话 |
| `EXAM_PREP_003` | 考试日期已过 | 提示会话已过期 |
| `EXAM_PREP_004` | 诊断试卷生成失败（考点数据不足） | 跳过诊断，使用现有学情 |
| `EXAM_PREP_005` | 冲刺计划生成失败（时间不足） | 提示调整考试日期或降低强度 |
| `EXAM_PREP_006` | 超出备考功能额度 | 引导升级会员 |
| `EXAM_PREP_007` | 模考试卷生成失败 | 重试或降级为普通练习 |
| `EXAM_PREP_008` | 知识点依赖循环检测 | 忽略循环依赖，使用线性排序 |
| `EXAM_PREP_009` | 计划调整冲突（调整过于频繁） | 限制调整频率，最少间隔2小时 |
| `EXAM_PREP_010` | 模考未完成就查看报告 | 提示先完成模考 |

### 8.2 降级策略

```
[正常链路]
  诊断测评 → 冲刺计划 → 专题训练 → 模拟考试 → 考前冲刺
      │
      ▼ (考点数据不足 / AI服务不可用)
[降级链路]
  跳过诊断 → 基于现有学情生成计划 → 标准练习 → 历年真题 → 速查回顾
      │
      ▼ (数据库负载高 / Redis不可用)
[最低保障]
  读取本地缓存学情 → 生成基础计划 → 离线题库练习 → 本地错题重练
```
