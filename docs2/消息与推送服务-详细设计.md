# 消息与推送服务 - 详细设计

## 1. 模块概述

消息与推送服务是 PrimeTop 的核心基础设施模块，负责将系统事件、学习提醒、家长通知、运营消息等通过多渠道（APP 端内消息、Push 推送、短信、邮件）及时送达用户。该模块被学习规划、错题复习、家长中心、会员订阅、系统运营等多个业务模块依赖。

### 1.1 功能范围

| 功能 | 说明 |
|------|------|
| 端内消息 | APP 内消息中心，支持系统通知、学习提醒、互动消息 |
| Push 推送 | 基于 FCM/APNs 的移动端推送通知 |
| 消息模板 | 消息内容模板管理，支持变量替换 |
| 消息偏好 | 用户可配置接收哪些类型的消息、免打扰时段 |
| 定时/延迟发送 | 支持消息定时发送和延迟投递 |
| 批量群发 | 运营活动、系统公告的批量推送 |
| 已读/未读管理 | 消息阅读状态管理与未读计数 |
| 家长代收 | 低龄学生的消息同步推送给绑定的家长 |
| 推送记录与统计 | 消息发送记录、送达率、打开率统计 |

### 1.2 依赖关系

```
学习规划模块 ──→ 学习任务提醒
错题整理模块 ──→ 遗忘曲线复习提醒
学情分析模块 ──→ 周报/月报生成通知
家长中心   ──→ 孩子学习动态推送
会员订阅   ──→ 续费提醒、权益到期通知
内容运营后台 ──→ 运营活动、系统公告
```

## 2. 数据结构定义

### 2.1 消息模板（msg_template）

```sql
CREATE TABLE msg_template (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    code            VARCHAR(64) NOT NULL UNIQUE COMMENT '模板编码，如 STUDY_PLAN_REMINDER',
    name            VARCHAR(128) NOT NULL COMMENT '模板名称',
    category        VARCHAR(32) NOT NULL COMMENT '分类：system|study|parent|marketing',
    title_template  VARCHAR(256) NOT NULL COMMENT '标题模板，支持 ${variable} 占位',
    body_template   TEXT NOT NULL COMMENT '正文模板，支持 ${variable} 占位',
    push_enabled    TINYINT(1) DEFAULT 1 COMMENT '是否支持 Push 推送',
    inapp_enabled   TINYINT(1) DEFAULT 1 COMMENT '是否支持端内消息',
    sms_enabled     TINYINT(1) DEFAULT 0 COMMENT '是否支持短信',
    email_enabled   TINYINT(1) DEFAULT 0 COMMENT '是否支持邮件',
    priority        TINYINT DEFAULT 5 COMMENT '优先级 1-10，数字越大越优先',
    expire_minutes  INT DEFAULT 0 COMMENT '消息过期时间(分钟)，0=不过期',
    max_daily_count INT DEFAULT 0 COMMENT '同一用户每日最大发送数，0=不限',
    status          TINYINT DEFAULT 1 COMMENT '1=启用 0=禁用',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_category (category),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='消息模板';
```

### 2.2 消息记录（msg_record）

```sql
CREATE TABLE msg_record (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    msg_id          VARCHAR(64) NOT NULL UNIQUE COMMENT '消息唯一ID (UUID)',
    template_id     BIGINT COMMENT '关联模板ID，系统消息可为空',
    template_code   VARCHAR(64) COMMENT '模板编码快照',
    user_id         BIGINT NOT NULL COMMENT '接收用户ID',
    student_id      BIGINT COMMENT '关联学生ID（家长消息场景）',
    category        VARCHAR(32) NOT NULL COMMENT '分类：system|study|parent|marketing',
    msg_type        VARCHAR(32) NOT NULL COMMENT '消息类型标识',
    title           VARCHAR(256) NOT NULL COMMENT '消息标题',
    body            TEXT NOT NULL COMMENT '消息正文',
    extra_data      JSON COMMENT '扩展数据，如跳转链接、附件等',
    channels        VARCHAR(64) NOT NULL COMMENT '投递渠道，逗号分隔：inapp,push,sms,email',

    -- 状态
    status          VARCHAR(16) NOT NULL DEFAULT 'pending' COMMENT 'pending|sent|delivered|read|failed|expired',
    is_read         TINYINT(1) DEFAULT 0 COMMENT '是否已读',
    read_at         DATETIME COMMENT '阅读时间',

    -- 投递详情
    push_msg_id     VARCHAR(128) COMMENT '第三方推送平台消息ID',
    push_platform   VARCHAR(16) COMMENT 'apns|fcm|hms',
    sent_at         DATETIME COMMENT '发送时间',
    delivered_at    DATETIME COMMENT '送达时间',

    -- 定时发送
    schedule_at     DATETIME COMMENT '计划发送时间，NULL=立即发送',

    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_user_status (user_id, status, created_at),
    INDEX idx_user_read (user_id, is_read, created_at),
    INDEX idx_schedule (schedule_at, status),
    INDEX idx_category_type (category, msg_type),
    INDEX idx_student (student_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='消息记录';
```

## 3. API 接口设计

### 3.1 端内消息 API

#### 3.1.1 获取消息列表

```
GET /api/v1/messages
```

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| category | string | 否 | 消息分类筛选 |
| is_read | boolean | 否 | 已读/未读筛选 |
| cursor | string | 否 | 游标分页 token |
| limit | int | 否 | 每页条数，默认 20，最大 50 |

**响应：**

```json
{
  "code": 0,
  "data": {
    "messages": [
      {
        "msg_id": "msg_01HXYZ123",
        "category": "study",
        "msg_type": "STUDY_PLAN_REMINDER",
        "title": "今日学习任务提醒",
        "body": "小明，你今天有3个学习任务待完成，预计用时45分钟。",
        "extra_data": {
          "action": "navigate",
          "route": "/study-plan/today"
        },
        "is_read": false,
        "created_at": "2026-05-19T08:00:00+08:00"
      }
    ],
    "unread_count": 5,
    "cursor": "eyJpZCI6MTAwfQ==",
    "has_more": true
  }
}
```

#### 3.1.2 标记消息已读

```
PUT /api/v1/messages/{msg_id}/read
```

**响应：**

```json
{
  "code": 0,
  "data": {
    "msg_id": "msg_01HXYZ123",
    "is_read": true,
    "read_at": "2026-05-19T09:30:00+08:00"
  }
}
```

#### 3.1.3 批量标记已读

```
PUT /api/v1/messages/batch-read
```

```json
{
  "msg_ids": ["msg_01HXYZ123", "msg_01HXYZ456"],
  "category": "study",
  "mark_all": false
}
```

支持三种模式：
- 传 `msg_ids` 数组：标记指定消息
- 传 `category`：标记该分类下所有消息
- 传 `mark_all: true`：标记所有消息已读

#### 3.1.4 获取未读数

```
GET /api/v1/messages/unread-count
```

**响应：**

```json
{
  "code": 0,
  "data": {
    "total": 5,
    "by_category": {
      "system": 1,
      "study": 2,
      "parent": 1,
      "marketing": 1
    }
  }
}
```

#### 3.1.5 删除消息

```
DELETE /api/v1/messages/{msg_id}
```

### 3.2 推送管理 API

#### 3.2.1 注册设备 Token

```
POST /api/v1/messages/device-token
```

```json
{
  "device_id": "ABCD-1234-EFGH",
  "platform": "ios",
  "token": "apns_token_string_here",
  "bundle_id": "com.primetop.app"
}
```

**处理逻辑：**
1. 同一 `user_id + device_id` 记录存在则更新 token
2. 若 token 被其他用户占用，标记旧记录失效
3. 返回注册成功状态

#### 3.2.2 注销设备 Token

```
DELETE /api/v1/messages/device-token
```

```json
{
  "device_id": "ABCD-1234-EFGH"
}
```

用户退出登录或卸载时调用。

#### 3.2.3 更新消息偏好

```
PUT /api/v1/messages/preferences
```

```json
{
  "push_enabled": true,
  "dnd_start": "22:00",
  "dnd_end": "07:00",
  "categories": {
    "study": { "push": true, "inapp": true },
    "marketing": { "push": false, "inapp": true }
  }
}
```

#### 3.2.4 获取消息偏好

```
GET /api/v1/messages/preferences
```

### 3.3 内部发送接口（服务间调用）

#### 3.3.1 发送单条消息

```
POST /api/internal/v1/messages/send
```

```json
{
  "template_code": "STUDY_PLAN_REMINDER",
  "user_id": 10001,
  "student_id": 10001,
  "template_vars": {
    "student_name": "小明",
    "task_count": 3,
    "estimated_minutes": 45
  },
  "channels": ["inapp", "push"],
  "schedule_at": null,
  "priority": 5,
  "extra_data": {
    "action": "navigate",
    "route": "/study-plan/today"
  },
  "fallback_channels": ["sms"]
}
```

**处理流程：**
1. 加载模板，用 `template_vars` 渲染标题和正文
2. 检查用户偏好（是否关闭该分类推送、是否在免打扰时段）
3. 检查每日发送上限（模板级别 `max_daily_count`）
4. 按渠道发送：优先 inapp，其次 push，降级到 fallback
5. 记录 `msg_record`

**响应：**

```json
{
  "code": 0,
  "data": {
    "msg_id": "msg_01HXYZ789",
    "status": "sent",
    "channels_sent": ["inapp", "push"]
  }
}
```

#### 3.3.2 批量发送消息

```
POST /api/internal/v1/messages/batch-send
```

```json
{
  "template_code": "WEEKLY_STUDY_REPORT",
  "user_ids": [10001, 10002, 10003],
  "batch_vars": {
    "10001": { "student_name": "小明", "study_hours": 12.5 },
    "10002": { "student_name": "小红", "study_hours": 8.0 },
    "10003": { "student_name": "小华", "study_hours": 15.0 }
  },
  "channels": ["inapp", "push"],
  "schedule_at": "2026-05-19T20:00:00+08:00"
}
```

#### 3.3.3 按条件群发

```
POST /api/internal/v1/messages/broadcast
```

```json
{
  "template_code": "SUMMER_CAMPAIGN",
  "target_type": "segment",
  "target_rule": {
    "grade_range": ["初中一年级", "初中二年级"],
    "membership_status": "free",
    "last_active_days": 30
  },
  "channels": ["inapp", "push"],
  "schedule_at": "2026-06-01T10:00:00+08:00"
}
```

## 4. 消息场景定义

### 4.1 学习类消息

| 消息类型 | 模板编码 | 触发时机 | 投递渠道 |
|----------|----------|----------|----------|
| 学习计划提醒 | `STUDY_PLAN_REMINDER` | 每日计划开始前（可配置时间） | inapp, push |
| 任务到期提醒 | `TASK_DUE_REMINDER` | 任务截止前 1 小时 | inapp, push |
| 错题复习提醒 | `MISTAKE_REVIEW_REMINDER` | 遗忘曲线到达复习节点 | inapp, push |
| 学情周报 | `WEEKLY_STUDY_REPORT` | 每周日晚 20:00 | inapp, push |
| 学习里程碑 | `STUDY_MILESTONE` | 连续打卡/完成阶段目标 | inapp, push |
| 薄弱点预警 | `WEAK_POINT_ALERT` | 检测到新薄弱知识点 | inapp |

### 4.2 家长类消息

| 消息类型 | 模板编码 | 触发时机 | 投递渠道 |
|----------|----------|----------|----------|
| 今日学情推送 | `PARENT_DAILY_DIGEST` | 每日 20:00 | inapp, push |
| 周学情报告 | `PARENT_WEEKLY_REPORT` | 每周五 19:00 | inapp, push, email |
| 异常使用提醒 | `PARENT_USAGE_ALERT` | 超过时长限制/异常时段使用 | inapp, push, sms |
| 会员即将到期 | `PARENT_MEMBERSHIP_EXPIRY` | 到期前 3 天 | inapp, push |

### 4.3 系统类消息

| 消息类型 | 模板编码 | 触发时机 | 投递渠道 |
|----------|----------|----------|----------|
| 系统公告 | `SYSTEM_ANNOUNCEMENT` | 运营手动触发 | inapp, push |
| 版本更新 | `APP_VERSION_UPDATE` | 发布新版本 | inapp |
| 账号安全 | `ACCOUNT_SECURITY_ALERT` | 异常登录/密码修改 | inapp, push, sms |

### 4.4 营销类消息

| 消息类型 | 模板编码 | 触发时机 | 投递渠道 |
|----------|----------|----------|----------|
| 会员续费提醒 | `MEMBERSHIP_RENEWAL` | 到期前 7/3/1 天 | inapp, push |
| 活动推广 | `MARKETING_CAMPAIGN` | 运营手动/定时触发 | inapp |
| 增值服务推荐 | `VALUE_ADDED_SERVICE` | 匹配用户画像触发 | inapp |

## 5. 核心流程设计

### 5.1 消息发送主流程

```
┌─────────────────────────────────────────────────────────────┐
│                     业务模块触发消息                           │
│  (学习规划 / 错题复习 / 学情分析 / 家长中心 / 运营后台)         │
└───────────────────────┬─────────────────────────────────────┘
                        │ POST /internal/v1/messages/send
                        ▼
              ┌─────────────────────┐
              │  1. 加载消息模板      │
              │  2. 变量渲染          │
              │  3. 频率/限额检查     │
              │  4. 偏好/免打扰检查   │
              └─────────┬───────────┘
                        │
                        ▼
              ┌─────────────────────┐
              │   渠道路由决策        │
              │ inapp → push → sms  │
              └─────────┬───────────┘
                        │
            ┌───────────┼───────────┐
            ▼           ▼           ▼
     ┌──────────┐ ┌──────────┐ ┌──────────┐
     │ 端内消息  │ │ Push推送  │ │ 短信/邮件 │
     │ 写入DB   │ │ 调用推送  │ │ 调用第三方 │
     │          │ │ 平台API  │ │ 服务      │
     └────┬─────┘ └────┬─────┘ └────┬─────┘
          │            │            │
          ▼            ▼            ▼
     ┌─────────────────────────────────────┐
     │         更新 msg_record 状态          │
     │  记录发送结果、送达回执、错误信息       │
     └─────────────────────────────────────┘
```

### 5.2 推送 Token 生命周期

```
APP 启动
  │
  ▼
请求推送权限 ──(用户拒绝)──→ 记录 push_enabled=false，仅走端内消息
  │
  │(用户同意)
  ▼
获取 Device Token
  │
  ▼
POST /messages/device-token ──→ 写入/更新 msg_device_token
  │
  ▼
后续每次 APP 启动 → 检查 Token 是否变化 → 变化则重新注册
  │
  ▼
用户退出登录 → DELETE /messages/device-token → 标记 is_active=0
  │
  ▼
推送平台返回 InvalidToken → 标记 is_active=0 → 下次启动重新注册
```

### 5.3 定时消息调度

```
消息创建时 schedule_at != null
  │
  ▼
写入 msg_record (status='pending', schedule_at=指定时间)
  │
  ▼
定时扫描器 (每 30 秒执行一次)
  │
  ├── SELECT * FROM msg_record
  │   WHERE status='pending'
  │   AND schedule_at <= NOW()
  │   LIMIT 500
  │
  ▼
逐条执行发送主流程
  │
  ▼
更新 status='sent' 或 'failed'
```

### 5.4 批量群发流程

```
运营后台创建批次
  │
  ▼
写入 msg_batch (status='draft')
  │
  ▼
预计算目标用户列表
  │ target_type=all → 全量用户
  │ target_type=segment → 按条件筛选
  │ target_type=user_list → 指定用户ID列表
  │
  ▼
写入 msg_batch (user_count=N, status='scheduled')
  │
  ▼
到达 schedule_at 或手动触发发送
  │
  ▼
分批发送 (每批 100 用户)
  │  ├── 查询用户偏好 → 过滤已关闭推送的用户
  │  ├── 查询设备 Token → 过滤无效 Token
  │  ├── 查询免打扰时段 → 延迟到免打扰结束
  │  └── 执行发送 → 更新 sent_count
  │
  ▼
发送完成 → status='completed'
```

// services/message.service.ts

interface SendMessageParams {
  templateCode: string;
  userId: number;
  studentId?: number;
  templateVars: Record<string, string | number>;
  channels?: ('inapp' | 'push' | 'sms' | 'email')[];
  scheduleAt?: Date;
  priority?: number;
  extraData?: Record<string, any>;
  fallbackChannels?: ('inapp' | 'push' | 'sms' | 'email')[];
}

interface SendResult {
  msgId: string;
  status: 'sent' | 'failed' | 'pending' | 'skipped';
  channelsSent: string[];
  reason?: string;
}

class MessageService {
  constructor(
    private templateRepo: MsgTemplateRepository,
    private recordRepo: MsgRecordRepository,
    private preferenceRepo: MsgPreferenceRepository,
    private deviceTokenRepo: DeviceTokenRepository,
    private pushProvider: PushProvider,
    private smsProvider: SmsProvider,
  ) {}

  async sendMessage(params: SendMessageParams): Promise<SendResult> {
    // 1. 加载模板
    const template = await this.templateRepo.findByCode(params.templateCode);
    if (!template || template.status !== 1) {
      return { msgId: '', status: 'failed', channelsSent: [], reason: 'TEMPLATE_NOT_FOUND' };
    }

    // 2. 每日限额检查
    if (template.max_daily_count > 0) {
      const todayCount = await this.recordRepo.countTodaySent(
        params.userId, params.templateCode
      );
      if (todayCount >= template.max_daily_count) {
        return { msgId: '', status: 'skipped', channelsSent: [], reason: 'DAILY_LIMIT_EXCEEDED' };
      }
    }

    // 3. 加载用户偏好
    const pref = await this.preferenceRepo.findByUserId(params.userId);

    // 4. 确定渠道
    const desiredChannels = params.channels || ['inapp', 'push'];
    const allowedChannels = this.filterChannelsByPreference(
      desiredChannels, template, pref
    );

    if (allowedChannels.length === 0) {
      return { msgId: '', status: 'skipped', channelsSent: [], reason: 'USER_PREFERENCE_BLOCKED' };
    }

    // 5. 免打扰检查
    const inDnd = this.isInDoNotDisturb(pref);
    const finalChannels = inDnd
      ? allowedChannels.filter(c => c === 'inapp') // 免打扰时段只发端内消息
      : allowedChannels;

    // 6. 渲染模板
    const title = this.renderTemplate(template.titleTemplate, params.templateVars);
    const body = this.renderTemplate(template.bodyTemplate, params.templateVars);

    // 7. 创建消息记录
    const msgId = generateMsgId();
    const record = await this.recordRepo.create({
      msgId,
      templateId: template.id,
      templateCode: template.code,
      userId: params.userId,
      studentId: params.studentId,
      category: template.category,
      msgType: template.code,
      title,
      body,
      extraData: params.extraData,
      channels: finalChannels.join(','),
      status: params.scheduleAt ? 'pending' : 'sent',
      scheduleAt: params.scheduleAt,
    });

    // 8. 定时消息不立即发送
    if (params.scheduleAt) {
      return { msgId, status: 'pending', channelsSent: [] };
    }

    // 9. 立即发送
    const sentChannels: string[] = [];

    for (const channel of finalChannels) {
      try {
        if (channel === 'inapp') {
          // 端内消息已通过 DB 写入，无需额外操作
          sentChannels.push('inapp');
        } else if (channel === 'push') {
          await this.sendPush(params.userId, title, body, params.extraData, msgId);
          sentChannels.push('push');
        } else if (channel === 'sms') {
          await this.smsProvider.send(params.userId, body);
          sentChannels.push('sms');
        }
      } catch (err) {
        logger.error(`Channel ${channel} send failed for msg ${msgId}`, err);
        // 尝试降级渠道
        if (params.fallbackChannels?.length) {
          for (const fb of params.fallbackChannels) {
            if (!finalChannels.includes(fb) && !sentChannels.includes(fb)) {
              try {
                if (fb === 'sms') {
                  await this.smsProvider.send(params.userId, body);
                  sentChannels.push('sms');
                }
                break;
              } catch { /* fallback also failed */ }
            }
          }
        }
      }
    }

    await this.recordRepo.updateStatus(msgId, sentChannels.length > 0 ? 'sent' : 'failed');

    return { msgId, status: sentChannels.length > 0 ? 'sent' : 'failed', channelsSent: sentChannels };
  }

  private renderTemplate(template: string, vars: Record<string, any>): string {
    return template.replace(/\$\{(\w+)\}/g, (_, key) =>
      vars[key] !== undefined ? String(vars[key]) : `\${${key}}`
    );
  }

  private isInDoNotDisturb(pref: MsgPreference | null): boolean {
    if (!pref || !pref.dndStart || !pref.dndEnd) return false;
    const now = new Date();
    // 转为用户时区的当前时间
    const currentTime = now.toLocaleTimeString('en-US', { hour12: false, timeZone: pref.timezone });
    return currentTime >= pref.dndStart && currentTime < pref.dndEnd;
  }

  private async sendPush(
    userId: number, title: string, body: string,
    extraData: Record<string, any> | undefined, msgId: string
  ): Promise<void> {
    const tokens = await this.deviceTokenRepo.findActiveByUserId(userId);
    if (tokens.length === 0) throw new Error('NO_ACTIVE_TOKEN');

    for (const token of tokens) {
      await this.pushProvider.send({
        platform: token.platform,
        token: token.token,
        title,
        body,
        data: { msg_id: msgId, ...extraData },
      });
    }
  }
}

## 9. 错误处理

### 9.1 错误码定义

| 错误码 | HTTP | 说明 | 处理策略 |
|--------|------|------|----------|
| `MSG_TEMPLATE_NOT_FOUND` | 404 | 模板不存在或已禁用 | 记录日志，跳过发送 |
| `MSG_DAILY_LIMIT_EXCEEDED` | 429 | 当日发送次数已达上限 | 静默跳过，不重试 |
| `MSG_USER_PREF_BLOCKED` | 200 | 用户关闭了该渠道 | 静默跳过，不重试 |
| `MSG_DND_ACTIVE` | 200 | 用户处于免打扰时段 | 降级为端内消息 |
| `MSG_NO_ACTIVE_TOKEN` | 200 | 用户无有效推送 Token | 降级为端内消息 |
| `MSG_PUSH_PROVIDER_ERROR` | 502 | 推送平台异常 | 重试 3 次，间隔 5/30/120 秒 |
| `MSG_SMS_PROVIDER_ERROR` | 502 | 短信服务异常 | 记录失败，不重试 |
| `MSG_INVALID_TOKEN` | 200 | 推送 Token 无效（平台回执） | 标记 Token 失效 |
| `MSG_BATCH_TOO_LARGE` | 400 | 批量发送超过上限 | 拒绝并提示拆分 |
| `MSG_SCHEDULE_CONFLICT` | 409 | 同一模板同一用户存在待发定时消息 | 去重跳过 |

### 9.2 重试策略

```
发送失败 → 判断错误类型
  │
  ├── 可重试错误 (网络超时、推送平台临时异常)
  │   ├── 第1次重试：5秒后
  │   ├── 第2次重试：30秒后
  │   └── 第3次重试：120秒后 → 仍失败则标记 failed
  │
  ├── 不可重试错误 (Token无效、用户偏好关闭)
  │   └── 标记 failed，记录原因
  │
  └── 降级处理
      ├── Push 失败 → 降级到 inapp
      └── 主渠道全部失败 → 尝试 fallback_channels
```

### 9.3 Token 失效处理

```
推送平台返回 InvalidToken / NotRegistered
  │
  ▼
标记 msg_device_token.is_active = 0
  │
  ▼
记录失效时间和原因
  │
  ▼
等待用户下次启动 APP 时重新注册 Token
```

`msg_record` 是数据量增长最快的表，按以下策略分表：

- **分表维度：** 按 `user_id % 16` 分 16 张表
- **归档策略：** 超过 6 个月的消息移入归档表 `msg_record_archive`
- **端内消息列表查询** 走分表
- **管理后台统计查询** 走独立的统计汇总表或 ClickHouse

### 11.3 消息去重

对于重复触发的消息（如短时间内多次触发同一模板），采用去重机制：

```
去重键: msg:dedup:{templateCode}:{userId}:{digestHash}
TTL: 1 小时

digestHash = MDH (模板变量 JSON 的排序哈希)

SETNX 去重键 → 成功则发送，失败则跳过
```

## 12. 安全与合规

### 12.1 消息内容安全

- 所有模板内容需通过内容审核才能启用
- 动态变量渲染后的最终消息文本需经过敏感词过滤
- 营销类消息需标注"广告"或"推广"标识
- 未成年人相关消息不得包含外链（防止跳转到不安全页面）

### 12.2 推送频率限制

| 分类 | 单用户每日上限 | 说明 |
|------|----------------|------|
| system | 不限 | 系统消息 |
| study | ≤ 10 条 | 学习提醒类 |
| parent | ≤ 5 条 | 家长通知类 |
| marketing | ≤ 2 条 | 营销推广类 |

### 12.3 隐私保护

- 推送通知不显示具体学习内容（如错题内容），仅显示摘要提示
- 短信内容不包含学生具体成绩数据
- Token 存储加密，日志中脱敏
- 家长代收消息需验证绑定关系

| 指标 | 告警阈值 |
|------|----------|

| 批次发送进度停滞 | 单批次 > 30 分钟未完成 |
