# 服务端-教育内容触达转化漏斗与学习内容消费深度多维分析引擎-详细设计

## 1. 概述

### 1.1 模块定位

本引擎负责追踪和分析学生用户与教育内容交互的全链路漏斗数据，从内容被推荐/展示给用户，到用户点击查看、开始学习、持续消费、最终完成或中途放弃，逐层量化转化率和流失率，并结合内容属性（学科、难度、类型、长度、格式等）进行多维度归因分析，为内容运营团队和推荐算法提供数据反馈闭环。

### 1.2 与现有模块的边界

| 现有模块 | 关注点 | 本引擎差异 |
|---------|--------|-----------|
| `用户转化漏斗分析与增长归因引擎` | 用户注册→激活→付费的宏观漏斗 | 本引擎聚焦**内容消费**微观漏斗，对象是单条/组内容而非用户生命周期 |
| `教育内容有效性数据驱动评估` | 内容是否帮助学生达成学习目标（效果导向） | 本引擎聚焦内容是否被学生**消费完毕**（过程导向），是效果评估的前置条件 |
| `学习行为事件流与跨模块级联处理引擎` | 通用行为事件流处理基础设施 | 本引擎建立在该事件流之上，定义内容消费专属的事件模型和漏斗逻辑 |
| `统一用户行为埋点平台与事件流处理管线` | 埋点采集与传输 | 本引擎消费埋点数据，定义内容消费场景的分析模型 |
| `内容推荐与个性化推荐引擎` | 推荐什么内容给用户 | 本引擎回答"推荐了但用户看了吗？看完了吗？没看完为什么？" |

### 1.3 设计目标

1. **全链路漏斗建模**：定义内容消费的标准漏斗阶段，支持自定义漏斗节点。
2. **多维归因分析**：从内容属性、用户特征、推荐场景、时间维度等归因转化表现。
3. **实时感知**：分钟级延迟内反映内容的曝光、点击和消费情况。
4. **自动诊断**：自动识别高流失率环节和异常内容，触发告警和优化建议。
5. **A/B 测试支撑**：为内容呈现策略的 A/B 测试提供漏斗对比数据。

### 1.4 适用范围

- 覆盖所有学生端内容消费场景：同步课堂章节学习、推荐卡片、搜索结果、错题关联内容、专题训练、打卡任务等。
- 支持内容类型：图文课程、视频课程、练习测评、知识点讲解、互动课件、学习卡片等。
- 服务对象：推荐算法（反馈信号）、内容运营（内容调优）、产品（体验优化）、教研（内容质量）。

## 2. 核心概念与漏斗模型

### 2.1 标准内容消费漏斗

```
┌──────────────────────────────────────────────────────────────────────────┐
│                        内容消费漏斗 (Content Funnel)                      │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  Stage 1: IMPRESSION (曝光)                                             │
│  ├── 内容在推荐位/搜索结果/任务列表中被展示给用户                           │
│  ├── 事件: content_impression                                            │
│  └── 度量: 曝光量、曝光UV、曝光位置分布                                    │
│         │                                                                │
│         ▼ 转化率: CTR (Click-Through Rate)                               │
│                                                                          │
│  Stage 2: CLICK (点击)                                                   │
│  ├── 用户点击内容卡片/链接进入内容详情页                                    │
│  ├── 事件: content_click                                                 │
│  └── 度量: 点击量、点击UV、CTR                                            │
│         │                                                                │
│         ▼ 转化率: Start Rate (进入率)                                     │
│                                                                          │
│  Stage 3: START (开始消费)                                               │
│  ├── 用户在内容详情页中实际开始消费内容（非立即退出）                        │
│  ├── 判定条件: 停留时长 > 最小阈值 或 完成首个交互事件                       │
│  ├── 事件: content_start                                                 │
│  └── 度量: 进入率、平均首屏停留时长                                        │
│         │                                                                │
│         ▼ 转化率: Engagement Rate (深度参与率)                             │
│                                                                          │
│  Stage 4: ENGAGE (深度消费)                                              │
│  ├── 用户深度消费内容：阅读≥30%、视频观看≥30%、完成≥1道题等                  │
│  ├── 判定条件: 消费进度 ≥ 30% 或 累计交互事件数 ≥ 阈值                      │
│  ├── 事件: content_engage                                                │
│  └── 度量: 深度参与率、平均消费时长、中位消费进度                            │
│         │                                                                │
│         ▼ 转化率: Completion Rate (完成率)                                │
│                                                                          │
│  Stage 5: COMPLETE (完成消费)                                            │
│  ├── 用户完整消费内容：阅读完、视频看完、答完所有题目等                       │
│  ├── 判定条件: 消费进度 ≥ 95% 或 触发 content_complete 事件                │
│  ├── 事件: content_complete                                              │
│  └── 度量: 完成率、平均完成时长、完成用户画像                               │
│         │                                                                │
│         ▼ 转化率: Replay/Share Rate (复看/分享率)                          │
│                                                                          │
│  Stage 6: AMPLIFY (传播放大)                                             │
│  ├── 用户重新消费、收藏、分享或推荐该内容                                    │
│  ├── 事件: content_replay / content_share / content_favorite              │
│  └── 度量: 复看率、分享率、收藏率                                          │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

### 2.2 漏斗节点自定义扩展

不同内容类型有不同的消费行为定义，系统支持通过配置文件自定义漏斗节点判定规则。

```yaml
# 漏斗配置示例
funnel_configs:
  VIDEO_COURSE:
    stages:
      IMPRESSION:
        event: content_impression
      CLICK:
        event: content_click
      START:
        event: content_start
        condition: "video_play AND play_duration_ms >= 3000"
      ENGAGE:
        event: content_engage
        condition: "play_duration_ms >= total_duration * 0.3"
      COMPLETE:
        event: content_complete
        condition: "play_duration_ms >= total_duration * 0.95 OR video_ended == true"
    
  TEXT_COURSE:
    stages:
      IMPRESSION:
        event: content_impression
      CLICK:
        event: content_click
      START:
        event: content_start
        condition: "scroll_depth >= 0.1 OR dwell_time_ms >= 5000"
      ENGAGE:
        event: content_engage
        condition: "scroll_depth >= 0.3 OR dwell_time_ms >= 30000"
      COMPLETE:
        event: content_complete
        condition: "scroll_depth >= 0.95 OR read_finished == true"
    
  PRACTICE_QUIZ:
    stages:
      IMPRESSION:
        event: content_impression
      CLICK:
        event: content_click
      START:
        event: content_start
        condition: "first_question_rendered == true"
      ENGAGE:
        event: content_engage
        condition: "answered_count >= total_questions * 0.3"
      COMPLETE:
        event: content_complete
        condition: "answered_count >= total_questions"
    
  INTERACTIVE_COURSEWARE:
    stages:
      IMPRESSION:
        event: content_impression
      CLICK:
        event: content_click
      START:
        event: content_start
        condition: "first_interaction == true"
      ENGAGE:
        event: content_engage
        condition: "interaction_count >= 3 AND dwell_time_ms >= 15000"
      COMPLETE:
        event: content_complete
        condition: "all_slides_viewed == true OR progress >= 0.95"
```

### 2.3 消费深度评分模型

除了离散的漏斗阶段，系统还计算一个连续的 **消费深度评分 (Consumption Depth Score, CDS)**，取值 0~100，用于精细量化用户对内容的消费深度。

```
CDS = w1 × progress_score + w2 × dwell_score + w3 × interaction_score + w4 × focus_score

其中:
  progress_score  = 实际消费进度 (0~1) × 100
  dwell_score     = min(actual_dwell / expected_dwell, 1) × 100
  interaction_score = min(interaction_count / expected_interactions, 1) × 100
  focus_score     = (1 - background_ratio) × 100  // 非后台播放占比

默认权重:
  w1 = 0.40, w2 = 0.25, w3 = 0.20, w4 = 0.15
```

## 3. 数据结构定义

### 3.1 核心数据表

#### 3.1.1 content_funnel_event（内容消费漏斗事件表）

存储用户与内容交互的原始事件，是漏斗分析的基础数据。

```sql
CREATE TABLE content_funnel_event (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '自增主键',
    event_id        VARCHAR(64) NOT NULL UNIQUE COMMENT '事件唯一ID (雪花算法)',
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    student_profile_id BIGINT NOT NULL COMMENT '学生档案ID (含年级学科信息)',
    content_id      VARCHAR(64) NOT NULL COMMENT '内容ID',
    content_type    VARCHAR(32) NOT NULL COMMENT '内容类型: VIDEO_COURSE/TEXT_COURSE/PRACTICE_QUIZ/...',
    subject         VARCHAR(16) NOT NULL COMMENT '学科: CHINESE/MATH/ENGLISH/...',
    stage           VARCHAR(32) NOT NULL COMMENT '漏斗阶段: IMPRESSION/CLICK/START/ENGAGE/COMPLETE/AMPLIFY',
    event_type      VARCHAR(64) NOT NULL COMMENT '事件类型: content_impression/content_click/...',
    
    -- 曝光上下文
    source_module   VARCHAR(32) COMMENT '曝光来源模块: RECOMMEND/SEARCH/HOMEPAGE/TASK/ERROR_BOOK/...',
    source_position VARCHAR(32) COMMENT '曝光位置: BANNER/CARD_LIST/DETAIL_RELATED/...',
    recommend_id    VARCHAR(64) COMMENT '推荐批次ID (关联推荐引擎)',
    ab_test_id      VARCHAR(64) COMMENT 'A/B测试实验ID',
    ab_variant      VARCHAR(32) COMMENT 'A/B测试变体: CONTROL/TREATMENT_A/...',
    
    -- 消费度量
    progress        DECIMAL(5,4) DEFAULT 0 COMMENT '消费进度 0~1',
    dwell_time_ms   INT DEFAULT 0 COMMENT '停留时长(毫秒)',
    interaction_count INT DEFAULT 0 COMMENT '交互事件次数',
    focus_time_ms   INT DEFAULT 0 COMMENT '前台聚焦时长(毫秒)',
    background_time_ms INT DEFAULT 0 COMMENT '后台播放时长(毫秒)',
    cds_score       DECIMAL(5,2) COMMENT '消费深度评分 (0~100)',
    
    -- 设备与环境
    device_id       VARCHAR(64) COMMENT '设备ID',
    platform        VARCHAR(16) COMMENT '平台: ANDROID/iOS/WEB/...',
    app_version     VARCHAR(32) COMMENT 'App版本号',
    network_type    VARCHAR(16) COMMENT '网络类型: WIFI/4G/5G/...',
    
    -- 时间
    occurred_at     DATETIME(3) NOT NULL COMMENT '事件发生时间(毫秒精度)',
    server_time     DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '服务端接收时间',
    day_partition   DATE NOT NULL COMMENT '日期分区键 (按occurred_at)',
    hour_bucket     INT NOT NULL COMMENT '小时桶 0-23',
    
    INDEX idx_content_day (content_id, day_partition),
    INDEX idx_user_day (user_id, day_partition),
    INDEX idx_stage_content (stage, content_id, day_partition),
    INDEX idx_source_module (source_module, content_id, day_partition),
    INDEX idx_recommend (recommend_id),
    INDEX idx_ab_test (ab_test_id, ab_variant)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='内容消费漏斗事件表'
PARTITION BY RANGE COLUMNS(day_partition) (
    PARTITION p202607 VALUES LESS THAN ('2026-08-01'),
    PARTITION p202608 VALUES LESS THAN ('2026-09-01'),
    PARTITION p_max VALUES LESS THAN (MAXVALUE)
);
```

#### 3.1.2 content_funnel_daily（内容漏斗日聚合表）

按天聚合每个内容的漏斗各阶段 UV/PV，供实时查询和看板展示。

```sql
CREATE TABLE content_funnel_daily (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    stat_date       DATE NOT NULL COMMENT '统计日期',
    content_id      VARCHAR(64) NOT NULL COMMENT '内容ID',
    content_type    VARCHAR(32) NOT NULL COMMENT '内容类型',
    subject         VARCHAR(16) NOT NULL COMMENT '学科',
    
    -- 各阶段PV
    impression_pv   INT DEFAULT 0 COMMENT '曝光PV',
    click_pv        INT DEFAULT 0 COMMENT '点击PV',
    start_pv        INT DEFAULT 0 COMMENT '开始消费PV',
    engage_pv       INT DEFAULT 0 COMMENT '深度消费PV',
    complete_pv     INT DEFAULT 0 COMMENT '完成消费PV',
    replay_pv       INT DEFAULT 0 COMMENT '复看PV',
    share_pv        INT DEFAULT 0 COMMENT '分享PV',
    favorite_pv     INT DEFAULT 0 COMMENT '收藏PV',
    
    -- 各阶段UV (去重)
    impression_uv   INT DEFAULT 0 COMMENT '曝光UV',
    click_uv        INT DEFAULT 0 COMMENT '点击UV',
    start_uv        INT DEFAULT 0 COMMENT '开始消费UV',
    engage_uv       INT DEFAULT 0 COMMENT '深度消费UV',
    complete_uv     INT DEFAULT 0 COMMENT '完成消费UV',
    replay_uv       INT DEFAULT 0 COMMENT '复看UV',
    share_uv        INT DEFAULT 0 COMMENT '分享UV',
    favorite_uv     INT DEFAULT 0 COMMENT '收藏UV',
    
    -- 转化率 (基于UV)
    ctr             DECIMAL(6,4) COMMENT '点击率 = click_uv / impression_uv',
    start_rate      DECIMAL(6,4) COMMENT '进入率 = start_uv / click_uv',
    engage_rate     DECIMAL(6,4) COMMENT '深参率 = engage_uv / start_uv',
    completion_rate DECIMAL(6,4) COMMENT '完成率 = complete_uv / start_uv',
    overall_rate    DECIMAL(6,4) COMMENT '总转化率 = complete_uv / impression_uv',
    
    -- 消费度量
    avg_dwell_ms    INT COMMENT '平均停留时长(毫秒)',
    avg_cds_score   DECIMAL(5,2) COMMENT '平均消费深度评分',
    median_progress DECIMAL(5,4) COMMENT '中位消费进度',
    
    -- 来源分布 (JSON)
    source_distribution JSON COMMENT '{"RECOMMEND": 0.35, "SEARCH": 0.25, ...}',
    
    -- 异常标记
    is_anomaly      TINYINT DEFAULT 0 COMMENT '是否异常: 完成率骤降、曝光骤降等',
    anomaly_type    VARCHAR(64) COMMENT '异常类型: COMPLETION_DROP/EXPOSURE_DROP/...',
    
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_date_content (stat_date, content_id),
    INDEX idx_date_subject (stat_date, subject),
    INDEX idx_date_type (stat_date, content_type),
    INDEX idx_anomaly (stat_date, is_anomaly)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='内容漏斗日聚合表';
```

#### 3.1.4 content_dropoff_analysis（内容流失点分析表）

存储内容在细粒度进度区间的流失分布，帮助定位内容中导致用户放弃的具体位置。

```sql
CREATE TABLE content_dropoff_analysis (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    stat_date       DATE NOT NULL,
    content_id      VARCHAR(64) NOT NULL,
    content_type    VARCHAR(32) NOT NULL,
    
    -- 进度区间 (10等分: 0-10%, 10-20%, ..., 90-100%)
    progress_bucket VARCHAR(16) NOT NULL COMMENT '进度区间: P_0_10/P_10_20/.../P_90_100',
    bucket_order    INT NOT NULL COMMENT '区间序号 0-9',
    
    -- 流失度量
    enter_count     INT DEFAULT 0 COMMENT '进入该区间的用户数',
    drop_count      INT DEFAULT 0 COMMENT '在该区间流失的用户数 (未进入下一区间)',
    drop_rate       DECIMAL(6,4) COMMENT '该区间流失率 = drop_count / enter_count',
    
    -- 流失原因分布 (JSON)
    drop_reasons    JSON COMMENT '{"USER_EXIT": 0.45, "APP_BACKGROUND": 0.30, "TIMEOUT": 0.25}',
    
    -- 关联的媒体位置 (视频/音频内容的秒数区间)
    media_start_sec INT COMMENT '对应媒体开始秒数',
    media_end_sec   INT COMMENT '对应媒体结束秒数',
    
    UNIQUE KEY uk_date_content_bucket (stat_date, content_id, progress_bucket),
    INDEX idx_date_content (stat_date, content_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='内容流失点分析表';
```


### 5.2 漏斗阶段判定

```java
public class FunnelStageResolver {
    private final Map<String, FunnelConfig> funnelConfigMap;

    public FunnelStage resolve(RawBehaviorEvent event) {
        FunnelConfig config = funnelConfigMap.get(event.getContentType());
        if (config == null) return null;

        // 1. 事件类型直接映射
        String stage = mapEventTypeToStage(event.getEventType());
        if (stage != null) return FunnelStage.of(stage);

        // 2. 条件判定进入更深阶段
        ContentConsumptionContext ctx = getContext(event);
        if (!ctx.isStageRecorded("ENGAGE") 
            && evaluateCondition(config.getStage("ENGAGE"), ctx)) {
            return FunnelStage.of("ENGAGE");
        }
        if (!ctx.isStageRecorded("COMPLETE") 
            && evaluateCondition(config.getStage("COMPLETE"), ctx)) {
            return FunnelStage.of("COMPLETE");
        }
        return null;
    }

    private String mapEventTypeToStage(String eventType) {
        switch (eventType) {
            case "content_impression": return "IMPRESSION";
            case "content_click": return "CLICK";
            case "content_start": return "START";
            case "content_complete": return "COMPLETE";
            case "content_replay":
            case "content_share":
            case "content_favorite": return "AMPLIFY";
            default: return null;
        }
    }
}
```

### 5.3 消费深度评分(CDS)

```java
public class ConsumptionDepthScoreCalculator {
    // CDS = 0.40×progress + 0.25×dwell + 0.20×interaction + 0.15×focus
    private static final double[] WEIGHTS = {0.40, 0.25, 0.20, 0.15};

    public static double calculate(double progress, int dwellMs, int expectedDwellMs,
            int interactionCount, int expectedInteractions, int focusMs, int totalMs) {
        double progressScore = Math.min(progress, 1.0) * 100;
        double dwellScore = expectedDwellMs > 0 
            ? Math.min((double) dwellMs / expectedDwellMs, 1.0) * 100 : 0;
        double interactionScore = expectedInteractions > 0
            ? Math.min((double) interactionCount / expectedInteractions, 1.0) * 100 : 0;
        double focusScore = totalMs > 0 ? (double) focusMs / totalMs * 100 : 100;
        
        return WEIGHTS[0]*progressScore + WEIGHTS[1]*dwellScore 
             + WEIGHTS[2]*interactionScore + WEIGHTS[3]*focusScore;
    }
}
```

### 5.4 异常检测

```java
public class FunnelAnomalyDetector {
    private static final double[] THRESHOLDS = {0.15, 0.30, 0.50, 0.70}; // LOW~CRITICAL
    
    public List<FunnelAnomaly> detect(LocalDate date) {
        List<FunnelAnomaly> anomalies = new ArrayList<>();
        for (String contentId : funnelDailyRepository.findActiveContentIds(date)) {
            FunnelDaily today = funnelDailyRepository.findByDateAndContent(date, contentId);
            if (today.getStartUv() < 50) continue;
            
            FunnelBaseline baseline = funnelDailyRepository
                .calculateBaseline(contentId, date.minusDays(7), date.minusDays(1));
            
            checkMetric(anomalies, contentId, date, "ctr", today.getCtr(), baseline.getCtr());
            checkMetric(anomalies, contentId, date, "completion_rate", 
                today.getCompletionRate(), baseline.getCompletionRate());
            checkMetric(anomalies, contentId, date, "cds_score",
                today.getAvgCdsScore().doubleValue(), baseline.getAvgCdsScore());
        }
        anomalyRepository.batchInsert(anomalies);
        return anomalies;
    }
    
    private void checkMetric(List<FunnelAnomaly> result, String contentId, 
            LocalDate date, String metric, double current, double baseline) {
        if (baseline <= 0) return;
        double deviation = (current - baseline) / baseline;
        if (deviation > -THRESHOLDS[0]) return;
        
        result.add(FunnelAnomaly.builder()
            .contentId(contentId).statDate(date)
            .anomalyType(metric.toUpperCase() + "_DROP")
            .currentValue(current).baselineValue(baseline)
            .deviationPct(deviation * 100)
            .severity(classify(deviation))
            .status("OPEN").build());
    }
}
```

### 5.5 流失点分析批处理

```java
public class DropoffAnalysisJob {
    // 每天凌晨执行，将消费会话映射到10个进度区间
    public void execute(LocalDate statDate) {
        for (String contentId : sessionRepository.findActiveContentIds(statDate)) {
            List<ConsumptionSession> sessions = sessionRepository
                .findByContentAndDate(contentId, statDate);
            int[] enter = new int[10], drop = new int[10];
            
            for (ConsumptionSession s : sessions) {
                int idx = Math.min((int)(s.getMaxProgress() * 10), 9);
                for (int i = 0; i <= idx; i++) enter[i]++;
                if (s.getMaxProgress() < 0.95 && "ABANDONED".equals(s.getStatus()))
                    drop[idx]++;
            }
            
            List<ContentDropoff> list = new ArrayList<>();
            for (int i = 0; i < 10; i++) {
                if (enter[i] == 0) continue;
                list.add(ContentDropoff.builder()
                    .statDate(statDate).contentId(contentId)
                    .progressBucket("P_" + i*10 + "_" + (i+1)*10)
                    .enterCount(enter[i]).dropCount(drop[i])
                    .dropRate((double) drop[i] / enter[i]).build());
            }
            dropoffRepository.batchInsert(list);
        }
    }
}
```
