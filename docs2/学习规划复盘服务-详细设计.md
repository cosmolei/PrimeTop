# 学习规划复盘服务 - 详细设计文档

## 1. 模块概述

### 1.1 功能定位

学习规划复盘服务（Study Plan Review Service）负责在**每日、每周、每月、冲刺计划结束或目标达成时**，对学习计划的执行情况进行结构化汇总，生成可阅读的复盘报告，并给出下一阶段学习建议。它是“目标 → 计划 → 执行 → **反馈**”闭环中的反馈节点，直接决定学习规划模块能否持续优化。

核心职责：

1. **周期汇总**：统计任务完成率、实际学习时长、各学科投入占比、错题改善情况。
2. **能力变化追踪**：对比计划周期开始与结束时的知识点掌握度，识别提升、稳定和下降的知识点。
3. **AI 解读生成**：基于汇总数据调用大模型生成自然语言复盘总结与改进建议。
4. **报告持久化与查询**：将复盘报告持久化，支持学生、家长、管理后台查询历史复盘。
5. **触发调度**：支持自动触发（定时任务）、手动触发、计划完成自动触发三种模式。

### 1.2 适用范围

| 学段 | 支持情况 | 说明 |
|------|----------|------|
| 幼儿 | 不支持 | 幼儿阶段无学习规划模块 |
| 小学 | 支持 | 以周/月复盘为主，内容简明 |
| 初中 | 支持 | 支持周/月/冲刺复盘 |
| 高中 | 支持 | 支持日/周/月/冲刺/考前复盘 |

### 1.3 关键术语

| 术语 | 说明 |
|------|------|
| Review（复盘） | 一次计划周期结束后的总结报告 |
| Review Type | 复盘类型：`daily`、`weekly`、`monthly`、`sprint`、`goal_completion`、`manual` |
| Snapshot | 知识点掌握度、错题状态在复盘周期开始和结束时的快照 |
| Insight | AI 生成的自然语言解读与建议 |
| Action | 系统根据复盘结果生成的下一步行动建议 |

### 1.4 依赖模块

| 依赖模块 | 依赖说明 |
|----------|----------|
| 学习规划模块 | 获取计划、目标、任务、执行记录 |
| 学情分析模块 | 获取知识点掌握度、能力画像 |
| 错题服务 | 获取错题状态、复习次数、订正结果 |
| 用户服务 | 获取学生学段、年级、教材版本 |
| AI 服务 | 生成自然语言复盘总结 |
| 消息服务 | 推送复盘完成通知 |
| 文件服务 | 生成分享卡片图片 |

### 2.4 索引设计说明

- `idx_user_created`：支持“我的复盘”列表按时间倒序查询。
- `idx_plan_type`：支持查询某个计划的所有周/月复盘。
- `idx_status_scheduled`：定时任务扫描待执行的复盘作业。
- `idx_idempotency`：防止同一计划同一周期重复生成复盘。

## 4. 关键代码示例

### 4.1 复盘数据聚合（Python + SQL）

```python
from typing import List, Dict
from datetime import date

class ReviewDataAggregator:
    def __init__(self, db, learning_analytics, mistake_service):
        self.db = db
        self.analytics = learning_analytics
        self.mistake_service = mistake_service

    def aggregate(self, plan_id: str, user_id: str,
                  start_date: date, end_date: date) -> Dict:
        # 1. 任务统计
        task_stats = self.db.execute(
            """
            SELECT status, task_type,
                   COUNT(*) AS cnt,
                   SUM(estimated_minutes) AS planned_min,
                   SUM(actual_minutes) AS actual_min
            FROM study_task
            WHERE plan_id = %s
              AND scheduled_date BETWEEN %s AND %s
            GROUP BY status, task_type
            """, (plan_id, start_date, end_date)
        ).fetchall()

        # 2. 知识点掌握度快照
        kp_snapshots = self.analytics.get_mastery_snapshots(
            user_id=user_id,
            kp_ids=self._get_plan_kp_ids(plan_id),
            start_date=start_date,
            end_date=end_date
        )

        # 3. 错题改善快照
        mistake_snapshots = self.mistake_service.get_mistake_snapshots(
            user_id=user_id,
            start_date=start_date,
            end_date=end_date
        )

        return {
            "task_stats": self._normalize_task_stats(task_stats),
            "knowledge_snapshots": kp_snapshots,
            "mistake_snapshots": mistake_snapshots,
        }

    def _normalize_task_stats(self, rows) -> List[Dict]:
        summary = {}
        for r in rows:
            t = r["task_type"]
            summary.setdefault(t, {
                "task_type": t,
                "total": 0, "completed": 0, "skipped": 0,
                "overdue": 0, "planned_minutes": 0, "actual_minutes": 0
            })
            summary[t]["total"] += r["cnt"]
            if r["status"] == "completed":
                summary[t]["completed"] += r["cnt"]
            elif r["status"] == "skipped":
                summary[t]["skipped"] += r["cnt"]
            elif r["status"] == "overdue":
                summary[t]["overdue"] += r["cnt"]
            summary[t]["planned_minutes"] += r["planned_min"] or 0
            summary[t]["actual_minutes"] += r["actual_min"] or 0
        return list(summary.values())
```

```python
3. 以 JSON 格式输出：{{"summary": "...", "suggestions": ["..."]}}"""

    def build(self, review_data: Dict, student_profile: Dict) -> str:
        return self.TEMPLATE.format(
            grade=student_profile.get("grade_name"),
            subjects=", ".join(student_profile.get("subjects", [])),
            total_tasks=review_data["total_tasks"],
            completed_tasks=review_data["completed_tasks"],
            skipped_tasks=review_data["skipped_tasks"],
            overdue_tasks=review_data["overdue_tasks"],
            planned_minutes=review_data["planned_minutes"],
            actual_minutes=review_data["actual_minutes"],
            subject_distribution=self._format_subject_distribution(
                review_data["subject_distribution"]
            ),
            improved_kps=self._format_kps(review_data["improved_kps"]),
            stable_kps=self._format_kps(review_data["stable_kps"]),
            declined_kps=self._format_kps(review_data["declined_kps"]),
            total_mistakes=review_data["total_mistakes"],
            resolved_mistakes=review_data["resolved_mistakes"],
        )
```

### 4.3 复盘报告生成服务

```python
class PlanReviewService:
    def __init__(self, aggregator, ai_client, db, job_repo):
        self.aggregator = aggregator
        self.ai = ai_client
        self.db = db
        self.job_repo = job_repo

    def create_review(self, plan_id, review_type, start_date, end_date,
                      trigger_type, idempotency_key) -> str:
        # 幂等检查
        if self.job_repo.exists_by_idempotency(idempotency_key):
            raise ReviewAlreadyExistsException(idempotency_key)

        review_id = generate_id("rev")
        job_id = generate_id("job")

        with self.db.transaction() as tx:
            tx.execute(
                """INSERT INTO plan_review
                (review_id, plan_id, user_id, review_type, status, start_date, end_date)
                SELECT %s, %s, user_id, %s, 'pending', %s, %s
                FROM study_plan WHERE plan_id = %s""",
                (review_id, plan_id, review_type, start_date, end_date, plan_id)
            )
            tx.execute(
                """INSERT INTO review_generation_job
                (job_id, review_id, trigger_type, scheduled_at, idempotency_key)
                VALUES (%s, %s, %s, NOW(), %s)""",
                (job_id, review_id, trigger_type, idempotency_key)
            )

        # 异步提交生成任务
        self._submit_generation_job(job_id, review_id)
        return review_id

    def generate_report(self, review_id: str):
        review = self.db.fetchone(
            "SELECT * FROM plan_review WHERE review_id = %s", (review_id,)
        )
        self._update_review_status(review_id, "generating")
        self.job_repo.update_status(review["job_id"], "running")

        try:
            data = self.aggregator.aggregate(
                review["plan_id"], review["user_id"],
                review["start_date"], review["end_date"]
            )
            ai_result = self._call_ai_summary(data, review["user_id"])
            actions = self._derive_actions(data, ai_result)

            self._persist_snapshots(review_id, data)
            self._update_review_with_result(review_id, data, ai_result, actions)
            self._update_review_status(review_id, "ready")
            self.job_repo.update_status(review["job_id"], "success")
            self._notify_user(review["user_id"], review_id)

        except AIException as e:
            self._handle_ai_failure(review_id, review["job_id"], str(e), data)
        except Exception as e:
            self.job_repo.mark_failed(review["job_id"], str(e))
            self._update_review_status(review_id, "failed")

    def _handle_ai_failure(self, review_id, job_id, error_msg, data):
        # 降级：使用规则化总结
        fallback_summary = self._build_fallback_summary(data)
        self._update_review_with_result(review_id, data, fallback_summary, [])
        self._update_review_status(review_id, "ready")
        self.job_repo.update_status(job_id, "success")
```

```python
from celery import Celery

app = Celery('review_tasks')

@app.task(bind=True, max_retries=3)
def scheduled_review_generation(self):
    """每日 21:30 扫描到期的日/周/月计划并触发复盘。"""
    due_jobs = ReviewJobRepository().find_due_jobs(

        status='scheduled',

        except Exception as exc:
            self.retry(exc=exc, countdown=60)
```

```python
# 创建到期复盘任务（每日 21:00 执行）
@app.task
def create_due_review_jobs():
    """
    为今天到期的计划创建复盘任务：
    - 日计划：每天到期
    - 周计划：周日到期
    - 月计划：每月最后一天到期
    - 冲刺计划：end_date 当天到期
    """
    db.execute("""
        INSERT INTO review_generation_job (job_id, review_id, trigger_type, scheduled_at, idempotency_key)
        SELECT generate_id('job'), generate_id('rev'), 'auto_schedule', NOW(),
               CONCAT(plan_id, ':', end_date, ':', plan_type)
        FROM study_plan
        WHERE status = 'active'
          AND end_date = CURDATE()
          AND NOT EXISTS (
              SELECT 1 FROM review_generation_job
              WHERE idempotency_key = CONCAT(study_plan.plan_id, ':', study_plan.end_date, ':', study_plan.plan_type)
          )
    """)
    # 同时创建 plan_review 主记录，状态为 pending
    db.execute("""
        INSERT INTO plan_review (review_id, plan_id, user_id, review_type, status, start_date, end_date)
        SELECT generate_id('rev'), plan_id, user_id, plan_type, 'pending', start_date, end_date
        FROM study_plan
        WHERE status = 'active'
          AND end_date = CURDATE()
          AND NOT EXISTS (
              SELECT 1 FROM plan_review
              WHERE plan_review.plan_id = study_plan.plan_id
                AND plan_review.end_date = study_plan.end_date
          )
    """)
```

## 5. 状态流转

### 5.1 复盘记录状态机

```text
pending ──(开始生成)──▶ generating ──(成功)──▶ ready
   │                       │
   │                       │(失败且可重试)
   │                       ▼
   │                    failed ──(重试成功)──▶ ready
   │                       │
   │                       │(超过最大重试)
   ▼                       ▼
(手动取消)            cancelled

ready ──(用户查看)──▶ viewed
ready ──(用户忽略)──▶ dismissed
```

**状态说明：**

| 状态 | 说明 |
|------|------|
| pending | 已创建，等待调度 |
| generating | 正在聚合数据或调用 AI |
| ready | 报告已生成，可查看 |
| viewed | 用户已查看 |
| dismissed | 用户手动忽略 |
| failed | 生成失败，不可自动恢复 |
| cancelled | 被取消（如计划中途取消） |

### 5.2 复盘生成作业状态机

```text
scheduled ──(Worker 领取)──▶ running ──(成功)──▶ success
                                │
                                │(失败)
                                ▼
                              failed ──(重试)──▶ running
                                │
                                │(超过重试)
                                ▼
                              dead_letter
```

### 5.3 触发条件

| 触发类型 | 触发时机 | 生成 review_type |
|----------|----------|------------------|
| auto_schedule | 定时任务扫描到计划 end_date | 与 plan_type 一致 |
| plan_complete | 用户完成最后一个任务时 | 与 plan_type 一致 |
| manual | 用户手动点击“复盘” | manual |
| goal_completion | 目标达成或到期时 | goal_completion |

## 6. 错误处理

### 6.1 异常场景

| 异常场景 | 处理方式 | 返回给用户 |
|----------|----------|------------|
| 计划不存在 | 抛 `PlanNotFoundException` | 404，错误码 `PLAN_NOT_FOUND` |
| 复盘已存在 | 幂等键命中，返回已有 review_id | 200，返回已有任务 |
| 周期内无任务 | 生成空报告，AI 提示“暂无数据” | 200，报告状态 ready |
| AI 调用超时 | 重试 3 次，失败后使用规则化总结 | 200，fallback 报告 |
| AI 输出非法 JSON | 用正则提取 summary/suggestions，失败则降级 | 200，fallback 报告 |
| 知识点数据缺失 | 跳过该知识点，不影响整体报告 | 200，报告中标注数据缺失 |
| 生成任务 Worker 崩溃 | 定时扫描 running 超时任务，重新投递 | 异步恢复 |
| 用户越权访问 | 校验 `user_id` 与 JWT 中用户一致 | 403，错误码 `ACCESS_DENIED` |

### 6.2 错误码定义

| 错误码 | 含义 | HTTP 状态 |
|--------|------|-----------|
| 0 | 成功 | 200 |
| 400100 | 复盘已存在 | 200（返回已有） |
| 400101 | 计划不存在 | 404 |
| 400102 | 复盘不存在 | 404 |
| 400103 | 复盘尚未生成完成 | 202 |
| 400104 | 复盘已失败 | 500 |
| 400105 | 无权访问该复盘 | 403 |
| 400106 | 生成任务超时 | 202 |
| 400107 | 参数非法（日期不合法等） | 400 |

### 6.3 降级策略

1. **AI 服务降级**：当 AI 生成失败或超时时，使用规则化模板生成总结：
   - 完成率 ≥ 80%：鼓励型模板
   - 完成率 50%-80%：提醒型模板
   - 完成率 < 50%：关怀型模板 + 建议减少任务量
2. **数据缺失降级**：缺少知识点掌握度时，用任务完成率代替能力变化描述。
3. **高并发降级**：在高峰期限制手动触发频率，自动触发任务进入队列延迟处理。

## 7. 性能优化

### 7.1 预聚合策略

- 将“每日任务完成数、实际学习时长”在每日定时任务中预计算到 `study_plan_daily_stats` 表，复盘时直接读取，避免扫描全量任务表。
- 知识点掌握度快照由学情分析模块每日生成，复盘时直接取最新快照。

### 7.2 缓存策略

- 已生成的复盘报告缓存到 Redis，Key：`review:rev_id:report`，TTL 7 天。
- 列表接口缓存 Key：`reviews:list:{plan_id}:{page}:{size}`，TTL 1 小时，写入/删除时失效。
- AI 生成结果写入缓存，避免重复调用。

### 7.3 异步处理

- 复盘生成必须走异步队列（Celery / RabbitMQ），避免阻塞用户请求。
- 手动触发时返回 `review_id` 和 `job_id`，前端轮询 `/reviews/{review_id}` 查询状态。

### 7.4 数据库优化

- `study_task` 表增加 `(plan_id, scheduled_date, status)` 复合索引。
- 大数据量时按 `user_id` 分表或归档历史复盘数据。

## 8. 安全与合规

### 8.1 权限控制

- 所有复盘查询必须校验 `user_id` 与当前登录学生一致，家长需通过 `parent_binding` 关系校验。
- 管理后台查询支持按 `user_id` 检索，但需记录审计日志。

### 8.2 数据脱敏

- 向家长端展示时，可保留学习时长和完成率，但隐藏具体 AI 对话内容。
- 分享卡片不包含用户真实姓名、学校等敏感信息。

### 8.3 内容安全

- AI 生成的复盘总结和建议需经过内容安全审核，避免制造焦虑、歧视或不当引导。
- 对未成年人使用鼓励性语言，避免成绩排名、同辈比较等可能引发压力的内容。

### 8.4 审计与日志

- 记录复盘生成、查看、分享、删除操作到审计日志。
- 保留 AI 原始输出 30 天，便于质量分析和人工复核。
