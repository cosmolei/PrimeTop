# 数据埋点与关键指标系统 - 详细设计

> 对应原始设计文档第 16 节"关键指标设计"，以及各模块中提到的行为记录、学习统计和运营分析需求。

## 1. 概述

### 1.1 设计目标

建立统一的埋点采集、传输、存储和分析体系，覆盖用户行为、学习过程、AI 调用质量、商业化转化和系统性能五大维度，使产品、运营和研发团队能够：

1. 实时监控核心业务指标
2. 漏斗分析转化与流失
3. 归因分析学习效果与留存
4. 监控 AI 回答质量和调用成本
5. 支撑 A/B 实验和产品决策

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 最小侵入 | 埋点 SDK 与业务逻辑解耦，不侵入核心代码路径 |
| 语义化事件 | 事件名和属性采用统一命名规范，见名知义 |
| 批量上传 | 客户端批量聚合 + 压缩上传，减少网络开销 |
| 离线优先 | 本地 SQLite 缓存，网络恢复后重传，不丢事件 |
| 隐私合规 | 未成年用户 ID 脱敏，不采集明文姓名/手机号 |
| 可扩展 | 新增事件只需声明 schema，无需改动管道 |

### 1.3 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 客户端 SDK | 自研 Flutter Plugin | 轻量，支持分龄参数过滤 |
| 消息队列 | Kafka | 高吞吐，多消费组 |
| 实时处理 | Flink | 窗口聚合、漏斗计算 |
| 离线数仓 | ClickHouse | 列存储，亚秒级 OLAP 查询 |
| 可视化 | 自建看板 + Grafana | 运营看板 + 系统监控看板 |
| 元数据管理 | 自研 Event Registry | 事件 schema 注册与版本管理 |

### 2.1 数据流说明

1. **采集**：业务模块调用 `Tracker.track(event, properties)` 触发事件
2. **本地缓存**：事件写入 SQLite `event_queue` 表，附加序列号
3. **批量上传**：每 30 秒或积累 50 条触发上传，gzip 压缩
4. **网关鉴权**：JWT 校验 + 设备指纹校验 + 限流（单设备 100 条/秒）
5. **Ingest 服务**：Schema 校验 → 去重（device_id + seq_id）→ 设备/用户属性富化 → 写 Kafka
6. **实时计算**：Flink 消费 Kafka，按分钟/小时窗口聚合，结果写 Redis
7. **离线存储**：Flink 同步写入 ClickHouse 全量明细表，供 OLAP 查询
8. **指标查询**：指标服务 API 从 Redis（实时）或 ClickHouse（历史）读取


- 全小写 + 下划线：`question_id`, `subject_code`

- 数量后缀 `_count`：`question_count`, `hint_count`
- 比例/率后缀 `_rate`：`accuracy_rate`

## 5. 客户端 SDK 设计

### 5.1 Tracker 接口

```dart
/// 埋点追踪器 — 单例，全局唯一
class Tracker {
  static final Tracker instance = Tracker._();

  late final EventStore _store;
  late final EventUploader _uploader;
  late final UserContext _userContext;
  late final DeviceContext _deviceContext;

  Tracker._();

  /// 初始化（APP 启动时调用一次）
  Future<void> init({required String appId}) async {
    _store = EventStore();
    await _store.open();
    _uploader = EventUploader(store: _store, appId: appId);
    _userContext = UserContext();
    _deviceContext = await DeviceContext.collect();

    // 启动定时上传
    _uploader.startPeriodic(
      interval: const Duration(seconds: 30),
      batchSize: 50,
    );
  }

  /// 追踪事件
  void track(
    String eventName, {
    Map<String, dynamic>? properties,
    int? eventVersion,
  }) {
    final event = _buildEvent(eventName, properties ?? {}, eventVersion ?? 1);
    _store.insert(event);
  }

  /// 设置用户 ID（登录后）
  void identify(String userId) {
    _userContext.userId = userId;
  }

  /// 清除用户 ID（登出后）
  void reset() {
    _userContext.userId = null;
    _userContext.sessionId = _newSessionId();
  }

  /// 构建完整事件
  EventEntity _buildEvent(
    String eventName,
    Map<String, dynamic> properties,
    int version,
  ) {
    return EventEntity(
      eventId: _uuidV7(),
      eventName: eventName,
      eventVersion: version,
      timestamp: DateTime.now().toUtc(),
      deviceId: _deviceContext.deviceId,
      userId: _userContext.userId,
      sessionId: _userContext.sessionId,
      seqId: _store.nextSeqId(),
      platform: _deviceContext.platform,
      appVersion: _deviceContext.appVersion,
      osVersion: _deviceContext.osVersion,
      deviceModel: _deviceContext.deviceModel,
      network: _deviceContext.network,
      timezone: _deviceContext.timezone,
      properties: properties,
    );
  }
}
```

### 5.2 本地存储（EventStore）

```dart
/// 本地 SQLite 事件队列
class EventStore {
  late Database _db;
  int _seqCounter = 0;

  Future<void> open() async {
    _db = await openDatabase(
      join(await getDatabasesPath(), 'analytics.db'),
      version: 1,
      onCreate: (db, version) async {
        await db.execute('''
          CREATE TABLE event_queue (
            seq_id       INTEGER PRIMARY KEY,
            event_id     TEXT NOT NULL,
            event_name   TEXT NOT NULL,
            payload      TEXT NOT NULL,   -- JSON
            created_at   INTEGER NOT NULL, -- ms since epoch
            retry_count  INTEGER NOT NULL DEFAULT 0,
            status       TEXT NOT NULL DEFAULT 'pending'  -- pending/sending/sent/failed
          )
        ''');
        await db.execute(
          'CREATE INDEX idx_event_queue_status ON event_queue(status, created_at)',
        );
      },
    );
    // 恢复上次未发送的记录
    await _db.execute(
      "UPDATE event_queue SET status = 'pending' WHERE status = 'sending'",
    );
    // 获取当前最大 seq_id
    final row = await _db.rawQuery(
      'SELECT MAX(seq_id) as max_seq FROM event_queue',
    );
    _seqCounter = row.first['max_seq'] as int? ?? 0;
  }

  int nextSeqId() => ++_seqCounter;

  Future<void> insert(EventEntity event) async {
    _db.insert('event_queue', {
      'seq_id': event.seqId,
      'event_id': event.eventId,
      'event_name': event.eventName,
      'payload': jsonEncode(event.toJson()),
      'created_at': event.timestamp.millisecondsSinceEpoch,
      'status': 'pending',
    });
  }

  /// 取出一批待发送事件
  Future<List<QueuedEvent>> fetchPending({int limit = 50}) async {
    final rows = await _db.query(
      'event_queue',
      where: "status = 'pending'",
      orderBy: 'seq_id ASC',
      limit: limit,
    );
    return rows.map((r) => QueuedEvent.fromRow(r)).toList();
  }

  /// 标记已发送
  Future<void> markSent(List<int> seqIds) async {
    if (seqIds.isEmpty) return;
    final placeholders = List.filled(seqIds.length, '?').join(',');
    await _db.execute(
      "UPDATE event_queue SET status = 'sent' WHERE seq_id IN ($placeholders)",
      seqIds.map((e) => e).toList(),
    );
    // 清理已发送记录（保留最近 1 小时用于去重）
    final cutoff = DateTime.now()
        .subtract(const Duration(hours: 1))
        .millisecondsSinceEpoch;
    await _db.delete(
      'event_queue',
      where: "status = 'sent' AND created_at < ?",
      whereArgs: [cutoff],
    );
  }

  /// 标记发送失败，增加重试计数
  Future<void> markFailed(List<int> seqIds) async {
    if (seqIds.isEmpty) return;
    final placeholders = List.filled(seqIds.length, '?').join(',');
    await _db.execute(
      '''
      UPDATE event_queue
      SET status = 'pending', retry_count = retry_count + 1
      WHERE seq_id IN ($placeholders) AND retry_count < 5
      ''',
      seqIds.map((e) => e).toList(),
    );
    // 超过重试次数的标记为永久失败
    await _db.execute(
      "UPDATE event_queue SET status = 'failed' WHERE status = 'pending' AND retry_count >= 5",
    );
  }

  /// 清理超过 7 天的失败记录
  Future<void> purgeOld() async {
    final cutoff = DateTime.now()
        .subtract(const Duration(days: 7))
        .millisecondsSinceEpoch;
    await _db.delete(
      'event_queue',
      where: "created_at < ?",
      whereArgs: [cutoff],
    );
  }
}

class QueuedEvent {

  final String eventId;
  final String eventName;
  final String payload;

    required this.seqId,
    required this.eventId,
```

```dart
class EventUploader {
  final EventStore _store;
  final String _appId;
  Timer? _timer;
  bool _isUploading = false;

  EventUploader({required EventStore store, required String appId})
      : _store = store,
        _appId = appId;

  void startPeriodic({
    required Duration interval,
    required int batchSize,
  }) {
    _timer?.cancel();
    _timer = Timer.periodic(interval, (_) => _doUpload(batchSize));
    // APP 启动后立即尝试一次
    _doUpload(batchSize);
  }

  void stop() {
    _timer?.cancel();
    _timer = null;
  }

  Future<void> _doUpload(int batchSize) async {
    if (_isUploading) return;
    _isUploading = true;
    try {
      final events = await _store.fetchPending(limit: batchSize);
      if (events.isEmpty) return;

      final response = await _sendBatch(events);
      if (response.statusCode == 200 || response.statusCode == 202) {
        await _store.markSent(events.map((e) => e.seqId).toList());
      } else {
        await _store.markFailed(events.map((e) => e.seqId).toList());
      }
    } catch (e) {
      // 网络异常，下次重试
    } finally {
      _isUploading = false;
    }
  }

  Future<Response> _sendBatch(List<QueuedEvent> events) async {
    final payloads = events.map((e) => jsonDecode(e.payload)).toList();
    final body = gzip.encode(utf8.encode(jsonEncode({
      'app_id': _appId,
      'events': payloads,
    })));

    return dio.post(
      '/api/v1/events/batch',
      data: Stream.fromIterable([body]),
      options: Options(
        headers: {\n          'Content-Type': 'application/json',
          'Content-Encoding': 'gzip',
          'X-Batch-Size': events.length,
        },
        responseType: ResponseType.json,
      ),
    );
  }
}
```

### 6.2 Ingest 服务（事件摄入）

```python
# event_ingest/service.py

import hashlib
import time
from dataclasses import dataclass
from typing import Any

import structlog
from kafka import KafkaProducer
from jsonschema import validate, ValidationError

logger = structlog.get_logger()


# 事件注册表 — 每个事件名对应一个 JSON Schema
EVENT_SCHEMAS: dict[str, dict] = {
    "ai_chat.send_message": {
        "type": "object",
        "required": ["session_id", "input_type"],
        "properties": {
            "session_id": {"type": "string"},
            "input_type": {"type": "string", "enum": ["text", "voice", "image"]},
            "char_count": {"type": "integer", "minimum": 0},
            "subject_hint": {"type": "string"},
        },
        "additionalProperties": False,
    },
    # ... 其他事件 schema（由 Event Registry 自动加载）
}


@dataclass
class IngestResult:
    accepted: int = 0
    rejected: int = 0
    dropped_duplicate: int = 0


class EventIngestService:
    def __init__(self, kafka_producer: KafkaProducer, topic: str = "events"):
        self._producer = kafka_producer
        self._topic = topic
        self._dedup_window: dict[str, float] = {}  # key → timestamp

    def ingest_batch(self, events: list[dict], device_id: str) -> IngestResult:
        result = IngestResult()
        now = time.time()

        # 清理过期去重窗口（1 小时）
        expired = [k for k, ts in self._dedup_window.items() if now - ts > 3600]
        for k in expired:
            del self._dedup_window[k]

        for event in events:
            # 1. 基础校验
            event_name = event.get("event_name", "")
            if not event_name or "." not in event_name:
                result.rejected += 1
                logger.warn("invalid_event_name", event_name=event_name)
                continue

            # 2. 去重（device_id + seq_id）
            seq_id = event.get("seq_id")
            dedup_key = f"{device_id}:{seq_id}"
            if dedup_key in self._dedup_window:
                result.dropped_duplicate += 1
                continue
            self._dedup_window[dedup_key] = now

            # 3. Schema 校验
            schema = EVENT_SCHEMAS.get(event_name)
            if schema:
                try:
                    validate(instance=event.get("properties", {}), schema=schema)
                except ValidationError as e:
                    result.rejected += 1
                    logger.warn(
                        "schema_validation_failed",
                        event_name=event_name,
                        error=str(e),
                    )
                    continue

            # 4. 富化 — 注入服务端时间、IP 地域等
            event["server_timestamp"] = time.strftime(
                "%Y-%m-%dT%H:%M:%S.000Z", time.gmtime()
            )
            event["ingest_version"] = 1

            # 5. 写入 Kafka
            partition_key = event.get("user_id") or device_id
            self._producer.send(
                self._topic,
                key=partition_key.encode(),
                value=event,
            )
            result.accepted += 1

        return result
```

```java
// RealtimeMetricsJob.java — 分钟级实时指标
public class RealtimeMetricsJob extends StreamExecutionEnvironment {

    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env = StreamExecutionEnvironment.getExecutionEnvironment();
        env.setParallelism(6);

        // Kafka source
        KafkaSource<String> source = KafkaSource.<String>builder()
            .setBootstrapServers("kafka:9092")
            .setTopics("events")
            .setGroupId("flink-realtime-metrics")
            .setStartingOffsets(OffsetsInitializer.latest())
            .setValueOnlyDeserializer(new SimpleStringSchema())
            .build();

        DataStream<String> raw = env.fromSource(
            source, WatermarkStrategy.noWatermarks(), "events-source"
        );

        DataStream<Event> events = raw
            .map(json -> objectMapper.readValue(json, Event.class))
            .filter(e -> e.getUserId() != null);

        // --- DAU (当日累计) ---
        events
            .keyBy(e -> "global")
            .window(GlobalWindows.create())
            .trigger(new DailyTrigger())
            .aggregate(new DistinctCountAgg())
            .addSink(new RedisSink<>("metrics:dau:" + today()));

        // --- AI QPS (1 分钟滚动) ---
        events
            .filter(e -> "ai_chat.receive_response".equals(e.getEventName()))
            .keyBy(e -> "global")
            .window(TumblingProcessingTimeWindows.of(Time.minutes(1)))
            .aggregate(new CountAgg())
            .addSink(new RedisSink<>("metrics:ai_qps:" + currentMinute()));

        // --- 平均 TTFT (5 分钟滑动) ---
        events
            .filter(e -> "system.ai_model_call".equals(e.getEventName()))
            .keyBy(e -> "global")
            .window(SlidingProcessingTimeWindows.of(Time.minutes(5), Time.minutes(1)))
            .aggregate(new AvgAgg("ttft_ms"))
            .addSink(new RedisSink<>("metrics:avg_ttft:" + currentMinute()));

        env.execute("RealtimeMetricsJob");
    }
}
```

## 11. Event Registry（事件注册表）

### 11.1 事件注册格式

每个事件在注册表中声明 schema，用于校验、文档生成和权限控制：

```yaml
# event_registry/ai_chat/send_message.yaml
event_name: ai_chat.send_message
version: 2
status: active
owner: team-ai
description: "用户在 AI 对话中发送消息"
since: "2026-05-01"

properties:
  session_id:
    type: string
    required: true
    description: "对话会话 ID"
  input_type:
    type: string
    required: true
    enum: [text, voice, image]
    description: "输入方式"
  char_count:
    type: integer
    required: false
    minimum: 0
    description: "输入文本字符数"
  subject_hint:
    type: string
    required: false
    description: "用户选择的学科提示"

pii_fields: []  # 无 PII 字段

# 指标消费
metrics:
  - name: ai_messages_per_user_daily
    aggregation: count
    group_by: [user_id, date]
```

### 11.2 版本管理规则

1. 新增属性：`event_version` 递增，老属性不动 → **向后兼容**
2. 删除属性：设置 `deprecated: true`，保留 90 天后再移除 → **需过渡期**
3. 修改属性类型：视为删除旧 + 新增新，两个版本并行 → **需通知下游**
4. 所有变更通过 PR 合入 `event_registry/` 目录，CI 自动校验

## 12. 状态流转

### 12.1 事件生命周期

```
客户端触发 → 本地 SQLite (pending)
    ↓ 批量上传
网关鉴权 → Ingest 校验
    ├─ 校验通过 → Kafka (accepted)
    │              ├─ Flink 实时计算 → Redis (metrics)
    │              └─ Flink → ClickHouse (archived)
    ├─ 校验失败 → 死信队列 (rejected)
    └─ 去重跳过 → 不写入 (dropped_duplicate)
```

### 12.2 异常处理

| 异常场景 | 处理策略 |
|---------|----------|
| 客户端离线 | SQLite 缓存，上线后重传，最多保留 7 天 |
| 上传失败（网络） | 重试最多 5 次，指数退避（1s/2s/4s/8s/16s） |
| 上传失败（429 限流） | 退避 60 秒后重试 |
| 上传失败（413 过大） | 减半 batch size 重试 |
| Schema 校验失败 | 记录到死信队列，告警通知 owner |
| Kafka 写入失败 | Ingest 服务本地暂存，Kafka 恢复后补发 |
| ClickHouse 写入延迟 | 实时指标从 Redis 读取，不受影响 |
| Redis 宕机 | Flink 降级为仅写 ClickHouse，查询走 CH |
| 事件积压（Kafka lag > 10min） | 告警，增加 Flink 并行度 |

## 13. 性能预估与容量规划

### 13.1 日事件量预估

| 阶段 | DAU | 人均事件/日 | 日事件量 | 峰值 QPS |
|------|-----|------------|---------|----------|
| MVP | 1 万 | 100 | 100 万 | ~200 |
| V1.0 | 10 万 | 120 | 1,200 万 | ~2,400 |
| V2.0 | 50 万 | 150 | 7,500 万 | ~15,000 |

### 13.2 存储预估

单条事件压缩后约 200~500 字节。

| 阶段 | 日存储 | 月存储 | ClickHouse 180天 |
|------|--------|--------|------------------|
| MVP | ~300 MB | ~9 GB | ~54 GB |
| V1.0 | ~3.6 GB | ~108 GB | ~648 GB |
| V2.0 | ~22 GB | ~660 GB | ~4 TB |

### 13.3 扩容策略

1. Kafka 分区数按峰值 QPS × 2 预留
2. Flink 并行度 = Kafka 分区数
3. ClickHouse 单 shard 可承受 ~10 万 inserts/s，V1.0 足够
4. V2.0 考虑 ClickHouse 双 shard 集群 + 副本
