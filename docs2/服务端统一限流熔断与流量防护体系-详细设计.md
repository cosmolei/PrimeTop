# 服务端统一限流、熔断与流量防护体系 - 详细设计

## 1. 概述

### 1.1 设计目标

为 PrimeTop 平台建立统一的流量防护体系，覆盖 API 网关层限流、服务间调用熔断、过载保护与自动降级，确保在高并发、AI 模型响应波动、恶意刷量等场景下系统依然稳定可用。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 分层防护 | 网关层 → 服务层 → 资源层，逐级拦截异常流量 |
| 精细粒度 | 支持按用户、IP、设备、接口、租户等多维度限流 |
| 快速失败 | 超出限额立即拒绝，不占用下游资源 |
| 优雅降级 | 限流触发时返回友好提示与重试建议，非粗暴 500 |
| 可观测 | 限流/熔断事件全链路可追踪，支持实时监控与告警 |
| 动态可调 | 限流阈值支持配置中心热更新，无需重启 |

### 1.3 适用范围

- 所有对外暴露的 HTTP/gRPC API
- 服务间内部调用链路
- AI 模型调用通道
- 消息推送、定时任务等异步通道的并发控制

## 2. 整体架构

### 2.1 分层流量防护架构

```
                         ┌─────────────────────────┐
                         │       客户端请求          │
                         └────────────┬─────────────┘
                                      │
                         ┌────────────▼─────────────┐
                         │   L1: API 网关层限流       │
                         │  (OpenResty + Lua)        │
                         │  - IP 维度全局限流          │
                         │  - 接口维度全局限流          │
                         │  - 恶意请求识别与黑名单     │
                         └────────────┬─────────────┘
                                      │
                         ┌────────────▼─────────────┐
                         │   L2: 业务服务层限流       │
                         │  (注解 + Redis)           │
                         │  - 用户维度精细限流         │
                         │  - 会员等级差异化           │
                         │  - AI 调用额度控制          │
                         └────────────┬─────────────┘
                                      │
                         ┌────────────▼─────────────┐
                         │   L3: 服务间调用熔断        │
                         │  (Circuit Breaker)        │
                         │  - 慢调用比例熔断           │
                         │  - 异常比例熔断             │
                         │  - 连续失败熔断             │
                         └────────────┬─────────────┘
                                      │
                         ┌────────────▼─────────────┐
                         │   L4: 资源层过载保护       │
                         │  - 数据库连接池排队         │
                         │  - Redis 连接数限制         │
                         │  - AI 模型并发槽位控制      │
                         └──────────────────────────┘
```

### 2.2 技术选型

| 层级 | 技术方案 | 说明 |
|------|----------|------|
| L1 网关层 | OpenResty (Lua) + 自定义限流插件 | 高性能、低延迟 |
| L2 服务层 | 自定义注解 + Redis + Lua 脚本 | 细粒度控制、与 Spring 集成 |
| L3 熔断层 | Sentinel / Resilience4j | 成熟稳定、规则动态加载 |
| L4 资源层 | 连接池配置 + 信号量隔离 | 防止资源耗尽 |

### 3.4 Redis Key 设计

| Key 模式 | 类型 | 用途 | TTL |
|----------|------|------|-----|
| `ratelimit:sw:{ruleId}:{dimKey}` | Sorted Set | 滑动窗口计数器 | windowSeconds + 1 |
| `ratelimit:fw:{ruleId}:{dimKey}` | String | 固定窗口计数器 | windowSeconds |
| `ratelimit:tb:{ruleId}:{dimKey}` | Hash | 令牌桶 | windowSeconds × 2 |
| `circuit:{ruleId}:{service}` | Hash | 熔断器状态 | 无（持久） |
| `ratelimit:events:{date}` | List | 限流事件日志 | 7 天 |
| `ratelimit:blacklist:ip` | Set | IP 黑名单 | 24h |
| `circuit:events:{date}` | List | 熔断事件日志 | 7 天 |

## 4. 网关层限流（L1）

### 4.1 Lua 限流核心模块

```lua
-- gateway_rate_limiter.lua

local redis = require "resty.redis"
local cjson = require "cjson"
local _M = {}

-- JWT payload 提取（网关层仅做粗筛，不验证签名）
function _M.extract_user_info()
    local auth = ngx.var.http_authorization
    if not auth then return nil end
    local token = auth:match("Bearer%s+(.+)")
    if not token then return nil end
    local payload_b64 = token:match("%w+%.(%w+)%.%w+")
    if not payload_b64 then return nil end

    -- 补齐 Base64 padding 并解码
    local pad = 4 - #payload_b64 % 4
    if pad < 4 then payload_b64 = payload_b64 .. string.rep("=", pad) end
    payload_b64 = payload_b64:gsub("-", "+"):gsub("_", "/")
    local payload = cjson.decode(ngx.decode_base64(payload_b64))
    return { userId = payload.sub, memberTier = payload.member_tier or "FREE" }
end

-- 滑动窗口限流（Redis Pipeline 原子操作）
function _M.sliding_window_check(rule_id, dim_key, max_req, window_sec)
    local red = redis:new()
    red:set_timeouts(100, 100, 100)
    local ok, err = red:connect("redis-cluster", 6379)
    if not ok then
        ngx.log(ngx.ERR, "redis connect failed: ", err)
        return true, 0, max_req  -- Redis 故障时放行，避免限流成为单点
    end

    local now = ngx.now() * 1000
    local window_start = now - window_sec * 1000
    local key = "ratelimit:sw:" .. rule_id .. ":" .. dim_key

    red:init_pipeline()
    red:zremrangebyscore(key, "-inf", window_start)  -- 移除过期记录
    red:zcard(key)                                     -- 统计当前计数
    red:zadd(key, now, ngx.var.request_id)             -- 添加当前请求
    red:expire(key, window_sec + 1)                    -- 设置过期
    local res = red:commit_pipeline()

    red:set_keepalive(10000, 100)
    return res[2] < max_req, res[2], max_req
end

-- 令牌桶限流（Redis Lua 脚本原子操作）
function _M.token_bucket_check(rule_id, dim_key, capacity, rate_per_sec)
    local red = redis:new()
    red:set_timeouts(100, 100, 100)
    local ok, err = red:connect("redis-cluster", 6379)
    if not ok then return true, capacity end

    local key = "ratelimit:tb:" .. rule_id .. ":" .. dim_key
    local now = ngx.now()

    local script = [[
        local key = KEYS[1]
        local capacity = tonumber(ARGV[1])
        local rate = tonumber(ARGV[2])
        local now = tonumber(ARGV[3])
        local data = redis.call('HMGET', key, 'tokens', 'last_refill')
        local tokens = tonumber(data[1]) or capacity
        local last = tonumber(data[2]) or now
        tokens = math.min(capacity, tokens + (now - last) * rate)
        if tokens >= 1 then
            tokens = tokens - 1
            redis.call('HMSET', key, 'tokens', tokens, 'last_refill', now)
            return {1, math.floor(tokens)}
        else
            redis.call('HMSET', key, 'tokens', tokens, 'last_refill', now)
            return {0, math.floor(tokens)}
        end
    ]]

    local res = red:eval(script, 1, key, capacity, rate_per_sec, now)
    red:set_keepalive(10000, 100)
    return res[1] == 1, res[2]
end

-- 优雅拒绝响应
function _M.reject(info)
    ngx.status = 429
    ngx.header["Content-Type"] = "application/json; charset=utf-8"
    ngx.header["Retry-After"] = tostring(info.retry_after or 60)
    ngx.header["X-RateLimit-Limit"] = tostring(info.limit)
    ngx.header["X-RateLimit-Remaining"] = "0"
    ngx.say(cjson.encode({
        code = "RATE_LIMITED",
        message = "请求过于频繁，请稍后再试",
        detail = string.format("请求已超过限制（%d次/%d秒），请在 %d 秒后重试",
            info.limit, info.window, info.retry_after or 60),
        retryAfter = info.retry_after or 60,
        childFriendlyMessage = "你学得太认真啦！让 AI 老师休息一下，马上回来～"
    }))
    ngx.exit(429)
end

return _M
```

```nginx
server {
    listen 443 ssl;
    server_name api.primetop.com;

    limit_req_zone $binary_remote_addr zone=ip_global:100m rate=50r/s;
    limit_req_zone $request_uri zone=ai_global:50m rate=200r/s;
    limit_conn_zone $binary_remote_addr zone=conn_limit:100m;
    limit_conn conn_limit 100;

    # ── AI 对话接口 ──
    location ~ ^/api/v1/ai/ {
        limit_req zone=ai_global burst=50 nodelay;
        access_by_lua_block {
            local L = require "gateway_rate_limiter"
            local u = L.extract_user_info()
            if u then
                local m = 30  -- FREE: 30次/分
                if u.memberTier == "YEARLY" then m = 120
                elseif u.memberTier == "MONTHLY" then m = 60 end
                local ok, cnt, lim = L.sliding_window_check("ai-user", "u:"..u.userId, m, 60)
                if not ok then L.reject({limit=lim, window=60, retry_after=60}) end
            end
        }
        proxy_pass http://ai-service;
    }

    # ── 拍题 OCR 接口（高成本操作）──
    location ~ ^/api/v1/photo/ {
        limit_req zone=ip_global burst=20 nodelay;
        access_by_lua_block {
            local L = require "gateway_rate_limiter"
            local u = L.extract_user_info()
            if u then
                local m = 10  -- FREE: 10次/小时
                if u.memberTier == "YEARLY" then m = 50
                elseif u.memberTier == "MONTHLY" then m = 30 end
                local ok, cnt, lim = L.sliding_window_check("photo-user", "u:"..u.userId, m, 3600)
                if not ok then L.reject({limit=lim, window=3600, retry_after=300}) end
            end
        }
        proxy_pass http://photo-service;
    }

    # ── 注册/登录（防暴力破解）──
    location ~ ^/api/v1/auth/(register|login|sms) {

            if not ok then L.reject({limit=lim, window=3600, retry_after=1800}) end
        }
        proxy_pass http://user-service;
    }

    # ── 通用接口 ──
    location /api/v1/ {
        limit_req zone=ip_global burst=100 nodelay;
        proxy_pass http://backend;
    }
}
```

### 5.1 限流注解定义

```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RateLimit {
    String ruleId();
    LimitDimension[] dimensions() default {LimitDimension.USER};
    LimitAlgorithm algorithm() default LimitAlgorithm.SLIDING_WINDOW;
    int maxRequests() default 100;
    int windowSeconds() default 60;
    String memberOverrides() default "";  // JSON: {"MONTHLY":{"maxRequests":200},...}
    String fallbackMethod() default "";

    enum LimitDimension { USER, IP, DEVICE, GLOBAL }
    enum LimitAlgorithm { TOKEN_BUCKET, SLIDING_WINDOW, FIXED_WINDOW, LEAKY_BUCKET }
}
```

### 5.2 限流切面核心逻辑

```java
@Aspect
@Component
@Slf4j
public class RateLimitAspect {

    @Autowired private StringRedisTemplate redisTemplate;
    @Autowired private UserContextService userCtx;

    // 令牌桶 Lua 脚本（原子操作）
    private static final String TB_SCRIPT = """
        local key = KEYS[1]
        local cap = tonumber(ARGV[1])
        local rate = tonumber(ARGV[2]) / tonumber(ARGV[3])
        local now = tonumber(ARGV[4])
        local d = redis.call('HMGET', key, 'tokens', 'last_refill')
        local t = tonumber(d[1]) or cap
        local lr = tonumber(d[2]) or now
        t = math.min(cap, t + (now - lr) * rate)
        if t >= 1 then
            t = t - 1
            redis.call('HMSET', key, 'tokens', t, 'last_refill', now)
            redis.call('EXPIRE', key, tonumber(ARGV[3]) * 2)
            return 1
        else
            redis.call('HMSET', key, 'tokens', t, 'last_refill', now)
            redis.call('EXPIRE', key, tonumber(ARGV[3]) * 2)
            return 0
        end
        """;

    @Around("@annotation(rl)")
    public Object around(ProceedingJoinPoint pjp, RateLimit rl) throws Throwable {
        // 1. 解析限流维度键
        String dimKey = resolveDimKey(rl);
        if (dimKey == null) return pjp.proceed();

        int maxReq = resolveMax(rl);
        String key = "ratelimit:" + rl.ruleId() + ":" + dimKey;
        boolean allowed;
        long remaining = 0;

        // 2. 执行限流检查
        switch (rl.algorithm()) {
            case SLIDING_WINDOW -> {
                long now = System.currentTimeMillis();
                List<Object> res = redisTemplate.executePipelined(
                    (RedisCallback<Object>) conn -> {
                        byte[] kb = key.getBytes();
                        conn.zRemRangeByScore(kb, 0, now - rl.windowSeconds() * 1000L);
                        conn.zCard(kb);
                        conn.zAdd(kb, now, (MDC.get("traceId") + "-" + UUID.randomUUID()).getBytes());
                        conn.expire(kb, rl.windowSeconds() + 1);
                        return null;
                    });
                long cnt = (Long) res.get(1);
                allowed = cnt < maxReq;
                remaining = Math.max(0, maxReq - cnt - 1);
            }
            case TOKEN_BUCKET -> {
                var script = new DefaultRedisScript<>(TB_SCRIPT, Long.class);
                Long r = redisTemplate.execute(script, List.of(key),
                    String.valueOf(maxReq), String.valueOf(maxReq),
                    String.valueOf(rl.windowSeconds()),
                    String.valueOf(System.currentTimeMillis() / 1000.0));
                allowed = r != null && r == 1L;
            }
            case FIXED_WINDOW -> {
                String fwKey = "ratelimit:fw:" + rl.ruleId() + ":" + dimKey;
                Long cnt = redisTemplate.opsForValue().increment(fwKey);
                if (cnt != null && cnt == 1)
                    redisTemplate.expire(fwKey, rl.windowSeconds(), TimeUnit.SECONDS);
                allowed = cnt == null || cnt <= maxReq;
                remaining = Math.max(0, maxReq - (cnt != null ? cnt : 0));
            }
            default -> allowed = true;
        }

        // 3. 设置响应头
        setHeaders(maxReq, remaining, rl.windowSeconds());

        // 4. 限流处理
        if (!allowed) {
            logRateEvent(rl, dimKey, maxReq);
            return handleFallback(pjp, rl, maxReq);
        }
        return pjp.proceed();
    }

    private String resolveDimKey(RateLimit rl) {
        var sb = new StringBuilder();
        for (var dim : rl.dimensions()) {
            switch (dim) {
                case USER -> {
                    var u = userCtx.getCurrentUserId();
                    if (u == null) return null;
                    sb.append("u:").append(u);
                }
                case IP -> sb.append("ip:").append(RequestContext.getClientIp());
                case DEVICE -> {
                    var d = userCtx.getDeviceId();
                    if (d == null) return null;
                    sb.append("d:").append(d);
                }
                case GLOBAL -> sb.append("global");
            }
        }
        return sb.toString();
    }

    /** 会员等级覆盖阈值解析 */
    private int resolveMax(RateLimit rl) {
        String json = rl.memberOverrides();
        if (!json.isEmpty()) {
            try {
                var map = new ObjectMapper().readValue(json,
                    new TypeReference<Map<String, Map<String, Integer>>>(){});
                var tier = userCtx.getCurrentMemberTier().name();
                var o = map.get(tier);
                if (o != null && o.containsKey("maxRequests")) return o.get("maxRequests");
            } catch (Exception e) {
                log.warn("parse memberOverrides failed", e);
            }
        }
        return rl.maxRequests();
    }

    private Object handleFallback(ProceedingJoinPoint pjp, RateLimit rl, int max) throws Throwable {
        if (!rl.fallbackMethod().isEmpty()) {
            var sig = (MethodSignature) pjp.getSignature();
            var m = pjp.getTarget().getClass().getMethod(rl.fallbackMethod(), sig.getParameterTypes());
            return m.invoke(pjp.getTarget(), pjp.getArgs());
        }
        throw new RateLimitedException(max, rl.windowSeconds());
    }
}
```

### 6.1 熔断器管理服务

```java
@Service
@Slf4j
public class CircuitBreakerManager {

    private final Map<String, CircuitBreaker> breakerMap = new ConcurrentHashMap<>();

    @PostConstruct
    public void init() {
        // 从数据库/配置中心加载所有启用的熔断规则
        List<CircuitBreakerRule> rules = ruleRepo.findAllEnabled();
        rules.forEach(this::registerBreaker);
        log.info("Initialized {} circuit breakers", rules.size());
    }

    public void registerBreaker(CircuitBreakerRule rule) {
        CircuitBreakerConfig config = buildConfig(rule);
        CircuitBreaker breaker = CircuitBreaker.of(rule.getId(), config);

        // 状态变更监听
        breaker.getEventPublisher()
            .onStateTransition(event -> {
                log.warn("Circuit [{}] state: {} -> {}",
                    rule.getTargetService(),
                    event.getStateTransition().getFromState(),
                    event.getStateTransition().getToState());
                publishCircuitEvent(rule, event);
            })
            .onError(event -> log.debug("Circuit [{}] error: {}",
                rule.getTargetService(), event.getThrowable().getMessage()))
            .onSuccess(event -> log.debug("Circuit [{}] success: {}ms",
                rule.getTargetService(), event.getElapsedDuration().toMillis()));

        breakerMap.put(rule.getId(), breaker);
    }

    private CircuitBreakerConfig buildConfig(CircuitBreakerRule rule) {
        CircuitBreakerConfig.Builder builder = CircuitBreakerConfig.custom()
            .waitDurationInOpenState(Duration.ofSeconds(rule.getOpenDurationSeconds()))
            .permittedNumberOfCallsInHalfOpenState(rule.getHalfOpenMaxRequests())
            .minimumNumberOfCalls(rule.getMinRequestsInWindow())
            .slidingWindowType(SlidingWindowType.TIME_BASED)
            .slidingWindowSize(rule.getEvaluationWindowSeconds());

        switch (rule.getStrategy()) {
            case SLOW_CALL -> builder
                .slowCallDurationThreshold(Duration.ofMillis(rule.getSlowCallDurationMs()))
                .slowCallRateThreshold(rule.getSlowCallRatePercent());
            case ERROR_RATE -> builder
                .failureRateThreshold(rule.getErrorRatePercent())
                .recordExceptions(Throwable.class);
            case CONSECUTIVE_FAILURE -> builder
                .failureRateThreshold(100.0)
                .minimumNumberOfCalls(rule.getConsecutiveFailures());
        }

        return builder.build();
    }

    /** 执行带熔断保护的服务调用 */
    public <T> T executeWithCircuit(String breakerId, Supplier<T> supplier, Supplier<T> fallback) {
        CircuitBreaker breaker = breakerMap.get(breakerId);
        if (breaker == null) {
            return supplier.get();  // 无熔断器，直接执行
        }

        return Try.ofSupplier(() -> breaker.executeSupplier(supplier))
            .recover(CallNotPermittedException.class, e -> {
                log.warn("Circuit [{}] is OPEN, using fallback", breakerId);
                return fallback.get();
            })
            .recover(Exception.class, e -> {
                log.error("Circuit [{}] execution failed: {}", breakerId, e.getMessage());
                return fallback.get();
            })
            .get();
    }
}
```

### 6.3 熔断使用示例

```java
@Service
public class AiService {

    @Autowired private CircuitBreakerManager cbManager;
    @Autowired private LlmClient llmClient;
    @Autowired private CacheService cacheService;
    @Autowired private LlmClient fallbackLlmClient;

    public ChatResponse chat(ChatRequest request) {
        // 主模型调用带熔断保护
        return cbManager.executeWithCircuit(
            "ai-llm-primary",
            () -> llmClient.chat(request),       // 正常调用
            () -> fallbackChat(request)            // 熔断回退
        );
    }

    private ChatResponse fallbackChat(ChatRequest request) {
        // 回退策略 1：尝试使用缓存
        Optional<ChatResponse> cached = cacheService.findSimilarResponse(
            request.getQuestion(), request.getSubject());
        if (cached.isPresent()) {
            ChatResponse resp = cached.get();
            resp.setMeta(Map.of("degraded", true, "reason", "缓存回退"));
            return resp;
        }

        // 回退策略 2：降级模型
        try {
            ChatResponse resp = fallbackLlmClient.chat(request);
            resp.setMeta(Map.of("degraded", true, "reason", "降级模型"));
            return resp;
        } catch (Exception e) {
            // 回退策略 3：友好提示
            return ChatResponse.builder()
                .content("AI 老师正在休息中，请稍后再试～")
                .degraded(true)
                .retryable(true)
                .retryAfterSeconds(30)
                .build();
        }
    }
}
```

```java
     * 定时检查数据库连接池健康度

    public void checkPoolHealth() {

            int total = pool.getTotalConnections();

                redisTemplate.opsForValue().set("overload:db", "1", 10, TimeUnit.SECONDS);
            } else if (usage > 0.85) {
                log.warn("DB pool high usage: active={}, total={}, waiting={}",
                    active, total, waiting);
            }
        }
    }
```

### 7.2 AI 模型并发槽位控制

```java
@Service
public class AiConcurrencyGuard {

    // 使用 Redis 信号量控制 AI 模型并发调用数
    private static final String SLOT_KEY = "ai:concurrency:slots";
    private static final int MAX_CONCURRENT = 100; // 最大并发 AI 调用数

    @Autowired private StringRedisTemplate redisTemplate;

    /**
     * 获取 AI 调用槽位
     * @return true 获取成功，false 已满需要排队
     */
    public boolean acquireSlot(String userId) {
        String script = """
            local key = KEYS[1]
            local max = tonumber(ARGV[1])
            local user = ARGV[2]
            local now = tonumber(ARGV[3])
            -- 移除超时槽位（30秒超时）
            redis.call('ZREMRANGEBYSCORE', key, '-inf', now - 30000)
            local current = redis.call('ZCARD', key)
            if current < max then
                redis.call('ZADD', key, now, user)
                redis.call('EXPIRE', key, 60)
                return 1
            else
                return 0
            end
            """;
        Long result = redisTemplate.execute(
            new DefaultRedisScript<>(script, Long.class),
            List.of(SLOT_KEY),
            String.valueOf(MAX_CONCURRENT),
            userId,
            String.valueOf(System.currentTimeMillis())
        );
        return result != null && result == 1L;
    }

    /**
     * 释放 AI 调用槽位
     */
    public void releaseSlot(String userId) {
        redisTemplate.opsForZSet().remove(SLOT_KEY, userId);
    }

    /**
     * 带槽位控制的 AI 调用
     */
    public <T> CompletableFuture<T> executeWithSlot(String userId, Supplier<CompletableFuture<T>> task) {
        if (!acquireSlot(userId)) {
            return CompletableFuture.failedFuture(
                new RateLimitedException("AI 服务繁忙，请稍后重试", 100, 30));
        }
        try {
            return task.get().whenComplete((result, ex) -> releaseSlot(userId));
        } catch (Exception e) {
            releaseSlot(userId);
            return CompletableFuture.failedFuture(e);
        }
    }
}
```

## 10. 错误处理与边界情况

### 10.1 限流错误码

| 错误码 | HTTP 状态码 | 含义 | 客户端处理 |
|--------|------------|------|------------|
| `RATE_LIMITED` | 429 | 请求超过限流阈值 | 读取 Retry-After，延迟重试 |
| `SERVICE_OVERLOADED` | 503 | 服务过载保护触发 | 稍后重试 |
| `CIRCUIT_OPEN` | 503 | 熔断器开启 | 降级展示或重试 |
| `AI_CONCURRENCY_FULL` | 429 | AI 并发槽位已满 | 排队等待 |
| `IP_BLACKLISTED` | 403 | IP 被拉黑 | 联系客服 |

### 10.2 Redis 故障容错

```
Redis 故障时的处理策略：

1. 网关层 (L1)
   ├── Redis 连接超时 → 放行请求（Fail-Open）
   └── Redis 命令超时 → 放行请求

2. 服务层 (L2)
   ├── Redis 不可用 → 放行请求 + 日志告警
   └── Redis 恢复后 → 自动恢复限流计数

3. 熔断器 (L3)
   ├── Redis 不可用 → 使用本地内存状态
   └── Redis 恢复后 → 从 Redis 同步状态

原则：限流系统不可用时，不能阻塞正常业务流量
```

### 10.3 时钟偏移处理

- 所有时间戳使用毫秒精度
- 限流计数器依赖 Redis TIME 命令（非本地时钟）
- 令牌桶的 last_refill 使用服务端时间
- 多节点部署时确保 NTP 同步

### 10.4 限流键冲突处理

- 用户 ID 由认证系统保证全局唯一
- 设备 ID 使用设备指纹（UUID v5 命名空间）
- IP 维度使用 `binary_remote_addr`（二进制压缩）
- 请求 ID 使用 Nginx 内置 `$request_id`
