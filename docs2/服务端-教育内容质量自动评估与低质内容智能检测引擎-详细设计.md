## 1. 概述

### 1.1 设计目的

PrimeTop 平台拥有大量结构化教育内容——教材讲解、知识点解析、题目与解析、练习方案、学习路径等。随着内容规模增长和教材版本迭代，**内容质量的持续监控和低质内容的自动识别**成为核心运营诉求。

现有设计中，`题库质量监控`聚焦于题目生命周期管理，`AI回答质量监控`聚焦于实时 AI 对话质量。但平台中还有大量**静态教育内容**（知识点讲解、教材解读、范文素材、学习计划模板等）缺乏统一的质量评估机制。

本引擎旨在建立**全内容类型覆盖的质量评估体系**，通过多维度指标采集、机器学习预测模型和规则引擎，实现：

1. 已发布内容的**持续质量巡检**
2. 低质内容的**自动检测与预警**
3. 内容**过期/失效**的自动识别
4. 质量分数驱动的内容**推荐加权/降权**
5. 编辑团队的**质量工作台**

### 1.2 设计范围

| 范围 | 包含 | 不包含 |
|------|------|--------|
| 内容类型 | 知识点讲解、教材解读、题目解析、范文素材、学习计划模板、考点总结、错题归因模板 | AI 实时对话回答（已由 AI回答质量监控覆盖） |
| 评估维度 | 准确性、完整性、适龄性、时效性、用户满意度、使用效率、覆盖度 | 题目本身的质量（已由题库质量监控覆盖） |
| 操作动作 | 标记、降权、预警、下线建议、复审触发 | 直接删除内容（需人工确认） |
| 数据来源 | 用户行为埋点、反馈数据、审核结果、内容元数据、教材版本信息 | 第三方外部数据源 |

### 1.3 核心价值

| 角色 | 价值 |
|------|------|
| 内容编辑团队 | 自动获知哪些内容需要修订，聚焦工作精力 |
| 推荐系统 | 获得内容质量分作为推荐排序因子 |
| 学生用户 | 减少遇到错误/过时/低质内容的概率 |
| 运营管理 | 全局内容健康度可视，支撑内容采购和-production决策 |

## 3. 数据结构设计

### 3.1 内容质量评分表 `content_quality_scores`

存储每条内容的最新质量评分快照。

```sql
CREATE TABLE content_quality_scores (
    id                  BIGSERIAL PRIMARY KEY,
    content_id          BIGINT NOT NULL,              -- 内容ID（对应 knowledge_points / explanations / templates 等表的ID）
    content_type        VARCHAR(32) NOT NULL,         -- 内容类型：EXPLANATION / ANSWER_ANALYSIS / ESSAY_SAMPLE / STUDY_PLAN_TEMPLATE / EXAM_POINT_SUMMARY / MISTAKE_TEMPLATE
    subject             VARCHAR(16),                  -- 学科
    grade_range         VARCHAR(32),                  -- 适用学段年级
    textbook_version    VARCHAR(64),                  -- 教材版本

    -- 综合质量分（0-100，越高越好）
    overall_score       DECIMAL(5,2) NOT NULL DEFAULT 50.00,
    quality_tier        VARCHAR(16) NOT NULL DEFAULT 'NORMAL', -- EXCELLENT / GOOD / NORMAL / BELOW_AVG / POOR / CRITICAL

    -- 各维度分数（0-100）
    accuracy_score      DECIMAL(5,2),                 -- 准确性得分
    completeness_score  DECIMAL(5,2),                 -- 完整性得分
    age_fit_score       DECIMAL(5,2),                 -- 适龄性得分
    freshness_score     DECIMAL(5,2),                 -- 时效性/新鲜度得分
    satisfaction_score  DECIMAL(5,2),                 -- 用户满意度得分
    usage_efficiency    DECIMAL(5,2),                 -- 使用效率得分（完播率/完成率等）

    -- 关键指标原始值
    total_views         INT NOT NULL DEFAULT 0,       -- 总浏览/使用次数
    total_completions   INT NOT NULL DEFAULT 0,       -- 完整完成次数
    completion_rate     DECIMAL(5,4) DEFAULT 0.0000,  -- 完成率
    positive_feedbacks  INT NOT NULL DEFAULT 0,       -- 正面反馈数
    negative_feedbacks  INT NOT NULL DEFAULT 0,       -- 负面反馈数
    error_reports       INT NOT NULL DEFAULT 0,       -- 纠错报告数
    avg_dwell_time_ms   INT,                          -- 平均停留时长（毫秒）

    -- 状态
    evaluation_status   VARCHAR(20) NOT NULL DEFAULT 'ACTIVE', -- ACTIVE / UNDER_REVIEW / QUARANTINED / RETIRED
    last_evaluated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_scored_by      VARCHAR(32) NOT NULL DEFAULT 'SYSTEM', -- SYSTEM / MANUAL

    -- 元数据
    version             INT NOT NULL DEFAULT 1,       -- 评分版本号（每次重新评估+1）
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    -- 约束
    CONSTRAINT ck_quality_tier CHECK (quality_tier IN ('EXCELLENT','GOOD','NORMAL','BELOW_AVG','POOR','CRITICAL')),
    CONSTRAINT ck_eval_status CHECK (evaluation_status IN ('ACTIVE','UNDER_REVIEW','QUARANTINED','RETIRED')),
    CONSTRAINT ck_content_type CHECK (content_type IN ('EXPLANATION','ANSWER_ANALYSIS','ESSAY_SAMPLE','STUDY_PLAN_TEMPLATE','EXAM_POINT_SUMMARY','MISTAKE_TEMPLATE'))
);

-- 唯一索引：同一内容只有一条最新评分
CREATE UNIQUE INDEX idx_quality_content_unique ON content_quality_scores (content_id, content_type);

-- 查询索引
CREATE INDEX idx_quality_tier ON content_quality_scores (quality_tier, overall_score);
CREATE INDEX idx_quality_status ON content_quality_scores (evaluation_status);
CREATE INDEX idx_quality_subject_grade ON content_quality_scores (subject, grade_range);
CREATE INDEX idx_quality_last_eval ON content_quality_scores (last_evaluated_at);
```

### 3.6 质量维度权重配置 `quality_dimension_weights`

不同内容类型在各质量维度上的权重不同，通过配置表管理。

```sql
CREATE TABLE quality_dimension_weights (
    id                  BIGSERIAL PRIMARY KEY,
    content_type        VARCHAR(32) NOT NULL,
    subject             VARCHAR(16) NOT NULL DEFAULT 'ALL',

    -- 各维度权重（总和=1.0）
    accuracy_weight     DECIMAL(4,3) NOT NULL DEFAULT 0.300,
    completeness_weight DECIMAL(4,3) NOT NULL DEFAULT 0.150,
    age_fit_weight      DECIMAL(4,3) NOT NULL DEFAULT 0.150,
    freshness_weight    DECIMAL(4,3) NOT NULL DEFAULT 0.100,
    satisfaction_weight DECIMAL(4,3) NOT NULL DEFAULT 0.200,
    usage_weight        DECIMAL(4,3) NOT NULL DEFAULT 0.100,

    enabled             BOOLEAN NOT NULL DEFAULT TRUE,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    -- 校验：权重之和应为 1.0（允许浮点误差）
    CONSTRAINT ck_weights_sum CHECK (
        ABS(accuracy_weight + completeness_weight + age_fit_weight +
            freshness_weight + satisfaction_weight + usage_weight - 1.0) < 0.001
    )
);

CREATE UNIQUE INDEX idx_dim_weight ON quality_dimension_weights (content_type, subject);
```

## 4. 质量评估模型设计

### 4.1 质量评分总览

整体质量分 `overall_score` 由 6 个维度加权融合得到：

```
overall_score = accuracy_score × W_accuracy
              + completeness_score × W_completeness
              + age_fit_score × W_age_fit
              + freshness_score × W_freshness
              + satisfaction_score × W_satisfaction
              + usage_efficiency × W_usage
```

权重由 `quality_dimension_weights` 表配置，不同内容类型和学科有不同的默认权重。

### 4.2 各维度评分计算

#### 4.2.1 准确性得分 `accuracy_score`

评估内容本身的正确性。

**数据来源**：
- 用户纠错报告（纠错率越低越好）
- 人工审核通过率
- AI 自动校验结果（对关键事实进行 RAG 校验）

**计算公式**：

```
accuracy_score = 100
               - min(error_report_rate × 500, 40)        -- 纠错报告扣分（最多扣40）
               - min(ai_verification_errors × 20, 30)     -- AI自动校验错误扣分（最多扣30）
               - min(manual_review_issues × 15, 20)       -- 人工审核问题扣分（最多扣20）
               - min(consecutive_errors × 10, 10)         -- 连续纠错扣分（趋势恶化加扣）
```

其中：
- `error_report_rate` = error_reports / max(total_views, 1) × 1000（千分率）
- `ai_verification_errors` = AI 自动校验发现的事实性错误数
- `manual_review_issues` = 最近一次人工审核中标记的问题数
- `consecutive_errors` = 连续评估周期中纠错数上升的次数

#### 4.2.2 完整性得分 `completeness_score`

评估内容是否充分覆盖应包含的知识要素。

**计算方式**：基于内容类型定义"必备要素清单"，逐项检查。

```
completeness_score = (covered_elements / total_required_elements) × 100
```

不同内容类型的必备要素：

| 内容类型 | 必备要素 |
|----------|----------|
| EXPLANATION（知识点讲解） | 定义说明、核心概念、关键公式/定理、示例、常见误区、与相关知识点关联 |
| ANSWER_ANALYSIS（题目解析） | 题干理解、解题思路、分步过程、最终答案、易错点提醒、知识点标注 |
| ESSAY_SAMPLE（范文素材） | 写作背景、文章正文、结构分析、亮点赏析、适用主题标签 |
| STUDY_PLAN_TEMPLATE（学习计划模板） | 学习目标、时间安排、任务分解、资源链接、检验节点、调整建议 |
