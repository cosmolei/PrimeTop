# 数据架构 - 详细设计文档

## 1. 模块概述

数据架构是 PrimeTop 全系统的基石，定义了跨所有业务模块的统一数据存储策略、数据库表结构、实体关系、索引设计、缓存方案和向量数据库方案。本文档为开发人员提供完整的 DDL、ER 关系和数据操作规范，是所有模块数据库操作的权威参考。

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 单一数据源 | 每种数据只有一个权威存储，避免双写不一致 |
| 适度反范式 | 高频查询允许冗余字段，减少 JOIN，通过应用层保证一致性 |
| 分层存储 | 热数据→Redis，温数据→MySQL，冷数据→归档存储，向量→Milvus |
| 软删除优先 | 业务核心表使用 `status` 字段软删除，避免外键断裂 |
| 时间戳标准 | 所有表必须包含 `created_at` 和 `updated_at`，使用 `DATETIME` 类型存储 UTC+8 本地时间 |
| ID 策略 | 主键使用 `BIGINT AUTO_INCREMENT`，分布式场景预留 Snowflake 方案 |
| 字符集统一 | 所有表 `utf8mb4`，支持 Emoji 和生僻字 |

### 1.2 存储矩阵

| 数据类型 | 存储引擎 | 用途 |
|----------|----------|------|
| 业务主数据 | MySQL 8.0+ | 用户、订单、错题、学习计划等强一致性数据 |
| 热点缓存 | Redis 7.x | 会话、Token、限流计数器、排行榜、实时状态 |
| 学习行为日志 | ClickHouse | 海量写入的学习事件流，用于分析和报表 |
| 向量索引 | Milvus 2.x | 知识库向量检索（RAG）、题目相似度匹配 |
| 全文检索 | Elasticsearch 8.x | 题库搜索、知识点搜索、内容检索 |
| 文件资源 | 对象存储（MinIO/S3） | 图片、语音、PDF、教材资源文件 |
| 消息队列 | RabbitMQ/Redis Stream | 异步任务、事件通知、数据同步 |

## 3. 数据库分库策略

### 3.1 库划分

```
primetop_core        -- 核心业务库（用户、账号、绑定、会员、订单）
primetop_learning    -- 学习业务库（对话、错题、计划、学习记录、答题）
primetop_content     -- 内容资源库（教材、知识点、题库、考点）
primetop_log         -- 日志库（学习事件、操作审计、AI调用日志）
```

### 3.2 分库原则

| 规则 | 说明 |
|------|------|
| 用户相关 → core | users, student_profiles, parent_bindings, memberships, orders |
| 学习行为 → learning | ai_conversations, ai_messages, mistake_records, learning_plans, plan_tasks, answer_records, learning_sessions |
| 教学内容 → content | textbooks, chapters, knowledge_points, questions, exam_points, essay_prompts |
| 日志分析 → log | learning_events, ai_call_logs, audit_logs, operation_logs |

### 5.7 学习会话表 `learning_sessions`（新增）

学习会话记录用户每次使用 App 的学习行为片段，是学情分析和学习时长统计的基础。

```sql
CREATE TABLE learning_sessions (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '会话ID',
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    session_type    VARCHAR(30) NOT NULL COMMENT '会话类型: ai_chat/photo_search/sync_class/mistake_review/essay_writing/recitation/practice',
    subject         VARCHAR(20) COMMENT '学科',
    -- 时间追踪
    started_at      DATETIME NOT NULL COMMENT '开始时间',
    ended_at        DATETIME COMMENT '结束时间',
    duration_sec    INT COMMENT '持续时长(秒)',
    -- 关联上下文
    ref_id          BIGINT COMMENT '关联业务ID（如 conversation_id / mistake_id）',
    ref_type        VARCHAR(30) COMMENT '关联业务类型: conversation/mistake/chapter/plan_task',
    -- 学习产出
    items_count     INT NOT NULL DEFAULT 0 COMMENT '产出数量（消息数/答题数/错题复习数等）',
    summary         VARCHAR(500) COMMENT 'AI生成的本次学习小结',
    -- 知识点覆盖
    kp_ids          JSON COMMENT '涉及的知识点ID列表 [1001, 1002]',
    -- 质量评估
    focus_score     DECIMAL(3,2) COMMENT '专注度评分 0.00~1.00（基于交互频率和间隔）',
    effectiveness   DECIMAL(3,2) COMMENT '有效性评分 0.00~1.00（基于正确率和互动深度）',
    -- 客户端信息
    app_version     VARCHAR(20) COMMENT 'App版本号',
    platform        VARCHAR(10) COMMENT '平台: android/ios/web',
    network_type    VARCHAR(10) COMMENT '网络: wifi/4g/5g/offline',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_user_started (user_id, started_at DESC),
    INDEX idx_type_started (session_type, started_at DESC),
    INDEX idx_user_type (user_id, session_type, started_at DESC),
    INDEX idx_ref (ref_type, ref_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学习会话记录';
```

### 5.8 学习事件流表 `learning_events`（新增）

记录细粒度的用户学习行为事件，写入 ClickHouse 用于分析。MySQL 保留近期数据供查询。

```sql
CREATE TABLE learning_events (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '事件ID',
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    event_type      VARCHAR(40) NOT NULL COMMENT '事件类型',
    event_time      DATETIME(3) NOT NULL COMMENT '事件发生时间（毫秒精度）',
    -- 上下文
    session_id      BIGINT COMMENT '学习会话ID',
    subject         VARCHAR(20) COMMENT '学科',
    chapter_id      BIGINT COMMENT '章节ID',
    kp_id           BIGINT COMMENT '知识点ID',
    -- 事件详情
    payload         JSON COMMENT '事件详情（结构因 event_type 不同而不同）',
    -- 设备信息
    platform        VARCHAR(10) COMMENT 'android/ios/web',
    app_version     VARCHAR(20) COMMENT 'App版本',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_user_time (user_id, event_time DESC),
    INDEX idx_type_time (event_type, event_time DESC),
    INDEX idx_user_type_time (user_id, event_type, event_time DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学习事件流（MySQL近期数据）';
```

**ClickHouse 建表（冷数据归档）：**

```sql
CREATE TABLE learning_events_archive (
    id              Int64,
    user_id         Int64,
    event_type      String,
    event_time      DateTime64(3),
    session_id      Nullable(Int64),
    subject         Nullable(String),
    chapter_id      Nullable(Int64),
    kp_id           Nullable(Int64),
    payload         String,      -- JSON string
    platform        Nullable(String),
    app_version     Nullable(String),
    created_at      DateTime DEFAULT now()
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(event_time)
ORDER BY (user_id, event_time)
TTL event_time + INTERVAL 2 YEAR
SETTINGS index_granularity = 8192;
```

```python
# AI 调用日计数器（每日重置）
import redis
import time

class RateLimiter:
    def __init__(self, client: redis.Redis):
        self.client = client
    
    def check_and_incr(self, key: str, limit: int, window_sec: int) -> tuple[bool, int]:
        """滑动窗口限流
        Returns: (allowed, current_count)
        """
        now = time.time()
        pipe = self.client.pipeline()
        pipe.zremrangebyscore(key, 0, now - window_sec)
        pipe.zadd(key, {str(now): now})
        pipe.zcard(key)
        pipe.expire(key, window_sec)
        results = pipe.execute()
        count = results[2]
        return count <= limit, count


# 日计数器（用于会员每日用量）

        if count == 1:
```

### 8.3 RAG 检索流程

```python
class RAGRetriever:
    """RAG 检索器：根据用户问题检索相关知识"""
    
    def retrieve(
        self,
        query: str,
        subject: str,
        stage: str,
        top_k: int = 5,
        score_threshold: float = 0.7
    ) -> list[dict]:
        """检索与用户问题最相关的知识点"""
        # 1. 将用户问题向量化
        query_embedding = self.embedding_model.encode(query)
        
        # 2. 在 Milvus 中检索
        search_params = {"metric_type": "COSINE", "params": {"nprobe": 32}}
        results = self.milvus_collection.search(
            data=[query_embedding],
            anns_field="embedding",
            param=search_params,
            limit=top_k * 2,  # 多取一些，后面按学科过滤
            expr=f'subject_id == {subject_id} and stage == "{stage}"',
            output_fields=["kp_id", "text_content", "subject_id"]
        )
        
        # 3. 过滤低分结果
        filtered = [
            {"kp_id": r.kp_id, "text": r.text_content, "score": r.score}
            for r in results[0]
            if r.score >= score_threshold
        ]
        
        return filtered[:top_k]
```

## 10. 跨模块数据操作规范

### 10.1 用户数据隔离

所有学习业务表必须包含 `user_id` 字段，查询时强制带 `user_id` 条件：

```sql
-- ✅ 正确：始终带 user_id
SELECT * FROM mistake_records WHERE user_id = ? AND subject = 'math';

-- ❌ 错误：遗漏 user_id（安全风险）
SELECT * FROM mistake_records WHERE subject = 'math';
```

### 10.2 分页查询规范

统一使用游标分页（cursor-based），避免深度分页性能问题：

```sql
-- ✅ 推荐：基于ID游标的分页
SELECT * FROM ai_messages 
WHERE conversation_id = ? AND id > ? 
ORDER BY id ASC LIMIT 20;

-- ❌ 避免：OFFSET 深度分页
SELECT * FROM ai_messages 
WHERE conversation_id = ? 
ORDER BY id ASC LIMIT 20 OFFSET 100000;  -- 性能灾难
```

### 10.3 JSON 字段使用规范

MySQL 8.0 的 JSON 字段用于存储动态结构数据，但**禁止**在 JSON 字段上做核心过滤条件：

```sql
-- ✅ 正确：JSON 用于存储和展示
SELECT kp_ids FROM questions WHERE id = ?;

-- ✅ 可接受：多值索引辅助查询
SELECT * FROM questions 
WHERE stage = 'junior' AND JSON_CONTAINS(kp_ids, '1001');

-- ❌ 避免：复杂 JSON 查询做核心业务
SELECT * FROM questions WHERE JSON_EXTRACT(payload, '$.difficulty') > 3;
```

### 10.4 事务边界

| 场景 | 事务范围 | 隔离级别 |
|------|----------|----------|
| 用户注册 | users + student_profiles 单库事务 | READ_COMMITTED |
| 拍题→加入错题本 | 跨库，使用本地消息表保证最终一致 | READ_COMMITTED |

**处理流程：**

```
1. 开启本地事务
2. 写入业务数据（如 mistake_records）
3. 写入 outbox_messages（同事务）
4. 提交事务
5. 异步轮询 outbox → 发送到 MQ → 更新 status
6. 消费者处理事件 → 更新其他库 → 确认
```

```python
# 发件箱扫描器（定时任务，每 5 秒执行）
class OutboxScanner:
    def scan_and_publish(self):
        messages = self.db.query("""
            SELECT * FROM outbox_messages 
            WHERE status = 0 AND created_at < NOW() - INTERVAL 5 SECOND
            ORDER BY created_at LIMIT 100 FOR UPDATE SKIP LOCKED
        """)
        for msg in messages:
            try:
                self.mq.publish(
                    exchange='data.sync.fanout',
                    routing_key=f'{msg.aggregate_type}.{msg.event_type}',
                    body=msg.payload
                )
                self.db.execute(
                    "UPDATE outbox_messages SET status = 1, sent_at = NOW() WHERE id = %s",
                    msg.id
                )
            except Exception as e:
                self.db.execute(
                    "UPDATE outbox_messages SET retry_count = retry_count + 1, "
                    "status = CASE WHEN retry_count + 1 >= max_retries THEN 3 ELSE 0 END "
                    "WHERE id = %s",
                    msg.id
                )
```

## 13. 性能优化要点

### 13.1 读写分离

```
                  ┌──────────────┐
                  │   ProxySQL   │ ← 应用层连接池
                  └──────┬───────┘
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
     ┌──────────────┐     ┌──────────────┐
     │   Master     │────→│   Slave x2   │
     │   (写+读)     │复制 │   (只读)      │
     └──────────────┘     └──────────────┘
```

**路由规则：**
- 写操作 → Master
- 事务内的读 → Master
- AI 对话写入 → Master
- 学情分析报表查询 → Slave
- 题库/知识点检索 → Slave
- 用户信息查询 → 优先 Redis 缓存，Miss → Slave

### 14.1 敏感字段加密

| 字段 | 加密方式 | 说明 |
|------|----------|------|
| users.phone | AES-256-GCM | 解密需密钥管理服务 |
| user_oauth.access_token | AES-256-GCM | 第三方令牌 |
| orders.payment_info | AES-256-GCM | 支付信息 |
| users.phone_hash | SHA-256 | 用于快速查找（无需解密） |

```python
from cryptography.fernet import Fernet

class FieldEncryptor:
    """字段级加密工具"""
    
    def __init__(self, key: bytes):
        self.cipher = Fernet(key)
    
    def encrypt(self, plaintext: str) -> str:
        return self.cipher.encrypt(plaintext.encode()).decode()
    
    def decrypt(self, ciphertext: str) -> str:
        return self.cipher.decrypt(ciphertext.encode()).decode()
```
