# 服务端 - 亲子共学会话管理与双角色状态同步服务 详细设计

> **版本**：v1.1 | **日期**：2026-08-19 | **优先级**：P1 | **服务负责人**：待定
> **关联模块**：用户账号体系、家长中心、拼音识字启蒙、语音服务(ASR/TTS)、学习记录与进度追踪、防沉迷系统、运营活动与成长激励

---

## 1. 概述

### 1.1 功能定位

亲子共学会话管理服务（CoLearn Session Service）是服务端侧负责管理亲子共学全生命周期的核心服务。它处理会话创建、双角色状态流转、任务编排、实时状态同步、学习数据持久化以及与其他业务模块的集成。该服务解决的核心问题是：**在家长与孩子共享同一设备的场景下，如何安全、可靠地管理共学过程的服务端状态**。

### 1.2 与现有设计的关系

| 现有文档 | 覆盖范围 | 本文档补充 |
|---------|---------|-----------|
| 亲子共学模式与双角色交互设计 | 客户端交互、UI 流程、本地数据模型 | 服务端 API、状态机、数据库完整设计 |
| 端到端流程设计-亲子共学模式完整链路 | 端到端用户旅程、角色权限矩阵 | 服务端内部编排、跨服务调用链、异常处理 |
| 服务端-家庭账户管理与多孩子切换服务 | 家庭账户绑定关系 | 共学会话中的家长-孩子关系校验与联动 |

### 1.3 设计目标

| 目标 | 指标 |
|------|------|
| 会话创建响应时间 | < 200ms |
| 任务下发延迟 | < 300ms |
| 实时状态同步延迟 | < 500ms（WebSocket 推送） |
| 会话结束后报告生成 | < 3s |
| 并发共学会话支持 | 10,000+ 同时在线 |
| 数据一致性 | 最终一致，会话结束时强一致 |

### 1.4 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 主数据库 | PostgreSQL | 会话持久化，JSONB 存储灵活结构 |
| 缓存 | Redis | 会话实时状态、分布式锁、发布/订阅 |
| 实时通信 | WebSocket (Socket.IO / ws) | 双角色状态同步 |
| 消息队列 | RabbitMQ / Kafka | 异步事件通知（学情分析、成就触发） |
| 对象存储 | S3 / MinIO | 语音作答录音文件 |

## 3. 数据库设计

> **实现注记（v1.1）**：以下 DDL 中行内 `COMMENT` 为示意写法（MySQL 风格）；生产环境为 PostgreSQL 时应改用 `COMMENT ON COLUMN` 子句或统一迁移 MySQL，语义不变，以 Flyway 迁移脚本为最终实现权威。

### 3.1 共学会话主表 (colearn_session)

```sql
CREATE TABLE colearn_session (
    id                  VARCHAR(36)    NOT NULL PRIMARY KEY,
    parent_user_id      VARCHAR(36)    NOT NULL,
    child_user_id       VARCHAR(36)    NOT NULL,
    family_id           VARCHAR(36)    NULL COMMENT '家庭ID，冗余加速查询',
    
    -- 会话配置
    subject             VARCHAR(20)    NOT NULL COMMENT '学科: pinyin/literacy/math/english',
    topic               VARCHAR(100)   NOT NULL COMMENT '学习主题，如"声母认读"',
    topic_code          VARCHAR(50)    NULL COMMENT '主题编码，用于关联知识库',
    difficulty          VARCHAR(10)    NOT NULL DEFAULT 'easy' COMMENT 'easy/medium/hard',
    max_duration_min    INT            NOT NULL DEFAULT 20,
    break_interval_min  INT            NOT NULL DEFAULT 10,
    reward_mode         VARCHAR(10)    NOT NULL DEFAULT 'star',
    
    -- 状态与时间
    status              VARCHAR(20)    NOT NULL DEFAULT 'active',
    current_role        VARCHAR(10)    NOT NULL DEFAULT 'child' COMMENT 'parent/child',
    current_task_index  INT            NOT NULL DEFAULT 0 COMMENT '当前任务序号(0-based)',
    start_time          TIMESTAMPTZ    NOT NULL DEFAULT NOW(),
    end_time            TIMESTAMPTZ    NULL,
    last_active_time    TIMESTAMPTZ    NOT NULL DEFAULT NOW(),
    pause_start_time    TIMESTAMPTZ    NULL COMMENT '最近一次暂停开始时间',
    total_pause_sec     INT            NOT NULL DEFAULT 0 COMMENT '累计暂停秒数',
    
    -- 统计快照（会话结束时写入）
    total_tasks         INT            NOT NULL DEFAULT 0,
    completed_tasks     INT            NOT NULL DEFAULT 0,
    correct_count       INT            NOT NULL DEFAULT 0,
    parent_action_count INT            NOT NULL DEFAULT 0,
    stars_earned        INT            NOT NULL DEFAULT 0,
    accuracy            DECIMAL(5,4)   NULL COMMENT '正确率 0.0000-1.0000',
    effective_duration_sec INT         NULL COMMENT '有效学习时长(秒，扣除暂停)',
    
    -- 元数据
    client_version      VARCHAR(20)    NULL,
    device_model        VARCHAR(50)    NULL,
    os_platform         VARCHAR(20)    NULL COMMENT 'ios/android',
    app_session_id      VARCHAR(36)    NULL COMMENT '客户端本地会话ID，用于去重',
    
    created_at          TIMESTAMPTZ    NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ    NOT NULL DEFAULT NOW()
);

-- 索引
CREATE INDEX idx_colearn_session_parent ON colearn_session (parent_user_id, start_time DESC);
CREATE INDEX idx_colearn_session_child ON colearn_session (child_user_id, start_time DESC);
CREATE INDEX idx_colearn_session_status ON colearn_session (status) WHERE status = 'active';
CREATE INDEX idx_colearn_session_active ON colearn_session (last_active_time) WHERE status = 'active';
CREATE INDEX idx_colearn_session_family ON colearn_session (family_id, start_time DESC);

-- 分区策略（按月分区，会话数据量大）
-- 生产环境建议按 start_time 做 RANGE 分区
```

### 3.2 共学任务明细表 (colearn_task)

```sql
CREATE TABLE colearn_task (
    id                  VARCHAR(36)    NOT NULL PRIMARY KEY,
    session_id          VARCHAR(36)    NOT NULL,
    task_order          INT            NOT NULL COMMENT '任务序号(1-based)',
    
    -- 任务内容
    task_type           VARCHAR(20)    NOT NULL COMMENT 'recognize/pronounce/match/sort/fill_blank/listen_choose/trace',
    content_ref         JSONB          NOT NULL COMMENT '内容引用，包含知识点ID、题目ID等',
    content_snapshot    JSONB          NULL COMMENT '内容快照，任务创建时的题目内容缓存',
    
    -- 状态流转
    status              VARCHAR(20)    NOT NULL DEFAULT 'pending',
    started_at          TIMESTAMPTZ    NULL,
    ended_at            TIMESTAMPTZ    NULL,
    duration_ms         INT            NULL COMMENT '任务耗时',
    
    -- 孩子作答
    child_response_type VARCHAR(20)    NULL COMMENT 'voice/tap/drag/trace_path/none',
    child_response_data JSONB          NULL COMMENT '孩子作答详情',
    child_is_correct    BOOLEAN        NULL,
    
    -- AI 评估
    ai_evaluated        BOOLEAN        NOT NULL DEFAULT FALSE,
    ai_confidence       DECIMAL(3,2)   NULL COMMENT 'AI判断置信度 0.00-1.00',
    ai_evaluation       JSONB          NULL COMMENT 'AI评估详情(评分/建议)',
    
    -- 家长操作
    parent_action_type  VARCHAR(20)    NULL COMMENT 'hint/encourage/correct/confirm/skip/demo/praise',
    parent_action_data  JSONB          NULL COMMENT '家长操作详情',
    
    -- 综合结果
    final_result        VARCHAR(10)    NULL COMMENT 'correct/incorrect/skipped/pending_review',
    score               INT            NULL COMMENT '本任务得分 0-100',
    stars               INT            NULL COMMENT '本任务获得星星数 0-3',
    
    created_at          TIMESTAMPTZ    NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ    NOT NULL DEFAULT NOW(),
    
    FOREIGN KEY (session_id) REFERENCES colearn_session(id) ON DELETE CASCADE
);

CREATE INDEX idx_colearn_task_session ON colearn_task (session_id, task_order);
CREATE INDEX idx_colearn_task_status ON colearn_task (session_id, status);
```

## 4. 会话状态机

### 4.1 会话级状态机

```
                    ┌──────────────────────────┐
                    │                          │
                    ▼                          │
  ┌─────────┐   ┌────────┐   ┌─────────┐    │
  │ CREATED │──→│ ACTIVE │──→│ PAUSED  │────┘
  └─────────┘   └───┬─┬──┘   └─────────┘
                    │ │         ▲
                    │ │         │ 暂停
                    │ │    ┌────┴─────┐
                    │ │    │ BREAKING │ ← 休息中
                    │ │    └────┬─────┘
                    │ │         │ 休息结束
                    │ │         └──────→ ACTIVE
                    │ │
          ┌─────────┘ └───────────────────┐
          │                               │
          ▼                               ▼
  ┌─────────────┐              ┌───────────────┐
  │  COMPLETED  │              │  FORCE_ENDED  │
  └─────────────┘              └───────────────┘
          │                               │
          └───────────┬───────────────────┘
                      ▼
               ┌─────────────┐
               │  ARCHIVED   │ ← 定时任务归档
               └─────────────┘
```

### 4.2 状态转换规则

| 当前状态 | 事件 | 目标状态 | 触发条件 | 服务端动作 |
|---------|------|---------|---------|-----------|
| CREATED | session.activate | ACTIVE | 家长确认配置并点击开始 | 初始化 Redis 状态、加载任务序列、推送首任务 |
| ACTIVE | session.pause | PAUSED | 家长点击暂停 / 系统触发休息 | 记录暂停时间、冻结计时器、推送暂停状态 |
| ACTIVE | session.break | BREAKING | 达到休息间隔或连续错误触发 | 生成休息内容、推送休息界面 |
| ACTIVE | session.complete | COMPLETED | 所有任务完成 | 计算统计、生成报告、发布事件 |
| ACTIVE | session.force_end | FORCE_ENDED | 家长主动结束 / 服务端超时清理 | 保存已做数据、标记未完成任务 |
| ACTIVE | session.timeout | FORCE_ENDED | 无心跳超过 5 分钟 | 同 force_end |
| PAUSED | session.resume | ACTIVE | 家长点击继续 | 恢复计时器、推送当前任务 |
| PAUSED | session.timeout | FORCE_ENDED | 暂停超过 30 分钟未恢复 | 同 force_end |
| BREAKING | break.end | ACTIVE | 休息倒计时结束 / 家长跳过 | 推送下一任务 |
| COMPLETED | - | ARCHIVED | 定时归档任务（T+1 凌晨） | 压缩事件日志、更新聚合统计 |

## 5. Redis 状态设计

### 5.1 Key 规划

```
# 会话实时状态（Hash）
colearn:session:{sessionId}
  ├─ status: "active"
  ├─ currentRole: "child"
  ├─ currentTaskIndex: "3"
  ├─ lastActiveTime: "1749264000000"
  ├─ parentUserId: "xxx"
  ├─ childUserId: "xxx"
  ├─ startTime: "1749264000000"
  ├─ totalPauseSec: "60"
  ├─ pauseStartTime: ""
  ├─ totalTasks: "10"
  ├─ completedTasks: "3"
  ├─ correctCount: "2"
  ├─ parentActionCount: "1"
  └─ starsEarned: "4"

# 任务实时状态（Hash）
colearn:task:{sessionId}:{taskOrder}
  ├─ id: "task-uuid"
  ├─ status: "in_progress"
  ├─ taskType: "pronounce"
  ├─ startedAt: "1749264100000"
  ├─ childResponseType: ""
  ├─ childIsCorrect: ""
  ├─ aiConfidence: ""
  └─ parentActionType: ""

# 会话 WebSocket 连接映射（Set，支持重连）
colearn:ws:{sessionId}
  └─ members: ["parent:connId1", "child:connId2"]
  注：单设备场景通常只有一个连接，但保留扩展能力

# 活跃会话列表（Sorted Set，按最后活跃时间排序，用于超时扫描）
colearn:active_sessions
  └─ score = lastActiveTime, member = sessionId

# 分布式锁（防止并发操作冲突）
colearn:lock:session:{sessionId}
  └─ value = operationId, TTL = 10s

# 幂等键（防止重复提交）
colearn:idempotent:{operationType}:{clientEventId}
  └─ value = "1", TTL = 60s
```

### 5.2 TTL 策略

| Key 模式 | TTL | 说明 |
|---------|-----|------|
| `colearn:session:*` | 会话结束后 1 小时 | 会话结束后延迟删除，供报告查询 |
| `colearn:task:*` | 跟随会话 TTL | 随会话一起清理 |
| `colearn:ws:*` | 无（主动清理） | 断线时主动移除 |
| `colearn:active_sessions` | 无（定时扫描清理） | 通过定时任务清理过期条目 |
| `colearn:lock:*` | 10 秒 | 自动过期释放 |
| `colearn:idempotent:*` | 60 秒 | 防止短时间重复提交 |

**校验规则：**

```java
// 服务端校验伪代码
public SessionCreateResult createSession(CreateSessionRequest req, UserContext ctx) {
    // 1. 权限校验：当前用户必须是家长角色
    validateParentRole(ctx.getUserId());
    
    // 2. 绑定关系校验：家长必须已绑定该孩子
    FamilyBinding binding = familyService.getBinding(ctx.getUserId(), req.getChildUserId());
    if (binding == null || !binding.isActive()) {
        throw new BusinessException(ErrorCode.PARENT_CHILD_NOT_BOUND);
    }
    
    // 3. 防沉迷校验：检查孩子今日使用时长是否已达上限
    UsageLimit limit = antiAddictionService.checkDailyLimit(req.getChildUserId());
    if (limit.isExceeded()) {
        throw new BusinessException(ErrorCode.DAILY_USAGE_LIMIT_EXCEEDED, 
            Map.of("remainingMin", limit.getRemainingMin()));
    }
    
    // 4. 并发会话校验：同一对家长-孩子不能同时有多个活跃会话
    String pairKey = "colearn:active_pair:" + ctx.getUserId() + ":" + req.getChildUserId();
    String existingSessionId = redis.get(pairKey);
    if (existingSessionId != null) {
        // 双设备场景：第二台设备创建被拒，返回现有会话供客户端引导「恢复现有会话」
        throw new BusinessException(ErrorCode.COLEARN_SESSION_EXISTS,          // 19004
                Map.of("existingSessionId", existingSessionId));
    }

    // 5. 内容池校验：主题下必须有足量适龄学习项（3-8 岁适龄池，合规 C7）
    ContentPool pool = contentService.getPool(req.getSubject(), req.getTopicCode(),
            req.getDifficulty(), childProfile.getAgeBand());
    if (pool == null || pool.availableCount() < MIN_TASK_COUNT) {              // MIN_TASK_COUNT = 6
        throw new BusinessException(ErrorCode.COLEARN_CONTENT_UNAVAILABLE);    // 19005
    }

    // 6. 时长收敛：min(请求值, 分龄单次上限, 防沉迷今日剩余)
    int ageSingleLimit = antiAddictionService.getSingleSessionLimit(req.getChildUserId());
    int remainingMin = limit.getRemainingMin();
    int maxDuration = Math.min(Math.min(req.getMaxDurationMin(), ageSingleLimit), remainingMin);
    if (maxDuration < MIN_SESSION_MIN) {                                       // < 3min 无共学价值
        throw new BusinessException(ErrorCode.DAILY_USAGE_LIMIT_EXCEEDED,      // 19008
                Map.of("remainingMin", remainingMin));
    }

    // 7. 创建互斥：SETNX 双人锁，防并发双击/双设备竞态（10s 自动过期）
    String lockKey = "colearn:lock:create:" + ctx.getUserId() + ":" + req.getChildUserId();
    String opId = UUID.randomUUID().toString();
    if (!"OK".equals(redis.setNxEx(lockKey, opId, 10))) {
        throw new BusinessException(ErrorCode.COLEARN_SESSION_EXISTS);         // 19004（并发竞态兜底）
    }
    try {
        // 8. 幂等创建：appSessionId 唯一索引兜底；命中则直接返回首次结果
        ColearnSession dup = sessionRepo.findByAppSessionId(req.getAppSessionId());
        if (dup != null) {
            return SessionCreateResult.replay(dup);                           // 幂等命中返回首次结果（§12.1）
        }

        // 9. 生成任务序列（TaskOrchestrator：难度梯度 + 类型多样性 + 数量 8~15 收敛，§9.2）
        String sessionId = idGenerator.next("colearn");
        List<TaskDraft> tasks = taskOrchestrator.generate(pool, maxDuration, settings);

        // 10. 事务写入：session + tasks + Outbox 事件同事务（§10）
        colearnTx.execute(status -> {
            sessionRepo.insert(ColearnSession.from(req, sessionId, maxDuration, tasks.size()));
            taskRepo.batchInsert(sessionId, tasks);
            outbox.append(sessionId, "colearn.session.created", buildCreatedPayload(sessionId, req));
            return null;
        });

        // 11. Redis 实时状态初始化（cache-after-commit；失败走 §13 D1 降级，不回滚 DB）
        redis.hMSet("colearn:session:" + sessionId, initialStateMap(sessionId, tasks.size(), req));
        redis.setEx(pairKey, sessionId, Duration.ofHours(12));                 // 双人互斥，TTL 兜底
        redis.zAdd("colearn:active_sessions", clock.now(), sessionId);

        // 12. 注册超时守护任务（统一延迟任务调度引擎，§8.6/§9.6）
        delayTaskClient.register("COLEARN_MAX_DURATION", sessionId,
                clock.now() + maxDuration * 60_000L);
        delayTaskClient.register("COLEARN_HEARTBEAT_TIMEOUT", sessionId,
                clock.now() + HEARTBEAT_GRACE_MS);                             // 5min 无心跳清理

        // 13. 签发 wsToken（HMAC，10 分钟有效，§7.1）
        String wsToken = wsTokenCodec.sign(sessionId, ctx.getUserId(), "parent",
                clock.now() + WS_TOKEN_TTL_MS);

        return SessionCreateResult.of(sessionId, tasks, wsToken);
    } finally {
        redis.releaseLock(lockKey, opId);                                     // Lua 校验 value 再删，防误删他人锁
    }
}
```

| 19004 | 该家长-孩子已有活跃会话（含并发竞态） | 409 | existingSessionId |

## 7. WebSocket 实时通道设计

### 7.1 连接与鉴权

- **端点**：`/ws/v1/colearn/{sessionId}`，连接时携带 `wsToken`（query param 或首帧 auth）。
- **wsToken**：`base64url(sessionId|userId|role|expMs)` + HMAC-SHA256 签名（密钥走《服务端密钥管理与敏感配置安全策略》）；TTL 10 分钟，`GET /sessions/{id}` 每次刷新（§6.3）；过期拒绝并下发 `error{code:19010}`，客户端重取 token 重连。
- **单写者原则**：每会话同一时刻仅一条**可写连接**。新连接接入同会话时：校验同 (sessionId, userId) → 替换旧连接（旧连接收 `error{code:19011, reason:"replaced"}` 后关闭），不同 userId 拒绝（19021 语义）。断线重连即走此替换路径，天然去重。

### 7.2 帧协议

**客户端 → 服务端：**

| 帧类型 | 载荷 | 说明 |
|-------|------|------|
| auth | { wsToken } | 首帧鉴权（若未走 query param） |
| heartbeat | { clientTime } | 30s 周期；服务端回 pong 并刷新 active_sessions score |
| reconnect | { lastSeq } | 重连声明：服务端回放 lastSeq 之后的缓冲帧（§7.3） |

**服务端 → 客户端：**

| 帧类型 | 载荷 | 触发时机 |
|-------|------|---------|
| pong | { serverTime } | 心跳应答，兼作时钟校准 |
| task.advance | { taskOrder, prevResult } | 任务终态收敛后（AUTO 判定 / 家长操作 / 跳过） |
| status.sync | { status, currentRole, break, pause } | 状态变化（含他端操作、服务端触发），客户端强制对齐 |
| break.start | { reason, endsAt, forced, skippable } | 休息开始（触发类型见 §8.3） |
| break.end | { skipped } | 休息结束 / 家长跳过 |
| difficulty.suggest | { suggestionId, direction, reason } | 自适应建议（家长确认才生效，G10） |
| remind.parent_judge | { taskOrder, waitedMs } | EVALUATING 悬挂 60s 提醒 |
| session.end | { finalStatus, endReason, summary } | 服务端终态（超时清理/每日上限/自然完成），客户端停止主循环进报告 |
| error | { code, message, detail } | 协议级错误（19010/19011/19102 等） |

### 7.3 seq 分配与事件回放

- 服务端每帧携带单调递增 `seq`（`colearn:seq:{sessionId}` INCR），与 §6.4 事件接口共用同一序号空间。
- 每帧写入 Redis 环形缓冲 `colearn:wsbuf:{sessionId}`（LPUSH + LTRIM 200），TTL 随会话；重连 `reconnect{lastSeq}` → 服务端按 seq 过滤回放缺失帧，再进入实时推送。
- 缓冲耗尽（> 200 帧未消费）→ 下发 `error{code:19010, reason:"buffer_overflow"}` 指引客户端走 §6.3 全量校准。
- **帧投递语义**：at-least-once + 客户端按 seq 去重；关键帧（task.advance/session.end）同时落 `colearn_event`，HTTP 事件接口可兜底重放（D6 双通道）。

### 7.4 心跳与超时判定

| 阈值 | 动作 |
|------|------|
| 90s 无心跳 | 标记连接僵死，关闭连接、清理 `colearn:ws:{sessionId}` 成员 |
| 5min 无心跳（会话级） | 延迟任务触发 force_end(timeout)，广播 session.end（§8.6） |
| 心跳续期 | 刷新 `colearn:active_sessions` score（ZADD XX），滚动重注册 HEARTBEAT_TIMEOUT 延迟任务 |

### 7.5 下行推送时机矩阵

| 领域事件 | 帧 | 备注 |
|---------|----|------|
| 任务终态（AUTO/家长收敛/跳过） | task.advance | 同连接即时 |
| 会话状态 CAS 成功 | status.sync | pause/resume/end 全部广播 |
| 休息调度器触发 | break.start / break.end | forced 帧不可被客户端跳过入口响应（G9，客户端侧执行） |
| 自适应评估命中 | difficulty.suggest | 每会话最多 2 次建议，防打扰 |
| EVALUATING 悬挂 60s | remind.parent_judge | 每任务至多 1 次 |
| 服务端终态 | session.end | 终帧，随后服务端主动关闭连接 |

### 8.3 暂停 / 恢复 / 强制休息

- **暂停**：pause 请求 → CAS ACTIVE→PAUSED → 记 `pause_start_time` → status.sync 广播 → 注册 PAUSE_TIMEOUT(30min) 延迟任务。重复 pause 幂等成功。
- **恢复**：resume → CAS PAUSED→ACTIVE → `total_pause_sec += now − pause_start_time` → 重推当前任务 → 注销 PAUSE_TIMEOUT。BREAKING 中暂停：休息断点存 `colearn:break:{sessionId}`，恢复后先补完剩余休息秒数。
- **休息触发三类**（对齐客户端埋点 reason）：`timed`（达到 break_interval，可跳过，每会话 1 次——第二次跳过尝试返回 19009）/ `wrong_streak`（连续 3 错，强制不可跳过，G9）/ `timeout_streak`（孩子 90s 无操作，强制）。休息开始：CAS ACTIVE→BREAKING + break.start 帧 + 注册 BREAK_END 延迟任务（双保险：客户端倒计时 + 服务端延迟任务，以服务端为准）。
- **休息计入口径**：休息时长计入会话最大时长（防时长规避，C3），但不计入有效学习时长（§9.5 公式，对齐《学习时长统计与有效性判定引擎》消费口径）。

## 9. 核心服务实现（关键代码）

### 9.1 SessionManager 状态机流转

```java
@Component
public class ColearnSessionManager {

    private static final Map<String, Set<String>> TRANSITIONS = Map.of(
        "created",   Set.of("active"),
        "active",    Set.of("paused", "breaking", "completed", "force_ended"),
        "paused",    Set.of("active", "force_ended"),
        "breaking",  Set.of("active", "paused", "force_ended"));

    /**
     * 状态流转（DB CAS + Redis 同步）。返回 false 表示当前状态不允许该流转。
     * 终态（completed/force_ended）后任何流转请求由调用方映射 19006。
     */
    public boolean transition(String sessionId, String target, String endReason) {
        // UPDATE colearn_session SET status=:target,
        //   end_time = CASE WHEN :target IN ('completed','force_ended') THEN now() ELSE end_time END,
        //   end_reason = :endReason, version = version + 1
        // WHERE id = :sessionId AND status IN (:allowedFrom)
        int updated = sessionRepo.casStatus(sessionId, target, TRANSITIONS.get(currentOf(sessionId)), endReason);
        if (updated == 0) return false;
        redis.hSet("colearn:session:" + sessionId, "status", target);
        if (isTerminal(target)) {
            redis.zRem("colearn:active_sessions", sessionId);
            redis.delete("colearn:active_pair:" + pairOf(sessionId));   // 延迟双删：先删 + 1h 后兜底
            eventPublisher.frame(sessionId, Frame.sessionEnd(target, endReason));
        } else {
            eventPublisher.frame(sessionId, Frame.statusSync(target));
        }
        return true;
    }
}
```

### 9.2 TaskOrchestrator 任务序列生成

```java
public List<TaskDraft> generate(ContentPool pool, int maxDurationMin, ColearnSettings settings) {
    // 1. 数量收敛：按 90s/任务 估算，钳制 [8, 15]，并受池容量约束
    int est = (int) Math.max(8, Math.min(15, maxDurationMin * 60 / 90));
    int count = Math.min(est, pool.availableCount());

    // 2. 类型多样性：recognize/pronounce/match/sort/listen_choose/trace 轮转，
    //    相邻同类型 ≤ 2；单一类型池降级为顺序卡片
    // 3. 难度梯度：前 40% 低难度热身 → 中段主体 → 末段 1-2 个巩固项（不超当前档）
    // 4. 内容快照物化：写入 content_snapshot（题目文本/选项/媒体URL签名），
    //    会话内内容不失效（版本升级不影响进行中会话）
    List<ContentItem> items = pool.select(count, DiversityPolicy.ROUND_ROBIN, GradientPolicy.WARM_UP);
    return items.stream().map(t -> TaskDraft.from(t, nextOrder++, settings.getRewardMode())).toList();
}
```

### 9.3 EvaluationEngine 双路由判定

```java
public EvaluationRoute evaluate(TaskContext task, ChildResponse resp) {
    try {
        AiConfidence conf = switch (resp.responseType()) {
            case "tap", "drag", "trace_path", "fill_blank" ->
                // 结构化作答：规则判分，置信度直接给高（0.95+），3s 预算内同步
                ruleEngine.judge(task, resp);
            case "voice" ->
                // 语音：ASR 已在网关侧完成（recognizedText + pronunciationScore），
                // 置信度 = f(发音分, 文本匹配, 音素混淆度)；音频不留存（C1，流式转写后即弃）
                voiceEval.confidence(task, resp);
            default -> AiConfidence.unknown();                       // 19013 上游已拦截，兜底
        };
        if (conf.value() >= AUTO_THRESHOLD) {                       // 0.80
            return EvaluationRoute.auto(conf, task.isExpected(resp));
        }
        return EvaluationRoute.parentJudge(conf);                    // < 0.8 交家长
    } catch (EvalUnavailableException e) {
        // D4 fail-safe：评估服务不可用一律走家长判定，绝不自动判错
        return EvaluationRoute.parentJudge(AiConfidence.nullConfidence());
    }
}
```

### 9.4 RealtimeSync 帧广播与回放

```java
public void frame(String sessionId, Frame frame) {
    long seq = redis.incr("colearn:seq:" + sessionId);               // 与事件接口共用序号空间
    frame.setSeq(seq);
    // 1. 环形缓冲（LPUSH+LTRIM 200, at-least-once 重放源）
    redis.lPush("colearn:wsbuf:" + sessionId, json(frame));
    redis.lTrim("colearn:wsbuf:" + sessionId, 0, 199);
    // 2. 关键帧落 DB 事件表（HTTP 兜底通道）
    if (frame.isPersistent()) eventRepo.insertAsync(sessionId, frame.toEvent());
    // 3. 实时推送（单写者连接；连接僵死则静默，等重连回放）
    wsSessions.pushIfPresent(sessionId, frame);
}

public void replay(String sessionId, long lastSeq, WsConn conn) {
    List<Frame> buffered = redis.lRange("colearn:wsbuf:" + sessionId, 0, -1).stream()
            .map(Frame::parse).filter(f -> f.getSeq() > lastSeq)
            .sorted(Comparator.comparingLong(Frame::getSeq)).toList();
    if (buffered.size() >= 200) {                                    // 缓冲耗尽
        conn.send(Frame.error(19010, "buffer_overflow"));           // 指引全量校准
        return;
    }
    buffered.forEach(conn::send);
}
```

### 9.5 StatisticsAggregator 结束统计

```java
public SessionStats aggregate(ColearnSession s, List<ColearnTask> tasks) {
    long pauseSec = s.getTotalPauseSec();
    long breakSec = eventRepo.sumBreakDuration(s.getId());           // break_start..break_end 累计
    long effective = durationSec(s) - pauseSec - breakSec;            // 有效时长（对齐时长对账引擎口径）

    long evaluated = tasks.stream().filter(t -> t.getFinalResult() != null).count();
    long correct   = tasks.stream().filter(t -> "correct".equals(t.getFinalResult())).count();
    BigDecimal accuracy = evaluated == 0 ? null
            : BigDecimal.valueOf(correct).divide(BigDecimal.valueOf(evaluated), 4, RoundingMode.HALF_UP);

    // 星星规则（单任务 0-3）：首尝试正确 3 / 提示后正确 2 / 家长确认正确 1 / 其他 0
    int stars = tasks.stream().mapToInt(this::taskStars).sum();

    // 家长参与度 = 覆盖度 0.5 + 强度 0.3 + 陪伴时长 0.2（报告页展示 & 日报聚合）
    double coverage   = evaluated == 0 ? 0 : (double) tasksWithParentAction(tasks) / evaluated;
    double intensity  = Math.min(1.0, (double) s.getParentActionCount() / (evaluated * 1.5));
    double company    = Math.min(1.0, (double) effective / 300);      // 5min 陪伴满分
    double involvement = Math.min(1.00, 0.5 * coverage + 0.3 * intensity + 0.2 * company);

    return SessionStats.of(effective, correct, evaluated, accuracy, stars, involvement);
}
```

## 12. 幂等与并发控制

### 12.1 clientEventId 结果回放

- 首次处理成功后将**响应 JSON** 写入 `colearn:idem:result:{clientEventId}`（TTL 60s，取代 v1.0 §5.1 的 `colearn:idempotent:*` 计数语义——幂等命中必须返回首次结果而非空响应，客户端 §9.1 规则 4）。
- 写入与业务处理非原子（先业务后缓存），竞态窗口内的重复请求以 DB 唯一索引兜底：`colearn_event.client_event_id` 部分唯一索引。

### 12.2 seq 单调序号

- 客户端每会话维护单调 `seq`（互动事件递增）；服务端按会话记 `maxConsumedSeq`（Redis + 落库），`seq ≤ maxConsumedSeq` → 19102 业务忽略（HTTP 200）。
- seq 是 60s 幂等窗口之外的兜底（迟到重试、离线补报乱序）。

### 12.3 离线补报保序

- 补报批次按 seq 升序串行（客户端保证）；服务端 19102 丢弃 + 19002/19101 状态守卫双防线，任何乱序不产生脏终态。

### 12.4 DDL 增补（v1.1）

## 15. 容量与性能规划

- **业务假设**：平台 DAU 50 万，幼儿 + 小学低年级占比 25%（12.5 万），共学日渗透 ~10% → **日会话 ~1.25 万**，晚间高峰并发 ~4k，按 10k 并发会话设计余量（§1.3 目标）。
- **写入量**：日 task 行 15 万（12/会话）、event 行 75 万（60/会话）；PG 按月 RANGE 分区，在线保留 180 天（合规 C9），之后归档 OSS Parquet（session/task/event 三表 ~0.9GB/日，180 天 ≈ 160GB，分区裁剪保证查询性能）。
- **Redis**：活跃会话 hash ~3KB × 10k = 30MB；wsbuf 200 帧 × 1KB × 活跃会话 = 并发 4k 时 ≈ 800MB；seq/idem 等零散 Key < 50MB。
- **WS 网关**：单节点 5k 连接，2 节点 + LB 覆盖 10k；帧广播为单播（单写者），无扇出压力。
- **评估引擎**：作答峰值 QPS = 并发 4k / 90s 每任务 ≈ 45 QPS，ASR 走语音服务既有容量（不新建）。

## 18. 验收场景

1. 创建：绑定校验、防沉迷剩余 2min → 19008 拒绝；剩余 8min → maxDuration 收敛为 8。
2. 双设备第二台创建 → 19004 + existingSessionId，客户端引导恢复。
3. 弱网双击「开始共学」→ appSessionId 唯一索引兜底，两次请求返回同一 sessionId。
4. 语音作答 aiConfidence=0.9 → AUTO 即时判分并 task.advance；0.35 → PARENT_JUDGE，家长 confirm 后推进。
5. ASR 超时（>3s）→ route=PARENT_JUDGE、aiConfidence=null，会话不中断。
6. EVALUATING 悬挂 60s 收到 remind 帧；5min 后 pending_review 收敛，统计计入分母不计 correct。
7. 作答与家长 skip 并发 → 后到者 19002，客户端按服务端终态校准。
8. timed 休息第二次跳过 → 19009；wrong_streak 强制休息无跳过入口，休息中提交作答 → 19101。
9. 暂停 31 分钟 → 延迟任务 force_end(timeout)，重连客户端收 session.end 进报告。
10. 心跳停止 5min（连接已断）→ force_end(timeout)；心跳续期后延迟任务比对 score 跳过误杀。
11. WS 断线 30s：flush→GET 校准→events 增量→reconnect 回放，任务序号与服务端一致。
12. 断线超 200 帧未消费 → buffer_overflow 帧走全量校准路径。
13. 正常完成 10 任务 → 报告含 summary/highlights/weakPoints/nextSuggestion，孩子视角无 accuracy/parentDetail。
14. 报告生成失败 → 响应含 reportPending，15min 内重试成功并推送，历史可查。
15. Redis 宕机演练 → PG 权威降级，会话可继续（轮询同步），恢复后缓存重建无脏状态。
16. Kafka 宕机 10min → Outbox 积压，恢复后补投，消费方按 event_id 幂等无重复发放星星。
17. 历史查询越权（查他人孩子）→ 403/19003 语义，审计日志记录。
18. 180 天后会话查询 → 19017 引导聚合视图；归档副本 OSS 可下载（家长本人）。
