# 管理后台 - 商品与增值服务配置工作台 详细设计

## 1. 概述

### 1.1 模块定位

商品与增值服务配置工作台是 PrimeTop 管理后台的商业化运营核心模块，面向平台运营人员、商业化产品经理、财务人员，提供虚拟商品、增值服务包、会员套餐、商品分类、定价策略、渠道分发、权益绑定、库存限量等商品全生命周期管理能力。该工作台是连接 C 端购买入口、支付订单、会员权益与积分系统的后台配置中枢。

### 1.2 设计目标

| 目标 | 说明 |
| --- | --- |
| 商品配置灵活 | 支持会员、次数包、课程包、虚拟道具等多种商品类型，支持套餐组合与单卖 |
| 权益绑定清晰 | 商品与权益（AI 额度、功能解锁、内容访问、会员时长等）明确映射，可追踪 |
| 定价策略可控 | 支持原价、售价、折扣价、渠道价、区域价、限时价等多层定价 |
| 渠道分发可配 | 支持 Android/iOS/Web/小程序等渠道差异化展示与价格 |
| 库存与限量管理 | 支持虚拟库存、限量发售、每人限购、新用户专属等运营规则 |
| 合规与审计完整 | 商品变更留痕、高危操作审批、未成年人保护提示 |  

### 1.3 适用范围

- **商业化产品经理**：设计商品 SKU、套餐组合、定价与活动策略。
- **运营人员**：管理商品上下架、渠道展示、库存放量、限时活动。
- **财务人员**：核对商品定价、成本、收入归属与对账口径。
- **平台管理员**：审批高危商品变更、查看商品销售与权益发放数据。

## 2. 数据结构定义

### 2.1 商品分类表 `product_category`

```sql
CREATE TABLE product_category (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    category_code   VARCHAR(64) NOT NULL UNIQUE COMMENT '分类编码: membership/photo_pack/essay_pack/course_pack/virtual_goods/combo',
    category_name   VARCHAR(128) NOT NULL COMMENT '分类名称',
    parent_id       BIGINT DEFAULT 0 COMMENT '父分类ID，0=根分类',
    level           TINYINT NOT NULL DEFAULT 1 COMMENT '层级: 1=一级 2=二级',
    icon_url        VARCHAR(512) COMMENT '分类图标',
    description     VARCHAR(512) COMMENT '分类描述',
    display_order   INT DEFAULT 0 COMMENT '展示排序',
    status          TINYINT NOT NULL DEFAULT 1 COMMENT '1=启用 0=停用',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_parent_level (parent_id, level),
    INDEX idx_status_order (status, display_order)

```

### 2.2 商品主表 `product`

```sql
    selling_price       DECIMAL(10,2) NOT NULL COMMENT '售价（分）',

    thumbnail_url       VARCHAR(512) COMMENT '商品封面图',

    description         TEXT COMMENT '商品详情描述（富文本）',

    updated_by          BIGINT NOT NULL COMMENT '最近更新人ID',
```

## 3. 核心业务状态机

### 3.1 商品状态流转

```text
                    ┌─────────┐
                    │  草稿   │  ← 创建后初始状态，仅后台可见
                    └────┬────┘
                         │ 运营人员提交上架
                         ▼
                    ┌─────────┐
                    │  上架中 │  ← 可定时上架，C端可见可购买
                    └────┬────┘
                         │
           运营下架      │     库存售罄
              │          │          │
              ▼          ▼          ▼
        ┌─────────┐ ┌─────────┐ ┌─────────┐
        │  已下架 │ │  已过期 │ │  已售罄 │
        └─────────┘ └─────────┘ └─────────┘
              │
              │ 重新上架
              └──────────▶  上架中
```

**状态说明：**

| 状态 | 编码 | 说明 |
| --- | --- | --- |
| 草稿 | 0 | 后台配置中，不对外展示 |
| 上架 | 1 | 正常售卖 |
| 下架 | 2 | 运营手动下架，不可购买 |
| 售罄 | 3 | 库存耗尽自动触发，可补库存后恢复 |
| 过期 | 4 | 达到 off_sale_time 自动下架 |

### 3.2 权益发放状态流转

```text
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ pending  │────▶│ granting │────▶│ granted  │────▶│ consumed │
│ 待发放   │     │ 发放中   │     │ 已发放   │     │ 已消费   │
└──────────┘     └──────────┘     └─────┬────┘     └──────────┘
                                        │
                                        ▼
                                  ┌──────────┐
                                  │ expired  │
                                  │ 已过期   │
                                  └──────────┘
                                        │
                                        ▼
                                  ┌──────────┐
                                  │ revoked  │
                                  │ 已撤销   │ ← 退款或风控撤销
                                  └──────────┘
```

## 4. API 接口设计

### 4.1 接口规范

- 基础路径：`/api/admin/product`
- 认证方式：Bearer Token + 角色权限校验（`product_admin` / `finance_admin` / `super_admin`）
- 响应格式：统一 `{ code, message, data }`

### 4.2 商品分类管理

#### 4.2.1 获取分类列表

```
GET /api/admin/product/categories
```

**Query 参数：**

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| status | int | 状态筛选 |
| level | int | 层级筛选 |
| parentId | long | 父分类ID |

**响应示例：**

```json
{
  "code": 0,
  "data": [
    {
      "id": 1,
      "categoryCode": "membership",
      "categoryName": "会员订阅",

      "level": 1,
      "status": 1,

        {
          "id": 11,
          "categoryCode": "monthly_membership",
          "categoryName": "月度会员",
          "parentId": 1,
          "level": 2

      ]
    }
  ]
}
```

### 5.1 商品可购买性校验（Java）

```java
@Service
public class ProductPurchaseService {

    @Autowired
    private ProductRepository productRepository;
    @Autowired
    private ProductSkuRepository skuRepository;
    @Autowired
    private ProductChannelConfigRepository channelConfigRepository;
    @Autowired
    private UserProfileService userProfileService;
    @Autowired
    private OrderRepository orderRepository;

    /**
     * 校验商品是否可购买
     */
    public PurchaseCheckResult checkPurchaseEligibility(Long userId, Long productId, Long skuId, String channel) {
        Product product = productRepository.findById(productId)
            .orElseThrow(() -> new ProductException(ErrorCode.PRODUCT_NOT_FOUND));

        // 1. 状态校验
        if (product.getStatus() != 1) {
            return PurchaseCheckResult.fail(ErrorCode.PRODUCT_NOT_ON_SALE);
        }

        // 2. 定时上下架校验
        LocalDateTime now = LocalDateTime.now();
        if (product.getOnSaleTime() != null && now.isBefore(product.getOnSaleTime())) {
            return PurchaseCheckResult.fail(ErrorCode.PRODUCT_NOT_STARTED);
        }
        if (product.getOffSaleTime() != null && now.isAfter(product.getOffSaleTime())) {
            return PurchaseCheckResult.fail(ErrorCode.PRODUCT_EXPIRED);
        }

        // 3. SKU 校验
        ProductSku sku = skuRepository.findById(skuId)
            .orElseThrow(() -> new ProductException(ErrorCode.SKU_NOT_FOUND));
        if (sku.getStatus() != 1 || !sku.getProductId().equals(productId)) {
            return PurchaseCheckResult.fail(ErrorCode.SKU_INVALID);
        }

        // 4. 渠道配置校验
        ProductChannelConfig channelConfig = channelConfigRepository
            .findByProductIdAndSkuIdAndChannel(productId, skuId, channel)
            .orElseGet(() -> channelConfigRepository
                .findByProductIdAndSkuIdAndChannel(productId, null, "all")
                .orElseThrow(() -> new ProductException(ErrorCode.CHANNEL_NOT_SUPPORTED)));

        if (channelConfig.getIsVisible() != 1 || channelConfig.getIsPurchasable() != 1) {
            return PurchaseCheckResult.fail(ErrorCode.PRODUCT_NOT_AVAILABLE_IN_CHANNEL);
        }

        // 5. 学段年级校验
        StudentProfile profile = userProfileService.getStudentProfile(userId);
        if (!isSegmentApplicable(product, profile.getSegment())) {
            return PurchaseCheckResult.fail(ErrorCode.SEGMENT_NOT_APPLICABLE);
        }
        if (product.getMinGrade() != null && profile.getGrade() < product.getMinGrade()) {
            return PurchaseCheckResult.fail(ErrorCode.GRADE_NOT_APPLICABLE);
        }
        if (product.getMaxGrade() != null && profile.getGrade() > product.getMaxGrade()) {
            return PurchaseCheckResult.fail(ErrorCode.GRADE_NOT_APPLICABLE);
        }

        // 6. 新用户专享校验
        if (product.getNewUserOnly() == 1) {
            boolean hasPaid = orderRepository.existsPaidOrderByUserId(userId);
            if (hasPaid) {
                return PurchaseCheckResult.fail(ErrorCode.NEW_USER_ONLY);
            }
        }

        // 7. 库存校验
        if (product.getTotalStock() != -1 && product.getRemainingStock() <= 0) {
            return PurchaseCheckResult.fail(ErrorCode.PRODUCT_SOLD_OUT);
        }
        if (sku.getTotalStock() != -1 && sku.getRemainingStock() <= 0) {
            return PurchaseCheckResult.fail(ErrorCode.SKU_SOLD_OUT);
        }

        // 8. 限购校验
        if (product.getPerUserLimit() > 0) {
            long boughtCount = orderRepository.countPaidProductByUser(userId, productId);
            if (boughtCount >= product.getPerUserLimit()) {
                return PurchaseCheckResult.fail(ErrorCode.EXCEED_USER_LIMIT);
            }
        }
        if (product.getPerUserDailyLimit() > 0) {
            long todayCount = orderRepository.countPaidProductByUserToday(userId, productId);
            if (todayCount >= product.getPerUserDailyLimit()) {
                return PurchaseCheckResult.fail(ErrorCode.EXCEED_DAILY_LIMIT);
            }
        }

        return PurchaseCheckResult.ok(product, sku, channelConfig);
    }

    private boolean isSegmentApplicable(Product product, String segment) {
        if (StringUtils.isBlank(product.getApplicableSegments())) return true;
        return Arrays.asList(product.getApplicableSegments().split(",")).contains(segment);
    }
}
```

### 5.2 权益发放与解析（Python）

```python
from dataclasses import dataclass
from typing import List, Optional
from datetime import datetime, timedelta

@dataclass
class ProductBenefit:
    benefit_type: str
    benefit_code: str
    benefit_value: str
    benefit_unit: str
    grant_mode: int
    valid_days: int
    stackable: int
    consumption_scope: dict

class BenefitGrantService:
    def __init__(self, quota_service, membership_service, feature_service, content_service):
        self.quota_service = quota_service
        self.membership_service = membership_service
        self.feature_service = feature_service
        self.content_service = content_service

    def grant_benefits(self, user_id: int, product_id: int, sku_id: Optional[int], order_id: int) -> List[dict]:
        """根据商品权益配置发放权益"""
        benefits = self.load_benefits(product_id, sku_id)
        results = []
        for benefit in benefits:
            valid_until = self._calc_valid_until(benefit)
            result = self._grant_single_benefit(user_id, benefit, order_id, valid_until)
            results.append(result)
        return results

    def _load_benefits(self, product_id: int, sku_id: Optional[int]) -> List[ProductBenefit]:
        # 先查 SKU 级权益，再查商品级权益
        benefits = BenefitRepository.find_by_product_and_sku(product_id, sku_id)
        if not benefits:
            benefits = BenefitRepository.find_by_product_and_sku(product_id, None)
        return benefits

    def _calc_valid_until(self, benefit: ProductBenefit) -> datetime:
        if benefit.valid_days and benefit.valid_days > 0:
            return datetime.now() + timedelta(days=benefit.valid_days)
        return datetime.max  # 永久或跟随商品有效期

    def _grant_single_benefit(self, user_id: int, benefit: ProductBenefit, order_id: int, valid_until: datetime):
        grant_record = {
            "user_id": user_id,
            "order_id": order_id,
            "benefit_type": benefit.benefit_type,
            "benefit_code": benefit.benefit_code,
            "benefit_value": benefit.benefit_value,
            "valid_until": valid_until,
            "status": "granted",
            "created_at": datetime.now()
        }

        if benefit.benefit_type == "ai_quota":
            times = int(benefit.benefit_value)
            self.quota_service.add_quota(user_id, "ai_chat", times, valid_until, order_id)

        elif benefit.benefit_type == "photo_quota":
            times = int(benefit.benefit_value)
            self.quota_service.add_quota(user_id, "photo_search", times, valid_until, order_id)

        elif benefit.benefit_type == "membership_days":
            days = int(benefit.benefit_value)
            self.membership_service.extend_membership(user_id, days, order_id)

        elif benefit.benefit_type == "feature_unlock":
            feature_code = benefit.benefit_value
            self.feature_service.unlock_feature(user_id, feature_code, valid_until, order_id)

        elif benefit.benefit_type == "course_access":
            course_ids = benefit.benefit_value.split(",")
            self.content_service.grant_course_access(user_id, course_ids, valid_until, order_id)

        elif benefit.benefit_type == "points":
            points = int(benefit.benefit_value)
            self.quota_service.add_points(user_id, points, "purchase_grant", order_id)

        else:
            grant_record["status"] = "pending_manual"
            grant_record["remark"] = f"未识别的权益类型: {benefit.benefit_type}"

        GrantRecordRepository.save(grant_record)
        return grant_record
```

### 5.3 套餐价格校验（TypeScript）

```typescript
interface ComboItem {
  itemProductId: number;
  itemSkuId?: number;
  itemQuantity: number;
  itemOriginalPrice: number;
  itemSellingPrice: number;
}

function validateComboPrice(
  comboOriginalPrice: number,
  comboSellingPrice: number,
  items: ComboItem[]
): { valid: boolean; message?: string } {
  const totalOriginal = items.reduce(
    (sum, item) => sum + item.itemOriginalPrice * item.itemQuantity,
    0
  );
  const totalSelling = items.reduce(
    (sum, item) => sum + item.itemSellingPrice * item.itemQuantity,
    0
  );

  if (comboOriginalPrice > totalOriginal) {
    return {
      valid: false,
      message: `套餐原价 ${comboOriginalPrice} 不能高于子商品原价总和 ${totalOriginal}`,
    };
  }

  if (comboSellingPrice >= totalSelling) {
    return {
      valid: false,
      message: `套餐售价 ${comboSellingPrice} 必须低于子商品单独购买总价 ${totalSelling}，否则失去套餐意义`,
    };
  }

  const discountRate = comboSellingPrice / totalSelling;
  if (discountRate < 0.5) {
    return {
      valid: false,
      message: `套餐折扣率 ${(discountRate * 100).toFixed(1)}% 过低，需管理员特批`,
    };
  }

  return { valid: true };
}
```

### 6.1 业务错误码

| 错误码 | 含义 | 处理建议 |
| --- | --- | --- |
| PRODUCT_NOT_FOUND | 商品不存在 | 检查商品ID |
| SKU_NOT_FOUND | SKU 不存在 | 检查 SKU ID |
| PRODUCT_NOT_ON_SALE | 商品未上架 | 提示商品已下架 |
| PRODUCT_NOT_STARTED | 商品未到开售时间 | 展示开售倒计时 |
| PRODUCT_EXPIRED | 商品已过期 | 提示活动已结束 |
| CHANNEL_NOT_SUPPORTED | 当前渠道不支持 | 切换渠道或联系客服 |
| PRODUCT_NOT_AVAILABLE_IN_CHANNEL | 该渠道不可购买 | 隐藏购买按钮 |
| SEGMENT_NOT_APPLICABLE | 学段不适用 | 根据年级学段过滤展示 |
| GRADE_NOT_APPLICABLE | 年级不适用 | 根据年级学段过滤展示 |
| NEW_USER_ONLY | 仅限新用户 | 提示老用户不可购买 |
| PRODUCT_SOLD_OUT | 商品售罄 | 展示补货通知 |
| SKU_SOLD_OUT | SKU 售罄 | 切换其他 SKU |
| EXCEED_USER_LIMIT | 超出每人限购 | 提示已到达购买上限 |
| EXCEED_DAILY_LIMIT | 超出每日限购 | 提示明日再来 |
| COMBO_PRICE_INVALID | 套餐价格不合法 | 后台校验失败 |
| BENEFIT_TYPE_INVALID | 权益类型无效 | 后台配置错误 |
| PRICE_CHANGE_NEED_APPROVAL | 价格变更需审批 | 提交审批工单 |
| PRODUCT_AUDIT_FAILED | 商品审核未通过 | 查看审核意见 |

### 6.2 异常处理策略

| 异常场景 | 处理策略 |
| --- | --- |
| 商品配置数据缺失 | 上架前强制校验，缺失则阻止上架并提示 |
| 价格变更未审批 | 上架状态价格修改走审批流，草稿状态可直接修改 |
| 权益发放失败 | 记录失败日志，进入补偿队列，人工可手动补发 |
| 库存扣减并发冲突 | 使用数据库乐观锁或 Redis 分布式锁 |
| 渠道配置不一致 | 上架前校验各渠道必要字段（如 iOS 的 apple_product_id） |
| 定时上下架任务遗漏 | 使用延迟任务队列 + 兜底扫描双保险 |
| 退款后权益撤销 | 根据 grant_mode 逆向撤销，不可撤销的权益记录为已失效 |

## 7. 性能优化

### 7.1 缓存策略

| 缓存对象 | 缓存方式 | 过期时间 | 说明 |
| --- | --- | --- | --- |
| C 端商品列表 | Redis Hash + List | 5 分钟 | 按渠道+学段+年级维度缓存 |
| 商品详情 | Redis Hash | 10 分钟 | 含 SKU、权益、渠道配置 |
| 商品可购买性 | Redis 本地缓存 | 1 分钟 | 用户级限购计数用 Redis 缓存 |
| 分类树 | Redis String | 30 分钟 | 全量分类树缓存 |
| 库存计数 | Redis Decr | 实时 | 限量商品使用 Redis 原子扣减 |

### 7.2 查询优化

- 商品列表查询走 `(status, product_type, category_id)` 组合索引。
- C 端列表按渠道和学段预过滤，避免全表扫描。
- 销售统计使用每日预聚合表，避免实时统计大订单表。
- 商品详情查询采用 JOIN 减少多次请求，或应用层缓存合并。

### 7.3 并发控制

- 库存扣减：使用 `UPDATE product SET remaining_stock = remaining_stock - 1 WHERE id = ? AND remaining_stock > 0` 或 Redis 原子扣减。
- 限购计数：使用 Redis INCR + 过期时间，按用户/商品/天维度。
- 价格变更：上架状态价格修改加分布式锁，防止并发修改。

| 超管 | 全部权限 |

### 8.2 审计与留痕

- 商品创建、修改、上下架、价格变更、权益变更、删除等操作全部写入 `product_audit_log`。
- 快照字段保存变更前后的完整 JSON，便于追溯。
- 高危操作（价格修改超过 20%、库存清零、新用户专享商品创建）强制走审批流。

### 8.3 未成年人保护

- 商品详情中涉及付费的内容必须标注适龄提示。
- 限制低龄用户（幼儿、小学低年级）可见的商品类型，避免诱导消费高单价商品。
- 单笔超过 200 元或月度累计超过 500 元的购买触发家长确认机制（由家长支付或短信确认）。
- 新用户专享、限时折扣等营销活动不得面向 8 周岁以下儿童用户。

### 8.4 数据安全

- 商品成本价字段仅对财务和管理员可见，普通运营人员不展示。
- 渠道配置中的 Apple Product ID、小程序路径等敏感配置加密存储。
- 商品变更接口增加 IP 白名单和异地登录提醒。

## 9. 关键指标设计

### 9.1 商品运营指标

| 指标 | 计算方式 | 用途 |
| --- | --- | --- |
| 商品曝光转化率 | 支付成功数 / 曝光 UV | 评估商品吸引力 |
| 商品点击转化率 | 支付成功数 / 点击次数 | 评估详情页转化 |
| 商品退款率 | 退款笔数 / 支付成功笔数 | 评估商品质量与预期匹配 |
| 新用户购买占比 | 新用户购买数 / 总购买数 | 评估拉新效果 |
| 套餐购买率 | 套餐订单数 / 总订单数 | 评估交叉销售 |
| 渠道销售占比 | 各渠道销售额 / 总销售额 | 评估渠道策略 |

### 9.2 库存与限购监控

| 指标 | 告警阈值 | 处理建议 |
| --- | --- | --- |
| 商品库存不足 | 剩余库存 < 10% | 提醒运营补库存或下架 |
| 限购命中率高 | 命中限购用户数 > 50% | 考虑提高限购上限或推出新 SKU |
| 渠道价格异常 | 渠道价与商品售价差异 > 30% | 检查渠道配置 |

## 10. 待办与扩展点

5. **商品与优惠券联动**：支持商品级、SKU 级优惠券叠加规则配置。
