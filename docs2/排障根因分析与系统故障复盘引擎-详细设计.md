## 1. 模块概述

### 1.1 功能目标

为 PrimeTop 教育平台提供**统一的故障根因分析（RCA）与事故复盘（Postmortem）体系**，实现从告警触发到根因定位、从故障复盘到改进追踪的全生命周期管理，确保每一起生产事故都能转化为可落地的改进措施，推动系统韧性持续提升。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **自动化优先** | 故障发生时自动采集诊断数据、构建时间线、关联变更，减少人工排查时间 |
| **无指责文化** | 复盘聚焦系统和流程改进，而非个人追责；复盘文档对内公开 |
| **闭环追踪** | 每个改进措施都有 Owner、Due Date 和状态跟踪，确保落地 |
| **知识沉淀** | 历史事故形成知识库，辅助未来类似故障的快速定位 |
| **教育与合规** | 教育场景下故障影响面评估需包含学生学习数据完整性、内容可用性 |

### 1.3 与相关模块的边界

| 模块 | 职责 | 与本模块关系 |
|------|------|-------------|
| 监控告警体系 | 指标采集、阈值告警、通知分发 | **上游**：告警事件触发排障流程 |
| 智能故障检测与自愈引擎 | 实时异常检测、自动恢复动作 | **平行**：负责"发现+恢复"，本模块负责"分析+学习" |
| 分布式链路追踪 | 请求级全链路追踪与依赖拓扑 | **数据源**：提供调用链数据用于根因定位 |
| 审计日志系统 | 用户操作与管理操作追溯 | **数据源**：提供变更审计线索 |

## 3. 数据结构定义

### 3.1 事故实体 (Incident)

```typescript
interface Incident {
  // ── 基础信息 ──
  id: string;                          // 事故唯一ID，格式: INC-{YYYYMMDD}-{序号}
  title: string;                       // 事故标题
  severity: IncidentSeverity;          // 严重等级
  status: IncidentStatus;              // 事故状态
  category: IncidentCategory;          // 故障分类
  
  // ── 时间信息 ──
  detectedAt: Date;                    // 故障发现时间
  startTime: Date;                     // 故障实际开始时间（可能早于发现时间）
  mitigatedAt: Date | null;            // 故障缓解时间
  resolvedAt: Date | null;             // 故障完全恢复时间
  detectedBy: string;                  // 发现者：alert / auto-heal / manual / patrol
  
  // ── 影响范围 ──
  impact: IncidentImpact;              // 影响评估
  affectedServices: string[];          // 受影响服务列表
  affectedUserCount: number;           // 影响用户数（估算）
  affectedUserSegments: UserSegment[]; // 影响用户群体（学生/家长/教师/管理员）
  
  // ── 教育场景特有 ──
  educationalImpact: EducationalImpact; // 教育业务影响评估
  
  // ── 根因分析 ──
  rootCause: RootCause | null;         // 根因分析结果
  contributingFactors: string[];       // 促成因素
  
  // ── 时间线 ──
  timeline: TimelineEvent[];           // 事件时间线
  
  // ── 关联信息 ──
  alertIds: string[];                  // 关联告警ID
  changeIds: string[];                 // 关联变更ID（发布/配置/扩缩容）
  traceIds: string[];                  // 关键链路追踪ID
  runbookId: string | null;            // 使用的应急手册ID
  
  // ── 人员 ──
  incidentCommander: string;           // 事故指挥官
  responders: IncidentResponder[];     // 参与响应人员
  
  // ── 复盘 ──
  postmortemId: string | null;         // 关联的复盘文档ID
  
  createdAt: Date;
  updatedAt: Date;
}

type IncidentSeverity = 'SEV0' | 'SEV1' | 'SEV2' | 'SEV3';
// SEV0: 核心服务完全不可用（AI辅导全挂、登录不可用）
// SEV1: 核心服务严重降级（AI响应超时率>30%、支付异常）
// SEV2: 非核心服务不可用或核心服务轻微降级（学情报告生成失败、部分教材加载慢）
// SEV3: 小范围问题，用户体验轻微影响

type IncidentStatus = 
  | 'DETECTED'        // 已发现，待确认
  | 'TRIAGING'        // 分诊中
  | 'INVESTIGATING'   // 调查中
  | 'MITIGATING'      // 缓解中
  | 'MONITORING'      // 缓解后观察
  | 'RESOLVED'        // 已恢复
  | 'POSTMORTEM'      // 复盘中
  | 'CLOSED';         // 已关闭

type IncidentCategory = 
  | 'SERVICE_OUTAGE'      // 服务中断
  | 'PERFORMANCE_DEGRADATION' // 性能降级
  | 'DATA_ISSUE'          // 数据异常/不一致
  | 'AI_QUALITY'          // AI回答质量严重劣化
  | 'CONTENT_ERROR'       // 教育内容错误
  | 'SECURITY'            // 安全事件
  | 'THIRD_PARTY'         // 第三方依赖故障
  | 'INFRASTRUCTURE'      // 基础设施故障
  | 'CONFIG_ERROR'        // 配置错误
  | 'CAPACITY';           // 容量问题
```

### 3.2 根因分析实体 (RootCause)

```typescript
interface RootCause {
  incidentId: string;
  
  // ── 根因分类 ──
  rootCauseCategory: RootCauseCategory;
  rootCauseDetail: string;              // 根因详细描述
  
  // ── 因果链 ──
  causalChain: CausalFactor[];          // 因果链（从症状到根因）
  
  // ── 触发条件 ──
  trigger: string;                      // 直接触发因素
  conditions: string[];                 // 必要条件
  
  // ── 五问分析 ──
  fiveWhys: FiveWhyAnalysis[];          // 5-Why分析链
  
  // ── 变更分析 ──
  relatedChanges: ChangeRecord[];       // 相关变更记录
  
  // ── AI 辅助分析 ──
  aiAnalysis: AIAnalysisResult | null;  // AI辅助分析结论
  
  analyzedBy: string;
  analyzedAt: Date;
  confidence: 'HIGH' | 'MEDIUM' | 'LOW'; // 根因置信度
}

type RootCauseCategory =
  | 'CODE_DEFECT'           // 代码缺陷
  | 'CONFIG_CHANGE'         // 配置变更
  | 'CAPACITY_EXHAUSTION'  // 容量耗尽
  | 'DEPENDENCY_FAILURE'   // 依赖服务故障
  | 'NETWORK_ISSUE'        // 网络问题
  | 'DATA_CORRUPTION'      // 数据损坏
  | 'HUMAN_ERROR'          // 人为操作失误
  | 'THIRD_PARTY_OUTAGE'   // 第三方服务中断
  | 'RESOURCE_LEAK'        // 资源泄漏
  | 'RACE_CONDITION'       // 竞态条件
  | 'UNDOCUMENTED_BEHAVIOR'; // 未文档化的系统行为

interface CausalFactor {
  order: number;                        // 因果链顺序（1=直接原因）
  factor: string;                       // 因素描述
  evidence: string;                     // 支撑证据
  evidenceType: 'LOG' | 'METRIC' | 'TRACE' | 'AUDIT' | 'CODE';
  evidenceRef: string;                  // 证据引用（日志路径/metric名/trace链接）
}

interface FiveWhyAnalysis {
  level: number;                        // 第几层为什么 (1-5+)
  question: string;                     // 为什么...
  answer: string;                       // 因为...
  evidence: string;                     // 证据
}

interface ChangeRecord {
  changeId: string;                     // 变更ID
  changeType: 'DEPLOY' | 'CONFIG' | 'SCALE' | 'MIGRATION' | 'ROLLBACK';
  description: string;
  changedBy: string;
  changedAt: Date;
  riskLevel: 'LOW' | 'MEDIUM' | 'HIGH';
  relatedService: string;
}

interface AIAnalysisResult {
  model: string;                        // 使用的AI模型
  hypothesis: string[];                 // 根因假设列表
  evidenceCorrelation: string;          // 证据关联分析
  similarIncidents: string[];           // 历史相似事故ID
  confidenceScore: number;              // 置信度 0-1
  analysisData: string;                 // 原始分析数据
  analyzedAt: Date;
}
```

```typescript
interface Postmortem {
  id: string;                           // 格式: PM-{YYYYMMDD}-{序号}
  incidentId: string;                   // 关联事故ID
  
  // ── 状态 ──
  status: PostmortemStatus;
  
  // ── 会议信息 ──
  meetingScheduledAt: Date | null;
  meetingCompletedAt: Date | null;
  participants: string[];
  facilitator: string;                  // 复盘主持人（非事故指挥官）
  
  // ── 核心内容 ──
  summary: string;                      // 事故摘要
  timelineNarrative: string;            // 时间线叙述
  impactAssessment: string;             // 影响评估描述
  rootCauseAnalysis: string;            // 根因分析详述
  whatWentWell: string[];               // 做得好的方面
  whatWentWrong: string[];              // 做得不好的方面
  whereWeGotLucky: string[];            // 运气成分
  
  // ── 改进措施 ──
  actionItems: ActionItem[];            // 改进措施清单
  
  // ── 知识库 ──
  lessonsLearned: string[];             // 经验教训
  knowledgeTags: string[];              // 知识标签
  preventionPatterns: string[];         // 预防模式
  
  // ── 审批 ──
  reviewedBy: string | null;            // 审核人
  approvedAt: Date | null;
  
  createdAt: Date;
  updatedAt: Date;
}

type PostmortemStatus = 
  | 'DRAFT'           // 草稿
  | 'SCHEDULED'       // 已安排会议
  | 'IN_REVIEW'       // 审核中
  | 'ACTION_ITEMS'    // 措施执行中

  | 'TEST'              // 测试覆盖
```

## 4. API 接口设计

### 4.1 事故管理 API

#### 4.1.1 创建事故

```
POST /api/v1/incidents
```

**请求体：**
```json
{
  "title": "AI辅导服务响应超时率激增",
  "severity": "SEV1",
  "detectedBy": "alert",
  "alertIds": ["ALT-20260814-001"],
  "description": "AI辅导对话API P99延迟从3s升至15s，错误率从0.5%升至12%",
  "affectedServices": ["ai-tutoring-service", "rag-service"]
}
```

**响应（201 Created）：**
```json
{
  "code": 0,
  "data": {
    "id": "INC-20260814-003",
    "title": "AI辅导服务响应超时率激增",
    "severity": "SEV1",
    "status": "TRIAGING",
    "detectedAt": "2026-08-14T08:57:00Z",
    "startTime": "2026-08-14T08:45:00Z",
    "incidentCommander": "auto-assigned:ops-oncall",
    "timeline": [
      {
        "timestamp": "2026-08-14T08:57:00Z",
        "type": "INCIDENT_CREATED",
        "description": "事故创建（自动触发来源：告警 ALT-20260814-001）",
        "actor": "system"
      }
    ],
    "diagnosticSnapshotIds": ["DS-20260814-003-01"]
  }
}
```

#### 4.1.2 获取事故详情

```
GET /api/v1/incidents/{incidentId}
```

#### 4.1.3 查询事故列表

```
GET /api/v1/incidents?status=INVESTIGATING&severity=SEV0,SEV1&page=1&size=20
```

**查询参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| status | string (逗号分隔) | 按状态筛选 |
| severity | string (逗号分隔) | 按严重程度筛选 |
| category | string | 按故障分类筛选 |
| service | string | 按受影响服务筛选 |

```typescript
const INCIDENT_TRANSITIONS: Record<IncidentStatus, IncidentStatus[]> = {
  'DETECTED':     ['TRIAGING', 'CLOSED'],           // 可直接关闭（误报）
  'TRIAGING':     ['INVESTIGATING', 'CLOSED'],       // 确认后调查，或判定误报关闭
  'INVESTIGATING':['MITIGATING', 'MONITORING', 'TRIAGING'],  // 可回退
  'MITIGATING':   ['MONITORING', 'INVESTIGATING'],   // 缓解无效可回退
  'MONITORING':   ['RESOLVED', 'INVESTIGATING'],     // 观察期复发可回退
  'RESOLVED':     ['POSTMORTEM', 'CLOSED'],          // SEV3可不复盘直接关闭
  'POSTMORTEM':   ['CLOSED', 'RESOLVED'],            // 复盘需补充时可回退
  'CLOSED':       [],                                  // 终态
};

// 复盘触发规则
function shouldTriggerPostmortem(incident: Incident): boolean {
  if (incident.severity === 'SEV0' || incident.severity === 'SEV1') return true;
  if (incident.severity === 'SEV2' && incident.impact.affectedUserCount > 1000) return true;
  if (incident.category === 'SECURITY') return true;
  if (incident.category === 'DATA_ISSUE' && incident.impact.educationalImpact.dataLossEstimate) return true;
  return false;
}

// 状态流转校验
function validateTransition(from: IncidentStatus, to: IncidentStatus): boolean {
  return INCIDENT_TRANSITIONS[from]?.includes(to) ?? false;
}
```

## 6. 自动化诊断数据采集

### 6.1 采集器架构

```python
# diagnostic_collector.py — 诊断数据自动采集器

import asyncio
from datetime import datetime, timedelta
from typing import Any
import json

class DiagnosticCollector:
    """故障诊断数据自动采集器，并行采集多维数据"""

    def __init__(self, config: dict):
        self.metrics_client = MetricsClient(config["metrics"]["url"])
        self.trace_client = TraceClient(config["tracing"]["url"])
        self.change_client = ChangeManagementClient(config["changes"]["url"])
        self.alert_client = AlertClient(config["alerts"]["url"])
        self.db_client = DatabaseMonitorClient(config["database"]["url"])

    async def collect(
        self,
        incident_id: str,
        services: list[str],
        lookback_minutes: int = 30,
        trace_sample_size: int = 10,
    ) -> dict[str, Any]:
        """并行采集所有维度诊断数据"""
        end_time = datetime.utcnow()
        start_time = end_time - timedelta(minutes=lookback_minutes)

        tasks = [
            self._collect_metrics(services, start_time, end_time),
            self._collect_traces(services, start_time, end_time, trace_sample_size),
            self._collect_changes(services, start_time, end_time),
            self._collect_alerts(services, start_time, end_time),
            self._collect_db_metrics(start_time, end_time),
            self._collect_ai_service_metrics(start_time, end_time),
        ]
        results = await asyncio.gather(*tasks, return_exceptions=True)

        snapshot = {
            "incidentId": incident_id,
            "capturedAt": end_time.isoformat(),
            "metricsSnapshot": results[0] if not isinstance(results[0], Exception) else {},
            "traceSamples": results[1] if not isinstance(results[1], Exception) else [],
            "recentChanges": results[2] if not isinstance(results[2], Exception) else [],
            "activeAlerts": results[3] if not isinstance(results[3], Exception) else [],
            "databaseSnapshot": results[4] if not isinstance(results[4], Exception) else {},
            "aiServiceSnapshot": results[5] if not isinstance(results[5], Exception) else {},
            "collectionErrors": [
                f"Failed to collect {task}: {str(err)}"
                for task, err in zip(
                    ["metrics", "traces", "changes", "alerts", "db", "ai"],
                    results,
                )
                if isinstance(err, Exception)
            ],
        }
        return snapshot

    async def _collect_metrics(
        self, services: list[str], start: datetime, end: datetime
    ) -> dict:
        """采集关键服务指标"""
        metric_queries = {
            "cpuUsage": lambda s: f'avg(cpu_usage{{service="{s}"}})',
            "memoryUsage": lambda s: f'avg(memory_usage{{service="{s}"}})',
            "errorRates": lambda s: f'avg(rate(http_errors{{service="{s}"}}[5m]))',
            "requestRates": lambda s: f'avg(rate(http_requests{{service="{s}"}}[5m]))',
            "p99Latency": lambda s: f'histogram_quantile(0.99, http_latency{{service="{s}"}})',
        }

        result = {}
        for service in services:
            result[service] = {}
            for metric_name, query_fn in metric_queries.items():
                data = await self.metrics_client.query_range(
                    query=query_fn(service),
                    start=start,
                    end=end,
                    step="60s",
                )
                result[service][metric_name] = self._summarize_timeseries(data)
        return result

    async def _collect_ai_service_metrics(
        self, start: datetime, end: datetime
    ) -> dict:
        """采集AI服务专属指标"""
        queries = {
            "tokenConsumptionRate": 'rate(ai_tokens_consumed_total[5m])',
            "averageResponseTime": 'avg(ai_response_duration_ms)',
            "errorRate": 'rate(ai_errors_total[5m])',
            "activeRequests": 'ai_active_requests',
            "queueLength": 'ai_request_queue_depth',
            "rateLimitedRequests": 'rate(ai_rate_limited_total[5m])',
        }
        result = {}
        for name, query in queries.items():
            data = await self.metrics_client.query_range(
                query=query, start=start, end=end, step="60s"
            )
            result[name] = self._summarize_timeseries(data)

        # 采集各供应商状态
        providers = ["openai", "anthropic", "zhipu", "qwen"]
        result["modelProviders"] = []
        for provider in providers:
            status = await self._collect_provider_status(provider, start, end)
            result["modelProviders"].append(status)
        return result

    async def _collect_provider_status(
        self, provider: str, start: datetime, end: datetime
    ) -> dict:
        """采集单个模型供应商状态"""
        error_rate = await self.metrics_client.query(
            f'rate(ai_provider_errors{{provider="{provider}"}}[5m])'
        )
        latency = await self.metrics_client.query(
            f'avg(ai_provider_latency_ms{{provider="{provider}"}})'
        )
        quota = await self.metrics_client.query(
            f'ai_provider_remaining_quota{{provider="{provider}"}}'
        )
        return {
            "provider": provider,
            "status": self._determine_provider_status(error_rate, latency),
            "errorRate": float(error_rate) if error_rate else 0,
            "avgLatency": float(latency) if latency else 0,
            "remainingQuota": float(quota) if quota else 0,
        }

    @staticmethod
    def _determine_provider_status(error_rate: float, latency: float) -> str:
        if error_rate > 0.1 or latency > 30000:
            return "DOWN"
        elif error_rate > 0.03 or latency > 10000:
            return "DEGRADED"
        return "HEALTHY"

    @staticmethod
    def _summarize_timeseries(data: list) -> dict:
        if not data:
            return {}
        values = [float(d["value"]) for d in data if d.get("value")]
        if not values:
            return {}
        return {
            "current": values[-1],
            "min": min(values),
            "max": max(values),
            "avg": sum(values) / len(values),
            "trend": "increasing" if values[-1] > values[0] else "decreasing",
        }
```

```python
# change_correlation_analyzer.py

from datetime import datetime, timedelta
from typing import Optional
import math

class ChangeCorrelationAnalyzer:
    """分析变更与故障的关联性"""

    # 时间衰减因子：变更距离故障开始越近，相关性越高
    TIME_DECAY_HALF_LIFE_MINUTES = 30

    # 服务关联权重：直接变更受影响服务 > 间接关联服务
    DIRECT_SERVICE_WEIGHT = 1.0
    INDIRECT_SERVICE_WEIGHT = 0.4

    def analyze(
        self,
        incident_start_time: datetime,
        affected_services: list[str],
        recent_changes: list[dict],
        service_dependency_graph: dict[str, list[str]],
        threshold: float = 0.3,
    ) -> list[dict]:
        """
        分析变更与故障的关联性，返回按相关性得分排序的变更列表

        Args:
            incident_start_time: 故障开始时间
            affected_services: 受影响服务列表
            recent_changes: 近期变更记录
            service_dependency_graph: 服务依赖图 {service: [dependencies]}
            threshold: 最低相关性阈值，低于此值的变更被过滤
        """
        results = []
        for change in recent_changes:
            score = self._calculate_correlation_score(
                incident_start_time=incident_start_time,
                affected_services=affected_services,
                change=change,
                dependency_graph=service_dependency_graph,
            )
            if score["total"] >= threshold:
                results.append({
                    **change,
                    "correlationScore": round(score["total"], 2),
                    "correlationReason": score["reason"],
                })

        results.sort(key=lambda x: x["correlationScore"], reverse=True)
        return results

    def _calculate_correlation_score(
        self,
        incident_start_time: datetime,
        affected_services: list[str],
        change: dict,
        dependency_graph: dict[str, list[str]],
    ) -> dict[str, float | str]:
        score = 0.0
        reasons = []

        # 1. 时间相关性（指数衰减）
        time_delta_min = abs(
            (change["changedAt"] - incident_start_time).total_seconds() / 60
        )
        if time_delta_min <= 5:
            time_score = 1.0
            reasons.append("变更时间与故障开始时间高度吻合（5分钟内）")
        elif time_delta_min <= 30:
            time_score = math.exp(
                -0.693 * time_delta_min / self.TIME_DECAY_HALF_LIFE_MINUTES
            )
            reasons.append(f"变更时间在故障前{int(time_delta_min)}分钟")
        else:
            time_score = max(
                0,
                math.exp(
                    -0.693 * time_delta_min / self.TIME_DECAY_HALF_LIFE_MINUTES
                ) * 0.5,
            )
        score += time_score * 0.5  # 时间权重50%

        # 2. 服务关联性
        changed_service = change.get("relatedService", "")
        if changed_service in affected_services:
            service_score = self.DIRECT_SERVICE_WEIGHT
            reasons.append(f"变更直接影响故障服务: {changed_service}")
        elif self._is_upstream(changed_service, affected_services, dependency_graph):
            service_score = self.INDIRECT_SERVICE_WEIGHT
            reasons.append(f"变更是故障服务的上游依赖: {changed_service}")
        else:
            service_score = 0.0

        score += service_score * 0.3  # 服务权重30%

        # 3. 变更类型风险加权
        change_type = change.get("changeType", "")
        type_risk = {
            "CONFIG": 0.9,
            "DEPLOY": 0.8,
            "SCALE": 0.5,
            "MIGRATION": 0.7,
            "ROLLBACK": 0.6,
        }.get(change_type, 0.3)
        if type_risk > 0.7:
            reasons.append(f"高变更类型风险: {change_type}")

        score += type_risk * 0.15  # 类型权重15%

        # 4. 变更风险等级加权
        risk_level = change.get("riskLevel", "LOW")
        risk_weight = {"HIGH": 1.0, "MEDIUM": 0.6, "LOW": 0.3}.get(risk_level, 0.3)
        score += risk_weight * 0.05  # 风险等级权重5%

        return {
            "total": min(score, 1.0),
            "time_score": round(time_score, 2),
            "service_score": round(service_score, 2),
            "type_risk": round(type_risk, 2),
            "reason": "; ".join(reasons),
        }

    @staticmethod
    def _is_upstream(
        service: str, targets: list[str], graph: dict[str, list[str]]
    ) -> bool:
        """检查 service 是否是 targets 中任一服务的上游（依赖）"""
        visited = set()

        def dfs(node: str) -> bool:
            if node in visited:
                return False
            visited.add(node)
            deps = graph.get(node, [])
            for dep in deps:
                if dep in targets:
                    return True
                if dfs(dep):
                    return True
            return False

        return dfs(service)
```

```python
from typing import Optional
import json

class AIRCAEngine:
    """利用LLM对诊断数据进行辅助根因分析"""

    SYSTEM_PROMPT = """你是一位资深的SRE和系统架构专家，正在分析一个教育平台的线上故障。
    
你的任务：
1. 分析诊断数据，提出根因假设（按可能性排序）
2. 对每个假设提供支撑证据和反驳证据
3. 检索历史相似事故，提供参考
4. 给出推荐的下一步排查动作

分析规则：
- 基于证据分析，不做无依据的推测
- 优先考虑"变更导致"的根因（统计上最常见）
- 关注时间相关性：变更时间 vs 故障时间
- 关注教育场景特殊影响（学生数据、内容可用性）
- 明确标注每个假设的置信度
"""

    RCA_TEMPLATE = """## 故障概述
- 标题: {title}
- 严重程度: {severity}
- 开始时间: {start_time}
- 发现时间: {detected_time}
- 受影响服务: {affected_services}
- 影响用户数: {affected_users}

## 诊断数据摘要

### 关键指标异常
{metrics_anomaly}

### 关键链路追踪
{trace_anomaly}

### 近期变更（按时间排序）
{recent_changes}

### 活跃告警
{active_alerts}

### 数据库异常
{db_anomaly}

## 历史相似事故
{similar_incidents}

请分析并输出JSON格式结果。
"""

    async def analyze(
        self,
        incident: dict,
        diagnostic_snapshot: dict,
        similar_incidents: list[dict],
    ) -> dict:
        """执行AI辅助根因分析"""

        prompt = self._build_prompt(incident, diagnostic_snapshot, similar_incidents)
        response = await self.llm_client.chat(
            model="gpt-4o",  # 使用推理能力强的模型
            system=self.SYSTEM_PROMPT,
            messages=[{"role": "user", "content": prompt}],
            temperature=0.1,  # 低温度保证确定性输出
            response_format={"type": "json_object"},
            max_tokens=4000,
        )

        return self._parse_rca_response(response, incident["id"])

    def _build_prompt(
        self, incident: dict, snapshot: dict, similar: list[dict]
    ) -> str:
        """构建分析Prompt"""
        return self.RCA_TEMPLATE.format(
            title=incident["title"],
            severity=incident["severity"],
            start_time=incident["startTime"],
            detected_time=incident["detectedAt"],
            affected_services=", ".join(incident["affectedServices"]),
            affected_users=incident.get("affectedUserCount", "unknown"),
            metrics_anomaly=self._format_metrics(snapshot.get("metricsSnapshot", {})),
            trace_anomaly=self._format_traces(snapshot.get("traceSamples", [])),
            recent_changes=self._format_changes(snapshot.get("recentChanges", [])),
            active_alerts=self._format_alerts(snapshot.get("activeAlerts", [])),
            db_anomaly=self._format_db(snapshot.get("databaseSnapshot", {})),
            similar_incidents=self._format_similar(similar),
        )

    def _format_metrics(self, metrics: dict) -> str:
        lines = []
        for service, data in metrics.items():
            for metric_name, values in data.items():
                if isinstance(values, dict):
                    current = values.get("current", "N/A")
                    avg = values.get("avg", "N/A")
                    if current != "N/A" and avg != "N/A":
                        ratio = current / avg if avg != 0 else 0
                        if ratio > 2 or ratio < 0.5:
                            lines.append(
                                f"⚠️ {service}.{metric_name}: "
                                f"当前={current}, 均值={avg}, "
                                f"偏差={ratio:.1f}x"
                            )
        return "\n".join(lines) if lines else "无明显指标异常"

    def _format_traces(self, traces: list) -> str:
        lines = []
        for trace in traces:
            duration = trace.get("durationMs", 0)
            if duration > 5000:
                error_spans = trace.get("errorSpans", [])
                lines.append(
                    f"⚠️ {trace['servicePath']} | "
                    f"耗时={duration}ms | "
                    f"错误span: {error_spans}"
                )
        return "\n".join(lines) if lines else "无异常链路"

    def _format_changes(self, changes: list) -> str:
        if not changes:
            return "近30分钟无变更记录"
        lines = []
        for ch in changes[:10]:
            lines.append(
                f"- [{ch['changedAt']}] {ch['changeType']}: "
                f"{ch['description']} (by {ch['changedBy']}, "
                f"risk: {ch.get('riskLevel', 'N/A')})"
            )
        return "\n".join(lines)

    def _format_alerts(self, alerts: list) -> str:
        if not alerts:
            return "无活跃告警"
        lines = []
        for alert in alerts[:10]:
            lines.append(
                f"- [{alert['severity']}] {alert['alertName']}: "
                f"当前值={alert['currentValue']} "
                f"(阈值={alert['threshold']}) "
                f"@{alert['triggeredAt']}"
            )
        return "\n".join(lines)

    def _format_db(self, db: dict) -> str:
        lines = []
        if db.get("replicationLag", 0) > 1000:
            lines.append(f"⚠️ 复制延迟: {db['replicationLag']}ms")
        if db.get("slowQueries"):
            for q in db["slowQueries"][:3]:
                lines.append(
                    f"⚠️ 慢查询({q['durationMs']}ms): "
                    f"{q['query'][:100]}..."
                )
        if db.get("lockWaits", 0) > 10:
            lines.append(f"⚠️ 锁等待: {db['lockWaits']}")
        return "\n".join(lines) if lines else "数据库正常"

    def _format_similar(self, similar: list) -> str:
        if not similar:
            return "无历史相似事故"
        lines = []
        for inc in similar[:5]:
            lines.append(
                f"- {inc['incidentId']}: {inc['title']} "
                f"(根因: {inc.get('rootCause', '未知')})"
            )
        return "\n".join(lines)

    def _parse_rca_response(self, response: str, incident_id: str) -> dict:
        """解析LLM返回的根因分析结果"""
        try:
            data = json.loads(response)
        except json.JSONDecodeError:
            return {
                "analysisId": f"AI-RCA-{incident_id}",
                "hypotheses": [],
                "error": "Failed to parse LLM response",
                "rawResponse": response,
            }

        return {
            "analysisId": f"AI-RCA-{incident_id}",
            "hypotheses": [
                {
                    "rank": i + 1,
                    "hypothesis": h.get("hypothesis", ""),
                    "probability": h.get("probability", 0),
                    "supportingEvidence": h.get("supportingEvidence", []),
                    "contradictingEvidence": h.get("contradictingEvidence", []),
                }
                for i, h in enumerate(data.get("hypotheses", []))
            ],
            "similarIncidents": data.get("similarIncidents", []),
            "confidenceScore": data.get("confidenceScore", 0),
            "recommendedNextSteps": data.get("recommendedNextSteps", []),
        }
```

```python
# action_item_tracker.py — 改进措施自动追踪

from datetime import datetime, timedelta
from typing import Optional

class ActionItemTracker:
    """改进措施生命周期追踪与自动提醒"""

    # 升级规则
    ESCALATION_RULES = [
        # (逾期天数, 通知对象, 通知渠道)
        (0, ["owner"], ["in_app", "email"]),           # 到期日提醒
        (1, ["owner"], ["in_app", "email", "im"]),     # 逾期1天
        (3, ["owner", "facilitator"], ["im", "email"]), # 逾期3天抄送复盘主持人
        (7, ["owner", "facilitator", "tech_lead"], ["im", "email"]),  # 逾期7天抄送技术负责人
        (14, ["owner", "facilitator", "tech_lead", "cto"], ["im", "email"]),  # 逾期14天CTO升级
    ]

    P0_REMINDER_DAYS_BEFORE = 3   # P0措施到期前3天开始提醒
    P1_REMINDER_DAYS_BEFORE = 2
    P2_REMINDER_DAYS_BEFORE = 1

    async def check_and_notify(self, postmortem_id: str) -> dict:
        """检查所有未完成措施，发送提醒"""
        action_items = await self._get_pending_items(postmortem_id)
        notifications_sent = []

        for item in action_items:
            if item["status"] in ("DONE", "CANCELLED"):
                continue

            days_overdue = self._calculate_days_overdue(item["dueDate"])
            days_before_due = self._calculate_days_before_due(item["dueDate"])

            if days_overdue >= 0:
                # 已逾期 - 按升级规则通知
                notif = self._apply_escalation(item, days_overdue)
                if notif:
                    notifications_sent.append(notif)
            elif days_before_due <= self._get_reminder_threshold(item["priority"]):
                # 即将到期 - 提醒
                notif = await self._send_reminder(item, days_before_due)
                notifications_sent.append(notif)

        return {
            "postmortemId": postmortem_id,
            "checkedItems": len(action_items),
            "notificationsSent": len(notifications_sent),
            "details": notifications_sent,
        }

    def _apply_escalation(self, item: dict, days_overdue: int) -> Optional[dict]:
        """根据逾期天数应用升级规则"""
        applicable_rules = [
            rule for rule in self.ESCALATION_RULES
            if days_overdue >= rule[0]
        ]
        if not applicable_rules:
            return None

        # 取最高级别的升级规则
        _, recipients, channels = applicable_rules[-1]
        return {
            "actionItemId": item["id"],
            "type": "ESCALATION",
            "recipients": recipients,
            "channels": channels,
            "message": (
                f"改进措施逾期{days_overdue}天: {item['description']} "
                f"(Owner: {item['owner']}, Due: {item['dueDate']})"
            ),
        }

    @staticmethod
    def _calculate_days_overdue(due_date_str: str) -> int:
        due = datetime.fromisoformat(due_date_str)
        return (datetime.utcnow() - due).days

    @staticmethod
    def _calculate_days_before_due(due_date_str: str) -> int:
        due = datetime.fromisoformat(due_date_str)
        return (due - datetime.utcnow()).days

    @staticmethod
    def _get_reminder_threshold(priority: str) -> int:
        return {
            "P0": ActionItemTracker.P0_REMINDER_DAYS_BEFORE,
            "P1": ActionItemTracker.P1_REMINDER_DAYS_BEFORE,
            "P2": ActionItemTracker.P2_REMINDER_DAYS_BEFORE,
        }.get(priority, 1)
```

## 13. 错误处理

### 13.1 错误码定义

| 错误码 | HTTP | 说明 | 处理建议 |
|--------|------|------|---------|
| `INCIDENT_NOT_FOUND` | 404 | 事故不存在 | 检查ID |
| `INCIDENT_ALREADY_CLOSED` | 409 | 事故已关闭，不允许修改 | 需重新打开请联系管理员 |
| `INVALID_STATUS_TRANSITION` | 409 | 非法状态流转 | 检查状态机定义 |
| `POSTMORTEM_EXISTS` | 409 | 复盘已存在 | 一个事故只能有一个复盘 |
| `DIAGNOSTIC_COLLECTION_FAILED` | 500 | 诊断数据采集失败 | 检查各采集器连接状态 |
| `AI_ANALYSIS_TIMEOUT` | 504 | AI分析超时 | 降低分析深度或重试 |
| `ACTION_ITEM_OVERDUE_LOCKED` | 409 | 逾期措施被锁定 | 联系负责人更新状态或申请延期 |

## 16. 关键指标定义

| 指标名 | 计算方式 | 目标值 |
|--------|---------|--------|
| MTTD (Mean Time To Detect) | detectedAt - startTime | < 3 min |
| MTTI (Mean Time To Investigate) | 首次响应 - detectedAt | < 5 min |
| MTTM (Mean Time To Mitigate) | mitigatedAt - detectedAt | < 30 min |
| MTTR (Mean Time To Resolve) | resolvedAt - detectedAt | < 2 h |
| 复盘覆盖率 | SEV0/1事故复盘数 / SEV0/1事故总数 | 100% |
| 复盘及时率 | 7天内完成复盘数 / 应复盘总数 | > 90% |
| 措施完成率 | DONE措施数 / 总措施数 | > 80% |
| 措施按时完成率 | 按时DONE数 / 总措施数 | > 70% |
| 同类事故复发率 | 同根因事故数 / 总事故数 | < 10% |
| AI根因分析准确率 | AI首选假设正确数 / 分析总数 | > 60% |
