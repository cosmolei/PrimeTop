# 教育内容适龄性评估与分级引擎 - 详细设计

> 版本: 1.1 | 创建: 2026-05-24 | 最近更新: 2026-08-17 | 状态: 已补全（v1.0 为烂尾截断稿，修复与增补清单见 §14 维护记录）

## 1. 概述

### 1.1 问题背景

PrimeTop 覆盖幼儿至高中全学段，同一知识点在不同年级的讲解深度、表达方式、示例难度和术语密度差异巨大。例如"分数"这个概念：
- 小学三年级：把一个披萨切成 4 块，每块是 1/4
- 初中：分数是有理数的一种表示，分子/分母互质时为最简分数
- 高中：分数是实数域中的元素，可以映射到数轴上的点

原始设计文档多处要求"分学段讲解"、"分龄适配"，但当前各模块各自实现适龄逻辑，缺乏统一的内容复杂度评估和适龄分级能力。具体痛点：

1. **AI 输出不可控**：大模型可能用高中生语言回答小学生问题，反之亦然
2. **题目推荐错配**：向低年级学生推荐超纲题目
3. **知识讲解跳跃**：跳过前置概念直接讲解高阶内容
4. **素材推荐不当**：推荐与学段认知水平不符的阅读材料
5. **无量化指标**：无法度量内容的"适龄程度"，只能靠人工审核

### 1.2 模块定位

**教育内容适龄性评估与分级引擎**（AgeFit Engine）是一个跨模块的内容评估服务，负责：
- 对任意文本内容（AI 回复、题目、知识点讲解、素材等）进行复杂度评分
- 将评分映射到目标学段的适龄等级
- 为内容生产/推荐/AI 生成提供适龄约束
- 监控全系统内容的适龄合规率

**本模块不负责：**
- UI 层面的分龄适配 → 见 `分龄UI适配与交互设计规范-详细设计.md`
- Prompt 模板的分龄策略 → 见 `AI-Prompt编排与场景模板系统-详细设计.md`
- 题目 IRT 难度标定 → 见 `题目难度标定与能力评估模型-详细设计.md`
- 学生能力评估 → 见 `用户学习画像与能力维度模型-详细设计.md`

### 1.3 设计目标

| 目标 | 指标 |
|------|------|
| 评估准确率 | 适龄等级与人工标注一致率 ≥ 90% |
| 评估延迟 | 单次文本评估 ≤ 50ms（规则引擎）, ≤ 500ms（模型引擎） |
| 覆盖率 | 全系统 AI 输出、题目、知识讲解 100% 经过评估 |
| 可解释性 | 每次评估输出具体不达标维度和修改建议 |
| 成本 | 规则引擎零模型调用成本，模型引擎仅对规则不确定样本调用 |

## 2. 核心概念与数据模型

### 2.1 适龄等级定义

系统定义 5 个适龄等级，覆盖从幼儿到高中的完整学段：

```python
class AgeFitLevel(str, Enum):
    """内容适龄等级"""
    LEVEL_1 = "L1"  # 幼儿启蒙 (3-6岁)：无专业术语，图像化描述，短句
    LEVEL_2 = "L2"  # 小学低段 (6-9岁)：简单词汇，生活化类比，短段落
    LEVEL_3 = "L3"  # 小学高段 (9-12岁)：基础学科术语，简单推理，中等段落
    LEVEL_4 = "L4"  # 初中 (12-15岁)：学科标准术语，多步推理，长段落
    LEVEL_5 = "L5"  # 高中 (15-18岁)：专业术语，复杂推理，抽象建模

    @classmethod
    def from_grade(cls, grade: "GradeEnum") -> "AgeFitLevel":
        """根据年级映射适龄等级"""
        mapping = {
            "K1": cls.LEVEL_1, "K2": cls.LEVEL_1, "K3": cls.LEVEL_1,
            "G1": cls.LEVEL_2, "G2": cls.LEVEL_2, "G3": cls.LEVEL_2,
            "G4": cls.LEVEL_3, "G5": cls.LEVEL_3, "G6": cls.LEVEL_3,
            "G7": cls.LEVEL_4, "G8": cls.LEVEL_4, "G9": cls.LEVEL_4,
            "G10": cls.LEVEL_5, "G11": cls.LEVEL_5, "G12": cls.LEVEL_5,
        }
        return mapping.get(grade, cls.LEVEL_3)  # 默认小学高段
```

### 2.2 内容复杂度维度

评估内容时从 6 个独立维度打分，每个维度 1-5 分：

```python
class ComplexityDimension(str, Enum):
    """内容复杂度评估维度"""
    VOCABULARY = "vocabulary"        # 词汇复杂度：专业术语密度、生僻字比例
    SENTENCE = "sentence"            # 句式复杂度：句子长度、从句嵌套、修辞手法
    CONCEPT = "concept"              # 概念深度：前置知识要求、抽象程度
    REASONING = "reasoning"          # 推理复杂度：逻辑步骤数、思维转换次数
    EXPRESSION = "expression"        # 表达密度：信息密度、单位文本信息量
    DOMAIN_TERM = "domain_term"      # 学科术语：学科专属概念和符号的使用频率


class ComplexityScore:
    """内容复杂度评分"""
    vocabulary: float     # 1.0-5.0
    sentence: float       # 1.0-5.0
    concept: float        # 1.0-5.0
    reasoning: float      # 1.0-5.0
    expression: float     # 1.0-5.0
    domain_term: float    # 1.0-5.0

    @property
    def overall(self) -> float:
        """加权综合评分"""
        weights = {
            "vocabulary": 0.20,
            "sentence": 0.15,
            "concept": 0.25,
            "reasoning": 0.20,
            "expression": 0.10,
            "domain_term": 0.10,
        }
        return sum(getattr(self, k) * w for k, w in weights.items())

    def to_age_fit_level(self) -> AgeFitLevel:
        """综合评分映射到适龄等级"""
        score = self.overall
        if score <= 1.5: return AgeFitLevel.LEVEL_1
        elif score <= 2.3: return AgeFitLevel.LEVEL_2
        elif score <= 3.1: return AgeFitLevel.LEVEL_3
        elif score <= 3.9: return AgeFitLevel.LEVEL_4
        else: return AgeFitLevel.LEVEL_5
```

## 3. 评估引擎架构

### 3.1 两级评估架构

系统采用"规则引擎优先 + 模型引擎兜底"的两级评估架构：

```
               ┌─────────────────┐
               │   输入内容       │
               │  + 目标适龄等级   │
               └────────┬────────┘
                        │
               ┌────────▼────────┐
               │  L1: 规则引擎    │
               │  (正则 + 词典    │
               │   + 统计特征)    │
               └────────┬────────┘
                        │
                ┌───────┴───────┐
                │ confidence ≥  │
                │    0.85?      │
                ├───Yes────┐──No┤
                │          │    │
           ┌────▼───┐      │ ┌──▼─────────┐
           │ 直接输出 │      │ │ L2: 模型引擎│
           │ 结果     │      │ │ (轻量分类器)│
           └─────────┘      │ └──────┬─────┘
                            │        │
                            │   ┌────▼─────┐
                            │   │ 输出结果   │
                            │   └──────────┘
                            │
                       ┌────▼────────────┐
                       │ 异步写入评估记录  │
                       │ + 更新缓存       │
                       └─────────────────┘
```

### 3.2 规则引擎

规则引擎基于可量化的文本统计特征，无模型调用成本：

```python
class RuleBasedEvaluator:
    """规则引擎：基于统计特征和词典匹配"""

    def __init__(self, db: AsyncSession, redis: Redis):
        self.db = db
        self.redis = redis
        self._vocab_cache: Dict[int, Set[str]] = {}  # level -> word set
        self._term_cache: Dict[str, Dict[str, int]] = {}  # subject -> {term -> min_level}

    async def evaluate(
        self, text: str, target_level: AgeFitLevel, subject: str = None
    ) -> "EvaluationResult":
        """评估内容的适龄性"""

        # 1. 预处理：分句、分词
        sentences = self._split_sentences(text)
        words = self._tokenize(text)

        # 2. 逐维度打分
        scores = ComplexityScore()
        scores.vocabulary = await self._score_vocabulary(words, target_level)
        scores.sentence = self._score_sentence_complexity(sentences, target_level)
        scores.concept = await self._score_concept_depth(text, target_level, subject)
        scores.reasoning = self._score_reasoning_complexity(text, target_level)
        scores.expression = self._score_expression_density(text, sentences)
        scores.domain_term = await self._score_domain_terms(text, target_level, subject)

        # 3. 综合评级
        scored_level = scores.to_age_fit_level()
        is_fit = self._is_level_compatible(scored_level, target_level)

        # 4. 收集超标细节（含超纲词/术语明细，供重写引擎与管理端展示）
        detail = self._collect_violations(text, scores, target_level)
        detail["over_level_items"] = self._collect_over_level_items(
            words, text, target_level, subject
        )

        # 5. 计算置信度
        confidence = self._calculate_confidence(scores)

        return EvaluationResult(
            scores=scores,
            scored_level=scored_level,
            is_fit=is_fit,
            confidence=confidence,
            detail=detail,
            method="rule",
        )

    async def _score_vocabulary(
        self, words: List[str], target_level: AgeFitLevel
    ) -> float:
        """词汇复杂度评分"""
        if not words:
            return 1.0

        level_value = {"L1": 1, "L2": 2, "L3": 3, "L4": 4, "L5": 5}[target_level.value]

        # 统计超纲词汇比例（词级等级查询走进程内内存词典，禁止逐词查库，见 §3.2.2）
        over_level_count = 0
        over_level_words = []

        for word in words:
            word_level = await self._get_word_level(word)
            if word_level and word_level > level_value:
                over_level_count += 1
                over_level_words.append((word, word_level))

        ratio = over_level_count / len(words) if words else 0

        # 超纲率映射到分数
        # 0% -> 1.0, 5% -> 2.0, 10% -> 3.0, 20% -> 4.0, 30%+ -> 5.0
        if ratio <= 0.01: return 1.0
        elif ratio <= 0.05: return 2.0
        elif ratio <= 0.10: return 3.0
        elif ratio <= 0.20: return 4.0
        else: return 5.0

    def _score_sentence_complexity(
        self, sentences: List[str], target_level: AgeFitLevel
    ) -> float:
        """句式复杂度评分"""
        if not sentences:
            return 1.0

        # 平均句长（中文字符数）
        avg_len = sum(len(self._remove_punct(s)) for s in sentences) / len(sentences)

        # 从句/修饰语密度（通过逗号、顿号、关联词近似估算）
        clause_markers = ["，", "、", "因为", "所以", "虽然", "但是", "如果", "那么", "既然", "因此"]
        clause_count = sum(
            sum(1 for m in clause_markers if m in s) for s in sentences
        )
        clause_density = clause_count / len(sentences)

        # 长句比例（超过 target 等级标准句长的句子占比）
        max_lengths = {"L1": 15, "L2": 20, "L3": 30, "L4": 40, "L5": 50}
        threshold = max_lengths[target_level.value]
        long_ratio = sum(1 for s in sentences if len(s) > threshold) / len(sentences)

        # 综合评分
        score = 1.0
        if avg_len > threshold * 1.5: score += 1.0
        if clause_density > 1.5: score += 0.5
        if long_ratio > 0.3: score += 0.5
        if avg_len > threshold * 2.0: score += 1.0
        if clause_density > 3.0: score += 1.0

        return min(score, 5.0)

    async def _score_concept_depth(
        self, text: str, target_level: AgeFitLevel, subject: str = None
    ) -> float:
        """概念深度评分：检测是否使用了超出目标等级的抽象概念"""
        level_value = {"L1": 1, "L2": 2, "L3": 3, "L4": 4, "L5": 5}[target_level.value]

        # 抽象概念标记词
        abstract_markers = {
            3: ["概念", "原理", "规律", "性质", "定理", "定义"],
            4: ["模型", "假设", "推导", "证明", "归纳", "演绎", "公理"],
            5: ["范式", "映射", "同构", "变换", "张量", "矩阵变换", "傅里叶"],
        }

        # 计算使用的抽象概念中超出目标等级的数量
        over_level_concepts = 0
        for concept_level, markers in abstract_markers.items():
            if concept_level > level_value:
                for marker in markers:
                    if marker in text:
                        over_level_concepts += 1

        # 抽象概念数量映射
        if over_level_concepts == 0: return min(level_value, 3.0)
        elif over_level_concepts <= 1: return level_value + 0.5
        elif over_level_concepts <= 3: return level_value + 1.0
        else: return min(level_value + 2.0, 5.0)

    def _score_reasoning_complexity(
        self, text: str, target_level: AgeFitLevel
    ) -> float:
        """推理复杂度评分"""
        # 推理步骤标记词
        step_markers = [
            "首先", "其次", "然后", "接着", "最后", "因此", "所以",
            "第一步", "第二步", "第三步", "第四步", "第五步",
            "已知", "求证", "证明", "因为", "可得",
        ]
        step_count = sum(1 for m in step_markers if m in text)

        # 条件嵌套深度（"如果...那么如果...那么"模式）
        conditional_count = text.count("如果") + text.count("若") + text.count("假设")

        # 映射到分数
        if step_count <= 1 and conditional_count == 0: return 1.0
        elif step_count <= 2 and conditional_count <= 1: return 2.0
        elif step_count <= 4 and conditional_count <= 2: return 3.0
        elif step_count <= 6 and conditional_count <= 3: return 4.0
        else: return 5.0

    def _score_expression_density(
        self, text: str, sentences: List[str]
    ) -> float:
        """表达密度评分：单位文本中的信息量"""
        if not text:
            return 1.0

        # 公式/符号密度
        formula_markers = ["=", "+", "-", "×", "÷", "²", "³", "√", "∫", "∑", "π"]
        formula_count = sum(text.count(m) for m in formula_markers)

        # 列表/枚举密度
        list_markers = ["①", "②", "③", "1.", "2.", "3.", "•", "-"]
        list_count = sum(text.count(m) for m in list_markers)

        chars = len(text)
        density = (formula_count + list_count * 2) / max(chars / 100, 1)

        if density <= 0.5: return 1.0
        elif density <= 1.0: return 2.0
        elif density <= 2.0: return 3.0
        elif density <= 4.0: return 4.0
        else: return 5.0

    async def _score_domain_terms(
        self, text: str, target_level: AgeFitLevel, subject: str = None
    ) -> float:
        """学科术语复杂度评分"""
        level_value = {"L1": 1, "L2": 2, "L3": 3, "L4": 4, "L5": 5}[target_level.value]

        term_registry = await self._get_term_registry(subject)
        over_level_terms = 0
        over_level_list = []

        for term, min_level in term_registry.items():
            if term in text and min_level > level_value:
                over_level_terms += 1
                over_level_list.append((term, min_level))

        if over_level_terms == 0: return 1.0
        elif over_level_terms <= 1: return 3.0
        elif over_level_terms <= 3: return 4.0
        else: return 5.0

    def _is_level_compatible(
        self, scored: AgeFitLevel, target: AgeFitLevel
    ) -> bool:
        """判断评估等级是否兼容目标等级（允许低1级，不允许高）"""
        level_order = {"L1": 1, "L2": 2, "L3": 3, "L4": 4, "L5": 5}
        return level_order[scored.value] <= level_order[target.value]

    def _calculate_confidence(self, scores: ComplexityScore) -> float:
        """计算规则引擎置信度"""
        score_values = [
            scores.vocabulary, scores.sentence, scores.concept,
            scores.reasoning, scores.expression, scores.domain_term,
        ]
        # 各维度方差越小，置信度越高（评分一致 = 规则引擎足够判断）
        # 注：n=6 时样本方差会高估离散度约 20%，导致置信度偏低、模型兜底比例虚高，v1.1 改用总体方差
        import statistics
        variance = statistics.pvariance(score_values)
        # 方差 < 0.5 → 高置信度，方差 > 2.0 → 低置信度
        if variance <= 0.3: return 0.95
        elif variance <= 0.8: return 0.85
        elif variance <= 1.5: return 0.70
        else: return 0.50

    def _collect_violations(
        self, text: str, scores: ComplexityScore, target_level: AgeFitLevel
    ) -> dict:
        """收集具体的超标项"""
        violations = []

        # 词汇超标
        if scores.vocabulary > {"L1": 1.5, "L2": 2.5, "L3": 3.5, "L4": 4.5, "L5": 5.0}[target_level.value]:
            violations.append({
                "dimension": "vocabulary",
                "severity": "high",
                "message": f"词汇复杂度 {scores.vocabulary:.1f} 超出目标等级阈值",
                "suggestion": "替换为更简单的同义词或添加解释",
            })

        # 句式超标
        if scores.sentence > {"L1": 2.0, "L2": 2.5, "L3": 3.5, "L4": 4.5, "L5": 5.0}[target_level.value]:
            violations.append({
                "dimension": "sentence",
                "severity": "medium",
                "message": f"句式复杂度 {scores.sentence:.1f} 超出目标等级",
                "suggestion": "拆分长句，减少从句嵌套",
            })

        # 概念深度超标
        if scores.concept > {"L1": 1.5, "L2": 2.5, "L3": 3.5, "L4": 4.5, "L5": 5.0}[target_level.value]:
            violations.append({
                "dimension": "concept",
                "severity": "high",
                "message": f"概念深度 {scores.concept:.1f} 超出目标等级",
                "suggestion": "添加前置概念说明或使用类比解释",
            })

        # 推理复杂度超标
        if scores.reasoning > {"L1": 1.5, "L2": 2.5, "L3": 3.5, "L4": 4.5, "L5": 5.0}[target_level.value]:
            violations.append({
                "dimension": "reasoning",
                "severity": "medium",
                "message": f"推理复杂度 {scores.reasoning:.1f} 超出目标等级",
                "suggestion": "减少单段推理步骤数，拆分为多轮渐进引导",
            })

        # 表达密度超标
        if scores.expression > {"L1": 1.5, "L2": 2.5, "L3": 3.5, "L4": 4.5, "L5": 5.0}[target_level.value]:
            violations.append({
                "dimension": "expression",
                "severity": "low",
                "message": f"表达密度 {scores.expression:.1f} 超出目标等级",
                "suggestion": "降低单位篇幅信息量，在公式/枚举之间补充解释性语句",
            })

        # 学科术语超标（幼儿段零容忍，见 §11 合规红线 C3）
        if scores.domain_term > {"L1": 1.0, "L2": 2.0, "L3": 3.5, "L4": 4.5, "L5": 5.0}[target_level.value]:
            violations.append({
                "dimension": "domain_term",
                "severity": "high",
                "message": f"学科术语复杂度 {scores.domain_term:.1f} 超出目标等级",
                "suggestion": "术语首次出现时补充生活化解释，或替换为通俗说法",
            })

        return {
            "violations": violations,
            "total_score": round(scores.overall, 2),
            "scored_level": scores.to_age_fit_level().value,
        }

    def _collect_over_level_items(
        self, words: List[str], text: str, target_level: AgeFitLevel, subject: str = None
    ) -> dict:
        """收集超纲词汇与超纲术语明细（写入 detail.over_level_items）。

        仅用于重写引擎定位改写点与管理端展示；与评分共用同一份进程内词典，
        O(n) 单遍扫描，不产生额外 IO。上限：词 20 个、术语 30 个（防大结果集）。
        """
        level_value = {"L1": 1, "L2": 2, "L3": 3, "L4": 4, "L5": 5}[target_level.value]

        # ── 超纲词汇（去重计数，按超出等级降序、词频降序） ──
        word_counter: Dict[str, int] = {}
        for word in words:
            wl = self._word_level(word)
            if wl is not None and wl > level_value:
                word_counter[word] = word_counter.get(word, 0) + 1
        over_words = sorted(
            (
                {"word": w, "word_level": self._word_level(w), "count": c}
                for w, c in word_counter.items()
            ),
            key=lambda x: (-x["word_level"], -x["count"]),
        )[:20]

        # ── 超纲术语（AC 最长匹配去重：命中区间重叠时保留更长术语） ──
        matcher = self._term_lookup(subject)
        over_terms = [
            {"term": t, "min_level": lv}
            for t, lv in matcher.match(text)
            if lv > level_value
        ][:30]

        return {"over_level_words": over_words, "over_level_terms": over_terms}

    # ──────────── 预处理辅助方法 ────────────

    _SENTENCE_DELIMS = "。！？!?；;\n"
    _PUNCTUATIONS = set("，。！？、；："“”‘’（）《》【】,.;:!?()<>[]{} \t·—…")

    def _split_sentences(self, text: str) -> List[str]:
        """按句末标点切句；末尾无标点的剩余文本也计为一句（空句丢弃）。"""
        sentences, buf = [], []
        for ch in text:
            buf.append(ch)
            if ch in self._SENTENCE_DELIMS:
                s = "".join(buf).strip()
                if s:
                    sentences.append(s)
                buf = []
        tail = "".join(buf).strip()
        if tail:
            sentences.append(tail)
        return sentences

    def _remove_punct(self, s: str) -> str:
        return "".join(ch for ch in s if ch not in self._PUNCTUATIONS)

    def _tokenize(self, text: str) -> List[str]:
        """中文分词（jieba 精确模式，进程级单例，启动时预热首次加载）。

        英文连续字母数字串按空白切分后小写化。纯标点片段丢弃。
        """
        import jieba
        return [t.strip() for t in jieba.lcut(text) if t.strip()]

    # ──────────── 词典访问（全部走进程内内存词典，禁止逐词查库，见 §3.2.2） ────────────

    async def _get_vocab_for_level(self, level_value: int) -> Set[str]:
        """返回 ≤level_value 的累计词集（供 GetLevelParams 与冷启动预载，非评分热路径）。"""
        store = await VocabularyStore.get_instance(self.db, self.redis)
        return store.words_within(level_value)

    async def _get_word_level(self, word: str) -> Optional[int]:
        """查询单词等级；未收录返回 None（未收录词不计入超纲，避免误杀新词）。"""
        store = await VocabularyStore.get_instance(self.db, self.redis)
        return store.word_level(word)

    def _word_level(self, word: str) -> Optional[int]:
        """同步版（词典已由启动门保证加载，无 IO）。"""
        return VocabularyStore.peek().word_level(word)

    async def _get_term_registry(self, subject: str) -> Dict[str, int]:
        """学科术语合并视图 {term: min_level} = subject 术语 ∪ 通用术语。"""
        store = await VocabularyStore.get_instance(self.db, self.redis)
        return store.term_map(subject)

    def _term_lookup(self, subject: str = None):
        """返回术语匹配器（AC 自动机，见 §3.5.2；构建失败降级朴素匹配）。"""
        return VocabularyStore.peek().term_matcher(subject)
```

### 3.2.2 词典全量预加载与热更新（50ms 预算的必要条件）

**性能红线**：`_score_vocabulary` 若逐词查库（即使连接池内网 RTT 0.5ms），200 词文本仅词汇扫描就需 100ms+，50ms 总预算不可达。因此词表与术语表必须**全量常驻进程内存**，评分热路径零 IO：

| 方案 | 词汇扫描耗时(200词) | 是否采用 |
|------|---------------------|----------|
| 逐词 await 查 MySQL | 100-400ms | ❌ 禁止 |
| 逐词查 Redis | 20-60ms | ❌ 禁止（仍有网络往返） |
| 全量内存字典 O(1) | <1ms | ✅ 本设计 |

词典通过**快照 + 版本指针 + 双缓冲**实现热更新：工作区表（`vocabulary_registry` / `domain_term_registry`）发布时物化为快照文件（对象存储 + 本地磁盘缓存），评估节点按版本号轮询加载，构建完成后**原子切换**进程内指针，在途评估用旧缓冲跑完，新评估进入新缓冲，永不出线混合版本：

```python
class VocabularyStore:
    """词典全量内存存储：启动全量加载 + 版本轮询 + 双缓冲原子切换。"""

    _instance: "VocabularyStore" = None          # 当前生效缓冲（读路径唯一入口）
    _building: "VocabularyStore" = None          # 构建中的新缓冲（写路径隔离）
    _lock = asyncio.Lock()

    ACTIVE_VERSION_KEY = "agefit:dict:active_version"   # Redis 版本指针
    POLL_INTERVAL = 30                                    # 版本轮询周期（秒）

    def __init__(self, version: str, snapshot_path: str):
        self.version = version
        self._vocab: Dict[str, Tuple[int, Optional[str]]] = {}  # word -> (level, subject)
        self._terms: Dict[str, Dict[str, int]] = {}   # subject(含 GENERAL) -> {term: min_level}
        self._matchers: Dict[str, "TermMatcher"] = {} # subject -> AC 匹配器（惰性构建）
        self._build_from(snapshot_path)

    @classmethod
    async def get_instance(cls, db, redis) -> "VocabularyStore":
        """读路径：无实例时触发首次加载（正常流程由启动门提前完成）。"""
        if cls._instance is None:
            async with cls._lock:
                if cls._instance is None:
                    version = await redis.get(cls.ACTIVE_VERSION_KEY)
                    cls._instance = cls._load_snapshot(version or "bootstrap")
        return cls._instance

    @classmethod
    def peek(cls) -> "VocabularyStore":
        """同步读：启动门保证已加载；未加载直接抛错（fail-fast，不静默降级）。"""
        if cls._instance is None:
            raise RuntimeError("VocabularyStore not loaded (startup gate failed)")
        return cls._instance

    @classmethod
    async def start_poller(cls, redis, interval: int = POLL_INTERVAL):
        """后台版本轮询：发现新版本 → 下载快照 → 构建新缓冲 → 原子切换。

        切换是单指针赋值（GIL 原子），在途评估持有旧 store 引用继续跑完不受影响。
        """
        while True:
            try:
                latest = await redis.get(cls.ACTIVE_VERSION_KEY)
                if latest and (cls._instance is None or latest != cls._instance.version):
                    new_store = await asyncio.to_thread(
                        cls._load_snapshot, latest
                    )          # ① 快照下载+构建放线程池，不阻塞事件循环
                    cls._instance = new_store   # ② 原子切换
                    metrics.dict_version.set(latest)
            except Exception as e:
                logger.warning("dict reload failed, keep old version=%s err=%s",
                               cls._instance.version if cls._instance else None, e)
                # 刷新失败沿用旧版本（降级 D3），下一轮重试
            await asyncio.sleep(interval)

    # ── 查询接口（全部 O(1) 或单遍扫描） ──
    def word_level(self, word: str) -> Optional[int]:
        entry = self._vocab.get(word)
        return entry[0] if entry else None

    def words_within(self, level_value: int) -> Set[str]:
        return {w for w, (lv, _) in self._vocab.items() if lv <= level_value}

    def term_map(self, subject: str = None) -> Dict[str, int]:
        merged = dict(self._terms.get("GENERAL", {}))
        if subject and subject in self._terms:
            merged.update(self._terms[subject])   # 学科术语覆盖同名通用术语
        return merged

    def term_matcher(self, subject: str = None) -> "TermMatcher":
        key = subject or "GENERAL"
        if key not in self._matchers:
            self._matchers[key] = TermMatcher.build(self.term_map(subject))
        return self._matchers[key]
```

> 快照文件格式：`{version}/vocab.tsv`（word\tlevel\tsubject）+ `{version}/terms.json`（按学科分组，含 aliases 展开后的条目）。构建耗时预算 ≤120s（32 万词 + 6 万术语），超时即视为构建失败（降级 D3），详见 §3.5。

## 3.3 模型引擎（ModelBasedEvaluator）

### 3.3.1 定位与选型

模型引擎仅在**规则引擎置信度 < 0.85** 且调用模式允许时介入（SYNC_FULL / ASYNC；SYNC_FAST 永不调模型）。选型对比：

| 候选 | 单样本延迟 | 部署成本 | 可解释性 | 结论 |
|------|-----------|---------|---------|------|
| LLM 提示词评估 | 800-3000ms | 极高（每次调用计费） | 好（可输出理由） | 仅离线标注辅助，不在在线链路 |
| BERT 类微调模型 | 15-40ms(GPU)/80ms+(CPU) | 需 GPU 或高 CPU | 中 | 否（延迟与成本不满足 500ms×15% 兜底量） |
| **LightGBM 多分类** | 2-5ms(CPU) | 无 GPU、模型 <20MB | 特征重要度 | ✅ 采用 |

模型输入为 42 维统计特征（不输入原文，天然无 PII 泄漏面），输出 L1-L5 五分类概率分布。

### 3.3.2 特征工程（42 维，关键 20 项摘录）

| # | 特征 | 说明 |
|---|------|------|
| 1-6 | 规则六维分 | vocabulary/sentence/concept/reasoning/expression/domain_term 原值 |
| 7 | 超纲词率 | 超纲词数 / 总词数 |
| 8 | 超纲术语数 | min_level 超标的术语命中数（最长匹配去重后） |
| 9 | 平均句长 | 去标点后字符均值 |
| 10 | 句长标准差 | 反映长短句交错程度 |
| 11 | 最长句长 | 单句极端复杂度 |
| 12 | 长句比例 | 超过目标等级阈值的句子占比 |
| 13 | 从句密度 | 关联词+逗号分句标记数 / 句数 |
| 14 | 推理标记数 | 首先其次因此等 16 类标记计数 |
| 15 | 条件嵌套数 | 如果/若/假设 出现次数 |
| 16 | 公式密度 | 数学符号数 / 百字符 |
| 17 | 列表密度 | 枚举标记数 / 百字符 |
| 18 | 词汇丰富度 TTR | 去重词数 / 总词数（截断至前 500 词防长度干扰） |
| 19 | 字符熵 | 2-gram 熵，衡量语言书面化程度 |
| 20 | 汉字占比 | 汉字数 / 总字符（过滤代码/公式混排干扰） |

> 其余 22 维：标点密度、数字密度、段落数、平均段长、重复句率、虚词率、目标等级 one-hot(5)、学科 one-hot(12，缺失学科全零)、文本长度分桶(4)。全部特征由规则引擎评分过程中**顺带产出**，无二次扫描开销。

### 3.3.3 训练数据管线

| 来源 | 规模 | 标签质量 | 用途 |
|------|------|---------|------|
| 课标教材语料（按学段自动预标） | 40 万条 | 弱标签（学段即标签） | 预训练主体 |
| 人工精标（教研团队） | 2 万条，学科×学段分层抽样 | 金标准 | 微调 + 离线评估集 |
| 线上 abstain 人工回流 | 月均 3000 条 | 金标准 | 持续校准 |

- **月度重训**：abstain 回流 + 抽样复核数据合并重训；离线评估与人工标注一致率 **≥90%** 才允许进入灰度（模型版本状态机见 §6.4）。
- 训练样本**不保留用户 ID 与原文**，仅保留特征向量与标签（合规红线 C6）。

### 3.3.4 推理与规则/模型融合

```python
class ModelBasedEvaluator:
    """LightGBM 五分类：L1-L5 概率分布 + abstain 机制。"""

    MODEL_BUDGET_MS = 450          # 含特征组装+推理，超时回退规则结论（D4）
    ABSTAIN_THRESHOLD = 0.55
    ADOPT_THRESHOLD = 0.75

    def __init__(self, model_path: str, version: str):
        self.booster = lgb.Booster(model_file=model_path)
        self.version = version

    def predict(self, features: np.ndarray) -> Dict[str, float]:
        proba = self.booster.predict(features.reshape(1, -1))[0]
        return {f"L{i+1}": float(p) for i, p in enumerate(proba)}


def fuse_rule_and_model(rule_result: EvaluationResult,
                        proba: Dict[str, float]) -> EvaluationResult:
    """融合裁决（保守优先：宁可误判偏难，不可误判偏易）：
    - max_proba ≥ 0.75      → 采用模型结论（method=hybrid）
    - 0.55 ≤ max_proba <0.75 → 取规则与模型中【更高】等级，标记 low_confidence，
                               进人工抽检队列（rate=100%）
    - max_proba < 0.55      → abstain：保留规则结论，标记 model_abstained，
                               按策略抽样入人工标注队列
    """
    best_level, best_p = max(proba.items(), key=lambda kv: kv[1])
    order = {"L1": 1, "L2": 2, "L3": 3, "L4": 4, "L5": 5}

    if best_p >= ModelBasedEvaluator.ADOPT_THRESHOLD:
        fused = AgeFitLevel(best_level)
    elif best_p >= ModelBasedEvaluator.ABSTAIN_THRESHOLD:
        fused = max([rule_result.scored_level, AgeFitLevel(best_level)],
                    key=lambda l: order[l.value])
        rule_result.detail["low_confidence"] = True
    else:
        fused = rule_result.scored_level
        rule_result.detail["model_abstained"] = True

    rule_result.scored_level = fused
    rule_result.is_fit = order[fused.value] <= order[rule_result.detail["target_level"]]
    rule_result.method = "hybrid"
    rule_result.model_proba = proba
    # 幼儿段硬门槛（合规红线 C3）：任一硬维度 ≥4.0 一票否决，优先于融合结论
    if rule_result.detail["target_level"] == "L1" and max(
        rule_result.scores.vocabulary, rule_result.scores.domain_term
    ) >= 4.0:
        rule_result.is_fit = False
        rule_result.detail["hard_gate"] = "L1_zero_tolerance"
    return rule_result
```

## 3.4 评估编排器（AgeFitOrchestrator）

### 3.4.1 三种调用模式

| 模式 | 延迟预算 | 评估路径 | 典型调用方 |
|------|---------|---------|-----------|
| `SYNC_FAST` | ≤50ms (P99) | 缓存→规则，**永不调模型** | 推荐过滤、ARPP 流式首评、推荐引擎候选集过滤 |
| `SYNC_FULL` | ≤500ms (P99) | 缓存→规则→(置信度<0.85)模型→融合 | ARPP 异步补评估、学习报告、适龄化引擎改写后复评 |
| `ASYNC` | 无（队列） | 规则+模型+全量落库+事件 | 题目入库批量标注、内容巡检、词典回归验证 |

SYNC_FAST 延迟预算分解（P99 ≤50ms）：分词预处理 6ms / 词汇扫描 8ms / 术语 AC 匹配 10ms / 概念推理表达正则 12ms / 违规收集组装 4ms / gRPC 内网序列化 5ms，合计 45ms。

### 3.4.2 主流程

```python
class AgeFitOrchestrator:
    """统一评估入口：缓存 → 规则 → 置信度路由 → 模型 → 落库/事件（异步旁路）。"""

    def __init__(self, rule_evaluator, model_evaluator, redis, persist_queue):
        self.rule = rule_evaluator
        self.model = model_evaluator
        self.redis = redis
        self.persist_queue = persist_queue   # 内存批量落库队列（见 §3.4.4）

    async def evaluate(self, text: str, target_level: AgeFitLevel,
                       subject: str = None, mode: str = "SYNC_FAST",
                       source: dict = None) -> EvaluationResult:
        # 0. 输入校验（54300/54301/54302）
        self._validate(text, target_level, subject)

        # 1. 规范化 + 幂等键
        normalized = normalize_text(text)               # 去多余空白/统一全半角
        content_hash = sha256(f"{normalized}|{subject or ''}".encode()).hexdigest()
        cache_key = f"age_fit:eval:{content_hash}:{target_level.value}"

        # 2. 缓存命中 → 直接返回（命中记录 method 追加 :cached）
        if mode != "ASYNC":
            cached = await self.redis.get(cache_key)
            if cached:
                result = EvaluationResult.from_json(cached)
                result.method += ":cached"
                return result

        # 3. 规则评估（零 IO，见 §3.2.2）
        result = await self.rule.evaluate(normalized, target_level, subject)
        result.detail["target_level"] = target_level.value
        result.eval_version = fingerprint()             # dict|model|threshold 三版本指纹

        # 4. 置信度路由 → 模型引擎（仅 SYNC_FULL / ASYNC 且规则置信度 <0.85）
        if mode != "SYNC_FAST" and result.confidence < 0.85 and self.model:
            try:
                async with timeout_ms(ModelBasedEvaluator.MODEL_BUDGET_MS):
                    features = build_features(result, normalized)
                    proba = await asyncio.to_thread(self.model.predict, features)
                result = fuse_rule_and_model(result, proba)
            except (TimeoutError, ModelNotLoadedError) as e:
                result.degraded.append("D4")            # 回退规则结论
                result.detail["model_fallback"] = str(e)

        # 5. 异步旁路：缓存写入 + 批量落库 + 事件（不阻塞返回）
        asyncio.create_task(self._side_effect(
            cache_key, result, content_hash, normalized, source
        ))
        return result

    async def _side_effect(self, cache_key, result, content_hash,
                           normalized, source):
        try:
            await self.redis.set(cache_key, result.to_json(), ex=86400)  # TTL 24h，与 §2.4 一致
            # 持久化采样：not_fit 全量 / fit 且缓存未命中 / fit 抽样 5%（见 §10 容量）
            if (not result.is_fit or source and source.get("miss_cache")
                    or random.random() < 0.05):
                self.persist_queue.put(content_age_fit_eval_row(
                    result, content_hash, normalized, source
                ))
        except Exception:
            # 旁路失败不影响主结果；持久化失败走 D2 本地补偿队列
            logger.exception("agefit side-effect failed")
```

### 3.4.3 流式（chunk）评估契约（与 ARPP 对齐）

- ARPP 的 `AgeAdaptFilter` 负责**句界缓冲**（跨 chunk 的半句不送评），本引擎提供 `evaluate_sentences(List[str], ...)` 按句批量评估：各句独立评分，输出按句的 `local_score` 与全句聚合 `aggregate_result`。
- 流式首评固定 `SYNC_FAST`（预算 50ms；ARPP 侧总预算 300ms 由其自行在“评估+改写”间分配，见其 E3 降级）。
- 流结束 `flush()` 后由 ARPP 异步发起 `SYNC_FULL` 全文补评估（不追改已输出内容，结果入缓存供同题复用）——补评估入口即本编排器 `evaluate(mode="SYNC_FULL")`，无需独立接口。

### 3.4.4 落库与幂等

- 评估记录写入走**进程内批量队列**（500 条或 2s 触发批量 INSERT），同步路径不碰 DB 写；DB 不可用时队列转本地磁盘补偿文件（上限 100MB，超限丢最旧 fit 记录保 not_fit，降级 D2）。
- 幂等键 = `sha256(normalized_text|subject) + target_level`（与缓存键一致）；`EvaluateBatch` 分片 200 条/批，分片级重试以 `batch_id + shard_index` 幂等（54313），回写方以 `uk(source_type, source_id, eval_version)` 去重。

### 3.5.2 术语 AC 自动机与别名展开

- 术语匹配采用 **Aho-Corasick 最长匹配**：`domain_term_registry.aliases` 展开后共约 12 万模式节点（6 万术语 × 平均 2 别名），构建耗时 <5s/学科，进程内惰性构建缓存（`VocabularyStore._matchers`）。

- AC 构建失败 → 降级朴素子串匹配（延迟 +15ms，结果一致，告警，D7）。

## 5. 关键流程时序

### 5.1 AI 输出评估与重写触发闭环（ARPP × 本引擎 × 适龄化引擎）

```text
AI网关          ARPP管线          AgeFit引擎         适龄化引擎(改写)
  │  流式chunk      │                  │                   │
  │───────────────>│ 句界缓冲满出      │                   │
  │                │──SYNC_FAST 50ms──>│ 规则评估(零IO)     │
  │                │<─local_score─────│                   │
  │                │ 超标且幼儿/小学低段│                   │
  │                │─────────改写请求(预算300ms)───────────>│
  │                │<────────改写后文本─────────────────────│
  │<─流式输出──────│                  │                   │
  │                │ flush()后异步     │                   │
  │                │──SYNC_FULL──────>│ 缓存→规则→模型融合  │
  │                │<─最终结论─────────│ 入缓存+落库+事件    │
  │                │ 持续not_fit→violation.persisted事件    │
  │                │ → AI质量监控/RLHF样本库(抽样)           │
```

要点：①首评永不出现在用户等待路径之外（50ms 内）；②改写执行归适龄化引擎，本引擎只给证据（over_level_items）；③复评结论不追改已输出内容，仅供缓存复用与质量统计。

### 5.2 题目入库批量标注

题库导入完成 → 发 `agefit.batch.requested`（题库服务）→ 本引擎 ASYNC 消费：`EvaluateBatch` 200 条/分片、失败分片重试 2 次、幂等键 `batch_id+shard_index` → 逐题回写 `questions.age_fit_level / age_fit_confidence / age_fit_eval_version` → 置信度 <0.85 的题目进人工标注队列 → 批次完成发 `agefit.batch.completed`（含失败清单）。题目难度（IRT）与适龄等级解耦：同一题可能“难度 b=0.2（易）但适龄 L5（术语重）”。

### 5.3 推荐内容过滤

推荐引擎召回 500 候选 → 批量 `Evaluate(mode=SYNC_FAST)`（总预算 300ms，内网并行分片 3×200 条）→ 过滤 `is_fit=false` → 未评估且无缓存的新内容按“已有 age_fit_level 字段的直通，缺失的现场评”。可选个性化：`age_fit:user_vocab:{user_id}`（TTL 7d）提供学生实际词汇等级，允许**上调**目标等级（学有余力），**禁止下调**幼儿段硬门槛（C3 合规优先）。缓存未命中率突增（新内容上新）时由推荐引擎预热任务提前批量评估热点题目。

### 5.4 学习报告双版本

学习报告生成服务产出两版文本：学生版按学生学段（`AgeFitLevel.from_grade`）、家长版固定 L4 基线。两版分别走 `SYNC_FULL` 评估，`not_fit` 时报告生成方触发自身模板降级（简化句式模板），不经过 ARPP（非 AI 流式场景）。

## 6. 状态流转

### 6.1 评估记录生命周期

`TRANSIENT`（进程内批量队列）→ `PERSISTED`（content_age_fit_eval，月分区）→ `ARCHIVED`（3 个月后明细迁 ClickHouse，MySQL 仅留 3 个月；CH 明细保留 13 个月，聚合表永久）。

### 6.2 词典发布状态机与守卫（G1-G6）

`DRAFT → BUILDING → CANARY(1%) → PUBLISHED(100%) → ARCHIVED`

| 守卫 | 规则 |
|------|------|
| G1 | PUBLISHED/ARCHIVED 版本快照不可变；工作区编辑不影响已发布版本 |
| G2 | BUILDING→CANARY 需快照构建成功且冒烟集（200 条历史标注）一致率 ≥95% |
| G3 | CANARY 观察窗 ≥30min 且 gray 错误率 <1% 才允许放量；灰度中可一键回切 |
| G4 | 快照 SHA-256 校验失败即拒绝加载（节点侧校验，防篡改/半传） |
| G5 | 同一时刻仅一个 PUBLISHED 版本；新版本全量后旧版本自动 ARCHIVED（保留可回切 90 天） |
| G6 | 回切目标必须为 PUBLISHED 状态且发布时间 <90 天 |

### 6.3 人工标注任务状态机

`PENDING → CLAIMED → LABELED → ADOPTED / REJECTED`。REJECTED 样本回流候选池且 30 天内不重复推送；ADOPTED 进训练集（月度重训）。认领冲突返回 54330；同任务重复提交 54331；标注人配额（默认 500 条/日）超限 54332。

### 6.4 模型版本状态机与守卫（G7-G9）

`TRAINING → EVALUATING → CANARY(5%流量) → ACTIVE → RETIRED`

| 守卫 | 规则 |
|------|------|
| G7 | EVALUATING→CANARY 需离线一致率 ≥90%（金标准集） |
| G8 | CANARY 推理超时率 >5% 或结论分布漂移（KL>0.3）→ 自动回切 ACTIVE，告警 |
| G9 | 同一时刻仅一个 ACTIVE；RETIRED 版本保留 6 个月供审计复现 |

## 8. 降级矩阵

| 编号 | 故障 | 策略 | 用户影响 | 恢复动作 |
|------|------|------|---------|---------|
| D1 | Redis 不可用 | 跳过缓存直评，延迟 +5ms | 无感知 | 恢复后缓存重建（评估穿透由 DB 采样兜底） |
| D2 | DB 不可用 | 评估照常，记录进本地磁盘补偿队列（≤100MB，超限先丢 fit 采样保 not_fit） | 无感知 | 恢复后回放队列，对账缺失量 |
| D3 | 词典热更新失败 | 沿用旧版本继续服务，`dict_version_lag` 告警 | 无感知 | 下一轮轮询重试；连续 10 轮失败转人工 |
| D4 | 模型引擎故障/超时 | 规则结论直出 + `degraded=["D4"]` + low_confidence 抽检比例 5%→20% | 兜底时段准确率下降 | 告警；模型状态机回切 |
| D5 | 模型灰度异常 | 自动回切 ACTIVE 版本（G8） | 无感知 | 事故复盘入排障根因库 |
| D6 | ASYNC 队列积压 >10 万 | 削峰：内容巡检让位题目入库标注（优先级表：题目入库 > 内容巡检 > 词典回归） | 标注延迟 | 积压 <2 万恢复全量消费 |
| D7 | AC 构建失败 | 朴素子串匹配（+15ms，结果一致） | 无感知 | 告警；下次快照重建修复 |
| D8 | 批量接口上游超时 | 返回已完成分片 + next_cursor，调用方续传 | 部分结果延迟 | 重试缺失分片（幂等） |
| D9 | 评估原文含 PII | 评估照常，原文按脱敏引擎（scene=AGEFIT）脱敏后存储 | 无感知 | detail.masked=true 审计 |
| D10 | 本引擎全链路不可用 | 调用方各自兜底：ARPP 原样透传、推荐引擎跳过适龄过滤并记 skip 事件；**幼儿段例外**——跳过过滤时 L1 用户仅推荐已人工核定 age_fit_level 的内容（保守白名单） | 幼儿段推荐多样性下降 | 服务恢复探针自动切回 |

## 9. 事件与 Outbox

```sql
CREATE TABLE agefit_outbox (
    id            BIGINT PRIMARY KEY AUTO_INCREMENT,
    event_id      VARCHAR(64) NOT NULL,
    event_type    VARCHAR(60) NOT NULL,
    aggregate_id  VARCHAR(64) NOT NULL,       -- source_id / release_version / model_version
    payload       JSON NOT NULL,
    status        VARCHAR(10) NOT NULL DEFAULT 'PENDING',
    retry_count   INT DEFAULT 0,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    published_at  TIMESTAMP NULL,
    UNIQUE KEY uk_event (event_id)
);
```

Topic：`agefit.domain.events`（信封格式对齐《服务端-消息队列与事件驱动架构》）

| 事件 | 触发 | 关键字段 | 消费方 |
|------|------|---------|--------|
| agefit.eval.completed | 评估落库成功 | source_type/source_id/scored_level/is_fit/confidence/method | 埋点平台（聚合）、题库（exercise 回写）、学习报告（report） |
| agefit.eval.violation.persisted | 同一 source 连续 3 次 not_fit | source_type/source_id/violations 摘要 | AI 质量监控、RLHF 样本库（抽样 10%） |
| agefit.dict.published | 词典放量 100% | version/vocab_delta/term_delta | 全部 agefit 节点（刷新指针）、管理后台通知 |
| agefit.threshold.updated | 阈值配置变更 | config_version/dimensions | 全部 agefit 节点 |
| agefit.model.promoted / rolled_back | 模型晋级/回切 | from_version/to_version/reason | agefit 节点、监控、混沌平台 |
| agefit.batch.completed | ASYNC 批次完成 | batch_id/total/failed_list | 题库服务、内容生产任务引擎 |

消费方幂等：`(event_id, consumer)` 唯一；outbox 与评估记录同库不同表，落库批事务内写入（侧路任务合并提交）。

## 10. 监控与容量

### 10.1 指标与告警

| 指标 | 目标 | 告警阈值 |
|------|------|---------|
| agefit_eval_latency_p99{mode} | SYNC_FAST ≤50ms / FULL ≤500ms | FAST>100ms 持续 5min（P1） |
| agefit_compliance_rate{source_type,target_level} | 环比稳定 | 日环比下跌 >5pct（P2，内容质量问题线索） |
| agefit_rule_model_route_ratio（模型兜底占比） | 10%-20% | >35%（词典覆盖退化信号，P2） |
| agefit_model_abstain_rate | <3% | >5%（模型漂移，触发重训评估） |
| agefit_cache_hit_rate | >55% | <30%（缓存失效/上新突增） |
| agefit_dict_version_lag_seconds | <60s | >300s（D3 持续） |
| agefit_dict_build_duration | ≤120s | >300s |
| agefit_model_inference_latency_p99 | ≤50ms | >100ms |
| agefit_outbox_lag | <30s | >120s（P2） |
| agefit_persist_queue_depth | <1 万 | >10 万（D2 触发临界，P1） |

### 10.2 容量估算（DAU 50 万）

- **调用量**：AI 输出评估 125 万次/日（对话 80 万 + 搜题解析 20 万 + 报告讲解 25 万）+ 内容批任务 5 万条/日；峰值 260 eval/s（晚 19:00-21:00）。规则评估 CPU 单核 ~800 次/s → 4 worker×2 核富余；模型兜底 15% ≈ 39 q/s，LightGBM 单样本 3ms 单核 300+/s 富余。
- **内存**/节点：词表 32 万条双缓冲 ≈ 2×80MB + 术语 AC ≈ 2×20MB + 模型 20MB ≈ **320MB** 常驻。
- **存储**：持久化采样（not_fit 全量 + fit 未命中缓存 + fit 5% 抽样）≈ 55 万行/日 ×0.8KB ≈ 440MB/日；MySQL 月分区留 3 个月（≈40GB）+ ClickHouse 明细 13 个月 + 聚合永久。

## 11. 合规红线

- **C1** 评估原文仅存脱敏后前 2000 字（`content_text` 字段定义）；含 PII 时经脱敏引擎 scene=AGEFIT 处理（D9），未成年对话原文不得进入分析类系统。
- **C2** 合规率与评估明细仅用于内容质量聚合统计，**禁止**用于单个学生画像或个性化推送决策依据。
- **C3** 幼儿段（L1）硬门槛：vocabulary 或 domain_term 任一 ≥4.0 一票否决（`hard_gate=L1_zero_tolerance`），不可被个性化/融合结论豁免。
- **C4** 词典与阈值变更双人审批，审计记录不可删除。
- **C5** 人工标注任务内容不得含可识别学生身份信息（标注样本来自内容侧与脱敏 AI 输出）。
- **C6** 模型训练样本仅保留特征向量与标签，不保留用户 ID 与原文。
- **C7** 评估接口不对客户端开放 detail（原文相关字段仅内网/管理端按权限可见），防探测构造内容反推词库。
- **C8** 营销/运营内容同样纳入评估（source_type=marketing），not_fit 的营销文案禁止投递给低学段用户。

## 12. 契约对齐

1. **AI 回答后处理管线（ARPP）§3.4**：流式首评=SYNC_FAST（50ms）；flush 后异步补评=SYNC_FULL；同 `content_hash+target_level` 缓存键复用（其“同题复用”承诺由本引擎缓存承担）；其 E3（300ms 超时原句透传）与本引擎 50ms 预算兼容。
2. **AI 回答适龄化处理与学段表达适配引擎**：改写执行权归该引擎；本引擎只输出证据（over_level_items/violations）；改写后复评由该引擎回调本引擎 `Evaluate(SYNC_FULL)`；双方评分字段命名区分（本引擎六维 complexity vs 其表达难度分），避免下游误用。
3. **教育内容认知适宜性评估与信息负载优化引擎**：互补不重叠——本引擎产出语言适龄等级 L1-L5，其产出认知负荷指数；两者在内容画像并列挂载，由《教育内容语义标签体系与多维度内容画像引擎》统一归并；其 §1.3 边界表对应行以本口径为准修正理解。
4. **AI-Prompt 编排系统**：`GetLevelParams` 为其提供词汇等级分布/句长阈值/概念范围；该文档当前版本无适龄引用，列为待其 v1.1 接入项。
5. **题目与题库服务**：题目表新增 `age_fit_level / age_fit_confidence / age_fit_eval_version` 回写字段；批量标注走 ASYNC + `agefit.batch.*` 事件；IRT 难度与适龄等级解耦（§5.2）。
6. **自适应学习与个性化推荐引擎**：候选过滤用 `EvaluateBatch(SYNC_FAST)` 总预算 300ms；`user_vocab` 个性化仅允许上调目标等级（§5.3）。
7. **学习报告生成与交付服务**：学生版按学段、家长版 L4 基线双评估入参（§5.4）。
8. **多题型统一判题引擎**：不消费本引擎——判题正确性与语言适龄正交。
9. **用户生成内容安全审核引擎**：其“分龄从严”属安全维度（RiskLevel），与本引擎适龄等级独立并存，结果在内容画像并列。
10. **数据字典与统一枚举体系**：注册 `AgeFitLevel`、`ComplexityDimension`、`agefit.dict/release` 状态枚举。
11. **统一埋点数据治理**：注册 §4.3 六事件（含属性 Schema）。
12. **灰度发布与特性开关系统**：词典/模型灰度复用 flag `agefit.dict.gray` / `agefit.model.canary`，放量动作双写特性开关平台。
13. **管理后台**：新增“适龄运营”一级菜单（词库/阈值/标注/报表四页），路由与权限码注册至权限管理。

## 13. 验收场景

1. 幼儿提问，AI 输出含“勾股定理”→ domain_term≥4.0 → `hard_gate` 一票否决 not_fit，触发重写链路。
2. L2 目标文本超纲词率 8% → vocabulary=3.0 → scored L3 → not_fit（高 1 级不允许）；L3 内容推给 L4 学生 → fit（低 1 级兼容）。
3. 规则置信度 0.9 → 不调模型，SYNC_FAST P99 ≤50ms（压测回归）。
4. 规则置信度 0.5 且模型 max_proba=0.82 与规则结论不同 → 采用模型结论（method=hybrid）。
5. 模型 max_proba=0.50 → abstain → 规则结论 + 人工抽检队列入队。
6. 同文本同学科同学段 2 次评估 → 第二次缓存命中，DB 零写入，method=`rule:cached`。
7. 词典发布双缓冲切换：切换瞬间 100 并发在途评估全部用旧版本完成，新请求用新版本，无混合版本记录（eval_version 抽查）。
8. 词典灰度期错误率 2%（>1%）→ 自动回切上一 PUBLISHED 版本，事件 `agefit.dict.published` 补偿通知。
9. Redis 宕机演练 → 评估成功率 100%，延迟 +5ms 内，`degraded=["D1"]`，命中率指标归零告警。
10. 5 万题批量标注：注入 3% 分片失败 → 重试 2 轮补齐，回写零重复（`uk(source,eval_version)` 验证），置信度 <0.85 全部入人工队列。
11. 术语“匀速直线运动”与“直线运动”同现 → 最长匹配仅计前者；别名“等速直线运动”同样命中。
12. 评估原文含手机号 → 评估结论正常返回，落库 `content_text` 为脱敏值，detail.masked=true（D9）。
13. 阈值配置修改 → `agefit.threshold.updated` 广播后 ≤30s 全节点生效（版本指纹变化验证）。
14. 模型灰度 5% 流量推理超时率 6%（>5%）→ 自动回切 ACTIVE，G8 事件留痕。
15. 本引擎整体下线演练（D10）：推荐引擎记 skip 事件正常出结果；L1 用户候选全部来自人工核定白名单。
16. 管理端合规率报表（学段×来源聚合）与明细表对账误差 <0.1%；评估记录原文回显操作留审计。
