# 账号体系-第三方登录与授权集成详细设计

## 1. 概述

### 1.1 设计目标

第三方登录与授权集成模块负责为 PrimeTop 提供基于 OAuth 2.0 / OpenID Connect 的第三方账号登录能力，支持学生、家长在不依赖手机号的情况下快速完成注册与登录，并保证同一自然人在不同终端、不同平台下的账号统一性（One ID）。

**核心价值：**
- 降低注册门槛，提升新用户转化率（尤其是低龄学生和家长）
- 复用微信、QQ、Apple 等平台的实名与未成年人信息，简化身份核验
- 支持多端登录状态统一，避免同一用户产生多个孤立账号
- 为家庭账号、教师账号等后续账号体系扩展预留扩展点
- 满足《儿童个人信息网络保护规定》等平台授权合规要求

### 1.2 适用范围

| 范围项 | 说明 |
| --- | --- |
| 用户类型 | 学生、家长（后续可扩展教师） |
| 登录平台 | 微信（iOS/Android）、QQ（Android）、Apple ID（iOS） |
| 授权协议 | OAuth 2.0 + OpenID Connect（Apple）/ 各平台授权 SDK |
| 账号策略 | 首次授权自动注册，已有手机账号则绑定第三方账号；同一 OpenID 不可重复注册 |
| 后续扩展 | 钉钉、支付宝、企业微信、学校统一身份认证等 |

### 1.3 设计原则

1. **平台隔离**：不同平台授权凭证、OpenID 独立存储，避免混用。
2. **账号归一**：通过 `union_id` 或手机号将同一自然人的多个账号合并为统一 `user_id`。
3. **安全优先**：服务端校验授权码（Authorization Code）与 AccessToken，客户端 token 不可直接用于登录。
4. **未成年人保护**：授权完成后仍须完成学段/年级设置与家长确认流程；家长账号可代未成年人设置。
5. **幂等可重试**：授权登录接口具备幂等性，重复提交相同授权码不会重复创建账号。
6. **可审计**：所有授权、绑定、解绑操作均留审计日志，包括平台、IP、设备指纹。

## 2. 业务流程

### 2.1 标准 OAuth2 授权登录流程（以微信为例）

```text
┌──────────┐         ① 打开授权页          ┌──────────┐
│  客户端   │ ───────────────────────────────> │ 微信平台  │
│ (APP/H5) │                                 │          │
└──────────┘         ② 用户确认授权          └──────────┘
     │  <───────────────────────────────  │
     │ ③ 返回 authorization_code          │
     │                                    │
     │ ④ /auth/oauth/{provider}/callback  │
     │    {code, state, device_id}        │
     │ ────────────────────────────────>  │
     │                                    │  ┌──────────────┐
     │                                    │  │  平台授权服务  │
     │                                    │  │  - 校验 state  │
     │                                    │  │  - 用 code 换  │
     │                                    │  │    access_token│
     │                                    │  │  - 获取用户信息│
     │                                    │  └──────────────┘
     │ ⑤ 返回 JWT（access + refresh）     │
     │    或 302/需要绑定手机号           │
     │ <────────────────────────────────  │
     │                                    │
```

### 2.2 首次授权自动注册 vs 已有账号绑定

| 场景 | 判定条件 | 处理结果 |
| --- | --- | --- |
| 纯新用户 | 该 `provider_open_id` 未绑定任何用户 | 创建新用户，生成默认学生档案，进入年级/学段设置引导 |
| 已存在第三方账号 | `provider_open_id` 已绑定用户 | 直接登录，刷新 JWT 令牌 |
| 已存在手机号账号 | 手机号未注册，但授权信息中包含手机号且与手机号账号一致 | 自动合并，绑定第三方账号 |
| 需要补充手机号 | 平台未返回手机号，且本地未绑定手机 | 登录成功但标记为“弱账号”，引导后续绑定手机号 |
| 账号冲突 | 同一手机号下已绑定其他第三方账号 | 提示用户选择合并或换绑，进入账号合并流程 |

### 2.3 家长账号代孩子授权（家庭场景）

家长使用自己微信登录后，可在“家长中心”扫描孩子端二维码或输入孩子账号，触发“孩子授权绑定”流程。该流程由家长账号发起，孩子端确认，绑定关系写入 `parent_student_bindings` 表，不改变学生账号的第三方登录状态。

## 3. 数据结构设计

### 3.1 核心实体关系

```text
User
 ├─ UserOAuthAccount (第三方账号，多对一)
 ├─ StudentProfile
 ├─ ParentBinding
 └─ OAuthAuditLog (授权审计日志)

OAuthProviderConfig (平台配置，如微信、QQ、Apple)
 └─ OAuthClientApp (多客户端应用配置，如 iOS 微信、Android 微信、H5 微信)
```

### 3.2 数据库表设计

#### 3.2.1 `user_oauth_accounts`（第三方账号绑定表）

```sql
CREATE TABLE user_oauth_accounts (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    user_id BIGINT NOT NULL COMMENT '关联用户ID',
    provider VARCHAR(32) NOT NULL COMMENT '平台标识：wechat、qq、apple、dingtalk 等',
    app_id VARCHAR(128) NOT NULL COMMENT '我方在平台申请的应用ID',
    open_id VARCHAR(255) NOT NULL COMMENT '平台返回的 OpenID，同一应用下唯一',
    union_id VARCHAR(255) COMMENT '跨应用唯一标识，如微信 unionid、Apple 未提供则为空',
    display_name VARCHAR(128) COMMENT '第三方昵称（如微信昵称）',
    avatar_url VARCHAR(512) COMMENT '第三方头像',
    raw_profile JSON COMMENT '平台返回的原始用户信息（脱敏后归档）',
    access_token_hash VARCHAR(128) COMMENT 'AccessToken 脱敏哈希，用于后续解绑校验',
    refresh_token_hash VARCHAR(128) COMMENT 'RefreshToken 哈希（如适用）',
    token_expires_at DATETIME COMMENT 'AccessToken 过期时间',
    is_primary TINYINT DEFAULT 0 COMMENT '是否主登录方式：0-否，1-是（每个用户仅允许一个主登录方式）',
    status TINYINT DEFAULT 1 COMMENT '状态：0-解绑，1-正常，2-异常冻结',
    bound_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '绑定时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_provider_open_id (provider, app_id, open_id),
    UNIQUE KEY uk_user_provider (user_id, provider),
    KEY idx_union_id (union_id),
    KEY idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户第三方账号绑定表';
```

> 注意：平台 AccessToken 属于敏感凭证，不允许明文持久化；仅存储不可逆哈希，用于解绑时确认操作者身份。实际调用平台 API 时由临时缓存（Redis，TTL <= 5 分钟）持有。

```text
oauth:state:{state}  ->  { clientType, deviceId, redirectUri, nonce, ttl: 600s }
```

## 4. API 接口设计

### 4.1 接口概览

| 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 获取授权链接 | GET | `/api/v1/auth/oauth/{provider}/authorize` | 客户端拉起授权页前获取 URL 与 state |
| 授权回调（服务端） | POST | `/api/v1/auth/oauth/{provider}/callback` | 客户端将授权码提交给服务端换 token |
| 绑定第三方账号 | POST | `/api/v1/account/oauth/{provider}/bind` | 已登录用户绑定新的第三方账号 |
| 解绑第三方账号 | POST | `/api/v1/account/oauth/{provider}/unbind` | 已登录用户解绑第三方账号 |
| 查询已绑定账号 | GET | `/api/v1/account/oauth/list` | 返回当前用户已绑定的第三方账号列表 |
| 设置主登录方式 | PUT | `/api/v1/account/oauth/{provider}/primary` | 设置默认第三方登录方式 |
| 刷新 Access Token | POST | `/api/v1/auth/oauth/{provider}/refresh` | 使用 refresh_token 刷新 JWT |
| 账号合并确认 | POST | `/api/v1/account/oauth/merge` | 处理 OpenID/手机号冲突合并 |

**请求：**

```http

```

**响应：**

```json

  "code": 0,
  "data": {
```

### 4.5 解绑第三方账号

**请求：**

```http
POST /api/v1/account/oauth/qq/unbind
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "verify_code": "123456"  // 如当前未绑定手机号，则必须先绑定手机才能解绑
}
```

**响应：**

```json
{
  "code": 0,
  "data": {
    "unbound": true
  }
}
```

> 解绑策略：每个用户必须保留至少一种登录方式（手机号或另一个第三方账号）。若仅剩第三方账号，拒绝解绑并提示绑定手机号。

### 4.6 错误码

| 错误码 | 含义 | 说明 |
| --- | --- | --- |
| 400001 | 参数缺失 | code/state/client_type 为空 |
| 400002 | state 无效或过期 | 无法从 Redis 找到 state |
| 400003 | 授权码已被使用 | 同一 code 不能重复换 token |
| 400004 | 平台配置未启用 | 当前平台或客户端类型未启用 |
| 400005 | 不支持的 provider | 如传入 `facebook` |
| 401001 | 平台授权失败 | 微信/Apple 返回错误 |
| 401002 | 用户拒绝授权 | 平台明确返回用户取消 |
| 409001 | 账号冲突 | 需要合并或换绑 |
| 409002 | 该第三方账号已绑定其他用户 | 无法绑定 |
| 409003 | 用户已绑定同平台账号 | 不允许重复绑定同一平台 |
| 422001 | 缺少必要用户信息 | 平台未返回 open_id |
| 500001 | 内部服务错误 | 平台 API 调用异常 |

## 6. 关键代码示例

### 6.1 平台策略接口（Strategy 模式）

```java
public interface OAuthProviderStrategy {
    String getProvider();
    OAuthAuthUrl buildAuthUrl(String clientType, String deviceId, String redirectUri);
    OAuthUserInfo exchangeCode(String code, String state, OAuthClientApp clientApp);
    boolean verifyToken(String accessToken, String openId);
    String refreshAccessToken(String refreshToken);
}

@Component
public class WechatOAuthStrategy implements OAuthProviderStrategy {
    @Override
    public OAuthUserInfo exchangeCode(String code, String state, OAuthClientApp clientApp) {
        // 1. 校验 state
        OAuthStateCache stateCache = stateCacheRepo.get(state);
        if (stateCache == null || !stateCache.getClientType().equals(clientApp.getClientType())) {
            throw new OAuthException(ErrorCode.OAUTH_STATE_INVALID);
        }
        // 2. 用 code 换 access_token + openid
        String url = String.format(
            "https://api.weixin.qq.com/sns/oauth2/access_token?appid=%s&secret=%s&code=%s&grant_type=authorization_code",
            clientApp.getAppId(), decryptSecret(clientApp), code
        );
        WechatTokenResponse resp = httpClient.get(url, WechatTokenResponse.class);
        if (resp.getErrcode() != null) {
            throw new OAuthException(ErrorCode.OAUTH_PLATFORM_FAILED, resp.getErrmsg());
        }
        // 3. 获取用户信息（scope 为 snsapi_userinfo 时）
        String userInfoUrl = String.format(
            "https://api.weixin.qq.com/sns/userinfo?access_token=%s&openid=%s",
            resp.getAccessToken(), resp.getOpenid()
        );
        WechatUserInfo wx = httpClient.get(userInfoUrl, WechatUserInfo.class);
        return OAuthUserInfo.builder()
            .provider("wechat")
            .appId(clientApp.getAppId())
            .openId(wx.getOpenid())
            .unionId(wx.getUnionid())
            .displayName(wx.getNickname())
            .avatarUrl(wx.getHeadimgurl())
            .build();
    }
}
```

### 6.2 登录/绑定核心服务

```java
@Service
@RequiredArgsConstructor
public class OAuthLoginService {
    private final UserOAuthAccountRepository oauthRepo;
    private final UserRepository userRepo;
    private final OAuthProviderStrategyFactory strategyFactory;
    private final JwtService jwtService;
    private final OAuthAuditLogger auditLogger;

    @Transactional
    public OAuthLoginResult callback(String provider, OAuthCallbackRequest req) {
        OAuthClientApp clientApp = getClientApp(provider, req.getClientType());
        OAuthProviderStrategy strategy = strategyFactory.get(provider);

        // 1. 平台授权，获取用户标识
        OAuthUserInfo userInfo = strategy.exchangeCode(req.getCode(), req.getState(), clientApp);
        if (StringUtils.isBlank(userInfo.getOpenId())) {
            throw new OAuthException(ErrorCode.OAUTH_MISSING_OPEN_ID);
        }

        // 2. 幂等：检查该 code 是否已被使用
        if (oauthCodeUsedCache.contains(req.getCode())) {
            throw new OAuthException(ErrorCode.OAUTH_CODE_REUSED);
        }
        oauthCodeUsedCache.put(req.getCode(), "1", Duration.ofSeconds(60));

        // 3. 查找账号绑定
        Optional<UserOAuthAccount> bound = oauthRepo.findByProviderAndAppIdAndOpenId(
            provider, clientApp.getAppId(), userInfo.getOpenId()
        );

        User user;
        boolean isNew = false;
        if (bound.isPresent()) {
            user = userRepo.findById(bound.get().getUserId())
                .orElseThrow(() -> new OAuthException(ErrorCode.USER_NOT_FOUND));
            updateOAuthAccount(bound.get(), userInfo);
        } else {
            // 4. 新账号：检查 union_id 是否已存在其他用户
            user = findByUnionId(provider, userInfo.getUnionId())
                .orElseGet(() -> {
                    boolean newFlag = true;
                    return createUserFromOAuth(userInfo);
                });
            isNew = !bound.isPresent();
            bindOAuthAccount(user, userInfo, clientApp);
        }

        // 5. 审计日志
        auditLogger.log(OAuthAction.LOGIN, user.getId(), provider, userInfo.getOpenId(),
            req.getDeviceId(), true, null);

        // 6. 签发 JWT
        String accessToken = jwtService.createAccessToken(user.getId(), req.getDeviceId());
        String refreshToken = jwtService.createRefreshToken(user.getId(), req.getDeviceId());

        return OAuthLoginResult.builder()
            .action(isNew ? "register" : "login")
            .userId(user.getId())
            .isNew(isNew)
            .accessToken(accessToken)
            .refreshToken(refreshToken)
            .profileStatus(detectProfileStatus(user))
            .build();
    }

    private User createUserFromOAuth(OAuthUserInfo info) {
        User user = new User();
        user.setNickname(info.getDisplayName());
        user.setAvatarUrl(info.getAvatarUrl());
        user.setStatus(UserStatus.ACTIVE);
        user.setAccountType(AccountType.STUDENT);
        user.setPhoneVerified(false);
        return userRepo.save(user);
    }

    private void bindOAuthAccount(User user, OAuthUserInfo info, OAuthClientApp app) {
        UserOAuthAccount account = new UserOAuthAccount();
        account.setUserId(user.getId());
        account.setProvider(info.getProvider());
        account.setAppId(app.getAppId());
        account.setOpenId(info.getOpenId());
        account.setUnionId(info.getUnionId());
        account.setDisplayName(info.getDisplayName());
        account.setAvatarUrl(info.getAvatarUrl());
        account.setStatus(1);
        account.setPrimary(oauthRepo.countByUserId(user.getId()) == 0 ? 1 : 0);
        oauthRepo.save(account);
    }
}
```

### 6.4 Apple ID 特殊处理（客户端身份校验）

Apple 登录返回的 `identity_token` 是 JWT，服务端必须校验签名与 audience。

```java
public class AppleIdentityTokenVerifier {
    public AppleUserInfo verify(String identityToken, String clientId) {
        DecodedJWT jwt = JWT.decode(identityToken);
        // 1. 校验 audience 是否为本方 Bundle ID
        if (!jwt.getAudience().contains(clientId)) {
            throw new OAuthException(ErrorCode.OAUTH_AUDIENCE_MISMATCH);
        }
        // 2. 校验 issuer
        if (!"https://appleid.apple.com".equals(jwt.getIssuer())) {
            throw new OAuthException(ErrorCode.OAUTH_ISSUER_MISMATCH);
        }
        // 3. 从 Apple 公钥端点获取公钥并验签
        RSAPublicKey publicKey = appleKeyProvider.getPublicKey(jwt.getKeyId());
        JWTVerifier verifier = JWT.require(Algorithm.RSA256(publicKey, null))
            .withIssuer("https://appleid.apple.com")
            .withAudience(clientId)
            .build();
        verifier.verify(identityToken);

        String appleUserId = jwt.getSubject();
        String email = jwt.getClaim("email").asString();
        boolean emailVerified = jwt.getClaim("email_verified").asBoolean();
        return new AppleUserInfo(appleUserId, email, emailVerified);
    }
}
```

## 7. 安全与合规

### 7.1 授权码安全

- 所有 `code` 必须一次性使用，服务端记录已使用 code 并拒绝重复提交。
- `state` 参数由服务端生成，长度不低于 32 位随机字符，写入 Redis 并设置 600 秒过期。
- 客户端禁止缓存 `code` 或将其暴露给非本端应用。
- H5 场景下必须使用 `state` 校验，防止跨站伪造请求。

### 7.2 Token 与密钥管理

- 平台 `app_secret` 必须加密存储（AES-256-GCM 或 KMS），禁止硬编码在客户端。
- AccessToken 仅在服务端使用；如需客户端临时使用（如拉取头像），应使用独立短有效期 token。
- 第三方 RefreshToken 不长期存储；仅保存哈希值用于审计与解绑校验。

### 7.3 未成年人保护

- 14 周岁以下用户通过微信授权后，必须要求家长手机号绑定并确认《儿童个人信息保护规则》。
- 第三方登录获取的头像、昵称仅用于展示，不可用于精准广告或向第三方平台回传。
- 家长端可查看并管理孩子绑定的第三方账号，支持一键解绑。

### 7.4 数据脱敏

- 审计日志中 OpenID 必须掩码展示（前 4 后 4）。
- 管理后台查询用户第三方账号时，需二次鉴权（管理员 + 操作原因）。

## 8. 错误处理与降级策略

### 8.1 平台授权失败

| 失败场景 | 服务端行为 | 客户端行为 |
| --- | --- | --- |
| 微信接口超时 | 返回 500001，记录日志，触发告警 | 提示“授权服务繁忙，请重试” |
| 用户取消授权 | 返回 401002 | 停留在登录页，提供手机号登录入口 |
| 授权码过期 | 返回 401001 | 引导重新拉起授权页 |
| 平台返回 open_id 为空 | 返回 422001 | 提示换用其他登录方式 |
| 同一 code 重复提交 | 返回 400003 | 忽略第二次响应，避免重复弹窗 |

### 8.2 登录链路降级

当第三方平台大面积异常时，启用降级策略：

1. 自动切换为“手机号 + 验证码”登录入口为默认选项。
2. 隐藏第三方登录按钮或置灰提示“暂时不可用”。
3. 已绑定第三方账号但平台不可用时，允许通过手机号找回登录。

### 8.3 熔断与限流

- 对 `/auth/oauth/{provider}/callback` 按 IP + 设备指纹限流：每 60 秒最多 10 次。
- 对平台 API 调用配置熔断：连续失败 20 次或错误率 > 50% 持续 1 分钟，触发降级并告警。
- 使用 Hystrix / Sentinel 包装平台 HTTP 调用，设置 5 秒超时与 2 次重试。

## 9. 性能与缓存策略

### 9.1 缓存设计

| 缓存对象 | 存储 | TTL | 说明 |
| --- | --- | --- | --- |
| 授权 state | Redis | 600s | 防止 CSRF 与重放 |
| 已使用 code | Redis | 60s | 幂等控制 |
| 平台 AccessToken | Redis + AES | 300s | 服务端临时调用用户信息 |
| 用户绑定关系 | Redis | 3600s | 加速登录时查询，写操作后失效 |
| Apple 公钥 | Redis | 86400s | 减少 Apple 公钥接口调用 |

### 9.2 并发控制

- 绑定同一 `open_id` 时，对 `(provider, app_id, open_id)` 加分布式锁，防止重复注册。
- 合并账号时，对 `current_user_id` 与 `target_user_id` 加排他锁，顺序加锁避免死锁。
