# 学习行为事件流与跨模块级联处理引擎 - 详细设计

> **模块定位**：定义 PrimeTop 学习行为的领域事件体系、事件路由分发、跨模块级联处理规则与一致性保障机制。当学生完成一次答题、一次 AI 辅导对话、一次章节学习等行为后，系统如何自动触发掌握度更新、错题收录、复习调度、学情分析、通知推送等后续级联处理。
> **覆盖学段**：全学段
> **优先级**：P0（学习闭环的核心数据驱动引擎）

---

## 1. 问题域分析

### 1.1 核心场景

一次典型的「答题行为」需要触发以下级联处理：

```
学生提交答案
  ├─ 1. 批改判定（同步）
  │     └─ 生成 AnswerResult
  ├─ 2. 错题判定（异步，答案错误时）
  │     └─ 写入 MistakeRecord → 错因分析 → 归类到知识点
  ├─ 3. 知识点掌握度更新（异步）
  │     └─ 更新 KnowledgePointMastery → 影响 推荐权重
  ├─ 4. 学习进度更新（异步）
  │     └─ 更新 ChapterProgress → 更新 学习计划任务状态
  ├─ 5. 间隔重复调度（异步，错题时）
  │     └─ 生成/调整 复习计划 → 计算下次复习时间
  ├─ 6. 学情数据聚合（异步）
  │     └─ 更新 日/周/月统计 → 更新 能力画像 → 检测 薄弱点变化
  ├─ 7. 成就/里程碑检测（异步）
  │     └─ 检查是否达成 成就条件 → 解锁 徽章/称号
  ├─ 8. 通知触发评估（异步）
  │     └─ 评估是否需要推送 学习提醒/家长通知
  └─ 9. 埋点事件采集（异步，Fire-and-forget）
        └─ 写入 行为日志 → 实时流处理 → ClickHouse
```

### 1.2 设计挑战

| 挑战 | 描述 |
|------|------|
| **级联深度** | 一个行为最多触发 9+ 下游处理，部分下游还有二级级联 |
| **延迟敏感度不同** | 批改结果需 <500ms 返回；掌握度更新可延迟数秒；学情聚合可延迟分钟级 |
| **幂等性** | 同一行为事件可能因重试被消费多次，下游处理必须幂等 |
| **部分失败** | 某个下游处理失败不应阻塞其他下游，也不应丢失事件 |
| **事件顺序** | 掌握度更新必须在错题收录之后；成就检测必须在掌握度更新之后 |
| **回溯需求** | 某些下游处理需要查询原始行为上下文（题目信息、学生选项、AI 解析等） |
| **流量尖峰** | 考试/作业高峰期答题事件量可能是平时 10-50 倍 |

### 1.3 设计目标

1. **端到端延迟**：批改结果 <500ms 同步返回；核心级联处理 <5s 完成；全链路 <30s
2. **可靠性**：事件零丢失，至少一次投递（at-least-once），下游幂等消费
3. **可观测**：每个行为的级联处理状态可追踪、可查询
4. **可扩展**：新增行为类型或下游处理器不需修改已有代码
5. **可降级**：非关键路径失败时主流程不受影响

## 2. 事件体系设计

### 2.1 领域事件分类

#### 2.1.1 一级行为事件（Behavior Event）

由用户直接触发的学习行为，是级联处理的起点。

| 事件类型 | 事件编码 | 触发场景 | 同步处理 | 异步级联 |
|----------|----------|----------|----------|----------|
| 答题提交 | `answer.submit` | 练习/测评/考试/错题重做 | 批改判定 | 全链路 |
| AI对话完成 | `ai.session.close` | AI辅导对话结束 | — | 学情归集 |
| 拍照搜题 | `photo.search` | 拍题答疑 | OCR+解析 | 错题评估 |
| 章节学习完成 | `chapter.complete` | 同步课堂 | 进度更新 | 推荐调度 |
| 背诵检测完成 | `recite.check` | 文科背诵 | 评分 | 复习调度 |
| 作文提交 | `essay.submit` | 作文辅导 | — | 批改调度 |
| 语音练习完成 | `voice.practice` | 口语陪练/朗读 | 发音评测 | 统计归集 |
| 复习任务完成 | `review.complete` | 间隔重复复习 | 判定 | 复习调度更新 |
| 计划任务完成 | `plan.task.done` | 学习计划执行 | 任务状态更新 | 计划调整评估 |
| 学习会话开始 | `session.start` | 任意学习场景 | 创建会话 | — |
| 学习会话结束 | `session.end` | 退出学习场景 | 时长计算 | 全链路（轻量） |

#### 2.1.2 二级领域事件（Domain Event）

由一级行为事件触发的中间处理结果事件，作为下游处理的输入。

| 事件类型 | 事件编码 | 产生者 | 消费者 |
|----------|----------|--------|--------|
| 错题收录完成 | `mistake.created` | 错题服务 | 复习调度、掌握度更新 |
| 掌握度变更 | `mastery.updated` | 知识点服务 | 推荐引擎、学情分析、成就检测 |
| 复习计划生成 | `review.scheduled` | 复习调度 | 通知评估 |
| 批改完成 | `grade.completed` | 批改引擎 | 错题判定、掌握度更新 |
| 章节进度变更 | `progress.changed` | 进度服务 | 计划调整、通知评估 |
| 薄弱点检测 | `weakness.detected` | 学情服务 | 通知评估、推荐引擎 |
| 成就达成 | `achievement.unlocked` | 成就引擎 | 通知评估、积分发放 |
| 作文批改完成 | `essay.graded` | AI批改 | 掌握度更新、通知 |

| 字段 | 类型 | 说明 |
|------|------|------|
| eventId | string | 事件全局唯一ID，格式 `evt_{ULID}` |
| eventType | string | 事件类型编码 |
| eventTime | ISO8601 | 事件发生时间（客户端/服务端中更早的那个） |
| source | string | 产生事件的服务名 |
| correlationId | string | 关联ID，整个级联链共享同一个 |

| studentId | int | 学生ID（通常等于userId） |
| sessionId | string | 学习会话ID |
| traceId | string | OpenTelemetry Trace ID，用于链路追踪 |
| version | string | 事件结构版本号 |

### 3.2 三级通道设计

根据延迟敏感度和重要性，事件被路由到三个通道：

| 通道 | Redis Key 模式 | 消费模式 | 适用场景 | 延迟目标 |
|------|---------------|----------|----------|----------|
| 快速通道 `priority` | `evt:q:priority:{type}` | 独立 Worker 立即消费 | 掌握度更新、进度更新 | <1s |
| 标准通道 `standard` | `evt:q:standard:{type}` | 普通 Worker Pool | 错题收录、复习调度、成就检测 | <5s |
| 批量通道 `batch` | `evt:q:batch:{type}` | 批量 Worker (攒批) | 学情聚合、统计分析、埋点 | <30s |

```python
# 处理器注册表 (进程内，应用启动时注册)
class EventHandlerRegistry:
    _handlers: Dict[str, Type[BaseEventHandler]] = {}

    @classmethod
    def register(cls, handler_name: str, handler_class: Type[BaseEventHandler]):
        cls._handlers[handler_name] = handler_class

    @classmethod
    def get(cls, handler_name: str) -> Type[BaseEventHandler]:
        if handler_name not in cls._handlers:
            raise ValueError(f"Unknown event handler: {handler_name}")
        return cls._handlers[handler_name]
```

## 4. 核心级联流程详细设计

### 4.1 答题提交全链路（最复杂场景）

#### 4.1.1 同步阶段（请求线程内）

```python
class PracticeService:
    async def submit_answer(self, req: AnswerSubmitRequest) -> AnswerResult:
        # 1. 参数校验
        question = await self.question_repo.get(req.question_id)
        self._validate(req, question)

        # 2. 批改判定（同步）
        grading_result = self.grading_engine.grade(
            question=question,
            user_answer=req.user_answer,
            method=self._select_grading_method(question),
        )

        # 3. 写入答题记录（同步）
        answer_record = AnswerRecord(
            id=snowflake_id(),
            user_id=req.user_id,
            question_id=req.question_id,
            user_answer=req.user_answer,
            is_correct=grading_result.is_correct,
            score=grading_result.score,
            time_spent_ms=req.time_spent_ms,
            practice_type=req.practice_type,
            practice_session_id=req.practice_session_id,
            hint_used=req.hint_used,
            attempt_number=req.attempt_number,
            knowledge_point_ids=question.knowledge_point_ids,
            created_at=datetime.now(),
        )
        await self.answer_repo.create(answer_record)

        # 4. 发布一级行为事件（异步级联起点）
        await self.event_bus.publish("answer.submit", {
            "answerRecordId": answer_record.id,
            "questionId": question.id,
            "practiceSessionId": req.practice_session_id,
            "practiceType": req.practice_type,
            "subject": question.subject,
            "knowledgePointIds": question.knowledge_point_ids,
            "chapterId": question.chapter_id,
            "textbookId": question.textbook_id,
            "stage": req.stage,
            "grade": req.grade,
            "userAnswer": req.user_answer,
            "correctAnswer": question.correct_answer,
            "isCorrect": grading_result.is_correct,
            "timeSpentMs": req.time_spent_ms,
            "hintUsed": req.hint_used,
            "attemptNumber": req.attempt_number,
            "difficulty": question.difficulty,
            "clientTimestamp": req.client_timestamp.isoformat(),
        }, context={
            "userId": req.user_id,
            "sessionId": req.session_id,
            "correlationId": ulid(),
        })

        # 5. 返回同步结果
        return AnswerResult(
            is_correct=grading_result.is_correct,
            score=grading_result.score,
            correct_answer=question.correct_answer if not grading_result.is_correct else None,
            explanation_hint=grading_result.hint,
        )
```

#### 4.1.2 异步级联阶段

```python
class AnswerSubmitHandler(BaseEventHandler):
    """answer.submit 事件的分发处理器"""

    async def handle(self, event: LearningEvent):
        # 创建二级事件 grade.completed（已经完成批改，直接发布）
        grade_event = event.derive("grade.completed", {
            "answerRecordId": event.payload["answerRecordId"],
            "questionId": event.payload["questionId"],
            "isCorrect": event.payload["isCorrect"],
            "score": 100 if event.payload["isCorrect"] else 0,
            "gradingMethod": "exact_match",
            "gradingTimeMs": 0,  # 已在同步阶段完成
        })
        await self.event_bus.publish_event(grade_event)


class MistakeCheckHandler(BaseEventHandler):
    """错题判定处理器"""

    @idempotent(key="mistake_check:{correlationId}:{answerRecordId}")
    async def handle(self, event: LearningEvent):
        if event.payload["isCorrect"]:
            return  # 答对了，不需要收录错题

        # 错因分析
        error_analysis = await self.error_analyzer.analyze(
            question_id=event.payload["questionId"],
            user_answer=event.payload["userAnswer"],
            correct_answer=event.payload["correctAnswer"],
            subject=event.payload["subject"],
        )

        # 创建错题记录
        mistake = MistakeRecord(
            id=snowflake_id(),
            user_id=event.user_id,
            question_id=event.payload["questionId"],
            answer_record_id=event.payload["answerRecordId"],
            subject=event.payload["subject"],
            knowledge_point_ids=event.payload["knowledgePointIds"],
            error_type=error_analysis.error_type,
            error_analysis=error_analysis.description,
            severity=error_analysis.severity,
            source=event.payload["practiceType"],
            status="pending_review",  # 待订正
            created_at=datetime.now(),
        )
        await self.mistake_repo.upsert(mistake)

        # 发布 mistake.created 二级事件
        await self.event_bus.publish("mistake.created", {
            "mistakeRecordId": mistake.id,
            "answerRecordId": event.payload["answerRecordId"],
            "questionId": event.payload["questionId"],
            "subject": event.payload["subject"],
            "knowledgePointIds": event.payload["knowledgePointIds"],
            "errorType": error_analysis.error_type,
            "errorAnalysis": error_analysis.description,
            "severity": error_analysis.severity,
            "autoTagged": True,
            "aiAnalysisConfidence": error_analysis.confidence,
        }, context=event.child_context())


class MasteryUpdateHandler(BaseEventHandler):
    """知识点掌握度更新处理器"""

    @idempotent(key="mastery_update:{correlationId}:{knowledgePointId}")
    async def handle(self, event: LearningEvent):
        # 从事件中提取证据
        evidence = self._extract_evidence(event)

        for kp_id in evidence.knowledge_point_ids:
            # BKT 算法更新掌握度
            current = await self.mastery_repo.get(event.user_id, kp_id)
            updated = self.bkt_engine.update(
                prior=current.mastery,
                is_correct=evidence.is_correct,
                difficulty=evidence.difficulty,
                slip_prob=0.1,   # 猜对概率
                guess_prob=0.2,  # 猜测概率
            )

            await self.mastery_repo.update(
                user_id=event.user_id,
                knowledge_point_id=kp_id,
                mastery=updated.posterior,
                evidence_count=updated.evidence_count + 1,
                last_updated=datetime.now(),
            )

            # 判断是否有显著变化（≥5%）
            if abs(updated.posterior - current.mastery) >= 0.05:
                await self.event_bus.publish("mastery.updated", {
                    "userId": event.user_id,
                    "knowledgePointId": kp_id,
                    "previousMastery": round(current.mastery, 4),
                    "currentMastery": round(updated.posterior, 4),
                    "delta": round(updated.posterior - current.mastery, 4),
                    "updateReason": evidence.reason,
                    "evidenceEventId": event.event_id,
                    "evidenceType": evidence.type,
                    "confidence": round(updated.confidence, 4),
                    "algorithm": "bkt",
                }, context=event.child_context())

    def _extract_evidence(self, event: LearningEvent) -> MasteryEvidence:
        if event.event_type == "grade.completed":
            return MasteryEvidence(
                knowledge_point_ids=event.payload.get("knowledgePointIds", []),
                is_correct=event.payload["isCorrect"],

                reason="answer_correct" if event.payload["isCorrect"] else "answer_wrong",
```

```python
class EventConsumer:
    """事件消费者基类"""
    
    async def consume_loop(self, channel: str, handler_name: str):
        queue_key = f"evt:q:{channel}:{handler_name}"
        
        while True:
            try:
                # BRPOP 阻塞等待（超时 5s）
                result = await self.redis.brpop(queue_key, timeout=5)
                if not result:
                    continue
                
                event = LearningEvent.from_json(result[1])
                
                # 获取分发记录并标记处理中
                dispatch = await self.get_dispatch_record(
                    event.event_id, handler_name
                )
                if dispatch and dispatch.status == 'success':
                    continue  # 已处理过（幂等保护）
                
                await self.mark_dispatch_status(
                    event.event_id, handler_name, 'processing'
                )
                
                # 执行处理器
                handler = EventHandlerRegistry.get(handler_name)
                await handler().handle(event)
                
                # 标记成功
                await self.mark_dispatch_status(
                    event.event_id, handler_name, 'success'
                )
                
            except Exception as e:
                # 标记失败，安排重试
                await self.handle_failure(
                    event.event_id, handler_name, e
                )
    
    async def handle_failure(
        self, event_id: str, handler_name: str, error: Exception
    ):
        dispatch = await self.get_dispatch_record(event_id, handler_name)
        
        new_attempt = dispatch.attempt_count + 1
        
        if new_attempt >= dispatch.max_attempts:
            # 超过最大重试次数 → 进入死信
            await self.mark_dispatch_status(
                event_id, handler_name, 'dead_letter',
                error_code="MAX_RETRY_EXCEEDED",
                error_message=str(error)[:2000],
            )
            # 发送告警
            await self.alert_dead_letter(event_id, handler_name, error)
        else:
            # 指数退避重试：1min → 5min → 30min
            retry_delays = [60, 300, 1800]
            delay = retry_delays[min(new_attempt - 1, len(retry_delays) - 1)]
            
            await self.mark_dispatch_status(
                event_id, handler_name, 'failed',
                attempt_count=new_attempt,
                next_retry_at=datetime.now() + timedelta(seconds=delay),
                error_code=type(error).__name__,
                error_message=str(error)[:2000],
            )
            
            # 重新放入队列（延迟投递）
            await self.schedule_retry(event_id, handler_name, delay)
```

## 6. 幂等性设计

### 6.1 幂等键规范

每个处理器必须声明幂等键模板，确保同一事件重复消费不会产生副作用：

| 处理器 | 幂等键模板 | 说明 |
|--------|-----------|------|
| `mistake_check` | `mistake:{correlationId}:{answerRecordId}` | 同一答题记录只收录一次错题 |
| `mastery_update` | `mastery:{correlationId}:{knowledgePointId}` | 同一事件对同一知识点只更新一次 |
| `review_schedule` | `review:{correlationId}:{mistakeRecordId}` | 同一错题只生成一份复习计划 |
| `progress_update` | `progress:{correlationId}:{chapterId}` | 同一事件只更新一次进度 |
| `achievement_check` | `achv:{correlationId}:{achievementRuleId}` | 同一事件对同一成就规则只检查一次 |
| `analytics_aggregate` | `agg:{date}:{userId}:{subject}` | 聚合按天幂等 |
| `weakness_detect` | `weak:{correlationId}:{knowledgePointId}` | 同一事件只检测一次 |
| `notification_evaluate` | `notif:{date}:{userId}:{triggerType}` | 通知按天+触发类型幂等 |
| `plan_adjust` | `plan:{correlationId}:{planId}` | 同一事件只调整一次计划 |

### 6.2 幂等实现

```python
class IdempotentDecorator:
    """幂等装饰器：基于 Redis SETNX 实现分布式幂等"""
    
    def __init__(self, redis: Redis, ttl: int = 86400):
        self._redis = redis
        self._ttl = ttl  # 幂等键保留 24 小时
    
    def __call__(self, key: str):
        def decorator(func):
            @wraps(func)
            async def wrapper(*args, **kwargs):
                # 从参数中提取变量替换幂等键模板
                event = kwargs.get('event') or args[0]
                resolved_key = self._resolve_key(key, event)
                
                # SETNX 尝试获取锁
                acquired = await self._redis.set(
                    f"idempotent:{resolved_key}",
                    "1",
                    nx=True,
                    ex=self._ttl,
                )
                
                if not acquired:
                    logger.debug(
                        f"Idempotent skip: {resolved_key} already processed"
                    )
                    return None
                
                try:
                    return await func(*args, **kwargs)
                except Exception:
                    # 处理失败，删除幂等键允许重试
                    await self._redis.delete(f"idempotent:{resolved_key}")
                    raise
            
            return wrapper
        return decorator
    
    def _resolve_key(self, template: str, event: LearningEvent) -> str:
        """将模板变量替换为实际值"""
        replacements = {
            '{correlationId}': event.correlation_id,
            '{answerRecordId}': str(event.payload.get('answerRecordId', '')),
            '{knowledgePointId}': str(event.payload.get('knowledgePointId', '')),
            '{chapterId}': str(event.payload.get('chapterId', '')),
            '{mistakeRecordId}': str(event.payload.get('mistakeRecordId', '')),
            '{achievementRuleId}': str(event.payload.get('ruleId', '')),
            '{date}': event.event_time.strftime('%Y-%m-%d'),
            '{userId}': str(event.user_id),
            '{subject}': event.payload.get('subject', ''),
            '{planId}': str(event.payload.get('planId', '')),
            '{triggerType}': event.event_type,
        }
        result = template
        for placeholder, value in replacements.items():
            result = result.replace(placeholder, value)
        return result
```

### 7.2 部分失败处理原则

```python
class CascadeOrchestrator:
    """级联编排器：管理一个事件的所有下游分发"""
    
    async def dispatch(self, event: LearningEvent, routes: dict):
        """
        将事件分发到所有配置的通道和处理器。
        
        核心原则：
        1. 各通道独立，互不阻塞
        2. 单个处理器失败不影响其他处理器
        3. 失败的处理器进入重试队列
        4. 所有分发结果记录到 dispatch_record
        """
        results = {}
        
        for channel, handler_names in routes.items():
            for handler_name in handler_names:
                try:
                    # 为每个处理器创建分发记录
                    await self.create_dispatch_record(
                        event_id=event.event_id,
                        handler_name=handler_name,
                        channel=channel,
                    )
                    
                    # 投递到对应 Redis 队列
                    queue_key = f"evt:q:{channel}:{handler_name}"
                    await self.redis.lpush(
                        queue_key,
                        event.to_json(),
                    )
                    
                    results[handler_name] = 'dispatched'
                    
                except Exception as e:
                    # 投递失败 → 记录但不影响其他处理器
                    logger.error(
                        f"Dispatch failed: {event.event_id} → {handler_name}: {e}"
                    )
                    results[handler_name] = 'dispatch_failed'
                    
                    # 投递失败也写入 dispatch_record
                    # 补偿扫描会捡起重试
                    await self.create_dispatch_record(
                        event_id=event.event_id,
                        handler_name=handler_name,
                        channel=channel,
                        status='failed',
                        error_message=str(e)[:2000],
                    )
        
        # 更新事件分发状态
        all_ok = all(v == 'dispatched' for v in results.values())
        some_failed = any(v == 'dispatch_failed' for v in results.values())
        
        if all_ok:
            await self.mark_event_dispatched(event.event_id)
        elif some_failed:
            await self.mark_event_partial_failed(event.event_id)
```

```python
class EventThrottle:
    """事件流量控制：防止高峰期压垮下游服务"""
    
    # 每种事件类型的速率限制
    EVENT_RATE_LIMITS = {
        'answer.submit':       1000,  # 每秒最大处理量
        'ai.session.close':     500,
        'chapter.complete':     200,
        'session.end':          800,
        'review.complete':      300,
    }
    
    # 队列深度阈值
    QUEUE_DEPTH_THRESHOLDS = {
        'priority': {'warning': 1000, 'critical': 5000},
        'standard': {'warning': 5000, 'critical': 20000},
        'batch':    {'warning': 10000, 'critical': 50000},
    }
    
    async def check_and_throttle(self, event_type: str) -> ThrottleAction:
        """检查当前流量并返回控制动作"""
        limit = self.EVENT_RATE_LIMITS.get(event_type, 500)
        current_rate = await self._get_current_rate(event_type)
        
        if current_rate > limit * 1.5:
            # 严重超限 → 丢弃低优先级事件（batch 通道）
            return ThrottleAction.DROP_BATCH
        elif current_rate > limit:
            # 轻度超限 → 合并批量通道事件
            return ThrottleAction.MERGE_BATCH
        else:
            return ThrottleAction.PROCEED
```

```python
class EventArchiver:
    """事件数据归档：将过期事件迁移到 OSS 冷存储"""
    
    @celery.task(run_every=86400, run_at='04:00')
    async def archive_old_events(self):
        """归档 90 天前的事件到 OSS"""
        cutoff = datetime.now() - timedelta(days=90)
        
        while True:
            batch = await self.event_repo.find(
                created_before=cutoff,
                limit=10000,
            )
            if not batch:
                break
            
            # 写入 Parquet 文件并上传 OSS
            parquet_key = f"events/{cutoff.strftime('%Y-%m')}/events_{uuid4().hex[:8]}.parquet"
            await self.oss.upload_parquet(batch, parquet_key)
            
            # 从 MySQL 删除已归档数据
            event_ids = [e.event_id for e in batch]
            await self.event_repo.bulk_delete(event_ids)
            await self.dispatch_repo.bulk_delete_by_event_ids(event_ids)
            
            logger.info(f"Archived {len(batch)} events to {parquet_key}")
```

```python
@celery.task(run_every=86400, run_at='05:00')
async def cleanup_idempotent_keys(self):
    """清理过期的幂等键"""
    # Redis 幂等键本身设置了 TTL（24小时），无需主动清理
    # 但检查是否有大量键未正确设置 TTL
    keys = await self.redis.keys('idempotent:*')
    if len(keys) > 100000:
        logger.warning(f"Too many idempotent keys: {len(keys)}")
        # 检查 TTL 并为无 TTL 的键补设
        for key in keys:
            ttl = await self.redis.ttl(key)
            if ttl == -1:  # 无过期时间
                await self.redis.expire(key, 86400)
```

```python
class SomeBusinessService:
    
    async def do_something(self, user_id: int, ...):
        # 1. 执行业务逻辑（在事务内）
        async with self.db.transaction() as tx:
            result = await self._do_business_logic(tx, ...)
            
            # 2. 在同一事务内写入事件（Outbox 模式）
            #    保证业务操作和事件写入的原子性

                event_id=f"evt_{ulid()}",

                event_time=datetime.now(),
                source="some-service",
                correlation_id=ulid(),
                user_id=user_id,
                payload={...},
            )
            await self.event_outbox_repo.create(tx, event)
        
        # 3. 事务提交后，异步投递到 Redis
        #    由 OutboxRelay 定时扫描未投递事件
        await self.event_bus.publish_event(event)
        
        return result
```

```python
class OutboxRelay:
    """Outbox 中继：扫描未发布事件并投递到 Redis"""
    
    @celery.task(run_every=5)  # 每 5 秒扫描一次
    async def relay_pending(self):
        pending = await self.outbox_repo.find(
            status='pending',
            created_before=datetime.now() - timedelta(seconds=5),
            limit=500,
        )
        
        for outbox_event in pending:
            try:
                event = LearningEvent.from_outbox(outbox_event)
                await self.event_bus.publish_event(event)
                await self.outbox_repo.mark_published(outbox_event.id)
            except Exception as e:
                logger.error(f"Outbox relay failed for {outbox_event.event_id}: {e}")
                await self.outbox_repo.mark_failed(outbox_event.id, str(e))
```
