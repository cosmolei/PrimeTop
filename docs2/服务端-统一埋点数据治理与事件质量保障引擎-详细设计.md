# 服务端-统一埋点数据治理与事件质量保障引擎 详细设计

## 1. 概述

### 1.1 功能定位

统一埋点数据治理与事件质量保障引擎是 PrimeTop 平台数据基础设施的核心守护层。它不负责"采集什么"和"怎么采集"（由客户端埋点 SDK 和服务端事件管线负责），而是专注于**保障已采集埋点数据的可信度**——确保下游分析、BI 报表、机器学习模型消费到的是准确、完整、一致的数据。

### 1.2 问题背景

| 问题类型 | 典型表现 | 业务影响 |
| --- | --- | --- |
| 事件丢失 | 客户端弱网导致事件未上报 | 活跃用户被低估、漏斗转化率失真 |
| 字段缺失 | 新版本事件缺少 `grade` 字段 | 学段分布报表无法出数 |
| Schema 漂移 | 客户端发送 `page_name`，服务端期望 `page_key` | 下游 ETL 解析失败 |
| 重复事件 | 用户刷新页面触发重复 `page_view` | PV 指标虚高 |
| 类型错误 | `duration_ms` 传成字符串 `"1234"` | 聚合计算报错或静默截断 |
| 时序错乱 | 事件到达顺序与发生顺序不一致 | 会话重建失败 |
| 僵尸事件 | 已废弃事件仍被客户端发送 | 无效数据占用存储和计算资源 |
| 时区偏差 | 不同时区客户端时间戳不统一 | 日活统计跨天错位 |

### 1.3 设计目标

1. **实时感知**：数据质量问题在 5 分钟内被发现并告警
2. **自动修复**：可自动修复的问题（如类型转换、字段补全）在入口处自动处理
3. **不可修复阻断**：严重质量问题的事件被拦截，不进入下游
4. **全链路可追溯**：每条事件的质检结果可追溯，质检规则版本化
5. **零代码侵入**：质检规则通过配置管理，不修改业务代码
6. **SLA 量化**：数据质量以评分形式量化，驱动团队改进

### 1.4 适用范围

| 范围 | 说明 |
| --- | --- |
| 数据来源 | 客户端埋点 SDK（APP / Web / 小程序）、服务端业务事件、第三方回传事件 |
| 数据去向 | 数据仓库、实时分析引擎、BI 看板、机器学习特征存储 |
| 团队角色 | 数据工程师（规则配置）、数据分析师（质量监控）、后端开发（SDK 对接） |

### 4.2 事件指纹去重设计

#### 4.2.1 指纹计算规则

```java
/**
 * 事件指纹计算
 * 
 * 策略：将事件的关键标识字段拼接后做 SHA-256 摘要
 * 不同事件类型使用不同字段组合
 */
public class EventFingerprinter {

    // 每种事件类型的指纹字段配置
    private static final Map<String, List<String>> FINGERPRINT_FIELDS = Map.of(
        "page_view",        List.of("event_id", "device_id"),
        "question_answered", List.of("event_id", "session_id", "question_id"),
        "ai_conversation",   List.of("event_id", "session_id", "turn_index"),
        "default",           List.of("event_id", "device_id")
    );

    public String fingerprint(JsonNode eventPayload, String eventKey) {
        List<String> fields = FINGERPRINT_FIELDS.getOrDefault(
            eventKey, FINGERPRINT_FIELDS.get("default")
        );
        
        String fingerprintInput = fields.stream()
            .map(field -> eventPayload.path(field).asText(""))
            .collect(Collectors.joining("|"));
        
        return DigestUtils.sha256Hex(fingerprintInput);
    }
}
```

#### 4.2.2 去重存储策略

| 存储 | 用途 | TTL | 说明 |
| --- | --- | --- | --- |
| Redis Bloom Filter | 第一层快速过滤 | 2h | 容量 1亿，误判率 0.1% |
| Redis SET | 第二层精确判断 | 1h | 仅 Bloom 命中时查 SET |

```python
# 伪代码：双层去重
def is_duplicate(fingerprint: str) -> bool:
    # 第一层：Bloom Filter（可能有假阳性）
    if not bloom_filter.contains(fingerprint):
        bloom_filter.add(fingerprint)
        return False  # 确定不是重复
    
    # 第二层：精确 SET 查询
    if redis_set.sismember("dedup:events", fingerprint):
        return True  # 确定是重复
    
    # Bloom 命中但 SET 未命中 = 假阳性
    redis_set.sadd("dedup:events", fingerprint)
    redis_set.expire("dedup:events", 3600)
    return False
```

#### 4.3.2 Schema 兼容性策略

| 策略 | 含义 | 适用场景 |
| --- | --- | --- |
| BACKWARD | 新 Schema 能读旧数据（可以删字段、加可选字段） | 绝大多数事件默认策略 |
| FORWARD | 旧 Schema 能读新数据（可以加字段、删可选字段） | 客户端无法立即升级时 |
| FULL | 同时满足 BACKWARD 和 FORWARD | 关键业务事件 |
| NONE | 无兼容性保证 | 实验性事件 |

```java
/**
 * Schema 兼容性检查器
 * 在 Schema 注册时自动检查与上一版本的兼容性
 */
public class SchemaCompatibilityChecker {

    /**
     * 检查新 Schema 是否与旧版本兼容
     */
    public CompatibilityResult check(
            JSONObject newSchema, 
            JSONObject oldSchema, 
            CompatibilityLevel level) {
        
        List<String> errors = new ArrayList<>();
        List<String> warnings = new ArrayList<>();
        
        JSONObject newRequired = newSchema.optJSONArray("required", new JSONArray());
        JSONObject oldRequired = oldSchema.optJSONArray("required", new JSONArray());
        JSONObject newProps = newSchema.optJSONObject("properties", new JSONObject());
        JSONObject oldProps = oldSchema.optJSONObject("properties", new JSONObject());
        
        // BACKWARD: 新版本不能新增必填字段（旧数据没有这个字段）
        if (level == BACKWARD || level == FULL) {
            for (String field : getRequiredFields(newRequired)) {
                if (!oldProps.has(field) && !oldRequired.asList().contains(field)) {
                    // 新增的必填字段检查旧版本中是否存在
                    if (!oldProps.has(field)) {
                        errors.add(String.format(
                            "BACKWARD违规: 新增必填字段 '%s' 在旧版本中不存在，旧数据将无法通过校验", field));
                    }
                }
            }
        }
        
        // FORWARD: 不能删除旧版本中的必填字段（新数据没有旧消费者期望的字段）
        if (level == FORWARD || level == FULL) {
            for (String field : getRequiredFields(oldRequired)) {
                if (!newProps.has(field)) {
                    errors.add(String.format(
                        "FORWARD违规: 删除了必填字段 '%s'，旧消费者将无法解析新数据", field));
                }
            }
        }
        
        // 检查字段类型变更
        for (String field : getFieldNames(newProps)) {
            if (oldProps.has(field)) {
                String newType = getFieldType(newProps.getJSONObject(field));
                String oldType = getFieldType(oldProps.getJSONObject(field));
                if (!isTypeCompatible(oldType, newType, level)) {
                    errors.add(String.format(
                        "类型变更违规: 字段 '%s' 从 '%s' 变为 '%s'", field, oldType, newType));
                }
            }
        }
        
        // 检查枚举值变更
        for (String field : getFieldNames(newProps)) {
            if (oldProps.has(field)) {
                List<String> warnings_ = checkEnumCompatibility(
                    field, newProps.getJSONObject(field), oldProps.getJSONObject(field));
                warnings.addAll(warnings_);
            }
        }
        
        return new CompatibilityResult(errors.isEmpty(), errors, warnings);
    }
}
```

### 4.4 自动修复引擎 (AutoFixer)

#### 4.4.1 可自动修复的问题分类

| 问题类型 | 修复策略 | 示例 |
| --- | --- | --- |
| 类型转换 | 安全类型转换 | `"1234"` → `1234`（字符串数字转整型） |
| 默认值填充 | 用配置的默认值填充 | `grade` 为空 → 用用户档案中的当前年级 |

#### 4.4.3 自动修复执行器

```python
class AutoFixer:
    """事件自动修复引擎"""
    
    def __init__(self, rules_config: dict, user_profile_service: UserProfileService):
        self.rules = self._parse_rules(rules_config)
        self.profile_service = user_profile_service
    
    def try_fix(self, event: dict, event_key: str, 
                violations: list[Violation]) -> FixResult:
        """
        尝试修复事件中已知问题
        
        Returns:
            FixResult: 包含修复后的事件、执行了哪些修复、是否仍有不可修复问题
        """
        fixed_event = copy.deepcopy(event)
        applied_fixes = []
        remaining_violations = []
        
        for violation in violations:
            fix_rule = self._find_fix_rule(violation, event_key)
            if fix_rule is None:
                remaining_violations.append(violation)
                continue
            
            try:
                old_value = jsonpath_get(fixed_event, violation.field_path)
                new_value = self._apply_fix(fix_rule, fixed_event, violation)
                
                if new_value is not None:
                    jsonpath_set(fixed_event, violation.field_path, new_value)
                    applied_fixes.append(FixRecord(
                        field=violation.field_path,
                        action=fix_rule.action.type,
                        old_value=old_value,
                        new_value=new_value,
                        rule_code=fix_rule.rule_code
                    ))
                else:
                    applied_fixes.append(FixRecord(
                        field=violation.field_path,
                        action=fix_rule.action.type,
                        old_value=old_value,
                        new_value="(removed)",
                        rule_code=fix_rule.rule_code
                    ))
            except Exception as e:
                logger.warning(f"AutoFix failed for {violation}: {e}")
                remaining_violations.append(violation)
        
        success = len(remaining_violations) == 0
        return FixResult(
            fixed_event=fixed_event,
            applied_fixes=applied_fixes,
            remaining_violations=remaining_violations,
            success=success
        )
    
    def _apply_fix(self, rule: FixRule, event: dict, 
                   violation: Violation):
        action = rule.action
        
        if action.type == "CAST":
            return self._safe_cast(
                jsonpath_get(event, violation.field_path),
                action.target_type
            )
        
        elif action.type == "DEFAULT_FROM_PROFILE":
            user_id = event.get("user_id")
            if user_id and action.profile_field:
                profile = self.profile_service.get_profile(user_id)
                return getattr(profile, action.profile_field, action.fallback)
            return action.fallback
        
        elif action.type == "MAP":
            current = jsonpath_get(event, violation.field_path)
            return action.mapping.get(current, current)
        
        elif action.type == "MULTIPLY":
            current = jsonpath_get(event, violation.field_path)
            return int(current * action.factor) if current else None
        
        elif action.type == "RENAME":
            old_val = jsonpath_get(event, violation.field_path)
            if old_val is not None:
                jsonpath_delete(event, violation.field_path)
                jsonpath_set(event, f"$.{action.to}", old_val)
            return None  # 返回None表示已通过副作用处理
        
        return None
    
    @staticmethod
    def _safe_cast(value, target_type: str):
        """安全类型转换，失败返回原值"""
        try:
            if target_type == "integer":
                return int(float(value)) if isinstance(value, str) else int(value)
            elif target_type == "float":
                return float(value)
            elif target_type == "string":
                return str(value)
            elif target_type == "boolean":
                if isinstance(value, str):
                    return value.lower() in ("true", "1", "yes")
                return bool(value)
        except (ValueError, TypeError):
            return value
        return value
```

### 4.5 质量评分模型

#### 4.5.1 评分算法

采用**加权扣分制**，初始分 100，根据违反的规则严重程度扣分：

```java
/**
 * 事件质量评分器
 */
public class QualityScorer {
    
    // 严重程度对应的扣分权重
    private static final Map<Severity, Integer> SEVERITY_DEDUCTION = Map.of(
        Severity.BLOCKER,   100,  // 直接拦截
        Severity.CRITICAL,   40,
        Severity.MAJOR,      20,
        Severity.MINOR,       8,
        Severity.WARNING,     3
    );
    
    // 数据质量维度权重（用于维度评分）
    private static final Map<QualityDimension, Double> DIMENSION_WEIGHTS = Map.of(
        QualityDimension.COMPLETENESS, 0.30,  // 完整性权重最高
        QualityDimension.CONFORMITY,   0.25,  // 规范性
        QualityDimension.CONSISTENCY,  0.20,  // 一致性
        QualityDimension.TIMELINESS,   0.15,  // 时效性
        QualityDimension.ACCURACY,     0.10   // 准确性
    );
    
    /**
     * 计算事件质量评分
     * @param violations 违反的规则列表
     * @return 质量评分 0-100
     */
    public QualityScore score(List<RuleViolation> violations) {
        if (violations.isEmpty()) {
            return QualityScore.perfect();
        }
        
        int totalScore = 100;
        Map<QualityDimension, Integer> dimensionDeductions = new EnumMap<>(QualityDimension.class);
        
        for (RuleViolation v : violations) {
            int deduction = SEVERITY_DEDUCTION.get(v.getSeverity());
            totalScore -= deduction;
            
            // 按维度累计扣分
            dimensionDeductions.merge(
                v.getDimension(), 
                deduction, 
                Integer::sum
            );
        }
        
        totalScore = Math.max(0, totalScore);
        
        // 计算各维度得分
        Map<QualityDimension, Double> dimensionScores = new EnumMap<>(QualityDimension.class);
        for (QualityDimension dim : QualityDimension.values()) {
            int deduction = dimensionDeductions.getOrDefault(dim, 0);
            double weightedScore = Math.max(0, 100.0 - deduction) * DIMENSION_WEIGHTS.get(dim);
            dimensionScores.put(dim, weightedScore);
        }
        
        return new QualityScore(totalScore, dimensionScores, violations);
    }
    
    /**
     * 根据评分决定处理策略
     */
    public CheckAction decideAction(QualityScore score) {
        if (score.getOverall() >= 80) {
            return CheckAction.PASS;
        } else if (score.getOverall() >= 50) {
            return CheckAction.TRY_FIX;  // 尝试自动修复
        } else {
            return CheckAction.REJECT;
        }
    }
}
```

class QualityMetricsAggregator:
    """

    输出到 Prometheus + ClickHouse
    """
    
    # 定义计算指标
    METRICS = {

        "events_passed":        CounterMetric("events_passed_total", "通过事件数", ["event_key"]),

        "events_rejected":      CounterMetric("events_rejected_total", "拦截事件数", ["event_key"]),

        "pass_rate":            GaugeMetric("events_pass_rate", "通过率%", ["event_key"]),

        "avg_quality_score":    GaugeMetric("events_avg_quality_score", "平均质量评分", ["event_key"]),

        "completeness_rate":    GaugeMetric("events_completeness_rate", "完整性率%", ["event_key"]),
        "conformity_rate":      GaugeMetric("events_conformity_rate", "规范性率%", ["event_key"]),
        
        # 规则维度
        "top_violated_rules":   TopNMetric("top_violated_rules", "Top违反规则", n=10),
        
        # 客户端版本维度
        "quality_by_version":   GaugeMetric(
            "events_quality_by_app_version", "按版本质量评分", ["event_key", "app_version"]
        ),
    }
    
    def process_window(self, events: list[EventQualityLog], window_end: datetime):
        """处理一个窗口内的事件"""
        event_key = events[0].event_key
        
        total = len(events)
        passed = sum(1 for e in events if e.check_result == "PASS")
        fixed = sum(1 for e in events if e.check_result == "FIXED")
        rejected = sum(1 for e in events if e.check_result == "REJECTED")
        
        avg_score = sum(e.quality_score for e in events) / total
        
        # 计算维度得分
        completeness_violations = sum(
            1 for e in events 
            for r in (e.violated_rules or [])
            if self._get_rule_dimension(r) == "COMPLETENESS"
        )
        completeness_rate = (1 - completeness_violations / total) * 100
        
        # 输出指标
        self.METRICS["events_total"].inc(total, labels={"event_key": event_key})
        self.METRICS["pass_rate"].set(passed / total * 100, labels={"event_key": event_key})
        self.METRICS["reject_rate"].set(rejected / total * 100, labels={"event_key": event_key})
        self.METRICS["avg_quality_score"].set(avg_score, labels={"event_key": event_key})
        self.METRICS["completeness_rate"].set(completeness_rate, labels={"event_key": event_key})

## 8. 僵尸事件检测与清理

### 8.1 检测策略

系统自动识别"还在上报但应该已废弃"的事件。

```python
class ZombieEventDetector:
    """僵尸事件检测器"""
    
    def detect_zombies(self, lookback_days: int = 30) -> list[ZombieEventReport]:
        """
        检测条件（满足全部）:
        1. 事件 Schema 状态为 DEPRECATED
        2. 最近 7 天仍有上报数据
        3. 上报量 < 历史日均的 5%（少量残留）
        """
        deprecated_events = self.schema_registry.list_events(status="DEPRECATED")
        zombies = []
        
        for event in deprecated_events:
            recent_stats = self.get_event_stats(
                event_key=event.event_key,
                start=datetime.now() - timedelta(days=7),
                end=datetime.now()
            )
            
            if recent_stats.total_count > 0:
                # 找出还在发送这些事件的客户端版本
                active_versions = self.get_active_client_versions(event.event_key)
                
                zombies.append(ZombieEventReport(
                    event_key=event.event_key,
                    deprecated_date=event.deprecated_at,
                    recent_count=recent_stats.total_count,
                    active_client_versions=active_versions,
                    recommendation=self._generate_recommendation(
                        event, recent_stats, active_versions
                    )
                ))
        
        return zombies
    
    def _generate_recommendation(self, event, stats, versions):
        if stats.total_count < 10:
            return f"残留量极低({stats.total_count}条/周)，建议直接忽略，将在版本升级后自然消失"
        elif any(v.startswith("v1.") for v in versions):
            return f"主要来自旧版本 {versions}，建议推动用户升级客户端"
        else:
            return f"当前版本仍在发送，需检查客户端埋点代码并提交修复"
```

### 8.2 清理流程

1. **检测**：每周自动执行僵尸事件检测
2. **通知**：检测结果通过邮件/企微通知相关团队
3. **宽限期**：DEPRECATED 状态保留 90 天
4. **退役**：90 天后状态改为 `RETIRED`，事件被入口直接拦截
5. **清理**：RETIRED 后 180 天，历史数据从热存储迁移到冷存储

### 9.2 与客户端埋点 SDK 的集成

客户端 SDK 在初始化时从服务端拉取最新 Schema 快照，在本地做轻量级预校验：

```typescript
// 客户端 SDK 集成示例 (TypeScript)
class TrackingSDK {
  private schemaCache: Map<string, EventSchema>;
  
  async initialize(): Promise<void> {
    // 拉取当前生效的所有事件 Schema
    const schemas = await api.get('/api/v1/dq/schemas/bundle');
    this.schemaCache = new Map(
      schemas.map(s => [s.event_key, s])
    );
  }
  
  track(eventKey: string, payload: Record<string, any>): void {
    const schema = this.schemaCache.get(eventKey);
    
    if (!schema) {
      // 未知事件：开发环境警告，生产环境仍然发送（由服务端拦截）
      if (__DEV__) {
        console.warn(`[Tracking] 未注册的事件类型: ${eventKey}`);
      }
      this._send(eventKey, payload);
      return;
    }
    
    // 本地预校验
    const validationResult = validate(payload, schema.schema_json);
    if (!validationResult.valid) {
      if (__DEV__) {
        console.error(`[Tracking] 事件 ${eventKey} 校验失败:`, validationResult.errors);
      }
      // 生产环境：仍然发送，服务端会做进一步处理
      // 但加上 _validation_hints 字段帮助服务端诊断
      payload._validation_hints = {
        client_errors: validationResult.errors.map(e => ({
          field: e.path,
          message: e.message
        })),
        client_schema_version: schema.current_version
      };
    }
    
    this._send(eventKey, payload);
  }
}
```

### 15.1 常用数据质量规则模板

| 规则编码 | 规则名称 | 类型 | 表达式 | 严重程度 |
| --- | --- | --- | --- | --- |
| R001 | user_id 非空 | COMPLETENESS | `$.user_id != null` | CRITICAL |

| R003 | app_version 格式 | CONFORMITY | `$.app_version =~ /^\d+\.\d+\.\d+/` | MINOR |
| R004 | subject 合法枚举 | ACCURACY | `$.subject in ["chinese","math","english",...]` | MAJOR |
| R005 | event_id 格式 | CONFORMITY | `$.event_id =~ /^[0-9a-f-]{36}$/` | MINOR |
| R006 | duration 非负 | ACCURACY | `$.duration_ms >= 0` | MAJOR |
| R007 | grade 范围 | ACCURACY | `$.grade == null \|\| ($.grade >= 1 && $.grade <= 12)` | MINOR |
| R008 | duration 上限 | ACCURACY | `$.duration_ms <= 3600000` | MAJOR |

### 15.2 术语表

| 术语 | 说明 |
| --- | --- |
| Schema Registry | 事件结构定义的注册中心，管理事件 Schema 的版本和兼容性 |
| DLQ (Dead Letter Queue) | 死信队列，存放被拦截或处理失败的事件 |
| AutoFixer | 自动修复引擎，对已知可修复问题进行自动纠正 |
| Quality Score | 质量评分，0-100 分量化事件数据质量 |
| Zombie Event | 僵尸事件，已废弃但仍有上报的事件 |
| Schema Drift | Schema 漂移，实际数据结构与注册 Schema 不一致 |
| Completeness Rate | 完整性率，必需字段非空的比例 |
| Conformity Rate | 规范性率，字段类型和格式符合 Schema 的比例 |
