# 服务端 - 家长学习辅导建议生成与家庭教育内容推荐引擎

> **文档版本**: v1.0
> **最后更新**: 2026-06-14
> **负责模块**: parent-guidance-service
> **依赖模块**: 学情分析服务、学习画像服务、消息推送服务、内容服务、用户服务

---

## 1. 模块概述

### 1.1 功能目标

为家长提供 AI 驱动的个性化学习辅导建议和家庭教育内容推荐。系统持续分析孩子的学习行为、薄弱知识点、学习习惯和心理状态数据，自动生成可执行的辅导建议（如"本周数学函数掌握度偏低，建议周末花30分钟复习"），并推送匹配的家庭教育文章、亲子互动活动和沟通技巧内容。

### 1.2 核心价值

| 价值维度 | 说明 |
|---------|------|
| **可执行性** | 不止报数据，还告诉家长"该做什么、怎么做" |
| **适龄适配** | 根据孩子学段（幼儿/小学/初中/高中）调整建议深度和沟通方式 |
| **及时性** | 基于实时学习数据变化触发，而非固定模板 |
| **隐私安全** | 建议内容不暴露敏感数据细节，家长端仅展示指导性文字 |

### 1.3 用户场景

```
场景1: 小学生家长
  孩子本周数学「分数运算」知识点连续答错3题
  → 系统生成建议："孩子本周在分数运算遇到困难，建议您抽出15分钟，
    一起用切苹果的方式理解分数概念。这里有一篇《如何用生活场景教分数》
    的文章供您参考。"

场景2: 初中生家长
  孩子最近一周学习时长下降40%，AI对话中多次出现"好累"等情绪词
  → 系统生成建议："孩子近期学习强度较高，建议适当调整作息。
    可考虑安排一次轻松的户外活动。以下是《如何帮初中生减压》
    的家庭教育指南。"

场景3: 高中生家长
  孩子月考数学成绩提升，但英语阅读理解持续薄弱
  → 系统生成建议："孩子数学进步明显，建议给予肯定。同时英语阅读
    理解正确率连续两周低于60%，建议鼓励孩子每天阅读一篇英语短文。"
```

### 1.4 系统边界

```
本模块负责                          不负责
─────────────                      ─────────────
✅ 辅导建议内容生成                  ❌ 学情数据采集（学情分析服务负责）
✅ 家庭教育内容匹配推荐              ❌ 消息推送投递（消息推送服务负责）
✅ 建议生成策略与规则编排            ❌ 家长端UI渲染（客户端负责）
✅ 建议效果追踪（家长是否采纳）      ❌ 家长账号管理（用户服务负责）
✅ 教育内容库管理（后台运营）        ❌ 课程内容生产（内容服务负责）
```

### 3.1 数据库表设计

#### 3.1.1 parent_guidance_record（家长辅导建议记录表）

```sql
CREATE TABLE parent_guidance_record (
    id              BIGSERIAL PRIMARY KEY,
    record_id       VARCHAR(36) NOT NULL UNIQUE,      -- UUID，建议记录唯一标识
    parent_user_id  BIGINT NOT NULL,                   -- 家长用户ID
    student_user_id BIGINT NOT NULL,                   -- 学生用户ID
    trigger_type    VARCHAR(20) NOT NULL,              -- 触发类型: SCHEDULED/EVENT/MANUAL/ON_DEMAND
    trigger_ref     VARCHAR(255),                      -- 触发来源引用（事件ID/定时任务批次号）
    
    -- 建议内容
    title           VARCHAR(100) NOT NULL,             -- 建议标题
    summary         VARCHAR(500) NOT NULL,             -- 建议摘要（一句话）
    body            TEXT NOT NULL,                     -- 建议正文（富文本/Markdown）
    priority        SMALLINT NOT NULL DEFAULT 50,      -- 优先级: 10(紧急)/30(重要)/50(普通)/70(低)
    category        VARCHAR(30) NOT NULL,              -- 分类: ACADEMIC/HABIT/EMOTION/STRATEGY/MOTIVATION
    
    -- 关联数据
    related_subject VARCHAR(20),                       -- 关联学科
    related_kp_ids  JSONB,                             -- 关联知识点ID列表
    related_content_ids JSONB,                          -- 关联教育内容ID列表
    
    -- AI生成元信息
    ai_generated    BOOLEAN NOT NULL DEFAULT FALSE,    -- 是否经过AI增强
    ai_model        VARCHAR(50),                       -- 使用的AI模型
    ai_prompt_hash  VARCHAR(64),                       -- Prompt模板哈希（追溯）
    
    -- 状态管理
    status          VARCHAR(20) NOT NULL DEFAULT 'PENDING', -- PENDING/DELIVERED/READ/ACTED/DISMISSED/EXPIRED
    delivered_at    TIMESTAMPTZ,                       -- 送达时间
    read_at         TIMESTAMPTZ,                       -- 阅读时间
    acted_at        TIMESTAMPTZ,                       -- 家长采取行动时间
    dismissed_at    TIMESTAMPTZ,                       -- 家长忽略时间
    expired_at      TIMESTAMPTZ,                       -- 过期时间
    
    -- 反馈
    parent_feedback VARCHAR(20),                       -- 家长反馈: HELPFUL/NOT_HELPFUL/TOO_GENERIC
    feedback_detail TEXT,                              -- 反馈详情
    
    -- 时间戳
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    -- 索引
    CONSTRAINT idx_pgr_parent_student UNIQUE (parent_user_id, student_user_id, created_at),
    CONSTRAINT chk_trigger_type CHECK (trigger_type IN ('SCHEDULED', 'EVENT', 'MANUAL', 'ON_DEMAND')),
    CONSTRAINT chk_priority CHECK (priority BETWEEN 1 AND 99),
    CONSTRAINT chk_category CHECK (category IN ('ACADEMIC', 'HABIT', 'EMOTION', 'STRATEGY', 'MOTIVATION')),
    CONSTRAINT chk_status CHECK (status IN ('PENDING', 'DELIVERED', 'READ', 'ACTED', 'DISMISSED', 'EXPIRED'))
);

CREATE INDEX idx_pgr_student ON parent_guidance_record(student_user_id, created_at DESC);
CREATE INDEX idx_pgr_parent_status ON parent_guidance_record(parent_user_id, status, created_at DESC);
CREATE INDEX idx_pgr_trigger ON parent_guidance_record(trigger_type, created_at DESC);
CREATE INDEX idx_pgr_category ON parent_guidance_record(category, priority);
```

### 3.2 条件表达式规则 DSL

策略的 `condition_expr` 字段使用 JSON 规则 DSL，支持多条件组合：

```jsonc
// 示例：薄弱知识点连续错误策略
{
  "logic": "AND",
  "conditions": [
    {
      "type": "KP_MASTERY",
      "params": {
        "operator": "<=",
        "value": 0.4,
        "window_days": 7,
        "min_questions": 3
      }
    },
    {
      "type": "STAGE_IN",
      "params": {
        "values": ["PRIMARY", "JUNIOR", "SENIOR"]
      }
    }
  ]
}
```

**支持的条件下类型（condition type）**:

| type | 说明 | 关键参数 |
|------|------|---------|
| `KP_MASTERY` | 知识点掌握度 | `operator`, `value`, `window_days`, `min_questions` |
| `STUDY_TIME_TREND` | 学习时长趋势 | `trend`(`UP`/`DOWN`), `change_pct`, `window_days` |
| `ERROR_RATE` | 错误率 | `operator`, `value`, `subject`, `window_days` |
| `EMOTION_SIGNAL` | 情绪信号 | `signals`: [`FRUSTRATED`, `TIRED`, `ANXIOUS`, `CONFIDENT`], `window_days` |
| `STAGE_IN` | 学段匹配 | `values`: 学段列表 |
| `STUDY_PLAN_COMPLETION` | 计划完成率 | `operator`, `value`, `window_days` |
| `ACTIVE_DAYS_DROP` | 活跃天数下降 | `drop_pct`, `window_days` |
| `SUBJECT_PERFORMANCE` | 单科成绩波动 | `subject`, `operator`, `value`, `window_days` |
| `PLAN_OVERDUE` | 计划逾期 | `overdue_task_count`, `window_days` |
| `MISTAKE_REVIEW_LAG` | 错题复习滞后 | `lag_days`, `pending_count` |
| `POSITIVE_FEEDBACK` | 正向激励窗口 | `streak_days`, `subject` |

## 5. 状态流转

### 5.1 建议记录生命周期

```text
[PENDING] ──(推送成功)──► [DELIVERED] ──(家长打开)──► [READ]
    │                          │
    │                          └──(家长标记已做)──► [ACTED]
    │                          │
    │                          └──(家长忽略/左滑)──► [DISMISSED]
    │
    └──(到达过期时间)──► [EXPIRED]
    │
    └──(生成前被策略冷却/频控拦截)──► 不创建记录
```

**状态说明**

| 状态 | 说明 | 允许的外部操作 |
|------|------|---------------|
| `PENDING` | 已生成，待投递 | 无 |
| `DELIVERED` | 已通过消息通道/站内信送达 | feedback, action, read |
| `READ` | 家长已阅读 | feedback, action |
| `ACTED` | 家长已采取行动 | feedback |
| `DISMISSED` | 家长忽略 | 无 |
| `EXPIRED` | 超过 7 天有效期 | 无 |

### 5.2 状态迁移守卫规则

```
G1: PENDING → DELIVERED 仅允许由内部投递任务触发，需幂等
G2: DELIVERED → READ 由家长打开详情触发，同一记录只计一次
G3: DELIVERED → ACTED 由 action 接口触发，需携带 action_type
G4: DELIVERED → DISMISSED 由 dismiss 接口触发，冷却 24h 内同一策略不重复生成
G5: 任何终态（ACTED/DISMISSED/EXPIRED）不可回退
G6: EXPIRED 由定时任务在每日 00:00 UTC+8 扫描，仅对创建超过 7 天的 PENDING/DELIVERED 生效
G7: 家长反馈（feedback）仅可在 READ/ACTED/DELIVERED 状态下提交
```

### 5.3 策略状态机

```text
DRAFT ──(审核通过)──► ENABLED ──(运营关闭)──► DISABLED
                         │
                         └──(触发条件临时禁用)──► PAUSED
```

## 6. 关键代码示例

### 6.1 策略规则引擎（Java）

```java
@Component
public class GuidanceRuleEngine {

    private final ObjectMapper objectMapper;
    private final LearningDataClient learningDataClient;

    public List<MatchedStrategy> evaluate(long studentUserId, GuidanceContext ctx) {
        List<GuidanceStrategy> strategies = loadEnabledStrategies(ctx.getStage());
        StudentSnapshot snapshot = learningDataClient.getSnapshot(studentUserId);

        return strategies.stream()
            .filter(s -> stageMatch(s, ctx.getStage()))
            .filter(s -> cooldownPassed(studentUserId, s.getStrategyCode()))
            .filter(s -> evaluateCondition(s.getConditionExpr(), snapshot))
            .sorted(Comparator.comparingInt(GuidanceStrategy::getPriority))
            .collect(Collectors.toList());
    }

    private boolean evaluateCondition(JsonNode expr, StudentSnapshot snapshot) {
        String logic = expr.path("logic").asText("AND");
        List<JsonNode> conditions = objectMapper.convertValue(
            expr.path("conditions"), new TypeReference<>() {}
        );

        for (JsonNode c : conditions) {
            boolean r = ConditionEvaluatorFactory.get(c.path("type").asText())
                        .evaluate(c.path("params"), snapshot);
            if ("AND".equals(logic) && !r) return false;
            if ("OR".equals(logic) && r) return true;
        }
        return "AND".equals(logic);
    }
}
```

### 6.2 冷却检查（Redis + Lua）

```java
@Component
public class GuidanceCooldownChecker {

    private static final String LUA = """
        local key = KEYS[1]
        local maxWeek = tonumber(ARGV[1])
        local cooldownSec = tonumber(ARGV[2])
        local now = tonumber(ARGV[3])
        local weekKey = ARGV[4]

        local last = redis.call('HGET', key, 'last_triggered')
        local weekCount = redis.call('HGET', key, 'count_' .. weekKey)

        if last and (now - tonumber(last)) < cooldownSec then
            return {0, 'COOLDOWN'}
        end
        if weekCount and tonumber(weekCount) >= maxWeek then
            return {0, 'WEEK_LIMIT'}
        end

        redis.call('HSET', key, 'last_triggered', now)
        redis.call('HINCRBY', key, 'count_' .. weekKey, 1)
        redis.call('EXPIRE', key, 604800)
        return {1, 'OK'}
        """;

    public CooldownResult check(String strategyCode, long studentUserId,
                                 int cooldownHours, int maxPerWeek, String weekKey) {
        String key = String.format("guidance:cooldown:%d:%s", studentUserId, strategyCode);
        long now = System.currentTimeMillis() / 1000;
        return (CooldownResult) redisTemplate.execute(
            new DefaultRedisScript<>(LUA, CooldownResult.class),
            List.of(key), maxPerWeek, cooldownHours * 3600L, now, weekKey
        );
    }
}
```

```java
@Service
public class ContentMatcher {

    public List<FamilyEducationContent> match(GuidanceStrategy strategy, StudentSnapshot snapshot) {
        // 1. 规则过滤：学段 + 分类 + 标签
        List<FamilyEducationContent> candidates = contentRepository
            .findByCategoryAndStageAndTags(
                strategy.getCategory(),
                snapshot.getStage(),
                strategy.getContentTags()
            );

        // 2. 语义相似度排序
        float[] queryVector = embeddingClient.encode(buildQueryText(strategy, snapshot));
        return candidates.stream()
            .map(c -> new ScoredContent(c, cosineSimilarity(queryVector, c.getEmbedding())))
            .filter(sc -> sc.score > 0.65)
            .sorted(Comparator.comparingDouble(ScoredContent::getScore).reversed())
            .limit(5)
            .map(ScoredContent::getContent)
            .collect(Collectors.toList());
    }
}
```

## 8. 缓存与性能

### 8.1 Redis Key 设计

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `guidance:cooldown:{student_id}:{strategy_code}` | Hash | 7 天 | 策略冷却计数 |
| `guidance:snapshot:{student_id}` | String(JSON) | 1 小时 | 学生学情快照缓存 |
| `guidance:strategies:{stage}` | String(JSON) | 10 分钟 | 启用策略列表缓存 |
| `guidance:content:top:{category}:{stage}` | ZSET | 30 分钟 | 热门内容排行榜 |
| `guidance:recent:{student_id}` | List | 24 小时 | 近期已生成建议去重窗口 |

### 8.2 性能优化策略

1. **快照批预取**：每日 04:00 批量生成活跃学生学情快照，写入 Redis，减少实时 RPC。
2. **策略匹配早停**：条件按计算成本排序，先执行廉价规则（学段、冷却），再执行 expensive 规则（知识点掌握度、情绪模型）。
3. **内容检索分层**：先规则过滤（MySQL）再语义排序（pgvector），避免全量向量扫描。
4. **AI 生成异步化**：事件触发建议默认 500ms 同步返回；复杂场景（周报）转异步任务。

## 9. 错误处理

### 9.1 业务错误码

| 错误码 | 说明 | HTTP | 处理建议 |
|--------|------|------|---------|
| `57100` | 学生未绑定家长 | 404 | 静默，不生成建议 |
| `57101` | 策略冷却中，跳过生成 | 200 | missReason，审计日志 |
| `57102` | 策略学段不匹配 | 200 | missReason |
| `57103` | 学情快照不可用 | 503 | 降级为通用关怀建议 |
| `57104` | AI 增强生成失败 | 503 | 使用模板兜底文案 |
| `57105` | 家庭教育内容库为空 | 503 | 仅返回建议，不带 content |
| `57106` | 建议记录不存在 | 404 | 正常 404 |
| `57107` | 非法状态迁移 | 409 | 返回当前状态 |
| `57108` | 反馈重复提交 | 409 | 幂等返回已有结果 |
| `57109` | 批量生成任务冲突 | 409 | 同一批次唯一 |
| `57110` | 家长无权查看该学生 | 403 | 权限校验失败 |

### 9.2 降级策略

| 故障场景 | 降级行为 | 红线 |
|---------|---------|------|
| 学情分析服务不可用 | 使用 Redis 缓存快照；无缓存则生成通用关怀建议 | 不阻塞消息主链路 |
| AI 服务不可用 | 使用 Prompt 模板中的兜底文案 | 不暴露系统错误给家长 |
| 内容库检索失败 | 仅返回建议正文，不附带推荐阅读 | 建议本身仍可用 |
| 消息推送失败 | 记录 PENDING，由补偿任务重试 3 次 | 不丢失已生成建议 |
| PostgreSQL 不可用 | 缓存读命中则返回历史建议；写入端快速失败 | 不生成脏数据 |

### 9.3 幂等设计

- **事件触发**：幂等键 = `(event_id, strategy_code, student_user_id)`，DB 唯一索引兜底。
- **批量任务**：幂等键 = `batch_id`，Redis SETNX 抢占 + DB 唯一索引。
- **家长反馈/行动**：幂等键 = `(record_id, action_type)`，同类型重复提交返回首次结果。

## 10. 核心算法

### 10.1 策略优先级综合评分

```
final_score = strategy.base_priority
              + urgency_bonus(event_type)
              - fatigue_penalty(recent_same_category_count)
              - cooldown_penalty(hours_since_last_trigger)
```

| 因素 | 计算方式 | 范围 |
|------|---------|------|
| `urgency_bonus` | 紧急事件 +20，重要事件 +10，普通事件 0 | [-10, 20] |
| `fatigue_penalty` | 近 7 天同类建议数 × 5 | [0, 30] |
| `cooldown_penalty` | max(0, 72 - hours_since_last) / 8 | [0, 9] |

### 10.2 内容匹配相似度融合

```
final_content_score = 0.6 * semantic_score
                      + 0.25 * tag_overlap_score
                      + 0.15 * helpful_score_norm
```

- `semantic_score`: 内容向量与学生问题/薄弱点向量的余弦相似度。
- `tag_overlap_score`: 策略标签与内容标签的 Jaccard 相似度。
- `helpful_score_norm`: 家长反馈平均分归一化到 [0,1]。

## 13. 合规与安全

### 13.1 数据隐私

- 不向家长展示孩子具体错题原文，仅展示知识点名称与统计口径。
- 情绪信号仅用于生成关怀建议，不入画像用于营销定向。
- 家庭教育内容命中日志 90 天后删除原文，保留统计标签。

### 13.2 未成年人保护

- 向家长建议中不得出现排名、攀比、制造焦虑的表述。
- 初中生/高中生建议需保留孩子自主空间，避免过度监控感。
- 任何 AI 生成内容需经本地敏感词过滤 + 云端安全审核。

### 13.3 内容安全

- 家庭教育内容发布前需运营审核，禁止出现医疗、心理诊断结论。
- 文章引用教材内容 ≤ 50 字，避免版权风险。
