# 服务端数据库事务管理与并发控制策略 - 详细设计

## 1. 模块概述

### 1.1 功能定位

定义 PrimeTop 服务端统一的事务管理规范与并发控制策略，为开发人员在处理数据一致性、高并发写入、资源竞争等场景时提供明确的编码指导和可复用的基础设施组件。

### 1.2 适用范围

| 范围 | 说明 |
|------|------|
| 模块化单体内部 | 同进程内跨模块调用的事务边界控制 |
| 数据库层 | MySQL/PostgreSQL 事务隔离级别、锁策略、死锁处理 |
| 分布式锁 | Redis 分布式锁，用于跨实例互斥操作 |
| 异步补偿 | 本地消息表 + 重试机制的最终一致性保障 |

### 1.3 设计原则

1. **最小事务范围**：事务持有时间尽量短，避免在事务内执行外部调用（HTTP/RPC/MQ）
2. **乐观优先**：读多写少场景优先使用乐观锁，减少锁竞争
3. **显式优于隐式**：所有事务边界必须在代码中显式声明，禁止隐式自动提交
4. **幂等兜底**：并发控制失败时，通过幂等机制保证重试安全
5. **可观测性**：事务耗时、锁等待、死锁事件均纳入监控告警

## 3. 事务隔离级别与使用场景

### 3.1 隔离级别对照表

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 锁开销 | 适用场景 |
|----------|------|-----------|------|--------|----------|
| READ UNCOMMITTED | ❌可能 | ❌可能 | ❌可能 | 最低 | **禁止使用** |
| READ COMMITTED | ✅防 | ❌可能 | ❌可能 | 适中 | **默认级别**，适用于绝大多数场景 |
| REPEATABLE READ | ✅防 | ✅防 | ❌可能 | 较高 | 需要同一事务内多次读取一致时（如报表快照）
| SERIALIZABLE | ✅防 | ✅防 | ✅防 | 最高 | 极端一致性要求（如支付结算，按需使用）

### 3.2 默认策略

```python
# 全局默认 READ COMMITTED
# 原因：MySQL InnoDB 默认 REPEATABLE READ 会导致更多 Gap Lock，增加死锁概率
# READ COMMITTED 在业务层通过乐观锁保证一致性即可

from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine

engine = create_async_engine(
    "mysql+asyncmy://...",
    isolation_level="READ COMMITTED",
)
```

### 3.3 特殊场景隔离级别切换

```python
from contextlib import asynccontextmanager
from sqlalchemy.ext.asyncio import AsyncSession

async def serializable_transaction(session: AsyncSession):

    try:
        await session.execute(text("SET SESSION TRANSACTION ISOLATION LEVEL SERIALIZABLE"))
        async with session.begin():
            yield session
    finally:
        await session.execute(text(f"SET SESSION TRANSACTION ISOLATION LEVEL {original_isolation}"))
```

## 4. 事务管理模式

### 4.1 基础事务模板

```python
# infrastructure/transaction.py
from contextlib import asynccontextmanager
from sqlalchemy.ext.asyncio import AsyncSession, AsyncSessionTransaction
from src.infrastructure.database import async_session_factory
import logging

logger = logging.getLogger(__name__)


@asynccontextmanager
async def transactional(
    timeout_seconds: float = 5.0,
    isolation_level: str | None = None,
):
    """
    统一事务上下文管理器。
    
    用法:
        async with transactional() as session:
            user = User(name="test")
            session.add(user)
            # 退出时自动 commit；异常时自动 rollback
    
    约束:
        - 禁止在事务内执行外部 HTTP/MQ 调用
        - 事务超时由数据库 innodb_lock_wait_timeout 控制
        - 所有写操作通过 session.execute/flush 提交
    """
    session = async_session_factory()
    txn: AsyncSessionTransaction | None = None
    try:
        if isolation_level:
            await session.execute(
                text(f"SET SESSION TRANSACTION ISOLATION LEVEL {isolation_level}")
            )
        txn = await session.begin()
        yield session
        await session.flush()
        await txn.commit()
    except Exception as e:
        if txn:
            await txn.rollback()
        logger.warning(f"Transaction rolled back: {e}", exc_info=True)
        raise
    finally:
        await session.close()
```

```python
# 应用侧超时保护
import asyncio

@asynccontextmanager
async def transactional_with_timeout(timeout_seconds: float = 5.0):
    """带应用层超时的事务管理器"""
    async with transactional() as session:
        try:
            # 设置 MySQL 锁等待超时
            await session.execute(
                text(f"SET SESSION innodb_lock_wait_timeout = {int(timeout_seconds)}")

            raise TransactionTimeoutError(timeout_seconds)
```

### 4.4 事务内禁止事项检查器

```python
import functools
import inspect

# 标记为"外部调用"的函数，禁止在事务内执行
def external_call(func):
    """装饰器：标记此函数为外部调用，禁止在事务内执行"""
    func._is_external_call = True
    
    @functools.wraps(func)
    async def wrapper(*args, **kwargs):
        return await func(*args, **kwargs)
    return wrapper


class TransactionGuard:
    """事务守卫 —— 检测事务内是否执行了外部调用"""
    
    _in_transaction = False
    
    @classmethod
    def enter(cls):
        cls._in_transaction = True
    
    @classmethod
    def exit(cls):
        cls._in_transaction = False
    
    @classmethod
    def check_external_call(cls, func_name: str):
        if cls._in_transaction:
            raise TransactionViolationError(
                f"External call '{func_name}' detected inside transaction. "
                f"Move external calls outside the transaction boundary."
            )
```

## 5. 乐观锁（Optimistic Locking）

### 5.1 适用场景

读多写少、冲突概率低、性能敏感的操作：
- 用户信息更新
- 学习进度更新
- 错题标签修改
- 笔记/收藏编辑

### 5.2 数据模型

```sql

ALTER TABLE study_plans ADD COLUMN version INT UNSIGNED NOT NULL DEFAULT 1;
ALTER TABLE notes ADD COLUMN version INT UNSIGNED NOT NULL DEFAULT 1;
```

### 5.3 乐观锁基类

```python
# infrastructure/optimistic_lock.py
from sqlalchemy import Column, Integer
from sqlalchemy.ext.declarative import declared_attr
from src.infrastructure.exceptions import OptimisticLockError


class OptimisticLockMixin:
    """乐观锁 Mixin —— 所有需要并发更新的模型继承此类"""
    
    version = Column(
        Integer, 
        nullable=False, 
        default=1,
        comment="乐观锁版本号，每次更新 +1"
    )
    
    async def concurrent_save(self, session):
        """
        乐观锁保存。
        
        UPDATE xxx SET ..., version = version + 1 
        WHERE id = ? AND version = ?
        
        Returns: 影响行数（0 表示冲突）
        Raises: OptimisticLockError if conflict
        """
        expected_version = self.version
        self.version += 1
        
        result = await session.execute(
            self.__table__.update()
            .where(
                self.__table__.c.id == self.id,
                self.__table__.c.version == expected_version
            )
            .values(**self._dirty_values(), version=self.version)
        )
        
        if result.rowcount == 0:
            # 版本冲突，回滚本地 version
            self.version = expected_version
            raise OptimisticLockError(
                f"Optimistic lock conflict on {self.__class__.__name__} "
                f"id={self.id}, expected_version={expected_version}"
            )
        
        return result.rowcount
    
    def _dirty_values(self) -> dict:
        """获取已修改的字段值（子类或通过 SQLAlchemy 属性历史实现）"""
        return {
            col.key: getattr(self, col.key)
            for col in self.__table__.columns
            if col.key not in ('id', 'version') and hasattr(self, col.key)
        }
```

### 5.4 乐观锁重试策略

```python
import asyncio
import random
from src.infrastructure.exceptions import OptimisticLockError

async def with_optimistic_retry(
    operation,
    max_retries: int = 3,
    base_delay: float = 0.05,
    max_delay: float = 0.5,
):
    """
    乐观锁冲突时自动重试（指数退避 + 随机抖动）。
    
    用法:
        async with transactional() as session:
            result = await with_optimistic_retry(
                lambda: update_user_profile(session, user_id, data)
            )
    """
    last_error = None
    
    for attempt in range(max_retries):
        try:
            return await operation()
        except OptimisticLockError as e:
            last_error = e
            if attempt < max_retries - 1:
                delay = min(base_delay * (2 ** attempt), max_delay)
                jitter = random.uniform(0, delay * 0.3)
                await asyncio.sleep(delay + jitter)
                logger.info(
                    f"Optimistic lock retry attempt {attempt + 1}/{max_retries}, "
                    f"waiting {delay:.3f}s"
                )
    
    raise last_error
```

### 5.5 使用示例

```python
# services/user_service.py
from src.infrastructure.transaction import transactional
from src.infrastructure.optimistic_lock import with_optimistic_retry, OptimisticLockError
from src.models.user import User


async def update_user_nickname(user_id: int, nickname: str):
    """更新用户昵称 —— 乐观锁 + 自动重试"""
    
    async def _do_update():
        async with transactional() as session:
            # 1. 读取当前记录（无锁）
            user = await session.get(User, user_id)
            if not user:
                raise UserNotFoundError(user_id)
            
            # 2. 修改字段
            user.nickname = nickname
            
            # 3. 乐观锁保存（内置版本检查）
            await user.concurrent_save(session)
            return user
    
    return await with_optimistic_retry(_do_update, max_retries=3)
```

## 6. 悲观锁（Pessimistic Locking）

### 6.1 适用场景

写冲突概率高、数据一致性要求严格、需要串行化操作：
- 支付订单处理（同一订单并发支付）
- 会员权益变更（升级/降级）
- 错题订正状态变更（同一错题并发订正）
- 学习连续天数更新（跨天临界点）
- 题目提交计分（同一练习并发提交）

### 6.2 行级锁模式

```python
from sqlalchemy import select, text
from sqlalchemy.orm import with_for_update


# ========== 模式一：普通行锁 (FOR UPDATE) ==========
# 阻塞其他 FOR UPDATE 和写操作，直到事务提交
async def lock_row_for_update(session, model_class, row_id: int):
    """获取行级排他锁"""
    result = await session.execute(
        select(model_class)
        .where(model_class.id == row_id)
        .with_for_update()  # SELECT ... FOR UPDATE
    )
    return result.scalar_one_or_none()


# ========== 模式二：非阻塞行锁 (FOR UPDATE SKIP LOCKED) ==========
# 如果行被锁定则跳过，不阻塞 —— 用于队列/任务调度
async def lock_available_rows(session, model_class, limit: int = 10):
    """获取未被锁定的行（适合任务调度场景）"""
    result = await session.execute(
        select(model_class)
        .where(model_class.status == "pending")
        .order_by(model_class.created_at)
        .limit(limit)
        .with_for_update(skip_locked=True)  # MySQL 8.0+ / PG
    )
    return result.scalars().all()


# ========== 模式三：共享锁 (LOCK IN SHARE MODE) ==========
# 允许其他事务读取，但阻止写 —— 用于读取后依赖一致性判断
async def lock_row_for_read(session, model_class, row_id: int):
    """获取行级共享锁（读取后需要在同一事务内决策）"""
    result = await session.execute(
        select(model_class)
        .where(model_class.id == row_id)
        .with_for_update(read=True)  # SELECT ... LOCK IN SHARE MODE
    )
    return result.scalar_one_or_none()


# ========== 模式四：NOWAIT ==========
# 如果行被锁定立即报错，不等待 —— 用于快速失败场景
async def try_lock_row(session, model_class, row_id: int):
    """尝试获取行锁，失败立即抛异常"""
    try:
        result = await session.execute(
            select(model_class)
            .where(model_class.id == row_id)
            .with_for_update(nowait=True)  # MySQL 8.0+ / PG
        )
        return result.scalar_one_or_none()
    except OperationalError as e:
        if "lock(s)" in str(e).lower() or "nowait" in str(e).lower():
            raise RowLockConflictError(f"Row {row_id} is locked by another transaction")
        raise
```

### 6.3 悲观锁使用模板

```python
# services/payment_service.py
async def process_order_payment(order_id: int, payment_method: str):
    """
    支付订单处理 —— 悲观锁防止同一订单并发支付。
    
    关键点：
    1. 先锁行再读取，防止并发读到相同状态
    2. 锁粒度：仅锁定目标订单行
    3. 事务内禁止外部调用（支付网关调用在锁外）
    """
    
    # ====== 阶段一：获取锁 + 校验 ======
    async with transactional(timeout_seconds=3) as session:
        # 1. 行锁锁定订单
        order = await lock_row_for_update(session, Order, order_id)
        if not order:
            raise OrderNotFoundError(order_id)
        
        # 2. 幂等校验：已支付/处理中则直接返回
        if order.status == OrderStatus.PAID:
            return order  # 幂等返回
        if order.status == OrderStatus.PROCESSING:
            raise OrderBeingProcessedException(order_id)
        if order.status != OrderStatus.PENDING:
            raise InvalidOrderStatusError(order.status)
        
        # 3. 标记为处理中
        order.status = OrderStatus.PROCESSING
        session.add(order)
    
    # ====== 阶段二：外部支付调用（事务外） ======
    payment_result = await call_payment_gateway(
        amount=order.amount,
        method=payment_method,
        order_no=order.order_no,
    )
    
    # ====== 阶段三：更新支付结果 ======
    async with transactional() as session:
        order = await lock_row_for_update(session, Order, order_id)
        if payment_result.success:
            order.status = OrderStatus.PAID
            order.paid_at = datetime.utcnow()
            order.transaction_id = payment_result.txn_id
            
            # 同事务更新会员权益
            await activate_membership(session, order.user_id, order.plan_id)
        else:
            order.status = OrderStatus.FAILED
            order.fail_reason = payment_result.error_message
        
        session.add(order)
    
    return order
```

## 7. 分布式锁（Distributed Lock）

### 7.1 适用场景

跨进程/跨实例互斥操作，数据库行锁无法覆盖的场景：
- 每日学习统计聚合（同一用户只能有一个聚合任务）
- 全局唯一资源创建（如每日排行榜生成）
- 定时任务防重执行
- 批量操作的并发限流
- 用户级操作串行化（避免分布式事务）

### 7.2 Redis 分布式锁实现

```python
# infrastructure/distributed_lock.py
import uuid
import logging
import asyncio
from contextlib import asynccontextmanager
from src.infrastructure.redis import get_redis

logger = logging.getLogger(__name__)


class DistributedLock:
    """
    基于 Redis 的分布式锁（单实例 Redlock 简化版）。
    
    特性：
    - 原子加锁/解锁（Lua 脚本）
    - 自动续约（看门狗）
    - 可重入检测
    - 超时自动释放（防止死锁）
    """
    
    UNLOCK_SCRIPT = """
    if redis.call("get", KEYS[1]) == ARGV[1] then
        return redis.call("del", KEYS[1])
    else
        return 0
    end
    """
    
    RENEW_SCRIPT = """
    if redis.call("get", KEYS[1]) == ARGV[1] then
        return redis.call("pexpire", KEYS[1], ARGV[2])
    else
        return 0
    end
    """
    
    def __init__(
        self,
        lock_key: str,
        timeout_ms: int = 10_000,        # 锁超时（毫秒）
        retry_times: int = 3,             # 获取失败重试次数
        retry_delay_ms: int = 200,        # 重试间隔（毫秒）
        auto_renew: bool = False,         # 是否自动续约
    ):
        self.lock_key = f"lock:{lock_key}"
        self.timeout_ms = timeout_ms
        self.retry_times = retry_times
        self.retry_delay_ms = retry_delay_ms
        self.auto_renew = auto_renew
        self._token = str(uuid.uuid4())
        self._renew_task: asyncio.Task | None = None
    
    async def acquire(self) -> bool:
        """尝试获取锁"""
        redis = get_redis()
        
        for attempt in range(self.retry_times + 1):
            success = await redis.set(
                self.lock_key, 
                self._token, 
                px=self.timeout_ms, 
                nx=True
            )
            if success:
                logger.debug(f"Lock acquired: {self.lock_key}, token={self._token}")
                if self.auto_renew:
                    self._start_renewal()
                return True
            
            if attempt < self.retry_times:
                await asyncio.sleep(self.retry_delay_ms / 1000)
        
        logger.warning(f"Lock acquire failed after {self.retry_times} retries: {self.lock_key}")
        return False
    
    async def release(self):
        """释放锁（Lua 原子操作，仅释放自己持有的锁）"""
        redis = get_redis()
        
        if self._renew_task:
            self._renew_task.cancel()
            try:
                await self._renew_task
            except asyncio.CancelledError:
                pass
        
        result = await redis.eval(self.UNLOCK_SCRIPT, 1, self.lock_key, self._token)
        released = result == 1
        if released:
            logger.debug(f"Lock released: {self.lock_key}")
        else:
            logger.warning(
                f"Lock release failed (expired or held by another): {self.lock_key}"
            )
        return released
    
    def _start_renewal(self):
        """启动看门狗自动续约"""
        async def _renew_loop():
            renew_interval = self.timeout_ms / 3  # 每超时时间的 1/3 续约一次
            redis = get_redis()
            while True:
                await asyncio.sleep(renew_interval / 1000)
                result = await redis.eval(
                    self.RENEW_SCRIPT, 1, 
                    self.lock_key, self._token, 
                    str(self.timeout_ms)
                )
                if result == 0:
                    logger.warning(f"Lock renewal failed: {self.lock_key}")
                    break
                logger.debug(f"Lock renewed: {self.lock_key}")
        
        self._renew_task = asyncio.create_task(_renew_loop())
    
    @asynccontextmanager
    async def __aenter__(self):
        acquired = await self.acquire()
        if not acquired:
            raise DistributedLockAcquireError(
                f"Failed to acquire lock: {self.lock_key}"
            )
        try:
            yield self
        finally:
            await self.release()
    
    async def __aexit__(self, exc_type, exc_val, exc_tb):
        pass  # 由 __aenter__ 的 finally 处理


# ========== 便捷函数 ==========

@asynccontextmanager
async def distributed_lock(
    lock_key: str,
    timeout_ms: int = 10_000,
    retry_times: int = 3,
):
    """
    分布式锁上下文管理器。
    
    用法:
        async with distributed_lock("user:123:daily_agg", timeout_ms=5000):
            await aggregate_daily_stats(user_id=123)
    """
    lock = DistributedLock(
        lock_key=lock_key,
        timeout_ms=timeout_ms,
        retry_times=retry_times,
    )
    async with lock:
        yield lock
```

```python
class SingletonTask:
    """
    定时任务单实例执行保障。
    确保同一时间只有一个 Worker 执行某个定时任务。
    """
    
    def __init__(self, task_name: str, timeout_ms: int = 300_000):

                    f"Task '{self.task_name}' skipped: "
                    f"another instance is already running"

                return None
        return wrapper
```

```python
    """
    更新连续学习天数。
    
    竞争场景：用户在 23:59:59 完成学习，多个异步任务并发更新。
    策略：乐观锁 + 重试。
    """
    
    async def _do_update():
        async with transactional() as session:
            streak = await session.execute(
                select(LearningStreak).where(LearningStreak.user_id == user_id)
            )
            streak = streak.scalar_one_or_none()
            
            if not streak:
                # 首次记录
                streak = LearningStreak(
                    user_id=user_id,
                    current_streak=1,
                    longest_streak=1,
                    last_active_date=date.today(),
                    version=1,
                )
                session.add(streak)
                return streak
            
            today = date.today()
            if streak.last_active_date == today:
                return streak  # 幂等：今日已更新
            
            if streak.last_active_date == today - timedelta(days=1):
                streak.current_streak += 1  # 连续
            else:
                streak.current_streak = 1  # 断连，重新计算
            
            streak.last_active_date = today
            streak.longest_streak = max(streak.longest_streak, streak.current_streak)
            
            await streak.concurrent_save(session)  # 乐观锁
            return streak
    
    return await with_optimistic_retry(_do_update, max_retries=3)
```

## 9. 死锁预防与处理

### 9.1 死锁产生的常见原因

| 原因 | 示例 | 预防措施 |
|------|------|----------|
| 交叉更新 | 事务A锁行1→锁行2，事务B锁行2→锁行1 | 统一按主键排序更新 |
| Gap Lock 冲突 | REPEATABLE READ 下的范围插入 | 使用 READ COMMITTED |
| 索引不足 | UPDATE 无索引字段导致锁表 | 确保WHERE条件走索引 |
| 长事务 | 事务内包含外部调用导致锁持有时间过长 | 事务内禁止外部调用 |
| 自增ID竞争 | INSERT 并发竞争 AUTO_INCREMENT 锁 | 批量插入或使用分布式ID |

### 9.3 死锁检测与自动重试

```python
import re
from src.infrastructure.database import async_session_factory

DEADLOCK_ERROR_PATTERNS = [
    r"Deadlock found when trying to get lock",  # MySQL
    r"deadlock detected",                        # PostgreSQL
    r"Lock wait timeout exceeded",
]


def is_deadlock_error(error: Exception) -> bool:
    """判断是否为死锁或锁超时错误"""
    error_msg = str(error).lower()
    return any(re.search(p.lower(), error_msg) for p in DEADLOCK_ERROR_PATTERNS)


async def with_deadlock_retry(
    operation,
    max_retries: int = 3,
    base_delay: float = 0.1,
):
    """
    死锁自动重试包装器。
    
    仅在检测到死锁或锁超时时重试，其他错误直接抛出。
    
    用法:
        result = await with_deadlock_retry(
            lambda: process_order_payment(order_id)
        )
    """
    last_error = None
    
    for attempt in range(max_retries):
        try:
            return await operation()
        except Exception as e:
            if not is_deadlock_error(e):
                raise  # 非死锁错误，直接抛出
            
            last_error = e
            if attempt < max_retries - 1:
                # 指数退避 + 随机抖动
                delay = base_delay * (2 ** attempt) + random.uniform(0, 0.1)
                logger.warning(
                    f"Deadlock detected, retrying ({attempt + 1}/{max_retries}) "
                    f"after {delay:.3f}s: {e}"
                )
                await asyncio.sleep(delay)
    
    logger.error(f"Deadlock retry exhausted after {max_retries} attempts")
    raise last_error
```

```python
from datetime import datetime
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession


class OutboxWriter:
    """本地消息表写入器 —— 在业务事务内调用"""
    
    def __init__(self, session: AsyncSession):
        self.session = session
    
    async def write(
        self,
        aggregate_type: str,
        aggregate_id: int,
        event_type: str,
        payload: dict,
    ):
        """
        写入 Outbox 消息。

        """
        await self.session.execute(
            text("""
                INSERT INTO outbox_messages 
                    (aggregate_type, aggregate_id, event_type, payload, status)
                VALUES 
                    (:agg_type, :agg_id, :event_type, :payload, 0)
            """),
            {
                "agg_type": aggregate_type,
                "agg_id": aggregate_id,
                "event_type": event_type,
                "payload": json.dumps(payload, ensure_ascii=False, default=str),
            }
        )
```

### 10.4 Outbox 扫描器

```python
# infrastructure/outbox_scanner.py
import asyncio
import logging
from datetime import datetime
from sqlalchemy import text, select
from src.infrastructure.database import async_session_factory
from src.infrastructure.event_bus import event_bus

logger = logging.getLogger(__name__)


class OutboxScanner:
    """
    Outbox 消息扫描器。
    
    定时扫描 outbox_messages 表，将待发送消息发布到事件总线。
    使用 FOR UPDATE SKIP LOCKED 确保多实例安全。
    """
    
    BATCH_SIZE = 100
    SCAN_INTERVAL_SECONDS = 5
    MAX_AGE_SECONDS = 300  # 超过 5 分钟的消息标记为异常
    
    async def scan_and_publish(self):
        """扫描并发布一批消息"""
        async with transactional() as session:
            # SKIP LOCKED：多个实例扫描时互不干扰
            messages = await session.execute(
                text("""
                    SELECT id, aggregate_type, aggregate_id, event_type, payload, retry_count
                    FROM outbox_messages
                    WHERE status = 0 
                      AND created_at < NOW() - INTERVAL 5 SECOND
                    ORDER BY created_at
                    LIMIT :batch_size
                    FOR UPDATE SKIP LOCKED
                """),
                {"batch_size": self.BATCH_SIZE}
            )
            
            rows = messages.fetchall()
            if not rows:
                return
            
            for row in rows:
                try:
                    # 发布到事件总线
                    await event_bus.publish(
                        event_type=row.event_type,
                        payload=row.payload,
                    )
                    
                    # 标记为已发送
                    await session.execute(
                        text("UPDATE outbox_messages SET status = 1, sent_at = NOW() WHERE id = :id"),
                        {"id": row.id}
                    )
                except Exception as e:
                    logger.error(f"Outbox publish failed for id={row.id}: {e}")
                    
                    # 重试计数 +1
                    new_retry = row.retry_count + 1
                    new_status = 3 if new_retry >= 3 else 0  # 超过最大重试则标记失败
                    
                    await session.execute(
                        text("""
                            UPDATE outbox_messages 
                            SET retry_count = :retry, status = :status 
                            WHERE id = :id
                        """),
                        {"id": row.id, "retry": new_retry, "status": new_status}
                    )
    
    async def start(self):
        """启动定时扫描"""
        while True:
            try:
                await self.scan_and_publish()
            except Exception as e:
                logger.error(f"Outbox scanner error: {e}", exc_info=True)
            await asyncio.sleep(self.SCAN_INTERVAL_SECONDS)
```

```python
import logging
import time
from functools import wraps

logger = logging.getLogger("txn")


def transaction_logged(operation: str):
    """
    事务操作日志装饰器。
    
    自动记录事务开始、耗时、结果，以及乐观锁/死锁重试。
    """
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            TXN_STARTED.labels(operation=operation).inc()
            start_time = time.monotonic()
            
            try:
                result = await func(*args, **kwargs)
                duration = time.monotonic() - start_time
                TXN_COMMITTED.labels(operation=operation).inc()
                TXN_DURATION.labels(operation=operation).observe(duration)
                
                logger.info(
                    f"[TXN:COMMIT] op={operation} duration={duration:.3f}s"
                )
                return result
                
            except OptimisticLockError as e:
                duration = time.monotonic() - start_time
                TXN_ROLLED_BACK.labels(operation=operation, reason="optimistic_conflict").inc()
                OPTIMISTIC_CONFLICT.labels(model=str(e).split("on ")[-1] if "on " in str(e) else "unknown").inc()
                
                logger.warning(
                    f"[TXN:OPTIMISTIC_CONFLICT] op={operation} duration={duration:.3f}s error={e}"
                )
                raise
                
            except Exception as e:
                duration = time.monotonic() - start_time
                if is_deadlock_error(e):
                    TXN_ROLLED_BACK.labels(operation=operation, reason="deadlock").inc()
                    DEADLOCK_TOTAL.labels(operation=operation).inc()
                    logger.error(
                        f"[TXN:DEADLOCK] op={operation} duration={duration:.3f}s"
                    )
                else:
                    TXN_ROLLED_BACK.labels(operation=operation, reason="error").inc()
                    logger.error(
                        f"[TXN:ROLLBACK] op={operation} duration={duration:.3f}s error={e}"
                    )
                raise
        
        return wrapper
    return decorator
```

### 12.1 并发测试基类

```python
# tests/concurrency/base.py
import asyncio
from typing import Callable, Any


class ConcurrencyTestCase:
    """并发测试工具基类"""
    
    @staticmethod
    async def run_concurrent(
        operation: Callable,
        count: int = 10,
        expected_successes: int | None = None,
        expected_conflicts: int | None = None,
    ) -> list[dict]:
        """
        并发执行操作，收集结果。
        
        Args:
            operation: 异步函数
            count: 并发数
            expected_successes: 期望成功数（用于断言）
            expected_conflicts: 期望冲突数
            
        Returns:
            [{"status": "success"|"conflict"|"error", "result": ..., "error": ...}]
        """
        tasks = [asyncio.create_task(operation()) for _ in range(count)]
        results = await asyncio.gather(*tasks, return_exceptions=True)
        
        summary = []
        success_count = 0
        conflict_count = 0
        error_count = 0
        
        for r in results:
            if isinstance(r, OptimisticLockError):
                summary.append({"status": "conflict", "error": str(r)})
                conflict_count += 1
            elif isinstance(r, Exception):
                summary.append({"status": "error", "error": str(r)})
                error_count += 1
            else:
                summary.append({"status": "success", "result": r})
                success_count += 1
        
        if expected_successes is not None:
            assert success_count == expected_successes, (
                f"Expected {expected_successes} successes, got {success_count}. "
                f"Conflicts: {conflict_count}, Errors: {error_count}"
            )
        
        return summary
```

## 16. 迁移与演进策略

### 16.1 从模块化单体到微服务

当业务规模增长需要拆分微服务时，事务策略需同步演进：

| 阶段 | 事务策略 | 说明 |
|------|---------|------|
| 模块化单体（当前） | 单库事务 + 进程内事件 | 大部分操作在同库同进程 |
| 模块拆分初期 | 单库事务 + Outbox | 跨模块调用通过 Outbox 解耦 |
| 微服务化 | Saga 编排 + Outbox | 跨服务使用 Saga 补偿事务 |
| 事件驱动 | Event Sourcing + CQRS | 核心领域使用事件溯源 |

### 16.2 注意事项

1. **Outbox 表随业务库迁移**：微服务拆分时，每个服务自带 Outbox 表
2. **分布式锁 Key 前缀加服务名**：`lock:{service}:{operation}:{id}`
3. **连接池按服务独立配置**：避免跨服务共享连接池
4. **监控指标加服务标签**：`txn_duration_seconds{service="payment"}`
