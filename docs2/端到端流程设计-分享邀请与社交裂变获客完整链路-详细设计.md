# 端到端流程设计：分享邀请与社交裂变获客完整链路

> 本文档描述 PrimeTop 用户从发起分享/邀请、到新用户通过裂变链接注册转化、再到邀请奖励发放与反作弊校验的完整端到端链路，覆盖客户端分享交互、深链接解析、归因追踪、奖励结算和数据分析全环节。

---

## 1. 流程概览

### 1.1 端到端旅程图

```text
邀请人(老用户)                           被邀请人(新用户)                     后端服务
    │                                         │                              │
    ├─ P1: 选择分享场景                        │                              │
    │   (学习成就/邀请好友/内容分享)             │                              │
    │                                         │                              │
    ├─ P2: 生成分享素材                        │                              │
    │   (海报/链接/小程序卡片)                  │                              │
    │                                         │                              │
    ├─ P3: 发起到社交平台                      │                              │
    │   (微信/QQ/朋友圈/复制链接)               │                              │
    │                                         │                              │
    │  ─ ─ ─ ─ ─ ─ 社交平台传播 ─ ─ ─ ─ ─ ─ ─ ─│                              │
    │                                         │                              │
    │                                   P4: 打开分享链接/扫码                  │
    │                                         │                              │
    │                                   P5: 深链接解析与落地                   │
    │                                    (App Store/应用内跳转)  ────────────►│
    │                                         │                     解析短链/参数
    │                                   P6: 注册/登录                          │
    │                                         │                ──────────────►│
    │                                         │                     归因记录
    │                                         │                              │
    │                                   P7: 首次使用引导                       │
    │                                    (完成新手任务)         ──────────────►│
    │                                         │                     奖励判定
    │                                         │                              │
    │  P8: 邀请人收到奖励通知  ◄───────────────────────────────────────────── │
    │                                   P9: 被邀请人获得新人礼包               │
    │                                         │                              │
    │                                   P10: 持续使用                          │
    │                                    (触发阶梯奖励)         ──────────────►│
    │                                         │                     补发奖励
```

### 1.2 阶段定义

| 阶段 | 名称 | 核心动作 | 涉及端 |
| --- | --- | --- | --- |
| P1 | 场景选择 | 选择分享类型(成就/邀请/内容) | 客户端 |
| P2 | 素材生成 | 生成海报/短链/小程序卡片 | 客户端 + Share Service |
| P3 | 社交分发 | 调起微信/QQ分享或复制链接 | 客户端 |
| P4 | 链接打开 | 点击链接/扫码/打开小程序 | 被邀请人客户端 |
| P5 | 深链解析 | 解析渠道参数、跳转落地页 | 客户端 + Gateway |
| P6 | 注册转化 | 完成注册/登录并绑定归因 | 客户端 + User Service |
| P7 | 新手引导 | 完成首次使用(触发邀请人奖励条件) | 客户端 |
| P8 | 奖励发放(邀请人) | 发放邀请奖励+推送通知 | Share Service + 积分服务 |
| P9 | 奖励发放(被邀请人) | 发放新人礼包 | Share Service + 积分服务 |
| P10 | 阶梯奖励 | 被邀请人持续使用触发后续奖励 | Share Service |

### 1.3 核心指标

| 指标 | 定义 | 目标值 |
| --- | --- | --- |
| 分享率 | 发起分享用户数 / DAU | ≥ 5% |
| 链接点击率 | 链接点击次数 / 分享次数 | ≥ 30% |
| 注册转化率 | 通过邀请链接注册数 / 链接点击数 | ≥ 15% |
| 激活率 | 完成新手引导的注册用户 / 邀请注册用户 | ≥ 60% |
| 邀请人7日留存 | 发起邀请用户7日后仍活跃 | ≥ 80% |
| 被邀请人7日留存 | 通过邀请注册用户7日后仍活跃 | ≥ 40% |
| K因子 | 每个用户平均邀请成功人数 | ≥ 0.3 |

## 3. 深链接解析与落地

### 3.1 深链接解析流程

```text
用户点击短链 https://pt4.top/s/xK9mP2
        │
        ▼
  短链服务(302重定向)
        │
        ├─ 携带 User-Agent 判断平台
        │   ├─ Android → Intent Filter 唤起 App
        │   ├─ iOS → Universal Link 唤起 App
        │   └─ 其他 → H5 中间页
        │
        ▼
  App 已安装？
        ├─ YES → App 接收 Deep Link
        │          │
        │          ▼
        │   解析 primetop://invite?ref=ABC123&chl=wechat_session&sid=xK9mP2
        │          │
        │          ▼
        │   路由到邀请落地页
        │
        └─ NO  → 应用商店 / H5 中间页
                   │
                   ▼
            安装后首次打开 → 延迟深链接(Deferred Deep Link)
                   │
                   ▼
            从剪贴板/服务端匹配恢复归因参数
```

## 4. 邀请归因与注册绑定

### 4.1 归因绑定流程

```text
新用户打开App → Deep Link 携带 ref=ABC123&sid=xK9mP2
        │
        ▼
  客户端缓存归因参数到本地 (SharedPreferences / Keychain)
        │
        ▼
  用户进入注册/登录流程
        │
        ▼
  注册成功回调 → 携带归因参数调用后端
        │
        ▼
  后端归因绑定:
    1. 验证邀请码有效性
    2. 防作弊检查(设备指纹/IP/手机号)
    3. 创建归因记录 (referral_attribution)
    4. 更新邀请人统计数据
    5. 发放新人礼包(被邀请人)
    6. 标记邀请为"待激活"(需被邀请人完成新手引导后才触发邀请人奖励)
```

### 4.2 归因绑定 API

#### POST `/api/v1/referral/attribute`

在用户注册成功后由客户端调用。

**请求体：**

```json
{
  "referralCode": "ABC123",
  "shortCode": "xK9mP2",
  "channel": "wechat_session",
  "installReferrer": "utm_source=wechat&utm_medium=social",
  "deviceFingerprint": "a1b2c3d4e5f6"
}
```

**响应体：**

```json
{
  "attributed": true,
  "inviterUserId": 12345,
  "isNewUserGift": true,
  "giftDetails": {
    "membershipDays": 7,
    "coins": 200,
    "description": "7天会员体验 + 200学币"
  },
  "activationCondition": {
    "type": "complete_first_ai_chat",
    "description": "完成首次AI对话后，邀请人将获得奖励"
  }
}
```

**错误响应：**

| HTTP | code | 说明 |
| --- | --- | --- |
| 200 | `SELF_REFERRAL` | 不能邀请自己（已登录用户打开自己的链接） |
| 200 | `ALREADY_ATTRIBUTED` | 用户已有归属邀请人（首次归属优先） |
| 200 | `CODE_EXPIRED` | 邀请码已过期 |
| 200 | `CODE_INVALID` | 邀请码无效 |
| 200 | `RISK_BLOCKED` | 疑似作弊，归因被拒绝，新人礼包不发放 |

> 注意：归因失败不阻塞注册流程，仅影响奖励发放。

## 5. 奖励体系设计

### 5.1 奖励层级

| 层级 | 触发条件 | 邀请人奖励 | 被邀请人奖励 | 说明 |
| --- | --- | --- | --- | --- |
| L1 注册 | 被邀请人完成注册 | 50 学币 | 新人礼包(7天会员体验+200学币) | 即时发放 |
| L2 激活 | 被邀请人完成首次AI对话 | 100 学币 + 1天会员体验 | — | 核心奖励 |
| L3 深度 | 被邀请人连续学习3天 | 200 学币 + 3天会员体验 | 100 学币 | 质量奖励 |
| L4 付费 | 被邀请人首次购买会员 | 500 学币 + 7天会员体验 | 返还首月10%学币 | 商业奖励 |

### 5.2 奖励配置表

```sql

    id                  BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT 'ID',
    reward_tier         VARCHAR(16) NOT NULL COMMENT '奖励层级: L1/L2/L3/L4',
    tier_name           VARCHAR(64) NOT NULL COMMENT '层级名称',
```

### 5.4 奖励发放核心代码

```python
class ReferralRewardService:
    """邀请奖励发放服务"""
    
    def __init__(self, 
                 attribution_repo: ReferralAttributionRepository,
                 reward_config_repo: ReferralRewardConfigRepository,
                 reward_log_repo: ReferralRewardLogRepository,
                 coin_service: CoinService,
                 membership_service: MembershipService,
                 notification_service: NotificationService,
                 event_bus: EventBus,
                 distributed_lock: DistributedLock):
        self.attribution_repo = attribution_repo
        self.reward_config_repo = reward_config_repo
        self.reward_log_repo = reward_log_repo
        self.coin_service = coin_service
        self.membership_service = membership_service
        self.notification_service = notification_service
        self.event_bus = event_bus
        self.lock = distributed_lock
    
    async def handle_activation_event(self, event: dict):
        """
        处理激活事件，检查是否触发邀请奖励。
        
        被以下事件触发:
        - user.registered (注册完成)
        - first_ai_chat (首次AI对话)  
        - consecutive_3_days (连续学习3天)
        - first_purchase (首次购买会员)
        """
        invitee_user_id = event["user_id"]
        event_type = event["event_type"]
        
        # 1. 查找被邀请人的归因记录
        attribution = await self.attribution_repo.find_by_invitee(invitee_user_id)
        if not attribution:
            return  # 非邀请渠道用户，跳过
        
        if attribution.status == 4:  # 作弊撤销
            return
        
        # 2. 查找匹配的奖励层级
        reward_config = await self.reward_config_repo.find_by_trigger_event(event_type)
        if not reward_config or not reward_config.is_active:
            return
        
        # 3. 检查触发窗口
        if reward_config.trigger_window_days:
            days_since = (datetime.utcnow() - attribution.created_at).days
            if days_since > reward_config.trigger_window_days:
                return
        
        # 4. 幂等检查：是否已发放过该层级的邀请人奖励
        inviter_reward_exists = await self.reward_log_repo.exists(
            attribution_id=attribution.id,
            receiver_role="inviter",
            reward_tier=reward_config.reward_tier,
            status__in=[1, 2]
        )
        if inviter_reward_exists:
            return
        
        # 5. 检查邀请人每日/总上限
        if reward_config.daily_limit:
            today_count = await self.reward_log_repo.count_today_by_inviter(
                inviter_user_id=attribution.inviter_user_id,
                receiver_role="inviter"
            )
            if today_count >= reward_config.daily_limit:
                return
        
        # 6. 发放邀请人奖励（分布式锁防止并发）
        lock_key = f"referral:reward:{attribution.id}:{reward_config.reward_tier}"
        async with self.lock.acquire(lock_key, timeout_ms=10000):
            # 双重检查
            if await self.reward_log_repo.exists(
                attribution_id=attribution.id,
                receiver_role="inviter",
                reward_tier=reward_config.reward_tier,
                status__in=[1, 2]
            ):
                return
            
            # 创建奖励记录
            reward_log = ReferralRewardLog(
                reward_no=await self._generate_reward_no(),
                attribution_id=attribution.id,
                receiver_user_id=attribution.inviter_user_id,
                receiver_role="inviter",
                reward_tier=reward_config.reward_tier,
                coins=reward_config.inviter_coins,
                membership_days=reward_config.inviter_membership_days,
                custom_gift_id=reward_config.inviter_custom_gift,
                reward_description=self._build_description(
                    reward_config.tier_name, 
                    attribution.inviter_user_id,
                    "inviter"
                ),
                status=1
            )
            await self.reward_log_repo.save(reward_log)
            
            # 执行发放
            try:
                await self._grant_reward(reward_log)
                
                # 更新归因记录
                if event_type == "first_ai_chat":
                    attribution.status = 2  # 已激活
                    attribution.activated_at = datetime.utcnow()
                    attribution.activation_event = event_type
                
                if event_type == "user.registered":
                    attribution.invitee_rewarded = True
                    attribution.invitee_reward_time = datetime.utcnow()
                
                attribution.inviter_rewarded = True
                attribution.inviter_reward_time = datetime.utcnow()
                await self.attribution_repo.save(attribution)
                
            except Exception as e:
                log.error("邀请奖励发放失败: attribution_id=%s, tier=%s, error=%s",
                         attribution.id, reward_config.reward_tier, e)
                # 发放失败，记录状态，由补偿任务重试
                reward_log.status = 3  # 发放失败
                await self.reward_log_repo.save(reward_log)
                return
    
    async def _grant_reward(self, reward_log: ReferralRewardLog):
        """执行实际奖励发放"""
        
        # 发放学币
        if reward_log.coins > 0:
            await self.coin_service.grant(
                user_id=reward_log.receiver_user_id,
                amount=reward_log.coins,
                source_type="referral_reward",
                source_id=reward_log.reward_no,
                description=reward_log.reward_description
            )
        
        # 发放会员天数
        if reward_log.membership_days > 0:
            await self.membership_service.grant_trial(
                user_id=reward_log.receiver_user_id,
                days=reward_log.membership_days,
                source="referral_reward",
                source_id=reward_log.reward_no
            )
        
        # 更新状态
        reward_log.status = 2  # 已发放
        reward_log.granted_at = datetime.utcnow()
        await self.reward_log_repo.save(reward_log)
        
        # 发送通知
        await self.notification_service.send(
            user_id=reward_log.receiver_user_id,
            template_code="REFERRAL_REWARD_GRANTED",
            params={
                "coins": reward_log.coins,
                "membership_days": reward_log.membership_days,
                "tier_name": reward_log.reward_tier
            }
        )
        
        # 发布事件
        await self.event_bus.publish("referral.reward_granted", {
            "reward_no": reward_log.reward_no,
            "receiver_user_id": reward_log.receiver_user_id,
            "receiver_role": reward_log.receiver_role,
            "reward_tier": reward_log.reward_tier,
            "coins": reward_log.coins,
            "membership_days": reward_log.membership_days
        })
    
    @staticmethod
    def _build_description(tier_name: str, user_id: int, role: str) -> str:
        if role == "inviter":
            return f"邀请好友奖励({tier_name})"
        return f"邀请注册奖励({tier_name})"
    
    @staticmethod
    async def _generate_reward_no() -> str:
        date_str = datetime.utcnow().strftime("%Y%m%d")
        seq = await SequenceService.next(f"reward_no_{date_str}")
        return f"RWD{date_str}{seq:06d}"
```

### 6.1 风控检测维度

| 维度 | 检测项 | 阈值 | 处理 |
| --- | --- | --- | --- |
| 设备指纹 | 同一设备注册多个账号 | ≥ 3个/月 | 拒绝归因 |
| IP 地址 | 同一IP高频注册 | ≥ 5个/天 | 标记+人工审核 |
| 手机号 | 手机号前缀高度相似 | 批量号段特征 | 拒绝归因 |
| 行为模式 | 注册后无真实学习行为 | 0次学习/7天 | 延迟发放/回收奖励 |
| 邀请集中度 | 邀请人短期大量邀请 | ≥ 20人/天 | 限流+人工审核 |
| 社交图谱 | 被邀请人之间互邀 | 环路检测 | 拒绝归因 |
| 设备重置 | 频繁重置设备ID | ≥ 3次/周 | 标记 |

### 6.2 风控评分引擎

```python
class ReferralRiskEngine:
    """邀请归因风控引擎"""
    
    # 风险权重配置
    WEIGHTS = {
        "same_device": 40,       # 同设备
        "same_ip_cluster": 25,   # 同IP段
        "rapid_register": 20,    # 快速注册
        "no_real_activity": 10,  # 无真实行为
        "phone_pattern": 15,     # 手机号模式
        "invite_burst": 15,      # 邀请突发
    }
    
    async def evaluate(self, attribution: ReferralAttribution) -> RiskAssessment:
        """评估归因风险评分"""
        score = 0
        tags = []
        
        # 1. 设备指纹检查
        device_dup = await self._check_device_duplicate(attribution.invitee_device_fp)
        if device_dup >= 3:
            score += self.WEIGHTS["same_device"]
            tags.append("same_device")
        
        # 2. IP聚类检查
        ip_cluster = await self._check_ip_cluster(attribution.invitee_ip)
        if ip_cluster >= 5:
            score += self.WEIGHTS["same_ip_cluster"]
            tags.append("same_ip_cluster")
        
        # 3. 注册速度检查 (从点击到注册的时间)
        click = await self._get_click_log(attribution.short_code)
        if click and click.created_at:
            reg_time = attribution.created_at
            time_diff = (reg_time - click.created_at).total_seconds()
            if time_diff < 5:  # 5秒内完成注册(非人类速度)
                score += self.WEIGHTS["rapid_register"]
                tags.append("rapid_register")
        
        # 4. 邀请人突发检查
        inviter_today_count = await self._get_inviter_today_count(attribution.inviter_user_id)
        if inviter_today_count >= 20:
            score += self.WEIGHTS["invite_burst"]
            tags.append("invite_burst")
        
        # 5. 手机号模式
        phone_suspicious = await self._check_phone_pattern(attribution.invitee_phone_hash)
        if phone_suspicious:
            score += self.WEIGHTS["phone_pattern"]
            tags.append("phone_pattern")
        
        # 判定结果
        if score >= 60:
            action = "block"       # 直接拒绝
        elif score >= 30:
            action = "review"      # 人工审核
        else:
            action = "pass"        # 自动通过
        
        return RiskAssessment(
            score=score,
            tags=tags,
            action=action,
            evaluated_at=datetime.utcnow()
        )
```
