## 1. 概述

### 1.1 模块定位

系统通知与公告管理配置工作台（Admin Notification & Announcement Console）是 PrimeTop 管理后台面向运营团队、客服团队和系统管理员的统一消息管理界面。

该工作台与「运营活动与营销推广配置工作台」的区别在于：

| 维度 | 系统通知与公告工作台 | 运营活动与营销推广工作台 |
| --- | --- | --- |
| **消息性质** | 系统级、服务级、合规级通知 | 营销级、活动级、推广级消息 |
| **触发方式** | 事件触发 / 定时触发 / 手动紧急广播 | 运营人员主动创建活动 |
| **典型场景** | 系统维护公告、隐私政策更新、安全预警、功能下线通知、考试日程提醒、未成年人保护合规通知 | 优惠券发放、学习挑战赛、裂变邀请、节日活动 |
| **发送权限** | 系统管理员、客服主管、合规专员 | 运营专员、市场推广 |
| **审批要求** | 紧急通道可免审批即时发送 | 必须经过审核 → 发布流程 |
| **退订规则** | 法定/合规通知不可退订，非必要通知尊重用户偏好 | 用户可在设置中关闭营销推送 |

### 1.2 设计目标

| 目标 | 说明 |
| --- | --- |
| 统一消息出口 | 系统公告、服务通知、合规消息、紧急广播统一在此工作台管理 |
| 精准触达 | 基于用户标签、学段年级、地域、行为特征进行精细化人群圈选 |
| 多通道编排 | 一次编辑，自动适配 App 推送、站内信、短信、微信等多通道投递 |
| 智能频控 | 对接通知疲劳度管控引擎，避免短时间内对同一用户重复打扰 |
| 效果可追踪 | 推送到达率、点击率、已读率、退订率实时统计 |
| 合规可审计 | 所有发送记录留存审计日志，支持合规检查与事后追溯 |

### 1.3 适用范围与角色权限

| 角色 | 可用功能 | 权限范围 |
| --- | --- | --- |
| 系统管理员 | 全部功能 | 创建/编辑/审核/发布/撤回/紧急广播/模板管理/通道配置 |
| 运营主管 | 公告管理、通知模板、定时推送、数据查看 | 创建/编辑/审核/发布/撤回 |
| 运营专员 | 公告管理（草稿）、定时推送、数据查看 | 创建/编辑（不可发布） |
| 客服主管 | 服务通知发送、紧急通知（受限）、数据查看 | 创建/发送受限范围通知 |
| 合规专员 | 合规通知创建与发布、隐私政策推送 | 合规类通知全权限 |

### 1.4 依赖关系

```text
系统通知与公告管理配置工作台（前端）
    │
    ├── 通知中心与站内消息系统（站内信存储与查询）
    ├── 统一通知消息模板引擎（模板渲染与变量替换）
    ├── 多厂商推送通道适配层（APNs/FCM/华为/小米/VIVO/OPPO/魅族推送）

    ├── 多源通知智能合并与用户通知疲劳度管控引擎（频控去重）
    ├── 用户标签与智能分群引擎（目标人群圈选）
    ├── 统一审计日志与操作追溯系统（操作记录）
```

### 3.2 系统公告表 (sys_announcement)

```sql
CREATE TABLE sys_announcement (
    id                BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '公告ID',
    announcement_no   VARCHAR(32) NOT NULL UNIQUE COMMENT '公告编号 ANN+YYYYMMDD+NNNNN',
    title             VARCHAR(200) NOT NULL COMMENT '公告标题',
    category          VARCHAR(32) NOT NULL COMMENT '类别: SYSTEM_UPDATE|MAINTENANCE|POLICY_UPDATE|SECURITY_ALERT|FEATURE_RELEASE|EXAM_REMINDER|COMPLIANCE_NOTICE|HOLIDAY_NOTICE',
    priority          TINYINT NOT NULL DEFAULT 2 COMMENT '优先级: 1-紧急 2-重要 3-普通 4-低',
    status            VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT|PENDING_REVIEW|APPROVED|SCHEDULED|SENT|CANCELED|ARCHIVED',

    -- 内容
    summary           VARCHAR(500) COMMENT '摘要（用于推送通知展示）',
    body_content      MEDIUMTEXT NOT NULL COMMENT '正文（富文本/Markdown）',
    body_format       VARCHAR(16) NOT NULL DEFAULT 'markdown' COMMENT 'markdown|richtext|plaintext',
    cover_image       VARCHAR(512) COMMENT '封面图URL（可选）',
    attachment_urls   JSON COMMENT '附件URL列表',

    -- 目标人群
    target_scope      VARCHAR(16) NOT NULL DEFAULT 'ALL' COMMENT 'ALL-全量 USER_SEGMENT-分群 GRADE_SPECIFIC-指定年级 INDIVIDUAL-指定用户',
    target_config     JSON COMMENT '目标配置: {stage:[], grade:[], subject:[], user_ids:[], segment_ids:[], exclude_ids:[]}',

    -- 通道配置
    channels          JSON NOT NULL COMMENT '投递通道: ["in_app","push","sms","wechat_template"]',
    channel_strategy  VARCHAR(16) DEFAULT 'PRIORITY' COMMENT 'PRIORITY-按优先级选首个可达 ALL-全通道下发 FALLBACK-逐通道降级',

    -- 调度
    send_type         VARCHAR(16) NOT NULL DEFAULT 'IMMEDIATE' COMMENT 'IMMEDIATE-立即 SCHEDULED-定时 RECURRING-循环',
    scheduled_at      DATETIME COMMENT '计划发送时间（SCHEDULED 类型必填）',
    recurring_cron    VARCHAR(64) COMMENT '循环规则（RECURRING 类型，cron 表达式）',
    recurring_end_at  DATETIME COMMENT '循环结束时间',
    expire_at         DATETIME COMMENT '公告过期时间（过期后不再展示）',

    -- 展示控制
    in_app_display    JSON COMMENT '站内信展示配置: {pin_to_top:Bool, banner_enabled:Bool, banner_until:DATETIME, dismissible:Bool, popup_on_open:Bool}',
    push_config       JSON COMMENT '推送配置: {sound:String, badge:Int, android_channel_id:String, ios_interruption_level:String}',

    -- 合规
    is_compliance     BOOLEAN DEFAULT FALSE COMMENT '是否合规通知（合规通知不可退订）',
    privacy_policy_ref VARCHAR(128) COMMENT '关联隐私政策版本号（如适用）',

    -- 审批
    created_by        BIGINT NOT NULL COMMENT '创建人ID',
    created_by_name   VARCHAR(50) COMMENT '创建人姓名',
    reviewed_by       BIGINT COMMENT '审核人ID',
    reviewed_by_name  VARCHAR(50) COMMENT '审核人姓名',
    reviewed_at       DATETIME COMMENT '审核时间',
    review_comment    VARCHAR(500) COMMENT '审核意见',
    published_by      BIGINT COMMENT '发布人ID',
    published_at      DATETIME COMMENT '实际发布时间',

    -- 统计（异步更新）
    target_count      INT DEFAULT 0 COMMENT '目标用户总数',
    sent_count        INT DEFAULT 0 COMMENT '已发送数',
    delivered_count   INT DEFAULT 0 COMMENT '已送达数',
    read_count        INT DEFAULT 0 COMMENT '已读数',
    clicked_count     INT DEFAULT 0 COMMENT '点击数',
    dismissed_count   INT DEFAULT 0 COMMENT '关闭/退订数',

    created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at        DATETIME COMMENT '逻辑删除',

    INDEX idx_ann_no (announcement_no),
    INDEX idx_status_priority (status, priority),
    INDEX idx_category (category),
    INDEX idx_scheduled (send_type, scheduled_at),
    INDEX idx_created_by (created_by),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统公告表';
```

### 4.4 紧急广播 `/notify/emergency/broadcast`

**设计约束**：紧急广播追求快，但必须防误发。三字段极简表单（标题/正文/受众范围），默认通道 `in_app+push`，默认类目 `SECURITY_ALERT`，默认优先级 1。

**免审批条件（守卫 G11，全部满足才免审）**：

1. 操作者角色为**系统管理员**；
2. 类目 ∈ {SECURITY_ALERT, MAINTENANCE}；
3. 受众为全量或分群（不允许 INDIVIDUAL 指定用户——防针对骚扰）；
4. 该管理员 1 小时内全量紧急广播次数 < 2（超出走双人复核：另一系统管理员在 15 分钟内确认）。

不满足任一条件则降级为普通公告流程（走审核）。

**双确认交互**：提交时弹出确认对话框，需手动输入公告编号后 4 位方可点击确认；确认后立即发送并跳转任务详情页（紧急广播不灰度，但受通道 200/s 平滑限速）。

| --- | --- | --- |
| POST | `/admin/notify/emergency/broadcast` | 创建并立即发送（免审或双人复核令牌） |
| GET | `/admin/notify/emergency/history` | 历史记录（含发送人、确认人、耗时） |

## 5. 关键流程与代码示例

### 5.1 公告发布编排主流程

```text
审批通过(APPROVED)
    │ publish(mode) 或 延迟任务引擎到点触发
    ▼
┌─ startPublish（事务内）──────────────────────────────┐
│ 1. 锁公告行，状态 → PUBLISHING                        │
│ 2. 模板渲染快照 → 创建 notify_send_task(SENDING)      │
│ 3. 圈人：audienceClient.selectBySegment(ramp=1%)      │
│    uk(announcement_id,user_id) 天然 excludePublished   │
│ 4. 未成年人屏蔽：MARKETING 类目过滤 is_minor_u16       │
│ 5. 快照写入 announcement_target（SELECTED/SKIPPED_*）   │
│ 6. Outbox 同事务写入 NotifyTaskCreatedEvent            │
└──────────────────────────────────────────────┘
    │ 事件驱动批次执行器
    ▼
每批次（200/s 平滑限速分片）
    │ 每用户：FrequencyController.check 频控（拦截→SKIPPED_FREQUENCY）
    │ ChannelOrchestrator 通道编排（策略+健康+偏好）
    │ PushVendorProvider.batchSend / 短信网关 / 微信 / 站内信写入
    │ notify_channel_log 逐次记录（含重试）
    ▼
回执消费（到达/已读/点击事件）
    │ 按 (task_id,user_id) 幂等 upsert notify_send_record 时间线
    │ Redis 计数器增量 → 每 5 分钟刷库回写 task/announcement 统计
    ▼
批次完成 → ramp 评估（退订率/关闭推送率/投诉量）
    │ 正常 → 下一档（观察 30min）│ 异常 → 自动暂停 + 告警运营群
    ▼
100% 档完成 → 状态 SENT → 统计持续回流
```

**发布编排门面（核心代码）**：

```java
@Service
public class AnnouncementPublishFacade {

    private static final int[] RAMP_STEPS = {1, 10, 50, 100};      // 对齐端到端链路 §3.7.2
    private static final Duration STEP_OBSERVE = Duration.ofMinutes(30);
    private static final int SEND_QPS_LIMIT = 200;                  // 百万受众 ≈ 83 分钟

    private final AnnouncementDao announcementDao;
    private final NotifyTaskFactory taskFactory;
    private final AudienceClient audienceClient;        // 用户标签与智能分群引擎
    private final MinorShieldService minorShield;        // 未成年人营销屏蔽
    private final TargetSnapshotService targetSnapshot;  // announcement_target 写入
    private final NotifyTaskDao taskDao;
    private final TransactionalOutbox outbox;

    /** 审批通过后进入发布编排；SCHEDULED 由延迟任务引擎到点回调本方法 */
    @Transactional(rollbackFor = Exception.class)
    public Long startPublish(Long announcementId) {
        Announcement ann = announcementDao.selectForUpdate(announcementId);
        if (ann == null) throw new BizException(NotifyErrorCode.ANN_NOT_FOUND);
        ann.assertStatusIn(Status.APPROVED, Status.SCHEDULED);       // 守卫 G5

        ann.setStatus(Status.PUBLISHING);

        // 1. 渲染快照 + 创建发送任务
        NotifySendTask task = taskFactory.from(ann);

        // 2. 首档圈人（uk 幂等，重入安全：重试不会重复圈人）
        AudienceSelection audience = audienceClient.selectBySegment(
                ann.getTargetConfig(), RAMP_STEPS[0], /*excludePublished*/ true);

        // 3. 合规红线 C1：MARKETING 类目对 <16 岁未成年人整体屏蔽
        if (ann.isMarketingLike()) {   // 营销类目判定（MARKETING 类公告与活动导流类 SERVICE 通知）
            audience = minorShield.filterOut(ann, audience);   // 被过滤者记 SKIPPED_MINOR_SHIELD
        }

        // 4. 快照落库（分片 INSERT IGNORE，每片 2000 行）
        targetSnapshot.persist(ann.getId(), task.getId(), audience);

        task.setTargetCount(audience.selectedCount());
        task.setStatus(TaskStatus.SENDING);
        taskDao.insert(task);
        outbox.save(NotifyTaskCreatedEvent.of(task));             // Outbox 同事务
        return task.getId();
    }

    /** 下一档放量（批次全部完成 + 观察指标达标后由 ramp 评估器回调） */
    @Transactional(rollbackFor = Exception.class)
    public void publishNextRamp(Long announcementId) {
        Announcement ann = announcementDao.selectForUpdate(announcementId);
        ann.assertStatusIn(Status.PUBLISHING);                     // 守卫 G7
        int nextPercent = resolveNextPercent(ann);                 // 1→10→50→100
        if (nextPercent == 100 && ann.isRampPaused()) {
            throw new BizException(NotifyErrorCode.RAMP_PAUSED);
        }
        AudienceSelection extra = audienceClient.selectBySegment(
                ann.getTargetConfig(), nextPercent, true);
        // ……同 startPublish 步骤3/4：增量快照 + 追加批次
    }
}
```

### 5.2 通道编排器（三策略）

```java
@Component
public class ChannelOrchestrator {

    private final ChannelRegistry channelRegistry;   // notify_channel_config 缓存（30s 刷新）
    private final UserChannelPreferenceClient preferenceClient; // 通知偏好授权中心（只读）

    /** 将一个用户的通道包解析为有序投递通道序列 */
    public List<String> resolve(UserChannelContext ctx, NotifyChannelPack pack,
                                boolean isCompliance) {
        // 1. 用户偏好过滤：非合规通知尊重用户退订/偏好（合规红线 C2）
        Set<String> optedOut = isCompliance
                ? Set.of() : preferenceClient.optedOutChannels(ctx.getUserId());

        // 2. 健康与配额过滤（HEALTHY/DEGRADED 可用，DOWN 不可用）
        List<String> usable = pack.getChannels().stream()
                .filter(ch -> !optedOut.contains(ch))
                .filter(channelRegistry::isSendable)      // health != DOWN && daily_sent < daily_limit
                .sorted(Comparator.comparingInt(ch -> channelRegistry.priority(ch)))
                .collect(Collectors.toList());

        // 3. 策略裁决
        switch (pack.getStrategy()) {
            case PRIORITY:                                  // 按优先级取首个可达
                return usable.subList(0, Math.min(1, usable.size()));
            case ALL:                                       // 全通道下发（如合规+紧急同时走 push+in_app）
                return usable;
            case FALLBACK:                                  // 逐通道尝试，成功即停（投递器配合）
                return usable;
            default:
                return usable.subList(0, Math.min(1, usable.size()));
        }
    }
}
```

> 推送实际下发调用《服务端-多厂商推送通道适配层…》`PushVendorProvider.batchSend(List<UnifiedPushMessage>, List<PushDeviceReg>)`；短信走《服务端-统一短信验证码服务与多渠道通知发送网关》发送接口（模板编号已绑定）；站内信写入 `in_app_message` 并通知《通知中心与站内消息系统》刷新未读数。

### 5.3 定时与循环调度

- SCHEDULED：`publish` 时校验 `scheduled_at >= now + 30min`（G4），注册到《服务端-统一延迟任务调度与到期事件触发引擎》回调 `startPublish`；
- RECURRING：每次触发生成**独立任务**（不复用历史任务），任务号携带序号；
- **错过窗口补偿**：回调迟到 >15 分钟的非紧急循环公告**跳过本周期**并告警（防补偿风暴）；紧急类（SECURITY_ALERT）迟到仍执行。

### 5.5 撤回流程

```java
@Transactional(rollbackFor = Exception.class)
public void revoke(Long announcementId, Long operatorId, String reason) {
    Announcement ann = announcementDao.selectForUpdate(announcementId);
    ann.assertStatusIn(Status.SENT);                            // 守卫 G8
    Assert.hasText(reason, () -> new BizException(NotifyErrorCode.REVOKE_REASON_REQUIRED));

    // 1. 站内信下架：标记删除 + 深链失效（通知中心未读数同步刷新）
    inAppMessageClient.markDeletedBySource(announcementId);
    // 2. 推送栏消息无法撤回 → 仅记录，前端确认弹窗已提示
    // 3. 状态流转 + 审计 + 事件
    ann.setStatus(Status.REVOKED);
    auditLog.write(NotifyAuditAction.ANNOUNCEMENT_REVOKED, operatorId, announcementId, reason);
    outbox.save(AnnouncementRevokedEvent.of(announcementId, reason));
}
```

**撤回确认弹窗文案要点**（合规红线 C6）：明确告知「应用内公告已下架；已送达的系统推送栏消息无法远程撤回」；若公告存在误导风险，提供一键创建澄清公告入口（预填类目与受众）。

## 6. 状态机与守卫总表

### 6.1 公告状态机（9 态）

```text
DRAFT ──提交──→ PENDING_REVIEW ──驳回──→ DRAFT
                     ││
              机审+人审││命中敏感词→人工复审
                     ▼▼
                 APPROVED ──定时──→ SCHEDULED ──到点──→ PUBLISHING ──全批次完成──→ SENT
                     │                                          │                        │
              立即发布└────────────────────────────→ PUBLISHING   │暂停/恢复(档位级)        │撤回(reason)
                     │                                                                    ▼
                CANCELED ←──(APPROVED/SCHEDULED/PUBLISHING 均可取消)              REVOKED
                     │                                                                    │
                     └────────────────────→ ARCHIVED ←─────────────────────────────┘
```

### 6.2 守卫总表（G1–G14）

| 守卫 | 状态迁移/操作 | 规则 |
| --- | --- | --- |
| G1 | DRAFT→PENDING_REVIEW | 必填 title/body/target_config/channels；提交人 ≠ 审核人 |
| G1a | PUT 编辑 | 仅 DRAFT（或驳回后回 DRAFT）；非 DRAFT 禁改 |
| G1b | DELETE | 仅 DRAFT 逻辑删 |
| G2 | PENDING_REVIEW→APPROVED | 机审+人审均通过；COMPLIANCE_NOTICE 类必须由合规专员审核 |
| G3 | PENDING_REVIEW→DRAFT | 驳回必填 comment（≥5 字） |
| G4 | APPROVED→SCHEDULED | scheduled_at ≥ now + 30min |
| G5 | APPROVED/SCHEDULED→PUBLISHING | 生成任务+人群快照；同事务 Outbox |
| G6 | PUBLISHING→SENT | 全部批次完成且 100% 档放量 |
| G7 | PUBLISHING 暂停/恢复 | 暂停停在当前档位；恢复重新计时观察期；已 SENT 不可（G6 已终态） |
| G8 | SENT→REVOKED | 必填 reason；触发站内信下架扇出 |
| G9 | APPROVED/SCHEDULED/PUBLISHING→CANCELED | PUBLISHING 中取消 = 停止后续批次，已发送不撤回（弹窗告知） |
| G10 | SENT/CANCELED/REVOKED→ARCHIVED | 归档只读，统计仍可查 |
| G11 | 紧急广播免审 | 见 §4.4 四条件；否则走普通审核流 |
| G12 | 任务取消/重试 | 取消仅 PENDING/SENDING；retry-failed 仅失败记录且单任务总重试 ≤ 2 轮 |
| G13 | 模板生命周期 | UNDER_REVIEW→ACTIVE 需审核；is_system 不可删；被引用模板停用需二次确认 |
| G14 | 通道凭据变更 | 双人审批 + test 通过才激活；fallback 不自指/成环 |

### 6.3 任务状态机（6 态）与模板状态机（3 态）

任务：`PENDING → SENDING → COMPLETED | PARTIAL_SENT | FAILED | CANCELED`（PARTIAL_SENT=成功率≥95% 但有失败；FAILED=首通道全军覆没且无降级可用）。模板：`UNDER_REVIEW → ACTIVE ⇄ INACTIVE`（停用可再启用，需重审）。

| 报表查看 | ✅ | ✅ | ✅（脱敏版） | ✅ | ✅ |

### 8.2 数据脱敏规则

手机号/凭据/设备 token 列表导出时脱敏（`138****5678`）；失败明细中 `error_msg` 已在写入时脱敏（§3.10）；运营专员报表隐藏个体用户明细，仅聚合视图。

### 8.3 审计要求

所有写操作（提交/审核/发布/暂停/取消/撤回/归档/凭据变更/健康覆写/紧急广播）发布 `notify.admin.audit` 事件，写入《服务端-审计日志与操作追溯系统》统一审计表，含 operator/action/target_id/before/after/reason/ip/ua；**审计日志不可删除，留存 ≥3 年**。双人审批类操作记录两位审批人。

### 9.2 降级矩阵（D1–D10）

| 编号 | 故障 | 降级策略 |
| --- | --- | --- |
| D1 | 分群引擎不可用 | **拒绝发布**（安全优先，不退化为全量）；预估接口回 stale 缓存 |
| D2 | 疲劳度引擎不可用 | 本地保守频控（同源每日≤2条）+ 异步补记，恢复后重放 |
| D3 | 单通道 DOWN | 自动走 fallback 链；无可用降级通道时仅留 in_app |
| D4 | 短信网关超时 | FALLBACK 策略下切下一通道；ALL 策略下标记失败可重试 |
| D5 | 统计回写延迟 | 前端显示「截至 T-5min」；对账任务每日校正 |
| D6 | 报表 ClickHouse 不可用 | 降 MySQL 慢查（限 7 天内、限管理员角色） |
| D7 | 延迟任务引擎回调迟到>15min | 非紧急循环公告跳过本周期+告警（防风暴） |
| D8 | Outbox 积压 | 批次执行器幂等重试，任务进度停滞 >10min 告警 |
| D9 | KMS 不可用 | 凭据变更入口关闭（只读），存量凭据解密走本地缓存密文兜底 |
| D10 | 审计服务不可用 | 本地落盘暂存 + 恢复后补传，审计丢失率必须为 0 |

## 11. 合规红线（C1–C9）

| 编号 | 红线 |
