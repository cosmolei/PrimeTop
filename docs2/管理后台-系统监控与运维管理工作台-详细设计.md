## 1. 概述

### 1.1 功能定位

系统监控与运维管理工作台是 PrimeTop 管理后台面向 **运维工程师（SRE）、技术负责人、on-call 值班人员** 的统一操作面板。它将底层可观测性基础设施（日志、指标、链路追踪、告警引擎）聚合为可视化的管理界面，使运维团队无需直连 Grafana / Prometheus / Kibana 等底层系统即可完成日常监控、告警处置、故障应急和容量分析工作。

### 1.2 设计目标

| 目标 | 说明 |
| --- | --- |
| **统一运维入口** | 一个工作台聚合系统健康、告警、日志、部署、成本五大维度 |
| **告警闭环管理** | 告警从触发→确认→分派→处理→复盘全流程在线化 |
| **故障快速响应** | P0 故障从发现到定位根因 ≤ 10 分钟，到修复 ≤ 30 分钟 |
| **成本可视可控** | AI 模型调用成本、基础设施成本实时追踪，预算超标自动预警 |
| **应急操作可视化** | 限流降级、服务熔断、功能开关等应急操作通过工作台一键执行，全部审计留痕 |
| **数据驱动容量规划** | 基于历史趋势和 SLO 错误预算给出扩缩容建议 |

### 1.3 适用范围

| 范围内 | 范围外 |
| --- | --- |
| 运维仪表盘页面与交互设计 | Prometheus / Fluent Bit 等采集组件配置（由基础设施文档负责） |
| 告警规则前端配置与告警事件管理 | 告警引擎底层实现（由日志与监控告警体系负责） |
| 故障事件管理流程（Incident） | 自动根因分析算法（由 AIOps 模块未来迭代） |
| AI 成本、API 调用量等业务运营指标可视化 | 成本核算计费逻辑（由计费账单中心负责） |
| 运维应急操作（限流、降级、熔断、开关） | 服务端限流熔断中间件实现（由统一限流熔断体系负责） |
| On-call 排班可视化展示 | 排班算法本身（由团队管理流程决定） |
| 发布与变更记录查看 | CI/CD 流水线底层实现（由 CI/CD 文档负责） |

### 1.4 目标用户

| 角色 | 典型场景 | 权限等级 |
| --- | --- | --- |
| SRE / 运维工程师 | 日常巡检、告警处理、故障排查、容量分析 | `ops:full` |
| 技术负责人 | 关注 SLO 达成率、错误预算消耗、发布决策 | `ops:read` + `slo:read` |
| On-call 值班人员 | 接收告警、快速分诊、启动应急流程 | `ops:alert:*` + `ops:emergency:*` |
| 后端开发 | 查看自己负责服务的日志、指标、Trace | `ops:read`（限本服务） |
| 管理层 | 查看整体系统健康度、成本趋势、SLA 达成 | `ops:read`（只读看板） |

## 2. 数据结构定义

### 2.1 告警事件表 `ops_alert_events`

> 本表同步 AlertManager 中的告警状态，提供工作台统一查询和管理能力。

```sql
CREATE TABLE `ops_alert_events` (
    `id`                BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `alert_fingerprint` VARCHAR(64)  NOT NULL COMMENT '告警唯一指纹(AlertManager fingerprint)',
    `alert_name`        VARCHAR(256) NOT NULL COMMENT '告警规则名称',
    `severity`          VARCHAR(16)  NOT NULL COMMENT '严重级别: critical, warning, info',
    `service_name`      VARCHAR(128) NOT NULL DEFAULT '' COMMENT '关联服务名',
    `instance`          VARCHAR(256) NOT NULL DEFAULT '' COMMENT '实例地址',
    `summary`           VARCHAR(512) NOT NULL DEFAULT '' COMMENT '告警摘要',
    `description`       TEXT         NULL COMMENT '告警详细描述',
    `labels_json`       JSON         NULL COMMENT '告警标签(JSON, 完整 labels)',
    `annotations_json`  JSON         NULL COMMENT '告警注解(JSON)',
    `status`            VARCHAR(16)  NOT NULL DEFAULT 'firing' COMMENT '状态: firing, resolved',
    `triggered_at`      DATETIME(3)  NOT NULL COMMENT '告警触发时间',
    `resolved_at`       DATETIME(3)  NULL COMMENT '告警恢复时间',
    `duration_seconds`  INT          NOT NULL DEFAULT 0 COMMENT '持续时长(秒)',
    -- 工作台管理字段
    `ack_status`        VARCHAR(16)  NOT NULL DEFAULT 'unack' COMMENT '确认状态: unack, acked, auto_ack',
    `acked_by`          BIGINT       NOT NULL DEFAULT 0 COMMENT '确认人(admin_users.id)',
    `acked_at`          DATETIME(3)  NULL COMMENT '确认时间',
    `ack_note`          VARCHAR(512) NOT NULL DEFAULT '' COMMENT '确认备注',
    `incident_id`       BIGINT       NOT NULL DEFAULT 0 COMMENT '关联故障事件ID(0=未关联)',
    `created_at`        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_fingerprint` (`alert_fingerprint`),
    KEY `idx_status_severity` (`status`, `severity`),
    KEY `idx_service_triggered` (`service_name`, `triggered_at`),
    KEY `idx_ack_status` (`ack_status`),
    KEY `idx_incident` (`incident_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='运维告警事件';
```

## 3. API 接口设计

### 3.1 接口总览

| 分组 | 接口 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- | --- |
| 仪表盘 | 健康总览 | GET | `/api/ops/dashboard/overview` | 系统健康度总览 |
| 仪表盘 | 服务详情 | GET | `/api/ops/dashboard/services/{serviceName}` | 单服务监控详情 |
| 仪表盘 | 自定义看板 | GET/POST | `/api/ops/dashboards` | 看板 CRUD |

| 告警 | 告警列表 | GET | `/api/ops/alerts` | 查询告警事件列表 |
| 告警 | 确认告警 | PUT | `/api/ops/alerts/{id}/ack` | 确认/认领告警 |
| 告警 | 静默告警 | POST | `/api/ops/alerts/silence` | 创建静默规则 |

```
POST /api/ops/emergency/execute
```

**Request Body (限流操作示例):**

```json

}
```

**Request Body (特性开关示例):**

```json
{
  "action_type": "feature_toggle",
  "target_service": "ai-service",
  "target_resource": "feature.multi_model_voting",
  "action_params": {
    "enabled": false
  },
  "reason": "多模型投票功能导致延迟倍增，临时关闭",
  "incident_id": 2156
}
```

**Response 200:**

```json
{
  "code": 0,
  "data": {
    "id": 5681,
    "action_type": "rate_limit",
    "target_service": "ai-service",
    "status": "success",
    "previous_state": {"max_qps": 200, "strategy": "token_bucket"},
    "new_state": {"max_qps": 50, "strategy": "token_bucket"},
    "executed_at": "2026-07-23T00:30:00+08:00",
    "rollback_deadline": "2026-07-23T01:30:00+08:00",
    "message": "限流规则已下发，预计 30s 内生效"
  }
}
```

**业务规则与安全保障:**
- **双人确认**: `action_type` 为 `service_restart`、`traffic_drain`、`scale_down` 的操作需要另一名 SRE 二次确认
- **白名单限制**: 仅 `target_service` 在允许列表中的服务可执行应急操作
- **只增不减**: `scale_up` 操作无需审批，`scale_down` 需审批
- **自动回滚**: 设置了 `auto_rollback_after_minutes` 的操作，到期后自动恢复 `previous_state`
- **审计日志**: 所有操作记录完整审计日志，包含操作前后状态快照

## 8. 关键代码示例

### 8.1 ops-workbench-service BFF 聚合查询

```java
/**
 * 系统健康总览 - 聚合多数据源
 */
@Service
@Slf4j
public class OverviewDashboardService {

    @Autowired
    private PrometheusQueryClient prometheusClient;
    @Autowired
    private AlertManagerClient alertManagerClient;
    @Autowired
    private IncidentRepository incidentRepository;
    @Autowired
    private AiCostCollectorClient costClient;
    @Autowired
    private K8sHealthClient k8sClient;
    @Autowired
    private SLOServiceClient sloServiceClient;
    @Autowired
    private ChangeRecordRepository changeRecordRepository;
    @Autowired
    private OnCallService onCallService;

    /**
     * 并行查询各数据源，超时降级
     */
    @Timeout(value = 5, unit = ChronoUnit.SECONDS)
    public OverviewDTO getOverview(String timeRange) {
        // 使用 CompletableFuture 并行查询
        CompletableFuture<List<ServiceHealthDTO>> servicesFuture =
            CompletableFuture.supplyAsync(() -> queryServiceHealth(timeRange));
        CompletableFuture<AlertSummaryDTO> alertsFuture =
            CompletableFuture.supplyAsync(() -> queryActiveAlerts());
        CompletableFuture<List<IncidentSummaryDTO>> incidentsFuture =
            CompletableFuture.supplyAsync(() -> queryActiveIncidents());
        CompletableFuture<AiCostDTO> costFuture =
            CompletableFuture.supplyAsync(() -> queryAiCostToday());
        CompletableFuture<InfrastructureDTO> infraFuture =
            CompletableFuture.supplyAsync(() -> queryInfrastructure());
        CompletableFuture<OnCallDTO> onCallFuture =
            CompletableFuture.supplyAsync(onCallService::getCurrentOnCall);
        CompletableFuture<List<ChangeRecord>> changesFuture =
            CompletableFuture.supplyAsync(() -> queryRecentChanges(24));

        try {
            CompletableFuture.allOf(
                servicesFuture, alertsFuture, incidentsFuture,
                costFuture, infraFuture, onCallFuture, changesFuture
            ).join();
        } catch (CompletionException e) {
            // 部分查询失败不阻塞整体响应，用降级值填充
            log.warn("Overview partial query failed", e);
        }

        return OverviewDTO.builder()
            .overallHealth(calculateOverallHealth(
                safeGet(servicesFuture), safeGet(alertsFuture), safeGet(incidentsFuture)))
            .healthScore(calculateHealthScore(safeGet(servicesFuture)))
            .activeAlerts(safeGet(alertsFuture))
            .activeIncidents(safeGet(incidentsFuture))
            .services(safeGet(servicesFuture))
            .aiCostToday(safeGet(costFuture))
            .infrastructure(safeGet(infraFuture))
            .onCall(safeGet(onCallFuture))
            .recentChanges24h(safeGet(changesFuture))
            .timestamp(LocalDateTime.now())
            .build();
    }

    /**
     * 健康度评分算法: 加权平均
     * - 服务可用性 40%
     * - 错误率 30%
     * - 延迟达标 20%
     * - 告警负载 10%
     */
    private int calculateHealthScore(List<ServiceHealthDTO> services) {
        if (CollectionUtils.isEmpty(services)) return 100;

        double availabilityScore = services.stream()
            .mapToDouble(s -> s.getUptime30d())
            .average().orElse(100);

        double errorRateScore = services.stream()
            .mapToDouble(s -> Math.max(0, 100 - s.getErrorRate() * 10))
            .average().orElse(100);

        double latencyScore = services.stream()
            .mapToDouble(s -> {
                // P99 延迟在阈值内得分高
                double ratio = s.getAvgLatencyP99() / s.getLatencyTargetMs();
                return Math.max(0, 100 - Math.max(0, (ratio - 1)) * 50);
            })
            .average().orElse(100);

        double alertPenalty = Math.min(30,
            services.stream().mapToInt(s -> s.getActiveCriticalAlerts()).sum() * 10);

        double score = availabilityScore * 0.4
                      + errorRateScore * 0.3
                      + latencyScore * 0.2
                      + (100 - alertPenalty) * 0.1;

        return (int) Math.round(Math.max(0, Math.min(100, score)));
    }

    private <T> T safeGet(CompletableFuture<T> future) {
        try {
            return future.getNow(null);
        } catch (Exception e) {
            return null;
        }
    }
}
```

```java
/**
 * 应急操作执行引擎 - 策略模式
 */
public interface EmergencyActionExecutor {
    String getActionType();
    EmergencyActionResult execute(EmergencyActionRequest request);
    EmergencyActionResult rollback(Long actionId);
}

@Service
public class RateLimitExecutor implements EmergencyActionExecutor {

    @Autowired
    private ConfigCenterClient configCenterClient;
    @Autowired
    private EmergencyActionRepository actionRepo;

    @Override
    public String getActionType() {
        return "rate_limit";
    }

    @Override
    @Transactional
    public EmergencyActionResult execute(EmergencyActionRequest request) {
        String service = request.getTargetService();
        String resource = request.getTargetResource();
        Map<String, Object> params = request.getActionParams();

        // 1. 记录前置状态
        RateLimitConfig currentConfig = configCenterClient.getRateLimitConfig(service, resource);
        Map<String, Object> previousState = JsonUtil.toMap(currentConfig);

        // 2. 构建新配置
        RateLimitConfig newConfig = RateLimitConfig.builder()
            .maxQps((Integer) params.get("max_qps"))
            .strategy((String) params.getOrDefault("strategy", "token_bucket"))
            .build();

        // 3. 下发配置到配置中心 (热生效)
        ConfigUpdateResult result = configCenterClient.updateRateLimitConfig(
            service, resource, newConfig);

        if (!result.isSuccess()) {
            return EmergencyActionResult.failed("配置下发失败: " + result.getError());
        }

        // 4. 写入操作记录
        EmergencyActionRecord record = EmergencyActionRecord.builder()
            .actionType("rate_limit")
            .targetService(service)
            .targetResource(resource)
            .actionParams(JsonUtil.toJson(params))
            .previousState(JsonUtil.toJson(previousState))
            .newState(JsonUtil.toJson(newConfig))
            .reason(request.getReason())
            .incidentId(request.getIncidentId())
            .status("success")
            .executedBy(request.getExecutedBy())
            .executedAt(LocalDateTime.now())
            .build();

        // 5. 设置自动回滚
        if (request.getAutoRollbackMinutes() != null && request.getAutoRollbackMinutes() > 0) {
            record.setRollbackDeadline(LocalDateTime.now()
                .plusMinutes(request.getAutoRollbackMinutes()));
            // 注册定时回滚任务
            scheduledTaskScheduler.schedule(
                () -> autoRollback(record.getId()),
                record.getRollbackDeadline().toInstant(ZoneOffset.UTC));
        }

        actionRepo.save(record);

        // 6. 推送通知
        notificationService.notifyOpsTeam(
            String.format("🚦 限流操作已执行: %s %s QPS %d→%d, 执行人: %s",
                service, resource,
                currentConfig.getMaxQps(), newConfig.getMaxQps(),
                userService.getAdminName(request.getExecutedBy())));

        return EmergencyActionResult.success(record.getId(), "限流规则已下发，预计 30s 内生效");
    }

    @Override
    @Transactional
    public EmergencyActionResult rollback(Long actionId) {
        EmergencyActionRecord record = actionRepo.findById(actionId)
            .orElseThrow(() -> new BusinessException("操作记录不存在"));

        if (!"success".equals(record.getStatus())) {
            throw new BusinessException("仅成功的操作可回滚");
        }

        // 恢复到前置状态
        Map<String, Object> previousState = JsonUtil.fromJson(record.getPreviousState());
        RateLimitConfig rollbackConfig = JsonUtil.fromMap(previousState, RateLimitConfig.class);

        configCenterClient.updateRateLimitConfig(
            record.getTargetService(), record.getTargetResource(), rollbackConfig);

        record.setRolledBackAt(LocalDateTime.now());
        record.setStatus("rolled_back");
        actionRepo.save(record);

        return EmergencyActionResult.success(null, "已回滚至原始配置");
    }
}
```

```java
/**
 * AI 调用成本聚合器
 * 数据源: ai-cost-collector 写入的 Redis 实时计数器
 */
@Service
public class AiCostAggregator {

    @Autowired
    private RedisTemplate<String, String> redis;

    private static final String KEY_COST_TODAY = "ai:cost:today:{date}:total";
    private static final String KEY_COST_BY_MODEL = "ai:cost:today:{date}:model:{model}";
    private static final String KEY_CALLS_BY_MODEL = "ai:calls:today:{date}:model:{model}";
    private static final String KEY_BUDGET_DAILY = "ai:budget:daily";

    /**
     * 增量记录一次 AI 调用成本
     */
    public void recordCall(String model, int inputTokens, int outputTokens,
                           BigDecimal costCny) {
        String today = LocalDate.now().format(DateTimeFormatter.ISO_DATE);

        redis.opsForValue().increment(
            KEY_COST_TODAY.replace("{date}", today),
            costCny.doubleValue());

        redis.opsForValue().increment(
            KEY_COST_BY_MODEL.replace("{date}", today).replace("{model}", model),
            costCny.doubleValue());

        redis.opsForValue().increment(
            KEY_CALLS_BY_MODEL.replace("{date}", today).replace("{model}", model),
            1);
    }

    /**
     * 获取今日成本概览 (从 Redis 读取，低延迟)
     */
    public AiCostOverviewDTO getTodayOverview() {
        String today = LocalDate.now().format(DateTimeFormatter.ISO_DATE);
        double totalCost = parseDouble(redis.opsForValue().get(
            KEY_COST_TODAY.replace("{date}", today)));
        double budget = parseDouble(redis.opsForValue().get(KEY_BUDGET_DAILY));

        double usagePct = budget > 0 ? (totalCost / budget * 100) : 0;

        // 预测 EOD 成本 (按小时均摊)
        int currentHour = LocalTime.now().getHour();
        double hourlyAvg = currentHour > 0 ? totalCost / (currentHour + 1) : totalCost;
        double projectedEod = hourlyAvg * 24;

        AiCostOverviewDTO dto = new AiCostOverviewDTO();
        dto.setTotalCostCny(BigDecimal.valueOf(totalCost));
        dto.setBudgetCny(BigDecimal.valueOf(budget));
        dto.setBudgetUsagePct(usagePct);
        dto.setProjectedEodCny(BigDecimal.valueOf(projectedEod));

        // 预算状态判定
        if (usagePct >= 100) {
            dto.setBudgetStatus("exceeded");
        } else if (usagePct >= 80 || projectedEod > budget) {
            dto.setBudgetStatus("warning");
        } else {
            dto.setBudgetStatus("normal");
        }

        return dto;
    }

    /**
     * 定时任务: 每分钟检查预算并发送预警
     */
    @Scheduled(fixedRate = 60_000)
    public void checkBudgetAndAlert() {
        AiCostOverviewDTO overview = getTodayOverview();

        if ("exceeded".equals(overview.getBudgetStatus())) {
            alertService.fireAlert(
                "AI Daily Budget Exceeded",
                "critical",
                String.format("今日AI调用成本 ¥%.2f 已超出预算 ¥%.2f",
                    overview.getTotalCostCny(), overview.getBudgetCny()),
                Map.of("service", "ai-cost-monitor",
                       "runbook", "https://wiki.primetop.com/runbooks/ai-budget-exceeded"));
        } else if ("warning".equals(overview.getBudgetStatus())) {
            // 80% 和 90% 各通知一次 (用 Redis 标记防重)
            String alertKey = "ai:cost:alert:" + LocalDate.now() + ":" +
                (int)(overview.getBudgetUsagePct() / 10) + "0";
            if (redis.opsForValue().setIfAbsent(alertKey, "1", Duration.ofDays(1))) {
                notificationService.notifyOpsTeam(
                    String.format("⚠️ AI成本预算预警: 已用 %.1f%%, 预计今日支出 ¥%.0f",
                        overview.getBudgetUsagePct(), overview.getProjectedEodCny()));
            }
        }
    }
}
```

### 9.1 API 错误码

| 错误码 | HTTP Status | 说明 | 处理建议 |
| --- | --- | --- | --- |

| `OPS_006` | 422 | 应急操作需要二次确认 | 等待确认人审批 |
| `OPS_007` | 408 | 底层系统查询超时(Prometheus/ES) | 自动降级返回缓存数据 |
| `OPS_008` | 503 | 底层系统不可用 | 返回降级数据 + 错误提示 |
| `OPS_009` | 422 | 回滚失败 | 检查目标服务状态 |
| `OPS_010` | 429 | 查询频率超限 | 降低查询频率 |
