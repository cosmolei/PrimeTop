# 客户端网络请求治理与弱网适配方案 - 详细设计

## 1. 概述

### 1.1 背景

PrimeTop 作为面向全学段的移动端 AI 辅助学习 APP，网络请求场景复杂且多样：AI 对话的 SSE 流式响应、拍题 OCR 的大图上传、错题本的高频读写、同步课堂的离线资源包下载、学习记录的实时上报等。移动端网络环境天然不稳定（地铁、电梯、校园 WiFi 拥堵），部分目标用户（乡村学生）甚至长期处于弱网环境。

现有各模块文档（客户端架构、离线缓存、性能优化）分别从各自角度提及了网络处理，但缺少一份统一的网络请求治理方案，定义请求分类、优先级调度、弱网检测、降级策略和离线队列等横切关注点。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **请求分级调度** | 不同业务请求按优先级排队，高优先级请求优先获得网络资源 |
| **弱网感知** | 实时检测网络质量，自动切换请求策略 |
| **离线可用** | 关键操作在无网络时本地排队，网络恢复后自动重放 |
| **流量节约** | 根据网络类型（WiFi/移动数据）自适应调整请求行为 |
| **体验一致** | 对上层业务屏蔽网络波动，提供统一的成功/失败/降级语义 |
| **可观测** | 网络质量、请求成功率、重试次数等指标可追踪 |

### 1.3 与其他文档的关系

| 文档 | 交叉点 | 本文档侧重点 |
|------|--------|-------------|
| 客户端架构与前端框架 | Dio 网络层封装 | 本文档细化 Dio 之上的请求治理层 |
| 离线缓存与数据同步 | 离线数据同步策略 | 本文档聚焦网络请求层面的队列与重放 |
| 非功能性需求-性能优化 | 首屏加载、资源预加载 | 本文档聚焦网络请求维度的优化 |
| 错误处理与服务降级 | 降级策略 | 本文档聚焦网络维度的降级 |
| 配置中心与动态配置 | 超时/重试等参数动态下发 | 本文档定义消费方的具体策略 |

## 3. 请求分类与优先级体系

### 3.1 请求通道定义

根据业务特征，将所有网络请求分为 6 个通道（Channel），每个通道有独立的优先级、并发数和超时策略。

```dart
/// 请求通道枚举
enum RequestChannel {
  /// 关键交互 - AI对话流式、拍题OCR
  /// 最高优先级，用户正在等待结果
  critical,

  /// 用户操作 - 错题收录、练习提交、作文提交
  /// 高优先级，用户刚做了操作需要确认
  userAction,

  /// 数据同步 - 学习记录上报、进度同步、答题记录
  /// 中优先级，可延迟但不能丢
  dataSync,

  /// 内容加载 - 同步课堂章节、知识点详情、题目列表
  /// 中优先级，影响浏览体验
  contentLoad,

  /// 资源下载 - 教材资源包、音频文件、图片预加载
  /// 低优先级，后台静默下载
  resourceDownload,

  /// 数据上报 - 埋点事件、崩溃日志、性能指标
  /// 最低优先级，批量合并后上报
  telemetry,
}
```

### 3.2 通道配置矩阵

| 通道 | 优先级 | 最大并发 | 默认超时 | 弱网超时 | 离线可队列 | 重试次数 |
|------|--------|---------|---------|---------|-----------|---------|
| `critical` | 100 | 3 | 15s | 30s | ❌ | 1 |
| `userAction` | 80 | 2 | 10s | 20s | ✅ | 2 |
| `dataSync` | 60 | 2 | 8s | 15s | ✅ | 3 |
| `contentLoad` | 50 | 4 | 10s | 20s | ❌ | 1 |
| `resourceDownload` | 20 | 1 | 30s | 60s | ✅ | 5 |
| `telemetry` | 10 | 1 | 5s | 10s | ✅ | 2 |

## 4. 网络质量检测引擎

### 4.1 网络质量分级

```dart
/// 网络质量等级
enum NetworkQuality {
  /// 优秀 - WiFi/5G，延迟 < 100ms，带宽充足
  excellent,

  /// 良好 - 4G/强WiFi，延迟 100-300ms
  good,

  /// 一般 - 3G/弱WiFi，延迟 300-1000ms
  fair,

  /// 差 - 2G/极弱信号，延迟 > 1000ms，高丢包
  poor,

  /// 离线 - 无网络连接
  offline,
}

/// 网络质量等级对应的数值范围
extension NetworkQualityScore on NetworkQuality {
  int get minScore => switch (this) {
    NetworkQuality.excellent => 80,
    NetworkQuality.good => 60,
    NetworkQuality.fair => 30,
    NetworkQuality.poor => 0,
    NetworkQuality.offline => -1,
  };
}
```

### 4.2 检测指标与算法

网络质量评分采用加权综合评分模型：

```
qualityScore = w1 × latencyScore + w2 × successRateScore + w3 × bandwidthScore + w4 × connectionTypeScore

其中:
  latencyScore    = max(0, 100 - (avgLatencyMs / 10))        // 延迟越低越好
  successRateScore = recentSuccessCount / recentTotalCount × 100
  bandwidthScore  = estimatedBandwidthKbps / 1000 × 100       // capped at 100
  connectionTypeScore = WiFi:100, 5G:90, 4G:70, 3G:40, 2G:10

  w1=0.3, w2=0.3, w3=0.2, w4=0.2
```

### 4.3 检测实现

```dart
/// 网络质量检测引擎
class NetworkQualityDetector {
  final Dio _dio;
  final Connectivity _connectivity;

  /// 最近 N 次请求的延迟记录（滑动窗口）
  final _recentLatencies = <_LatencyRecord>[];
  static const _maxRecords = 20;

  /// 最近 N 次请求的成功/失败统计
  int _recentSuccess = 0;
  int _recentFailure = 0;
  static const _statsWindow = 20;

  /// 当前网络质量（实时更新）
  NetworkQuality _currentQuality = NetworkQuality.good;
  NetworkQuality get currentQuality => _currentQuality;

  /// 质量变化流（供 UI 层监听显示网络提示）
  final _qualityStream = StreamController<NetworkQuality>.broadcast();
  Stream<NetworkQuality> get qualityStream => _qualityStream.stream;

  /// 连接类型
  ConnectivityResult _connectionType = ConnectivityResult.wifi;

  /// 质量检测探针端点（轻量级健康检查）
  static const _probeUrl = '/api/v1/health/ping';
  static const _probeInterval = Duration(seconds: 30);
  Timer? _probeTimer;

  /// 初始化
  Future<void> init() async {
    // 监听连接类型变化
    _connectivity.onConnectivityChanged.listen(_onConnectivityChanged);
    _connectionType = await _connectivity.checkConnectivity()
        .then((r) => r.firstOrNull ?? ConnectivityResult.none);

    // 启动定期探针
    _startProbing();

    // 初始检测
    await _probeOnce();
  }

  /// 记录一次请求结果（由 Dio 拦截器调用）
  void recordRequestResult({
    required Duration latency,
    required bool success,
    int? responseBytes,
  }) {
    // 记录延迟
    _recentLatencies.add(_LatencyRecord(
      timestamp: DateTime.now(),
      latencyMs: latency.inMilliseconds,
    ));
    if (_recentLatencies.length > _maxRecords) {
      _recentLatencies.removeAt(0);
    }

    // 记录成功/失败
    if (success) {
      _recentSuccess++;
    } else {
      _recentFailure++;
    }
    final total = _recentSuccess + _recentFailure;
    if (total > _statsWindow) {
      if (_recentSuccess > 0) _recentSuccess--;
      if (_recentFailure > 0) _recentFailure--;
    }

    // 重新计算质量
    _recalculateQuality();
  }

  void _recalculateQuality() {
    final score = _calculateScore();
    final newQuality = _scoreToQuality(score);

    if (newQuality != _currentQuality) {
      _currentQuality = newQuality;
      _qualityStream.add(newQuality);
    }
  }

  double _calculateScore() {
    if (_connectionType == ConnectivityResult.none) {
      return -1; // 离线
    }

    // 延迟得分 (w=0.3)
    final latencyScore = _recentLatencies.isEmpty
        ? 50.0 // 无数据时给中等分数
        : _recentLatencies
              .map((r) => (100 - (r.latencyMs / 10)).clamp(0, 100).toDouble())
              .reduce((a, b) => a + b) /
              _recentLatencies.length;

    // 成功率得分 (w=0.3)
    final total = _recentSuccess + _recentFailure;
    final successScore = total == 0 ? 50.0 : (_recentSuccess / total) * 100;

    // 连接类型得分 (w=0.2)
    final typeScore = switch (_connectionType) {
      ConnectivityResult.wifi => 100.0,
      ConnectivityResult.mobile => 70.0, // 简化，实际应细分 5G/4G/3G
      ConnectivityResult.ethernet => 100.0,
      _ => 30.0,
    };

    // 带宽得分 (w=0.2) - 简化：根据连接类型估算
    final bandwidthScore = typeScore; // 简化处理

    return 0.3 * latencyScore +
           0.3 * successScore +
           0.2 * bandwidthScore +
           0.2 * typeScore;
  }

  NetworkQuality _scoreToQuality(double score) {
    if (score < 0) return NetworkQuality.offline;
    if (score >= 80) return NetworkQuality.excellent;
    if (score >= 60) return NetworkQuality.good;
    if (score >= 30) return NetworkQuality.fair;
    return NetworkQuality.poor;
  }

  Future<void> _probeOnce() async {
    try {
      final stopwatch = Stopwatch()..start();
      await _dio.get(_probeUrl).timeout(const Duration(seconds: 5));
      stopwatch.stop();
      recordRequestResult(
        latency: stopwatch.elapsed,
        success: true,
      );
    } catch (_) {
      recordRequestResult(
        latency: const Duration(seconds: 5),
        success: false,
      );
    }
  }

  void _startProbing() {
    _probeTimer?.cancel();
    _probeTimer = Timer.periodic(_probeInterval, (_) => _probeOnce());
  }

  void _onConnectivityChanged(List<ConnectivityResult> results) {
    final result = results.firstOrNull ?? ConnectivityResult.none;
    if (result != _connectionType) {
      _connectionType = result;
      // 网络类型变化时立即探测
      if (result != ConnectivityResult.none) {
        _probeOnce();
        // 网络恢复时触发离线队列重放
        if (_currentQuality == NetworkQuality.offline) {
          _recalculateQuality();
        }
      } else {
        _currentQuality = NetworkQuality.offline;
        _qualityStream.add(NetworkQuality.offline);
      }
    }
  }

  void dispose() {
    _probeTimer?.cancel();
    _qualityStream.close();
  }
}

class _LatencyRecord {
  final DateTime timestamp;
  final int latencyMs;
  _LatencyRecord({required this.timestamp, required this.latencyMs});
}
```

## 5. 优先级调度器

### 5.1 调度策略

调度器维护每个通道的待执行请求队列，按优先级从高到低调度：

1. 每个通道维护一个 FIFO 队列
2. 全局调度器按通道优先级轮转选取请求
3. 同通道内的并发数受 `maxConcurrency` 限制
4. 低优先级通道在弱网时自动暂停（`resourceDownload`、`telemetry`）

### 5.2 调度器实现

```dart
/// 优先级调度器
class PriorityScheduler {
  final NetworkQualityDetector _qualityDetector;

  /// 每个通道的待执行队列
  final Map<RequestChannel, Queue<_QueuedRequest>> _queues = {};

  /// 每个通道当前执行中的请求数
  final Map<RequestChannel, int> _runningCount = {};

  /// 全局调度锁
  final _scheduleLock = Mutex();

  PriorityScheduler(this._qualityDetector) {
    for (final channel in RequestChannel.values) {
      _queues[channel] = Queue();
      _runningCount[channel] = 0;
    }
  }

  /// 提交请求到调度器
  Future<Response> submit({
    required RequestChannel channel,
    required Future<Response> Function() executor,
    required Duration timeout,
    int retryCount = 0,
  }) {
    final completer = Completer<Response>();
    final config = kChannelConfigs[channel]!;

    final request = _QueuedRequest(
      channel: channel,
      executor: executor,
      timeout: timeout,
      maxRetries: retryCount > 0 ? retryCount : config.maxRetries,
      completer: completer,
      enqueuedAt: DateTime.now(),
    );

    _queues[channel]!.add(request);
    _schedule();

    return completer.future;
  }

  /// 触发调度
  void _schedule() {
    // 不用锁的方式：用 scheduleMicrotask 避免递归
    scheduleMicrotask(() => _doSchedule());
  }

  Future<void> _doSchedule() async {
    await _scheduleLock.acquire();
    try {
      final quality = _qualityDetector.currentQuality;

      // 按优先级从高到低遍历通道
      final sortedChannels = RequestChannel.values.toList()
        ..sort((a, b) =>
            kChannelConfigs[b]!.priority.compareTo(kChannelConfigs[a]!.priority));

      for (final channel in sortedChannels) {
        final config = kChannelConfigs[channel]!;

        // 弱网时暂停低优先级通道
        if (_shouldPauseChannel(channel, quality)) {
          continue;
        }

        // 填充该通道的并发槽位
        while (_runningCount[channel]! < config.maxConcurrency &&
               _queues[channel]!.isNotEmpty) {
          final request = _queues[channel]!.removeFirst();
          _runningCount[channel] = _runningCount[channel]! + 1;
          _executeRequest(request, config);
        }
      }
    } finally {
      _scheduleLock.release();
    }
  }

  /// 判断通道是否应在当前网络质量下暂停
  bool _shouldPauseChannel(RequestChannel channel, NetworkQuality quality) {
    return switch (quality) {
      NetworkQuality.poor =>
        // 弱网时只保留 critical 和 userAction
        channel == RequestChannel.resourceDownload ||
        channel == RequestChannel.telemetry ||
        channel == RequestChannel.contentLoad,
      NetworkQuality.fair =>
        // 一般网络时暂停资源下载和埋点
        channel == RequestChannel.resourceDownload ||
        channel == RequestChannel.telemetry,
      _ => false,
    };
  }

  Future<void> _executeRequest(
    _QueuedRequest request,
    ChannelConfig config,
  ) async {
    int attempt = 0;
    while (attempt <= request.maxRetries) {
      try {
        final response = await request.executor()
            .timeout(request.timeout);
        request.completer.complete(response);
        return;
      } on TimeoutException {
        attempt++;
        if (attempt > request.maxRetries) {
          request.completer.completeError(
            NetworkTimeoutException(channel: request.channel),
          );
          break;
        }
        // 指数退避
        await Future.delayed(Duration(seconds: pow(2, attempt).toInt()));
      } catch (e) {
        attempt++;
        if (attempt > request.maxRetries) {
          request.completer.completeError(e);
          break;
        }
        await Future.delayed(Duration(milliseconds: 500 * attempt));
      } finally {
        _runningCount[request.channel] =
            _runningCount[request.channel]! - 1;
        _schedule(); // 触发下一轮调度
      }
    }
  }

  /// 取消某个通道的所有排队请求
  void cancelChannel(RequestChannel channel) {
    final queue = _queues[channel]!;
    while (queue.isNotEmpty) {
      final request = queue.removeFirst();
      request.completer.completeError(
        RequestCancelledException(channel: channel),
      );
    }
  }
}

class _QueuedRequest {
  final RequestChannel channel;
  final Future<Response> Function() executor;
  final Duration timeout;
  final int maxRetries;
  final Completer<Response> completer;
  final DateTime enqueuedAt;
  int retryCount = 0;

  _QueuedRequest({
    required this.channel,
    required this.executor,
    required this.timeout,
    required this.maxRetries,
    required this.completer,
    required this.enqueuedAt,
  });
}
```

## 6. 离线队列管理器

### 6.1 设计原则

1. **只队列幂等操作**：只有安全可重试的请求才进入离线队列（GET、部分幂等 POST）
2. **持久化存储**：队列数据写入本地 SQLite，APP 重启后不丢失
3. **优先级继承**：入队时继承通道优先级，重放时按优先级执行
4. **过期清理**：超过 TTL 的队列请求自动清理，避免陈旧数据回放
5. **容量限制**：队列总量有上限，防止磁盘溢出

### 6.2 可队列操作清单

| 业务操作 | HTTP 方法 | 幂等性 | 离线队列 | TTL |
|----------|----------|--------|---------|-----|
| 学习记录上报 | POST | 幂等（基于 idempotency_key） | ✅ | 24h |
| 答题记录提交 | POST | 幂等（基于 attempt_id） | ✅ | 24h |
| 错题收录 | POST | 幂等（去重检查） | ✅ | 72h |
| 学习进度同步 | PUT | 幂等 | ✅ | 48h |
| 笔记/收藏操作 | POST | 幂等（idempotency_key） | ✅ | 72h |
| 埋点事件上报 | POST | 非严格幂等（允许少量重复） | ✅ | 12h |
