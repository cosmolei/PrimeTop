## 2. 领域模型

### 2.1 核心实体关系

```
User (用户)
 ├── Wallet (钱包, 1:1)
 │    ├── CoinBalance (学币余额)
 │    ├── ExpBalance (经验值累计)
 │    └── StarBalance (星光余额)
 ├── WalletTransaction (交易流水, 1:N)
 ├── DailyEarnCap (每日获取上限, 1:1 per day)
 └── EarnRuleHitLog (规则命中日志, 1:N)

EarnRule (获取规则)
 └── EarnRuleCondition (触发条件, 1:N)

ConsumeRule (消耗规则)
 └── ConsumeRuleItem (消耗项, 1:N)
```

### 2.2 货币类型枚举

```java
public enum CurrencyType {

    private final String code;
    private final String name;

}
```

## 3. 数据库设计

### 3.1 用户钱包表 `user_wallet`

> 每个用户一条记录，余额字段使用 `DECIMAL(20,2)` 保证精度。

```sql
CREATE TABLE user_wallet (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    user_id         BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    currency_type   VARCHAR(16)     NOT NULL COMMENT '货币类型: COIN/EXP/STAR',
    balance         DECIMAL(20,2)   NOT NULL DEFAULT 0.00 COMMENT '当前余额',
    total_earned    DECIMAL(20,2)   NOT NULL DEFAULT 0.00 COMMENT '累计获取总量',
    total_consumed  DECIMAL(20,2)   NOT NULL DEFAULT 0.00 COMMENT '累计消耗总量',
    version         INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    created_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_currency (user_id, currency_type),
    KEY idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户虚拟资产钱包';
```

### 3.2 交易流水表 `wallet_transaction`

> 所有积分变动都产生流水记录，不可修改、不可删除（仅追加）。

```sql
CREATE TABLE wallet_transaction (
    id                  BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '流水ID',
    transaction_no      VARCHAR(64)     NOT NULL COMMENT '交易流水号(全局唯一, 幂等键)',
    user_id             BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    currency_type       VARCHAR(16)     NOT NULL COMMENT '货币类型',
    transaction_type    VARCHAR(32)     NOT NULL COMMENT '交易类型(枚举code)',
    amount              DECIMAL(20,2)   NOT NULL COMMENT '变动金额(正数=获取, 负数=消耗)',
    balance_before      DECIMAL(20,2)   NOT NULL COMMENT '交易前余额',
    balance_after       DECIMAL(20,2)   NOT NULL COMMENT '交易后余额',
    biz_type            VARCHAR(32)     NOT NULL COMMENT '业务来源类型',
    biz_id              VARCHAR(128)    NOT NULL DEFAULT '' COMMENT '业务ID(如题目ID/订单ID)',
    rule_id             BIGINT UNSIGNED NULL COMMENT '触发的规则ID',
    earn_cap_snapshot   DECIMAL(20,2)   NULL COMMENT '获取时当日上限快照',
    remark              VARCHAR(512)    NOT NULL DEFAULT '' COMMENT '备注',
    idempotent_key      VARCHAR(128)    NOT NULL DEFAULT '' COMMENT '幂等键(bizType+bizId防重)',
    created_at          DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_transaction_no (transaction_no),
    UNIQUE KEY uk_idempotent (user_id, idempotent_key),
    KEY idx_user_currency_time (user_id, currency_type, created_at DESC),
    KEY idx_biz (biz_type, biz_id),
    KEY idx_type_time (transaction_type, created_at DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='虚拟资产交易流水';
```

### 3.3 每日获取上限追踪表 `daily_earn_cap`

> 跟踪用户每日各类行为的积分获取累计值，用于上限判定。

```sql
CREATE TABLE daily_earn_cap (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id         BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    currency_type   VARCHAR(16)     NOT NULL COMMENT '货币类型',
    earn_date       DATE            NOT NULL COMMENT '获取日期',
    daily_total     DECIMAL(20,2)   NOT NULL DEFAULT 0.00 COMMENT '当日已获取总量',
    behavior_stats  JSON            NOT NULL COMMENT '各行为当日获取明细 {behaviorCode: amount}',
    version         INT UNSIGNED    NOT NULL DEFAULT 0,
    created_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_date_currency (user_id, earn_date, currency_type),
    KEY idx_date (earn_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='每日积分获取上限追踪';
```


## 4. API 接口设计

### 4.1 积分获取触发接口

**POST** `/api/v1/wallet/earn`

> 由各业务服务调用（内部 RPC / Feign），触发积分获取。

**请求体：**

```json
{
    "userId": 100234,
    "transactionType": "EARN_EXERCISE_CORRECT",
    "bizType": "EXERCISE",
    "bizId": "ex_20260603_a8f3c",
    "idempotentKey": "EXERCISE:ex_20260603_a8f3c",
    "context": {
        "subject": "MATH",
        "questionId": 45678,
        "isCorrect": true,
        "studyDurationSec": 45,
        "membershipLevel": "MONTHLY"
    }
}
```

**响应体：**

```json
{
    "code": 0,
    "message": "success",
    "data": {
        "transactionNo": "TXN20260603150200001",
        "currencyType": "COIN",
        "amount": 5,
        "balanceAfter": 128.00,
        "dailyEarned": 85.00,
        "dailyCap": 200.00,
        "capped": false,
        "ruleCode": "EARN_EXERCISE_CORRECT"
    }
}
```

**异常场景：**

| HTTP状态码 | 业务码 | 说明 |
|-----------|--------|------|
| 200 | `EARN_CAPPED` | 已达每日上限，amount=0, capped=true |
| 200 | `EARN_RULE_DISABLED` | 规则已禁用，不触发获取 |
| 409 | `DUPLICATE_REQUEST` | 幂等键重复，返回原交易结果 |
| 400 | `INVALID_PARAM` | 参数校验失败 |
| 429 | `RATE_LIMITED` | 请求频率超限 |

## 5. 核心流程设计

### 5.1 积分获取流程

```
业务服务                         积分服务                           缓存/DB
  │                                │                                │
  │  1. POST /wallet/earn          │                                │
  │───────────────────────────────>│                                │
  │                                │  2. 幂等性检查                   │
  │                                │───────────────────────────────>│ Redis GET idempotent:{key}
  │                                │<───────────────────────────────│
  │                                │                                │
  │                                │  [重复请求] → 返回原交易结果      │
  │                                │                                │
  │                                │  3. 查询规则                    │
  │                                │───────────────────────────────>│ DB/Redis: earn_rule
  │                                │<───────────────────────────────│
  │                                │                                │
  │                                │  4. 规则条件评估                 │
  │                                │  (condition_expr 校验)          │
  │                                │                                │
  │                                │  5. 计算奖励金额                 │
  │                                │  (静态值 or reward_expr)         │
  │                                │                                │
  │                                │  6. 获取分布式锁                 │
  │                                │  LOCK wallet:earn:{userId}:{}  │
  │                                │                                │
  │                                │  7. 检查每日上限                 │
  │                                │───────────────────────────────>│ DB: daily_earn_cap
  │                                │<───────────────────────────────│
  │                                │                                │
  │                                │  [超上限] → 返回 EARN_CAPPED    │
  │                                │                                │
  │                                │  8. 计算实际可发放金额            │
  │                                │     actualAmount = min(         │
  │                                │       rewardAmount,             │
  │                                │       dailyCap - dailyEarned)   │
  │                                │                                │
```

**过期执行细则：**

| 规则 | 说明 |
|------|------|
| 过期时点 | `expire_at` 精确到秒, 扫描容差为前一自然日 00:00 前到期的全部批次 |
| 过期金额来源 | 仅批次 `remaining` 字段, **不重复计算**钱包余额(批次是 SSOT) |
| 钱包扣减守恒 | 若 `Σ(有效批次remaining) ≠ wallet.balance` 触发 G6 守卫: 告警 P1 + 差额挂起人工, **不强扣、不放过期** |
| 过期不退不补 | 过期流水 `remark` 记录批次清单, 用户可在流水详情看到每笔过期来源 |
| 通知失败 | 过期执行与通知解耦, 通知失败仅重试不回滚过期事实(Outbox 异步) |
| 幂等 | 过期流水 `idempotent_key = EXPIRE:{userId}:{date}`, 重跑撞唯一键即跳过 |

| 场景 | 退回批次 expire_at | 理由 |
|------|--------------------|------|
| 原批次未过期 | **重新起算 12 个月** | 履约失败非用户过错, 不应让用户承担「退回即过期」损失 |

#### 5.5.1 划扣的 FIFO 批次联动

司法划扣真实扣减余额时, 必须同步按 FIFO 消耗 `coin_expire_batch`(否则批次守恒被破坏):

```sql
-- 与钱包扣减同事务, 按过期时间升序逐批扣
UPDATE coin_expire_batch
SET remaining = remaining - LEAST(remaining, #{deductRemaining}),
    status = CASE WHEN remaining - LEAST(remaining, #{deductRemaining}) <= 0 THEN 3 ELSE 1 END
WHERE id = #{batchId}
  AND status IN (0, 1)
  AND remaining > 0;
```

**冻结语义边界（契约 R7）：**

| 动作 | wallet_transaction | 钱包 balance | frozen_balance | 说明 |
|------|--------------------|--------------|----------------|------|
| freeze | 不产生 | 不变 | +=X | 冻结只是可用性限制 |
| release | 不产生 | 不变 | -=X | 解冻恢复可用 |
| deductFrozen | SYSTEM_ADJUST_SUB | -=amt | -=amt | 划扣才真实出账 |
| 过期遇冻结 | SYSTEM_EXPIRE | -=remaining | 不变 | 冻结额不参与过期(冻结的是可用性, 批次仍可能过期; 过期扣的是 balance, 若 balance 不足触发 G6 挂起) |

### 5.8 余额预检与快速失败(Lua 镜像)

> 对齐《端到端流程设计-会员订阅与增值服务购买完整链路》§6.3「负余额保护由额度管控引擎与本服务统一定义」的契约: **DB 条件更新为权威, Redis Lua 预检为快速失败优化**。

```
  │                                │                            │
  │                                │  3. 镜像充足→返回 OK         │
```

镜像同步策略: 每笔结算事务提交后异步 `HSET wallet:mirror:{userId} balance`(TTL 无, 账号注销时清理); 镜像丢失时 Lua 返回 MISS → 回源 DB 并回填。**镜像只用于预检, 永不作为记账依据**(D1 降级: Redis 宕机直接回源 DB, 功能无损)。

### 5.9 等级与经验值联动

本服务只负责 EXP 记账与事件发布, 等级计算/升级仪式/称号归《积分与虚拟经济体系》等级引擎:

```
积分服务 ──wallet.earned(currency=EXP)──> 等级计算服务
                                          │ SELECT user_level FOR UPDATE
                                          │ 累计 EXP → 判定升级
                                          ├──升级──> 全屏庆祝推送(SSE) + 称号发放
                                          │           + wallet.level.up 事件(成就引擎消费)
                                          └──未升级──> 静默
```

守卫: 等级计算幂等键 = `(transactionNo)`, 事件重放不会重复触发升级仪式(等级服务侧 CAS)。

```java
public class EarnService {

    /**
     * 核心入账: 全部写操作在同一本地事务(G14), Outbox 同事务落库。
     * 幂等三层: Redis 抢占(快速) → uk_idempotent(权威) → 请求参数重放。
     */
    @Transactional(rollbackFor = Exception.class)
    public EarnResult earn(EarnRequest req) {
        // 1. 规则快照(进行中请求不受热更新影响, G13)
        EarnRule rule = ruleRepository.findSnapshot(req.getTransactionType());
        if (rule == null) throw new WalletException(57902);
        if (!rule.isEnabled() || !rule.inEffect(now)) {
            return EarnResult.ruleDisabled();          // 200 语义 EARN_RULE_DISABLED
        }

        // 2. 条件评估(condition_expr)
        if (!conditionEvaluator.evaluate(rule.getConditionExpr(), req.getContext())) {
            return EarnResult.conditionNotMet();       // 200 语义 EARN_CONDITION_NOT_MET
        }

        // 3. 奖励金额(base + membership_bonus + reward_expr 动态加成)
        BigDecimal reward = rewardCalculator.calculate(rule, req.getContext());

        // 4. 分布式锁(锁粒度: 用户+货币, 与消费/退款/冻结同锁域互斥)
        String lockKey = "wallet:op:" + req.getUserId();
        return distributedLocks.execute(lockKey, Duration.ofSeconds(3), () -> {

            // 5. 幂等回放(权威层)
            WalletTransaction existed = txRepository
                .findByIdempotentKey(req.getIdempotentKey());
            if (existed != null) return EarnResult.replay(existed);   // G12

            // 6. 每日上限(原子 UPSERT + 条件累加)
            BigDecimal dailyCap = capResolver.resolve(rule, req.getContext()); // 普通200/会员300 取 MAX
            BigDecimal actual = capAccumulator.tryAccumulate(
                req.getUserId(), rule, reward, dailyCap);              // G-日上限
            if (actual.compareTo(BigDecimal.ZERO) <= 0) {
                return EarnResult.capped(dailyCap);    // 200 语义 EARN_CAPPED
            }

            // 7. 钱包条件更新(乐观锁, 重试 3 次)
            Wallet wallet = walletRepository.lockOrRetry(
                req.getUserId(), rule.getCurrencyType(), actual, true);

            // 8. 流水(同事务)
            WalletTransaction tx = WalletTransaction.earn(
                wallet, req, rule, actual, dailyCap);
            txRepository.insert(tx);                    // uk 冲突→回滚重放(G12)

            // 9. COIN 生成过期批次
            if (rule.getCurrencyType() == CurrencyType.COIN) {
                batchRepository.insert(ExpireBatch.of(tx, now.plusMonths(12)));
            }

            // 10. Outbox 同事务(G14): wallet.earned + economy MINT
            outbox.append(tx.toOutboxEvents());

            return EarnResult.success(tx, wallet);
        });
    }
}
```

### 6.3 消费扣减与 FIFO 批次消耗（同事务）

```java
@Transactional(rollbackFor = Exception.class)
public ConsumeResult consume(ConsumeRequest req) {
    ConsumeRule rule = ruleRepository.findConsumeRule(
        req.getConsumeRuleCode(), req.getTargetType(), req.getTargetId());
    if (rule == null || !rule.isEnabled()) throw new WalletException(57908);

    // F2 修复(v1.0 缺陷): 金额漂移防护
    if (req.getExpectedCost() != null
            && req.getExpectedCost().compareTo(rule.getCostAmount()) != 0) {
        throw new WalletException(57911);              // COST_CHANGED
    }

    return distributedLocks.execute("wallet:op:" + req.getUserId(),
      Duration.ofSeconds(3), () -> {
        // 幂等回放
        WalletTransaction existed = txRepository.findByIdempotentKey(req.getIdempotentKey());
        if (existed != null) return ConsumeResult.replay(existed);

        // F3 修复: 规则级库存条件扣减(防超卖); 商品级库存归商城服务
        if (rule.getStock() >= 0
                && ruleRepository.deductStock(rule.getId()) != 1) {
            throw new WalletException(57909);          // STOCK_INSUFFICIENT
        }

        // 钱包条件更新: 负余额保护权威层(G1)
        // UPDATE user_wallet SET balance = balance - #{amt},
        //   total_consumed = total_consumed + #{amt}, version = version + 1
        // WHERE user_id=? AND currency_type=?
        //   AND (balance - frozen_balance) >= #{amt}   ← 可用余额(扣除冻结)
        //   AND version = #{version}
        Wallet wallet = walletRepository
            .conditionalConsume(req.getUserId(), rule.getCurrencyType(),
                                rule.getCostAmount());
        if (wallet == null) {                          // 余额不足回滚库存
            ruleRepository.restoreStock(rule.getId());
            throw new WalletException(57907);          // INSUFFICIENT_BALANCE
        }

        // FIFO 批次消耗(仅 COIN, expire_at 升序, G5)
        int batches = batchRepository.consumeFifo(
            req.getUserId(), rule.getCostAmount());

        WalletTransaction tx = WalletTransaction.consume(wallet, req, rule);
        txRepository.insert(tx);
        outbox.append(tx.toOutboxEvents());            // wallet.consumed + BURN

        return ConsumeResult.success(tx, wallet, batches);
    });
}
```

### 6.4 退款服务（RefundService）

```java
@Transactional(rollbackFor = Exception.class)
public RefundResult refund(RefundRequest req) {
    return distributedLocks.execute("wallet:op:" + req.getUserId(),
      Duration.ofSeconds(3), () -> {
        // 幂等: REFUND:{originalTxNo} 天然唯一(一笔消耗流水只允许退一次, G3)
        WalletTransaction origin = txRepository
            .findByTransactionNoForUpdate(req.getOriginalTxNo());
        if (origin == null) throw new WalletException(57915);
        if (origin.getAmount().signum() >= 0
                || origin.getRefundedBy() != null) {
            throw new WalletException(57916);          // 不可退款/已退
        }
        if (origin.getCreatedAt().isBefore(now.minusDays(180))) {
            throw new WalletException(57917);          // 退款窗口 180 天
        }

        BigDecimal refundAmt = origin.getAmount().abs();

        // 批次重新起算 12 个月(§5.4 裁决)
        ExpireBatch batch = batchRepository.insert(
            ExpireBatch.refundOf(origin, now.plusMonths(12)));

        Wallet wallet = walletRepository
            .conditionalRefund(origin.getUserId(), origin.getCurrencyType(), refundAmt);

        WalletTransaction tx = WalletTransaction.refundOf(origin, wallet, req.getReason());
        txRepository.insert(tx);
        origin.markRefunded(tx.getTransactionNo());      // related 回写

        outbox.append(tx.toOutboxEvents());              // wallet.refunded + MINT
        return RefundResult.success(tx, batch);
    });
}
```

```java
        }
        return FreezeResponse.accepted();
```

## 8. 幂等与并发控制

### 8.1 幂等键设计总表

| 场景 | 幂等键 | 生成方 | 冲突行为 |
|------|--------|--------|----------|
| 学习行为入账 | 调用方传入 `bizType:bizId` | 业务服务 | 回放原交易 |
| 消费/兑换 | `EXCHANGE:{targetId}:{yyyymmdd}` 或调用方指定 | 商城服务 | 回放原交易 |
| 退款 | `REFUND:{originalTxNo}` (确定性) | 本服务 | 原流水 related 回写双重防护 |
| 过期执行 | `EXPIRE:{userId}:{date}` (确定性) | 本服务 | 跳过 |
| 过期提醒 | `EXPREMIND:{userId}:{expireDate}:{days}` | 本服务 | 跳过 |
| 系统调整 | `ADJUST:{bizType}:{bizId}` 或 `approvalNo` | 调用方/审批器 | 回放 |
| 司法冻结/解冻/划扣 | `freezeId` / `releaseId` / `deductId` | LERMS | 回放当前状态 |
| 运营日预算 | `ops_budget:{userId}:{date}` (Redis INCR, 非幂等键) | 本服务 | 超限拒绝 |

> v1.0 缺陷 F1 修复: 原 DDL `idempotent_key DEFAULT ''` 会让无幂等语义的批量操作(如过期)互相撞键。裁决: **所有插入流水的路径必须携带确定性幂等键**(见上表), 应用层强制非空, DDL 同步收紧为 `NOT NULL`(去掉 DEFAULT '')。

### 8.2 并发场景裁决八则

| # | 场景 | 时序 | 裁决 |
|---|------|------|------|
| C1 | 同一学习行为双服务重复触发(如判题重试后再发事件) | 两请求同 idempotentKey | 后到者在步骤 5/8 被拦截回放, 不双发(事件层再兑底 event_id=transactionNo 去重) |
| C2 | 双设备同时兑换同一商品 | 同 idempotentKey 不同锁批次 | 先后串行, 后者回放; 不同幂等键则余额条件更新裁决, 不足者 57907 |
| C3 | 消费与退款并发(退款到达时另一笔消费正在扣 FIFO) | 同锁域 G7 | 串行; 退款不依赖批次态, 只认原流水 |
| C4 | 过期扫描与消费并发 | 过期锁 wallet:expire:{uid} 与消费锁 wallet:op:{uid} 不同 | 过期前已锁定批次集内快照; 批次被消费后 status 变更, 过期更新行数=0 自动跳过(条件 UPDATE 兑底) |
| C5 | 冻结与消费并发 | 同锁域 G7 | 串行; 可用余额条件更新保证冻结额不可消费 |
| C6 | 管理端调整与用户消费并发 | 同锁域 G7 | 串行; 乐观锁重试 3 次后 57924 |
| C7 | 规则热更新与进行中请求 | 请求开始时读快照 G13 | 请求内用旧规则完成, 不产生半新半旧 |
| C8 | Outbox Relay 与事务提交竞态 | Relay 轮询 SKIP LOCKED | 未提交不可见, 提交后必达; 至少一次语义 + 消费方幂等 |

### 8.3 分布式锁规格

| 项 | 规格 |
|----|------|
| 锁键 | `wallet:op:{userId}`(全局操作锁); `wallet:expire:{userId}`(过期扫描, 与操作锁独立) |
| 超时 | 3s(获取)/10s(持有自动过期), 释放前校验 token 防误删 |
| 重试 | 获取不重试直接 57924(客户端退避重试), 避免雪崩 |
| 兑底 | 锁服务容灾时降级 DB `SELECT ... FOR UPDATE` 行锁串行(D3), 性能下降但正确性不变 |

### 12.2 日终对账四恒等式

1. **钱包恒等式**: 每用户 `balance = Σ(流水 amount) - 0`(全量流水代数和 = 当前余额); 差异>0.01 → P1 自动修复前先冻结该用户变更并告警(修复单向: 以流水重建钱包, 镜像失效)。
2. **批次守恒**: `Σ(未终态批次 remaining) = wallet.balance`(COIN); 分账户对账。
3. **冻结守恒**: `user_wallet.frozen_balance = Σ(FROZEN/PARTIAL 冻结单 remaining)`; 与 LERMS 指令状态机交叉对账(指令态↔资产态映射表)。
4. **经济守恒**: 日 `ΣMINT - ΣBURN - ΣEXPIRE = Σ当日流水正负代数和`(economy.events vs wallet_transaction 双源对账, 平衡引擎双向校验)。
