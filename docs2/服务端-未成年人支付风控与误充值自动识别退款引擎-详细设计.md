## 1. 模块概述

### 1.1 设计背景

启硕 PrimeTop 面向 K12 全学段用户，核心用户群包含大量未成年人。根据中国《未成年人保护法》《未成年人网络保护条例》《关于防止未成年人沉迷网络游戏的通知》等法规要求，以及 Apple App Store / Google Play 的相关合规政策，教育类 APP 必须建立完善的未成年人支付保护机制：

1. **法规要求**：未成年人未经监护人同意进行的网络消费，监护人有权要求退款。
2. **平台合规**：App Store 和 Google Play 对未成年人应用内购有严格审核要求。
3. **用户体验**：误充值引发的客诉若处理不当，将导致差评、投诉升级和品牌损失。
4. **风控需求**：恶意退款请求也需要被有效识别和拦截，保障平台营收安全。

### 1.2 功能目标

构建一套覆盖**事前拦截、事中监控、事后处理**的全链路支付风控引擎：

| 阶段 | 核心能力 |
| --- | --- |
| 事前拦截 | 支付前风险评估、未成年人操作识别、支付密码验证、家长授权校验 |
| 事中监控 | 异常支付行为实时检测、高频消费拦截、大额消费预警 |
| 事后处理 | 误充值自动识别、退款申请智能分拣、自动化退款执行、人工审核工作台 |

### 1.3 设计原则

1. **未成年人优先**：在风险与体验冲突时，优先保护未成年人权益。
2. **自动为主、人工为辅**：标准化场景自动处理，复杂场景人工介入。
3. **可审计可追溯**：所有风控决策保留完整推理链路和审计日志。
4. **合规驱动**：严格遵循教育类产品支付合规要求。

### 2.2 核心服务职责

| 服务 | 职责 | 部署方式 |
| --- | --- | --- |
| RiskPreCheck | 支付前风险评估与拦截决策 | 同步调用，<100ms 响应 |
| RiskMonitor | 实时支付行为监控与异常告警 | 异步事件驱动 |
| RefundProcess | 退款申请接收、分拣、执行 | 混合（自动+人工） |
| RuleEngine | 风控规则管理与执行 | 同步+异步 |

| RefundDecisionEngine | 退款决策（自动批准/拒绝/转人工） | 同步调用 |

## 4. 事前风控：支付前风险评估

### 4.1 风控检查流程

```
用户发起支付请求
        │
        ▼
┌───────────────────┐
│ 1. 基础身份校验    │ ── 用户是否存在、是否登录态有效
└───────┬───────────┘
        │ pass
        ▼
┌───────────────────┐
│ 2. 支付权限校验    │ ── 支付管控状态检查（冻结/禁止？）
└───────┬───────────┘
        │ pass
        ▼
┌───────────────────┐
│ 3. 未成年人专项检查 │ ── 是否未成年？家长是否授权？家长支付密码？
└───────┬───────────┘
        │ pass / challenge
        ▼
┌───────────────────┐
│ 4. 规则引擎评估    │ ── 频次/金额/设备/行为模式等规则匹配
└───────┬───────────┘
        │
        ▼
┌───────────────────────────────────────┐
│ 5. 综合决策                           │
│   risk_score < 30 → PASS              │
│   30 ≤ risk_score < 60 → CHALLENGE    │
│   60 ≤ risk_score < 80 → REVIEW       │
│   risk_score ≥ 80 → BLOCK             │
└───────────────────────────────────────┘
```

```java
     * @return 检查结果
     */
    public PreCheckResult check(MinorPaymentContext context) {
        Long userId = context.getUserId();
        RiskProfile profile = profileService.getOrInit(userId);

        // Step 1: 判断是否未成年人
        if (!profile.isMinor()) {
            return PreCheckResult.pass();
        }

        // Step 2: 检查支付管控状态
        if (profile.getPaymentStatus() == PaymentControlStatus.PERMANENT_BAN.getCode()) {
            return PreCheckResult.block("ACCOUNT_PAYMENT_BANNED", 
                "该账号已被禁止支付：" + profile.getFrozenReason());
        }
        if (profile.getPaymentStatus() == PaymentControlStatus.FROZEN_TEMP.getCode()) {
            if (profile.getFrozenUntil() != null 
                && profile.getFrozenUntil().isAfter(LocalDateTime.now())) {
                return PreCheckResult.block("ACCOUNT_PAYMENT_FROZEN",
                    "该账号支付功能暂时冻结，解冻时间：" + profile.getFrozenUntil());
            }
        }

        // Step 3: 金额限制检查
        BigDecimal amount = context.getAmount();
        if (profile.getPaymentLimitSingle() != null 
            && amount.compareTo(profile.getPaymentLimitSingle()) > 0) {
            return PreCheckResult.block("EXCEED_SINGLE_LIMIT",
                String.format("单笔支付限额 ¥%.2f，当前金额 ¥%.2f", 
                    profile.getPaymentLimitSingle(), amount));
        }

        // Step 4: 家长授权校验
        ParentAuthorizationResult authResult = checkParentAuthorization(context, profile);
        if (!authResult.isPassed()) {
            return authResult.toPreCheckResult();
        }

        // Step 5: 24小时/7天 累计限额检查
        if (exceedsCumulativeLimit(profile, amount)) {
            return PreCheckResult.block("EXCEED_CUMULATIVE_LIMIT",
                "超出周期内累计支付限额");
        }

        // Step 6: 高风险行为模式检测
        RiskPatternResult patternResult = detectRiskPattern(context, profile);
        if (patternResult.getRiskLevel() >= RiskLevel.HIGH) {
            return PreCheckResult.review("HIGH_RISK_PATTERN_DETECTED", 
                patternResult.getDetail());
        }

        return PreCheckResult.pass();
    }

    /**
     * 家长授权校验
     */
    private ParentAuthorizationResult checkParentAuthorization(
            MinorPaymentContext context, RiskProfile profile) {
        // 未绑定家长：根据金额和频次决定是否需要绑定
        if (!profile.isParentBound()) {
            BigDecimal amount = context.getAmount();
            // 超过阈值必须绑定家长才能支付
            if (amount.compareTo( minorPaymentConfig.getRequireParentBindThreshold()) >= 0) {
                return ParentAuthorizationResult.requireParentBinding(
                    "根据未成年人保护要求，支付 ¥" 
                    + minorPaymentConfig.getRequireParentBindThreshold() 
                    + " 以上需要绑定家长账号");
            }
            // 首次支付需要引导绑定（但不强制阻断）
            if (profile.getTotalPaymentCount() == 0) {
                return ParentAuthorizationResult.guideBindParent(null);
            }
            return ParentAuthorizationResult.pass();
        }

        // 已绑定家长：检查家长是否设置了支付密码
        Long parentId = parentBindingService.getParentId(context.getUserId());
        if (!passwordService.hasPaymentPassword(parentId)) {
            // 低额支付允许，高额需要设置密码
            if (context.getAmount().compareTo(
                    minorPaymentConfig.getHighAmountWithoutPasswordThreshold()) >= 0) {
                return ParentAuthorizationResult.requireChallenge(
                    ChallengeType.SET_PAYMENT_PASSWORD,
                    "单笔 ¥" + minorPaymentConfig.getHighAmountWithoutPasswordThreshold()
                    + " 以上支付需要家长先设置支付密码");
            }
            // 未设置密码且金额较低：放行但打 FLAG，事件留痕供事后追溯
            return ParentAuthorizationResult.passWithFlag("PARENT_PASSWORD_NOT_SET");
        }

        // 家长已设置支付密码：本笔是否需要"验证后放行"由家长门策略决定
        // 边界约定：验证链路（PIN/生物/远程确认/实名强核验）统一由
        // 《服务端-统一家长门与监护人授权核验引擎》承接（gate action = payment.subscribe），
        // 本引擎只负责"消费凭证 + 风控加签"，不重复实现验证细节。
        GatePolicy policy = parentGateClient.resolvePolicy(
            "payment.subscribe", context.getAmount(), profile.getMinorAgeRange());

        if (policy.isNeedGrant()) {
            // 客户端未携带授权凭证 → 返回 CHALLENGE，附上家长门发起参数
            if (StringUtils.isBlank(context.getGateGrantToken())) {
                return ParentAuthorizationResult.requireChallenge(
                    ChallengeType.PARENT_GATE,
                    policy.getVerifyLevel(),
                    parentGateClient.buildSessionParams(context));
            }
            // 消费一次性 Grant Token（single_use，重放即失效）
            GrantConsumeResult consume = parentGateClient.consumeGrant(
                context.getGateGrantToken(), "payment.subscribe",
                "PAY:" + context.getRequestId());
            if (!consume.isSuccess()) {
                return ParentAuthorizationResult.block(
                    "GRANT_TOKEN_INVALID", consume.getMessage());
            }
            // 凭证消费回执写入风控上下文快照：事后审计"该笔支付经过家长核验"的证据链
            context.setGrantConsumeRef(consume.getConsumeRef());
            context.setGrantVerifyLevel(consume.getVerifyLevel());
        }
        return ParentAuthorizationResult.pass();
    }

    /**
     * 周期累计限额检查（24h / 7d 双窗口，与画像时间窗口统计同口径）
     */
    private boolean exceedsCumulativeLimit(RiskProfile profile, BigDecimal amount) {
        MinorAgeLimitConfig limit = minorPaymentConfig
            .getLimitByAgeRange(profile.getMinorAgeRange());
        if (profile.getPaymentAmount24h().add(amount).compareTo(limit.getDailyAmount()) > 0) {
            return true;
        }
        if (profile.getPaymentAmount7d().add(amount).compareTo(limit.getWeeklyAmount()) > 0) {
            return true;
        }
        return profile.getPaymentCount24h() + 1 > limit.getDailyCount();
    }

    /**
     * 高风险行为模式检测（规则引擎的"模式类"规则前置快筛，避免逐条查库）
     */
    private RiskPatternResult detectRiskPattern(MinorPaymentContext context, RiskProfile profile) {
        List<String> hits = new ArrayList<>();
        LocalDateTime now = LocalDateTime.now();

        // P1 深夜支付（22:00-06:00）
        int hour = now.getHour();
        if (hour >= 22 || hour < 6) {
            hits.add("LATE_NIGHT_PAYMENT");
        }
        // P2 上课时段支付（工作日 08:00-11:30 / 14:00-17:00，仅学龄段）
        if (isSchoolAge(profile.getMinorAgeRange()) && isSchoolTime(now)) {
            hits.add("SCHOOL_TIME_PAYMENT");
        }
        // P3 新设备首次支付且金额接近单笔限额（试探/盗用特征）
        BigDecimal singleLimit = profile.getPaymentLimitSingle() != null
            ? profile.getPaymentLimitSingle()
            : minorPaymentConfig.getLimitByAgeRange(profile.getMinorAgeRange()).getSingle();
        if (!context.getDeviceFingerprint().equals(profile.getDeviceFingerprint())
            && context.getAmount()
                   .compareTo(singleLimit.multiply(new BigDecimal("0.8"))) >= 0) {
            hits.add("NEW_DEVICE_HIGH_AMOUNT");
        }
        // P4 短时连续支付（10 分钟内第 3 笔起）
        Long recentCount = featureService.getPaymentCountSince(
            context.getUserId(), now.minusMinutes(10));
        if (recentCount != null && recentCount >= 2) {
            hits.add("RAPID_CONSECUTIVE_PAYMENT");
        }
        // P5 金额试探递增（连续 3 笔金额递增逼近限额）
        if (featureService.isEscalatingAmount(context.getUserId(), context.getAmount())) {
            hits.add("ESCALATING_AMOUNT");
        }
        return RiskPatternResult.of(hits);
    }
}
```

### 4.3 规则引擎评估与综合决策

事前风控的最终决策由 `RiskDecisionComposer` 统一合成：未成年专项检查结论 + 规则引擎命中分 + 模式检测分三路加权。

```java
/**
 * 风控综合决策合成器
 * 决策阈值（配置中心 risk.payment.threshold.* 热更新）：
 *   score < 30           → PASS
 *   30 ≤ score < 60      → CHALLENGE（密码/家长门）
 *   60 ≤ score < 80      → REVIEW（转人工）
 *   score ≥ 80           → BLOCK
 */
@Service
public class RiskDecisionComposer {

    public RiskDecision compose(MinorPaymentContext context, PreCheckResult minorCheck,
                                RuleEvalResult ruleResult, RiskPatternResult patternResult) {
        int score = 0;
        List<RuleHit> hits = new ArrayList<>(ruleResult.getHits());

        // 未成年专项检查风险注入
        if (minorCheck.isBlocked()) {
            return RiskDecision.block(minorCheck.getReasonCode(), minorCheck.getMessage(), hits);
        }
        if (minorCheck.isFlagged()) {
            score += 10;
            hits.add(RuleHit.flag("MINOR_FLAG", 10));
        }
        // 规则引擎加权（BLOCK 类规则一票否决）
        for (RuleHit hit : ruleResult.getHits()) {
            if (hit.getAction() == RuleAction.BLOCK) {
                return RiskDecision.block(hit.getRuleCode(), hit.getRuleName(), hits);
            }
            score += hit.getScore();
        }
        // 行为模式加权（每个命中 +15，≥2 个直接进 REVIEW 档）
        score += patternResult.getHits().size() * 15;
        patternResult.getHits().forEach(h -> hits.add(RuleHit.flag(h, 15)));

        // 家长已核验（Grant 已消费）抵扣：-25，体现"监护人知情"是最强风险缓释
        if (context.getGrantConsumeRef() != null) {
            score = Math.max(0, score - 25);
        }

        return RiskDecision.byScore(score, hits);
    }
}
```

**决策落库（审计溯源）**：每次事前决策无论放行与否，均写入 `payment_risk_event`（event_type=PRE_CHECK），`risk_context` 保存完整快照（金额/商品/设备指纹/家长门凭证消费回执/规则命中列表/最终分值）。该表同时是事后"误充值争议裁决"的原始证据链。

### 4.4 支付挑战（CHALLENGE）流程

```
客户端                     风控引擎                    家长门引擎              家长端
  │ POST /payment/preCheck   │                            │                    │
  ├─────────────────────────►│ 决策=CHALLENGE(PARENT_GATE) │                    │
  │◄─── challenge {action,   │                            │                    │
  │     verifyLevel=V3,      │                            │                    │
  │     sessionParams}       │                            │                    │
  │ POST /parent-gate/sessions (verifyLevel=V3)           │                    │
  ├───────────────────────────────────────────────────────►│                    │
  │◄─── sessionId / 二维码 / 深链 │                         │                    │
  │     （V3=家长端远程确认，防同设备代验）                   │                    │
  │                          │        远程确认(家长App推送) │                    │
  │                          │                            ├───────────────────►│
  │                          │                            │◄─── 确认/PIN/生物   │
  │◄─── grantToken(single_use, TTL=10min, purpose=payment.subscribe)           │
  │ POST /payment/preCheck (携带 grantToken)               │                    │
  ├─────────────────────────►│ consumeGrant → PASS 加签    │                    │
  │◄─── pass {decisionToken} │                            │                    │
  │ 携带 decisionToken 发起支付（支付服务校验 decisionToken）  │                    │
```

关键约定：

1. `decisionToken`（决策令牌）由风控引擎签发（JWT，10 分钟有效，绑定 userId+amount+商品 SKU+ requestId），支付服务创建订单时**必须校验**，缺失或金额不匹配一律拒绝（55404）。防止绕过风控直连支付。
2. **金额变更重新风控**：订单金额与 decisionToken 声明金额不一致时，支付服务返回 55405，客户端须携带新金额重新 preCheck。
3. **挑战失败三次**：会话进入冷却（30 分钟内不再发起家长门验证），连续失败按家长门防爆破规则锁定并通知家长。

### 4.6 iOS IAP 场景的服务端强校验（合规重点）

Apple 不允许在 IAP 支付流程中插入平台自定义强验证页，且禁止引导用户绕过 Apple 退款。因此 iOS 端采用"**客户端前置门控 + 服务端回查凭证**"双保险：

1. **前置（客户端）**：会员中心收银台在发起 SKPayment 前，先走 4.4 挑战流程取 grantToken（Apple 审核允许家长验证类门控，但不允许把"必须付费"作为门控结果）。
2. **回查（服务端）**：应用内购集成层在 receipt 验证/交易确认时，调用本引擎 `verifyIapAuthorization()`（gRPC）：校验该 userId 本次交易存在有效 `grant_consume_ref` 且金额匹配（transactionId 绑定）。校验失败 ≠ 扣款失败（Apple 交易已发生），进入**自动退款通道**：订单标记 `RISK_UNAUTHORIZED`，走 §6.5 自动退款编排（原路 Apple 退款或拒付申诉材料准备），并对账号支付权限升级管控。
3. **消费数据上报联动**：Apple CONSUMPTION_REQUEST（12 小时 SLA）所需的"用户消耗情况"（是否已使用权益/使用比例），由本引擎 §6.2 权益使用度快照供给应用内购层上报，帮助 Apple 做出退款裁决。

### 5.2 滑动窗口计数（Redis ZSET + Lua）

画像表的小时级刷新粒度不足以支撑"分钟级高频拦截"，事中窗口计数走 Redis：

```lua
-- KEYS[1]=risk:pay:win:{userId}  ARGV[1]=now_ms  ARGV[2]=window_ms  ARGV[3]=amount  ARGV[4]=max_count
-- 返回 {count_in_window, amount_in_window}
local z = redis.call('ZRANGE', KEYS[1], 0, -1, 'WITHSCORES')
local now = tonumber(ARGV[1]); local win = tonumber(ARGV[2])
local cut = now - win; local count = 0; local sum = 0
for i = 2, #z, 2 do
  if tonumber(z[i]) >= cut then count = count + 1
  else redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, cut) break end
end
-- 金额窗口以伴随 HASH(KEYS[2]) 累加，此处省略合并逻辑，完整脚本见实现注记
local sum = tonumber(redis.call('HGET', KEYS[2], 'sum') or 0)
redis.call('ZADD', KEYS[1], now, ARGV[3] .. ':' .. now)
redis.call('PEXPIRE', KEYS[1], win)
return {count, sum}
```

> 实现注记：金额窗口以 `ZSET(member=seq, score=ts)` + `HASH(field=seq, value=amount)` 双结构原子维护，完整 Lua 脚本随服务脚手架交付（`risk_pay_window.lua`）；ZSET TTL=窗口长度+1h 自动清理。

### 5.4 监控处理器骨架

```java
@Component
public class PaymentRiskMonitorHandler {

    @KafkaListener(topics = {"order.paid", "payment.callback.verified"},
                   groupId = "payment-risk-monitor")
    public void onPaymentEvent(EventEnvelope envelope) {
        if (!idempotentService.markConsumed(envelope.getEventId(), "payment-risk-monitor")) {
            return; // 幂等去重
        }
        RiskProfile profile = profileService.getOrInit(envelope.getUserId());
        if (!profile.isMinor()) {
            return; // 非未成年走通用风控（设备指纹引擎），本模块只管未成年专项
        }

        // 1) 窗口计数（含本笔）
        WindowStat stat = windowCounter.addAndQuery(
            envelope.getUserId(), envelope.getAmount(), Duration.ofHours(1));

        // 2) 逐条匹配监控规则（规则表 MON_*，动作见 5.3 矩阵）
        for (MonitorRule rule : ruleEngine.getEnabledMonitorRules()) {
            Optional<RiskAction> action = rule.match(envelope, profile, stat);
            if (action.isPresent()) {
                actionExecutor.execute(action.get());          // 管控升级/冻结/放行标记
                eventRecorder.record(envelope, rule, action.get()); // payment_risk_event(MONITOR)
                notifier.notifyParentIfNeeded(profile, rule);   // 家长通知（频控 1 条/小时）
                metrics.increment("risk.monitor.hit", "rule", rule.getCode());
            }
        }

        // 3) 画像增量更新（事务内）+ 峰值校验：paid 金额若超出 preCheck 放行金额 → 记 tamper 事件
        profileService.applyPayment(profile, envelope);
        if (envelope.getAmount().compareTo(envelope.getPreCheckAmount()) > 0) {
            eventRecorder.recordTamper(envelope);  // 高危：决策令牌金额被篡改，账号支付冻结
            actionExecutor.execute(RiskAction.freezeTemp(envelope.getUserId(),
                Duration.ofHours(24), "AMOUNT_TAMPER_SUSPECT"));
        }
    }
}
```

### 5.5 管控状态自动恢复

`FROZEN_TEMP` 到期由延迟任务（《服务端-统一延迟任务调度与到期事件触发引擎》）回调自动恢复为 `LIMITED`（冻结前状态），恢复通知家长；`PERMANENT_BAN` 仅人工可解（管理端双人复核），解封走审计工单。

## 6. 事后处理：误充值识别与退款

### 6.1 误充值识别信号源

| 信号源 | 入口 | 初判类别 |
| --- | --- | --- |
| 家长端"孩子乱充值"申诉 | 家长中心 → 一键退款申请 | MINOR_UNAUTHORIZED |
| 用户/学生自诉 | 我的-订单-申请退款 | ACCIDENTAL_PURCHASE 等 |
| 客服工单 | 客服系统建单转派 | 全类别 |
| Apple REFUND 通知 | 应用内购层 → gRPC `channelRefundNotify` | 渠道已退，平台做权益回收与画像更新 |
| Google VOIDED_PURCHASES | 应用内购层轮询 | 同上 |
| 平台自检（preCheck 金额篡改/凭证缺失） | §5.4 tamper 事件 | SYSTEM_ERROR/RISK_UNAUTHORIZED 主动退款 |

### 6.2 权益使用度快照（退款裁决核心证据）

```sql
CREATE TABLE payment_usage_snapshot (

    usage_detail    JSON COMMENT '明细: {aiCalls:120, printExports:2, memberDays:14}',

```

计算口径（每日离线任务，幂等 upsert）：

- 会员：`consumed = 客单价 × 已生效天数 / 应生效天数`；
- AI 额度类：`consumed = 单价 × 已用额度 / 总额度`；
- 积分/实物：已发放/已核销即视为全额消耗；
- 快照同时供 Apple CONSUMPTION_REQUEST 上报复用（§4.6）。

### 6.3 RefundDecisionEngine 自动决策规则矩阵

| 规则 | 条件（全部满足） | 决策 | 说明 |
| --- | --- | --- | --- |
| RD-01 | 申请人=家长 + 账号未成年 + 首次退款 + 支付 ≤7 天 + usage_ratio ≤0.1 + 单笔 ≤¥328 | **AUTO_APPROVE** | 法规友好区：全额退 |
| RD-02 | 未成年人 + preCheck 快照无 grant_consume_ref（未经家长核验）+ ≤48h + usage_ratio ≤0.3 | **AUTO_APPROVE** | 平台举证责任：凭证缺失视为未尽核验义务 |
| RD-03 | 重复扣款（同 SKU 同金额 5 分钟内 ≥2 笔） | **AUTO_APPROVE**（多扣部分） | 系统错误类，拆单退差额 |
| RD-04 | Apple/Google 渠道已退（通知到达） | 权益回收（不二次退款） | 幂等：渠道流水号去重 |
| RD-05 | usage_ratio ≥0.8 + 申请全额退 | **NEED_REVIEW** | 大量消耗后退款，疑似白嫖 |
| RD-06 | 30 天内第 2 次退款申请 | **NEED_REVIEW** + risk_tags += refund_repeat | 收紧后续自动通道 |
| RD-07 | 30 天内第 3 次及以上 / 命中退款黑名单 | **NEED_REVIEW（高级）** | 转反滥用专班 |
| RD-08 | 成年账号（非未成年）申请"未成年退款" | **NEED_EVIDENCE** | 要求监护关系证明（户口本/出生证明打码上传） |
| RD-09 | 支付 >180 天 | **AUTO_REJECT**（可申诉） | 超合理追溯期 |
| RD-10 | 证据含未成年人出生日期与账号实名信息矛盾 | **NEED_REVIEW（反欺诈）** | 成人冒充未成年骗退 |

决策优先级：RD-04 > RD-03 > RD-07 > RD-06 > RD-10 > RD-09 > RD-02 > RD-01 > RD-05 > RD-08；命中即停。所有决策写入 `refund_request.auto_decision` 与 `payment_risk_event(REFUND_REQUEST)`，`decision_detail` 保存规则命中链。

### 6.4 决策代码

```java
@Service
public class RefundDecisionEngine {

    public AutoDecision decide(RefundRequestContext ctx) {
        for (RefundRule rule : orderedRules) {          // 按 6.3 优先级排序
            RuleResult r = rule.evaluate(ctx);
            if (r.isHit()) {
                return AutoDecision.of(r.getDecision(), rule.getCode(), r.getEvidenceRefs());
            }
        }
        return AutoDecision.of(NEED_REVIEW, "RD_FALLBACK", List.of());
    }

    /** RD-02：未经家长核验的未成年支付（平台举证责任） */
    boolean evaluateUnverifiedMinor(RefundRequestContext ctx) {
        Optional<PaymentRiskEvent> preCheck = eventRepo
            .findLatestPreCheck(ctx.getOrderId());
        // 无决策事件本身就是缺陷：支付服务强制 decisionToken 使正常订单必有 PRE_CHECK 记录
        boolean noGrant = preCheck.isEmpty()
            || preCheck.get().getRiskContext().getGrantConsumeRef() == null;
        return ctx.getProfile().isMinor()
            && noGrant
            && ctx.getHoursSincePaid() <= 48
            && ctx.getUsageRatio() <= 0.3;
    }
}
```

### 6.5 自动退款执行编排

```
RefundDecisionEngine(AUTO_APPROVE)
   │
   ▼
① 事务：refund_request.review_status=1(自动批准) + Outbox(risk.refund.auto_approved)
   │
   ▼ ②委托执行：调用《服务端退款与订单售后处理服务》
   │   POST /internal/refunds {refundNo, orderId, amount, channel=ORIGINAL, reason=MINOR_UNAUTHORIZED}
   │   —— 渠道差异(微信/支付宝/Apple 拒付申诉)、退款状态机、对账均由售后服务承接
   ▼
③ 执行回调：售后服务 webhook refund.executed → refund_request.execution_status=2
   │
   ▼ ④权益回收（同事务幂等）：
   │   membership_revoked=1：会员到期日回拨（复用会员订阅服务回收协议）
   │   addon 额度冻结、积分扣回（不足则负债记账）
   ▼
⑤ 画像更新：total_refund_count/amount +1；RD-06 命中打标
   ▼
⑥ 通知：家长(退款成功) + 学生端(权益回收提醒，温和文案) + 审计日志
```

失败补偿：②超时未受理（5 分钟）→ 重试 3 次退避 → 挂起人工；③超时 24h → 对账任务核对售后单状态自动补齐或告警。全部动作以 `(refund_no, step)` 幂等。

### 6.6 渠道被动退款（Apple/Google）

Apple `REFUND` / Google `VOIDED_PURCHASES` 到达时渠道已完成退款，平台动作：

1. 幂等去重（渠道交易号）；
2. 调用会员订阅服务回收权益（按剩余价值）；
3. `payment_risk_event(REFUND_APPROVED, source=THIRD_PARTY)` 留痕 + 画像退款计数；
4. 若 7 天内同用户 ≥2 笔渠道退款 → 触发 MON_REFUND_ABUSE 与支付管控收紧（Apple 明令禁止拦截已退款交易的权益收回以外的惩罚，**不封号、不断已购内容访问之外的既有功能**，仅收紧"后续新支付"的家长核验档位）。

### 6.7 部分退款与拆单

- 重复扣款只退差额（RD-03 生成 `parent_refund_id` 关联的子单）；
- 已部分消耗的会员退款金额 = `客单价 × (1 - usage_ratio) - 已开发票冲红部分`，四舍五入到分，**宁多退一分不少退**（合规口径，见 §12 C6）；
- 一单多权益（会员+加购）按权益明细拆子单，各自走执行链。

### 6.8 申诉与升级（refund_appeal）

1. 自动拒绝/人工拒绝后 15 天内可申诉一次，需提交新证据；
2. 申诉由高级客服 + 风控双签处理，SLA 48 小时；
3. `escalation_type=12315/12345/COURT/APP_STORE/MEDIA` 的申诉单自动升级 P0 优先级，生成合规事件通报（《服务端-司法协查与外部调证请求响应系统》联动），处理结论回填监管答复模板；
4. 申诉成功率、升级量纳入月度风控复盘。

### 6.9 未成年人退款 24 小时快速通道

`refund_category=MINOR_UNAUTHORIZED` 且金额 ≤¥200 的申请：无视 RD-06 规则直接进入决策（首次），人工兜底队列 SLA 从 48h 压缩到 24h；超时未处理自动升级提醒风控值班群——对应《未成年人网络保护条例》"及时处理"要求。

## 8. 状态机与守卫

### 8.1 refund_request 审核状态机（review_status）

```
0待处理 ──自动批准──► 1自动批准 ──执行成功──► (终态)
   │                      └──执行失败──► 3转人工(执行异常子态)
   ├──自动拒绝──► 2自动拒绝 ──15天内申诉──► refund_appeal
   ├──补证据──► (计时冻结) ──补齐──► 0待处理(重评) ──超时7天──► 2自动拒绝
   └──转人工──► 3人工审核中 ──人工批准──► 4人工批准
                            └──人工拒绝──► 5人工拒绝
0/3 ──用户撤回──► 6已撤回(终态)
```

守卫：

| # | 守卫规则 |
| --- | --- |
| G1 | 仅 `0待处理/3人工审核中` 可人工操作；终态单操作返回 55430 |
| G2 | 人工批准金额 ≤ 申请金额（只可调减），调减必须填备注 |
| G3 | 同一 order 存在非终态/非拒绝退款单时，新申请返回 55431（防并行双退） |
| G4 | 撤回仅限未进入执行的待处理/审核中状态 |
| G5 | NEED_EVIDENCE 冻结计时 ≤7 天，超时自动拒绝并通知 |
| G6 | 人工拒绝必须选择模板化理由（自由文本仅补充），保证可申诉性告知 |

### 8.2 执行状态机（execution_status）

`0未执行 → 1执行中 → 2成功 / 3失败(重试≤3) / 4取消`

| # | 守卫规则 |
| --- | --- |
| G7 | 仅 1自动批准/4人工批准 可触发执行 |
| G8 | 执行以 `(refund_no, channel_trade_no)` 幂等，渠道重试不重复扣款 |
| G9 | 执行失败重试 3 次后转人工，挂 P1 告警 |
| G10 | 执行成功后权益回收失败 → 补偿队列重试，超 5 次告警；**钱已退权益必须收**（除 §6.6 Apple 边界） |

### 8.3 支付管控状态机（payment_risk_profile.payment_status）

`0正常 ⇄ 1限制 →(升级) 2临时冻结 →(到期自动回 1/人工解) … 3永久禁止(仅人工，双人复核)`

| # | 守卫规则 |
| --- | --- |
| G11 | 状态只能沿风险升序自动升级；降级必须人工（3 需双人） |
| G12 | 家长主动收紧（家长中心）写入本表 `payment_limit_*`，收紧即时生效，放宽次日生效（§4.5） |
| G13 | FROZEN_TEMP 最长 7 天，到期延迟任务自动恢复并通知 |

### 8.4 refund_appeal 状态机

`0待处理 → 1成功/2驳回/3撤回`；每退款单限一次申诉；`is_escalated=1` 单独 P0 队列（§6.8）。

## 10. 降级与熔断矩阵

| 编号 | 故障 | 降级策略 |
| --- | --- | --- |
| D1 | 规则引擎异常 | 回退内置默认规则集（分龄限额+家长授权两条硬规则），其余规则跳过 |
| D2 | 特征服务（Redis）不可用 | 窗口计数退化为画像小时级统计（宁可多挑战：≥¥30 一律 CHALLENGE） |
| D3 | 家长门不可用 | **fail-secure**：未成年支付一律 BLOCK（55407 类文案），绝不无凭证放行 |
| D4 | decisionToken 签发故障 | 同 D3，拒绝支付创建（宁可丢单不可绕风控） |
| D5 | 退款售后服务不可用 | 自动批准单挂起队列，恢复后按序补发；用户侧显示"退款处理中" |
| D6 | 使用度快照任务延迟 | 决策引擎用"已生效天数"粗算兜底（保守：消耗按最低估） |
| D7 | 通知服务不可用 | 家长通知进延迟队列（复用统一通知免打扰队列），风控群降级短信 |
| D8 | 管理后台不可用 | 审核队列冻结（SLA 顺延），紧急管控走 CLI 应急通道（双人+审计） |
| D9 | 画像小时刷新延迟 | preCheck 现算兜底（实时查订单表聚合），P99 超预算 200ms 告警 |
| D10 | Outbox 投递积压 | 消费方按 event_id 幂等可安全重放；积压 >10 分钟告警 |

## 11. 监控指标与容量估算

### 11.1 核心指标

| 指标 | 口径 | 告警阈值 |
| --- | --- | --- |
| preCheck P99 延迟 | gRPC 直方图 | >100ms 持续 5 分钟 |
| 未成年支付拦截率 | BLOCK+CHALLENGE / 未成年 preCheck 总量 | 周环比突变 ±30% 告警（规则误伤排查） |
| decisionToken 校验失败率 | 55404/55405 / 支付创建总量 | >0.5% 告警（疑似绕过攻击） |
| 自动退款占比 | AUTO_APPROVE / 全部批准 | >40% 告警（事前风控失效信号） |
| 自动决策推翻率 | 人工改判 / 自动决策进入人工复核部分 | >10% 规则复盘 |
| 退款执行失败率 | execution_status=3 / 已执行 | >1% P1 |
| 审核队列 SLA 违约数 | review_deadline 过期未处理 | >0 P2（快速通道 >0 P1） |
| 渠道被动退款 7 日重复率 | §6.6 触发 MON_REFUND_ABUSE | 突增告警 |
| 金额篡改事件数 | risk.tamper.detected | >0 立即 P0（安全事件） |
| 申诉升级量（12315 等） | is_escalated=1 | 周环比 +50% 合规通报 |

### 11.2 容量估算（DAU 50 万，未成年占比 ~85%）

- preCheck QPS 峰值 ≈ 支付创建峰值 ×1.2（含重试）≈ 60 QPS，单实例（2C4G）可承载，部署 3 副本；
- payment_risk_event：日增 ≈ preCheck 量 + 监控命中 ≈ 8 万行/日，按月分区，热数据 90 天，归档 ClickHouse；
- refund_request：日均 ≈ 300 单（按支付客诉率 0.5% 估），量级无压力；
- Redis 窗口结构：活跃付费未成年 ≈ 5 万 × 2 结构 × ~1KB ≈ 100MB；
- usage_snapshot：日订单量级 2 万行/日，保留 2 年。

## 14. 验收场景

1. 8 岁学生未绑定家长，购买 ¥6 单词卡：首次支付 → 返回引导绑定（不阻断）+ FLAG 留痕。
2. 同学生再购 ¥98 季度会员：返回 CHALLENGE(PARENT_GATE, V3)；家长远程确认后携带 grantToken 重试 → PASS + decisionToken；支付服务验 token 成功创建订单。
3. grantToken 被重放第二次 preCheck：55406 拦截，事件留痕。
4. 13 岁学生单日累计支付达 ¥500 后再购 ¥1：55408 拦截，展示限额说明与家长调整入口。
5. 幼儿段账号直接调用 preCheck：55410 拦截；客户端收款台对该年龄段不渲染支付按钮。
6. 家长在家长中心关闭孩子支付：1 分钟内生效（画像管控 LIMITED，额度 0）。
7. decisionToken ¥98 被用于 ¥198 订单创建：支付服务返回 55405，重下 preCheck 后正常。
8. 支付回调金额大于 preCheck 金额：tamper 事件 → 账号冻结 24h + P0 告警。
9. 1 小时内第 5 笔未成年支付：MON_HIGH_FREQ_1H 触发，当日额度归零，家长收到推送。
10. 家长申请"孩子乱充值"（首次、7 天内、未消耗）：RD-01 自动批准 → 售后服务执行 → 权益回收 → 双端通知，全链 <10 分钟。
11. 无 grant_consume_ref 的未成年 48h 内订单退款：RD-02 自动批准（平台举证责任）。
12. 会员已用 14/90 天后申请全额退：RD-05 转人工，人工按折算公式调减金额批准（宁多不少）。
13. Apple REFUND 通知到达：权益按剩余价值回收、画像计数 +1、不二次退款、无惩罚性封号。
14. 30 天内第 3 次退款：RD-07 转反滥用专班，risk_tags 打标。
15. 成年账号冒充未成年申请退款：RD-10 转反欺诈，要求监护证明。
16. 自动拒绝 15 天内申诉成功：高级双签处理，结论回填，监管升级单 48h 出结论。
17. 快速通道申请 24h 未处理：自动升级风控值班群提醒。
18. 家长门服务宕机演练：未成年支付全部 BLOCK（fail-secure），恢复后自动放开，无绕过漏单。
