# 服务端-学生缺课补救与学习进度追赶智能辅导引擎-详细设计

## 1. 概述

### 1.1 功能定位

学生缺课补救与学习进度追赶智能辅导引擎（Absence Recovery & Catch-up Engine，简称 ARCE）是 PrimeTop 学习闭环中"学习规划"与"学情分析"的交叉子系统。其核心职责是：当学生因请假（病假、事假、旅行等）导致学习中断后，自动检测缺课期间的学业损失，生成个性化补救学习计划，并在有限时间内帮助学生高效追赶进度，最终平稳回归正常学习节奏。

### 1.2 设计背景

PrimeTop 覆盖全学段用户，学生因生病、家庭出行、考试冲突等原因缺课是高频场景。现有系统已有以下相关能力：

| 现有系统 | 覆盖范围 | 缺失场景 |
|---------|---------|---------|
| 假期学习衰减评估引擎 | 寒暑假/长假后的知识遗忘唤醒 | 非周期性短期缺课 |
| 学习断更回归预测引擎 | 流失用户的回归唤醒 | 未流失但有学业缺口 |
| 学习计划动态调整服务 | 常规计划的微调和重排 | 缺课后的集中追赶 |
| 课前预习导学案生成引擎 | 正常预习流程 | 缺课后的补课式学习 |

ARCE 填补的正是"**非自愿中断 → 学业缺口识别 → 高效追赶 → 回归正轨**"这条链路。

### 1.3 适用范围

| 维度 | 说明 |
|------|------|
| 适用学段 | 小学、初中、高中全学段 |
| 适用场景 | 病假、事假、短期转学适应、考试期间缺课、意外停学 |
| 缺课时长 | 1~30 个自然日（超过 30 日走留级/重修流程，不在本引擎范围） |
| 触发方式 | 用户主动请假、系统自动检测断更、家长代请 |
| 核心输出 | 缺课影响评估报告、个性化追赶计划、每日补救任务清单 |

### 1.4 系统目标

1. **精准识别**：检测学生在缺课期间错过了哪些知识点、练习和考试
2. **优先分级**：将缺课内容按重要性和依赖关系排序，剔除低优先内容
3. **高效压缩**：在有限追赶时间内，最大化学习成效而非简单堆砌任务
4. **平稳过渡**：追赶计划结束时自动衔接正常学习节奏，避免二次断裂
5. **心理减负**：避免缺课学生面对过大学业压力，合理控制每日负荷

## 2. 核心概念与领域模型

### 2.1 领域概念

```
┌─────────────────────────────────────────────────────────┐
│                  Absence Recovery Context                │
│                                                          │
│  ┌──────────────┐   ┌──────────────┐   ┌─────────────┐ │
│  │  Absence     │──▶│  Gap Analysis│──▶│ Catch-up    │ │
│  │  Record      │   │  Report      │   │ Plan        │ │
│  │  (缺课记录)   │   │  (缺口报告)   │   │ (追赶计划)   │ │
│  └──────────────┘   └──────────────┘   └─────────────┘ │
│         │                                      │        │
│         │           ┌──────────────┐           │        │
│         └──────────▶│ Daily Catch- │◀──────────┘        │
│                     │ up Tasks     │                    │
│                     │ (每日补救任务)│                    │
│                     └──────────────┘                    │
│                              │                          │
│                              ▼                          │
│                     ┌──────────────┐                    │
│                     │ Recovery     │                    │
│                     │ Progress     │                    │
│                     │ (恢复进度)    │                    │
│                     └──────────────┘                    │
└─────────────────────────────────────────────────────────┘
```

### 2.2 核心概念定义

| 概念 | 定义 |
|------|------|
| **缺课记录 (Absence Record)** | 记录缺课起止时间、原因、涉及学科范围 |
| **学业缺口 (Learning Gap)** | 缺课期间应学但未学的知识点、练习、考试 |
| **追赶计划 (Catch-up Plan)** | 为弥补学业缺口生成的有时间约束的学习计划 |
| **补救任务 (Remediation Task)** | 追赶计划中每日需完成的具体学习任务 |
| **追赶期 (Catch-up Period)** | 从开始追赶到达成正常进度的预估时间段 |
| **关键路径知识点 (Critical Path KP)** | 后续学习强依赖的前置知识点，必须优先补救 |
| **弹性知识点 (Flexible KP)** | 可暂缓或简化学习的知识点，追赶期可跳过 |

## 3. 数据结构定义

### 3.1 数据库表设计

#### 3.1.1 `absence_record` 缺课记录表

```sql
CREATE TABLE `absence_record` (
    `id`                BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `student_id`        BIGINT       NOT NULL COMMENT '学生ID',
    `absence_type`      VARCHAR(32)  NOT NULL COMMENT '缺课类型: SICK_LEAVE/PERSONAL/TRAVEL/EXAM_CONFLICT/OTHER',
    `start_date`        DATE         NOT NULL COMMENT '缺课开始日期',
    `end_date`          DATE         NOT NULL COMMENT '缺课结束日期',
    `absence_days`      INT          NOT NULL COMMENT '缺课自然日数',
    `school_days`       INT          NOT NULL COMMENT '缺课工作日数（不含周末节假日）',
    `reason`            VARCHAR(500) NULL COMMENT '缺课原因描述',
    `affected_subjects` JSON         NULL COMMENT '受影响学科ID列表, null表示全部学科',
    `reported_by`       VARCHAR(32)  NOT NULL COMMENT '上报来源: STUDENT/PARENT/SYSTEM_DETECTED/TEACHER',
    `reporter_id`       BIGINT       NULL COMMENT '上报人ID（家长/教师ID）',
    `status`            VARCHAR(32)  NOT NULL DEFAULT 'ACTIVE' COMMENT '状态: ACTIVE/ANALYZING/PLANNED/RECOVERING/COMPLETED/CANCELLED',
    `catch_up_deadline` DATE         NULL COMMENT '追赶截止日期（期望回归正常进度的时间）',
    `created_at`        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted_at`        DATETIME     NULL,
    PRIMARY KEY (`id`),
    INDEX `idx_student_status` (`student_id`, `status`),
    INDEX `idx_dates` (`start_date`, `end_date`),
    INDEX `idx_reported_by` (`reported_by`, `reporter_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学生缺课记录表';
```

```sql
    `is_compensated`    TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '是否已编入追赶计划',
    `compensation_strategy` VARCHAR(32) NULL COMMENT '补救策略: FULL_LEARN/CONDENSED/SUMMARY_ONLY/PRACTICE_ONLY/SKIP',

    `updated_at`        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

```

```sql
    `plan_strategy`     VARCHAR(32)  NOT NULL COMMENT '计划策略: CRITICAL_FIRST/BALANCED_SUBJECT/EXAM_PRIORITY',
```

### 4.1 缺课记录状态机

```
                    ┌─────────┐
     上报缺课        │         │
    ──────────────▶ │ ACTIVE  │
                    │         │
                    └────┬────┘
                         │ 触发分析
                         ▼
                    ┌──────────┐
                    │          │
                    │ANALYZING │──── 分析失败 ────▶ ACTIVE (重试)
                    │          │
                    └────┬─────┘
                         │ 分析完成, 生成计划
                         ▼
                    ┌──────────┐
                    │          │
                    │ PLANNED  │──── 用户确认 ───▶ RECOVERING
                    │          │──── 用户放弃 ───▶ CANCELLED
                    └──────────┘
                                              ┌──────────┐
                    ┌──────────┐               │          │
```

## 6. 核心算法设计

### 6.1 学业缺口检测算法

```python
class GapAnalysisEngine:
    """学业缺口检测引擎"""

    def analyze_gaps(self, student_id: int, absence: AbsenceRecord) -> List[LearningGap]:
        """
        分析缺课期间的学业缺口。
        
        步骤：
        1. 获取缺课期间的教学计划（学校进度 + 平台同步课堂进度）
        2. 获取学生已学记录，过滤已完成的内容
        3. 对每个缺口进行优先级和依赖关系评估
        4. 输出排序后的缺口列表
        """
        gaps = []
        
        # Step 1: 获取缺课期间应学内容
        expected_content = self._get_expected_content(
            student_id=student_id,
            start_date=absence.start_date,
            end_date=absence.end_date,
            subject_ids=absence.affected_subject_ids
        )
        
        # Step 2: 获取学生已学记录
        completed_kps = self.progress_service.get_completed_knowledge_points(student_id)
        completed_exercises = self.practice_service.get_completed_exercises(
            student_id, absence.start_date, absence.end_date
        )
        
        # Step 3: 逐项分析缺口
        for item in expected_content:
            if self._is_already_completed(item, completed_kps, completed_exercises):
                continue
            
            gap = self._create_gap(student_id, absence.id, item)
            gap.priority = self._assess_priority(item, student_id)
            gap.dependency_level = self._assess_dependency(item)
            gap.estimated_time_min = self._estimate_learning_time(item, student_id)
            gaps.append(gap)
        
        # Step 4: 排序 - 关键路径 > 高 > 中 > 低
        gaps.sort(key=lambda g: (-g.priority.value, g.dependency_level.value))
        
        return gaps
    
    def _assess_priority(self, content_item, student_id: int) -> Priority:
        """评估缺口优先级"""
        score = 0
        
        # 因素1: 是否为后续学习的强依赖前置
        downstream_kps = self.knowledge_graph.get_downstream_kps(content_item.knowledge_point_id)
        blocking_count = len([k for k in downstream_kps 
                            if k.is_scheduled_in_days(student_id, days=14)])
        if blocking_count >= 3:
            score += 50
        elif blocking_count >= 1:
            score += 30
        
        # 因素2: 是否为考试高频考点
        if content_item.knowledge_point_id in self.exam_freq_cache.get_high_freq_kps(
            student_id):
            score += 25
        
        # 因素3: 是否为即将到来的考试范围
        upcoming_exams = self.exam_service.get_upcoming_exams(student_id, days=30)
        for exam in upcoming_exams:
            if content_item.knowledge_point_id in exam.scope_kp_ids:
                score += 20
                break
        
        # 因素4: 学生在此知识点的历史掌握度
        mastery = self.mastery_service.get_mastery(student_id, content_item.knowledge_point_id)
        if mastery < 0.3:
            score += 15  # 基础薄弱，更需要补救
        
        # 分级
        if score >= 50:
            return Priority.CRITICAL
        elif score >= 30:
            return Priority.HIGH
        elif score >= 15:
            return Priority.MEDIUM
        elif score >= 5:
            return Priority.LOW
        else:
            return Priority.OPTIONAL
    
    def _assess_dependency(self, content_item) -> DependencyLevel:
        """评估依赖级别"""
        # 检查知识图谱中后续节点是否有强依赖
        edges = self.knowledge_graph.get_outgoing_edges(content_item.knowledge_point_id)
        strong_deps = [e for e in edges if e.edge_type == 'STRONG_DEPENDENCY']
        
        if strong_deps:
            return DependencyLevel.BLOCKING
        elif len(edges) > 0:
            return DependencyLevel.RECOMMENDED
        else:
            return DependencyLevel.INDEPENDENT
    
    def _estimate_learning_time(self, content_item, student_id: int) -> int:
        """估算学习时间（分钟）"""
        base_time = content_item.default_study_time_min
        
        # 根据学生历史学习速度调整
        student_speed = self.analytics_service.get_student_learning_speed_factor(student_id)
        # student_speed 通常在 0.7~1.5 之间
        
        adjusted_time = int(base_time * student_speed)
        return max(10, min(120, adjusted_time))  # 限制在 10~120 分钟
```

### 6.2 追赶计划生成算法

```python
class CatchUpPlanGenerator:
    """追赶计划生成器"""

    def generate_plan(
        self,
        absence: AbsenceRecord,
        gaps: List[LearningGap],
        student_profile: StudentProfile
    ) -> CatchUpPlan:
        """
        基于学业缺口和学生画像生成追赶计划。
        
        核心策略：
        1. 计算可用追赶时间和每日容量
        2. 筛选缺口（全选/精简/跳过）
        3. 分配补救策略（完整学习/精简/仅总结/仅练习）
        4. 排序并分配到每日任务
        """
        
        # Step 1: 计算追赶窗口
        available_days = (absence.catch_up_deadline - absence.start_date).days
        available_days = max(1, min(available_days, 30))
        
        # Step 2: 确定每日学习容量
        daily_capacity = self._calculate_daily_capacity(
            student_profile, absence.school_days, available_days
        )
        
        # Step 3: 筛选和分配策略
        total_available_min = available_days * daily_capacity
        selected_gaps, skipped_gaps = self._select_and_assign_strategies(
            gaps, total_available_min, student_profile
        )
        
        # Step 4: 每日任务编排
        daily_tasks = self._distribute_tasks(
            selected_gaps, available_days, daily_capacity, student_profile
        )
        
        # Step 5: 生成计划
        plan = CatchUpPlan(
            absence_record_id=absence.id,
            student_id=absence.student_id,
            plan_name=f"{absence.start_date.month}月缺课{absence.school_days}天追赶计划",
            total_gap_items=len(gaps),
            selected_items=len(selected_gaps),
            skipped_items=len(skipped_gaps),
            total_estimated_min=sum(g.estimated_time_min for g in selected_gaps),
            start_date=absence.start_date + timedelta(days=1),
            target_end_date=absence.catch_up_deadline,
            daily_capacity_min=daily_capacity,
            intensity_level=self._determine_intensity(daily_capacity),
            plan_strategy=student_profile.preferred_strategy or PlanStrategy.CRITICAL_FIRST,
        )
        
        return plan, daily_tasks
    
    def _calculate_daily_capacity(
        self, profile: StudentProfile, school_days: int, available_days: int
    ) -> int:
        """
        计算每日额外学习时间（分钟）。
        
        规则：
        - 基础容量 = 缺课工作日数 × 40分钟 / 可用追赶天数
        - 根据学段调整：小学 +20%, 初中 +0%, 高中 -10%（已有较重常规课业）
        - 根据学生日常学习时长调整
        - 封顶在 30~120 分钟/天
        """
        # 缺课内容总量转日均
        base = (school_days * 40) / available_days
        
        # 学段调整系数
        stage_factor = {
            'PRIMARY': 1.2,
            'JUNIOR': 1.0,
            'SENIOR': 0.9
        }.get(profile.stage, 1.0)
        
        # 学生日常学习强度调整
        avg_daily_study = profile.avg_daily_study_min  # 通常 30~120
        if avg_daily_study > 90:
            intensity_factor = 1.3  # 高强度学习者可以多补
        elif avg_daily_study > 60:
            intensity_factor = 1.0
        else:
            intensity_factor = 0.8  # 低强度学习者适当减量
        
        capacity = int(base * stage_factor * intensity_factor)
        return max(30, min(120, capacity))
    
    def _select_and_assign_strategies(
        self,
        gaps: List[LearningGap],
        budget_min: int,
        profile: StudentProfile
    ) -> Tuple[List[LearningGap], List[LearningGap]]:
        """
        在时间预算内选择缺口并分配补救策略。
        
        使用贪心策略 + 时间装箱：
        1. 先选入所有 CRITICAL 和 BLOCKING
        2. 再按优先级从高到低选入
        3. 时间不够时降级策略（FULL → CONDENSED → SUMMARY_ONLY）
        4. 仍不够则跳过
        """
        selected = []
        skipped = []
        remaining_budget = budget_min
        
        # Phase 1: 必选 - CRITICAL + BLOCKING
        must_have = [g for g in gaps 
                     if g.priority == Priority.CRITICAL or g.dependency_level == DependencyLevel.BLOCKING]
        optional = [g for g in gaps 
                    if g not in must_have]
        
        for gap in must_have:
            # 尝试完整学习
            if remaining_budget >= gap.estimated_time_min:
                gap.compensation_strategy = CompensationStrategy.FULL_LEARN
                remaining_budget -= gap.estimated_time_min
                selected.append(gap)
            else:
                # 降级：尝试精简
                condensed_time = int(gap.estimated_time_min * 0.6)
                if remaining_budget >= condensed_time:
                    gap.compensation_strategy = CompensationStrategy.CONDENSED
                    gap.estimated_time_min = condensed_time
                    remaining_budget -= condensed_time
                    selected.append(gap)
                else:
                    # 降级：仅看总结
                    summary_time = max(10, int(gap.estimated_time_min * 0.25))
                    if remaining_budget >= summary_time:
                        gap.compensation_strategy = CompensationStrategy.SUMMARY_ONLY
                        gap.estimated_time_min = summary_time
                        remaining_budget -= summary_time
                        selected.append(gap)
                    else:
                        gap.compensation_strategy = CompensationStrategy.SKIP
                        skipped.append(gap)
        
        # Phase 2: 可选 - 按优先级填入剩余预算
        optional.sort(key=lambda g: -g.priority.value)
        for gap in optional:
            if remaining_budget >= gap.estimated_time_min:
                gap.compensation_strategy = CompensationStrategy.FULL_LEARN
                remaining_budget -= gap.estimated_time_min
                selected.append(gap)
            else:
                condensed_time = int(gap.estimated_time_min * 0.5)
                if remaining_budget >= condensed_time:
                    gap.compensation_strategy = CompensationStrategy.CONDENSED
                    gap.estimated_time_min = condensed_time
                    remaining_budget -= condensed_time
                    selected.append(gap)
                else:
                    gap.compensation_strategy = CompensationStrategy.SKIP
                    skipped.append(gap)
        
        return selected, skipped
    
    def _distribute_tasks(
        self,
        gaps: List[LearningGap],
        available_days: int,
        daily_capacity: int,
        profile: StudentProfile
    ) -> List[List[DailyCatchUpTask]]:
        """
        将选中的缺口分配到每日任务。
        
        策略：
        1. 关键路径优先安排在前 60% 的时间
        2. 同一学科连续安排，避免频繁切换
        3. 高难度任务安排在学生高效时段
        4. 每日任务总时间不超过 daily_capacity
        5. 每日同一知识点不超过 2 个任务
        """
        daily_tasks = [[] for _ in range(available_days)]
        daily_time = [0] * available_days
        
        # 按学科分组，同组内按优先级排序
        by_subject = {}
        for gap in gaps:
            by_subject.setdefault(gap.subject_id, []).append(gap)
        
        # 计算关键路径截止日（前 60%）
        critical_cutoff = int(available_days * 0.6)
        
        for subject_id, subject_gaps in by_subject.items():
            day_index = 0
            for gap in subject_gaps:
                assigned = False
                attempts = 0
                
                while not assigned and attempts < available_days:
                    current_day = day_index % available_days
                    
                    # 检查约束
                    if (daily_time[current_day] + gap.estimated_time_min <= daily_capacity and
                        self._can_assign_to_day(gap, daily_tasks[current_day])):
                        
                        task = self._create_task(gap, current_day, len(daily_tasks[current_day]))
                        daily_tasks[current_day].append(task)
                        daily_time[current_day] += gap.estimated_time_min
                        assigned = True
                    
                    day_index += 1
                    attempts += 1
                
                if not assigned:
                    # 放到最后一天
                    last_day = available_days - 1
                    task = self._create_task(gap, last_day, len(daily_tasks[last_day]))
                    daily_tasks[last_day].append(task)
                    daily_time[last_day] += gap.estimated_time_min
        
        # 对每天内任务按类型排序：先学概念 → 练习 → 总结
        for day_tasks in daily_tasks:
            type_order = {
                TaskType.KNOWLEDGE_SUMMARY: 0,
                TaskType.CONCEPT_LEARN: 1,
                TaskType.CONDENSED_REVIEW: 2,
                TaskType.PRACTICE: 3,
                TaskType.EXAM_SIMULATION: 4
            }
            day_tasks.sort(key=lambda t: type_order.get(t.task_type, 99))
        
        return daily_tasks
    
    def _can_assign_to_day(self, gap: LearningGap, day_tasks: list) -> bool:
        """检查是否可以分配到当天"""
        # 同一知识点不超过2个任务
        same_kp_count = sum(1 for t in day_tasks 
                           if gap.knowledge_point_id in (t.knowledge_point_ids or []))
        return same_kp_count < 2
```

### 6.3 追赶进度动态调整算法

```python
class ProgressAdjustmentEngine:
    """追赶进度动态调整引擎"""

    def check_and_adjust(self, plan_id: int) -> Optional[PlanAdjustment]:
        """
        定期检查追赶计划进度，动态调整。
        
        触发条件：
        - 每日任务完成回调
        - 每日定时检查（21:00）
        - 连续2天未完成任务
        """
        plan = self.plan_repo.get_by_id(plan_id)
        if plan.status != CatchUpPlanStatus.ACTIVE:
            return None
        
        progress = self._calculate_progress(plan)
        pace_analysis = self._analyze_pace(plan, progress)
        
        adjustment = None
        
        if pace_analysis.is_behind_schedule:
            if pace_analysis.deficit_days >= 2:
                # 严重落后 → 需要调整
                adjustment = self._generate_adjustment(plan, progress, pace_analysis)
            elif pace_analysis.deficit_days >= 1:
                # 轻微落后 → 标记预警，暂不调整
                self.notification_service.send_warning(
                    student_id=plan.student_id,
                    message="追赶进度略落后，今天多花15分钟就能跟上！"
                )
        elif pace_analysis.is_ahead_of_schedule:
            # 提前 → 可以恢复部分跳过的内容
            adjustment = self._maybe_restore_skipped(plan, progress, pace_analysis)
        
        return adjustment
    
    def _analyze_pace(self, plan: CatchUpPlan, progress: dict) -> PaceAnalysis:
        """分析追赶速度"""
        days_elapsed = (date.today() - plan.start_date).days + 1
        days_remaining = (plan.target_end_date - date.today()).days
        
        expected_progress = days_elapsed / (days_elapsed + days_remaining) * 100
        actual_progress = progress['completion_rate']
        
        pace_diff = actual_progress - expected_progress
        
        if pace_diff < -10:
            # 落后超过10%
            deficit_days = abs(pace_diff / 100 * (days_elapsed + days_remaining))
            return PaceAnalysis(
                is_behind_schedule=True,
                deficit_days=ceil(deficit_days),
                is_ahead_of_schedule=False
            )
        elif pace_diff > 15:
            return PaceAnalysis(
                is_behind_schedule=False,
                deficit_days=0,
                is_ahead_of_schedule=True,
                surplus_days=floor(pace_diff / 100 * (days_elapsed + days_remaining))
            )
        else:
            return PaceAnalysis(
                is_behind_schedule=False,
                deficit_days=0,
                is_ahead_of_schedule=False
            )
    
    def _generate_adjustment(
        self, plan: CatchUpPlan, progress: dict, pace: PaceAnalysis
    ) -> PlanAdjustment:
        """生成计划调整方案"""
        remaining_tasks = self.task_repo.get_pending_tasks(plan.id)
        
        adjustments = []
        
        # 策略1: 降级部分 FULL_LEARN 为 CONDENSED
        full_learn_tasks = [t for t in remaining_tasks 
                           if t.task_type == TaskType.CONCEPT_LEARN]
        for task in full_learn_tasks:
            if task.gap_analysis and task.gap_analysis.priority in [Priority.LOW, Priority.OPTIONAL]:
                adjustments.append(TaskAdjustment(
                    task_id=task.id,
                    action='DOWNGRADE',
                    from_type=TaskType.CONCEPT_LEARN,
                    to_type=TaskType.KNOWLEDGE_SUMMARY,
                    time_reduction=int(task.estimated_time_min * 0.6)
                ))
        
        # 策略2: 将部分 MEDIUM/LOW 任务标记为 SKIP
        low_priority_tasks = [t for t in remaining_tasks
                             if t.gap_analysis and 
                             t.gap_analysis.priority in [Priority.LOW, Priority.OPTIONAL] and
                             t.gap_analysis.dependency_level == DependencyLevel.INDEPENDENT]
        
        for task in low_priority_tasks[:int(pace.deficit_days)]:
            adjustments.append(TaskAdjustment(
                task_id=task.id,
                action='SKIP',
                reason='进度落后，跳过低优先级独立知识点'
            ))
        
        # 策略3: 如果仍不够，建议延长截止日期
        total_time_saved = sum(a.time_reduction or 0 for a in adjustments)
        if total_time_saved < pace.deficit_days * plan.daily_capacity_min:
            extension_days = ceil(
                (pace.deficit_days * plan.daily_capacity_min - total_time_saved) 
                / plan.daily_capacity_min
            )
            adjustments.append(PlanLevelAdjustment(
                action='EXTEND_DEADLINE',
                new_deadline=plan.target_end_date + timedelta(days=extension_days),
                reason=f'自动延长{extension_days}天截止日期'
            ))
        
        return PlanAdjustment(
            plan_id=plan.id,
            adjustments=adjustments,
            auto_apply=False,
            requires_user_confirmation=True
        )
```

```java
                .estimatedTimeMin(30)            // 统一30分钟
                .build())
            .collect(Collectors.toList());
        
        return GapAnalysisResult.builder()
            .gaps(simpleGaps)
            .degraded(true)
            .degradationReason("知识图谱服务不可用，使用简化分析")
            .build();
    }

    /**
     * 追赶计划生成降级策略
     */
    public CatchUpPlan fallbackPlanGeneration(
            AbsenceRecord absence, List<LearningGap> gaps) {
        log.warn("降级执行计划生成, studentId={}", absence.studentId);
        
        // 降级方案：简单的均匀分配
        int dailyCapacity = 60;  // 默认60分钟/天
        int availableDays = ChronoUnit.DAYS.between(
            absence.startDate.plusDays(1), absence.catchUpDeadline);
        availableDays = Math.max(1, availableDays);
        
        // 简单截取（不做策略分配）
        int maxItems = (dailyCapacity * availableDays) / 30; // 每项30分钟
        List<LearningGap> selected = gaps.stream()
            .sorted(Comparator.comparing(g -> g.priority, Comparator.reverseOrder()))
            .limit(maxItems)
            .collect(Collectors.toList());
        
        return CatchUpPlan.builder()
            .absenceRecordId(absence.id)
            .selectedItems(selected.size())
            .dailyCapacityMin(dailyCapacity)
            .intensityLevel(IntensityLevel.MODERATE)
            .planStrategy(PlanStrategy.CRITICAL_FIRST)
            .degraded(true)
            .build();
    }

    /**
     * AI补救内容生成降级策略
     */
    public RemediationContent fallbackContent(LearningGap gap, StudentProfile profile) {
        log.warn("降级执行内容生成, gapId={}, kpId={}", gap.id, gap.knowledgePointId);
        
        // 降级方案：使用预制内容，不走AI生成
        KnowledgePoint kp = knowledgePointService.getById(gap.knowledgePointId);
        
        return RemediationContent.builder()
            .contentType('FALLBACK_SUMMARY')
            .body(kp.getDefaultSummary())  // 知识点预置摘要
            .note("AI内容生成服务暂时不可用，已使用标准知识点摘要")
            .build();
    }
}
```

```java
@Component
public class AutoAbsenceDetectionJob {

    /**
     * 每日20:00自动检测连续未学习天数
     * 触发条件: 连续3个自然日无学习行为记录
     */
    @Scheduled(cron = "0 0 20 * * ?")
    public void detectAbsence() {
        List<Long> activeStudentIds = studentService.getAllActiveStudentIds();
        LocalDate today = LocalDate.now();
        
        for (Long studentId : activeStudentIds) {
            // 跳过已有活跃缺课记录的学生
            if (absenceRepo.hasActiveAbsence(studentId)) {
                continue;
            }
            
            // 获取最后一次学习行为日期
            LocalDate lastActiveDate = learningActivityService
                .getLastActiveDate(studentId);
            
            if (lastActiveDate == null) {
                continue;  // 新用户，跳过
            }
            
            long daysSinceActive = ChronoUnit.DAYS.between(lastActiveDate, today);
            
            if (daysSinceActive >= 3 && daysSinceActive <= 30) {
                // 发送关怀通知
                notificationService.sendAbsenceDetectionNotice(studentId, 
                    daysSinceActive, lastActiveDate);
                
                // 7天以上自动创建缺课记录
                if (daysSinceActive >= 7) {
                    AbsenceRecord record = AbsenceRecord.builder()
                        .studentId(studentId)
                        .absenceType(AbsenceType.OTHER)
                        .startDate(lastActiveDate.plusDays(1))
                        .endDate(today.minusDays(1))
                        .reportedBy(ReportSource.SYSTEM_DETECTED)
                        .status(AbsenceStatus.ACTIVE)
                        .catchUpDeadline(today.plusDays((int) daysSinceActive))
                        .build();
                    absenceRepo.save(record);
                    
                    eventPublisher.publish(new AbsenceReported(
                        record.id, studentId, record.startDate, record.endDate));
                }
            }
        }
    }
}
```

```java
/**
 * 敏感数据脱敏

@Component
public class AbsenceDataMasking {

    // 缺课原因可能包含敏感健康信息，需要脱敏
    public String maskReason(String reason, Long requesterId, Long studentId) {
        if (requesterId.equals(studentId)) {
            return reason;  // 本人可见
        }
        if (parentBindingService.isParentOf(requesterId, studentId)) {
            return reason;  // 绑定家长可见
        }
        // 教师和其他角色只看到类型，不看具体原因
        return "[已隐藏]";
    }
    
    // 缺课记录不进入用户画像公开数据
    public AbsenceRecordDTO toDTO(AbsenceRecord record, Long requesterId) {
        AbsenceRecordDTO dto = new AbsenceRecordDTO();
        dto.setId(record.id);
        dto.setAbsenceType(record.absenceType);
        dto.setStartDate(record.startDate);
        dto.setEndDate(record.endDate);
        dto.setReason(maskReason(record.reason, requesterId, record.studentId));
        dto.setStatus(record.status);
        return dto;
    }
}
```

### 13.3 合规要点

1. **未成年人保护**：缺课原因可能涉及健康信息，不做长期留存，90天后自动脱敏
2. **数据最小化**：不记录具体病情诊断，仅记录缺课类型
3. **家长知情权**：家长上报的缺课记录同步通知学生端，学生上报的通知家长端
4. **教师可见性**：教师只能看到汇总统计（多少学生缺课、缺几天），不能看到具体原因
5. **数据保留**：缺课记录和追赶计划保留至当前学年结束，新学年自动归档
