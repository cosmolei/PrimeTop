# 数据字典与统一枚举体系 - 详细设计

> 版本：v1.0 | 日期：2026-05-23 | 类型：全局参照文档

## 1. 文档定位

### 1.1 目的

本文档为 PrimeTop 项目的**全局数据字典**，统一定义各模块共享的枚举类型、常量编码和命名规范。所有模块的设计文档和代码实现应以此文档为准，保证跨模块数据语义一致。

### 1.2 适用范围

- 服务端 API 请求/响应中的枚举字段
- 数据库表中 ENUM、VARCHAR 编码字段
- 客户端 TypeScript/Dart 类型定义
- 管理后台筛选条件和展示映射
- 数据仓库/分析层的维度编码

### 1.3 使用约定

| 规则 | 说明 |
|------|------|
| 编码格式 | 小写字母 + 下划线（snake_case），如 `grade_7` |
| 数据库存储 | VARCHAR 存储编码字符串，禁止使用数字常量（可读性优先） |
| API 传输 | JSON 字段使用 snake_case 编码字符串 |
| 客户端映射 | 各端定义对应的 enum / sealed class，必须包含编码→展示名映射 |
| 新增流程 | 新增枚举值需在本文档登记后，各端同步更新 |
| 废弃规则 | 枚举值一旦发布不可删除，只能标记 `deprecated` 并保留映射 |

## 19. 数据库枚举字段 DDL 参考

以下是各表使用枚举字段时的标准 DDL 写法（以 MySQL 为例）：

```sql
-- 推荐：VARCHAR + CHECK 约束（灵活性高，无需 ALTER TABLE 即可扩展）
ALTER TABLE users ADD COLUMN grade VARCHAR(16) NOT NULL
  COMMENT '年级，见数据字典 Grade 枚举';

ALTER TABLE questions ADD COLUMN difficulty VARCHAR(16) NOT NULL DEFAULT 'medium'
  COMMENT '难度等级：easy/medium/hard/expert，见数据字典';

-- 或使用 ENUM 类型（严格的值约束，需 ALTER TABLE 扩展）
ALTER TABLE users ADD COLUMN status ENUM('active','suspended','deleted','pending')
  NOT NULL DEFAULT 'active' COMMENT '用户状态';
```

**推荐方案：** 使用 VARCHAR + 应用层校验。好处：
1. 无需 ALTER TABLE 即可新增枚举值
2. 更好的跨数据库兼容
3. 数据迁移更简单
4. 适合快速迭代的 MVP 阶段
