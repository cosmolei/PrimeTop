# 服务端 - 平台多角色统一身份与跨角色切换管理服务 详细设计

## 1. 概述

### 1.1 功能定位

PrimeTop 平台覆盖学生、家长、教师、内容运营、平台管理员等多种用户群体。在实际使用中，同一自然人往往兼具多种角色：

| 场景 | 角色组合 | 典型需求 |
| --- | --- | --- |
| 教师同时是家长 | `TEACHER` + `PARENT` | 管理班级的同时查看自己孩子的学情 |
| 高中生管理弟妹 | `STUDENT` + `PARENT` | 自己学习 + 弟妹的学习监督 |
| 运营人员也是家长 | `OPERATOR` + `PARENT` | 内容运营工作 + 自己孩子使用 |
| 学校管理员兼教师 | `SCHOOL_ADMIN` + `TEACHER` | 管理学校教学 + 本班教学 |
| 家长有多个孩子 | `PARENT` × N | 切换查看不同孩子的学情 |

本服务提供**统一账号多角色绑定、角色上下文切换、角色级数据隔离、角色级权限控制**能力，确保用户在不同角色间无缝切换且数据互不干扰。

### 1.2 设计目标

1. **一号多角色**：一个手机号/账号可绑定多种角色身份，无需重复注册。
2. **角色隔离**：各角色数据严格隔离，切换角色后仅可见当前角色数据。
3. **无缝切换**：客户端一键切换角色，无需重新登录。
4. **权限精确**：API 层面基于当前角色上下文进行权限校验。
5. **可扩展**：后续新增角色类型无需改动核心架构。

### 1.3 适用范围

- 客户端 APP（学生端、家长端、教师端）
- 管理后台 Web
- 后续 Web 端、小程序端
- 所有需要角色上下文的服务端 API

## 2. 核心概念与领域模型

### 2.1 领域语言定义

| 术语 | 定义 |
| --- | --- |
| **UserAccount（用户账号）** | 自然人级别的统一账号，对应一个手机号/ openid，是角色的容器 |
| **RoleIdentity（角色身份）** | 用户在平台中的某一种身份，如学生、家长、教师等 |
| **ActiveRoleContext（当前活跃角色上下文）** | 用户当前正在使用的角色身份，决定可见数据和可用功能 |
| **RoleBinding（角色绑定关系）** | UserAccount 与 RoleIdentity 之间的关联，包含角色特定的 Profile |
| **RoleSwitchEvent（角色切换事件）** | 用户切换角色时产生的事件，用于审计和行为追踪 |

### 2.2 角色类型枚举

```java
public enum RoleType {
    STUDENT("学生", "S"),
    PARENT("家长", "P"),
    TEACHER("教师", "T"),
    OPERATOR("运营人员", "O"),
    SCHOOL_ADMIN("学校管理员", "A"),
    PLATFORM_ADMIN("平台管理员", "PA");

    private final String displayName;
    private final String code;

    RoleType(String displayName, String code) {
        this.displayName = displayName;
        this.code = code;
    }
}
```

### 2.3 角色间关系

```
UserAccount (1) ──── (N) RoleIdentity
    │
    ├── RoleIdentity: STUDENT → StudentProfile (学段、年级、教材版本)
    ├── RoleIdentity: PARENT  → ParentProfile + ParentStudentBinding[] (绑定的孩子列表)
    ├── RoleIdentity: TEACHER → TeacherProfile (学校、学科、班级列表)
    ├── RoleIdentity: OPERATOR → OperatorProfile (管理后台权限组)
    └── ...
```

## 5. Token 与权限设计

### 5.1 JWT Token Payload 结构

```json
{
  "sub": "10001",
  "accountId": 10001,
  "roleId": 20001,
  "roleType": "TEACHER",
  "deviceId": "DEV_abc123",
  "iat": 1723485600,
  "exp": 1723492800,
  "jti": "unique-token-id"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sub` | string | 用户账号ID（字符串形式） |
| `accountId` | number | 用户账号ID |
| `roleId` | number | **当前角色身份ID**（切换后变化） |
| `roleType` | string | 当前角色类型 |
| `deviceId` | string | 登录设备标识 |
| `iat` | number | 签发时间 |
| `exp` | number | 过期时间 |
| `jti` | string | Token 唯一标识（用于黑名单/吊销） |

### 5.2 权限校验流程

```
客户端请求
    │
    ▼
API 网关
    │ ── 提取 Authorization Header
    │ ── 验证 JWT 签名 & 过期时间
    │ ── 提取 accountId, roleId, roleType
    ▼
角色上下文拦截器 (RoleContextInterceptor)
    │ ── 从 Redis 查询 roleId 的活跃状态
    │ ── 校验 roleId 是否属于该 accountId
    │ ── 校验 roleId 是否未被禁用/解绑
    │ ── 将 RoleContext 注入请求上下文
    ▼
权限校验拦截器 (PermissionInterceptor)
    │ ─ ─ 获取当前接口所需的角色类型 @RequireRole
    │ ── 校验 roleType 是否匹配
    │ ── 查询角色级权限覆盖表
    │ ── 查询功能门控（会员权益/功能开关）
    ▼
业务 Controller
    │ ── 从 RequestContextHolder 获取 RoleContext
    │ ── 执行业务逻辑（仅查询当前角色可见数据）
    ▼
返回响应
```

### 5.3 角色上下文注解

```java
/**
 * 标记接口所需的角色类型
 */
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    RoleType[] value();
    boolean requireAll() default false; // false=满足其一即可, true=需全部满足
}

// 使用示例
@RestController
@RequestMapping("/api/v1/teacher")
public class TeacherController {

    @RequireRole(RoleType.TEACHER)
    @GetMapping("/classes")
    public Result<List<ClassDTO>> getMyClasses() {
        RoleContext ctx = RoleContextHolder.get();
        return Result.success(teacherService.getClasses(ctx.getRoleId()));
    }

    @RequireRole({RoleType.TEACHER, RoleType.SCHOOL_ADMIN})
    @PostMapping("/homework")
    public Result<HomeworkDTO> publishHomework(@RequestBody HomeworkReq req) {
        RoleContext ctx = RoleContextHolder.get();
        return Result.success(homeworkService.publish(ctx, req));
    }
}
```

### 5.4 RoleContext 对象

```java
/**
 * 请求级角色上下文，在拦截器中设置
 */
public class RoleContext {
    private final Long accountId;
    private final Long roleId;
    private final RoleType roleType;
    private final String deviceId;
    private final String ipAddress;
    private final Map<String, Object> profileAttributes; // 角色Profile的缓存数据

    // 便捷方法
    public boolean isStudent() {
        return roleType == RoleType.STUDENT;
    }

    public boolean isParent() {
        return roleType == RoleType.PARENT;
    }

    public boolean isTeacher() {
        return roleType == RoleType.TEACHER;
    }

    public Long getActiveStudentRoleId() {
        if (roleType == RoleType.PARENT) {
            return (Long) profileAttributes.get("activeStudentRoleId");
        }
```

```dart
  static final RoleManager _instance = RoleManager._();
  factory RoleManager() => _instance;
  RoleManager._();

  RoleContext? _currentRole;
  List<RoleSummary> _availableRoles = [];

  /// 获取当前角色上下文
  RoleContext get currentRole {
    if (_currentRole == null) {
      throw StateError('角色未初始化，请先登录');
    }
    return _currentRole!;
  }

  /// 切换角色
  Future<void> switchRole(int targetRoleId) async {
    final response = await apiClient.post(
      '/api/v1/account/roles/switch',
      body: {'targetRoleId': targetRoleId},
    );

    // 更新 Token
    await tokenStore.saveAccessToken(response['accessToken']);
    await tokenStore.saveRefreshToken(response['refreshToken']);

    // 更新角色上下文
    _currentRole = RoleContext.fromJson(response);

    // 清理上一角色的页面缓存
    navigationService.resetToHome(response['homePage']);

    // 通知全局状态变更
    eventBus.fire(RoleSwitchedEvent(_currentRole!));
  }

  /// 获取可用角色列表
  Future<List<RoleSummary>> loadRoles() async {
    final response = await apiClient.get('/api/v1/account/roles');
    _availableRoles = (response['roles'] as List)
        .map((e) => RoleSummary.fromJson(e))
        .toList();

    // 确保当前角色已设置
    if (_currentRole == null && response['activeRole'] != null) {
      _currentRole = RoleContext.fromActiveRole(response['activeRole']);
    }

    return _availableRoles;
  }

  /// 检查是否有某角色
  bool hasRole(RoleType type) {
    return _availableRoles.any((r) => r.roleType == type);
  }

  /// 当前角色是否为指定类型
  bool get isStudent => _currentRole?.roleType == RoleType.student;
  bool get isParent => _currentRole?.roleType == RoleType.parent;
  bool get isTeacher => _currentRole?.roleType == RoleType.teacher;
}
```

## 8. 数据隔离策略

### 8.1 数据隔离原则

| 数据类别 | 隔离方式 | 说明 |
| --- | --- | --- |
| 学习记录 | `student_role_id` | 绑定到学生角色，与账号解耦 |
| 错题数据 | `student_role_id` | 同上 |
| AI 对话 | `role_id` | 对话归属于发起角色 |
| 家长查看数据 | 通过 `parent_student_binding` 间接访问 | 家长无直接数据所有权 |
| 教师班级数据 | `teacher_role_id` | 班级管理权限绑定到教师角色 |
| 订单与会员 | `user_account_id` | 订单属于账号级别，多角色共享 |
| 站内消息 | `role_id` | 消息归属于角色（学生消息≠教师消息） |
| 审计日志 | `role_id` | 操作记录绑定到角色 |

### 8.2 查询层隔离实现

```java
/**
 * MyBatis 拦截器：自动为查询追加角色隔离条件
 */
@Intercepts({
    @Signature(type = Executor.class, method = "query",
               args = {MappedStatement.class, Object.class, RowBounds.class, ResultHandler.class})
})
public class RoleDataIsolationInterceptor implements Interceptor {

    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        // 获取当前角色上下文
        RoleContext ctx = RoleContextHolder.get();

        // 获取MappedStatement和参数
        MappedStatement ms = (MappedStatement) invocation.getArgs()[0];
        Object parameter = invocation.getArgs()[1];

        // 检查是否标记了 @RoleIsolated
        if (hasRoleIsolatedAnnotation(ms)) {
            // 注入角色隔离条件
            parameter = injectRoleCondition(parameter, ctx);
        }

        return invocation.proceed();
    }

    private Object injectRoleCondition(Object parameter, RoleContext ctx) {
        if (parameter instanceof Map) {
            Map<?, ?> map = (Map<?, ?>) parameter;
            // 根据当前角色类型注入对应的角色ID
            if (ctx.isStudent()) {
                ((Map) map).put("ownerRoleId", ctx.getRoleId());
            } else if (ctx.isParent()) {
                // 家长只能查看绑定学生的数据
                Long activeStudentRoleId = ctx.getActiveStudentRoleId();
                ((Map) map).put("ownerRoleId", activeStudentRoleId);
                ((Map) map).put("viewerRoleId", ctx.getRoleId());
                ((Map) map).put("isParentView", true);
            } else if (ctx.isTeacher()) {
                ((Map) map).put("ownerRoleId", ctx.getRoleId());
            }
        }
        return parameter;
    }
}
```

```java
@Service
public class RoleCacheService {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    @Autowired
    private RoleIdentityMapper roleIdentityMapper;

    private static final long ROLES_TTL = TimeUnit.MINUTES.toSeconds(30);
    private static final long PROFILE_TTL = TimeUnit.HOURS.toSeconds(1);
    private static final long ACTIVE_ROLE_TTL = TimeUnit.HOURS.toSeconds(24);

    /**
     * 获取用户角色列表（带缓存）
     */
    public List<RoleIdentity> getRolesByAccountId(Long accountId) {
        String key = String.format("account:roles:%d", accountId);
        List<RoleIdentity> roles = (List<RoleIdentity>) redisTemplate.opsForValue().get(key);
        if (roles == null) {
            roles = roleIdentityMapper.selectByAccountId(accountId);
            redisTemplate.opsForValue().set(key, roles, ROLES_TTL, TimeUnit.SECONDS);
        }
        return roles;
    }

    /**
     * 切换角色时更新缓存
     */
    public void updateActiveRole(Long accountId, Long roleId, RoleType roleType) {
        String activeKey = String.format("account:active_role:%d", accountId);
        Map<String, Object> activeRole = Map.of(
            "roleId", roleId,
            "roleType", roleType.getCode(),
            "updatedAt", System.currentTimeMillis()
        );
        redisTemplate.opsForValue().set(activeKey, activeRole, ACTIVE_ROLE_TTL, TimeUnit.SECONDS);
    }

    /**
     * 角色变更时失效相关缓存
     */
    public void evictRoleCache(Long accountId, Long roleId) {
        redisTemplate.delete(String.format("account:roles:%d", accountId));
        redisTemplate.delete(String.format("account:active_role:%d", accountId));
        redisTemplate.delete(String.format("role:profile:%d", roleId));
        redisTemplate.delete(String.format("role:permissions:%d", roleId));
    }
}
```

## 12. 安全与合规

### 12.1 角色安全策略

| 安全场景 | 策略 |
| --- | --- |
| 切换到管理角色 | 需要短信验证码二次验证 |
| 新设备首次切换 | 触发设备验证 |
| 频繁切换（>10次/小时） | 触发风控审查 |
| 未成年人添加角色 | 禁止添加 TEACHER/OPERATOR/SCHOOL_ADMIN |
| 解绑家长角色 | 需要确认当前无活跃订阅或转移订阅 |
| 解绑最后角色 | 拒绝操作，提示至少保留一个 |

### 12.2 Token 安全

1. **旧 Token 失效**：角色切换后，旧 access_token 的 `jti` 写入 Redis 黑名单，TTL 等于剩余有效期。
2. **Refresh Token 轮换**：每次角色切换生成新的 refresh_token，旧 refresh_token 失效。
3. **并发登录控制**：同一账号同一角色仅允许 N 个设备在线（默认 3），超出时踢出最早设备。

```java
@Service
public class TokenBlacklistService {

    private static final String BLACKLIST_PREFIX = "token:blacklist:";

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    /**
     * 将旧 Token 加入黑名单
     */
    public void blacklistToken(String jti, long remainingSeconds) {
        if (remainingSeconds > 0) {
            String key = BLACKLIST_PREFIX + jti;
            redisTemplate.opsForValue().set(key, "1", remainingSeconds, TimeUnit.SECONDS);
        }
    }

    /**
     * 检查 Token 是否在黑名单中
     */
    public boolean isBlacklisted(String jti) {
        return Boolean.TRUE.equals(redisTemplate.hasKey(BLACKLIST_PREFIX + jti));
    }
}
```

### 14.4 并发安全

```java
/**
 * 使用分布式锁防止并发角色操作
 */
@Service
public class RoleSwitchService {

    private static final String LOCK_KEY = "role:switch:lock:%d";

    @Autowired
    private RedisLock redisLock;

    public SwitchResult switchRole(Long accountId, Long targetRoleId) {
        String lockKey = String.format(LOCK_KEY, accountId);

        return redisLock.execute(lockKey, Duration.ofSeconds(5), () -> {
            // 双重检查：确认角色状态
            RoleIdentity target = roleIdentityMapper.selectById(targetRoleId);
            if (target == null || target.getStatus() != RoleStatus.ACTIVE) {
                throw RoleException.roleDisabled(targetRoleId);
            }

            // 执行切换
            return doSwitch(accountId, target);
        });
    }
}
```
