## 1. 概述

### 1.1 文档目的

本文档对 PrimeTop 平台「作文深度批改包」这一增值服务进行细化设计，覆盖商品定义、购买发放、按次消费、批改结果交付、退款与过期回收等全链路，使开发人员能够据此独立完成该模块的后端服务、客户端接口及管理后台开发。

### 1.2 功能定位

作文深度批改包是会员体系之外的按次付费增值服务：

- 用户购买后获得固定次数的「深度批改」权益；
- 每次提交作文进行深度批改时扣除 1 次；
- 深度批改比普通 AI 作文辅导多维度更全面，输出：立意、结构、语言、素材、书写、创意、总分与改进建议；
- 支持同一篇作文的多轮批改（每轮均扣次，除非首轮判定为无效提交）。

### 1.3 设计边界

| 范围内 | 范围外 |
|--------|--------|
| 作文深度批改包的商品配置与 SKU 管理 | 通用商品管理（见增值服务与商品系统） |
| 用户购买后的资产发放与扣减 | 支付渠道对接与资金清结算（见支付服务） |
| 按次消费的幂等扣减 | 通用作文批改评分算法（见作文批改评分引擎） |
| 多轮批改消费规则与状态记录 | 客户端富文本编辑器、UI 排版 |
| 退款/过期/申诉回收逻辑 | 通用用户资产、额度门控 |

### 1.4 术语

| 术语 | 说明 |
|------|------|
| ESSAY_CORRECT | 资产类型，表示作文深度批改次数 |
| CorrectionRound | 同一篇作文的第 N 轮批改，round=1 为首轮 |
| ESSAY_CORRECT_PACK | 商品编码前缀，示例 `ESSAY_CORRECT_PACK_5` |
| CorrectionTicket | 一次批改扣减后生成的消费凭证，用于与评分引擎对账 |
| DeepCorrection | 深度批改结果，区别于普通 AI 辅导中的轻量润色 |

## 2. 数据结构设计

### 2.1 复用通用表

作文深度批改包复用《增值服务与商品系统》中的以下核心表：

- `product` / `product_sku`：商品与 SKU 定义；
- `user_asset`：用户资产（次数/时长包）；
- `asset_consume_log`：资产消费流水；
- `vas_order` / `vas_order_item`：增值服务订单（与支付订单关联）。

本文档只补充作文深度批改特有的扩展表。

### 3.2 内部 gRPC 接口

服务于评分引擎与额度门控之间的内部调用。

```protobuf
syntax = "proto3";
package essay.v1;

service EssayCorrectionQuotaService {
  // 预扣减：返回是否成功、剩余次数、扣减凭证
  rpc PreDeduct(PreDeductRequest) returns (PreDeductResponse);

  // 确认扣减：评分引擎完成批改后调用
  rpc ConfirmDeduct(ConfirmDeductRequest) returns (ConfirmDeductResponse);

  // 回滚扣减：评分失败或作文无效时调用
  rpc RollbackDeduct(RollbackDeductRequest) returns (RollbackDeductResponse);

  // 查询某次批改是否已扣次
  rpc GetConsumeStatus(GetConsumeStatusRequest) returns (GetConsumeStatusResponse);
}

message PreDeductRequest {
  int64 user_id = 1;
  string asset_type = 2;      // 固定 ESSAY_CORRECT
  int32 amount = 3;            // 固定 1
  string business_type = 4;    // ESSAY_CORRECT
  string business_id = 5;      // submission_no
  string trace_id = 6;
  string client_request_id = 7;
}

message PreDeductResponse {
  bool success = 1;
  int32 remaining = 2;
  int64 asset_id = 3;
  int64 consume_log_id = 4;
  string error_code = 5;
}

message ConfirmDeductRequest {
  int64 consume_log_id = 1;
  string submission_no = 2;
  string trace_id = 3;
}

message ConfirmDeductResponse {
  bool success = 1;
}

message RollbackDeductRequest {
  int64 consume_log_id = 1;
  string submission_no = 2;
  string reason = 3;
  string trace_id = 4;
}

message RollbackDeductResponse {
  bool success = 1;
}
```

## 4. 核心流程

### 4.1 购买与资产发放流程

```text
1. 客户端 -> VAS 商品系统：选择 SKU，创建增值服务订单
2. 支付服务：调起微信支付/支付宝/IAP
3. 支付回调成功 -> VAS 订单服务：确认订单
4. VAS 订单服务 -> 资产服务：grant_asset(
     user_id, asset_type=ESSAY_CORRECT,
     quota=sku.quota, source_type=PURCHASE,
     source_id=order_id, expires_at=now+validity_days
   )
5. 资产服务：写入 user_asset，刷新 Redis 缓存
6. 资产服务 -> Outbox：asset.granted 事件
7. 客户端：轮询资产到账，刷新「我的批改资产」
```

**发放幂等：** 通过 `source_type + source_id + asset_type + user_id` 唯一索引保证同一订单不重复发放。

### 4.2 提交批改与消费扣减流程

```text
1. 客户端上传作文内容 -> essay_content 落库
2. 客户端 POST /essay-correction/submissions
   携带 essay_id、grade、is_rewrite
3. 服务端执行字数校验、年级校验、多轮冷却校验
4. 服务端调用额度服务 PreDeduct(
     user_id, asset_type=ESSAY_CORRECT, amount=1)
   - 成功：写入 essay_correction_submission 状态=PENDING
   - 失败：返回余额不足，引导购买
5. 服务端将批改任务投递给 Kafka topic: essay.correction.task
6. 评分引擎消费任务 -> 执行深度批改
7. 评分引擎回调 ConfirmDeduct(consume_log_id)
8. 服务端更新 submission 状态 COMPLETED，写入 score_summary
9. 服务端通过 SSE / WebSocket / 轮询通知客户端结果就绪
10. 客户端 GET /essay-correction/submissions/{no} 拉取结果
```

**失败回退：**

- 若字数不足、图片无法识别、内容违规等「无效提交」：在 PreDeduct 成功后立即 Rollback；
- 若评分引擎异常：60s 内超时自动 Rollback（由补偿任务扫描执行）。

### 4.3 退款与过期回收流程

#### 4.3.1 未消费全额退款

```text
1. 管理后台/用户端发起退款申请
2. 校验：asset 来源=PURCHASE、未使用、未过期、购买 <= 7 天
3. 售后服务 -> 资产服务：revoke_asset(asset_id)
4. 资产服务更新 user_asset.status=REFUNDED
5. 资产服务 -> Outbox：asset.revoked
6. 支付服务 -> 原路退款
```

#### 4.3.2 部分消费退款

- 按剩余未使用次数比例退款；
- 已使用次数按单价折算，不退；
- 退款后剩余次数清零，资产标记为 REFUNDED。

#### 4.3.3 过期回收

- 每日 04:00 扫描 `user_asset` 中 `asset_type=ESSAY_CORRECT` 且 `expires_at < now()` 且 `remaining_quota > 0` 的记录；
- 状态改为 EXPIRED；
- 写入 asset_consume_log action=EXPIRE；
- 删除 Redis 剩余缓存。

### 4.4 多轮批改规则

| 场景 | 扣次规则 |
|------|----------|
| 同一篇作文，修改后再次提交 | round_no +1，扣 1 次 |
| 首轮提交后 5 分钟内重复提交（未修改） | 视为重试，不扣次 |
| 评分引擎判定为无效作文（字数不足/内容违规） | 回滚扣次 |
| 同轮多次查询结果 | 不重复扣次 |
| 已达最大轮数 | 拒绝提交，返回 59406 |

```text
  │ refund
  ▼
REFUNDED
```

| 状态 | 说明 |
|------|------|
| ACTIVE | 有效，可消费 |
| PARTIAL_USED | 已部分使用（逻辑状态，实际仍映射为 status=1） |
| DEPLETED | 已用完，status=2 |
| EXPIRED | 已过期，status=3 |
| REFUNDED | 已退款，status=4 |

### 5.2 提交批改状态机

```text
PENDING
  │
  │ 通过校验并扣次
  ▼
SUBMITTED ──投递评分任务──> SCORING
  │
  │ 评分成功
  ▼
COMPLETED
  │
  │ 评分失败/内容无效
  ▼
FAILED ──回滚扣次──> REFUNDED(quota)
  │
  │ 申诉成功
  ▼
REFUNDED
```

### 5.3 消费流水状态机

消费流水一旦写入即为终态，不修改：

```text
CREATED -> CONFIRMED
       -> ROLLED_BACK
       -> EXPIRED (系统批量)
```

## 6. 关键代码示例

### 6.1 预扣减与提交流程（Python 伪代码）

```python
class EssayCorrectionApplicationService:

    async def submit(self, cmd: SubmitEssayCorrectionCommand) -> SubmissionDTO:
        # 1. 幂等锁
        lock_key = f"essay:submit:lock:{cmd.client_request_id}"
        if not await redis.set(lock_key, "1", nx=True, ex=60):
            raise DuplicateSubmissionError(code=59404)

        # 2. 多轮校验
        round_info = await self._ensure_round_allowed(cmd)

        # 3. 字数校验
        essay = await essay_repo.get(cmd.essay_id)
        config = await product_essay_config_repo.get(cmd.product_code)
        if essay.word_count < config.min_word_count:
            raise InvalidEssayError(code=59407)

        # 4. 预扣减
        pre = await quota_service.pre_deduct(
            user_id=cmd.user_id,
            asset_type="ESSAY_CORRECT",
            amount=1,
            business_type="ESSAY_CORRECT",
            business_id=cmd.client_request_id,
            trace_id=cmd.trace_id,
            client_request_id=cmd.client_request_id,
        )
        if not pre.success:
            raise QuotaInsufficientError(
                remaining=pre.remaining,
                suggested_product=pre.suggested_product,
                code=59401,
            )

        # 5. 持久化提交记录
        submission = EssayCorrectionSubmission.create(
            user_id=cmd.user_id,
            asset_id=pre.asset_id,
            consume_log_id=pre.consume_log_id,
            essay_id=cmd.essay_id,
            grade=cmd.grade,
            subject=cmd.subject,
            round_no=round_info.round_no,
            parent_submission_id=round_info.parent_id,
            client_request_id=cmd.client_request_id,
            trace_id=cmd.trace_id,
            status="PENDING",
        )
        await submission_repo.save(submission)

        # 6. 更新多轮聚合记录
        await round_repo.upsert(
            essay_id=cmd.essay_id,
            user_id=cmd.user_id,
            latest_round=round_info.round_no,
            next_available_at=now() + timedelta(hours=config.round_cooldown_hours or 0),
        )

        # 7. 状态推进为 SUBMITTED 并投递评分任务
        submission.submit()
        await submission_repo.update_status(submission)
        await kafka_producer.send(
            topic="essay.correction.task",
            key=submission.submission_no,
            value=submission.to_task_payload(),
        )

        return SubmissionDTO.from_entity(submission, remaining=pre.remaining - 1)
```

### 6.2 评分引擎回调确认消费

```python
async def on_correction_completed(event: CorrectionCompletedEvent):
    submission = await submission_repo.get_by_no(event.submission_no)
    if submission.status != "SCORING":
        logger.warning("submission not in SCORING, ignore: %s", event.submission_no)
        return

    # 确认扣减（幂等）
    await quota_service.confirm_deduct(
        consume_log_id=submission.consume_log_id,
        submission_no=submission.submission_no,
        trace_id=event.trace_id,
    )

    # 更新结果
    submission.complete(event.score_summary)
    await submission_repo.update(submission)

    # 通知客户端
    await notification_service.notify_user(
        user_id=submission.user_id,
        event="essay.correction.completed",
        payload={"submission_no": submission.submission_no},
    )
```

### 6.3 无效提交回滚

```python
async def on_invalid_essay(event: InvalidEssayEvent):
    submission = await submission_repo.get_by_no(event.submission_no)
    if submission.status not in ("PENDING", "SUBMITTED"):
        return

    # 回滚扣减
    await quota_service.rollback_deduct(
        consume_log_id=submission.consume_log_id,
        submission_no=submission.submission_no,
        reason=event.reason,
        trace_id=event.trace_id,
    )

    submission.mark_invalid(event.reason, event.error_code)
    await submission_repo.update(submission)
```

### 6.4 Lua 原子扣减脚本

```lua
-- KEYS[1]: asset:{user_id}:{asset_type}:remaining
-- ARGV[1]: 扣减数量
local remaining = tonumber(redis.call('HGET', KEYS[1], 'remaining'))
if remaining == nil or remaining < tonumber(ARGV[1]) then
    return {-1, remaining or 0}
end
local new_remaining = remaining - tonumber(ARGV[1])
redis.call('HSET', KEYS[1], 'remaining', new_remaining)
return {new_remaining, new_remaining}
```

## 8. 幂等与并发控制

### 8.1 幂等键

| 场景 | 幂等键 | 位置 |
|------|--------|------|
| 提交批改 | `client_request_id` | 请求头 X-Client-Request-Id |
| 扣减确认 | `consume_log_id` | gRPC 参数 |
| 扣减回滚 | `consume_log_id` | gRPC 参数 |
| 发放资产 | `source_type + source_id + asset_type + user_id` | DB 唯一索引 |
| 退款 | `asset_id + refund_order_no` | DB 唯一索引 |

### 8.2 并发裁决

- 同一 `client_request_id` 在 60s 内只能创建一次提交；
- `essay_correction_round` 使用 `INSERT ... ON DUPLICATE KEY UPDATE` 更新 latest_round，配合 Redis 锁防止并发多扣；
- 评分引擎回调 Confirm/Rollback 时，先查消费流水状态，已终态直接返回成功，避免双写；
- 退款与消费竞态：先对资产加悲观锁或 Redis 分布式锁，再执行退款。

## 10. 降级与容灾

| 故障场景 | 降级策略 | 红线 |
|----------|----------|------|
| 额度服务 Redis 不可用 | 直接查 DB 扣减，DB 不可用则拒绝提交 | 不允许无扣减放行 |
| 评分引擎不可用 | 拒绝新提交；已扣次任务进入补偿队列 30min 后回滚 | 已扣次未批改必须可回滚 |
| 对象存储不可用 | 仅接受文本输入，图片提交提示稍后重试 | - |
| Kafka 不可用 | 写入本地表，定时任务补偿投递 | 提交记录不丢 |
| 用户资产服务异常 | 无法购买，不影响已购买用户的消费 | - |
| 未成年人支付风控拦截 | 阻断购买，引导家长授权 | 合规优先 |

## 12. 安全与合规

### 12.1 未成年人保护

- 购买需经未成年人支付风控校验（见《服务端-未成年人支付风控与误充值自动识别退款引擎》）；
- 14 岁以下用户单笔消费不超过 50 元，月累计不超过 200 元；
- 购买成功后同步家长通知，不含作文原文；
- 退款按剩余价值计算，已批改次数不退。

### 12.2 数据隐私

- 作文原文存储加密，90 天后归档；
- 消费记录保留 180 天；
- 用户注销后 180 天延迟删除作文内容与批改记录。

### 12.3 内容安全

- 提交内容先经过教育场景敏感词过滤；
- 违规作文不计入批改次数，直接回滚；
- 批改结果输出前经过 AI 回答后处理安全过滤。
