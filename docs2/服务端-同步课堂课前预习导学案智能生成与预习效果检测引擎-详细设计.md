# 服务端-同步课堂课前预习导学案智能生成与预习效果检测引擎 详细设计

## 1. 概述

### 1.1 模块定位

课前预习导学案智能生成与预习效果检测引擎是同步课堂学习模块的核心子服务之一。它负责在学生进入新章节学习之前，基于教材章节内容、知识点体系、学生当前学情画像，自动生成个性化预习导学案（含知识导读、重点词汇、基础概念、预习自测题），并在学生完成预习后检测预习效果，将检测结果反馈给后续课堂学习流编排服务，实现"预习→检测→课堂学习→课后复习"的完整学习闭环。

### 1.2 核心职责

| 职责 | 说明 |
| --- | --- |
| 预习导学案生成 | 根据章节知识点、教材内容、学生学情，生成结构化预习导学案 |
| 预习内容推送 | 将导学案推送到客户端，支持离线缓存 |
| 预习自测评估 | 生成预习检测题，评估学生预习效果 |
| 预习效果反馈 | 输出预习掌握度数据，驱动后续学习流编排 |
| 预习数据沉淀 | 记录预习行为数据，供学情分析和学习报告使用 |

### 1.3 依赖关系

```
┌─────────────────────────────────────────────────────────┐
│               课前预习导学案智能生成引擎                   │
├─────────────┬─────────────┬──────────────┬──────────────┤
│  章节内容    │  知识点体系   │  学生学情    │  AI大模型    │
│  聚合服务    │  管理服务     │  画像服务    │  调用服务    │
│  (上游)      │  (上游)      │  (上游)      │  (下游)      │
└─────────────┴─────────────┴──────────────┴──────────────┘
                         │
                         ▼
              ┌─────────────────────┐
              │  学习流编排服务      │
              │  (下游消费者)        │
              └─────────────────────┘
```

**上游依赖：**
- 同步课堂章节内容聚合服务：提供章节教材内容、知识结构
- 知识点体系管理服务：提供知识点定义、前置依赖关系
- 学生学情画像服务：提供当前掌握度、学习风格、认知水平
- AI Prompt 编排服务：提供大模型调用能力

**下游消费者：**
- 同步课堂学习流编排服务：接收预习效果数据，调整课堂学习路径
- 学情分析服务：消费预习行为数据
- 学习记录服务：记录预习完成情况
- 通知服务：发送预习提醒

## 2. 数据模型

### 2.1 核心实体定义

#### 2.1.1 PreviewGuide（预习导学案）

```typescript
interface PreviewGuide {
  id: string;                          // 导学案唯一ID (UUID)
  studentId: string;                   // 学生ID
  textbookVersionId: string;           // 教材版本ID
  subjectCode: string;                 // 学科编码 (e.g. "math", "chinese")
  gradeLevel: string;                  // 年级 (e.g. "grade_7")
  chapterId: string;                   // 章节ID
  lessonId?: string;                   // 课时ID (可选，精确到课时级别)
  guideType: GuideType;                // 导学案类型
  status: GuideStatus;                 // 生成状态
  sections: GuideSection[];            // 导学案各模块内容
  generatedAt: string;                 // 生成时间 (ISO 8601)
  expiredAt: string;                   // 过期时间 (章节学习完成后失效)
  modelVersion: string;                // 生成所用AI模型版本
  metadata: GuideMetadata;             // 元数据
}

type GuideType = 'STANDARD' | 'REINFORCED' | 'ADVANCED' | 'REVIEW';
// STANDARD: 标准预习导学案
// REINFORCED: 补强型预习 (针对薄弱基础)
// ADVANCED: 拔尖型预习 (针对学有余力)
// REVIEW: 复习型导学案 (章节复习场景)

type GuideStatus = 'GENERATING' | 'READY' | 'IN_PROGRESS' | 'COMPLETED' | 'EXPIRED' | 'FAILED';

interface GuideSection {
  sectionType: SectionType;
  title: string;
  content: string;                     // Markdown格式内容
  estimatedMinutes: number;            // 预计用时(分钟)
  order: number;                       // 排序
  interactions?: InteractionConfig;    // 交互配置
}

type SectionType =
  | 'KNOWLEDGE_OVERVIEW'    // 知识导读
  | 'KEY_VOCABULARY'        // 重点词汇/术语
  | 'BASIC_CONCEPTS'        // 基础概念
  | 'PREREQUISITE_REVIEW'   // 前置知识回顾
  | 'GUIDING_QUESTIONS'     // 导学思考题
  | 'PREVIEW_QUIZ'          // 预习自测题
  | 'REAL_WORLD_CONNECTION';// 生活化联系

interface GuideMetadata {
  knowledgePointIds: string[];         // 涉及知识点ID列表
  difficultyLevel: number;             // 难度等级 1-5
  bloomLevel: BloomLevel;              // 布鲁姆认知层级
  estimatedTotalMinutes: number;       // 预计总用时
  generatedBy: 'AI' | 'TEMPLATE' | 'HYBRID';
  promptTemplateId?: string;           // 使用的Prompt模板ID
  contentHash: string;                 // 内容哈希 (用于缓存/去重)
}

type BloomLevel = 'REMEMBER' | 'UNDERSTAND' | 'APPLY' | 'ANALYZE' | 'EVALUATE' | 'CREATE';
```

```typescript
interface PreviewQuiz {

  explanation: string;                 // 答案解析
  difficulty: number;                  // 难度 1-5
  bloomLevel: BloomLevel;

}

type PreviewQuestionType =
  | 'SINGLE_CHOICE'       // 单选
  | 'MULTIPLE_CHOICE'     // 多选
  | 'TRUE_FALSE'          // 判断

```

#### 2.1.3 PreviewResult（预习效果记录）

```typescript
interface PreviewResult {
  id: string;
  guideId: string;                     // 导学案ID
  studentId: string;
  chapterId: string;
  startedAt: string;                   // 开始时间
  completedAt?: string;                // 完成时间
  durationMinutes: number;             // 实际用时

  sectionProgress: SectionProgress[];  // 各模块完成情况

interface SectionProgress {
  sectionType: SectionType;
  status: 'NOT_VIEWED' | 'VIEWED' | 'STUDIED' | 'SKIPPED';
  viewCount: number;
  timeSpentSeconds: number;
}

interface QuizResult {
  totalQuestions: number;
  correctCount: number;
  score: number;                       // 百分比
  passed: boolean;
  attemptCount: number;
  questionResults: QuestionResult[];
}

interface QuestionResult {
  questionId: string;
  studentAnswer: string;
  isCorrect: boolean;
  timeSpentSeconds: number;
}

interface MasterySnapshot {
  // 预习后各知识点掌握度 (0-1)
  knowledgePointMastery: Map<string, number>;
  // 整体预习掌握度
  overallMastery: number;
  // 预估认知层级
  achievedBloomLevel: BloomLevel;
}

interface LessonFeedback {
  // 推荐课堂学习起点
  recommendedStartPoint: 'BEGINNING' | 'KEY_CONCEPTS' | 'ADVANCED_TOPIC' | 'PRACTICE';
  // 识别到的共性薄弱点
  weakKnowledgePoints: string[];
  // 已掌握的知识点 (可跳过基础讲解)
  masteredKnowledgePoints: string[];
  // 建议课堂重点
  suggestedFocusAreas: string[];
  // 建议课堂难度
  suggestedDifficulty: number; // 1-5
}

interface StudentFeedback {
  difficultyRating: number;            // 难度评价 1-5
  helpfulRating: number;               // 有用程度 1-5
  comment?: string;                    // 文字反馈
}
```

### 2.3 缓存策略

| 缓存层 | Key 设计 | TTL | 用途 |
| --- | --- | --- | --- |
| Redis L1 | `pg:student:{studentId}:chapter:{chapterId}` | 2h | 学生当前导学案热数据 |
| Redis L2 | `pg:cache:hash:{contentHash}` | 24h | 相同参数导学案复用 |
| Redis L3 | `pg:result:{guideId}` | 7d | 预习结果热数据 |
| DB Cache | preview_guide_cache 表 | 30d | 跨学生导学案复用 |

**缓存复用策略：**
- 同一教材版本 + 同一年级 + 同一章节 + 同一导学案类型 → 可复用导学案内容
- 学生个性化部分（如难度适配）通过参数差异区分，不影响基础内容复用
- 当教材内容更新时，旧缓存自动失效（通过 content_hash 变化检测）

### 3.2 核心接口详细定义

#### 3.2.1 生成预习导学案

```
POST /api/v1/preview/guides
```

**请求体：**
```json
{
  "studentId": "stu_2026_00001",
  "chapterId": "ch_math_7a_ch3",
  "subjectCode": "math",
  "gradeLevel": "grade_7",
  "textbookVersionId": "tb_people_edition_v2024",
  "lessonId": "lesson_3_1",
  "guideType": "STANDARD",
  "forceRegenerate": false,
  "preferences": {
    "preferredLearningStyle": "VISUAL",
    "estimatedTimeMinutes": 15,
    "difficultyPreference": "AUTO"
  }
}
```

**响应（202 Accepted）：**
```json
{
  "code": 0,
  "data": {
    "guideId": "pg_a3f5e8d2_20260709",
    "status": "GENERATING",
    "estimatedWaitSeconds": 8,
    "callbackUrl": "/api/v1/preview/guides/pg_a3f5e8d2_20260709/status"
  }
}
```

**错误码：**

| 错误码 | 说明 | HTTP Status |
| --- | --- | --- |
| 40901 | 该章节导学案已存在且未过期 | 409 |
| 40902 | 章节内容尚未就绪（教材未配置） | 422 |
| 42901 | 生成频率超限 (同一章节5分钟内只能生成1次) | 429 |
| 50301 | AI模型服务不可用 | 503 |

### 4.4 预习效果评估算法

#### 4.4.1 掌握度计算

```typescript
/**
 * 计算预习后各知识点掌握度
 * 综合考虑：自测题正确率 + 预习时长充分度 + 模块完成度
 */
function calculateMastery(
  quizResult: QuizResult,
  sectionProgress: SectionProgress[],
  knowledgePoints: KnowledgePoint[],
  estimatedMinutes: number
): MasterySnapshot {
  const knowledgePointMastery = new Map<string, number>();

  for (const kp of knowledgePoints) {
    // 1. 基于自测题的掌握度 (权重60%)
    const kpQuestions = quizResult.questionResults.filter(
      qr => getKnowledgePointForQuestion(qr.questionId) === kp.id
    );
    const quizMastery = kpQuestions.length > 0
      ? kpQuestions.filter(q => q.isCorrect).length / kpQuestions.length
      : 0.5; // 无题目关联时默认0.5

    // 2. 基于模块完成度的掌握度 (权重25%)
    const relatedSections = getSectionsForKnowledgePoint(kp.id, sectionProgress);
    const completionRate = relatedSections.length > 0
      ? relatedSections.filter(s => s.status === 'STUDIED').length / relatedSections.length
      : 0.5;

    // 3. 基于时间充分度的掌握度 (权重15%)
    const actualTime = sectionProgress.reduce((sum, s) => sum + s.timeSpentSeconds, 0) / 60;
    const timeRatio = Math.min(actualTime / estimatedMinutes, 1.5);
    const timeMastery = Math.min(timeRatio * 0.6, 1); // 时间充分但不超过1

    // 综合掌握度
    const mastery = quizMastery * 0.6 + completionRate * 0.25 + timeMastery * 0.15;
    knowledgePointMastery.set(kp.id, Math.round(mastery * 100) / 100);
  }

  const overallMastery = Array.from(knowledgePointMastery.values())
    .reduce((sum, v) => sum + v, 0) / knowledgePointMastery.size;

  const achievedBloomLevel = determineBloomLevel(quizResult, knowledgePoints);

  return {
    knowledgePointMastery,
    overallMastery,
    achievedBloomLevel,
  };
}
```

#### 4.4.2 课堂学习反馈生成

```typescript
function generateLessonFeedback(
  mastery: MasterySnapshot,
  knowledgePoints: KnowledgePoint[],
  wrongKpIds: string[] = []             // v1.1 增补参数：自测错题关联知识点（v1.0 引用了未声明变量）
): LessonFeedback {
  const weakKnowledgePoints: string[] = [];
  const masteredKnowledgePoints: string[] = [];

  for (const [kpId, m] of mastery.knowledgePointMastery) {
    // < 0.5 → 薄弱点：课堂阶段需要重点讲解
    if (m < 0.5) {
      weakKnowledgePoints.push(kpId);
    }
    // >= 0.8 → 已掌握：课堂可跳过该知识点的基础讲解
    else if (m >= 0.8) {
      masteredKnowledgePoints.push(kpId);
    }
    // 0.5 ~ 0.8 → 发展中：不进任何清单，按常规节奏学习
  }

  // ① 推荐课堂学习起点：按整体掌握度分档
  let recommendedStartPoint: LessonFeedback['recommendedStartPoint'];
  if (mastery.overallMastery < 0.3) {
    recommendedStartPoint = 'BEGINNING';       // 基础严重不足，课堂从头讲
  } else if (mastery.overallMastery < 0.7) {
    recommendedStartPoint = 'KEY_CONCEPTS';    // 常规路径：从重点概念讲起
  } else if (mastery.overallMastery < 0.9) {
    recommendedStartPoint = 'ADVANCED_TOPIC';  // 预习充分：直接进入拓展主题
  } else {
    recommendedStartPoint = 'PRACTICE';        // 预习质量极高：直接进入练习环节
  }

  // ② 建议课堂难度：章节基础难度 + 掌握度偏移，收敛到 [1, 5]
  const baseDifficulty = knowledgePoints.length > 0
    ? knowledgePoints.reduce((sum, kp) => sum + kp.difficultyLevel, 0) / knowledgePoints.length
    : 2.5;
  const suggestedDifficulty = Math.max(1, Math.min(5,
    Math.round(baseDifficulty + (mastery.overallMastery - 0.5) * 2)));

  // ③ 建议课堂重点：薄弱知识点 ∪ 自测错题关联知识点（去重，上限 5 条）
  const kpNameMap = new Map(knowledgePoints.map(kp => [kp.id, kp.name]));
  const focusIds = Array.from(new Set([...weakKnowledgePoints, ...wrongKpIds]));
  const suggestedFocusAreas = focusIds
    .slice(0, 5)
    .map(id => kpNameMap.get(id) ?? id);

  return {
    recommendedStartPoint,
    weakKnowledgePoints,
    masteredKnowledgePoints,
    suggestedFocusAreas,
    suggestedDifficulty,
  };
}
```

> **设计说明**：`generateLessonFeedback` 为纯函数（相同输入产生相同输出），便于单元测试与结果复算；错题关联知识点由调用方从 `QuizResult` 提取后传入（`wrongKpIds`），避免函数内部二次查库。`KnowledgePoint` 的 `difficultyLevel` 与 `name` 字段由知识点体系管理服务提供。

#### 4.4.3 评估辅助函数

§4.4.1 引用的三个辅助函数统一定义如下（均优先读缓存，Redis L3 miss 回源 DB）：

```typescript
/**
 * 题目 → 知识点映射：读 preview_quiz.questions_json 内嵌的 knowledgePointId。
 * 运行于 PreviewEvaluationService 评估上下文（guideId 已知，闭包注入）。
 */
function getKnowledgePointForQuestion(questionId: string): string | null {
  const quiz = quizRepository.findByGuideId(currentGuideId);
  const question = quiz?.questions.find(q => q.id === questionId);
  return question?.knowledgePointId ?? null;
}

/**
 * 知识点 → 关联学习模块：基于内容装配期生成的「知识点×模块类型」映射（随 guide 元数据缓存）。
 * 未命中映射时回退默认关联模块。
 */
function getSectionsForKnowledgePoint(
  kpId: string,
  sectionProgress: SectionProgress[]
): SectionProgress[] {
  const relatedTypes: SectionType[] = guideMetadata.kpSectionMapping[kpId]
    ?? ['KNOWLEDGE_OVERVIEW', 'BASIC_CONCEPTS', 'PREREQUISITE_REVIEW'];
  return sectionProgress.filter(sp => relatedTypes.includes(sp.sectionType));
}

/**
 * 布鲁姆层级判定：逐层抬升，取「正确率 >= 60% 的最高认知层级」。
 * 层级来自题目元数据（课标目标层级）；题目缺失层级时回退其知识点的课标标注。
 */
function determineBloomLevel(
  quizResult: QuizResult,
  knowledgePoints: KnowledgePoint[] = []
): BloomLevel {
  const ORDER: BloomLevel[] =
    ['REMEMBER', 'UNDERSTAND', 'APPLY', 'ANALYZE', 'EVALUATE', 'CREATE'];
  const byLevel = new Map<BloomLevel, { total: number; correct: number }>();
  for (const qr of quizResult.questionResults) {
    const level = questionRepository.getTargetBloom(qr.questionId)
      ?? getKpTargetBloom(getKnowledgePointForQuestion(qr.questionId), knowledgePoints);
    const agg = byLevel.get(level) ?? { total: 0, correct: 0 };
    agg.total += 1;
    if (qr.isCorrect) agg.correct += 1;
    byLevel.set(level, agg);
  }
  let achieved: BloomLevel = 'REMEMBER';      // 全错/无题时兜底最低层
  for (const level of ORDER) {
    const agg = byLevel.get(level);
    if (agg && agg.total > 0 && agg.correct / agg.total >= 0.6) {
      achieved = level;
    }
  }
  return achieved;
}
```

**掌握度证据权重（与 §4.4.1 公式一致）：**

| 证据源 | 权重 | 设计理由 |
| --- | --- | --- |
| 自测题正确率 | 60% | 最客观的预习效果证据 |
| 模块完成度 | 25% | 防止「只做题不看导读」的投机路径 |
| 时间充分度 | 15% | 用时不足预估 2/3 视为预习不充分；`timeMastery` 封顶 1.0 防挂机刷时长 |

> 边界规则：知识点无关联题目时 `quizMastery` 取 0.5（中性先验，不奖惩）；D6 自评降级场景下自测证据缺失，权重自动归一为完成度 62.5% / 时长 37.5%（见 §9）。

### 4.5 模板降级生成器（TEMPLATE_FALLBACK）

§4.1 生成策略中的模板降级路径在此落地。模板生成完全不依赖 AI，保证 AI 服务全线故障时预习链路仍可用。

**模板库（配置中心管理，双缓冲热更新）：**

| 模板 ID | 适用范围 | guideType | 模块骨架 |
| --- | --- | --- | --- |
| TPL_GENERIC_STD | 全学科兜底 | STANDARD | 前置回顾 → 知识导读 → 术语表 → 导学思考题 → 生活联系 |
| TPL_GENERIC_REIN | 全学科 | REINFORCED | 前置回顾（加倍篇幅，含前置点清单）→ 基础概念 → 自评清单 |
| TPL_GENERIC_ADV | 全学科 | ADVANCED | 知识导读（简）→ 拓展问题 → 挑战自测引导 |
| TPL_MATH_REVIEW | 数学（示例） | REVIEW | 章节知识结构 → 易错点清单 → 复习自测引导 |

```typescript
class TemplateGuideGenerator {
  /**
   * 模板降级生成：内容槽位全部来自章节聚合 manifest 字段填充，禁止编造讲解正文。
   */
  async generate(ctx: PreviewContext): Promise<PreviewGuide> {
    const template = templateRegistry.resolve(
        ctx.config.subjectCode, ctx.config.guideType)
      ?? templateRegistry.resolve('generic', ctx.config.guideType);   // 通用兜底

    const sections: GuideSection[] = template.sectionSkeletons.map(skel => ({
      sectionType: skel.sectionType,
      title: skel.titleTemplate.replace('{chapterTitle}', ctx.chapter.title),
      content: this.fillSlots(skel, ctx),   // 填充 manifest 字段：summary/KP 名称列表/术语/前置点
      estimatedMinutes: skel.estimatedMinutes,
      order: skel.order,
    }));

    return this.buildGuide(ctx, sections, {
      generatedBy: 'TEMPLATE',              // 客户端据此展示「基础版」角标（合规 C3）
      promptTemplateId: template.id,
    });
  }
}
```

**模板降级约束：**

1. 模板内容只做「骨架 + 章节 manifest 字段填充」，模板中不得出现具体学科讲解正文（防止过期/错误内容固化）；
2. `generatedBy: 'TEMPLATE'` 必须透出至客户端并显示「基础版导学案」角标，不得冒充 AI 个性化内容（合规 C2/C3）；
3. 模板产物不进入 `preview_guide_cache` 跨学生复用表（守卫 G11，防止低质模板内容被当成优质缓存扩散）；
4. 模板导学案的自测题只走题库匹配（不走 AI 出题）；题库同时不可用时走 D6 自评降级。

### 4.6 预习有效期与过期处理

**有效期规则：**

| 场景 | expired_at 规则 | 触发方式 |
| --- | --- | --- |
| 默认 | `generated_at + 30 天` | 生成时写入 |
| 章节学习完成 | 学习记录服务 `chapter.completed` 事件到达即流转 EXPIRED（reason=CHAPTER_DONE） | 事件驱动 |
| 教材版本/学段切换 | 用户年级升迁服务事件触发该学生全部导学案 EXPIRED（reason=VERSION_SWITCH） | 事件驱动（守卫 G12） |

**过期扫描任务（每小时，分批 CAS，避免大事务）：**

```sql
-- 每批 500 行，影响行数 > 0 则继续下一批
UPDATE preview_guide
SET status = 'EXPIRED', updated_at = NOW(3)
WHERE status IN ('READY', 'IN_PROGRESS')
  AND expired_at < NOW()
ORDER BY id
LIMIT 500;

-- GENERATING 态过期说明异步生成任务挂死，单独捞出走 FAILED + preview.guide.failed 事件（守卫 G8）
```

**ABANDONED 判定（每日 02:00）：** `preview_result` 中 `status = 'IN_PROGRESS'` 且 `updated_at < NOW() - INTERVAL 30 DAY` 的记录流转为 ABANDONED——只改状态不删数据，预习行为数据保留供学情分析（事件 preview.abandoned）。

**REVIEW 型例外（守卫 G2 例外）：** 章节复习场景允许 REVIEW 型导学案与 STANDARD 型并存，不受「同章节唯一活跃导学案」约束；但同章节 7 天内仅允许 1 份 REVIEW 型。

| 事件 | 触发点（同事务写入） | 关键 payload | 消费方 |

### 7.3 消费幂等与对账

1. 消费方以 `(event_id, consumer)` 为幂等键，处理前先落消费记录，重复投递直接 ACK；
2. 掌握度融合：`preview.completed` 的 masterySnapshot 作为 `source=PREVIEW, weight=0.2` 的证据写入，不覆盖权威掌握度（边界见 §13 第 3 项）；
3. Relay 进程每 500ms 批量投递（≤200 条/批），指数退避重试，5 次失败进 DEAD 并 P2 告警；
4. 日终对账：Outbox SENT 与业务表状态交叉核对，差异以 `preview_guide/preview_result` DB 为准单向补投。

## 8. 幂等与并发控制

| 场景 | 机制 |
| --- | --- |
| 生成防重 | Redis `pg:gen:lock:{studentId}:{chapterId}` SETNX 10s（G1/G2 前置）+ DB 唯一活跃索引兜底 |
| 唯一活跃索引 | MySQL 8.0 函数唯一索引，仅约束活跃行（过期后可再次生成，避免「过期后无法重生成」撞键），DDL 见下 |
| 自测 attempt | SQL 原子自增 CAS（读出的 attemptCount < max_attempts 才更新），并发双击仅一次成功 |
| 完成幂等 | `preview_result` 上 `UNIQUE INDEX uk_guide_id (guide_id)` + 状态 CAS；重复 complete 返回已有结果（G6） |
| 进度上报 | 按 (guideId, sectionType) upsert 覆盖写；客户端携带 clientTimestamp，服务端取最新，不信任客户端累计值 |
| Outbox 一致性 | 生成/完成/过期三类写入点与业务写同事务，禁止跨事务补写 |
| 缓存击穿 | content_hash 重建加分布式锁（60s）；等待者读旧值或走模板兜底 |

唯一活跃索引 DDL（v1.1 增补，MySQL 8.0.13+，REVIEW 型通过键前缀实现独立命名空间）：

```sql
CREATE UNIQUE INDEX uk_student_chapter_active
ON preview_guide (
  (student_id),
  (IF(guide_type = 'REVIEW', CONCAT('R:', chapter_id), chapter_id)),
  (IF(status IN ('GENERATING','READY','IN_PROGRESS'), 'A', NULL))
);
```

> 与《管理后台-教师与班级数据管理工作台》§5.6 的函数唯一索引方案同源：状态列直接参与唯一键会导致「过期后重生成」撞键，函数索引仅对活跃行生效。

## 11. 容量估算（DAU 50 万基准）

- 预习渗透率假设 25% → 日均 12.5 万份导学案请求；
- 缓存复用率 60%（L2 + preview_guide_cache）→ AI 实际生成约 5 万次/日；单次约 2k token、按 ¥0.02/次估算 → 预习域 AI 成本约 ¥1,000/日；
- 写入：preview_guide 峰值 12.5 万行/日，月分区，在线保留 180 天后转归档（对齐存储清理引擎）；
- 读取：晚高峰 19:00-21:00 承载 35% 日请求 → 峰值生成约 12 QPS、详情读约 120 QPS（读多写少，Redis L1/L2 扛读）；
- preview_result 与 guide 近似 1:1，行均 JSON 约 8KB → 月增量约 30GB（含索引）。

## 12. 合规红线

| # | 红线 |
| --- | --- |
| C1 | 自测题 answer/explanation 在提交判题前永不下发客户端（守卫 G5，防止预习环节变成抄答案通道） |
| C2 | AI 生成内容携带 AIGC 标识：metadata.generatedBy 透出客户端，展示「AI 生成」角标 |
| C3 | 模板降级导学案必须显示「基础版」角标，不得冒充 AI 个性化内容 |
| C4 | 导学案内容与掌握度快照不含任何 PII；预习行为数据仅按知识点/模块粒度存储 |
| C5 | 家长端仅展示预习聚合信息（完成率/用时/薄弱知识点名称），不展示自测原始答案与错题明细 |
| C6 | AI 生成输出接入内容安全引擎（scene=PREVIEW_EDU）过滤后方可落库；被拦截内容不留存原文 |
| C7 | 预习自测结果不计入任何成绩、排名或班级对比（防焦虑红线），仅用于个性化学习编排 |
| C8 | 过期数据 180 天后转冷存、按存储清理引擎统一删除；删除操作保留审计记录 |

| 7 | 消息与推送服务 + 统一延迟任务调度引擎 | 预习提醒：进入新章节次日 19:00 提醒一次，频控对齐通知疲劳度管控引擎，不重复打扰 |
| 8 | 数据埋点与关键指标系统 | 客户端埋点 sync_class_preview_started/completed 与服务端 preview.domain.events 双轨并存，指标口径以埋点规范文档为准 |

| 11 | 服务端-存储资源统一生命周期管理与过期数据自动清理引擎 | 归档与删除以该引擎为权威，本引擎仅维护 expired_at 与状态标记 |
| 12 | 服务端-每日任务智能生成与学习计划执行追踪服务 | preview.completed 可作为「预习任务」完成信号（task.completed 由任务调度引擎归因，防时长双计） |

## 14. 验收场景

| # | 场景 | 预期结果 |
| --- | --- | --- |
| 1 | 新学生首次生成 | 202 → 轮询 ≤3 次内 READY；详情含 6 类模块 + quiz；响应无 answer 字段 |

| 5 | 并发生成（G2） | 双端并发双击生成：仅一份成功，另一请求 40901；DB 活跃行唯一 |
| 6 | 掌握度计算 | 构造 quiz 4/5 对、模块全 STUDIED、用时 14/15 分钟：masterySnapshot 数值与 60/25/15 权重公式一致（单测断言） |

| 8 | 答案保密（G5/C1） | READY/IN_PROGRESS 状态下遍历全部接口抓包：响应体无 answer/explanation 键（契约测试） |
| 9 | 完成幂等（G6） | complete 双击：两次返回同 resultId；preview.completed 事件恰好 1 条 |
| 10 | 类型自动分型 | 前置掌握度 0.35 + 章节难度 4 → determineGuideType 返回 REINFORCED |
| 11 | 布鲁姆判定 | REMEMBER 全对 + APPLY 3 题对 2（66%）→ achievedBloomLevel=APPLY |
| 12 | TTL 过期 | 手工回拨 expired_at → 1h 内扫描任务流转 EXPIRED + preview.expired(TTL) 事件 |
