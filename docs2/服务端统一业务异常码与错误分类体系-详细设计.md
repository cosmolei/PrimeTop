# 服务端统一业务异常码与错误分类体系 - 详细设计

## 1. 概述

### 1.1 设计目的

为 PrimeTop 所有后端服务提供统一的异常码定义、错误分类、错误响应格式和处理规范。本体系的目标：

1. **前端可精确处理**：客户端根据异常码执行差异化 UI 逻辑（重试、跳转登录、降级提示等）。
2. **服务间可传递**：微服务间调用异常能透传原始错误码，不丢失上下文。
3. **可监控可告警**：日志与监控系统按异常码聚合统计，精准定位问题。
4. **开发可扩展**：新增业务模块可按规范自行扩展异常码，无需全局协调。

### 1.2 适用范围

- 所有 RESTful API 响应
- gRPC / 消息队列服务间调用的错误传递
- 客户端 SDK 解析的错误响应
- 管理后台接口响应

### 1.3 与其他文档的关系

| 关联文档 | 关系 |
| --- | --- |
| 错误处理与服务降级策略 | 本文档是其中"异常码定义"部分的细化实现 |
| API网关与通用接口规范 | 本文档定义的响应格式需嵌入通用 API 响应结构 |
| 客户端全局异常处理与安全恢复机制 | 客户端根据本文档的异常码做对应处理 |
| 日志与监控告警体系 | 异常码作为日志字段和告警维度 |

## 2. 异常码设计规范

### 2.1 异常码结构

采用 **6 位数字编码**，结构为 `XXYYZZ`：

```
  XX    YY    ZZ
  │     │     └── 具体错误序号 (01-99)
  │     └──────── 子模块/场景 (01-99)
  └────────────── 服务/模块 (01-99)
```

| 层级 | 范围 | 说明 |
| --- | --- | --- |
| 服务码 (XX) | 01-99 | 标识产生异常的服务/模块 |
| 场景码 (YY) | 01-99 | 标识服务内的业务场景 |
| 错误序号 (ZZ) | 01-99 | 具体错误在场景内的序号 |

**特殊约定**：
- `XX = 00`：通用/网关层错误（不归属于特定服务）
- `YY = 00`：服务级通用错误（不归属于特定场景）
- `ZZ = 00`：保留，不使用

### 2.2 HTTP 状态码映射规则

异常码不替代 HTTP 状态码，两者配合使用：

| HTTP Status | 使用场景 |
| --- | --- |
| 200 | 请求成功（业务正常） |
| 400 | 请求参数校验失败、格式错误 |
| 401 | 未认证（Token 缺失/过期） |
| 403 | 无权限（角色不足、资源受限） |
| 404 | 资源不存在 |
| 409 | 业务冲突（重复操作、状态冲突） |
| 429 | 限流/频率超限 |
| 500 | 服务内部异常（未知错误） |
| 502 | 上游服务不可用 |
| 503 | 服务降级/维护中 |

**原则**：HTTP 状态码表达"传输层语义"，异常码表达"业务层语义"。一个 HTTP 400 可以包含不同的业务异常码（参数格式错误、参数范围越界等）。

### 2.3 错误严重度分级

| 级别 | 标识 | 含义 | 告警要求 |
| --- | --- | --- | --- |
| LOW | 1 | 预期内的业务拒绝（如余额不足） | 不告警，记录日志 |
| MEDIUM | 2 | 业务流程受阻但可恢复（如并发冲突） | 监控面板展示 |
| HIGH | 3 | 数据一致性风险（如扣费后调用失败） | 准实时告警 |
| CRITICAL | 4 | 服务不可用或数据损坏 | 立即告警 + 通知值班 |

## 3. 统一错误响应格式

### 3.1 标准响应结构

所有 API 错误响应必须使用以下 JSON 结构：

```json
{
  "code": 400102,
  "message": "手机号格式不正确",
  "detail": "手机号必须为11位数字，以1开头",
  "traceId": "a1b2c3d4e5f6-1234567890",
  "timestamp": 1748102400000,
  "path": "/api/v1/auth/register",
  "suggestions": [
    {
      "action": "RETRY_WITH_FIX",
      "field": "phone",
      "description": "请输入正确的手机号"
    }
  ]
}
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| code | integer | ✅ | 6位业务异常码 |
| message | string | ✅ | 面向用户的简短错误描述（可直接展示） |
| detail | string | ❌ | 面向开发者的详细说明（Debug 用途） |
| traceId | string | ✅ | 全链路追踪 ID（关联日志系统） |
| timestamp | long | ✅ | 服务端时间戳（毫秒） |
| path | string | ✅ | 请求路径 |
| suggestions | array | ❌ | 客户端可执行的修复建议列表 |
| suggestions[].action | string | ❌ | 建议动作枚举 |
| suggestions[].field | string | ❌ | 关联字段名（表单场景） |
| suggestions[].description | string | ❌ | 建议描述文本 |

### 3.3 建议 Action 枚举

```typescript
enum ErrorSuggestionAction {
  RETRY_WITH_FIX   = "RETRY_WITH_FIX",    // 修正参数后重试
  RETRY_LATER      = "RETRY_LATER",       // 稍后重试（服务暂时不可用）
  LOGIN_AGAIN      = "LOGIN_AGAIN",       // 重新登录
  UPGRADE_APP      = "UPGRADE_APP",       // 升级应用版本
  CONTACT_SUPPORT  = "CONTACT_SUPPORT",   // 联系客服
  REDIRECT         = "REDIRECT",          // 跳转指定页面
  SWITCH_NETWORK   = "SWITCH_NETWORK",    // 切换网络
  ENABLE_PERMISSION = "ENABLE_PERMISSION", // 开启权限
}
```

### 3.4 批量操作错误格式

批量接口（如批量加入错题本）采用部分成功模式：

```json
{
  "code": 0,
  "message": "部分操作成功",
  "data": {
    "successCount": 3,
    "failCount": 2,
    "failures": [
      {
        "index": 1,
        "code": 050301,
        "message": "题目不存在",
        "input": { "questionId": "q_abc123" }
      },
      {
        "index": 3,
        "code": 050305,
        "message": "已在错题本中",
        "input": { "questionId": "q_def456" }
      }
    ]
  }
}
```

## 5. 技术实现

### 5.1 后端异常码注册中心

所有异常码集中注册，编译期校验唯一性。

```java
/**
 * 异常码注册表
 * 使用静态初始化块确保编译期唯一性校验
 */
public final class ErrorCodeRegistry {

    private static final Map<Integer, ErrorCode> CODE_MAP = new HashMap<>();
    private static final Map<String, Set<Integer>> SERVICE_CODE_MAP = new HashMap<>();

    static {
        // 通用/网关层
        register("SYSTEM", 0, "系统内部未知错误", Severity.HIGH, 500);
        register("SYSTEM", 2, "请求参数格式错误", Severity.LOW, 400);
        register("SYSTEM", 3, "请求体过大", Severity.LOW, 413);
        register("SYSTEM", 4, "请求频率超限", Severity.LOW, 429);
        register("SYSTEM", 5, "服务维护中", Severity.HIGH, 503);
        // ... 省略其他注册
    }

    private static void register(String service, int seq,
                                  String message, Severity severity,
                                  int httpStatus) {
        // 根据注册顺序自动计算异常码
        // 或者显式传入完整6位码
        int code = buildCode(service, seq);
        if (CODE_MAP.containsKey(code)) {
            throw new IllegalStateException(
                "Duplicate error code: " + code +
                " already registered as: " + CODE_MAP.get(code).getMessage());
        }
        CODE_MAP.put(code, new ErrorCode(code, message, severity, httpStatus));
        SERVICE_CODE_MAP.computeIfAbsent(service, k -> new HashSet<>()).add(code);
    }

    public static ErrorCode get(int code) {
        ErrorCode ec = CODE_MAP.get(code);
        if (ec == null) {
            return CODE_MAP.get(0); // fallback to SYSTEM_UNKNOWN
        }
        return ec;
    }

    /**
     * 获取某个服务下的所有异常码（用于文档生成）
     */
    public static Set<ErrorCode> getByService(String service) {
        return SERVICE_CODE_MAP.getOrDefault(service, Set.of())
            .stream()
            .map(CODE_MAP::get)
            .collect(Collectors.toSet());
    }
}
```

### 5.3 BusinessException 统一异常基类

```java
/**
 * 业务异常基类
 * 所有业务层抛出的异常都应使用此类或其子类
 */
public class BusinessException extends RuntimeException {

    private final int code;
    private final String userMessage;
    private final String detail;
    private final List<ErrorSuggestion> suggestions;

    public BusinessException(int code) {
        this(code, null, null, null);
    }

    public BusinessException(int code, String detail) {
        this(code, detail, null, null);
    }

    public BusinessException(int code, String detail,
                             String userMessage,
                             List<ErrorSuggestion> suggestions) {
        super(formatMessage(code, detail));
        this.code = code;
        this.userMessage = userMessage;
        this.detail = detail;
        this.suggestions = suggestions;
    }

    /**
     * 快捷构造：从注册表获取默认信息
     */
    public static BusinessException of(int code, Object... args) {
        ErrorCode ec = ErrorCodeRegistry.get(code);
        String msg = args.length > 0
            ? String.format(ec.getMessage(), args)
            : ec.getMessage();
        return new BusinessException(code, null, msg, null);
    }

    /**
     * 带修复建议
     */
    public static BusinessException withSuggestion(int code,
                                                    ErrorSuggestion suggestion) {
        ErrorCode ec = ErrorCodeRegistry.get(code);
        return new BusinessException(code, null, ec.getMessage(),
            List.of(suggestion));
    }

    // Getters
    public int getCode() { return code; }
    public String getUserMessage() { return userMessage; }
    public String getDetail() { return detail; }
    public List<ErrorSuggestion> getSuggestions() {
        return suggestions != null ? suggestions : List.of();
    }
}
```

### 5.4 全局异常处理器（Spring Boot）

```java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ErrorResponse> handleBusinessException(
            BusinessException ex, HttpServletRequest request) {

        ErrorCode ec = ErrorCodeRegistry.get(ex.getCode());

        // 记录日志（根据严重度决定级别）
        logError(ex, ec);

        ErrorResponse response = ErrorResponse.builder()
            .code(ex.getCode())
            .message(ex.getUserMessage() != null
                ? ex.getUserMessage() : ec.getMessage())
            .detail(ex.getDetail())
            .traceId(TraceContext.getTraceId())
            .timestamp(System.currentTimeMillis())
            .path(request.getRequestURI())
            .suggestions(ex.getSuggestions())
            .build();

        return ResponseEntity
            .status(ec.getHttpStatus())
            .body(response);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(
            MethodArgumentNotValidException ex,
            HttpServletRequest request) {

        String firstError = ex.getBindingResult()
            .getFieldErrors().stream()
            .map(fe -> fe.getField() + ": " + fe.getDefaultMessage())
            .findFirst()
            .orElse("参数校验失败");

        ErrorResponse response = ErrorResponse.builder()
            .code(2) // PARAM_FORMAT_ERROR
            .message("请求参数有误")
            .detail(firstError)
            .traceId(TraceContext.getTraceId())
            .timestamp(System.currentTimeMillis())
            .path(request.getRequestURI())
            .build();

        return ResponseEntity.badRequest().body(response);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleUnknown(
            Exception ex, HttpServletRequest request) {

        log.error("Unhandled exception on {}", request.getRequestURI(), ex);

        // 触发告警
        AlertService.alert(Severity.HIGH,
            "Unhandled exception: " + ex.getClass().getSimpleName());

        ErrorResponse response = ErrorResponse.builder()
            .code(1) // SYSTEM_UNKNOWN
            .message("系统繁忙，请稍后重试")
            .traceId(TraceContext.getTraceId())
            .timestamp(System.currentTimeMillis())
            .path(request.getRequestURI())
            .build();

        return ResponseEntity.status(500).body(response);
    }

    private void logError(BusinessException ex, ErrorCode ec) {
        switch (ec.getSeverity()) {
            case CRITICAL -> log.error("[CRITICAL] code={}, msg={}, detail={}",
                ex.getCode(), ex.getUserMessage(), ex.getDetail(), ex);
            case HIGH -> log.error("[HIGH] code={}, msg={}, detail={}",
                ex.getCode(), ex.getUserMessage(), ex.getDetail());
            case MEDIUM -> log.warn("[MEDIUM] code={}, msg={}, detail={}",
                ex.getCode(), ex.getUserMessage(), ex.getDetail());
            case LOW -> log.info("[LOW] code={}, msg={}, detail={}",
                ex.getCode(), ex.getUserMessage(), ex.getDetail());
        }
    }
}
```

### 5.5 服务间调用错误透传

当服务 A 调用服务 B 失败时，B 的异常码需要透传给 A，再透传给客户端。

```java
/**
 * Feign 异常解码器：将上游服务异常码透传
 */
public class FeignErrorDecoder implements ErrorDecoder {

    @Override
    public Exception decode(String methodKey, Response response) {
        try {
            String body = Util.toString(response.body().asReader(UTF_8));
            ErrorResponse error = JsonUtils.fromJson(body, ErrorResponse.class);

            // 包装为 RemoteServiceException 保留原始异常码
            return new RemoteServiceException(
                error.getCode(),
                error.getMessage(),
                response.status(),
                error.getTraceId()
            );
        } catch (IOException e) {
            return new RemoteServiceException(
                1, "上游服务响应解析失败",
                response.status(), null
            );
        }
    }
}

/**
 * 远程服务调用异常
 */
public class RemoteServiceException extends RuntimeException {
    private final int remoteCode;
    private final String remoteMessage;
    private final int remoteHttpStatus;
    private final String remoteTraceId;

    // 构造器 + getters
}

/**
 * 全局处理器中对 RemoteServiceException 的处理
 */
@ExceptionHandler(RemoteServiceException.class)
public ResponseEntity<ErrorResponse> handleRemote(
        RemoteServiceException ex, HttpServletRequest request) {

    // 映射上游 HTTP 状态码
    int httpStatus = ex.getRemoteHttpStatus();
    if (httpStatus >= 500) {
        // 上游 5xx → 对调用方也是 5xx，但用原始异常码
        httpStatus = 502; // Bad Gateway
    }

    ErrorResponse response = ErrorResponse.builder()
        .code(ex.getRemoteCode())
        .message(ex.getRemoteMessage())
        .traceId(TraceContext.getTraceId())
        .timestamp(System.currentTimeMillis())
        .path(request.getRequestURI())
        .build();

    return ResponseEntity.status(httpStatus).body(response);
}
```

## 6. 异常码扩展流程

### 6.1 新增异常码步骤

```
1. 确认服务码（XX）和场景码（YY）
   ↓
2. 分配错误序号（ZZ），确保不与已有冲突
   ↓
3. 在 ErrorCodeRegistry 中注册
   ↓
4. 在本文档中记录（保持文档与代码同步）
   ↓
5. 编写单元测试验证
   ↓
6. 提交 MR，由 Tech Lead 审核异常码合理性
```

### 6.2 异常码命名规范

代码中应使用常量引用异常码，禁止硬编码数字：

```java

    int ACCOUNT_LOCKED = 10203;     // 010203
}

throw BusinessException.of(UserErrorCodes.ACCOUNT_NOT_FOUND);
```

## 8. 监控与告警集成

### 8.1 日志格式

```
2026-05-25T03:30:00.000+08:00 ERROR [traceId=a1b2c3d4] [code=020101] [severity=HIGH] [service=ai-service] AI model unavailable: upstream timeout after 30s
```

**必须包含的字段**：
- `traceId`：全链路追踪 ID
- `code`：6位异常码
- `severity`：严重度级别
- `service`：产生异常的服务名

### 8.2 告警规则

| 规则 | 条件 | 通知方式 |
| --- | --- | --- |
| CRITICAL 立即告警 | severity=CRITICAL，任何异常码 | 电话 + 短信 + IM |
| HIGH 5分钟聚集 | 同一异常码 5分钟内 > 10次 | 短信 + IM |
| 支付异常告警 | code 在 080000-089999 且 severity>=HIGH | 电话 + 短信 |
| AI 服务降级 | code=020105 且 比例>30%（5分钟） | IM 通知 |
| 限流激增 | code=000004 且 5分钟内增速>200% | IM 通知 |

### 8.3 错误看板维度

- 按**服务码**聚合：各服务错误量排行
- 按**场景码**聚合：高频错误场景 TOP 20
- 按**严重度**聚合：CRITICAL/HIGH 趋势
- 按**用户学段**聚合：不同学段用户遇到的错误分布
- 按**客户端版本**聚合：新版本是否引入新错误

## 9. 异常码文档自动生成

通过注解 + 编译插件自动生成异常码文档，确保代码与文档始终同步：

```java
/**
 * 注解标记异常码定义
 */
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface ErrorCodeDef {
    String message();
    int httpStatus();
    Severity severity();
    String detail() default "";
}

// 使用方式
public interface UserErrorCodes {
    @ErrorCodeDef(
        message = "手机号格式不正确",
        httpStatus = 400,
        severity = Severity.LOW,
        detail = "手机号必须为11位数字，以1开头"
    )
    int PHONE_FORMAT_INVALID = 10101;
}
```

```gradle
// build.gradle — 文档生成插件
task generateErrorCodeDoc(type: JavaExec) {
    mainClass = 'com.primetop.tools.ErrorCodeDocGenerator'
    classpath = sourceSets.main.runtimeClasspath
    args = ['docs2/服务端统一业务异常码与错误分类体系-详细设计.md']
}

// CI 中执行
// ./gradlew generateErrorCodeDoc
```

## 10. 设计决策记录

| 决策 | 选项 | 结论 | 原因 |
| --- | --- | --- | --- |
| 编码长度 | 4位 / 6位 / 8位 | 6位数字 | 足够表达层级，易读易记，不会过长 |
| 字母vs数字 | 纯数字 / 字母数字混合 | 纯数字 | 客户端解析简单，日志检索方便 |
| HTTP映射 | 一对一 / 一对多 | 一对多 | 同一 HTTP 状态码下可表达多种业务语义 |
| 是否内嵌HTTP码 | 是 / 否 | 否 | 异常码独立于传输层，支持非 HTTP 协议复用 |
| 注册方式 | 文件配置 / 代码注册 | 代码注册 + 注解 | 编译期校验，IDE 友好，可自动文档化 |
