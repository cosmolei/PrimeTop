# 家长端使用管控与权限配置服务 详细设计

## 1. 概述

### 1.1 模块定位

家长端使用管控与权限配置服务（Parental Control Service）是 PrimeTop 家长中心的核心能力之一，负责为家长提供对孩子账号的全方位使用管控能力。服务覆盖**使用时长限制、可用时段控制、内容范围限制、功能权限开关、强制休息与锁屏、实时使用状态同步**六大能力，确保未成年人在安全、可控、健康的范围内使用学习产品。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 管控规则配置 | 家长可设置每日/单次使用时长、可用时间段、禁用功能、学科内容范围等 |
| 规则实时生效 | 配置变更后通过配置推送通道实时同步到孩子端设备 |
| 使用时长统计 | 聚合多设备学习时长，按自然日/周/月进行统计和有效性判定 |
| 限制触发执行 | 当达到时长上限、进入禁用时段或触发强制休息时，客户端执行限制 |
| 使用状态同步 | 向家长端实时或准实时上报孩子当前学习状态、剩余可用时长、在线设备 |
| 管控审计日志 | 记录所有配置变更、限制触发、家长解锁等操作，支持合规审计 |

### 1.3 依赖关系

```text
家长端使用管控与权限配置服务
├── 依赖：用户服务（User Service）          — 家长/学生账号、绑定关系、家庭关系
├── 依赖：学习时长统计服务（Learning Time Service）— 多设备学习时长聚合
├── 依赖：消息推送服务（Push Service）      — 规则变更推送、限制触发提醒
├── 依赖：设备服务（Device Service）        — 设备在线状态、设备标识
├── 依赖：实时通信服务（WebSocket/SSE）     — 家长端实时状态同步
└── 被依赖：家长中心 App / 学生端 App / 管理后台
```

## 4. 业务逻辑

### 4.1 核心流程

#### 4.1.1 规则创建/更新流程

```text
家长端提交规则
    │
    ▼
校验家长对孩子是否有管控权限
    │
    ▼
校验参数合法性（时段不重叠、时长合法、scopeCode 在白名单）
    │
    ▼
开启数据库事务
    │
    ├── 更新/插入 parental_control_rule（version + 1）
    ├── 替换 time_limit_config
    ├── 替换 available_period_config
    ├── 替换 content_scope_config
    └── 提交事务
    │
    ▼
写入管控事件日志 RULE_UPDATE
    │
    ▼
刷新缓存 ctrl:rule:{childUserId}
    │
    ▼
通过 Push / WebSocket 向孩子端推送规则变更事件
    │
    ▼
返回更新后的规则版本号
```

#### 4.1.2 功能可用性校验流程

```text
学生端发起功能调用前
    │
    ▼
从缓存获取 ctrl:rule:{childUserId}
    │
    ▼
按优先级依次检查：
    1. 内容范围（FUNCTION / FEATURE / SUBJECT）是否被禁用
    2. 当前时间是否在可用时段内
    3. 当日累计使用时长是否已达上限
    4. 单次连续使用时长是否达到上限（需要休息）
    5. 是否处于家长临时解锁有效期内
    │
    ▼
返回 allow / reason / 剩余时长
```

#### 4.2.2 限制触发规则

| 触发条件 | 状态 | 客户端行为 | 家长端通知 |
|----------|------|------------|------------|
| 当日累计时长 >= 每日上限 | TIME_LIMIT_HIT | 弹出锁屏提示，无法继续使用 | 推送“孩子今日使用时长已达上限” |
| 当前时间不在可用时段 | PERIOD_BLOCKED | 进入锁屏，显示可用时段 | 推送“孩子尝试在非可用时段使用” |
| 单次连续时长 >= 上限 | REST_FORCE | 弹出强制休息倒计时 | 可选推送“孩子已连续使用 X 分钟，已休息” |
| 家长手动解锁 | UNLOCKED | 临时恢复使用指定时长 | 记录审计日志 |

### 4.3 关键算法

#### 4.3.1 可用时段判定算法

```python
def is_in_available_period(now: datetime, periods: list) -> bool:
    """
    支持跨日时段（如 22:00-次日 07:00）。
    当 end_time < start_time 时，认为时段跨天。
    """
    weekday = now.weekday() + 1  # 周一=1
    time = now.time()

    for p in periods:
        if not p.enabled:
            continue
        if p.day_of_week != 0 and p.day_of_week != weekday:
            continue

        s = p.start_time
        e = p.end_time

        if e < s:
            # 跨日：当前时间 >= start 或 当前时间 <= end
            if time >= s or time <= e:
                return True
        else:
            if s <= time <= e:
                return True
    return False
```

#### 4.3.2 当日剩余时长计算

```python
def calc_remaining_daily_seconds(
    daily_limit_minutes: int,
    used_seconds_today: int,
    unlock_extra_seconds: int
) -> int:
    if daily_limit_minutes <= 0:
        return -1  # 无限制
    limit_seconds = daily_limit_minutes * 60
    return max(0, limit_seconds - used_seconds_today + unlock_extra_seconds)
```

#### 4.3.3 强制休息判定

```python
def should_force_rest(session_seconds: int, single_session_limit: int, rest_seconds: int) -> tuple:
    if single_session_limit <= 0:
        return False, 0
    if session_seconds >= single_session_limit * 60:
        return True, rest_seconds * 60
    remaining = single_session_limit * 60 - session_seconds
    return False, remaining
```

### 5.2 服务层核心实现

```java
@Service
public class ParentalControlService {

    @Autowired
    private ControlRuleRepository ruleRepository;
    @Autowired
    private TimeLimitRepository timeLimitRepository;
    @Autowired
    private AvailablePeriodRepository periodRepository;
    @Autowired
    private ContentScopeRepository scopeRepository;
    @Autowired
    private ControlEventLogRepository eventLogRepository;
    @Autowired
    private StringRedisTemplate redisTemplate;
    @Autowired
    private FamilyServiceClient familyServiceClient;
    @Autowired
    private LearningTimeClient learningTimeClient;
    @Autowired
    private PushService pushService;

    private static final String RULE_KEY = "ctrl:rule:%d";
    private static final String USAGE_KEY = "ctrl:usage:%d:%s";
    private static final String SESSION_KEY = "ctrl:session:%d:%s";
    private static final String LOCK_KEY = "ctrl:lock:%d";

    /**
     * 获取孩子的管控规则，优先读缓存，未命中读数据库。
     */
    public ControlRuleDTO getRule(Long childUserId, Long parentUserId) {
        validateParentAccess(parentUserId, childUserId);
        String cacheKey = String.format(RULE_KEY, childUserId);
        String cached = redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return JSON.parseObject(cached, ControlRuleDTO.class);
        }
        ControlRuleDTO rule = loadRuleFromDb(childUserId);
        if (rule != null) {
            redisTemplate.opsForValue().set(cacheKey, JSON.toJSONString(rule), 7, TimeUnit.DAYS);
        }
        return rule;
    }

    /**
     * 更新管控规则。
     */
    @Transactional
    public ControlRuleDTO updateRule(Long childUserId, Long parentUserId, ControlRuleUpdateRequest request) {
        validateParentAccess(parentUserId, childUserId);
        validateRule(request);

        ControlRule rule = ruleRepository.findByChildUserIdAndStatus(childUserId, 1)
            .orElse(new ControlRule());

        rule.setChildUserId(childUserId);
        rule.setParentUserId(parentUserId);
        rule.setStatus(1);
        rule.setVersion(rule.getVersion() == null ? 1 : rule.getVersion() + 1);
        rule.setRuleId("ctrl_" + childUserId);
        rule.setEffectiveFrom(LocalDateTime.now());
        ruleRepository.save(rule);

        // 替换子配置
        timeLimitRepository.deleteByRuleId(rule.getRuleId());
        availablePeriodRepository.deleteByRuleId(rule.getRuleId());
        contentScopeRepository.deleteByRuleId(rule.getRuleId());

        timeLimitRepository.save(mapTimeLimit(rule.getRuleId(), request.getTimeLimit()));
        periodRepository.saveAll(mapPeriods(rule.getRuleId(), request.getAvailablePeriods()));
        scopeRepository.saveAll(mapScopes(rule.getRuleId(), request.getContentScopes()));

        // 刷新缓存并推送
        ControlRuleDTO dto = loadRuleFromDb(childUserId);
        redisTemplate.opsForValue().set(
            String.format(RULE_KEY, childUserId),
            JSON.toJSONString(dto),
            7, TimeUnit.DAYS
        );

        logEvent(childUserId, parentUserId, "RULE_UPDATE", Map.of("version", dto.getVersion()));
        pushService.pushToStudentDevices(childUserId, "CONTROL_RULE_CHANGED", Map.of("version", dto.getVersion()));

        return dto;
    }

    /**
     * 校验功能是否可用。
     */
    public FeatureCheckResult checkFeatureAvailability(
        Long childUserId,
        String deviceId,
        String featureCode,
        LocalDateTime now
    ) {
        ControlRuleDTO rule = getRule(childUserId, null);
        if (rule == null) {
            return FeatureCheckResult.allow(); // 无规则默认允许
        }

        // 1. 内容范围检查
        ContentScopeDTO scope = findContentScope(rule, featureCode);
        if (scope != null && scope.getPermission() == 0) {
            return FeatureCheckResult.deny("FUNCTION_DISABLED");
        }

        // 2. 可用时段检查
        if (!isInAvailablePeriod(now, rule.getAvailablePeriods())) {
            return FeatureCheckResult.deny("PERIOD_BLOCKED");
        }

        // 3. 时长限制检查
        long usedSeconds = getTodayUsedSeconds(childUserId, deviceId, rule);
        long dailyRemaining = calcRemainingDailySeconds(rule, usedSeconds);
        if (dailyRemaining == 0) {
            return FeatureCheckResult.deny("TIME_LIMIT")
                .setNextForbiddenTime(getNextResetTime(rule));
        }

        // 4. 单次连续时长检查
        long sessionSeconds = getSessionSeconds(childUserId, deviceId);
        RestCheckResult rest = checkRest(rule, sessionSeconds);
        if (rest.isNeedRest()) {
            return FeatureCheckResult.deny("REST_FORCE")
                .setNeedRest(true);
        }

        return FeatureCheckResult.allow()
            .setRemainingDailySeconds(dailyRemaining)
            .setRemainingSessionSeconds(rest.getRemainingSeconds())
            .setRuleVersion(rule.getVersion());
    }

    /**
     * 上报使用心跳，更新缓存中的使用时长和会话状态。
     */
    public HeartbeatResult heartbeat(HeartbeatRequest request) {
        Long childUserId = request.getChildUserId();
        String deviceId = request.getDeviceId();
        ControlRuleDTO rule = getRule(childUserId, null);

        String sessionKey = String.format(SESSION_KEY, childUserId, deviceId);
        String sessionJson = redisTemplate.opsForValue().get(sessionKey);
        SessionState session = sessionJson == null ? new SessionState() : JSON.parseObject(sessionJson, SessionState.class);

        if (request.getIsLearningActivity()) {
            session.accum(request.getActiveSeconds());
            String usageKey = String.format(USAGE_KEY, childUserId, LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE));
            redisTemplate.opsForValue().increment(usageKey, request.getActiveSeconds());
            redisTemplate.expire(usageKey, 2, TimeUnit.DAYS);
        } else {
            // 非学习活动可视为会话中断
            session.reset();
        }

        redisTemplate.opsForValue().set(sessionKey, JSON.toJSONString(session), 1, TimeUnit.DAYS);

        FeatureCheckResult check = checkFeatureAvailability(childUserId, deviceId, request.getCurrentFeature(),
            LocalDateTime.ofInstant(Instant.ofEpochSecond(request.getTimestamp()), ZoneId.of(rule.getTimeLimit().getTimezone())));

        return new HeartbeatResult()
            .setDailyUsedSeconds(getTodayUsedSeconds(childUserId, deviceId, rule))
            .setDailyRemainingSeconds(check.getRemainingDailySeconds())
            .setSessionUsedSeconds(session.getAccumSeconds())
            .setSessionRemainingSeconds(check.getRemainingSessionSeconds())
            .setLocked(!check.isAllow())
            .setNextAction(check.isAllow() ? "CONTINUE" : "LOCK")
            .setRuleVersion(rule.getVersion());
    }

    // -------------- 私有辅助方法 --------------

    private void validateParentAccess(Long parentUserId, Long childUserId) {
        if (!familyServiceClient.isParentOfChild(parentUserId, childUserId)) {
            throw new BizException(400104, "无权限操作该孩子的管控规则");
        }
    }

    private void validateRule(ControlRuleUpdateRequest request) {
        TimeLimitDTO tl = request.getTimeLimit();
        if (tl != null) {
            if (tl.getDailyLimitMinutes() > 0 && tl.getSingleSessionMinutes() > tl.getDailyLimitMinutes()) {
                throw new BizException(400103, "单次连续时长不能大于每日总时长");
            }
            if (tl.getRestMinutes() < 0) {
                throw new BizException(400103, "休息时长不能为负数");
            }
        }
        // 校验时段不重叠
        validatePeriods(request.getAvailablePeriods());
    }

    private void logEvent(Long childUserId, Long parentUserId, String eventType, Map<String, Object> payload) {
        ControlEventLog log = new ControlEventLog();
        log.setChildUserId(childUserId);
        log.setParentUserId(parentUserId);
        log.setEventType(eventType);
        log.setEventPayload(JSON.toJSONString(payload));
        log.setEventTime(LocalDateTime.now());
        eventLogRepository.save(log);
    }
}
```

## 6. 错误处理

### 6.1 异常类型

```java
public class BizException extends RuntimeException {
    private int code;
    public BizException(int code, String message) { super(message); this.code = code; }
}

public class RuleNotFoundException extends BizException {
    public RuleNotFoundException() { super(400105, "管控规则不存在"); }
}

public class RuleVersionConflictException extends BizException {
    public RuleVersionConflictException() { super(400110, "规则版本冲突，请刷新后重试"); }
}
```

### 6.2 重试策略

| 场景 | 策略 | 说明 |
|------|------|------|
| 更新规则并发冲突 | 乐观锁重试 3 次 | 基于 version 字段，CAS 更新失败则重试 |
| 缓存刷新失败 | 记录失败日志，后台定时修复 | 缓存失效后自动回源数据库，不影响主链路 |
| 推送失败 | 退化为静默推送 + 客户端轮询 | 学生端心跳会再次拉取最新规则 |
| 使用时长统计丢失 | 心跳补偿 | 客户端本地缓存时长，断网恢复后补报 |

### 6.3 降级方案

1. **缓存不可用**：直接读取数据库，写入失败不阻塞主流程，但告警。
2. **数据库不可用**：返回默认规则（允许使用），并记录日志，避免学生端完全无法学习。
3. **学习时长服务不可用**：使用本地缓存的 usage 值，允许继续累计，待恢复后补偿。
4. **推送服务不可用**：学生端心跳周期（建议 30 秒）会自动拉取最新规则，实现准实时同步。

## 7. 性能优化

### 7.1 缓存策略

- 规则全量缓存：每个孩子的规则 JSON 缓存 7 天，更新时主动失效。
- 使用时长计数器：Redis 原子递增，避免数据库高频写入。
- 会话状态缓存：按设备缓存，支持多设备独立累计时长。
- 批量预加载：家长端有多个孩子时，批量查询并缓存所有孩子的规则。

### 7.2 并发控制

- 更新规则使用数据库 version 字段乐观锁，防止并发更新导致规则覆盖。
- 使用时长递增使用 Redis `INCR`，保证原子性。
- 对同一孩子同一设备的会话状态更新，使用 Redis 单 key 串行化。

### 7.3 资源限制

- 每个孩子的规则 JSON 控制在 32KB 以内，避免缓存大 value。
- 使用时长心跳最小粒度 30 秒，减少请求量。
- 管控事件日志异步写入（通过 MQ 削峰），避免影响主链路响应。

## 8. 安全考虑

### 8.1 权限控制

- 所有家长端接口必须校验 `Authorization` 中的家长 token，并确认家长与孩子存在绑定关系。
- 学生端接口只能查询和操作自己的使用状态，不能修改规则。
- 管理后台可查看但不可修改单个家庭的管控规则，仅用于客服支持和审计。

### 8.2 数据验证

- 规则更新时校验 scope_code 必须在配置白名单内，防止非法功能代码。
- 时段校验不允许跨日重叠（如 22:00-24:00 与 00:00-02:00 视为不重叠）。
- 对 `dailyLimitMinutes` 设置上限（如 1440 分钟），防止异常大值。

### 8.3 审计日志

- 记录所有规则变更、临时解锁、限制触发事件，保留 180 天。
- 日志包含操作人、设备 ID、IP、时间戳和变更前后快照。
- 审计日志不可修改，独立表存储，仅允许管理员查询。

### 8.4 隐私保护

- 孩子端使用时长、在线状态等数据仅对绑定家长可见。
- 不记录孩子具体学习内容明细，仅记录功能类型和学科类型。
- 管控规则数据加密存储敏感字段（如解锁原因中的自定义文本）。
