# 知识点图数据库建模与图查询服务 - 详细设计

> 版本: 1.0 | 创建: 2026-05-30 | 模块: 知识体系 / 数据层

## 1. 概述

### 1.1 背景

PrimeTop 知识体系的核心是知识点之间的**网状关系**：前置依赖、层级包含、学科关联、考点映射等。传统关系数据库难以高效表达多层级、多类型的图结构关系（如"求导"的前置知识包含"函数概念"和"极限"，而它们又分别依赖更基础的"代数运算"），尤其在进行**多跳遍历**（如查询某知识点的所有间接前置知识）和**路径分析**（如从当前掌握点到目标考点的最短学习路径）时性能极差。

本服务采用图数据库（Neo4j）作为知识图谱的存储引擎，提供高效的关系建模、图遍历和路径查询能力。

### 1.2 设计目标

1. **完整建模**：覆盖知识点层级、前置依赖、学科关联、考点映射、教材版本差异等全部关系类型
2. **高效查询**：多跳遍历、路径搜索、子图提取等操作毫秒级响应
3. **多版本兼容**：同一知识点在不同教材版本中的编排差异可通过关系属性区分
4. **双向同步**：与 MySQL 主库保持数据一致性，支持增量同步
5. **开发者友好**：提供封装好的图查询 API 服务，屏蔽 Cypher 查询细节

### 1.3 与相关模块的关系

| 关联模块 | 关系说明 |
|---------|---------|
| 知识点体系与教材映射引擎 | 本服务是其底层图存储实现 |
| 知识图谱构建与可视化交互引擎 | 可视化层调用本服务的子图查询 API |
| 自适应学习与个性化推荐引擎 | 调用本服务的路径分析和依赖查询 |
| 考点梳理模块 | 调用考点映射和关联知识点查询 |
| 同步课堂学习模块 | 调用章节知识点层级查询 |
| 错题整理模块 | 调用错题关联知识点的上游依赖查询 |
| RAG 与知识库系统 | 利用知识点关系进行上下文扩展检索 |

## 2. 技术选型

### 2.1 图数据库选型：Neo4j

| 维度 | 决策 |
|------|------|
| 数据库 | Neo4j Community Edition（单机）→ 后续可升级 Enterprise（集群） |
| 版本要求 | Neo4j 5.x+ |
| 驱动 | neo4j-driver (Java/Python/Node.js) |
| 查询语言 | Cypher |
| 部署方式 | Docker 容器，独立于 MySQL 主库 |

### 2.2 选型理由

- **原生图存储**：节点和关系以指针直接连接，多跳遍历无需 JOIN，时间复杂度与总图规模无关
- **Cypher 表达力**：声明式图查询语言，表达路径、模式匹配简洁直观
- **ACID 事务**：单实例支持完整事务，保证图写入一致性
- **成熟生态**：APOC 扩展库提供丰富的图算法（最短路径、PageRank、社区发现等）
- **可视化工具**：Neo4j Browser 可直接可视化调试图结构

### 2.3 不选替代方案的理由

| 替代方案 | 不选理由 |
|---------|---------|
| MySQL + 邻接表 | 多跳递归查询性能差（CTE 递归有深度限制），无法高效做路径分析 |
| PostgreSQL + AGE 插件 | AGE 成熟度不如 Neo4j 原生图，调试和运维工具链不完善 |
| ArangoDB | 多模型但图查询性能不如专用图库，社区生态较小 |
| JanusGraph | 分布式方案，MVP 阶段过于复杂 |

## 3. 图数据模型

### 3.1 节点类型（Node Labels）

#### 3.1.1 核心节点

```
(:KnowledgePoint)       // 知识点
(:Subject)              // 学科
(:Textbook)             // 教材版本
(:Chapter)              // 章节
(:ExamPoint)            // 考点
(:Question)             // 题目（引用，不存全量数据）
(:CompetencyDimension)  // 能力维度
```

### 3.2 节点属性定义

#### KnowledgePoint（知识点）

| 属性名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| kp_id | STRING | ✅ | 全局唯一ID，与 MySQL 主表一致 | "KP-MATH-J3-0042" |
| name | STRING | ✅ | 知识点名称 | "一元二次方程" |
| subject_code | STRING | ✅ | 学科编码 | "MATH" |
| stage | STRING | ✅ | 学段 | "JUNIOR" |
| grade_level | INT | ✅ | 年级序号(1-12) | 9 |
| difficulty | FLOAT | ❌ | 难度系数 0-1 | 0.65 |
| description | STRING | ❌ | 知识点描述 | "含一个未知数的二次方程..." |
| tags | LIST<STRING> | ❌ | 标签 | ["代数","方程","中考高频"] |
| bloom_level | STRING | ❌ | 布鲁姆认知层级 | "APPLY" |
| status | STRING | ✅ | 状态 | "ACTIVE" |
| mysql_id | INT | ✅ | MySQL 主表 ID，用于同步关联 | 12345 |
| created_at | DATETIME | ✅ | 创建时间 | 2026-01-15T10:00:00Z |
| updated_at | DATETIME | ✅ | 更新时间 | 2026-05-20T14:30:00Z |

#### Subject（学科）

| 属性名 | 类型 | 说明 |
|--------|------|------|
| code | STRING | "MATH","CHINESE","ENGLISH","PHYSICS" 等 |
| name | STRING | "数学","语文","英语","物理" |

#### Textbook（教材）

| 属性名 | 类型 | 说明 |
|--------|------|------|
| tb_id | STRING | 教材版本唯一标识 |
| publisher | STRING | "人教版","苏教版","北师大版" |
| subject_code | STRING | 学科 |
| stage | STRING | 学段 |
| grade | INT | 年级 |
| semester | STRING | "上册"/"下册" |
| edition_year | INT | 版本年份 |

#### Chapter（章节）

| 属性名 | 类型 | 说明 |
|--------|------|------|
| chapter_id | STRING | 章节唯一标识 |
| title | STRING | 章节标题 |
| level | INT | 层级深度(0=章, 1=节, 2=课时) |
| sort_order | INT | 同级排序 |
| tb_id | STRING | 所属教材版本 |

#### ExamPoint（考点）

| 属性名 | 类型 | 说明 |
|--------|------|------|
| ep_id | STRING | 考点唯一标识 |
| name | STRING | 考点名称 |
| exam_type | STRING | "MIDTERM"/"FINAL"/"ZHONGKAO"/"GAOKAO" |
| frequency | STRING | "HIGH"/"MEDIUM"/"LOW" 出题频率 |
| year_range | STRING | 适用年份范围 |

### 3.3 关系类型（Relationship Types）

```
// 层级关系
(:KnowledgePoint)-[:HAS_CHILD]->(:KnowledgePoint)       // 父子层级
(:KnowledgePoint)-[:PREREQUISITE]->(:KnowledgePoint)     // 前置依赖
(:KnowledgePoint)-[:RELATED_TO]->(:KnowledgePoint)       // 关联关系

// 学科归属
(:KnowledgePoint)-[:BELONGS_TO]->(:Subject)

// 教材映射
(:KnowledgePoint)-[:APPEARS_IN {sort_order, depth}]->(:Chapter)
(:Chapter)-[:PART_OF]->(:Textbook)
(:Chapter)-[:HAS_SUBCHAPTER]->(:Chapter)

// 考点映射
(:KnowledgePoint)-[:MAPPED_TO]->(:ExamPoint)

// 题目关联
(:Question)-[:TESTS]->(:KnowledgePoint)

// 能力维度
(:KnowledgePoint)-[:REQUIRES]->(:CompetencyDimension)
```

### 3.4 关系属性

#### PREREQUISITE（前置依赖）

| 属性 | 类型 | 说明 | 示例 |
|------|------|------|------|
| strength | STRING | 依赖强度 "REQUIRED"/"RECOMMENDED" | "REQUIRED" |
| textbook_scope | LIST<STRING> | 仅特定教材版本需要 | ["人教版"] |
| description | STRING | 依赖说明 | "需要先掌握因式分解" |

#### APPEARS_IN（知识点出现在章节中）

| 属性 | 类型 | 说明 | 示例 |
|------|------|------|------|
| sort_order | INT | 本章内排序 | 3 |
| depth | STRING | 深度 "INTRODUCE"/"DEEPEN"/"REVIEW" | "INTRODUCE" |
| is_core | BOOLEAN | 是否本章核心知识点 | true |

#### TESTS（题目考查知识点）

| 属性 | 类型 | 说明 |
|------|------|------|
| weight | FLOAT | 该知识点在题目中的权重(0-1) |
| is_primary | BOOLEAN | 是否主要考查点 |

### 3.5 图模型示例

```
[Subject:数学] ← BELONGS_TO ← [KP:一元二次方程]
                                    ↑ HAS_CHILD
                              [KP:判别式]
                                    ↓ PREREQUISITE
                              [KP:平方根]
                                    ↓ PREREQUISITE
                              [KP:乘方运算]

[KP:一元二次方程] → APPEARS_IN → [Chapter:第2章 一元二次方程] → PART_OF → [Textbook:人教版九年级上]
[KP:一元二次方程] → MAPPED_TO → [ExamPoint:一元二次方程的解法] (中考高频)
```

## 4. 核心查询 API 设计

### 4.1 API 总览

| API | Method | Path | 说明 |
|-----|--------|------|------|
| 获取知识点子图 | GET | `/graph/kp/{kpId}/subgraph` | 获取知识点及其 N 跳关系子图 |
| 查询前置知识链 | GET | `/graph/kp/{kpId}/prerequisites` | 获取所有直接和间接前置知识 |
| 学习路径规划 | GET | `/graph/path/plan` | 从当前知识到目标的最优学习路径 |
| 章节知识点树 | GET | `/graph/chapter/{chapterId}/tree` | 获取章节下的知识点层级树 |
| 考点关联知识点 | GET | `/graph/exam-point/{epId}/knowledge-points` | 获取考点关联的所有知识点 |

| 知识点搜索 | GET | `/graph/kp/search` | 按条件搜索知识点节点 |

#### 4.2.2 查询前置知识链

**GET** `/api/v1/graph/kp/{kpId}/prerequisites`

请求参数：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| max_depth | int | ❌ | 最大深度，默认 10 |
| strength | string | ❌ | 过滤 "REQUIRED"/"ALL"，默认 "ALL" |

响应：
```json
{
  "code": 0,
  "data": {
    "target": {
      "kp_id": "KP-MATH-J3-0042",
      "name": "一元二次方程"
    },
    "prerequisiteLevels": [
      {
        "level": 1,
        "items": [
          {
            "kp_id": "KP-MATH-J2-0018",
            "name": "平方根",
            "strength": "REQUIRED",
            "directPrerequisiteOf": "KP-MATH-J3-0042"
          }
        ]
      },
      {
        "level": 2,
        "items": [
          {
            "kp_id": "KP-MATH-J2-0005",
            "name": "乘方运算",
            "strength": "REQUIRED",
            "directPrerequisiteOf": "KP-MATH-J2-0018"
          }
        ]
      }
    ],
    "totalCount": 5,
    "maxDepthReached": 3
  }
}
```

底层 Cypher：
```cypher
MATCH (root:KnowledgePoint {kp_id: $kpId})
MATCH path = (root)-[:PREREQUISITE*1..$maxDepth]->(prereq:KnowledgePoint)
WHERE $strength = 'ALL' OR ALL(r IN relationships(path) WHERE r.strength = $strength)
WITH prereq, 
     length(path) AS level,
     relationships(path)[0] AS directRel,
     [p IN nodes(path)[1..-1] | p.kp_id] AS pathThrough
RETURN prereq.kp_id AS kp_id,
       prereq.name AS name,
       directRel.strength AS strength,
       level,
       pathThrough
ORDER BY level ASC, prereq.name ASC
```

```json
      }

```

底层 Cypher（最短路径）：
```cypher
// 找到所有起点节点
UNWIND $fromKpIds AS fromId
MATCH (from:KnowledgePoint {kp_id: fromId})
WITH collect(DISTINCT from) AS fromNodes

MATCH (to:KnowledgePoint {kp_id: $toKpId})

// 从任一起点到目标的最短路径（沿 PREREQUISITE 反向遍历）
UNWIND fromNodes AS startNode
MATCH path = shortestPath((startNode)<-[:PREREQUISITE*1..15]-(to))
WITH path
ORDER BY length(path) ASC
LIMIT 1

UNWIND nodes(path) AS node
WITH path, node,
     CASE WHEN node = nodes(path)[0] THEN 1
          ELSE length(shortestPath((nodes(path)[0])<-[:PREREQUISITE*]-(node)))
     END AS step
RETURN node.kp_id AS kp_id,
       node.name AS name,
       node.difficulty AS difficulty,
       step
ORDER BY step ASC
```

## 5. 服务架构

### 5.1 服务分层

```
┌──────────────────────────────────────────────────────┐
│                   调用方                              │
│  学习服务 / 推荐引擎 / 考点梳理 / RAG检索 / 可视化    │
└──────────────────────┬───────────────────────────────┘
                       │ HTTP/gRPC
┌──────────────────────▼───────────────────────────────┐
│              Graph Query Service                      │
│  (Spring Boot / Node.js 微服务)                       │
│  ┌─────────────┐  ┌──────────────┐  ┌────────────┐  │
│  │ REST API    │  │ Cypher       │  │ Cache      │  │
│  │ Controller  │  │ Builder      │  │ Manager    │  │
│  └─────────────┘  └──────────────┘  └────────────┘  │
│  ┌─────────────┐  ┌──────────────┐  ┌────────────┐  │
│  │ Sync        │  │ Path         │  │ Query      │  │
│  │ Service     │  │ Planner      │  │ Optimizer  │  │
│  └─────────────┘  └──────────────┘  └────────────┘  │
└──────────────────────┬───────────────────────────────┘
                       │ Bolt Protocol
┌──────────────────────▼───────────────────────────────┐
│                  Neo4j 5.x                           │
│  ┌───────────────────────────────────────────────┐   │
│  │  Indexes | Constraints | APOC Procedures      │   │
│  └───────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────┘
```

### 5.2 核心组件职责

| 组件 | 职责 |
|------|------|
| **REST API Controller** | 接收 HTTP 请求，参数校验，响应封装 |
| **Cypher Builder** | 将查询参数动态组装为 Cypher 查询，防止注入 |
| **Cache Manager** | 缓存热点查询结果（子图、前置链），基于 TTL 过期 |
| **Sync Service** | 监听 MySQL binlog，增量同步知识点数据到 Neo4j |
| **Path Planner** | 封装路径规划算法（最短路径、权重路径） |
| **Query Optimizer** | 查询超时保护、深度限制、结果集大小限制 |

## 6. 数据同步策略

### 6.1 同步架构

```
MySQL (主库)                    Neo4j (图库)
┌──────────┐                   ┌──────────┐
│ kp表      │──binlog──┐       │ KnowledgePoint │
│ chapter表 │          │       │ Chapter        │
│ exam_point│          ▼       │ ExamPoint      │
│ relation表│   Sync Service   │ + Relationships│
└──────────┘   (Canal/Debezium)└──────────┘
```

### 6.2 同步策略

| 策略 | 说明 |
|------|------|
| **增量同步** | 通过 Canal 监听 MySQL binlog，捕获 INSERT/UPDATE/DELETE 事件 |
| **批量初始化** | 首次部署时全量导入 MySQL 数据到 Neo4j |
| **最终一致性** | 同步延迟控制在 5 秒以内 |
| **冲突处理** | 以 MySQL 为准，Neo4j 仅做查询加速，不直接写入 |

### 6.3 同步事件处理

```java
// Canal binlog 事件处理伪代码
public void onBinlogEvent(BinlogEvent event) {
    switch (event.getType()) {
        case INSERT:
            if (event.getTable().equals("knowledge_point")) {
                KnowledgePoint kp = mapToKp(event.getData());
                neo4jClient.run(
                    "CREATE (n:KnowledgePoint SET n += $props)",
                    Map.of("props", kpToProperties(kp))
                );
            }
            break;
        case UPDATE:
            if (event.getTable().equals("knowledge_point")) {
                neo4jClient.run(
                    "MATCH (n:KnowledgePoint {mysql_id: $id}) SET n += $props",
                    Map.of("id", event.getId(), "props", kpToProperties(event.getData()))
                );
            }
            break;
        case DELETE:
            neo4jClient.run(
                "MATCH (n:KnowledgePoint {mysql_id: $id}) DETACH DELETE n",
                Map.of("id", event.getId())
            );
            break;
    }
    
    // 关系表同步
    if (event.getTable().equals("kp_relation")) {
        syncRelation(event);
    }
}
```

## 8. 关键 Cypher 查询模板

### 8.1 章节知识点树

```cypher
// 查询某章节下所有知识点及其层级关系
MATCH (ch:Chapter {chapter_id: $chapterId})<-[:APPEARS_IN]-(kp:KnowledgePoint)
OPTIONAL MATCH (kp)-[:HAS_CHILD*0..3]->(child:KnowledgePoint)
RETURN kp, child,
       [(kp)-[:APPEARS_IN]->(c:Chapter) | c.chapter_id] AS chapterIds,
       [(kp)-[:MAPPED_TO]->(ep:ExamPoint) | ep.ep_id] AS examPointIds
ORDER BY kp.name
```

### 8.2 考点关联知识点（含间接关联）

```cypher
// 查询考点直接关联和间接关联的知识点
MATCH (ep:ExamPoint {ep_id: $epId})<-[:MAPPED_TO]-(directKP:KnowledgePoint)
OPTIONAL MATCH (directKP)-[:HAS_CHILD*0..2]->(childKP:KnowledgePoint)
RETURN DISTINCT directKP.kp_id AS kp_id,
       directKP.name AS name,
       CASE WHEN directKP-[:MAPPED_TO]->(ep) THEN 'DIRECT' ELSE 'INDIRECT' END AS relationType,
       childKP.kp_id AS childKpId,
       childKP.name AS childName
```

### 8.3 知识点影响力评估（PageRank）

```cypher
// 识别核心枢纽知识点（被大量其他知识点依赖）
CALL gds.pageRank.stream('knowledgeGraph', {
    relationshipTypes: ['PREREQUISITE'],
    maxIterations: 20
})
YIELD nodeId, score
WITH gds.util.asNode(nodeId) AS kp, score
WHERE kp:KnowledgePoint AND kp.subject_code = $subjectCode
RETURN kp.kp_id AS kp_id,
       kp.name AS name,
       score
ORDER BY score DESC
LIMIT 20
```

### 8.4 共现知识点（常一起出现在题目中）

```cypher
// 查找与目标知识点经常一起被考查的其他知识点
MATCH (q:Question)-[:TESTS]->(target:KnowledgePoint {kp_id: $kpId})
MATCH (q)-[:TESTS]->(other:KnowledgePoint)
WHERE other.kp_id <> $kpId
WITH other.kp_id AS kp_id, other.name AS name, count(q) AS coOccurrence
ORDER BY coOccurrence DESC
LIMIT 10
RETURN kp_id, name, coOccurrence
```

## 9. 缓存策略

### 9.1 缓存层级

| 缓存层 | 存储 | TTL | 适用场景 |
|--------|------|-----|---------|
| L1: 应用内存 | Caffeine/Guava Cache | 5 分钟 | 热点知识点子图、频繁查询的前置链 |
| L2: Redis | Redis Hash | 30 分钟 | 章节知识点树、考点关联、路径规划结果 |
| L3: Neo4j 查询缓存 | Neo4j 内置 | 会话级 | Cypher 执行计划缓存 |

### 9.2 缓存 Key 设计

```
// 知识点子图
graph:subgraph:{kpId}:d{depth}:r{relTypes}    → JSON (nodes + relationships)

// 前置知识链
graph:prereq:{kpId}:s{strength}               → JSON (层级列表)

// 章节知识点树
graph:chapter:tree:{chapterId}                → JSON (树形结构)

// 考点关联
graph:exam:kp:{epId}                          → JSON (知识点列表)

// 学习路径
graph:path:{fromHash}:{toKpId}                → JSON (路径步骤)
```

### 9.3 缓存失效

```java
// 数据同步时主动失效缓存
public void invalidateCache(String kpId) {
    // 1. 删除直接相关的所有缓存
    cacheManager.deleteByPattern("graph:subgraph:" + kpId + ":*");
    cacheManager.deleteByPattern("graph:prereq:" + kpId + ":*");
    cacheManager.deleteByPattern("graph:path:*:" + kpId);
    
    // 2. 删除关联章节缓存（知识点可能出现在多个章节）
    List<String> chapterIds = getRelatedChapterIds(kpId);
    for (String chId : chapterIds) {
        cacheManager.delete("graph:chapter:tree:" + chId);
    }
    
    // 3. 通知关联知识点失效（因为路径可能经过此节点）
    // 使用消息队列广播，让所有实例清理本地 L1 缓存
    messageQueue.publish("graph-cache-invalidate", kpId);
}
```

## 11. 错误处理

### 11.1 错误码定义

| 错误码 | HTTP 状态 | 说明 | 处理建议 |
|--------|----------|------|---------|
| GRAPH_KPI_NOT_FOUND | 404 | 知识点不存在 | 检查 kpId 是否正确 |
| GRAPH_QUERY_TIMEOUT | 504 | 图查询超时 | 缩小查询范围或降低深度 |
| GRAPH_PATH_NOT_FOUND | 404 | 无法找到路径 | 可能缺少前置关系数据 |
| GRAPH_RESULT_TOO_LARGE | 422 | 结果集超限 | 降低深度或增加过滤条件 |
| GRAPH_SYNC_ERROR | 500 | 同步失败 | 检查 binlog 消费状态 |
| GRAPH_NEO4J_UNAVAILABLE | 503 | Neo4j 不可用 | 降级到 MySQL 查询 |
| GRAPH_INVALID_PARAM | 400 | 参数校验失败 | 检查请求参数 |

### 11.2 降级策略

```java
public class GraphQueryService {
    
    /**
     * 带降级的图查询
     * 优先走 Neo4j，失败时降级到 MySQL 递归查询
     */
    public SubGraphResult getSubgraph(String kpId, int depth) {
        try {
            // 优先使用 Neo4j
            return neo4jTemplate.querySubgraph(kpId, depth);
        } catch (Neo4jException | TimeoutException e) {
            log.warn("Neo4j query failed, degrading to MySQL. kpId={}", kpId, e);
            
            // 降级：使用 MySQL 递归 CTE 查询（性能较差但可用）
            return mysqlTemplate.querySubgraphRecursive(kpId, depth);
        }
    }
    
    /**
     * 路径查询降级
     */
    public PathResult planPath(List<String> fromIds, String toId) {
        try {
            return neo4jPathPlanner.plan(fromIds, toId);
        } catch (Exception e) {
            // 降级：直接返回目标知识点的前置链，不做全局路径优化
            return simplePathFallback(toId);
        }
    }
}
```

### 11.3 MySQL 降级查询（递归 CTE）

```sql
-- 降级方案：用 MySQL 8.0 递归 CTE 查询前置知识链
WITH RECURSIVE prereq_chain AS (
    -- 基础查询：直接前置知识
    SELECT 
        kp_id, kp_name, parent_kp_id, 1 AS level
    FROM kp_relation kr
    JOIN knowledge_point kp ON kr.from_kp_id = kp.kp_id
    WHERE kr.to_kp_id = #{targetKpId}
      AND kr.relation_type = 'PREREQUISITE'
    
    UNION ALL
    
    -- 递归：继续向上查找
    SELECT 
        kp.kp_id, kp.kp_name, kp.parent_kp_id, pc.level + 1
    FROM kp_relation kr
    JOIN knowledge_point kp ON kr.from_kp_id = kp.kp_id
    JOIN prereq_chain pc ON kr.to_kp_id = pc.kp_id
    WHERE kr.relation_type = 'PREREQUISITE'
      AND pc.level < 10  -- 深度限制
)
SELECT DISTINCT kp_id, kp_name, level
FROM prereq_chain
ORDER BY level;
```
