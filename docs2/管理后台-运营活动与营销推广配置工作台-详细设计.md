# 管理后台 - 运营活动与营销推广配置工作台 详细设计

## 1. 概述

### 1.1 模块定位

运营活动与营销推广配置工作台是 PrimeTop 管理后台的核心运营模块之一，为运营团队、市场团队和增长团队提供统一的可视化操作界面，用于创建、配置、发布和管理各类运营活动、营销推广、优惠券、App 弹窗 Banner、推送通知、增长激励任务及裂变邀请方案。

本工作台是对后端已有运营引擎（运营活动引擎、优惠券引擎、积分引擎、弹窗规则引擎、推送通道适配层、增长自动化引擎）的前端编排层，将分散的服务端能力聚合为运营人员可直接操作的「活动生产线」。

### 1.2 设计目标

| 目标 | 说明 |
| --- | --- |
| 统一入口 | 将活动、优惠券、Banner、推送、增长任务、裂变配置归入一个工作台 |
| 可视化编排 | 所见即所得的活动页面编辑、Banner 预览、推送文案预览 |
| 安全发布 | 多级审核 + 定时发布 + 一键下线 + 灰度放量 |
| 效果可量化 | 内嵌活动数据看板，ROI、参与率、转化率实时可见 |
| 权限分离 | 运营编辑 → 审核 → 发布 全链路权限管控 |

### 1.3 适用范围

| 角色 | 使用场景 |
| --- | --- |
| 运营专员 | 日常创建活动、配置优惠券、编辑 Banner |
| 运营主管 | 审核活动方案、控制发布节奏 |
| 市场推广 | 配置裂变邀请方案、渠道追踪 |
| 增长产品 | 配置增长任务、A/B 实验方案 |
| 数据分析 | 查看活动效果、导出报表 |

### 1.4 依赖关系

```
本工作台（前端）
    │
    ├── 运营内容管理与活动配置引擎（活动 CRUD + 页面模板）
    ├── 优惠券与促销活动引擎（券生命周期）
    ├── 积分获取规则计算与虚拟资产交易结算服务（积分/奖励发放）
    ├── 运营弹窗规则引擎（弹窗触发规则）
    ├── 统一通知消息模板引擎（推送/短信/站内信）
    ├── 多厂商推送通道适配层（推送投递）
    ├── 邀请裂变与用户增长服务（裂变方案）
    ├── 用户标签与智能分群引擎（目标人群圈选）
    ├── AB测试与实验平台（分流策略）
    └── 统一文件生成与异步报表导出中心服务（报表导出）
```

## 3. 数据模型设计

### 3.1 运营活动 (ops_campaign)

```sql
CREATE TABLE ops_campaign (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    campaign_no     VARCHAR(32) NOT NULL UNIQUE COMMENT '活动编号 OPS+YYYYMMDD+序号',
    title           VARCHAR(128) NOT NULL COMMENT '活动标题',
    subtitle        VARCHAR(256) DEFAULT NULL COMMENT '副标题',
    type            VARCHAR(32) NOT NULL COMMENT '活动类型: LEARNING_CHALLENGE|SEASONAL|EXAM_SPRINT|HOLIDAY_CAMP|PROMOTION|NEW_USER_GUIDE',
    status          VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT|PENDING_REVIEW|APPROVED|SCHEDULED|LIVE|PAUSED|ENDED|ARCHIVED',
    description     TEXT COMMENT '活动描述',
    cover_image     VARCHAR(512) COMMENT '封面图 URL',
    start_at        DATETIME NOT NULL COMMENT '开始时间',
    end_at          DATETIME NOT NULL COMMENT '结束时间',
    target_segment  JSON COMMENT '目标人群标签 JSON: {grade:[], stage:[], tags:[], user_type:[]}',
    page_config     JSON COMMENT '活动页面 JSON 配置（驱动客户端动态渲染）',
    reward_config   JSON COMMENT '奖励配置: {points:Int, coupon_batch_ids:[], badge_id:Int, virtual_items:[]}',
    display_config  JSON COMMENT '展示配置: {banner_positions:[], popup_enabled:Bool, feed_priority:Int}',
    ab_experiment_id BIGINT DEFAULT NULL COMMENT '关联 A/B 实验 ID',
    budget          DECIMAL(12,2) DEFAULT 0 COMMENT '活动预算（元）',
    actual_cost     DECIMAL(12,2) DEFAULT 0 COMMENT '实际消耗（元）',
    priority        INT DEFAULT 50 COMMENT '优先级 1-100, 越大越优先',
    created_by      BIGINT NOT NULL COMMENT '创建人 ID',
    reviewed_by     BIGINT DEFAULT NULL COMMENT '审核人 ID',
    reviewed_at     DATETIME DEFAULT NULL COMMENT '审核时间',
    review_comment  VARCHAR(512) DEFAULT NULL COMMENT '审核意见',
    published_at    DATETIME DEFAULT NULL COMMENT '发布时间',
    published_by    BIGINT DEFAULT NULL COMMENT '发布人 ID',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_status (status),
    INDEX idx_type_start (type, start_at),
    INDEX idx_date_range (start_at, end_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='运营活动表';
```

## 4. 活动状态流转

### 4.1 运营活动状态机

```
    ┌─────────┐  submit   ┌────────────────┐  approve  ┌───────────┐  schedule  ┌───────────┐
    │  DRAFT  │ ────────► │ PENDING_REVIEW │ ────────► │ APPROVED  │ ─────────► │ SCHEDULED │
    └─────────┘           └────────────────┘           └───────────┘            └───────────┘
         │                       │                          │                         │
         │                       │ reject                   │                         │ to=start_at
         │                       ▼                          │ cancel                  ▼
         │                  ┌─────────┐                     │                  ┌───────┐
         │                  │ REJECTED │                    │                  │ LIVE  │
         │                  └─────────┘                     │                  └───────┘
         │                       │                          │                    │   │
         └─── edit ──────────────┘                          │              pause  │   │ to=end_at
                                                          cancel│                  ▼   ▼
                                                                ▼             ┌──────────┐ ┌───────┐
                                                          ┌──────────┐       │  PAUSED  │ │ ENDED │
                                                          │ CANCELLED│       └──────────┘ └───────┘
                                                          └──────────┘            │             │
                                                                 resume           │             │ archive
                                                                 ▼                │             ▼
                                                             ┌───────┐          │      ┌──────────┐
                                                             │ LIVE  │◄─────────┘      │ARCHIVED  │
                                                             └───────┘                └──────────┘
```

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| `DRAFT` | 草稿，编辑中 | 编辑、提交审核、删除 |
| `PENDING_REVIEW` | 待审核 | 审核（通过/驳回/要求修改） |
| `REJECTED` | 已驳回 | 修改后重新提交、归档 |
| `APPROVED` | 已审核通过 | 设置定时发布、立即发布、取消 |
| `SCHEDULED` | 已排期 | 取消发布 |
| `LIVE` | 上线中 | 暂停、强制下线 |
| `PAUSED` | 已暂停 | 恢复、强制下线 |
| `ENDED` | 已结束（到达 end_at） | 归档 |
| `CANCELLED` | 已取消 | 归档 |
| `ARCHIVED` | 已归档（只读） | 无 |

### 4.2 优惠券批次状态机

```
DRAFT ──activate──► ACTIVE ──quantity=0──► EXHAUSTED
                       │                       │
                       │ disable            expire
                       ▼                       ▼
                   DISABLED                EXPIRED
```

### 4.3 推送任务状态机

```
DRAFT ──submit──► PENDING_REVIEW ──approve──► APPROVED ──trigger──► SENDING ──done──► SENT
                       │                       │                                              │
                    reject                  cancel                                      cancelled
                       │                       │
                       ▼                       ▼
                   DRAFT                  CANCELLED                              CANCELLED
                                                                              ▲
                                                                       ┌──────┘
                                                                  FAILED ──retry──► SENDING
```

## 5. API 接口设计

### 5.1 通用约定

```
Base URL: /api/admin/v1/ops
Content-Type: application/json
Auth: Bearer {admin_token}
Permission: 需 ops:* 相关权限
```

统一响应格式：

```json
{
    "code": 0,
    "message": "success",
    "data": { ... },
    "timestamp": 1721635200000

```
?page=1&page_size=20&sort=created_at:desc

### 6.1 活动状态机流转（Spring StateMachine DSL）

```java
@Component
public class CampaignStateMachineConfig
        extends EnumStateMachineConfigurerAdapter<CampaignStatus, CampaignEvent> {

    @Override
    public void configure(StateMachineStateConfigurer<CampaignStatus, CampaignEvent> states)
            throws Exception {
        states.withStates()
            .initial(CampaignStatus.DRAFT)
            .states(EnumSet.allOf(CampaignStatus.class))
            .end(CampaignStatus.ARCHIVED);
    }

    @Override
    public void configure(StateMachineTransitionConfigurer<CampaignStatus, CampaignEvent> transitions)
            throws Exception {
        transitions
            .withExternal().source(DRAFT).target(PENDING_REVIEW).event(SUBMIT)
            .and()
            .withExternal().source(PENDING_REVIEW).target(APPROVED).event(APPROVE)
            .and()
            .withExternal().source(PENDING_REVIEW).target(REJECTED).event(REJECT)
            .and()
            .withExternal().source(REJECTED).target(PENDING_REVIEW).event(SUBMIT)
            .and()
            .withExternal().source(APPROVED).target(SCHEDULED).event(SCHEDULE)
            .and()
            .withExternal().source(SCHEDULED).target(LIVE).event(START)
            .and()
            .withExternal().source(LIVE).target(PAUSED).event(PAUSE)
            .and()
            .withExternal().source(PAUSED).target(LIVE).event(RESUME)
            .and()
            .withExternal().source(LIVE).target(ENDED).event(END)
            .and()
            .withExternal().source(ENDED).target(ARCHIVED).event(ARCHIVE)
            .and()
            .withExternal().source(APPROVED).target(CANCELLED).event(CANCEL)
            .and()
            .withExternal().source(SCHEDULED).target(CANCELLED).event(CANCEL)
            .and()
            .withExternal().source(LIVE).target(CANCELLED).event(CANCEL)
            .and()
            .withExternal().source(CANCELLED).target(ARCHIVED).event(ARCHIVE);
    }
}
```

### 6.2 审核动作幂等处理

```java
@Service
public class ReviewService {

    @Transactional
    public ReviewResult review(ReviewCommand cmd) {
        Long lockKey = LockKey.of("ops:review:%s:%d", cmd.getEntityType(), cmd.getEntityId());
        if (!redisLock.tryLock(lockKey, 10, TimeUnit.SECONDS)) {
            throw new OpsException(OpsError.REVIEW_CONFLICT);
        }
        try {
            ReviewRecord latest = reviewRepo.findTopByEntityOrderByCreatedAtDesc(
                cmd.getEntityType(), cmd.getEntityId());
            if (latest != null && latest.getAction().equals(cmd.getAction())
                    && latest.getReviewerId().equals(cmd.getReviewerId())) {
                return ReviewResult.duplicate(latest.getId());
            }
            ReviewRecord record = ReviewRecord.builder()
                .entityType(cmd.getEntityType())
                .entityId(cmd.getEntityId())
                .action(cmd.getAction())
                .reviewerId(cmd.getReviewerId())
                .comment(cmd.getComment())
                .snapshot(snapshotService.capture(cmd.getEntityType(), cmd.getEntityId()))
                .build();
            reviewRepo.save(record);

            // 状态流转
            Campaign campaign = campaignRepo.findByIdForUpdate(cmd.getEntityId())
                .orElseThrow(() -> new OpsException(OpsError.CAMPAIGN_NOT_FOUND));
            CampaignStatus next = transition(campaign.getStatus(), cmd.getAction());
            campaign.setStatus(next);
            if (next == APPROVED) {
                campaign.setReviewedBy(cmd.getReviewerId());
                campaign.setReviewedAt(LocalDateTime.now());
            }
            campaignRepo.save(campaign);

            // 发送审核事件
            opsOutbox.publish(OpsDomainEvent.reviewed(cmd.getEntityType(), cmd.getEntityId(),
                    next.name(), record.getId()));
            return ReviewResult.ok(record.getId());
        } finally {
            redisLock.unlock(lockKey);
        }
    }
}
```

@Service
public class CouponDistributionService {

    @Async("opsTaskExecutor")
    public void distributeAsync(Long batchId, DistributionRequest request) {
        String taskId = IdUtil.generate("cdist_");
        // 1. 创建发放任务记录
        distributionTaskRepo.save(DistributionTask.start(batchId, taskId, request));

        Pageable page = PageRequest.of(0, 500);

        opsOutbox.publish(OpsDomainEvent.couponDistributed(batchId, taskId));
    }

## 7. 状态机守卫规则

| 编号 | 守卫规则 | 说明 |
|------|---------|------|
| G1 | 创建人≠审核人 | 活动/券/Banner/推送的提交、审核、发布须由不同角色执行 |
| G2 | 时间一致性 | `end_at` 必须晚于 `start_at`，且定时发布时间位于两者之间 |
| G3 | 预算强校验 | `actual_cost` 超过 `budget` 时，新增奖励发放暂停，需走超预算审批 |
| G4 | 目标人群非空 | 必须配置 `target_segment` 或 `target_user_ids`，禁止全量盲发（系统公告除外） |
| G5 | 未成年保护 | 幼儿/小学阶段活动不得包含诱导付费、攀比排名、社交裂变；文案需过未成年人审核 |
| G6 | 渠道白名单 | `channels` 只能选择已接入且健康的推送通道， unhealthy 通道自动剔除 |
| G7 | 互斥活动检查 | 同一展示位同一时段只能有一个 LIVE 活动；冲突时按优先级 + 创建时间仲裁 |
| G8 | 券库存守恒 | `issued_quantity + 冻结库存 ≤ total_quantity`，禁止超发 |
| G9 | 幂等键唯一 | 所有变更操作须携带 `client_request_id`，重复请求返回相同结果 |
| G10 | 审计快照 | 每次审核、发布、下线操作保存配置快照，支持 180 天内追溯 |
| G11 | 下线即失效 | 活动下线/暂停后，客户端缓存 5 分钟内失效，不得继续展示 |
| G12 | 拼团/秒杀审批 | 涉及资金的活动（拼团、秒杀、限时折扣）需财务 + 法务双人审批 |
| G13 | 测试预览 | 推送、Banner 必须完成预览或沙箱测试才能提交审核 |
| G14 | 活动结束归档 | 到达 `end_at` 后自动迁移至 ENDED，30 天后归档至 ARCHIVED，不可编辑 |

## 12. 合规与安全

### 12.1 未成年人保护

- 幼儿/小学活动禁止出现诱导消费、攀比、抽奖、裂变的文案和交互。
- 推送时间默认限制：小学生 21:00 后、初中生 22:00 后不得发送营销类推送。
- 优惠券不得发放给未绑定监护人的 14 岁以下用户。

### 12.2 数据隐私

- 运营后台查看用户列表时，手机号、设备号脱敏展示。
- 分群人群包导出需双人审批，且只返回聚合数据，禁止导出明细。
- 活动埋点数据 90 天归档，审计日志 3 年。

### 12.3 资金安全

- 涉及现金/代金券的活动，创建、修改、发布均需财务角色审批。
- 实际消耗接近预算 80% 时系统告警，达到 100% 自动暂停奖励发放。
- 优惠券发放记录对账：日终 `ops_coupon_batch.issued_quantity` 与券实例表总数必须一致。

### 12.4 内容安全

- 所有活动文案、Banner 图片、推送内容必须经过敏感词过滤与未成年人内容审核。
- 涉及教育的活动不得宣传“保分”“必过”等违规用语。
