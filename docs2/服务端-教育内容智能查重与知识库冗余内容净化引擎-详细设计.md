# 服务端-教育内容智能查重与知识库冗余内容净化引擎 详细设计

## 1. 概述

### 1.1 模块定位

教育内容智能查重与知识库冗余内容净化引擎是 PrimeTop 内容管理体系的底层质量保障组件。随着平台知识库、教材解析、题目讲解、知识点说明等内容持续增长，不同编辑者、不同学科团队、不同教材版本之间不可避免地产生语义重复、近似抄袭、冗余表述等内容质量问题。

本引擎负责对全量教育内容进行**多维度相似性检测**，自动发现并标记冗余内容，提供合并建议与净化工作流，确保知识库精炼、权威、无冗余。

### 1.2 核心职责

| 职责 | 说明 |
| --- | --- |
| 内容指纹生成 | 为每条教育内容生成唯一的内容指纹与语义向量 |
| 全量相似性扫描 | 定期对知识库进行全量交叉比对，发现相似内容对 |
| 增量实时查重 | 新内容入库前实时检测与已有内容的相似度 |
| 冗余聚类分析 | 将相似内容聚类，识别冗余内容组 |
| 净化工作流 | 为运营团队提供查重报告、合并建议、审核工具 |
| 外部抄袭检测 | 对接外部学术资源库，检测内容抄袭（可选扩展） |

### 1.3 与已有模块的区别

| 已有模块 | 本引擎 |
| --- | --- |
| 题目相似度计算与智能去重服务 | 仅针对题库中的**考试题目**去重 |
| 教育内容质量自动评估 | 关注内容**质量**（低质、错误），不关注**冗余** |
| 教育内容事实性校验 | 关注内容**准确性**，不关注**重复性** |
| 教育内容语义标签体系 | 关注内容**标注分类**，不做查重 |
| 作文抄袭检测 | 仅针对**学生作文**的学术诚信检测 |

### 1.5 关键术语

| 术语 | 说明 |
| --- | --- |
| Fingerprint | 内容指纹，包含 SimHash、MinHash、MD5、关键短语等 |
| Pair | 相似内容对，记录两条内容的综合相似度与匹配片段 |
| Cluster | 冗余聚类，由若干相互相似的内容组成的内容组 |
| Verdict | 查重裁决，如 `HIGH_SIMILARITY`、`MODERATE_SIMILARITY`、`LOW` |
| Merge | 净化动作，将冗余内容合并到保留内容并废弃重复项 |

## 2. 数据模型

### 2.1 核心实体定义

#### 2.1.1 内容指纹表 `content_fingerprint`

存储每条教育内容的指纹信息和语义向量引用。

```sql
CREATE TABLE content_fingerprint (
    id              BIGSERIAL PRIMARY KEY,
    content_id      BIGINT NOT NULL,              -- 关联的内容ID
    content_type    VARCHAR(32) NOT NULL,         -- 内容类型: EXPLANATION/ARTICLE/KNOWLEDGE_POINT/VIDEO_SCRIPT/EXERCISE_ANALYSIS
    subject_code    VARCHAR(16),                  -- 学科代码
    grade_range     VARCHAR(32),                  -- 适用学段
    knowledge_point_ids BIGINT[],                 -- 关联知识点ID列表

    -- 文本指纹
    simhash_value   BIGINT,                       -- SimHash指纹值(64位)
    minhash_values  BIGINT[],                     -- MinHash签名(128个)
    content_hash    VARCHAR(64),                  -- MD5精确哈希(完全去重)
    text_length     INTEGER,                      -- 原文长度

    -- 语义向量引用
    embedding_id    VARCHAR(64),                  -- 向量库中的向量ID
    embedding_model VARCHAR(64),                  -- 使用的嵌入模型标识
    embedding_dim   INTEGER,                      -- 向量维度

    -- 分词特征
    term_frequency  JSONB,                        -- TF特征 {term: freq}
    key_phrases     TEXT[],                       -- 关键短语列表

    -- 元数据
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    fingerprint_version INTEGER NOT NULL DEFAULT 1, -- 指纹版本(重算时递增)

    UNIQUE (content_id, content_type),
    INDEX idx_simhash (simhash_value),
    INDEX idx_content_hash (content_hash),
    INDEX idx_content_type_subject (content_type, subject_code)
);

COMMENT ON TABLE content_fingerprint IS '内容指纹表 - 存储所有教育内容的指纹和向量引用';
```

#### 2.1.2 相似内容对表 `content_similarity_pair`

存储检测到的相似内容对及其相似度详情。

```sql
CREATE TABLE content_similarity_pair (
    id              BIGSERIAL PRIMARY KEY,
    content_a_id    BIGINT NOT NULL,
    content_b_id    BIGINT NOT NULL,
    content_a_type  VARCHAR(32) NOT NULL,
    content_b_type  VARCHAR(32) NOT NULL,

    -- 相似度分数 (0~1)
    overall_similarity  DECIMAL(5,4) NOT NULL,    -- 综合相似度
    semantic_similarity DECIMAL(5,4),             -- 语义相似度(向量余弦)
    lexical_similarity  DECIMAL(5,4),             -- 词汇相似度(Jaccard/MinHash)
    structural_similarity DECIMAL(5,4),           -- 结构相似度(段落/格式)
    exact_match_ratio   DECIMAL(5,4),             -- 精确匹配片段比例

    -- 检测详情
    detection_method    VARCHAR(32) NOT NULL,     -- BATCH_SCAN / INCREMENTAL / MANUAL
    matched_segments    JSONB,                    -- 匹配片段详情 [{a_start, a_end, b_start, b_end, text}]
    detection_model     VARCHAR(64),              -- 检测模型版本

    -- 状态
    pair_status         VARCHAR(24) NOT NULL DEFAULT 'DETECTED',
    -- DETECTED: 刚检出 / CONFIRMED: 确认冗余 / RESOLVED_MERGE: 已合并
    -- RESOLVED_KEEP: 确认保留(非冗余) / RESOLVED_REWRITE: 已改写 / FALSE_POSITIVE: 误报

    review_comment      TEXT,                     -- 审核备注
    reviewer_id         BIGINT,                   -- 审核人
    reviewed_at         TIMESTAMPTZ,

    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE (content_a_id, content_b_id),
    INDEX idx_pair_status (pair_status),
    INDEX idx_similarity (overall_similarity DESC),
    INDEX idx_content_a (content_a_id),
    INDEX idx_content_b (content_b_id)
);

COMMENT ON TABLE content_similarity_pair IS '相似内容对表 - 存储查重检测结果';
```

#### 2.1.3 冗余内容聚类表 `redundancy_cluster`

将多个相似内容聚为一组，便于批量处理。

```sql
CREATE TABLE redundancy_cluster (
    id                  BIGSERIAL PRIMARY KEY,
    cluster_uid         VARCHAR(48) NOT NULL UNIQUE,  -- 聚类唯一标识 UUID
    content_ids         BIGINT[] NOT NULL,            -- 聚类内所有内容ID
    content_count       INTEGER NOT NULL,
    representative_id   BIGINT,                       -- 推荐保留的"最佳"内容ID
    cluster_similarity  DECIMAL(5,4) NOT NULL,        -- 聚类内平均相似度

    -- 聚类分析
    subject_code        VARCHAR(16),                  -- 学科
    knowledge_point_ids BIGINT[],                     -- 涉及知识点
    redundancy_type     VARCHAR(32),                  -- DUPLICATE / NEAR_DUPLICATE / PARAPHRASE / OVERLAP

    -- 状态
    cluster_status      VARCHAR(24) NOT NULL DEFAULT 'OPEN',
    -- OPEN: 待处理 / IN_REVIEW: 审核中 / RESOLVED: 已处理 / IGNORED: 忽略

    resolution_action   VARCHAR(32),                  -- MERGE / DELETE_REDUNDANT / REWRITE / KEEP_ALL
    resolved_at         TIMESTAMPTZ,
    resolved_by         BIGINT,

    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    INDEX idx_cluster_status (cluster_status),
    INDEX idx_subject (subject_code)
);

COMMENT ON TABLE redundancy_cluster IS '冗余内容聚类表 - 相似内容批量处理';
```

#### 2.1.4 查重任务表 `dedup_scan_task`

管理全量扫描和增量查重任务。

```sql
CREATE TABLE dedup_scan_task (
    id              BIGSERIAL PRIMARY KEY,
    task_uid        VARCHAR(48) NOT NULL UNIQUE,
    task_type       VARCHAR(24) NOT NULL,       -- FULL_SCAN / INCREMENTAL / SUBJECT_SCAN / TARGETED

    -- 扫描范围
    scope_subject   VARCHAR(16),                -- 指定学科(NULL=全量)
    scope_type      VARCHAR(32),                -- 指定内容类型(NULL=全部)
    scope_ids       BIGINT[],                   -- 指定内容ID列表(TARGETED模式)

    -- 任务参数
    similarity_threshold DECIMAL(4,3) NOT NULL DEFAULT 0.750, -- 相似度阈值
    batch_size      INTEGER NOT NULL DEFAULT 500,

    -- 执行状态
    status          VARCHAR(20) NOT NULL DEFAULT 'PENDING',
    -- PENDING / RUNNING / COMPLETED / FAILED / CANCELLED

    total_count     INTEGER,                    -- 待扫描内容总数
    processed_count INTEGER DEFAULT 0,          -- 已处理数
    found_count     INTEGER DEFAULT 0,          -- 发现的相似对数
    cluster_count   INTEGER DEFAULT 0,          -- 生成的聚类数

    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    error_message   TEXT,

    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    INDEX idx_task_status (status),
    INDEX idx_task_type (task_type)
);

COMMENT ON TABLE dedup_scan_task IS '查重任务表 - 管理扫描任务';
```

#### 2.1.5 查重规则配置表 `dedup_rule_config`

```sql
CREATE TABLE dedup_rule_config (
    id              BIGSERIAL PRIMARY KEY,
    rule_name       VARCHAR(64) NOT NULL,
    rule_code       VARCHAR(32) NOT NULL UNIQUE,

    content_type    VARCHAR(32),                -- 适用内容类型(NULL=全部)
    subject_code    VARCHAR(16),                -- 适用学科(NULL=全部)

    -- 阈值配置
    semantic_threshold DECIMAL(4,3) DEFAULT 0.800,  -- 语义相似度阈值
    lexical_threshold   DECIMAL(4,3) DEFAULT 0.700, -- 词汇相似度阈值
    overall_threshold   DECIMAL(4,3) DEFAULT 0.750, -- 综合相似度阈值

    -- 权重配置
    semantic_weight DECIMAL(3,2) DEFAULT 0.50,  -- 语义相似度权重
    lexical_weight  DECIMAL(3,2) DEFAULT 0.30,  -- 词汇相似度权重
    structural_weight DECIMAL(3,2) DEFAULT 0.20,-- 结构相似度权重

    -- 处理策略
    auto_action     VARCHAR(32) DEFAULT 'FLAG', -- FLAG: 标记 / AUTO_MERGE: 自动合并 / BLOCK: 阻止入库
    min_content_length INTEGER DEFAULT 50,      -- 最小查重内容长度(跳过太短的内容)

    is_active       BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE dedup_rule_config IS '查重规则配置表 - 分内容类型/学科的查重阈值';
```

### 3.3 错误码定义（业务层）

| 错误码 | HTTP状态 | 说明 |
| --- | --- | --- |
| `DEDUP_001` | 400 | 内容文本过短，低于最小查重长度 |
| `DEDUP_002` | 400 | 不支持的内容类型 |
| `DEDUP_003` | 404 | 内容指纹未生成，需等待预处理 |
| `DEDUP_004` | 404 | 相似内容对不存在 |
| `DEDUP_005` | 409 | 重复创建扫描任务(同一范围已有运行中任务) |
| `DEDUP_006` | 409 | 相似内容对已审核，不可重复操作 |
| `DEDUP_007` | 422 | 聚类处理失败，内容已被删除或状态变更 |
| `DEDUP_008` | 500 | 向量检索服务不可用 |
| `DEDUP_009` | 500 | 嵌入服务调用超时 |
| `DEDUP_010` | 429 | 实时查重请求频率超限 |

> 完整全局错误码段见 §8。


### 4.2 内容指纹生成管线

```text
原始内容
  │
  ▼
[文本清洗] → 去除 HTML 标签、统一全角半角、规范化公式占位符、剔除首尾空白
  │
  ▼
[长度校验] ──文本过短(<min_length)──▶ 返回 DEDUP_001
  │
  ▼
[关键短语提取] ── TF-IDF / KeyBERT 提取 top-K 关键短语
  │
  ▼
[精确哈希] ── MD5(text_normalized) 生成 content_hash
  │
  ▼
[SimHash] ── 64 位局部敏感哈希，用于快速近重复检测
  │
  ▼
[MinHash] ── 128 个签名，用于估算 Jaccard 相似度
  │
  ▼
[Embedding] ── 调用 Embedding 服务生成 1024 维向量，写入 Milvus/pgvector
  │
  ▼
持久化 content_fingerprint 记录
```

**指纹生成算法参数：**

| 指纹类型 | 算法 | 维度/长度 | 用途 |
| --- | --- | --- | --- |
| 精确哈希 | MD5 | 128 bit (hex 32) | 完全重复检测 |
| 近重复哈希 | SimHash | 64 bit | 海明距离 ≤3 判定近重复 |
| 集合相似 | MinHash | 128 个 64 bit | Jaccard 相似度估算 |
| 语义向量 | Embedding | 1024 维 | 语义相似度 Top-K 召回 |

**归一化规则：**

1. 去除所有 HTML/Markdown 标记，保留纯文本。
2. 全角数字/字母/标点转半角。
3. 连续空白合并为单空格。
4. 数学公式 `$$...$$` 替换为统一占位符 `__FORMULA__`。
5. 不区分大小写（英文内容）。

### 4.3 相似性检测引擎

#### 4.3.1 检测分层策略

```text
┌────────────────────────────────────────────────────────────┐
│                    相似性检测分层                            │
├──────────────┬────────────────┬────────────────────────────┤
│ 层级          │ 方法            │ 阈值/策略                    │
├──────────────┼────────────────┼────────────────────────────┤
│ L1 精确去重   │ content_hash   │ MD5 完全一致 → 直接标记 DUPLICATE│
│ L2 近重复     │ SimHash 海明距离│ 海明距离 ≤ 3 → 进入词汇/语义复核│
│ L3 词汇相似   │ MinHash Jaccard │ Jaccard ≥ lexical_threshold   │
│ L4 语义召回   │ 向量 ANN Top-K   │ 余弦 ≥ semantic_threshold    │
│ L5 综合评分   │ 加权融合         │ overall ≥ overall_threshold  │
└──────────────┴────────────────┴────────────────────────────┘
```

#### 4.3.2 综合相似度公式

```
overall_similarity = w_sem * semantic_similarity
                   + w_lex * lexical_similarity
                   + w_str * structural_similarity

其中 w_sem + w_lex + w_str = 1
默认: w_sem=0.50, w_lex=0.30, w_str=0.20
```

**结构相似度计算：**

```
structural_similarity = 0.4 * paragraph_align_score
                      + 0.3 * heading_overlap_ratio
                      + 0.2 * formula_count_diff_ratio
                      + 0.1 * length_ratio
```

### 4.4 冗余聚类分析

#### 4.4.1 聚类方法

使用**无向图连通分量** + **DBSCAN 密度聚类**双层策略：

1. **粗聚类**：将 `overall_similarity ≥ 0.70` 的相似对构建图，求连通分量，得到候选簇。
2. **精聚类**：在每个连通分量内运行 DBSCAN（eps=0.15，minPts=2，距离=1 - overall_similarity），剔除弱关联边。
3. ** representative 推荐**：根据内容质量评分选择保留项。

**内容质量评分公式：**

```
quality_score = 0.35 * review_status_score(已审核=1, 草稿=0.6)
              + 0.25 * completeness_score(字段完整度)
              + 0.20 * usage_score(近30天曝光/使用次数归一)
              + 0.15 * freshness_score(创建时间越近越高，但不超过 1)
              + 0.05 * authority_score(官方来源=1, UGC=0.7)
```

### 4.5 净化工作流与合并语义

#### 4.5.1 操作类型

| 操作 | 语义 | 适用场景 |
| --- | --- | --- |
| MERGE | 将 discard 内容合并进 keep 内容，废弃 discard | 两条内容实质相同 |
| DELETE_REDUNDANT | 直接删除冗余内容，保留 representative | 多条内容中仅保留一条 |
| REWRITE | 标记需要人工改写，暂不删除 | 语义近似但各有价值 |
| KEEP_ALL | 确认非冗余，全部保留 | 误判或互补内容 |
| IGNORE | 聚级标记为忽略 | 短期不处理 |

#### 4.5.2 合并执行规则

1. **元数据合并**：将 discard 内容的 `knowledge_point_ids`、`grade_range`、`tags` 合并到 keep 内容，去重。
2. **引用重定向**：所有引用 discard 内容的位置（知识点关联、题目解析引用、推荐卡片）统一重定向到 keep 内容 ID。
3. **版本历史保留**：discard 内容进入 `DEPRECATED` 状态，保留历史记录，不物理删除（除用户明确要求外）。
4. **审计日志**：每次合并写 `dedup_resolution_log` 表，记录操作人、原因、合并字段。

```java
@Service
public class FingerprintService {

    private final EmbeddingClient embeddingClient;
    private final FingerprintRepository fingerprintRepository;
    private final VectorStoreClient vectorStoreClient;

    public Fingerprint generateFingerprint(Long contentId, ContentType type,
                                            String text, String subjectCode,
                                            List<Long> kpIds) {
        String normalized = TextNormalizer.normalize(text);
        if (normalized.length() < getMinLength(type)) {
            throw new DedupBizException(DedupErrorCode.TEXT_TOO_SHORT);
        }

        Fingerprint fp = new Fingerprint();
        fp.setContentId(contentId);
        fp.setContentType(type);
        fp.setContentHash(DigestUtils.md5Hex(normalized));
        fp.setSimhashValue(SimHash.compute(normalized));
        fp.setMinhashValues(MinHash.computeSignatures(normalized, 128));
        fp.setTextLength(normalized.length());
        fp.setKeyPhrases(KeyPhraseExtractor.extract(normalized, 20));

        // 调用 Embedding 服务生成向量
        EmbeddingVector vector = embeddingClient.embed(normalized, subjectCode);
        String embeddingId = vectorStoreClient.upsert(contentId, type.name(), subjectCode, vector);
        fp.setEmbeddingId(embeddingId);
        fp.setEmbeddingModel(vector.getModel());
        fp.setEmbeddingDim(vector.getDim());

        fingerprintRepository.save(fp);
        return fp;
    }
}
```

### 5.2 相似性检测服务

```java
@Service
public class SimilarityDetectionService {

    public SimilarityResult detect(Fingerprint source, Fingerprint target,
                                    DedupRuleConfig rule) {
        // L1 精确
        if (source.getContentHash().equals(target.getContentHash())) {
            return SimilarityResult.duplicate();
        }

        // L2 SimHash
        int hamming = SimHash.hammingDistance(source.getSimhashValue(), target.getSimhashValue());
        if (hamming > 3 && hamming < 8) {
            // 进入复核
        } else if (hamming <= 3) {
            // 强近重复信号，加权 lexical
        }

        double lexical = MinHash.jaccard(source.getMinhashValues(), target.getMinhashValues());
        double semantic = vectorStoreClient.cosineSimilarity(
            source.getEmbeddingId(), target.getEmbeddingId());
        double structural = structuralSimilarity(source, target);

        double overall = rule.getSemanticWeight() * semantic
                       + rule.getLexicalWeight() * lexical
                       + rule.getStructuralWeight() * structural;

        return SimilarityResult.builder()
            .overall(overall)
            .semantic(semantic)
            .lexical(lexical)
            .structural(structural)
            .verdict(verdict(overall, rule.getOverallThreshold()))
            .matchedSegments(alignSegments(source, target))
            .build();
    }
}
```

### 5.3 冗余聚类任务

```python
import networkx as nx
from sklearn.cluster import DBSCAN

def build_clusters(pairs, overall_threshold=0.75, dbscan_eps=0.15):
    G = nx.Graph()
    for p in pairs:
        if p.overall_similarity >= overall_threshold:
            G.add_edge(p.content_a_id, p.content_b_id,
                       weight=p.overall_similarity)

    clusters = []
    for component in nx.connected_components(G):
        sub = G.subgraph(component)
        nodes = list(sub.nodes)
        if len(nodes) <= 2:
            clusters.append(nodes)
            continue
        # distance matrix
        dists = [[1 - sub.edges.get((a,b), {'weight':0})['weight']
                  for b in nodes] for a in nodes]
        labels = DBSCAN(eps=dbscan_eps, min_samples=2, metric='precomputed').fit_predict(dists)
        # collect by label, -1 as singletons
        label_map = {}
        for node, label in zip(nodes, labels):
            label_map.setdefault(label, []).append(node)
        for label, members in label_map.items():
            if label == -1:
                for m in members:
                    clusters.append([m])
            else:
                clusters.append(members)
    return clusters
```

### 5.5 合并执行器

```java
@Service
public class MergeExecutor {

    @Transactional
    public MergeResult merge(Long pairId, Long keepId, Long discardId, Long operatorId, String reason) {
        Content keep = contentService.get(keepId);
        Content discard = contentService.get(discardId);

        // 1. 合并元数据
        keep.mergeMetadataFrom(discard);
        contentService.save(keep);

        // 2. 引用重定向
        referenceRedirectService.redirect(discardId, keepId);

        // 3. 废弃 discard
        discard.setStatus(ContentStatus.DEPRECATED);
        discard.setRedirectTo(keepId);
        contentService.save(discard);

        // 4. 更新 pair/cluster 状态
        pairService.resolve(pairId, RESOLVED_MERGE, operatorId, reason);

        // 5. 发布事件
        eventPublisher.publish(new ContentMergedEvent(keepId, discardId, operatorId, reason));

        return new MergeResult(keepId, discardId);
    }
}
```

### 6.1 查重任务状态机


| 向量检索服务不可用 | 仅使用 SimHash/MinHash 进行粗筛，语义召回跳过 | 精确重复检测不能降级 |
| 嵌入服务超时 | 返回低置信度结果，标记 `semanticConfidence=LOW` | 不能伪造相似度 |
| Redis 缓存不可用 | 直接读数据库，响应延迟增加 | 数据一致性不能丢 |
| 实时查重压力过大 | 批量/全量任务错峰，实时接口限流 429 | 内容发布管线的超时 fallback 需审计 |
| 内容发布查重超时 | 允许放行，但记录审计并异步补检 | 仅允许一次放行，不能静默跳过 |

## 10. 安全与合规

### 10.1 数据隐私

1. **PII 最小化**：指纹表不存储原文，仅存储哈希、向量引用和特征。
2. **向量隔离**：不同租户/学科使用同一集合，但通过 `subject_code` 过滤访问范围。
3. **审计留痕**：所有审核、合并、删除操作写入不可变审计日志，保留 3 年。

### 10.2 内容安全

1. 查重结果中不得泄露其他内容的完整原文，仅展示匹配片段（≤ 200 字）。
2. 废弃内容对外接口返回 `410 Gone` 或重定向到保留内容。
3. 合并操作需双人复核当涉及已上线/已购买内容。

### 10.3 未成年人保护

1. 废弃或合并的内容若出现在未成年人学习路径中，必须触发学习会话状态快照引擎的刷新事件，避免断点恢复指向失效内容。
2. 查重报告不对学生端暴露。

## 11. 与关联文档的契约对齐

| 文档 | 关键契约 |
| --- | --- |
| 题目相似度计算与智能去重服务 | 题库题目去重由该服务负责，本引擎不处理题目实体 |
| 教育内容审核工作流 | 查重出的 HIGH_SIMILARITY 内容可触发审核任务；审核结论回流到 pair_status |
| 内容与运营后台 | 后台调用本引擎 API 展示查重面板与操作入口 |
| 教育内容质量自动评估 | 质量评分公式中的 `review_status_score` 来自该服务 |
| 教育内容语义标签体系 | 查重时优先在相同 `knowledge_point_ids` 集合内召回 |
| 知识图谱 | 合并/废弃后需同步更新知识图谱中内容引用关系 |
| AI模型评测 | RLHF 训练数据去重需调用本引擎批量查重接口 |
| 多端数据同步 | 内容废弃后需向客户端推送 sync.invalidated 事件 |

| 编号 | 场景 | 预期结果 |
