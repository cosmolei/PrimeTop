# 管理后台 - 客户服务与工单管理工作台 详细设计

## 1. 概述

### 1.1 模块定位

客户服务与工单管理工作台是 PrimeTop 管理后台的核心运营支撑模块，为客服团队、运营主管和技术支持团队提供统一的工单处理、用户服务、FAQ管理和质量监控界面。

本工作台是对后端客服工单系统（`support-ticket-service`）、AI智能客服引擎、用户反馈系统和意见反馈与客服工单处理链路的前端编排层，将分散的服务端能力聚合为客服人员可直接操作的「服务生产线」。

### 1.2 设计目标

| 目标 | 说明 |
| --- | --- |
| 统一工作台 | 工单处理、用户查询、FAQ管理、SLA监控归入一个界面 |
| 高效处理 | 快捷回复模板、一键查询用户信息、智能推荐解决方案 |
| 全流程可控 | 工单从接入→分配→处理→回复→关闭全链路可视可控 |
| 质量可量化 | SLA达标率、满意度、处理效率实时统计 |
| 权限分离 | 客服专员→客服主管→运营经理 分级权限管控 |

### 1.3 适用范围

| 角色 | 使用场景 |
| --- | --- |
| 客服专员 | 接单、回复用户、查看用户信息、使用FAQ回复 |
| 客服主管 | 工单分配、SLA监控、质量抽检、团队管理 |
| 运营人员 | FAQ维护、分类管理、常见问题分析 |
| 技术支持 | 处理技术类工单、查看错误日志、排查问题 |
| 运营经理 | 整体服务数据分析、服务质量评估、人员绩效考核 |

### 1.4 依赖关系

```
本工作台（Web 前端）
    │
    ├── 客服与工单系统（工单 CRUD + 状态流转 + 分配）
    ├── AI智能客服对话与工单自动分流解决引擎（智能分发 + 自动回复）
    ├── 用户基础服务与身份认证系统（用户信息查询）
    ├── 意见反馈与客服工单处理链路（反馈升级为工单）
    ├── 支付服务与订单管理（关联订单查询）
    ├── 学习服务（学习数据查询）
    ├── 消息与推送服务（通知用户工单进度）
    ├── 统一通知消息模板引擎（通知模板配置）
    ├── 服务端审计日志与操作追溯系统（操作审计）
    └── 统一文件生成与异步报表导出中心服务（报表导出）
```

## 2. 页面架构与导航设计

### 2.1 一级导航

```
管理后台
  └── 客户服务
        ├── 工作台首页      (workspace)     ← 今日概览、待办、实时统计
        ├── 工单管理        (tickets)       ← 工单列表 + 详情 + 处理
        ├── 用户服务        (users)         ← 用户查询 + 服务记录
        ├── FAQ管理         (faq)           ← 知识库 + 快捷回复
        ├── 客服管理        (agents)        ← 客服人员 + 组 + 排班
        ├── SLA与质量       (quality)       ← SLA监控 + 质检 + 满意度
        └── 数据报表        (reports)       ← 工单统计 + 服务分析
```

### 2.2 页面路由

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/cs/workspace` | 工作台首页 | 实时数据看板、待处理工单、紧急提醒 |
| `/cs/tickets/list` | 工单列表 | 所有工单，支持多维筛选 |
| `/cs/tickets/:id/detail` | 工单详情 | 工单完整信息 + 处理操作 |
| `/cs/tickets/create` | 创建工单 | 后台手动创建工单 |
| `/cs/users/search` | 用户查询 | 按手机号/昵称/ID查询用户 |
| `/cs/users/:id/profile` | 用户服务档案 | 用户信息 + 工单历史 + 学习数据 |
| `/cs/faq/list` | FAQ列表 | 知识库文章管理 |
| `/cs/faq/categories` | FAQ分类 | 分类树管理 |
| `/cs/faq/quick-reply` | 快捷回复模板 | 模板管理 |
| `/cs/agents/list` | 客服列表 | 客服人员管理 |
| `/cs/agents/groups` | 客服组管理 | 组别 + 技能组 |
| `/cs/agents/schedule` | 排班管理 | 班次 + 假期 |
| `/cs/quality/sla` | SLA监控 | 实时SLA达标情况 |
| `/cs/quality/inspection` | 质量抽检 | 抽检任务 + 评分 |
| `/cs/quality/satisfaction` | 满意度分析 | 评价数据 + 趋势 |
| `/cs/reports/overview` | 服务报表 | 综合数据看板 |
| `/cs/reports/tickets` | 工单报表 | 工单量 + 分类 + 趋势 |
| `/cs/reports/performance` | 绩效报表 | 客服个人绩效数据 |

#### 4.2.2 操作按钮

| 操作 | 权限 | 说明 |
| --- | --- | --- |
| 接单 | 客服专员+ | 将工单分配给自己 |
| 回复 | 当前处理人 | 向用户发送回复消息 |
| 转派 | 客服专员+ | 转给其他客服或客服组 |
| 修改分类 | 客服专员+ | 修改一级/二级分类 |
| 修改优先级 | 客服主管+ | 调整优先级 |
| 添加标签 | 客服专员+ | 添加/移除标签 |
| 关联工单 | 客服专员+ | 关联重复或相关工单 |
| 挂起 | 当前处理人 | 等待用户提供更多信息 |
| 解决 | 当前处理人 | 标记为已解决 |
| 关闭 | 客服主管+ | 关闭工单 |
| 重新打开 | 客服主管+ | 重新打开已关闭工单 |
| 标记重复 | 客服专员+ | 标记为重复工单 |

### 4.2.4 工单操作 API 总表

所有写操作请求头需携带 `Idempotency-Key`（UUID，重试复用），服务端按 `(agent_id, path, key)` 幂等去重。

| 操作 | 方法与路径 | 前置状态 | 权限 | 服务端映射（工单系统 /api/v1/admin/support） |
| --- | --- | --- | --- | --- |
| 接单 | POST `/api/admin/cs/tickets/{id}/claim` | pending / assigned | 客服专员+ | `POST /tickets/{id}/claim` |
| 回复用户 | POST `/api/admin/cs/tickets/{id}/replies` | in_progress / waiting_user | 当前处理人 | `POST /tickets/{id}/replies`(visible_to_user=true) |
| 内部备注 | POST `/api/admin/cs/tickets/{id}/notes` | 任意活跃态 | 本组客服+ | `POST /tickets/{id}/replies`(is_internal=true，需服务端扩展) |
| 转派 | POST `/api/admin/cs/tickets/{id}/transfer` | pending / assigned / in_progress | 客服专员+（跨客服组需组长+） | `POST /tickets/{id}/transfer` |
| 挂起等用户 | POST `/api/admin/cs/tickets/{id}/wait-user` | in_progress | 当前处理人 | 状态流转 in_progress→waiting_user |
| 等待第三方 | POST `/api/admin/cs/tickets/{id}/wait-third-party` | in_progress | 当前处理人 | 状态流转 in_progress→waiting_third_party（暂停解决 SLA） |
| 恢复处理 | POST `/api/admin/cs/tickets/{id}/resume` | waiting_user / waiting_third_party | 当前处理人 | waiting_third_party→in_progress（恢复 SLA） |
| 解决 | POST `/api/admin/cs/tickets/{id}/resolve` | in_progress / waiting_user | 当前处理人 | `POST /tickets/{id}/resolve` |
| 关闭 | POST `/api/admin/cs/tickets/{id}/close` | resolved | 客服主管+ | `POST /tickets/{id}/close` |
| 重新打开 | POST `/api/admin/cs/tickets/{id}/reopen` | resolved / closed | 客服主管+ | resolved→in_progress（需服务端扩展 allowed_by） |
| 标记重复 | POST `/api/admin/cs/tickets/{id}/mark-duplicate` | 任意活跃态 | 客服专员+ | 新增接口（需服务端扩展） |
| 修改属性 | PATCH `/api/admin/cs/tickets/{id}/meta` | 任意未关闭态 | 分类/标签:专员+；优先级:主管+ | 新增接口（需服务端扩展） |
| 催办提醒 | POST `/api/admin/cs/tickets/{id}/remind` | waiting_user | 当前处理人 | 消息服务模板 `ticket_remind` |

**接单请求/响应示例：**

```json

// Headers: Idempotency-Key: 8f14e45f-ea0f-4c1a-9d2b-7c6a1e8d9001
```

**转派请求/响应示例：**


**解决请求/响应示例：**

```json
// POST /api/admin/cs/tickets/123456/resolve
{
  "resolutionNote": "核实订单符合7天无理由退款，已发起原路退款，退款单 RF-20260723-000045，承诺1-3个工作日到账。",
```

**重新打开 / 标记重复 / 修改属性示例：**


### 4.2.5 消息增量拉取与实时推送

**增量拉取（断线补偿）：**

```
GET /api/admin/cs/tickets/{ticketId}/messages?after_seq=3&direction=forward&limit=50
```

按 seq 单调递增返回，前端据此补偿 WebSocket 断线期间丢失的消息。

**WebSocket 工作台通道 `cs.workbench`：**

| 帧类型 | 方向 | 载荷 | 前端行为 |
| --- | --- | --- | --- |
| `hello` | C→S | token | 鉴权握手，返回订阅的组 ID 列表 |
| `ticket.created` | S→C | ticketId、categoryL1、priority | 组内新工单，列表置顶刷新 + 声音提示 |
| `ticket.assigned_to_me` | S→C | ticketId | 我的待办 +1，红点 |
| `ticket.user_replied` | S→C | ticketId、seq、预览(脱敏) | 打开中的详情页实时追加，其余计数 |
| `ticket.sla_warning` | S→C | ticketId、剩余分钟 | 告警区刷新 |
| `ticket.transferred_in` | S→C | ticketId、fromGroup | 组内转派入列刷新 |
| `ticket.state_changed` | S→C | ticketId、from、to | 列表/详情状态联动 |
| `ping/pong` | 双向 | ts | 30s 心跳，3 次未 pong 触发重连 |

断线重连采用指数退避（1s/2s/4s/8s/max 60s），重连成功后先执行 `after_seq` 增量补偿再恢复实时渲染；连续失败 5 分钟降级为 30s 轮询 `workspace/overview + my-tickets`，顶部显示「实时连接中断」横幅。

> 与《服务端-在线人工客服会话与坐席智能调度服务》的 `cc.agent` 通道边界：`cc.agent` 承载在线实时会话消息（同步低延迟），`cs.workbench` 承载工单事件（异步通知）。坐席同时开启两个通道，互不复用；在线会话 escalate 升级生成的工单经 `ticket.created` 帧进入工单队列，source=`chat`。

### 4.3 创建工单页

客服代用户创建工单（电话/邮件渠道进线时使用）。

**表单字段：**

| --- | --- | --- | --- |

**列表列：** 标题 / 分类 / 适用学段 / 状态(草稿·待审·已发布·已下线) / 版本号 / 匹配命中次数(近30天) / 更新人 / 更新时间 / 操作([编辑][提审][发布][下线][历史版本])。

**编辑器：** Markdown + 受限富文本（图片、加粗、有序列表；不支持外链脚本）；正文支持插入「适用学段」标记块，用户端按学段过滤展示；保存即存草稿并递增 version，提审生成快照供 diff。

**FAQ 状态机：**

```
 draft ──提交──> reviewing ──通过──> published ──下线──> offline
   ▲               │拒绝                    │重新编辑
   └───────────────┘                        └──> draft
```

| 守卫 | 规则 |
| --- | --- |
| F1 | 仅 faq_editor 及以上角色可提审/发布/下线；普通运营仅可编辑草稿 |
| F2 | published 状态下再编辑不直接影响线上，必须重走 reviewing |
| F3 | 下线需填写原因并二次确认；已下线文章在用户端搜索立即失效（缓存 TTL 5 分钟） |
| F4 | 删除仅限无命中记录的 draft；其余只能下线保留历史 |

```
POST /api/admin/cs/faq/articles                 # 新建草稿
PATCH /api/admin/cs/faq/articles/{id}           # 保存草稿(带 version 乐观锁)
POST /api/admin/cs/faq/articles/{id}/submit-review
POST /api/admin/cs/faq/articles/{id}/publish    # 审核(仅工作台首页待审队列入口)
POST /api/admin/cs/faq/articles/{id}/offline    # { "reason": "政策变更" }
GET  /api/admin/cs/faq/articles/{id}/versions   # 版本列表与 diff
```

用户端 FAQ 展示接口为工单系统 `/api/v1/support/faq/*`（已有），工作台仅维护数据；`matching` 命中统计由智能问答库引擎回写（见 §15 契约对齐）。

### 6.2 FAQ 分类树管理

两级树（对齐服务端 faq_categories），拖拽排序写 sort_order；删除守卫：存在文章或子分类时禁止删除（FAQ_HAS_CHILDREN / FAQ_HAS_ARTICLES）；重命名实时生效并同步用户端分类接口缓存。

```
GET   /api/admin/cs/faq/categories
POST  /api/admin/cs/faq/categories       { "name": "会员与订阅", "parentId": 0, "sortOrder": 1 }
PATCH /api/admin/cs/faq/categories/{id}
```

### 6.3 快捷回复模板管理

工单回复与内部备注的模板库，三级作用域：全局(global) / 客服组(group) / 个人(personal)，同 key 优先级 personal > group > global。

**表结构（新增，归属工单服务 schema）：**

```sql
CREATE TABLE cs_quick_reply_templates (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  scope         ENUM('global','group','personal') NOT NULL,
  owner_id      BIGINT NOT NULL DEFAULT 0 COMMENT 'group=组ID / personal=客服ID / global=0',

  UNIQUE KEY uk_scope_owner_title (scope, owner_id, title)
```

**变量占位符（发送前替换，未知变量留空不报错）：** `{user_nickname}` `{ticket_no}` `{order_no}` `{agent_name}` `{due_date}`。

```
GET   /api/admin/cs/quick-replies?scope=&category_l1=&keyword=
```

ReplyEditor 中输入 `/` 唤起 QuickReplyPalette，按当前工单分类 + 使用频次排序，插入后变量立即填充并可编辑；usage_count 异步累加（防抖 5s 批量上报）。

### 6.4 审核队列

## 8. SLA 与质量页面设计

### 8.1 SLA 监控页 `/cs/quality/sla`

**SLA 策略（对齐工单系统 SLA_POLICIES）：**

| 优先级 | 首次响应 | 解决时限 |
| --- | --- | --- |
| urgent | 15 分钟 | 2 小时 |
| high | 30 分钟 | 8 小时 |
| normal | 2 小时 | 24 小时 |
| low | 4 小时 | 48 小时 |

**时钟口径：** 响应时钟从 `assigned`（分配）启动、首次回复停止；解决时钟从创建启动、`resolved` 停止；`waiting_third_party` 期间解决时钟暂停，`waiting_user` 不暂停（等待用户是服务方可控之外的正常环节，但响应时钟已完成）。重新打开执行 restart_sla。

**页面结构：** ①总达标率两卡片（响应/解决，近 7 日 vs 上一周期）②组×优先级达标率热力图（点击下钻该格工单列表）③当前超时/即将超时(30 分钟内)实时列表（[接管] 一键转派给自己）④暂停中工单列表（waiting_third_party，显示暂停累计时长）。

```
GET /api/admin/cs/quality/sla/summary?date_from=&date_to=&group_id=
// 响应(节选): { "response": { "met": 1250, "total": 1300, "rate": 0.9615 }, "resolution": { "met": 1180, "total": 1300, "rate": 0.9077 }, "byGroup": [...] }
GET /api/admin/cs/quality/sla/breach?state=overdue|warning&page=
```

### 8.2 质量抽检工作台 `/cs/quality/inspection`

**抽样规则：** 每日按组从昨日 resolved 且含客服回复的工单中拖取 5%（每人每周最少 3 单）；QC 任务自动生成并轮派给质检员（不得抽检本人处理的工单）。

**评分量表（百分制）：**

| 维度 | 分值 | 评分要点 |
| --- | --- | --- |
| 响应及时性 | 15 | 首次响应与中间回复是否在承诺时效内 |
| 解决方案正确性 | 30 | 判断与处理结果是否正确（退款金额/操作步骤/结论） |
| 服务态度与表达 | 25 | 语气、适龄表达、无违规承诺 |
| 流程合规 | 20 | 分类/标签/转派/SLA 操作是否规范，敏感操作是否留痕 |
| 记录完整 | 10 | resolutionNote 质量、内部备注是否可追溯 |

**QC 任务状态机：** `pending → scored → (appealing →) final`。客服对评分有异议可在 3 天内提交申诉（附证据），质检员复核一次后终审；总分 <70 标记「需辅导」，生成辅导待办推送组长，连续两周 <70 升级主管。

```sql
CREATE TABLE cs_qc_tasks (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  ticket_id     BIGINT NOT NULL,
  inspector_id  BIGINT NOT NULL COMMENT '质检员(非原处理人)',
  agent_id      BIGINT NOT NULL COMMENT '被检客服',
  scores        JSON NOT NULL COMMENT '{"timeliness":12,"correctness":27,...}',
  total_score   TINYINT NOT NULL,
  status        ENUM('pending','scored','appealing','final') NOT NULL DEFAULT 'pending',
  appeal_reason VARCHAR(500) DEFAULT NULL,
  sampled_date  DATE NOT NULL,
  UNIQUE KEY uk_ticket_sample (ticket_id, sampled_date)
) COMMENT '工单质量抽检任务';
```

```
GET  /api/admin/cs/quality/inspection/tasks?inspector=me&status=
POST /api/admin/cs/quality/inspection/tasks/{id}/score
POST /api/admin/cs/quality/inspection/tasks/{id}/appeal   # 原处理人
```

### 8.3 满意度分析页 `/cs/quality/satisfaction`

评分分布(1-5 星)、均分趋势、评价率漏斗（已解决 → 邀请评价 → 已评价，各环节转化率）、低分(≤2)工单回溯列表（关联 QC 抽检加权：低分单 100% 抽检）。低分单自动打「低分待回访」标签并生成回访待办（3 日内），回访动作记录进工单 timeline。

```

```

## 10. 前端架构与关键组件

### 10.1 工程结构

复用《客户端-管理后台Web前端架构与开发规范》：React 18 + TypeScript + Ant Design，qiankun 微前端子应用 `cs-workbench`，独立发布不阻塞主后台；路由权限由主应用下发菜单 + 子应用内 `hasPerm(code)` 指令双校验（见 §11.1 权限码）。

### 10.2 状态管理与数据流

| 数据 | 策略 |
| --- | --- |
| 列表页（工单/用户/FAQ/报表） | server-state 缓存（staleTime 30s），筛选条件入 URL query 可分享/回退 |
| 工单详情 | store 三 slice：ticket(含 meta 乐观锁 version) / messages(seq 有序) / timeline；WS 帧直接 reduce 入 store |
| 乐观更新 | 仅「回复发送」本地先插入 pending 态消息，失败回滚并提示重试；其余写操作均等服务端确认 |
| 概览/告警 | workspace overview 30s 轮询 + WS 覆盖，页面隐藏时暂停轮询（visibilitychange） |

### 10.3 关键组件

| 组件 | 要点 |
| --- | --- |
| `<SlaCountdown dueAt paused>` | 以服务端时间戳为准的 delta 渲染（防本地时钟漂移）；paused 态灰显并累计暂停时长；<30min 黄 / 超时红闪烁 |
| `<TicketMessageList>` | 按 seq 排序；内部备注黄底+「仅内部可见」角标；>100 条启用虚拟滚动；新消息到达底部自动跟随，用户上滚则停止跟随并显示「回到最新」 |
| `<ReplyEditor>` | 字数计数(≤5000)；附件 10MB/20MB 白名单；`/` 唤起模板面板；发送前敏感词预检（调用敏感词引擎 scene=INTERNAL_NOTE，命中提示改写，不阻断保存为内部备注） |
| `<QuickReplyPalette>` | 按当前工单分类匹配 + usage_count 排序；预览回车插入，变量即时填充 |
| `<UserSidePanel>` | 右侧抽屉复用于工单详情/列表/搜索；明文查看按钮仅权限可见（§11.2） |
| `<BatchBar>` | 列表勾选后底部浮出，展示已选数与可用批量操作（按角色过滤） |

### 10.4 实时性与降级

WS 协议见 §4.2.5；重连指数退避；5 分钟不可达切 30s 轮询并顶部横幅；所有 WS 帧幂等（ticketId+seq 去重），刷新页面始终以 HTTP 快照为准、WS 仅增量。

### 10.5 性能预算

列表首屏 ≤1.5s；详情打开 ≤1s；回复发送 P95 ≤800ms；WS 帧到渲染 ≤500ms。超出预算项由前端性能监控上报（§14）。

| G4 | resolve 必须 resolutionNote ≥ 10 字 | 新增 |
| G5 | close 仅 resolved；批量关闭同 | 服务端 |
| G6 | 主管重开需 reopenReason；restart_sla 重启解决时钟；满意度邀请作废 | 需服务端扩展 allowed_by=supervisor |
| G7 | mark-duplicate 目标单必须存在、非本单、非重复链下游（防 A→B→A）；标记后本单自动 resolved(解决方案=重复) | 新增 |
| G8 | 优先级改 urgent 需主管二次确认；降级不限 | 新增 |
| G9 | waiting_third_party 超 72h 未恢复，每日提醒处理人并上报组长 | 新增（工作台定时扫描） |
| G10 | pending 30 天无活动自动 cancelled（不短信通知） | 对齐服务端 auto_cancel_stale_tickets |
| G11 | resolved 后 72h 用户未评价且未重开，自动关闭并计默认「未评价」 | 工作台可配置，默认 72h |

FAQ 状态机守卫 F1-F4 见 §6.1；QC 任务状态机 Q1-Q4（不得自检 / 申诉一次 / <70 触发辅导 / final 不可改）见 §8.2。

| 数字码 | 源码 | HTTP | 用户可见提示 |
| --- | --- | --- | --- |
| 54800 | TICKET_NOT_FOUND | 404 | 工单不存在或已删除 |
| 54801 | TICKET_ACCESS_DENIED | 403 | 无权访问该工单 |
| 54802 | TICKET_INVALID_STATUS | 409 | 工单状态已变化，请刷新后重试 |
| 54803 | TICKET_DUPLICATE | 409 | 疑似重复工单，已为您定位原单 |
| 54804 | REPLY_EMPTY / REPLY_TOO_LONG | 400 | 回复为空或超过 5000 字 |
| 54805 | ATTACHMENT_TOO_LARGE / TYPE_FORBIDDEN | 400 | 附件超限或类型不允许 |
| 54806 | TRANSFER_DENIED | 403 | 无权转派（跨组需组长） |
| 54807 | AGENT_HAS_OPEN_TICKETS | 409 | 该客服仍有在处理工单，需先转出 |
| 54808 | GROUP_HAS_OPEN_TICKETS | 409 | 该组存在未结工单，不可删除 |
| 54809 | FAQ_HAS_CHILDREN / FAQ_HAS_ARTICLES | 409 | 分类下仍有子分类或文章 |
| 54810 | DUPLICATE_VERSION | 409 | 内容已被他人修改，请刷新 |
| 54811 | QC_APPEAL_USED | 409 | 申诉机会已使用 |

| 54813 | EXPORT_TOO_LARGE | 400 | 导出超 10 万行，请缩小范围 |
| 54814 | RATE_LIMITED | 429 | 操作过于频繁，请稍后重试 |

**降级策略：**

| 故障 | 行为 |
| --- | --- |
| 工单服务不可达 | 只读缓存兜底(5 分钟快照) + 顶部「服务降级只读」横幅，写操作禁用并提示 |

| 用户/订单聚合接口部分失败 | 详情页对应卡片显示「暂不可用」骨架，其余正常 |

## 16. 验收场景

1. 客服专员登录，仅见工作台/工单/用户服务三菜单，无绩效报表入口。
2. 列表按「待分配 + 退款 + 最近 7 天」筛选，URL 同步筛选条件，刷新后保持。
3. 两名客服同时接单同一工单，后到者收到 54802 提示，列表状态自动刷新为他人处理中。
4. 回复插入快捷模板，{user_nickname}/{ticket_no} 变量正确填充，字数上限 5000 生效。
5. 内部备注发送后用户端不可见，工单状态不变，列表角标「仅内部可见」。
6. urgent 工单 15 分钟未回复，SlaCountdown 变红、WS sla_warning 帧到达、告警区出现可点击条目。
7. 跨组转派由专员发起被拒（54806）；组长发起成功后 SLA 剩余时长随单转移。
8. waiting_third_party 下解决时钟暂停显示；恢复后继续；72h 未恢复收到提醒并上报组长。
9. resolve 未填解决方案被拦（G4）；填写后用户收到满意度邀请，72h 未评价自动关闭（G11）。
10. 主管重开已解决工单需填原因，重启 SLA，原满意度邀请作废。
11. 标记重复工单 A→B 后，B 不能再标记为 A 的重复（G7 防环）。
12. 批量分配 50 单 least_load，部分成功结构正确，失败项可定位原因。
13. FAQ 发布流程：草稿→提审→首页待审卡片→通过发布；用户端 5 分钟内可搜到；下线后失效。
14. 无敏感权限的组长请求用户档案，接口不含明文手机号；主管提交原因审批后明文展示 15 秒并产生 CS_SENSITIVE_VIEW 审计。
15. QC 抽样不包含质检员本人处理单；申诉一次后终审不可改；总分 65 触发辅导待办。
16. WS 断开 5 分钟后自动切 30s 轮询并显示降级横幅；重连后 after_seq 补齐期间消息无重复。
17. 工单服务不可达时工作台进入只读模式，写按钮禁用，缓存数据可浏览。
18. 绩效报表：专员仅见本人；组长见本组；导出自动脱敏且审计记录导出行数。
