# 服务端 - 学生学科迷思概念检测与诊断纠偏引擎 详细设计

> 版本: v1.0 | 更新日期: 2026-06-17 | 状态: 初稿

## 1. 模块概述

### 1.1 功能定位

学生学科迷思概念检测与诊断纠偏引擎（Misconception Detection & Remediation Engine, MDR Engine）是 PrimeTop 智能学习体系中**认知诊断层**的核心组件。

它与已有的"错题聚类诊断""能力测评补强"模块有本质区别：

| 维度 | 错题聚类诊断 | 能力测评补强 | **迷思概念检测纠偏（本模块）** |
|------|-------------|-------------|-------------------------------|
| 核心问题 | 学生在哪儿频繁出错？ | 学生掌握到什么程度？ | **学生为什么这样错误地想？** |
| 诊断对象 | 错题模式与高频错点 | 知识点掌握度百分比 | **根深蒂固的错误认知结构** |
| 典型输出 | "分数运算聚类错误率 72%" | "分数加减法掌握度 45%" | **"学生在异分母加减中将分子加分子、分母加分母"** |
| 干预策略 | 推荐相似题练习 | 安排知识点复习+练习 | **认知冲突 → 概念重建 → 巩固验证** |
| 效果衡量 | 同类题正确率提升 | 掌握度达标 | 迷思消除、错误推理路径断裂 |

**核心理念**：学生做错题不一定是"没学会"，很可能是"学错了"——形成了系统性的错误心智模型。传统的"多练几道题"无法消除迷思概念，必须通过**认知冲突**和**概念重建**来纠正。

### 1.2 适用学段与学科

| 学段 | 覆盖学科 | 迷思概念库规模（初期目标） |
|------|----------|---------------------------|
| 小学 | 数学、英语、科学 | 数学 120+、英语 60+、科学 40+ |
| 初中 | 数学、物理、化学、生物、英语 | 数学 200+、物理 150+、化学 100+、生物 80+、英语 80+ |
| 高中 | 数学、物理、化学、生物、英语 | 数学 250+、物理 200+、化学 120+、生物 100+、英语 80+ |

> 语文、历史、地理、政治等文科学科的迷思概念以"常见理解偏差"形式纳入，不单独建库。

**数据依赖（输入）：**

### 1.4 设计目标

| 目标 | 指标 |
|------|------|
| 迷思识别准确率 | 对已标注的常见迷思，检测准确率 ≥ 85% |
| 检测时效 | 实时检测 < 500ms，批量诊断 < 5s/学生 |
| 迷思覆盖率 | 对学生已暴露的错误，能匹配到已知迷思概念的比例 ≥ 70% |

| 误报率 | 非迷思概念错误被误判为迷思概念的比例 < 10% |

## 2. 核心概念与领域模型

### 2.1 什么是迷思概念（Misconception）

**迷思概念**是指学生在学习过程中形成的、与科学共识或正确理解相矛盾的系统性错误认知。它具有以下特征：

1. **稳定性**：不是随机错误，而是学生持续使用同一种错误推理方式
2. **系统性**：错误回答遵循可预测的模式，有内在的逻辑一致性
3. **顽固性**：简单的"告诉正确答案"无法消除，需要认知冲突
4. **迁移性**：一个迷思概念会影响对多个相关知识点的理解

**典型示例：**

| 学科 | 知识点 | 迷思概念 | 典型错误表现 | 正确理解 |
|------|--------|----------|-------------|----------|
| 数学 | 异分母加减 | "分子加分子，分母加分母" | 1/2 + 1/3 = 2/5 | 需通分：3/6 + 2/6 = 5/6 |
| 物理 | 力与运动 | "力是维持运动的原因" | 认为匀速运动的物体一定受力 | 力是改变运动状态的原因 |
| 化学 | 化学平衡 | "平衡意味着反应停止" | 到达平衡后正逆反应停止 | 动态平衡，速率相等但不停 |
| 数学 | 负数运算 | "负号意味着更小" | 认为 -3 > -2 | 数轴上越靠左越小 |
| 物理 | 电路 | "电流被灯泡消耗了" | 灯泡后面的导线电流更小 | 串联电路电流处处相等 |
| 数学 | 概率 | "连续事件有记忆" | 抛硬币5次正面后下次更可能反面 | 每次独立事件概率不变 |
| 英语 | 时态 | "现在完成时=过去时" | "I have seen him yesterday" | 现在完成时不与明确过去时间连用 |

### 2.2 迷思概念分类体系

```
MisconceptionType
├── CONCEPTUAL_ERRORS           // 概念性错误：对核心概念的理解有偏差
│   ├── DEFINITION_CONFUSION        // 定义混淆
│   ├── PRINCIPLE_MISUNDERSTANDING   // 原理误解
│   └── PROPERTY_MISATTRIBUTION      // 属性误归
├── PROCEDURAL_ERRORS           // 程序性错误：操作步骤/流程有系统性错误
│   ├── ALGORITHM_MISAPPLICATION     // 算法误用
│   ├── SEQUENCE_VIOLATION           // 步骤顺序错误
│   └── RULE_OVERGENERALIZATION      // 规则过度泛化
├── PRECONCEPTION               // 前概念/直觉偏差：日常经验导致的错误直觉
│   ├── INTUITIVE_PHYSICS            // 物理直觉偏差
│   ├── INTUITIVE_MATH               // 数学直觉偏差
│   └── LINGUISTIC_INTERFERENCE      // 语言干扰
├── TRANSFER_ERRORS             // 迁移错误：将一个领域的规则错误套用到另一领域
│   ├── CROSS_DOMAIN_MISAPPLICATION
│   └── PRIOR_KNOWLEDGE_INTERFERENCE
└── REPRESENTATION_ERRORS       // 表征错误：对图表、公式、模型的解读有偏差
    ├── NOTATION_MISREADING
    ├── GRAPH_MISINTERPRETATION
    └── SYMBOL_CONFUSION
```

### 2.3 检测信号来源

引擎通过多种信号渠道检测迷思概念：

| 信号来源 | 数据内容 | 可检测的迷思类型 | 可靠度 |
|----------|---------|-----------------|--------|
| 选择题答案模式 | 特定干扰项选择频率 | 概念性错误、程序性错误 | ★★★★★ |
| 填空题答案 | 特定错误填入内容 | 概念性错误、表征错误 | ★★★★☆ |
| 答题过程轨迹 | 答案修改轨迹、选项犹豫时间 | 程序性错误、直觉偏差 | ★★★☆☆ |
| AI对话中的自由文本 | 学生的解释和推理过程 | 所有类型 | ★★★★☆ |
| 诊断性测评 | 专门设计的迷思检测题 | 所有类型 | ★★★★★ |
| 解题步骤分步数据 | 中间步骤的特定错误 | 程序性错误 | ★★★★☆ |

## 3. 数据库设计

### 3.1 PostgreSQL 表结构

#### 3.1.1 迷思概念目录表

```sql
CREATE TABLE misconception_catalogue (
    id                  VARCHAR(36)   PRIMARY KEY DEFAULT gen_random_uuid()::varchar,
    code                VARCHAR(64)   NOT NULL UNIQUE,
    title               VARCHAR(200)  NOT NULL,
    type                VARCHAR(50)   NOT NULL,
    sub_type            VARCHAR(50),                       -- 子类型
    subject             VARCHAR(20)   NOT NULL,
    grade_range         INT4RANGE     NOT NULL,

    description         TEXT          NOT NULL,
    wrong_reasoning     TEXT          NOT NULL,             -- 错误推理过程描述
    correct_reasoning   TEXT          NOT NULL,             -- 正确推理过程描述
    common_scenario     TEXT,                                -- 常见出错场景

    severity            VARCHAR(20)   NOT NULL DEFAULT 'MEDIUM',
    status              VARCHAR(20)   NOT NULL DEFAULT 'DRAFT',
    tags                TEXT[]        DEFAULT '{}',

    prerequisite_kp_ids TEXT[]        DEFAULT '{}',
    impact_kp_ids       TEXT[]        DEFAULT '{}',
    related_misconception_ids TEXT[]  DEFAULT '{}',

    detection_config    JSONB         NOT NULL DEFAULT '{}',
    remediation_config  JSONB         NOT NULL DEFAULT '{}',

    created_by          VARCHAR(36),
    reviewed_by         VARCHAR(36),
    created_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    published_at        TIMESTAMPTZ,

    CONSTRAINT chk_miscon_type CHECK (type IN (
        'CONCEPTUAL_ERRORS', 'PROCEDURAL_ERRORS', 'PRECONCEPTION',
        'TRANSFER_ERRORS', 'REPRESENTATION_ERRORS'
    )),
    CONSTRAINT chk_miscon_severity CHECK (severity IN ('LOW','MEDIUM','HIGH','CRITICAL')),
    CONSTRAINT chk_miscon_status CHECK (status IN ('DRAFT','REVIEWING','ACTIVE','ARCHIVED'))
);

CREATE INDEX idx_miscon_subject_grade ON misconception_catalogue (subject, grade_range);
CREATE INDEX idx_miscon_active ON misconception_catalogue (status) WHERE status = 'ACTIVE';
CREATE INDEX idx_miscon_tags ON misconception_catalogue USING GIN (tags);
CREATE INDEX idx_miscon_kp_ids ON misconception_catalogue USING GIN (impact_kp_ids);
```

## 4. 迷思概念检测引擎

### 4.1 检测流水线架构

```
答题事件 / AI对话事件 / 诊断测评事件
            │
            ▼
    ┌───────────────┐
    │  事件预处理    │  ← 过滤、标准化、补充上下文
    └───────┬───────┘
            │
            ▼
    ┌───────────────┐
    │ 候选迷思检索   │  ← 根据学科+知识点+年级快速检索可能匹配的迷思
    └───────┬───────┘
            │ candidate misconceptions (通常 3~15 个)
            ▼
    ┌───────────────┐
    │ 多模式匹配    │  ← 对每个候选迷思执行模式匹配
    │               │     - 答案模式匹配
    │               │     - 行为轨迹匹配
    │               │     - 文本关键词匹配
    └───────┬───────┘
            │ match results with scores
            ▼
    ┌───────────────┐
```

### 4.3 多模式匹配引擎

#### 4.3.1 答案模式匹配器（AnswerPatternMatcher）

**适用场景**：选择题、填空题的答案直接匹配。

```java
public class AnswerPatternMatcher implements PatternMatcher {

    /**
     * 匹配逻辑：
     * 1. EXACT_ANSWER: 判断学生答案是否等于迷思预期的错误答案
     * 2. ANSWER_SET: 判断学生选择的是否为带特定标签的干扰项
     */
    @Override
    public MatchResult match(AnswerEvent event, DetectionPattern pattern) {
        PatternConfig config = pattern.getPatternConfig();

        return switch (config.getPatternType()) {
            case EXACT_ANSWER -> matchExactAnswer(event, config);
            case ANSWER_SET  -> matchAnswerSet(event, config);
            default -> MatchResult.noMatch();
        };
    }

    private MatchResult matchExactAnswer(AnswerEvent event, PatternConfig config) {
        // 对于填空题：检查答案是否匹配迷思预期错误
        if (event.getQuestionType() == QuestionType.FILL_BLANK) {
            String studentAnswer = event.getStudentAnswer().trim();
            String expectedWrong = config.getExpectedWrongAnswer();

            // 数学公式类题目使用公式等价判断
            if (config.hasFormulaCheck()) {
                boolean isEquivalent = FormulaComparator.isEquivalent(
                    studentAnswer,
                    expectedWrong,
                    FormulaComparator.Options.strict()
                );
                return isEquivalent
                    ? MatchResult.match(pattern.getMatchScore(), "公式等价匹配")
                    : MatchResult.noMatch();
            }

            // 文本类直接比较
            boolean match = studentAnswer.equalsIgnoreCase(expectedWrong);
            return match
                ? MatchResult.match(pattern.getMinConfidence(), "精确答案匹配")
                : MatchResult.noMatch();
        }

        // 对于选择题：检查选项是否为迷思干扰项
        if (event.getQuestionType() == QuestionType.CHOICE) {
            String selectedOption = event.getSelectedOptionId();
            List<String> distractorOptions = config.getDistractorOptionIds();

            boolean match = distractorOptions.contains(selectedOption);
            return match
                ? MatchResult.match(pattern.getMinConfidence(), "干扰项选择匹配")
                : MatchResult.noMatch();
        }

        return MatchResult.noMatch();
    }
}
```

#### 4.3.2 行为轨迹匹配器（BehavioralTraceMatcher）

**适用场景**：利用答题过程数据（犹豫时间、修改轨迹等）增强检测。

```java
public class BehavioralTraceMatcher implements PatternMatcher {

    @Override
    public MatchResult match(AnswerEvent event, DetectionPattern pattern) {
        PatternConfig config = pattern.getPatternConfig();
        AnswerTrace trace = event.getAnswerTrace();

        if (trace == null) {
            return MatchResult.noMatch();
        }

        double score = 0.0;
        List<String> signals = new ArrayList<>();

        // 信号1: 犹豫时间（超过阈值表明不确定）
        if (config.getHesitationMsMin() != null) {
            long hesitation = trace.getTimeToFirstActionMs();
            if (hesitation >= config.getHesitationMsMin()) {
                score += 0.15;
                signals.add("犹豫时间" + hesitation + "ms");
            }
        }

        // 信号2: 修改轨迹（先选干扰项又改回）
        if (config.hasInitialChoiceTag()) {
            List<ChoiceChange> changes = trace.getChoiceChangeHistory();
            boolean initiallyChoseDistractor = changes.stream()
                .filter(c -> c.getChangeType() == "SELECT")
                .map(ChoiceChange::getOptionTag)
                .anyMatch(config.getInitialChoiceTag()::equals);
            if (initiallyChoseDistractor) {
                score += 0.2;
                signals.add("初始选择了迷思干扰项");
            }
        }

        // 信号3: 最终答案错误
        if (!event.isCorrect() && score > 0) {
            score += 0.1;
            signals.add("最终答案错误");
        }

        return score >= config.getThreshold()
            ? MatchResult.match(Math.min(score, 0.95), String.join(", ", signals))
            : MatchResult.noMatch();
    }
}
```

#### 4.3.3 文本关键词匹配器（TextKeywordMatcher）

**适用场景**：分析学生在AI对话中的自由文本回答、解题过程描述。

```java
public class TextKeywordMatcher implements PatternMatcher {

    /**
     * 基于 NLP 分析学生的自由文本，检测迷思概念的语言信号。
     * 使用轻量级 BERT 分词 + 关键词匹配 + 语义相似度。
     */
    @Override
    public MatchResult match(AnswerEvent event, DetectionPattern pattern) {
        String text = event.getFreeTextAnswer();
        if (text == null || text.length() < 5) {
            return MatchResult.noMatch();
        }

        PatternConfig config = pattern.getPatternConfig();
        double maxScore = 0.0;
        String bestSignal = "";

        // 关键词直接匹配
        for (String keyword : config.getKeywords()) {
            if (text.contains(keyword)) {
                double s = config.getKeywordWeight(keyword);
                if (s > maxScore) {
                    maxScore = s;
                    bestSignal = "关键词匹配: " + keyword;
                }
            }
        }

        // 语义相似度匹配（对于AI对话场景）
        if (config.hasSemanticPatterns()) {
            double sim = SemanticSimilarityCalculator.compute(
                text,
                config.getSemanticPatterns(),
                SemanticModel.LIGHT_BERT
            );
            if (sim > config.getSemanticThreshold()) {
                double combined = Math.min(maxScore + sim * 0.3, 0.9);
                if (combined > maxScore) {
                    maxScore = combined;
                    bestSignal += String.format("; 语义相似度: %.2f", sim);
                }
            }
        }

        return maxScore >= pattern.getMinConfidence()
            ? MatchResult.match(maxScore, bestSignal)
            : MatchResult.noMatch();
    }
}
```

### 4.4 置信度融合算法

当多个匹配器对同一个迷思概念产生信号时，使用加权Dempster-Shafer证据理论融合置信度：

```java
public class ConfidenceFusion {

    /**
     * 多信号融合策略：
     * 1. 同一事件内多模式 → 加权求和（上限0.95）
     * 2. 跨事件累积 → 指数衰减加权（近期事件权重更高）
     * 3. 时序一致性 bonus → 多次检测到同一迷思给予额外置信度
     */
    public static double fuse(List<MatchResult> results, FusionContext ctx) {
        // Step 1: 单事件内融合
        double eventScore = fuseWithinEvent(results);

        // Step 2: 跨事件历史融合
        double historicalScore = fuseWithHistory(ctx.getStudentId(),
            ctx.getMisconceptionId(), ctx.getRecentWindowDays());

        // Step 3: 融合
        double fused = eventScore * 0.6 + historicalScore * 0.4;

        // Step 4: 时序一致性加成
        int detectionCount = ctx.getRecentDetectionCount();
        if (detectionCount >= 3) {
            fused += 0.1 * Math.min(detectionCount - 2, 3); // 最多+0.3
        }

        return Math.min(fused, 0.99);
    }

    private static double fuseWithinEvent(List<MatchResult> results) {
        // 取各匹配器得分，按预设权重加权
        double weightedSum = 0;
        double totalWeight = 0;
        for (MatchResult r : results) {
            weightedSum += r.getScore() * r.getMatcherWeight();
            totalWeight += r.getMatcherWeight();
        }
        return totalWeight > 0 ? Math.min(weightedSum / totalWeight + 0.15, 0.95) : 0;
    }

    private static double fuseWithHistory(String studentId, String misconId, int windowDays) {
        // 查询近 N 天的检测证据，按时间衰减加权
        List<DetectionEvidence> history = evidenceRepository
            .findByStudentAndMiscon(studentId, misconId, windowDays);

        if (history.isEmpty()) return 0;

        double weightedSum = 0;
        double totalWeight = 0;
        for (DetectionEvidence ev : history) {
            double ageDays = ChronoUnit.DAYS.between(
                ev.getDetectedAt().toLocalDate(), LocalDate.now());
            double weight = Math.exp(-0.1 * ageDays); // 指数衰减
            weightedSum += ev.getMatchScore() * weight;
            totalWeight += weight;
        }
        return totalWeight > 0 ? weightedSum / totalWeight : 0;
    }
}
```

### 5.1 纠偏学习路径设计

|----------|---------|----------|

### 5.3 纠偏步骤执行器

```java
public class RemediationStepExecutor {

    /**
     * 执行单步纠偏，返回步骤结果
     */
    public StepResult execute(RemediationStep step, StudentContext ctx) {
        return switch (step.getStepType()) {
            case COGNITIVE_CONFLICT   -> executeConflict(step, ctx);
            case CONCEPT_REBUILD      -> executeRebuild(step, ctx);
            case GUIDED_PRACTICE      -> executeGuidedPractice(step, ctx);
            case INDEPENDENT_PRACTICE -> executeIndependentPractice(step, ctx);
            case TRANSFER_TEST        -> executeTransferTest(step, ctx);
            case REVIEW               -> executeReview(step, ctx);
        };
    }

    /**
     * 认知冲突步骤：呈现冲突情境 → 学生判断 → 揭示矛盾
     */
    private StepResult executeConflict(RemediationStep step, StudentContext ctx) {
        ConflictContent content = contentService.load(step.getContentRef());

        // 通过AI辅导对话引擎呈现认知冲突内容
        // 使用专门的 Prompt 模板：misconception_cognitive_conflict
        AIConversationSession session = aiDialogEngine.createSession(
            ctx.getStudentId(),
            SceneType.MISCONCEPTION_REMEDIATION,
            Map.of(
                "misconception_id", ctx.getMisconceptionId(),
                "conflict_content", content,
                "student_grade", ctx.getGrade(),
                "strategy", "COGNITIVE_CONFLICT"
            )
        );

        // 监控学生的冲突响应
        ConflictResponse response = monitorConflictResponse(session, content);

        // 判定是否成功引发认知冲突
        boolean conflictTriggered = response.indicatesCognitiveDissonance();

        return StepResult.builder()
            .stepId(step.getId())
            .status(conflictTriggered ? StepStatus.COMPLETED : StepStatus.IN_PROGRESS)
            .score(conflictTriggered ? 0.8 : 0.3)
            .metadata(Map.of(
                "conflict_triggered", conflictTriggered,
                "student_response", response.getSummary(),
                "session_id", session.getId()
            ))
            .build();
    }

    /**
     * 迁移检测步骤：测试学生是否能在新情境中正确应用概念
     */
    private StepResult executeTransferTest(RemediationStep step, StudentContext ctx) {
        // 从题库中选取与迷思相关但情境不同的题目
        List<Question> transferQuestions = questionService.selectByCriteria(
            QuestionQuery.builder()
                .knowledgePointIds(step.getRelatedKpIds())
                .questionType(QuestionType.CHOICE)
                .excludeSourceExam(true)  // 排除学生做过的题
                .limit(step.getQuestionCount())
                .build()
        );

        // 生成专项测试会话
        PracticeSession session = practiceService.createSession(
            ctx.getStudentId(),
            SessionType.TRANSFER_TEST,
            transferQuestions
        );

        // 等待完成并评判
        PracticeResult result = practiceService.waitForCompletion(
            session.getId(),
            Duration.ofMinutes(step.getEstimatedMinutes())
        );

        double accuracy = result.getCorrectRate();
        boolean passed = accuracy >= step.getPassThreshold();

        return StepResult.builder()
            .stepId(step.getId())
            .status(passed ? StepStatus.COMPLETED : StepStatus.IN_PROGRESS)
            .score(accuracy)
            .metadata(Map.of(
                "accuracy", accuracy,
                "threshold", step.getPassThreshold(),
                "needs_retry", !passed
            ))
            .build();
    }
}
```

```java
public class RemediationEffectivenessEvaluator {

    /**
     * 评估纠偏效果：对比纠偏前后的答题表现
     */
    public EffectivenessReport evaluate(String studentId, String misconceptionId) {
        // 获取纠偏完成时间
        StudentMisconception sm = repository.find(studentId, misconceptionId);
        Instant resolvedAt = sm.getResolvedAt();

        // 对比窗口：纠偏前14天 vs 纠偏后14天
        AnswerStats before = answerStatsService.getStats(
            studentId,
            sm.getRelatedKpIds(),
            resolvedAt.minus(14, ChronoUnit.DAYS),
            resolvedAt
        );

            studentId,
            sm.getRelatedKpIds(),
            resolvedAt,
            resolvedAt.plus(14, ChronoUnit.DAYS)
        );

        // 计算改善指标
        double accuracyImprovement = after.getAccuracy() - before.getAccuracy();
        double errorRecurrenceRate = after.getMistakeRate();
        boolean specificErrorEliminated = !after.hasErrorPattern(
            sm.getDetectionPatternSignature()
        );

        // 效果评分
        double score = calculateEffectivenessScore(
            accuracyImprovement, errorRecurrenceRate, specificErrorEliminated
        );

        return EffectivenessReport.builder()
            .studentId(studentId)
            .misconceptionId(misconceptionId)
            .beforeStats(before)
            .afterStats(after)
            .accuracyImprovement(accuracyImprovement)
            .errorEliminated(specificErrorEliminated)
            .effectivenessScore(score)
            .recommendation(score >= 0.6 ? "RESOLVED_CONFIRMED" : "NEEDS_REINFORCEMENT")
            .build();
    }
```

## 8. 错误处理与边界情况

### 8.1 错误码定义

| 错误码 | HTTP | 含义 | 处理建议 |
|--------|------|------|----------|
| MISCON_001 | 404 | 迷思概念不存在 | 检查ID或code |
| MISCON_002 | 409 | 学生已存在该迷思记录 | 使用更新接口 |
| MISCON_003 | 422 | 检测模式配置无效 | 检查pattern_config格式 |
| MISCON_004 | 409 | 当前状态不允许该操作 | 检查状态流转规则 |
| MISCON_005 | 422 | 纠偏策略不适用当前迷思类型 | 检查strategy与type的匹配关系 |
| MISCON_006 | 403 | 无权限访问该学生数据 | 检查家长绑定关系 |
| MISCON_007 | 429 | 检测请求过于频繁 | 限流，每学生每分钟最多30次 |

### 8.2 边界情况处理

| 场景 | 处理策略 |
|------|----------|
| 学生年级跨度过大（如跳级） | 按实际年级检索迷思库，不按年龄 |
| 同一知识点多个迷思同时检测到 | 按置信度排序，取Top-3创建记录 |
| 迷思概念库覆盖不足（未匹配） | 记录为UNCLASSIFIED_ERROR，定期供教研分析 |
| 纠偏中途学生升入新学段 | 保留当前纠偏进度，补充新学段的相关迷思检测 |
| 纠偏完成但未通过迁移测试 | 标记为NEEDS_REINFORCEMENT，生成补充练习 |
| AI分析服务不可用 | 降级为纯模式匹配，跳过文本语义分析 |
| 大量历史数据首次导入 | 使用批量诊断API，分页处理，每批100学生 |

### 8.3 降级策略

```java
public class MisconceptionDetectionService {

    /**
     * 检测降级链：
     * 1. 正常模式：多模式匹配 + AI语义分析 + 历史融合
     * 2. 降级模式1：AI不可用 → 仅规则模式匹配 + 历史融合
     * 3. 降级模式2：历史数据不可用 → 仅当前事件实时匹配
     * 4. 降级模式3：Redis不可用 → 直查DB，跳过缓存层
     */
    public DetectionResult detect(AnswerEvent event) {
        try {
            return fullDetectionPipeline(event);
        } catch (AIServiceUnavailableException e) {
            log.warn("AI服务不可用，降级为纯规则匹配");
            return ruleBasedDetectionOnly(event);
        } catch (DataStoreException e) {
            log.warn("存储异常，降级为实时单次检测");
            return realtimeDetectionOnly(event);
        }
    }
}
```
