## 1. 模块概述

### 1.1 定位

本规范解决"**一个请求/任务内部，代码到底在哪类执行资源上运行**"的问题。服务端采用 FastAPI（asyncio 事件循环）+ SQLAlchemy + Celery 的组合后，存在四类进程内/进程间执行资源：

1. **事件循环（asyncio Task）**：HTTP Handler、AI 流式输出、WebSocket/SSE 推送；
2. **进程内线程池（ThreadPoolExecutor）**：阻塞型 SDK 调用（部分 OCR/语音厂商 SDK、老版本数据库驱动）、并行扇出 IO；
3. **进程内进程池（ProcessPoolExecutor）**：CPU 密集型计算（LaTeX 渲染、图像预处理、符号计算）；
4. **进程外任务（Celery / DAG 编排）**：长耗时、可重试、跨请求的后台作业。

已有文档分别覆盖了上下文透传（《请求上下文传递》§12.4）、停机排空（《优雅停机》）、跨服务编排（《DAG 编排引擎》），但**缺少对进程内执行资源（2/3 类）与 asyncio 后台任务（1 类的非请求部分）的统一注册、隔离、背压、监控与治理规范**。各业务模块若自行 `ThreadPoolExecutor()` / `asyncio.create_task()`，会导致：匿名池无法容量规划、故障域互相传染、队列无上限引发内存膨胀、孤儿任务泄漏、停机时任务丢失。

本规范提供：

- 统一的**执行资源注册中心**（池清单、容量配置、命名规则）；
- 统一的**编程接口**（`run_in_pool` / `@blocking_call` / `spawn_background_task`），禁止业务代码直接创建裸池/裸任务；
- **背压与拒绝策略**（队列上限、失败快速返回、降级衔接）；
- **任务状态机**（提交→排队→运行→终态）与**停机 drain 顺序**；
- **监控指标与告警**、静态检查与代码评审清单。

### 1.2 设计目标

| 目标 | 度量 |
| --- | --- |
| 事件循环不被阻塞 | Handler 线程内单次阻塞调用 ≥10ms 必须走池；P99 事件循环滞后（loop lag）< 50ms |
| 故障隔离 | 任一业务域池打满，不影响其他域（池间零共享） |
| 有界队列 | 所有池队列长度有上限，内存占用可预估 |
| 可观测 | 每个池的排队数/在跑数/拒绝数/耗时均有 Prometheus 指标 |
| 可停机 | 停机时按优先级 drain，进行中任务要么完成要么显式放弃并记录 |
| 上下文不丢 | 跨池/跨任务自动透传 RequestContext 与 trace_id |

### 1.3 不做什么（边界）

- **不做**跨进程任务调度（由 Celery /《DAG 编排引擎》负责），本规范只管"请求内"与"轻量后台"执行资源；
- **不做**业务级重试语义（幂等与重试遵循《接口幂等性与防重提交机制》）；本规范只提供超时与取消原语；
- **不做**限流决策（入口限流遵循《统一限流熔断与流量防护体系》），池背压是限流之后的**第二道防线**。

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| 执行域（Executor Domain） | 按故障隔离边界划分的业务域池，如 `db_blocking`、`ocr_sdk` |
| ManagedExecutor | 经注册中心创建、带指标/上下文透传/拒绝策略的受管线程池或进程池 |
| BackgroundTask | 在事件循环上运行、但不属于任何请求生命周期的 asyncio 任务（如缓存预热） |
| 孤儿任务（Orphan Task） | 创建后失去强引用、无法被停机等待或统计的 asyncio 任务 |
| 放弃等待（Abandon） | 线程任务超时后调用方不再等待结果，但线程继续跑完并记录终态的语义 |
| Loop Lag | 事件循环单次调度延迟，衡量事件循环被阻塞程度 |

## 3. 整体架构

### 3.1 执行资源分层

```text
                        ┌────────────────────────────────────────────┐
 HTTP/SSE/WS 请求 ──▶   │  事件循环（asyncio）                          │
                        │  Handler / AI流式 / 推送                     │
                        └───────┬───────────────┬────────────────────┘
                                │ run_in_pool   │ spawn_background_task
                                ▼               ▼
 ┌─────────────────────────────────────┐   ┌──────────────────────────┐
 │ 执行资源注册中心 ExecutorRegistry     │   │ BackgroundTaskRegistry   │
 │  ├ db_blocking   (线程池)            │   │  (命名任务表/强引用/停机)  │
 │  ├ ocr_sdk       (线程池)            │   └──────────────────────────┘
 │  ├ asr_tts_sdk   (线程池)            │
 │  ├ media_io      (线程池)            │   统一能力：
 │  ├ cpu_render    (进程池)            │   · RequestContext 透传
 │  └ ...           (按需注册)          │   · trace_id 注入日志
 └─────────────────────────────────────┘   · Prometheus 指标
        ▲                                  · 拒绝策略 → EXEC 错误码
        │ 超过 30s 或需重试/跨请求
        └──▶ Celery / DAG 编排引擎（进程外，本规范范围之外）
```

### 3.2 执行资源选型决策

开发新增一段逻辑时按以下顺序决策：

| 判断条件 | 选择 | 说明 |
| --- | --- | --- |
| 纯 async 库（httpx.AsyncClient、asyncpg、redis.asyncio） | 直接 `await` | 不占线程，首选 |
| 同步但 IO 型、单次 < 30s（厂商同步 SDK、boto3 等） | `run_in_pool("<域池>")` | 线程池 |
| CPU 密集、单次 < 30s（LaTeX 渲染、图像处理、sympy） | `run_in_pool("cpu_render")` | 进程池，避开 GIL |
| 单次 ≥ 30s，或需要重试/进度/跨请求可见 | Celery 任务 / DAG 节点 | 见《DAG 编排引擎》 |
| 事件循环上的周期性/触发型轻量任务（< 5s） | `spawn_background_task` | 本规范 §6 |
| 需要定时触发 | 统一延迟任务调度引擎 / 定时任务框架 | 不在本规范内 |

> 经验阈值：同步 IO 调用预估 P99 ≥ 10ms 就不允许出现在 Handler 协程里；CPU 计算预估 ≥ 5ms 不允许出现在事件循环里。

### 3.3 与既有组件的关系

| 既有组件 | 关系 |
| --- | --- |
| `ContextAwareExecutor`（《请求上下文传递》§12.4） | `ManagedExecutor` 继承它，复用上下文透传，追加指标/拒绝/停机能力 |
| `ShutdownManager`（《优雅停机》） | 注册中心在启动时注册 drain 回调，按池优先级排空 |
| 统一异常码体系 | 新增 `EXEC_xxx` 段位（见 §9） |
| Prometheus（《日志与监控告警体系》） | 指标命名 `executor_*` / `background_task_*`，与停机指标同风格 |
| 限流熔断体系 | 池拒绝返回 `EXEC_503`，由 BFF/网关转译为限流类响应并计入熔断统计 |

## 4. 数据结构定义

### 4.1 池规格 `ExecutorSpec`

```python
# app/core/executors/spec.py
from enum import Enum
from pydantic import BaseModel, Field


class ExecutorKind(str, Enum):
    THREAD = "thread"      # 线程池
    PROCESS = "process"    # 进程池


class RejectPolicy(str, Enum):
    ABORT = "abort"        # 抛 RejectedError（推荐默认）
    CALLER_RUNS = "caller_runs"  # 由提交线程执行（仅线程池，天然背压，慎用于事件循环侧）


class ExecutorSpec(BaseModel):
    """单个执行域池的声明式规格，来源：config/executors.yaml"""
    name: str                          # 全局唯一，snake_case，如 ocr_sdk
    kind: ExecutorKind = ExecutorKind.THREAD
    max_workers: int = Field(ge=1, le=64)
    queue_capacity: int = Field(ge=0, le=10_000)   # 有界队列，0 表示仅直接提交
    reject_policy: RejectPolicy = RejectPolicy.ABORT
    task_timeout_s: float | None = Field(default=None, description="默认放弃等待阈值")
    shutdown_grace_s: float = Field(default=10.0, ge=1, le=120)
    drain_priority: int = Field(default=100, ge=0, le=999, description="数值越小越先停")
    description: str = ""
```

`config/executors.yaml`（生产基线，4C8G 单实例）：

| name | kind | max_workers | queue_capacity | 用途 | drain_priority |
| --- | --- | --- | --- | --- | --- |
| `db_blocking` | thread | 8 | 200 | 同步 DB 驱动/遗留 ORM 调用 | 200 |
| `ocr_sdk` | thread | 6 | 100 | 拍题 OCR 厂商同步 SDK | 100 |
| `asr_tts_sdk` | thread | 6 | 100 | 语音识别/合成同步 SDK | 100 |
| `media_io` | thread | 4 | 200 | 图片下载转存、文件校验 | 300 |
| `thirdparty_sync` | thread | 4 | 200 | 支付/短信等其他同步 SDK | 150 |
| `cpu_render` | process | 2 | 50 | LaTeX 渲染、图像压缩、符号计算 | 400 |
| `internal_misc` | thread | 2 | 50 | 兜底杂项（新增业务域前的临时归属） | 500 |

约束：

1. `queue_capacity` 必须 > 0（除 `internal_misc` 明确小队列外，禁止无限队列）；
2. `max_workers` 总和（线程）≤ 实例 CPU 核数 × 4；进程池 worker 总和 ≤ CPU 核数 − 1；
3. 新增业务域池必须走 MR 修改本文件，禁止代码内内联创建（见 §10 静态检查）。

### 4.3 注册中心与受管池

```python
# app/core/executors/registry.py
from __future__ import annotations

import asyncio
import logging
import time
from concurrent.futures import Future, ProcessPoolExecutor, ThreadPoolExecutor
from typing import Any, Callable

from prometheus_client import Counter, Gauge, Histogram

from app.common.thread_context import ContextAwareExecutor  # 上游：请求上下文传递规范 §12.4
from app.core.executors.spec import ExecutorKind, ExecutorSpec, RejectPolicy

logger = logging.getLogger(__name__)

# ── 指标（与《日志与监控告警体系》命名风格一致） ──────────────────
executor_submitted = Counter(
    "executor_submitted_total", "任务提交数", ["pool"])
executor_finished = Counter(
    "executor_finished_total", "任务终态计数", ["pool", "outcome"])  # success/failure/timeout/abandoned
executor_queue_depth = Gauge(
    "executor_queue_depth", "当前排队数", ["pool"])
executor_active = Gauge(
    "executor_active_workers", "当前运行 worker 数", ["pool"])
executor_rejected = Counter(
    "executor_rejected_total", "提交被拒绝数", ["pool"])
executor_task_seconds = Histogram(
    "executor_task_seconds", "任务执行耗时(秒)", ["pool"],
    buckets=(0.01, 0.05, 0.1, 0.5, 1, 3, 5, 10, 30, 60))
executor_wait_seconds = Histogram(
    "executor_wait_seconds", "任务排队等待耗时(秒)", ["pool"],
    buckets=(0.005, 0.01, 0.05, 0.1, 0.5, 1, 3, 10))


class RejectedExecutionError(RuntimeError):
    """池与队列均满，提交被拒绝。"""


class ManagedExecutor:
    """受管执行域池：上下文透传 + 指标 + 拒绝策略 + 有界队列。

    线程池继承 ContextAwareExecutor 以复用 RequestContext 透传；
    进程池无法透传 contextvars（子进程隔离），只做指标与拒绝治理，
    需要上下文的参数必须显式传值。
    """

    def __init__(self, spec: ExecutorSpec) -> None:
        self._spec = spec
        self._semaphore = asyncio.Semaphore(spec.queue_capacity) if spec.queue_capacity else None
        if spec.kind is ExecutorKind.PROCESS:
            self._executor: ThreadPoolExecutor | ProcessPoolExecutor = ProcessPoolExecutor(
                max_workers=spec.max_workers)
        else:
            self._executor = _BoundedThreadPool(spec)
        self._inflight: set[Future] = set()

    # -- 提交（同步侧入口，供 Celery Worker / 脚本使用） -------------
    def submit(self, fn: Callable[..., Any], /, *args: Any, **kwargs: Any) -> Future:
        try:
            future = self._executor.submit(fn, *args, **kwargs)
        except RejectedExecutionError:
            executor_rejected.labels(self._spec.name).inc()
            raise
        executor_submitted.labels(self._spec.name).inc()
        self._track(future)
        return future

    def _track(self, future: Future) -> None:
        pool = self._spec.name
        executor_queue_depth.labels(pool).inc()
        submit_ts = time.monotonic()
        self._inflight.add(future)
        executor_active.labels(pool).inc()

        def _done(f: Future) -> None:
            self._inflight.discard(f)
            executor_active.labels(pool).dec()
            executor_queue_depth.labels(pool).dec()
            executor_wait_seconds.labels(pool).observe(time.monotonic() - submit_ts)
            executor_task_seconds.labels(pool).observe(f._pt_duration)  # 由包装器写入
            outcome = (
                "success" if not f.cancelled() and f.exception() is None
                else "cancelled" if f.cancelled()
                else f._pt_outcome or "failure"
            )
            executor_finished.labels(pool, outcome).inc()

        future.add_done_callback(_done)

    async def drain(self, grace_s: float | None = None) -> dict[str, int]:
        """停机排空：等待在跑任务结束，不再接受新提交（见 §8）。"""
        ...
```

> 说明：`_BoundedThreadPool` 为继承 `ContextAwareExecutor` 并以 `queue_size=spec.queue_capacity + 1`（ThreadPoolExecutor 的 queue 即待执行任务列表）+ `reject_policy` 构造的实现；包装器负责写入 `future._pt_duration/_pt_outcome`（超时→`timeout`，调用方放弃→`abandoned`）。完整实现位于 `app/core/executors/managed.py`，此处省略样板。

## 5. 统一编程接口（业务侧 API）

### 5.1 接口一览

| 接口 | 签名 | 适用 |
| --- | --- | --- |
| 同步函数上池 | `await run_in_pool(pool: str, fn, /, *args, timeout_s: float \| None = None, **kwargs)` | Handler 协程内调用阻塞函数 |

| 取消后台任务 | `await cancel_background_task(name)` | 管理接口/停机 |
| 池状态查询 | `GET /internal/executors`（内部运维接口） | 管理后台/巡检 |

### 5.2 `run_in_pool` 实现（含放弃等待语义）

```python
# app/core/executors/api.py
import asyncio
import contextlib

from app.core.executors.registry import ManagedExecutor, RejectedExecutionError, get_registry
from app.core.exceptions import ExecutorTimeoutError, ExecutorRejectedError


async def run_in_pool(
    pool: str,
    fn,
    /,
    *args,
    timeout_s: float | None = None,
    **kwargs,
):
    """在受管执行域池上运行同步函数并返回结果。

    语义：
    - timeout_s 到期 → 调用方收到 ExecutorTimeoutError（放弃等待）；
      线程无法被强杀，会继续执行至结束并记 outcome=timeout，用于容量归因；
    - 池满被拒 → ExecutorRejectedError（EXEC_503），调用方应走降级分支；
    - fn 抛出的原始异常原样透传（不吞异常）。
    """
    executor: ManagedExecutor = get_registry().get(pool)   # 未注册的池直接 KeyError=配置错误
    timeout = timeout_s or executor.spec.task_timeout_s

    loop = asyncio.get_running_loop()
    try:
        future = executor.submit(fn, *args, **kwargs)
    except RejectedExecutionError as exc:
        raise ExecutorRejectedError(f"EXEC_503: 执行域 {pool} 已满") from exc

    awaitable = asyncio.wrap_future(future)
    if timeout is None:
        return await awaitable

    try:
        return await asyncio.wait_for(awaitable, timeout=timeout)
    except asyncio.TimeoutError:
        executor.mark_abandoned(future)                # 记 outcome=timeout（线程自然结束后归因）
        with contextlib.suppress(Exception):
            awaitable.cancel()                       # 取消的是等待侧
        raise ExecutorTimeoutError(f"EXEC_408: {pool} 任务超时(>{timeout}s)已放弃等待")
```

### 5.3 声明式装饰器

```python
# app/core/executors/decorator.py
import functools

from app.core.executors.api import run_in_pool


def blocking_call(pool: str, timeout_s: float | None = None):
    """将同步 SDK 函数包装为异步函数，并声明其执行域。"""

    def decorator(fn):
        assert not asyncio.iscoroutinefunction(fn), "blocking_call 只能装饰同步函数"

        @functools.wraps(fn)
        async def wrapper(*args, **kwargs):
            return await run_in_pool(pool, fn, *args, timeout_s=timeout_s, **kwargs)

        wrapper.__blocking_pool__ = pool     # 供静态检查/文档生成识别
        return wrapper

    return decorator


# 使用示例：拍题 OCR 适配层
# modules/cameraquestion/sdk_adapter.py
@blocking_call(pool="ocr_sdk", timeout_s=20)
def ocr_recognize_sync(image_bytes: bytes, lang: str) -> dict:
    return _vendor_sdk.recognize(image_bytes, lang=lang)

async def handle_photo_question(...):
    result = await ocr_recognize_sync(data, lang="CHN")   # 事件循环不被阻塞
```

## 6. BackgroundTask 管理（事件循环侧）

### 6.1 `spawn_background_task`

```python
# app/core/tasks/api.py
import asyncio

from app.core.tasks.registry import BackgroundTask, TaskState, get_task_registry


async def spawn_background_task(
    name: str,
    coro_factory,                       # Callable[[], Coroutine]：惰性创建，便于重放
    *,
    timeout_s: float = 300,
    critical: bool = False,              # critical=True：停机时等待完成；False：尝试取消
) -> BackgroundTask:
    registry = get_task_registry()
    task = BackgroundTask(name=name, coro_factory=coro_factory)

    async def _runner():
        task.state, task.started_at = TaskState.RUNNING, utcnow()
        try:
            await asyncio.wait_for(coro_factory(), timeout=timeout_s)
            task.state = TaskState.SUCCEEDED
        except asyncio.TimeoutError:
            task.state, task.error = TaskState.TIMED_OUT, f">{timeout_s}s"
        except asyncio.CancelledError:
            task.state = TaskState.CANCELLED
            raise
        except Exception as exc:                     # 后台任务异常必须留痕
            task.state, task.error = TaskState.FAILED, repr(exc)
            logger.exception("background task failed: %s", name)   # 结构化日志含 trace_id
        finally:
            task.finished_at = utcnow()

    task.aio_task = asyncio.create_task(_runner(), name=name)
    registry.register(task, critical=critical)       # 强引用入表，防孤儿
    task.aio_task.add_done_callback(lambda _: registry.mark_done(name))
    return task
```

规则：

1. **禁止**在业务代码中直接 `asyncio.create_task(...)` 而不经过本接口（评审红线，见 §10）；
2. 任务名全局唯一（重复 spawn 拒绝并告警），命名 `<模块>.<动作>`；
3. `critical=True` 仅限：缓存写回、进度落库等中断会造成数据不一致的任务；其余一律可取消；
4. 周期性任务（如首页卡片预热）在任务体内自行 `while` + 可中断 `asyncio.sleep`，停机时由取消语义打断。

### 6.2 与 Celery 的分工

| 维度 | BackgroundTask（本规范） | Celery（《异步任务体系》） |
| --- | --- | --- |
| 生命周期 | 随进程 | 跨进程、跨重启 |
| 可靠性 | 尽力而为（停机可能取消） | 持久化 + 重试 |
| 耗时上限 | ≤ 5 分钟 | 无限制 |
| 典型场景 | 请求后置收尾、缓存预热、统计聚合触发 | 报表导出、转码、批量导入 |

## 7. 状态流转

### 7.1 池任务状态机

```text
            submit()                worker 取出
 CREATED ──────────▶ QUEUED ────────────────▶ RUNNING ──┬──▶ SUCCEEDED
                       │                            │    ├──▶ FAILED(异常)
                       ├─ shutdown 拒绝 ─▶ REJECTED  │    ├──▶ TIMED_OUT(调用方放弃等待,
                       │                            │    │     线程稍后自然结束)
                       └── future.cancel() ─▶ CANCELLED   └──▶ ABANDONED(停机放弃)
```

| 迁移 | 触发 | 副作用 |
| --- | --- | --- |
| CREATED→QUEUED | submit 入队 | `executor_submitted` +1，queue_depth +1 |
| QUEUED→REJECTED | 队列满 + ABORT 策略 | `executor_rejected` +1，抛 `ExecutorRejectedError` |
| QUEUED→RUNNING | worker 取任务 | active +1，记 wait 耗时 |
| RUNNING→终态 | 函数返回/抛错/放弃 | outcome 打点，active −1 |

### 7.2 停机 drain 状态机

```text
RUNNING(服务中) ─ pre-stop hook ─▶ DRAINING(拒绝新提交,按 drain_priority 排空各池)
      └─ 超过 termination_grace_period ─▶ FORCED(取消 critical=False 的 BackgroundTask，
                                            放弃仍在跑的池任务并记 outcome=abandoned)
FORCED ─▶ TERMINATED
```

## 8. 优雅停机集成

按《服务端优雅停机与流量排空策略》的 ShutdownManager 注册回调：

```python
# app/core/executors/lifecycle.py
from app.core.shutdown import register_shutdown_callback, ShutdownPhase


def install_shutdown_hooks() -> None:
    register_shutdown_callback(ShutdownPhase.DRAIN, _drain_executors)


async def _drain_executors() -> None:
    registry = get_registry()
    # 1) 先停接收新任务的低优先级池（drain_priority 大者先停）
    for spec in sorted(registry.specs(), key=lambda s: -s.drain_priority):
        executor = registry.get(spec.name)
        executor.stop_accepting()                       # 后续 submit 一律 REJECTED
        stats = await executor.drain(grace_s=spec.shutdown_grace_s)
        logger.info("pool %s drained: %s", spec.name, stats)
    # 2) BackgroundTask：critical=False → cancel；critical=True → 等待(上限 30s)
    await get_task_registry().shutdown(critical_wait_s=30.0)
```

顺序约束（与停机文档的阶段对齐）：

1. 网关排空流量（已有机制）→ 2. **本规范 DRAIN**（先杂项池、后核心池）→ 3. 数据库连接池关闭。`ocr_sdk`/`asr_tts_sdk`（drain_priority=100）最后停，保证仍在处理的拍题/语音请求能完成。

## 9. 错误处理

### 9.1 错误码（扩展统一业务异常码体系）

| 错误码 | HTTP 映射 | 场景 | 处理建议 |
| --- | --- | --- | --- |
| EXEC_401 | 500 | 池名未注册（配置错误） | 修复配置，禁止捕获吞掉 |
| EXEC_408 | 504 | `run_in_pool` 放弃等待 | 调用方走降级；记录慢任务归因 |
| EXEC_409 | 500 | BackgroundTask 重名 | 修复调用方 |
| EXEC_410 | 500 | 向进程池提交不可 pickle 参数 | 改传基础类型/路径 |
| EXEC_503 | 503 | 池与队列均满（背压触发） | 网关按限流语义响应客户端"稍后重试"，计入熔断统计 |
| EXEC_504 | 500 | 池内任务异常且无调用方等待（fire-and-forget） | 仅日志+指标，必须包含 trace_id |

### 9.2 异常透传原则

- `run_in_pool` **不包装、不吞**业务异常，原样透传；
- fire-and-forget 场景必须通过 `add_done_callback` 打日志，禁止提交后不管；
- `ExecutorRejectedError` 是**预期内**的背压信号，客户端文案统一为"当前使用人数较多，请稍后再试"（与限流话术一致）。

async def load_home_bff(user_id: int) -> HomeBundle:

## 13. 容量基线与演进

| 实例规格 | 线程池 worker 总额 | 进程池 worker | 队列总额 | 说明 |
| --- | --- | --- | --- | --- |
| 2C4G（灰度/低峰） | ≤ 8 | 1 | ≤ 400 | executors.yaml 覆盖为 `profile: small` |
| 4C8G（生产基线） | ≤ 30 | 2 | ≤ 900 | §4.2 基线 |
| 8C16G（大促） | ≤ 48 | 4 | 按 K8s HPA 副本摊薄 | 优先扩副本而非单实例加池 |

演进约定：

1. 池利用率连续 7 天 `active/max_workers < 20%` → 缩容 MR；
2. `executor_wait_seconds` P99 > 500ms 持续出现 → 优先评估迁移 Celery；
3. 微服务拆分时，`ExecutorRegistry` 配置随服务裁剪，接口与语义不变。
