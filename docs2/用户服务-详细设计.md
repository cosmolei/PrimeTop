# 用户服务 / 账号体系 - 详细设计

> 细化日期：2026-06-03
> 原始文档：`docs/design/启硕-PrimeTop-全学段AI辅助学习软件项目设计文档.md` §6.1 账号体系、§8.4 用户服务、§8.6 数据架构

## 1. 模块概述

用户服务是 PrimeTop 的基础模块，负责：

- 用户注册与登录（手机号验证码、第三方登录）
- 用户身份管理（学生 / 家长 / 管理员）
- 学生档案维护（学段、年级、教材版本、学习目标）
- 家长-学生绑定关系
- 会员权益与订阅状态查询
- Token 签发与刷新

本模块是其他所有业务模块的前置依赖。

## 2. 数据结构定义

### 2.1 users 表 — 用户主表

```sql
CREATE TABLE users (
    id              BIGSERIAL PRIMARY KEY,
    phone           VARCHAR(20) UNIQUE,               -- 手机号（国际格式 +8613800138000）
    phone_verified  BOOLEAN DEFAULT FALSE,             -- 手机号是否已验证
    nickname        VARCHAR(50) NOT NULL,              -- 昵称
    avatar_url      VARCHAR(512),                      -- 头像 URL
    password_hash   VARCHAR(255),                      -- 密码哈希（可选，预留）
    user_type       VARCHAR(20) NOT NULL DEFAULT 'student',  -- student | parent | admin
    status          VARCHAR(20) NOT NULL DEFAULT 'active',   -- active | disabled | deleted
    last_login_at   TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_phone ON users(phone);
CREATE INDEX idx_users_user_type ON users(user_type);
```

**字段说明：**

| 字段 | 说明 | 约束 |
|------|------|------|
| `id` | 用户 ID，全局唯一，BIGSERIAL 自增 | PK |
| `phone` | 手机号，含国际区号 | 唯一，可为空（第三方登录场景） |
| `user_type` | 用户角色 | 枚举值，NOT NULL |
| `status` | 账号状态 | 禁用状态由管理后台设置 |

### 2.2 third_party_bindings 表 — 第三方登录绑定

```sql
CREATE TABLE third_party_bindings (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL REFERENCES users(id),
    provider        VARCHAR(20) NOT NULL,              -- wechat | apple | google
    provider_uid    VARCHAR(128) NOT NULL,             -- 第三方用户标识
    union_id        VARCHAR(128),                      -- 第三方 UnionID（如微信）
    bind_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(provider, provider_uid)
);

CREATE INDEX idx_tpb_user_id ON third_party_bindings(user_id);
```

### 2.3 student_profiles 表 — 学生档案

```sql
CREATE TABLE student_profiles (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL UNIQUE REFERENCES users(id),
    stage           VARCHAR(20) NOT NULL,              -- preschool | primary | junior | senior
    grade           INT NOT NULL,                      -- 年级序号（1-12）
    grade_label     VARCHAR(20),                       -- 展示用：如"三年级"、"高一"
    textbook_ver    VARCHAR(50)[] DEFAULT '{}',        -- 各学科教材版本 JSON 映射
    school_name     VARCHAR(100),                      -- 学校名称（可选）
    learning_goal   VARCHAR(50),                       -- 学习目标：daily | midterm | final | zhongkao | gaokao
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_sp_user_id ON student_profiles(user_id);
CREATE INDEX idx_sp_stage ON student_profiles(stage);
```

**学段与年级映射关系：**

| stage | 年级范围 (grade) | grade_label 示例 |
|-------|-----------------|-----------------|
| `preschool` | 1-3 | 小班、中班、大班 |
| `primary` | 1-6 | 一年级~六年级 |
| `junior` | 1-3 | 初一~初三 |
| `senior` | 1-3 | 高一~高三 |

**textbook_ver 字段示例：**

```json
{
  "math": "人教版",
  "chinese": "人教版",
  "english": "外研版",
  "physics": "人教版"
}
```

> 使用 PostgreSQL JSONB 类型存储更佳，MVP 阶段先用 TEXT 存储 JSON 字符串。

### 2.4 parent_bindings 表 — 家长-学生绑定

```sql
CREATE TABLE parent_bindings (
    id              BIGSERIAL PRIMARY KEY,
    parent_id       BIGINT NOT NULL REFERENCES users(id),
    student_id      BIGINT NOT NULL REFERENCES users(id),
    relation        VARCHAR(20) DEFAULT 'other',      -- father | mother | grandparent | other
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',  -- pending | active | revoked
    invited_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    accepted_at     TIMESTAMPTZ,
    UNIQUE(parent_id, student_id)
);

CREATE INDEX idx_pb_parent_id ON parent_bindings(parent_id);
CREATE INDEX idx_pb_student_id ON parent_bindings(student_id);
```

**绑定状态流转：**

```
student 发出邀请 → pending → parent 接受 → active
                           → parent 拒绝 → revoked
active → parent/student 主动解绑 → revoked
```

## 3. API 接口设计

**基础路径：** `/api/v1/user`

**通用响应格式：**

```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

**通用错误码：**

| code | 含义 |
|------|------|
| 0 | 成功 |
| 10001 | 参数错误 |
| 10002 | 验证码错误或已过期 |
| 10003 | 手机号已注册 |
| 10004 | 手机号未注册 |
| 10005 | 账号已禁用 |
| 10006 | Token 无效或已过期 |
| 10007 | 权限不足 |
| 10008 | 第三方登录失败 |
| 10009 | 绑定关系已存在 |
| 10010 | 频率限制（短信发送过频） |

### 3.1 发送验证码

```
POST /api/v1/user/sms/send
```

**请求体：**

```json
{
  "phone": "+8613800138000",
  "purpose": "login"
}
```

**响应：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "expire_in": 300
  }
}
```

**限制规则：**
- 同一手机号 60 秒内只能发 1 次
- 同一手机号每天最多 10 次
- 验证码 5 分钟有效
- 验证码为 6 位数字

**Redis 限流 Key 设计：**

```
sms:limit:60:{phone}    → TTL 60s，值为发送次数（最多 1）
sms:limit:daily:{phone} → TTL 至当天结束，值为当天发送次数（最多 10）
sms:code:{phone}:{purpose} → TTL 300s，值为验证码
```

### 3.2 手机号注册/登录（验证码方式）

```
POST /api/v1/user/auth/phone
```

**请求体：**

```json
{
  "phone": "+8613800138000",
  "code": "123456",
  "purpose": "login"
}
```

**行为说明：**
- 如果手机号已注册 → 登录，返回 Token
- 如果手机号未注册且 purpose=register → 自动注册并登录
- 如果手机号未注册且 purpose=login → 返回错误 10004

**成功响应：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "access_token": "eyJhbGci...",
    "refresh_token": "dGhpcyBp",
    "token_type": "Bearer",
    "expires_in": 7200,
    "user": {
      "id": 10001,
      "nickname": "用户10001",
      "avatar_url": null,
      "user_type": "student",
      "phone": "138****8000",
      "has_profile": false
    }
  }
}
```

**注意：** 新注册用户 `has_profile=false`，客户端应引导用户填写学生档案。

### 3.3 第三方登录

```
POST /api/v1/user/auth/third-party
```

**请求体：**

```json
{
  "provider": "wechat",
  "code": "071234567890abcdef",
  "user_type": "student"
}
```

**行为说明：**
1. 用 `code` 向第三方换取 `openid` / `unionid`
2. 查找 `third_party_bindings` 表
3. 已绑定 → 返回对应用户的 Token
4. 未绑定 → 自动创建用户 + 绑定 + 返回 Token

**成功响应格式同 3.2。**

### 3.4 Token 刷新

```
POST /api/v1/user/auth/refresh
```

**请求体：**

```json
{
  "refresh_token": "dGhpcyBp"
}
```

**响应：**

```json
{
  "code": 0,
  "data": {
    "access_token": "eyJhbGci...",
    "expires_in": 7200
  }
}
```

**Token 策略：**
- Access Token 有效期 2 小时
- Refresh Token 有效期 30 天
- Refresh Token 使用后轮换（旧 Token 失效，签发新 Token）
- 使用 JWT，payload 包含 `user_id`、`user_type`、`exp`

## 4. 鉴权中间件设计

### 4.1 JWT 结构

```json
{
  "sub": 10001,
  "type": "student",
  "iat": 1717344000,
  "exp": 1717351200,
  "jti": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

### 4.2 中间件伪代码

```go
func AuthMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // 1. 从 Header 提取 Token
        authHeader := r.Header.Get("Authorization")
        if authHeader == "" || !strings.HasPrefix(authHeader, "Bearer ") {
            writeError(w, 10006, "missing or invalid token")
            return
        }
        tokenStr := strings.TrimPrefix(authHeader, "Bearer ")

        // 2. 解析并验证 JWT
        claims, err := parseJWT(tokenStr)
        if err != nil {
            writeError(w, 10006, "invalid token")
            return
        }

        // 3. 检查 Token 是否在 Redis 黑名单中（用于主动注销）
        if isTokenRevoked(claims.JTI) {
            writeError(w, 10006, "token revoked")
            return
        }

        // 4. 检查用户状态
        user, err := userService.GetByID(claims.Sub)
        if err != nil || user.Status != "active" {
            writeError(w, 10005, "account disabled")
            return
        }

        // 5. 注入用户信息到 Context
        ctx := context.WithValue(r.Context(), "userID", claims.Sub)
        ctx = context.WithValue(ctx, "userType", claims.Type)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}
```

### 6.1 AI 调用配额（按会员等级）

| 指标 | free | monthly | yearly | exam_prep |
|------|------|---------|--------|-----------|
| 每日 AI 问答 | 10 | 50 | 100 | 100 |
| 每日拍题 | 5 | 30 | 50 | 50 |
| 错题收录 | 50 | 无限 | 无限 | 无限 |
| 学情报告 | 基础 | 完整 | 完整 | 完整 |

### 6.2 Redis 配额 Key

```
quota:{user_id}:{date}:ai_questions     → 当日已用次数
quota:{user_id}:{date}:photo_questions  → 当日已用次数
```

**原子递增逻辑：**

```go
func CheckAndIncrQuota(userID int64, quotaType string, limit int) (bool, int, error) {
    key := fmt.Sprintf("quota:%d:%s:%s", userID, time.Now().Format("20060102"), quotaType)
    
    // 使用 Lua 脚本保证原子性
    script := `
        local current = redis.call('GET', KEYS[1])
        if current and tonumber(current) >= tonumber(ARGV[1]) then
            return {0, tonumber(current)}
        end
        local new = redis.call('INCR', KEYS[1])
        if new == 1 then
            redis.call('EXPIRE', KEYS[1], 86400)
        end
        return {1, new}
    `
    result, err := redisEval(script, []string{key}, limit)
    allowed := result[0] == 1
    used := result[1]
    return allowed, used, err
}
```

## 7. 错误处理策略

### 7.1 错误响应格式

```json
{
  "code": 10002,
  "message": "验证码错误或已过期",
  "details": {
    "field": "code",
    "reason": "code expired at 2026-06-03T00:10:00Z"
  }
}
```

### 7.2 各场景错误处理

| 场景 | 处理策略 |
|------|----------|
| 验证码错误 | 返回 10002，不提示是"错误"还是"过期"（防暴力破解） |
| 手机号已注册 | 注册时返回 10003，提示直接登录 |
| Token 过期 | 返回 10006，客户端自动用 Refresh Token 刷新 |
| 账号禁用 | 返回 10005，提示联系客服 |
| 短信发送过频 | 返回 10010，告知剩余等待秒数 |
| 第三方登录失败 | 返回 10008，附带第三方错误信息（日志记录，不暴露给用户） |

### 7.3 防暴力破解

- 验证码连续错误 5 次 → 锁定该手机号 30 分钟
- Redis Key: `sms:lock:{phone}` → TTL 1800s

```go
func OnVerifyFailed(phone string) {
    key := fmt.Sprintf("sms:fail:%s", phone)
    count, _ := redis.Incr(key)
    if count == 1 {
        redis.Expire(key, 1800)
    }
    if count >= 5 {
        lockKey := fmt.Sprintf("sms:lock:%s", phone)
        redis.Set(lockKey, "1", 30*time.Minute)
    }
}
```

## 8. 客户端缓存策略

### 8.1 本地缓存数据

| 数据 | 缓存方式 | 失效条件 |
|------|----------|----------|
| 用户基本信息 | SharedPreferences / Keychain | 登录/登出/修改 |
| 学生档案 | 本地 JSON | 每次启动拉取 + 修改后刷新 |
| Access Token | 安全存储 | 过期时通过 Refresh Token 刷新 |
| 会员状态 | 内存 + 本地 | 每次打开 APP 拉取 |

### 8.2 Token 自动刷新流程

```
客户端请求 → 收到 10006 → 
  用 Refresh Token 调用 /auth/refresh →
    成功 → 用新 Token 重试原始请求
    失败 → 跳转登录页
```

## 9. 数据安全

### 9.1 敏感数据处理

| 数据 | 处理方式 |
|------|----------|
| 手机号 | 数据库完整存储，API 响应脱敏（138****8000） |
| 密码 | bcrypt 哈希，rounds=12 |
| Token | 客户端使用安全存储（iOS Keychain / Android EncryptedSharedPreferences） |
| 验证码 | Redis 存储，验证后立即删除 |

### 9.2 未成年人保护

- 注册时如 user_type=student 且 grade ≤ 3（小学三年级以下），强制要求家长绑定
- 14 周岁以下用户按《儿童个人信息网络保护规定》处理
- 家长可随时查看/导出孩子的学习数据

## 10. 部署与运维

### 10.1 Redis Key 命名规范

```
{业务域}:{实体}:{标识}:{子字段}
例：sms:code:+8613800138000:login
例：quota:10001:20260603:ai_questions
例：token:blacklist:{jti}
```

### 10.2 监控指标

| 指标 | 告警阈值 |
|------|----------|
| 注册成功率 | < 90% 告警 |
| 登录响应时间 P99 | > 1s 告警 |
| 短信发送失败率 | > 5% 告警 |
| Token 刷新失败率 | > 2% 告警 |
| 验证码验证成功率 | < 80% 告警（可能短信通道故障） |
