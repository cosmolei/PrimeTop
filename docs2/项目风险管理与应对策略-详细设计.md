# 项目风险管理与应对策略 - 详细设计

> 本文档基于主设计文档第15节，对 PrimeTop 项目全生命周期可能面临的风险进行系统化识别、分级、量化，并给出可落地的应对策略、监控指标和应急预案。

---

## 1. 概述

### 1.1 目的

为 PrimeTop 项目建立结构化的风险管理框架，确保团队能够：
- 在项目早期识别潜在风险
- 对风险进行优先级排序和资源分配
- 制定预防措施和应急预案
- 持续监控风险状态，及时响应

### 1.2 风险管理流程

```
风险识别 → 风险评估(概率×影响) → 风险分级 → 应对策略制定 → 监控与复盘
    ↑                                                        |
    └──────────────────── 周期性迭代 ←────────────────────────┘
```

### 1.3 风险等级定义

| 等级 | 分值 | 响应要求 | 复审周期 |
|------|------|----------|----------|
| P0-致命 | ≥20 | 立即启动应急预案，24h内解决 | 每日 |
| P1-严重 | 15-19 | 一周内制定详细对策并执行 | 每周 |
| P2-中等 | 10-14 | 排入迭代计划，持续跟踪 | 双周 |
| P3-轻微 | 5-9 | 记录在案，定期审视 | 月度 |
| P4-可忽略 | 1-4 | 观察即可 | 季度 |

评分规则：`风险分值 = 发生概率(1-5) × 影响程度(1-5)`

## 3. 各风险详细分析与应对

### 3.1 A类：AI技术风险

#### A1 AI回答不准确/幻觉

| 维度 | 描述 |
|------|------|
| **风险描述** | AI在解题、知识讲解中给出错误答案、编造不存在的知识点或公式，误导学生 |
| **触发场景** | 复杂理科推理、冷门知识点、跨学科问题、多步骤推导 |
| **发生概率** | 4（较高） |
| **影响程度** | 5（致命 - 直接损害学习效果和用户信任） |
| **风险等级** | **P0-致命 (20分)** |

**预防措施：**

1. **RAG检索增强**
```typescript
// RAG 质量门控示例
interface RAGQualityGate {
  // 检索相关性阈值
  minRelevanceScore: 0.75;
  // 最少检索文档数
  minRetrievedDocs: 3;
  // 强制引用来源
  requireCitation: true;
}

// 答案生成时的约束
interface AnswerConstraint {
  // 数学公式必须可验证
  mathFormulaValidation: true;
  // 知识点必须在教材知识图谱中存在
  knowledgePointValidation: true;
  // 不确定时标注置信度
  confidenceThreshold: 0.8; // 低于此值提示"仅供参考"
}
```

2. **多模型复核机制**
```
用户提问 → 主模型生成答案
                ↓
        置信度评估 < 阈值?
           ├─ 否 → 直接输出
           └─ 是 → 第二模型交叉验证
                      ├─ 一致 → 输出 + 标注"已验证"
                      └─ 不一致 → 标注"存疑" + 推荐咨询老师
```

3. **用户反馈闭环**
```sql
-- AI回答质量追踪表
CREATE TABLE ai_answer_feedback (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    session_id      VARCHAR(64) NOT NULL COMMENT '会话ID',
    message_id      VARCHAR(64) NOT NULL COMMENT '消息ID',
    user_id         BIGINT NOT NULL,
    question_text   TEXT NOT NULL COMMENT '原始问题',
    answer_text     TEXT NOT NULL COMMENT 'AI回答',
    model_id        VARCHAR(32) NOT NULL COMMENT '使用的模型',
    feedback_type   ENUM('correct', 'partially_correct', 'wrong', 'inappropriate'),
    user_comment    TEXT COMMENT '用户补充说明',
    correct_answer  TEXT COMMENT '正确答案（用户或专家填写）',
    verified        TINYINT DEFAULT 0 COMMENT '是否已由教研专家确认',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_model_time (model_id, created_at),
    INDEX idx_verified (verified, feedback_type)
);
```

**应急预案：**

| 触发条件 | 响应动作 | 责任人 | 时限 |
|----------|----------|--------|------|
| 单模型错误率 >5%/天 | 降低该模型权重，切换备用模型 | AI工程师 | 2h内 |
| 某学科批量投诉（>50条/天） | 临时下线该学科AI回答，转为"人工客服待答" | 产品经理+AI | 1h内 |
| 被媒体/监管曝光错误内容 | 紧急修复+公开声明+全量排查 | 管理层+PR | 4h内 |

**监控指标：**
- AI回答用户满意率（目标：≥85%）
- AI解析错误反馈率（目标：≤3%）
- 多模型复核触发率（监控阈值：≤15%）
- 用户"举报"按钮点击率（目标：≤1%）

#### A2 AI响应延迟/不可用

| 维度 | 描述 |
|------|------|
| **风险描述** | AI模型API响应超时、限流或完全不可用，导致用户无法获得学习帮助 |
| **触发场景** | 模型供应商故障、网络波动、高峰期流量突增、API配额耗尽 |
| **发生概率** | 3（中等） |
| **影响程度** | 4（严重） |
| **风险等级** | **P1-严重 (12分)** |

**预防措施：**

1. **多供应商冗余架构**
```yaml
# 模型供应商配置（优先级从高到低）
model_providers:
  primary:
    name: "provider-a"
    model: "gpt-4-turbo"
    timeout: 8s
    rate_limit: 500/min
    
  secondary:
    name: "provider-b"  
    model: "claude-3"
    timeout: 10s
    rate_limit: 300/min
    failover_delay: 2s  # 主供应商失败后等待时间
    
  tertiary:
    name: "provider-c"
    model: "glm-4"
    timeout: 12s
    rate_limit: 200/min

# 降级策略
degradation:
  level_1:
    trigger: "primary failure rate > 10%"
    action: "route 50% traffic to secondary"
  level_2:
    trigger: "all providers degraded"
    action: "enable local cache response + estimated wait time"
  level_3:
    trigger: "all providers unavailable"
    action: "offline mode, cached answers only, queue request"
```

2. **前端体验优化**
```typescript

```

**监控指标：**
- AI首token响应P95（目标：≤3s）
- 模型可用率（目标：≥99.5%）
- 供应商切换频率（告警阈值：>5次/小时）
- 用户因超时放弃率（目标：≤2%）

#### A3 OCR识别准确率不足

| 维度 | 描述 |
|------|------|
| **风险描述** | 拍照搜题时无法准确识别手写、模糊、复杂排版题目，导致解析错误 |
| **发生概率** | 3（中等） |
| **影响程度** | 3（中等） |
| **风险等级** | **P2-中等 (9分)** |

**预防措施：**

1. **图像预处理管线**
```
原始图片 → 自动旋转校正 → 去噪增强 → 对比度优化
    → 区域检测(题目/图/公式) → 分别OCR → 结构化合并
```

2. **识别结果校验**
```typescript
interface OCRResult {
  text: string;
  confidence: number;      // 整体置信度 0-1
  regions: OCRRegion[];    // 各识别区域
  warnings: OCRWarning[];  // 告警信息
}

// 低置信度时的处理策略
function handleLowConfidence(result: OCRResult): Action {
  if (result.confidence >= 0.9) return 'proceed';
  if (result.confidence >= 0.7) return 'show_for_confirmation'; // 用户确认
  if (result.confidence >= 0.5) return 'suggest_retake';        // 建议重拍
  return 'manual_input';  // 引导手动输入
}
```

3. **持续优化闭环**
- 收集低置信度图片加入标注集
- 每月评估OCR供应商表现
- 针对高频失败题型专项优化

**监控指标：**
- OCR整体准确率（目标：印刷体≥95%，手写体≥85%）
- 低置信度比例（目标：≤10%）
- 用户手动修正率（目标：≤15%）

### 3.2 B类：内容与教育风险

#### B1 教材适配复杂度高

| 维度 | 描述 |
|------|------|
| **风险描述** | 国内教材版本众多（人教版、苏教版、北师大版等），各版本章节结构、知识点编排差异大，适配工作量大 |
| **发生概率** | 4（较高） |
| **影响程度** | 3（中等） |
| **风险等级** | **P2-中等 (12分)** |

**预防措施：**

1. **知识点标准化映射层**
```sql
-- 统一知识点体系，各教材版本映射到同一套知识点
CREATE TABLE knowledge_points (
    id          BIGINT PRIMARY KEY,
    subject     VARCHAR(16) NOT NULL,   -- 学科
    stage       VARCHAR(16) NOT NULL,   -- 学段
    code        VARCHAR(32) NOT NULL,   -- 标准编码 如 MATH-P-001
    name        VARCHAR(128) NOT NULL,  -- 知识点名称
    parent_id   BIGINT,                 -- 父知识点
    difficulty  TINYINT,                -- 难度等级 1-5
    description TEXT,
    UNIQUE KEY uk_code (code)
);

-- 教材章节到知识点的映射
CREATE TABLE textbook_chapter_kp_mapping (
    id              BIGINT PRIMARY KEY,
    textbook_id     INT NOT NULL,
    chapter_id      INT NOT NULL,
    kp_id           BIGINT NOT NULL,
    sequence        INT,                -- 章节内的知识点顺序
    INDEX idx_textbook_chapter (textbook_id, chapter_id)
);
```

2. **分阶段适配策略**
```
Phase 1 (MVP): 人教版 + 语数英三科 + 小学4-6年级
Phase 2 (V1.0): 人教版全科 + 苏教版语数 + 初中
Phase 3 (V1.5): 北师大版 + 外研版 + 高中
Phase 4 (V2.0): 区域性教材版本 + 高中选修
```

3. **社区反馈机制**
- 用户可报告"章节内容不匹配"
- 教研团队48h内确认并修正
- 每月统计各版本匹配满意度

**监控指标：**
- 教材版本覆盖率（MVP目标：主流版本≥60%）
- 章节映射准确率（目标：≥95%）
- 用户"内容不匹配"反馈率（目标：≤2%）

```typescript
  // Layer 1: 输入过滤 - 在用户请求到达模型前
  inputFilter(userInput: string): SafetyCheckResult;
  
  // Layer 2: 模型输出过滤 - AI生成内容展示前
  outputFilter(aiOutput: string, context: ConversationContext): SafetyCheckResult;
  
  // Layer 3: 用户举报 + 人工审核
  reportHandler(report: ContentReport): Promise<ReviewResult>;
}

interface SafetyCheckResult {
  passed: boolean;
  riskLevel: 'safe' | 'low' | 'medium' | 'high' | 'critical';
  categories: string[];        // 命中的风险类别
  action: 'allow' | 'warn' | 'block' | 'rewrite';
  rewrittenContent?: string;   // 重写后的安全内容
}
```
