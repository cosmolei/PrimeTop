# 端到端流程设计 - 弱网离线学习与数据同步恢复完整链路

> 细化日期：2026-06-09  
> 关联模块：离线缓存与数据同步、客户端本地持久层、多端数据同步与冲突解决策略、客户端断点续学

## 1. 概述

### 1.1 背景

学生使用 PrimeTop 的场景复杂多变：地铁通勤、家庭弱 Wi-Fi、校园网络不稳定、乡村网络覆盖差等。若网络波动即导致学习中断、数据丢失或功能不可用，将严重影响学习体验和学习连续性。本设计旨在建立完整的弱网/离线学习与数据同步恢复链路，确保学生在任何网络状况下均可正常学习，并在网络恢复后无缝同步数据。

### 1.2 设计目标

1. **离线可用**：核心学习功能（AI 对话历史查看、错题本浏览、同步课堂已缓存内容、练习答题）在离线状态下可正常使用
2. **数据不丢失**：弱网或断网期间产生的学习行为、答题记录、错题操作均本地持久化，网络恢复后可靠上传
3. **冲突可解决**：多端同时操作产生的数据冲突有明确的合并/解决策略
4. **体验无缝**：网络状态切换对用户透明，仅在网络恢复后通过轻量提示告知同步完成
5. **容量可控**：离线缓存占用空间有上限管理，避免占用过多设备存储

### 1.3 适用场景

| 场景 | 典型表现 | 预期行为 |
|------|----------|----------|
| 短暂断网（<30s） | 地铁过隧道、电梯中 | 请求自动队列缓存，重连后静默重试 |
| 长时间离线（>5min） | 无信号区域飞行模式 | 切换为离线模式，仅可使用已缓存内容 |
| 弱网高延迟（>3s） | 2G/3G 网络、拥挤 Wi-Fi | 降级体验：延迟加载、减少图片、预加载关键资源 |
| 网络波动（间歇性） | 频繁断连重连 | 请求幂等重试，避免数据重复提交 |
| 多端同时使用 | 手机 + 平板同时学习 | 冲突检测与服务端仲裁 |

```dart
  online,

class NetworkStatusInfo {

  final double packetLossRate; // 估算丢包率
  final DateTime lastChangedAt;
  final int consecutiveFailures; // 连续失败次数
```

### 3.3 网络探测策略

```dart
class NetworkProber {
  static const _probeUrl = 'https://api.primetop.com/health/ping';
  static const _onlineThreshold = 1000;   // 1s
  static const _weakThreshold = 3000;     // 3s
  static const _probeInterval = 15;       // 弱网/离线状态下的探测间隔（秒）
  static const _normalCheckInterval = 60; // 正常状态下的检查间隔（秒）

  /// 发送探测请求
  Future<ProbeResult> probe() async {
    final stopwatch = Stopwatch()..start();
    try {
      final response = await http.get(
        Uri.parse(_probeUrl),
      ).timeout(const Duration(seconds: 5));
      stopwatch.stop();
      
      if (response.statusCode == 200) {
        return ProbeResult(
          success: true,
          latencyMs: stopwatch.elapsedMilliseconds,
        );
      }
      return ProbeResult(success: false, latencyMs: stopwatch.elapsedMilliseconds);
    } on TimeoutException {
      return ProbeResult(success: false, latencyMs: 5000);
    } on SocketException {
      return ProbeResult(success: false, latencyMs: -1);
    }
  }
}

class ProbeResult {
  final bool success;
  final int latencyMs;
  ProbeResult({required this.success, required this.latencyMs});
}
```

## 4. 离线操作队列

### 4.1 数据模型

```sql
-- 离线操作队列表
CREATE TABLE offline_operation_queue (
    id              TEXT PRIMARY KEY,          -- UUID
    operation_type  TEXT NOT NULL,             -- 操作类型 (见枚举)
    target_entity   TEXT NOT NULL,             -- 目标实体 (answer_record, mistake_record 等)
    target_id       TEXT NOT NULL,             -- 目标实体 ID
    payload         TEXT NOT NULL,             -- JSON 序列化的请求体
    idempotency_key TEXT NOT NULL UNIQUE,      -- 幂等键，防止重复提交
    priority        INTEGER NOT NULL DEFAULT 5, -- 优先级 1(最高) - 10(最低)
    retry_count     INTEGER NOT NULL DEFAULT 0,
    max_retries     INTEGER NOT NULL DEFAULT 5,
    status          TEXT NOT NULL DEFAULT 'pending', -- pending/syncing/success/failed/dead
    created_at      TEXT NOT NULL,             -- ISO 8601
    updated_at      TEXT NOT NULL,
    scheduled_at    TEXT NOT NULL,             -- 计划同步时间（用于延迟操作）
    error_message   TEXT,                      -- 最近一次失败原因
    version         INTEGER NOT NULL DEFAULT 1, -- 乐观锁版本号
    depends_on      TEXT                       -- 依赖的前置操作 ID (可为空)
);

-- 索引
CREATE INDEX idx_opq_status_priority ON offline_operation_queue(status, priority, created_at);
CREATE INDEX idx_opq_idempotency ON offline_operation_queue(idempotency_key);
CREATE INDEX idx_opq_target ON offline_operation_queue(target_entity, target_id);
```

### 4.3 操作入队流程

```dart
class OfflineQueueService {
  final LocalDatabase _db;
  
  /// 将操作加入离线队列
  Future<String> enqueue({
    required OfflineOperationType type,
    required String targetEntity,
    required String targetId,
    required Map<String, dynamic> payload,
    String? dependsOn,
    int? priority,
  }) async {
    final id = _uuid.v4();
    final idempotencyKey = '${type.value}:${targetEntity}:${targetId}:${DateTime.now().millisecondsSinceEpoch}';
    final now = DateTime.now().toUtc().toIso8601String();
    
    // 对于同实体的同类操作，尝试合并而非堆叠
    final existing = await _findMergeableOperation(type, targetEntity, targetId);
    if (existing != null) {
      await _mergeOperation(existing, payload);
      return existing.id;
    }
    
    await _db.insert('offline_operation_queue', {
      'id': id,
      'operation_type': type.value,
      'target_entity': targetEntity,
      'target_id': targetId,
      'payload': jsonEncode(payload),
      'idempotency_key': idempotencyKey,
      'priority': priority ?? type.defaultPriority,
      'status': 'pending',
      'created_at': now,
      'updated_at': now,
      'scheduled_at': now,
      'depends_on': dependsOn,
    });
    
    return id;
  }
  
  /// 查找可合并的操作
  Future<OfflineOperation?> _findMergeableOperation(
    OfflineOperationType type,
    String entity,
    String targetId,
  ) async {
    // 对于更新类操作，如果队列中已有同一实体的 pending 操作，可以合并
    if (type == OfflineOperationType.learningProgress ||
        type == OfflineOperationType.userPreferenceUpdate) {
      final rows = await _db.query(
        'offline_operation_queue',
        where: 'operation_type = ? AND target_entity = ? AND target_id = ? AND status = ?',
        whereArgs: [type.value, entity, targetId, 'pending'],
        limit: 1,
      );
      if (rows.isNotEmpty) return OfflineOperation.fromMap(rows.first);
    }
    return null;
  }
  
  /// 合并操作（保留最新 payload，更新时间戳）
  Future<void> _mergeOperation(OfflineOperation existing, Map<String, dynamic> newPayload) async {
    final merged = _deepMerge(jsonDecode(existing.payload), newPayload);
    await _db.update(
      'offline_operation_queue',
      {
        'payload': jsonEncode(merged),
        'updated_at': DateTime.now().toUtc().toIso8601String(),
        'version': existing.version + 1,
      },
      where: 'id = ?',
      whereArgs: [existing.id],
    );
  }
}
```

### 5.2 离线练习题目缓存策略

```dart
class PracticeCacheService {
  /// 预加载练习题目到本地
  /// 调用时机：用户进入练习页时、WiFi 下后台预加载
  Future<void> preloadPracticeSet({
    required String subjectCode,
    required String chapterId,
    int count = 20,
  }) async {
    // 检查本地是否已有足够缓存
    final cached = await _countCachedQuestions(subjectCode, chapterId);
    if (cached >= count) return;
    
    final remaining = count - cached;
    
    // 从服务端获取题目
    final response = await api.get(
      '/api/v1/practice/questions',
      queryParameters: {
        'subject': subjectCode,
        'chapterId': chapterId,
        'count': remaining,
        'includeAnswer': true,  // 包含答案用于离线批改
        'includeAnalysis': true, // 包含解析
      },
    );
    
    // 写入本地缓存
    for (final q in response.data['questions']) {
      await _db.insert('cached_practice_questions', {
        'id': q['id'],
        'subject_code': subjectCode,
        'chapter_id': chapterId,
        'content_json': jsonEncode(q),
        'answer_data': jsonEncode({
          'correctAnswer': q['correctAnswer'],
          'analysis': q['analysis'],
          'knowledgePoints': q['knowledgePoints'],
        }),
        'cached_at': DateTime.now().toUtc().toIso8601String(),
        'expires_at': DateTime.now().add(Duration(days: 7)).toUtc().toIso8601String(),
        'is_used': 0,
      });
    }
  }
}
```

### 5.3 离线 AI 对话处理

离线时 AI 新对话**不可用**（依赖服务端模型），但已有对话历史可浏览。

```dart
class AIConversationOfflineHandler {
  /// 离线时处理用户消息
  Future<OfflineConversationResult> handleOfflineMessage({
    required String conversationId,
    required String userMessage,
  }) async {
    // 1. 保存用户消息到本地
    await _localAIConversationDao.insertMessage(
      conversationId: conversationId,
      role: 'user',
      content: userMessage,
      createdAt: DateTime.now(),
      syncStatus: 'pending', // 待同步标记
    );
    
    // 2. 加入离线队列，等待网络恢复后发送给 AI
    await _offlineQueue.enqueue(
      type: OfflineOperationType.aiMessageAppend,
      targetEntity: 'ai_conversation_message',
      targetId: conversationId,
      payload: {
        'conversationId': conversationId,
        'role': 'user',
        'content': userMessage,
        'createdAt': DateTime.now().toUtc().toIso8601String(),
      },
    );
    
    // 3. 返回离线提示
    return OfflineConversationResult(
      canRespond: false,
      placeholderMessage: '当前无网络连接，您的问题已保存。恢复网络后 AI 将为您解答。',
      savedLocally: true,
    );
  }
  
  /// 恢复网络后，处理挂起的 AI 请求
  Future<void> processPendingAIRequests() async {
    final pendingOps = await _offlineQueue.getByType(
      OfflineOperationType.aiMessageAppend,
      status: 'pending',
    );
    
    for (final op in pendingOps) {
      try {
        final payload = jsonDecode(op.payload);
        // 先将用户消息同步到服务端
        await _api.post('/api/v1/ai/conversations/${payload['conversationId']}/messages', data: {
          'role': 'user',
          'content': payload['content'],
          'createdAt': payload['createdAt'],
          'offlineCreated': true,
        });
        // 触发 AI 生成回复（异步，通过推送通知用户）
        await _api.post('/api/v1/ai/conversations/${payload['conversationId']}/generate');
        
        await _offlineQueue.markSuccess(op.id);
      } catch (e) {
        await _offlineQueue.incrementRetry(op.id, errorMessage: e.toString());
      }
    }
  }
}
```

### 6.4 同步引擎核心实现

```dart
class SyncEngine {
  final ApiClient _api;
  final LocalDatabase _db;
  final OfflineQueueService _queue;
  final ConflictResolver _conflictResolver;
  final NetworkMonitor _network;

  /// 触发完整同步流程
  Future<SyncResult> triggerFullSync() async {
    if (_network.currentStatus == NetworkStatus.offline) {
      return SyncResult.skipped('offline');
    }

    final lastSyncTs = await _getLastSyncTimestamp();
    final deviceId = await _getDeviceId();
    
    try {
      // Phase 1: 拉取服务端变更
      final pullResult = await _pullChanges(lastSyncTs, deviceId);
      
      // Phase 2: 处理冲突
      if (pullResult.conflicts.isNotEmpty) {
        await _conflictResolver.resolve(pullResult.conflicts);
      }
      
      // 应用服务端变更到本地
      await _applyServerChanges(pullResult.changes);
      
      // Phase 3: 推送本地待同步操作
      final pushResult = await _pushLocalOperations(deviceId);
      
      // Phase 4: 确认同步
      if (pushResult.batchId != null) {
        await _acknowledge(pushResult.batchId!, pullResult.serverTimestamp);
      }
      
      // 更新同步时间戳
      await _updateLastSyncTimestamp(pullResult.serverTimestamp);
      
      return SyncResult.success(
        pulledCount: pullResult.changes.length,
        pushedCount: pushResult.successCount,
        conflictCount: pullResult.conflicts.length,
      );
    } on SyncException catch (e) {
      return SyncResult.failed(e.message);
    }
  }
  
  /// 推送本地操作到服务端
  Future<PushResult> _pushLocalOperations(String deviceId) async {
    final pendingOps = await _queue.getPendingBatch(limit: 50);
    if (pendingOps.isEmpty) return PushResult.empty();
    
    // 按 depends_on 拓扑排序
    final sorted = _topologicalSort(pendingOps);
    
    // 分批推送
    int successCount = 0;
    String? batchId;
    
    for (int i = 0; i < sorted.length; i += 50) {
      final batch = sorted.skip(i).take(50).toList();
      
      // 标记为 syncing
      for (final op in batch) {
        await _queue.updateStatus(op.id, 'syncing');
      }
      
      try {
        final response = await _api.post('/api/v1/sync/push', data: {
          'deviceId': deviceId,
          'batchId': batchId ??= _uuid.v4(),
          'operations': batch.map((op) => {
            'idempotencyKey': op.idempotencyKey,
            'operationType': op.operationType,
            'targetEntity': op.targetEntity,
            'targetId': op.targetId,
            'payload': jsonDecode(op.payload),
            'clientTimestamp': op.createdAt,
            'clientVersion': op.version,
          }).toList(),
        });
        
        final results = response.data['results'] as List;
        for (final result in results) {
          final key = result['idempotencyKey'];
          final op = batch.firstWhere((o) => o.idempotencyKey == key);
          
          if (result['status'] == 'success') {
            await _queue.markSuccess(op.id);
            successCount++;
          } else if (result['status'] == 'conflict') {
            await _handlePushConflict(op, result);
          }
        }
      } catch (e) {
        // 批次失败，回滚状态
        for (final op in batch) {
          await _queue.incrementRetry(op.id, errorMessage: e.toString());
        }
        // 如果是网络错误，停止后续批次
        if (e is NetworkException) break;
      }
    }
    
    return PushResult(batchId: batchId, successCount: successCount);
  }
}
```

## 7. 冲突检测与解决策略

### 7.1 冲突检测机制

冲突发生于：同一实体在两个不同端（或设备）上有版本号交叉的修改。

```
冲突判定条件：
  local_version > 0  (本地有修改)
  AND
  server_version > local_last_known_server_version  (服务端有更新版本)
```

### 7.2 冲突解决策略矩阵

| 实体类型 | 冲突字段 | 解决策略 | 说明 |
|----------|----------|----------|------|
| answer_record | 几乎不冲突 | **服务端优先** | 答题记录是追加式的，服务端有权威 |
| mistake_record.tags | 标签列表 | **合并** | 双方标签取并集 |
| mistake_record.reviewCount | 复习次数 | **取最大值** | max(local, server) |
| mistake_record.masteryLevel | 掌握程度 | **服务端优先** | 服务端有更完整的计算逻辑 |
| mistake_record.notes | 笔记内容 | **合并** | 按时间戳保留最新 |
| learning_progress | 进度百分比 | **取最大值** | 进度只增不减 |
| learning_progress.completedSections | 已完成章节 | **合并** | 双方集合取并集 |
| study_plan.tasks | 任务列表 | **服务端优先** | 计划由服务端生成 |
| study_plan.completionStatus | 完成状态 | **取最大值** | 一端完成即完成 |
| user_preference | 偏好设置 | **最后写入胜出 (LWW)** | 以较新的时间戳为准 |
| ai_conversation.messages | 对话消息 | **合并追加** | 按时间排序合并消息列表 |
| check_in_record | 打卡记录 | **服务端优先** | 防止重复打卡 |

### 7.3 冲突解决器实现

```dart
class ConflictResolver {
  final Map<String, EntityConflictStrategy> _strategies = {};

  ConflictResolver() {
    _registerStrategies();
  }

  void _registerStrategies() {
    // 错题记录
    register('mistake_record', MistakeRecordConflictStrategy());
    // 学习进度
    register('learning_progress', LearningProgressConflictStrategy());
    // 学习计划
    register('study_plan', StudyPlanConflictStrategy());
    // 答题记录
    register('answer_record', ServerWinsStrategy());
    // 用户偏好
    register('user_preference', LastWriterWinsStrategy());
    // AI 对话
    register('ai_conversation', MessageMergeStrategy());
    // 打卡记录
    register('check_in_record', ServerWinsStrategy());
    // 收藏/笔记
    register('favorite', LastWriterWinsStrategy());
    register('note', LastWriterWinsStrategy());
  }

  Future<void> resolve(List<SyncConflict> conflicts) async {
    for (final conflict in conflicts) {
      final strategy = _strategies[conflict.entityType] ?? ServerWinsStrategy();
      final resolution = await strategy.resolve(conflict);
      
      // 应用解决结果到本地
      await _applyResolution(resolution);
      
      // 如果需要，推送解决结果到服务端
      if (resolution.notifyServer) {
        await _notifyServerResolution(resolution);
      }
    }
  }
}

/// 错题记录冲突策略：字段级合并
class MistakeRecordConflictStrategy implements EntityConflictStrategy {
  @override
  Future<ConflictResolution> resolve(SyncConflict conflict) async {
    final local = conflict.localData;
    final server = conflict.serverData;
    final merged = <String, dynamic>{};
    
    // 所有字段先取服务端值
    merged.addAll(server);
    
    // tags: 取并集
    final localTags = List<String>.from(local['tags'] ?? []);
    final serverTags = List<String>.from(server['tags'] ?? []);
    merged['tags'] = {...serverTags, ...localTags}.toList();
    
    // reviewCount: 取最大值
    merged['reviewCount'] = max(
      (local['reviewCount'] ?? 0) as int,
      (server['reviewCount'] ?? 0) as int,
    );
    
    // masteryLevel: 服务端优先（保留 merged 中的 server 值）
    // notes: 按时间戳保留最新
    final localNoteTs = local['notesUpdatedAt'] ?? '';
    final serverNoteTs = server['notesUpdatedAt'] ?? '';
    if (localNoteTs.compareTo(serverNoteTs) > 0) {
      merged['notes'] = local['notes'];
      merged['notesUpdatedAt'] = localNoteTs;
    }
    
    return ConflictResolution(
      entityType: conflict.entityType,
      entityId: conflict.entityId,
      resolvedData: merged,
      action: ResolutionAction.merge,
      notifyServer: true, // 需要通知服务端合并结果
    );
  }
}

/// 最后写入胜出策略
class LastWriterWinsStrategy implements EntityConflictStrategy {
  @override
  Future<ConflictResolution> resolve(SyncConflict conflict) async {
    final localTs = conflict.localData['updatedAt'] ?? conflict.localData['createdAt'] ?? '';
    final serverTs = conflict.serverData['updatedAt'] ?? conflict.serverData['createdAt'] ?? '';
    
    final localWins = localTs.compareTo(serverTs) > 0;
    
    return ConflictResolution(
      entityType: conflict.entityType,
      entityId: conflict.entityId,
      resolvedData: localWins ? conflict.localData : conflict.serverData,
      action: localWins ? ResolutionAction.localWins : ResolutionAction.serverWins,
      notifyServer: localWins,
    );
  }
}
```

### 8.1 缓存内容优先级

| 用户头像/昵称 | 基础用户信息 | 登录后 | 7 天 | 1 MB |

### 8.2 预加载调度器

```dart
class PreloadScheduler {
  final NetworkMonitor _network;
  final StorageMonitor _storage;
  
  /// WiFi 下的后台预加载任务
  static const _wifiPreloadTasks = [
    PreloadTask(key: 'next_chapter_questions', priority: 1, sizeEstimate: 2 * 1024 * 1024),
    PreloadTask(key: 'knowledge_summaries', priority: 2, sizeEstimate: 5 * 1024 * 1024),
    PreloadTask(key: 'resource_assets', priority: 5, sizeEstimate: 10 * 1024 * 1024),
  ];
  
  /// 触发预加载
  Future<void> schedulePreload() async {
    // 仅在 WiFi 且充电时执行大流量预加载
    if (_network.currentConnectionType != ConnectivityResult.wifi) return;
    
    // 检查存储空间（至少保留 500MB 可用）
    final available = await _storage.getAvailableSpace();
    if (available < 500 * 1024 * 1024) return;
    
    // 检查当前缓存总大小
    final cacheSize = await _storage.getCacheSize();
    final maxCacheSize = 200 * 1024 * 1024; // 200MB 上限
    
    if (cacheSize >= maxCacheSize) {
      await _evictExpiredCache();
      return;
    }
    
    // 按优先级执行预加载
    for (final task in _wifiPreloadTasks) {
      if (cacheSize + task.sizeEstimate > maxCacheSize) break;
      await _executePreloadTask(task);
    }
  }
}
```

```
    └─ SyncEngine 分阶段处理：
    
    Phase 1 - 拉取服务端变更
    └─ 服务端在离线期间可能有：
       ├─ 新的学习计划任务
       ├─ 家长端更新的管控设置
       └─ 系统推送的通知
    └─ 本地应用变更
    
    Phase 2 - 推送本地操作（分批）
    └─ 第 1 批 (50条): answer_submit (priority=1)
    └─ 第 2 批 (50条): answer_submit
    └─ 第 3 批 (50条): answer_submit
    └─ 第 4 批 (30条): mistake_review + learning_progress
    └─ 第 5 批 (10条): session_duration + behavior

    └─ 服务端重新计算学习画像
    └─ 触发学情报告更新
```

### 10.4 服务端同步处理逻辑

```java
@Service
public class SyncService {
    
    @Transactional
    public SyncPushResponse pushOperations(String deviceId, SyncPushRequest request) {
        List<OperationResult> results = new ArrayList<>();
        List<SyncConflict> conflicts = new ArrayList<>();
        
        for (SyncPushOperation op : request.getOperations()) {
            // 幂等性检查
            if (operationLogRepository.existsByIdempotencyKey(op.getIdempotencyKey())) {
                results.add(OperationResult.success(op.getIdempotencyKey(), 
                    operationLogRepository.findByIdempotencyKey(op.getIdempotencyKey()).get().getVersion()));
                continue;
            }
            
            // 获取实体当前版本
            Integer currentVersion = entityVersionRepository
                .getVersion(op.getTargetEntity(), op.getTargetId());
            
            // 冲突检测：客户端版本与服务端版本不一致
            if (currentVersion != null && op.getClientVersion() != null 
                && !currentVersion.equals(op.getClientVersion())) {
                // 检查是否真的冲突（字段级别）
                EntityData serverData = entityRepository.get(op.getTargetEntity(), op.getTargetId());
                SyncConflict conflict = detectConflict(op, serverData, currentVersion);
                if (conflict != null) {
                    conflicts.add(conflict);
                    results.add(OperationResult.conflict(op.getIdempotencyKey(), currentVersion));
                    continue;
                }
            }
            
            // 应用操作
            try {
                int newVersion = applyOperation(op);
                
                // 记录变更日志
                syncChangelogRepository.insert(SyncChangelog.builder()
                    .entityType(op.getTargetEntity())
                    .entityId(op.getTargetId())
                    .operation(mapOperationType(op.getOperationType()))
                    .changedFields(op.getPayload())
                    .version(newVersion)
                    .changedBy(deviceId)
                    .createdAt(Instant.now())
                    .build());
                
                // 记录幂等键
                operationLogRepository.insert(OperationLog.builder()
                    .idempotencyKey(op.getIdempotencyKey())
                    .entityType(op.getTargetEntity())
                    .entityId(op.getTargetId())
                    .version(newVersion)
                    .processedAt(Instant.now())
                    .build());
                
                results.add(OperationResult.success(op.getIdempotencyKey(), newVersion));
            } catch (Exception e) {
                results.add(OperationResult.failed(op.getIdempotencyKey(), e.getMessage()));
            }
        }
        
        return SyncPushResponse.builder()
            .batchId(request.getBatchId())
            .results(results)
            .conflicts(conflicts)
            .serverTimestamp(Instant.now())
            .build();
    }
}
```

## 11. 错误处理

### 11.1 错误码定义

| 错误码 | 说明 | 客户端处理 |
|--------|------|-----------|
| `SYNC_001` | 同步版本冲突 | 触发冲突解决流程 |
| `SYNC_002` | 幂等键重复 | 忽略，标记为成功 |
| `SYNC_003` | 批次部分失败 | 重试失败的操作 |
| `SYNC_004` | 同步频率超限 | 退避 30s 后重试 |
| `SYNC_005` | 设备未注册 | 重新注册设备 |
| `SYNC_006` | 实体不存在 | 本地标记为已删除 |
| `SYNC_007` | 载荷格式错误 | 记录日志，标记操作为 dead |
| `SYNC_008` | 存储空间不足 | 提示用户清理空间 |
| `SYNC_009` | 离线队列已满 (上限 10000) | 丢弃最低优先级操作 |
| `SYNC_010` | 同步中服务端不可用 | 退避重试 |

### 11.2 重试策略

```dart
class SyncRetryPolicy {
  /// 重试退避时间（指数退避 + 抖动）
  static Duration getRetryDelay(int retryCount, String errorCode) {
    // 基础退避：指数退避
    final baseDelay = Duration(seconds: math.pow(2, retryCount).toInt());
    final cappedDelay = baseDelay > const Duration(minutes: 5) 
        ? const Duration(minutes: 5) 
        : baseDelay;
    
    // 加入抖动（±30%）
    final jitter = cappedDelay.inSeconds * 0.3;
    final jitteredSeconds = cappedDelay.inSeconds + 
        (Random().nextDouble() * 2 - 1) * jitter;
    
    // 特定错误码使用固定延迟
    switch (errorCode) {
      case 'SYNC_004': // 频率超限
        return const Duration(seconds: 30);
      case 'SYNC_010': // 服务端不可用
        return const Duration(minutes: 1);
      default:
        return Duration(seconds: jitteredSeconds.round());
    }
  }
  
  /// 是否应该重试
  static bool shouldRetry(int retryCount, int maxRetries, String errorCode) {
    if (retryCount >= maxRetries) return false;
    
    // 不可重试的错误码
    const nonRetryable = {'SYNC_006', 'SYNC_007'};
    if (nonRetryable.contains(errorCode)) return false;
    
    return true;
  }
}
```

```dart
class DeadLetterHandler {
  Future<void> handleDeadLetters() async {
    final deadOps = await _queue.getDeadLetters();
    if (deadOps.isEmpty) return;
    
    // 按操作类型分组汇总

  }
```

## 14. 安全考虑

### 14.1 数据安全

1. **本地加密**：SQLite 数据库使用 SQLCipher 加密，密钥派生自用户登录凭证
2. **传输加密**：同步请求强制 HTTPS，证书固定 (Certificate Pinning)
3. **敏感字段**：离线缓存的答案数据使用 AES-256 加密存储
4. **设备绑定**：同步操作需携带设备 ID，服务端验证设备合法性

### 14.2 防滥用

1. **同步频率限制**：每设备每分钟最多 6 次同步请求
2. **批量大小限制**：单次推送最多 50 条操作
3. **幂等性保证**：防止网络重传导致数据重复
4. **数据完整性校验**：每条操作附带 payload hash，服务端验证
