# 服务端-试卷手写痕迹智能擦除与空白卷还原重练引擎 详细设计

> 对应原始设计文档：6.3 拍照搜题与习题答疑模块、6.6 错题整理模块（错题重练场景）、9.5 拍题答疑交互设计。
> 现有《图片处理与 OCR 识别管线》《服务端-学生试卷扫描智能识别与考试错题自动归档入库引擎》均侧重"识别与归档"，未覆盖"**将已作答试卷还原为空白卷用于重练/打印**"的图像擦除能力。本文档补齐该细化空白。

---

## 1. 模块概述

### 1.1 功能定位

学生在纸质试卷/练习册上作答后，拍照即可对手写笔迹（中性笔、钢笔、铅笔、荧光笔标记）进行智能擦除，还原出接近原始的空白卷图像，用于：

1. **错题重练**：擦除整卷后重新作答，检验订正效果（与错题本"重练"动作闭环）。
2. **空白卷打印**：家长/学生将还原后的空白卷导出 PDF 打印，供线下重考（与错题打印、学习内容 PDF 导出模块联动）。
3. **卷面复用**：教辅资料拍摄一次，多次刷题（受版权约束，见 §11 合规）。
4. **分题擦除**：仅擦除指定题目的作答区域，保留其余笔迹，用于"只重做错题"场景。
5. **对照模式**：左原卷 / 右空白卷双栏展示，配合解析进行复盘讲评。

### 1.2 非目标（明确不做）

- 不做 OCR 题目识别本身（属图片处理与 OCR 识别管线）。
- 不做手写答案内容判分（属学生手写答案识别与手写体智能批改引擎）。
- 不做试卷结构切分（属试卷扫描识别引擎）；本引擎消费其输出的题目区域坐标。
- 不处理红色印刷内容（印章、红头文件）的保留/擦除裁决，V1 一律保留彩色印刷内容。

### 1.3 关键指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 擦除任务提交到出图 P95 | ≤ 15s（整卷 A4） | 含排队与推理 |
| 单题区域擦除 P95 | ≤ 4s | 小区域 GPU 推理 |
| 擦除后可读性 | 印刷文字 SSIM ≥ 0.92（相对原图） | 质检模型自动评估 |
| 笔迹残留率 | ≤ 3%（笔画级漏检） | 质检模型自动评估 |
| 误擦率（印刷被擦除） | ≤ 1% | 质检模型自动评估，超阈值自动回退原图 |
| 日均承载 | 10 万张（可水平扩缩） | 按 20 万 DAU 的 5% 渗透率估算 |

### 1.4 设计原则

- **两段式擦除**：传统 CV 笔迹检测（确定性、可解释、零成本优先）+ AI 图像修复（Diffusion/UNet inpainting，处理 CV 漏检与阴影残留）混合管线，纯 AI 直出方案仅在 CV 置信度低时启用。
- **像素可追溯**：擦除为派生数据，原图永不修改；所有产物与原图通过血缘关系绑定，支持对账与审计。
- **质检门禁**：每张产物图必须经过自动质检（印刷保留度/笔迹残留度），不合格自动重试或降级为"仅 CV 擦除"版本，绝不允许明显破损图下发到客户端。
- **成本分层**：小区域擦除走轻量模型，整卷擦除走重型模型；学生端免费额度有限（与额度管控引擎联动），打印导出走增值权益。

### 2.2 模块职责边界

| 模块 | 职责 | 不做的事 |
| --- | --- | --- |
| 任务编排 | 接收请求、参数校验、任务拆分（整卷/分题）、队列投递、状态机维护 | 不直接执行图像推理 |
| 区域检测 | 调用 CV 模型产出笔迹掩码与置信度 | 不判定题目边界（输入来自扫描识别引擎） |
| 擦除执行 | 按策略执行 CV 填充 / AI inpainting / 二次处理 | 不做质量裁决 |
| 质量检验门禁 | 产物质检、重试/降级裁决、结果落库 | 不修改图像内容 |
| 模型服务层 | 模型加载、批量推理、GPU 调度 | 无业务逻辑 |

### 2.3 上下游依赖

| 依赖方 | 依赖内容 | 集成方式 |
| --- | --- | --- |
| 统一异步任务进度中心 | 任务状态透传、客户端轮询/推送 | 复用，不自建状态推送 |
| 试卷扫描识别引擎 | 题目区域坐标（bbox 列表）、版面类型 | 内部 RPC，缓存 24h |
| 错题本服务 | 错题 ID 列表（分题擦除场景）、重练记录回写 | 事件总线 + RPC |
| 额度管控引擎 | 擦除次数额度校验与扣减 | 同步 RPC（提交前置） |
| 对象存储服务 | 原图/产物存储、预签名 URL 下发 | SDK |
| GPU 推理资源池 | inpainting 模型推理 | 内部 gRPC |
| 内容安全审核服务 | 仅当用户上传图含敏感内容时的兜底审核 | 异步事件（检出率极低，见 §11） |

## 3. 数据结构定义

### 3.1 核心表 DDL（MySQL 8.0，InnoDB，utf8mb4）

```sql
-- 3.1.1 擦除任务主表
CREATE TABLE paper_clean_task (
  id               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '任务ID(雪花)',
  task_no          VARCHAR(32)  NOT NULL COMMENT '对外任务号: PC+yyyyMMdd+8位序列',
  user_id          BIGINT UNSIGNED NOT NULL COMMENT '发起用户(学生)',
  student_id       BIGINT UNSIGNED NOT NULL COMMENT '学生档案ID(家庭多孩隔离)',
  clean_mode       VARCHAR(16)  NOT NULL COMMENT 'WHOLE=整卷擦除, REGION=分题擦除, ANSWER_AREA=仅擦作答区',
  source_image_id  BIGINT UNSIGNED NOT NULL COMMENT '源图ID(paper_source_image)',
  scope_ref_type   VARCHAR(32)  DEFAULT NULL COMMENT '分题擦除时题目来源: MISTAKE=错题本, EXAM_PAPER=试卷识别',
  scope_ref_ids    JSON         DEFAULT NULL COMMENT '题目/错题ID列表 ["123","456"]，整卷时为NULL',
  status           VARCHAR(24)  NOT NULL DEFAULT 'PENDING'
                   COMMENT 'PENDING/DETECTING/ERASING/QC_CHECKING/SUCCEEDED/FAILED/DEGRADED/CANCELED/EXPIRED',
  retry_count      INT          NOT NULL DEFAULT 0,
  degrade_level    TINYINT      NOT NULL DEFAULT 0 COMMENT '0=完整管线 1=仅CV擦除降级 2=原图直返(彻底失败)',
  qc_score         DECIMAL(5,4) DEFAULT NULL COMMENT '质检综合分 0~1',
  fail_code        VARCHAR(16)  DEFAULT NULL COMMENT '失败业务码，见 §7.3',
  fail_reason      VARCHAR(512) DEFAULT NULL,
  client_request_id VARCHAR(64) NOT NULL COMMENT '客户端幂等键',
  idem_key         VARCHAR(80)  NOT NULL COMMENT '唯一幂等键: user_id+client_request_id',
  expire_at        DATETIME     NOT NULL COMMENT '产物保留截止时间(默认72h)',
```

### 3.2 状态枚举（TypeScript 契约）

```typescript
/** 擦除任务状态机（唯一 SSOT，与 DB status 字段一一对应） */
enum CleanTaskStatus {
  PENDING      = 'PENDING',      // 已受理，待入队
  DETECTING    = 'DETECTING',    // CV 笔迹检测中
  ERASING      = 'ERASING',      // AI 修复/填充执行中
  QC_CHECKING  = 'QC_CHECKING',  // 质量检验门禁中
  SUCCEEDED    = 'SUCCEEDED',    // 质检通过，产物可用
  DEGRADED     = 'DEGRADED',     // 降级成功（仅 CV 擦除/部分区域失败），产物可用但有提示
  FAILED       = 'FAILED',       // 彻底失败，不返还额度(因成本已发生) 或返还见 §7.4 裁决
  CANCELED     = 'CANCELED',     // 用户取消（仅 PENDING/DETECTING 可取消）
  EXPIRED      = 'EXPIRED',      // 产物过期，OSS 已清理
}

/** 允许的迁移（守卫表，服务端强校验） */
const TRANSITIONS: Record<CleanTaskStatus, CleanTaskStatus[]> = {
  PENDING:     [DETECTING, CANCELED],
  DETECTING:   [ERASING, CANCELED, FAILED],
  ERASING:     [QC_CHECKING, FAILED],
  QC_CHECKING: [SUCCEEDED, DEGRADED, ERASING /*重试*/, FAILED],
  SUCCEEDED:   [EXPIRED],
  DEGRADED:    [EXPIRED],
  FAILED:      [],               // 终态；如需重试须新建任务（新幂等键规则见 §4.5）
  CANCELED:    [],
  EXPIRED:     [],
};

/** 降级级别 */
enum DegradeLevel {
  FULL    = 0,  // CV + AI 完整管线
  CV_ONLY = 1,  // AI 修复失败/超时，仅 CV 填充（可能残留阴影）
  RAW     = 2,  // 彻底失败兜底：原图直返 + 明确失败提示（不视为成功）
}
```

## 4. API 接口设计

> 统一规范：HTTPS + JSON；鉴权 `Authorization: Bearer <token>`；错误响应遵循《服务端统一业务异常码与错误分类体系》，本文档错误码段使用 `13xxxx`（图像处理域预留子段，若冲突以错误码总表为准）。

### 4.1 提交擦除任务

```
POST /api/v1/paper-clean/tasks
Content-Type: application/json
```

请求：

```json
{
  "clientRequestId": "uuid-v4-由客户端生成",
  "cleanMode": "WHOLE",
  "sourceImageId": 8821345,
  "scopeRefType": "MISTAKE",
  "scopeRefIds": [99123, 99124],
  "options": {
    "keepMarkings": true,
    "outputFormat": "JPEG",
    "printDpi": 300
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| clientRequestId | string | 是 | 幂等键，重复提交返回同一任务 |
| cleanMode | enum | 是 | WHOLE / REGION / ANSWER_AREA |
| sourceImageId | long | 是 | 已上传源图 ID（先走 §4.2 上传） |
| scopeRefType | string | 分题必填 | MISTAKE / EXAM_PAPER |
| scopeRefIds | long[] | 分题必填 | 题目/错题 ID 列表，≤ 30 个 |
| options.keepMarkings | bool | 否 | 是否保留教师批改符号（红笔），默认 true |
| options.outputFormat | string | 否 | JPEG（默认）/ PNG（打印建议） |
| options.printDpi | int | 否 | 打印分辨率 150/300，默认 300 |

响应 `202 Accepted`：

```json
{
  "code": 0,
  "data": {
    "taskNo": "PC2026110900001234",
    "status": "PENDING",
    "estimatedSeconds": 12,
    "quota": { "type": "FREE_DAILY", "remaining": 2 }
  }
}
```

异常响应：

| HTTP | 业务码 | 场景 |
| --- | --- | --- |
| 400 | 130001 | 参数校验失败（scopeRefIds 超上限等） |
| 400 | 130002 | sourceImageId 不属于当前用户 |
| 409 | 130003 | 同 clientRequestId 且前任务进行中（返回原 taskNo，非报错语义） |
| 402 | 130004 | 额度不足（返回 quota 详情与购买引导） |
| 422 | 130005 | 源图质量过低（模糊/反光/倾斜角>15°，客户端应先做拍摄质检） |

### 4.2 源图上传（复用统一文件上传服务，补充业务回调）

```
POST /api/v1/files/upload-init   ← 统一文件上传服务
```

业务侧登记：

```
POST /api/v1/paper-clean/source-images
{ "fileId": 123, "sha256": "...", "captureMeta": {...} }
→ 200 { "sourceImageId": 8821345 }
```

说明：文件传输走统一上传服务的分片/断点续传通道（见《客户端文件上传服务与断点续传机制》），本引擎只登记血缘。

### 4.3 查询任务状态（客户端轮询，长轮询兜底）

```
GET /api/v1/paper-clean/tasks/{taskNo}
→ 200
{
  "code": 0,
  "data": {
    "taskNo": "PC2026110900001234",
    "status": "SUCCEEDED",
    "progress": 100,
    "degradeLevel": 0,
    "outputs": [
      {
        "outputType": "FULL",
        "imageUrl": "https://oss.../signed?exp=3600",
        "thumbUrl": "https://oss.../signed?exp=3600",
        "width": 2480, "height": 3507
      },
      {
        "outputType": "CLIP", "clipRefId": 99123,
        "imageUrl": "...", "thumbUrl": "..."
      }
    ],
    "qc": { "score": 0.973, "verdict": "PASS" },
    "expireAt": "2026-11-12T16:35:00+08:00"
  }
}
```

| status | progress 语义 |
| --- | --- |
| PENDING/DETECTING | 10 |
| ERASING | 10 + 70×(已完成区域/总区域) |
| QC_CHECKING | 85 |
| SUCCEEDED/DEGRADED | 100 |
| FAILED/CANCELED/EXPIRED | —（带 failCode/failReason） |

轮询策略：1s/2s/4s/8s 指数退避，上限 15s，总超时 120s 后建议客户端走推送（统一异步任务进度中心的 WebSocket/SSE 通道）。

### 4.4 取消任务

```
POST /api/v1/paper-clean/tasks/{taskNo}/cancel
→ 200 { "status": "CANCELED" }
→ 409 130006  当前状态不可取消（ERASING 之后不可取消，GPU 成本已发生）
```

### 4.5 失败重试

```
POST /api/v1/paper-clean/tasks/{taskNo}/retry
→ 202 { "taskNo": "PC...新任务号" }
```

约束：重试生成**新任务**（沿用同一 sourceImageId），客户端必须更换 clientRequestId；同任务 24h 内限重试 3 次（防 GPU 成本刷爆）。额度裁决：FAIL_RETRY 首 3 次不重复扣额度，见 §7.4。

### 4.6 产物续期 / 删除

```
POST /api/v1/paper-clean/tasks/{taskNo}/outputs/renew   → 延长 expireAt 至 +72h（限 2 次）
```

### 5.2 笔迹检测与策略路由（关键伪代码）

```java
// 5.2.1 CV 笔迹检测输出
public record InkDetectionResult(
    Mat inkMask,                 // 0/1 掩码，与原图同尺寸
    float meanConfidence,        // 全图平均置信度
    List<InkRegion> regions      // 连通域列表
) {}

public record InkRegion(
    Rect bbox,
    float confidence,
    InkType type,                // BLUE_PEN/BLACK_PEN/PENCIL/HIGHLIGHTER/RED_MARK
    boolean overlapPrint         // 与印刷文字笔画重叠（高风险区）
) {}

// 5.2.2 策略路由
public ErasePlan route(InkDetectionResult det, CleanOptions opt) {
    var plan = new ErasePlan();
    for (var r : det.regions()) {
        if (r.type() == RED_MARK && opt.keepMarkings()) {
            plan.keep(r);                                   // 保留批改痕迹
        } else if (r.confidence() >= 0.90 && !r.overlapPrint()) {
            plan.lamaFill(r);                               // 快通道
        } else if (r.confidence() >= 0.55 || r.overlapPrint()) {
            plan.sdInpaint(r, InpaintStrength.STANDARD);    // 精通道
        } else {
            plan.sdInpaint(r, InpaintStrength.CONSERVATIVE);// 保守策略+局部人工质检
        }
    }
    // 荧光笔：先做颜色去饱和+低透明度混合，再走 inpaint，避免色块残留
    plan.highlightPreprocess(HLPolicy.DESATURATE_BLEND);
    return plan;
}
```

### 5.4 质量检验门禁（QC Gate）

```python
# qc-model: 双指标轻量网络 (MobileNetV3 二分类 + SSIM 计算)
def qc_check(origin, cleaned, ink_mask_before) -> QCVerdict:
    print_ssim = compute_ssim(origin_print_region, cleaned_print_region)  # 印刷保留度
    residual = ink_residual_ratio(cleaned, ink_mask_before)               # 笔迹残留率
    over_erase = over_erase_ratio(origin, cleaned)                        # 误擦率

    if print_ssim >= 0.92 and residual <= 0.03 and over_erase <= 0.01:
        return PASS
    if residual <= 0.08 and print_ssim >= 0.85:
        return DEGRADABLE   # 允许降级下发，客户端提示"部分笔迹残留"
    return REJECT

# REJECT 处理：单区域重试(≤1次, 降 denoise 重跑) → 仍 REJECT 则整任务 FAILED 或 DEGRADED(CV_ONLY)
```

### 5.5 分题擦除流程差异

1. 从错题本/试卷识别服务取题目 bbox（缓存 24h）。
2. bbox 外扩 12px 作为擦除区域，区域外像素原样透传（零推理）。
3. 每题独立小图推理，批量打包进一次 GPU 调用（动态 batch，最大 8）。
4. 产物按 clipRefId 一一对应下发，客户端在错题详情页直接嵌入预览。

### 6.2 并发与幂等守卫

| 守卫 | 规则 | 实现 |
| --- | --- | --- |
| G1 幂等提交 | 同 `idem_key` 重复提交返回原任务（含进行中的） | `uk_idem` 唯一键，冲突捕获后 SELECT 返回 |
| G2 状态迁移 | 仅允许 §3.2 TRANSITIONS 表内的迁移 | CAS：`UPDATE ... SET status=? WHERE task_no=? AND status IN (...)`，影响行数=0 抛 409 |
| G3 乐观锁 | 任务记录更新必须携带 version | `version=version+1` 同上 CAS |
| G4 取消窗口 | 仅 PENDING/DETECTING 可取消 | 服务端校验状态，ERASING 后返回 130006 |
| G5 重试限频 | 同任务 24h 重试 ≤3 次 | Redis `INCR paperclean:retry:{taskNo}` TTL 24h |
| G6 额度防超扣 | 提交时预扣（冻结），终态结算；任务超时未终态（15min）自动解冻 | 额度引擎 Freeze/Settle 接口，taskNo 为凭据 |
| G7 多任务并发 | 同一 sourceImageId 最多 2 个进行中任务 | Redis `SET paperclean:inflight:{imageId}:{n}` |
| G8 产物可见性 | 查询/下载必须校验 user_id + student_id 归属 | BFF 层数据权限拦截（行级隔离规范） |
| G9 OSS 越权 | 产物一律短时预签名 URL（≤1h），不使用永久公共读 | 对象存储桶私有 + STS 临时凭证 |

## 7. 错误处理与降级策略

### 7.1 分层降级矩阵

| 层级 | 故障场景 | 降级动作 | 用户感知 |
| --- | --- | --- | --- |
| L1 | CV 模型服务超时（>5s） | 重试 1 次 → 全图走 SD-Inpaint（慢通道） | 处理时间 +8s 左右 |
| L2 | SD-Inpaint GPU 队列拥塞（>60s） | 切换 LaMa 全图填充 + 质检阈值放宽（residual ≤ 0.08 放行 DEGRADED） | 提示"部分笔迹可能残留" |
| L3 | GPU 资源池全忙/故障 | 任务挂起 PENDING（最长 10min）→ 仍失败则 FAILED + 额度返还 | 提示"高峰期，请稍后重试" |
| L4 | 质检 REJECT | 区域级重试 1 次 → DEGRADED(CV_ONLY) 或 FAILED | 见 7.4 |
| L5 | OSS 产物写入失败 | 重试 3 次（指数退避）→ FAILED | 提示系统错误，额度返还 |

### 7.2 重试与补偿

- 所有外部调用（OSS、GPU、错题本 RPC）带超时（连接 2s / 读取 30s）与重试（幂等操作最多 3 次，非幂等仅网络层重试）。
- Outbox Relay 至少一次投递，消费方必须幂等（事件携带 `eventId` 去重表）。
- 任务终态与额度结算对账：每 5min 调度扫描 `status in (PENDING,DETECTING,ERASING,QC_CHECKING) AND updated_at < now()-15min` 的僵尸任务，标记 FAILED 并触发额度解冻（补偿任务）。

## 8. 性能与容量规划

### 8.1 推理资源估算

| 项目 | 数值 |
| --- | --- |
| 整卷擦除平均 GPU 时间（SD-Inpaint, A10） | 6~8s/张（20 steps, 768×1024 切片×4） |
| 分题擦除（8 题打包） | 4s/batch |
| LaMa 快通道 | 0.4s/张（CPU 亦可，2.5s） |
| 峰值 QPS（按 10 万张/日、晚高峰 20% 集中 2h） | ≈ 3 QPS 整卷 + 5 QPS 分题 |
| A10 卡数（N+1 冗余） | 4 张（KEDA 按队列长度 0~8 Pod 伸缩） |

### 8.2 优化手段

1. **切片并行**：整卷按版面列切 4 片，掩码外切片直接跳过推理。
2. **掩码最小化**：仅对 ink mask 外扩 8px 的 bounding rect 区域推理，其余像素原样拷贝。
3. **模型预热与常驻**：Pod 启动即加载 SD-Inpaint（冷启动 40s →  readiness 探针保证）。
4. **结果缓存**：以 `(source_sha256, model_version, options_hash)` 为键缓存产物 7 天，同卷重复擦除直接命中（教材卷面复用场景命中率高）。
5. **缩略图异步**：预览图（长边 1280）由产物异步派生，不阻塞任务终态。

## 9. 安全与合规

1. **未成年人图片保护**：源图与产物均属未成年人学习数据，桶私有、传输 TLS、存储 SSE-KMS；数据出境禁止（GPU 推理资源池部署境内可用区）。
2. **血缘与删除**：用户删除源图/注销账号 → `deleted_flag=1` → 生命周期引擎 30 天内物理删除源图与全部产物（对齐《数据导出与账户注销》《存储资源统一生命周期管理》）。
3. **版权约束**：空白卷还原产物仅限个人学习重练使用；客户端导出页必须带"仅供个人学习使用"水印（与《教育内容数字版权保护》联动），禁止批量导出（单任务产物 ≤ 30 页，日导出 ≤ 3 卷）。
4. **内容安全**：用户上传图可能含个人信息（姓名、学校），V1 不做 OCR 提取即不触碰文本内容；若后续启用"姓名擦除"功能（V2 规划），必须先过内容安全审核服务的个人信息识别，且默认关闭。
5. **模型安全**：Inpaint prompt 为固定模板，禁止用户输入注入 prompt（提示词注入攻击防御规范适用）。

## 12. 验收场景

1. 整卷擦除：蓝色中性笔作答的数学卷 → 15s 内出图，印刷公式清晰无残留，红笔批改保留。
2. 分题擦除：错题本选 5 道错题 → 每题独立产物，bbox 裁剪正确（外扩 12px），未选题目区域笔迹原样保留。
3. 幂等：双击提交/弱网重发 → 仅一个任务，额度仅扣一次。
4. 取消：DETECTING 阶段取消 → 额度全额返还；ERASING 取消 → 409 与话术正确。
5. 降级：GPU 故障注入 → 任务排队提示 → 恢复后完成；或 DEGRADED 产物带"部分残留"提示。
6. 额度：免费 3 次/日用尽 → 402 + 会员引导；会员任务不占用免费额度。
7. 过期：产物 72h 后 URL 失效 → 410，OSS 对象已被生命周期清理。
8. 权限：其他账号访问任务详情/产物 URL → 403；预签名 URL 过期后访问 → 403。
9. 打印导出：300dpi PNG 导出 → 尺寸 ≥ 2480×3507（A4），带版权水印。
10. 重练闭环：擦除产物生成 → 错题本"重练"按钮亮起 → 重练作答记录关联原错题。
