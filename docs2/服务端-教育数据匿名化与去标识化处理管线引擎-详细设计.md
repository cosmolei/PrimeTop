# 服务端 - 教育数据匿名化与去标识化处理管线引擎 详细设计

## 1. 模块概述

### 1.1 背景与目标

PrimeTop 作为覆盖幼儿至高中全学段的 AI 辅助学习平台，持续采集大量未成年人学习行为数据、答题记录、学情画像等敏感信息。在以下场景中，需要将原始数据转化为匿名化/去标识化数据集后才能安全使用：

| 场景 | 说明 |
| --- | --- |
| 数据分析与 BI | 学习行为统计、AB 实验效果分析、运营看板 |
| 模型训练 | AI 模型微调训练数据集准备（RLHF 反馈数据等） |
| 学术研究 | 与教育研究机构合作，共享学习行为研究数据 |
| 第三方合作 | B 端合作方向合作方提供脱敏后的学情趋势数据 |
| 数据开放 | 教育行业报告、白皮书中的统计数据生成 |
| 内部测试 | 测试环境使用接近真实的脱敏数据 |

现有 `数据脱敏规则引擎` 负责在线展示场景的动态遮蔽（如手机号显示为 138****5678），`密钥管理` 负责加密密钥生命周期管理。本模块聚焦于**离线/近线批量数据的匿名化处理管线**，解决"如何安全地将生产数据用于分析、研究、训练和共享"的问题。

### 1.2 设计目标

1. **不可逆性保障**：匿名化后的数据无法通过合理手段还原到具体学生个人。
2. **数据可用性**：在匿名化前提下，尽可能保留数据的统计特征和分析价值。
3. **合规对标**：满足《个人信息保护法》（PIPL）、《数据安全法》（DSL）、《未成年人保护法》及《儿童个人信息网络保护规定》的匿名化要求。
4. **风险量化**：对每次匿名化输出提供可量化的重标识风险评估报告。
5. **管线自动化**：支持定时调度和按需触发，自动完成抽取→清洗→匿名→审核→交付的完整链路。
6. **全程审计**：匿名化操作的全链路可追溯，满足合规审计要求。

### 1.3 与现有模块的关系

| 现有模块 | 关系 |
| --- | --- |
| 数据脱敏规则引擎 | 展示层实时脱敏；本模块是数据层批量匿名化，两者互补 |
| 密钥管理与敏感配置安全策略 | 本模块的加密型匿名化操作依赖其密钥管理基础设施 |
| 数据安全与隐私合规体系 | 本模块是该体系在"数据使用"环节的具体落地 |
| 学习数据仓库与BI分析平台 | 本模块为其提供合规的匿名化数据源 |
| 数据血缘追踪与元数据治理平台 | 匿名化数据集的血缘关系注册到该平台 |
| 数据质量监控与异常数据自动检测引擎 | 匿名化后数据的质量校验复用该引擎 |
| 统一审计日志与操作追溯系统 | 匿名化操作日志写入该系统 |

### 1.4 术语定义

| 术语 | 定义 |
| --- | --- |
| **PII**（Personally Identifiable Information） | 可直接或间接识别到自然人的信息 |
| **准标识符**（Quasi-Identifier） | 单独不能识别个体，但组合后可能唯一识别的数据（如年级+学校+出生月份） |
| **K-匿名**（K-Anonymity） | 数据集中每条记录至少与 K-1 条其他记录在准标识符上不可区分 |
| **L-多样性**（L-Diversity） | 在 K-匿名基础上，每个等价类中敏感属性至少有 L 个不同值 |
| **T-贴近**（T-Closeness） | 等价类中敏感属性的分布与整体分布的距离不超过 T |
| **差分隐私**（Differential Privacy） | 在查询结果中注入可控噪声，使得任意单条记录的存在与否对输出影响有界 |
| **重标识风险**（Re-identification Risk） | 匿名化数据被关联攻击还原到具体个体的概率 |
| **假名化**（Pseudonymization） | 用可逆映射替换直接标识符，映射表单独保管 |

```python
from enum import Enum

class AnonymizationTechnique(str, Enum):
    """匿名化技术枚举"""
    
    # ── 不可逆变换 ──
    HASH = "HASH"                          # 单向哈希 (SHA-256 + 盐)
    HASH_WITH_SALT = "HASH_WITH_SALT"      # 加盐哈希 (每次使用不同盐值)
    TRUNCATE = "TRUNCATE"                  # 截断 (保留前 N 位，后面丢弃)
    SUPPRESS = "SUPPRESS"                  # 完全抑制 (直接删除字段)
    RANDOMIZE = "RANDOMIZE"               # 随机替换 (从同分布中随机抽样)
    
    # ── 可逆变换 (假名化) ──
    PSEUDONYMIZE = "PSEUDONYMIZE"          # 假名化 (映射表单独加密保管)
    FORMAT_PRESERVING_ENCRYPT = "FPE"      # 格式保留加密 (密文与明文格式相同)
    
    # ── 泛化与粒度退化 ──
    GENERALIZE = "GENERALIZE"              # 泛化 (如精确年龄→年龄段)
    AGGREGATE = "AGGREGATE"                # 聚合 (多行合并为统计值)
    BINNING = "BINNING"                   # 分箱 (连续值离散化)
    
    # ── 扰动 ──
    PERTURBATION = "PERTURBATION"          # 数值微扰 (加 Laplace/Gaussian 噪声)
    SWAP = "SWAP"                          # 数据交换 (同类记录间交换属性值)
    
    # ── 差分隐私 ──
    DP_LAPLACE = "DP_LAPLACE"             # Laplace 机制 (数值型)
    DP_EXPONENTIAL = "DP_EXPONENTIAL"      # 指数机制 (类别型)
    
    # ── 组合技术 ──
    K_ANONYMIZE = "K_ANONYMIZE"            # K-匿名化 (对准标识符组做泛化+抑制)
```

## 4. 核心算法设计

### 4.1 K-匿名化算法（Mondrian 多维泛化）

K-匿名化的核心目标：确保数据集中任意一条记录在准标识符组合上，至少与 K-1 条其他记录不可区分。采用 **Mondrian** 算法实现多维泛化。

```python
"""
K-匿名化 Mondrian 算法实现

原理：递归地将数据集按准标识符维度做二分分割，
直到每个分区的大小 < 2K 为止，然后将每个分区内的
准标识符值泛化为分区范围内的通用值。
"""

from dataclasses import dataclass, field
from typing import Any
import pandas as pd


@dataclass
class KAnonymityConfig:
    """K-匿名配置"""
    k_value: int = 5                    # K 值，默认 5
    quasi_identifiers: list[str] = field(default_factory=list)  # 准标识符列表
    sensitive_attributes: list[str] = field(default_factory=list)  # 敏感属性
    max_generalization_levels: dict[str, int] = field(default_factory=lambda: {})  # 各字段最大泛化层级


@dataclass  
class Partition:
    """数据分区"""
    data: pd.DataFrame
    qi_ranges: dict[str, tuple]         # 各准标识符的 (min, max) 范围
    
    def can_split(self, k: int) -> bool:
        """是否还能继续分割"""
        return len(self.data) >= 2 * k
    
    def find_best_split_dim(self, k: int) -> str | None:
        """选择使信息损失最小的分割维度"""
        best_dim = None
        best_normalized_width = -1
        
        for dim in self.qi_ranges:
            col = self.data[dim]
            min_val, max_val = self.qi_ranges[dim]
            
            # 连续值：选择中位数分割点
            if pd.api.types.is_numeric_dtype(col):
                median = col.median()
                left_count = (col <= median).sum()
                right_count = (col > median).sum()
                
                if left_count >= k and right_count >= k:
                    # 归一化范围宽度，选最宽的维度分割
                    normalized_width = (max_val - min_val) / (col.max() - col.min() + 1e-9)
                    if normalized_width > best_normalized_width:
                        best_normalized_width = normalized_width
                        best_dim = dim
            else:
                # 类别值：按频次二分
                value_counts = col.value_counts().sort_values(ascending=False)
                if len(value_counts) < 2:
                    continue
                split_point = len(value_counts) // 2
                left_values = set(value_counts.index[:split_point])
                
                left_count = col.isin(left_values).sum()
                right_count = (~col.isin(left_values)).sum()
                
                if left_count >= k and right_count >= k:
                    normalized_width = len(value_counts) / (len(value_counts) + 1)
                    if normalized_width > best_normalized_width:
                        best_normalized_width = normalized_width
                        best_dim = dim
        
        return best_dim
    
    def split(self, dim: str, k: int) -> tuple['Partition', 'Partition']:
        """按指定维度分割"""
        col = self.data[dim]
        
        if pd.api.types.is_numeric_dtype(col):
            median = col.median()
            left_mask = col <= median
        else:
            value_counts = col.value_counts().sort_values(ascending=False)
            split_point = len(value_counts) // 2
            left_values = set(value_counts.index[:split_point])
            left_mask = col.isin(left_values)
        
        left_data = self.data[left_mask].copy()
        right_data = self.data[~left_mask].copy()
        
        left_partition = Partition(
            data=left_data,
            qi_ranges=self._compute_ranges(left_data)
        )
        right_partition = Partition(
            data=right_data,
            qi_ranges=self._compute_ranges(right_data)
        )
        
        return left_partition, right_partition
    
    def generalize(self) -> pd.DataFrame:
        """将分区内数据做泛化处理"""
        generalized = self.data.copy()
        for dim, (min_val, max_val) in self.qi_ranges.items():
            if pd.api.types.is_numeric_dtype(generalized[dim]):
                if min_val == max_val:
                    generalized[dim] = min_val
                else:
                    generalized[dim] = f"[{min_val}, {max_val}]"
            else:
                # 类别值：取所有不同值的组合表示
                unique_vals = generalized[dim].unique()
                if len(unique_vals) == 1:
                    generalized[dim] = unique_vals[0]
                else:
                    generalized[dim] = f"{{{','.join(sorted(unique_vals))}}}"
        return generalized
    
    @staticmethod
    def _compute_ranges(data: pd.DataFrame) -> dict[str, tuple]:
        ranges = {}
        for col in data.columns:
            if pd.api.types.is_numeric_dtype(data[col]):
                ranges[col] = (data[col].min(), data[col].max())
            else:
                ranges[col] = (data[col].min(), data[col].max())  # 字符串的 min/max
        return ranges


class MondrianAnonymizer:
    """Mondrian K-匿名化引擎"""
    
    def __init__(self, config: KAnonymityConfig):
        self.config = config
    
    def anonymize(self, data: pd.DataFrame) -> pd.DataFrame:
        """执行 K-匿名化"""
        if len(data) < self.config.k_value:
            raise ValueError(
                f"数据集行数 {len(data)} 小于 K={self.config.k_value}，无法满足 K-匿名要求"
            )
        
        qi_data = data[self.config.quasi_identifiers + 
                       self.config.sensitive_attributes + 
                       [c for c in data.columns if c not in self.config.quasi_identifiers 
                        and c not in self.config.sensitive_attributes]].copy()
        
        # 初始分区
        initial = Partition(data=qi_data, qi_ranges=Partition._compute_ranges(qi_data))
        
        # 递归分割
        partitions = self._recursive_split(initial)
        
        # 泛化输出
        result_parts = []
        for p in partitions:
            generalized = p.generalize()
            result_parts.append(generalized)
        
        result = pd.concat(result_parts, ignore_index=True)
        return result
    
    def _recursive_split(self, partition: Partition) -> list[Partition]:
        """递归分割直到不可再分"""
        if not partition.can_split(self.config.k_value):
            return [partition]
        
        split_dim = partition.find_best_split_dim(self.config.k_value)
        if split_dim is None:
            return [partition]
        
        left, right = partition.split(split_dim, self.config.k_value)
        
        return (self._recursive_split(left) + self._recursive_split(right))
```

### 4.2 差分隐私 Laplace 机制

对数值型统计查询添加 Laplace 噪声，实现 ε-差分隐私。

```python
"""
差分隐私 Laplace 机制

保证：对于任意两个仅差一条记录的相邻数据集 D 和 D'，
查询结果 f(D) 和 f(D') 的分布比值 ≤ exp(ε)。

敏感度 (Sensitivity)：查询函数在相邻数据集上的最大输出差。
  - 计数查询敏感度 = 1
  - 求和查询敏感度 = |单条记录最大值|
  - 均值查询敏感度 = |单条记录最大值| / |D|
"""

import numpy as np
from dataclasses import dataclass


@dataclass
class DPConfig:
    """差分隐私配置"""
    epsilon: float = 1.0         # 隐私预算 ε (越小越隐私，噪声越大)
    delta: float = 1e-6          # 松弛参数 δ (Gaussian 机制用)
    mechanism: str = "laplace"   # laplace | gaussian
    sensitivity: float = 1.0     # 查询敏感度
    random_state: int | None = None  # 随机种子 (测试用，生产不设)


class DifferentialPrivacyEngine:
    """差分隐私引擎"""
    
    def __init__(self, config: DPConfig):
        self.config = config
        self._rng = np.random.default_rng(config.random_state)
        self._budget_consumed = 0.0  # 已消耗的隐私预算
    
    @property
    def remaining_budget(self) -> float:
        """剩余隐私预算"""
        return max(0.0, self.config.epsilon - self._budget_consumed)
    
    def apply_laplace(self, true_value: float) -> float:
        """
        对单个数值添加 Laplace 噪声
        
        Laplace 噪声: scale = sensitivity / epsilon
        """
        if self.remaining_budget <= 0:
            raise RuntimeError(
                f"隐私预算已耗尽: consumed={self._budget_consumed:.4f}, "
                f"epsilon={self.config.epsilon:.4f}"
            )
        
        scale = self.config.sensitivity / self.config.epsilon
        noise = self._rng.laplace(0, scale)
        result = true_value + noise
        
        self._budget_consumed += self.config.epsilon
        return result
    
    def apply_gaussian(self, true_value: float) -> float:
        """
        对单个数值添加 Gaussian 噪声 (ε, δ)-差分隐私
        
        Gaussian 标准差: σ = sensitivity * sqrt(2 * ln(1.25/δ)) / ε
        """
        if self.remaining_budget <= 0:
            raise RuntimeError("隐私预算已耗尽")
        
        sigma = (self.config.sensitivity * 
                 np.sqrt(2 * np.log(1.25 / self.config.delta)) / 
                 self.config.epsilon)
        noise = self._rng.normal(0, sigma)
        result = true_value + noise
        
        self._budget_consumed += self.config.epsilon
        return result
    
    def apply_to_count(self, true_count: int) -> int:
        """计数查询差分隐私 (敏感度=1)"""
        self.config.sensitivity = 1.0
        noisy = self.apply_laplace(float(true_count))
        return max(0, int(round(noisy)))  # 计数不可能为负
    
    def apply_to_sum(self, values: list[float], 
                     clip_lower: float, clip_upper: float) -> float:
        """求和查询差分隐私 (先裁剪再计算)"""
        # 裁剪以控制敏感度
        clipped = [max(clip_lower, min(clip_upper, v)) for v in values]
        true_sum = sum(clipped)
        self.config.sensitivity = max(abs(clip_lower), abs(clip_upper))
        return self.apply_laplace(true_sum)
    
    def apply_to_mean(self, values: list[float],
                      clip_lower: float, clip_upper: float) -> float:
        """均值查询差分隐私"""
        clipped = [max(clip_lower, min(clip_upper, v)) for v in values]
        n = len(clipped)
        if n == 0:
            return 0.0
        true_mean = sum(clipped) / n
        self.config.sensitivity = max(abs(clip_lower), abs(clip_upper)) / n
        return self.apply_laplace(true_mean)


class PrivacyBudgetManager:
    """
    隐私预算管理器
    
    管理一个数据集在整个生命周期内的总隐私预算，
    防止通过多次查询逐渐消耗隐私保护。
    
    采用串行组合定理 (Serial Composition):
    如果对同一数据集执行 k 次 ε_i-差分隐私查询，
    总隐私保证为 Σε_i。
    """
    
    def __init__(self, total_epsilon: float):
        self.total_epsilon = total_epsilon
        self.consumed = 0.0
        self.query_history: list[dict] = []
    
    def request_budget(self, epsilon: float, query_name: str) -> bool:
        """请求隐私预算"""
        if self.consumed + epsilon > self.total_epsilon:
            remaining = self.total_epsilon - self.consumed
            raise RuntimeError(
                f"隐私预算不足: 请求 {epsilon:.4f}，"
                f"剩余 {remaining:.4f}，"
                f"查询 '{query_name}' 被拒绝"
            )
        
        self.consumed += epsilon
        self.query_history.append({
            'query_name': query_name,
            'epsilon_used': epsilon,
            'cumulative_epsilon': self.consumed,
        })
        return True
    
    def get_budget_report(self) -> dict:
        """获取隐私预算使用报告"""
        return {
            'total_epsilon': self.total_epsilon,
            'consumed_epsilon': round(self.consumed, 4),
            'remaining_epsilon': round(self.total_epsilon - self.consumed, 4),
            'query_count': len(self.query_history),
            'queries': self.query_history,
        }
```

### 4.3 重标识风险评估引擎

```python
"""
重标识风险评估

评估匿名化后数据集中，攻击者通过关联公开数据集（如学校名录、公开排名等）
重新识别到具体学生的风险。

核心指标：
1. 单记录风险 (Individual Risk): 每条记录被唯一识别的概率
2. 样本风险 (Sample Risk): 整个数据集中高风险记录的占比
3. 准标识符熵风险: 准标识符组合的信息熵
"""

from dataclasses import dataclass
import pandas as pd
import numpy as np
from collections import Counter


@dataclass
class RiskAssessmentResult:
    """风险评估结果"""
    overall_risk_score: float         # 综合风险分 (0-1, 越低越安全)
    max_individual_risk: float        # 最大单记录风险
    avg_individual_risk: float        # 平均单记录风险
    high_risk_record_ratio: float     # 高风险记录占比 (risk > 0.2)
    smallest_equivalence_class: int   # 最小等价类大小
    field_uniqueness: dict[str, float]  # 各字段唯一性比率
    qi_combination_uniqueness: float  # 准标识符组合唯一性比率
    assessment_passed: bool           # 是否通过风险阈值
    risk_breakdown: dict             # 风险详情
    recommendations: list[str]        # 优化建议


class ReidentificationRiskAssessor:
    """重标识风险评估引擎"""
    
    def __init__(self, quasi_identifiers: list[str], 
                 max_risk_score: float = 0.2,
                 min_equivalence_class: int = 5):
        self.quasi_identifiers = quasi_identifiers
        self.max_risk_score = max_risk_score
        self.min_equivalence_class = min_equivalence_class
    
    def assess(self, data: pd.DataFrame) -> RiskAssessmentResult:
        """执行风险评估"""
        
        # 1. 准标识符组合分组统计
        qi_groups = data.groupby(self.quasi_identifiers).size()
        
        # 2. 单记录风险计算
        # 使用 log-linear 模型估计: risk = 1 / group_size
        individual_risks = data.merge(
            qi_groups.reset_index().rename(columns={0: '_group_size'}),
            on=self.quasi_identifiers,
            how='left'
        )['_group_size'].apply(lambda s: 1.0 / s)
        
        max_individual_risk = float(individual_risks.max())
        avg_individual_risk = float(individual_risks.mean())
        high_risk_count = int((individual_risks > 0.2).sum())
        high_risk_ratio = high_risk_count / len(data)
        
        # 3. 准标识符组合唯一性
        unique_qi_combos = data[self.quasi_identifiers].drop_duplicates()
        qi_combination_uniqueness = len(unique_qi_combos) / len(data)
        
        # 4. 各字段唯一性比率 (单字段越接近 1 越危险)
        field_uniqueness = {
            col: float(data[col].nunique() / len(data))
            for col in self.quasi_identifiers
        }
        
        # 5. 最小等价类大小 (K-匿名有效性直接验证)
        smallest_equivalence_class = int(qi_groups.min())
        
        # 6. 准标识符组合信息熵风险
        # 熵越高 → 组合空间越大 → 攻击者穷举关联难度越高 → 风险越低
        entropy_risk = self._compute_entropy_risk(data)
        
        # 7. 敏感属性 L-多样性检查
        l_diversity_report = self._check_l_diversity(data, qi_groups)
        
        # 8. 综合风险分取各维度最大值 (短板原则，任一维度失守即整体失守)
        equivalence_risk = 1.0 - min(
            1.0, smallest_equivalence_class / self.min_equivalence_class
        )
        overall_risk_score = max(
            max_individual_risk,
            high_risk_ratio,
            entropy_risk,
            equivalence_risk,
        )
        
        passed = (
            overall_risk_score <= self.max_risk_score
            and smallest_equivalence_class >= self.min_equivalence_class
            and l_diversity_report['min_distinct_sensitive_values'] >= 2
        )
        
        recommendations = self._generate_recommendations(
            field_uniqueness=field_uniqueness,
            smallest_equivalence_class=smallest_equivalence_class,
            high_risk_ratio=high_risk_ratio,
            l_diversity_report=l_diversity_report,
        )
        
        return RiskAssessmentResult(
            overall_risk_score=round(overall_risk_score, 4),
            max_individual_risk=round(max_individual_risk, 4),
            avg_individual_risk=round(avg_individual_risk, 4),
            high_risk_record_ratio=round(high_risk_ratio, 4),
            smallest_equivalence_class=smallest_equivalence_class,
            field_uniqueness={k: round(v, 4) for k, v in field_uniqueness.items()},
            qi_combination_uniqueness=round(qi_combination_uniqueness, 4),
            assessment_passed=passed,
            risk_breakdown={
                'equivalence_risk': round(equivalence_risk, 4),
                'entropy_risk': round(entropy_risk, 4),
                'l_diversity': l_diversity_report,
                'group_size_distribution': qi_groups.describe().to_dict(),
            },
            recommendations=recommendations,
        )
    
    def _compute_entropy_risk(self, data: pd.DataFrame) -> float:
        """准标识符组合的信息熵风险 (0-1)
        
        对每列计算归一化熵 H(X)/log2(n)，取各列均值后
        用 1 - 归一化熵 作为风险分：分布越集中，越容易被猜中。
        """
        import math
        risks = []
        for col in self.quasi_identifiers:
            counts = data[col].value_counts()
            n = len(data)
            entropy = -sum((c / n) * math.log2(c / n) for c in counts)
            max_entropy = math.log2(max(n, 2))
            normalized_entropy = entropy / max_entropy if max_entropy > 0 else 0.0
            risks.append(1.0 - normalized_entropy)
        return float(np.mean(risks)) if risks else 0.0
    
    def _check_l_diversity(self, data: pd.DataFrame,
                           qi_groups: pd.Series) -> dict:
        """L-多样性检查：每个等价类中敏感属性不同值的数量
        
        注：sensitive_attributes 为空时跳过，返回通过。
        """
        # 调用方通过构造时注入 sensitive_columns（此处从实例属性读取）
        sensitive_cols = getattr(self, 'sensitive_columns', [])
        if not sensitive_cols:
            return {
                'checked': False,
                'min_distinct_sensitive_values': 999,
                'violating_classes': 0,
            }
        
        grouped = data.groupby(self.quasi_identifiers)
        min_distinct = 999
        violating = 0
        for _, group in grouped:
            distinct = group[sensitive_cols[0]].nunique()
            min_distinct = min(min_distinct, distinct)
            if distinct < 2:
                violating += 1
        
        return {
            'checked': True,
            'min_distinct_sensitive_values': int(min_distinct),
            'violating_classes': violating,
        }
    
    def _generate_recommendations(self, field_uniqueness: dict,
                                  smallest_equivalence_class: int,
                                  high_risk_ratio: float,
                                  l_diversity_report: dict) -> list[str]:
        """根据风险画像生成优化建议（供审核人参考）"""
        recs = []
        
        # 找出唯一性比率 > 0.8 的高危字段
        for field, ratio in field_uniqueness.items():
            if ratio > 0.8:
                recs.append(
                    f"字段 '{field}' 唯一性比率 {ratio:.2f} 过高，"
                    f"建议提升泛化层级（如精确值→区间值）或加入 SUPPRESS"
                )
        
        if smallest_equivalence_class < self.min_equivalence_class:
            recs.append(
                f"存在 {smallest_equivalence_class} 条记录的微小等价类"
                f"（要求 ≥{self.min_equivalence_class}），"
                f"建议收紧泛化粒度或对微小类做整行抑制"
            )
        
        if high_risk_ratio > 0.05:
            recs.append(
                f"高风险记录占比 {high_risk_ratio:.2%} 超过 5% 警戒线，"
                f"建议提高 K 值或对高风险子集二次泛化"
            )
        
        if l_diversity_report.get('checked') and l_diversity_report.get('violating_classes', 0) > 0:
            recs.append(
                f"{l_diversity_report['violating_classes']} 个等价类不满足 L-多样性，"
                f"建议对敏感属性做扰动或分桶"
            )
        
        if not recs:
            recs.append("风险指标均在阈值内，可提交人工审核")
        
        return recs
```

**风险评估判定规则：**

| 判定项 | 阈值来源 | 失败后果 |
| --- | --- | --- |
| 综合风险分 ≤ `max_risk_score` | `anon_policy.max_risk_score`（默认 0.2） | 任务进入 `REJECTED_AUTO`，禁止交付 |
| 最小等价类 ≥ `min_equivalence_class` | 引擎默认 5（不低于策略 K 值） | 同上，输出强制二次泛化建议 |
| L-多样性（如有敏感属性） | 每等价类敏感值 ≥ 2 | 同上 |
| 高风险记录占比 | 警戒线 5%（超线仅告警不拦截，计入审核重点） | 写入 `risk_details` 供审核人关注 |

### 4.4 假名化与映射表管理（PseudonymMappingRegistry）

假名化是唯一**可逆**的匿名化技术，映射表本身是最高敏感级资产，必须单独防护：

```python
"""
假名映射表管理器

安全护栏：
1. 映射表与匿名化数据物理分离（独立 Schema anon_internal，独立实例更佳）
2. 写入权限仅授予匿名化引擎服务账号，审计账号只读，其他服务零权限
3. pseudonym 本身经 Vault Transit 加密后落库，encryption_kid 记录密钥版本
4. 映射表设置 TTL：消费方确认数据集销毁后，映射表记录同步销毁（默认 180 天）
5. 任何读取操作写入统一审计日志（操作人/目的/记录数）
"""

import hashlib
import uuid
from datetime import datetime, timedelta


class PseudonymMappingRegistry:
    
    def __init__(self, vault_client, db, default_ttl_days: int = 180):
        self.vault = vault_client      # Vault Transit 客户端（依赖密钥管理模块）
        self.db = db                   # anon_internal Schema 连接
        self.default_ttl_days = default_ttl_days
    
    def pseudonymize(self, policy_id: int, field_path: str,
                     original_value: str, key_id: str) -> str:
        """为原始值生成/复用假名（幂等：同值同策略同密钥 → 同假名）"""
        mapping_key = f"{policy_id}:{field_path}"
        original_hash = hashlib.sha256(
            original_value.encode('utf-8')
        ).hexdigest()
        
        # 1. 查已有映射（按 hash 命中，不明文比对）
        row = self.db.query_one(
            "SELECT pseudonym, encryption_kid FROM anon_internal.pseudonym_mapping "
            "WHERE mapping_key=%s AND original_hash=%s",
            (mapping_key, original_hash),
        )
        if row and row['encryption_kid'] == key_id:
            return self.vault.decrypt(row['pseudonym'], key_id)
        
        # 2. 生成确定性假名：HMAC(key, hash) 取前 16 字节，保证同输入同输出
        import hmac as hmac_mod
        digest = hmac_mod.new(
            key_id.encode(), original_hash.encode(), hashlib.sha256
        ).hexdigest()[:32]
        pseudonym = f"PSN-{digest}"
        
        # 3. 加密落库（Vault Transit，加密后密文 Base64 存储）
        ciphertext = self.vault.encrypt(pseudonym, key_id)
        self.db.execute(
            "INSERT INTO anon_internal.pseudonym_mapping "
            "(mapping_key, original_hash, pseudonym, encryption_kid) "
            "VALUES (%s, %s, %s, %s) "
            "ON DUPLICATE KEY UPDATE pseudonym=VALUES(pseudonym)",
            (mapping_key, original_hash, ciphertext, key_id),
        )
        return pseudonym
    
    def schedule_expiry(self, dataset_code: str) -> int:
        """数据集销毁后调度映射表过期：返回标记过期的映射记录数"""
        expire_before = datetime.utcnow() - timedelta(days=self.default_ttl_days)
        result = self.db.execute(
            "DELETE FROM anon_internal.pseudonym_mapping "
            "WHERE mapping_key LIKE %s AND created_at < %s",
            (f"{dataset_code}:%", expire_before),
        )
        self.audit_log('MAPPING_EXPIRED', dataset_code, result.rowcount)
        return result.rowcount
    
    def audit_log(self, action: str, target: str, record_count: int):
        """所有映射表操作写统一审计日志（见统一审计日志与操作追溯系统）"""
        ...  # 调用审计 SDK，字段：operator/service_account, action, target, count, ts
```

**关键设计决策：**

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 假名是否允许反查 | 仅允许合规审批后的反查流程（如司法协查），且走统一审计 | PIPL 匿名化要求"不可识别"，可逆能力必须受控 |
| 同值是否映射同假名 | 是（确定性假名） | 保证跨表 join 分析可用；跨数据集使用不同 policy_id 前缀隔离 |
| 映射表存储位置 | 独立 Schema，生产库与应用库网络隔离 | 降低拖库后关联还原风险 |

```text
┌───────────────┐   质量校验 + 风险评估                ┌───────────────┐
│ 4. Validator  │ ─────────────────────────────────▶ │ 匿名化结果集   │
│  + RiskAssess │  质量分/风险分/统计偏差报告           │ (待审核区)     │
└───────────────┘                                    └───────┬───────┘
        │                                                    │
        ▼ (自动通过)                              (自动拒绝/待人工)
┌───────────────┐                                  ┌───────────────┐
│ 状态=REVIEWING │                                  │ REJECTED_AUTO  │
│ 推送审核人     │                                  │ 记录原因,不入审│
└───────┬───────┘                                  └───────────────┘
        │ 人工审核(双人复核 for 敏感数据集)
        ▼
   APPROVED ──▶ Deliverer 投递到目标存储 ──▶ DELIVERED
   REJECTED ──▶ 记录原因,可调整后重跑
```

### 5.2 触发模式

| 触发方式 | 来源 | 说明 |
| --- | --- | --- |
| SCHEDULED | `schedule_cron` 定时 | 调度引擎按 cron 触发，适用于周期性数据集市 |
| MANUAL | 管理后台按钮 | 数据合规专员手动触发，需二次确认 |
| API | 内部服务调用 | 如模型训练数据集准备管线完成后触发匿名化步骤，需 `system` 级权限 |

### 5.3 执行耗时与规模基线

| 指标 | 基线值 | 说明 |
| --- | --- | --- |
| 单次任务源数据规模 | ≤ 500 万行 | 超过则按主键游标分片执行 |
| 分片大小 | 50 万行/片 | 与任务调度引擎的分片规范一致 |
| 100 万行全量匿名化耗时 | P95 ≤ 25 分钟 | 含 K-匿名（5 准标识符）与风险评估 |
| 任务级超时 | 2 小时 | 超时标记 FAILED，暂存区自动清理 |

## 6. API 接口设计

### 6.1 管理端接口

#### 6.1.1 策略管理

**创建/更新策略** `POST /admin/anon/policies`

```json
{
  "policy_name": "学习行为分析数据集-周更",
  "dataset_code": "behavior_weekly",
  "description": "供 BI 平台使用的周度学习行为匿名化数据集",
  "k_anonymity": 5,
  "l_diversity": 2,
  "max_risk_score": 0.2,
  "schedule_cron": "0 3 * * 1",
  "incremental": 0,
  "field_rules": [
    {
      "field_path": "student.phone",
      "field_type": "DIRECT_ID",
      "technique": "PSEUDONYMIZE",
      "params": {"key_id": "anon-fpe-2026q4"},
      "priority": 10
    },
    {
      "field_path": "student.birthday",
      "field_type": "QUASI_ID",
      "technique": "GENERALIZE",
      "params": {"hierarchy": "date→month→quarter→year", "max_level": 2},
      "priority": 20
    },
    {
      "field_path": "score.raw",
      "field_type": "SENSITIVE",
      "technique": "BINNING",
      "params": {"bins": [0, 60, 75, 85, 95, 100]},
      "priority": 30
    }
  ]
}
```

响应：`{ "policy_id": 1012, "version": 1 }`。更新走版本递增（`version+1`），执行中的任务仍按旧版本快照运行。

**校验规则：**
- `dataset_code` 全局唯一（uk_dataset_code），冲突返回 `50701`；
- `field_type=DIRECT_ID` 的规则禁止配置可逆技术以外的透传（即不允许 `RANDOMIZE` 单独用于直接标识符，必须 `PSEUDONYMIZE/FPE/HASH`）；
- `max_risk_score` 允许范围 (0, 0.5]，超出返回 `50702`。

#### 6.1.2 任务触发

`POST /admin/anon/tasks`

```json
{
  "policy_id": 1012,
  "trigger_note": "Q4 分析数据集补跑"
}
```

响应：`{ "task_id": "a1b2c3d4-...", "status": "PENDING" }`。

幂等：同 `policy_id` 存在状态为 `PENDING/RUNNING/REVIEWING` 的任务时返回 `50703`（防重复触发冲垮暂存区）；管理端可用 `force=true` 参数跳过（自动为旧任务标记 SUPERSEDED）。

#### 6.1.3 任务列表与详情

`GET /admin/anon/tasks?status=REVIEWING&page=1&page_size=20`

`GET /admin/anon/tasks/{task_id}` —— 详情含 `risk_details`（风险评估全量 JSON）、`quality_details`、执行时间线。

#### 6.1.4 人工审核

`POST /admin/anon/tasks/{task_id}/review`

```json
{
  "decision": "APPROVE",
  "review_note": "风险分 0.12，高风险占比 2%，通过"
}
```

- `decision ∈ {APPROVE, REJECT}`；
- 仅 `REVIEWING` 状态可审核，其余状态返回 `50704`；
- 数据集含敏感属性（心理健康标记等）时必须双人复核：第二人 `APPROVE` 后才进入交付队列，单人审批通过仅置 `REVIEWING_SECOND`；
- 审核操作强审计：审核人、时间、IP、note 全量落审计日志。

#### 6.1.5 风险评估查询

`GET /admin/anon/tasks/{task_id}/risk-report` —— 返回 §4.3 `RiskAssessmentResult` 全量字段及优化建议，供合规专员下载归档。

## 7. 状态机与守卫

### 7.1 任务状态机

```text
                触发              抽取/匿名化完成
  ┌─────┐ ─────────────▶ ┌─────────┐ ───────────────▶ ┌────────────┐
  │PENDING│                │ RUNNING │                    │ REVIEWING  │
  └─────┘ ◀───────────── └────┬────┘                    └─────┬──────┘
       (抢占超时回收)           │ 执行异常                       │ 人工审核
                                ▼                               ▼
                          ┌─────────┐      ┌──────────────┐   ┌──────────────┐
                          │ FAILED  │      │REJECTED_AUTO │   │REVIEWING_2ND │
                          └─────────┘      └──────────────┘   └──────┬───────┘
                                                     (仅敏感数据集)     │ 第二人
                                                                       ▼
                                                              ┌──────────────┐
                                                              │  APPROVED    │
                                                              └──────┬───────┘
                                                                     │ Deliverer
                                                                     ▼
                                                              ┌──────────────┐
                                                              │  DELIVERED   │
                                                              └──────────────┘
                                                                     │ 数据集销毁
                                                                     ▼
                                                              ┌──────────────┐
                                                              │  DESTROYED   │ (终态)
                                                              └──────────────┘

  REJECTED: REVIEWING 人工拒绝后的终态（可重新触发新任务）
  SUPERSEDED: 被 force 触发的新任务取代的历史任务终态
```

### 7.2 守卫规则

| 编号 | 规则 | 违反后果 |
| --- | --- | --- |
| G1 | 状态迁移必须 CAS：`UPDATE anon_task_log SET status=? WHERE task_id=? AND status=?`，影响行数 0 即冲突 | 返回 50705，操作方重查状态 |
| G2 | 仅 `REVIEWING` 可审核；敏感数据集须 `REVIEWING_2ND` 才能交付 | 50704 |
| G3 | `FAILED`/`REJECTED_AUTO`/`DESTROYED`/`SUPERSEDED` 为终态，不允许任何迁移 | 50706 |
| G4 | 交付动作幂等：`(task_id, deliver_version)` 唯一，重复投递返回已有交付记录 | 50707 |
| G5 | 数据集生命周期内（DELIVERED 之后）禁止修改策略的 K 值/风险阈值；修改须建新策略版本并重新全量匿名化 | 50708 |
| G6 | 暂存区数据仅当前任务可见，任务终态（含 FAILED）后 24h 内物理清理 | 后台清理任务保证 |
| G7 | 假名映射表禁止随数据集一起导出/复制，导出任务中映射表字段一律视为 `DIRECT_ID` 二次校验 | 导出管线硬编码校验 |
| G8 | 风险评估未执行成功（异常）的任务禁止进入 REVIEWING | 状态机兜底，异常自动 FAILED |

## 8. 幂等与并发场景

| 场景 | 幂等机制 | 说明 |
| --- | --- | --- |
| 重复触发同策略任务 | 活跃任务去重（50703）+ `force` 取代语义 | 见 §6.1.2 |
| 审核重复提交 | `(task_id, reviewer, decision)` 唯一约束 + G1 CAS | 双击/重试安全 |
| 交付重复执行 | `(task_id, deliver_version)` 唯一键（G4） | 消费方重试安全 |
| 调度器多副本 | 抢占式领取：`UPDATE ... SET status='RUNNING', worker_id=? WHERE status='PENDING' LIMIT 1` | 与任务调度框架规范一致 |
| 分片断点续跑 | 分片游标 `(task_id, shard_no, last_pk)` 持久化 | 崩溃后从断点继续，已完成分片跳过 |
| 管理端并发编辑策略 | 乐观锁 `version` 字段 | 冲突返回 50709，提示刷新 |
| 假名映射并发生成 | `uk_hash_key(original_hash, mapping_key)` + ON DUPLICATE KEY UPDATE | 并发同值生成同一假名 |

**并发上限保护：** 同策略并发执行任务数 ≤ 1；全局并发执行分片数 ≤ 32（与离线计算资源池对齐）。

## 9. 事件 Outbox

### 9.1 Outbox 表

```sql
CREATE TABLE anon_outbox (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    event_id        VARCHAR(64) NOT NULL UNIQUE COMMENT '事件唯一 ID (UUID)',
    aggregate_type  VARCHAR(32) NOT NULL DEFAULT 'anon_task',
    aggregate_id    VARCHAR(64) NOT NULL COMMENT 'task_id',
    event_type      VARCHAR(48) NOT NULL,
    payload         JSON NOT NULL,
    occurred_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    published_at    DATETIME COMMENT '投递成功时间',
    retry_count     INT NOT NULL DEFAULT 0,
    
    KEY idx_unpublished (published_at),
    KEY idx_aggregate (aggregate_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='匿名化管线 Outbox';
```

Outbox 与任务状态变更同事务写入；投递器 at-least-once，消费方幂等（`event_id` 去重）。

### 9.2 事件清单与消费方矩阵

| 事件类型 | 触发时机 | 关键 payload | 消费方 |
| --- | --- | --- | --- |
| `anon.task.created` | 任务创建 | task_id, policy_id, dataset_code, trigger_type | 调度引擎（领取执行） |
| `anon.task.failed` | 任务失败 | task_id, error_message, failed_stage | 监控告警、运维值班 |
| `anon.task.review_required` | 进入审核 | task_id, risk_score, high_risk_ratio, review_url | 审核人站内信/待办 |

| `anon.task.approved` | 审核通过 | task_id, reviewer, dataset_code | 数据集目录（血缘平台） |
| `anon.task.delivered` | 交付完成 | task_id, output_location, output_rows, schema_version | BI 平台、训练平台、血缘平台 |
| `anon.task.rejected` | 人工拒绝 | task_id, reviewer, review_note | 触发方（API 触发的管线重决策） |
| `anon.dataset.destroyed` | 数据集销毁 | task_id, dataset_code | 映射表管理（§4.4 schedule_expiry）、存储治理 |

### 9.3 上游订阅

本模块消费：`config.policy.updated`（策略变更后下一调度周期生效，运行中任务不受影响）。

## 11. 降级矩阵

| 编号 | 故障场景 | 降级策略 | 数据安全红线 |

| D10 | 管理后台不可用 | 内部 API 触发通道保留（system 账号），审核流转暂停 | 审核不可绕过 |

## 13. 合规红线（C1-C10）

| 编号 | 红线 | 依据 |
| --- | --- | --- |
| C1 | 匿名化输出必须通过风险评估且人工审核后方可离开待审核区 | PIPL 第 73 条匿名化定义："无法识别且不能复原" |

| C10 | 本模块全部数据处理行为纳入数据血缘平台登记，数据字典同步标注匿名化状态 | 元数据治理 |

## 14. 契约对齐（R1-R12）

| 编号 | 契约 | 对齐说明 |
| --- | --- | --- |
| R1 | 密钥管理模块 | 假名化加密密钥（Vault Transit key_id）由其签发与轮换；本模块只引用 kid 不持有密钥 |
| R2 | 数据脱敏规则引擎 | 展示层动态脱敏归其负责；本模块不接管在线请求路径，二者技术枚举独立命名避免混淆 |
| R3 | 统一审计日志系统 | 所有审计写入走其 SDK，格式遵循其 schema（operator/action/target/detail/ts） |
| R4 | 数据血缘平台 | `anon.task.delivered` 事件携带血缘节点信息，数据集注册由其消费 |
| R5 | 数据质量监控引擎 | 质量校验规则复用其框架；质量分口径与其对齐（0-100） |
| R6 | 任务调度引擎 | 调度触发、cron 规范、分片规范、抢占语义与其批处理框架规范一致 |
| R7 | 学习数据仓库 | BI 消费入口为 `GET /internal/anon/datasets/{code}/latest`，不直连匿名化存储 |
| R8 | 数据标准化与跨平台交换引擎 | 对外交付数据格式遵循其交换 schema；本模块负责前置匿名化 |
| R9 | 司法协查系统 | 唯一允许的反查入口；反查须审批并回写审计，本模块不提供任何其他反查 API |
| R10 | 未成年人数据隐私合规引擎 | 未成年人标记由其在源数据层打标，本模块按标记自动套用 C2 最高保护级参数 |
| R11 | 存储资源生命周期管理引擎 | 暂存区清理、匿名化数据冷热分层销毁由其统一调度，本模块发起 `anon.dataset.destroyed` |
| R12 | 统一事件总线 | Outbox 投递走统一事件总线，Topic 命名 `anon.domain.events`，事件 schema 遵循事件标准化规范 |
