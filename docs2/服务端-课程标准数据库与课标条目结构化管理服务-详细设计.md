# 服务端-课程标准数据库与课标条目结构化管理服务 详细设计

## 1. 概述

### 1.1 模块定位

课程标准数据库与课标条目结构化管理服务（CurriculumStandardService）是 PrimeTop 教育内容体系的基座服务。它负责：

- 结构化存储国家教育部颁布的《义务教育课程方案和课程标准（2022年版）》及《普通高中课程方案和课程标准（2017年版2020年修订）》等权威文件。
- 将课标文档拆解为可查询、可引用、可对齐的条目数据库（学段 → 学科 → 主题群 → 主题 → 核心素养 → 具体条目）。
- 为题目标注、教材对齐、内容审核、学情分析等上游服务提供统一的课标条目查询接口。
- 管理课标版本迭代（如 2011 版 → 2022 版），支持版本间差异对比和内容迁移。

### 1.2 核心职责

| 职责 | 说明 |
| --- | --- |
| 课标数据建模 | 将非结构化的课标文档转化为结构化的层次化数据模型。 |
| 课标条目管理 | 条目的增删改查、批量导入、结构化标注。 |
| 核心素养管理 | 维护各学科定义的核心素养维度及其描述。 |
| 学业质量标准 | 管理课标中的学业质量水平描述（如水平一至水平五）。 |
| 版本管理 | 课标版本的创建、发布、归档与版本间差异对比。 |
| 外部映射 | 课标条目与知识点、教材章节、考点的映射关系管理。 |
| 查询服务 | 提供多维度检索（按学段、学科、核心素养、关键词等）。 |

### 1.3 目标用户

| 用户 | 使用场景 |
|------|----------|
| 内容教研团队 | 录入和维护课标条目，标注核心素养 |
| 题目/内容生产 | 检索课标条目，为内容和题目打上课标标签 |
| AI 对齐引擎 | 自动将学习内容与课标条目匹配 |
| 学情分析服务 | 基于课标维度评估学生能力 |
| 管理后台 | 可视化浏览和管理课标数据库 |

### 1.4 依赖关系

```text
教育部课标文档（PDF/Word原始文件）
        |
    课标导入与解析管线
        |
    CurriculumStandardService（本服务）
        |
    +-----------+-----------+-----------+-----------+
    |           |           |           |           |
  题目服务   内容服务   学情分析   AI对齐引擎  教材映射
  (课标标注)  (内容对齐)  (素养评估)  (自动匹配)  (章节关联)
```

**上游依赖：**
- 教育部官方课标文档：权威数据源。
- 学科与科目基础数据管理：提供学段、学科编码体系。

**下游消费方：**
- 题目服务：题目知识点自动标注与课标对齐引擎。
- 内容服务：教材课标对齐度分析与内容覆盖率统计。
- AI 服务：Prompt 编排中注入课标要求。
- 学情分析：核心素养评估与学科能力维度分析。
- 教材版本与章节管理服务：章节到课标条目的映射。

## 2. 数据模型

### 2.1 核心实体定义

| 实体 | 英文 | 说明 |
|------|------|------|
| 课标版本 | CurriculumStandardVersion | 一份完整的课程标准发布版本（如"义务教育数学课程标准 2022年版"）。 |
| 学科课标 | SubjectCurriculum | 某版本下某学科的课标主体。 |
| 主题群 | ThemeGroup | 学科课标下的一级分类（如数学中的"数与代数""图形与几何"）。 |
| 主题 | Theme | 主题群下的二级分类（如"数与代数"下的"数的认识""数的运算"等）。 |
| 核心素养 | CoreCompetency | 学科定义的核心素养维度（如数学核心素养：数学抽象、逻辑推理、数学建模等）。 |
| 课标条目 | StandardItem | 课标中最小的可引用单元，包含具体的 content requirements（内容要求）和学业要求。 |
| 学业质量水平 | ProficiencyLevel | 课标中定义的学业质量等级描述。 |
| 课标映射关系 | StandardMapping | 课标条目与知识点/教材章节/考点的关联关系。 |

### 2.2 数据库表结构（DDL，MySQL 8）

```sql
-- ============================================================
-- 1. 课标版本表
-- ============================================================
CREATE TABLE `curriculum_standard_version` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `version_code` VARCHAR(64) NOT NULL COMMENT '版本编码，如 CS-MATH-2022',
    `title` VARCHAR(256) NOT NULL COMMENT '课标全称',
    `stage` VARCHAR(16) NOT NULL COMMENT '学段：PRIMARY/JUNIOR/SENIOR',
    `subject_code` VARCHAR(32) NOT NULL COMMENT '学科编码',
    `publisher` VARCHAR(128) NOT NULL DEFAULT '中华人民共和国教育部' COMMENT '发布机构',
    `publish_date` DATE NOT NULL COMMENT '发布日期',
    `effective_date` DATE NOT NULL COMMENT '生效日期',
    `doc_url` VARCHAR(512) COMMENT '原始文档URL（对象存储）',
    `status` VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT/PUBLISHED/ARCHIVED',
    `previous_version_id` BIGINT UNSIGNED COMMENT '上一版本ID（用于版本链）',
    `description` TEXT COMMENT '版本说明',
    `created_by` BIGINT UNSIGNED NOT NULL,
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_version_code` (`version_code`),
    KEY `idx_stage_subject` (`stage`, `subject_code`),
    KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='课标版本';

-- ============================================================
-- 2. 学科课标表
-- ============================================================
CREATE TABLE `subject_curriculum` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `version_id` BIGINT UNSIGNED NOT NULL COMMENT '课标版本ID',
    `subject_code` VARCHAR(32) NOT NULL COMMENT '学科编码',
    `stage` VARCHAR(16) NOT NULL COMMENT '学段',
    `total_hours` INT UNSIGNED COMMENT '总课时数',
    `overview` TEXT COMMENT '课程性质与基本理念',
    `design_principles` TEXT COMMENT '课程设计思路',
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),

-- ============================================================
-- 3. 核心素养表

    UNIQUE KEY `uk_version_subject_comp` (`version_id`, `competency_code`),

    CONSTRAINT `fk_cc_version` FOREIGN KEY (`version_id`) REFERENCES `curriculum_standard_version`(`id`)

-- ============================================================
-- 4. 主题群表
-- ============================================================
CREATE TABLE `theme_group` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `version_id` BIGINT UNSIGNED NOT NULL,
    `subject_code` VARCHAR(32) NOT NULL,

    `name` VARCHAR(128) NOT NULL COMMENT '名称，如"数与代数"',
    `description` TEXT,
    `grade_range` VARCHAR(32) COMMENT '适用年级范围，如 1-3',
    `display_order` INT UNSIGNED NOT NULL DEFAULT 0,
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),

    KEY `idx_version_subject` (`version_id`, `subject_code`),
    CONSTRAINT `fk_tg_version` FOREIGN KEY (`version_id`) REFERENCES `curriculum_standard_version`(`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='课标主题群';

-- ============================================================
-- 5. 主题表
-- ============================================================
CREATE TABLE `theme` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `group_id` BIGINT UNSIGNED NOT NULL COMMENT '所属主题群ID',
    `theme_code` VARCHAR(64) NOT NULL COMMENT '主题编码',
    `name` VARCHAR(128) NOT NULL COMMENT '名称，如"数的认识"',
    `description` TEXT,
    `grade_range` VARCHAR(32) COMMENT '适用年级范围',

    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_group_theme_code` (`group_id`, `theme_code`),
    KEY `idx_group` (`group_id`),
    CONSTRAINT `fk_theme_group` FOREIGN KEY (`group_id`) REFERENCES `theme_group`(`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='课标主题';

-- ============================================================
-- 6. 课标条目表（核心表）
-- ============================================================
CREATE TABLE `standard_item` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `version_id` BIGINT UNSIGNED NOT NULL COMMENT '课标版本ID',
    `subject_code` VARCHAR(32) NOT NULL COMMENT '学科编码',
    `stage` VARCHAR(16) NOT NULL COMMENT '学段',
    `theme_id` BIGINT UNSIGNED COMMENT '所属主题ID',
    `theme_group_id` BIGINT UNSIGNED COMMENT '所属主题群ID（冗余，方便查询）',
    `item_code` VARCHAR(128) NOT NULL COMMENT '条目编码，如 CS-MATH-2022-NA-NUM-001',
    `item_type` VARCHAR(32) NOT NULL COMMENT 'CONTENT_REQUIREMENT/ACADEMIC_REQUIREMENT/TEACHING_SUGGESTION/EVALUATION_CRITERION',
    `title` VARCHAR(256) NOT NULL COMMENT '条目标题',
    `content` TEXT NOT NULL COMMENT '条目正文内容',
    `grade_range` VARCHAR(32) COMMENT '适用年级，如 1-2 / 7 / 高一',
    `semester` VARCHAR(16) COMMENT '建议学期：FIRST/SECOND',
    `competency_ids` JSON COMMENT '关联核心素养ID数组',
    `difficulty_level` VARCHAR(16) COMMENT '认知层次：KNOW/UNDERSTAND/APPLY/ANALYZE/EVALUATE/CREATE',
    `keywords` JSON COMMENT '关键词数组，用于检索',
    `parent_item_id` BIGINT UNSIGNED COMMENT '父条目ID（条目可嵌套）',
    `display_order` INT UNSIGNED NOT NULL DEFAULT 0,
    `source_reference` VARCHAR(256) COMMENT '原文引用位置（页码/章节号）',
    `status` VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/DEPRECATED',
    `created_by` BIGINT UNSIGNED NOT NULL,
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    `updated_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_item_code` (`item_code`),
    KEY `idx_version_subject` (`version_id`, `subject_code`),
    KEY `idx_theme` (`theme_id`),
    KEY `idx_stage_grade` (`stage`, `grade_range`),
    KEY `idx_type` (`item_type`),
    KEY `idx_parent` (`parent_item_id`),
    FULLTEXT KEY `ft_content` (`title`, `content`),
    CONSTRAINT `fk_si_version` FOREIGN KEY (`version_id`) REFERENCES `curriculum_standard_version`(`id`),
    CONSTRAINT `fk_si_theme` FOREIGN KEY (`theme_id`) REFERENCES `theme`(`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='课标条目';

-- ============================================================
-- 7. 学业质量水平表
-- ============================================================
CREATE TABLE `proficiency_level` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,

    PRIMARY KEY (`id`),

    KEY `idx_target` (`target_type`, `target_id`),

    CONSTRAINT `fk_sm_item` FOREIGN KEY (`standard_item_id`) REFERENCES `standard_item`(`id`)

```

### 2.3 缓存策略

| 缓存键 | TTL | 说明 |
|--------|-----|------|
| `cs:version:active:{stage}:{subject}` | 24h | 当前生效版本缓存 |
| `cs:tree:{versionId}:{subjectCode}` | 6h | 完整学科课标树结构 |
| `cs:item:{itemId}` | 2h | 单条目详情缓存 |
| `cs:competency:{versionId}:{subjectCode}` | 12h | 核心素养列表缓存 |
| `cs:mappings:{itemId}:{targetType}` | 4h | 条目映射关系缓存 |
| `cs:search:{versionId}:{queryHash}` | 30min | 搜索结果缓存 |

缓存失效策略：
- 课标版本发布/归档时，批量清除该版本所有缓存。
- 条目更新时，清除该条目及所属树结构缓存。
- 映射关系变更时，清除相关条目的映射缓存。

## 4. 关键流程与算法

### 4.1 课标导入解析管线

```text
上传文件 ──► 创建批次(PENDING) ──► 异步领取(PROCESSING)
   │                                    │
   │                        ┌───────────┴────────────┐
   │                        ▼                        ▼
   │                  格式探测/解析              结构与行级校验
   │                (.xlsx / .json / .jsonl)      (§4.1.1 规则表)
   │                        │                        │
   │                        ▼                        ▼
   │                  行级错误 → error_log          通过行 → 分块(200行/块)
   │                                                │
   │                                                ▼
   │                                    幂等 UPSERT（按 item_code 自然键）
   │                                                │
   │                                    ┌───────────┴───────────┐
   │                                    ▼                       ▼
   │                            全部成功→COMPLETED      有失败→COMPLETED(带failed)
   │                            全部失败→FAILED             │
   │                                    │                       │
   └────────────────────────────────────┴───────────────────────┘
                                        ▼
                        缓存刷新(cs:tree/*, cs:item/*) + 事件 cs.item.batch_imported
```

**关键代码（Spring Boot + MyBatis，节选）：**

```java
@Service
public class CurriculumImportPipeline {

    private static final int CHUNK_SIZE = 200;

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public ChunkResult persistChunk(Long batchId, List<StandardItemRow> rows) {
        ChunkResult result = new ChunkResult(batchId);
        for (StandardItemRow row : rows) {
            try {
                // 幂等：item_code 为自然键，重复导入 = 更新而非报错
                int affected = itemMapper.upsertByItemCode(row.toEntity());
                result.success(affected == 1 ? row.getItemCode() : row.getItemCode() + "(updated)");
            } catch (DuplicateKeyException | DataIntegrityViolationException e) {
                // 违反 FK/唯一约束：记入失败行，不中断整块
                result.fail(row.getLineNumber(), row.getItemCode(),
                        resolveImportError(e));   // 53711 / 53713 / 53714 映射
            }
        }
        batchMapper.incrementProgress(batchId, result);
        return result;   // REQUIRES_NEW：块内部分失败不影响已提交块
    }

    public void onBatchFinished(Long batchId) {
        ImportBatch b = batchMapper.selectById(batchId);
        if (b.getFailedItems() > 0 && b.getSuccessItems() == 0) {
            batchMapper.updateStatus(batchId, "FAILED");
        } else {
            batchMapper.updateStatus(batchId, "COMPLETED");
        }
        cacheRefresher.evictVersionTree(b.getVersionId());          // cs:tree/*
        outbox.publish("cs.domain.events", CsItemBatchImported.of(b)); // Outbox 事务外发布
        if (b.getFailedItems() > 0) {
            notifyService.pushOpsChannel("CS_IMPORT_PARTIAL_FAILURE", b); // 运维群告警
        }
    }
}
```

**设计要点：**

1. **块级事务**：200 行一块独立事务（`REQUIRES_NEW`），单块失败不回滚已成功块；`error_log` 记录 JSON 数组 `[{line, itemCode, rule, message}]`，可下载修复后重导（INCREMENTAL）。
2. **幂等**：`item_code` 唯一键 UPSERT，重放安全；`CORRECTION` 类型导入对已 `PUBLISHED` 版本的条目仅允许修改 `content/keywords/competency_ids` 等非结构字段（结构变更必须走新版本，守卫见 §5.1 G4）。
3. **并发控制**：同一版本同时只允许一个 `PROCESSING` 批次（Redis 锁 `cs:import:lock:{versionId}`，TTL 30min，锁内续期）；重复提交返回 53721。

#### 4.1.1 行级校验规则表

| # | 规则 | 失败错误码 |
|---|------|-----------|
| V1 | `item_code` 匹配 `^CS-[A-Z]{2,8}-\d{4}-[A-Z0-9(-)]+$` 且版本前缀与目标版本一致 | 53711 |
| V2 | `item_type` / `difficulty_level` 在枚举内 | 53713 |
| V3 | `grade_range` 匹配 `^\d{1,2}(-\d{1,2})?$` 或高中段 `高一/高二/高三` 字典 | 53714 |
| V4 | `competency_ids` 中每个素养 ID 属于该版本该学科 | 53713 |
| V5 | `theme_id`/`theme_group_id` 属于该版本（FK 兜底前的显式校验，错误信息更友好） | 53713 |
| V6 | `content` 非空且 ≤ 4000 字符 | 53723 |
| V7 | `parent_item_id` 存在且不成环（导入后统一做 DFS 环检测） | 53713 |

### 4.2 课标树构建与缓存

树查询是最高频接口（题目标注、内容对齐、命题蓝图、管理后台全部依赖），采用「读时拼装 + 整树缓存」：

1. 首次查询：`theme_group` → `theme` → `standard_item`(摘要) 三次批量查询（各按 `display_order` 排序），内存拼装后整体 JSON 序列化写入 `cs:tree:{versionId}:{subjectCode}`（TTL 6h，无 TTL 随机抖动 +1h 防雪崩）。
2. 值对象为不可变结构，序列化字节数较大（200KB 级）时启用本地 Caffeine 二级缓存（容量 64 棵树，LFU），命中路径不经过 Redis。
3. 失效时机（主动）：版本发布/归档、条目导入完成、条目单条更新（仅清树缓存与该条目缓存，不清 `cs:version:active`）。
4. 缓存击穿防护：重建使用 `Redisson` 分布式锁 `cs:tree:build:{versionId}:{subjectCode}`（等待 3s），未抢到锁的请求读旧值（Graceful Degradation：树数据允许 6h 级陈旧，绝不因缓存故障拒绝服务——Redis 不可用时直接回源 DB 并打点告警，错误码不对外暴露）。

### 4.3 版本差异对比算法

目标：回答「2011 版 → 2022 版某学科的条目怎么变了、旧映射怎么迁」。三阶段：

```java
public class VersionDiffService {

    /** 阶段1：编码锚定 —— 新旧版本条目按 item_code 语义段对齐。
     *  CS-MATH-2011-NA-NR-003 vs CS-MATH-2022-NA-NR-003
     *  取去掉年份段的尾部编码做主锚点；主锚点唯一匹配 → 进入阶段2 */
    Map<String, MatchedPair> anchorByCode(List<Item> oldItems, List<Item> newItems) {
        Map<String, List<Item>> newByTail = newItems.stream()
                .collect(Collectors.groupingBy(Item::tailCode));   // NA-NR-003
        return oldItems.stream()
                .flatMap(o -> newByTail.getOrDefault(o.tailCode(), List.of()).stream()
                        .map(n -> new MatchedPair(o, n)))
                .filter(MatchedPair::isUnique)                     // 一对多/多对一剔除
                .collect(toMap(MatchedPair::key, identity()));
    }

    /** 阶段2：文本相似度 —— 锚定对 + 未锚定条目池。
     *  TF-IDF(2-gram) 余弦相似度；阈值：≥0.75 视为配对候选 */
    DiffReport classify(MatchedPair p) {
        double sim = tfidfCosine(p.old().getContent(), p.new().getContent());
        if (sim >= 0.98) return DiffReport.unchanged(p);
        if (sim >= 0.75) return DiffReport.contentChanged(p, sim);
        return DiffReport.needsManualMatch(p);                     // 锚点相同但文本重写
    }

    /** 阶段3：未配对池二次匹配 —— SPLIT/MERGE 检测。
     *  一旧对多新（相似度均≥0.60）标记 SPLIT；多旧对一新标记 MERGE；
     *  均标记 needsManualMatch，仅生成迁移建议，绝不自动执行 */
}
```

**迁移执行规则：**

| 变更类型 | 映射迁移策略 |
|----------|--------------|
| UNCHANGED | 无需处理 |
| CONTENT_CHANGED 且 sim ≥ 0.85 | 自动迁移旧条目全部 `standard_mapping` 至新条目，`verified` 保持原值，发布 `cs.mapping.migrated` 事件 |
| CONTENT_CHANGED 且 0.75 ≤ sim < 0.85 | 生成迁移工单，教研确认后执行 |
| ADDED | 无迁移 |
| REMOVED | 映射置 `mapping_type=ORPHAN`（软隔离），连续 90 天无人工处理自动归档并告警 |
| SPLIT / MERGE / needsManualMatch | 仅生成工单 |

### 4.4 AI 映射回写与人工审核

回写入口即 §3.2.5，审核流在工作台「AI 对齐待审」：

```text
AI_AUTO 写入(confidence 0.60~0.85) ──► 审核队列(ZSET cs:review:pending, 分值=confidence 升序)
        │                                      │
        │                          教研「通过」→ verified=1（CAS 更新，事件 cs.mapping.verified）

```

### 4.5 覆盖率统计预聚合

```sql
-- 每日 02:30，按 (课标版本, 学科, 教材版本) 物化，幂等重跑（先删后插当日分区）
INSERT INTO curriculum_coverage_daily
  (stat_date, version_id, subject_code, textbook_version_id,
   total_items, content_covered, question_covered, uncovered_item_codes, computed_at)
SELECT CURDATE(), si.version_id, si.subject_code, tbv.id,
       COUNT(DISTINCT si.id),
       COUNT(DISTINCT CASE WHEN cm_ch.standard_item_id IS NOT NULL THEN si.id END),
       COUNT(DISTINCT CASE WHEN cm_q.standard_item_id IS NOT NULL THEN si.id END),
       /* uncovered_item_codes 由应用层拼装 JSON */
       NOW()
FROM standard_item si
LEFT JOIN (SELECT DISTINCT standard_item_id FROM standard_mapping
            WHERE target_type='CHAPTER' AND verified=1) cm_ch ON cm_ch.standard_item_id = si.id
LEFT JOIN (SELECT DISTINCT standard_item_id FROM standard_mapping
            WHERE target_type='QUESTION') cm_q ON cm_q.standard_item_id = si.id
CROSS JOIN textbook_version tbv
WHERE si.status='ACTIVE'
GROUP BY si.version_id, si.subject_code, tbv.id;
```

> 说明：题目覆盖率不要求 `verified=1`（AI 自动标注即视为覆盖，与题目标注引擎口径一致）；内容覆盖率要求人工验证（`verified=1`），防止 AI 幻觉映射虚增覆盖率。两口径差异在对齐度分析服务的看板中并列展示。

### 5.1 课标版本状态机

| 守卫 | 规则 | 违反错误码 |
|------|------|-----------|
| G1 | `publish` 仅允许 `DRAFT` 状态 | 53702 |
| G2 | 条目导入（FULL/INCREMENTAL）仅允许 `DRAFT`；`CORRECTION` 允许 `DRAFT/PUBLISHED`（限非结构字段） | 53722 |
| G3 | `publish` 前置检查：≥1 个主题群、≥1 个条目、≥1 条素养、≥1 条学业水平；`effective_date` ≤ 今天+365 天 | 53704 |
| G4 | `PUBLISHED` 版本条目结构变更（增删条目/改层级）拒绝；仅允许 CORRECTION 导入 | 53705 |
| G5 | `archive` 前置检查：无教材版本将其标记为 `active_curriculum_version_id`（反查教材服务）；存在则返回依赖清单 | 53703 |
| G6 | 同学段+学科同时仅一个版本处于「已生效未归档」状态（发布时若已有生效版本，旧版本自动置 ARCHIVED 并记录版本链） | 自动流转 |
| G7 | `clone` 产生新 `DRAFT`，`previous_version_id` 指向源版本，条目/素养/主题树深拷贝，映射关系不拷贝 | — |

**发布动作副作用（同一事务 + Outbox）：**

1. 旧生效版本 → ARCHIVED（G6）；2. 写 `cs:version:active:{stage}:{subject}` 缓存（直写）；3. 清该学科全部树缓存；4. Outbox 发布 `cs.version.published`（订阅方：教材对齐分析服务触发重算、题目标注引擎刷新课标索引、管理后台看板刷新）。

### 5.2 导入批次状态机

```text
PENDING ──claim──► PROCESSING ──┬─全部成功──► COMPLETED
   │                            ├─部分失败──► COMPLETED（failed_items>0，告警）
   │                            └─全部失败/异常──► FAILED
   └─超过 24h 未被领取（Worker 全挂）──► FAILED（超时兑底 Job）
```

| 守卫 | 规则 | 错误码 |
|------|------|--------|
| B1 | 同一版本存在 `PENDING/PROCESSING` 批次时拒绝新导入 | 53721 |
| B2 | `claim` 仅允许 `PENDING`，Redis 锁 `cs:import:lock:{versionId}` 30min 续期 | 53721 |
| B3 | `PROCESSING` 超过 6h 未完成（卡死）→ 运维告警 + 强制置 FAILED（error_log 记录卡死块号） | 兑底 |
| B4 | FAILED/POR COMPLETED 批次不可重跑；修复文件后新建 INCREMENTAL 批次 | 53720 |

### 5.3 条目与映射的轻量状态

- `standard_item.status`：`ACTIVE → DEPRECATED`（单向下行；存在非 ORPHAN 映射时拒绝，53712）；DEPRECATED 条目不进树、不进搜索，历史映射保留供追溯。
- `standard_mapping`：无独立状态列，生命周期由 `verified(0/1)` + `mapping_type(含 ORPHAN)` 表达：`AI_AUTO 未审 → verified=1（人工确认）/ 删除 / ORPHAN 化（版本对比 REMOVED）`。审核动作仅允许 pending 队列内记录，越权操作返回 53733。

## 9. 部署与配置

模块化单体中的独立 module（`curriculum-standard`），无独立进程；读多写少，随主应用部署。

```yaml
# application-curriculum.yml
curriculum:
  import:
    max-file-size: 10MB
    chunk-size: 200
    worker-concurrency: 2            # 全局仅 2 个导入 Worker，防小版本写放大
    lock-ttl-minutes: 30
  tree:
    cache-ttl-hours: 6
    jitter-hours: 1
    local-cache-spec: maximumSize=64,recordFreq
    with-content-default: false
  mapping:
    ai-auto-accept-threshold: 0.85   # ≥ 此值直接入库
    ai-review-threshold: 0.60        # ≥ 此值进待审，< 此值拒收
    review-expire-days: 14
  diff:
    anchor-similarity-auto-migrate: 0.85
    text-pair-threshold: 0.75
  coverage:
    cron: "30 2 * * *"
    realtime-query-timeout-ms: 3000  # 超时降级返回昨日物化数据并标记 freshness=STALE
```

容量估算：全部学段全学科课标条目约 1.2 万条（含 2022 义教 20 学科 + 2017/2020 高中 14 学科），映射关系约 40 万条，单表体量极小；FULLTEXT + 索引足够，无需引入 ES。

## 10. 安全与权限

1. **读写分离鉴权**：查询类接口对学生端/家长端只读开放（需登录态）；管理类接口（创建/导入/发布/迁移执行）仅限 `OPS_CURRICULUM_EDITOR` / `OPS_CURRICULUM_ADMIN` 角色，发布与映射迁移需 ADMIN（双人复核：发布操作需另一管理员 confirm token）。
2. **审计**：全部管理端写操作入审计日志（操作人、diff 前后快照、traceId），保留 3 年。
3. **数据边界**：课标数据为平台级公开教育数据，无学生个人数据；但 `error_log` 可能含教研备注，接口仅管理员可见。
4. **导入文件安全**：Excel/JSON 解析禁用外部实体（POI `XMLConstants.DISALLOW_DOCTYPE`）；文件先落对象存储再由 Worker 拉取，不信任客户端文件名。
