# 服务端-混沌工程实践与系统韧性自动化验证平台 详细设计

## 1. 概述

### 1.1 模块定位

混沌工程（Chaos Engineering）是在系统正常运行的分布式环境中，主动注入故障以验证系统韧性的工程实践。对于 PrimeTop 这类包含数百个微服务、多模型 AI 调用链路、实时互动通道和支付链路的复杂系统，仅靠被动监控和告警不足以发现隐藏的单点故障、级联崩溃和超时雪崩问题。

混沌工程平台是 SRE 体系中的**主动验证层**，与已有的 SLO 管理平台（目标定义）、分布式链路追踪（观测层）、限流熔断体系（防护层）形成完整的可靠性保障闭环。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 故障注入 | 支持网络、Pod、数据库、缓存、AI 供应商等多种故障类型的可控注入 |
| 实验编排 | 定义实验假设、爆炸半径、自动终止条件和回滚策略 |
| 自动化调度 | 支持 Game Day 手动触发和 CI/CD 流水线自动执行 |
| 韧性验证 | 自动采集 SLO 指标，判定系统在故障下的表现是否符合预期 |
| 安全护栏 | 通过爆炸半径控制、健康守护进程和自动中止机制保障生产安全 |
| 知识沉淀 | 归档实验报告，追踪发现的问题和修复进展 |

### 1.4 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 故障注入框架 | Chaos Mesh 2.x | Kubernetes 原生，CRD 驱动，CNCF 毕业项目，社区活跃 |
| 实验编排 | 自研调度服务 + Chaos Mesh CRD | 需要适配 PrimeTop 的 AI 链路和教育业务语义 |
| 指标采集 | Prometheus + Thanos | 已有基础设施，无需额外引入 |
| 实验数据存储 | PostgreSQL + ClickHouse | 关系数据（实验定义）+ 时序数据（指标快照） |
| 可视化 | Grafana + 自研实验看板 | Grafana 展示指标，自研看板展示实验编排和报告 |
| 告警通知 | 复用现有告警通道 | 飞书/钉钉 Webhook + 短信 |

## 2. 数据模型

### 2.1 核心实体关系

```
chaos_experiment (实验定义)
  ├── chaos_experiment_run (执行记录)
  │     ├── chaos_metric_snapshot (指标快照)
  │     └── chaos_event_log (事件日志)
  └── chaos_finding (发现的问题)
        └── chaos_finding remediation (修复追踪)
```

### 2.2 数据库表结构

#### 2.2.1 实验定义表 `chaos_experiment`

```sql
CREATE TABLE chaos_experiment (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    experiment_key  VARCHAR(128) NOT NULL UNIQUE COMMENT '唯一标识，如 exp-ai-provider-downgrade',
    name            VARCHAR(256) NOT NULL COMMENT '实验名称',
    description     TEXT COMMENT '实验描述',
    
    -- 故障类型与参数
    fault_type      VARCHAR(64) NOT NULL COMMENT '故障类型: network_delay/pod_kill/db_latency/cache_miss/ai_error/...',
    fault_namespace VARCHAR(128) NOT NULL COMMENT '目标命名空间',
    fault_target    JSON NOT NULL COMMENT '故障注入目标，见下方详细定义',
    fault_params    JSON NOT NULL COMMENT '故障参数，见下方详细定义',
    
    -- 实验假设与判定
    hypothesis      TEXT NOT NULL COMMENT '韧性假设，如"AI供应商超时后3s内切换备用模型"',
    slo_keys        JSON NOT NULL COMMENT '关联的SLO指标key列表',
    success_criteria JSON NOT NULL COMMENT '成功标准，如 {"error_rate_max": 0.01, "p99_latency_max_ms": 5000}',
    
    -- 安全控制
    blast_radius    JSON NOT NULL COMMENT '爆炸半径控制',
    max_duration_s  INT NOT NULL DEFAULT 300 COMMENT '最长持续时间(秒)',
    auto_abort_rules JSON NOT NULL COMMENT '自动中止规则',
    guardrail_services JSON NOT NULL COMMENT '守护服务列表，这些服务异常则中止',
    
    -- 调度
    schedule_type   VARCHAR(32) NOT NULL DEFAULT 'manual' COMMENT 'manual/cron/cicd',
    schedule_cron   VARCHAR(128) COMMENT 'cron表达式，schedule_type=cron时有效',
    cicd_stage      VARCHAR(64) COMMENT 'CI/CD阶段名，schedule_type=cicd时有效',
    
    -- 生命周期
    status          VARCHAR(32) NOT NULL DEFAULT 'draft' COMMENT 'draft/approved/active/paused/archived',
    created_by      VARCHAR(64) NOT NULL,
    approved_by     VARCHAR(64),
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_status (status),
    INDEX idx_schedule (schedule_type, status),
    INDEX idx_fault_type (fault_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='混沌实验定义';
```

#### 2.2.2 执行记录表 `chaos_experiment_run`

```sql
CREATE TABLE chaos_experiment_run (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    experiment_id   BIGINT NOT NULL COMMENT '关联实验定义',
    run_key         VARCHAR(64) NOT NULL UNIQUE COMMENT '执行唯一标识',
    
    -- 执行状态
    status          VARCHAR(32) NOT NULL COMMENT 'pending/injecting/running/observing/completed/aborted/failed',
    trigger_source  VARCHAR(32) NOT NULL COMMENT 'manual/cron/cicd/auto-remediation',
    triggered_by    VARCHAR(64) NOT NULL,
    
    -- 时间线
    started_at      DATETIME NOT NULL,
    injected_at     DATETIME COMMENT '故障注入完成时间',
    completed_at    DATETIME COMMENT '实验完成时间',
    duration_s      INT COMMENT '实际持续时间',
    
    -- 结果
    result          VARCHAR(32) COMMENT 'passed/failed/inconclusive',
    result_summary  TEXT COMMENT '结果摘要',
    result_detail   JSON COMMENT '详细结果数据',
    
    -- 中止信息
    abort_reason    VARCHAR(256) COMMENT '中止原因',
    abort_triggered_by VARCHAR(64) COMMENT '中止触发者(系统/人工)',
    
    -- Chaos Mesh 工作流 ID
    chaos_workflow_id VARCHAR(128) COMMENT 'Chaos Mesh Workflow ID',
    
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_experiment (experiment_id),
    INDEX idx_status (status),
    INDEX idx_started (started_at),
    CONSTRAINT fk_run_experiment FOREIGN KEY (experiment_id) REFERENCES chaos_experiment(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='混沌实验执行记录';
```

#### 2.2.3 指标快照表 `chaos_metric_snapshot`

```sql
CREATE TABLE chaos_metric_snapshot (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    run_id          BIGINT NOT NULL COMMENT '关联执行记录',
    metric_key      VARCHAR(128) NOT NULL COMMENT '指标key，如 error_rate/p99_latency/ai_success_rate',
    metric_value    DOUBLE NOT NULL COMMENT '指标值',
    metric_labels   JSON COMMENT '标签维度，如 {"service":"ai-service","model":"gpt-4"}',
    captured_at     DATETIME NOT NULL COMMENT '采集时间',
    phase           VARCHAR(32) NOT NULL COMMENT 'baseline/fault_injected/recovering',
    
    INDEX idx_run (run_id),
    INDEX idx_metric (metric_key, captured_at),
    CONSTRAINT fk_snapshot_run FOREIGN KEY (run_id) REFERENCES chaos_experiment_run(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='实验期间指标快照';
```

#### 2.2.4 问题发现表 `chaos_finding`

```sql
CREATE TABLE chaos_finding (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    experiment_id   BIGINT NOT NULL,
    run_id          BIGINT NOT NULL,
    
    title           VARCHAR(512) NOT NULL COMMENT '问题标题',
    severity        VARCHAR(16) NOT NULL COMMENT 'critical/high/medium/low',
    category        VARCHAR(64) NOT NULL COMMENT 'cascading_failure/no_fallback/timeout_misconfig/resource_exhaustion/data_inconsistency/...',
    description     TEXT NOT NULL COMMENT '详细描述',
    evidence        JSON NOT NULL COMMENT '证据数据(指标图表链接/日志片段/trace链接)',
    
    -- 修复追踪
    remediation_status VARCHAR(32) NOT NULL DEFAULT 'open' COMMENT 'open/in_progress/resolved/wont_fix',
    remediation_owner VARCHAR(64),
    remediation_plan TEXT,
    jira_issue_key  VARCHAR(64),
    resolved_at     DATETIME,
    
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_experiment (experiment_id),
    INDEX idx_severity (severity, remediation_status),
    CONSTRAINT fk_finding_experiment FOREIGN KEY (experiment_id) REFERENCES chaos_experiment(id),
    CONSTRAINT fk_finding_run FOREIGN KEY (run_id) REFERENCES chaos_experiment_run(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='混沌实验发现的问题';
```

### 3.3 错误码定义

| 错误码 | HTTP Status | 说明 |
|--------|-------------|------|
| CHAOS_001 | 400 | 实验定义参数不合法 |
| CHAOS_002 | 403 | 实验目标命名空间不在允许列表中 |
| CHAOS_003 | 403 | 爆炸半径超过安全阈值（如影响用户>1%） |
| CHAOS_004 | 403 | 当前时间不在允许的实验时间窗口内 |
| CHAOS_005 | 409 | 同一实验已有运行中的实例 |
| CHAOS_006 | 409 | 实验未审批，不允许在生产环境运行 |
| CHAOS_007 | 422 | 守护服务（Guardrail）当前状态不健康，拒绝启动 |
| CHAOS_008 | 422 | Chaos Mesh 工作流创建失败 |

### 4.3 自动中止监控引擎

自动中止是混沌实验在复杂生产环境中安全运行的核心保障。

```go
package chaos

// AutoAbortMonitor 自动中止监控器
type AutoAbortMonitor struct {
    runID         int64
    rules         []AbortRule
    metricClient  metrics.Client
    checkInterval time.Duration
    abortCh       chan AbortSignal
}

type AbortRule struct {
    MetricKey       string  `json:"metric_key"`
    Condition       string  `json:"condition"`        // >, <, ==, drop_percent
    Threshold       float64 `json:"threshold"`
    WindowSeconds   int     `json:"window_s"`
    GuardrailSvc    string  `json:"guardrail_service"` // 可选
    Action          string  `json:"action"`           // abort
}

type AbortSignal struct {
    Rule      AbortRule
    ActualVal float64
    Timestamp time.Time
    Reason    string
}

func (m *AutoAbortMonitor) Run(ctx context.Context) {
    ticker := time.NewTicker(m.checkInterval)
    defer ticker.Stop()

    for {
        select {
        case <-ctx.Done():
            return // 实验正常结束
        case <-ticker.C:
            if signal := m.evaluate(); signal != nil {
                m.abortCh <- *signal
                return
            }
        }
    }
}

func (m *AutoAbortMonitor) evaluate() *AbortSignal {
    now := time.Now()
    for _, rule := range m.rules {
        val, err := m.queryMetricWithWindow(rule, now)
        if err != nil {
 log.Warn("query abort metric failed: key=%s err=%v", rule.MetricKey, err)
            continue
        }
        if m.isBreached(rule, val) {
            return &AbortSignal{
                Rule:      rule,
                ActualVal: val,
                Timestamp: now,
                Reason: fmt.Sprintf("metric %s = %.4f %s %.4f",
                    rule.MetricKey, val, rule.Condition, rule.Threshold),
            }
        }
    }
    return nil
}

func (m *AutoAbortMonitor) queryMetricWithWindow(rule AbortRule, now time.Time) (float64, error) {
    query := fmt.Sprintf(
        "avg_over_time(%s{%s}["+strconv.Itoa(rule.WindowSeconds)+"s])",
        rule.MetricKey,
        m.buildLabelSelector(rule),
    )
    return m.metricClient.QueryInstant(ctx, query, now)
}

func (m *AutoAbortMonitor) isBreached(rule AbortRule, val float64) bool {
    switch rule.Condition {
    case ">":
        return val > rule.Threshold
    case "<":
        return val < rule.Threshold
    case "drop_percent":
        baseline := m.getBaseline(rule.MetricKey)
        if baseline == 0 {
            return false
        }
        dropPct := (baseline - val) / baseline * 100
        return dropPct > rule.Threshold
    default:
        return false
    }
}
```

### 4.4 结果判定引擎

```go
// ResultJudge 结果判定器
type ResultJudge struct {
    baselineMetrics map[string]float64 // 实验前基线
    faultMetrics    map[string]float64 // 故障期间峰值
    recoveryMetrics map[string]float64 // 恢复后稳态
}

type CriteriaResult struct {
    MetricKey  string      `json:"metric_key"`
    Expected   CriteriaSpec `json:"expected"`
    ActualMax  float64     `json:"actual_max"`
    Passed     bool        `json:"passed"`
}

func (j *ResultJudge) Judge(criteria []CriteriaSpec) (string, []CriteriaResult) {
    results := make([]CriteriaResult, 0, len(criteria))
    allPassed := true
    inconclusive := false

    for _, c := range criteria {
        actual, exists := j.faultMetrics[c.MetricKey]
        if !exists {
            inconclusive = true
            results = append(results, CriteriaResult{
                MetricKey: c.MetricKey,
                Expected:  c,
                Passed:    false,
            })
            continue
        }

        passed := j.compare(actual, c.Op, c.Value)
        results = append(results, CriteriaResult{
            MetricKey: c.MetricKey,
            Expected:  c,
            ActualMax: actual,
            Passed:    passed,
        })
        if !passed {
            allPassed = false
        }
    }

    if inconclusive {
        return "inconclusive", results
    }
    if allPassed {
        return "passed", results
    }
    return "failed", results
}

func (j *ResultJudge) compare(actual float64, op string, threshold float64) bool {
    switch op {
    case "<=":
        return actual <= threshold
    case ">=":
        return actual >= threshold
    case "<":
        return actual < threshold
    case ">":
        return actual > threshold
    case "==":
        return actual == threshold
    default:
        return false
    }
}
```

```go
package chaos

import (
    "encoding/json"
    "fmt"
)

// ChaosMeshWorkflowBuilder 将平台实验定义转为 Chaos Mesh Workflow
type ChaosMeshWorkflowBuilder struct {
    experiment *ChaosExperiment
    runID      int64
}

func (b *ChaosMeshWorkflowBuilder) Build() (string, error) {
    wf := map[string]interface{}{
        "apiVersion": "chaos-mesh.org/v1alpha1",
        "kind":       "Workflow",
        "metadata": map[string]string{
            "name":      fmt.Sprintf("chaos-run-%d", b.runID),
            "namespace": "chaos-mesh",
        },
    }

    steps := []map[string]interface{}{}

    // Step 1: 基线采集等待
    steps = append(steps, b.buildSleepStep(30, "baseline-wait"))

    // Step 2: 注入故障
    faultAction, err := b.buildFaultAction()
    if err != nil {
        return "", fmt.Errorf("build fault action: %w", err)
    }
    steps = append(steps, faultAction)

    // Step 3: 故障持续期间等待
    faultDuration := b.getFaultDurationSeconds()
    steps = append(steps, b.buildSleepStep(faultDuration, "fault-duration"))

    // Step 4: 自动恢复（Chaos Mesh 删除 CRD 后自动恢复）
    steps = append(steps, b.buildSleepStep(60, "recovery-wait"))

    wf["spec"] = map[string]interface{}{
        "entry":      "main",
        "templates":  steps,
    }

    yaml, err := json.Marshal(wf)
    if err != nil {
        return "", err
    }
    return string(yaml), nil
}

func (b *ChaosMeshWorkflowBuilder) buildFaultAction() (map[string]interface{}, error) {
    params := b.experiment.FaultParams
    switch b.experiment.FaultType {
    case "network_delay":
        return b.buildNetworkChaos(params), nil
    case "pod_kill":
        return b.buildPodChaos(params), nil
    case "cpu_burn":
        return b.buildStressChaos(params), nil
    case "ai_provider_error":
        return b.buildHTTPChaos(params), nil
    case "db_latency":
        return b.buildHTTPChaos(params), nil
    case "disk_fill":
        return b.buildIOChaos(params), nil
    default:
        return nil, fmt.Errorf("unsupported fault type: %s", b.experiment.FaultType)
    }
}

            "selector": b.buildSelector(),

                "correlation": fmt.Sprintf("%v", params["correlation"]),
                "jitter":      fmt.Sprintf("%vms", params["variation_ms"]),
            },
            "direction": params["direction"],
            "duration":  fmt.Sprintf("%vs", params["duration_s"]),
```

## 6. 关键代码示例

### 6.1 实验执行服务 (核心编排)

```go
package chaos

import (
    "context"
    "fmt"
    "time"
)

type ExperimentExecutor struct {
    repo          Repository
    chaosMesh     ChaosMeshClient
    metricService MetricService
    abortMonitor  *AutoAbortMonitor
    notifyService NotifyService
}

func (e *ExperimentExecutor) Execute(ctx context.Context, runID int64) error {
    run, err := e.repo.GetRun(ctx, runID)
    if err != nil {
        return fmt.Errorf("get run: %w", err)
    }

    exp, err := e.repo.GetExperiment(ctx, run.ExperimentID)
    if err != nil {
        return fmt.Errorf("get experiment: %w", err)
    }

    // 1. 前置安全检查
    if err := e.runPreflightChecks(ctx, exp); err != nil {
        e.markFailed(ctx, run, fmt.Sprintf("preflight failed: %v", err))
        return err
    }

    // 2. 采集基线指标
    e.updateStatus(ctx, run, "collecting-baseline")
    baseline, err := e.metricService.CaptureBaseline(ctx, exp.SLOKeys, 30*time.Second)
    if err != nil {
        e.markFailed(ctx, run, fmt.Sprintf("capture baseline: %v", err))
        return err
    }

    // 3. 生成并提交 Chaos Mesh Workflow
    e.updateStatus(ctx, run, "injecting")
    builder := &ChaosMeshWorkflowBuilder{experiment: exp, runID: runID}
    workflowYAML, err := builder.Build()
    if err != nil {
        e.markFailed(ctx, run, fmt.Sprintf("build workflow: %v", err))
        return err
    }

    wfID, err := e.chaosMesh.ApplyWorkflow(ctx, workflowYAML)
    if err != nil {
        e.markFailed(ctx, run, fmt.Sprintf("apply workflow: %v", err))
        return err
    }
    e.repo.UpdateRunChaosWorkflowID(ctx, runID, wfID)

    // 4. 启动自动中止监控
    e.updateStatus(ctx, run, "running")
    abortCh := make(chan AbortSignal, 1)
    monitor := &AutoAbortMonitor{
        runID:         runID,
        rules:         exp.AutoAbortRules,
        metricClient:  e.metricService,
        checkInterval: 5 * time.Second,
        abortCh:       abortCh,
    }

    monitorCtx, monitorCancel := context.WithTimeout(ctx,
        time.Duration(exp.MaxDurationS)*time.Second)
    go monitor.Run(monitorCtx)

    // 5. 持续采集指标
    faultMetrics, err := e.metricService.CaptureDuring(ctx, exp.SLOKeys,
        time.Duration(exp.MaxDurationS)*time.Second, 10*time.Second)
    monitorCancel()

    // 检查是否被中止
    select {
    case signal := <-abortCh:
        e.abortExperiment(ctx, run, signal)
        e.chaosMesh.DeleteWorkflow(ctx, wfID) // 紧急清理
        return nil
    default:
    }

    // 6. 进入恢复观测期
    e.updateStatus(ctx, run, "observing")
    e.chaosMesh.DeleteWorkflow(ctx, wfID) // 删除 CRD，触发自动恢复
    time.Sleep(60 * time.Second)          // 等待恢复

    // 7. 结果判定
    judge := &ResultJudge{
        baselineMetrics: baseline,
        faultMetrics:    faultMetrics.Peak(),
        recoveryMetrics: faultMetrics.Latest(),
    }
    result, details := judge.Judge(exp.SuccessCriteria)

    e.repo.UpdateRunResult(ctx, runID, result, details)
    e.notifyService.NotifyExperimentResult(ctx, run, exp, result, details)

    // 8. 自动提取 findings
    if result == "failed" {
        e.autoExtractFindings(ctx, run, exp, details, baseline, faultMetrics)
    }

    return nil
}

func (e *ExperimentExecutor) runPreflightChecks(ctx context.Context, exp *ChaosExperiment) error {
    // 检查时间窗口
    if !e.isWithinTimeWindow(exp.BlastRadius.TimeWindow) {
        return fmt.Errorf("current time not in allowed window %s",
            exp.BlastRadius.TimeWindow.AllowedHours)
    }

    // 检查守护服务健康状态
    for _, svc := range exp.GuardrailServices {
        healthy, err := e.metricService.CheckServiceHealth(ctx, svc)
        if err != nil || !healthy {
            return fmt.Errorf("guardrail service %s is not healthy", svc)
        }
    }

    // 检查是否有冲突的运行中实验
    conflicting, err := e.repo.CheckConflictingRuns(ctx, exp.FaultNamespace,
        exp.FaultTarget.LabelSelectors)
    if err != nil {
        return fmt.Errorf("check conflicts: %w", err)
    }
    if conflicting {
        return fmt.Errorf("a conflicting experiment is already running in the same namespace/target")
    }

    // 检查爆炸半径
    activeUsers, err := e.metricService.GetActiveUserCount(ctx)
    if err != nil {
        return fmt.Errorf("get active users: %w", err)
    }
    maxAffected := float64(activeUsers) * exp.BlastRadius.MaxAffectedUsersPercent / 100
    if int(maxAffected) > exp.BlastRadius.MaxAffectedUsersCount {
        return fmt.Errorf("blast radius too large: estimated %d users affected",
            int(maxAffected))
    }

    return nil
}
```

```go
package chaos

import (

type ExperimentReport struct {

func (r *ReportGenerator) Generate(ctx context.Context, runID int64) (*ExperimentReport, error) {
    run, err := r.repo.GetRun(ctx, runID)

    // 生成 Grafana 深链接
    chartURLs := r.generateGrafanaDeepLinks(exp.SLOKeys, run.StartedAt, run.CompletedAt)

    // 生成时间线
    timeline := r.buildTimeline(run, snapshots)

    // 生成摘要
    summary := r.buildSummary(exp, run, snapshots)

    return &ExperimentReport{

        ExperimentKey: exp.ExperimentKey,
        Name:          exp.Name,
        FaultType:     exp.FaultType,
        StartTime:     run.StartedAt,
        Duration:      fmt.Sprintf("%ds", run.DurationS),
        Result:        run.Result,
        Summary:       summary,
        MetricsChart:  chartURLs,
        Findings:      r.getFindingSummaries(ctx, runID),
        Timeline:      timeline,
    }, nil
}

func (r *ReportGenerator) generateGrafanaDeepLinks(sloKeys []string, start, end time.Time) map[string]string {
    urls := make(map[string]string)
    from := start.UnixMilli()
    to := end.UnixMilli()

    for _, key := range sloKeys {
        panelURL := fmt.Sprintf("%s/d/chaos-overview?from=%d&to=%d&var-metric=%s",
            r.grafanaBaseURL, from, to, key)
        urls[key] = panelURL
    }
    return urls
}
```

## 7. 错误处理与安全

### 7.1 异常处理矩阵

| 异常类型 | 场景 | 处理策略 | 用户影响 |
|----------|------|---------|---------|
| Chaos Mesh 不可达 | 创建 Workflow 时 | 立即标记 run 为 failed，通知 SRE | 无（实验未开始） |
| 故障注入超时未生效 | CRD 创建后但 Pod 未注入 | 等待 30s 后重试查询，超时则标记 inconclusive | 无影响 |
| 自动中止触发 | 守护服务异常 | 立即删除 CRD，终止实验 | 最小化生产影响 |
| 指标采集失败 | Prometheus 查询超时 | 使用最近一次缓存值，标记 metric 为 stale | 结果可能 inconclusive |
| Chaos Mesh CRD 删除失败 | 清理阶段 | 指数退避重试 3 次，超时后告警人工介入 | 故障可能持续，需人工处理 |
| 网络分区导致实验失控 | 无法连接目标集群 | 全局超时 + Chaos Mesh TTL 自动过期 | Chaos Mesh TTL 到期后自动恢复 |

### 7.2 安全机制

#### 7.2.1 多级审批流程

```
实验创建者 (SRE/开发)
      │
      ▼
[提交审批]
      │
      ├── 影响范围 < 0.1% 用户 + 非核心服务 → 自动审批通过
      │
      ├── 影响范围 0.1%~1% 用户 或 核心服务   → SRE Lead 审批
      │
      └── 影响范围 > 1% 用户 或 支付/认证服务  → SRE Lead + CTO 双重审批
```

#### 7.2.2 TTL 安全网

所有 Chaos Mesh CRD 必须设置 TTL（`spec.duration`），确保即使控制面失联，故障也会自动消除：

```yaml
spec:
  duration: "300s"  # 最长 5 分钟，到期自动恢复
```

#### 7.2.3 命名空间隔离

- 混沌工程控制面部署在 `chaos-mesh` 专用命名空间
- Chaos Controller 仅被授权在指定命名空间注入故障
- 通过 Kubernetes RBAC 限制 Chaos Mesh 的 Target Scope

## 8. 性能优化

### 8.1 指标查询优化

实验期间每 10s 采集一次指标快照，使用 Prometheus 的 `query_range` API 批量拉取，避免频繁单点查询。

```go
// 批量查询优化
func (s *MetricService) CaptureDuring(ctx context.Context, keys []string,
    duration time.Duration, interval time.Duration) (*MetricSeries, error) {

    end := time.Now()
    start := end.Add(-duration)

    // 并发查询多个指标
    var wg sync.WaitGroup
    results := make(map[string][]MetricPoint)
    var mu sync.Mutex

    for _, key := range keys {
        wg.Add(1)
        go func(k string) {
            defer wg.Done()
            points, err := s.promClient.QueryRange(ctx, k, start, end, interval)
            if err != nil {
                log.Warn("metric query failed: %s err=%v", k, err)
                return
            }
            mu.Lock()
            results[k] = points
            mu.Unlock()
        }(key)
    }
    wg.Wait()

    return &MetricSeries{Points: results}, nil
}
```

### 8.2 实验并发控制

- 同一命名空间同一时间最多允许 1 个实验运行
- 全局最多 3 个实验并发（跨命名空间）
- 通过分布式锁保证（Redis `SETNX chaos:lock:{namespace}`，TTL=实验最长持续时间）

### 8.3 数据清理策略

| 数据 | 保留策略 |
|------|----------|
| 实验定义 | 永久保留（归档不删除） |
| 执行记录 | 保留 180 天，之后归档到对象存储 |
| 指标快照 | 保留 90 天，之后从 ClickHouse 分区过期 |
| Finding 记录 | 关联 Jira，永久保留 |
| 审计日志 | 按现有审计日志策略（7 年） |

```go
func (s *SilenceManager) CreateExperimentSilence(ctx context.Context, runID int64,
    targetServices []string, duration time.Duration) error {
    matchers := make([]map[string]interface{}, 0, len(targetServices))
    for _, svc := range targetServices {
        matchers = append(matchers, map[string]interface{}{
            "name":  "service",
            "value": svc,
            "isRegex": false,
        })
    }

    silence := map[string]interface{}{
        "id":        fmt.Sprintf("chaos-run-%d", runID),
        "matchers":  matchers,
        "startsAt":  time.Now(),
        "endsAt":    time.Now().Add(duration + 10*time.Minute),
        "createdBy": "chaos-platform",
        "comment":   fmt.Sprintf("Auto-silenced by chaos experiment run #%d", runID),
    }

    return s.alertmanagerClient.CreateSilence(ctx, silence)
}
```
