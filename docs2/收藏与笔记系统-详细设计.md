# 收藏与笔记系统 - 详细设计

> 模块定位：跨模块用户内容收藏与标注基础设施，为 AI 对话、题目、知识点、教材章节等场景提供统一的收藏夹、书签和学习笔记能力。

---

## 1. 模块概述

### 1.1 功能目标

为学生提供一套统一的"收藏 + 笔记"体系：

1. **收藏夹（Favorites）**：用户可将 AI 对话消息、题目、知识点、教材章节等内容一键收藏，按分类与标签组织，支持快速检索。
2. **学习笔记（Notes）**：用户可在学习过程中针对任意内容源（对话、题目、章节、知识点）创建富文本笔记，支持 Markdown、LaTeX 公式、图片附件。
3. **文件夹管理（Folders）**：支持多级文件夹组织收藏与笔记，支持按学科、专题等维度分类。
4. **智能标签（Tags）**：系统自动推荐标签 + 用户自定义标签，实现跨学科、跨类型的灵活归类。
5. **全文检索**：支持对笔记内容、收藏标题、标签进行全文搜索。

### 1.2 覆盖场景

| 场景 | 收藏 | 笔记 | 说明 |
|------|------|------|------|
| AI 对话 | 收藏单条 AI 回答 | 在对话上下文中记笔记 | 保存有价值的讲解 |
| 题目浏览 | 收藏好题/经典题 | 记录解题思路、易错点 | 辅助错题本以外的题目积累 |
| 知识点学习 | 收藏知识卡片 | 补充个人理解、总结 | 考前快速回顾 |
| 教材章节 | 收藏章节/小节 | 记录课堂笔记、预习笔记 | 同步课堂配套 |
| 考点梳理 | 收藏考点清单 | 记录专题心得 | 备考冲刺 |
| 作文素材 | 收藏好词好句/范文 | 积累写作素材 | 作文辅导配套 |

### 1.3 设计原则

1. **统一抽象**：收藏和笔记面向多种内容类型，通过 `target_type` + `target_id` 统一抽象，避免每个模块重复实现。
2. **轻量触发**：收藏一键完成，笔记最低仅需文本输入，降低使用门槛。
3. **分龄适配**：低龄用户以收藏为主，笔记入口简化；高龄用户支持完整富文本编辑。
4. **离线优先**：收藏和笔记操作支持离线写入，联网后自动同步。
5. **配额限制**：免费用户有收藏/笔记上限，会员享有更大空间。

```python
async def create_collection(user_id: int, dto: CreateCollectionDTO) -> Collection:
    # 1. 配额检查
    await check_collection_quota(user_id)
    
    # 2. 去重检查
    existing = await collection_repo.find_by_user_and_target(
        user_id, dto.target_type, dto.target_id
    )
    if existing:
        raise BusinessException(ErrorCode.COLLECTION_ALREADY_EXISTS)
    
    # 3. 目标内容解析 — 根据类型获取标题、摘要、缩略图
    resolver = target_resolver_factory.get(dto.target_type)
    meta = await resolver.resolve(dto.target_id)
    
    # 4. 构建收藏记录
    collection = Collection(
        user_id=user_id,
        target_type=dto.target_type,
        target_id=dto.target_id,
        folder_id=dto.folder_id,
        title=dto.title or meta.title,
        summary=meta.summary,
        thumbnail_url=meta.thumbnail_url,
        source_meta=meta.source_meta,
    )
    
    # 5. 保存
    await collection_repo.create(collection)
    
    # 6. 保存标签
    if dto.tags:
        await tag_service.add_tags(user_id, collection.id, dto.tags)
    
    # 7. 更新文件夹计数
    if dto.folder_id:
        await folder_repo.increment_count(dto.folder_id, 1)
    
    # 8. 更新ES索引
    await search_service.index_collection(collection)
    
    # 9. 更新缓存计数
    await cache.incr(f"user:{user_id}:collection_count")
    
    # 10. 发布事件
    event_bus.publish(CollectionCreatedEvent(user_id, collection.id))
    
    return collection
```

```python
async def update_note(user_id: int, note_id: int, dto: UpdateNoteDTO) -> Note:
    note = await note_repo.get_by_id(note_id)
    
    # 权限检查
    if note.user_id != user_id:
        raise PermissionDeniedError()
    
    # 乐观锁检查
    if note.content_version != dto.expected_version:
        raise VersionConflictError(note.content_version)
    
    # 保存历史版本
    await note_history_repo.create(NoteHistory(
        note_id=note.id,
        version=note.content_version,
        title=note.title,
        content=note.content,
    ))
    
    # 保留最近 N 个版本（默认 20）
    await note_history_repo.trim_old_versions(note.id, keep=20)
    
    # 更新笔记
    note.title = dto.title
    note.content = dto.content
    note.content_plain = markdown_to_plain(dto.content)
    note.content_version += 1
    note.word_count = count_words(dto.content)
    
    await note_repo.update(note)
    await search_service.index_note(note)
    
    return note
```

## 4. 目标内容解析器（Target Resolver）

不同 target_type 需要不同的解析逻辑来获取标题、摘要、缩略图等信息。采用策略模式：

### 4.1 解析器接口

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class TargetMeta:
    title: str
    summary: str | None = None
    thumbnail_url: str | None = None
    source_meta: dict | None = None

class TargetResolver(ABC):
    @abstractmethod
    async def resolve(self, target_id: str) -> TargetMeta:
        ...

class TargetResolverFactory:
    _resolvers: dict[str, TargetResolver] = {}

    def register(self, target_type: str, resolver: TargetResolver):
        self._resolvers[target_type] = resolver

    def get(self, target_type: str) -> TargetResolver:
        resolver = self._resolvers.get(target_type)
        if not resolver:
            raise ValueError(f"Unsupported target_type: {target_type}")
        return resolver
```

## 7. 离线支持

### 7.1 客户端离线策略

收藏和笔记是高频操作，需要良好的离线支持：

```dart
/// 离线操作队列
class OfflineContentQueue {
  final Box<Map> _box; // Hive 本地存储

  /// 离线收藏
  Future<void> collectOffline(String targetType, String targetId, {
    String? title, List<String>? tags, int? folderId
  }) async {
    final op = OfflineOperation(
      id: const Uuid().v4(),
      type: 'create_collection',
      payload: {
        'target_type': targetType,
        'target_id': targetId,
        'title': title,
        'tags': tags,
        'folder_id': folderId,
      },
      createdAt: DateTime.now(),
      status: OperationStatus.pending,
    );
    await _box.put(op.id, op.toJson());

    // 立即在本地显示（乐观更新）
    await _localCache.addCollection(op.toLocalCollection());
  }

  /// 离线创建笔记
  Future<void> createNoteOffline(Note note) async {
    final op = OfflineOperation(
      id: const Uuid().v4(),
      type: 'create_note',
      payload: note.toJson(),
      createdAt: DateTime.now(),
      status: OperationStatus.pending,
    );
    await _box.put(op.id, op.toJson());
    await _localCache.addNote(note);
  }

  /// 网络恢复后同步
  Future<void> syncPending() async {
    final pending = _box.values
        .map((e) => OfflineOperation.fromJson(e))
        .where((op) => op.status == OperationStatus.pending)
        .toList()
      ..sort((a, b) => a.createdAt.compareTo(b.createdAt));

    for (final op in pending) {
      try {
        await _api.execute(op);
        await _box.delete(op.id);
      } on ConflictException {
        // 服务端已存在，标记为已处理
        await _box.delete(op.id);
      } catch (e) {
        op.retryCount++;
        if (op.retryCount >= 3) {
          op.status = OperationStatus.failed;
          await _box.put(op.id, op.toJson());
        }
      }
    }
  }
}
```

### 7.2 同步冲突策略

| 场景 | 策略 | 说明 |
|------|------|------|
| 同一条收藏重复添加 | 服务端去重 | `uk_user_target` 唯一索引 |
| 笔记并发编辑 | 乐观锁 + 版本号 | 客户端提交 expected_version |
| 离线删除后又恢复 | 以服务端状态为准 | 恢复操作优先 |
| 文件夹离线移动冲突 | 最后写入胜出 | 合并到目标文件夹 |

## 11. 性能与缓存策略

### 11.1 缓存策略

| 数据 | 缓存方式 | TTL | 更新策略 |
|------|----------|-----|----------|
| 文件夹树 | Redis JSON | 1h | 文件夹变更时主动失效 |
| 收藏计数 | Redis INCR | 24h | 增删时实时更新 |
| 笔记计数 | Redis INCR | 24h | 增删时实时更新 |
| 收藏状态（是否已收藏） | 客户端本地缓存 | 永久（LRU） | 操作后实时更新 |
| 热门标签 | Redis ZSET | 7d | 每次使用标签时 ZINCRBY |
| 笔记内容 | 客户端本地 SQLite | 永久 | 编辑后实时写入 |

### 11.2 列表查询优化

收藏列表和笔记列表默认走 MySQL 主库查询（数据量可控，配额限制上限），搜索走 ES。

```sql
-- 收藏列表查询（覆盖索引）
SELECT c.id, c.target_type, c.target_id, c.title, c.summary,
       c.thumbnail_url, c.is_pinned, c.created_at,
       GROUP_CONCAT(ct.tag_name) AS tags
FROM collections c
LEFT JOIN collection_tags ct ON ct.collection_id = c.id
WHERE c.user_id = ? AND c.folder_id = ?
GROUP BY c.id
ORDER BY c.is_pinned DESC, c.sort_order ASC, c.created_at DESC
LIMIT ? OFFSET ?;
```

对于高频用户（收藏 > 200），考虑将列表查询迁移到 ES。

### 11.3 批量检查优化

收藏状态检查接口（3.1.8）使用 Redis SET 批量查询：

```python
async def batch_check_collected(
    user_id: int, targets: list[tuple[str, str]]
) -> dict[str, bool]:
    """批量检查收藏状态"""
    # 构建 Redis SET key
    key = f"user:{user_id}:collected_set"
    
    # 尝试从 Redis SET 读取
    if await cache.exists(key):
        members = await cache.smembers(key)
        result = {}
        for tt, tid in targets:
            composed = f"{tt}:{tid}"
            result[composed] = composed in members
        return result
    
    # 缓存未命中，从 DB 加载并构建 SET
    all_collections = await collection_repo.find_all_simple(user_id)
    pipe = cache.pipeline()
    pipe.delete(key)
    for c in all_collections:
        pipe.sadd(key, f"{c.target_type}:{c.target_id}")
    pipe.expire(key, 3600)
    await pipe.execute()
    
    # 再次检查
    collected_set = {f"{c.target_type}:{c.target_id}" for c in all_collections}
    return {
        f"{tt}:{tid}": f"{tt}:{tid}" in collected_set
        for tt, tid in targets
    }
```

## 13. 安全与合规

### 13.1 数据隔离

- 所有查询强制带 `user_id` 条件，无全局查询接口
- API 层鉴权校验 `current_user.id == resource.user_id`

### 13.2 内容安全

- 笔记标题和内容在保存时经过内容安全过滤（敏感词检测）
- 用户上传的图片附件经过图片审核
- 标签名称经过敏感词过滤

```python
async def validate_note_content(title: str, content: str) -> None:
    """笔记内容安全校验"""
    # 合并标题和纯文本内容进行检测
    text = f"{title}\n{content}"
    result = await moderation_service.text_check(text)
    if result.is_rejected:
        raise ContentRejectedError(reason=result.reason)
    if result.is_sensitive:
        # 标记但不阻止，人工审核队列
        await audit_queue.add(NoteAuditItem(text=text, flags=result.flags))
```

### 13.3 未成年人保护

- 低龄用户笔记内容额外过滤（暴力、成人内容等）
- 收藏和笔记数据不对外分享（无社交功能）
- 家长端可查看子女笔记数量统计（不查看内容，尊重隐私）

## 14. 数据同步与 ES 索引

### 14.1 CDC 同步流程

```
MySQL (collections/notes)
    │
    ├── binlog (Debezium)
    │       │
    │       ▼
    │   Kafka Topic: primetop.user_content.cdc
    │       │
    │       ▼
    │   Flink Job: 解析 binlog → ES Index
    │       │
    │       ▼
    │   Elasticsearch
    │
    └── 关键操作同时双写（写DB + 异步写ES，保证最终一致）
```

### 14.2 索引刷新策略

- 写操作：异步写入 ES，延迟 < 2s
- 删除操作：同步标记 ES 文档为 deleted
- 全量重建：支持按用户范围重建索引的管理接口
