# 学习习惯养成与打卡系统 - 详细设计

## 1. 模块概述

### 1.1 定位

学习习惯养成与打卡系统是 PrimeTop 学习闭环中的**行为塑造层**，通过每日打卡、连续学习天数（Streak）、目标追踪、里程碑奖励等机制，帮助学生建立稳定的学习习惯，提升长期留存和学习效果。

### 1.2 与其他模块的关系

```
学习规划模块 ──→ 生成每日任务 ──→ 本模块（打卡 & 目标追踪）
                                              │
                                              ├──→ 运营活动与成长激励体系（发放勋章/积分）
                                              ├──→ 学习记录与进度追踪服务（读取学习行为）
                                              ├──→ 学习提醒与智能通知调度系统（推送提醒）
                                              ├──→ 学情分析模块（输入打卡数据）
                                              └──→ 家长中心（家长查看孩子打卡状态）
```

### 1.3 核心目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 次日打卡留存率 | ≥ 45% | 完成首日打卡后次日继续打卡 |
| 7日连续打卡率 | ≥ 25% | 首周不中断 |
| 30日连续打卡率 | ≥ 8% | 形成习惯 |
| 日均学习时长提升 | +15% | 对比无打卡机制时 |

## 2. 核心概念与数据模型

### 2.1 核心概念

- **打卡规则（CheckInRule）**：定义何种学习行为算作一次有效打卡（如：完成≥1道题、学习≥10分钟）
- **打卡记录（CheckInRecord）**：用户每日的打卡流水
- **连续天数（Streak）**：连续完成打卡的天数，中断则归零
- **学习目标（LearningGoal）**：用户设定的周期性学习目标（每日/每周/自定义）
- **里程碑（Milestone）**：连续打卡或目标达成的阶段性成就
- **补签卡（MakeupCard）**：允许用户补回漏打卡的资源（限时/限量）

## 4. 核心业务流程

### 4.1 打卡触发流程

```
用户完成学习行为
        │
        ▼
┌─────────────────┐
│ 事件总线接收事件   │  (QUESTION_COMPLETED / STUDY_SESSION_END / ERROR_REVIEW_DONE)
└────────┬────────┘
         │
         ▼
┌─────────────────────┐
│ 查询用户适用的打卡规则 │  按 phase + is_active + priority 过滤
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐      否
│ 今日是否已有该规则打卡？├──────────→ 结束
└────────┬────────────┘
         │ 是（未完成）
         ▼
┌─────────────────────┐
│ 累加今日行为指标       │  更新 Redis 实时计数
│ 检查条件是否满足       │
└────────┬────────────┘
         │ 条件满足
         ▼
┌─────────────────────┐
│ 写入 check_in_records │
│ 更新 user_streaks    │  current_streak++, longest_streak = MAX(...)
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐
│ 检查里程碑达成       │
│ → 达成则发事件通知    │  → 推送 + 勋章 + 积分
└─────────────────────┘
```

### 4.2 连续天数（Streak）更新逻辑

```python
def update_streak(user_id: int, rule_id: int, check_date: date):
    streak = db.get_user_streak(user_id, rule_id)
    
    if streak is None:
        # 首次打卡
        db.insert_user_streak(user_id, rule_id, 
                              current_streak=1, 
                              longest_streak=1, 
                              last_check_date=check_date)
        return
    
    yesterday = check_date - timedelta(days=1)
    
    if streak.last_check_date == check_date:
        # 今日已更新，跳过
        return
    
    if streak.last_check_date == yesterday:
        # 连续打卡
        streak.current_streak += 1
    elif streak.last_check_date < yesterday:
        # 中断过，检查是否有冻结保护
        gap_days = (check_date - streak.last_check_date).days - 1
        
        if gap_days == 1 and streak.freeze_count > 0:
            # 使用1次冻结保护，视为连续
            streak.freeze_count -= 1
            streak.freeze_used += 1
            streak.current_streak += 1
        else:
            # 重新计数
            streak.current_streak = 1
    
    streak.longest_streak = max(streak.longest_streak, streak.current_streak)
    streak.last_check_date = check_date
    db.update_user_streak(streak)
```

### 4.3 Streak 中断处理时序

```
        周一    周二    周三    周四    周五    周六    周日
打卡:    ✅     ✅     ❌     ❌     ✅     ✅     ✅
Streak:  1→2    2→3    断→0    0      1→2    2→3    3→4

使用补签卡补周三后：
打卡:    ✅     ✅     ✅(补)  ❌     ✅     ✅     ✅
Streak:  1→2    2→3    3→4    断→0   1→2    2→3    3→4

使用冻结保护（仅1天gap时自动生效）：
打卡:    ✅     ✅     ❌     ✅     ✅     ✅     ✅
Streak:  1→2    2→3    3(冻结) 3→4   4→5    5→6    6→7
```

### 4.4 里程碑检测流程

```python
MILESTONE_THRESHOLDS = {
    "STREAK_DAYS": [3, 7, 14, 30, 60, 100, 180, 365],
    "TOTAL_CHECK_INS": [10, 50, 100, 365, 500, 1000],
}

async def check_milestones(user_id: int, streak: UserStreak):
    achieved_ids = set(db.get_user_milestone_ids(user_id))
    
    # 检查连续天数里程碑
    for threshold in MILESTONE_THRESHOLDS["STREAK_DAYS"]:
        if streak.current_streak >= threshold:
            milestone = db.get_milestone_by_condition("STREAK_DAYS", threshold)
            if milestone and milestone.id not in achieved_ids:
                await grant_milestone(user_id, milestone)
    
    # 检查总打卡数里程碑
    total_checkins = db.count_user_checkins(user_id)
    for threshold in MILESTONE_THRESHOLDS["TOTAL_CHECK_INS"]:
        if total_checkins >= threshold:
            milestone = db.get_milestone_by_condition("TOTAL_CHECK_INS", threshold)
            if milestone and milestone.id not in achieved_ids:
                await grant_milestone(user_id, milestone)
```

## 5. 事件驱动集成

### 5.1 消费的事件

| 事件源 | 事件名 | 说明 |
|--------|--------|------|
| 学习记录服务 | `STUDY_SESSION_END` | 学习会话结束，携带时长 |
| 练习与测评服务 | `QUESTION_COMPLETED` | 完成一道题 |
| 错题整理服务 | `ERROR_REVIEW_DONE` | 完成错题复习 |
| 课程内容服务 | `CHAPTER_LEARNED` | 完成章节学习 |
| 作文辅导服务 | `ESSAY_SUBMITTED` | 提交作文 |

### 5.2 生产的事件

| 事件名 | 说明 | 消费者 |
|--------|------|--------|
| `CHECK_IN_COMPLETED` | 打卡完成 | 运营活动服务（积分）、通知服务 |
| `STREAK_UPDATED` | 连续天数变化 | 通知服务（推送给家长） |
| `STREAK_BROKEN` | 连续天数中断 | 通知服务（鼓励回归） |
| `MILESTONE_ACHIEVED` | 里程碑达成 | 运营活动服务（发放奖励）、通知服务 |
| `GOAL_COMPLETED` | 学习目标达成 | 通知服务、学情分析 |

```json
{
```

## 6. AI 智能目标推荐

### 6.1 推荐策略

系统根据用户历史学习数据，推荐合理的学习目标，避免目标过高导致挫败或过低缺乏挑战。

```python
class GoalRecommender:
    """AI 学习目标推荐引擎"""
    
    def recommend(self, user_id: int, goal_type: str) -> list[GoalRecommendation]:
        profile = self.get_user_profile(user_id)
        recent_stats = self.get_recent_stats(user_id, days=14)
        
        recommendations = []
        
        # 维度1：学习时长
        avg_daily_min = recent_stats.avg_study_duration_sec / 60
        duration_target = self._calc_target(avg_daily_min, goal_type)
        recommendations.append(GoalRecommendation(
            dimension="STUDY_DURATION",
            target_value=duration_target,
            reason=f"根据您近期日均学习 {avg_daily_min:.0f} 分钟，建议目标为 {duration_target} 分钟",
            confidence=0.85
        ))
        
        # 维度2：做题数
        avg_daily_questions = recent_stats.avg_questions_per_day
        question_target = self._calc_target(avg_daily_questions, goal_type)
        recommendations.append(GoalRecommendation(
            dimension="QUESTION_COUNT",
            target_value=question_target,
            reason=f"您近期日均做题 {avg_daily_questions:.0f} 道，建议目标为 {question_target} 道",
            confidence=0.80
        ))
        
        return recommendations
    
    def _calc_target(self, avg_value: float, goal_type: str) -> int:
        """基于平均值计算合理目标值（约1.1~1.3倍均值，有挑战但可达）"""
        multiplier = {
            "DAILY": 1.2,     # 日目标：1.2倍均值
            "WEEKLY": 1.15,   # 周目标：1.15倍均值（周总需求更稳定）
            "MONTHLY": 1.1,   # 月目标：1.1倍均值
        }.get(goal_type, 1.15)
        
        target = avg_value * multiplier
        # 圆整到合理值
        if target < 10:
            return max(1, round(target))
        return round(target / 5) * 5  # 取整到5的倍数
```

### 6.2 目标进度跟踪

目标进度由后台定时任务每小时聚合一次（非实时），避免频繁查询。

```sql
-- 每小时更新目标进度（存储过程伪代码）
UPDATE learning_goals g
SET current_value = (
    SELECT CASE g.dimension
        WHEN 'STUDY_DURATION' THEN 
            COALESCE(SUM(LEAST(sr.duration_sec, 7200)) / 60, 0)  -- 单次上限2小时防刷
        WHEN 'QUESTION_COUNT' THEN 
            COALESCE(COUNT(qr.id), 0)
        WHEN 'ERROR_REVIEW' THEN 
            COALESCE(COUNT(er.id), 0)
        ELSE 0
    END
    FROM ... -- 根据 dimension JOIN 不同的事实表
    WHERE user_id = g.user_id
      AND created_at BETWEEN g.start_date AND g.end_date
),
updated_at = NOW()
WHERE g.status = 1  -- 进行中
  AND g.end_date >= CURDATE();
```

## 8. 防刷与公平性

### 8.1 防刷机制

| 策略 | 说明 |
|------|------|
| 单次学习时长上限 | 单次学习最长计2小时，超出不计入打卡指标 |
| 最短有效学习时间 | 每道题最少停留15秒，否则不计入完成数 |
| 每日上限 | 单维度每日最多计入正常值的3倍，防止刷量 |
| IP/设备异常检测 | 短时间多账号同一设备打卡触发风控 |
| 补签限制 | 最多补签7天内的记录，每月最多补签3次 |

### 8.2 排行榜防作弊

- 排行榜只展示 Top 100，且只对本人展示精确天数
- 连续天数超过30天时需人工审核（管理后台标记异常后不进入排行榜）
- 排行榜数据缓存5分钟，非实时更新

### 9.1 Streak 中断检测（关键定时任务）

```python
async def daily_streak_check():
    """每日凌晨执行，检查并处理未打卡用户的 Streak"""
    yesterday = date.today() - timedelta(days=1)
    
    # 查询所有活跃 Streak 记录
    active_streaks = db.query(
        "SELECT * FROM user_streaks WHERE current_streak > 0"
    )
    
    for streak in active_streaks:
        # 检查昨日是否有打卡记录
        has_checkin = db.exists(
            "SELECT 1 FROM check_in_records "
            "WHERE user_id = %s AND rule_id = %s AND check_date = %s AND status IN (1, 2)",
            (streak.user_id, streak.rule_id, yesterday)
        )
        
        if not has_checkin:
            if streak.freeze_count > 0:
                # 自动使用冻结保护（仅1天gap）
                streak.freeze_count -= 1
                streak.freeze_used += 1
                # Streak 不变，但 last_check_date 更新为 yesterday
                streak.last_check_date = yesterday
                db.update(streak)
            else:
                # Streak 中断
                streak.current_streak = 0
                db.update(streak)
                
                # 发送中断事件
                await event_bus.publish("STREAK_BROKEN", {
                    "user_id": streak.user_id,
                    "previous_streak": streak.current_streak,  # 中断前的值
                    "longest_streak": streak.longest_streak
                })
```

```python
async def update_realtime_progress(user_id: int, event: LearningEvent):
    """学习事件触发后，实时更新 Redis 中的打卡进度"""
    today = date.today().isoformat()
    key = f"checkin:today:{user_id}"
    
    # 累加指标
    if event.type == "STUDY_SESSION_END":
        r.hincrby(key, "study_duration_sec", event.duration_sec)
    elif event.type == "QUESTION_COMPLETED":
        r.hincrby(key, "questions_completed", 1)
    elif event.type == "ERROR_REVIEW_DONE":
        r.hincrby(key, "error_reviews", 1)
    
    r.hset(key, "updated_at", datetime.now().isoformat())
    r.expireat(key, end_of_today_timestamp())
    
    # 检查是否满足打卡规则
    await check_and_trigger_checkin(user_id, key)
```

| `MAKEUP_002` | 400 | 补签日期超出7天范围 |
| `MAKEUP_003` | 409 | 该日期已有打卡记录 |
| `MAKEUP_004` | 429 | 本月补签次数已达上限 |
| `GOAL_001` | 400 | 目标类型无效 |
| `GOAL_002` | 400 | 目标日期范围无效（end < start） |
| `GOAL_003` | 409 | 同类型同周期目标已存在 |
| `GOAL_004` | 403 | 进行中目标数量已达上限（最多5个） |
| `MILESTONE_001` | 404 | 里程碑不存在 |
| `MILESTONE_002` | 409 | 里程碑未达成，不可领取 |
| `MILESTONE_003` | 409 | 奖励已领取 |

### 11.2 降级策略

| 场景 | 策略 |
|------|------|
| Redis 不可用 | 打卡进度写入 DB，由定时任务补偿检查；Streak 读 DB |
| 消息队列积压 | 打卡触发容忍秒级延迟，非关键路径，降级为DB轮询 |
