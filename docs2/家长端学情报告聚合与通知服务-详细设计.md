# 家长端学情报告聚合与通知服务 - 详细设计文档

## 1. 概述

### 1.1 模块定位

家长端学情报告聚合与通知服务（Parent Learning Report & Notification Service）负责将学生的学习行为、答题结果、错题数据、计划完成情况等原始数据，按照家长视角聚合为**周报、月报、自定义周期报告**，并通过 App 推送、短信、家长端消息等渠道触达家长。该服务向上为家长中心、消息中心、推送服务提供统一 API；向下依赖学情分析、错题整理、学习规划、学习记录、家长绑定等模块的数据。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 数据聚合 | 按家长绑定的孩子，汇总指定周期内的学习数据 |
| 报告生成 | 基于模板 + AI 生成自然语言解读与建议 |
| 报告存储 | 持久化报告快照，支持家长回溯历史报告 |
| 多渠道通知 | 按家长偏好，通过 App Push、短信、站内信、微信服务号（可选）推送 |
| 阅读状态 | 记录家长是否已读、分享、反馈 |
| 多孩子支持 | 同一家长可切换/接收多个孩子的报告 |

### 1.3 服务边界

```
┌─────────────────────────────────────────────────────────────┐
│        家长端学情报告聚合与通知服务 (Parent Report Service)    │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
│  │ 数据聚合  │  │ 报告生成  │  │ 通知推送  │  │ 阅读状态  │   │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘   │
└────────┬────────────┬────────────┬────────────┬──────────┘
         │              │            │            │
    学情分析服务      错题服务        学习规划服务    家长绑定服务
```

### 1.4 依赖关系

- **上游依赖**：家长绑定服务、用户账号体系、学情分析服务、学习记录服务、错题服务、学习规划服务、AI 服务（自然语言生成）、消息推送服务。
- **下游依赖**：消息中心、家长中心客户端、数据看板。

## 4. 关键代码示例

### 4.1 数据聚合器（Python）

```python
from datetime import date, timedelta
from typing import List, Dict
from dataclasses import dataclass

@dataclass
class PeriodMetrics:
    total_study_minutes: int = 0
    active_days: int = 0
    completed_tasks: int = 0
    total_tasks: int = 0
    questions_attempted: int = 0
    questions_correct: int = 0
    mistakes_added: int = 0
    mistakes_reviewed: int = 0
    subject_stats: Dict[str, Dict] = None

class ParentReportAggregator:
    def __init__(self, analytics_client, mistake_client, plan_client, session_client):
        self.analytics = analytics_client
        self.mistakes = mistake_client
        self.plans = plan_client
        self.sessions = session_client

    async def aggregate(self, student_user_id: str, start: date, end: date) -> PeriodMetrics:
        m = PeriodMetrics(subject_stats={})

        # 1. 学习时长与会话数
        sessions = await self.sessions.get_sessions(student_user_id, start, end)
        m.total_study_minutes = sum(s.duration_minutes for s in sessions)
        m.active_days = len(set(s.date for s in sessions))

        # 2. 任务完成情况
        tasks = await self.plans.get_tasks(student_user_id, start, end)
        m.total_tasks = len(tasks)
        m.completed_tasks = sum(1 for t in tasks if t.status == 'completed')

        # 3. 答题正确率
        answers = await self.analytics.get_answer_records(student_user_id, start, end)
        m.questions_attempted = len(answers)
        m.questions_correct = sum(1 for a in answers if a.is_correct)

        # 4. 错题数据
        mistakes = await self.mistakes.get_mistakes(student_user_id, start, end)
        m.mistakes_added = len(mistakes)
        m.mistakes_reviewed = sum(1 for mm in mistakes if mm.reviewed_in_period)

        # 5. 按学科聚合
        for ans in answers:
            sub = ans.subject_code
            stat = m.subject_stats.setdefault(sub, {
                'subject_name': SUBJECT_NAME_MAP.get(sub, sub),
                'questions_attempted': 0,
                'questions_correct': 0,
                'study_minutes': 0,
                'weak_knowledge_points': []
            })
            stat['questions_attempted'] += 1
            if ans.is_correct:
                stat['questions_correct'] += 1
            stat['study_minutes'] += ans.duration_minutes or 0

        # 6. 计算学科正确率并提取薄弱点
        for sub, stat in m.subject_stats.items():
            stat['accuracy'] = (
                stat['questions_correct'] / stat['questions_attempted']
                if stat['questions_attempted'] else 0
            )
            stat['weak_knowledge_points'] = await self.analytics.get_weak_kps(
                student_user_id, sub, start, end, threshold=0.6
            )

        return m
```

### 4.2 AI 报告生成服务

```python
import json
from typing import Dict

class ParentReportAIService:
    def __init__(self, llm_client, prompt_template_service):
        self.llm = llm_client
        self.prompts = prompt_template_service

    async def generate_analysis(self, metrics: PeriodMetrics, student_profile: Dict) -> Dict:
        prompt = self.prompts.render('parent_weekly_report', {
            'student_name': student_profile['nickname'],
            'grade': student_profile['grade_label'],
            'period_start': metrics.start.isoformat(),
            'period_end': metrics.end.isoformat(),
            'metrics_json': json.dumps(metrics.to_dict(), ensure_ascii=False),
        })

        response = await self.llm.chat(
            model='gpt-4o-mini',  # 轻量模型即可
            messages=[{"role": "user", "content": prompt}],
            temperature=0.6,
            max_tokens=1200,
            response_format='json'
        )

        return json.loads(response)
```

### 4.3 通知发送器

```python
from enum import Enum

class Channel(str, Enum):
    APP_PUSH = 'app_push'
    SMS = 'sms'
    IN_APP = 'in_app'
    WECHAT = 'wechat'

class ParentNotificationSender:
    def __init__(self, push_service, sms_service, in_app_service):
        self.push = push_service
        self.sms = sms_service
        self.in_app = in_app_service

    async def send(self, report, preference, log_id: str) -> bool:
        channels = preference.channels or [Channel.APP_PUSH]
        title = report.title
        body = report.summary

        for channel in channels:
            try:
                if channel == Channel.APP_PUSH:
                    await self.push.send_to_user(
                        user_id=report.user_id,
                        title=title,
                        body=body,
                        payload={'report_id': report.id, 'type': 'parent_report'}
                    )
                elif channel == Channel.SMS:
                    await self.sms.send(
                        phone=report.parent_phone,
                        template='parent_weekly_report',
                        params={'student_name': report.student_name, 'summary': body}
                    )
                elif channel == Channel.IN_APP:
                    await self.in_app.send_message(
                        user_id=report.user_id,
                        title=title,
                        content=body,
                        biz_type='parent_report',
                        biz_id=report.id
                    )
                # 记录成功
                await self.update_log(log_id, channel, 'sent')
                return True
            except Exception as e:
                await self.update_log(log_id, channel, 'failed', str(e))
                # 继续尝试下一个渠道
                continue

        return False
```

## 5. 状态流转

### 5.1 报告生成状态机

```
                    ┌──────────┐
              创建  │  pending  │  ← 生成请求入队
                    └────┬─────┘
                         │ 定时任务消费
                         ▼
                    ┌──────────┐
                    │aggregating│  ← 聚合各模块数据
                    └────┬─────┘
                         │ 数据聚合完成
                         ▼
                    ┌──────────┐
                    │generating │  ← 调用 AI 生成解读
                    └────┬─────┘
                         │
            ┌────────────┼────────────┐
            │            │            │
            ▼            ▼            ▼
      ┌─────────┐  ┌─────────┐  ┌─────────┐
      │completed│  │ failed  │  │ expired │
      └────┬────┘  └────┬────┘  └─────────┘
           │            │ 重试（最多3次）
           │            ▼
           │       ┌─────────┐
           │       │ pending │
           │       └─────────┘
           │ 通知发送
           ▼
      ┌─────────┐
      │  sent   │  ← 已推送给家长
      └────┬────┘
           │ 家长打开
           ▼
      ┌─────────┐
      │  read   │  ← 已读
      └─────────┘
```

### 5.2 状态说明

| 状态 | 说明 | 可转移 |
|------|------|--------|
| pending | 等待执行 | aggregating |
| aggregating | 正在聚合数据 | generating, failed |
| generating | 正在生成 AI 解读 | completed, failed |
| completed | 报告已生成 | sent, expired |
| sent | 已发送通知 | read, failed |
| read | 家长已阅读 | expired |
| failed | 生成或发送失败 | pending（重试）, expired |
| expired | 超过保留期（如 90 天） | - |

## 6. 错误处理

### 6.1 业务错误码

| 错误码 | 名称 | 说明 | HTTP 状态 |
|--------|------|------|-----------|
| 70001 | PARENT_BINDING_NOT_FOUND | 家长未绑定该学生 | 403 |
| 70002 | REPORT_NOT_FOUND | 报告不存在 | 404 |
| 70003 | REPORT_ALREADY_EXISTS | 同周期报告已存在 | 409 |
| 70004 | AGGREGATION_FAILED | 数据聚合失败 | 500 |
| 70005 | AI_GENERATION_FAILED | AI 生成失败 | 500 |
| 70006 | NOTIFICATION_FAILED | 通知发送失败 | 502 |
| 70007 | PREFERENCE_NOT_FOUND | 家长偏好未设置 | 404 |
| 70008 | INVALID_PERIOD | 周期参数不合法 | 400 |
| 70009 | NO_DATA_IN_PERIOD | 周期内无学习数据 | 200（返回空报告） |
| 70010 | RATE_LIMITED | 生成请求过于频繁 | 429 |

### 6.2 降级策略

| 场景 | 策略 | 说明 |
|------|------|------|
| AI 生成失败 | 使用模板化报告 | 基于指标 JSON 直接拼接文本，保证报告可产出 |
| 聚合部分数据源失败 | 标记缺失字段，跳过该部分 | 如错题服务不可用，则报告中不显示错题数据 |
| 通知发送失败 | 切换渠道重试 | 优先 App Push，失败改站内信，最后短信 |
| 周期内无数据 | 生成"本周暂无学习记录"占位报告 | 避免空白，提醒家长关注 |

## 7. 性能与优化

### 7.1 缓存策略

| 缓存 Key | 类型 | TTL | 说明 |
|----------|------|-----|------|
| `parent:report:{report_id}` | Hash | 7 天 | 报告详情缓存 |
| `parent:reports:list:{user_id}:{student_id}:{type}` | List | 1 小时 | 报告列表缓存 |
| `parent:metrics:{student_id}:{period}` | String | 6 小时 | 周期指标聚合缓存 |
| `parent:pref:{user_id}:{student_id}` | Hash | 24 小时 | 家长偏好缓存 |

### 7.2 异步处理

- 报告生成通过消息队列异步执行，避免前端长时间等待。
- 定时任务：周报每周日 08:00 触发，月报每月 1 日 08:00 触发。
- 批量生成：使用线程池/协程批量处理同一时段的多个学生。

### 7.3 限流与配额

- 单家长手动生成报告：每 5 分钟最多 1 次。
- 单个学生同周期报告：幂等，重复请求返回已有报告 ID。
- AI 生成调用按家长会员等级配额控制。

## 8. 安全与合规

### 8.1 权限控制

- 所有接口必须校验家长与学生的 `parent_bindings` 关系有效。
- 报告数据按 `user_id` + `student_user_id` 双重隔离。
- 教师/管理员不可直接查看家长报告，除非家长授权。

### 8.2 数据隐私

- 不展示学生与 AI 的具体对话内容。
- 不展示学生位置、设备敏感信息。
- 报告分享时自动生成脱敏摘要图。
- 家长解绑后，历史报告保留 90 天，之后归档或删除。

### 8.3 未成年人保护

- 14 周岁以下学生报告默认推送给家长，学生端不可关闭。
- 报告内容避免排名、竞争性表述，减少焦虑。

## 9. 测试策略

### 9.1 单元测试

- 指标聚合公式正确性（正确率、环比变化）。
- 状态机合法/非法转移。
- 通知渠道优先级与降级。

### 9.2 集成测试

- 与学情分析、错题、学习规划的跨服务集成。
- AI 生成超时与模板降级。
- 定时任务调度与幂等生成。

### 9.3 验收标准

| 场景 | 标准 |
|------|------|
| 周报生成 | 每周日 08:00 前完成上周所有绑定家长的报告生成与通知 |
| 月报生成 | 每月 1 日 08:00 前完成上月所有报告生成与通知 |
| 手动生成 | 家长点击后 5 秒内返回报告 ID，1 分钟内完成生成 |
| 无数据周期 | 仍生成占位报告，标题为"暂无学习记录" |
| 多孩子家长 | 可分别查看每个孩子的报告，互不混淆 |
