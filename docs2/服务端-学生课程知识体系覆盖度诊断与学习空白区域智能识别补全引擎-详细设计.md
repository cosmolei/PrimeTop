## 1. 模块概述

### 1.1 一句话定义

将学生**个人知识图谱**与所在年级/学科/教材版本的**课程标准知识图谱**进行全景比对，识别学习空白区、知识链断裂、纸面知识（只学未练）和覆盖度不足的分支，生成结构化的知识覆盖度诊断报告和优先级补全路径。

### 1.2 设计动机

| 现有系统 | 局限性 | 本引擎解决的问题 |
|---------|--------|----------------|
| 个人知识图谱构建引擎 | 构建"学生知道什么"的网络 | 不回答"学生**应该知道什么但还不知道**" |
| 知识追踪模型引擎 (KTE) | 输出每个已接触知识点的掌握度 | 不关注**从未接触**的知识点 |
| 薄弱点识别服务 | 聚焦低正确率、高错题率知识点 | 无法发现从未学习过的**盲区** |
| 跨年级知识漏洞根因追溯 | 向前追溯历史年级的前置缺失 | 不做**当前年级**的横向覆盖度扫描 |
| 学习路径推荐引擎 | 基于已有学习数据推荐下一个内容 | 缺少**全局覆盖度视角**，容易形成信息茧房 |

**核心洞察**：学生的"薄弱"有两种——一种是学过但没掌握（已有系统处理），另一种是**完全没学过**（现有系统盲区）。一个初三学生可能从未接触过"圆与圆的位置关系"这个知识点，但因为没有答题记录，所有现有系统都对其"无感知"。本引擎通过**标准图谱 vs 个人图谱**的全景比对，系统性发现这类盲区。

### 1.3 典型应用场景

| 场景 | 用户 | 价值 |
|------|------|------|
| 学期中定期体检 | 学生 | 每月自动扫描知识覆盖盲区，生成补漏清单 |
| 考前全覆盖检查 | 学生/教师 | 考前2周扫描未覆盖考点，生成冲刺补漏计划 |
| 家长查看学习全面性 | 家长 | 直观展示孩子哪些章节学过、哪些完全空白 |
| 教师查看班级覆盖盲区 | 教师 | 识别全班普遍未学习的知识点，调整教学进度 |
| 学习计划优化 | 系统 | 基于覆盖度数据，优先推荐空白区域内容 |

### 1.4 与现有模块的边界

| 职责 | 归属 | 说明 |
|------|------|------|

## 2. 核心概念与数据模型

### 2.1 核心概念定义

| 概念 | 定义 | 示例 |
|------|------|------|
| **标准知识图谱 (Standard KG)** | 某年级/学科/教材版本下全部应有知识点的规范集合，含层级结构和前置依赖关系 | 人教版九年级数学上册的全部87个知识点 |
| **个人知识足迹 (Personal Footprint)** | 学生在该标准图谱范围内有过明确学习行为（学习/练习/对话涉及）的知识点集合 | 学生接触过其中52个知识点 |
| **覆盖状态 (Coverage Status)** | 每个标准知识点相对于该学生的状态分类 | covered / thin / paper-only / blank / prerequisite-missing |
| **覆盖度 (Coverage Rate)** | 各维度覆盖比例的综合评分 | 章节覆盖度 68%，知识点覆盖度 59%，考点覆盖度 72% |
| **学习空白区 (Blank Zone)** | 标准图谱中存在但学生从未接触的知识点 | "圆与圆的位置关系"从未学习/练习 |
| **学习冷淡区 (Cold Zone)** | 有学习行为但交互次数 < 阈值的知识点 | 仅看过1次讲解视频，从未练习 |
| **纸面知识区 (Paper-Only Zone)** | 有理论学习记录但无任何练习/答题记录的知识点 | 学了"勾股定理"概念但从未做过相关题 |
| **知识链断裂 (Chain Break)** | 前置知识点未覆盖导致后续知识点无法有效学习的断裂点 | "一元二次方程"未学，导致"二次函数"虽然标记为接触但实际无法掌握 |
| **覆盖度风险等级 (Risk Level)** | 基于覆盖度和考试重要性综合评估的风险分级 | critical / high / medium / low |

### 2.2 覆盖状态分类体系

```
标准知识点集合
├── 已覆盖 (Covered) — 有学习行为且掌握度 ≥ 0.5
│   ├── 扎实 (Solid):          掌握度 ≥ 0.75 且有练习记录
│   └── 基本掌握 (Adequate):   0.5 ≤ 掌握度 < 0.75
├── 覆盖薄弱 (Thin) — 有学习行为但掌握度 < 0.5
│   ├── 练习不足 (Under-practiced): 学习≥3次但练习<2次
│   └── 需强化 (Needs-reinforcement): 学习且练习但掌握度低
├── 纸面知识 (Paper-Only) — 有理论学习但零练习记录
├── 学习冷淡 (Cold) — 学习行为 < 3次且无练习
├── 空白 (Blank) — 完全无学习行为
└── 前置缺失 (Prerequisite-Missing) — 前置知识点未覆盖
```

### 2.3 覆盖度多维评分模型

```
CourseCoverageScore = w1 × KP_Coverage      // 知识点覆盖率 (0.35)
                   + w2 × Chapter_Coverage   // 章节覆盖率 (0.20)
                   + w3 × ExamPoint_Coverage // 考点覆盖率 (0.30)
                   + w4 × Practice_Coverage  // 练习覆盖率 (0.15)

其中:
  KP_Coverage      = solid_kps + 0.6 × adequate_kps + 0.3 × thin_kps  / total_kps
  Chapter_Coverage = Σ(章节内已覆盖KP / 章节总KP) / total_chapters
  ExamPoint_Coverage = covered_exam_points / total_exam_points
  Practice_Coverage = kps_with_practice / kps_with_learning
```

## 3. 核心算法设计

### 3.1 全景覆盖度诊断算法

```
输入: userId, subjectCode, gradeCode, textbookVersion, semesterCode
输出: CoverageDiagnosisReport

1. 获取标准知识图谱
   standardKps = KnowledgeMapService.getStandardKps(
       subjectCode, gradeCode, textbookVersion, semesterCode
   )
   // 返回该教材版本下学期全部知识点，含章节归属、前置依赖、是否考点

2. 获取个人学习足迹
   personalFootprint = LearningBehaviorService.aggregateKpFootprint(
       userId, subjectCode, semesterCode
   )
   // 返回每个KP的学习次数、练习次数、最近学习时间

3. 获取掌握度数据
   masteryMap = KnowledgeTrackingEngine.batchGetMastery(
       userId, standardKps.ids
   )

4. 分类计算覆盖状态
   for each kp in standardKps:
       footprint = personalFootprint.get(kp.id)
       mastery = masteryMap.get(kp.id)

       if footprint == null OR (footprint.learningCount == 0 AND footprint.practiceCount == 0):
           // 完全空白
           kpStatus = CoverageStatus.BLANK

       elif footprint.learningCount > 0 AND footprint.practiceCount == 0:
           // 有学习无练习 — 纸面知识
           kpStatus = CoverageStatus.PAPER_ONLY

       elif footprint.learningCount < 3 AND footprint.practiceCount < 2:
           // 学习冷淡
           kpStatus = CoverageStatus.COLD

       elif mastery != null AND mastery >= 0.75 AND footprint.practiceCount >= 2:
           // 扎实
           kpStatus = CoverageStatus.SOLID

       elif mastery != null AND mastery >= 0.5:
           // 基本掌握
           kpStatus = CoverageStatus.ADEQUATE

       else:
           // 覆盖薄弱
           kpStatus = CoverageStatus.THIN

5. 前置依赖检测 — 标记前置缺失
   for each kp where kpStatus == BLANK:
       prereqs = standardKps.getPrerequisites(kp.id)
       for prereq in prereqs:
           if prereq.status in [BLANK, PREREQUISITE_MISSING, THIN]:
               kpStatus = CoverageStatus.PREREQUISITE_MISSING
               recordMissingPrereq(kp.id, prereq.id)
               break

6. 知识链断裂检测
   chainBreaks = detectChainBreaks(standardKps, kpStatusMap)

7. 计算覆盖度评分
   coverageScore = calculateCoverageScore(kpStatusMap, standardKps)

8. 风险分级
   riskLevel = classifyRiskLevel(coverageScore, examPointCoverage, chainBreaks)

9. 计算补全优先级
   for each kp where status in [BLANK, PAPER_ONLY, COLD, THIN, PREREQUISITE_MISSING]:
       priorityScore = calculatePriorityScore(kp, status, isExamPoint, chainDepth)

10. 生成补全建议
    recommendedActions = generateSupplementActions(
        kpStatusMap, chainBreaks, priorityScores, standardKps
    )

11. 持久化报告并返回
    saveReport(report)
    return report
```

### 3.2 知识链断裂检测算法

```java
/**
 * 知识链断裂检测 — BFS遍历标准知识图谱的前置依赖边,
 * 找出因前置未覆盖导致的连锁阻断路径
 */
public List<ChainBreak> detectChainBreaks(
        StandardKnowledgeGraph standardKg,
        Map<Long, CoverageStatus> statusMap) {

    List<ChainBreak> breaks = new ArrayList<>();
    Map<Long, Integer> affectedCount = new HashMap<>(); // kp → 受影响的后继数量

    // 1. 找出所有前置未覆盖的知识点
    Set<Long> blockedKps = new HashSet<>();
    for (KpNode kp : standardKg.getAllNodes()) {
        if (statusMap.get(kp.getId()) == CoverageStatus.PREREQUISITE_MISSING) {
            blockedKps.add(kp.getId());
        }
    }

    // 2. 对每个被阻断知识点，BFS向下计算影响深度
    for (Long blockedKpId : blockedKps) {
        Set<Long> downstream = new HashSet<>();
        Queue<Long> queue = new LinkedList<>(standardKg.getDependents(blockedKpId));

        while (!queue.isEmpty()) {
            Long current = queue.poll();
            if (!downstream.contains(current)) {
                downstream.add(current);
                queue.addAll(standardKg.getDependents(current));
            }
        }

        affectedCount.put(blockedKpId, downstream.size());
    }

    // 3. 构建ChainBreak记录
    for (Long blockedKpId : blockedKps) {
        KpNode blockedKp = standardKg.getNode(blockedKpId);
        List<Long> missingPrereqs = findMissingPrereqs(blockedKpId, standardKg, statusMap);
        int depth = calculateMaxChainDepth(blockedKpId, standardKg, statusMap);
        int affected = affectedCount.get(blockedKpId);

        ChainBreakSeverity severity;
        if (depth >= 3 || affected >= 5) {
            severity = ChainBreakSeverity.CRITICAL;
        } else if (depth >= 2 || affected >= 2) {
            severity = ChainBreakSeverity.MAJOR;
        } else {
            severity = ChainBreakSeverity.MINOR;
        }

        // 为每个缺失的前置创建一条断裂记录
        for (Long missingId : missingPrereqs) {
            breaks.add(ChainBreak.builder()
                .currentKpId(missingId)
                .currentKpName(standardKg.getNode(missingId).getName())
                .blockedKpId(blockedKpId)
                .blockedKpName(blockedKp.getName())
                .missingPrereqIds(missingPrereqs)
                .missingPrereqNames(missingPrereqs.stream()
                    .map(id -> standardKg.getNode(id).getName())
                    .collect(Collectors.toList()))
                .chainDepth(depth)
                .affectedKpCount(affected)
                .severity(severity)
                .build());
        }
    }

    return breaks;
}
```

### 3.3 补全优先级评分算法

```java
/**
 * 补全优先级评分 — 决定先补哪些知识点
 * 
 * 评分维度:
 * 1. 考点重要性 (30%): 高频考点 > 普通 > 拓展
 * 2. 知识链影响 (25%): 阻断后续知识点越多越优先
 * 3. 前置就绪度 (20%): 前置已全部覆盖的更容易补
 * 4. 时间效率  (15%): 预估学习时间越短越优先（速效）
 * 5. 章节连续性 (10%): 与已覆盖知识点在同一章节的优先
 */
public BigDecimal calculatePriorityScore(
        KpNode kp,
        CoverageStatus status,
        boolean isExamPoint,
        int chainAffectedCount,
        StandardKnowledgeGraph standardKg,
        Map<Long, CoverageStatus> statusMap) {

    // 1. 考点重要性
    double examWeight;
    if (isExamPoint) {
        ExamPointFrequency freq = standardKg.getExamFrequency(kp.getId());
        examWeight = switch (freq) {
            case VERY_HIGH -> 30.0;
            case HIGH -> 25.0;
            case MEDIUM -> 20.0;
            case LOW -> 15.0;
        };
    } else {
        examWeight = 8.0;
    }

    // 2. 知识链影响
    double chainWeight = Math.min(25.0, chainAffectedCount * 5.0);

    // 3. 前置就绪度
    List<Long> prereqs = standardKg.getPrerequisites(kp.getId());
    long coveredPrereqs = prereqs.stream()
        .filter(id -> {
            CoverageStatus s = statusMap.getOrDefault(id, CoverageStatus.BLANK);
            return s == CoverageStatus.SOLID || s == CoverageStatus.ADEQUATE;
        })
        .count();
    double prereqWeight = prereqs.isEmpty()
        ? 20.0  // 无前置依赖，直接可学
        : 20.0 * ((double) coveredPrereqs / prereqs.size());

    // 4. 时间效率 — 估算学习时间，越短分越高
    int estimatedMinutes = estimateLearningMinutes(kp);
    double efficiencyWeight = switch (estimateDifficultyLevel(kp)) {
        case EASY -> 15.0;        // < 15分钟
        case MEDIUM -> 10.0;      // 15-30分钟
        case HARD -> 5.0;         // > 30分钟
    };

    // 5. 章节连续性 — 同章节已有覆盖知识点越多越优先
    String chapterPath = kp.getChapterPath();
    long sameChapterCovered = statusMap.entrySet().stream()
        .filter(e -> {
            KpNode node = standardKg.getNode(e.getKey());
            return node != null
                && node.getChapterPath().equals(chapterPath)
                && (e.getValue() == CoverageStatus.SOLID
                    || e.getValue() == CoverageStatus.ADEQUATE);
        })
        .count();
    double continuityWeight = Math.min(10.0, sameChapterCovered * 2.5);

    // 6. 状态加权修正
    double statusModifier = switch (status) {
        case PREREQUISITE_MISSING -> 1.2;  // 前置缺失最紧急
        case BLANK -> 1.1;                 // 完全空白次之
        case PAPER_ONLY -> 1.05;           // 有理论无练习
        case COLD -> 1.0;                  // 常规
        case THIN -> 0.9;                  // 已有基础
        default -> 1.0;
    };

    double totalScore = (examWeight + chainWeight + prereqWeight
                       + efficiencyWeight + continuityWeight) * statusModifier;

    return BigDecimal.valueOf(Math.min(100.0, totalScore))
        .setScale(2, RoundingMode.HALF_UP);
}
```

### 3.4 补全路径规划算法

```java
/**
 * 补全路径规划 — 基于拓扑排序 + 优先级评分生成有序补全序列
 *
 * 策略:
 * 1. 先修复知识链断裂的前置知识点（critical > major > minor）
 * 2. 再按优先级评分排序补充空白和纸面知识
 * 3. 同优先级内，按章节顺序排列（保持学习连贯性）
 * 4. 控制单次计划规模（建议不超过20个知识点/2周）
 */
public List<SupplementAction> generateSupplementActions(
        Map<Long, CoverageStatus> statusMap,
        List<ChainBreak> chainBreaks,
        Map<Long, BigDecimal> priorityScores,
        StandardKnowledgeGraph standardKg) {

    List<SupplementAction> actions = new ArrayList<>();

    // Phase 1: 修复知识链断裂
    List<ChainBreak> criticalBreaks = chainBreaks.stream()
        .filter(cb -> cb.getSeverity() == ChainBreakSeverity.CRITICAL)
        .sorted(Comparator.comparing(ChainBreak::getAffectedKpCount).reversed())
        .collect(Collectors.toList());

    Set<Long> processedKps = new HashSet<>();
    for (ChainBreak cb : criticalBreaks) {
        for (Long missingId : cb.getMissingPrereqIds()) {
            if (processedKps.add(missingId)) {
                actions.add(SupplementAction.builder()
                    .knowledgePointId(missingId)
                    .actionType(SupplementActionType.CHAIN_REPAIR)
                    .reason("修复知识链断裂: " + cb.getBlockedKpName()
                          + " 的前置知识未覆盖")
                    .estimatedMinutes(estimateLearningMinutes(standardKg.getNode(missingId)))
                    .build());
            }
        }
    }

    // Phase 2: 按优先级补充空白和纸面知识
    List<Map.Entry<Long, BigDecimal>> sortedByPriority = priorityScores.entrySet().stream()
        .filter(e -> !processedKps.contains(e.getKey()))
        .filter(e -> {
            CoverageStatus s = statusMap.get(e.getKey());
            return s == CoverageStatus.BLANK
                || s == CoverageStatus.PAPER_ONLY
                || s == CoverageStatus.COLD;
        })
        .sorted(Map.Entry.<Long, BigDecimal>comparingByValue().reversed())
        .collect(Collectors.toList());

    int remainingCapacity = 20 - processedKps.size(); // 控制计划规模

    for (Map.Entry<Long, BigDecimal> entry : sortedByPriority) {
        if (remainingCapacity <= 0) break;

        Long kpId = entry.getKey();
        KpNode kp = standardKg.getNode(kpId);
        CoverageStatus status = statusMap.get(kpId);

        String reason = switch (status) {
            case BLANK -> "完全空白知识点，建议尽快学习";
            case PAPER_ONLY -> "已学理论但未练习，建议补充练习巩固";
            case COLD -> "学习次数不足，建议加深学习";
            default -> "覆盖度不足";
        };

        actions.add(SupplementAction.builder()
            .knowledgePointId(kpId)
            .actionType(switch (status) {
                case BLANK -> SupplementActionType.NEW_LEARN;
                case PAPER_ONLY -> SupplementActionType.ADD_PRACTICE;
                case COLD -> SupplementActionType.DEEPEN_LEARN;
                default -> SupplementActionType.REVIEW;
            })
            .reason(reason)
            .priorityScore(entry.getValue())
            .estimatedMinutes(estimateLearningMinutes(kp))
            .build());

        remainingCapacity--;
    }

    // Phase 3: 按章节路径排序，使学习更连贯
    actions.sort(Comparator
        .comparing((SupplementAction a) ->
            standardKg.getNode(a.getKnowledgePointId()).getChapterPath())
        .thenComparing(SupplementAction::getPriorityScore,
            Comparator.reverseOrder()));

    return actions;
}
```

## 5. 触发机制与调度策略

### 5.1 自动触发时机

| 触发场景 | 触发条件 | 调度策略 |
|---------|---------|---------|
| 定期体检 | 每月1号凌晨 | 批量调度，按学校/年级分批，凌晨2-5点执行 |
| 考前扫描 | 距考试 ≤ 14天 | 事件驱动，由学习日历考试事件触发 |
| 学期中扫描 | 新章节上线时 | 事件驱动，由内容服务章节解锁事件触发 |
| 异常恢复 | 学生长时间断更后回归 | 事件驱动，由用户登录事件+断更天数≥7触发 |
| 按需触发 | 用户/管理员手动请求 | 同步执行，超时5秒则转异步 |

### 5.2 增量更新策略

全量诊断较重（需遍历整张标准知识图谱），采用增量+全量结合策略：

```
全量诊断: 首次诊断 / 考前扫描 / 每月定期
增量更新: 每次学习行为上报时，更新相关KP的覆盖状态

增量逻辑:
  - 学习行为上报 → KP状态可能变化(blank→cold→adequate等)
  - 仅重计算受影响KP的优先级
  - 不重新执行知识链断裂检测（仅在下次全量时执行）
  - 增量更新覆盖率统计缓存
```

## 6. 缓存策略

### 6.1 多级缓存设计

```
L1 — 本地缓存 (Caffeine)
├── 标准知识图谱缓存: key = standard_kg:{subject}:{grade}:{version}:{semester}
│   TTL: 24h (教材内容不频繁变更)
│   最大: 50个学科×年级组合
├── 最新报告摘要缓存: key = report_summary:{userId}:{subject}:{semester}
│   TTL: 1h (允许1小时延迟)
│   最大: 10000

L2 — 分布式缓存 (Redis)
├── 覆盖度实时增量缓存: key = cov_incremental:{userId}:{subject}
│   TTL: 7天
│   存储: 最近7天的KP状态增量变化
├── 章节覆盖率聚合缓存: key = chapter_cov:{userId}:{subject}:{semester}
│   TTL: 6h
├── 补全计划缓存: key = supplement_plan:{userId}:{subject}
│   TTL: 2h (短TTL，允许频繁调整)
└── 标准知识图谱共享缓存: key = standard_kg:{subject}:{grade}:{version}:{semester}
    TTL: 24h
```

### 6.2 缓存失效策略

| 操作 | 失效范围 |
|------|---------|
| 新诊断报告生成 | `report_summary:{userId}:*`、`chapter_cov:{userId}:*` |
| 学习行为上报 | `cov_incremental:{userId}:*`（增量更新） |
| 教材内容变更 | `standard_kg:*`（全局失效，通过消息广播） |
| 补全计划激活 | `supplement_plan:{userId}:*` |

## 8. 错误处理与降级策略

### 8.1 错误码定义

| 错误码 | HTTP | 含义 | 处理建议 |
|--------|------|------|---------|
| `COV_001` | 400 | 请求参数无效（年级/学科/教材版本组合不存在） | 前端校验，提示用户检查设置 |
| `COV_002` | 404 | 标准知识图谱未配置 | 提示"该学科教材版本的内容正在建设中" |
| `COV_003` | 404 | 学生学习数据不足（新用户） | 返回空报告，提示"开始学习后可查看覆盖度" |
| `COV_004` | 409 | 诊断任务正在进行中 | 返回已有报告ID，提示"请稍后查看" |
| `COV_005` | 500 | 诊断计算超时 | 降级为简化模式（见下文） |
| `COV_006` | 503 | 依赖服务（KTE/行为服务）不可用 | 降级为基于行为数据的简单覆盖统计 |

### 8.2 降级策略

```
正常模式:
  全量诊断 → 覆盖状态分类 → 知识链断裂检测 → 优先级评分 → 补全路径规划

降级 Level 1 (超时 > 15s):
  跳过知识链断裂检测（最耗时步骤）
  → 仅返回覆盖状态分类和简化优先级

降级 Level 2 (KTE不可用):
  跳过掌握度依赖
  → 仅使用行为数据判定覆盖状态:
     有学习+有练习 → covered (粗略)
     有学习无练习 → paper_only
     无学习       → blank

降级 Level 3 (行为服务也不可用):
  返回缓存的上一次诊断报告
  → 标注"数据可能不是最新"
```

### 8.3 异常恢复

```java
@Retryable(maxAttempts = 3, backoff = @Backoff(delay = 2000, multiplier = 2))
public CoverageDiagnosisReport executeDiagnosis(DiagnosisRequest request) {
    try {
        // 正常诊断流程
        return fullDiagnosis(request);
    } catch (DiagnosisTimeoutException e) {
        log.warn("Diagnosis timeout for user {}, falling back to simplified mode",
                 request.getUserId());
        return simplifiedDiagnosis(request); // 降级 Level 1
    } catch (DependencyServiceException e) {
        log.error("Dependency service unavailable for user {} diagnosis",
                  request.getUserId(), e);
        return cachedOrEmptyReport(request);  // 降级 Level 2/3
    }
}
```

## 10. 性能优化

### 10.1 批量诊断优化

```java
/**
 * 批量诊断 — 按学校/班级分批执行，避免单次全量扫描压力
 */
public BatchDiagnosisResult batchDiagnose(List<Long> userIds, String subjectCode) {
    // 1. 预加载共享数据（标准知识图谱只需加载一次）
    StandardKnowledgeGraph standardKg = loadStandardKg(subjectCode);

    // 2. 批量查询学习足迹（避免N+1查询）
    Map<Long, Map<Long, KpFootprint>> allFootprints =
        learningBehaviorService.batchAggregateKpFootprint(userIds, subjectCode);

    // 3. 批量查询掌握度
    Map<Long, Map<Long, BigDecimal>> allMasteries =
        knowledgeTrackingEngine.batchGetMasteryForUsers(userIds, standardKpIds);

    // 4. 并行计算每个学生的诊断
    return userIds.parallelStream()
        .map(userId -> {
            try {
                return diagnoseSingle(userId, standardKg,
                    allFootprints.get(userId), allMasteries.get(userId));
            } catch (Exception e) {
                log.warn("Diagnosis failed for user {}", userId, e);
                return DiagnosisResult.failed(userId, e.getMessage());
            }
        })
        .collect(Collectors.toList());
}
```
