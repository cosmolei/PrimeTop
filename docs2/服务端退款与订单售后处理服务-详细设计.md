# 服务端退款与订单售后处理服务 - 详细设计文档

## 1. 模块概述

退款与订单售后处理服务是 PrimeTop 支付体系的关键后置环节，负责处理用户退款申请、管理退款策略、回收已分配权益、处理各支付渠道的退款差异，以及维护完整的售后工单与对账记录。

本模块与 [支付与会员订阅系统](支付与会员订阅-详细设计.md) 紧密关联，退款操作会触发会员权益回收、用量回滚、订阅取消等级联动作。

### 1.1 功能范围

| 功能 | 优先级 | V1.0 |
|------|--------|------|
| 用户端退款申请 | P1 | ✅ |
| 退款策略引擎（天数/用量/渠道规则） | P1 | ✅ |
| 各渠道退款执行（微信/支付宝/Apple IAP） | P1 | ✅ |
| 会员权益回收与降级 | P1 | ✅ |
| 增值服务（次数包）退款 | P1 | ✅ |
| 退款工单管理（运营后台） | P1 | ✅ |
| 部分退款计算（已使用天数/次数扣减） | P1 | ✅ |
| 退款对账与财务报表 | P1 | ✅ |
| 用户申诉与争议处理 | P2 | ❌ |
| 发票红冲联动 | P2 | ❌ |
| 批量退款（运营活动结束后） | P2 | ❌ |

### 1.2 设计原则

1. **未成年人保护优先**：家长绑定的学生账号退款申请需经家长确认或自动通过（根据金额）
2. **最小化权益滥用**：退款后立即回收权益，防止"退款后继续使用"
3. **财务一致性**：退款金额计算透明，与第三方支付渠道退款结果严格对账
4. **审计可追溯**：每笔退款全程留痕，包含申请原因、审批记录、执行结果

## 2. 退款策略与规则引擎

### 2.1 退款策略总览

退款策略由以下维度组合决定：

```
退款资格 = f(订单类型, 支付渠道, 已用时长, 已用配额, 历史退款次数)
退款金额 = f(订单金额, 已用时长/次数, 退款策略档位)
```

### 2.2 策略档位定义

| 档位 | 条件 | 退款比例 | 说明 |
|------|------|----------|------|
| 全额退款 | 购买后 ≤ 24h 且未使用高级功能 | 100% | 无条件全额退款 |
| 标准退款 | 购买后 ≤ 7 天 | 扣除已用天数费用 | 按日折算扣减 |
| 按量扣减退款 | 购买后 7-30 天 | 扣除已用天数+固定手续费 | 手续费 5%，最低 1 元 |
| 不予退款 | 购买后 > 30 天 | 0% | 仅特殊情形人工审批 |
| 增值服务退款 | 次数包未使用部分 | 未使用次数×单价 | 已使用次数不退 |

> **注意**：Apple IAP 退款由 Apple 审批，PrimeTop 无法直接控制退款结果，需通过 App Store Server Notifications V2 接收退款通知。

### 2.4 退款限制规则

| 规则 | 限制值 | 说明 |
|------|--------|------|
| 同一用户月退款次数上限 | 2 次 | 防止恶意退款 |
| 同一用户历史累计退款金额上限 | 500 元 | 触发风控审核 |
| 同一订单仅允许退款一次 | 1 次 | 不支持部分退款后再退 |
| 优惠/促销订单 | 按实付金额退 | 不退优惠部分 |

## 4. 退款状态机

### 4.1 状态定义

| 状态 | 说明 |
|------|------|
| `pending` | 用户已提交，待审核 |
| `approved` | 审核通过，待执行退款 |
| `processing` | 已向第三方发起退款，等待回调 |
| `refunded` | 退款成功完成 |
| `rejected` | 审核拒绝 |
| `failed` | 第三方退款失败 |
| `cancelled` | 用户主动撤消退款申请 |

### 4.2 状态流转图

```
                    ┌───────────┐
                    │  pending   │ ← 用户提交退款申请
                    └─────┬─────┘
                          │
           ┌──────────────┼──────────────┐
           │              │              │
           ▼              ▼              ▼
    ┌────────────┐ ┌──────────┐  ┌───────────┐
    │ rejected   │ │ approved │  │ cancelled │
    └────────────┘ └────┬─────┘  └───────────┘
                        │ 自动/人工审核通过
                        ▼
                  ┌───────────┐
                  │ processing│ ← 调用第三方退款API
                  └─────┬─────┘
                        │
              ┌─────────┼─────────┐
              │                   │
              ▼                   ▼
       ┌──────────┐        ┌──────────┐
       │ refunded │        │  failed  │
       └──────────┘        └────┬─────┘
                                │ 重试或人工处理
                                │
                          ┌─────┴──────┐
                          │ processing │ (重新发起)
                          └────────────┘
```

### 4.3 状态流转规则

| 当前状态 | 目标状态 | 触发条件 | 操作人 |
|----------|----------|----------|--------|
| `pending` | `approved` | 自动审核通过（≤24h 且满足策略）或管理员审批 | system/admin |
| `pending` | `rejected` | 不满足退款条件或管理员拒绝 | admin/system |
| `pending` | `cancelled` | 用户主动取消 | user |
| `approved` | `processing` | 调用第三方退款接口成功发起 | system |
| `processing` | `refunded` | 第三方回调确认退款成功 | system |
| `processing` | `failed` | 第三方回调退款失败或超时（72h） | system |
| `failed` | `processing` | 重试退款（最多 3 次） | system/admin |

#### 5.1.2 提交退款申请

```
POST /api/v1/orders/{orderId}/refund
```

**请求体：**

```json
{
  "reason_code": "quality_ai_answer",
  "reason_text": "AI回答的数学解题步骤有明显错误，误导了孩子",
  "confirm_membership_revoke": true
}
```

| 字段 | 类型 | 必选 | 说明 |
|------|------|------|------|
| reason_code | string | 是 | 退款原因编码 |
| reason_text | string | 条件必填 | 详细描述（reason_code 要求时必填） |
| confirm_membership_revoke | boolean | 是 | 用户确认退款后会员权益将被回收 |

**响应体：**

```json
{
  "code": 0,
  "data": {
    "refund_id": 12345,
    "refund_no": "RF20260604181500123456",
    "status": "pending",
    "refund_amount": 2400,
    "estimated_days": "1-3个工作日",
    "notice": "退款审核中。审核通过后，退款将在1-3个工作日内原路退回。会员权益将在退款成功后立即回收。"
  }
}
```

**错误码：**

| 错误码 | HTTP状态 | 说明 |
|--------|----------|------|
| `ORDER_NOT_FOUND` | 404 | 订单不存在 |
| `ORDER_NOT_REFUNDABLE` | 400 | 订单状态不允许退款（非 paid 状态） |
| `REFUND_ALREADY_EXISTS` | 409 | 该订单已存在退款工单 |
| `REFUND_LIMIT_EXCEEDED` | 429 | 本月退款次数已达上限 |
| `REFUND_INELIGIBLE` | 400 | 不满足退款条件 |
| `REFUND_CONFIRM_REQUIRED` | 400 | 未确认会员权益回收 |

## 6. 核心流程设计

### 6.1 退款申请提交流程

```
用户点击"申请退款"
       │
       ▼
┌──────────────────┐
│ 查询退款资格     │ ← 调用退款策略引擎
└────────┬─────────┘
         │
    资格校验
    ┌────┴────┐
    │         │
  通过      不通过 → 返回 ineligible 原因
    │
    ▼
┌──────────────────┐
│ 展示退款原因选项  │
│ 展示预计退款金额  │
│ 用户确认回收权益  │
└────────┬─────────┘
         │
    用户提交
         │
         ▼
┌──────────────────┐
│ 二次校验         │ ← 防并发：检查是否已有退款工单
```

### 6.3 退款金额计算引擎

```java
/**
 * 退款金额计算服务
 */
@Service
public class RefundCalculationService {

    @Autowired
    private RefundPolicyConfig policyConfig;

    /**
     * 计算退款金额
     * @param order 原始订单
     * @param usageInfo 使用情况
     * @return 退款计算结果
     */
    public RefundCalculationResult calculate(Order order, UsageInfo usageInfo) {
        RefundCalculationResult result = new RefundCalculationResult();

        // Apple IAP 特殊处理
        if ("apple_iap".equals(order.getPaymentChannel())) {
            result.setEligible(true);
            result.setPolicyTier("apple_iap");
            result.setRefundAmount(order.getPaidAmount()); // Apple 控制实际退款金额
            result.setNotice("退款由 Apple 审批处理");
            return result;
        }

        // 计算已使用时长（小时）
        long hoursSincePayment = Duration.between(
            order.getPaidAt().toInstant(),
            Instant.now()
        ).toHours();

        // 匹配策略档位
        RefundPolicyTier tier = matchPolicyTier(hoursSincePayment);
        result.setPolicyTier(tier.getName());

        if (tier.getRefundRatio() == 0) {
            result.setEligible(false);
            result.setIneligibleReason("order_paid_more_than_30_days");
            return result;
        }

        // 订单类型分支
        if ("subscription".equals(order.getOrderType())) {
            calculateSubscriptionRefund(order, tier, usageInfo, result);
        } else if ("value_added".equals(order.getOrderType())) {
            calculateValueAddedRefund(order, usageInfo, result);
        }

        // 应用固定手续费
        if (tier.getDeductionFixedCents() > 0) {
            result.setDeductionAmount(
                result.getDeductionAmount() + tier.getDeductionFixedCents()
            );
        }

        // 应用百分比手续费
        if (tier.getDeductionPercentage() > 0) {
            int pctDeduction = (int)(order.getPaidAmount() * tier.getDeductionPercentage() / 100.0);
            int minDeduction = tier.getMinDeductionCents();
            int fee = Math.max(pctDeduction, minDeduction);
            result.setDeductionAmount(result.getDeductionAmount() + fee);
        }

        // 最终退款金额 = 原金额 - 扣减金额
        int refundAmount = Math.max(0, order.getPaidAmount() - result.getDeductionAmount());
        result.setRefundAmount(refundAmount);
        result.setEligible(refundAmount > 0);

        return result;
    }

    /**
     * 订阅类退款计算：按日折算
     */
    private void calculateSubscriptionRefund(Order order, RefundPolicyTier tier,
                                              UsageInfo usage, RefundCalculationResult result) {
        MembershipPlan plan = getPlan(order.getPlanCode());
        int totalDays = plan.getDurationDays();
        long daysUsed = ChronoUnit.DAYS.between(
            order.getPaidAt().toLocalDate(),
            LocalDate.now()
        );
        long daysRemaining = Math.max(0, totalDays - daysUsed);

        int dailyPrice = order.getPaidAmount() / totalDays; // 向下取整日均价
        int usedAmount = (int)(daysUsed * dailyPrice);

        result.setDaysUsed(daysUsed);
        result.setDailyPrice(dailyPrice);
        result.setDeductionAmount(usedAmount);

        // 全额退款档位：≤24h 且未使用高级功能
        if ("full_refund".equals(tier.getName()) && !usage.hasPremiumUsage()) {
            result.setDeductionAmount(0);
        }
    }

    /**
     * 增值服务类退款计算：按未使用次数
     */
    private void calculateValueAddedRefund(Order order, UsageInfo usage,
                                            RefundCalculationResult result) {
        int totalCount = order.getItemCount();
        int usedCount = usage.getUsedQuota();
        int unusedCount = Math.max(0, totalCount - usedCount);
        int unitPrice = order.getPaidAmount() / totalCount;

        result.setDeductionAmount(usedCount * unitPrice);
        result.setRefundAmount(unusedCount * unitPrice);
    }
}
```

### 6.4 权益回收流程

```java
/**
 * 权益回收服务 - 退款成功后级联执行
 */
@Service
public class MembershipRevocationService {

    /**
     * 执行权益回收（在退款成功回调中触发）
     */    @Transactional
    public void revokeOnRefund(RefundOrder refundOrder) {
        Order originalOrder = orderRepository.findById(refundOrder.getOriginalOrderId());

        // 1. 查找当前会员状态
        UserMembership membership = membershipRepository
            .findActiveByUserId(refundOrder.getUserId())
            .orElse(null);

        if (membership == null) {
            // 无活跃会员，无需回收
            return;
        }

        // 2. 仅当当前会员来自被退款的订单时才回收
        if (membership.getSourceOrderId().equals(refundOrder.getOriginalOrderId())) {
            // 回退到免费用户
            membership.setPlanCode("free");
            membership.setExpiresAt(LocalDateTime.now()); // 立即过期
            membership.setStatus("refunded");
            membershipRepository.save(membership);
        }

        // 3. 记录会员变更日志
        MembershipChangeLog changeLog = new MembershipChangeLog();
        changeLog.setUserId(refundOrder.getUserId());
        changeLog.setOldPlanCode(membership.getPlanCode());
        changeLog.setNewPlanCode("free");
        changeLog.setChangeType("refund");
        changeLog.setOrderId(refundOrder.getOriginalOrderId());
        changeLogRepository.save(changeLog);

        // 4. 清除 Redis 中的权益缓存
        redisTemplate.delete("membership:" + refundOrder.getUserId());
        redisTemplate.delete("quota:" + refundOrder.getUserId());

        // 5. 发送通知
        notificationService.sendRefundSuccessNotification(
            refundOrder.getUserId(),
            refundOrder.getRefundAmount(),
            membership.getPlanCode() // 被回收的等级
        );

        // 6. 标记回收完成
        refundOrder.setMembershipRevoked(true);
        refundOrder.setQuotaRolledBack(true);
        refundOrderRepository.save(refundOrder);
    }
}
```

### 7.3 Apple IAP 退款

Apple IAP 的退款机制与其他渠道**根本不同**：PrimeTop 无法主动发起退款，只能被动接收 Apple 的退款通知。

| 项目 | 说明 |
|------|------|
| 退款方式 | 用户在 App Store / 设置中申请，Apple 审核 |
| 到账时间 | Apple 决定 |
| 接收方式 | App Store Server Notifications V2 |
| 通知类型 | `REFUND` |

**处理流程：**

```
用户在 Apple 端申请退款
       │
       ▼
Apple 审核并决定退款
       │
       ▼
App Store Server Notification V2
  type=REFUND 推送到 PrimeTop
       │
       ▼
┌─────────────────────┐
│ 1. 验证 JWT 签名    │
│ 2. 解析通知体       │
│ 3. 匹配原始交易     │
│ 4. 创建退款工单     │
│    (applicant=system)│
│ 5. 直接标记 refunded│
│ 6. 执行权益回收     │
│ 7. 记录对账数据     │
└─────────────────────┘
```

**Apple 退款通知处理代码：**

```java
@Service
public class AppleIAPRefundHandler {

    public void handleRefundNotification(AppStoreNotification notification) {
        // 提取关键信息
        String originalTransactionId = notification.getOriginalTransactionId();
        String transactionId = notification.getTransactionId();

        // 查找本地订单
        Order order = orderRepository.findByAppleOriginalTransactionId(originalTransactionId)
            .orElseThrow(() -> new OrderNotFoundException(originalTransactionId));

        // 幂等校验：是否已处理过该退款
        if (refundOrderRepository.existsByChannelRefundNo(transactionId)) {
            log.info("Apple IAP refund already processed: {}", transactionId);
            return;
        }

        // 创建退款工单
        RefundOrder refundOrder = new RefundOrder();
        refundOrder.setOriginalOrderId(order.getId());
        refundOrder.setOriginalOrderNo(order.getOrderNo());
        refundOrder.setUserId(order.getUserId());
        refundOrder.setApplicantType("system");
        refundOrder.setRefundReasonCode("apple_iap_refund");
        refundOrder.setRefundType("full");
        refundOrder.setOriginalAmount(order.getPaidAmount());
        refundOrder.setRefundAmount(order.getPaidAmount()); // Apple 不提供退款金额，按全额记
        refundOrder.setPaymentChannel("apple_iap");
        refundOrder.setChannelRefundNo(transactionId);
        refundOrder.setStatus("refunded"); // 直接标记成功
        refundOrder.setPolicyTier("apple_iap");
        refundOrder.setChannelRawResponse(
            objectMapper.writeValueAsString(notification)
        );
        refundOrderRepository.save(refundOrder);

        // 执行权益回收
        membershipRevocationService.revokeOnRefund(refundOrder);
    }
}
```

> **重要**：Apple 可能仅部分退款或由 Apple Support 酌情处理，实际退款金额可能与订单金额不同。需在后续对账中处理差异。

## 8. 风控与反滥用机制

### 8.1 退款频率限制

```java
@Service
public class RefundRateLimiter {

    /**
     * 检查用户退款频率
     */    public RefundRateCheckResult check(Long userId) {
        // 月退款次数
        int monthlyCount = refundOrderRepository
            .countByUserIdAndCreatedAtAfter(userId, LocalDate.now().minusMonths(1));

        if (monthlyCount >= 2) {
            return RefundRateCheckResult.denied(
                "MONTHLY_REFUND_LIMIT_REACHED",
                "本月退款次数已达上限（2次）"
            );
        }

        // 历史累计退款金额
        int totalRefunded = refundOrderRepository
            .sumRefundAmountByUserId(userId);

        if (totalRefunded >= 50000) { // 500 元
            // 标记为高风险，需要人工审核
            return RefundRateCheckResult.requiresReview(
                "HIGH_REFUND_HISTORY",
                "累计退款金额较高，需人工审核"
            );
        }

        return RefundRateCheckResult.allowed();
    }
}
```

## 11. 错误处理与异常场景

### 11.1 异常场景与处理策略

| 场景 | 处理策略 |
|------|----------|
| 第三方退款接口超时 | 标记 processing，等待回调或定时任务主动查询 |
| 第三方返回「退款中」 | 保持 processing，继续等待 |
| 退款金额不一致 | 写入 mismatch 对账记录，人工处理 |
| 退款成功但权益回收失败 | 告警 + 补偿任务重试权益回收 |
| 并发退款（同一订单） | 数据库唯一索引 + 分布式锁防护 |
| Apple 重复退款通知 | 幂等校验（transactionId） |
| 用户退款后快速重新购买 | 正常允许，风控系统标记观察 |

### 11.2 补偿事务设计

```java
/**
 * 退款补偿任务 - 处理不一致状态
 */
@Scheduled(fixedDelay = 4 * 3600 * 1000) // 每4小时
public void compensateRefundInconsistencies() {
    // 场景1：已退款但权益未回收
    List<RefundOrder> notRevoked = refundOrderRepository
        .findByStatusAndMembershipRevokedFalse("refunded");
    notRevoked.forEach(refund -> {
        try {
            membershipRevocationService.revokeOnRefund(refund);
        } catch (Exception e) {
            log.error("补偿权益回收失败: refundId={}", refund.getId(), e);
            alertService.sendAlert("退款权益回收补偿失败", refund.getRefundNo());
        }
    });

    // 场景2：processing 超时未收到回调
    List<RefundOrder> timeout = refundOrderRepository
        .findByStatusAndUpdatedAtBefore("processing",
            LocalDateTime.now().minusHours(72));
    timeout.forEach(refund -> {
        // 主动查询第三方退款状态
        queryRefundStatusFromChannel(refund);
    });
}
```

- 工单详情：完整的退款信息、操作日志、渠道回调原始数据
- 审批操作：通过/拒绝，支持调整退款金额
- 手动重试：针对失败工单
- 手动标记完成：第三方已退但回调未收到时

### 13.2 退款数据看板

| 指标 | 说明 |
|------|------|
| 当日退款笔数 | 分渠道统计 |
| 当日退款金额 | 分渠道统计 |
| 退款率 | 退款笔数/总订单数 |
| 平均退款处理时长 | 从申请到完成的时间 |
| 退款原因分布 | 饼图展示各原因占比 |
| 退款失败告警 | 实时推送失败工单 |

### 13.3 财务对账

- 每日自动生成退款对账文件
- 与微信/支付宝对账文件自动比对
- 差异记录人工处理
- 月度退款报表导出
