# 服务端定时任务调度与批处理框架 - 详细设计

## 1. 概述

### 1.1 背景

PrimeTop 系统存在大量需要定时执行或批量处理的业务场景，包括但不限于：学习日报/周报生成、过期会员清理、错题复习提醒推送、学习数据聚合统计、临时文件清理、教材同步检查等。这些任务具有执行时间确定、数据量大、容错要求高的特点，需要一个统一的调度与批处理框架来管理。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 统一调度 | 所有定时任务通过统一框架注册、调度、监控 |
| 高可用 | 调度节点故障时自动 failover，任务不丢失 |
| 可观测 | 任务执行状态、耗时、成功/失败率实时可查 |
| 幂等执行 | 同一任务重复执行不产生副作用 |
| 弹性伸缩 | 支持分片执行，数据量大时可水平扩展 |
| 失败重试 | 任务失败自动重试，超限告警 |

### 1.3 与相关模块的关系

```
┌──────────────────────────────────────────────────────┐
│                   定时任务调度框架                      │
├──────────────┬──────────────┬─────────────────────────┤
│  Cron 调度器  │  批处理引擎   │  任务监控与告警          │
├──────────────┴──────────────┴─────────────────────────┤
│  基础设施：分布式锁 / 消息队列 / 数据库 / Redis        │
└──────────────────────────────────────────────────────┘
         │              │              │
    ┌────▼────┐   ┌────▼────┐   ┌────▼──────┐
    │学习服务 │   │用户服务 │   │通知推送服务│
    └─────────┘   └─────────┘   └───────────┘
```

### 3.2 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 调度框架 | **Node.js + BullMQ** | 基于 Redis 的分布式任务队列，天然支持定时任务、重试、优先级 |
| 分布式锁 | **Redis (Redlock)** | 确保同一定时任务只有一个节点执行 |
| 任务日志存储 | **MySQL** | 结构化存储任务执行历史 |
| 批处理分片 | **BullMQ Repeatable + 自定义分片逻辑** | 灵活可控 |
| 监控 | **Prometheus + Grafana** | 任务执行指标采集与可视化 |
| 告警 | **Webhook → 通知中心** | 任务失败/超限告警 |

> **选型说明：** MVP 阶段使用单节点 BullMQ + Redis 即可满足需求。BullMQ 原生支持 repeatable jobs（基于 cron），天然具备分布式能力，无需引入 XXL-JOB 等重量级框架。后续规模增大时可平滑迁移至多节点模式。

### 3.3 调度器生命周期

```
应用启动
  │
  ├── 注册所有定时任务定义
  ├── 创建/更新 BullMQ Repeatable Jobs
  ├── 启动 Worker 进程监听队列
  │
  ▼
正常运行
  │
  ├── Cron 触发 → 分发到 Worker → 执行 → 记录日志
  ├── 手动触发 → 注入队列 → Worker 消费
  ├── 事件触发 → 创建一次性任务 → Worker 消费
  │
  ▼
优雅关闭
  │
  ├── 停止接受新任务
  ├── 等待当前任务完成 (graceful shutdown)
  ├── 超时后强制中断
  └── 记录关闭日志
```

### 4.4 Redis 数据结构

```
# 分布式锁（确保单节点执行）
sched:lock:{taskKey}          → 节点标识 + 过期时间    TTL = timeoutSeconds * 2

# 执行状态追踪
sched:running:{taskKey}       → JSON { nodeId, startedAt, shardIndex }

# 连续失败计数
sched:fail_count:{taskKey}    → 计数值                 TTL = 24h

# 上次执行时间（用于幂等判断）
sched:last_run:{taskKey}      → timestamp              TTL = 7d

# 分片进度追踪
sched:shard:{taskKey}:{runId} → Hash { shard0: "done", shard1: "running", ... }  TTL = 1h
```

## 5. 核心流程设计

### 5.1 任务注册与调度流程

```typescript
// src/scheduler/registry.ts

import { Queue, Worker, Repeat } from 'bullmq';
import { redis } from '../common/redis';
import { TaskDefinition } from './types';

const TASK_REGISTRY = new Map<string, TaskDefinition>();

/**
 * 注册定时任务
 */
export function registerTask(definition: TaskDefinition): void {
  TASK_REGISTRY.set(definition.taskKey, definition);
  
  if (definition.enabled && definition.cronExpression) {
    const queue = new Queue(`sched:${definition.taskKey}`, { connection: redis });
    
    queue.add(
      definition.taskKey,
      { taskKey: definition.taskKey },
      {
        repeat: { pattern: definition.cronExpression },
        priority: definition.priority,
      }
    );
  }
}

/**
 * 获取所有已注册任务
 */
export function getRegisteredTasks(): TaskDefinition[] {
  return Array.from(TASK_REGISTRY.values());
}
```

### 5.3 Worker 执行流程

```typescript
// src/scheduler/worker.ts

import { Worker, Job } from 'bullmq';
import { redis } from '../common/redis';
import { acquireLock, releaseLock } from './lock';
import { TaskLogRepository } from '../repositories/task-log-repo';
import { createTaskExecutor } from './executors';
import type { TaskContext, TaskResult } from './types';

const WORKER_ID = `${process.env.HOSTNAME || 'node'}-${process.pid}`;
const logRepo = new TaskLogRepository();

export function startSchedulerWorker(): Worker {
  const worker = new Worker(
    'scheduler-main',
    async (job: Job) => {
      const { taskKey } = job.data;
      const executor = createTaskExecutor(taskKey);
      if (!executor) {
        throw new Error(`Unknown task: ${taskKey}`);
      }

      // 1. 获取分布式锁
      const lockKey = `sched:lock:${taskKey}`;
      const acquired = await acquireLock(lockKey, WORKER_ID, job.timeout);
      if (!acquired) {
        return { status: 'SKIPPED', reason: 'LOCK_NOT_ACQUIRED' };
      }

      // 2. 创建执行日志
      const logId = await logRepo.create({
        taskKey,
        triggerType: job.data.triggerType || 'CRON',
        triggeredBy: job.data.triggeredBy,
        status: 'RUNNING',
        workerNode: WORKER_ID,
        startedAt: new Date(),
      });

      const ctx: TaskContext = {
        taskKey,
        triggerType: job.data.triggerType || 'CRON',
        triggeredBy: job.data.triggeredBy,
        logId,
      };

      try {
        // 3. 可选的前置检查
        if (executor.shouldExecute && !(await executor.shouldExecute(ctx))) {
          await logRepo.update(logId, { status: 'SKIPPED', finishedAt: new Date() });
          return { status: 'SKIPPED' };
        }

        // 4. 执行核心逻辑
        const result: TaskResult = await executor.execute(ctx);

        // 5. 记录结果
        await logRepo.update(logId, {
          status: 'SUCCESS',
          finishedAt: new Date(),
          totalItems: result.totalItems,
          successItems: result.successItems,
          failedItems: result.failedItems,
          resultSummary: JSON.stringify(result.summary),
        });

        // 6. 级联触发下游任务
        if (result.cascadeTasks?.length) {
          for (const cascade of result.cascadeTasks) {
            await triggerCascadeTask(cascade, logId);
          }
        }

        return result;

      } catch (error) {
        // 7. 错误处理
        await logRepo.update(logId, {
          status: 'FAILED',
          finishedAt: new Date(),
          errorMessage: String(error?.message || error).substring(0, 2000),
          errorStack: String(error?.stack || '').substring(0, 4000),
        });

        // 更新连续失败计数
        await incrementFailCount(taskKey);

        throw error; // 让 BullMQ 处理重试

      } finally {
        await releaseLock(lockKey, WORKER_ID);
      }
    },
    {
      connection: redis,
      concurrency: 5,
    }
  );

  // 事件监听
  worker.on('completed', (job) => {
    metrics.increment('sched.task.completed', 1, { taskKey: job.data.taskKey });
  });

  worker.on('failed', (job, err) => {
    metrics.increment('sched.task.failed', 1, { taskKey: job.data.taskKey });
    logger.error(`Task ${job?.data?.taskKey} failed`, err);
  });

  return worker;
}
```

### 5.4 分片执行流程

对于数据量大的任务（如每日报告生成），采用分片策略并行处理：

```typescript
// src/scheduler/sharding.ts

import { Queue } from 'bullmq';

interface ShardingStrategy {
  /**
   * 根据分片键计算分片范围
   * @param shardIndex 当前分片序号
   * @param shardTotal 总分片数
   * @returns 该分片处理的数据范围条件
   */
  getShardRange(shardIndex: number, shardTotal: number): {
    minId: number;
    maxId: number;
  };
}

/**
 * 基于用户ID的分片策略
 * 利用 user_id % shardTotal = shardIndex 来分配
 */
export class UserIdShardingStrategy implements ShardingStrategy {
  getShardRange(shardIndex: number, shardTotal: number) {
    // 分片信息通过 WHERE user_id % shardTotal = shardIndex 传递给SQL
    return { shardIndex, shardTotal };
  }
}

/**
 * 分片任务分发器
 */
export async function dispatchShardedTask(
  taskKey: string,
  shardTotal: number,
  params?: Record<string, any>
): Promise<void> {
  const queue = new Queue(`sched:${taskKey}`, { connection: redis });
  
  // 生成唯一的 runId 用于追踪本次分片执行
  const runId = Date.now().toString(36);
  
  // 初始化分片进度
  const progressKey = `sched:shard:${taskKey}:${runId}`;
  for (let i = 0; i < shardTotal; i++) {
    await redis.hset(progressKey, `shard${i}`, 'pending');
  }
  await redis.expire(progressKey, 3600); // 1小时过期

  // 逐分片分发
  for (let i = 0; i < shardTotal; i++) {
    await queue.add(`${taskKey}:shard${i}`, {
      taskKey,
      triggerType: 'CRON',
      shardIndex: i,
      shardTotal,
      runId,
      ...params,
    }, {
      priority: 5,
    });
  }
}
```

```typescript
// src/scheduler/executors/learn-daily-report.ts

export class LearnDailyReportExecutor implements TaskExecutor {
  readonly taskKey = 'learn-daily-report';

  async execute(ctx: TaskContext): Promise<TaskResult> {
    const yesterday = dayjs().subtract(1, 'day').format('YYYY-MM-DD');
    
    let query = db('learning_records')
      .where('date', yesterday);
    
    // 分片条件
    if (ctx.shardIndex !== undefined && ctx.shardTotal !== undefined) {
      query = query.whereRaw('user_id % ? = ?', [ctx.shardTotal, ctx.shardIndex]);
    }

    const activeUsers = await query
      .select('user_id')
      .groupBy('user_id');

    let successItems = 0;
    let failedItems = 0;

    // 批量处理，每批100条
    for (const batch of chunk(activeUsers, 100)) {
      await Promise.allSettled(
        batch.map(({ user_id }) => 
          this.generateUserDailyReport(user_id, yesterday)
            .then(() => { successItems++; })
            .catch((e) => { failedItems++; logger.warn(`Report failed for ${user_id}`, e); })
        )
      );
    }

    return {
      totalItems: activeUsers.length,
      successItems,
      failedItems,
      summary: { date: yesterday, shardIndex: ctx.shardIndex },
    };
  }

        db.raw('COUNT(DISTINCT subject_id) as subject_count'),
        db.raw('COUNT(*) as record_count'),
      )
      .first();

    // 获取错题数据

      .whereRaw('DATE(created_at) = ?', [date])
```

```typescript
// src/scheduler/lock.ts

import { redis } from '../common/redis';
import { v4 as uuid } from 'uuid';

const LOCK_PREFIX = 'sched:lock:';

/**
 * 获取分布式锁
 * @returns lockValue 用于释放锁时验证
 */
export async function acquireLock(
  resource: string,
  nodeId: string,
  ttlSeconds: number,
): Promise<string | null> {
  const key = `${LOCK_PREFIX}${resource}`;
  const value = `${nodeId}:${uuid()}`;
  
  const result = await redis.set(key, value, 'PX', ttlSeconds * 1000, 'NX');
  
  if (result === 'OK') {
    return value;
  }
  return null;
}

/**
 * 释放锁（Lua脚本保证原子性）
 */
export async function releaseLock(
  resource: string,
  lockValue: string,
): Promise<boolean> {
  const key = `${LOCK_PREFIX}${resource}`;
  const script = `
    if redis.call("get", KEYS[1]) == ARGV[1] then
      return redis.call("del", KEYS[1])
    else
      return 0
    end
  `;
  const result = await redis.eval(script, 1, key, lockValue);
  return result === 1;
}

/**
 * 锁续约（长时间任务需要）
 */
export async function renewLock(
  resource: string,
  lockValue: string,
  ttlSeconds: number,
): Promise<boolean> {
  const key = `${LOCK_PREFIX}${resource}`;
  const script = `
    if redis.call("get", KEYS[1]) == ARGV[1] then
      return redis.call("pexpire", KEYS[1], ARGV[2])
    else
      return 0
    end
  `;
  const result = await redis.eval(script, 1, key, lockValue, String(ttlSeconds * 1000));
  return result === 1;
}
```

### 6.2 幂等控制

```typescript
// src/scheduler/idempotent.ts

/**
 * 基于「上次执行时间」的幂等判断
 * 防止同一天内重复执行日级别任务
 */
export async function checkDailyIdempotent(
  taskKey: string,
  date?: string,
): Promise<boolean> {
  const key = `sched:last_run:${taskKey}`;
  const today = date || dayjs().format('YYYY-MM-DD');
  
  const lastRun = await redis.get(key);
  if (lastRun === today) {
    logger.info(`Task ${taskKey} already executed for ${today}, skipping`);
    return false; // 不应执行
  }
  
  // 标记为执行中（执行成功后会更新为当天日期）
  await redis.set(key, `running:${today}`, 'EX', 86400);
  return true; // 可以执行
}

/**
 * 执行成功后确认
 */
export async function confirmDailyExecution(taskKey: string): Promise<void> {
  const key = `sched:last_run:${taskKey}`;
  const today = dayjs().format('YYYY-MM-DD');
  await redis.set(key, today, 'EX', 86400 * 7); // 保留7天
}
```

```typescript
// src/scheduler/graceful-shutdown.ts

export function setupGracefulShutdown(worker: Worker): void {
  let isShuttingDown = false;

  const shutdown = async (signal: string) => {
    if (isShuttingDown) return;
    isShuttingDown = true;
    
    logger.info(`Received ${signal}, starting graceful shutdown...`);
    
    // 1. 停止接受新任务
    await worker.pause(true); // pause processing, do not await current jobs
    
    // 2. 等待当前任务完成（最多30秒）
    const waitTimeout = setTimeout(() => {
      logger.warn('Graceful shutdown timeout, forcing close');
      worker.close(true); // force close
    }, 30_000);
    
    await worker.close(false); // graceful close
    clearTimeout(waitTimeout);
    
    logger.info('Scheduler worker shut down successfully');
    process.exit(0);
  };

  process.on('SIGTERM', () => shutdown('SIGTERM'));
  process.on('SIGINT', () => shutdown('SIGINT'));
}
```

```typescript
  }

  async execute(ctx: TaskContext): Promise<TaskResult> {

    // 免费用户的每日额度配置
    const FREE_DAILY_QUOTA = {
      ai_chat_count: 10,
      photo_search_count: 5,
    };

    // 方案1：使用 Redis Key 天然过期（推荐）
    // 额度 Key: quota:{userId}:ai_chat:{YYYY-MM-DD}
    // 无需主动重置，每天自然切换到新的 Key
    // 但需要清理前一天的旧 Key

    // 清理7天前的额度 Key
    const sevenDaysAgo = dayjs().subtract(7, 'day').format('YYYY-MM-DD');
    const pattern = `quota:*:*:${sevenDaysAgo}`;
    
    // 使用 SCAN 避免阻塞 Redis
    let totalItems = 0;
    let successItems = 0;
    
    const stream = redis.scanStream({ match: pattern, count: 100 });
    
    await new Promise<void>((resolve, reject) => {
      stream.on('data', async (keys: string[]) => {
        if (keys.length > 0) {
          totalItems += keys.length;
          try {
            await redis.del(...keys);
            successItems += keys.length;
          } catch (e) {
            logger.warn('Failed to delete quota keys', e);
          }
        }
      });
      stream.on('end', resolve);
      stream.on('error', reject);
    });

    await confirmDailyExecution(this.taskKey);

    return {
      totalItems,
      successItems,
      failedItems: totalItems - successItems,
      summary: { date: today, cleanedDate: sevenDaysAgo },
    };
  }
}
```

```typescript
            .where({ user_id: membership.user_id, source: 'MEMBERSHIP' })
            .update({ status: 'REVOKED' });

          // 3. 清除缓存
          await redis.del(`user:membership:${membership.user_id}`);
          await redis.del(`user:privileges:${membership.user_id}`);

          userId: membership.user_id,
          membershipId: membership.id,
          planType: membership.plan_type,
        });

        successItems++;
      } catch (error) {
        logger.error(`Failed to expire membership ${membership.id}`, error);
        failedItems++;
      }
    }

    return {
      totalItems: expiringMemberships.length,
      successItems,
      failedItems,
```

```typescript
// src/scheduler/executors/temp-file-clean.ts

import { S3Client, ListObjectsV2Command, DeleteObjectsCommand } from '@aws-sdk/client-s3';

export class TempFileCleanExecutor implements TaskExecutor {
  readonly taskKey = 'sys-temp-file-clean';

  async execute(ctx: TaskContext): Promise<TaskResult> {
    const RETENTION_DAYS = 7;
    const cutoffTime = dayjs().subtract(RETENTION_DAYS, 'day').toDate();
    
    const s3 = new S3Client({ region: process.env.S3_REGION });
    const bucket = process.env.S3_BUCKET!;
    
    let totalItems = 0;
    let successItems = 0;
    let failedItems = 0;
    let continuationToken: string | undefined;

    do {
      // 列出 temp/ 前缀的文件
      const listResult = await s3.send(new ListObjectsV2Command({
        Bucket: bucket,
        Prefix: 'temp/',
        ContinuationToken: continuationToken,
        MaxKeys: 1000,
      }));

      const objectsToDelete = (listResult.Contents || [])
        .filter(obj => obj.LastModified! < cutoffTime)
        .map(obj => ({ Key: obj.Key! }));

      totalItems += objectsToDelete.length;

      if (objectsToDelete.length > 0) {
        try {
          await s3.send(new DeleteObjectsCommand({
            Bucket: bucket,
            Delete: { Objects: objectsToDelete, Quiet: true },
          }));
          successItems += objectsToDelete.length;
        } catch (error) {
          failedItems += objectsToDelete.length;
          logger.error('Failed to delete temp files batch', error);
        }
      }

      continuationToken = listResult.NextContinuationToken;
    } while (continuationToken);

    return {
      totalItems,
      successItems,
      failedItems,
      summary: { retentionDays: RETENTION_DAYS, cutoffTime: cutoffTime.toISOString() },
    };
  }
}
```

### 10.1 任务超时处理

```
任务开始
  │
  ├── BullMQ job.timeout 设置 = definition.timeoutSeconds
  │
  ├── 任务内设置 watchdog，每 60s 续约分布式锁

  ├── 超时触发：
  │   ├── BullMQ 标记 job 为 failed
  │   ├── Worker 进程内的 executor 收到超时信号
  │   ├── 调用 executor.onAbort() 进行清理
  │   └── 分布式锁自然过期释放
  │
  └── 日志记录 status=TIMEOUT
```

### 10.2 重复执行防护

| 场景 | 防护机制 |
|------|----------|
| 调度器重复注册 | 应用启动时先移除旧的 repeatable job，再重新注册 |
| 多节点同时触发 | 分布式锁保证只有一个节点执行 |
| 手动触发 + Cron 同时触发 | 日级别幂等检查 (`checkDailyIdempotent`) |
| 任务执行时间超过下一个 Cron 周期 | BullMQ 默认不会并发执行同一 repeatable job |

### 10.3 数据一致性保障

```
┌─────────────────────────────────────────┐
│          批量处理事务策略                  │
├─────────────────────────────────────────┤
│                                         │
│  对于每条数据的处理：                      │
│  ├── 成功 → COMMIT                      │
│  ├── 失败 → 记录到 failed_items 表       │
│  │         不影响其他数据处理              │
│  └── 超时 → 标记为 UNKOWN                │
│            下次执行时通过幂等检查跳过       │
│                                         │
│  整批完成后：                             │
│  ├── 写入 result_summary               │
│  └── 如果 failedItems > 0              │
│      → 生成重试清单，下次执行优先处理      │
└─────────────────────────────────────────┘
```

### 10.4 节点故障恢复

```
节点 A 执行任务中 → 节点 A 突然宕机
  │
  ├── BullMQ 检测到 Worker 失联（stalled job check）
  │   └── 默认 30s 检测一次
  │
  ├── 任务被重新放入队列（可见性超时）
  │
  ├── 其他 Worker 节点拾取任务
  │
  ├── 新节点尝试获取分布式锁
  │   ├── 锁已过期（宕机超过 TTL）→ 获取成功，执行任务
  │   └── 锁未过期 → 等待或跳过
  │
  └── 日志中记录原执行节点故障信息
```

### 11.3 数据归档策略

`sched_task_log` 表数据增长较快，需要定期归档：

```sql
-- 归档超过 90 天的日志到归档表
INSERT INTO sched_task_log_archive
SELECT * FROM sched_task_log
WHERE created_at < DATE_SUB(NOW(), INTERVAL 90 DAY)
AND status IN ('SUCCESS', 'SKIPPED');

-- 删除已归档的记录
DELETE FROM sched_task_log
WHERE created_at < DATE_SUB(NOW(), INTERVAL 90 DAY)
AND status IN ('SUCCESS', 'SKIPPED');

-- 失败记录保留 180 天
DELETE FROM sched_task_log
WHERE created_at < DATE_SUB(NOW(), INTERVAL 180 DAY)
AND status = 'FAILED';
```

```typescript
      const items = await this.fetchData(ctx);
      totalItems = items.length;

      for (const batch of chunk(items, 100)) {

          batch.map(item => this.processItem(item, ctx))
        );

          if (result.status === 'fulfilled') {
            successItems++;
          } else {
            failedItems++;
            logger.warn(`Item processing failed`, result.reason);
          }
        }
      }

      // 3. 确认执行（幂等标记）
      await confirmDailyExecution(this.taskKey);

      return {
        totalItems,
        successItems,
        failedItems,
        summary: { /* 自定义摘要信息 */ },
      };
    } catch (error) {
      logger.error(`Task ${this.taskKey} failed`, error);
      throw error;
    }
  }
```

## 14. 风险与注意事项

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| Redis 宕机导致调度不可用 | 所有定时任务停摆 | Redis 主从 + 哨兵模式；降级方案：本地 cron + DB 锁 |
| 大数据量任务阻塞队列 | 其他任务等待 | 分片执行 + 优先级调度 + 独立队列 |
| 任务执行时间重叠 | 资源争用、数据冲突 | 错开高峰任务时间；分布式锁保证互斥 |
| 时区问题 | 任务执行时间偏移 | 统一使用 Asia/Shanghai 时区；Cron 表达式明确标注时区 |
| 日志表膨胀 | 存储和查询性能下降 | 定期归档；添加时间索引；分表策略 |
| 手动触发误操作 | 重复执行导致数据异常 | 幂等保护 + 操作二次确认 + 操作审计 |
