# 服务端-学生每日学习时间智能分配与多学科学习负荷均衡优化引擎-详细设计

## 1. 模块概述

### 1.1 功能定位

本引擎解决一个核心优化问题：**给定学生当日可用学习时间和多维学习上下文，如何将有限时间在不同学科、不同学习活动类型之间进行最优分配，使得学习效果最大化、认知负荷均衡、关键截止项不被遗漏。**

与现有模块的边界划分：

| 模块 | 职责边界 | 与本引擎的关系 |
| --- | --- | --- |
| 每日任务智能生成服务 | 生成具体的学习任务条目（做什么） | 本引擎决定时间预算（做多久），任务生成服务在本引擎分配的时间槽内填充任务 |
| 多源学习任务统一调度引擎 | 多来源任务的优先级仲裁 | 本引擎为其提供学科维度的时间配额约束 |
| 学习计划动态调整服务 | 中长期计划（周/月）的重排 | 本引擎聚焦当日微观层面的时间分配 |
| 学生认知负荷监测引擎 | 实时监测认知负荷并反馈 | 本引擎是其前置——在事前预防负荷失衡 |
| 学习规划与每日任务 E2E | 端到端用户旅程 | 本引擎是其中"时间分配决策"环节的深度展开 |

### 1.2 设计目标

| 目标 | 指标 |
| --- | --- |
| 时间分配合理性 | 分配方案覆盖所有待复习遗忘曲线临界点 ≥ 95% |
| 学科负荷均衡 | 单日单学科学习时长占比 ≤ 45%（除非考前冲刺模式） |
| 截止项覆盖率 | 当日截止作业/任务 100% 纳入分配 |
| 响应速度 | 分配方案计算 ≤ 200ms（P99） |
| 用户满意度 | 学生"今天学什么"入口推荐采纳率 ≥ 70% |
| 可解释性 | 每个时间块分配原因可向用户/家长解释 |

### 1.3 核心挑战

1. **多约束优化**：时间总量、截止日期、遗忘曲线、认知负荷、用户偏好等多维度约束。
2. **动态变化**：学生实际学习进度与计划存在偏差，需实时重计算。
3. **冷启动**：新用户缺乏学习画像数据时的降级策略。
4. **可解释性**：不能是黑箱——学生/家长需要理解"为什么今天要学这个"。

## 4. 优化算法设计

### 4.1 问题建模

将时间分配形式化为一个 **带约束的多目标优化问题**。

#### 4.1.1 决策变量

设当日有 $n$ 个候选时间块槽位（由可用时间段切分而来），每个槽位需要决定：
- 分配给哪个学科 $s_i \in \{数学, 语文, 英语, ...\}$
- 执行哪种活动 $a_i \in \{新学, 练习, 复习, 错题订正, 背诵\}$
- 时长 $t_i \in [t_{min}, t_{max}]$

#### 4.1.2 目标函数

$$
\text{Maximize} \quad F = w_1 \cdot U_{\text{urgency}} + w_2 \cdot U_{\text{mastery}} + w_3 \cdot U_{\text{balance}} + w_4 \cdot U_{\text{efficiency}} + w_5 \cdot U_{\text{preference}}
$$

各子目标：

| 子目标 | 含义 | 计算 |
| --- | --- | --- |
| $U_{\text{urgency}}$ | 紧急度收益 | 时间块覆盖的截止项和逾期复习项的加权紧急度之和 |
| $U_{\text{mastery}}$ | 掌握度提升 | 分配给低掌握度学科/知识点的时间带来的预期掌握度增量 |
| $U_{\text{balance}}$ | 均衡度收益 | 学科间时间分配的均匀程度（信息熵） |
| $U_{\text{efficiency}}$ | 效率收益 | 活动类型与时段精力系数的匹配程度 |
| $U_{\text{preference}}$ | 偏好收益 | 符合用户偏好策略的程度 |

权重默认值：

```java
public class AllocationWeights {
    public static final double W_URGENCY = 0.35;
    public static final double W_MASTERY = 0.25;
    public static final double W_BALANCE = 0.15;
    public static final double W_EFFICIENCY = 0.15;
    public static final double W_PREFERENCE = 0.10;
}
```

权重在不同模式下动态调整：

```java
public enum ScheduleMode {
    NORMAL,         // 正常日常模式，使用默认权重
    EXAM_WEEK,      // 考试周模式：W_URGENCY↑, W_MASTERY↑, W_BALANCE↓
    HOLIDAY,        // 假期模式：W_BALANCE↑, W_PREFERENCE↑, W_URGENCY↓
    PRE_EXAM_SPRINT // 考前冲刺模式：W_URGENCY↑↑, W_MASTERY↑, W_BALANCE↓↓
```

#### 4.1.3 约束条件

| 约束 | 表达 | 说明 |
| --- | --- | --- |
| 时间总量约束 | $\sum t_i \leq T_{\text{available}}$ | 分配总量不超过可用时间 |
| 单科上限 | $\forall s: \sum_{i: s_i=s} t_i \leq 0.45 \cdot T_{\text{available}}$ | 单学科不超过45%（冲刺模式可放宽到60%） |
| 连续学习上限 | $\forall \text{连续块}: \sum t_i \leq T_{\text{maxContinuous}}$ | 避免认知疲劳 |
| 截止项必选 | $\text{所有截止项} \in \text{分配的块}$ | 截止任务必须被覆盖 |
| 最小块时长 | $t_i \geq 15\text{min}$ | 太短的时间块无意义 |
| 精力匹配 | 难度高的活动安排在精力系数≥1.0的时段 | |

### 4.2 求解策略

由于精确的多约束整数规划在实时场景中不现实（NP-hard），采用 **三阶段启发式求解**：

#### 阶段一：必做项锚定（Must-Do Anchoring）

```java
/**
 * 阶段一：将截止任务和逾期复习项锚定到时间轴。
 * 这些是"不可商量"的，优先占据最优时段。
 */
public List<TimeBlock> anchorMustDoItems(DailyStudyContext ctx) {
    List<TimeBlock> anchoredBlocks = new ArrayList<>();
    
    // 1. 截止任务按紧急度排序，依次分配
    List<DeadlineTask> sortedDeadlines = ctx.getDeadlines().stream()
        .filter(t -> t.getCompletionRate() < 100f)
        .sorted(Comparator.comparing(DeadlineTask::getDeadline))
        .collect(Collectors.toList());
    
    int slotCursor = 0;
    for (DeadlineTask task : sortedDeadlines) {
        int remainingMinutes = (int)(task.getEstimatedMinutes() * (1 - task.getCompletionRate() / 100f));
        TimeSlot bestSlot = findBestAvailableSlot(ctx.getAvailableSlots(), slotCursor, 
            remainingMinutes, task.getSubject());
        
        TimeBlock block = TimeBlock.builder()
            .blockIndex(anchoredBlocks.size())
            .startTime(bestSlot.getStart())
            .endTime(bestSlot.getStart().plusMinutes(remainingMinutes))
            .durationMinutes(remainingMinutes)
            .subject(task.getSubject())
            .activityType(mapDeadlineToActivity(task.getType()))
            .reasonCode(AllocationReason.DEADLINE_URGENT)
            .mandatory(true)
            .build();
        anchoredBlocks.add(block);
        slotCursor = advanceCursor(slotCursor, bestSlot, remainingMinutes);
    }
    
    // 2. 逾期复习项按紧急度排序
    List<ReviewItem> overdueReviews = ctx.getDueReviews().stream()
        .filter(r -> r.getUrgency() >= 80f)  // 高紧急度
        .sorted(Comparator.comparing(ReviewItem::getUrgency).reversed())
        .collect(Collectors.toList());
    
    for (ReviewItem review : overdueReviews) {
        // 检查剩余可用时间
        int remainingTotal = calculateRemainingMinutes(ctx, anchoredBlocks);
        if (remainingTotal < review.getEstimatedMinutes()) break;
        
        TimeSlot slot = findBestAvailableSlot(ctx.getAvailableSlots(), slotCursor,
            review.getEstimatedMinutes(), review.getSubject());
        
        TimeBlock block = TimeBlock.builder()
            .blockIndex(anchoredBlocks.size())
            .startTime(slot.getStart())
            .endTime(slot.getStart().plusMinutes(review.getEstimatedMinutes()))
            .durationMinutes(review.getEstimatedMinutes())
            .subject(review.getSubject())
            .activityType(mapReviewToActivity(review.getType()))
            .reasonCode(AllocationReason.REVIEW_OVERDUE)
            .mandatory(true)
            .build();
        anchoredBlocks.add(block);
    }
    
    return anchoredBlocks;
}
```

#### 阶段二：学科均衡填充（Balanced Filling）

```java
/**
 * 阶段二：在必做项锚定后的剩余时间中，按学科均衡策略填充。
 * 使用贪心+局部搜索的混合策略。
 */
public List<TimeBlock> balancedFilling(DailyStudyContext ctx, 
                                        List<TimeBlock> anchoredBlocks) {
    int remainingMinutes = calculateRemainingMinutes(ctx, anchoredBlocks);
    if (remainingMinutes < 15) return List.of();
    
    // 计算各学科的时间需求评分
    Map<String, Double> subjectDemand = calculateSubjectDemand(ctx, anchoredBlocks);
    
    // 贪心分配：按需求×效率系数排序，逐个填充
    List<TimeBlock> fillBlocks = new ArrayList<>();
    int allocatedFromRemaining = 0;
    
    while (remainingMinutes - allocatedFromRemaining >= 15) {
        // 找到需求最高且未达单科上限的学科
        String bestSubject = findTopDemandSubject(subjectDemand, ctx, 
            anchoredBlocks, fillBlocks, remainingMinutes);
        if (bestSubject == null) break;
        
        // 决定活动类型
        ActivityType bestActivity = decideActivityType(bestSubject, ctx);
        
        // 决定时长（15-35min，基于活动类型和剩余时间）
        int blockMinutes = decideBlockDuration(bestActivity, 
            remainingMinutes - allocatedFromRemaining, ctx.getPreferences());
        
        // 找到最佳时段
        TimeSlot slot = findOptimalSlot(ctx.getAvailableSlots(), 
            anchoredBlocks, fillBlocks, bestSubject, bestActivity, blockMinutes);
        
        TimeBlock block = TimeBlock.builder()
            .blockIndex(anchoredBlocks.size() + fillBlocks.size())
            .startTime(slot.getStart())
            .endTime(slot.getStart().plusMinutes(blockMinutes))
            .durationMinutes(blockMinutes)
            .subject(bestSubject)
            .activityType(bestActivity)
            .reasonCode(decideReasonCode(bestSubject, bestActivity, ctx))
            .mandatory(false)
            .build();
        fillBlocks.add(block);
        allocatedFromRemaining += blockMinutes;
        
        // 更新需求评分（该学科需求降低）
        subjectDemand.merge(bestSubject, 
            -blockMinutes * DEMAND_DECAY_FACTOR, Double::sum);
    }
    
    return fillBlocks;
}

/**
 * 计算各学科时间需求评分（0~100）。
 * 综合考虑：掌握度水平、错题积压、距上次学习天数、考试临近度。
 */
private Map<String, Double> calculateSubjectDemand(
        DailyStudyContext ctx, List<TimeBlock> anchored) {
    
    Map<String, Double> demand = new HashMap<>();
    Map<String, Integer> alreadyAllocated = sumMinutesBySubject(anchored);
    int totalAvailable = ctx.getAvailableMinutes();
    
    for (SubjectState ss : ctx.getSubjectStates()) {
        double score = 0;
        
        // 掌握度越低，需求越高
        score += (100 - ss.getMasteryScore()) * 0.3;
        
        // 错题积压越多，需求越高
        score += Math.min(ss.getPendingErrorCount() * 3, 30);
        
        // 距上次学习越久，需求越高
        score += Math.min(ss.getDaysSinceLastStudy() * 5, 20);
        
        // 考试临近时需求急增
        if (ss.getDaysToNextExam() != null) {
            int days = ss.getDaysToNextExam();
            if (days <= 7) score += 40 * (1 - days / 7.0);
            else if (days <= 14) score += 20 * (1 - (days - 7) / 7.0);
        }
        
        // 近期学习量不足的需求增加
        double recentAvg = ss.getRecentStudyMinutes() / 7.0;
        double expectedDaily = totalAvailable * 0.2; // 期望每科约20%
        if (recentAvg < expectedDaily) {
            score += (expectedDaily - recentAvg) * 0.1;
        }
        
        // 减去已锚定分配的时间
        int already = alreadyAllocated.getOrDefault(ss.getSubject(), 0);
        score -= already * 0.5;
        
        // 用户偏好加权
        int prefIndex = ctx.getPreferences().getPreferredSubjectOrder()
            .indexOf(ss.getSubject());
        if (prefIndex >= 0) {
            score *= (1.0 + 0.1 * (ctx.getSubjectStates().size() - prefIndex) 
                / ctx.getSubjectStates().size());
        }
        
        // 根据优先策略调整
        score = applyPriorityStrategy(score, ss, ctx.getPreferences());
        
        demand.put(ss.getSubject(), Math.max(0, score));
    }
    return demand;
}
```

#### 阶段三：局部优化（Local Optimization）

```java
/**
 * 阶段三：对已生成的分配方案进行局部优化。
 * 通过邻域搜索提升目标函数值。
 */
public List<TimeBlock> localOptimize(List<TimeBlock> blocks, 
                                      DailyStudyContext ctx) {
    List<TimeBlock> current = new ArrayList<>(blocks);
    double currentScore = evaluateObjective(current, ctx);
    
    boolean improved = true;
    int iterations = 0;
    int maxIterations = 50; // 限制迭代次数保证响应速度
    
    while (improved && iterations++ < maxIterations) {
        improved = false;
        
        // 邻域操作1：交换相邻不同学科块的顺序
        for (int i = 0; i < current.size() - 1; i++) {
            if (!current.get(i).getSubject().equals(current.get(i + 1).getSubject())) {
                List<TimeBlock> candidate = swapBlocks(current, i, i + 1);
                double candidateScore = evaluateObjective(candidate, ctx);
                if (candidateScore > currentScore + EPSILON) {
                    current = candidate;
                    currentScore = candidateScore;
                    improved = true;
                }
            }
        }
        
        // 邻域操作2：从高活动量的学科移动时间到低活动量的学科
        Map<String, Integer> subjectMinutes = sumMinutesBySubject(current);
        String maxSubject = subjectMinutes.entrySet().stream()
            .max(Map.Entry.comparingByValue()).map(Map.Entry::getKey).orElse(null);
        String minSubject = subjectMinutes.entrySet().stream()
            .filter(e -> !e.getKey().equals(maxSubject))
            .min(Map.Entry.comparingByValue()).map(Map.Entry::getKey).orElse(null);
        
        if (maxSubject != null && minSubject != null) {
            int diff = subjectMinutes.get(maxSubject) - subjectMinutes.get(minSubject);
            if (diff > 30) { // 差距超过30分钟才调整
                List<TimeBlock> candidate = transferTime(current, maxSubject, 
                    minSubject, Math.min(diff / 4, 15));
                double candidateScore = evaluateObjective(candidate, ctx);
                if (candidateScore > currentScore + EPSILON) {
                    current = candidate;
                    currentScore = candidateScore;
                    improved = true;
                }
            }
        }
        
        // 邻域操作3：调整块时长（从效果低的块移到效果高的块）
        // 略，实现类似
    }
    
    return current;
}

private static final double EPSILON = 0.001;
```

### 4.3 目标函数评估

```java
/**
 * 评估一个时间分配方案的目标函数值。
 */
public double evaluateObjective(List<TimeBlock> blocks, DailyStudyContext ctx) {
    ScheduleMode mode = ctx.getScheduleMode();
    double[] weights = getWeights(mode);
    
    double urgency = evaluateUrgency(blocks, ctx);
    double mastery = evaluateMastery(blocks, ctx);
    double balance = evaluateBalance(blocks, ctx);
    double efficiency = evaluateEfficiency(blocks, ctx);
    double preference = evaluatePreference(blocks, ctx);
    
    return weights[0] * urgency 
         + weights[1] * mastery 
         + weights[2] * balance 
         + weights[3] * efficiency 
         + weights[4] * preference;
}

/**
 * 均衡度评估：使用 Shannon 熵衡量学科分配的均匀程度。
 * 熵越高 = 分配越均匀 = 均衡度越好。
 */
private double evaluateBalance(List<TimeBlock> blocks, DailyStudyContext ctx) {
    Map<String, Integer> subjectMinutes = sumMinutesBySubject(blocks);
    int total = subjectMinutes.values().stream().mapToInt(Integer::intValue).sum();
    if (total == 0) return 0;
    
    double entropy = 0;
    for (int minutes : subjectMinutes.values()) {
        double p = (double) minutes / total;
        if (p > 0) entropy -= p * Math.log(p);
    }
    
    // 归一化到 0~100
    int numSubjects = subjectMinutes.size();
    double maxEntropy = Math.log(numSubjects);
    return numSubjects > 1 ? (entropy / maxEntropy) * 100 : 50;
}

/**
 * 效率评估：活动类型与时段精力系数的匹配度。
 */
private double evaluateEfficiency(List<TimeBlock> blocks, DailyStudyContext ctx) {
    double totalScore = 0;
    int totalMinutes = 0;
    
    for (TimeBlock block : blocks) {
        float energyFactor = getEnergyFactor(block.getStartTime(), ctx.getStudent());
        int difficulty = getActivityDifficulty(block.getActivityType());
        
        // 高难度活动在高精力时段得分高
        double matchScore = energyFactor * (difficulty / 5.0) * 100;
        totalScore += matchScore * block.getDurationMinutes();
        totalMinutes += block.getDurationMinutes();
    }
    
    return totalMinutes > 0 ? totalScore / totalMinutes : 0;
}

private int getActivityDifficulty(ActivityType type) {
    return switch (type) {
        case EXAM_SIMULATION -> 5;
        case NEW_LEARNING -> 4;
        case PRACTICE -> 3;
        case ERROR_CORRECTION -> 3;
        case REVIEW -> 2;
        case MEMORIZATION -> 2;
        case LIGHT_TASK -> 1;
    };
}
```

```java
@Component
public class AllocationEventHandler {
    
    @Autowired
    private AllocationEngine engine;
    @Autowired
    private PlanCacheService cache;
    
    @EventListener
    @Async("allocationExecutor")
    public void onAnswerSubmitted(AnswerSubmittedEvent event) {
        // 1. 检查冷却期
        if (cache.isInCooldown(event.getStudentId(), LocalDate.now())) {
            return;
        }
        
        // 2. 更新执行进度
        cache.updateBlockProgress(event.getStudentId(), LocalDate.now(),
            event.getBlockIndex(), "COMPLETED", event.getActualMinutes());
        
        // 3. 增量重计算剩余时间块
        if (event.shouldRecalculate()) {
            engine.recalculateRemaining(event.getStudentId(), LocalDate.now(),
                event.getBlockIndex(), event.getActualMinutes());
        }
        
        // 4. 设置冷却
        cache.setCooldown(event.getStudentId(), LocalDate.now(), 
            RECOUND_COOLDOWN_SECONDS);
    }

    @Async("allocationExecutor")

            event.getSubject(), event.getKnowledgePointId(),
            event.getEstimatedMinutes());

        // 批量预生成新一天的分配方案
        engine.batchPregenerateForActiveUsers(LocalDate.now().plusDays(1));
    }
```

### 8.3 解释生成流程

```java
@Service
public class ExplanationGenerator {
    
    @Autowired
    private ExplanationTemplateRegistry registry;
    
    public List<AllocationExplanation> generate(List<TimeBlock> blocks, 
                                                  DailyStudyContext ctx) {
        List<AllocationExplanation> explanations = new ArrayList<>();
        
        for (TimeBlock block : blocks) {
            ExplanationTemplate template = registry.get(block.getReasonCode());
            Map<String, Object> variables = collectVariables(block, ctx);
            
            String userMsg = template.renderUser(variables);
            String parentMsg = template.renderParent(variables);
            Map<String, Object> evidence = extractEvidence(block, ctx);
            int priority = calculateDisplayPriority(block);
            
            explanations.add(AllocationExplanation.builder()
                .blockIndex(block.getBlockIndex())
                .userMessage(userMsg)
                .parentMessage(parentMsg)
                .evidence(evidence)
                .displayPriority(priority)
                .build());
        }
        
        // 按显示优先级排序
        explanations.sort(Comparator.comparing(AllocationExplanation::getDisplayPriority));
        return explanations;
    }
    
    private Map<String, Object> collectVariables(TimeBlock block, DailyStudyContext ctx) {
        Map<String, Object> vars = new HashMap<>();
        vars.put("subject", subjectDisplayName(block.getSubject()));
        vars.put("activityName", activityDisplayName(block.getActivityType()));
        
        // 从学科状态中提取数据
        SubjectState ss = findSubjectState(ctx, block.getSubject());
        if (ss != null) {
            vars.put("masteryScore", formatDecimal(ss.getMasteryScore(), 0));
            vars.put("chapterProgress", formatDecimal(ss.getChapterProgress(), 0));
            vars.put("pendingErrorCount", ss.getPendingErrorCount());
            vars.put("daysSinceLastStudy", ss.getDaysSinceLastStudy());
            if (ss.getDaysToNextExam() != null) {
                vars.put("daysToExam", ss.getDaysToNextExam());
            }
        }
        
        // 从复习项中提取
        List<ReviewItem> blockReviews = filterReviewsForBlock(ctx, block);
        if (!blockReviews.isEmpty()) {
            vars.put("overdueCount", blockReviews.size());
            vars.put("maxOverdueDays", blockReviews.stream()
                .mapToDouble(r -> r.getUrgency() / 40f) // 近似换算
                .max().orElse(0));
        }
        
        return vars;
    }
}
```

```java
public class TimeOptimizer {
    
    private static final long OPTIMIZE_TIMEOUT_MS = 180;
    
    public List<TimeBlock> optimize(DailyStudyContext ctx) {
        long deadline = System.currentTimeMillis() + OPTIMIZE_TIMEOUT_MS;
        
        // 阶段一：必做项锚定（总是执行）
        List<TimeBlock> anchored = anchorMustDoItems(ctx);
        
        // 阶段二：均衡填充（总是执行）
        List<TimeBlock> filled = balancedFilling(ctx, anchored, deadline);
        
        List<TimeBlock> result = new ArrayList<>();
        result.addAll(anchored);
        result.addAll(filled);
        
        // 阶段三：局部优化（时间允许时执行）
        long remaining = deadline - System.currentTimeMillis();
        if (remaining > 50) {
            int maxIter = (int) Math.min(50, remaining / 5);
            result = localOptimize(result, ctx, maxIter);
        }
        
        return result;
    }
}
```

```java
/**
 * 新用户或数据不足时的冷启动分配策略。
 */
public List<TimeBlock> coldStartAllocation(DailyStudyContext ctx) {
    List<TimeBlock> blocks = new ArrayList<>();
    int remaining = ctx.getAvailableMinutes();
    
    // 策略：已订阅学科均分，首选复习/练习
    int numSubjects = ctx.getStudent().getSubscribedSubjects().size();
    int perSubject = Math.min(remaining / numSubjects, 30);
    
    LocalTime cursor = ctx.getAvailableSlots().get(0).getStart();
    int idx = 0;
    
    for (String subject : ctx.getStudent().getSubscribedSubjects()) {
        if (remaining < 15) break;
        
        int duration = Math.min(perSubject, remaining);
        blocks.add(TimeBlock.builder()
            .blockIndex(idx++)
            .startTime(cursor)
            .endTime(cursor.plusMinutes(duration))
            .durationMinutes(duration)
            .subject(subject)
            .activityType(ActivityType.REVIEW)  // 冷启动默认复习
            .reasonCode(AllocationReason.BALANCED_DISTRIBUTION)
            .mandatory(false)
            .build());
        
        cursor = cursor.plusMinutes(duration + 5); // 5分钟休息
        remaining -= duration + 5;
    }
    
    return blocks;
}
```

### 11.1 性能指标

| 解释生成 | ≤ 20ms |
| 缓存命中查询 | ≤ 10ms |

### 11.2 性能优化措施

1. **方案缓存**：当日方案生成后缓存到 Redis，后续查询直接命中缓存。
2. **增量重计算**：事件触发的重计算仅影响变化部分，不全量重算。
3. **预生成**：每天凌晨批量预生成活跃用户的当日方案，减少实时计算压力。
4. **并行上下文收集**：多个下游服务调用并行化。

```java
@Component
public class ContextCollector {
    
    @Autowired
    private SubjectStateFetcher subjectFetcher;
    @Autowired
    private ReviewItemFetcher reviewFetcher;
    @Autowired
    private DeadlineTaskFetcher deadlineFetcher;
    @Autowired

        Executors.newFixedThreadPool(8,

        StudentBasics basics = studentService.getBasics(studentId); // 同步

            CompletableFuture.supplyAsync(() -> subjectFetcher.fetch(studentId), parallelExecutor);
        CompletableFuture<List<ReviewItem>> reviewsFuture = 
            CompletableFuture.supplyAsync(() -> reviewFetcher.fetch(studentId, date), parallelExecutor);
        CompletableFuture<List<DeadlineTask>> deadlinesFuture = 
            CompletableFuture.supplyAsync(() -> deadlineFetcher.fetch(studentId, date), parallelExecutor);
        CompletableFuture<RecentHistory> historyFuture = 
            CompletableFuture.supplyAsync(() -> historyFetcher.fetch(studentId, date), parallelExecutor);
        
        CompletableFuture.allOf(statesFuture, reviewsFuture, 
            deadlinesFuture, historyFuture).join();
        
        return DailyStudyContext.builder()
            .studentId(studentId)
            .date(date)
            .student(basics)
            .subjectStates(statesFuture.join())
            .dueReviews(reviewsFuture.join())
            .deadlines(deadlinesFuture.join())
            .recentHistory(historyFuture.join())
            // ... 其他字段
            .build();
    }
}
```

```java
/**
 * 计算两个时间块之间需要的休息时间（分钟）。
 */
public int calculateBreakMinutes(TimeBlock prev, TimeBlock next) {
    // 不同学科切换：至少5分钟
    if (!prev.getSubject().equals(next.getSubject())) {
        return 5;
    }
    
    // 同学科连续：根据已连续学习时长递增
    int consecutiveMinutes = prev.getDurationMinutes();
    if (consecutiveMinutes >= 40) return 10;
    if (consecutiveMinutes >= 25) return 5;
    return 3;
}
```

```gherkin
    And 数学科目应包含错题复习块
    And 单科时长不超过48分钟（40%上限）
    And 总分配时间不超过120分钟

  Scenario: 考试周模式
    Given 学生高一，物理3天后考试
    And 今日可用时间150分钟
    And schedule_mode为EXAM_WEEK
    When 请求获取今日分配方案
    Then 物理占比应 ≥ 40%
    And 物理占比应 ≤ 82分钟（55%上限）
    And 包含物理考前复习块

  Scenario: 完成任务后触发重计算
    Given 学生有一个5个时间块的活跃方案
    When 第0块完成，实际耗时比计划少10分钟
    Then 剩余块应重新分配这10分钟
    And 方案version+1
    And 重计算在100ms内完成

  Scenario: 下游服务降级
    Given 知识追踪服务不可用
    When 请求获取分配方案
    Then 方案应使用缓存掌握度数据
    And response header 包含 degraded=true

  Scenario: 冷启动
    Given 新注册学生，无学习历史
    When 请求获取分配方案
    Then 应返回均分方案
    And 各学科时间块时长相近
    And effectiveness_score < 70
```
