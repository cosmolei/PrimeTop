# 服务端-订阅续费预警与自动续费失败补偿调度引擎 — 详细设计

> 版本：v1.0 | 创建日期：2026-06-23 | 状态：草案

---

## 1. 模块概述

### 1.1 背景

PrimeTop 采用 Freemium + 会员订阅商业模式，支持月度会员、年度会员、中高考专项会员等多种订阅类型。用户通过 Apple IAP、Google Play Billing、微信支付、支付宝等多渠道完成订阅购买后，系统需要持续管理订阅的完整生命周期——从续费预警、自动扣款、失败重试、宽限期管理、权益降级到流失挽回。

当前的「支付与会员订阅模块」定义了订阅基础结构和权益矩阵，「应用内购与商店支付集成层」封装了多渠道支付 SDK 与票据验证。但两者均未覆盖**订阅续费阶段的调度编排与失败补偿逻辑**——这是决定订阅业务收入留存率的关键引擎。

### 1.2 设计目标

1. **续费最大化**：在用户知情且合规的前提下，最大化自动续费成功率，减少非自愿流失。
2. **平台合规**：严格遵循 Apple App Store、Google Play 对自动续期订阅的管理规范。
3. **用户体验**：续费过程透明无感，失败时提供清晰的恢复路径，避免突然中断服务。
4. **数据驱动**：通过多维度分析持续优化续费提醒时机、重试策略和挽回方案。
5. **幂等可靠**：所有调度任务和消息处理支持幂等，避免重复扣款或状态错乱。

### 1.5 术语定义

| 术语 | 说明 |
|------|------|
| 订阅周期 | 一次订阅购买覆盖的有效期，如 30 天（月度）、365 天（年度） |
| 续费窗口 | 订阅到期前可执行自动续费的时间范围 |
| 宽限期 | 扣款失败后仍保留会员权益的缓冲期 |
| 计费重试期 | 宽限期之后、正式过期之前，商店端仍在尝试扣款的期间 |
| Dunning | 针对失败扣款的一系列重试和通知策略 |
| 非自愿流失 | 用户有意愿继续使用但因支付失败导致的订阅过期 |
| 自愿流失 | 用户主动取消订阅导致的过期 |
| Win-back | 针对已流失用户的重新触达和转化策略 |

## 3. 订阅状态机设计

### 3.1 状态定义

| 状态 | 标识 | 说明 |
|------|------|------|
| 活跃 | `ACTIVE` | 订阅有效，用户享有完整权益 |
| 待续费 | `PENDING_RENEWAL` | 即将到期，进入续费预警窗口 |
| 续费中 | `RENEWING` | 正在执行自动续费扣款 |
| 宽限期 | `GRACE_PERIOD` | 扣款失败，但仍保留权益的缓冲期 |
| 计费重试中 | `BILLING_RETRY` | 宽限期结束，商店端仍在重试扣款，权益降级 |
| 已过期 | `EXPIRED` | 订阅正式结束，权益已终止 |
| 已取消 | `CANCELED` | 用户主动取消（当前周期仍有效） |
| 已退款 | `REFUNDED` | 订阅已退款，权益立即终止 |

### 3.3 状态机引擎核心代码

```java
/**
 * 订阅状态机引擎
 * 负责所有订阅状态流转的统一控制，确保状态变更合法、可追溯
 */
@Component
@Slf4j
public class SubscriptionStateMachine {

    @Resource
    private SubscriptionRecordMapper subscriptionMapper;
    @Resource
    private SubscriptionEventService eventService;
    @Resource
    private MembershipEntitlementService entitlementService;
    
    /**
     * 状态转移规则定义
     */
    private static final Map<SubscriptionStatus, Set<SubscriptionStatus>> TRANSITIONS = Map.of(
        SubscriptionStatus.ACTIVE, EnumSet.of(
            SubscriptionStatus.PENDING_RENEWAL,
            SubscriptionStatus.CANCELED,
            SubscriptionStatus.REFUNDED
        ),
        SubscriptionStatus.PENDING_RENEWAL, EnumSet.of(
            SubscriptionStatus.RENEWING,
            SubscriptionStatus.ACTIVE,        // 用户手动续费成功
            SubscriptionStatus.CANCELED,
            SubscriptionStatus.REFUNDED
        ),
        SubscriptionStatus.RENEWING, EnumSet.of(
            SubscriptionStatus.ACTIVE,         // 续费成功
            SubscriptionStatus.GRACE_PERIOD,   // 续费失败，进入宽限期
            SubscriptionStatus.REFUNDED
        ),
        SubscriptionStatus.GRACE_PERIOD, EnumSet.of(
            SubscriptionStatus.ACTIVE,         // 宽限期内续费成功
            SubscriptionStatus.BILLING_RETRY,  // 宽限期结束
            SubscriptionStatus.REFUNDED
        ),
        SubscriptionStatus.BILLING_RETRY, EnumSet.of(
            SubscriptionStatus.ACTIVE,         // 重试成功
            SubscriptionStatus.EXPIRED,        // 重试彻底失败
            SubscriptionStatus.GRACE_PERIOD,   // 平台通知恢复宽限
            SubscriptionStatus.REFUNDED
        ),
        SubscriptionStatus.CANCELED, EnumSet.of(
            SubscriptionStatus.EXPIRED,        // 取消后周期结束
            SubscriptionStatus.ACTIVE,         // 用户恢复订阅
            SubscriptionStatus.REFUNDED
        ),
        SubscriptionStatus.EXPIRED, EnumSet.of(
            SubscriptionStatus.ACTIVE          // 重新购买
        )
    );

    /**
     * 执行状态转移
     */
    @Transactional(rollbackFor = Exception.class)
    public SubscriptionRecord transition(String subscriptionId, 
                                          SubscriptionStatus targetStatus,
                                          SubscriptionEventContext ctx) {
        // 1. 查询当前订阅
        SubscriptionRecord sub = subscriptionMapper.findBySubscriptionId(subscriptionId);
        if (sub == null) {
            throw new BusinessException(ErrorCode.SUBSCRIPTION_NOT_FOUND, subscriptionId);
        }
        
        SubscriptionStatus fromStatus = sub.getStatus();
        
        // 2. 校验状态转移合法性
        if (!isValidTransition(fromStatus, targetStatus)) {
            log.error("非法状态转移: {} -> {}, subscriptionId={}", 
                      fromStatus, targetStatus, subscriptionId);
            throw new BusinessException(ErrorCode.INVALID_STATUS_TRANSITION,
                String.format("%s -> %s", fromStatus, targetStatus));
        }
        
        // 3. 乐观锁更新状态
        int updated = subscriptionMapper.updateStatusWithVersion(
            subscriptionId, targetStatus, fromStatus, sub.getVersion());
        if (updated == 0) {
            throw new BusinessException(ErrorCode.CONCURRENT_MODIFICATION,
                "订阅状态已被其他事务修改，请重试");
        }
        
        // 4. 记录事件流水
        eventService.recordEvent(SubscriptionEvent.builder()
            .subscriptionId(subscriptionId)
            .userId(sub.getUserId())
            .eventType(ctx.getEventType())
            .eventSource(ctx.getSource())
            .fromStatus(fromStatus)
            .toStatus(targetStatus)
            .relatedOrderId(ctx.getOrderId())
            .rawPayload(ctx.getRawPayload())
            .errorCode(ctx.getErrorCode())
            .errorMessage(ctx.getErrorMessage())
            .build());
        
        // 5. 触发后置动作
        handlePostTransition(sub, fromStatus, targetStatus, ctx);
        
        return sub;
    }
    
    private boolean isValidTransition(SubscriptionStatus from, SubscriptionStatus to) {
        Set<SubscriptionStatus> allowed = TRANSITIONS.get(from);
        return allowed != null && allowed.contains(to);
    }
    
    /**
     * 状态变更后的联动处理
     */
    private void handlePostTransition(SubscriptionRecord sub,
                                       SubscriptionStatus from,
                                       SubscriptionStatus to,
                                       SubscriptionEventContext ctx) {
        switch (to) {
            case ACTIVE:
                // 恢复/赋予完整权益
                entitlementService.grantFullEntitlements(sub.getUserId(), sub.getPlanCode());
                break;
                
            case GRACE_PERIOD:
                // 保持权益但标记警告状态
                entitlementService.markWarningState(sub.getUserId());
                break;
                
            case BILLING_RETRY:
                // 降级为受限访问模式
                entitlementService.downgradeToLimited(sub.getUserId());
                break;
                
            case EXPIRED:
            case REFUNDED:
                // 撤销会员权益，恢复为免费用户
                entitlementService.revokeToFree(sub.getUserId());
                break;
                
            case CANCELED:
                // 标记取消但保持当前周期权益
                entitlementService.markCanceledButActive(
                    sub.getUserId(), sub.getCurrentPeriodEnd());
                break;
                
            default:
                break;
        }
    }
}
```

## 4. 续费预警调度

### 4.1 预警时间线

| 触发时间 | 通知类型 | 渠道 | 内容重点 | 备注 |
|----------|----------|------|----------|------|
| 到期前 72h | 友好提醒 | APP推送 | "您的{plan}会员将于{date}自动续费{amount}" | 仅自动续费用户 |
| 到期前 24h | 确认提醒 | APP推送+站内信 | "明日将自动续费，如需取消请点击此处" | 包含取消链接 |
| 到期前 1h | 最后提醒 | 无 | 静默检查 | 仅日志记录，不打扰用户 |
| 到期时 | 续费结果 | 视结果而定 | 成功通知 / 失败通知 | 见§5 |
| 到期后+宽限期开始 | 失败通知 | APP推送+短信 | "续费失败，请更新支付方式" | 见§6 |

```java
/**
 * 续费预警调度器
 * 定时扫描即将到期的订阅，生成预警通知任务
 */
@Component
@Slf4j
public class RenewalReminderScheduler {

    @Resource
    private SubscriptionRecordMapper subscriptionMapper;
    @Resource
    private NotificationService notificationService;
    @Resource
    private SubscriptionStateMachine stateMachine;
    
    /**
     * 每30分钟扫描一次即将到期的订阅
     * 处理到期前72h和24h的预警通知
     */
    @Scheduled(fixedDelay = 30 * 60 * 1000)
    public void scheduleReminders() {
        LocalDateTime now = LocalDateTime.now();
        
        // 72小时预警
        LocalDateTime target72h = now.plusHours(72);
        processReminderBatch(now, target72h, 72, "RENEWAL_REMINDER_72H");
        
        // 24小时预警
        LocalDateTime target24h = now.plusHours(24);
        processReminderBatch(now, target24h, 24, "RENEWAL_REMINDER_24H");
    }
    
    private void processReminderBatch(LocalDateTime windowStart, 
                                       LocalDateTime windowEnd,
                                       int hoursBefore,
                                       String reminderType) {
        // 查询：ACTIVE状态 + auto_renew=1 + 到期时间在窗口内 + 未发过该类型通知
        List<SubscriptionRecord> pending = subscriptionMapper.findSubscriptionsForReminder(
            SubscriptionStatus.ACTIVE,
            true,
            windowStart,
            windowEnd,
            reminderType  // 通过metadata中的已发送标记排除
        );
        
        log.info("处理{}预警: 命中{}条订阅", reminderType, pending.size());
        
        for (SubscriptionRecord sub : pending) {
            try {
                sendRenewalReminder(sub, hoursBefore);
            } catch (Exception e) {
                log.error("发送续费预警失败: subscriptionId={}", 
                    sub.getSubscriptionId(), e);
            }
        }
    }
    
    private void sendRenewalReminder(SubscriptionRecord sub, int hoursBefore) {
        String planName = PlanCode.valueOf(sub.getPlanCode()).getDisplayName();
        
        NotificationMessage msg = NotificationMessage.builder()
            .userId(sub.getUserId())
            .title(hoursBefore >= 72 ? "会员续费提醒" : "明日续费提醒")
            .content(String.format(
                "您的%s会员将于%s到期，届时将自动续费%s元。" +
                "如需管理订阅，请前往「我的-会员中心」。",
                planName,
                sub.getCurrentPeriodEnd().toLocalDate(),
                sub.getAmountCents() / 100.0))
            .type(hoursBefore >= 72 ? "renewal_reminder_friendly" : "renewal_reminder_urgent")
            .actionUrl("/my/membership")
            .build();
        
        notificationService.send(msg);
        
        // 标记已发送该类型通知（写入metadata防重）
        subscriptionMapper.markReminderSent(
            sub.getSubscriptionId(), reminderType, LocalDateTime.now());
    }
}
```

## 5. 平台通知处理器

### 5.1 Apple App Store Server Notifications V2

Apple 通过 App Store Server Notifications V2 向服务端推送订阅状态变更通知。本模块负责接收、解析和路由这些通知。

#### 5.1.1 通知类型映射

| Apple notificationType | subType | 系统动作 |
|------------------------|----------|--------|
| `DID_RENEW` | - | 续费成功 → 状态转为 ACTIVE |
| `DID_FAIL_TO_RENEW` | `GRACE_PERIOD` | 进入宽限期 → 状态转为 GRACE_PERIOD |
| `DID_FAIL_TO_RENEW` | `RETRY` | 商店重试中 → 保持 BILLING_RETRY |
| `EXPIRED` | - | 正式过期 → 状态转为 EXPIRED |
| `CANCEL` | - | 用户/Apple取消 → 状态转为 CANCELED |
| `GRACE_PERIOD_EXPIRED` | - | 宽限期结束 → 状态转为 BILLING_RETRY |
| `PRICE_INCREASE` | `ACCEPTED`/`PENDING` | 价格变更通知，记录但不改状态 |
| `REFUND` | - | 已退款 → 状态转为 REFUNDED |
| `REVOKE` | - | 家庭共享撤销 → 撤销权益 |

#### 5.1.2 Apple 通知处理核心代码

```java
/**
 * Apple App Store Server Notifications V2 处理器
 */
@Component
@Slf4j
public class AppleServerNotificationHandler {

    @Resource
    private AppleJwsVerifier jwsVerifier;  // JWS签名验证
    @Resource
    private SubscriptionStateMachine stateMachine;
    @Resource
    private OrderService orderService;
    @Resource
    private SubscriptionEventService eventService;

    /**
     * 处理 Apple 通知
     * @param signedPayload Apple发送的JWS签名payload
     */
    public void handleNotification(String signedPayload) {
        // 1. 验证JWS签名（防伪造）
        DecodedNotification decoded = jwsVerifier.verifyAndDecode(signedPayload);
        if (decoded == null) {
            log.warn("Apple通知JWS验证失败，丢弃");
            return;
        }

        // 2. 幂等检查（Apple可能重复发送同一通知）
        String transactionId = decoded.getData().getSignedTransactionInfo()
            .getTransactionId();
        String notificationUUID = decoded.getNotificationUUID();
        
        if (eventService.isDuplicateNotification(notificationUUID)) {
            log.info("Apple通知已处理过(幂等跳过): uuid={}", notificationUUID);
            return;
        }

        // 3. 查找对应订阅
        String originalTxnId = decoded.getData().getSignedTransactionInfo()
            .getOriginalTransactionId();
        SubscriptionRecord sub = subscriptionMapper.findByStoreTxnId(originalTxnId);
        if (sub == null) {
            log.error("Apple通知找不到对应订阅: originalTxnId={}", originalTxnId);
            return;
        }

        // 4. 按通知类型路由处理
        String notifType = decoded.getNotificationType();
        String subType = decoded.getSubtype();
        
        AppleNotificationContext ctx = AppleNotificationContext.from(decoded);
        
        switch (notifType) {
            case "DID_RENEW":
                handleDidRenew(sub, ctx);
                break;
            case "DID_FAIL_TO_RENEW":
                handleDidFailToRenew(sub, subType, ctx);
                break;
            case "EXPIRED":
                handleExpired(sub, ctx);
                break;
            case "CANCEL":
                handleCancel(sub, ctx);
                break;
            case "GRACE_PERIOD_EXPIRED":
                handleGracePeriodExpired(sub, ctx);
                break;
            case "REFUND":
                handleRefund(sub, ctx);
                break;
            default:
                log.info("未处理的Apple通知类型: {} subtype={}", notifType, subType);
        }
    }

    private void handleDidRenew(SubscriptionRecord sub, AppleNotificationContext ctx) {
        // 续费成功：续扣下一周期
        LocalDateTime newPeriodStart = ctx.getRevocationDate() != null ? 
            ctx.getRevocationDate() : sub.getCurrentPeriodEnd();
        LocalDateTime newPeriodEnd = newPeriodStart.plus(
            PlanCode.valueOf(sub.getPlanCode()).getDuration());
        
        subscriptionMapper.updatePeriod(
            sub.getSubscriptionId(), newPeriodStart, newPeriodEnd);
        
        stateMachine.transition(sub.getSubscriptionId(), 
            SubscriptionStatus.ACTIVE,
            SubscriptionEventContext.builder()
                .eventType(SubscriptionEventType.AUTO_RENEWAL_SUCCESS)
                .source("platform")
                .orderId(ctx.getOrderId())
                .rawPayload(ctx.getRawPayload())
                .build());
        
        log.info("Apple续费成功: sub={}, newPeriodEnd={}", 
            sub.getSubscriptionId(), newPeriodEnd);
    }

    private void handleDidFailToRenew(SubscriptionRecord sub, String subType,
                                       AppleNotificationContext ctx) {
        if ("GRACE_PERIOD".equals(subType)) {
            // 进入Apple宽限期（Apple在尝试扣款但失败，给予宽限）
            LocalDateTime graceEnd = ctx.getGracePeriodExpiresDate();
            subscriptionMapper.updateGracePeriod(
                sub.getSubscriptionId(), graceEnd);
            
            stateMachine.transition(sub.getSubscriptionId(),
                SubscriptionStatus.GRACE_PERIOD,
                SubscriptionEventContext.builder()
                    .eventType(SubscriptionEventType.GRACE_PERIOD_STARTED)
                    .source("platform")
                    .rawPayload(ctx.getRawPayload())
                    .build());
            
            // 发送支付失败通知
            sendPaymentFailedNotification(sub);
            
        } else if ("RETRY".equals(subType)) {
            // Apple仍在重试中
            stateMachine.transition(sub.getSubscriptionId(),
                SubscriptionStatus.BILLING_RETRY,
                SubscriptionEventContext.builder()
                    .eventType(SubscriptionEventType.DUNNING_RETRY_FAILED)
                    .source("platform")
                    .rawPayload(ctx.getRawPayload())
                    .build());
        }
    }

    private void handleGracePeriodExpired(SubscriptionRecord sub,
                                           AppleNotificationContext ctx) {
        stateMachine.transition(sub.getSubscriptionId(),
            SubscriptionStatus.BILLING_RETRY,
            SubscriptionEventContext.builder()
                .eventType(SubscriptionEventType.GRACE_PERIOD_EXPIRED)
                .source("platform")
                .rawPayload(ctx.getRawPayload())
                .build());
    }

    private void handleExpired(SubscriptionRecord sub, AppleNotificationContext ctx) {
        stateMachine.transition(sub.getSubscriptionId(),
            SubscriptionStatus.EXPIRED,
            SubscriptionEventContext.builder()
                .eventType(SubscriptionEventType.SYSTEM_EXPIRED)
                .source("platform")
                .rawPayload(ctx.getRawPayload())
                .build());
        
        // 触发流失用户挽回流程
        winbackService.scheduleWinbackSequence(sub);
    }
}
```

### 5.2 Google Play RTDN 处理

Google Play 通过 Pub/Sub 推送 Real-Time Developer Notifications（RTDN）。

#### 5.2.1 通知类型映射

| Google eventType | 系统动作 |
|-----------------|--------|
| `SUBSCRIPTION_RENEWED` | 续费成功 → ACTIVE |
| `SUBSCRIPTION_ON_HOLD` | 暂停（扣款失败）→ GRACE_PERIOD |
| `SUBSCRIPTION_IN_GRACE_PERIOD` | Google宽限期 → GRACE_PERIOD |
| `SUBSCRIPTION_RECOVERED` | 从暂停恢复 → ACTIVE |
| `SUBSCRIPTION_EXPIRED` | 正式过期 → EXPIRED |
| `SUBSCRIPTION_REVOKED` | 用户撤销 → CANCELED |
| `SUBSCRIPTION_CANCELED` | 用户取消 → CANCELED（当前周期仍有效） |
| `SUBSCRIPTION_PAUSED` | 用户暂停 → 记录但不改状态 |

```java
/**
 * Google Play RTDN 处理器
 */
@Component
@Slf4j
public class GoogleRtdnHandler {

    /**
     * 处理 Google Pub/Sub 消息
     */
    public void handleRtdn(PubsubMessage message) {
        String data = new String(message.getData().toByteArray(), StandardCharsets.UTF_8);
        GoogleDeveloperNotification notification = parseAndVerify(data);
        
        String purchaseToken = notification.getSubscriptionNotification().getPurchaseToken();
        SubscriptionRecord sub = subscriptionMapper.findByStoreTxnId(purchaseToken);
        if (sub == null) {
            log.error("Google RTDN找不到对应订阅: purchaseToken={}", purchaseToken);
            return;
        }
        
        // 通过 Google Developer API 查询最新订阅状态（以API为准）
        SubscriptionPurchaseV2 purchase = googlePlayApiService
            .getSubscriptionPurchase(purchaseToken);
        
        syncSubscriptionFromGoogle(sub, purchase);
        
        String eventType = notification.getSubscriptionNotification().getNotificationType();
        handleGoogleEvent(sub, eventType, purchase);
    }
    
    private void handleGoogleEvent(SubscriptionRecord sub, String eventType,
                                    SubscriptionPurchaseV2 purchase) {
        switch (eventType) {
            case 1: // SUBSCRIPTION_RECOVERED
            case 2: // SUBSCRIPTION_RENEWED
                stateMachine.transition(sub.getSubscriptionId(),
                    SubscriptionStatus.ACTIVE,
                    SubscriptionEventContext.builder()
                        .eventType(SubscriptionEventType.AUTO_RENEWAL_SUCCESS)
                        .source("platform")
                        .build());
                break;
            case 3: // SUBSCRIPTION_CANCELED
                stateMachine.transition(sub.getSubscriptionId(),
                    SubscriptionStatus.CANCELED,
                    SubscriptionEventContext.builder()
                        .eventType(SubscriptionEventType.USER_CANCELED)
                        .source("platform")
                        .build());
                break;
            case 4: // SUBSCRIPTION_ON_HOLD
                stateMachine.transition(sub.getSubscriptionId(),
                    SubscriptionStatus.GRACE_PERIOD,
                    SubscriptionEventContext.builder()
                        .eventType(SubscriptionEventType.GRACE_PERIOD_STARTED)
                        .source("platform")
                        .build());
                sendPaymentFailedNotification(sub);
                break;
            case 5: // SUBSCRIPTION_IN_GRACE_PERIOD
                stateMachine.transition(sub.getSubscriptionId(),
                    SubscriptionStatus.GRACE_PERIOD,
                    SubscriptionEventContext.builder()
                        .eventType(SubscriptionEventType.GRACE_PERIOD_STARTED)
                        .source("platform")
                        .build());
                break;
            case 6: // SUBSCRIPTION_EXPIRED
                stateMachine.transition(sub.getSubscriptionId(),
                    SubscriptionStatus.EXPIRED,
                    SubscriptionEventContext.builder()
                        .eventType(SubscriptionEventType.SYSTEM_EXPIRED)
                        .source("platform")
                        .build());
                winbackService.scheduleWinbackSequence(sub);
                break;
            default:
                log.info("未处理的Google通知类型: {}", eventType);
        }
    }
}
```

### 5.3 微信/支付宝周期扣款处理

对于通过微信支付、支付宝订阅的国内 Android 用户，自动续费由本系统主动发起扣款请求（非商店驱动）。

```java
/**
 * 第三方支付自动续费执行器
 * 每小时扫描到期订阅，主动发起扣款
 */
@Component
@Slf4j
public class ThirdPartyAutoRenewalExecutor {

    @Resource
    private WeChatPayService weChatPayService;
    @Resource
    private AlipayService alipayService;
    @Resource
    private SubscriptionStateMachine stateMachine;
    @Resource
    private DunningService dunningService;

    @Scheduled(fixedDelay = 60 * 60 * 1000)  // 每小时
    public void executeAutoRenewals() {
        LocalDateTime now = LocalDateTime.now();
        LocalDateTime window = now.plusHours(2);  // 提前2小时窗口
        
        // 查找即将到期、auto_renew=1、且非商店渠道的订阅
        List<SubscriptionRecord> due = subscriptionMapper.findDueForThirdPartyRenewal(
            SubscriptionStatus.ACTIVE, true, 
            Arrays.asList("wechat", "alipay"),
            now, window);
        
        for (SubscriptionRecord sub : due) {
            try {
                // 先转为续费中状态
                stateMachine.transition(sub.getSubscriptionId(),
                    SubscriptionStatus.RENEWING,
                    SubscriptionEventContext.builder()
                        .eventType(SubscriptionEventType.AUTO_RENEWAL_FAILED)
                        .source("scheduler")
                        .build());
                
                boolean success = executeRenewalPayment(sub);
                
                if (success) {
                    handleRenewalSuccess(sub);
                } else {
                    // 扣款失败，启动 Dunning 流程
                    dunningService.startDunningCampaign(sub);
                }
            } catch (Exception e) {
                log.error("第三方续费执行异常: subId={}", sub.getSubscriptionId(), e);
            }
        }
    }

    private boolean executeRenewalPayment(SubscriptionRecord sub) {
        int amountCents = PlanCode.valueOf(sub.getPlanCode()).getPriceCents();
        String agreementId = sub.getMetadata().getString("agreement_id");
        
        try {
            switch (sub.getChannel()) {
                case "wechat":
                    WeChatPayResult result = weChatPayService
                        .autoDeduct(agreementId, amountCents, 
                            "PrimeTop_" + sub.getPlanCode());
                    return result.isSuccess();
                    
                case "alipay":
                    AlipayResult alipayResult = alipayService
                        .autoDeduct(agreementId, amountCents,
                            "PrimeTop会员续费-" + sub.getPlanCode());
                    return alipayResult.isSuccess();
                    
                default:
                    log.error("未知的第三方支付渠道: {}", sub.getChannel());
                    return false;
            }
        } catch (Exception e) {
            log.error("第三方扣款异常: channel={}, agreementId={}",
                sub.getChannel(), agreementId, e);
            return false;
        }
    }
}
```

## 6. Dunning（失败扣款重试）编排

### 6.1 Dunning 策略

对于扣款失败的订阅，按以下策略进行多轮重试：

| 轮次 | 延迟时间 | 通知动作 | 权益状态 |
|------|----------|----------|----------|
| 第1轮 | 失败后 6h | APP推送「续费失败提醒」 | GRACE_PERIOD（完整权益）|
| 第2轮 | 失败后 24h | APP推送+站内信「请更新支付方式」 | GRACE_PERIOD（完整权益）|
| 第3轮 | 失败后 72h | APP推送+短信「最后提醒：会员即将暂停」 | GRACE_PERIOD（完整权益）|
| 宽限期结束 | 失败后 7天 | APP推送「会员权益已暂停」 | BILLING_RETRY（降级）|
| 重试终止 | 失败后 14天 | APP推送+短信「会员已过期」 | EXPIRED |

> **注意**：对于 Apple/Google 渠道，Dunning 主要由平台自动处理（Apple 的 billing retry period 通常为 60 天，Google 为 30 天）。本系统的 Dunning 策略主要针对微信/支付宝渠道。对于商店渠道，本系统主要做通知补充和状态同步。

### 6.2 Dunning 调度引擎

```java
/**
 * Dunning 重试调度引擎
 */
@Component
@Slf4j
public class DunningScheduler {

    @Resource
    private DunningScheduleMapper dunningMapper;
    @Resource
    private ThirdPartyAutoRenewalExecutor renewalExecutor;
    @Resource
    private NotificationService notificationService;
    @Resource
    private SubscriptionStateMachine stateMachine;
    
    /**
     * Dunning 策略配置
     */
    private static final List<DunningStep> DUNNING_STEPS = List.of(
        new DunningStep(1, Duration.ofHours(6),   "dunning_round_1", true),
        new DunningStep(2, Duration.ofHours(24),  "dunning_round_2", true),
        new DunningStep(3, Duration.ofHours(72),  "dunning_round_3", true),
        new DunningStep(4, Duration.ofDays(7),    "dunning_grace_expired", false),
        new DunningStep(5, Duration.ofDays(14),   "dunning_final_expired", false)
    );

    /**
     * 启动 Dunning 序列
     */
    @Transactional
    public void startDunningCampaign(SubscriptionRecord sub) {
        LocalDateTime baseTime = LocalDateTime.now();
        
        for (DunningStep step : DUNNING_STEPS) {
            DunningSchedule schedule = new DunningSchedule();
            schedule.setSubscriptionId(sub.getSubscriptionId());
            schedule.setUserId(sub.getUserId());
            schedule.setRound(step.round);
            schedule.setScheduledAt(baseTime.plus(step.delay));
            schedule.setChannel(sub.getChannel());
            schedule.setAmountCents(
                PlanCode.valueOf(sub.getPlanCode()).getPriceCents());
            schedule.setStatus("pending");
            
            dunningMapper.insert(schedule);
        }
        
        // 订阅进入宽限期
        stateMachine.transition(sub.getSubscriptionId(),
            SubscriptionStatus.GRACE_PERIOD,
            SubscriptionEventContext.builder()
                .eventType(SubscriptionEventType.GRACE_PERIOD_STARTED)
                .source("system")
                .build());
    }

    /**
     * 每30分钟执行到期的 Dunning 任务
     */
    @Scheduled(fixedDelay = 30 * 60 * 1000)
    public void executeDunningTasks() {
        List<DunningSchedule> tasks = dunningMapper.findDueTasks("pending",
            LocalDateTime.now(), 100);
        
        for (DunningSchedule task : tasks) {
            try {
                executeDunningRound(task);
            } catch (Exception e) {
                log.error("Dunning执行异常: taskId={}", task.getId(), e);
            }
        }
    }

    private void executeDunningRound(DunningSchedule task) {
        task.setExecutedAt(LocalDateTime.now());
        task.setStatus("executing");
        dunningMapper.update(task);
        
        SubscriptionRecord sub = subscriptionMapper
            .findBySubscriptionId(task.getSubscriptionId());
        
        // 判断是否已在更高轮次成功续费
        if (sub.getStatus() == SubscriptionStatus.ACTIVE) {
            task.setStatus("skipped");
            task.setFailureReason("subscription_already_active");
            dunningMapper.update(task);
            // 取消后续所有轮次
            dunningMapper.cancelPendingBySubscription(
                sub.getSubscriptionId(), task.getRound());
            return;
        }
        
        // 第4轮：宽限期结束，降级权益
        if (task.getRound() == 4) {
            stateMachine.transition(sub.getSubscriptionId(),
                SubscriptionStatus.BILLING_RETRY,
                SubscriptionEventContext.builder()
                    .eventType(SubscriptionEventType.GRACE_PERIOD_EXPIRED)
                    .source("system")
                    .build());
        }
        
        // 第5轮：彻底过期
        if (task.getRound() == 5) {
            stateMachine.transition(sub.getSubscriptionId(),
                SubscriptionStatus.EXPIRED,
                SubscriptionEventContext.builder()
                    .eventType(SubscriptionEventType.SYSTEM_EXPIRED)
                    .source("system")
                    .build());
            
            task.setStatus("success");
            dunningMapper.update(task);
            sendDunningNotification(sub, task);
            return;
        }
        
        // 第1-3轮：尝试重新扣款（仅第三方支付渠道）
        boolean success = retryPayment(sub, task);
        
        if (success) {
            task.setStatus("success");
            dunningMapper.update(task);
            
            // 取消后续所有轮次
            dunningMapper.cancelPendingBySubscription(
                sub.getSubscriptionId(), task.getRound());
            
            // 恢复订阅
            handleRetrySuccess(sub);
        } else {
            task.setStatus("failed");
            task.setFailureReason("payment_failed");
            dunningMapper.update(task);
        }
        
        sendDunningNotification(sub, task);
    }
}
```

## 7. 宽限期与权益降级

### 7.1 宽限期规则

| 渠道 | 宽限期时长 | 权益状态 | 控制方 |
|------|-----------|----------|--------|
| Apple IAP | 约16天（由Apple控制） | 完整权益 | Apple |
| Google Play | 约30天（由Google控制） | 完整权益 | Google |
| 微信支付 | 7天（本系统控制） | 完整权益 | 本系统 |
| 支付宝 | 7天（本系统控制） | 完整权益 | 本系统 |

### 7.2 权益降级策略

宽限期结束后，用户进入 `BILLING_RETRY` 状态，权益进行降级处理：

```java
/**
 * 权益降级处理器
 */
@Component
public class EntitlementDegradationHandler {

    /**
     * 降级为受限访问模式
     * 保留基础功能，限制高级功能
     */
    public void downgradeToLimited(Long userId) {
```

## 8. 续费恢复流程

### 8.1 用户主动恢复

当用户在宽限期或计费重试期主动更新支付方式或手动续费时：

```java
/**
 * 订阅恢复服务
 */
@Service
@Slf4j
public class SubscriptionRecoveryService {

    @Resource
    private SubscriptionStateMachine stateMachine;
    @Resource
    private OrderService orderService;

    /**
     * 用户手动支付恢复订阅
     */
    @Transactional
    public RecoveryResult recoverByPayment(String subscriptionId, String paymentMethod,
                                           String paymentProof) {
        SubscriptionRecord sub = subscriptionMapper.findBySubscriptionId(subscriptionId);
        
        // 校验当前状态允许恢复
        if (!canRecover(sub.getStatus())) {
            return RecoveryResult.fail("当前状态不支持恢复: " + sub.getStatus());
        }

        // 创建续费订单
        Order order = orderService.createRenewalOrder(sub);
        
        // 执行支付
        PaymentResult paymentResult = paymentService.processPayment(
            order.getId(), paymentMethod, paymentProof);
        
        if (!paymentResult.isSuccess()) {
            return RecoveryResult.fail("支付失败: " + paymentResult.getMessage());
        }

        // 更新订阅周期
        LocalDateTime newPeriodStart = sub.getCurrentPeriodEnd().isAfter(LocalDateTime.now()) ?
            sub.getCurrentPeriodEnd() : LocalDateTime.now();
        LocalDateTime newPeriodEnd = newPeriodStart
            .plus(PlanCode.valueOf(sub.getPlanCode()).getDuration());
        
        subscriptionMapper.updatePeriod(subscriptionId, newPeriodStart, newPeriodEnd);
        subscriptionMapper.clearGracePeriod(subscriptionId);
        subscriptionMapper.setAutoRenew(subscriptionId, true);
        
        // 状态转为 ACTIVE
        stateMachine.transition(subscriptionId,
            SubscriptionStatus.ACTIVE,
            SubscriptionEventContext.builder()
                .eventType(SubscriptionEventType.REACTIVATED)
                .source("user")
                .orderId(order.getId())
                .build());

        // 取消所有待执行的 Dunning 任务
        dunningMapper.cancelAllPending(subscriptionId);
        
        return RecoveryResult.success(order);
    }

    private boolean canRecover(SubscriptionStatus status) {
        return status == SubscriptionStatus.GRACE_PERIOD 
            || status == SubscriptionStatus.BILLING_RETRY
            || status == SubscriptionStatus.EXPIRED;
    }
}
```

### 9.2 挽回调度引擎

```java
/**
 * Win-back 挽回调度器
 */
@Component
@Slf4j
public class WinbackScheduler {

    /**
     * 每天上午10:00执行挽回任务
     */
    @Scheduled(cron = "0 0 10 * * ?")
    public void executeWinbackTasks() {
        LocalDateTime now = LocalDateTime.now();
        
        // 查找过期1/3/7/14/30天的订阅
        int[] targetDays = {1, 3, 7, 14, 30};
        
        for (int days : targetDays) {
            List<SubscriptionRecord> expired = subscriptionMapper.findExpiredAt(
                SubscriptionStatus.EXPIRED,
                now.minusDays(days).toLocalDate().atStartOfDay(),
                now.minusDays(days).toLocalDate().atTime(23, 59, 59));
            
            for (SubscriptionRecord sub : expired) {
                if (shouldSkipWinback(sub)) continue;
                
                try {
                    sendWinbackOffer(sub, days);
                } catch (Exception e) {
                    log.error("Win-back发送失败: subId={}, days={}",
                        sub.getSubscriptionId(), days, e);
                }
            }
        }
    }
    
    private boolean shouldSkipWinback(SubscriptionRecord sub) {
        // 用户已重新订阅则跳过
        if (subscriptionMapper.hasActiveSubscription(sub.getUserId())) {
            return true;
        }
        // 用户已注销账号
        if (userService.isDeactivated(sub.getUserId())) {
            return true;
        }
        // 已发送过该轮次
        return eventService.hasWinbackSent(sub.getSubscriptionId(),
            "winback_day_" + getDaysBucket(sub));
    }

    private void sendWinbackOffer(SubscriptionRecord sub, int daysExpired) {
        WinbackOffer offer = buildOffer(daysExpired, sub.getPlanCode());
        
        NotificationMessage msg = NotificationMessage.builder()
            .userId(sub.getUserId())
            .title(offer.getTitle())
            .content(offer.getContent())
            .type("winback_offer")
            .actionUrl("/my/membership/subscribe?code=" + offer.getCampaignCode())
            .actionText(offer.getButtonText())
            .expireAt(LocalDateTime.now().plusDays(3))
            .build();
        
        notificationService.send(msg);
        
        eventService.recordEvent(SubscriptionEvent.builder()
            .subscriptionId(sub.getSubscriptionId())
            .userId(sub.getUserId())
            .eventType(SubscriptionEventType.WINBACK_OFFER_SENT)
            .eventSource("system")
            .fromStatus(SubscriptionStatus.EXPIRED.name())
            .toStatus(SubscriptionStatus.EXPIRED.name())
            .metadata(Map.of("days_expired", daysExpired,
                "campaign_code", offer.getCampaignCode()))
            .build());
    }
}
```

## 11. 错误处理与边界情况

### 11.1 幂等保障

| 场景 | 幂等策略 |
|------|----------|
| Apple/Google重复通知 | 以 `notificationUUID` / `messageId` 去重，TTL 7天 |
| 重复扣款 | 订单号+订阅ID联合唯一约束，重复请求返回原结果 |
| 状态机并发转移 | 乐观锁（version字段）+ 数据库行锁兜底 |
| Dunning重复执行 | `uk_sub_round` 唯一索引 + status CAS |

### 11.2 异常场景处理

| 异常场景 | 处理策略 |
|----------|----------|
| 平台通知延迟到达 | 定时任务主动查询商店API校正状态（每小时） |
| 用户跨平台重复订阅 | 以最近购买为准，旧订阅标记 `superseded` |
| 退款通知到达但用户已续费 | 退款仅影响对应交易周期，新周期不受影响 |
| Apple家庭共享变更 | 监听 `REVOKE` 通知，撤销被共享方权益 |
| Google暂停后恢复 | 监听 `SUBSCRIPTION_PAUSED` / `SUBSCRIPTION_RECOVERED` |
| 微信代扣协议失效 | 检测到 `INVALID_AGREEMENT` 时通知用户重新签约 |
| 网络超时导致扣款结果不确定 | 进入人工对账队列，T+1日通过商店API核实 |

### 11.3 补偿与对账机制

```java
/**
 * 每日订阅状态对账任务
 * 主动与各平台核对订阅状态，修正不一致
 */
@Scheduled(cron = "0 30 2 * * ?")  // 每天凌晨2:30
public void dailyReconciliation() {
    // 1. 查找所有非终态订阅（ACTIVE/GRACE_PERIOD/BILLING_RETRY/CANCELED）
    List<SubscriptionRecord> active = subscriptionMapper.findAllNonTerminal();
    
    int inconsistent = 0;
    for (SubscriptionRecord sub : active) {
        try {
            SubscriptionStatus platformStatus = queryPlatformStatus(sub);
            if (platformStatus != null && platformStatus != sub.getStatus()) {
                log.warn("状态不一致: internal={}, platform={}, subId={}",
                    sub.getStatus(), platformStatus, sub.getSubscriptionId());
                reconcileStatus(sub, platformStatus);
                inconsistent++;
            }
        } catch (Exception e) {
            log.error("对账查询失败: subId={}", sub.getSubscriptionId(), e);
        }
    }
    
    log.info("订阅对账完成: 总计{}条, 不一致{}条", active.size(), inconsistent);
}
```
