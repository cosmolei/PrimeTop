# 用户生成内容(UGC)安全审核与未成年人社交保护引擎 - 详细设计

## 1. 概述

### 1.1 文档目的

本文档详细设计 PrimeTop 教育 APP 中用户生成内容（UGC）的安全审核引擎与未成年人社交互动保护体系。覆盖学生在使用社交学习功能（学习圈讨论、同伴互助问答、学习笔记分享、评论互动、学习挑战赛交流、协作学习等）时产生的所有文本、图片、语音内容的实时安全审核与管控。

### 1.2 设计背景

PrimeTop 作为面向 K12 全学段的 AI 辅助学习产品，用户主体为未成年人。随着产品迭代引入学习社交功能（学习圈、同伴互助、协作学习、学习挑战赛等），用户之间会产生大量 UGC 内容。依据以下法律法规，必须建立完善的 UGC 内容审核与未成年人保护机制：

| 法规 | 核心要求 |
| --- | --- |
| 《未成年人保护法》 | 网络服务提供者应设置未成年人模式，防止有害信息 |
| 《网络安全法》 | 用户发布信息需实时巡查，违法内容立即处置 |
| 《未成年人网络保护条例》 | 建立未成年人专属内容池，过滤不良信息 |
| 《互联网信息服务管理办法》 | 建立信息发布审核制度 |
| 《网络信息内容生态治理规定》 | 建立内容生态治理机制，防范不良信息传播 |

### 1.3 核心挑战

1. **实时性要求**：UGC 内容必须在发布前或发布后秒级完成审核
2. **准确性与误杀平衡**：未成年人用语多变，需精准识别隐喻、谐音、拼音替代等隐蔽表达
3. **多模态审核**：文本、图片、语音三种内容形态均需覆盖
4. **分级管控**：不同学段（幼儿/小学/初中/高中）审核标准不同
5. **隐私保护**：审核过程本身需保护未成年人隐私
6. **成本控制**：大量 UGC 内容需要高效低成本的审核管线

### 1.4 设计原则

| 原则 | 说明 |
| --- | --- |
| **儿童优先** | 一切审核策略以保护未成年人为最高优先级 |
| **实时拦截 + 异步复审** | 高风险内容实时拦截，中低风险异步人工复审 |
| **多层防护** | 关键词过滤 → NLP 模型 → 规则引擎 → 人工审核 |
| **最小化收集** | 审核日志仅记录必要信息，避免过度采集儿童数据 |
| **可解释性** | 每次拦截/标记需附带可追溯的理由和规则 ID |
| **可申诉性** | 被拦截内容提供申诉通道，人工复核后可放行 |

#### 2.2.1 违法违规内容（红线，必须实时拦截）

| 考试作弊讨论 | `UGC_RISK_CHEAT` | 讨论如何作弊、传答案 | 标记 + 审查 + 告警 |

| 类别 | 编码 | 示例 | 处置策略 |
| --- | --- | --- | --- |
| 学习压力表达 | `UGC_RISK_STRESS` | "作业好多写不完""好累" | 记录 + 可触发关怀消息 |
| 人际关系困扰 | `UGC_RISK_SOCIAL` | "没有朋友""被孤立了" | 记录 + 触发关怀 |

### 3.2 同步管线与异步管线

UGC 审核采用"双管线"模式，根据内容来源的风险等级选择管线：

#### 同步管线（先审后发）

适用场景：评论/回复、协作学习聊天、学习挑战赛互动、用户昵称/签名

```text
用户提交内容 → 内容暂存(不对外可见) → L1→L2→L3快速审核(≤500ms)
     │
     ├── 安全 → 内容发布，对外可见
     ├── 疑似(中风险) → 内容暂存 + 进入异步人工审核队列（用户看到"审核中"提示）
     └── 违规(高风险) → 拦截 + 用户提示修改
```

#### 异步管线（先发后审）

适用场景：学习圈帖子（含图）、学习笔记分享、互助问答、语音分享

```text
用户提交内容 → L1快速过滤(≤100ms)
     │
     ├── 命中高风险关键词 → 实时拦截
     └── 通过L1 → 内容发布(标记"审核中")
          → L2→L3→L4异步审核(≤30s)
               │
               ├── 安全 → 移除"审核中"标记
               ├── 疑似 → 隐藏内容 + 人工复审
               └── 违规 → 删除内容 + 用户通知 + 处置
```

### 3.3 模块划分

| 模块 | 职责 | 技术方案 |
| --- | --- | --- |
| UGC接入网关 | 统一接收所有UGC内容，去重、限频、路由 | Go + Kafka |
| 关键词过滤引擎 | 高速关键词/正则匹配及变体识别 | Go + DFA/AC自动机 |
| NLP分析引擎 | 文本分类、意图识别、情感分析 | Python + Transformers |
| 多模态识别引擎 | 图片内容安全识别、语音转文字分析 | Python + CV/NLP模型 |
| 规则决策引擎 | 叠加用户画像、分龄策略，输出最终决策 | Go + Drools/自研规则引擎 |
| 人工审核平台 | 审核工作台、标注工具、质检管理 | Vue3 + Java/Go |
| 处置执行服务 | 执行拦截/隐藏/删除/封禁等操作 | Java + Redis |
| 审计报表服务 | 审核日志、合规报表、数据回流 | Java + ClickHouse |

## 4. 数据结构设计

### 4.1 核心数据表

#### 4.1.1 UGC内容记录表 `ugc_content`

```sql
CREATE TABLE `ugc_content` (
    `id`                BIGINT       UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `content_id`        VARCHAR(40)  NOT NULL COMMENT '内容唯一ID(UUID)',
    `user_id`           BIGINT       UNSIGNED NOT NULL COMMENT '发布用户ID',
    `source_module`     VARCHAR(40)  NOT NULL COMMENT '来源模块: STUDY_CIRCLE/PEER_HELP/COMMENT/CHAT/NOTE/CHALLENGE/NICKNAME/AVATAR/REPORT/ESSAY_REVIEW/VOICE_SHARE/STUDY_ROOM',
    `source_ref_id`     VARCHAR(40)  DEFAULT NULL COMMENT '来源关联ID(帖子ID/回答ID等)',
    `content_type`      VARCHAR(20)  NOT NULL COMMENT '内容类型: TEXT/IMAGE/VOICE',
    `content_text`      MEDIUMTEXT   DEFAULT NULL COMMENT '文本内容(已脱敏)',
    `content_hash`      VARCHAR(64)  NOT NULL COMMENT '内容hash(SHA256),用于去重',
    `media_urls`        JSON         DEFAULT NULL COMMENT '媒体文件URL列表',
    `pipe_line`         VARCHAR(20)  NOT NULL COMMENT '审核管线: SYNC/ASYNC',
    `status`            VARCHAR(30)  NOT NULL DEFAULT 'PENDING' COMMENT '审核状态: PENDING/REVIEWING/APPROVED/REJECTED/HIDDEN/DELETED',
    `risk_level`        VARCHAR(20)  DEFAULT NULL COMMENT '风险等级: SAFE/LOW/MEDIUM/HIGH/CRITICAL',
    `publish_time`      DATETIME(3)  DEFAULT NULL COMMENT '内容发布时间',
    `created_at`        DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    `updated_at`        DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_content_id` (`content_id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_source_module` (`source_module`, `status`),
    KEY `idx_content_hash` (`content_hash`),
    KEY `idx_status_created` (`status`, `created_at`),
    KEY `idx_risk_level` (`risk_level`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='UGC内容记录表';
```


#### 5.1.2 ModerationOrchestrator 主编排

```java
@Service
public class ModerationOrchestrator {

    public ModerationDecision moderate(UgcContentRequest req) {
        // ── 0. 能力门控：禁言/封禁用户直接拒绝（读处罚服务能力门控缓存）──
        UserRestrictionInfo restrict = restrictionCache.get(req.getUserId()); // UGC:USER:RESTRICT
        if (restrict.isBanned())  throw new UgcException(54206, "账号封禁期");
        if (restrict.isSilenced()) throw new UgcException(54205, "禁言期至 " + restrict.getUntil());

        // ── 1. 频控：当日发布次数（幼儿/小学低 20 条/日，其余 50 条/日）──
        if (!rateLimiter.tryAcquire(req.getUserId(), req.getStageBudget()))
            throw new UgcException(54207, "超出当日发布频率限制");

        // ── 2. 去重：contentHash 命中缓存 → 复用历史决策（规则见 §5.12）──
        Optional<AuditResult> cached = auditCache.find(req.getContentHash());
        if (cached.isPresent() && cached.get().isReusable()) return cached.get().toDecision();

        // ── 3. L1 关键词快速过滤（≤30ms，含变体归一化）──
        L1Result l1 = keywordFilter.scan(req.normalizedText());          // 文本
        if (l1.hasCriticalHit()) return finish(req, l1.toDecision());    // 红线直接终审

        // ── 4. 按管线编排 L2 / L3 ──
        PipelinePlan plan = pipelineRouter.plan(req);                    // 由 §5.1.1 表驱动
        AuditContext ctx = AuditContext.of(req, l1);
        if (plan.syncNlp())   nlpClient.analyzeAsync(ctx);               // L2 同步/异步由 plan 决定
        if (plan.syncMulti() && req.hasMedia()) multimodalClient.analyze(ctx); // L3
        if (!plan.isFullySync()) {                                        // ASYNC 管线：先发布后深检
            asyncAuditQueue.submit(ctx.getContentId());                  // Kafka: ugc.audit.async
            return ModerationDecision.publishedPendingReview();
        }

        // ── 5. L4 规则决策（叠加画像/学段/信任等级）──
        ModerationDecision d = ruleEngine.decide(ctx);
        // ── 6. 持久化 + Outbox + 处置执行 ──
        return finish(req, d);
    }
}
```

敏感词过滤引擎是平台内容安全**底层基础设施**（覆盖 AI 输入/输出、UGC、搜索、站内消息），本引擎不重复建设底层匹配能力：

| --- | --- | --- |

#### 5.2.2 变体归一化管线（L1 前置）

```python
def normalize(text: str) -> str:
    s = unicodedata.normalize('NFKC', text)      # 全角→半角、特殊字符归一
    s = re.sub(r'[\s\.\-_·•*,，。~〜^]+', '', s)  # 剔除间隔符: "微  信"→"微信"
    s = collapse_repeats(s)                       # 折叠连续重复字: "微vv信"→"微v信"
    s = homophone_restore(s)                      # 谐音还原表: 薇/威/微→微, 扣/蔻→QQ
    s = pinyin_expand(s)                          # 拼音首字母/全拼映射: wx/weixin→微信
    return s
```

| 变体家族 | 示例 | 归一化策略 |
| --- | --- | --- |
| 谐音替换 | 薇信、威信、V信 | 同音字还原表（词库 `keyword_pinyin` 驱动） |
| 拼音/字母 | wx、weixin、V.X、vx+x | 拼音映射词典 + 首字母组合 |
| 符号混淆 | 微-信、微、、信、微*信 | 间隔符剔除后精确匹配 |
| 拆字/形近 | 弓长 、口天吴（姓氏拆分加好友话术） | 拆字合并表（仅维护高危类别） |
| 混合数字 | 加v1234、扣扣1234 | "加v/扣扣"等引导词 + 数字串正则（`REGEX` 匹配型） |

#### 5.2.3 词库热更新（双缓冲）

```java
public final class KeywordRepository {
    private final AtomicReference<AcTrie> current = new AtomicReference<>(AcTrie.empty());

    /** 每 5min 兜底轮询 + 敏感词引擎变更推送（Redis Pub/Sub: UGC:KEYWORDS:HOT）触发即时刷新 */
    @Scheduled(fixedDelay = 300_000)
    public void refresh() {
        long remoteVersion = keywordClient.versionOfScene("UGC");       // 敏感词引擎词库版本
        long localVersion  = ugcKeywordDictMapper.maxUpdatedVersion();
        if (remoteVersion == currentVersion && localVersion == currentVersion) return;
        AcTrie next = AcTrie.build(
            keywordClient.loadAll("UGC"),                               // 主库全量
            ugcKeywordDictMapper.loadEnabled(now()));                    // 场景补充词（含时效窗口过滤）
        current.set(next);                                              // 原子切换，读侧无锁
        eventPublisher.publish(new UgcKeywordsUpdated(next.version()));
    }
}
```

```python
class MultimodalPipeline:
    def analyze(self, content: UgcContent) -> L3Result:
        result = L3Result(content.content_id)
        for img in content.media_urls:                          # 图片：厂商内容安全 API + OCR
            safe  = vendor_client.image_check(img, scenes=["porn","terrorism","politics","ad_logo","qr_code"])
            ocr   = vendor_client.ocr(img)                      # 全量文字提取
            result.merge_image(safe)
            if ocr.text:                                        # OCR 文本回流 L1/L2 二次审核
                rerun = orchestrator.rescan_text(ocr.text, source=f"OCR:{content.content_id}")
                result.merge_text_result(rerun)
            if safe.has_qr_code:                                # 二维码解码白名单裁决
                url = vendor_client.qr_decode(img)
                if not shortlink_service.is_platform_domain(url):
                    result.add_hit("UGC_RISK_FRAUD", confidence=0.95)
            faces = vendor_client.face_detect(img)              # 未成年人肖像保护（仅 AVATAR/分享类）
            if content.source == "AVATAR" and faces.has_clear_other_minor_face:
                result.add_hit("UGC_RISK_PRIVACY_FACE", confidence=1.0)  # 提示更换，非违规
        if content.content_type == "VOICE":
            asr_text = asr_service.transcribe(content.voice_url, max_seconds=60)  # 超长截断
            result.merge_text_result(orchestrator.rescan_text(asr_text))
        return result
```

#### 5.5.2 违规积分与信任等级

```java
/** 违规分增量：按类别基础分 × 学段从严系数 × 类别加权 */
int delta(RiskCategory cat, Stage stage) {
    int base = switch (cat.level) { CRITICAL -> 60; HIGH -> 40; MEDIUM -> 20; default -> 0; };
    double stageFactor = (stage.isEnrollmentOrPrimaryLow() ? 1.5 : 1.0);   // 发布人低学段→内容受众同为低学段，从严
    double catFactor   = (cat.is(BULLY) ? 1.5 : cat.is(CONTACT) ? 1.2 : 1.0);
    return (int) Math.round(base * stageFactor * catFactor);
}
// 滑动窗口：180 天（与《用户违规处罚执行》累犯窗口对齐）；每日凌晨 -1 衰减，下限 0
// 信任等级：1-10；连续 30 天无违规且发布 ≥10 条 → +1；每次违规 -2
```

| 100 | BANNED | 永久 | PenaltyCommand `ban`（处罚服务二级审批，§11 四眼） |

### 5.6 L5：人工审核工作台流程

#### 5.6.1 任务生命周期状态机

```text
PENDING ──claim(Lua抢占)──▶ CLAIMED ──submit──▶ SUBMITTED ──qc抽样──▶ (QC PASSED/FAILED)
   ▲                          │ │

```

#### 5.6.2 抢占式领取（Redis Lua 原子）

```lua
-- KEYS[1]=UGC:TASK:QUEUE:{taskType}:{priority}  (ZSET, score=slaDeadline)
-- ARGV[1]=auditorId, ARGV[2]=now, ARGV[3]=skillGroup
local ids = redis.call('ZRANGEBYSCORE', KEYS[1], 0, ARGV[2] + 300000, 'LIMIT', 0, 1)
if #ids == 0 then return nil end
redis.call('ZREM', KEYS[1], ids[1])
redis.call('HSET', 'UGC:TASK:CLAIM:'..ids[1], 'auditor', ARGV[1], 'ts', ARGV[2])
redis.call('EXPIRE', 'UGC:TASK:CLAIM:'..ids[1], 300)   -- 5min 领取锁，超时由回收 Job 归还队列
return ids[1]
```

> MySQL 侧同步 `UPDATE ... SET status='CLAIMED', assigned_auditor=? WHERE task_id=? AND status='PENDING'`，影响行数=0 时归还 Redis（双存储最终一致，以 MySQL 为准，Redis 仅做排队索引）。

#### 5.6.3 队列路由与 SLA

| task_type | skill_group | 优先级来源 | SLA | 超时升级 |
| --- | --- | --- | --- | --- |
| ugc_appeal | CRISIS_APPEAL / DEFAULT | 固定 P0 | 24h（危机相关 2h） | SLA×1.5 告警 → ×2 强制 P0 |
| ugc_text | TEXT / PRIMARY_SCHOOL | L4 决策矩阵 | P0 30min / P1 2h / P2 8h / P3 24h | 同上 |
| ugc_image | IMAGE | 同上 | 同上 | 同上 |
| ugc_composition | TEXT（作文专项） | 互改评论疑似 | P2 | 同上 |

- 分配策略：技能组匹配 + 审核员在途任务 <20 才可领取 + 未成年人相关任务需审核员资质标记 `MINOR_CERTIFIED`；
- 质检：SUBMITTED 任务按 5% 抽样 QC，审核员周误判率 >5% 自动停岗（`qc_status=FAILED` 累计）；
- ESCALATE：审核员可升级为安全事件，走《管理后台-学生安全事件与心理健康预警管理工作台》通道（涉心理危机/校园欺凌线索强制升级）。

### 5.7 处置执行层

```java
@Service
public class DisposalExecutor {
    /** 按决策执行动作组合；同事务写 ugc_disposal_record + Outbox 事件，处罚与通知异步可靠执行 */
    @Transactional
    public void execute(ModerationDecision d, AuditContext ctx) {
        ugcContentMapper.updateStatus(ctx.contentId(), d.contentStatus());     // 终态守卫见 §5.10
        disposalRecordMapper.insert(DisposalRecord.of(ctx, d.actions()));
        if (d.has(PENALTY_MUTE, PENALTY_BAN, RESTRICT)) {
            penaltyClient.submit(buildCommand(ctx, d));                        // gRPC, 失败→54219+本地重试表
        }
        if (d.has(NOTIFY_PARENT)) {
            outbox.append(UgcParentNotifyEvent.minimal(ctx));                  // 仅违规事实+处罚，不含原文（§11）
        }
        if (d.has(CRISIS_REPORT)) {
            crisisReporter.report(ctx);                                        // §5.8
        }
        if (d.has(WARN)) {
            profileClient.applyViolation(ctx.userId(), d.scoreDelta());        // §5.5.2
            outbox.append(UgcUserWarnedEvent.of(ctx, d));
        }
        outbox.append(UgcDecisionEvent.of(ctx, d));                            // 学习圈/问答等消费翻转展示状态
    }
}
```

### 5.8 心理危机信号联动（对接危机引擎）

| 环节 | 设计 |
| --- | --- |
| 信号源 | ① L2 危机子模型 `selfHarm/suicide ≥0.5`；② L1 命中自残类词库（CRITICAL 类别挂载 `crisis=true` 标记）；③ L5 人工审核 ESCALATE；④ 举报分类"自残倾向"（举报服务移交） |
| 上报 | gRPC `crisis.v1.CrisisSignalIngest/Ingest`：`{source:"UGC", userId, signalType, confidence, excerpt(≤50字关键句), contentId, occurredAt}`；**不传内容全文**，危机引擎需要时凭 contentId 经授权回查 |
| 分级裁决 | 复用危机引擎 L0-L4 分级与干预动作表（PARENT_NOTIFY/人工介入等），本引擎不建第二套分级 |
| 红线1 | 求助类内容（"我不想活了"等直接求助帖）**不因触发词而自动删除**——先上报危机引擎，内容处置跟随危机引擎干预等级：L3 以下保留（保留求助可见性），L3+ 可 HIDE 并由人工介入 |
| 红线2 | 上报失败降级链：本地重试 3 次（1s/5s/30s）→ 写 `ugc_crisis_signal.report_status=FAILED` 兜底队列 → OnCall 15min 内人工外呼通道（危机引擎不可用时的兜底 SLA） |
| 留痕 | `ugc_crisis_signal` 仅存信号元数据；`LOW` 风险 STRESS/SOCIAL 类不构成危机信号，仅经通知中心触发关怀消息（每日至多 1 条，防骚扰） |

### 5.9 申诉流程

```text
用户(被拦截提示页)        学生端BFF           UGC引擎                    L5申诉复核组
   │ 申诉(仅BLOCK/REJECT可诉)  │                 │                          │

   │                         │        │                          ├─复核(24h SLA)
   │                         │◀─APPROVED/REJECTED 事件通知       │
```

守卫与防滥用：

- 每条内容仅 1 次申诉机会（`ugc_appeal.uk_content_active` 以状态机保证：PENDING/APPROVED 存在期间禁止新建）；
- 同用户 30 天内申诉 >10 次且成立率 <10% → 申诉入口冷却 30 天（返回 54212，引导在线客服）；
- 申诉复核权限独立技能组（`CRISIS_APPEAL` 组需 `MINOR_CERTIFIED` 资质，普通组不可复核涉危机内容 → 54220）；
- `APPEAL_REVERT` 处置记录不可再次回滚（`reverted_at` 非空即拒绝，幂等 appealId）。

## 11. 安全与合规

1. **数据最小化**：审核日志不记录设备指纹/位置；`content_text` 落库前对手机号等 PII 做掩码（`138****8000`），原文仅在证据对象存储（加密桶，90 天）；
2. **审核员权限**：违规内容默认脱敏展示（昵称打码）；查看原文需二次授权并写审计日志；`MINOR_CERTIFIED` 资质方可处理未成年人高危件；
3. **四眼原则**：BAN 级处罚由处罚服务二级审批落地（本引擎仅提交指令）；CRITICAL 内容删除+封禁组合处置需 L5 双人确认（提交人+复核人）；
4. **家长通知边界**：`UgcParentNotifyRequested` 仅含违规事实与处罚摘要，**不含违规内容原文**（防二次伤害与家庭内部激化）；涉自残类通知走危机引擎 PARENT_NOTIFY 话术模板；
5. **语音不留存**：ASR 转写完成并处置后，原始音频 72h 内删除（处置争议期内冻结保留）；
6. **保留期限**：REJECTED 证据 90 天（脱敏归档后入 ClickHouse）、申诉记录 180 天、审计宽表 180 天（TTL）、危机留痕 1 年（监管要求）；
7. **监管报送**：涉政 CRITICAL 事件 24h 内经《教育行业监管合规与政策适配引擎》报送通道上报；
8. **算法合规**：审核模型属内容治理算法，纳入算法备案条目（对齐监管合规引擎备案清单）；拦截决策可解释（ruleId/modelVersion 全链路留痕）；
9. **反规避**：`userTipCode` 不透出规则细节；词库/模型阈值不随响应返回；高频探测行为（同用户 1h 触发 ≥5 次不同拦截）→ 风控中心布控事件。

## 13. 验收场景

1. 评论同步审核：正常学习讨论 ≤300ms 返回 APPROVE，`ugc_content=APPROVED`，业务侧立即可见；
2. 评论含"加我微信 wx_abc123"：正则+NER 双轨命中 CONTACT，返回 REJECT + `TIP_CONTACT_LEAK`，违规分 +48（HIGH×1.2），用户收到警告站内信；
3. 同一用户 1h 内第 3 次发送同一条被拒内容：命中缓存直接拒绝 + STREAK 计数触发额外 WARN（§5.12）；
4. 协作聊天含变体联系方式"加V 138 0013 8000"：归一化（间隔符剔除+谐音还原）后 L1 命中，PreCheck ≤200ms 拒绝；
5. 幼儿学段用户发送中风险擦边内容：L4 分龄从严直接 BLOCK（不进疑似态）；高中用户同内容且信任等级 8：REPLACE/APPROVE+记录；
6. 学习圈带图帖子（ASYNC）：L1 通过立即发布（status=2）→ 图片 OCR 提取出联系方式 → 深检 HIDE（status=3）→ 事件驱动分发引擎翻转 → 用户收到修改通知；
7. 图片含外部二维码：解码非平台域名 → FRAUD 置信 0.95 自动拦截，无需人工；
8. 头像含他人清晰儿童面部：拒绝并提示更换，首次不扣违规分（PRIVACY_FACE）；
9. 昵称同步通道：完整 L1+L2+L4 ≤500ms，含"处cp"黑话在初中以下学段判 HIGH 拦截；
10. 自习室消息 10% 抽样：同步仅 L1 放行，异步 L2 抽样检出脏话 → 内容已扩散则走召回（G8）+ 替换展示；
11. 危机信号：笔记分享含自残描述（危机子模型 0.72）→ gRPC 上报成功 → 内容不自动删除（L2 级）→ 家长收到关怀话术通知（不含原文）→ `ugc_crisis_signal=ACCEPTED`；
12. 危机引擎宕机：上报 3 次重试失败 → FAILED 入兜底队列 → OnCall 15min 响应 → 恢复后补报无重复（signal_id 幂等）；
13. 人工审核：P1 任务被 A 领取 5min 未提交自动回收回队，expire_count=1；B 领取并 REJECT，QC 抽样 PASSED；
