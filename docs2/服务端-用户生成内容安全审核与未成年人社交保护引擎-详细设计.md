# 用户生成内容(UGC)安全审核与未成年人社交保护引擎 - 详细设计

## 1. 概述

### 1.1 文档目的

本文档详细设计 PrimeTop 教育 APP 中用户生成内容（UGC）的安全审核引擎与未成年人社交互动保护体系。覆盖学生在使用社交学习功能（学习圈讨论、同伴互助问答、学习笔记分享、评论互动、学习挑战赛交流、协作学习等）时产生的所有文本、图片、语音内容的实时安全审核与管控。

### 1.2 设计背景

PrimeTop 作为面向 K12 全学段的 AI 辅助学习产品，用户主体为未成年人。随着产品迭代引入学习社交功能（学习圈、同伴互助、协作学习、学习挑战赛等），用户之间会产生大量 UGC 内容。依据以下法律法规，必须建立完善的 UGC 内容审核与未成年人保护机制：

| 法规 | 核心要求 |
| --- | --- |
| 《未成年人保护法》 | 网络服务提供者应设置未成年人模式，防止有害信息 |
| 《网络安全法》 | 用户发布信息需实时巡查，违法内容立即处置 |
| 《未成年人网络保护条例》 | 建立未成年人专属内容池，过滤不良信息 |
| 《互联网信息服务管理办法》 | 建立信息发布审核制度 |
| 《网络信息内容生态治理规定》 | 建立内容生态治理机制，防范不良信息传播 |

### 1.3 核心挑战

1. **实时性要求**：UGC 内容必须在发布前或发布后秒级完成审核
2. **准确性与误杀平衡**：未成年人用语多变，需精准识别隐喻、谐音、拼音替代等隐蔽表达
3. **多模态审核**：文本、图片、语音三种内容形态均需覆盖
4. **分级管控**：不同学段（幼儿/小学/初中/高中）审核标准不同
5. **隐私保护**：审核过程本身需保护未成年人隐私
6. **成本控制**：大量 UGC 内容需要高效低成本的审核管线

### 1.4 设计原则

| 原则 | 说明 |
| --- | --- |
| **儿童优先** | 一切审核策略以保护未成年人为最高优先级 |
| **实时拦截 + 异步复审** | 高风险内容实时拦截，中低风险异步人工复审 |
| **多层防护** | 关键词过滤 → NLP 模型 → 规则引擎 → 人工审核 |
| **最小化收集** | 审核日志仅记录必要信息，避免过度采集儿童数据 |
| **可解释性** | 每次拦截/标记需附带可追溯的理由和规则 ID |
| **可申诉性** | 被拦截内容提供申诉通道，人工复核后可放行 |

### 2.2 风险内容分类

#### 2.2.1 违法违规内容（红线，必须实时拦截）

| 类别 | 编码 | 示例 | 处置策略 |
| --- | --- | --- | --- |

| 暴力恐怖 | `UGC_RISK_VIOLENCE` | 暴力描述、自残自杀暗示、恐怖内容 | 实时拦截 + 告警 + 家长通知 |
| 涉政敏感 | `UGC_RISK_POLITICAL` | 政治敏感言论、谣言传播 | 实时拦截 + 上报 + 记录 |

| 类别 | 编码 | 示例 | 处置策略 |
| --- | --- | --- | --- |
| 网络欺凌 | `UGC_RISK_BULLY` | 嘲讽、辱骂、排挤、人身攻击 | 实时拦截 + 警告 + 3次封禁 |
| 联系方式泄露 | `UGC_RISK_CONTACT` | 手机号、微信号、QQ号、住址泄露 | 实时拦截 + 提醒隐私保护 |

| 类别 | 编码 | 示例 | 处置策略 |
| --- | --- | --- | --- |

| 情绪宣泄 | `UGC_RISK_VENT` | 过度负面情绪宣泄、哭泣求助 | 标记 + 关怀引导 |
| 考试作弊讨论 | `UGC_RISK_CHEAT` | 讨论如何作弊、传答案 | 标记 + 审查 + 告警 |

| 类别 | 编码 | 示例 | 处置策略 |
| --- | --- | --- | --- |
| 学习压力表达 | `UGC_RISK_STRESS` | "作业好多写不完""好累" | 记录 + 可触发关怀消息 |
| 人际关系困扰 | `UGC_RISK_SOCIAL` | "没有朋友""被孤立了" | 记录 + 触发关怀 |
| 非学习话题 | `UGC_RISK_OFFTOPIC` | 讨论明星、动漫等非学习话题 | 记录（不拦截，可限流） |

### 3.2 同步管线与异步管线

UGC 审核采用"双管线"模式，根据内容来源的风险等级选择管线：

#### 同步管线（先审后发）

适用场景：评论/回复、协作学习聊天、学习挑战赛互动、用户昵称/签名

```text
用户提交内容 → 内容暂存(不对外可见) → L1→L2→L3快速审核(≤500ms)
     │
     ├── 安全 → 内容发布，对外可见
     ├── 疑似(中风险) → 内容暂存 + 进入异步人工审核队列（用户看到"审核中"提示）
     └── 违规(高风险) → 拦截 + 用户提示修改
```

#### 异步管线（先发后审）

适用场景：学习圈帖子（含图）、学习笔记分享、互助问答、语音分享

```text
用户提交内容 → L1快速过滤(≤100ms)
     │
     ├── 命中高风险关键词 → 实时拦截
     └── 通过L1 → 内容发布(标记"审核中")
          → L2→L3→L4异步审核(≤30s)
               │
               ├── 安全 → 移除"审核中"标记
               ├── 疑似 → 隐藏内容 + 人工复审
               └── 违规 → 删除内容 + 用户通知 + 处置
```

### 3.3 模块划分

| 模块 | 职责 | 技术方案 |
| --- | --- | --- |
| UGC接入网关 | 统一接收所有UGC内容，去重、限频、路由 | Go + Kafka |
| 关键词过滤引擎 | 高速关键词/正则匹配及变体识别 | Go + DFA/AC自动机 |
| NLP分析引擎 | 文本分类、意图识别、情感分析 | Python + Transformers |
| 多模态识别引擎 | 图片内容安全识别、语音转文字分析 | Python + CV/NLP模型 |
| 规则决策引擎 | 叠加用户画像、分龄策略，输出最终决策 | Go + Drools/自研规则引擎 |
| 人工审核平台 | 审核工作台、标注工具、质检管理 | Vue3 + Java/Go |
| 处置执行服务 | 执行拦截/隐藏/删除/封禁等操作 | Java + Redis |
| 审计报表服务 | 审核日志、合规报表、数据回流 | Java + ClickHouse |

## 4. 数据结构设计

### 4.1 核心数据表

#### 4.1.1 UGC内容记录表 `ugc_content`

```sql
CREATE TABLE `ugc_content` (
    `id`                BIGINT       UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `content_id`        VARCHAR(40)  NOT NULL COMMENT '内容唯一ID(UUID)',
    `user_id`           BIGINT       UNSIGNED NOT NULL COMMENT '发布用户ID',
    `source_module`     VARCHAR(40)  NOT NULL COMMENT '来源模块: STUDY_CIRCLE/PEER_HELP/COMMENT/CHAT/NOTE/CHALLENGE/NICKNAME/AVATAR/REPORT/ESSAY_REVIEW/VOICE_SHARE/STUDY_ROOM',
    `source_ref_id`     VARCHAR(40)  DEFAULT NULL COMMENT '来源关联ID(帖子ID/回答ID等)',
    `content_type`      VARCHAR(20)  NOT NULL COMMENT '内容类型: TEXT/IMAGE/VOICE',
    `content_text`      MEDIUMTEXT   DEFAULT NULL COMMENT '文本内容(已脱敏)',
    `content_hash`      VARCHAR(64)  NOT NULL COMMENT '内容hash(SHA256),用于去重',
    `media_urls`        JSON         DEFAULT NULL COMMENT '媒体文件URL列表',
    `pipe_line`         VARCHAR(20)  NOT NULL COMMENT '审核管线: SYNC/ASYNC',
    `status`            VARCHAR(30)  NOT NULL DEFAULT 'PENDING' COMMENT '审核状态: PENDING/REVIEWING/APPROVED/REJECTED/HIDDEN/DELETED',
    `risk_level`        VARCHAR(20)  DEFAULT NULL COMMENT '风险等级: SAFE/LOW/MEDIUM/HIGH/CRITICAL',
    `publish_time`      DATETIME(3)  DEFAULT NULL COMMENT '内容发布时间',
    `created_at`        DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    `updated_at`        DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_content_id` (`content_id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_source_module` (`source_module`, `status`),
    KEY `idx_content_hash` (`content_hash`),
    KEY `idx_status_created` (`status`, `created_at`),
    KEY `idx_risk_level` (`risk_level`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='UGC内容记录表';
```

#### 4.1.2 审核结果记录表 `ugc_audit_result`

```sql
CREATE TABLE `ugc_audit_result` (
    `id`                BIGINT       UNSIGNED NOT NULL AUTO_INCREMENT,
    `audit_id`          VARCHAR(40)  NOT NULL COMMENT '审核记录UUID',
    `content_id`        VARCHAR(40)  NOT NULL COMMENT '关联UGC内容ID',

    `decision`          VARCHAR(20)  NOT NULL COMMENT '决策结果: APPROVE/REJECT/HIDE/MANUAL_REVIEW',
    `confidence`        DECIMAL(5,4) DEFAULT NULL COMMENT '模型置信度 0.0000-1.0000',
    `risk_categories`   JSON         DEFAULT NULL COMMENT '命中的风险类别编码数组',
    `hit_rules`         JSON         DEFAULT NULL COMMENT '命中规则详情',
    `model_version`     VARCHAR(40)  DEFAULT NULL COMMENT '模型版本号',
    `processing_time_ms` INT         DEFAULT NULL COMMENT '处理耗时(毫秒)',
    `auditor_id`        BIGINT       UNSIGNED DEFAULT NULL COMMENT '人工审核员ID(L5)',

    UNIQUE KEY `uk_audit_id` (`audit_id`),
```

### 4.2 Redis 数据结构

```
# 用户当日发帖频率控制
UGC:RATE:POST:{userId}:{date}  → INCR/EXPIRE(86400)

# 用户连续违规计数器
UGC:VIOLATION:STREAK:{userId}  → INCR/EXPIRE(3600)

# 内容审核结果缓存(避免重复审核相同内容)
UGC:CACHE:HASH:{contentHash}   → JSON(auditResult) / EXPIRE(604800)

# 用户限制状态缓存
UGC:USER:RESTRICT:{userId}     → JSON(restrictionInfo) / EXPIRE(300)

# 实时拦截关键词列表(高频更新,缓存到本地)
UGC:KEYWORDS:HOT               → SET(keywordIds) / EXPIRE(60)

# 异步审核队列
UGC:QUEUE:ASYNC:AUDIT          → LIST(contentId) # Kafka Topic替代

# 用户信任等级缓存
UGC:USER:TRUST:{userId}        → INT(trustLevel) / EXPIRE(600)
```
