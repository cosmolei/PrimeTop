## 1. 模块概述

### 1.1 背景与目标

PrimeTop 作为面向 K12 全学段的教育产品，平台承载的海量教育内容（题库、解析、教材章节、知识点讲解、AI 生成内容、用户上传素材等）直接关系到学生学习效果和人身安全。内容质量低下、知识性错误、表述不当或包含违规信息，都会造成严重的教育事故和合规风险。

现有文档已覆盖 AI 对话安全审计（AI 对话安全审计与敏感内容自动上报服务）和 AI 输出质量抽样审核（AI 对话质量抽样审核与标注工作台服务），但缺少面向**全平台教育内容**的通用审核工作流——覆盖题库题目、教材资源、知识点讲解、解析文本、用户举报内容等多种内容形态的统一审核管线。

本服务构建从**内容提交 → 自动预筛 → 人工多级审核 → 发布/驳回 → 版本管理 → 用户举报响应**的完整审核闭环。

### 1.2 核心目标

| 目标 | 说明 |
|------|------|
| 统一审核入口 | 所有教育内容（题目、解析、教材、知识点、AI 输出沉淀）共用一套审核管线 |
| 多级审核机制 | 支持 L1 初审（内容运营）→ L2 复审（学科教研）→ L3 终审（专家/主管）三级审核 |
| 自动预筛前置 | 内容提交后先经过自动化安全检测和格式校验，减少人工审核负担 |
| 智能任务分配 | 按审核员技能标签、工作负载、内容学科自动分配审核任务 |
| 举报快速响应 | 用户举报的内容自动进入高优先级审核队列，限时处理 |
| 全链路可追溯 | 所有审核操作、意见、状态变更记录审计日志，满足合规要求 |
| 内容版本管理 | 审核不通过时可退回修改，保留历史版本，支持一键回滚 |

### 1.3 与其他模块的关系

```
题库服务 / 知识点服务 / 教材内容服务 / AI对话引擎
           │
           ↓ (内容提交/变更)
    ┌──────────────────────────────┐
    │    教育内容审核工作流引擎       │
    │  ┌─────────┐ ┌────────────┐ │
    │  │自动预筛  │ │多级审核调度 │ │
    │  └─────────┘ └────────────┘ │
    │  ┌─────────┐ ┌────────────┐ │
    │  │举报响应  │ │版本管理     │ │
    │  └─────────┘ └────────────┘ │
    └──────────────────────────────┘
           │              │
     审核通过发布      审核日志/统计
           ↓              ↓
     内容服务(生效)   管理后台/运营驾驶舱
```

| 关联模块 | 交互方式 |
|----------|----------|
| 题目与题库服务 | 题目/解析创建或修改时触发审核流程 |
| 知识点体系与教材映射引擎 | 知识点讲解内容变更触发审核 |
| 教材内容数字化与结构化生产管线 | 批量导入的内容进入审核管线 |
| 安全与内容合规系统 | 调用内容安全过滤 API 进行自动预筛 |
| AI对话质量抽样审核与标注工作台服务 | AI 输出沉淀为正式内容时进入本审核管线 |
| 服务端审计日志与操作追溯系统 | 所有审核操作写入审计日志 |
| 用户意见反馈与客服工单 | 用户举报内容进入高优先级审核队列 |
| 管理后台数据分析看板与运营驾驶舱 | 审核统计指标输出到运营看板 |
| 权限管理与角色访问控制 | 审核员权限、审核级别由 RBAC 控制 |
| 服务端统一业务异常码与错误分类体系 | 复用标准异常码 |

## 2. 数据结构设计

### 2.1 核心实体关系

```
ContentReviewTemplate ──1:N──→ ReviewChecklistItem
         │
         ↓ (内容提交时绑定模板)
ContentReviewTask ──1:N──→ ReviewAssignment ──1:N──→ ReviewOpinion
         │                                            │
         ├── 内容快照版本                               └── 维度评分
         └── 关联举报记录
                  
ReviewerProfile ──1:N──→ ReviewAssignment

ContentReport ──1:1──→ ContentReviewTask (举报触发时)
```

### 2.2 审核模板表 `content_review_template`

定义不同内容类型的审核标准模板。

```sql
CREATE TABLE content_review_template (
    id                  BIGSERIAL PRIMARY KEY,
    template_name       VARCHAR(100) NOT NULL COMMENT '模板名称',
    template_code       VARCHAR(50) NOT NULL UNIQUE COMMENT '模板编码',
    
    -- 适用范围
    content_types       JSONB NOT NULL COMMENT '适用内容类型,如["question","explanation","knowledge_point"]',
    subject_filter      JSONB COMMENT '适用学科,null=全部',
    grade_filter        JSONB COMMENT '适用学段,null=全部',
    
    -- 审核级别配置
    required_levels     SMALLINT NOT NULL DEFAULT 2 COMMENT '需要经过的审核级别数(1-3)',
    level1_name         VARCHAR(50) DEFAULT '初审' COMMENT 'L1级别名称',
    level2_name         VARCHAR(50) DEFAULT '复审' COMMENT 'L2级别名称',
    level3_name         VARCHAR(50) DEFAULT '终审' COMMENT 'L3级别名称',
    
    -- 自动预筛配置
    auto_precheck_enabled  BOOLEAN NOT NULL DEFAULT TRUE COMMENT '是否启用自动预筛',
    auto_reject_enabled    BOOLEAN NOT NULL DEFAULT FALSE COMMENT '预筛不通过是否自动驳回',
    
    -- SLA 配置
    sla_hours_l1        INT NOT NULL DEFAULT 24 COMMENT 'L1审核SLA(小时)',
    sla_hours_l2        INT NOT NULL DEFAULT 48 COMMENT 'L2审核SLA(小时)',
    sla_hours_l3        INT NOT NULL DEFAULT 72 COMMENT 'L3审核SLA(小时)',
    
    -- 状态
    is_active           BOOLEAN NOT NULL DEFAULT TRUE,
    
    -- 元数据
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by          BIGINT NOT NULL COMMENT '创建人ID'
);

COMMENT ON TABLE content_review_template IS '内容审核模板';
```

### 2.3 审核清单项表 `review_checklist_item`

每个模板下的具体审核检查项。

```sql
CREATE TABLE review_checklist_item (
    id                  BIGSERIAL PRIMARY KEY,
    template_id         BIGINT NOT NULL REFERENCES content_review_template(id),
    
    -- 检查项定义
    item_name           VARCHAR(200) NOT NULL COMMENT '检查项名称',
    item_code           VARCHAR(50) NOT NULL COMMENT '检查项编码',
    description         TEXT COMMENT '详细说明与示例',
    category            VARCHAR(50) NOT NULL COMMENT '分类: accuracy/safety/format/pedagogy/age_appropriate',
    
    -- 级别
    required_level      SMALLINT NOT NULL DEFAULT 1 COMMENT '在哪一级审核中检查此项(1/2/3)',
    
    -- 评分
    scoring_type        VARCHAR(20) NOT NULL DEFAULT 'pass_fail' COMMENT '评分方式: pass_fail/score_5/score_10',
    passing_threshold   DECIMAL(5,2) COMMENT '分数型评分的通过线',
    
    -- 排序与状态
    sort_order          INT NOT NULL DEFAULT 0,
    is_required         BOOLEAN NOT NULL DEFAULT TRUE COMMENT '是否必检项',
    is_active           BOOLEAN NOT NULL DEFAULT TRUE,
    
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_checklist_template ON review_checklist_item(template_id);
CREATE INDEX idx_checklist_level ON review_checklist_item(template_id, required_level);
```

### 2.4 内容审核任务表 `content_review_task`

每次内容提交/变更产生的审核任务。

```sql
CREATE TABLE content_review_task (
    id                  BIGSERIAL PRIMARY KEY,
    task_no             VARCHAR(32) NOT NULL UNIQUE COMMENT '任务编号,如 CRT20260610001',
    
    -- 关联内容
    content_type        VARCHAR(30) NOT NULL COMMENT '内容类型: question/explanation/knowledge_point/textbook_chapter/ai_output/user_report',
    content_id          BIGINT NOT NULL COMMENT '内容ID(对应各业务表的主键)',
    content_version     INT NOT NULL DEFAULT 1 COMMENT '内容版本号',
    content_snapshot    JSONB NOT NULL COMMENT '内容快照(审核时的完整内容副本)',
    
    -- 来源信息
    source              VARCHAR(30) NOT NULL COMMENT '来源: manual_create/batch_import/ai_generate/user_edit/system_detect',
    source_id           VARCHAR(100) COMMENT '来源标识(如导入批次号、AI对话ID)',
    submitter_id        BIGINT COMMENT '提交人ID',
    submitter_type      VARCHAR(20) COMMENT '提交人类型: admin/teacher/system',
    
    -- 审核配置
    template_id         BIGINT NOT NULL REFERENCES content_review_template(id),
    required_levels     SMALLINT NOT NULL COMMENT '需审核级别数',
    current_level       SMALLINT NOT NULL DEFAULT 0 COMMENT '当前所处审核级别(0=预筛中)',
    
    -- 任务状态
    status              VARCHAR(20) NOT NULL DEFAULT 'pending_precheck' 
                        COMMENT '状态: pending_precheck/precheck_failed/pending_l1/in_review_l1/pending_l2/in_review_l2/pending_l3/in_review_l3/approved/rejected/withdrawn/escalated',
    
    -- 自动预筛结果
    precheck_result     JSONB COMMENT '预筛结果详情',
    precheck_passed     BOOLEAN COMMENT '预筛是否通过',
    precheck_at         TIMESTAMPTZ,
    
    -- 审核结论
    final_verdict       VARCHAR(20) COMMENT '最终结论: approved/rejected/approved_with_modification',
    final_verdict_by    BIGINT COMMENT '最终审核人ID',
    final_verdict_at    TIMESTAMPTZ,
    
    -- 关联举报
    report_id           BIGINT COMMENT '关联的用户举报ID',
    priority            VARCHAR(10) NOT NULL DEFAULT 'normal' COMMENT '优先级: critical/high/normal/low',
    
    -- SLA 追踪
    sla_deadline        TIMESTAMPTZ COMMENT 'SLA截止时间',
    sla_breached        BOOLEAN NOT NULL DEFAULT FALSE COMMENT '是否已超SLA',
    
    -- 元数据
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_review_task_content ON content_review_task(content_type, content_id);
CREATE INDEX idx_review_task_status ON content_review_task(status, priority);
CREATE INDEX idx_review_task_sla ON content_review_task(status, sla_deadline) WHERE status NOT IN ('approved','rejected','withdrawn');
CREATE INDEX idx_review_task_report ON content_review_task(report_id) WHERE report_id IS NOT NULL;
CREATE INDEX idx_review_task_assignee ON content_review_task(id); -- 通过 assignment 关联查询
```

### 2.5 审核分配表 `review_assignment`

记录每次审核级别的人员分配。

```sql
CREATE TABLE review_assignment (
    id                  BIGSERIAL PRIMARY KEY,
    task_id             BIGINT NOT NULL REFERENCES content_review_task(id),
    
    -- 级别信息
    review_level        SMALLINT NOT NULL COMMENT '审核级别(1/2/3)',
    
    -- 审核员
    reviewer_id         BIGINT COMMENT '审核员ID(null=待分配)',
    assigned_at         TIMESTAMPTZ,
    assigned_by         BIGINT COMMENT '分配人ID(系统自动分配时为null)',
    
    -- 审核状态
    status              VARCHAR(20) NOT NULL DEFAULT 'pending' 
                        COMMENT 'pending/accepted/in_progress/submitted/skipped/reassigned',
    started_at          TIMESTAMPTZ COMMENT '开始审核时间',
    submitted_at        TIMESTAMPTZ COMMENT '提交审核时间',
    
    -- 审核结论
    verdict             VARCHAR(20) COMMENT 'approved/rejected/needs_modification/escalate',
    
    -- SLA
    level_sla_deadline  TIMESTAMPTZ COMMENT '本级别SLA截止时间',
    
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    UNIQUE(task_id, review_level, reviewer_id)
);

CREATE INDEX idx_assignment_reviewer ON review_assignment(reviewer_id, status);
CREATE INDEX idx_assignment_task ON review_assignment(task_id, review_level);
CREATE INDEX idx_assignment_pending ON review_assignment(status) WHERE status = 'pending';
```

### 2.6 审核意见表 `review_opinion`

审核员对每个检查项的评审结果。

```sql
CREATE TABLE review_opinion (
    id                  BIGSERIAL PRIMARY KEY,
    assignment_id       BIGINT NOT NULL REFERENCES review_assignment(id),
    task_id             BIGINT NOT NULL REFERENCES content_review_task(id),
    
    -- 检查项
    checklist_item_id   BIGINT REFERENCES review_checklist_item(id) COMMENT '检查项ID(null=总体意见)',
    item_code           VARCHAR(50) COMMENT '检查项编码(冗余,便于查询)',
    
    -- 评审结果
    result              VARCHAR(20) NOT NULL COMMENT 'pass/fail/na',
    score               DECIMAL(5,2) COMMENT '分数型评分值',
    comment             TEXT COMMENT '审核意见',
    suggested_fix       TEXT COMMENT '修改建议',
    
    -- 附件
    attachments         JSONB COMMENT '附件列表,[{"name":"xxx","url":"xxx"}]',
    
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    reviewer_id         BIGINT NOT NULL COMMENT '审核员ID'
);

CREATE INDEX idx_opinion_assignment ON review_opinion(assignment_id);
CREATE INDEX idx_opinion_task ON review_opinion(task_id);
```


### 2.8 用户举报记录表 `content_report`

```sql
CREATE TABLE content_report (

    sla_breached        BOOLEAN NOT NULL DEFAULT FALSE,
    
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_report_target ON content_report(target_type, target_id);
CREATE INDEX idx_report_reporter ON content_report(reporter_id);
```

## 3. API 接口设计

### 3.1 提交内容审核

提交一段内容进入审核管线。

```
POST /api/v1/content-review/tasks
```

**请求体：**

```json
{
  "contentType": "question",
  "contentId": 12345,
  "contentSnapshot": {
    "subject": "math",
    "grade": "junior_2",
    "chapterId": 789,
    "knowledgePointIds": [101, 102],
    "stem": "已知函数 f(x) = x² - 2x + 1，求 f(x) 的最小值。",
    "options": [
      {"label": "A", "text": "0"},
      {"label": "B", "text": "1"},
      {"label": "C", "text": "-1"},
      {"label": "D", "text": "2"}

    "correctAnswer": "A",
    "explanation": "f(x) = (x-1)²，当 x=1 时取最小值 0。",
    "difficulty": 2,

  },
  "source": "manual_create",
  "submitterId": 1001,
  "submitterType": "admin",
```

```java
@Service
public class ContentReviewService {

    @Autowired
    private ContentSafetyClient safetyClient;  // 安全与内容合规系统
    @Autowired
    private ReviewTaskRepository taskRepo;
    @Autowired
    private ReviewAssignmentService assignmentService;
    @Autowired
    private ReviewerMatchService reviewerMatchService;

    /**
     * 提交内容审核
     */
    @Transactional
    public ReviewTaskDTO submitForReview(ReviewSubmitRequest request) {
        // 1. 匹配审核模板
        ContentReviewTemplate template = findTemplate(
            request.getContentType(), request.getSubject(), request.getGrade());
        
        // 2. 创建审核任务
        ContentReviewTask task = new ContentReviewTask();
        task.setTaskNo(generateTaskNo());
        task.setContentType(request.getContentType());
        task.setContentId(request.getContentId());
        task.setContentSnapshot(request.getContentSnapshot());
        task.setSource(request.getSource());
        task.setSubmitterId(request.getSubmitterId());
        task.setTemplateId(template.getId());
        task.setRequiredLevels(template.getRequiredLevels());
        task.setCurrentLevel(0);
        task.setStatus(ReviewTaskStatus.PENDING_PRECHECK);
        task.setPriority(request.getPriority());
        task.setSlaDeadline(calculateSlaDeadline(template));
        taskRepo.save(task);

        // 3. 异步执行自动预筛
        if (template.isAutoPrecheckEnabled()) {
            asyncPrecheck(task, template);
        } else {
            // 跳过预筛，直接进入 L1
            advanceToLevel(task, 1, template);
        }

        return toDTO(task);
    }

    /**
     * 异步自动预筛
     */
    @Async("reviewPrecheckExecutor")
    public void asyncPrecheck(ContentReviewTask task, ContentReviewTemplate template) {
        try {
            PrecheckResult result = new PrecheckResult();

            // A. 内容安全检测
            SafetyCheckResult safetyResult = safetyClient.checkText(
                extractAllText(task.getContentSnapshot()),
                SafetyCheckContext.EDUCATIONAL_CONTENT
            );
            result.setSafetyCheck(safetyResult.isPassed() ? "passed" : "failed");
            result.setSafetyDetails(safetyResult.getDetails());

            // B. 格式完整性校验
            FormatCheckResult formatResult = formatValidator.validate(
                task.getContentType(), task.getContentSnapshot());
            result.setFormatCheck(formatResult.isPassed() ? "passed" : "failed");
            result.setFormatDetails(formatResult.getIssues());

            // C. 必填字段完整性
            CompletenessCheckResult completeResult = completenessChecker.check(
                task.getContentType(), task.getContentSnapshot());
            result.setCompletenessCheck(completeResult.isPassed() ? "passed" : "warning");
            result.setWarnings(completeResult.getWarnings());

            // D. 知识点关联校验（如有）
            if (task.getContentSnapshot().containsKey("knowledgePointIds")) {
                KnowledgeConsistencyCheckResult kpResult = 
                    knowledgeChecker.checkConsistency(task.getContentSnapshot());
                result.setKnowledgeCheck(kpResult.isPassed() ? "passed" : "warning");
            }

            // 更新任务
            task.setPrecheckResult(JsonUtils.toJson(result));
            task.setPrecheckAt(Instant.now());

            boolean precheckPassed = "passed".equals(result.getSafetyCheck())
                && "passed".equals(result.getFormatCheck());
            task.setPrecheckPassed(precheckPassed);

            if (precheckPassed) {
                advanceToLevel(task, 1, template);
            } else if (template.isAutoRejectEnabled()) {
                task.setStatus(ReviewTaskStatus.PRECHECK_FAILED);
                taskRepo.save(task);
                // 通知提交人
                notifySubmitter(task, "预筛未通过", result);
            } else {
                // 预筛未通过但不自动驳回，标记警告后仍进入审核
                advanceToLevel(task, 1, template);
            }
        } catch (Exception e) {
            log.error("预筛异常, taskId={}", task.getId(), e);
            // 预筛异常时保守处理：进入人工审核
            advanceToLevel(task, 1, template);
        }
    }
}
```

### 5.2 智能审核员匹配

```java
@Service
public class ReviewerMatchService {

    @Autowired
    private ReviewerProfileRepository reviewerRepo;

    /**
     * 为审核任务匹配最合适的审核员
     * 
     * 策略优先级：
     * 1. 技能匹配（学科 + 内容类型 + 学段）
     * 2. 负载均衡（当前任务数 < 最大并发数，当日任务 < 每日上限）
     * 3. 效率优先（平均审核耗时短）
     * 4. 轮转公平（上次分配时间最久的人优先）
     */
    public Optional<ReviewerProfile> matchReviewer(
            ContentReviewTask task, int reviewLevel) {
        
        String subject = task.getContentSnapshot().getOrDefault("subject", "").toString();
        String grade = task.getContentSnapshot().getOrDefault("grade", "").toString();
        String contentType = task.getContentType();

        // 查询满足条件的审核员，按优先级排序
        List<ReviewerProfile> candidates = reviewerRepo.findAvailableReviewers(
            contentType, subject, grade, reviewLevel);

        if (candidates.isEmpty()) {
            log.warn("无可用审核员: contentType={}, subject={}, level={}", 
                contentType, subject, reviewLevel);
            return Optional.empty();
        }

        // 打分排序
        candidates.sort((a, b) -> {
            // 1. 负载因子（越少越好）
            double loadA = a.getCurrentTaskCount() * 1.0 / a.getMaxConcurrentTasks();
            double loadB = b.getCurrentTaskCount() * 1.0 / b.getMaxConcurrentTasks();
            int loadCmp = Double.compare(loadA, loadB);
            if (loadCmp != 0) return loadCmp;

            // 2. 准确率因子（越高越好）
            double accA = a.getAccuracyRate() != null ? a.getAccuracyRate() : 0.8;
            double accB = b.getAccuracyRate() != null ? b.getAccuracyRate() : 0.8;
            int accCmp = Double.compare(accB, accA);
            if (accCmp != 0) return accCmp;

            // 3. 上次分配时间（越久越好）
            long agoA = a.getLastAssignedAt() != null ? 
                Duration.between(a.getLastAssignedAt(), Instant.now()).toMinutes() : Long.MAX_VALUE;
            long agoB = b.getLastAssignedAt() != null ? 
                Duration.between(b.getLastAssignedAt(), Instant.now()).toMinutes() : Long.MAX_VALUE;
            return Long.compare(agoB, agoA);
        });

        return Optional.of(candidates.get(0));
    }
}
```

```sql
SELECT rp.*
FROM reviewer_profile rp
LEFT JOIN LATERAL (
    SELECT COUNT(*) AS cnt
    FROM review_assignment ra
    JOIN content_review_task crt ON ra.task_id = crt.id
    WHERE ra.reviewer_id = rp.user_id
      AND ra.status IN ('accepted', 'in_progress')
      AND crt.status NOT IN ('approved', 'rejected', 'withdrawn')
) active ON TRUE
LEFT JOIN LATERAL (
    SELECT COUNT(*) AS cnt
    FROM review_assignment ra
    WHERE ra.reviewer_id = rp.user_id
      AND ra.created_at >= CURRENT_DATE
) daily ON TRUE
WHERE rp.is_active = TRUE
  AND rp.on_duty = TRUE
  AND rp.max_review_level >= :reviewLevel
  AND rp.reviewable_content_types @> to_jsonb(:contentType::text)
  AND (rp.reviewable_subjects @> to_jsonb(:subject::text) OR rp.reviewable_subjects = 'null'::jsonb)
  AND active.cnt < rp.max_concurrent_tasks
  AND daily.cnt < rp.max_daily_tasks
ORDER BY rp.last_assigned_at ASC NULLS FIRST
LIMIT 20;
```

### 5.3 审核意见提交与流转

```java
@Service
public class ReviewVerdictService {

    /**
     * 提交审核结论
     */
    @Transactional
    public ReviewResultDTO submitVerdict(Long taskId, ReviewVerdictRequest request) {
        ContentReviewTask task = taskRepo.findById(taskId)
            .orElseThrow(() -> new BusinessException(ErrorCode.REVIEW_TASK_NOT_FOUND));

        ReviewAssignment assignment = assignmentRepo.findById(request.getAssignmentId())
            .orElseThrow(() -> new BusinessException(ErrorCode.REVIEW_ASSIGNMENT_NOT_FOUND));

        // 校验：当前用户必须是分配的审核员
        if (!assignment.getReviewerId().equals(SecurityContext.getCurrentUserId())) {
            throw new BusinessException(ErrorCode.REVIEW_NOT_ASSIGNED_TO_YOU);
        }

        // 校验：任务状态必须是审核中
        if (!isInReviewStatus(task)) {
            throw new BusinessException(ErrorCode.REVIEW_TASK_NOT_IN_REVIEW);
        }

        // 保存审核意见
        List<ReviewOpinion> opinions = request.getOpinions().stream()
            .map(op -> {
                ReviewOpinion opinion = new ReviewOpinion();
                opinion.setAssignmentId(assignment.getId());
                opinion.setTaskId(taskId);
                opinion.setChecklistItemId(op.getChecklistItemId());
                opinion.setItemCode(op.getItemCode());
                opinion.setResult(op.getResult());
                opinion.setScore(op.getScore());
                opinion.setComment(op.getComment());
                opinion.setSuggestedFix(op.getSuggestedFix());
                opinion.setReviewerId(assignment.getReviewerId());
                return opinion;
            }).collect(Collectors.toList());
        opinionRepo.saveAll(opinions);

        // 更新分配状态
        assignment.setStatus("submitted");
        assignment.setVerdict(request.getVerdict());
        assignment.setSubmittedAt(Instant.now());
        assignmentRepo.save(assignment);

        // 根据结论流转任务状态
        switch (request.getVerdict()) {
            case "approved":
                handleApproved(task, assignment);
                break;
            case "rejected":
                handleRejected(task, assignment, request);
                break;
            case "needs_modification":
                handleNeedsModification(task, assignment);
                break;
            case "escalate":
                handleEscalate(task, assignment);
                break;
        }

        // 记录审计日志
        auditLogService.log(AuditAction.REVIEW_VERDICT, Map.of(
            "taskId", taskId,
            "level", assignment.getReviewLevel(),
            "verdict", request.getVerdict()
        ));

        return buildResult(task);
    }

    private void handleApproved(ContentReviewTask task, ReviewAssignment assignment) {
        int nextLevel = assignment.getReviewLevel() + 1;
        if (nextLevel <= task.getRequiredLevels()) {
            // 还有下一级审核
            advanceToLevel(task, nextLevel);
        } else {
            // 所有级别通过，标记为已通过
            task.setStatus(ReviewTaskStatus.APPROVED);
            task.setFinalVerdict("approved");
            task.setFinalVerdictBy(assignment.getReviewerId());
            task.setFinalVerdictAt(Instant.now());
            taskRepo.save(task);
            
            // 通知内容服务：内容审核通过，可以发布
            eventPublisher.publishEvent(new ContentApprovedEvent(
                task.getContentType(), task.getContentId(), task.getId()));
        }
    }

    private void handleRejected(ContentReviewTask task, ReviewAssignment assignment,
                                  ReviewVerdictRequest request) {
        task.setStatus(ReviewTaskStatus.REJECTED);
        task.setFinalVerdict("rejected");
        task.setFinalVerdictBy(assignment.getReviewerId());
        task.setFinalVerdictAt(Instant.now());
        taskRepo.save(task);
        
        // 通知提交人
        notifySubmitter(task, "内容未通过审核", request.getOverallComment());
    }

    private void handleNeedsModification(ContentReviewTask task, ReviewAssignment assignment) {
        // 回退到上一级等待修改后重新提交
        task.setCurrentLevel(Math.max(0, assignment.getReviewLevel() - 1));
        task.setStatus(ReviewTaskStatus.PRECHECK_FAILED); // 复用待修改状态
        taskRepo.save(task);
        
        notifySubmitter(task, "内容需要修改", "请根据审核意见修改后重新提交");
    }

    private void handleEscalate(ContentReviewTask task, ReviewAssignment assignment) {
        // 跳级至更高级别
        int escalateTo = Math.min(assignment.getReviewLevel() + 2, task.getRequiredLevels());
        task.setStatus(ReviewTaskStatus.ESCALATED);
        task.setCurrentLevel((int) escalateTo);
        taskRepo.save(task);
        advanceToLevel(task, escalateTo);
    }
}
```

```java
            log.info("举报导致内容修正: reportId={}, targetId={}", reportId, report.getTargetId());
        }
    }
}
```

## 6. 定时任务

### 6.1 SLA 超时检测与告警

```java
@Component
public class ReviewSlaMonitor {

    @Autowired private StringRedisTemplate redisTemplate;
    @Autowired private ContentReviewTaskRepository taskRepo;
    @Autowired private ReviewAssignmentRepository assignmentRepo;
    @Autowired private ContentReportRepository reportRepo;
    @Autowired private OutboxService outboxService;
    @Autowired private NotificationService notificationService;

    /**
     * 每 15 分钟检测一次 SLA 超时
     * cron: 0 */15 * * * ?
     */
    @Scheduled(cron = "0 */15 * * * ?")
    public void checkSlaBreaches() {
        // 多实例部署下使用分布式锁，防止重复扫描/重复告警
        String lockKey = "content-review:sla:scan:lock";
        String token = UUID.randomUUID().toString();
        Boolean acquired = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, token, Duration.ofMinutes(10));
        if (!Boolean.TRUE.equals(acquired)) {
            return;
        }
        try {
            scanTaskLevelSla();        // A. 任务级总 SLA
            scanAssignmentLevelSla();  // B. 分级别 SLA（提醒，回收见 §6.2）
            scanReportSla();           // C. 举报处理 SLA（48h）
        } finally {
            releaseLockSafely(lockKey, token);  // Lua: GET==token 才 DEL，防误删他人锁
        }
    }

    /** A. 任务级：终态之外且总截止时间已过的任务 */
    private void scanTaskLevelSla() {
        List<ContentReviewTask> breached =
                taskRepo.markBreachedAndReturn(Instant.now(), PageRequest.of(0, 500));
        for (ContentReviewTask task : breached) {
            escalatePriority(task);   // normal→high→critical 单向提升
            outboxService.save(OutboxEvent.of("review.sla.breached", task.getId(), Map.of(
                    "taskNo", task.getTaskNo(),
                    "contentType", task.getContentType(),
                    "contentId", task.getContentId(),
                    "currentLevel", task.getCurrentLevel(),
                    "priority", task.getPriority(),
                    "deadline", task.getSlaDeadline().toString())));
            notifyCurrentAssignee(task, "审核任务已超SLA，请立即处理");
        }
    }

    /** 优先级单向提升：low/normal→high；high→critical；critical 保持并双通道提醒 */
    private void escalatePriority(ContentReviewTask task) {
        String next = switch (task.getPriority()) {
            case "low", "normal" -> "high";
            case "high" -> "critical";
            default -> "critical";
        };
        task.setPriority(next);
        if ("critical".equals(next) && !"critical".equals(task.getPriority())) {
            // 首次升至 critical：站内 + IM 双通道触达审核组长
            notificationService.notifyReviewGroupLeader(task, NotifyChannel.IN_APP_AND_IM);
        }
        taskRepo.save(task);
    }

    /** B. 级别 SLA：分配后长时间未认领/未提交，先提醒（1.5×SLA 后由 §6.2 回收改派） */
    private void scanAssignmentLevelSla() {
        // B1. pending 超过 0.5×级别SLA 未认领 → 提醒审核员
        assignmentRepo.findPendingNearDeadline(0.5).forEach(a ->
                notificationService.notifyReviewer(a.getReviewerId(),
                        "任务已分配过久仍未认领，即将回收改派", a));
        // B2. in_progress 超过级别SLA 未提交 → 提醒
        assignmentRepo.findInProgressOverdue().forEach(a ->
                notificationService.notifyReviewer(a.getReviewerId(),
                        "任务已超本级别SLA，请尽快提交审核意见", a));
    }

    /** C. 举报处理 SLA：默认 48h 内办结 */
    private void scanReportSla() {
        List<ContentReport> breached = reportRepo.markBreachedAndReturn(Instant.now());
        for (ContentReport report : breached) {
            outboxService.save(OutboxEvent.of("report.sla.breached", report.getId(), Map.of(
                    "reportNo", report.getReportNo(),
                    "reasonCategory", report.getReasonCategory(),
                    "deadline", report.getSlaDeadline().toString())));
            notificationService.notifyReportOwner(report, "举报处理已超SLA（48h红线）");
        }
    }
}
```

```sql
WITH breached AS (

       SET sla_breached = TRUE,
```

### 6.2 审核卡单自动回收与改派

`in_review_*` 状态下长时间不提交意见的分配（审核员离职、遗忘、请假）会阻塞任务流转，需自动回收。

```java
@Component
public class ReviewAssignmentRecycler {

    /**
     * 每 30 分钟执行一次：回收超过 1.5×级别SLA 仍未提交的分配
     * cron: 0 */30 * * * ?
     */
    @Scheduled(cron = "0 */30 * * * ?")
    public void recycleStuckAssignments() {
        List<ReviewAssignment> stuck =
                assignmentRepo.findStuckBeyondFactor(1.5, PageRequest.of(0, 200));
        for (ReviewAssignment a : stuck) {
            // CAS 回收：仅当状态仍为 pending/in_progress 时生效
            // 与审核员提交意见（§5.3 中 assignment.status CAS）双向互斥，不会误回收
            int updated = assignmentRepo.casReassign(a.getId(), Instant.now());
            if (updated == 0) {
                continue;  // 审核员恰好同时提交，跳过
            }
            // 同任务同级别改派次数 >= 3 → 不再自动改派，升级人工
            int reassignCount = assignmentRepo.countByTaskAndLevel(
                    a.getTaskId(), a.getReviewLevel(), "reassigned");
            if (reassignCount >= 3) {
                escalateToLeader(a);   // 任务置 escalated + 通知组长在工作台手动指派
                continue;
            }
            // 重新匹配审核员（UNIQUE(task_id, review_level, reviewer_id) 保证不会改派回同一人）
            reviewerMatchService.matchReviewer(taskRepo.findById(a.getTaskId()).orElseThrow(),
                            a.getReviewLevel())
                    .ifPresentOrElse(
                            reviewer -> assignmentService.createAssignment(
                                    a.getTaskId(), a.getReviewLevel(), reviewer),
                            () -> escalateToLeader(a));  // 无人可派 → 升级
            outboxService.save(OutboxEvent.of("review.task.reassigned", a.getTaskId(),
                    Map.of("assignmentId", a.getId(), "level", a.getReviewLevel())));
        }
    }
}
```

回收 SQL（CAS 核心）：

```sql
UPDATE review_assignment
   SET status = 'reassigned', updated_at = NOW()
 WHERE id = :assignmentId
   AND status IN ('pending', 'in_progress');
```

| 规则 | 说明 |
|------|------|
| 回收阈值 | 分配后超过 1.5×级别 SLA 未提交（pending 未认领或 in_progress 未提交均适用） |
| 回收前置提醒 | 0.5×SLA 未认领、1.0×SLA 未提交各提醒一次（§6.1 B） |
| 改派上限 | 同任务同级别自动改派 ≤3 次，超出转 escalated 由组长人工指派 |
| 审核员侧影响 | 被回收计入当日统计（recycled_count），连续 3 次/周被回收自动降低次日分配权重并提醒 |
| 幂等与竞态 | CAS 状态更新 + 审核员提交同样以状态 CAS 抢占，二者互斥；事件按 assignmentId 幂等 |

### 6.3 审核员负载与绩效统计每日刷新

```sql
-- 每日 02:00 执行（cron: 0 0 2 * * ?），刷新 reviewer_profile 统计字段
WITH stat AS (
    SELECT ra.reviewer_id,
           COUNT(*) FILTER (WHERE ra.status = 'submitted')                          AS submitted_cnt,
           AVG(EXTRACT(EPOCH FROM (ra.submitted_at - ra.started_at)) / 60.0)        AS avg_minutes,
           COUNT(*) FILTER (WHERE ra.status = 'reassigned')                          AS recycled_cnt
    FROM review_assignment ra
    WHERE ra.created_at >= NOW() - INTERVAL '30 days'
    GROUP BY ra.reviewer_id
)
UPDATE reviewer_profile rp
   SET total_reviewed     = rp.total_reviewed + s.submitted_cnt,
       avg_review_minutes = ROUND(s.avg_minutes, 2),
       updated_at         = NOW()
  FROM stat s
 WHERE rp.user_id = s.reviewer_id;
```

准确率（accuracy_rate）口径——"被上级推翻比例"的反算：

```
accuracy_rate = 1 - overturn_count / approved_count

overturn_count：该审核员 180 天内 verdict=approved 的级别中，
                任务最终结论为 rejected（被更高级别驳回）的分配数
approved_count：该审核员 180 天内 verdict=approved 的分配数
```

| 规则 | 说明 |
|------|------|
| 最小样本量 | approved_count < 20 时保留旧值不更新（防止小样本抖动，对齐《学生知识掌握度数据可信度评估与最小样本量保障引擎》同类思路） |
| 权重影响 | accuracy_rate 直接进入 §5.2 匹配排序第二因子；< 0.70 连续两周 → 移出自动匹配池并通知组长复训 |
| 负载缓存 | 同时重建 Redis `reviewer:load:{userId}`（currentTaskCount），供 §5.2 匹配排序毫秒级读取；Redis 不可用时降级 DB 实时查询（§10 D8） |

### 6.5 终态任务治理与快照冷存

| 任务 | 规则 | 时间参数 |
|------|------|---------|
| 驳回未重提提醒 | rejected 且 allow_resubmit=true，无子版本任务 | 14 天首次提醒，其后每 7 天提醒一次 |
| 驳回任务关闭 | 仍无重提 | 30 天后保持 rejected 终态、停止提醒（数据不删，审计留存） |

```java
@Transactional
public ReviewTaskDTO resubmit(Long taskId, ResubmitRequest request) {
    ContentReviewTask old = taskRepo.findById(taskId)
            .orElseThrow(() -> new BusinessException(ErrorCode.REVIEW_TASK_NOT_FOUND)); // 55302

    // G1: 仅 rejected 且 allow_resubmit 的任务可重提
    if (!"rejected".equals(old.getStatus()) || !old.isAllowResubmit()) {
        throw new BusinessException(ErrorCode.RESUBMIT_NOT_ALLOWED);          // 55312
    }
    // G2: 内容必须发生变化（hash 判重）
    String newHash = ContentHashUtils.sha256(normalize(request.getContentSnapshot()));
    if (newHash.equals(old.getContentHash())) {
        throw new BusinessException(ErrorCode.CONTENT_VERSION_CONFLICT,      // 55320
                "内容未发生变化，无需重新提交");
    }
    // G3: 提交人必须为原任务提交人或其同组编辑
    if (!canResubmit(old, SecurityContext.getCurrentUserId())) {
        throw new BusinessException(ErrorCode.REVIEW_NOT_ASSIGNED_TO_YOU);   // 55304 复用越权语义
    }

    try {
        ContentReviewTask task = buildResubmitTask(old, request, newHash);
        // G4: uq_review_task_active_content 兜底（old 已终态不会冲突；
        //     拦截并发重复点击/同内容其他来源在办任务）
        taskRepo.save(task);
        return toDTO(task);
    } catch (DuplicateKeyException e) {
        throw new BusinessException(ErrorCode.ACTIVE_TASK_EXISTS);            // 55313
    }
}

private ContentReviewTask buildResubmitTask(ContentReviewTask old,
                                             ResubmitRequest req, String newHash) {
    ContentReviewTask t = new ContentReviewTask();
    t.setParentTaskId(old.getId());
    t.setContentType(old.getContentType());
    t.setContentId(old.getContentId());
    t.setContentVersion(old.getContentVersion() + 1);   // 版本链 +1
    t.setContentSnapshot(req.getContentSnapshot());
    t.setContentHash(newHash);
    t.setChangelog(req.getChangelog());
    t.setSource(old.getSource());                        // 来源继承（user_report 保持）
    t.setSubmitterId(SecurityContext.getCurrentUserId());
    t.setTemplateId(old.getTemplateId());
    t.setRequiredLevels(old.getRequiredLevels());
    t.setPriority(old.getPriority());                    // 举报任务保持 high/critical
    t.setReportId(old.getReportId());                    // 举报关联继承，闭环不丢失
    // status=pending_precheck，重新走完整预筛+多级审核
    return t;
}
```

### 7.4 needs_modification 语义澄清与 v1.1 收敛

v1.0 §5.3 `handleNeedsModification` 将"需修改"任务状态置为 `PRECHECK_FAILED`，与"预筛未通过"语义混淆，且未定义重提路径。v1.1 收敛口径：

| 项 | v1.1 口径 |
|----|----------|
| 落库语义 | 审核员选 needs_modification 时，任务按 **rejected + allow_resubmit=true** 落库（终态），assignment.verdict 保留 `needs_modification` 判定记录 |
| 重提路径 | 修改后统一走 §7.2 resubmit（version+1、版本链可追溯） |
| 状态机兼容 | §4 状态机不变：`PRECHECK_FAILED` 仅表示预筛未通过终态，不再复用 |
| 通知差异 | needs_modification 通知文案为"需修改后重新提交"，携带全部 suggested_fix；与 rejected（直接驳回）区分 |
| 存量迁移 | 若已按 v1.0 语义上线：迁移脚本将 status=precheck_failed 且存在 verdict=needs_modification assignment 的任务统一置 rejected（allow_resubmit=true），按 task_no 分批幂等执行 |

```sql
    aggregate_type VARCHAR(30) NOT NULL,
    aggregate_id   BIGINT NOT NULL,
    payload        JSONB NOT NULL,
    status         VARCHAR(15) NOT NULL DEFAULT 'pending',  -- pending/dispatched/dead
    retry_count    SMALLINT NOT NULL DEFAULT 0,
    next_retry_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    dispatched_at  TIMESTAMPTZ
);

CREATE INDEX idx_outbox_dispatch ON content_review_outbox(status, next_retry_at)
    WHERE status = 'pending';
```

所有审核状态变更与 Outbox 写入**同事务**（本地消息表模式），保证"结论落库必发事件"。

### 8.3 approved → 内容生效联动时序

```
审核员末级通过 ──► 任务 APPROVED（同事务写 Outbox）
                      │
                      ▼
             Relay 派发(≤5s) ──► MQ topic: review.content
                      │
                      ▼
         内容服务消费 review.task.approved
           1. 幂等检查 content_effect_log(task_id) 已存在则直接 ACK
           2. CAS 内容状态 review_pending → published
           3. 回执 ACK；处理异常 → NACK 重试（指数退避，≥5 次进死信）
                      │
                      ▼
         死信告警(P2) → 人工介入（审核结论已持久化在任务表，不丢失）
```

关键设计：**审核结论落库与内容生效解耦**。内容服务不可用不影响审核吞吐；恢复后 Relay 重放 pending 事件即可（至少一次投递 + 消费端 `(task_id)` 幂等，保证不重复生效）。

### 8.4 派发器与对账

- Relay：`@Scheduled(fixedDelay = 5000)` 批量拉取 200 条 pending → 同步发 MQ 成功后置 dispatched；失败 `retry_count+1`、`next_retry_at = now + 2^n × 30s`（n≤5），超 5 次置 dead + P2 告警。
- 每日对账 Job：`dispatched` 计数 vs MQ 回执计数 vs 消费方 `content_effect_log` 计数，三方差异 > 0.1% 告警，并按事件清单重放差异事件。

## 12. 容量与性能估算

- **提交量**：日常约 5,000 任务/日（题目 2,000 / 解析 1,500 / 知识点讲解 500 / AI 沉淀 800 / 举报触发 200），批量导入高峰日 20,000（走批量入口 + 夜间削峰）。
- **任务表**：年增约 180 万行，按月分区（created_at）；assignment / opinion 分别约 2.5× / 6× 任务量。
- **存储**：JSONB 快照均值 8KB，热存 180 天 ≈ 180 万 × 2.5 版本系数 × 8KB ≈ 3.6GB，单库可承载；180 天后冷存释放主库。
- **并发与延迟**：并发审核员约 80 人，工作台 QPS < 50；任务列表 / 详情接口 P99 < 300ms（idx_review_task_status + idx_assignment_reviewer 覆盖）。
- **预筛吞吐**：日常 5,000/日 × 峰值集中度 3 ≈ 10 TPS 即可消化（异步线程池 reviewPrecheckExecutor 建议 core=8/max=16，队列 1000，拒绝时降级 D2）。
