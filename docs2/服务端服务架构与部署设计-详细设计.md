# 服务端服务架构与部署 - 详细设计

> 模块版本：v1.0 | 最后更新：2026-05-19
> 原始需求来源：`docs/design/启硕-PrimeTop-全学段AI辅助学习软件项目设计文档.md` §8.4

## 1. 模块概述

### 1.1 定位

服务端服务架构是 PrimeTop 后端的骨架，定义各业务服务的边界、职责、通信方式、数据隔离策略、部署拓扑和运维保障机制。本文档为后端团队提供明确的服务拆分方案和技术选型，使各模块（用户、AI、题目、错题、支付等）可以独立开发、测试和部署。

### 1.2 设计原则

1. **模块化单体起步，按需拆微服务**：MVP 阶段采用单体模块化架构（Modular Monolith），同一进程内按模块划分边界代码，为后续拆分预留接口契约。
2. **接口先行**：跨服务调用必须通过明确定义的 API 接口（REST/gRPC），禁止直接访问其他服务的数据库。
3. **数据隔离**：每个服务拥有自己的数据Schema，跨服务数据通过API聚合或事件同步。
4. **可观测性**：统一日志、指标、链路追踪标准，任何服务上线必须接入。
5. **渐进演进**：架构支持从单体到微服务的平滑迁移，不提前引入不必要的分布式复杂度。

### 1.3 术语定义

| 术语 | 含义 |
|------|------|
| 模块 (Module) | 单体应用内的业务边界单元，对应独立包/命名空间 |
| 服务 (Service) | 独立部署的业务单元，拥有独立进程和数据 |
| 网关 (Gateway) | 统一入口，负责路由、鉴权、限流、日志 |
| 事件 (Event) | 异步消息，用于跨服务解耦 |

## 2. 服务拆分方案

### 2.1 服务清单

| 服务名 | 职责 | MVP阶段 | 对应详细设计文档 |
|--------|------|---------|----------------|
| `gateway` | API 网关：路由、鉴权、限流、协议转换 | 独立进程 | API网关与通用接口规范 |
| `user-service` | 用户注册登录、学生档案、家长绑定、权限 | 模块 | 用户账号体系 |
| `ai-service` | 大模型调用、Prompt 编排、模型路由、降级 | 模块 | AI智能辅导 |
| `question-service` | 题目OCR识别、题库检索、解析生成、类题推荐 | 模块 | 拍照搜题与习题答疑 |
| `learning-service` | 学习记录、章节进度、学习会话 | 模块 | 同步课堂学习 |
| `mistake-service` | 错题收录、错因标签、复习计划、遗忘曲线 | 模块 | 错题整理 |
| `plan-service` | 学习目标、计划生成、任务管理、提醒调度 | 模块 | 学习规划 |
| `content-service` | 教材、知识点、考点、题库资源管理 | 模块 | 内容与运营后台 |
| `analytics-service` | 学情分析、能力画像、运营看板、数据聚合 | 模块 | 学情分析 |
| `payment-service` | 会员管理、订单、支付渠道、权益校验 | 模块 | 支付与会员订阅 |
| `notification-service` | 消息模板、推送调度、多渠道发送 | 模块 | 消息与推送服务 |
| `rag-service` | 向量检索、知识库管理、知识图谱 | 模块 | RAG与知识库系统 |
| `safety-service` | 内容安全审核、合规检查 | 模块 | 安全与内容合规系统 |

### 2.2 MVP 阶段架构（模块化单体）

### 2.3 演进路线（V2.0 微服务拆分）

当用户量达到日活 10 万+或团队超过 15 人时，按以下优先级拆分为独立服务：

| 拆分阶段 | 目标服务 | 拆分原因 |
|---------|---------|---------|
| Phase 1 | `ai-service` | 调用频次高、外部依赖重、独立扩缩容需求强 |
| Phase 1 | `question-service` | OCR计算密集、与AI服务紧密协同 |
| Phase 2 | `payment-service` | 金融合规、数据隔离要求高 |
| Phase 2 | `notification-service` | 推送量大、需要异步处理 |
| Phase 3 | `content-service` | 内容管理独立、后台使用 |
| Phase 3 | `analytics-service` | 计算密集、可独立扩展 |
| Phase 4 | 其余模块 | 视业务压力决定 |

## 3. 技术选型

### 3.1 核心技术栈

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| 语言 | Python 3.11+ | AI 生态成熟，团队上手快 |
| Web 框架 | FastAPI | 异步高性能，自带 OpenAPI 文档 |
| 任务队列 | Celery + Redis | 异步任务（解析生成、报告计算、推送调度） |
| ORM | SQLAlchemy 2.0 (async) | 成熟稳定，支持异步 |
| 数据库迁移 | Alembic | 与 SQLAlchemy 集成 |
| API 网关 | Nginx + Kong（或 APISIX） | MVP 阶段 Nginx 即可，后续按需升级 |
| 消息队列 | Redis Streams（MVP）→ RabbitMQ/Kafka（V2） | MVP 用 Redis 轻量方案 |
| 配置管理 | pydantic-settings | 类型安全的配置管理 |

### 3.2 数据存储选型

| 数据类型 | 存储 | 版本/规格建议 |
|---------|------|-------------|
| 业务数据 | PostgreSQL 15+ | 主库，支持 JSONB、全文搜索 |
| 缓存/会话 | Redis 7+ | Sentinel 高可用 |
| 向量检索 | pgvector（MVP）→ Milvus（V2） | MVP 阶段复用 PG |
| 搜索引擎 | PostgreSQL tsvector（MVP）→ Elasticsearch（V2） | 初期不引入额外组件 |
| 对象存储 | 阿里云 OSS / 腾讯云 COS | 图片、语音、资源文件 |
| 行为日志 | 应用日志写文件 → ClickHouse（V2） | MVP 阶段直接写 PG |

### 3.3 第三方服务选型

| 服务 | 推荐供应商 | 备选 |
|------|-----------|------|
| OCR 识别 | 百度 OCR / 阿里云 OCR | 腾讯云 OCR、Mathpix（数学公式） |
| ASR 语音识别 | 讯飞开放平台 | 阿里云智能语音、腾讯云 ASR |
| TTS 语音合成 | 讯飞开放平台 | 阿里云 TTS |
| Push 推送 | 极光推送 (JPush) | 个推、友盟推送 |
| 短信 | 阿里云短信 | 腾讯云 SMS |
| 支付 | 微信支付 + 支付宝 | 苹果 IAP |

### 4.2 模块内分层规范

每个模块严格遵循四层架构：

```python
# modules/user/router.py — 路由层：只负责HTTP协议转换
@router.post("/register", response_model=UserRegisterResponse)
async def register(
    req: UserRegisterRequest,
    svc: UserService = Depends(get_user_service),
):
    return await svc.register(req)

# modules/user/service.py — 业务层：核心业务逻辑
class UserService:
    async def register(self, req: UserRegisterRequest) -> UserRegisterResponse:
        # 检查手机号是否已注册
        existing = await self.repo.get_by_phone(req.phone)
        if existing:
            raise BizException(ErrCode.USER_ALREADY_EXISTS)
        # 创建用户
        user = await self.repo.create(...)
        # 发送欢迎消息（通过事件总线解耦）
        self.event_bus.emit("user.registered", {"user_id": user.id})
        return UserRegisterResponse(...)

# modules/user/repository.py — 数据层：数据库操作
class UserRepository:
    async def get_by_phone(self, phone: str) -> User | None:
        stmt = select(User).where(User.phone == phone)
        result = await self.db.execute(stmt)
        return result.scalar_one_or_none()

# modules/user/models.py — ORM 模型
class User(Base):
    __tablename__ = "users"
    id = Column(BigInteger, primary_key=True)
    phone = Column(String(20), unique=True, nullable=False)
    ...
```

### 4.3 跨模块调用规范

模块间调用必须通过 Service 接口，禁止直接 import 其他模块的 repository 或 models：

```python
# ✅ 正确：通过服务接口调用
class MistakeService:
    def __init__(self, question_service: QuestionService):
        self.question_svc = question_service

    async def add_mistake(self, question_id: int, ...):
        question = await self.question_svc.get_question(question_id)

# ❌ 错误：直接访问其他模块数据层
from primetop.modules.question.repository import QuestionRepository
class MistakeService:
    async def add_mistake(self, question_id: int):
        repo = QuestionRepository(self.db)
        question = await repo.get_by_id(question_id)  # 禁止！
```

依赖注入注册（`deps.py`）：

```python
# primetop/deps.py
from primetop.modules.user.service import UserService
from primetop.modules.question.service import QuestionService
from primetop.modules.mistake.service import MistakeService

def get_user_service(db: AsyncSession = Depends(get_db)) -> UserService:
    repo = UserRepository(db)
    return UserService(repo=repo)

def get_question_service(db: AsyncSession = Depends(get_db)) -> QuestionService:
    repo = QuestionRepository(db)
    return QuestionService(repo=repo)

def get_mistake_service(
    db: AsyncSession = Depends(get_db),
    question_svc: QuestionService = Depends(get_question_service),
) -> MistakeService:
    repo = MistakeRepository(db)
    return MistakeService(repo=repo, question_service=question_svc)
```

```python
import asyncio
from collections import defaultdict
from typing import Callable, Any
import logging

logger = logging.getLogger(__name__)


class EventBus:
    """进程内事件总线，用于模块间异步解耦"""

    _handlers: dict[str, list[Callable]] = defaultdict(list)
    _instance: "EventBus | None" = None

    @classmethod
    def initialize(cls):
        cls._instance = cls()

    @classmethod
    def get(cls) -> "EventBus":
        if cls._instance is None:
            raise RuntimeError("EventBus not initialized")
        return cls._instance

    def subscribe(self, event_type: str, handler: Callable):
        self._handlers[event_type].append(handler)

    async def emit(self, event_type: str, payload: dict[str, Any]):
        handlers = self._handlers.get(event_type, [])
        for handler in handlers:
            try:
                if asyncio.iscoroutinefunction(handler):
                    await handler(payload)
                else:
                    handler(payload)
            except Exception as e:
                logger.error(f"Event handler error: {event_type} -> {handler.__name__}: {e}")
```

```python
# V2: 跨服务事件发布（示例）
import json
import redis.asyncio as redis

class EventPublisher:
    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client

    async def publish(self, event_type: str, payload: dict, trace_id: str = ""):
        message = {
            "type": event_type,
            "payload": payload,
            "trace_id": trace_id,
            "timestamp": datetime.utcnow().isoformat(),
        }
        await self.redis.xadd(
            f"events:{event_type}",
            {"data": json.dumps(message, ensure_ascii=False)},
        )


class EventConsumer:
    """各服务启动时，订阅感兴趣的事件流"""

    async def consume(self, service_name: str, event_type: str, handler):
        stream_key = f"events:{event_type}"
        group_name = f"consumer:{service_name}"
        # 创建消费者组（幂等）
        try:
            await self.redis.xgroup_create(stream_key, group_name, id="0", mkstream=True)
        except redis.ResponseError:
            pass  # group already exists

        while True:
            messages = await self.redis.xreadgroup(
                group_name, service_name, {stream_key: ">"}, count=10, block=5000
            )
            for stream, msgs in messages:
                for msg_id, data in msgs:
                    try:
                        await handler(json.loads(data[b"data"]))
                        await self.redis.xack(stream_key, group_name, msg_id)
                    except Exception as e:
                        logger.error(f"Event consume error: {e}")
```

```python
    """结构化日志格式"""

        log_entry = {
            "timestamp": self.formatTime(record, self.datefmt),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "line": record.lineno,
        }
        # 附加请求上下文

            log_entry["request_id"] = record.request_id
        if hasattr(record, "user_id"):
            log_entry["user_id"] = record.user_id
        if hasattr(record, "trace_id"):
            log_entry["trace_id"] = record.trace_id

        if record.exc_info and record.exc_info[1]:
            log_entry["exception"] = self.formatException(record.exc_info)

        return json.dumps(log_entry, ensure_ascii=False)
```

### 10.2 请求链路追踪中间件

```python
# primetop/core/middleware.py
import time
import uuid
import logging
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import Response

logger = logging.getLogger("primetop.request")


class RequestLogMiddleware(BaseHTTPMiddleware):
    """请求日志 + 链路 ID + 耗时统计"""

    async def dispatch(self, request: Request, call_next) -> Response:
        request_id = request.headers.get("X-Request-ID", str(uuid.uuid4()))
        start = time.monotonic()

        # 将 request_id 注入到 state，后续可传递
        request.state.request_id = request_id

        response = await call_next(request)

        duration_ms = (time.monotonic() - start) * 1000

        # 记录请求日志
        logger.info(
            f"{request.method} {request.url.path} "
            f"status={response.status_code} "
            f"duration={duration_ms:.1f}ms",
            extra={
                "request_id": request_id,
                "method": request.method,
                "path": str(request.url.path),
                "status_code": response.status_code,
                "duration_ms": round(duration_ms, 1),
            },
        )

        response.headers["X-Request-ID"] = request_id
        return response
```

### 11.1 JWT 鉴权依赖

```python
# primetop/core/security.py
from datetime import datetime, timedelta
from jose import jwt, JWTError
from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
from primetop.config import get_settings

settings = get_settings()
security = HTTPBearer()


def create_access_token(user_id: int, extra: dict = None) -> str:
    expire = datetime.utcnow() + timedelta(minutes=settings.JWT_ACCESS_TOKEN_EXPIRE_MINUTES)
    payload = {"sub": str(user_id), "exp": expire, "type": "access"}
    if extra:
        payload.update(extra)
    return jwt.encode(payload, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM)


def create_refresh_token(user_id: int) -> str:
    expire = datetime.utcnow() + timedelta(days=settings.JWT_REFRESH_TOKEN_EXPIRE_DAYS)
    payload = {"sub": str(user_id), "exp": expire, "type": "refresh"}
    return jwt.encode(payload, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM)


async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(security),
) -> dict:
    """从 JWT 提取当前用户信息"""
    token = credentials.credentials
    try:
        payload = jwt.decode(token, settings.JWT_SECRET_KEY, algorithms=[settings.JWT_ALGORITHM])
        if payload.get("type") != "access":
            raise HTTPException(status_code=401, detail="Invalid token type")
        return {
            "user_id": int(payload["sub"]),
            "device_id": payload.get("device_id"),
        }
    except JWTError:
        raise HTTPException(status_code=401, detail="Token expired or invalid")


# 可选鉴权（不强制，匿名也可访问）
async def get_optional_user(
    credentials: HTTPAuthorizationCredentials = Depends(HTTPBearer(auto_error=False)),
) -> dict | None:
    if credentials is None:
        return None
    try:
        return await get_current_user(credentials)
    except HTTPException:
        return None
```

## 12. CI/CD 流水线

### 12.1 GitHub Actions

```yaml
# .github/workflows/ci.yml
name: PrimeTop CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:15-alpine
        env:
          POSTGRES_DB: primetop_test
          POSTGRES_USER: primetop
          POSTGRES_PASSWORD: primetop
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
      redis:
        image: redis:7-alpine
        ports:
          - 6379:6379

    steps:
      - uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: "pip"

      - name: Install dependencies
        run: |
          pip install poetry
          poetry install

      - name: Lint
        run: |
          poetry run ruff check primetop/
          poetry run mypy primetop/ --ignore-missing-imports

      - name: Test
        env:
          DATABASE_URL: postgresql+asyncpg://primetop:primetop@localhost:5432/primetop_test
          REDIS_URL: redis://localhost:6379/0
          JWT_SECRET_KEY: test-secret
        run: |
          poetry run pytest tests/ -v --tb=short -x

  build:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4

      - name: Login to Registry
        uses: docker/login-action@v3
        with:
          registry: ${{ secrets.DOCKER_REGISTRY }}
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Build and Push
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: |
            ${{ secrets.DOCKER_REGISTRY }}/primetop-server:${{ github.sha }}
            ${{ secrets.DOCKER_REGISTRY }}/primetop-server:latest
```

## 14. 服务拆分检查清单

当决定将某个模块从单体拆分为独立微服务时，需完成以下检查：

| 检查项 | 说明 | 状态 |
|--------|------|------|
| API 边界确认 | 模块所有对外调用已通过 REST/gRPC 接口 | ☐ |
| 数据库拆分 | 模块拥有独立数据库，无跨库 JOIN | ☐ |
| 事件替代同步调用 | 模块间非实时调用改为事件驱动 | ☐ |
| 配置独立 | 模块有独立配置文件和环境变量 | ☐ |
| 独立 Dockerfile | 可独立构建镜像 | ☐ |
| 独立测试 | 单元测试 + 集成测试不依赖其他服务 | ☐ |
| 健康检查 | 模块有独立 `/health` 端点 | ☐ |
| 链路追踪 | 服务间调用携带 trace_id | ☐ |
| 灰度策略 | 支持流量比例切换新旧服务 | ☐ |
| 回滚方案 | 可快速切回单体版本 | ☐ |

## 15. 容量规划

### 15.1 MVP 阶段资源估算

| 资源 | 配置 | 预期容量 |
|------|------|---------|
| 应用服务器 | 4C8G × 1 | 日活 5000 用户 |
| PostgreSQL | 4C8G × 1 (RDS) | 100 万条记录 |
| Redis | 2G × 1 | 缓存 + 会话 + 队列 |
| 对象存储 | 按量付费 | 图片/语音/资源 |
| AI 调用 | 按量付费 | 预估 5 万次/日 |

### 15.2 扩容阈值

| 指标 | 触发扩容 | 扩容动作 |
|------|---------|---------|
| CPU 使用率 | > 70% 持续 5 分钟 | 增加应用实例 |
| 请求延迟 P99 | > 3s | 增加应用实例 / 优化慢查询 |
| DB 连接池使用率 | > 80% | 增大连接池 / 读写分离 |
| Redis 内存 | > 80% | 扩容 / 清理过期数据 |
| AI 调用延迟 | > 10s P99 | 检查模型状态 / 切换降级 |
| 磁盘使用 | > 80% | 扩容 / 归档历史数据 |

## 16. 关键风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| AI 模型供应商宕机 | 全平台无法辅导 | 多供应商降级链，缓存常见问答 |
| 数据库单点故障 | 全平台不可用 | PG 主从复制，定期备份，RDS 自动故障切换 |
| 图片上传量大 | 存储成本高 | 图片压缩，OSS 生命周期管理 |
| 高并发拍题 | 服务器过载 | 限流排队，OCR 结果缓存 |
| 单体代码耦合 | 迭代效率下降 | 严格模块边界，接口隔离，定期 review |
