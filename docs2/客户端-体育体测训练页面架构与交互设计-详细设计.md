- 版本: v1.0

## 1. 概述

### 1.1 模块定位

本文档是体育体测训练域(Fitness Training Engine, FTE)的客户端呈现层与**端侧计数权威层**设计,兑现服务端契约:

- §1.4 权威边界:"姿态估计与实时计数 = 客户端(端侧引擎,见《客户端-…》,本引擎只约定上报协议)";
- §3.4 端侧上报协议(骨架关键点)的客户端实现细则;
- §10 降级矩阵"端侧引擎在低配机不可用 → 客户端降级为「节拍引导+手动计数」模式"的客户端落地。

覆盖四种计数模式在 Flutter 客户端的完整实现:

| 计数模式 | 项目 | 客户端职责 |
| --- | --- | --- |
| VISION | 跳绳/仰卧起坐/俯卧撑/深蹲/高抬腿/引体向上 | 相机帧→姿态估计→动作周期判定→实时计数→计数事件上报 |
| VISION_ASSIST | 坐位体前屈 | 相机辅助标尺+手动确认读数 |
| MANUAL | 肺活量/立定跳远 | 表单录入(可对接蓝牙体测设备) |
| TIMING | 50米跑/800米/1000米 | 秒表计时(分段计时)+原始秒数录入 |

经全目录关键词扫描(2026-11-23)确认:服务端《体育体测训练引擎》就绪(批次二十九),客户端页面层零覆盖(相机计数页/模拟考编排页/体测档案页/手动录入页均无设计),本文补齐。

### 1.2 设计原则

1. **端侧优先、服务端权威**:计数在端侧实时完成(离线可用),评分/等级/档案/防作弊全部归服务端;客户端任何界面不得展示未经服务端确认的分数(G8 对端红线)。
2. **影像零出端**:原始视频/图像帧在端侧 SDK 输出层物理剥离,仅骨架关键点(33 点 x/y/z/visibility)可进入上报管道;本地缓存零图像文件(合规 C1 对端红线)。
3. **seq 单调、乱序可补偿**:计数事件严格单调递增,弱网本地队列按 seq 补传,服务端以 lastSeq 回放补偿为权威。
4. **防沉迷 fail-closed 呈现**:48010/48011 为硬阻断,客户端禁本地时间裁决、禁提供重试绕过按钮。
5. **防作弊客户端不裁决**:设备静止检测、频率分布异常等判作弊逻辑全部归服务端;客户端只如实上报数据,禁自行提示"疑似作弊"类话术(48041 提示文案由服务端下发)。
6. **健康数据默认私密**:成绩单/趋势页默认仅本人与家长可见;分享必须二次确认且成绩图脱敏(对齐服务端 §12)。
7. **低配可降级**:端侧引擎不可用时降级「节拍引导+手动计数」,训练记录仍成立(质量分 N/A),不阻塞主链路。

### 1.3 职责边界(客户端不做)

| 不做的事 | 权威归属 |
| --- | --- |
| 评分换算/等级判定/及格线计算 | 服务端 ScoreConverter(标准表 GB-2026-01 唯一权威) |
| 计数校准/抽样复核/校准系数 | 服务端 CountCalibrator |
| 防作弊判定与成绩撤销 | 服务端 AntiCheatGuard + 管理端 |
| 训练计划生成/每日任务派发 | 服务端 PlanScheduler + 每日任务服务 |
| 体测档案写入/趋势斜率/达标风险 | 服务端 ArchiveWriter(客户端 /archive 只读消费) |
| 防沉迷时段/时长裁决 | 统一家长门+防沉迷体系(客户端只呈现) |
| 排行榜/同伴对比 | 本模块不存在任何排行接口与组件(健康敏感数据) |

## 2. 信息架构与页面地图

### 2.1 路由表

| 路由 | 页面 | 入口 | 权限 |
| --- | --- | --- | --- |
| `/fitness` | 体测首页(项目卡/最近成绩/达标风险/训练入口) | 学习工作台"运动健康"分组卡片、深链接 | 学生,登录,适龄闸(小学及以上) |
| `/fitness/train/:sessionId` | 视觉计数训练页(相机预览+实时计数) | 项目卡"开始训练" | 学生,本人会话 |

| `/fitness/exam/:examId` | 模拟考执行页(当前项/进度/休息倒计时) | 组考成功 | 学生,本人考次 |

### 2.2 页面地图

```text
/fitness 首页
 ├─ 项目卡(N个项目)→ 按 CountMode 分发:
 │    VISION        → POST /sessions → /fitness/train/:sessionId
 │    TIMING        → POST /sessions → /fitness/timing/:sessionId
 │    MANUAL/VISION_ASSIST → POST /sessions → /fitness/manual/:sessionId
 ├─ 模拟体测 → POST /exams → /fitness/exam/:examId(顺序执行+休息守卫)
 │    → POST /exams/{id}/finish → /fitness/exam/:examId/result
 ├─ 体测档案 → /fitness/archive
 └─ 家长管控(角色切换)→ /parent/fitness

/fitness/train/:sessionId 视觉计数训练页
 ├─ 相机授权→姿态引擎初始化→3-2-1 倒计时→COUNTING
 ├─ 暂停(≤5次,48013 超限中性提示)→恢复→finish
 ├─ finish → 服务端校准(≤800ms)→ 结算弹层(分数/等级/成长话术)
 ├─ 48050(校准超时降级)→ 标注"已按本地计数记录(校准中)"
 ├─ 48010/48011(防沉迷/家长禁用)→ 休息引导页,禁重试按钮
 └─ 引擎不可用 → 降级「节拍引导+手动计数」(§8 D3)
```

### 2.3 页面状态规范

遵循《客户端页面状态模式与骨架屏加载空态错误态设计规范》:

| 态 | 呈现 |
| --- | --- |
| loading | 项目卡骨架;相机页黑屏+引擎初始化进度 |
| empty | 档案无数据:插画+"还没有体测记录,来测一次吧" |
| error | 网络错误:整页错误态+重试;**计数进行中网络错误不替换整页**(§8 D2 专线) |
| content | 正常训练界面 |

## 3. 数据模型与 API 契约

### 3.1 Dart 数据模型(与服务端响应 1:1)

```dart
enum FitProject {
  ropeSkipping, sitUp, sitAndReach, vitalCapacity, run50m, standingJump,
  pushUp, squat, highKnee, pullUp, run800m, run1000m,
}

enum FitCountMode { vision, visionAssist, manual, timing }

enum FitUnit { times, ml, cm, second }

enum FitSessionStatus { created, counting, paused, finished, calibrating, scored, archived, revoked }

enum FitGrade { excellent, good, pass, fail }

enum FitEventSource { appVision, manual, bleDevice, import }

enum FitExamItemState { pending, resting, ready, done, skipped }

/// 计数事件(端侧→服务端,协议 SSOT 归服务端 §3.4)
class FitCountEvent {
  final String sessionId;
  final int seq;               // 严格单调递增,弱网补传不重置
  final int count;
  final int cycleMs;           // 最近一个动作周期耗时
  final double qualityHint;    // 端侧质量提示 0-1,服务端参考
  final FitKpSample? kpSample; // 仅骨架关键点,≤64KB(硬限制)
  FitCountEvent({required this.sessionId, required this.seq, required this.count,
      required this.cycleMs, required this.qualityHint, this.kpSample});
  Map<String, dynamic> toJson() => {
    'sessionId': sessionId, 'seq': seq, 'count': count,
    'cycleMs': cycleMs, 'qualityHint': qualityHint,
    'kpSample': kpSample?.toJson(),
  };
}

/// 骨架关键点抽样:33关键点×frames帧,仅坐标,零像素
class FitKpSample {
  final int frames;
  final String pointsBase64; // BASE64(ZSTD( [ {t, kp:[33×(x,y,z,visibility)]} ] ))
  FitKpSample({required this.frames, required this.pointsBase64});
  Map<String, dynamic> toJson() =>
      {'frames': frames, 'points': pointsBase64, 'note': 'skeleton-only'};
}

/// 会话镜像(内存 + 轻量落盘仅恢复用,见 §6)
class FitSessionMirror {
  final String sessionId;
  final String sessionNo;
  final FitProject project;
  final FitCountMode mode;
  final String status;          // 镜像态,服务端为权威
  final String countStartToken; // X-Count-Token,会话级机密
  final int lastSeq;            // 已确认最大 seq
  final int localCount;         // 端侧实时计数(乐观)
  final DateTime? startedAt;
  final int pauseUsed;          // 已用暂停次数(镜像 G3)
  FitSessionMirror({required this.sessionId, required this.sessionNo,
      required this.project, required this.mode, required this.status,
      required this.countStartToken, required this.lastSeq,
      required this.localCount, this.startedAt, required this.pauseUsed});
}

class FitScoreBand {
  final double rawFrom, rawTo; final int score; final FitGrade grade;
  FitScoreBand({required this.rawFrom, required this.rawTo,
      required this.score, required this.grade});
}

  final String standardVer; final FitProject project;

  final List<FitScoreBand> bands;
  FitStandard({required this.standardVer, required this.project,
      required this.gradeYear, required this.gender,
      required this.passLine, required this.excellentLine, required this.bands});

  final FitSessionStatus status;
  final int clientCount; final double? calibratedCount; final double? qualityScore;
  final int antiCheatFlag; // 0正常 1可疑 2判作弊(客户端禁自行解读,只渲染服务端文案)
  final double raw; final int standardScore; final FitGrade grade;

  FitFinishResult({required this.status, required this.clientCount,

      required this.standardVer, required this.passLine,

class FitExamScheduleItem {
  final int index; final FitProject project; final int restSecondsAfter;
  FitExamScheduleItem({required this.index, required this.project,

}

class FitExamState {
  final String examId; final String status;
  final List<FitExamScheduleItem> schedule;
  final int currentIndex;             // 当前进行项

  FitExamState({required this.examId, required this.status,

class FitArchiveItem {
  final FitProject project;
  final double? latestRaw; final int? latestScore; final FitGrade? latestGrade;
  final double? bestRaw; final String? trend; final String? passRisk;
  final int totalSessions;
```

### 4.2 视觉计数训练页 `/fitness/train/:sessionId`

```
┌──────────────────────────────────────┐
│ 1分钟跳绳          目标:137(优秀线)  │
│ ┌──────────────────────────────────┐ │
│ │                                  │ │
│ │        相机预览(全屏)            │ │ ← 人体骨骼 overlay 仅本地渲染
│ │         ╲○╱  ← 骨架线            │ │   骨架帧禁入截图/录屏分享管线
│ │                                  │ │
│ └──────────────────────────────────┘ │
│           ┌──────────┐               │
│           │   136    │  ← 大字计数    │
│           └──────────┘               │
│  质量:●●●○○  节奏:580ms/个           │
│  [  暂停  ]        [  结束  ]        │
└──────────────────────────────────────┘
```

流程状态:引擎初始化 → 人体入镜校验(未检出骨骼连续 3s 提示"请全身入镜")→ 3-2-1 倒计时 → COUNTING(事件流上报)→ 用户暂停/恢复(≤5 次)→ 结束 → finish → 结算弹层。

交互规则:

- **计数乐观呈现**:端侧计数器即时 +1 并伴随轻震动/音效(可在设置关闭);服务端 `serverCount` 不回填界面(避免与服务端计数不一致引发困惑,校准结果只在结算呈现)。
- **pause**:倒计时暂停同时暂停事件上报流(seq 不增长,恢复后继续);镜像 pauseUsed+1,达 5 次后隐藏暂停按钮(服务端 G3 双保险,48013 兜底)。
- **finish**:二次确认弹层("本次计数 136 个,确定结束吗?");确认后进入 `FINISHING` 本地态(按钮禁点,防双击重复提交;重试复用 Idempotency-Key)。
- **结算弹层**:分数大数字呈现 + 等级徽章色(EXCELLENT 金/GOOD 蓝/PASS 绿/FAIL 灰)+ 与及格线差值成长话术("距优秀线还差 3 个,再练两次试试");`calibrated=false` 时附加灰字"成绩复核中,如有偏差将自动修正";`antiCheatFlag≠0` 时渲染服务端下发文案,客户端禁自造话术。
- **切后台**:自动暂停计数与事件流(防沉迷对齐:后台不计运动时长),回前台需手动恢复,不自动续计(G5 对端规则)。

### 4.3 计时项目页 `/fitness/timing/:sessionId`(50米/800米/1000米)

```
┌──────────────────────────────────────┐
│ 50米跑                               │
│ ┌──────────────────────────────────┐ │
│ │          00:00.0                 │ │ ← 大字秒表(本地计时,原始秒数提交)
│ │      (大字,远端不可读仍可用)     │ │
│ └──────────────────────────────────┘ │
│  [  开始  ] → [  到终点  ]           │
│  分段:—                              │
│  原始成绩录入: [______] 秒(人工复核) │
└──────────────────────────────────────┘
```

- 秒表为纯本地计时工具,权威成绩以用户确认录入的原始秒数提交;本地计时值自动填入录入框,用户可改(人工复核场景,如老师掐表)。
- 分段计时(800/1000米每 200 米打点)仅本地展示,不上报。
- 录入校验:客户端仅做格式与常识软提示(如 <5 秒或 >30 分钟弹"确认成绩无误?"),硬上限拦截归服务端 G10(48025)。
- 室外弱网可用:计时与录入全离线,联网后随 finish 一次性提交。

## 5. 端侧姿态估计与计数引擎

### 5.1 架构

```text
相机帧流(CameraX/AVCaptureSession)
   → 帧采样(目标 15fps,低配 8fps)
   → 姿态估计(TFLite BlazePose 类模型,端侧推理,模型文件经资源包管理器下发)
   → 关键点序列(33点 x/y/z/visibility,滑动窗口 3s)
   → 项目计数器(周期判定,见 §5.2)
   → 计数事件组装(seq/count/cycleMs/qualityHint/kpSample)
   → 上报管道(在线直连 / 弱网本地队列)
         │
         └─► SDK 输出层物理红线:帧图像在进入计数器后即销毁,
             全链路(内存/磁盘/日志/埋点)禁出现像素数据
```

- 模型推理在独立 Isolate(对齐《客户端-端侧AI推理与端智能引擎》),主线程零阻塞;低端设备(运行内存 <4GB 或推理 >80ms/帧)自动降采样到 8fps 并提示"已启用流畅模式"。
- 模型文件版本与端侧引擎版本写入 `deviceInfo.engineVer` 上报,供服务端按(引擎版本 × 项目)聚合校准系数。

### 5.2 项目计数器(周期判定算法)

| 项目 | 判定信号(骨架关键点) | 周期定义 |
| --- | --- | --- |
| 跳绳 | 手腕关键点相对脚踝关键点垂直交叉 + 周期节奏 | 绳过脚一次 |
| 仰卧起坐 | 肩部-髋部夹角:躺平(≥160°)→起坐(≤80°)→回躺 | 完成一次起坐 |
| 俯卧撑 | 肘部夹角:撑起(≥160°)→下降(≤90°)→撑起 | 完成一次 |
| 深蹲 | 髋部-膝部相对位移 + 膝夹角 <100° 为低点 | 起立完成一次 |
| 高抬腿 | 膝部抬升高度 > 髋部基准 + 交替节奏 | 单腿抬起一次 |
| 引体向上 | 腕部相对肩部垂直位移上升 > 下颌过杠代理点 | 完成一次 |

- 每个周期结束生成一个计数事件(含该周期 cycleMs 与 qualityHint);无周期发生时每 5 秒兜底发一次心跳事件(seq+1, count 不变),保活会话并给服务端抽样机会。
- qualityHint 由周期幅度/节奏稳定性启发式得出(0-1),仅供服务端参考,**不影响端侧计数结果**(计数只数完整周期,半截动作不计)。

### 5.3 kpSample 打包(红线)

- 抽样:每 10 个周期打包一次关键点序列(约 3 秒),zstd 压缩 + BASE64;**>64KB 直接丢弃该样本不上报**(宁可少样本不可超阈,服务端 48031 为最后防线)。
- 打包后即清空对应滑动窗口的原始坐标数组;本地零持久化关键点文件(对齐服务端 §12 骨架样本 30 天删除的端侧镜像:端侧根本不留)。

### 5.4 弱网本地队列

- 事件先进本地队列(SQLite,对齐《客户端-本地持久层与数据管理》),成功 202 才出队;队列上限 5000 条,溢出 DropOldest 仅允许丢心跳事件,计数事件禁丢(G1:计数完整性优先)。
- 断网训练完全可用;恢复联网后按 seq 顺序补传,补传期间界面不阻塞新训练(新会话独立队列分片,按 sessionId 隔离)。

## 6. 客户端镜像状态机与守卫

### 6.1 镜像状态机(服务端 §6.1 的客户端镜像)

| 镜像态 | 进入条件 | 客户端行为 |
| --- | --- | --- |
| INITIALIZING | 进入相机页 | 引擎加载/权限申请 |
| READY | 人体入镜校验通过 | 展示 3-2-1 倒计时 |
| COUNTING | 倒计时结束 | 事件流上报开启 |
| PAUSED | 用户暂停 | 事件流暂停,seq 冻结 |
| FINISHING | 用户确认结束 | 禁一切操作,等待 finish |
| RESULT | finish 200 | 结算弹层 |
| DEGRADED | 引擎不可用 | 节拍引导+手动计数(§8 D3) |
| BLOCKED | 48010/48011/48040 | 全屏引导页,禁重试 |

### 6.2 守卫(G1-G10)

| 守卫 | 规则 | 违反处理 |
| --- | --- | --- |
| G1 | 计数事件 seq 严格单调;队列溢出禁丢计数事件 | 内部断言,seq 回退即丢事件并报诊断日志 |
| G2 | countStartToken 仅存内存,禁落盘/禁写日志 | 进程重启后重新拉取会话(服务端令牌校验失败 48012 则回首页重建) |
| G3 | 暂停 ≤5 次,客户端镜像提前隐藏按钮 | 双保险,服务端 48013 兜底 |
| G4 | FINISHING 态一切用户操作被吞掉 | 防双击双提交 |
| G5 | 切后台自动暂停,回前台禁自动恢复 | 防沉迷对齐,时长口径与服务端一致 |
| G6 | 结算渲染只用服务端字段,禁客户端换算分数/等级 | 标准表唯一权威在服务端 |
| G7 | 骨架帧禁入截图/分享/录屏内容(相机页 overlay 加 FLAG_SECURE/屏幕录制检测) | 检测到录屏直接黑屏相机区 |
| G8 | 模拟考进度展示以服务端响应为准,本地倒计时不作为封锁依据 | 48021/48022 裁决后刷新 |
| G9 | 影像零出端:SDK 输出层剥离 + 单元测试断言帧缓冲清零 | CI 红线用例 |
| G10 | finish 重试必须复用同一 Idempotency-Key 与同一 clientCount | 服务端 48024 幂等回放原样渲染 |

### 6.3 竞态裁决

- **finish 与在途计数事件并发**:finish 前先 flush 本地队列(≤3s 等待),超时带现有 lastSeq 提交,剩余事件由服务端补偿窗口处理;客户端不自行重算。
- **重复点击结束**:G4 吞操作 + 幂等键双保险。
- **会话恢复 vs 服务端过期**(48014):本地镜像存在但服务端会话已过期 → 放弃本地计数(不可补传,防跨日成绩污染),中性提示重新开始。
- **模拟考中途退出**:进度已持久化,回来自动续考;服务端 6h 过期则重新组考(已完成项成绩保留在历次会话中,不合并)。

## 7. 关键代码示例

### 7.1 计数控制器(心跳与周期事件统一出口)

```dart
class FitCountController {
  final String sessionId;
  final String countToken;
  final FitProject project;
  final FitEventUploader _uploader;
  int _seq = 0;
  int _count = 0;
  DateTime? _lastCycleAt;
  Timer? _heartbeat;

  FitCountController({required this.sessionId, required this.countToken,
      required this.project, required FitEventUploader uploader})
      : _uploader = uploader;

  void start() {
    _heartbeat = Timer.periodic(const Duration(seconds: 5), (_) => _emit(heartbeat: true));
  }

  /// 姿态引擎回调:完成一个动作周期
  void onCycleDetected(int cycleMs, double qualityHint) {
    _count += 1;
    _lastCycleAt = DateTime.now();
    _emit(cycleMs: cycleMs, qualityHint: qualityHint,
        kpSample: _maybePackKpSample());
  }

  void _emit({bool heartbeat = false, int cycleMs = 0,
      double qualityHint = 0, FitKpSample? kpSample}) {
    _seq += 1; // G1:严格单调,任何路径不得重置
    final event = FitCountEvent(
      sessionId: sessionId, seq: _seq, count: _count,
      cycleMs: heartbeat ? 0 : cycleMs,
      qualityHint: heartbeat ? 0 : qualityHint,
      kpSample: kpSample,
    );
    _uploader.enqueue(event, token: countToken); // 队列兜底,fire-and-forget
  }

  Future<void> dispose() async {
    _heartbeat?.cancel();
    await _uploader.flush(timeout: const Duration(seconds: 3));
  }
}
```

### 7.2 事件上传器(在线/离线透明切换)

```dart
class FitEventUploader {
  final FitApiClient _api;
  final LocalEventQueue _queue; // SQLite,按 sessionId 分片

  Future<void> enqueue(FitCountEvent event, {required String token}) async {
    await _queue.append(event);
    _drain(token);
  }

  Future<void> _drain(String token) async {
    while (await _queue.hasPending()) {
      final batch = await _queue.peek(20);
      try {
        await _api.postCountEvents(batch, token: token); // 202
        await _queue.ack(batch.last.seq);
      } on NetworkException {
        return; // 留在队列,网络恢复广播触发再 drain
      } on FitApiException catch (e) {
        if (e.code == '48012') { await _queue.clear(); rethrow; } // 令牌失效
        if (e.code == '48031') { await _queue.dropOversize(); continue; } // 样本超阈丢弃
        return;
      }
    }
  }

  Future<void> flush({required Duration timeout}) =>
      _drainFuture?.timeout(timeout, onTimeout: () {}) ?? Future.value();
  Future<void>? _drainFuture;
}
```

### 7.3 模拟考休息守卫(服务端权威渲染)

```dart
class FitExamRestController {
  final FitExamState state;
  Timer? _ticker;

  Duration? get remaining =>
      state.restUntil == null ? null
      : state.restUntil!.difference(DateTime.now());

  void startTicking(void Function() onExpire) {
    _ticker?.cancel();
    final r = remaining;
    if (r == null || r.isNegative) return;
    _ticker = Timer(r, onExpire); // 到点仅提示"可以开始了",不自动提交
  }

  Future<void> startNext() async {
    // G8:不本地封锁,提交由服务端裁决
    try {
      await _api.submitExamItem(state.examId, state.currentIndex);
    } on FitApiException catch (e) {
      if (e.code == '48021' || e.code == '48022') {
        // 原位提示 + 重新拉取服务端进度(refreshState)后重渲染
        await refreshState();
        throw FitUiHint(e.userMessage);
      }
      rethrow;
    }
  }
}
```
