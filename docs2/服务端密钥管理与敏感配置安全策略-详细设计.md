# 服务端密钥管理与敏感配置安全策略 - 详细设计

## 1. 概述

### 1.1 背景与问题

PrimeTop 作为全学段 AI 辅助学习平台，在运行时依赖大量敏感配置与密钥：

| 密钥/配置类型 | 示例 | 风险等级 | 泄露后果 |
|---------------|------|----------|----------|
| AI 大模型 API Key | OpenAI / 通义千问 / 文心一言 | 🔴 高 | 未授权调用、巨额账单、数据泄露 |
| 数据库连接串 | MySQL / Redis / PostgreSQL URL | 🔴 高 | 数据全量泄露、删库 |
| 对象存储密钥 | MinIO / 阿里云 OSS AK/SK | 🔴 高 | 教材资源、用户上传文件泄露/删除 |
| 支付密钥 | 微信支付 / 支付宝私钥 | 🔴 高 | 伪造交易、资金损失 |
| JWT 签名密钥 | Token 签发/验证密钥 | 🟡 中 | 伪造身份、越权访问 |
| 数据加密密钥 | 用户手机号/身份证加密密钥 | 🔴 高 | 解密敏感数据 |
| SMS/推送密钥 | 阿里云短信 / 极光推送 | 🟡 中 | 短信轰炸、推送滥用 |
| OCR/语音服务密钥 | 百度 OCR / 讯飞 ASR | 🟡 中 | 额度盗用、服务中断 |
| 数据库加密密钥 | TDE / 字段加密主密钥 | 🔴 高 | 数据库文件直接解密 |
| CI/CD 凭据 | GitHub Token / Docker Registry | 🟡 中 | 代码仓库篡改、镜像投毒 |

**核心问题**：
1. 密钥散落在配置文件、环境变量、代码仓库中，缺乏统一管理
2. 密钥轮换（Rotation）无自动化流程，长期不更换增加泄露风险
3. 开发/测试/生产环境密钥隔离不严格，存在生产密钥流入测试环境的可能
4. 密钥使用缺乏审计追踪，无法追溯谁在何时使用了哪个密钥
5. 密钥泄露后无快速吊销与应急替换机制

### 1.2 设计目标

1. **集中管控**：所有敏感配置与密钥统一存储、统一分发、统一审计
2. **最小权限**：每个服务/模块仅能访问自己所需的密钥
3. **自动轮换**：支持密钥定期自动轮换，零停机完成
4. **泄露防护**：密钥全生命周期加密，日志/监控中自动脱敏
5. **应急响应**：密钥泄露后 5 分钟内完成吊销与替换
6. **开发友好**：对业务代码透明，通过注解/配置自动注入

### 1.3 适用范围

- 服务端所有微服务/BFF 的敏感配置管理
- CI/CD 流水线中的密钥注入
- 开发/测试/预发布/生产四套环境的密钥隔离
- 客户端需要的非对称密钥（如 API 签名公钥）分发

### 1.4 术语定义

| 术语 | 含义 |
|------|------|
| Secret | 任意敏感配置项（API Key、密码、证书等）的统称 |
| SecretStore | 密钥存储后端（HashiCorp Vault / 加密数据库等） |
| SecretEngine | Vault 中的密钥引擎类型（KV / Transit / Database 等） |
| SecretPath | 密钥在 Vault 中的路径，如 `secret/data/primetop/ai/openai` |
| KeyRotation | 密钥轮换，即在不中断服务的前提下更换密钥值 |
| Envelope Encryption | 信封加密，用主密钥（KEK）加密数据密钥（DEK）的分层加密方案 |
| Seal/Unseal | Vault 的封印/解封操作，封印状态下所有密钥不可访问 |

### 2.2 密钥分类与存储策略

| 分类 | 存储引擎 | 轮换策略 | 示例 |
|------|----------|----------|------|
| **第三方 API Key** | KV v2 (静态) | 手动轮换 + 版本保留 | OpenAI Key、短信 Key |
| **数据库凭据** | Database Engine (动态) | 自动轮换，按需生成短期凭据 | MySQL 用户密码 |
| **加密密钥 (KEK/DEK)** | Transit Engine | 自动轮换，保留旧版本解密能力 | 手机号加密密钥 |
| **TLS 证书** | PKI Engine | 自动续期 | 服务间 mTLS 证书 |
| **JWT 签名密钥** | Transit Engine | 90 天轮换，保留旧版本验证 | 用户 Token 签名 |
| **支付私钥** | KV v2 (高安全) | 人工审批轮换 | 微信支付商户私钥 |
| **客户端公钥** | KV v2 (只读分发) | 年度轮换 | API 签名验证公钥 |

### 2.3 环境隔离策略

```
Vault 集群部署拓扑：

┌─ dev (开发) ─────────────────────────────┐
│  Vault: 内存模式 (dev server)             │
│  密钥: 本地生成的测试密钥                  │
│  数据: 完全模拟，无真实服务连接             │
└──────────────────────────────────────────┘

┌─ staging (预发布) ───────────────────────┐
│  Vault: 独立实例 (HA 模式)               │
│  密钥: 使用 staging 级别的服务端点         │
│  数据: 可连接真实服务的测试环境版本         │
└──────────────────────────────────────────┘

┌─ production (生产) ──────────────────────┐
│  Vault: 3 节点 HA 集群 + 自动 Unseal     │
│  密钥: 仅生产密钥，严格审计               │
│  网络: 独立 VPC，仅白名单服务可访问        │
└──────────────────────────────────────────┘
```

**隔离规则**：
1. 每个环境使用独立的 Vault Namespace（或独立 Vault 实例）
2. 生产密钥 **绝不** 进入非生产环境
3. 测试密钥带有明显的 `test-` / `dev-` 前缀标识
4. CI/CD 通过环境变量 `VAULT_ADDR` + `VAULT_TOKEN` 区分环境

### 3.3 Transit Engine 加密密钥配置

```hcl
# Transit Engine 启用
resource "vault_mount" "transit" {
  path        = "transit"
  type        = "transit"
  description = "Transit secret engine for encryption/decryption"
}

# 用户数据加密密钥 (KEK)
resource "vault_transit_secret_backend_key" "user_data_kek" {
  backend             = vault_mount.transit.path
  name                = "user-data-kek"
  type                = "aes256-gcm96"
  deletion_allowed    = false
  exportable          = false
  allow_plaintext_backup = false
  auto_rotate_period  = 7776000  # 90 天自动轮换 (秒)
  min_decryption_version = 1     # 保留所有旧版本解密能力
  min_encryption_version => 0    # 使用最新版本加密
}

# JWT 签名密钥
resource "vault_transit_secret_backend_key" "jwt_signing" {
  backend             = vault_mount.transit.path
  name                = "jwt-signing-key"
  type                = "ed25519"
  deletion_allowed    = false
  auto_rotate_period  = 7776000  # 90 天
}

# 支付数据加密密钥
resource "vault_transit_secret_backend_key" "payment_kek" {
  backend             = vault_mount.transit.path
  name                = "payment-kek"
  type                = "aes256-gcm96"
  deletion_allowed    = false
  auto_rotate_period  = 2592000  # 30 天
  min_decryption_version = 1
}
```

### 3.4 Database Engine 动态凭据配置

```hcl
# MySQL 动态凭据引擎
resource "vault_database_secret_backend_connection" "mysql" {
  backend       = "database"
  name          = "mysql-primetop"
  allowed_roles = ["primetop-app", "primetop-readonly", "primetop-migration"]

  mysql {
    connection_url = "{{username}}:{{password}}@tcp(mysql-primary.internal:3306)/"
    username       = "vault_admin"
    password       = ""  # 从环境变量注入
  }

  max_open_connections     = 10
  max_idle_connections     = 5
  max_connection_lifetime  = "1h"
}

# 应用服务角色 — 自动生成短期数据库账号
resource "vault_database_secret_backend_role" "app" {
  backend    = vault_database_secret_backend_connection.mysql.backend
  name       = "primetop-app"
  db_name    = vault_database_secret_backend_connection.mysql.name
  
  default_ttl = "1h"           # 凭据默认有效期 1 小时
  max_ttl     = "4h"           # 最大有效期 4 小时
  
  creation_statements = [
    "CREATE USER '{{name}}'@'%' IDENTIFIED BY '{{password}}';",
    "GRANT SELECT, INSERT, UPDATE, DELETE ON primetop.* TO '{{name}}'@'%';",
    "GRANT SELECT ON primetop_readonly.* TO '{{name}}'@'%';"
  ]
  
  revocation_statements = [
    "DROP USER IF EXISTS '{{name}}'@'%';"
  ]
  
  rotate_statements = [
    "ALTER USER '{{name}}'@'%' IDENTIFIED BY '{{password}}';"
  ]
}

# 只读角色 — BI / 报表服务
resource "vault_database_secret_backend_role" "readonly" {
  backend    = vault_database_secret_backend_connection.mysql.backend
  name       = "primetop-readonly"
  db_name    = vault_database_secret_backend_connection.mysql.name
  
  default_ttl = "2h"
  max_ttl     = "8h"
  
  creation_statements = [
    "CREATE USER '{{name}}'@'%' IDENTIFIED BY '{{password}}';",
    "GRANT SELECT ON primetop.* TO '{{name}}'@'%';"
  ]
  
  revocation_statements = [
    "DROP USER IF EXISTS '{{name}}'@'%';"
  ]
}
```

### 4.1 认证方式 (Auth Methods)

#### 4.1.1 Kubernetes ServiceAccount 认证 (生产环境首选)

```yaml
# Kubernetes Auth Method 配置
apiVersion: v1
kind: ServiceAccount
metadata:
  name: vault-auth
  namespace: primetop
---
# 每个微服务的 ServiceAccount
apiVersion: v1
kind: ServiceAccount
metadata:
  name: ai-service
  namespace: primetop
  annotations:
    vault.hashicorp.com/role: "ai-service"
```

```hcl
# Vault Kubernetes Auth 配置
resource "vault_auth_backend" "kubernetes" {
  type = "kubernetes"
}

resource "vault_kubernetes_auth_backend_config" "config" {
  backend            = vault_auth_backend.kubernetes.path
  kubernetes_host    = "https://kubernetes.default.svc:443"
  kubernetes_ca_cert = file("/etc/kubernetes/ca.crt")
  issuer             = "kubernetes/serviceaccount"
}

# AI 服务角色绑定
resource "vault_kubernetes_auth_backend_role" "ai_service" {
  backend                          = vault_auth_backend.kubernetes.path
  role_name                        = "ai-service"
  bound_service_account_names      = ["ai-service"]
  bound_service_account_namespaces = ["primetop"]
  
  token_policies = [
    "primetop.ai.read",
    "primetop.encryption.read"
  ]
  
  token_ttl    = "1h"
  token_max_ttl = "4h"

}
```

```java
/**
 * Vault 数据库凭据续租监听器
 * 在凭据即将过期前自动向 Vault 请求续租或获取新凭据

@Component
@RequiredArgsConstructor
@Slf4j
public class VaultDatabaseCredentialRenewal {
    
    private final VaultTemplate vaultTemplate;
    private final HikariDataSource dataSource;
    
    @Scheduled(fixedDelay = 1800000)  // 每 30 分钟检查一次
    public void checkAndRenewCredentials() {
        try {
            // 获取当前 lease 信息
            String leaseId = vaultTemplate.getLeaseId(
                "database/creds/primetop-app");
            
            if (leaseId != null) {
                // 续租
                VaultRenewalResponse response = vaultTemplate.renew(
                    leaseId, Duration.ofHours(1));
                
                log.info("数据库凭据续租成功, leaseId={}, ttl={}",
                    leaseId, response.getLeaseDuration());
            }
        } catch (Exception e) {
            // 续租失败，获取新凭据并重建连接池
            log.warn("凭据续租失败，准备获取新凭据", e);
            rotateDatabaseCredentials();
        }
    }
    
    private void rotateDatabaseCredentials() {
        try {
            // 获取新凭据
            DatabaseCredentials newCreds = vaultTemplate.read(
                "database/creds/primetop-app",
                DatabaseCredentials.class).getData();
            
            // 优雅重建连接池
            HikariConfig newConfig = new HikariConfig();
            newConfig.setJdbcUrl(dataSource.getJdbcUrl());
            newConfig.setUsername(newCreds.getUsername());
            newConfig.setPassword(newCreds.getPassword());
            newConfig.setMaximumPoolSize(20);
            
            HikariDataSource newDataSource = new HikariDataSource(newConfig);
            
            // 原子替换（需配合 DataSource Proxy）
            DataSourceContextHolder.replaceDataSource(newDataSource);
            
            // 优雅关闭旧连接池
            dataSource.close();
            
            log.info("数据库凭据轮换成功, newUser={}", newCreds.getUsername());
        } catch (Exception e) {
            log.error("数据库凭据轮换失败，触发告警", e);
            throw new SecretRotationException("数据库凭据轮换失败", e);
        }
    }
}
```

```python
# requirements.txt
# hvac==2.3.0           # HashiCorp Vault Client
# pydantic-settings==2.3.0
# cryptography==43.0.0

import os
import functools
from typing import Optional
from dataclasses import dataclass
import hvac
from hvac.api.auth_methods import Kubernetes


@dataclass
class VaultConfig:
    """Vault 连接配置"""
    addr: str = os.getenv("VAULT_ADDR", "https://vault.internal.primetop.local:8200")
    namespace: str = os.getenv("VAULT_NAMESPACE", "production")
    k8s_role: str = os.getenv("VAULT_K8S_ROLE", "ai-service")
    k8s_token_path: str = "/var/run/secrets/kubernetes.io/serviceaccount/token"


class VaultClient:
    """Vault 客户端封装 — 单例模式"""
    
    _instance: Optional['VaultClient'] = None
    _client: Optional[hvac.Client] = None
    
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
    
    @property
    def client(self) -> hvac.Client:
        if self._client is None or not self._client.is_authenticated():
            self._client = self._authenticate()
        return self._client
    
    def _authenticate(self) -> hvac.Client:
        """通过 Kubernetes ServiceAccount Token 认证"""
        client = hvac.Client(url=VaultConfig.addr)
        
        with open(VaultConfig.k8s_token_path, 'r') as f:
            jwt_token = f.read().strip()
        
        Kubernetes(client.adapter).login(
            role=VaultConfig.k8s_role,
            jwt=jwt_token,
        )
        
        if not client.is_authenticated():
            raise RuntimeError("Vault 认证失败")
        
        return client
    
    def read_secret(self, path: str) -> dict:
        """读取 KV v2 密钥"""
        response = self.client.secrets.kv.v2.read_secret_version(
            path=path,
            mount_point="secret",
        )
        return response["data"]["data"]
    
    def encrypt(self, key_name: str, plaintext: str) -> str:
        """Transit Engine 加密"""
        import base64
        plaintext_b64 = base64.b64encode(plaintext.encode()).decode()
        
        response = self.client.secrets.transit.encrypt_data(
            name=key_name,
            plaintext=plaintext_b64,
        )
        return response["data"]["ciphertext"]
    
    def decrypt(self, key_name: str, ciphertext: str) -> str:
        """Transit Engine 解密"""
        import base64
        
        response = self.client.secrets.transit.decrypt_data(
            name=key_name,
            ciphertext=ciphertext,
        )
        
        plaintext_b64 = response["data"]["plaintext"]
        return base64.b64decode(plaintext_b64).decode()


def vault_secret(path: str, key: str):
    """装饰器 — 从 Vault 注入密钥到函数参数"""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            vault = VaultClient()
            secrets = vault.read_secret(path)
            kwargs[key] = secrets[key]
            return func(*args, **kwargs)
        return wrapper
    return decorator
```

### 5.3 客户端密钥分发

客户端（Flutter APP）需要的密钥场景有限，主要通过以下方式处理：

```dart
/// 客户端密钥分发策略
///
/// 客户端绝不存储高敏感密钥（如 AI API Key、数据库密码等）。
/// 客户端仅需：
/// 1. API Gateway 公钥 — 用于请求签名验证
/// 2. WebSocket JWT Token — 服务端签发
/// 3. 本地数据加密密钥 — 设备级密钥

class ClientKeyService {
  static const _keyCacheDuration = Duration(hours: 24);
  
  /// 获取 API 签名公钥（用于验证服务端响应真实性）
  /// 从服务端 API 获取，缓存在本地安全存储
  Future<String> getApiSigningPublicKey() async {
    final cacheKey = 'api_signing_pubkey';
    final cached = await SecureStorage.read(cacheKey);
    
    if (cached != null) {
      // 检查缓存是否过期
      final cachedTime = await SecureStorage.read('${cacheKey}_time');
      if (cachedTime != null) {
        final age = DateTime.now().difference(
          DateTime.parse(cachedTime));
        if (age < _keyCacheDuration) return cached;
      }
    }
    
    // 从服务端获取最新公钥
    final response = await http.get(
      Uri.parse('${Env.apiBase}/v1/system/public-key'),
    );
    
    if (response.statusCode == 200) {
      final publicKey = jsonDecode(response.body)['data']['publicKey'];
      await SecureStorage.write(cacheKey, publicKey);
      await SecureStorage.write('${cacheKey}_time',
        DateTime.now().toIso8601String());
      return publicKey;
    }
    
    throw KeyFetchException('获取 API 公钥失败');
  }
  
  /// 生成设备本地加密密钥（用于本地数据加密）
  /// 此密钥不离开设备，使用平台 KeyStore / Keychain 保护
  Future<String> getDeviceEncryptionKey() async {
    const keyAlias = 'primetop_device_key';
    
    // Android: AndroidKeyStore
    // iOS: Secure Enclave (通过 flutter_secure_storage)
    final existing = await SecureStorage.read(keyAlias);
    if (existing != null) return existing;
    
    // 生成新的设备密钥
    final key = _generateSecureRandom(32);  // 256-bit
    await SecureStorage.write(keyAlias, key);
    return key;
  }
}
```

### 6.3 双 Key 并行配置实现

```java
/**
 * 双 Key 管理器 — 支持 API Key 无缝轮换
 */
@Component
@RequiredArgsConstructor
@Slf4j
public class DualKeyManager {
    
    private final VaultTemplate vaultTemplate;
    
    // 当前 active key 和 standby key 的本地缓存
    private volatile KeyPair activeKeyPair;
    private volatile KeyPair standbyKeyPair;
    
    @Data
    @AllArgsConstructor
    private static class KeyPair {
        private String keyId;
        private String keyValue;
        private Instant loadedAt;
    }
    
    /**
     * 获取当前 Active Key
     */
    public String getActiveKey(String servicePath) {
        refreshKeysIfNeeded(servicePath);
        return activeKeyPair.getKeyValue();
    }
    
    /**
     * 获取指定版本的 Key（用于灰度）
     */
    public String getKeyForUser(String servicePath, String userId) {
        refreshKeysIfNeeded(servicePath);
        
        // 灰度比例判断
        int hash = Math.abs(userId.hashCode() % 100);
        int grayPercentage = getCurrentGrayPercentage(servicePath);
        
        if (hash < grayPercentage && standbyKeyPair != null) {
            log.debug("用户 {} 使用 standby key (灰度 {}%)", 
                userId, grayPercentage);
            return standbyKeyPair.getKeyValue();
        }
        
        return activeKeyPair.getKeyValue();
    }
    
    private void refreshKeysIfNeeded(String path) {
        if (activeKeyPair != null && 
            activeKeyPair.getLoadedAt().isAfter(
                Instant.now().minus(Duration.ofMinutes(5)))) {
            return;  // 5 分钟内不刷新
        }
        
        // 从 Vault KV v2 读取最新版本和前一版本
        Versioned<VaultResponse> current = vaultTemplate.read(
            "secret/data/production/" + path);
        Versioned<VaultResponse> previous = vaultTemplate.read(
            "secret/data/production/" + path,
            Versioned.Version.from(current.getMetadata().getVersion() - 1));
        
        Map<String, Object> currentData = current.getRequiredData();
        Map<String, Object> previousData = previous != null ? 
            previous.getRequiredData() : null;
        
        activeKeyPair = new KeyPair(
            (String) currentData.get("key_id"),
            (String) currentData.get("api_key"),
            Instant.now()
        );
        
        if (previousData != null) {
            standbyKeyPair = new KeyPair(
                (String) previousData.get("key_id"),
                (String) previousData.get("api_key"),
                Instant.now()
            );
        }
    }
    
    private int getCurrentGrayPercentage(String path) {
        // 从配置中心读取灰度比例
        return ConfigCenter.getInt(
            "secret.rotation.gray.${path}", 0);
    }
}
```

### 6.4 Transit Engine 密钥自动轮换

Transit Engine 的密钥轮换对业务完全透明：

```
加密：始终使用最新版本 (version N)
解密：自动识别密文中的版本号，使用对应版本解密

示例：
  v1: aes256-gcm96 key material A  (2026-01-01)
  v2: aes256-gcm96 key material B  (2026-04-01)  ← 当前加密版本
  v3: aes256-gcm96 key material C  (2026-07-01)  ← 未来版本

加密流程：
  plaintext → Transit Engine → vault:v2:xxxxxxxxxxxx  (使用 v2 加密)

解密流程：
  vault:v1:yyyyyyyyyyyy → Transit Engine → 检测 v1 → 用 v1 解密 → plaintext
  vault:v2:xxxxxxxxxxxx → Transit Engine → 检测 v2 → 用 v2 解密 → plaintext

自动轮换配置：
  auto_rotate_period = 7776000  # 90 天
  min_decryption_version = 1    # 所有版本都能解密
```

```java
 * 自动检测并替换日志中的敏感信息
 */
@Component
@Slf4j
public class LogSanitizationFilter implements Filter {
    
    // 敏感模式匹配
    private static final List<Pattern> SENSITIVE_PATTERNS = List.of(
        // API Key 格式
        Pattern.compile("(sk-proj-|sk-)[a-zA-Z0-9_-]{20,}", 
            Pattern.CASE_INSENSITIVE),
        // AWS/阿里云 AK 格式
        Pattern.compile("(LTAI|AKIA)[A-Z0-9]{12,}"),
        // 连接串中的密码
        Pattern.compile("://[^:]+:([^@]+)@"),
        // 手机号
        Pattern.compile("(1[3-9]\\d)\\d{4}(\\d{4})"),
        // Bearer Token
        Pattern.compile("(Bearer\\s+)[A-Za-z0-9-._~+/]+=*"),
        // 通用 Base64 密钥（长于 32 字符）
        Pattern.compile("(key|token|secret|password)[\":\\s=]+([A-Za-z0-9+/]{32,}=*)",
            Pattern.CASE_INSENSITIVE)
    );
    
    private static final String MASK = "****REDACTED****";
    
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, 
                         FilterChain chain) throws IOException, ServletException {
        // 使用 Logback TurboFilter 进行日志脱敏
        chain.doFilter(request, response);
    }
    
    /**
     * 对日志消息进行脱敏处理
     */
    public static String sanitize(String message) {
        if (message == null) return null;
        
        String sanitized = message;
        for (Pattern pattern : SENSITIVE_PATTERNS) {
            sanitized = pattern.matcher(sanitized).replaceAll(m -> {
                // 保留前后部分，中间替换
                String group = m.group(0);
                if (group.length() > 8) {
                    return group.substring(0, 4) + MASK + 
                           group.substring(group.length() - 4);
                }
                return MASK;
            });
        }
        return sanitized;
    }
}

/**
 * Logback 脱敏 TurboFilter
 */
public class SensitiveDataTurboFilter extends TurboFilter {
    @Override
    public FilterReply decide(Marker marker, Logger logger, Level level,
                              String format, Object[] params, Throwable t) {
        if (format != null) {
            String sanitized = LogSanitizationFilter.sanitize(format);
            if (!sanitized.equals(format)) {
                // 使用脱敏后的消息继续日志
                logger.log(null, logger.getName(), 
                    toLocationAwareLogger(level), 
                    sanitized, params, t);
                return FilterReply.DENY;  // 拦截原始日志
            }
        }
        return FilterReply.NEUTRAL;
    }
}
```

```bash
SENSITIVE_PATTERNS=(
    'sk-proj-[a-zA-Z0-9]{40,}'           # OpenAI
    'sk-[a-zA-Z0-9]{32,}'                 # Generic API Key
    'LTAI[A-Z0-9]{12,}'                   # 阿里云 AK
    'AKIA[A-Z0-9]{12,}'                   # AWS AK

    'secret\s*[:=]\s*["\x27][^"\x27]{8,}'    # Secret 赋值
    'mysql://[^:]+:[^@]+@'                # MySQL URL
    'redis://:[^@]+@'                     # Redis URL
)

STAGED_FILES=$(git diff --cached --name-only --diff-filter=ACM | \
    grep -E '\.(java|py|yaml|yml|properties|json|xml|conf|env|sh|toml)$')

if [ -z "$STAGED_FILES" ]; then
    exit 0
fi

FOUND_SECRETS=false

for FILE in $STAGED_FILES; do
    for PATTERN in "${SENSITIVE_PATTERNS[@]}"; do
        if grep -Eq "$PATTERN" "$FILE" 2>/dev/null; then
            echo "❌ 发现敏感信息: $FILE"
            echo "   匹配模式: $PATTERN"
            grep -En "$PATTERN" "$FILE" | head -3
            FOUND_SECRETS=true
        fi
    done
done

    echo ""
    echo "⛔ 提交被阻止！请将敏感信息移至 Vault，代码中使用占位符引用。"
    echo "   如确实需要提交（如测试密钥），请使用: git commit --no-verify"
    exit 1
fi

echo "✅ 未检测到敏感信息"
```

## 11. 开发规范

### 11.1 密钥使用规范检查清单

| 规范项 | 要求 | 检查方式 |
|--------|------|---------|
| **无明文密钥** | 代码中不得出现任何密钥明文 | Git pre-commit hook + CI 扫描 |
| **无硬编码配置** | 敏感配置必须通过 Vault/环境变量注入 | 代码审查 |
| **密钥不落盘** | 密钥不得写入日志、临时文件、响应体 | 日志脱敏 + 响应过滤器 |
| **最小权限** | 每个服务只能访问自己所需的密钥 | Vault Policy Review |
| **短期凭据** | 数据库密码使用动态凭据，TTL ≤ 4h | Vault 配置审计 |
| **密钥版本化** | 所有密钥变更通过 Vault 版本管理，可回溯 | KV v2 Version History |
| **双 Key 并行** | 轮换期间新旧 Key 并行可用 | 配置检查 |
| **审计完整** | 所有密钥访问操作有审计记录 | Audit Device 检查 |

### 12.1 开发环境 Vault 启动

```bash
#!/bin/bash
# scripts/start-dev-vault.sh
# 本地开发用 Vault — 内存模式，自动预置测试密钥

set -euo pipefail

# 启动 Vault Dev Server（内存模式，自动 Unseal）

VAULT_PID=$!

sleep 3

export VAULT_ADDR="http://127.0.0.1:8200"
export VAULT_TOKEN="dev-only-token"

# 启用 KV v2
vault secrets enable -path=secret kv-v2

# 预置测试密钥
vault kv put secret/dev/ai/openai \
  api_key="sk-dev-test-key-not-real-1234567890" \
  api_base="https://api.openai.com/v1" \
  organization_id="org-dev-test"

vault kv put secret/dev/ai/tongyi \
  api_key="sk-dev-tongyi-test-key-1234567890"

vault kv put secret/dev/database/mysql \
  url="jdbc:mysql://localhost:3306/primetop_dev" \
  username="dev_user" \
  password="dev_password_123"

vault kv put secret/dev/database/redis \
  host="localhost" \
  port="6379" \
  password="dev_redis_123"

vault kv put secret/dev/sms/aliyun \
  access_key_id="LTAI_DEV_TEST_123" \
  access_key_secret="dev_secret_1234567890" \

# 启用 Transit Engine
```

## 附录 B：常见问题 FAQ

**Q: 开发环境如何获取密钥？**
A: 使用本地 Dev Vault（`scripts/start-dev-vault.sh`），预置测试密钥。严禁使用生产密钥进行开发。

**Q: 密钥更新后需要重启服务吗？**
A: 不需要。Spring Cloud Vault 支持 `@RefreshScope` 热更新，密钥变更后自动刷新。

**Q: Vault 宕机了怎么办？**
A: Vault HA 集群保证可用性。如果全部节点宕机，各服务使用本地缓存的密钥继续运行（最长 TTL 内有效），同时触发 PagerDuty 告警。

**Q: 如何处理第三方供应商要求密钥以环境变量传入？**
A: 通过 Vault Agent 或 CSI Driver 将密钥注入为环境变量，对第三方 SDK 透明。

**Q: 支付密钥为什么不能自动轮换？**
A: 微信支付、支付宝的商户密钥需要在支付平台后台同步更新，涉及资金安全，必须人工确认。建议使用双 Key 并行策略降低风险。
