> 版本：v1.0 · 日期：2026-06-09 · 状态：初稿

## 1. 概述

### 1.1 范围

本文档覆盖优惠券从 **运营创建** → **多渠道分发** → **用户领取** → **支付时使用/核销** → **过期/退款处理** 的完整端到端链路。重点关注各子系统间的协作时序、数据流转、异常分支和幂等保障，使开发人员能清晰理解优惠券在全链路中的生命周期。

### 1.2 优惠券在业务中的定位

优惠券是连接"定价策略"与"用户转化"的核心促销工具，覆盖以下业务场景：

| 场景 | 优惠券类型 | 触发方式 |
|------|-----------|---------|
| 新用户注册激励 | 折扣券（8折） | 系统自动发放 |
| 会员续费挽回 | 满减券（满100减20） | 系统定向发放 |
| 运营活动促销 | 折扣券/满减券 | 用户主动领取 |
| 积分商城兑换 | 满减券/体验券 | 积分兑换 |
| 裂变邀请奖励 | 兑换券/折扣券 | 邀请成功自动发放 |
| 线下合作推广 | 兑换码（PRIME-XXXX） | 兑换码领取 |

### 3.1 流程说明

### 3.3 关键校验规则

| 校验项 | 规则 | 失败处理 |
|--------|------|---------|
| 折扣上限 | 最高不超过5折（即 `discountValue ≥ 50`） | 返回 `COUPON_DISCOUNT_EXCEEDS_LIMIT`，需主管审批 |
| 有效期合理性 | 固定时间段 `valid_until > NOW()` | 返回 `COUPON_INVALID_VALIDITY` |
| 面额合理性 | `discountValue > 0`，满减券 `minPurchaseAmount ≥ discountValue` | 返回参数错误 |
| 编码唯一性 | `code` 全局唯一 | 返回 `COUPON_CODE_DUPLICATE` |

### 3.4 兑换码生成（可选）

若 `distributeType = CODE_REDEEM`，上线后可批量生成兑换码：

```
POST /api/v1/admin/coupon-templates/{templateId}/redeem-codes/generate
{ "quantity": 1000, "codePrefix": "PRIME-" }
```

服务端生成 `PRIME-{4位随机}-{4位随机}` 格式的兑换码，批量写入 `coupon_redeem_code` 表。通过 CSV 下载链接返回给运营人员，用于线下分发。

#### 4.2.2 关键逻辑

**有效期计算**：

```typescript
function calculateValidity(template: CouponTemplate): { validFrom: Date; validUntil: Date } {
  const now = new Date();
  if (template.validityType === 'FIXED_RANGE') {
    // 固定时间段：直接使用模板配置
    return { validFrom: template.validFrom, validUntil: template.validUntil };
  } else {
    // 相对有效期：领取后N天
    return {
      validFrom: now,
      validUntil: new Date(now.getTime() + template.validDaysAfterClaim * 86400000)
    };
  }
}
```

**库存扣减 Lua 脚本**（保障原子性，防止超发）：

```lua
local stock = redis.call('GET', KEYS[1])
if stock == false then return -1 end     -- 需初始化
if tonumber(stock) <= 0 then return 0 end -- 已售罄
return redis.call('DECR', KEYS[1])        -- 扣减成功，返回剩余量
```

#### 4.2.3 客户端交互

1. 用户进入优惠券中心 → 展示可领取列表（带剩余数量、倒计时）
2. 点击"立即领取" → 按钮变为 loading 状态 → 防止重复点击

4. 领取失败 → Toast 提示具体原因（"已领完" / "您已领取过" / "不在活动范围内"）
