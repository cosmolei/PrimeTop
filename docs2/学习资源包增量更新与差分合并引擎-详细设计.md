# 学习资源包增量更新与差分合并引擎 - 详细设计

## 1. 概述

### 1.1 功能定位

本引擎负责 PrimeTop 移动端离线学习资源（教材点读音频、知识点微课、题库图片、学科工具资源包、启蒙卡片素材等）在版本升级时的**增量更新**。目标是：

- 降低用户流量消耗与下载等待时间；
- 保证离线内容完整性与版本一致性；
- 支持断点续传、后台静默更新、失败回滚；
- 为多学段、多教材版本、多地区的资源包提供可扩展的分发能力。

### 1.2 适用范围

| 资源类型 | 示例 | 单包大小 | 更新频率 |
| --- | --- | --- | --- |
| 教材点读音频包 | 人教版三年级上册英语点读音频 | 30~80 MB | 每学期 |
| 知识点微课视频包 | 函数概念讲解短视频合集 | 50~200 MB | 每月 |
| 题库图片资源包 | 题目配图、公式图、几何图 | 20~100 MB | 每周 |
| 启蒙内容资源包 | 识字卡片、拼音音频、互动素材 | 10~50 MB | 每两周 |
| 学科工具资源包 | 元素周期表、地图、实验模型 | 5~30 MB | 按需 |

### 1.3 设计目标

1. 增量更新比例平均达到 70% 以上（相同版本内容不重复下发）。
2. 下载过程支持断点续传，中断后能从断点恢复。
3. 合并失败可自动回滚到上一个可用版本。
4. 资源包签名验证，防止篡改。
5. 后台静默下载，不影响当前学习流程。

## 2. 核心概念

| 术语 | 说明 |
| --- | --- |
| **资源包（ResourcePackage）** | 一个离线资源集合，例如 "人教版三年级上册英语点读音频包 v1.2.3"。 |
| **版本（Version）** | 语义化版本 `MAJOR.MINOR.PATCH`，用于兼容性判断。 |
| **全量包（Full Package）** | 包含该版本完整资源文件的包。 |
| **增量包（Delta Package）** | 仅包含从旧版本到新版本差异文件的包。 |
| **分块（Chunk）** | 将大文件切分为固定大小的块，便于增量复用与断点续传。 |
| **清单（Manifest）** | 描述资源包文件列表、版本、分块哈希、签名等元数据。 |
| **差异计划（DeltaPlan）** | 服务端根据客户端当前版本生成的差异下载计划。 |

## 6. 关键代码示例

### 6.1 服务端：生成差异计划

```python
from typing import List, Dict
import hashlib

class DeltaPlanner:
    def __init__(self, old_manifest: Dict, new_manifest: Dict):
        self.old_files = {f['path']: f for f in old_manifest['files']}
        self.new_files = {f['path']: f for f in new_manifest['files']}

    def plan(self) -> Dict:
        reuse_files: List[Dict] = []
        download_files: List[Dict] = []

        for path, new_file in self.new_files.items():
            old_file = self.old_files.get(path)
            if old_file and old_file['hash'] == new_file['hash']:
                reuse_files.append({
                    'path': path,
                    'hash': new_file['hash'],
                    'size': new_file['size']
                })
            else:
                # 文件新增或变更，尝试按 chunk 级别复用
                reuse_chunks = self._compute_chunk_reuse(path, old_file, new_file)
                download_files.append({
                    'path': path,
                    'size': new_file['size'],
                    'hash': new_file['hash'],
                    'reuse_chunks': reuse_chunks,
                    'download_chunks': self._missing_chunks(new_file, reuse_chunks)
                })

        removed_files = [p for p in self.old_files if p not in self.new_files]

        return {
            'reuse_files': reuse_files,
            'download_files': download_files,
            'removed_files': removed_files,
            'reuse_bytes': sum(f['size'] for f in reuse_files),
            'download_bytes': sum(f['size'] for f in download_files)
        }

    def _compute_chunk_reuse(self, path, old_file, new_file) -> List[int]:
        if not old_file:
            return []
        old_hashes = set(old_file.get('chunk_hashes', []))
        return [
            idx for idx, h in enumerate(new_file.get('chunk_hashes', []))
            if h in old_hashes
        ]

    def _missing_chunks(self, new_file, reuse_chunks) -> List[int]:
        total = new_file.get('chunk_count', 0)
        reuse_set = set(reuse_chunks)
        return [i for i in range(total) if i not in reuse_set]
```

### 6.2 服务端：增量包构建

```python
import os
import zstandard as zstd
from pathlib import Path

class DeltaPackageBuilder:
    def build(self, base_dir: Path, new_dir: Path, output_dir: Path) -> Path:
        """
        基于文件级差异构建增量包：
        1. 扫描新增/变更文件；
        2. 使用 zstd 压缩；
        3. 写入 tar 增量包；
        4. 生成增量清单。
        """
        delta_files = []
        for root, _, files in os.walk(new_dir):
            for name in files:
                new_path = Path(root) / name
                rel_path = new_path.relative_to(new_dir)
                old_path = base_dir / rel_path

                new_hash = sha256_file(new_path)
                if old_path.exists() and sha256_file(old_path) == new_hash:
                    continue

                compressed = self._compress(new_path)
                delta_files.append({
                    'path': str(rel_path),
                    'hash': new_hash,
                    'compressed_size': len(compressed),
                    'data': compressed
                })

        return self._pack(output_dir, delta_files)

    def _compress(self, file_path: Path) -> bytes:
        cctx = zstd.ZstdCompressor(level=3)
        with open(file_path, 'rb') as f:
            return cctx.compress(f.read())
```

### 6.3 客户端：下载与合并（Dart 伪代码）

```dart
enum UpdateState { idle, checking, pending, downloading, merging, ready, failed }

class ResourcePackageUpdater {
  final String packageCode;
  UpdateState state = UpdateState.idle;

  Future<void> checkAndDownload() async {
    state = UpdateState.checking;
    final current = await _localManager.getCurrentVersion(packageCode);
    final plan = await _api.checkUpdate(packageCode, current);

    if (!plan.hasUpdate) {
      state = UpdateState.ready;
      return;
    }

    state = UpdateState.downloading;
    await _downloadDelta(plan.deltaPlan);

    state = UpdateState.merging;
    await _mergeDelta(plan.deltaPlan);

    state = UpdateState.ready;
    await _api.reportUpdate(packageCode, plan, status: 'success');
  }

  Future<void> _downloadDelta(DeltaPlan plan) async {
    final downloader = ChunkedDownloader(
      url: plan.deltaPackageUrl,
      savePath: _tempDeltaPath,
      chunkSize: 256 * 1024,
      onProgress: (down, total) => _persistProgress(down, total),
    );
    await downloader.start();

    // 校验整包哈希
    final actualHash = await sha256File(_tempDeltaPath);
    if (actualHash != plan.expectedHash) {
      throw UpdateException('HASH_MISMATCH', '增量包哈希校验失败');
    }
  }

  Future<void> _mergeDelta(DeltaPlan plan) async {
    // 1. 复制旧版本到临时目录
    await _localManager.copyToStaging(packageCode);

    // 2. 解压增量包到临时目录，覆盖/新增文件
    await _deltaExtractor.extract(_tempDeltaPath, _stagingPath);

    // 3. 按新清单校验所有文件哈希
    final manifest = await _fetchManifest(plan.toVersion);
    await _verifyManifest(_stagingPath, manifest);

    // 4. 签名验证
    await _verifySignature(manifest);

    // 5. 原子切换：staging -> active
    await _localManager.activateStaging(packageCode, plan.toVersion);
  }
}
```

### 6.4 客户端：原子切换与回滚

```dart
class LocalPackageManager {
  Future<void> activateStaging(String packageCode, String version) async {
    final activeDir = await _activeDir(packageCode);
    final stagingDir = await _stagingDir(packageCode);
    final backupDir = await _backupDir(packageCode);

    // 备份当前版本
    if (await activeDir.exists()) {
      await activeDir.rename(backupDir.path);
    }

    try {
      await stagingDir.rename(activeDir.path);
      await _setCurrentVersion(packageCode, version);
      await backupDir.delete(recursive: true);
    } catch (e) {
      // 切换失败，回滚到旧版本
      if (await backupDir.exists()) {
        await activeDir.delete(recursive: true);
        await backupDir.rename(activeDir.path);
      }
      rethrow;
    }
  }
}
```

### 7.2 状态定义

| 状态码 | 状态名 | 说明 |
| --- | --- | --- |
| 0 | `idle` | 空闲，等待调度 |
| 1 | `checking` | 正在向服务端检查更新 |
| 2 | `pending` | 有待下载的更新，等待网络/电量条件 |
| 3 | `downloading` | 正在下载增量/全量包 |
| 4 | `merging` | 正在合并、校验、签名验证 |
| 5 | `ready` | 更新完成，当前版本可用 |
| 6 | `failed` | 更新失败，记录错误码与错误信息 |

### 7.3 触发条件

| 当前状态 | 事件 | 目标状态 | 条件 |
| --- | --- | --- | --- |
| idle | 用户进入同步课堂/点读页 | checking | 距上次检查超过 24 小时 |
| checking | 服务端返回有更新 | pending | 更新包大小 > 0 |
| checking | 服务端返回无更新 | ready | 版本已最新 |
| pending | 设备连接 Wi-Fi 且电量 > 20% | downloading | 后台调度允许 |
| downloading | 下载完成且哈希校验通过 | merging | 文件完整 |
| downloading | 网络中断/哈希失败 | failed | 重试 3 次后仍失败 |
| merging | 校验与签名通过 | ready | 原子切换成功 |
| merging | 校验失败/切换异常 | failed | 回滚到旧版本 |
| failed | 用户点击重试/下次后台调度 | checking | 清理临时文件后重试 |

## 8. 错误处理

### 8.1 错误码体系

| 错误码 | 场景 | 客户端处理 |
| --- | --- | --- |
| `HASH_MISMATCH` | 下载文件/整包哈希校验失败 | 删除临时文件，重试下载；连续 3 次失败则降级全量包 |
| `SIGNATURE_INVALID` | 清单签名验证失败 | 拒绝安装，上报服务端，回滚旧版本 |
| `MANIFEST_PARSE_ERROR` | 清单 JSON 解析失败 | 尝试重新拉取清单，失败则暂停更新 |
| `DELTA_MERGE_FAILED` | 增量合并后文件缺失或校验不通过 | 自动回滚，并尝试全量包更新 |
| `STORAGE_INSUFFICIENT` | 设备存储空间不足 | 提示用户清理空间，暂停后台下载 |
| `NETWORK_INTERRUPTED` | 下载过程中网络断开 | 保留已下载分片，恢复网络后继续 |
| `VERSION_INCOMPATIBLE` | 当前 App 版本低于资源包最低版本 | 提示用户升级 App |
| `NO_DELTA_AVAILABLE` | 服务端未生成该版本对的增量包 | 自动降级到全量包更新 |

### 8.2 降级策略

```text
检查更新
    │
    ▼
存在增量计划？
    ├── 是 ──▶ 下载增量包
    │              │
    │              ▼
    │        增量下载/合并失败？
    │              ├── 否 ──▶ 更新完成
    │              │
    │              是
    │              ▼
    │        失败次数 < 3？
    │              ├── 是 ──▶ 重试增量下载
    │              └── 否 ──▶ 切换全量包下载
    │                            │
    │                            ▼
    │                      全量包失败？
    │                            ├── 否 ──▶ 更新完成
    │                            └── 是 ──▶ 标记失败，保留旧版本
    │
    └── 否 ──▶ 下载全量包
```

### 8.3 幂等性保障

- 客户端每次启动更新时根据 `(package_code, from_version, to_version)` 生成唯一任务 ID；
- 下载任务支持断点续传，服务端对同一任务返回一致的 `Content-Range`；
- 合并前对 staging 目录进行完整校验，失败则删除 staging，避免脏数据进入 active；
- 更新结果上报接口使用任务 ID 去重，防止重复计费与统计。

## 9. 性能优化

### 9.1 分块与压缩

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 文件分块大小 | 256 KB | 音频/视频等大文件按 256KB 切分，便于断点续传与 chunk 级复用 |
| 压缩算法 | zstd level 3 | 音频/图片压缩率有限但解压快；文本/JSON 压缩率高 |
| 并发下载数 | 4 | 根据网络类型动态调整，Wi-Fi 下可提高到 6 |
| 后台下载限速 | 2 MB/s | 避免影响用户其他网络操作 |

### 9.2 缓存策略

- CDN 对清单文件和增量包设置长期缓存 + URL 中携带版本签名参数；
- 客户端本地缓存每个文件的 chunk 索引，合并时优先从本地旧版本复用；
- 对于高频复用的小文件（如卡片图片），使用 LRU 本地缓存。

### 9.3 并发控制

- 同一资源包同时只允许一个更新任务；
- 多资源包并行下载数不超过 2 个，避免 I/O 与内存压力；
- 合并操作在独立 isolate/线程中执行，不阻塞 UI。

## 10. 安全与合规

### 10.1 签名与完整性

- 清单文件使用 RSA-2048 私钥签名，客户端内置公钥验签；
- 每个文件与分块均有 SHA-256 哈希，下载后逐块校验；
- 增量包整包同样进行 SHA-256 校验与签名验证。

### 10.2 传输安全

- 所有下载地址强制 HTTPS；
- CDN 签名 URL 过期时间 1 小时，防止长期盗链；
- 下载 URL 中包含随机 nonce，避免 CDN 缓存污染统计。

### 10.3 数据隐私

- 更新检查接口不携带用户学习数据，仅传输版本号与设备标识；
- 上报更新结果时脱敏设备 ID，使用匿名化会话 ID。

## 12. 边界与假设

1. 资源包版本号严格遵循语义化版本，`MAJOR` 变更表示不兼容，必须走全量更新；
2. 客户端必须保留当前版本的完整文件列表，直到新版本激活成功；
3. 服务端为每个资源包维护最近 3 个历史版本的增量包，过旧版本直接走全量；
4. 同一设备同一时刻只允许一个资源包处于 `merging` 状态。
