# 学习服务 详细设计

## 1. 概述

### 1.1 模块定位

学习服务（Learning Service）是 PrimeTop 中学习数据与进度的核心聚合层。它负责：

- 统一记录学生在各模块（AI 辅导、拍题、同步课堂、练习、错题复习等）的学习行为。
- 维护章节/知识点掌握进度、学习计划、每日任务与目标达成状态。
- 为学情分析、学习规划、家长报告等下游服务提供标准化、可溯源的数据接口。
- 协调异步任务（如每日任务生成、复习提醒、计划调整）。

### 1.2 核心职责

| 职责 | 说明 |
| --- | --- |
| 学习行为记录 | 接收各业务模块事件，持久化学习记录（LearningRecord）。 |
| 进度追踪 | 基于学习记录与答题结果，更新章节/知识点掌握度（ChapterProgress / KnowledgePointProficiency）。 |
| 学习计划 | 管理学生目标（StudyGoal）与计划（StudyPlan），生成每日任务（DailyTask）。 |
| 任务调度 | 学习计划的动态调整、任务完成/跳过、逾期处理。 |
| 数据服务 | 向上游提供聚合查询、时序统计、最近学习记录等 API。 |

### 1.3 依赖关系

```text
AI 辅导 / 拍题 / 同步课堂 / 练习 / 错题
        |
    学习服务 (Learning Service)
        |
    用户服务   题目服务   错题服务   规划服务   消息服务
        |
    MySQL  +  Redis  +  Elasticsearch/ClickHouse（学习日志）
```

- 用户服务：获取学生学段、年级、教材版本、家长绑定关系。
- 题目服务：获取题目元数据、知识点、难度。
- 错题服务：错题收录、复习状态同步。
- 规划服务：学习目标与计划生成策略（学习服务可调用其策略接口，或内嵌生成器）。
- 消息服务：每日任务提醒、计划到期提醒。

## 2. 数据模型

### 2.1 核心实体定义

| 实体 | 英文 | 说明 |
| --- | --- | --- |
| 学习记录 | LearningRecord | 一次学习行为的最小记录，如“完成某题”“观看某视频”“与 AI 对话 5 分钟”。 |
| 学习行为类型 | LearningActionType | 枚举：AI_CHAT、TAKE_PHOTO、SYNC_CLASS、PRACTICE、MISTAKE_REVIEW、VIDEO_WATCH、READ、VOICE。 |
| 章节进度 | ChapterProgress | 学生在某教材版本某章节的完成度与掌握度。 |
| 知识点掌握度 | KnowledgePointProficiency | 对某个知识点的掌握评估（0~1）。 |
| 学习目标 | StudyGoal | 学生设定的目标，如期中备考、函数专项。 |
| 学习计划 | StudyPlan | 围绕目标生成的一段可执行计划。 |
| 每日任务 | DailyTask | 计划拆分到某天的任务。 |
| 学习资源引用 | LearningResourceRef | 指向具体学习资源的统一标识（资源类型 + 资源 ID）。 |

## 4. 业务逻辑

### 4.1 核心流程

#### 4.1.1 学习行为记录流程

```text
业务模块 -> POST /learning/records
              |
              v
        参数校验 + 幂等（去重 key）
              |
              v
        写入 learning_record
              |
              v
        异步事件：LearningRecordEvent
              |--> 更新章节进度
              |--> 更新知识点掌握度
              |--> 检查并自动完成任务
              |--> 学习时长累加
              |--> 消息服务（达标提醒）
```

幂等 key 生成：`{student_id}:{action_type}:{resource_type}:{resource_id}:{created_at_date}`，通过 Redis `SETNX` 30 秒防重。对于同一道题的多次作答，业务方应传入不同的 `record_uuid` 或时间戳，允许重复记录。

#### 4.1.2 章节进度更新流程

1. 收到 `LearningRecordEvent`。
2. 根据 `chapter_id` 查询 `chapter_progress` 或初始化新记录。
3. 根据行为类型更新：
   - 观看/阅读 → completion_rate += 权重（0.1 ~ 0.2）。
   - 练习 → 基于正确率更新 mastery_rate；completion_rate 基于已完成任务数/总任务数。
   - 错题复习 → mastery_rate 提升根据连续正确次数。
4. 更新 `last_study_at`。
5. 写入 `learning_record` 时同步完成（保证强一致）或异步最终一致。

#### 4.1.3 每日任务生成流程

1. 接收生成请求（每日凌晨 02:00 或用户首次打开 APP 时）。
2. 获取学生当前年级、教材版本、章节进度。
3. 从规划服务/策略引擎获取推荐任务候选：
   - 未完成章节 → 学习任务。
   - 薄弱知识点 → 练习任务。
   - 今日复习错题 → 错题复习任务。
   - 高频目标拆解 → 专题任务。
4. 按学生设置每日可用时长进行裁剪与排序。
5. 写入 `daily_task`，同时缓存到 Redis。
6. 发送消息提醒。

#### 4.1.4 计划动态调整流程

当学生连续多天未完成任务或知识点掌握度变化较大时，触发计划重排：

1. 计算计划完成率与平均掌握度。
2. 若完成率 < 60%，降低任务密度或增加复习任务。
3. 若完成率 > 90%，适当增加进阶任务。
4. 生成新版本 `daily_task`（旧任务标记为 EXPIRED），`study_plan.version` + 1。

### 4.2 状态机

#### 4.2.1 学习计划状态机

```text
DRAFT -> ACTIVE
ACTIVE -> PAUSED
PAUSED -> ACTIVE
ACTIVE -> COMPLETED
ACTIVE -> ARCHIVED
COMPLETED -> ARCHIVED
```

- `DRAFT`：创建后未生效。
- `ACTIVE`：当前生效中。
- `PAUSED`：学生手动暂停。
- `COMPLETED`：到达截止日期且所有任务完成。
- `ARCHIVED`：过期或学生删除。

#### 4.2.2 每日任务状态机

```text
PENDING -> DONE
PENDING -> SKIPPED
PENDING -> EXPIRED
```

- `DONE`：只能由 PENDING 转换，幂等（已完成不可回退）。
- `SKIPPED`：允许用户手动跳过，且需记录原因（可选）。
- `EXPIRED`：系统定时任务（每天 00:10）将前一天未完成任务标记。

### 4.3 关键算法

#### 4.3.1 知识点掌握度更新（增量贝叶斯/指数加权）

```python
def update_proficiency(old: float, is_correct: bool, streak: int, weight: float = 0.3) -> float:
    """
    使用平滑后的增量更新掌握度。
    old: 旧掌握度 [0,1]
    is_correct: 本次是否正确
    streak: 连续正确次数（上限 5）
    weight: 学习率，随答题次数递减
    """
    target = 1.0 if is_correct else 0.0
    streak_bonus = min(streak, 5) * 0.02
    if not is_correct:
        streak_bonus = 0.0
    new_value = old + (target - old) * (weight * (1 - old * 0.5)) + (streak_bonus if is_correct else -0.05)
    return max(0.0, min(1.0, new_value))
```

- 随答题次数增加，weight 衰减（从 0.3 降至 0.1）。
- 连续正确给予额外加成；错误大幅扣减，避免刷题灌水。
- 掌握度 0.7 以上视为“掌握”，0.4 以下视为“薄弱”。

#### 4.3.2 章节掌握度聚合

```python
def compute_chapter_mastery(kp_proficiencies: list[float]) -> float:
    """加权平均，近期学习过的知识点权重更高。"""
    if not kp_proficiencies:
        return 0.0
    return sum(kp_proficiencies) / len(kp_proficiencies)
```

章节完成度 = `completed_tasks / max(total_tasks, 1)`，同时结合学习时长阈值。

### 5.4 服务层示例

```java
package com.primetop.learning.application.service;

import com.primetop.learning.api.dto.*;
import com.primetop.learning.domain.entity.*;
import com.primetop.learning.domain.enums.*;
import com.primetop.learning.domain.event.LearningRecordEvent;
import com.primetop.learning.infrastructure.repository.*;
import com.primetop.learning.infrastructure.cache.LearningCache;
import com.primetop.learning.infrastructure.event.EventPublisher;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.math.BigDecimal;
import java.time.LocalDate;

@Service
@RequiredArgsConstructor
public class LearningService {

    private final LearningRecordRepository recordRepository;
    private final ChapterProgressRepository chapterProgressRepository;
    private final KnowledgePointProficiencyRepository kpRepository;
    private final DailyTaskRepository dailyTaskRepository;
    private final LearningCache learningCache;
    private final EventPublisher eventPublisher;

    /**
     * 记录学习行为，并发布事件驱动后续更新。
     */
    @Transactional
    public RecordLearningResult recordLearning(RecordLearningRequest request) {
        // 幂等校验
        String idempotencyKey = String.format("%d:%s:%s:%s:%s",
                request.getStudentId(), request.getActionType(),
                request.getResourceType(), request.getResourceId(),
                LocalDate.now());
        if (!learningCache.tryLockIdempotency(idempotencyKey, 30)) {
            throw new BusinessException(409, "重复提交，请稍后重试");
        }

        LearningRecord record = new LearningRecord();
        record.setStudentId(request.getStudentId());
        record.setActionType(request.getActionType());
        record.setSubjectCode(request.getSubjectCode());
        record.setResourceType(request.getResourceType());
        record.setResourceId(request.getResourceId());
        record.setChapterId(request.getChapterId());
        record.setKnowledgePointIds(request.getKnowledgePointIds());
        record.setDurationSeconds(request.getDurationSeconds());
        record.setIsCorrect(request.getIsCorrect());
        record.setScore(request.getScore());
        record.setMetadataJson(JsonUtils.toJson(request.getMetadata()));

        recordRepository.save(record);

        // 发布事件，异步更新进度、任务、统计
        eventPublisher.publish(new LearningRecordEvent(record));

        return new RecordLearningResult(record.getId(), record.getCreatedAt());
    }

    /**
     * 事件处理器：更新章节进度与知识点掌握度。
     */
    @Transactional
    public void handleLearningRecordEvent(LearningRecordEvent event) {
        LearningRecord record = event.getRecord();

        if (record.getChapterId() != null) {
            updateChapterProgress(record);
        }
        if (record.getKnowledgePointIds() != null && !record.getKnowledgePointIds().isEmpty()) {
            updateKnowledgePointProficiency(record);
        }
        checkAndCompleteDailyTask(record);
        accumulateDuration(record);
    }

    private void updateChapterProgress(LearningRecord record) {
        ChapterProgress progress = chapterProgressRepository
                .findByStudentIdAndChapterId(record.getStudentId(), record.getChapterId())
                .orElse(initChapterProgress(record));

        // 简化示例：根据行为类型增加完成度，按答题正确率更新掌握度
        if ("PRACTICE".equals(record.getActionType()) && record.getIsCorrect() != null) {
            progress.setAnswerCount(progress.getAnswerCount() + 1);
            if (Boolean.TRUE.equals(record.getIsCorrect())) {
                progress.setCorrectCount(progress.getCorrectCount() + 1);
            }
            BigDecimal mastery = BigDecimal.valueOf(progress.getCorrectCount())
                    .divide(BigDecimal.valueOf(Math.max(progress.getAnswerCount(), 1)), 3, BigDecimal.ROUND_HALF_UP);
            progress.setMasteryRate(mastery);
        }
        progress.setCompletionRate(min(progress.getCompletionRate().add(new BigDecimal("0.05")), BigDecimal.ONE));
        progress.setLastStudyAt(LocalDateTime.now());
        chapterProgressRepository.save(progress);
    }

    private void updateKnowledgePointProficiency(LearningRecord record) {
        for (Long kpId : record.getKnowledgePointIds()) {
            KnowledgePointProficiency kp = kpRepository
                    .findByStudentIdAndKnowledgePointId(record.getStudentId(), kpId)
                    .orElseGet(() -> initKnowledgePointProficiency(record.getStudentId(), kpId, record.getSubjectCode()));

            if ("PRACTICE".equals(record.getActionType()) && record.getIsCorrect() != null) {
                kp.setAnswerCount(kp.getAnswerCount() + 1);
                if (Boolean.TRUE.equals(record.getIsCorrect())) {
                    kp.setCorrectCount(kp.getCorrectCount() + 1);
                    kp.setStreakCount(kp.getStreakCount() + 1);
                } else {
                    kp.setStreakCount(0);
                }
                double weight = 0.3 / (1 + kp.getAnswerCount() / 10.0);
                double newProficiency = ProficiencyAlgorithm.update(
                        kp.getProficiency().doubleValue(),
                        record.getIsCorrect(),
                        kp.getStreakCount(),
                        weight
                );
                kp.setProficiency(BigDecimal.valueOf(newProficiency).setScale(3, BigDecimal.ROUND_HALF_UP));
                kp.setLastAnswerAt(LocalDateTime.now());
            }
            kpRepository.save(kp);
        }
    }

    private void checkAndCompleteDailyTask(LearningRecord record) {
        // 查找当日待完成且资源匹配的任务，自动完成
        List<DailyTask> tasks = dailyTaskRepository
                .findPendingTasksByStudentAndDate(record.getStudentId(), LocalDate.now());
        for (DailyTask task : tasks) {
            if (task.matches(record)) {
                task.setStatus(DailyTaskStatus.DONE);
                task.setCompletedAt(LocalDateTime.now());
                dailyTaskRepository.save(task);
            }
        }
    }

    private void accumulateDuration(LearningRecord record) {
        if (record.getDurationSeconds() == null || record.getDurationSeconds() <= 0) {
            return;
        }
        learningCache.incrementDuration(record.getStudentId(), LocalDate.now(), record.getDurationSeconds());
    }
}
```

### 5.5 控制器层示例

```java
package com.primetop.learning.api;

import com.primetop.learning.api.dto.*;
import com.primetop.learning.application.service.LearningService;
import com.primetop.learning.common.ApiResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.*;
import javax.validation.Valid;

@RestController
@RequestMapping("/api/v1/learning")
@RequiredArgsConstructor
public class LearningController {

    private final LearningService learningService;

    @PostMapping("/records")
    public ApiResponse<RecordLearningResult> record(@Valid @RequestBody RecordLearningRequest request) {
        return ApiResponse.ok(learningService.recordLearning(request));
    }

    @GetMapping("/overview")
    public ApiResponse<LearningOverviewResponse> overview(@RequestParam Long studentId) {
        return ApiResponse.ok(learningService.getOverview(studentId));
    }

    @PostMapping("/daily-tasks/{taskId}/complete")
    public ApiResponse<Void> completeDailyTask(@PathVariable Long taskId, @RequestParam Long studentId) {
        learningService.completeDailyTask(studentId, taskId);
        return ApiResponse.ok();
    }
}
```

## 6. 错误处理

### 6.1 异常类型

| 异常 | 说明 | 处理 |
| --- | --- | --- |
| `BusinessException` | 业务校验失败 | 返回 400/409，提示明确。 |
| `DuplicateRecordException` | 幂等重复 | 返回 409，幂等 key 已存在。 |
| `ExternalServiceException` | 下游服务异常 | 降级返回，记录日志。 |
| `OptimisticLockException` | 并发更新冲突 | 重试 3 次，仍失败则提示。 |
| `IllegalStateTransitionException` | 状态机非法转换 | 返回 400。 |

### 6.2 重试策略

- **记录学习行为**：不重试，写入失败立即返回错误；客户端可重试，服务端幂等。
- **进度更新**：事件消费失败进入死信队列，延迟 30s/60s/180s 重试，最多 5 次。
- **任务生成**：失败可回退至前一天缓存或返回空列表，保证首页不白屏。
- **学习时长统计**：异步聚合，允许分钟级延迟。

### 6.3 降级方案

| 场景 | 降级 |
| --- | --- |
| 学习记录写入失败 | 本地缓存（APP 端），后续批量补报。 |
| 进度更新事件堆积 | 返回旧缓存值，不阻塞学习行为接口。 |
| 规划服务不可用 | 使用本地兜底策略：预习/复习/错题各占 1/3。 |
| 消息服务不可用 | 学习提醒静默失败，不阻塞主流程。 |

## 7. 性能优化

### 7.1 缓存策略

- 首页“今日任务”和“继续学习”强依赖 Redis，减少数据库查询。
- 章节进度与知识点掌握度采用写后缓存（write-through）+ 过期，写入时同时更新缓存。
- 学习时长使用 Redis HyperLogLog / INCR 聚合，每日异步落库。

### 7.2 并发控制

- `chapter_progress` 与 `knowledge_point_proficiency` 更新使用 `SELECT ... FOR UPDATE` 或乐观锁（version 字段）防止并发覆盖。
- 任务完成接口使用分布式锁（`learning:task:{taskId}`）防止重复完成。
- 批量生成任务使用数据库唯一索引避免重复生成：`uk_student_plan_date`。

### 7.3 资源限制

- 单用户单日学习记录写入上限：10,000 条（防止异常刷量）。
- 单接口响应时间目标：记录学习行为 < 200ms，任务查询 < 100ms。
- 学习记录表按 `student_id` 范围分区或分表（当数据量 > 1 亿时）。

### 7.4 异步化

- 学习行为记录写入后，发布事件到消息队列（Kafka/RabbitMQ）。
- 进度、掌握度、任务自动完成、消息提醒均作为事件消费者异步处理。
- 学习日志（埋点）异步写入 ClickHouse/Elasticsearch，不影响主库。

## 8. 安全考虑

### 8.1 权限控制

- 所有接口必须校验 `student_id` 与当前登录用户的所属关系，防止越权访问。
- 家长查看数据时，通过 `ParentBinding` 校验绑定关系。
- 管理后台查询需通过 RBAC 授权。

### 8.2 数据验证

- 输入字段限制长度、枚举值校验、ID 正整数。
- `metadata` JSON 字段限制大小（最大 16KB），禁止嵌套危险字段。
- `duration_seconds` 必须 >= 0，且单日累计超过 12 小时触发风控审计。

### 8.3 审计日志

- 记录学习行为写入、计划调整、任务完成等关键操作。
- 日志包含：操作人、操作类型、时间、影响数据、来源 IP/设备。
- 日志保留 180 天，可导出用于合规审计。

### 8.4 未成年人保护

- 学习时长数据与家长共享需用户（家长）授权。
- 删除账户时，学习数据按《儿童个人信息保护规则》处理，可 anonymize 或删除。

## 9. 测试策略

### 9.1 单元测试

- 覆盖掌握度更新算法、任务匹配逻辑、状态机转换。
- 使用 JUnit 5 + AssertJ / pytest + pytest-cov。
- 示例：

```java
@Test
void proficiencyShouldIncreaseWhenCorrect() {
    double updated = ProficiencyAlgorithm.update(0.5, true, 2, 0.3);
    assertThat(updated).isGreaterThan(0.5);
    assertThat(updated).isLessThanOrEqualTo(1.0);
}

@Test
void completedTaskCannotTransitionToPending() {
    DailyTask task = new DailyTask();
    task.setStatus(DailyTaskStatus.DONE);
    assertThrows(IllegalStateTransitionException.class,
            () -> task.transitionTo(DailyTaskStatus.PENDING));
}
```

### 9.2 集成测试

- 记录学习行为 → 验证 `learning_record` 入库、事件发布、章节进度更新。
- 生成每日任务 → 验证任务数量、顺序、缓存写入。
- 完成任务 → 验证状态流转与重复完成幂等。
- 使用 Testcontainers 启动 MySQL + Redis，模拟消息队列。

### 9.3 性能测试

- 学习行为写入压测：目标 1000 TPS，P99 < 200ms。
- 首页概览查询压测：目标 2000 QPS，P99 < 100ms。
- 任务过期批处理：10 万条任务在 5 分钟内完成状态更新。
