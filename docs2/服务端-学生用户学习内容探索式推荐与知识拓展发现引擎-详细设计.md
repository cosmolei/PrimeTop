# 服务端-学生用户学习内容探索式推荐与知识拓展发现引擎-详细设计

## 1. 概述

### 1.1 模块定位

探索式推荐与知识拓展发现引擎（Exploratory Recommendation & Knowledge Discovery Engine，简称 ERKDE）是 PrimeTop 推荐体系中的**探索层（Exploration Layer）**。

现有推荐引擎全部采用**利用导向（Exploitation）**策略——基于学生已有画像推荐"最需要"的内容（薄弱点补强、同步课堂跟进、错题复习等）。ERKDE 补齐了**探索导向（Exploration）**能力，主动向学生推荐：

- 他们尚未接触但**可能感兴趣**的知识领域
- 跨学科的**知识桥梁内容**（如喜欢数学的学生发现编程的乐趣）
- **趋势性学习内容**（近期平台热门、学科前沿应用）
- **适度超前**的认知挑战内容（最近发展区上沿）

### 1.2 核心目标

| 目标 | 说明 |
|------|------|
| 打破信息茧房 | 避免学生长期局限于"只学推荐薄弱点"的循环 |
| 激发学习兴趣 | 通过有趣、意外的知识发现提升学习内驱力 |
| 拓展认知边界 | 系统性引入学生知识图谱中的"邻接但未探索"区域 |
| 平衡探索与利用 | 在保证核心学习闭环的前提下，控制探索内容的占比 |

### 1.3 适用范围

- **学段**：小学及以上（幼儿阶段不适用，因认知范围有限且需要更结构化的引导）
- **触发场景**：首页"发现"卡片、学习完成后的"拓展推荐"、周末/假期的"探索任务"
- **推荐粒度**：知识点级、内容单元级、学科主题级

### 1.4 与现有模块边界

| 现有模块 | 策略 | 与本引擎区别 |
|----------|------|-------------|
| 题目智能推荐与个性化练习编排服务 | 利用导向，推荐"最需要练"的题 | 本引擎推荐"可能感兴趣"的知识领域 |
| 自适应学习与个性化推荐引擎 | 基于掌握度差距做路径规划 | 本引擎不关注差距，关注兴趣可能性 |
| 推荐内容多样性保障与信息茧房破壁引擎 | 在已有推荐结果中做多样性重排 | 本引擎从源头生成探索性候选集 |
| 教育内容推荐冷启动策略引擎 | 新用户无数据时的冷启动 | 本引擎适用于有历史数据的用户，做跨域探索 |
| 知识图谱浏览与关联学习 | 用户主动浏览知识图谱 | 本引擎系统主动推送探索内容 |
| 学习内容热度评估与趋势发现引擎 | 平台维度的热度统计 | 本引擎做个性化热度匹配 |

### 2.2 核心流程

```text
学生请求推荐 → 探索触发条件检查
  │
  ├─ 不满足触发条件 → 返回空，由常规推荐引擎接管
  │
  └─ 满足触发条件 → 并行执行三个探索策略
       │
       ├─ ① 兴趣边界扩展：找到学生兴趣领域的"边缘地带"
       ├─ ② 知识邻接发现：在知识图谱中找"已掌握→未探索"的邻接节点
       └─ ③ 跨域桥梁构建：找跨学科的兴趣迁移路径
            │
            ▼
       候选集融合 → 探索价值评分 → 认知负荷校验 → 时机判定
            │
            ▼
       输出 Top-N 探索推荐（附带"为什么推荐给你"解释）
```

```sql
    exposure_count  INT          NOT NULL DEFAULT 0 COMMENT '该域内容曝光次数',
    engage_count    INT          NOT NULL DEFAULT 0 COMMENT '该域内容有效交互次数(点击/完成/收藏)',

    last_exposure_at DATETIME(3) DEFAULT NULL COMMENT '最近一次曝光时间',
    last_engage_at  DATETIME(3)  DEFAULT NULL COMMENT '最近一次有效交互时间',

    updated_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    
    UNIQUE KEY uk_user_domain (user_id, domain_code),
    KEY idx_user_interest (user_id, interest_score DESC),
    KEY idx_subject (subject_code)
```

### 3.2 知识域关联图谱表 `knowledge_domain_graph`

描述知识域之间的关联关系，用于跨域探索。

```sql

    KEY idx_target (target_domain)
```

| `ANALOGOUS` | 跨学科类比 | 数学函数→物理运动规律 |
| `CROSS_BRIDGE` | 跨学科桥梁 | 代数→编程逻辑→算法思维 |

## 4. 核心算法设计

### 4.1 探索触发条件检查器

不是每次请求都触发探索推荐。需要判断当前是否适合探索。

```python
class ExplorationTriggerChecker:
    """探索触发条件检查器"""
    
    # 探索触发阈值配置（按学段差异化）
    TRIGGER_CONFIG = {
        "primary": {   # 小学
            "min_mastery_avg": 0.45,      # 核心学习不能太差才允许探索
            "max_explore_ratio": 0.15,    # 探索内容占比上限15%
            "daily_explore_limit": 3,     # 每日最多3次探索推荐
            "min_core_task_completion": 0.6,  # 核心任务完成率需≥60%
        },
        "junior": {    # 初中
            "min_mastery_avg": 0.40,
            "max_explore_ratio": 0.20,
            "daily_explore_limit": 5,
            "min_core_task_completion": 0.5,
        },
        "senior": {    # 高中
            "min_mastery_avg": 0.35,
            "max_explore_ratio": 0.25,
            "daily_explore_limit": 5,
            "min_core_task_completion": 0.4,
        }
    }
    
    def should_explore(self, user_id: int, context: dict) -> tuple[bool, str]:
        """
        判断是否应该触发探索推荐。
        
        Returns:
            (should_explore: bool, reason: str)
        """
        grade_stage = context["grade_stage"]  # primary/junior/senior
        config = self.TRIGGER_CONFIG[grade_stage]
        
        # 1. 核心任务完成率检查
        core_completion = context.get("core_task_completion", 0)
        if core_completion < config["min_core_task_completion"]:
            return False, "核心学习任务完成率不足，暂不探索"
        
        # 2. 整体掌握度检查（避免薄弱学生过度探索）
        mastery_avg = context.get("mastery_avg", 0)
        if mastery_avg < config["min_mastery_avg"]:
            return False, "整体掌握度偏低，优先补强薄弱点"
        
        # 3. 当日探索次数限制
        daily_count = self._get_daily_explore_count(user_id)
        if daily_count >= config["daily_explore_limit"]:
            return False, "今日探索推荐次数已用完"
        
        # 4. 探索疲劳度检查（连续忽略3次则暂停）
        fatigue = self._get_explore_fatigue(user_id)
        if fatigue["consecutive_dismiss"] >= 3:
            return False, "学生可能对探索推荐不感兴趣，暂停一段时间"
        
        # 5. 场景适配检查
        scene = context.get("scene")
        if scene not in ["HOME_DISCOVERY", "POST_LEARNING", "WEEKEND_EXPLORE"]:
            return False, f"场景{scene}不适合探索推荐"
        
        return True, "OK"
```

### 4.2 兴趣边界扩展器（Boundary Expansion）

基于学生现有兴趣域，找到兴趣域的"边界"——即学生有一定接触但尚未深入的知识域。

```python
class BoundaryExpansionStrategy:
    """
    兴趣边界扩展策略。
    
    核心思想：学生的兴趣不是二元的（有兴趣/没兴趣），
    而是从"核心兴趣域"向外辐射，存在"边缘兴趣域"。
    本策略找到这些边缘域并推荐。
    """
    
    def discover(self, user_id: int, interest_profile: dict) -> list[dict]:
        """
        发现兴趣边界。
        
        Args:
            interest_profile: 学生兴趣域画像
            {"MATH_ALGEBRA": 0.85, "MATH_GEOMETRY": 0.62, "PHYSICS_MECHANICS": 0.15, ...}
        
        Returns:
            探索候选列表
        """
        candidates = []
        
        for domain_code, score in interest_profile.items():
            # 划分兴趣层次
            if score >= 0.7:
                tier = "CORE"        # 核心兴趣域
            elif score >= 0.4:
                tier = "ACTIVE"     # 活跃兴趣域
            elif score >= 0.15:
                tier = "PERIPHERAL" # 边缘兴趣域（重点探索对象）
            else:
                tier = "UNKNOWN"    # 未知域
            
            # 策略：对ACTIVE域，寻找其邻接但学生未探索的域
            if tier == "ACTIVE":
                adjacent_domains = self._get_adjacent_domains(domain_code)
                for adj in adjacent_domains:
                    if adj["target_domain"] not in interest_profile or \
                       interest_profile.get(adj["target_domain"], 0) < 0.1:
                        # 学生几乎没接触过的邻接域
                        explore_score = self._calc_boundary_score(
                            source_score=score,
                            relation_strength=adj["relation_strength"],
                            target_exposure=interest_profile.get(adj["target_domain"], 0)
                        )
                        candidates.append({
                            "domain": adj["target_domain"],
                            "source_domain": domain_code,
                            "exploration_type": "BOUNDARY_EXPANSION",
                            "score": explore_score,
                            "reason": f"你对{self._domain_name(domain_code)}很感兴趣，"
                                      f"{self._domain_name(adj['target_domain'])}和它密切相关"
                        })
        
        # 对PERIPHERAL域，直接推荐（学生已有初步接触，值得深化）
        for domain_code, score in interest_profile.items():
            if 0.15 <= score < 0.4:
                candidates.append({
                    "domain": domain_code,
                    "source_domain": None,
                    "exploration_type": "BOUNDARY_EXPANSION",
                    "score": score * 0.8,  # 边缘域本身分数较低
                    "reason": f"你之前看过一些{self._domain_name(domain_code)}的内容，"
                              f"想不想深入了解？"
                })
        
        return sorted(candidates, key=lambda x: x["score"], reverse=True)[:10]
    
    def _calc_boundary_score(self, source_score: float, 
                              relation_strength: float, 
                              target_exposure: float) -> float:
        """计算边界扩展探索分数"""
        # 来源兴趣越强、关联越紧、目标越陌生 → 探索价值越高
        novelty = 1.0 - target_exposure  # 新颖度
        return source_score * relation_strength * novelty * 0.9
```

### 4.3 知识邻接发现器（Adjacent Discovery）

在学科知识图谱中，寻找"学生已掌握的知识点 → 邻接但未探索的知识点"路径。

```python
class AdjacentDiscoveryStrategy:
    """
    知识邻接发现策略。
    
    在知识图谱中寻找模式：
    学生已掌握A → A的前置是B(已掌握) → A的后续是C(未探索) → 推荐C
    
    特别关注"桥梁知识点"——同时是多个后续知识前置依赖的关键节点。
    """
    
    def discover(self, user_id: int, mastery_map: dict, kp_graph: dict) -> list[dict]:
        """
        在知识图谱上发现邻接但未探索的区域。
        
        Args:
            mastery_map: {knowledge_point_id: mastery_score, ...}
            kp_graph: 知识图谱邻接表 {kp_id: [{"target": kp_id, "type": "next/postreq", "weight": 0.8}]} 
        Returns:
            探索候选列表
        """
        candidates = []
        mastered_kps = [kp for kp, m in mastery_map.items() if m >= 0.7]
        
        for kp_id in mastered_kps:
            # 在知识图谱中找该知识点的后续节点
            neighbors = kp_graph.get(kp_id, [])
            for edge in neighbors:
                target_kp = edge["target"]
                target_mastery = mastery_map.get(target_kp, 0)
                
                # 目标知识点尚未探索（掌握度 < 0.3）
                if target_mastery < 0.3:
                    # 检查路径上是否有充足的准备（前置链路已掌握）
                    prereqs_met = self._check_prerequisites(target_kp, mastery_map, kp_graph)
                    
                    if prereqs_met:
                        explore_score = self._calc_adjacent_score(
                            source_mastery=mastery_map[kp_id],
                            edge_weight=edge["weight"],
                            target_mastery=target_mastery,
                            kp_importance=edge.get("importance", 0.5)
                        )
                        candidates.append({
                            "domain": str(target_kp),
                            "source_domain": str(kp_id),
                            "exploration_type": "ADJACENT_DISCOVERY",
                            "score": explore_score,
                            "reason": f"你已经掌握了「{self._kp_name(kp_id)}」，"
                                      f"接下来可以探索「{self._kp_name(target_kp)}」"
                        })
        
        return sorted(candidates, key=lambda x: x["score"], reverse=True)[:8]
    
    def _check_prerequisites(self, kp_id, mastery_map, kp_graph) -> bool:
        """检查目标知识点的前置条件是否满足"""
        # 反向查图谱，找该知识点的前置依赖
        prereqs = self._get_prerequisites(kp_id, kp_graph)
        for prereq in prereqs:
            if mastery_map.get(prereq["id"], 0) < prereq["required_mastery"]:
                return False
        return True
    
    def _calc_adjacent_score(self, source_mastery, edge_weight, 
                              target_mastery, kp_importance) -> float:
        """计算邻接发现探索分数"""
        readiness = source_mastery * edge_weight  # 准备度
        novelty = 1.0 - target_mastery             # 新颖度
        return readiness * novelty * (0.5 + kp_importance * 0.5)
```

### 4.4 跨域桥梁构建器（Cross-Bridge Builder）

利用跨学科关联，将一个学科的兴趣迁移到另一个学科。

```python
class CrossBridgeStrategy:
    """
    跨域桥梁构建策略。
    
    核心思想：学生喜欢数学中的「函数」，那可能也会对物理中的「
    运动规律」感兴趣（函数是描述物理运动的数学工具）。
    通过跨域桥梁表进行兴趣迁移。
    """
    
    BRIDGE_TEMPLATES = {
        ("MATH_FUNCTION", "PHYSICS_KINEMATICS"): {
            "bridge": "函数是描述物理运动的数学语言",
            "common_concept": "变量关系",
            "difficulty_delta": 0.1,  # 目标域允许比源域略难
        },
        ("MATH_GEOMETRY", "PHYSICS_OPTICS"): {
            "bridge": "光的传播与几何图形密切相关",
            "common_concept": "角度与路径",
            "difficulty_delta": 0.0,
        },
        ("CHINESE_POETRY", "HISTORY_ANCIENT"): {
            "bridge": "古诗文承载着丰富的历史背景",
            "common_concept": "历史与文化",
            "difficulty_delta": -0.1,
        },
        ("MATH_ALGEBRA", "CS_PROGRAMMING"): {
            "bridge": "代数思维是编程的基础",
            "common_concept": "逻辑与抽象",
            "difficulty_delta": 0.15,
        },
        ("BIO_CELLS", "CHEMISTRY_ORGANIC"): {
            "bridge": "细胞活动本质上是化学反应",
            "common_concept": "分子与生命",
            "difficulty_delta": 0.1,
        },
    }
    
    def discover(self, user_id: int, interest_profile: dict, 
                 user_grade: str) -> list[dict]:
        """
        基于跨域桥梁表发现跨学科探索机会。
        """
        candidates = []
        
        for (source_domain, target_domain), bridge_info in self.BRIDGE_TEMPLATES.items():
            source_score = interest_profile.get(source_domain, 0)
            target_score = interest_profile.get(target_domain, 0)
            
            # 源域有兴趣、目标域几乎未接触
            if source_score >= 0.5 and target_score < 0.2:
                # 检查学段适配（如编程只推荐给初中以上）
                if not self._is_grade_appropriate(target_domain, user_grade):
                    continue
                
                explore_score = source_score * (1.0 - target_score) * 0.85
                candidates.append({
                    "domain": target_domain,
                    "source_domain": source_domain,
                    "exploration_type": "CROSS_BRIDGE",
                    "score": explore_score,
                    "reason": (
                        f"你喜欢「{self._domain_name(source_domain)}」，"
                        f"{bridge_info['bridge']}。"
                        f"试试「{self._domain_name(target_domain)}」吧！"
                    )
        
        return sorted(candidates, key=lambda x: x["score"], reverse=True)[:5]
    
    def _is_grade_appropriate(self, domain: str, grade: str) -> bool:
        """检查目标域是否适合学生年级"""
        # CS_PROGRAMMING 只推荐给初中及以上
        if domain.startswith("CS_"):
            return grade in ["G7", "G8", "G9", "G10", "G11", "G12"]
        return True
```

### 4.5 探索候选集融合与评分

三个策略的候选集合并后统一评分。

```python
class CandidateFusionScorer:
    """探索候选集融合评分器"""
    
    def score_and_rank(self, candidates: list[dict], 
                       user_context: dict) -> list[dict]:
        """
        对融合后的候选集进行多维度评分。
        
        评分维度:
          - strategy_score:    策略原始分 (0~1)
          - novelty_score:     新颖度 (0~1) - 越陌生越高
          - readiness_score:   准备度 (0~1) - 前置知识越充分越高
          - interest_lift:     预期兴趣提升 (0~1)
          - cognitive_fit:     认知适宜度 (0~1)
        """
        scored = []
        for c in candidates:
            # 综合评分公式
            final_score = (
                c["score"] * 0.30 +           # 策略原始分
                self._calc_novelty(c, user_context) * 0.25 +  # 新颖度
                self._calc_readiness(c, user_context) * 0.20 + # 准备度
                self._calc_interest_lift(c, user_context) * 0.15 + # 预期兴趣提升
                self._calc_cognitive_fit(c, user_context) * 0.10  # 认知适宜度
            )
            c["final_score"] = round(final_score, 4)
            scored.append(c)
        
        return sorted(scored, key=lambda x: x["final_score"], reverse=True)
    
    def _calc_novelty(self, candidate, ctx) -> float:
        """新颖度：该域在最近30天内的曝光次数越少越高"""
        exposure = ctx.get("recent_exposure", {}).get(candidate["domain"], 0)
        return max(0, 1.0 - exposure * 0.15)
    
    def _calc_readiness(self, candidate, ctx) -> float:
        """准备度：前置知识掌握程度"""
        if candidate.get("source_domain"):
            return ctx.get("mastery_map", {}).get(
                candidate["source_domain"], 0.3
            )
        return 0.5  # 无明确前置时给中等分
    
    def _calc_interest_lift(self, candidate, ctx) -> float:
        """预期兴趣提升：基于同类学生的兴趣转化率"""
        # 查询群体数据：和该学生相似的学生中，
        # 接触该域后兴趣分数提升的比例
        return ctx.get("cohort_interest_lift", {}).get(
            candidate["domain"], 0.5
        )
    
    def _calc_cognitive_fit(self, candidate, ctx) -> float:
        """认知适宜度：检查目标域难度是否在学生可达范围内"""
        target_difficulty = ctx.get("domain_difficulty", {}).get(
            candidate["domain"], 0.5
        )
        user_ability = ctx.get("ability_estimate", 0.5)
        # 最近发展区：目标难度略高于当前能力但不过大
        zpd_lower = user_ability + 0.05
        zpd_upper = user_ability + 0.25
        if zpd_lower <= target_difficulty <= zpd_upper:
            return 1.0  # 完美匹配最近发展区
        elif target_difficulty < zpd_lower:
            return 0.7  # 太简单，略有价值
        else:
            return max(0, 1.0 - (target_difficulty - zpd_upper) * 3)
```

### 4.6 认知负荷校验器

确保探索推荐不会增加过多认知负担。

```python
class CognitiveLoadValidator:
    """认知负荷校验器"""
    
    MAX_DAILY_EXPLORE_MINUTES = 20  # 每日探索学习总时长上限
    MAX_CONCURRENT_EXPLORE_DOMAINS = 2  # 同时探索的域不超过2个
    
    def validate(self, candidate, user_context) -> tuple[bool, str]:
        # 1. 并发探索域数量检查
        active_explore_domains = user_context.get("active_explore_domains", [])
        if (candidate["domain"] not in active_explore_domains and
            len(active_explore_domains) >= self.MAX_CONCURRENT_EXPLORE_DOMAINS):
            return False, f"已有{len(active_explore_domains)}个探索域在进行中"
        
        # 2. 今日探索时长检查
        today_explore_min = user_context.get("today_explore_minutes", 0)
        if today_explore_min >= self.MAX_DAILY_EXPLORE_MINUTES:
            return False, "今日探索学习时长已达上限"
        
        # 3. 学科负荷均衡检查
        subject = candidate.get("recommended_subject")
        subject_time_today = user_context.get("subject_time_today", {}).get(subject, 0)
        total_time_today = sum(user_context.get("subject_time_today", {}).values())
        if total_time_today > 0:
            subject_ratio = subject_time_today / total_time_today
            if subject_ratio > 0.6:
                return False, f"{subject}学科占比已超过60%"
        
        return True, "OK"
```

### 8.1 隐式兴趣评分

```python
class ImplicitInterestScorer:
    """从行为事件中推断兴趣分数"""
    
    SIGNAL_WEIGHTS = {
        "content_complete":  0.25,
        "dwell_long":        0.12,
        "bookmark":          0.20,
        "ai_question":       0.15,
        "practice_extra":    0.15,
        "share":             0.10,
        "revisit":           0.10,
        "dismiss":          -0.08,
        "dwell_short":      -0.05,
    }
    
    def calculate(self, events: list[dict], window_days: int = 30) -> float:
        if not events:
            return 0.0
        raw_score = 0.0
        for event in events:
            signal = self._classify(event)
            weight = self.SIGNAL_WEIGHTS.get(signal, 0)
            decay = self._time_decay(event["ts"], window_days)
            raw_score += weight * decay
        return round(1.0 / (1.0 + math.exp(-raw_score * 2)), 4)
```
