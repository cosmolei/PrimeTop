# 首页薄弱点提醒服务 - 详细设计文档

## 1. 概述

### 1.1 模块定位

首页薄弱点提醒服务（Home Weak-Point Reminder Service，简称 HWRS）是 PrimeTop **学习工作台首页**的个性化数据子服务。它负责把学生的错题、答题记录、知识点掌握度等数据转化为首页可展示、可行动的“薄弱点提醒卡片”，引导学生针对性地进行复习和练习。

该服务的核心价值：

- **化数据为行动**：将学情分析结果直接呈现在首页，减少学生的决策成本。
- **精准干预**：基于错误率、遗忘曲线、计划冲突等多维因素，选择当前最需要复习的知识点。
- **闭环反馈**：记录学生的点击、忽略、完成等行为，回流给推荐和学情分析引擎，持续优化提醒质量。

### 1.2 覆盖学段

全学段（幼儿启蒙阶段暂不展示知识性薄弱点，可替换为“识字/拼音待巩固”等低龄化提醒）。

### 1.3 优先级

P1 — V1.0 阶段核心体验功能。

### 1.4 核心职责

| 职责 | 说明 |
|------|------|
| 薄弱点计算 | 基于答题记录、错题记录、掌握度数据，计算每个学生当前需要复习的知识点 |
| 提醒卡片生成 | 为每个薄弱点生成提醒卡片，包含标题、原因、推荐动作、预计用时 |
| 排序与去重 | 综合紧迫度、新鲜感、计划冲突等因素排序，避免同一知识点反复刷屏 |
| 用户动作处理 | 支持点击学习、一键忽略/稍后提醒、标记已掌握 |
| 首页数据聚合 | 为首页工作台接口提供 `home/weak-point-reminders` 数据 |
| 数据回流 | 将用户反馈回流给学情分析和推荐引擎 |

### 1.5 依赖关系

```text
首页薄弱点提醒服务
├── 依赖：用户账号体系（User Service）          — 获取用户学段、年级、学科设置
├── 依赖：答题记录服务（Answer Record Service）— 获取近期答题正确率、次数
├── 依赖：错题服务（Mistake Service）          — 获取错题分布、复习状态
├── 依赖：知识点掌握度服务（Mastery Service）  — 获取知识点掌握度
├── 依赖：学习计划服务（Study Plan Service）    — 避免与今日已安排任务重复
├── 依赖：内容服务（Content Service）          — 获取知识点的名称、章节、推荐资源
├── 依赖：消息服务（Notification Service）    — 触发 push/站内信提醒
└── 被依赖：学生端首页 / 家长端首页 / 数据看板
```

## 2. 术语与概念

| 术语 | 说明 |
|------|------|
| 薄弱点（Weak Point） | 学生在某个知识点上表现出的低掌握度、高错误率或长期未复习状态 |
| 提醒卡片（Reminder Card） | 首页展示的、可点击的薄弱点提醒单元 |
| 紧迫度分（Urgency Score） | 0-100 的综合评分，决定卡片排序；越高越优先 |
| 提醒状态 | `pending` / `shown` / `clicked` / `dismissed` / `mastered` / `expired` |
| 冷去期（Cooldown） | 用户忽略某卡片后，一段时间内不再展示该知识点的时长 |
| 复习动作 | 快速练习、查看解析、观看微课、加入错题本等 |

## 5. 关键代码示例

### 5.1 薄弱点计算流程

```java
@Service
@RequiredArgsConstructor
public class WeakPointComputeService {

    private final AnswerRecordClient answerRecordClient;
    private final MistakeClient mistakeClient;
    private final MasteryClient masteryClient;
    private final StudyPlanClient studyPlanClient;
    private final WeakPointReminderRepository reminderRepository;
    private final RedisTemplate<String, String> redisTemplate;

    /**
     * 为指定用户计算首页薄弱点提醒
     */
    public List<WeakPointReminder> computeForUser(String userId, ComputeTrigger trigger) {
        // 1. 获取用户学段/年级/学科设置
        UserProfile profile = userService.getProfile(userId);

        // 2. 拉取基础数据
        LocalDateTime since = LocalDateTime.now().minusDays(30);
        List<AnswerStat> answerStats = answerRecordClient.getKnowledgePointStats(userId, since);
        List<MistakeStat> mistakeStats = mistakeClient.getKnowledgePointStats(userId, since);
        Map<String, Integer> masteryMap = masteryClient.getLatestMastery(userId);
        Set<String> plannedKps = studyPlanClient.getTodayKnowledgePoints(userId);

        // 3. 合并所有知识点
        Map<String, WeakCandidate> candidates = mergeCandidates(answerStats, mistakeStats, masteryMap);

        // 4. 过滤与评分
        List<WeakCandidate> scored = candidates.values().stream()
            .filter(c -> filterCandidate(c, plannedKps))
            .map(this::scoreCandidate)
            .filter(c -> c.getUrgencyScore() >= 60)
            .sorted(Comparator.comparing(WeakCandidate::getUrgencyScore).reversed())
            .limit(20)
            .collect(Collectors.toList());

        // 5. 去重：同一知识点在冷去期内不重复创建
        Set<String> coolingKps = getCoolingKnowledgePoints(userId);

        // 6. 生成提醒记录
        List<WeakPointReminder> reminders = scored.stream()
            .filter(c -> !coolingKps.contains(c.getKnowledgePointId()))
            .map(c -> buildReminder(userId, c, profile))
            .collect(Collectors.toList());

        // 7. 持久化并更新缓存
        reminderRepository.batchUpsert(reminders);
        refreshHomeCache(userId);

        return reminders;
    }

    private WeakCandidate scoreCandidate(WeakCandidate c) {
        double errorRate = c.getCorrectCount() + c.getWrongCount() == 0
            ? 0 : (double) c.getWrongCount() / (c.getCorrectCount() + c.getWrongCount());

        // 错误率分（0-40）
        int errorScore = (int) Math.min(40, errorRate * 40);

        // 掌握度低分（0-30）
        int masteryScore = (int) Math.max(0, (60 - c.getMasteryScore()) / 60.0 * 30);

        // 长期未复习分（0-20）
        int reviewScore = Math.min(20, c.getDaysSinceReview() * 2);

        // 错题反复分（0-10）
        int repeatScore = Math.min(10, c.getRepeatedMistakeCount() * 2);

        // 学段权重：越高年级，理科知识点权重略升
        double gradeWeight = 1.0;
        if (c.getSubjectId().equals("sub_math")) gradeWeight = 1.1;

        int urgency = (int) Math.min(100, (errorScore + masteryScore + reviewScore + repeatScore) * gradeWeight);
        c.setUrgencyScore(urgency);
        return c;
    }

    private boolean filterCandidate(WeakCandidate c, Set<String> plannedKps) {
        // 今日已有计划安排的知识点不展示
        if (plannedKps.contains(c.getKnowledgePointId())) return false;
        // 总练习次数不足 3 次不判定
        if (c.getCorrectCount() + c.getWrongCount() < 3) return false;
        // 近期已掌握（掌握度 > 85 且 7 天内正确率 > 80%）不展示
        if (c.getMasteryScore() > 85 && c.getRecentCorrectRate() > 0.8) return false;
        return true;
    }

    private Set<String> getCoolingKnowledgePoints(String userId) {
        String key = "hwr:cooldown:" + userId;
        Set<String> members = redisTemplate.opsForSet().members(key);
        if (members == null) return Collections.emptySet();
        long now = System.currentTimeMillis();
        return members.stream()
            .filter(m -> {
                String[] parts = m.split(":");
                if (parts.length != 2) return false;
                long ts = Long.parseLong(parts[1]);
                return ts > now;
            })
            .map(m -> m.split(":")[0])
            .collect(Collectors.toSet());
    }
}
```

### 5.2 推荐动作与内容选择

```java
public class RecommendedActionResolver {

    public RecommendedAction resolve(WeakCandidate c, List<ContentResource> resources) {
        if (c.getRepeatedMistakeCount() >= 2) {
            return RecommendedAction.REVIEW_MISTAKE;
        }
        if (c.getMasteryScore() < 40 && hasVideo(resources)) {
            return RecommendedAction.WATCH_VIDEO;
        }
        if (c.getErrorRate() > 0.6) {
            return RecommendedAction.VIEW_EXPLANATION;
        }
        return RecommendedAction.QUICK_PRACTICE;
    }

    private boolean hasVideo(List<ContentResource> resources) {
        return resources.stream().anyMatch(r -> r.getType() == ContentType.VIDEO);
    }
}
```

### 5.3 首页缓存刷新

```java
public void refreshHomeCache(String userId) {
    String key = "hwr:home:" + userId;
    List<WeakPointReminder> reminders = reminderRepository
        .findActiveByUserAndScene(userId, ReminderScene.HOME, PageLimit.of(10));

    if (reminders.isEmpty()) {
        redisTemplate.delete(key);
        return;
    }

    redisTemplate.opsForZSet().removeRange(key, 0, -1);
    for (WeakPointReminder r : reminders) {
        double score = r.getUrgencyScore();
        redisTemplate.opsForZSet().add(key, JsonUtils.toJson(r), score);
    }
    redisTemplate.expire(key, Duration.ofHours(1));
}
```

### 5.4 用户点击后状态流转

```java
@Transactional
public ReminderActionResult click(String userId, String reminderId, String clientInfo) {
    WeakPointReminder reminder = reminderRepository.findById(reminderId)
        .orElseThrow(() -> new BizException(ReminderErrorCode.REMINDER_NOT_FOUND));

    if (!reminder.getUserId().equals(userId)) {
        throw new BizException(CommonErrorCode.FORBIDDEN);
    }

    if (reminder.getStatus() == ReminderStatus.EXPIRED) {
        throw new BizException(ReminderErrorCode.REMINDER_EXPIRED);
    }

    reminder.setStatus(ReminderStatus.CLICKED);
    reminder.setClickedAt(LocalDateTime.now());
    reminderRepository.update(reminder);

    actionLogRepository.insert(new ActionLog(reminderId, userId, "click", clientInfo));

    // 发送学习意图事件，触发学习计划、学情分析更新
    eventPublisher.publish(new WeakPointClickedEvent(userId, reminder.getKnowledgePointId(),
        reminder.getRecommendedAction(), reminder.getRecommendedContentId()));

    refreshHomeCache(userId);
    return new ReminderActionResult(reminderId, ReminderStatus.CLICKED, null);
}
```


### 6.2 状态转换条件

| 源状态 | 目标状态 | 触发条件 | 附加动作 |
|--------|----------|----------|----------|
| none | pending | 计算任务生成新提醒 | 写入主表，写入缓存 |
| pending | shown | 首页接口返回该卡片 | 记录曝光日志 |
| shown | clicked | 用户点击“去学习” | 跳转、发送点击事件、刷新缓存 |
| shown | dismissed | 用户点击“忽略”或“稍后提醒” | 写入冷去集合、N 小时内不再生成同知识点提醒 |
| shown | mastered | 用户点击“已掌握” | 更新掌握度、N 天内不再提醒 |
| pending/shown | expired | 到达 valid_end 且未交互 | 软标记过期，不删除 |

### 6.3 冷去与防刷策略

- **忽略冷去**：默认 24 小时，用户可主动选择“24 小时后提醒我”或“本周不再提醒”。
- **掌握标记**：标记后 7 天内不再生成该知识点提醒，若后续数据重新变差可再次生成。
- **曝光去重**：同一张卡片 24 小时内最多曝光 5 次，超过则自动降低排序权重。

## 7. 错误处理

### 7.1 业务错误码

| 错误码 | 含义 | 说明 |
|--------|------|------|
| `REMINDER_0001` | 提醒不存在 | reminder_id 无效 |
| `REMINDER_0002` | 提醒已过期 | 超过 valid_end |
| `REMINDER_0003` | 无权限操作 | 非本人提醒 |
| `REMINDER_0004` | 提醒状态不可操作 | 如已点击后不能忽略 |
| `REMINDER_0005` | 计算任务冲突 | 分布式锁未释放 |
| `REMINDER_0006` | 下游服务降级 | 依赖服务超时或不可用 |

### 7.2 异常降级策略

```java
@CircuitBreaker(name = "weakPointCompute", fallbackMethod = "fallbackCompute")
public List<WeakPointReminder> computeForUser(String userId, ComputeTrigger trigger) {
    // 正常计算逻辑
}

public List<WeakPointReminder> fallbackCompute(String userId, ComputeTrigger trigger, Throwable ex) {
    log.warn("薄弱点计算降级，userId={}", userId, ex);
    // 1. 返回缓存中的旧提醒（若有）
    List<WeakPointReminder> cached = getFromCache(userId);
    if (!cached.isEmpty()) return cached;

    // 2. 返回基于错题的简化策略：直接取最近 3 条错题知识点
    return mistakeClient.getRecentMistakeKnowledgePoints(userId, 3).stream()
        .map(kp -> buildSimpleReminder(userId, kp))
        .collect(Collectors.toList());
}
```

### 7.3 幂等性保证

- 提醒 ID 采用 `userId:knowledgePointId:scene:date` 的哈希生成策略，保证同一天同一知识点同一用户只生成一条提醒。
- 用户动作接口使用数据库唯一索引 + 状态校验，重复请求返回相同结果。
- 计算任务通过 Redis 分布式锁避免并发重复计算。

## 8. 性能优化

### 8.1 预计算策略

- **定时任务**：每日凌晨 2:00 对所有活跃用户批量预计算一次。
- **事件触发**：每次学生完成一次练习或错题复习后，异步触发该用户的增量计算。
- **手动刷新**：用户下拉首页时允许触发，但受 5 分钟内最多 1 次的限流。

### 8.2 缓存与查询优化

- 首页接口优先从 Redis Sorted Set 读取，避免直接查库。
- 数据库索引覆盖 `(user_id, scene, status, urgency_score)`，排序走索引。
- 每日快照表按 `user_id + snapshot_date` 分区归档，避免大表扫描。
- 计算任务异步线程池执行，避免阻塞首页请求。

### 8.3 并发控制

- 单用户计算加 Redis 锁 `hwr:lock:compute:{userId}`，锁超时 5 分钟。
- 批量计算任务分片处理，每片 500 用户，避免数据库连接池打满。

## 9. 安全与合规

### 9.1 权限控制

- 学生只能查看和操作自己的提醒。
- 家长端查看需通过 `ParentBinding` 校验，且只展示 `is_visible_to_parent` 为 true 的数据。
- 内部计算接口必须携带服务间 token，禁止客户端直接调用。

### 9.2 数据隐私

- 不采集、不存储任何可定位到具体学校或班级的敏感信息。
- 薄弱点数据属于学生学习画像的一部分，导出、分享需脱敏处理。
- 未成年人账号的提醒内容需经过内容安全审核，避免出现打击自尊、过度焦虑等表述。

### 9.3 内容安全

- `reason_text` 字段由服务端统一模板渲染，禁止直接拼接学生数据后透传给 AI 生成。
- 推荐内容和 deeplink 需经过内容审核，确保适龄、正确。
