# 服务端 - 学习动力量化与学习倦怠预警引擎 详细设计

## 1. 模块概述

### 1.1 功能定位

学习动力量化与学习倦怠预警引擎通过持续追踪学生的学习行为特征（包括学习时长变化、任务完成积极性、互动深度、情绪信号等），构建学生学习动力指数（Learning Motivation Index, LMI），并在动力持续下降至危险阈值时自动触发倦怠预警，生成干预建议推送至学生端、家长端，帮助学生在失去学习兴趣前获得正向引导。

### 1.2 与现有模块的边界

| 模块 | 关注点 | 与本模块的区别 |
|------|--------|---------------|
| 学生学习风险评估与早期预警系统 | **学业风险**——知识点断层、正确率下降 | 关注"学不会"，本模块关注"不想学" |
| 用户流失预警与智能挽留策略引擎 | **商业流失**——用户即将卸载/停止使用 | 关注"不用了"，本模块关注"学累了" |
| 用户活跃度统计与留存分析引擎 | **活跃指标**——DAU/留存率等运营数据 | 是统计工具，本模块是行为分析+干预 |
| 学习习惯养成与打卡系统 | **习惯建立**——通过打卡机制培养习惯 | 是正向激励工具，本模块是预警诊断工具 |
| 学习提醒与智能通知调度系统 | **消息通道**——统一通知分发 | 本模块生产预警内容，由通知系统分发 |

**核心定位**：在"学业下降"和"用户流失"之间，填补"学习倦怠"这一中间态的识别与干预空白。

### 1.3 核心价值

1. **心理层面预警**：在学业成绩明显下滑之前，先捕获动力衰减信号
2. **量化可追踪**：将抽象的"学习兴趣"转化为可度量的 LMI 指数
3. **干预有据**：每个倦怠预警附带具体行为证据和个性化干预建议
4. **闭环设计**：预警 → 干预 → 效果追踪 → 模型优化，持续自学习

## 2. 核心概念与数据模型

### 2.1 学习动力指数（LMI）

LMI 是一个 0-100 的综合评分，由以下 6 个子维度加权计算：

| 子维度 | 代码 | 权重 | 数据来源 | 说明 |
|--------|------|------|---------|------|
| 主动发起率 | `initiative` | 0.20 | 学习会话统计 | 主动打开APP进入学习 vs 被推送/提醒触发 |
| 任务完成意愿 | `completion` | 0.20 | 任务系统 | 每日任务完成率、超时放弃率 |
| 互动深度 | `engagement` | 0.20 | AI对话分析 | 每次学习的平均交互轮数、追问频率 |
| 学习持续性 | `persistence` | 0.15 | 会话分析 | 单次学习时长趋势、中途退出率 |
| 情绪倾向 | `sentiment` | 0.15 | 文本/语音情绪分析 | AI对话中的正/负面情绪比例 |
| 自我挑战性 | `challenge` | 0.10 | 练习行为 | 是否主动尝试高难度题、是否使用拓展功能 |

**LMI 计算公式**：

```
LMI(t) = Σ(wi × si(t))

其中:
  wi = 子维度 i 的权重
  si(t) = 子维度 i 在时间窗口 t 的归一化得分 (0-1)
```

### 2.2 倦怠等级定义

| 等级 | LMI 范围 | 状态 | 颜色标识 | 干预策略 |
|------|----------|------|---------|---------|
| L0 充沛 | 80-100 | 🟢 绿色 | 学习动力旺盛 | 维持现有节奏，可适当增加挑战 |
| L1 轻微衰减 | 60-79 | 🟡 黄色 | 动力略有下降 | 轻量鼓励，推荐趣味内容 |
| L2 明显倦怠 | 40-59 | 🟠 橙色 | 动力显著不足 | 建议休息，调整学习计划，通知家长 |
| L3 严重倦怠 | 20-39 | 🔴 红色 | 几乎无学习意愿 | 家长介入，暂停学习任务，联系关怀 |
| L4 中断 | 0-19 | ⚫ 黑色 | 完全停止学习 | 深度挽留，转交运营/客服团队 |

## 3. 计算引擎设计

### 3.1 子维度评分算法

#### 3.1.1 主动发起率（initiative）

```python
def calc_initiative_score(metrics: DailyMetric, baseline: Baseline) -> float:
    """
    主动发起率得分
    - 如果当天没有会话，得分为 0
    - 与用户自身基线对比，而非全局对比
    """
    if metrics.total_sessions == 0:
        return 0.0
    
    # 主动发起比例
    self_init_ratio = metrics.self_initiated / metrics.total_sessions
    
    # 相对基线的变化
    baseline_ratio = baseline.avg_self_init_ratio  # 用户过去30天均值
    if baseline_ratio > 0:
        relative_change = self_init_ratio / baseline_ratio
    else:
        relative_change = 1.0
    
    # 综合评分: 绝对值(40%) + 相对变化(60%)
    abs_score = min(self_init_ratio * 100, 100)
    rel_score = min(relative_change * 70, 100)  # 相对基线略高于基线即可满分
    
    return 0.4 * abs_score + 0.6 * rel_score
```

#### 3.1.2 任务完成意愿（completion）

```python
def calc_completion_score(metrics: DailyMetric, baseline: Baseline) -> float:
    """
    任务完成意愿得分
    - 综合考虑: 完成率、放弃率、超时率
    """
    if metrics.tasks_assigned == 0:
        return 50.0  # 无任务时给中间分
    
    completion_rate = metrics.tasks_completed / metrics.tasks_assigned
    abandon_rate = metrics.tasks_abandoned / metrics.tasks_assigned
    timeout_rate = metrics.tasks_timeout / metrics.tasks_assigned
    
    # 完成率正向，放弃和超时负向
    score = (completion_rate * 60 
             + (1 - abandon_rate) * 25 
             + (1 - timeout_rate) * 15)
    
    return min(max(score, 0), 100)
```

#### 3.1.3 互动深度（engagement）

```python
def calc_engagement_score(metrics: DailyMetric, baseline: Baseline) -> float:
    """
    互动深度得分
    - 关注单次学习的交互质量，而非总量
    """
    if metrics.total_sessions == 0:
        return 0.0
    
    # 平均每会话对话轮数
    avg_rounds = metrics.avg_session_rounds
    
    # 追问频率 (追问次数 / 总对话轮数)
    followup_ratio = (metrics.followup_count / metrics.total_chat_rounds 
                      if metrics.total_chat_rounds > 0 else 0)
    
    # 与基线对比
    rounds_score = min(avg_rounds / max(baseline.avg_session_rounds, 3) * 50, 60)
    followup_score = min(followup_ratio * 200, 40)  # 追问比例占40%
    
    return min(rounds_score + followup_score, 100)
```

#### 3.1.4 学习持续性（persistence）

```python
def calc_persistence_score(metrics: DailyMetric, baseline: Baseline) -> float:
    """
    学习持续性得分
    - 侧重时间趋势而非单日绝对值
    """
    # 单次学习时长
    duration_score = min(metrics.avg_session_min / 15 * 40, 40)  # 15分钟为合理参考
    
    # 中途退出率（越低越好）
    exit_score = (1 - metrics.session_exit_rate) * 35
    
    # 日总时长
    total_score = min(metrics.total_study_min / 30 * 25, 25)  # 30分钟为合理参考
    
    return min(duration_score + exit_score + total_score, 100)
```

#### 3.1.5 情绪倾向（sentiment）

```python
def calc_sentiment_score(metrics: DailyMetric) -> float:
    """
    情绪倾向得分
    - 基于AI对话中的情绪分析结果
    """
    total = metrics.positive_count + metrics.negative_count + metrics.neutral_count
    if total == 0:
        return 50.0  # 无对话时给中间分
    
    positive_ratio = metrics.positive_count / total
    negative_ratio = metrics.negative_count / total
    
    # 正向加分，负向扣分
    score = 50 + (positive_ratio * 50) - (negative_ratio * 40)
    # 中性情绪不加分不扣分
    
    return min(max(score, 0), 100)
```

#### 3.1.6 自我挑战性（challenge）

```python
def calc_challenge_score(metrics: DailyMetric, baseline: Baseline) -> float:
    """
    自我挑战性得分
    - 是否主动选择更有难度的学习内容
    """
    # 高难度题尝试率
    total_attempts = metrics.tasks_assigned + metrics.hard_question_attempts
    if total_attempts == 0:
        return 50.0
    
    hard_ratio = metrics.hard_question_attempts / total_attempts
    
    # 拓展功能使用
    extend_score = min(metrics.extend_feature_uses / 3 * 30, 30)
    
    # 难度选择得分
    difficulty_score = min(hard_ratio * 100, 70)
    
    return min(difficulty_score + extend_score, 100)
```

### 3.2 LMI 综合计算

```python
# 子维度权重配置
LMI_WEIGHTS = {
    'initiative':  0.20,
    'completion':  0.20,
    'engagement':  0.20,
    'persistence': 0.15,
    'sentiment':   0.15,
    'challenge':   0.10,
}

def compute_lmi(scores: dict[str, float]) -> tuple[int, dict]:
    """
    计算LMI综合评分
    返回: (lmi_score, details)
    """
    weighted_sum = 0.0
    details = {}
    for dim, weight in LMI_WEIGHTS.items():
        s = scores.get(dim, 50.0)
        weighted_sum += weight * s
        details[dim] = round(s, 1)
    
    lmi = round(weighted_sum)
    lmi = max(0, min(100, lmi))  # 钳位到 [0, 100]
    
    return lmi, details


def compute_lmi_level(lmi: int) -> int:
    """LMI评分 → 倦怠等级"""
    if lmi >= 80: return 0  # L0 充沛
    if lmi >= 60: return 1  # L1 轻微衰减
    if lmi >= 40: return 2  # L2 明显倦怠
    if lmi >= 20: return 3  # L3 严重倦怠
    return 4                 # L4 中断
```

### 3.3 趋势计算

```python
def compute_lmi_delta(user_id: int, snapshot_date: date, window_days: int) -> int:
    """
    计算LMI在指定时间窗口内的变化值
    """
    historical = fetch_snapshots(user_id, snapshot_date - timedelta(days=window_days), snapshot_date)
    
    if len(historical) < 2:
        return 0
    
    # 使用线性回归斜率 * 天数作为变化值
    x = np.arange(len(historical))
    y = np.array([s.lmi_score for s in historical])
    
    if len(x) > 2:
        slope = np.polyfit(x, y, 1)[0]
        delta = int(slope * len(x))
    else:
        delta = y[-1] - y[0]
    
    return delta


def compute_consecutive_decline(user_id: int, snapshot_date: date) -> int:
    """
    计算LMI连续下降天数
    """
    snapshots = fetch_recent_snapshots(user_id, snapshot_date, limit=60)
    
    decline_days = 0
    for i in range(1, len(snapshots)):
        if snapshots[i].lmi_score < snapshots[i-1].lmi_score:
            decline_days += 1
        else:
            break
    
    return decline_days
```

### 4.1 预警规则定义

### 4.2 预警评估流程

```python
class BurnoutAlertEngine:
    
    def evaluate(self, user_id: int, snapshot: MotivationSnapshot) -> list[BurnoutAlert]:
        """
        对单个用户的最新快照评估所有规则
        """
        alerts = []
        context = self._build_context(user_id, snapshot)
        
        for rule in self.rules:
            # 检查冷却期
            if self._in_cooldown(user_id, rule.rule_id, rule.cooldown_hours):
                continue
            
            # 评估条件
            if self._evaluate_conditions(rule.conditions, context):
                alert = self._create_alert(user_id, rule, snapshot, context)
                alerts.append(alert)
        
        # 按优先级排序，只取最高优先级的一条（避免预警轰炸）
        if alerts:
            alerts.sort(key=lambda a: a.priority)
            return [alerts[0]]
        
        return alerts
    
    def _build_context(self, user_id: int, snapshot: MotivationSnapshot) -> dict:
        """构建规则评估上下文"""
        prev = self._get_prev_snapshot(user_id, snapshot.snapshot_date)
        baseline = self._get_user_baseline(user_id)
        
        context = {
            'lmi_score': snapshot.lmi_score,
            'lmi_level': snapshot.lmi_level,
            'prev_lmi_level': prev.lmi_level if prev else 0,
            'consecutive_decline_days': snapshot.consecutive_decline_days,
            'lmi_delta_7d': snapshot.lmi_delta_7d,
            'lmi_delta_30d': snapshot.lmi_delta_30d,
            'sentiment_score': snapshot.sentiment_score,
            'sentiment_score_delta_1d': (snapshot.sentiment_score - prev.sentiment_score) if prev else 0,
            'anomaly_dimensions_count': self._count_anomaly_dimensions(snapshot, baseline),
        }
        return context
    
    def _count_anomaly_dimensions(self, snapshot: MotivationSnapshot, baseline: Baseline) -> int:
        """统计偏离基线超过2个标准差的维度数量"""
        anomaly_count = 0
        dims = ['initiative', 'completion', 'engagement', 'persistence', 'sentiment', 'challenge']
        for dim in dims:
            score = getattr(snapshot, f'{dim}_score')
            base_mean = getattr(baseline, f'{dim}_mean')
            base_std = getattr(baseline, f'{dim}_std')
            if base_std > 0:
                z_score = abs(score - base_mean) / base_std
                if z_score > 2.0:  # 超过2个标准差
                    anomaly_count += 1
        return anomaly_count
```

```python
class InterventionStrategy:
    
    def select(self, user_id: int, alert: BurnoutAlert, user_profile: UserProfile) -> Intervention:
        """
        基于预警信息和用户画像选择干预策略
        """
        # 获取导致倦怠的主要因素
        top_factors = self._get_top_decline_factors(alert.evidence)
        
        strategies = []
        
        if alert.alert_level >= 3:
            # L3/L4: 优先通知家长
            strategies.append(Intervention(
                type='PARENT_NOTIFY',
                channel='PUSH',
                priority=1,
                template_id=f'burnout_parent_l{alert.alert_level}',
            ))
        
        if 'completion' in top_factors:
            # 任务完成意愿下降 → 调整计划
            strategies.append(Intervention(
                type='PLAN_ADJUST',
                channel='IN_APP',
                priority=2,
                template_id='burnout_plan_adjust',
                params={'reduce_ratio': 0.5},  # 任务量减半
            ))
        
        if 'persistence' in top_factors:
            # 持续性下降 → 建议休息
            strategies.append(Intervention(
                type='BREAK_SUGGEST',
                channel='IN_APP',
                priority=1,
                template_id='burnout_break_suggest',
                params={'suggest_days': 1},
            ))
        
        if 'engagement' in top_factors:
            # 互动深度下降 → 推荐趣味内容
            strategies.append(Intervention(
                type='FUN_CONTENT',
                channel='IN_APP',
                priority=2,
                template_id='burnout_fun_content',
                params={'subject': user_profile.preferred_subject},
            ))
        
        if 'sentiment' in top_factors:
            # 情绪低落 → 鼓励消息
            strategies.append(Intervention(
                type='ENCOURAGE',
                channel='IN_APP',
                priority=1,
                template_id='burnout_encourage',
            ))
        
        # 按优先级排序
        strategies.sort(key=lambda s: s.priority)
        return strategies[0] if strategies else None
```

### 6.2 LMI 快照计算任务（核心）

```python
class LMISnapshotJob:
    """
    每日LMI快照计算任务
    """
    
    def run(self, target_date: date):
        # 1. 获取当天有学习行为的活跃用户
        active_users = self.get_active_users(target_date)
        
        # 2. 分批处理（每批500用户）
        for batch in chunked(active_users, 500):
            self._process_batch(batch, target_date)
    
    def _process_batch(self, user_ids: list[int], target_date: date):
        # 批量获取指标数据
        metrics_map = self.batch_get_metrics(user_ids, target_date)
        
        # 批量获取用户基线
        baselines = self.batch_get_baselines(user_ids)
        
        snapshots = []
        for uid in user_ids:
            metrics = metrics_map.get(uid)
            if not metrics:
                continue
            
            baseline = baselines.get(uid, Baseline.default())
            
            # 计算子维度得分
            scores = {
                'initiative':  calc_initiative_score(metrics, baseline),
                'completion':  calc_completion_score(metrics, baseline),
                'engagement':  calc_engagement_score(metrics, baseline),
                'persistence': calc_persistence_score(metrics, baseline),
                'sentiment':   calc_sentiment_score(metrics),
                'challenge':   calc_challenge_score(metrics, baseline),
            }
            
            # 计算LMI
            lmi, details = compute_lmi(scores)
            level = compute_lmi_level(lmi)
            
            # 计算趋势
            delta_7d = compute_lmi_delta(uid, target_date, 7)
            delta_30d = compute_lmi_delta(uid, target_date, 30)
            decline_days = compute_consecutive_decline(uid, target_date)
            
            snapshots.append(MotivationSnapshot(
                user_id=uid,
                snapshot_date=target_date,
                lmi_score=lmi,
                lmi_level=level,
                initiative_score=round(scores['initiative']),
                completion_score=round(scores['completion']),
                engagement_score=round(scores['engagement']),
                persistence_score=round(scores['persistence']),
                sentiment_score=round(scores['sentiment']),
                challenge_score=round(scores['challenge']),
                lmi_delta_7d=delta_7d,
                lmi_delta_30d=delta_30d,
                consecutive_decline_days=decline_days,
            ))
        
        # 批量写入
        self.batch_upsert_snapshots(snapshots)
```

## 9. 错误处理

### 9.1 异常场景与处理策略

| 异常场景 | 处理策略 | 告警级别 |
|---------|---------|---------|
| 指标数据缺失（行为埋点未上报） | 使用前一天的指标值填充，标记 `data_quality=ESTIMATED` | WARN |
| 用户基线数据不足（新用户<7天） | 使用全局默认基线，LMI计算结果标记为 `preliminary=true` | INFO |
| 快照计算超时 | 跳过当前用户，记录到补偿队列，下次执行时补算 | WARN |
| 预警推送失败 | 重试3次（间隔5/15/60分钟），仍失败则降级为站内信 | ERROR |
| 数据库写入冲突 | 使用 `INSERT ON DUPLICATE KEY UPDATE` 保证幂等 | INFO |
| 批量处理部分失败 | 成功的写入，失败的进入死信队列人工审查 | ERROR |

### 9.2 数据质量保障

```python
def validate_snapshot(snapshot: MotivationSnapshot) -> ValidationResult:
    """快照数据质量校验"""
    issues = []
    
    # 检查LMI合理性
    if snapshot.lmi_score < 0 or snapshot.lmi_score > 100:
        issues.append(f"LMI out of range: {snapshot.lmi_score}")
    
    # 检查子维度与LMI的一致性
    recomputed_lmi, _ = compute_lmi({
        'initiative': snapshot.initiative_score,
        'completion': snapshot.completion_score,
        'engagement': snapshot.engagement_score,
        'persistence': snapshot.persistence_score,
        'sentiment': snapshot.sentiment_score,
        'challenge': snapshot.challenge_score,
    })
    if abs(recomputed_lmi - snapshot.lmi_score) > 2:
        issues.append(f"LMI inconsistency: stored={snapshot.lmi_score}, recomputed={recomputed_lmi}")
    
    # 检查趋势值的合理性
    if abs(snapshot.lmi_delta_7d) > 70:
        issues.append(f"7d delta seems too large: {snapshot.lmi_delta_7d}")
    
    return ValidationResult(valid=len(issues) == 0, issues=issues)
```

```yaml
      - name: practice.answer.events       # 答题事件
        handler: PracticeEventHandler      # 更新自我挑战性
```
