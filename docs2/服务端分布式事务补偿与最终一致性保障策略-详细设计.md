## 1. 设计背景与目标

### 1.1 问题定义

PrimeTop 采用模块化单体起步、逐步演进微服务的架构策略。在 MVP 阶段以单进程模块化为主，但以下场景已天然具备分布式特征：

| 场景 | 涉及模块 | 一致性要求 |
|------|----------|------------|
| 支付成功 → 激活会员 → 更新额度 → 发送通知 | 支付服务、用户服务、AI 服务、消息服务 | 最终一致，不可丢失 |
| AI 辅导完成 → 记录学习行为 → 更新学情画像 → 触发成就检查 | 学习服务、AI 服务、分析服务、激励服务 | 最终一致，允许短暂延迟 |
| 拍题识别 → 题目结构化 → AI 解析 → 错题收录 | OCR 服务、题目服务、AI 服务、错题服务 | 最终一致，需可追溯 |
| 内容审核 → AI 输出拦截 → 用户反馈记录 | 安全服务、AI 服务、反馈服务 | 强一致拦截，其余最终一致 |
| 批量导入题目 → 索引构建 → 向量化 → 搜索同步 | 内容服务、搜索服务、向量服务 | 最终一致，允许长时间处理 |

核心问题：**如何在不引入重量的分布式事务协调器的前提下，保障跨模块/跨服务的数据最终一致性？**

### 1.2 设计目标

1. **可靠性优先**: 关键业务链路零数据丢失，异常场景可自动恢复
2. **开发友好**: 提供统一框架和注解，开发者无需手动处理补偿逻辑
3. **可观测性**: 每个分布式事务的状态、进度、异常均可追踪
4. **渐进式演进**: MVP 阶段适用于模块化单体，后期可无缝扩展到微服务
5. **成本可控**: 不依赖外部协调器（如 Seata），基于本地事务 + 消息实现

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **本地事务优先** | 能用本地事务解决的绝不用分布式方案 |
| **显式补偿** | 每个业务操作必须定义对应的补偿操作 |
| **幂等保证** | 所有补偿操作和重试操作必须天然幂等 |
| **状态可查** | 每笔分布式事务有全局唯一 ID 和状态记录 |
| **超时兜底** | 所有操作设置合理超时，超时后走补偿路径 |
| **人工介入** | 提供管理后台接口，自动补偿失败时可人工干预 |

## 2. 核心概念与术语

### 2.1 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| 全局事务 | Global Transaction | 由一个业务操作触发的、涉及多个模块/服务的完整业务流程 |
| 分支事务 | Branch Transaction | 全局事务中的单个本地事务单元 |
| 事务编排 | Orchestration | 由一个协调者统一调度各分支事务的执行顺序 |
| 事务协同 | Choreography | 各模块通过事件驱动自主完成各自职责，无中心协调者 |
| 补偿操作 | Compensating Action | 对已完成的分支事务进行业务层面的逆向操作 |
| TCC | Try-Confirm-Cancel | 一种分布式事务模式：预留 → 确认 → 取消 |
| Saga 模式 | Saga Pattern | 将长事务拆分为一系列本地事务，每个事务有对应补偿 |
| 幂等键 | Idempotency Key | 保证同一操作多次执行结果一致的唯一标识 |
| 事务日志 | Transaction Log | 记录全局事务状态变更的持久化日志 |

### 2.2 一致性级别定义

```java
/**
 * 业务一致性级别枚举
 */
public enum ConsistencyLevel {
    /**
     * 强一致 - 操作必须立即对所有模块可见
     * 适用: 内容安全拦截、用户鉴权
     */
    STRONG,
    
    /**
     * 最终一致 - 允许短暂延迟，但最终必须一致
     * 适用: 学情数据同步、通知发送、额度更新
     */
    EVENTUAL,
    
    /**
     * 尽力一致 - 允许偶尔丢失，通过对账补偿
     * 适用: 学习行为日志、非关键统计数据
     */
    BEST_EFFORT
}
```

### 3.2 模式选择策略

不同业务场景选用不同的分布式事务模式：

| 模式 | 适用场景 | 实现复杂度 | 性能影响 |
|------|----------|------------|----------|
| **本地事务 + 事件** | 学情同步、通知触发 | 低 | 低 |
| **Saga (编排)** | 支付→会员→额度、拍题→解析→错题收录 | 中 | 中 |
| **TCC** | 额度预留与扣减、高并发抢购 | 高 | 中 |
| **可靠消息最终一致** | 学习行为记录、数据分析同步 | 低 | 低 |

**选择决策树**：

```
是否跨模块/服务？
├── 否 → 本地事务（@Transactional）
└── 是
    ├── 是否涉及资金/额度？
    │   └── 是 → TCC 模式
    │       └── 否 → Saga 编排模式
    └── 是否仅通知/日志类？
        └── 是 → 本地事务 + 可靠事件
            └── 否 → Saga 编排模式
```

## 4. Saga 编排模式实现

### 4.1 Saga 定义 DSL

采用编排式（Orchestration）Saga，由协调者统一控制流程。

```java
/**
 * Saga 定义构建器
 */
public class SagaDefinition {
    
    private final String sagaType;
    private final List<SagaStep> steps;
    private final Duration timeout;
    private final ConsistencyLevel level;
    
    public static SagaDefinition.Builder builder(String sagaType) {
        return new Builder(sagaType);
    }
    
    @Data
    public static class SagaStep {
        /** 步骤名称 */
        private String name;
        /** 正向操作 Bean 名称 */
        private String actionBean;
        /** 补偿操作 Bean 名称 */
        private String compensateBean;
        /** 步骤超时 */
        private Duration timeout;
        /** 最大重试次数 */
        private int maxRetries;
        /** 重试间隔策略 */
        private RetryPolicy retryPolicy;
    }
    
    public static class Builder {
        // ...
        public Builder step(String name, String actionBean, String compensateBean) {
            steps.add(new SagaStep(name, actionBean, compensateBean));
            return this;
        }
        
        public Builder timeout(Duration timeout) {
            this.timeout = timeout;
            return this;
        }
        
        public SagaDefinition build() {
            return new SagaDefinition(sagaType, steps, timeout, level);
        }
    }
}
```

### 4.5 核心 Saga 编排器实现

```java
/**
 * Saga 编排器 - 核心引擎
 */
@Component
@Slf4j
public class SagaOrchestrator {
    
    @Autowired
    private DistributedTxRepository txRepository;
    @Autowired
    private DistributedTxStepRepository stepRepository;
    @Autowired
    private CompensationActionRepository compensationRepository;
    @Autowired
    private SagaDefinitionRegistry definitionRegistry;
    @Autowired
    private SagaActionRegistry actionRegistry;
    @Autowired
    private ApplicationEventPublisher eventPublisher;
    
    private final ObjectMapper objectMapper = new ObjectMapper();
    
    /**
     * 启动一个 Saga 事务
     *
     * @param sagaType Saga 类型
     * @param context  业务上下文
     * @return 全局事务ID
     */
    @Transactional
    public String startSaga(String sagaType, Map<String, Object> context) {
        SagaDefinition definition = definitionRegistry.get(sagaType);
        if (definition == null) {
            throw new IllegalArgumentException("Unknown saga type: " + sagaType);
        }
        
        String globalTxId = generateGlobalTxId();
        LocalDateTime now = LocalDateTime.now();
        
        // 1. 创建全局事务记录
        DistributedTx tx = new DistributedTx();
        tx.setGlobalTxId(globalTxId);
        tx.setSagaType(sagaType);
        tx.setStatus("CREATED");
        tx.setContext(objectMapper.writeValueAsString(context));
        tx.setCurrentStep(0);
        tx.setTotalSteps(definition.getSteps().size());
        tx.setTimeoutAt(now.plus(definition.getTimeout()));
        txRepository.insert(tx);
        
        // 2. 创建所有步骤记录
        List<DistributedTxStep> steps = new ArrayList<>();
        for (int i = 0; i < definition.getSteps().size(); i++) {
            SagaStep stepDef = definition.getSteps().get(i);
            DistributedTxStep step = new DistributedTxStep();
            step.setGlobalTxId(globalTxId);
            step.setStepIndex(i);
            step.setStepName(stepDef.getName());
            step.setStatus("PENDING");
            step.setActionBean(stepDef.getActionBean());
            step.setCompensateBean(stepDef.getCompensateBean());
            steps.add(step);
        }
        stepRepository.batchInsert(steps);
        
        // 3. 异步触发执行
        tx.setStatus("RUNNING");
        txRepository.updateStatus(globalTxId, "RUNNING");
        
        eventPublisher.publishEvent(new SagaStartedEvent(globalTxId, sagaType));
        
        // 4. 同步执行第一步（减少延迟）
        executeNextStep(globalTxId);
        
        return globalTxId;
    }
    
    /**
     * 执行下一个步骤
     */
    public void executeNextStep(String globalTxId) {
        DistributedTx tx = txRepository.findByGlobalTxId(globalTxId);
        if (tx == null || !"RUNNING".equals(tx.getStatus())) {
            log.warn("Transaction {} is not in RUNNING state: {}", globalTxId, 
                     tx != null ? tx.getStatus() : "NOT_FOUND");
            return;
        }
        
        // 检查超时
        if (LocalDateTime.now().isAfter(tx.getTimeoutAt())) {
            log.error("Transaction {} timed out", globalTxId);
            triggerCompensation(globalTxId, "TIMEOUT");
            return;
        }
        
        int currentStep = tx.getCurrentStep();
        if (currentStep >= tx.getTotalSteps()) {
            // 所有步骤完成
            txRepository.updateStatus(globalTxId, "COMMITTED");
            eventPublisher.publishEvent(new SagaCommittedEvent(globalTxId, tx.getSagaType()));
            log.info("Transaction {} committed successfully", globalTxId);
            return;
        }
        
        DistributedTxStep step = stepRepository.findByTxAndIndex(globalTxId, currentStep);
        SagaDefinition definition = definitionRegistry.get(tx.getSagaType());
        SagaStep stepDef = definition.getSteps().get(currentStep);
        
        try {
            // 执行正向操作
            step.setStatus("EXECUTING");
            stepRepository.updateStatus(globalTxId, currentStep, "EXECUTING");
            
            SagaAction action = actionRegistry.getAction(stepDef.getActionBean());
            Map<String, Object> context = deserializeContext(tx.getContext());
            
            SagaActionInput input = new SagaActionInput(globalTxId, currentStep, context);
            SagaActionOutput output = action.execute(input);
            
            // 记录输出，用于后续可能的补偿
            step.setOutputData(objectMapper.writeValueAsString(output.getData()));
            step.setStatus("SUCCESS");
            stepRepository.updateOutputAndStatus(globalTxId, currentStep, 
                                                  step.getOutputData(), "SUCCESS");
            
            // 推进到下一步
            txRepository.updateCurrentStep(globalTxId, currentStep + 1);
            
            // 继续执行下一步
            executeNextStep(globalTxId);
            
        } catch (Exception e) {
            log.error("Step {} of transaction {} failed: {}", currentStep, globalTxId, e.getMessage(), e);
            step.setErrorMessage(truncate(e.getMessage(), 2000));
            stepRepository.updateErrorAndStatus(globalTxId, currentStep, step.getErrorMessage(), "FAILED");
            
            // 触发补偿
            triggerCompensation(globalTxId, "STEP_FAILED:" + currentStep);
        }
    }
    
    /**
     * 触发补偿流程 - 按反向顺序补偿已成功的步骤
     */
    @Transactional
    public void triggerCompensation(String globalTxId, String reason) {
        DistributedTx tx = txRepository.findByGlobalTxId(globalTxId);
        txRepository.updateStatus(globalTxId, "COMPENSATING");
        
        // 查找所有已成功的步骤，按逆序创建补偿任务
        List<DistributedTxStep> successSteps = stepRepository
            .findSuccessStepsReverse(globalTxId);
        
        for (DistributedTxStep step : successSteps) {
            if ("noopCompensate".equals(step.getCompensateBean())) {
                continue; // 跳过无需补偿的步骤
            }
            
            CompensationAction compensation = new CompensationAction();
            compensation.setGlobalTxId(globalTxId);
            compensation.setStepIndex(step.getStepIndex());
            compensation.setCompensateBean(step.getCompensateBean());
            compensation.setCompensateInput(step.getOutputData());
            compensation.setStatus("PENDING");
            compensation.setNextRetryAt(LocalDateTime.now());
            compensationRepository.insert(compensation);
        }
        
        // 异步执行补偿
        eventPublisher.publishEvent(new SagaCompensationTriggeredEvent(globalTxId, reason));
        
        // 开始执行补偿
        executeCompensation(globalTxId);
    }
    
    /**
     * 执行补偿操作
     */
    public void executeCompensation(String globalTxId) {
        List<CompensationAction> pendingActions = compensationRepository
            .findPendingByGlobalTxId(globalTxId);
        
        boolean allSuccess = true;
        
        for (CompensationAction action : pendingActions) {
            try {
                SagaAction compensateAction = actionRegistry.getAction(action.getCompensateBean());
                Map<String, Object> input = objectMapper.readValue(
                    action.getCompensateInput(), new TypeReference<Map<String, Object>>() {});
                
                compensateAction.execute(new SagaActionInput(globalTxId, action.getStepIndex(), input));
                
                action.setStatus("SUCCESS");
                compensationRepository.updateStatus(action.getId(), "SUCCESS");
                
            } catch (Exception e) {
                allSuccess = false;
                log.error("Compensation for tx {} step {} failed: {}", 
                         globalTxId, action.getStepIndex(), e.getMessage());
                action.setStatus("FAILED");
                action.setErrorMessage(truncate(e.getMessage(), 2000));
                action.setRetryCount(action.getRetryCount() + 1);
                
                if (action.getRetryCount() >= action.getMaxRetry()) {
                    // 超过最大重试次数，标记需要人工介入
                    log.error("Compensation exhausted for tx {} step {}, requires manual intervention",
                             globalTxId, action.getStepIndex());
                } else {
                    // 指数退避重试
                    LocalDateTime nextRetry = LocalDateTime.now()
                        .plusSeconds((long) Math.pow(2, action.getRetryCount()));
                    action.setNextRetryAt(nextRetry);
                    action.setStatus("PENDING"); // 重置为待重试
                }
                compensationRepository.updateRetryInfo(action);
            }
        }
        
        // 检查是否全部补偿完成
        if (allSuccess && pendingActions.isEmpty()) {
            // 没有需要补偿的步骤（全是 noop）
            txRepository.updateStatus(globalTxId, "COMPENSATED");
        } else if (allSuccess) {
            txRepository.updateStatus(globalTxId, "COMPENSATED");
            eventPublisher.publishEvent(new SagaCompensatedEvent(globalTxId));
        } else {
            // 有补偿失败，等待补偿调度器重试
            log.warn("Some compensations failed for tx {}, waiting for scheduler", globalTxId);
        }
    }
    
    private String generateGlobalTxId() {
        return "TX-" + UUID.randomUUID().toString().replace("-", "").substring(0, 24)
               + "-" + System.currentTimeMillis() % 100000;
    }
}
```

## 5. TCC 模式实现（额度扣减场景）

### 5.1 适用场景

用户使用 AI 辅导、拍题等功能时需要扣减额度。在高并发场景下，采用 TCC 模式：
- **Try**: 冻结额度（预扣减）
- **Confirm**: 确认扣减（将冻结额度转为已消费）
- **Cancel**: 释放冻结额度

### 5.2 数据结构

```sql
-- 用户额度表
CREATE TABLE user_quota (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT       NOT NULL COMMENT '用户ID',
    quota_type      VARCHAR(32)  NOT NULL COMMENT '额度类型: AI_CHAT|PHOTO_SOLVE|VOICE_ASK',
    total_quota     INT          NOT NULL DEFAULT 0 COMMENT '总额度',
    used_quota      INT          NOT NULL DEFAULT 0 COMMENT '已使用额度',
    frozen_quota    INT          NOT NULL DEFAULT 0 COMMENT '冻结额度(TRY阶段)',

-- 额度冻结记录表
```

### 5.3 TCC 实现

```java
/**
 * 额度 TCC 服务
 */
@Service
@Slf4j
public class QuotaTccService {
    
    @Autowired
    private UserQuotaRepository quotaRepository;
    @Autowired
    private QuotaFreezeRecordRepository freezeRepository;
    
    /**
     * Try 阶段 - 冻结额度
     * 使用乐观锁 + 数据库行锁保证并发安全
     */
    @Transactional(rollbackFor = Exception.class)
    public QuotaFreezeResult tryFreeze(String globalTxId, Long userId, 
                                        String quotaType, int amount) {
        // 幂等检查
        QuotaFreezeRecord existing = freezeRepository.findByGlobalTxId(globalTxId);
        if (existing != null) {
            if ("FROZEN".equals(existing.getStatus())) {
                return QuotaFreezeResult.success(existing.getId());
            }
            throw new BusinessException(ErrorCode.QUOTA_FREEZE_CONFLICT, 
                "Freeze record already exists with status: " + existing.getStatus());
        }
        
        // 冻结额度 (SELECT FOR UPDATE 行锁)
        UserQuota quota = quotaRepository.findByUserAndTypeForUpdate(userId, quotaType);
        int available = quota.getTotalQuota() - quota.getUsedQuota() - quota.getFrozenQuota();
        if (available < amount) {
            throw new BusinessException(ErrorCode.QUOTA_INSUFFICIENT, 
                "Insufficient quota. Available: " + available + ", Required: " + amount);
        }
        
        // 增加冻结额度
        quota.setFrozenQuota(quota.getFrozenQuota() + amount);
        quotaRepository.update(quota);
        
        // 创建冻结记录
        QuotaFreezeRecord record = new QuotaFreezeRecord();
        record.setGlobalTxId(globalTxId);
        record.setUserId(userId);
        record.setQuotaType(quotaType);
        record.setFreezeAmount(amount);
        record.setStatus("FROZEN");
        record.setExpiredAt(LocalDateTime.now().plusMinutes(10)); // 10分钟冻结超时
        freezeRepository.insert(record);
        
        return QuotaFreezeResult.success(record.getId());
    }
    
    /**
     * Confirm 阶段 - 确认扣减
     */
    @Transactional(rollbackFor = Exception.class)
    public void confirmFreeze(String globalTxId) {
        QuotaFreezeRecord record = freezeRepository.findByGlobalTxId(globalTxId);
        if (record == null) {
            throw new BusinessException(ErrorCode.QUOTA_FREEZE_NOT_FOUND);
        }
        
        // 幂等: 已确认直接返回
        if ("CONFIRMED".equals(record.getStatus())) {
            return;
        }
        
        if (!"FROZEN".equals(record.getStatus())) {
            throw new BusinessException(ErrorCode.QUOTA_FREEZE_STATUS_INVALID,
                "Expected FROZEN but got: " + record.getStatus());
        }
        
        // 将冻结额度转为已使用
        UserQuota quota = quotaRepository.findByUserAndTypeForUpdate(
            record.getUserId(), record.getQuotaType());
        quota.setFrozenQuota(quota.getFrozenQuota() - record.getFreezeAmount());
        quota.setUsedQuota(quota.getUsedQuota() + record.getFreezeAmount());
        quotaRepository.update(quota);
        
        // 更新冻结记录状态
        record.setStatus("CONFIRMED");
        freezeRepository.updateStatus(record.getId(), "CONFIRMED");
    }
    
    /**
     * Cancel 阶段 - 释放冻结
     */
    @Transactional(rollbackFor = Exception.class)
    public void cancelFreeze(String globalTxId) {
        QuotaFreezeRecord record = freezeRepository.findByGlobalTxId(globalTxId);
        if (record == null) {
            return; // 幂等
        }
        
        // 幂等: 已取消直接返回
        if ("CANCELLED".equals(record.getStatus()) || "CONFIRMED".equals(record.getStatus())) {
            return;
        }
        
        // 释放冻结额度
        UserQuota quota = quotaRepository.findByUserAndTypeForUpdate(
            record.getUserId(), record.getQuotaType());
        quota.setFrozenQuota(quota.getFrozenQuota() - record.getFreezeAmount());
        quotaRepository.update(quota);
        
        record.setStatus("CANCELLED");
        freezeRepository.updateStatus(record.getId(), "CANCELLED");
    }
}
```

### 6.4 Outbox 事件扫描与投递

```java
/**
 * Outbox 事件扫描器 - 定时扫描并发送待投递事件
 * 间隔: 1 秒
 */
@Component
@Slf4j
public class EventOutboxScanner {
    
    @Autowired
    private EventOutboxRepository outboxRepository;
    @Autowired
    private ApplicationEventPublisher eventPublisher;
    
    @Scheduled(fixedDelay = 1000)
    public void scanAndPublish() {
        List<EventOutbox> pendingEvents = outboxRepository.findPendingBatch(50);
        
        for (EventOutbox event : pendingEvents) {
            try {
                // 发布到 Spring 事件总线（MVP阶段）
                // 后期可替换为 Kafka/RabbitMQ
                eventPublisher.publishEvent(new OutboxEvent(
                    event.getEventId(),
                    event.getAggregateType(),
                    event.getAggregateId(),
                    event.getEventType(),
                    event.getPayload()
                ));
                
                // 标记已发送
                outboxRepository.updatePublished(event.getId(), LocalDateTime.now());
                
            } catch (Exception e) {
                log.error("Failed to publish outbox event {}: {}", event.getEventId(), e.getMessage());
                // 更新重试信息
                int newRetryCount = event.getRetryCount() + 1;
                if (newRetryCount >= event.getMaxRetry()) {
                    outboxRepository.updateFailed(event.getId(), "MAX_RETRY_EXCEEDED");
                    // 发送告警
                    log.error("Outbox event {} exceeded max retries", event.getEventId());
                } else {
                    LocalDateTime nextRetry = LocalDateTime.now()
                        .plusSeconds((long) Math.pow(2, newRetryCount));
                    outboxRepository.updateRetry(event.getId(), newRetryCount, nextRetry);
                }
            }
        }
    }
}
```

## 8. 补偿调度器与异常恢复

### 8.1 定时补偿调度

```java
/**
 * 补偿调度器 - 定时扫描失败的全局事务和补偿任务
 */
@Component
@Slf4j
public class CompensationScheduler {
    
    @Autowired
    private DistributedTxRepository txRepository;
    @Autowired
    private CompensationActionRepository compensationRepository;
    @Autowired
    private SagaOrchestrator sagaOrchestrator;
    
    /**
     * 扫描超时的全局事务
     * 执行频率: 每 30 秒
     */
    @Scheduled(fixedDelay = 30000)
    public void scanTimeoutTransactions() {
        List<DistributedTx> timeoutTxs = txRepository.findRunningAndTimeout(LocalDateTime.now());
        
        for (DistributedTx tx : timeoutTxs) {
            try {
                log.warn("Transaction {} timed out, triggering compensation", tx.getGlobalTxId());
                sagaOrchestrator.triggerCompensation(tx.getGlobalTxId(), "TIMEOUT_SCAN");
            } catch (Exception e) {
                log.error("Failed to compensate timeout transaction {}: {}", 
                         tx.getGlobalTxId(), e.getMessage());
            }
        }
    }
    
    /**
     * 重试失败的补偿操作
     * 执行频率: 每 10 秒
     */
    @Scheduled(fixedDelay = 10000)
    public void retryFailedCompensations() {
        List<CompensationAction> retryableActions = compensationRepository
            .findRetryable(LocalDateTime.now());
        
        for (CompensationAction action : retryableActions) {
            try {
                sagaOrchestrator.executeCompensation(action.getGlobalTxId());
            } catch (Exception e) {
                log.error("Retry compensation failed for tx {} step {}: {}",
                         action.getGlobalTxId(), action.getStepIndex(), e.getMessage());
            }
        }
    }
    
    /**
     * 清理已完成的事务记录
     * 执行频率: 每天凌晨 3 点
     * 保留最近 30 天的记录
     */
    @Scheduled(cron = "0 0 3 * * ?")
    public void cleanupCompletedTransactions() {
        LocalDateTime threshold = LocalDateTime.now().minusDays(30);
        int deleted = txRepository.deleteCompletedBefore(threshold);
        log.info("Cleaned up {} completed transactions before {}", deleted, threshold);
    }
}
```

### 8.2 冻结额度超时自动释放

```java
/**
 * 冻结额度超时释放扫描
 * 防止 Try 成功但 Confirm/Cancel 未调用的悬挂事务
 * 执行频率: 每 60 秒
 */
@Component
@Slf4j
public class QuotaFreezeTimeoutScanner {
    
    @Autowired
    private QuotaFreezeRecordRepository freezeRepository;
    @Autowired
    private QuotaTccService quotaTccService;
    
    @Scheduled(fixedDelay = 60000)
    public void scanExpiredFreezes() {
        List<QuotaFreezeRecord> expiredRecords = freezeRepository
            .findByStatusAndExpiredAtBefore("FROZEN", LocalDateTime.now());
        
        for (QuotaFreezeRecord record : expiredRecords) {
            try {
                log.warn("Auto-cancelling expired freeze for tx {}", record.getGlobalTxId());
                quotaTccService.cancelFreeze(record.getGlobalTxId());
            } catch (Exception e) {
                log.error("Failed to auto-cancel freeze {}: {}", 
                         record.getGlobalTxId(), e.getMessage());
            }
        }
    }
```

## 9. 幂等性保障

### 9.1 幂等性设计原则

所有 Saga 操作和补偿操作必须天然幂等。实现方式：

| 方式 | 适用场景 | 实现方式 |
|------|----------|----------|
| **唯一键去重** | 数据库插入操作 | 利用 global_tx_id + step_index 唯一约束 |
| **状态前置检查** | 状态变更操作 | 执行前检查当前状态，已变更则直接返回 |
| **幂等键表** | 外部API调用 | 调用前在 idempotent_key 表插入记录 |
| **天然幂等** | 绝对值设置、绝对值更新 | `SET quota = X` 而非 `SET quota = quota + X` |

### 9.2 幂等键管理

```sql
CREATE TABLE idempotent_key (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    key_value       VARCHAR(128) NOT NULL COMMENT '幂等键 (globalTxId + action + 目标标识)',
    status          VARCHAR(20)  NOT NULL COMMENT 'PROCESSING|COMPLETED|FAILED',
    result          JSON         COMMENT '执行结果',
    created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    expired_at      DATETIME     NOT NULL COMMENT '过期时间',
    
    UNIQUE KEY uk_key_value (key_value),
    KEY idx_expired (expired_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='幂等键表';
```

```java
/**
 * 幂等键服务
 */
@Service
public class IdempotentKeyService {
    
    @Autowired
    private IdempotentKeyRepository keyRepository;
    
    /**
     * 尝试获取执行权
     * @return true=首次执行, false=已执行过
     */
    @Transactional(rollbackFor = Exception.class)
    public IdempotentResult tryAcquire(String key, Duration ttl) {
        IdempotentKey existing = keyRepository.findByKeyValue(key);
        
        if (existing != null) {
            if ("COMPLETED".equals(existing.getStatus())) {
                return IdempotentResult.alreadyCompleted(existing.getResult());
            }
            if ("PROCESSING".equals(existing.getStatus())) {
                return IdempotentResult.processing();
            }
            // FAILED 状态允许重试
        }
        
        // 创建或更新为处理中
        IdempotentKey record = new IdempotentKey();
        record.setKeyValue(key);
        record.setStatus("PROCESSING");
        record.setExpiredAt(LocalDateTime.now().plus(ttl));
        
        try {
            keyRepository.insert(record);
            return IdempotentResult.firstExecution();
        } catch (DuplicateKeyException e) {
            // 并发插入冲突，说明其他线程已在处理
            return IdempotentResult.processing();
        }
    }
    
    public void markCompleted(String key, String result) {
        keyRepository.updateStatusAndResult(key, "COMPLETED", result);
    }
    
    public void markFailed(String key) {
        keyRepository.updateStatus(key, "FAILED");
    }
}
```

## 12. 错误处理与异常分类

### 12.1 异常分类

```java
/**
 * 分布式事务异常分类
 */
public enum TxFaultType {
    /** 业务校验失败 - 不需要重试 */
    BUSINESS_RULE_VIOLATION,
    /** 下游服务超时 - 可重试 */
    DOWNSTREAM_TIMEOUT,
    /** 下游服务不可用 - 可重试（退避） */
    DOWNSTREAM_UNAVAILABLE,
    /** 数据冲突 - 需要重新计算后重试 */
    DATA_CONFLICT,
    /** 网络瞬断 - 可快速重试 */
    TRANSIENT_NETWORK,
    /** 未知错误 - 需人工介入 */
    UNKNOWN
}

/**
 * 根据异常类型判断是否可重试
 */
public class FaultClassifier {
    
    public static TxFaultType classify(Exception e) {
        if (e instanceof BusinessException) {
            return TxFaultType.BUSINESS_RULE_VIOLATION;
        }
        if (e instanceof SocketTimeoutException || e instanceof TimeoutException) {
            return TxFaultType.DOWNSTREAM_TIMEOUT;
        }
        if (e instanceof ConnectException || e instanceof ServiceUnavailableException) {
            return TxFaultType.DOWNSTREAM_UNAVAILABLE;
        }
        if (e instanceof DataIntegrityViolationException || 
            e instanceof OptimisticLockingFailureException) {
            return TxFaultType.DATA_CONFLICT;
        }
        if (e instanceof IOException) {
            return TxFaultType.TRANSIENT_NETWORK;
        }
        return TxFaultType.UNKNOWN;
    }
    
    public static boolean isRetryable(TxFaultType type) {
        return type != TxFaultType.BUSINESS_RULE_VIOLATION 
            && type != TxFaultType.UNKNOWN;
    }
}
```

## 13. 性能考量

### 13.1 性能指标要求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| Saga 事务启动延迟 | < 10ms | 仅写入数据库 |
| 单步骤执行延迟 | < 500ms | 不含 AI 调用 |
| 补偿触发延迟 | < 5s | 从失败到开始补偿 |
| Outbox 事件投递延迟 | < 2s | 从写入到消费 |
| 全局事务完成耗时 | < 30s | 不含 AI 调用等待 |
| 数据库连接占用 | < 3 per tx | 避免长事务占用连接 |

### 13.2 优化策略

1. **步骤并行化**: 无依赖的步骤可并行执行（如通知和审计）
2. **异步步骤**: IO 密集步骤使用异步线程池
3. **Outbox 批量扫描**: 每次扫描一批而非逐条
4. **补偿合并**: 同一全局事务的多个补偿可批量执行
5. **事务日志归档**: 超过保留期的记录归档到冷存储
