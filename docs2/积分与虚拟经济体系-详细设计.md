# 积分与虚拟经济体系 - 详细设计

## 1. 模块概述

### 1.1 功能定位

积分与虚拟经济体系是 PrimeTop 的核心激励层，通过学习行为获得虚拟货币（学币）和成长值（经验值），驱动等级提升、道具兑换和荣誉展示，将学习行为与正向反馈紧密绑定，形成可持续的学习动力引擎。

### 1.2 设计目标

1. **行为驱动**：通过积分奖励引导用户完成学习任务、坚持每日打卡、主动纠错
2. **适度激励**：避免过度游戏化导致学习分心，积分获取以学习行为为主
3. **防刷防作弊**：设置合理上限和风控策略，防止恶意刷分
4. **经济平衡**：控制积分产出与消耗，避免通胀或通缩
5. **家长可控**：家长可查看和限制子女的积分使用
6. **数据可审计**：所有积分变动留痕，支持对账和纠纷处理

### 1.3 适用学段

| 学段 | 积分参与度 | 主要激励方式 |
|------|-----------|-------------|
| 幼儿 | 全自动，家长代管 | 星星收集、勋章动画、趣味解锁 |
| 小学 | 核心参与者 | 等级提升、道具兑换、排行榜 |
| 初中 | 核心参与者 | 积分兑换增值服务、学习报告解锁 |
| 高中 | 辅助激励 | 专题内容解锁、限时特权兑换 |

## 2. 虚拟货币体系设计

### 2.1 货币类型

系统内设三种虚拟价值载体，各有独立用途和获取渠道：

| 货币类型 | 代号 | 用途 | 是否可充值 | 是否有过期 |
|---------|------|------|-----------|-----------|
| **学币** | `COIN` | 兑换增值服务、功能道具、虚拟商品 | 否（仅学习获取） | 12个月未使用过期 |
| **经验值** | `EXP` | 等级提升的唯一指标 | 否 | 永不过期 |
| **星光** | `STAR` | 幼儿启蒙专属，解锁趣味内容 | 否 | 永不过期 |

### 2.2 学币（COIN）获取规则

学币是核心可消耗货币，获取与学习行为强绑定：

| 行为编码 | 行为描述 | 奖励学币 | 每日上限 | 条件约束 |
|---------|---------|---------|---------|---------|
| `DAILY_LOGIN` | 每日登录 | 5 | 5 | 首次打开APP当天 |
| `DAILY_CHECKIN` | 每日打卡签到 | 10 | 10 | 连续签到第N天额外 +N（最多+7） |
| `AI_QUESTION` | AI问答（有效提问） | 2 | 20 | 提问后停留≥10秒视为有效 |
| `PHOTO_SOLVE` | 拍照搜题 | 3 | 15 | 查看完整解析视为有效 |
| `EXERCISE_CORRECT` | 练习答题正确 | 5 | 50 | 单次练习中每题计一次 |
| `EXERCISE_SET` | 完成一套练习 | 20 | 60 | 完成率≥80% |
| `MISTAKE_REVIEW` | 错题复习 | 3 | 30 | 完成订正且答对 |
| `STUDY_DURATION` | 学习时长达标 | 10 | 30 | 单次连续学习≥20分钟 |
| `PLAN_COMPLETE` | 完成每日计划 | 30 | 30 | 当日所有学习任务完成 |
| `ESSAY_SUBMIT` | 提交作文辅导 | 15 | 15 | 提交≥200字的作文 |
| `RECITE_PASS` | 背诵检测通过 | 10 | 30 | 准确率≥80% |
| `SHARE_ACHIEVEMENT` | 分享学习成就 | 5 | 5 | 分享至社交平台 |
| `INVITE_SUCCESS` | 邀请好友注册 | 50 | 无上限 | 被邀请人完成首次学习 |
| `WEEKLY_GOAL` | 周目标达成 | 100 | 100 | 本周学习计划完成率≥90% |

**学币获取总上限**：普通用户每日最多获取 200 学币，会员用户 300 学币。

### 2.3 经验值（EXP）获取规则

经验值不可消耗，仅用于等级提升：

| 行为 | 奖励EXP | 说明 |
|------|---------|------|
| 与学币获取行为相同 | 学币奖励 × 2 | 每次获得学币时同步获得双倍经验值 |
| 完成章节学习 | 50 | 首次完成某章节的所有内容 |
| 首次连续7天学习 | 200 | 一次性奖励 |
| 首次连续30天学习 | 1000 | 一次性奖励 |
| 突破知识薄弱点 | 100 | 系统检测到某知识点从弱变强 |

### 2.4 星光（STAR）获取规则（幼儿专属）

| 行为 | 奖励星光 | 每日上限 |
|------|---------|---------|
| 完成拼音练习 | 3 | 15 |
| 完成识字卡片 | 3 | 15 |
| 完成发音练习 | 2 | 10 |
| 听完故事 | 5 | 20 |

## 3. 等级体系设计

### 3.1 等级定义

等级反映用户的累计学习投入，分为10个大级，每个大级含3个小级，共30级：

| 大级 | 小级范围 | 称号 | 所需累计EXP | 解锁权益 |
|------|---------|------|------------|---------|
| 1 | 1-3 | 启蒙星 | 0 - 300 | 基础功能 |
| 2 | 4-6 | 学习芽 | 300 - 1,500 | 自定义头像框 |
| 3 | 7-9 | 知识苗 | 1,500 - 5,000 | 学习报告基础版 |
| 4 | 10-12 | 探索者 | 5,000 - 12,000 | 错题导出功能 |
| 5 | 13-15 | 智慧树 | 12,000 - 25,000 | 专属学习壁纸 |
| 6 | 16-18 | 学霸星 | 25,000 - 50,000 | 每日额外学币奖励 |
| 7 | 19-21 | 博学达人 | 50,000 - 100,000 | 高级学情报告 |
| 8 | 22-24 | 知识大师 | 100,000 - 200,000 | 限时道具优惠 |
| 9 | 25-27 | 学神之路 | 200,000 - 500,000 | 专属称号展示 |
| 10 | 28-30 | 至尊学者 | 500,000+ | 全部权益 + 专属客服 |

### 3.2 升级经验表

每个小级所需经验公式：

```
小级 n 所需累计经验 = floor(50 × 1.35^(n-1))  （n 从1开始）
```

前10级经验明细：

| 小级 | 累计EXP | 本级所需EXP |
|------|---------|------------|
| 1 | 0 | 50 |
| 2 | 50 | 68 |
| 3 | 118 | 91 |
| 4 | 209 | 123 |
| 5 | 332 | 166 |
| 6 | 498 | 225 |
| 7 | 723 | 303 |
| 8 | 1,026 | 409 |
| 9 | 1,435 | 553 |
| 10 | 1,988 | 746 |

### 3.3 升级通知与动画

- 升级时弹出全屏庆祝动画（2秒），展示新等级和称号
- 幼儿学段：星星爆炸动画 + 欢快音效
- 小学学段：角色进化动画
- 初中/高中学段：简洁进度条 + 成就解锁提示
- 升级消息同步推送到家长端

## 4. 消耗与兑换体系

### 4.1 学币消耗场景

| 商品类型 | 商品示例 | 消耗学币 | 说明 |
|---------|---------|---------|------|
| 功能道具 | 双倍经验卡（1天） | 100 | 激活后24h内获取EXP翻倍 |
| 功能道具 | 错题导出券 | 50 | 可导出PDF错题集 |
| 功能道具 | AI深度解析券 | 30 | 获取更详细的解题步骤 |
| 功能道具 | 作文润色券 | 40 | AI对作文提供逐句润色建议 |
| 虚拟装扮 | 头像框 | 80-200 | 永久解锁 |
| 虚拟装扮 | 聊天背景 | 60-150 | 永久解锁 |
| 虚拟装扮 | 称号装饰 | 100-300 | 永久解锁 |
| 内容解锁 | 专题练习包 | 150-300 | 限时访问7天 |
| 内容解锁 | 名师讲解视频 | 200 | 限时访问7天 |
| 公益捐赠 | 捐赠学习包 | 500 | 向公益项目捐赠（附捐赠证书） |

### 4.2 兑换流程

```
用户选择商品 → 展示商品详情和学币价格
       ↓
检查学币余额是否充足
       ↓ (充足)
检查是否为未成年人操作 → 是 → 检查家长是否开启消费限制
       ↓                           ↓ (已限制)
确认兑换                    提示"需要家长授权"
       ↓
扣除学币 → 发放商品/权益 → 记录交易流水
       ↓
展示兑换成功页 → 展示余额和新权益
```

### 4.3 学币过期策略

- 学币自获得之日起 **12个月** 后过期
- 采用 **FIFO（先进先出）** 原则：优先消耗最早获得的学币
- 过期前 **7天** 和 **1天** 各发送一次提醒通知
- 过期学币不退不补，但过期记录保留供查询

## 5. 数据模型设计

### 5.1 核心表结构

#### 5.1.1 用户货币账户表 `user_currency_account`

```sql
CREATE TABLE user_currency_account (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    currency_type   VARCHAR(10) NOT NULL COMMENT '货币类型：COIN/EXP/STAR',
    balance         BIGINT NOT NULL DEFAULT 0 COMMENT '当前余额',
    total_earned    BIGINT NOT NULL DEFAULT 0 COMMENT '累计获得',
    total_spent     BIGINT NOT NULL DEFAULT 0 COMMENT '累计消耗',
    total_expired   BIGINT NOT NULL DEFAULT 0 COMMENT '累计过期',
    version         INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_currency (user_id, currency_type),
    KEY idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户货币账户';
```

#### 5.1.2 积分流水表 `currency_transaction`

```sql
CREATE TABLE currency_transaction (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    transaction_no  VARCHAR(32) NOT NULL COMMENT '交易流水号（唯一）',
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    currency_type   VARCHAR(10) NOT NULL COMMENT '货币类型',
    change_amount   BIGINT NOT NULL COMMENT '变动数量（正=获得，负=消耗/过期）',
    balance_after   BIGINT NOT NULL COMMENT '变动后余额',
    transaction_type VARCHAR(20) NOT NULL COMMENT '交易类型：EARN/SPEND/EXPIRE/ADJUST',
    source_type     VARCHAR(30) NOT NULL COMMENT '来源类型（行为编码）',
    source_id       VARCHAR(64) DEFAULT NULL COMMENT '来源关联ID（如练习ID、兑换订单ID）',
    description     VARCHAR(200) DEFAULT NULL COMMENT '描述',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_transaction_no (transaction_no),
    KEY idx_user_type (user_id, currency_type, created_at),
    KEY idx_user_created (user_id, created_at),
    KEY idx_source (source_type, source_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='货币交易流水';
```

#### 5.1.3 学币批次表（FIFO过期管理） `coin_batch`

```sql
CREATE TABLE coin_batch (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    transaction_id  BIGINT NOT NULL COMMENT '关联的交易流水ID',
    original_amount BIGINT NOT NULL COMMENT '原始数量',
    remaining       BIGINT NOT NULL COMMENT '剩余数量',
    earned_at       DATETIME NOT NULL COMMENT '获得时间',
    expire_at       DATETIME NOT NULL COMMENT '过期时间',
    status          VARCHAR(10) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/EXPIRED/EMPTY',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_user_expire (user_id, status, expire_at),
    KEY idx_expire_scan (status, expire_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学币批次（FIFO过期管理）';
```

## 7. 核心业务逻辑

### 7.1 积分发放服务

```java
@Service
@Transactional
public class CurrencyEarnService {

    @Autowired
    private UserCurrencyAccountMapper accountMapper;
    @Autowired
    private CurrencyTransactionMapper transactionMapper;
    @Autowired
    private CoinBatchMapper coinBatchMapper;
    @Autowired
    private DailyEarningCapMapper dailyCapMapper;
    @Autowired
    private UserLevelService userLevelService;
    @Autowired
    private CurrencyRuleConfig ruleConfig;
    @Autowired
    private RedissonClient redissonClient;

    /**
     * 发放积分（核心方法）
     * 幂等性：基于 sourceType + sourceId 去重
     */
    public EarnResult earn(EarnRequest request) {
        // 1. 幂等校验
        if (isDuplicate(request.getSourceType(), request.getSourceId())) {
            return EarnResult.duplicate();
        }

        // 2. 分布式锁（防止并发导致超额）
        RLock lock = redissonClient.getLock(
            "currency:earn:" + request.getUserId() + ":" + request.getCurrencyType());
        try {
            if (!lock.tryLock(3, 10, TimeUnit.SECONDS)) {
                throw new BusinessException("SYSTEM_BUSY", "系统繁忙，请稍后重试");
            }

            // 3. 每日上限校验
            if (isDailyCapExceeded(request)) {
                return EarnResult.capExceeded();
            }

            // 4. 查询账户（乐观锁）
            UserCurrencyAccount account = accountMapper.selectByUserAndType(
                request.getUserId(), request.getCurrencyType());
            if (account == null) {
                account = createAccount(request.getUserId(), request.getCurrencyType());
            }

            // 5. 更新余额（乐观锁）
            int updated = accountMapper.addBalance(
                account.getId(), request.getAmount(), account.getVersion());
            if (updated == 0) {
                throw new OptimisticLockException("余额更新冲突，请重试");
            }

            // 6. 写入流水
            CurrencyTransaction txn = buildTransaction(
                request, account.getBalance() + request.getAmount());
            transactionMapper.insert(txn);

            // 7. 更新每日上限计数
            updateDailyCap(request);

            // 8. 学币写入批次（FIFO过期管理）
            if ("COIN".equals(request.getCurrencyType())) {
                createCoinBatch(request, txn.getId());
            }

            // 9. 经验值 → 检查升级
            LevelUpResult levelUpResult = null;
            if ("EXP".equals(request.getCurrencyType())) {
                levelUpResult = userLevelService.checkAndLevelUp(
                    request.getUserId(), request.getAmount());
            }

            return EarnResult.success(txn.getTransactionNo(),
                request.getAmount(), account.getBalance() + request.getAmount(),
                levelUpResult);

        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException("SYSTEM_ERROR", "获取锁失败");
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    private boolean isDailyCapExceeded(EarnRequest request) {
        EarningRule rule = ruleConfig.getRule(request.getSourceType());
        if (rule == null || rule.getDailyCap() <= 0) {
            return false;
        }
        DailyEarningCap cap = dailyCapMapper.selectByUserAndDate(
            request.getUserId(), request.getCurrencyType(),
            request.getSourceType(), LocalDate.now());
        return cap != null && cap.getEarnedToday() >= rule.getDailyCap();
    }
}
```

### 7.2 学币消耗服务（FIFO）

```java
@Service
@Transactional
public class CurrencySpendService {

    /**
     * 消耗学币（FIFO方式扣减批次）
     */
    public SpendResult spend(Long userId, int amount, String orderNo) {
        // 1. 查询账户余额
        UserCurrencyAccount account = accountMapper.selectByUserAndType(userId, "COIN");
        if (account == null || account.getBalance() < amount) {
            throw new BusinessException("CURRENCY_INSUFFICIENT", "学币余额不足");
        }

        // 2. 按FIFO查询活跃批次
        List<CoinBatch> batches = coinBatchMapper.selectActiveByUser(userId);
        int remaining = amount;

        // 3. 逐批扣减
        for (CoinBatch batch : batches) {
            if (remaining <= 0) break;
            int deduct = Math.min(batch.getRemaining(), remaining);
            coinBatchMapper.deductBatch(batch.getId(), deduct);
            remaining -= deduct;
        }

        if (remaining > 0) {
            throw new BusinessException("CURRENCY_INSUFFICIENT", "可用学币不足（含过期）");
        }

        // 4. 更新账户余额
        accountMapper.subtractBalance(account.getId(), amount, account.getVersion());

        // 5. 写入流水
        CurrencyTransaction txn = new CurrencyTransaction();
        txn.setTransactionNo(generateTxnNo("SPEND"));
        txn.setUserId(userId);
        txn.setCurrencyType("COIN");
        txn.setChangeAmount(-amount);
        txn.setBalanceAfter(account.getBalance() - amount);
        txn.setTransactionType("SPEND");
        txn.setSourceType("REDEEM");
        txn.setSourceId(orderNo);
        transactionMapper.insert(txn);

        return SpendResult.success(txn.getTransactionNo(),
            account.getBalance() - amount);
    }
}
```

### 7.3 学币过期扫描（定时任务）

```java
@Component
public class CoinExpireJob {

    /**
     * 每天凌晨3点扫描过期批次
     * Cron: 0 0 3 * * ?
     */
    @Scheduled(cron = "0 0 3 * * ?")
    @Transactional
    public void expireCoinBatches() {
        LocalDate today = LocalDate.now();

        // 1. 查询所有已过期但未处理的批次
        List<CoinBatch> expiredBatches = coinBatchMapper
            .selectExpired(today);

        // 按用户分组处理（避免同一用户并发问题）
        Map<Long, List<CoinBatch>> userBatches = expiredBatches.stream()
            .collect(Collectors.groupingBy(CoinBatch::getUserId));

        for (Map.Entry<Long, List<CoinBatch>> entry : userBatches.entrySet()) {
            Long userId = entry.getKey();
            long totalExpired = 0;

            for (CoinBatch batch : entry.getValue()) {
                totalExpired += batch.getRemaining();
                coinBatchMapper.updateStatus(batch.getId(), "EXPIRED");
            }

            // 扣减账户余额
            accountMapper.subtractBalance(userId, (int) totalExpired);

            // 写入过期流水
            CurrencyTransaction txn = new CurrencyTransaction();
            txn.setTransactionNo(generateTxnNo("EXPIRE"));
            txn.setUserId(userId);
            txn.setCurrencyType("COIN");
            txn.setChangeAmount(-(int) totalExpired);
            txn.setTransactionType("EXPIRE");
            txn.setSourceType("SYSTEM_EXPIRE");
            transactionMapper.insert(txn);
        }

        log.info("Coin expire job completed. {} batches expired for {} users",
            expiredBatches.size(), userBatches.size());
    }

    /**
     * 过期前7天和1天发送提醒
     * 每天上午10点执行
     * Cron: 0 0 10 * * ?
     */
    @Scheduled(cron = "0 0 10 * * ?")
    public void sendExpireReminders() {
        LocalDate today = LocalDate.now();

        // 7天后过期
        sendReminders(today.plusDays(7), "7天后");
        // 1天后过期
        sendReminders(today.plusDays(1), "1天后");
    }

    private void sendReminders(LocalDate expireDate, String timeDesc) {
        List<CoinBatch> batches = coinBatchMapper
            .selectExpiringSoon(expireDate);

        Map<Long, Long> userExpireAmount = batches.stream()
            .collect(Collectors.groupingBy(CoinBatch::getUserId,
                Collectors.summingLong(CoinBatch::getRemaining)));

        for (Map.Entry<Long, Long> entry : userExpireAmount.entrySet()) {
            notificationService.send(entry.getKey(),
                NotificationTemplate.COIN_EXPIRING,
                Map.of("amount", entry.getValue(), "timeDesc", timeDesc));
        }
    }
}
```

### 7.4 等级升级服务

```java
@Service
public class UserLevelService {

    private static final int MAX_LEVEL = 30;
    private static final double EXP_BASE = 50;
    private static final double EXP_GROWTH = 1.35;

    /**
     * 检查并执行升级
     */
    @Transactional
    public LevelUpResult checkAndLevelUp(Long userId, long addedExp) {
        UserLevel level = userLevelMapper.selectByUserId(userId);
        int oldLevel = level.getCurrentLevel();

        // 加经验
        level.setTotalExp(level.getTotalExp() + addedExp);

        // 计算新等级
        int newLevel = calculateLevel(level.getTotalExp());

        if (newLevel > oldLevel) {
            level.setCurrentLevel(newLevel);
            level.setCurrentTitle(getTitle(newLevel));
            level.setLevelUpAt(LocalDateTime.now());
            userLevelMapper.update(level);

            // 发放升级奖励
            grantLevelUpReward(userId, newLevel);

            // 发送升级通知
            eventPublisher.publishEvent(new LevelUpEvent(userId, oldLevel, newLevel));

            return LevelUpResult.upgraded(oldLevel, newLevel, getTitle(newLevel));
        }

        userLevelMapper.update(level);
        return LevelUpResult.noChange(newLevel);
    }

    /**
     * 根据累计经验计算等级
     */
    private int calculateLevel(long totalExp) {
        long cumulative = 0;
        for (int i = 1; i <= MAX_LEVEL; i++) {
            cumulative += Math.floor(EXP_BASE * Math.pow(EXP_GROWTH, i - 1));
            if (totalExp < cumulative) {
                return i;
            }
        }
        return MAX_LEVEL;
    }

    /**
     * 升级奖励：达到特定等级获得额外学币
     */
    private void grantLevelUpReward(Long userId, int newLevel) {
        int reward = 0;
        if (newLevel >= 5)  reward = 50;
        if (newLevel >= 10) reward = 100;
        if (newLevel >= 15) reward = 200;
        if (newLevel >= 20) reward = 300;
        if (newLevel >= 25) reward = 500;
        if (newLevel >= 30) reward = 1000;

        if (reward > 0) {
            earnService.earn(EarnRequest.builder()
                .userId(userId)
                .currencyType("COIN")
                .sourceType("LEVEL_UP_REWARD")
                .sourceId("LEVEL_" + newLevel)
                .amount(reward)
                .description("升级至Lv." + newLevel + " 奖励")
                .build());
        }
    }
}
```

```java
@Component
public class EarningAntiFraudService {

    /**
     * 检测异常积分获取行为
     */
    public AntiFraudResult check(EarnRequest request) {
        // 1. 设备指纹校验（同设备多账号互刷）
        int deviceAccounts = getAccountCountByDevice(request.getDeviceFingerprint());
        if (deviceAccounts > 3) {
            return AntiFraudResult.block("同设备账号过多");
        }

        // 2. 行为频率异常检测
        int recentCount = getRecentActionCount(request.getUserId(),
            request.getSourceType(), Duration.ofMinutes(10));
        if (recentCount > getAnomalyThreshold(request.getSourceType())) {
            return AntiFraudResult.block("行为频率异常");
        }

        // 3. 学习时间与行为不匹配
        if (isTimeMismatch(request)) {
            flagForReview(request.getUserId(), "学习时长与行为不匹配");
        }

        return AntiFraudResult.pass();
    }

    private int getAnomalyThreshold(String sourceType) {
        return switch (sourceType) {
            case "AI_QUESTION" -> 15;       // 10分钟内AI问答不超过15次
            case "PHOTO_SOLVE" -> 10;        // 10分钟内拍题不超过10次
            case "EXERCISE_CORRECT" -> 30;   // 10分钟内答题不超过30次
            default -> 20;
        };
    }
}
```

```lua
if currentBalance < deductAmount then

end

redis.call('HINCRBY', balanceKey, 'balance', -deductAmount)
return currentBalance - deductAmount
```

| 人均日获得学币 | 日总发放 / 日活跃用户 | 监控积分产出 |
| 人均日消耗学币 | 日总消耗 / 日活跃用户 | 监控积分消耗 |
| 积分消耗率 | 日消耗 / (日发放 + 期初余额) | 经济健康度 |
| 兑换转化率 | 兑换人数 / 有余额人数 | 商城吸引力 |
| 商品热度排名 | 各商品兑换次数 | 运营决策 |
| 积分过期率 | 日过期量 / 日初余额 | 过期策略是否合理 |
| 等级分布 | 各等级用户数 | 用户成长分布 |

### 13.2 运营配置能力

后台支持运营人员动态调整以下配置（无需发版）：

| 配置项 | 说明 |
|-------|------|
| 积分获取规则 | 各行为的学币奖励数和每日上限 |
| 商品上下架 | 商品信息、价格、库存、时间 |
| 过期天数 | 学币过期周期（默认365天） |
| 等级经验表 | 各等级所需累计经验值 |
| 升级奖励 | 特定等级的额外奖励 |
| 活动加成 | 限定时间内获取积分倍率 |

## 14. 安全与合规

### 14.1 数据安全

- 积分流水不可修改，仅可追加
- 管理员手动调整积分需审批流，记录操作人和原因
- 用户可导出自己的积分流水记录

### 14.2 未成年人保护

- 幼儿学段：星光体系独立，不支持兑换商城
- 小学学段：商城展示简化，仅显示功能道具和装扮类
- 家长可一键关闭子女的商城访问权限
- 单次兑换超过500学币需家长授权
- 不设置"限时抢购"等刺激消费的营销机制

### 14.3 反作弊审计

- 所有积分变动记录 `userId + sourceType + sourceId + IP + deviceId`
- 异常行为自动标记，人工复核
- 月度出具积分审计报告
