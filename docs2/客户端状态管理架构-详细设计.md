# 客户端状态管理架构 - 详细设计

> 版本：v1.0 | 日期：2026-05-24 | 状态：初稿
> 原始需求来源：`docs/design/启硕-PrimeTop-全学段AI辅助学习软件项目设计文档.md` §8.3

## 1. 模块概述

### 1.1 定位

客户端状态管理架构（Client State Management Architecture）是 PrimeTop Flutter 客户端的核心基础设施，定义全局/局部状态的划分规则、Provider 编排模式、状态同步策略、生命周期管理和错误处理规范。本文档为前端开发人员提供可直接编码落地的状态管理方案，确保各功能模块状态管理方式统一、可测试、可维护。

### 1.2 与其他文档的关系

| 文档 | 交叉点 | 本文档侧重 |
|------|--------|-----------|
| 客户端架构与前端框架 | Riverpod 选型确认 | 本文档细化 Provider 层级、状态模型、编排模式 |
| 客户端本地持久层与数据管理 | 本地数据存储 | 本文档定义状态与持久层的衔接策略 |
| 客户端网络请求治理与弱网适配方案 | 网络请求状态 | 本文档定义请求状态管理（Loading/Error/Data） |
| 客户端应用启动流程与初始化管线 | 启动时状态初始化 | 本文档定义全局状态初始化顺序 |
| 客户端路由与深链接系统 | 路由守卫依赖状态 | 本文档定义鉴权/权益/角色等守卫所需状态 |
| 用户账号体系 | 登录状态 | 本文档定义认证状态模型与 Provider |
| 首页与学习工作台 | 首页聚合状态 | 本文档定义跨模块状态聚合模式 |
| 分龄UI适配与交互设计规范 | 学段主题状态 | 本文档定义分龄状态模型 |
| 多端数据同步与冲突解决策略 | 同步状态 | 本文档定义本地状态与远程同步的协调 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 单一数据源 | 每一类状态只有一个权威 Provider，避免多个来源导致不一致 |
| 细粒度重建 | Provider 拆分到最小粒度，避免无关 UI 无谓重建 |
| 编译期安全 | 使用 `riverpod_generator` 代码生成，避免字符串 key 和运行时错误 |
| 可测试性 | Provider 通过 override 实现可替换，方便单元测试和 Widget 测试 |
| 渐进式加载 | 非首屏必需的 Provider 采用懒加载，减少启动耗时 |
| 优雅降级 | 网络失败/数据缺失时状态降级而非崩溃，UI 层展示兜底内容 |

## 2. 状态分类体系

### 2.1 状态分层模型

```
┌──────────────────────────────────────────────────────────┐
│                    全局应用状态 (Global)                    │
│  AuthState · UserProfile · AppSettings · ThemeState      │
│  ConnectivityState · DeviceState                         │
├──────────────────────────────────────────────────────────┤
│                    跨功能域状态 (Cross-Feature)             │
│  LearningProgressState · MembershipState · SyncState      │
│  NotificationState · AgeGroupState                       │
├──────────────────────────────────────────────────────────┤
│                    功能域状态 (Feature)                     │
│  AI: ConversationState · StreamingState                  │
│  题目: QuestionListState · AnswerRevealState              │
│  错题: MistakeBookState · ReviewPlanState                 │
│  ...各模块独立状态                                         │
├──────────────────────────────────────────────────────────┤
│                    页面/UI 状态 (UI)                        │
│  ScrollState · TextFieldState · AnimationState           │
│  DialogState · BottomSheetState · TabIndexState          │
└──────────────────────────────────────────────────────────┘
```

### 2.2 四层状态定义

#### 2.2.1 全局应用状态（Global App State）

生命周期 = App 进程生命周期，随 App 启动初始化，进程退出销毁。

| 状态 | Provider 名称 | 数据来源 | 持久化 | 说明 |
|------|--------------|----------|--------|------|
| 认证状态 | `authStateProvider` | SecureStorage + API | SecureStorage | Token、登录态、角色 |
| 用户档案 | `userProfileProvider` | API + Hive | Hive | 学段、年级、昵称、头像 |
| 应用设置 | `appSettingsProvider` | SharedPreferences | SharedPrefs | 语言、护眼模式、字体大小 |
| 主题状态 | `themeStateProvider` | 派生自 UserProfile + AppSettings | — | 分龄主题令牌 |
| 网络状态 | `connectivityProvider` | Connectivity 插件 | — | 在线/离线/Wi-Fi/蜂窝 |
| 设备状态 | `deviceInfoProvider` | device_info_plus | — | 设备 ID、型号、OS 版本 |
| 会员状态 | `membershipProvider` | API + 本地缓存 | Hive | 订阅类型、到期日、权益列表 |

#### 2.2.2 跨功能域状态（Cross-Feature State）

被多个功能模块共同使用的业务状态。

| 状态 | Provider 名称 | 消费方 | 说明 |
|------|--------------|--------|------|
| 学段年级 | `gradeStateProvider` | 几乎所有模块 | 当前学段、年级、教材版本 |
| 学习进度总览 | `learningOverviewProvider` | 首页、学情分析、家长中心 | 今日学习时长、任务完成数、连续天数 |
| 同步状态 | `syncStateProvider` | 各数据写入模块 | 本地变更是否已同步到云端 |
| 通知计数 | `unreadCountProvider` | 首页、个人中心 | 未读消息/提醒数 |
| 功能开关 | `featureFlagsProvider` | 各模块入口 | 灰度特性开关映射 |

#### 2.2.3 功能域状态（Feature State）

各功能模块内部的业务状态，生命周期 = 模块页面栈存活期间。

| 模块 | 核心状态 Provider | 说明 |
|------|-------------------|------|
| AI 辅导 | `conversationProvider` | 对话列表、当前会话、消息流 |
| AI 辅导 | `streamingAnswerProvider` | SSE 流式回答的增量状态 |
| 拍题答疑 | `photoQuestionProvider` | 拍照 → OCR → 题目识别结果 |
| 同步课堂 | `chapterContentProvider` | 当前章节、知识点、练习列表 |
| 错题本 | `mistakeBookProvider` | 错题列表、筛选条件、复习计划 |
| 学习规划 | `studyPlanProvider` | 今日任务、计划进度 |
| 作文辅导 | `essayReviewProvider` | 作文上传 → 评分 → 批注 |
| 考试模拟 | `examSessionProvider` | 试卷、计时、答题卡、交卷 |
| 文科背诵 | `recitationProvider` | 背诵内容、识别结果、评分 |

#### 2.2.4 页面/UI 状态（UI State）

页面级别的交互状态，通常不需要 Provider，用 `StatefulWidget` 的 `State` 或 `flutter_hooks` 管理即可。

| 场景 | 管理方式 | 说明 |
|------|----------|------|
| 滚动位置、动画进度 | StatefulWidget State | 纯 UI 无需 Provider |
| 输入框文本、焦点 | TextEditingController | Flutter 内置 |
| Tab 选中、页面切换 | PageController / TabController | Flutter 内置 |
| 底部弹窗开关 | 局部 bool state | 无需全局 |
| 列表滚动恢复 | ScrollController + keepAlive | Flutter 内置 |

**判断标准**：如果状态只在单个页面内使用、不需要跨页面共享、不需要持久化 → 用局部 State，不要过度设计成 Provider。

## 3. Provider 架构设计

### 3.1 Provider 命名规范

```
{状态名}Provider         — 只读 Provider（派生/计算型）
{状态名}NotifierProvider — 可变状态（AsyncNotifierProvider / NotifierProvider）
```

| 类型 | 命名模式 | 示例 |
|------|----------|------|
| 只读派生 | `{name}Provider` | `themeProvider`, `isLoggedInProvider` |
| 可变同步 | `{name}Provider` (Notifier) | `appSettingsProvider`, `gradeProvider` |
| 可变异步 | `{name}Provider` (AsyncNotifier) | `userProfileProvider`, `mistakeBookProvider` |
| Future 一次性 | `{name}FutureProvider` | `appVersionFutureProvider` |
| Stream 持续 | `{name}StreamProvider` | `connectivityStreamProvider` |

### 3.2 Provider 文件组织

每个功能模块的 Provider 放在该模块的 `presentation/` 目录下：

```
features/
  auth/
    presentation/
      auth_provider.dart        # 认证相关所有 Provider
      auth_page.dart            # 登录页
      register_page.dart        # 注册页
  ai_tutor/
    presentation/
      conversation_provider.dart  # 对话列表 Provider
      streaming_provider.dart     # SSE 流式回答 Provider
      chat_page.dart
      history_page.dart
```

全局 Provider 放在 `core/providers/`：

```
core/
  providers/
    auth_provider.dart          # 认证状态
    user_profile_provider.dart  # 用户档案
    app_settings_provider.dart  # 应用设置
    theme_provider.dart         # 主题状态（派生）
    connectivity_provider.dart  # 网络状态
    device_provider.dart        # 设备信息
    membership_provider.dart    # 会员状态
    feature_flags_provider.dart # 功能开关
```

### 3.3 代码生成模式（riverpod_generator）

所有 Provider 使用 `@riverpod` 注解生成，禁止手写 `Provider`：

```dart
// === auth_provider.dart ===
import 'package:riverpod_annotation/riverpod_annotation.dart';
import 'package:prime_top/core/storage/secure_storage.dart';
import 'package:prime_top/core/network/dio_client.dart';

part 'auth_provider.g.dart';

/// 认证状态数据模型
@freezed
class AuthState with _$AuthState {
  const factory AuthState({
    @Default(false) bool isLoggedIn,
    @Default(false) bool isLoading,
    String? userId,
    String? accessToken,
    String? refreshToken,
    String? phone,
    UserRole? role, // student, parent, teacher
    String? errorMessage,
  }) = _AuthState;
}

/// 认证状态 Notifier
@Riverpod(keepAlive: true)
class Auth extends _$Auth {
  @override
  AuthState build() {
    // 启动时从 SecureStorage 恢复登录态
    _restoreFromStorage();
    return const AuthState();
  }

  Future<void> _restoreFromStorage() async {
    final storage = ref.read(secureStorageProvider);
    final token = await storage.getAccessToken();
    if (token != null) {
      state = state.copyWith(
        isLoggedIn: true,
        accessToken: token,
        refreshToken: await storage.getRefreshToken(),
        userId: await storage.getUserId(),
        phone: await storage.getPhone(),
      );
      // 后台静默校验 Token 有效性
      _validateToken();
    }
  }

  Future<void> login(String phone, String code) async {
    state = state.copyWith(isLoading: true, errorMessage: null);
    try {
      final api = ref.read(apiClientProvider);
      final response = await api.post('/auth/login', data: {
        'phone': phone,
        'code': code,
      });
      final authData = AuthResponse.fromJson(response.data);
      
      // 持久化 Token
      final storage = ref.read(secureStorageProvider);
      await storage.saveAccessToken(authData.accessToken);
      await storage.saveRefreshToken(authData.refreshToken);
      await storage.saveUserId(authData.userId);
      await storage.savePhone(phone);
      
      state = state.copyWith(
        isLoggedIn: true,
        isLoading: false,
        accessToken: authData.accessToken,
        refreshToken: authData.refreshToken,
        userId: authData.userId,
        phone: phone,
        role: authData.role,
      );
    } catch (e) {
      state = state.copyWith(
        isLoading: false,
        errorMessage: _mapError(e),
      );
    }
  }

  Future<void> logout() async {
    final storage = ref.read(secureStorageProvider);
    await storage.clearAll();
    state = const AuthState();
  }

  Future<void> _validateToken() async {
    try {
      final api = ref.read(apiClientProvider);
      await api.get('/auth/validate');
    } catch (_) {
      // Token 失效，触发登出
      await logout();
    }
  }

  String _mapError(Object e) {
    if (e is DioException) {
      return switch (e.response?.statusCode) {
        401 => '验证码错误',
        429 => '请求过于频繁，请稍后重试',
        _ => '网络异常，请检查网络连接',
      };
    }
    return '登录失败，请重试';
  }
}
```

### 3.4 派生 Provider 模式

通过组合已有 Provider 派生新状态，避免重复逻辑：

```dart
/// 是否已登录 — 派生 Provider
@riverpod
bool isLoggedIn(IsLoggedInRef ref) {
  return ref.watch(authProvider).isLoggedIn;
}

/// 当前学段 — 派生自用户档案
@riverpod
GradeGroup currentGradeGroup(CurrentGradeGroupRef ref) {
  final profile = ref.watch(userProfileProvider).valueOrNull;
  if (profile == null) return GradeGroup.primary; // 默认小学
  return GradeGroup.fromGrade(profile.grade);
}

/// 是否 VIP — 派生自会员状态
@riverpod
bool isVip(IsVipRef ref) {
  final membership = ref.watch(membershipProvider).valueOrNull;
  if (membership == null) return false;
  return membership.isActive && membership.expireDate.isAfter(DateTime.now());
}

/// 是否离线模式 — 派生自网络状态
@riverpod
bool isOffline(IsOfflineRef ref) {
  return !ref.watch(connectivityProvider).isOnline;
}

/// 分龄主题令牌 — 组合多个 Provider
@riverpod
AppThemeTokens themeTokens(ThemeTokensRef ref) {
  final gradeGroup = ref.watch(currentGradeGroupProvider);
  final settings = ref.watch(appSettingsProvider);
  final isEyeCare = settings.eyeCareMode;
  
  return AppThemeTokens.resolve(
    gradeGroup: gradeGroup,
    eyeCareMode: isEyeCare,
    darkMode: settings.darkMode,
    fontSize: settings.fontSize,
  );
}
```

## 4. 异步状态管理规范

### 4.1 AsyncValue 统一处理

所有异步 Provider 返回 `AsyncValue<T>`，UI 层统一处理 loading/error/data 三态：

```dart
/// 标准 AsyncValue 处理模式
classUserProfilePage extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final profileAsync = ref.watch(userProfileProvider);
    
    return profileAsync.when(
      loading: () => const ProfileSkeleton(),       // 骨架屏
      error: (err, stack) => ProfileErrorView(       // 错误视图
        message: _friendlyError(err),
        onRetry: () => ref.invalidate(userProfileProvider),
      ),
      data: (profile) => ProfileContent(profile: profile),  // 正常数据
    );
  }
  
  String _friendlyError(Object err) {
    if (err is DioException && err.type == DioExceptionType.connectionError) {
      return '网络连接失败，请检查网络';
    }
    return '加载失败，请下拉刷新';
  }
}
```

### 4.2 手动 CRUD 操作模式

对于需要手动触发写操作的场景，使用 Notifier 方法 + 局部 loading 状态：

```dart
/// 错题本 Provider — CRUD 示例
@Riverpod(keepAlive: true)
class MistakeBook extends _$MistakeBook {
  @override
  FutureOr<MistakeBookState> build() async {
    // 初始化：从本地加载 + 后台从服务端拉取
    final localRepo = ref.read(mistakeLocalRepoProvider);
    final remoteRepo = ref.read(mistakeRemoteRepoProvider);
    
    // 1. 先返回本地数据（快速展示）
    final localData = await localRepo.getAll();
    
    // 2. 后台同步远端数据
    _syncFromRemote(remoteRepo, localRepo);
    
    return MistakeBookState(
      mistakes: localData,
      filter: MistakeFilter.empty,
      sortBy: MistakeSortBy.dateDesc,
    );
  }

  Future<void> _syncFromRemote(
    MistakeRemoteRepo remote,
    MistakeLocalRepo local,
  ) async {
    try {
      final remoteData = await remote.getAll();
      await local.replaceAll(remoteData);
      state = AsyncData(state.value!.copyWith(mistakes: remoteData));
    } catch (_) {
      // 后台同步失败不阻塞 UI，使用本地数据
    }
  }

  /// 添加错题
  Future<AddMistakeResult> addMistake(MistakeRecord mistake) async {
    try {
      // 乐观更新：先更新本地状态
      final current = state.value!;
      state = AsyncData(current.copyWith(
        mistakes: [mistake, ...current.mistakes],
      ));
      
      // 异步持久化到本地 + 远端
      final localRepo = ref.read(mistakeLocalRepoProvider);
      final remoteRepo = ref.read(mistakeRemoteRepoProvider);
      await localRepo.insert(mistake);
      await remoteRepo.create(mistake);
      
      return AddMistakeResult.success;
    } catch (e) {
      // 回滚本地状态
      ref.invalidateSelf();
      return AddMistakeResult.failed(_mapError(e));
    }
  }

  /// 删除错题
  Future<void> removeMistake(String mistakeId) async {
    try {
      final current = state.value!;
      state = AsyncData(current.copyWith(
        mistakes: current.mistakes.where((m) => m.id != mistakeId).toList(),
      ));
      
      final localRepo = ref.read(mistakeLocalRepoProvider);
      final remoteRepo = ref.read(mistakeRemoteRepoProvider);
      await localRepo.delete(mistakeId);
      await remoteRepo.delete(mistakeId);
    } catch (e) {
      ref.invalidateSelf();
    }
  }
}

/// 操作结果封装
enum AddMistakeResult {
  success,
  failed;
  
  final String? message;
  const AddMistakeResult([this.message]);
  
  factory AddMistakeResult.failed(String msg) => 
    AddMistakeResult.failed(msg);
}
```

### 4.3 SSE 流式状态管理

AI 回答采用 SSE 流式推送，使用 `StreamProvider` 配合自定义 SSE 客户端：

```dart
/// AI 流式回答 Provider
@riverpod
class StreamingAnswer extends _$StreamingAnswer {
  @override
  StreamingAnswerState build() {
    return const StreamingAnswerState.idle();
  }

  /// 开始流式回答
  void startStream(String conversationId, String userMessage) {
    state = const StreamingAnswerState.loading();
    
    final sseClient = ref.read(sseClientProvider);
    final buffer = StringBuffer();
    
    sseClient
        .connect('/ai/chat/stream', body: {
          'conversation_id': conversationId,
          'message': userMessage,
        })
        .listen(
          (event) {
            if (event.data != null) {
              buffer.write(event.data);
              state = StreamingAnswerState.streaming(
                content: buffer.toString(),
                isDone: false,
              );
            }
            if (event.event == 'done') {
              state = StreamingAnswerState.streaming(
                content: buffer.toString(),
                isDone: true,
              );
            }
          },
          onError: (err) {
            state = StreamingAnswerState.error(
              content: buffer.toString(),
              errorMessage: '回答生成失败，请重试',
            );
          },
          onDone: () {
            // 流正常结束，如果没有被 done 事件关闭
            final current = state;
            if (current is _Streaming) {
              state = StreamingAnswerState.streaming(
                content: current.content,
                isDone: true,
              );
            }
          },
          cancelOnError: false,
        );
  }

  void reset() {
    state = const StreamingAnswerState.idle();
  }
}

/// 流式回答状态 — 使用 Freezed sealed class
@freezed
sealed class StreamingAnswerState with _$StreamingAnswerState {
  const factory StreamingAnswerState.idle() = _Idle;
  const factory StreamingAnswerState.loading() = _Loading;
  const factory StreamingAnswerState.streaming({
    required String content,
    required bool isDone,
  }) = _Streaming;
  const factory StreamingAnswerState.error({
    @Default('') String content,
    required String errorMessage,
  }) = _StreamError;
}
```

## 5. 状态初始化与生命周期

### 5.1 Provider 初始化顺序

App 启动时 Provider 按依赖顺序初始化（`keepAlive: true` 的 Provider 不会自动释放）：

```
启动阶段 1 — 基础设施（main() 中 pre-warm）
  ┌─ deviceInfoProvider        (设备信息，无依赖)
  ├─ secureStorageProvider     (加密存储实例，无依赖)
  ├─ sharedPreferencesProvider (键值存储实例，无依赖)
  └─ connectivityProvider      (网络监听，无依赖)

启动阶段 2 — 认证与用户（SplashScreen 中 await）
  ┌─ authProvider              (依赖: secureStorage)
  ├─ appSettingsProvider       (依赖: sharedPreferences)
  └─ featureFlagsProvider      (依赖: 无，远程拉取)

启动阶段 3 — 用户数据（认证完成后加载）
  ┌─ userProfileProvider       (依赖: auth, 需登录)
  ├─ gradeProvider             (依赖: userProfile)
  ├─ membershipProvider        (依赖: auth)
  └─ themeProvider             (依赖: grade + settings)

启动阶段 4 — 业务数据（进入首页后懒加载）
  ┌─ learningOverviewProvider  (依赖: auth, userProfile)
  ├─ unreadCountProvider       (依赖: auth)
  └─ syncStateProvider         (依赖: auth, connectivity)
```

### 5.2 keepAlive 策略

| keepAlive | 适用场景 | 示例 |
|-----------|----------|------|
| `true` | 全局状态、跨页面共享、初始化成本高 | auth, userProfile, theme, membership |
| `false` (默认) | 页面级状态、功能域状态、用户离开页面后应释放 | conversationList, mistakeBook, examSession |
| `autoDispose` + `ref.keepAlive()` | 条件保活：首次创建后保留 | 缓存型 Provider，首次加载后保活 |

```dart
/// 条件保活示例：首次加载后不自动释放
@Riverpod(keepAlive: false)
Future<List<Subject>> subjectList(SubjectListRef ref) async {
  final api = ref.read(apiClientProvider);
  final subjects = await api.get('/subjects');
  
  // 首次加载成功后保活，避免每次进入页面重新请求
  ref.keepAlive();
  
  return subjects.map((s) => Subject.fromJson(s)).toList();
}
```

### 5.3 状态刷新策略

| 场景 | 刷新方式 | 说明 |
|------|----------|------|
| 用户下拉刷新 | `ref.invalidate(provider)` | 重置 Provider 重新 build |
| 收到推送通知 | `ref.invalidate(targetProvider)` | 按需刷新对应数据 |
| 页面恢复可见 | `WidgetsBindingObserver.didChangeAppLifecycleState` | App 从后台回到前台时刷新关键状态 |
| Token 刷新后 | `ref.invalidate(protectedApiProvider)` | 重新发起之前因 401 失败的请求 |
| 强制数据更新 | `ref.refresh(provider)` | 获取新值并替换旧值 |

## 6. 状态同步与冲突解决

### 6.1 离线写入队列

离线状态下用户操作进入写入队列，恢复网络后按序提交：

```dart
/// 离线操作队列 Provider
@Riverpod(keepAlive: true)
class OfflineQueue extends _$OfflineQueue {
  @override
  OfflineQueueState build() {
    // 启动时加载未提交的操作
    _loadPendingOps();
    
    // 监听网络状态变化
    ref.listen(connectivityProvider, (prev, next) {
      if (next.isOnline && state.hasPendingOps) {
        _flushQueue();
      }
    });
    
    return const OfflineQueueState.empty();
  }

  Future<void> _loadPendingOps() async {
    final storage = ref.read(offlineOpStorageProvider);
    final ops = await storage.getAll();
    if (ops.isNotEmpty) {
      state = OfflineQueueState(pendingOps: ops, isSyncing: false);
    }
  }

  /// 添加离线操作
  Future<void> enqueue(OfflineOp op) async {
    // 1. 本地持久化（防丢失）
    final storage = ref.read(offlineOpStorageProvider);
    await storage.insert(op);
    
    // 2. 更新内存状态
    state = state.copyWith(
      pendingOps: [...state.pendingOps, op],
    );
    
    // 3. 如果在线，立即尝试提交
    final connectivity = ref.read(connectivityProvider);
    if (connectivity.isOnline) {
      _flushQueue();
    }
  }

  Future<void> _flushQueue() async {
    if (state.isSyncing || state.pendingOps.isEmpty) return;
    
    state = state.copyWith(isSyncing: true);
    
    final api = ref.read(apiClientProvider);
    final storage = ref.read(offlineOpStorageProvider);
    
    final remaining = <OfflineOp>[...state.pendingOps];
    
    for (final op in remaining) {
      try {
        await op.execute(api);
        await storage.delete(op.id);
        remaining.remove(op);
        state = state.copyWith(pendingOps: List.of(remaining));
      } catch (e) {
        // 提交失败，保留在队列中，下次重试
        break;
      }
    }
    
    state = state.copyWith(isSyncing: false);
  }
}

/// 离线操作定义
@freezed
class OfflineOp with _$OfflineOp {
  const factory OfflineOp({
    required String id,
    required String type,     // 'add_mistake', 'save_note', 'update_progress'
    required Map<String, dynamic> payload,
    required DateTime createdAt,
    int retryCount = 0,
  }) = _OfflineOp;

  const OfflineOp._();

  Future<void> execute(ApiClient api) async {
    switch (type) {
      case 'add_mistake':
        await api.post('/mistakes', data: payload);
      case 'save_note':
        await api.post('/notes', data: payload);
      case 'update_progress':
        await api.patch('/learning/progress', data: payload);
      default:
        throw UnimplementedError('Unknown op type: $type');
    }
  }
}
```

### 6.2 服务端数据合并策略

当本地与服务端数据存在冲突时，按以下规则处理：

| 冲突场景 | 策略 | 实现 |
|----------|------|------|
| 学习进度 | **服务端优先** | 以服务端记录的最新进度为准 |
| 错题列表 | **合并（union）** | 本地新增 + 服务端新增取并集，基于 ID 去重 |
| 用户设置 | **最新时间戳优先** | 比较 `updatedAt`，取较新的版本 |
| AI 对话记录 | **服务端优先** | 对话由服务端生成，以服务端为准 |
| 离线操作 | **客户端操作重放** | 恢复网络后按时间顺序重放未提交操作 |

各功能模块通过 `ref.read()` 获取其他模块的 Repository（不直接 watch 状态，避免过度耦合）：

**规则**：
- `ref.watch()` — 仅用于派生 Provider 中监听上游状态变化
- `ref.read()` — 用于 Notifier 方法中获取一次性依赖（Repository、ApiClient）
- `ref.listen()` — 用于副作用响应（如网络恢复后触发同步）

/// 根 Navigator 层的全局错误处理
class AppErrorObserver extends ConsumerWidget {
  final Widget child;
  
  const AppErrorObserver({super.key, required this.child});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    // 监听认证状态变化
    ref.listen(authProvider, (prev, next) {
      if (prev?.isLoggedIn == true && !next.isLoggedIn) {
        // 被登出，跳转登录页
        context.go('/login');
      }
    });

    // 监听网络状态变化
    ref.listen(connectivityProvider, (prev, next) {
      if (prev?.isOnline == true && !next.isOnline) {
        ScaffoldMessenger.of(context).showSnackBar(
          const SnackBar(content: Text('网络已断开，部分功能可能受限')),
        );
      }
    });

    return child;
  }
}

### 8.3 降级策略

| 场景 | 降级行为 | UI 表现 |
|------|----------|---------|
| 网络断开 | 使用本地缓存数据 | 顶部显示「离线模式」横幅 |
| API 401 | Token 刷新 → 失败则登出 | 跳转登录页 |
| API 429 | 显示限流提示，定时重试 | 提示「请求过于频繁」 |
| API 5xx | 使用本地缓存或空态 | 错误页 + 重试按钮 |
| Token 刷新失败 | 清除本地认证，跳转登录 | 登录页 |
| 本地存储损坏 | 清除并重建本地数据 | 静默处理，用户无感知 |
| AI 流式中断 | 展示已接收内容 + 提示 | 「回答中断，点击重试」 |

## 10. 性能优化规范

### 10.1 避免 Provider 过度重建

| 反模式 | 正确做法 |
|--------|----------|
| `ref.watch(userProfileProvider)` 在多处使用 | 派生细粒度 Provider，如 `ref.watch(currentGradeGroupProvider)` |
| 单个大 Provider 包含所有字段 | 按职责拆分为多个小 Provider |
| `ref.listen` 中 `setState` | 使用 `ref.listen` 直接驱动 UI，不经过 Widget State |
| 在 `build()` 中使用 `ref.read()` | 应使用 `ref.watch()` 以响应变化 |
| `keepAlive: true` 滥用 | 仅全局共享状态使用，页面级用 `autoDispose` |

### 10.2 Selector 模式

对于大对象 Provider，使用 `select` 只监听需要的字段：

```dart
class UserNameBar extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    // 只监听 nickname 变化，avatar 变化不触发重建
    final nickname = ref.watch(
      userProfileProvider.select(
        (async) => async.valueOrNull?.nickname ?? '',
      ),
    );
    
    return Text(nickname);
  }
}
```

### 10.3 Debounce 与 Throttle

高频状态变化（如搜索输入、实时同步进度）应加防抖：

```dart
/// 搜索输入防抖
@riverpod
Future<List<Question>> searchResults(SearchResultsRef ref) async {
  // 搜索关键词变化后 300ms 才发起请求
  final keyword = ref.watchDebounced(
    searchKeywordProvider,
    duration: const Duration(milliseconds: 300),
  );
  
  if (keyword.isEmpty) return [];
  
  final api = ref.read(apiClientProvider);
  final response = await api.get('/questions/search', queryParameters: {
    'keyword': keyword,
  });
  
  return (response.data as List).map((e) => Question.fromJson(e)).toList();
}
```

## 13. 迁移指南

如果未来从 Riverpod 2.x 升级到 3.x，注意以下变化：

| 2.x | 3.x | 影响 |
|-----|-----|------|
| `ConsumerWidget` | 不变 | 无迁移成本 |
| `@riverpod` 注解 | 可能变更生成器 API | 重新运行 build_runner |
| `ref.watch()` | 不变 | 无迁移成本 |
| `AsyncValue` | 可能增强 | 关注新 API |
| `keepAlive` | 不变 | 无迁移成本 |

建议：始终使用 `riverpod_generator` 代码生成模式，避免手写 Provider，这样升级时只需重新生成代码。
