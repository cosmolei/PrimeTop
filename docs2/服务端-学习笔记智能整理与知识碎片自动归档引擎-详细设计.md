# 服务端 - 学习笔记智能整理与知识碎片自动归档引擎

> **模块定位**：在现有「收藏与笔记系统」基础上构建智能化处理层，利用 NLP 与知识图谱技术，将学生的零散笔记自动转化为结构化、可检索、可复习的个人知识体系。
>
> **依赖文档**：`收藏与笔记系统-详细设计.md`、`知识点体系与教材映射引擎-详细设计.md`、`间隔重复算法与遗忘曲线复习调度引擎-详细设计.md`、`RAG与知识库系统-详细设计.md`

## 1. 模块概述

### 1.1 背景与问题

现有笔记系统提供了完善的 CRUD 能力（创建、编辑、收藏、文件夹、标签、全文检索），但随着使用深入，学生面临以下痛点：

| 痛点 | 描述 | 影响 |
|------|------|------|
| **知识碎片化** | 学习过程中随手记录的笔记分散在各学科、各章节下，缺乏统一视图 | 考前复习效率低 |
| **手动分类负担** | 需要学生自己选择文件夹、打标签，使用门槛高 | 低龄学生放弃整理 |
| **笔记质量参差** | 学生不清楚什么样的笔记更有价值 | 学习效果难以保证 |
| **缺乏关联** | 笔记之间、笔记与教材知识点之间没有关联 | 无法形成知识网络 |
| **复习转化难** | 笔记内容无法直接用于自测和复习 | 笔记沦为"写了不看" |

### 1.2 功能目标

1. **智能分类归档**：自动识别笔记的学科、章节、知识点，无需用户手动选择文件夹。
2. **知识关联提取**：自动建立笔记与教材知识点、题目的关联关系。
3. **内容摘要生成**：为长笔记生成要点摘要，支持快速浏览。
4. **复习卡片自动生成**：将笔记内容转化为问答卡片，接入间隔重复复习系统。
5. **笔记质量评估**：评估笔记的完整性、结构化程度，给出改进建议。
6. **个人知识图谱**：从笔记中提取关键概念，构建学生个人知识网络。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **异步处理** | 所有智能分析均异步执行，笔记保存即刻返回，后台逐步完成处理 |
| **渐进增强** | 笔记保存后先执行快速分类（<2s），深度分析在后台逐步完成（<30s） |
| **可纠正** | 系统的自动分类和标签允许用户手动修改，并记录反馈用于模型优化 |
| **降级友好** | AI 服务不可用时退回到规则匹配，不影响核心笔记功能 |
| **隐私优先** | 笔记内容属于学生个人数据，智能分析仅产出结构化元数据，不对外暴露原文 |

### 1.4 用户场景

```
场景1：快速记录
学生做完一道数学题，随手写了一条笔记："二次函数最值问题，注意对称轴位置"
→ 系统自动识别：学科=数学，知识点=二次函数，关联章节=九年级上册第22章
→ 自动生成复习卡片：Q: 二次函数求最值要注意什么？ A: 注意对称轴的位置

场景2：考前整理
期末考试前，学生打开笔记复习，系统展示：
→ 按学科自动归类的笔记列表
→ 每条笔记的要点摘要
→ 自动生成的复习卡片集
→ 建议重点复习的薄弱知识点（基于笔记中的疑问标记）

场景3：长期积累
学生使用三个月后，系统构建出个人知识图谱：
→ 可视化展示各学科笔记积累情况
→ 自动发现知识盲区（某些章节笔记极少）
→ 关联推荐："你关于'电学'的笔记较少，建议复习欧姆定律相关内容"
```

### 2.2 处理管线总览

笔记从创建到完成智能处理的全生命周期：

```
用户保存笔记
     │
     ▼
[1] 笔记写入 DB (同步, <100ms) → 返回客户端
     │
     ▼
[2] 发送事件到消息队列 NoteCreatedEvent
     │
     ▼
[3] 快速分类管线 (异步, <2s)
     ├── 学科识别 (规则 + 关键词词典)
     ├── 章节匹配 (基于用户当前学习上下文)
     └── 写入分类元数据 → 可被用户看到
     │
     ▼
[4] 深度分析管线 (异步, <15s)
     ├── 知识点关联提取 (调用知识点服务 + 向量检索)
     ├── 内容摘要生成 (LLM 调用)
     ├── 笔记质量评估 (规则 + LLM)
     └── 写入分析结果 → 更新笔记元数据
     │
     ▼
[5] 卡片生成管线 (异步, <10s)
     ├── 从笔记内容提取关键概念
     ├── 生成问答对 (LLM 调用)
     ├── 质量过滤 (置信度 > 阈值)
     └── 写入复习卡片库 → 接入间隔重复系统
     │
     ▼
[6] 图谱更新管线 (异步, <5s)
     ├── 提取实体与关系 (NER + 关系抽取)
     ├── 更新个人知识图谱节点
     ├── 更新笔记间关联关系
     └── 写入图数据库 → 更新可视化
```

## 3. 数据模型

### 3.1 核心表结构

> 以下表基于 MySQL 8.0，字符集 utf8mb4。与现有 `notes` 表通过 `note_id` 关联，不修改原表结构。

#### 3.1.1 note_analysis（笔记智能分析结果）

```sql
CREATE TABLE note_analysis (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    note_id         BIGINT NOT NULL COMMENT '笔记ID，关联notes.id',
    user_id         BIGINT NOT NULL COMMENT '用户ID（冗余，便于查询）',

    -- 快速分类结果
    subject_code    VARCHAR(20)   COMMENT '学科编码: MATH/CHINESE/ENGLISH/...',
    subject_confidence DECIMAL(4,3) COMMENT '学科识别置信度 0-1',
    chapter_id      BIGINT        COMMENT '匹配的教材章节ID',
    chapter_confidence DECIMAL(4,3) COMMENT '章节匹配置信度',
    grade_stage     VARCHAR(20)   COMMENT '推断学段: PRIMARY/JUNIOR/SENIOR',

    -- 深度分析结果
    summary         TEXT          COMMENT 'AI生成的笔记摘要（≤200字）',
    quality_score   INT           COMMENT '笔记质量评分 0-100',
    quality_tags    JSON          COMMENT '质量标签数组: ["structured","concise","has_examples"]',
    improvement_hints JSON        COMMENT '改进建议数组: [{"type":"add_example","text":"..."}]',

    -- 关联信息
    knowledge_points JSON         COMMENT '关联知识点: [{"kp_id":123,"name":"二次函数","confidence":0.92}]',
    linked_note_ids  JSON         COMMENT '关联笔记ID数组',
    linked_question_ids JSON      COMMENT '关联题目ID数组（如有）',

    -- 处理状态
    analysis_status VARCHAR(20) NOT NULL DEFAULT 'pending'
                    COMMENT 'pending/classifying/analyzing/card_generating/graph_updating/done/failed',
    pipeline_version INT NOT NULL DEFAULT 1 COMMENT '处理管线版本号',
    error_code      VARCHAR(50)   COMMENT '失败时的错误码',
    error_msg       TEXT          COMMENT '失败时的错误信息',
    retry_count     INT NOT NULL DEFAULT 0,

    -- 置信度与纠正
    user_corrected  TINYINT NOT NULL DEFAULT 0 COMMENT '用户是否手动修正过分类',
    corrected_subject_code VARCHAR(20) COMMENT '用户修正后的学科',

    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),

    UNIQUE KEY uk_note_id (note_id),
    INDEX idx_user_subject (user_id, subject_code),
    INDEX idx_user_status (user_id, analysis_status),
    INDEX idx_chapter (chapter_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='笔记智能分析结果表';
```

#### 3.1.2 note_review_card（笔记复习卡片）

```sql
CREATE TABLE note_review_card (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    note_id         BIGINT NOT NULL COMMENT '源笔记ID',
    user_id         BIGINT NOT NULL COMMENT '用户ID',

    question        TEXT NOT NULL COMMENT '卡片问题面（如：二次函数最值怎么求？）',
    answer          TEXT NOT NULL COMMENT '卡片答案面',
    card_type       VARCHAR(20) NOT NULL DEFAULT 'qa'
                    COMMENT '卡片类型: qa/fill_blank/multiple_choice/concept_map',

    -- 关联
    knowledge_point_ids JSON     COMMENT '关联知识点ID数组',

    -- 质量与状态
    confidence_score DECIMAL(4,3) COMMENT '生成质量置信度 0-1',
    status          VARCHAR(20) NOT NULL DEFAULT 'active'
                    COMMENT 'active/archived/deleted',
    user_feedback   TINYINT       COMMENT '用户反馈: 1=有用 -1=无用 NULL=未反馈',

    -- 间隔重复系统集成字段
    srs_card_id     BIGINT        COMMENT '在间隔重复系统中的卡片ID',
    next_review_at  DATETIME      COMMENT '下次复习时间（冗余，便于查询）',
    review_count    INT NOT NULL DEFAULT 0,
    last_reviewed_at DATETIME,

    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),

    INDEX idx_note (note_id),
    INDEX idx_user_status (user_id, status),
    INDEX idx_user_review (user_id, next_review_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='笔记复习卡片表';
```

#### 3.1.3 note_entity（笔记知识实体 - 用于个人知识图谱）

```sql
CREATE TABLE note_entity (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL,
    entity_text     VARCHAR(200) NOT NULL COMMENT '实体文本: 如"二次函数"',
    entity_type     VARCHAR(50)          COMMENT '实体类型: concept/formula/person/event/...',
    subject_code    VARCHAR(20)          COMMENT '所属学科',
    kp_id           BIGINT               COMMENT '关联的全局知识点ID（如能匹配）',

    mention_count   INT NOT NULL DEFAULT 1 COMMENT '在笔记中被提及次数',
    first_note_id   BIGINT                COMMENT '首次出现的笔记ID',
    last_note_id    BIGINT                COMMENT '最近出现的笔记ID',

    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),

    UNIQUE KEY uk_user_entity (user_id, entity_text),
    INDEX idx_user_subject (user_id, subject_code),
    INDEX idx_kp (kp_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='笔记知识实体表';
```

#### 3.1.4 note_entity_relation（笔记知识实体关系）

```sql
CREATE TABLE note_entity_relation (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL,
    source_entity_id BIGINT NOT NULL COMMENT '源实体ID',
    target_entity_id BIGINT NOT NULL COMMENT '目标实体ID',
    relation_type   VARCHAR(50) NOT NULL COMMENT '关系类型: prerequisite/related/contrast/example',
    weight          DECIMAL(4,3) NOT NULL DEFAULT 0.5 COMMENT '关系强度 0-1',
    evidence_note_ids JSON              COMMENT '支撑该关系的笔记ID数组',

    INDEX idx_user (user_id),

```

### 3.2 Redis 缓存设计

```
# 笔记分析结果缓存（1小时TTL）
note:analysis:{note_id} → JSON(note_analysis row)

# 用户笔记统计缓存（10分钟TTL）
note:stats:{user_id} → {
    "total": 156,
    "by_subject": {"MATH": 45, "CHINESE": 38, ...},
    "review_cards_due": 12,
    "quality_avg": 72,
    "last_analysis_at": "2026-06-19T01:00:00Z"
}

# 快速分类关键词词典缓存（1小时TTL）
note:classify:keywords:{subject_code} → Set("二次函数", "方程", "几何", ...)

# 管线幂等锁（防止重复处理）
note:pipeline:lock:{note_id} → "processing" (TTL=120s)

# 用户知识图谱缓存（30分钟TTL）
note:graph:{user_id} → JSON(nodes & edges)
```

### 3.3 向量索引设计

笔记内容向量化后存入 Milvus（或 pgvector），用于笔记间语义相似度计算和知识关联。

```python
# Milvus Collection Schema: note_embeddings
collection_name = "note_embeddings"
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True),
    FieldSchema(name="note_id", dtype=DataType.INT64),
    FieldSchema(name="user_id", dtype=DataType.INT64),
    FieldSchema(name="subject_code", dtype=DataType.VARCHAR, max_length=20),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=1024),
    FieldSchema(name="created_at", dtype=DataType.INT64),  # timestamp
]
# 索引: IVF_FLAT on embedding, nlist=1024
# 度量: Inner Product (归一化后等价于余弦相似度)
```

### 4.1 API 总览

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 触发笔记分析 | POST | `/api/v1/notes/{noteId}/analyze` | 手动触发或重新分析 |

## 5. 核心管线详细设计

### 5.1 快速分类管线（Quick Classification Pipeline）

**目标**：在笔记保存后 2 秒内完成学科识别和章节匹配，结果立即可见。

**处理流程**：

```python
class QuickClassificationPipeline:
    """
    快速分类管线：基于规则 + 关键词词典 + 上下文推断
    不调用 LLM，确保快速响应。
    """

    def process(self, note_id: int, content: str, context: NoteContext) -> ClassificationResult:
        # Step 1: 上下文推断（最快速）
        context_result = self._infer_from_context(context)
        # 如果上下文置信度足够高，直接返回
        if context_result.confidence >= 0.85:
            return context_result

        # Step 2: 关键词词典匹配
        keyword_result = self._match_keywords(content)
        # 合并上下文和关键词结果
        merged = self._merge_results(context_result, keyword_result)

        # Step 3: 如果前两步置信度不足，使用轻量级分类模型
        if merged.confidence < 0.6:
            model_result = self._lightweight_classify(content)
            merged = self._merge_results(merged, model_result)

        # Step 4: 章节匹配（在确定的学科内搜索）
        if merged.subject_code:
            merged.chapter = self._match_chapter(
                content, merged.subject_code, context.grade, context.textbook_version
            )

        return merged

    def _infer_from_context(self, context: NoteContext) -> ClassificationResult:
        """
        基于用户当前的学习上下文推断学科和章节。
        例如：用户正在学"九年级数学第22章"，创建笔记时大概率属于该章节。
        """
        if context.current_subject and context.current_chapter_id:
            return ClassificationResult(
                subject_code=context.current_subject,
                chapter_id=context.current_chapter_id,
                confidence=0.70,  # 上下文置信度基线
                source="context"
            )
        return ClassificationResult(confidence=0.0, source="context")

    def _match_keywords(self, content: str) -> ClassificationResult:
        """
        学科关键词词典匹配。
        词典来源：教材知识点名称、学科专有名词、公式名、历史事件等。
        词典缓存在 Redis 中，每日刷新。
        """
        scores = {}  # {subject_code: (score, matched_keywords)}
        for subject_code, keyword_set in self.keyword_cache.items():
            matched = []
            for keyword in keyword_set:
                if keyword in content:
                    matched.append(keyword)
            if matched:
                scores[subject_code] = (len(matched) / 10.0, matched)

        if not scores:
            return ClassificationResult(confidence=0.0, source="keyword")

        best_subject = max(scores, key=lambda k: scores[k][0])
        score, matched = scores[best_subject]
        # 置信度 = min(命中关键词数 / 5, 1.0) * 0.8
        confidence = min(len(matched) / 5.0, 1.0) * 0.8

        return ClassificationResult(
            subject_code=best_subject,
            confidence=confidence,
            source="keyword",
            matched_keywords=matched
        )

    def _lightweight_classify(self, content: str) -> ClassificationResult:
        """
        轻量级文本分类模型（FastText / 朴素贝叶斯）。
        模型大小 <10MB，推理延迟 <50ms。
        训练数据：标注过的教育内容（题目、知识点描述、教材摘要）。
        """
        # 加载预训练模型
        labels = self.classifier.predict(content)
        return ClassificationResult(
            subject_code=labels[0][0],
            confidence=labels[0][1],
            source="model"
        )
```

### 5.2 深度分析管线（Deep Analysis Pipeline）

**目标**：在笔记保存后 15 秒内完成深度分析，包括摘要生成、知识点关联、质量评估。

```python
class DeepAnalysisPipeline:
    """
    深度分析管线：调用 LLM 完成摘要、知识点关联和质量评估。
    使用合并 Prompt 策略，单次 LLM 调用完成多项分析。
    """

    ANALYSIS_PROMPT_TEMPLATE = """你是一个教育内容分析助手。请分析以下学生笔记：

## 笔记内容
{note_content}

## 学生信息
- 学段: {grade_stage}
- 学科（已识别）: {subject_code}
- 教材版本: {textbook_version}

## 请以 JSON 格式输出分析结果：

```json
{{
  "summary": "100-200字的笔记摘要，提炼核心知识点",
  "knowledge_points": [
    {{
      "name": "知识点名称",
      "confidence": 0.0-1.0,
      "relevance": "该知识点与笔记的关联说明"
    }}
  ],
  "quality": {{
    "score": 0-100,
    "tags": ["structured|concise|detailed|has_examples|unclear|incomplete"],
    "improvement_hints": [
      {{
        "type": "add_formula|add_example|add_connection|clarify|expand",
        "text": "具体的改进建议"
      }}
    ]
  }},
  "key_concepts": ["从笔记中提取的关键概念，用于知识图谱构建"]
}}
```

注意：
1. 知识点名称请使用标准教材术语
2. 质量评分标准：内容完整性(40%) + 结构清晰度(25%) + 有无示例(15%) + 与教材关联度(20%)
3. 如果笔记内容过少或无实质内容，score 给 30 以下
4. improvement_hints 最多 3 条，按优先级排序"""

    async def process(self, note_id: int, content: str,
                      classification: ClassificationResult,
                      user_profile: UserProfile) -> AnalysisResult:
        # 1. 构建 Prompt
        prompt = self.ANALYSIS_PROMPT_TEMPLATE.format(
            note_content=content[:2000],  # 截断，防止超长
            grade_stage=user_profile.grade_stage,
            subject_code=classification.subject_code or "未知",
            textbook_version=user_profile.textbook_version or "通用"
        )

        # 2. 调用 LLM（带超时和重试）
        llm_response = await self.llm_client.complete(
            prompt=prompt,
            model="gpt-4o-mini",  # 使用成本较低的模型
            temperature=0.3,
            max_tokens=1000,
            timeout=10,
            retry=2
        )

        # 3. 解析并校验结果
        try:
            result = self._parse_analysis_result(llm_response)
            self._validate_result(result)
        except (JSONParseError, ValidationError) as e:
            # 降级：使用规则基础的简单分析
            result = self._fallback_analysis(content)
            logger.warning(f"LLM分析失败，降级为规则分析 note_id={note_id}: {e}")

        # 4. 知识点ID 匹配
        # 将 LLM 返回的知识点名称匹配到全局知识点库的 kp_id
        for kp in result.knowledge_points:
            kp_id = await self.kp_service.find_kp_by_name(
                kp.name, classification.subject_code
            )
            if kp_id:
                kp.kp_id = kp_id

        # 5. 笔记向量化和相似笔记查找
        embedding = await self.embedding_client.embed(content[:500])
        similar_notes = await self._find_similar_notes(
            note_id, user_profile.user_id, embedding, top_k=5
        )
        result.linked_notes = similar_notes

        # 6. 存储 embedding 到向量索引
        await self.vector_store.upsert(
            collection="note_embeddings",
            records=[{
                "id": note_id,
                "note_id": note_id,
                "user_id": user_profile.user_id,
                "subject_code": classification.subject_code,
                "embedding": embedding,
                "created_at": int(time.time())
            }]
        )

        return result

    async def _find_similar_notes(self, note_id: int, user_id: int,
                                   embedding: List[float], top_k: int = 5) -> List[LinkedNote]:
        """在同用户的笔记中查找语义相似的笔记"""
        results = await self.vector_store.search(
            collection="note_embeddings",
            query_vector=embedding,
            filter_expr=f"user_id == {user_id} and note_id != {note_id}",
            top_k=top_k,
            score_threshold=0.75  # 余弦相似度阈值
        )
        return [
            LinkedNote(note_id=r.id, similarity=r.score)
            for r in results
        ]

    def _fallback_analysis(self, content: str) -> AnalysisResult:
        """降级分析：不依赖 LLM 的规则分析"""
        word_count = len(content)
        return AnalysisResult(
            summary=content[:100] + "..." if word_count > 100 else content,
            quality_score=min(word_count // 5, 60),  # 简单基于字数
            quality_tags=["fallback_analyzed"],
            improvement_hints=[],
            knowledge_points=[]
        )
```

### 5.4 知识图谱构建管线（Graph Building Pipeline）

```python
class GraphBuildingPipeline:
    """
    从笔记中提取实体和关系，构建个人知识图谱。
    使用轻量级 NER 模型 + 规则匹配，不依赖 LLM（控制成本）。
    """

    def process(self, note_id: int, content: str, user_id: int,
                classification: ClassificationResult,
                analysis: AnalysisResult) -> GraphUpdate:
        # 1. 实体抽取
        entities = self._extract_entities(content, classification.subject_code)

        # 2. 利用深度分析结果补充实体
        if analysis.key_concepts:
            for concept in analysis.key_concepts:
                entities.add(concept)

        # 3. 实体写入/更新（upsert）
        entity_ids = []
        for entity_text in entities:
            entity = self.entity_repo.upsert(
                user_id=user_id,
                entity_text=entity_text,
                entity_type=self._classify_entity_type(entity_text, classification.subject_code),
                subject_code=classification.subject_code,
                note_id=note_id
            )
            entity_ids.append(entity.id)

        # 4. 关系抽取
        relations = self._extract_relations(content, entities, classification.subject_code)

        # 5. 补充隐式关系：同一篇笔记中出现的实体视为 "co_occurrence" 关系
        relations.extend(self._co_occurrence_relations(entity_ids, note_id))

        # 6. 关系写入
        for rel in relations:
            self.relation_repo.upsert(
                source_entity_id=rel.source,
                target_entity_id=rel.target,
                relation_type=rel.type,
                weight=rel.weight,
                evidence_note_ids=[note_id]
            )

        # 7. 更新图谱缓存
        self._invalidate_graph_cache(user_id)

        return GraphUpdate(
            new_entities=len(entities),
            new_relations=len(relations),
            entity_ids=entity_ids
        )

    def _extract_entities(self, content: str, subject_code: str) -> Set[str]:
        """使用学科专用 NER 模型 + 规则提取实体"""
        entities = set()

        # 方式1: 学科术语词典匹配
        terms = self.term_cache.get(subject_code, set())
        for term in terms:
            if term in content:
                entities.add(term)

        # 方式2: 轻量级 NER 模型（如 HanLP / LAC）
        ner_results = self.ner_model.recognize(content)
        for entity_text, entity_type in ner_results:
            if entity_type in ("CONCEPT", "TERMINOLOGY", "FORMULA"):
                entities.add(entity_text)

        # 方式3: 公式提取（LaTeX）
        formula_pattern = r'\$([^$]+)\$'
        formulas = re.findall(formula_pattern, content)
        entities.update(formulas)

        return entities

    def _extract_relations(self, content: str, entities: Set[str],
                           subject_code: str) -> List[Relation]:
        """基于模式规则提取实体间关系"""
        relations = []
        entity_list = list(entities)

        # 模式1: "A是B的C" / "A属于B"
        for src, tgt in itertools.combinations(entity_list, 2):
            if self._has_relation_pattern(content, src, tgt):
                relations.append(Relation(
                    source=src, target=tgt,
                    type="related", weight=0.7
                ))

        # 模式2: 前置依赖（基于全局知识点库的前置关系）
        for src, tgt in itertools.combinations(entity_list, 2):
            prereq = self.kp_service.check_prerequisite(src, tgt, subject_code)
            if prereq:
                relations.append(Relation(
                    source=src, target=tgt,
                    type="prerequisite", weight=0.9
                ))

        return relations
```

### 6.3 幂等与去重

```python
class PipelineOrchestrator:
    """
    管线编排器：管理事件消费和管线执行。
    确保幂等性：同一笔记不会被重复处理。
    """

    async def handle_note_created(self, event: NoteCreatedEvent):
        note_id = event.data["note_id"]

        # 获取分布式锁（防止并发处理）
        lock_key = f"note:pipeline:lock:{note_id}"
        acquired = await self.redis.set(lock_key, "processing", nx=True, ex=120)
        if not acquired:
            logger.info(f"笔记 {note_id} 正在处理中，跳过")
            return

        try:
            # 检查是否已处理过（幂等检查）
            existing = await self.analysis_repo.get(note_id)
            if existing and existing.analysis_status == "done" and not event.force:
                logger.info(f"笔记 {note_id} 已完成分析，跳过")
                return

            # 初始化分析记录
            await self.analysis_repo.upsert_status(note_id, "classifying")

            # 执行快速分类
            classification = await self.quick_pipeline.process(
                note_id=note_id,
                content=event.data["content"],
                context=NoteContext.from_event(event)
            )

            await self.analysis_repo.update_classification(note_id, classification)
            await self.analysis_repo.upsert_status(note_id, "analyzing")

            # 发布分类完成事件
            await self.event_bus.publish(NoteClassifiedEvent(
                note_id=note_id, **classification.dict()
            ))

            # 并行执行深度分析、卡片生成、图谱构建
            analysis_task = asyncio.create_task(
                self._run_deep_analysis(note_id, event, classification)
            )
            card_task = asyncio.create_task(
                self._run_card_generation(note_id, event, classification)
            )
            graph_task = asyncio.create_task(
                self._run_graph_building(note_id, event, classification)
            )

            # 等待全部完成
            results = await asyncio.gather(
                analysis_task, card_task, graph_task,
                return_exceptions=True
            )

            # 更新最终状态
            all_success = all(not isinstance(r, Exception) for r in results)
            await self.analysis_repo.upsert_status(
                note_id,
                "done" if all_success else "partial_done"
            )

        except Exception as e:
            logger.error(f"笔记分析失败 note_id={note_id}: {e}")
            await self.analysis_repo.upsert_status(
                note_id, "failed",
                error_code="PIPELINE_ERROR",
                error_msg=str(e)
            )
            # 投入重试队列（延迟60秒，最多重试3次）
            await self.retry_queue.enqueue(
                handler="note_analysis_retry",
                payload={"note_id": note_id},
                delay_seconds=60,
                max_retries=3
            )
        finally:
            await self.redis.delete(lock_key)
```

### 8.2 LLM 调用成本控制

```python
class LLMCostController:
    """
    LLM 调用成本控制策略：
    1. 使用成本较低的模型（gpt-4o-mini / glm-4-flash）
    2. 合并 Prompt（深度分析 + 卡片生成使用一次调用）
    3. 缓存分析结果（相似内容不重复调用）
    4. 按学段分级处理（小学笔记简化分析）
    5. 每日 LLM 调用预算限制
    """

    # 单次笔记分析的预估 Token 消耗
    TOKEN_ESTIMATES = {
        "deep_analysis": {
            "input": 800,   # prompt + 笔记内容
            "output": 400   # 分析结果 JSON
        },
        "card_generation": {
            "input": 600,
            "output": 300
        }
    }

    # 成本（USD / 1M tokens）参考
    COST_PER_MILLION = {
        "gpt-4o-mini": {"input": 0.15, "output": 0.60},
        "glm-4-flash": {"input": 0.10, "output": 0.10}  # 智谱 Flash 模型
    }

    def estimate_cost_per_note(self) -> float:
        """估算单条笔记的 LLM 成本"""
        model = "glm-4-flash"  # 默认使用国产低成本模型
        cost = 0
        for task, tokens in self.TOKEN_ESTIMATES.items():
            input_cost = tokens["input"] / 1_000_000 * self.COST_PER_MILLION[model]["input"]
            output_cost = tokens["output"] / 1_000_000 * self.COST_PER_MILLION[model]["output"]
            cost += input_cost + output_cost
        return cost  # 约 $0.0007/条 ≈ ¥0.005/条

    # 每日预算
    DAILY_BUDGET_YUAN = 50.0  # 约 10000 条笔记/天

    async def check_budget(self) -> bool:
        """检查今日 LLM 预算是否充足"""
        today_cost = await self.redis.incrbyfloat(
            f"note:llm:cost:{date.today()}", 0
        )
        return today_cost < self.DAILY_BUDGET_YUAN
```

## 9. 降级与容错策略

### 9.1 多级降级方案

```
正常模式：
  快速分类(规则+模型) → 深度分析(LLM) → 卡片生成(LLM) → 图谱构建(NER)

降级1 - LLM 不可用：
  快速分类(规则+模型) → 深度分析(规则降级) → 卡片生成(跳过) → 图谱构建(NER)
  - 深度分析降级为：基于关键词提取的简单摘要
  - 卡片生成标记为 "pending"，LLM 恢复后补偿处理
  - 通知客户端：智能分析部分功能暂时不可用

降级2 - 向量检索不可用：
  快速分类(规则) → 深度分析(LLM) → 卡片生成(LLM) → 图谱构建(跳过)
  - 相似笔记推荐暂时不可用
  - 图谱更新延后

降级3 - 全面故障（仅规则引擎可用）：
  快速分类(规则) → 写入基础分类 → 标记为 "rule_only"
  - 仅提供学科分类和基本统计
  - 待服务恢复后补偿分析
```

### 9.2 错误处理矩阵

| 错误场景 | 检测方式 | 处理策略 | 用户影响 |
|----------|----------|----------|----------|
| LLM 调用超时 | 10s 超时 | 重试1次→降级为规则分析 | 无摘要和卡片 |
| LLM 返回格式错误 | JSON 解析失败 | 重试1次→降级分析 | 降级质量 |
| 向量索引写入失败 | Milvus 异常 | 记录日志，延后重试 | 相似推荐不可用 |
| 向量检索失败 | Milvus 超时 | 跳过相似推荐 | 无相似笔记 |
| NER 模型加载失败 | 模型文件缺失 | 跳过图谱构建 | 图谱不更新 |
| 消息队列积压 | 队列深度 > 1000 | 降级为同步处理（限流） | 分析延迟增加 |
| 数据库写入失败 | DB 异常 | 重试3次→死信队列 | 分析结果可能丢失 |
| 全链路超时 | 120s 总超时 | 标记 failed，释放锁 | 需手动重新触发 |

### 9.3 补偿机制

```python
class CompensationJob:
    """
    定时补偿任务：处理因异常未完成分析的笔记。
    每小时执行一次。
    """

    async def run_hourly(self):
        # 1. 查找 status 为 failed 或分析超过 5 分钟仍在 pending 的笔记
        stuck_notes = await self.analysis_repo.find_stuck_notes(
            older_than_minutes=5,
            limit=100
        )

        for note_analysis in stuck_notes:
            try:
                await self.pipeline_orchestrator.reprocess(note_analysis.note_id)
            except Exception as e:
                logger.error(f"补偿处理失败 note_id={note_analysis.note_id}: {e}")

        # 2. 查找 LLM 不可用时跳过卡片生成的笔记，尝试补偿
        pending_cards = await self.analysis_repo.find_pending_cards(limit=50)
        for note_analysis in pending_cards:
            if await self.cost_controller.check_budget():
                await self.card_pipeline.process(
                    note_id=note_analysis.note_id,
                    content=note_analysis.content,
                    classification=note_analysis.classification,
                    analysis=note_analysis.analysis_result
                )
```

### 11.1 客户端轮询策略

笔记保存后，客户端需要获取分析结果。采用渐进式轮询：

```dart
// Flutter 客户端示例
class NoteAnalysisPoller {
  Timer? _timer;
  int _pollCount = 0;

  void startPolling(int noteId, Function(AnalysisResult) onComplete) {
    _pollCount = 0;
    _timer = Timer.periodic(Duration(seconds: 2), (timer) async {
      _pollCount++;

      final result = await api.get('/api/v1/notes/$noteId/analysis');

      if (result.data['analysisStatus'] == 'done' ||
          result.data['analysisStatus'] == 'partial_done') {
        timer.cancel();
        onComplete(AnalysisResult.fromJson(result.data));
      }

      // 超时停止轮询（30秒 = 15次）
      if (_pollCount >= 15) {
        timer.cancel();
        // 静默失败，不干扰用户
      }

      // 前 3 次快速轮询（2s），之后降为 5s
      if (_pollCount == 3) {
        timer.cancel();
        _timer = Timer.periodic(Duration(seconds: 5), (t) => _poll(noteId, onComplete, t));
      }
    });
  }
}
```

## 14. 安全与隐私

1. **数据隔离**：笔记内容和分析结果仅用户本人可见，不对外暴露原文。
2. **LLM 数据处理**：发送给 LLM 的笔记内容截断前 2000 字，不发送用户身份信息。
3. **向量数据**：笔记向量索引按 user_id 隔离，查询时强制带 user_id 过滤。
4. **缓存清理**：用户删除笔记时，同步删除分析结果、向量、卡片、图谱实体引用。
5. **合规**：笔记内容属于学生个人信息，遵循 PIPL（个人信息保护法）要求，数据导出和删除接口必须支持。

### 15.2 笔记质量评分标准

| 维度 | 权重 | 评分依据 |
|------|------|----------|
| 内容完整性 | 40% | 是否包含足够的知识点信息，不仅仅是碎片 |
| 结构清晰度 | 25% | 是否有逻辑层次（标题、列表、分段） |
