# 服务端 - 订单全生命周期健康管理与异常自愈引擎 - 详细设计

## 1. 概述

### 1.1 功能定位

本引擎是 PrimeTop 平台支付订单领域的**横切守护服务**，不负责订单的创建与正常流转（由支付服务、会员订阅服务处理），而是专注于：

1. **订单状态机统一管理**：为所有业务线（订阅会员、增值服务购买、积分兑换、优惠券购买）提供统一的订单状态模型与状态流转规则。
2. **异常订单自动检测**：通过定时巡检 + 实时事件监听，识别卡在中间态、数据不一致、回调丢失等异常订单。
3. **自愈策略执行**：对识别出的异常订单自动执行补偿操作（查询网关、补发回调、自动关单、自动退款等），减少人工干预。
4. **告警与升级**：自愈失败时触发告警并升级至人工处理队列。

### 1.2 适用范围

| 订单类型 | 说明 | 状态机版本 |
| --- | --- | --- |
| SUBSCRIPTION | 会员订阅订单（月度/年度/中考/高考专项） | v2 |
| ADDON | 增值服务订单（作文批改包、拍题次数包、题库训练包等） | v2 |
| POINTS_EXCHANGE | 积分商城兑换订单 | v1 |
| COUPON | 优惠券购买订单 | v1 |
| FAMILY_PLAN | 家庭多账号套餐订单 | v2 |

### 1.3 设计目标

| 指标 | 目标 |
| --- | --- |
| 异常订单发现延迟 | ≤ 5 分钟（实时事件）/ ≤ 30 分钟（定时巡检） |
| 自愈成功率 | ≥ 95%（无需人工介入） |
| 资金安全零误差 | 所有自动退款必须可追溯、可回滚 |
| 幂等保证 | 同一异常订单同一规则 24h 内最多执行一次自愈 |
| 审计完整性 | 所有自愈操作 100% 留存审计日志 |

## 2. 数据结构定义

### 2.1 统一订单状态枚举

```java
public enum OrderStatus {
    // ===== 初始状态 =====
    CREATED,                    // 订单已创建，待支付
    
    // ===== 支付中状态 =====
    PAYMENT_PENDING,            // 已调用支付网关，等待用户支付
    PAYMENT_PROCESSING,         // 支付网关回调处理中（已收到回调，正在处理）
    THREE_DS_VERIFYING,         // 3D Secure / 银行验证中
    
    // ===== 成功状态 =====
    PAID,                       // 支付成功，权益待发放
    FULFILLED,                  // 权益已发放，订单完成
    COMPLETED,                  // 订单终态：完成（含售后期满）
    
    // ===== 关闭/失败状态 =====
    CANCELLED,                  // 用户主动取消
    EXPIRED,                    // 超时未支付，系统自动关闭
    PAYMENT_FAILED,             // 支付网关返回失败
    REFUNDED,                   // 全额退款完成
    PARTIAL_REFUNDED,           // 部分退款完成
    
    // ===== 异常状态（自愈引擎关注的核心） =====
    GATEWAY_TIMEOUT,            // 调用网关超时，未知结果
    CALLBACK_LOST,             // 预期回调未到达
    STATE_INCONSISTENT,         // 本地状态与网关状态不一致
    FULFILL_FAILED,            // 支付成功但权益发放失败
    REFUND_STUCK,              // 退款发起后长时间未确认
    DUPLICATE_PAID,            // 同一订单被重复支付
    AMOUNT_MISMATCH            // 实付金额与订单金额不一致
}
```

## 4. 异常检测引擎设计

### 4.1 检测来源

| 来源 | 触发方式 | 延迟 | 适用场景 |
| --- | --- | --- | --- |
| REALTIME | 事件驱动（MQ 消费） | 秒级 | 状态变更即时校验 |
| SCHEDULED | 定时任务扫描 | 分钟级 | 中间态超时、卡单检测 |
| RECONCILIATION | 对账系统差异推送 | 小时级 | 金额不一致、遗漏订单 |

### 4.2 实时检测流程

```python
# 伪代码：实时异常检测消费者
class OrderAnomalyRealtimeDetector:
    
    def on_order_event(self, event: OrderEvent):
        """消费订单状态变更事件"""
        order = self.order_service.get_by_id(event.order_id)
        
        # 1. 验证状态流转合法性
        if not self.state_machine.is_valid_transition(
            event.from_status, event.to_status, order.order_type
        ):
            # 记录非法状态转换
            self.create_anomaly(order, "ILLEGAL_TRANSITION", {
                "from": event.from_status,
                "to": event.to_status
            })
            # 阻止状态写入
            return False
        
        # 2. 对新状态执行规则检测
        rules = self.rule_engine.get_rules_for_status(order.status)
        for rule in rules:
            if self.evaluate_condition(rule.detection_condition, order):
                self.create_anomaly(order, rule.anomaly_type, {
                    "rule_id": rule.id,
                    "source": "REALTIME"
                })
                # 触发自愈
                self.heal_executor.schedule(order, rule)
        
        # 3. 重复支付检测（特殊：需要查询历史订单）
        if event.to_status == "PAID":
            self.check_duplicate_payment(order)
        
        return True
```

class DuplicatePaymentDetector:
    
    def check(self, paid_order: Order):
        """检测同一用户的重复支付"""
        
        # 查找同一用户最近10分钟内同一类型的其他已支付订单
        related_orders = self.order_repo.find_related_paid_orders(
            user_id=paid_order.user_id,
            order_type=paid_order.order_type,
            time_window_seconds=600,
            exclude_order_id=paid_order.id
        )
        
        if not related_orders:
            return None
        
        # 场景1：同一商品重复购买（可能是误触）
        for related in related_orders:
            if (related.metadata.get("product_id") == 
                paid_order.metadata.get("product_id")):
                # 标记为重复支付，触发自动退款
                self.flag_duplicate(
                    primary_order=related,      # 第一笔（保留）
                    duplicate_order=paid_order,  # 第二笔（退款）
                    reason="SAME_PRODUCT_SAME_SESSION"
                )
                return "DUPLICATE_DETECTED"
        
        # 场景2：同一渠道流水号（更严重，可能是系统bug）
        for related in related_orders:
            if (related.channel == paid_order.channel and
                related.channel_order_no == paid_order.channel_order_no):
                self.flag_duplicate(
                    primary_order=related,
                    duplicate_order=paid_order,
                    reason="SAME_CHANNEL_TRANSACTION"
                )
                return "CHANNEL_DUPLICATE"
        
        return None

## 5. 自愈策略执行器

### 5.1 自愈动作类型

| 动作 | 说明 | 适用异常 |
| --- | --- | --- |
| `QUERY_GATEWAY` | 主动查询支付网关获取最新状态 | GATEWAY_TIMEOUT, CALLBACK_LOST |
| `RETRY_FULFILL` | 重试权益发放 | FULFILL_FAILED |
| `AUTO_CLOSE` | 自动关闭订单 | CREATED_TIMEOUT, EXPIRED |
| `AUTO_REFUND` | 自动发起退款 | DUPLICATE_PAID, AMOUNT_MISMATCH |
| `SYNC_STATUS` | 同步本地状态与网关状态 | STATE_INCONSISTENT |
| `FLAG_REVIEW` | 标记需人工审核（不自愈） | AMOUNT_MISMATCH |
| `RETRY_REFUND_QUERY` | 查询退款结果 | REFUND_STUCK |

### 5.2 自愈执行器核心逻辑

```java
/**
 * 订单异常自愈执行器
 */
@Service
public class OrderHealExecutor {
    
    @Autowired private OrderService orderService;
    @Autowired private PaymentGatewayFactory gatewayFactory;
    @Autowired private MembershipFulfillmentService fulfillmentService;
    @Autowired private RefundService refundService;
    @Autowired private OrderHealAuditLogRepository auditLogRepo;
    @Autowired private OrderAnomalyRepository anomalyRepo;
    
    private final ScheduledExecutorService scheduler = 
        Executors.newScheduledThreadPool(4, 
            new ThreadFactoryBuilder().setNameFormat("order-heal-%d").build());
    
    /**
     * 调度自愈任务
     */
    public void schedule(Order order, OrderHealRule rule) {
        AnomalyRecord anomaly = anomalyRepo.findActiveByOrderAndType(
            order.getId(), rule.getAnomalyType());
        
        if (anomaly == null || anomaly.getHealAttempt() >= rule.getMaxRetry()) {
            return;
        }
        
        // 冷却期检查
        if (isInCooldown(order.getId(), rule.getId(), rule.getCooldownSeconds())) {
            return;
        }
        
        // 延迟调度
        int delay = rule.getRetryIntervalSeconds() * anomaly.getHealAttempt();
        scheduler.schedule(() -> {
            executeHeal(order, anomaly, rule);
        }, delay, TimeUnit.SECONDS);
    }
    
    /**
     * 执行自愈动作
     */
    @Transactional
    public HealResult executeHeal(Order order, AnomalyRecord anomaly, 
                                   OrderHealRule rule) {
        long startTime = System.currentTimeMillis();
        HealResult result = new HealResult();
        
        try {
            // 更新异常状态为 HEALING
            anomaly.setStatus("HEALING");
            anomaly.setHealStartedAt(LocalDateTime.now());
            anomaly.incrementHealAttempt();
            anomalyRepo.save(anomaly);
            
            // 执行对应的自愈动作
            switch (rule.getHealAction()) {
                case "QUERY_GATEWAY":
                    result = executeQueryGateway(order, rule);
                    break;
                case "RETRY_FULFILL":
                    result = executeRetryFulfill(order, rule);
                    break;
                case "AUTO_CLOSE":
                    result = executeAutoClose(order, rule);
                    break;
                case "AUTO_REFUND":
                    result = executeAutoRefund(order, rule);
                    break;
                case "SYNC_STATUS":
                    result = executeSyncStatus(order, rule);
                    break;
                case "RETRY_REFUND_QUERY":
                    result = executeRefundQuery(order, rule);
                    break;
                default:
                    result = HealResult.unsupported(rule.getHealAction());
            }
            
            result.setDurationMs(System.currentTimeMillis() - startTime);
            
            // 记录审计日志
            auditLogRepo.save(buildAuditLog(anomaly, order, rule, result));
            
            // 更新异常状态
            if (result.isSuccess()) {
                anomaly.setStatus("HEALED");
                anomaly.setHealCompletedAt(LocalDateTime.now());
            } else if (anomaly.getHealAttempt() >= rule.getMaxRetry()) {
                // 达到最大重试次数，升级处理
                anomaly.setStatus("FAILED");
                escalate(anomaly, order, "MAX_RETRY_EXCEEDED");
            }
            anomalyRepo.save(anomaly);
            
        } catch (Exception e) {
            log.error("自愈执行异常 orderId={} ruleId={}", 
                order.getId(), rule.getId(), e);
            result = HealResult.error(e.getMessage());
            auditLogRepo.save(buildAuditLog(anomaly, order, rule, result));
        }
        
        return result;
    }
    
    /**
     * 动作：查询支付网关
     */
    private HealResult executeQueryGateway(Order order, OrderHealRule rule) {
        PaymentGateway gateway = gatewayFactory.get(order.getChannel());
        
        // 查询网关最新状态
        GatewayQueryResult queryResult = gateway.queryOrder(order.getChannelOrderNo());
        
        if (queryResult.isSuccess()) {
            // 网关显示已支付，更新订单状态
            if ("PAID".equals(queryResult.getTradeStatus())) {
                orderService.markPaid(order.getId(), queryResult);
                return HealResult.success("ORDER_MARKED_PAID");
            }
            // 网关显示未支付，关闭订单
            if ("NOT_PAID".equals(queryResult.getTradeStatus()) || 
                "CLOSED".equals(queryResult.getTradeStatus())) {
                orderService.markExpired(order.getId());
                return HealResult.success("ORDER_CLOSED");
            }
        }
        
        // 网关查询失败或状态仍不确定
        return HealResult.pending("GATEWAY_STATUS_UNKNOWN");
    }
    
    /**
     * 动作：重试权益发放
     */
    private HealResult executeRetryFulfill(Order order, OrderHealRule rule) {
        try {
            switch (order.getOrderType()) {
                case "SUBSCRIPTION":
                    fulfillmentService.grantSubscription(
                        order.getUserId(), 
                        order.getMetadata().get("plan_id"),
                        order.getId()
                    );
                    break;
                case "ADDON":
                    fulfillmentService.grantAddonPackage(
                        order.getUserId(),
                        order.getMetadata().get("product_id"),
                        order.getMetadata().get("quantity"),
                        order.getId()
                    );
                    break;
                case "POINTS_EXCHANGE":
                    fulfillmentService.grantPointsExchange(
                        order.getUserId(),
                        order.getMetadata().get("item_id"),
                        order.getId()
                    );
                    break;
                case "FAMILY_PLAN":
                    fulfillmentService.grantFamilyPlan(
                        order.getUserId(),
                        order.getMetadata().get("plan_id"),
                        order.getMetadata().get("child_count"),
                        order.getId()
                    );
                    break;
                default:
                    return HealResult.fail("UNKNOWN_ORDER_TYPE");
            }
            
            orderService.markFulfilled(order.getId());
            return HealResult.success("FULFILLMENT_COMPLETED");
            
        } catch (FulfillmentException e) {
            log.warn("权益发放重试失败 orderId={}", order.getId(), e);
            return HealResult.fail(e.getMessage());
        }
    }
    
    /**
     * 动作：自动退款（处理重复支付）
     */
    private HealResult executeAutoRefund(Order order, OrderHealRule rule) {
        // 安全检查：退款金额不能超过实付金额
        if (order.getPaidAmount() == null || 
            order.getPaidAmount().compareTo(BigDecimal.ZERO) <= 0) {
            return HealResult.fail("INVALID_PAID_AMOUNT");
        }
        
        // 幂等检查：是否已发起过退款
        if (refundService.hasPendingRefund(order.getId())) {
            return HealResult.pending("REFUND_ALREADY_PENDING");
        }
        
        RefundRequest refundRequest = RefundRequest.builder()
            .orderId(order.getId())
            .userId(order.getUserId())
            .amount(order.getPaidAmount())
            .reason("AUTO_HEAL_DUPLICATE_PAYMENT")
            .operator("SYSTEM")
            .build();
        
        RefundResult refundResult = refundService.autoRefund(refundRequest);
        
        if (refundResult.isAccepted()) {
            // 退款已被网关接受，等待确认
            orderService.markRefundPending(order.getId(), refundResult.getRefundNo());
            return HealResult.success("REFUND_SUBMITTED");
        } else {
            return HealResult.fail("REFUND_REJECTED: " + refundResult.getReason());
        }
    }
}
```

class EscalationManager:
    
    ESCALATION_RULES = [
        # (条件, 升级动作, 通知渠道)
        ("MAX_RETRY_EXCEEDED",    "CREATE_TICKET",   "SMS+EMAIL"),  # 自愈重试用尽
        ("HIGH_VALUE_ORDER",      "NOTIFY_MANAGER",  "SMS"),         # 高金额订单异常（>500元）
        ("BATCH_ANOMALY",         "ALERT_ALL",       "WEBHOOK"),     # 5分钟内同类型异常>10笔
        ("REFUND_FAILURE",        "CREATE_TICKET",   "EMAIL"),       # 自动退款失败
        ("AMOUNT_MISMATCH",       "CREATE_TICKET",   "EMAIL"),       # 金额不一致（需人工判断）
    ]
    
    def escalate(self, anomaly: AnomalyRecord, order: Order, trigger_reason: str):
        """升级异常订单到人工处理"""
        
        # 1. 确定升级动作
        escalation_action = self.determine_escalation(anomaly, order, trigger_reason)
        
        # 2. 创建客服工单
        if escalation_action == "CREATE_TICKET":
            ticket = self.ticket_service.create(
                title=f"[订单异常] {order.order_no} - {anomaly.anomaly_type}",
                description=self.build_ticket_description(anomaly, order),
                priority=self.calculate_priority(order),
                category="PAYMENT_ANOMALY",
                related_order_id=order.getId(),
                related_anomaly_id=anomaly.getId()
            )
            anomaly.setEscalatedTo(ticket.getId())
        
        # 3. 发送通知
        self.notify(anomaly, order, escalation_action)
        
        # 4. 更新异常状态
        anomaly.setStatus("ESCALATED")
        anomaly.setEscalatedAt(LocalDateTime.now())
        self.anomalyRepo.save(anomaly)
    
    def calculate_priority(self, order: Order) -> str:
        """根据订单金额计算优先级"""
        if order.getAmount().compareTo(BigDecimal.valueOf(500)) >= 0:
            return "P1"  # 紧急
        elif order.getAmount().compareTo(BigDecimal.valueOf(100)) >= 0:
            return "P2"  # 高
        else:
            return "P3"  # 普通
    
    def build_ticket_description(self, anomaly, order) -> str:
        return f"""
        订单号: {order.getOrderNo()}
        用户ID: {order.getUserId()}
        异常类型: {anomaly.getAnomalyType()}
        订单金额: ¥{order.getAmount()}
        支付渠道: {order.getChannel()}
        异常发现时间: {anomaly.getDetectedAt()}
        自愈尝试次数: {anomaly.getHealAttempt()}
        异常详情: {anomaly.getAnomalyDetail()}
        
        请核实订单状态并处理。
        """

/**
 * 批量补偿执行器 - 用于渠道故障恢复后批量处理积压异常

@Service
public class BatchCompensationExecutor {
    
    /**
     * 渠道恢复后批量补偿
     */
    public void compensateAfterRecovery(String channel) {
        // 1. 查询所有该渠道的积压异常订单
        List<AnomalyRecord> backlog = anomalyRepo.findPendingByChannel(channel);
        
        log.info("渠道 {} 恢复，开始批量补偿 {} 笔异常订单", channel, backlog.size());
        
        // 2. 分批并行执行（每批20笔，避免冲击网关）
        int batchSize = 20;
        for (int i = 0; i < backlog.size(); i += batchSize) {
            List<AnomalyRecord> batch = backlog.subList(i, 
                Math.min(i + batchSize, backlog.size()));
            
            CompletableFuture.runAsync(() -> {
                for (AnomalyRecord anomaly : batch) {
                    Order order = orderService.getById(anomaly.getOrderId());
                    OrderHealRule rule = ruleService.getById(anomaly.getHealRuleId());
                    healExecutor.executeHeal(order, anomaly, rule);
                }
            });
            
            // 批次间间隔2秒
            Thread.sleep(2000);
        }
    }
}

## 11. 安全与合规

### 11.1 资金安全保障

| 保障措施 | 实现方式 |
| --- | --- |
| 退款金额上限 | 单笔自动退款不超过 ¥2,000，超过需人工审批 |
| 日累计退款上限 | 自动退款日累计不超过 ¥50,000，超过暂停自愈 |
| 双写校验 | 所有自动退款同时记录到退款表和审计表，定时对账 |
| 操作回滚 | 自愈操作支持逆向回滚（除了已完成的网关退款） |
| 金额校验 | 退款前校验：退款金额 ≤ 实付金额 - 已退款金额 |

### 11.2 幂等控制

```java
/**
 * 自愈操作幂等控制
 */
@Component
public class HealIdempotencyControl {
    
    private final StringRedisTemplate redis;
    
    /**
     * 获取自愈执行锁（幂等）
     * @return true=获取成功可执行, false=已有在执行
     */
    public boolean tryAcquire(Long orderId, String ruleId) {
        String key = String.format("order_heal:lock:%d:%s", orderId, ruleId);
        // SETNX + TTL
        return Boolean.TRUE.equals(
            redis.opsForValue().setIfAbsent(key, 
                UUID.randomUUID().toString(), 
                Duration.ofSeconds(300))
        );
    }
    
    /**
     * 冷却期检查
     */
    public boolean isInCooldown(Long orderId, String ruleId, int cooldownSeconds) {
        String key = String.format("order_heal:cooldown:%d:%s", orderId, ruleId);
        return Boolean.TRUE.equals(redis.hasKey(key));
    }
    
    /**
     * 设置冷却期标记
     */
    public void markExecuted(Long orderId, String ruleId, int cooldownSeconds) {
        String key = String.format("order_heal:cooldown:%d:%s", orderId, ruleId);
        redis.opsForValue().set(key, Instant.now().toString(), 
            Duration.ofSeconds(cooldownSeconds));
    }
}
```

## 14. 边界场景与注意事项

### 14.1 边界场景

| 场景 | 处理方式 |
| --- | --- |
| 用户在自愈执行过程中主动取消订单 | 自愈任务通过乐观锁检测状态变更，若状态已变则中止 |
| 渠道网关返回的结果与实际不一致 | 以渠道查询结果为准但标记需对账，同时触发对账流程 |
| 并发触发同一订单的自愈 | 通过 Redis 分布式锁保证同一订单同一规则只有一个执行实例 |
| 自愈服务重启时正在执行的怎么办 | 重启后定时巡检会重新发现这些异常并重新调度 |
| 跨时区订单的处理 | 所有时间以服务端 UTC+8 为准，订单创建时记录时区 |
| Apple/Google 内购的特殊性 | 回调延迟较大（可能数小时），为这类渠道单独配置更长的超时阈值 |
| 部分退款后的状态一致性 | 部分退款后订单状态为 PARTIAL_REFUNDED，不自动关单 |

### 14.2 注意事项

1. **不要自愈终态订单**：COMPLETED、CANCELLED、EXPIRED、REFUNDED 等终态订单不参与自愈。
2. **金额一致性优先**：在执行任何涉及金额变动的自愈动作前，必须校验金额一致性。
3. **审计日志不可删改**：`order_heal_audit_logs` 表为追加写入，不允许修改或删除。
4. **规则变更热生效**：通过配置中心推送规则变更，无需重启服务。
5. **跨服务事务**：涉及支付和权益的操作采用最终一致性（Saga 模式），自愈引擎负责补偿。
