# 用户流失预警与智能挽留策略引擎 - 详细设计

## 1. 模块概述

### 1.1 定位与目标

本模块负责从多维度用户行为数据中识别潜在的流失风险用户，通过规则引擎与统计模型相结合的方式计算流失风险评分，并自动触发个性化的挽留干预策略（消息推送、权益激励、功能引导等），同时追踪干预效果，形成"识别→干预→评估→优化"的闭环。

**与"学生学习风险评估"的区别：**
- 学生学习风险评估：关注学习效果（知识点掌握度、成绩下滑），触发的是学习辅导类干预
- 用户流失预警：关注用户粘性与活跃度（登录频次、功能使用广度、使用时长趋势），触发的是运营挽留类干预

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 用户生命周期阶段判定 | 新增→活跃→衰退→沉默→流失，五阶段自动流转 |
| 多维流失风险评分 | 综合登录、学习、互动、付费等多维信号计算风险分 |
| 流失预警规则引擎 | 可配置规则 + 统计阈值 + 趋势分析三层判定 |
| 挽留策略编排 | 按风险等级、用户画像、生命周期阶段匹配干预动作 |
| 干预效果归因 | 追踪每次干预后用户行为变化，评估策略ROI |
| 管理后台 | 规则配置、策略管理、效果看板、手动干预 |

## 3. 核心算法

### 3.1 用户参与度评分（Engagement Score）

综合多个维度计算用户当前的参与度，范围 0-100，分越高越活跃。

```python
def compute_engagement_score(features: UserBehaviorFeature) -> float:
    """
    多维加权参与度评分

    权重分配:
    - 登录维度: 20%
    - 学习维度: 35%
    - 功能使用维度: 20%
    - 互动维度: 15%
    - 趋势维度: 10%
    """
    # ── 登录维度 (0-20分) ──
    login_score = min(20.0,
        features.login_days_last_7d * 2.0  # 每天登录+2分，7天满分14
        + min(6.0, max(0, 7 - features.login_interval_avg_7d))  # 登录间隔越小分越高
    )

    # ── 学习维度 (0-35分) ──
    # 近7天学习时长映射 (每天30分钟为满分)
    learning_time_score = min(20.0, features.learning_minutes_last_7d / 30.0 * 20.0 / 7.0)
    learning_freq_score = min(10.0, features.learning_sessions_last_7d * 1.5)
    learning_recency = min(5.0, max(0, 5 - features.days_since_last_learning))
    learning_score = learning_time_score + learning_freq_score + learning_recency

    # ── 功能使用维度 (0-20分) ──
    feature_breadth = min(8.0, features.features_used_last_7d * 1.5)  # 功能种类广度
    ai_usage = min(6.0, features.ai_questions_last_7d * 0.5)
    photo_usage = min(3.0, features.photo_search_last_7d * 0.5)
    exercise_usage = min(3.0, features.exercise_count_last_7d * 0.3)
    feature_score = feature_breadth + ai_usage + photo_usage + exercise_usage

    # ── 互动维度 (0-15分) ──
    plan_score = min(8.0, features.plan_completion_rate_7d * 8.0)
    checkin_score = min(4.0, features.checkin_days_last_7d * 0.6)
    feedback_score = min(3.0, features.feedback_given_last_30d * 0.5)
    interaction_score = plan_score + checkin_score + feedback_score

    # ── 趋势维度 (0-10分) ──
    trend_score = 5.0  # 基准分
    if features.learning_minutes_trend_7d_vs_prev > 0.2:
        trend_score += 3.0  # 学习时长增长
    elif features.learning_minutes_trend_7d_vs_prev < -0.3:
        trend_score -= 4.0  # 学习时长显著下降
    if features.login_days_trend_7d_vs_prev > 0.1:
        trend_score += 2.0
    elif features.login_days_trend_7d_vs_prev < -0.3:
        trend_score -= 3.0
    trend_score = max(0.0, min(10.0, trend_score))

    total = login_score + learning_score + feature_score + interaction_score + trend_score
    return round(max(0.0, min(100.0, total)), 2)
```

### 3.2 流失风险评分（Churn Risk Score）

风险评分范围 0-100，分越高流失风险越大。与参与度评分互为镜像但不完全对称。

```python
def compute_churn_risk_score(
    features: UserBehaviorFeature,
    lifecycle: UserLifecycleRecord,
    triggered_rule_contributions: list[float],
) -> tuple[float, dict]:
    """
    综合流失风险评分

    三层模型:
    1. 基础分 (基于参与度的逆向映射)
    2. 规则加分 (触发的预警规则贡献)
    3. 生命周期修正

    Returns: (risk_score, risk_factors)
    """
    risk_factors = {}

    # ── 第1层: 基础分 (参与度的逆向映射) ──
    # 参与度 0→风险100, 参与度 100→风险 0
    # 使用非线性映射，让中间区域更敏感
    engagement = features.engagement_score
    base_risk = 100.0 * (1.0 - engagement / 100.0) ** 1.3
    risk_factors["base_risk"] = round(base_risk, 2)

    # ── 第2层: 规则加分 ──
    rule_contribution = sum(triggered_rule_contributions)
    rule_contribution = min(rule_contribution, 30.0)  # 规则贡献上限30分
    risk_factors["rule_contribution"] = round(rule_contribution, 2)

    # ── 第3层: 生命周期修正 ──
    lifecycle_modifier = 0.0
    if lifecycle.stage == UserLifecycleStage.NEW:
        lifecycle_modifier = -5.0  # 新用户有蜜月期
    elif lifecycle.stage == UserLifecycleStage.DECLINING:
        lifecycle_modifier = 10.0  # 明确衰退，加分
    elif lifecycle.stage == UserLifecycleStage.DORMANT:
        lifecycle_modifier = 20.0  # 沉默用户，大幅加分
    risk_factors["lifecycle_modifier"] = lifecycle_modifier

    # ── 付费用户修正 ──
    paid_modifier = 0.0
    if features.is_paid_user and features.days_to_expiry is not None:
        if features.days_to_expiry <= 7:
            paid_modifier = 15.0  # 即将到期，流失风险高
        elif features.days_to_expiry <= 30:
            paid_modifier = 5.0
    if features.has_ever_paid and not features.is_paid_user:
        paid_modifier = 10.0  # 曾付费现已过期，易流失
    risk_factors["paid_modifier"] = paid_modifier

    # ── 综合计算 ──
    total_risk = base_risk + rule_contribution + lifecycle_modifier + paid_modifier
    total_risk = max(0.0, min(100.0, total_risk))

    return round(total_risk, 2), risk_factors
```

```python
    },
    UserLifecycleStage.DORMANT: {
        "to_reactivated": lambda f, lc: f.days_since_last_login == 0 and f.login_days_last_7d >= 2,
        "to_churned": lambda f, lc: f.days_since_last_login >= 30,
    },
    UserLifecycleStage.REACTIVATED: {
        "to_active": lambda f, lc: (
            f.login_days_last_7d >= 3 and
            f.learning_sessions_last_7d >= 2
        ),
        "to_declining": lambda f, lc: f.engagement_score < 40,
        "to_dormant": lambda f, lc: f.days_since_last_login >= 7,
    },
    # 流失用户仅通过手动标记或特殊回流活动恢复
}

def evaluate_lifecycle_transition(
    current_stage: str,
    features: UserBehaviorFeature,
    lifecycle: UserLifecycleRecord,
) -> str | None:
    """评估是否应发生阶段流转，返回目标阶段或None"""
    transitions = LIFECYCLE_TRANSITIONS.get(current_stage, {})
    for target_stage_name, condition_fn in transitions.items():
        if condition_fn(features, lifecycle):
            return target_stage_name.replace("to_", "")  # 提取阶段名
    return None
```

```python
@celery_app.task(
    name="churn.compute_daily_features",
    queue="batch",
    max_retries=2,
    time_limit=7200,  # 2小时
)
def compute_daily_features(snapshot_date: str | None = None):
    """
    计算全量用户行为特征快照

    流程:
    1. 从 ClickHouse 聚合用户行为数据
    2. 从 MySQL 查询付费信息
    3. 计算参与度评分
    4. 写入 user_behavior_feature 表
    """
    date = parse_date(snapshot_date) or date.today() - timedelta(days=1)

    # 分批处理，避免内存溢出
    batch_size = 5000
    offset = 0
    processed = 0

    while True:
        user_ids = get_active_user_ids_batch(offset, batch_size, lookback_days=60)
        if not user_ids:
            break

        # 从 ClickHouse 聚合行为数据
        behavior_data = clickhouse_client.query("""
            SELECT
                user_id,
                countDistinctIf(event_time >= now() - INTERVAL 7 DAY) as login_days_7d,
                countDistinctIf(event_time >= now() - INTERVAL 14 DAY) as login_days_14d,
                countDistinctIf(event_time >= now() - INTERVAL 30 DAY) as login_days_30d,
                -- ... 更多聚合字段
            FROM user_event_log
            WHERE user_id IN :user_ids
              AND event_date >= :start_date
            GROUP BY user_id
        """, parameters={
            "user_ids": user_ids,
            "start_date": date - timedelta(days=30),
        })

        # 查询付费信息
        paid_info = get_paid_user_info_batch(user_ids)

        # 计算特征并批量写入
        features_batch = []
        for row in behavior_data:
            feature = build_feature_from_row(row, paid_info.get(row.user_id))
            feature.engagement_score = compute_engagement_score(feature)
            features_batch.append(feature)

        bulk_upsert_features(features_batch)
        processed += len(features_batch)
        offset += batch_size

    logger.info("compute_daily_features completed", extra={
        "snapshot_date": str(date),
        "processed_users": processed,
    })
```

### 5.3 风险评估任务

```python
@celery_app.task(
    name="churn.evaluate_churn_risk",
    queue="batch",
    max_retries=2,
    time_limit=3600,
)
def evaluate_churn_risk():
    """
    每日流失风险评估

    流程:
    1. 加载所有活跃规则
    2. 遍历用户特征快照
    3. 评估每条规则
    4. 计算综合风险评分
    5. 生成预警事件（风险分较前日上升超过阈值时）
    """
    rules = load_active_rules()
    features_list = load_today_features()
    previous_scores = load_previous_risk_scores()

    new_alerts = []

    for features in features_list:
        lifecycle = get_lifecycle(features.user_id)

        # 评估规则
        triggered = []
        contributions = []
        for rule in rules:
            if evaluate_rule(rule, features, lifecycle):
                triggered.append(rule.rule_code)
                contributions.append(rule.risk_contribution)
                increment_rule_trigger_count(rule.id)

        # 计算风险分
        risk_score, risk_factors = compute_churn_risk_score(
            features, lifecycle, contributions
        )

        # 更新生命周期记录中的风险分
        update_lifecycle_risk_score(features.user_id, risk_score)

        # 判断是否需要生成预警（风险分上升超过阈值或首次进入高风险区间）
        prev_score = previous_scores.get(features.user_id, 0.0)
        risk_level = classify_risk_level(risk_score)

        should_alert = (
            (risk_score - prev_score >= 10.0) or  # 单日上升超过10分
            (risk_level in ("high", "critical") and
             classify_risk_level(prev_score) not in ("high", "critical"))  # 新进入高风险
        )

        if should_alert:
            alert = ChurnAlertEvent(
                user_id=features.user_id,
                alert_level=risk_level,
                risk_score=risk_score,
                risk_factors=risk_factors,
                triggered_rules=triggered,
                previous_risk_score=prev_score,
                score_change=risk_score - prev_score,
            )
            new_alerts.append(alert)

    # 批量写入预警
    if new_alerts:
        bulk_insert_alerts(new_alerts)
        logger.info("Generated churn alerts", extra={"count": len(new_alerts)})


def classify_risk_level(score: float) -> str:
    if score >= 85:
        return "critical"
    elif score >= 70:
        return "high"
    elif score >= 50:
        return "medium"
    else:
        return "low"
```

```python
@celery_app.task(
    name="churn.dispatch_interventions",
    queue="default",
    max_retries=2,
    time_limit=3600,
)
def dispatch_interventions():
    """
    遍历待干预的预警事件，匹配最佳挽留策略并执行
    """
    pending_alerts = get_pending_alerts_ordered_by_risk()

    for alert in pending_alerts:
        # 查找匹配的策略
        strategies = find_matching_strategies(
            lifecycle_stage=get_lifecycle_stage(alert.user_id),
            risk_level=alert.alert_level,
            user_tags=get_user_tags(alert.user_id),
        )

        if not strategies:
            alert.intervention_status = "resolved"  # 无匹配策略，标记为已处理
            continue

        # 检查冷却期与频率限制
        eligible_strategies = filter_by_cooldown_and_frequency(
            strategies, alert.user_id
        )

        if not eligible_strategies:
            continue

        # 选择最高优先级策略
        best_strategy = max(eligible_strategies, key=lambda s: s.priority)

        # 执行干预
        execute_intervention(alert, best_strategy)


def execute_intervention(alert: ChurnAlertEvent, strategy: RetentionStrategy):
    """执行单个干预动作"""
    intervention = RetentionIntervention(
        user_id=alert.user_id,
        alert_event_id=alert.id,
        strategy_id=strategy.id,
        strategy_name=strategy.name,
        strategy_type=strategy.strategy_type,
        strategy_config=strategy.strategy_params,
        status="executing",
    )

    try:
        # 根据策略类型分发
        handler = STRATEGY_HANDLERS[strategy.strategy_type]
        handler(intervention)
        intervention.status = "completed"
        intervention.completed_at = datetime.utcnow()

        alert.intervention_status = "intervened"
        alert.intervention_id = intervention.id
        alert.intervention_dispatched_at = datetime.utcnow()

        # 更新策略统计
        strategy.total_dispatched += 1

    except Exception as e:
        intervention.status = "failed"
        intervention.error_message = str(e)
        logger.error("Intervention execution failed", extra={
            "intervention_id": intervention.id,
            "strategy_id": strategy.id,
            "error": str(e),
        })

    db.session.add(intervention)
    db.session.commit()
```

```python
@celery_app.task(name="churn.track_intervention_effect")
def track_intervention_effect():
    """
    追踪干预后 7/14/30 天的用户行为变化

    每日执行，检查到达观测窗口期的干预记录
    """
    now = datetime.utcnow()

    # 7天窗口
    interventions_7d = get_interventions_needing_tracking(window_days=7)
    for intervention in interventions_7d:
        features = get_latest_feature(intervention.user_id)
        intervention.user_active_after_7d = features.login_days_last_7d >= 1
        intervention.learning_minutes_after_7d = features.learning_minutes_last_7d

        # 判断干预是否有效（用户重新活跃）
        if intervention.user_active_after_7d:
            intervention.effectiveness_tracked = True
            strategy = get_strategy(intervention.strategy_id)
            strategy.total_effective += 1

    # 14天窗口
    interventions_14d = get_interventions_needing_tracking(window_days=14)
    for intervention in interventions_14d:
        features = get_latest_feature(intervention.user_id)
        intervention.user_active_after_14d = features.login_days_last_7d >= 2

    # 30天窗口
    interventions_30d = get_interventions_needing_tracking(window_days=30)
    for intervention in interventions_30d:
        features = get_latest_feature(intervention.user_id)
        intervention.user_active_after_30d = features.login_days_last_7d >= 2
        intervention.subscribed_after = check_subscribed_after(intervention)

        # 最终标记
        intervention.effectiveness_tracked = True

        # 更新策略效果率
        strategy = get_strategy(intervention.strategy_id)
        if strategy.total_dispatched > 0:
            strategy.effectiveness_rate = (
                strategy.total_effective / strategy.total_dispatched
            )

    db.session.commit()
```

```python
EVENT_SUBSCRIPTIONS = {

def on_user_login(event: DomainEvent):
    """用户登录事件 → 实时更新参与度特征"""
    update_feature_realtime(
        user_id=event.user_id,
        updates={"days_since_last_login": 0},
        increment={"login_days_last_7d": 1},
    )

    # 回流用户处理
    lifecycle = get_lifecycle(event.user_id)
    if lifecycle.stage in (UserLifecycleStage.DORMANT, UserLifecycleStage.CHURNED):
        # 标记回流
        transition_lifecycle(event.user_id, UserLifecycleStage.REACTIVATED)
        # 设置欢迎回来标记
        set_welcome_back_flag(event.user_id, lifecycle.stage_duration_days)


def on_subscription_expiring(event: DomainEvent):
    """会员即将到期 → 触发专项预警"""
    create_or_upgrade_alert(
        user_id=event.user_id,
        alert_type="subscription_expiring",
        extra_risk=12.0,
        metadata={"days_to_expiry": event.days_to_expiry},
    )
```

## 10. 缓存策略

### 10.1 缓存层设计

| 数据 | 缓存键 | TTL | 说明 |
|------|--------|-----|------|
| 用户生命周期状态 | `churn:lifecycle:{user_id}` | 24h | 每日计算后更新 |
| 用户风险评分 | `churn:risk:{user_id}` | 24h | 每日计算后更新 |
| 行为特征快照 | `churn:feature:{user_id}` | 24h | 每日计算后更新 |
| 用户干预冷却期 | `churn:cooldown:{user_id}` | 动态TTL | 按策略配置的冷却期 |
| 规则列表 | `churn:rules:active` | 10min | 规则变更后主动失效 |
| 策略列表 | `churn:strategies:active` | 10min | 策略变更后主动失效 |
| 效果看板数据 | `churn:dashboard:{period}` | 30min | 查询时懒加载 |

### 10.2 缓存更新策略

- **定时批量更新**：每日计算任务完成后，批量刷新所有用户的缓存
- **事件驱动更新**：用户登录、学习等实时事件触发增量更新
- **主动失效**：管理后台修改规则/策略后，主动清除相关缓存

## 11. 错误处理

### 11.1 错误码段

| 错误码段 | 模块 |
|---------|------|
| 74000-74099 | 流失风险评估 |
| 74100-74199 | 生命周期管理 |
| 74200-74299 | 干预调度 |
| 74300-74399 | 策略执行 |

### 11.2 核心错误码

| 错误码 | 说明 | 处理策略 |
|--------|------|---------|
| 74001 | 特征数据不足（新用户无足够行为数据） | 跳过计算，使用默认低风险值 |
| 74002 | 规则表达式解析失败 | 记录日志，跳过该规则，降级为基础评分 |
| 74101 | 生命周期流转冲突（并发更新） | 乐观锁重试，最多3次 |
| 74201 | 无匹配策略 | 标记预警为resolved，记录未干预原因 |
| 74202 | 干预冷却期内 | 跳过本次干预 |
| 74301 | 推送服务调用失败 | 重试1次，仍失败则标记为failed |
| 74302 | 权益发放失败 | 回滚干预状态，记录失败原因 |
| 74303 | 家长未绑定 | 跳过parent_notify类型，降级为push |

### 11.3 降级策略

| 场景 | 降级方案 |
|------|---------|
| ClickHouse 不可用 | 使用 MySQL 事件表聚合（性能下降但可用） |
| 规则引擎异常 | 仅使用基础评分（参与度逆向映射） |
| 消息推送服务不可用 | 干预入队等待，标记为pending，服务恢复后重试 |
| 全量计算超时 | 分批计算，优先处理高风险用户 |
