## 1. 模块概述

### 1.1 功能定位

学习数据实时聚合与统计预计算引擎（Learning Statistics Aggregation Engine，简称 LSAE）是 PrimeTop 的**统计计算基础设施**，位于学习行为记录（LRPS）与上层分析展示（学情分析、首页工作台、学习报告）之间。它负责将海量的细粒度学习行为事件实时或准实时地聚合为可供直接查询的统计指标，避免上层模块每次请求都回溯原始日志进行全量计算。

### 1.2 核心问题

| 问题 | 说明 |
|------|------|
| 实时性 | 首页工作台需要秒级展示"今日学习XX分钟、完成XX题"，不能依赖离线批处理 |
| 高并发 | 高峰期数十万活跃用户同时查看统计数据，直接查询原始日志不可行 |
| 多维度 | 同一份行为数据需要按日/周/月、按学科、按模块、按知识点等多个维度聚合 |
| 一致性 | 离线上报数据可能延迟数小时到达，需要回溯更新已聚合的统计 |
| 成本 | 原始日志量巨大（日增千万级），频繁全量扫描消耗大量计算资源 |

### 1.3 设计目标

| 指标 | 目标值 |
|------|--------|
| 实时计数器写入延迟 | ≤ 50ms（P99） |
| 统计快照查询延迟 | ≤ 100ms（P99） |
| 离线上报数据回溯窗口 | T-7 天内可自动修正 |
| 日聚合批处理耗时 | ≤ 30min（百万DAU规模） |
| 预计算统计表存储膨胀 | 原始日志量的 ≤ 5% |

                    │        原始事件写入               │

                    └───────────┬─────────────────────┘

                    │  日终批处理写入（分钟级）           │

### 2.2 数据流路径

| 场景 | 数据源 | 路径 | 延迟 |
|------|--------|------|------|

## 3. 数据结构设计

### 3.1 Redis 实时计数器

#### 3.1.1 Key 命名规范

```
stat:{user_id}:{date}:{metric}
```

- `{date}` 格式：`yyyyMMdd`（如 `20260523`）
- Key 过期策略：创建后 **8 天**（覆盖回溯窗口 + 1天 buffer）

#### 3.1.2 计数器指标定义

| metric | Redis 类型 | 说明 | 写入时机 |
|--------|-----------|------|----------|
| `study_time` | String (int) | 学习时长（秒） | 每次 session 结束 / 心跳上报 |
| `question_count` | String (int) | 答题总数 | 答题行为写入时 |
| `correct_count` | String (int) | 正确数 | 答题行为写入时（is_correct=1） |
| `ai_chat_count` | String (int) | AI 对话次数 | AI 问答行为写入时 |
| `photo_solve_count` | String (int) | 拍题次数 | 拍题行为写入时 |
| `chapter_completed` | Set | 已完成章节ID集合 | 章节进度达到100%时 |
| `active_modules` | HyperLogLog | 活跃模块去重计数 | 任意行为写入时 |
| `study_sessions` | String (int) | 学习会话数 | session 开始时 |
| `mistake_added` | String (int) | 新增错题数 | 错题收录行为写入时 |
| `mistake_reviewed` | String (int) | 复习错题数 | 错题复习行为写入时 |

#### 3.1.3 学科维度计数器

对于需要按学科拆分的指标，使用 Hash 类型：

```
stat:{user_id}:{date}:subject_time  → Hash
  field: MATH    → 1200  (秒)
  field: CHINESE → 900
  field: ENGLISH → 600

stat:{user_id}:{date}:subject_questions  → Hash
  field: MATH    → 15
  field: CHINESE → 10
  field: ENGLISH → 8

stat:{user_id}:{date}:subject_correct  → Hash
  field: MATH    → 12
  field: CHINESE → 8
  field: ENGLISH → 7
```

#### 3.1.4 连续天数计数器

```
streak:{user_id}  → String (int)
  值：连续学习天数
  过期：永不过期（由服务管理）
  每日首次学习时更新
```

辅助 Key：

```
streak:{user_id}:last_date  → String
  值：最近一次有学习行为的日期 yyyyMMdd
  过期：永不过期
```

## 4. 核心流程设计

### 4.1 实时计数器更新流程

事件写入时同步更新 Redis 计数器，与 LRPS 事件写入在同一事务内。

```python
# aggregation/realtime_counter.py

import redis
from datetime import date
from typing import Optional

class RealtimeCounter:
    """实时统计计数器"""

    def __init__(self, redis_client: redis.Redis):
        self.r = redis_client
        self._today = date.today().strftime("%Y%m%d")

    def _key(self, user_id: int, metric: str) -> str:
        return f"stat:{user_id}:{self._today}:{metric}"

    def _subject_key(self, user_id: int, metric: str) -> str:
        return f"stat:{user_id}:{self._today}:{metric}"

    def incr_study_time(self, user_id: int, seconds: int) -> None:
        """累加学习时长"""
        key = self._key(user_id, "study_time")
        pipe = self.r.pipeline()
        pipe.incrby(key, seconds)
        pipe.expire(key, 8 * 86400)  # 8天过期
        pipe.execute()

    def incr_subject_time(self, user_id: int, subject_code: str, seconds: int) -> None:
        """累加学科学习时长"""
        key = self._subject_key(user_id, "subject_time")
        pipe = self.r.pipeline()
        pipe.hincrby(key, subject_code, seconds)
        pipe.expire(key, 8 * 86400)
        pipe.execute()

    def record_answer(self, user_id: int, subject_code: str,
                      is_correct: bool) -> None:
        """记录一次答题"""
        pipe = self.r.pipeline()
        
        # 总计数
        pipe.incrby(self._key(user_id, "question_count"), 1)
        if is_correct:
            pipe.incrby(self._key(user_id, "correct_count"), 1)
        
        # 学科计数
        q_key = self._subject_key(user_id, "subject_questions")
        c_key = self._subject_key(user_id, "subject_correct")
        pipe.hincrby(q_key, subject_code, 1)
        if is_correct:
            pipe.hincrby(c_key, subject_code, 1)
        
        # 设置过期
        for k in [q_key, c_key]:
            pipe.expire(k, 8 * 86400)
        
        pipe.execute()

    def incr_module_count(self, user_id: int, module: str) -> None:
        """记录模块使用次数"""
        key = self._key(user_id, f"{module}_count")
        pipe = self.r.pipeline()
        pipe.incrby(key, 1)
        pipe.expire(key, 8 * 86400)
        pipe.execute()

    def record_active_module(self, user_id: int, module: str) -> None:
        """记录活跃模块（HyperLogLog 去重）"""
        key = self._key(user_id, "active_modules")
        pipe = self.r.pipeline()
        pipe.pfadd(key, module)
        pipe.expire(key, 8 * 86400)
        pipe.execute()

    def add_completed_chapter(self, user_id: int, chapter_id: int) -> None:
        """记录完成章节（Set 去重）"""
        key = self._key(user_id, "chapter_completed")
        pipe = self.r.pipeline()
        pipe.sadd(key, chapter_id)
        pipe.expire(key, 8 * 86400)
        pipe.execute()

    def update_streak(self, user_id: int) -> int:
        """更新连续学习天数，返回当前连续天数"""
        streak_key = f"streak:{user_id}"
        last_date_key = f"streak:{user_id}:last_date"
        today_str = self._today

        # Lua 脚本保证原子性
        lua_script = """
        local streak_key = KEYS[1]
        local last_date_key = KEYS[2]
        local today = ARGV[1]
        
        local last_date = redis.call('GET', last_date_key)
        
        if last_date == today then
            -- 今天已更新过
            return tonumber(redis.call('GET', streak_key))
        end
        
        redis.call('SET', last_date_key, today)
        
        if last_date == nil then
            -- 首次
            redis.call('SET', streak_key, 1)
            return 1
        end
        
        -- 检查昨天是否有学习（允许1天gap）
        local yesterday = ARGV[2]
        if last_date == yesterday then
            -- 连续
            return redis.call('INCR', streak_key)
        else
            -- 断了，重新计数
            redis.call('SET', streak_key, 1)
            return 1
        end
        """
        
        from datetime import timedelta
        yesterday = (date.today() - timedelta(days=1)).strftime("%Y%m%d")
        
        return self.r.eval(
            lua_script, 2,
            streak_key, last_date_key,
            today_str, yesterday
        )

    def get_today_summary(self, user_id: int) -> dict:
        """获取今日实时统计概要"""
        pipe = self.r.pipeline()
        
        keys = {
            "study_time": self._key(user_id, "study_time"),
            "question_count": self._key(user_id, "question_count"),
            "correct_count": self._key(user_id, "correct_count"),
            "ai_chat_count": self._key(user_id, "ai_chat_count"),
            "photo_solve_count": self._key(user_id, "photo_solve_count"),
            "study_sessions": self._key(user_id, "study_sessions"),
            "mistake_added": self._key(user_id, "mistake_added"),
            "mistake_reviewed": self._key(user_id, "mistake_reviewed"),
        }
        
        for key in keys.values():
            pipe.get(key)
        
        pipe.pfcount(self._key(user_id, "active_modules"))
        pipe.scard(self._key(user_id, "chapter_completed"))
        pipe.get(f"streak:{user_id}")
        
        results = pipe.execute()
        
        values = {}
        for name, result in zip(keys.keys(), results[:len(keys)]):
            values[name] = int(result) if result else 0
        
        values["active_modules"] = results[len(keys)] or 0
        values["chapter_completed"] = results[len(keys) + 1] or 0
        values["streak_days"] = int(results[len(keys) + 2]) if results[len(keys) + 2] else 0
        
        # 计算正确率
        if values["question_count"] > 0:
            values["accuracy_rate"] = round(
                values["correct_count"] / values["question_count"], 4
            )
        else:
            values["accuracy_rate"] = None
        
        return values

## 5. 日终批处理（Daily Batch Aggregation）

### 5.1 批处理总览

日终批处理在每日凌晨 `02:00 CST` 由 Celery Beat 触发，扫描前一天的原始学习日志，生成日统计快照并写入 MySQL。

```
┌──────────────────────────────────────────────────────────┐
│  Celery Beat 触发 (每日 02:00)                           │
│       │                                                  │
│       ▼                                                  │
│  daily_aggregation_task(date=yesterday)                  │
│       │                                                  │
│       ├─── Step 1: 扫描活跃用户列表                      │
│       ├─── Step 2: 分片处理（按 user_id % N）             │
│       │      │                                           │
│       │      ├── 聚合用户日统计 → user_daily_stat        │
│       │      ├── 聚合学科维度 → user_daily_subject_stat  │
│       │      └── 聚合知识点维度 → knowledge_point_daily_stat│
│       ├─── Step 3: Redis 计数器 → MySQL 对账             │
│       ├─── Step 4: 周聚合（如果是周一）                   │
│       └─── Step 5: 月聚合（如果是每月1日）               │
└──────────────────────────────────────────────────────────┘
```

### 5.2 主批处理任务

```python
# aggregation/tasks.py

from celery import shared_task, group, chord
from datetime import date, timedelta
import logging

logger = logging.getLogger(__name__)

SHARD_COUNT = 16  # 分片数，根据 DAU 调整


@shared_task(name="aggregation.daily_aggregation")
def daily_aggregation_task(target_date: str = None):
    """
    日终聚合主任务。
    
    :param target_date: 聚合日期，格式 YYYY-MM-DD，默认昨天
    """
    if target_date:
        stat_date = date.fromisoformat(target_date)
    else:
        stat_date = date.today() - timedelta(days=1)
    
    logger.info(f"开始日终聚合，日期: {stat_date}")
    
    # Step 1: 获取有学习行为的活跃用户列表
    active_user_ids = _get_active_users(stat_date)
    logger.info(f"活跃用户数: {len(active_user_ids)}")
    
    if not active_user_ids:
        logger.info("无活跃用户，跳过聚合")
        return {"status": "skipped", "date": str(stat_date)}
    
    # Step 2: 分片并行处理
    shards = _shard_user_ids(active_user_ids, SHARD_COUNT)
    
    job = group(
        aggregate_user_shard.s(
            shard_users=shard, 
            stat_date=str(stat_date)
        )
        for shard in shards if shard  # 跳过空分片
    )
    
    # Step 3: 所有分片完成后执行对账
    callback = finalize_daily_aggregation.s(stat_date=str(stat_date))
    chord(job)(callback)
    
    return {"status": "dispatched", "date": str(stat_date), "shards": len(shards)}


def _get_active_users(stat_date: date) -> list[int]:
    """从原始日志中获取当天有学习行为的用户ID列表"""
    from django.db import connection
    
    with connection.cursor() as cursor:
        cursor.execute("""
            SELECT DISTINCT user_id 
            FROM learning_activity_log 
            WHERE DATE(created_at) = %s
        """, [stat_date])
        return [row[0] for row in cursor.fetchall()]


def _shard_user_ids(user_ids: list[int], shard_count: int) -> list[list[int]]:
    """按 user_id 分片，用于并行处理"""
    shards = [[] for _ in range(shard_count)]
    for uid in user_ids:
        shards[uid % shard_count].append(uid)
    return shards


@shared_task(name="aggregation.aggregate_user_shard", bind=True, max_retries=2)
def aggregate_user_shard(self, shard_users: list[int], stat_date: str):
    """
    单分片用户聚合处理。
    
    对分片内的每个用户：
    1. 聚合日统计
    2. 聚合学科统计
    3. 聚合知识点统计
    """
    from django.db import transaction
    from .aggregator import UserDailyAggregator
    
    success_count = 0
    error_count = 0
    errors = []
    
    for user_id in shard_users:
        try:
            with transaction.atomic():
                aggregator = UserDailyAggregator(user_id, stat_date)
                aggregator.aggregate()
            success_count += 1
        except Exception as e:
            error_count += 1
            errors.append({"user_id": user_id, "error": str(e)})
            logger.error(f"用户 {user_id} 日聚合失败: {e}")
    
    return {
        "success": success_count,
        "errors": error_count,
        "error_details": errors[:10],  # 只保留前10个错误
    }


@shared_task(name="aggregation.finalize_daily_aggregation")
def finalize_daily_aggregation(results: list, stat_date: str):
    """
    所有分片完成后的收尾工作：
    1. Redis 对账
    2. 周/月聚合检查
    3. 聚合质量统计
    """
    total_success = sum(r["success"] for r in results if r)
    total_errors = sum(r["errors"] for r in results if r)
    
    logger.info(
        f"日终聚合完成: date={stat_date}, "
        f"success={total_success}, errors={total_errors}"
    )
    
    # Redis 对账
    redis_reconciliation.delay(stat_date)
    
    # 判断是否需要周/月聚合
    d = date.fromisoformat(stat_date)
    
    # 周一 → 聚合上周
    if d.weekday() == 0:  # Monday
        week_start = d - timedelta(days=7)
        weekly_aggregation_task.delay(str(week_start))
    
    # 每月1日 → 聚合上月
    if d.day == 1:
        prev_month = d.replace(day=1) - timedelta(days=1)
        prev_month_first = prev_month.replace(day=1)
        monthly_aggregation_task.delay(str(prev_month_first))
    
    # 记录聚合统计
    _record_aggregation_meta(stat_date, total_success, total_errors)
    
    return {"status": "done", "date": stat_date, "total_success": total_success}


def _record_aggregation_meta(stat_date: str, success: int, errors: int):
    """记录聚合元数据"""
    from django.db import connection
    with connection.cursor() as cursor:
        cursor.execute("""
            INSERT INTO aggregation_meta (stat_date, task_type, total_users, error_count, completed_at)
            VALUES (%s, 'daily', %s, %s, NOW())
            ON DUPLICATE KEY UPDATE 
                total_users = VALUES(total_users),
                error_count = VALUES(error_count),
                completed_at = NOW()
        """, [stat_date, success, errors])
```

### 5.4 Redis 对账任务

日终批处理完成后，将 Redis 实时计数器与 MySQL 日统计快照进行对账，确保数据一致。

```python
@shared_task(name="aggregation.redis_reconciliation", bind=True, max_retries=1)
def redis_reconciliation(self, stat_date: str, sample_rate: float = 0.05):
    """
    Redis 对账：抽样对比 Redis 计数器与 MySQL 快照的一致性。
    
    策略：不逐条比对（成本太高），而是按 5% 抽样，发现偏差后全量修正。
    """
    from .counter import RealtimeCounter
    from django.db import connection
    
    counter = RealtimeCounter(get_redis_client())
    d = date.fromisoformat(stat_date)
    date_key = d.strftime("%Y%m%d")
    
    # 从 MySQL 获取当天有统计的用户
    with connection.cursor() as cursor:
        cursor.execute("""
            SELECT user_id FROM user_daily_stat WHERE stat_date = %s
            ORDER BY RAND() LIMIT CEIL(COUNT(*) * %s)
        """, [d, sample_rate])
        sample_users = [row[0] for row in cursor.fetchall()]
    
    discrepancy_count = 0
    
    for user_id in sample_users:
        # Redis 侧
        redis_study_time = counter.r.get(f"stat:{user_id}:{date_key}:study_time")
        redis_value = int(redis_study_time) if redis_study_time else 0
        
        # MySQL 侧
        with connection.cursor() as cursor:
            cursor.execute("""
                SELECT total_study_time FROM user_daily_stat 
                WHERE user_id = %s AND stat_date = %s
            """, [user_id, d])
            row = cursor.fetchone()
            mysql_value = row[0] if row else 0
        
        # 偏差超过 60 秒视为不一致
        if abs(redis_value - mysql_value) > 60:
            discrepancy_count += 1
            logger.warning(
                f"对账偏差: user={user_id}, redis={redis_value}, mysql={mysql_value}"
            )
    
    discrepancy_rate = discrepancy_count / len(sample_users) if sample_users else 0
    
    if discrepancy_rate > 0.1:  # 超过 10% 偏差，触发全量修正
        logger.warning(f"偏差率 {discrepancy_rate:.2%} 超阈值，触发全量修正")
        full_reconciliation.delay(stat_date)
    
    return {
        "date": stat_date,
        "sample_count": len(sample_users),
        "discrepancy_count": discrepancy_count,
        "discrepancy_rate": round(discrepancy_rate, 4),
    }

## 7. 离线上报数据回溯修正

### 7.1 问题场景

移动端在弱网或离线场景下，学习行为可能延迟数小时甚至数天才上报。这些延迟数据写入原始日志后，已聚合的统计快照可能与实际不符。

### 7.2 回溯检测

```python
@shared_task(name="aggregation.offline_correction", cron_hour=4)
def offline_correction_task():
    """
    每日凌晨 04:00 执行，检测 T-7 到 T-1 天内是否有新增的离线上报数据。
    
    判定条件：learning_activity_log 的 created_at 与 server_received_at 差值 > 1 小时
    """
    today = date.today()
    
    for days_back in range(1, 8):  # T-1 ~ T-7
        check_date = today - timedelta(days=days_back)
        
        # 检查该日期是否有新增的离线上报
        with connection.cursor() as cursor:
            cursor.execute("""
                SELECT DISTINCT user_id
                FROM learning_activity_log
                WHERE DATE(created_at) = %s
                  AND TIMESTAMPDIFF(HOUR, created_at, server_received_at) > 1
                  AND is_offline_backfill = 1
                  AND user_id NOT IN (
                      SELECT user_id FROM user_daily_stat 
                      WHERE stat_date = %s AND is_offline_corrected = 1 
                      AND correction_version >= %s
                  )
            """, [check_date, check_date, days_back])
            
            affected_users = [row[0] for row in cursor.fetchall()]
        
        if affected_users:
            logger.info(
                f"日期 {check_date} 发现 {len(affected_users)} 个用户的离线上报需回溯"
            )
            for user_id in affected_users:
                correct_user_daily_stat.delay(user_id, str(check_date))


@shared_task(name="aggregation.correct_user_daily_stat", bind=True, max_retries=2)
def correct_user_daily_stat(user_id: int, stat_date: str):
    """
    对单个用户的某日统计快照进行回溯修正。
    
    策略：直接重新全量聚合该用户该日的所有日志（包括原始+延迟上报的），
    覆盖原有快照。
    """
    aggregator = UserDailyAggregator(user_id, stat_date)
    
    with transaction.atomic():
        aggregator.aggregate()
        
        # 标记已修正
        with connection.cursor() as cursor:
            cursor.execute("""
                UPDATE user_daily_stat
                SET is_offline_corrected = 1,
                    correction_version = correction_version + 1,
                    aggregated_at = NOW()
                WHERE user_id = %s AND stat_date = %s
            """, [user_id, stat_date])
    
    # 如果修正的日期属于当前周/月，需要级联更新周/月快照
    d = date.fromisoformat(stat_date)
    today = date.today()
    
    # 判断是否在当前周内
    week_start = today - timedelta(days=today.weekday())
    if d >= week_start:
        refresh_weekly_stat.delay(user_id, str(week_start))
    
    # 判断是否在当前月内
    month_start = today.replace(day=1)
    if d >= month_start:
        refresh_monthly_stat.delay(user_id, str(month_start))

## 9. 错误处理与降级策略

### 9.1 错误场景与处理

| 场景 | 检测方式 | 处理策略 | 恢复机制 |
|------|----------|----------|----------|
| Redis 宕机 | 健康检查失败 | 跳过实时计数器更新，仅写 MySQL 日志 | Redis 恢复后日终批处理补正 |
| MySQL 日统计写入失败 | 异常捕获 | 重试 2 次，仍失败则记录到 dead_letter 表 | 手动/定时重跑 |
| 批处理超时（>30min） | Celery task timeout | 分片级别超时，成功分片保留，失败分片重跑 | 手动触发重跑特定分片 |
| 离线上报量激增 | 监控告警 | 扩大回溯窗口，增加 worker 并发 | 自适应 |
| 聚合数据与 Redis 不一致 | 对账任务检测 | MySQL 快照为准，覆盖 Redis | 日终批处理 |
| 大查询慢 SQL | 慢查询日志 | 增加索引或分日分表 | 优化后自动恢复 |

### 11.3 Redis 内存估算

```
单用户单日计数器 Key 数量：
  基础指标 10 个（String/Int）       → ~10 × 80B  = 800B
  学科维度 3 个（Hash，平均 5 field） → ~3 × 300B = 900B
  HyperLogLog 1 个                   → ~12KB
  Set (chapters) 1 个                → ~500B
  连续天数 2 个                       → ~160B
                                        ─────────
  合计约 ~15KB/用户/天

10 万 DAU × 8 天 TTL = 80 万 Key × 15KB ≈ 12GB
100 万 DAU × 8 天 TTL = 800 万 Key × 15KB ≈ 120GB
```

建议：100 万 DAU 规模使用 Redis Cluster（6 节点，每节点 32GB）。
