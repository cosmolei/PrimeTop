# 服务端-支付对账与资金清结算服务 - 详细设计

> 最后更新：2026-06-05

## 1. 概述

### 1.1 背景

启硕 PrimeTop 的支付渠道涵盖微信支付、支付宝、Apple IAP 和华为应用市场，未来还将扩展 Google Play 和银联等渠道。多渠道支付的引入带来了对账复杂度：各渠道结算周期不同（T+1 / T+3）、回调延迟、退款冲正、手续费扣除规则各异。缺乏统一的支付对账与资金清结算机制将导致：

- **资金风险**：短款（用户付了钱但订单未到账）和长款（重复支付）无法及时发现。
- **财务不透明**：无法准确核算各渠道收入、手续费、净额。
- **合规风险**：税务申报、发票开具依赖准确的交易流水记录。

### 1.2 目标

1. 建立 **自动化 T+1 对账机制**，每日自动拉取各渠道账单，与系统内部订单进行逐笔核对。
2. 构建 **多维度清结算模型**，按渠道、商户号、业务线（会员/增值服务/商城）进行收入分账。
3. 提供 **差异自动识别与告警**，对短款、长款、金额不一致、手续费异常等情况自动报警。
4. 支撑 **财务报表自动生成**，为月度结算、税务申报、发票开具提供准确数据基础。

### 1.3 适用范围

- 本服务为后端独立服务，由定时任务调度触发。
- 依赖支付与会员订阅服务、退款与订单售后处理服务、发票管理服务的数据。
- 对接微信支付、支付宝、Apple IAP、华为应用市场的对账接口。

## 2. 核心概念

### 2.1 对账（Reconciliation）

将支付渠道提供的交易账单（每日对账单）与系统内部订单记录进行逐笔匹配，确保金额、状态、手续费一致。

### 2.2 清结算（Settlement）

根据对账结果，计算各渠道、各业务线的净收入（扣除手续费、退款），生成结算单供财务确认和入账。

### 2.3 关键术语

| 术语 | 说明 |
|------|------|
| 对账日（Reconciliation Date） | 对账操作对应的交易日，通常为 T+1 |
| 渠道账单（Channel Statement） | 支付渠道提供的原始交易明细文件 |
| 内部流水（Internal Ledger） | 系统记录的交易流水 |
| 短款（Short Payment） | 渠道有收款记录但系统无对应订单 |
| 长款（Over Payment） | 系统有订单但渠道无收款记录 |
| 手续费（Transaction Fee） | 渠道收取的每笔交易手续费 |
| 净额（Net Amount） | 交易金额减去手续费和退款后的实际入账 |
| 结算周期（Settlement Cycle） | 渠道将资金打入我方账户的周期 |

## 4. 对账流程设计

### 4.1 整体流程

```
┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  下载渠道账单 │───▶│  解析账单文件  │───▶│  逐笔匹配核对  │───▶│  生成差异报告  │
└─────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
       │                   │                   │                   │
   微信/支付宝          标准化为统一         匹配规则引擎          短款/长款/金额差异
   Apple/华为           内部数据格式                             告警通知
```

### 4.2 对账任务调度

对账任务由定时任务调度框架触发，每个交易日 T+1 自动执行。

```
触发时间：每日凌晨 02:00（北京时间）
对账日期：前一个自然日（T-1）
并行策略：各渠道并行执行，互不阻塞
超时控制：单渠道任务 30 分钟超时
```

#### 4.3.1 微信支付对账单下载

```java
/**
 * 微信支付账单下载服务
 */
@Service
public class WechatBillDownloadService {

    @Value("${payment.wechat.mch-id}")
    private String mchId;

    @Value("${payment.wechat.api-v3-key}")
    private String apiV3Key;

    /**
     * 下载微信支付对账单
     * API: GET https://api.mch.weixin.qq.com/v3/bill/tradebill
     */
    public BillDownloadResult downloadBill(LocalDate reconDate) {
        // 1. 请求微信账单下载接口
        String response = httpClient.get(
            "https://api.mch.weixin.qq.com/v3/bill/tradebill"
        )
        .param("bill_date", reconDate.format(DateTimeFormatter.ofPattern("yyyy-MM-dd")))
        .param("bill_type", "ALL")       // ALL：包含成功与退款
        .param("tar_type", "GZIP")        // GZIP 压缩
        .withSignature("WECHAT_V3", mchId, apiV3Key)
        .execute();

        // 2. 解析响应，获取账单下载链接
        BillDownloadUrl downloadUrl = parseDownloadUrl(response);

        // 3. 下载账单文件（gzip 压缩的 CSV）
        byte[] billData = httpClient.download(downloadUrl.getDownloadUrl());

        // 4. 校验哈希
        if (!verifyHash(billData, downloadUrl.getHashValue())) {
            throw new BillVerifyException("微信账单哈希校验失败: " + reconDate);
        }

        return BillDownloadResult.success(reconDate, billData);
    }
}
```

### 4.4 账单解析与标准化

各渠道账单格式不同，需统一转换为内部标准格式。

```java
/**
 * 渠道账单标准化模型
 */
@Data
@Builder
public class StandardBillItem {
    private String channel;           // wechat/alipay/apple/huawei
    private String channelTxId;       // 渠道交易号
    private String channelMchId;      // 渠道商户号
    private String channelOrderNo;    // 渠道侧商户订单号
    private String tradeType;         // PAY / REFUND
    private String tradeStatus;       // SUCCESS / REFUND / CLOSED
    private BigDecimal tradeAmount;   // 交易金额
    private BigDecimal feeAmount;     // 手续费
    private BigDecimal refundAmount;  // 退款金额
    private String payerAccount;      // 付款方（脱敏）
    private LocalDateTime tradeTime;  // 交易完成时间
    private String rawData;           // 原始数据 JSON
}

/**
 * 账单解析器工厂
 */
@Component
public class BillParserFactory {

    private final Map<String, BillParser> parsers;

    public BillParserFactory(List<BillParser> parserList) {
        this.parsers = parserList.stream()
            .collect(Collectors.toMap(
                p -> p.getClass().getAnnotation(ChannelType.class).value(),
                Function.identity()
            ));
    }

    public BillParser getParser(String channel) {
        BillParser parser = parsers.get(channel);
        if (parser == null) {
            throw new UnsupportedOperationException("不支持的对账渠道: " + channel);
        }
        return parser;
    }
}

/**
 * 微信账单解析器
 * 微信对账单 CSV 格式（含表头）：
 * 交易时间,公众账号ID,商户号,子商户号,设备号,订单号,商户订单号,...
 */
@ChannelType("wechat")
@Component
public class WechatBillParser implements BillParser {

    @Override
    public List<StandardBillItem> parse(byte[] billData) {
        // 微信账单前几行是汇总信息，以 `交易时间,...` 开头的是明细
        String content = decompressGzip(billData);
        String[] lines = content.split("\n");

        boolean detailStarted = false;
        List<StandardBillItem> items = new ArrayList<>();

        for (String line : lines) {
            line = line.trim();
            if (line.startsWith("`交易时间")) {
                detailStarted = true;
                continue; // 跳过表头
            }
            if (line.startsWith("`总交易单数") || line.isEmpty()) {
                continue; // 跳过汇总行
            }
            if (!detailStarted) continue;

            String[] fields = line.replace("`", "").split(",");
            if (fields.length < 24) continue;

            String tradeType = fields[9].trim();  // PAY/REFUND
            items.add(StandardBillItem.builder()
                .channel("wechat")
                .channelTxId(fields[7].trim())     // 微信支付订单号
                .channelMchId(fields[2].trim())     // 商户号
                .channelOrderNo(fields[8].trim())   // 商户订单号
                .tradeType("REFUND".equals(tradeType) ? "REFUND" : "PAY")
                .tradeStatus("SUCCESS")
                .tradeAmount(new BigDecimal(fields[12].trim()))  // 订单金额
                .feeAmount(new BigDecimal(fields[16].trim()))    // 手续费
                .refundAmount(new BigDecimal(fields[17].trim())) // 退款金额
                .tradeTime(parseWechatTime(fields[0].trim()))
                .rawData(line)
                .build());
        }

        return items;
    }
}
```

### 4.5 匹配引擎

#### 4.5.1 匹配规则

```
匹配优先级（从高到低）：
1. 精确匹配：channel_tx_id 完全一致 && 金额一致 && 状态一致
2. 订单号匹配：channel_order_no 匹配 && 金额一致（channel_tx_id 可能为空）
3. 模糊匹配：金额一致 && 交易时间 ±5分钟 && 渠道一致
4. 手动匹配：以上规则均未匹配，标记为待人工处理
```

```java
/**
 * 对账匹配引擎
 */
@Service
@Slf4j
public class ReconciliationMatchEngine {

    /**
     * 执行匹配
     * @param channelItems 渠道账单明细
     * @param internalItems 内部流水明细
     * @return 匹配结果
     */
    public MatchResult match(List<ChannelBillItem> channelItems,
                             List<InternalLedger> internalItems) {

        MatchResult result = new MatchResult();

        // 构建内部流水索引（channelTxId -> InternalLedger）
        Map<String, InternalLedger> txIdIndex = internalItems.stream()
            .filter(i -> i.getChannelTxId() != null)
            .collect(Collectors.toMap(
                InternalLedger::getChannelTxId,
                Function.identity(),
                (a, b) -> a  // 去重策略：取第一条
            ));

        // 构建订单号索引
        Map<String, InternalLedger> orderNoIndex = internalItems.stream()
            .collect(Collectors.toMap(
                InternalLedger::getOrderNo,
                Function.identity(),
                (a, b) -> a
            ));

        // 已匹配的内部流水 ID 集合
        Set<Long> matchedInternalIds = new HashSet<>();

        for (ChannelBillItem channelItem : channelItems) {
            InternalLedger matched = null;
            String matchType = null;

            // 规则1：精确匹配（channel_tx_id）
            if (channelItem.getChannelTxId() != null) {
                matched = txIdIndex.get(channelItem.getChannelTxId());
                if (matched != null && matchedInternalIds.contains(matched.getId())) {
                    matched = null; // 防止重复匹配
                }
                if (matched != null) {
                    matchType = "EXACT";
                }
            }

            // 规则2：订单号匹配
            if (matched == null && channelItem.getChannelOrderNo() != null) {
                matched = orderNoIndex.get(channelItem.getChannelOrderNo());
                if (matched != null && matchedInternalIds.contains(matched.getId())) {
                    matched = null;
                }
                if (matched != null) {
                    matchType = "ORDER_NO";
                }
            }

            // 规则3：模糊匹配（金额+时间）
            if (matched == null) {
                matched = fuzzyMatch(channelItem, internalItems, matchedInternalIds);
                if (matched != null) {
                    matchType = "FUZZY";
                }
            }

            if (matched != null) {
                matchedInternalIds.add(matched.getId());
                result.addMatched(channelItem, matched, matchType);
            } else {
                // 渠道有记录，内部无 → 短款
                result.addUnmatchedChannel(channelItem);
            }
        }

        // 内部未匹配 → 长款
        internalItems.stream()
            .filter(i -> !matchedInternalIds.contains(i.getId()))
            .forEach(result::addUnmatchedInternal);

        return result;
    }

    /**
     * 模糊匹配：金额一致 + 交易时间在 ±5 分钟内
     */
    private InternalLedger fuzzyMatch(ChannelBillItem channelItem,
                                       List<InternalLedger> internalItems,
                                       Set<Long> matchedIds) {
        LocalDateTime tradeTime = channelItem.getTradeTime();
        BigDecimal amount = channelItem.getTradeAmount();

        return internalItems.stream()
            .filter(i -> !matchedIds.contains(i.getId()))
            .filter(i -> i.getChannel().equals(channelItem.getChannel()))
            .filter(i -> i.getTradeAmount().compareTo(amount) == 0)
            .filter(i -> Math.abs(Duration.between(i.getTradeTime(), tradeTime).toMinutes()) <= 5)
            .findFirst()
            .orElse(null);
    }
}
```

### 4.6 对账任务主流程

```java
/**
 * 对账任务执行器
 */
@Service
@Slf4j
public class ReconciliationExecutor {

    private final BillDownloadServiceFactory downloadFactory;
    private final BillParserFactory parserFactory;
    private final ReconciliationMatchEngine matchEngine;
    private final ReconciliationTaskRepository taskRepo;
    private final ChannelBillItemRepository billRepo;
    private final InternalLedgerRepository ledgerRepo;
    private final ReconciliationMatchRepository matchRepo;
    private final AlertService alertService;

    /**
     * 执行单渠道对账
     */
    @Transactional
    public ReconciliationTask execute(String channel, LocalDate reconDate) {
        log.info("开始对账: channel={}, date={}", channel, reconDate);

        // 1. 创建对账任务
        ReconciliationTask task = taskRepo.save(
            ReconciliationTask.builder()
                .taskNo(generateTaskNo(reconDate))
                .channel(channel)
                .reconDate(reconDate)
                .status("DOWNLOADING")
                .build()
        );

        try {
            // 2. 下载渠道账单
            BillDownloadResult billResult = downloadFactory.getService(channel)
                .downloadBill(reconDate);
            task.setChannelBillUrl(billResult.getDownloadUrl());
            task.setStatus("PARSING");
            taskRepo.save(task);

            // 3. 解析账单
            List<StandardBillItem> billItems = parserFactory.getParser(channel)
                .parse(billResult.getData());

            // 4. 保存渠道账单明细
            List<ChannelBillItem> channelItems = billItems.stream()
                .map(item -> toChannelBillItem(task.getId(), item))
                .collect(Collectors.toList());
            billRepo.batchInsert(channelItems);
            task.setTotalChannelCount(channelItems.size());

            // 5. 查询内部流水
            List<InternalLedger> internalItems = ledgerRepo.findByChannelAndDate(
                channel,
                reconDate.atStartOfDay(ZoneId.of("Asia/Shanghai")).toInstant(),
                reconDate.plusDays(1).atStartOfDay(ZoneId.of("Asia/Shanghai")).toInstant()
            );
            task.setTotalInternalCount(internalItems.size());

            // 6. 执行匹配
            task.setStatus("MATCHING");
            taskRepo.save(task);

            MatchResult matchResult = matchEngine.match(channelItems, internalItems);

            // 7. 保存匹配结果
            matchRepo.batchInsert(matchResult.getAllMatches().stream()
                .map(m -> toReconciliationMatch(task.getId(), m))
                .collect(Collectors.toList()));

            // 8. 更新任务统计
            task.setMatchedCount(matchResult.getMatchedCount());
            task.setUnmatchedChannel(matchResult.getUnmatchedChannelCount());
            task.setUnmatchedInternal(matchResult.getUnmatchedInternalCount());
            task.setAmountDiffCount(matchResult.getAmountDiffCount());
            task.setStatus("COMPLETED");
            task.setCompletedAt(Instant.now());
            taskRepo.save(task);

            // 9. 差异告警
            if (matchResult.hasDiscrepancy()) {
                alertService.sendReconciliationAlert(task, matchResult);
            }

            log.info("对账完成: channel={}, matched={}, short={}, over={}, amountDiff={}",
                channel, matchResult.getMatchedCount(),
                matchResult.getUnmatchedChannelCount(),
                matchResult.getUnmatchedInternalCount(),
                matchResult.getAmountDiffCount());

            return task;

        } catch (Exception e) {
            log.error("对账失败: channel={}, date={}", channel, reconDate, e);
            task.setStatus("FAILED");
            task.setErrorMessage(e.getMessage());
            taskRepo.save(task);
            alertService.sendReconciliationFailedAlert(task, e);
            throw e;
        }
    }
}
```

### 5.2 结算计算逻辑

```java
/**
 * 结算服务
 */
@Service
@Slf4j
public class SettlementService {

    private final SettlementSummaryRepository settlementRepo;
    private final ReconciliationTaskRepository reconTaskRepo;
    private final ChannelBillItemRepository billRepo;
    private final FeeConfigRepository feeConfigRepo;

    /**
     * 生成月度结算单
     * @param period 格式：yyyy-MM（如 2026-06）
     */
    @Transactional
    public List<SettlementSummary> generateMonthlySettlement(String period) {
        YearMonth ym = YearMonth.parse(period);
        LocalDate startDate = ym.atDay(1);
        LocalDate endDate = ym.atEndOfMonth();

        // 1. 校验：该月所有对账任务是否已完成
        List<ReconciliationTask> tasks = reconTaskRepo
            .findByReconDateBetween(startDate, endDate);
        boolean allCompleted = tasks.stream()
            .allMatch(t -> "COMPLETED".equals(t.getStatus()));
        if (!allCompleted) {
            throw new SettlementException(
                "存在未完成的对账任务，无法生成结算单: " + period);
        }

        // 2. 按渠道 + 业务类型汇总
        List<SettlementSummary> summaries = new ArrayList<>();
        for (String channel : List.of("wechat", "alipay", "apple", "huawei")) {
            // 查询该渠道该月所有已匹配的账单明细
            List<ChannelBillItem> items = billRepo
                .findMatchedByChannelAndDateRange(channel, startDate, endDate);

            // 按业务类型分组汇总
            Map<String, List<ChannelBillItem>> grouped = items.stream()
                .collect(Collectors.groupingBy(
                    item -> resolveBizType(item.getChannelOrderNo())
                ));

            for (Map.Entry<String, List<ChannelBillItem>> entry : grouped.entrySet()) {
                String bizType = entry.getKey();
                List<ChannelBillItem> bizItems = entry.getValue();

                BigDecimal totalAmount = bizItems.stream()
                    .filter(i -> "PAY".equals(i.getTradeType()))
                    .map(ChannelBillItem::getTradeAmount)
                    .reduce(BigDecimal.ZERO, BigDecimal::add);

                BigDecimal totalRefund = bizItems.stream()
                    .filter(i -> "REFUND".equals(i.getTradeType()))
                    .map(ChannelBillItem::getRefundAmount)
                    .reduce(BigDecimal.ZERO, BigDecimal::add);

                BigDecimal totalFee = calculateTotalFee(channel, bizItems);

                BigDecimal netAmount = totalAmount
                    .subtract(totalRefund)
                    .subtract(totalFee);

                summaries.add(SettlementSummary.builder()
                    .settlementNo(generateSettlementNo(period, channel, bizType))
                    .settlementPeriod(period)
                    .channel(channel)
                    .bizType(bizType)
                    .totalTransactions(bizItems.size())
                    .totalAmount(totalAmount)
                    .totalRefund(totalRefund)
                    .totalFee(totalFee)
                    .netAmount(netAmount)
                    .status("PENDING")
                    .build());
            }
        }

        return settlementRepo.saveAll(summaries);
    }

    /**
     * 计算手续费
     */
    private BigDecimal calculateTotalFee(String channel, List<ChannelBillItem> items) {
        return items.stream()
            .map(item -> {
                // 优先使用渠道账单中的实际手续费
                if (item.getFeeAmount() != null && item.getFeeAmount().compareTo(BigDecimal.ZERO) > 0) {
                    return item.getFeeAmount();
                }
                // 否则使用配置的手续费率计算
                FeeConfig config = feeConfigRepo.findEffective(
                    channel, item.getChannelMchId(),
                    item.getTradeType(), item.getTradeTime().toLocalDate());
                if (config == null) return BigDecimal.ZERO;
                return calculateFee(config, item.getTradeAmount());
            })
            .reduce(BigDecimal.ZERO, BigDecimal::add);
    }

    private BigDecimal calculateFee(FeeConfig config, BigDecimal amount) {
        BigDecimal fee;
        if ("RATE".equals(config.getFeeType())) {
            fee = amount.multiply(config.getFeeRate())
                .setScale(2, RoundingMode.HALF_UP);
        } else {
            fee = config.getFeeFixed();
        }
        // 最低手续费
        if (config.getMinFee() != null && fee.compareTo(config.getMinFee()) < 0) {
            fee = config.getMinFee();
        }
        // 最高手续费
        if (config.getMaxFee() != null && fee.compareTo(config.getMaxFee()) > 0) {
            fee = config.getMaxFee();
        }
        return fee;
    }

    /**
     * 根据订单号解析业务类型
     * 订单号前缀规则：
     *   MEM-xxx → MEMBERSHIP
     *   VAS-xxx → VALUE_ADDED
     *   MAL-xxx → MALL
     */
    private String resolveBizType(String orderNo) {
        if (orderNo == null) return "UNKNOWN";
        if (orderNo.startsWith("MEM-")) return "MEMBERSHIP";
        if (orderNo.startsWith("VAS-")) return "VALUE_ADDED";
        if (orderNo.startsWith("MAL-")) return "MALL";
        return "UNKNOWN";
    }
}
```

## 7. 告警与通知

### 7.1 告警规则

| 告警级别 | 触发条件 | 通知渠道 |
|----------|----------|----------|
| **P0 紧急** | 单渠道短款金额 > 10,000 元 | 电话 + 企业微信群 |
| **P1 高** | 单渠道短款/长款笔数 > 10 笔 | 企业微信群 |
| **P2 中** | 金额不一致笔数 > 0 或对账失败 | 企业微信群 |
| **P3 低** | 手续费率变动（与上月对比差异 > 10%） | 邮件周报 |

### 7.2 告警服务

```java
@Service
@Slf4j
public class AlertService {

    private final WechatWorkNotifier wechatNotifier;
    private final PhoneCallNotifier phoneNotifier;
    private final EmailNotifier emailNotifier;

    /**
     * 发送对账差异告警
     */
    public void sendReconciliationAlert(ReconciliationTask task, MatchResult result) {
        String summary = String.format(
            "【对账差异告警】\n" +
            "渠道：%s\n" +
            "对账日：%s\n" +
            "短款：%d笔\n" +
            "长款：%d笔\n" +
            "金额不一致：%d笔",
            task.getChannel(), task.getReconDate(),
            result.getUnmatchedChannelCount(),
            result.getUnmatchedInternalCount(),
            result.getAmountDiffCount()
        );

        // 计算短款金额
        BigDecimal shortAmount = result.getUnmatchedChannelItems().stream()
            .map(ChannelBillItem::getTradeAmount)
            .reduce(BigDecimal.ZERO, BigDecimal::add);

        AlertLevel level = determineLevel(shortAmount, result);

        switch (level) {
            case P0:
                phoneNotifier.call("财务值班", summary);
                wechatNotifier.send("finance-group", summary);
                break;
            case P1:
            case P2:
                wechatNotifier.send("finance-group", summary);
                break;
            default:
                emailNotifier.send("finance@primetop.com", "对账差异报告", summary);
        }
    }

    private AlertLevel determineLevel(BigDecimal shortAmount, MatchResult result) {
        if (shortAmount.compareTo(new BigDecimal("10000")) > 0) {
            return AlertLevel.P0;
        }
        int totalDiscrepancy = result.getUnmatchedChannelCount()
            + result.getUnmatchedInternalCount();
        if (totalDiscrepancy > 10) {
            return AlertLevel.P1;
        }
        if (result.getAmountDiffCount() > 0) {
            return AlertLevel.P2;
        }
        return AlertLevel.P3;
    }
}
```

## 8. 内部流水写入规范

对账服务依赖支付服务在交易成功时写入内部流水。支付服务需遵循以下规范：

### 8.1 流水写入时机

```

```

### 8.2 流水写入要求

```java
/**
 * 支付服务中的流水写入示例

@Service
public class PaymentCallbackHandler {

    private final InternalLedgerRepository ledgerRepo;

    /**
     * 处理支付成功回调
     */
    public void handlePaymentSuccess(PaymentCallback callback) {
        // 1. 处理业务逻辑（订单状态更新、权益开通等）
        processOrder(callback);

        // 2. 写入内部流水（对账依赖）
        InternalLedger ledger = InternalLedger.builder()
            .ledgerNo(generateLedgerNo())
            .orderNo(callback.getOrderNo())
            .channel(callback.getChannel())
            .channelTxId(callback.getChannelTxId())    // ← 关键：渠道交易号
            .bizType(resolveBizType(callback.getOrderNo()))
            .tradeType("PAY")
            .tradeAmount(callback.getPayAmount())
            .tradeStatus("SUCCESS")
            .userId(callback.getUserId())
            .tradeTime(callback.getPayTime())
            .build();
        ledgerRepo.save(ledger);
    }
}
```

**关键注意事项：**
- `channelTxId` 必须从支付回调中准确获取，这是对账精确匹配的核心字段。
- `tradeTime` 使用渠道回调中的交易完成时间，而非系统处理时间。
- 幂等控制：同一笔订单+渠道交易号只能写入一条流水。

## 9. 定时任务配置

| 任务名 | Cron 表达式 | 说明 |
|--------|-------------|------|
| `recon-daily` | `0 0 2 * * ?` | 每日凌晨 2:00 执行 T+1 对账 |
| `recon-retry` | `0 0 6 * * ?` | 每日早 6:00 重试失败的对账任务 |
| `settlement-monthly` | `0 0 3 5 * ?` | 每月 5 号凌晨 3:00 生成上月结算单 |
| `settlement-weekly` | `0 0 3 ? * MON` | 每周一凌晨 3:00 生成上周结算快报 |
| `fee-rate-check` | `0 0 4 1 * ?` | 每月 1 号凌晨 4:00 校验手续费率变动 |

```java
@Component
@Slf4j
public class ReconciliationScheduledTasks {

    private final ReconciliationExecutor reconExecutor;

    /**
     * 每日凌晨 2:00 执行全渠道对账
     */
    @Scheduled(cron = "0 0 2 * * ?")
    public void dailyReconciliation() {
        LocalDate yesterday = LocalDate.now(ZoneId.of("Asia/Shanghai")).minusDays(1);
        log.info("开始每日对账，对账日期：{}", yesterday);

        List<String> channels = List.of("wechat", "alipay", "apple", "huawei");
        for (String channel : channels) {
            try {
                // 各渠道并行执行（使用线程池）
                reconExecutor.executeAsync(channel, yesterday);
            } catch (Exception e) {
                log.error("对账任务提交失败: channel={}", channel, e);
            }
        }
    }

    /**
     * 每日早 6:00 重试失败的对账任务
     */
    @Scheduled(cron = "0 0 6 * * ?")
    public void retryFailedTasks() {
        List<ReconciliationTask> failedTasks = reconTaskRepo
            .findByStatusAndReconDateAfter("FAILED",
                LocalDate.now(ZoneId.of("Asia/Shanghai")).minusDays(3));

        for (ReconciliationTask task : failedTasks) {
            try {
                reconExecutor.execute(task.getChannel(), task.getReconDate());
            } catch (Exception e) {
                log.error("对账重试失败: taskNo={}", task.getTaskNo(), e);
            }
        }
```

## 10. 各渠道对账差异特征与处理策略

### 10.1 微信支付常见差异

| 差异类型 | 原因 | 处理策略 |
|----------|------|----------|
| 短款（渠道有，系统无） | 回调通知丢失，订单未创建 | 补录订单 + 开通权益 |
| 长款（系统有，渠道无） | 系统记录了但交易实际未完成 | 核实后标记关闭 |
| 金额不一致 | 优惠券/满减导致实付金额不同 | 核对营销活动后标记调整 |
| 手续费差异 | 微信手续费率调整 | 更新 fee_config |

### 10.2 支付宝常见差异

| 差异类型 | 原因 | 处理策略 |
|----------|------|----------|
| 短款 | 异步回调延迟（>24h） | 等待 T+2 再确认 |
| 退款冲正 | 退款后用户又发起原交易申诉 | 联系支付宝客服处理 |

### 10.3 Apple IAP 常见差异

| 差异类型 | 原因 | 处理策略 |
|----------|------|----------|
| 短款 | Apple 通知延迟、沙盒测试数据混入 | 过滤沙盒数据，等待 72h |
| 手续费固定 30% | Apple 不单独出对账单，需按公式计算 | 按收入 70% 记账 |
| 订阅续费时差 | 订阅续费可能有 1-3 天延迟 | 等待续费通知后补充 |

### 10.4 华为应用市场常见差异

| 差异类型 | 原因 | 处理策略 |
|----------|------|----------|
| 时间不一致 | 华为账单使用 UTC 时间 | 统一转换为 Asia/Shanghai |
| 退款周期长 | 华为退款审核可达 7 天 | 设置更长的对账窗口（T+7） |

## 12. 错误处理

### 12.1 异常码定义

| 异常码 | HTTP 状态码 | 说明 | 处理建议 |
|--------|------------|------|----------|
| `RECON_001` | 409 | 该渠道该日期的对账任务已存在 | 跳过或查看已有任务 |
| `RECON_002` | 502 | 渠道账单下载失败 | 检查网络/凭证，稍后重试 |
| `RECON_003` | 422 | 账单文件格式校验失败 | 检查渠道接口变更 |
| `RECON_004` | 422 | 账单哈希校验失败 | 重新下载账单 |
| `RECON_005` | 409 | 对账任务正在执行中 | 等待完成 |
| `STTL_001` | 422 | 存在未完成的对账任务 | 先完成对账 |
| `STTL_002` | 409 | 结算单已存在 | 查看已有结算单 |
| `STTL_003` | 400 | 结算单已确认，不可修改 | 联系管理员 |
| `FEE_001` | 404 | 未找到有效手续费配置 | 先配置手续费规则 |

### 12.2 重试策略

```java
@Configuration
public class ReconciliationRetryConfig {

    @Bean
    public RetryTemplate reconRetryTemplate() {
        RetryTemplate template = new RetryTemplate();

        // 指数退避：初始 1 分钟，最大 10 分钟，倍数 2
        ExponentialBackOffPolicy backOff = new ExponentialBackOffPolicy();
        backOff.setInitialInterval(60_000L);  // 1 min
        backOff.setMaxInterval(600_000L);     // 10 min
        backOff.setMultiplier(2.0);

        // 重试策略：最多 3 次
        SimpleRetryPolicy retryPolicy = new SimpleRetryPolicy();
        retryPolicy.setMaxAttempts(3);

        // 仅对网络异常和超时重试
        Map<Class<? extends Throwable>, Boolean> retryable = Map.of(
            SocketTimeoutException.class, true,
            HttpServerErrorException.class, true,
            BillVerifyException.class, false  // 校验失败不重试
        );

        template.setBackOffPolicy(backOff);
        template.setRetryPolicy(new SimpleRetryPolicy(3, retryable));

        return template;
    }
}
```

### 12.3 幂等保障

- 对账任务：同一 `(channel, reconDate)` 组合只允许一个任务。
- 结算单：同一 `(period, channel, bizType)` 组合只允许一个结算单。
- 匹配结果：同一 `(taskId, channelBillId, internalLedgerId)` 唯一。
- 数据库层使用 UNIQUE 约束保障。
