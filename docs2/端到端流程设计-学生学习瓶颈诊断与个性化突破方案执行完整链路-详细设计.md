# 端到端流程设计 — 学生学习瓶颈诊断与个性化突破方案执行完整链路

## 1. 概述

### 1.1 流程定位

本流程覆盖从"系统检测到学生学习瓶颈"到"生成诊断→制定突破方案→执行干预→评估效果"的完整闭环。该链路横跨学情分析、AI 辅导、题目服务、内容服务、学习规划、消息推送等多个核心服务，是 PrimeTop 实现"个性化学习"的关键差异化路径。

### 1.2 与现有文档的关系

| 已有文档 | 关系 |
| --- | --- |
| 服务端-学生学习卡点智能诊断与突破辅导策略推荐引擎 | 聚焦"诊断+策略推荐"引擎层，本文聚焦端到端业务全链路 |
| 服务端-知识追踪模型引擎与学生能力动态评估服务 | 提供掌握度数据输入，本流程消费其产出 |
| 服务端-学习计划动态调整与智能重排服务 | 本流程产出"突破计划"，由该服务落地执行 |
| 端到端流程设计-自适应学习与个性化推荐完整链路 | 更泛化的推荐流程，本流程是"问题驱动型"的特化路径 |

### 1.3 业务价值

- **降低流失率**：在学生产生挫败感前主动干预，减少因"学不会"而流失
- **提升学习效果**：精准定位瓶颈根因，避免无效刷题
- **增强家长信任**：为家长提供可理解的诊断报告和改进计划
- **差异化竞争力**：从"被动答疑"升级为"主动诊断+靶向突破"

### 3.3 触发去重与合并

同一学生同一知识点的触发事件在 **6 小时窗口**内合并，避免重复诊断：

```java
public class TriggerDeduplicator {

    private static final long DEDUP_WINDOW_MS = 6 * 60 * 60 * 1000; // 6h
    private final RedisTemplate<String, String> redis;

    public boolean shouldProcess(TriggerEvent event) {
        String key = String.format("bottleneck:trigger:%s:%s",
            event.getUserId(),
            String.join(",", event.getKnowledgePointIds()));

        // SETNX with TTL — first one in the window wins
        Boolean acquired = redis.opsForValue()
            .setIfAbsent(key, event.getEventId(), Duration.ofMillis(DEDUP_WINDOW_MS));

        if (Boolean.TRUE.equals(acquired)) {
            return true;
        }

        // Priority upgrade: if new event has higher priority, force process
        String existingId = redis.opsForValue().get(key);
        TriggerEvent existing = eventStore.findById(existingId);
        return existing != null && event.getPriority().ordinal()
             < existing.getPriority().ordinal();
    }
}
```

### 4.3 瓶颈分类体系

```java
public enum BottleneckType {
    KNOWLEDGE_GAP,         // 知识断层：前置知识点未掌握
    CONCEPT_MISUNDERSTAND, // 迷思概念：存在错误认知模型
    CALCULATION_ERROR,     // 计算能力：方法对但计算频繁出错
    METHOD_MISMATCH,       // 方法缺失：不知道该用什么方法
    READING_COMPREHENSION, // 题意理解：读不懂题目或审题失误
    TRANSFER_FAILURE,      // 迁移失败：会做基础题但不会综合应用
    PSYCHOLOGICAL_BLOCK,   // 心理障碍：焦虑/回避/自我否定
    ATTENTION_ISSUE        // 注意力：粗心/跳步/未检查
}

public enum BottleneckSeverity {
    MILD,       // 轻微：偶尔出错，通过少量练习可修正
    MODERATE,   // 中等：系统性错误，需要专项讲解+练习
    SEVERE,     // 严重：核心知识缺失，需要回退到前置知识重建
    CRITICAL    // 关键：多维度同时出现问题，需要AI+人工联合干预
}
```

### 4.4 根因分析决策树

```python
# 伪代码：根因分析核心逻辑
def analyze_root_cause(signals, classification):
    kp_id = signals.target_knowledge_point_id

    # 决策路径 1：前置知识是否缺失？
    prerequisites = knowledge_graph.get_prerequisites(kp_id)
    weak_prereqs = [p for p in prerequisites
                    if signals.mastery_of(p) < 0.6]

    if weak_prereqs:
        return RootCause(
            type=BottleneckType.KNOWLEDGE_GAP,
            root_knowledge_points=weak_prereqs,
            description=f"前置知识点掌握不足: {weak_prereqs}",
            confidence=0.85,
            recommended_action="REVIEW_PREREQUISITE"
        )

    # 决策路径 2：是否存在迷思概念？
    misconception_patterns = misconception_detector.detect(
        signals.answer_patterns,
        signals.error_type_distribution
    )
    if misconception_patterns:
        return RootCause(
            type=BottleneckType.CONCEPT_MISUNDERSTAND,
            misconception_details=misconception_patterns,
            confidence=0.78,
            recommended_action="CONCEPT_CORRECTION"
        )

    # 决策路径 3：方法识别是否失败？
    if signals.consecutive_wrong_on_same_type >= 3:
        if signals.avg_first_step_correct_rate < 0.3:
            return RootCause(
                type=BottleneckType.METHOD_MISMATCH,
                confidence=0.82,
                recommended_action="METHOD_TEACHING"
            )

    # 决策路径 4：计算能力？
    calc_error_rate = signals.calculation_error_ratio
    if calc_error_rate > 0.4:
        return RootCause(
            type=BottleneckType.CALCULATION_ERROR,
            confidence=0.90,
            recommended_action="CALCULATION_DRILL"
        )

    # 决策路径 5：心理/注意力？
    if signals.frustration_signals_count > 3 or signals.avg_session_attention_score < 0.4:
        return RootCause(
            type=BottleneckType.PSYCHOLOGICAL_BLOCK,
            confidence=0.65,
            recommended_action="PSYCHOLOGICAL_SUPPORT"
        )

    # 默认：综合迁移困难
    return RootCause(
        type=BottleneckType.TRANSFER_FAILURE,
        confidence=0.55,
        recommended_action="COMPREHENSIVE_PRACTICE"
    )
```

## 5. 阶段三：方案阶段

### 5.1 突破方案生成

基于诊断结果，方案生成器产出一份结构化的突破计划：

```java
public class BreakthroughPlanGenerator {

    public BreakthroughPlan generate(DiagnosisResult diagnosis, StudentProfile profile) {

        // 1. 根据瓶颈类型选择策略模板
        StrategyTemplate template = strategyFactory.select(
            diagnosis.getRootCause().getType(),
            diagnosis.getClassification().getSeverity()
        );

        // 2. 根据学生画像调整
        template.adapt(profile.getLearningStyle(), profile.getAvailableTimePerDay());

        // 3. 生成内容序列
        List<StudyUnit> units = template.buildUnits(diagnosis);

        // 4. 生成时间表
        Schedule schedule = scheduler.plan(units, profile.getCalendar());

        // 5. 设置成功指标
        SuccessCriteria criteria = criteriaBuilder.build(diagnosis, template);

        return BreakthroughPlan.builder()
            .planId(generatePlanId())
            .userId(diagnosis.getUserId())
            .diagnosisId(diagnosis.getDiagnosisId())
            .title(template.getTitle())
            .description(template.getDescription())
            .units(units)
            .schedule(schedule)
            .successCriteria(criteria)
            .status(PlanStatus.PENDING_CONFIRMATION)
            .createdAt(Instant.now())
            .build();
    }
}
```

### 5.2 策略模板定义

| 瓶颈类型 | 严重度 | 策略步骤 |
| --- | --- | --- |
| KNOWLEDGE_GAP | SEVERE | ① 前置知识微课复习 → ② 基础检测 → ③ 补充讲解 → ④ 回到目标知识点 |

| METHOD_MISMATCH | 任意 | ① 题型识别训练 → ② 经典方法讲解 → ③ 同类题集中练习 → ④ 一题多解拓展 |

```java
public class BreakthroughContextInjector {

    public AiTutorContext inject(String userId, String currentContentId) {
        BreakthroughPlan activePlan = planService.findActivePlan(userId);

        if (activePlan == null) {
            return AiTutorContext.defaultContext();
        }

        BreakthroughUnit currentUnit = activePlan.findUnitByContent(currentContentId);
        if (currentUnit == null) {
            return AiTutorContext.defaultContext();
        }

        return AiTutorContext.builder()
            .mode(AiTutorMode.BREAKTHROUGH_TUTORING)
            .bottleneckType(activePlan.getDiagnosis().getBottleneckType())
            .rootCause(activePlan.getDiagnosis().getRootCause().getDescription())

            .strategyHints(activePlan.getStrategy().getAiHints())
            .encouragementLevel(calculateEncouragementLevel(activePlan))
            .answerRevealPolicy(AnswerRevealPolicy.HINT_FIRST) // 突破模式默认先提示
            .build();
    }

    private EncouragementLevel calculateEncouragementLevel(BreakthroughPlan plan) {
        int failedUnits = plan.countUnitsByStatus(UnitStatus.FAILED);
        if (failedUnits >= 2) {
            return EncouragementLevel.HIGH; // 连续失败时增加鼓励
        }
        int completedUnits = plan.countUnitsByStatus(UnitStatus.COMPLETED);
        if (completedUnits == 0) {
            return EncouragementLevel.HIGH; // 刚开始时多鼓励
        }
        return EncouragementLevel.NORMAL;
    }
}
```

## 7. 阶段五：评估阶段

### 7.1 效果评估模型

每个 Unit 完成后触发增量评估；整个计划完成后触发综合评估。

```java
public class BreakthroughEvaluator {

    /**
     * 单元级评估 — 每个 Unit 完成后触发
     */
    public UnitEvaluation evaluateUnit(BreakthroughUnit unit, TaskResult result) {
        double accuracy = result.getAccuracy();
        double threshold = unit.getSuccessThreshold().getAccuracy();

        UnitOutcome outcome;
        if (accuracy >= threshold) {
            outcome = UnitOutcome.PASSED;
        } else if (accuracy >= threshold - 0.15) {
            outcome = UnitOutcome.BORDERLINE;  // 接近通过，可继续但需关注
        } else {
            outcome = UnitOutcome.FAILED;
        }

        return UnitEvaluation.builder()
            .unitId(unit.getUnitId())
            .outcome(outcome)
            .accuracy(accuracy)
            .threshold(threshold)
            .timeSpentMinutes(result.getTimeSpentMinutes())
            .errorPatterns(result.getErrorPatterns())
            .recommendation(decideNextStep(outcome, unit))
            .build();
    }

    /**
     * 计划级评估 — 最终检测 + 整体回顾
     */
    public PlanEvaluation evaluatePlan(BreakthroughPlan plan, List<UnitEvaluation> unitEvals) {
        // 1. 对比诊断前后的掌握度变化
        double beforeMastery = plan.getDiagnosis().getSignals().getMasteryBefore();
        double afterMastery = knowledgeMasteryService.getCurrentMastery(
            plan.getUserId(),
            plan.getDiagnosis().getTarget().getKnowledgePointIds()
        );

        double masteryDelta = afterMastery - beforeMastery;

        // 2. 计算计划整体成功率
        double passRate = (double) unitEvals.stream()
            .filter(e -> e.getOutcome() == UnitOutcome.PASSED)
            .count() / unitEvals.size();

        // 3. 综合判定
        PlanOutcome outcome;
        if (afterMastery >= plan.getSuccessCriteria().getKnowledgeMasteryTarget()
                && passRate >= 0.7) {
            outcome = PlanOutcome.SUCCESS;
        } else if (masteryDelta > 0.15) {
            outcome = PlanOutcome.PARTIAL_SUCCESS;
        } else {
            outcome = PlanOutcome.INSUFFICIENT;
        }

        return PlanEvaluation.builder()
            .planId(plan.getPlanId())
            .outcome(outcome)
            .masteryBefore(beforeMastery)
            .masteryAfter(afterMastery)
            .masteryDelta(masteryDelta)
            .unitPassRate(passRate)
            .totalDaysSpent(plan.getActualDaysSpent())
            .totalMinutesSpent(plan.getActualMinutesSpent())
            .build();
    }

    private NextStep decideNextStep(UnitOutcome outcome, BreakthroughUnit unit) {
        return switch (outcome) {
            case PASSED -> NextStep.PROCEED_TO_NEXT_UNIT;
            case BORDERLINE -> NextStep.PROCEED_WITH_REVIEW;
            case FAILED -> {
                int retryCount = unit.getRetryCount();
                yield retryCount < unit.getMaxRetries()
                    ? NextStep.RETRY_UNIT_WITH_LOWER_DIFFICULTY
                    : NextStep.ESCALATE_TO_HUMAN;
            }
        };
    }
}
```

### 7.2 评估结果处理矩阵

| PlanOutcome | 掌握度变化 | 处理动作 |
| --- | --- | --- |
| SUCCESS | Δ ≥ 0.25 | ✅ 标记突破成功 → 生成成就 → 通知家长 → 归档 |
| SUCCESS | 0.15 ≤ Δ < 0.25 | ✅ 标记突破成功 → 建议巩固练习 → 归档 |
| PARTIAL_SUCCESS | 0.10 ≤ Δ < 0.15 | ⚠️ 生成补强计划（3天短计划）→ 继续干预 |
| PARTIAL_SUCCESS | Δ < 0.10 | ⚠️ 更新诊断 → 调整根因假设 → 换策略重试 |
| INSUFFICIENT | Δ < 0.05 | 🔴 升级处理 → 通知家长建议线下辅导 → AI切换辅助模式 |

## 10. 关键错误处理

### 10.1 错误码定义

| 错误码 | HTTP | 说明 | 处理方式 |
| --- | --- | --- | --- |
| `BOTTLENECK_001` | 409 | 同一知识点已有进行中的突破计划 | 返回现有 planId，前端跳转 |
| `BOTTLENECK_002` | 422 | 诊断信号不足，无法判定瓶颈类型 | 建议继续学习积累数据后重试 |
| `BOTTLENECK_003` | 408 | 突破计划确认超时（>72h未确认） | 标记 DEFERRED，14天后重新触发 |
| `BOTTLENECK_004` | 409 | 任务已被提交过（幂等冲突） | 返回已有结果 |
| `BOTTLENECK_005` | 422 | 计划依赖的前置内容缺失 | 自动降级为 AI 辅导模式 |
| `BOTTLENECK_006` | 500 | 诊断服务调用知识追踪模型超时 | 返回降级诊断（基于规则引擎） |
| `BOTTLENECK_007` | 429 | 触发频率超限（同用户24h内>3次触发） | 合并到最新触发事件 |

### 10.2 降级策略

```java
@Component
public class BottleneckFallbackHandler {

    /**
     * 诊断服务降级 — AI模型不可用时使用规则引擎
     */
    public DiagnosisResult fallbackDiagnose(TriggerEvent trigger) {
        log.warn("降级诊断触发: userId={}, reason=AI_MODEL_UNAVAILABLE",
                 trigger.getUserId());

        // 使用纯规则引擎：基于错误率、连续错误数给出基础分类
        BottleneckType type = ruleBasedClassifier(trigger);
        return DiagnosisResult.builder()
            .diagnosisId(generateId())
            .classification(Classification.builder()
                .bottleneckType(type)
                .severity(Estimator.estimateSeverity(trigger))
                .confidence(0.50) // 降级诊断置信度降低
                .build())
            .rootCause(RootCause.simpleRule(trigger, type))
            .degraded(true)
            .degradedReason("AI诊断服务暂时不可用，已使用规则引擎降级诊断")
            .build();
    }

    /**
     * 内容缺失降级 — 前置知识微课不存在时切换为纯AI辅导
     */
    public BreakthroughPlan fallbackPlan(DiagnosisResult diagnosis) {
        return BreakthroughPlan.aiOnly(diagnosis,
            "由于前置内容建设中，本次突破将以AI专项辅导为主，"
            + "每日通过AI对话进行针对性讲解和练习。");
    }
}
```

- 诊断数据在学生年满 18 岁后自动按隐私策略处理

### 13.2 批处理优化

定时巡检任务（每日 20:00）处理全量活跃用户：

```python
# 批处理架构伪代码
async def daily_bottleneck_scan():
    """每日瓶颈扫描 — 分片并行处理"""
    active_users = await get_active_users_batch(batch_size=5000)

    # 按 user_id hash 分片到不同 worker
    shards = partition(active_users, shard_count=8)

    async for shard in shards:
        tasks = [check_user_bottleneck(user) for user in shard]
        results = await asyncio.gather(*tasks, return_exceptions=True)

        # 过滤出需要触发的用户
        triggered = [r for r in results if r and not isinstance(r, Exception)]

        # 批量写入触发事件
        await batch_insert_triggers(triggered)

        # 控制下游消费速率
        await rate_limiter.acquire(len(triggered))
```

## 14. 测试策略

### 14.1 核心测试场景

| 场景 | 类型 | 验证点 |
| --- | --- | --- |
| 错误率飙升触发诊断 | 集成测试 | 5题4错后 6h 内触发且仅触发1次 |
| 前置知识缺失诊断准确性 | 单元测试 | KNOWLEDGE_GAP 分类的 precision ≥ 0.80 |
| 突破计划生成合理性 | 集成测试 | 前置知识微课排在目标知识点之前 |
| 任务失败后重试逻辑 | 单元测试 | retryCount 递增、达到上限后 ESCALATE |
| 计划超时自动放弃 | 集成测试 | 72h 未确认 → DEFERRED 状态 |
| 并发提交同一任务 | 集成测试 | 幂等控制，第二次返回已有结果 |
| AI模型不可用降级 | 集成测试 | 降级诊断 confidence 降低且不报错 |
| 计划完成后掌握度提升 | E2E 测试 | masteryDelta 计算、成就解锁 |
