# 服务端 - 教育知识点前置依赖检测与学习路径推荐服务

## 1. 模块概述

### 1.1 功能定位

本服务基于知识图谱中的知识点依赖关系（如"二次方程"依赖"一次方程"），当学生在某个知识点上表现不佳时，自动检测其前置知识是否掌握，并生成个性化的补学路径推荐。核心解决的问题是：**学生不会某道题，往往不是因为当前知识点不会，而是前置知识存在缺口**。

### 1.2 核心能力

1. **前置知识检测**：根据知识图谱的依赖边，递归查询当前知识点的前置知识链，结合学生的掌握度数据，定位真正的薄弱根因。
2. **学习路径生成**：基于学生的当前能力和目标知识点，生成一条从"当前掌握的知识"到"目标知识"的最优学习路径。
3. **缺口诊断报告**：输出一份结构化的知识缺口报告，包含缺口层级、严重程度、推荐补学顺序。
4. **路径动态调整**：随着学生补学进度的推进，实时更新推荐路径，跳过已掌握的中间节点。

### 1.3 在系统中的位置

```
知识图谱构建引擎 ──→ 知识点依赖关系数据 ──→ 本服务
                                               │
用户学习画像 ──────→ 知识点掌握度数据 ──────→ 本服务
                                               │
AI辅导引擎 ────────→ "学生不懂二次方程求根" ──→ 本服务
                                               ├──→ 缺口诊断报告（返回给 AI 辅导引擎）
                                               ├──→ 补学路径（返回给学习规划模块）
                                               └──→ 前置知识列表（返回给同步课堂模块）
```

### 1.4 与其他模块的关系

| 关联模块 | 交互方式 | 说明 |
|----------|----------|------|
| 知识点图数据库建模与图查询服务 | 读取 | 获取知识点依赖关系图 |
| 用户学习画像与能力维度模型 | 读取 | 获取学生各知识点的掌握度 |
| AI辅导全链路请求处理与编排设计 | 被调用 | AI辅导发现学生不理解时请求前置分析 |
| 学习规划模块 | 被调用 | 将补学路径转化为学习任务 |
| 同步课堂学习模块 | 被调用 | 推荐学生应先复习的前置章节 |
| 错题整理模块 | 被调用 | 根据错题归因触发前置检测 |
| 练习与测评系统 | 被调用 | 根据前置掌握度推荐练习 |

## 2. 数据模型

### 2.1 知识点依赖关系（存储于图数据库）

依赖关系由知识图谱构建引擎维护，本服务只读取。

```cypher
// 图数据库中的节点和边结构（已有，本服务查询用）
(:KnowledgePoint {
  id: "kp_001",
  name: "一元二次方程求根公式",
  subject: "math",
  grade_level: 8,           // 初二年级
  difficulty: 0.65,         // 难度系数 0-1
  textbook_id: "tb_pep_8",
  chapter_id: "ch_16_2"
})

// PREREQUISITE 边：A 是 B 的前置知识
(:KnowledgePoint {id: "kp_001"})-[:PREREQUISITE {
  strength: 0.9,            // 依赖强度 0-1
  mandatory: true           // 是否必须掌握的前置
}]->(:KnowledgePoint {id: "kp_002"})
```

```typescript

interface KnowledgeGap {
  knowledgeId: string;           // 知识点ID
  knowledgeName: string;         // 知识点名称
  depth: number;                 // 距离目标知识点的层级（1=直接前置, 2=前置的前置...）
  masteryLevel: number;          // 学生当前掌握度 0~1
  masteryThreshold: number;      // 达标阈值（通常 0.6）
  isGap: boolean;                // 是否判定为缺口
  mandatory: boolean;            // 是否为必须前置
  prerequisiteStrength: number;  // 依赖强度 0~1
  difficulty: number;             // 难度系数 0~1（预估补学时长加权用，v1.1 新增 F2）
  confidence: number;            // 掌握度置信度（答题次数太少时置信度低）
  subject: string;
  gradeLevel: number;
  textbookId: string;
  chapterId: string;
}

interface GapDiagnosisReport {
  studentId: number;
  targetKnowledgeId: string;
  targetKnowledgeName: string;
  triggerSource: 'ai_tutor' | 'error_book' | 'practice' | 'manual';
  detectionTimestamp: string;        // ISO 8601
  maxDepth: number;
  totalPrerequisites: number;        // 检测的前置总数
  gapsFound: number;
  criticalGaps: number;              // 必须掌握但未掌握的缺口数
  gaps: KnowledgeGap[];              // 按层级排序的缺口列表
  rootCauses: string[];              // 最底层根因知识点ID列表
  recommendation: DiagnosisRecommendation;

  estimatedEffort: number;           // 预估补学时长（分钟）

  estimatedMinutes: number;          // 预估总时长

  expiresAt: string;

  status: 'pending' | 'in_progress' | 'mastered' | 'skipped';
  masteryLevel: number;
  masteryThreshold: number;
  isCritical: boolean;               // 是否为关键路径节点
  suggestedActivities: LearningActivity[];
}

  type: 'review_chapter' | 'watch_explanation' | 'practice_basic' | 'practice_intermediate';
  description: string;
  estimatedMinutes: number;
```

## 4. 核心算法

### 4.1 前置知识缺口检测算法

```python
class PrerequisiteDetector:
    """
    前置知识缺口检测器
    
    核心思路：BFS/DFS 遍历知识图谱的 PREREQUISITE 边，
    结合学生的掌握度数据，识别未达标的前置知识点。
    """
    
    def __init__(
        self,
        graph_client: GraphDatabaseClient,    # 图数据库客户端
        mastery_repo: MasteryRepository,       # 掌握度数据仓库
        config: DetectionConfig,
    ):
        self.graph = graph_client
        self.mastery = mastery_repo
        self.config = config
    
    async def detect(
        self,
        student_id: int,
        target_kp_id: str,
        max_depth: int = 3,
        mastery_threshold: float = 0.6,
        min_confidence: float = 0.3,
    ) -> GapDiagnosisReport:
        """
        执行前置知识缺口检测。
        
        算法：带剪枝的广度优先遍历
        1. 从目标知识点出发，沿 PREREQUISITE 边向外扩展
        2. 每层检查学生的掌握度是否低于阈值
        3. 如果某个前置知识点已掌握且为唯一路径，则剪枝不再深入
        4. 如果某个前置知识点未掌握但置信度太低（答题次数不足），
           标记为"待验证"而非确定缺口
        """
        # Step 1: 图查询返回邻接表 {kp_id: [直接前置边...]}，仅含 max_depth 层内节点
        # （修复 v1.0 F1：原实现按层号取前置与实际图结构不符，
        #   正确做法是邻接表按当前节点查其直接前置）
        adjacency: dict[str, list[dict]] = (
            await self.graph.get_prerequisite_adjacency(
                target_kp_id, max_depth=max_depth
            )
        )
        
        kp_ids = {target_kp_id}
        for edges in adjacency.values():
            kp_ids.update(e['knowledgeId'] for e in edges)
        
        # 批量获取掌握度（减少DB查询次数）
        mastery_map = await self.mastery.batch_get_mastery(
            student_id, list(kp_ids)
        )
        
        # Step 2: BFS 遍历，标记缺口
        gaps: list[KnowledgeGap] = []
        visited: set[str] = set()
        root_causes: list[str] = []
        
        # 队列：(当前知识点ID, 当前深度)
        queue = deque()
        queue.append((target_kp_id, 0))
        visited.add(target_kp_id)
        
        while queue:
            current_kp, depth = queue.popleft()
            
            if depth >= max_depth:
                continue
            
            # 从邻接表 O(1) 获取 current_kp 的直接前置
            for prereq in adjacency.get(current_kp, []):
                if prereq['knowledgeId'] in visited:
                    continue
                visited.add(prereq['knowledgeId'])
                
                # 获取掌握度
                mastery_data = mastery_map.get(prereq['knowledgeId'])
                mastery_level = mastery_data.mastery_level if mastery_data else 0.0
                confidence = mastery_data.confidence if mastery_data else 0.0
                
                is_gap = mastery_level < mastery_threshold
                
                gap = KnowledgeGap(
                    knowledge_id=prereq['knowledgeId'],
                    knowledge_name=prereq['name'],
                    depth=depth + 1,
                    mastery_level=mastery_level,
                    mastery_threshold=mastery_threshold,
                    is_gap=is_gap,
                    mandatory=prereq.get('mandatory', True),
                    prerequisite_strength=prereq.get('strength', 1.0),
                    confidence=confidence,
                    difficulty=prereq.get('difficulty', 0.5),  # F2：按难度加权预估时长
                    subject=prereq.get('subject', ''),
                    grade_level=prereq.get('grade_level', 0),
                    textbook_id=prereq.get('textbook_id', ''),
                    chapter_id=prereq.get('chapter_id', ''),
                )
                
                if is_gap:
                    gaps.append(gap)
                    
                    # 判断是否为根因：其直接前置均已掌握或不存在更深层前置
                    deeper = adjacency.get(prereq['knowledgeId'], [])
                    has_deeper_gap = False
                    for d in deeper:
                        dm = mastery_map.get(d['knowledgeId'])
                        dm_level = dm.mastery_level if dm else 0.0
                        if dm_level < mastery_threshold:
                            has_deeper_gap = True
                            break
                    if not has_deeper_gap or depth + 1 == max_depth:
                        root_causes.append(prereq['knowledgeId'])
                    
                    # 未掌握的前置需要继续深入检查其前置
                    queue.append((prereq['knowledgeId'], depth + 1))
                else:
                    # 已掌握的前置：如果是 mandatory 且已充分掌握，可以剪枝
                    # 但如果是 non-mandatory 的，不剪枝（可能还有其他路径）
                    if prereq.get('mandatory', True) and confidence >= min_confidence:
                        pass  # 剪枝，不继续深入
                    else:
                        queue.append((prereq['knowledgeId'], depth + 1))
        
        # Step 3: 生成推荐
        recommendation = self._generate_recommendation(
            gaps, root_causes, mastery_threshold
        )
        
        return GapDiagnosisReport(
            student_id=student_id,
            target_knowledge_id=target_kp_id,
            target_knowledge_name=await self.graph.get_kp_name(target_kp_id),
            trigger_source='',  # 由调用方填充
            detection_timestamp=datetime.utcnow().isoformat(),
            max_depth=max_depth,
            total_prerequisites=len(visited) - 1,  # 排除目标知识点自身
            gaps_found=len(gaps),
            critical_gaps=len([g for g in gaps if g.mandatory]),
            gaps=sorted(gaps, key=lambda g: (g.depth, -g.prerequisite_strength)),
            root_causes=root_causes,
            recommendation=recommendation,
        )
    
    def _generate_recommendation(
        self,
        gaps: list[KnowledgeGap],
        root_causes: list[str],
        threshold: float,
    ) -> DiagnosisRecommendation:
        """
        根据缺口情况生成推荐动作。
        
        决策逻辑：
        - 无缺口 → no_action
        - 仅有1层浅层缺口且数量≤2 → immediate_prerequisite
        - 缺口数量多或有多层深层缺口 → deep_remedy
        - 缺口是非强制性的且掌握度接近阈值 → continue_with_support
        """
        if not gaps:
            return DiagnosisRecommendation(
                action='no_action',
                priority_gaps=[],
                estimated_effort=0,
                suggested_learning_mode='review',
                message='未发现前置知识缺口，可以继续学习当前知识点。',
            )
        
        critical_gaps = [g for g in gaps if g.mandatory]
        shallow_gaps = [g for g in gaps if g.depth == 1]
        deep_gaps = [g for g in gaps if g.depth > 1]
        
        # 按优先级排序：先深层（根因），再浅层；同层按依赖强度降序
        priority_gaps = sorted(
            gaps,
            key=lambda g: (-g.depth, -g.prerequisite_strength, g.mastery_level),
        )
        priority_gap_ids = [g.knowledge_id for g in priority_gaps]
        
        # 预估补学时长：每个缺口按 基础时长 × 难度系数 × 缺口比例 累加（修复 v1.0 F2）
        BASE_MINUTES = self.config.base_minutes              # 单知识点基础补学时长（分钟）
        estimated = 0.0
        for g in priority_gaps:
            difficulty_factor = 1.0 + g.difficulty * 0.5     # 难度 0~1 → 系数 1.0~1.5
            gap_factor = 1.0 - min(g.mastery_level, 0.9)     # 缺口越大耗时越长
            estimated += BASE_MINUTES * difficulty_factor * (0.5 + gap_factor)
        # 向上取整到 5 分钟，最低 5 分钟
        estimated_effort = max(5, int(math.ceil(estimated / 5.0) * 5))
        
        # 决策动作
        if not critical_gaps and all(
            g.mastery_level >= threshold - 0.1 for g in gaps
        ):
            action = 'continue_with_support'
            learning_mode = 'guided_practice'
        elif len(gaps) <= 2 and not deep_gaps:
            action = 'immediate_prerequisite'
            learning_mode = 'review'
        else:
            action = 'deep_remedy'
            learning_mode = 'relearn'
        
        # 生成话术（成长型表述红线：只描述知识缺口，不评价学生能力）
        names = '、'.join(g.knowledge_name for g in priority_gaps[:3])
        if action == 'continue_with_support':
            message = (f'前置知识整体接近达标，建议继续学习当前知识点，'
                       f'同时穿插练习巩固：{names}。')
        elif action == 'immediate_prerequisite':
            message = (f'发现少量前置知识缺口：{names}。'
                       f'建议先快速复习以上知识点，再继续当前内容。')
        else:
            message = (f'检测到较深层的前置知识缺口，根源可能在：{names}。'
                       f'建议按推荐顺序从基础开始补学，再进入当前知识点。')
        
        # 低置信度标注：掌握度样本不足的缺口，话术追加验证提示
        low_conf = [g for g in gaps if g.confidence < self.config.min_confidence]
        if low_conf:
            conf_names = '、'.join(g.knowledge_name for g in low_conf[:3])
            message += (f'（注：{conf_names}的掌握度样本较少，'
                        f'建议先通过少量练习验证实际水平。）')
        
        return DiagnosisRecommendation(
            action=action,
            priority_gaps=priority_gap_ids,
            estimated_effort=estimated_effort,
            suggested_learning_mode=learning_mode,
            message=message,
        )
```

### 4.1.2 邻接表图查询实现（Cypher + 图客户端）

`get_prerequisite_adjacency` 是检测算法的读模型入口，一次查询取回目标知识点 `max_depth` 层闭包内的全部依赖边：

```cypher
// ADJACENCY_CYPHER：返回 {知识点ID: [直接前置...]} 邻接表
// $targetId 目标知识点ID, $maxDepth 检测深度（≤5）
MATCH (t:KnowledgePoint {id: $targetId})<-[:PREREQUISITE*0..3]-(n:KnowledgePoint)
WITH collect(DISTINCT n.id) AS ballIds
MATCH (pre:KnowledgePoint)-[r:PREREQUISITE]->(cur:KnowledgePoint)
WHERE cur.id IN ballIds AND pre.id IN ballIds
RETURN cur.id AS nodeId,
       collect({
           knowledgeId: pre.id,
           name:        pre.name,
           mandatory:   r.mandatory,      // 依赖边属性：是否必须
           strength:    r.strength,       // 依赖边属性：依赖强度 0~1
           difficulty:  pre.difficulty,
           subject:     pre.subject,
           gradeLevel:  pre.grade_level,
           textbookId:  pre.textbook_id,
           chapterId:   pre.chapter_id
       }) AS prereqs
```

### 4.2 补学路径生成算法

```python
class LearningPathPlanner:
    """
    补学路径生成器。

    算法（Kahn 拓扑排序 + 层级优先级）：
    1. 候选节点 = 诊断报告中的缺口（is_gap=true）；include_optional=false 时
       仅保留 mandatory 缺口
    2. 二次校验掌握度：检测与生成之间可能已隔数小时（期间学生补学过），
       剔除当前已达标的节点
    3. 建图：仅保留候选节点之间的依赖边
    4. Kahn 拓扑排序，零入度节点按 (depth 降序, strength 降序) 出队——
       先补深层根因，再补浅层（根因不补，浅层学了也稳不住）
    5. 截断到 max_steps：mandatory 节点优先保留
    6. 末尾追加目标知识点本身作为最后一步
    """

    async def plan(
        self,
        student_id: int,
        target_kp_id: str,
        gap_report: GapDiagnosisReport,
        max_steps: int = 8,
        include_optional: bool = False,
    ) -> LearningPath:
        candidates = [g for g in gap_report.gaps if g.is_gap]
        if not include_optional:
            candidates = [g for g in candidates if g.mandatory]

        # 二次校验：剔除补学过程中已达标的节点
        if candidates:
            mastered_now = await self.mastery.filter_mastered(
                student_id, [g.knowledge_id for g in candidates]
            )
            candidates = [g for g in candidates
                          if g.knowledge_id not in mastered_now]

        node_ids = {g.knowledge_id for g in candidates}
        adjacency = await self.graph.get_prerequisite_adjacency(
            target_kp_id, max_depth=gap_report.max_depth + 1
        )

        # 入度 = 候选集合中本节点的前置数量（候选之外的前置不计，已被剔除）
        indeg: dict[str, int] = {g.knowledge_id: 0 for g in candidates}
        for g in candidates:
            for pre in adjacency.get(g.knowledge_id, []):
                if pre['knowledgeId'] in node_ids:
                    indeg[g.knowledge_id] += 1

        # Kahn：优先级堆，depth 降序 → strength 降序（heapq 最小堆取反实现）
        heap: list[tuple] = []
        by_id = {g.knowledge_id: g for g in candidates}
        for g in candidates:
            if indeg[g.knowledge_id] == 0:
                heapq.heappush(heap, (-g.depth, -g.prerequisite_strength, g.knowledge_id))

        ordered: list[KnowledgeGap] = []
        released: set[str] = set()
        while heap and len(ordered) < max_steps:
            _, _, kid = heapq.heappop(heap)
            if kid in released:
                continue
            released.add(kid)
            ordered.append(by_id[kid])
            # 释放后继：g 是 cur 的前置 ⇒ cur 入度 -1
            for cur_id in node_ids - released:
                if any(e['knowledgeId'] == kid
                       for e in adjacency.get(cur_id, [])):
                    indeg[cur_id] -= 1
                    if indeg[cur_id] == 0:
                        ng = by_id[cur_id]
                        heapq.heappush(
                            heap, (-ng.depth, -ng.prerequisite_strength, cur_id)
                        )

        # 截断时 mandatory 优先保留（ordered 已被截断则重排）
        truncated = len(released) < len(candidates)
        if truncated:
            ordered.sort(key=lambda g: (not g.mandatory,))

        nodes = [
            LearningPathNode(
                step=i + 1,
                knowledge_id=g.knowledge_id,
                knowledge_name=g.knowledge_name,
                status='pending',
                mastery_level=g.mastery_level,
                mastery_threshold=g.mastery_threshold,
                is_critical=g.mandatory,
                suggested_activities=self._suggest_activities(g),
            )
            for i, g in enumerate(ordered)
        ]
        # 目标知识点作为最后一步
        target_gap = next(
            (g for g in gap_report.gaps if g.knowledge_id == target_kp_id),
            None,
        )
        nodes.append(LearningPathNode(
            step=len(nodes) + 1,
            knowledge_id=target_kp_id,
            knowledge_name=gap_report.target_knowledge_name,
            status='pending',
            mastery_level=target_gap.mastery_level if target_gap else 0.0,
            mastery_threshold=self.config.mastery_threshold,
            is_critical=True,
            suggested_activities=[LearningActivity(
                type='practice_intermediate',
                description=f'{gap_report.target_knowledge_name}综合练习',
                estimated_minutes=15,
                resource_refs=[],
            )],
        ))

        total_minutes = sum(
            a.estimated_minutes for n in nodes for a in n.suggested_activities
        )
        return LearningPath(
            path_id=self._id_gen.next_id('path'),     # 分布式唯一ID服务
            student_id=student_id,
            target_knowledge_id=target_kp_id,
            target_knowledge_name=gap_report.target_knowledge_name,
            nodes=nodes,
            total_steps=len(nodes),
            estimated_minutes=total_minutes,
            created_at=datetime.utcnow().isoformat(),
            expires_at=(datetime.utcnow() + timedelta(days=7)).isoformat(),
        )

    def _suggest_activities(self, g: KnowledgeGap) -> list[LearningActivity]:
        """按缺口程度推荐学习活动（资源引用由内容服务解析）。"""
        refs = [ {'chapterId': g.chapter_id} ] if g.chapter_id else []
        if g.mastery_level < 0.3:      # 几乎不会 → 先看 AI 讲解再练基础
            return [
                LearningActivity('watch_explanation',
                                 f'AI讲解{g.knowledge_name}', 10, refs),
                LearningActivity('practice_basic',
                                 f'{g.knowledge_name}基础练习（5题）', 10, refs),
            ]
        # 接近达标 → 复习章节 + 基础练习
        return [
            LearningActivity('review_chapter',
                             f'复习{g.knowledge_name}', 10, refs),
            LearningActivity('practice_basic',
                             f'{g.knowledge_name}基础练习（5题）', 10, refs),
        ]
```

**关键点说明：**

1. **二次校验（§4.2 第 2 步）是幂等防错的核心**：掌握度由练习/测评引擎持续更新，检测报告的 `mastery_level` 是检测时刻的快照，生成路径时必须以最新值过滤，否则会出现"路径第一步就是已掌握内容"的坏体验（验收 AC03）。
2. **先根因后浅层**：排序键取 `depth` 降序，与直觉相反。原因：若只补浅层（如直接前置"一元二次方程概念"），深层根因（"一元一次方程"）缺口仍在，补完仍会错；先根因后浅层的顺序使后续学习可"搭积木"向上支撑。
3. **截断保护**：`max_steps` 默认 8。若缺口过多被截断，mandatory 优先保留；`totalEstimatedEffort` 超过 120 分钟时建议拆分多次学习（由学习规划模块决定，本服务只在 `estimated_minutes` 上如实上报）。
4. 批量检测（§3.5）在多目标场景下先做**缺口去重合并**（`mergedPriorityGaps`），再统一调用一次 `plan`，避免同一前置知识点在多条路径中重复出现。

### 4.3 路径动态调整与增量重规划

路径不是一次生成后静态执行。两类动态调整：

**A. 掌握度驱动的跳步（skip）**：学生在路径外练习达标 → 对应节点应自动跳过，避免无效学习。
**B. 中途新发现的缺口插入（insert）**：路径执行中 AI 辅导发现新的深层缺口 → 需要插入新节点并保持拓扑有序。

```sql
UPDATE learning_path_tracking
SET path_nodes = jsonb_set(
        path_nodes,
        ARRAY[(idx - 1)::text, 'status'],
        '"skipped"'::jsonb

    revision = revision + 1,
    updated_at = NOW()
FROM (
    SELECT path_id AS pid, ord - 1 AS idx
    FROM learning_path_tracking,
         jsonb_array_elements(path_nodes) WITH ORDINALITY AS t(elem, ord)
    WHERE path_id = $1
      AND elem->>'knowledgeId' = $2
) sub
WHERE learning_path_tracking.path_id = sub.pid
  AND status = 'active'
  AND revision = $3
  AND path_nodes -> sub.idx ->>'status' IN ('pending', 'in_progress')
```

```sql
UPDATE learning_path_tracking
SET path_nodes = (
        SELECT jsonb_agg(elem ORDER BY (elem->>'step')::int)
        FROM (
            SELECT CASE
                       WHEN (elem->>'step')::int >= $2
                       THEN jsonb_set(elem, '{step}',
                              to_jsonb((elem->>'step')::int + 1))
                       ELSE elem

        ) s
    ) || jsonb_build_object(
           'step', $2, 'knowledgeId', $4, 'knowledgeName', $5,
           'status', 'pending', 'masteryLevel', $6,
           'masteryThreshold', $7, 'isCritical', $8,
           'suggestedActivities', $9::jsonb),
    total_steps = total_steps + 1,
    revision = revision + 1
WHERE path_id = $1 AND status = 'active' AND revision = $3;
```

## 5. 状态流转与守卫

### 5.1 路径状态机

```
                    ┌────────── 全部节点 mastered/skipped ──────────┐
                    │                                               ▼
  (创建) ──→ active ──→ completed（终态）
               │   │
               │   ├──── 学生/家长主动放弃 ────→ abandoned（终态）
               │   │
               │   └──── expires_at 到期（定时任务）────→ expired（终态）
               │
               └──── 目标知识点被下架/删除（监听 KG 事件）──→ expired（终态）
```

**终态不可逆。** `expired` 不区分原因，详情写入运维日志。

### 5.2 步骤状态机

```
                 ┌────────── 开始学习 ──────────┐
                 │                              ▼
  (建路径) ──→ pending ──────────────────→ in_progress
                 │                              │
                 │ 掌握度达标事件（仅系统）        │ 掌握度达标/完成上报
                 ▼                              ▼
              skipped（终态）              mastered（终态）
```

- `skipped` 只能由系统通过 §4.3 CAS 置位，客户端不可直接上报（守卫 G7）。
- 两个终态均不可逆；重复上报同值视为幂等成功（守卫 G5）。

### 5.3 守卫规则表

| 编号 | 规则 | 违反时错误码 |
|------|------|--------------|
| G1 | 步骤状态只能从 pending/in_progress → mastered | 52113 |
| G2 | 路径处于 completed/abandoned/expired 时禁止一切写操作 | 52114 |
| G3 | step 必须在 [1, total_steps] 区间内 | 52112 |
| G4 | 客户端上报 mastered 需携带 masteryLevel，服务端校验 ∈ [threshold, 1] | 52113 |
| G5 | 节点已是 mastered 且 masteryLevel 变化 < 0.01 → 幂等返回成功 | —（返回 0） |
| G6 | expired 仅由定时任务/KG 下架事件置位，客户端不可上报 | 52113 |
| G7 | skipped 仅系统可置（§4.3 CAS），客户端上报 skipped 一律拒绝 | 52113 |
| G8 | 路径创建按 (student_id, client_request_id) 幂等，重试返回原路径 | —（返回原 pathId） |
| G9 | detect 按 request_id 幂等：10 分钟内同 requestId 重试返回首次报告（cached=true） | — |
| G10 | 目标知识点被 KG 引擎下架（kp.status != active）时，新建路径拒绝、存量路径置 expired | 52101 |

## 7. 幂等、事务与事件扇出

### 7.1 幂等 DDL 追加（v1.1 修复 F3）

```sql
-- 路径表：幂等键 + 乐观锁版本
ALTER TABLE learning_path_tracking
    ADD COLUMN client_request_id VARCHAR(64),
    ADD COLUMN revision          INTEGER NOT NULL DEFAULT 0;

-- 部分唯一索引：client_request_id 非空时 (student_id, client_request_id) 唯一
-- （PG 中 NULL 不参与唯一约束，历史无键数据不受影响）
CREATE UNIQUE INDEX uk_lpt_client_req
    ON learning_path_tracking (student_id, client_request_id)
    WHERE client_request_id IS NOT NULL;

-- 检测日志表：请求级幂等 + 图谱版本留痕
ALTER TABLE prerequisite_detection_log
    ADD COLUMN request_id  VARCHAR(64),
    ADD COLUMN kg_version  VARCHAR(32);

CREATE UNIQUE INDEX uk_pdl_request
    ON prerequisite_detection_log (request_id)
    WHERE request_id IS NOT NULL;
```

### 7.2 幂等场景裁决

| 场景 | 裁决 |
|------|------|
| detect 网络重试（同 requestId） | G9：10 分钟内命中 uk_pdl_request，直接返回首次报告（`cached=true`），不重复写日志；超过 10 分钟视为新检测 |
| 路径创建重试（同 clientRequestId） | G8：命中 uk_lpt_client_req，返回已创建路径原样响应 |
| 步骤上报重试 | G5：终态同值幂等成功；异值（masteryLevel 变化 ≥0.01）按新事件处理并刷新 |
| 过期任务与手动完成竞态 | 双方均以 `UPDATE ... WHERE status='active'` 为闸门，先成功者生效，另一方影响行数=0 → 52114/52111 |
| 掌握度跳步与手动 mastered 并发 | §4.3 CAS 的 revision+状态双重校验，后到者收到 52115 后读最新态重试 |

### 7.3 事务边界与 Outbox 事件

所有写操作遵循「**本地事务 + Outbox 同表写入**」模式（事件驱动架构统一规范）：

| 事件 | 触发点 | 关键字段 | 消费方 | 消费用途 |
|------|--------|----------|--------|----------|
| prerequisite.gap_detected | detect 落日志 | studentId, targetKpId, gaps[], action, triggerSource | 学习规划引擎 / 家长学情聚合 / AI 辅导编排 | 生成补学任务 / 周报素材 / 辅导上下文注入 |
| learning_path.created | plan 入库 | pathId, studentId, targetKpId, totalSteps, estimatedMinutes | 学习规划引擎 | 任务列表刷新 |
| learning_path.step_mastered | 步骤终态 CAS 成功 | pathId, step, kpId, masteryLevel | 激励引擎 / 掌握度引擎 | 补学成就判定 / 交叉校验 |
| learning_path.completed | 末节点终态 | pathId, studentId, targetKpId, actualMinutes | 学情报告 / 激励引擎 | 阶段报告素材 / 路径完成成就 |
| learning_path.expired | 定时任务/KG 下架 | pathId, reason | 学习规划引擎 | 重新规划触发 |

消费方一律按 `event_id` 幂等去重（D8 重试不重复消费）。
