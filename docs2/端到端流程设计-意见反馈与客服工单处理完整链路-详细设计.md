# 端到端流程设计：意见反馈与客服工单处理完整链路

> 本文档描述 PrimeTop 用户从发现问题到问题解决的全链路设计，涵盖反馈提交、智能分流、工单处理、AI质量回溯、用户通知等完整闭环。

---

## 1. 流程概览

### 1.1 端到端旅程图

```text
用户发现问题
    │
    ├─ AI回答有误 ──────────┐
    ├─ 拍照识别不准 ────────┤
    ├─ 内容错误/不适 ──────┤
    ├─ 功能Bug/闪退 ────────┤
    ├─ 会员/支付问题 ──────┤
    └─ 其他建议/投诉 ──────┘
                            │
                    ┌───────▼───────┐
                    │  反馈入口选择  │
                    │ (场景化触发)   │
                    └───────┬───────┘
                            │
                    ┌───────▼───────┐
                    │  反馈表单填写  │
                    │ (智能预填+附件)│
                    └───────┬───────┘
                            │
                    ┌───────▼────────┐
                    │  前置智能处理   │
                    │ (FAQ匹配/自动答)│
                    └──┬────────┬────┘
                  匹配  │        │ 未匹配
                  FAQ   │        │
                    ┌───▼──┐ ┌──▼─────────┐
                    │返回答案│ │ 工单创建    │
                    └──────┘ │ (自动分类+  │
                             │  优先级判定) │
                             └──┬─────────┘
                                │
                     ┌──────────▼──────────┐
                     │  工单路由与分配      │
                     │ (按类型→处理队列)    │
                     └──┬───────┬──────────┘
                        │       │
              ┌─────────▼┐  ┌──▼──────────┐
              │ 人工处理   │  │ AI辅助处理   │
              │ (客服/教研)│  │ (自动分析)   │
              └─────┬─────┘  └──────┬──────┘
                    │               │
              ┌─────▼───────────────▼────┐
              │  问题解决 & 知识回流       │
              │ (更新FAQ/修正AI/修复Bug)  │
              └───────────┬──────────────┘
                          │
              ┌───────────▼──────────┐
              │  用户通知 & 满意度评价 │
              └──────────────────────┘
```

### 1.2 触发场景矩阵

| 场景 | 触发位置 | 反馈类型 | 自动携带信息 |
| --- | --- | --- | --- |
| AI回答有误 | AI对话页→回答底部反馈按钮 | AI质量反馈 | 对话ID、问题原文、AI回答原文、模型标识、Prompt模板ID |
| 拍照识别不准 | 拍题结果页→识别反馈 | OCR质量反馈 | 图片URL、识别结果、原始题目文本（用户修正后） |
| 题目解析错误 | 解析页→报错按钮 | 内容纠错 | 题目ID、解析内容、错误类型 |
| 内容不适/违规 | 任意内容页→举报按钮 | 内容举报 | 内容ID、内容快照、举报原因 |
| 功能Bug | 设置页→意见反馈 / 异常弹窗 | Bug反馈 | 设备信息、App版本、系统版本、崩溃日志、页面路径 |
| 会员/支付问题 | 会员中心→帮助 / 订单详情页 | 支付反馈 | 订单ID、支付渠道、支付时间、金额 |
| 体验建议 | 设置页→意见反馈 | 产品建议 | 用户画像摘要（年级、学段、会员状态） |
| AI对话涉敏 | AI对话页→举报按钮 | 安全举报 | 对话ID、消息内容快照、安全策略版本 |

## 2. 数据结构设计

### 2.1 反馈记录表 (feedback_record)

```sql
CREATE TABLE feedback_record (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '反馈ID',
    feedback_no         VARCHAR(32) NOT NULL UNIQUE COMMENT '反馈编号 FB{yyyyMMdd}{6位序号}',
    user_id             BIGINT NOT NULL COMMENT '提交用户ID',
    student_id          BIGINT COMMENT '关联学生ID（家长账号时）',
    
    -- 反馈分类
    feedback_type       TINYINT NOT NULL COMMENT '反馈类型: 1=AI质量 2=OCR质量 3=内容纠错 4=内容举报 5=Bug反馈 6=支付问题 7=产品建议 8=安全举报',
    feedback_subtype    VARCHAR(32) COMMENT '子类型: 如AI质量下的 解题错误/概念错误/引导不当/答案泄露',
    severity            TINYINT NOT NULL DEFAULT 2 COMMENT '严重程度: 1=紧急 2=一般 3=轻微',
    
    -- 反馈内容
    title               VARCHAR(200) NOT NULL COMMENT '反馈标题（自动生成或用户填写）',
    content             TEXT COMMENT '用户详细描述',
    attachments         JSON COMMENT '附件列表 [{type:image/video/log, url:string, size:int}]',
    
    -- 上下文信息
    context             JSON NOT NULL COMMENT '场景上下文（按类型不同携带不同字段）',
    app_version         VARCHAR(20) COMMENT 'APP版本号',
    device_info         JSON COMMENT '设备信息 {os, model, screen, network, memory, storage}',
    page_path           VARCHAR(200) COMMENT '反馈所在页面路径',
    session_id          VARCHAR(64) COMMENT '用户会话ID',
    
    -- 前置处理
    faq_matched         BOOLEAN DEFAULT FALSE COMMENT '是否匹配到FAQ',
    faq_id              BIGINT COMMENT '匹配的FAQ ID',
    auto_resolved       BOOLEAN DEFAULT FALSE COMMENT '是否自动解决',
    
    -- 工单关联
    ticket_id           BIGINT COMMENT '关联工单ID（创建工单后填写）',
    
    -- 用户满意度
    user_rating         TINYINT COMMENT '用户评价: 1-5星',
    user_rating_comment VARCHAR(500) COMMENT '用户评价文字',
    
    -- 状态与时间
    status              TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 1=待处理 2=已匹配FAQ 3=已转工单 4=处理中 5=已回复 6=已关闭 7=已撤回',
    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_user_id (user_id),
    INDEX idx_type_status (feedback_type, status),
    INDEX idx_created (created_at),
    INDEX idx_ticket (ticket_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户反馈记录表';
```

### 2.2 工单表 (support_ticket)

```sql
CREATE TABLE support_ticket (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '工单ID',
    ticket_no           VARCHAR(32) NOT NULL UNIQUE COMMENT '工单编号 TK{yyyyMMdd}{6位序号}',
    feedback_id         BIGINT COMMENT '来源反馈ID',
    user_id             BIGINT NOT NULL COMMENT '提交用户ID',
    
    -- 工单分类
    category            TINYINT NOT NULL COMMENT '一级分类: 同feedback_type',
    subcategory         VARCHAR(32) COMMENT '二级分类',
    priority            TINYINT NOT NULL DEFAULT 2 COMMENT '优先级: 1=紧急(P0) 2=高(P1) 3=中(P2) 4=低(P3)',
    
    -- 工单内容
    title               VARCHAR(200) NOT NULL COMMENT '工单标题',
    description         TEXT NOT NULL COMMENT '工单描述（由反馈内容+系统信息组装）',
    attachments         JSON COMMENT '附件列表',
    
    -- 路由与分配
    queue_id            INT COMMENT '处理队列ID',
    assignee_id         BIGINT COMMENT '当前处理人ID（客服/教研/开发）',
    assignee_type       TINYINT COMMENT '处理人类型: 1=客服 2=教研 3=开发 4=运营',
    team_id             INT COMMENT '负责团队ID',
    
    -- AI辅助
    ai_analysis         JSON COMMENT 'AI自动分析结果 {summary, suggested_action, related_tickets, affected_users}',
    ai_suggested_reply  TEXT COMMENT 'AI建议的回复内容',
    
    -- 关联信息
    related_tickets     JSON COMMENT '关联工单ID列表',
    related_feedbacks   JSON COMMENT '关联反馈ID列表（合并工单时）',
    escalation_count    TINYINT DEFAULT 0 COMMENT '升级次数',
    
    -- 处理结果
    resolution          TEXT COMMENT '处理结果描述',
    resolution_type     TINYINT COMMENT '解决类型: 1=直接回复 2=FAQ更新 3=内容修正 4=Bug修复 5=退款 6=解释说明',
    resolved_by         BIGINT COMMENT '解决人ID',
    resolved_at         DATETIME COMMENT '解决时间',
    
    -- 时间追踪
    first_response_at   DATETIME COMMENT '首次响应时间',
    sla_due_at          DATETIME COMMENT 'SLA截止时间',
    
    -- 状态
    status              TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 1=待分配 2=待处理 3=处理中 4=待用户确认 5=已解决 6=已关闭 7=已合并',
    status_history      JSON COMMENT '状态变更历史 [{from, to, by, at, reason}]',
    
    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_user (user_id),
    INDEX idx_status_priority (status, priority),
    INDEX idx_assignee (assignee_id, status),
    INDEX idx_queue (queue_id, status),
    INDEX idx_sla (sla_due_at),
    INDEX idx_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='客服工单表';
```

### 2.3 工单处理记录表 (ticket_interaction)

```sql
CREATE TABLE ticket_interaction (

```

### 2.4 FAQ知识库表 (faq_knowledge)

```sql
CREATE TABLE faq_knowledge (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT 'FAQ ID',
    question_pattern    VARCHAR(500) NOT NULL COMMENT '问题模式（支持模糊匹配）',
    answer              TEXT NOT NULL COMMENT '标准答案',
    
    -- 匹配配置
    keywords            JSON COMMENT '关键词列表 ["拍照","识别","不准"]',
    feedback_types      JSON COMMENT '适用的反馈类型 [1,2,5]',
    intent_tags         JSON COMMENT '意图标签 ["refund","login","crash"]',
    match_priority      INT DEFAULT 100 COMMENT '匹配优先级（数值小优先）',
    
    -- 适用范围
    applicable_grades   JSON COMMENT '适用学段/年级',
    applicable_platform JSON COMMENT '适用平台 ["android","ios"]',
    
    -- 统计
    match_count         INT DEFAULT 0 COMMENT '匹配次数',
    resolve_rate        DECIMAL(5,2) DEFAULT 0 COMMENT 'FAQ解决率(%)',
    helpful_count       INT DEFAULT 0 COMMENT '有帮助点击数',
    not_helpful_count   INT DEFAULT 0 COMMENT '无帮助点击数',
    
    -- 状态
    status              TINYINT DEFAULT 1 COMMENT '1=启用 2=禁用 3=待审核',
    source              TINYINT DEFAULT 1 COMMENT '1=人工编写 2=工单提炼 3=AI生成',
    source_ticket_id    BIGINT COMMENT '来源工单ID',
    
    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FULLTEXT INDEX ft_question (question_pattern),
    INDEX idx_status (status, match_priority)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='FAQ知识库';
```

## 3. API接口设计

### 3.1 反馈提交接口

```
POST /api/v1/feedback
```

**请求体：**
```json
{
  "feedbackType": 1,
  "feedbackSubtype": "calculation_error",
  "context": {
    "conversationId": "conv_20260604_xxxx",
    "messageId": "msg_12345",
    "errorType": "calculation_error"
  },
  "content": "AI说x=2，但应该是x=3",
  "attachments": [
    {
      "type": "image",
      "url": "https://cdn.primetop.com/uploads/xxx.jpg",
      "size": 102400
    }
  ],
  "pagePath": "/ai-chat/session/conv_xxx",
  "clientMeta": {
    "appVersion": "1.2.0",
    "platform": "android",
    "osVersion": "14",
    "deviceModel": "Pixel 8",
    "networkType": "wifi",
    "screenResolution": "1080x2400"
  }
}
```

**响应体：**
```json
{
  "code": 0,
  "data": {
    "feedbackNo": "FB20260604000123",
    "faqMatched": true,
    "faqAnswer": "感谢反馈！我们已记录此问题，AI回答正在持续优化中...",
    "faqId": 456,
    "ticketCreated": false,
    "estimatedResponseTime": null
  }
}
```

**处理逻辑：**
1. 校验用户登录状态和频率限制（同一用户 1 分钟内最多 3 次反馈）
2. 自动填充用户ID、学生ID、设备信息
3. 调用FAQ匹配引擎 → 匹配则返回FAQ答案
4. 未匹配则自动判定严重程度和优先级
5. 高严重度（涉及安全/支付）自动创建工单
6. 低严重度走批量聚合流程（同类型反馈达到阈值再创建工单）

### 6.1 反馈提交服务（Kotlin/Spring Boot）

```kotlin
@Service
class FeedbackService(
    private val feedbackRepository: FeedbackRecordRepository,
    private val faqMatchEngine: FaqMatchEngine,
    private val ticketService: TicketService,
    private val feedbackAggregator: FeedbackAggregator,
    private val notificationService: NotificationService,
    private val rateLimiter: DistributedRateLimiter
) {
    companion object {
        private val log = LoggerFactory.getLogger(FeedbackService::class.java)
        private const val RATE_LIMIT_KEY_PREFIX = "feedback:rate:"
        private const val RATE_LIMIT_MAX = 3L
        private const val RATE_LIMIT_WINDOW_SEC = 60L
    }

    @Transactional
    suspend fun submitFeedback(userId: Long, request: FeedbackSubmitRequest): FeedbackSubmitResponse {
        // 1. 频率限制
        val rateLimitKey = "$RATE_LIMIT_KEY_PREFIX$userId"
        check(rateLimiter.tryAcquire(rateLimitKey, RATE_LIMIT_MAX, RATE_LIMIT_WINDOW_SEC)) {
            BusinessException(ErrorCode.FEEDBACK_RATE_LIMIT_EXCEEDED)
        }

        // 2. 构建反馈记录
        val feedback = FeedbackRecord(
            feedbackNo = generateFeedbackNo(),
            userId = userId,
            studentId = request.studentId,
            feedbackType = request.feedbackType,
            feedbackSubtype = request.feedbackSubtype,
            severity = determineSeverity(request.feedbackType, request.context),
            title = generateTitle(request),
            content = request.content,
            attachments = request.attachments.toJson(),
            context = request.context.toJson(),
            appVersion = request.clientMeta?.appVersion,
            deviceInfo = request.clientMeta?.toJson(),
            pagePath = request.pagePath,
            status = FeedbackStatus.PENDING.code
        )

        feedbackRepository.insert(feedback)
        log.info("反馈已创建: feedbackNo={}, type={}, userId={}", feedback.feedbackNo, feedback.feedbackType, userId)

        // 3. FAQ匹配
        val faqResult = faqMatchEngine.match(
            FaqMatchInput(
                feedbackType = request.feedbackType,
                content = request.content ?: "",
                context = request.context
            )
        )

        return if (faqResult.matched && faqResult.confidence > 0.8) {
            // 匹配成功
            feedback.faqMatched = true
            feedback.faqId = faqResult.faqId
            feedback.status = FeedbackStatus.FAQ_MATCHED.code
            feedbackRepository.updateById(feedback)

            // 异步更新FAQ统计
            GlobalScope.launch(Dispatchers.IO) {
                faqMatchEngine.incrementMatchCount(faqResult.faqId!!)
            }

            FeedbackSubmitResponse(
                feedbackNo = feedback.feedbackNo,
                faqMatched = true,
                faqAnswer = faqResult.answer,
                faqId = faqResult.faqId,
                ticketCreated = false
            )
        } else {
            // FAQ未匹配，评估是否创建工单
            val shouldCreateTicket = when {
                feedback.severity <= 2 -> true  // P0/P1 立即创建
                feedbackAggregator.shouldAggregate(feedback) -> false  // 聚合处理
                else -> true  // 独立工单
            }

            if (shouldCreateTicket) {
                val ticket = ticketService.createTicketFromFeedback(feedback)
                feedback.ticketId = ticket.id
                feedback.status = FeedbackStatus.TICKET_CREATED.code
                feedbackRepository.updateById(feedback)

                FeedbackSubmitResponse(
                    feedbackNo = feedback.feedbackNo,
                    faqMatched = false,
                    ticketCreated = true,
                    estimatedResponseTime = ticket.slaDueAt?.toString()
                )
            } else {
                // 加入聚合队列
                feedbackAggregator.addToQueue(feedback)
                FeedbackSubmitResponse(
                    feedbackNo = feedback.feedbackNo,
                    faqMatched = false,
                    ticketCreated = false,
                    message = "已收到您的反馈，我们会尽快处理"
                )
            }
        }
    }

    private fun determineSeverity(type: Int, context: Map<String, Any>?): Int {
        return when (type) {
            4, 8 -> 1   // 内容举报、安全举报 → P0
            6 -> {       // 支付问题
                val paymentStatus = context?.get("payment_status") as? String
                if (paymentStatus == "paid_unreceived") 1 else 2  // 已付未到账→P0
            }
            5 -> 2       // Bug反馈 → P1
            1, 2, 3 -> 3 // AI/OCR/内容 → P2
            7 -> 4       // 产品建议 → P3
            else -> 3
        }
    }

    private fun generateFeedbackNo(): String {
        val datePart = LocalDate.now().format(DateTimeFormatter.ofPattern("yyyyMMdd"))
        val seq = feedbackRepository.nextSequence("feedback", datePart)
        return "FB${datePart}${seq.toString().padStart(6, '0')}"
    }

    private fun generateTitle(request: FeedbackSubmitRequest): String {
        val typeLabel = FeedbackTypeLabels[request.feedbackType] ?: "反馈"
        val contentPreview = (request.content ?: "").take(50)
        return "[$typeLabel] $contentPreview"
    }
}
```

### 6.2 FAQ匹配引擎

```kotlin
@Service
class FaqMatchEngine(
    private val faqRepository: FaqKnowledgeRepository,
    private val embeddingService: EmbeddingService,
    private val vectorSearchClient: VectorSearchClient
) {

    suspend fun match(input: FaqMatchInput): FaqMatchResult {
        val candidateFaqs = faqRepository.findByTypeAndStatus(
            input.feedbackType, FaqStatus.ACTIVE
        )

        if (candidateFaqs.isEmpty()) {
            return FaqMatchResult(matched = false)
        }

        // Step 1: 关键词匹配
        val keywordScores = keywordMatch(input.content, candidateFaqs)

        // Step 2: 语义匹配（向量检索）
        val contentEmbedding = embeddingService.embed(input.content)
        val semanticScores = vectorSearchClient.search(
            collection = "faq_vectors",
            vector = contentEmbedding,
            topK = 5,
            filter = mapOf("feedback_types" to input.feedbackType)
        )

        // Step 3: 综合评分
        val combinedScores = mutableMapOf<Long, Double>()
        for (faq in candidateFaqs) {
            val keyword = keywordScores[faq.id] ?: 0.0
            val semantic = semanticScores.find { it.id == faq.id }?.score ?: 0.0
            val priorityBoost = (100 - faq.matchPriority) / 100.0 * 0.1  // 优先级加权
            combinedScores[faq.id] = 0.4 * keyword + 0.4 * semantic + 0.2 * priorityBoost
        }

        val bestMatch = combinedScores.entries.maxByOrNull { it.value }
        return if (bestMatch != null && bestMatch.value > 0.8) {
            val faq = candidateFaqs.first { it.id == bestMatch.key }
            FaqMatchResult(
                matched = true,
                faqId = faq.id,
                confidence = bestMatch.value,
                answer = faq.answer
            )
        } else {
            FaqMatchResult(matched = false, bestScore = bestMatch?.value)
        }
    }

    private fun keywordMatch(content: String, faqs: List<FaqKnowledge>): Map<Long, Double> {
        val contentLower = content.lowercase()
        val tokens = jiebaTokenize(contentLower)  // 结巴分词

        return faqs.associate { faq ->
            val keywords = faq.keywords?.fromJson<List<String>>() ?: emptyList()
            val hitCount = keywords.count { kw -> contentLower.contains(kw.lowercase()) }
            val score = if (keywords.isNotEmpty()) hitCount.toDouble() / keywords.size else 0.0
            faq.id to score
        }
    }
}
```

### 6.3 工单服务核心逻辑

```kotlin
@Service
class TicketService(
    private val ticketRepository: SupportTicketRepository,
    private val interactionRepository: TicketInteractionRepository,
    private val assignmentService: TicketAssignmentService,
    private val slaService: SlaService,
    private val aiAnalysisService: AiAnalysisService,
    private val notificationService: NotificationService,
    private val eventPublisher: ApplicationEventPublisher
) {

    @Transactional
    suspend fun createTicketFromFeedback(feedback: FeedbackRecord): SupportTicket {
        // 1. 确定优先级和队列
        val priority = mapSeverityToPriority(feedback.severity)
        val queueId = resolveQueueId(feedback.feedbackType, feedback.feedbackSubtype)

        // 2. 计算SLA
        val sla = slaService.calculateSla(priority, feedback.userId)

        // 3. 创建工单
        val ticket = SupportTicket(
            ticketNo = generateTicketNo(),
            feedbackId = feedback.id,
            userId = feedback.userId,
            category = feedback.feedbackType,
            subcategory = feedback.feedbackSubtype,
            priority = priority.code,
            title = feedback.title,
            description = buildTicketDescription(feedback),
            attachments = feedback.attachments,
            queueId = queueId,
            status = TicketStatus.PENDING_ASSIGN.code,
            slaDueAt = sla.resolutionDue,
            statusHistory = listOf(
                StatusChange(
                    from = null, to = TicketStatus.PENDING_ASSIGN.code,
                    by = "system", at = LocalDateTime.now(), reason = "工单创建"
                )
            ).toJson()
        )

        ticketRepository.insert(ticket)

        // 4. 自动分配
        assignmentService.assign(ticket)

        // 5. AI辅助预分析（异步）
        GlobalScope.launch(Dispatchers.IO) {
            try {
                val analysis = aiAnalysisService.analyzeTicket(ticket, feedback)
                ticket.aiAnalysis = analysis.toJson()
                ticket.aiSuggestedReply = analysis.suggestedReply
                ticketRepository.updateById(ticket)
            } catch (e: Exception) {
                log.warn("AI预分析失败: ticketNo={}", ticket.ticketNo, e)
            }
        }

        // 6. 发布事件
        eventPublisher.publishEvent(TicketCreatedEvent(ticket))

        return ticket
    }

    @Transactional
    suspend fun reply(ticketNo: String, request: TicketReplyRequest, operatorId: Long): TicketInteraction {
        val ticket = ticketRepository.findByTicketNo(ticketNo)
            ?: throw BusinessException(ErrorCode.TICKET_NOT_FOUND)

        // 创建交互记录
        val interaction = TicketInteraction(
            ticketId = ticket.id,
            interactionType = InteractionType.AGENT_REPLY.code,
            authorId = operatorId,
            authorType = AuthorType.SUPPORT.code,
            content = request.content,
            internalNotes = request.internalNotes,
            visibility = request.visibility
        )
        interactionRepository.insert(interaction)

        // 更新工单状态
        val oldStatus = ticket.status
        ticket.status = TicketStatus.PENDING_CONFIRM.code
        if (ticket.firstResponseAt == null) {
            ticket.firstResponseAt = LocalDateTime.now()
        }
        if (request.resolutionType != null) {
            ticket.resolutionType = request.resolutionType
            ticket.resolution = request.content
            ticket.resolvedBy = operatorId
            ticket.resolvedAt = LocalDateTime.now()
            ticket.status = TicketStatus.RESOLVED.code
        }
        ticket.addStatusChange(oldStatus, ticket.status, operatorId.toString(), "客服回复")
        ticketRepository.updateById(ticket)

        // 通知用户
        if (request.visibility == 1) {
            notificationService.sendFeedbackReplyNotification(
                userId = ticket.userId,
                ticketNo = ticket.ticketNo,
                replyPreview = request.content.take(100)
            )
        }

        return interaction
    }

    private fun generateTicketNo(): String {
        val datePart = LocalDate.now().format(DateTimeFormatter.ofPattern("yyyyMMdd"))
        val seq = ticketRepository.nextSequence("ticket", datePart)
        return "TK${datePart}${seq.toString().padStart(6, '0')}"
    }

    private fun buildTicketDescription(feedback: FeedbackRecord): String {
        return buildString {
            appendLine("【反馈来源】${FeedbackTypeLabels[feedback.feedbackType]}")
            appendLine("【用户描述】${feedback.content ?: "（无）"}")
            if (feedback.context != null) {
                appendLine("【上下文信息】")
                val ctx = feedback.parseContext()
                ctx.forEach { (k, v) -> appendLine("  $k: $v") }
            }
            appendLine("【提交时间】${feedback.createdAt}")
            appendLine("【APP版本】${feedback.appVersion ?: "未知"}")
        }
    }
}
```

### 6.4 SLA监控定时任务

```kotlin
@Component
class SlaMonitorTask(
    private val ticketRepository: SupportTicketRepository,
    private val notificationService: NotificationService,
    private val assignmentService: TicketAssignmentService
) {
    private val log = LoggerFactory.getLogger(SlaMonitorTask::class.java)

    // 每5分钟执行
    @Scheduled(fixedRate = 5 * 60 * 1000)
    fun monitorSla() {
        val now = LocalDateTime.now()

        // 查询即将超时的工单（SLA剩余 < 30min）
        val warningThreshold = now.plusMinutes(30)
        val atRiskTickets = ticketRepository.findByStatusInAndSlaDueAtBefore(
            listOf(
                TicketStatus.PENDING_ASSIGN.code,
                TicketStatus.PENDING_PROCESS.code,
                TicketStatus.PROCESSING.code
            ),
            warningThreshold
        )

        for (ticket in atRiskTickets) {
            val remaining = Duration.between(now, ticket.slaDueAt)
            log.warn("工单SLA即将到期: ticketNo={}, 剩余={}分钟", ticket.ticketNo, remaining.toMinutes())

            // 通知处理人
            if (ticket.assigneeId != null) {
                notificationService.sendSlaWarning(
                    assigneeId = ticket.assigneeId!!,
                    ticketNo = ticket.ticketNo,
                    remainingMinutes = remaining.toMinutes()
                )
            }
        }

        // 查询已超时的工单
        val overdueTickets = ticketRepository.findByStatusInAndSlaDueAtBefore(
            listOf(
                TicketStatus.PENDING_ASSIGN.code,
                TicketStatus.PENDING_PROCESS.code,
                TicketStatus.PROCESSING.code
            ),
            now
        )

        for (ticket in overdueTickets) {
            log.error("工单SLA已超时: ticketNo={}, 超时={}分钟",
                ticket.ticketNo, Duration.between(ticket.slaDueAt, now).toMinutes())

            // 自动升级优先级
            if (ticket.priority > 1) {
                ticket.priority -= 1  // 提升优先级（数值越小优先级越高）
                ticketRepository.updateById(ticket)
            }

            // 如果未分配，触发紧急分配
            if (ticket.assigneeId == null) {
                assignmentService.emergencyAssign(ticket)
            }

            // 通知组长
            notificationService.sendSlaOverdueAlert(ticket)
        }
    }
}
```

### 7.2 降级策略

| 故障场景 | 降级策略 | 用户感知 |
| --- | --- | --- |
| FAQ匹配引擎不可用 | 跳过FAQ匹配，直接创建工单 | 无影响，可能响应稍慢 |
| 向量数据库不可用 | 仅使用关键词匹配 | FAQ命中率降低 |
| AI预分析超时 | 跳过AI分析，人工处理 | 客服效率略降 |
| 通知服务不可用 | 重试3次后写入待发送队列 | 用户收到通知延迟 |
| 工单分配无可用人员 | 自动升级 + 通知组长 | 无影响 |
| 数据库写入失败 | 返回友好错误 + 记录本地日志 | 用户被提示稍后重试 |
