## 1. 总体版本规划概览

### 1.1 版本时间线

```
┌─────────────────────────────────────────────────────────────────────┐
│                        PrimeTop 版本迭代路线                          │
├──────────┬──────────┬──────────┬──────────┬─────────────────────────┤
│  MVP     │  V1.0    │  V1.5    │  V2.0    │  V2.5+                 │

│          │          │          │          │                         │

└──────────┴──────────┴──────────┴──────────┴─────────────────────────┘
```

### 1.2 版本定位与目标

| 版本 | 代号 | 核心目标 | 目标用户 | 商业目标 |
|------|------|----------|----------|----------|
| MVP | 「基石」 | 验证 AI 助学核心闭环 | 内测用户（500-2000） | 验证产品价值，收集反馈 |
| V1.0 | 「成长」 | 全学段可用学习产品 | 公测用户（1万-10万） | 会员订阅上线，首批付费 |
| V1.5 | 「进阶」 | 差异化能力与深度闭环 | 活跃用户（10万+） | 提升付费率与续费率 |
| V2.0 | 「扩展」 | 多端与 B 端能力 | 全平台用户 | B 端收入、多端覆盖 |
| V2.5+ | 「生态」 | 教育生态平台 | 全量用户 | 规模化盈利 |

### 1.3 优先级定义（统一规范）

```
P0 = 阻塞版本发布，必须完成
P1 = 版本核心价值，应完成（允许≤20% 延期至下个 hotfix）
P2 = 提升体验，尽力完成（可延期一个版本）
P3 = 锦上添花，排期灵活
```

## 3. MVP 阶段详细规划（W1-W12）

### 3.1 MVP 范围与目标

**核心命题：** 用户能否在 PrimeTop 上完成「提问 → AI 讲解 → 错题收录 → 再次学习」的最小闭环？

**成功标准：**
- 次日留存 ≥ 30%
- AI 问答满意度 ≥ 70%（用户主动反馈）
- 拍题识别准确率 ≥ 80%
- 核心流程 Crash 率 < 0.5%

### 3.2 MVP Sprint 拆分

#### Sprint 1（W1-W2）：基础设施

| 编号 | 任务 | 优先级 | 负责 | 交付物 |
|------|------|--------|------|--------|
| M1-01 | 客户端框架搭建（Flutter/React Native 选定） | P0 | 移动端 | 可运行的空壳 APP |
| M1-02 | 服务端脚手架（框架选型、目录规范） | P0 | 服务端 | 可运行的空项目 |
| M1-03 | 数据库 Schema 设计（用户、题目、错题、学习记录） | P0 | 服务端 | DDL + ER 图 |
| M1-04 | API 网关基础（路由、鉴权中间件） | P0 | 服务端 | 可调通的网关 |
| M1-05 | CI/CD 流水线搭建 | P1 | DevOps | 自动构建 + 部署 |
| M1-06 | 设计系统初始版本（色彩、字体、基础组件） | P1 | UI/UX | Figma 组件库 |

### 3.3 MVP 团队配置

```
最小团队（8-10 人）：
├── 产品经理 ×1       — 需求定义、验收
├── UI/UX 设计师 ×1   — 视觉 + 交互
├── 移动端工程师 ×2   — Flutter/RN 开发
├── 服务端工程师 ×2   — API + 业务服务
├── AI 工程师 ×1-2    — 模型接入、Prompt、RAG
├── 测试工程师 ×1     — 功能 + 兼容测试
└── 内容教研 ×1       — 题库内容（可兼职）
```

### 3.4 MVP 技术选型建议

| 领域 | 推荐选型 | 备选 | 选型理由 |
|------|----------|------|----------|
| 移动端 | Flutter | React Native | 一套代码两端，UI 一致性好 |
| 服务端 | Go (Gin) / Node.js (NestJS) | Java (Spring Boot) | 快速迭代，AI 调用生态好 |
| 数据库 | PostgreSQL + Redis | MySQL + Redis | JSON 支持好，扩展灵活 |
| 大模型 | 通义千问 / 文心一言 / GPT-4o | DeepSeek / Claude | 多模型降级保障 |
| OCR | 百度 OCR / 腾讯 OCR | Google Vision | 中文识别准确率高 |
| 对象存储 | 阿里云 OSS / 腾讯 COS | AWS S3 | 国内访问快 |
| 消息队列 | RabbitMQ / Redis Stream | Kafka | MVP 阶段够用 |

## 7. 数据接口与里程碑跟踪

### 7.1 版本里程碑数据模型

```typescript
// 里程碑定义
interface Milestone {
  id: string;                    // 格式：M{phase}-{seq}，如 M2-03
  version: string;               // 所属版本：MVP / V1.0 / V1.5 / V2.0
  sprint: number;                // 所属 Sprint 编号
  title: string;                 // 任务标题
  priority: 'P0' | 'P1' | 'P2' | 'P3';
  status: 'planned' | 'in_progress' | 'dev_complete' | 'testing' | 'done' | 'deferred';
  assignee: string;              // 负责人/角色
  dependencies: string[];        // 依赖的里程碑 ID 列表
  deliverable: string;           // 交付物描述
  acceptance_criteria: string[]; // 验收标准
  estimated_hours: number;       // 预估工时
  actual_hours?: number;         // 实际工时
  start_date?: string;           // ISO date
  end_date?: string;             // ISO date
}

// Sprint 定义
interface Sprint {
  id: number;
  version: string;
  name: string;
  start_week: number;
  end_week: number;
```

### 7.3 版本燃尽图数据查询

```sql
-- 查询某版本的每日完成进度
SELECT 
    DATE(updated_at) AS date,
    COUNT(CASE WHEN status = 'done' THEN 1 END) AS completed,
    COUNT(*) AS total,
    ROUND(COUNT(CASE WHEN status = 'done' THEN 1 END) * 100.0 / COUNT(*), 1) AS pct
FROM milestones
WHERE version = 'MVP'
GROUP BY DATE(updated_at)
ORDER BY date;
```

### 11.2 依赖关系查询

```sql
-- 查询被阻塞的任务
SELECT m.id, m.title, m.status,
       d.id AS blocker_id, d.title AS blocker_title, d.status AS blocker_status
FROM milestones m
JOIN milestone_dependencies dep ON m.id = dep.milestone_id
JOIN milestones d ON dep.depends_on = d.id
WHERE d.status != 'done'
  AND m.status = 'planned'
ORDER BY m.version, m.sprint;
```
