> **模块定位**：基础设施层 — 全栈技术选型、工程化规范、开发环境搭建与项目组织结构
> **优先级**：P0（团队启动前必须确立，否则后续开发规范不统一）
> **前置依赖**：整体架构设计、开发优先级与版本迭代路线图
> **关联文档**：服务端代码分层规范与通用开发模板、客户端架构与前端框架、CI-CD流水线与自动化构建发布系统、研发协作流程与工程规范、服务端接口文档自动化与契约测试规范、服务端API版本管理与接口兼容性策略、配置中心与动态配置管理、服务端密钥管理与敏感配置安全策略、种子数据管理与自动化测试数据生成引擎、API Mock服务与契约驱动前后端并行开发支撑平台、第三方SDK与开源依赖治理体系

## 1. 概述

### 1.1 文档目的

本文档为 PrimeTop 项目提供完整的技术选型决策记录、开发环境搭建指南、项目代码组织结构、工程化规范和团队协作流程。目标是让新加入的开发人员在 1 天内完成环境搭建并能提交第一行代码。

### 1.2 选型原则

| 原则 | 说明 |
|------|------|
| 团队适配 | 优先选择团队熟悉或学习曲线平缓的技术 |
| 生态成熟 | 选择社区活跃、文档完善、长期支持的技术 |
| 成本可控 | 开发工具链优先选择开源或免费方案 |
| 性能达标 | 满足 MVP 非功能性需求（首屏 2s、首 token 3s、OCR 5s） |
| 可扩展性 | 为后续微服务拆分、多端扩展预留空间 |
| 一致性 | 同类问题使用统一方案，避免技术栈碎片化 |

### 2.3 版本锁定策略

所有依赖版本在 `pubspec.yaml`（Flutter）、`pom.xml` / `build.gradle`（Java）、`pyproject.toml`（Python）中**精确锁定**（使用 `==` 或 `strict` 版本约束），避免构建不确定性。

```
# Flutter 示例
dependencies:
  flutter_riverpod: "2.5.1"      # ✅ 锁定补丁版本
  dio: "5.4.0"                   # ✅ 不用 ^5.4.0

# Java 示例 (build.gradle)
implementation 'com.baomidou:mybatis-plus-spring-boot3-starter:3.5.7'  // ✅ 精确版本
```

依赖升级流程：
1. 每月一次统一升级审查
2. 在特性分支升级 → 运行全量测试 → 合并
3. 安全漏洞（CVE）立即升级，不受月度周期限制

### 4.3 一键环境搭建脚本

```bash
#!/bin/bash
# scripts/setup.sh - PrimeTop 开发环境一键搭建
set -e

echo "🔧 PrimeTop 开发环境搭建"
echo "========================"

# 1. 检查依赖
echo "📋 检查系统依赖..."
command -v git >/dev/null 2>&1 || { echo "❌ 请先安装 Git"; exit 1; }
command -v docker >/dev/null 2>&1 || { echo "❌ 请先安装 Docker Desktop"; exit 1; }
java -version >/dev/null 2>&1 || { echo "❌ 请先安装 JDK 21"; exit 1; }
command -v flutter >/dev/null 2>&1 || { echo "❌ 请先安装 Flutter SDK"; exit 1; }
command -v python3 >/dev/null 2>&1 || { echo "❌ 请先安装 Python 3.11+"; exit 1; }
command -v mvn >/dev/null 2>&1 || { echo "❌ 请先安装 Maven 3.9+"; exit 1; }
command -v node >/dev/null 2>&1 || { echo "❌ 请先安装 Node.js 18+（管理后台构建）"; exit 1; }

# 2. 校验关键版本（软校验：仅告警不阻断，硬版本差异由 CI 统一拦截）
JAVA_MAJOR=$(java -version 2>&1 | head -n1 | grep -oE 'version "?[0-9]+' | grep -oE '[0-9]+$')
[ "$JAVA_MAJOR" = "21" ] || echo "⚠️  JDK 主版本为 ${JAVA_MAJOR:-未知}，项目基线为 21 LTS，请对齐避免编译行为差异"
PYTHON_MAJOR=$(python3 -c 'import sys;print(sys.version_info.major)')
PYTHON_MINOR=$(python3 -c 'import sys;print(sys.version_info.minor)')
[ "$PYTHON_MAJOR.$PYTHON_MINOR" \> "3.10" ] || echo "⚠️  Python 为 ${PYTHON_MAJOR}.${PYTHON_MINOR}，AI 服务要求 3.11+"

# 3. 启动本地基础设施（primetop-infra 仓库）
INFRA_DIR="${PRIMETOP_INFRA:-$(cd "$(dirname "$0")/.." && pwd)/../primetop-infra}"
if [ ! -f "$INFRA_DIR/docker-compose.yml" ]; then
  echo "❌ 未找到 primetop-infra（搜索路径：$INFRA_DIR），请先克隆并设置 PRIMETOP_INFRA 环境变量"
  exit 1
fi
echo "🐳 启动本地基础设施..."
docker compose -f "$INFRA_DIR/docker-compose.yml" --env-file "$INFRA_DIR/.env" up -d

# 4. 等待核心服务就绪（MySQL/Redis/RabbitMQ/MinIO 最长 120s；ES/Milvus/ClickHouse 冷启动较慢，单独放宽）
wait_for() {
  local name="$1" cmd="$2" timeout_s="${3:-120}"
  local waited=0
  until eval "$cmd" >/dev/null 2>&1; do
    waited=$((waited+3)); sleep 3
    [ $waited -ge $timeout_s ] && { echo "❌ $name 在 ${timeout_s}s 内未就绪，请查看 docker logs"; exit 1; }
  done
  echo "✅ $name 就绪"
}
wait_for "MySQL"     "docker exec primetop-mysql mysqladmin ping -h127.0.0.1 -uroot -proot --silent 2>/dev/null || docker exec primetop-mysql mysqladmin ping -hlocalhost --silent"
wait_for "Redis"     "docker exec primetop-redis redis-cli ping | grep -q PONG"
wait_for "RabbitMQ"  "docker exec primetop-rabbitmq rabbitmq-diagnostics -q ping"
wait_for "MinIO"     "curl -sf http://localhost:9000/minio/health/live"
wait_for "Elasticsearch" "curl -sf http://localhost:9200/_cluster/health | grep -qE 'yellow|green'" 300

# 5. 预建数据库与账号（应用层表结构由 Flyway 在服务首次启动时自动迁移，见 §9.4）
docker exec -i primetop-mysql mysql -uroot -proot < "$INFRA_DIR/mysql/init.sql" 2>/dev/null \
  && echo "✅ 数据库初始化完成" || echo "⚠️  init.sql 执行失败或已初始化，忽略（Flyway 幂等迁移兜底）"

# 6.（可选）导入种子数据
read -p "是否导入开发种子数据（教材/题库样例/测试账号）？[y/N] " -n 1 -r; echo
if [[ $REPLY =~ ^[Yy]$ ]]; then
  bash "$INFRA_DIR/scripts/seed-data.sh" || echo "⚠️  种子数据导入失败，可稍后手动执行（不影响启动）"
fi

# 7. 各端依赖安装（可按需注释掉不参与的端）
echo "📦 安装各端依赖..."
(cd "${PRIMETOP_SERVER_DIR:-../primetop-server}" 2>/dev/null && mvn -T 1C -q dependency:go-offline) \
  || echo "⚠️  服务端依赖预下载跳过（未克隆 primetop-server）"
(cd ../primetop-ai 2>/dev/null && poetry install --sync) || echo "⚠️  AI 服务依赖安装跳过"
(cd ../primetop-app 2>/dev/null \
  && flutter pub get \
  && dart run build_runner build --delete-conflicting-outputs) || echo "⚠️  客户端依赖安装跳过"
(cd ../primetop-admin 2>/dev/null && npm ci) || echo "⚠️  管理后台依赖安装跳过"

# 8. 安装 pre-commit 钩子（见 §5.6；commit-msg 钩子见研发协作文档 §6.2）
command -v pre-commit >/dev/null 2>&1 \
  && (cd "$(git rev-parse --show-toplevel 2>/dev/null || echo .)" && pre-commit install) \
  || echo "⚠️  未安装 pre-commit（pip install pre-commit），已跳过钩子安装"

echo ""
echo "🎉 环境搭建完成！常用启动命令："
echo "   服务端:    cd primetop-server && make run          # = mvn spring-boot:run -pl primetop-service-user -am"
echo "   AI 服务:  cd primetop-ai && make run             # = poetry run uvicorn app.main:app --reload --port 8100"
echo "   客户端:    cd primetop-app && make run-dev        # = flutter run --dart-define=ENV=dev"
echo "   管理后台:  cd primetop-admin && npm run dev"
echo "   基础设施面板: RabbitMQ http://localhost:15672 (guest/guest) | MinIO http://localhost:9001 (minioadmin/minioadmin) | Grafana http://localhost:3000 (admin/admin)"
```

> **说明**：
> 1. 脚本幂等可重入：重复执行不会破坏已有数据（MySQL init.sql 使用 `CREATE DATABASE IF NOT EXISTS`，Flyway 迁移带版本号幂等）。
> 2. Windows 团队成员建议在 WSL2 (Ubuntu 22.04+) 中执行本脚本；Docker Desktop 需开启 WSL2 集成。
> 3. 首次执行需联网拉取镜像与依赖，国内网络环境请先完成 §4.5 镜像加速配置。

### 4.5 国内网络环境加速与常见问题

#### 4.5.1 依赖镜像加速

国内网络环境下，依赖与镜像拉取慢是环境搭建失败的首要原因。各端镜像配置如下（一次性配置，全局生效）：

| 端 | 配置方式 |
|----|---------|
| Flutter/Dart | 环境变量 `PUB_HOSTED_URL=https://pub.flutter-io.cn`、`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`（写入 `~/.bashrc`） |
| Maven | `~/.m2/settings.xml` 配置阿里云镜像（见下方代码块） |
| Gradle（Flutter Android 构建） | 项目 `android/build.gradle.kts` 已内置阿里云/腾讯云 maven 镜像仓库，勿提交个人配置 |
| pip/Poetry | `pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`；Poetry 读取 pip 配置 |
| npm | `npm config set registry https://registry.npmmirror.com` |
| Docker | Docker Desktop → Settings → Docker Engine 增加 `registry-mirrors`（见下方代码块） |
| Homebrew（macOS，可选） | `export HOMEBREW_API_DOMAIN=https://mirrors.tuna.tsinghua.edu.cn/homebrew-bottles/api` |

```xml
<!-- ~/.m2/settings.xml —— Maven 阿里云镜像 -->
<settings>
  <mirrors>
    <mirror>
      <id>aliyunmaven</id>
      <mirrorOf>central</mirrorOf>
      <name>阿里云公共仓库</name>
      <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
  </mirrors>
</settings>
```

```json
// Docker Desktop → Settings → Docker Engine
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
```

> 镜像站仅用于**开发环境加速**；CI 与生产构建必须使用官方源 + 制品库缓存（见 CI/CD 文档 §5 制品库），避免镜像站内容不同步导致构建差异。

#### 4.5.2 常见环境问题排查

| 现象 | 原因 | 解决方式 |
|------|------|---------|
| MySQL/Redis/RabbitMQ 端口冲突 | 本机已装同端口服务 | 修改 `primetop-infra/.env` 中端口映射（如 `MYSQL_PORT=3307`）并同步各模块 dev 配置 |
| ES 启动失败 `max virtual memory areas` | Linux/macOS 未调 `vm.max_map_count` | `sudo sysctl -w vm.max_map_count=262144` 并写入 `/etc/sysctl.conf` |
| WSL2 内存占用过高 | Docker Desktop 默认分配过大 | `%UserProfile%\.wslconfig` 限制 `memory=8GB`、`processors=4` |
| Milvus 启动后立即退出 | 依赖的 etcd/MinIO 未就绪 | `docker compose restart milvus-standalone`；Milvus 首次初始化需 1-2 分钟 |
| `flutter pub get` 超时 | 未配置 PUB 镜像 | 见 §4.5.1；公司网络下确认代理放行 `*.flutter-io.cn` |
| Maven 下载依赖 502 | 镜像站限流 | 切换华为云镜像或临时直连官方源 `-Dmaven.repo.remote=central::default::https://repo.maven.apache.org/maven2` |
| Flyway 校验失败 `Validate failed` | 多人改了同一迁移脚本 | 迁移脚本一经合并**禁止修改**，新变更新增版本号脚本（见 §9.4） |
| iOS 真机运行报签名错误 | 未配置开发证书 | Xcode → Signing & Capabilities 选择个人 Team；CI 侧见 CI/CD 文档 iOS 签名管理 |

## 5. 代码规范与静态检查工具链

> 本节定义**四端统一的格式化与静态检查配置**，配置文件随仓库提交，CI 门禁与本地钩子共用同一套规则（见 §5.6 与 CI/CD 文档）。代码评审流程、Conventional Commits、MR 模板等**协作流程类规范**见[研发协作流程与工程规范](研发协作流程与工程规范-详细设计.md)，本文不重复。

### 5.1 全仓库统一基础约定（EditorConfig）

所有仓库根目录放置同一份 `.editorconfig`，由 IDE 自动应用：

```ini
# .editorconfig —— 五仓库统一
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 2

[*.{java,py}]      # Java/Python 4 空格
indent_size = 4

[*.dart]           # Dart 2 空格（dart format 官方默认）
indent_size = 2

[*.md]
trim_trailing_whitespace = false   # 保留 Markdown 行尾双空格换行语法

[Makefile]
indent_style = tab
```

### 5.2 Java（primetop-server）

**格式化：Spotless + Palantir Java Format**（4 空格缩进，贴近国内团队习惯；google-java-format 的 2 空格风格不采用）：

```xml
<!-- pom.xml（父 POM，插件管理统一版本） -->
<plugin>
  <groupId>com.diffplug.spotless</groupId>
  <artifactId>spotless-maven-plugin</artifactId>
  <version>2.44.0</version>
  <configuration>
    <java>
      <palantirJavaFormat>
        <version>2.50.0</version>
      </palantirJavaFormat>
      <importOrder>
        <order>java|javax,jakarta,org,com,com.primetop,\#</order>
      </importOrder>
      <removeUnusedImports/>
    </java>
  </configuration>
  <executions>
    <execution>
      <goals><goal>check</goal></goals>
      <phase>validate</phase>   <!-- 任何 mvn 构建前先检查格式 -->
    </execution>
  </executions>
</plugin>
```

日常命令：`mvn spotless:apply`（一键格式化）/ `mvn spotless:check`（CI 门禁）。

**静态检查：Checkstyle**，采用精简规则集（放在 `primetop-common/build-config/checkstyle.xml`，全模块引用），核心规则：

| 规则 | 约束 |
|------|------|
| LineLength | 120 字符 |
| MethodLength | 80 行（超过拆方法，领域逻辑复杂处评审时说明） |
| CyclomaticComplexity | 15（switch 分支豁免） |
| HiddenField | 关闭（Lombok/Builder 场景误报多） |
| RequireEmptyLineBeforeBlockTagGroup | Javadoc 规范 |
| UncommentedMain | 禁止提交调试 main（仅启动类豁免清单） |

**单元测试覆盖率门禁（JaCoCo）**：MVP 阶段全局行覆盖 ≥ 60%、`primetop-common` 与核心域（用户/支付/优惠券）≥ 80%，每次发布前由 CI 校验并输出趋势报告。分层测试策略与用例编写规范详见[单元测试与集成测试策略](单元测试与集成测试策略-详细设计.md)。

### 5.3 Dart/Flutter（primetop-app）

**格式化**：`dart format`（行宽 120，写入 `analysis_options.yaml`），IDE 保存自动格式化，CI 执行 `dart format --set-exit-if-changed --output=none .`。

**静态分析**：`analysis_options.yaml`（仓库根目录）：

```yaml
include: package:flutter_lints/flutter.yaml

analyzer:
  language:
    strict-casts: true        # 强制显式类型转换
    strict-raw-types: true    # 泛型裸类型告警
  errors:
    invalid_annotation_target: ignore   # freezed 需要的豁免
  exclude:
    - "**/*.g.dart"           # build_runner 生成物不检查
    - "**/*.freezed.dart"

linter:
  rules:
    - always_declare_return_types
    - prefer_single_quotes
    - unawaited_futures        # 未 await 的 Future 必须显式 unawaited()
    - avoid_print              # 统一走 core/logger
    - directives_ordering      # import 排序，消除合并冲突噪音
    - prefer_final_locals
    - prefer_const_constructors
    - cancel_subscriptions     # StreamSubscription 必须 cancel，防内存泄漏
    - close_sinks
```

CI 门禁：`flutter analyze` 必须 0 error 0 warning（info 允许但计入技术债）。

### 5.4 Python（primetop-ai）

**Lint + 格式化统一用 Ruff**（替代 black+isort+flake8 三件套，速度快且规则兼容）：

```toml
# pyproject.toml
[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "W", "I", "N", "UP", "B", "C4", "SIM", "ASYNC", "RUF"]
ignore = ["E501"]   # 行长交给 formatter 管

[tool.ruff.lint.isort]
known-first-party = ["app"]

[tool.mypy]
python_version = "3.11"
strict = true
disallow_untyped_defs = true
# 渐进式严格：vendor SDK 适配器目录降级
[[tool.mypy.overrides]]
module = ["app.core.llm.*", "tests.*"]
disallow_untyped_defs = false
```

日常命令：`poetry run ruff check --fix . && poetry run ruff format .`；CI 门禁 `ruff check` + `mypy app` 零失败。

### 5.5 TypeScript/Vue（primetop-admin）

ESLint Flat Config + Prettier，`npm run lint` / `npm run format` 与 CI 门禁一致；`vue-tsc --noEmit` 作为类型检查门禁。规则要点：`@typescript-eslint/no-floating-promises: error`、`vue/multi-word-component-names` 保留、禁用 `any`（`no-explicit-any: warn` 逐步清零）。

### 5.6 pre-commit 统一钩子

各仓库根目录提交同一份 `.pre-commit-config.yaml`（按仓库类型启用对应 hook），配合 §5.2-§5.5 的 CI 门禁形成本地+远端双保险：

```yaml
# .pre-commit-config.yaml（通用部分，全仓库一致）
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: check-yaml
      - id: check-json
      - id: end-of-file-fixer
      - id: trailing-whitespace
      - id: check-merge-conflict
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.18.0
    hooks:
      - id: gitleaks        # 密钥扫描，防 .env / API Key 误提交（见 §8.4）
  - repo: local            # 大文件拦截：二进制 > 2MB 拒绝（字体/图片走 LFS 或对象存储）
    hooks:
      - id: no-large-files
        name: no large binary files
        entry: bash -c 'find . -size +2M -type f -not -path "./.git/*" -not -path "*/node_modules/*" | grep -qv . && exit 1 || exit 0'
        language: system
        pass_filenames: false
```

> 服务端仓库额外追加 spotless/checkstyle 本地快速检查 hook；commit-msg 规范钩子（Conventional Commits 校验）见[研发协作流程与工程规范 §6.2](研发协作流程与工程规范-详细设计.md)，由该文档统一维护。

## 6. 依赖治理与版本升级

### 6.1 版本锁定执行细则

§2.3 定义了“精确锁定”原则，落地要求：

1. **锁文件必须提交**：`pubspec.lock`（app）、`poetry.lock`（ai）、`package-lock.json`（admin）随代码提交；Maven 无锁文件，以父 POM `<dependencyManagement>` 统一版本（BOM 模式），子模块禁止自声明版本号。
2. **新增依赖准入**：任何新依赖需在 MR 中说明用途与体积影响；客户端纯 UI 依赖额外说明与设计系统的关系（避免重复造轮子）。运行时第三方 SDK 的完整准入评审流程见[第三方SDK与开源依赖治理体系](第三方SDK与开源依赖治理体系-详细设计.md)。
3. **CI 依赖审查**：GitHub Actions 开启 dependency-review（基于锁文件的已知漏洞拦截），配置见 CI/CD 文档 §4。

### 6.2 Renovate 自动升级

五仓库统一配置 `.renovate.json`（组织级 default.json 统一注入）：

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["config:recommended", ":timezone(Asia/Shanghai)"],
  "rangeStrategy": "pin",
  "schedule": ["before 5am on Monday"],
  "prCreation": "status-success",
  "packageRules": [
    {
      "description": "安全更新立即提 PR，不受周窗口限制",
      "matchUpdateTypes": ["patch", "digest", "pin"],
      "matchCategories": ["security"],
      "schedule": ["at any time"],
      "labels": ["security", "ready-to-merge"]
    },
    {
      "description": "主版本升级单独分组，需人工评估",
      "matchUpdateTypes": ["major"],
      "groupName": "major-upgrades-manual",
      "labels": ["major"]
    },
    {
      "description": "Flutter SDK 版本不自动升，跟随季度基线",
      "matchPackageNames": ["flutter"],
      "enabled": false
    }
  ]
}
```

与 §2.3 的月度升级窗口对齐：非安全类 PR 统一周一凌晨生成，负责人当周内评审合并；安全类 PR 到达即处理（SLA 见 §6.3）。

### 6.3 CVE 应急流程

| 阶段 | 动作 | SLA |
|------|------|-----|
| 发现（dependency-review / Renovate / GitHub Advisory 告警） | 建立 `security/cve-xxx` 分支升级 | 高危（RCE/反序列化类）2h 内响应 |
| 评估 | 确认是否在受影响调用路径上；不在路径上的降级处理 | 1 个工作日出结论 |
| 修复验证 | 升级 + 相关模块回归测试（最小回归集：受影响模块单测 + 冒烟） | 高危 24h 内发版，中危随下个版本 |
| 复盘 | 高危 CVE 复盘依赖引入路径，更新准入清单 | 发版后 3 日内 |

### 6.4 内部公共库版本策略

- `primetop-common` 禁止 `SNAPSHOT` 版本进入 `main`（CI 校验 `-Drevision=*.SNAPSHOT` 拒绝合并）；
- 公共库版本号 `1.{minor}.{patch}`，破坏性变更必须升 minor 并提供迁移说明；
- 各服务模块通过 BOM 引用公共库，升级公共库 = 升 BOM 一处，避免版本漂移。

## 7. 多仓库协作与 API 契约同步

多仓库策略（§3.1）的最大风险是**接口改了、调用方不知道**。本章以“契约先行”解决跨仓库同步问题；契约测试的实施细节见[服务端接口文档自动化与契约测试规范](服务端接口文档自动化与契约测试规范-详细设计.md)，接口兼容性策略（版本化、N-1 窗口）见[服务端API版本管理与接口兼容性策略](服务端API版本管理与接口兼容性策略-详细设计.md)。

### 7.1 契约仓库结构

API 契约作为唯一事实源（Single Source of Truth），集中存放在 `primetop-docs` 仓库：

```text
primetop-docs/
├── api-specs/
│   ├── openapi/                    # REST 契约（OpenAPI 3.1，YAML）
│   │   ├── user-service.yaml
│   │   ├── learning-service.yaml
│   │   ├── question-service.yaml
│   │   ├── mistake-service.yaml
│   │   ├── ai-service.yaml
│   │   └── payment-service.yaml
│   ├── events/                     # 异步事件契约（事件名/Payload Schema/版本）
│   │   └── domain-events.md
│   └── CHANGELOG.md                # 契约变更日志（自动生成）
├── design/ → 即本 docs2 目录镜像
└── adr/                            # 架构决策记录（见 §10）
```

### 7.2 契约变更三步流程

```text
① 提案：修改 openapi/*.yaml 提交 MR（打 label「api-change」）
     ↓ oasdiff breaking 检查（CI 自动执行）
② 评审：服务端负责人 + 受影响调用方（app/admin）负责人双 Approve
     ↓ 合并后自动触发
③ 同步：CI 自动生成客户端 SDK MR 到 primetop-app / primetop-admin，
        并在服务端仓库建「实现契约」跟踪 issue（模板自动关联契约 commit）
```

破坏性变更（删字段/改类型/改语义）额外要求：按 API 版本管理文档走 `/v2` 路径或双写过渡，`oasdiff --breaking` 输出必须为空或附豁免评审记录。

### 7.3 客户端代码生成

```bash
# primetop-app（Dart）
openapi-generator-cli generate \
  -i ../primetop-docs/api-specs/openapi/user-service.yaml \
  -g dart-dio -o lib/core/api/generated/user \
  --additional-properties=pubName=pt_user_api

# primetop-admin（TypeScript）
openapi-generator-cli generate \
  -i ../primetop-docs/api-specs/openapi/user-service.yaml \
  -g typescript-axios -o src/api/generated/user
```

约定：生成物目录 `generated/` 不手改（文件头含“DO NOT MODIFY”），重新生成覆盖；`make gen-api` 一键全量刷新。

### 7.4 跨仓库版本对齐与 Mock 联动

| 场景 | 约束 |
|------|------|
| 客户端发版 | 依赖的契约版本 ≥ 服务端已部署版本（服务端保持 N-1 向后兼容，见 API 版本管理文档） |
| 服务端先行上线 | 新字段必须可选（additive change），客户端旧版本无感知 |
| 并行开发 | 客户端设 `LOCAL_MOCK=1` 时全部请求走 [API Mock 平台](API-Mock服务与契约驱动前后端并行开发支撑平台-详细设计.md)，契约 MR 合并即 Mock 生效，前后端零等待 |

## 8. 配置管理与密钥安全

### 8.1 十二要素配置原则

所有环境差异通过**环境变量**注入，代码与配置分离：同一构建产物（镜像/APK）跑通 dev/staging/prod，仅环境变量不同。禁止在代码库出现任何环境 URL、账号、密钥字面量（pre-commit gitleaks + CI 双重拦截）。

### 8.2 环境变量清单模板

`primetop-infra/.env.example` 是全部本地环境变量的**唯一权威模板**，新增变量必须先改模板再使用：

```bash
# ===== 基础设施连接（本地开发默认值） =====
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=primetop
MYSQL_USERNAME=primetop
MYSQL_PASSWORD=primetop_dev      # 本地默认弱口令仅限 dev，staging/prod 走密钥管理服务

REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=

RABBITMQ_HOST=127.0.0.1
RABBITMQ_PORT=5672
RABBITMQ_USERNAME=primetop
RABBITMQ_PASSWORD=primetop_dev

ES_HOST=http://127.0.0.1:9200
MINIO_ENDPOINT=http://127.0.0.1:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin_dev
MILVUS_URI=http://127.0.0.1:19530

# ===== AI 供应商（占位，真实 Key 见 §8.4） =====
LLM_PROVIDER_OPENAI_API_KEY=${LLM_PROVIDER_OPENAI_API_KEY}   # 从 .env.local 注入，不入库
LLM_PROVIDER_ZHIPU_API_KEY=${LLM_PROVIDER_ZHIPU_API_KEY}
ASR_PROVIDER_API_KEY=${ASR_PROVIDER_API_KEY}

# ===== 业务开关 =====
XXL_JOB_ADMIN_ADDRESSES=http://127.0.0.1:8088/xxl-job-admin
LOCAL_MOCK=0                     # 1=客户端全量走 Mock 平台（见 §7.4）
```

`.env.example` 提交入库；真实值写 `.env`（已被统一 `.gitignore` 排除）。首次搭建执行 `cp .env.example .env` 即可获得全部默认值。

### 8.3 各端配置装载方式

| 端 | 装载机制 | 说明 |
|----|---------|------|
| 服务端 | Spring Profiles（`application-{dev,staging,prod}.yml`）+ `spring.config.import=optional:file:.env[.properties]` + 环境变量占位符 `${MYSQL_HOST}` | 本地零配置启动（默认值兜底），生产全量环境变量注入 |
| AI 服务 | Pydantic Settings（`app/config/settings.py` 定义字段与校验）自动读环境变量与 `.env` | 启动时校验必填项，缺 Key 直接 fail-fast 并列出缺失清单 |
| 客户端 | `--dart-define=ENV=dev/staging/prod` + `config/env_config.dart` 三环境实现类；敏感值不进客户端（见下方红线） | 构建期注入非敏感配置（API 域名/开关）；**客户端禁止内嵌任何服务端密钥**，第三方 SDK Key 走服务端代理下发 |
| 管理后台 | Vite 环境文件（`.env.development` / `.env.production`），`VITE_` 前缀变量 | 同上，敏感配置走登录后服务端接口获取 |

### 8.4 密钥红线与泄露应急

1. **密钥分级**：LLM/云厂商/支付密钥为 L1（最高），仅存于[密钥管理服务](服务端密钥管理与敏感配置安全策略-详细设计.md)（信封加密），本地开发用测试环境专属 Key 且放 `.env.local`（gitignore）。
2. **泄露应急**：任何人发现密钥入库（即使立即 revert 也视为泄露——Git 历史仍可提取）：① 立即在供应商控制台禁用/轮换该 Key；② 按[密钥管理文档](服务端密钥管理与敏感配置安全策略-详细设计.md)应急流程通知安全负责人；③ 视影响面决定是否重写 Git 历史（公共仓库必重写）。
3. **CI 密钥**：GitHub Actions Secrets 引用，日志自动脱敏；制品签名密钥仅签名 Job 可见。

## 9. 本地开发体验

### 9.1 统一任务入口（Makefile）

每个仓库根目录提供同名目标的 Makefile，团队记忆成本 = 一套命令：

| 目标 | primetop-server | primetop-ai | primetop-app | primetop-admin |
|------|----------------|------------|-------------|----------------|
| `make setup` | `mvn dependency:go-offline` | `poetry install --sync` | `flutter pub get && build_runner` | `npm ci` |
| `make lint` | `spotless:check + checkstyle` | `ruff check + mypy` | `flutter analyze` | `npm run lint && vue-tsc` |
| `make format` | `spotless:apply` | `ruff format` | `dart format .` | `npm run format` |
| `make test` | `mvn test`（+ JaCoCo 报告） | `pytest` | `flutter test` | `vitest run` |
| `make run` | `spring-boot:run -pl primetop-service-user -am` | `uvicorn --reload :8100` | `flutter run --dart-define=ENV=dev` | `npm run dev` |

Windows 无 make 环境：各目标同时在 `package.json scripts` / `Justfile`（just 命令器）提供等价入口；CI 与文档统一引用 make 目标名。

### 9.2 热重载与调试

| 端 | 热重载 | 远程调试 |
|----|--------|---------|
| 服务端 | spring-boot-devtools（classpath 变更自动重启，配合 IDEA「Build project」快捷键） | JDWP `agentlib:jdwp=...*:5005`，IDEA Remote JVM Debug 一键附加 |
| AI 服务 | uvicorn `--reload`（文件变更自动重启 worker） | `debugpy.listen(5678)`，VS Code Python Remote Attach |
| 客户端 | Flutter hot reload（r 键 / ⌘R）与 hot restart（R 键 / ⇧R）；Riverpod 状态在 restart 后保留方案见状态管理文档 | Flutter DevTools（性能/内存/网络面板）；Android `adb logcat | grep flutter` |

种子数据（教材章节样例、题库样例、测试账号、运营配置）由 [种子数据管理引擎](种子数据管理与自动化测试数据生成引擎-详细设计.md) 统一生产，`primetop-infra/scripts/seed-data.sh` 一键导入。**标准测试账号**（仅本地/staging 存在，prod 禁止）：

| `13800000002` / 验证码 `888888` | 家长（已绑定上方学生） | 家长中心、学情报告 |

### 9.4 数据库迁移（Flyway）

- 迁移脚本位于各模块 `src/main/resources/db/migration/`，命名 `V{序号}__{描述}.sql`（如 `V0007__create_coupon_usage_log.sql`），序号全局单调递增；
- **合并后不可修改**：CI 校验已应用版本的 checksum，变更历史数据用新脚本 `V0008__fix_xxx.sql` 修正；
- 本地推倒重来：`make db-reset`（drop & recreate + 全量迁移 + 种子数据），日常禁止在共享环境执行。

### 9.5 集成测试环境（Testcontainers）

单测不依赖本地 compose；集成测试用 Testcontainers 按需拉起 MySQL/Redis/RabbitMQ，测试结束自动销毁，保障「克隆即可跑测试」：

```java
// 服务端集成测试基类（Spring Boot 3.3 + Testcontainers）
@SpringBootTest(webEnvironment = RANDOM_PORT)
@Testcontainers
class AbstractIntegrationTest {
  @Container
  @ServiceConnection
  static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0");

  @Container
  @ServiceConnection
  static GenericContainer<?> redis = new GenericContainer<>("redis:7-alpine").withExposedPorts(6379);
}
```

Python 侧使用 `testcontainers-python`，细节见[单元测试与集成测试策略](单元测试与集成测试策略-详细设计.md)。

## 10. 技术决策记录（ADR）与技术债治理

### 10.1 ADR 模板与流程

所有 §2.2 决策表中的选型必须有对应 ADR（`primetop-docs/adr/ADR-{编号}-{标题}.md`），状态机：`proposed → accepted →（被取代）superseded`。**不写 ADR 的新中间件引入视为违规**。

```markdown
# ADR-004：消息队列选用 RabbitMQ
- 状态：accepted（2026-06-02）
- 背景：MVP 阶段需要延迟队列（订单超时关单）、死信与优先级队列，日消息量预估 < 100 万
- 决策：选用 RabbitMQ 3.13；Kafka 留待日志/埋点量级上来后评估（届时新开 ADR）
- 备选方案：RocketMQ（运维复杂度高）、Kafka（延迟队列需自建，超配）
- 后果：接受吞吐上限；获得管理界面与低运维成本
- 退出成本评估：消费端统一走抽象层（消息服务封装），迁移成本 ≈ 2 人周
```

### 10.2 首批 ADR 清单

| 编号 | 决策 | 对应本文 |
|------|------|---------|
| ADR-001 | 客户端跨端框架选 Flutter | §2.2 |
| ADR-002 | 服务端 Java 21 + Spring Boot 3.3，模块化单体起步 | §2.2 / §3.3 |
| ADR-003 | 多仓库拆分策略 | §3.1 |
| ADR-004 | 消息队列 RabbitMQ | §2.2 |
| ADR-005 | 关系库 MySQL 8 / 分析库 ClickHouse 分离 | §2.2 |

| ADR-008 | CI 选 GitHub Actions（国内构建加速方案见 CI/CD 文档） | §2.2 |

### 10.3 技术债台账

`primetop-docs/tech-debt.md` 维护台账，每迭代规划时强制预留 **10% 容量**消化高利息项：

| 字段 | 说明 |
|------|------|
| 编号 / 描述 | 如 TD-012：user_coupon 状态机在两服务重复实现 |
| 利息（高/中/低） | 每次触碰的额外成本 × 触碰频率 |
| 偿还窗口 | 必须在哪个里程碑前还清（如「支付 V1.1 前」） |
| 状态 | open / doing / paid | 

### 10.4 选型复审节奏

季度技术例会复审一次决策表，触发条件（满足其一即强制复审）：性能连续两周不达标（SLO 文档口径）、上游许可证变更、社区活跃度骤降（发版间隔 > 12 月）、高危 CVE 无官方修复路径。复审产出：新 ADR 或维持结论记录。
