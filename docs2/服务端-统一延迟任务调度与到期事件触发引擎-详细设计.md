# 服务端-统一延迟任务调度与到期事件触发引擎-详细设计

## 1. 概述

### 1.1 功能定位

统一延迟任务调度与到期事件触发引擎是 PrimeTop 教育平台的基础设施中间件，负责管理**一次性延迟任务**的生命周期：注册、存储、到期触发、执行回调、状态追踪和异常恢复。

与现有调度系统的区别：

| 系统 | 适用场景 | 典型案例 |
|------|----------|----------|
| 定时任务调度与批处理框架 | 周期性 Cron 任务、批量处理 | 每日凌晨统计报表、每15分钟同步缓存 |
| 异步任务DAG编排引擎 | 复杂多步骤工作流、有依赖关系的任务链 | 报表生成→审核→发布→通知 |
| **本引擎（延迟任务调度）** | **一次性延迟触发、到期回调** | **24h后发送复习提醒、5分钟后过期验证码** |

### 1.2 设计目标

1. **精准触发**：任务在指定延迟后触发，误差不超过 3 秒（P99）
2. **可靠投递**：任务到期后至少被触发一次（At-Least-Once），配合业务幂等保证 Exactly-Once
3. **高吞吐**：单节点支持 10 万级并发延迟任务，集群支持百万级
4. **可取消**：任务在触发前可随时取消
5. **可观测**：任务全生命周期可追踪，支持慢任务、积压任务告警
6. **业务解耦**：各业务服务通过 SDK/API 注册延迟任务，无需关心调度细节

### 1.3 教育平台典型场景

| 场景 | 延迟时间 | 说明 |
|------|----------|------|
| 验证码/OTP 过期 | 5 分钟 | 用户注册、登录验证码自动失效 |
| 错题复习提醒 | 24h / 3d / 7d | 基于遗忘曲线触发复习推送 |
| 考试倒计时提醒 | 考前 3 天/1 天/2 小时 | 自动推送备考提醒 |
| 订单支付超时关闭 | 30 分钟 | 未支付订单自动取消 |
| 会员到期前提醒 | 到期前 7 天/1 天 | 自动续费提醒 |
| 沉默用户唤醒 | 注册后 3 天/7 天/14 天 | 未活跃用户召回推送 |
| 作业提交截止提醒 | 截止前 1 天/2 小时 | 作业即将到期通知 |
| AI 对话超时关闭 | 5 分钟无响应 | 会话自动结束并保存 |
| 学习会话超时检测 | 30 分钟无操作 | 自动暂停学习计时 |
| 限时练习/考试计时 | 根据试卷设定 | 时间到自动交卷 |

### 3.3 Redis 数据结构

#### 3.3.1 延迟任务 ZSET（核心调度队列）

```
Key:   delay:task:zset:{namespace}
Type:  Sorted Set
Member: taskId
Score:  executeAt (Unix毫秒时间戳)
```

每个 namespace 维护一个独立的 ZSET，按到期时间排序。调度器通过 `ZRANGEBYSCORE` 拉取到期任务。

#### 3.3.2 任务详情 Hash（快速查询缓存）

```
Key:   delay:task:detail:{taskId}
Type:  Hash
Fields:
  task_type, payload(JSON), callback_url, callback_method,
  callback_headers, max_retry, retry_interval, priority,
  status, retry_count, execute_at
TTL:   execute_at + 7天 (到期后7天自动清理)
```

#### 3.3.3 处理中任务 ZSET（故障恢复用）

```
Key:   delay:task:processing:{workerId}
Type:  Sorted Set
Member: taskId
Score:  processingStartedAt (Unix毫秒)
TTL:   300秒 (5分钟超时自动恢复)
```

#### 3.3.4 分布式锁

```
Key:   delay:task:lock:scan:{namespace}
Type:  String (Redis SET NX EX)
Value: workerId
TTL:   10秒
```

#### 3.3.5 重试队列

```
Key:   delay:task:retry:zset
Type:  Sorted Set
Member: taskId
Score:  nextRetryAt (Unix毫秒)
```

## 5. 核心算法与关键代码

### 5.1 时间轮调度器核心逻辑

```java
/**
 * 延迟任务调度器核心实现
 * 基于 Redis ZSET 的时间轮扫描
 */
@Component
@Slf4j
public class TimeWheelScheduler {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Autowired
    private TriggerWorker triggerWorker;

    @Value("${delay-task.scan.interval-ms:1000}")
    private long scanIntervalMs;

    @Value("${delay-task.scan.batch-size:500}")
    private int batchSize;

    @Value("${delay-task.namespaces:default,study,payment,notification}")
    private List<String> namespaces;

    private final String LOCK_KEY_PREFIX = "delay:task:lock:scan:";
    private final String ZSET_KEY_PREFIX = "delay:task:zset:";
    private static final long LOCK_TTL_SECONDS = 10;

    /**
     * 定时扫描到期任务（每秒执行一次）
     */
    @Scheduled(fixedDelayString = "${delay-task.scan.interval-ms:1000}")
    public void scanExpiredTasks() {
        long now = System.currentTimeMillis();

        for (String namespace : namespaces) {
            try {
                // 尝试获取分布式锁（同一namespace只有一个worker扫描）
                String lockKey = LOCK_KEY_PREFIX + namespace;
                String workerId = WorkerContext.getWorkerId();

                Boolean acquired = redisTemplate.opsForValue()
                    .setIfAbsent(lockKey, workerId, LOCK_TTL_SECONDS, TimeUnit.SECONDS);

                if (Boolean.FALSE.equals(acquired)) {
                    continue; // 其他worker正在处理
                }

                // 扫描到期任务
                String zsetKey = ZSET_KEY_PREFIX + namespace;
                Set<TypedTuple<String>> expiredTasks = redisTemplate.opsForZSet()
                    .rangeByScoreWithScores(zsetKey, 0, now, 0, batchSize);

                if (expiredTasks == null || expiredTasks.isEmpty()) {
                    continue;
                }

                // 提取任务ID列表
                List<String> taskIds = expiredTasks.stream()
                    .map(TypedTuple::getValue)
                    .filter(Objects::nonNull)
                    .collect(Collectors.toList());

                // 从ZSET中移除已扫描的任务（原子操作： Lua脚本保证移除和判断同时完成）
                String luaScript = """
                    local key = KEYS[1]
                    local tasks = ARGV
                    local removed = 0
                    for i = 1, #tasks do
                        local score = redis.call('ZSCORE', key, tasks[i])
                        if score ~= false and tonumber(score) <= tonumber(ARGV[#tasks]) then
                            redis.call('ZREM', key, tasks[i])
                            removed = removed + 1
                        end
                    end
                    return removed
                """;

                // 简化版：批量移除已到期的任务
                for (String taskId : taskIds) {
                    Double score = redisTemplate.opsForZSet().score(zsetKey, taskId);
                    if (score != null && score <= now) {
                        Long removed = redisTemplate.opsForZSet().remove(zsetKey, taskId);
                        if (removed != null && removed > 0) {
                            // 成功抢占到任务，交给TriggerWorker执行
                            triggerWorker.execute(namespace, taskId);
                        }
                    }
                }

            } catch (Exception e) {
                log.error("扫描延迟任务异常 namespace={}", namespace, e);
                MonitorAlarm.alarm("delay_task_scan_error",
                    "namespace=" + namespace + ", error=" + e.getMessage());
            }
        }
    }

    /**
     * 处理中任务超时恢复
     * 检查超过5分钟仍在执行中的任务，重新加入调度队列
     */
    @Scheduled(fixedDelay = 60000) // 每分钟执行
    public void recoverStaleTasks() {
        long threshold = System.currentTimeMillis() - 5 * 60 * 1000;

        // 从MySQL查询超时任务
        List<DelayTask> staleTasks = delayTaskMapper.selectList(
            new LambdaQueryWrapper<DelayTask>()
                .eq(DelayTask::getStatus, DelayTaskStatus.RUNNING.getCode())
                .lt(DelayTask::getStartedAt, threshold)
                .last("LIMIT 200")
        );

        for (DelayTask task : staleTasks) {
            log.warn("发现超时任务 taskId={}, startedAt={}, 重新调度", 
                task.getTaskId(), task.getStartedAt());
            
            // 重置状态为待执行
            task.setStatus(DelayTaskStatus.PENDING.getCode());
            task.setRetryCount(task.getRetryCount() + 1);
            task.setErrorMsg("处理超时, 自动恢复");
            delayTaskMapper.updateById(task);

            // 重新加入ZSET（立即执行）
            if (task.getRetryCount() < task.getMaxRetry()) {
                String zsetKey = ZSET_KEY_PREFIX + task.getNamespace();
                redisTemplate.opsForZSet().add(zsetKey, task.getTaskId(), 
                    System.currentTimeMillis());
            } else {
                // 超过重试次数，进入死信
                deadLetterHandler.moveToDeadLetter(task);
            }
        }
    }
}
```

### 5.2 任务注册逻辑

```java
/**
 * 延迟任务注册服务
 */
@Service
@Slf4j
public class DelayTaskRegistry {

    @Autowired
    private DelayTaskMapper delayTaskMapper;

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Autowired
    private IdGenerator idGenerator;

    private static final String ZSET_KEY_PREFIX = "delay:task:zset:";
    private static final String DETAIL_KEY_PREFIX = "delay:task:detail:";

    /**
     * 注册延迟任务
     */
    @Transactional(rollbackFor = Exception.class)
    public RegisterResult register(DelayTaskRegisterRequest request) {
        // 1. 参数校验
        validateRequest(request);

        // 2. 计算执行时间
        long now = System.currentTimeMillis();
        long executeAt;
        if (request.getExecuteAt() != null) {
            executeAt = request.getExecuteAt();
            if (executeAt <= now) {
                // 已过期，立即执行
                executeAt = now;
            }
        } else {
            executeAt = now + (long) request.getDelaySeconds() * 1000;
        }

        // 3. 幂等检查
        if (StringUtils.isNotBlank(request.getIdempotentKey())) {
            DelayTask existing = delayTaskMapper.findByIdempotent(
                request.getNamespace(), request.getIdempotentKey());
            if (existing != null) {
                log.info("幂等命中, 返回已存在任务 taskId={}", existing.getTaskId());
                return RegisterResult.of(existing);
            }
        }

        // 4. 生成任务ID
        String taskId = StringUtils.isNotBlank(request.getTaskId()) 
            ? request.getTaskId() 
            : "dt-" + idGenerator.nextUuid();

        // 5. 持久化到MySQL
        DelayTask task = new DelayTask();
        task.setTaskId(taskId);
        task.setTaskType(request.getTaskType());
        task.setNamespace(request.getNamespace());
        task.setPayload(JsonUtils.toJson(request.getPayload()));
        task.setCallbackUrl(request.getCallbackUrl());
        task.setCallbackMethod(request.getCallbackMethod());
        task.setCallbackHeaders(JsonUtils.toJson(request.getCallbackHeaders()));
        task.setDelaySeconds(request.getDelaySeconds());
        task.setExecuteAt(executeAt);
        task.setMaxRetry(request.getMaxRetry());
        task.setRetryInterval(request.getRetryInterval());
        task.setPriority(request.getPriority());
        task.setStatus(DelayTaskStatus.PENDING.getCode());
        task.setRetryCount(0);
        task.setIdempotentKey(request.getIdempotentKey());

        delayTaskMapper.insert(task);

        // 6. 写入Redis ZSET
        String zsetKey = ZSET_KEY_PREFIX + request.getNamespace();
        redisTemplate.opsForZSet().add(zsetKey, taskId, executeAt);

        // 7. 写入Redis详情缓存
        String detailKey = DETAIL_KEY_PREFIX + taskId;
        Map<String, String> detail = new HashMap<>();
        detail.put("taskType", task.getTaskType());
        detail.put("payload", task.getPayload());
        detail.put("callbackUrl", task.getCallbackUrl());
        detail.put("callbackMethod", task.getCallbackMethod());
        detail.put("maxRetry", String.valueOf(task.getMaxRetry()));
        detail.put("retryInterval", String.valueOf(task.getRetryInterval()));
        detail.put("status", String.valueOf(task.getStatus()));
        // TTL: 执行时间 + 7天
        long ttlSeconds = (executeAt - now) / 1000 + 7 * 24 * 3600;
        redisTemplate.opsForHash().putAll(detailKey, detail);
        redisTemplate.expire(detailKey, ttlSeconds, TimeUnit.SECONDS);

        log.info("延迟任务注册成功 taskId={}, type={}, executeAt={}, delay={}s",
            taskId, request.getTaskType(), executeAt, request.getDelaySeconds());

        return RegisterResult.of(task);
    }

    /**
     * 批量注册
     */
    @Transactional(rollbackFor = Exception.class)
    public List<RegisterResult> registerBatch(List<DelayTaskRegisterRequest> requests) {
        if (requests.size() > 100) {
            throw new BizException("单次批量注册最多100条");
        }

        // 使用 Redis Pipeline 批量写入
        return requests.stream()
            .map(this::register)
            .collect(Collectors.toList());
    }

    private void validateRequest(DelayTaskRegisterRequest request) {
        Assert.notBlank(request.getTaskType(), "taskType不能为空");
        Assert.notBlank(request.getCallbackUrl(), "callbackUrl不能为空");
        if (request.getDelaySeconds() == null && request.getExecuteAt() == null) {
            throw new BizException("delaySeconds和executeAt至少传一个");
        }
        if (request.getDelaySeconds() != null && request.getDelaySeconds() > 30 * 24 * 3600) {
            throw new BizException("延迟时间不能超过30天");
        }
    }
}
```

```java
/**
 * 到期任务回调执行器
 */
@Component
@Slf4j
public class CallbackExecutor {

    @Autowired
    private RestTemplate restTemplate;

    @Autowired
    private DelayTaskMapper delayTaskMapper;

    @Autowired
    private RetryHandler retryHandler;

    @Value("${delay-task.callback.timeout-ms:10000}")
    private int callbackTimeoutMs;

    /**
     * 执行回调
     */
    public void execute(DelayTask task) {
        long startTime = System.currentTimeMillis();
        String taskId = task.getTaskId();

        try {
            // 1. 更新状态为执行中
            updateStatus(taskId, DelayTaskStatus.RUNNING, null);

            // 2. 构建回调请求
            CallbackPayload callbackPayload = CallbackPayload.builder()
                .taskId(taskId)
                .taskType(task.getTaskType())
                .executeAt(task.getExecuteAt())
                .retryCount(task.getRetryCount())
                .payload(JsonUtils.parse(task.getPayload()))
                .build();

            HttpHeaders headers = buildHeaders(task);
            HttpEntity<CallbackPayload> entity = new HttpEntity<>(callbackPayload, headers);

            // 3. 发起HTTP调用
            ResponseEntity<String> response = restTemplate.exchange(
                task.getCallbackUrl(),
                HttpMethod.valueOf(task.getCallbackMethod()),
                entity,
                String.class
            );

            int statusCode = response.getStatusCodeValue();
            String body = response.getBody();

            // 4. 处理回调结果
            if (statusCode >= 200 && statusCode < 300) {
                // 成功
                task.setStatus(DelayTaskStatus.SUCCESS.getCode());
                task.setResultCode(statusCode);
                task.setResultBody(StringUtils.left(body, 2000));
                task.setCompletedAt(System.currentTimeMillis());
                delayTaskMapper.updateById(task);

                log.info("延迟任务回调成功 taskId={}, duration={}ms", 
                    taskId, System.currentTimeMillis() - startTime);
                cleanRedisCache(taskId);
            } else if (statusCode >= 400 && statusCode < 500) {
                // 4xx: 业务失败，不可重试，直接进入死信
                log.warn("延迟任务回调业务失败 taskId={}, statusCode={}", taskId, statusCode);
                retryHandler.moveToDeadLetter(task, 
                    "Callback returned 4xx: " + statusCode + ", body=" + body);
            } else {
                // 5xx: 系统失败，进入重试
                log.warn("延迟任务回调系统失败 taskId={}, statusCode={}", taskId, statusCode);
                retryHandler.scheduleRetry(task, 
                    "Callback returned 5xx: " + statusCode);
            }

        } catch (ResourceAccessException e) {
            // 网络异常，进入重试
            log.warn("延迟任务回调网络异常 taskId={}", taskId, e);
            retryHandler.scheduleRetry(task, "Network error: " + e.getMessage());

        } catch (Exception e) {
            log.error("延迟任务回调异常 taskId={}", taskId, e);
            retryHandler.scheduleRetry(task, "Unexpected error: " + e.getMessage());
        }
    }

    /**
     * 构建回调Headers
     */
    private HttpHeaders buildHeaders(DelayTask task) {
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        headers.set("X-Delay-Task-Id", task.getTaskId());
        headers.set("X-Delay-Task-Type", task.getTaskType());
        headers.set("X-Delay-Task-Retry", String.valueOf(task.getRetryCount()));

        // HMAC签名（防伪造）
        String signature = HmacUtils.sign(
            task.getTaskId() + "|" + task.getExecuteAt(),
            secretKey
        );
        headers.set("X-Delay-Task-Signature", signature);

        // 合并自定义Headers
        if (StringUtils.isNotBlank(task.getCallbackHeaders())) {
            Map<String, String> custom = JsonUtils.parseMap(task.getCallbackHeaders());
            custom.forEach(headers::set);
        }

        return headers;
    }
}
```

### 5.4 重试处理器

```java
/**
 * 失败重试处理器
 * 采用指数退避策略
 */
@Component
@Slf4j
public class RetryHandler {

    @Autowired
    private DelayTaskMapper delayTaskMapper;

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Value("${delay-task.retry.max-attempts:3}")
    private int defaultMaxRetry;

    private static final double BACKOFF_MULTIPLIER = 2.0;
    private static final long MAX_RETRY_DELAY_SECONDS = 3600; // 最大重试间隔1小时
    private static final String RETRY_ZSET_KEY = "delay:task:retry:zset";

    /**
     * 调度重试
     */
    public void scheduleRetry(DelayTask task, String errorMsg) {
        int maxRetry = task.getMaxRetry() != null ? task.getMaxRetry() : defaultMaxRetry;
        int currentRetry = task.getRetryCount();

        if (currentRetry >= maxRetry) {
            // 超过最大重试次数，进入死信
            moveToDeadLetter(task, errorMsg);
            return;
        }

        // 计算下次重试时间（指数退避）
        long baseInterval = task.getRetryInterval() != null ? task.getRetryInterval() : 30;
        long nextDelay = (long) (baseInterval * Math.pow(BACKOFF_MULTIPLIER, currentRetry));
        nextDelay = Math.min(nextDelay, MAX_RETRY_DELAY_SECONDS);

        long nextRetryAt = System.currentTimeMillis() + nextDelay * 1000;

        // 更新任务状态
        task.setStatus(DelayTaskStatus.PENDING.getCode());
        task.setRetryCount(currentRetry + 1);
        task.setErrorMsg(StringUtils.left(errorMsg, 1000));
        task.setExecuteAt(nextRetryAt);
        delayTaskMapper.updateById(task);

        // 加入重试ZSET
        redisTemplate.opsForZSet().add(RETRY_ZSET_KEY, task.getTaskId(), nextRetryAt);

        log.info("延迟任务重试调度 taskId={}, retryCount={}, nextRetryAt={}s", 
            task.getTaskId(), currentRetry + 1, nextDelay);
    }

    /**
     * 移入死信队列
     */
    @Transactional(rollbackFor = Exception.class)
    public void moveToDeadLetter(DelayTask task, String errorMsg) {
        // 插入死信表
        DelayTaskDeadLetter deadLetter = new DelayTaskDeadLetter();
        deadLetter.setTaskId(task.getTaskId());
        deadLetter.setTaskType(task.getTaskType());
        deadLetter.setNamespace(task.getNamespace());
        deadLetter.setPayload(task.getPayload());
        deadLetter.setCallbackUrl(task.getCallbackUrl());
        deadLetter.setLastError(StringUtils.left(errorMsg, 2000));
        deadLetter.setTotalRetry(task.getRetryCount());
        deadLetter.setOriginalExecuteAt(task.getExecuteAt());
        deadLetterMapper.insert(deadLetter);

        // 更新原任务状态
        task.setStatus(DelayTaskStatus.DEAD_LETTER.getCode());
        task.setErrorMsg(StringUtils.left(errorMsg, 1000));
        task.setCompletedAt(System.currentTimeMillis());
        delayTaskMapper.updateById(task);

        // 清理Redis
        cleanRedisCache(task.getTaskId());

        // 告警
        MonitorAlarm.alarm("delay_task_dead_letter",
            String.format("taskId=%s, type=%s, retries=%d, error=%s",
                task.getTaskId(), task.getTaskType(), 
                task.getRetryCount(), errorMsg));

        log.error("延迟任务进入死信 taskId={}, type={}, totalRetry={}", 
            task.getTaskId(), task.getTaskType(), task.getRetryCount());
    }
}
```

```java
/**

@Service
public class DelayTaskCancelHandler {

    @Transactional(rollbackFor = Exception.class)
    public CancelResult cancel(String taskId, String reason) {

        task.setCompletedAt(System.currentTimeMillis());

        // 3. 清理详情缓存
        cleanRedisCache(taskId);

        return CancelResult.builder()
            .taskId(taskId)
            .previousStatus(DelayTaskStatus.PENDING.getDesc())
            .currentStatus(DelayTaskStatus.CANCELLED.getDesc())
            .build();
    }
```

## 7. 故障恢复与高可用

### 7.1 Redis 宕机恢复

```
故障场景: Redis 不可用，ZSET 中的任务丢失

恢复策略:
1. 应用层感知 Redis 异常后，自动降级到 MySQL 轮询模式
2. RecoveryScanner 定期从 MySQL 查询 execute_at <= now + 60s 的 PENDING 任务
3. 以 MySQL 为 Source of Truth，重建 Redis ZSET
4. Redis 恢复后，全量同步 MySQL 中的未完成任务到 ZSET
```

**降级轮询代码示例：**

```java
@Component
@Slf4j
public class FallbackPollingScanner {

    @Autowired
    private DelayTaskMapper delayTaskMapper;

    @Autowired
    private TriggerWorker triggerWorker;

    @Autowired
    private RedisHealthChecker redisHealthChecker;

    /**
     * 降级扫描（Redis不可用时启用）
     */
    @Scheduled(fixedDelay = 5000) // 5秒一次
    public void fallbackScan() {
        if (redisHealthChecker.isHealthy()) {
            return; // Redis正常，不需要降级
        }

        log.warn("Redis不可用, 启用MySQL降级轮询模式");

        long now = System.currentTimeMillis() + 60_000; // 预取未来1分钟内到期的任务
        List<DelayTask> tasks = delayTaskMapper.selectList(
            new LambdaQueryWrapper<DelayTask>()
                .eq(DelayTask::getStatus, DelayTaskStatus.PENDING.getCode())
                .le(DelayTask::getExecuteAt, now)
                .last("LIMIT 200")
        );

        for (DelayTask task : tasks) {
            try {
                // 乐观锁更新状态为RUNNING
                int updated = delayTaskMapper.casUpdateStatus(
                    task.getTaskId(),
                    DelayTaskStatus.PENDING.getCode(),
                    DelayTaskStatus.RUNNING.getCode()
                );

                if (updated > 0) {
                    // CAS成功，执行回调
                    triggerWorker.executeDirectly(task);
                }
            } catch (Exception e) {
                log.error("降级执行任务异常 taskId={}", task.getTaskId(), e);
            }
        }
    }
}
```

### 7.2 Worker 节点宕机恢复

```
故障场景: Worker 节点拉取任务后宕机，任务处于 RUNNING 状态但未完成

恢复策略:
1. processing ZSET TTL 机制：任务进入处理时写入 Worker 专属 ZSET，TTL=300s
2. RecoveryScanner 每分钟扫描 RUNNING 超过5分钟的任务
3. 将超时任务状态重置为 PENDING，retryCount+1
4. 重新加入调度 ZSET
5. 若超过最大重试次数则进入死信
```

### 7.3 高可用部署

| 维度 | 方案 |
|------|------|
| Redis | Redis Cluster 或 Sentinel 哨兵模式 |
| MySQL | 主从复制 + 半同步，单点故障自动切换 |
| Worker | 多实例部署（≥2），通过 Redis 分布式锁协调 |
| 调度器 | 多实例部署，同一 namespace 同时只有一个 active |

| Redis不可用 | health_check failed | P0 | 电话 + 钉钉 |
| MySQL不可用 | health_check failed | P0 | 电话 + 钉钉 |

### 11.2 SDK 内部实现（简化）

```java
@Component
public class DelayTaskClient {

    @Autowired
    private RestTemplate internalRestTemplate;

    @Value("${delay-task.engine.url}")
    private String engineBaseUrl;

    public RegisterResult register(DelayTaskRegisterRequest request) {
        String url = engineBaseUrl + "/api/v1/delay-task/register";
        ApiResponse<RegisterResult> resp = internalRestTemplate.postForObject(
            url, request, ApiResponse.class);
        return resp.getData();
    }

    public List<RegisterResult> registerBatch(List<DelayTaskRegisterRequest> tasks) {
        String url = engineBaseUrl + "/api/v1/delay-task/register/batch";
        Map<String, Object> body = Map.of("tasks", tasks);
        ApiResponse<List<RegisterResult>> resp = internalRestTemplate.postForObject(
            url, body, ApiResponse.class);
        return resp.getData();
    }

    public CancelResult cancel(String taskId, String reason) {
        String url = engineBaseUrl + "/api/v1/delay-task/cancel";
        Map<String, String> body = Map.of("taskId", taskId, "reason", reason);
        ApiResponse<CancelResult> resp = internalRestTemplate.postForObject(
            url, body, ApiResponse.class);
        return resp.getData();
    }

    public DelayTaskDetail query(String taskId) {
        String url = engineBaseUrl + "/api/v1/delay-task/" + taskId;
        ApiResponse<DelayTaskDetail> resp = internalRestTemplate.getForObject(
            url, ApiResponse.class);
        return resp.getData();
    }
}
```

## 12. 安全设计

### 12.1 回调安全

1. **HMAC 签名验证**：每个回调请求携带 `X-Delay-Task-Signature`，业务方应验证签名防止伪造
2. **内网隔离**：callbackUrl 必须为内网地址（`10.*` / `172.16-31.*` / `192.168.*` 或内部域名）
3. **URL 白名单**：支持配置回调域名白名单，防止 SSRF

### 12.2 接口安全

1. **认证**：所有 API 需携带内部服务 Token（`X-Internal-Token`）
2. **限流**：单个 namespace 注册频率限制 1000/s
3. **隔离**：不同 namespace 通过白名单控制，防止未授权服务注册任务

### 12.3 数据安全

1. **Payload 加密**：敏感 payload 字段支持 AES 加密存储
2. **日志脱敏**：日志中 payload 自动脱敏（手机号、身份证号等）
3. **定期清理**：终态任务 30 天后自动归档，90 天后物理删除

## 14. 与现有系统的关系

### 14.1 关联文档

| 系统模块 | 关系 | 说明 |
|----------|------|------|
| 服务端定时任务调度与批处理框架 | 互补 | 定时任务=Cron周期任务；本引擎=一次性延迟任务 |
| 服务端异步任务DAG编排引擎 | 互补 | DAG=复杂多步骤工作流；本引擎=简单延迟回调 |
| 服务端统一回调中心 | 协作 | 对外Webhook回调走回调中心；延迟任务内部回调自行处理 |
| 消息与推送服务 | 使用方 | 延迟引擎到期后调用消息服务发送通知 |
| 间隔重复算法与遗忘曲线复习调度 | 使用方 | 复习调度引擎计算复习时机，通过延迟引擎注册定时触发 |
| 订阅续费预警与自动续费失败补偿调度 | 使用方 | 续费提醒通过延迟引擎定时触发 |
| 服务端统一限流熔断 | 被保护 | 延迟引擎API受统一限流保护 |
| 服务端分布式链路追踪 | 集成 | 延迟引擎全链路接入Tracing |

### 14.2 不涉及的范围

本引擎**不负责**以下内容（由其他系统处理）：
- 周期性 Cron 任务调度 → 由「定时任务调度与批处理框架」处理
- 复杂多步骤工作流编排 → 由「异步任务DAG编排引擎」处理
- 消息推送到最终用户设备 → 由「消息与推送服务」处理
- 业务逻辑判断（如何选择复习时机等） → 由各业务服务处理
