# 教育平台搜索智能联想与实时热搜推荐引擎 - 详细设计

## 1. 概述

### 1.1 功能定位

本模块是 PrimeTop 搜索系统的**用户体验增强层**，位于用户搜索交互前端与底层搜索服务（全文检索 + 意图理解）之间。核心职责是在用户输入过程中提供**实时智能联想**、在搜索入口展示**实时热搜榜单**、管理**搜索历史**，并根据用户画像进行**个性化搜索推荐**。

与已有搜索模块的分工：

| 模块 | 核心职责 | 延迟要求 |
|------|---------|---------|
| **本模块**（智能联想与热搜） | 输入过程实时联想、热搜榜单、搜索历史、个性化推荐 | ≤30ms |
| 搜索服务与全文检索 | ES 底层索引构建、多字段查询、结果高亮 | ≤50ms |
| 搜索意图理解与查询改写 | 意图分类、同义词扩展、纠错改写、结果重排 | ≤50ms |
| 客户端全局搜索与智能发现 | 搜索 UI 交互、搜索结果页面渲染 | 客户端 |

### 1.2 核心问题

教育场景下的搜索联想面临独特挑战：

1. **学科术语专业性强**：用户输入"二次函"时需联想出"二次函数""二次函数图像""二次函数解析式"等完整术语
2. **学段上下文敏感**：小学生搜"函数"期望一次函数，高中生期望指数/对数/三角函数
3. **中英混合输入**：数学公式 LaTeX 片段、英语单词拼写等混合场景
4. **拼音容错**：低龄用户可能用拼音输入"er ci han shu"
5. **热搜时效性**：考前季节"中考数学真题"搜索量暴增，需快速反映在榜单

### 1.3 设计目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 联想响应延迟 | ≤ 30ms (P99) | 用户每次按键后到联想结果返回 |
| 联想命中率 | ≥ 70% | 用户从联想词中选择的比例 |
| 热搜榜单更新 | ≤ 5min | 热搜数据延迟不超过5分钟 |
| 热搜覆盖学段 | 全覆盖 | 榜单内容按学段/学科分类 |
| 零结果搜索率 | < 2% | 通过联想降低无结果搜索 |
| 搜索历史容量 | 每用户 200 条 | 滚动保留最近200条 |
| 日活联想QPS | ≥ 10,000 | 高峰期并发联想请求 |

### 1.4 适用范围

- APP 首页搜索栏（全局搜索入口）
- AI 对话页搜索（查找历史对话、知识点）
- 题库浏览页搜索
- 错题本搜索
- 同步课堂章节搜索
- 管理后台内容搜索（复用热搜展示）

### 2.2 核心流程

```
用户输入 "二次函"
    │
    ├─→ [联想匹配] Trie前缀匹配 → ["二次函数", "二次函数图像", "二次函数解析式"]
    │                                     │
    ├─→ [学段过滤] 高中用户 → 排除初中专属联想
    │                                     │
    ├─→ [热度加权] 按全平台搜索频次排序
    │                                     │
    ├─→ [个性化] 叠加用户学科偏好、近期学习内容
    │                                     │
    ├─→ [历史去重] 排除用户已搜过的完全匹配词
    │                                     │
    └─→ 返回 Top-10 联想词 + 类型标签 + 图标
```

## 3. 数据结构设计

### 3.1 搜索词库表 `search_term_dict`

存储平台所有可联想的搜索词及其元信息。

```sql
CREATE TABLE `search_term_dict` (
    `id`             BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `term_text`      VARCHAR(128) NOT NULL COMMENT '搜索词文本',
    `term_pinyin`    VARCHAR(256) NOT NULL COMMENT '全拼拼音 (空格分隔)',
    `term_initials`  VARCHAR(64)  NOT NULL COMMENT '首字母缩写',
    `term_type`      TINYINT      NOT NULL DEFAULT 1 COMMENT '词类型: 1=知识点, 2=题目, 3=章节, 4=考点, 5=通用',
    `subject_code`   VARCHAR(16)  DEFAULT NULL COMMENT '学科代码: MATH/CHINESE/ENGLISH/... 为NULL表示通用',
    `stage_mask`     INT          NOT NULL DEFAULT 0 COMMENT '适用学段位掩码: bit0=幼儿, bit1=小学, bit2=初中, bit3=高中',
    `grade_mask`     INT          NOT NULL DEFAULT 0 COMMENT '适用年级位掩码',
    `search_count`   BIGINT       NOT NULL DEFAULT 0 COMMENT '累计被搜索次数',
    `click_count`    BIGINT       NOT NULL DEFAULT 0 COMMENT '累计被点击次数',
    `popularity`     DECIMAL(8,2) NOT NULL DEFAULT 0.00 COMMENT '热度评分 (0-100)',
    `related_terms`  JSON         DEFAULT NULL COMMENT '关联搜索词 [{"term":"抛物线","weight":0.85}]',
    `entity_id`      VARCHAR(64)  DEFAULT NULL COMMENT '关联实体ID (知识点ID/题目ID等)',
    `status`         TINYINT      NOT NULL DEFAULT 1 COMMENT '状态: 0=禁用, 1=正常',
    `created_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_term_text_type_subject` (`term_text`, `term_type`, `subject_code`),
    KEY `idx_pinyin` (`term_pinyin`),
    KEY `idx_initials` (`term_initials`),
    KEY `idx_popularity` (`popularity` DESC),
    KEY `idx_subject_stage` (`subject_code`, `stage_mask`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='搜索词库';
```

### 3.2 用户搜索历史表 `user_search_history`

```sql
CREATE TABLE `user_search_history` (
    `id`             BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `user_id`        BIGINT       NOT NULL COMMENT '用户ID',
    `term_text`      VARCHAR(128) NOT NULL COMMENT '搜索词',
    `term_type`      TINYINT      NOT NULL DEFAULT 0 COMMENT '搜索类型: 1=知识点, 2=题目, 3=章节...',
    `search_source`  TINYINT      NOT NULL DEFAULT 1 COMMENT '来源: 1=首页, 2=AI对话, 3=题库, 4=错题',
    `result_count`   INT          NOT NULL DEFAULT 0 COMMENT '搜索结果数量',
    `clicked_rank`   INT          DEFAULT NULL COMMENT '用户点击了第几条结果 (NULL=未点击)',
    `search_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '搜索时间',
    `device_type`    TINYINT      DEFAULT 1 COMMENT '设备: 1=Android, 2=iOS, 3=Web',
    PRIMARY KEY (`id`),
    KEY `idx_user_time` (`user_id`, `search_time` DESC),
    KEY `idx_user_term` (`user_id`, `term_text`)

    PARTITION p_202609 VALUES LESS THAN (TO_DAYS('2026-10-01')),
```

### 3.3 热搜聚合统计表 `hot_search_daily`

```sql
CREATE TABLE `hot_search_daily` (
    `id`             BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `stat_date`      DATE         NOT NULL COMMENT '统计日期',
    `term_text`      VARCHAR(128) NOT NULL COMMENT '搜索词',
    `term_type`      TINYINT      NOT NULL COMMENT '词类型',

    `unique_users`   INT          NOT NULL DEFAULT 0 COMMENT '当日独立搜索用户数',
    `click_through`  INT          NOT NULL DEFAULT 0 COMMENT '点击结果次数',
```

### 3.4 搜索词关联关系表 `search_term_association`

存储搜索词之间的关联关系（协同搜索、语义关联）。

```sql
CREATE TABLE `search_term_association` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `source_term`     VARCHAR(128) NOT NULL COMMENT '源搜索词',
    `target_term`     VARCHAR(128) NOT NULL COMMENT '关联搜索词',
    `association_type` TINYINT     NOT NULL COMMENT '关联类型: 1=协同搜索, 2=语义相似, 3=知识点前置, 4=考点关联',
    `strength`        DECIMAL(6,4) NOT NULL DEFAULT 0.0000 COMMENT '关联强度 (0-1)',
    `sample_count`    INT          NOT NULL DEFAULT 0 COMMENT '统计样本量',
    `updated_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_source_target_type` (`source_term`, `target_term`, `association_type`),
    KEY `idx_source_strength` (`source_term`, `strength` DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='搜索词关联关系';
```

### 3.5 Redis 数据结构

#### 3.5.1 联想词 Trie（Redis Sorted Set + Hash 混合方案）

```
# 方案：按前缀分桶的 Sorted Set
# Key 格式：search:trie:{前缀2-4字}
# 每个桶存储该前缀下的候选联想词及其热度分

ZADD search:trie:二次  95.5 "二次函数"  88.2 "二次函数图像"  82.0 "二次函数解析式"
ZADD search:trie:二函  90.0 "二次函数"   0     ""  # 首字母缩写桶

# 完整词元信息 Hash
HSET search:term:二次函数
    type        1
    subject     MATH
    stage_mask  12   # 初中+高中 (bit2|bit3 = 4+8)
    entity_id   "kp_math_0451"
    popularity  95.5
```

#### 3.5.2 热搜榜单（分学段+学科的 Sorted Set）

```
# 全局热搜
ZADD search:hot:global  98.5 "二次函数"  95.0 "勾股定理"  92.3 "光合作用"

# 分学段热搜
ZADD search:hot:stage:3  96.0 "二次函数"  93.5 "勾股定理"  90.0 "电阻串联"
ZADD search:hot:stage:4  97.0 "导数"     94.0 "二次函数"  91.0 "牛顿第二定律"

# 分学科热搜
ZADD search:hot:subject:MATH  98.5 "二次函数"  95.0 "勾股定理"
ZADD search:hot:subject:PHY   93.0 "受力分析"  90.5 "电场强度"
```

#### 3.5.3 用户搜索历史（List + Hash）

```
# 用户最近搜索 (List, LTRIM 保持 200 条)
LPUSH search:history:user:{uid}  "二次函数" "光合作用" "勾股定理"
LTRIM search:history:user:{uid}  0 199

# 搜索词详情 Hash
HSET search:history:user:{uid}:detail:二次函数
    timestamp   "1723372800"
    type        1
    source      1
```

#### 3.5.4 搜索趋势滑动窗口

```
# 1分钟粒度的搜索计数 (用于实时热搜计算)
# 使用 Redis Sorted Set with timestamp score
ZADD search:stream:1min:二次函数  1723372800 "sess_001"  1723372832 "sess_002"
# 过期时间设为 30 分钟
EXPIRE search:stream:1min:二次函数 1800
```

## 5. 核心算法

### 5.1 联想词匹配引擎

采用 **Trie 前缀匹配 + 拼音双路召回 + 向量语义补充** 的三路并行策略。

#### 5.1.1 Trie 前缀匹配（主路径）

```python
class SearchSuggestionEngine:
    """
    联想词匹配引擎
    策略：Trie前缀匹配（中文）+ 拼音匹配（拼音输入）+ 语义向量召回（补充）
    """

    PREFIX_BUCKETS_KEY = "search:trie:{prefix}"  # Redis key 模板
    MIN_PREFIX_LEN = 1   # 最小前缀长度（单字即触发）
    MAX_PREFIX_LEN = 8   # 最大前缀桶长度（避免桶过大）

    async def suggest(
        self,
        query: str,
        stage: int = None,
        subject: str = None,
        grade: int = None,
        user_id: int = None,
        limit: int = 10
    ) -> list[dict]:
        """
        主入口：获取联想词
        """
        query = query.strip()
        if not query or len(query) > 50:
            return []

        # 并行三路召回
        prefix_results, pinyin_results, semantic_results = await asyncio.gather(
            self._trie_prefix_match(query, stage, subject, limit * 3),
            self._pinyin_match(query, stage, subject, limit * 2),
            self._semantic_match(query, stage, subject, limit)
        )

        # 融合去重 + 加权排序
        merged = self._merge_and_rank(
            prefix_results=prefix_results,     # 权重: 1.0
            pinyin_results=pinyin_results,     # 权重: 0.85
            semantic_results=semantic_results, # 权重: 0.6
            query=query,
            user_id=user_id,
            limit=limit
        )

        return merged[:limit]

    async def _trie_prefix_match(
        self, query: str, stage: int, subject: str, limit: int
    ) -> list[dict]:
        """
        Redis Trie 前缀匹配
        将 query 作为前缀，查对应的 Sorted Set 桶
        """
        results = []

        # 对中文 query，取 2~4 字前缀查桶
        for prefix_len in range(min(len(query), 2),
                                 min(len(query), self.MAX_PREFIX_LEN) + 1):
            prefix = query[:prefix_len]
            cache_key = self.PREFIX_BUCKETS_KEY.format(prefix=prefix)

            # ZREVRANGE 按热度降序获取
            raw_items = await redis.zrevrange(
                cache_key, 0, limit - 1, withscores=True
            )

            for term_text, score in raw_items:
                # 必须以完整 query 为前缀（桶可能有残留数据）
                if not term_text.startswith(query):
                    continue

                term_info = await self._get_term_info(term_text)
                if not term_info or not self._stage_match(term_info, stage):
                    continue
                if subject and not self._subject_match(term_info, subject):
                    continue

                results.append({
                    "term": term_text,
                    "type": term_info["type"],
                    "subject": term_info.get("subject_code"),
                    "entity_id": term_info.get("entity_id"),
                    "popularity": float(score),
                    "matched_field": "prefix",
                    "matched_prefix": prefix
                })

            if len(results) >= limit:
                break

        return results

    async def _pinyin_match(
        self, query: str, stage: int, subject: str, limit: int
    ) -> list[dict]:
        """
        拼音匹配：支持用户用拼音输入搜索
        如 "er ci han shu" → 匹配 "二次函数"
        """
        # 判断是否为拼音输入
        if not self._is_pinyin(query):
            return []

        # 全拼匹配
        pinyin_normalized = query.lower().replace(" ", "")
        cache_key = f"search:pinyin:{pinyin_normalized[:6]}"
        raw_items = await redis.zrevrange(
            cache_key, 0, limit - 1, withscores=True
        )

        results = []
        for term_text, score in raw_items:
            term_info = await self._get_term_info(term_text)
            if not term_info or not self._stage_match(term_info, stage):
                continue

            results.append({
                "term": term_text,
                "type": term_info["type"],
                "subject": term_info.get("subject_code"),
                "entity_id": term_info.get("entity_id"),
                "popularity": float(score),
                "matched_field": "pinyin"
            })

        return results

    async def _semantic_match(
        self, query: str, stage: int, subject: str, limit: int
    ) -> list[dict]:
        """
        语义向量召回：当 Trie 和拼音召回不足时补充
        如 "抛物线顶点" → 召回 "二次函数顶点公式"
        """
        # 仅在 query >= 3 字时启用，避免短 query 语义噪音
        if len(query) < 3:
            return []

        # 调用向量服务获取 query embedding
        embedding = await self.embedding_service.encode(query)

        # 向量检索（使用 ES dense_vector 或 Redis Vector Search）
        raw_results = await self.vector_search(
            embedding=embedding,
            stage=stage,
            subject=subject,
            limit=limit,
            min_score=0.65  # 最低相似度阈值
        )

        return [
            {
                "term": r["term"],
                "type": r["type"],
                "subject": r.get("subject_code"),
                "entity_id": r.get("entity_id"),
                "popularity": r.get("popularity", 50.0),
                "matched_field": "semantic",
                "semantic_score": r["score"]
            }
            for r in raw_results
        ]

    def _merge_and_rank(
        self,
        prefix_results: list[dict],
        pinyin_results: list[dict],
        semantic_results: list[dict],
        query: str,
        user_id: int,
        limit: int
    ) -> list[dict]:
        """
        多路召回融合：加权 + 去重 + 用户偏好叠加
        """
        weight_map = {
            "prefix": 1.0,
            "pinyin": 0.85,
            "semantic": 0.60
        }

        # 去重合并
        merged = {}
        for source, results in [
            ("prefix", prefix_results),
            ("pinyin", pinyin_results),
            ("semantic", semantic_results)
        ]:
            for item in results:
                term = item["term"]
                weight = weight_map[source]

                # 精确匹配前缀加分
                if term.startswith(query):
                    weight *= 1.15

                # 完全匹配降权（用户已经在输入这个词，不需要联想出一样的）
                if term == query:
                    weight *= 0.3

                score = item["popularity"] * weight

                if term not in merged or score > merged[term]["_final_score"]:
                    item["_final_score"] = score
                    item["_source"] = source
                    merged[term] = item

        # 用户偏好加权
        if user_id:
            user_prefs = await self._get_user_search_preferences(user_id)
            for term, item in merged.items():
                # 用户历史搜过的相关词加权
                if term in user_prefs.get("related_terms", set()):
                    item["_final_score"] *= 1.2
                # 用户学科偏好加权
                if item.get("subject") in user_prefs.get("preferred_subjects", set()):
                    item["_final_score"] *= 1.1

        # 排序
        sorted_items = sorted(
            merged.values(),
            key=lambda x: x["_final_score"],
            reverse=True
        )

        # 清理内部字段
        for item in sorted_items:
            item.pop("_final_score", None)
            item.pop("_source", None)

        return sorted_items
```

#### 5.1.2 Trie 树构建与维护

联想 Trie 树在 Redis 中的构建逻辑：

```python
class TrieBuilder:
    """
    将 MySQL search_term_dict 数据同步到 Redis Trie
    按前缀分桶存储为 Sorted Set
    """

    BUCKET_MIN_LEN = 2   # 最小前缀桶长度
    BUCKET_MAX_LEN = 6   # 最大前缀桶长度

    async def rebuild_trie(self):
        """
        全量重建 Redis Trie（每日凌晨低峰期执行）
        """
        # 清理旧 Trie
        old_keys = await redis.keys("search:trie:*")
        if old_keys:
            await redis.delete(*old_keys)

        # 分批从 MySQL 读取搜索词
        offset = 0
        batch_size = 5000
        while True:
            terms = await db.fetch_all(
                "SELECT term_text, term_pinyin, term_initials, popularity, "
                "subject_code, stage_mask, status "
                "FROM search_term_dict WHERE status = 1 "
                "ORDER BY id LIMIT %s OFFSET %s",
                [batch_size, offset]
            )
            if not terms:
                break

            pipe = redis.pipeline()
            for term in terms:
                self._add_to_trie(pipe, term)
            await pipe.execute()

            offset += batch_size

        logger.info(f"Trie rebuild complete. Processed {offset} terms.")

    async def incremental_update(self, term: dict, action: str = "upsert"):
        """
        增量更新（单条搜索词变更时调用）
        """
        if action == "delete":
            await self._remove_from_trie(term)
            return

        pipe = redis.pipeline()
        self._add_to_trie(pipe, term)
        await pipe.execute()

    def _add_to_trie(self, pipe, term: dict):
        """
        将单个搜索词加入 Redis Trie
        策略：生成 2~6 字前缀，分别加入对应桶
        """
        text = term["term_text"]
        popularity = float(term["popularity"])

        # 中文前缀桶
        for prefix_len in range(self.BUCKET_MIN_LEN,
                                 min(len(text), self.BUCKET_MAX_LEN) + 1):
            prefix = text[:prefix_len]
            cache_key = f"search:trie:{prefix}"
            pipe.zadd(cache_key, {text: popularity})

        # 拼音前缀桶
        pinyin = term.get("term_pinyin", "")
        if pinyin:
            pinyin_clean = pinyin.replace(" ", "").lower()
            for plen in range(2, min(len(pinyin_clean), 8) + 1):
                p_prefix = pinyin_clean[:plen]
                cache_key = f"search:pinyin:{p_prefix}"
                pipe.zadd(cache_key, {text: popularity})

        # 首字母缩写桶
        initials = term.get("term_initials", "")
        if initials and len(initials) >= 2:
            cache_key = f"search:initials:{initials[:4]}"
            pipe.zadd(cache_key, {text: popularity})

        # 词元信息 Hash
        info_key = f"search:term:{text}"
        pipe.hset(info_key, mapping={
            "type": term.get("term_type", 1),
            "subject": term.get("subject_code", ""),
            "stage_mask": term.get("stage_mask", 0),
            "entity_id": term.get("entity_id", ""),
            "popularity": popularity
        })
```

### 5.2 热搜排序算法

#### 5.2.1 实时热度计算

```python
class HotSearchCalculator:
    """
    热搜热度评分计算器
    采用类 Hacker News 算法，结合教育场景调优
    """

    # 权重常量
    SEARCH_WEIGHT = 1.0       # 搜索次数权重
    CLICK_WEIGHT = 1.5        # 点击权重（点击比搜索更有价值）
    UNIQUE_WEIGHT = 2.0       # 独立用户权重（去刷量）
    TIME_DECAY_HOURS = 24.0   # 时间衰减半衰期（小时）
    ZERO_RESULT_PENALTY = 0.5 # 零结果惩罚系数

    async def calculate_hot_score(
        self,
        term: str,
        time_window_hours: int = 24
    ) -> float:
        """
        计算单个搜索词的热度分

        公式:
        score = (search_count * W_search + click_count * W_click
                + unique_users * W_unique)
                * time_decay_factor
                * zero_result_penalty

        time_decay_factor = 0.5 ^ (hours_since_peak / TIME_DECAY_HOURS)
        """
        # 从 Redis 滑动窗口获取统计数据
        stats = await self._get_term_stats(term, time_window_hours)

        if not stats["search_count"]:
            return 0.0

        # 基础热度分
        base_score = (
            stats["search_count"] * self.SEARCH_WEIGHT
            + stats["click_count"] * self.CLICK_WEIGHT
            + stats["unique_users"] * self.UNIQUE_WEIGHT
        )

        # 时间衰减因子
        decay = self._time_decay(stats["peak_timestamp"])

        # 零结果惩罚
        zero_penalty = 1.0
        if stats["zero_result_rate"] > 0.3:
            zero_penalty = self.ZERO_RESULT_PENALTY

        score = base_score * decay * zero_penalty

        # 考试季节性加权（中考/高考前 3 个月相关词加权）
        seasonal_boost = await self._get_seasonal_boost(term)
        score *= seasonal_boost

        # 人工置顶/置底（运营干预）
        manual_weight = await self._get_manual_weight(term)

        return round(score * manual_weight, 2)

    def _time_decay(self, peak_timestamp: float) -> float:
        """
        时间衰减：越久没被搜索，分数越低
        """
        hours_elapsed = (time.time() - peak_timestamp) / 3600
        return 0.5 ** (hours_elapsed / self.TIME_DECAY_HOURS)

    async def _get_seasonal_boost(self, term: str) -> float:
        """
        考试季节性加权
        如：中考前 "中考真题" 加权 1.5
        """
        now = datetime.now()
        month = now.month

        # 中考季节（5-6月）
        if month in (5, 6) and any(
            kw in term for kw in ["中考", "初中毕业", "中考真题"]
        ):
            return 1.5

        # 高考季节（5-6月）
        if month in (5, 6) and any(
            kw in term for kw in ["高考", "高中毕业", "高考真题"]
        ):
            return 1.8

        # 期末季节（12-1月, 6-7月）
        if month in (12, 1, 6, 7) and "期末" in term:
            return 1.3

        return 1.0

    async def refresh_hot_search_ranking(self):
        """
        定时刷新热搜榜单（每 5 分钟执行）
        """
        # 1. 从滑动窗口获取近 1 小时搜索量 Top-500 词
        recent_terms = await self._get_recent_top_terms(
            window_minutes=60, top_n=500
        )

        # 2. 计算每个词的综合热度
        scored_terms = []
        for term_data in recent_terms:
            score = await self.calculate_hot_score(term_data["term"])
            if score > 0:
                scored_terms.append((term_data["term"], score))

        # 3. 更新 Redis 热搜榜单
        pipe = redis.pipeline()

        # 清空旧榜单
        pipe.delete("search:hot:global")
        for stage in (1, 2, 3, 4):
            pipe.delete(f"search:hot:stage:{stage}")
        for subject in ("MATH", "CHINESE", "ENGLISH", "PHY", "CHEM",
                         "BIO", "HIS", "GEO", "POL"):
            pipe.delete(f"search:hot:subject:{subject}")

        # 写入新榜单
        for term, score in scored_terms:
            pipe.zadd("search:hot:global", {term: score})

            # 分学段
            term_info = await self._get_term_info(term)
            if term_info:
                for stage in self._extract_stages(term_info["stage_mask"]):
                    pipe.zadd(f"search:hot:stage:{stage}", {term: score})

                if term_info.get("subject_code"):
                    pipe.zadd(
                        f"search:hot:subject:{term_info['subject_code']}",
                        {term: score}
                    )

        await pipe.execute()

        # 4. 持久化到 MySQL（供历史分析和离线计算）
        await self._persist_daily_stats(scored_terms)
```

class PersonalizedRecommendation:

`python
class SearchEventProcessor:
    """
    搜索行为事件处理器
    双写：Redis 实时计数 + Kafka 异步持久化
    """

    async def on_search_event(self, event: dict):
        """
        处理搜索事件
        """
        term = event["term"]
        user_id = event.get("user_id")
        timestamp = event["timestamp"]

        # 1. Redis 滑动窗口计数（用于实时热搜）
        minute_key = f"search:stream:1min:{term}"
        await redis.zadd(minute_key, {event["session_id"]: timestamp})
        await redis.expire(minute_key, 1800)  # 30分钟过期

        # 独立用户 HyperLogLog
        if user_id:
            user_key = f"search:users:1h:{term}"
            await redis.pfadd(user_key, str(user_id))
            await redis.expire(user_key, 7200)

        # 2. Kafka 异步持久化
        await kafka_producer.send(
            topic="search_events",
            value=event
        )

        # 3. 更新用户搜索历史
        if user_id:
            await self._update_user_history(user_id, event)

    async def _update_user_history(self, user_id: int, event: dict):
        """
        更新用户搜索历史（Redis + 异步写入 MySQL）
        """
        term = event["term"]

        # Redis List (LPUSH + LTRIM)
        history_key = f"search:history:user:{user_id}"
        await redis.lpush(history_key, term)
        await redis.ltrim(history_key, 0, 199)  # 保持 200 条

        # 搜索详情 Hash
        detail_key = f"search:history:user:{user_id}:detail:{term}"
        await redis.hset(detail_key, mapping={
            "timestamp": event["timestamp"],
            "type": event.get("type", 0),
            "source": event.get("source", 1),
        })
        await redis.expire(detail_key, 86400 * 30)  # 30天过期

        # 异步写入 MySQL
        await kafka_producer.send(
            topic="search_history_persist",
            value={
                "user_id": user_id,
                "term_text": term,
                "term_type": event.get("type", 0),
                "search_source": event.get("source", 1),
                "result_count": event.get("result_count", 0),
                "search_time": datetime.now().isoformat(),
                "device_type": event.get("device_type", 1),
            }
        )
`

### 7.2 热搜缓存策略

`python
class HotSearchCache:
    """
    热搜多级缓存
    """

    # 客户端缓存策略
    CLIENT_CACHE_STRATEGY = {
        "global": {"ttl": 300, "max_items": 20},    # 全局热搜 5min
        "stage":  {"ttl": 300, "max_items": 15},    # 学段热搜 5min
        "subject":{"ttl": 600, "max_items": 10},    # 学科热搜 10min
    }

    async def get_hot_search(
        self, category: str, stage: int = None, subject: str = None
    ) -> list[dict]:
        """
        获取热搜（带缓存）
        """
        cache_key = self._build_cache_key(category, stage, subject)

        # L2: Redis 缓存
        cached = await redis.get(cache_key)
        if cached:
            return json.loads(cached)

        # 缓存未命中：从 Redis ZSet 读取并组装
        zset_key = self._build_zset_key(category, stage, subject)
        raw_items = await redis.zrevrange(zset_key, 0, 19, withscores=True)

        items = []
        for rank, (term, score) in enumerate(raw_items, 1):
            term_info = await self._get_term_info(term)
            trend = await self._calculate_trend(term)
            items.append({
                "rank": rank,
                "term": term,
                "search_count_today": int(score),
                "trend": trend["direction"],
                "trend_pct": trend["pct"],
                "type": term_info.get("type", 5),
                "subject": term_info.get("subject_code"),
                "entity_id": term_info.get("entity_id"),
            })

        # 写回缓存
        await redis.setex(cache_key, 300, json.dumps(items, ensure_ascii=False))

        return items

    async def _calculate_trend(self, term: str) -> dict:
        """
        计算搜索趋势（对比过去1小时 vs 前1小时）
        """
        current_hour = await self._get_search_count(term, hours=1)
        previous_hour = await self._get_search_count(
            term, hours=1, offset_hours=1
        )

        if previous_hour == 0:
            return {"direction": "up" if current_hour > 0 else "stable", "pct": 100.0}

        pct = ((current_hour - previous_hour) / previous_hour) * 100

        if pct > 10:
            direction = "up"
        elif pct < -10:
            direction = "down"
        else:
            direction = "stable"

        return {"direction": direction, "pct": round(abs(pct), 1)}
`

## 8. 错误处理与降级策略

### 8.1 错误处理矩阵

| 异常场景 | 影响范围 | 降级策略 | 用户感知 |
|---------|---------|---------|---------|
| Redis Trie 不可用 | 联想功能 | 返回用户搜索历史 Top-N | 联想词减少，可继续手动输入 |
| Redis 热搜 ZSet 不可用 | 热搜榜单 | 返回上次缓存的榜单（标记为延迟数据） | 榜单不更新，不影响搜索 |
| 向量服务超时 | 语义联想补充 | 仅返回 Trie + 拼音匹配结果 | 联想结果可能减少，体验略降 |
| MySQL 词库不可用 | 联想词元信息 | 使用 Redis 缓存的 term Hash | 无感知（缓存命中） |
| Kafka 不可用 | 搜索行为持久化 | 丢弃事件，仅保留 Redis 实时计数 | 无感知（热搜不受影响） |
| 用户画像服务不可用 | 个性化推荐 | 返回通用热搜而非个性化推荐 | 推荐不够精准 |

### 8.2 熔断器配置

`python
from circuitbreaker import circuit

class SuggestionService:

    @circuit(
        failure_threshold=10,
        recovery_timeout=30,
        expected_exception=RedisError
    )
    async def get_suggestions(self, query: str, **kwargs) -> list[dict]:
        """
        带熔断器的联想接口
        Redis 连续失败 10 次后熔断 30 秒
        """
        return await self.engine.suggest(query, **kwargs)

    async def get_suggestions_fallback(
        self, query: str, user_id: int = None, **kwargs
    ) -> list[dict]:
        """
        熔断降级：返回用户搜索历史中包含 query 的词
        """
        if not user_id:
            return []

        history = await redis.lrange(
            f"search:history:user:{user_id}", 0, 19
        )
        return [
            {"term": h, "type": 0, "matched_field": "history_fallback"}
            for h in history
            if query.lower() in h.lower()
        ]
`

`python
class TrieOptimizer:
    """
    Redis Trie 内存优化
    """

    async def optimize_buckets(self):
        """
        定时优化 Trie 桶（每小时执行）
        1. 合并过小桶（<3 词）
        2. 拆分过大桶（>500 词）
        3. 清理低频词
        """
        keys = await redis.keys("search:trie:*")

        for key in keys:
            count = await redis.zcard(key)
            prefix = key.split(":")[-1]

            if count > 500:
                # 大桶：按更长的前缀拆分（用户输入更多字时自然分流）
                # 无需主动拆分，长前缀桶已存在
                pass

            if count < 3:
                # 小桶：删除（节省内存）
                # 但保留前2字桶，只清理4字以上且<3词的桶
                if len(prefix) >= 4:
                    await redis.delete(key)

        # 统计内存占用
        info = await redis.info("memory")
        logger.info(f"Redis memory used: {info['used_memory_human']}")
`

## 12. 安全与合规

### 12.1 搜索词安全过滤

所有联想词和热搜词在展示前必须经过安全过滤：

`python
class SearchSafetyFilter:
    """
    搜索词安全过滤器
    确保联想和热搜不展示敏感内容
    """

    async def filter_suggestions(
        self, suggestions: list[dict], stage: int
    ) -> list[dict]:
        """
        过滤联想词中的敏感内容
        """
        safe = []
        for item in suggestions:
            # 1. 敏感词检查
            if await self.sensitive_word_service.contains(
                item["term"], level="strict"
            ):
                logger.warning(
                    f"Blocked sensitive suggestion: {item['term']}"
                )
                continue

            # 2. 年龄不适宜内容过滤
            if not self._is_age_appropriate(item["term"], stage):
                continue

            # 3. 答案泄露检查（防止通过搜索获取考试答案）
            if await self._is_answer_leak(item["term"], stage):
                continue

            safe.append(item)

        return safe

    async def filter_hot_search(
        self, hot_items: list[dict]
    ) -> list[dict]:
        """
        过滤热搜中的敏感内容
        """
        safe = []
        for item in hot_items:
            if await self.sensitive_word_service.contains(
                item["term"], level="normal"
            ):
                # 敏感热搜：从榜单移除并记录
                await self._log_blocked_hot_term(item["term"])
                continue

            safe.append(item)

        return safe
`
