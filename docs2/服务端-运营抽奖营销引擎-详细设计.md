## 1. 模块概述

### 1.1 定位

运营抽奖营销引擎是积分虚拟经济体系的**核心消耗出口**与运营侧的**活跃拉动引擎**：

1. **积分消耗出口**：学生通过学习行为（打卡、完成任务、连续学习）获得积分后，需要高趣味性的消耗场景维持虚拟经济循环。抽奖以小博大、结果不确定的娱乐性，是积分留存与消耗平衡的重要调节阀（《积分与虚拟经济体系》防通胀手段之一）。
2. **运营节奏工具**：开学季、考试季、寒暑假专题等运营节点，通过限时抽奖活动拉动 DAU 与回访。
3. **权益/优惠券发放通道**：奖池可配置会员体验天数、优惠券、学习资源包、实物学习用品，以低成本权益撬动付费转化（中奖优惠券 → 下单转化链路）。
4. **玩法统一抽象**：大转盘（LuckyWheel）、九宫格（NineGrid）、盲盒（MysteryBox）、刮刮卡（ScratchCard）四种玩法共享同一套活动配置、概率算法、库存与履约体系，客户端只负责表现形式差异。

**教育产品合规红线（决定本引擎与普通电商抽奖的根本差异）**：

- 抽奖机会**只能来自学习行为奖励与运营发放**，严禁向未成年人售卖抽奖次数（不得出现"6元10连抽"类现金直购入口）；家长端购买"抽奖机会礼包"仅作为兜底供给且需家长身份核验 + 二次确认。
- 各奖品**中奖概率必须客户端可公示**，服务端存证概率快照，随时可审计（透明度要求）。
- 单个奖品市场价值不超过 50,000 元（《规范促销行为暂行规定》抽奖式有奖销售上限），后台配置校验拦截。
- 青少年模式 / 家长管控关闭抽奖入口时，客户端隐藏入口、服务端拒绝请求双保险。
- 严禁虚假中奖、伪造"仅剩最后 X 次"倒计时等诱导性设计（《广告法》红线）。

### 1.3 设计原则

1. **库存不超发**：奖品库存以 Redis 原子预扣为准入闸门，DB 异步落库对账；预扣失败即返回未中奖兜底文案，宁可少发不可超发。
2. **概率可审计**：每次抽奖落库时记录当时生效的概率版本号（`probability_version`），任何概率调整生成新版本快照存证，做到"任意一笔回放可解释"。
3. **机会即资产**：抽奖机会是用户虚拟资产，发放/消耗/过期全程流水可对账，与积分同等严肃对待。
4. **发奖最终一致**：中奖落库与发奖解耦，发奖失败进补偿队列指数退避重试，超过阈值转人工工单，绝不静默丢单。
5. **幂等**：抽奖请求带 `draw_token`（一次性），回调与重试以业务唯一键约束兜底。
6. **未成年人优先保护**：所有入口默认按"未成年人模式"收紧；风控与家长管控双开关。
7. **可降级**：Redis/风控依赖故障时返回友好降级话术，不影响主 App 其他功能。

### 1.4 业务边界

本引擎负责：抽奖活动配置与生命周期、奖池与概率、机会账户（发放/消耗/过期）、抽奖执行、中奖记录、非实物奖品发奖编排、实物奖品履约单创建与状态跟踪（履约细节由履约服务负责）。

本引擎不负责：积分账本（积分服务）、优惠券核销规则（优惠券引擎）、会员权益生效逻辑（会员服务）、物流发货执行（履约服务）、任务完成判定（任务系统）、页面渲染（客户端动态化引擎）。

## 2. 核心概念与数据模型

### 2.1 概念模型

```text
DrawActivity (抽奖活动聚合根)
├── PrizePool            奖池（活动 × 奖品，含权重/库存/日限）
│     └── Prize          奖品定义（可跨活动复用：优惠券模板/会员天数/积分包/实物SKU/谢谢参与）
├── DrawChance           用户机会账户（按 活动×用户 汇总，含来源明细流水）
│     └── ChanceFlow     机会流水（来源/消耗/过期/冻结）
├── DrawRecord           抽奖流水（每一次 Roll 的完整快照：概率版本/权重快照/种子）
└── WinningRecord        中奖记录（→ 积分加账 / 发券 / 会员天数 / 实物履约单 / 谢谢参与无履约）
      └── FulfillOrder   履约单（实物类，关联履约服务的 delivery order）
```

- 一次 `DrawRecord` 必然产出一条 `WinningRecord`（奖品可以是 `THANKS` 谢谢参与，视为"中了空气奖"），保证审计闭环。
- 概率配置不在活动表内联，独立 `probability_version` 快照表，支持回放。

### 2.2 抽奖活动（draw_activity）

```sql
CREATE TABLE draw_activity (
    id                    BIGSERIAL PRIMARY KEY,
    code                  VARCHAR(64) NOT NULL UNIQUE,       -- 活动编码，如 LW-OPEN-202609
    name                  VARCHAR(128) NOT NULL,             -- "开学季幸运大转盘"
    draw_type             VARCHAR(32) NOT NULL,              -- WHEEL / NINE_GRID / MYSTERY_BOX / SCRATCH_CARD
    scene_code            VARCHAR(64) NOT NULL,              -- 承载场景：home / summer_camp / points_mall ...
    begin_time            TIMESTAMPTZ NOT NULL,
    end_time              TIMESTAMPTZ NOT NULL,
    cost_type             VARCHAR(16) NOT NULL,               -- CHANCE（消耗机会）/ POINTS（直接消耗积分）/ FREE（免费限次）
    cost_points           INTEGER NOT NULL DEFAULT 0,        -- cost_type=POINTS 时每次消耗积分
    per_user_daily_limit  INTEGER NOT NULL DEFAULT 3,        -- 每用户每日抽奖次数上限（含未中奖）
    per_user_total_limit  INTEGER NOT NULL DEFAULT -1,       -- 活动期内总次数上限，-1 不限
    guarantee_enable      BOOLEAN NOT NULL DEFAULT FALSE,    -- 保底开关：连续 N 次未中实物/权益奖则第 N+1 次必中
    guarantee_threshold   INTEGER NOT NULL DEFAULT 10,       -- 保底阈值 N
    guarantee_prize_id    BIGINT,                            -- 保底奖品（须为 THANKS 之外的确定性奖品）
    purchase_enable       BOOLEAN NOT NULL DEFAULT FALSE,    -- 是否开放家长端购买机会礼包（默认关闭）
    minor_visible         BOOLEAN NOT NULL DEFAULT TRUE,     -- 未成年人是否可见（合规审查点，虚假可见会被审核拒绝）
    status                VARCHAR(32) NOT NULL DEFAULT 'DRAFT',
    audit_status          VARCHAR(32) NOT NULL DEFAULT 'PENDING',
    probability_version   INTEGER NOT NULL DEFAULT 0,        -- 当前生效概率版本号，每次奖池变更 +1
    page_config           JSONB NOT NULL DEFAULT '{}',       -- 客户端 JSON 渲染配置（转盘分区/九宫格布局/动画），透传给动态化页面引擎
    ext_config            JSONB NOT NULL DEFAULT '{}',       -- 扩展：时段轮换、文案组、分享加次数开关等
    creator_id            BIGINT NOT NULL,
    created_at            TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_draw_activity_time ON draw_activity (begin_time, end_time) WHERE status <> 'DRAFT';
```

要点：

- `cost_type=CHANCE` 为主流模式（机会来自任务）；`POINTS` 模式给高自由度活动用（直接花积分抽）；`FREE` 仅用于官方补偿类小活动。
- `guarantee_*` 保底三字段必须同时生效，审核时校验 `guarantee_enable=true ⇒ guarantee_threshold≥2 且 guarantee_prize_id 非空且该奖品在池内`。
- `page_config` 只做透传存储，本引擎不解析其内部结构（客户端动态化引擎的 `schema` 约束）。

### 2.3 奖品与奖池（prize / prize_pool）

```sql
CREATE TABLE prize (
    id              BIGSERIAL PRIMARY KEY,
    code            VARCHAR(64) NOT NULL UNIQUE,            -- PRIZE-COUPON-50 / PRIZE-MEMBER-3D / PRIZE-POINTS-100 / PRIZE-GOODS-PEN ...
    name            VARCHAR(128) NOT NULL,                  -- "50元会员立减券"
    prize_type      VARCHAR(32) NOT NULL,                   -- POINTS / COUPON / MEMBER_DAYS / GOODS / RESOURCE / THANKS
    icon_url        VARCHAR(512) NOT NULL DEFAULT '',
    market_value    NUMERIC(12,2) NOT NULL DEFAULT 0,       -- 市场价值（元），后台校验 ≤ 50000（合规上限）
    payload         JSONB NOT NULL DEFAULT '{}',            -- 类型化载荷，见下方说明
    status          VARCHAR(16) NOT NULL DEFAULT 'ENABLED', -- ENABLED / DISABLED
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE prize_pool (
    id                BIGSERIAL PRIMARY KEY,
    activity_id       BIGINT NOT NULL REFERENCES draw_activity(id),
    prize_id          BIGINT NOT NULL REFERENCES prize(id),
    weight            INTEGER NOT NULL,                     -- 权重（万分比基础），同一活动所有 weight 之和即总权重
    total_stock       INTEGER NOT NULL DEFAULT -1,          -- 活动期总库存，-1 不限（仅 THANKS 可不限）
    daily_stock       INTEGER NOT NULL DEFAULT -1,          -- 每日库存，-1 不限
    per_user_win_limit INTEGER NOT NULL DEFAULT 1,          -- 每用户该奖品中奖上限（防一人抽走大奖）
    stock_remaining   INTEGER NOT NULL DEFAULT 0,           -- DB 剩余库存（Redis 为准入闸门，DB 异步收敛）
    daily_reset_stock INTEGER NOT NULL DEFAULT 0,           -- 当日已重置标记用字段，配合日库存任务
    notify_on_win     BOOLEAN NOT NULL DEFAULT TRUE,        -- 中奖是否弹全局喜报（可配置关闭防打扰）
    UNIQUE (activity_id, prize_id)
);
CREATE INDEX idx_prize_pool_activity ON prize_pool (activity_id);
```

`prize.payload` 按类型约定 Schema（服务端强校验）：

```jsonc
// POINTS
{ "points": 100 }
// COUPON：关联优惠券引擎的券模板
{ "coupon_template_code": "CT-MEMBER-50", "valid_days_after_issue": 7 }
// MEMBER_DAYS
{ "member_days": 3, "member_level": "VIP", "overlapping_policy": "STACK" }
// GOODS：关联履约服务的实物 SKU
{ "goods_sku_code": "SKU-STATIONERY-PEN01", "need_address": true, "address_expire_hours": 168 }
// RESOURCE：学习资源包（课件/真题集），调用资源包服务发放
{ "resource_pack_code": "RP-EXAM-2027-01" }
// THANKS：无载荷
{}
```

**约束**：`THANKS` 奖品 `weight` 通常占大头且 `total_stock=-1`；任何活动奖池必须包含恰好一个 `THANKS` 奖品（审核校验），作为库存耗尽与未中奖的统一兜底展示。

### 2.4 概率快照（probability_snapshot）

```sql
CREATE TABLE probability_snapshot (
    id            BIGSERIAL PRIMARY KEY,
    activity_id   BIGINT NOT NULL,
    version       INTEGER NOT NULL,
    snapshot      JSONB NOT NULL,        -- [{prize_code, weight, probability_permille(千分比，计算后固化)}...]
    total_weight  INTEGER NOT NULL,
    operator_id   BIGINT NOT NULL,
    reason        VARCHAR(255) NOT NULL DEFAULT '',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (activity_id, version)
);
```

- 每次奖池 `weight` / `total_stock` 变更，发布时自动生成新版本；`DrawRecord` 记录 `probability_version`，实现"任意一笔抽奖可回放当时概率"。
- 千分比 `probability_permille` 在发布时按 `weight / total_weight` 计算固化，同时用于**客户端公示接口**——公示值与实际 Roll 值同源，杜绝"公示一套、后台一套"。

### 2.5 机会账户与流水（draw_chance / chance_flow）

```sql
CREATE TABLE draw_chance (
    id           BIGSERIAL PRIMARY KEY,
    activity_id  BIGINT NOT NULL,
    user_id      BIGINT NOT NULL,
    total        INTEGER NOT NULL DEFAULT 0,   -- 累计获得
    consumed     INTEGER NOT NULL DEFAULT 0,   -- 累计消耗
    expired      INTEGER NOT NULL DEFAULT 0,   -- 累计过期
    balance      INTEGER NOT NULL DEFAULT 0,   -- 当前可用（= total - consumed - expired，事务维护）
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (activity_id, user_id)
);

CREATE TABLE chance_flow (
    id           BIGSERIAL PRIMARY KEY,
    activity_id  BIGINT NOT NULL,
    user_id      BIGINT NOT NULL,
    flow_type    VARCHAR(16) NOT NULL,         -- GRANT / CONSUME / EXPIRE / MANUAL_ADJUST / FREEZE
    amount       INTEGER NOT NULL,             -- 正数
    biz_type     VARCHAR(32) NOT NULL,         -- TASK / CHECKIN / OPERATION / PURCHASE / DRAW / SYSTEM
    biz_no       VARCHAR(64) NOT NULL,         -- 业务单号（任务完成流水号/抽奖流水号/运营发放批次号）
    expire_at    TIMESTAMPTZ,                  -- GRANT 时写入该批机会的过期时间
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (activity_id, user_id, flow_type, biz_no)   -- 幂等锚点
);
CREATE INDEX idx_chance_flow_expire ON chance_flow (expire_at) WHERE flow_type = 'GRANT';
```

要点：

- 机会分批过期（FIFO）：`GRANT` 流水带 `expire_at`，消耗时从最早过期批次扣（Redis ZSET 辅助，见 §8）。
- `UNIQUE(activity_id, user_id, flow_type, biz_no)` 保证任务系统重复回调不重复发放。

### 2.6 抽奖流水与中奖记录（draw_record / winning_record）

```sql
CREATE TABLE draw_record (
    id                  BIGSERIAL PRIMARY KEY,
    record_no           VARCHAR(64) NOT NULL UNIQUE,        -- DR-YYYYMMDD-序列
    activity_id         BIGINT NOT NULL,
    user_id             BIGINT NOT NULL,
    cost_type           VARCHAR(16) NOT NULL,
    cost_amount         INTEGER NOT NULL DEFAULT 0,          -- 消耗积分数（POINTS 模式）
    chance_flow_id      BIGINT,                              -- 消耗的机会流水（CHANCE 模式）
    probability_version INTEGER NOT NULL,
    roll_seed           BIGINT NOT NULL,                     -- 本次 Roll 的随机种子（审计回放）
    roll_value          INTEGER NOT NULL,                    -- Roll 命中的总权重坐标
    guarantee_hit       BOOLEAN NOT NULL DEFAULT FALSE,      -- 本次是否保底命中
    risk_level          VARCHAR(16) NOT NULL DEFAULT 'PASS', -- 风控结论：PASS / VERIFY_PASS / REJECT
    client_info         JSONB NOT NULL DEFAULT '{}',         -- 设备指纹/渠道/版本（风控存证）
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_draw_record_user ON draw_record (activity_id, user_id, created_at DESC);

CREATE TABLE winning_record (
    id              BIGSERIAL PRIMARY KEY,
    win_no          VARCHAR(64) NOT NULL UNIQUE,             -- WIN-YYYYMMDD-序列
    draw_record_id  BIGINT NOT NULL REFERENCES draw_record(id),
    activity_id     BIGINT NOT NULL,
    user_id         BIGINT NOT NULL,
    prize_id        BIGINT NOT NULL,
    prize_snapshot  JSONB NOT NULL,                          -- 中奖瞬间奖品快照（名称/图标/payload），防后续改配置污染历史
    fulfill_type    VARCHAR(32) NOT NULL,                    -- 同 prize_type 冗余，便于分流路由
    fulfill_status  VARCHAR(32) NOT NULL DEFAULT 'PENDING',
    fulfill_no      VARCHAR(64),                             -- 下游履约单号（发券批次/会员开通流水/履约服务单号）
    retry_count     SMALLINT NOT NULL DEFAULT 0,
    next_retry_at   TIMESTAMPTZ,
    address_id      BIGINT,                                  -- 实物类：用户填写的收货地址ID
    address_deadline TIMESTAMPTZ,                            -- 实物类：填地址截止时间
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_winning_user ON winning_record (user_id, created_at DESC);
```

## 3. 状态流转

### 3.1 抽奖活动状态机

```text
DRAFT ──提交审核──▶ AUDITING ──通过──▶ SCHEDULED ──到达begin_time(定时任务)──▶ ONLINE
 ▲                    │拒绝                                    │      │
 └────────────────────┘                                        ▼      │
                     PAUSED ◀──运营手动暂停/风控熔断──  ONLINE ─┘      │
                        │                                       │     │
                        └──恢复──▶ ONLINE                        ▼
                                            到达end_time(定时任务) ──▶ ENDED
                                                                   │
                                            未领奖/未履约全部终态(定时对账) ──▶ SETTLED（终态，允许导出与归档）
```

规则：

- 仅 `DRAFT/PAUSED` 状态可编辑奖池；`ONLINE` 状态禁止修改 `weight`（防"边抽边改概率"审计风险），只能**增加库存**（走新概率版本发布的除外——修改权重必须先 `PAUSED` 再发布新版本）。
- `AUDITING` 由内容合规 + 运营双审：合规审 `minor_visible`、文案诱导性、概率合理性；运营审预算与库存。
- `ENDED` 后仍有 `PENDING/FULFILLING/FAILED` 的中奖记录时不可进入 `SETTLED`，由对账任务守护。

### 3.2 机会账户生命周期

```text
[任务/打卡/运营] --GRANT(带expire_at)--> 可用余额+
可用余额 --CONSUME(抽奖, FIFO扣最早过期批次)--> 已消耗
可用余额 --EXPIRE(延迟任务到期)--> 已过期（先冻结后核销两步）
运营手动 --MANUAL_ADJUST--> ±余额（须审计工单号）
```

### 3.3 中奖记录状态机（发奖分流）

```text
                ┌─ THANKS ─────────────────────▶ FULFILLED（直接终态）
                ├─ POINTS ──积分加账成功────────▶ FULFILLED
                ├─ COUPON ──发券成功────────────▶ FULFILLED
PENDING ────────┤
                ├─ MEMBER_DAYS ──开通成功───────▶ FULFILLED
                ├─ RESOURCE ──资源包发放成功─────▶ FULFILLED
                └─ GOODS ──创建履约单成功───────▶ FULFILLING ──物流签收──▶ FULFILLED
```

### 5.1 机会获取流程（任务联动）

```text

  └─▶ I1 grantChance（携带任务流水号 bizNo）

        │        update draw_chance (total+1, balance+1) ON CONFLICT 创建
        └─ 写 Redis：ZADD lottery:chance:{activityId}:{userId} expireTs batchSeq
             （batchSeq 单调递增，供 FIFO 扣减，见 §5.2/§8）
通知中心（可选）：App 内轻提示"获得1次抽奖机会"（受疲劳度管控）
```

### 5.2 抽奖主流程（核心时序）

```text
客户端                    网关/BFF               lottery-svc              Redis/DB/下游
  │ POST draw(token) ──▶ │ ──▶ 风控前置(I7) ─▶ PASS/VERIFY/REJECT
  │                        │      REJECT → 403 LOTTERY_RISK_REJECTED
  │                        │      VERIFY → 401 需人机验证(C1重试带ticket)
  │                        ├─▶ ①幂等闸门: SETNX dr:{token} 30s（防双击/重放）
  │                        ├─▶ ②资格校验: 活动ONLINE? 日限/总限剩余? 机会余额≥1?
  │                        │     (POINTS模式改为积分预检)
  │                        ├─▶ ③扣机会: Lua脚本 FIFO扣最早过期批次(Redis) + 落chance_flow(CONSUME)
  │                        │     失败→ 兜底查DB余额，仍不足→ LOTTERY_NO_CHANCE
  │                        ├─▶ ④Roll: 载入概率表(本地缓存,带version) → AliasMethod采样
  │                        │     命中prize → 检查per_user_win_limit/保底计数
  │                        ├─▶ ⑤库存预扣: Lua DECR stock:{activityId}:{prizeId} (含日库存)
  │                        │     ≤0 → 降级重Roll到THANKS(仅一次) → 仍THANKS则THANKS
  │                        ├─▶ ⑥落库(同事务): draw_record + winning_record(PENDING)
  │                        │     + 失败即回补Redis库存与机会(补偿路径)
  │                        ├─▶ ⑦发奖(异步, 事务提交后MQ/线程池): 按fulfill_type分流I3~I6
  │                        │     成功→FULFILLED/GOODS→FULFILLING；异常→FAILED+next_retry_at
  │ ◀── 返回C3响应(动画编排) ─┘（⑥成功即可返回，不等⑦）
```

设计取舍：**⑥落库成功即返回**，发奖异步化——用户感知延迟要求 <500ms，而发奖涉及多个下游；未中奖也可先返回（THANKS 无履约）。若 ⑥ 后进程崩溃，⑦ 由定时扫描 `PENDING` 超时记录补偿（见 §6.6）。

### 5.3 概率 Roll 与保底算法

1. **权重采样**：`total = Σweight`，取 `r ∈ [0, total)`，命中累积区间所属奖品。实现用 **AliasMethod**（O(n) 构建、O(1) 采样），概率表随 `probability_version` 缓存重建。
2. **库存感知重 Roll**：中奖但库存 ≤0 时，将 `r` 平移重采样一次（限定一次，防止循环）；仍不可得则落 `THANKS`。选择"重 Roll 一次"而非"直接 THANKS"是为了让其他有库存奖品仍有机会被抽中，且**公示概率仅在库存充足时严格成立**——此约束写入概率公示页文案（合规提示：*奖品数量有限，抽完即止*）。
3. **保底**：`guarantee_counter`（Redis `INCR lottery:guarantee:{activityId}:{userId}`，抽中非 THANKS 即 `DEL`）。当 `counter+1 ≥ guarantee_threshold` 时，本回合**跳过随机采样**，直接锁定 `guarantee_prize_id`（同样要过库存与 `per_user_win_limit`，不满足则顺延至下一回合并保留计数）。`guarantee_hit=true` 落 `draw_record`。
4. **防策略性弃奖**：`per_user_win_limit` 命中后该奖品对该用户权重置 0（本地缓存中按用户维度生成裁剪后的概率表副本，仅内存计算，不落库），防止小号反复抽大奖。

### 5.4 库存一致性与对账

- **准入**：Redis `stock:{activityId}:{prizeId}`（总库存）+ `dstock:{activityId}:{prizeId}:{yyyyMMdd}`（日库存）双 Key，Lua 原子扣减。
- **收敛**：DB `stock_remaining` 由发奖成功后异步 `UPDATE prize_pool SET stock_remaining = stock_remaining - 1 WHERE id=? AND stock_remaining > 0`（乐观扣，防超 DB 值）。
- **对账**：每 10 分钟采样比对 Redis 余量与 `total_stock - COUNT(winning_record 中该奖品非 VOIDED 数)`，偏差 > 阈值告警并触发全量核对 Job（以 DB 中奖记录为准，Redis 只重放）。日库存 Key 由每日 00:05 任务重置。
- **回补**：⑥ 落库失败、VOIDED 作废时，执行 Redis `INCRBY` 回补 + 库存流水表记录（`stock_flow`，字段：pool_id, delta, reason, biz_no, created_at），保证每次库存变动可追溯。

### 6.2 AliasMethod 加权随机

```java
public final class AliasMethod {
    private final int[] alias;
    private final double[] probability;   // 每个桶的原始概率
    private final int n;

    public AliasMethod(List<Integer> weights) {
        this.n = weights.size();
        alias = new int[n];
        probability = new double[n];
        double total = weights.stream().mapToDouble(Integer::doubleValue).sum();
        if (total <= 0) throw new IllegalArgumentException("total weight must > 0");

        double[] scaled = new double[n];
        Deque<Integer> small = new ArrayDeque<>(), large = new ArrayDeque<>();
        for (int i = 0; i < n; i++) {
            scaled[i] = weights.get(i) * n / total;
            (scaled[i] < 1.0 ? small : large).add(i);
        }
        while (!small.isEmpty() && !large.isEmpty()) {
            int s = small.poll(), l = large.poll();
            probability[s] = scaled[s];
            alias[s] = l;                       // s 桶不足部分由 l 桶别名补足
            scaled[l] -= (1.0 - scaled[s]);
            (scaled[l] < 1.0 ? small : large).add(l);
        }
        while (!large.isEmpty()) probability[large.poll()] = 1.0;
        while (!small.isEmpty()) probability[small.poll()] = 1.0; // 浮点误差兜底
    }

    /** 返回命中下标；seed 由调用方传入以便审计回放 */
    public int sample(ThreadLocalRandom rng) {
        int bucket = rng.nextInt(n);
        return rng.nextDouble() < probability[bucket] ? bucket : alias[bucket];
    }
}
```

审计回放：`draw_record.roll_seed` 采用可重放随机源——生产用 `SecureRandom` 种子 + 独立 `Random` 实例采样，落库存 seed 与 `roll_value`，事后可用同 seed + 同 `probability_version` 快照重算验证命中一致（防内部作弊）。

```lua
-- ZSET member=batchSeq score=expireTs, hash field=batchSeq→剩余数（存同key hash）
local zset, hkey = KEYS[1], KEYS[1] .. ':h'
local batches = redis.call('ZRANGE', zset, 0, -1)   -- score升序=最早过期在前
for _, b in ipairs(batches) do
    local left = tonumber(redis.call('HGET', hkey, b) or '0')
    if left > 0 then
        redis.call('HSET', hkey, b, left - 1)
        return b                                    -- 返回被扣批次，落流水对账
    end
end
return nil                                          -- 无可用批次
```

```lua
-- stock_deduct.lua  KEYS[1]=总库存 KEYS[2]=日库存 ARGV[1]=日库存key(可能为空串)
local total = tonumber(redis.call('GET', KEYS[1]) or '-1')
if total >= 0 and total <= 0 then return -1 end     -- 有限库存且耗尽
if total >= 0 then redis.call('DECR', KEYS[1]) end
if ARGV[1] ~= '' then
    local daily = tonumber(redis.call('GET', KEYS[2]) or '-1')
    if daily >= 0 then
        if daily <= 0 then                          -- 日库存耗尽需回补总库存
            if total >= 0 then redis.call('INCR', KEYS[1]) end
            return -2
        end
        redis.call('DECR', KEYS[2])
    end
end
return 1
```

### 6.4 DrawService 抽奖编排（骨架）

```java
@Transactional  // 仅包裹⑥落库；③④⑤为Redis操作在事务外先行
public DrawResultVO draw(long userId, String activityCode, String drawToken, String verifyTicket) {
    DrawActivity act = activityService.loadOnline(activityCode);          // ② Caffeine本地缓存
    restrictionGuard.checkLotteryAllowed(userId);                         // ⑤.7 家长管控/防沉迷/时段
    riskClient.decideOrVerify("LOTTERY_DRAW", userId, verifyTicket);      // ① 风控(异常即抛)

    String idemKey = "lottery:dr:" + drawToken;                           // ① 幂等闸门
    Boolean first = redis.opsForValue().setIfAbsent(idemKey, "1", Duration.ofSeconds(30));
    if (Boolean.FALSE.equals(first)) {
        DrawRecord existed = drawRepo.findByToken(drawToken);             // 双击场景返回首次结果
        return existed != null ? resultOf(existed) : throwBiz("LOTTERY_DUPLICATE_REQUEST");
    }

    quotaGuard.checkDailyAndTotalLimit(act, userId);                      // ② 日限/总限(Redis计数)
    CostContext cost = costDeductor.deduct(act, userId);                  // ③ 机会FIFO / 积分预扣

    ProbabilityTable pt = probabilityService.table(act.getId(), act.getProbabilityVersion());
    RollResult roll = rollEngine.roll(pt, userId, act);                   // ④ 含保底/用户限中裁剪

    if (!fulfillStock.tryDeduct(act.getId(), roll.getPrizeId())) {        // ⑤ 库存预扣
        roll = rollEngine.reRollOnceOrThanks(pt, userId);
        if (!fulfillStock.tryDeduct(act.getId(), roll.getPrizeId()))
            roll = RollResult.thanks(pt);
    }

    DrawRecord record = drawRepo.insert(DrawRecord.of(act, userId, cost, pt.getVersion(), roll));
    WinningRecord win = winningRepo.insert(WinningRecord.pending(record, roll.prizeSnapshot()));
    if (roll.isThanks()) win.markFulfilled();                             // THANKS直接终态

    fulfillDispatcher.dispatchAsync(win);                                 // ⑦ 事务提交后(MQ)执行
    return DrawResultVO.of(record, win, quotaGuard.remaining(act, userId), cost);
}
```

> 若 ⑥ insert 失败抛异常回滚：`fulfillStock.compensate()`（回补库存）+ `costDeductor.compensate()`（回补机会/积分）在 catch 中显式执行并记 `stock_flow`，两段补偿自身也幂等（以 `record_no` 预生成的 biz_no 去重）。

### 6.5 幂等控制汇总

| 动作 | 幂等锚点 |
| --- | --- |
| 执行抽奖 | `draw_token`：Redis SETNX 30s + `draw_record.token` 唯一索引兜底 |
| 机会发放(I1) | `chance_flow(activity, user, GRANT, bizNo)` 唯一索引 |
| 积分扣/加 | 调用积分服务携带 `bizNo = record_no / win_no` |
| 发券/会员/履约 | 下游接口均以 `win_no` 为幂等键 |
| 手动补发(M6) | 工单号 + 操作流水唯一索引 |
| 库存回补 | `stock_flow(biz_no)` 唯一索引 |

| 任务 | 频率 | 逻辑 |

## 7. 错误处理

### 7.1 统一错误码（LOTTERY 段）

| 错误码 | HTTP | 场景 | 客户端处理 |
| --- | --- | --- | --- |
| LOTTERY_ACTIVITY_NOT_FOUND | 404 | 活动不存在/未开始/已结束（统一模糊返回，防探测） | 提示活动不存在或已结束 |
| LOTTERY_ACTIVITY_NOT_ONLINE | 403 | 活动暂停中 | "活动暂时休息，稍后再来" |
| LOTTERY_DISABLED_BY_PARENT | 403 | 家长管控关闭 | 引导查看家长中心说明 |
| LOTTERY_ANTI_ADDICTION | 403 | 防沉迷时段/时长超限 | 防沉迷统一弹窗 |
| LOTTERY_NO_CHANCE | 422 | 机会不足 | 弹任务列表引导赚机会 |
| LOTTERY_DAILY_LIMIT | 422 | 日限到达 | 明日再来提示 |
| LOTTERY_TOTAL_LIMIT | 422 | 活动总限到达 | 终态提示 |
| LOTTERY_INSUFFICIENT_POINTS | 422 | 积分模式余额不足 | 引导积分页 |
| LOTTERY_DUPLICATE_REQUEST | 429 | draw_token 重复且无首次结果 | 刷新后重试 |
| LOTTERY_RISK_REJECTED | 403 | 风控拒绝 | "操作异常，稍后再试"（不暴露原因） |
| LOTTERY_RISK_VERIFY_REQUIRED | 401 | 需人机验证 | 拉起滑块后带 ticket 重试 |
| LOTTERY_STOCK_BUSY | 503 | Redis 不可用 | 降级话术"活动太火爆"；**禁止**退化为无库存控制的裸 Roll |
| LOTTERY_FULFILL_LAGGING | 200 | 中奖但发奖异步未完成 | 正常返回，履约提示"发放中" |

### 7.2 并发与一致性场景

| 场景 | 防护 |
| --- | --- |
| 双击/弱网重放同一 token | 幂等闸门 + 唯一索引，返回首次结果 |
| 扣机会后、落库前宕机 | Redis 扣减带 `record_no` 流水，重启对账 Job 以流水回补未落库扣减 |
| 库存预扣后落库失败 | catch 中显式回补 + `stock_flow` 审计；对账 Job 兜底 |
| 同用户并发两请求各中同一限中奖品 | `per_user_win_limit` 以 DB `winning_record(prize,user,非VOIDED)` 计数 + 行锁校验，超限重 Roll |
| 发奖下游超时 | 状态机 FAILED + 指数退避，不阻塞用户 |
| Redis/DB 库存漂移 | ReconcileJob 以 DB 中奖记录为准重建 Redis |
| 机会批次过期与消耗竞态 | Lua 内先判 `score < now` 则移除批次再继续，杜绝过期批次被扣 |

### 7.3 降级策略

- **Redis 故障**：抽奖全链路熔断为 `LOTTERY_STOCK_BUSY`（库存失控风险 > 活动收益），任务发放机会降级只落 DB，恢复后由对账 Job 重建 ZSET。
- **风控中心故障**：fail-open + 采样日志（抽奖为低资金风险场景），但**人机验证开关一旦触发过则 fail-closed**。
- **发奖下游故障**：正常降级路径（FAILED 重试），用户侧展示"发放中"。
- **活动配置中心故障**：本地 Caffeine 缓存继续服务，最长容忍 10 分钟陈旧（活动下线广播丢失由 1min 调度纠偏）。

## 11. 测试要点（摘要）

1. **概率正确性**：蒙特卡洛 10^6 次采样，各奖品频率与公示千分比误差 < 0.5%；`probability_version` 切换后新表立即生效。
2. **并发库存**：100 并发抢 total_stock=10 的奖品，断言中奖数 = 10、Redis/DB/记录三方一致。
3. **幂等**：同 token 重放 100 次仅一次生效；I1 重复回调不重复发机会。
4. **保底**：阈值 N 连续未中后必中且 `guarantee_hit=true`；中奖后计数清零。
5. **状态机**：ONLINE 改权重被拒；ENDED 有未终态记录不可 SETTLED。
6. **合规**：`market_value>50000` 创建被拒；`minor_visible=false` 活动对未成年人 404；家长管控关闭后服务端 403。
7. **故障注入**：Kill Redis 后抽奖熔断且无超发；发奖下游 500 后重试链路完整、耗尽转 MANUAL。

## 12. 上线与灰度

- 配置开关 `lottery.enabled`（全局）+ 活动级 `page_config.visible` 灰度百分比，接入灰度发布系统按用户尾号放量。
- 首个活动建议 `NINE_GRID` 小奖池（仅积分+优惠券）试点，验证发奖链路后再上实物奖与 WHEEL 大型活动。
- 回滚预案：活动 `PAUSED` 即时生效（广播 I8），未履约中奖记录继续走补偿链路不受影响。
