# 设备指纹与反作弊风控引擎 - 详细设计

## 1. 概述

### 1.1 背景

启硕 PrimeTop 作为付费教育产品，面临多重作弊与滥用风险：
- AI 大模型 API 调用成本高昂，需防止自动化刷量与爬虫批量调用
- 会员订阅制度下，需防止账号共享与倒卖
- 拍题 OCR、语音识别等能力存在被批量盗用的风险
- 支付环节需防范欺诈与恶意退款
- 未成年人账号需确保不被成人冒用绕过家长管控

### 1.2 设计目标

1. **精准识别**：通过多维度设备指纹和行为分析，准确识别作弊与滥用行为
2. **低误判率**：对正常用户的影响 < 0.1%，避免阻断合法学习活动
3. **实时响应**：风控决策延迟 < 50ms（P99），不阻塞核心学习链路
4. **渐进式处置**：从验证码、限流到封禁，分级别处置
5. **隐私合规**：符合《个人信息保护法》和《儿童个人信息网络保护规定》，数据最小化采集

### 1.3 适用范围

本设计覆盖客户端 SDK、服务端风控引擎、规则管理系统、风险运营后台四大子系统。

## 4. 设备指纹采集

### 4.1 指纹生成算法

分层哈希生成，确保单维度变更不导致指纹完全改变：

```
fingerprint_id = SHA-256(
    SHA-256(hardware_features) +   // 型号/CPU/屏幕/内存/存储
    SHA-256(software_features) +   // OS主版本
    SHA-256(device_identifier)     // Android ID / IDFV
)
```

**稳定特征（权重 80%）**：

| 特征 | Android | iOS | 说明 |
|------|---------|-----|------|
| 设备型号 | `Build.MODEL` | `deviceModel` | 硬件型号 |
| 制造商 | `Build.MANUFACTURER` | - | 厂商 |
| CPU架构 | `Build.SUPPORTED_ABIS` | `cpuType` | 芯片 |
| 屏幕分辨率 | `DisplayMetrics` | `screenBounds` | 物理像素 |
| 总内存 | `MemoryInfo.totalMem` | `physicalMemory` | RAM |
| 持久存储 | `StatFs.totalBytes` | `volumeCapacity` | 存储 |
| Android ID | `Settings.Secure` | - | Android专用 |
| IDFV | - | `identifierForVendor` | iOS专用 |

### 4.2 环境安全检测

| 检测项 | 检测方式 | 风险权重 |
|--------|----------|----------|
| Root/越狱 | su/sudo存在 + 沙箱写入测试 | 30分 |
| 模拟器 | CPU特征+传感器+硬件属性综合 | 25分 |
| 调试器 | ptrace/DebugProbe检测 | 20分 |
| Hook框架 | Frida/Xposed特征字符串扫描 | 15分 |
| VPN/代理 | 网络接口检测+DNS泄漏测试 | 5分 |
| 自动化工具 | AccessibilityService滥用检测 | 10分 |
| 多开/虚拟空间 | 进程/文件系统特征检测 | 15分 |
| 重打包 | APK/IPA签名校验 | 20分 |

环境可信度 = max(0, 1 - sum(detected × weight) / 100)

- ≥ 0.8：安全放行
- 0.5~0.8：可疑，加强监控
- < 0.5：高危，触发挑战验证

### 4.4 Flutter 集成示例

```dart
class RiskInterceptor extends Interceptor {
  @override
  void onRequest(RequestOptions options, RequestInterceptorHandler handler) {
    final risk = RiskService.instance;
    final headers = risk.signHeaders(options.data ?? {});
    options.headers.addAll(headers);

    // 高风险接口检查环境
    if (_isHighRisk(options.path) && !risk.isEnvironmentSafe) {
      handler.reject(DioException(
        requestOptions: options,
        error: 'Environment not safe',
      ));
      return;
    }
    handler.next(options);
  }

  @override
  void onError(DioException err, ErrorInterceptorHandler handler) {
    if (err.response?.statusCode == 403) {
      final body = err.response?.data;
      if (body?['code'] == 40301) {
        // 风控挑战
        final challenge = ServerChallenge.fromJson(body['data']['challenge']);
        _handleChallenge(challenge, err.requestOptions, handler);
        return;
      }
    }
    handler.next(err);
  }

  Future<void> _handleChallenge(
    ServerChallenge challenge,
    RequestOptions original,
    ErrorInterceptorHandler handler,
  ) async {
    final result = await Navigator.pushNamed(
      AppRouter.instance.navigatorKey.currentContext!,
      '/risk_challenge',
      arguments: challenge,
    );
    if (result != null && result is ChallengeResponse) {
      // 验证通过后重试原请求
      original.headers['X-Challenge-Token'] = result.token;
      final dio = Dio();
      final response = await dio.fetch(original);
      handler.resolve(response);
    } else {
      handler.next(DioException(
        requestOptions: original,
        error: 'Challenge failed',
      ));
    }
  }
}
```

## 5. 服务端风控引擎

### 5.1 风控接入层（网关拦截器）

```python
class RiskInterceptor:
    async def intercept(self, request) -> RiskDecision:
        fp = request.header('X-Device-Fingerprint')
        ts = int(request.header('X-Request-Timestamp'))
        nonce = request.header('X-Request-Nonce')
        sig = request.header('X-Request-Signature')

        # 签名校验（防篡改）
        expected = hmac_sha256(SECRET, f"{fp}|{ts}|{nonce}")
        if sig != expected:
            return RiskDecision(block=True, reason='INVALID_SIGNATURE')

        # 时间窗口（防重放，5分钟）
        if abs(now_ms() - ts) > 300_000:
            return RiskDecision(block=True, reason='EXPIRED_REQUEST')

        # Nonce去重
        if await redis.exists(f"nonce:{nonce}"):
            return RiskDecision(block=True, reason='REPLAY')
        await redis.setex(f"nonce:{nonce}", 300, "1")

        # 频率计数
        key = f"rate:{fp}:{request.path}"
        count = await redis.incr(key)
        if count == 1:
            await redis.expire(key, 60)

        # 构建上下文，执行规则
        ctx = RiskContext(
            fingerprint_id=fp, user_id=request.user_id,
            ip=request.client_ip, path=request.path,
            rate_1min=count,
        )
        return await self.engine.evaluate(ctx)
```

### 5.3 评分引擎

```
final_score = base_score
            + sum(rule_hit_scores)     // 规则命中累加
            + device_risk_bonus        // 设备历史风险加权
            + behavior_anomaly_bonus   // 行为异常加权
            - trust_discount           // 信用历史折扣

trust_discount = min(20, active_trust_days × 0.5)
```

| 风险分 | 等级 | 处置 |
|--------|------|------|
| 0-20 | low | 正常放行 |
| 21-50 | medium | 监控，必要时验证码 |
| 51-80 | high | 严格限流，二次验证 |
| 81-100 | blocked | 阻断，账号受限 |

### 5.4 核心检测场景

#### 账号共享检测

| 维度 | 阈值 |
|------|------|
| 7天设备绑定数 | > 5 |
| 7天同设备多账号 | > 3 |
| 同时在线设备 | > 2 |
| 短时间跨城市(>500km) | < 2h |
| 24h使用时段覆盖 | > 18h |

处置：疑似→设备确认提示；确认→限并发1；严重→冻结

#### 爬虫检测

| 维度 | 说明 |
|------|------|
| 请求间隔方差 | 机器请求方差极小 |
| 操作路径覆盖 | 爬虫只打API不访问页面 |
| TLS指纹(JA3) | 非APP的TLS特征 |
| 交互事件 | 缺少自然交互 |
| API/页面比 | 爬虫比值接近100% |

#### 支付欺诈检测

| 维度 | 说明 |
|------|------|
| 新设备支付 | 首次即支付，结合注册时间 |
| 退款频率 | 多次购买后退款 |
| 支付工具 | 同一工具绑定多账号>5 |
| 设备黑名单 | 关联历史欺诈设备 |
| IP信誉 | 命中代理/黑名单库 |

### 7.1 登录风控流程

```
用户发起登录
    │
    ▼
签名校验 + 环境检测
    │
    ├──[签名无效]──▶ 拒绝(403)
    │
    ▼
设备指纹匹配/注册
    │
    ▼
加载设备绑定记录 ──▶ 绑定用户数>5? ──▶ 标记共享嫌疑
    │
    ▼
异地登录检测 ──▶ 跨省且<2h? ──▶ 触发短信验证
    │
    ▼
执行风控规则集
    │
    ├──[low]──▶ 正常放行
    ├──[medium]──▶ 放行 + 弹出滑块验证
    ├──[high]──▶ 放行 + 短信验证 + 标记监控
```

```
客户端调用 precheck(action=ai_chat)
    │
    ▼
频率检查 ──▶ 10min内>50次? ──▶ 触发挑战(验证码)
    │
    ▼
设备风险检查 ──▶ risk_level=high? ──▶ 拒绝 + 提示
    │

额度检查 ──▶ 超出会员额度? ──▶ 拒绝 + 引导升级
    │

放行，返回 remaining_quota
    │
    ▼
客户端发起实际 ai/chat 请求
    │
    ▼
网关风控二次校验(防止绕过precheck)
    │
    ├──[通过]──▶ 转发到AI服务
    └──[拦截]──▶ 返回403 + 挑战
```

### 7.3 支付风控流程

```
用户发起支付
    │
    ▼
设备环境检查 ──▶ 新设备? ──▶ 短信验证
    │
    ▼
支付历史检查 ──▶ 多次退款? ──▶ 拒绝 + 运营审核
    │
    ▼

    │
    ▼

    │
    ▼
支付路由执行(渠道侧二次校验)
    │
    ▼
支付结果回调 ──▶ 校验设备与下单时一致? ──▶ 不一致→冻结+人工
    │

```

**关键裁决**：支付风控只做**事前前置校验**（设备/行为/IP），资金侧事后规则（重复退款、误充值识别）归《服务端-未成年人支付风控与误充值自动识别退款引擎》，两级各自 fail-closed，互不替代（契约 R3）。

### 7.4 处置执行与解除流程

```
评分引擎输出决策(decision, score, rule_hits)
    │
    ▼
处置中心决策落库 risk_actions(status=1 生效) ──G1:无落库不执行──
    │
    ├──[challenge]──▶ 生成 challenge_id+一次性令牌 ──▶ 客户端拉起验证
    ├──[throttle]──▶ 写 Redis 限流键(limit:fp:action) ──▶ 网关/业务侧读取执行
    ├──[block]─────▶ 写 Redis 黑名单(blacklist:fp/user) ──▶ 网关拦截
    └──[freeze]────▶ 发事件 account.freeze.requested ──▶ 处罚执行服务接管(契约 R2)
    │
    ▼
到期/人工解除：expire_at 到期自动清键 ──或── 运营撤销(status=0)
    │
    ▼
解除后进入 7 天观察期：风险分正常衰减，但不加信任分(G4)
```

**处置时长矩阵**：

| 处置 | 默认时长 | 最长 | 解除方式 |
|------|----------|------|----------|
| challenge 通行 | 30 分钟 | 2 小时 | 自动过期 |
| throttle 限流 | 1 小时 | 24 小时 | 自动过期/人工 |
| block 设备 | 24 小时 | 永久 | 人工复核 |
| freeze 账号 | 人工裁定 | - | 处罚执行服务 |

## 8. 状态机与守卫规则

### 8.1 设备风险等级状态机

```
                    规则命中 score≥51            规则命中 score≥81
        ┌──────┐ ───────────────────▶ ┌──────┐ ───────────────────▶ ┌──────────┐
        │ low  │                      │ high │                      │ blocked  │
        └──────┘ ◀─────────────────── └──────┘ ◀─────────────────── └──────────┘
                    衰减至 <51(每日-2)          人工解除/衰减+人工复核
                    │                             ▲
                    ▼                             │
        ┌────────┐  score 21-50   ┌──────────┐    │
        │ medium │ ◀───────────── │ (同左)   │────┘
        └────────┘                └──────────┘
           │ score≥51 ▲
           ▼          │ 衰减至 ≤20
        high ─────────┘
```

- `blocked` 只能由**人工复核**解除（G2/G8），不允许纯自动迁移。
- 风险分每日衰减 `-2`，下限 0；处置解除后 7 天观察期内不衰减也不加信任分。
- `trust_discount` 最多抵扣 20 分，且不能使最终分低于 0。

### 8.2 处置记录状态机

```
创建(1 生效) ──▶ 到期自动清理(2 过期)     ←─ expire_at 到点扫描
     │
     └──▶ 人工撤销(0 撤销) ──G8:>7天或影响>100用户需双人复核──
              │
              ▼
        撤销事件写审计 + 关联 risk_events 标记 is_false_positive 待复核
```

状态迁移一律 CAS：`UPDATE risk_actions SET status=? WHERE action_id=? AND status=1`。

### 8.3 守卫规则总表

| # | 守卫 | 规则 | 违反后果 |
|---|------|------|----------|
| G1 | 处置先落库 | 任何阻断/限流必须有 status=1 的 risk_actions 记录 | 拒绝执行，记 ENGINE_ERROR |
| G2 | 设备封禁波及用户需复核 | 设备 blocked 影响其绑定用户时生成复核工单 | 工单缺失即视为未生效 |
| G3 | 未成年人联动通知 | 处置对象为未成年人账号，同事务发家长端通知事件 | 通知失败回滚处置 |
| G4 | 观察期不加信任分 | 解除后 7 天内 trust_discount 冻结 | 防止刷信任分绕过 |
| G5 | 白名单不免频率 | 白名单仅豁免 challenge，不豁免 rate/payment 规则 | 白名单越权即告警 |
| G6 | 挑战令牌一次性 | challenge token 验证成功即作废，30 分钟过期 | 重放直接 40702/40703 |
| G7 | 通过≠洗白 | challenge 通过只授予 30min 通行，不清除风险分 | 防绕过抬升 |
| G8 | 重处置双人复核 | block>7 天或影响面>100 用户需第二人复核 | 未复核不得生效 |
| G9 | 规则版本化 | 规则变更生成新版本+审计日志，禁原地改 | 违规修改回滚 |
| G10 | 误报闭环 | is_false_positive 标注 72h 内必须复核出结论 | 超时升 P1 工单 |
| G11 | 响应最小化 | 对外不暴露命中规则 ID/阈值 | 防对抗调参 |
| G12 | 故障双轨 | 学习链路 fail-open（放行+补记+事后回放），支付链路 fail-closed | 见 §11 |
| G13 | 决策日志脱敏 | risk_events.evidence 落 ES 前脱敏 | 见 §13-C5 |
| G14 | 挑战频控 | 同一设备 24h challenge≤5 次，超限直接 throttle | 防挑战服务被当绕过通道 |

## 9. 幂等与并发设计

| 场景 | 幂等键 | 机制 | 重复请求行为 |
|------|--------|------|--------------|
| 请求防重放 | nonce | `SET nonce:{nonce} 1 EX 300 NX`，失败即重放 | 40708 |
| 设备注册/上报 | fingerprint_id | INSERT ... ON DUPLICATE KEY UPDATE last_seen_at | 更新活跃时间，返回既有 risk_level |
| 风控预检查 | 无副作用 | 只读评分，天然幂等 | 返回相同决策（含缓存 10s） |
| 挑战验证 | challenge_id | 状态 CAS：INIT→VERIFIED/FAILED，token 一次性消费 | 已 VERIFIED 重复提交→40703 |
| 行为批量上报 | event_id | Redis ZSET `behave:dedup:{fp}` 24h，score=ts | 丢弃重复事件，响应仍 200 |
| 处置创建 | action_id | 请求方生成 UUID，uk 冲突返回既有记录 | 幂等返回 |
| 规则管理端 | rule_id+version | 乐观锁 version 校验 | 409 冲突提示刷新 |

**并发控制**：

- 同设备并发注册：Redis 锁 `lock:fpreg:{fp}`（5s，SET NX PX），串行化首注册。
- 评分读路径无锁：规则集快照本地缓存 60s，设备风险读 Redis + Caffeine 二级缓存。
- 处置执行与解除竞态：以 risk_actions 状态 CAS 为准，Redis 键操作在事务提交后执行（Outbox 模式），避免库改键未改的悬挂。

## 10. 错误码

本节使用 **40700-40719**（全库扫描确认 407xx 段位空闲）。对外统一走《服务端统一业务异常码与错误分类体系》基础段映射，401 语义代表“需用户配合动作”。

| 码 | 符号 | 语义 | HTTP | 客户端动作 |
|----|------|------|------|-----------|
| 40700 | RISK_REQUEST_INVALID | 签名/时间窗/nonce 参数非法 | 400 | 校时后重试，连续失败上报 |
| 40701 | RISK_CHALLENGE_REQUIRED | 需完成人机挑战 | 200* | 拉起挑战页，通过后重放原请求（G6/G7） |
| 40702 | RISK_CHALLENGE_EXPIRED | 挑战已过期 | 400 | 重新申请挑战 |

| 40705 | RISK_ACCOUNT_RESTRICTED | 账号受限 | 403 | 引导联系客服/家长 |
| 40706 | RISK_RATE_LIMITED | 业务限流中 | 429 | 退避重试，Backoff 由 Retry-After 指定 |
| 40707 | RISK_ENVIRONMENT_UNSAFE | 运行环境高危 | 403 | 提示关闭模拟器/调试器/VPN |
| 40708 | RISK_REPLAY_DETECTED | 重放请求拦截 | 403 | 不重试，直接报错埋点 |
| 40709 | RISK_ACTION_NOT_FOUND | 处置记录不存在 | 404 | 管理端刷新 |
| 40710 | RISK_RULE_CONFLICT | 规则冲突/版本过期 | 409 | 管理端刷新后重提 |
| 40711 | RISK_REVIEW_CONFLICT | 复核状态冲突 | 409 | 管理端刷新 |
| 40712 | RISK_RETENTION_DENIED | 合规保留期拒绝删除 | 400 | -（管理端） |
| 40713 | RISK_TOKEN_INVALID | 设备会话令牌无效 | 401 | 重新 device/report |

### 12.1 监控指标

| # | 指标 | 口径 | 告警阈值 |
|---|------|------|----------|

### 12.2 容量估算（DAU 50 万）

- 决策 QPS：峰值 3000（登录/拍题/AI 问答聚合），单机（4C8G）可承载 800 QPS，部署 6 实例。
- Redis：nonce（300s TTL）峰值约 30 万键 ≈ 40MB；rate 计数（60s TTL）约 200 万键 ≈ 200MB；行为去重 ZSET 按设备 100 条 ≈ 300MB；总预算 1GB。
- MySQL：risk_events 约 300 万行/日，按月分区，热库 90 天，归档至 ClickHouse。
- ClickHouse：行为明细 6000 万行/日，TTL 180 天。
- ES：决策日志（脱敏）保留 30 天热查 + 冷归档 OSS。
