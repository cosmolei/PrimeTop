> 版本：1.0 | 日期：2026-05-23 | 作者：设计细化助手
> 关联文档：离线缓存与数据同步、用户设备管理与多端登录策略、客户端本地持久层与数据管理、异步任务与事件驱动架构

## 1. 概述

### 1.1 背景

启硕 PrimeTop 面向全学段学生，用户可能在手机、平板、Web 端和小程序之间切换使用。学生在手机上做了一组练习，回家后在平板上继续复习，或在 Web 端查看学情报告——这些场景要求各端数据实时一致。

然而，网络不稳定、离线使用、后台切换等因素会导致本地数据与服务端产生差异。如果没有系统化的同步与冲突解决机制，将出现：

- 错题在不同设备上不一致
- 学习进度回退或丢失
- 笔记/收藏状态漂移
- 学习计划完成状态混乱

### 1.2 目标

1. 保证用户在任意设备上的操作最终一致（最终一致性）
2. 离线场景下允许正常操作，联网后自动同步
3. 冲突检测与自动解决，用户无感知（高优先级数据需用户确认）
4. 同步过程不影响用户体验（增量同步、后台静默）
5. 控制同步流量，避免全量同步浪费带宽

### 1.3 适用范围

| 数据类别 | 同步方向 | 冲突概率 | 示例 |
|---------|---------|---------|------|
| 学习进度 | 双向 | 中 | 章节完成状态、练习进度 |
| 错题记录 | 双向 | 低 | 新增错题、订正状态 |
| 笔记与收藏 | 双向 | 中 | 新增/删除/编辑笔记 |
| 学习计划 | 双向 | 高 | 计划调整、任务完成 |
| AI 对话记录 | 双向 | 低 | 历史会话同步 |
| 用户设置 | 双向 | 低 | 偏好设置、教材版本 |
| 草稿数据 | 客户端→服务端 | 中 | 未完成的作文、练习答案 |

### 2.2 核心组件

| 组件 | 职责 | 部署位置 |
|-----|------|---------|
| SyncEngine (客户端) | 本地变更捕获、增量同步、冲突应用 | 各客户端 |

| SyncEventBus | 变更事件广播（实时推送） | 服务端 (Kafka + WebSocket) |
| SyncState Cache | 同步游标与设备状态缓存 | 服务端 (Redis) |

### 2.3 同步模式

| 模式 | 触发时机 | 适用场景 | 特点 |
|-----|---------|---------|------|
| 实时同步 | 数据变更即时推送 | 在线状态、多端同时使用 | 延迟低，通过 WebSocket |
| 拉取同步 | App 启动、前台切换 | 常规场景 | 增量拉取，按游标 |
| 推送同步 | 服务端主动通知 | 其他设备有变更 | WebSocket + 降级轮询 |
| 冲突解决同步 | 检测到冲突时 | 数据版本不一致 | 自动 + 手动混合 |

## 3. 数据模型

### 3.1 变更日志 (ChangeLog)

每一条数据变更生成一条 ChangeLog 记录，是同步的核心数据结构。

```sql
CREATE TABLE sync_change_log (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    -- 变更标识
    change_id       VARCHAR(64) NOT NULL UNIQUE COMMENT '变更唯一ID (UUIDv7)',
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    
    -- 数据定位
    entity_type     VARCHAR(32) NOT NULL COMMENT '实体类型: mistake_record, note, study_progress, ...',
    entity_id       VARCHAR(64) NOT NULL COMMENT '实体ID',
    
    -- 变更内容
    operation       ENUM('CREATE', 'UPDATE', 'DELETE') NOT NULL COMMENT '操作类型',
    field_changes   JSON NOT NULL COMMENT '字段级变更 {field: {old, new}}',
    snapshot        JSON DEFAULT NULL COMMENT '变更后完整快照 (仅CREATE时)',
    
    -- 版本信息
    revision        BIGINT NOT NULL COMMENT '全局递增版本号',
    device_id       VARCHAR(64) NOT NULL COMMENT '产生变更的设备ID',
    client_timestamp BIGINT NOT NULL COMMENT '客户端时间戳 (ms)',
    server_timestamp BIGINT NOT NULL COMMENT '服务端时间戳 (ms)',
    
    -- 状态
    status          ENUM('PENDING', 'APPLIED', 'CONFLICT', 'DISCARDED') DEFAULT 'APPLIED',
    conflict_resolution VARCHAR(32) DEFAULT NULL COMMENT '冲突解决策略',
    
    -- 索引
    INDEX idx_user_revision (user_id, revision),
    INDEX idx_user_entity (user_id, entity_type, entity_id),
    INDEX idx_user_timestamp (user_id, server_timestamp)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**field_changes 结构示例：**

```json
{
    "mastery_level": { "old": 0.3, "new": 0.65 },
    "last_practice_at": { "old": "2026-05-22T10:00:00Z", "new": "2026-05-23T08:30:00Z" }
}
```

## 4. 同步流程

### 4.1 完整同步流程 (Push + Pull)

```
客户端                                     服务端
  │                                          │
  │  1. 上报本地变更 (Push)                   │
  │─────────────────────────────────────────→│
  │  POST /sync/push                         │
  │  {changes: [{entity, fields, rev}...]}   │
  │                                          │  2. 逐条检查版本冲突
  │                                          │     应用无冲突变更
  │  3. 返回处理结果                          │     标记冲突变更
  │←─────────────────────────────────────────│
  │  {applied: [...], conflicts: [...]}      │
  │                                          │
  │  4. 拉取远端变更 (Pull)                   │
  │─────────────────────────────────────────→│
  │  GET /sync/pull?since_revision=R         │
  │                                          │  5. 查询变更日志
  │  6. 返回变更列表                          │     排除设备自身变更
  │←─────────────────────────────────────────│
  │  {changes: [...], latest_revision: R'}   │
  │                                          │
  │  7. 本地应用变更 + 处理冲突               │
  │                                          │
```

### 4.2 实时推送同步

当设备 A 产生变更后，服务端通过 WebSocket 推送到同一用户的其他活跃设备：

```
设备A (产生变更)              服务端                  设备B (接收推送)
    │                          │                          │
    │── Push Changes ────────→│                          │
    │                          │── 写入 ChangeLog         │
    │                          │── 发布 Kafka Event       │
    │                          │                          │
    │                          │← Kafka Consumer ─────    │
    │                          │── WebSocket Push ──────→ │
    │                          │  {type:"sync_change",    │
    │                          │   changes:[...]}         │
    │←── Push Response ───────│                          │
    │                          │                   设备B本地应用
```

## 6. 冲突检测与解决

### 6.1 冲突检测机制

基于**乐观并发控制 (OCC)**：

1. 每条数据有全局递增 `revision` 版本号
2. 客户端推送变更时携带本地 `revision`
3. 服务端比较客户端 `revision` 与服务端当前 `revision`
4. 一致 → 无冲突；不一致 → 冲突

```
                服务端 revision = 100
                
设备A (revision=100)      设备B (revision=100)
     │ UPDATE                  │ UPDATE
     │ 先到达                   │
     ▼                         │
revision = 101                 │
(A的变更已应用)                 │
                               │ 后到达
                               ▼
                        客户端 rev=100 ≠ 服务端 rev=101
                               │
                               ▼
                          检测到冲突！
```

### 6.2 冲突解决策略矩阵

| 实体类型 | 策略 | 说明 | 用户介入 |
|---------|------|------|---------|
| mistake_record | **Last-Write-Wins** | 服务端时间戳最新覆盖 | 否 |
| note | **Field-Level Merge** | 字段级合并，不同字段各自保留最新值 | 仅内容冲突时 |
| study_progress | **Progress Merge** | 数值取 max（进度只增不减） | 否 |
| study_plan | **User-Choice** | 提示用户选择保留哪个版本 | 是 |
| ai_conversation | **Append-Only** | 仅追加，不修改历史 | 否 |
| user_settings | **Field-Level Merge** | 逐字段取最新值 | 否 |
| favorite/bookmark | **Union Merge** | 合并两端集合（取并集） | 否 |
| draft | **Last-Write-Wins** | 最新草稿覆盖 | 否 |

### 6.3 冲突解决详细实现

#### 6.3.1 Last-Write-Wins (LWW)

适用于：错题记录、草稿

```java
public class LWWConflictResolver implements ConflictResolver {
    @Override
    public ConflictResult resolve(ChangeLog local, ChangeLog remote) {
        if (local.getServerTimestamp() >= remote.getServerTimestamp()) {
            return ConflictResult.useLocal(local);
        } else {
            return ConflictResult.useRemote(remote);
        }
    }
}
```

#### 6.3.2 Field-Level Merge (字段级合并)

适用于：笔记、用户设置

```java
public class FieldLevelMergeResolver implements ConflictResolver {
    private static final Set<String> AUTO_MERGE_FIELDS = Set.of("tags", "labels", "category");
    
    @Override
    public ConflictResult resolve(ChangeLog local, ChangeLog remote) {
        Map<String, FieldChange> merged = new LinkedHashMap<>();
        List<String> userConflictFields = new ArrayList<>();
        
        Set<String> allFields = new HashSet<>();
        allFields.addAll(local.getFieldChanges().keySet());
        allFields.addAll(remote.getFieldChanges().keySet());
        
        for (String field : allFields) {
            FieldChange localFC = local.getFieldChanges().get(field);
            FieldChange remoteFC = remote.getFieldChanges().get(field);
            
            if (localFC == null) {
                merged.put(field, remoteFC);
            } else if (remoteFC == null) {
                merged.put(field, localFC);
            } else if (localFC.getNewValue().equals(remoteFC.getNewValue())) {
                merged.put(field, localFC);
            } else if (AUTO_MERGE_FIELDS.contains(field)) {
                FieldChange winner = local.getServerTimestamp() >= 
                    remote.getServerTimestamp() ? localFC : remoteFC;
                merged.put(field, winner);
            } else {
                userConflictFields.add(field);
                merged.put(field, remoteFC);
            }
        }
        
        if (userConflictFields.isEmpty()) {
            return ConflictResult.merged(merged);
        } else {
            return ConflictResult.needUserDecision(merged, userConflictFields, local, remote);
        }
    }
}
```

#### 6.3.3 Progress Merge (进度类数据)

核心原则：**进度只增不减**

```java
public class ProgressMergeResolver implements ConflictResolver {
    @Override
    public ConflictResult resolve(ChangeLog local, ChangeLog remote) {
        Map<String, FieldChange> merged = new LinkedHashMap<>();
        for (String field : getAllFields(local, remote)) {
            FieldChange lfc = local.getFieldChanges().get(field);
            FieldChange rfc = remote.getFieldChanges().get(field);
            if (lfc != null && rfc != null) {
                Object value = applyMergeRule(field, lfc.getNewValue(), rfc.getNewValue());
                merged.put(field, new FieldChange(lfc.getOldValue(), value));
            } else {
                merged.put(field, lfc != null ? lfc : rfc);
            }
        }
        return ConflictResult.merged(merged);
    }
    
    private Object applyMergeRule(String field, Object localVal, Object remoteVal) {
        switch (field) {
            // 数值型：取 max
            case "progress_percentage": case "mastery_level":
            case "correct_count": case "total_practice_count": case "streak_days":
                return Math.max(toDouble(localVal), toDouble(remoteVal));
            // 布尔型：OR
            case "completed": case "is_mastered":
                return (boolean) localVal || (boolean) remoteVal;
            // 时间型：取最新
            case "last_practice_at": case "completed_at": case "last_review_at":
                return Math.max(toLong(localVal), toLong(remoteVal));
            // 列表型：合并去重
            case "completed_chapters": case "practiced_knowledge_points":
                return unionMerge(localVal, remoteVal);
            default:
                return Math.max(toDouble(localVal), toDouble(remoteVal));
        }
    }
}
```

#### 6.3.4 Union Merge (集合并集)

适用于：收藏、标签集合

```java
public class UnionMergeResolver implements ConflictResolver {
    @Override
    public ConflictResult resolve(ChangeLog local, ChangeLog remote) {
        Map<String, FieldChange> merged = new LinkedHashMap<>();
        for (String field : getAllFields(local, remote)) {
            FieldChange lfc = local.getFieldChanges().get(field);
            FieldChange rfc = remote.getFieldChanges().get(field);
            if (field.endsWith("_ids") || field.endsWith("_list")) {
                Set<Object> union = new LinkedHashSet<>();
                if (lfc != null && lfc.getNewValue() instanceof List) 
                    union.addAll((List<?>) lfc.getNewValue());
                if (rfc != null && rfc.getNewValue() instanceof List) 
                    union.addAll((List<?>) rfc.getNewValue());
                merged.put(field, new FieldChange(
                    lfc != null ? lfc.getOldValue() : rfc.getOldValue(),
                    new ArrayList<>(union)));
            } else {
                FieldChange winner = (local.getServerTimestamp() >= remote.getServerTimestamp()) 
                    ? lfc : rfc;
                if (winner != null) merged.put(field, winner);
            }
        }
        return ConflictResult.merged(merged);
    }
}
```
