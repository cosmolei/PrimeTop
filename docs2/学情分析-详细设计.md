# 学情分析 - 详细设计文档

## 1. 模块概述

### 1.1 功能定位

学情分析是 PrimeTop 的数据中枢模块，负责收集、聚合和分析用户在学习过程中产生的行为数据，形成动态学情画像。它为其他模块（错题复习、学习规划、家长报告等）提供数据支撑，是"学习→记录→分析→反馈→优化"闭环的关键环节。

### 1.2 核心目标

1. **学习记录**：完整记录每次学习行为（AI问答、拍题、练习、复习等）。
2. **掌握度评估**：量化各学科、章节、知识点的掌握水平。
3. **薄弱点识别**：自动发现正确率低、错题集中的知识盲区。
4. **能力画像**：构建计算能力、阅读理解、逻辑推理等维度分析。
5. **学情报告**：面向学生和家长生成周期性学习报告。
6. **趋势分析**：对比阶段性学习变化，呈现进步或退步趋势。

### 1.3 依赖关系

```
用户账号体系 ──→ 提供用户身份、学段、年级信息
AI智能辅导   ──→ 提供问答会话记录
拍照搜题     ──→ 提供拍题识别和答题记录
同步课堂     ──→ 提供章节学习进度
错题整理     ──→ 提供错题收录和订正记录
学习规划     ──→ 消费学情数据生成/调整计划 ←（依赖学情分析）
家长中心     ──→ 消费学情数据生成家长报告 ←（依赖学情分析）
```

**status 状态流转：**

```
NEW ──→ LEARNING ──→ MASTERED
```

| status | 含义 | mastery_level 范围 |
|---|---|---|

| `WEAK` | 曾学习但当前薄弱 | 1-40 |

### 2.2 数据聚合策略

学习行为日志是高频写入的原始数据，各项聚合指标不实时计算，而是通过**定时任务 + 增量更新**实现：

```
学习行为 → learning_activity_log (实时写入)
               │
               ├── 5分钟聚合 → 更新 knowledge_mastery (知识点掌握度)
               ├── 5分钟聚合 → 更新 subject_overview (学科概览)
               ├── 每日聚合  → 更新 ability_dimension (能力维度)
               ├── 每日生成  → learning_report (DAILY 日报)
               ├── 每周生成  → learning_report (WEEKLY 周报)
               └── 每月生成  → learning_report (MONTHLY 月报)
```

## 4. 核心业务逻辑

### 4.1 掌握度计算算法

掌握度是学情分析的核心指标。采用**加权滑动窗口**算法，综合考虑正确率、题目难度和时间衰减。

```python
def calculate_mastery_level(user_id: int, knowledge_point_id: int) -> float:
    """
    计算某用户某知识点的掌握度 (0-100)
    
    核心公式:
    mastery = correctness_score * difficulty_weight * recency_weight
    
    - correctness_score: 近期答题正确率加权得分
    - difficulty_weight: 难度调整系数
    - recency_weight: 时间衰减系数
    """
    
    # 1. 获取该知识点最近 30 条答题记录
    records = get_recent_answers(user_id, knowledge_point_id, limit=30)
    
    if not records:
        return 0.0
    
    # 2. 计算加权正确率（近期记录权重更高）
    total_weight = 0
    weighted_correct = 0
    
    for i, record in enumerate(records):
        # 时间衰减：越近的权重越大 (指数衰减)
        days_ago = (now() - record.client_time).days
        recency = math.exp(-0.1 * days_ago)
        
        # 难度权重：答对难题得分更高
        diff_bonus = 1.0 + (record.difficulty - 3) * 0.1  # difficulty 1-5
        
        weight = recency * diff_bonus
        total_weight += weight
        
        if record.is_correct:
            weighted_correct += weight
    
    correctness_score = weighted_correct / total_weight if total_weight > 0 else 0
    
    # 3. 连续正确加分（连续答对说明已掌握）
    consecutive_bonus = min(records[0].consecutive_correct * 5, 20) if records else 0
    
    # 4. 计算最终掌握度
    mastery = correctness_score * 70 + consecutive_bonus + min(len(records) * 2, 10)
    mastery = max(0, min(100, mastery))
    
    return round(mastery, 2)


def determine_mastery_status(mastery_level: float, total_attempts: int,
                              days_since_last: int) -> str:
    """确定知识点状态"""
    if total_attempts == 0:
        return 'NEW'
    
    # 长期未练习退化为 NEW
    if days_since_last > 30 and mastery_level < 30:
        return 'NEW'
    
    if mastery_level >= 60:
        return 'MASTERED'
    elif mastery_level >= 40 or total_attempts < 3:
        return 'LEARNING'
    else:
        return 'WEAK'
```

### 4.2 能力维度评估算法

```python
# 能力维度与学科的映射关系
DIMENSION_SUBJECT_MAP = {
    'CALCULATION': ['MATH'],
    'READING_COMP': ['CHINESE', 'ENGLISH'],
    'LOGIC_REASON': ['MATH', 'PHYSICS', 'CHEMISTRY'],
    'EXPRESSION': ['CHINESE', 'ENGLISH'],
    'MEMORIZATION': ['CHINESE', 'ENGLISH', 'HISTORY', 'GEOGRAPHY', 'POLITICS'],
    'APPLICATION': ['MATH', 'PHYSICS', 'CHEMISTRY', 'BIOLOGY'],
}

def calculate_ability_score(user_id: int, dimension_code: str) -> dict:
    """
    计算某能力维度的评分
    
    综合该维度关联学科下的答题数据来评估
    """
    subjects = DIMENSION_SUBJECT_MAP[dimension_code]
    
    total_weighted_score = 0
    total_weight = 0
    total_count = 0
    
    for subject_code in subjects:
        # 获取该学科最近 200 条答题记录
        records = get_recent_practice(user_id, subject_code=subject_code, limit=200)
        
        for record in records:
            days_ago = (now() - record.client_time).days
            recency = math.exp(-0.05 * days_ago)
            
            weight = recency
            score = 100 if record.is_correct else 0
            
            total_weighted_score += score * weight
            total_weight += weight
            total_count += 1
    
    avg_score = total_weighted_score / total_weight if total_weight > 0 else 0
    
    # 能力等级划分
    if total_count < 5:
        level = 'UNASSESSED'
    elif avg_score >= 80:
        level = 'EXCELLENT'
    elif avg_score >= 60:
        level = 'GOOD'
    elif avg_score >= 40:
        level = 'AVERAGE'
    else:
        level = 'WEAK'
    
    return {
        'score': round(avg_score, 2),
        'level': level,
        'basedOnCount': total_count
    }
```

### 4.3 薄弱点识别逻辑

```python
def identify_weak_points(user_id: int, subject_code: str = None,
                          limit: int = 10) -> list:
    """
    识别用户的薄弱知识点
    
    筛选条件（满足任一即为薄弱点）:
    1. mastery_level < 40 且 total_attempts >= 3
    2. 最近 7 天正确率 < 40%
    3. 错题数量 >= 3 且未订正
    
    排序权重 = 紧急度排序:
    - 错误频率越高越紧急
    - 越接近考试/当前学习章节越紧急
    """
    weak_points = []
    
    # 查询所有非 MASTERED 状态的知识点
    masteries = get_user_masteries(user_id, subject_code, 
                                    statuses=['WEAK', 'LEARNING'])
    
    for m in masteries:
        urgency_score = 0
        
        # 因素1: 掌握度越低越紧急 (权重 40%)
        urgency_score += (100 - m.mastery_level) * 0.4
        
        # 因素2: 最近正确率 (权重 30%)
        recent_rate = get_recent_correct_rate(user_id, m.knowledge_point_id, days=7)
        if recent_rate is not None:
            urgency_score += (1 - recent_rate) * 100 * 0.3
        
        # 因素3: 练习频次（越少练习说明越需要关注） (权重 15%)
        if m.total_attempts < 5:
            urgency_score += (5 - m.total_attempts) * 10 * 0.15
        
        # 因素4: 是否属于当前学习章节 (权重 15%)
        if is_current_chapter(user_id, m.knowledge_point_id):
            urgency_score += 100 * 0.15
        
        weak_points.append({
            'knowledgePointId': m.knowledge_point_id,
            'pointName': m.point_name,
            'masteryLevel': m.mastery_level,
            'status': m.status,
            'urgencyScore': round(urgency_score, 2),
            'recentCorrectRate': recent_rate
        })
    
    # 按紧急度降序排列
    weak_points.sort(key=lambda x: x['urgencyScore'], reverse=True)
    return weak_points[:limit]
```

### 4.4 学情报告生成

```python
def generate_weekly_report(user_id: int, week_start: date) -> dict:
    """
    生成周报
    
    包含:
    1. 本周学习时长、次数、答题数、正确率
    2. 各学科摘要
    3. 薄弱知识点 Top5
    4. 能力维度评分变化
    5. 进步/退步知识点
    6. AI 学习建议
    """
    week_end = week_start + timedelta(days=6)
    
    # 1. 汇总本周数据
    activities = get_activities_in_period(user_id, week_start, week_end)
    
    total_duration = sum(a.duration_sec for a in activities)
    total_questions = len([a for a in activities if a.is_correct is not None])
    correct_count = len([a for a in activities if a.is_correct is True])
    correct_rate = correct_count / total_questions if total_questions > 0 else 0
    
    # 2. 按学科分组
    subject_summaries = {}
    for code in SUBJECT_CODES:
        sub_activities = [a for a in activities if a.subject_code == code]
        if sub_activities:
            subject_summaries[code] = summarize_subject(sub_activities)
    
    # 3. 薄弱知识点
    weak_points = identify_weak_points(user_id, limit=5)
    
    # 4. 对比上周数据，计算进步/退步
    last_week_activities = get_activities_in_period(
        user_id, week_start - timedelta(days=7), week_start - timedelta(days=1)
    )
    improvements, regressions = compare_knowledge_mastery(
        user_id, week_start, week_start + timedelta(days=6)
    )
    
    # 5. 生成 AI 建议
    ai_suggestion = generate_ai_suggestion(
        user_id, subject_summaries, weak_points, improvements, regressions
    )
    
    report = {
        'userId': user_id,
        'reportType': 'WEEKLY',
        'periodStart': week_start.isoformat(),
        'periodEnd': week_end.isoformat(),
        'totalDurationSec': total_duration,
        'totalActivities': len(activities),
        'totalQuestions': total_questions,
        'correctRate': round(correct_rate, 4),
        'subjectSummaries': subject_summaries,
        'weakPoints': [format_weak_point(wp) for wp in weak_points],
        'abilityScores': get_all_ability_scores(user_id),
        'improvements': improvements,
        'regressions': regressions,
        'aiSuggestion': ai_suggestion
    }
    
    # 6. 写入报告表
    upsert_report(report)
    
    return report
```

```python
def mastery_update_task():
    """
    每 5 分钟执行一次，增量更新知识点掌握度。
    
    策略：只处理最近 10 分钟内有新活动的知识点，
    而非全量重新计算。
    """
    # 查找最近 10 分钟内有新活动的 (user_id, knowledge_point_id) 对
    cutoff = now() - timedelta(minutes=10)
    
    active_pairs = query("""
        SELECT DISTINCT user_id, knowledge_point_id
        FROM learning_activity_log
        WHERE created_at >= %s
          AND knowledge_point_id IS NOT NULL
          AND is_correct IS NOT NULL
    """, [cutoff])
    
    for user_id, kp_id in active_pairs:
        # 重新计算该知识点的掌握度
        mastery_level = calculate_mastery_level(user_id, kp_id)
        
        # 获取当前记录
        current = get_mastery_record(user_id, kp_id)
        
        # 计算状态
        total_attempts = current.total_attempts if current else 0
        days_since_last = 0  # 刚有活动，所以为 0
        new_status = determine_mastery_status(mastery_level, total_attempts, days_since_last)
        
        # 更新或插入
        upsert_mastery(user_id, kp_id, mastery_level, new_status, total_attempts)
```

## 8. 错误处理

### 8.1 学习行为上报错误处理

| 场景 | 处理方式 |
|---|---|
| 网络异常，上报失败 | 客户端本地缓存，支持离线积攒，网络恢复后批量上报 |
| `knowledgePointId` 不存在 | 忽略该字段，仍记录行为，仅不关联知识点 |
| `clientTime` 时间偏差 >5min | 以服务端时间为准写入，但不拒绝 |
| 上报频率超限 | 返回 429，客户端排队延迟重试 |
| 数据库写入失败 | 写入失败队列，由消费者重试（最多 3 次） |

### 8.2 定时任务错误处理

| 场景 | 处理方式 |
|---|---|
| 某用户聚合计算失败 | 跳过该用户，记录日志，不影响其他用户 |
| AI 建议生成超时 | 使用模板建议兜底，记录日志 |
| 批量任务超时 | 分页处理，每页 100 用户，超时后下一页继续 |
| 数据库连接异常 | 指数退避重试，3 次后告警 |

### 8.3 客户端离线策略

```typescript
// 客户端离线缓存策略（伪代码）
class ActivityReporter {
    private pendingQueue: Activity[] = [];
    private isOnline: boolean = true;
    
    async report(activity: Activity): Promise<void> {
        if (!this.isOnline) {
            // 离线时存入本地队列
            this.pendingQueue.push(activity);
            await localDB.save('pending_activities', activity);
            return;
        }
        
        try {
            await api.post('/learning/activities', activity);
        } catch (error) {
            // 发送失败也存入队列
            this.pendingQueue.push(activity);
            await localDB.save('pending_activities', activity);
        }
    }
    
    // 网络恢复时批量同步
    async syncPending(): Promise<void> {
        if (this.pendingQueue.length === 0) return;
        
        const batch = this.pendingQueue.splice(0, 50);
        await api.post('/learning/activities/batch', { activities: batch });
        
        // 同步成功后清除本地缓存
        await localDB.remove('pending_activities', batch);
    }
}
```

## 9. 性能考量

### 9.1 写入优化

- `learning_activity_log` 是高写入频率表，建议按月分区或按 `user_id` 取模分表
- 上报接口同步写日志表，聚合异步化，保证接口响应 < 100ms
- 批量上报接口支持最多 50 条合并写入

### 9.2 查询优化

- 所有查询走 Redis 缓存，缓存未命中再查 DB
- 趋势查询可考虑写入预聚合表 `learning_daily_stats`，避免实时聚合日志表
- 报告查询直接读 `learning_report` 表，不做实时计算

### 9.3 数据归档

- `learning_activity_log` 保留 180 天在线数据，超期数据归档至对象存储或冷存储
- 聚合结果（掌握度、概览、报告）长期保留
- 用户注销后 30 天内清除所有学习数据
