## 1. 模块概述

### 1.1 功能定位

家庭共享会员权益配额调度引擎负责在家庭套餐（多孩子账号）场景下，对会员权益进行统一购买、按成员分配、动态调度与实时核扣。核心解决以下问题：

- 一个家庭购买高阶会员后，多个孩子如何共享权益；
- 如何防止某个孩子过度占用导致其他孩子权益耗尽；
- 如何实现按功能、按学科、按时间维度的灵活配额；
- 如何支持权益的临时借用、超额预警和自动回收。

### 1.2 适用范围

| 场景 | 说明 |
|------|------|
| 家庭套餐权益共享 | 家长购买年度/月度家庭会员，多个学生子账号共用权益池 |
| 功能级配额 | 对 AI 问答、拍题解析、作文批改、听力练习等功能分别设限 |
| 时间级配额 | 支持每日/每周/每月的用量上限，防止单成员短期刷量 |
| 超额保护 | 单个成员接近配额阈值时触发提醒，超限时进入只读/降级模式 |
| 运营活动 | 临时赠送家庭共享额度、节假日加倍权益等 |

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 权益池 (QuotaPool) | 家庭会员对应的全局可用资源总量 |
| 配额单元 (QuotaUnit) | 最小可分配权益单位，如 `ai_chat:50` 表示 50 次 AI 问答 |
| 分配策略 (AllocationPolicy) | 定义权益如何在多个成员间分配的规则 |
| 核扣记录 (QuotaDeduction) | 每次使用权益时的扣减流水 |
| 借用 (Borrow) | 某成员配额耗尽后，从家庭共享池临时借用额度 |

## 4. 状态流转

### 4.1 权益池生命周期

```
              购买/续费
    [不存在] ──────────> [生效中 active]
                          │
                          │ 到期 / 取消
                          ▼
                    [已过期 expired]
                          │
                          │ 续费
                          ▼
                    [生效中 active]
```

### 4.2 单次核扣状态机

```
[预占 preoccupied] ──确认──> [已扣减 confirmed]
        │
        └──超时/失败──> [已回滚 rollback]
```

### 4.3 配额使用顺序

```
1. 先消耗该成员当前周期的 allocated 配额
2. allocated 不足时，若允许借用，则从家庭共享池剩余可用额度中借用
3. 共享池不足时，检查是否有临时赠送/运营活动额度
4. 全部耗尽则拒绝服务，返回升级/购买提示
```

## 5. 关键代码示例

### 5.1 权益核减核心逻辑（Python + Redis + PostgreSQL）

```python
from typing import Dict, Optional
import redis
import psycopg2
from contextlib import contextmanager

class FamilyQuotaService:
    def __init__(self, db, redis_client: redis.Redis):
        self.db = db
        self.redis = redis_client

    def deduct(self, family_id: int, member_id: int, user_id: int,
               quota_type: str, amount: int, biz_type: str, biz_id: str,
               need_borrow: bool = True) -> Dict:
        lock_key = f"family:quota:{family_id}:{quota_type}:lock"
        with self.redis_lock(lock_key, timeout=10):
            # 1. 校验家庭会员状态
            family = self._get_family(family_id)
            if family['status'] != 'active':
                raise QuotaError(460200, '家庭会员未生效或已过期')

            # 2. 查询成员分配额
            alloc = self._get_member_allocation(family_id, member_id, quota_type)
            remaining_allocated = (alloc['allocated'] - alloc['used'] - alloc['borrowed']) if alloc else 0

            source = 'allocated'
            borrowed_amount = 0

            if remaining_allocated >= amount:
                # 完全使用 allocated
                self._incr_alloc_used(alloc['id'], amount)
            elif need_borrow:
                # 部分/全部借用共享池
                allocated_part = remaining_allocated
                borrowed_amount = amount - allocated_part
                pool = self._get_pool(family_id)
                total_used = sum(pool['used_quota'].get(quota_type, 0) for qt in pool['used_quota'])
                shared_remaining = pool['total_quota'].get(quota_type, 0) - total_used

                if borrowed_amount > shared_remaining:
                    raise QuotaError(460201, '家庭会员权益已用尽',
                                     {'required': amount, 'available': remaining_allocated + shared_remaining})

                if allocated_part > 0:
                    self._incr_alloc_used(alloc['id'], allocated_part)
                self._incr_pool_used(family_id, quota_type, borrowed_amount)
                source = 'borrowed' if allocated_part == 0 else 'mixed'
            else:
                raise QuotaError(460201, '个人配额已用尽', {'required': amount, 'available': remaining_allocated})

            # 3. 写入核扣流水
            deduction_id = self._insert_deduction(
                family_id, member_id, user_id, quota_type, amount,
                source, biz_type, biz_id
            )

            return {
                'deduction_id': deduction_id,
                'source': source,
                'borrowed_amount': borrowed_amount,
                'remaining': self._build_remaining(family_id, member_id, quota_type)
            }

    def _incr_alloc_used(self, alloc_id: int, amount: int):
        # 使用乐观锁防止并发覆盖
        with self.db.cursor() as cur:
            cur.execute("""
                UPDATE member_quota_allocations
                SET used = used + %s, version = version + 1
                WHERE id = %s AND (allocated - used - borrowed) >= %s
                RETURNING version
            """, (amount, alloc_id, amount))
            if not cur.fetchone():
                raise QuotaError(460202, '配额并发更新冲突')

    def _incr_pool_used(self, family_id: int, quota_type: str, amount: int):
        with self.db.cursor() as cur:
            cur.execute("""
                UPDATE quota_pools
                SET used_quota = jsonb_set(
                    used_quota,
                    array[%s],
                    COALESCE((used_quota->>%s)::int, 0)::text::jsonb + %s
                ),
                version = version + 1
                WHERE family_id = %s
                RETURNING version
            """, (quota_type, quota_type, amount, family_id))

    @contextmanager
    def redis_lock(self, key: str, timeout: int = 10):
        identifier = str(uuid.uuid4())
        try:
            acquired = self.redis.set(key, identifier, nx=True, ex=timeout)
            if not acquired:
                raise QuotaError(460203, '权益核扣排队中，请稍后重试')
            yield
        finally:
            # Lua 脚本保证安全释放
            script = """
            if redis.call("get", KEYS[1]) == ARGV[1] then
                return redis.call("del", KEYS[1])
            else
                return 0
            end
            """
            self.redis.eval(script, 1, key, identifier)
```

### 5.2 周期重置任务（Go 示例）

```go
package main

import (
    "context"
    "database/sql"
    "fmt"
    "time"

    _ "github.com/lib/pq"
)

// ResetFamilyQuota 每月 1 号执行，重置所有按月重置的配额
func ResetFamilyQuota(db *sql.DB, resetTime time.Time) error {
    ctx := context.Background()
    tx, err := db.BeginTx(ctx, nil)
    if err != nil {
        return err
    }
    defer tx.Rollback()

    // 1. 重置成员分配表
    _, err = tx.ExecContext(ctx, `
        UPDATE member_quota_allocations
        SET used = 0,
            borrowed = 0,
            effective_at = $1,
            expired_at = $2,
            updated_at = NOW()
        WHERE cycle = 'monthly'
          AND effective_at < $1
          AND expired_at IS NULL
    `, resetTime, resetTime.AddDate(0, 1, 0))
    if err != nil {
        return fmt.Errorf("reset member allocations failed: %w", err)
    }

    // 2. 重置家庭池已用量
    _, err = tx.ExecContext(ctx, `
        UPDATE quota_pools
        SET used_quota = '{}'::jsonb,
            frozen_quota = '{}'::jsonb,
            last_reset_at = $1,
            next_reset_at = $2,
            version = version + 1
        WHERE reset_cycle = 'monthly'
          AND next_reset_at <= $1
    `, resetTime, resetTime.AddDate(0, 1, 0))
    if err != nil {
        return fmt.Errorf("reset pool failed: %w", err)
    }

    return tx.Commit()
}
```

### 5.3 配额预检查（Kotlin/Android 端）

```kotlin
class FamilyQuotaChecker(private val api: FamilyApi) {

    suspend fun checkBeforeUse(memberId: Long, quotaType: String, amount: Int): CheckResult {
        return try {
            val resp = api.getMemberQuota(memberId)
            val quota = resp.quotas.find { it.quotaType == quotaType }
                ?: return CheckResult.NoQuota(quotaType)

            val available = quota.remaining + if (quota.allowBorrow) quota.sharedAvailable else 0
            if (available < amount) {
                return CheckResult.Insufficient(available, amount)
            }
            CheckResult.OK(quota)
        } catch (e: Exception) {
            // 弱网场景：本地缓存兜底，允许一次使用并在后台同步
            CheckResult.NetworkFallback
        }
    }

    sealed class CheckResult {
        data class OK(val quota: MemberQuota) : CheckResult()
        data class Insufficient(val available: Int, val required: Int) : CheckResult()
        data class NoQuota(val quotaType: String) : CheckResult()
        object NetworkFallback : CheckResult()
    }
}
```

## 6. 错误处理

### 6.1 错误码定义

| 错误码 | 含义 | 处理建议 |
|--------|------|----------|
| 460200 | 家庭会员未生效或已过期 | 引导购买/续费家庭套餐 |
| 460201 | 家庭会员权益已用尽 | 提示升级套餐或购买增值服务包 |
| 460202 | 配额并发更新冲突 | 客户端重试，服务端使用乐观锁 |
| 460203 | 权益核扣排队中 | 稍后重试，避免高频重入 |
| 460204 | 非法的配额类型 | 校验 quota_type 是否合法 |
| 460205 | 成员不在该家庭中 | 校验 member_id 归属 |
| 460206 | 借用额度超过共享池上限 | 调整借用策略或购买临时包 |
| 460207 | 配额转移受限 | 该 quota_type 不支持 transfer |
| 460208 | 核扣流水幂等重复 | 直接返回已存在的扣减结果 |

### 6.2 幂等性保证

- 使用 `(family_id, member_id, biz_type, biz_id)` 四元组作为唯一键；
- 重复请求返回第一次扣减结果，不重复扣减；
- 幂等记录保留 7 天，过期后自动清理。

```sql
CREATE UNIQUE INDEX idx_qd_idempotent
ON quota_deductions(family_id, member_id, biz_type, biz_id)
WHERE status = 'confirmed';
```

### 6.3 降级策略

| 场景 | 降级行为 |
|------|----------|
| 配额服务不可用 | 允许单次使用并标记为待核扣，服务恢复后异步补扣；连续 3 次失败则暂停该功能 |
| Redis 锁获取失败 | 返回"服务繁忙"，客户端 2 秒后重试 |
| 数据库写入超时 | 进入预占状态，通过补偿任务确认或回滚 |
| 家庭会员过期 | 切换为免费额度策略，不影响已有学习记录查看 |

| 缓存对象 | 方案 | TTL |
|----------|------|-----|
| 成员配额余额 | Redis Hash | 5 分钟 + 写时失效 |
| 家庭权益池总额 | Redis Hash | 10 分钟 |
| 配额类型字典 | Caffeine 本地缓存 | 1 小时 |
| 核扣幂等键 | Redis SETNX | 7 天 |

### 7.2 并发控制

- 同一家庭同一配额类型使用 Redis 分布式锁，粒度：`family:{id}:{quota_type}`；
- 数据库更新使用乐观锁 version 字段；
- 批量核扣（如一次拍题多小题）合并为一条 deduction 记录。

### 7.3 数据库优化

- `quota_pools.total_quota`、`used_quota` 使用 JSONB 存储多类型额度；
- 按 `created_at` 对 `quota_deductions` 进行分区（按月）；
- 频繁查询的 `member_quota_allocations` 加复合索引 `(family_id, member_id, quota_type, effective_at)`。

## 8. 安全与合规

### 8.1 权限控制

- 只有家庭管理员（家长）可调整成员配额分配；
- 学生只能查看自己的配额，不能修改；
- 接口鉴权时校验 `member_id` 是否属于当前 `family_id`；
- 管理后台操作需记录审计日志。

### 8.2 数据隐私

- 核扣流水中的 `extra` 字段不采集精确地理位置；
- 删除成员时保留历史核扣流水用于对账，但匿名化 user_id；
- 未成年人消费额度受家长控制，单成员日消费上限默认 0 元。

### 8.3 防刷限流

- 单个成员每分钟核扣同一配额类型不超过 60 次；
- 异常高频调用触发风控，临时冻结该成员该功能 10 分钟；
- 借用共享池每日有上限，防止单成员独占。

## 9. 与周边模块关系

```text
家庭共享会员权益配额调度引擎
        │
        ├─ 依赖：用户服务（users、family_members）
        ├─ 依赖：支付服务（订单、套餐、续费状态）
        ├─ 依赖：会员服务（权益模板、plan_code 解析）
        │
        ├─ 被依赖：AI 辅导服务（核减 ai_chat 额度）
        ├─ 被依赖：拍照搜题服务（核减 photo_q 额度）
        ├─ 被依赖：作文辅导服务（核减 essay_correct 额度）
        └─ 被依赖：消息服务（额度不足提醒、重置通知）
```

## 10. 验收标准

1. 家庭购买套餐后，权益池总额正确初始化；
2. 多成员同时使用同一配额类型，核减结果准确无超卖；
3. 周期重置任务在每月 1 号 00:00 准时执行，重置后 used 归零；
4. 额度不足时客户端收到明确错误码和引导文案；
5. 核扣流水支持按成员、按类型、按业务单号查询；
6. 并发场景下 1000 TPS 核扣请求无数据不一致。
