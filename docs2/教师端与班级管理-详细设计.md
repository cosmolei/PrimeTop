> 版本：1.1

> 状态：预研设计（V2.0 规划；v1.1 补全至可开发粒度）  
> 模块优先级：P3（中长期扩展）

---

## 1. 模块概述

### 1.1 功能定位

教师端与班级管理模块为 PrimeTop 的 V2.0 扩展功能，面向学校教师和教培机构讲师，提供班级创建、学生管理、作业布置与批改、班级学情分析、家校沟通等核心能力。该模块需与现有学生端、家长端、内容服务、AI 服务和数据分析体系深度集成。

### 1.2 设计目标

1. **低门槛接入**：教师无需复杂培训即可快速上手，核心操作 ≤ 3 步完成
2. **与学生端无缝衔接**：教师发布的作业、通知直接推送到学生 APP
3. **与家长端联动**：学情报告、班级通知自动同步至家长中心
4. **与现有模块解耦**：通过事件驱动和 API 集成，不侵入现有核心代码
5. **支持多场景**：公立学校班级、培训机构小班、一对一辅导

### 1.3 核心用户角色

| 角色 | 说明 | 典型场景 |
|------|------|----------|
| 班主任 | 管理本班学生、查看全科成绩 | 日常班级管理、家校沟通 |
| 科任教师 | 管理所教学科的学生 | 布置作业、查看学科数据 |
| 教研组长 | 管理年级/学科组 | 年级横向对比、教研资源共享 |
| 机构讲师 | 培训机构教师 | 小班管理、学员进度跟踪 |

### 3.2 DDL 定义

#### 3.2.1 教师表 teacher

```sql
CREATE TABLE teacher (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL COMMENT '关联 users 表（教师也是用户）',
    real_name       VARCHAR(50) NOT NULL COMMENT '真实姓名',
    phone           VARCHAR(20) NOT NULL COMMENT '手机号',
    school_name     VARCHAR(200) COMMENT '所属学校/机构名称',
    school_code     VARCHAR(50) COMMENT '学校代码（用于官方学校匹配）',
    title           VARCHAR(50) COMMENT '职称：高级教师/一级教师/...',
    subject_ids     JSON COMMENT '所教学科 ID 列表 [1,3,5]',
    cert_no         VARCHAR(100) COMMENT '教师资格证编号',
    cert_status     TINYINT NOT NULL DEFAULT 0 COMMENT '认证状态：0-未认证 1-审核中 2-已认证 3-认证失败',
    cert_verified_at DATETIME COMMENT '认证通过时间',
    avatar_url      VARCHAR(500) COMMENT '头像',
    bio             VARCHAR(500) COMMENT '个人简介',
    status          TINYINT NOT NULL DEFAULT 1 COMMENT '状态：0-禁用 1-正常',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_user_id (user_id),
    UNIQUE KEY uk_phone (phone),
    INDEX idx_school_code (school_code),
    INDEX idx_cert_status (cert_status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='教师信息表';
```

#### 3.2.5 作业/任务表 assignment

```sql
CREATE TABLE assignment (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    class_id        BIGINT NOT NULL COMMENT '目标班级',
    teacher_id      BIGINT NOT NULL COMMENT '发布教师',
    title           VARCHAR(200) NOT NULL COMMENT '作业标题',
    description     TEXT COMMENT '作业说明',
    assignment_type TINYINT NOT NULL COMMENT '类型：1-题库选题 2-AI生成 3-自定义题目 4-综合练习',
    subject_id      INT NOT NULL COMMENT '学科',
    content         JSON NOT NULL COMMENT '作业内容（结构化，见下方 JSON Schema）',
    knowledge_point_ids JSON COMMENT '关联知识点 ID 列表',
    difficulty      TINYINT COMMENT '难度：1-基础 2-中等 3-提高',
    total_score     DECIMAL(5,1) COMMENT '总分（如果适用）',
    
    -- 时间控制
    publish_at      DATETIME NOT NULL COMMENT '发布时间（定时发布）',
    deadline_at     DATETIME COMMENT '截止时间（NULL 表示不限时）',
    time_limit_min  INT COMMENT '限时（分钟），NULL 表示不限时',
    
    -- 完成规则
    allow_late_submit TINYINT NOT NULL DEFAULT 0 COMMENT '是否允许补交：0-否 1-是',
    late_submit_deadline DATETIME COMMENT '补交截止时间',
    show_answer_after TINYINT NOT NULL DEFAULT 1 COMMENT '提交后是否显示答案：0-不显示 1-立即显示 2-截止后显示',
    
    -- 状态
    status          TINYINT NOT NULL DEFAULT 0 COMMENT '0-草稿 1-已发布 2-已截止 3-已批改 4-已归档',
    published_at    DATETIME COMMENT '实际发布时间',
    
    -- 统计（冗余字段，异步更新）
    total_students  INT NOT NULL DEFAULT 0 COMMENT '应提交人数',
    submitted_count INT NOT NULL DEFAULT 0 COMMENT '已提交人数',
    graded_count    INT NOT NULL DEFAULT 0 COMMENT '已批改人数',
    avg_score       DECIMAL(5,2) COMMENT '平均分',
    completion_rate DECIMAL(5,4) COMMENT '完成率',
    
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_class (class_id),
    INDEX idx_teacher (teacher_id),
    INDEX idx_status_publish (status, publish_at),
    INDEX idx_deadline (deadline_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='作业/任务表';
```

## 4. API 接口设计

### 4.1 接口规范

所有接口遵循 `API网关与通用接口规范-详细设计.md` 中的统一规范：
- 基础路径：`/api/v1/teacher/`
- 认证方式：Bearer Token (JWT)
- 响应格式：`{ "code": 0, "message": "success", "data": {...} }`
- 错误码段：`50xxx`

## 5. 关键流程时序

### 5.1 班级创建与学生加入审批

```
教师           教师端BFF           班级服务            通知服务         学生/家长
 │  创建班级      │                  │                  │               │
 │─────────────>│ POST /classes    │                  │               │
 │              │────────────────>│ 生成 class_code（SETNX 防碰撞,重试≤3） │
 │              │                  │ 写 class + teacher_class(角色=班主任) │
 │              │<────────────────│ classId/class_code/qr_url          │
 │<─────────────│                  │                  │               │
 │                                                                │
 │        学生输入邀请码 ──────────────────────────────────────────>│
 │              │ POST /student/classes/join       │               │
 │              │────────────────>│ 校验码有效性/班级状态/人数上限      │
 │              │                  │ class_student(join_status=0)      │
 │              │                  │──class.student.apply────────────>│ (通知教师)
 │  审批         │                  │                  │               │
 │─────────────>│────────────────>│ join_status 0→1 (CAS)            │
 │              │                  │ joined_at=now；清邀请码占用        │
 │              │                  │──class.student.approved─────────>│ (通知学生；家长端可见)
 │              │                  │   作业服务消费：补发进行中作业      │
```

要点：
1. 审批采用逐条 CAS（`UPDATE ... SET join_status=1 WHERE id=? AND join_status=0`），批量接口循环单条、部分成功返回逐条结果（D8）；
2. 被拒绝学生可重新申请——新行插入受函数唯一索引约束，仅当无「待审/已通过」活跃行时允许（§14.2）；
3. 学生加入成功后，进行中作业由作业服务消费 `class.student.approved` 补发，不由班级服务直接写作业表。

### 5.2 作业发布流水线（概要）

权威实现见《服务端-教师班级管理与作业发布服务》§5.1。本模块职责仅在入口：

创建草稿(status=0) → 题目校验（题库题 question_id 有效性/学科一致性；自定义题敏感词预检）→ 发布（立即或定时，`idx_status_publish` 扫描）→ `assignment.published` → 通知服务（学生推送 + `parent.notify.assignment` 家长推送）→ 学生端作业中心可见。

发布失败（题目校验不过 50301）回滚为草稿并标注具体题号；定时发布到点由调度器触发，与手动发布同路径。

### 5.3 批改闭环

```
学生提交(assignment_task.status=2, submit_method=1手动/2超时)
   │ assignment.task.submitted
   ├─> AI批改服务：客观题判分 + 主观题初评(auto_score/ai_feedback)
   │      置信度 < 0.8 → needs_manual_review=1，进教师批改队列
   ├─> 教师批改工作台：GET tasks?status=2 → 逐题打分/评语 → POST grade
   │      ├─ status 2→3 CAS；manual_score/teacher_comment 落库
   │      ├─ assignment.task.graded → 教师端统计刷新、师生通知
   │      └─ homework.graded（学生作业链路权威事件）→ 错题收录/学情更新/订正触发/激励
   └─> 全部批改完成 → assignment.status=3，统计冗余字段刷新
```

要点：
1. `assignment.task.graded` 与 `homework.graded` 为同一业务事实双视角事件，同批改事务双写 Outbox；错题收录/学情更新以 `homework.graded` 为唯一扇出源，防止重复收录（§14.4）；
2. `batch-grade` 仅适用于客观题 100% 或教师确认采纳 `auto_score` 的任务；采纳后仍可逐题改判（批改记录留痕）；
3. 助教批改结果进入待复核态，科任教师/班主任确认后学生可见。

### 5.4 通知发布与回执

发布 → 通知服务按 `target_audience` 拆学生/家长双通道 → 阅读/确认回执异步写入 `class_notice_read` / `class_notice_confirm` → 冗余计数（read_count/confirm_count）每 5min 批量刷新 → 教师端可查未确认名单并一键提醒（频控见 §4.8）。

### 5.5 学期归档

教师发起归档 → 校验无进行中作业（有则先截止结算：发 `class.archived`，作业服务消费）→ `class.status 1→0`，师生关联保留只读（历史作业/成绩可查）→ 通知师生。归档不可逆；如需恢复联系管理后台（双人审批，见工作台 §5）。

## 6. 状态机与守卫

### 6.1 教师认证状态机（cert_status）

对齐《服务端-教师班级管理与作业发布服务》§4.1：

```
0 未认证 ──提交──> 1 审核中 ──┬──> 2 已认证
   ▲                          └──> 3 认证失败 ──重新提交──> 1 审核中
   │                                            └──快速体验──> 4 快速体验(90天)
   └──────────────────── 4 过期回落 ──────────────┘
```

快速体验（v1.0 未定义，§14.3 增补）：90 天有效；期间建班上限 2 个（正式认证 20 个，触发 50303 引导认证）；过期回落 0 后不可新建班级与发布新作业，已建班级保留只读、存量未批改作业可继续批改。

### 6.2 班级状态机（class.status）

```
活跃(1) ──归档(G5)──> 已归档(0)
   │                      │
   └──毕业──> 已毕业(2)    └──管理后台恢复(双人审批)──> 活跃(1)
管理台合并特例：源班数据并入目标班（class.merged，见工作台 §5）
```

### 6.3 作业状态机（assignment.status）

`0 草稿 →（发布/定时）→ 1 已发布 →（到达 deadline）→ 2 已截止 →（全部批改/手动关闭）→ 3 已批改 →（归档/学期结束）→ 4 已归档`。权威定义见服务端文档 §4.2。

### 6.4 学生作业实例状态机（assignment_task.status）

`0 未开始 → 1 答题中 → {2 已提交（含超时自动提交，submit_method=2）→ 3 已批改 | 4 超时未交}`。权威定义见服务端文档 §4.3。

与《服务端-学生作业全生命周期管理》引擎记录态的映射：WITHDRAWN（教师撤回）/EXEMPT（免做）为引擎层记录态，不改变本表 status，仅在任务详情以 flags 呈现。

### 6.5 学生加入状态机（join_status × status）

`0 待审核 → {1 已通过 | 2 已拒绝 →（重新申请）→ 0}`；`1 →（移除/退出/转班）→ status=0 已退出（行保留）`。

### 6.6 守卫总表

| 编号 | 守卫规则 | 错误码 |
|------|----------|--------|
| G1 | 仅 status=0 草稿作业可编辑/删除 | 50300/50302 |
| G2 | 作业发布必须通过题目校验（题库题存在且学科一致；自定义题敏感词通过） | 50301 |
| G3 | 仅 assignment_task.status=2 可批改；对已批改任务重复提交按幂等返回成功 | 50200 |
| G4 | 批改人必须是本班教师且角色 ≥ 科任；助教可批改但结果需复核 | 50201/50402 |
| G5 | 班级归档前必须无进行中作业（否则先截止结算） | 50605 |
| G6 | 移除学生前其进行中作业须先结算或转交；批量移除部分成功 | 50605 |
| G7 | 班主任移除/退出前必须先移交班主任角色 | 50402 |
| G8 | 刷新邀请码后旧码立即失效（Redis 删除 + DB 覆写） | - |
| G9 | 加入审批逐条 CAS；重复审批返回幂等成功 | - |

## 12. 合规与未成年人保护

1. **成绩与排名**：义务教育阶段不提供全班成绩排名展示；个体成绩仅本人/家长/本班教师可见；班级看板仅聚合统计与 band 化区间（k-匿名，对齐同伴基准引擎）。
2. **双减约束**：作业总量管控由《服务端-跨学科作业负载协同调控与学生作业总量智能管控引擎》执行；教师端发布时展示「今日该班作业总时长预估」，超限提醒但不硬拦截，标记 `homework.overload` 事件供调控引擎仲裁。
3. **教师可见性最小化**：学生手机号默认脱敏，明文查看需班主任权限 + 强制审计（§7.2）。
4. **家长触达**：含家长通道的通知同步进家长中心；确认回执仅统计口径，不向学生暴露家长个人已读明细。
5. **数据保留**：班级归档后数据保留 3 学年；注销账号学生记录匿名化（对齐《服务端数据归档与生命周期管理策略》）。
6. **班级内社交限制**：本模块不提供学生间自由聊天；互动仅限作业/通知场景，通知内容经敏感词引擎 scene=CLASS_NOTICE 预检，用户可见内容不落 UGC 自由文本区。

## 14. 契约对齐与 v1.0 缺陷修复

### 14.1 表名与权威文档映射

| 本文档 v1.0 | 服务端权威文档 | 说明 |
|-------------|----------------|------|
| teacher | teacher_profile | 以服务端文档为准 |
| teacher_class | class_teacher | 以服务端文档为准 |
| class / assignment / assignment_task / class_student / class_notice / class_notice_confirm | 同名 | 字段以服务端文档为权威，本文档 §3 保留模块级视图 |

### 14.2 唯一索引缺陷修复（v1.0 缺陷，方案对齐工作台 §5.6）

v1.0 中 `uk_teacher_class(teacher_id, class_id, subject_id)` 与 `uk_class_student(class_id, student_id)` 将状态列排除在键外但行保留历史：教师/学生「退出后再次加入」「被拒后重新申请」会与 `status=0` 历史行撞唯一键，导致再次加入失败。修复：改用 MySQL 8.0 函数唯一索引，仅约束活跃行（函数返回 NULL 不参与唯一约束）：

```sql
-- 教师班级关联：至多一条在职记录，允许多条历史记录
ALTER TABLE class_teacher
  DROP INDEX uk_teacher_class,
  ADD UNIQUE KEY uk_teacher_class_active
    ((IF(status = 1, 0, NULL)), teacher_id, class_id);

-- 班级学生关联：至多一条「待审/已通过」活跃记录，允许多条已退出/已拒绝历史
ALTER TABLE class_student
  DROP INDEX uk_class_student,
  ADD UNIQUE KEY uk_class_student_active
    ((IF(join_status IN (0, 1) AND status = 1, 0, NULL)), class_id, student_id);
```

> 上线前需执行存量重复数据检查（同键多条活跃行先人工归并）；保留普通索引 `idx_teacher_id` / `idx_student_id` 支撑历史查询。

### 14.3 DDL 增补（v1.1）

```sql
-- cert_status 增补快速体验态（§6.1）：0-未认证 1-审核中 2-已认证 3-认证失败 4-快速体验(90天)
ALTER TABLE teacher_profile
  MODIFY COLUMN cert_status TINYINT NOT NULL DEFAULT 0
  COMMENT '0-未认证 1-审核中 2-已认证 3-认证失败 4-快速体验(90天)';

-- 作业实例增补提交方式与人工复核标记（§5.3/§6.4）
ALTER TABLE assignment_task
  ADD COLUMN submit_method TINYINT NOT NULL DEFAULT 1
  COMMENT '1-手动提交 2-超时自动提交' AFTER submitted_at,
  ADD COLUMN needs_manual_review TINYINT NOT NULL DEFAULT 0
  COMMENT 'AI 初评置信度<0.8 标记人工复核' AFTER ai_feedback;
```

### 14.4 双事件边界（assignment.task.graded × homework.graded）

两事件为同一批改业务事实的双视角输出，同批改事务双写 Outbox：

- `assignment.task.graded`：仅驱动教师侧（统计刷新、教师通知），消费方轻量；
- `homework.graded`：错题收录/学情更新/订正触发/激励的唯一扇出源（权威：《端到端流程设计-学生作业接收完成提交与反馈闭环完整链路》）。

错题服务等下游仅订阅 `homework.graded`，避免双事件重复收录；幂等以 (studentId, assignmentId, gradedAt) 兜底。

## 15. 验收场景

1. 教师注册提交认证 → 审核通过 → 建班能力解锁；快速体验教师建班第 3 个被 50303 拦截并引导认证（G12）。
2. 邀请码加入：正确码 → 待审核 → 审批通过 → 进行中作业自动补发（class.student.approved 消费验证）。
3. 错误码路径：无效码 50101 / 班级停用 50102 / 满员 50103 / 重复加入 50104 / 猜码限流 50100。
4. 被拒学生重新申请成功；学生退出后再次加入成功（§14.2 函数唯一索引验证，不撞键）。
5. 草稿可编辑可删除；已发布作业编辑被拒 50300、删除被拒 50302（G1）。
6. 定时发布到点自动发布；到达 deadline 自动置已截止；限时作业超时自动提交（submit_method=2）。
7. 客观题自动判分；主观题 AI 初评置信度 < 0.8 转人工复核（needs_manual_review=1）。
8. 助教批改后学生不可见，科任教师复核确认后可见（G4）。
9. 批改完成 → 错题自动收录且仅一次（错题服务只消费 homework.graded，§14.4）。
10. 班级看板不出现排名；个体百分位仅 band 区间（§12.1）。
11. 科任教师访问个体学情仅返回本学科维度；跨班访问返回 404（§7.2）。
12. 通知家长通道投递、未绑定家长的班级返回 skipped_parent_count；回执统计与未确认名单正确。
13. 一键提醒频控：每通知每用户 24h 内第二次被拒。
14. 紧急通知第 3 次/日被 50604 拦截（G11）；发布超 24h 撤回被 50603 拦截（G10）。
15. 归档时存在进行中作业被 50605 拦截（G5）；结算后归档成功，历史只读。
16. 学情引擎宕机 → 返回快照 + 「数据延迟」标识；快照超 48h 退化为基础统计（D2）。
17. 批量审批部分失败：逐条返回结果，成功条目不回滚（D8/G9）。
18. 教师查看学生手机号默认脱敏；明文查看触发审计日志（§7.2/§12.3）。
