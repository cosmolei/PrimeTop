# 服务端 - 多源学习任务统一调度与优先级仲裁引擎 详细设计

> **文档版本**: v1.0  
> **创建日期**: 2026-06-15  
> **所属模块**: 学习规划 / 首页工作台  
> **优先级**: P1  

---

## 1. 概述

### 1.1 设计目标

学生在使用 PrimeTop 过程中，会同时面对来自多个子系统产生的学习任务：

| 任务来源 | 产出方 | 典型示例 |
|----------|--------|----------|
| 学习规划系统 | 每日计划引擎 | "复习数学第三章 - 函数" |
| 教师作业 | 教师端发布 | "完成数学练习册 P45-46" |
| 错题复习 | 间隔重复算法 | "复习 12 道错题（今日到期）" |
| 薄弱点补强 | 诊断测评引擎 | "强化训练：二次函数图像变换" |
| 考试冲刺 | 备考计划引擎 | "刷 10 道高频考点选择题" |
| 家长任务 | 家长中心 | "完成 30 分钟英语阅读" |
| 系统推荐 | 个性化推荐 | "推荐阅读：物理受力分析专题" |

**多源学习任务统一调度与优先级仲裁引擎**（以下简称"任务调度引擎"或"引擎"）负责：

1. **聚合**：从所有任务源实时收集待执行任务
2. **去重合并**：检测内容重叠的任务并智能合并
3. **优先级仲裁**：根据截止时间、来源权重、认知负荷等维度排序
4. **认知负荷控制**：控制每日总任务量在合理范围内
5. **统一输出**：生成结构化的"今日优先队列"供客户端渲染

### 1.2 设计原则

- **来源解耦**：各任务源独立生产任务，通过标准接口投递，互不依赖
- **实时响应**：任务队列在新增、完成、取消时近实时更新
- **学生友好**：优先呈现最紧急、最重要的任务，避免任务过载焦虑
- **可解释性**：每个任务的优先级理由可追溯、可解释
- **渐进增强**：MVP 阶段支持基本聚合排序，后续迭代增加智能合并与负荷控制

### 1.3 与现有模块的关系

| 模块 | 关系 |
|------|------|
| 每日任务智能生成服务 | **上游**：产生学习计划任务，投递到调度引擎 |
| 学习计划动态调整服务 | **上游**：计划变更时通知调度引擎重新排程 |
| 间隔重复算法引擎 | **上游**：每日生成的错题复习任务投递到调度引擎 |
| 教师班级管理与作业发布服务 | **上游**：教师发布作业时投递到调度引擎 |
| 家长中心 | **上游**：家长设置任务时投递到调度引擎 |
| 学科能力诊断测评引擎 | **上游**：诊断后生成补强任务投递到调度引擎 |
| 首页内容卡片推荐服务 | **下游**：消费调度引擎输出的统一任务队列 |
| 学习场景意图识别引擎 | **协同**：根据学生当前意图动态调整任务推荐 |

### 2.2 核心组件

| 组件 | 职责 | 实现 |
|------|------|------|
| Task Ingestion API | 接收各源任务投递，校验格式 | REST API + MQ Consumer |
| Task Aggregator | 聚合指定时间范围内的全部待执行任务 | 定时计算 + 实时增量 |
| Task Merger | 检测重叠/相似任务并智能合并 | 规则引擎 + 知识点匹配 |
| Priority Arbiter | 多维度评分排序 | 加权评分模型 |
| Cognitive Load Balancer | 控制总量、学科分布、难度梯度 | 负荷模型 + 约束优化 |
| Unified Task Queue | 存储并维护统一任务队列 | Redis ZSet + RDB 持久 |
| Task Query API | 对外提供任务查询接口 | REST API + SSE 推送 |

## 3. 数据结构设计

### 3.1 任务源注册表 `task_source_registry`

记录所有合法的任务来源及其配置。

```sql
CREATE TABLE task_source_registry (
    source_id          VARCHAR(32)   PRIMARY KEY,          -- 任务来源唯一标识
    source_name        VARCHAR(64)   NOT NULL,             -- 来源名称
    source_type        VARCHAR(32)   NOT NULL,             -- STUDY_PLAN / HOMEWORK / ERROR_REVIEW / WEAKNESS / EXAM_PREP / PARENT / SYSTEM_RECOMMEND
    base_priority      SMALLINT      NOT NULL DEFAULT 50,  -- 基础优先级权重 (1-100)
    can_be_merged      BOOLEAN       NOT NULL DEFAULT TRUE,-- 该来源的任务是否允许被合并
    can_be_deferred    BOOLEAN       NOT NULL DEFAULT TRUE,-- 是否允许推迟
    max_daily_count    INT           DEFAULT 10,           -- 每日最大产出任务数
    max_daily_minutes  INT           DEFAULT 120,          -- 每日最大预估总时长（分钟）
    cooldown_minutes   INT           DEFAULT 0,            -- 连续投递冷却时间
    is_active          BOOLEAN       NOT NULL DEFAULT TRUE,
    created_at         TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    updated_at         TIMESTAMPTZ   NOT NULL DEFAULT NOW()
);

### 3.2 原始任务表 `unified_task`

存储从所有来源投递的原始任务。

```sql
CREATE TABLE unified_task (
    task_id            BIGSERIAL     PRIMARY KEY,
    uuid               UUID          NOT NULL UNIQUE DEFAULT gen_random_uuid(),
    user_id            BIGINT        NOT NULL,                -- 归属学生ID
    source_id          VARCHAR(32)   NOT NULL,                -- 任务来源ID（FK → task_source_registry）
    external_ref       VARCHAR(128),                          -- 来源系统的外部引用ID（如作业ID、计划ID等）
    
    -- 任务基本信息
    title              VARCHAR(200)  NOT NULL,                -- 任务标题
    description        TEXT,                                  -- 任务描述
    task_type          VARCHAR(32)   NOT NULL,                -- PRACTICE / REVIEW / READ / WATCH / WRITE / QUIZ / CUSTOM
    subject_code       VARCHAR(16),                           -- 学科代码（MATH / CHINESE / ENGLISH / ...）
    chapter_ids        BIGINT[],                              -- 关联章节ID列表
    knowledge_point_ids BIGINT[],                             -- 关联知识点ID列表
    
    -- 时间属性
    suggested_start    TIMESTAMPTZ,                           -- 建议开始时间
    suggested_end      TIMESTAMPTZ,                           -- 建议结束时间
    deadline           TIMESTAMPTZ,                           -- 截止时间（如果有）
    estimated_minutes  INT           NOT NULL DEFAULT 30,     -- 预估耗时（分钟）
    
    -- 难度与认知负荷
    difficulty_level   SMALLINT      NOT NULL DEFAULT 3,      -- 难度等级 1-5
    cognitive_load     SMALLINT      NOT NULL DEFAULT 3,      -- 认知负荷 1-5（不完全等同于难度）
    
    -- 状态
    status             VARCHAR(20)   NOT NULL DEFAULT 'PENDING', -- PENDING / ACTIVE / COMPLETED / SKIPPED / EXPIRED / MERGED
    merged_into_task_id BIGINT,                               -- 如果被合并，指向合并后的任务ID
    
    -- 优先级计算缓存
    priority_score     DECIMAL(6,2),                          -- 最终优先级得分（由仲裁器计算）
    priority_reason    JSONB,                                 -- 优先级得分明细
    
    -- 关联资源
    resource_url       VARCHAR(512),                          -- 任务关联资源URL
    metadata           JSONB,                                 -- 扩展元数据
    
    created_at         TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    updated_at         TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    completed_at       TIMESTAMPTZ,
    
    CONSTRAINT chk_status CHECK (status IN ('PENDING', 'ACTIVE', 'COMPLETED', 'SKIPPED', 'EXPIRED', 'MERGED')),
    CONSTRAINT chk_difficulty CHECK (difficulty_level BETWEEN 1 AND 5),
    CONSTRAINT chk_cognitive_load CHECK (cognitive_load BETWEEN 1 AND 5)
);

-- 核心索引
CREATE INDEX idx_unified_task_user_date ON unified_task (user_id, suggested_start, status);
CREATE INDEX idx_unified_task_user_status ON unified_task (user_id, status, deadline);
CREATE INDEX idx_unified_task_source_ref ON unified_task (source_id, external_ref);
CREATE INDEX idx_unified_task_kp ON unified_task USING GIN (knowledge_point_ids);
CREATE INDEX idx_unified_task_priority ON unified_task (user_id, priority_score DESC) WHERE status = 'PENDING';
```

### 3.3 任务合并记录表 `task_merge_log`

记录任务合并操作，用于审计和撤销。

```sql
CREATE TABLE task_merge_log (
    id                 BIGSERIAL     PRIMARY KEY,
    merged_task_id     BIGINT        NOT NULL,   -- 合并后的目标任务ID
    source_task_id     BIGINT        NOT NULL,   -- 被合并的源任务ID
    merge_strategy     VARCHAR(32)   NOT NULL,   -- DEDUPLICATE / COMBINE / SUPerset
    merge_reason       VARCHAR(256),
    merge_confidence   DECIMAL(3,2),              -- 合并置信度 0.00-1.00
    created_at         TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    
    CONSTRAINT fk_merged FOREIGN KEY (merged_task_id) REFERENCES unified_task(task_id),
    CONSTRAINT fk_source FOREIGN KEY (source_task_id) REFERENCES unified_task(task_id)
);

CREATE INDEX idx_merge_log_merged ON task_merge_log (merged_task_id);
```

### 3.4 每日任务快照表 `daily_task_snapshot`

记录每天的最终调度结果，用于趋势分析和历史回溯。

```sql
CREATE TABLE daily_task_snapshot (
    id                 BIGSERIAL     PRIMARY KEY,
    user_id            BIGINT        NOT NULL,
    snapshot_date      DATE          NOT NULL,
    task_ids           BIGINT[]      NOT NULL,              -- 当日最终排定的任务ID有序列表
    total_count        INT           NOT NULL,
    total_minutes      INT           NOT NULL,
    avg_difficulty     DECIMAL(3,2),
    subject_distribution JSONB,                             -- {"MATH": 3, "ENGLISH": 2, ...}
    created_at         TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    
    UNIQUE (user_id, snapshot_date)
);
```

### 3.5 任务状态枚举与流转

```
                        ┌──────────┐
        投递任务 ──→     │ PENDING  │
                        └────┬─────┘
                             │
               ┌─────────────┼─────────────┐
               │             │              │
               ▼             ▼              ▼
        ┌──────────┐  ┌──────────┐  ┌──────────┐
        │ ACTIVE   │  │ MERGED   │  │ EXPIRED  │
        │(学生开始) │  │(被合并)   │  │(过期)    │
        └────┬─────┘  └──────────┘  └──────────┘
             │
      ┌──────┴──────┐
      │             │
      ▼             ▼
┌──────────┐  ┌──────────┐
│COMPLETED │  │ SKIPPED  │
│(完成)     │  │(跳过)    │
└──────────┘  └──────────┘
```

| 状态 | 含义 | 触发条件 |
|------|------|----------|
| `PENDING` | 待执行 | 任务投递后初始状态 |
| `ACTIVE` | 进行中 | 学生点击"开始"或客户端上报开始信号 |
| `COMPLETED` | 已完成 | 学生完成任务，或外部系统回报完成 |
| `SKIPPED` | 已跳过 | 学生主动跳过、或被负荷控制裁剪 |
| `EXPIRED` | 已过期 | 超过 deadline 且未被完成 |
| `MERGED` | 已合并 | 被去重合并器合并到另一个任务中 |

## 6. 核心算法设计

### 6.1 任务聚合器（Task Aggregator）

#### 6.1.1 触发时机

| 触发方式 | 场景 | 延迟 |
|----------|------|------|
| 定时触发 | 每日凌晨 6:00 生成当日任务队列 | 批量计算 |
| 增量触发 | 新任务投递时 | ≤ 2秒 |
| 事件触发 | 任务完成/跳过/过期时重排 | ≤ 2秒 |
| 手动触发 | 学生刷新首页 | 即时 |

#### 6.1.2 聚合逻辑

```java
/**
 * 聚合指定用户指定日期的所有待执行任务
 */
public List<UnifiedTask> aggregateTasks(Long userId, LocalDate date) {
    // 1. 查询时间范围内的所有 PENDING 任务
    LocalDateTime dayStart = date.atStartOfDay();
    LocalDateTime dayEnd = date.plusDays(1).atStartOfDay();
    
    List<UnifiedTask> tasks = unifiedTaskMapper.selectByUserAndDateRange(
        userId, 
        dayStart, 
        dayEnd,
        List.of("PENDING", "ACTIVE")
    );
    
    // 2. 拉取逾期任务（status=PENDING 且 deadline < now）
    List<UnifiedTask> overdueTasks = unifiedTaskMapper.selectOverdueTasks(userId, date);
    
    // 3. 合并去重
    tasks.addAll(overdueTasks);
    
    // 4. 过滤已合并任务
    tasks = tasks.stream()
        .filter(t -> !"MERGED".equals(t.getStatus()))
        .collect(Collectors.toList());
    
    return tasks;
}
```

### 6.2 去重合并器（Task Merger）

#### 6.2.1 合并规则

当两个任务满足以下条件之一时，触发合并评估：

| 规则 | 条件 | 合并策略 |
|------|------|----------|
| **完全重复** | 同用户 + 同 `externalRef` + 同 `sourceId` | 保留最新一条，旧标记 `MERGED` |
| **知识点重叠** | 同用户 + 同学科 + `knowledgePoint_ids` 交集 ≥ 60% | 合并为一个"综合学习"任务 |
| **章节重叠** | 同用户 + 同学科 + `chapter_ids` 交集 ≥ 70% | 合并为章节级任务 |
| **错题+薄弱点重叠** | `ERROR_REVIEW` 与 `WEAKNESS_FIX` 指向相同知识点 | 合并为"错题强化"任务 |

#### 6.2.2 合并实现

```java
/**
 * 检测并合并重复/重叠任务
 * @return 合并后的任务列表 + 合并记录
 */
public MergeResult mergeTasks(List<UnifiedTask> tasks, Long userId) {
    List<TaskMergeRecord> mergeLogs = new ArrayList<>();
    Set<Long> mergedIds = new HashSet<>();
    
    // 按学科分组，同学科内检测重叠
    Map<String, List<UnifiedTask>> bySubject = tasks.stream()
        .filter(t -> t.getSubjectCode() != null)
        .collect(Collectors.groupingBy(UnifiedTask::getSubjectCode));
    
    for (Map.Entry<String, List<UnifiedTask>> entry : bySubject.entrySet()) {
        List<UnifiedTask> subjectTasks = entry.getValue();
        
        for (int i = 0; i < subjectTasks.size(); i++) {
            UnifiedTask t1 = subjectTasks.get(i);
            if (mergedIds.contains(t1.getTaskId())) continue;
            
            for (int j = i + 1; j < subjectTasks.size(); j++) {
                UnifiedTask t2 = subjectTasks.get(j);
                if (mergedIds.contains(t2.getTaskId())) continue;
                
                MergeDecision decision = evaluateMerge(t1, t2);
                if (decision.shouldMerge()) {
                    UnifiedTask merged = performMerge(t1, t2, decision);
                    mergedIds.add(decision.getAbsorbedTaskId());
                    mergeLogs.add(new TaskMergeRecord(
                        merged.getTaskId(),
                        decision.getAbsorbedTaskId(),
                        decision.getStrategy(),
                        decision.getReason(),
                        decision.getConfidence()
                    ));
                }
            }
        }
    }
    
    // 过滤掉被合并的任务
    List<UnifiedTask> result = tasks.stream()
        .filter(t -> !mergedIds.contains(t.getTaskId()))
        .collect(Collectors.toList());
    
    return new MergeResult(result, mergeLogs);
}

/**
 * 评估两个任务是否应该合并
 */
private MergeDecision evaluateMerge(UnifiedTask t1, UnifiedTask t2) {
    // 规则1: 完全重复（同来源同外部引用）
    if (Objects.equals(t1.getSourceId(), t2.getSourceId()) 
        && Objects.equals(t1.getExternalRef(), t2.getExternalRef())) {
        return MergeDecision.merge(t1.getTaskId(), t2.getTaskId(), 
            "DEDUPLICATE", "相同来源重复投递", 1.00);
    }
    
    // 规则2: 知识点重叠
    double kpOverlap = calculateSetOverlap(
        t1.getKnowledgePointIds(), 
        t2.getKnowledgePointIds()
    );
    if (kpOverlap >= 0.6) {
        // 保留优先级更高的任务作为主任务
        Long primaryId = comparePriority(t1, t2) >= 0 ? t1.getTaskId() : t2.getTaskId();
        Long absorbedId = primaryId.equals(t1.getTaskId()) ? t2.getTaskId() : t1.getTaskId();
        return MergeDecision.merge(primaryId, absorbedId,
            "COMBINE", 
            String.format("知识点重叠率 %.0f%%，合并为综合学习任务", kpOverlap * 100),
            kpOverlap);
    }
    
    // 规则3: 特殊规则 - 错题复习 + 薄弱点补强
    if ("ERROR_REVIEW".equals(t1.getSourceId()) && "WEAKNESS_FIX".equals(t2.getSourceId())
        && hasCommonKnowledgePoints(t1, t2)) {
        return MergeDecision.merge(t1.getTaskId(), t2.getTaskId(),
            "SUPERSET", "错题复习与薄弱点补强指向相同知识点，合并为强化训练",
            0.85);
    }
    
    return MergeDecision.noMerge();
}
```

### 6.3 优先级仲裁器（Priority Arbiter）

#### 6.3.1 评分模型

每个任务的最终优先级得分由以下因素加权计算：

```
finalScore = basePriority
           + deadlineBonus
           + overdueBonus
           + subjectBalanceAdjust
           + userPreferenceBonus
           - cognitiveLoadPenalty
           - redundancyPenalty
```

| 因子 | 公式 | 说明 |
|------|------|------|
| `basePriority` | 任务来源的基础权重 (1-100) | 见 `task_source_registry.base_priority` |
| `deadlineBonus` | `min(30, max(0, 30 × (1 - hoursUntilDeadline / 24)))` | 越接近截止时间加成越高，24h内最高+30 |
| `overdueBonus` | `min(20, overdueDays × 5)` | 逾期任务每天+5，最多+20 |
| `subjectBalanceAdjust` | 见 6.3.2 学科平衡策略 | 避免某一学科任务过多 |
| `userPreferenceBonus` | 学生偏好学科 +5，弱势学科 +3 | 根据学情画像动态调整 |
| `cognitiveLoadPenalty` | 连续高负荷任务的惩罚项 | 见 6.3.3 认知负荷控制 |
| `redundancyPenalty` | 与已完成任务的内容重叠惩罚 | 避免重复学习 |

#### 6.3.2 学科平衡策略

```java
/**
 * 计算学科平衡调整分
 * 目标：避免队列中某一学科任务占比过高
 */
private double calculateSubjectBalanceAdjust(
    UnifiedTask task, 
    List<UnifiedTask> allTasks,
    UserLearningProfile profile
) {
    String subject = task.getSubjectCode();
    if (subject == null) return 0;
    
    // 统计当前队列中各学科任务数
    Map<String, Long> subjectCounts = allTasks.stream()
        .filter(t -> t.getSubjectCode() != null)
        .collect(Collectors.groupingBy(
            UnifiedTask::getSubjectCode, 
            Collectors.counting()
        ));
    
    long totalTasks = allTasks.size();
    long subjectCount = subjectCounts.getOrDefault(subject, 0L);
    double subjectRatio = (double) subjectCount / totalTasks;
    
    // 如果该学科占比已超过 50%，降低优先级
    if (subjectRatio > 0.5) {
        return -8.0;
    } else if (subjectRatio > 0.4) {
        return -4.0;
    }
    
    // 如果学生该学科较弱，适当提高
    Double masteryLevel = profile.getSubjectMastery(subject);
    if (masteryLevel != null && masteryLevel < 0.5) {
        return +5.0;  // 弱势学科加成
    }
    
    return 0;
}
```

#### 6.3.3 认知负荷控制（Cognitive Load Balancer）

```java
/**
 * 控制每日认知负荷总量，避免任务过载
 */
public List<UnifiedTask> balanceCognitiveLoad(
    List<UnifiedTask> rankedTasks, 
    Long userId,
    UserPreference preference
) {
    // 1. 获取用户每日最大学习时长偏好
    int maxDailyMinutes = preference.getMaxDailyStudyMinutes(); // 默认 180
    
    // 2. 获取已完成的今日学习时长
    int completedMinutes = taskService.getTodayCompletedMinutes(userId);
    
    // 3. 计算可用时长
    int availableMinutes = maxDailyMinutes - completedMinutes;
    
    // 4. 贪心填充：按优先级从高到低，填充直到达到时长上限
    List<UnifiedTask> result = new ArrayList<>();
    int accumulatedMinutes = 0;
    int consecutiveHighLoadCount = 0;
    
    for (UnifiedTask task : rankedTasks) {
        if (accumulatedMinutes + task.getEstimatedMinutes() <= availableMinutes) {
            // 检查连续高认知负荷任务限制
            if (task.getCognitiveLoad() >= 4) {
                if (consecutiveHighLoadCount >= 2) {
                    // 插入一个低负荷任务作为缓冲
                    UnifiedTask buffer = findLowLoadTask(rankedTasks, result);
                    if (buffer != null) {
                        result.add(buffer);
                        accumulatedMinutes += buffer.getEstimatedMinutes();
                    }
                    consecutiveHighLoadCount = 0;
                }
                consecutiveHighLoadCount++;
            } else {
                consecutiveHighLoadCount = 0;
            }
            
            result.add(task);
            accumulatedMinutes += task.getEstimatedMinutes();
        } else if (result.isEmpty()) {
            // 至少保留第一个任务（即使超时）
            result.add(task);
            accumulatedMinutes += task.getEstimatedMinutes();
        } else {
            // 剩余任务标记为推迟
            task.setSkipReason("COGNITIVE_LOAD_LIMIT");
            log.info("任务 {} 因认知负荷限制被推迟到明日", task.getTaskId());
        }
    }
    
    return result;
}
```

#### 6.3.4 完整仲裁流程

```java
/**
 * 完整的优先级仲裁流程
 */
public SchedulingResult schedule(Long userId, LocalDate date) {
    // Step 1: 聚合任务
    List<UnifiedTask> tasks = aggregator.aggregateTasks(userId, date);
    
    if (tasks.isEmpty()) {
        return SchedulingResult.empty();
    }
    
    // Step 2: 去重合并
    MergeResult mergeResult = merger.mergeTasks(tasks, userId);
    List<UnifiedTask> mergedTasks = mergeResult.getTasks();
    
    // Step 3: 加载用户画像
    UserLearningProfile profile = profileService.getProfile(userId);
    UserPreference preference = preferenceService.getPreference(userId);
    
    // Step 4: 计算每个任务的优先级得分
    for (UnifiedTask task : mergedTasks) {
        double score = calculatePriorityScore(task, mergedTasks, profile);
        task.setPriorityScore(BigDecimal.valueOf(score));
    }
    
    // Step 5: 按优先级排序
    mergedTasks.sort(Comparator.comparing(UnifiedTask::getPriorityScore).reversed());
    
    // Step 6: 认知负荷控制
    List<UnifiedTask> finalTasks = balancer.balanceCognitiveLoad(mergedTasks, userId, preference);
    
    // Step 7: 持久化结果
    persistSchedulingResult(userId, date, finalTasks, mergeResult);
    
    // Step 8: 发布 SSE 通知
    eventPublisher.publishEvent(new TaskQueueUpdatedEvent(userId, date, finalTasks));
    
    return new SchedulingResult(finalTasks, mergeResult);
}
```

### 6.4 优先级得分计算完整实现

```java
/**
 * 计算单个任务的最终优先级得分
 */
private double calculatePriorityScore(
    UnifiedTask task, 
    List<UnifiedTask> allTasks,
    UserLearningProfile profile
) {
    PriorityReason.PriorityReasonBuilder reasonBuilder = PriorityReason.builder();
    
    // 1. 基础优先级
    TaskSourceRegistry sourceReg = sourceRegistryCache.get(task.getSourceId());
    double base = sourceReg.getBasePriority();
    reasonBuilder.basePriority(base);
    
    // 2. 截止时间加成
    double deadlineBonus = 0;
    if (task.getDeadline() != null) {
        long hoursUntilDeadline = Duration.between(
            LocalDateTime.now(), 
            task.getDeadline().toLocalDateTime()
        ).toHours();
        
        if (hoursUntilDeadline <= 0) {
            // 已逾期
            long overdueDays = Math.abs(hoursUntilDeadline) / 24;
            deadlineBonus = 30;
            deadlineBonus += Math.min(20, overdueDays * 5);
        } else if (hoursUntilDeadline <= 24) {
            deadlineBonus = 30 * (1 - hoursUntilDeadline / 24.0);
        }
    }
    reasonBuilder.deadlineBonus(deadlineBonus);
    
    // 3. 学科平衡调整
    double subjectAdjust = calculateSubjectBalanceAdjust(task, allTasks, profile);
    reasonBuilder.subjectBalanceAdjust(subjectAdjust);
    
    // 4. 用户偏好加成
    double preferenceBonus = calculateUserPreferenceBonus(task, profile);
    reasonBuilder.userPreferenceBonus(preferenceBonus);
    
    // 5. 认知负荷惩罚
    double loadPenalty = calculateCognitiveLoadPenalty(task, allTasks);
    reasonBuilder.cognitiveLoadPenalty(loadPenalty);
    
    // 6. 冗余惩罚（与已
