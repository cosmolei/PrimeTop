# 接口幂等性与防重提交机制 - 详细设计

## 1. 概述

### 1.1 问题背景

在移动端弱网、用户快速重复点击、网络超时重试、服务端重试等场景下，同一请求可能被多次发送到服务端。若接口不具备幂等性，将导致：

- 重复扣费、重复下单
- AI 模型重复调用（成本浪费）
- 错题重复收录
- 学习记录重复写入
- 练习答案重复提交
- 重复注册/发送验证码

### 1.2 设计目标

1. **业务幂等**：同一业务操作无论执行多少次，结果与执行一次相同
2. **防重提交**：客户端与服务端双重防护，避免重复请求到达业务层
3. **透明集成**：通过中间件/装饰器模式，业务代码最小化改动
4. **可配置**：不同接口可配置不同的幂等策略和过期时间
5. **高可用**：幂等检查失败不应阻塞正常业务（降级策略）

### 1.3 适用范围

| 模块 | 关键幂等接口 | 幂等类型 |
|------|-------------|----------|
| 支付 | 创建订单、支付回调 | 强幂等 |
| AI 辅导 | 发起对话、生成解析 | 弱幂等（允许短时重复） |
| 拍题答疑 | 提交识别、收藏错题 | 强幂等 |
| 错题整理 | 收录错题、提交订正 | 强幂等 |
| 练习测评 | 提交答案、完成练习 | 强幂等 |
| 用户账号 | 注册、发送验证码、绑定手机 | 强幂等 |
| 学习记录 | 上报学习行为、同步进度 | 最终一致 |
| 收藏笔记 | 收藏/取消收藏 | 强幂等 |
| 评价反馈 | 点赞/点踩、提交反馈 | 强幂等 |
| 作文辅导 | 提交作文批改 | 弱幂等 |

## 2. 幂等策略模型

### 2.1 幂等级别定义

```python
class IdempotencyLevel(str, Enum):
    """幂等级别"""
    STRONG = "strong"       # 强幂等：绝对不允许重复执行（支付、订单）
    WEAK = "weak"           # 弱幂等：短时间内不重复执行（AI调用），可配置窗口期
    EVENTUAL = "eventual"   # 最终一致：允许短时重复，但最终结果一致（学习记录上报）
    NONE = "none"           # 不需要幂等（纯查询接口）
```

### 2.2 幂等策略配置

```python
@dataclass
class IdempotencyPolicy:
    """幂等策略配置"""
    level: IdempotencyLevel
    ttl_seconds: int                # 幂等键过期时间
    key_template: str               # 幂等键模板，支持变量：{user_id}, {device_id}, {body_hash} 等
    cache_result: bool = True       # 是否缓存首次执行结果
    on_duplicate: str = "reject"    # reject: 返回错误 | return_cached: 返回缓存结果 | dedupe: 静默去重
    max_retry_after_ms: int = 0     # 窗口期后允许重新执行（仅 WEAK 级别）
```

## 3. 数据结构设计

### 3.1 幂等记录表（MySQL）

```sql
CREATE TABLE idempotency_records (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    idempotency_key VARCHAR(255)    NOT NULL COMMENT '幂等键，由策略模板生成',
    user_id         BIGINT UNSIGNED NOT NULL COMMENT '用户ID，用于分区和清理',
    service_name    VARCHAR(64)     NOT NULL COMMENT '服务/模块名',
    policy_name     VARCHAR(128)    NOT NULL COMMENT '策略名（如 payment:create_order）',
    request_hash    VARCHAR(64)     DEFAULT NULL COMMENT '请求体 SHA-256 摘要',
    status          TINYINT         NOT NULL DEFAULT 0 COMMENT '0=处理中, 1=成功, 2=失败',
    response_data   JSON            DEFAULT NULL COMMENT '缓存的响应数据（可选）',
    created_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    expires_at      DATETIME(3)     NOT NULL COMMENT '过期时间',
    
    UNIQUE KEY uk_idempotency_key (idempotency_key),
    INDEX idx_user_expires (user_id, expires_at),
    INDEX idx_expires (expires_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='接口幂等记录表';
```

/// Flutter 端：请求幂等上下文
class IdempotencyContext {
  /// 客户端生成的唯一请求 ID（UUID v7）
  final String requestId;
  
  /// 请求时间戳（毫秒）
  final int timestamp;
  
  /// 请求体哈希（用于服务端校验）
  final String? bodyHash;
  
  /// 重试次数
  final int retryCount;
  
  IdempotencyContext({
    String? requestId,
    this.timestamp = 0,
    this.bodyHash,
    this.retryCount = 0,
  }) : requestId = requestId ?? _generateRequestId();
  
  static String _generateRequestId() {
    // UUID v7: 时间有序 + 随机后缀
    final ts = DateTime.now().millisecondsSinceEpoch;
    final random = List.generate(8, (_) => 
      Random().nextInt(16).toRadixString(16)).join();
    return '${ts.toRadixString(16)}-$random';
  }
  
  Map<String, String> toHeaders() => {
    'X-Request-Id': requestId,
    'X-Request-Ts': timestamp.toString(),
    if (bodyHash != null) 'X-Body-Hash': bodyHash!,
    if (retryCount > 0) 'X-Retry-Count': retryCount.toString(),
  };
}

## 4. 服务端幂等中间件

### 4.1 核心流程

```
请求到达
  │
  ├─ 1. 提取/生成幂等键
  │     └─ 从策略模板 + 请求参数生成
  │
  ├─ 2. 检查 Redis 缓存（快速路径）
  │     ├─ 命中 + status=1 → 直接返回缓存响应
  │     ├─ 命中 + status=0 → 正在处理中 → 短暂等待/返回 202
  │     └─ 未命中 → 继续
  │
  ├─ 3. Redis SETNX 抢占（防并发）
  │     ├─ 抢占成功 → 标记 status=0（处理中），执行业务
  │     └─ 抢占失败 → 再次检查（可能其他节点已处理）
  │
  ├─ 4. 执行业务逻辑
  │     ├─ 成功 → 更新 status=1，缓存响应，写入 MySQL
  │     └─ 失败 → 更新 status=2，清理 Redis 锁
  │
  └─ 5. 返回响应
```

### 4.2 FastAPI 中间件实现

```python
import json
import hashlib
import uuid
from datetime import datetime, timedelta, timezone
from functools import wraps
from typing import Any, Callable, Optional

import redis
from fastapi import Request, Response
from fastapi.responses import JSONResponse
from pydantic import BaseModel


# ── 幂等错误码 ──
class IdempotencyError:
    DUPLICATE_REQUEST = ("IDEMP_001", "重复请求，该操作已执行")
    PROCESSING = ("IDEMP_002", "请求正在处理中，请稍后")
    KEY_CONFLICT = ("IDEMP_003", "幂等键冲突，请重试")
    SERVICE_DOWN = ("IDEMP_004", "幂等服务暂时不可用，已降级处理")


class IdempotencyService:
    """幂等性服务"""
    
    def __init__(self, redis_client: redis.Redis, db_session_factory):
        self.redis = redis_client
        self.db_session_factory = db_session_factory
    
    def _build_key(self, policy: IdempotencyPolicy, context: dict) -> str:
        """根据模板构建幂等键"""
        try:
            key = policy.key_template.format(**context)
            return f"idemp:{key}"
        except KeyError as e:
            raise ValueError(f"幂等键模板缺少变量: {e}")
    
    def _body_hash(self, body: bytes) -> str:
        """计算请求体 SHA-256 摘要"""
        return hashlib.sha256(body).hexdigest()
    
    async def check_and_acquire(
        self,
        policy_name: str,
        context: dict,
        request_body: bytes = b"",
    ) -> tuple[bool, Optional[dict], Optional[str]]:
        """
        检查幂等状态并尝试抢占。
        
        Returns:
            (should_proceed, cached_response, idempotency_key)
            - should_proceed=True: 业务应执行
            - should_proceed=False: cached_response 包含之前的结果
        """
        policy = IDEMPOTENCY_POLICIES.get(policy_name)
        if not policy:
            raise ValueError(f"未知的幂等策略: {policy_name}")
        
        # 幂等级别为 NONE 的直接放行
        if policy.level == IdempotencyLevel.NONE:
            return True, None, None
        
        idemp_key = self._build_key(policy, context)
        redis_key = f"idemp:{idemp_key}"
        lock_key = f"idemp_lock:{idemp_key}"
        now = datetime.now(timezone.utc)
        
        # ── Step 1: 检查 Redis 缓存 ──
        cached = self.redis.get(redis_key)
        if cached:
            data = json.loads(cached)
            status = data.get("status")
            
            if status == 1:
                # 已成功执行过
                if policy.on_duplicate == "return_cached":
                    return False, data.get("response"), idemp_key
                elif policy.on_duplicate == "reject":
                    return False, {"error": IdempotencyError.DUPLICATE_REQUEST}, idemp_key
                elif policy.on_duplicate == "dedupe":
                    # 静默去重，假装成功
                    return False, data.get("response"), idemp_key
            
            elif status == 0:
                # 正在处理中
                if policy.on_duplicate == "return_cached":
                    return False, {"status": "processing", "retry_after_ms": 1000}, idemp_key
                else:
                    return False, {"error": IdempotencyError.PROCESSING}, idemp_key
            
            elif status == 2:
                # 上次执行失败，允许重试
                pass  # fall through to acquire
        
        # ── Step 2: SETNX 抢占 ──
        lock_owner = str(uuid.uuid4())
        acquired = self.redis.set(
            lock_key, lock_owner,
            nx=True,
            ex=30,  # 30s 处理超时保护
        )
        
        if not acquired:
            # 其他节点正在处理
            return False, {"error": IdempotencyError.PROCESSING}, idemp_key
        
        # ── Step 3: 标记处理中 ──
        processing_data = {
            "status": 0,
            "policy": policy_name,
            "ts": now.isoformat(),
        }
        self.redis.set(
            redis_key,
            json.dumps(processing_data),
            ex=policy.ttl_seconds,
        )
        
        return True, None, idemp_key
    
    async def commit(
        self,
        idempotency_key: str,
        policy_name: str,
        success: bool,
        response_data: Optional[dict] = None,
        context: Optional[dict] = None,
    ):
        """提交幂等结果"""
        if not idempotency_key:
            return
        
        policy = IDEMPOTENCY_POLICIES[policy_name]
        redis_key = f"idemp:{idempotency_key}"
        lock_key = f"idemp_lock:{idemp_key}"
        status = 1 if success else 2
        
        # 更新 Redis 缓存
        cache_data = {
            "status": status,
            "ts": datetime.now(timezone.utc).isoformat(),
        }
        if success and policy.cache_result and response_data:
            cache_data["response"] = response_data
        
        self.redis.set(redis_key, json.dumps(cache_data), ex=policy.ttl_seconds)
        
        # 释放锁
        # 使用 Lua 脚本确保只释放自己持有的锁
        self.redis.eval(
            """if redis.call('get', KEYS[1]) == ARGV[1] then 
               return redis.call('del', KEYS[1]) 
               else return 0 end""",
            1, lock_key, "",  # owner check 在 acquire 时已处理
        )
        # 简化：直接删除锁
        self.redis.delete(lock_key)
        
        # 异步写入 MySQL（用于持久化和审计）
        if policy.level in (IdempotencyLevel.STRONG,):
            await self._persist_to_mysql(
                idempotency_key, policy_name, status, response_data, context
            )
    
    async def _persist_to_mysql(
        self,
        idempotency_key: str,
        policy_name: str,
        status: int,
        response_data: Optional[dict],
        context: Optional[dict],
    ):
        """持久化到 MySQL"""
        async with self.db_session_factory() as session:
            session.execute(
                """
                INSERT INTO idempotency_records 
                    (idempotency_key, user_id, service_name, policy_name, 
                     request_hash, status, response_data, expires_at)
                VALUES (:key, :uid, :svc, :policy, :hash, :status, :resp, :expires)
                ON DUPLICATE KEY UPDATE 
                    status = VALUES(status),
                    response_data = VALUES(response_data)
                """,
                {
                    "key": idempotency_key,
                    "uid": context.get("user_id", 0) if context else 0,
                    "svc": policy_name.split(":")[0],
                    "policy": policy_name,
                    "hash": context.get("body_hash") if context else None,
                    "status": status,
                    "resp": json.dumps(response_data) if response_data else None,
                    "expires": datetime.now(timezone.utc) + timedelta(
                        seconds=IDEMPOTENCY_POLICIES[policy_name].ttl_seconds
                    ),
                },
            )
            await session.commit()


# ── FastAPI 依赖注入装饰器 ──
def idempotent(policy_name: str, key_context_builder: Callable):
    """
    幂等装饰器。
    
    Usage:
        @idempotent("mistake:add", lambda req: {
            "user_id": req.state.user_id,
            "question_id": req.body.question_id,
            "source": req.body.source,
        })
        async def add_mistake(request: Request):
            ...
    """
    def decorator(func: Callable):
        @wraps(func)
        async def wrapper(request: Request, *args, **kwargs):
            idemp_service: IdempotencyService = request.app.state.idempotency_service
            
            # 构建上下文
            context = key_context_builder(request)
            
            # 读取请求体
            body = await request.body()
            if body:
                context["body_hash"] = hashlib.sha256(body).hexdigest()
            
            # 幂等检查
            should_proceed, cached_response, idemp_key = \
                await idemp_service.check_and_acquire(policy_name, context, body)
            
            if not should_proceed:
                # 返回缓存结果或错误
                if cached_response and "error" not in cached_response:
                    return JSONResponse(content=cached_response, status_code=200)
                elif cached_response and "error" in cached_response:
                    code, msg = cached_response["error"]
                    return JSONResponse(
                        content={"code": code, "message": msg},
                        status_code=409 if code == "IDEMP_001" else 202,
                    )
            
            # 执行业务
            try:
                result = await func(request, *args, **kwargs)
                response_data = result.body.decode() if isinstance(result, Response) else result
                if isinstance(response_data, dict):
                    pass
                elif hasattr(response_data, 'body'):
                    response_data = json.loads(response_data.body)
                else:
                    response_data = {"data": str(response_data)}
                
                await idemp_service.commit(
                    idemp_key, policy_name, True, response_data, context
                )
                return result
                
            except Exception as e:
                await idemp_service.commit(
                    idemp_key, policy_name, False, None, context
                )
                raise
        
        return wrapper
    return decorator
```

## 5. 客户端防重机制

### 5.1 双重防护架构

```
用户操作
  │
  ├─ 1. UI 层防抖（按钮 disabled、loading 状态）
  │
  ├─ 2. 网络层自动重试 + 幂等头注入
  │     ├─ 自动附加 X-Request-Id
  │     ├─ 失败自动重试（最多 3 次）
  │     └─ 服务端 409 → 不重试，直接返回
  │
  └─ 3. 服务端幂等中间件检查
```

### 5.2 Flutter Dio 拦截器

```dart
import 'dart:convert';
import 'package:crypto/crypto.dart';
import 'package:dio/dio.dart';

/// 幂等请求拦截器
class IdempotencyInterceptor extends Interceptor {
  
  /// 需要幂等保护的 HTTP 方法
  static const _idempotentMethods = {'POST', 'PUT', 'PATCH'};
  
  /// 正在进行中的请求（本地去重）
  final Map<String, Completer<Response>> _inflightRequests = {};
  
  @override
  void onRequest(RequestOptions options, RequestInterceptorHandler handler) {
    if (!_idempotentMethods.contains(options.method.toUpperCase())) {
      handler.next(options);
      return;
    }
    
    // 生成请求指纹（URL + 排序后的参数 + Body 摘要）
    final fingerprint = _buildFingerprint(options);
    
    // 检查是否有相同请求正在进行
    if (_inflightRequests.containsKey(fingerprint)) {
      // 等待已有请求完成，复用其结果
      _inflightRequests[fingerprint]!.future.then((response) {
        handler.resolve(response);
      }).catchError((error) {
        handler.reject(error as DioException);
      });
      return;
    }
    
    // 生成幂等请求头
    final requestId = _generateRequestId();
    final bodyHash = options.data != null
        ? sha256.convert(utf8.encode(jsonEncode(options.data))).toString().substring(0, 16)
        : null;
    
    options.headers['X-Request-Id'] = requestId;
    options.headers['X-Request-Ts'] = DateTime.now().millisecondsSinceEpoch.toString();
    if (bodyHash != null) {
      options.headers['X-Body-Hash'] = bodyHash;
    }
    
    // 注册 inflight 请求
    final completer = Completer<Response>();
    _inflightRequests[fingerprint] = completer;
    options.extra['idempotency_fingerprint'] = fingerprint;
    
    handler.next(options);
  }
  
  @override
  void onResponse(Response response, ResponseInterceptorHandler handler) {
    _completeInflight(response.requestOptions, response);
    handler.next(response);
  }
  
  @override
  void onError(DioException err, ErrorInterceptorHandler handler) {
    // 409 Conflict = 幂等拒绝 → 不重试
    if (err.response?.statusCode == 409) {
      _completeInflight(err.requestOptions, null, error: err);
      handler.next(err);
      return;
    }
    
    // 202 Accepted = 正在处理 → 轮询等待
    if (err.response?.statusCode == 202) {
      _handleProcessing(err.requestOptions, err.response!, handler);
      _completeInflight(err.requestOptions, null, error: err);
      return;
    }
    
    _completeInflight(err.requestOptions, null, error: err);
    handler.next(err);
  }
  
  void _completeInflight(
    RequestOptions options,
    Response? response, {
    DioException? error,
  }) {
    final fp = options.extra['idempotency_fingerprint'] as String?;
    if (fp == null) return;
    
    final completer = _inflightRequests.remove(fp);
    if (completer == null || completer.isCompleted) return;
    
    if (error != null) {
      completer.completeError(error);
    } else if (response != null) {
      completer.complete(response);
    }
  }
  
  String _buildFingerprint(RequestOptions options) {
    final buffer = StringBuffer();
    buffer.write(options.method);
    buffer.write(options.path);
    
    // 排序 query 参数
    final sortedParams = options.queryParameters.keys.toList()..sort();
    for (final key in sortedParams) {
      buffer.write('$key=${options.queryParameters[key]}');
    }
    
    // Body 摘要
    if (options.data != null) {
      buffer.write(sha256.convert(utf8.encode(jsonEncode(options.data))).toString().substring(0, 16));
    }
    
    return buffer.toString();
  }
  
  String _generateRequestId() {
    final ts = DateTime.now().millisecondsSinceEpoch;
    final random = List.generate(
      8, (_) => DateTime.now().microsecond.toRadixString(16).padLeft(2, '0')
    ).join();
    return '${ts.toRadixString(16)}-$random';
  }
  
  void _handleProcessing(
    RequestOptions options,
    Response response,
    ErrorInterceptorHandler handler,
  ) {
    // 对于 202 正在处理中的响应，客户端可以选择：
    // 1. 短暂等待后重试
    // 2. 直接返回 "正在处理中" 状态
    // 当前策略：直接透传给业务层处理
  }
}
```

### 6.1 SSE 流式响应的幂等

AI 对话使用 SSE 流式响应，无法简单缓存完整结果。策略：

```python
async def handle_idempotent_sse(policy_name: str, context: dict, stream_generator):
    """SSE 流式接口的幂等处理"""
    idemp_service = get_idempotency_service()
    
    should_proceed, cached, idemp_key = \
        await idemp_service.check_and_acquire(policy_name, context)
    
    if not should_proceed and cached:
        # 如果有缓存的完整响应，直接返回
        # （首次流式完成后，结果会写入缓存）
        return cached
    
    if not should_proceed:
        # 正在处理中 → 返回 409 或等待
        raise DuplicateRequestError()
    
    # 执行流式生成，同时在内存中累积完整响应
    chunks = []
    async for chunk in stream_generator:
        chunks.append(chunk)
        yield chunk  # 实时推送给客户端
    
    # 流式完成后，缓存完整响应
    full_response = "".join(chunks)
    await idemp_service.commit(
        idemp_key, policy_name, True,
        response_data={"content": full_response, "streamed": True},
        context=context,
    )
```

## 7. 降级策略

### 7.1 Redis 不可用时的降级

```python
class IdempotencyServiceWithFallback(IdempotencyService):
    """带降级的幂等服务"""
    
    async def check_and_acquire(self, policy_name, context, request_body=b""):
        policy = IDEMPOTENCY_POLICIES.get(policy_name)
        
        try:
            # 尝试 Redis 快速路径
            return await super().check_and_acquire(policy_name, context, request_body)
        except redis.RedisError as e:
            logger.warning(f"Redis 不可用，降级幂等检查: {e}")
            
            # ── 降级策略：按级别处理 ──
            if policy.level == IdempotencyLevel.NONE:
                return True, None, None
            
            if policy.level == IdempotencyLevel.EVENTUAL:
                # 最终一致：允许通过，MySQL 层面去重
                return True, None, None
            
            if policy.level == IdempotencyLevel.WEAK:
                # 弱幂等：降级为 MySQL 检查
                return await self._check_mysql_fallback(policy_name, context)
            
            if policy.level == IdempotencyLevel.STRONG:
                # 强幂等：必须 MySQL 检查
                return await self._check_mysql_fallback(policy_name, context)
            
            return True, None, None
    
    async def _check_mysql_fallback(self, policy_name, context):
        """MySQL 降级检查"""
        policy = IDEMPOTENCY_POLICIES[policy_name]
        idemp_key = self._build_key(policy, context)
        
        async with self.db_session_factory() as session:
            result = await session.execute(
                "SELECT status, response_data FROM idempotency_records "
                "WHERE idempotency_key = :key AND status = 1 AND expires_at > NOW()",
                {"key": idemp_key},
            )
            row = result.first()
            
            if row and row.status == 1:
                if policy.on_duplicate == "return_cached":
                    return False, json.loads(row.response_data) if row.response_data else None, idemp_key
                else:
                    return False, {"error": IdempotencyError.DUPLICATE_REQUEST}, idemp_key
        
        # MySQL 也没有 → 允许执行
        return True, None, idemp_key
```

## 10. API 接口规范

### 10.1 客户端请求头

| Header | 必选 | 说明 |
|--------|------|------|
| `X-Request-Id` | 是 | 客户端生成的唯一请求 ID（UUID v7 格式） |
| `X-Request-Ts` | 否 | 请求发起时间戳（毫秒），用于检测过期请求 |
| `X-Body-Hash` | 否 | 请求体 SHA-256 前 16 字符，服务端可选校验 |
| `X-Retry-Count` | 否 | 重试次数，0=首次请求 |

### 10.2 服务端响应

**正常首次请求：** `200 OK` + 业务响应

**重复请求（已处理完成）：**
```json
HTTP 200 OK（return_cached 策略）
或
HTTP 409 Conflict（reject 策略）
{
    "code": "IDEMP_001",
    "message": "重复请求，该操作已执行",
    "data": { ... }  // 可选：缓存的结果
}
```

**请求处理中：**
```json
HTTP 202 Accepted
{
    "code": "IDEMP_002",
    "message": "请求正在处理中",
    "retry_after_ms": 1000
}
```
