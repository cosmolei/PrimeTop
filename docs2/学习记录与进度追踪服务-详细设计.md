## 1. 模块概述

### 1.1 功能定位

学习记录与进度追踪服务（Learning Record & Progress Service，简称 LRPS）是 PrimeTop 的 **数据基础设施层**，负责统一管理学生的学习行为记录、章节学习进度、知识点掌握度快照和学习时长聚合。它是学情分析、首页工作台、学习规划、错题复习、同步课堂等多个上层模块的底层数据源。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 行为采集 | 统一接收各模块上报的学习行为事件，标准化存储 |
| 进度追踪 | 按章节、知识点、学科三个粒度追踪学习进度 |
| 时长统计 | 实时与离线双模式累积学习时长，支持日/周/月多维度聚合 |
| 掌握度评估 | 基于行为数据周期性计算知识点掌握度快照 |
| 事件分发 | 将关键进度变更事件通知给订阅方（学情、规划、推送等） |
| 离线同步 | 客户端离线期间产生的行为记录在上报后正确归集 |

## 2. 数据模型设计

### 2.1 学习行为日志表 `learning_activity_log`

所有学习行为的原始记录，是聚合计算的唯一数据源。

```sql
CREATE TABLE learning_activity_log (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '日志ID',
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    session_id      VARCHAR(64) COMMENT '学习会话ID，关联 learning_session',
    activity_type   VARCHAR(32) NOT NULL COMMENT '行为类型（见枚举表）',
    source_module   VARCHAR(32) NOT NULL COMMENT '来源模块: AI_TUTOR|PHOTO_SOLVE|SYNC_CLASS|PRACTICE|ESSAY|REVIEW|MEMORIZATION',

    -- 学科与知识定位
    subject_code    VARCHAR(16) COMMENT '学科代码: MATH|CHINESE|ENGLISH|PHYSICS|CHEMISTRY|BIOLOGY|HISTORY|GEOGRAPHY|POLITICS',
    chapter_id      BIGINT COMMENT '关联教材章节ID',
    knowledge_point_ids JSON COMMENT '关联知识点ID列表 [1001, 1002]',

    -- 行为度量
    duration_sec    INT DEFAULT 0 COMMENT '有效学习时长（秒）',
    is_correct      TINYINT(1) COMMENT '答题正确性: 0=错, 1=对, NULL=不适用',
    difficulty      TINYINT COMMENT '难度等级 1-5',
    score           DECIMAL(5,2) COMMENT '得分（练习/测评场景）',

    -- 扩展信息
    detail_json     JSON COMMENT '行为详情扩展字段',
    -- 示例: {"question_id": 2001, "conversation_id": "conv_xxx", "attempt_no": 2, "model_used": "glm-5"}

    -- 时间与来源
    client_time     DATETIME(3) NOT NULL COMMENT '客户端行为发生时间（毫秒精度）',
    server_time     DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '服务端接收时间',
    client_id       VARCHAR(64) COMMENT '客户端设备标识，用于去重',
    is_offline      TINYINT(1) DEFAULT 0 COMMENT '是否离线产生',
    upload_batch_id VARCHAR(64) COMMENT '离线上报批次ID',

    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_user_time (user_id, client_time),
    INDEX idx_user_subject (user_id, subject_code, client_time),
    INDEX idx_user_chapter (user_id, chapter_id, client_time),
    INDEX idx_user_kp_json ((CAST(knowledge_point_ids AS CHAR(512))), user_id),  -- MySQL 8.0 函数索引
    INDEX idx_type_time (activity_type, client_time),
    INDEX idx_upload_batch (upload_batch_id),
    INDEX idx_client_dedup (user_id, client_id, client_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学习行为日志';
```

**activity_type 枚举值完整定义：**

| 值 | 说明 | duration_sec | is_correct | source_module |
|---|---|---|---|---|
| `AI_CHAT` | AI 对话问答（含单轮和多轮） | 对话时长 | NULL | AI_TUTOR |
| `AI_CHAT_FOLLOWUP` | AI 追问 | 追问时长 | NULL | AI_TUTOR |
| `PHOTO_SOLVE` | 拍照搜题 | 答题查看时长 | NULL | PHOTO_SOLVE |
| `PHOTO_SOLVE_REVIEW` | 拍题后用户标记理解/不理解 | 0 | 0/1 | PHOTO_SOLVE |
| `PRACTICE_ANSWER` | 练习答题 | 答题耗时 | 0/1 | PRACTICE |
| `PRACTICE_BATCH` | 批量练习提交 | 总耗时 | NULL(批量) | PRACTICE |
| `SYNC_CHAPTER_START` | 开始学习章节 | 0 | NULL | SYNC_CLASS |
| `SYNC_CHAPTER_END` | 完成章节学习 | 学习时长 | NULL | SYNC_CLASS |
| `SYNC_PRETEST` | 课前预习测试 | 答题耗时 | 0/1 | SYNC_CLASS |
| `SYNC_EXERCISE` | 章节同步练习 | 答题耗时 | 0/1 | SYNC_CLASS |
| `MISTAKE_REVIEW` | 错题复习 | 复习时长 | 0/1 | REVIEW |
| `MISTAKE_CORRECT` | 错题订正 | 订正耗时 | 0/1 | REVIEW |
| `MISTAKE_ADD` | 新增错题 | 0 | NULL | REVIEW |
| `ESSAY_SUBMIT` | 作文提交 | 写作时长 | NULL | ESSAY |
| `ESSAY_REVIEW` | 查看作文批改 | 查看时长 | NULL | ESSAY |
| `MEMORIZE_START` | 开始背诵 | 0 | NULL | MEMORIZATION |
| `MEMORIZE_CHECK` | 背诵检测 | 检测时长 | 0/1 | MEMORIZATION |
| `PLAN_TASK_START` | 开始执行学习任务 | 0 | NULL | PLAN |
| `PLAN_TASK_COMPLETE` | 完成学习任务 | 任务耗时 | NULL | PLAN |
| `MOCK_TEST_START` | 模拟测试开始 | 0 | NULL | PRACTICE |
| `MOCK_TEST_SUBMIT` | 模拟测试提交 | 总耗时 | NULL | PRACTICE |

### 2.2 学习会话表 `learning_session`

管理一次完整的学习会话生命周期，一个会话可能跨越多个模块。例如：用户打开APP → 拍题 → 看解析 → 加入错题 → 复习相关知识点，整个过程属于同一个学习会话。

```sql
CREATE TABLE learning_session (
    id              VARCHAR(64) PRIMARY KEY COMMENT '会话ID（UUID）',
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    session_type    VARCHAR(32) NOT NULL COMMENT '会话类型: SINGLE|STUDY|PLAN_DRIVEN',
    -- SINGLE: 单次快速操作（拍个题就走）
    -- STUDY: 系统性学习会话（学习某个章节、做一组练习）
    -- PLAN_DRIVEN: 由学习规划触发的会话

    primary_subject VARCHAR(16) COMMENT '主学科',
    primary_chapter BIGINT COMMENT '主章节',

    -- 时间
    started_at      DATETIME(3) NOT NULL COMMENT '会话开始时间',
    last_active_at  DATETIME(3) NOT NULL COMMENT '最后活跃时间',
    ended_at        DATETIME COMMENT '会话结束时间',
    total_duration_sec INT DEFAULT 0 COMMENT '累计有效学习时长(秒)',

    -- 统计
    activity_count  INT DEFAULT 0 COMMENT '行为事件数',
    question_count  INT DEFAULT 0 COMMENT '答题数',
    correct_count   INT DEFAULT 0 COMMENT '正确数',

    -- 来源追踪
    trigger_source  VARCHAR(32) COMMENT '触发来源: HOME_SHORTCUT|NOTIFICATION|PLAN_TASK|CHAPTER_NAV|DEEP_LINK',
    trigger_ref     VARCHAR(128) COMMENT '触发来源引用（如任务ID、章节ID）',

    -- 状态
    status          TINYINT NOT NULL DEFAULT 1 COMMENT '1=活跃, 2=自然超时结束, 3=用户主动结束, 4=异常结束',

    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_user_active (user_id, status, last_active_at DESC),
    INDEX idx_user_time (user_id, started_at DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学习会话';
```

**会话超时规则：**
- 用户连续 **10 分钟** 无行为 → 自动标记为超时结束（status=2）
- 用户切换学科/章节不自动结束会话，但记录切换事件
- 用户主动关闭 APP → 客户端上报会话结束（status=3）
- 单个会话最大时长 4 小时，超过强制结束

### 2.3 章节学习进度表 `chapter_progress`

追踪每个用户在每个教材章节上的学习进度。

```sql
CREATE TABLE chapter_progress (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    chapter_id      BIGINT NOT NULL COMMENT '章节ID',
    textbook_edition VARCHAR(50) NOT NULL COMMENT '教材版本',

    -- 进度状态
    progress_status VARCHAR(20) NOT NULL DEFAULT 'NOT_STARTED' COMMENT 'NOT_STARTED|IN_PROGRESS|COMPLETED|MASTERED',
    -- NOT_STARTED: 未开始
    -- IN_PROGRESS: 学习中
    -- COMPLETED: 已完成基本学习
    -- MASTERED: 掌握（通过测评验证）

    -- 进度百分比（0-100），基于子任务完成度计算
    progress_pct    TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '进度百分比',

    -- 学习次数与时长
    study_count     INT DEFAULT 0 COMMENT '学习次数',
    total_duration_sec INT DEFAULT 0 COMMENT '累计学习时长(秒)',
    last_study_at   DATETIME COMMENT '最后学习时间',

    -- 预习/复习标记
    pretest_score   DECIMAL(5,2) COMMENT '课前测试得分',
    pretest_passed  TINYINT(1) DEFAULT 0 COMMENT '课前测试是否通过',
    exercise_count  INT DEFAULT 0 COMMENT '已做练习数',
    exercise_correct_rate DECIMAL(5,3) COMMENT '练习正确率 0.000-1.000',
    review_count    INT DEFAULT 0 COMMENT '复习次数',

    -- 掌握度评估
    mastery_level   TINYINT COMMENT '掌握等级 1-5 (来自掌握度快照)',

    -- 时间戳
    first_study_at  DATETIME COMMENT '首次学习时间',
    completed_at    DATETIME COMMENT '完成时间',
    mastered_at     DATETIME COMMENT '掌握时间',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_user_chapter_edition (user_id, chapter_id, textbook_edition),
    INDEX idx_user_status (user_id, progress_status, last_study_at DESC),
    INDEX idx_user_mastery (user_id, mastery_level)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='章节学习进度';
```

**进度百分比计算规则：**

| 学习阶段 | 占比 | 完成条件 |
|----------|------|----------|
| 课前预习 | 10% | 查看知识点导读 OR 完成课前测试 |
| 知识学习 | 30% | 完成章节内容浏览（min 2 分钟有效时长） |
| 同步练习 | 30% | 完成章节练习（≥N 题，N 按年级设定） |
| 巩固复习 | 20% | 至少复习一次 且 练习正确率 ≥ 60% |
| 测评验证 | 10% | 通过章节测评 |

### 2.4 知识点掌握度快照表 `knowledge_mastery_snapshot`

周期性从行为日志聚合计算，为学情分析和推荐引擎提供快速查询。

```sql
CREATE TABLE knowledge_mastery_snapshot (
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id             BIGINT NOT NULL COMMENT '用户ID',
    knowledge_point_id  BIGINT NOT NULL COMMENT '知识点ID',
    subject_code        VARCHAR(16) NOT NULL COMMENT '学科代码',

    -- 掌握度评估 (0.000 - 1.000)
    mastery_score       DECIMAL(5,3) NOT NULL DEFAULT 0 COMMENT '综合掌握度',
    -- 计算公式: 0.4 × 正确率 + 0.3 × 练习覆盖率 + 0.2 × 复习完成率 + 0.1 × 时长因子

    -- 分项指标
    correct_rate        DECIMAL(5,3) COMMENT '答题正确率',
    practice_coverage   DECIMAL(5,3) COMMENT '练习覆盖率（已做/应做题目比例）',
    review_completion   DECIMAL(5,3) COMMENT '复习完成率（按遗忘曲线应复习次数/实际完成次数）',
    duration_factor     DECIMAL(5,3) COMMENT '时长因子（有效学习时长/建议时长，上限1.0）',

    -- 统计基础
    total_attempts      INT DEFAULT 0 COMMENT '累计答题次数',
    total_correct       INT DEFAULT 0 COMMENT '累计正确次数',
    total_review_count  INT DEFAULT 0 COMMENT '累计复习次数',
    total_duration_sec  INT DEFAULT 0 COMMENT '累计学习时长(秒)',

    -- 趋势
    prev_mastery_score  DECIMAL(5,3) COMMENT '上次掌握度（用于趋势判断）',
    trend               VARCHAR(10) COMMENT 'UP|DOWN|STABLE|NEW',

    -- 快照时间
    snapshot_date       DATE NOT NULL COMMENT '快照日期',
    last_activity_at    DATETIME COMMENT '最后活跃时间',

    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY uk_user_kp_date (user_id, knowledge_point_id, snapshot_date),
    INDEX idx_user_subject (user_id, subject_code, snapshot_date DESC),
    INDEX idx_user_score (user_id, mastery_score),
    INDEX idx_snapshot_date (snapshot_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识点掌握度快照';
```

**掌握度等级映射：**

| mastery_score 范围 | mastery_level | 描述 |
|---|---|---|
| 0.000 - 0.200 | 1 | 未掌握（需系统学习） |
| 0.201 - 0.400 | 2 | 初步了解（需加强练习） |
| 0.401 - 0.600 | 3 | 基本掌握（需巩固复习） |
| 0.601 - 0.800 | 4 | 熟练掌握（可拔高训练） |
| 0.801 - 1.000 | 5 | 精通（无需重复学习） |

### 2.6 学习连续记录表 `learning_streak`

追踪用户的连续学习天数，供打卡、成长激励使用。

```sql
CREATE TABLE learning_streak (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL COMMENT '用户ID',

    current_streak  INT NOT NULL DEFAULT 0 COMMENT '当前连续天数',
    longest_streak  INT NOT NULL DEFAULT 0 COMMENT '历史最长连续天数',
    last_study_date DATE COMMENT '最后学习日期',
    streak_start_date DATE COMMENT '当前连续段起始日期',

    -- 有效学习定义：当日有效学习时长 ≥ 有效阈值
    min_daily_sec   INT NOT NULL DEFAULT 300 COMMENT '有效学习最短时长(秒)，默认5分钟',

    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学习连续记录';
```

**连续天数更新逻辑：**

```
每日凌晨 02:00 定时任务执行：
1. 查询昨日的 learning_daily_summary，判断 total_duration_sec >= min_daily_sec
2. 如果达标：
   - last_study_date == 前天 → current_streak += 1
   - last_study_date != 前天（断了又来）→ current_streak = 1, streak_start_date = 昨天
   - 更新 last_study_date = 昨天
   - 如果 current_streak > longest_streak → 更新 longest_streak
3. 如果未达标：
   - current_streak = 0, streak_start_date = NULL
```

## 4. 核心流程设计

### 4.1 行为上报处理流程

```
客户端                           LRPS 服务端                        下游
  │                                │                               │
  │── POST /activities/batch ─────▶│                               │
  │                                │                               │
  │                                │ ① 参数校验 & 去重              │
  │                                │   - client_id+client_time      │
  │                                │   - upload_batch_id 幂等       │
  │                                │                               │
  │                                │ ② 写入 learning_activity_log   │
  │                                │                               │
  │                                │ ③ 异步更新（消息队列）：        │
  │                                │   ├─▶ 更新 learning_session    │
  │                                │   ├─▶ 更新 chapter_progress    │
  │                                │   ├─▶ 增量更新 daily_summary   │
  │                                │   └─▶ 发送进度变更事件          │
  │                                │       (消息总线)                │──▶ 学情分析
  │◀── { accepted: N } ───────────│                               │──▶ 学习规划
  │                                │                               │──▶ 消息推送
  │                                │                               │──▶ 首页缓存刷新
```

**关键设计决策：**

1. **同步写日志 + 异步更新聚合**：行为日志写入是同步的（保证不丢失），聚合更新通过消息队列异步执行（保证吞吐量）
2. **Redis 实时缓存**：当日时长统计在 Redis 中实时累加，定时（每 5 分钟）刷入 MySQL 的 `learning_daily_summary`
3. **幂等保证**：通过 `client_id` + `client_time` 组合去重，离线场景通过 `upload_batch_id` 整批去重

### 4.2 章节进度更新流程

```python
# 伪代码：章节进度更新（消费行为日志消息后执行）

async def update_chapter_progress(user_id: int, activity: ActivityLog):
    progress = db.get_or_create(ChapterProgress,
        user_id=user_id, chapter_id=activity.chapter_id,
        textbook_edition=activity.textbook_edition)

    # 更新基础统计
    progress.study_count += 1
    progress.total_duration_sec += activity.duration_sec
    progress.last_study_at = activity.client_time

    if progress.first_study_at is None:
        progress.first_study_at = activity.client_time

    # 根据行为类型更新进度
    if activity.activity_type == 'SYNC_PRETEST':
        progress.pretest_score = activity.score
        progress.pretest_passed = 1 if activity.score >= 60 else 0

    elif activity.activity_type == 'SYNC_EXERCISE':
        progress.exercise_count += 1
        # 重新计算正确率
        progress.exercise_correct_rate = recalc_correct_rate(
            user_id, activity.chapter_id)

    elif activity.activity_type == 'SYNC_CHAPTER_END':
        if progress.progress_status == 'NOT_STARTED':
            progress.progress_status = 'IN_PROGRESS'

    # 重算进度百分比
    progress.progress_pct = calc_progress_pct(progress)

    # 状态流转
    if progress.progress_pct >= 100 and progress.progress_status == 'IN_PROGRESS':
        progress.progress_status = 'COMPLETED'
        progress.completed_at = now()
        # 发送事件：CHAPTER_COMPLETED
        event_bus.emit('chapter.completed', user_id, progress.chapter_id)

    db.save(progress)
```

## 5. 进度变更事件设计

### 5.1 事件类型

| 事件名 | 触发条件 | 订阅方 |
|--------|----------|--------|
| `session.started` | 创建学习会话 | 首页(更新进行中状态) |

| `chapter.progress_updated` | 章节进度百分比变化 | 首页、学情 |
| `chapter.completed` | 章节进度达到 100% | 学习规划(任务自动完成)、推送(祝贺) |
| `chapter.mastered` | 章节测评通过 | 学情分析、推荐引擎 |

### 5.3 事件分发机制

MVP 阶段使用 **Redis Pub/Sub**，V1.0+ 迁移至 **消息队列（RocketMQ/Kafka）**。

```python
# MVP: Redis Pub/Sub 简易实现
class ProgressEventBus:
    def __init__(self, redis_client):
        self.redis = redis_client

    async def emit(self, event_type: str, user_id: int, payload: dict):
        event = {
            "event_id": str(uuid.uuid4()),
            "event_type": event_type,
            "timestamp": datetime.utcnow().isoformat(),
            "user_id": user_id,
            "payload": payload
        }
        # 发布到频道
        await self.redis.publish(
            f"lrps:events:{event_type}",
            json.dumps(event, ensure_ascii=False)
        )
        # 同时写入 Stream（持久化，防止离线订阅方丢失）
        await self.redis.xadd(
            f"lrps:stream:{event_type}",
            {"data": json.dumps(event, ensure_ascii=False)},
            maxlen=10000  # 保留最近1万条
        )
```

## 6. 缓存设计

### 6.1 Redis 缓存结构

| Key 模式 | 类型 | TTL | 说明 |
|----------|------|-----|------|
| `lrps:today:{user_id}` | Hash | 当日有效 | 当日实时时长统计 |
| `lrps:session:active:{user_id}` | String | 15min | 当前活跃会话 ID |
| `lrps:progress:chapter:{user_id}:{chapter_id}` | Hash | 10min | 章节进度缓存 |
| `lrps:streak:{user_id}` | Hash | 24h | 连续天数缓存 |
| `lrps:dedup:{user_id}:{client_id}:{ts}` | String | 24h | 去重标记 |
| `lrps:batch:{batch_id}` | String | 7d | 批次幂等标记 |

### 6.2 当日时长实时累加

```
# 每次行为上报后，实时更新 Redis
HINCRBY lrps:today:{user_id} total_duration {duration_sec}
HINCRBY lrps:today:{user_id} ai_chat_duration {ai_chat_duration}
HINCRBY lrps:today:{user_id} practice_duration {practice_duration}
HINCRBY lrps:today:{user_id} activities 1

# 每5分钟，后台任务将 Redis 数据刷入 MySQL
# 流程：读取 Redis → UPSERT learning_daily_summary → 清除过期 Key
```

### 6.3 缓存一致性

- **写入策略**：行为上报时先写 MySQL 日志，再更新 Redis 缓存
- **刷新策略**：每 5 分钟将 Redis 累加值刷入 MySQL 的 `learning_daily_summary`
- **兜底策略**：凌晨 T+1 定时任务从 `learning_activity_log` 重新聚合，覆盖 `learning_daily_summary`，确保数据最终一致
- **缓存失效**：章节进度缓存 10 分钟 TTL，过期后从 MySQL 重新加载

## 7. 错误处理

### 7.1 行为上报错误码

| 错误码 | HTTP 状态 | 说明 | 客户端处理 |
|--------|-----------|------|------------|
| `INVALID_ACTIVITY_TYPE` | 400 | 无效的行为类型 | 丢弃，不重试 |
| `INVALID_CLIENT_TIME` | 400 | 时间超出允许范围 | 调整为服务端时间后重试 |
| `INVALID_SUBJECT` | 400 | 无效学科代码 | 丢弃 |
| `BATCH_TOO_LARGE` | 400 | 批次超过 100 条 | 分批重试 |
| `DUPLICATE_BATCH` | 200 | 重复的 upload_batch_id | 忽略（幂等） |
| `RATE_LIMITED` | 429 | 上报频率过高（>60次/分钟） | 退避重试 |
| `INTERNAL_ERROR` | 500 | 服务端异常 | 本地缓存，稍后重试 |

### 7.2 离线上报异常处理

```
客户端策略：
1. 上报失败 → 保留在本地 SQLite，标记 retry_count += 1
2. retry_count > 3 → 标记为 failed，不再自动重试
3. 每次登录后检查 failed 记录，提示用户"有N条学习记录未同步"
4. 用户点击"立即同步" → 强制重试所有 failed 记录

服务端策略：
1. 接收到离线数据时，以 client_time 为准重建进度
2. 如果离线数据与已有进度冲突（如章节已完成但离线数据显示未完成）
   → 取进度更高的状态（不降级）
3. 时长类数据直接累加，不存在冲突
```

### 7.3 定时任务容错

| 任务 | 频率 | 失败策略 |
|------|------|----------|
| 会话超时检查 | 每 5 分钟 | 跳过本轮，下轮补偿 |
| Redis→MySQL 时长同步 | 每 5 分钟 | 记录失败位点，下次从位点继续 |
| 掌握度快照生成 | 每日凌晨 | 失败后 1 小时重试，最多 3 次 |
| 连续天数更新 | 每日凌晨 | 失败后 30 分钟重试 |
| T+1 日汇总归档 | 次日 03:00 | 失败后 1 小时重试，最多 3 次 |

## 8. 性能考量

### 8.1 写入优化

| 策略 | 说明 |
|------|------|
| **异步聚合** | 行为日志同步写入 MySQL，聚合计算全部异步 |
| **Redis 累加** | 当日实时统计用 Redis HINCRBY，避免高频写 MySQL |
| **批量插入** | 行为日志使用 INSERT BATCH，单次最多 100 条 |
| **消息队列削峰** | 高峰期行为通过 MQ 异步消费，不直接写聚合表 |
| **分区（远期）** | `learning_activity_log` 按月分区，保留 6 个月热数据 |

### 8.2 查询优化

| 策略 | 说明 |
|------|------|
| **预聚合表** | `learning_daily_summary` 避免实时扫描日志表 |
| **快照表** | `knowledge_mastery_snapshot` 避免实时聚合计算 |
| **Redis 缓存** | 当日统计、活跃会话、连续天数走缓存 |
| **索引覆盖** | 核心查询走 `(user_id, client_time)` 联合索引 |
| **读写分离** | 聚合查询走只读副本，实时写入走主库 |

### 8.3 容量预估（10 万 DAU 场景）

| 表 | 日增量 | 保留周期 | 存储估算 |
|----|--------|----------|----------|
| `learning_activity_log` | ~200 万行 | 6 个月 | ~36 亿行，约 500 GB |
| `learning_session` | ~30 万行 | 12 个月 | ~1.1 亿行，约 20 GB |
| `chapter_progress` | 初始 ~500 万行，日增 ~1 万 | 永久 | ~800 万行，约 2 GB |
| `knowledge_mastery_snapshot` | 日增 ~50 万行 | 12 个月 | ~1.8 亿行，约 30 GB |
| `learning_daily_summary` | 日增 ~50 万行 | 24 个月 | ~3.6 亿行，约 15 GB |

### 9.1 Flutter 端行为上报 SDK

```dart
/// 学习行为上报管理器
class LearningTracker {
  final Dio _dio;
  final HiveBox _localBox;      // 本地缓存（离线支持）
  final String _deviceId;

  /// 当前活跃会话
  String? _activeSessionId;

  /// 上报单条行为（在线）
  Future<void> track(LearningActivity activity) async {
    activity.sessionId = _activeSessionId;

    if (await _isOnline()) {
      try {
        await _dio.post('/api/v1/learning/activities/single',
          data: activity.toJson(),
        );
        return;
      } catch (e) {
        // 上报失败，存入本地
      }
    }
    // 离线或失败：存入本地队列
    await _localBox.add({
      'activity': activity.toJson(),
      'synced': false,
      'retry_count': 0,
      'created_at': DateTime.now().toIso8601String(),
    });
  }

  /// 批量上报（在线后同步离线数据）
  Future<void> syncOfflineActivities() async {
    final unsynced = _localBox.values
        .where((e) => e['synced'] == false && (e['retry_count'] ?? 0) < 3)
        .toList();

    if (unsynced.isEmpty) return;

    final batchId = 'batch_${_deviceId}_${DateTime.now().millisecondsSinceEpoch}';

    try {
      final response = await _dio.post('/api/v1/learning/activities/batch',
        data: {
          'upload_batch_id': batchId,
          'activities': unsynced.map((e) => e['activity']).toList(),
        },
      );

      if (response.data['code'] == 0) {
        // 标记已同步
        for (final entry in unsynced) {
          await _localBox.put(entry.key, {
            ...entry,
            'synced': true,
          });
        }
      }
    } catch (e) {
      // 增加重试计数
      for (final entry in unsynced) {
        await _localBox.put(entry.key, {
          ...entry,
          'retry_count': (entry['retry_count'] ?? 0) + 1,
        });
      }
    }
  }

  /// 创建学习会话
  Future<String> startSession({
    required String sessionType,
    String? subject,
    int? chapterId,
    String? triggerSource,
  }) async {
    final response = await _dio.post('/api/v1/learning/sessions', data: {
      'session_type': sessionType,
      'primary_subject': subject,
      'primary_chapter': chapterId,
      'trigger_source': triggerSource,
    });

    _activeSessionId = response.data['data']['session_id'];

    // 启动心跳定时器
    _startHeartbeat();

    return _activeSessionId!;
  }

  /// 结束学习会话
  Future<void> endSession() async {
    if (_activeSessionId == null) return;

    _stopHeartbeat();

    await _dio.put(
      '/api/v1/learning/sessions/$_activeSessionId/end',
      data: {'end_status': 3},
    );
    _activeSessionId = null;
  }

  /// 心跳：每 60 秒
  Timer? _heartbeatTimer;
  void _startHeartbeat() {
    _heartbeatTimer = Timer.periodic(
      Duration(seconds: 60),
      (_) => _heartbeat(),
    );
  }

  void _stopHeartbeat() {
    _heartbeatTimer?.cancel();
    _heartbeatTimer = null;
  }

  Future<void> _heartbeat() async {
    if (_activeSessionId == null) return;
    try {
      await _dio.put(
        '/api/v1/learning/sessions/$_activeSessionId/heartbeat',
        data: {'current_module': 'AI_TUTOR'},
      );
    } catch (_) {
      // 心跳失败不影响用户体验，静默处理
    }
  }
}

/// 学习行为数据模型
class LearningActivity {
  final String activityType;
  final String sourceModule;
  String? sessionId;
  final String? subjectCode;
  final int? chapterId;
  final List<int>? knowledgePointIds;
  final int durationSec;
  final bool? isCorrect;
  final int? difficulty;
  final Map<String, dynamic>? detailJson;
  final DateTime clientTime;
  final String clientId;

  LearningActivity({
    required this.activityType,
    required this.sourceModule,
    this.sessionId,
    this.subjectCode,
    this.chapterId,
    this.knowledgePointIds,
    this.durationSec = 0,
    this.isCorrect,
    this.difficulty,
    this.detailJson,
    required this.clientTime,
    required this.clientId,
  });

  Map<String, dynamic> toJson() => {
    'activity_type': activityType,
    'source_module': sourceModule,
    'session_id': sessionId,
    'subject_code': subjectCode,
    'chapter_id': chapterId,
    'knowledge_point_ids': knowledgePointIds,
    'duration_sec': durationSec,
    'is_correct': isCorrect,
    'difficulty': difficulty,
    'detail_json': detailJson,
    'client_time': clientTime.toIso8601String(),
    'client_id': clientId,
    'is_offline': false,
  };
}
```
