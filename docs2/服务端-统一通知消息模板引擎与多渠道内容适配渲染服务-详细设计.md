# 服务端-统一通知消息模板引擎与多渠道内容适配渲染服务 详细设计

## 1. 概述

### 1.1 模块定位

统一通知消息模板引擎是 PrimeTop 通知体系中位于**业务逻辑层**与**投递通道层**之间的中间服务。当业务模块（学习提醒、系统公告、家长报告、运营活动等）决定需要发送通知时，不直接拼接消息内容，而是向模板引擎提交「模板标识 + 变量上下文 + 目标渠道集合」，由模板引擎统一完成变量替换、渠道适配渲染、内容安全过滤、长度截断、多语言/分龄变体选择，最终输出各渠道可直接投递的最终报文。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| 模板管理 | 模板的 CRUD、版本控制、审核发布、灰度上线 |
| 变量替换 | 占位符渲染、嵌套对象访问、默认值兜底、条件块 |
| 渠道适配 | 同一模板按 Push / SMS / 站内信 / 邮件 / 微信小程序订阅消息等渠道输出不同格式与长度 |
| 分龄适配 | 按学生学段（幼儿/小学/初中/高中）和家长视角输出不同表达 |
| 内容安全过滤 | 渲染后文本经过敏感词过滤与未成年人保护处理 |
| 模板预览与试发 | 运营/开发人员在后台预览渲染效果并发送测试 |
| 降级与兜底 | 渠道不可用时自动降级到备用模板或纯文本摘要 |

### 1.3 依赖关系

```
┌─────────────────────────────────────────────────┐
│              业务模块 (调用方)                    │
│  学习提醒 / 学情报告 / 运营活动 / 系统公告 / ...  │
└────────────────────┬────────────────────────────┘
                     │ renderRequest

┌─────────────────────────────────────────────────┐
│         统一通知消息模板引擎 (本服务)              │

│  └──────────┘ └──────────┘ └──────────────────┘ │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐ │
│  │ 分龄适配  │ │ 安全过滤  │ │ 预览与试发        │ │
│  └──────────┘ └──────────┘ └──────────────────┘ │
└──────┬──────────────┬───────────────────┬───────┘
       │              │                   │
       ▼              ▼                   ▼
┌──────────┐  ┌────────────┐   ┌──────────────────┐
│ MySQL    │  │ Redis 缓存  │   │ 投递通道层        │
│ 模板表    │  │ 模板缓存    │   │ Push/SMS/站内信/  │
│          │  │            │   │ 邮件/小程序        │
└──────────┘  └────────────┘   └──────────────────┘
```

**上游依赖（调用方）：**
- 学习提醒调度服务 → 渲染学习提醒消息
- 学情分析服务 → 渲染学情报告摘要
- 运营活动引擎 → 渲染活动弹窗与推送文案
- 系统公告服务 → 渲染公告内容
- 家长报告服务 → 渲染家长端周报/月报
- 错题复习调度 → 渲染复习提醒

**下游依赖（被调用方）：**
- Push 推送通道适配层（APNs / FCM / 华为 / 小米 / OPPO / VIVO / 魅族）
- SMS 短信网关
- 站内消息服务
- 邮件服务
- 微信小程序订阅消息接口

### 2.2 数据库表结构

#### 2.2.1 `notification_template` — 模板主表

```sql
CREATE TABLE `notification_template` (
    `id`                BIGINT          NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    `template_code`     VARCHAR(64)     NOT NULL                 COMMENT '模板编码，业务侧引用的唯一标识，如 study_reminder.daily_task',
    `template_name`     VARCHAR(128)    NOT NULL                 COMMENT '模板名称，人工可读',
    `category`          VARCHAR(32)     NOT NULL                 COMMENT '模板分类: study / operation / system / parent / marketing',
    `description`       VARCHAR(512)    NULL                     COMMENT '模板用途描述',
    `status`            TINYINT         NOT NULL DEFAULT 0       COMMENT '状态: 0=草稿, 1=待审核, 2=已发布, 3=已下线, 4=已废弃',
    `current_version`   INT             NOT NULL DEFAULT 0       COMMENT '当前生效版本号',
    `supported_channels` VARCHAR(256)   NOT NULL                 COMMENT '支持的渠道列表 JSON 数组: ["push","sms","inapp","email","mp"]',
    `priority`          TINYINT         NOT NULL DEFAULT 5       COMMENT '消息优先级: 1-最高 5-普通 9-最低',
    `expire_minutes`    INT             NULL                     COMMENT '消息有效期(分钟)，超时不再投递，NULL=不过期',
    `created_by`        BIGINT          NOT NULL                 COMMENT '创建人ID',
    `updated_by`        BIGINT          NOT NULL                 COMMENT '最后更新人ID',
    `created_at`        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_template_code` (`template_code`),
    KEY `idx_category_status` (`category`, `status`),
    KEY `idx_updated_at` (`updated_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='通知消息模板主表';
```

#### 2.2.2 `notification_template_version` — 模板版本表

```sql
CREATE TABLE `notification_template_version` (
    `id`                BIGINT          NOT NULL AUTO_INCREMENT,
    `template_id`       BIGINT          NOT NULL                 COMMENT '关联模板ID',

    `title_template`    VARCHAR(512)    NOT NULL                 COMMENT '标题模板（含占位符）',
    `body_template`     TEXT            NOT NULL                 COMMENT '正文模板（含占位符，支持条件块语法）',
    `short_template`    VARCHAR(256)    NULL                     COMMENT '短文本模板（Push/SMS专用，如不填则自动截断）',
    `rich_template`     TEXT            NULL                     COMMENT '富文本模板（邮件/站内信专用，HTML格式）',
    `fallback_template` VARCHAR(512)    NULL                     COMMENT '降级纯文本模板，当富文本渲染失败时使用',
    `change_log`        VARCHAR(512)    NULL                     COMMENT '版本变更说明',
    `review_status`     TINYINT         NOT NULL DEFAULT 0       COMMENT '审核状态: 0=待审核, 1=审核通过, 2=审核驳回',
    `reviewer_id`       BIGINT          NULL                     COMMENT '审核人ID',
    `reviewed_at`       DATETIME        NULL                     COMMENT '审核时间',
    `review_comment`    VARCHAR(512)    NULL                     COMMENT '审核意见',

    `created_by`        BIGINT          NOT NULL,
    `created_at`        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY `uk_template_version` (`template_id`, `version`),
```

```sql
CREATE TABLE `notification_template_channel_config` (
    `id`                BIGINT          NOT NULL AUTO_INCREMENT,
    `template_id`       BIGINT          NOT NULL,
```

#### 2.2.6 `notification_render_log` — 渲染日志表

```sql
CREATE TABLE `notification_render_log` (
    `id`                BIGINT          NOT NULL AUTO_INCREMENT,
    `request_id`        VARCHAR(64)     NOT NULL                 COMMENT '请求唯一ID（雪花ID/UUID）',
    `template_code`     VARCHAR(64)     NOT NULL                 COMMENT '使用的模板编码',
    `template_version`  INT             NOT NULL                 COMMENT '使用的模板版本',
    `user_id`           BIGINT          NULL                     COMMENT '目标用户ID',

    `render_status`     TINYINT         NOT NULL                 COMMENT '渲染结果: 1=成功 2=变量缺失 3=模板异常 4=安全拦截',

    `rendered_body`     TEXT            NULL                     COMMENT '渲染后正文（脱敏存储）',
    `context_snapshot`  JSON            NULL                     COMMENT '渲染上下文快照（脱敏后）',
    `error_message`     VARCHAR(512)    NULL                     COMMENT '失败原因',

    KEY `idx_request_id` (`request_id`),

    KEY `idx_user_channel` (`user_id`, `channel`, `created_at`)

```

### 2.3 Redis 缓存策略

| 缓存键 | TTL | 说明 |
|--------|-----|------|
| `tpl:published:{templateCode}` | 10 min | 已发布模板完整配置（主表 + 当前版本 + 渠道配置 + 分龄变体 + 变量定义），JSON 序列化 |
| `tpl:version:{templateId}:{version}` | 30 min | 历史版本内容（用于回滚与对比） |
| `tpl:code:set` | 60 min | 全量模板编码集合，用于快速判断编码是否存在 |
| `tpl:render:blacklist` | - (Set) | 被安全引擎标记的模板编码，渲染时直接拒绝 |

**缓存失效策略：**
- 模板发布 / 下线 / 废弃时，主动删除 `tpl:published:{templateCode}`
- 模板修改（草稿态）不触发缓存失效（草稿不缓存）
- 采用 `CACHE-ASIDE`（旁路缓存）模式：先读缓存，miss 时读 DB 并回写

## 3. API 接口设计

### 3.1 接口总览

| # | 接口 | 方法 | 路径 | 用途 |
|---|------|------|------|------|
| 1 | 渲染消息 | POST | `/api/v1/notification-template/render` | 核心渲染接口，业务调用 |
| 2 | 批量渲染 | POST | `/api/v1/notification-template/render/batch` | 批量渲染（如全班通知） |
| 3 | 创建模板 | POST | `/api/v1/notification-template/templates` | 后台管理 |
| 4 | 更新模板 | PUT | `/api/v1/notification-template/templates/{id}` | 后台管理 |
| 5 | 提交审核 | POST | `/api/v1/notification-template/templates/{id}/submit-review` | 后台管理 |
| 6 | 审核模板 | POST | `/api/v1/notification-template/templates/{id}/review` | 后台管理 |
| 7 | 发布模板 | POST | `/api/v1/notification-template/templates/{id}/publish` | 后台管理 |
| 8 | 下线模板 | POST | `/api/v1/notification-template/templates/{id}/offline` | 后台管理 |
| 9 | 预览渲染 | POST | `/api/v1/notification-template/preview` | 后台预览 |
| 10 | 试发测试 | POST | `/api/v1/notification-template/test-send` | 后台试发 |
| 11 | 查询模板列表 | GET | `/api/v1/notification-template/templates` | 后台列表 |
| 12 | 查询模板详情 | GET | `/api/v1/notification-template/templates/{id}` | 后台详情 |
| 13 | 查询渲染日志 | GET | `/api/v1/notification-template/render-logs` | 排障查询 |

### 3.2 核心接口详细定义

#### 3.2.1 渲染消息

**POST** `/api/v1/notification-template/render`

业务模块调用此接口，传入模板编码与变量上下文，获取各渠道的最终渲染内容。

**请求体：**

```json
{
  "templateCode": "study_reminder.daily_task",
  "userId": 10086,
  "channels": ["push", "inapp"],

    "parent_view": false
  },
  "options": {
    "enableAgeAdapt": true,
    "enableSafetyFilter": true,
    "fallbackOnFailure": true
  }
}
```

#### 3.2.2 批量渲染

**POST** `/api/v1/notification-template/render/batch`

用于一次调用中对多个用户批量渲染同一模板（如全班通知、年级公告）。

**请求体：**

```json
{
  "templateCode": "exam_reminder.midterm",
  "items": [
    {
      "userId": 1001,
      "context": {"student_name": "张三", "exam_date": "2026-07-10", "subjects": ["数学", "语文"]}

    {
      "userId": 1002,

  ],
  "channels": ["push", "inapp"],
  "options": {
    "enableAgeAdapt": true,
    "enableSafetyFilter": true
  }
}
```

**响应体：**

```json
{
  "code": 0,

```

#### 3.2.3 预览渲染

**POST** `/api/v1/notification-template/preview`

后台管理使用，支持指定模板版本、模拟不同学段/渠道查看渲染效果，不写入日志、不投递。

```json
{
  "templateId": 42,
  "version": 4,
  "simulatedStage": "primary",
  "channels": ["push", "sms", "inapp", "email"],
  "context": {
    "student_name": "小红",
    "task_count": 2,
    "task_list": ["语文：生字抄写", "数学：口算100题"]
  }
}
```

#### 3.2.4 试发测试

**POST** `/api/v1/notification-template/test-send`

后台使用，将渲染结果发送到指定测试账号，用于上线前验证。

```json
{
  "templateId": 42,
  "version": 4,
  "targetUserId": 999,        // 测试账号ID
  "channels": ["push", "inapp"],
  "context": {
    "student_name": "测试用户",
    "task_count": 1,
    "task_list": ["测试任务"]
  }
}
```

## 4. 模板语法规范

### 4.1 占位符语法

采用 `{{ }}` 双花括号包裹变量名，支持管道操作符进行链式处理。

| 语法 | 说明 | 示例 |
|------|------|------|
| `{{variable}}` | 简单变量替换 | `{{student_name}}` → `小明` |
| `{{object.field}}` | 嵌套对象字段 | `{{exam.subject}}` → `数学` |
| `{{var \| filter(args)}}` | 管道过滤器 | `{{deadline \| dateFormat("MM月dd日 HH:mm")}}` |
| `{{var \| default("兜底")}}` | 默认值 | `{{nickname \| default("同学")}}` |
| `{% if condition %}...{% endif %}` | 条件块 | 见下方示例 |
| `{% for item in list %}...{% endfor %}` | 循环块 | 遍历任务列表 |

### 4.2 内置过滤器

| 过滤器 | 说明 | 示例 |
|--------|------|------|
| `dateFormat(pattern)` | 日期格式化 | `{{date \| dateFormat("YYYY-MM-DD")}}` |
| `numberFormat(pattern)` | 数字格式化 | `{{score \| numberFormat("#.##")}}` |
| `default(value)` | 空值默认 | `{{name \| default("同学")}}` |
| `truncate(maxLen)` | 截断+省略号 | `{{text \| truncate(50)}}` |
| `join(separator)` | 列表拼接 | `{{subjects \| join("、")}}` |
| `enumerate` | 列表编号 | `1. xxx\n2. yyy` |
| `mask` | 脱敏处理 | `{{phone \| mask}}` → `138****5678` |
| `pluralize(single, plural)` | 复数化 | `{{count}}个{{unit \| pluralize("任务", "任务")}}` |
| `upper` / `lower` | 大小写转换 | `{{code \| upper}}` |
| `safe` | 标记为安全（不转义） | `{{html_content \| safe}}` |

### 5.2 模板加载与缓存

```java
@Service
public class TemplateLoader {

    @Cacheable(value = "tpl:published", key = "#templateCode")
    public PublishedTemplate load(String templateCode) {
        // 1. Redis
        String cached = redis.get("tpl:published:" + templateCode);
        if (cached != null) {
            return JSON.parseObject(cached, PublishedTemplate.class);
        }
        // 2. MySQL
        NotificationTemplate tpl = templateRepo.findByCodeAndStatus(templateCode, PUBLISHED);
        if (tpl == null) {
            throw new TemplateException(TemplateError.TEMPLATE_NOT_FOUND);
        }
        PublishedTemplate pt = assemble(tpl);
        redis.setex("tpl:published:" + templateCode, 600, JSON.toJSONString(pt));
        return pt;
    }

    private PublishedTemplate assemble(NotificationTemplate tpl) {
        PublishedTemplate pt = new PublishedTemplate();
        BeanUtils.copyProperties(tpl, pt);
        pt.setVersion(versionRepo.findPublished(tpl.getId()));
        pt.setChannelConfigs(channelConfigRepo.findByTemplateId(tpl.getId()));
        pt.setAgeVariants(ageVariantRepo.findByTemplateId(tpl.getId()));
        pt.setVariables(variableRepo.findByTemplateId(tpl.getId()));
        return pt;
    }
}
```

### 5.3 变量校验与上下文

```java
public class VariableValidator {

    public void validate(Map<String, Object> context, List<TemplateVariable> defs) {
        for (TemplateVariable def : defs) {
            Object value = context.get(def.getVariableName());
            if (value == null || (value instanceof String && ((String) value).isEmpty())) {
                if (def.getIsRequired() == 1) {
                    throw new TemplateException(TemplateError.REQUIRED_VARIABLE_MISSING,
                            def.getVariableName());
                }
                context.put(def.getVariableName(), def.getDefaultValue());
                continue;
            }
            if (!typeMatch(value, def.getVariableType())) {
                throw new TemplateException(TemplateError.VARIABLE_TYPE_MISMATCH,
                        def.getVariableName());
            }
            if (def.getEnumValues() != null && !def.getEnumValues().contains(value)) {
                throw new TemplateException(TemplateError.VARIABLE_VALUE_INVALID,
                        def.getVariableName());
            }
        }
    }
}
```

### 5.4 渠道适配渲染

```java
public class ChannelRenderer {

    public ChannelRenderResult render(PublishedTemplate tpl, String channel,
                                       Map<String, Object> context, RenderOptions opts) {
        ChannelConfig config = tpl.getChannelConfig(channel);
        if (config == null || config.getEnabled() == 0) {
            return ChannelRenderResult.skipped(channel, "渠道未启用");
        }

        // 1. 选择分龄变体
        TemplateVariant variant = selectVariant(tpl, context, opts);

        // 2. 标题渲染
        String title = renderTitle(tpl, variant, config, context);
        title = truncate(title, config.getTitleMaxLength());

        // 3. 正文渲染
        String body = renderBody(tpl, variant, config, context);
        body = truncate(body, config.getBodyMaxLength());

        // 4. 渠道扩展字段
        Map<String, Object> extras = buildExtras(config, context);

        return ChannelRenderResult.success(channel, title, body, extras);
    }

    private TemplateVariant selectVariant(PublishedTemplate tpl, Map<String, Object> ctx, RenderOptions opts) {
        if (!opts.isEnableAgeAdapt()) return null;
        String stage = (String) ctx.get("stage");
        if (stage == null) return null;
        if (Boolean.TRUE.equals(ctx.get("parent_view"))) {
            stage = "parent";
        }
        return tpl.getAgeVariant(stage);
    }
}
```

### 5.6 批量渲染

```java
public class BatchRenderService {

    public BatchRenderResponse render(BatchRenderRequest req) {
        if (req.getItems().size() > 500) {
            throw new TemplateException(TemplateError.BATCH_SIZE_EXCEEDED);
        }
        List<SingleRenderResult> results = req.getItems().parallelStream()
            .map(item -> {
                try {
                    return singleRenderService.render(req.getTemplateCode(),
                            item.getUserId(), item.getContext(), req.getChannels(), req.getOptions());
                } catch (TemplateException e) {
                    return SingleRenderResult.failed(item.getUserId(), e.getError(), e.getMessage());
                }
            }).collect(Collectors.toList());
        return aggregate(results);
    }
}
```

### 5.7 幂等与限流实现

**幂等：** 渲染接口支持 `idempotencyKey`（业务调用方传入或内部按 `templateCode+userId+channels+contextHash` 生成）。同一幂等键 24h 内返回相同 `requestId` 与结果，幂等键冲突但请求体不同返回 `59305`。

**限流：**

| 维度 | 阈值 | 行为 |
|------|------|------|
| 单租户 QPS | 300/s | 超出返回 429 + `59318` |
| 批量接口 | 500 items/req | 超出返回 400 + `59317` |
| 单个模板 | 100/s | 触发模板级熔断，30s 后探测恢复 |
| 管理端写入 | 30/s | 超出排队或 429 |

```java
@Component

            throw new TemplateException(TemplateError.TEMPLATE_RATE_LIMITED);
```

```text
        │              └────┬─────┘                                │
        │                   │ reject                               │ offline
        │                   ▼                                      ▼
        │              ┌──────────┐                          ┌──────────┐
        │              │ REJECTED │                          │ OFFLINE  │
        │              └──────────┘                          └────┬─────┘
        │                                                          │
        │ update                                                    │ deprecate
        │                                                           ▼
        └────────────────────────────────────────────────────▶ ┌──────────┐
                                                                 │DEPRECATED│
```

| 转换 | 触发 | 守卫 |
|------|------|------|
| DRAFT → PENDING_REVIEW | 提交审核 | 变量定义完整、至少一个渠道配置、正文非空 |
| PENDING_REVIEW → APPROVED | 审核通过 | reviewer_id ≠ created_by |
| PENDING_REVIEW → REJECTED | 审核驳回 | 填写 review_comment |
| APPROVED → PUBLISHED | 发布 | 无同 code 已发布模板 |
| PUBLISHED → OFFLINE | 下线 | 有运营审批 |
| OFFLINE → DRAFT | 重新编辑 | - |
| OFFLINE → DEPRECATED | 废弃 | 无 PENDING 渲染任务 |

### 6.2 渲染任务状态

```text
CREATED
   │
   ▼
PROCESSING
   │
   ├─ success ──▶ COMPLETED
   │
   ├─ partial ──▶ PARTIAL_FAILED（部分渠道失败）
   │
   └─ failure ──▶ FAILED
```

| 状态 | 说明 |
|------|------|
| CREATED | 请求已接受，幂等键已落库 |
| PROCESSING | 正在渲染 |
| COMPLETED | 所有请求渠道渲染成功 |
| PARTIAL_FAILED | 部分渠道失败，已使用 fallback 或跳过 |
| FAILED | 全部失败或模板级错误 |

### 6.3 渠道配置状态

| 状态 | 说明 |
|------|------|
| ENABLED | 该渠道启用，正常渲染 |
| DISABLED | 该渠道禁用，渲染时跳过 |
| DEGRADED | 该渠道被熔断（下游异常），自动走 fallback |

### 7.2 降级矩阵

| 编号 | 故障场景 | 降级策略 | 影响 |
|------|---------|---------|------|
| D1 | Redis 缓存不可用 | 直查 MySQL，渲染成功但延迟增加 | P99 升高 |
| D2 | MySQL 主库不可用 | 读从库 + 本地缓存；写日志失败走本地 WAL | 管理写入不可用 |
| D3 | 安全过滤服务超时 | 跳过敏感词检查并标记审计，仍做 HTML 转义 | 安全性降级，审计兜底 |
| D4 | 分龄变体缺失 | 回退到通用模板 | 表达可能不够适龄 |
| D5 | 渠道专属模板渲染失败 | 使用默认标题/正文模板 | 格式可能非最优 |
| D6 | 渠道适配器异常 | 跳过该渠道，返回其他渠道结果 | 该渠道消息缺失 |
| D7 | 模板富文本渲染失败 | 使用 fallback_template 纯文本 | 样式丢失 |
| D8 | 下游投递通道不可用 | 仅返回渲染结果，不保证投递 | 调用方自行处理 |
| D9 | 批量任务部分失败 | 成功项正常返回，失败项带错误码 | 部分用户未触达 |
| D10 | 限流触发 | 优先拒绝非学习类营销模板 | 营销消息延迟 |

### 7.3 重试与补偿规则

| 场景 | 重试策略 | 补偿 |
|------|---------|------|
| Redis 读失败 | 立即重试 1 次，仍失败走 MySQL | - |
| MySQL 写渲染日志失败 | 退避 3 次（1s/2s/4s），失败后入本地 WAL | 定时任务重放 WAL |
| Outbox 投递失败 | 2^n 退避，最多 16 次，后进 DEAD | DEAD>0 触发 P2 |
| 下游安全过滤超时 | 1 次重试，仍超时按 D3 降级 | 安全审计标记 |
| 批量单条失败 | 不重试，返回失败明细 | 调用方决定是否重发 |
| 模板缓存重建 | 异步双删缓存，30s 后探测 | 防止脏读 |
