# 服务端-统一短信验证码服务与多渠道通知发送网关 - 详细设计

> **模块定位：** 基础设施层 / 通知服务  
> **文档版本：** 1.0  
> **最后更新：** 2026-06-17  
> **依赖模块：** 用户服务、认证授权、消息与推送服务、风控引擎、支付服务

---

## 1. 模块概述

### 1.1 背景与目标

PrimeTop 作为面向全学段的 AI 辅助学习产品，在用户注册登录、身份核验、支付安全、家长提醒等多个场景中依赖短信能力。国内短信发送受工信部监管约束，需使用经过审批的短信签名和模板，且对发送频率、内容合规有严格要求。

本模块提供**统一的短信发送网关**，屏蔽底层多供应商差异，实现：

1. **验证码短信**：注册/登录验证码、身份核验验证码、支付确认验证码
2. **通知短信**：学习提醒、安全告警、订单通知（仅在用户未开启 APP Push 或 Push 投递失败时降级发送）
3. **营销短信**：运营活动通知（仅限已同意接收营销消息的用户）

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 多供应商容灾 | 主备双通道自动切换，避免单一供应商故障导致服务中断 |
| 合规优先 | 短信签名和模板必须预审批，发送内容不超出备案范围 |
| 防刷限流 | 验证码场景实施严格的频率控制和用量上限 |
| 成本可控 | 实时统计发送量与成本，超预算自动告警 |
| 可观测 | 全链路发送日志，支持按手机号、模板、时间范围查询 |

### 1.3 与现有模块的关系

本模块聚焦于**短信（SMS）渠道**的发送能力。APP Push 通知由 `消息与推送服务` 模块负责，端内消息由 `通知中心与站内消息系统` 负责。本模块作为通知投递链路中的 SMS 通道提供者，被上层消息服务按需调用。

## 2. 数据结构定义

### 2.1 短信模板表 `sms_templates`

```sql
CREATE TABLE sms_templates (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '自增主键',
    template_code   VARCHAR(64) NOT NULL UNIQUE COMMENT '内部模板编码，如 VERIFY_REGISTER',
    template_name   VARCHAR(128) NOT NULL COMMENT '模板名称',
    scene_code      VARCHAR(32) NOT NULL COMMENT '业务场景',
    content_template TEXT NOT NULL COMMENT '模板内容，变量用 ${var} 表示',
    variables       JSON NOT NULL COMMENT '变量定义列表',
    description     VARCHAR(512) DEFAULT NULL COMMENT '模板说明',

    -- 供应商模板审批信息（一个内部模板需在各供应商分别审批）
    provider_configs JSON NOT NULL COMMENT '各供应商已审批模板配置',

    -- 状态：DRAFT→PENDING→APPROVED/REJECTED→RETIRED
    status          VARCHAR(16) NOT NULL DEFAULT 'DRAFT',
    review_remark   VARCHAR(512) DEFAULT NULL COMMENT '审批备注',

    created_by      BIGINT NOT NULL COMMENT '创建人ID',
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),

    INDEX idx_scene_code (scene_code),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='短信模板';
```

```json
  "tencent": {
    "template_id": 12345,
    "sign_name": "启硕",
    "status": "APPROVED",
```

### 2.2 短信发送记录表 `sms_send_logs`

```sql

    phone_hash      VARCHAR(64) NOT NULL COMMENT '手机号SHA256哈希（用于检索）',
    phone_suffix    VARCHAR(4) NOT NULL COMMENT '手机号后4位（展示用）',

    template_code   VARCHAR(64) NOT NULL COMMENT '使用的模板编码',
    scene_code      VARCHAR(32) NOT NULL COMMENT '业务场景',
    rendered_content TEXT NOT NULL COMMENT '渲染后内容（验证码用******替代）',

    provider        VARCHAR(16) NOT NULL COMMENT '发送供应商：ALIYUN/TENCENT/HUAWEI',
    provider_biz_id VARCHAR(64) DEFAULT NULL COMMENT '供应商返回的业务流水号',

    error_message   VARCHAR(256) DEFAULT NULL,
    retry_count     INT NOT NULL DEFAULT 0,

    cost_cents      INT DEFAULT NULL COMMENT '单条费用（分）',

    sent_at         DATETIME(3) DEFAULT NULL COMMENT '提交供应商时间',
    delivered_at    DATETIME(3) DEFAULT NULL COMMENT '收到送达回执时间',
    failed_at       DATETIME(3) DEFAULT NULL,
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),

    biz_ref_type    VARCHAR(32) DEFAULT NULL COMMENT '业务关联类型',
    biz_ref_id      VARCHAR(64) DEFAULT NULL COMMENT '业务关联ID',
    ip_address      VARCHAR(45) DEFAULT NULL,
    device_id       VARCHAR(64) DEFAULT NULL,

    INDEX idx_phone_hash_created (phone_hash, created_at),
    INDEX idx_scene_created (scene_code, created_at),
    INDEX idx_provider_status (provider, send_status),
    INDEX idx_biz_ref (biz_ref_type, biz_ref_id),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='短信发送记录';
```

> **隐私说明：** 手机号不存明文，仅存储 SHA256 哈希用于检索及后4位用于界面展示。完整手机号在发送时从用户服务实时获取，发送后不持久化明文。

## 3. API 接口设计

### 3.1 发送验证码

```
POST /api/v1/sms/verification-code/send
```

**请求体：**

```json
{
  "phone": "13800138000",
  "scene": "VERIFY_REGISTER",
  "captcha_token": "t03a2b...",
  "device_id": "device_fp_abc123"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | string | 是 | 手机号（带国际区号，默认 +86） |
| scene | string | 是 | 场景编码 |
| captcha_token | string | 是 | 人机验证Token（前端先通过极验/腾讯Captcha） |
| device_id | string | 否 | 设备指纹（风控辅助） |

**成功响应 (200)：**

```json
{
  "code": 0,
  "data": {
    "verify_id": "01HZX8KQRTP5N9V3WBYJ7MCFDQ",
    "phone_suffix": "****8000",
    "expires_in": 300,
    "next_send_in": 60
  }
}
```

**错误响应：**

| HTTP | code | 说明 |
|------|------|------|
| 429 | 42901 | 该手机号发送过于频繁 |
| 429 | 42902 | 该IP发送量超限 |
| 429 | 42903 | 该场景今日发送量超限 |
| 400 | 40001 | 手机号格式错误 |
| 400 | 40002 | 人机验证失败 |
| 409 | 40901 | 该手机号已注册（注册场景） |
| 503 | 50301 | 短信通道暂时不可用 |

### 3.2 验证验证码

```
POST /api/v1/sms/verification-code/verify
```

**请求体：**

```json
{
  "verify_id": "01HZX8KQRTP5N9V3WBYJ7MCFDQ",
  "phone": "13800138000",
  "code": "836291",
  "scene": "VERIFY_REGISTER"
}
```

**成功响应：**

```json
{
  "code": 0,
  "data": {
    "verify_token": "vt_01HZX8KW2RT5N9V3WBYJ7MD6AB",
    "verified_at": "2026-06-17T07:35:00.000Z"
  }
}
```

> `verify_token` 为一次性令牌，有效期 10 分钟。业务方（如注册接口）需校验此 token 后完成后续操作。

**错误响应：**

| HTTP | code | 说明 |
|------|------|------|
| 400 | 40010 | 验证码错误 |
| 400 | 40011 | 验证码已过期 |
| 400 | 40012 | 验证码已使用 |
| 429 | 42910 | 验证尝试次数过多，验证码已失效 |
| 404 | 40401 | verify_id 不存在 |

## 4. 核心业务流程

### 4.1 验证码发送完整流程

```
客户端                      API网关                    短信服务                    
  │                           │                          │
  │  1. POST /sms/verify/send │                          │
  │  (phone, scene, captcha)  │                          │
  │──────────────────────────>│                          │
  │                           │  2. 鉴权 + 人机验证Token校验  │
  │                           │                          │
  │                           │  3. 转发请求              │
  │                           │─────────────────────────>│
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  4. 频率检查           │
  │                           │              │  (Redis: phone+scene) │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  5. 业务前置检查        │
  │                           │              │  注册场景: 手机号未注册  │
  │                           │              │  登录场景: 手机号已注册  │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  6. 生成6位验证码       │
  │                           │              │  BCrypt哈希存储        │
  │                           │              │  设置有效期5分钟       │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  7. 选择发送通道       │
  │                           │              │  主通道(阿里云)→      │
  │                           │              │  备通道(腾讯云)       │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  8. 渲染模板+调用API   │
  │                           │              │  记录发送日志         │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │  9. 返回 verify_id        │                          │
  │  + expires_in=300         │                          │
  │  + next_send_in=60        │                          │
  │<──────────────────────────│<─────────────────────────│
  │                           │                          │
```

### 4.3 验证码状态流转

```
    ┌───────┐
    │CREATED│ (验证码生成，写入DB)
    └───┬───┘
        │
        ▼
   ┌────────┐  用户输入正确    ┌──────────┐
   │ ACTIVE ├────────────────>│ VERIFIED │ (签发verify_token)
   └────┬───┘                  └─────┬────┘
        │                            │
        │ 超过有效期                  │ 上游业务消费token
```

### 5.1 频率控制策略

采用**多维度限流**，在 Redis 中使用滑动窗口计数器实现：

```java
/**
 * 短信发送频率控制器
 * 基于 Redis 滑动窗口实现多维度限流
 */
@Component
public class SmsRateLimiter {

    @Autowired
    private StringRedisTemplate redis;

    // ── 限流规则定义 ──
    // 维度1: 同一手机号 + 同一场景
    private static final int PHONE_SCENE_WINDOW = 60;   // 60秒
    private static final int PHONE_SCENE_MAX = 1;       // 60秒内最多1次

    // 维度2: 同一手机号（所有场景）
    private static final int PHONE_WINDOW = 3600;       // 1小时
    private static final int PHONE_MAX = 5;             // 1小时内最多5次

    // 维度3: 同一IP
    private static final int IP_WINDOW = 3600;          // 1小时
    private static final int IP_MAX = 20;               // 1小时内最多20次

    // 维度4: 同一场景（全局）
    private static final int SCENE_WINDOW = 86400;      // 24小时
    private static final int SCENE_MAX = 10000;         // 场景日上限

    /**
     * 检查是否允许发送
     * @return null=允许, 否则返回被限流的规则名
     */
    public String checkRate(String phoneHash, String ip, String sceneCode) {
        List<RateRule> rules = List.of(
            new RateRule("PHONE_SCENE",
                "sms:rl:ps:" + phoneHash + ":" + sceneCode,
                PHONE_SCENE_WINDOW, PHONE_SCENE_MAX),
            new RateRule("PHONE",
                "sms:rl:p:" + phoneHash,
                PHONE_WINDOW, PHONE_MAX),
            new RateRule("IP",
                "sms:rl:ip:" + ip,
                IP_WINDOW, IP_MAX),
            new RateRule("SCENE",
                "sms:rl:sc:" + sceneCode,
                SCENE_WINDOW, SCENE_MAX)
        );

        for (RateRule rule : rules) {
            if (!tryAcquire(rule.key, rule.windowSeconds, rule.maxCount)) {
                return rule.name;
            }
        }
        return null; // 全部通过
    }

    /**
     * Redis 滑动窗口计数
     */
    private boolean tryAcquire(String key, int windowSeconds, int maxCount) {
        long now = System.currentTimeMillis();
        long windowStart = now - windowSeconds * 1000L;

        // Lua 脚本保证原子性
        String luaScript = """
            local key = KEYS[1]
            local now = tonumber(ARGV[1])
            local windowStart = tonumber(ARGV[2])
            local maxCount = tonumber(ARGV[3])
            local ttl = tonumber(ARGV[4])

            -- 移除窗口外的记录
            redis.call('ZREMRANGEBYSCORE', key, 0, windowStart)

            -- 获取当前计数
            local current = redis.call('ZCARD', key)

            if current >= maxCount then
                return 0  -- 被限流
            end

            -- 添加当前请求
            redis.call('ZADD', key, now, now .. '-' .. math.random(1000000))
            redis.call('EXPIRE', key, ttl)
            return 1  -- 允许
        """;

        Long result = redis.execute(
            (RedisCallback<Long>) connection -> connection.eval(
                luaScript.getBytes(),
                ReturnType.INTEGER,
                1,
                key.getBytes(),
                String.valueOf(now).getBytes(),
                String.valueOf(windowStart).getBytes(),
                String.valueOf(maxCount).getBytes(),
                String.valueOf(windowSeconds + 10).getBytes()
            )
        );

        return result != null && result == 1;
    }

    // 如果发送失败(供应商原因)，退还限流计数
    public void refundQuota(String phoneHash, String ip, String sceneCode) {
        // 在实际实现中，可以选择是否退还。
        // 建议：验证码场景不退还（防止刷接口），通知场景退还
    }

    private record RateRule(String name, String key, int windowSeconds, int maxCount) {}
}
```

### 5.2 通道选择与降级策略

```java
/**
 * 短信发送通道选择器
 */
@Component
public class SmsChannelSelector {

    @Autowired
    private SmsProviderConfigRepository providerRepo;

    // 供应商连续失败阈值，超过则标记降级
    private static final int DEGRADE_FAIL_THRESHOLD = 5;

    // 降级冷却时间（秒）
    private static final int DEGRADE_COOLDOWN = 300;

    /**
     * 选择发送通道
     * 按优先级排序 → 过滤不可用 → 检查日额度 → 返回最优通道
     */
    public SmsProviderConfig selectChannel(String sceneCode) {
        List<SmsProviderConfig> providers = providerRepo.findEnabledOrderByPriority();

        for (SmsProviderConfig provider : providers) {
            // 跳过不健康的供应商
            if ("DOWN".equals(provider.getHealthStatus())) {
                continue;
            }
            if ("DEGRADED".equals(provider.getHealthStatus())) {
                // 检查冷却时间是否已过
                if (!isCooldownExpired(provider)) {
                    continue;
                }
            }

            // 检查日额度
            if (provider.getDailyQuota() != null
                && provider.getDailySent() >= provider.getDailyQuota()) {
                continue;
            }

            // 检查该供应商是否有当前场景的已审批模板
            if (!hasApprovedTemplate(provider, sceneCode)) {
                continue;
            }

            return provider;
        }

        throw new SmsChannelUnavailableException("所有短信通道均不可用");
    }

    /**
     * 记录发送结果，更新供应商健康状态
     */
    @Transactional
    public void recordSendResult(String providerCode, boolean success, String errorCode) {
        // 更新日发送计数
        providerRepo.incrementDailySent(providerCode);

        // 连续失败检测
        String failKey = "sms:provider:fail:" + providerCode;
        if (success) {
            redis.delete(failKey);
        } else {
            Long failCount = redis.opsForValue().increment(failKey);
            redis.expire(failKey, Duration.ofMinutes(10));

            if (failCount != null && failCount >= DEGRADE_FAIL_THRESHOLD) {
                providerRepo.updateHealthStatus(providerCode, "DEGRADED");
                // 发布降级事件，触发告警
                eventBus.publish(new ProviderDegradedEvent(providerCode, failCount));
                log.warn("供应商 {} 连续失败{}次，已降级", providerCode, failCount);
            }
        }
    }

    private boolean isCooldownExpired(SmsProviderConfig provider) {
        if (provider.getLastCheckAt() == null) return true;
        return Duration.between(provider.getLastCheckAt().toInstant(),
                                Instant.now()).getSeconds() > DEGRADE_COOLDOWN;
    }
}
```

### 5.3 验证码生成与校验

```java
/**
 * 验证码引擎
 */
@Component
public class VerificationCodeEngine {

    @Autowired
    private SmsVerificationCodeRepository codeRepo;

    @Autowired
    private PasswordEncoder passwordEncoder; // BCrypt

    private static final SecureRandom RANDOM = new SecureRandom();
    private static final int CODE_LENGTH = 6;
    private static final Duration CODE_TTL = Duration.ofMinutes(5);

    /**
     * 生成验证码
     */
    public SmsVerificationCode generateCode(String phone, String sceneCode,
                                            String ip, String deviceId) {
        // 1. 检查是否有未过期的有效验证码（避免重复生成）
        Optional<SmsVerificationCode> existing = codeRepo
            .findActiveByPhoneAndScene(hashPhone(phone), sceneCode);
        if (existing.isPresent() && existing.get().getAttemptCount() == 0) {
            // 首次请求且验证码仍有效，重用（但不重新发送——由调用方决定）
            throw new CodeStillActiveException(existing.get().getVerifyId(),
                existing.get().getExpiresAt());
        }

        // 2. 生成6位数字验证码
        String code = generateNumericCode(CODE_LENGTH);

        // 3. 构建实体（只存哈希）
        SmsVerificationCode entity = new SmsVerificationCode();
        entity.setVerifyId(ULID.next());
        entity.setPhoneHash(hashPhone(phone));
        entity.setPhoneSuffix(phone.substring(phone.length() - 4));
        entity.setCodeHash(passwordEncoder.encode(code));
        entity.setSceneCode(sceneCode);
        entity.setStatus("ACTIVE");
        entity.setMaxAttempts(5);
        entity.setExpiresAt(LocalDateTime.now().plus(CODE_TTL));
        entity.setIpAddress(ip);
        entity.setDeviceId(deviceId);

        codeRepo.save(entity);

        // 4. 返回包含明文的临时对象（仅用于本次发送）
        return entity.withPlainCode(code);
    }

    /**
     * 校验验证码
     */
    @Transactional
    public VerifyResult verify(String verifyId, String phone, String inputCode,
                               String sceneCode) {
        // 1. 查找验证码记录
        SmsVerificationCode record = codeRepo.findByVerifyId(verifyId)
            .orElseThrow(() -> new VerifyNotFoundException(verifyId));

        // 2. 状态校验
        if (!"ACTIVE".equals(record.getStatus())) {
            return VerifyResult.fail("CODE_INVALID",
                "验证码状态为: " + record.getStatus());
        }

        // 3. 过期检查
        if (record.getExpiresAt().isBefore(LocalDateTime.now())) {
            record.setStatus("EXPIRED");
            codeRepo.save(record);
            return VerifyResult.fail("CODE_EXPIRED", "验证码已过期");
        }

        // 4. 尝试次数检查
        if (record.getAttemptCount() >= record.getMaxAttempts()) {
            record.setStatus("CANCELLED");
            codeRepo.save(record);
            return VerifyResult.fail("MAX_ATTEMPTS", "验证尝试次数过多");
        }

        // 5. 手机号匹配检查
        if (!record.getPhoneHash().equals(hashPhone(phone))) {
            codeRepo.incrementAttemptCount(verifyId);
            return VerifyResult.fail("PHONE_MISMATCH", "手机号不匹配");
        }

        // 6. BCrypt 比对
        if (!passwordEncoder.matches(inputCode, record.getCodeHash())) {
            int newAttemptCount = codeRepo.incrementAttemptCount(verifyId);

            // 达到上限则自动失效
            if (newAttemptCount >= record.getMaxAttempts()) {
                codeRepo.updateStatus(verifyId, "CANCELLED");
            }
            return VerifyResult.fail("CODE_WRONG",
                "验证码错误，剩余尝试次数: " + (record.getMaxAttempts() - newAttemptCount));
        }

        // 7. 验证成功
        record.setStatus("VERIFIED");
        record.setVerifiedAt(LocalDateTime.now());
        codeRepo.save(record);

        // 8. 签发一次性 verify_token
        String verifyToken = generateVerifyToken(record);

        return VerifyResult.success(verifyToken);
    }

    /**
     * 上游业务消费 verify_token 后，标记为 USED
     */
    @Transactional
    public void consumeToken(String verifyToken) {
        // 解析token获取verify_id
        String verifyId = parseVerifyToken(verifyToken);

        SmsVerificationCode record = codeRepo.findByVerifyId(verifyId)
            .orElseThrow(() -> new VerifyNotFoundException(verifyId));

        if (!"VERIFIED".equals(record.getStatus())) {
            throw new IllegalStateException("验证码状态不允许消费: " + record.getStatus());
        }

        record.setStatus("USED");
        codeRepo.save(record);
    }

    private String generateNumericCode(int length) {
        StringBuilder sb = new StringBuilder(length);
        for (int i = 0; i < length; i++) {
            sb.append(RANDOM.nextInt(10));
        }
        return sb.toString();
    }

    private String hashPhone(String phone) {
        return DigestUtils.sha256Hex(phone);
    }

    private String generateVerifyToken(SmsVerificationCode record) {
        // JWT格式，包含verify_id + phone_hash + scene + 过期时间
        return Jwts.builder()
            .setSubject(record.getVerifyId())
            .claim("phone_hash", record.getPhoneHash())
            .claim("scene", record.getSceneCode())
            .setExpiration(Date.from(Instant.now().plus(10, ChronoUnit.MINUTES)))
            .signWith(signingKey)
            .compact();
    }
}
```
