# 服务端-统一短信验证码服务与多渠道通知发送网关 - 详细设计

> **模块定位：** 基础设施层 / 通知服务  
> **文档版本：** 1.1  
> **最后更新：** 2026-08-16  
> **依赖模块：** 用户服务、认证授权、消息与推送服务、风控引擎、支付服务

---

## 1. 模块概述

### 1.1 背景与目标

PrimeTop 作为面向全学段的 AI 辅助学习产品，在用户注册登录、身份核验、支付安全、家长提醒等多个场景中依赖短信能力。国内短信发送受工信部监管约束，需使用经过审批的短信签名和模板，且对发送频率、内容合规有严格要求。

本模块提供**统一的短信发送网关**，屏蔽底层多供应商差异，实现：

1. **验证码短信**：注册/登录验证码、身份核验验证码、支付确认验证码
2. **通知短信**：学习提醒、安全告警、订单通知（仅在用户未开启 APP Push 或 Push 投递失败时降级发送）
3. **营销短信**：运营活动通知（仅限已同意接收营销消息的用户）

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 多供应商容灾 | 主备双通道自动切换，避免单一供应商故障导致服务中断 |
| 合规优先 | 短信签名和模板必须预审批，发送内容不超出备案范围 |
| 防刷限流 | 验证码场景实施严格的频率控制和用量上限 |
| 成本可控 | 实时统计发送量与成本，超预算自动告警 |
| 可观测 | 全链路发送日志，支持按手机号、模板、时间范围查询 |

### 1.3 与现有模块的关系

本模块聚焦于**短信（SMS）渠道**的发送能力。APP Push 通知由 `消息与推送服务` 模块负责，端内消息由 `通知中心与站内消息系统` 负责。本模块作为通知投递链路中的 SMS 通道提供者，被上层消息服务按需调用。

## 2. 数据结构定义

### 2.1 短信模板表 `sms_templates`

```sql
CREATE TABLE sms_templates (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '自增主键',
    template_code   VARCHAR(64) NOT NULL UNIQUE COMMENT '内部模板编码，如 VERIFY_REGISTER',
    template_name   VARCHAR(128) NOT NULL COMMENT '模板名称',
    scene_code      VARCHAR(32) NOT NULL COMMENT '业务场景',
    content_template TEXT NOT NULL COMMENT '模板内容，变量用 ${var} 表示',
    variables       JSON NOT NULL COMMENT '变量定义列表',
    description     VARCHAR(512) DEFAULT NULL COMMENT '模板说明',

    -- 供应商模板审批信息（一个内部模板需在各供应商分别审批）
    provider_configs JSON NOT NULL COMMENT '各供应商已审批模板配置',

    -- 状态：DRAFT→PENDING→APPROVED/REJECTED→RETIRED
    status          VARCHAR(16) NOT NULL DEFAULT 'DRAFT',
    review_remark   VARCHAR(512) DEFAULT NULL COMMENT '审批备注',

    created_by      BIGINT NOT NULL COMMENT '创建人ID',
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),

    INDEX idx_scene_code (scene_code),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='短信模板';
```

```sql
    phone_suffix    VARCHAR(4) NOT NULL COMMENT '手机号后4位（展示用）',

    template_code   VARCHAR(64) NOT NULL COMMENT '使用的模板编码',

    rendered_content TEXT NOT NULL COMMENT '渲染后内容（验证码用******替代）',

    provider        VARCHAR(16) NOT NULL COMMENT '发送供应商：ALIYUN/TENCENT/HUAWEI',
    provider_biz_id VARCHAR(64) DEFAULT NULL COMMENT '供应商返回的业务流水号',

    sent_at         DATETIME(3) DEFAULT NULL COMMENT '提交供应商时间',
    delivered_at    DATETIME(3) DEFAULT NULL COMMENT '收到送达回执时间',
    failed_at       DATETIME(3) DEFAULT NULL,
    created_at      DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),

    biz_ref_type    VARCHAR(32) DEFAULT NULL COMMENT '业务关联类型',
    biz_ref_id      VARCHAR(64) DEFAULT NULL COMMENT '业务关联ID',
    ip_address      VARCHAR(45) DEFAULT NULL,
    device_id       VARCHAR(64) DEFAULT NULL,

    INDEX idx_phone_hash_created (phone_hash, created_at),
    INDEX idx_scene_created (scene_code, created_at),
    INDEX idx_provider_status (provider, send_status),
    INDEX idx_biz_ref (biz_ref_type, biz_ref_id),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='短信发送记录';
```

> **隐私说明：** 手机号不存明文，仅存储 SHA256 哈希用于检索及后4位用于界面展示。完整手机号在发送时从用户服务实时获取，发送后不持久化明文。

## 3. API 接口设计

### 3.1 发送验证码

```
POST /api/v1/sms/verification-code/send
```

**请求体：**

```json
{
  "phone": "13800138000",
  "scene": "VERIFY_REGISTER",
  "captcha_token": "t03a2b...",
  "device_id": "device_fp_abc123"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | string | 是 | 手机号（带国际区号，默认 +86） |
| scene | string | 是 | 场景编码 |
| captcha_token | string | 是 | 人机验证Token（前端先通过极验/腾讯Captcha） |
| device_id | string | 否 | 设备指纹（风控辅助） |

**成功响应 (200)：**

```json
{
  "code": 0,
  "data": {
    "verify_id": "01HZX8KQRTP5N9V3WBYJ7MCFDQ",
    "phone_suffix": "****8000",
    "expires_in": 300,
    "next_send_in": 60
  }
}
```

**错误响应：**

| HTTP | code | 说明 |
|------|------|------|
| 429 | 42901 | 该手机号发送过于频繁 |
| 429 | 42902 | 该IP发送量超限 |
| 429 | 42903 | 该场景今日发送量超限 |
| 400 | 40001 | 手机号格式错误 |
| 400 | 40002 | 人机验证失败 |
| 409 | 40901 | 该手机号已注册（注册场景） |
| 503 | 50301 | 短信通道暂时不可用 |

### 3.2 验证验证码

```
POST /api/v1/sms/verification-code/verify
```

**请求体：**

```json
{
  "verify_id": "01HZX8KQRTP5N9V3WBYJ7MCFDQ",
  "phone": "13800138000",
  "code": "836291",
  "scene": "VERIFY_REGISTER"
}
```

**成功响应：**

```json
{
  "code": 0,
  "data": {
    "verify_token": "vt_01HZX8KW2RT5N9V3WBYJ7MD6AB",
    "verified_at": "2026-06-17T07:35:00.000Z"
  }
}
```

> `verify_token` 为一次性令牌，有效期 10 分钟。业务方（如注册接口）需校验此 token 后完成后续操作。

**错误响应：**

| HTTP | code | 说明 |
|------|------|------|
| 400 | 40010 | 验证码错误 |
| 400 | 40011 | 验证码已过期 |
| 400 | 40012 | 验证码已使用 |
| 429 | 42910 | 验证尝试次数过多，验证码已失效 |
| 404 | 40401 | verify_id 不存在 |

## 4. 核心业务流程

### 4.1 验证码发送完整流程

```
客户端                      API网关                    短信服务                    
  │                           │                          │
  │  1. POST /sms/verify/send │                          │
  │  (phone, scene, captcha)  │                          │
  │──────────────────────────>│                          │
  │                           │  2. 鉴权 + 人机验证Token校验  │
  │                           │                          │
  │                           │  3. 转发请求              │
  │                           │─────────────────────────>│
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  4. 频率检查           │
  │                           │              │  (Redis: phone+scene) │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  5. 业务前置检查        │
  │                           │              │  注册场景: 手机号未注册  │
  │                           │              │  登录场景: 手机号已注册  │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  6. 生成6位验证码       │
  │                           │              │  BCrypt哈希存储        │
  │                           │              │  设置有效期5分钟       │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  7. 选择发送通道       │
  │                           │              │  主通道(阿里云)→      │
  │                           │              │  备通道(腾讯云)       │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │                           │              ┌───────────┴───────────┐
  │                           │              │  8. 渲染模板+调用API   │
  │                           │              │  记录发送日志         │
  │                           │              └───────────┬───────────┘
  │                           │                          │
  │  9. 返回 verify_id        │                          │
  │  + expires_in=300         │                          │
  │  + next_send_in=60        │                          │
  │<──────────────────────────│<─────────────────────────│
  │                           │                          │
```

### 4.3 验证码状态流转

```
    ┌───────┐
    │CREATED│ (验证码生成，写入DB)
    └───┬───┘
        │
        ▼
   ┌────────┐  用户输入正确    ┌──────────┐
   │ ACTIVE ├────────────────>│ VERIFIED │ (签发verify_token)
   └────┬───┘                  └─────┬────┘
        │                            │
        │ 超过有效期                  │ 上游业务消费token
```

### 5.1 频率控制策略

采用**多维度限流**，在 Redis 中使用滑动窗口计数器实现：

```java
/**
 * 短信发送频率控制器
 * 基于 Redis 滑动窗口实现多维度限流
 */
@Component
public class SmsRateLimiter {

    @Autowired
    private StringRedisTemplate redis;

    // ── 限流规则定义 ──
    // 维度1: 同一手机号 + 同一场景
    private static final int PHONE_SCENE_WINDOW = 60;   // 60秒
    private static final int PHONE_SCENE_MAX = 1;       // 60秒内最多1次

    // 维度2: 同一手机号（所有场景）
    private static final int PHONE_WINDOW = 3600;       // 1小时
    private static final int PHONE_MAX = 5;             // 1小时内最多5次

    // 维度3: 同一IP
    private static final int IP_WINDOW = 3600;          // 1小时
    private static final int IP_MAX = 20;               // 1小时内最多20次

    // 维度4: 同一场景（全局）
    private static final int SCENE_WINDOW = 86400;      // 24小时
    private static final int SCENE_MAX = 10000;         // 场景日上限

    /**
     * 检查是否允许发送
     * @return null=允许, 否则返回被限流的规则名
     */
    public String checkRate(String phoneHash, String ip, String sceneCode) {
        List<RateRule> rules = List.of(
            new RateRule("PHONE_SCENE",
                "sms:rl:ps:" + phoneHash + ":" + sceneCode,
                PHONE_SCENE_WINDOW, PHONE_SCENE_MAX),
            new RateRule("PHONE",
                "sms:rl:p:" + phoneHash,
                PHONE_WINDOW, PHONE_MAX),
            new RateRule("IP",
                "sms:rl:ip:" + ip,
                IP_WINDOW, IP_MAX),
            new RateRule("SCENE",
                "sms:rl:sc:" + sceneCode,
                SCENE_WINDOW, SCENE_MAX)
        );

        for (RateRule rule : rules) {
            if (!tryAcquire(rule.key, rule.windowSeconds, rule.maxCount)) {
                return rule.name;
            }
        }
        return null; // 全部通过
    }

    /**
     * Redis 滑动窗口计数
     */
    private boolean tryAcquire(String key, int windowSeconds, int maxCount) {
        long now = System.currentTimeMillis();
        long windowStart = now - windowSeconds * 1000L;

        // Lua 脚本保证原子性
        String luaScript = """
            local key = KEYS[1]
            local now = tonumber(ARGV[1])
            local windowStart = tonumber(ARGV[2])
            local maxCount = tonumber(ARGV[3])
            local ttl = tonumber(ARGV[4])

            -- 移除窗口外的记录
            redis.call('ZREMRANGEBYSCORE', key, 0, windowStart)

            -- 获取当前计数
            local current = redis.call('ZCARD', key)

            if current >= maxCount then
                return 0  -- 被限流
            end

            -- 添加当前请求
            redis.call('ZADD', key, now, now .. '-' .. math.random(1000000))
            redis.call('EXPIRE', key, ttl)
            return 1  -- 允许
        """;

        Long result = redis.execute(
            (RedisCallback<Long>) connection -> connection.eval(
                luaScript.getBytes(),
                ReturnType.INTEGER,
                1,
                key.getBytes(),
                String.valueOf(now).getBytes(),
                String.valueOf(windowStart).getBytes(),
                String.valueOf(maxCount).getBytes(),
                String.valueOf(windowSeconds + 10).getBytes()
            )
        );

        return result != null && result == 1;
    }

    // 如果发送失败(供应商原因)，退还限流计数
    public void refundQuota(String phoneHash, String ip, String sceneCode) {
        // 在实际实现中，可以选择是否退还。
        // 建议：验证码场景不退还（防止刷接口），通知场景退还
    }

    private record RateRule(String name, String key, int windowSeconds, int maxCount) {}
}
```

```java
/**
 * 短信发送通道选择器

@Component
public class SmsChannelSelector {

    @Autowired
    private SmsProviderConfigRepository providerRepo;

    // 供应商连续失败阈值，超过则标记降级
    private static final int DEGRADE_FAIL_THRESHOLD = 5;

    // 降级冷却时间（秒）
    private static final int DEGRADE_COOLDOWN = 300;

    /**
     * 选择发送通道
     * 按优先级排序 → 过滤不可用 → 检查日额度 → 返回最优通道
     */
    public SmsProviderConfig selectChannel(String sceneCode) {
        List<SmsProviderConfig> providers = providerRepo.findEnabledOrderByPriority();

        for (SmsProviderConfig provider : providers) {
            // 跳过不健康的供应商
            if ("DOWN".equals(provider.getHealthStatus())) {
                continue;
            }
            if ("DEGRADED".equals(provider.getHealthStatus())) {
                // 检查冷却时间是否已过
                if (!isCooldownExpired(provider)) {
                    continue;
                }
            }

            // 检查日额度
            if (provider.getDailyQuota() != null
                && provider.getDailySent() >= provider.getDailyQuota()) {
                continue;
            }

            // 检查该供应商是否有当前场景的已审批模板
            if (!hasApprovedTemplate(provider, sceneCode)) {
                continue;
            }

            return provider;
        }

        throw new SmsChannelUnavailableException("所有短信通道均不可用");
    }

    /**
     * 记录发送结果，更新供应商健康状态
     */
    @Transactional
    public void recordSendResult(String providerCode, boolean success, String errorCode) {
        // 更新日发送计数
        providerRepo.incrementDailySent(providerCode);

        // 连续失败检测
        String failKey = "sms:provider:fail:" + providerCode;
        if (success) {
            redis.delete(failKey);
        } else {
            Long failCount = redis.opsForValue().increment(failKey);
            redis.expire(failKey, Duration.ofMinutes(10));

            if (failCount != null && failCount >= DEGRADE_FAIL_THRESHOLD) {
                providerRepo.updateHealthStatus(providerCode, "DEGRADED");
                // 发布降级事件，触发告警
                eventBus.publish(new ProviderDegradedEvent(providerCode, failCount));
                log.warn("供应商 {} 连续失败{}次，已降级", providerCode, failCount);
            }
        }
    }

    private boolean isCooldownExpired(SmsProviderConfig provider) {
        if (provider.getLastCheckAt() == null) return true;
        return Duration.between(provider.getLastCheckAt().toInstant(),
                                Instant.now()).getSeconds() > DEGRADE_COOLDOWN;
    }
}
```

### 5.3 验证码生成与校验

```java
/**
 * 验证码引擎
 */
@Component
public class VerificationCodeEngine {

    @Autowired
    private SmsVerificationCodeRepository codeRepo;

    @Autowired
    private PasswordEncoder passwordEncoder; // BCrypt

    private static final SecureRandom RANDOM = new SecureRandom();
    private static final int CODE_LENGTH = 6;
    private static final Duration CODE_TTL = Duration.ofMinutes(5);

    /**
     * 生成验证码
     */
    public SmsVerificationCode generateCode(String phone, String sceneCode,
                                            String ip, String deviceId) {
        // 1. 检查是否有未过期的有效验证码（避免重复生成）
        Optional<SmsVerificationCode> existing = codeRepo
            .findActiveByPhoneAndScene(hashPhone(phone), sceneCode);
        if (existing.isPresent() && existing.get().getAttemptCount() == 0) {
            // 首次请求且验证码仍有效，重用（但不重新发送——由调用方决定）
            throw new CodeStillActiveException(existing.get().getVerifyId(),
                existing.get().getExpiresAt());
        }

        // 2. 生成6位数字验证码
        String code = generateNumericCode(CODE_LENGTH);

        // 3. 构建实体（只存哈希）
        SmsVerificationCode entity = new SmsVerificationCode();
        entity.setVerifyId(ULID.next());
        entity.setPhoneHash(hashPhone(phone));
        entity.setPhoneSuffix(phone.substring(phone.length() - 4));
        entity.setCodeHash(passwordEncoder.encode(code));
        entity.setSceneCode(sceneCode);
        entity.setStatus("ACTIVE");
        entity.setMaxAttempts(5);
        entity.setExpiresAt(LocalDateTime.now().plus(CODE_TTL));
        entity.setIpAddress(ip);
        entity.setDeviceId(deviceId);

        codeRepo.save(entity);

        // 4. 返回包含明文的临时对象（仅用于本次发送）
        return entity.withPlainCode(code);
    }

    /**
     * 校验验证码
     */
    @Transactional
    public VerifyResult verify(String verifyId, String phone, String inputCode,
                               String sceneCode) {
        // 1. 查找验证码记录
        SmsVerificationCode record = codeRepo.findByVerifyId(verifyId)
            .orElseThrow(() -> new VerifyNotFoundException(verifyId));

        // 2. 状态校验
        if (!"ACTIVE".equals(record.getStatus())) {
            return VerifyResult.fail("CODE_INVALID",
                "验证码状态为: " + record.getStatus());
        }

        // 3. 过期检查
        if (record.getExpiresAt().isBefore(LocalDateTime.now())) {
            record.setStatus("EXPIRED");
            codeRepo.save(record);
            return VerifyResult.fail("CODE_EXPIRED", "验证码已过期");
        }

        // 4. 尝试次数检查
        if (record.getAttemptCount() >= record.getMaxAttempts()) {
            record.setStatus("CANCELLED");
            codeRepo.save(record);
            return VerifyResult.fail("MAX_ATTEMPTS", "验证尝试次数过多");
        }

        // 5. 手机号匹配检查
        if (!record.getPhoneHash().equals(hashPhone(phone))) {
            codeRepo.incrementAttemptCount(verifyId);
            return VerifyResult.fail("PHONE_MISMATCH", "手机号不匹配");
        }

        // 6. BCrypt 比对
        if (!passwordEncoder.matches(inputCode, record.getCodeHash())) {
            int newAttemptCount = codeRepo.incrementAttemptCount(verifyId);

            // 达到上限则自动失效
            if (newAttemptCount >= record.getMaxAttempts()) {
                codeRepo.updateStatus(verifyId, "CANCELLED");
            }
            return VerifyResult.fail("CODE_WRONG",
                "验证码错误，剩余尝试次数: " + (record.getMaxAttempts() - newAttemptCount));
        }

        // 7. 验证成功
        record.setStatus("VERIFIED");
        record.setVerifiedAt(LocalDateTime.now());
        codeRepo.save(record);

        // 8. 签发一次性 verify_token
        String verifyToken = generateVerifyToken(record);

        return VerifyResult.success(verifyToken);
    }

    /**
     * 上游业务消费 verify_token 后，标记为 USED
     */
    @Transactional
    public void consumeToken(String verifyToken) {
        // 解析token获取verify_id
        String verifyId = parseVerifyToken(verifyToken);

        SmsVerificationCode record = codeRepo.findByVerifyId(verifyId)
            .orElseThrow(() -> new VerifyNotFoundException(verifyId));

        if (!"VERIFIED".equals(record.getStatus())) {
            throw new IllegalStateException("验证码状态不允许消费: " + record.getStatus());
        }

        record.setStatus("USED");
        codeRepo.save(record);
    }

    private String generateNumericCode(int length) {
        StringBuilder sb = new StringBuilder(length);
        for (int i = 0; i < length; i++) {
            sb.append(RANDOM.nextInt(10));
        }
        return sb.toString();
    }

    private String hashPhone(String phone) {
        return DigestUtils.sha256Hex(phone);
    }

    private String generateVerifyToken(SmsVerificationCode record) {
        // JWT格式，包含verify_id + phone_hash + scene + 过期时间
        return Jwts.builder()
            .setSubject(record.getVerifyId())
            .claim("phone_hash", record.getPhoneHash())
            .claim("scene", record.getSceneCode())
            .setExpiration(Date.from(Instant.now().plus(10, ChronoUnit.MINUTES)))
            .signWith(signingKey)
            .compact();
    }
}
```

```java
                .accessKeyId(props.getAccessKey())          // 来自 sms_provider_configs，KMS 解密后注入

                .connectTimeout(3000)
                .readTimeout(3000);
            this.client = new com.aliyun.dysmsapi20170525.Client(config);
        } catch (Exception e) {
            throw new IllegalStateException("阿里云短信客户端初始化失败", e);
        }
    }

    @Override
    public String providerCode() { return "ALIYUN"; }

    @Override
    public SmsSendResult send(SmsSendRequest request) {
        try {
            SendSmsRequest api = new SendSmsRequest()
                .setPhoneNumbers(request.getPhone())
                .setSignName(request.getSignName())
                .setTemplateCode(request.getProviderTemplateId())
                .setTemplateParam(JsonUtils.toJson(request.getTemplateVars()))
                .setOutId(request.getLogId());       // 我方流水号随回执带回

            SendSmsResponse resp = client.sendSms(api);
            String code = resp.getBody().getCode();

            if ("OK".equals(code)) {
                return SmsSendResult.ok(resp.getBody().getBizId());
            }
            return translateError(code, resp.getBody().getMessage());

        } catch (Exception e) {
            // 网络超时/连接失败：归一化为可重试错误，不抛出
            log.warn("[SMS] 阿里云调用异常 logId={}", request.getLogId(), e);
            return SmsSendResult.fail("NETWORK_ERROR", e.getMessage(), true);
        }
    }

    /** 阿里云错误码 → 归一化错误码映射（子集，持续维护） */
    private SmsSendResult translateError(String aliyunCode, String message) {
        return switch (aliyunCode) {
            case "isv.BUSINESS_LIMIT_CONTROL" ->      // 手机号频控（运营商/供应商侧）
                SmsSendResult.fail("PROVIDER_RATE_LIMIT", message, true);
            case "isv.BLACK_KEY_CONTROL_LIMIT",
                 "isv.SMS_CONTENT_ILLEGAL" ->
                SmsSendResult.fail("CONTENT_BLOCKED", message, false);
            case "isv.SMS_SIGNATURE_ILLEGAL" ->
                SmsSendResult.fail("SIGN_INVALID", message, false);
            case "isv.TEMPLATE_MISSING_PARAMETERS" ->
                SmsSendResult.fail("TEMPLATE_VARS_MISSING", message, false);
            case "isv.MOBILE_NUMBER_ILLEGAL" ->
                SmsSendResult.fail("PHONE_ILLEGAL", message, false);
            case "isv.AMOUNT_NOT_ENOUGH" ->          // 账户余额不足
                SmsSendResult.fail("PROVIDER_BALANCE_LOW", message, false);
            default ->
                SmsSendResult.fail("PROVIDER_UNKNOWN", aliyunCode + ": " + message, true);
        };
    }

    @Override
    public List<DeliveryReport> parseCallback(String payload, Map<String, String> headers) {
        // 阿里云状态报告经 MNS Queue 拉取后转投本服务，payload 示例：
        // [{"phone_number":"138****8000","success":true,"biz_id":"7000...",
        //   "out_id":"01HZ...","send_time":"2026-08-16 10:00:00",
        //   "report_time":"2026-08-16 10:00:03","err_code":"DELIVERED"}]
        List<Map<String, Object>> items = JsonUtils.parseArray(payload);
        return items.stream().map(item -> {
            DeliveryReport r = new DeliveryReport();
            r.setLogId((String) item.get("out_id"));
            r.setProviderBizId((String) item.get("biz_id"));
            r.setSuccess(Boolean.TRUE.equals(item.get("success")));
            r.setErrorCode((String) item.get("err_code"));
            r.setReportTime((String) item.get("report_time"));
            return r;
        }).toList();
    }
}
```

```java
        SendStatus status = resp.getSendStatusSet()[0];

        if ("Ok".equals(status.getCode())) {
            return SmsSendResult.ok(status.getSerialNo());
        }
        // 典型码：LimitExceeded.PhoneNumberDaily（号码日频控）/
        //         FailedOperation.ProvinceNotSupported / InvalidParameterValue PhoneNumber 格式错误
        boolean retryable = status.getCode().startsWith("LimitExceeded");
        return SmsSendResult.fail("PROVIDER_UNKNOWN", status.getCode() + ": " + status.getMessage(), retryable);
    } catch (Exception e) {
        return SmsSendResult.fail("NETWORK_ERROR", e.getMessage(), true);
    }
}
```

### 5.6 模板渲染与变量安全防线

模板渲染是短信内容合规的**最后一道程序化防线**，任何绕过渲染直接拼接内容的路径都是禁止的（代码评审红线）。

```java
@Component
public class TemplateRenderEngine {

    private static final Pattern VAR_PATTERN = Pattern.compile("\\$\\{([a-zA-Z0-9_]+)}");
    private static final int MAX_TOTAL_LENGTH  = 500;  // 渲染后总长度上限
    private static final int MAX_VAR_LENGTH    = 60;   // 单变量值上限

    @Autowired
    private SensitiveWordFilter sensitiveWordFilter;  // 复用教育场景敏感词多层次过滤引擎

    public String render(SmsTemplate template, Map<String, String> vars) {
        // ── 1. 变量集合白名单校验：请求键必须与模板声明完全一致 ──
        Set<String> declared = template.getVariableNames();   // variables JSON 解析
        if (!declared.equals(vars.keySet())) {
            throw new SmsRenderException(52902, "SMS_TEMPLATE_VARS_MISMATCH",
                "期望: " + declared + " 实际: " + vars.keySet());
        }

        // ── 2. 逐值安全校验 ──
        for (Map.Entry<String, String> e : vars.entrySet()) {
            String v = e.getValue();
            if (v == null || v.isEmpty())
                throw new SmsRenderException(52902, "TEMPLATE_VARS_MISSING", e.getKey() + " 为空");
            if (v.length() > MAX_VAR_LENGTH || v.contains("\n"))
                throw new SmsRenderException(52902, "VAR_VALUE_ILLEGAL", e.getKey());
            // 禁止变量值包含 ${ —— 防止二次渲染注入
            if (v.contains("${"))
                throw new SmsRenderException(52902, "VAR_INJECTION_BLOCKED", e.getKey());
        }

        // ── 3. 替换（Matcher 循环，未匹配变量已在第1步拦截） ──
        Matcher m = VAR_PATTERN.matcher(template.getContentTemplate());
        StringBuilder sb = new StringBuilder();
        while (m.find()) {
            m.appendReplacement(sb, Matcher.quoteReplacement(vars.get(m.group(1))));
        }
        m.appendTail(sb);
        String content = sb.toString();

        // ── 4. 总长度校验 ──
        if (content.length() > MAX_TOTAL_LENGTH)
            throw new SmsRenderException(52902, "CONTENT_TOO_LONG",
                String.valueOf(content.length()));

        // ── 5. 敏感词复检（调用方为内部服务仍可能带入不当内容） ──
        SensitiveWordFilter.Result filterResult = sensitiveWordFilter.scan(content);
        if (filterResult.hit()) {
            // 命中即拒绝发送并转人工审核队列，不自动替换（短信为对外输出，替换可能改变语义）
            auditQueue.publish(new SmsContentReviewEvent(template.getTemplateCode(), content,
                                                         filterResult.getHitWords()));
            throw new SmsRenderException(52903, "SMS_CONTENT_SENSITIVE",
                String.join(",", filterResult.getHitWords()));
        }
        return content;
    }

    /** 计费条数：中文短信按 70 字/条（GBK），长短信分段 67 字/条 */
    public int calcBillingSegments(String content) {
        int len = content.getBytes(Charset.forName("GBK")).length;
        return len <= 70 ? 1 : (int) Math.ceil(len / 67.0);
    }
}
```

> **验证码脱敏：** 验证码场景渲染结果写入 `sms_send_logs.rendered_content` 时，验证码数字统一替换为 `******`，全链路日志同样禁止输出明文。

**5.7.1 验签（统一网关层实现）：**

```java
private void verifySignature(String provider, String payload,
                             Map<String, String> headers) {
    String timestamp = headers.get("X-PT-Timestamp");
    String nonce     = headers.get("X-PT-Nonce");
    String signature = headers.get("X-PT-Signature");

    // 1. 时间窗校验（±5分钟，防重放）
    if (Math.abs(Instant.now().toEpochMilli() - Long.parseLong(timestamp)) > 300_000)
        throw new SmsCallbackException(52906, "TIMESTAMP_EXPIRED");

    // 2. Nonce 一次性（Redis SETNX，10分钟过期）
    Boolean first = redis.opsForValue().setIfAbsent("sms:cb:nonce:" + nonce, "1",
                                                    Duration.ofMinutes(10));
    if (!Boolean.TRUE.equals(first))
        throw new SmsCallbackException(52906, "NONCE_REPLAYED");

    // 3. HMAC-SHA256(payload + timestamp + nonce, providerSecret)
    String expected = HmacUtils.hmacSha256Hex(getProviderSecret(provider),
                                               payload + timestamp + nonce);
    if (!MessageDigest.isEqual(expected.getBytes(), signature.getBytes()))
        throw new SmsCallbackException(52906, "SIGN_INVALID");
}
```

**5.7.2 回执落库（幂等 + 状态机守卫）：**

```java
@Transactional
public void applyReport(DeliveryReport report) {
    SmsSendLog log = logRepo.findByLogId(report.getLogId());

    // ── 乱序容忍：回执先于发送响应落库（极端网络抖动）──
    if (log == null) {
        // 暂存 5 分钟，发送主流程落库后由合并任务补处理
        redis.opsForValue().set("sms:cb:early:" + report.getLogId(),
                                JsonUtils.toJson(report), Duration.ofMinutes(5));
        log.info("[SMS] 回执早于主记录，暂存 logId={}", report.getLogId());
        return;
    }

    // ── 状态机守卫：仅 PENDING/SENT 可流转，其余视为重复回执直接丢弃（幂等）──
    String status = log.getSendStatus();
    if (!"PENDING".equals(status) && !"SENT".equals(status)) {
        return;
    }

    if (report.isSuccess()) {
        log.setSendStatus("DELIVERED");
        log.setDeliveredAt(parseTime(report.getReportTime()));
    } else {
        log.setSendStatus("FAILED");
        log.setFailedAt(now());
        log.setErrorCode(report.getErrorCode());
        // 可重试类失败 → 投递重试队列（§5.8，仅通知/营销场景）
        if (retryPolicy.isRetryable(report.getErrorCode())
            && !sceneCategory.isVerification(log.getSceneCode())) {
            retryQueue.offer(RetryTask.of(log.getLogId(), nextDelay(0)));
        }
    }
    logRepo.save(log);

    // 发送主流程落库时检查早到回执（双向兜底）
    String early = redis.opsForValue().get("sms:cb:early:" + log.getLogId());
    if (early != null) {
        redis.delete("sms:cb:early:" + log.getLogId());
        applyReport(JsonUtils.fromJson(early, DeliveryReport.class));
    }
}
```

**回执流转守卫表：**

| 当前状态 | 回执结果 | 允许流转 | 动作 |
|----------|----------|----------|------|
| PENDING / SENT | success=true | DELIVERED | 记 delivered_at |
| PENDING / SENT | success=false 且可重试 | FAILED | 通知/营销场景入重试队列 |
| PENDING / SENT | success=false 且不可重试 | FAILED | 记 error_code，终态 |
| DELIVERED / FAILED / REJECTED / DEAD | 任意 | 不流转 | 丢弃（重复回执） |

**5.7.3 回调响应约定：** 全部回执处理成功返回 `200`；单条处理内部异常时**仍返回 200** 并记录待修复队列（避免供应商无限重推造成重复消费风暴），修复任务由对账兜底（§5.9）。验签失败返回 `401`（供应商侧会告警，需人工介入）。

**重试工作器（RocketMQ 延迟消息或 Redis ZSET 扫描实现）：**

```java
@Scheduled(fixedDelay = 5000)
public void scanRetryQueue() {
    // ZSET: score=到期时间戳, member=logId:attempt
    Set<ZSetOperations.TypedTuple<String>> tasks =
        redis.opsForZSet().rangeByScoreWithScores("sms:retry:queue", 0, now, 0, 50);

    for (var t : tasks) {
        String[] parts = t.getValue().split(":");
        String logId = parts[0];
        int attempt = Integer.parseInt(parts[1]);
        redis.opsForZSet().remove("sms:retry:queue", t.getValue());

        SmsSendLog log = logRepo.findByLogId(logId).orElse(null);
        // 主记录已终态（如人工重发成功/用户已完成验证）→ 跳过
        if (log == null || !"FAILED".equals(log.getSendStatus())) continue;

        // 状态机：FAILED → RETRYING → SENT / FAILED(attempt+1) / DEAD
        if (attempt >= MAX_ASYNC_RETRY) {
            log.setSendStatus("DEAD");           // 死信：仅通知/营销场景
            logRepo.save(log);
            metrics.increment("sms_dlq_total", log.getProvider());
            alertService.warn("SMS_DLQ", "logId=" + logId + " 重试耗尽");
            continue;
        }

        resendViaBestChannel(log);  // 内部复用 §4.4 通知发送流程（跳过频率检查，attempt+1）
        if (attempt + 1 < MAX_ASYNC_RETRY)
            redis.opsForZSet().add("sms:retry:queue",
                logId + ":" + (attempt + 1), now + backoffMs(attempt + 1));
    }
}
```

> `sms_send_logs.send_status` 枚举扩展值：`RETRYING`（异步重试中）、`DEAD`（重试耗尽，管理后台可手工重发）。

> **验证码场景红线：** 验证码短信发送失败**不做任何自动重试**（防止对同一手机号连续触发多网关轰炸），直接 FAILED 并在响应中提示用户稍后手动重试；`retryable=true` 的信息仅用于通道健康度统计（§5.2 recordSendResult）。

**人工重发（管理后台）：** `POST /admin/v1/sms/logs/{logId}/resend`，校验：当前状态 ∈ {FAILED, DEAD}，且距创建时间 < 24h，重置状态为 PENDING 并走完整发送流程（含频率检查）。

```yaml
        labels: { severity: high }
      - alert: SmsVerifyAttackSuspected      # 疑似验证码轰炸/撞库
        expr: sum(rate(sms_verify_total{result="WRONG"}[10m])) by (scene)
              / sum(rate(sms_verify_total[10m])) by (scene) > 0.6
        for: 10m
        labels: { severity: high }
      - alert: SmsSceneBurst                 # 单场景量突增（攻击或配置错误）
        expr: rate(sms_ratelimit_hit_total{rule="SCENE"}[5m])
              > 5 * rate(sms_ratelimit_hit_total{rule="SCENE"}[5m] offset 1h)
        for: 5m
        labels: { severity: high }
      - alert: SmsBudgetNearLimit            # 成本预算 80%/100%
        expr: sms_cost_cents_daily / on(provider) sms_budget_cents > 0.8
        labels: { severity: medium }
      - alert: SmsDlqGrowing                 # 死信堆积
        expr: increase(sms_dlq_total[1h]) > 10
        labels: { severity: medium }
```

### 7.3 运营看板核心 SQL

```sql
-- 送达率日报（按供应商）
SELECT provider,
       SUM(send_status = 'DELIVERED') AS delivered,
       SUM(send_status IN ('DELIVERED','FAILED')) AS finished,
       ROUND(SUM(send_status = 'DELIVERED') / SUM(send_status IN ('DELIVERED','FAILED')) * 100, 2) AS delivery_rate
FROM sms_send_logs
WHERE sent_at >= CURDATE() - INTERVAL 1 DAY AND sent_at < CURDATE()
GROUP BY provider;

-- TOP 失败原因
SELECT error_code, COUNT(*) AS cnt
FROM sms_send_logs
WHERE send_status IN ('FAILED','DEAD') AND created_at >= CURDATE() - INTERVAL 1 DAY
GROUP BY error_code ORDER BY cnt DESC LIMIT 10;
```

## 9. 安全与合规红线

1. **模板审批前置**：仅 `APPROVED` 且目标供应商已审批的模板可发送；运行时二次校验（52901），任何“先发后补审批”路径禁止。
2. **场景强绑定**：验证码模板仅允许验证码场景调用（发送编排器按 `scene_code` ↔ `template.scene_code` 一致性强校验），严禁验证码签名/模板被挪用于营销。
3. **营销双同意**：营销短信需用户明示同意（且未成年人账号关联号码一律不发）；缺少同意记录直接拒绝（52912）。
4. **静默时段**：营销短信默认仅 09:00-21:00 发送，静默时段入延迟队列次日首发（52913）；验证码/安全告警类不受限。
5. **内容最小化**：通知短信不携带任何学习成绩、薄弱点、健康等学生敏感信息，仅做“报告已生成”类引导。
6. **退订即停**：营销短信必带“回T退订”，退订指令 24 小时内全网生效（写入退订表并同步营销触达引擎，永久生效）。
7. **明文最小化**：明文手机号仅存在于调用链路内存与供应商请求；DB/日志仅存 SHA256 哈希+后 4 位；验证码 BCrypt 存储、明文不落任何日志。
8. **密钥管理**：供应商 AccessKey/Secret 与回调密钥 KMS 加密存储，90 天轮换；轮换采用双密钥并行窗口（旧密钥验证通过、新密钥签名）平滑过渡。
9. **审计**：管理后台模板审批/供应商配置修改/手工重发/对账处理全部落审计日志（对接服务端审计日志系统）。
10. **防轰炸联动**：限流命中黑名单特征（同 IP 多号码、同设备多号码）时推送风控引擎，由风控决策临时封禁（本模块只做信号上报不做处罚决策）。

## 11. 验收场景

| # | 场景 | 预期 |
|---|------|------|
| 1 | 注册场景 60s 内重复发送验证码 | 第二次拒绝 42901，返回 next_send_in 正确倒计时 |
| 2 | 验证码连续 5 次输错 | 第 5 次后状态 CANCELLED，后续验证返回 42910 |
| 3 | 验证码 5 分钟后验证 | 状态 EXPIRED，返回 40011 |
| 4 | verify_token 二次消费（注册后再用于绑定手机） | 返回 52916 拒绝，状态保持 USED |
| 5 | verify 成功但 10 分钟后业务方才消费 | JWT 过期校验失败，返回 52915 |
| 6 | 阿里云连续失败 5 次 | 自动 DEGRADED 切腾讯云，ProviderDegradedEvent 发布并告警，DEGRADED 300s 冷却后探活恢复 |
| 7 | 主备通道均不可用 | 返回 50301，P1 告警；验证码场景无自动重试记录 |
| 8 | 回执早于发送响应落库 | 暂存 Redis，主记录落库后合并，最终 DELIVERED |
| 9 | 同一 biz_id 回执重复推送两次 | 状态只流转一次，delivered_at 不变（幂等守卫） |
| 10 | 通知短信缺少模板变量 | 渲染前拦截 52902，不产生发送记录，调用方收到明确错误 |
| 11 | 变量值包含 `${amount}` 注入尝试 | 拦截 VAR_INJECTION_BLOCKED，审计日志记录 |
| 12 | 营销短信 21:30 提交 | 入延迟队列次日 09:00 发送；已回 T 退订用户被过滤 |
| 13 | 营销短信无用户同意记录 | 直接拒绝 52912，不产生费用 |
| 14 | 渲染内容命中敏感词 | 52903 拦截并转人工审核队列，无发送 |
| 15 | 对账模拟供应商账单多 10 条 | diff 记录 + 分类 B（供应商多计），超阈值触发 52914 告警 |
| 16 | 日成本达预算 100% | 营销场景自动熔断（验证码/安全类不受影响），P2 告警 |

| 19 | 手工重发 DEAD 状态短信 | 状态重置 PENDING 走完整流程；重发 24h 外记录被拒绝 |
| 20 | 供应商日额度耗尽 | 通道选择跳过该供应商；全部耗尽返回 52907 并尝试其他通道 |
