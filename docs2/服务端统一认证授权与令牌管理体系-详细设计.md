# 服务端统一认证授权与令牌管理体系 - 详细设计

> 本文档详细定义 PrimeTop 系统的认证授权架构，包括 JWT 令牌设计、OAuth2.0 授权流程、Refresh Token 轮转策略、多设备会话管理、令牌吊销机制、认证中间件及安全防护措施，为开发人员提供可直接编码的实现规范。

---

## 1. 概述

### 1.1 设计目标

| 目标 | 说明 |
| --- | --- |
| 统一认证入口 | 所有业务服务的认证由 API 网关统一拦截，下游服务信任网关传递的用户上下文 |
| 无状态为主 | 采用 JWT 令牌实现无状态认证，降低服务端 Session 存储压力 |
| 多端会话管理 | 支持同一账号在多设备（Android、iOS、Web、小程序）同时在线，可按设备维度管理会话 |
| 安全合规 | 符合《个人信息保护法》《儿童个人信息网络保护规定》要求，敏感操作需二次验证 |
| 高可用 | 认证服务作为核心基础设施，可用性目标 ≥ 99.95% |
| 可扩展 | 支持未来接入第三方 OAuth（微信、QQ、Apple ID）和企业 SSO |

### 1.2 适用范围

- 移动端 APP（Android / iOS）登录认证
- 管理后台（Web）登录认证
- 家长端 Web / 小程序认证
- 服务间内部调用认证
- 未来第三方 OAuth 接入

### 1.3 技术选型

| 组件 | 选型 | 理由 |
| --- | --- | --- |
| 令牌格式 | JWT（RS256 签名） | 无状态、可验证、跨服务传递 |
| 签名算法 | RS256（非对称） | 公钥可分发到多个服务验证，私钥仅在认证服务持有 |
| 会话存储 | Redis Cluster | 存储 Refresh Token 白名单、令牌吊销列表、设备会话 |
| 密码哈希 | Argon2id | 当前最强密码哈希算法，抗 GPU/ASIC 破解 |
| 短信验证码 | Redis + 限流 | 验证码 5 分钟有效，60 秒间隔限制 |
| API 网关认证 | 网关层 JWT 验证 + 用户上下文注入 | 下游服务无需重复验证 |

│  └──────────┘   └──────────────┘   └──────────────┘               │

## 3. 数据结构定义

### 3.1 JWT Payload 结构

#### 3.1.1 Access Token

```json
{
  "sub": "usr_a1b2c3d4e5f6",         // 用户ID
  " typ": "access",                   // 令牌类型
  "device_id": "dev_x7y8z9w0",       // 设备ID
  "platform": "android",              // 平台：android | ios | web | mini_app
  "roles": ["student"],               // 角色
  "grade": "G8",                      // 年级编码
  "member_level": "premium",          // 会员等级：free | premium | annual
  "sid": "sess_k1l2m3n4",            // 会话ID
  "iat": 1748470400,                  // 签发时间
  "exp": 1748474000,                  // 过期时间（签发 + 60分钟）
  "jti": "tok_p5q6r7s8t9"            // 令牌唯一ID（用于吊销）
}
```

#### 3.1.2 Refresh Token

```json
{
  "sub": "usr_a1b2c3d4e5f6",         // 用户ID
  "typ": "refresh",                   // 令牌类型
  "device_id": "dev_x7y8z9w0",       // 设备ID
  "sid": "sess_k1l2m3n4",            // 会话ID
  "rot": 3,                           // 轮转计数器
  "iat": 1748470400,                  // 签发时间
  "exp": 1749766400,                  // 过期时间（签发 + 15天）
  "jti": "rtk_u1v2w3x4"             // 令牌唯一ID
}
```

### 3.2 令牌参数配置

| 参数 | 值 | 说明 |
| --- | --- | --- |
| Access Token 有效期 | 60 分钟 | 短有效期，减少被盗用的风险窗口 |
| Refresh Token 有效期 | 15 天 | 支持长期免登录，轮转后重新计算 |
| Refresh Token 最大轮转次数 | 100 次 | 防止无限轮转 |
| RSA 密钥长度 | 2048 bit | 安全性与性能平衡 |
| 密钥轮转周期 | 90 天 | 定期更换签名密钥 |
| 旧密钥宽限期 | 7 天 | 密钥轮转后旧令牌仍可验证 |
| 最大同时在线设备数 | 5 | 超出后最早设备被踢下线 |
| 登录失败锁定阈值 | 5 次 / 15 分钟 | 锁定 30 分钟 |

### 3.3 Redis 数据结构

#### 3.3.1 Refresh Token 白名单

```
Key:    auth:rt:{user_id}:{device_id}
Value:  {
          "jti": "rtk_u1v2w3x4",
          "sid": "sess_k1l2m3n4",
          "rot": 3,
          "ip": "192.168.1.100",
          "ua": "PrimeTop/1.0 (Android 14)",
          "created_at": 1748470400
        }
TTL:    15 天（与 Refresh Token 有效期一致）
```

#### 3.3.2 Token 吊销列表

```
Key:    auth:revoke:{jti}
Value:  "1"
TTL:    等于该 Token 的剩余有效期

示例：
auth:revoke:tok_p5q6r7s8t9  →  TTL = 3200（秒，即该 AT 剩余有效期）
auth:revoke:rtk_u1v2w3x4    →  TTL = 864000（秒，即该 RT 剩余有效期）
```

#### 3.3.3 全局吊销（用户级）

```
Key:    auth:revoke_all:{user_id}
Value:  {timestamp}    // 该时间之前的所有 Token 全部失效
TTL:    15 天
```

#### 3.3.4 设备会话索引

```
Key:    auth:devices:{user_id}
Value:  Sorted Set（score 为最后活跃时间戳）
        {
          "dev_x7y8z9w0": 1748474000,
          "dev_a1b2c3d4": 1748473000,
          ...
        }
TTL:    无过期（随 Refresh Token 过期清理）
```

#### 3.3.5 登录失败计数

```
Key:    auth:fail:{login_type}:{identifier}
Value:  失败次数（整数）
TTL:    15 分钟

示例：
auth:fail:sms:8613800138000    →  3
auth:fail:pwd:8613800138000    →  2
```

#### 3.3.6 签名密钥版本

```
Key:    auth:keys:current
Value:  "kid_2026Q2"               // 当前活跃密钥ID

Key:    auth:keys:kid_2026Q2:private
Value:  {RSA Private Key PEM}      // 私钥

Key:    auth:keys:kid_2026Q2:public
Value:  {RSA Public Key PEM}       // 公钥（供网关和其他服务使用）

Key:    auth:keys:kid_2026Q1:public
Value:  {RSA Public Key PEM}       // 旧公钥（宽限期内仍需保留）
TTL:    密钥轮转后 7 天
```

## 4. API 接口设计

### 4.1 发送短信验证码

```
POST /api/v1/auth/sms/send
```

**请求体：**
```json
{
  "phone": "8613800138000",
  "region": "CN",
  "captcha_token": "g-recaptcha-xxx"
}
```

**响应体：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "expires_in": 300,
    "resend_after": 60
  }
}
```

**业务规则：**
- 同一手机号 60 秒内只能发送一次
- 同一手机号每天最多 10 条
- 同一 IP 每小时最多 20 条
- 验证码长度 6 位，纯数字
- 验证码 5 分钟有效
- 需先通过图形验证码/人机验证
- 返回中不包含验证码内容

**错误码：**

| code | 含义 |
| --- | --- |
| 42901 | 发送过于频繁（60秒内重复） |
| 42902 | 日发送次数超限 |
| 42903 | IP 发送频率超限 |
| 40001 | 手机号格式无效 |
| 40002 | 人机验证失败 |

### 4.2 手机号注册

```
POST /api/v1/auth/register
```

**请求体：**
```json
{
  "phone": "8613800138000",
  "sms_code": "123456",
  "password": "MyP@ssw0rd",
  "nickname": "小明",
  "role": "student",
  "grade": "G8",
  "textbook_version": "PEP",
  "device_info": {
    "device_id": "dev_x7y8z9w0",
    "device_name": "小米14",
    "platform": "android",
    "os_version": "Android 14",
    "app_version": "1.0.0"
  }
}
```

**响应体：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "user_id": "usr_a1b2c3d4e5f6",
    "access_token": "eyJhbGciOiJSUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJSUzI1NiIs...",
    "expires_in": 3600,
    "token_type": "Bearer",
    "session_id": "sess_k1l2m3n4"

}
```

**业务规则：**
- 短信验证码验证通过后才能注册
- 密码强度要求：≥8位，含大小写字母和数字
- 密码使用 Argon2id 哈希存储，绝不存储明文
- 注册成功自动登录，返回令牌
- 同时创建 `user_auth`、`user`、`student_profile`（学生角色时）记录

### 4.5 令牌刷新

```
POST /api/v1/auth/token/refresh
```

**请求体：**
```json
{
  "refresh_token": "eyJhbGciOiJSUzI1NiIs..."
}
```

**成功响应：**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "access_token": "eyJhbGciOiJSUzI1NiIs...(新)",
    "refresh_token": "eyJhbGciOiJSUzI1NiIs...(新，轮转)",
    "expires_in": 3600,
    "token_type": "Bearer"
  }
}
```

**业务规则（Refresh Token Rotation）：**
- 每次刷新生成全新的 Access Token + Refresh Token 对
- **旧 Refresh Token 立即失效**（加入吊销列表）
- 如果旧的 Refresh Token 已被使用过（检测到重放），则 **吊销该用户所有会话**（安全威胁：Token 泄露）
- 轮转计数器递增，超过最大轮转次数需重新登录
- 新 Refresh Token 的 TTL 重新计算（滑动过期）

### 5.3 网关认证过滤器处理流程

```java
// 伪代码：网关认证过滤器
public class AuthGatewayFilter implements GlobalFilter {
    
    // 白名单路径（无需认证）
    private static final Set<String> WHITELIST = Set.of(
        "/api/v1/auth/login/sms",
        "/api/v1/auth/login/password",
        "/api/v1/auth/register",
        "/api/v1/auth/sms/send",
        "/api/v1/auth/token/refresh",
        "/api/v1/auth/public-key",
        "/api/v1/auth/password/reset"
    );

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getPath().value();
        
        // 1. 白名单直接放行
        if (WHITELIST.contains(path)) {
            return chain.filter(exchange);
        }
        
        // 2. 提取 Token
        String authHeader = exchange.getRequest().getHeaders().getFirst("Authorization");
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            return reject(exchange, 401, "AUTH_TOKEN_MISSING", "缺少认证令牌");
        }
        
        String token = authHeader.substring(7);
        
        try {
            // 3. 验证 JWT 签名 + 过期时间
            Claims claims = jwtParser.parseClaimsJws(token).getBody();
            
            // 4. 检查令牌类型
            if (!"access".equals(claims.get("typ", String.class))) {
                return reject(exchange, 401, "INVALID_TOKEN_TYPE", "令牌类型错误");
            }
            
            // 5. 检查吊销列表（Redis Bloom Filter，低延迟）
            String jti = claims.getId();
            if (tokenRevokeCache.isRevoked(jti)) {
                return reject(exchange, 401, "TOKEN_REVOKED", "令牌已被吊销");
            }
            
            // 6. 检查全局吊销
            String userId = claims.getSubject();
            Long globalRevokeAt = globalRevokeCache.getRevokeTime(userId);
            if (globalRevokeAt != null && claims.getIssuedAt().getTime() / 1000 < globalRevokeAt) {
                return reject(exchange, 401, "TOKEN_REVOKED", "令牌已被全局吊销");
            }
            
            // 7. 注入用户上下文 Header（传递给下游服务）
            ServerHttpRequest mutatedRequest = exchange.getRequest().mutate()
                .header("X-User-Id", userId)
                .header("X-Device-Id", claims.get("device_id", String.class))
                .header("X-Platform", claims.get("platform", String.class))
                .header("X-Session-Id", claims.get("sid", String.class))
                .header("X-Member-Level", claims.get("member_level", String.class))
                .header("X-Grade", claims.get("grade", String.class))
                .header("X-Roles", String.join(",", claims.get("roles", List.class)))
                .build();
            
            return chain.filter(exchange.mutate().request(mutatedRequest).build());
            
        } catch (ExpiredJwtException e) {
            return reject(exchange, 401, "TOKEN_EXPIRED", "令牌已过期");
        } catch (JwtException e) {
            return reject(exchange, 401, "TOKEN_INVALID", "令牌无效");
        }
    }
}
```

### 5.4 客户端 Token 刷新守护

```dart
// Flutter 客户端：HTTP 拦截器
import 'package:dio/dio.dart';

class AuthInterceptor extends Interceptor {
  final TokenStorage _tokenStorage;
  final Dio _refreshDio; // 专用 Dio 实例，不经过拦截器
  final Lock _refreshLock = Lock(); // 防止并发刷新
  String? _newRefreshToken; // 刷新期间的中间结果
  
  @override
  void onRequest(RequestOptions options, RequestInterceptorHandler handler) async {
    final tokens = await _tokenStorage.getTokens();
    if (tokens != null && tokens.accessToken != null) {
      options.headers['Authorization'] = 'Bearer ${tokens.accessToken}';
    }
    handler.next(options);
  }
  
  @override
  void onError(DioException err, ErrorInterceptorHandler handler) async {
    if (err.response?.statusCode == 401) {
      final errorCode = err.response?.data?['code'];
      
      if (errorCode == 'TOKEN_EXPIRED') {
        // Token 过期，尝试刷新
        try {
          final newTokens = await _refreshLock.synchronized(() async {
            // 双重检查：可能其他请求已经刷新过了
            final current = await _tokenStorage.getTokens();
            if (current?.refreshToken == null) return null;
            
            final response = await _refreshDio.post(
              '/api/v1/auth/token/refresh',
              data: {'refresh_token': current!.refreshToken},
            );
            
            if (response.statusCode == 200) {
              final tokenData = response.data['data'];
              final newTokens = TokenPair(
                accessToken: tokenData['access_token'],
                refreshToken: tokenData['refresh_token'],
                expiresAt: DateTime.now().add(
                  Duration(seconds: tokenData['expires_in']),
                ),
              );
              await _tokenStorage.saveTokens(newTokens);
              return newTokens;
            }
            return null;
          });
          
          if (newTokens != null) {
            // 用新 Token 重试原始请求
            err.requestOptions.headers['Authorization'] = 
              'Bearer ${newTokens.accessToken}';
            final retryResponse = await _retry(err.requestOptions);
            handler.resolve(retryResponse);
            return;
          }
        } catch (_) {
          // 刷新失败，清除 Token，跳转登录页
        }
        
        // 刷新失败或 Token 不可恢复
        await _tokenStorage.clearTokens();
        _navigateToLogin();
        handler.reject(err);
      } else {
        // 其他 401 错误（吊销、无效等）
        await _tokenStorage.clearTokens();
        _navigateToLogin();
        handler.reject(err);
      }
    } else {
      handler.next(err);
    }
  }
}
```

### 6.1 轮转流程

            // 先从 Redis 缓存获取

            if (pem == null) {

            return parsePublicKey(pem);
        });

## 7. 安全防护机制

### 7.1 异地登录检测

```
用户历史登录 IP 地域          当前登录 IP 地域
┌─────────────┐           ┌─────────────┐
│  北京、上海   │           │  境外 IP     │
│  最近30天     │           │  首次出现     │
└─────────────┘           └─────────────┘
          │                        │
          └────────────────────────┘
                   │
            风险评估引擎
                   │
         ┌────────┴────────┐
         │                 │
    低风险              高风险
    (同城不同IP)      (境外/跨省异常)
         │                 │
    正常登录           增强验证
    推送通知           发送短信验证码
    "您的账号在新设备   用户必须输入短信
     上登录"           验证码才能完成登录
```

**实现要点：**
- 维护用户最近 30 天的登录 IP 地域集合
- 使用 IP 归属地库进行地域匹配
- 异地登录事件写入 `login_log` 表（result=7 标记为异地验证）
- 推送通知通过消息服务异步发送

### 7.2 暴力破解防护

```
登录失败计数器（Redis，15分钟滑动窗口）

第1次失败: count=1  →  正常提示
第2次失败: count=2  →  正常提示
第3次失败: count=3  →  提示“还有2次机会”
第4次失败: count=4  →  提示“还有1次机会”
第5次失败: count=5  →  锁定30分钟
                                ↓
                   Redis: auth:lock:{login_type}:{identifier}
                   Value: lock_until_timestamp
                   TTL: 1800秒
                                ↓
                   写入 login_log (result=4, 账号锁定)
```

### 7.3 Token 泄露检测与响应

```
Refresh Token 重放检测

场景：攻击者获取了用户的 RT，在合法用户之前尝试刷新

时间线：
T1: 用户登录 → 获得 RT_A
T2: 攻击者获取 RT_A
T3: 攻击者用 RT_A 刷新 → 获得 AT_new + RT_B
    → Redis 白名单更新为 RT_B
    → RT_A 加入吊销列表
T4: 用户用 RT_A 刷新 → RT_A 已不在白名单！
    → ⚠️ 检测到重放攻击
    → 吊销该用户所有令牌
    → 所有设备强制重新登录
    → 发送安全告警短信
    → 记录安全事件审计日志
```

### 7.4 Token 安全传输规范

| 场景 | Access Token | Refresh Token |
| --- | --- | --- |
| 传输方式 | HTTP Header (Authorization) | 仅 HTTPS 请求体 |
| 存储位置（移动端） | Secure Storage / Keychain | Secure Storage / Keychain |
| 存储位置（Web） | 内存变量（不存 localStorage） | HttpOnly + Secure + SameSite Cookie |
| URL 暴露 | 禁止在 URL 参数中传递 | 禁止在 URL 参数中传递 |
| 日志打印 | 禁止打印完整 Token | 禁止打印完整 Token |

### 7.5 服务间认证

内部服务间调用不使用用户 JWT，而使用 Service Token：

```json
// Service Token（用于服务间调用）
{
  "sub": "svc:learning-service",
  "typ": "service",
  "permissions": ["read:user_profile", "write:learning_record"],
  "iat": 1748470400,
  "exp": 1748474000
}
```

**规则：**
- Service Token 有效期 10 分钟，由服务启动时向 Auth Service 申请
- 内部调用通过 API 网关时，网关识别 `typ=service` 后跳过用户级检查
- Service Token 权限范围受限，遵循最小权限原则
- 服务间也可使用 mTLS 双向认证（生产环境推荐）

## 9. 状态流转

### 9.1 会话状态机

```
                    登录成功
                      │
                      ▼
              ┌──────────────┐
              │   ACTIVE     │◄───── Token 刷新成功
              │  （活跃中）   │
              └──────┬───────┘
                     │
        ┌────────────┼────────────────┐
        │            │                │
   用户主动登出   被踢下线       Refresh Token 过期
        │       (其他设备登录)         │
        ▼            ▼                ▼
  ┌──────────┐ ┌──────────┐   ┌──────────┐
  │ LOGOUT    │ │ KICKED   │   │ EXPIRED  │
  │（已登出） │ │（被踢）  │   │ （已过期）│
  └──────────┘ └──────────┘   └──────────┘
        │            │                │
        ▼            ▼                ▼
     清除本地 Token              清除本地 Token
     吊销 AT + RT               需重新登录
     写入日志                                 
```

### 9.2 令牌生命周期

```
Access Token 生命周期（60分钟）

签发 ──────────────────────────────────────────> 过期
  │                                               │
  │  ← 可用于 API 调用 →                          │
  │                                               │
  │  任意时刻可被吊销（加入吊销列表）                  │
  │                                               │
  └─ 过期后从吊销列表自动清除（TTL 到期）


Refresh Token 生命周期（15天，滑动窗口）

签发 ──── 轮转1 ──── 轮转2 ──── ... ──── 轮转N ──> 过期/最大轮转
  │         │          │                    │         │
  │    新RT+AT    新RT+AT              新RT+AT      需重新
  │    旧RT失效   旧RT失效             旧RT失效      登录
  │
  │  每次轮转 TTL 重置为15天
  │  轮转计数器递增
  │  超过100次需重新登录
```

## 11. 性能设计

### 11.1 关键性能指标

| 操作 | 目标延迟 | 说明 |
| --- | --- | --- |
| 网关 JWT 验证 | < 5ms | 非对称签名验证，纯 CPU 操作 |
| Redis 吊销检查 | < 2ms | Bloom Filter + Redis GET |
| 登录流程（端到端） | < 500ms | 含短信验证码校验 + JWT签发 + Redis写入 |
| Token 刷新 | < 100ms | Redis 读写 + JWT 签发 |
| 公钥分发 | < 10ms | Redis 缓存命中 |

### 11.2 缓存策略

| 数据 | 缓存位置 | TTL | 说明 |
| --- | --- | --- | --- |
| 公钥 | 网关本地内存 | 5 分钟 | 定期从 Auth Service 同步 |
| 公钥 | Redis | 1 小时 | 回源到 DB |
| 吊销列表 | Redis | 随 Token TTL | 自动过期清理 |
| 全局吊销时间戳 | Redis | 15 天 | 随会话周期 |
| 用户登录失败计数 | Redis | 15 分钟 | 滑动窗口 |

### 11.3 高可用部署

```
┌────────────────────────────────────────────┐
│              Load Balancer                  │
│           (健康检查: /health)               │
└──────────────┬─────────────────────────────┘
               │
     ┌─────────┴─────────┐
     ▼                   ▼
┌──────────┐       ┌──────────┐
│ Auth Svc │       │ Auth Svc │
│ Instance │       │ Instance │   （无状态，可水平扩展）
│   #1     │       │   #2     │
└────┬─────┘       └────┬─────┘
     │                   │
     └─────────┬─────────┘
               │
     ┌─────────┴─────────┐
     ▼                   ▼
┌──────────┐       ┌──────────┐
│  Redis   │       │  MySQL   │
│ Cluster  │       │  主从     │
│ (6节点)  │       │          │
└──────────┘       └──────────┘

关键保障：
- Auth Service 无状态设计，所有状态存储在 Redis
- Redis Cluster 6 节点（3主3从），支持自动故障转移
- MySQL 主从同步，读写分离
- 签名私钥加密存储在 DB，启动时加载到内存
```
