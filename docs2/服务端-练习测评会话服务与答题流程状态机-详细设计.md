## 1. 文档定位

### 1.1 为什么需要这份文档

PrimeTop 的练习测评功能是核心学习闭环的关键环节。当用户进入一次练习/考试时，系统需要管理从**会话创建 → 答题交互 → 批改评分 → 结果汇总 → 学习记录沉淀**的完整生命周期。

现有文档已分别覆盖：
- **题目智能推荐与编排**：如何选择合适的题目组成一套练习
- **实时批改与评分**：如何对提交的答案进行判分
- **客户端答题页面**：前端如何展示题目、收集答案
- **学习记录追踪**：如何持久化学习数据

但缺少一份专注于**练习会话本身的生命周期管理**的文档，回答以下问题：

1. 一次练习会话从创建到结束经过哪些状态？状态流转规则是什么？
2. 答题计时器如何在服务端与客户端之间保持同步？
3. 用户中途退出（切后台、杀进程、断网）后如何恢复会话？
4. 多设备同时操作同一会话时如何保证数据一致性？
5. 练习会话的题目队列如何管理（顺序、跳过、标记）？
6. 每道题的答题过程如何记录（草稿、修改、犹豫时长）？
7. 会话完成后如何批量触发下游任务（错题收录、掌握度更新、报告生成）？

### 1.2 适用读者

- **服务端开发工程师**：实现练习会话服务、状态机、计时器和恢复机制
- **客户端开发工程师**：理解会话协议、计时器同步策略和断点恢复流程
- **测试工程师**：设计会话生命周期测试用例、异常恢复测试场景

### 1.3 设计目标

| 目标 | 说明 | 指标 |
| --- | --- | --- |
| 会话可靠性 | 会话创建后不丢失，支持断点恢复 | 恢复成功率 ≥ 99.9% |

### 3.2 状态流转规则

```python
# 状态转换定义
SESSION_TRANSITIONS = {
    # (current_status, action) -> (new_status, preconditions, side_effects)
    
    (SessionStatus.CREATED, "start"): {
        "target": SessionStatus.ACTIVE,
        "preconditions": [
            "session not expired (created_at + 48h > now)",
            "user has active quota",
        ],
        "side_effects": [
            "set started_at = now()",
            "set last_active_at = now()",
            "set server_start_ts in Redis",
            "add to active timers sorted set",
            "set all session_questions[0] answer_status = VIEWED",
            "emit SessionStartedEvent",
        ],
    },
    
    (SessionStatus.ACTIVE, "pause"): {
        "target": SessionStatus.PAUSED,
        "preconditions": [
            "session_type != MOCK_EXAM",  # 模拟考试不允许暂停
        ],
        "side_effects": [
            "set paused_at = now()",
            "record pause timestamp in Redis",
            "remove from active timers sorted set",
            "flush pending answer cache to DB",
            "emit SessionPausedEvent",
        ],
    },
    
    (SessionStatus.PAUSED, "resume"): {
        "target": SessionStatus.ACTIVE,
        "preconditions": [
            "paused_at + 24h > now()",  # 暂停超过24h则过期
        ],
        "side_effects": [
            "accumulate paused duration",
            "set paused_at = NULL",
            "re-add to active timers sorted set (adjust deadline)",
            "emit SessionResumedEvent",
        ],
    },
    
    (SessionStatus.ACTIVE, "complete"): {
        "target": SessionStatus.COMPLETED,
        "preconditions": [
            "all questions answered OR user explicitly submits all",
        ],
        "side_effects": [
            "set completed_at = now()",
            "calculate final scores",
            "remove from active timers sorted set",
            "flush all answer cache to DB",
            "trigger async: grading pipeline",
            "trigger async: knowledge mastery update",
            "trigger async: mistake detection",
            "trigger async: learning record creation",
            "trigger async: session summary report generation",
            "emit SessionCompletedEvent",
        ],
    },
    
    (SessionStatus.ACTIVE, "timeout"): {
        "target": SessionStatus.EXPIRED,
        "preconditions": [
            "elapsed_seconds >= time_limit_seconds",
        ],
        "side_effects": [
            "auto-submit all unanswered questions",
            "set expired_at = now()",
            "same as complete side_effects",
            "emit SessionExpiredEvent",
        ],
    },
    
    # 任何非终态 → 放弃
    (SessionStatus.CREATED, "abandon"): {"target": SessionStatus.ABANDONED},
    (SessionStatus.ACTIVE, "abandon"): {"target": SessionStatus.ABANDONED},
    (SessionStatus.PAUSED, "abandon"): {"target": SessionStatus.ABANDONED},
}

def validate_transition(
    current: SessionStatus,
    action: str,
    session: PracticeSession,
) -> tuple[bool, Optional[str]]:
    """验证状态转换是否合法"""
    key = (current, action)
    if key not in SESSION_TRANSITIONS:
        return False, f"不允许的操作：在 {current.name} 状态下执行 {action}"
    
    transition = SESSION_TRANSITIONS[key]
    
    # 检查前置条件
    for precondition in transition.get("preconditions", []):
        result = evaluate_precondition(precondition, session)
        if not result.ok:
            return False, result.message
    
    return True, None
```

### 4.9 暂停与恢复

```

3. 暂停期间题目接口只读（§4.4 规则 4），心跳返回 `status=PAUSED`。

      "accuracy_rate": 0.8,
      "objective_graded": 8,
      "subjective_pending": 2,
      "avg_time_per_q": 62.5
    },
    "report_ready": false,
    "report_poll_url": "/api/v1/practice/sessions/ps_20260817_a1b2c3d4/report"
  }
}
```

**规则**：

1. 执行 `(ACTIVE|PAUSED, complete)`：PAUSED 交卷合法（等价放弃剩余时间）。CAS `WHERE status IN (2,3)`，败则 55112。
2. 交卷主流程（单事务 + Outbox）：① 草稿全量刷库；② 未答题统一置 `is_skipped`/空卷；③ 客观题批量判分（调批改服务 `BatchGrade`，≤ 200 题/批）；④ 汇总分数回填主表；⑤ 写 `practice_outbox`（`practice.session.completed`，见 §10）同事务提交。主观题标记 `grading_status=PENDING`，异步批改完成后增量更新分数并二次发 `practice.session.regraded` 事件。
3. 幂等：同 key 重复交卷返回首次结果；不同 key 的并发交卷靠状态 CAS 兜底（仅一个生效）。
4. 未答题数 > 30% 时要求 `confirm=true`，否则返回 55118 要求二次确认（防误触交卷）。
5. `report_ready=false` 时客户端轮询 report 接口（2s 间隔，最多 30 次），报告生成由扇出任务异步完成。

### 4.11 放弃会话

```

```

**规则**：

1. 仅非终态可放弃；ABANDONED 会话已答题仍保留（可回看），不计成绩、不触发掌握度更新（避免半途数据污染学情）；错题重练会话放弃时已答错题仍回错题本（错题收录在单题批改时已即时触发，与会话终态无关）。

## 6. 服务端权威计时器设计

### 6.1 时间模型

```text
authoritative_elapsed_ms(t) = t − server_start_ts − paused_accumulated_ms(t)
remaining_ms(t)             = time_limit_seconds×1000 − authoritative_elapsed_ms(t)   （不限时会话不计算 remaining）
pause_accumulated_ms(t)     = Σ(已结束暂停段) + (当前处于 PAUSED ? t − pause_started_ts : 0)
```

- **唯一权威**：`server_start_ts` 与 `paused_accumulated_ms` 只存在于服务端（Redis 权威 + DB 定期回填）；客户端计时器仅是投影，通过心跳 offset 修正（§4.8）。
- **时钟源**：服务端统一 UTC 毫秒；不信任客户端绝对时间，仅采纳相对时长（`answer_elapsed_ms`）做行为分析。
- **暂停语义**：非考试会话切后台 30s 自动 pause（客户端触发；客户端失效未触发时由 §9 无操作扫描兜底转 PAUSED，不直接判交卷，保护低龄用户「忘了回来」场景）。

### 6.2 单题计时

- `per_question_limit` 仅客户端强制（到点禁输入），服务端只记录 `first_viewed_at`/`answer_elapsed_ms` 并标记 `overtime`（§4.6 规则 6）——避免服务端单题定时器海量调度。
- MOCK_EXAM 的整卷时限必须服务端强制（§9 扫描自动交卷）；单题不设限。

### 6.3 漂移与防作弊

- 心跳携带 `client_elapsed_ms` 与服务端值偏差 > 10%（且 > 30s）连续 3 次：标记 `timer_anomaly`，记入会话元数据供《在线测评防作弊检测》取用（本服务不做处罚决策）。
- 客户端本地时间回拨/快进不影响权威计时；`answer_elapsed_ms` 超过 (提交时刻 elapsed − first_viewed elapsed) 5% 以上按服务端值截断。

## 7. 断点恢复机制

### 7.1 可恢复窗口

| 会话状态 | 可恢复窗口 | 窗口外去向 | 恢复动作 |
| --- | --- | --- | --- |
  | CREATED | 创建后 48h | EXPIRED（status_reason=CREATE_TIMEOUT） | 重新 start |
  | ACTIVE | 无操作 30min 自动转 PAUSED；PAUSED 24h | EXPIRED（status_reason=PAUSE_TIMEOUT） | resume 续答 |
  | ACTIVE（有心跳但客户端被杀） | 心跳断即视为无操作计时起点 | 同上 | 直接续答（ACTIVE 不需 resume） |
  | 终态（COMPLETED/EXPIRED/ABANDONED） | 不可恢复 | — | 仅可回看报告 |

### 7.2 恢复数据组装

1. 优先 Redis：会话缓存 + 各题 answer 缓存（草稿、answer_status、first_viewed_at）。
2. Redis MISS/部分缺失：回源 DB（`practice_sessions` + `session_questions`），以 DB 为准重建缓存；草稿以 DB `user_answer(is_confirmed=false)` 为兜底（丢失最近 ≤3s 草稿可接受，客户端本地 Hive 草稿箱 `practice_drafts` 优先展示，提交时以服务端 version CAS 裁决）。
3. 冲突裁决：恢复时携带客户端本地 `version`；小于服务端 version → 客户端丢弃本地草稿（其他端已推进）；等于 → 保留并继续；大于（异常）→ 以服务端为准并上报日志。
4. 计时恢复：ACTIVE 直接以 §6.1 公式重建本地计时器；恢复响应总是带 `server_now`/`authoritative_elapsed_ms` 供 offset 校正。

### 7.3 客户端契约

对齐《客户端-断点续学与学习上下文恢复》：本服务 `GET /sessions/active` 即其恢复数据源之一（scene=practice）；恢复深链格式 `primetop://practice/session?uuid={session_uuid}`；客户端 500ms 内完成上下文装配的指标不含网络往返。

## 8. 多设备并发控制

### 8.1 设备锁

```text
SET practice:lock:{session_uuid} <device_id> NX EX 30
心跳续期：EXPIRE practice:lock:{session_uuid} 30（仅持锁设备可续）
```

- 每个写操作（draft/answer/skip/flag/submit/pause/abandon）前置校验锁归属；非持锁设备写操作 → MOCK_EXAM 返回 55116，其他类型返回 55119（提示只读快照模式）。
- 锁过期（30s 无心跳）后任意设备可在下一次心跳/写操作时抢锁，抢锁即接管（`device_info` 更新，记 `answer_events(TAKE_OVER)`）。
- Redis 不可用降级：以 DB 乐观锁 `version` + `last_active_at + 30s` 等价判定（见 D1）。

### 8.2 写冲突与一致性

1. **行级**：`session_questions` 每次写带 `WHERE version=?`，失败重读后按「已提交答案不可被旧设备覆盖」裁决（新提交以 `submitted_at` 后者胜，未提交草稿以 client_timestamp 新者胜）。
2. **会话级**：状态流转全部 CAS（§3.2），天然防双端同时 pause/submit/abandon。
3. **进度计数**：`answered_count/correct_count/marked_for_review` 采用 Redis `HINCRBY` 增量维护，交卷与 pause 时以 DB 全量重算校准（消除增量漂移）。

## 9. 超时处理与定时扫描

### 9.1 扫描任务矩阵

| 任务 | 频率 | 数据源 | 动作 |
| --- | --- | --- | --- |
  | 整卷到期扫描 | 2s | `practice:timers:active` ZSET | CAS→EXPIRED + 自动交卷（§5.4 双保险之一） |
  | 无操作转暂停 | 1min | DB `idx_status_expired` + `last_active_at`（ACTIVE 且 last_active_at+30min<now） | ACTIVE→PAUSED（status_reason=IDLE_TIMEOUT），清计时 ZSET |
  | 暂停超时过期 | 5min | DB（PAUSED 且 paused_at+24h<now） | PAUSED→EXPIRED（PAUSE_TIMEOUT），走交卷清算 |
  | 创建超时过期 | 10min | DB（CREATED 且 created_at+48h<now） | CREATED→EXPIRED（CREATE_TIMEOUT），释放题目额度（不回收快照） |
  | 归档清理 | 每日 | DB（终态且 completed_at<now-180d） | 软标记 `archived=1` + `answer_events` 迁移 ClickHouse 后删除行 |

> §3.1 图中 ARCHIVED 并非状态机状态：终态会话 180 天后打 `archived=1` 标记并迁移明细，状态字段保持不变（枚举仅 6 态，见 §2.5）。

### 9.2 扫描器实现要点

- 分片：按 `session_id % 8` 分片多实例执行，Redis Set `practice:scanner:lease:{shard}` 租约 60s 防重复。
- 批量：每轮 ≤ 500 会话，逐个 CAS，失败跳过不重试（下轮自然处理）；自动交卷复用 §4.10 同一服务方法（唯一入口，禁止旁路复制逻辑）。
- 背压：交卷扇出走 Outbox 异步，扫描器仅完成状态翻转与 Outbox 写入，不在扫描线程内做批改调用。

## 10. 完成后异步扇出（Outbox）

### 10.1 Outbox 表

```sql
CREATE TABLE practice_outbox (
    id             BIGINT PRIMARY KEY AUTO_INCREMENT,
    event_id       CHAR(36) NOT NULL UNIQUE COMMENT '幂等键，消费方按(event_id,consumer)去重',
    event_type     VARCHAR(64) NOT NULL,
    aggregate_id   VARCHAR(64) NOT NULL COMMENT 'session_uuid',
    payload        JSON NOT NULL,
    occurred_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    published_at   DATETIME(3) NULL,
    retry_count    INT NOT NULL DEFAULT 0,
    INDEX idx_pub (published_at, retry_count)
) ENGINE=InnoDB COMMENT='练习会话 Outbox';
```

### 10.2 事件清单与消费方

| 事件 | 触发时机 | payload 关键字段 | 消费方 |
| --- | --- | --- | --- |
  | practice.session.started | start 成功 | session_uuid, user_id, session_type, time_limit_seconds | 学习时长归因引擎（会话开始锚点）、行为分析 |
  | practice.session.completed | 交卷成功（含自动交卷） | session_uuid, user_id, scores, per_question 摘要, elapsed_seconds | 学习记录服务、学情分析/报告、学习时长归因、每日任务完成核销、消息服务（家长提醒）、首页薄弱点提醒 |
  | practice.session.regraded | 主观题异步批改回填 | session_uuid, score_delta, affected_questions | 学情分析/报告（分数刷新）、用户消息中心（报告更新） |
  | practice.session.expired | 超时自动交卷 | session_uuid, auto_submitted_count | 同 completed 消费方（下游按事件类型区分文案） |
  | practice.session.paused / resumed | 暂停/恢复 | session_uuid, paused_seconds | 学习时长归因（剔除暂停段） |
  | practice.session.abandoned | 主动放弃 | session_uuid, reason | 行为分析（弃题原因）、学习规划复盘 |

**命名对齐说明**：全库既有引用 `practice.session.completed`（《端到端-考点梳理》）为准；《互动练习与即时反馈引擎》的 `exercise.session.completed`、《端到端-自适应学习》的 `practice.session_finished` 属同名异写，本服务统一发布 `practice.session.*`，由事件总线适配层做别名映射（已在 §15 契约表登记，逐步收敛）。

### 10.3 投递语义

- At-least-once + 消费方幂等（`event_id` 天然唯一，消费方落 `(event_id, consumer)` 去重表）。
- 发布器 500ms 扫描未发布行，指数退避重试 8 次后进死信人工处理；`practice.session.completed` 属关键业务事件，死信积压 > 100 触发 P2 告警。

## 11. 错误码定义（55100-55199）

| 错误码 | 场景 | 客户端处理 |
| --- | --- | --- |
  | 55100 | 会话不存在或已删除 | 返回列表页 |
  | 55101 | 非本人会话（越权） | 静默退出，前端提示无权限 |
  | 55102 | 会话状态不允许该操作（通用） | 刷新会话详情后按新状态引导 |
  | 55103 | 每日会话额度不足 | 引导会员/明日再来 |

## 12. 降级矩阵

| 编号 | 故障 | 策略 | 用户感知 |
| --- | --- | --- | --- |
  | D1 | Redis 不可用 | 会话读写直落 DB；计时器改 DB 计算（started_at+paused 累计）；设备锁退化为 DB version+last_active_at 判定；单题缓存关闭 | 答题可用，P99 升高至 ~500ms |
  | D2 | 批改服务不可用 | 客观题提交返回 grading_pending，答案暂存 PENDING，恢复后扫描器批量补判；after_all 模式无感 | 「批改中」状态，可继续答题 |
  | D3 | 题目推荐服务不可用 | 固定卷不受影响；智能推荐降级为「最近章节错题 TopN」本地装配 | 题目相关性下降，可用 |
  | D4 | 延迟任务引擎不可用 | 仅 ZSET 扫描器兜底（反之亦然），单路存活即保证到期交卷 | 无感 |
  | D5 | 消息队列不可用 | Outbox 停留在未发布态，恢复后补发（at-least-once）；下游消费滞后 | 报告/提醒延迟，答题无感 |
  | D6 | ClickHouse 不可用 | answer_events 暂存 MySQL 溢出表 7 天，恢复后迁移 | 无感 |
  | D7 | 心跳通道异常（网关限流） | 客户端本地计时继续，回到前台一次性补报；服务端以 last_active_at 容忍 5min 空窗 | 计时最多漂移至下次心跳校正 |
  | D8 | 单点会话写热点（同会话并发风暴） | 设备锁前置拦截 + CAS 失败快速返回，不做排队 | 多端场景其中一端只读 |
  | D9 | 主观题 AI 批改长时间未完成（> 10min） | 报告先行发布 provisional 分数，regraded 事件二次刷新 | 「部分题目批改中」标注 |
  | D10 | 数据库慢（P99 > 1s） | 草稿/事件全走 Redis 缓冲，仅状态流转落库；读路径强制走缓存副本 | 答题流程可用的最低保障 |

## 13. 监控与容量

### 13.1 核心指标

| 指标 | 口径 | 告警阈值 |
| --- | --- | --- |
  | session.create.success_rate | 创建成功率（排除 55103 额度） | < 99.5% P2 |
  | session.start.latency_p99 | start P99 | > 300ms P3 |
  | answer.submit.p99 | 单题提交全链路 P99 | > 500ms P3 |
  | session.submit.autorace_dup | 双保险空转率（CAS 失败次数/到期数） | 仅观测 |
  | timer.scan.lag | 整卷到期扫描滞后（now − 最老到期未处理） | > 10s P1 |
  | grading.pending.backlog | PENDING 批改积压 | > 5000 或 10min 不消化 P2 |
  | outbox.dead_letter | 死信积压 | > 100 P2 / > 1000 P1 |
  | session.resume.success_rate | 断点恢复成功率 | < 99.9% P2 |
  | multi_device.conflict.rate | 多端写冲突占比 | 突增 50% 环比观测 |
  | session.abandon.rate | 放弃率（按 type 分桶） | 环比突增 P3 观测 |

### 13.2 容量估算（DAU 50 万）

- 并发答题会话峰值：50 万 × 20% 同时在线 × 40% 在练习 ≈ 4 万活跃会话。
- 心跳 QPS：4 万 / 15s ≈ 2.7k QPS（纯 Redis，单集群可承载）。
- 写库 QPS：draft 走 Redis（3s 合并）≈ 4 万 × 1/3s 上限 ≈ 13k 缓存写 + 刷库批量 ≤ 500 QPS；answer 提交 ≈ 峰值 2k QPS（含批改转发）。
- 存储：`practice_sessions` 日增 ~40 万行/日（含未完成），终态 180 天归档 → 热数据 ≈ 40 万 × 30 天 ≈ 1200 万行；`session_questions` ×10 ≈ 1.2 亿行（按月分区 `PARTITION BY RANGE (month)`，归档任务按区清理）；`answer_events` 直写 ClickHouse，MySQL 不长存。
- Redis 内存：会话缓存 ~2KB × 4 万 + 单题缓存 ~0.5KB × 40 万 ≈ 250MB，容余 ×3 部署。

## 14. 安全与合规

1. **答案保密**：`correct_answer/explanation` 以 AES-GCM 密文存快照 `sealed` 字段（密钥由《服务端-密钥管理与敏感配置安全策略》KMS 托管，按季度轮换）；仅批改链路解密，题目下发接口永不返回；`after_all` 模式解析在交卷后才进入可解密上下文。
2. **越权防护**：所有接口校验 `user_id` 归属；内部 gRPC 走服务间 mTLS + 服务账户。
3. **未成年人**：心跳/暂停策略天然贴合防沉迷——防沉迷引擎的强制下线事件到达时，本服务自动 pause（非考试）或按监管允许的考试例外策略处理；`answer_events` 含未成年行为数据，仅用于学情，180 天归档。
4. **审计**：ForceTerminate、管理端查卷、密钥轮换均落《服务端-审计日志与操作追溯系统》。
5. **数据最小化**：`device_info` 仅存型号/OS/版本，不采集 IMEI 等标识；事件 `event_data` 不含答案明文的场景（草稿）只存摘要哈希 + 长度。

## 16. 验收场景

1. 创建幂等：同 Idempotency-Key 连发 5 次创建，仅生成 1 个会话、扣 1 次额度。
2. 同章节重复进入：存在 ACTIVE 同章节会话时再次创建，返回原会话并可直接续答。
3. 全生命周期状态机：CREATED→ACTIVE→PAUSED→ACTIVE→COMPLETED 各节点 DB/Redis/客户端三侧状态一致。
4. 非法流转拦截：COMPLETED 会话调用 pause/answer/abandon 均返回对应错误码且数据无变化。
5. 计时同步：人为将客户端时钟 +5min，心跳后 3s 内本地计时器恢复与服务端偏差 ≤ 2s。
6. 暂停时长剔除：PAUSED 10min 后 resume，elapsed_seconds 不含暂停段，deadline 顺延 10min。
7. 断点恢复（杀进程）：答题至第 5 题杀进程 2h 后冷启动，经 /sessions/active 恢复，进度/草稿/计时完整，恢复耗时（服务端侧）< 200ms。
8. 无操作自动暂停：ACTIVE 无心跳 30min，扫描器转 PAUSED；再 24h 后转 EXPIRED 并完成清算。
9. 超时自动交卷双保险：同时停用 ZSET 扫描器与延迟任务其中一路，到期会话仍被另一路正确交卷且仅交卷一次（无重复 completed 事件）。
10. 多端-考试独占：平板答题中手机 start/answer 返回 55116；平板心跳断 35s 后手机可接管。
11. 多端-练习只读：手机进入平板正在答的同步练习，获得快照只读态，写操作返回 55119，平板不受打断。
12. 单题幂等：同题同 key 重复提交，分数与 answered_count 仅累计一次。
13. 防重窗：同题 2s 内换 key 提交返回 55114。
14. 修改答案：allow_go_back 会话 re-submit 重新判分，attempt_number 递增且事件留痕。
15. after_all 防泄题：交卷前任何接口（题目/详情/心跳）均无法获得 is_correct 与解析。
16. 主观题异步：主观题提交返回 PENDING，报告 provisional；批改完成后 regraded 事件驱动客户端分数刷新。
17. 批改服务宕机降级：D2 生效，答题不中断，恢复后 PENDING 自动补判且分数正确。
18. Redis 宕机降级：D1 生效，创建/答题/交卷全链路可用（允许 P99 升高），计时以 DB 计算无跳变。
19. 答案保密审计：抓包全部题目下发报文，无 correct_answer/explanation 字段。
20. 事件扇出幂等：模拟 MQ 重复投递 completed 事件，各消费方（学习记录/学情/时长）数据无重复。
